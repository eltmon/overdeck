Spawn, monitor, and control autonomous AI coding agents.

## pan start

Spawn an agent for an issue from a GitHub, Linear, Rally or Jira project.

```bash
# Spawn an agent for a Linear issue
pan start MIN-123

# GitHub issue #42 in the project whose issue_prefix is PAN
pan start PAN-42
```

This command:
1. Plans the issue first if it has no plan yet (`--plan interactive|auto|skip`)
2. Creates a workspace (git worktree) if it doesn't exist
3. Spawns an autonomous agent in a terminal-backend pane (Herdr by default)
4. The agent reads the issue and plan, explores the codebase, and implements the solution

To run the agent on a linked machine, add `--machine <label|environment-id>`, or
`--machine auto` to let Auto placement pick one by load (`--needs <tag,…>` limits the
choice). The other machine needs a project for the same repository. `pan start` refuses
when your branch has unpushed commits; `--push-first` pushes them, `--ignore-unpushed`
starts anyway. See [Linked machines](/configuration/linked-machines#start-work-on-another-machine).

```bash
pan start PAN-123 --machine desk
pan start PAN-123 --machine auto --needs docker
```

Other options: `--model`, `--harness` and `--effort` override the work role; `--force`
clears paused, troubled and pending-decision gates; `--fresh` drops the saved session;
`--remote` runs on a Fly.io workspace; `--dry-run` shows what would be created.

## pan status

List all running agents and their status.

```bash
pan status
pan status --json
```

Shows:
- Agent ID (for example agent-pan-123)
- Issue ID
- Current status
- Runtime duration
- Workspace location
- Harness, model, effort and role
- A Gate line when paused or troubled, and STACK BROKEN when the workspace Docker stack is broken

`pan status --context` also shows each agent's context-window use.

The dashboard's **Agents** page is the visual counterpart to this command. It is experimental: turn on Settings → Experimental → **Experimental features** to show it. It opens on a Live view that groups running and in-pipeline agents into Needs you, Live and Waiting, one row per agent with its issue, reason, current tool and age, beside a preview of the selected agent's transcript. History lists finished agents.

<Tip>
Use `pan status` from the terminal for a quick check, and the Agents page (experimental) when you want to watch many agents at once and see which ones need you.
</Tip>

## Targeting an agent

`pan tell`, `pan pause`, `pan unpause`, `pan untroubled`, and `pan kill`/`pan stop` all resolve their `<id>` argument the same way:

| Form | Example | Resolves to |
| --- | --- | --- |
| Issue ID | `PAN-1148` | The issue's work agent (or its one registered non-work agent, such as a strike session) |
| Agent ID | `agent-pan-1148`, `strike-pan-1723`, `conv-20260928-7563` | Exactly that agent |
| Conversation | its name `20260928-7563`, `conv/2972`, `conv:2972`, or a dashboard URL such as `https://overdeck.localhost/conv/2972` | The conversation's agent |
| Bare number | `2972` | An issue agent if exactly one matches; otherwise that conversation, if one exists |

A bare number is convenient but can be ambiguous: a conversation's dashboard number and an issue's number can coincide. When a bare number or a bare name matches more than one target (an issue agent *and* a conversation, or two issue agents), the command refuses and lists every candidate with its explicit form (`PAN-2972`, `conv/2972`, …) so you can pick one. Use the explicit form whenever you already know it.

## pan tell

Send a message to a running agent.

```bash
# Send a message to an agent (handles Enter key automatically)
pan tell min-123 "Please also add tests"

# Message a conversation by its dashboard number, name, or URL
pan tell conv/2972 "Please also add tests"
pan tell https://overdeck.localhost/conv/2972 "Please also add tests"
```

This command:
- Sends your message to the agent's pane
- The agent receives it and responds accordingly
- Useful for providing feedback, clarification, or guidance

`--steer` interrupts the running turn and sends now. `--when-limit-resets` queues the
message on the server until a conversation's usage limit resets. `--force` delivers to a
critic or verifier lane that already filed its verdict. When a message cannot be
delivered, the command says why and exits 1; the text may be saved under
`~/.overdeck/agents/<agent>/mail/`.

### A conversation on a linked machine

Name a conversation another machine runs as `@<machine>/<conv>` (its label or
environment id; see [Linked machines](/configuration/linked-machines)):

```bash
pan tell @desk/conv-20261101-1234 "Rebase on main before you push."
pan tell @desk/conv-20261101-1234 "Rebase on main before you push." --message-id rebase-1
```

The message goes through this machine's dashboard and the encrypted link. It prints
`Delivered to <conv> on <machine>`, or the other machine's error and exits 1.
`--message-id <id>` makes a repeat land once (the default is a fresh id); on a local
target it is the delivery's idempotency key too. `--steer` works; `--when-limit-resets`
and `--force` exit 1 for a remote target. Only conversations are accepted after
`@<machine>/`: an agent name exits 1 with "pan tell @&lt;label&gt;/… targets conversations only".

## pan pause

Pause an agent. The pause persists, a running agent is stopped, and pausing an issue's
work agent also stops that issue's review and test agents. `--reason "<text>"` stores
why. See [Targeting an agent](#targeting-an-agent) for every accepted `<id>` form,
including `conv/<n>` and dashboard URLs.

```bash
pan pause min-123
```

## pan unpause

Clear a pause gate set by `pan pause` and resume the agent immediately if it has a session to resume. See [Targeting an agent](#targeting-an-agent) for every accepted `<id>` form.

```bash
pan unpause min-123
```

## pan untroubled

Clear an agent's troubled gate. It does not start the agent; run `pan start <id>` afterwards.

```bash
pan untroubled min-123
```

## pan kill

Stop a running agent.

```bash
pan kill min-123

# A conversation target stops only that conversation; an issue ID stops
# every agent registered for the issue (work, review, test, swarm slots, …)
pan kill conv/2972
```

Stops the agent, and stops the workspace's Docker stack unless another agent of the
issue is still live. The workspace, branch, and any uncommitted work remain intact.

## pan reset-session

Clear an agent's saved session pointers so its next start creates a fresh session.

```bash
pan reset-session min-123
```

## Reviewing and approving work

Finished work is an open pull request. Approval is a PR review, not a CLI verb.

```bash
# Work awaiting review
gh pr list

# Approve a PR
gh pr review <pr-number> --approve
```

Merge from the dashboard's **Merge** button. Merge readiness is derived live
from the PR: approvals, green checks, and forge mergeability.

## pan issues

List issues from configured trackers.

```bash
pan issues

# Show the triage queue
pan issues --triage
```

Options: `--mine`, `--all` (include closed), `--tracker <type>`, `--all-trackers`, `--json`.

Shows issues from GitHub, Linear, Rally or Jira based on your configuration.

## pan reopen

Re-enter the pipeline for a closed, completed, or cancelled issue.

```bash
pan reopen min-123 --reason "Regression found in staging"
```

For an issue that is still in progress, use `pan review restart` or `pan start` instead.
`--force` skips the in-progress guard and the confirmation prompt.

## pan review request

Request re-review after fixing feedback.

```bash
pan review request min-123 -m "Fixed: added tests and removed duplication"
```

## pan wipe

Deep wipe: completely reset an issue.

```bash
# Asks for confirmation
pan wipe min-123

# Skip confirmation
pan wipe min-123 -y
```

This is a nuclear option that:
- Kills any running agents
- Removes the workspace files
- Deletes the issue's branches
- Resets the issue tracker status
- Clears review state and xBRIEF task state, and resets the issue to Todo

## pan recover

Recover crashed agents.

```bash
# Recover a specific agent
pan recover min-123

# Recover all crashed agents
pan recover --all

# Compact-respawn a context-wedged agent
pan recover min-123 --compact

# Switch the model on recovery
pan recover min-123 --model sonnet
```

Resumes a crashed or stopped agent. With no ID it lists crashed agents; `--all` recovers
them all. `--compact` compact-respawns a context-wedged agent, including troubled or
user-stopped work agents that automatic recovery will not resume, and `--model <model>`
switches its model.

## pan admin specialists

Manage specialist agents (review, test, UAT, merge).

```bash
# Show all specialists and their status
pan admin specialists list

# Wake a specialist with a task
pan admin specialists wake review-agent --task "review MIN-123"

# Reset a specialist (clear session, start fresh)
pan admin specialists reset review-agent
```

`pan admin specialists reset --all` resets every specialist.

See [Specialist Agents](/features/specialists) for detailed information on each specialist type.

## pan admin config set

Set one `config.yaml` key on this machine.

```bash
pan admin config set resources.quality_gate_slots 2
pan admin config set anywhere.machine.tags '[docker, payments]'
```

The value is parsed as YAML, so numbers, booleans and flow lists keep their types. The
key path is created when missing and the rest of the file is kept. **Compare settings**
in Settings → Anywhere → Machines prints these lines for the keys that differ between two
machines; see [Compare settings](/configuration/linked-machines#compare-settings).

## pan admin remote

Manage remote workspaces via Fly.io.

```bash
# Initialize the Fly.io app for workspace machines
pan admin remote init

# Install flyctl and configure auth
pan admin remote setup

# Check Fly.io connection and machine status
pan admin remote status

# Show RAM/disk usage across VMs
pan admin remote resources
```

`pan admin remote reap` hands completed remote agents to the review pipeline and stops
their machines. Remote workspaces stay off until `enabled = true` is set under
`[remote]` in `~/.overdeck/config.toml`.

See [Workspaces](/features/workspaces#remote-workspaces-flyio) for details on remote workspace execution.
