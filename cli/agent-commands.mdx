# Agent Commands

Spawn, monitor, and control autonomous AI coding agents.

## pan start

Spawn an agent for a Linear or GitHub issue.

```bash
# Spawn an agent for a Linear issue
pan start MIN-123

# Spawn an agent for a GitHub issue
pan start 42
```

This command:
1. Plans the issue first if it has no plan yet (`--plan interactive|auto|skip`)
2. Creates a workspace (git worktree) if it doesn't exist
3. Spawns an autonomous agent in a terminal-backend pane (Herdr by default)
4. The agent reads the issue and plan, explores the codebase, and implements the solution

## pan status

List all running agents and their status.

```bash
pan status
pan status --json
```

Shows:
- Agent session ID
- Issue number and title
- Current status
- Runtime duration
- Workspace location

The dashboard's **Agents** page is the visual counterpart to this command. A metric strip across the top tallies how many agents are running, how many are stuck, and the rolling cost and token spend over the last 24 hours, with each agent rendered as a card showing its model, runtime, and last activity.

## Targeting an agent

`pan tell`, `pan pause`, `pan unpause`, `pan untroubled`, and `pan kill`/`pan stop` all resolve their `<id>` argument the same way:

| Form | Example | Resolves to |
| --- | --- | --- |
| Issue ID | `PAN-1148` | The issue's work agent (or its one registered non-work agent, such as a strike session) |
| Agent ID | `agent-pan-1148`, `strike-pan-1723`, `conv-20260928-7563` | Exactly that agent |
| Conversation | `conv/2972`, `conv:2972`, or a dashboard URL such as `https://overdeck.localhost/conv/2972` | The conversation's agent |
| Bare number | `2972` | An issue agent if exactly one matches; otherwise that conversation, if one exists |

A bare number is convenient but can be ambiguous — a conversation's dashboard number and an issue's number can coincide. When a bare number matches more than one target (an issue agent *and* a conversation, or two issue agents), the command refuses and lists every candidate with its explicit form (`PAN-2972`, `conv/2972`, …) so you can pick one. Use the explicit form whenever you already know it.

## pan tell

Send a message to a running agent.

```bash
# Send a message to an agent (handles Enter key automatically)
pan tell min-123 "Please also add tests"

# Message a conversation by its dashboard number, name, or URL
pan tell conv/2972 "Please also add tests"
pan tell https://overdeck.localhost/conv/2972 "Please also add tests"
```

This command:
- Sends your message to the agent's pane
- The agent receives it and responds accordingly
- Useful for providing feedback, clarification, or guidance

## pan pause

Pause a running agent — it stops accepting new work until unpaused. See [Targeting an agent](#targeting-an-agent) for every accepted `<id>` form, including `conv/<n>` and dashboard URLs.

```bash
pan pause min-123
```

## pan unpause

Clear a pause gate set by `pan pause` and resume the agent immediately if it has a session to resume. See [Targeting an agent](#targeting-an-agent) for every accepted `<id>` form.

```bash
pan unpause min-123
```

## pan kill

Stop a running agent.

```bash
pan kill min-123

# A conversation target stops only that conversation; an issue ID stops
# every agent registered for the issue (work, review, test, swarm slots, …)
pan kill conv/2972
```

Stops the agent. The workspace, branch, and any uncommitted work remain intact.

## Reviewing and approving work

Finished work is an open pull request. Approval is a PR review, not a CLI verb.

```bash
# Work awaiting review
gh pr list

# Approve a PR
gh pr review <pr-number> --approve
```

Merge from the dashboard's **MERGE** button. Merge readiness is derived live
from the PR: approvals, green checks, and forge mergeability.

## pan issues

List issues from configured trackers.

```bash
pan issues

# Show the triage queue
pan issues --triage
```

Shows issues from Linear, GitHub, or GitLab based on your configuration.

## pan reopen

Re-enter the pipeline for a closed, completed, or cancelled issue.

```bash
pan reopen min-123 --reason "Regression found in staging"
```

For an issue that is still in progress, use `pan review restart` or `pan start` instead.

## pan review request

Request re-review after fixing feedback.

```bash
pan review request min-123 -m "Fixed: added tests and removed duplication"
```

## pan wipe

Deep wipe: completely reset an issue.

```bash
# Asks for confirmation
pan wipe min-123

# Skip confirmation
pan wipe min-123 -y
```

This is a nuclear option that:
- Kills any running agents
- Removes the workspace files
- Deletes the issue's branches
- Resets the issue tracker status

## pan recover

Recover crashed agents.

```bash
# Recover a specific agent
pan recover min-123

# Recover all crashed agents
pan recover --all
```

Attempts to resume agents that crashed or were interrupted.

## pan admin specialists

Manage specialist agents (review, test, UAT, merge).

```bash
# Show all specialists and their status
pan admin specialists list

# Wake a specialist with a task
pan admin specialists wake review-agent --task "review MIN-123"

# Reset a specialist (clear session, start fresh)
pan admin specialists reset review-agent
```

See [Specialist Agents](/features/specialists) for detailed information on each specialist type.

## pan admin remote

Manage remote workspaces via Fly.io.

```bash
# Initialize the Fly.io app for workspace machines
pan admin remote init

# Install flyctl and configure auth
pan admin remote setup

# Check Fly.io connection and machine status
pan admin remote status

# Show RAM/disk usage across VMs
pan admin remote resources
```

See [Workspaces](/features/workspaces#remote-workspaces-flyio) for details on remote workspace execution.
