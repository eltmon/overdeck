The Overdeck CLI (`pan`) provides a comprehensive set of commands for managing agents, workspaces, and multi-project orchestration.

Most day-to-day CLI commands have a counterpart in the dashboard, where the same agents, conversations, and workflow are managed visually. The Command Deck shows a live agent: the left column with the project switcher and the project's conversations and issues, and the agent's turn-by-turn tool calls and reasoning in the center. The Needs-you / Project / Global feed is on `/activity`.

<Tip>
  The CLI and dashboard operate on the same state. You can spawn an agent from the terminal with `pan start MIN-123` and watch its reasoning stream into the Command Deck, or start it from the board and drive it from the CLI: they are two views of one orchestrator.
</Tip>

## Philosophy

The Overdeck CLI is designed around a few key principles:

1. **Agent-centric** - Commands focus on spawning, monitoring, and controlling AI agents
2. **Workspace isolation** - Each issue gets its own git worktree workspace
3. **Multi-project support** - Manage multiple projects from a single installation
4. **Integration-first** - Works with issues in GitHub, Linear, Rally and Jira, and with code on GitHub or GitLab

## Command Structure

Overdeck commands are organized into logical groups:

| Group | Purpose | Examples |
|-------|---------|----------|
| **Core** | System management | `pan up`, `pan down`, `pan sync`, `pan doctor`, `pan reload`, `pan restart`, `pan update` |
| **Work** | Agent management | `pan start`, `pan status`, `pan tell`, `pan kill` |
| **Workspace** | Workspace lifecycle | `pan workspace create`, `pan workspace destroy` |
| **Review** | Code review loop | `pan review request`, `pan review restart`, `pan review abort` |
| **Project** | Project registry | `pan project add`, `pan project list` |
| **Skills** | Skills and per-level overrides ([reference](/cli/skills-commands)) | `pan skills`, `pan sync` |
| **Conversations** | Session history and conversation metadata ([reference](/cli/conversation-commands)) | `pan conv list`, `pan conv search` ([searching](/features/conversations#search-from-the-command-line)), `pan conv move`, `pan conv link-pr` ([linking pull requests](/features/conversations#linking-a-pull-request-by-hand)), `pan conv schedule add` ([scheduled runs](/features/conversations#scheduled-runs)), `pan handoff`, `pan fork`, `pan resume` |
| **Pipeline** | Plan, track and close issues, the Flywheel ([reference](/cli/pipeline-commands)) | `pan plan`, `pan task`, `pan show`, `pan close`, `pan flywheel`, `pan orders`, `pan done`, `pan strike` |
| **Memory** | Curated facts, observation memory, context layers ([reference](/cli/memory-commands)) | `pan memory search`, `pan memory add`, `pan context list` |
| **Admin** | Specialists, remote workspaces, Cloister | `pan admin specialists list`, `pan admin remote status`, `pan admin cloister status` |
| **Operations** | Health, resources, cost, hygiene ([reference](/cli/hygiene)) | `pan health` (experimental: turn on Settings → Experimental → **Experimental features** to show it), `pan resources` (experimental), `pan cost` (experimental), `pan hygiene` |
| **Machines** | Linked machines, workers, lanes ([reference](/cli/machines)) | `pan machines`, `pan connect`, `pan worker run`, `pan lane start` |
| **Sharing** | Shared sessions, Session Vault, accounts ([reference](/cli/share)) | `pan share`, `pan join`, `pan vault`, `pan account` |

## Installation & Setup

```bash
# Install Overdeck globally
npm install -g @overdeck/core

# Run first-time setup
pan install

# Sync skills to AI tools
pan sync

# Check system health
pan doctor
```

## Common Patterns

### Issue-based workflows

Most commands accept an issue identifier such as `MIN-123`. A GitHub issue uses its project's `issue_prefix`, so eltmon/overdeck#42 is `PAN-42`. A bare number such as `42` works for commands that act on an existing agent (`pan tell`, `pan kill`, `pan show`, `pan close`, `pan reopen` …) when exactly one agent on this machine matches; `pan start` needs the full ID:

```bash
pan start MIN-123           # Spawn agent
pan tell MIN-123 "msg"      # Send message
pan status                  # List all agents
pan kill MIN-123            # Stop agent
```

### Workspace management

Workspaces are git worktrees created automatically or on-demand:

```bash
pan workspace create MIN-123         # Create workspace
pan workspace create MIN-123 --docker # With Docker containers
pan workspace destroy MIN-123        # Clean up workspace
```

### Dashboard integration

Many operations can be performed either via CLI or dashboard:

```bash
pan up    # Start the dashboard (https://overdeck.localhost with Traefik, else http://localhost:3011)
```

The dashboard provides a visual interface for most CLI operations.

## Getting Help

```bash
# General help
pan --help

# Command-specific help
pan start --help
pan workspace --help
```

Run `pan doctor` to check your setup, or `pan diagnose` to collect a redacted diagnostic bundle and start an agent on the problem. Ask questions on the [Overdeck Discord](https://discord.gg/ZpHE2ZTv5P) and report bugs on [GitHub Issues](https://github.com/eltmon/overdeck/issues).

## Common Options

### Global flags

| Flag | Description |
|------|-------------|
| `--help` | Show help for any command |
| `-V`, `--version` | Show Overdeck version |
| `--yolo [value]` | Override the permission mode for spawned Claude Code agents (`--yolo=false` forces auto mode); works in any position |

### Issue identifiers

Commands accept various issue identifier formats:

- **Linear**: `MIN-123`, `min-123` (case-insensitive)
- **GitHub**: `PAN-42` (the project's `issue_prefix` plus the issue number)
- **Rally**: `F29698`, `US1234`, `DE123`
- **Jira**: `PROJ-123`

## Configuration

Overdeck stores configuration in:

- `~/.overdeck.env` - API keys and tokens
- `~/.overdeck/projects.yaml` - Registered projects
- `~/.overdeck/config.yaml` - Global settings (`pan admin config set` writes here)
- `~/.overdeck/config.toml` - Dashboard ports, Traefik and remote workspace switches
- Project-level: `.pan.yaml` in the repository root - Project-specific settings (a legacy `.overdeck.yaml` still loads, with a deprecation warning)
