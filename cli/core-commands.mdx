Core system management commands for Overdeck.

## pan install

Install prerequisites and perform first-time setup.

```bash
# Full install (includes Traefik + mkcert for HTTPS)
pan install

# Minimal install (skip Traefik, use ports)
pan install --minimal
```

This command:
- Installs ttyd (web terminal)
- Installs the tools Overdeck needs for managed workspaces
- Optionally sets up Traefik and mkcert for HTTPS
- Creates necessary configuration directories
- Sets up git hooks for registered projects

The prerequisite gate only fails on Node, git, and (under the tmux backend) tmux. Docker, ast-grep, and (under Herdr) tmux print a yellow warning instead of failing, and installation continues.

## pan sync

Sync skills and configuration to all AI tools.

```bash
pan sync
```

This command:
- Copies skills from `~/.overdeck/skills/` to AI tool directories
- Updates Claude Code skills in `~/.claude/skills/`
- Prunes managed cache and target files when their bundled source is removed
- Preserves user-owned files and reports user-modified stale files instead of deleting them
- Skips empty bundled skill directories instead of propagating them into caches
- Syncs to Codex, Cursor, Gemini CLI, and Google Antigravity
- Installs/updates git hooks in all registered projects

Run this after:
- Installing Overdeck
- Updating skills
- Adding new projects
- Upgrading Overdeck

## pan doctor

Check system health and configuration.

```bash
pan doctor
```

Checks:
- Node.js version (22+ required)
- Git installation
- Docker installation and status
- tmux installation (a warning, not an error, when Herdr is the terminal backend)
- Claude Code and GitHub CLI login state (warnings)
- Required CLI tools (gh, glab)
- Configuration files
- API key validity
- Workspace health
- Traefik status (if installed)

Returns a health report with recommendations for any issues found.

`pan doctor --json` prints the same checks as one JSON object (no banner,
no colour) instead:

```bash
pan doctor --json
```

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-11-01T04:52:00.000Z",
  "strict": false,
  "exitCode": 0,
  "summary": { "ok": 40, "warn": 2, "error": 0 },
  "checks": [
    { "name": "Git", "status": "ok", "message": "Installed", "fix": null }
  ],
  "patrolBudgets": [
    { "patrol": "example-patrol", "actions": 3, "budget": 20, "suspended": false }
  ]
}
```

The exit code matches text mode: `1` when any check is `error`, or when any
check is `warn` and `--strict` was passed; otherwise `0`.

## pan semgrep ci-setup

Open a pull request that adds a Semgrep GitHub Actions workflow to a project.

```bash
pan semgrep ci-setup myapp --dry-run
pan semgrep ci-setup myapp
```

Options:
- `--dry-run`: print the target repository, base branch, gate mode and the
  workflow, and change nothing
- `--sarif-upload`: also scan base-branch pushes and upload the results to
  GitHub code scanning

It needs `security.semgrep.enabled: true` and a single-repo GitHub project. The
generated commit skips repository hooks. See
[Semgrep CI workflow](/configuration/semgrep#ci-workflow).

## pan computer

Read and operate a local desktop app's accessibility tree, clicks, keys and
screenshots through a vendored Orca helper.

```bash
pan computer list-apps
pan computer get-app-state --app gnome-calculator --query 7
pan computer click --app gnome-calculator --element-index 12
```

It needs `computer_use.enabled: true` (global config only) and a Linux desktop
with a logged-in session. See [Computer use](/configuration/computer-use).

## pan diagnose

Collect a redacted diagnostic bundle and, with your consent, start Claude
Code or Codex in that bundle's directory to find and fix the problem. It
works even when the dashboard, the supervisor, or Herdr is down, which is
exactly when you need it most.

```bash
pan diagnose
pan diagnose --bundle-only
pan diagnose --harness codex --describe "dashboard will not start"
pan diagnose --no-issue
```

Flags: `--harness <claude-code|codex>`, `--describe <text>`, `--bundle-only`
(collect the bundle and print its path; never launches a harness),
`--no-issue` (never draft or create an upstream issue), `--yes` (skip the
launch confirmation).

Before starting a harness, `pan diagnose` always prints the bundle path and
its file list, then asks for confirmation; nothing launches without it. See
[DIAGNOSTICS-BUNDLE.md](https://github.com/eltmon/overdeck/blob/main/docs/DIAGNOSTICS-BUNDLE.md)
for exactly what the bundle holds, what is redacted, and what is never
collected.

## pan hygiene

Audit commits, working-tree changes, pull requests, agents, tmux sessions,
merged branches, stale workspaces, and disk headroom in one report. See the
[Hygiene Check](/cli/hygiene) reference for safe-fix semantics.

```bash
pan hygiene
pan hygiene --strict
```

## pan up

Start the Overdeck dashboard and services.

```bash
# Start with default settings
pan up

# Minimal mode (without Traefik)
pan up --minimal
```

Starts:
- **Frontend** - React dashboard (default: http://localhost:3010)
- **API Server** - Backend API (default: http://localhost:3011)
- **Traefik** - Reverse proxy (if installed)

With HTTPS enabled:
- Dashboard: https://overdeck.localhost
- Traefik UI: https://traefik.overdeck.localhost:8080

The dashboard provides:
- Kanban board of issues
- Agent monitoring
- Real-time activity logs
- Cost tracking
- Skills browser
- Health checks

Beyond the board, the dashboard is where you watch and steer live agent
conversations and the work moving through the pipeline. The Pipeline page
groups every active issue by phase (Ship, Review, and Verifying) above a
metric strip tracking active issues, work running, the review queue, ship
count, and spend, with a live activity feed alongside.

## pan down

Stop the dashboard and services gracefully.

```bash
pan down
```

This command:
- Stops the frontend and API server
- Optionally stops Traefik
- Does NOT stop running agents (use `pan kill` for that)
- Does NOT affect workspaces or containers

Agents continue running independently in tmux sessions.

## pan restart

Restart one part of the Overdeck stack. With no option it restarts only the dashboard and leaves
CLIProxy and Traefik running.

```bash
pan restart                                          # dashboard only
pan restart --full                                   # same as pan down, then pan up
pan restart --cliproxy --force                       # redownload the pinned CLIProxy binary first
pan restart hold --reason "live demo" --until 2h
pan restart release
```

Dashboard restarts, reloads, and post-merge deploy restarts wait for operator approval before
they run, so they cannot interrupt live work. `pan restart --now` approves everything already
waiting and restarts immediately, the same as the dashboard banner's Restart now button.

| Command | What it does |
| --- | --- |
| `pan restart approve` | Approves every dashboard restart request waiting for the operator |
| `pan restart hold` | Holds every dashboard restart and reload until `pan restart release`, or until `--until` expires; `--reason <text>`, `--until <when>` (a duration such as `90m`, `2h`, `1d`, or an ISO time), `--status` (shows the current hold instead of setting one) |
| `pan restart release` | Releases the restart hold so `pan reload` and `pan restart` run again |

| Option | What it does |
| --- | --- |
| `--dashboard` | Restarts only the dashboard (default) |
| `--cliproxy` | Restarts only the CLIProxy sidecar |
| `--traefik` | Restarts only Traefik |
| `--full` | Restarts the entire stack, equivalent to `pan down` then `pan up` |
| `--force` | For `--cliproxy`: redownloads the binary at the pinned version first. For the dashboard scope: bypasses the agent deploy-window gate, which otherwise refuses an agent-initiated restart while a deploy-window block reason is active |
| `--health-timeout <duration>` | Dashboard health-check wait budget, in milliseconds or with an `s`/`m` suffix (default 15s; floor 1000ms) |
| `--deacon` | Forces Cloister/Deacon auto-start even if the shell inherited `OVERDECK_DISABLE_DEACON` |
| `--no-deacon` | Skips Cloister/Deacon auto-start on restart; an escape hatch when the Deacon's startup scan is starving the event loop |
| `--resume` | Enables agent auto-resume on boot (kept for explicitness; auto-resume is on by default) |
| `--no-resume` | Disables agent auto-resume on restart, opting out of the default-on behavior |
| `--now` | Skips the operator-approval wait: approves everything already waiting, then restarts the dashboard immediately |

## pan reload

Build Overdeck and restart the dashboard only if the build succeeds; the old dashboard keeps
running if it does not. It works only from an Overdeck source checkout: it resolves the primary
repo root of the current directory, fetches `origin/main`, and builds and deploys that commit,
never the local branch. Uncommitted changes and a local `HEAD` that differs from `origin/main`
are excluded from what gets deployed. An npm install that only updates the published package
uses `pan update` instead.

```bash
pan reload
pan reload --skip-build                 # restart the existing bundle without rebuilding
pan reload --health-timeout 60s
```

| Option | What it does |
| --- | --- |
| `--skip-build` | Skips `npm run build` and restarts the existing bundle |
| `--force` | Bypasses the agent deploy-window gate, which otherwise refuses an agent-initiated reload while a deploy-window block reason is active |
| `--health-timeout <duration>` | Dashboard health-check wait budget, in milliseconds or with an `s`/`m` suffix (default 30s; floor 1000ms) |
| `--deacon` | Starts Cloister/Deacon on the reloaded dashboard (always on after a reload) |
| `--no-deacon` | Refused: a Deacon-off dashboard is a peer and cannot hold the host dashboard port |
| `--resume` | Enables agent auto-resume on the reloaded dashboard (default: keeps the running dashboard's resume gate) |
| `--no-resume` | Disables agent auto-resume on the reloaded dashboard (default: keeps the running dashboard's resume gate) |

A hold from `pan restart hold` also blocks `pan reload` until released.

## pan shutdown

Drain Overdeck safely: let every agent finish its current tool call, stop everything, then
report that the machine is safe to reboot.

```bash
pan shutdown
pan shutdown --reboot --deadline 300
pan shutdown --status
pan shutdown --cancel
```

| Option | What it does |
| --- | --- |
| `--deadline <seconds>` | Seconds before stragglers are listed (default 120, from 10 to 3600) |
| `--reboot` | Reboots the machine once the drain completes (Linux) |
| `--force` | At the deadline, stops stragglers mid-tool call; on an already-running drain, stops them now |
| `--cancel` | Cancels a running drain; stopped sessions are offered for resume |
| `--status` | Prints the current drain and exits |
| `--no-wait` | Starts the drain and exits without following it |

See [Safe shutdown](/features/safe-shutdown) for what happens phase by phase.

## pan update

Check npm for the latest `@overdeck/core`, install it globally, run an automatic sync, then tell
you to restart the dashboard and running agents.

```bash
pan update
pan update --check     # only check, don't install
pan update --force     # reinstall even when already on the latest version
```

| Option | What it does |
| --- | --- |
| `--check` | Only checks for updates; does not install |
| `--force` | Updates even when already on the latest version |

An Overdeck source checkout uses `pan reload` instead; `pan update` installs the published npm
package.

## pan cost

Track and report Overdeck's own recorded AI usage costs across agents, issues, and budgets.

```bash
pan cost today --detail
pan cost issue PAN-1148 --days 7
pan cost budget create team-monthly --limit 200 --type monthly
pan cost budget check team-monthly
```

| Command | What it does | Options |
| --- | --- | --- |
| `pan cost today` | Shows today's cost summary | `-d, --detail` (shows individual entries) |
| `pan cost week` | Shows the weekly cost summary | none |
| `pan cost month` | Shows the monthly cost summary | none |
| `pan cost report` | Generates a cost report | `-s, --start <date>` (`YYYY-MM-DD`), `-e, --end <date>` (`YYYY-MM-DD`) |
| `pan cost issue <issueId>` | Shows costs for a specific issue | `-d, --days <n>` (default 30) |
| `pan cost effort` | Shows costs grouped by reasoning effort | `-i, --issue <issueId>`, `--json` |
| `pan cost budget create <name>` | Creates a cost budget | `-l, --limit <amount>` (in USD, default 100), `-t, --type daily\|monthly\|project\|issue\|feature` (default `monthly`), `-a, --alert <threshold>` (0 to 1, default 0.8) |
| `pan cost budget list` | Lists all budgets | none |
| `pan cost budget check <id>` | Checks budget status | none |
| `pan cost budget delete <id>` | Deletes a budget | none |
| `pan cost sync` | Imports cost events from per-project WAL files into the local database | none |
| `pan cost backfill` | Reconstructs cost events from stored harness session transcripts | `--write` (persists non-duplicate reconstructed events) |

`pan cost` reports Overdeck's own recorded agent cost events; `pan conv cost` instead estimates
API spend across the Claude Code sessions `pan conv scan` has discovered on this machine. Budget
limits are in &#36;; a budget's alert threshold is a fraction of its limit, not a dollar amount.
`pan cost today`, `week`, `month`, `report` and the budget commands currently report zero spend
([#5562](https://github.com/eltmon/overdeck/issues/5562)); see [Costs and spend](/features/costs).

## pan models

Apply eval-backed provider model presets to `config.yaml`. A preset writes explicit values once;
it never auto-applies and never watches for drift.

```bash
pan models preset list
pan models preset show anthropic
pan models preset apply anthropic --dry-run
pan models preset undo
```

| Command | What it does | Options |
| --- | --- | --- |
| `pan models preset list` | Lists presets, their versions, and what was last applied | `--json` |
| `pan models preset show <id>` | Shows the per-setting diff a preset would make to `config.yaml` | `--json` |
| `pan models preset apply <id>` | Applies a preset: prints the diff, confirms, then writes only the changed settings | `--dry-run` (prints the diff, writes nothing), `--yes` (skips the confirmation prompt), `--json` |
| `pan models preset undo` | Restores the values the last preset apply replaced | `--json` |

See [Apply a preset](/configuration/model-presets#apply-a-preset).

## pan tts

Manage the local Qwen text-to-speech daemon and its saved voices.

```bash
pan tts start --detach
pan tts status
pan tts test "deployment finished"
```

| Command | What it does | Options |
| --- | --- | --- |
| `pan tts voices` | Lists and inspects saved TTS voices (own subcommands: `list`, `show <name>`, `play <name> [text]`, `delete <name>`, `set-default <name>`, `map <event> <name>`) | none |
| `pan tts start` | Starts the local Qwen TTS daemon | `--detach` (runs detached in the background), `--foreground` (runs in the foreground), `--no-wait-for-health` (returns without waiting for the health check), `--timeout-ms <ms>` |
| `pan tts stop` | Stops the local Qwen TTS daemon | none |
| `pan tts status` | Shows the local Qwen TTS daemon status | none |
| `pan tts restart` | Restarts the local Qwen TTS daemon | `--no-wait-for-health`, `--timeout-ms <ms>` |
| `pan tts install-systemd` | Installs a user systemd unit for the local Qwen TTS daemon | none |
| `pan tts test [text]` | Speaks a test phrase using the configured system (priority) voice | `--status` (uses the status voice instead) |

## pan backup

`pan sync` backs up the synced skill and command directories before each sync and prunes old
backups automatically; backups live in `~/.overdeck/backups/`.

```bash
pan backup list
pan backup clean --keep 5
```

| Command | What it does | Options |
| --- | --- | --- |
| `pan backup list` | Lists all backups | `--json` |
| `pan backup clean` | Removes old backups | `--keep <count>` (default 10) |

## pan restore

Restore a backup into the Claude Code skill and command directories. With no timestamp, pick
from the 10 newest.

```bash
pan restore
pan restore 2026-11-01T04-52-00
```

## pan health

Check the health of all Overdeck services.

```bash
pan health
```

Shows status of:
- Dashboard (frontend) - Running/stopped
- API server - Running/stopped + health endpoint check
- Traefik - Running/stopped (if installed)
- Running agents - Count and session IDs
- Workspaces - Count and disk usage
- Docker containers - Count and status

Returns:
- Exit code 0 if all services healthy
- Exit code 1 if any service is down

Useful for:
- Pre-flight checks before spawning agents
- Monitoring in automation scripts
- Troubleshooting issues
