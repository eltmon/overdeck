# `pan devices`

Manage the devices paired with this machine's dashboard. Released in v0.64.0. The
**Revoke** button in **Settings → Anywhere → Paired devices** does the same. See
[Remote access](/configuration/remote-access#list-and-revoke-devices).

## list

```bash
pan devices list [--json]
```

Lists paired browser devices and paired phones (the Overdeck app) with columns
`ID NAME CREATED LAST USED REVOKED`.

| Flag | Effect |
| --- | --- |
| `--json` | Print the device array as JSON; each entry has `id`, `name`, `kind` (`device` or `phone`), `scopes`, `createdAt`, `lastUsedAt` and `revokedAt`. |

With no paired devices: `` `No paired devices. Pair one with `pan pair`.` ``

It needs the running dashboard: without one it prints the not-running message and exits 1.
A dashboard that rejects the internal token prints the same token message as `pan pair`
and exits 1. Any other dashboard error prints `pan devices list failed: <message>` and
exits 1.

## revoke

```bash
pan devices revoke <id>
```

Revoke a paired device and close its live connections. Revoking a phone also closes its
secure-channel connections.

Through the dashboard it prints:

```
Revoked device "<name>" (<id>); its live connections were closed.
```

With no dashboard running it writes the revocation of a paired browser device into
`~/.overdeck/access-tokens.json` and prints:

```
Dashboard not running; revoked in the registry. No live connections were open.
```

A phone cannot be revoked this way: with the dashboard down, a phone's id prints
`No paired device with id <id>.` Start the dashboard and run the command again.

An unknown id prints `No paired device with id <id>.` and exits 1. A dashboard that
rejects the internal token prints the same token message as `pan pair` and exits 1. Any
other dashboard error prints `pan devices revoke failed: <message>` and exits 1.
