Cloister is Overdeck's agent watchdog. It starts with the dashboard, checks the health of every running agent, and runs a patrol loop that recovers work that has stalled. Cloister does not choose models and does not decide merges.

## Start, stop and check Cloister

```bash
pan admin cloister status

pan admin cloister start

pan admin cloister stop          # agents keep running

pan admin cloister emergency-stop # kills every agent at once
```

Cloister starts automatically when the dashboard starts. Set `auto_start = false` under `[startup]` in `~/.overdeck/cloister.toml` to turn that off. In the dashboard, open the System Health menu in the top bar and choose **Start Cloister** or **Stop Cloister**, or run the same action from the command palette.

## Agent health

Cloister marks an agent stale after 5 minutes without activity, warning after 15 and stuck after 30. It pokes an agent at warning and at stuck, at most once every 30 minutes per agent. It never kills a stuck agent unless you set `kill_on_stuck = true`. When an agent's harness crashes, Cloister restarts it up to 3 times, waiting 30 seconds, 1 minute and then 2 minutes.

```toml
[thresholds]
stale = 5
warning = 15
stuck = 30

[auto_actions]
poke_on_warning = true
poke_on_stuck = true
kill_on_stuck = false

[auto_restart]
enabled = true
max_retries = 3
```

## The patrol loop

- Nudges a work agent that has been idle for 20 minutes with commits it has not pushed. It asks the agent to continue, or to push and open a pull request. One nudge per agent per hour.
- Nudges agents that stopped on an API error.
- Recovers reviews that stalled, never started, or whose reviewer went silent.
- Resumes a work agent whose harness died without a recorded stop, after confirming it twice.
- Stops agents for issues that were closed.
- Hands finished remote (Fly.io) agents to review.

Each routine writes what it did to `~/.overdeck/logs/deacon.log`.

<Note>
The **Fix-All Flywheel** is a separate loop built on the same pipeline. It picks what to work on next, launches planning and work agents, and parks what it cannot decide. Cloister is the per-agent lifecycle layer; the Flywheel is the cross-issue orchestrator built on top of it.
</Note>

## Where agent health shows up

The Agents page shows each running agent's model, runtime and last activity. The Health page shows system checks for the services Cloister depends on. Both are experimental: turn on Settings → Experimental → **Experimental features** to see them.

## Model routing

Cloister does not pick models. Roles, workhorse slots and tiered execution do that, configured in Settings → Model Routing; see [Model routing](/configuration/model-routing).
