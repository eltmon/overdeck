The Flywheel is a loop that runs in one conversation. Each tick it picks the next issue, starts it with `pan start`, watches the pull request to landing, and parks what it cannot decide for you. Its status is never stored: everything on this page and in `pan flywheel status` is derived fresh from the conversation, the tracker and the pull request.

<Warning>
The Flywheel is early: today Overdeck uses it to build Overdeck itself. The limits below are known and worth reading before you turn it on. For the roadmap, see [Flywheel vision](/vision).
</Warning>

## Known limits

- The loop's author gate names fixed GitHub logins: it acts only on issues whose author is `eltmon` (the Overdeck maintainer) or `panopticon-agent[bot]`, or that are assigned to `eltmon`. On any other repo or account the loop skips your issues, and the current GitHub App bot (`overdeck-agent[bot]`) does not pass it either. See [issue #5544](https://github.com/eltmon/overdeck/issues/5544).
- The Backlog page and its automatic pass read the sequence from the dashboard server's working directory, the Overdeck checkout or install it runs from. There is no project picker yet.
- The agent cap (`roles.flywheel.maxAgents`) and the pickup rule are applied by the loop's own instructions; `pan start` checks neither on its own.
- There is one Flywheel conversation per Overdeck install, `conv-flywheel`.
