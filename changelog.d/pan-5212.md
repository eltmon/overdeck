#### New

- **pi harness:** the Pi Coding Agent (`pi`) is a harness again, with its own runtime, launcher, extension, `pan doctor` check, model provisioning and dashboard picker entry. Stored `pi` conversations read as pi instead of oh-my-pi. Install it with `npm install -g @earendil-works/pi-coding-agent`. ([#5212](https://github.com/eltmon/overdeck/issues/5212))

#### Improved

- **pi is the default for non-Anthropic, non-OpenAI providers:** Google, xAI, MiniMax, Z.AI, MiMo, OpenRouter, Nous, DashScope, Groq, Cerebras and Mistral models now launch on pi instead of oh-my-pi. An explicit `providerHarnesses` or role `harness: ohmypi` setting still wins, and existing oh-my-pi conversations keep resuming on oh-my-pi. ([#5212](https://github.com/eltmon/overdeck/issues/5212))

#### Fixed

- **OpenRouter and Groq models bind the right provider on pi-family harnesses:** pi and oh-my-pi read the vendor segment of a bare `vendor/model` id as the provider, so an OpenRouter `openai/gpt-oss-20b` ran on Groq. Launches now pass `openrouter/<vendor>/<model>` and `groq/<id>`. ([#5212](https://github.com/eltmon/overdeck/issues/5212))
