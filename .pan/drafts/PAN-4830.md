## Glossary

- **Directory:** the connect service's per-account Durable Object (`AccountDirectory`, glue in `services/connect/src/directory.ts`). One instance per account. Owns every directory socket of that account's machines and phones.
- **Reducer:** the pure functions that decide everything (`reduce` in `directory-state.ts` for machines, `reduceClient` in `client-state.ts` for phones). They return `{ state, effects }` and never do I/O. The glue (`directory.ts` `execute()`) runs effects in a fixed order: persist (0) → register (1) → send/fetch (2) → close (3) → log (4).
- **Client / phone:** a socket that sent `hello-client`; a row of the `clients` SQLite table (`ClientRow`). Never counts as a machine.
- **Push registration:** the phone's APNs or FCM device token plus, for iOS, which APNs host it belongs to. Stored in the reserved nullable columns `push_platform`, `push_token`, `aps_environment` of `clients` (created by PAN-4829, never written until now).
- **Sealed payload / `sealed`:** a base64 `crypto_box_seal` ciphertext made by the machine for the phone's push key. Opaque to the directory: it is never decoded, logged or inspected, only length- and charset-checked.
- **`push` frame:** machine → directory, `{ type:'push', requestId (32 hex), to (phone clientId, uuid v4), sealed (base64 ≤ 3,072 chars), urgency:'high'|'normal', collapseId (32 hex) }` (`connect.ts:141-152`).
- **`push-result` frame:** directory → machine, `{ type:'push-result', requestId, ok:true }` or `{ …, ok:false, error:'no_registration'|'rate_limited'|'delivery_failed'|'unknown_client' }` (`connect.ts:200-202`).
- **`push-register` / `push-unregister`:** phone → directory frames (`connect.ts:238-240`).
- **APNs:** Apple Push Notification service, HTTP/2 JSON API at `https://api.push.apple.com` (production) and `https://api.sandbox.push.apple.com` (development builds). Path `/3/device/<token>`.
- **Provider token (APNs JWT):** an ES256 JWT `{alg:'ES256',kid:<key id>}.{iss:<team id>,iat:<seconds>}` signed with the `.p8` key. Apple rejects a token older than 60 minutes and answers `429 TooManyProviderTokenUpdates` when the token changes more often than about every 20 minutes.
- **FCM HTTP v1:** `POST https://fcm.googleapis.com/v1/projects/<project id>/messages:send` with an OAuth 2 access token obtained from a service-account JWT (RS256) at `https://oauth2.googleapis.com/token`.
- **Data-only message:** an FCM message with a `data` map and no `notification` key, so Android hands it to the app's `FirebaseMessagingService` even when the app is closed.
- **Dead token:** a token the provider says will never work again (APNs 410 or certain 400 reasons; FCM 404 or `UNREGISTERED`). The directory clears it.
- **RFC 6979:** deterministic ECDSA. The same key and message always produce the same signature bytes.
- **Isolate:** one V8 instance on a Cloudflare host. Many Durable Objects may share one; module-level variables are shared by them and lost on eviction.

## Requirements

### Functional

- **FR-1 Register.** A registered phone's `push-register { platform, token, apsEnvironment? }` stores the registration on its `clients` row (SQL and in-memory state). `push-unregister` clears it. A later `hello-client` from the same phone keeps it.
- **FR-2 Validate the push.** A registered machine's `push` frame is answered `push-result { ok:false, error:'unknown_client' }` when `to` is not a phone of this account, and `'no_registration'` when that phone has no registration. Whether the phone is online does not matter.
- **FR-3 Rate limit.** At most `PUSH_RATE_PER_MINUTE` (30) pushes per account per UTC calendar minute are delivered; the 31st is answered `'rate_limited'` without an outbound request. The counter survives Durable Object hibernation.
- **FR-4 APNs delivery.** An iOS registration is delivered with one `POST https://<host>/3/device/<token>`; host is `api.sandbox.push.apple.com` when `apsEnvironment` is `sandbox`, else `api.push.apple.com`. Headers: `authorization: bearer <jwt>`, `apns-push-type: alert`, `apns-topic: ai.overdeck.app`, `apns-priority: 10` (high) or `5` (normal), `apns-collapse-id: <collapseId>`, `content-type: application/json`. Body, exactly:
  ```json
  {"aps":{"alert":{"title":"Overdeck","body":"Something needs you"},"mutable-content":1,"sound":"default","thread-id":"<collapseId>"},"s":"<sealed>"}
  ```
- **FR-5 APNs provider token.** ES256 JWT, `iat` quantized down to a 45-minute (2,700 s) window, signed with RFC 6979 deterministic ECDSA (`@noble/curves` p256), cached per `(teamId, keyId)` at module level. Two caches at the same time produce byte-identical tokens.
- **FR-6 FCM delivery.** An Android registration is delivered with `POST https://fcm.googleapis.com/v1/projects/<FCM_PROJECT_ID>/messages:send`, `authorization: Bearer <access token>`, body exactly:
  ```json
  {"message":{"token":"<token>","data":{"s":"<sealed>"},"android":{"priority":"HIGH","ttl":"3600s","collapse_key":"<collapseId>"}}}
  ```
  with `"NORMAL"` for `urgency: 'normal'`. No `notification` key.
- **FR-7 FCM access token.** An RS256 service-account assertion `{iss:<client_email>, scope:'https://www.googleapis.com/auth/firebase.messaging', aud:'https://oauth2.googleapis.com/token', iat, exp:iat+3600}` exchanged at `https://oauth2.googleapis.com/token` (`grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer`). The access token is cached at module level per `client_email` until 5 minutes before its `expires_in`.
- **FR-8 Dead tokens.** APNs 410, or 400 with reason `BadDeviceToken`, `DeviceTokenNotForTopic` or `Unregistered`; FCM 404, or any `error.details[].errorCode === 'UNREGISTERED'`: the registration is cleared (only if the phone's current token is still the one that failed) and the machine gets `push-result { ok:false, error:'no_registration' }`.
- **FR-9 Retry.** A 5xx answer or a network error / timeout of the send request is retried exactly once after 2 s. FCM's OAuth exchange is not retried.
- **FR-10 Answer.** Delivered ⇒ `push-result { ok:true }`. Any other failure, including an unconfigured provider ⇒ `push-result { ok:false, error:'delivery_failed' }`.
- **FR-11 Health.** `/healthz` answers `{ ok, configured, turn, apns, fcm }`; `apns`/`fcm` are true when that provider's secrets parse. It reveals no value.

### Non-functional

- **NFR-1 No plaintext.** The outbound APNs body carries only the fixed placeholder title/body, the `collapseId` and `sealed`; the FCM body only the token, `sealed`, priority, ttl and `collapseId`. Nothing else from the machine reaches Apple or Google.
- **NFR-2 No secrets or payloads in logs.** Log lines (`logFrame`) never contain a push token, `sealed`, a JWT, an access token or a key. Outcomes are short fixed strings plus HTTP status codes.
- **NFR-3 Time budget.** Each outbound fetch has a 2,000 ms timeout (`AbortController` + `setTimeout`, never `AbortSignal.timeout`). Worst case: OAuth 2 s + send 2 s + 2 s wait + send 2 s = 8 s, under the machine's 10 s wait.
- **NFR-4 Web APIs only** in `services/connect/src` (no `node:` imports, no new dependencies).
- **NFR-5 Module size.** No source file in `services/connect/src` passes 600 lines (`wc -l`).
- **NFR-6 Fake timers.** Retry and timeout tests use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`; no test sleeps (repo rule `fake-timers-for-retry-tests`).
- **NFR-7 No committed keys.** Test keys (P-256 and RSA) are generated at runtime with WebCrypto; no PEM private key is committed (GitHub push protection rejects the whole push).
- **NFR-8 Pure decisions.** Every decision (validation, rate limit, outcome → `push-result`, clearing a dead token) is made by a pure reducer; the glue only performs I/O.

## Decisions

- **D-1 Two-event round trip.** `push` → `pushAnswer` (pure) validates and emits a `deliver-push` effect. The glue awaits `deliverPush` (I/O) and feeds the result back as a second pure step, `reducePushOutcome`, which clears a dead token and emits the `push-result` send to `self`. Why: dead-token cleanup and the `push-result` mapping become testable without I/O, and the outcome step re-reads current state, which is correct when other events run during the `await fetch` (a Durable Object processes other events during a non-storage await).
- **D-2 Clear only the token that failed.** `reducePushOutcome` clears the registration only when the phone's current `push.token` equals the token the delivery used. A phone that re-registered during the fetch keeps its new token.
- **D-3 `push` never consults presence.** `pushAnswer` ignores `ctx.online` and `ctx.onlineClients`; a closed app is the reason push exists.
- **D-4 `PushRegistration` is `{ platform: ClientPlatform; token: string; apsEnvironment: ApsEnvironment | null }`,** defined in the new `services/connect/src/push/config.ts`, and `ClientRow` gains `readonly push: PushRegistration | null`. iOS without `apsEnvironment` stores `'production'`; Android stores `null`.
- **D-5 Registration is written by its own statement.** New `PUT_CLIENT_PUSH_SQL = 'UPDATE clients SET push_platform = ?, push_token = ?, aps_environment = ? WHERE client_id = ?'` run by a new effect `put-client-push`. `PUT_CLIENT_SQL` stays unchanged, so `directory-glue.test.ts:24` keeps passing and a re-hello cannot wipe a registration.
- **D-6 Decoder rules.** `push-register`: `platform` `'ios'|'android'`; `token` 1-4096 chars matching `/^[0-9A-Za-z:_.-]+$/` (the token is put into the APNs URL path, so `/`, `?`, `%` and spaces are refused); `apsEnvironment` optional, `'production'|'sandbox'`, and present only with `platform: 'ios'` (else `bad_frame`). `push-unregister`: `{ type }` only. Machine `push`: `requestId` 32 lowercase hex, `to` uuid v4, `sealed` 4-3,072 chars matching `/^[A-Za-z0-9+/]+={0,2}$/` with length divisible by 4, `urgency` `'high'|'normal'`, `collapseId` 32 lowercase hex.
- **D-7 Platform mismatch is refused.** A `push-register` whose `platform` differs from the row's `hello-client` platform answers `error bad_frame` ("push platform does not match the phone") and stores nothing.
- **D-8 Rate limit = fixed UTC-minute window persisted in `meta`.** `DirectoryState.pushWindow: { minute: number; count: number } | null`, where `minute = Math.floor(now / 60_000)`. Accepting a push in the same minute increments `count`; a new minute resets it to 1. Persisted by effect `put-push-window` as `meta` row `push_window` (JSON). Why not in memory: a hibernating Durable Object reloads from storage on its next event, which would reset an in-memory counter after ~10 s of idleness. Why not the Cloudflare `RateLimit` binding: it is a Worker binding keyed per request, and the push decision lives in the Durable Object. Only pushes that pass the client and registration checks count.
- **D-9 Deterministic, quantized APNs tokens.** `iat = Math.floor(nowSeconds / 2700) * 2700`; `p256.sign(utf8(signingInput), d)` with noble defaults; module-level `Map` cache keyed `${teamId}:${keyId}` holding `{ iat, jwt }`. Every account's Durable Object, in every isolate, derives the same token for a window, so Apple sees one token change per 45 minutes. A token is at most 45 minutes old (< 60).
- **D-10 Reading the `.p8` without `node:crypto`.** `crypto.subtle.importKey('pkcs8', der, { name:'ECDSA', namedCurve:'P-256' }, true, ['sign'])`, then `exportKey('jwk', key)`; `jwk.d` (base64url) is the 32-byte scalar. **Implementation checkpoint CP-1:** confirm in the Miniflare test (workerd) that `exportKey('jwk')` returns `d` for an extractable PKCS#8 import. **Fallback:** read the scalar from the DER directly: find the byte sequence `02 01 01 04 20` (ECPrivateKey version 1, OCTET STRING of 32 bytes) and take the next 32 bytes; throw if absent.
- **D-11 FCM signing uses WebCrypto** `RSASSA-PKCS1-v1_5` / `SHA-256` (deterministic by construction), as t3code does. The token endpoint is the fixed constant `https://oauth2.googleapis.com/token`; the service account's `token_uri` is ignored.
- **D-12 Retry and timeouts.** `PUSH_FETCH_TIMEOUT_MS = 2_000` per fetch; `PUSH_RETRY_DELAY_MS = 2_000`; one retry of the send request on 5xx, network error or timeout. APNs 403 (bad or expired provider token) and FCM 401 are not retried; FCM 401 drops the cached access token so the next push fetches a new one. 429 is not retried.
- **D-13 Outcome mapping.** `PushOutcome` = `delivered` | `gone` | `failed { detail }` | `not_configured`. `delivered` ⇒ `ok:true`; `gone` ⇒ `no_registration` (the phone uninstalled the app or turned notifications off; not an operator error, per epic W-MAC3); `failed`/`not_configured` ⇒ `delivery_failed`. Log outcomes: `delivered`, `gone`, `not_configured`, `failed_<detail>` where detail is one of `apns_<status>`, `apns_network`, `fcm_<status>`, `fcm_network`, `fcm_oauth_<status>`, `fcm_oauth_network`, `bad_key`.
- **D-14 Configuration.** Secrets `APNS_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `FCM_SERVICE_ACCOUNT_JSON`, `FCM_PROJECT_ID`. `parsePushConfig(env)` returns `{ apns: ApnsConfig | null, fcm: FcmConfig | null }`; a provider is null when any of its values is missing or blank, or when `FCM_SERVICE_ACCOUNT_JSON` is not JSON with string `client_email` and `private_key`. `APNS_KEY_P8` literal `\n` sequences are turned into newlines before PEM decoding. An unconfigured provider is not a 503; that platform's pushes answer `delivery_failed` with log outcome `not_configured`.
- **D-15 Extract storage first.** `SCHEMA`, `PUT_CLIENT_SQL`, the SQL row interfaces and `load()` move from `directory.ts` to a new `services/connect/src/directory-store.ts` (`loadDirectory(sql: SqlStorage): DirectoryState`) before any push code lands, so `directory.ts` has room under 600 lines.
- **D-16 Module layout.** Pure push decisions in `services/connect/src/push-state.ts` (imports only types from `directory-state.ts`, like `ice-relay.ts`; `directory-state.ts` and `client-state.ts` import values from it — acyclic at runtime). I/O in `services/connect/src/push/`: `config.ts` (types + `parsePushConfig`), `jwt.ts` (base64url, PEM, JWT assembly), `http.ts` (`fetchWithTimeout`), `apns.ts`, `fcm.ts`, `deliver.ts`.
- **D-17 Caches are injectable.** `ApnsTokenCache` and `FcmTokenCache` are classes; `apns.ts`/`fcm.ts` export one module-level shared instance each (`sharedApnsTokens`, `sharedFcmTokens`), used by default; tests pass fresh instances. No test-only reset export.

## Hazards

- **H-1 Start gate.** Do not start implementation before the PAN-4774 acceptance run passes (issue text).
- **H-2 Interleaving during delivery.** Other events run while `deliver-push` awaits. Never cache `this.state` across the await; `applyPushOutcome` reduces against the current state (D-1, D-2).
- **H-3 workerd JWK export (CP-1).** If `exportKey('jwk')` does not return `d` in workerd, use the D-10 DER fallback; the WI-10 JWT verification proves which one works.
- **H-4 Push protection.** A committed PEM private key blocks the whole branch push. Generate every key at runtime.
- **H-5 Shared Miniflare account.** The `u-phones` account is capped at 5 phones and earlier tests leave rows; the push tests use the new `u-push` account.
- **H-6 Fake timers and fetch.** `fetchWithTimeout` uses `setTimeout`; tests that use fake timers and also await a stub fetch must advance timers with the async variant.

## Acceptance criteria

- **AC-1 (WI-1):** `directory-store.ts` exports `SCHEMA`, `PUT_CLIENT_SQL`, `loadDirectory`; `directory.ts` has no `load()` and is ≤ 490 lines; all connect tests pass.
- **AC-2 (WI-2):** `/healthz` returns `{ ok, configured, turn, apns, fcm }` and never a secret value; `parsePushConfig` nulls a provider with any missing value.
- **AC-3 (WI-3):** `fetchWithTimeout` rejects at 2,000 ms on fake timers; `pemToDer` round-trips a generated PKCS#8 key.
- **AC-4 (WI-4):** the APNs JWT verifies with the public key, is identical across caches and within a 45-minute window, changes after it; the request body equals exactly the FR-4 object; 410/dead reasons map to `gone`.
- **AC-5 (WI-5):** the FCM body equals exactly the FR-6 object with no `notification` key; the access token is reused until 5 minutes before expiry; 404/`UNREGISTERED` map to `gone`.
- **AC-6 (WI-6):** one retry after exactly 2 s for 5xx/network, none for 4xx; an unconfigured provider makes no request.
- **AC-7 (WI-7):** the decoder accepts a valid `push` and rejects each D-6 violation.
- **AC-8 (WI-8):** `push-register` persists via `PUT_CLIENT_PUSH_SQL`, survives a re-hello, refuses a platform mismatch; `push-unregister` clears it.
- **AC-9 (WI-9):** `unknown_client`, `no_registration` and the 31st-push `rate_limited` answers; offline phones still get `deliver-push`; `gone` clears only the matching token.
- **AC-10 (WI-10, epic AC-3):** on workerd, a `push` produces an APNs request whose body contains only the fixed placeholder text and the sealed blob, and an FCM data-only request with only the sealed blob; a 410 clears the registration; no log line holds a token, payload or credential.
- **AC-11 (WI-11):** `docs/CONNECT-SERVICE.md` has the "Phone push" section, the five secrets, the healthz shape and the push limit, and no "until push delivery (PAN-4830)" text.

## Non-goals

- The machine's native push provider, sealing, and reading `push-result` (PAN-4843).
- Phone-side registration, NSE and FCM handler (PAN-4838, PAN-4840).
- Live Activity pushes and the `push-activity` frame (PAN-4839).
- Setting production secrets, creating Apple/Firebase credentials, or deploying (PAN-4841; deploy is operator-only).
- User-facing Mintlify pages (PAN-4842).
- Changing `CONNECT_PROTOCOL_VERSION` or any contracts type.
- A persistent delivery queue or retries beyond the single 2 s retry.
