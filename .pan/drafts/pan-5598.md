# PAN-5598: Order books — every action from `pan orders` and as MCP tools

**Issue:** https://github.com/eltmon/overdeck/issues/5598
**Related:** PAN-5597 reworks the Order books page and is in flight on its own branch. This issue does not depend on its code. Read "Working beside PAN-5597" before you edit shared files.

## Problem

The operator asked that every way to interact with an order book be available from the `pan` command line and as an MCP tool. Today the dashboard page can do things neither surface can.

- `pan orders` has `create`, `list`, `show`, `add`, `remove`, `move`, `queue`, `start`. It cannot rename a book, set the parallel limit, set the extra-instructions file, pause or resume pickup, edit an issue's options after adding it, show the problems that block a book, preview the brief, or list backlog candidates.
- The Overdeck MCP server (`src/lib/mcp/`) has no order-book tools at all.
- The `/api/orders*` routes are missing from `ROUTE_SCOPES` in `src/dashboard/server/route-scopes.ts`. An unlisted route needs the `admin` scope, so a managed agent's token cannot call them.
- Even with a scope row, an MCP call to `DELETE /api/orders/:id/items/:issue` fails today: the route's `mutationAuth` calls `rejectUnsafeDashboardMutationRequest` (`src/dashboard/server/routes/dashboard-auth.ts`, line 282), which answers 400 `Content-Type must be application/json` when the header is missing, and both MCP clients send no `Content-Type` on `DELETE` (`src/lib/mcp/dashboard-api.ts` line 39: `if (method !== 'GET' && method !== 'DELETE')`; `src/lib/mcp/connector/channel-api.ts` line 270: `...(method === 'GET' || method === 'DELETE' ? {} : { body: body ?? {} })`). The dashboard page works because `LaneEditor.tsx` sends `dashboardMutationJsonHeaders()` on its `DELETE`.

## Glossary

- **Book**: an order book, a JSON file under `<planHome>/.pan/orders/`, type `OrderBook` in `packages/contracts/src/orders.ts`.
- **Parallel limit**: `settings.laneAConcurrency`, how many Lane A issues run at once. The dashboard stepper allows 1 to 8 (`LANE_A_MAX = 8` in `src/dashboard/frontend/src/components/orders/RunSettingsPanel.tsx`); the route only requires a positive integer.
- **Extra instructions file**: `settings.briefOverlay`, a repo-relative `.md` path added to every issue's kickoff brief. An empty string means none (the page writes `''` to clear it).
- **Pickup paused / open**: `settings.posture` is `drain` / `open`.
- **Issue options**: `prereqs` (issue ids that must land first), `reVerify` (re-check the PRD before starting), `planAtPickup` (write the plan when the issue starts).
- **Findings**: the result of `validateBookForStart` (`src/lib/orders/validate.ts`): `blocks` and `warns`. `GET /api/orders/:id` returns them as `validation`.
- **Overdeck tool**: an `OverdeckTool` object (`src/lib/mcp/tool.ts`). Each proxies one dashboard route through `ctx.api.request(method, path, body)`.
- **MCP client**: an implementation of `DashboardApi`. There are two: `createFetchDashboardApi` (`src/lib/mcp/dashboard-api.ts`, used by `/mcp` and `pan mcp serve`) and `createConnectorDashboardApi` (`src/lib/mcp/connector/channel-api.ts`, used by the bot connector through `linkFetch`).
- **Route scope**: the row in `ROUTE_SCOPES` that says which token scope a route needs. First match wins.
- **Telemetry domains**: closed value lists in `packages/contracts/src/telemetry.ts`. `TELEMETRY_CLIENT_ROUTES` must contain every `ROUTE_SCOPES` path (`src/dashboard/server/__tests__/route-scopes.test.ts`, "lists every scoped path as a telemetry client route"); `TELEMETRY_MCP_TOOLS` must equal the sorted `ALL_TOOLS` names (`tests/unit/lib/telemetry/mcp-domains.test.ts`). `docs/TELEMETRY.md` must list both domains verbatim (`tests/unit/telemetry-docs.test.ts`).
- **Plan home**: the repo that holds `.pan/` for a project. `panDirFor(deps)` in `src/cli/commands/orders.ts` resolves `<planHome>/.pan`.
- **callDashboard**: `src/cli/commands/dashboard-call.ts`, the CLI helper that calls the running dashboard with this machine's internal token and throws `DashboardUnreachableError` when nothing answers.

## Decisions

- **D1. No new HTTP routes.** Every MCP tool proxies an existing `/api/orders*` route. No row is added to `tests/unit/lib/overdeck/no-loss-matrix.ts`.
- **D2. Reads need `read:state`; writes need `operate`.** These are the scopes a managed agent's token already has (`AGENT_TOKEN_SCOPES` in `src/lib/mcp/agent-token.ts`).
- **D3. MCP tools are for every caller** (`audience: 'any'`), not agents only. Through the public funnel and the connector they behave like `start_issue`: the token's scope decides. No public-MCP or connector allowlist changes.
- **D4. The CLI writes the book file directly and commits it**, like the existing verbs (`commitOrders`). The CLI does not go through the dashboard, except for `check`, which needs the dashboard's issue cache.
- **D5. The status tool passes the value through.** `update_order_book` accepts `status` `ready`, `draft` or `complete` and sends it to `PATCH /api/orders/:id`. The route decides what is allowed. Until PAN-5597 merges the route accepts only `ready`; after it merges, all three work. Do not add a second check in the tool.
- **D6. New CLI verbs live in a new file** (`src/cli/commands/orders-edit.ts`) so this branch and PAN-5597 do not edit the same lines.
- **D7. DELETE with an explicit body sends JSON.** Both MCP clients change one condition: a `DELETE` whose `body` argument is not `undefined` sends `Content-Type: application/json` and the JSON body. A `DELETE` with no body keeps sending neither, so `unwatch_pull_request` and `delete_scheduled` are unchanged. `remove_order_book_issue` passes `{}`. The auth helper `rejectUnsafeDashboardMutationRequest` is not changed.
- **D8. `pan orders check` always sends `?project=<key>`.** It resolves the key on the CLI side (`--project`, else the registered project that contains the cwd, the same rule as every other verb) and calls `GET /api/orders/<id>?project=<key>` through `callDashboard`. Without the key, the route would resolve the dashboard process's cwd project instead.
- **D9. MCP tools validate the parallel limit as 1 to 8 and the CLI does too**, matching the dashboard stepper. The route is not changed.
- **D10. Route writes stay uncommitted.** The MCP write tools reach the same route the page uses; that route writes the book file and does not commit it (`src/lib/orders/io.ts` line 159: "the agent or operator that changed them commits them"). This issue does not change that.
