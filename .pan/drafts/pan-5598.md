# PAN-5598: Order books — every action from `pan orders` and as MCP tools

**Issue:** https://github.com/eltmon/overdeck/issues/5598
**Related:** PAN-5597 reworks the Order books page and is in flight on its own branch. This issue does not depend on its code. Read "Working beside PAN-5597" before you edit shared files.

## Problem

The operator asked that every way to interact with an order book be available from the `pan` command line and as an MCP tool. Today the dashboard page can do things neither surface can.

- `pan orders` has `create`, `list`, `show`, `add`, `remove`, `move`, `queue`, `start`. It cannot rename a book, set the parallel limit, set the extra-instructions file, pause or resume pickup, edit an issue's options after adding it, show the problems that block a book, preview the brief, or list backlog candidates.
- The Overdeck MCP server (`src/lib/mcp/`) has no order-book tools at all.
- The `/api/orders*` routes are missing from `ROUTE_SCOPES` in `src/dashboard/server/route-scopes.ts`. An unlisted route needs the `admin` scope, so a managed agent's token cannot call them.

## Glossary

- **Book**: an order book, a JSON file under `<planHome>/.pan/orders/`, type `OrderBook` in `packages/contracts/src/orders.ts`.
- **Parallel limit**: `settings.laneAConcurrency`, how many Lane A issues run at once (1 to 8).
- **Extra instructions file**: `settings.briefOverlay`, a repo-relative `.md` path added to every issue's kickoff brief.
- **Pickup paused / open**: `settings.posture` is `drain` / `open`.
- **Issue options**: `prereqs` (issue ids that must land first), `reVerify` (re-check the PRD before starting), `planAtPickup` (write the plan when the issue starts).
- **Findings**: the result of `validateBookForStart` (`src/lib/orders/validate.ts`): `blocks` and `warns`.
- **Overdeck tool**: an `OverdeckTool` object (`src/lib/mcp/tool.ts`). Each proxies one dashboard route through `ctx.api.request(method, path, body)`.
- **Route scope**: the row in `ROUTE_SCOPES` that says which token scope a route needs. First match wins.
- **Plan home**: the repo that holds `.pan/` for a project. `panDirFor(deps)` in `src/cli/commands/orders.ts` resolves `<planHome>/.pan`.

## Decisions

- **D1. No new HTTP routes.** Every MCP tool proxies an existing `/api/orders*` route. No row is added to `tests/unit/lib/overdeck/no-loss-matrix.ts`.
- **D2. Reads need `read:state`; writes need `operate`.** These are the scopes a managed agent's token already has.
- **D3. MCP tools are for every caller** (`audience: 'any'`), not agents only.
- **D4. The CLI writes the book file directly and commits it**, like the existing verbs (`commitOrders`). The CLI does not go through the dashboard, except for `check`, which needs the dashboard's issue cache.
- **D5. The status tool passes the value through.** `update_order_book` accepts `status` `ready`, `draft` or `complete` and sends it to `PATCH /api/orders/:id`. The route decides what is allowed. Until PAN-5597 merges the route accepts only `ready`; after it merges, all three work. Do not add a second check in the tool.
- **D6. New CLI verbs live in a new file** so this branch and PAN-5597 do not edit the same lines.
