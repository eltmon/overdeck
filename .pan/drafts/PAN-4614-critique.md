## blocks-the-design: GitHub conflict gate remains unverified

The PRD itself says GitHub may report `CONFLICTING` with `merge=union` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4614/.pan/drafts/PAN-4614.md), lines 101–107), then defers that check until after landing (lines 231–234). GitHub's result is the gate: [pr-facts.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4614/src/lib/cloister/pr-facts.ts), lines 483–486, maps `CONFLICTING` to `mergeable: false`; lines 983–989 refuse the merge unless `mergeable === true`. The merge queue checks that gate before starting the merge ([merge-strike.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4614/src/dashboard/server/routes/workspaces/merge-strike.ts), lines 140–172). The four planned tests exercise local rebase and `git merge-tree`, which do not settle GitHub's result. If GitHub reports `CONFLICTING`, concurrent PRs still enter the repair and review cycle that this issue aims to remove. The proposed documentation also promises that concurrent appends “never conflict” (PRD lines 197–204), despite this unresolved path.

Smallest resolution: make GitHub mergeability an explicit implementation checkpoint before claiming this fix complete. Verify it with a controlled concurrent PR pair, then specify the same-plan fallback if GitHub reports `CONFLICTING` (or explicitly narrow the objective to local rebases and correct the documentation). Keep the existing local-git tests for the rebase behavior.
