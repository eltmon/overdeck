## blocks-the-design: Gate-approved PRs are excluded from refresh

The refresher requires `pr.reviewState === 'approved'` ([approval-at-head-refresh.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/dashboard/server/services/approval-at-head-refresh.ts), lines 41–42), although derived `ready` requires the gate's approval answer and only rejects `changes-requested` ([derived-issue-state.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/lib/overdeck/derived-issue-state.ts), lines 163–177). GitHub self-authored PRs can have a trusted approval marker while `reviewDecision` remains empty ([pr-facts.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/lib/cloister/pr-facts.ts), lines 194–201). GitLab's gate obtains positive approval from `approved_by` via a separate endpoint (same file, lines 539–544 and 694–716), while the proposed listing derives `reviewState` from optional `row.approved` ([derived-issue-state.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/lib/overdeck/derived-issue-state.ts), lines 423–459). Thus a gate-approved PR in either case can lose `ready` when its answer expires and never be refreshed. The new test fixtures all set GitHub `reviewDecision: 'APPROVED'` ([approval-at-head-refresh.test.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/dashboard/server/services/__tests__/approval-at-head-refresh.test.ts), lines 20–36), so they miss both cases. Smallest plan change: make every open, non-draft, green, mergeable PR with a head eligible for a throttled gate check; let the gate decide approval, and test a marker-only GitHub PR and a GitLab MR whose `approved_by` is populated but listing `approved` is absent. The existing `evaluateIssueMergeGate` already performs that decision ([merge-gate.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/lib/cloister/merge-gate.ts), lines 96–120).

## blocks-the-design: The listing can omit open PRs

The new `listOpenPullRequestsForProject` filters `listRepoPullRequests` ([derived-issue-state.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/lib/overdeck/derived-issue-state.ts), lines 843–855), but that existing GitHub reader requests `--state all --limit 100` (same file, lines 343–368). GitLab likewise requests one `state=all&per_page=100` page (same file, lines 468–479). An older open PR can be outside these first 100 rows even with fewer than 100 open PRs. It receives no refresh, and the batch derived-state loader also uses the bounded GitHub listing (same file, lines 882–890), so the claimed “every PR” and Awaiting Merge behavior are false. Smallest plan change: require a complete, paginated open-PR candidate listing and account for the batch state loader's same cap; add a fixture with more than 100 mixed open and closed rows.

## blocks-the-design: The refresh pass can miss its TTL deadline

The PRD sets refresh age to three minutes against a five-minute answer TTL ([pan-4597.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/.pan/drafts/pan-4597.md), lines 19–31), leaving at most two minutes to renew an answer. The new pass awaits each project's listing and then each PR's gate evaluation in nested serial loops ([approval-at-head-refresh.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/dashboard/server/services/approval-at-head-refresh.ts), lines 58–80). A gate's GitHub PR read alone permits 15 seconds ([pull-requests.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/lib/overdeck/pull-requests.ts), lines 245–261); several slow PRs ahead of another can exhaust the margin and let that answer expire. One-minute interval invocations may also overlap because the hook does not await the prior pass ([uat-train.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/dashboard/server/services/uat-train.ts), lines 497–508). The existing auto-merge scheduler provides a single-flight, timed pass pattern ([auto-merge-scheduler.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4597/src/dashboard/server/services/auto-merge-scheduler.ts), lines 303–330). Smallest plan change: specify a bounded-concurrency, single-flight refresh that prioritizes oldest answers and verifies that multiple slow gate calls still renew all eligible heads before TTL.
