# PAN-4741: A public-link-only server advertises no endpoints

**Issue:** [PAN-4741](https://github.com/eltmon/overdeck/issues/4741) — Fly machine advertises private Fly IPs as lan routes ranked before its public route. Found in the [PAN-4652](https://github.com/eltmon/overdeck/issues/4652) live check, 2026-11-01.

## Glossary

- **Machine link** — a stored connection from this dashboard ("home") to another Overdeck server, held in `~/.overdeck/machine-links.json`. Each link has a list of **routes**.
- **Route** — one way to reach a linked machine: a transport URL (`tcp://host:port` or `wss://host/ws/link`), a **kind** and a **source** (`src/lib/anywhere/routes.ts`).
- **Route kind** — ranked best first `lan < tailnet < ssh < public < direct < relay` (`ROUTE_KINDS` in `@overdeck/contracts`). `rankRoutes` dials better kinds first.
- **Route source** — `manual` (Add route), `pairing` (the pairing URL), `advertised` (listed by the peer), `directory` (WebRTC, never stored).
- **Advertised endpoints** — the `{ kind, url }` list a server publishes in its environment descriptor (`GET /api/environment`, field `endpoints`) and over the directory hello. Computed by `discoverEndpoints` in `src/lib/anywhere/endpoints.ts`, cached by `EndpointAdvertiser`.
- **`mergeAdvertised`** — home's reconciliation (`src/lib/anywhere/routes.ts`): adds advertised endpoints the link lacks, **drops advertised routes no longer advertised**, never touches `pairing`/`manual` routes.
- **Public-link-only mode** — env `OVERDECK_PUBLIC_LINK_ONLY=1` (PAN-4652 FR-5). Rule 0b of the remote request gate 404s every HTTP request that is neither inside a secure channel nor a loopback caller. Only a linked Fly machine's server runs with it (`src/lib/anywhere/fly/provision.ts`, the `const env = ` line in step 8).
- **Fly machine** — a Fly.io VM running `pan serve`, linked one way from home over the `public` pairing route `wss://<app>.fly.dev/ws/link?fly-instance=<machineId>`.

## Problem

A Fly machine's server computes its advertised endpoints from its interface table like any other server. Its `eth0` carries Fly's private IPv4 (`172.19.x.y`), which `isRfc1918IPv4` accepts, so the descriptor lists `{ kind: 'lan', url: 'tcp://172.19.x.y:3011' }`. Home stores it through `mergeAdvertised` (at link creation in `machine-link-service.ts` and on every connect in `link-supervisor.ts` `applyDescriptor`). `rankRoutes` puts `lan` before `public`, so every reconnect dials the unreachable private address first, waits for it to fail and mark `unreachable`, then falls back to the public route. The link still comes online, but every reconnect is slower than it needs to be.

The server is in public-link-only mode, whose contract is "nothing but the public link reaches this server". Advertising private interface addresses contradicts that contract.

## Decision

**D-1 (chosen): a server with `OVERDECK_PUBLIC_LINK_ONLY=1` advertises no endpoints at all.** `discoverEndpoints` already returns `[]` under `OVERDECK_ANYWHERE_NO_ADVERTISE=1`; extend that early return to also fire when `OVERDECK_PUBLIC_LINK_ONLY === '1'`. This is the issue's first option.

Why this option and not home-side filtering (the issue's second option):

1. The server is the authority on how it can be reached. Fixing the source makes every future public-link-only server correct, not just Fly ones, and keeps Fly-specific knowledge (`fly-instance`) out of the generic route merge.
2. Fly provisioning forces the VM onto home's exact `pan` version (`provision.ts` step 4, "Version equality by install (D-7)", search `const want = await deps.localVersion()`). A VM-side fix therefore reaches every newly provisioned Fly machine as soon as home has it; there is no version-skew case for new machines.
3. Links created before the fix heal themselves with no migration: once the VM's descriptor lists no endpoints, `mergeAdvertised(routes, [])` drops every `advertised` route, and `applyDescriptor` persists the result with `setLinkRoutes` and deletes their `routeStatus` entries. A Fly machine that was already running an older `pan` keeps advertising until it is destroyed (unlink, idle sweep, stopped sweep — Fly machines are never restarted), which is acceptable because it still links over the public route.
4. Side benefit: the early return skips the `tailscale status --json` probe (5 s timeout) on the VM.

"Advertise nothing" rather than "advertise no `lan`": the mode means only the public link reaches this server, so `tailnet` IP and Tailscale Serve endpoints are equally out of contract. A Fly VM has no Tailscale anyway.

**D-2: read the env var directly in `src/lib/anywhere/endpoints.ts`.** Do NOT import `publicLinkOnly` from `src/dashboard/server/remote-request-gate.ts`: `src/lib` must not import dashboard-server code (layering inversion, and `lint:circular` guards cycles). Do not hoist a shared helper either; one inline comparison matching the `OVERDECK_ANYWHERE_NO_ADVERTISE` line is the whole change. Use the exact `=== '1'` comparison so it agrees with `publicLinkOnly()` (which treats `'true'` as off).

## Requirements

- **FR-1** With `OVERDECK_PUBLIC_LINK_ONLY=1`, `discoverEndpoints` resolves to `[]` whatever the interface table holds, so `GET /api/environment` lists `endpoints: []` and the heartbeat `endpointsHash` is `''`.
- **FR-2** With `OVERDECK_PUBLIC_LINK_ONLY=1`, `discoverEndpoints` does not run `tailscale status --json` and does not fetch a Tailscale Serve URL.
- **FR-3** With `OVERDECK_PUBLIC_LINK_ONLY` unset (or any value other than `'1'`), `discoverEndpoints` behaves exactly as today.
- **FR-4** The docs state that a public-link-only server advertises no endpoints, so home reaches a Fly machine only over its public `wss://<app>.fly.dev` route.
- **NFR-1** No new import from `src/dashboard/server/` into `src/lib/`.
- **NFR-2** Tests restore the environment (`vi.stubEnv` + `vi.unstubAllEnvs` in `finally`), matching the existing NO_ADVERTISE test.

### WI-1 — Public-link-only servers advertise nothing (FR-1, FR-2, FR-3, NFR-1, NFR-2)

**Files:** `src/lib/anywhere/endpoints.ts`, `src/lib/anywhere/__tests__/endpoints.test.ts`.

**Step 1.** In `src/lib/anywhere/endpoints.ts`, function `discoverEndpoints` (search `export async function discoverEndpoints`, line ~113).

Before:

```ts
/**
 * Everything this machine advertises, deduplicated and sorted by URL. `OVERDECK_ANYWHERE_NO_ADVERTISE=1`
 * advertises nothing (PAN-2356): the directory smoke uses it so two dashboards on one host can only
 * reach each other over the `direct` route.
 */
export async function discoverEndpoints(deps: DiscoverEndpointsDeps): Promise<AdvertisedEndpoint[]> {
  if (process.env['OVERDECK_ANYWHERE_NO_ADVERTISE'] === '1') return [];
```

After:

```ts
/**
 * Everything this machine advertises, deduplicated and sorted by URL. `OVERDECK_ANYWHERE_NO_ADVERTISE=1`
 * advertises nothing (PAN-2356): the directory smoke uses it so two dashboards on one host can only
 * reach each other over the `direct` route. `OVERDECK_PUBLIC_LINK_ONLY=1` (a linked Fly machine) also
 * advertises nothing (PAN-4741): only its public pairing route reaches it, and its private Fly
 * addresses would otherwise rank before that route as unreachable `lan` routes.
 */
export async function discoverEndpoints(deps: DiscoverEndpointsDeps): Promise<AdvertisedEndpoint[]> {
  if (process.env['OVERDECK_ANYWHERE_NO_ADVERTISE'] === '1' || process.env['OVERDECK_PUBLIC_LINK_ONLY'] === '1') return [];
```

Also add one line to the module header's bullet list (top of the file, after the `tailnet` bullet) — e.g. "A server in public-link-only mode (`OVERDECK_PUBLIC_LINK_ONLY=1`) advertises nothing (PAN-4741)."

**Step 2.** In `src/lib/anywhere/__tests__/endpoints.test.ts`, next to the test `'advertises nothing under OVERDECK_ANYWHERE_NO_ADVERTISE=1 (PAN-2356 directory smoke)'`, add:
