## Problem

After the cut, three routes derive issue state at request time by walking the whole issue universe:

| Route | What it does per request today | Live timing (2026-09-19, load avg 17) |
| --- | --- | --- |
| `GET /api/parked` (`routes/parked.ts` 63–145) | Candidate universe = live panes ∪ every tracker issue (1302 issues: PAN 975, MIN 114, LEX 212, KRUX 1). Groups by project and calls the batch door per project. | 184s cold, 78s warm |
| `GET /api/merge-train/auto-merge` (`routes/merge-train.ts` 613–647) | For each of the 13 registered projects, serially: `gh pr list` (0.7s each; fails and returns `[]` in the two GitLab projects and in projects without a remote), then the batch door over the PR-bearing issue ids. | 12.9s cold, 21.8s warm |
| `GET /api/agents` (`routes/agents/listing.ts` 82–121) | `Promise.all` over 846 registered agent states; every stopped agent calls the single-issue door (`getDerivedIssueState`, line 116) — three `git` execs each, all launched concurrently. Result cached 5s (`AGENTS_CACHE_TTL_MS`, `agents/shared.ts` line 204). | 15.1s cold, 11.7s warm |

The root cost is inside the batch door itself. For every issue that has no row in the 200-PR listing — which is nearly every one of the 975 PAN issues — it runs `readBranchWithGit` (lib lines 388–405): three sequential `execFile('git', …)` calls (`rev-list --count`, `rev-parse origin/<branch>`, `rev-parse <branch>`), awaited one issue at a time (lib lines 691–693). It also re-reads the specs directory (`specExistsFor`, lines 416–425, two `readdirSync` per issue) and `parked.md` (`parkedListedIn`, lines 427–435, one `readFileSync` per issue). Idle, 975 × 3 execs ≈ 10s; on the loaded live box it is minutes.

The issue service already keeps a derived-state cache that is refreshed off the tracker poll, and the read model already seeds its snapshot from it (`read-model.ts` 437–451). The routes do not read it. Two facts stop a naive "just read the cache" fix:

1. The cache only refreshes when a tracker poll reports changed issues. PR-driven transitions (`in-review` → `ready`) never refresh it, so a pure cache read would go stale for as long as the tracker is quiet.
2. It is empty until the first poll-and-refresh completes after boot. The God View fetches `/api/parked` once and refetches only on a `sweep.scan` event (`docs/GOD-VIEW.md` line 88), so an empty answer at boot would stay empty.

## Proposal

1. **Make the batch door cheap** (lib): one `git for-each-ref` per project instead of three execs per issue; read the specs directory and `parked.md` once per call. This shrinks both the request path and the existing background `refreshDerivedStates`, which today burns the same cost on every tracker change.
2. **Add a TTL read-through door on the derived-state cache** owned by the issue service: `ensureDerivedStates(issueIds)` serves entries younger than 30s, recomputes the rest through the batch door grouped by project with single-flight per project, stores them, and emits changes through the existing `onDerivedStatesChanged` hook. The logic lives in a new small module so `issue-data-service.ts` does not grow past its ratchet row.
3. **Re-point the three routes** at that door. `/api/parked` keeps its candidate universe. `/api/merge-train/auto-merge` takes its candidates from the tracker issues instead of a per-project forge listing, so it issues zero forge reads at request time. `/api/agents` collects every registered agent's issue id, calls the door once, and looks up.
4. **Docs and headers** that state the old cost model are corrected.

Empty-cache at boot is handled by the read-through (the route computes on a miss); staleness is handled by the TTL (30s, matched to the PR listing TTL so a recompute never runs against an unchanged forge answer).

## Requirements

### Functional

- **FR-1** The batch door derives N PR-less issues of one project with exactly one branch-listing `git` exec, not 3×N.
- **FR-2** The batch door reads the project's specs directory and `parked.md` at most once per call, not once per issue.
- **FR-3** The issue service exposes `ensureDerivedStates(issueIds)` returning `Map<issueId, DerivedIssueState>`; an entry computed within `DERIVED_STATE_TTL_MS` is served from the cache, any other entry is recomputed through the batch door.
- **FR-4** Concurrent `ensureDerivedStates` calls that need the same project share one batch computation (single-flight per project path).
- **FR-5** A recomputed entry whose value differs from the cached one is reported through `onDerivedStatesChanged`; an unchanged entry is not.
- **FR-6** `GET /api/parked` returns the same rows as today for the same facts, sourced from `ensureDerivedStates`, and issues no per-issue `git` exec at request time.
- **FR-7** `GET /api/merge-train/auto-merge` returns `{ issues: [{ issueId, autoMerge }] }` for every tracker issue whose derived state is in-flight, and calls `listRepoPullRequests` zero times at request time.
- **FR-8** `GET /api/agents` decides `keepStoppedAgentVisible` from one `ensureDerivedStates` call over every registered agent's issue id, and never calls the single-issue door.
- **FR-9** The background refresh scheduled by the tracker poll (`refreshDerivedStates`) recomputes unconditionally (TTL ignored) through the same cache module, so there is one implementation.

### Non-functional

- **NFR-1** No `execSync` anywhere in this change (dashboard-server-reachable code); all process reads go through `execFileAsync`.
- **NFR-2** Every TTL/time test injects `now` (the cache takes `now: () => number`); no real waits and no `setTimeout` in tests.
- **NFR-3** `issue-data-service.ts` does not exceed its allowlist line count; if the diff grows it, the `scripts/file-size-allowlist.txt` row is updated in the same commit to `<lines> src/dashboard/server/services/issue-data-service.ts # PAN-3925`. Preferred outcome: the file shrinks because refresh logic moves out.
- **NFR-4** On the live server, with the cache warm (second of two consecutive calls), `/api/parked` and `/api/merge-train/auto-merge` answer in under 1s and `/api/agents` in under 3s (it still reads `health.json`, runtime state, and remote state per registered agent — 846 today — which this PRD does not touch). UAT measurement with `curl -w '%{time_total}'`; not a unit AC.
- **NFR-5** Existing test seams keep working: callers that inject `readBranch` (e.g. `derived-issue-state-server-facts.test.ts`, `tests/unit/dashboard/routes/resources-reclaim.test.ts`) get per-issue behavior unchanged.

## Decisions

- **D1 — TTL read-through, not pure cache.** Pure cache reads regress the God View (empty at boot, no refetch until `sweep.scan`) and go stale on PR-only changes. Read-through fixes both; the cost of a miss is bounded by D2.
- **D2 — `DERIVED_STATE_TTL_MS = PR_CACHE_TTL_MS` (30s).** A recompute inside the PR-listing TTL would re-derive against the same cached forge answer; a shorter TTL buys nothing.
- **D3 — The cache logic lives in a new module `src/dashboard/server/services/derived-state-cache.ts`**, class `DerivedStateCache`, with every IO injected. `IssueDataService` holds one instance and delegates `getDerivedState`, `listDerivedStates`, `refreshDerivedStates`, and the new `ensureDerivedStates`. Reason: ratchet (NFR-3) and offline tests.
- **D4 — Branch facts come from `git for-each-ref` with `%(ahead-behind:origin/main)`** (git ≥ 2.41; the live box runs 2.43.0, measured 0.05s for 483 refs). If that exec fails with stderr matching `unknown field name` (verified: git 2.43 prints `fatal: unknown field name: bogusfield`; a missing base prints `fatal: failed to find 'origin/main'`, which must NOT take this branch), fall back to a plain `for-each-ref --format='%(refname) %(objectname)'` plus one `rev-list --count origin/main..<branch>` per LOCAL feature branch (bounded by branch count, ~241 in overdeck, not by issue count). If `for-each-ref` fails for any other reason (not a git repo — `/home/eltmon/Projects/myn` is a polyrepo wrapper; no `origin/main`), the project has no branch facts, which is today's behavior (`readBranchWithGit` returns `null`).
- **D5 — Only LOCAL `refs/heads/feature/*` produce a branch entry.** Today `rev-list --count origin/main..feature/x` fails when no local ref exists (git does not DWIM `feature/x` to `origin/feature/x`), so remote-only branches derive no branch. Parity kept. `pushed` = local sha equals `refs/remotes/origin/feature/x` sha.
- **D6 — Seam precedence in the batch door:** if the caller passed `readBranches`, use it; else if the caller passed `readBranch`, keep today's per-issue path for PR-less issues (test seams); else use the git lister.
- **D7 — `ensureDerivedStates` emits `onDerivedStatesChanged` but never calls `pushSnapshot()`.** The read model turns those into `issue_state.changed` events; a full issues snapshot push on every route read is unnecessary. The poll-driven `refreshDerivedStates` keeps its `pushSnapshot()` on change (today's behavior).
- **D8 — `/api/merge-train/auto-merge` candidates = every issue in `getSharedIssueService().getIssues()`.** In-flight states are only ever derived for open issues that the tracker knows, so this loses nothing for tracked projects. It drops rows for an open PR in a project whose tracker is not polled (see Non-goals); the toggle renders a missing row as "Not routed yet" (`AutoMergeToggle.tsx` lines 56–57).
- **D9 — `/api/agents` semantics:** the batch door sets `apiError: false` (lib line 705) where the single-issue door reads pane text. `keepStoppedAgentVisible` (listing.ts 117–120) uses only `state` and `pr`, so the answer is identical.
- **D10 — Time source for TTL:** the cache class takes `now?: () => number` and `ttlMs?: number` in its constructor; production passes nothing.

## Non-goals

- Making the derived-state cache refresh on a fixed cadence regardless of tracker changes (the read model's own staleness on PR-only changes when NO route reads happen). Route reads now refresh what they touch; a cadence is a separate issue.
- Fixing `listCandidateIssueIds` running `gh pr list` inside GitLab projects (it returns `[]` there today). The function is deleted by this PRD; GitLab auto-merge routing is a separate issue.
- Deriving states for issues that have an open PR but no tracker row (untracked projects such as `papers-please`, `orca`). They were candidates before only via the forge listing; after D8 they have no auto-merge row.
- Touching the other ~20 per-request `getDerivedIssueState` callers (`command-deck.ts`, `merge-ops.ts`, `metrics.ts`, `system-health-service.ts`, …). Only the three routes the issue names.
- Changing the parked orbit rules, the FR-6 table, or the auto-merge policy rules.
- Frontend changes. Response shapes are unchanged.

```ts
/** Every local feature branch of one repo, keyed by branch name (`feature/pan-1`). */
export type FeatureBranchMap = ReadonlyMap<string, DerivedBranchState>;

/**
 * One `git for-each-ref` per repo (D4/D5). Local `refs/heads/feature/*` rows
 * become entries; `refs/remotes/origin/feature/*` rows only decide `pushed`.
 */
export async function listFeatureBranchesWithGit(projectPath: string): Promise<FeatureBranchMap> {
  const format = '%(refname) %(objectname) %(ahead-behind:origin/main)';
  const refs = ['refs/heads/feature/', 'refs/remotes/origin/feature/'];
  let stdout: string;
  try {
    ({ stdout } = await execFileAsync('git', ['for-each-ref', `--format=${format}`, ...refs],
      { cwd: projectPath, encoding: 'utf-8', timeout: 15_000, maxBuffer: 16 * 1024 * 1024 }));
  } catch (error) {
    // Verified 2026-09-19: git prints `fatal: unknown field name: <field>` for an
    // unsupported format atom, and `fatal: failed to find 'origin/main'` when the
    // base ref is missing — only the first means "old git", the second means "no facts".
    if (!/unknown field name/.test(String((error as { stderr?: string }).stderr ?? ''))) return new Map();
    return listFeatureBranchesWithoutAheadBehind(projectPath); // D4 fallback, git < 2.41
  }
  return parseFeatureBranchRefs(stdout);
}

/** Pure: `refs/heads/feature/x <sha> <ahead> <behind>` lines → the map. Exported for tests. */
export function parseFeatureBranchRefs(stdout: string): FeatureBranchMap { /* … */ }
```

   `parseFeatureBranchRefs`: for each non-empty line split on whitespace into `[ref, sha, ahead, behind]`. `refs/heads/feature/<x>` → local entry `{ name: 'feature/<x>', sha, aheadOfMain: Number.parseInt(ahead, 10) || 0 }`; `refs/remotes/origin/feature/<x>` → remote sha for `feature/<x>`. Output entry per LOCAL branch: `{ name, aheadOfMain, pushed: remoteSha !== undefined && remoteSha === sha }`.

A branch whose `rev-list` fails is DROPPED from the map (no entry), never emitted with `aheadOfMain: 0`. Same output shape.

export class DerivedStateCache {
  private readonly entries = new Map<string, Entry>();
  private readonly inFlight = new Map<string, Promise<void>>(); // per projectPath
  constructor(private readonly deps: DerivedStateCacheDeps) {}

  get(issueId: string): DerivedIssueState | null
  list(): DerivedIssueState[]
  /** FR-3/FR-4: fresh entries from memory; the rest recomputed, grouped by project, single-flight. */
  ensure(issueIds: readonly string[]): Promise<Map<string, DerivedIssueState>>
  /** FR-9: recompute regardless of age. Returns the changed states. */
  refresh(issueIds: readonly string[]): Promise<readonly DerivedIssueState[]>

   Decision rules inside `ensure`:
   - Upper-case every id and collapse them to a `Set` first — `/api/agents` passes one id per registered agent, so duplicates are the norm.
   - An id is *fresh* when `now() - entry.computedAt < ttlMs`.
   - Stale projects are computed in parallel (`Promise.all` over the per-project promises), never serially; the per-project single-flight below is what bounds concurrency.
   - Group stale ids by `resolveProject(id).projectPath`; ids with no project are skipped (today's behavior in `refreshDerivedStates`).

A thrown `loadStates` keeps previous entries (today's behavior) and resolves the promise.
   - Return a `Map` of every requested id that has an entry (fresh or just computed).
   - `refresh(ids)` = the same with `ttlMs` treated as 0 for this call; returns the changed list.
