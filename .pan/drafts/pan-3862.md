# PAN-3862 — /agents-v2 machine session explorer

Issue: https://github.com/eltmon/overdeck/issues/3862
Research date: 2026-09-17 UTC. Additive route; retain /agents.

## Glossary

- Environment: authoritative Overdeck server on a machine (PAN-3762).
- Source: one reachable terminal backend/server namespace on an execution host.
- Managed session: terminal linked to an Overdeck agent or conversation by a persisted reference.
- External session: accessible terminal not owned by Overdeck; discovery does not adopt it.
- Inventory: current observed sources/sessions/panes, separate from historical agent records.
- Coverage gap: a source that could not be inspected; this is not evidence of an empty machine.
- Liveness: live, exited or unverifiable. Work state: working, idle, blocked or unknown. Completion is separately recorded pipeline evidence.

## Problem and intended experience

The current /agents page is a managed-agent fleet backed by retained records; it is not a machine terminal inventory. The new /agents-v2 page answers what actually exists on this machine, in both Herdr and tmux, including conversations and external shells. A machine-first hierarchy must not describe every shell as an AI agent.

The initial view is Local → source/backend → server/session → workspace/tab/pane (omit hierarchy levels not present). Show backend, host, cwd, title, ownership, process liveness and available agent state. Provide search, backend/host/ownership/state filters, refresh, source diagnostics and selected-pane preview. Observe by default; Control is explicit. Managed rows retain links to their issue/conversation and existing actions. External rows cannot invoke pipeline operations until explicitly adopted by a future feature.

“All sessions” means sessions accessible to the current OS user in discovered/configured sockets and namespaces. Do not promise root-wide enumeration, inspect other users' terminals, or hide gaps. Custom tmux socket locations need a setting. A failed source must not hide healthy ones. Remote host/environment tabs arrive through PAN-3863/PAN-3762, using the same scoped references.

- FR-8: Remote sources use PAN-3762 environments and PAN-3863 host refs. A Herdr saved-machine profile targets one remote session; it does not enumerate every host session automatically.
- FR-9: Enforce scoped read/control authorization server-side; opaque session refs resolve privately on the owning host. Reject arbitrary socket paths and foreign refs supplied by browser.

## Chosen architecture and before/after

The existing page reads `useDashboardStore(selectAgents)`. That selector returns Object.values(agentsById), which includes retained history; the server bootstraps it from AgentsResolver.list({}). A terminal inventory must come from backend observations and join lifecycle records afterward.

```ts
// Before: managed record list
const agents = useDashboardStore(selectAgents);
// After: proposed dedicated, scoped inventory query
const inventory = useSessionInventory({ environmentId, hostId, cursor, filters });
const selected = inventory.sessions.find(s => s.refKey === selectedRefKey);
```

Create a terminal-session domain door at `src/lib/overdeck/terminal-sessions.ts`, backed only by PAN-3861's backend registry and existing agent/conversation resolvers. Add `src/lib/terminal-backends/discovery.ts` for OS-user socket discovery. Discovery is an observation, not a writer of canonical agent state. Never move the existing /api/agents data into a second store.

Proposed endpoint: authenticated `GET /api/terminal-sessions`, plus `/api/terminal-sessions/:opaqueRef/output` and `/ws/terminal-sessions/:opaqueRef` adapters to existing terminal authorization/stream services. Exact routing registration follows current HttpRouter layers. Query scoping includes environmentId at the federated client; the receiving server validates local ownership. Read returns `{sources, sessions, nextCursor, observedAt}`; each source includes `{id, backend, hostId, state, lastSuccessAt, error}`. It must be possible to report sources=[] with a discovery error rather than claiming “No sessions.”

For tmux, list each approved socket via async argv `tmux -S <resolvedSocket> list-sessions/list-windows/list-panes` with explicit format fields. Collect pane_id, window_id, session_id, pane_dead, pane_pid, cwd and title in bounded batches. Do not use managed-only buildTmuxArgs for every source because it forces the overdeck namespace. Do not run ensureOverdeckTmuxServer during discovery. Do not infer provider/model from arbitrary process arguments containing credentials.

For Herdr, list known namespaces using session list JSON; query a running source's session.snapshot/pane.list and agent.list through the adapter. Use stable terminal_id for pane moves when available. Source restart advances generation so a reused short pane ID cannot inherit a stale browser controller. Remote machine forwarding can inspect one saved session; remote full inventory requires owner-host discovery through the host service/environment.

| Existing fleet surface | Home after this change |

| /agents URL, grid/table/timeline, view query | Retained unchanged, except PAN-3864 lifecycle correction. |
| Phase/project/model filters and URL restoration | Retained /agents; v2 adds host/backend/ownership filters. |

| Issue action menu and issue navigation | Retained on managed agent rows; v2 reuses the same action registry. |
| Start agent CTA and pending-input/permission navigation | Retained /agents and linked from managed v2 details. |

| Finished strike outcome inspection | History, preserving transcripts/session refs (PAN-3864). |

Encode this table in a test fixture with actionable target route/component, not only prose. Any later replacement of /agents requires a fresh audit and a separate explicit decision.

Herdr's rich TUI remains available; this page exposes operational inventory rather than rebuilding every layout/plugin editor.
