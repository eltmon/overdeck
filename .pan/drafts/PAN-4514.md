# PAN-4514 — Reject non-decision AskUserQuestion calls before they reach the operator

**Issue:** [PAN-4514](https://github.com/eltmon/overdeck/issues/4514)
**Mode:** `pan plan --auto` (no operator Q&A; defaults recorded under "Decisions").

## Glossary

- **AUQ** — Claude Code's `AskUserQuestion` tool. Input shape: `{ questions: [{ question, header, multiSelect, options: [{ label, description }] }] }`.
- **AUQ hook** — `sync-sources/hooks/ask-user-question-hook`, a bash PreToolUse hook (PAN-1520) registered with matcher `AskUserQuestion` in `src/lib/claude-hooks-registration.ts` (grep: `scriptName: 'ask-user-question-hook', matcher: 'AskUserQuestion'`). `pan sync` copies it to `~/.overdeck/bin/`. Today it **denies every** AUQ call with a reason that tells the agent the question was "surfaced to the operator".
- **Surface deny** — the existing deny verdict. Its `permissionDecisionReason` contains the literal marker `PAN-1520` and the phrase `surfaced to the operator`.
- **Detector** — `scanPendingInputs()` in `src/lib/agent-enrichment.ts`. It reads the session JSONL. An AUQ `tool_use` whose `tool_result` has `is_error: true` **and** contains `PAN-1520` or `surfaced to the operator` is treated as "pending, awaiting operator" and becomes `pendingAskUserQuestion` → the dashboard `AskUserQuestionDialog` modal. Any other `tool_result` (including an `is_error` deny without those strings) marks the AUQ **answered**, so no modal.
- **Junk AUQ** — an AUQ call that is not a real operator decision: empty, placeholder text, degenerate options, or self-described status/informational text.
- **Guard deny** — the new deny verdict this issue adds for junk AUQs. Its reason MUST NOT contain `PAN-1520` or `surfaced to the operator`.
- **Kickoff prompt** — `src/lib/cloister/prompts/work.md`, rendered by `src/lib/cloister/work-agent-prompt.ts` as the work agent's first message.
- **Role file** — `roles/work.md`, loaded as the agent definition (`claude --agent roles/work.md`, see `src/lib/agents/spawn-prep.ts` comment "emits 'claude --agent roles/<role>.md").

## Problem

On 2026-10-04 02:38–02:39 the PAN-4260 work agent started a background Monitor on its lint run, said it would wait for the notification, then called AUQ three times in 35 s:

1. `{"questions": []}` — schema-rejected by Claude Code (never reached the hook in practice).
2. header `x`, question `placeholder`, options `a` / `b` — surfaced to the operator as a modal.
3. "Status check only (no action needed): I'm mid-task… This is informational, not a decision point", option "Acknowledge" — surfaced.

## Root cause (verified)

1. **Hook has no content check.** `sync-sources/hooks/ask-user-question-hook` lines 37–92: after the `tool_name` check it emits an `ask_user_question_blocked` event (lines 42–57) and unconditionally returns the surface deny (line 59, `REASON='Your question has been surfaced to the operator in the Overdeck dashboard (PAN-1520)…'`). The detector then turns every such call into a modal.
2. **The kickoff prompt leaves no legal way to idle.** `src/lib/cloister/prompts/work.md`:
   - line 269: `- Use \`sleep\` to wait for reviews, tests, or any external process` (in the NEVER list);
   - line 286: `**CRITICAL: NEVER stop working without calling \`pan done\`.** If you have remaining tasks, keep going — do NOT end your turn to "wait for input." … Ending your turn without either continuing work or calling \`pan done\` is a failure state…`.
   An agent with a Monitor or `run_in_background` Bash task running cannot sleep and believes it cannot end its turn, so it reaches for AUQ as the only remaining pause. Neither `roles/work.md` nor the kickoff prompt says that ending the turn while a background task/Monitor runs is the correct wait.

## Requirements

- **FR-1** The AUQ hook classifies each call before any side effect. A junk AUQ (rules in FR-2) gets a guard deny and the hook exits; it emits no `ask_user_question_blocked` event and returns no surface deny.
- **FR-2** Junk rules, evaluated per question; the call is junk if `tool_input.questions` is missing, not an array, or empty, or if **any** question matches a rule. Text is trimmed; comparisons are case-insensitive.
  - R1 placeholder question: question text length ≤ 3, or equals one of `placeholder`, `test`, `todo`, `tbd`, `foo`, `xxx`, `n/a`, `...`.
  - R2 placeholder header: header is non-empty and (length ≤ 1, or equals one of `placeholder`, `todo`, `tbd`, `foo`, `xxx`). (`test` is excluded for headers — a 12-char header chip like "Test" can be real.)
  - R3 fewer than two options.
  - R4 duplicate option labels (trimmed, lowercased).
  - R5 every option label is ≤ 1 character **and** no option has a non-empty description.
  - R6 status-only text: `question + " " + header` matches regex (case-insensitive) `no action (is )?(needed|required)|status (check|update) only|informational only|(this is|purely|just) (informational|an fyi|fyi)|not a decision( point)?|nothing to decide|no decision (is )?(needed|required)`.
- **FR-3** Guard deny output: `hookSpecificOutput.hookEventName = "PreToolUse"`, `permissionDecision = "deny"`, `permissionDecisionReason` = `AskUserQuestion is for decisions only (PAN-4514). Rejected: <rule reason>. To wait for a background task or Monitor, end your turn; its notification wakes you. To report status, write it as text.` No `additionalContext`. The reason MUST NOT contain `PAN-1520` or `surfaced to the operator`.
- **FR-4** A real question (meaningful header, a question, two or more distinct options) gets exactly today's surface deny, event, and additionalContext — byte-for-byte unchanged behavior.
- **FR-5** Fail-open: if the classifier jq expression errors or prints nothing, the hook takes the existing surface path. A false negative is today's behavior; a false positive would suppress a real decision.
- **FR-6** The detector treats a guard-denied AUQ as answered: `scanPendingInputs()` on a JSONL with an AUQ `tool_use` followed by an `is_error` `tool_result` carrying the guard reason returns `askUserQuestions: []`. No change to `agent-enrichment.ts` is needed; a contract test pins it.
- **FR-7** The kickoff prompt carves out background waits: ending the turn while a Monitor or background task you started is still running is the correct way to wait, is not parking, and its notification wakes you. AUQ is only for real operator decisions — never to pause, wait, or report status.
- **FR-8** `roles/work.md` gets a short "Waiting on background work" section with the same rule. The commit carries a `Prompt-Change:` trailer.
- **NFR-1** The hook still never breaks Claude Code: exit 0 on every path, silent pass-through when `jq` is missing or `tool_name` differs.
- **NFR-2** No new runtime dependency; guard logic is jq inside the existing bash hook.

## Decisions (auto mode)

- **D1 Guard lives only in the hook.** The issue names the hook as the fix point; the detector already ignores denies without the PAN-1520 markers, so no detector or frontend change is needed.
- **D2 Single-letter rule is narrow (R5).** Only "all labels ≤ 1 char AND no descriptions". The existing contract fixture uses `A`/`B` *with* descriptions ("Fast path"/"Safe path") and is a real question; "Option A / Option B" with descriptions is a common legitimate pattern. Case 2 of the incident (`a`/`b`) had no descriptions and is also caught by R1 and R2.
- **D3 Status-only regex is phrase-based (R6)**, never the bare word `informational`, so "Should the default log level be informational or debug?" still surfaces. Prototyped with jq against the incident payloads and real questions.
- **D4 Fail-open (FR-5).**
- **D5 Prompt scope: work role only** — `roles/work.md` and the kickoff prompt. `roles/review.md` and `roles/test.md` have no waiting-on-background guidance to share ("if they share it" in the issue), so they are untouched.
- **D6 Existing test fixture update.** `tests/scripts/ask-user-question-hook.test.ts` "emits a dashboard event" uses `{ question: 'Q', options: [{ label: 'A' }, { label: 'B' }] }` — junk under R1/R5. Replace it with a real question; do not weaken the rules to keep it.

### WI-1 Hook guard (FR-1..FR-5, NFR-1, NFR-2)

File: `sync-sources/hooks/ask-user-question-hook`.

1. After the `TOOL_NAME` check (current line 38–40) and **before** the `SCRIPT_DIR=` / event block (current line 42), add:

```bash
# PAN-4514 — reject non-decision calls (placeholders, status-only "questions")
# before anything reaches the dashboard. The reason below MUST NOT contain the
# PAN-1520 marker or the 'surfaced to the operator' phrase, or the detector in
# src/lib/agent-enrichment.ts would treat the call as pending and show a modal.
GUARD_REASON=$(echo "$INPUT" | jq -r '
  def norm: (. // "") | tostring | gsub("^\\s+|\\s+$"; "");
  def status_only_re: "no action (is )?(needed|required)|status (check|update) only|informational only|(this is|purely|just) (informational|an fyi|fyi)|not a decision( point)?|nothing to decide|no decision (is )?(needed|required)";
  def question_reject:
    (.question | norm) as $q
    | (.header | norm) as $h
    | (.options // []) as $opts
    | ($opts | map(.label | norm | ascii_downcase)) as $labels
    | if ($q | length) <= 3 or (["placeholder","test","todo","tbd","foo","xxx","n/a","..."] | index($q | ascii_downcase)) != null then "placeholder question text"
      elif ($h != "") and (($h | length) <= 1 or (["placeholder","todo","tbd","foo","xxx"] | index($h | ascii_downcase)) != null) then "placeholder header"
      elif ($opts | length) < 2 then "fewer than two options"
      elif ($labels | unique | length) < ($labels | length) then "duplicate option labels"
      elif ($opts | all((.label | norm | length) <= 1 and ((.description | norm) == ""))) then "single-letter options with no descriptions"
      elif (($q + " " + $h) | test(status_only_re; "i")) then "status-only text, not a decision"
      else empty end;
  (.tool_input.questions) as $qs
  | if ($qs | type) != "array" or ($qs | length) == 0 then "no questions"
    else ([$qs[] | question_reject] | first // empty) end
' 2>/dev/null)

if [ -n "$GUARD_REASON" ]; then
  jq -n --arg reason "AskUserQuestion is for decisions only (PAN-4514). Rejected: ${GUARD_REASON}. To wait for a background task or Monitor, end your turn; its notification wakes you. To report status, write it as text." \
    '{ hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason: $reason } }'
  exit 0
fi
```
