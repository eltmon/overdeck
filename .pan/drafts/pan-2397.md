## Glossary

| Term | Meaning |
| --- | --- |
| **Tier table** | `tiered_execution.tiers` — named tiers, each `{model, harness, difficulties[]}`. Validated by `validateTieredExecutionConfig` (`src/lib/agents/tier-table.ts`, grep `export function validateTieredExecutionConfig`). |
| **Implicit tier table** | NEW: a one-tier table synthesized from `roles.work` (or workhorse slots) when no explicit `tiered_execution` block is enabled. One tier `default` owning all five difficulties; supervisor only if explicitly configured. |
| **Slot** | Swarm's unit of parallel work: worktree + branch + registered agent session (`agent-<issue>-slot-N`). Allocator in `src/lib/cloister/deacon-swarm.ts` (`dispatchNextWave`). |
| **Staffing** | Resolving WHICH model+harness a slot session runs, from the bead's difficulty/kind via `resolveTier` (`src/lib/agents/resolve-tier.ts:107`). |
| **Crew** | The observable cast of an issue: its slot agents + optional supervisor. Post-unification every issue has a crew (sometimes crew-of-one). |
| **StandingTierManager** | The tiered library's own scheduler (`src/lib/agents/standing-tiers.ts`) — per-TIER session ownership, run schedule, replay. Overlaps the swarm allocator; to be folded in and retired. |
| **Feed / supervisor hooks** | `fireTieredCommitHooks` (`src/lib/cloister/swarm-tiered-hooks.ts`, landed PAN-2385) — broadcast + subscribe-policy review fired from `mergeReadySlots`. |
| **Write door** | `PUT /api/settings` → `saveSettingsApiPromise` (`src/lib/settings-api.ts`, grep `saveSettingsApiPromise`) with `writeYamlConfigPreservingComments`. |

## Problem

Two parallel execution worlds (Role-Models work agents + inspect subroles vs.
tier table + slots + supervisor) mean: duplicated routing config, two
inspection paths, two schedulers, and mode-conditional bugs — the PAN-2283 and
PAN-2385 "library without ignition" gaps were both artifacts of the split.
Config errors currently blast-radius unrelated subsystems (PAN-2395: an
invalid `tiered_execution` enum broke conversation lifecycle and falsely ended
a live conversation).

## Decision rules (made here, not by the executor)

- D1. `resolveTieredExecutionEnabled` semantics survive but stop gating code
  paths: when the result is "off", dispatch uses the **implicit tier table**
  — same code path, degenerate table.
- D2. The implicit table's tier is named `default`, staffed from
  `roles.work` resolution (model+harness exactly as today's work-agent spawn
  resolves them). No supervisor unless `tiered_execution.supervisor` is
  explicitly configured.
- D3. Escalation with a one-tier table is a no-op by construction (no rung
  above) — do not special-case it.
- D4. The feed with a crew-of-one broadcasts to zero *other* listeners; keep
  the everyone-hears-everything call (it no-ops cheaply) — no mode check.
- D5. Config-load validation errors must degrade to "tiered execution
  unavailable + loud health warning", never throw out of `mergeConfigs` into
  unrelated callers (conversation lifecycle, session trees). Save-time
  validation at the write door becomes the enforcement point.
- D6. Distribution selection is deterministic: FNV-1a hash of
  `issueId:beadId` → [0,1) → weighted bucket (same pattern as
  `shouldSupervise` sampling, grep `fnv1a` in tier-supervisor.ts).

## Requirements

- **FR-1** Every bead dispatch resolves staffing through ONE resolver that
  consults the explicit tier table when enabled, else the implicit table.
  No caller branches on "tiered vs not".
- **FR-2** A tier MAY declare `distribution: [{model, harness, weight}]`
  instead of `model`+`harness`. Weights must total 100 (fail-loud), every
  entry passes `canUseHarnessSync`, selection per D6. (PAN-2391)
- **FR-3** The swarm slot allocator is the only scheduler: tier-aware slot
  reuse (a freed slot prefers the next bead resolving to the same
  tier+distribution-entry, keeping the session warm), replay_threshold and
  compaction_reroute enforced at wave boundaries. `StandingTierManager` and
  `computeTierRunSchedule` are folded in or deleted; no second allocator.
- **FR-4** Inspection: when a supervisor is configured it owns inspection
  (today's `owns_inspection` flag becomes implied-true-when-supervisor-present,
  overridable); without a supervisor the inspect/inspect-deep subroles run.
  Exclusivity stays structural (`routeInspectToStandingSupervisorIfEnabled`
  first in `spawnInspectAgentPromise`, inspect-agent.ts).
- **FR-5** Save-time validation (PAN-2395): the settings write door validates
  `tiered_execution` (and the implicit-table compile) on PUT and returns 400
  on invalid — invalid config can never persist. Config LOAD tolerates an
  invalid block per D5: dispatch disabled + health warning; conversation
  lifecycle, session trees, and issue enumeration unaffected (regression test
  reproducing PAN-2395's false-ended-conversation is REQUIRED).
- **FR-6** Cost/roster surfaces (PAN-2392/2393) assume every issue has a crew;
  no tiered-vs-not UI branches. The supervisor renders as its own tree node
  with its own cost when present.
- **NFR-1** No hardcoded model fallback anywhere (existing rule); the implicit
  table derives from explicit roles config or fails loudly.
- **NFR-2** File-size ceiling: `deacon-swarm.ts` is at exactly 1000 lines —
  ALL new logic goes in new modules (`swarm-staffing.ts`,
  `swarm-tiered-hooks.ts` pattern).
- **NFR-3** Retry/delay tests use fake timers; all primitives async;
  no execSync in server-reachable code.

## Acceptance

1. `git grep -n "resolveTieredExecutionEnabled" src/ | grep -v tier-table`
   shows zero call sites that branch execution paths (only the resolver and
   surfaces reading effective state).
2. A project with NO tiered_execution block dispatches through
   `resolveStaffing` (log line proves implicit table) and behaves byte-
   identically to today's roles.work behavior.
3. Distribution tier: 100-bead simulation distributes ±5% of weights;
   same bead always resolves identically.
4. `standing-tiers.ts` exports no scheduler (manager deleted/reduced);
   allocator tests cover affinity + replay.
5. PAN-2395 regression: invalid enum in config.yaml → conversations enumerate
   fine, health shows the warning, dispatch refuses tiered staffing.
6. All existing suites green; new modules only (NFR-2).
