# PAN-4767: styleguide-conformance spec times out on main — split the six-route test

**Issue:** https://github.com/eltmon/overdeck/issues/4767
**Status:** planned (auto mode)

## Summary

The issue blames the Skills page redesign (`a443ff0619a`, `index.css` +26 lines) for the
`tests/e2e/styleguide-conformance.spec.ts:417` timeout. That diagnosis is wrong. The spec's own
Vite plugin replaces `index.css` with a two-rule stub, so no CSS from that commit reaches the test.
The real cause is older: one `it` opens six routes, each in a fresh browser context against the
unbundled Vite dev server, inside a single 45 s budget. On a loaded CI runner that `it` has timed
out on its first attempt and passed only on the retry since at least 2026-10-24. Its retry time
has crept up (35 s → 37 s → 40 s → 44 s) as the app grows. The two red runs (#12510, #12514) are
the first where the retry also crossed 45 s.

The fix splits that one `it` into six `it`s, one per route, each keeping the 45 s budget. No
timeout value changes, nothing is quarantined, and the Skills page is not touched.

## Glossary

- **The spec** — `tests/e2e/styleguide-conformance.spec.ts`. A Vitest file (root project, `node`
  environment) that starts a Vite dev server on `src/dashboard/frontend` and drives Chromium via
  the `playwright` library. It runs inside the default unit shards (`vitest.config.ts` includes
  `tests/**/*.spec.ts`); on CI it lands in `test-shard (4/4)`.
- **The six-route `it`** — the first test in the spec,
  `it('renders shared primitives on Pipeline, Board, Command Deck, and Agents routes', …, 45_000)`
  (spec line 417). It opens `/pipeline`, `/board`, `/command-deck`, `/agents`,
  `/agents?view=history` and `/pipeline?issue=PAN-1148&tab=overview` in sequence.
- **`openRoute(path)`** — spec helper (line 324) that creates a fresh `BrowserContext` via
  `newContext()` (fixture `localStorage` + `window.fetch` mock), opens a page and `goto`s the path.
  Every call is a full cold page load of the app's unbundled module graph.
- **`renderPoll`** — `{ timeout: 10_000, interval: 100 }` (spec line 106), the per-`expect.poll`
  budget. Not changed by this issue.
- **Per-`it` budget** — the third argument to `it(…)`. All three `it`s in the spec use `45_000`.
  Vitest's CI `retry: 1` (`vitest.config.ts` line 41) gives a failing `it` one more attempt; a
  retried pass is printed as `(retry x1)`.
- **Slow runner** — a CI `test-shard` job whose shard-wide Vitest summary shows
  `import ≈ 500–600 s` (fast runners show `import ≈ 300–350 s`). Same image
  (`ubuntu-24.04 20261025.353.1`), roughly 2x slower for every test.
- **PAN-4733** — the open structural follow-up that moves all four browser specs to a serial
  `tests/e2e/browser/*.slow.test.ts` lane. Out of scope here.

### Cost model, measured locally

A temporary instrumented copy of the spec (deleted afterwards) printed per-route laps:

| Condition | First route (`/pipeline`) | Each later route |
| --- | --- | --- |
| 16 cores, warm Vite dep cache | 6.4 s | 1.4–1.9 s |
| `taskset -c 0,1`, warm dep cache | 7.5 s | 2.9–3.3 s |
| `taskset -c 0,1`, cold dep cache (`node_modules/.vite` removed) | 12.3–14.7 s | 3.2–3.5 s |
| `taskset -c 0,1`, one shared `BrowserContext` | 7.9 s | 2.5–2.9 s (~10% saving) |
| `taskset -c 0,1`, cold, plus Vite `server.warmup` on `./src/main.tsx` | 11.3 s | 3.3 s (~1 s saving) |

So the cost is one cold load plus a fixed full-page-load cost per route, about 6–7 s per route on
a slow CI runner. Shared contexts and Vite warmup do not pay for themselves; splitting the `it`
does: each per-route `it` then spends one page load against its own 45 s budget.

## Requirements

- **FR-1** — The six-route `it` is replaced by six `it`s inside the same
  `describe('styleguide rendered surface conformance')`, one per route, in the original order:
  Pipeline, Board, Command Deck, Agents Live, Agents History (directory), issue drawer.
- **FR-2** — Every assertion of the old `it` survives unchanged in exactly one new `it`: same
  locators, same matchers (`toBeGreaterThan(0)`, `toBe(1)`, `toBe(0)`), same `renderPoll`, same
  Command Deck `getByText('Overdeck', { exact: true }).nth(1).click()` step.
- **FR-3** — Each new `it` keeps the per-`it` budget `45_000`. No timeout value anywhere in the
  spec changes (`renderPoll`, the `beforeAll` `30_000`, the other two `it`s' `45_000`).
- **FR-4** — Each new `it` closes the `BrowserContext` it opened, as the old code did.
- **FR-5** — `docs/TESTING.md` states the browser-spec page-load budget rule, so the next author
  does not re-grow a many-route `it`.
- **NFR-1** — No change to the Skills page or `index.css` (`src/dashboard/frontend/src/index.css`,
  `components/SkillsList.tsx`, `components/skills/*`).
- **NFR-2** — No quarantine entry (`scripts/flaky-quarantine.txt`), no `.skip`, `.only` or
  `skipIf`, no `vitest.config.ts` or `.github/workflows/ci.yml` change.
- **NFR-3** — On a cold dep cache pinned to two cores, no `it` in the spec takes longer than 25 s.

## Decisions

- **D1 — Split per route, do not raise the timeout.** The issue forbids raising the timeout and
  quarantining. Splitting keeps the per-`it` budget at `45_000` (the value the file already uses
  for all three `it`s). It removes the reason the budget was too small: six page loads in one `it`.
  This is not a hidden timeout raise: each page load still has the same 45 s ceiling it had as the
  first step of the old `it`, and a broken route still fails its own `it` within 45 s.
- **D2 — Exactly one route per new `it`.** Two routes per `it` would also fit today (≈14 s on a
  slow runner), but one route per `it` gives the most headroom and names the failing route in the
  test title. The old `it` title is retired; no code references it (grep finds only historical
  CI-feedback bodies in `.pan/continues/` and PRD prose).
- **D3 — New `it` titles** (exact strings):
  1. `renders shared primitives on the Pipeline route`
  2. `renders shared primitives on the Board route`
  3. `renders shared primitives on the Command Deck route`
  4. `renders shared primitives on the Agents Live route`
  5. `renders shared primitives on the Agents History route`
  6. `renders the issue drawer action bar on the Pipeline route`
- **D4 — No shared context, no Vite warmup, no client-side navigation.** Measured (above): shared
  context saves ~10%, warmup ~1 s. Client-side navigation would couple the spec to the router.
  None is needed once the `it` is split.
- **D5 — The cold first load stays on the first `it`.** Vitest runs `it`s in file order, so the
  Pipeline `it` pays the cold Vite transform and dep-optimize cost (12–15 s on two local cores,
  estimated ~30 s on a slow CI runner). That is inside 45 s. Moving it into `beforeAll` would need a
  raised hook timeout, which D1 rules out.
- **D6 — The structural fix belongs to PAN-4733.** Moving the browser specs out of the loaded unit
  shards into a serial lane is PAN-4733's scope. This issue does not move or rename the file.
- **D7 — Correct the diagnosis on the issue.** A short comment on PAN-4767 records the real cause
  so reviewers do not look for a CSS diff.
