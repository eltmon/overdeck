# PAN-4310: Herdr terminal stream decodes UTF-8 bytes as Latin-1

**Issue:** [PAN-4310](https://github.com/eltmon/overdeck/issues/4310)
**Status:** planned (auto mode, 2026-09-28)

## Glossary

- **Herdr** — the default terminal backend. Agents run in Herdr panes; the dashboard reads a pane
  through `herdr --session <s> terminal session observe <terminalId>`.
- **Terminal stream / NDJSON record** — `observe` and `control` write one JSON object per line on
  stdout. A `terminal.frame` record carries the pane output as base64 in `bytes`
  (`{"type":"terminal.frame","bytes":"<base64>","encoding":"ansi","full":true|false,"width","height","seq"}`).
- **Full frame / snapshot** — a `terminal.frame` with `full: true`. It is a whole-screen render and
  is always the first frame of a stream. Decodes to a `{kind:'snapshot'}` `TerminalFrame`.
- **Incremental frame** — a `terminal.frame` with `full: false`: new output bytes. Decodes to a
  `{kind:'output'}` `TerminalFrame` (preceded by `{kind:'size'}` when geometry changed).
- **`encoding: "ansi"`** — Herdr's label meaning "raw terminal bytes including ANSI escape
  sequences". It is **not** a character-set name. Do not branch on it.
- **`TerminalFrame`** — the dashboard frame contract in `src/lib/terminal-backends/types.ts`
  (line 185, `export type TerminalFrame =`). Its `data` field is a JS string of decoded text.
- **Streaming decoder** — a `TextDecoder` called with `{ stream: true }`. It holds the trailing
  bytes of an incomplete multi-byte UTF-8 sequence and joins them with the next call's bytes.
- **Mojibake** — text decoded with the wrong character set. `●` is UTF-8 `E2 97 8F`; decoded as
  Latin-1 it becomes `â` plus two invisible C1 control characters.

## Problem

On the Herdr backend the dashboard Terminal tab shows every non-ASCII character as mojibake:
`●` renders as `â`, box-drawing rules as rows of `â`, `·` as `Â·`. The pane itself is fine
(`LANG=C.UTF-8`). The bytes are decoded wrongly on the way to the browser.

### Root cause (verified 2026-09-28)

`decodeTerminalRecord()` in `src/lib/terminal-backends/herdr-stream.ts`, lines 65–67, decodes the
base64 bytes with Node's `'binary'` (Latin-1) encoding:

```ts
  const data = record.bytes !== undefined
    ? Buffer.from(record.bytes, 'base64').toString('binary')
    : record.text ?? '';
```

Empirical check (`node -e`): `Buffer.from([0xe2,0x97,0x8f]).toString('binary')` returns `"â"`
(plus the two C1 characters).

That string reaches the browser unchanged:

1. `startStream()` (same file, line 176) pushes the decoded frames into the stream's `FrameQueue`.
2. `HerdrTerminalProcess.pump()` in `src/dashboard/server/services/terminal-service.ts`, lines
   268–271 (`if (frame.kind === 'snapshot' || frame.kind === 'output')` →
   `listener(frame.data)`), hands `frame.data` to the data listeners.
3. The listener at lines 360–363 (`bridge.onData((data) => {`) queues it for the WebSocket as a
   string; xterm.js renders the string as-is.

Introduced with the Herdr adapter in `48c0c6ce2d9` (PAN-3917 W8, 2026-09-18). It is the only
`'binary'`/`latin1` decode in `src/lib/terminal-backends/` and `terminal-service.ts`
(`grep -rn "'binary'\|latin1"`). The tmux path is not affected: `BunPtyProcess.emitData`
(terminal-service.ts, lines 74–79) already uses a streaming `TextDecoder`, and node-pty decodes
UTF-8 itself.

`observeTerminal` has one other caller, `src/lib/terminal-backends/herdr.ts` line 868
(`return attempt('observe', async () => observeTerminal(terminalId));`). It gets the fix for free
and needs no change.

## Requirements

- **FR-1** — `decodeTerminalRecord` decodes `record.bytes` as UTF-8, so `●`, `·`, `─`, `⎿` and emoji
  (4-byte sequences) arrive in `TerminalFrame.data` as the correct characters.
- **FR-2** — A multi-byte UTF-8 character split across two incremental frames decodes to the correct
  single character. The decoder is held per stream in `TerminalDecodeState`.
- **FR-3** — A `full` (snapshot) frame starts a fresh decoder: pending partial bytes from before the
  snapshot are discarded and never appear as U+FFFD at the start of the snapshot.
- **FR-4** — An incremental frame whose bytes decode to the empty string (it carried only the start
  of a split character) produces no `output` frame. A `size` frame is still emitted when the
  geometry changed.
- **FR-5** — The `record.text` branch is unchanged: `text` passes through as-is and does not touch
  the decoder.
- **FR-6** — `docs/TERMINAL-BACKENDS.md` states the UTF-8 decoding contract in the Herdr wire facts.
- **NFR-1** — Invalid UTF-8 never throws. The decoder is non-fatal (the `TextDecoder` default), so
  invalid bytes become U+FFFD. This matches the existing stance at herdr-stream.ts line 174
  ("A corrupt line must not tear down a live terminal").
- **NFR-2** — No change to the `TerminalFrame` type, `terminal-service.ts`, the WebSocket protocol,
  or the frontend.
- **NFR-3** — The existing tests in `tests/unit/lib/terminal-backends/herdr-stream.test.ts` pass
  without modification of their assertions.

## Decisions (made here, not left to the executor)

- **D1 — Decoder lives in `TerminalDecodeState` as an optional field, created lazily.** Add
  `decoder?: TextDecoder` to the exported interface. `decodeTerminalRecord` does
  `state.decoder ??= new TextDecoder('utf-8')` for incremental frames. Optional keeps the existing
  test literals (`{ cols: 80, rows: 24 }`) valid, so NFR-3 holds and `startStream` line 157 needs no
  change.
- **D2 — Use the global `TextDecoder`, not `string_decoder`.** It is already used under `src/lib`
  (`src/lib/cloister/deacon-event-client.ts` line 265, `src/lib/overdeck/conversation-message.ts`
  line 188) and by `BunPtyProcess`, so it typechecks in this tsconfig. Implementation checkpoint:
  if `npm run typecheck` rejects `TextDecoder` in `herdr-stream.ts`, fall back to
  `import { StringDecoder } from 'string_decoder'` with `decoder.write(buf)` (StringDecoder also
  buffers partial sequences) — same field, same semantics.
- **D3 — A full frame assigns a new decoder before decoding.** `state.decoder = new TextDecoder('utf-8')`
  then `state.decoder.decode(bytes, { stream: true })`. Stream mode is used on the snapshot too, so a
  snapshot that ends mid-character continues correctly into the next incremental frame.
- **D4 — Suppress empty output frames** (FR-4). In-repo precedent: `BunPtyProcess.emitData`
  (`if (text.length === 0) return;`). Snapshots are always emitted, even when empty — an empty
  snapshot is a real blank-screen render.
- **D5 — No flush on exit.** A dangling partial sequence at stream end would flush to a single
  U+FFFD. The EOF path (`endOfStream` in `startStream`) never calls `decodeTerminalRecord`, so a
  flush needs plumbing in two places for no visible value. Out of scope.
- **D6 — `record.text` frames do not touch the decoder.** If a `text` frame arrives while the
  decoder holds pending bytes, those bytes join the next `bytes` frame. Herdr v0.9.1 sends `bytes`
  only; this interleaving is not observed and is out of scope.

## Work items

### WI-1 — Decode Herdr frame bytes as streaming UTF-8 (FR-1…FR-5, NFR-1…NFR-3)

**Files:** `src/lib/terminal-backends/herdr-stream.ts`,
`tests/unit/lib/terminal-backends/herdr-stream.test.ts`.

Steps:

1. In `TerminalDecodeState` (herdr-stream.ts line 46), add the optional decoder:

   Before:
   ```ts
   /** Size carried forward so an incremental frame can report a resize. */
   export interface TerminalDecodeState {
     cols: number;
     rows: number;
   }
   ```
   After:
   ```ts
   /**
    * Size carried forward so an incremental frame can report a resize, plus the
    * stream's UTF-8 decoder so a character split across two frames decodes whole.
    */
   export interface TerminalDecodeState {
     cols: number;
     rows: number;
     decoder?: TextDecoder;
   }
   ```

2. In `decodeTerminalRecord` replace lines 65–84 (from `const data = record.bytes !== undefined`
   to the final `return frames;`):

   After:
   ```ts
     const cols = record.width ?? state.cols;
     const rows = record.height ?? state.rows;

     if (record.full) {
       // A snapshot is a fresh render: drop any partial character left by the
       // previous frame instead of prepending it as U+FFFD.
       state.decoder = new TextDecoder('utf-8');
       state.cols = cols;
       state.rows = rows;
       return [{ kind: 'snapshot', cols, rows, data: decodeFrameData(record, state) }];
     }

     const frames: TerminalFrame[] = [];
     if (cols !== state.cols || rows !== state.rows) {
       state.cols = cols;
       state.rows = rows;
       frames.push({ kind: 'size', cols, rows });
     }
     const data = decodeFrameData(record, state);
     if (data.length > 0) frames.push({ kind: 'output', data });
     return frames;
   ```

   And add above `decodeTerminalRecord`:
   ```ts
   /**
    * Frame bytes are UTF-8 terminal output. The decoder is per stream and runs in
    * stream mode, so a multi-byte character split across two frames decodes whole.
    * Invalid bytes become U+FFFD; they never throw.
    */
   function decodeFrameData(record: HerdrTerminalRecord, state: TerminalDecodeState): string {
     if (record.bytes === undefined) return record.text ?? '';
     state.decoder ??= new TextDecoder('utf-8');
     return state.decoder.decode(Buffer.from(record.bytes, 'base64'), { stream: true });
   }
   ```

3. Update the `decodeTerminalRecord` doc comment (lines 51–55) to add: "Frame bytes decode as
   UTF-8 through the stream's decoder; an incremental frame that decodes to nothing (the first
   half of a split character) yields no output frame." Update the module header (lines 1–24):
   after the `terminal.frame` example lines, add one line: "`bytes` is base64 of UTF-8 terminal
   output (`encoding: "ansi"` means escape sequences, not a charset)."

4. Tests — add to `describe('decodeTerminalRecord', …)` in the test file. Build fixtures from
   explicit byte arrays, e.g. a local helper
   `const frame = (bytes: number[], full = false) => ({ type: 'terminal.frame', bytes: Buffer.from(bytes).toString('base64'), encoding: 'ansi', full, width: 100, height: 30 });`
   - **`decodes a 3-byte character split across two frames`** — state `{ cols: 100, rows: 30 }`;
     `frame([0xe2])` → `[]`; `frame([0x97, 0x8f])` → `[{ kind: 'output', data: '●' }]`.
   - **`starts a fresh decoder on a snapshot frame`** — `frame([0xe2])` → `[]`; then
     `frame([...Buffer.from('hello')], true)` → `[{ kind: 'snapshot', cols: 100, rows: 30, data: 'hello' }]`
     (no leading `�`); then `frame([0xe2, 0x97, 0x8f])` → `[{ kind: 'output', data: '●' }]`.
   - **`decodes multi-byte characters and emoji`** — one incremental frame with
