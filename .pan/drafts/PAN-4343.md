# PAN-4343: Operator-grant labels (`released`, `auto-merge`, `hold-for-uat`) honored only from a non-agent actor

**Issue:** [PAN-4343](https://github.com/eltmon/overdeck/issues/4343)
**Parent PRD:** `.pan/drafts/deft-adoption.md`, "Issue 9" (lines 380-394).
**Related:** PAN-2059 (the `released` pickup gate), PAN-4264 (the count-only agent `gh` shim this extends), PAN-4337 (branch check in the same shim file), PAN-4349 (also uses the agent `gh` shim).

## Glossary

- **Grant label** — one of exactly three GitHub labels that carry an operator decision: `released` (operator's "go" for autonomous pickup, `src/lib/backlog/pickup.ts:31-32`, `export const RELEASED_LABEL = 'released';`), `auto-merge` and `hold-for-uat` (per-issue merge policy, `src/lib/cloister/auto-merge-eligibility.ts:34-35`, `export const AUTO_MERGE_LABEL = 'auto-merge';`). Comparison is case-insensitive (GitHub label names are case-insensitive).
- **Grant-label write** — any `gh` call that adds or removes a grant label on an issue or PR (see FR-2 / FR-3 for the exact shapes recognized).
- **Agent pane** — any launcher generated by `generateLauncherScript` with `overdeckEnv.agentId` set and `spawnMode !== 'conversation'` (work, planning, review, test, workers, strike, etc.). Today these already get the git guard and the count-only `gh` shim.
- **Conversation** — a launcher generated with `spawnMode: 'conversation'`. The only non-test call site is `spawnConversationSession` in `src/lib/overdeck/conversation-runtime.ts` (grep anchor `spawnMode: 'conversation',`, currently line 779). Its identity is `tmuxSession` (`conv-<name>`).
- **Flywheel conversation** — the conversation whose `tmuxSession` equals `FLYWHEEL_CONVERSATION_SESSION` (`'conv-flywheel'`, `src/lib/flywheel/constants.ts:7`).
- **Operator conversation** — every conversation other than the flywheel conversation.
- **Guard dir** — a directory whose path ends in `/git-guard`, prepended to `PATH` by a launcher. Two filters strip inherited guard dirs by that suffix: the launcher prelude (`src/lib/launcher-git-guard.ts:296-302`) and `pan restart` (`src/cli/commands/restart.ts:241-245`, `!segment.endsWith('/git-guard')`).
- **gh shim** — the `#!/bin/sh` file `<guard dir>/gh` written by `buildGhShimLines` (`src/lib/launcher-git-guard.ts:471-494`). Today it appends one ledger line and `exec`s the real `gh`; it never blocks.

## Problem

`isAutoPickable` and the auto-merge resolver check label **presence** only. Agents run `gh` with the operator's own token, so an agent-applied `released` is indistinguishable from the operator's go, and the GitHub events API would name the operator either way. The Flywheel is the caller most likely to self-release, and it runs as a conversation, which today gets **no** `gh` shim at all:

```ts
// src/lib/launcher-generator.ts:381-383 (today)
  if (config.overdeckEnv?.agentId && config.spawnMode !== 'conversation') {
    lines.push(...buildGitGuardLines(config.overdeckEnv.agentId, config.workingDir, config.gitGuardMode ?? 'default'));
  }
```

The flywheel skill already says the rule in prose (`sync-sources/skills/pan-flywheel/SKILL.md:92-93`, "Operator-only — never add the label yourself", and lines 104-105, "`released` and `vetoed` are operator-only labels: this loop never adds or removes either one"). Nothing enforces it.

## Design (decisions made)

1. **The `gh` shim deny is the load-bearing layer.** A closed-set, stateless check at call time. No grant store, no events-API actor check (it adds nothing while agents share the operator's token).
2. **Who is denied** is decided at launch and baked into the shim as a literal: every agent pane, plus the flywheel conversation. Operator conversations get the shim count-only (no deny).
3. **Direction:** both adding **and** removing a grant label is refused. For `hold-for-uat`, removal is the grant; the flywheel skill already forbids both directions. (Recorded as an auto-decision.)
4. **Verbs:** `gh issue edit`, `gh issue create`, `gh pr edit`, `gh pr create` (label flags), and `gh api` REST writes on `issues/<n>/labels` endpoints. `create --label released` is included because creating an issue already released bypasses the gate exactly like `edit`.
5. **No bypass switch.** The deny does not honor `OVERDECK_GH_METERED=1` (that only skips counting) nor `OVERDECK_PAN_GIT_OP=1`. Verified: no `pan` CLI verb writes grant labels through `gh`; the only writer is the dashboard server (`src/lib/backlog/label-ops.ts:14-19` via `src/dashboard/server/routes/backlog.ts:400`), whose `PATH` has no guard dir.
6. **A refused call is not counted** in the GitHub quota ledger: it never reached GitHub. The deny block runs before the ledger append.
7. **Conversation shim location:** `~/.overdeck/conversations/<tmuxSession>/git-guard/gh` (beside that conversation's `launcher.sh`, `conversation-runtime.ts:160`). The directory **must** be named `git-guard` so both PATH filters (launcher prelude, `pan restart`) strip it. Otherwise a flywheel-initiated `pan restart` could leak the flywheel's deny shim into the dashboard server's `PATH`, and `label-ops.ts` runs `gh issue edit … 2>/dev/null || true`, so the operator's Release button would silently no-op. No `git` shim is written in a conversation guard dir. No cleanup code is added: the directory is rewritten on every launch, like `launcher.sh`, and conversations are archived, not deleted (`handleConversationDelete`, `conversation-runtime.ts:1164`).
8. **Ledger fields for conversations:** `caller: 'agent'`, `agent: '<tmuxSession>'`. Extending the `GitHubQuotaCaller` contracts enum is out of scope.
9. **Explicit launcher field**, not inference from `managedStateKey`: `LauncherConfig.ghShim?: { id: string; denyGrantLabels: boolean }`, honored only when `spawnMode === 'conversation'`. The flywheel decision lives in `conversation-runtime.ts`, the one module that knows the conversation; the generator does not import flywheel constants. Because only `spawnConversationSession` generates conversation launchers, spawn, resume, respawn and model switch all inherit the shim.

## Requirements

- **FR-1** Every agent-pane `gh` shim refuses grant-label writes; every other `gh` call passes through unchanged (stdout, stderr, exit code) and is counted as today.
- **FR-2** `gh issue edit|create` and `gh pr edit|create` are refused when any of `--add-label V`, `--add-label=V`, `--remove-label V`, `--remove-label=V`, `--label V`, `--label=V`, `-l V`, `-lV`, `-l=V` carries a grant label in its comma-separated value list (whitespace removed, case-insensitive).
- **FR-3** `gh api` is refused when (a) some argument is a *label carrier* — it matches `*labels*=*` (a `-f/-F` field such as `labels[]=V` or `labels=V`) or `*issues/*/labels/*` (a path naming one label) — and that argument contains a grant-label name (case-insensitive substring), and (b) the effective method is not `GET`. The effective method is the explicit one (`-X M`, `-XM`, `--method M`, `--method=M`, any case) or, when none is given, `POST` if any of `-f`, `-F`, `--field`, `--raw-field`, `--input` (or their `=`/attached forms) is present, else `GET` — matching `gh api`'s own default. This covers label add/replace/remove endpoints, `POST repos/o/r/issues` with labels, and `PATCH repos/o/r/issues/<n>` with labels, while comment bodies and label-filtered listings pass.
- **FR-4** A refusal prints one line to stderr naming the label, stating that only the operator adds or removes grant labels, and telling the caller to ask the operator; it exits 1, does not run the real `gh`, and writes no ledger line.
- **FR-5** Every conversation launcher (a `LauncherConfig` with `spawnMode: 'conversation'` and `ghShim` set) writes a `gh` shim at `<OVERDECK_HOME>/conversations/<id>/git-guard/gh`, drops inherited guard dirs from `PATH` first, and prepends that guard dir to `PATH`. It writes no `git` shim.
- **FR-6** `spawnConversationSession` sets `ghShim: { id: tmuxSession, denyGrantLabels: tmuxSession === FLYWHEEL_CONVERSATION_SESSION }`.
- **FR-7** Docs state that grant labels are operator-only and that the agent/flywheel `gh` shim enforces it, with the residual bypasses.
- **NFR-1** The deny is plain POSIX `sh` (the shim is `#!/bin/sh`): no arrays, no `[[ ]]`, no `local`, no bashisms; only `case`, `for`, `tr`, `printf`.
- **NFR-2** `src/lib/launcher-generator.ts` stays at **≤ 1000 lines** (it is 999 on `origin/main`; `scripts/lint-file-size.sh` `CEILING=1000`, and its allowlist rows cap it at 938, so it cannot grow past 1000 and agents cannot raise the cap). `src/lib/overdeck/conversation-runtime.ts` (1234 lines) stays ≤ its last allowlist row, 1248.
- **NFR-3** Tests execute the generated shims (no source-text grepping, no `skipIf`/`.only`), following `src/lib/__tests__/launcher-git-guard-gh-shim.test.ts`.

```sh
_overdeck_gh_refuse() {
  echo "Overdeck refused gh: '$1' is an operator grant label (released, auto-merge, hold-for-uat). Only the operator adds or removes it. Ask the operator instead of changing it." >&2
  exit 1
}
_overdeck_gh_grant_in() {
  _og_list="$(printf '%s' "$1" | tr -d '[:space:]' | tr '[:upper:]' '[:lower:]')"
  _og_ifs="$IFS"; IFS=','
  for _og_v in $_og_list; do
    case "$_og_v" in
      released|auto-merge|hold-for-uat) IFS="$_og_ifs"; printf '%s\n' "$_og_v"; return 0 ;;
    esac
  done
  IFS="$_og_ifs"
  return 1
}
case "$1:$2" in
  issue:edit|issue:create|pr:edit|pr:create)
    _og_next=0
    for _og_arg in "$@"; do
      if [ "$_og_next" = 1 ]; then
        _og_next=0
        _og_hit="$(_overdeck_gh_grant_in "$_og_arg")" && _overdeck_gh_refuse "$_og_hit"
        continue
      fi
      case "$_og_arg" in
        --add-label|--remove-label|--label|-l) _og_next=1 ;;
        --add-label=*|--remove-label=*|--label=*)
          _og_hit="$(_overdeck_gh_grant_in "${_og_arg#*=}")" && _overdeck_gh_refuse "$_og_hit" ;;
        -l?*)
          _og_v="${_og_arg#-l}"; _og_v="${_og_v#=}"
          _og_hit="$(_overdeck_gh_grant_in "$_og_v")" && _overdeck_gh_refuse "$_og_hit" ;;
      esac
    done
    ;;
  api:*)
    _og_method=""; _og_fields=0; _og_hit=""; _og_next=0
    for _og_arg in "$@"; do
      if [ "$_og_next" = 1 ]; then _og_next=0; _og_method="$_og_arg"; continue; fi
      case "$_og_arg" in
        -X|--method) _og_next=1; continue ;;
        --method=*) _og_method="${_og_arg#--method=}" ;;
        -X?*) _og_method="${_og_arg#-X}" ;;
        -f|-F|--field|--raw-field|--input|-f?*|-F?*|--field=*|--raw-field=*|--input=*) _og_fields=1 ;;
      esac
      _og_low="$(printf '%s' "$_og_arg" | tr '[:upper:]' '[:lower:]')"
      case "$_og_low" in
        *labels*=*|*issues/*/labels/*)
          case "$_og_low" in
            *released*) _og_hit=released ;;
            *auto-merge*) _og_hit=auto-merge ;;
            *hold-for-uat*) _og_hit=hold-for-uat ;;
          esac
          ;;
      esac
    done
    if [ -z "$_og_method" ]; then
      if [ "$_og_fields" = 1 ]; then _og_method=POST; else _og_method=GET; fi
    fi
    _og_method="$(printf '%s' "$_og_method" | tr '[:lower:]' '[:upper:]')"
    if [ -n "$_og_hit" ] && [ "$_og_method" != GET ]; then
      _overdeck_gh_refuse "$_og_hit"
    fi
    ;;
esac
```

Escaping note: in the TypeScript source each line is a single-quoted string, so the shell's `'%s\n'` is written `'%s\\n'` in TS (as the existing ledger `printf` at line 487 does); the `$`-escaper then handles every `$`. The reference body above was run under `dash` against every WI-1 test case during planning and behaved as listed.

Note `"$1:$2"` with a colon separator (clearer than a space inside `case`). `api:*` matches `gh api <anything>`, including `gh api graphql`; a GraphQL query names labels by node ID, never as a `labels…=` field, so it passes. The `-X?*` arm comes after `-X|--method`, so a bare `-X` never reaches it.

```ts
/**
 * PAN-4343: the `gh` shim alone, for conversation launchers. Conversations get
 * no git guard (they are operator sessions), but the Flywheel runs as one, so
 * it needs the grant-label deny. The directory is named `git-guard` so the
 * launcher prelude and `pan restart` strip it from inherited PATHs.
 */
export function buildConversationGhShimLines(conversationId: string, denyGrantLabels: boolean): string[] {
  const guardDir = join(getOverdeckHome(), 'conversations', conversationId, 'git-guard');
  const pathForDoubleQuotes = guardDir.replace(/([\\"$`])/g, '\\$1');
  return [
    ...dropInheritedGuardDirLines(),
    `mkdir -p ${shellQuote(guardDir)}`,
    ...buildGhShimLines(conversationId, guardDir, denyGrantLabels),
    `export PATH="${pathForDoubleQuotes}:$PATH"`,
  ];
}
```
