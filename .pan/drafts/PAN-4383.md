# PAN-4383: A work agent's operator decision reaches Needs-you (`pan ask`)

**Issue:** [PAN-4383](https://github.com/eltmon/overdeck/issues/4383)
**Motivating incident:** PAN-2609's work agent hit GitHub push protection on 2026-09-28 13:35 UTC. It posted its question as an issue comment and ran `pan tell flywheel-orchestrator` ("not running"). Nothing reached Needs-you. The issue sat 16 hours with all work done locally, and God View drew it as "❄ PAN-2609 · 17h idle".

## Glossary

- **Operator decision** — a question a work agent cannot answer itself and that blocks its progress. It has a question text and 2–4 option labels. The operator answers it once.
- **Pipeline journal** — the per-workspace append-only log `<workspace>/.overdeck/pipeline.jsonl` owned by `src/lib/cloister/pipeline-journal.ts`. Entries are `{ at, type, issueId, source?, data? }`. It is never rewritten. Appending fires `pipeline.entry` on the pipeline notifier. From a CLI process that forwards over `POST /api/internal/pipeline/notify`.
- **Open decision** — the most recent `operator.decision-requested` journal entry with no later `operator.decision-answered` or `operator.decision-withdrawn` entry for the same `questionId`, and no later `verification.started` entry. It is derived on read. Nothing stores "open".
- **Needs-you** — the dashboard's `DecisionsPanel` (`src/dashboard/frontend/src/components/DecisionsPanel.tsx`), fed by `useDecisions()` (`src/dashboard/frontend/src/lib/useDecisions.ts`). An agent row appears when its read-model snapshot has a non-empty `pendingInputKinds`. The kind `askUserQuestion` renders with the Answer button, which opens `AskUserQuestionDialog`.
- **Enrichment poller** — `src/dashboard/server/services/agent-enrichment-service.ts`. It runs every 10 s (`POLL_INTERVAL_MS = 10_000`) and calls `computeAgentEnrichment` (`src/lib/agent-enrichment.ts:632`) per active agent. On the rising edge of a pending input (count 0 → >0) it emits an activity entry and `emitActivityTts` (TTS when `tts.enabled`). The browser fires a desktop notification per new `pendingAskUserQuestion.toolUseId` (`App/hooks/usePendingInputDialogs.ts`, near line 280).
- **Derived attention** — `IssueAttention = "needs-you" | "stuck" | "api-error"` from `deriveAttention()` in `src/lib/overdeck/derived-issue-state.ts:184`. The Command Deck's `isNeedsYouFeature` (`src/dashboard/frontend/src/components/CommandDeck/pipeline-helpers.ts:112`) already buckets any issue with `derived.attention === 'needs-you'` as "Needs you". God View reads the same field (`useConfluenceData.ts:700`, `attention: derived?.attention ?? null`).
- **Parked orbit** — a classification from `classifyParked()` in `src/lib/parked/resolver.ts:139`. `idle-running` is a live agent with no activity for 6 h. The stall sweeper (`src/lib/cloister/stall-sweeper.ts`) recommends "nudge, then stop" for it. `operator-gate` rows are only re-surfaced every 24 h.
- **Orb state** — God View's `OrbState = 'active' | 'shelf' | 'stale' | 'failed'` (`src/dashboard/frontend/src/components/GodView/confluence/model.ts:128`), from `classifyOrb()` (`model.ts:166`).

## Problem

Today no channel carries a work agent's blocking question to the operator:

1. `computeAgentEnrichment` adds `agentTurnEnded` only for interactive roles (`isInteractiveRoleAgent`, `agent-enrichment.ts:172`: plan or `conv-`). A work agent that asks in prose produces no pending-input kind.
2. `deriveAttention` returns `needs-you` only when a live backend pane reports `state === 'blocked'` (`derived-issue-state.ts:189`). An idle work agent never qualifies.
3. `classifyOrb` turns any orb with 30 min of inactivity into `stale` ("❄ … idle").
4. `classifyParked` classifies the idle agent as `idle-running`, and the sweeper recommends nudging or stopping it.
5. `roles/work.md` ("Signal the flywheel before you stall", line 110) tells the agent to `pan tell flywheel-orchestrator`, and to post an issue comment when that fails. Neither reaches Needs-you.

## Proposal (decided)

Add a harness-agnostic CLI verb, **`pan ask`**, that appends an `operator.decision-requested` entry to the issue's pipeline journal. Every surface derives the open decision from the journal:

- **Needs-you:** the enrichment synthesizes a pending `askUserQuestion` from the open decision. The existing panel, dialog, rising-edge TTS, activity entry and desktop notification then work unchanged.
- **Answering:** `POST /api/agents/:id/answer-question` delivers the answer through `deliverAgentMessage` (the `pan tell` delivery path). On `ok` it appends `operator.decision-answered`, which clears the item.
- **Any operator message closes it:** a delivered `pan tell` from the CLI, or `POST /api/agents/:id/message|tell` from the dashboard, to the asking agent also appends `operator.decision-answered`. The flywheel's `pan tell` therefore answers and clears it too.
- **Status surfaces:** `deriveAttention` returns `needs-you` when a decision is open, so the Command Deck buckets the issue as "Needs you". God View gains a `needs-you` orb state drawn on the shelf row with the flare color and a "needs you" label.
- **Parked population:** `classifyParked` emits an `operator-gate` row (`gate: 'operator-decision'`) for an open decision. That suppresses `idle-running`, so the sweeper re-surfaces the row on its 24 h TTL instead of recommending a nudge or stop.
- **Role prompt:** `roles/work.md` tells the work agent to use `pan ask` for a blocking question instead of an issue comment or a flywheel tell.

No new stored status, table, HTTP route or read-model field is added.

## Requirements

- **FR-1** `pan ask <ISSUE> "<question>" --option <label> --option <label> [--context <text>]` appends one `operator.decision-requested` entry to `<workspace>/.overdeck/pipeline.jsonl`. `data` is `{ questionId, agentId, question, options, context? }` and `source` is `'pan-ask'`. It needs 2–4 non-empty options and exits 1 otherwise.
- **FR-2** `pan ask <ISSUE> --withdraw` appends `operator.decision-withdrawn` for the open decision. It exits 1 when no decision is open.
- **FR-3** A pure `deriveOpenOperatorDecision(entries)` returns the open decision or `null`, using the rule in the glossary.
- **FR-4** For an agent whose id equals the open decision's `agentId`, `computeAgentEnrichment` reports `pendingInputKinds` containing `'askUserQuestion'`, and `pendingAskUserQuestion.toolUseId` equals `operator-decision:<questionId>`, with the question and options. The next enrichment poll (≤10 s) produces it.
- **FR-5** `POST /api/agents/:id/answer-question` answers the open decision. It delivers through `deliverAgentMessage` and appends `operator.decision-answered` only when delivery returns `ok: true`. After that, `computeAgentEnrichment` no longer reports the decision.
- **FR-6** A delivered operator message to the asking agent appends `operator.decision-answered`. This covers `pan tell` (CLI) and `POST /api/agents/:id/message|tell` (dashboard).
- **FR-7** `deriveAttention` returns `'needs-you'` when `IssueStateFacts.operatorDecisionOpen` is true. Both loaders fill the fact from the journal.
- **FR-8** God View classifies an orb whose attention is `needs-you` as `'needs-you'` (not `'stale'`). It draws the orb on the shelf row with the label `⚑ <ID> · needs you <age>`, and the issue rail shows `needs you ⚑`.
- **FR-9** `classifyParked` emits an `operator-gate` row with `details.gate === 'operator-decision'` for an open decision, and emits no `idle-running` row for that issue.
- **FR-10** `roles/work.md` directs blocking questions to `pan ask`. `docs/PIPELINE-GATES.md` and `docs/GOD-VIEW.md` describe the channel.
- **NFR-1** A journal read or write failure never throws into its caller. It logs and returns `null` or no-ops, in line with the pipeline-journal contract.
- **NFR-2** No `execSync` in server-reachable code. Journal reads use the existing sync `readPipelineJournal` on a small file. Do not add an async twin (the "one variant per operation" rule).
- **NFR-3** No file over 1000 lines grows past its `origin/main` count or its `scripts/file-size-allowlist.txt` cap. `src/cli/index.ts` has cap 1379 and is currently 1282 lines, so the new verb fits.
- **NFR-4** No import cycle. `src/lib/cloister/operator-decision.ts` must not import `src/lib/agent-enrichment.ts`. It returns a structurally typed pending-question object instead.

## Decisions (auto mode; no operator available)

1. **A new verb `pan ask`, not a labelled issue comment.** The journal is the durable, event-firing, workspace-scoped fact the issue asks for, and it needs no forge round-trip. A comment would need a forge poll to surface.
2. **Reuse the `askUserQuestion` kind** instead of a new `PendingInputKind`. The dialog (which has a free-form textarea), the TTS rising edge, the activity entry and the desktop notification all work without frontend changes. The only frontend change is sending `toolUseId` in the answer POST body.
3. **Clearing rule.** A decision closes on `operator.decision-answered` (dashboard answer, dashboard message, `pan tell`), on `operator.decision-withdrawn` (`pan ask --withdraw`), or on a later `verification.started` (`pan done` ran, so the work moved on). A newer `operator.decision-requested` supersedes an older one. The panel does NOT also clear on a transcript user-text turn. One journal rule keeps the panel and the Command Deck in agreement.
4. **Any delivered operator message closes the decision.** An operator message to an agent blocked on a decision is treated as its answer. If the message did not answer it, the role prompt tells the agent to run `pan ask` again.
5. **Specialist suppression exemption.** PAN-1834 suppresses transcript-derived pending inputs while a review or test specialist is active. The journal decision is exempt: it is a fresh, timestamped request, not stale transcript residue. When suppressed, only the decision is shown.
6. **No `startedAt` filter for the decision.** A restarted agent still owes the answer.
7. **The decision surfaces only on the agent whose id equals `data.agentId`.** `pan ask` records `process.env.OVERDECK_AGENT_ID` when set, else `agent-<issue lowercase>`.
8. **God View placement.** The `needs-you` orb sits on the shelf row (paused work that still belongs to the pipeline). It uses `SWEEP_FLARE_COLOR` (`#ffd75e`), which `docs/GOD-VIEW.md` already defines as "a parked orb only a human can release". Precedence in `classifyOrb`: paused/yield → `shelf`, then `needs-you`, then `stuck`/`api-error` → `failed`, then `stale`.
9. **Role-prompt scope.** Only the "blocking question" shape moves to `pan ask`. Self-abort, refuse-to-fix-forward and full-pipeline-needed keep the flywheel tell. The identical sections in `roles/plan.md`, `review.md`, `test.md` and `strike.md` are not changed.
10. **The AskUserQuestion deny hook is unchanged.** `sync-sources/hooks/ask-user-question-hook` already makes a Claude work agent's AskUserQuestion visible in Needs-you through its `(PAN-1520)` deny marker, which the enrichment detects (`agent-enrichment.ts` lines 341–367). Its REASON string is a load-bearing contract (`tests/lib/auq-hook-detector-contract.test.ts`).
11. **`pan answer` is not extended.** The operator answers from the dashboard dialog or with `pan tell`, and FR-6 closes the decision in both cases.

## Hazards

- The read-model reducer wipes pending fields when an agent is not running and its pane is dead. If the agent crashes mid-wait, the Needs-you item disappears, but the issue-level `needs-you` attention (Command Deck, God View) and the parked row survive. This is intended. The operator's answer then needs the agent restarted.
- `getIssueWorkspacePath` and WI-6 assume `<projectPath>/workspaces/feature-<issue>`. A polyrepo project with another workspace layout reads no decision at the issue level. The agent-level surfaces use `AgentState.workspace` and are unaffected.
- Any delivered operator message closes the decision (Decision 4). A review agent's `pan tell` to the work agent would also close it. The agent re-asks if needed.
- Adding the verb changes the generated composer-command manifest. Forgetting to regenerate it fails lint.
