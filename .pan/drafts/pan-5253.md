## Glossary

- **Drawer** — the issue slide-over, `components/drawer/IssueDrawer.tsx`, 980px wide. PAN-5244 rebuilt it conversation-first. Everything this issue changes is visible in the drawer.
- **Stage issue tab (the cockpit)** — the issue view in the Command Deck's centre pane, `components/Stage/cockpit/IssueMissionControl.tsx`. Not changed by this issue. PAN-5246 changes it.
- **Shared view** — `IssueDetail` (`components/issue-detail/IssueDetail.tsx`): the pipeline strip, banner slot, tab strip and tab bodies.
- **Density** — the `density` prop of `IssueDetail`: `drawer`, `page`, `rail` (search `export type IssueDetailDensity`). The drawer passes `drawer`. The cockpit passes `page` with `showTabs={false}` and only the tab values `conversation` and `terminal` (`IssueMissionControl.tsx:776-791`). After PAN-5244, `IssueDetail` has three return paths: the `rail` branch, the **drawer branch** (`if (density === 'drawer')`), and the **legacy page return** below it.
- **Pipeline strip** — `components/issue-view/IssuePipelineStrip.tsx` (PAN-5244 WI-3): six phase buttons, the checks chip, the pickup controls.
- **Banner slot** — NEW. One slot under the strip that shows at most one banner: the needs-you banner or the paused banner.
- **Tab entry** — one button in the tab strip (for example Changes). **View** — a sub-view inside a tab entry (Changes has Files, Checks, Artifacts). **Tab value** — the single string that selects an entry and a view: the `tab` prop, `drawer.tab` in the store, `?tab=` in the URL.
- **Details tab** — tab value `overview`, labelled "Details" (PAN-5244). Body: `components/issue-detail/IssueDrawerDetails.tsx`.
- **Agent** — an entry of the dashboard store's `agentsById` (`lib/store.ts`, search `export const selectAgents`). The shared view takes `agents: Agent[]`.
- **Backend pane** — a terminal-backend pane in the issue workspace (`BackendPane`, `packages/contracts/src/backend-pane.ts`; `useBackendPanes(issueId)` in the store). A pane can exist without an agent record, for example a reviewer spawned by `pan handoff --issue`.
- **Section marker** — an HTML attribute `data-section="<name>"` on a visible element. Tests use it to prove a section still renders. The drawer's 16 names are `DENSITY_SECTIONS.console` (`components/issue-view/densitySections.ts:4`).
- **Deft issue** — an issue running on the Deft pipeline: `useDeftIssueSummary(issueId).isDeft` (`components/deft/queries.ts:42`).
- **Named tint classes** — `.chip-selected`, `.list-row`, `.list-group-bar`, `.switch-track-on`, `.badge-bg-*`, `.badge-border-*` in `index.css`. This project is on Tailwind 3 with `var()`-based colours, where an opacity modifier on a token (`bg-background/40`) compiles to no CSS.

## Background

After PAN-5244 the drawer is conversation-first: a one-row title, the pipeline strip, the paused banner, eight tabs (Conversation, Tasks, Plan map, Files, Activity, Artifacts, Skills, Details) and a full-width tab body.

The cockpit has surfaces the drawer lacks. This issue gives them to the shared view so the drawer shows them now and PAN-5246 can make the Stage tab render the same view without losing anything. Verified facts:

- **Tabs and views.** The cockpit has Plan with Tasks, Map and PRD views (`IssueMissionControl.tsx:792-818`), Changes with Files, Checks and Artifacts views (824-854), Activity (855-859), Discussion (860) and, for a Deft issue, Decisions (861). Its legacy `?tab=` map is at lines 98-108.
- **Needs-you slot.** The cockpit mounts `NeedsYouSlot` (`components/issue-view/NeedsYouSlot.tsx:66`) under its header (`IssueMissionControl.tsx:694-698`), with agent-scoped actions from `Stage/cockpit/useCockpitNeedsYouActions.ts`.
- **The drawer's Activity and the cockpit's Activity are different feeds.** The drawer shows `DrawerActivityPanel` (`components/drawer/DrawerSecondaryPanels.tsx:11`), the live activity log. The cockpit shows `ActivityTab` (`components/CommandDeck/ZoneCOverviewTabs/ActivityTab.tsx:8`): time-bucketed action status updates plus the Deft finish-loop feed. A third feed, `HappenedFeed` (`Stage/cockpit/HappenedFeed.tsx:42`), shows plain-language session events on the cockpit Overview.
- **No "Status history" view exists in code.** `MissionSubView` (`IssueMissionControl.tsx:80`) has `feed` and nothing else for Activity. `docs/ISSUE-VIEW.md:63` describes a segment the code does not have.
- **The drawer's "Plan map" and the cockpit's map are different components.** `DrawerPlanPanel` (`DrawerSecondaryPanels.tsx:20`) is the xBRIEF viewer with DAG, List and Raw; the cockpit's `PlanMapCard` is the DAG alone. The viewer's DAG tab lazy-loads the same `PlanMapViewer` (`components/xbrief/XBriefViewer.tsx:127`).
- **The cockpit PRD view is a modal dialog.** `PrdViewer` (`components/PrdViewer.tsx:46`) is `fixed inset-0` and closes on a `window` Escape listener (lines 26-32). In the drawer that Escape would also close the drawer.
- **Per-agent cost** comes from the cost query's `sessions[]` (`components/CommandDeck/ZoneCOverviewTabs/queries.ts:95-119`), matched as `Stage/cockpit/AgentsLane.tsx:239-252` matches it. `CostCard` has by-model and by-stage bars only.
- **`ShipProgress` has no log.** It renders the merge gate's facts (`components/issue-view/ShipProgress.tsx:62-96`); the merge door writes no record.
- **`LinkedConversations`** (`Stage/cockpit/LinkedConversations.tsx:26`) is keyed by PR URL and is imported only by `CodeCard.tsx`, which no mounted file imports. This issue mounts it again.
- **`DrawerActivityPanel` reads the open drawer from the store** (`useDrawerData()`, `DrawerSecondaryPanels.tsx:12`). A shell with no open drawer gets nothing from it.
- **The cockpit lists sessions the shared view does not.** Its crew spine builds rows from backend panes (`Stage/cockpit/IssueTreeLane.tsx:117`); the shared view lists store agents. A pane with no agent record is invisible in the drawer today.

## Decisions

Each decision is final for this issue.

- **D-1 Scope is the shared view as the drawer renders it.** All changes go into the drawer branch of `IssueDetail`, the tab strip, the Details body, `DrawerAgentSession`'s conversation-header layout and new shell-independent components. The legacy page return, the `rail` branch, `IssueMissionControl.tsx` and every file under `components/Stage/cockpit/` are not edited. The Stage issue tab renders exactly as before.
- **D-2 New pieces are shell-independent.** They take an issue id and callbacks and never read `drawer.issueId` from the store, so PAN-5246 can mount them in the Stage tab.
- **D-3 One tab set.** Entries in order: Conversation, Tasks, Plan, Changes, Activity, (Decisions), Discussion, Skills, Details. Entry ids: `session`, `tasks`, `plan`, `changes`, `activity`, `decisions`, `discussion`, `skills`, `overview`. The `files` and `artifacts` entries are replaced by `changes`; their tab values keep working (D-4).
- **D-4 A view is selected by the tab value.** There is no second state field. The precedent is `conversation | terminal → session`. One pure function, `resolveIssueTab`, maps every value either shell accepts today to an entry and a view. The cockpit's legacy values are included now so PAN-5246 needs no second table. New values: `prd`, `checks`, `history`. The full table is in "Tab values".
- **D-5 Unknown tab value.** The drawer keeps today's behaviour: `TabPlaceholder`.
- **D-6 Decisions tab.** The `decisions` entry sits before Discussion and is listed only for a Deft issue. `tab="decisions"` renders `DeftDecisionsTab` for any issue, as the cockpit does (`IssueMissionControl.tsx:121`, `:861`).
- **D-7 Banner slot rule.** The slot renders exactly one of the following, first match wins:
  1. `NeedsYouSlot`, when its top item is `awaiting_input` or `stuck`.
  2. `PausedBanner`, when any agent of the issue has `paused === true`.
  3. `NeedsYouSlot`, when it has any item (`blocker`, `pickup_gate`, `ready_for_merge`, `stopped`).
  4. Nothing.

  This is the existing priority ladder (`components/issue-view/derivations.ts:47-55`, search `OPERATOR_NEED_PRIORITY`) with the paused banner taking the `paused` rung, because it lists every paused agent with its reason and its own Unpause button. The slot sits under the strip and above the tabs.
- **D-8 Plan tab.** Views: Map, PRD. Map is `DrawerPlanPanel`, unchanged. PRD renders the PRD inline, not in a dialog. Tasks keeps its own tab entry.
- **D-9 Changes tab.** Views: Files (`ChangedFilesView`), Checks (the PR's check runs), Artifacts (`DrawerArtifactsPanel`).
- **D-10 Activity tab.** Views: Feed and Status history. Feed is `HappenedFeed` followed by `DrawerActivityPanel`. Status history is `ActivityTab`. No new data source is built; all three existing feeds get a home.
- **D-11 Details additions:** a Status section; in the pipeline table a model line, a cost column, a total, a live duration and rows for pane-only phases; a cost breakdown disclosure; a Ship section; linked conversations; the stack disclosure; and the Deft panels. The two-column layout switches by container width, not viewport width.
- **D-12 Per-agent cost source.** The cost column reads `useIssueCostsQuery(issueId).data.sessions`, the cost ledger behind the header total and the Costs page. An agent's rows are summed. The conversation meta row keeps the live `costSoFar` counter PAN-5244 gave it.
- **D-13 Pane-only sessions become visible.** A phase with a live backend pane and no agent record renders as live in the pipeline strip and gets a row in the Details pipeline table showing the pane's model and harness. Its conversation is not opened from the issue view.
- **D-14 Temporary duplicates.** Because no cockpit file is edited, two components exist twice on main until PAN-5246 merges, and PAN-5246 deletes the cockpit copies:
  1. the check-run list: old `CheckRunList` and `GitHubCiPanel` inside `Stage/cockpit/IssueMissionControl.tsx:252-327`; new `components/issue-view/IssueChecksPanel.tsx`;
  2. the stack disclosure: old `StackDrawer` inside `Stage/cockpit/AgentsLane.tsx:108-233`; new `components/issue-view/StackDrawer.tsx`.

  Two small helpers are also copied and lose their originals in PAN-5246: the needs-you action resolver (old `Stage/cockpit/useCockpitNeedsYouActions.ts`, new `components/issue-view/useNeedsYouActions.ts`) and `formatDuration` (old `Stage/cockpit/CockpitPhaseRail.tsx:50-57`).

  The tab map also exists twice. The cockpit keeps its own `LEGACY_TAB_MAP` and `resolveTabSelection` (`IssueMissionControl.tsx:98-123`) beside the new `TAB_TABLE` in `issueTabs.ts`. They disagree on one value by design: `tasks` opens Plan › Tasks in the cockpit and the Tasks tab in the shared table. PAN-5246's rewrite of `IssueMissionControl.tsx` removes the cockpit map.
- **D-15 Protected code is not edited:** `components/IssueActionMenu/*`, `components/chat/ConversationPanel.tsx`, `components/issue-view/NeedsYouSlot.tsx`, `components/issue-detail/IssueDetailShell.tsx`, the body of `SkillOverridesPanel`, the full variant of `PickupGateControls`, and everything under `components/Stage/`.
