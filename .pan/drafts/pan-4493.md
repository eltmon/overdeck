# PAN-4493 — Click a pasted image to view it full size, in the composer and in sent messages

**Issue:** https://github.com/eltmon/overdeck/issues/4493

**Verified against:** `feature/pan-4493` at `bb8ffba0885` (2026-10-03).

## Glossary

- **Attachment** — a file the operator adds to a composer message (paste, drag-drop, or paperclip). It uploads to the attachments folder and the sent message refers to it by absolute path.
- **Attachments folder** — `<OVERDECK_HOME>/conversation-attachments/<conversation-name>/`. `getConversationAttachmentDir(name)` in `src/dashboard/server/services/conversation-attachments.ts` builds it. The upload handler writes image files as `<uuid>.<ext>` (`src/lib/overdeck/conversation-message.ts`, grep `fileName = \`${randomUUID()}${extension}\``).
- **Conversation name** — the `name` column of a conversation row, validated as `/^[a-zA-Z0-9_-]{1,64}$/` by `assertSafeName()` in `conversation-attachments.ts`. Example: `20260815-f8c3`.
- **Attachment reference** — the text the composer adds for each uploaded attachment: `@<absolute path>` (`ComposerFooter.tsx`, grep `` `@${attachment.serverPath}` ``). Claude Code stores this text verbatim in the transcript user record, for example `"content":"@/home/eltmon/.overdeck/conversation-attachments/20260815-f8c3/cfbbfdf0-43e4-4ae3-91a7-3b441a574aed.png"`. For non-Claude harnesses, `transformMessageForHarness()` (`conversation-message.ts`) removes the `@` and lists the bare path as `- /abs/path`.
- **Image extension** — one of `IMAGE_ATTACHMENT_EXTENSIONS = ['.png', '.jpg', '.jpeg', '.gif', '.webp']` (`conversation-message.ts`).
- **Lightbox** — a full-screen overlay that shows one image at its natural size (capped to the viewport). Escape or a click on the dark backdrop closes it.
- **Dialog host** — the repo pattern for overlays: a zustand store plus a `<XxxHost />` component mounted once in `src/dashboard/frontend/src/main.tsx` (see `LinkPullRequestDialogHost`, `ContinueOnDeviceDialogHost`). The overlay outlives the component that opened it.
- **No-loss matrix** — `tests/unit/lib/overdeck/no-loss-matrix.ts`. `tests/unit/lib/overdeck/no-loss-matrix.test.ts` enumerates every `HttpRouter.add('METHOD', '/path')` under `src/dashboard/server/routes/` and fails when a route has no row.
- **File-size ratchet** — `scripts/lint-file-size.sh` (part of `npm run lint`): a non-test `.ts`/`.tsx` file under `src/` may not grow past its `origin/main` line count when over 1000 lines, or past its last row in `scripts/file-size-allowlist.txt`.

## Problem

A pasted image shows only as a 32×32 thumbnail in the composer (`.composerImageThumb`, `command-deck.module.css`). The thumbnail is not clickable. After send, the timeline shows only the `@/…/conversation-attachments/<name>/<uuid>.png` path as text. No server route reads an attachment back, so the browser has no URL for the stored image. The operator cannot check what they pasted, before or after sending.

## Decisions (made here; `--auto` mode)

- **D1 — Images only.** The read route serves only files with an image extension. Content types: `.png` → `image/png`, `.jpg`/`.jpeg` → `image/jpeg`, `.gif` → `image/gif`, `.webp` → `image/webp`. Every other name returns 404. Why: the folder also holds uploaded `.html`, `.js`, `.svg`-free text and PDF files; serving `.html` from the dashboard origin would run operator-uploaded script same-origin.
- **D2 — Every failure is 404.** Bad conversation name, bad file name, traversal, other conversation's file, non-image extension, missing file, a symlink that escapes the folder: all 404 with `{ "error": "Attachment not found" }`. Origin failure stays 403 like every other conversation route.
- **D3 — No database lookup.** The route trusts filesystem containment (`hasConversationAttachment`) and does not call `getConversationByName`. The folder only exists for real conversations, and cleanup deletes folders of deleted conversations. This keeps the unit test DB-free.
- **D4 — Response headers.** `Content-Type` from D1, `X-Content-Type-Options: nosniff`, `Cache-Control: private, max-age=31536000, immutable` (file names are UUIDs and never rewritten).
- **D5 — New route file.** `src/dashboard/server/routes/conversation-attachments.ts`, registered in `server.ts` next to `conversationPermissionRoutes`. Do not edit `routes/conversations.ts` (file-size cap, fact 4).
- **D6 — One shared lightbox, dialog-host pattern.** `src/dashboard/frontend/src/components/chat/ImageLightbox.tsx` exports `useImageLightboxStore`, `openImageLightbox(src, alt)`, `ImageLightboxHost`. Mounted in `main.tsx`. Why: the timeline is virtualized (a row-owned overlay unmounts when its row scrolls out) and the composer box may clip a fixed child.
- **D7 — Thumbnails beside the text, not instead of it.** The sent message keeps its text unchanged (the path stays a `MarkdownFileLink`) and gains a thumbnail strip under the text inside the same bubble. Why: no text is lost, and replacing a token inside `ChatMarkdown` would fight its path linkifier.
- **D8 — Reference detection by path segment.** A pure helper finds every `/conversation-attachments/<name>/<file>` occurrence in the message text, with or without a leading `@`, where `<name>` matches `[A-Za-z0-9_-]{1,64}` and `<file>` matches `[A-Za-z0-9._-]+` ending in an image extension. The thumbnail URL uses the `<name>` from the path itself, so `UserMessageRow` needs no new prop, and a post-`/clear` or forked conversation whose transcript references its parent's folder still renders. De-duplicate by URL; keep first-seen order.
- **D9 — Missing file hides the thumbnail.** A thumbnail whose `<img>` fires `onError` (file cleaned up, 404) renders nothing; the path text remains.
- **D10 — Composer lightbox closes when its own attachment goes away.** When a composer thumbnail opens the lightbox, that `ComposerFooter` records the attachment id in a ref. Its effect closes the lightbox only when that recorded id is no longer in its own `pendingAttachments` (removed or sent) and the lightbox still shows that attachment's `previewUrl`, because the object URL is revoked at that moment. A composer never closes a lightbox it did not open, so two mounted composers (Stage tabs, issue detail + session panel) cannot close each other's lightbox.
- **D11 — Route scope unchanged.** The route is not added to `src/dashboard/server/route-scopes.ts`, so a scoped access token needs `admin` for it. The dashboard page uses the root session, and paired devices are `admin`, so nothing user-facing breaks.

     '.png': 'image/png',
     '.jpg': 'image/jpeg',
     '.jpeg': 'image/jpeg',
     '.gif': 'image/gif',

   /** PAN-4493: resolve a GET of one attachment to a servable image, or null (→ 404). */
   export async function resolveConversationImageAttachment(
     name: string,
     file: string,
   ): Promise<{ path: string; contentType: string } | null> {
     if (!/^[a-zA-Z0-9_-]{1,64}$/.test(name)) return null;
     if (!/^[A-Za-z0-9._-]+$/.test(file) || file.startsWith('.')) return null;
     const contentType = IMAGE_CONTENT_TYPES[extname(file).toLowerCase()];
     if (!contentType) return null;
     const candidate = join(getConversationAttachmentDir(name), file);
     if (!(await hasConversationAttachment(name, candidate))) return null;
     const resolved = await realpath(candidate).catch(() => null);
     if (!resolved) return null;
     const info = await stat(resolved).catch(() => null);
     return info?.isFile() ? { path: resolved, contentType } : null;
   }

       const request = yield* HttpServerRequest.HttpServerRequest;
       const originCheck = validateOrigin(request);
       if (!originCheck.ok) return jsonResponse({ error: originCheck.error }, { status: 403 });
       const params = yield* HttpRouter.params;

         contentType: found.contentType,

### WI-4 — Attachment reference parser — traces FR-7

**Files:** `src/dashboard/frontend/src/components/chat/messagesTimeline/helpers.ts`, `src/dashboard/frontend/src/components/chat/messagesTimeline/__tests__/attachmentRefs.test.ts` (new).

Add:
```ts
const ATTACHMENT_IMAGE_REF = /\/conversation-attachments\/([A-Za-z0-9_-]{1,64})\/([A-Za-z0-9._-]+\.(?:png|jpe?g|gif|webp))(?![A-Za-z0-9._-])/gi;

export interface AttachmentImageRef { conversationName: string; file: string; url: string }

/** PAN-4493: image attachments a user message references, in first-seen order. */
export function extractAttachmentImageRefs(text: string): AttachmentImageRef[] {
  const seen = new Set<string>();
  const refs: AttachmentImageRef[] = [];
  for (const [, conversationName, file] of text.matchAll(ATTACHMENT_IMAGE_REF)) {
    if (file.startsWith('.')) continue;
    const url = `/api/conversations/${encodeURIComponent(conversationName)}/attachments/${encodeURIComponent(file)}`;
    if (seen.has(url)) continue;
    seen.add(url);
    refs.push({ conversationName, file, url });
  }
  return refs;
}
```
