# PAN-3964 — Restore the Flywheel page as a derived view

**Issue:** https://github.com/eltmon/overdeck/issues/3964
**Planned:** 2026-09-21 (auto mode, `pan plan --auto`)
**Supersedes:** PAN-3917 FR-13 / D12 in `.pan/drafts/pan-3917.md` (the page and operator affordances come back; the loop-skill shape stays).

The operator said "No, I didn't want it cut!" The Cut (commit `3fb7100`, W7; `0219a2636e1`, W6; `fb67bbabf5c`/`f5c25f818ae`, W9; `7b953449633`, W10) deleted the Flywheel dashboard page, its run-record telemetry, and the `pause`/`resume`/`abort`/`report`/`stats` verbs, keeping only `pan flywheel start|stop|status` and the `pan-flywheel` loop skill. This PRD restores every v1 affordance as a **derived view**: nothing new is stored in SQLite, the only files are under `.pan/flywheel/`, and every status the page shows is computed on read from the flywheel conversation's transcript, the pipeline journals, the tracker, the forge, and the control settings.

## Glossary

- **Flywheel conversation** — the one operator conversation named `conv-flywheel` (`FLYWHEEL_CONVERSATION_SESSION`, `src/cli/commands/flywheel.ts:30`) whose tmux session runs the `/pan-flywheel` skill. Its row lives in the `conversations` table of overdeck.db; its transcript is a harness JSONL resolved by `resolveSessionFile` (`src/lib/overdeck/conversation-reads.ts:88`).
- **Loop skill** — `sync-sources/skills/pan-flywheel/SKILL.md`, the prompt the conversation executes. It is the orchestrator; there is no daemon.
- **Tick** — one revolution of the loop (orient → pick → launch → watch → park). The skill ends every tick by printing a **tick marker**, one line the server can parse (see FR-2).
- **Tick marker** — a single assistant-message line of the form `flywheel-tick: tick=<n> pick=<ISSUE-ID|none> phase=<orient|pick|launch|watch|park|idle|stopping> in-flight=<ISSUE-ID,…|none> needs-you=<free text|none>`. Parsed by `parseTickMarker` (FR-2). The message's `createdAt` is the tick timestamp.
- **Derived flywheel status** — the `FlywheelDerivedStatus` value computed by `deriveFlywheelStatus()` (FR-1) from live sources. Never stored.
- **Plan home** — the checkout whose `.pan/` holds project-level artifacts; `resolvePlanHome(projectRoot)` (`src/lib/pan-dir/paths.ts:46`). For the flywheel it is resolved from the flywheel conversation's `cwd`, or from `process.cwd()` when no conversation exists (the dashboard runs from the Overdeck project root, as v1's `readFlywheelState` did).
- **State file** — `<planHome>/.pan/flywheel/state.md`, the durable cumulative memory the loop maintains (substrate fixes, learnings). Replaces v1 `docs/FLYWHEEL-STATE.md`. Committed by whoever writes it (`commitPlanArtifacts`, `src/lib/overdeck/plan-artifact-commit.ts:42`).
- **Report file** — `<planHome>/.pan/flywheel/report.md`, written by the loop when it stops (what shipped, in flight, parked). Overwritten per stop; git history is the archive.
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl`, append-only, read with `readPipelineJournal`/`lastPipelineEntry` (`src/lib/cloister/pipeline-journal.ts:92,118`). Dies with the workspace.
- **Policies** — the three booleans in the control-settings table: `auto_pickup_backlog`, `require_uat_before_merge`, `merge_train_enabled` (`src/lib/overdeck/control-settings.ts:473-494`), served by `GET/POST /api/merge-train/config` (`src/dashboard/server/routes/merge-train.ts:433-458`).
- **Pickup gate vocabulary** — the labels `ready`, `released`, `parked`, `vetoed`, `objection` plus the derived facts `planned`, `inPipeline`, `epic`, as defined in `src/lib/backlog/pickup.ts:1-60` and `roles/flywheel.md:216-231`. `released` and `vetoed` are operator-only labels.
- **Substrate bug** — a tracker issue carrying the `substrate-improvement` label (the label that exists on eltmon/overdeck; v1 searched `label:substrate`, which no longer exists). Severity comes from a `P0`/`P1`/`P2` label when present, else `unknown`.
- **NO_LOSS_MATRIX** — `tests/unit/lib/overdeck/no-loss-matrix.ts`; `no-loss-matrix.test.ts` enumerates every `HttpRouter.add(` in `src/dashboard/server/routes/*.ts` and fails when a route has no row.

## Decisions (made here, not by the executor)

- **D1 State store.** The state file and report file live under `<planHome>/.pan/flywheel/`, not `docs/`. Acceptance says the only stores are `.pan/` files and the journal. The loop writes them and commits them with `commitPlanArtifacts({ paths: ['.pan/flywheel'], message: 'chore(workspace): flywheel state' })` — the same shape `pan backlog write-sequence` uses (`src/cli/index.ts:361-368`).
- **D2 Stats source.** Substrate-bug stats are computed on read from the tracker and the forge, not from a `.pan/` observation file. Reason: a substrate bug already lives in the tracker as a labeled issue; a second file would drift. The pipeline journal cannot hold a 30-day window because it dies with the workspace. The tracker cache cannot serve it either (`closedWindowDays` defaults to 14, `src/lib/config-yaml/defaults.ts:235`), so the reader shells `gh issue list --label substrate-improvement --state all --search "created:>=<iso-date>" --json number,title,createdAt,closedAt,labels --limit 500` through an injected dependency and caches it for 60 s. The denominator (completed pipeline runs) is merged PRs in the window from `listRepoPullRequests` (`src/lib/overdeck/derived-issue-state.ts:272`, `mergedAt` set). Only criteria c1 (discovery rate) and c2 (P0 count) come back; c3–c7 are non-goals (their inputs were the deleted telemetry).
- **D3 Tick marker in the transcript.** The "last tick summary / current pick / phase / needs-you" pane is fed by a parseable line the skill prints at the end of every tick (FR-2). No status endpoint, no POST from the loop. The dashboard and the CLI both parse the same transcript through the same function.
- **D4 Pause = stop the session, keep the row.** `pan flywheel pause` calls `handleConversationStop` (`src/lib/overdeck/conversation-runtime.ts:996`) — session killed, conversation row marked ended, transcript preserved. `resume` calls `handleConversationResume` (`:1028`) and then re-sends `/pan-flywheel` (the skill re-orients from live state, so re-entry is idempotent). `abort` = pause without a report. `stop` = graceful: ask the loop to write the report, wait, then stop.
- **D5 Start refuses a paused conversation.** `createConversation` (`src/lib/overdeck/conversations.ts:1209`) deletes any existing row by name, so `start` over a paused flywheel would drop its row. `pan flywheel start` exits 1 with "paused flywheel exists — `pan flywheel resume` to continue, `pan flywheel start --fresh` to start over" unless `--fresh`.
- **D6 Policies' home.** `auto_pickup_backlog` and `require_uat_before_merge` get toggles in the Flywheel page header (they have no UI today). `merge_train_enabled` stays on the Merge train section of the Awaiting Merge page (`components/merge-train/MergeTrainSection.tsx`); the Flywheel header shows a read-only "Merge train: on/off" chip linking to `/awaiting-merge`.
- **D7 One shared deriver.** `pan flywheel status`, `GET /api/flywheel/status`, and the page all consume `deriveFlywheelStatus()` from `src/lib/flywheel/derive-status.ts`. That is what makes "the CLI and the page agree" mechanically true.
- **D8 Project scope.** The flywheel is scoped to the project of its conversation's `cwd`. In-flight issues are that project's `workspaces/feature-*` directories (`listFeatureWorkspaces()`, `src/lib/cloister/deacon-workspaces.ts:15`, filtered by `projectPath`), derived with `loadIssueStatesForProject` (`src/lib/overdeck/derived-issue-state.ts:718`).
- **D9 Sizing.** This is one plan with `plan.metadata.sizeJustification`: the no-loss acceptance ("every row has a home") and the CLI/page agreement acceptance span all rows, and a page without its verbs or verbs without the page is exactly the partial state the operator objected to.

## Repo rules that apply (restated)

- No `execSync` in server-reachable code; `execFile` + `promisify`, or `spawn`. `src/lib/flywheel/*` is server-reachable.
- Async tmux only (`sendKeysAsync`, `sessionExists`, `killSession` from `src/lib/tmux.ts`).
- Fake timers for any test with a delay (`stopFlywheel` waits for the report; test with `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync`).
- Every new `HttpRouter.add` route needs a `NO_LOSS_MATRIX` row in the same commit.
- Editing `sync-sources/skills/pan-flywheel/SKILL.md` requires a `Prompt-Change: <reason>` trailer in the commit (`scripts/check-prompt-change-trailer.sh:31`).
- Any `pan flywheel <sub>` mentioned in the skill must exist in `pan flywheel --help` (`scripts/lint-skills.sh`).
- Files over 1,000 lines that grow need a `scripts/file-size-allowlist.txt` row `<lines> <path> # PAN-3964`: `CommandPalette.tsx` (1,113), `App.tsx` (1,010), and `Sidebar.tsx` (981 — crosses the ceiling if it grows by 20+ lines).
- Frontend: `pan-style-guide` — no pill badges, no decorative color, running is not green.
- Never hardcode a model fallback; `pan flywheel start` keeps using `resolveModel('flywheel', …)` and `resolveHarness`.
- Never `git stash`; never checkout inside the workspace.
