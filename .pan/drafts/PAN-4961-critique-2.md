## blocks-the-design: Docker usage command cannot supply per-volume JSON

[PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4961/.pan/drafts/PAN-4961.md), lines 362–370, tells the estimator to parse `Volumes[]` and `Images[]` from `docker system df -v --format '{{json .}}'`. Docker's [command reference](https://docs.docker.com/reference/cli/docker/system/df/) says `--format` has no effect with `--verbose`; without verbose, JSON contains aggregate `Type`/`Size` rows, not named volumes or images. I reran the specified command, but this sandbox cannot access `/var/run/docker.sock` (`permission denied`). The planned fixtures would pass while the real estimator cannot measure any sibling stack, leaving the seed as the only cost on every host. Replace the command with a verified machine-readable per-volume/per-image source, and make a test parse that source's real output shape.

## blocks-the-design: CLI fallback creates workspaces without admission

[PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4961/.pan/drafts/PAN-4961.md), lines 157–163, lists the covered creation and Docker doors. But [workspace-create.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4961/src/cli/commands/workspace-create.ts), lines 107–115, uses `createWorkspace` only when a workspace config exists. Its fallback directly creates a worktree at lines 211–263, optionally runs `docker compose ... up -d --build` at lines 325–362, and installs dependencies at lines 390–397. None of those steps pass through the planned reservation or re-check. Concurrent `pan workspace create --docker` calls for a project without `workspace` config can therefore reproduce the disk exhaustion this issue aims to stop. Add admission and release around this fallback's host and Docker phases, with re-checks before its install and compose calls; cover it in the plan and a test.

## blocks-the-design: Partial sibling stacks can shrink the cost estimate

[PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4961/.pan/drafts/PAN-4961.md), lines 126–129, calls the 2 GiB stack seed a lower bound, but WI-2 at lines 362–370 takes any nonzero sibling volume/image sum as `stackBytes` without that lower bound. A sibling with a failed Docker startup still qualifies as “finished”: [create.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4961/src/lib/workspace-manager/create.ts), lines 720–730, records compose failure as a soft error, then clears the setup-incomplete marker at lines 784–789. Its partially filled, nonzero volume can be far smaller than a successful stack. Subsequent concurrent rebuilds would reserve that small figure and could again cross the floor. Require a healthy, completed stack for a sibling sample and apply `max(SEED_STACK_DISK_COST_BYTES, measuredBytes)` as D-5 promises; add a partial-volume fixture that proves the estimate cannot fall below the seed.
