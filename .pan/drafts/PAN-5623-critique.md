## blocks-the-design: A failed journal write can strand stopped containers

The PRD's D5 and WI-12 require `stack.reclaimed` to be appended before `docker stop` ([PAN-5623.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/.pan/drafts/PAN-5623.md), lines 122 and 381–382). But `appendPipelineEntry` catches write errors, returns the stamped entry even if no bytes landed, and still notifies listeners ([pipeline-journal.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/src/lib/cloister/pipeline-journal.ts), lines 66–101). A full or unwritable filesystem therefore lets the poll stop containers with no recoverable record. Require a confirmed journal write (or verify the exact new entry can be read back) before the first stop, and test the write-failure path.

## blocks-the-design: Restore accepts foreign containers named in the journal

D9 validates only name syntax, then looks up each journaled name in `docker ps -a` and starts it ([PAN-5623.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/.pan/drafts/PAN-5623.md), lines 126–132). `readPipelineJournal` accepts any JSON line with string `type` and `at` from the workspace file ([pipeline-journal.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/src/lib/cloister/pipeline-journal.ts), lines 127–149). A well-formed `stack.reclaimed` line can therefore make a spawn or verification start `postgres` or a container from another project; the regex does not enforce ownership. Before `docker start`, recompute the issue's compose project with the existing `tryComposeProjectNameForWorkspace` ([stack-health.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/src/lib/workspace/stack-health.ts), lines 180–186) and require the listed container to have that project label and an allowed service. Add a foreign-project and disallowed-service restore test.

## blocks-the-design: Restore can close the journal before stop finishes

WI-12 appends `stack.reclaimed` and then awaits separate `docker stop` calls; WI-5 allows spawn and verification in other processes to restore as soon as the entry exists ([PAN-5623.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/.pan/drafts/PAN-5623.md), lines 126–135 and 381–382). If a spawn reads the journal while a stop is pending, it can classify a still-running container as `alreadyRunning` and append `stack.restored`. The delayed stop can then finish, leaving a stopped container with no open reclaim for the restore poll. Serialize reclaim and restore for each issue across processes, covering journal reads/writes and Docker calls; the repo already has a cross-process `withFileLock` primitive ([file-lock.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/src/lib/vault/file-lock.ts), lines 1–9 and 63–71). Set its stale timeout beyond the entire bounded stop sequence, and test this interleaving.

## blocks-the-design: Dashboard spawn can reject before reaching restore

D10 adds restoration only inside `assertWorkspaceStackHealthyForSpawn` ([PAN-5623.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/.pan/drafts/PAN-5623.md), line 134). The dashboard's local spawn route reads strict health, then returns a disk-floor hold before calling that gate ([spawn-issue.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/src/dashboard/server/routes/agents/spawn-issue.ts), lines 506–524). A reclaimed stack plus low free disk therefore blocks the promised spawn restore even though this path only needs `docker start`. Restore before the route's disk hold, refresh its health snapshot, and apply the disk-floor check only if a rebuild is still needed. Test a reclaimed stack with a disk-floor hold.

## blocks-the-design: The pre-stop check omits starvation and container ownership

WI-12 first checks the open starvation episode and obtains a Docker listing, then may spend seconds in `evaluateIssueMergeGate` (which explicitly waits before a fresh forge read at [merge-gate.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/src/lib/cloister/merge-gate.ts), lines 141–150). Its step 8 rechecks only gate membership, verification activity and panes ([PAN-5623.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5623/.pan/drafts/PAN-5623.md), lines 373–382). By the time it stops a name, the queue may have admitted a gate, memory may have recovered, or Docker may have replaced that name with a container under another compose label. Recheck the episode/head/memory and the target containers' IDs, labels, services and running states immediately before journaling; stop by the verified IDs so name reuse cannot redirect the stop. Test an admitted queue and a changed container identity during the merge-gate wait.
