## Glossary

- **Agent token:** an access-token record of `kind: 'token'` that carries `agentId`, `agentKind` (`'agent' | 'conversation'`) and `role` (W-TOK1, `src/lib/mcp/agent-token.ts`). For an agent, `agentId` is the normalized agent id (`agent-pan-1`); for a conversation, it is the conversation **name**.
- **Agent scopes:** `AGENT_TOKEN_SCOPES` (`src/lib/mcp/agent-token.ts:37-49`). `work`, `worker`, `plan`, `strike`, `sequencer`, `knowledge`, `flywheel`: `read:events, read:state, read:conversations, tell, operate`. `review`, `test`, `ship`: the same **without** `operate` (`REVIEW_SCOPES`, line 34). `conversation`: adds `operate` and `approve`.
- **Self route:** a route under `/api/self/` that acts for the calling agent. It accepts only an agent token and takes the agent from the token, never from the request.
- **Self caller:** `SelfCaller` (`src/dashboard/server/self-caller.ts:20-31`): `agentId`, `agentKind`, `role`, `cwd`, `issueId`, `tmuxSession`. Built by `selfCallerFromCredential` (line 51), which answers 403 `not-an-agent-token` or 404 `agent-gone`.
- **Job:** one `pan` command a self route runs as a child process for the caller (`createSelfJobs().start`, `services/self-jobs.ts`). Held in dashboard memory.
- **Job verb:** a key of `SELF_JOB_VERBS` (`services/self-job-argv.ts:14-24`). This item uses `task-claim`, `task-done`, `task-block`, `done`, `handoff`, `worker-report`; all six are already in the table.
- **Job argument piece:** `SelfJobArg` (`self-job-argv.ts:33`): `{ ref }` (an id that must match `SELF_JOB_REF_PATTERN`, never starting with `-`), `{ flag, value }` (one `--flag=value` token), `{ switch }` (a bare `--switch`), `{ rest }` (values after one `--`, last piece only). Caller text reaches argv only through these.
- **Job answer:** `selfJobAnswer(state)` (`services/self-jobs.ts:98-107`): `{ status: 'done', exitCode, stdout, stderr, … }` or `{ status: 'running', jobId, verb, startedAt, next: { tool: 'wait_job', arguments: { jobId } } }`.
- **Wait chunk:** `WAIT_CHUNK_MS = 50_000` (`src/lib/mcp/tool.ts`), the most any wait blocks.
- **Route-scope table:** `ROUTE_SCOPES` in `src/dashboard/server/route-scopes.ts`. The global gate (`remote-request-gate.ts:142-149`) refuses a credential without the row's scope with 403 `{ error: 'insufficient_scope', missingScope }` before any handler runs. Unlisted routes need `admin`.
- **No-loss matrix:** `NO_LOSS_MATRIX` in `tests/unit/lib/overdeck/no-loss-matrix.ts`; every route in a top-level `src/dashboard/server/routes/` file needs a row.
- **Claimant:** the id `pan task claim` writes as `claimedBy`: `OVERDECK_CLAIM_ID || OVERDECK_AGENT_ID || cli-<pid>` (`resolveClaimantId`, `src/lib/xbrief/claim-check.ts:151-153`). A `cli-` holder is treated as dead without a probe (`probeHolder`, lines 166-177), so anyone can take its item.

## Facts (verified 2026-11-04 against `feature/pan-4937`)

1. **The verbs and their flags.** `task claim <issue> <item>` with `--json` (and `--steal`, not used), `task done <issue> <item>` with `--json`, `task block <issue> <item>` with `--json` and `--on <refs...>` (`src/cli/commands/task.ts:253-261`). `done <id>` with `-c/--comment`, `--force`, `--test-waived`, `--strike` and no `--json` (`src/cli/index.ts:445-452`). `handoff [conv] [focus...]` with `--title <title>`, `--cwd`, `--allow-primary` and others (`src/cli/index.ts:399-418`). `worker report <worker-id>` with `--file`, `--stdin`, `--status <done|blocked|failed>` (`src/cli/commands/worker.ts:545-551`).
2. **The `pan` entry pre-parses `--yolo` anywhere in argv.** `src/cli/index.ts:60-86` removes any element equal to `--yolo` or `--no-yolo`, or starting with `--yolo=`, **even after `--`**, and sets `PAN_YOLO` (the permission-bypass mode, `src/lib/claude-permissions.ts:7-45`). `program.enablePositionalOptions()` (line 95) touches nothing else after a subcommand. 2a. **Commander parses the argv forms the jobs use** (probe run 2026-11-04 against `node_modules/commander` 12.1.0 with the same command shapes): `block PAN-1 item-a --on=PAN-2 --on=#45 --json` gives `on: ['PAN-2', '#45']`; a PR URL and `o/r#9` pass through `--on=` unchanged; `handoff my-conv --title=--allow-primary -- --cwd / Read the brief` gives `title: '--allow-primary'`, focus `['--cwd / Read the brief']` and no `cwd` or `allowPrimary` option; `report agent-pan-1-worker-1 --status=blocked --stdin` gives `status: 'blocked', stdin: true`.

## Requirements

### Functional

- **FR-1 Caller from the token.** Every route in this item resolves its caller with `selfCallerFromCredential` and never reads an agent, issue or conversation from the body. A non-agent credential gets 403 `not-an-agent-token`; a gone agent 404 `agent-gone`.
- **FR-2 Checklist routes.** `POST /api/self/tasks/claim`, `/api/self/tasks/done` and `/api/self/tasks/block` run `pan task claim|done|block <issueId> <itemId> [--on=<ref>…] --json`, where `issueId` is the caller's issue.
- **FR-3 Done route.** `POST /api/self/done` runs `pan done <issueId>`. Its scope row is `operate`, so a review, test or ship token gets the gate's 403 `missingScope: 'operate'`.
- **FR-4 Handoff route.** `POST /api/self/handoff` runs `pan handoff self [--title=<title>] -- <focus>`. It never passes `--cwd` or `--allow-primary`.
- **FR-5 Worker report route.** `POST /api/self/worker-report` runs `pan worker report <agentId> --status=<status> --stdin` with the report on the child's stdin, only for a caller whose role is `worker`.
- **FR-6 Start, then wait.** Each route starts the job, waits at most `WAIT_CHUNK_MS` for it, and answers 200 with `selfJobAnswer`: `done` with the result, or `running` with `next: wait_job`.
- **FR-7 Six tools.** `task_claim`, `task_done`, `task_block`, `done`, `handoff`, `worker_report` in `SELF_TOOLS`, each `audience: 'agent'`, each with the scope of its route, each passing the route's answer through unchanged.
- **FR-8 Conversation identity in jobs.** A job for a conversation caller carries `OVERDECK_AGENT_ID=<tmuxSession>` as well as `OVERDECK_CONVERSATION=<tmuxSession>`, as the conversation's own launcher exports (Fact 7).
- **FR-9 Documentation.** `configuration/mcp.mdx` lists the six tools; `docs/DASHBOARD-AUTH.md` lists the six routes, their codes and the corrected job env.

### Non-functional

- **NFR-1 Async only.** No `execSync`, `spawnSync`, `execFileSync` and no new `*Sync` function (repo rules `no-execsync-server`, `prefer-async`). Jobs run through W-SELF1's store only.
- **NFR-2 Safe argv.** Every argv piece is built with `buildSelfJobArgv` constructors. Body text reaches argv only as a `{ flag, value }` token or after `--` (`{ rest }`); ids reach it only as a validated `{ ref }`.
- **NFR-3 One authority.** Every route has a `route-scopes.ts` row and a no-loss row and lives in the top-level file `src/dashboard/server/routes/self-workflow.ts` (epic NFR-9).
- **NFR-4 Fake timers.** A test that waits on the 50 s chunk uses `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()` inside a nested `describe` only, never real sleeps (repo rule `fake-timers-for-retry-tests`).
- **NFR-5 Size and Effect boundary.** `routes/self-workflow.ts` stays under 300 lines; `tools-self.ts` under 250. No exported Effect wrapper (`npm run lint:effect-facades` must not rise).
- **NFR-6 Parity.** A job's argv, cwd and identity env equal what the same agent's own `pan` invocation uses, so the state it writes is the same.

## Decisions

- **D-1 One route file, sequential slices.** All six routes go in `routes/self-workflow.ts` (the epic's file). Every slice also appends to `route-scopes.ts`, `no-loss-matrix.ts`, `tools-self.ts` and the two enumerating tests, so the slices share mutations and run in a chain (see Build order).
- **D-2 Status codes.** Order in each handler: caller (403 `not-an-agent-token` / 404 `agent-gone`), role check (`worker_report`: 403 `not-a-worker`), body parse (400 `bad-body`), field validation (400 `bad-request`), issue (409 `no-issue`), start (400 `bad-job-arg` from `SelfJobArgError`, 429 `too-many-jobs`), wait (200 job answer). Error bodies are `{ error, code }`.
- **D-3 200 for both job answers.** A started job answers 200 whether `done` or `running`, like the W-SELF1 wait route. `routeResult` treats every 2xx alike.
- **D-4 Tools pass job failures through.** A finished job with a non-zero `exitCode` is `status: 'done'` (W-SELF1 D-3) and the tool returns it as a normal result, as `wait_job` does. Each tool description says: "A non-zero exitCode means pan refused; stderr says why." Why: the same answer then arrives the same way from the first call and from `wait_job`.
- **D-5 `self` for handoff, plus the env fix (FR-8).** The handoff job passes the literal ref `self`, and `selfJobEnv` gives a conversation caller `OVERDECK_AGENT_ID=<tmuxSession>`. Why: a conversation name cannot always be a `ref` (Fact 11); `self` resolves exactly as in the conversation's own shell (Facts 5, 7); and the same variable makes a conversation's `task claim` record `conv-<name>` instead of a dead `cli-<pid>` (Glossary, Claimant). Nothing in the six verbs depends on the variable being absent (Fact 8).
- **D-6 No pre-check for a conversation row.** A work agent's `handoff` job runs and `pan handoff` answers "Could not determine the current conversation" with exit 1 (Fact 9). The CLI stays the one door; the tool description says handoff works only from a conversation or a role run that has one.
- **D-7 No primary-checkout pre-check.** The handoff inherits the caller's cwd, which is what `pan handoff self` does today (Fact 10). A work-agent or role-run caller's cwd is its feature workspace. The route never passes `--cwd` or `--allow-primary`.
- **D-8 No CSRF or Content-Type check.** The handlers accept only an agent token, which arrives only in the `Authorization` header, and `rejectUnsafeDashboardMutationRequest` would skip CSRF for it anyway (Fact 13). An empty body is `{}`.
- **D-9 Field limits.** `itemId`: non-empty string, then `{ ref }` validation (`bad-job-arg` if it fails the pattern). `on`: absent, or an array of 0–20 non-empty strings of at most 500 characters each; absent or empty runs the plain block. `focus`: required, non-empty after trim, at most 10,000 characters (repo rule `pan-handoff-focus-limit`). `title`: optional, non-empty after trim, at most 200 characters. `status`: one of `done`, `blocked`, `failed`, required. `report`: required, non-empty after trim, at most `MAX_WORKER_REPORT_BYTES` UTF-8 bytes. `done` reads no fields.
- **D-10 `done` takes no options.** The route passes only `<issueId>`: no `--comment`, `--force`, `--test-waived` or `--strike`. Agents that need them use `pan done` in a shell.
- **D-11 Scope is the only role gate for `done`.** Any agent token with `operate` may call it, like any agent may run `pan done` today. `worker_report` adds the `role === 'worker'` check because the CLI refuses any other caller anyway (Fact 8) and the epic requires it.

## Corrections to the epic

- **C-1** The epic's handoff argv is `handoff self …` and says nothing about the env. `self` never resolves in a W-SELF1 job for a conversation (Fact 6). FR-8 fixes the env; the argv stays `self`.
- **C-2** The epic says "a conversation whose `cwd` is a primary checkout gets the CLI's own refusal". It does not: the server checks only an explicit `--cwd` (Fact 10). D-7 accepts today's behavior.
- **C-3** The epic says an agent's handoff inherits "its feature workspace". A work agent has no conversation row, so its handoff is refused (Fact 9, D-6). Role runs with a row can hand off.
- **C-4** The epic's argv shows `--on <ref>…` and `--status <status>`; the jobs pass `--on=<ref>` once per ref and `--status=<status>` (the `{ flag, value }` form), which commander parses the same way (Fact 2).

```
                                      │  POST /api/self/… (Bearer agent token, JSON body)

                     startSelfJobAnswer → selfJobs.start(caller, verb, args, { stdin })  (400 / 429)
                                      └→ selfJobs.wait(jobId, caller, 50 000, signal) → 200 selfJobAnswer
                                                      ▲
                                    running → agent calls wait_job (W-SELF1) with `next`
```

## Hazards

- **H-1 Jobs run with the dashboard's rights** (epic H-7). Only the six verbs, argv only through the constructors, issue and agent from the token.
- **H-2 A dashboard restart forgets a running job.** The tool's next `wait_job` answers 404 `unknown-job`; the side effect (claim, PR) is still on disk. `pan task show` tells the agent where it stands.
- **H-3 A client that disconnects mid-wait** leaves the job running and never learns its `jobId`. Accepted: the job finishes; repeating the call is safe for claim (same claimant) and done (idempotent PR update).
- **H-4 Sibling collisions are certain.** W-SEC1 (PAN-4941, planned) also appends to `tools-self.ts`, `tools-approve.test.ts`, `tool-annotations.test.ts`, `route-scopes.ts`, `no-loss-matrix.ts` and `server.ts`; W-MEM1 and W-DEL1 will too.
