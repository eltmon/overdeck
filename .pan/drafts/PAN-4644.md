# PAN-4644 — Import VS Code themes and custom color themes in the dashboard

**Issue:** https://github.com/eltmon/overdeck/issues/4644
**Siblings (split out during planning):** #4659 `.vsix` import · #4660 duplicate-and-edit theme editor
**Status:** planning draft, 2026-11-01, auto mode

## Glossary

- **Mode** — the dashboard's light/dark switch. Stored in the browser (`localStorage` key `overdeck.ui.theme`) and mirrored to `~/.overdeck/ui-theme.json` by `PUT /api/settings/ui-theme`. Unchanged by this issue.
- **Design language** — Ledger or Broadsheet (`ui.theme` in `config.yaml`, `data-theme` on `<html>`). It controls type, density and shape. Unchanged by this issue.
- **Color theme** — new. A named set of colors with a `type` (`light` or `dark`) and three optional groups: `terminal`, `syntax`, `ui`. Identified by an **id** (lowercase slug).
- **Built-in theme** — a color theme that ships in code: `overdeck-dark` and `overdeck-light`. They carry today's terminal palettes and no `syntax`/`ui` group, so selecting them changes nothing visible.
- **User theme** — a color theme stored as `~/.overdeck/themes/<id>.json` (imported, or written by hand).
- **Selection** — which theme applies in each mode: `ui.color_theme.light` and `ui.color_theme.dark` in `~/.overdeck/config.yaml`. Unset means the built-in for that mode.
- **Active theme** — the selected theme for the current mode.
- **Effective terminal palette** — the built-in palette for the theme's type, overlaid with the theme's own `terminal` colors.
- **VS Code theme file** — a JSON-with-comments (JSONC) file with `name`, optional `type`, a `colors` map and a `tokenColors` array. Shiki's bundled themes use exactly this shape.
- **Window-style stamp** — `tmux set-option window-style bg=<hex>` run at session creation (`src/lib/tmux.ts`), so tmux answers Claude Code's OSC 11 background query for headless agents.
- **`COLORFGBG`** — env var exported by launcher scripts (`src/lib/launcher-generator.ts:355`); it encodes only light vs dark.

## Problem

Overdeck has a mode and a design language, but no way to change colors. The terminal palette is hardcoded in `XTerminal.tsx` (`xtermTheme(isDark)`), the tmux background stamp uses a fixed pair (`TERMINAL_BG` in `src/lib/ui-theme.ts`), and chat code blocks always use `github-light`. Operators cannot import a VS Code theme or define their own.

## Scope

In scope: the color theme model and built-ins; the `~/.overdeck/themes/` store; single-file VS Code `.json` import with preview; separate light and dark pickers; `ui.color_theme.{light,dark}` in `config.yaml`; terminal colors in xterm.js; the tmux window-style stamp; chat code-block syntax colors; a fenced UI token subset; docs.

Moved to siblings (the issue body records the move): `.vsix` import (#4659); the duplicate-and-edit editor with color pickers (#4660). Hand-editing JSON files in `~/.overdeck/themes/` works in this issue.

## Design

### Theme file shape (on disk and over the wire)

```jsonc
{
  "name": "Ayu Dark",
  "type": "dark",
  "terminal": {                       // every key optional, values "#rgb"/"#rrggbb"/"#rrggbbaa"
    "background": "#0d1017", "foreground": "#bfbdb6",
    "cursor": "#e6b450", "cursorAccent": "#0d1017", "selectionBackground": "#409fff4d",
    "black": "...", "red": "...", "green": "...", "yellow": "...", "blue": "...", "magenta": "...", "cyan": "...", "white": "...",
    "brightBlack": "...", "brightRed": "...", "brightGreen": "...", "brightYellow": "...", "brightBlue": "...", "brightMagenta": "...", "brightCyan": "...", "brightWhite": "..."
  },
  "syntax": {
    "colors": { "editor.background": "#10141c", "editor.foreground": "#bfbdb6" },
    "tokenColors": [ { "scope": ["comment"], "settings": { "foreground": "#5a6378", "fontStyle": "italic" } } ]
  },
  "ui": { "background": "...", "surface": "...", "border": "...", "foreground": "...", "muted": "...", "accent": "..." },
  "source": { "kind": "vscode-import", "fileName": "ayu-dark.json", "importedAt": "2026-11-01T00:00:00.000Z" }
}
```

The file name is the id: `~/.overdeck/themes/ayu-dark.json` → id `ayu-dark`. The id is never stored inside the file. Over the wire, a theme object also carries `id` and `builtin: boolean`.

### Validation rules (`normalizeColorTheme` in contracts)

- `name`: non-empty string, trimmed, at most 80 chars. Missing → error.
- `type`: `light` or `dark`. Missing or other → error.
- Hex color regex: `/^#(?:[0-9a-f]{3}|[0-9a-f]{4}|[0-9a-f]{6}|[0-9a-f]{8})$/i`. An invalid color is dropped with a warning naming the key. Never an error.
- `terminal` keys outside the 21 listed keys are dropped with a warning.
- `ui` keys outside the six listed keys are dropped with a warning.
- `syntax.tokenColors`: an array of at most 2000 entries. Keep an entry only if `settings` is an object; keep `scope` only if it is a string or string array; keep `settings.foreground`/`settings.background` only if they pass the hex regex; keep `settings.fontStyle` only if it matches `/^[a-z ]*$/`. `syntax.colors` keeps only `editor.background` and `editor.foreground`.
- Id regex: `/^[a-z0-9][a-z0-9-]{0,63}$/`. `slugifyThemeId(name)`: lowercase, runs of non-`[a-z0-9]` → `-`, trim `-`, cut to 64, empty → `theme`.
- Reserved ids: `overdeck-dark`, `overdeck-light`.

### Effective values

- `effectiveTerminalPalette(theme)` = `{ ...builtinFor(theme.type).terminal, ...theme.terminal }`, then `background` passed through `toOpaqueHex` (expand `#rgb`, drop alpha) so xterm and tmux render the same opaque color.
- `toOpaqueHex('#abc') === '#aabbcc'`, `toOpaqueHex('#0d1017cc') === '#0d1017'`.
- `readableForeground(hex)` returns `'#000000'` when the color's relative luminance is above 0.5, else `'#ffffff'`.

### UI token table (frontend applies these as inline `style.setProperty` on `<html>`, which beats every `.dark[data-theme=…]` selector)

| `ui` key | CSS tokens set |
| --- | --- |
| `background` | `--background`; and derived `--muted: color-mix(in srgb, var(--foreground) 5%, var(--background))`, `--secondary: color-mix(in srgb, var(--foreground) 6%, var(--background))`, `--accent: color-mix(in srgb, var(--foreground) 8%, var(--background))` |
| `surface` | `--card`, `--popover` |
| `border` | `--border`, `--input` |
| `foreground` | `--foreground`, `--card-foreground`, `--popover-foreground`, `--secondary-foreground`, `--accent-foreground`; derived `--body-foreground: color-mix(in srgb, var(--foreground) 85%, var(--background))`, `--faint-foreground: color-mix(in srgb, var(--foreground) 45%, var(--background))` |
| `muted` | `--muted-foreground` |
| `accent` | `--primary`, `--ring`, `--primary-ink`; `--primary-foreground: readableForeground(accent)` |

Never set: `--destructive*`, `--info*`, `--success*`, `--warning*`, `--signal-*`, `--state-*`. When the active theme changes, every property the previous apply set is removed first (`removeProperty`), so switching to a theme without `ui` restores the stylesheet values exactly.

### VS Code mapping (`src/lib/color-themes/vscode-import.ts`)

| VS Code key | Theme field |
| --- | --- |
| `terminal.background` / `terminal.foreground` | `terminal.background` / `terminal.foreground` |
| `terminalCursor.foreground` / `terminalCursor.background` | `terminal.cursor` / `terminal.cursorAccent` |
| `terminal.selectionBackground` | `terminal.selectionBackground` |
| `terminal.ansiBlack` … `terminal.ansiBrightWhite` (16) | `terminal.black` … `terminal.brightWhite` |
| `tokenColors` (array) | `syntax.tokenColors` |
| `editor.background`, `editor.foreground` | `syntax.colors` |
| `editor.background` | `ui.background` |
| `sideBar.background` | `ui.surface` |
| `panel.border` | `ui.border` |
| `editor.foreground`, else `foreground` | `ui.foreground` |
| `descriptionForeground` | `ui.muted` |
| `focusBorder` | `ui.accent` |

- `type`: VS Code `type` `dark`/`hc-black`/`hcDark` → `dark`; `light`/`hc-light`/`hcLight` → `light`. If absent, compute relative luminance of `editor.background`: below 0.5 → `dark`, else `light`. If that is absent too → `dark`, with a warning.
- `name`: `name` field, else the file name without extension.
- `include` present → ignored, warning `"include" is not supported for single-file import; colors from the included file are missing`.
- `tokenColors` as a string (a path) → ignored, warning; the theme imports without `syntax`.
- Parse with `jsonc-parser` `parse(text, errors, { allowTrailingComma: true, disallowComments: false })`. Any parse error → reject the import with 400 and the first error's offset.
- The mapper never fills fallbacks into the stored file. Fallbacks apply at use time (`effectiveTerminalPalette`), so a built-in palette change reaches imported themes.

## Repo rules that apply

- No `execSync` or new sync I/O in server-reachable code; use `fs/promises`.
- `tmux.ts` and `routes/settings.ts` are at their file-size cap: edits must be line-neutral; new routes go in a new file. Never raise `scripts/file-size-allowlist.txt`.
- Fake timers for any delay-based test (none expected here).
- Frontend CI runs only the files listed in root `package.json` `test:frontend-subset`; add new frontend test files there.
- A new HTTP route needs a row in `tests/unit/lib/overdeck/no-loss-matrix.ts` or CI fails.
- New tests must not grep source text (the source-introspection lint rejects that) and must not add `skipIf`/`.only`.
- pan-style-guide: no pill badges, no decorative color, running is never green; signal colors stay fixed.
- Quality gates per item: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>` (frontend: `npm --prefix ./src/dashboard/frontend run test -- <files>`). Never run the full `npm test` on the host.
- Contracts change needs `npm --prefix packages/contracts run build` before the server build picks it up; vitest aliases contracts to source.

## Acceptance criteria

1. Contracts: `normalizeColorTheme` drops an invalid hex with a warning and keeps the rest; rejects a missing `type`; `effectiveTerminalPalette` of a theme with no `terminal` equals the built-in palette of its type; `toOpaqueHex('#0d1017cc')` returns `#0d1017`.
2. Store: a saved theme is listed by a fresh `listColorThemes()` call (restart-equivalent); saving a second theme with the same name yields id `<slug>-2`; `overdeck-dark` can never be written; a malformed file is skipped with a warning naming it.
3. Config: `ui.color_theme: { light: ayu-light, dark: ayu-dark }` loads to `colorTheme` with both ids; `ui.color_theme.dark: 42` loads without throwing, warns, and yields `null`; a `PUT /api/settings`-style `saveSettingsApi` call on a config with only `ui.color_theme` set leaves `ui.color_theme` in the file.
4. Selection: an id with no file resolves to the built-in and warns once across two calls; a light theme in the dark slot resolves to `overdeck-dark`; `saveColorThemeSelection('dark', 'ayu-dark')` then a fresh load returns `ayu-dark`, and other config keys and comments are unchanged.
5. Terminal background: with mode `dark` and `ayu-dark` selected, `resolveTerminalBackground()` returns `#0d1017`; with no selection it returns `#1a1a2e`; with a selected theme lacking `terminal.background` it returns `#1a1a2e`.
6. VS Code mapper: the Ayu Dark fixture maps `terminal.background` `#0d1017`, all 16 ANSI keys, 66 `tokenColors`, and `ui.accent` `#e6b450`; the Ayu Light fixture maps `type: light`; the no-terminal fixture maps with no `terminal` group and no error; invalid JSONC rejects with an error naming the offset; `include` produces a warning.
7. Routes: preview returns the mapped theme and writes nothing; POST saves a file under `<OVERDECK_HOME>/themes/`; PUT selection with a wrong-type id answers 400; a `.vsix` file name answers 400 naming #4659; a 3 MB payload answers 413; mutations without the CSRF/session check are refused.
8. Frontend store: with a stored dark selection whose theme has `ui.background`, toggling to light removes the inline `--background` (or applies the light theme's value) without a reload; `--state-live` is never set inline.
9. xterm: with `ayu-dark` active the terminal's `options.theme.background` is `#0d1017` and `red` is the theme's `terminal.ansiRed`; per-pane `light` override uses the light slot's palette.
10. Syntax: with a theme that has `syntax`, `highlight` is called with a name starting `overdeck-ayu-dark-` and registration happens once for two calls; a theme without `syntax` uses `github-light`; editing the syntax yields a new name.
11. Pickers: the dark select lists only dark themes; choosing one sends `PUT /api/color-themes/selection` with `{ mode: 'dark', id }`.
12. Import UI: choosing a `.json` file shows the preview with name, swatches and warnings; Save posts the theme and the new theme appears in the matching select; Cancel posts nothing.
13. Docs: `configuration/appearance.mdx` shows a `ui.color_theme` YAML example, the mapping table, and the signal-color fence, and no longer says "not a color change"; `docs/DASHBOARD-ARCHITECTURE.md` names `resolveTerminalBackground()` and `/api/color-themes`.

## Non-goals

- `.vsix` import (#4659) and the duplicate-and-edit editor UI (#4660).
- Herdr background stamp; `COLORFGBG` stays mode-based and unchanged.
- Diff viewer syntax colors (stay `pierre-dark`/`pierre-light`).
- Deleting or renaming themes from the UI.
- Overriding signal/state colors, fonts, density, radius, or chat width.
- Extra curated built-in themes beyond `overdeck-dark`/`overdeck-light`.
- Recoloring already-running tmux sessions (only new sessions get the stamp; the per-pane override remains the escape hatch).
- VS Code `include` resolution and `.tmTheme` token files for single-file import.

## Hazards

- `registerCustomTheme` refuses duplicate names silently (console.error) — always hash the syntax into the name.
- `writeYamlConfigPreservingComments` deletes the whole `ui` block when the save carries none — item 3 must land with item 4 or a general settings save erases the selection.
- `selection.ts` is reachable from `tmux.ts`; it must not import `settings-api.ts` (cycle risk; `npm run lint:circular`). The write door lives in `selection-write.ts`.
- `tmux.ts`/`routes/settings.ts` are at cap; any extra line fails `lint:file-size`.
- Imported colors reach inline CSS, shiki HTML and a tmux argument — only hex values that pass the regex may get through.
- The ChatMarkdown highlight cache must key on the theme name or a theme switch serves stale HTML.
- The design-language specimens nest `[data-theme]` scopes; inline tokens on `<html>` are inherited but the specimen scopes override them — expected.
