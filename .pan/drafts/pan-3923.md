## Glossary

- **Terminal backend** — the adapter that owns agent panes. Two implement `TerminalBackend` (`src/lib/terminal-backends/types.ts`): **Herdr** (default) and **tmux**. `hostTerminalBackendName()` in `src/lib/terminal-backends/select.ts` says which one this host uses.
- **Pane** — one agent terminal on the backend. On tmux it is a session named by the agent id. On Herdr it is a pane (`w1:p1`) whose live agent name is the Overdeck agent id (bound with `agent.rename` at launch).
- **Role run** — a non-`work` agent spawned through `spawnRun` in `src/lib/agents/spawn.ts` (`review`, `test`, `ship`, `knowledge`, `sequencer`, …). It receives one prompt and is expected to finish.
- **Sequencer / `sequencer-runner`** — the singleton role run (`SEQUENCER_AGENT_ID` in `src/lib/backlog/sequencer-agent.ts`) that ranks the backlog and writes `.pan/backlog/sequence.md` through `pan backlog write-sequence`.
- **Auto-trigger** — `src/lib/backlog/backlog-auto-trigger.ts`: a 30 s-debounced incremental pass on backlog deltas and a periodic review pass.
- **Herdr agent status** — Herdr's own per-pane state: `idle`, `working`, `blocked`, `done`, `unknown`; `exited` for a dead pane. `toAgentState()` in `src/lib/terminal-backends/herdr.ts:101` maps it to the contract's `AgentState`.
- **Runtime mirror** — the in-process per-agent activity snapshot fed by harness hooks; read with `getAgentRuntimeStateSync()` (`src/lib/agents/runtime-state.ts:88`). Its `state` is `idle` after the harness's Stop hook fires at the end of a turn.
- **Live inventory** — `liveAgentInventory()` / `listLiveAgentPanes()` in `src/lib/terminal-backends/inventory.ts`: every live pane on the selected backend, exited panes excluded, `null` when unreadable (indeterminate).
- **Runtime census** — `src/lib/runtime-census.ts`: a tmux-only pane/process snapshot. `listRunningAgentsSync().tmuxActive` is derived from it, so on Herdr it reports every agent as not active.
- **Plan home** — the checkout whose `.pan/` holds project-level artifacts; for overdeck it is the primary checkout on `main` (`resolvePlanHome()` in `src/lib/pan-dir/paths.ts:46`).
- **Git guard** — the per-agent `git` shim on an agent pane's PATH (`src/lib/launcher-git-guard.ts`). Inside the agent's own worktree it refuses `git rebase`, state-moving `git stash`, and `git reset`; every other git command passes through.

## Problem

Three defects, all observed on the Herdr backend after the cut:

1. **A finished sequencer pane counts as running.** A role run that has finished its one prompt stays alive on Herdr as an idle pane (the interactive harness sits at its prompt). `spawnRun`'s guard (`src/lib/agents/spawn.ts:171-190`) sees the pane through `agentPaneExists()` and only reaps it when the **tmux** `isPaneDead` probe says the pane process exited — which is never true on Herdr — so every later pass throws `Role run sequencer-runner already running`. Before the cut the tmux session simply exited with the harness. Live evidence at planning time (`herdr agent list`, 2026-09-19 11:40Z): `sequencer-runner` pane `wD:p4`, `agent_status: idle`, `state_change_seq: 49`; its `state.json` says `status: running`, `startedAt: 2026-09-19T10:44:44Z`; `.pan/backlog/sequence.md` was committed at 10:46:48Z (`b7bedc3278a`), i.e. the pass finished 55 minutes ago. Note the finished pane reads **`idle`**, not only `done` as the issue text says; both must count.
2. **Nothing can clear a finished run on Herdr.** The dashboard route already calls `clearFinishedSequencerRun()` before an operator-started pass, but (a) `getSequencerRunStatus()` derives `alive` from the tmux census, so on Herdr the run is never `alive`, never `done`, and the clear is a no-op; (b) even when it fires, `stopAgent()` (`src/lib/agents/termination.ts:200`) is tmux-only — it kills a tmux session, marks `state.json` stopped, and leaves a Herdr pane running. The auto-trigger does not call the clear at all.
3. **Sequence commits are never pushed.** `pan backlog write-sequence` (`src/cli/index.ts:340-372`) commits `.pan/backlog` on the plan home (`main`) and stops. Nothing pushes, so local `main` drifts ahead of `origin/main` by sequence-only commits until a human pushes. At planning time the primary was in sync (`## main...origin/main`, someone pushed by hand); the defect is in the code path, not reproduced live right now.

## Proposal (decisions made here)

- **D1 — One backend-aware pane close.** Add `closeAgentPaneByName(agentId)` to `src/lib/terminal-backends/launch.ts`. Herdr: `findHerdrAgent` → `backend.close({ backend: 'herdr', workspaceId, paneId, terminalId, agentName })`. tmux: `killSession`. Async `stopAgent` uses it. `stopAgentSync` stays tmux-only: there is no sync Herdr client, and that gap belongs to [PAN-3926](https://github.com/eltmon/overdeck/issues/3926).
- **D2 — Reapable Herdr states for a role-run dispatch.** In `spawnRun`'s guard, on Herdr a pane with the same agent id is reaped (closed, then the dispatch proceeds) when its Herdr state is `exited` or `done`, or when it is `idle` **and** the agent's `state.json` status is not `starting` (the previous run's prompt was delivered, so `idle` means "turn finished", not "still booting"). `working`, `blocked`, `unknown`, and `idle`-while-`starting` keep throwing the existing error. tmux keeps the `isPaneDead` rule unchanged.
- **D3 — Sequencer status reads the live inventory.** `getSequencerRunStatus()` becomes async and reads `listLiveAgentPanes()`; the census path stays as the fallback when the inventory is `null`. A Herdr pane in a reapable state (D2 rule) is a new `doneReason: 'pane-finished'`.
- **D4 — The auto-trigger clears before it spawns**, exactly as the operator route does, and a failing clear never blocks the pass (the D2 guard is the second line).
- **D5 — `write-sequence` syncs, commits, pushes; no rebase.** Before writing: `git fetch origin <branch>` then `git merge --ff-only origin/<branch>`. After committing: `git push origin HEAD:refs/heads/<branch>`. A rebase is not an option: the verb runs inside the sequencer pane, whose git guard refuses `git rebase` in the primary checkout, and the primary is shared. Every failure is a printed warning, exit code 0, and the sequencer prompt tells the agent to stop rather than run git itself.

## Requirements

- **FR-1** `closeAgentPaneByName(agentId)` closes the Herdr pane bound to `agentId` through `TerminalBackend.close`, kills the tmux session on tmux, and returns `{ closed: true }`, `{ closed: false, reason: 'absent' }`, or `{ closed: false, reason: <message> }` without throwing.
- **FR-2** Async `stopAgent()` closes a Herdr pane (FR-1) and still captures the pane's last 5000 lines to `output.log` before closing; tmux behavior is unchanged.
- **FR-3** `spawnRun` reaps a finished Herdr role-run pane under the D2 rule and proceeds with the new dispatch; a `working`/`blocked`/`unknown` pane, or an `idle` pane whose state is `starting`, still throws `Role run <id> already running`.
- **FR-4** `spawnRun` persists `state.backend` and `state.paneId` for role runs, as `spawnAgent` already does at `spawn.ts:882-883`.
- **FR-5** `getSequencerRunStatus()` reports `alive: true` for a Herdr-hosted sequencer and `done: true, doneReason: 'pane-finished'` when its pane is in a reapable state (D2 rule); falls back to the census when the inventory is `null`.
- **FR-6** Both auto-trigger timers call `clearFinishedSequencerRun(projectRoot)` before `spawnSequencerAgent`; a rejected clear is logged and the spawn still runs.
- **FR-7** `pan backlog write-sequence` fast-forwards the plan-home branch from `origin` before writing, and pushes `HEAD` to `origin/<branch>` after committing; every git failure prints a `⚠` line naming the step and reason, and the command still exits 0 after a successful local write.
- **FR-8** The sequencer prompt says the verb commits **and pushes**, and instructs the agent to stop without running git when the verb reports a push failure.
- **FR-9** The dashboard 409 text for a running sequencer no longer recommends `pan kill sequencer-runner` as the universal fix (it is tmux-only on Herdr).
- **NFR-1** No `execSync` anywhere on these paths; all git and backend calls are async (`execFile`/Effect). The verb and `plan-artifact-commit.ts` are server-reachable.
- **NFR-2** No `git stash`, `git rebase`, or `git reset` is issued by any new code.
- **NFR-3** A Herdr probe that fails (socket down) is indeterminate: the guard keeps throwing (conservative), the status falls back to the census, and no pane is closed on a guess.
- **NFR-4** `src/lib/agents/spawn.ts` must not grow past its `origin/main` line count (file-size ratchet, `scripts/lint-file-size.sh`); new guard logic lives in a new module.

```ts
export type CloseAgentPaneResult =
  | { readonly closed: true; readonly backend: TerminalBackendName }
  | { readonly closed: false; readonly reason: string };

/**
 * Close the pane bound to an agent id on whichever backend hosts it (PAN-3923).
 * `closeBackendPane` needs the reference a launch returned; a stop or a reap
 * only has the agent id. Herdr: `agent.get` by name → `pane.close`. tmux:
 * `kill-session`. Never throws — a stop must finish its bookkeeping.
 */
export async function closeAgentPaneByName(
  agentId: string,
  backend?: TerminalBackend,
): Promise<CloseAgentPaneResult> {
  let resolved: TerminalBackend;
  try {
    resolved = backend ?? (await resolveLaunchBackend());
  } catch (cause) {
    return { closed: false, reason: cause instanceof Error ? cause.message : String(cause) };
  }
  if (resolved.name === 'herdr') {
    const { findHerdrAgent } = await import('./herdr.js');
    const live = await findHerdrAgent(agentId);
    if (!live) return { closed: false, reason: 'absent' };
    const ref: AgentPaneRef = {
      backend: 'herdr',
      workspaceId: live.workspaceId,
      paneId: live.paneId,
      terminalId: live.terminalId,
      agentName: agentId,
    };
    try {
      const result = await Effect.runPromise(resolved.close(ref));
      if (isUnsupported(result)) return { closed: false, reason: result.reason };
      return { closed: true, backend: 'herdr' };
    } catch (cause) {
      return { closed: false, reason: cause instanceof Error ? cause.message : String(cause) };
    }
  }
  const { killSession, sessionExists } = await import('../tmux.js');
  if (!(await Effect.runPromise(sessionExists(agentId)).catch(() => false))) {
    return { closed: false, reason: 'absent' };
  }
  try {
    await Effect.runPromise(killSession(agentId));
    return { closed: true, backend: 'tmux' };
  } catch (cause) {
    return { closed: false, reason: cause instanceof Error ? cause.message : String(cause) };
  }
}
```

`findHerdrAgent` (`herdr.ts:190`) already returns `paneId`, `terminalId`, `workspaceId`. `HerdrBackend.close` (`herdr.ts:679`) calls `pane.close` when the ref carries `paneId`.

3. Herdr, `close` rejects → `{ closed: false, reason }`, no throw.

## Intersecting repo rules (restated)

- **No `execSync` in server-reachable code** — `plan-artifact-commit.ts`, `termination.ts`, `launch.ts`, and the backlog route are all reachable from the dashboard. Use `execFile` (promisified) or Effect.
- **Agents never stash; never rebase inside a workspace** — the verb must not either (NFR-2). The git guard would refuse the rebase anyway.
- **Fake timers for delay tests** — the auto-trigger tests already use them; keep it that way.
- **File-size ratchet** — `spawn.ts` is a god file; put new logic in `role-run-reap.ts`.
- **Effort default `high`** — no model or effort changes in this issue.
- **Investigate before fixing** — the live pane `wD:p4` is the fixture; do not kill it by hand before AC-3 can be exercised against it.

## Non-goals

- `stopAgentSync` / `pan kill` / `pan pause` on Herdr (no sync Herdr client) — [PAN-3926](https://github.com/eltmon/overdeck/issues/3926).
- The census (`runtime-census.ts`) staying tmux-only for other callers.
- Pushing from `pan orders`, `pan task`, `pan done`, or planning promotion.
- Committing operator gate/planning edits made through the backlog routes (they leave `sequence.md` dirty in the plan home today — file separately).
- Any rebase, stash, or history rewrite of the plan home.
- Changing what Herdr reports as `done` vs `idle`.
