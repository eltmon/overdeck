## blocks-the-design: Pane inventory lag can still offer Start work

The proposed `hasWorkAgent(pipelineState, panes)` ignores the already supplied work-agent snapshot. A reachable input is a written plan, an idle planner, `derived('working')`, a work snapshot with `role: 'work'` and `hasLivePane: true`, but a pane array that still contains only the planner. `derivePipelineState` returns `in_progress_work_idle` when no work pane is in that array ([issuePipelineState.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4670/src/dashboard/frontend/src/lib/issuePipelineState.ts), lines 64–70), so the proposed predicate returns false and the idle planner still produces “The plan is ready / Start work.” The client receives agent changes and pane inventory changes as separate reducer events ([event-reducers.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4670/packages/contracts/src/event-reducers.ts), lines 353–365 and 632–649); `AgentSnapshot.hasLivePane` is an existing backend-liveness field ([types.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4670/packages/contracts/src/types.ts), lines 319–337). [SimpleIssuePage.tsx](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4670/src/dashboard/frontend/src/components/simple/SimpleIssuePage.tsx), lines 42–54, passes both sources to `deriveSimpleIssue`. Add `agents.some(a => a.role === 'work' && a.hasLivePane === true)` as a positive liveness signal, or otherwise suppress Start work while that signal is present. Add the missing-pane/live-work-snapshot case to WI-3 tests. This does not require reading `AgentSnapshot.status`.

## sharpens-framing: Plan-ready card is not gated on hasPlan

The proposed documentation says the page shows “The plan is ready” *only* when `issue.hasPlan` is true. The proposed `isPlanReadyToStart` gates only its override. Independently, `derivePipelineState` maps `derived('planned')` with no live planner to `planning_done_awaiting_work` ([issuePipelineState.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4670/src/dashboard/frontend/src/lib/issuePipelineState.ts), lines 71–72), and that base state always renders “The plan is ready / Start work” ([userFacingState.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4670/src/dashboard/frontend/src/lib/simple/userFacingState.ts), lines 56–60 and 90–92), even if `issue.hasPlan` is false. Make WI-4 describe the `hasPlan` check as the idle-planner override’s condition, or explicitly extend the implementation and tests if the “only” rule is intended for every path.
