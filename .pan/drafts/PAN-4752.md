# PAN-4752 — Flywheel board shows strike workspaces as their base issue

**Issue:** [PAN-4752](https://github.com/eltmon/overdeck/issues/4752)
**Status:** planned (auto mode, 2026-11-02)

## Glossary

- **Flywheel board** — the in-flight table on the `/flywheel` page (`FlywheelStatusPane`) and the in-flight lines of `pan flywheel status`. Both render `FlywheelDerivedStatus.inFlight`, which `deriveFlywheelStatus()` computes on read.
- **Census** — the list of the project's `workspaces/feature-*` directories that `defaultListWorkspaces` returns (via `listFeatureWorkspaces` in `src/lib/cloister/deacon-workspaces.ts`). Slot workspaces (`-slot-<N>`) are already excluded.
- **Strike** — a precision fix launched by `pan strike <id>`. It runs in `workspaces/feature-<id>-strike` on branch `strike/<id>` (lower-case id) and opens a PR whose head is `strike/<id>` (`src/cli/commands/strike.ts` `planStrike`, lines ~117-135: `workspace = …feature-${normalized}-strike`, `branch: strike/${normalized}`). The operator merges that PR by hand.
- **Base issue id** — the tracker id a strike works on, e.g. `PAN-4669` for `feature-pan-4669-strike`.
- **Strike PR** — the open PR/MR whose head branch is exactly `strike/<lower-case base id>`. Merged or closed PRs on that head are not strike PRs for the board (D5).
- **Derived state** — `DerivedIssueState` from `loadIssueStatesForProject` (`src/lib/overdeck/derived-issue-state.ts`). It reads PRs only from `feature/<id>` heads (`issueIdFromBranch`, line ~840: `/^feature\/([a-z]+-\d+)$/i`), so it never sees a strike PR.

## Problem

`listFeatureWorkspaces` derives the issue id as `entry.replace(/^feature-/, '').toUpperCase()` (`src/lib/cloister/deacon-workspaces.ts` line 36). A strike workspace `feature-pan-4669-strike` therefore yields `PAN-4669-STRIKE`. `deriveFlywheelStatus()` puts that id on the board unchanged (`src/lib/flywheel/derive-status.ts` lines 267-281, the `candidates` loop). The tracker has no such issue, so the row shows `tracker unknown`, `backlog`, and no PR.

Live evidence (2026-11-02, `pan flywheel status --json`):

```
PAN-4669-STRIKE backlog trackerUnknown=True pr=None
PAN-4673-STRIKE backlog trackerUnknown=True pr=None
PAN-4674-STRIKE backlog trackerUnknown=True pr=None
PAN-4690-STRIKE backlog trackerUnknown=True pr=None
PAN-4702-STRIKE backlog trackerUnknown=True pr=None
```

and `gh pr list` shows the matching open PRs: `strike/pan-4669` #4698, `strike/pan-4673` #4678, `strike/pan-4674` #4679, `strike/pan-4690` #4701, `strike/pan-4702` #4707.

A second, hidden effect: a strike agent's pane carries the base issue token (`PAN-4669`), so `liveAgents` for the bogus `PAN-4669-STRIKE` row is always 0 and the strike agent never appears under `status.agents`. Folding the row onto the base id fixes this as a side effect.

## Decisions (made here, not left to the implementer)

- **D1. Fold in the deriver, not the census.** `deacon-workspaces.ts` stays unchanged (the deacon depends on its current ids). The fold happens inside `deriveFlywheelStatus()`, in the `candidates` loop **after** `listWorkspaces` returns. It must not live inside `defaultListWorkspaces`, because tests and the server route can inject their own `listWorkspaces`, and the fold must apply to every source.
- **D2. Strike detection.** An id is a strike id when it matches `/^(.+)-STRIKE$/i`. The base id is capture group 1, upper-cased. The same fold applies to tick-marker ids (an id the loop named in its tick), so no `-STRIKE` id can reach the board from either source.
- **D3. One row per base id.** When both `feature-pan-X` and `feature-pan-X-strike` exist, the board shows one row `PAN-X` with `strike: true`. The base workspace's path wins for the journal read (`lastJournal`), whatever order `readdirSync` returns. A strike-only issue uses the strike workspace path for its journal.
- **D4. Row marker.** `FlywheelInFlightRow` gains `strike: Schema.optional(Schema.Literal(true))`, set only when a strike workspace (or a `-STRIKE` tick id) folded onto the row. Absent otherwise, so existing `toEqual` assertions stay valid.
- **D5. Strike PR source: open PRs only.** A new injectable dep `readStrikePr(projectPath, issueId)` on `DeriveFlywheelStatusDeps`. Its lazy default reads the project's cached forge listing (GitHub `listRepoPullRequests` + `prFromGhRow`; GitLab `listRepoMergeRequests` + `mrFromGlabRow`, chosen by `forgeForProject`), keeps every row whose head is exactly `strike/<lower-case id>`, and returns the **open** one through the pure exported selector `selectOpenStrikePr` (highest PR number when several are open). Merged and closed PRs are ignored: `pan strike` reuses the same `strike/<id>` branch on every run (`src/cli/commands/strike.ts` lines ~207-223 allow a prior branch), so a merged PR on that head can belong to an earlier strike and is no evidence about the current workspace. No extra forge call per poll: both listings are already cached for `loadIssueStatesForProject`. The dep is called only for rows with `strike: true` and only when `derived.pr` is absent.
- **D6. PR precedence.** A feature-branch PR found by `loadStates` (`derived.pr`) wins. The strike PR is used only when `derived.pr` is absent.
- **D7. State overlay when the strike PR is used.** Tracker state is authoritative: if `derived.state` is `closed`, the row stays `closed` (and drops off the board). Otherwise, with an open strike PR: `changes-requested` when `pr.reviewState === 'changes-requested'`, else `in-review`. State derived from a strike PR is never `ready`: strikes are merged by the operator outside the merge gate, so there is no gate approval to read. (A row that has both shapes and a feature PR keeps the feature PR and whatever `loadStates` derived for it, `ready` included — D6.) A strike whose PR merged while the issue stays open keeps its row with no PR until the tracker closes the issue or the strike workspace reaper removes the workspace. When the overlay applies, the row drops `attention: 'work-not-started'` (that value means "no PR and no live pane", which an open strike PR contradicts) and keeps every other attention value.
- **D8. Visual marker.** The page shows a neutral `StatusBadge` reading `strike` in the issue cell, with `testId` `flywheel-strike-<issueId>`. The CLI appends ` · strike` to the state column text. Neutral tone follows the pan-style-guide color-restraint rule: the marker is an identity label, not a status signal.
- **D9. Line budget.** `src/lib/overdeck/derived-issue-state.ts` is 981 lines; the ceiling is 1000 and the file has no allowlist row (`scripts/lint-file-size.sh`, `CEILING=1000`). The only change there is adding the `export` keyword to `interface GlabMrRow` (line ~449) and `async function listRepoMergeRequests` (line ~496): zero added lines. Never raise the allowlist.
- **D10. Scope of the no-`-STRIKE` guarantee.** FR-1 covers in-flight row ids only. `lastTick` (including `lastTick.pick`) is the loop's own words and is shown verbatim; it is not rewritten.

## Requirements

- **FR-1** No in-flight row id matches `/-STRIKE$/i`, whether the id came from the census or from the tick marker's in-flight list. (`lastTick.pick` is out of scope, D10.)
- **FR-2** A strike workspace yields a row whose `issueId` is the base id and whose `strike` field is `true`; the base id (not the `-STRIKE` id) is what `readTrackerIssues` and `loadStates` receive.
- **FR-3** When both base and strike workspaces exist, exactly one row is produced, with `strike: true` and the base workspace's journal.
- **FR-4** A strike row with no feature-branch PR carries its open strike PR as `row.pr`, and its state follows D7. A merged or closed PR on the strike head never sets `row.pr` and never drops the row.
- **FR-5** Live strike panes (pane token = base id) count toward the folded row's `liveAgents` and appear under `status.agents`.
- **FR-6** The page renders a `strike` badge for rows with `strike: true` and none otherwise.
- **FR-7** `pan flywheel status` marks strike rows with `strike` on the row line.
- **FR-8** `docs/FLYWHEEL.md` documents the fold, the marker, and the strike PR source.
- **NFR-1** `src/lib/cloister/deacon-workspaces.ts` is not modified.
- **NFR-2** `src/lib/overdeck/derived-issue-state.ts` gains no lines (two `export` keywords only) and stays at or under 1000 lines.
- **NFR-3** No new forge call per status poll: the strike PR read reuses the cached repo listing.

  const candidates: Candidate[] = [];
  const byId = new Map<string, Candidate>();
  const tickIds = new Set((lastTick?.inFlight ?? []).map((id) => strikeBaseId(id) ?? id.toUpperCase()));
  const tickStrikeIds = new Set((lastTick?.inFlight ?? []).map(strikeBaseId).filter((id): id is string => id !== null));

```ts
/**
 * The open PR among those on one strike head, highest number first (PAN-4752).
 * `pan strike` reuses `strike/<id>` on every run, so a merged or closed PR on
 * that head may belong to an earlier strike: it never counts.
 */
export function selectOpenStrikePr(prs: readonly (LoadedPr | null)[]): DerivedPrState | null {
  const open = prs.filter((pr): pr is LoadedPr => pr !== null && !pr.merged).sort((a, b) => b.number - a.number)[0];
  return open ? { url: open.url, number: open.number, reviewState: open.reviewState, checks: open.checks, mergeable: open.mergeable } : null;
}

async function defaultReadStrikePr(projectPath: string, issueId: string): Promise<DerivedPrState | null> {
  const m = await import('../overdeck/derived-issue-state.js');
  const branch = `strike/${issueId.toLowerCase()}`;
  const prs = m.forgeForProject(projectPath) === 'gitlab'
    ? (await m.listRepoMergeRequests(projectPath)).filter((row) => row.source_branch === branch).map(m.mrFromGlabRow)
    : (await m.listRepoPullRequests(projectPath)).filter((row) => row.headRefName === branch).map(m.prFromGhRow);
  return selectOpenStrikePr(prs);
}
```

## Critique response

### A prior merged strike can hide a new strike

Accepted. The overlay now uses **open strike PRs only** (D5, D7, W3). A merged or closed PR on `strike/<id>` is ignored, because `pan strike` reuses that branch across runs and such a PR is no evidence about the current workspace. A row with no open strike PR keeps whatever `loadStates` derived and is never dropped by the strike read. When several PRs share the head, the pure selector `selectOpenStrikePr` drops merged ones (closed-unmerged rows are already `null` from `prFromGhRow`/`mrFromGlabRow`) and takes the highest open PR number. `src/lib/github-pr-selection.ts` was not reused: it works on `GitHubPullRequestForHead` from the GitHub App path, not on the cached `GhPrRow`/`GlabMrRow` listings the board reads, and the open-only rule needs no merged/closed ranking. New tests: W3 test 8 (only a non-open PR → row kept, no PR) and test 11 (selector over merged-only, merged + open, null + open, two open). Side effect: the strike PR read no longer needs `readPrForBranch`; `derived-issue-state.ts` only gains two `export` keywords.

### "Never ready" conflicts with feature-PR precedence

Accepted. D7 and the W6 doc text now say that state **derived from a strike PR** is never `ready`; a row with both shapes and a feature PR keeps the feature PR and its derived state, `ready` included.

### The last-tick pick can still show a strike ID

Accepted as a scope statement (D10): FR-1 covers in-flight row ids only. `lastTick` is the loop's own words and is shown verbatim.

### Unresolved after two critic rounds

- A merged feature PR hides an active strike
- Cached listings can omit an open strike PR
- Strike lookup defeats the dashboard's stale read
