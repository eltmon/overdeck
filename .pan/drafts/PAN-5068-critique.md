## blocks-the-design: shared cause text can expose sign-in secrets

The proposed W-1 `describeCause` appends an arbitrary `error.cause.message` to every account-client error. In [client.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5068/src/lib/account/client.ts), lines 225–238, `exchangeAuthorizationCode` sends the authorization code and PKCE verifier through the injected `fetch` and returns `describeError(error)` as `detail`. [account-sign-in.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5068/src/dashboard/server/services/account-sign-in.ts), lines 151–159, then puts that detail in the dashboard failure message. For example, a fetch rejection with `TypeError('fetch failed', { cause: { code: 'ECONNRESET', message: 'request failed for code odc_secret' } })` would expose `odc_secret`; the current formatter discards the cause. The same helper also formats token-bearing calls at `client.ts` lines 170–172, 258–260, and 278–283. This contradicts the PRD's NFR-2 and the module's line 7–8 secret invariant. Keep cause enrichment confined to calls without secrets, or pass the request's sensitive values to a formatter that redacts them before returning any detail. Add a test with a cause containing a known secret.
