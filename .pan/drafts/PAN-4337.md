# PAN-4337: The git shim refuses commits and pushes off the workspace's feature branch

**Issue:** https://github.com/eltmon/overdeck/issues/4337
**Parent PRD:** `.pan/drafts/deft-adoption.md`, "Issue 3" (line 250 onward). This document is the executable brief for that item.
**Planning mode:** `pan plan --auto` (no operator questions; defaults are recorded under "Decisions").

## Glossary

- **Git shim / git guard.** A per-agent `git` script written by the agent's launcher into `~/.overdeck/agents/<agentId>/git-guard/git` and placed first on the agent's `PATH`. Generated by `buildGitGuardLines()` in `src/lib/launcher-git-guard.ts`. It forwards to the real git (`$_OVERDECK_REAL_GIT`) unless it refuses the call.
- **Default mode / read-only mode.** The two shim modes (`GitGuardMode`). Default mode refuses `rebase`, state-moving `stash` and `reset --hard` in the agent's worktree. Read-only mode (`pan worker run --read-only`) refuses every git write in the repository. This issue changes **default mode only**.
- **guardRoot.** The directory the shim guards: the launcher's `config.workingDir` (`src/lib/launcher-generator.ts:382`). Resolved at launch to a canonical path in `$_OVERDECK_GUARD_ROOT`. For a work or planning agent it is the issue workspace; for a `pan worker run` worker it is that worker's item worktree; for review/test agents it is the project root.
- **Target directory.** The directory a git invocation operates on, after applying every `-C` value. Computed in the shim by `_overdeck_git_target_dir` (`launcher-git-guard.ts:260-304`). Default mode ignores `--git-dir`, `GIT_DIR` and `--work-tree`.
- **Issue workspace.** A git **linked worktree** at `<projectRoot>/<workspaces_dir>/feature-<name>` on branch `feature/<name>` (`src/lib/workspace-manager/create.ts:192-194` and `:336`). `workspaces_dir` is configurable and defaults to `workspaces`.
- **Item worktree.** A linked worktree at `<workspace>/.swarm/<item>` on branch `<feature-branch>-<item>` (`src/lib/workspaces/item-worktree.ts:22-45`). `pan spawn` uses it for xBRIEF items; `pan worker run` uses `.swarm/worker-<n>`.
- **Linked worktree.** A worktree added with `git worktree add`. Its top-level `.git` is a **file** (a `gitdir:` pointer), whereas a primary checkout or a freshly `git init`ed repo has a `.git` **directory**.
- **Expected branch.** The branch the shim requires for a guarded commit/push/merge/cherry-pick, derived from the target's `git rev-parse --show-toplevel` at call time (see FR-2).
- **Drift.** HEAD of a workspace or item worktree on a branch other than its expected branch, or detached.

## Problem

`sync-sources/rules/worktree-discipline.md:19` says: "every commit and push relies on the current branch; no part of the pipeline auto-checks it." Evidence of drift onto `main`: #3505 and PAN-2204. The shim already intercepts every agent git call and already scopes itself to the agent's worktree (PAN-3189), so it is the cheapest deterministic place to refuse a commit or push made from a drifted worktree.

## Requirements

### Functional

- **FR-1.** In default mode, the shim checks the branch only for the subcommands `commit`, `push`, `merge` and `cherry-pick`, matched as exact tokens (so `merge-base`, `merge-tree`, `merge-file` are untouched), and only when the target directory is `guardRoot` or a descendant (the existing PAN-3189 scope check).
- **FR-2.** The expected branch is derived from `T = "$_OVERDECK_REAL_GIT" -C <target> rev-parse --show-toplevel`:
  1. If `T` is empty, or `T/.git` is not a regular file (not a linked worktree), there is **no expectation**.
  2. If `T` contains `/.swarm/`, split it: `ws = ${T%/.swarm/*}`, `item = ${T##*/.swarm/}`. If `item` contains `/`, there is no expectation. Otherwise `ws = T` and `item` is empty.
  3. If the basename of `ws` matches `feature-?*`, the base is `feature/<basename without "feature-">`; otherwise there is no expectation.
  4. If `item` is non-empty, the expected branch is `<base>-<item>`; otherwise it is `<base>`.
- **FR-3.** When an expectation exists, the shim reads `"$_OVERDECK_REAL_GIT" -C <target> branch --show-current`. If the output differs from the expected branch, or is empty (detached HEAD), the shim prints one refusal line to stderr and exits 1 without running git.
- **FR-4.** The refusal message names the command, the toplevel, the expected branch and the actual state, and tells the agent to stop and report via `pan tell`. It must not mention `OVERDECK_PAN_GIT_OP`, `/usr/bin/git`, or any other way around the shim.
- **FR-5.** With no expectation, or with a matching branch, the invocation reaches the real git with its arguments unchanged.
- **FR-6.** The existing default-mode refusals (`rebase`, state-moving `stash`, `reset --hard`) and read-only mode behave exactly as before.

### Non-functional

- **NFR-1.** State is derived from git at call time. No new launcher parameter, environment variable, or stored field. (An exported variable would be wrong for in-harness subagents, which inherit the parent pane's environment while committing in an item worktree.)
- **NFR-2.** Subcommands other than the four pay no extra git process: they keep leaving through the first `case` before any `rev-parse`.
- **NFR-3.** POSIX `sh` only inside the shim (it starts with `#!/bin/sh`); no bash-isms.
- **NFR-4.** Tests run the generated shim as a process and assert on exit status and stderr. They do not grep source (the lint gate rejects new source-reading tests), add no `skipIf`/`.only`, and use no timers.

## Decisions (auto mode)

1. **Expectation comes from the toplevel path, not an issue-id parameter.** The issue says "the shim already knows guardRoot and the issue id", but `buildGitGuardLines(agentId, guardRoot, mode)` receives no issue id. The issue's own design ("derived rather than stamped") makes a new parameter unnecessary. The signature stays unchanged.
2. **Key on the basename `feature-<name>`, not on a `workspaces/` parent.** `workspaces_dir` is configurable (`create.ts:192`).
3. **Require a linked worktree (`T/.git` is a file).** A polyrepo workspace scaffold is `git init`ed at the workspace root by `commitCompletePlanningWorkspaceGit` (`src/lib/overdeck/planning-promotion.ts:256-259`). That wrapper repo has basename `feature-<name>` but sits on the init default branch. A basename-only rule would refuse every commit in it. The linked-worktree test also excludes every primary checkout. Verified during planning: in a fixture, `test -f "$(git rev-parse --show-toplevel)/.git"` is false for the primary checkout and true for both `workspaces/feature-x` and `workspaces/feature-x/.swarm/w1`.
4. **Exactly four subcommands: `commit`, `push`, `merge`, `cherry-pick`** (the issue's list). `pull`, `revert`, `am`, `commit-tree`, `update-ref` are not checked.
5. **No push refspec inspection.** `git push origin main` from a correct feature branch passes; refusing pushes to the default branch is #4344.
6. **Anything without an expectation passes through.** This covers review/test agents (guardRoot is the primary checkout), Claude Code isolation worktrees such as `<ws>/.claude/worktrees/agent-x`, polyrepo sub-repo worktrees `<ws>/<repo>` (whose branch prefix is per-repo `branch_prefix`), and test fixture repos.
7. **`pan` commands go through the check.** Only `src/lib/rebase-helper.ts` sets `OVERDECK_PAN_GIT_OP=1`. So `pan done` pushes and other `pan` git commits run from an agent pane are checked too. On the correct branch they pass. On a drifted worktree they are refused, which is the intended outcome. Do not add `OVERDECK_PAN_GIT_OP=1` anywhere to "fix" this. Checkpoints (`src/lib/checkpoint/checkpoint-manager.ts:177-184`) use `commit-tree`/`update-ref` and are not affected; server-side promotion commits run without the shim.
8. **Three work items:** the shim change, its behavior tests, and the docs. Tests depend on the shim; docs depend on nothing.

### WI-1. Branch check in the default-mode shim (`src/lib/launcher-git-guard.ts`)

**Step 1 — add the plain-sh branch check as a constant**, next to `READ_ONLY_SHIM_SH` (anchor: `const READ_ONLY_SHIM_SH = [`, line 61). Write every `$` unescaped, exactly as the shim should contain it, and emit it through an escaping helper that mirrors `readOnlyShimLines()` (anchor: `function readOnlyShimLines(): string[]`, line 186):

```ts
/**
 * PAN-4337: refuse commit/push/merge/cherry-pick when the target worktree is
 * off its expected branch. The expectation is derived from the target's
 * toplevel at call time: a linked worktree named `feature-<name>` expects
 * `feature/<name>`; `<that>/.swarm/<item>` expects `feature/<name>-<item>`.
 * Anything else (primary checkouts, `git init` wrappers, other worktrees)
 * has no expectation and passes through. Plain POSIX sh; every `$` is a
 * runtime expansion, escaped by `branchCheckShimLines`.
 */
const BRANCH_CHECK_SH = [
  'case "$_overdeck_git_command" in',
  '  commit|push|merge|cherry-pick)',
  '    _overdeck_top="$("$_OVERDECK_REAL_GIT" -C "$_overdeck_git_target" rev-parse --show-toplevel 2>/dev/null)"',
  '    _overdeck_expected=""',
  '    if [ -n "$_overdeck_top" ] && [ -f "$_overdeck_top/.git" ]; then',
  '      case "$_overdeck_top" in',
  '        */.swarm/*) _overdeck_ws="${_overdeck_top%/.swarm/*}"; _overdeck_item="${_overdeck_top##*/.swarm/}" ;;',
  '        *) _overdeck_ws="$_overdeck_top"; _overdeck_item="" ;;',
  '      esac',
  '      _overdeck_ws_name="${_overdeck_ws##*/}"',
  '      case "$_overdeck_ws_name" in',
  '        feature-?*) _overdeck_expected="feature/${_overdeck_ws_name#feature-}" ;;',
  '      esac',
  '      case "$_overdeck_item" in',
  '        */*) _overdeck_expected="" ;;',
  '        ?*) [ -z "$_overdeck_expected" ] || _overdeck_expected="$_overdeck_expected-$_overdeck_item" ;;',
  '      esac',
  '    fi',
  '    if [ -n "$_overdeck_expected" ]; then',
  '      _overdeck_branch="$("$_OVERDECK_REAL_GIT" -C "$_overdeck_git_target" branch --show-current 2>/dev/null)"',
  '      if [ "$_overdeck_branch" != "$_overdeck_expected" ]; then',
  '        _overdeck_actual="branch $_overdeck_branch"',
  '        [ -n "$_overdeck_branch" ] || _overdeck_actual="a detached HEAD"',
  '        echo "Overdeck refused git $_overdeck_git_command: $_overdeck_top must be on branch $_overdeck_expected, but it is on $_overdeck_actual. Stop and report this via pan tell; do not commit or push from this worktree." >&2',
  '        exit 1',
  '      fi',
  '    fi',
  '    exec "$_OVERDECK_REAL_GIT" "$@"',
  '    ;;',
  'esac',
];

/** The branch check, escaped for the launcher's unquoted heredoc. */
function branchCheckShimLines(): string[] {
  return BRANCH_CHECK_SH.map((line) => line.replace(/\$/g, '\\$'));
}
```

Do not put a backslash or backtick in `BRANCH_CHECK_SH`: the launcher writes the shim through an unquoted heredoc, and only `$` is escaped by the helper.

## Non-goals

- Refusing pushes whose refspec names the default branch (#4344).
- Commits made outside `guardRoot`, including an agent that `cd`s into the primary checkout (#3505's other shape; primary-cwd refusal is a separate Deft-adoption item).
- Polyrepo sub-repo worktrees `<ws>/<repo>` and per-repo `branch_prefix`: they have no expectation and pass through.
- Checking `pull`, `revert`, `am`, `commit-tree`, `update-ref`, `checkout` or `switch`.
- Following `--git-dir`, `GIT_DIR` or `--work-tree` in default mode.
- A `pan verify:branch` command, git hooks in registered projects, or a CI branch gate.
- Changing read-only mode, the `gh` shim, or the launcher signature.
- A bypass switch, or any mention of `OVERDECK_PAN_GIT_OP` in user-facing output.

## Acceptance criteria

- **AC-1 (WI-1, WI-2).** Given an agent worktree `feature-pan-1` checked out on `main`, when the agent runs `git commit`, then the shim exits 1 and stderr contains `feature/pan-1`.
- **AC-2 (WI-1, WI-2).** Given detached HEAD in the workspace, `git commit` exits 1 and stderr contains `detached`.
- **AC-3 (WI-1, WI-2).** Given the expected branch, `git commit` and `git push` exit 0; `git -C <fixture> commit` outside `guardRoot` exits 0.
- **AC-4 (WI-1, WI-2).** Given an item worktree `.swarm/w1` on `feature/pan-1-w1`, `git commit` exits 0; on `feature/pan-1` it exits 1.
- **AC-5 (WI-1, WI-2).** Given a `git init` repo named `feature-pan-2` on `master` (not a linked worktree), `git commit` exits 0.
- **AC-6 (WI-1, WI-2).** No refusal message contains `OVERDECK_PAN_GIT_OP`.
- **AC-7 (WI-1).** The existing tests in `launcher-git-guard-behavior.test.ts` and `launcher-git-guard-gh-shim.test.ts` pass unchanged.
- **AC-8 (WI-3).** `worktree-discipline.md` names `src/lib/launcher-git-guard.ts` and no longer says nothing auto-checks the branch; `reference/workers.mdx` says the worker shim refuses commit/push off `<feature-branch>-worker-<n>`.
