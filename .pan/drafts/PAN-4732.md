# PAN-4732 — Take the title-bar browser spec out of the CI unit shards; keep its five states in a component test

**Issue:** [PAN-4732](https://github.com/eltmon/overdeck/issues/4732)
**Follow-up:** [PAN-4733](https://github.com/eltmon/overdeck/issues/4733) (gating browser lane, audit of the other `tests/e2e/*.spec.ts`, root cause, un-quarantine)
**Status:** planned (auto mode, 2026-11-01, base `265473c9ba8`). Scope cut to the minimum by the
operator: main is red on this spec and every PR that merges main inherits it.

## Glossary

- **CI unit shards** — the `test-shard (1..4/4)` matrix in `.github/workflows/ci.yml`, running
  `npx vitest run --configLoader runner --shard=N/4` with the root `vitest.config.ts`. They feed
  the required `test` check.
- **Quarantine list** — `scripts/flaky-quarantine.txt`. `vitest.config.ts` reads it through
  `readQuarantineList(__dirname)` (line 15) and excludes every listed path when `CI=true` or
  `OVERDECK_VERIFICATION=1`, unless `OVERDECK_FLAKE_LANE=1` (lines 12-13:
  `const excludeQuarantined = (isCI || isVerification) && !isFlakeLane;`).
- **Flake lane** — the `flake-lane` CI job ("Non-blocking flake lane"). It installs Chromium
  (`npx playwright install --with-deps chromium`) and runs each quarantined file alone through
  `scripts/run-flake-lane.sh` with `OVERDECK_FLAKE_LANE=1`. Its result is logged in the job
  summary and never blocks a PR.
- **Frontend subset** — `npm run test:frontend-subset` runs the frontend Vitest files listed in
  `scripts/frontend-test-subset.txt`. CI runs it in the `test-e2e` job, which also feeds the
  required `test` check. An unlisted frontend test never runs in CI.
- **Title-bar states** — the five machine states of a conversation title bar from PAN-4650:
  `local`, `remote`, `offline-saved`, `offline-none`, `released`.

## Problem

`main` CI is red since the PAN-4650 merge (run 41335061342, commit `8d26b6fb84f`). All tests
pass, but `tests/e2e/linked-conversation-title-bar.spec.ts` fails in `beforeAll`:
`page.goto: Timeout 180000ms exceeded` at line 115 (the warm-up load), then
`Hook timed out in 30000ms` in `afterAll`. A CI re-run failed the same way, so the failure is
deterministic on main. The spec starts a Vite dev server and Chromium inside the default run
because `vitest.config.ts` lines 16-18 include `tests/**/*.spec.ts`.

Verified facts:

- `scripts/lint-quarantine-audit.sh` (part of `npm run lint`) requires every quarantine entry to
  carry an issue reference matching `([A-Z]+-[0-9]+|#[0-9]+)`.
- The flake-lane job installs Chromium before `run-flake-lane.sh`, so it can run the spec.
- `src/dashboard/frontend/src/components/chat/__tests__/ConversationMachineBanner.test.tsx` is in
  the frontend subset (`scripts/frontend-test-subset.txt` line 84). It covers the offline and
  released banners, the chip and the read-only notice, but not the `remote` header actions
  (Preview, Pull here) and not the full five-state table.
- `OpenPreviewPopover` (`src/dashboard/frontend/src/components/chat/OpenPreviewPopover.tsx`,
  lines 61-66) runs its `useQuery` with `enabled: open`, so rendering it closed makes no request.
- The browser fixture `tests/e2e/fixtures/linked-conversations.ts` cannot be imported by a
  frontend test: it lives outside the frontend root and would resolve a second copy of React.

## Decisions

- **D1 — Quarantine, not the slow convention.** The spec fails deterministically on main. A
  gating lane (rename to `*.slow.test.ts` + a step in `test-e2e`) would keep the required `test`
  check red. The quarantine list removes it from the shards and the verification gate at once,
  and the existing flake lane keeps running it in CI without blocking. This is the
  `readQuarantineList` option the operator named.
- **D2 — The quarantine entry references PAN-4733**, the follow-up that owns the root cause and
  the un-quarantine. PAN-4732 closes when this lands; the entry must point at an open issue.
- **D3 — The component test defines its five rows inline.** Sharing a module with the browser
  fixture would also edit the quarantined spec and the fixture; that is PAN-4733's work. The
  rows and expected outcomes are copied from the fixture (lines 27-55) and the spec's `EXPECTED`
  table (lines 43-50), with a comment naming both sources.
- **D4 — Colours stay browser-only.** happy-dom does not resolve the theme tokens through CSS
  modules and Tailwind. The component test covers chip, banner, buttons and read-only notice.
- **D5 — No docs edit.** Adding a quarantine line and a test case changes no documented
  behaviour; `docs/TESTING.md` already describes the suites, and the quarantine file header
  describes the flake lane. The browser-lane docs belong to PAN-4733.
- **D6 — The issue's "passes 10 consecutive times on CI" criterion moves to PAN-4733.** In the
  flake lane the spec is non-blocking and currently fails; ten green runs are only meaningful in
  the gating lane PAN-4733 builds.

## Requirements

- **FR-1** — With `CI=true`, the root Vitest run (with or without `--shard`) does not collect
  `tests/e2e/linked-conversation-title-bar.spec.ts`.
- **FR-2** — A CI lane still runs the spec: the flake-lane job's `run-flake-lane.sh` loop runs it.
- **FR-3** — A frontend component test in the CI frontend subset asserts, for all five title-bar
  states, the chip, banner and buttons, and the text of `MachineReadOnlyNotice` where the state
  is not live. It renders the same composition as the browser fixture, which also inserts the
  notice itself. Whether `ComposerFooter` switches to read-only mode is not part of this test
  (it is the existing switch at `ComposerFooter.tsx` lines 924-927, outside this issue).
- **NFR-1** — `npm run lint` passes (the quarantine audit accepts the new entry).

## Deferred to the follow-up (PAN-4733)

Design worked out during planning, recorded here so PAN-4733 starts from verified facts:

- Move the four browser specs to `tests/e2e/browser/<name>.slow.test.ts`; the existing
  `**/*.slow.test.ts` exclusion (`vitest.config.ts` lines 54-56, gated by `VITEST_INCLUDE_SLOW`)
  removes them from the default run with no config change. `VITEST_INCLUDE_SLOW` is set nowhere
  in `.github/`, so a CI step must opt in.
- Add `"test:e2e:browser": "VITEST_INCLUDE_SLOW=1 vitest run --configLoader runner tests/e2e/browser/ --maxWorkers=1"`.
  The `browser/` path filter keeps out the other slow tests, which need live binaries
  (`prime-agent-smoke`, `verification-worker-systemd-restart`, `kimi-code-capture-lock`,
  `kimi-probe`). Run serially so four dev servers and four Chromiums do not compete on four vCPUs.
- Run it as a step in the required `test-e2e` job after its Playwright install. Root `playwright`
  and frontend `@playwright/test` both resolve to `1.63.0` in `bun.lock`, so that install
  serves the root specs. `test-e2e` took 4 m 28 s of its 30-minute cap on run 41327462442.
- Drop `Install Playwright browsers (root) for vitest e2e` from `test-shard`: after the move, no
  shard test launches Chromium (the supervisor UAT is quarantined; the thumbnail test injects a
  fake renderer).
- A prebuilt static bundle was rejected: the harness page is not in the production bundle and
  would need its own Vite build.
- `ci.yml` runs only on `pull_request` and pushes to `main`, so the ten-run proof happens on the
  PR by rerunning the `test-e2e` job (`gh run rerun <run> --job <id>`).
- Update `docs/TESTING.md` and `.overdeck/context/codebase/stack.md` for the lane.
