**Depends on:** W-TOK1 ([PAN-4930](https://github.com/eltmon/overdeck/issues/4930), PR #4968, merged) and W-MCP1 ([PAN-4931](https://github.com/eltmon/overdeck/issues/4931), PR #4967, merged). Both are on `origin/main` at `332ebb39041`, the base of this plan.

**Why.** Agent tokens now exist (W-TOK1) and the MCP tool module can show agent-only tools (W-MCP1), but nothing on the dashboard turns an agent token into "who is calling", and nothing can run a CLI-only operation (`pan task claim`, `pan done`, `pan handoff`, `pan memory add`, …) for an agent. This item adds the one place that does both, plus the routes and the `wait_job` tool that let an agent wait on such a job in chunks of at most 50 s. It adds no route that *starts* a job; W-SELF2 and later items add those on top.

## Glossary

- **Agent token:** an access-token record of `kind: 'token'` that carries `agentId`, `agentKind` (`'agent' | 'conversation'`) and `role` (W-TOK1, `src/lib/mcp/agent-token.ts`). For an agent, `agentId` is the normalized agent id (`agent-pan-1`, `normalizeAgentId`, `src/lib/agents/identity.ts:52`); for a conversation, it is the conversation **name** (PAN-4930 D-2).
- **Credential:** the resolved caller, `DashboardCredential` (`src/dashboard/server/routes/dashboard-auth.ts:154-160`). An agent token resolves to `{ kind: 'token'; tokenId; scopes; agentId?; agentKind?; role? }` (line 158).
- **Self route:** a route under `/api/self/` that acts for the calling agent. It accepts only an agent token and takes the agent from the token, never from the request.
- **Self caller:** the resolved identity of a self route's caller: `SelfCaller` (new, Work item 1).
- **Job:** one `pan` CLI command a self route runs as an asynchronous child process for the caller (epic D-11). Held in dashboard memory only.
- **Job verb:** one member of the closed set of `pan` commands a job may run (`SelfJobVerb`, Work item 2).
- **Job owner:** the self caller that started a job. Only the owner can read or wait on it.
- **Wait chunk:** one blocking call of at most 50 s (`WAIT_CHUNK_MS = 50_000`) that returns early when the awaited state changes (epic D-12).
- **Route-scope table:** `ROUTE_SCOPES` in `src/dashboard/server/route-scopes.ts:28-153`, the one list of which scope each `METHOD path` needs from a registry credential. Unlisted routes need `admin`.
- **Remote request gate:** `remoteGateRejection` (`src/dashboard/server/remote-request-gate.ts:122-155`), global middleware that judges every `/api/` request. A request **with** a credential is judged by its scopes (lines 142-149). A request **without** one passes only when it is a trusted local caller (line 153).
- **No-loss matrix:** `NO_LOSS_MATRIX` in `tests/unit/lib/overdeck/no-loss-matrix.ts`. Every route registered in a top-level file of `src/dashboard/server/routes/` needs a row, or `tests/unit/lib/overdeck/no-loss-matrix.test.ts` fails; every route-scope row needs a matrix row, or `src/dashboard/server/__tests__/route-scopes.test.ts:12-17` fails.
- **Tool:** an `OverdeckTool` (`src/lib/mcp/tool.ts:21-30`) with `name`, `description`, `inputSchema`, `scope`, `audience` and `run`. `audience: 'agent'` tools are listed only when `ctx.isAgent` (`visibleTools`, `src/lib/mcp/server.ts:37-39`).

## Requirements

### Functional

- **FR-1 Caller from the token only.** A self route finds its caller only from the request's credential: `kind === 'token'` with a non-empty `agentId` and an `agentKind`. It never reads an agent id, issue id or conversation from the body, query or headers.
- **FR-2 Non-agent callers are refused.** Any other credential — none, `internal-token`, `root-session`, `device`, a plain `token`, `machine`, `phone` — gets 403 `{ error: 'self routes need an agent token', code: 'not-an-agent-token' }`.
- **FR-3 Gone agents are refused.** An agent token whose agent has no `state.json` (or an empty `workspace`), or whose conversation has no row (or an empty `cwd`), gets 404 `{ error: 'the agent for this token no longer exists', code: 'agent-gone' }`.
- **FR-4 Closed verb set, safe argv.** A job runs only one of the closed `SelfJobVerb` set. Its argv is the verb's fixed prefix followed by pieces built only through typed constructors: a validated id/ref positional, one `--<flag>=<value>` token, a bare `--<switch>`, or positionals after a single `--`. No caller text appears before the fixed prefix or as an argv element that could be read as a flag.
- **FR-5 Job process.** A job runs `panCliInvocation(argv)` through promisified `execFile`, with `cwd` = the caller's workspace or conversation `cwd`, the caller's identity env (Work item 3, step 3), a 15-minute timeout, a 4 MiB `maxBuffer`, and optional stdin text.
- **FR-6 Job retention.** A job keeps the last 16,384 bytes of stdout and of stderr. Finished jobs are dropped 1 hour after they end. At most 200 jobs are held; starting a job drops the oldest finished jobs to make room and refuses with `too-many-jobs` when 200 jobs are still running.
- **FR-7 Owner-only jobs.** Only the job owner can read or wait on a job. Another caller and an unknown id get the same 404 `{ error: 'no such job', code: 'unknown-job' }`.
- **FR-8 State route.** `GET /api/self/jobs/:id` answers the job's state now.
- **FR-9 Wait route.** `GET /api/self/jobs/:id/wait?timeoutMs=<1..50000>` blocks until the job ends or `timeoutMs` passes (default 50,000) and answers the state. A `timeoutMs` that is not an integer in 1..50,000 is 400 `{ error: 'timeoutMs must be an integer from 1 to 50000', code: 'bad-timeout' }`.
- **FR-10 `wait_job` tool.** An `audience: 'agent'` tool with scope `read:state` calls the wait route with `timeoutMs=50000` and returns the route's answer: `{ status: 'done', … }` or `{ status: 'running', …, next: { tool: 'wait_job', arguments: { jobId } } }`.
- **FR-11 Documentation.** `docs/DASHBOARD-AUTH.md` and `configuration/mcp.mdx` describe the self routes, the job model and `wait_job`.

### Non-functional

- **NFR-1 Async only.** No `execSync`, `spawnSync` or `execFileSync`; no new `*Sync` function (repo rules `no-execsync-server`, `prefer-async`). `getAgentState` and `getConversationByName` are existing synchronous reads that routes already call; they stay as they are.
- **NFR-2 Fake timers.** The 50 s wait test and the 1-hour retention test use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`, never real sleeps (repo rule `fake-timers-for-retry-tests`). The one test that runs a real child process (`process.execPath -e …`) uses no timers.
- **NFR-3 One authority.** Both routes have `route-scopes.ts` rows (`read:state`) and no-loss rows, and live in a top-level file of `src/dashboard/server/routes/` (epic NFR-9). The scope table admits the request; the handler then requires an agent token (epic NFR-1).
- **NFR-4 No secrets in a job.** A job's env never contains `OVERDECK_MCP_TOKEN` or `OVERDECK_MCP_TOKEN_FILE`, and its argv never contains a token. Answers never include the env.
- **NFR-5 Module size and Effect boundary.** Every new module stays under 300 lines. No exported Effect wrapper around in-repo Promise code (`npm run lint:effect-facades` must not rise); the job store and caller resolver export plain functions.
- **NFR-6 One CLI door.** Jobs build their command with `panCliInvocation` (Fact 7), never a hand-built `process.execPath` path.

## Decisions

- **D-1 Status codes.** 403 `not-an-agent-token` for every non-agent credential and for no credential (Fact 2). 404 `agent-gone` for a token whose owner is gone. 404 `unknown-job` for an unknown job **and** for another caller's job, so a job id's existence never leaks. 400 `bad-timeout`. The handler checks in this order: caller (403/404), then `timeoutMs` (400), then the job (404).
- **D-2 The route answers `next`.** Epic D-12 says every wait route returns `{ status: 'running', next: { tool, arguments } }`. `selfJobAnswer(state)` in the job store builds it, so the routes of this item and of W-SELF2 return the same shape and the tool passes it through unchanged.
- **D-3 Job answer shape.** A finished job always answers `status: 'done'`, whatever its exit code; failure shows in `exitCode`, `signal`, `timedOut` and `error`. Epic AC-7 names only `running` and `done`.
- **D-4 Verb table now, routes later.** This item defines the whole closed `SELF_JOB_VERBS` table (nine verbs, Fact 8) with **verb words only** as fixed prefixes: `task claim`, `task done`, `task block`, `done`, `handoff`, `worker report`, `lane report`, `memory add`, `memory search`. Flags and positionals stay with the route item that adds the verb. Why: the argv-safety rules are one security boundary (epic H-7) reviewed once here; W-SELF2, W-DEL1 and W-MEM1 can then run in parallel without each editing the same union.
- **D-5 Identity env.** A job's env is the dashboard's `process.env` minus `OVERDECK_AGENT_ID`, `OVERDECK_CONVERSATION`, `OVERDECK_ISSUE_ID`, `OVERDECK_CLAIM_ID`, `OVERDECK_AGENT_STARTED_BY`, `OVERDECK_MCP_TOKEN` and `OVERDECK_MCP_TOKEN_FILE`, plus: for an agent, `OVERDECK_AGENT_ID=<agentId>`; for a conversation, `OVERDECK_CONVERSATION=<tmuxSession>` (Fact 5, not the name); for both, `OVERDECK_ISSUE_ID=<issueId>` when the caller has one and `OVERDECK_DASHBOARD_URL=http://127.0.0.1:<API_PORT ?? PORT ?? 3011>`. Why: the dashboard may have been started from an agent's or the Flywheel's shell, and an inherited identity variable would make the child `pan` act for the wrong agent (Fact 6).
- **D-6 Capacity.** At 200 held jobs, `start` first drops the oldest finished jobs; if 200 are still running it refuses with `{ ok: false, code: 'too-many-jobs' }` (later route items answer 429). There is no per-agent quota.
- **D-7 Output arrives at the end.** Promisified `execFile` buffers output until the child exits, so a running job's state shows empty `stdout`/`stderr`. Streaming partial output is not needed by any epic item.
- **D-8 Injected runner.** The job store takes a `runner` dependency (default `runPanJob`, the real `execFile` wrapper). Store tests inject a fake runner with a controllable promise instead of mocking `node:child_process`; `runPanJob` itself is tested once against a real `process.execPath -e` child.
- **D-9 `WAIT_CHUNK_MS` lives in `src/lib/mcp/tool.ts`.** Both the job store (server) and the tool module import it; `lib/mcp` must never import dashboard server code (`lib/mcp/server.ts` header), so the constant goes in the MCP leaf module.
- **D-10 Wait cancellation.** The wait route passes `Effect.promise`'s `AbortSignal` (Fact 9) to the store's `wait`, which clears its timer and returns early when the signal aborts. The `wait_job` tool does not forward MCP request cancellation (NonGoal).

### WI-1 — Self caller resolver (`self-caller`)

- **What and why:** FR-1, FR-2, FR-3, D-1. One function turns a credential into the caller every self route acts for.
- **Files:** new `src/dashboard/server/self-caller.ts`; new test `src/dashboard/server/__tests__/self-caller.test.ts`.
- **Steps:**
  1. Create `self-caller.ts`:
     ```ts
     /**
      * The caller of a self route (PAN-4927 W-SELF1, D-10): an agent token's
      * agent, found from the token only. …
      */
     import type { HttpServerRequest } from 'effect/unstable/http';

     import { getAgentState } from '../../lib/agents/agent-state-read.js';
     import { getConversationByName } from '../../lib/overdeck/conversations.js';
     import { type DashboardCredential, resolveRequestCredential } from './routes/dashboard-auth.js';

     export interface SelfCaller {
       /** The token's `agentId`: a normalized agent id, or a conversation name. */
       agentId: string;
       agentKind: 'agent' | 'conversation';
       /** The token's role (`Role` or 'conversation'); null when the record has none. */
       role: string | null;
       /** The agent's workspace, or the conversation's cwd. Jobs run here. */
       cwd: string;
       issueId: string | null;
       /** The conversation's tmux session (`conv-<name>`); null for agents. */
       tmuxSession: string | null;
     }

     export const NOT_AN_AGENT_TOKEN = { error: 'self routes need an agent token', code: 'not-an-agent-token' } as const;
     export const AGENT_GONE = { error: 'the agent for this token no longer exists', code: 'agent-gone' } as const;

     export type SelfCallerResult =
       | { ok: true; caller: SelfCaller }
       | { ok: false; status: 403; body: typeof NOT_AN_AGENT_TOKEN }
       | { ok: false; status: 404; body: typeof AGENT_GONE };

     export interface SelfCallerDeps {
       getAgentState: (agentId: string) => { workspace: string; issueId: string } | null;
       getConversationByName: (name: string) => { cwd: string; tmuxSession: string; issueId: string | null } | null;
     }

     const defaultDeps: SelfCallerDeps = { getAgentState, getConversationByName };

     export function selfCallerFromCredential(credential: DashboardCredential | null, deps: SelfCallerDeps = defaultDeps): SelfCallerResult;
     export function resolveSelfCaller(request: HttpServerRequest.HttpServerRequest, deps: SelfCallerDeps = defaultDeps): SelfCallerResult {
       return selfCallerFromCredential(resolveRequestCredential(request), deps);
     }
     ```
  2. `selfCallerFromCredential` rules, in order:
     - `credential === null`, or `credential.kind !== 'token'`, or `typeof credential.agentId !== 'string' || credential.agentId === ''`, or `credential.agentKind` not `'agent' | 'conversation'` → `{ ok: false, status: 403, body: NOT_AN_AGENT_TOKEN }`.
     - `agentKind === 'agent'`: `state = deps.getAgentState(agentId)`; `state === null` or `!state.workspace` → 404 `AGENT_GONE`; else `{ agentId, agentKind, role: credential.role ?? null, cwd: state.workspace, issueId: state.issueId || null, tmuxSession: null }`.
     - `agentKind === 'conversation'`: `conv = deps.getConversationByName(agentId)`; `conv === null` or `!conv.cwd` → 404 `AGENT_GONE`; else `{ agentId, agentKind, role: credential.role ?? null, cwd: conv.cwd, issueId: conv.issueId, tmuxSession: conv.tmuxSession }`.
     - A throwing lookup is not caught (it surfaces as 500 through `httpHandler`).
  3. Do not create an HTTP response here; route files turn the result into `jsonResponse(result.body, { status: result.status })`.

### WI-2 — Closed verb table and argv builder (`self-job-argv`)

- **What and why:** FR-4, D-4, epic H-7. Jobs run `pan` with the dashboard user's rights, so argv construction is the security boundary.
- **Files:** new `src/dashboard/server/services/self-job-argv.ts`; new test `src/dashboard/server/__tests__/self-job-argv.test.ts`.
- **Steps:**
  1. Create `self-job-argv.ts`:
     ```ts
     /** PAN-4927 D-11 / W-SELF1 D-4: every pan verb a self route may run, with its fixed argv prefix. A verb not here cannot run. */
     export const SELF_JOB_VERBS = {
       'task-claim': ['task', 'claim'],
       'task-done': ['task', 'done'],
       'task-block': ['task', 'block'],
       done: ['done'],
       handoff: ['handoff'],
       'worker-report': ['worker', 'report'],
       'lane-report': ['lane', 'report'],
       'memory-add': ['memory', 'add'],
       'memory-search': ['memory', 'search'],
     } as const satisfies Record<string, readonly string[]>;
     export type SelfJobVerb = keyof typeof SELF_JOB_VERBS;

     /**
      * One argv piece after the prefix. Caller text reaches argv only through these:
      * `ref` — an id or ref positional, must match SELF_JOB_REF_PATTERN (never starts with '-');
      * `flag` — one `--<flag>=<value>` token; `flag` is a literal the route writes, `value` may be any text;
      * `switch` — a bare `--<switch>` literal such as 'json' or 'stdin';
      * `rest` — positionals after a single `--`; only as the last piece.
     ```

     ```ts
     const execFileAsync = promisify(execFile);

     export async function runPanJob(input: SelfJobRunInput): Promise<SelfJobRunResult> {
       let pending: PromiseWithChild<{ stdout: string; stderr: string }>; // type from node:child_process
       try {
         pending = execFileAsync(input.command, input.args, { cwd: input.cwd, env: input.env, timeout: input.timeoutMs, maxBuffer: input.maxBuffer, encoding: 'utf8' });
       } catch (error) {
         return { exitCode: null, signal: null, timedOut: false, stdout: '', stderr: '', error: (error as Error).message };
       }
       // A child that exits before reading stdin makes the write fail with EPIPE; ignore it.
       pending.child.stdin?.on('error', () => undefined);
       pending.child.stdin?.end(input.stdin ?? '');
       try {
         const { stdout, stderr } = await pending;
         return { exitCode: 0, signal: null, timedOut: false, stdout: tailUtf8(stdout), stderr: tailUtf8(stderr), error: null };
       } catch (raw) {
         const failure = raw as Error & { code?: number | string; signal?: NodeJS.Signals | null; killed?: boolean; stdout?: string; stderr?: string };
         const overflow = failure.code === 'ERR_CHILD_PROCESS_STDIO_MAXBUFFER';
         const timedOut = !overflow && failure.killed === true && failure.signal != null;
         return {
           exitCode: typeof failure.code === 'number' ? failure.code : null,
           signal: failure.signal ?? null,
           timedOut,
           stdout: tailUtf8(failure.stdout ?? ''),
           stderr: tailUtf8(failure.stderr ?? ''),
           error: overflow ? 'job output exceeded 4 MiB' : timedOut ? 'job timed out after 15 minutes' : typeof failure.code === 'number' ? null : failure.message,
         };
       }
     }
     ```

## Hazards

- **H-1 Jobs run with the dashboard's rights** (epic H-7). The child `pan` reaches the dashboard with the internal token (`admin`). Mitigation: the closed verb table, the argv constructors (WI-2) and the caller taken from the token only (WI-1). Later route items must never place body text in a `ref` without validation or before the prefix.
- **H-2 Restart loses jobs.** The store is in memory. A wait after a dashboard restart answers 404 `unknown-job`. The tool description says so; the job's side effect (for example a claimed item) is still on disk.
- **H-3 Inherited identity.** If `selfJobEnv` missed a variable, a job could act as the agent that started the dashboard. WI-3's env test covers every variable in Fact 6.
- **H-4 Stdin EPIPE.** A child that exits before reading stdin makes the write emit `error`; without the listener in `runPanJob` the dashboard would crash on an unhandled `error` event.
- **H-5 Test enumerations.** Appending `wait_job` to `ALL_TOOLS` breaks five existing tests (Fact 13); WI-5 updates them in the same commit.
- **H-6 Ref starting with `-`.** The epic's ref pattern `^[A-Za-z0-9#/:._-]{1,200}$` admits `-x`, which `pan` would read as a flag. WI-2 tightens the first character to `[A-Za-z0-9#]`.
