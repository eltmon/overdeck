## blocks-the-design: Failure age changes during cleanup

FR-1 says a failure older than six hours stops counting. The proposed cutoff reads `updatedAt` ([uat-reconciler.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/lib/cloister/uat-reconciler.ts), lines 308–315), but cleanup updates failed rows with `cleanedAt` ([uat-generation-engine.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/lib/cloister/uat-generation-engine.ts), lines 444–485), and every such update resets `updated_at` ([merge-sync-uat.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/lib/overdeck/merge-sync-uat.ts), lines 467–474). A failure cleaned hours later therefore blocks for six hours after cleanup, and the card reports cleanup time as failure time ([mergeTrainCopy.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/dashboard/frontend/src/components/merge-train/mergeTrainCopy.ts), lines 14–18). Add the store update path to the work item and preserve a stable failure timestamp when recording cleanup. Test a failed row cleaned later and assert that cutoff and displayed time still use the failure time.

## blocks-the-design: Retry can never assemble a batch

The card offers **Retry batch assembly** whenever the newest generation failed and at least one feature is ready ([MergeTrainView.tsx](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/dashboard/frontend/src/components/merge-train/MergeTrainView.tsx), lines 644–650 and 694–705). If the ready set has since fallen to one feature that is not held for UAT, even a forced reconcile returns `single-feature` before assembly ([uat-reconciler.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/lib/cloister/uat-reconciler.ts), lines 289–299). The confirmation nonetheless promises a new test batch ([mergeTrainCopy.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/dashboard/frontend/src/components/merge-train/mergeTrainCopy.ts), lines 50–55). Specify that retry appears only when the current ready set is batch eligible; add a test for a failed two-feature attempt followed by one unheld ready feature.

## blocks-the-design: Held rows lose their UAT warning

The queue response resolves an issue's own `hold-for-uat` label only when the queue contains exactly one row; with two or more rows, `holdsForUat` is the project default ([merge-train.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/dashboard/server/routes/merge-train.ts), lines 119–142). The new row confirmation uses that section value to omit its skipped-UAT warning when false ([MergeTrainView.tsx](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/dashboard/frontend/src/components/merge-train/MergeTrainView.tsx), lines 496–499; [mergeTrainCopy.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/dashboard/frontend/src/components/merge-train/mergeTrainCopy.ts), lines 39–45). In an auto-merge project with two ready rows, a row explicitly labeled `hold-for-uat` can therefore be merged without telling the operator that this skips its UAT hold; `issueHoldsForUat` gives the label precedence ([auto-merge-eligibility.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4598/src/lib/cloister/auto-merge-eligibility.ts), lines 109–135). Carry effective hold per queue item into the confirmation, and test a held row in a mixed multi-row queue.
