# PAN-5349 — `pan open <path>` and the right-click "Open in Overdeck"

**Issue:** https://github.com/eltmon/overdeck/issues/5349
**Requested by the operator, 2026-11-15:** opening files and folders should be a real Overdeck command, and installing Overdeck should be able to add "Open in Overdeck" to the operating system's right-click menu.
**Interacts with:** the workflow redesign epic PAN-5284. Its dock (PAN-5289) and Go to file are already on main. This child does not depend on any open child, and it must not edit `components/Stage/index.tsx` (owned by PAN-5290/5295/5343). It uses only the Stage's exported helpers.

FE means `src/dashboard/frontend/src`.

## 1. Glossary

- **Target** — the argument of `pan open`: a path (absolute, relative, or starting with `~`), optionally followed by `:line` or `:line:column`, or an issue id like `PAN-123`.
- **Root id** — the explorer's name for a readable tree: `project:<key>` (a project's primary checkout, read-only), `issue:<ID>` (an issue's feature workspace, writable), or `workspace:<id>` (a scratch workspace). The server resolves one with `resolveExplorerRoot` (`src/dashboard/server/services/explorer/roots.ts` line 115).
- **Resolution** — the server's answer for a path: `{ projectKey, rootId, relPath, kind: 'file' | 'dir' }`.
- **UI command** — a short-lived instruction from the server to open browser tabs ("open this path"). It is not stored, unlike a domain event.
- **Leader tab** — the one dashboard tab that acts on a UI command: the tab focused most recently.
- **File-manager integration** — the files `pan integrate file-manager` writes so that right-clicking a file or folder offers "Open in Overdeck".

## 2. What exists today (verified)

1. `pan open <id>` (`src/cli/index.ts` lines 266–271) opens an issue's workspace in an external editor or file manager:
   ```ts
   program
     .command('open <id>')
     .description('Open an issue workspace in your preferred editor')
     .option('-e, --editor <editor>', 'Editor to use (cursor, windsurf, vscode, zed, etc.)')
     .action(lazyAction(() => import('./commands/open.js'), 'openCommand'));
   ```
   The implementation is in `src/cli/commands/open.ts` (`openCommand`, line 47; workspace path `<project>/workspaces/feature-<id>`). It is listed in `packages/contracts/src/composer-commands.generated.ts` (`"id":"pan-open"`) and in `docs/SKILLS-CONVENTION.md` line 57.
2. No dashboard route opens a path. The frontend routes (`FE/App/routes.ts` lines 52–64) cover `/conv/`, `/issues/`, `/command-deck/:project[/:issue]` and `/workspace/:id`.
3. No server-to-browser UI command exists. `WS_METHODS` (`packages/contracts/src/rpc.ts` lines 51–127) streams domain events, issue events, terminals, agent output, conversation messages and project session trees. Domain events are stored in the event store (`POST /api/internal/events`, `src/dashboard/server/routes/internal-events.ts` lines 103–124), so they are the wrong carrier for a one-shot "open this" command.
4. Opening in the dashboard is already possible from frontend code:
   - `openCodePane(deckKey, target)` (`FE/components/explorer/openCodePane.ts` line 41) focuses or adds a code pane. `target` is `{ rootId, path, line?, column?, preview? }` with `path` relative to the root.
   - The dock opens with `openDock(deckKey, { tab: 'files', reveal: { rootId, path } })` (`OpenDockInput`, `FE/components/dock/workDockStore.ts` lines 43–52). A different root needs `setRootOverride` first (`FE/components/dock/WorkDock.tsx` line 177).
5. Path-to-root rules already exist in the frontend as `rootIdForConversation` (`FE/components/explorer/rootForConversation.ts` lines 36–69). Rule 4 maps `<project>/workspaces/feature-<x>/…` to `issue:<X>`. Rule 5 maps anything else under a project to `project:<key>`, longest project path first. The server has `findProjectByPath` (`src/lib/projects.ts` line 865) and `resolveWorkspaceForCwd` (`src/lib/workspaces/resolver.ts` line 322).
6. The CLI calls the dashboard with `callDashboard(path, { method, body })` (`src/cli/commands/dashboard-call.ts`). It sends the internal-token header and throws `DashboardUnreachableError` when nothing answers. The base URL comes from `getDashboardApiUrl()` (`src/lib/config.ts` line 439). `openBrowser(url)` is exported from `src/lib/browser.ts` line 91.
7. `pan install` (`src/cli/commands/install.ts` lines 59–71) uses `--skip-*` flags and `inquirer` confirms when stdin is a TTY. It writes no `.desktop` file, Finder service or registry key today. Doctor checks are `CheckResult` objects collected in `collectDoctorChecks` (`src/cli/commands/doctor.ts` line 699).
8. The desktop app (`apps/desktop/src/main.ts` lines 103–107) holds a single-instance lock, and `app.on("second-instance", () => showOrCreateWindow())` ignores the second launch's argv. Its `package.json` `build` block has no `fileAssociations`.
9. New HTTP routes need a row in `src/dashboard/server/route-scopes.ts` (unlisted routes need `admin`) and a row in `tests/unit/lib/overdeck/no-loss-matrix.ts`. `no-loss-matrix.test.ts` scans every `HttpRouter.add` route and every RPC method.

## 3. Decisions

- **O-D1 `pan open` means "open in Overdeck".**
  - `pan open <target>` opens in the dashboard.
  - `pan open <target> --editor [name]` keeps today's behavior: the external editor, or the file manager when the name is `file-manager`.
  - `pan open <issue>` without `--editor` opens the issue's workspace folder in the dashboard.
  This changes the default of an existing verb, so the changelog entry says so plainly.
- **O-D2 Target parsing, in order.**
  1. If the whole string, after `~` expansion and `path.resolve(process.cwd(), …)`, exists on disk, it is a path.
  2. Otherwise, if it matches `^(.*):(\d+)(?::(\d+))?$` and the part before the colon exists, it is a path plus line (and column).
  3. Otherwise, if `resolveBareNumericId` resolves it, it is an issue.
  4. Otherwise, exit 1 with `Not a file, folder or issue: <target>`.
  `--line <n>` and `--column <n>` override any suffix.
- **O-D3 The server resolves.** The new route `POST /api/ui/open` takes `{ path: string, line?: number, column?: number }` with an absolute path. It runs `realpath`, decides `kind` with `stat`, and picks the root with the same rules as `rootIdForConversation`. The rules are moved into a shared pure function, `resolvePathRoot(absPath, projects, workspaces)` in `packages/contracts/src/path-root.ts`, which both sides import. Scratch workspaces (`kind === 'scratch'`, matched by longest path) give `workspace:<id>`.
  - **Outside every registered project:** the route answers 404 `{ error: 'outside-projects', path, suggestion: 'pan project add <dir>' }`, where `<dir>` is the folder itself or the file's parent.
  - **Inside a project:** it answers 200 `{ projectKey, rootId, relPath, kind, line?, column?, delivered }`, where `delivered` is the number of tabs the command reached.
- **O-D4 A UI command channel.** Add the RPC stream `pan.subscribeUiCommands` (`WS_METHODS.subscribeUiCommands`), backed by one in-memory Effect `PubSub<UiCommand>` in a new server service, `src/dashboard/server/services/ui-commands.ts`. `UiCommand` is `{ id: string; type: 'open-path'; resolution }`, a Schema in `packages/contracts/src/ui-commands.ts`. Nothing is stored. `delivered` is the PubSub's current subscriber count. The route-scopes row gives it `read:events`, as for `pan.subscribeDomainEvents` (`route-scopes.ts` line 261).
- **O-D5 Only the leader tab acts.** Every tab writes `localStorage['overdeck.ui.focusedTab'] = { tabId, at }` on `focus` and `visibilitychange` to visible, where `tabId` is a random id made at load. On a UI command, a tab acts only if it is the stored `tabId`. If the stored entry is missing or older than 24 hours, the tab with the lowest `tabId` that is visible acts. Wrap storage access in try/catch. When storage is unavailable, every visible tab acts; a duplicate open focuses the same pane, so it is harmless. The acting tab calls `window.focus()`. Browsers may not raise the window, so the CLI prints where it opened.
- **O-D6 What the leader tab does.**
  1. Select the project's deck with the existing deck navigation (`openInDeck({ projectKey })` from `FE/components/frame/deck/deckNavigation.tsx`).
  2. If the root is not the dock's default root for that deck, call `setRootOverride`.
  3. For a folder, call `openDock(deckKey, { tab: 'files', reveal: { rootId, path: relPath } })`.
  4. For a file, call `openCodePane(deckKey, { rootId, path: relPath, line, column })` and also reveal it in the Files dock.
  5. Show the toast `Opened <relPath> from pan open`.
- **O-D7 No tab open.** When `delivered === 0`, the CLI opens `<dashboardUrl>/open?path=<encoded abs path>[&line=n&column=n]` with `openBrowser`. The new frontend route `/open` calls `POST /api/ui/open` with `{ path, dryRun: true }`, which resolves without publishing. It then runs O-D6 and replaces the URL with the deck's URL. `--new-tab` forces this even when a tab exists.
- **O-D8 Dashboard not running.** Exit 1 with `Overdeck isn't running. Start it with: pan up`. Do not start it automatically.
- **O-D9 Outside every project.** The CLI prints the 404's suggestion and exits 1. The `/open` route shows a dialog for a folder: `<dir> isn't in a project. Add it as a project?` Its buttons are **Add project**, which opens the existing Add-project dialog in `existing` mode with the path filled in (`/projects/new?mode=existing&path=…`), and **Cancel**. For a file, it shows the same text naming the parent folder.
- **O-D10 The desktop app.** `second-instance` passes the new argv. If argv contains `--open <path>`, the running app shows its window and navigates to `/open?path=…`. The packaged app gets no `fileAssociations` in this issue. The right-click integration calls `pan open`, which reaches the app like any tab once the app's window subscribes to UI commands. The app raises its window on a UI command through the existing preload bridge. If the bridge has no such call, add `raiseWindow()` to the preload API.
- **O-D11 The integration verb.** `pan integrate file-manager` installs the integration and `--remove` removes it. `--dry-run` prints each file it would write or delete and each command it would run. It records `integrations.fileManager: { installed: true, panPath, at }` in `~/.overdeck/config.yaml`. `panPath` is the absolute path of the `pan` executable (`process.argv[1]`'s shim, else the result of `which pan`). Every integration file calls that absolute path, so it works without a login shell's PATH.
- **O-D12 What gets written, per platform.** All paths are per user, and nothing needs root.
  - **Linux:**
    1. `~/.local/share/applications/overdeck-open.desktop` (`Type=Application`, `Name=Overdeck`, `Exec="<panPath>" open %f`, `NoDisplay=true`, `MimeType=inode/directory;text/plain;application/octet-stream;`, `Icon=` the installed `favicon.svg` path), then `update-desktop-database ~/.local/share/applications` when that command exists. This gives "Open With → Overdeck" in GNOME Files, Dolphin and others.
    2. GNOME Files: `~/.local/share/nautilus/scripts/Open in Overdeck`, mode 0755, a `#!/bin/sh` script that runs `"<panPath>" open "$f"` for each argument. It appears under right-click → Scripts.
    3. KDE Dolphin: `~/.local/share/kio/servicemenus/overdeck-open.desktop`, mode 0755, with `Type=Service`, `MimeType=all/all;`, `Actions=openInOverdeck;`, `X-KDE-Priority=TopLevel`, and a `[Desktop Action openInOverdeck]` section with `Name=Open in Overdeck` and `Exec="<panPath>" open %f`.
  - **macOS:** `~/Library/Services/Open in Overdeck.workflow`, an Automator Quick Action bundle. `Contents/Info.plist` has an `NSServices` entry with `NSMenuItem.default = "Open in Overdeck"` and `NSSendFileTypes = ["public.item"]`. `Contents/document.wflow` holds a "Run Shell Script" action (`/bin/zsh`, input as arguments) whose body runs `"<panPath>" open "$f"` for each argument, with input type files and folders in Finder. Then run `/System/Library/CoreServices/pbs -update`. The two plist files are generated from templates in `src/lib/integrations/templates/macos/`.
  - **Windows:** `reg add` under `HKCU\Software\Classes` for three keys:
    - `*\shell\OpenInOverdeck` with command `"<panPath>" open "%1"`;
    - `Directory\shell\OpenInOverdeck` with the same command;
    - `Directory\Background\shell\OpenInOverdeck` with command `"<panPath>" open "%V"`.
    Each key's default value is `Open in Overdeck`, and `Icon` is the installed `.ico`. On Windows 11 the entry appears under "Show more options". Say so in the docs.
- **O-D13 `pan install` asks.** After the existing optional steps, when stdin is a TTY, ask `Add "Open in Overdeck" to your file manager's right-click menu? (y/N)`, defaulting to No. New flags: `--file-manager-integration` installs without asking, and `--skip-file-manager-integration` neither asks nor installs. Without a TTY and without the first flag, skip. Install calls the same function as `pan integrate file-manager`.
- **O-D14 Doctor.**
  - When `integrations.fileManager.installed` is true, check that `panPath` exists and is executable, and that the platform's files exist.
  - If either check fails, return `warn` with the message `File-manager integration is stale` and the fix `pan integrate file-manager`.
  - When the integration is not installed, add no check.
- **O-D15 Implementation checkpoints.**
  - **macOS Quick Action:** verify on the operator's Mac rig that Finder shows Quick Actions → Open in Overdeck and that it runs. If the generated bundle does not register, the fallback is to keep the code and document the manual Automator steps (New → Quick Action → Run Shell Script with the same body) in the docs page, and to say so in the PR.
  - **Windows:** no Windows machine is available. Verify by unit tests on the exact `reg` argument arrays, and mark Windows as "untested on real hardware" in the docs page.

## 4. Requirements

- **FR-1** `pan open <path>` reveals a folder in the Files dock, or opens a file in a code pane, of the right project's deck in the leader tab (O-D1, O-D3, O-D5, O-D6).
- **FR-2** `pan open <file>:<line>[:<col>]` and `--line`/`--column` open the file at that position (O-D2).
- **FR-3** `pan open <issue>` opens the issue's workspace folder in the dashboard, and `--editor` keeps today's behavior (O-D1).
- **FR-4** With no tab open, or with `--new-tab`, the CLI opens `/open?path=…`, which does the same (O-D7).
- **FR-5** Paths outside every project fail with the add-project suggestion, and `/open` offers Add project (O-D9).
- **FR-6** The desktop app handles `--open <path>` from a second launch and raises its window on a UI command (O-D10).
- **FR-7** `pan integrate file-manager [--remove] [--dry-run]` writes or removes the per-platform files of O-D12 and records the config of O-D11.
- **FR-8** `pan install` offers the integration per O-D13.
- **FR-9** `pan doctor` warns on a stale integration per O-D14.
- **NFR-1** No `execSync` in any code the dashboard server reaches. The integration code runs only in the CLI, uses async `execFile`, and never runs a shell string built from a path. All paths are passed as argv elements or written into files.
- **NFR-2** UI commands are never persisted, and a tab that reconnects does not replay old ones.
- **NFR-3** The route reads only paths inside registered projects or workspaces. It never lists or reads file contents.

## 8. Out of scope

- Registering Overdeck as the default handler for any file type.
- Opening paths on linked (remote) machines.
- Opening non-text files in a viewer: they open as today's code pane would show them.
