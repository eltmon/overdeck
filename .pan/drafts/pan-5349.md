# PAN-5349 — `pan open <path>` and the right-click "Open in Overdeck"

**Issue:** https://github.com/eltmon/overdeck/issues/5349
**Requested by the operator, 2026-11-15:** opening files and folders should be a real Overdeck command, and installing Overdeck should be able to add "Open in Overdeck" to the operating system's right-click menu.
**Interacts with:** the workflow redesign epic PAN-5284. Its dock (PAN-5289) and Go to file are already on main. This issue does not depend on any open child, and it must not edit `components/Stage/index.tsx` (owned by the PAN-5284 children). It uses only exported helpers (`openCodePane`, `useWorkDockStore`, `useActiveDock`, `usePanesStore`, `useDeckNavigation`).

FE means `src/dashboard/frontend/src`. All line numbers were checked against `feature/pan-5349` at `0d5ce0a2875` (2026-11-15). Where a line may drift, the quoted code is the search anchor.

## 1. Glossary

- **Target** — the argument of `pan open`: a path (absolute, relative, or starting with `~`), optionally followed by `:line` or `:line:column`, or an issue id like `PAN-123`.
- **Root id** — the explorer's name for a readable tree: `project:<key>` (a project's primary checkout, read-only), `issue:<ID>` (an issue's feature workspace, writable), or `workspace:<id>` (a scratch workspace). The server resolves one with `resolveExplorerRoot` (`src/dashboard/server/services/explorer/roots.ts` line 115, `export async function resolveExplorerRoot`).
- **Deck key** — the key the Stage, the panes store and the dock store use for one project's deck. It is the project key: `CommandDeck/index.tsx` line 346 mounts `<Stage deckKey={selectedProject}>`, and `openInDeck({ projectKey })` sets `selectedProjectKey`.
- **Resolution** — the server's answer for a path: `{ projectKey, rootId, relPath, kind: 'file' | 'dir', line?, column? }`. `relPath` is POSIX, relative to the root folder, and `''` for the root itself.
- **UI command** — a short-lived instruction from the server to open dashboard tabs ("open this path"). It is never stored, unlike a domain event.
- **Leader tab** — the one dashboard tab that acts on a UI command: the tab focused most recently (rules in O-D5).
- **File-manager integration** — the files and registry keys `pan integrate file-manager` writes so that right-clicking a file or folder offers "Open in Overdeck".
- **Integration state file** — `~/.overdeck/integrations/file-manager.json` (under `getOverdeckHome()`), the record of what the integration installed.
- **pan shim** — `<OVERDECK_HOME>/cli-bin/pan`, the `#!/bin/sh` exec shim `pan install`/`pan sync` write (`src/lib/pan-cli-shim.ts`, `panCliShimDir()` line 45).

## 3. Decisions

- **O-D1 `pan open` means "open in Overdeck".**
  - `pan open <target>` opens in the dashboard.
  - `pan open <target> --editor [name]` opens the target's folder or file in an external editor: the named editor, or the first editor found on PATH when no name is given, or the file manager when the name is `file-manager`. This is today's behavior, extended from issue workspaces to any target. Line and column are ignored for editors.
  - `pan open <issue>` without `--editor` opens the issue's workspace folder in the dashboard.
  This changes the default of an existing verb, so the changelog says so plainly under `#### Improved`.
- **O-D2 Target parsing, in order** (pure `parseOpenTarget(raw, cwd, home)`):
  1. Expand a leading `~` to `home`, then `path.resolve(cwd, …)`. If that path exists, it is a path.
  2. Otherwise, if the raw string matches `^(.*):(\d+)(?::(\d+))?$` and the expanded, resolved part before the colon exists, it is a path plus line (and column).
  3. Otherwise, if `resolveBareNumericId(raw)` (`src/lib/issue-id.ts` line 183) returns an id, it is an issue.
  4. Otherwise, exit 1 with `Not a file, folder or issue: <target>`.
  `--line <n>` and `--column <n>` override any suffix. A Windows drive path such as `C:\x` never matches the suffix pattern because a digit must follow the colon.
- **O-D3 The server resolves.** `POST /api/ui/open` takes `{ path: string, line?: number, column?: number, dryRun?: boolean }`.
  1. A missing or non-absolute `path` answers 400 `{ error: 'path-must-be-absolute' }`. A `line`/`column` that is not a positive integer answers 400 `{ error: 'invalid-position' }`.
  2. It runs `realpath` and `stat` asynchronously (`node:fs/promises`). A missing path answers 404 `{ error: 'not-found', path }`.
  3. It builds the candidates: every project from `listProjectsAsync()` with `realpath(config.path)` (a project whose path fails `realpath` is skipped), and every non-archived scratch row from `listWorkspaces({ kind: 'scratch' })` with `realpath(row.path)` (failures skipped).
  4. It calls the shared pure `resolvePathRoot(realPath, projects, scratchWorkspaces)` from `packages/contracts/src/path-root.ts`. It returns `{ kind: 'root', projectKey, rootId } | { kind: 'no-root', projectKey } | { kind: 'outside' }`, applying in order: a scratch workspace path containing the target, longest first (`workspace:<id>`); `<projectPath>/workspaces/feature-<x>/…` (`issue:<X uppercase>`); any other folder under `<projectPath>/workspaces/` (`no-root`); the longest project path containing the target (`project:<key>`); else `outside`.
  5. For `root`, it calls `resolveExplorerRoot(rootId)` and computes `relPath = relative(root.absPath, realPath)` in POSIX form. When `resolveExplorerRoot` throws, or `relPath` starts with `..`, the answer is `no-root`. The deck's `projectKey` is `root.projectKey`.
  6. Answers: `outside` → 404 `{ error: 'outside-projects', path, kind, suggestion: 'pan project add <dir>' }`, where `<dir>` is the folder itself or the file's parent. `no-root` → 404 `{ error: 'no-root', path, projectKey }`. `root` → 200 `{ projectKey, rootId, relPath, kind, line?, column?, delivered }`.
  7. Unless `dryRun`, it publishes `{ id: <random UUID>, type: 'open-path', resolution }` and `delivered` is the subscriber count at publish time. With `dryRun`, it publishes nothing and `delivered` is 0.
  The frontend's `rootIdForConversation` rules 4–5 call `resolvePathRoot(cwd, ctx.projects, [])` (no scratch rows, so its behavior does not change) and map `root` to its `rootId`, anything else to `null`.
- **O-D4 A UI command channel.** RPC stream `pan.subscribeUiCommands` (`WS_METHODS.subscribeUiCommands`, payload `{}`, success `UiCommand`). `UiCommand` and `UiOpenResolution` are Schemas in `packages/contracts/src/ui-commands.ts`, exported from the contracts index. The server side is a module-level hub in `src/dashboard/server/services/ui-commands.ts` (no Effect layer, so `server.ts` is untouched): one `PubSub.unbounded<UiCommand>()` created once, `publishUiCommand(cmd): number` (publishes, returns the subscriber count), `uiCommandStream(): Stream<UiCommand>` (increments the count when a subscriber's stream starts, decrements in a finalizer when it ends), `uiCommandSubscriberCount(): number`. A late subscriber gets only commands published after it subscribed; nothing is replayed. The route-scopes RPC map gives it `read:events`, like `pan.subscribeDomainEvents`.
- **O-D5 Only the leader tab acts** (`FE/lib/uiCommands/leaderTab.ts`).
  1. Each tab makes a random `tabId` at load.
  2. On `focus`, and on `visibilitychange` to visible, the tab writes `localStorage['overdeck.ui.leaderTab'] = JSON.stringify({ tabId, at: Date.now() })`.
  3. On `pagehide`, the tab removes the entry when the stored `tabId` is its own.
  4. On a command, the tab's role is: `leader` when the stored `tabId` is its own; `fallback` when the entry is missing, unparseable, older than 24 hours, or storage throws; otherwise `follower`.
  5. A `leader` acts at once, whether visible or not. A `fallback` acts at once if `document.visibilityState === 'visible'`. A `follower` waits 750 ms; if it has not seen a `{ handled: id }` message for that command on `BroadcastChannel('overdeck.ui-commands')` and it is visible, it acts. This covers a leader that crashed without `pagehide`.
  6. Every tab that acts posts `{ handled: id }` on the channel (when `BroadcastChannel` exists), calls `window.focus()`, and calls `window.overdeckBridge?.raiseWindow?.()`.
  Two tabs acting on one command is harmless: each opens the same pane in its own deck state. Every storage access is in try/catch.
- **O-D6 What the acting tab does** (`openPathInDeck(resolution, navigation)` in `FE/lib/uiCommands/openPathInDeck.ts`, `deckKey = resolution.projectKey`):
  1. `usePanesStore.getState().ensureHome(deckKey)`, then `navigation.openInDeck({ projectKey: deckKey })`.
  2. A file: `openCodePane(deckKey, { rootId, path: relPath, line, column })`, then `openDock(deckKey, { tab: 'files', reveal: { rootId, path: relPath } })`. No override: the active code pane sets the dock scope.
  3. A folder: when `useActiveDock.getState().current` is not `{ deckKey, rootId }`, call `setRootOverride(deckKey, rootId, anchor)`, where `anchor` is `current.activePaneId` when `current?.deckKey === deckKey`, else `selectActivePaneId(deckKey)(usePanesStore.getState())` (`FE/lib/panesStore.ts` line 426), with `null` mapped to `undefined`. Then `openDock(deckKey, { tab: 'files', reveal: relPath === '' ? undefined : { rootId, path: relPath } })`.
  4. Show the sonner toast `Opened <relPath || root folder> from pan open`.
- **O-D7 No tab open.** When `delivered === 0`, or with `--new-tab`, the CLI opens `<dashboardUrl>/open?path=<encoded abs path>[&line=n&column=n]` with `openBrowser`, where `dashboardUrl` is `getDashboardApiUrl()`. With `--new-tab` the CLI sends `dryRun: true`, so existing tabs do not act too. The frontend handles `/open` with `OpenPathHost` (`FE/components/open/OpenPathHost.tsx`), mounted in `App.tsx` inside `<DeckNavigationProvider>`. On mount, when `window.location.pathname === '/open'`, it reads `path`, `line` and `column`, POSTs `/api/ui/open` with `dryRun: true` and `dashboardMutationJsonHeaders()`, runs `openPathInDeck`, and then, if the pathname is still `/open`, calls `history.replaceState(null, '', '/command-deck/' + encodeURIComponent(projectKey))`. A missing `path` param shows the toast `Nothing to open: the link has no path` and replaces the URL with `/`.
- **O-D8 Dashboard not running.** When `callDashboard` throws `DashboardUnreachableError`, exit 1 with `Overdeck isn't running. Start it with: pan up`. Do not start it.
- **O-D9 Outside every project.** The CLI prints `<path> isn't in a registered project. Add it with: <suggestion>` and exits 1; for `no-root` it prints `<path> is inside <projectKey> but not in a feature or scratch workspace` and exits 1. `/open` with `outside-projects` shows a `components/shared/Modal.tsx` dialog `<dir> isn't in a project. Add it as a project?` with **Add project** (calls `useAddProjectDialog.getState().show('existing', undefined, { initialPath: dir })`) and **Cancel**. For a file the text names the parent folder. `/open` with `no-root` or `not-found` shows the matching sentence as an error toast.
- **O-D10 Add-project prefill.** `AddProjectShowOptions` (`FE/components/project/new/addProjectDialogStore.ts`) gains `initialPath?: string`; the store keeps it and `hide()` clears it; `AddProjectDialogHost` passes it to `AddProjectDialog` as `initialPath`, which passes it to `AddProjectFolderStep`. When `initialPath` is set, the folder step calls its own `choose(initialPath)` once on mount, so it moves straight to resolving that folder.
- **O-D11 The desktop app.** `second-instance` receives `(event, argv)`. If argv contains `--open <path>` and the active dashboard is local (`getActiveDashboard().kind !== 'remote'`), the app shows its main window and loads `${resolveWindowUrl()}/open?path=<encoded>`; in remote mode it only shows the window. The preload bridge gains `raiseWindow()`, sent over a new IPC channel `pan:raise-window`; main handles it with `BrowserWindow.fromWebContents(event.sender)` → `show()` + `focus()`. `FE/types/ambient.d.ts` gains `raiseWindow?(): void` (optional, older desktop builds lack it). `pan open` reaches the desktop window only when the window shows the same server the CLI calls; routing to the embedded server on 7825+ is out of scope (§8).
- **O-D12 The integration verb.** `pan integrate file-manager` installs and `--remove` removes. `--dry-run` prints each file it would write or delete and each command it would run, and changes nothing. Install writes the integration state file `{ installed: true, platform, panPath, at, files: string[], registryKeys: string[] }`; remove deletes the listed files and keys, then the state file. The state lives in its own file, not `config.yaml`, because `config.yaml` is normalized and rewritten by dashboard settings doors (`src/lib/config-yaml.ts`), and doctor must read this record without them.
  - `panPath` on Linux/macOS is the pan shim `join(panCliShimDir(), 'pan')` when it exists and is executable, else `findExecutableOnPath('pan', process.env.PATH)`; on Windows it is the first of `pan.cmd`, `pan.exe` found by splitting `PATH` on `;`. No result exits 1 with `pan is not installed on PATH. Run: pan sync`.
  - Icon: the CLI copies `join(dirname(panCliBundlePath()), '..', 'dashboard', 'public', 'favicon.svg')` to `~/.overdeck/integrations/overdeck.svg` when that source exists; Linux files use that absolute path as `Icon=`. No icon is set on macOS or Windows.
  - Every integration file calls the absolute `panPath`, so it works without a login shell's PATH. Paths are argv elements or file content, never part of a shell string the CLI runs.
- **O-D13 What gets written, per platform.** All paths are per user; nothing needs root.
  - **Linux:**
    1. `~/.local/share/applications/overdeck-open.desktop`, mode 0644: `Type=Application`, `Name=Overdeck`, `Exec="<panPath>" open %f`, `NoDisplay=true`, `MimeType=inode/directory;text/plain;application/octet-stream;`, `Icon=<icon>`. Then `update-desktop-database ~/.local/share/applications` when that command exists. This gives "Open With → Overdeck" in GNOME Files, Dolphin and others.
    2. GNOME Files: `~/.local/share/nautilus/scripts/Open in Overdeck`, mode 0755: `#!/bin/sh` then `for f in "$@"; do "<panPath>" open "$f"; done`. It appears under right-click → Scripts.
    3. KDE Dolphin: `~/.local/share/kio/servicemenus/overdeck-open.desktop`, mode 0755: `[Desktop Entry]`, `Type=Service`, `MimeType=all/all;`, `Actions=openInOverdeck;`, `X-KDE-Priority=TopLevel`, and `[Desktop Action openInOverdeck]` with `Name=Open in Overdeck`, `Icon=<icon>`, `Exec="<panPath>" open %f`.
  - **macOS:** `~/Library/Services/Open in Overdeck.workflow/Contents/Info.plist` (an `NSServices` entry: `NSMenuItem.default = "Open in Overdeck"`, `NSMessage = "runWorkflowAsService"`, `NSSendFileTypes = ["public.item"]`, `NSRequiredContext = { NSApplicationIdentifier = "com.apple.finder" }`) and `Contents/document.wflow` (one "Run Shell Script" action, `/bin/zsh`, input as arguments, body `for f in "$@"; do "<panPath>" open "$f"; done`, input type files and folders in Finder). Both are rendered from TypeScript template strings in `src/lib/integrations/templates/macos.ts`. Then run `/System/Library/CoreServices/pbs -update` when it exists.
  - **Windows:** `reg add` (via async `execFile('reg', [...])`) under `HKCU\Software\Classes` for three keys, each with default value `Open in Overdeck` and a `command` subkey:
    - `*\shell\OpenInOverdeck` → `"<panPath>" open "%1"`;
    - `Directory\shell\OpenInOverdeck` → `"<panPath>" open "%1"`;
    - `Directory\Background\shell\OpenInOverdeck` → `"<panPath>" open "%V"`.
    Remove runs `reg delete <key> /f` for each. On Windows 11 the entry is under "Show more options"; the docs say so.
- **O-D14 `pan install` asks.** After the Ollama step, when stdin is a TTY, ask `Add "Open in Overdeck" to your file manager's right-click menu? (y/N)`, default No. `--file-manager-integration` installs without asking; `--skip-file-manager-integration` neither asks nor installs (it wins over the first flag). Without a TTY and without the first flag, skip with an info line. A failed install is a warning, never an install failure. Install calls the same function as `pan integrate file-manager`.
- **O-D15 Doctor.** When the state file says `installed: true`, check that `panPath` exists and is executable and that every listed file exists (registry keys are not checked). Any failure returns `warn`, name `File-manager integration`, message `File-manager integration is stale: <first missing path>`, fix `pan integrate file-manager`. Otherwise `ok`. No state file means no check.
- **O-D16 Implementation checkpoints.**
  - **macOS Quick Action:** verify on the operator's Mac rig (reachable by SSH; see the operator's machine memory) that Finder shows Quick Actions → Open in Overdeck and that it runs. Fallback if the generated bundle does not register: keep the code, document the manual Automator steps (New → Quick Action → Run Shell Script with the same body) on the docs page, and say so in the PR.
  - **Windows:** no Windows machine is available. Verify by unit tests on the exact `reg` argument arrays, and mark Windows "untested on real hardware" on the docs page.
  - **`/open` URL handling in `App.tsx`:** App's route effects may rewrite the URL during load. Verify in an isolated Playwright browser that `/open?path=…` ends on `/command-deck/<project>` with the pane open. Fallback: move the `replaceState` into a `setTimeout(…, 0)` after `openPathInDeck`.

## 4. Requirements

- **FR-1** `pan open <path>` reveals a folder in the Files dock, or opens a file in a code pane, of the right project's deck in the leader tab (O-D1, O-D3, O-D5, O-D6).
- **FR-2** `pan open <file>:<line>[:<col>]` and `--line`/`--column` open the file at that position (O-D2).
- **FR-3** `pan open <issue>` opens the issue's workspace folder in the dashboard, and `--editor [name]` opens the target in an external editor (O-D1).
- **FR-4** With no tab open, or with `--new-tab`, the CLI opens `/open?path=…`, which does the same (O-D7).
- **FR-5** Paths outside every project fail with the add-project suggestion, and `/open` offers Add project with the folder filled in (O-D9, O-D10).
- **FR-6** The desktop app handles `--open <path>` from a second launch and raises its window when it acts on a UI command (O-D11).
- **FR-7** `pan integrate file-manager [--remove] [--dry-run]` writes or removes the per-platform files of O-D13 and the state file of O-D12.
- **FR-8** `pan install` offers the integration per O-D14.
- **FR-9** `pan doctor` warns on a stale integration per O-D15.
- **FR-10** The docs describe `pan open`, the `/open` link, the integration per platform, and removal (WI-14).
- **NFR-1** No `execSync` in code the dashboard server reaches. The integration code runs only in the CLI, uses async `execFile`, and never runs a shell string built from a path.
- **NFR-2** UI commands are never persisted, and a tab that subscribes or resubscribes does not receive commands published before it subscribed.
- **NFR-3** `POST /api/ui/open` only calls `realpath` and `stat` on the given path. It never lists a directory or reads file contents.
