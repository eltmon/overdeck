**Issue:** https://github.com/eltmon/overdeck/issues/5499 (part of epic #5467, docs overhaul)

## Summary

The issue asks for a line-by-line accuracy audit of five published pages: `introduction.mdx`, `quickstart.mdx`,
`concepts.mdx`, `vision.mdx` and the intro of `changelog.mdx`. The planning session already did the audit: it read every
claim on the five pages against current code, `pan <verb> --help` and the dashboard source, and re-checked each wrong
claim by grep. This PRD lists every wrong, stale or removed claim per page with the current text (a grep anchor), the
replacement text and the code evidence. The implementation agent applies the changes, removes en and em dashes, fixes
frontmatter, recaptures the three screenshots that still show the old "Panopticon v0.21.0" brand, checks links, runs the
Mintlify validators and writes a PR body with one note per page. It does not re-research; it re-checks a claim only when a
grep anchor no longer matches.

## Glossary

- **Audited pages**: `introduction.mdx`, `quickstart.mdx`, `concepts.mdx` (the `Getting Started` group in `docs.json`,
  line 37 to 39), `vision.mdx` (the `Roadmap` group, `docs.json` line 208) and `changelog.mdx` (the `Changelog` tab,
  `docs.json` line 220). All five are at the repo root.
- **Changelog intro**: the part of `changelog.mdx` above the first `<Update` tag: the frontmatter, the two intro paragraphs
  and the `{/* RELEASE STEP ... */}` comment (lines 1 to 11 on the base). The `<Update>` blocks below it are release
  records written by `pan release stable` and are out of scope (Decision D1).
- **Claim**: any statement a reader could act on: a command or flag, a config key or default, a UI label or location, a
  file path, a behavior, a limit, a list of supported harnesses, trackers or platforms, or a maturity label.
- **Primary source**: the code on the base (`git grep`), `pan <verb> --help`, `src/lib/config-yaml/defaults.ts`, the
  dashboard source under `src/dashboard/frontend/src/`, and `changelog.mdx`. Other `.mdx` pages, `docs/*.md` and
  `README.md` are never proof.
- **Grep anchor**: the quoted current text in each change table. Line numbers drift as edits land, so find the text with
  `grep -n -F '<anchor>' <page>.mdx`, not by line number.
- **Dash rule**: no U+2013 (en dash) or U+2014 (em dash) in a touched page, in frontmatter and body. Check:
  `! grep -nP '[\x{2013}\x{2014}]' <page>.mdx` exits 0. Replace a dash with a comma, colon, period, parentheses, or the
  word "to" for a range. The one exception is a verbatim UI string inside a changelog release record (Decision D1).
- **Frontmatter rule**: `title` is specific and searchable; `description` is 50 to 160 characters (the text between the
  quotes); neither contains a dash. A retitled page keeps a short `sidebarTitle`.
- **Test role**: the pipeline role that runs tests and browser UAT on a PR. Today nothing starts it automatically after
  review approves (open bug #5537). CI tests on the PR head still gate the merge. `features/issue-pipeline.mdx` line 80
  already states this.
- **Doc shot**: a docs screenshot pair `<name>-light.png` and `<name>-dark.png`, produced by
  `node scripts/capture-doc-shot.mjs <route> <output-basename>` against a running dashboard and shown with the
  `<ThemedImage>` snippet.
- **Follow-ups**: code bugs or out-of-scope doc problems the audit found. They go in a `## Follow-ups` list in the PR body.
  This issue changes no code.
- **PR note**: one line per page saying what changed, or "verified, no change". Each page item puts it in its commit
  message as `PR-note: <page>.mdx: <note>`; WI-7 collects the notes into the PR body.

## Decisions

- **D1 (changelog scope)**: audit only the changelog intro (frontmatter, two paragraphs, RELEASE STEP comment). The
  `<Update>` blocks are dated release records produced by `pan release stable`; rewriting them would change history. The
  em dash at `changelog.mdx:611` is inside the verbatim UI string "Held handoff — kickoff not sent", which the code still
  renders (`src/dashboard/frontend/src/components/chat/HeldHandoffView.tsx:64`), so it stays. The PR note says so.
- **D2 (test role)**: on `introduction.mdx` and `concepts.mdx`, state only what is true whether or not #5537 lands: review
  agents check the work, and the PR needs approval and green checks before it merges. Link `/features/issue-pipeline` for
  the details. `features/specialists.mdx` still promises a test agent on every PR; that page belongs to #5502 and goes in
  Follow-ups.
- **D3 (vision scope)**: correct current-state facts on `vision.mdx`: file references, the bot login, the pickup
  predicate, setting names and storage, commands, gates and the merge and UAT model. Keep the operator's direction as is:
  the v1.0 targets and thresholds, the definitions, the industry anchors, and open questions that are still open. Where a
  criterion has no measurement today, say so in one sentence rather than deleting the target.
- **D4 (code bugs)**: when the code is wrong rather than the doc, the page states what the code does and the bug goes to
  Follow-ups. Never describe intended behavior as current.
- **D5 (screenshots)**: recapture the hero, board and pipeline pairs in place with `scripts/capture-doc-shot.mjs` (WI-6).
  Same file names, so every page that uses them gets the new image. **Implementation checkpoint:** if no dashboard is
  reachable at `https://overdeck.localhost` (or `--base http://localhost:3011`), or Playwright cannot launch, keep the old
  PNGs, still fix the alt text on the audited pages to describe current UI facts only where the old image already shows
  them, and add a Follow-up "recapture hero, board and pipeline doc shots". Never edit image pixels by hand.
- **D6 (one PR)**: all items commit to `feature/pan-5499`; one PR.
- **D7 (titles)**: retitle only where a work item says so. Slugs and file names never change.
- **D8 (other pages' alt text)**: after WI-6, other pages that use the recaptured images may carry alt text that no longer
  matches. They belong to #5501 (CLI) and #5502 (Features). WI-7 lists them in Follow-ups and posts one comment on each of
  #5501 and #5502 naming the changed images. It edits none of those pages.

## Common procedure for every page item

0. **Code wins.** If a primary source contradicts a row (main moved), skip the row, say so in the PR note, and leave that
   row's AC open with the evidence (`pan task block` with the reason). Never write a claim the code contradicts.
1. **Apply the change table.** For each row, find the anchor with `grep -n -F`, make the change. If an anchor no longer
   matches, find the claim by meaning; if it is gone, skip the row and note it.
2. **Spot-check before deleting.** Before deleting a section, re-run the row's evidence grep once.
3. **Residual rule.** Read the whole page once. For a claim the table does not list that looks doubtful, verify it against
   a primary source and fix the page to match the code. The rows marked "Verified, keep" need no re-check.
4. **Dashes.** Remove every en and em dash on the page (changelog: intro only) in the same commit.
5. **Frontmatter.** Apply the title change if any; confirm the description is 50 to 160 characters and dash-free; quote a
   `description` that contains `: `.
6. **Links.** For each internal link, `ls <path>.mdx` (and `grep -n "^#.*<heading words>"` for an anchor), counting
   `docs.json` redirects.
7. **MDX safety.** Keep any new `<word>` placeholder inside backticks.
8. **Commit** with `Item: <id>`, AC trailers and `PR-note: <page>.mdx: <one line>`; push; `pan task done`.
