# PAN-4565 — `pan handoff --fresh`: start a clean conversation with no summary and no parent link

**Issue:** [PAN-4565](https://github.com/eltmon/overdeck/issues/4565)
**Status:** planned (auto mode, 2026-10-19)
**Base commit verified against:** `6f80870ebfc` on `feature/pan-4565`

## Glossary

- **Source conversation** — the conversation `pan handoff <conv>` names (or `self`). For a fresh start it only donates defaults (project, cwd, model, effort). Its transcript is never read.
- **Successor** — the new conversation that `pan handoff` creates.
- **Fork pipeline** — the server-side path that creates and launches a successor: route handler `handleConversationSummaryFork()` and background runner `runForkPipeline()` in `src/lib/overdeck/conversation-forks.ts`, reached from `POST /api/conversations/:name/summary-fork` (`src/dashboard/server/routes/conversations.ts`, grep `'/api/conversations/:name/summary-fork'`).
- **Fork mode** — `forkMode` on the request: `'summary' | 'plain' | 'handoff'`. This issue does **not** add a fourth value.
- **Fresh start** — the new behavior: a `forkMode: 'handoff'` request with `fresh: true`. No document is authored, no summary is generated, the source transcript is not read, the successor gets no parent link, and the kickoff is the focus text only.
- **Focus** — the trailing positional text of `pan handoff`, carried as `focus` on the request and `handoffFocus` inside the pipeline. For a fresh start it is the successor's first user message, verbatim.
- **Kickoff / seed** — the first message delivered into the successor's harness by `deliverForkSeed()` (`conversation-forks.ts`, grep `export async function deliverForkSeed`).
- **Held kickoff** — PAN-4499's `--hold`: the kickoff is stored in `conversations.held_kickoff` via `holdKickoff()` (`src/lib/overdeck/conversation-kickoff-store.ts`) instead of being delivered.
- **Parent link / lineage** — `conversations.parent_conversation_id`, written once at creation by `createConversation({ parentName })` (`src/lib/overdeck/conversations.ts`, grep `if (opts.parentName)`). The dashboard nests a row under its parent and shows `continues ← #<id>` because of this column. Nothing else drives lineage in the UI.
- **Lane / effective launcher** — gauntlet lanes (PAN-4223) are conversations with `lane_key` set. `resolveEffectiveLauncher(name)` (`conversations.ts`, grep `export function resolveEffectiveLauncher`) walks parent links from a successor back to the nearest lane or root; `checkLauncher()` in `src/lib/lanes/launch.ts` lets only a root (or an orchestrator lane) launch lanes.
- **`ForkRequest`** — the persisted JSON on the successor row (`conversations.fork_request`) that `recoverStuckForks()` replays after a dashboard restart. Type in `conversations.ts`, grep `export interface ForkRequest`.
- **callerKind** — `'operator' | 'agent'` sent by the CLI from `verdictCallerFromEnv()` (`src/lib/cloister/verdict-caller.ts`). Note: every `conv-*` session, including a lane, is classified `operator`.

## Problem

`pan handoff` always links the successor to its source and always seeds it from the source transcript. In `handleConversationSummaryFork()` the `createConversation` call passes `parentName: conv.name` unconditionally (`conversation-forks.ts` line 937, grep `parentName: conv.name`), and `runForkPipeline()` always resolves the source session file first (line 455, grep `Parent has no session file`) and then authors a handoff document (`authorHandoffExternal`, line 522) or a summary. There is no CLI way to start a clean conversation that only takes the source's defaults. Example: conversation 20261019-2185 (Project Zomboid research) needed to start a new Dwarf Fortress fort on a cheaper model; a Zomboid summary is noise for that job, and the new conversation should not appear as a child of the old one.

## Proposal

Add a boolean `fresh` to the fork request, modeled exactly on PAN-4499's `hold`:

- CLI: `pan handoff [conv] --fresh [focus...]` sends `{ forkMode: 'handoff', fresh: true, focus, ... }`.
- Route: `fresh` is accepted only with `forkMode: 'handoff'`. The route skips the source session-file gate, the git-worktree gate, and author validation; creates the successor row **without** `parentName`; titles it from the focus; starts it at `forkStatus = 'spawning'`; and persists `fresh: true` in `ForkRequest`.
- Pipeline: a `fresh` branch at the very top of `runForkPipeline()` launches the session and delivers the focus verbatim (or holds it, or delivers nothing when there is no focus). It never resolves the source session file and never calls an author or summarizer.
- Recovery: `recoverStuckForks()` forwards `request.fresh` so a dashboard restart never turns a fresh start into a full handoff.
- Dashboard: a "Fresh start" checkbox in the Continue dialog under the Agent handoff intent (beside "Hold — start it myself") sends the same request. The composer's `/pan handoff --fresh …` and `/handoff --fresh …` set that checkbox.

## Requirements

### Functional

- **FR-1** `pan handoff <conv> --fresh "<focus>"` creates a successor whose first delivered user message is exactly the focus text (after the server's existing `trim()`), with no handoff document and no summary.
- **FR-2** The successor row has `parent_conversation_id = NULL`; the response and the stored row report `parentConversationId: null` and `parentConversationName: null`.
- **FR-3** No authoring or summarizing runs: `authorHandoffExternal`, `requestHandoffFromAgent`, `generateSummaryForFork` and `generateFallbackSummary` are never called, the source session file is never resolved, and a fresh start succeeds when `conversations.handoff_author_model` is unset.
- **FR-4** Defaults: project, cwd, model and effort default from the source exactly as for a handoff today (`resolveForkProjectKey`, `effectiveCwd`, `launchModel`, `inheritedEffort`). `--project`, `--cwd`, `--model`, `--effort`, `--title`, `--skill`, `--pack`, `--issue`, `--role`, `--allow-primary` and `--hold` keep their current meaning and validation.
- **FR-5** The source conversation is not changed: no message is delivered to it, and its `handoff_target_conv_id`, `handoff_doc_path`, title and status stay as they were.
- **FR-6** `pan handoff self --fresh "<focus>"` resolves the current conversation through the unchanged `resolveCurrentConversation()` path, so an agent can start its own clean successor. Positional parsing is unchanged: focus text still needs the `self` token in front of it.
- **FR-7** Empty focus: `--fresh` with no focus and no `--hold` launches the successor and delivers nothing (it waits for the operator's first message). `--fresh --hold` with no focus is rejected with HTTP 400 `fresh with hold needs focus text: there is nothing to hold` and no row is created; the CLI exits 1 with that message.
- **FR-8** `fresh: true` with `forkMode` `'summary'` or `'plain'` is rejected with HTTP 400 `fresh is only valid with forkMode "handoff"` and no row is created.
- **FR-9** Lane guard: a fresh start whose source's effective launcher is a lane (`resolveEffectiveLauncher(source.name)?.laneKey !== null`) is rejected with HTTP 400 `a fresh start cannot be made from a gauntlet lane or its successors: it would drop the lane standing that passes through the parent link (PAN-4223 D21). Use pan handoff without --fresh, or pan lane start --reuse.` and no row is created. This applies to every caller.
- **FR-10** Issue association: a fresh successor does NOT inherit the source's `issueId`. It uses `--issue` when given, else the issue detected from the effective cwd's git branch (`detectIssueIdFromBranch`, which today runs only when the source has no issue).
- **FR-11** Title: `--title` wins; else the focus collapsed to single spaces and cut to 70 characters with `…` (same rule as `handoffTitleFromFocus` but **without** the `Handoff: ` prefix); else `New conversation`. The source title is never used.
- **FR-12** A dashboard restart during a fresh start replays it as a fresh start: `recoverStuckForks()` passes `request.fresh === true` to `runForkPipeline()`, which never authors.
- **FR-13** The Continue dialog shows a "Fresh start" checkbox under the Agent handoff intent. Checked, it hides the Authored-by and Authoring-model controls, relabels the Focus field as the first message, blanks the default name, and the Continue button POSTs `{ forkMode: 'handoff', fresh: true, ... }` without `handoffAuthor`/`handoffAuthorModel`.
- **FR-14** The composer parser `parseHandoffComposerArgs()` strips a `--fresh` token from anywhere in the text and returns `fresh: true`, so the dialog opens with "Fresh start" checked and `--fresh` never reaches the Focus field.
- **FR-15** The CLI refuses `--fresh` combined with `--author source` or `--author-model <m>` (exit 1, no request sent) with `--fresh authors no handoff document; drop --author/--author-model`.

### Non-functional

- **NFR-1** Existing handoff, summary and plain forks behave exactly as before: the parent-link test's `it.each(['handoff','plain','summary'])` and the hold tests stay green unchanged.
- **NFR-2** `src/lib/overdeck/conversation-forks.ts` stays at or below 1000 lines (it is 973 today and has no allowlist row; `scripts/lint-file-size.sh` CEILING=1000). Never raise an allowlist cap.
- **NFR-3** No new circular import (`npm run lint:circular`). New modules are leaves.
- **NFR-4** `packages/contracts/src/composer-commands.generated.ts` matches the CLI registry (`npm run lint:slash-commands`).
- **NFR-5** `sync-sources/skills/pan-handoff/SKILL.md` documents `--fresh` in the same commit that registers the flag (skills ↔ CLI lockstep; `scripts/lint-skills.sh` fails on unknown flags in SKILL.md).

## Decisions

- **D1 — boolean `fresh`, not a fourth `forkMode`.** It mirrors `hold` (PAN-4499): the three `forkMode` unions (`src/lib/conversations/summary-fork.ts:38`, `conversations.ts` `ForkRequest.forkMode`, `src/cli/commands/fork-client.ts:25`, frontend `ApiForkMode` in `ForkModal.tsx` and `useConversationMutations.ts`) stay unchanged, and `parsePersistedForkRequest()` needs no change.
- **D2 — skip every source-transcript gate under fresh.** The source is only a defaults donor, so the route's session-file 400 (grep `No session file found for conversation ${conv.name}` in `conversation-forks.ts`), the pipeline's `Parent has no session file` throw, and the CLI's `No session file found` exit (`src/cli/commands/handoff.ts` lines 85–89) are all skipped when fresh.
- **D3 — skip the git-worktree gate under fresh** (grep `Handoff cwd is not inside a git repository`). That gate exists for document authoring; a plain `POST /api/conversations` has no such gate.
- **D4 — empty focus**: see FR-7.
- **D5 — lane guard is unconditional** (FR-9). A `callerKind` check cannot work: `verdictCallerFromEnv()` returns `operator` for every `conv-*` session, so a lane agent would pass as an operator. An operator who really wants a clean root conversation uses the dashboard's New conversation dialog.
- **D6 — no issue inheritance** (FR-10). The issue lists project, cwd, model and effort as the inherited defaults; an issue link is a soft lineage the operator asked to drop.
- **D7 — title rule** (FR-11). The source title is exactly the context the operator is discarding.
- **D8 — `fork_request.parentConversationName` still names the source.** It is internal recovery provenance, not lineage, and nothing in the dashboard renders it. `recoverStuckForks()` still requires the source row to exist; a fresh start whose source row was deleted mid-restart fails as it does today (acceptable edge).
- **D9 — skill overrides and launch context inherit as today.** `mergedSkillOverrides` (source map + `--skill/--pack`) and `conversationLaunchContext(conv)` are unchanged; the issue says these flags "work as they do now".
- **D10 — server ignores `handoffAuthor`/`handoffAuthorModel`/`handoffAuthorHarness` when fresh** (format validation of `handoffAuthorModel` still runs; the source-authored-harness 400 is skipped). The CLI refuses explicit author flags (FR-15); the dashboard never sends them under fresh.
- **D11 — make room by extraction first.** Move the source-session resolution helpers out of `conversation-forks.ts` into a new leaf module before adding fresh logic (WI-1), so NFR-2 holds with margin.
