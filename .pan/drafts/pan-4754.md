# PAN-4754 — Operator decision dialog: render markdown, show context separately, tighten `pan ask` guidance

**Issue:** [PAN-4754](https://github.com/eltmon/overdeck/issues/4754)

## Glossary

- **Operator decision** — a blocking question a work agent raises with `pan ask <ISSUE> "<question>" --option <a> --option <b> [--context <text>]` (PAN-4383). It is stored as an `operator.decision-requested` entry in the issue's pipeline journal. `src/lib/cloister/operator-decision.ts` derives whether it is still open.
- **Pending question** — the `AskUserQuestion`-shaped payload the dashboard shows. It comes from two sources: a real `AskUserQuestion` tool call in an agent transcript, and an open operator decision mapped by `operatorDecisionAsPendingQuestion`. On the wire it is `pendingAskUserQuestion` on agent snapshots and conversation rows.
- **Decision dialog** — `src/dashboard/frontend/src/components/AskUserQuestionDialog.tsx`, the modal that shows a pending question with option buttons and a custom-answer box.
- **Context** — the `--context` text of a `pan ask` call. It holds the facts and findings behind the question.
- **`ChatMarkdown`** — `src/dashboard/frontend/src/components/chat/ChatMarkdown.tsx`, the dashboard's shared markdown renderer (react-markdown + remark-gfm, themed, code highlighting). The sibling modal `PlanApprovalDialog.tsx` already uses it.

## Problem

The decision dialog shows every decision as one run-on paragraph. Example: the PAN-4638 live-check decision held four numbered points, a "Which do you want?" question and a separate `--context` block. The dialog showed all of it as one paragraph, and the first option label was a full sentence.

There are two causes.

1. **The dialog drops structure.** `operatorDecisionAsPendingQuestion` joins question and context into one string:

   `src/lib/cloister/operator-decision.ts` (around line 181, grep `d.context ?`):
   ```ts
   question: d.context ? `${d.question}\n\n${d.context}` : d.question,
   ```

   The dialog renders that string in a plain paragraph, which collapses newlines and does not parse markdown:

   `src/dashboard/frontend/src/components/AskUserQuestionDialog.tsx` (around line 159):
   ```tsx
   <p className="text-sm font-medium text-foreground">{q.question}</p>
   ```

2. **The work-agent prompt encourages one run-on string.** `roles/work.md`, section `## Ask the operator with \`pan ask\`` (around line 106), shows:
   ```bash
   pan ask <ISSUE-ID> "<the question, with the facts the operator needs>" --option "<choice 1>" --option "<choice 2>" --context "<what you already tried>"
   ```
   This tells the agent to put every fact into one quoted shell argument. `--option` takes a label only, so agents also put the consequence of each choice into the label.

## Requirements

- **FR-1** The decision dialog renders each question's text as GitHub-flavored markdown: paragraphs, bullet and numbered lists, bold and inline code display as such.
- **FR-2** An operator decision's context travels as its own optional `context` field on the pending question. It is no longer concatenated into `question`.
- **FR-3** The decision dialog shows `context`, when present, as a separate block under the question text, in muted styling, also rendered as markdown.
- **FR-4** Surfaces other than the decision dialog keep working. Compact surfaces (Needs-you strip, mobile Needs-you, decisions panel, simple question card, push notifications, TTS, the `awaitingInput` prompt) show the question text only. This is intended: those surfaces are summaries, and the context was trailing noise there.
- **FR-5** `roles/work.md` tells agents to write a short question, put facts in `--context` as a markdown bullet list with real newlines, keep option labels short, and explain each option's consequence in the context. It includes one worked example.
- **FR-6** `docs/PIPELINE-GATES.md` section `## Operator decisions (PAN-4383)` documents the formatting contract (markdown question, separate context block).
- **NFR-1** No change to the `pan ask` CLI flags or the pipeline journal entry format. Existing open decisions keep rendering.
- **NFR-2** No new dependencies. Reuse `ChatMarkdown`.

## Decisions

- **Reuse `ChatMarkdown`, not a bare `ReactMarkdown`.** `PlanApprovalDialog.tsx` (around line 115) renders `<ChatMarkdown text={pending.plan} cwd={undefined} />` inside a modal of the same design. Using it keeps theming, links and code styling consistent across dashboard modals. `UpdateDialog.tsx` uses a bare `ReactMarkdown` with `prose-invert`, which ignores the light theme, so do not copy that.
- **Add `context` to the shared wire schema** rather than a decision-only side channel. The field is optional, so transcript `AskUserQuestion` payloads (which never have it) are unaffected.
- **Do not add an option-description syntax to `--option`.** That would change the CLI contract (NFR-1). Consequences go in the context instead.
- **Option buttons stay as they are.** The existing `opt.description` span is unchanged.

### 3. Rewrite the `pan ask` guidance in `roles/work.md` (FR-5)

File: `roles/work.md`, section `## Ask the operator with \`pan ask\`` (around lines 106–114).

Replace the code block and add a formatting paragraph before the existing "`pan ask` writes the request…" paragraph. Keep that paragraph unchanged.

New content:

````markdown
When you need an operator decision before you can continue (a blocking question), raise it with:

```bash
pan ask <ISSUE-ID> "<one or two sentences: the decision you need>" \
  --option "<short label>" --option "<short label>" \
  --context $'- <fact the operator needs>\n- <what you already tried>\n- **<label>:** <what happens if they pick it>'
```

The dashboard renders the question and the context as markdown, in separate blocks. Write them so the operator can scan them:

- The question states the decision in one or two plain sentences. Do not put facts in it.
- `--context` carries the facts as a short bullet list, one fact per bullet. Use real newlines: `$'...\n...'` in bash, or build the text in a variable first.
- Option labels are a few words each. Explain each option's consequence in the context, under a bullet that starts with the label in bold.

Example:

```bash
pan ask PAN-4638 "The live check cannot run until this branch is merged and released. How should I close out?" \
  --option "Close out now, rig + Fly" --option "Close out now, rig only" --option "Hold until after merge" \
  --context $'- Both the rig and a Fly VM install the published npm version, so neither can run this branch.\n- The rig answers over SSH but has no Overdeck installed.\n- **Close out now, rig + Fly:** I cancel the two live-check criteria and run pan done; the check runs after release.\n- **Close out now, rig only:** same, but skip Fly.\n- **Hold until after merge:** the issue stays open and you run the check yourself.'
```
````

The commit that edits `roles/work.md` must carry a `Prompt-Change:` trailer (for example `Prompt-Change: pan ask guidance asks for a short question, bulleted markdown context and short option labels`). Without it, `lint:prompt-trailer` fails.
