# PAN-4723 — createWorkspace tests read the host's real free disk space

**Issue:** [PAN-4723](https://github.com/eltmon/overdeck/issues/4723)
**Type:** test fix (no production code change)

## Summary

The issue blamed an unmocked `git` call. That hypothesis is wrong. The CI failure came from
`checkDiskFloor()`, which `createWorkspace()` calls before any git work. It reads the real free
space of the test's `mkdtempSync` directory with `statfs`. The CI runner's `/tmp` had 9.3 GiB free,
below the 10 GiB floor, so `createWorkspace()` returned `success: false` with
`Only 9.3 GiB free on the filesystem holding /tmp/pan-1990-create-row-…`. The failure is
intermittent because free disk space differs from one GitHub runner to the next and hovers near
10 GiB; a rerun lands on a runner with more space and passes.

The fix mocks `disk-floor.js` in the three test files that drive the real `createWorkspace()`, and
adds one regression test that proves the disk-floor refusal path deterministically.

## Glossary

- **Disk floor** — the 10 GiB minimum free space `createWorkspace()` requires before it creates a
  worktree. Constant `DISK_SAFETY_FLOOR_BYTES` in `src/lib/disk-floor.ts`, line 5.
- **`checkDiskFloor(path, read?)`** — `src/lib/disk-floor.ts`, line 18. Returns `null` when free
  space is at or above the floor, or an error string (`Only X GiB free on the filesystem holding
  <path>; workspace creation needs at least 10.0 GiB. …`) when below. Its default reader
  `readAvailableBytes` (line 7) calls `statfs` from `node:fs/promises`.
- **The exec mock** — every `createWorkspace` test file mocks `util.promisify` to return
  `mockExecAsync`, so every `promisify(exec)` and `promisify(execFile)` (all git, npm, docker calls)
  goes through the mock. `statfs` is a plain promise API, never promisified, so it is NOT covered.
- **Low-disk repro** — run a test file with `TMPDIR` pointing at a filesystem that has less than
  10 GiB free. On this machine `/run/user/1000` is a 6.3 GiB tmpfs and reproduces the CI failure
  exactly.

## Root cause (verified)

1. **Evidence from CI.** Run 41317624589, attempt 1, job `test-shard (1/4)`:
   `create-workspace-row.test.ts (10 tests | 9 failed)`, each failure carrying
   `Received: "Only 9.3 GiB free on the filesystem holding /tmp/pan-1990-create-row-…"`. The issue
   text said one test failed; the log shows nine. Vitest's CI `retry: 1` (`vitest.config.ts`,
   line 44) retried each and they failed again, because the disk state did not change between
   attempts.
2. **The call.** `src/lib/workspace-manager/create.ts`, line 202:
   `const diskError = await checkDiskFloor(projectConfig.path);` — runs before the workspace row
   and before any git call, with `projectConfig.path` = the test's `mkdtempSync(tmpdir())` dir.
3. **Local reproduction (done during planning).** With `TMPDIR=/run/user/1000/pan4723`
   (6.3 GiB free):
   - `create-workspace-row.test.ts`: 9 failed | 1 passed — the exact CI signature.
   - `create-resume-setup.test.ts`: 4 failed.
   - `tests/lib/workspace-manager.test.ts`: 1 failed (`createWorkspace > stages metadata-only …`).
   With the default `/tmp` (53 GB free) all pass. So a 50-run loop on a roomy disk proves nothing;
   the discriminating check is the low-disk repro.
4. **The `git branch --show-current` line is unrelated.** It is the `console.error('Error
   capturing git state:', error)` at `src/lib/cloister/handoff-context.ts`, line 166, printed while
   `src/lib/cloister/__tests__/continue-readers-plan-home.test.ts` (which calls
   `captureHandoffContext` on a non-git dir) ran — a different file, which passed. The error is
   caught and logged by design.
5. **No other exposure.** Planning ran 21 candidate files that reach `createWorkspace`
   transitively (pr-workspace-adoption, planning spawn, swarm, agent-spawner, issues-start-planning,
   xbrief full-spec, autonomous-work-dispatch, workspace-registry-integration) under the low-disk
   repro: 240/240 passed. `checkDiskFloor` has exactly one production caller (`create.ts:202`).

## Decisions

- **D1 — Fix the tests, not the code.** The production check is correct: it guards real project
  paths against ENOSPC (PAN-1674). The defect is unit tests that mock every subprocess but let one
  real-filesystem probe through. No change to `src/`.
- **D2 — Mock the module, not `statfs`.** `checkDiskFloor`'s default reader is bound inside
  `disk-floor.ts`, so mocking the exported `readAvailableBytes` would not affect it. Mock
  `checkDiskFloor` itself with `vi.mock` of `disk-floor.js`, keeping the other exports via
  `importOriginal`.
- **D3 — Use a hoisted `vi.fn` in `create-workspace-row.test.ts`** so one new test can make it
  return an error string, giving the disk-floor gate inside `createWorkspace()` deterministic
  coverage. The other two files use the same hoisted shape for consistency.
- **D4 — No retries, skips, `.only`, or `skipIf`.** The test-skip gate rejects them and the issue
  forbids them.
