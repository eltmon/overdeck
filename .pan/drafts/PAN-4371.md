## Glossary

- **Jev**: TypeSafe AI's "System One" judgment model. It returns typed answers (Noul = probability a
  statement is true; Choice = one label plus per-label probabilities and a `confidence`). It never
  generates text.
- **Jev client**: `src/lib/jev/client.ts` `assess(featureKey, state, questions, opts)` from PAN-4369. It
  never throws. It returns `{status:'answered', answers, model, usage}`, `{status:'unavailable', reason}`
  (a gate said no, no request sent) or `{status:'failed', reason, message}`.
- **Feature gate**: `resolveJevForFeature('jevTurnEndAssessment', config)` in `src/lib/jev/config.ts`. It
  is synchronous and pure. It fails when the background-AI toggle is off, `background_ai.cheap_mode` is
  on, there is no `jev:` block, `jev.model` is unset, or there is no key.
- **Turn end**: the moment an agent stops producing output and yields to a human. Today it is visible
  only as the runtime state `idle`.
- **`agentTurnEnded`**: the pending-input kind that `computeAgentEnrichment` adds for an idle
  *interactive* agent (plan role, or an agent id starting `conv-`). The UI label is "Answer the agent".
- **Interactive agent**: `isInteractiveRoleAgent(agentId, role)` in `src/lib/agent-enrichment.ts`
  (line 172): `role === 'plan' || agentId.startsWith('conv-')`.
- **Turn-end assessment**: this issue's new derived value
  `{ kind, confidence, needsAnswer, model }`. `kind` is one of `asks_operator`, `reports_complete`,
  `reports_blocked`, `progress_update`, `other`.
- **Turn-end store**: this issue's new in-process map from agent id to the latest assessment outcome,
  keyed by the transcript mtime it was computed for. It is never persisted.
- **Peek**: a synchronous read of the turn-end store. It never does I/O and never calls Jev.
- **Schedule**: a fire-and-forget start of the transcript read plus Jev call. It returns `void`
  immediately; the result lands in the store for the next peek.
- **Enrichment poll**: `pollOnce` in `src/dashboard/server/services/agent-enrichment-service.ts`, run
  every 10 s (`POLL_INTERVAL_MS = 10_000`).
- **Parked row / idle-running orbit**: `ParkedRow` in `src/lib/parked/resolver.ts`. The `idle-running`
  orbit is a live, non-exempt agent idle for more than 6 h (`IDLE_RUNNING_THRESHOLD_MS`).
- **Stall sweeper**: `runStallSweeperPatrol` in `src/lib/cloister/stall-sweeper.ts`. Observability only by
  operator directive: it emits `sweep.*` events and activity sentences and never acts.
- **Sweep recommendation evidence**: the second argument of the sweeper's local `recommend()` helper. It
  is spread into the `sweep.recommendation` event payload.
- **Needs-you row**: one `DecisionRow` in `src/dashboard/frontend/src/components/DecisionsPanel.tsx`. Its
  badge text comes from `describePendingInput(decision.kinds)`.
- **Bare turn end**: `isBareTurnEnd(agent)` in `src/dashboard/frontend/src/lib/simple/derive.ts` (line 99):
  the agent's only pending kind is `agentTurnEnded`, read as "it stopped talking, it did not ask".

## Findings from planning (read before implementing)

1. **The stall sweeper has no caller on main.** PAN-3917 W4 (commit `94255f055fe`, "cut deacon.ts to
   deacon-lite + hygiene-scheduler") removed the only call site of `runStallSweeperPatrol`. Today the name
   appears only in `src/lib/cloister/config.ts` (the patrol-budget exempt list) and in tests. So the
   sweeper half of this issue is proven by tests with injected dependencies but has no live emitter.
   Rescheduling the sweeper is **out of scope** (it changes what runs, same category as PRD item 1b) and
   needs its own operator-signed issue.
2. **`ParkedRow` has `details`, not `evidence`.** The issue says rows "carry the assessment in `evidence`".
   The resolver writes it to `row.details.turnEnd` and appends a sentence to `row.parkReason`. The sweeper
   copies it into the recommendation evidence. The sweeper's activity sentence already interpolates
   `row.parkReason` (stall-sweeper.ts line 246), so the sentence carries it with no extra formatting code.
3. **Live resolver callers:** `/api/velocity` (dashboard process, counts rows only) and `pan parked` (a
   fresh CLI process, so its in-process store is always cold). `/api/parked`
   (`src/dashboard/server/routes/parked.ts`) builds its own rows and does not call the resolver. So with the
   strict peek-and-schedule design, the work-agent assessment has no visible live surface until the sweeper
   is rescheduled. This is accepted (auto-decision AD-2) and documented.
4. **Conversations do not get `agentTurnEnded` from the REST door.** `getConversationsPendingInputFeed`
   (`src/lib/overdeck/conversation-reads.ts` line 374) emits only AUQ, plan, pane-choice and permission rows.
   `agentTurnEnded` exists only on agent rows produced by `computeAgentEnrichment`. `conv-*` agent state
   directories do exist under `~/.overdeck/agents/`, so the enrichment path is reachable for them.
5. **CI runs only listed frontend tests.** Root `package.json` `test:frontend-subset` does not include
   `DecisionsPanel.test.tsx`, `simple-derive.test.ts`, `pendingInput.test.ts` or `useDecisions.test.ts`. The
   frontend items add the files they change to that list, or their tests never run on CI.

## Requirements

### Functional

- **FR-1** A question set for turn-end classification lives in `src/lib/jev/questions.ts`: a Choice
  `turn_end_kind` with the five kinds, each with a one-sentence criterion, and a Noul
  `needs_operator_answer`. `QUESTION_SET_VERSION` goes from `1` to `2`.
- **FR-2** `assessTurnEnd(input)` in `src/lib/jev/turn-end.ts` sends state `{ role, last_message }` with
  `last_message` tail-trimmed to at most `TURN_END_STATE_MAX_CHARS` (6000) characters, through
  `assess('jevTurnEndAssessment', …)`, and maps the answer to a `TurnEndAssessment`.
- **FR-3** An assessment whose Choice confidence is below `TURN_END_MIN_CONFIDENCE` is never shown
  anywhere. The server drops it; the frontend never sees it.
- **FR-4** `readLastAssistantMessage(agentId, workspace)` in `src/lib/agents/last-assistant-message.ts`
  returns the last non-empty assistant message (`id` + text) for claude-code JSONL and codex rollouts by
  reusing the existing parsers, and `{ ok:false, reason:'unsupported-harness' }` for every other
  transcript kind.
- **FR-5** A turn-end store (`src/lib/jev/turn-end-store.ts`) offers a synchronous `peek`, a
  fire-and-forget `schedule`, `clear` and a test `reset`. Entries are keyed by agent id and transcript mtime.
- **FR-6** `computeAgentEnrichment` accepts an optional turn-end assessment and attaches it as
  `turnEndAssessment` only when `pendingInputKinds` contains `agentTurnEnded`. Otherwise the key is absent.
- **FR-7** The enrichment poll peeks before computing, schedules after computing when the result contains
  `agentTurnEnded`, and never awaits the scheduled work. The event payload, the change diff and the reap
  event carry the new field.
- **FR-8** `@overdeck/contracts` `AgentSnapshot` and `AgentEnrichmentChangedEvent.payload` gain an optional
  `turnEndAssessment` struct. The reducer copies it on `agent.enrichment_changed` and deletes it with the
  other pending-input fields on the stop wipe.
- **FR-9** The Needs-you row badge reads "Asked you a question" (`asks_operator`), "Reported done"
  (`reports_complete`) or "Blocked" (`reports_blocked`) in place of "Answer the agent". For
  `progress_update`, `other` or no assessment it stays "Answer the agent".
- **FR-10** `isBareTurnEnd` returns `false` when the agent's `turnEndAssessment.kind` is `asks_operator`.
  Every other case returns exactly what it returns today.
- **FR-11** `resolveParkedPopulation` attaches the assessment to `idle-running` rows: `details.turnEnd`
  and a sentence `; last message reads as: <label> (<confidence to 2 dp>)` appended to `parkReason`. The
  default lookup is peek-and-schedule and never awaits.
- **FR-12** The stall sweeper's `idle-running` recommendation evidence includes `turnEnd` (the summary
  string). The sweeper still performs no spawn, stop, message or kill.
- **FR-13** An eval `evals/jev-turn-end.eval.ts` over a fixture set of at least 40 sanitized, labeled real
  final messages reports per-class precision and recall at the chosen threshold.

### Non-functional

- **NFR-1** With the feature gate closed (no `jev:` block, toggle off, cheap mode on, no model, no key),
  there is no transcript read, no Jev call, and enrichment output and events are byte-identical to today
  (the `turnEndAssessment` key is absent, not `undefined`).
- **NFR-2** The enrichment poll never awaits Jev or the transcript read that feeds it.
- **NFR-3** Nothing is persisted: no agent row, `sessions.json`, journal, tracker or file write. A restart
  starts cold.
- **NFR-4** No hardcoded model. The model is whatever `jev.model` resolves to; this issue adds no model
  literal outside tests.
- **NFR-5** Only the agent role and the last assistant message tail (≤ 6000 chars) leave the host.
- **NFR-6** Nothing in this issue changes a nudge, spawn, stop, message or kill. deacon-lite is untouched.
- **NFR-7** Fixtures contain no private project names, absolute home paths, or secrets.

## Decisions (made here; do not re-litigate)

- **D-1 Thresholds.** `TURN_END_MIN_CONFIDENCE = 0.7`; `TURN_END_NEEDS_ANSWER_THRESHOLD = 0.5`
  (`needsAnswer = noul >= 0.5`). The eval may change them; any change bumps `QUESTION_SET_VERSION`.
- **D-2 Where the threshold lives.** Only the server applies it (`toTurnEndView` in `turn-end.ts`). The
  frontend treats a present `turnEndAssessment` as confident. The frontend never imports `src/lib/jev`.
- **D-3 Store key.** Agent id plus the transcript mtime the poll already computes (`getAgentJsonlMtime`).
  A peek with a different mtime returns `undefined`, so a new turn end never shows the previous message's
  label. Every outcome (answered above threshold, answered below threshold, failed, unassessed) is stored
  for its mtime, so one message costs at most one attempt. A new mtime triggers a new attempt; the
  content-keyed memo inside `assess()` makes an unchanged message free.
- **D-4 Gate first.** `schedule` and `peek` call `isTurnEndAssessmentEnabled()` (a wrapper over
  `resolveJevForFeature(...).ok` with `loadConfigSync().config`, which is mtime-cached) before anything
  else. A closed gate means no transcript read (NFR-1).
- **D-5 Contract type.** `kind` is `Schema.String` in contracts (append-only event store: a literal union
  would make a future rename fail replay decode). The lib type `TurnEndKind` is the literal union.
- **D-6 Labels.** Only three kinds get a new label (FR-9). `progress_update` and `other` keep "Answer the
  agent", because the issue names only three labels.
- **D-7 Grouping unchanged.** `agentTurnEnded` stays in `BLOCKING_KINDS`; sort order and the blocking
  group do not change with the assessment.
- **D-8 Resolver purity.** `classifyParked` stays pure: its input `ParkedSignals` gains an optional
  `turnEndByAgentId` map. `resolveParkedPopulation` fills it through an injectable
  `ResolveParkedOptions.turnEndFor(agent)` whose default peeks and schedules.
- **D-9 Summary text.** `formatTurnEndSummary(view)` returns `last message reads as: <label> (<0.84>)`
  where label is `asked the operator` / `done` / `blocked` / `progress update` / `other`. Tests match on
  the word `blocked`.

export interface TurnEndAssessment { kind: TurnEndKind; confidence: number; needsAnswer: boolean; model: string }
export interface TurnEndInput { agentId: string; role: string; harness: string; lastAssistantText: string; messageId: string }
export type TurnEndOutcome =

export function buildTurnEndState(role: string, text: string): { role: string; last_message: string }

### WI-3 Turn-end store: peek, schedule, clear (FR-5, NFR-1, NFR-2, NFR-3)

Files: new `src/lib/jev/turn-end-store.ts`, new `src/lib/jev/__tests__/turn-end-store.test.ts`.

```ts
export interface TurnEndStoreDeps {
  isEnabled?: () => boolean;                                      // default isTurnEndAssessmentEnabled
  resolveWorkspace?: (agentId: string) => Promise<string | null>; // default getAgentWorkspace from ../agent-enrichment.js
  readLastAssistantMessage?: typeof readLastAssistantMessage;
  assessTurnEnd?: typeof assessTurnEnd;
}
export function isTurnEndAssessmentEnabled(): boolean
export function peekTurnEndAssessment(agentId: string, transcriptMtime: number | null): TurnEndAssessment | undefined
export function scheduleTurnEndAssessment(input: { agentId: string; role: string; transcriptMtime: number | null }, deps?: TurnEndStoreDeps): void
export function clearTurnEndAssessment(agentId: string): void
export function resetTurnEndStore(): void
export const TURN_END_STORE_MAX_ENTRIES = 256;
```

Behavior:
- `peek`: gate closed or `transcriptMtime === null` → `undefined`. Entry missing or `entry.mtime !== transcriptMtime`
  → `undefined`. Otherwise the entry's `view` (already threshold-filtered; may be `undefined`).
- `schedule`: returns `void` synchronously in every case. Gate closed, mtime null, an entry for the same mtime,
  or an in-flight run for the same `agentId:mtime` → return. Otherwise record in-flight and start
  `void (async () => { … })()` that: resolves the workspace; reads the last assistant message; on
  `ok:false` stores `{mtime, view: undefined, reason}`; else calls `assessTurnEnd` and stores
  `{mtime, messageId, view: toTurnEndView(outcome)}`. `finally` removes the in-flight mark. Any rejection
  is swallowed (`.catch(() => {})`).
- The store is a `Map` capped at `TURN_END_STORE_MAX_ENTRIES`, oldest insertion evicted.
- The default `resolveWorkspace` must be `getAgentWorkspace` (`src/lib/agent-enrichment.ts` line 206), the
  same door `getAgentJsonlMtime` uses to produce the mtime the poll passes in. A state-row-only lookup would
  miss agents whose workspace comes from the pane cwd or issue-prefix fallback, store `no-transcript` for
  their mtime, and never assess that message. `agent-enrichment.ts` imports only the *type* from
  `./jev/turn-end.js`, so this runtime import creates no cycle; confirm with `npm run lint:circular`.
- Nothing is written to disk.

Tests (all with injected deps, no network):
- gate closed → `readLastAssistantMessage` is never called and `peek` returns `undefined`;
- after `schedule` + a flushed microtask queue (`await vi.waitFor(...)` or awaiting the dep's promise), `peek`
  with the same mtime returns the view, and with a different mtime returns `undefined`;
- a below-threshold outcome stores a marker: `peek` returns `undefined` and a second `schedule` for the same
  mtime does not call `assessTurnEnd` again;
- `schedule` with a `readLastAssistantMessage` that never resolves returns synchronously, and a second
  `schedule` for the same mtime makes no second call (in-flight dedupe);
- `clearTurnEndAssessment` removes the entry.

### WI-11 Labeled, sanitized fixtures and pure metrics (FR-13, NFR-7)

Fixture shape: `[{ "name": string, "role": "plan"|"work"|"review"|"test"|"conversation", "text": string, "label": TurnEndKind }]`.

Collection procedure (the implementing agent does this by hand):
1. Take final assistant messages from local transcripts under `~/.claude/projects/*/*.jsonl` (read-only;
   never modify or delete these files) and codex rollouts, preferring overdeck project sessions.
2. Label each with one of the five kinds. At least 40 total, and at least 8 each of `asks_operator`,
   `reports_complete`, `reports_blocked`, `progress_update`.
3. Sanitize: replace absolute paths (`/home/...`, `/Users/...`) with `<path>`; replace any private project
   name or issue prefix other than `PAN-` (`myn`, `mind your now`, `krux`, `tindra`, `auricle`, `MIN-`,
   `AUR-`, `KRUX-`, `TIN-`, `ELV-`) with `<project>` / `<ISSUE>`; drop (do not redact) any message that
   contains a token-shaped string or an email address.
4. Trim each text to its last 6000 characters.

`jev-turn-end-metrics.ts` (pure, no I/O):

```ts
export interface TurnEndFixture { name: string; role: string; text: string; label: TurnEndKind }
export interface ClassMetrics { precision: number | null; recall: number | null; support: number }
export function perClassMetrics(rows: ReadonlyArray<{ label: TurnEndKind; predicted: TurnEndKind | null }>): Record<TurnEndKind, ClassMetrics>
export const FIXTURE_LEAK_PATTERNS: ReadonlyArray<{ name: string; pattern: RegExp }> // home paths, private names/prefixes, xoxb-/ghp_/github_pat_/sk-/AKIA, emails
export function findFixtureLeaks(fixtures: ReadonlyArray<TurnEndFixture>): string[] // "<name>: <pattern name>"
```

`predicted: null` means below threshold (counts against recall, not precision). Precision is `null` when
nothing was predicted for the class.

string containing `/home/alice/x` and one containing `MIN-12`; and the committed fixture, loaded with
