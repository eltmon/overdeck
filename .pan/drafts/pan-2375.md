# PAN-2375 — Tame beads/records auto-commit churn on main

**Issue:** [PAN-2375](https://github.com/eltmon/overdeck/issues/2375) — chore(state-plane): tame beads/records auto-commit churn on main — debounce, batch, and auto-push policy
**Part of:** CI/CD master epic + the state-plane commit-policy cluster.
**Governing policy:** [`docs/STATE-PLANE-COMMIT-POLICY.md`](../../docs/STATE-PLANE-COMMIT-POLICY.md) (adopted 2026-07-06, operator-directed). Fixes MUST land against those rules — notably the ONE shared `isStatePlaneOnlyDiff` predicate (rules 3 & 6).

---

## Glossary

- **State-plane paths** (per policy glossary): `.pan/records/`, `.pan/continues/`, `.pan/continue.json`, `.pan/specs/`, `.beads/`, `.pan/test/`, `.pan/review/`, `.pan/feedback/`. Everything else is **source**. (`.pan/drafts/` is human narrative, NOT state-plane.)
- **Auto-commit**: the fire-and-forget git-commit primitive in [`src/lib/pan-dir/auto-commit.ts`](../../src/lib/pan-dir/auto-commit.ts) that pipeline writers call after mutating a `.pan/`/`.beads/` file. Main-only, debounced, best-effort.
- **Flush window**: the coalescing interval. Every state write inside one window collapses into ONE commit at the window's end.
- **Divergence**: local `main` ahead of / behind `origin/main`, measured by `git rev-list --count`.
- **ff-only push**: `git push origin main` that succeeds only if it fast-forwards origin (no history rewrite on the remote).
- **`isStatePlaneOnlyDiff(baseSha, tipSha, repoRoot)`**: the shared predicate (rule 6) — returns true when every path changed between two commits is a state-plane path. New in this issue; the whole cluster consumes it.

---

## Problem

`auto-commit.ts` commits beads/records state to LOCAL `main` at high frequency — 64 `chore(beads)`/`chore(state)` commits in 24h (one every ~2 min under load). The current debounce is `DEBOUNCE_MS = 2_000` (2s) and, critically, **resets the timer on every write** (`queueAutoCommit` calls `clearTimeout` + reschedule on each add — [`auto-commit.ts:181-186`](../../src/lib/pan-dir/auto-commit.ts)), so any 2-second gap between bursts triggers a flush. There is **no push policy** at all. Consequences:

- Local `main` sits perpetually ahead of origin (ahead-10 observed twice on 2026-07-06), so `pan reload` deploys stale code (PAN-2095 root condition) and disk audits mislead operators (a wasted audit cycle on 2026-07-04).
- Every human push must rebase over dozens of noise commits.
- History pollution: ~60+ noise commits/day on `main`.

An earlier batching fix (the `chore(state): batch update N pan/beads file(s)` subject at [`auto-commit.ts`](../../src/lib/pan-dir/auto-commit.ts) `doCommit`) reduced per-file commits but changed neither cadence nor push policy.

## Requirements

- **FR-1** — A canonical state-plane module exports `STATE_PLANE_PATHS` and `isStatePlaneOnlyDiff(baseSha, tipSha, repoRoot)` (policy rule 6: one path list, one place). No gate re-implements the list.
- **FR-2** — A CI-enforced guard fails the build if the state-plane path list is duplicated outside the canonical module (policy rule 6, CI-guarded).
- **FR-3** — Auto-commit coalesces to **at most one commit per flush window** (default 10 min); writes inside a window do NOT reset the window (fixed-window, not reset-on-write). Window overridable via `OVERDECK_STATE_FLUSH_WINDOW_MS`.
- **FR-4** — Any pending auto-commit flushes on process shutdown (SIGTERM/SIGINT/SIGHUP) so the long window never strands committed-worthy state as a dirty tree.
- **FR-5** — After a successful flush commit on `main`, auto-commit pushes `origin main` ff-only. On non-ff rejection: fetch `origin/main`; if the working tree is clean AND `isStatePlaneOnlyDiff(origin/main, main, repoRoot)` is true, rebase the local state-only commits onto `origin/main` and retry the push **once**; otherwise surface loudly and do not force. Push disable via `OVERDECK_STATE_AUTOPUSH=0`.
- **FR-6** — `pan doctor` reports, per project, whether local `main` is ahead/behind `origin/main`, warning when ahead > N (default 1) or behind > 0.
- **FR-7** — The deacon health surface reports the same ahead/behind divergence so silent divergence is visible on the dashboard.
- **NFR-1** — Push and rebase are best-effort: a failure logs and never throws back to the calling pipeline writer (auto-commit's existing contract).
- **NFR-2** — The auto-rebase in FR-5 never rewrites `main` history when the working tree is dirty or any ahead-commit touches a non-state path (respects the shared-worktree-HEAD hazard already documented in `doCommit`).
- **NFR-3** — Tests for debounce-window (FR-3) and push-retry (FR-5) use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` — never real waits (repo rule).

## Proposal

1. **Foundation (FR-1/FR-2):** create `src/lib/state-plane.ts` with `STATE_PLANE_PATHS` (verbatim from the policy glossary) and `isStatePlaneOnlyDiff`. Add a single-source guard test.
2. **Debounce (FR-3):** in `queueAutoCommit`, stop resetting the timer on subsequent adds within a window — keep the original timer set on first queue. Raise the window constant to 10 min (env-overridable). This converts reset-on-write debounce → fixed-window coalescing: exactly one commit per window.
3. **Shutdown flush (FR-4):** export `flushAllPendingAutoCommits()` and call it from `handleShutdownSignal` in [`src/dashboard/server/main.ts`](../../src/dashboard/server/main.ts) and the deacon stop path.
4. **Push (FR-5):** extend `doCommit` — after a successful commit on `main`, attempt ff-only push; on rejection apply the safe rebase-retry-once described in FR-5/NFR-2, consuming `isStatePlaneOnlyDiff`.
5. **Divergence guard (FR-6/FR-7):** a small `getMainDivergence(repoPath)` → `{ahead, behind}`; a `pan doctor` check and a deacon health-surface field both consume it.

## Q&A / Auto-decisions (this was a `--auto` session)

- **AD-1 — Does PAN-2375 create the shared `isStatePlaneOnlyDiff` or consume a sibling's?** *Create it here.* The predicate does not exist yet (only a comment at `deacon.ts:1522`), and FR-5's rebase-safety needs it. Policy rule 6 forbids parallel copies, so this issue lands the canonical module; sibling cluster issues (PAN-2417/2167/2406/2386) consume it. **Hazard:** if a sibling merges the module first, the work agent MUST consume it, not add a second copy.
- **AD-2 — Flush window length?** *Default 10 min* (issue example), overridable via `OVERDECK_STATE_FLUSH_WINDOW_MS`. Balances history cleanliness against how long state may sit uncommitted; shutdown flush (FR-4) bounds the worst case.
- **AD-3 — Divergence warn threshold N?** *ahead > 1, behind > 0.* One in-flight window's commit is normal; two-plus means push is failing. Behind > 0 on local `main` is always worth flagging (drives stale `pan reload`).
- **AD-4 — Deliverable 4: move state commits off `main` entirely (dedicated state branch/worktree)?** *REJECTED for this issue* — recorded as NonGoal. The two-door model already supports a dedicated infra repo via `pan_records.repo` + `repoRoot` (PAN-1908), and debounce + push policy fully address the stated symptoms (stale reload, ahead-N divergence, history pollution) without a migration that would touch every state reader (`findSpecByIssue`, `readWorkspacePlan`, close-out, verify-merged). A branch/worktree migration is a larger, separately-plannable change.
- **AD-5 — Where do config knobs live?** *Module constants + env overrides* (matches the existing `DEBOUNCE_MS` style at `auto-commit.ts:38`); no `config-yaml.ts` plumbing, keeping the change surgical.

## NonGoals

- Moving state commits off the `main` working branch onto a dedicated state branch/worktree (AD-4).
- Changing which paths the pipeline treats as durable state, or gitignoring any state-plane path (policy rule 1 forbids it).
- Altering source-code review/merge behavior — this loosens nothing about code review (policy rule 4).
- Refactoring the other cluster gates (PAN-2417/2167/2406/2386) to consume the predicate — this issue only *creates* it; sibling issues adopt it.
