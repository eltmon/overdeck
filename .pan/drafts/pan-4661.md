# PAN-4661 — Phone PWA: read-only pipeline board tab at `/m/pipeline`

**Issue:** [PAN-4661](https://github.com/eltmon/overdeck/issues/4661) · **Parent PRD:** `.pan/drafts/pan-2355.md` (the `/m` phone shell, landed in #4693) · **Planned:** 2026-11-01, `pan plan --auto`, base `4fe47986f04`.

## Summary

The phone shell at `/m` (PAN-2355) has two tabs, **Needs you** and **Conversations**. This issue adds a third tab, **Pipeline**, at `/m/pipeline`. It lists the active issues grouped by phase (Ship, Review, Work, Plan, Ready), each row with the issue ID, the title and a **Needs you** mark when the operator must act. Tapping a row opens a full-screen, read-only issue sheet at `/m/pipeline?issue=<id>`. The tab reads only the Zustand store that `EventRouter` already fills from the `/ws/rpc` snapshot. It adds no API route, no HTTP request, no drag and drop and no issue actions.

## Glossary

- **Phone shell** — `MobileApp` (`src/dashboard/frontend/src/components/mobile/MobileApp.tsx`), the standalone, lazy-loaded React tree that `App.tsx` renders for `/m`. It mounts `EventRouter` and has no desktop chrome.
- **PAN-2355 D-3** — PAN-2355's routing decision (`MobileApp.tsx` header, lines 4-10): deep-link *ids* are query parameters, never path segments, because the static server 404s an unknown path that has a file extension (`src/dashboard/server/server.ts`, the `if (pathService.extname(urlPath))` branch in `staticRouteLayer`), so an id with a dot in a segment would break.
- **Store** — `useDashboardStore` (`src/dashboard/frontend/src/lib/store.ts`). Its issue slices come from the shared reducer in `packages/contracts/src/event-reducers.ts`: `issuesRaw` (from `snapshot.issues`), `derivedIssueStateByIssueId` (from `snapshot.derivedIssueStates`) and `agentsById` (from `snapshot.agents`).
- **Selectors** — `selectIssues` (`store.ts`, `export const selectIssues = (s: DashboardState): unknown[] => s.issuesRaw`), `selectAgents` (`store.ts`, `export const selectAgents = memoizeArraySelector<…>`), and the plain slice `state.derivedIssueStateByIssueId`. The desktop `PipelineView` reads exactly these three.
- **Derived issue state** — `DerivedIssueState` (`@overdeck/contracts`): `{ issueId, state, attention?, pr? }`. `state` is one of the nine derived names; `attention` may be `'needs-you'`, `'stuck'` or `'api-error'`; `pr` is `{ url, number, reviewState, checks, mergeable }`.
- **Phase** — `PipelineIssuePhase` (`src/dashboard/frontend/src/lib/pipeline-state.ts`, line 7): `'ship' | 'review' | 'work' | 'plan' | 'ready' | 'todo'`, computed by `getPipelineIssuePhase(derived, issue)`.
- **Board phases** — the five phases the desktop pipeline renders: `['ship', 'review', 'work', 'plan', 'ready']` (`PipelineView.tsx` line 20, `const PHASES`). `todo` (raw backlog) is never shown (PAN-1966).
- **Active issue** — an issue that is not outside the pipeline (`isOutsidePipeline(issue) === false`) and whose phase is a board phase. This is the same set the desktop "Active issues" tile counts.
- **Needs-you mark** — a small amber badge reading `Needs you` on a row whose issue needs the operator (FR-4).
- **`hasSnapshot`** — `useConnectionState((s) => s.hasSnapshot)` (`src/dashboard/frontend/src/lib/connectionState.ts`): `true` once a cached snapshot loaded or a bootstrap succeeded. Before that, `issuesRaw` is `[]`.
- **Snapshot cache seeding** — the Playwright pattern from `src/dashboard/frontend/tests/pan-4523-river-bands.spec.ts`: an `addInitScript` writes `localStorage['pan-snapshot-cache-v1'] = { data: <DashboardSnapshot>, timestamp }`; `EventRouter` renders it synchronously on mount; `page.routeWebSocket(/\/ws\/rpc/, (ws) => ws.close())` keeps a real (empty) snapshot from overwriting it.

## Decisions

- **D-4661-1 URL scheme.** The tab lives at the path `/m/pipeline`, as the issue title and "done when" require. The issue sheet is the query parameter `/m/pipeline?issue=<encodeURIComponent(id)>`. This keeps PAN-2355 D-3 intact: it forbids *ids* in path segments, and `pipeline` is a fixed segment without a dot or extension. The other tabs keep their existing URLs (`/m`, `/m?subject=`, `/m?tab=conversations`, `/m?conversation=`). `/m?tab=pipeline` is **not** added; there is one canonical URL per screen.
- **D-4661-2 `App.tsx` matches exactly.** The branch becomes `terminalPath === '/m' || terminalPath === '/m/' || terminalPath === '/m/pipeline' || terminalPath === '/m/pipeline/'`. A prefix match (`startsWith('/m/')`) is rejected: it would silently capture future desktop routes under `/m/`.
- **D-4661-3 Route precedence.** `readMobileRoute(search, pathname = '/m')`: when `pathname` is `/m/pipeline` or `/m/pipeline/`, the route is `{ tab: 'pipeline', issueId: params.get('issue') || null, subjectId: null, conversationId: null }` and every other query parameter is ignored. Otherwise the existing rules apply unchanged, with `issueId: null`. The second parameter defaults to `'/m'` so existing one-argument calls keep their meaning.
- **D-4661-4 Same data, same rules as desktop.** The tab reads `selectIssues`, `state.derivedIssueStateByIssueId` and `selectAgents`, and groups with helpers that the desktop `PipelineView` also uses after W-1 moves them into `lib/pipeline-state.ts`. There is one definition of "active issue", one phase order and one sort (priority, then `updatedAt` descending). No second copy of `isOutsidePipeline` is written.
- **D-4661-5 Phases shown.** The five board phases in desktop order (Ship, Review, Work, Plan, Ready). A phase with no issues is not rendered on the phone (the screen is short; the desktop shows empty headers because it has filters). No phase filter chips, project filters, metric strip or cost column.
- **D-4661-6 Needs-you predicate.** A row is marked when `issueNeedsYou(derived) || hasActualPendingQuestion(agent)`, where `agent` is the first agent for the issue from `firstAgentByIssueId(agents)` (W-1). The derived `attention` covers blocked panes and open `pan ask` decisions server-side; the agent check is the same one desktop uses for its `INPUT` badge. Both are store reads.
- **D-4661-7 Mark styling.** The mark is a status badge with the style guide's tint formula: `<span className="shrink-0 rounded-sm border px-1.5 py-0.5 text-[11px] font-medium badge-bg-warning badge-border-warning text-warning-foreground">Needs you</span>`. Amber means "a human must act" (style guide, Signal colors). It is the only colored element in a row; the ID and all other row text are `text-muted-foreground` or `text-foreground`. No `rounded-full`, no bold or semibold.
- **D-4661-8 Loading versus empty.** When `hasSnapshot` is `false`, the list shows `Loading pipeline…` and the sheet shows `Loading issue…`. When `hasSnapshot` is `true` and no issue is active, the list shows `No active issues.` This prevents a blank or falsely empty first paint.
- **D-4661-9 The sheet is full screen.** Like an open conversation, an open issue hides the shell header and the tab bar (`fullScreen = (tab === 'conversations' && conversationId !== null) || (tab === 'pipeline' && issueId !== null)`). The sheet has its own **Back** button, which pushes `/m/pipeline`. The browser back button also returns to the list, because opening the sheet pushed a history entry.
- **D-4661-10 Sheet fields.** In order: a header row with **Back** and the issue identifier; the title as an `h2`; then a `<dl>` with **Phase** (board phase label, e.g. `Review`), **State** (the raw derived state, e.g. `in-review`, or `—` when there is none), **Needs you** row only when D-4661-6 is true (shows the D-4661-7 badge), **Project** (`issue.project.name`, omitted when absent), **Pull request** (`#<number> · checks <checks> · <reviewState>`, omitted when `derived.pr` is absent), **Agent** (`<role> · <model> · <status>` from the first agent, omitted when none), **Labels** (comma-separated, neutral text, omitted when empty), **Updated** (`formatRelativeTime(issue.updatedAt, now)`). Last, an **Open in tracker** link to `issue.url` (`target="_blank" rel="noreferrer"`), omitted when `issue.url` is empty. The sheet finds the issue in `issuesRaw` by case-insensitive identifier; it shows an issue even if it has left the pipeline. When no issue matches and `hasSnapshot` is `true`, it shows `This issue is not in the pipeline.` with the Back button.
- **D-4661-11 What the sheet does not reuse.** It does not render `IssueActionMenu`, `AutoMergeToggle`, `IssuePeek` (a 380 px hover popover), the desktop `IssueRow` or the issue drawer. They carry actions or desktop-only layout.
- **D-4661-12 Tap targets and layout.** Every `button` and `a` in the tab and sheet has `min-h-11` (44 px) and, when not full-width, `min-w-11`. Row titles use `line-clamp-2 break-words`; the sheet title and values use `break-words`. Nothing may widen the 390 px page (`window.scrollX` stays `0`).
- **D-4661-13 Component contracts (fixed here so W-2 can be written against them before reading W-3 and W-4).**
  - `export function MobilePipeline({ onOpen }: { onOpen: (issueId: string) => void }): JSX.Element` in `components/mobile/MobilePipeline.tsx`.
  - `export function MobileIssueSheet({ issueId, onBack }: { issueId: string; onBack: () => void }): JSX.Element` in `components/mobile/MobileIssueSheet.tsx`.
  - Neither component reads or writes the URL; the shell owns navigation.
- **D-4661-14 Playwright proof uses snapshot-cache seeding.** The isolated dashboard has no tracker, so `issuesRaw` is empty there. The new spec seeds a `DashboardSnapshot` through `pan-snapshot-cache-v1` and closes `/ws/rpc`, exactly as `pan-4523-river-bands.spec.ts` does. No production test hook (`window.__store` or similar) is added.
