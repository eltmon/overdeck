# PAN-5459 — quality-gate-admission tests: bound every wait by real time, and gate every fixed drive on a signal

**Issue:** [PAN-5459](https://github.com/eltmon/overdeck/issues/5459)
**Follows:** PAN-5394 (`.pan/drafts/PAN-5394.md`, merged in `68fb06e6f10`)
**Scope:** one file, `tests/unit/lib/cloister/quality-gate-admission.test.ts`. Test-only. No `src/` change.

## Glossary

- **Admission loop** — `acquireQualityGateAdmission()` in `src/lib/cloister/quality-gate-admission.ts` (line 612). Each poll pass does real filesystem work (list tickets, list slot owners, read JSON, write the ticket) and then calls `sleep(pollMs)`. In these tests `sleep` is a fake timer.
- **Turn** — one iteration of the test's drive loop: a 1 ms real `setTimeout` (captured as `nativeSetTimeout` before fake timers start), one real `setImmediate`, then `vi.runOnlyPendingTimersAsync()`.
- **`drive(attempts, done?)`** — today's helper (test file, line 68). It runs up to `attempts` turns and stops early when `done()` is true. It never asserts.
- **`driveUntil(done)`** — today's helper (line 80): `drive(100, done)` then `expect(done()).toBe(true)`.
- **`driveUntilResolved(promise)`** — line 98: `driveUntil(() => settled)`.
- **Attempt cap** — the turn count a condition wait gives up after. Today: 100 in `driveUntil`, 200 at the PAN-5394 sites, 40 at line 692.
- **Fixed drive** — `await drive(N)` with no predicate. It runs N turns and returns, whatever state the loop is in.
- **Negative window** — a fixed drive followed by an assertion that something has *not* happened (`expect(settled()).toBe(false)`). On a slow host it passes without testing anything, because the loop may not have run a single poll.
- **Ordering wait** — a fixed drive that must let the loop reach a state *before* the test changes an input (the clock, a mock). If the loop is slower than the drive, the input change lands first and the test fails or proves nothing.
- **Wall-clock budget** — a limit on real elapsed time, read from `Date.now` captured before `vi.useFakeTimers()`. Fake time does not count against it.
- **`onWaiting`** — the admission dep the loop calls when it reports a wait reason. It reports the first reason, then a changed reason at most once per 60 s of `now()` (`QUALITY_GATE_WAIT_REPORT_MS`, source line 74). Most tests pin `now`, so **only a waiter's first reason is a reliable signal**.

## Problem

Main CI went red at `cbb8ebefb9e` (run 43969539204, test-shard 2/4, attempt 1) in this file. The issue says the cause is fixed `drive(N)` calls that PAN-5394 did not convert. The CI log disagrees. Every failing frame is a **condition wait that ran out of attempts**:

| Test | Failing frame | What ran out |
| --- | --- | --- |
| memory admission > waits on memory until MemAvailable recovers | line 573 → `driveUntilResolved` → `driveUntil` line 82 | 100-turn cap |
| memory admission > re-checks memory after the settle … (try 1) | line 700 → `driveUntil` line 82 | 100-turn cap |
| memory admission > re-checks memory after the settle … (retry) | line 693, `expected 2 to be greater than 2` | 40-turn cap at line 692 |
| head-of-line fairness > never admits a head alone below the hard reserve … | line 919 → `driveUntil` line 82 | 100-turn cap |

A turn yields only about 1 ms of real time. One admission needs about 15–30 sequential filesystem operations on the libuv threadpool. On a loaded runner those take longer than 100 turns. Raising the cap to 200 only halves the odds.

**Reproduced locally** (planning session, 2026-11-16): with 48 busy-loop processes on a 24-CPU host and `OVERDECK_GATE_ADMISSION=0`, the file failed 1 of 3 runs, at line 693 (40-turn cap) and at line 967 (`passes an older-version head that looks as if it fits …`). The second failure is an ordering wait. `drive(10)` at line 963 did not let the small waiter record `legacyFitSince` at clock 1 before the test set `clock = 40_000`, so the grace started at 40 000 and never expired. Idle, the file passes in about 0.6 s of test time.

So the fix has two parts:

1. **Budget.** Every condition wait gets a wall-clock budget instead of a turn count.
2. **Signals.** Every remaining fixed drive is replaced with a wait on a positive signal that the loop reached the state under test. This matters for the ordering waits, which are real races. It also matters for the negative windows, which today pass without testing anything on a slow host.

## Decisions

- **D1 — Wall-clock budget, not a bigger attempt cap.** The turn count consumed per filesystem operation grows with host load, so no fixed count is safe. A condition wait now loops until `done()` is true or `DRIVE_BUDGET_MS = 4_000` ms of real time has passed. A passing wait returns on the first turn where the condition holds, so fast hosts pay nothing extra. This is the issue's "generous cap", measured in real time.
- **D2 — Raise the file's test timeout to 30 s** with `vi.setConfig({ testTimeout: 30_000 })` at module top level. `vitest.config.ts` line 73 sets 5 000 ms. Without the raise, a longer budget turns the assertion failure into a timeout. The same pattern is in `tests/unit/lib/cloister/feedback-target.test.ts` (line 66) and `tests/unit/lib/lifecycle/workflows.test.ts` (line 11).
- **D3 — Read real time from `Date.now` captured at module load.** `vi.useFakeTimers({ doNotFake: ['setImmediate'] })` (test file, line 119) fakes `Date` and `performance`. The capture sits beside `nativeSetTimeout`, for the same reason.
- **D4 — `drive` keeps a non-asserting form; there is no fixed-count form.** PAN-5394 D1 used `drive(200, predicate)` rather than `driveUntil` so that the assertion after it fails with the real argument diff. That stays: `drive(done)` never asserts. After this change no caller needs a fixed count, so the `attempts` parameter is removed. This **retires PAN-5394 NFR-1** ("The `drive`, `driveUntil` and `driveUntilResolved` helpers do not change") on purpose. The helpers were the failing point.
- **D5 — Signal choice per site.** Use `onWaiting`'s *first* call when the waiter has not reported yet. Use a call counter (`samplePressure.mock.calls`, a memory-read counter) when the waiter may already have reported. Use the waiter ticket on disk (`blockedSince`, the new `waitKind`) when the test needs to know what the loop *persisted*. Never wait on a second `onWaiting` report: the 60 s report throttle (Glossary) suppresses it under a pinned clock.
- **D6 — Site F reorders the clock advance.** Today `never admits a head alone below the hard reserve …` sets `clock = 5_000` right after starting the head. The head reads `createdAt` and `memoryBlockedSince` only after `await mkdir`, so they are usually 5 000, not 1. The head is then never "past the bound" when the small gate arrives, and the test never checks the past-the-bound case. Waiting for `blockedSince(rootDir, 'vitest') === 1` before `clock = 5_000` matches its sibling at line 838 and makes the test check what its name says.
- **D7 — No changelog entry.** The change is test-only and not user-facing (`changelog.d/README.md` covers user-facing changes).

```ts
// Captured before vi.useFakeTimers() so it always schedules real wall-clock time.
const nativeSetTimeout = globalThis.setTimeout

async function drive(attempts: number, done: () => boolean = () => false): Promise<void> {
  for (let attempt = 0; attempt < attempts && !done(); attempt++) {
    // The admission loop awaits real fs promises that resolve on the libuv
    // threadpool; on a loaded host a bare setImmediate spin exhausts every
    // attempt before a single fs op completes. A 1ms real yield per attempt
    // gives the threadpool wall-clock time without unfaking tested delays.
    await new Promise((resolve) => nativeSetTimeout(resolve, 1))
    await realSetImmediate()
    await vi.runOnlyPendingTimersAsync()
  }
}

  expect(done()).toBe(true)
}
```

```ts
// Captured before vi.useFakeTimers() so they always schedule and read real wall-clock time.
const nativeSetTimeout = globalThis.setTimeout
const nativeNow = Date.now

/**
 * PAN-5459: real time one condition wait may take. A turn count is not safe: on a
 * loaded runner each fs op in the admission loop eats more turns. Fake time does
 * not count against it, and a wait that passes returns on its first true turn.
 */
const DRIVE_BUDGET_MS = 4_000

// Several condition waits per test can each use most of DRIVE_BUDGET_MS on a loaded runner.
vi.setConfig({ testTimeout: 30_000 })

/** One turn of the admission loop. */
async function turn(): Promise<void> {
  // The admission loop awaits real fs promises that resolve on the libuv
  // threadpool; on a loaded host a bare setImmediate spin exhausts every
  // attempt before a single fs op completes. A 1ms real yield per turn
  // gives the threadpool wall-clock time without unfaking tested delays.
  await new Promise((resolve) => nativeSetTimeout(resolve, 1))
  await realSetImmediate()
  await vi.runOnlyPendingTimersAsync()
}

/** Drive the admission loop until done() holds or DRIVE_BUDGET_MS of real time passes. Never asserts. */
async function drive(done: () => boolean): Promise<void> {
  const deadline = nativeNow() + DRIVE_BUDGET_MS
  while (!done() && nativeNow() < deadline) await turn()
}

/** PAN-5459 transition only: work item 7 deletes this once no fixed drive remains. */
async function driveTurns(turns: number): Promise<void> {
  for (let index = 0; index < turns; index++) await turn()
}

async function driveUntil(done: () => boolean): Promise<void> {
  await drive(done)
  expect(done(), `condition not met within ${DRIVE_BUDGET_MS} ms of real time`).toBe(true)
}
```

### Work item 2 — N slots: wait on pressure samples (FR-5; sites A, B)

Test `keeps a pressured second request waiting until slot 0 frees and pressure clears`, lines 235–257. `samplePressure` is the test's own `vi.fn().mockResolvedValue(high)`. While pressure is high, the second request samples it once per poll pass, because slot 1 is free and it has no `footprintKey`.

Before:

```ts

      expect(secondResolved).toBe(false)
      expect(existsSync(join(rootDir, 'slot-1.json'))).toBe(false)

      await first.release()
```

After:

```ts

      await driveUntil(() => samplePressure.mock.calls.length > 0)
      expect(secondResolved).toBe(false)
      expect(existsSync(join(rootDir, 'slot-1.json'))).toBe(false)

      await first.release()
      // A pass that listed slot 0 as held may still be in flight. Two more samples mean
      // the later pass started after the release, so B sees slot 0 free once pressure clears.
      const samplesAtRelease = samplePressure.mock.calls.length
      await driveUntil(() => samplePressure.mock.calls.length >= samplesAtRelease + 2)
      samplePressure.mockResolvedValue(low)
```

**Why two samples:** the first sample after the release may come from a pass that listed the slots before the release. If B saw low pressure in that pass, it would take slot 1 and `expect(second.slot).toBe(0)` would fail. The second sample comes from a pass that started after the first one slept, so after the release.

```bash
  all_alive() { for pid in $pids; do kill -0 "$pid" 2>/dev/null || return 1; done; }
  for r in $(seq 1 10); do
    all_alive || { echo "load processes died before run $r"; exit 1; }
    OVERDECK_GATE_ADMISSION=0 timeout 140 npx vitest run tests/unit/lib/cloister/quality-gate-admission.test.ts || exit 1
    all_alive || { echo "load processes died during run $r"; exit 1; }
  done
'
```

`OVERDECK_GATE_ADMISSION=0` skips the local Vitest admission queue (`tests/vitest-cpu-admission.ts`, line 83). Without it, the queue holds the run while the CPU is pressured, and the run times out before it starts.

The load processes have no time limit. Each one loops only while the driver shell (`$driver`) is alive, so they stay up through all ten runs and exit if the driver is killed, even by SIGKILL. The script checks that every load process is alive before and after each run, and fails if one died. The `EXIT` trap kills them when the script ends. So exit 0 means all ten runs passed under load.
