## 1. Summary

Child B moved the explorer into the right dock and made every dock open path use `openBeside`, so a file already opens next to the chat. What is still missing is in the code pane itself:

1. The header shows a raw path and a lone "Changes" button. It needs a breadcrumb with the human root name, a **File / Changes** switch and **Reveal in files**.
2. Nothing marks the lines the conversation beside the file changed.
3. The edit-workspace flow (Create PR, Discard, PR state, Merge) lives in a banner in the dock's Files tab. A code pane shows only a one-line note. The flow must live in an **editor bar** at the top of every code pane on a project or edit-workspace root, and follow the PR through to merged.
4. The Create PR dialog shows neither the files nor the question "How should it land?".
5. A code tab whose edit workspace was merged or discarded shows the generic "Couldn't open file".
6. The first edit on the main checkout remounts the code pane on the new edit root and the cursor jumps to line 1.

This child fixes all six. Two small server routes supply data the client does not have today: the line numbers a conversation changed in one file (gutter marks), and the files with +/− an edit workspace will land (bar and Create PR).

## 2. Glossary

- **Code pane** — a Stage tab of `paneType: 'code'` that shows one file of an explorer root in Monaco: `explorer/code/CodePane.tsx`, mounted by `explorer/code/CodePaneSlot.tsx` with `key = rootId + '\u0000' + path`, so a root change remounts it.
- **Explorer root / root id** — `project:<key>` (primary checkout), `issue:<ID>` (feature workspace), `workspace:<id>` (a scratch edit workspace). Parsed by `parseRootId` in `explorer/explorer-rpc.ts`.
- **Project root** — a `project:<key>` root. Saves never write it: the first save calls `ensureEditRoot` (`explorer/edit/edit-workspace-switch.ts`), which creates or reuses an edit workspace and moves every pane and draft onto it (`switchRoot`).
- **Edit workspace / edit root** — a git worktree on `scratch/edit-<MMDD-HHMM>` that receives the operator's hand edits (PAN-5191). Its root id is `workspace:<id>`.
- **Edit-workspace status** — `GET /api/explorer/edit-workspaces/:workspaceId` → `EditWorkspaceStatus` (`packages/contracts/src/explorer.ts`, search `export interface EditWorkspaceStatus`): workspace info, the PR with its merge verdict (`canMerge`, `reason`), `unpushedCommits`, `prSupport`, `pipelineSupport`. Client hook `useEditWorkspaceStatus` in `explorer/edit/edit-workspace-http.ts`.
- **Editor bar** — the new one-line bar `explorer/edit/EditorBar.tsx` under a code pane's header. It replaces the project note (`PROJECT_EDIT_NOTE` in `CodePane.tsx`) and `EditWorkspaceNote`, and takes over every action of `EditWorkspaceBanner`.
- **Landed note** — what the editor bar shows on the project root right after a merge, a pipeline send or a discard moved the panes back to main (`leaveEditWorkspace`). Client state in `edit-workspace-store.ts`, not persisted.
- **Scoped conversation (of a code pane)** — the conversation in the first other layout leaf of the deck that is a conversation agent pane. It is the same rule the dock uses for a code pane (`dock/dockScope.ts`, rule 5, search `Changes follows a conversation leaf beside it`).
- **Gutter mark** — a Monaco whole-line decoration with `linesDecorationsClassName: 'code-changed-line'`: a 3 px bar in `var(--primary)` left of the line text.
- **Repo path / root path** — a conversation's changes use paths relative to its git repo (`ConversationChanges.repoRoot`); the explorer uses paths relative to the root folder. `dock/changes-model.ts` `toRootPath` maps repo → root.
- **Stale tab** — a code pane whose root no longer resolves: the server answers `ROOT_NOT_FOUND`.
- **What will land** — every file that differs between the edit workspace's working tree (untracked files included) and its merge base with `origin/<default branch>`; Create PR commits all of it with `git add -A` (`commitAll`, `src/dashboard/server/services/explorer/edit-workspace-git.ts`).
- **NFR-6 screenshots** — parent NFR-6: Playwright screenshots at 1920×1000, light and dark, from an isolated dashboard seeded with the shared workflow fixture (`scripts/dev/seed-workflow-fixture.ts`).

## 4. Decisions

- **C-D1 WI-C1 is an audit plus the header.** B already routes every dock open through `openBeside` (§3). This child changes the one remaining call (`onOpenRenamed`) and pins the dock paths with a test; it does not rewrite them. Chat path chips are child D2's (parent FR-4).
- **C-D2 Gutter marks come from a new server route that uses `git blame`.** `GET /api/conversations/:name/changes/lines?file=<repo path>` returns the 1-based working-tree line numbers this conversation changed in that file. A line is marked when `git blame --porcelain` (working tree) attributes it to one of the conversation's commits, or when it is uncommitted and (the file's `attribution` is `'file'`) or (its trimmed text is in the conversation's `writtenLines` for the file). This is the only way to get line numbers in the current file's terms; commit hunks carry line numbers as of their own commit. On the fixture it marks `docs/shared.md` lines 21–24 and not 25–26.
  - **Implementation checkpoint:** if `git blame --porcelain` on the working tree fails for a file the conversation changed (a new untracked file, or a file deleted from the working tree), the fallback is: untracked file present in `uncommitted` → every non-empty line counts as uncommitted and follows the rule above; deleted file → `lines: []`.
- **C-D3 A code pane learns its scoped conversation from the Stage.** `StageDeckContextValue` gains `conversationBeside?: (paneId: string) => Conversation | null`: the first layout leaf other than `paneId` that is an agent pane bound to a known conversation. Not split ⇒ null ⇒ no marks. The code pane never reads the dock (the dock's changed paths are empty while the dock is closed).
- **C-D4 Marks show only when the file maps into the conversation's repo.** The pane maps its root path to a repo path with the new `toRepoPath(repoRoot, rootAbs, rootPath)` (inverse of `toRootPath`). A null mapping (the pane's root is another worktree, such as an edit workspace) ⇒ no marks. Marks refresh when the conversation's changes refetch, and never while the pane's draft is dirty (Monaco moves existing decorations with the edits).
- **C-D5 +/− for the bar and Create PR come from a new route.** `GET /api/explorer/edit-workspaces/:workspaceId/changes` returns **what will land** (glossary) with per-file +/−, plus the uncommitted paths. Base = `git merge-base HEAD refs/remotes/origin/<defaultBranch>`; when that fails, `HEAD`. It never calls `gh`, so the client may refetch it on every watch batch of the edit root.
- **C-D6 PR state advances by itself, slowly, and only while GitHub is still deciding.** `useEditWorkspaceStatus` refetches every 15 000 ms (`PR_STATUS_REFETCH_MS`) while an editor bar for that workspace is mounted **and** `shouldPollPr(pr)` is true: `pr.state === 'OPEN' && !pr.isDraft && !pr.canMerge && (pr.mergeable === 'UNKNOWN' || pr.mergeStateStatus === 'UNKNOWN' || pr.mergeStateStatus === 'BLOCKED')`. A draft, conflicting (`DIRTY`/`CONFLICTING`) or out-of-date (`BEHIND`) PR cannot advance by itself, so it is not polled; **Refresh** reads it again. Polling stops when the PR merges, closes or becomes mergeable. react-query shares one query per workspace. Each read calls `gh`, so 15 s (not the 5 s diff cadence) is the floor; parent NFR-4 allows ≥ 5 s.
- **C-D7 Dropped mockup details, each replaced.** The mockup's "checks running (3 of 9 done)" has no data (`EditWorkspacePr` has no check counts): the bar shows the merge verdict's `reason` in words. The mockup's "Merged into main as `a91c03e`" has no sha (`mergeEditWorkspace` returns none): the note names the PR number. "saved 1 s ago" becomes a state word: **Saving…** while a draft of the root is dirty, **All edits saved** otherwise. No contract change for these.
- **C-D8 Create PR keeps every function it has today.** The mockup omits the Body field, the "Commit and push" mode for an open PR, and the per-choice disabled reasons. All three stay: Body becomes **Description (optional)** under the title; push mode keeps its title and button and lists only the uncommitted files; an unavailable choice is a disabled radio with its reason under it.
- **C-D9 The editor bar shows on project and edit-workspace roots only.** Issue roots and other workspace roots (a workspace that is not an edit workspace, `NOT_AN_EDIT_WORKSPACE`) show no bar, as today. Viewer-only files (images, PDFs, archives…) keep today's rendering with no header and no bar.
- **C-D10 The Files tab's banner becomes the same editor bar.** `EditWorkspaceBanner.tsx` and `PrStatusRow.tsx` are deleted. On an edit root the Files tab mounts `<EditorBar rootId deckKey />` (no `paneId`, so no **Close tab**), the same component the code panes show. This keeps **Create PR** and **Discard…** reachable when no text file is open: a tree action (delete, rename, upload) on main creates an edit workspace through `ensureEditRoot` without any code pane, and a viewer-only or deleted file has no bar (C-D9), so the Files tab is the one place that always has it (parent D-13, D-14). **New edit workspace** moves into the Files root menu (parent §7). Every test in `EditWorkspaceBanner.test.tsx` and `PrStatusRow.test.tsx` is ported to `EditorBar.test.tsx` (the test-skip gate counts deleted tests).
- **C-D11 Landed notes live in `edit-workspace-store`, keyed by project key.** `landed: Record<projectKey, LandedNote>`, set by the bar before it calls `leaveEditWorkspace`, cleared by **Dismiss**, by Start editing, and when a new edit workspace starts for that project. Not persisted: a reload shows the plain read-only bar.
- **C-D12 Cursor, scroll and focus survive a root switch.** A module registry `explorer/code/view-state-registry.ts` holds the live editor of each mounted code pane by draft key. `switchRoot` and `leaveEditWorkspace` call `carryViewStates(fromRootId, toRootId)` before they retarget panes; it saves `saveViewState()` and `hasTextFocus()` of every live editor on the old root under the new draft key. The remounted pane restores the view state and focuses the editor if it had focus. An open Changes (diff) view closes on the remount (today's behavior); the pane registers the diff's modified editor while the diff is open, so its cursor lands in the plain editor.
- **C-D13 Stale-tab wording follows the root kind.** `workspace:` → "This edit workspace was merged or discarded."; `issue:` → "This issue's workspace no longer exists."; `project:` → "This project is no longer registered on this machine." Buttons: **Open on main** (workspace and issue roots; it retargets the pane to `project:<key>` of the deck's registered project, found with `findRegisteredProject(useRootContext().projects, deckKey)`; disabled with the title "This deck has no registered project" when none) and **Close tab**. One helper `isRootNotFound(error)` checks both error classes.
- **C-D13b A stale state also comes from the bar.** When the edit-workspace status query **or** the changes query (WI-5, which refetches on every watch batch of the root) of a mounted bar fails with `ROOT_NOT_FOUND`, the pane shows the same stale state, so a workspace removed elsewhere (another tab, the CLI) does not leave a live-looking editor.
- **C-D2b The lines route is cached.** `/changes` refetches every 5 s while a conversation works, and the client's lines query key follows it, so the route caches its answer per (conversation, file) keyed by `git rev-parse HEAD`, the file's `mtimeMs` and size (or "missing"), and the transcript file's size and `mtimeMs` — the same stamps `fullResult` in `conversation-changes.ts` uses — with at most 128 entries (oldest dropped). An unchanged second call spawns no `git blame`.
- **C-D14 Server work outside the stub's file list is in scope.** The stub lists only `components/explorer/**` and `Stage/index.tsx`, but C-D2 and C-D5 need contract, `src/lib` and route changes. Children A and B, which own those files, are merged, and no open PR (PAN-5334, PAN-5335 checked) touches them.
- **C-D15 UAT reaches PR states with route stubs.** The fixture has no GitHub repository (§3). The Playwright spec uses `page.route` to answer the edit-workspace status, `/pr`, `/merge` and `/discard` calls for the PR-open, mergeable, merged and pipeline states. The real edit workspace (beginEdit, the changes route, the stale tab) runs for real. Real-GitHub runs are the epic owner's (parent D-12).
- **C-D16 `scripts/frontend-test-subset.txt` is edited by several items.** It has `merge=union`, so parallel edits do not conflict; no edge is added for it. Each item adds its own new test path in C-locale order.

## 6. Repo rules that apply (restated)

- Dashboard server runs Node 22 from `dist`; run `npm run build` before any live or Playwright check. Never `bun run` or `tsx` the server.
- No `execSync` in server-reachable code.
- Delay-based tests use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync`; never real waits (the 15 s refetch test included).
- Frontend test files must be listed in `scripts/frontend-test-subset.txt`, or CI never runs them.
- A new HTTP route needs a `tests/unit/lib/overdeck/no-loss-matrix.ts` row and a `src/dashboard/server/route-scopes.ts` row (unless it should stay `admin` by default — the edit-workspace rows are explicit `admin`); a new `/api/conversations/*` route also needs an entry in `EXPECTED_CONVERSATION_ROUTES` (`tests/unit/dashboard/server/routes/conversations-no-loss.test.ts`).
- File size ceiling 1000 lines; extract a module instead of growing a file past it; agents never raise allowlist rows.
- Style guide: Broadsheet tokens; amber = human, blue = machine, emerald = outcome; running is blue, never green.
- New source-reading tests (tests that grep source files) fail lint; assert behavior instead. Never add `skipIf`/`.only`.
- Workspaces are git worktrees: never `git checkout` another branch, never `git stash`.
- A user-facing change adds `changelog.d/pan-5290.md` (README format: `#### New` / `#### Improved` / `#### Fixed`).

## Planning Q&A

Auto mode (`pan plan --auto`): no questions were asked. Each decision a question would have settled is recorded in §4 and in the xBRIEF `autoDecisions`:

- **Q: Where do gutter line numbers come from?** Options: client-side diff of HEAD vs the buffer; commit hunks fetched per commit; a server route using `git blame`. **Chosen:** the blame route (C-D2) — the only option that is exact for both commits and the shared-file case.
- **Q: Where do +/− counts come from?** Options: read HEAD and working copy per file in the browser; a server numstat route. **Chosen:** a server route (C-D5) — one cheap call, handles untracked and binary files.
- **Q: Does PR status poll?** Options: never (today); 5 s; 15 s while blocked. **Chosen:** 15 s while open and blocked (C-D6) — FR-16 needs the state to advance and each read calls `gh`.
- **Q: Keep the Description field and push mode the mockup omits?** **Chosen:** keep both (C-D8, parent D-14 "nothing is deleted without a home").

Keeping only the sentence would leave Create PR unreachable after a tree-only edit.
- **Q: Poll every blocked PR?** **Chosen:** no; only while GitHub is still deciding (UNKNOWN or BLOCKED, not a draft) — a draft, conflicting or out-of-date PR cannot change by itself (C-D6).
