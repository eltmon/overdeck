## Glossary

- **Tailscale Funnel:** a Tailscale feature that publishes one local address on the public internet on port 443, 8443 or 10000. TLS ends in `tailscaled` on this machine. tailscaled proxies the request to `127.0.0.1:<port>`, so without a check a Funnel request looks like the local operator.
- **Funnel request:** a request that carries the header `Tailscale-Funnel-Request`. tailscaled always overwrites a client-sent copy, so the header cannot be forged through Funnel. `isTailscaleFunnelRequest(headers)` in `src/dashboard/server/routes/dashboard-auth.ts` (line 458) tests it.
- **Funnel mount:** one `tailscale funnel --set-path=<path>` entry. Funnel strips the mount path before it proxies, so the target URL repeats the path (`--set-path=/mcp http://127.0.0.1:3011/mcp`).
- **Remote request gate ("the gate"):** the global middleware `remoteRequestGateLayer` in `src/dashboard/server/remote-request-gate.ts`. Its pure decision function is `remoteGateRejection(request, channel)`. Rule 0 handles Funnel requests.
- **Public MCP switch:** the config value `mcp.public.enabled` in the operator's global `~/.overdeck/config.yaml`. Off by default. Normalized by `mergeMcpConfig` (`src/lib/config-yaml/mcp-config.ts:28`).
- **Public MCP surface:** one of the nine `METHOD path` pairs listed in FR-2. Nothing else is ever reachable through Funnel for this feature.
- **OAuth token:** an `odk_` access-token record of kind `token` that carries `oauthClientId` (W-OAUTH1). The resolved credential is `{ kind: 'token'; tokenId; scopes; …; oauthClientId?: string }` (`dashboard-auth.ts:160`).
- **Plain token:** a kind `token` record without `oauthClientId`, made by `pan token create` or Copy MCP URL. Agent tokens (W-TOK1) are also plain tokens for this feature.
- **Root credential:** the internal token (`x-overdeck-internal-token`) or the root session cookie. `resolveRequestCredential(request)?.kind` is `'internal-token'` or `'root-session'`.
- **Activity entry:** one `activity.entry` event written with `emitActivityEntry(options)` (`src/lib/activity-logger.ts:245`). It is fire-and-forget and never throws.
- **Fixed window rate limit:** a counter per key that starts at the key's first request and resets 60 s later. Over the limit, the request gets 429 with `Retry-After: <whole seconds until the window resets>`.

## Problem

Hosted bots (Grok Bot, the xAI API) run on servers the operator does not control. They cannot run the Overdeck connector (W-CONN2) and cannot join the tailnet, so they need a public HTTPS URL for `/mcp`. Today the gate's rule 0 answers 404 to every Funnel request except `POST /hooks/*` (`remote-request-gate.ts:134-136`), so `/mcp` and the OAuth endpoints are unreachable from the internet. The epic decides (D-3, D-16) that the operator can opt in to publishing exactly `/mcp` and the OAuth endpoints through Funnel, with TLS ending on this machine, OAuth-issued tokens only, a rate limit and an audit trail.

## Requirements

### Functional

- **FR-1 Off by default, global config only.** Public MCP is on only when the operator's global `~/.overdeck/config.yaml` has `mcp.public.enabled: true`. A project `.pan.yaml` or `.overdeck.yaml` can never turn it on.
- **FR-2 The gate admits exactly nine surfaces.** With the switch on, a Funnel request passes rule 0 only when its method and raw path (the URL before `?` or `#`) exactly equal one of: `POST /mcp`, `GET /.well-known/oauth-protected-resource`, `GET /.well-known/oauth-protected-resource/mcp`, `GET /.well-known/oauth-authorization-server`, `POST /oauth/mcp/register`, `GET /oauth/mcp/authorize`, `GET /oauth/mcp/authorize/status`, `POST /oauth/mcp/token`, `POST /oauth/mcp/revoke`. `POST /hooks/*` keeps working as today. Everything else from Funnel is 404, credential or not. With the switch off, all nine are 404.
- **FR-3 OAuth tokens only on public `/mcp`.** A Funnel `POST /mcp` with a token credential that has no `oauthClientId` gets 403 `{ "error": "public MCP accepts only OAuth sign-ins" }`. An OAuth token works.
- **FR-4 Rate limits.** Funnel requests on the surfaces are limited per fixed 60-s window: `POST /mcp` with an OAuth token, 60 per token id; `GET /oauth/mcp/authorize/status`, 60 per client IP; every other surface (and a `POST /mcp` without an OAuth token), 20 per client IP. Over the limit: 429 `{ "error": "rate_limited" }` with `Retry-After`.
- **FR-5 Audit.** While the switch is on, every Funnel request to a surface writes exactly one activity entry: source `dashboard`, level `info` (level `warn` for status 429), message `Public MCP <METHOD> <path> <status>`, details `JSON.stringify({ clientId })`. The path never includes the query string. No entry carries a token, a code, a body or a header value other than the OAuth client id.
- **FR-6 Operator API.** `GET /api/mcp/public` → `{ enabled, funnelCommands, funnelOffCommands, mcpUrl }`; `PUT /api/mcp/public` with `{ enabled: boolean }` saves the switch and answers the same body. Both need a root credential.
- **FR-7 Settings panel.** Settings → Anywhere has a "Public MCP for hosted bots" panel with a switch, a warning, and (when on) the three Funnel commands with Copy buttons and the public `/mcp` URL.
- **FR-8 Documentation** for every changed surface (WI-9).

### Non-functional

- **NFR-1 Fail closed.** A missing, unreadable or unparsable `config.yaml` reads as off.
- **NFR-2 No new sync child processes; no new `*Sync` function.** The flag read uses `readFileSync` once per cache fill, the same as `remote-access/config.ts`; no function name ends in `Sync`. Overdeck never runs `tailscale`.
- **NFR-3 Fake timers** for every window and TTL test (`vi.useFakeTimers()` + `vi.advanceTimersByTime[Async]()`, or the injected clock); never a real sleep (repo rule `fake-timers-for-retry-tests`).
- **NFR-4 Bounded memory.** The rate limiter tracks at most 10,000 keys; when full it drops the oldest-inserted key.
- **NFR-5 New modules under 600 lines;** no file passes its `origin/main` line count + its stated budget; `npm run lint:effect-facades` must not rise (no exported Effect wrapper around Promise or sync code).
- **NFR-6 Import graph.** The gate imports only the read side of the flag (`src/lib/mcp/public-mcp.ts`), which must not import `settings-api.ts`; the write door is a separate module. `npm run lint:circular` stays green.
- **NFR-7 Every new HTTP route** is in a top-level `src/dashboard/server/routes/` file with a `no-loss-matrix.ts` row.

## Decisions

- **D-1 The flag is read from the global file only, cached, with an invalidator** (overrides the epic's "`loadConfigSync().config.mcp.public.enabled`"). `isPublicMcpEnabled()` reads `join(getOverdeckHome(), 'config.yaml')` with `readFileSync` + `js-yaml`, folds it with `mergeMcpConfig(defaultMcpConfig(), parsed)`, caches the boolean, and returns it. `invalidatePublicMcpConfig()` clears the cache. Why: the gate is sync and per request (no stat per request); a project layer must never reach it (Fact 6); tests can point it at a temp home (Fact 7). Cost: a hand edit of `config.yaml` takes effect after the next dashboard restart or the next switch save; the docs say so.
- **D-2 Also strip `mcp.public` from the project layer.** `stripProjectSecurity` (`load.ts:80`) also removes `mcp.public` (keeping `mcp.agents`), so the merged config never shows a project-set value. Belt and braces with D-1.
- **D-3 A narrow write door, not `saveSettingsApi`** (resolves the epic's checkpoint CP-4 at plan time; its `public-mcp.json` fallback is dropped). `savePublicMcpEnabled(enabled)` lives in a new `src/lib/mcp/public-mcp-write.ts` and follows `selection-write.ts` (Fact 9), with the path `join(getOverdeckHome(), 'config.yaml')`, then calls `clearConfigCache()` and `invalidatePublicMcpConfig()`. The gate sees the new value on the next request without a restart.
- **D-4 The surface match is exact on the raw path.** The gate admits a Funnel request only when `` `${method} ${rawPath}` `` is in `PUBLIC_MCP_SURFACES`, where `rawPath = url.split(/[?#]/, 1)[0]`. No decoding, no normalization, no trailing slash. Why: the router matches the raw path, so a path that only normalizes to a surface (`/api/../mcp`, `//mcp`, `/mcp/`, `/%6Dcp`) must not pass. An absolute-form request URL (`http://host/mcp`) is not in the set, so it gets 404.
- **D-5 One global middleware does rate limiting and audit for all nine surfaces.** New `src/dashboard/server/public-mcp-funnel.ts` exports `publicMcpFunnelLayer`, merged in `makeRoutesLayer` right after `remoteRequestGateLayer`. It acts only when the request is a Funnel request, the switch is on and `publicMcpSurface(method, url)` is not null (the gate's admit condition), so it is correct in either middleware order. The OAuth-only 403 stays in `routes/mcp.ts` (it is a credential rule of `/mcp`).
- **D-6 Rate-limit keys.** Client IP = the first comma-separated entry of `x-forwarded-for`, trimmed; when absent or empty, the literal `unknown`. Keys: `token:<tokenId>` (limit 60) for a `POST /mcp` whose `resolveDashboardCredential(headers)` is a `token` credential with `oauthClientId`; `poll:<ip>` (limit 60) for `GET /oauth/mcp/authorize/status`; `ip:<ip>` (limit 20) for everything else. Why the separate poll bucket: the authorize page polls 30 times a minute for up to 10 minutes (Fact 5), so a shared 20-per-minute IP bucket would throttle every browser sign-in (overrides the epic's single 20-per-minute OAuth bucket).
- **D-7 The window starts at a key's first request,** not at a wall-clock minute boundary, so "61 requests in one minute" is deterministic in tests. `Retry-After` = `ceil((windowStart + 60_000 - now) / 1000)`, at least 1.
- **D-8 Audit only while the switch is on.** With the switch off a surface request is an ordinary Funnel 404 and writes no entry, the same as any other Funnel path; a public scanner cannot fill the activity feed while the feature is off. The audit `clientId` is `credential.oauthClientId` for `POST /mcp`, the `client_id` query parameter for `GET /oauth/mcp/authorize`, else `null`. The middleware never reads a request body. A route failure (the inner effect fails) still writes one entry with status 500, and the failure propagates unchanged.
- **D-9 Operator route.** New top-level `routes/mcp-public.ts` with `GET`/`PUT /api/mcp/public`, root-only like `mcp-oauth-admin.ts` (Fact 11), no `route-scopes.ts` row. The response field is `mcpUrl` (`triggerFunnelBaseUrl(getTrustedOrigins())` + `/mcp`, or `null`), not the epic's `baseUrl`, because it is the `/mcp` URL, not a base. A bad body (`enabled` not boolean) is 400 `{ "error": "body must be { enabled: boolean }" }`.
- **D-10 Funnel commands.** `publicMcpFunnelCommands(port = triggerDashboardPort())` returns, in order: `tailscale funnel --bg --https=8443 --set-path=/mcp http://127.0.0.1:<port>/mcp`, the same for `/.well-known` and `/oauth`. `publicMcpFunnelOffCommands()` returns `tailscale funnel --https=8443 --set-path=<mount> off` for the same three mounts. Port 8443 is `TRIGGER_FUNNEL_PORT`, shared with `/hooks`.
- **D-11 No CLI verb.** The epic names no `pan` verb for this switch. The Settings panel and `PUT /api/mcp/public` are the doors. A `pan mcp public` verb is a possible follow-up.
- **D-12 Turning the switch off does not revoke anything.** OAuth sign-ins stay valid on the tailnet and loopback; only Funnel stops answering. The panel tells the operator to run the off commands.

## Implementation checkpoint CP-10 (Funnel mounts) — operator, not the work agent

Neither Overdeck nor the work agent runs `tailscale` on the operator's host. After merge, the operator turns the switch on, runs the three commands, and checks from outside the tailnet that `curl https://<host>.<tailnet>.ts.net:8443/.well-known/oauth-authorization-server` answers the metadata JSON and that `/hooks` still works. **Fallback** if the three path mounts misbehave on that Tailscale version: mount `/` on port 10000 (`tailscale funnel --bg --https=10000 --set-path=/ http://127.0.0.1:<port>/`); the gate already 404s everything outside the nine surfaces. Switching to the fallback is a follow-up change to `PUBLIC_MCP_FUNNEL_PORT`, `publicMcpFunnelCommands` and `triggerFunnelBaseUrl`'s port (the issuer), not part of this issue.

## Hazards

- **H-1** `issuerFor` returns null over Funnel without a `.ts.net` trusted origin, so the metadata endpoints answer 400; tests that call them over Funnel must seed one, and the panel shows the trusted-address hint.
- **H-2** `emitActivityEntry` is fire-and-forget into an event store that tests do not initialize; tests inject the audit function instead of reading the store.
- **H-3** Middleware order between `remoteRequestGateLayer` and `publicMcpFunnelLayer` is not guaranteed; the middleware re-checks the gate's admit condition itself (D-5).
- **H-4** The authorize page's status poll writes one activity entry every 2 s during a sign-in (up to 300 for a 10-minute wait). Accepted for a literal audit trail (FR-5).
- **H-5** A hand edit of `config.yaml` is seen after a restart or the next switch save (D-1); documented.
- **H-6** WHATWG `Request` normalizes dot segments, so traversal tests must set the raw URL with `.modify({ url })` (WI-2).
