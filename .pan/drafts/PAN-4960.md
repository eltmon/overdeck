# PAN-4960: dashboard Account card with PKCE sign-in (Settings → Anywhere)

**Issue:** [PAN-4960](https://github.com/eltmon/overdeck/issues/4960). Part of PAN-2350. Split from PAN-4959 (the overdeck.ai account page, merged in `960453e975c`, PR #4969).
**Mode:** planned with `pan plan --auto`; every choice the issue left open is recorded under "Decisions" and in the xBRIEF `plan.autoDecisions[]`.

## Glossary

- **Account service** — the overdeck.ai Cloudflare Worker in `services/account/` (default `https://account.overdeck.ai`). It issues device tokens.
- **account.json** — `${OVERDECK_HOME}/account.json`, the machine's sign-in record (`AccountRecord` in `src/lib/account/store.ts`: `v, baseUrl, accessToken, deviceId, label, githubLogin, githubId, signedInAt`). Written atomically, mode 0600, by `writeAccount()`.
- **Device token** — the `odd_…` bearer token in `account.json`.
- **PKCE loopback flow** — the account service's browser sign-in (`docs/ACCOUNT-SERVICE.md` "Sign-in flows", `services/account/src/pkce.ts`): `GET /auth/start?redirect_uri&state&code_challenge&code_challenge_method=S256&platform&environment_id` → GitHub → the browser is redirected to `redirect_uri?code=odc_…&state=…` (or `?error=access_denied&error_description=invite_only|account_deleting|github_denied&state=…`) → the client posts `grant_type=authorization_code&code&code_verifier&redirect_uri` to `POST /oauth/token` and gets `{ access_token, token_type, device_id, label }`. Codes are single use, expire after 5 minutes and need the identical `redirect_uri` string. The service accepts a loopback `redirect_uri` with host `127.0.0.1`, `localhost` or `[::1]` on any port (`validateLoopbackRedirect`).
- **Code verifier / challenge** — PKCE (RFC 7636). Verifier: 43–128 chars of `[A-Za-z0-9._~-]` (`CODE_VERIFIER_RE`). Challenge: base64url (no padding) of SHA-256 of the verifier's ASCII bytes, 43 chars (`CODE_CHALLENGE_RE`, `s256Challenge` in `services/account/src/crypto.ts`).
- **Pending sign-in** — the server-side record `{ state, verifier, redirectUri, baseUrl, createdAt }` this issue adds. Only the dashboard server holds the verifier; the browser never sees it.
- **Callback route** — `GET /oauth/account/callback`, the loopback `redirect_uri` this dashboard registers. Outside `/api/`, so the remote request gate (`src/dashboard/server/remote-request-gate.ts`, rule 1) does not judge it; the route checks the peer itself.
- **Directory client** — `DirectoryClient` in `src/dashboard/server/services/directory-client.ts`, the machine's socket to the overdeck.ai directory. Holds `plan` and `relay` from the last `welcome` / `relay-status` frame. Re-reads `account.json` only every `ACCOUNT_CHECK_MS = 60_000`.
- **Root session** — the dashboard credential kind `root-session` (`resolveDashboardCredential` in `src/dashboard/server/routes/dashboard-auth.ts`): the browser on this machine. `internal-token` is the other root kind (CLI/server callers).
- **Trusted local request** — `isTrustedLocalRequest(request)` in `src/dashboard/server/remote-request-gate.ts` (search `export function isTrustedLocalRequest`): loopback peer, not Funnel, and (with `dashboard.require_token_mint`) no proxy forwarding header.
- **Relay status** — `RelayStatus` / `RelayStatusView` (`packages/contracts/src/connect.ts`, `connect-view.ts`): `{ month: 'YYYY-MM', bytesUsed, capBytes, stopped }`.

## Decisions

- **D-1 Callback path `/oauth/account/callback`, outside `/api/`.** It sits beside `/oauth/mcp/*`. No `REMOTE_GATE_ALLOWLIST` row is needed (gate rule 1 passes non-`/api/` paths); the route checks the peer itself: `!isLoopbackPeer(request) || hasProxyForwardingHeader(headers) || isTailscaleFunnelRequest(headers)` → 404 JSON `{ "error": "not found" }`. A real callback is a direct browser hit on `127.0.0.1:<port>` and never carries forwarding headers.
- **D-2 `redirect_uri` host is exactly `127.0.0.1`.** The default bind `0.0.0.0` is IPv4-only, so `localhost` resolving to `::1` first would fail. Port = `Number.parseInt(env.API_PORT ?? env.PORT ?? '3011', 10)` (same expression as `ServerConfigLayer`). The exact string is stored in the pending record and sent unchanged to `/oauth/token`.
- **D-3 Bind check.** If `env.HOST` is set and is not one of `0.0.0.0`, `::`, `127.0.0.1`, `localhost`, the start route answers 409 `{ "error": "This dashboard does not listen on 127.0.0.1, so it cannot receive the sign-in. Run pan account login instead." }`.
- **D-4 Start gate = root credential AND trusted local request.** `rejectUnsafeDashboardMutationRequest` first; then credential kind must be `root-session` or `internal-token` (else 403 `{ "error": "Only this machine can sign in to overdeck.ai." }`); then `isTrustedLocalRequest(request)` must be true (else 403 `{ "error": "Sign in from a browser on this machine; the sign-in returns to 127.0.0.1." }`). Reason: a Tailscale Serve browser can hold a root session when `require_token_mint` is off, but its redirect to `127.0.0.1` would land on the wrong device.
- **D-5 One pending slot.** A new start replaces the previous pending sign-in (latest wins). A callback whose state does not match the current slot gets the "expired" page and does **not** clear the slot (a wrong state must not cancel a real sign-in). A matching state clears the slot before any network call (single use, like `redeemAuthorizationCode`). Lifetime `PENDING_SIGN_IN_TTL_MS = 600_000` (the service's `auth_requests` expiry), checked lazily with injected `now()`. States compare with `timingSafeEqual` over SHA-256 digests.
- **D-6 Two-step button (no `window.open`).** Clicking **Sign in** POSTs; the card then renders an `<a href={authorizeUrl} target="_blank" rel="noreferrer">Open overdeck.ai sign-in</a>` and "Waiting for sign-in…", like `TailscaleSetupDialog`'s "Open sign-in". Reason: `window.open` after an `await` is popup-blocked.
- **D-7 Completion signal = polling.** The callback tab is a different origin (`127.0.0.1:<port>`) and cannot message the dashboard tab. The card polls `GET /api/account` every 2000 ms while `signIn.state === 'pending'`, and on window focus (TanStack default). The callback page says "You can close this tab and go back to Overdeck."
- **D-8 Plan source.** `plan` = cached `/v1/me` `entitlement.plan`; when `/v1/me` is unreachable and nothing is cached, the directory client's `status().plan`; else `null`. Cache: one entry `{ accessToken, result, fetchedAt }`, reused while `now() - fetchedAt < ME_CACHE_TTL_MS = 300_000` and the token is unchanged; cleared by a successful dashboard sign-in. `getMe` is called with a fetch wrapped in `AbortSignal.timeout(5_000)`. An `unauthorized` result sets `tokenRejected: true` (the card then offers Sign in again).
- **D-9 Relay source.** `relay` = `currentDirectoryClient()?.relayStatus() ?? null` (the last `welcome`/`relay-status`, kept across reconnects).
- **D-10 Signed-in button.** Sign in shows only when `!signedIn || tokenRejected`. Signing in again replaces `account.json` in place (same as the CLI's D-7); the old device is not revoked. **Manage account** shows only when signed in (its base URL comes from `account.json`).
- **D-11 Base URL for a new sign-in** = `resolveBaseUrl(undefined, process.env)` (`OVERDECK_ACCOUNT_URL` or the default), same as `pan account login` without `--base-url`. An invalid URL answers 400 with `AccountClientError`'s message.
- **D-12 Unreadable `account.json`.** `GET /api/account` answers `signedIn: false, accountError: <readAccount message>`; the card shows the message. The start route answers 409 with the same message (the CLI also refuses).
- **D-13 ROUTE_SCOPES.** No scope rows: `GET /api/account` stays `admin` (default) and `POST /api/account/sign-in` is root-only, matching the existing `agent-requests` pattern. A comment line is added to `ROUTE_SCOPES` naming the three routes and why they have no row. Every new route gets a `NO_LOSS_MATRIX` row. This departs from the issue's literal "each new route needs a ROUTE_SCOPES row" because a scope row on a root-only route would let a token through the gate only to hit the route's own 403.
- **D-14 Response types are local, not in `@overdeck/contracts`.** The server exports `AccountView` from `services/account-view.ts`; the frontend declares the same interface in `accountApi.ts`, the pattern `AnywhereStatus` already uses.
- **D-15 Callback page copy** (HTML, `escapeHtml` on every interpolation, headers `PAGE_HEADERS` + `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`):
  - success 200: `<title>Signed in to overdeck.ai</title>`, text "Signed in to overdeck.ai as <login>. You can close this tab and go back to Overdeck." (no login → "Signed in to overdeck.ai. You can close this tab and go back to Overdeck.")
  - failure 200: `<title>Sign-in did not finish</title>`, the failure message, then "Go back to Settings → Anywhere in Overdeck and click Sign in to try again."
  - unknown/expired state 400: `<title>Sign-in link expired</title>`, "This sign-in link expired or was already used. Go back to Settings → Anywhere in Overdeck and click Sign in to try again."
- **D-16 Failure messages** (also stored as `signIn.message` with `state: 'failed'`):
  - `error_description=invite_only` or exchange `access_denied` → "This GitHub account is not on the overdeck.ai invite list. Ask the operator to allow it."
  - `account_deleting` → "This overdeck.ai account is being deleted."
  - `github_denied` → "Sign-in was cancelled on GitHub."
  - other `error` → "overdeck.ai did not complete the sign-in (<error>)."
  - no `code` → "overdeck.ai sent no sign-in code."
  - exchange `refused` → "overdeck.ai refused the sign-in code (<error>)."
  - exchange `unreachable` → "Cannot reach <baseUrl>: <detail>"
  - `writeAccount` throws → "Signed in, but could not save account.json: <message>"
  - expired pending seen by `GET /api/account` → "The sign-in expired. Click Sign in to try again."
  Success message: "Signed in as <login>." (no login → "Signed in.").

### WI-5 Pending sign-in service (security boundary)

Files: `src/dashboard/server/services/account-sign-in.ts` (new), `src/dashboard/server/services/__tests__/account-sign-in.test.ts` (new).

1. Exports:
   ```ts
   export const PENDING_SIGN_IN_TTL_MS = 600_000;
   export const CALLBACK_PATH = '/oauth/account/callback';
   export interface AccountSignInDeps {
     env: NodeJS.ProcessEnv;
     now(): number;
     fetch: typeof fetch;
     readAccount(): Promise<AccountRecord | null>;
     writeAccount(record: AccountRecord): Promise<void>;
     environmentId(): Promise<string>;
     platform(): string | null;
     onSignedIn(): Promise<void>; // default: accountViewService().clearMeCache(); await currentDirectoryClient()?.recheckAccount()
   }
   export type BeginResult = { ok: true; authorizeUrl: string } | { ok: false; status: 400 | 409; error: string };
   export type CallbackResult =
     | { kind: 'expired' }
     | { kind: 'failed'; message: string }
     | { kind: 'succeeded'; githubLogin: string | null };
   export class AccountSignInService {
     constructor(deps: AccountSignInDeps);
     begin(): Promise<BeginResult>;
     complete(query: URLSearchParams): Promise<CallbackResult>;
     view(canSignIn: boolean): AccountSignInView;
   }
   export function accountSignInService(): AccountSignInService; // lazy singleton with defaults
   ```
2. `begin()` order: `resolveBaseUrl(undefined, env)` (throw → 400 with its message); `platform()` null → 409 with the CLI's unsupported-platform text (`This platform (<platform>-<arch>) cannot sign in to overdeck.ai; supported: linux, darwin, win32 on x64 or arm64.`); D-3 bind check → 409; `readAccount()` throws → 409 with its message; then `createPkcePair()`, `createSignInState()`, `redirectUri = \`http://127.0.0.1:${port}${CALLBACK_PATH}\``, store the pending slot `{ state, verifier, redirectUri, baseUrl, createdAt: now() }`, set the last result to pending, and return `authorizeUrl(baseUrl, { … })`.
3. `complete(query)` order (D-5, D-16): no pending, expired (`now() - createdAt >= PENDING_SIGN_IN_TTL_MS`) or state mismatch → `{ kind: 'expired' }` (expired slot is cleared; mismatch leaves the slot); match → clear the slot; `error` param → failed with the D-16 message; no `code` → failed; `exchangeAuthorizationCode(baseUrl, { code, codeVerifier, redirectUri }, { fetch })` → failure messages per D-16; ok → `getMe(baseUrl, accessToken, { fetch })`; `writeAccount({ v: 1, baseUrl, accessToken, deviceId, label, githubLogin: me.ok ? me.me.githubLogin : null, githubId: me.ok ? me.me.githubId : null, signedInAt: new Date(now()).toISOString() })` (throw → failed "Signed in, but could not save account.json: …"); `await onSignedIn()` (errors swallowed); last result → succeeded with "Signed in as <login>." Every outcome updates the last result that `view()` reports.
4. `view(canSignIn)`: pending and unexpired → `{ state: 'pending', authorizeUrl: canSignIn ? <url> : null, message: null }`; pending but expired → clears the slot and reports `failed` "The sign-in expired. Click Sign in to try again."; else the last result (`idle` initially).
5. Tests (injected `now`, fake `fetch`, temp `OVERDECK_HOME` not needed because read/write are injected): authorize URL has `redirect_uri=http://127.0.0.1:3999/oauth/account/callback` with `API_PORT=3999`, `code_challenge` equal to `s256(<stored verifier>)`, and does not contain the verifier; a second `begin()` makes the first state answer `expired`; wrong state → `expired` and the real state still completes; replayed state → `expired`; `now + 600_000` → `expired`; `error=access_denied&error_description=invite_only` → the invite message; successful exchange posts the stored verifier and the exact redirect URI, writes a record with `githubLogin` from `/v1/me`, calls `onSignedIn` once; `getMe` failure still writes the record with `githubLogin: null`; `HOST=192.168.1.5` → 409; `HOST` unset → ok; the verifier never appears in `JSON.stringify(view(true))` or in any `BeginResult`.

## Repo rules that intersect this work

- No `execSync` in dashboard-server code; all I/O async (`fs/promises`, `fetch`).
- Fake timers for any delay test; here, prefer injected `now()` so no timers are needed. The directory-client tests already use `vi.useFakeTimers(FAKE_TIMERS)`.
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>` (frontend tests run from `src/dashboard/frontend`). Never run the full `npm test` on the host.
- `npm run typecheck` excludes `*.test.ts`; check test files compile by running them.
- New HTTP route ⇒ `NO_LOSS_MATRIX` row or CI fails.
- Frontend style guide: no pill badges, no green for running/online, muted status text.
- `src/lib/account/*` imports only Node built-ins and in-repo leaf modules (NFR-2).
- Never `git stash`; never `git checkout` inside the workspace.
