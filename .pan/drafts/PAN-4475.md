## Glossary

- **Share service.** The Cloudflare Worker in `services/share/`. Rooms, lobby, admission, SDP/ICE relay, TURN credentials. It never sees content. Its landing page is `GET /s/:code`.
- **Short code.** The 8-symbol room address from `BCDFGHJKLMNPQRSTVWXZ23456789`. The issue says `<roomId>`; the only room identifier that exists is the short code, so the route is `/#/shared/<shortCode>`.
- **Host / host server.** The machine that owns the shared conversation. Its dashboard server runs `ShareManager` (`src/dashboard/server/services/share-host.ts`) and one `PeerHub` per share (`src/dashboard/server/sharing/peer-hub.ts`). The host always sends the WebRTC offer.
- **Viewer server.** The joiner's own local dashboard server. It holds the joiner's device token and opens the join socket. New in this slice: `JoinManager` in `src/dashboard/server/services/share-join.ts`.
- **Viewer browser.** The joiner's browser tab on `/#/shared/<code>`, served by the viewer server. It holds the browser `RTCPeerConnection` (`webrtc-viewer.ts`) and never sees the device token (parent D-R3-2).
- **Device token.** `odd_…`, `AccountRecord.accessToken` in `${OVERDECK_HOME}/account.json` (`src/lib/account/store.ts` line 19, `readAccount()`).
- **Join socket.** The WebSocket the viewer server opens to `GET /v1/rooms/:code/join?v=1` with `Authorization: Bearer <device token>`. Frames: `ViewerFrame` out, `ServiceToViewerFrame` in (`packages/contracts/src/sharing.ts` lines 62–75). Close codes: `ShareCloseCode` (lines 78–87).
- **Socket generation.** A counter on one join. It goes up by one each time the viewer server opens a new join socket for that code.
- **Join.** The viewer server's in-memory record for one short code: its socket, its `JoinState`, its subscriber and buffered signals.
- **Join intent.** The act that makes the viewer server open the join socket. In this slice it is `POST /api/joins { code }`, sent only by the viewer browser after the user clicks **Join** (or by `pan join` in slice 9). It is never a side effect of a navigation (D-1).
- **Subscriber.** The one viewer-browser event stream (`GET /api/joins/:code/events`, server-sent events) attached to a join. At most one at a time (D-4).
- **Restart.** Closing the join socket with a plain close (no `leave` frame), waiting for its `close` event, then opening a new one. The service marks an admitted viewer `connected: false`, then `true`; the host hub sees that flip and sends a fresh offer (slice-3 D-13).
- **Grace timer.** `JOIN_UNSUBSCRIBED_GRACE_MS = 60_000`. A live join with no subscriber for this long is closed with a plain close and becomes `away`.
- **Probe.** `GET /api/share-probe` on the viewer server. The landing page's script calls it cross-origin to find a running Overdeck on this computer.
- **Wire format / envelope / hello.** Slice 3's types in `packages/contracts/src/sharing.ts` (lines 114–199) and runtime in `packages/contracts/src/sharing-wire.ts` (`SharedChannelReader`, `SeqTracker`, `negotiateHello`, `encodeSharedMessage`, `SHARED_WIRE_VERSION`, `SHARED_SCOPE_KINDS`).
- **LNA.** Chrome's Local Network Access check (default since about Chrome 142): a fetch from a public HTTPS page to `localhost` shows a permission prompt. Older Chromium sent a Private Network Access (PNA) preflight that expects `Access-Control-Allow-Private-Network: true`.

## Problem

Slices 1–3 let a host create a share, admit viewers and stream the conversation over WebRTC, but nobody can receive it. No viewer-side code opens the join socket, no browser answers the host's offer, no page renders shared content, and the landing page tells a joiner to run `pan join`, which does not exist yet (slice 9). This is the slice that makes Shared Sessions usable end to end.

## Scope

1. Viewer-server `JoinManager`: join socket, state, keepalive, leave, signal relay, ICE servers, one-subscriber rule, restart, grace timer.
2. Viewer routes under `/api/joins` plus the landing-page probe `/api/share-probe`.
3. Browser `webrtc-viewer.ts` (answerer, five channels, hello, conversation and presence decoding).
4. Browser `joinApi.ts`, `useSharedJoin.ts`, `SharedConversationView.tsx` reusing `MessagesTimeline`, mounted at `/#/shared/<code>`.
5. Landing page `GET /s/:code` with a nonce'd localhost-detect script.
6. Tests: unit, route, frontend, a Miniflare integration test of the full relay, and a two-context Playwright spec.
7. User docs `configuration/shared-sessions.mdx` (+ `docs.json`, `anywhere.mdx`) and developer docs.

## Requirements

- **FR-1** `POST /api/joins` with `{ "code": "<code or join URL>" }` opens the join socket with the device token and answers 201 with a `JoinView` (200 with the existing view when that code's join is already live). 412 `not_signed_in` without `account.json`.

- **FR-6** A new subscriber on an admitted join that already had a subscriber in the current socket generation triggers a restart, so a reloaded page gets a fresh offer and a fresh history.
- **FR-7** `/#/shared/<code>` shows a **Join** confirmation, then the lobby, admitted, "Host disconnected — reconnecting…", "Removed by host" and the other terminal states in the *Viewer screens* table, with **Leave** while live.

- **FR-9** A lobby viewer renders no conversation content: the timeline component is not mounted and no message text from the host is in the DOM.
- **FR-10** The browser runs `negotiateHello`; an unsupported scope kind shows "Your Overdeck is too old for this share type", and a host hello with `v` above `SHARED_WIRE_VERSION` shows "The host is on a newer Overdeck".
- **FR-11** The landing page probes `http://localhost:3011` and `http://127.0.0.1:3011` for `GET /api/share-probe`, navigates to `<origin>/#/shared/<CODE>` on success, and always shows a manual link and `pan up` instructions.

## Decisions

Auto mode asked the operator nothing. Every decision is final for this issue and mirrored in `plan.autoDecisions[]`.

- **D-1 Join intent is an explicit click on the local page, not a cross-origin POST.** The parent PRD sketched "the share page POSTs the join intent to localhost". A cross-origin POST to the dashboard must skip CSRF, and the server cannot open a tab in the user's browser anyway. More important: opening the join socket shows the joiner's GitHub login and avatar to the host. A drive-by page that navigates a browser to `/#/shared/<code>` must not be able to do that. So the landing page only **navigates** to `/#/shared/<code>`, and that page shows a **Join** button. The click sends a same-origin `POST /api/joins` with the normal CSRF headers (`dashboardMutationJsonHeaders()`). The only cross-origin surface is the read-only probe.
- **D-2 Browser ⇄ viewer server transport: server-sent events plus POSTs.** The event stream uses `HttpServerResponse.stream` like `src/dashboard/server/routes/machines-peer.ts` lines 155–187. The browser reads it with `EventSource` (same origin, cookies sent). Answers, candidates and ICE requests are CSRF-protected POSTs. Polling would add up to one poll interval to every trickled ICE candidate; a new `/ws/*` upgrade would touch the upgrade plumbing; a `/ws/rpc` domain event touches five shared files.
- **D-3 One join per short code per process.** `JoinManager` keeps `Map<shortCode, Join>`. Two codes can be joined at once.
- **D-4 One subscriber per join; last one wins.** A new subscriber replaces the old one. The old stream gets a `replaced` event and is ended. The host keeps one peer connection per GitHub id, so two tabs answering the same offer would break both.
- **D-5 Restart for a fresh offer.** When a subscriber attaches and the join's state is `admitted` or `host-disconnected` and the current socket generation already had a subscriber, the manager restarts: it sets `restarting`, calls `socket.close(1000, 'reconnect')` (never a `leave` frame — the reducer re-lobbies a viewer that sends `leave`), and opens a new socket only from that socket's `close` event (slice-3 D-13: opening first gets the old socket replaced with 4008 and no `connected` flip). If no `close` event arrives within `JOIN_CLOSE_FALLBACK_MS = 5_000`, it calls `terminate()` and proceeds. **Implementation checkpoint:** the Miniflare test (WI-9) asserts that a restart produces a second host offer. If it does not, add `JOIN_RESTART_REOPEN_DELAY_MS = 500` between the `close` event and the reopen (fake timers in unit tests), and record why in a comment in `share-join.ts`.
- **D-6 Signals are delivered to the current subscriber, else buffered per generation.** A `signal` frame from the service goes to the subscriber, or into `pendingSignals` (at most `JOIN_MAX_PENDING_SIGNALS = 64`; more are dropped) when there is none. A new subscriber that does not trigger a restart receives the buffer in order, then it is cleared. A new socket generation clears it.
- **D-7 Grace timer.** A join in a live state with no subscriber for `JOIN_UNSUBSCRIBED_GRACE_MS = 60_000` is closed with a plain close and becomes `away` (an admitted viewer stays admitted on the service; a lobby viewer leaves the lobby). `POST /api/joins` on an `away` join reopens it. The page auto-resumes an `away` join without the confirmation click, because the user already confirmed this code in this server process.
- **D-8 No automatic reconnect after an unexpected close.** A close other than the table's codes (for example 1006) or a socket `error` makes the join `disconnected`; the page offers **Rejoin** (a new `POST /api/joins`; the service restores an admitted viewer without the lobby). Automatic restore is slice 8 ([PAN-4479](https://github.com/eltmon/overdeck/issues/4479)).
- **D-9 ICE servers.** On `status admitted` the manager sends `{ "type": "ice-servers" }` once per socket generation unless a list younger than `JOIN_ICE_CACHE_MS = 50 * 60_000` is cached. `POST /api/joins/:code/ice-servers` answers the cached list, or waits for the pending request. `error turn_unavailable` or `JOIN_ICE_TIMEOUT_MS = 5_000` without an answer resolves to `[]` (not cached). This mirrors slice-3 D-16.
- **D-10 Teardown.** Join-socket close 4004 → the browser closes its peer connection (slice-3 D-15: the host may keep streaming after the room ends). `status host-disconnected` → keep the peer and show the banner; `host-reconnected` → back to `admitted`, banner gone. Kick (4010), revoke (4011), blocked (4003), replaced (4008), is-host (4009), full (4013), rejected and disconnected → close the peer and the event stream.
- **D-11 Peer loss inside an admitted join.** A browser peer whose `connectionState` becomes `failed` or `closed` (not closed by the viewer itself) shows "Connection to the host was lost." with **Reconnect**. **Reconnect** closes the event stream and the peer and opens a new event stream; D-5 then restarts the socket and the host offers again. A new offer while a peer exists closes the old peer first.
- **D-12 Hash route mounted before the deck.** `App()` (`src/dashboard/frontend/src/App.tsx` line 112) returns `<SharedConversationRoute code=… />` when `window.location.hash` matches `#/shared/<code>`, beside the existing standalone routes (lines 116–138). The landing page arrives by full navigation, so this match runs on load. A same-tab hash change into `#/shared/` reloads the page (one `hashchange` listener in the existing top-level effect), because `App`'s early returns run only on mount.
- **D-13 Reuse `MessagesTimeline` bare.** Props: `messages` (mapped field by field from `SharedMessage` to the frontend `ChatMessage`), `workLog: []`, `streaming` (true when any message has `streaming: true`), `conversationName: 'shared:<CODE>'`, `cwd: ''`. `TerminalPanel.tsx` line 185 renders it with `workLog={[]}` and no `ToolBodyLoaderContext`, so no provider is needed. `author`, tool calls and work log are not rendered (slice 5 sets `author`).
- **D-14 Landing page: nonce'd inline script, fixed port list, manual link always shown.** `invitePage(shortCode, nonce)` adds `<p id="detect-status">`, an `<a id="open-local" href="http://localhost:3011/#/shared/<CODE>">` link, `pan up` instructions, an LNA hint, and one `<script nonce>`. The per-response CSP adds `script-src 'nonce-<nonce>'; connect-src http://localhost:3011 http://127.0.0.1:3011; form-action 'none'`. The nonce is 16 bytes from `rc.deps.randomBytes(16)`, base64. The probe uses `credentials: 'omit'` and a 1,500 ms `AbortController` timeout per origin. `LOCAL_DASHBOARD_ORIGINS = ['http://localhost:3011', 'http://127.0.0.1:3011']` is a constant in `pages.ts` (the default `dashboard.api_port`, `src/lib/config.ts` line 230); a dashboard on another port uses the manual link. The 404 page keeps `HTML_CSP` and no script.
- **D-15 The `pan join` line leaves the landing page until slice 9.** `pan join` does not exist yet. The page instead says to start Overdeck with `pan up` and reload. Slice 9 ([PAN-4480](https://github.com/eltmon/overdeck/issues/4480)) adds the command back; `docs/SHARED-SESSIONS.md` says so.
- **D-16 Probe route.** `GET /api/share-probe` calls no dashboard auth function: a cross-origin fetch carries no cookie, and the remote request gate already admits a loopback peer and refuses LAN peers. It is **not** added to `REMOTE_GATE_ALLOWLIST` (`src/dashboard/server/remote-request-gate.ts` line 68), so a LAN host cannot learn that Overdeck runs there. Body `{ "overdeck": true, "v": 1 }`, `Cache-Control: no-store`, `Vary: Origin`. `Access-Control-Allow-Origin: <origin>` only when `Origin` equals `new URL(shareUrl).origin` from `readShareUrl()`. `OPTIONS /api/share-probe` answers 204 with, for that origin only, `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods: GET`, `Access-Control-Allow-Private-Network: true`. A mismatched or missing origin gets the same status with no CORS headers.
- **D-17 Routes live in `src/dashboard/server/routes/joins.ts`**, an Effect `HttpRouter` module like `routes/shares.ts`, registered in `src/dashboard/server/server.ts` `makeRoutesLayer` next to `sharesRouteLayer` (line 421). `normalizeShareCode` is imported from `./shares.js` (line 51).
- **D-18 States, not errors, for refusals.** Close codes and upgrade refusals become `JoinState`s (*State table*). Only setup failures before a socket exists are HTTP errors (412, 500).
- **D-19 Presence renders a header only.** The page header shows the stream label (`presence.streams[0].label`, else the code) and the host (`participants` entry with `isHost: true`) as avatar plus `@login`, and the admitted viewer count. The full roster UI belongs to later slices.
- **D-20 The Playwright spec is not added to `test:playwright`**, following slice-2 D-16. The Miniflare integration test (WI-9) is the CI-run end-to-end relay coverage.
- **D-21 Size justification.** About 29 files across about 13 path-subsystems: the lint counts each top-level doc file (`docs.json`, `anywhere.mdx`, `configuration/…`, `docs/X.md`) and each test root (`tests/unit`, `tests/integration`, `scripts/…`) as its own subsystem. The code is one vertical feature: the viewer server, its routes, the browser peer and the page are useless without each other, and the issue names the landing page and docs page as part of this slice.

## Design

### Contracts (`packages/contracts/src/sharing.ts`, appended; type-only, no `import`)

Append after the wire format block, and add one header sentence: "PAN-4475 (slice 4) adds the viewer dashboard API types at the end: the shapes the viewer browser exchanges with its own dashboard server."

```ts
// ── Viewer dashboard API (PAN-4475, slice 4): the viewer browser ⇄ its own dashboard server. ──
// The device token never appears in these types.

/** A join's state on the viewer server. Live: connecting, lobby, admitted, host-disconnected. */
export type JoinState =
  | 'connecting' | 'lobby' | 'admitted' | 'host-disconnected'
  | 'away'          // closed by the viewer server's grace timer; POST /api/joins reopens it
  | 'disconnected'  // unexpected close or network error; POST /api/joins reopens it
  | 'left' | 'kicked' | 'revoked' | 'ended' | 'is-host' | 'full' | 'replaced' | 'rejected';

export interface JoinView {
  readonly shortCode: string;
  readonly joinUrl: string;              // <share_url>/s/<shortCode>
  readonly state: JoinState;
  readonly contributor: boolean;
  readonly login: string | null;         // the signed-in GitHub login from account.json
  readonly closeCode: number | null;     // the last join-socket close code, if any
```

Rules:

- **`join(code)`** (code already normalized by the route). An existing join in a live state → `existing` with its view. Otherwise: `readShareUrl()` error → 500 `share_url_invalid`; `readAccount()` throws → 500 `account_unreadable` (its message); `null` → 412 `{ error: 'not_signed_in', message: 'Sign in with pan account login to join shared conversations.' }`. Then open `joinSocketUrl(base, code)` with `{ Authorization: 'Bearer ' + account.accessToken }`, state `connecting`, `login = account.githubLogin`, `joinUrl = base + '/s/' + code`, and answer `created`. A previous join entry for the code (terminal, `away`, `disconnected`) is replaced, but its subscriber (if any) is carried over to the new entry and immediately gets the new state.
- **Keepalive.** On `open`: ping every `PING_INTERVAL_MS`, pong deadline `PONG_TIMEOUT_MS` (copy `startKeepalive` / `armPongDeadline` / `stopKeepalive` from `share-host.ts` lines 368–391, `unref()` the timers).
- **`subscribe`.** If another subscriber exists, send it `{ type: 'replaced' }` and drop it. Store the new listener; clear the grace timer; emit `state`. Then: if `state ∈ {admitted, host-disconnected}` and `subscribedThisGeneration` → restart (D-5). Else flush `pendingSignals` to it in order and clear. Set `subscribedThisGeneration = true`. The unsubscribe function (only if this listener is still current) clears the subscriber and, if the state is live, arms the grace timer.
- **Grace timer** (D-7): on fire, if still no subscriber and still live, set `graceClosing` and `socket.close(1000, 'away')` with the `JOIN_CLOSE_FALLBACK_MS` terminate fallback.
- **Restart** (D-5): `restarting = true`, `socket.close(1000, 'reconnect')`, fallback terminate after `JOIN_CLOSE_FALLBACK_MS`. The `close` handler for a restarting socket opens a new socket (same headers; re-read nothing), generation + 1, `subscribedThisGeneration = true` (the subscriber is attached), state `connecting`.
- **`signal(code, data)`**: `not_found` without a join; `not_admitted` unless state is `admitted` and the socket's `readyState === WebSocket.OPEN`; else `socket.send(JSON.stringify({ type: 'signal', data }))` (`data` already rebuilt by the route) → `sent`; a throwing `send` → `not_admitted`.
- **`iceServers(code)`**: `not_found`; `not_admitted` unless `admitted` or `host-disconnected`; else per D-9.
- **`leave(code)`**: `not_found`; if the socket is open, `leaving = true`, send `{ "type": "leave" }`, fallback terminate after `JOIN_CLOSE_FALLBACK_MS` → `left`; if not open, set `left` at once and terminate the socket. Returns `left`.
- Nothing logs. No view, event or error carries `accessToken`.

- **Offer** (`data.sdp?.type === 'offer'`): close any existing peer (D-11); start a new negotiation with a fresh generation; phase `connecting`; `const servers = await deps.fetchIceServers().catch(() => [])`; if a newer negotiation started meanwhile, stop. `new PC({ iceServers: servers.map(s => ({ urls: [...s.urls], ...(s.username !== undefined ? { username: s.username } : {}), ...(s.credential !== undefined ? { credential: s.credential } : {}) })) })`. Listeners: `icecandidate` with a non-empty `candidate` → `sendSignal({ candidate: { candidate, sdpMid: c.sdpMid ?? null, sdpMLineIndex: c.sdpMLineIndex ?? null } })`; `datachannel` → wire by `channel.label` (`control`, `conversation`, `presence`; ignore `drafts` and `terminal`: no `message` listener); `connectionstatechange` → `connected` → phase `connected`; `failed` or `closed` (not after `close()`) → phase `lost`. Then `setRemoteDescription(offer)`, apply buffered remote candidates, `createAnswer`, `setLocalDescription`, `sendSignal({ sdp: { type: 'answer', sdp: answer.sdp } })`. Any thrown error → phase `lost`.
- **Candidate** before the remote description is set (or before the peer exists) → buffer for the current negotiation; after → `addIceCandidate(...)`, errors swallowed.
- **Channels.** Each channel has its own `SharedChannelReader`; one `SeqTracker` per peer. String messages only. `read()` → `envelope` only; a `SeqTracker.observe` gap → notice `updates_missed` (once per peer).
- **Control.** The first `{ kind: 'hello', hello }` envelope: `local = { v: SHARED_WIRE_VERSION, scopeKinds: SHARED_SCOPE_KINDS, scope: hello.scope }`; `negotiateHello(local, hello)`. `scope_kind_unsupported` → notice `scope_unsupported`, no reply. Other failure → notice `hello_failed` with the code, no reply. Success → if `hello.v > SHARED_WIRE_VERSION` notice `host_newer`; send `{ v: SHARED_WIRE_VERSION, ch: 'control', streamId: envelope.streamId, seq: 1, t: now(), payload: { kind: 'hello', hello: local } }` through `encodeSharedMessage(envelope, chunkId)` and `channel.send` per part; remember `streamId`. A `{ kind: 'error', code }` control payload → notice `hello_failed`.
- **Conversation** (only after the hello reply; only envelopes whose `streamId` equals the remembered one): `history` → rebuild `Map<id, SharedMessage>` from `messages.map(readSharedMessage)` (nulls dropped); `append` / `update` → set by id (an `update` for an unknown id appends); `unavailable` → notice `transcript_unavailable` or `history_too_large`; then `onMessages([...map.values()])`.
- **`readSharedMessage`**: `null` unless `id`, `text`, `createdAt` are strings and `role ∈ {user, assistant, system}`; copies `turnId`, `completedAt` (strings), `streaming` (boolean), `sequence` (finite number) field by field; never copies `author` or any other key.
- **Presence**: an object with an array `participants`, a number `controllerGithubId` and an array `streams` → `onPresence`.
- **`close()`**: marks closed, closes every channel and the peer; later calls are no-ops; no callback fires after it.
