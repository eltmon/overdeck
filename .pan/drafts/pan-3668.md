## Glossary

- **Prime Agent**: Prime Intellect's MIT-licensed coding and research agent. Its executable is `prime-agent`. The version verified for this plan is `0.8.0` (`prime-agent --version`), with daemon protocol version `7` (`prime-agent status --json` → `"protocolVersion": 7`).
- **RPC mode**: `prime-agent --mode rpc`. It reads JSON commands from stdin, one per line, and writes responses and events to stdout, one per line. Protocol reference: `docs/rpc.md` in the installed package (`$(npm root -g)/prime-agent/docs/rpc.md`). Types: `dist/modes/rpc/rpc-types.d.ts`.
- **Strict LF JSONL**: records are split on `\n` only, with one trailing `\r` stripped. Node `readline` must not be used, because it also splits on U+2028 and U+2029, which are valid inside JSON strings (rpc.md "Framing").
- **Prime supervisor (daemon)**: a detached background process that Prime starts for RPC and interactive clients. It has its own process group, and it outlives the client that started it. Its sessions run in **workers**, with **kernels** (IPython) below them. Reference: `docs/daemon.md`.
- **Per-agent daemon socket**: the path passed to `--daemon-socket`. It gives an agent a private supervisor instead of the user's shared default one at `/tmp/prime-agent-<uid>/daemon.sock`.
- **Session file / session ID**: `get_state` returns two different values. `sessionFile` is the durable JSONL path, for example `…/01a0d716-407e-….jsonl`. `sessionId` is the identity stored in that file's header, for example `01a0d716-423a-…`. They are different UUIDs. `--resume <sessionFile>` reopens the file and reports the same `sessionId`. This was verified live on 0.8.0.
- **Prime host**: a new Node process, `dist/prime-agent-host.js` (source `src/lib/prime-agent/host.ts`), that runs inside the agent's terminal pane. It spawns `prime-agent --mode rpc` as a stdio child, owns that child, and serves an Overdeck control socket. It mirrors the existing ACP host (`src/lib/acp/host.ts` → `dist/acp-host.js`).
- **Host control socket**: an HTTP server on a unix socket at `$OVERDECK_HOME/sockets/<transport>-<agentId>.sock`. It accepts POST only, requires the header `x-overdeck-bridge-token` (`BRIDGE_TOKEN_HEADER`, `src/lib/bridge-token.ts:7`), and takes JSON bodies with an `op`. The ACP host already implements this contract.
- **Host transport**: the family name of a host-backed harness's socket and files. Today it is `acp` (harnesses `acp` and `opencode`). This plan adds `prime-agent`. Files follow the pattern `<transport>-token`, `<transport>-session-id`, and `<transport>-launch-error` in the agent directory, plus the socket `<transport>-<agentId>.sock`.
- **Harness behavior**: the canonical record in `packages/contracts/src/harness-behavior.ts` that defines launch, delivery, readiness, transcript, session-ID, context and feed semantics for each harness.
- **Cloister**: Overdeck's lifecycle supervisor. It owns registration, recovery, messaging, dispatch and observability.
- **ToS gate**: `canUseHarness()` in `src/lib/harness-policy.ts`. It blocks harness, model and auth combinations that break provider terms. It must never be weakened.
- **No-loss audit**: a test that enumerates every harness-facing surface from `KNOWN_HARNESSES` and fails when any surface omits a harness.
- **CostWriter**: the cost door in `src/lib/overdeck/cost.ts`. `record()` deduplicates by `requestId` and `sourceFile`. `reconcile({ source })` sweeps per-agent session files.

## Problem

Overdeck cannot launch or supervise Prime Agent. Prime Agent offers a persistent IPython control environment, recursive subagents (RLM), and a documented RPC protocol with prompt, steer, follow-up, abort, state, message and usage-statistics commands. Operators want to route plan, work, review, test and conversation roles through it, while Cloister stays the lifecycle authority.

The first implementation, PR #3670, was 127 files. It fell 61 commits behind a main that the Cut rewrote, and it hit 27 conflicts in deleted or rewritten files. Beyond that, three facts found during this replan make the archived design unsafe to port as-is:

1. **RPC mode starts a detached daemon.** A live probe on 0.8.0 showed this. A plain `prime-agent --mode rpc` starts a supervisor on the user's shared default socket. The supervisor survives after the client exits. If the supervisor process alone is killed, a resident worker restarts it. The archived host never passed `--daemon-socket` and only killed its RPC child. As a result, every Overdeck agent would have shared the operator's own Prime daemon, and stopping an agent would have left that daemon running.
2. **The archived runtime is tmux-only.** It called `tmuxCreateSession` and `tmuxKillSession` directly. Herdr is now the default terminal backend, and on a Herdr host those calls miss the agent pane. The existing ACP runtime has the same defect (`src/lib/runtimes/acp.ts:150-173, :210`).
3. **The archived host treated `sessionFile` and `sessionId` as the same value.** They are different values (see Glossary).

## Goals

1. Operators can select `prime-agent` through the same resolved-harness routing as every other harness, for work, plan and role runs, and for supervised conversations.
2. Each Prime session runs under a Prime daemon that Overdeck owns and reaps. No Prime process outlives a stopped Overdeck agent.
3. Delivery, readiness, stop, recovery, transcripts, activity and cost work on both Herdr and tmux.
4. Installation, credentials, version compatibility and every failure mode produce standalone, actionable errors.
5. No existing harness loses any behavior. A no-loss audit enforces this.

## Non-goals

- Using Prime's ACP mode (`prime-agent --mode acp`). 0.8.0 answers `initialize` with `"loadSession": false`, so an ACP session cannot be resumed. ACP also has no `get_session_stats` equivalent, and Overdeck records no cost for ACP and OpenCode today (`cost.ts:627`). The issue specifies RPC mode.
- Training or evaluation through Prime Intellect Lab or `verifiers`, and Prime GPU compute.
- Exposing Prime schedules, heartbeats, `--autonomous`, `--goal`, cross-agent messaging (`send_message`, `observe`) or `/refine` as Overdeck controls.
- Registering Prime RLM children as Overdeck agents. Their usage is folded into the root session through `child_usage_attributed` entries.
- Discovering the operator's own Prime sessions under `~/.prime/agent/sessions` in the conversation list. Only Overdeck-launched sessions are shown.
- Relocating Prime's home with `PRIME_AGENT_CODING_AGENT_DIR`. That would move `auth.json` too and break subscription sign-in.
- Fixing the pre-existing ACP defects found during the survey. These are the tmux-only `AcpRuntimeSync`, OpenCode logged as `acp` in `sessions.json` (`src/lib/acp/host.ts:191`), and the missing muse and opencode labels in `ConversationFeedCard.tsx` and `ConversationRow.tsx`. They are recorded under "Found defects" for separate issues. The exception is the `harness-binary.ts` missing-binary label fallthrough: Prime must not inherit it, so Work item 2 fixes it.
- Changing any provider's default harness, or adding a hardcoded default model.
- Supporting Windows natively. Prime Agent documents macOS and Linux only.

## Decisions (made in this document)

- **D1 — RPC mode, not ACP.** See Non-goals.
- **D2 — Per-agent Prime daemon.** Every launch passes `--daemon-socket <path>`. `<path>` is `$OVERDECK_HOME/sockets/pd-<first 16 hex of sha256(agentId)>.sock`. The hash keeps the path short. The builder throws a standalone error if the path exceeds 100 bytes. Overdeck reaps that supervisor's process group on stop, and never touches the default daemon.
- **D3 — Reap by process group.** Reaping runs `prime-agent status --json`, selects the entry whose `socketPath` equals the agent's daemon socket, sends `SIGTERM` to `-<pid>`, polls up to 5 s until the entry is gone, then sends `SIGKILL` to `-<pid>`. The Prime host runs it on `SIGTERM`, `SIGINT` and `SIGHUP`. `stopAgent` and `stopConversationRuntime` also run it for the `prime-agent` harness, because a pane close can kill the host before it cleans up. It is idempotent: when no supervisor is listed, it does nothing.
- **D4 — Same host socket contract as ACP.** The Prime host accepts exactly the ACP ops `status`, `message`, `interrupt` and `set-effort`, with the same status codes, so the delivery paths are shared. `message` checks `get_state.isStreaming`. When the session is idle it sends `prompt`. When it is streaming it sends `steer`. It returns `202 {accepted:true, promptId, command}`.
- **D5 — One host-transport helper.** A new `src/lib/runtimes/host-transport.ts` derives the transport from `HarnessBehavior.deliveryKind` (`acp-host-rpc` → `acp`, `prime-agent-host-rpc` → `prime-agent`) and builds the socket and file paths. The shared delivery, messaging and readiness sites call it instead of testing `harness === 'acp' || harness === 'opencode'`. ACP file names and messages stay byte-identical.
- **D6 — Launch through the terminal backend.** Launches go through `launchAgentPane` (work, plan, conversation) and `launchRuntimePane` (Cloister respawn). They never call tmux directly.
- **D7 — Keep `sessionFile` and `sessionId` separate.** The host writes `prime-agent-session-id` (the `sessionId`) and `prime-agent-session-file` (the `sessionFile`). Resume passes the file to `--resume` and compares the returned `sessionId` against the stored ID. A mismatch or a missing file stops the replacement process, writes `prime-agent-launch-error`, and never accepts a fresh session.
- **D8 — Context through argv, not a shell.** The launcher materializes `<agentDir>/prime-agent-context.md` with `materializeManagedLaunchContext(path, workspace, 'prime-agent')`. The host reads that file and passes it as `--append-system-prompt` values in its `spawn()` argument array, not through a shell. Text over 100,000 bytes is split on paragraph boundaries into repeated flags. The Linux single-argument limit is 131,072 bytes. The managed policy text (`PRIME_AGENT_MANAGED_POLICY`) comes first.
- **D9 — Flags every launch passes.** `--mode rpc --daemon-socket <p> --provider <p> --model <m> --session-dir <agentDir>/prime-sessions --no-extensions [--thinking <effort>] [--resume <sessionFile>]`, plus the context flags. Launches never pass `--goal`, `--autonomous*`, `--continue`, `--no-session` or `--offline`. `--no-extensions` is used because user extensions can register schedules and open dialogs that no UI can answer. Workspace `CLAUDE.md` and `AGENTS.md` discovery stays on.
- **D10 — Answer dialogs automatically.** When the host sees an `extension_ui_request` with method `select`, `confirm`, `input` or `editor`, it answers immediately with `{"type":"extension_ui_response","id":<id>,"cancelled":true}` and logs the method name only.
- **D11 — Denylisted RPC commands.** The host's RPC client refuses `send_message`, `agent_messages_*`, `*_schedule`, `list_schedules`, `*_heartbeat`, `list_heartbeats`, `observe`, `unobserve`, `refine`, `new_session`, `switch_session`, `fork` and `clone`, with a typed `PrimeAgentManagedPolicyError`. This is the archived list from `policy.ts` plus `refine`, `new_session`, `switch_session`, `fork` and `clone`, because those change the root session behind Overdeck's back.
- **D12 — Credential sources.** A launch is allowed when any of these holds, checked in order: (1) Prime's `~/.prime/agent/auth.json` has the Prime provider key (key names are read, values never); (2) `process.env` has Prime's env var for that provider; (3) Overdeck `settings.api_keys.<overdeckProvider>` is set, in which case the launcher exports it to the host under Prime's env var name. Otherwise the launch fails with an error naming the env var, the `auth.json` key, and `prime-agent` → `/login`.
- **D13 — ToS gate.** `prime-agent` + Anthropic model + `subscription` auth → blocked, using the archived branch from the review-fixes patch. Every other cell goes through the existing model-level rules. The existing opencode, muse and `kimi-code/*` rules keep blocking those model IDs for Prime.
- **D14 — Compatibility pin.** `PRIME_AGENT_SUPPORTED_RANGE = { min: '0.8.0', maxExclusive: '0.9.0' }` and `PRIME_AGENT_PROTOCOL_VERSION = 7` are defined in `src/lib/prime-agent/compat.ts`. Doctor and the launcher both check them. An unsupported version fails the launch with the found version and the supported range. There is no silent fallback to another harness.
- **D15 — Scope stays in this issue.** The operator's 2026-08-15 and 2026-09-25 comments keep the feature in PAN-3668. Adding a literal to the harness union forces edits across contracts, lib, CLI, server and frontend together, and a harness that can be selected but not launched delivers zero value. The plan uses many small items and sets `plan.metadata.sizeJustification`.
- **D16 — Transcript and cost.** The transcript is Prime's own session JSONL under `<agentDir>/prime-sessions/`, reached through the `prime-agent-session-file` pointer. A new parser projects it into the conversation feed. Cost is read from the same file through `CostWriter.reconcile({ source: 'prime-agent' })`. For each assistant message, the event usage is the last `child_usage_attributed.aggregateUsage` whose `targetId` is that message's entry ID, or `message.usage` when there is none. `requestId` is `prime-agent:<sessionId>:<entryId>`.

## Requirements

### Functional

- **FR-1** — `prime-agent` is a canonical harness literal everywhere a harness is enumerated: contracts, runtime types, config and settings validation, CLI options and help, telemetry, artifacts, flywheel, context previews, server route types, frontend unions, pickers, labels and branding.
- **FR-2** — `PRIME_AGENT_BEHAVIOR` defines Prime-specific kinds: launch `prime-agent-host`, delivery `prime-agent-host-rpc`, readiness `prime-agent-host-ready`, transcript `prime-agent-jsonl`, session ID `prime-agent-session-id`, context layer `prime-agent`, feed `prime_agent`. `getHarnessBehavior('prime-agent')` returns it and never the Claude fallback.
- **FR-3** — Overdeck resolves the `prime-agent` executable through `resolveHarnessBinary`. A missing or non-executable binary fails the launch before any pane is created, and the error names "Prime Agent" and the install command.
- **FR-4** — `pan doctor` reports the Prime Agent version against `PRIME_AGENT_SUPPORTED_RANGE`, lists orphaned Overdeck-owned Prime supervisors, and warns (it does not fail) when Prime is not installed.
- **FR-5** — Work agents, planning agents, role runs and conversations launch `node dist/prime-agent-host.js` in the assigned workspace through the terminal backend, with the D9 flags.
- **FR-6** — The RPC client uses strict LF JSONL, correlates request IDs, routes events, bounds pending requests and record size, times out requests, rejects all pending requests when the child exits, and never throws from its stdout handler.
- **FR-7** — The host records `prime-agent-session-id` and `prime-agent-session-file`, and appends `{harness:'prime-agent', path: sessionFile}` to `sessions.json` through `appendSessionIdToHistory`. Resume reopens the same session file and verifies the session ID (D7).
- **FR-8** — `pan tell`, dashboard messages and conversation prompts go through the host `message` op. The host chooses `prompt` when idle and `steer` while streaming. Delivery never falls back to terminal keystrokes.

## Rollout

The harness is opt-in: an operator sets `harness: prime-agent` for a role, or a provider harness in settings. No default changes. If Prime changes its protocol, the version check refuses the launch with the found version and the range, and there is no silent fallback. Bumping support means updating `compat.ts`, re-running WI-23, and recording the new version in `docs/PRIME-AGENT-HARNESS.md`.
