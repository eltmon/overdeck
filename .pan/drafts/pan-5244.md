# PAN-5244 — Issue drawer: conversation first, with a compact pipeline strip and a Skills tab

**Issue:** [PAN-5244](https://github.com/eltmon/overdeck/issues/5244)
**Status:** draft, 2026-11-13
**Approved mockup:** `docs/design/issue-view-conversation-first.html` (open it in a browser; `?scn=fresh|planned|working|paused|merged` switches state, `?theme=dark` switches theme). Its CSS class names and its `render` / `header` / `strip` / `conversation` / `detailsTab` / `pickupPanel` functions are the design reference. Where this PRD and the mockup disagree, this PRD wins; every deliberate difference is listed in "Mockup deltas".

All frontend paths below are relative to `src/dashboard/frontend/src/` unless they start with `src/`, `tests/`, `docs/`, `scripts/` or `features/`. Line numbers were read on main at `dafeeaf8a7d`; each one carries a search string in case lines drift.

## Glossary

- **Drawer** — the issue slide-over, `components/drawer/IssueDrawer.tsx`. A fixed right-hand panel, `w-[min(980px,calc(100vw-48px))]` (line 96). It opens when `drawer.issueId` in the store is set. This PRD redesigns the drawer and nothing else.
- **Cockpit** — the full-page issue view at `/command-deck/:project/:issue`, `components/Stage/cockpit/IssueMissionControl.tsx`. Not changed by this PRD.
- **`IssueDetail`** — `components/issue-detail/IssueDetail.tsx`, the one issue-detail component. The drawer mounts it with `density="drawer"`; the cockpit mounts it with `density="page"` and `showTabs={false}` (`IssueMissionControl.tsx:778-781`).
- **Density** — the `density` prop of `IssueDetail`: `drawer`, `page` or `rail` (`IssueDetail.tsx:48`, search `export type IssueDetailDensity`). A second, separate vocabulary exists on `IssueView`: `console`, `cockpit`, `rail` (`components/issue-view/inventory.ts`, search `export type IssueViewDensity`). The drawer is `IssueDetail` density `drawer` inside `IssueView` density `console`.
- **Phase** — one of the six lifecycle steps `plan`, `work`, `review`, `test`, `ship`, `done` (`lib/simple/phases.ts:14`, search `export const PHASES`). Each phase has a rail state: `done`, `current`, `pending` or `attention` (`phases.ts:31`).
- **Pipeline strip** — NEW. One 34px row under the drawer title: the six phases as compact buttons on the left, the checks chip and the pickup controls on the right. Replaces the tall phase rail and the always-visible specialist cards in drawer density.
- **Pickup controls** — `components/backlog/PickupGateControls.tsx` (PAN-2059): the operator controls for one issue: Plan → Release, the AI objection, the Ready / Blocks main / Park switches, planning mode, and the pickup gate. One implementation shared by `BacklogDAG.tsx:367`, `Stage/cockpit/PickupGateCard.tsx:15` and `IssueDetail.tsx:90`.
- **Strip variant** — NEW. A compact rendering of the pickup controls for the pipeline strip (`variant="strip"`): three switch chips, a sliders button that opens the full controls in a popover, and the Release / Recall control.
- **Checks chip** — NEW. A button in the strip that shows the PR check state and opens a popover with the existing `VerificationGates`.
- **Agent picker** — the control that chooses which agent's conversation the Conversation tab shows. Today a `<select>` (`components/drawer/DrawerAgentSession.tsx:173-184`); in the drawer it becomes a menu on the agent name.
- **Conversation tab** — tab id `session` (unchanged id), labelled "Conversation". Its body is `DrawerAgentSession` → `ConversationPanel` (transcript and composer) or `XTerminal`.
- **Details tab** — tab id `overview` (unchanged id), labelled "Details". Everything that is not the conversation: pipeline table, reviewer verdicts, live activity, full pickup controls, verification gates, workspace, UAT environment, active agent.
- **Skills tab** — NEW tab id `skills`. Hosts the existing `SkillOverridesPanel` at issue level.
- **`data-section` marker** — an HTML attribute naming a section, for example `data-section="DrawerTabs"`. Tests query it to prove a section still renders.
- **No-loss inventory** — `ISSUE_VIEW_INVENTORY` in `components/issue-view/inventory.ts` plus `DENSITY_SECTIONS` in `components/issue-view/densitySections.ts`. A locked list of every section each issue view renders. The drawer's 16 names are `DENSITY_SECTIONS.console` (`densitySections.ts:4`). Rows are never deleted.
- **Home** — the `home` field of an inventory row: the file that owns the section. The file must exist on disk.
- **Derived state** — `DerivedIssueState` from the store (`useDerivedIssueState(issueId)`, `lib/store.ts:325`). Its `state` is one of `backlog`, `parked`, `planned`, `working`, `in-review`, `changes-requested`, `ready`, `merged`, `closed`. Its optional `pr.checks` is `green`, `red` or `pending`.
- **Named tint classes** — `.chip-selected`, `.list-group-bar`, `.list-row`, `.switch-track-on` (in `@layer components` in `index.css`) and `.badge-bg-*` / `.badge-border-*` (in `@layer utilities`). They exist because this project is on Tailwind 3 with `var()`-based colours (`src/dashboard/frontend/tailwind.config.js`), where an opacity modifier on a token (`bg-muted/40`, `border-foreground/40`, `bg-card/70`) compiles to no CSS.

## Background

Today the drawer opens on the Conversation tab but gives it little room. Verified layout, top to bottom:

1. An optional start/resume block above the header: `IssueView` renders `<StartAgentCta>` at console density before its children (`components/issue-view/IssueView.tsx:29-31`, search `density === 'console'`).
2. A 52px header: id, 22px title, Issue link, close button (`IssueDrawer.tsx:100-133`).
3. The paused banner (`IssueDetail.tsx:357`).
4. The tab strip, about 40px (`IssueDetail.tsx:358-360`).
5. The phase rail, about 62px, and under it the four specialist cards, about 46px, on every tab and in every state (`IssueDetail.tsx:363-365` → `IssueDetailShell.tsx:81-97`).
6. A two-column grid `grid-cols-[minmax(0,1fr)_320px]` (`IssueDetail.tsx:366`): the tab body on the left, and a 320px right rail holding verification gates, containers and live activity (`IssueDetail.tsx:406-417`).
7. A footer action bar (`IssueDrawer.tsx:144` → `components/drawer/DrawerActionBar.tsx:9`).

The conversation gets 660px of a 980px drawer and loses about 250px of height to chrome. The redesign gives it the full width and cuts the chrome to about 115px: a 46px title row that also carries the actions, the 34px pipeline strip, and a 34px tab strip.

## Decisions

Each decision is final for this issue.

- **D-1 Scope is the drawer.** All new layout applies when `density === 'drawer'`. The cockpit file `IssueMissionControl.tsx` is not edited. `density="page"` and `density="rail"` keep their current composition (see D-12 for the three shared components that do change).
- **D-2 New pieces are shell-independent.** They live under `components/issue-view/` and take an issue id and callbacks, so the cockpit can adopt them in a later issue.
- **D-3 Tab ids stay; labels and order change.** New order: `session` "Conversation", `tasks` "Tasks", `plan` "Plan map", `files` "Files", `activity` "Activity", `artifacts` "Artifacts", `skills` "Skills", `overview` "Details". Existing `?tab=` links keep working because no id changes.
- **D-4 Default tab.** `openIssue()` already defaults to `'conversation'` (`lib/store.ts:222`) and so does `openIssueFromRoute` (`store.ts:236`). The one remaining default that opens Overview is the URL read at `store.ts:180` (`params.get('tab') || 'overview'`): it becomes `'conversation'` when the URL names an issue. The closed-drawer value `{ issueId: null, tab: 'overview' }` at `store.ts:108`, `:174` and `:240` does NOT change: the tab is meaningless while no issue is open, and 32 lines across the frontend tests set or assert that exact object. The two callers that pass `'overview'` on purpose (`components/Agents/directory/DirectoryIssueContext.tsx:42`, `components/chat/TranscriptIssueLink.tsx:53`) do not change; they now land on Details.
- **D-5 Header is one row.** Issue id, title (`h2`, `font-display`, 15px, weight 600, truncates), derived state badge, cost, the action strip, the Issue link, the close button. The footer is removed. The action strip is the existing `<IssueActionMenu mode="primary-strip" pinRight={['viewPr']} />`, unchanged: its primary buttons, its "N more" overflow button and its pinned "Open pull request" button are the mockup's next-step button, "⋯" menu and PR chip. No second menu is built. `IssueActionMenu` is not edited.
- **D-6 Pipeline strip states.** A phase button's look is its *kind*, resolved from the rail state plus the phase's agent. First match wins:

  | # | Condition | Kind | Text class | Glyph (14px box) | `title` |
  | --- | --- | --- | --- | --- | --- |
  | 1 | an agent of this phase has `paused === true` | `paused` | `text-warning-foreground font-medium` | lucide `Pause`, 12px | `<Label> agent is paused` |
  | 2 | the phase's agent is live | `live` | `text-info-foreground font-medium` | 8px dot `bg-info animate-pulse` | `<Label> is running` |
  | 3 | rail state `attention` | `attention` | `text-destructive-foreground font-medium` | lucide `CircleAlert`, 12px | `<Label> needs a look` |
  | 4 | rail state `done`, or phase `done` with rail state `current` | `done` | `text-body-foreground font-medium` | lucide `Check`, 12px, `text-muted-foreground` | `<Label> finished <date>` (date only when one exists); for phase `done` with rail `current`: `Merged. Close-out has not run yet.` |
  | 5 | rail state `current` | `next` | `text-body-foreground font-medium` | hollow 8px ring | `<Label> is next. No agent is running.` |
  | 6 | rail state `pending` | `pending` | `text-muted-foreground font-normal` | 5px dot | `Not started` |

  A button is enabled only when an agent with that phase's role exists; then `. Open its conversation.` is appended to the title and a click opens that agent's conversation. The `done` phase never has an agent and is always disabled. The mockup's "skip" state (Test with a minus glyph) has no equivalent in `phaseRailState` and is not built. `attention` keeps the red the existing `PhaseRail` uses for it (`PhaseRail.tsx:38`).
- **D-7 Review count.** The Review button shows `<done>/<total>` from `deriveSpecialistChips(agentsToReviewerSessions(agents), derived)` (`components/issue-detail/deriveSpecialists.ts:67`): `total` is the chip count, `done` is the chips with `status === 'done'`. The count is hidden while every chip is `queued`.
- **D-8 Reviewer switcher.** The existing `SpecialistStrip` renders, unchanged, as a row under the conversation header, only while the selected agent has `role === 'review'`. It has no "Synthesis" chip; the coordinator agent is reached through the Review phase button or the agent picker.
- **D-9 Checks chip.** Rendered when the issue has a PR (`derived?.pr` is defined), in every state. Before a PR exists the gate can only say "pending", so the chip is omitted; Details shows the gates in every state.
- **D-10 Strip variant of the pickup controls.** One component instance, one copy of the state and mutations; the popover shows the full variant's own JSX. A `stage` prop decides what the strip shows:

  | `stage` | Derived state | Strip shows |
  | --- | --- | --- |
  | `open` | `backlog`, `parked`, `planned`, or unknown | 3 switch chips, sliders button, then the plan control |
  | `picked-up` | `working`, `in-review`, `changes-requested`, `ready` | 3 switch chips, sliders button |
  | `finished` | `merged`, `closed` | nothing, and no request is made |

  The plan control in stage `open`: an amber "Objection" chip when `objection` is true; otherwise nothing when not planned; a primary "Release" button when planned and not released; "Released" text plus a quiet "Recall" button when released. Recall after pickup stays available in the full variant (popover and Details). While the state loads the strip renders nothing. On a failed load it renders only the sliders button, whose popover shows the error text.
- **D-11 Switch colours.** Checked track: Ready `switch-track-on` (neutral), Blocks main `bg-destructive`, Park `bg-warning`. These follow the mockup and the signal table: red is urgent priority, amber is a human decision.
- **D-12 Three shared components change in every density.** `ISSUE_DETAIL_TABS` / `IssueDetailTabs` (new order, labels, count-chip style), `PausedBanner` (lucide icons) and `WorkspaceSection` (lucide branch icon) are used by drawer and page density alike. "Page density renders exactly as today" means the production cockpit mount: `density="page"`, `showTabs={false}`, tab `conversation` or `terminal` (the only values `issueDetailTabFor` returns, `IssueMissionControl.tsx:125-129`). In that mount none of the three is visible except `PausedBanner`, whose only change is the two icons.
- **D-13 No second start surface above the header.** The `StartAgentCta` block that `IssueView` renders at console density is removed. Its two replacements, both in the Conversation tab: the no-agent start surface (full form with model and harness overrides) and, when the selected agent has ended, a row under the meta row with the same full `StartAgentCta` (it renders Resume, Start with overrides, or nothing, by its own rules). `ConversationPanel` gets no resume wiring (`onEmbeddedResume` is not passed), so this row is the Conversation tab's resume path.
- **D-14 Skills tab fetch.** `SkillOverridesPanel` is mounted only while the Skills tab is selected, with `enabled` true. Tab bodies are mounted one at a time, so nothing is fetched on drawer open. The badge reads the react-query cache and never fetches.
- **D-15 Inventory.** No row is added to or removed from `ISSUE_VIEW_INVENTORY` or `DENSITY_SECTIONS`; the counts stay 16 / 21 / 15 / 52. Two `home` values are re-pointed to the new file that owns those components (WI-1). The `PhaseTimeline` home stays `issue-detail/IssuePhaseRail.tsx`, which still renders that section in page and rail density. `SkillOverrides` stays a plain marker outside the inventory, as it is today.
- **D-16 Protected code is not edited:** `components/IssueActionMenu/*`, `components/chat/ConversationPanel.tsx`, the body of `SkillOverridesPanel`, and the full variant's JSX in `PickupGateControls.tsx` (it keeps its existing glyphs and inline colours; three surfaces share it).

## Requirements

- **FR-1** The drawer tab strip shows, in this order: Conversation, Tasks, Plan map, Files, Activity, Artifacts, Skills, Details, with ids `session`, `tasks`, `plan`, `files`, `activity`, `artifacts`, `skills`, `overview`.
- **FR-2** A drawer opened without an explicit tab shows the Conversation tab, including a URL with `?issue=<id>` and no `tab=`.
- **FR-3** `?tab=conversation`, `?tab=terminal`, `?tab=session` and `?tab=overview` keep opening the surface they opened before (Conversation in the matching view mode; Details).
- **FR-4** The drawer header is one row: id, title, state badge, cost, action strip, Issue link, close button. The title truncates and carries the full title as its `title` attribute.
- **FR-5** The footer action bar is gone. The same `IssueActionMenu` strip renders in the header inside the element marked `data-section="DrawerActionBar"` / `data-component="drawer-action-bar"`.
- **FR-6** In drawer density the pipeline strip renders the six phases with the kinds, titles, selection and click behaviour of D-6, in one row together with the right-hand controls.
- **FR-7** The Review phase shows the reviewer count of D-7, and the `SpecialistStrip` row appears under the conversation header exactly while a review agent is selected.
- **FR-8** The checks chip renders when the issue has a PR, shows pass / failed / running, and opens a popover containing `<VerificationGates>`.
- **FR-9** `PickupGateControls` accepts `variant="strip"` and `stage`, and renders per D-10 and D-11 from the same state and mutations as the full variant. The full variant's output is unchanged.
- **FR-10** In drawer density there is no right rail. Verification gates, containers and live activity render in Details; live activity also stays in the Activity tab.
- **FR-11** The paused banner renders under the strip and above the tabs, on every tab, with lucide `Pause` and `Play` icons and no `⏸` / `▶` characters.
- **FR-12** In drawer density the Conversation tab has a header row (agent name, Conversation | Terminal toggle, Tools button), a meta row (status, branch, model and harness, cost, agent id, start time) and, when the issue has more than one agent, a menu on the agent name listing every agent on the issue, workers included. - **FR-13** With no agent, the Conversation tab shows the start surface with the full `StartAgentCta`. With an ended agent selected, the `StartAgentCta` row of D-13 renders under the meta row.
- **FR-14** The Skills tab mounts `SkillOverridesPanel level="issue"` outside any disclosure, keeps `data-section="SkillOverrides"`, passes `liveAgents`, and is hidden once the panel reports the issue has no resolvable project; if it was the selected tab, the drawer switches to Conversation.

- **FR-16** The Details tab renders two columns: Pipeline table, Review verdicts, Live activity; and Pickup controls (full variant), Verification gates, Workspace with containers, UAT environment, Active agent, and a link to the Skills tab. It does not render `TasksPanel` or a skills disclosure.
- **FR-17** `density="page"` and `density="rail"` render the same composition as today: `IssueDetailShell`, the two-column grid with the 360px rail (page), the legacy `DrawerAgentSession` toolbar with its `<select>`, and the Overview body with `IssueSkillsSection` and `TasksPanel`.
- **FR-18** Every name in `DENSITY_SECTIONS.console` is rendered as a `data-section` on a visible element in the drawer, in the tab given by the section map below.
- **FR-19** Pressing Escape inside an open popover or menu in the drawer closes that popover and leaves the drawer open.
- **NFR-1** No server change, no new endpoint, no new polling loop. The only new network use is `useIssueCostsQuery` in the header, an existing query (`components/CommandDeck/ZoneCOverviewTabs/queries.ts:207`, key `['issueCosts', issueId]`).
- **NFR-2** Opening the drawer issues no request to `/api/skills/overrides`.
- **NFR-3** New markup follows the style guide rules restated in "Repo rules that apply".
- **NFR-4** Every new popover and menu has an accessible name, closes on Escape and outside click, and returns focus to its trigger. Every new switch chip is a `role="switch"` button with `aria-checked`.
- **NFR-5** `lib/__tests__/conformance-gates.test.ts` keeps passing unedited. Its import gates match the end of a `from '…'` path, so no new or changed file may import a path ending in `drawer/DrawerAgentSession` (allowed importers: `ConversationDock.tsx`, `IssueDetail.tsx`; line 66), `IssueDetailShell` (allowed: `IssueDetail.tsx`; line 84) or `issue-detail/IssueDetail` (allowed: `IssueMissionControl.tsx`, `IssueDrawer.tsx`; line 91). interface CachedSkillStates { skills?: Array<{ core: boolean; issue: boolean | null }> }

/**
 * How many non-core skills this issue overrides, read from the react-query
 * cache only. Returns null until the Skills tab has loaded the data. It
 * creates no query and no observer, so it can never issue a request.

export function useIssueSkillOverrideCount(issueId: string): number | null {
  const queryClient = useQueryClient();
  // Same key SkillOverridesPanel uses for level="issue" (SkillOverridesPanel.tsx:142).
