# PAN-2353 — Hermes external-agent bridge: scoped API + Fly 6PN (Overdeck Anywhere Phase 1b)

**Epic:** [PAN-2350](https://github.com/eltmon/overdeck/issues/2350) · **Parent PRD:** `.pan/drafts/pan-2350.md`

Anchors verified 2026-07-04.

## Glossary

- **Hermes** — the operator's OpenClaw-gateway fork on Fly.io (app `hermes-eltmon`, region iad, machine
  `683540eb735748`), a Slack-connected chat agent. `HERMES_HOME=/opt/data`; dashboard on 9119. Zero
  Overdeck integration exists (repo grep: one incidental prose hit).
- **Fly 6PN** — Fly's org-private IPv6 WireGuard mesh. `flyctl wireguard create` mints a peer config for an
  external machine, giving the home machine a private 6PN address reachable from Hermes with no public
  exposure. Outbound-only from the home machine's perspective.
- **External routes** — new module `src/dashboard/server/routes/external.ts`: thin authenticated HTTP
  surface for non-browser services. Auth = PAN-2351 scoped tokens via `Authorization: Bearer` (NOT origin
  validation — machine callers send no Origin; NOT the root internal token — host-scoped by design).
- **`deliverAgentMessage`** — the single message-injection door
  (`src/lib/agents/delivery.ts:177-182`; `DeliveryResult` at `:27-31`). Works for conversations too:
  `conv-` is a recognized prefix (`src/lib/agents/identity.ts:10`), and the canonical conversation path is
  `handleConversationMessage()` (`src/lib/overdeck/conversation-message.ts:243`, delivery at `:332-336`),
  which wraps it with harness/compaction handling.
- **Authed event catalog** — extension of the SSE feed: `PUBLIC_CATALOG`
  (`src/dashboard/server/routes/events.ts:27-42`, 14 types) is what anonymous/legacy callers see;
  authenticated callers additionally receive needs-you events (see D-3).

## Problem

Hermes can only be reached BY the operator via Slack; it cannot see or touch Overdeck. The building blocks
all exist server-side — resumable SSE (`events.ts:118`, `Last-Event-ID`), state GET routes, and the
delivery door — but (a) there is no inbound network path from Fly to the desk, (b) no non-root credential
(PAN-2351 fixes), and (c) needs-you events (`agent.enrichment_changed`, emitted by
`src/dashboard/server/services/agent-enrichment-service.ts:213-231`) are NOT on the public SSE catalog, so
even an authed subscriber can't see "agent is blocked on a question" today.

## Decisions

- **D-1 Transport: Fly 6PN WireGuard peer, private-only.** No public API exposure for this leg. Fallback
  (if the 6PN checkpoint fails): Cloudflare Access **service tokens** over the PAN-2352 tunnel — same HTTP
  surface, two extra headers on Hermes's client; document both, implement 6PN first.
- **D-2 Reuse doors, add none.** `POST /api/external/tell` calls `deliverAgentMessage` for `agent-*` /
  work-agent targets and `handleConversationMessage` for conversation targets (parity with the dashboard's
  own `POST /api/conversations/:name/message`, `routes/conversations.ts:570-602`). No new write path.
- **D-3 Needs-you on the authed SSE feed, not the public catalog.** Keep `PUBLIC_CATALOG` unchanged (that
  contract is versioned — `EVENT_STREAM_VERSION`, `events.ts:44`, `docs/EXTERNAL-EVENT-STREAM.md`). Add an
  `AUTHED_CATALOG = [...PUBLIC_CATALOG, 'agent.enrichment_changed']` used when the request presents a
  valid credential (events bearer or scoped token with `read:events`). Anonymous local callers keep exactly
  today's view; the open-when-unset hazard is unchanged here and gated by PAN-2352 D-4 when tunneled.
- **D-4 Scopes:** Hermes gets ONE token with `read:events, read:state, read:conversations, tell`.
  Deliberately NOT `operate` in v1 — conversation creation is deferred until a concrete Slack workflow
  needs it (Karpathy: nothing speculative). The epic's FR-6(d) is explicitly re-scoped by this decision.
- **D-5 The Hermes-side skill lives in the Hermes repo**, not here. This PRD specifies the contract; a
  companion brief (W5) is written for the Hermes agent to implement against.

## Requirements

- **FR-1** `GET /events/stream` accepts scoped tokens (`read:events`) and serves the authed catalog (D-3),
  preserving resume semantics (`Last-Event-ID`/`?since=`, replay cap `MAX_REPLAY_EVENTS=1000`, `events.ts:52`).
- **FR-2** `GET /api/external/state` (`read:state`): one JSON summary — active agents (id, issueId, role,
  phase, hasPendingQuestion), pipeline issues by phase, conversations (name, title, status, pending-input
  flag), flywheel status. Aggregates existing readers: agents list (`routes/agents.ts` barrel `:11-61`),
  issues (`routes/issues.ts:210`), conversations + pending-input (`routes/conversations.ts:204`, `:236`).
  Read-only aggregation in the route; no store access outside existing resolvers (two doors).
- **FR-3** `POST /api/external/tell` (`tell` scope): body `{target: string, message: string}`. Target
  resolution: `conv-*` or a known conversation name → `handleConversationMessage`; else
  `deliverAgentMessage(target, message, 'external-api')`. Returns the `DeliveryResult` (or the conversation
  handler's result) verbatim; 404 unknown target; 504 on `MessageDeliveryFailed` (mirrors
  `conversations.ts:570-602` behavior).
- **FR-4** 6PN connectivity: home machine WireGuard-peered into the Fly org; dashboard reachable from the
  Hermes machine at `http://[<6pn-addr>]:3011`.
- **FR-5** Companion brief for the Hermes implementation (event→Slack notifications for needs-you, `/deck
  status`, `/deck tell <target> <msg>` Slack verbs), including reconnect-with-Last-Event-ID and the exact
  curl examples.
- **NFR-1** External routes never accept origin-validated (credential-less) requests; 401 without a
  bearer, 403 with wrong scope (PAN-2351 FR-3 semantics).
- **NFR-2** Node 22, no `execSync`, Effect route style identical to neighbors.

## Intersecting repo rules (restated)

Two doors — the state route aggregates existing resolvers only; delivery goes through
`deliverAgentMessage`/`handleConversationMessage`, never raw tmux. No `execSync`. Async tmux only (already
inside the delivery door). Fake timers for any retry test (Hermes reconnect logic lives in its repo — the
brief restates the rule there). Node 22 dist; route-layer-only change, normal `pan reload`.

## Out of scope

Conversation creation (`operate`) — deferred per D-4; Hermes writing events INTO Overdeck (the
`pipeline/notify` pattern exists if ever needed); any public exposure of the external routes; multi-service
token issuance UX (PAN-2351's CLI suffices).
