## 1. Summary

Today the window has three always-open side columns: the nav `Sidebar` (256 px, `components/Sidebar.tsx`), the Command Deck's own left column (320 px, "Command Deck" header, Conversations and Issues sections, inside `components/CommandDeck/index.tsx`), and the Awareness rail (300 px, `components/sessionFeed/SessionFeedSidebar.tsx`). This child replaces the first two with **one left column** (`components/frame/LeftColumn.tsx`, 264 px) that is visible on every route, and removes the Awareness rail: its feed becomes a **Feed** tab on `/activity`, and its Needs-you list is already the top-bar Needs-you menu (E).

The hard part is not the markup. The Command Deck's lists are driven by state and handlers that live inside the `CommandDeck` route component, which mounts only on the `command-deck` route. The left column is visible everywhere, so this child first extracts that state and those handlers into route-independent modules under `components/frame/deck/` (no behavior change), then builds the column's sections against them, then swaps the frame in one item.

## 2. Glossary

- **Left column** — the new single column on the left of the window (`components/frame/LeftColumn.tsx`). It replaces the nav `Sidebar` and the Command Deck's left column.
- **Deck** — the `command-deck` route: `CommandDeck` renders the project's Stage (`components/Stage/index.tsx`). **Deck key** — the value of `selectedProjectKey` in `App.tsx`; it is a registered project's `name ?? key` (see `resolveDeckKey` in `App.tsx`), or `NO_PROJECT_KEY` (`'__no-project__'`, `CommandDeck/projectsData.ts`).
- **Selected project** — `App.tsx`'s `selectedProjectKey`. It survives route changes, so the left column on `/flywheel` still shows the last project.
- **Off-deck** — any route where `activeTab !== 'command-deck'`.
- **Deck controller modules** — the route-independent hooks and stores this child extracts into `components/frame/deck/` (§6.1). They hold what `CommandDeck` held for its lists.
- **openInDeck** — the new `App.tsx` callback that shows the deck for a project and points the URL at a conversation, an issue cockpit or the project (§6.2), exposed through `DeckNavigationContext`.
- **Session tree** — per-project issue → session nodes (`ProjectSessionTree`, `@overdeck/contracts`), fetched by `fetchAllSessionTrees` and kept live by the `subscribeProjectSessionTree` WebSocket stream.
- **Awareness rail** — `SessionFeedSidebar` mounted as the deck's right column (`CommandDeck/index.tsx`, search `Awareness rail (PAN-1591)`) and as the off-deck toggled column (`App.tsx`, search `isSessionFeedSidebarOpen &&`).
- **Feed tab** — the new first tab on `/activity` (`components/ActivityPanel.tsx`) that renders the Awareness feed full-width.
- **Rail workspace** — a workspace-registry row that `isRailWorkspace()` accepts (operator-created or favorited; main rows only when favorited).
- **CI subset** — `scripts/frontend-test-subset.txt`; CI runs only the frontend Vitest files listed there (sorted, one path per line relative to `src/dashboard/frontend`). `tests/unit/scripts/frontend-test-subset-list.test.ts` fails if a listed file does not exist.
- **Workflow fixture** — `scripts/dev/seed-workflow-fixture.ts` (child S, WI-S7), seeds a fixture project and conversation `fixture-1` under an isolated `OVERDECK_HOME`.

## 3. Decisions (made here; the executor does not re-decide them)

- **F-D1 Lists leave the route component; selection moves to a store.** `CommandDeck`'s `selectedFeature` and `selectedConversation` (`CommandDeck/index.tsx` lines 212–213, `useState`) move into the existing `useCommandDeckSelection` store (`lib/commandDeckSelection.ts`) as `selectedConversation`, `selectedFeature`, `setSelectedConversation`, `setSelectedFeature`. `CommandDeck` reads and writes them there; its URL-sync and deep-link effects stay in `CommandDeck` unchanged otherwise. Because `useState` reset on every mount and the store does not, `CommandDeck` clears both fields in an unmount cleanup (`useEffect(() => () => { setSelectedConversation(null); setSelectedFeature(null) }, [])`); otherwise `prevSelectedRef`/`prevFeatureRef` (which start `null` on mount) would see the leftover value and rewrite the URL on the next mount (open conversation X, go to `/flywheel`, click Project home → URL wrongly becomes `/conv/X`). A left-column click made off-deck sets the fields after that cleanup, so they still reach the next mount. Reason: the left column and the deck must agree on which row is highlighted, and only one of them is mounted per route.
- **F-D2 One navigation door: `openInDeck`.** `App.tsx` gains `openInDeck(target: DeckTarget)` (§6.2) and provides it, together with `onSelectProject` (`handleSelectProject`), through `components/frame/deck/deckNavigation.tsx` (`DeckNavigationContext`, `useDeckNavigation()`). Every extracted handler that today calls `onSelectProject`, `onConvIdChange` or `onCockpitChange` to open something calls `openInDeck` instead. `App` subscribes to no new store slice (render discipline, PAN-4560).
- **F-D3 The left column shows the selected project's lists on every route.** On `/flywheel`, `/settings` and any other route, the column still lists the selected project's conversations, issues and workspaces. Clicking a row opens or focuses the pane through `panesStore` (as today) and calls `openInDeck`, which switches to the deck. With no project selected (`selectedProjectKey === null`), the column shows the switcher reading "Choose a project", the nav, New conversation (creates an unscoped conversation, as the deck's header button does today with no project), and one muted line "Pick a project to see its conversations and issues" instead of the lists.
- **F-D4 Session-tree subscription, container-stats poll and the `N` shortcut have exactly one owner, in the frame.** `useSessionTreeSubscription` is mounted once, by `components/frame/deck/DeckDataHost.tsx` (renders `null`) inside the left column. The 5 s `/api/resources` container-stats poll (`CommandDeck/index.tsx`, search `Poll container stats every 5s`) becomes `useContainerStats(projectsWithSessions)`, called only by `IssuesSection` (its sole consumer passes the map to `ProjectNode`). The `N` shortcut (`id: 'deck.new-conversation'`, search `deck.new-conversation`) is registered once, by the New conversation button. `CommandDeck` no longer subscribes, polls or registers `N`. Consequence (hazard H4): the tree subscription and the container poll now run on every desktop route, not only on the deck; the poll still runs only when an issue reports containers.
- **F-D5 Project-list query key unified.** The deck uses `['command-deck-projects', projectQueryEpoch]` and the Sidebar uses `['command-deck-projects']`, two cache entries. Both become `['command-deck-projects']` (via `useDeckProjects`), and `bumpProjectQueryEpoch()` (in `handleCleanupOrphanedResources`) becomes `await queryClient.invalidateQueries({ queryKey: ['command-deck-projects'] })`. ## 5. Repo rules that apply (restated)

- Frontend tests must be listed in `scripts/frontend-test-subset.txt` or CI never runs them (sorted position, `merge=union`); listing a deleted file fails `tests/unit/scripts/frontend-test-subset-list.test.ts`. Only item WI-22 edits that file.
- Run only touched tests: `cd src/dashboard/frontend && npx vitest run <files>`. Never the full `npm test` on the host.
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint` (includes `lint:docs`, `lint:file-size`, `lint:circular`).
- Frontend typecheck skips test files; run every touched test.
- Delay-based tests use `vi.useFakeTimers()`; never real waits.
- A test that reads source files, or adds `skipIf`/`.only`, fails lint / the test-skip gate.
- The test-skip gate counts deleted tests across the whole diff: replace pinned tests; a test deleted together with its subject component falls under the deleted-subject exemption, but behaviors that survive (workspaces rows, owner groups, PR badge, move-to-project, Flywheel live word, More groups, experimental filter) get replacement tests in the new components.
- No `execSync`; no hardcoded model ids; never `git checkout` another branch or `git stash` in the workspace.
- A user-facing change adds `changelog.d/pan-5293.md` (format `changelog.d/README.md`).
- New lib modules import `getAgentState` from `agent-state-read.js` if needed (`lint:circular`).
