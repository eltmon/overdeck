# PAN-5201 — Speaker-aware STT: new providers, speaker labels and per-provider settings

**Status:** draft, 2026-11-13. **Issue:** [PAN-5201](https://github.com/eltmon/overdeck/issues/5201).
**Unblocks:** [PAN-5202](https://github.com/eltmon/overdeck/issues/5202) (Flux meeting sessions), which needs speaker labels on every committed turn.
**Research:** `.pan/drafts/pan-5201-research.md` — the November 2026 STT landscape survey with sources. Every provider fact below comes from it; the facts that drive the design (live diarization, speaker caps, WebSocket endpoints, sample rates, mode conflicts) were re-checked against the vendor docs on 2026-11-13.

All paths are relative to the repo root and were checked against `main` at `9683b371bb1`. Line numbers drift, so each one is paired with a code string to search for.

---

## 1. Summary

Overdeck's speech-to-text has two engines, Moonshine (local sidecar) and Google Cloud, and a text-only engine interface. This issue:

1. Changes the engine interface so a committed turn carries a speaker label, timing and words, and so an engine can revise labels it already sent.
2. Adds five engines chosen from the survey: **Speechmatics Realtime**, **AssemblyAI Universal-3.6 Pro Realtime**, **Meta Muse Voice Transcribe**, **Mistral Voxtral Mini Transcribe Realtime 3**, and a local **NeMo-Speech.cpp** server (NVIDIA Nemotron streaming ASR plus Nemotron 3 Diarization).
3. Gives every provider its own settings block and API key, redacted the same way the Google key is today.
4. Fixes two existing bugs found while researching: the two browser clients send different sample rates into the same `/ws/voice` socket while each engine assumes one fixed rate (FR-9), and every dictated turn is also pushed into AutoPreso, which sends an error back to the dictation widget (FR-12).
5. Keeps Moonshine (default, local, CPU) and Google Cloud (frozen: kept working, no new features).

## 2. Glossary

- **Engine** — one implementation of the `TurnEmitter` interface for one provider (file per provider in `src/voice/`).
- **Provider id** — the settings value that selects an engine: `moonshine`, `google-cloud`, `speechmatics`, `assemblyai`, `meta-muse`, `mistral-voxtral`, `nemo-local`.
- **Partial** — interim text that may still change. **Turn** — a committed utterance that will not change text, though its speaker label may be revised.
- **`TranscriptTurn`** — the committed-turn type (FR-1).
- **Speaker label** — the provider's session-scoped speaker id, normalized to `S1`, `S2`, … in order of first appearance within one engine instance. `null` when diarization is off or the provider gives none.
- **Speaker revision** — an engine event that changes the label of turns already emitted (AssemblyAI `SpeakerRevision` messages; NeMo and Speechmatics label settling where they emit corrections).
- **Segmenter** — a small server-side component that turns a stream of provider text events into committed turns by silence detection, for engines that cannot detect turns while diarizing (Mistral, see D-4).
- **Diarization capability** — `realtime` (labels in the live stream) or `none`.
- **Keyterms** — words the engine should favor (project names, module names, people). Each provider has its own limit.
- **Frozen provider** — kept working and tested, but gets no new features. Google Cloud is frozen.

## 3. Decisions

- **D-1 Five new engines, chosen for live diarization.** From the survey (§6 of the research file):
  - **Speechmatics Realtime** (`wss://eu.rt.speechmatics.com/v2`): live diarization with `diarization: 'speaker'`, no speaker cap by default, custom dictionary, and enrolled-speaker identification on every model except Melia 1 and Oak 1. $0.45/hr Standard, $0.80/hr Enhanced. Accepts `pcm_s16le` at 16 kHz.
  - **AssemblyAI Universal-3.6 Pro Realtime**: lowest streaming WER in the largest published comparison; diarization on all streaming models, `max_speakers` 1–10, beta; `SpeakerRevision` messages correct labels (text and timestamps never change). 100 keyterms included. $0.57/hr with diarization.
  - **Meta Muse Voice Transcribe** (`wss://api.meta.ai/v1/asr/realtime`): best real-time diarization error rate in the one benchmark Meta did not run, 20+ speakers, keyword biasing, $0.18/hr, PCM16 at 16 or 24 kHz. Mode (`DIARIZATION`, `ENDPOINTING`, `PUSH_TO_TALK`) is fixed at handshake.
  - **Mistral Voxtral Mini Transcribe Realtime 3** (`wss://api.mistral.ai/v1/audio/transcriptions/realtime`): live diarization with up to 8 reference clips (3–15 s), at most 10 speakers in total, $0.48/hr. "A realtime session can label speakers or detect turns, not both."
  - **NeMo-Speech.cpp** local server (`nemo-speech serve`, WebSocket `/v1/audio/transcriptions/realtime`): native C++ binary, no Python; `session.update` takes `speaker_diarization` and `speech_contexts` (word boosting); binary PCM16 frames; 8 speakers with Nemotron 3 Diarization. Works on the RTX 3090 and on CPU (ASR published at 6x real time on CPU; diarizer CPU speed unpublished).
- **D-2 Not added:** Deepgram (streaming stuck on its v1 diarizer, worst-but-one diarization score; Deepgram's "Flux" model appears to have no diarization), OpenAI and Google Chirp 3 / Gemini Live (no live diarization), Gladia (diarization async only), Rev.ai and Cartesia (no speaker labels), ElevenLabs Scribe v3 Live (launched 2026-11-10, docs contradict each other; candidate for a follow-up after a bake-off).
- **D-3 Speaker labels are normalized per engine instance.** Each engine maps its provider ids (`A`, `S1`, `Guest-1`, `0`) to `S1`, `S2`, … in order of first appearance. Callers never see provider-specific ids.
- **D-4 Mistral needs a segmenter; Muse uses its DIARIZATION mode without one.** Mistral rejects diarization combined with turn detection, so its engine runs `diarize: true` without turn detection and feeds text events through the segmenter (`src/voice/segmenter.ts`), which commits a turn after 700 ms with no new text or when the speaker label changes. Muse in `DIARIZATION` mode does its own speech-boundary detection and speaker attribution; its engine commits on each finalized segment. **Implementation checkpoint:** if Muse's `DIARIZATION` stream does not emit final segments in practice, route Muse through the same segmenter; no other change.
- **D-5 Enrollment is out of scope.** Speechmatics `speaker_identifiers` and Mistral `speaker_references` are not wired in this issue. The interface reserves an optional `enrolledSpeakers` option (FR-2) that engines ignore for now.
- **D-6 Keys live in `voice-settings.json`, one block per provider.** The file already exists at `~/.overdeck/voice-settings.json`, mode `0600` (`src/dashboard/server/routes/voice.ts`, search `function voiceSettingsPath`). Each provider block that needs a key has `apiKey`; `GET /api/voice/settings` returns `apiKey: ''` plus `hasApiKey`, and `PUT` keeps the stored key when the submitted key is empty — the same rules the Google block follows today (search `function redactVoiceSettings` and `apiKey: settings.stt.googleCloud.apiKey || existing.stt.googleCloud.apiKey`), generalized to every block. Environment variables override the file when set. These names are Overdeck's own choice, not vendor requirements: `SPEECHMATICS_API_KEY`, `ASSEMBLYAI_API_KEY`, `META_MUSE_API_KEY`, `MISTRAL_API_KEY`.
- **D-7 One `VoiceSettings` type.** Today it is declared three times: `src/voice/transcription-manager.ts` (search `export interface VoiceSettings`), `src/dashboard/server/routes/voice.ts` (same search), and `src/dashboard/frontend/src/components/Settings/types.ts` (search `VoiceSettings`). Move the server shape to `packages/contracts` (search for an existing voice or settings schema there first; if none exists, add `packages/contracts/src/voice-settings.ts` and export it from the package index) and import it in all three places.
- **D-8 Unknown providers degrade, not reset.** Today `isVoiceSettings` rejects an unknown provider and `loadVoiceSettings` falls back to all defaults, silently dropping a stored Google key. The new loader keeps every known block, and if `stt.provider` is unknown it sets the provider to `moonshine` and logs one warning.
- **D-9 Moonshine stays the default; Google is frozen.** Moonshine is the only local CPU path and is already packaged (`packages/moonshine-linux-x64`). Google keeps its v1 streaming client; the only change is the sample-rate fix (FR-9).
- **D-10 NeMo is connect-only.** Overdeck connects to a NeMo-Speech.cpp server at a configured URL. The URL has no default: the provider shows "not configured" until the operator enters one (the server's default port was not verified; take it from NeMo-Speech.cpp `docs/server.md` when writing the docs). Overdeck does not download, install or supervise the binary in this issue; the docs give the launch command. Managed install is a follow-up.
- **D-11 Each channel is a separate engine instance.** None of the chosen providers offers multichannel streaming that fits (AssemblyAI recommends one session per channel). Callers that need two channels (Flux) create two engines.

## 4. Requirements

### Functional

- **FR-1 `TranscriptTurn` type.** New file `src/voice/transcript-turn.ts`:
  ```ts
  export interface TranscriptWord { text: string; startMs: number | null; endMs: number | null; speaker: string | null }
  export interface TranscriptTurn {
    /** Engine-local id, unique within one engine instance: `u-<n>`. */
    engineTurnId: string;
    text: string;
    speaker: string | null;      // normalized S1, S2, … (D-3)
    startMs: number | null;      // from stream start
    endMs: number | null;
    words: TranscriptWord[] | null;
  }
  export interface SpeakerRevision { engineTurnId: string; speaker: string | null; words: TranscriptWord[] | null }
  ```
- **FR-2 `TurnEmitter` interface.** Rename `ITurnEmitter` (`src/voice/transcription.ts`, search `export interface ITurnEmitter`) to `TurnEmitter` in a new `src/voice/engine.ts` and change it to:
  ```ts
  export interface EngineCapabilities { diarization: 'realtime' | 'none'; maxSpeakers: number | null; keytermLimit: number | null; enrollment: boolean }
  export interface EngineOptions { diarize: boolean; maxSpeakers?: number; keyterms?: string[]; enrolledSpeakers?: never[] }
  export interface TurnEmitter {
    readonly capabilities: EngineCapabilities;
    onPartial(cb: (partial: { text: string; speaker: string | null }) => void): void;
    onTurn(cb: (turn: TranscriptTurn) => void): void;
    onSpeakerRevision(cb: (revision: SpeakerRevision) => void): void;
    onError(cb: (error: Error) => void): void;
    sendAudio(pcm16le16k: Buffer): boolean;
    isAlive(): boolean;
    getLastError(): string | null;
    stop(): Promise<void>;
    close(): void;
  }
  ```
  `onCommitted(text)` is removed. All existing callers move to `onTurn` (FR-8).
- **FR-3 Engine factory.** `createTranscriptionManager(settings, options)` in `src/voice/transcription-manager.ts` builds the engine for `settings.stt.provider` with `options: EngineOptions`. `getProviderCapabilities(provider)` returns the static capabilities without opening a connection, for the settings page and Flux's provider filter. Keyterms beyond an engine's `keytermLimit` are truncated with one warning.
- **FR-4 Speechmatics engine** `src/voice/engines/speechmatics.ts`. Raw WebSocket to the configured region URL (default `wss://eu.rt.speechmatics.com/v2`), `StartRecognition` with `audio_format: { type: 'raw', encoding: 'pcm_s16le', sample_rate: 16000 }`, `transcription_config: { language, operating_point, enable_partials: true, diarization: diarize ? 'speaker' : 'none', speaker_diarization_config?: { max_speakers }, additional_vocab: keyterms }`. Partials from `AddPartialTranscript`, turns from `AddTranscript` grouped by speaker and end-of-utterance. The message names here come from memory of the Speechmatics v2 real-time API, not from a page read for this PRD; confirm them and the `speaker_diarization_config` and `additional_vocab` shapes in the Speechmatics real-time docs while implementing. Settings: `apiKey`, `region` (`eu` | `us`), `operatingPoint` (`standard` | `enhanced`, default `standard`), `language` (default `en`).
- **FR-5 AssemblyAI engine** `src/voice/engines/assemblyai.ts`. Universal Streaming v3 WebSocket with `speech_model: 'universal-3-6-pro'`, `sample_rate: 16000`, `encoding: 'pcm_s16le'`, `speaker_labels: diarize`, `max_speakers`, `keyterms_prompt: keyterms`, and `speaker_labels_revision_interval_ms: 120000` when diarizing. `Turn` messages with `end_of_turn: true` become turns; `SpeakerRevision` messages become `SpeakerRevision` events by mapping `turn_order` to `engineTurnId`. Settings: `apiKey`, `model` (default `universal-3-6-pro`). Look up the exact v3 URL and message names in the AssemblyAI streaming docs while implementing; the names above come from `https://www.assemblyai.com/docs/streaming/label-speakers-and-separate-channels`.
- **FR-6 Meta Muse engine** `src/voice/engines/meta-muse.ts`. WebSocket `wss://api.meta.ai/v1/asr/realtime`, mode `DIARIZATION` when `diarize` is true and `ENDPOINTING` otherwise, PCM16 mono 16 kHz, `keywords: keyterms`. Turn-level timestamps only (`words: null`). Settings: `apiKey`, `model` (default `muse-voice-transcribe-1.0`). D-4 checkpoint applies.
- **FR-7 Mistral Voxtral engine** `src/voice/engines/mistral-voxtral.ts`. WebSocket `wss://api.mistral.ai/v1/audio/transcriptions/realtime?model=<model>`, `session.update` with `diarize` and `pcm_s16le` 16 kHz; never sets turn detection when diarizing (D-4). Text events go through the segmenter. Live segments have no timestamps, so `startMs`/`endMs` are the segmenter's wall-clock offsets. Settings: `apiKey`, `model` (default `voxtral-mini-transcribe-realtime-3`; confirm the exact model id in Mistral's model list while implementing).
- **FR-8 NeMo-Speech.cpp engine** `src/voice/engines/nemo-local.ts`. WebSocket `<url>/v1/audio/transcriptions/realtime`; wait for `session.created`; send `session.update { sample_rate: 16000, speaker_diarization: diarize, word_timestamps: true, speech_contexts: [{ phrases: keyterms, boost: 2 }] }`; send binary PCM16 frames; `.completed` events become turns with words and speakers; `input_audio_buffer.commit` on `stop()`. Capabilities report `maxSpeakers: null`, because the cap depends on the diarizer the server loaded: 8 with Nemotron 3 Diarization, 4 with Streaming Sortformer 4spk. Settings: `url` (required, no default). No key. **Implementation checkpoint:** the docs do not show a real-time diarized example; log the first `.completed` payload at debug level during the WI-6 manual check and map its speaker field. Fallback if the real-time stream carries no speakers: report `diarization: 'none'` for this provider and file a follow-up.
- **FR-9 One sample rate on `/ws/voice`: 16 kHz.** Today the dictation hook captures at 16 kHz (`new AudioContext({ sampleRate: 16000 })` in `src/dashboard/frontend/src/hooks/useVoiceTranscription.ts`) and the AutoPreso hook at 24 kHz (`new AudioContextCtor({ sampleRate: 24000 })` in `src/dashboard/frontend/src/hooks/useAutoPresoWebSocket.ts`), into the same socket. Moonshine declares 16 kHz (`const SAMPLE_RATE = 16000` in `src/voice/transcription.ts`) and Google declares 24 kHz (`const SAMPLE_RATE = 24000` in `src/voice/google-cloud-transcription.ts`). So dictation through Google and AutoPreso through Moonshine both run at the wrong rate. Fix: both hooks capture at 16 kHz, Google declares 16000, and every new engine declares 16000. Google reports `diarization: 'none'`.
- **FR-10 Moonshine adapts to the new interface** with `diarization: 'none'`, `speaker: null`, `words: null`.
- **FR-11 Turn queue keeps one speaker per turn.** `createTurnQueue` (`src/voice/turn-queue.ts`) consumes `onTurn`. It still coalesces consecutive chunks within 150 ms, but only when the speaker is the same; a speaker change flushes first. Filler filtering stays for dictation only and is skipped when `speaker !== null`.
- **FR-12 `/ws/voice` sinks.** `ws-voice.ts` forwards every committed turn into `autoPresoSession.processTranscript` (search `autoPresoSession.processTranscript`) and sends an error back when AutoPreso is not live, which the dictation widget shows (`useVoiceTranscription.ts`, search `message.type === 'error'`). Add a `sink` query parameter: `/ws/voice?sink=autopreso` forwards to AutoPreso; no parameter (dictation) does not. Update `useAutoPresoWebSocket.ts` (search `websocketUrl('/ws/voice')`) to pass `sink=autopreso`. The committed-turn message to the browser becomes `{ type: 'transcript:committed', text, speaker }`; existing clients read `text` and keep working.
- **FR-13 Settings UI.** `VoiceSettingsSection.tsx` gets a provider select with all seven providers, each option showing its tag: "Local", "Cloud · diarizes live", "Cloud", "Frozen". Selecting a provider shows its block (key field with "saved" state from `hasApiKey`, model or operating point, region or URL). A short line under the select states price per hour and speaker limit from a static table in `src/dashboard/frontend/src/components/Settings/sttProviders.ts`. A "Test" button opens `/ws/voice`, streams 3 seconds of mic audio, and shows the first partial or the error.
- **FR-14 Capabilities route.** `GET /api/voice/providers` returns `[{ id, label, capabilities, configured: boolean }]`, where `configured` is true when the provider needs no key or has one stored or in the environment. Flux uses it to filter providers (PAN-5202 FR-1).

### Non-functional

- **NFR-1** No `execSync` or sync child-process calls. Engines use the `ws` package already in the server dependencies.
- **NFR-2** API keys never appear in logs, errors sent to the browser, or `GET` responses. Engine errors pass through `src/lib/secret-redaction.ts` before they reach `sendJson`.
- **NFR-3** Each engine reconnects at most 3 times with backoff 1 s, 2 s, 4 s on an unexpected socket close, then reports the error and `isAlive() === false`. Tests use fake timers.
- **NFR-4** Audio buffered while an engine connects is capped at 1,000,000 bytes, matching `MAX_BACKEND_AUDIO_BUFFER_BYTES` in `src/voice/transcription.ts`; beyond it `sendAudio` returns false (backpressure).
- **NFR-5** Adding a provider later touches exactly: one engine file, one entry in the provider registry (`src/voice/providers.ts`), one settings block in the contract, one row in `sttProviders.ts`, and tests.

## 5. Repo rules that apply (restated)

- No `execSync` in dashboard server code or anything it imports.
- Reconnect, segmenter (700 ms) and turn-queue (150 ms) tests use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`; never wait on real timers.
- New HTTP route `GET /api/voice/providers` needs a `ROUTE_SCOPES` row (`src/dashboard/server/route-scopes.ts`, admin) and a row in `tests/unit/lib/overdeck/no-loss-matrix.ts`.
- Test fixtures must not contain strings shaped like real API keys (GitHub push protection blocks the branch); build fake keys at runtime, for example `'sk-' + 'x'.repeat(20)`.
- One variant per operation in `src/lib`; no Effect wrappers around Promise functions.
- Before writing settings UI, load the `pan-style-guide` skill.
- User-facing change ⇒ `changelog.d/PAN-5201.md`.
- Quality gates: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never the full `npm test` locally.
