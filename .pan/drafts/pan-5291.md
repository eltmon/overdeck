## 1. Glossary

- **Conversation panel** — `components/chat/ConversationPanel.tsx`, the component that renders one conversation: header, machine banner, About drawer, bookmarks drawer, transcript/terminal body, subagents rail, fork modal. 1525 lines; its file-size cap is 1531 (`scripts/file-size-allowlist.txt` line 66, last row wins).
- **Header** — today the `{!embedded && (<div className={`${styles.conversationHeaderShell} …`}` block, `ConversationPanel.tsx` lines 689–1006. Row 1 (`styles.conversationHeaderPrimary`) is the title and the action buttons; row 2 (`styles.conversationMetaRow`) is the status line.
- **Status line** — row 2 of the header. Today: state dot + label, `ConversationBranchMeta` (branch chip + PR badge), `ConversationMachineChip`, `PanOpenInPicker`, cost, session id.
- **⋯ menu** — the header overflow menu. Today its trigger is a `MoreVertical` icon button with `aria-label="More conversation actions"` (line 831–842) and its body is a `MenuSurface` with `aria-label="Conversation actions"` (line 846). Right-clicking the header also opens it (line 692).
- **Stage / deck** — the tabbed pane area (`components/Stage/index.tsx`). Components inside a Stage pane get `useStageDeck()` (`components/Stage/StageDeckContext.tsx`), which returns `null` outside a Stage.
- **Inside a Stage** — `useStageDeck()?.openDock` is a function. True for the Command Deck agent pane (`components/Stage/panes/AgentPane.tsx` line 30). False for the popout window (`App/StandaloneRoutes.tsx`), the phone app (`components/mobile/MobileConversations.tsx`), the issue drawer (`components/drawer/DrawerAgentSession.tsx`), the Flywheel pane, the Agents directory and the other mount sites (12 mounts, `grep -rn "<ConversationPanel" components App`; the 13th hit is a comment). Verified: the only non-embedded mount inside a Stage is `AgentPane` — `SessionPanel` (the Stage's session-backed agent pane), `DrawerAgentSession` and `SessionTranscript` pass `embedded`, so they render no header, and `AgentOutputPanel`/`AgentSection` live in the Activity view, outside any Stage.
- **Work dock (dock)** — the right column with tabs Files, Changes, Search, Live (`components/dock/WorkDock.tsx`), shipped by #5289. State per deck in `components/dock/workDockStore.ts`; `openDock(deckKey, input)` opens it on a tab, sets `changesScope`, and increments `openSeq`.
- **Dock scope** — what the dock shows, derived from the **active** Stage pane by `deriveDockScope` (`components/dock/dockScope.ts`). For an agent pane bound to a conversation it is that conversation (rule 2). In a split deck, a mouse-down inside a pane makes it active (`components/Stage/PaneLayoutView.tsx` line 100, `onMouseDownCapture={() => onFocus(paneId)}`), so a click on a header button scopes the dock to that conversation before `openDock` runs.
- **Conversation changes** — `GET /api/conversations/:name/changes?scope=…` (child A), typed `ConversationChanges` in `packages/contracts/src/conversation-changes.ts`. Its `totals` are `{ files, additions, deletions, commitsPushed, commitsLocal, uncommittedFiles }`.
- **`useConversationChanges`** — `components/dock/useConversationChanges.ts`: the React Query hook for that route, query key `['conversation-changes', name, scope, turnId ?? null]`, refetch every 5 s only while `conversation.isWorking`, plus a refetch on every explorer watch batch for its `rootId`. The dock's Changes tab, Files tab dots and Changes tab count all use scope `conversation`, so the header shares their cache entry.
- **Root id** — `project:<key>`, `issue:<ID>` or `workspace:<id>`; `rootIdForConversation(conv, ctx)` and `useRootContext()` in `components/explorer/rootForConversation.ts`.
- **Changes chip** — the scope chips on the dock's conversation Changes list (`components/dock/changes/ConversationChangesList.tsx`): This conversation (`conversation`), Last turn (`turn`), Not committed (`uncommitted`), All of main today (`main`).
- **Strict fetch mock** — `installStrictFetchMock` in the panel's Vitest files; any request the test did not declare fails the test in `afterEach`.
- **Native / phone app** — `isNativeShell()` (`lib/nativeShell.ts`) is true inside the Capacitor app; the panel hides admin actions there (PAN-4837).
- **Frontend test subset** — `scripts/frontend-test-subset.txt`: one path per line relative to `src/dashboard/frontend`, C-locale sorted, `merge=union`. CI runs only the frontend test files listed there.

## 3. Decisions

- **D1-1 The header is extracted first, with no behavior change.** WI-1 moves the header JSX and its header-only state into `components/chat/header/`. The panel shrinks by about 400 lines, which frees the line budget for D2. Every existing panel test stays green unchanged after WI-1.
- **D1-2 Header layout.** Row 1, left to right: working icon, title, transcript-missing icon, rename pencil (all unchanged) … then, right-aligned: `ViewToggle`, `RemoteHeaderActions`, Pi Stop, the Archiving…/Stopping… status, **Changes** `+a −d`, **Files**, **⋯**. About, Tools, Bookmarks, Copy link and Detach leave row 1 for the ⋯ menu. The ⋯ trigger icon becomes `MoreHorizontal` (mockup three horizontal dots); its `aria-label` stays `"More conversation actions"` and right-click still opens it.
- **D1-3 ⋯ menu order** (FR-1, mockup `#moreMenu`, §7 D1 rows). Groups separated by `MenuSeparator`; an item marked † is hidden in the phone app (it is in today's `!native` group or is the picker that native hides):
  1. **About this conversation** (`role="menuitemcheckbox"`, `aria-checked={aboutOpen}`), **Bookmarks** (right side: count when > 0; toggles the bookmarks drawer), **Show tool calls** (`role="menuitemcheckbox"`, `aria-checked={!hideToolCalls}`, right side `on`/`off`), **Subagents** (right side: count; only when `subagents.length > 0`; D1-6).
  2. **Open folder in <Editor>** — one item per editor (D1-5) †; **Copy conversation id** (right side: the name in mono); **Copy session id** (only when the session id differs from the name; right side: the first 8 characters in mono); **Copy link**; **Open in new window** (today's Detach).
  3. † Favorite/Unfavorite, † Regenerate title, † `PullRequestMenuItems`.
  4. † Hand off to new conversation, † Create summary fork, † Export transcript, † `PullHereButton`, † Continue on another device, † Share, † Open handoff doc, † Open handoff target (same conditions as today).
  5. † **Advanced** — an `eyebrow` label "Advanced" followed by today's Delivery method row unchanged (claude-code only; D-6 of the parent: the transport selector moves under Advanced unchanged). The group and its separator render only when the delivery row renders.
  6. † Archive conversation (unchanged confirm), **Stop the agent** (today's "Stop agent"; same condition `sessionAlive`, same `convMutations.stop`, still no confirm — the mockup's trailing "…" is not adopted because today's action has no dialog).
  Phone app parity: About, Bookmarks, Show tool calls, Subagents, Copy conversation id, Copy session id, Copy link and Open in new window stay visible in the phone app, because their header buttons are visible there today.
- **D1-4 Copy conversation id copies `conversation.name`** (the mockup shows the name, e.g. `20261111-8078`). **Copy session id** keeps today's status-line value reachable (§7 no-loss): `conversation.sessionFile?.split('/').pop()?.replace('.jsonl', '')`; the item renders only when that value exists and differs from `conversation.name`. Both write with `navigator.clipboard.writeText` and show `toast.success('Copied conversation id')` / `toast.success('Copied session id')`; Copy link keeps its URL and shows `toast.success('Copied link')`.
- **D1-5 "Open folder in…" is a list of editor items, not a nested picker.** `MenuSurface` has no submenus. For a local conversation: one `MenuItemButton` per available editor, label `Open folder in <Editor label>`, the preferred editor first with the shortcut text `formatSpec('Meta+Shift+O'|'Ctrl+Shift+O')` on its right. For a linked conversation (`origin === 'linked'`): one item per `REMOTE_EDITORS`, then the `REMOTE_UNVERIFIED` items disabled with `title={REMOTE_EDITOR_UNSUPPORTED_HINT}`, labelled `Open folder in <Editor> (remote SSH)`. No editors available ⇒ no items. The launch code is shared with `PanOpenInPicker`, not copied (WI-6). The header always calls `useEditorOpenFavoriteShortcut(native || linked ? null : (conversation.cwd ?? null))`, so `⌘⇧O` keeps working while the menu is closed.
- **D1-6 D1 ships the ⋯ → Subagents item; D2 still owns the default.** `SubagentRail` gains one prop, `toggleSignal?: number`. Each increment after mount flips the rail: on a narrow pane it flips the pane-local override (never stored); on a wide pane it flips the stored state and writes localStorage exactly as the rail's own buttons do (`defaultCollapsed` set ⇒ no write). The panel owns a counter and bumps it from the menu. The item is hidden when there are no subagents (the rail renders nothing then). D2's WI-D6 (closed by default) only changes the initial state.
- **D1-7 Change data appears only inside a Stage.** Outside a Stage there is no dock to open, so the Changes and Files buttons are not rendered and the status line shows no commit or uncommitted parts (FR-4 of the parent keeps today's behavior outside a Stage; none of these parts exist today). Mechanically: `ConversationHeader` reads `useStageDeck()`; when `openDock` exists it renders `StageHeaderChanges`, a component that calls `useHeaderChanges` once and passes `{ totals, openDock }` down; otherwise it passes `changes = null`. This keeps `useRootContext()`'s two queries and `/changes` out of the 12 non-Stage mount sites and out of every test that renders the panel without a `StageDeckProvider`.
- **D1-8 Which conversations query `/changes`.** `useHeaderChanges` enables the query only when `conversation.id >= 0` (a real row, same guard as `/diffs`) and `conversation.origin !== 'linked'` and `conversation.origin !== 'vault'` (the root is `null` there and the API reads this machine's disk). It calls `useConversationChanges(conversation, 'conversation', { rootId, enabled })` — the dock's own hook and query key — so the header, the Files dots and the Changes tab share one cache entry and one request. Cost, stated: while a conversation pane is mounted inside a Stage, the hook holds one explorer watch subscription for its root (the dock already holds one per open dock); refetch is every 5 s only while `isWorking` (parent NFR-4: no new loop faster than today's 5 s `/diffs` poll).
- **D1-9 Loading, error and zero.** While the query loads or after it errors, `totals` is `null`: the Changes button shows the word "Changes" without numbers and the status line shows no commit/uncommitted parts. With totals loaded: the button shows `+additions −deletions` only when `additions + deletions > 0`; each status-line part shows only when its count is > 0.
- **D1-10 Status line, in words** (FR-2, mockup `.meta`). Parts in order, separated by `·` (`styles.conversationMetaSep`, `aria-hidden`):
  1. **state**: today's dot + `statusLabel` (unchanged);
  2. **machine**: `ConversationMachineChip` (unchanged, §7: "kept, after state");
  3. **folder**: `abbreviateHome(conversation.cwd)` in mono, `title={conversation.cwd}`; inside a Stage a button that runs `openDock({ tab: 'files' })`; outside a plain span; absent when `cwd` is empty;
  4. **branch**: `conversation.branch` in mono, `GitFork` 12 px icon before it when `isWorktree`, `title={`${isWorktree ? 'Worktree' : 'Local'} · ${cwd}`}` (the "Local"/"Worktree" word moves into the tooltip); then the PR badge exactly as today;
  5. **`N commits pushed`** (`totals.commitsPushed`) and **`N commits not pushed`** (`totals.commitsLocal`): buttons → `openDock({ tab: 'changes', changesScope: 'conversation' })`;
  6. **`N files not committed`** (`totals.uncommittedFiles`): button → `openDock({ tab: 'changes', changesScope: 'uncommitted' })`;
  7. **cost**: today's text and condition, colored `text-signal-cost-foreground`.
  The session id leaves the status line (D1-4). `PanOpenInPicker` leaves it (D1-5). Singular forms: `1 commit pushed`, `1 commit not pushed`, `1 file not committed`.
- **D1-11 `abbreviateHome(path)`** — the frontend has no home directory, so the rule is textual: replace a leading `/home/<user>` or `/Users/<user>` (up to the next `/` or the end) or a leading `/root` with `~`; any other path is returned unchanged. `/home/eltmon/Projects/dfai` → `~/Projects/dfai`; `/srv/app` → `/srv/app`.
- **D1-12 Colors in the status line** follow the mockup (parent D-1) and each keeps its one meaning: the state dot (existing), `N files not committed` in `text-state-needs-you` (amber: a human must commit it), cost in `text-signal-cost-foreground` (cyan: money). The commit parts, folder and branch stay `text-muted-foreground`. The style guide's "one colored signal per row" applies to data-dense list rows (kanban, trees, lists), not to this one-per-pane header line; this is a deliberate, recorded exception that matches the approved mockup.
- **D1-13 Header buttons open, they do not toggle.** Changes and Files always call `openDock`; the dock's own close button hides it. The `Ctrl+Shift+E/G` shortcuts keep their toggle behavior. Button titles name the shortcut: `Show what this conversation changed (<formatSpec>)` and `Show this conversation's files (<formatSpec>)`, using `formatSpec(spec, currentPlatform())` from `lib/shortcuts/keys.ts` with `Meta+Shift+G`/`Ctrl+Shift+G` and `Meta+Shift+E`/`Ctrl+Shift+E` (the specs in `explorer/search/useExplorerShortcuts.ts` lines 34–35).
- **D1-14 Changes button text.** Icon `FileDiff` 14 px, label `Changes`, then (D1-9) `<span className="tabular-nums"><span className="text-success-foreground">+{a}</span> <span className="text-destructive-foreground">−{d}</span></span>` with U+2212 minus, the same classes `dock/changes/ChangeFileRow.tsx` line 52 uses. `aria-label`: `Changes, ${a} lines added, ${d} removed` when numbers show, else `Changes`. Files: icon `Folder` 14 px, label `Files`, `aria-label="Files"`. Both use the existing header button class `styles.conversationAboutToggle` (no new button style).
- **D1-15 The dock chip follows a repeat open.** `ConversationChangesList` subscribes to the deck's `openSeq`; when it changes and the store's `changesScope` is set, the chip becomes that scope. Header and status-line calls always pass `changesScope`, so "Changes" resets the chip to This conversation and "N files not committed" sets Not committed even when the list is already on screen.
- **D1-16 Changelog file name** is `changelog.d/pan-5291.md` (lowercase issue id, `changelog.d/README.md`); the child stub's `5291.md` is wrong.

- **FR-7** The status line renders the parts of D1-10 in order with the wording, singular forms and actions stated there; the session id and the editor picker are not in it.

- **FR-9** Outside a Stage, no Changes/Files buttons and no commit/uncommitted parts render, and no `/changes`, `/api/registered-projects` or `/api/workspace-registry` request is made by the header (D1-7).

## 5. Repo rules that apply (restated)

- Do not run the full `npm test` on the host; run only touched test files with `npx vitest run <file>` from `src/dashboard/frontend`.
- Frontend typecheck skips test files, so a mistake in a test is caught only by running it.
- Delay-based tests use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`; never real waits.
- Frontend test files must be listed in `scripts/frontend-test-subset.txt` or CI never runs them. The file uses `merge=union`, so items that each add their own line do not conflict.
- File size: a file may not grow past its `origin/main` line count or its last allowlist row; agents cannot raise rows. Extract a module instead (WI-1 does exactly that).
- Style guide (`sync-sources/dev-skills/pan-style-guide/SKILL.md`): Broadsheet tokens only, no hardcoded hex; nothing outside `.display-*` heavier than 600; `font-mono` only for identifiers (paths, branch, ids, hashes); amber = human, blue = machine, emerald = outcome, red = broken, cyan = money; running is blue, never green; a Tailwind opacity modifier on a `var()` token (`bg-warning/30`) compiles to no CSS — use a named class with `color-mix(...)`.
- New lib modules must not create a circular import (`npm run lint` runs the guard).
- A user-facing change adds `changelog.d/<lowercase issue>.md`; never edit `changelog.mdx`.
- Workspaces are git worktrees: never `git checkout` another branch inside one; never `git stash`.
- The shared workflow fixture refuses to run against the operator's `~/.overdeck`; screenshots come from an isolated dashboard (`tests/fixtures/isolated-dashboard.js`), never from :3011.

## 6. Architecture

New folder `components/chat/header/`:

| File | Owns |
|---|---|
| `ConversationHeader.tsx` | both header rows, the title/rename state and mutations, the Pi abort mutation, the menu open state, the `useEditorOpenFavoriteShortcut` call, the Stage gate (D1-7) |
| `ConversationHeaderMenu.tsx` | the ⋯ `MenuSurface` body: every item of D1-3, the delivery-method state, export, copy link, open in new window, copy ids, handoff doc/target |
| `ConversationStatusLine.tsx` | row 2 per D1-10, plus the exported pure helpers `abbreviateHome`, `commitsPushedLabel`, `commitsNotPushedLabel`, `filesNotCommittedLabel` |
| `headerChanges.tsx` | `useHeaderChanges(conversation)`, `StageHeaderChanges` (the gate's inside branch) and `HeaderDockButtons` (Changes + Files) |
| `OpenFolderMenuItems.tsx` | the editor items of D1-5 |
| `__tests__/*.test.tsx` | one test file per module above |

Data flow inside a Stage:

```
AgentPane → ConversationPanel → ConversationHeader
                                  └─ useStageDeck().openDock ? StageHeaderChanges : (changes = null)
                                        └─ useHeaderChanges(conversation) → useConversationChanges(conv, 'conversation', { rootId, enabled })
                                              ↳ { totals | null }
                                        ├─ HeaderDockButtons  { totals, openDock }
                                        └─ ConversationStatusLine { totals, openDock }
```

`openDock` here is the deck's `StageDeckContextValue.openDock(input)` (deck key bound), not the store method.

### WI-1 — Extract the header into `chat/header/` (no behavior change) — FR-1 (foundation), NFR-1
