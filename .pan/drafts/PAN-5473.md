## Glossary

- **Desktop app** (or **the app**): the Electron app in `apps/desktop/`. Product name `Overdeck`,
  app id `com.overdeck.app`.
- **Embedded server**: the dashboard server the app starts as a child process
  (`apps/desktop/src/server.ts`, `spawnServer`). It is the same `server.js` that `pan up` runs.
- **`pan up` dashboard**: the dashboard `pan up` starts without the app, on API port 3011 by default.
- **Release installers**: the three files each GitHub Release carries for the app: `.AppImage`
  (Linux), `.dmg` (macOS), `Setup .exe` (Windows).
- **npm package**: `@overdeck/desktop` on npm. Its command is `overdeck-desktop`.
- **Chosen machine**: the one other Overdeck machine whose dashboard the app shows instead of running
  the embedded server (PAN-4402, changelog v0.73.0 #4665).
- **Pairing link**: a one-time URL from **Settings → Anywhere → Pair a device** or `pan pair`, shaped
  `http(s)://<address>/#pair=odp_…`.
- **Mint check**: `npx -y mint@4.3.49 validate` and `npx -y mint@4.3.49 broken-links`, run from the
  workspace root. Always pin `mint@4.3.49` (the version PAN-5483 standardized on). Never run
  `mint validate --fix`: it rewrites about 80 files that sibling issues edit in parallel.
- **Dash rule**: no em dash (U+2014) or en dash (U+2013) in any line this issue adds or edits, and none
  in the frontmatter `title` or `description` of any touched page.

`D/` below means `apps/desktop/`. `FE/` means `src/dashboard/frontend/src/`.

## Background: verified facts

### Downloads (release installers)

- F-1. Each release attaches (verified on the v0.89.1 release, `gh release view v0.89.1`):
  `Overdeck-<version>.AppImage` (Linux x64), `Overdeck-<version>-arm64.dmg` (macOS Apple silicon),
  `Overdeck.Setup.<version>.exe` (Windows x64 installer), plus update metadata files (`latest*.yml`,
  `*.blockmap`, `-arm64-mac.zip`) that the updater reads and readers should ignore. Targets are set in
  `D/package.json` `build.linux.target` (AppImage x64), `build.mac.target` (dmg arm64), `build.win.target`
  (nsis x64), and built by the `desktop` job in `.github/workflows/release.yml` (search `desktop:`).
- F-2. There is no build for Intel Macs, Linux on ARM or Windows on ARM. Those users run
  `@overdeck/core` and use the dashboard in a browser (`pan up`).
- F-3. Download page: `https://github.com/eltmon/overdeck/releases/latest`. Canary builds are GitHub
  prereleases (`release.yml`, `prerelease: ${{ needs.classify.outputs.prerelease }}`).
- F-4. macOS signing: the v0.89.1 mac job log says `skipped macOS application code signing` and
  `[notarize] Skipping ... The app is signed but NOT notarized`. So macOS will not open the app on the
  first try. **Implementation checkpoint IC-1:** run
  `gh run list --repo eltmon/overdeck --workflow release.yml --limit 1` and grep the mac `desktop` job log
  (`gh run view --job <id> --log | grep -i -E "notariz|skipped macOS"`). If it still skips
  notarization, add the Gatekeeper step from work item 1. If the latest release is notarized, leave the
  step out. Never call the app "signed" or "notarized".
- F-5. Windows: the installer is not one-click (`D/package.json` `nsis.oneClick: false`,
  `allowToChangeInstallationDirectory: true`). Its default per-user folder is
  `%LOCALAPPDATA%\Programs\Overdeck` (electron-builder `getWindowsInstallationDirName` uses the product
  name when `oneClick` is false; checked in `app-builder-lib@26.15.3`). Do not claim the installer is
  code-signed.
- F-6. Linux: the AppImage needs the executable bit (`chmod +x`). Put it in `~/Applications/` so
  `pan up` finds it (F-12).

### The npm package `@overdeck/desktop`

- F-7. `npx @overdeck/desktop` runs the app; `npm install -g @overdeck/desktop` installs the
  `overdeck-desktop` command (`D/package.json` `bin`, `D/bin/overdeck.mjs` header comment). The plain
  `overdeck` command belongs to `@overdeck/core`.
- F-8. The launcher needs Node.js 22 or later and exits with
  `[overdeck] Node.js 22 or later is required (found <version>).` otherwise (`D/bin/overdeck.mjs`,
  `checkNodeVersion`). The published package lists `electron` as a dependency
  (`D/scripts/build-for-publish.mjs`, search `Promote electron to dependencies`), so installing it
  downloads Electron.
- F-9. The npm package does not include the `pan` command: `cli/` is not in `D/package.json` `files`
  (only the release installers carry the packaged CLI runtime; `docs/DESKTOP-APP.md`
  "Packaged CLI runtime"). To run `pan` in a terminal, install `@overdeck/core`.
- F-10. `pan up` never finds the npm package; it is not one of the paths in F-12.
- F-11. The in-app updater (F-30) applies only to the release installers. For the npm package, update with
  `npm install -g @overdeck/desktop@latest`, or run `npx @overdeck/desktop@latest`.

### How `pan up` finds and launches the app

- F-12. `pan up` checks these paths in order and launches the first that exists
  (`src/cli/index.ts:728`, search `Check for installed Electron app`):
  - Linux: `~/.local/bin/overdeck`, `~/.local/share/applications/overdeck`, `/usr/local/bin/overdeck`,
    `/opt/overdeck/overdeck`, then any `~/Applications/Overdeck*.AppImage`.
  - macOS: `/Applications/Overdeck.app`, then `~/Applications/Overdeck.app`
    (it runs `Contents/MacOS/Overdeck` inside).
  - Windows: `%LOCALAPPDATA%\Programs\overdeck\Overdeck.exe` (the installer's default folder, F-5;
    Windows paths ignore case).
- F-13. **Linux hazard (#5557).** The install script (`scripts/install.sh`, `INSTALL_PREFIX` defaults to
  `$HOME/.local`) puts the `overdeck` CLI at `~/.local/bin/overdeck`, the first Linux candidate. Then
  `pan up` prints `Launching Overdeck desktop app...` and `✓ Desktop app launched`, but what it starts
  is `overdeck` with no arguments, which runs `overdeck serve` (`src/cli/index.ts`, search
  `Default action: no args`). `serve` starts the dashboard on port 3011 and opens it in the browser unless
  `--no-open` is given (`src/cli/index.ts`, search `.command('serve')`; `src/cli/commands/serve.ts`,
  `openBrowser(browserUrl)`), so the dashboard still opens in the browser. Document only
  `~/Applications/Overdeck*.AppImage` as the Linux place for the app, and add the one-sentence note in
  work item 2. **Decision rule:** if at writing time the Linux candidate list no longer contains
  `~/.local/bin/overdeck`, leave the note out.
- F-14. When it finds the app, `pan up` (`src/cli/index.ts:786`, `if (electronAppPath && options.open !== false)`)
  starts Herdr first (`ensureHerdrBeforeDashboard`), launches the app detached, prints
  `✓ Desktop app launched`, starts the post-launch sidecars (`startUpSidecars`), and returns. It does
  not start its own dashboard server; the app runs the dashboard. If the launch fails it prints
  `⚠ Could not launch desktop app: <message>` and `Falling back to bare server mode`, then starts the
  normal dashboard.
- F-15. `pan up --no-open` skips the app: it starts the normal `pan up` dashboard and opens nothing
  (`pan up --help`: `--no-open  Do not open the dashboard app/browser after startup`).
- F-16. `pan down` stops the dashboard on the configured `pan up` ports (3010/3011 by default,
  `src/cli/commands/down.ts`) and does not quit the app. Quit the app from its tray or menu.

### What the app runs

- F-17. At launch the app starts the embedded server unless a chosen machine is active
  (`D/src/main.ts`, `app.on("ready"`, `planBoot`). The window opens when `GET /api/health` answers,
  and loads the dashboard from `http://127.0.0.1:<port>` (`D/src/main.ts`, `resolveWindowUrl`).
- F-18. The embedded server listens on port **7825** (`D/src/server.ts:23`, `BASE_PORT = 7825`). After a
  crash it restarts with backoff on the next port, up to 7834 (`resolvePort`, `BASE_PORT + (restartAttempt % 10)`),
  and gives up after 8 consecutive failures. It is not port 3011.
- F-19. It uses the same Overdeck data as `pan up` (it inherits the environment, so the same `~/.overdeck`).
- F-20. `pan open` talks to the `pan up` dashboard, not the app's embedded server. Already documented in
  `features/open-in-overdeck.mdx` "The desktop app"; link to it, do not repeat it.
- F-21. Only one copy runs. A second launch focuses the running window; `--open <path>` on a second
  launch opens that path (`D/src/main.ts:104`, `requestSingleInstanceLock`; `handleSecondInstance`).
- F-22. Closing the window: on macOS it hides the window and the app keeps running
  (`D/src/main.ts`, search `win.hide()`); on Linux and Windows, closing the last window quits the app and
  stops the embedded server (`app.on("window-all-closed"`).

### Notifications

- F-26. The app shows the dashboard's notifications as native system notifications. They come from the
  frontend's web `Notification` calls, the same as in a browser (Electron approves the permission by

    `src/lib/cloister/memory-pressure-patrol.ts` and `disk-pressure-patrol.ts`, search `desktop: true`).
  Clicking one reopens that question, plan or permission dialog, or focuses the dashboard.
- F-27. **Broken today (#5556):** **Settings → Desktop App → Notifications** has six switches (**Input

### Open another machine (PAN-4402, changelog v0.73.0 #4665)

Facts F-33 to F-38 come from `D/src/machine-url.ts`, `D/src/machine-client.ts`, `D/src/machine-store.ts`,
`D/src/main.ts` and `D/resources/connect.html`.

- F-33. The app can show one other machine's dashboard instead of running the embedded server. It stores
  at most one chosen machine. While it shows it, no embedded server runs.
- F-34. Pair: on the machine, create a pairing link with **Settings → Anywhere → Pair a device** or
  `pan pair --url <its Tailscale address>` (`pan pair --help`). In the app choose **Connect to a
  Machine…** (Overdeck menu or tray), paste the whole link in the **Open another machine** window, and
  click **Connect**. A bare `odp_…` credential is refused with `Paste the whole pairing link, including the address.`
  The machine then lists this computer as `Overdeck desktop on <hostname>` under **Settings → Anywhere →
  Paired devices** (`deviceLabel`; `FE/components/Settings/anywhere/DevicesPanel.tsx`, `Paired devices`). `pan devices list` and `pan devices revoke <id>` manage it from that machine.
- F-35. Allowed addresses (`assessMachineTransport`): any `https:` address; `http:` to loopback
  (`localhost`, `127.0.0.0/8`, `::1`); `http:` to a Tailscale address (`100.64.0.0/10`,
  `fd7a:115c:a1e0::/48`, a name ending in `.ts.net`, or a name that resolves only to such addresses).
  Anything else, such as `http://192.168.1.5:3011`, is refused with `Overdeck sends this computer's
  credential only over HTTPS, Tailscale or this computer's loopback. Use the machine's Tailscale address
  or an HTTPS address.` The check runs at pairing and at every launch.
- F-36. Storage: `remote-machine.json` in the app's user-data folder, written with mode `0600`
  (`D/src/machine-store.ts`, `remote-machine.json` and `mode: 0o600`), with the device
  credential encrypted by Electron `safeStorage` (Keychain on macOS, DPAPI on Windows, GNOME Keyring or
  KWallet on Linux). With no secure store (Linux `basic_text` backend) the app refuses to pair
  (`machine-store.ts`, search `basic_text`). The remote dashboard window uses an in-memory session
  (`D/src/connection.ts`, search `No \`persist:\` prefix`), so its UI preferences and drafts reset each
  launch.
- F-37. Launch checks and messages (`machine-client.ts`, the `...Message` functions; none contain a dash):
  `Can't reach <label> at <origin>. Check that its Overdeck is running and that this computer is on the
  same tailnet.`; `<origin> is now a different Overdeck machine (<new label>). Pair again.`;
  `<label> no longer accepts this computer's credential. Pair again with a new link.`;
  `<label> speaks Overdeck protocol <n>; this app supports <m>. Update the older side.`;
  `This computer's credential store could not decrypt the saved credential. Pair again.`
  On a failed check the connect window opens with the reason and offers **Open `<label>`**, **Use this
  computer** and **Forget `<label>`**. The app never falls back to this computer on its own.
- F-38. **Use This Computer** keeps the pairing and starts the embedded server. **Forget `<label>`**
  revokes the device on the machine, then deletes the local record either way; if the machine is
  unreachable the app says so and you revoke the device in that machine's **Settings → Anywhere →
  Paired devices**.
  While a chosen machine is shown, links to other origins open in your browser, and a dashboard restart
  from the app is refused: restart it on that machine.
