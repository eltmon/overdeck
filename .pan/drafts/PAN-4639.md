# PAN-4639: Snooze, settle and sections in the conversation list

**Issue:** [PAN-4639](https://github.com/eltmon/overdeck/issues/4639)
**Siblings (split during planning):** auto-settle on merge is [PAN-4653](https://github.com/eltmon/overdeck/issues/4653); auto-settle when idle is [PAN-4655](https://github.com/eltmon/overdeck/issues/4655). Both are blocked by this issue and build on the storage it adds.
**Status:** planned 2026-11-01 (`pan plan --auto`, high effort)

## Scope note: what this issue delivers

The issue title says "snooze, settle and auto-settle". During planning the full proposal measured well past the plan size gate (25 files, 6 subsystems), and the two automatic paths are independently shippable once the settled column exists. So this issue delivers the **operator-facing triage surface**:

- the Needs you / Inbox / Snoozed / Settled sections in `ConversationList`,
- settle and unsettle (row checkbox, row menu, tab menu), with undo,
- snooze with presets and a custom time, and unsnooze,
- shift-click and Cmd/Ctrl-click multi-select with a bulk bar,
- the storage (`settled_at`, `settle_reason`, `snoozed_until`) and the one write route.

Auto-settle on merge (replacing `conversations.auto_archive_on_merge`, the per-conversation override, the Settings toggle, the CLI verb) is **PAN-4653**. Auto-settle when idle (`conversations.auto_settle_idle_days`, the sweep) is **PAN-4655**. This issue does not touch `autoArchiveSettledConversations`, `conversations.auto_archive_on_merge`, or `pan conv auto-archive-on-merge`.

## Glossary

- **Conversation list** — `ConversationList` in `src/dashboard/frontend/src/components/CommandDeck/ConversationList.tsx`, fed by `GET /api/conversations`. Rendered from `CommandDeck/index.tsx` and `components/workspace/WorkspaceView.tsx`.
- **Row** — one `ConversationRow` (`CommandDeck/ConversationRow.tsx`). A row is a `<button>`; its inline controls are `<span role="button">` children (the stop control at `ConversationRow.tsx:445`).
- **Top-level row / group** — a node returned by `buildConversationTree` (`CommandDeck/conversation-tree.ts:75`) with `depth: 0`. Its `descendants` are nested rows (lanes, successors), rendered with `variant="nested"`.
- **Settle** — operator marks a conversation done for now. The session keeps running. The row moves to the Settled section. Stored as `conversations.settled_at` (epoch ms) and `conversations.settle_reason`.
- **Settle reason** — `manual` (operator), `merge` (PAN-4653), `idle` (PAN-4655). This issue writes only `manual`, but the column and the route accept all three.
- **Snooze** — operator hides a conversation until a time T. Stored as `conversations.snoozed_until` (epoch ms). The row is in the Snoozed section while `snoozed_until > now`, else in Inbox.
- **Wake** — the moment `now >= snoozed_until`. Decided by the client on every render; no timer, no server job, no write.
- **Triage state** — the triple `{ settledAt, settleReason, snoozedUntil }` for one conversation.
- **Needs you** — a group where the root or any descendant has `pendingInputCount > 0` (the list enrichment's count of open AskUserQuestion / plan-mode / Codex approval surfaces, `conversation-list.ts:256-301`).
- **Section** — one of `needsYou`, `inbox`, `snoozed`, `settled`, top to bottom.
- **Undo stack** — a module-level list (max 20) of triage changes with each row's prior triage state, shared by every `useConversationMutations` instance.
- **Enrichment** — `enrichConversationList` in `src/lib/overdeck/conversation-list.ts:193`, which turns DB rows into the JSON the list renders.

## Decisions

- **D1 — Split.** Auto-settle on merge → PAN-4653; auto-settle when idle → PAN-4655 (see Scope note).
- **D2 — Storage.** Three new nullable columns on `conversations`: `settled_at integer`, `settle_reason text`, `snoozed_until integer`. Added to the init migration and as `runSchemaTopUp` lines. Read and written only through `src/lib/overdeck/conversation-triage-store.ts`. `conversations.ts` is not edited.
- **D3 — Settle and snooze are mutually exclusive in storage.** Settling clears `snoozed_until`. Snoozing clears `settled_at` and `settle_reason`. Unsettle clears `settled_at` and `settle_reason`. Unsnooze clears `snoozed_until`. Re-settling an already settled row keeps its original `settled_at` and reason.
- **D4 — One write route.** `POST /api/conversations/triage`, body `{ updates: TriageUpdate[] }` (1 to 200 entries). It serves single actions, bulk actions and undo.
- **D5 — Snooze wake is client-side.** The server returns `snoozedUntil` raw and never clears it on wake. The client compares it with `useNow(30_000)`. A dashboard restart therefore cannot lose or delay a wake.
- **D6 — Sections are assigned per top-level group, not per row.** Build the tree once over all filtered rows (as today), then place each top-level group:
  1. `needsYou` if the root or any descendant has `pendingInputCount > 0`;
  2. else `snoozed` if the root's `snoozedUntil` is in the future;
  3. else `settled` if the root's `settledAt` is set;
  4. else `inbox`.
  Rationale: PAN-4223 keeps lanes and successors nested under their launcher; settling a launcher must not strand its lanes as orphan rows in Inbox. A row whose parent is filtered out (for example by `includeIds` project scope) is already top-level (`orphanOf`), so its own state applies.
- **D7 — Triage controls render on top-level rows only.** The settle checkbox, the triage menu items and multi-select apply to rows rendered with `variant` other than `'nested'`. The tab/header menu (`ConversationActionMenu`) always shows them, because a tab names one conversation.
- **D8 — Needs-you is display-only.** A settled or snoozed conversation that starts waiting on the operator renders in Needs you; its stored state is untouched; it returns to Settled or Snoozed when the question is answered. New activity never changes stored state. Needs you counts `pendingInputCount` only; the separate store flag `conversationsAwaitingPermissionByName` is not part of the rule.
- **D9 — Section order.** `needsYou` and `inbox` keep the existing order (live first, then the selected sort, then tree rank). `snoozed` orders by root `snoozedUntil` ascending (soonest wake first). `settled` orders by root `settledAt` descending (most recent first).
- **D10 — Section headers.** Needs you shows a header `Needs you · N` when non-empty. Inbox has no header. Snoozed and Settled show a collapsible header `Snoozed · N` / `Settled · N` when non-empty, **collapsed by default**. Expanded state persists per viewer in `localStorage` key `commandDeck.sections.expanded` (JSON array of section ids), wrapped in try/catch like `writeCollapsedGroups` (`ConversationList.tsx:247`).
- **D11 — Undo.** Every triage change pushes `{ label, priors: [{ name, prior: TriageState }] }` onto a module-level undo stack (max 20) in `useConversationMutations.ts`, and shows a sonner toast with an `Undo` action. Undo replays the priors through the same route. `Cmd+Z` (macOS) / `Ctrl+Z` pops the newest entry when the keydown target is inside the list wrapper and is not an `input`, `textarea`, `select` or `contentEditable` element. An undo is itself not pushed.
- **D12 — Snooze presets** (local time, computed by a pure function with an injected `now`):
  - `1 hour` → now + 60 minutes.
  - `This evening` → today 18:00; offered only when now is before 17:00.
  - `Tomorrow morning` → tomorrow 09:00.
  - `Next week` → the next Monday 09:00 strictly after today (a Monday snoozes to the following Monday).
  - `Custom…` → an inline `<input type="datetime-local">` plus a `Snooze` button, disabled while the value is empty or not in the future.
- **D13 — Wake label.** A snoozed row shows `back <when>`: `today HH:MM`, `tomorrow HH:MM`, `<Ddd> HH:MM` within 7 days, else `<Mmm> <D> HH:MM` (24-hour, local).
- **D14 — Multi-select.** Cmd/Ctrl-click toggles one top-level row in the selection and sets the anchor. Shift-click selects the range from the anchor to the clicked row over the visible top-level rows in render order (all sections, collapsed sections excluded); with no anchor it acts like Cmd/Ctrl-click. A plain click clears the selection and opens the row as today. `Escape` clears the selection. Selected rows get the selected style plus `aria-selected="true"`.
- **D15 — Bulk bar.** When the selection is non-empty, a bar renders above the list: `N selected`, `Settle`, `Unsettle`, `Snooze ▾` (the D12 presets except Custom), `Clear`. Each action sends one `POST /api/conversations/triage` with one update per selected row, pushes one undo entry, and clears the selection.
- **D16 — Vault browse rows are read-only.** The route skips rows with `origin = 'vault'` and reports them in `rejected`. The enrichment returns empty triage for browse copies.
- **D17 — Fix the "Last activity" sort here.** `getSortKey('lastActivity')` becomes `conv.lastActivityAt ?? conv.lastAttachedAt ?? conv.createdAt`, because Inbox is ordered "by the selected sort" and the issue flags the bug.
- **D18 — Archive is unchanged.** Archive and unarchive do not read or clear triage columns; an unarchived conversation keeps its stored triage state.

## API contract (FR-3)

```ts
// POST /api/conversations/triage
interface TriageRequest {
  updates: Array<{
    name: string;
    /** true → settle (keeps an existing settled_at); false → unsettle. Omitted → unchanged. */
    settled?: boolean;
    /** Only read when settled === true. Default 'manual'. */
    settleReason?: 'manual' | 'merge' | 'idle';
    /** ISO time → snooze until then (clears settled); null → unsnooze. Omitted → unchanged. */
    snoozedUntil?: string | null;
  }>;
}
interface TriageResponse {
  conversations: Array<{ name: string; settledAt: string | null; settleReason: 'manual' | 'merge' | 'idle' | null; snoozedUntil: string | null }>;
  notFound: string[];
  rejected: Array<{ name: string; reason: 'vault-browse-row' }>;
}
```

Validation (400 with `{ error }`): `updates` missing, not an array, empty, or longer than 200; an entry without a non-empty string `name`; `settled` present and not boolean; `settleReason` not one of the three; `snoozedUntil` present and neither null nor a parseable date string; an entry with `settled: true` **and** a non-null `snoozedUntil`; an entry with neither `settled` nor `snoozedUntil`. Origin check via `validateOrigin` like every conversation route (403).

Undo of a prior state `{ settledAt, settleReason, snoozedUntil }` is sent as `{ name, settled: settledAt !== null, settleReason: settleReason ?? undefined, snoozedUntil }`.

```ts
export interface TriageConversation extends TreeConversation {
  settledAt?: string | null;
  settleReason?: 'manual' | 'merge' | 'idle' | null;
  snoozedUntil?: string | null;
}
export type ConversationSectionId = 'needsYou' | 'inbox' | 'snoozed' | 'settled';
export const SECTION_ORDER: readonly ConversationSectionId[] = ['needsYou', 'inbox', 'snoozed', 'settled'];
export interface ConversationSection<C extends TriageConversation> { id: ConversationSectionId; nodes: ConversationTreeNode<C>[] }

export function isSnoozed(conv: TriageConversation, now: number): boolean;      // snoozedUntil parses and > now
export function groupNeedsYou(node: ConversationTreeNode): boolean;              // root or any descendant pendingInputCount > 0
export function sectionOf(node: ConversationTreeNode<TriageConversation>, now: number): ConversationSectionId; // D6
/** Input: the tree in today's order. Output: all four sections in SECTION_ORDER (empty ones included), D9 ordering applied. */
export function partitionConversationSections<C extends TriageConversation>(nodes: readonly ConversationTreeNode<C>[], now: number): ConversationSection<C>[];
export interface SnoozePreset { id: 'hour' | 'evening' | 'tomorrow' | 'nextWeek'; label: string; until: Date }
export function snoozePresets(now: Date): SnoozePreset[];                      // D12, 'evening' omitted at or after 17:00
export function formatSnoozeWake(untilIso: string, now: Date): string;         // D13, e.g. "back tomorrow 09:00"
```
