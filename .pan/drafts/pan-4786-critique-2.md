## blocks-the-design: Plan lookup errors can authorize the skip

Evidence: [io.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/lib/xbrief/io.ts), lines 85–94, catches every `readdir` error and returns `null`; lines 509–523 then expose that as `findPlan(...) === null`. The proposed helper treats this as proof that no xBRIEF exists, so an adopted workspace with `.pan/specs` present but unreadable (or a regular file, causing `ENOTDIR`) skips the checklist. [done-preflight.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/lib/work/done-preflight.ts), lines 34–39, currently gets `null` and fails the required checklist. `Effect.orElseSucceed` in W1 cannot catch an error already converted to `null`.

Smallest change: make the async spec lookup distinguish a missing directory from a directory read failure, then keep the checklist on the error path. Add an adopted-workspace test where `.pan/specs` exists but `readdir` fails. Update W1's instruction that forbids changing `io.ts` if that is where the distinction is fixed.

## blocks-the-design: In-process coalescing still reuses different options

Evidence: [verification-worker-supervisor.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/lib/cloister/verification-worker-supervisor.ts), lines 395–409, returns `activeSupervisorRuns.get(issueId)` before reaching the proposed `sameOptions` check in `runSupervisedVerificationOnce` (lines 310–343). The review request path uses default sync options ([review-pipeline.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/dashboard/server/routes/workspaces/review-pipeline.ts), lines 274–280); merge verification uses `syncTargetBranch: false` ([merge-strike.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/dashboard/server/routes/workspaces/merge-strike.ts), lines 45–51, and [merge-ops.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/dashboard/server/routes/workspaces/merge-ops.ts), lines 1015–1023). If they overlap in one dashboard process, merge verification receives the review run's promise and never checks its post-rebase head or requested options. The review-request in-flight guard ([request-review-pipeline.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/lib/cloister/request-review-pipeline.ts), lines 25–53) does not guard merge verification. Thus W2b's option-sensitive live join and NFR-4 are bypassed in a real call path.

Smallest change: make the in-process coalescing check options and workspace/head before sharing a promise; route a mismatched request through the worker replacement path or queue it for a fresh run. Add a concurrent review/merge verification test with different options. Remove the non-goal that leaves this map unchanged.
