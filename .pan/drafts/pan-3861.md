# PAN-3861 — Global Herdr / tmux terminal backend

Issue: https://github.com/eltmon/overdeck/issues/3861
Research date: 2026-09-17 UTC. Status: implementation-ready design, with explicit protocol checkpoints.

## Glossary

- Terminal backend: the persistent process/terminal owner, independent of the model and harness.
- Harness: Claude Code, Codex, Pi, OMP or another agent application launched inside that backend.
- Environment: a machine-owned Overdeck server identified by PAN-3762's environmentId.
- Session reference: environment + backend + server namespace + session/pane/terminal IDs; labels are not identity.
- Observer: a terminal viewer without input or resize authority. Controller: a viewer that explicitly acquires that authority.
- Semantic state: Herdr's working/blocked/done observation. It is not an Overdeck review verdict or issue completion.
- Restore: reconstructing a process from saved state. Detach persistence leaves the original process alive.

## Problem and outcome

Overdeck hardcodes tmux through launching, delivery, liveness, browser terminal and recovery. A selector alone would launch Herdr sessions that the rest of Overdeck mistakes for dead. Add a real terminal backend boundary, keep tmux as the default, and make both coexist. Preserve existing tmux sessions when the operator changes the global setting.

PAN-2350's old decision to defer Herdr described an older product and license. Upstream's latest stable release checked through GitHub's latest-release API is v0.9.1, published 2026-09-16T18:40:01Z. Its pinned Cargo.toml and LICENSE say Apache-2.0. This issue supersedes that deferral only; it does not replace Anywhere federation, scoped authentication or mobile access.

## Research and capability disposition

Primary sources: [release](https://github.com/herdrdev/herdr/releases/tag/v0.9.1), [API](https://herdr.dev/docs/socket-api/), [CLI](https://herdr.dev/docs/cli-reference/), [restore](https://herdr.dev/docs/session-state/), [integrations](https://herdr.dev/docs/integrations/), [machines](https://herdr.dev/docs/connecting-machines/). Verify source behavior at the pinned tag; next/preview documentation may contain unreleased material.

| Capability | Decision for Overdeck |
| --- | --- |
| Default/named server sessions, workspace/tab/pane hierarchy | Use a dedicated named `overdeck` Herdr session, map IDs explicitly, enumerate external namespaces separately. |
| JSON socket request/response and schema export | Implement validated async client with correlated request IDs, bounded frames, typed failures and capability probe. Do not mistake correlation IDs for mutation deduplication. |
| Agent detection, explanation, integrations, status events | Display evidence/provenance and time; enrich needs-attention. Existing approval and pipeline truth wins. Never auto-answer a permission prompt from a heuristic. |
| Visible/recent/unwrapped output and wait helpers | Support capture/wait for backend users, bounded output and explicit timeout; prefer event subscriptions over per-pane polling. |
| Read-only terminal session observe; writable control | Use documented CLI NDJSON streams to avoid implementing Herdr's internal binary render protocol. Decode base64 ANSI frames; handle EOF without a close record. |
| Workspace metadata, labels, process info | Annotate Overdeck identity and surface project/role/worktree context. Labels can change without changing identity. |
| Native agent session references and restore | Record references through Overdeck's writer. Disable autonomous native restore in the dedicated managed session so Deacon remains the single recovery owner. Leave external Herdr sessions' policies untouched. |
| Screen-history replay | Leave experimental persistent history opt-in; it is not the transcript or evidence that a process survived. |
| Live handoff | Experimental, explicit operator operation only; never required for a normal launch, reconnect or upgrade. |
| Plugins/actions/custom commands | Discover and display available plugins/actions when supported. Explicit invocation is capability/auth-gated; no auto-install, no mirrored plugin execution on another host. |
| Herdr worktree operations | Display external worktree associations. Overdeck remains sole creator/remover for managed workspaces; do not run two worktree lifecycles. |
| SSH machine profiles and v0.9.1 --machine forwarding | Reuse in PAN-3863. Forwarded API commands do not support interactive terminal attach or session management; use owner-host transport for those. |
| Notifications, layout, mouse/keyboard, graphics | Keep Herdr native TUI available; expose useful notifications and hierarchy in agents-v2. Browser terminal remains limited by its renderer; do not promise native Kitty graphics parity. |

## Requirements

- FR-1: Global `terminal.backend: tmux | herdr`, default tmux, validated in config and visible in Settings. It applies per Overdeck installation/environment, not silently to every saved remote host.
- FR-2: Persist launch-time backend and exact reference for work, strike, planning, specialist, standing-role and conversation sessions; legacy records resolve to tmux. Existing sessions keep their owner across default changes.
- FR-3: Both adapters support create, inspect/list, read output, observe, control/resize, delivery, interrupt, close exact session, and recovery with explicit capability results.
- FR-4: Preserve delivery identity/dedup and transcript echo through deliverAgentMessage; never fall back from a failed remote/Herdr destination to another backend or local session.
- FR-5: Integrate semantic events, native session identity, metadata and output waits without making Herdr authoritative for pipeline outcomes.
- FR-6: Preserve global setting, managed session identity and recovery pointers through restart; only one recovery owner may relaunch a managed agent.
- FR-7: Report missing executable, unsupported protocol, permissions, stream loss and unavailable capability distinctly. Do not install/update/stop a server during a read or background reconnect.
- FR-8: Audit every existing managed tmux operation and map it to the backend boundary or an explicit tmux-only external tool operation.
- FR-9: Expose capability diagnostics and document supported advanced features and deliberate deferrals in the matrix above.
- NFR-1: Async-only server IO, bounded buffers/timeouts, cancellation and listener cleanup.
- NFR-2: No secret exposure through command logs, snapshots or client metadata; use argv and structured JSON, never interpolate user payloads into shell syntax.
- NFR-3: Default/mixed-backend compatibility and recovery safety are release gates; fake timers cover retry paths.

## Chosen design and before/after

Existing spawn imports createSession/sessionExists from src/lib/tmux.ts. Delivery already centralizes supervisor, channels and tmux. Keep that delivery door and insert backend dispatch below it; don't replace reliable supervisor delivery with unverified pane paste.

```ts
// Before (existing dependency)
import { createSession, exactPaneTarget, sessionExists, setOption } from '../tmux.js';
// After (proposed boundary; concrete method schemas live in the contract file)
const backend = yield* terminalBackends.forLaunch(config.terminal.backend);
const session = yield* backend.create({ agentId, cwd, argv, env });
yield* agentWriter.recordTerminalSession(agentId, session.ref);
```

Create `src/lib/terminal-backends/types.ts`, `registry.ts`, `tmux.ts`, `herdr.ts`, `herdr-api.ts`, and `herdr-stream.ts`. Use Effect-returning methods and Schema validation in repository style. Contract ref shape:

```ts
type TerminalSessionRef = {
  environmentId: string;
  backend: 'tmux' | 'herdr';
  serverId: string; // opaque identity; resolve socket privately on owner host
  sessionId: string;
  paneId?: string;
  terminalId?: string;
  generation: string; // distinguishes a replacement server/session incarnation
};
```

The registry resolves persisted refs first; only a fresh launch consults the setting. Socket paths stay server-side. Add optional ref fields to agents/conversations and contract snapshots through their existing writer/schema migration mechanisms. Coordinate durable pointer layout with PAN-3513; do not wait for its cross-machine consumption phase to preserve local launch ownership.

Herdr creates a managed workspace in the existing Overdeck cwd, preserving resolved launcher argv/environment. Choose an argv-capable schema operation such as layout.apply's command array after the contract checkpoint; do not let `agent.start` choose the harness/model itself. If no safe launch path exists for the tested release, keep managed Herdr launch unavailable with a diagnostic; do not fall back to shell interpolation. A creation attempt carries an Overdeck launch token in metadata for reconciliation of ambiguous responses.

For display, spawn `herdr --session overdeck terminal session observe <terminalId>` and parse NDJSON records, then adapt into the existing terminal WebSocket output contract. Explicit Control uses `terminal session control`; takeover requires its own user action. Observer failure closes only that viewer. Bridge browser resize only from the current controller. A stream ending without terminal.closed means lost observation, not process exit.

Existing supervisor/channels are still preferred for managed text delivery. If only Herdr paste is available, use structured commands and capability-tested submission. Preserve the existing keyed delivery receipt semantics. On disconnect after submission with unknown acknowledgment, return delivery-uncertain and reconcile; do not blindly replay a mutating request. Gate managed launch for configurations that cannot meet required delivery semantics.

## Delivery rules and verification

These are implementation briefs, not permission to launch implementation now. Preserve unrelated working-tree changes. Use isolated feature workspaces and the normal Overdeck workflow. Do not change model/harness routing. Keep default reasoning effort high.

All canonical reads and writes go through domain resolvers/writers. Do not add direct SQLite, state-worktree, state.json or tracker accesses in UI/routes. The state writer owns durable commit/push. One Deacon owns each OVERDECK_HOME; never mount a host state directory into a second orchestrator. Server code uses async subprocesses/Effect services, never execSync. Delay/retry tests use Vitest fake timers. Do not delete transcripts, branches, agent directories or user sessions to satisfy a visual test.
