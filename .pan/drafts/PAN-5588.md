# PAN-5588: Queue-level CPU bypass bound for quality-gate admission

**Issue:** [PAN-5588](https://github.com/eltmon/overdeck/issues/5588)
**Follows:** PAN-5520 (bounded CPU wait, `e7eea59bcf5`), PAN-5285 (memory bypass), PAN-4610 (atomic files)

## Glossary

- **Admission root.** The directory `~/.overdeck/verification-workers/admission/` (or `deps.rootDir` in tests). Every local quality gate, local Vitest run and `tsc` lane on the machine queues here.
- **Ticket.** A waiter file `waiter-<ticketId>.json`. Tickets sort FIFO by `createdAt`, then `ticketId`.
- **Head.** The waiter at position 0 of the sorted live tickets.
- **Slot / owner file.** `owner.json` (slot 0) or `slot-<i>.json` (slot i ≥ 1). A gate holding a slot file is running. `taken` in the loop is the set of held slots.
- **Pressured sample.** A `QualityGatePressureSample` with `pressured: true` (utilization ≥ 0.75, or PSI `some avg10` ≥ `resources.quality_gate_psi_start_avg10`, or load per core ≥ 1 without PSI).
- **CPU bypass bound.** `resources.quality_gate_cpu_bypass_minutes` (default 10), resolved per poll as `cpu.bypassMs` by `resolveCpu()`.
- **CPU bypass / `cpuAlone`.** The PAN-5520 path: a head past the bound with no slot held is admitted without sampling CPU, and its handle and owner file carry `cpuBypassed: true`.
- **Own CPU clock.** The ticket field `cpuBlockedSince`: when this waiter, as head, first sampled pressure. Cleared only by its own admission.
- **Queue CPU marker.** NEW in this issue. The file `cpu-blocked-since.json` in the admission root, holding `{"since": <epoch ms>}`. It records when the queue's current CPU-pressure episode began. The value is the injected `now()` clock value, never a file mtime.
- **Unpressured admission.** A successful return from `acquireQualityGateAdmission` with `cpuAlone === false`. Such an admission sampled CPU before and after the settle and both samples were unpressured.
- **Idle queue.** The admission root holds no `waiter-*.json` file and no slot owner file.

## Problem

Under sustained CPU pressure from work outside Overdeck, the queue admits one gate per bound (10 minutes). Each new head starts its own CPU clock, so it waits the full bound again after the previous head proved that "run alone under this pressure" is the accepted behavior. With N waiters, the last waits about N × 10 minutes plus run time. Observed 2026-11-21: four gates that each take seconds to a few minutes (2 `vitest`, 2 `tsc`) waited most of an hour behind six `ffmpeg` encodes plus OBS (PSI `some avg10` 33–37 on 24 cores).

### Root cause (verified against `9f86a20d82e`)

`src/lib/cloister/quality-gate-admission.ts`, lines 890–901 (grep anchor `const cpuSince = ticket.cpuBlockedSince`):

```ts
      const cpu = await resolveCpu()
      const cpuSince = ticket.cpuBlockedSince
      const cpuAlone = position === 0 && taken.size === 0 && cpuSince != null && now() - cpuSince > cpu.bypassMs
      const pressure = cpuAlone ? null : await samplePressure(cpu.psiStartAvg10)
      if (pressure?.pressured) {
        if (position === 0) await markCpuBlocked()
```

`markCpuBlocked()` (lines 696–703, grep anchor `PAN-5520: start our CPU-block clock as head`) sets `ticket.cpuBlockedSince` only for the head. The clock is per ticket, so every new head restarts it. The module header (lines 38–43) says "Under sustained pressure the queue drains one gate at a time"; the intended reading is one gate at a time, not one gate per bound.

## Requirements

### Functional

- **FR-1.** The CPU-pressure episode is a property of the queue. A head that has sampled pressure itself counts its CPU wait from the earlier of its own `cpuBlockedSince` and the queue marker's `since`.
- **FR-2.** When a head records a CPU block (pre-settle or post-settle pressured sample) and no valid marker exists, it writes the marker create-exclusive with `since = ticket.cpuBlockedSince`. A valid existing marker is never overwritten.
- **FR-3.** A head without its own `cpuBlockedSince` never uses the marker. It samples CPU first. So a marker alone never bypasses anything, and a stale marker plus an unpressured sample gives a normal admission.
- **FR-4.** An unpressured admission **of the queue head** (`position === 0`) deletes the marker. The delete runs at the final successful return (after the settle sample and the memory re-check), never on a pre-settle low sample, so a flapping sample cannot reset the queue clock. A later waiter that passes a memory-blocked head and is admitted on low samples does not delete it (see Critique response).
- **FR-5.** A `cpuBypassed` admission does not delete the marker, so the next head starts alone as soon as the slots are empty and it has sampled pressure once.
- **FR-6.** "Alone" is kept: a CPU bypass still requires `position === 0 && taken.size === 0`. Under sustained pressure two gates never hold slots at the same time.
- **FR-7.** *Retired during planning.* It proposed deleting the marker when `release()` left the queue idle. That re-creates the stall for gates that arrive one after another (a verification run's gates re-queue separately; an agent runs `tsc`, then `vitest`): gate 1 releases into an empty queue, the marker goes, and gate 2 waits the full bound again. See D2.
- **FR-9.** A `release()` never touches the marker. A gate that enqueues after the previous gate released, while pressure holds, inherits the episode after one pressured sample.
- **FR-8.** An unparseable marker, or one whose `since` is not a finite number above 0, counts as absent. The next head that records a CPU block replaces it.

### Non-functional

- **NFR-1.** Every marker operation is best effort and never throws out of `acquireQualityGateAdmission` or `release()`. A file-system error on the marker leaves PAN-5520 per-ticket behavior in force.
- **NFR-2.** `src/lib/cloister/quality-gate-admission.ts` stays at or under 1000 lines (`scripts/lint-file-size.sh`, ceiling 1000, file has no allowlist row and is 997 lines on `main`). The allowlist is never raised.
- **NFR-3.** No import cycle (`npm run lint:circular`). The new fs-helper module is a leaf: it imports only `node:fs/promises` and `node:path`.
- **NFR-4.** `quality-gate-cpu.ts` stays light: the `tsc` wrapper (`scripts/tsc-admitted.mjs`, through `gate-admission-run.ts`) and the Vitest globalSetup (`tests/vitest-cpu-admission.ts`) load it. It may import only `node:*` modules, the new fs-helper module, and the lazy `../config-yaml/load.js` it already imports.
- **NFR-5.** Tests use fake timers (`vi.useFakeTimers()`, already set in the file's `beforeEach`), an injected `now` clock and injected `samplePressure`. No real delays (repo rule: fake timers for retry/backoff/delay tests). Never add `.skip`, `.only` or `skipIf`, and never write a test that reads source files (both fail repo lint gates).

## Decisions

- **D1 (FR-3, resolves an issue-text gap).** The issue's step 2 ("the head computes `cpuSince` as the earlier of its own `cpuBlockedSince` and the queue marker") would let a stale marker bypass a head that never sampled, breaking the issue's own AC "a stale marker plus an unpressured sample does not bypass anything". Rule: `cpuSince = ticket.cpuBlockedSince == null ? undefined : Math.min(ticket.cpuBlockedSince, markerSince ?? Infinity)`. Cost: a new head spends one extra poll (`pollMs`, 1 s by default) sampling once before it inherits the episode.
- **D2 (FR-9).** The marker is deleted only by an unpressured admission, as the issue's step 3 says, and survives everything else (issue step 5). Clearing it when the queue goes idle was considered and rejected: gates that arrive in sequence rather than overlapping would each wait the full bound again. Consequence, accepted: after pressure ends with no gate admitted (nobody sampled), a later pressure episode lets its first head bypass after one pressured sample instead of the full bound (hazard H3).
- **D3.** The marker helpers live in `src/lib/cloister/quality-gate-cpu.ts` (the CPU-rule module, 36 lines). 
- **D4 (NFR-2).** Before any feature change, extract the private fs primitives of `quality-gate-admission.ts` into a new leaf module `src/lib/cloister/quality-gate-admission-files.ts`. Both the admission module and the marker helpers import it. Exporting them from `quality-gate-admission.ts` instead would make `quality-gate-cpu.ts` import the admission module, which imports `quality-gate-cpu.ts`: a cycle.
- **D5 (revised after critique).** The CPU-bypass log lines attribute the wait to the queue, because a gate that inherits the episode did not wait the bound itself. `cpuBypassedMessage(subject)` in `src/lib/cloister/gate-admission-run.ts` (line 81–83) and the `onLog` line in `src/lib/cloister/validation.ts` (line 502) change wording (WI-5).
- **D6.** The docs heading `### CPU and memory admission (PAN-4311, PAN-4546, PAN-5248, PAN-5285, PAN-5520)` in `docs/PIPELINE-GATES.md` is not renamed, because line 119 links to its anchor. PAN-5588 is named in the bullet text instead.
- **D7.** `readQualityGateQueue()` (the Flywheel snapshot) does not report the marker. Out of scope.

**Add** (after `resolveQualityGateCpuSettings`):

```ts
/** PAN-5588: the queue's CPU-pressure episode, `{"since": <epoch ms>}`, in the admission root. */
export const QUEUE_CPU_MARKER_FILE = 'cpu-blocked-since.json'

function validSince(value: unknown): number | null {
  const since = (value as { since?: unknown } | null)?.since
  return typeof since === 'number' && Number.isFinite(since) && since > 0 ? since : null
}

/** When the queue's CPU block began, or null when there is none or the marker is unreadable (FR-8). Never throws. */
export async function readQueueCpuBlockedSince(root: string): Promise<number | null> {
  try {
    return validSince(await readJson(join(root, QUEUE_CPU_MARKER_FILE)))
  } catch {
    return null
  }
}

/**
 * Start the queue's CPU block at `since` unless a valid one is recorded (FR-2).
 * Published create-exclusive, so of two heads racing, the first marker stays.
 * An invalid marker is replaced (FR-8). Never throws (NFR-1).
 */
export async function markQueueCpuBlocked(root: string, since: number): Promise<void> {
  const path = join(root, QUEUE_CPU_MARKER_FILE)
  try {
    let raw: string | null = null
    try {
      raw = await readFile(path, 'utf8')
    } catch (error) {
      if (!isErrnoException(error) || error.code !== 'ENOENT') return
    }
    if (raw !== null) {
      let parsed: unknown = null
      try { parsed = JSON.parse(raw) } catch { /* invalid: replace it */ }
      if (validSince(parsed) != null) return
      await unlinkIfExists(path)
    }
    await publishExclusive(path, { since })
  } catch {
    // EEXIST (another head won) or any fs error: best effort.
  }
}

/** End the queue's CPU block (FR-4). Never throws. */
export async function clearQueueCpuBlock(root: string): Promise<void> {
  try {
    await unlinkIfExists(join(root, QUEUE_CPU_MARKER_FILE))
  } catch {
    // Best effort.
  }
}
```

Imports: `readFile` from `node:fs/promises`, `join` from `node:path`, and `isErrnoException, publishExclusive, readJson, unlinkIfExists` from `./quality-gate-admission-files.js`. Update the file header to say it also holds the queue CPU marker (PAN-5588).
