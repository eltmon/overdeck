# PAN-5649: Opening an idle-stopped workspace app starts its stack again

**Issue:** [PAN-5649](https://github.com/eltmon/overdeck/issues/5649) (split from [PAN-5250](https://github.com/eltmon/overdeck/issues/5250) during planning)
**Builds on:** PAN-5250 (merged at `a0c59af036b`): the idle stop, `wakeWorkspaceStack`, `pan workspace up`. PAN-5623: `stack.reclaimed` / `stack.restored`, the restore door, `stackHealth.reclaimed`.

## Glossary

- **Workspace app host.** The HTTPS host a workspace's frontend answers on, for example `feature-pan-5649.overdeck.localhost` or `feature-min-1145.myn.localhost`. The first DNS label is always `feature-<issue id, lower case>`.
- **Label router.** The Traefik router a running frontend container declares in its Docker labels, for example `traefik.http.routers.pan-fe-feature-pan-5649.rule=Host(\`feature-pan-5649.overdeck.localhost\`)` (`infra/.devcontainer-template/docker-compose.devcontainer.yml.template:131`). It disappears when the container stops. Traefik gives a router with no explicit priority the length of its rule as priority.
- **Label host.** The host inside a label router's `Host(\`…\`)` rule whose first label is `feature-<issue lower>`. Read from the labels of the issue's compose-project containers (running or exited).
- **Wake router.** New Traefik router `overdeck-workspace-wake`, `priority: 1`, rule `HostRegexp(\`^feature-[a-z0-9]+-[0-9]+\..+$\`)`, with middleware `overdeck-workspace-wake-marker` that sets the request header `X-Overdeck-Wake-Router: 1`, routed to the dashboard API port. It only answers when no label router matches the host, that is, when the app's frontend is stopped.
- **Marker header.** `x-overdeck-wake-router: 1`. Traefik's `headers.customRequestHeaders` overwrites any client-sent value, so a request through Traefik carries it only when the wake router matched.
- **Wake host request.** A request reaching the dashboard server that carries the marker header and whose `Host` header (port stripped, lower case) matches `^feature-[a-z0-9]+-[0-9]+\.[a-z0-9.-]+$`. The dashboard consumes every such request in the wake handler; none reaches the dashboard's own routes. A request with a `feature-…` Host but no marker is not a wake host request and reaches the dashboard exactly as today (this matters: the overdeck frontend's Vite `/ws` proxy has no `changeOrigin`, so a workspace's own dashboard server receives `/ws` upgrades with `Host: feature-pan-N.overdeck.localhost`).
- **Wake domains.** The set of domains a wake host may use: `config.traefik.domain` (default `overdeck.localhost`) plus every registered project's `workspace.dns.domain` (`~/.overdeck/projects.yaml`).
- **Wake page.** The HTML page the dashboard serves on a wake host while the app is stopped.
- **Status path.** `/__overdeck_wake/status` on the wake host. Answered by the dashboard with JSON and the header `x-overdeck-wake: 1` while the wake router serves the host. Once the label router is back, the same path reaches the app instead, so a response without that header means the app answers.
- **Waking request.** A wake host request that may start containers: a request with no `Sec-Fetch-Mode` header (curl, Playwright's request API, scripts) or with `Sec-Fetch-Mode: navigate` (a browser page load, including Playwright `page.goto`). Every other request (subresources, `fetch`, Vite HMR pings, WebSocket upgrades) never starts containers. A request with `Accept: text/x-vite-ping` is never a waking request.
- **Wake coordinator.** In-memory per-issue record in the dashboard that runs `wakeWorkspaceStack` at most once at a time per issue and caches the outcome for 15 s.
- **Trusted local caller.** `isTrustedLocalCaller` (`src/dashboard/server/routes/dashboard-auth.ts:481`): a loopback peer, or the host-local Traefik on a Docker bridge whose rightmost `X-Forwarded-For` is local; never a Tailscale Funnel request. The same rule mints a full dashboard session.
- **Start-app action.** New button in the Command Deck issue row that replaces the `app ↗` link while the app is stopped.

## Problem

PAN-5250 stops a workspace's `frontend`/`fe`/`dev` containers after 20 unused minutes. A stopped frontend container removes its label router, so `https://feature-<issue>.<domain>` answers with Traefik's bare 404. Today only `pan workspace up <ISSUE>`, a spawn or a verification start brings it back. Three users hit the 404:

1. The operator opening the app from a bookmark or the `app ↗` chip.
2. A work agent's own Playwright or `curl` check against its frontend (issue comment, 2026-11-23).
3. The Command Deck: the `app ↗` chip (`src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureAppLink.tsx`) keeps rendering a link to the 404 while only the frontend is stopped, because the reclaim-aware health read reports the stack healthy (trace in "Verified code references").

There is also a pre-existing host mismatch on this machine. `projects.yaml` gives the overdeck project `workspace.dns.domain: pan.localhost`, so the dashboard's `frontendUrl` for a PAN workspace is `https://feature-pan-N.pan.localhost` (`workspace-data.ts:528`), while the overdeck compose template routes `feature-pan-N.overdeck.localhost`. The chip has pointed at a host no router serves. The wake handler redirects to the label host (FR-6), which fixes this for every project without touching operator config.

## Requirements

### Functional

- **FR-1 Wake router.** Overdeck writes `~/.overdeck/traefik/dynamic/workspace-wake.yml` with one router `overdeck-workspace-wake` (`priority: 1`, rule per glossary, `entryPoints: [websecure]`, `tls: {}`) one middleware `overdeck-workspace-wake-marker` (`headers.customRequestHeaders: { X-Overdeck-Wake-Router: "1" }`) attached to that router, and one service `overdeck-workspace-wake` → `http://host.docker.internal:<dashboard.api_port>`. `generateOverdeckTraefikConfig` writes it (so `pan install`, `pan up`, `pan dev` do), and the dashboard server writes it at startup when the content differs (so a `pan reload` deploy carries it without a `pan up`).
- **FR-2 Consumption.** Every wake host request (marker header present) is handled by the wake handler and never passed to the dashboard's HTTP routes or any WebSocket upgrade handler (`/ws/terminal`, linked, forward, knowledge viewer, Effect). A request without the marker header is passed through unchanged, whatever its Host.
- **FR-3 Trust.** A wake host request from a caller that is not a trusted local caller gets `404` with body `Not found` and causes no Docker call.
- **FR-4 Host validation.** A wake host request is for issue `I` only when: the host's domain (everything after the first label) is in the wake domains; `parseIssueId(<label minus "feature-">)` succeeds; `resolveProjectFromIssueSync(I)` returns a project. Otherwise `404` with an HTML/plain body `No Overdeck workspace answers at <host>.` and no Docker call.
- **FR-5 Waking requests only.** Only a waking request may call the wake coordinator. A non-waking request on a valid wake host gets `503`, `Retry-After: 5`, `x-overdeck-wake: 1`, `Cache-Control: no-store`, an empty body, and no Docker call. A WebSocket upgrade on a wake host is refused with `503` and the socket is destroyed (Vite 8's reconnect ping is a `vite-ping` WebSocket, so a stale tab's ping fails and never reloads the tab). A request with `Accept: text/x-vite-ping` (the `no-cors` fetch ping of older Vite clients, which resolves on any response and then reloads the tab) gets its socket destroyed with no response, so it fails the same way.
- **FR-6 Label-host redirect.** For a waking request, when the issue's label host is known and differs from the request host, the handler answers `307` to `https://<label host><original path and query>` without waking. The redirected request then wakes.
- **FR-7 Wake response.** Otherwise the handler asks the coordinator to wake the issue with trigger `browser` and answers at once (it does not wait for the wake): status `503`, `Retry-After: 5`, `Cache-Control: no-store`, `x-overdeck-wake: 1`. When `Accept` contains `text/html`, the body is the wake page; otherwise `text/plain` `Workspace app for <ISSUE> is starting (it was stopped after being unused). Retry in a few seconds.` A `no-stack` or `failed` coordinator state changes the message (FR-9) but keeps the status `503`.
- **FR-8 Status path.** `GET /__overdeck_wake/status` on a valid wake host returns `200` JSON `{ issueId, state, message, appUrl }` with `x-overdeck-wake: 1` and never wakes. `state` is `idle | starting | started | failed | no-stack`. `appUrl` is `https://<label host>` or `null`.
- **FR-9 Wake page.** Self-contained HTML (inline CSS and script, no external requests). Text: `This workspace's app was stopped after being unused. Starting it…` plus the issue id. Every 2 s it fetches the status path (`cache: 'no-store'`). When a response lacks `x-overdeck-wake` and its status is not 502, 503 or 504, it calls `location.reload()`. `failed` shows the error and `Run pan workspace up <ISSUE> in a terminal.`; `no-stack` shows `<ISSUE> has no Docker stack to start.`; `started` for more than 120 s while the page still polls shows `The containers started, but the app has not answered after 2 minutes.` with the same command hint.
- **FR-10 Coordinator.** One in-flight `wakeWorkspaceStack` per issue; a second request during it joins it. A finished outcome is reused for 15 s (`WAKE_RESULT_TTL_MS = 15_000`); after that, the next waking request starts a new wake. Label hosts are cached per issue for 60 s (`APP_HOST_TTL_MS = 60_000`). The coordinator never throws.
- **FR-11 REST route.** `POST /api/workspaces/:issueId/wake` (auth `rejectUnsafeDashboardMutationRequest`; no `route-scopes.ts` row, so registry credentials need `admin`, D13) runs the coordinator with trigger `dashboard`, awaits the outcome and answers: `200 { state: 'started', started, alreadyRunning, appUrl }`; `400` for an invalid issue id; `404 { error }` for `no-stack`/`no-workspace`; `409 { error }` for `no-stack`/`no-compose-project`; `500 { error }` for `failed`.
- **FR-12 Start-app action.** In `FeatureAppLink`, with `frontendUrl` set: when `stackHealth.reclaimed` is non-empty, or the stack summary state is `stopped`, the row shows a `start app` button instead of the `app ↗` link. Clicking it opens `frontendUrl` in a new tab synchronously (inside the click handler), then POSTs FR-11. While the POST runs the button reads `starting…` and is disabled. Success shows a toast and invalidates the `['workspace', issueId]` query; failure shows the route's error in a toast. Other states keep today's behavior (table in WI-6).
- **FR-13 Triggers.** `StackRestoreTrigger` gains `'browser'` and `'dashboard'`. Journal entries and activity entries name them (`stack-restore:browser`, `Started … (browser).`).
- **FR-14 Activity text.** The idle-stop activity entry tells the operator that opening the app URL starts it again.
- **FR-15 Other projects.** Covered when the project's workspace hosts are served by the managed `overdeck-traefik` container (verified 2026-11-23: one Traefik serves `*.overdeck.localhost`, `*.myn.localhost`, `*.auricle.localhost`; `tls.yml` lists all three wildcard certificates). The wake router's regexp is domain-agnostic; the dashboard limits it to wake domains (FR-4). A project that runs its own Traefik is not covered (NonGoal).
- **FR-16 Documentation and changelog** (WI-8).

### Non-functional

- **NFR-1 Fake timers** for the coordinator's TTLs and any delay test (`vi.useFakeTimers()`, `vi.advanceTimersByTimeAsync`); repo rule `fake-timers-for-retry-tests`.
- **NFR-2 No synchronous child processes** in dashboard-reachable code (`no-execsync-server`). Docker calls use promisified `execFile` with an argument array through `resolveHostTool('docker')` and a 10 000 ms timeout, like `runDocker` in `src/lib/workspace/stack-reclaim-docker.ts`. The startup write of `workspace-wake.yml` uses `fs/promises`.
- **NFR-3 Safety of the wake.** The handler only ever calls `wakeWorkspaceStack`, which starts only exited containers of the issue's own compose project whose service is wakeable (PAN-5250 D11). No new Docker verb is introduced. Container names reaching `docker inspect` pass `CONTAINER_NAME_RE`.
- **NFR-4 File-size ratchet.** `scripts/lint-file-size.sh`: no file may grow past its `origin/main` count when it is over 1000 lines, or past its allowlist cap. `FeatureItem.tsx` is 973 lines (cap 1351); `src/dashboard/server/main.ts` is not touched. Never raise a cap.
- **NFR-5 Import hygiene.** `src/lib/workspace/workspace-wake-host.ts` imports nothing from `src/dashboard/`. The dashboard server must not import `src/lib/traefik.ts` (it imports `child_process`); it imports the pure renderer from `workspace-wake-host.ts`. `npm run lint:circular` passes.
- **NFR-6 No reflected markup.** The wake page inserts only the validated issue id and host, HTML-escaped. Response header `Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; connect-src 'self'; base-uri 'none'; form-action 'none'`.

## Design decisions

- **D1. Auth model: trusted local caller, no credential.** The knowledge viewer's `?access=` token model cannot work here: a bookmark, an agent's `curl`, or Playwright has no token, and the operator's comment requires those to wake the stack. The wake handler therefore accepts only trusted local callers (FR-3), the same rule that mints a full root session; a wake grants strictly less. Because the raw `server.on('request')` wrapper runs before the Effect app, the remote request gate never sees these requests, so the handler gates itself. A Tailscale Funnel request is never trusted. The handler does nothing but start the issue's own existing containers through `wakeWorkspaceStack` (NFR-3).
- **D2. Only waking requests start containers.** Cross-site `<img>` tags, favicon and asset loads are not navigations, so they never wake (FR-5). A stale tab's Vite reconnect ping is a WebSocket (Vite 8) or an `Accept: text/x-vite-ping` fetch (older Vite); both fail on a wake host (FR-5), so the client never reloads the tab and never turns the ping into a navigation. A top-level navigation, including a cross-site one (the dashboard on `overdeck.localhost` opening `*.myn.localhost` is cross-site), does wake: it is the user's or agent's explicit intent. The residual risk (a site the operator visits navigates a tab to an app URL) starts a stopped container, which is exactly what opening the URL is meant to do.
- **D3. A browser wake restores memory reclaims too.** `wakeWorkspaceStack` runs the restore door over the whole open reclaim, including `gate-starvation` entries (for example a stopped `api`). The app needs them, and a stale tab cannot trigger it (D2), so the `browser` trigger behaves like `pan workspace up`. A memory reclaim that is still starved may stop the api again later; that needs another explicit navigation to undo, so there is no automatic cycle.
- **D4. Answer at once with 503.** The handler never holds the request while containers start. `503` + `Retry-After: 5` makes `curl -f` fail until the app answers (a `200` would let a check pass against the wake page), `curl --retry` retries it by default, and Playwright `page.goto` does not throw on a 503, so the page's script reloads into the app.
- **D5. Readiness = "the dashboard no longer answers the status path".** While the frontend is stopped or starting, Traefik keeps routing to the wake router (Traefik's Docker provider drops a container whose healthcheck is `starting`), or, for a container without a healthcheck, routes to the container and answers 502 until Vite listens. The page treats 502/503/504 as "not yet" and any other response without `x-overdeck-wake` as "the app answers".
- **D6. Separate dynamic file, written by two paths.** Rendering into `overdeck.yml.template` would reach the live host only on `pan up`/`pan install`/`pan dev`; `pan reload` (the deploy path) never renders Traefik config. A separate `workspace-wake.yml` with no mode-dependent content is written by `generateOverdeckTraefikConfig` and by the dashboard at startup, from the same pure renderer, with the same content (`config.dashboard.api_port`). Traefik's file provider watches the whole `dynamic/` directory, so no Traefik restart is needed.
- **D7. Domain-agnostic regexp, dashboard-side domain check.** One router covers every project domain served by this Traefik and needs no re-render when a project is added. It is anchored on `^feature-`, so it cannot shadow `knowledge-…`, `artifacts.…` or `api-feature-…` hosts. The dashboard rejects domains outside the wake domains (FR-4).
- **D8. Redirect to the label host.** The wake handler reads the label host from the compose project's container labels (`docker inspect --format '{{.Name}}\t{{json .Config.Labels}}'`). When the request host differs (the overdeck `pan.localhost` mismatch, or any `dns.domain` that disagrees with the compose template), it redirects before waking, so the reload lands where the label router will answer.
- **D9. New route instead of `POST /api/workspaces/:issueId/stack/start`.** That route runs `docker compose start` for every service with no stack lock and no `stack.restored` entry, so the open reclaim stays open and the health leniency keeps hiding the containers. The new route goes through the wake door. It lives in a top-level `routes/` file so the no-loss matrix test enforces its row.
- **D10. The chip opens the tab first.** `window.open` after an awaited fetch is blocked as a popup. The click handler opens `frontendUrl` synchronously; that tab lands on the wake page (the containers are still stopped when the navigation arrives), which waits and reloads into the app. The POST runs in parallel; the coordinator joins both into one wake.
- **D12. Dispatch on a Traefik-set marker header, not on Host alone.** Each overdeck workspace stack runs this same dashboard server, and its frontend's Vite proxy forwards `/ws` with the browser's `feature-…` Host. Host-shape dispatch would swallow every workspace dashboard's WebSockets. The marker header is set by the wake router's middleware only, so requests that did not come through the wake router behave exactly as today.
- **D13. No `route-scopes.ts` row.** Unlisted routes need `admin` (`route-scopes.ts:3`), which every dashboard browser session holds. Any row, even an explicit `admin` one, must also be added to `TELEMETRY_CLIENT_ROUTES` in `packages/contracts` and to `docs/TELEMETRY.md` (`route-scopes.test.ts:82`), for a route only the desktop Command Deck calls. Phone and connector tokens therefore cannot wake a stack; a later issue can add an `operate` row with its telemetry entries.
- **D14. Wiring order.** `setupWorkspaceWakeHost` runs right after `holdRequestsUntilServed` and before `setupTerminalWebSocket`, so its `server.on` patch wraps every later `request` and `upgrade` listener, including the terminal, linked, forward and knowledge-viewer handlers' own `originalOn` registrations.
- **D11. Show `start app` also for a fully stopped stack.** The old reaper stops containers without a journal entry, so `reclaimed` is empty, but the stack summary is `stopped`. The wake door starts those too (PAN-5250 D11), so the button appears for `stopped` as well. `unhealthy` keeps today's behavior (no chip): a crashed stack is not something to paper over with a start button.

## NonGoals

- Projects whose workspace hosts are served by a Traefik other than the managed `overdeck-traefik` container.
- Waking from `api-feature-<issue>` hosts or any host not starting with `feature-`.
- Changing the operator's `projects.yaml` (`pan.localhost` for overdeck); the label-host redirect works around it.
- Changing `workspace-data.ts`'s `frontendUrl` derivation.
- Waiting server-side for the app to be ready (the wake page and `Retry-After` do the waiting).
- A wake from subresource, `fetch`, or WebSocket requests.
- Any credential or token for the wake host.
- Changing the old reaper, the idle stop rules, or the restore door's container selection.
- Teaching work agents a role-prompt change; the app URL itself now wakes the stack.
- Changing `overdeck.yml.template`.
- A `route-scopes.ts` row (and its telemetry client-route entries) for the wake route; registry credentials need `admin` (D13).

## Hazards

- **H1. `main.ts` is at 997 of 1000 lines.** Nothing goes there; wiring is in `server.ts`.
- **H2. Consumed hosts.** Only marked requests are consumed (D12). Unmarked `feature-…` Hosts do reach the dashboard today: a workspace's own dashboard server gets them on `/ws` through Vite's proxy. Never widen dispatch to Host shape alone.
- **H3. Traefik regexp escaping.** A wrong escape makes Traefik drop the whole file with a log error, which only loses the wake router (the file is separate from `overdeck.yml`). WI-2's checkpoint checks it live.
- **H4. A frontend without a healthcheck** gets routed by Traefik as soon as it runs, so the page sees 502 for a few seconds; `wakePollDecision` waits on 502.
- **H5. Popup blocking.** `window.open` must stay the first statement in the click handler, before any `await`.
- **H6. `pan sync-main` auto-commits the dirty tree** (project memory `pan-sync-main-commits-dirty-tree`): commit item work first.
- **H7. Frontend node_modules** in a workspace can break after a verification run (project memory `frontend-node-modules-dangling-after-verification`); `bun install` repairs it.
