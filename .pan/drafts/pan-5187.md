## 1. Summary

This issue ships the editing half of the file explorer:

1. A **code pane** (`paneType: 'code'`) that opens one file of an explorer root in Monaco, with syntax highlighting for every Monaco language, preview tabs, a Changes view (diff against `HEAD`), word wrap, and a markdown Edit / Preview toggle.
2. **Autosave** 1,000 ms after the last keystroke and on blur, plus `Ctrl/Cmd+S`, through a per-file save queue. Every write carries the **disk signature** the editor last loaded or saved.
3. **Conflict handling** with Orca parity: clean panes reload when the file changes on disk; dirty panes show a banner with **Compare**, **Reload from disk**, **Keep my edits** and **Overwrite**; deletes and renames on disk are marked; the pane's own writes never trigger the banner.
4. The server **write services** the explorer needs: write (with the signature precondition, atomic), create, rename/move, copy, delete to the Overdeck trash, and restore from it.

The file tree, quick open and search are child B. Viewers for binary and large files are child D1. The tree's file-action UI and undo are child E. Edit workspaces (writing from a `project` root) are child F.

- **Draft** — the in-memory text of a code pane, keyed by `(rootId, path)`, held in a module-level zustand store so it survives the pane unmounting. A draft has a **base**: the text and signature last loaded from or saved to disk. The draft is **dirty** when its text differs from its base text.

- **Preview pane** — a code pane with `explorerPreview: true`. Each root has at most one. A single-click open reuses it; the first edit, a double click or **Keep open** makes it permanent. Its tab label is italic.
- **External-change state** — per code pane: `clean`, `changed` (the disk has content the pane did not write, and the pane is dirty), `deleted`, or `renamed` (with the new path).
- **Child B outputs** — the frontend modules PAN-5186 creates, which this issue imports (names from `.pan/drafts/pan-5186.md`; D-C1's rule applies if B's merged names differ):

## 3. Decisions

Parent decisions D-1 to D-14 hold. These refine them for this issue.

- **D-C1 Build on child A's names; verify them after merging main.** Child A is not merged at planning time. Before the first item, the work agent merges `origin/main` (A must be merged; the order book makes this issue wait for it) and confirms each name in §2 "Child A outputs" exists. **Implementation checkpoint:** if A exported a function or file under a different name, use A's name everywhere this PRD says the parent's name, and say so in the PR description. If an export this PRD needs does not exist at all (for example A put the 5 MiB threshold inline), define it in the file this PRD names for it. Never re-implement something A already exports.
- **D-C2 Replace A's handler stubs; verify the no-loss rows.** The no-loss-matrix test reads `packages/contracts/src/rpc.ts` and fails for any RPC method without a row (`tests/unit/lib/overdeck/no-loss-matrix.test.ts`, search `The following RPC methods exist`), so child A must already have rows for all 14 explorer methods. This issue sets the `door` of the six write rows to `Explorer write door (src/dashboard/server/services/explorer/write.ts, PAN-5187)` (trash rows: `.../trash.ts`) and keeps `disposition: 'WRITE'`. If a row is missing, add it in that form next to the other explorer rows.
- **D-C3 Writes follow symlinks inside the root.** When the write target is a symlink that resolves inside the root (A's `resolveInsideRoot` already refuses one that resolves outside), `writeFile` writes the symlink's real target: the temp file goes next to the real path and is renamed over it, so the link stays a link. This is what every editor does. A **dangling** symlink (its target is missing, so `realpath` throws `ENOENT`) is refused with `NOT_FOUND` and the message "Symlink target does not exist"; the service never resolves a link with `readlink`.
- **D-C4 The precondition table is exact.** `writeFile(root, rel, text, expectedSignature, allowMissing)`:

  | File on disk | `expectedSignature` | `allowMissing` | Result |
  |---|---|---|---|
  | exists | `null` | any | write (explicit Overwrite) |
  | exists | equals current signature | any | write |
  | exists | differs | any | `DISK_CONFLICT` |
  | missing | `null` | any | create the file (and missing parent dirs) |
  | missing | a string | `true` | create the file (and missing parent dirs) |
  | missing | a string | `false` | `DISK_CONFLICT` |

  The check-then-rename is not atomic against another process writing between the two steps. That race is accepted (Orca has the same window) and documented.
- **D-C5 Text over 5 MiB is refused on write** with `FILE_TOO_LARGE`, measured as `Buffer.byteLength(text, 'utf8')`. Use A's threshold constant if `read.ts` exports one (search `5 * 1024 * 1024` in `services/explorer/`); otherwise export `MAX_EDITABLE_TEXT_BYTES = 5 * 1024 * 1024` from `write.ts`. The parent D-12 payload checkpoint applies. **Implementation checkpoint:** unit tests have no WebSocket, so check the frame size once by hand: start `npm run dev`, open a 4.9 MiB text file of an issue workspace in a code pane (seeded as in §10), type one character, and confirm the autosave succeeds. If the WebSocket refuses the frame, lower the constant to the largest whole MiB that passes and report the value in the PR description.
- **D-C6 Trash layout.** The parent glossary puts the moved entry directly under the trash entry directory, which collides with `.overdeck-trash.json` when the deleted path itself is named `.overdeck-trash.json`. So the payload goes under `files/`:
  ```
  <OVERDECK_HOME>/trash/<root-slug>/<stamp>-<n>/
    .overdeck-trash.json        { "rootId": "issue:PAN-1", "path": "src/a.ts", "trashedAt": "2026-11-13T14:27:11.946Z" }
    files/<relative path>       the moved file or folder
  ```
  - `<root-slug>` is the root id with every character outside `[A-Za-z0-9._-]` replaced by `-` (so `issue:PAN-1` → `issue-PAN-1`).
  - `<stamp>` is compact ISO-8601 UTC, `new Date(now).toISOString().replace(/[-:.]/g, '')` → `20261113T142711946Z`.
  - `<n>` is the index of the path within one `explorerDelete` call (0, 1, 2…). If the directory already exists (two calls in the same millisecond), increment `n` until it does not.
  - The trash id returned to the client is `<root-slug>/<stamp>-<n>`.
  - `OVERDECK_HOME` is read with `getOverdeckHome()` from `src/lib/paths.ts` (search `export function getOverdeckHome`), not the module-load constant, so tests can point it at a temp dir. The root `vitest.config.ts` setup `tests/setup/overdeck-home.ts` already sets one, and `tests/setup/no-real-home-writes.ts` throws on writes into the real home.
- **D-C7 `explorerRestore` trusts nothing from the client.** The trash id must match `^[A-Za-z0-9._-]+/\d{8}T\d{9}Z-\d+$`, and its first segment must equal the slug of the request's root; otherwise `NOT_FOUND`. The manifest's `rootId` must equal the request's root id. The manifest's `path` is resolved again with `resolveInsideRoot(root, path, { forWrite: true })`, so a tampered manifest cannot write outside the root or into `.git`. If anything now exists at the path (`lstat` succeeds), `ALREADY_EXISTS`.
- **D-C8 Delete validates every path before moving any.** `trashPaths` resolves and `lstat`s all paths first; any failure throws before anything moves. Paths nested under another path in the same call are dropped (deleting `a` already deletes `a/b`). If a move then fails mid-way (a rare I/O error), earlier entries stay in the trash and the error is thrown; they are recoverable from the trash directory by hand. `pruneTrash` runs first and its errors are logged with `console.warn('[explorer-trash] prune failed', err)` and swallowed, so a prune failure never blocks a delete.
- **D-C9 One move helper with the EXDEV fallback.** `moveEntry(from, to, ops?)` in `write.ts` does `rename`; on `EXDEV` it does `cp(from, to, { recursive: true, errorOnExist: true, force: false, verbatimSymlinks: true })` then `rm(from, { recursive: true, force: true })`. `rename` and `trash` both use it. The `ops` parameter (`{ rename, cp, rm }`, defaulting to `fs/promises`) exists only so `write.test.ts` can simulate `EXDEV`.
- **D-C10 Moving or copying a folder into itself is refused** with a new error code `INVALID_TARGET` (target equals the source, or starts with `source + '/'`). Add `'INVALID_TARGET'` to `EXPLORER_ERROR_CODES` in `packages/contracts/src/explorer.ts`. A case-only rename (`a.ts` → `A.ts`) where `lstat` of both paths returns the same `dev` and `ino` is allowed, not `ALREADY_EXISTS`.
- **D-C11 New entries report `ignored: false`.** `create`, `rename` and `copy` return an `ExplorerEntry` built by `statEntry(root, rel)` in `write.ts` (`lstat` → `{ name, path, kind, size, mtimeMs, ignored: false }`). If A's `read.ts` exports a single-entry builder, use it instead. The tree re-lists on the watcher event that follows, which corrects `ignored`.
- **D-C12 `project` roots open read-only in this issue.** `explorerReadFile` returns `writable: false` for them, and every write to them returns `EDIT_WORKSPACE_REQUIRED` (A's `resolveInsideRoot`). Until child F adds edit workspaces, the code pane shows a `project` file with Monaco `readOnly: true` and a one-line note: "Read-only: the main checkout is never edited directly." Child F replaces this with editable drafts that create an edit workspace on first save. No save path in this issue ever targets a `project` root.
- **D-C13 Stage and tree items wait for child B.** Child B adds the `'code'` pane type, its fields, labels and icon, `openCodePane`, the watch hub and the tree (see §2 "Child B outputs"). This issue builds on them and never re-creates them, so the two children never add the same lines to `panesStore.ts`, `Stage/index.tsx` or `PaneBar.tsx`. - **D-C14 Code panes open through child B's `openCodePane`, extended with `preview`.** This issue adds `preview?: boolean` to `CodePaneTarget` and the one-preview-per-root rule to `openCodePane` itself, not to `addPane` (an `addPane` duplicate only focuses; it cannot retarget the preview pane's path). Every caller (B's tree and quick open, the banner's **Open** action here, child E's actions) goes through it. No new `StageApi` or `StageDeckContext` member is added: `CodePane` gets the deck key as `ctx.workspaceId`.
- **D-C15 Monaco language comes from the path on the client.** The server's `lang` field uses Shiki ids (`bash`, `tsx`, `jsx`, `mdx`, `toml`; `src/dashboard/server/services/read-workspace-file.ts`, search `const LANGUAGE_BY_EXTENSION`), which are not Monaco ids. `code/monaco-language.ts` exports `monacoLanguageForPath(path, languages)`, which matches the basename against each `languages[i].filenames` and then the extension against `languages[i].extensions` (case-insensitive) of `monaco.languages.getLanguages()`, and returns `'plaintext'` otherwise. Mapped explicitly: `.mdx` → `markdown`.
- **D-C16 All Monaco languages load only in the code pane's lazy chunk.** `lib/monaco-setup.ts` imports only `editor.api.js` and the five worker constructors; `ContextEditor.tsx` keeps its single markdown contribution. `code/MonacoCodeEditor.tsx`, which only `CodePane` imports and which `Stage/index.tsx` loads with `React.lazy`, adds `import 'monaco-editor/esm/vs/editor/editor.main.js'`. That module registers every basic language and the css/html/json/typescript language services on the same global Monaco instance (`editor.main.js` and `editor.api.js` both re-export `editor.api2.js`; checked in `node_modules/monaco-editor@0.55.1`).
- **D-C17 Keybindings are per editor.** `Ctrl/Cmd+S` and `Alt+Z` are registered with `editor.addAction({ id, label, keybindings, run })` on each Monaco instance, never `editor.addCommand` (which Monaco binds globally across instances) and never a `window` listener. The pane root also handles `Ctrl/Cmd+S` in a React `onKeyDown`, so it works while focus is on the pane header, following `EditorPane.tsx` (search `handlePaneKeyDown`).
- **D-C18 A save in flight defers external-change handling for that file.** If a watcher event for the file arrives while its save is in flight, the pane waits for the save to settle and then compares against the new base signature. Together with the 750 ms self-write registry, this keeps the pane's own atomic write (temp-file create, rename) from ever raising the banner.
- **D-C19 Closing a pane flushes a pending autosave.** If the autosave timer is armed when the code pane unmounts, it saves at once. The draft stays in the drafts store either way, so reopening a dirty file restores the unsaved text.
- **D-C20 Delete and rename on disk.** A `delete` event for the pane's path starts a 500 ms timer. A `create` of a path with the same basename in that window marks the pane `renamed` to that path. A `create` of the same path in that window (an atomic save by another editor) cancels the timer and is handled as an update. When the timer fires, the pane re-reads: still missing → `deleted`; present → handled as an update. A `rename` event whose `oldPath` is the pane's path marks it `renamed` at once. In `deleted` state a later `create` of the path re-reads and clears the mark.
- **D-C21 A `resync` signal re-reads.** Child B's hub turns an overflow batch and every reconnect into `{ kind: 'resync' }`. The code pane treats `resync` exactly like an `update` of its own path: it re-reads after 250 ms, because events may have been lost.
- **D-C22 Single click opens a preview pane.** B's D-B2 makes a single click only select a row and leaves preview tabs to this issue at the `openFileFromTree` seam. This issue changes the tree so a single click on a **file** row calls `openCodePane(deck, { rootId, path, preview: true })`, and a double click or Enter calls it with `preview: false`. A single click on a folder still only toggles it. B's `ExplorerTree` (`components/explorer/tree/ExplorerTree.tsx`, B's WI-B7 step 3) calls `onSelect(path, 'replace')` on a plain click of a file and `onOpen(path)` on a double click or Enter, and `ExplorerPane.tsx` wires `onOpen` to `openFileFromTree`. This issue adds one optional prop `onPreview?(path: string)` to `ExplorerTree`, called on a plain (no modifier) click of a **file** row right after `onSelect`, and wires it in `ExplorerPane.tsx` to `openCodePane(ctx.workspaceId, { rootId, path, preview: true })`. `onOpen` keeps opening a permanent pane. **Implementation checkpoint:** if B's merged code names these props differently, apply the same change to B's names.
- **D-C23 Reveal fields are read here.** B writes `explorerRevealLine`, `explorerRevealColumn` and `explorerRevealNonce` when content search opens a match. `CodePane` reveals that position (`editor.setPosition`, `revealLineInCenter`, then `focus`) when the editor mounts and whenever the nonce changes.

## 4. Requirements

Requirement ids keep the parent's numbers. Only the requirements this issue implements are listed; FR-10 is split, and this issue owns its server half.

### Functional

- **FR-7** Text files open in a code pane with Monaco and syntax highlighting for every Monaco language.
  - Autosave runs 1,000 ms after the last keystroke and when the editor loses focus. `Ctrl/Cmd+S` saves immediately.
  - Markdown files (`.md`, `.mdx`, `.markdown`) have an Edit / Preview toggle that reuses `MarkdownTab` (`src/dashboard/frontend/src/components/CommandDeck/ZoneCOverviewTabs/MarkdownTab.tsx`).
  - Preview tabs: a single-click open reuses the root's one preview pane, its label is italic, and an edit, a double click or **Keep open** makes it permanent.
  - Changes view: a header toggle shows a Monaco diff of `HEAD` against the live draft, keeping the cursor position.
  - Word wrap is on by default and toggles with `Alt+Z`.
  - The tab label shows `●` while the draft is dirty.
- **FR-8** Conflict handling:
  - Every write carries the base signature, and the server refuses a write whose precondition fails (D-C4).
  - When a file changes on disk and its pane is clean, the pane reloads after 250 ms.
  - When a file changes on disk and its pane is dirty, the pane shows a banner with **Compare**, **Reload from disk**, **Keep my edits** and **Overwrite**. A `DISK_CONFLICT` answer to a save shows the same banner.
  - A file deleted on disk is marked *deleted*; a delete followed by a create of the same basename is marked *renamed*; if the file reappears, the mark clears (D-C20).
  - The pane's own writes never show the banner (self-write suppression, D-C18).
- **FR-10 (server half)** The server implements `explorerCreate`, `explorerRename` (rename and move), `explorerCopy`, `explorerDelete` (to the Overdeck trash) and `explorerRestore`, with the semantics of §7 WI-11. The UI for them is child E.
- **FR-19** Code panes open through one function, child B's `openCodePane(deckKey, { rootId, path, line?, column?, preview? })`, which this issue extends with `preview` (D-C14). A single click on a file row in the tree opens a preview pane; a double click or Enter opens a permanent one (D-C22). A code pane reveals the line and column content search asked for (D-C23). *(New id in this refinement; the parent's FR-7 implies it.)*

### Non-functional

- **NFR-1** Server code uses only async I/O (`fs/promises`, async `execFile`). No `*Sync` call is reachable from the dashboard server.
- **NFR-3** Every write path goes through A's `resolveInsideRoot(..., { forWrite: true })`: no absolute paths, no `..`, no NUL, no write into any `.git` directory, no symlink escape. `explorerRestore` re-resolves the manifest path (D-C7).
- **NFR-6** The only new on-disk data is the trash. Drafts, the save queue, the self-write registry and external-change state are in memory only. The new pane fields (`explorerRootId`, `explorerPath`, `explorerPreview`) persist with the existing `pan-panes:<deck>` localStorage, which already holds UI pane state.
- **NFR-7** Every new `src/` file stays under 1,000 lines. `src/dashboard/frontend/src/components/Stage/index.tsx` is 718 lines and `src/dashboard/frontend/src/lib/panesStore.ts` is 424; neither may pass 1,000. `CodePane.tsx` is split into the modules of WI-8 so no file approaches the ceiling.
- **NFR-8** Monaco's all-language bundle loads only when a code pane first opens (D-C16).

## 5. Repo rules that apply (restated)

### WI-9.1 — External-change controller (traces FR-8)

**Files:** new `code/external-change.ts` (port header: decision logic of Orca `src/renderer/src/hooks/editor-external-watch-event-reconciliation.ts`), `code/__tests__/external-change.test.ts`.

**Steps:**
```ts
export type ExternalChangeState =
  | { kind: 'clean' }
  | { kind: 'changed'; diskText: string; diskSignature: string }
  | { kind: 'deleted' }
  | { kind: 'renamed'; newPath: string }
export type DiskRead = { missing: true } | { missing: false; text: string; signature: string }
export function createExternalChangeController(deps: {
  getPath(): string
  getBaseSignature(): string | null
  isDirty(): boolean
  isSaveInFlight(): boolean
  whenSaveIdle(): Promise<void>
  reread(): Promise<DiskRead>
  isSelfWrite(signature: string): boolean
  reload(read: { text: string; signature: string }): void
  setState(state: ExternalChangeState): void
}): { handle(events: ExplorerWatchEvent[]): void; dispose(): void }
```
Rules, in order:
- An `overflow` event, or a `create`/`update` whose `path` is the pane's path, schedules one re-read 250 ms later (several events coalesce into one).
- Before re-reading, if `isSaveInFlight()`, `await whenSaveIdle()` (D-C18).
- After the re-read: `missing` → `deleted`. `signature === getBaseSignature()` → nothing. `isSelfWrite(signature)` → nothing. Clean → `reload(read)`. Dirty → `setState({ kind: 'changed', diskText, diskSignature })`.
- `delete` and `rename` follow D-C20.
- From `deleted`, a `create` of the path re-reads and leaves `deleted` (a clean reload sets `clean`; a dirty pane gets `changed`).
- `dispose` clears every timer.

**Tests (fake timers, fake deps):** a clean pane reloads 250 ms after an update; a dirty pane gets `changed`; the base signature and a self-write signature are ignored; an event during an in-flight save waits for the save; delete then create of the same basename within 500 ms gives `renamed`; delete then create of the same path gives a re-read, not `deleted`; delete alone gives `deleted` after 500 ms; a later create clears `deleted`; overflow re-reads.
