## blocks-the-design: URL restoration recreates the dead-end drawer

The plan makes `trackerUrl` transient, while `openIssue` writes an `?issue=MIN-658&tab=overview` URL. On a refresh, `IssueDrawer` calls `syncDrawerFromUrl()` on mount (`src/dashboard/frontend/src/components/drawer/IssueDrawer.tsx:30-32`), and `readDrawerFromUrl()` restores only `issueId` and `tab` (`src/dashboard/frontend/src/lib/store.ts:152-174,256-260`). `backfillIssue()` returns early when the tracker poll already holds this cycle-filtered issue (`src/dashboard/server/services/issue-data-service.ts:801-805,821-830`), so no row arrives. `trackerIssueUrl()` has no MIN fallback (`src/dashboard/frontend/src/lib/issueLinks.ts:7-17`). The refreshed drawer again has the generic title and no Issue button, contrary to FR-3 and the proposed user documentation. The WI-1 URL-sync test explicitly expects this loss, so the defect would pass the planned tests. Preserve or reconstruct a validated tracker URL when restoring an absent issue from the drawer URL, and add a reload/URL-sync test for a cycle-filtered MIN issue. If the URL must remain free of `trackerUrl`, the plan needs another route-restoration source for it.
