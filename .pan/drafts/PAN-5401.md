# PAN-5401 — Close-out row 1 accepts the comment-posted review verdict the merge gate accepts

**Issue:** [PAN-5401](https://github.com/eltmon/overdeck/issues/5401)
**Status:** planned (auto mode, 2026-11-15)

## Glossary

- **DoD gate / close-out gate** — the Definition-of-Done table `pan close` prints before it archives
  anything (`evaluateDodGate`, `src/lib/lifecycle/dod-gate.ts`). Each row is `pass`, `miss`, `skip`,
  or `miss-accepted`. An unaccepted `miss` blocks close-out.
- **Row 1 (`review`)** — the DoD row "Review passed". Implemented by `checkReviewRow` →
  `checkVerdict(issueId, 'review', …)` in `src/lib/lifecycle/dod-gate.ts`. Overridden only by an
  operator with `pan close <id> --accept-review`.
- **Raw PR read** — `IssuePullRequestData` returned by `fetchIssuePullRequest`
  (`src/lib/overdeck/pull-requests.ts`) via `readPullRequestWithRetry` (`src/lib/lifecycle/dod-pr-read.ts`).
  Its `reviewDecision` is GitHub's own field, empty (`""`) or `null` when no formal review exists.
  It also carries `comments`, `commits`, and `headRefOid`.
- **Verdict marker** — the first line of a PR comment of the form
  `<!-- overdeck-verdict: APPROVED sha=<40-hex> -->` (or `CHANGES_REQUESTED`). The review agent posts it
  when GitHub refuses a formal review (the reviewer identity is the PR author, or the App lacks review
  permission). Written by `formatVerdictMarker`, parsed by `parseVerdictMarker` /
  `parseVerdictMarkerWithSha` (`src/lib/cloister/pr-facts.ts`, line ~200).
- **PR facts** — `PrFacts`, the cloister's single read door for forge PR facts (`getPrFacts`,
  `src/lib/cloister/pr-facts.ts`, line ~567). On GitHub it folds trusted verdict markers into
  `reviewDecision` / `approved`, and sets `approvedAtHead: true` only when the newest trusted marker is
  an APPROVED marker whose `sha=` names the PR head (`approvalMarkerAtHead`).
- **Marker trust** — a marker counts only from a trusted author (`OWNER`/`MEMBER`/`COLLABORATOR`
  association, or an Overdeck identity), and an APPROVED marker counts only from the App bot on a repo
  the GitHub App covers (`markerApproversFor`). These rules need forge calls (`appCoversRepo`, App bot
  login, author kinds), which run only when some comment carries a marker.
- **Approval proven at head** — `approvalProvenAtHead(facts)` (`src/lib/cloister/approval-at-head.ts`,
  re-exported from `pr-facts.ts` line 122): on GitHub, `facts.approvedAtHead === true` and no changes
  requested. This is the approval rule the merge gate uses (`evaluateMergeReadiness` with
  `requireApprovalAtHead: true`, `src/lib/cloister/merge-gate.ts`).
- **Merge door** — `POST /api/issues/:id/merge` → `evaluateIssueMergeGate` (`src/lib/cloister/merge-gate.ts`).
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl` (`src/lib/cloister/pipeline-journal.ts`).
  Append-only history, **never authority**: where it disagrees with the PR, the PR wins (CLAUDE.md).

## Problem

OKF-11 (eltmon/okf PR #12) was approved by Overdeck's review agent as a PR comment. Verified with
`gh pr view 12 --repo eltmon/okf` on 2026-11-15:

- `reviewDecision: ""`, `state: MERGED`, `headRefOid: 85a0643f0f476a21738036090b6fc8199a61c536`
  (last commit `committedDate 2026-11-15T20:37:06Z`).
- Comments (all author `eltmon`, association `OWNER`):
  1. 20:34:07 `<!-- overdeck-verdict: CHANGES_REQUESTED sha=2aa74173… -->`
  2. 20:39:17 `<!-- overdeck-verdict: APPROVED sha=85a0643f0f476a21738036090b6fc8199a61c536 -->`

The merge gate read that APPROVED marker through `getPrFacts` → `approvedAtHead: true` and merged.
Close-out then refused at row 1:

```
dod:review: expected: review passed ...; observed: PR #12 reviewDecision: ; MISS
```

Cause — `src/lib/lifecycle/dod-gate.ts`, `checkVerdict`, the `if (id === 'review')` block (line ~438):

```ts
  if (id === 'review') {
    const decision = pr.reviewDecision ?? 'none';
    const observed = `PR #${pr.number} reviewDecision: ${decision}`;
    if (decision === 'APPROVED') return result('review', 'pass', observed);
```

Row 1 reads only the raw `reviewDecision`, so a comment-posted approval can never pass it. The merge
gate and the close-out gate disagree about the same review, and the Flywheel needed the operator-only
`--accept-review` override for work whose review really passed.

## Requirements

- **FR-1** — When the raw PR's `reviewDecision` is neither `APPROVED` nor `CHANGES_REQUESTED`, row 1
  passes if the merge gate's own reader proves approval at the PR head: `approvalProvenAtHead(facts)`
  is true, where `facts` come from `getPrFacts` run on the PR row 1 already read.
- **FR-2** — An APPROVED marker whose `sha=` does not name the PR head (or has no `sha=`) does not pass
  row 1. The row keeps its existing behavior (strike skip, tracker-closed settlement, else miss).
- **FR-3** — A forge `reviewDecision` of `APPROVED` still passes without the marker read; a forge
  `CHANGES_REQUESTED` is still the row's negative verdict and the marker is never consulted for it.
- **FR-4** — Row 1 reuses the merge gate's reader (`getPrFacts` + `approvalProvenAtHead`). No second
  verdict parser, no new regex, no new trust rule.
- **FR-5** — The marker read runs only when at least one PR comment's first line parses as a
  verdict marker (`parseVerdictMarker(body) !== null`, APPROVED or CHANGES_REQUESTED). With no such
  comment, row 1 makes no extra forge call.
- **FR-6** — A marker read that fails (returns `facts.error`, or throws) never passes row 1 and never
  crashes the gate. The row falls through to today's logic with the failure appended to `observed`.
- **FR-7** — A `null` or empty-string `reviewDecision` renders as `none` in `observed`
  (`PR #12 reviewDecision: none`), never as an empty value.
- **FR-8** — When row 1 passes by marker, `observed` names the evidence:
  `PR #<n> reviewDecision: none; Overdeck verdict comment approved head <first 12 hex of head>`.
- **FR-9** — Row 1's `expected` text in `DOD_ROWS` (`src/lib/lifecycle/dod.ts`) names the comment
  verdict as accepted evidence.
- **FR-10** — Docs: `docs/MERGE-WORKFLOW.md` and `changelog.d/pan-5401.md` describe the new row 1
  evidence.
- **FR-11** — (critique round 1) When the forge reached no decision and the merge gate's reader reports
  `facts.changesRequested` (the newest trusted verdict marker is CHANGES_REQUESTED, including one posted
  after an APPROVED marker), row 1's verdict is negative, exactly like a forge `CHANGES_REQUESTED`: the
  strike path does not skip it, tracker-closed settlement does not skip it (`terminalVerdictSettlement`
  receives `'failed'`), and the row returns `miss` with observed
  `PR #<n> reviewDecision: none; Overdeck verdict comment requested changes`.
- **NFR-1** — `src/lib/cloister/pr-facts.ts` is not modified (it is 991 lines against the 1000-line
  `lint:file-size` ceiling, with no allowlist row): `git diff --stat origin/main...HEAD -- src/lib/cloister/pr-facts.ts`
  prints nothing. All new code lives in `dod-gate.ts` (889 lines).
- **NFR-2** — The new `lifecycle/dod-gate.ts → cloister/pr-facts.ts` import adds no import cycle
  (`npm run lint:circular` passes). Probed at planning time: `madge --json` on `pr-facts.ts` resolves 84
  transitive modules and none is under `src/lib/lifecycle/`, so no path leads back to `dod-gate.ts`.
- **NFR-3** — Every existing `observed` string asserted in `tests/unit/lib/lifecycle/dod-gate.test.ts`
  stays byte-identical, and every existing test there passes unchanged.
- **NFR-4** — Unit tests never call the real GitHub App / `gh` trust readers: they inject the
  `readReviewFacts` dep (WI-1) built from `getPrFacts` with injected `PrFactsDeps`.

## Decisions (made here; auto mode)

1. **Reader reuse without touching `pr-facts.ts`.** Row 1 calls
   `getPrFacts(issueId, { fetchGitHubPr: async () => ({ issueId, pr }) })` on the PR it already read.
   Injecting `fetchGitHubPr` (a) avoids a second `gh pr view`, (b) makes the call non-cacheable
   (`cacheable = Object.keys(deps).length === 0`, pr-facts.ts line ~572), so it neither reads nor
   writes the 60 s PR-facts cache and does not call `recordReadApprovalAtHead` (only cacheable reads
   record, line ~584). This keeps NFR-1 at zero lines.
2. **Predicate is `approvalProvenAtHead(facts)`, never `facts.approved` or `facts.reviewDecision`.**
   A fresh APPROVED marker with a mismatched `sha=` still sets `approved: true`; only `approvedAtHead`
   is withheld. The merge gate uses `approvalProvenAtHead`, so row 1 uses it too.
3. **The pipeline journal is not read.** The issue offered "or the journal's `review.verdict`" as an
   alternative. The merge gate does not read the journal, and CLAUDE.md makes the journal never
   authority. Accepting only what the merge gate accepts is the fix.
4. **A trusted CHANGES_REQUESTED marker is a negative verdict (FR-11, WI-3).** Revised after critique
   round 1. Row 1 claims the merge gate's evidence, and the merge gate refuses a PR whose newest trusted
   marker requests changes (`evaluateMergeReadiness` checks `facts.changesRequested` before any approval
   rule, so even an approval-waived strike merge is refused). Letting such a PR skip row 1 through
   settlement or the strike path would close out work whose latest review rejected it.
5. **Failure falls through, it does not fail closed harder than today.** A failed marker read only
   means the extra evidence is missing; today's row behavior is the floor. The PR read failure path
   (PAN-4821, fail closed) is untouched because it runs before this block.
6. **Dependency injection shape.** `DodStatusRowDeps` gains an optional
   `readReviewFacts?: (issueId: string, pr: IssuePullRequestData) => Promise<PrFacts>`. Optional so the
   many existing `deps()` fixtures and production callers keep compiling. The default is the getPrFacts
   call in Decision 1.
7. **Row 6 (main-verify checks for non-Overdeck projects) is out of scope** — the issue's "follow-up worth
   considering" is a NonGoal; okf already has `main_verify_required_checks` set.
