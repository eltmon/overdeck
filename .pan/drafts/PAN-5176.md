# PAN-5176: Test on the hosts users actually have

macOS CI and a bare-host smoke (no tmux, Docker or systemd), a spawn budget for unit tests, and a release gate.

**Issue:** [PAN-5176](https://github.com/eltmon/overdeck/issues/5176)
**Related (merged):** PAN-5168 (`872e5422c75`), PAN-5169 (`ce824ec7dc0`), PAN-5170 (`f534aa7149e`). **Related (open):** PAN-5171 (PR #5177).
**Planned against:** `main` at `872e5422c75` (v0.81.0 plus the three fixes).

## Glossary

- **Bare host:** a machine with Node 22, git and the OS's own `/usr/bin:/bin:/usr/sbin:/sbin`, and none of `docker`, `tmux`, `systemctl`, `journalctl` or `brew` on `PATH`. The operator's work Mac is one.
- **Denied tools:** `docker`, `tmux`, `systemctl`, `journalctl`, `brew`. This is the `HostToolName` set in `src/lib/host-tools.ts` line 19 (`export type HostToolName = 'docker' | 'tmux' | 'systemctl' | 'journalctl' | 'brew';`).
- **Subject:** the Overdeck package under test. It is either a tarball from `npm pack` or a published npm version such as `0.81.0`.
- **Bare env:** the environment the smoke script gives every child process it runs. It starts from `env -i` and adds only the variables listed in FR-4. In particular it drops `CI`, because `ensureHerdr` skips all Herdr setup when `CI` is set (`src/lib/herdr-setup/ensure.ts`, `if (env.CI) return 'Herdr setup skipped: running under CI';`), and a real user's host has no `CI`.
- **Spawn storm:** on macOS, each spawn of a bare command name that is not on `PATH` makes libuv call `posix_spawn` once per `PATH` entry. XNU creates a short-lived process for each try (PAN-5168). The cost therefore scales with the number of `PATH` entries.
- **New-PID count:** the difference between two PIDs from `sh -c 'echo $$'` taken N seconds apart. Both macOS and Linux allocate PIDs in sequence, so this counts every process created on the machine in that window. On Linux it also counts new threads, because thread IDs come from the PID space.
- **Baseline window / idle window:** two 30 s new-PID counts. The baseline window runs with no Overdeck process alive. The idle window runs with the dashboard booted, settled and idle. **Net** = idle minus baseline.
- **Idle budget:** the largest net new-PID count per 30 s window that the smoke accepts. It is separate per OS.
- **Spawn ledger:** the new Vitest helper (`tests/helpers/spawn-budget.ts`). It wraps the real `node:child_process` functions, records every call, and redirects denied tools to a path that does not exist.
- **Known-bad canary:** a CI job that runs the smoke against `@overdeck/core@0.81.0`, the last version with the PAN-5168/5169/5170 bugs. It asserts that the smoke **fails** for the expected reasons, which proves the smoke still detects those bugs.
- **Required check (in this repo):** `main` has no GitHub branch protection. `gh api repos/eltmon/overdeck/branches/main/protection/required_status_checks` returns 404 "Branch not protected", and the only ruleset is `protect-overdeck-state`. Overdeck's merge gate refuses a PR when **any** completed check on its head has a conclusion other than SUCCESS, NEUTRAL or SKIPPED (`src/lib/cloister/pr-facts.ts` line 257, `if (status === 'COMPLETED' && conclusion && !['SUCCESS', 'NEUTRAL', 'SKIPPED'].includes(conclusion)) failed = true;`). So a job with no `continue-on-error` that runs on the PR is required in practice.

## Problem

PAN-5168, PAN-5169 and PAN-5170 made the operator's Mac unusable:

- An idle dashboard spawned 13 to 60 dead processes per second.
- `pan up` refused to start without tmux.
- Linux-only checks ran on macOS.

None was caught, because every CI job runs on `ubuntu-latest` hosts that have tmux, Docker and systemd. In `.github/workflows/ci.yml` every job says `runs-on: ubuntu-latest`. macOS appears only in `release.yml`'s `desktop` matrix (`os: macos-latest`). No test starts Overdeck on a host that is missing an optional tool.

**Measured baseline (issue body, 2026-11-13, Mac rig, macOS 26.6.2 arm64, v0.81.0, `PATH` = Node 22 plus `/usr/bin:/bin:/usr/sbin:/sbin`, isolated HOME):**

- `pan up --no-resume` failed with "tmux not found. Installing... Failed to install tmux: brew: command not found".
- The idle dashboard created 461 new PIDs in 30 s, about 15 per second.

## Goals

1. A smoke script that installs the subject on a bare host and fails on the three bug classes: `pan up` needing a tool the backend does not need, an idle spawn rate over budget, and a repeated host-tool `ENOENT`.
2. The smoke runs on `macos-latest` and `ubuntu-latest` in CI. The macOS job runs on relevant PRs and on every CI-triggering push to `main` (pushes that touch only `.pan/**` or `.overdeck/memory/**` start no CI, per `ci.yml`'s `paths-ignore`). The Linux job runs on every PR.
3. `release.yml` runs the macOS smoke against the exact `@overdeck/core` tarball it publishes, and refuses to publish if the smoke fails.
4. Unit tests hold a spawn budget per poller tick for the PAN-5168 pollers, for the PAN-5170 Linux-only checks with `process.platform` set to `darwin`, and for the PAN-5169 Herdr conversation poll.

## Non-goals

- The PAN-5171 drawer-title Playwright e2e. PAN-5171's own plan has item `e2e-drawer-title` (`tests/e2e/styleguide-conformance.spec.ts`) and PR #5177 is open, so the issue's condition "if PAN-5171 has not already added it" is met by that plan.
- GitHub branch protection. Adding it is an operator setting, outside this repo.
- Adding the new checks to `DEFAULT_MAIN_VERIFY_REQUIRED_CHECKS` (`src/lib/lifecycle/dod-gate.ts` line 165). That default applies to every project without its own `main_verify_required_checks`, and other projects have no `bare-host-*` checks.
- A tmux-backend bare-host leg. A tmux-backend user must install tmux, so a bare host is not a supported tmux host.
- Windows. `windows-smoke.yml` already covers it, manually.
- Changes to runtime code in `src/`, except same-class fixes the smoke finds (see Decisions D9).
- Running the smoke on the Mac rig as a dependency. The rig is an optional manual check (operator decision, issue body).
- Sending `@overdeck/contracts` and `@overdeck/desktop` through the smoke. Only `@overdeck/core` is what `npx @overdeck/core` installs.

## Decisions

- **D1: The release gate is a CI job, never the Mac rig.** This was decided by the operator in the issue body.
- **D2: One script, `scripts/bare-host-smoke.sh`, runs locally, in CI and in the release.** It starts from the Flywheel reference check pasted in the issue.
- **D3: Bash 3.2 compatible.** macOS `/bin/bash` is 3.2, so the script uses no associative arrays, `mapfile`, `${x,,}`, `wait -n` or `|&`. CI runs it as `/bin/bash scripts/bare-host-smoke.sh` on macOS. It never uses coreutils `timeout`, which macOS lacks. Every wall-clock cap uses the bash `limit` function from the reference script.
- **D4: Fixed six-entry PATH.** The spawn storm scales with the `PATH` entry count, so both OSes use exactly six entries:
  - macOS: `$T/node-bin:$T/herdr-bin:/usr/bin:/bin:/usr/sbin:/sbin`. None of the denied tools live in those system directories on a macOS runner. Homebrew is in `/opt/homebrew/bin`, which is not included. The script verifies this before it runs anything.
  - Linux: `$T/node-bin:$T/herdr-bin:$T/sys/usr-bin:$T/sys/bin:$T/sys/usr-sbin:$T/sys/sbin`. Each `$T/sys/*` directory holds one symlink for every entry of the matching system directory, except the denied tools. The Ubuntu runner has `/usr/bin/docker` and `/usr/bin/systemctl`, so it needs this mirror.
  - `$T/node-bin` holds only symlinks to `node`, `npm` and `npx` from `dirname "$(command -v node)"`, resolved before `PATH` is stripped.
  - `$T` is `$WORK_DIR/tools`.
- **D5: Bare env for every child.** See FR-4. The script itself runs in the caller's normal environment, so it can use `jq`-free `node` for JSON and write `$GITHUB_STEP_SUMMARY`.
- **D6: `pan up --no-resume --no-open --detach`.** Without `--detach`, `pan up` runs the dashboard in the foreground and never exits (`src/cli/index.ts`, the `} else { // Run in foreground` branch). With `--detach` it returns after the `/api/health` gate. "pan up passed" means three things:
  - exit code 0;
  - `up.log` contains `passed /api/health`;
  - `up.log` contains no forbidden-tool line (FR-6).

  v0.81.0 has all three flags (`git show v0.81.0:src/cli/commands/dashboard-lifecycle-commands.ts`).
- **D7: The idle measurement starts its own server.** After `pan up`, the script runs `pan down`, a pkill backstop and a 5 s pause. It then takes the baseline window, then starts `node <core>/dist/dashboard/server.js` directly with `OVERDECK_NO_RESUME=1` and the port env `pan up` passes. This follows the reference script.
  - It measures the dashboard alone, without sidecars that `pan up` started (CLIProxy, smee, the deferred sync).
  - It still works on v0.81.0, where `pan up` exits before the dashboard starts.
- **D8: Safety on a developer host.** `stopDashboard` kills whatever owns ports 3010 and 3011 (`src/lib/platform-lifecycle.ts`, `stopDashboardBody`: "Collect pids across both ports, then SIGTERM"). So the script refuses to run (exit 2) when any of 3010, 3011, 3012 (supervisor) or 8317 (CLIProxy) has a TCP listener on **any** address. The check matches `pidsOnPort`'s scope (`src/lib/platform-lifecycle.ts` lines 189-205):
  - Run `lsof -nP -iTCP:<port> -sTCP:LISTEN -t` (in `/usr/sbin` on macOS, `/usr/bin` on Ubuntu). Any output means bound.
  - When `lsof` is not on `PATH`, use `ss -ltnH "sport = :<port>"` instead. Any output means bound.
  - When neither tool runs, the script fails closed: exit 2, "cannot determine whether port <p> is free".
  - As a second check, a `curl -s -o /dev/null --max-time 1 http://127.0.0.1:<port>/` exit code other than 7 also means bound.

  These probes run in the caller's normal environment, before the bare PATH exists.
  - Every pkill uses one of two patterns: `"$WORK_DIR/home/"` or `"$WORK_DIR/tools/"`. The script's own command line contains `$WORK_DIR` without those suffixes, so it cannot match itself. The script strips a trailing `/` from `--work-dir`.
  - The script never deletes any path outside `$WORK_DIR`. It creates `$WORK_DIR` fresh and refuses (exit 2) when `$WORK_DIR` already exists and is not empty.
- **D9: Same-class findings.** The smoke may find a further bug of the same class on `main` once this PR runs it: a missing optional host tool that is spawned on a timer or that `pan up` requires.
  - If the fix is 20 changed lines or fewer, the work agent fixes it in its own commit with a regression test that uses the spawn ledger, then files the issue afterwards. This follows operator memory "fix small things inline, file after".
  - Otherwise the agent files a GitHub issue with the smoke log, runs `pan tell flywheel-orchestrator "plan PAN-5176: bare-host smoke found <x>; blocked on #<n>"`, and does not weaken the smoke.
- **D10: Required means "runs and blocks".** The bare-host jobs have no `continue-on-error`. Overdeck's merge gate blocks on any failing check (Glossary). A job skipped by a job-level `if:` reports SKIPPED, which the gate and GitHub both treat as passing, so the macOS path filter does not strand PRs. A workflow-level `paths:` filter would leave no check at all, so the filter is a job-level `if:` over a `bare-host-changes` job.
- **D11: macOS path filter.** It includes the issue's three paths plus the files the smoke itself exercises or defines:
  - `src/dashboard/server/**`, `src/lib/**`, `package.json` (from the issue);
  - `src/cli/**`, because `pan up` lives in `src/cli/index.ts`;
  - `bun.lock`, for dependency changes;
  - `scripts/bare-host-smoke.sh` and `.github/workflows/ci.yml`.

  On `push` to `main` the macOS job always runs. The filter uses `dorny/paths-filter@v3`, a third-party action like the existing `Vampire/setup-wsl@v7`. It reads changed files from the GitHub API, so it needs no deep checkout.
- **D12: CI subject tarball.** The existing `build` job (check name `build (22)`, which stays unchanged) adds an `npm pack --ignore-scripts` step and uploads the artifact `bare-host-subject`. Both bare-host jobs download it. Packing once on Linux and installing on macOS is exactly what a user gets from npm.
- **D13: Release flow.** `release.yml`'s `npm` job is split in two:
  - **`pack`:** checkout, Node 22, Bun, install, ripgrep, build, PostHog sourcemaps, Playwright, full test, CLI smoke, then `npm pack --ignore-scripts` of the core package. It uploads artifact `release-core-tarball`.
  - **`npm`:** `needs: [classify, pack, bare-host-macos]`. It publishes the downloaded core tarball with `npm publish "$TGZ" --ignore-scripts --provenance --access public [--tag ...]`. It keeps the retry-safe skip, reading name and version from the tarball's `package/package.json`. It then builds and publishes contracts and desktop exactly as today, which means it keeps checkout, Bun, install and build.

  The pack step comes after the sourcemaps step, because `pan release sourcemaps` injects chunk ids into `dist` and deletes the `.map` files (`src/cli/commands/release.ts` `uploadReleaseSourcemaps`, `posthog-cli sourcemap inject`, `removeSourcemaps`). The published tarball must contain the injected `dist`.

  The `release` job still `needs: [classify, npm, desktop]`, so a failed smoke blocks npm and the GitHub Release.
- **D14: Separate idle budgets per OS, calibrated by rule** (implementation checkpoint WI-9). `IDLE_BUDGET_MACOS=30` and `IDLE_BUDGET_LINUX=30` start at 1/s. The rule:
  1. Read the net count from at least two green runs on this PR for each OS.
  2. Set that OS's budget to `max(10, min(30, 3 × highest net))`.
  3. Never set a budget above 30. A net count above 30 with all fixes merged is a D9 finding.
- **D15: Spawn ledger mechanism (verified by probe).** The ledger patches the real builtin, so it sees calls from vite-inlined `src` modules and from externalized `node_modules` (Effect's spawner). It is installed inside `vi.hoisted`, before the test file's static imports.
  - It gets the builtin with `createRequire(import.meta.url)('node:child_process')`, assigns wrapped functions, then calls `syncBuiltinESMExports()` from `node:module`.
  - **Probe result** (run during planning, Vitest 4.1.11, pool `forks`):
    - a module-scope `promisify(execFile)` call: counted once;
    - `exec('true')`: counted once (the nested `module.exports.execFile` call was not double-counted);
    - an Effect `ChildProcess.make` under `NodeServices.layer`: counted once.
  - The probe also showed one trap. Copying the original's `util.promisify.custom` symbol onto the wrapper bypasses the ledger, because the custom function calls the internal `execFile`. The wrapper must set its own `promisify.custom` that records and then calls the original custom function.
  - Test files that use the ledger must not `vi.mock('node:child_process')` or `vi.mock('child_process')`.
- **D16: The ledger denies, it does not pass through.** Calls whose program basename is a denied tool are recorded and then redirected to `/nonexistent/overdeck-spawn-budget/<tool>`. For the direct forms (`spawn`, `execFile`, `spawnSync`, `execFileSync` without `shell`), the real Node implementation then produces a genuine ENOENT in every calling style: callback, promise, sync throw, and the Effect `PlatformError` `NotFound`. For the shell forms the shell runs and exits 127 ("not found"). Either way, a regression never runs the CI runner's real `docker` or `tmux`.
  - For `exec`, `execSync` and the `shell: true` forms, the program is the first whitespace-delimited word of the command string. The redirect replaces that word.
  - All other calls pass through unchanged and are still recorded (for example `ps` and `git`).
- **D17: No duplicate tests.** The five PAN-5168 per-poller zero-spawn tests already exist. Each mocks its own `child_process` or injects a spawner layer:
  - `src/lib/__tests__/docker-stats.test.ts` "with docker missing, collect() spawns 0 processes per tick";
  - `tests/unit/dashboard/server/services/resource-discovery-docker-gate.test.ts`;
  - `src/lib/workspace/__tests__/stack-health.test.ts`;
  - `tests/unit/lib/runtime-census.test.ts`;
  - `src/lib/overdeck/__tests__/conversation-liveness.test.ts`.

  The new ledger tests add four things those tests lack:
  1. They run with **default dependencies**: the real `NodeServices.layer` and the real `child_process`.
  2. They count at the `child_process` boundary, across all six spawn functions.
  3. They advance fake time past `HOST_TOOL_MISSING_RECHECK_MS` (60 s) to prove the recheck also spawns nothing.
  4. Each has a positive control: with the tool reported present, the same tick records at least one call.

## Requirements

### Functional

- **FR-1:** `scripts/bare-host-smoke.sh` accepts exactly one of `--tarball <path>` or `--version <npm version>`. It also accepts `--work-dir <dir>` (required), `--out <result.json>` (default `<work-dir>/result.json`) and `--budget <n>` (overrides the OS default), plus `--help`. With bad usage it exits 64.
- **FR-2:** It installs the subject with `npm install --prefix "$WORK_DIR/home/pkg" --no-audit --no-fund <subject>` under the bare env, capped at 600 s, with one retry. It sets `CORE="$WORK_DIR/home/pkg/node_modules/@overdeck/core"` and requires `$CORE/dist/cli/index.js`.
- **FR-3:** It installs Herdr with `curl -fsSL https://herdr.dev/install.sh | HERDR_INSTALL_DIR="$WORK_DIR/tools/herdr-bin" sh` in the caller's normal environment, capped at 180 s, with one retry. This is the same installer as `src/lib/herdr-setup/binary.ts` `HERDR_INSTALL_URL`. It requires `$WORK_DIR/tools/herdr-bin/herdr --version` to exit 0.
- **FR-4:** Every child runs under `env -i` with exactly these variables:
  - `HOME="$WORK_DIR/home"`;
  - `PATH=<D4 path>`;
  - `USER` and `LOGNAME` from `id -un`;
  - `SHELL=/bin/bash`;
  - `LANG=en_US.UTF-8`;
  - `TMPDIR="$WORK_DIR/tmp"`;
  - `OVERDECK_TELEMETRY=0` (PAN-5084).

  The dashboard start adds `OVERDECK_NO_RESUME=1 DASHBOARD_PORT=3010 API_PORT=3011 PORT=3011 OVERDECK_MODE=production`. `CI`, `OVERDECK_HOME` and `OVERDECK_TERMINAL_BACKEND` are never passed, so the default backend (Herdr) applies, as on a user's host.
- **FR-5:** Before running anything, it verifies that `PATH=<D4 path> command -v <tool>` fails for every denied tool, and that ports 3010, 3011, 3012 and 8317 have no listener on any address (IPv4 or IPv6, any interface), checked with the D8 probes. Otherwise it exits 2 with a message that names the tool or port. If no probe tool can run, it also exits 2 (fail closed).
- **FR-6:** It runs `pan up --no-resume --no-open --detach` with a 180 s cap and writes `up.log`. `panUp.pass` is true only under D6. Forbidden-tool lines are lines of `up.log` that match, case-insensitive, `tmux not found|Failed to install tmux|brew: command not found|Install manually: brew|docker: command not found|systemctl: command not found|journalctl: command not found`.
- **FR-7:** It stops everything `pan up` started:
  1. `pan down`, with a 60 s cap;
  2. `pkill -TERM -f "$WORK_DIR/home/"` and `pkill -TERM -f "$WORK_DIR/tools/"`;
  3. a 3 s pause;
  4. the same two pkills with `-KILL`;
  5. a 5 s pause.
- **FR-8:** It takes the 30 s baseline window, starts the dashboard (FR-4 env, output to `server.log`), and polls `curl -sf http://127.0.0.1:3011/api/health` every 2 s for up to 120 s. It then sleeps 20 s to settle and takes the 30 s idle window.
  - If health never answers, `idle.booted=false` and `idle.pass=false`.
  - If a window's end PID is lower than its start PID (wrap), it retakes that window once.
  - `idle.pass` = `net <= budget`.
- **FR-9:** It stops the dashboard: SIGTERM to the server PID, a 5 s pause, SIGKILL, then the FR-7 pkills.
- **FR-10:** It scans `up.log`, `server.log` and `$WORK_DIR/home/.overdeck/logs/*.log` with `grep -a -o -E 'spawn [A-Za-z0-9_./-]+ ENOENT'`, ignoring lines that contain `(skipped: not on PATH)`. It counts each distinct match. `enoent.pass` is false when any match appears 2 or more times.
- **FR-11:** It writes `--out` as JSON with this shape:

  ```
  { version:"1", os, subject,
    panUp:{rc, healthy, forbiddenToolLines[], pass},
    idle:{booted, baselineNew, idleNew, net, netPerSec, budget, pass},
    enoent:{repeats:[{key,count}], pass},
    pass, setupError }
  ```

  It prints a plain summary to stdout. When `GITHUB_STEP_SUMMARY` is set, it appends a Markdown table there. It exits 0 when `pass`, 1 when an assertion failed, and 2 on setup error.
- **FR-12:** `ci.yml` job `bare-host-linux` (ubuntu-latest, `needs: build`, every PR and push) runs the smoke on the CI subject tarball. It uploads `result.json` and the logs as artifact `bare-host-linux-logs` with `if: always()`.
- **FR-13:** `ci.yml` job `bare-host-macos` (macos-latest, `needs: [build, bare-host-changes]`) runs the smoke with `/bin/bash` and uploads `bare-host-macos-logs`. Its `if:` is `github.event_name == 'push' || needs.bare-host-changes.outputs.macos == 'true'`.
- **FR-14:** `ci.yml` job `bare-host-macos-known-bad` (macos-latest, `needs: bare-host-changes`, `if: needs.bare-host-changes.outputs.smoke == 'true'`) runs the smoke with `--version 0.81.0`. It asserts three things, and fails the job otherwise:
  - the smoke exited 1;
  - `panUp.forbiddenToolLines` has an entry matching `/tmux/i`;
  - `idle.net > idle.budget`.

  The `smoke` filter is `scripts/bare-host-smoke.sh` only.
- **FR-15:** `release.yml` runs `bare-host-macos` on the release core tarball (D13). `npm` needs it, so a failed smoke publishes nothing and creates no GitHub Release.
- **FR-16:** `tests/helpers/spawn-budget.ts` exports `installSpawnLedger`, `SpawnLedger`, `spawnsPerTick` and `expectSpawnBudget` (WI-1 API).
- **FR-17:** With every denied tool reported missing, each PAN-5168 poller records 0 calls to denied tools per tick over 3 ticks, with 61 s of fake time between ticks.
- **FR-18:** With `process.platform` stubbed to `darwin`, the systemd helpers, the OOM canary and the restart announcer record 0 `systemctl` and 0 `journalctl` calls.
- **FR-19:** With the Herdr backend and tmux missing, a full conversation poll records 0 `tmux` calls. A full poll is the list, the pending-input feed and a single read of each of three live claude-code conversations.

### Non-functional

- **NFR-1:** The smoke script runs under macOS `/bin/bash` 3.2 (D3).
- **NFR-2:** The smoke script never uses `timeout`, `gtimeout`, `realpath`, `readlink -f` or GNU-only flags (`sed -i` without a suffix argument, `grep -P`). Use `cd "$d" && pwd -P` for absolute paths.
- **NFR-3:** Unit tests use fake timers for every time-dependent step. No unit test sleeps in real time or runs a real denied tool. The smoke script is the one place real time is measured.
- **NFR-4:** Every new CI job sets `timeout-minutes`: 30 for each smoke job, 5 for `bare-host-changes`.
- **NFR-5:** Workflow file edits are pushed over SSH with `git push git@github.com:eltmon/overdeck.git HEAD:feature/pan-5176`, because the gh OAuth token lacks the `workflow` scope.
- **NFR-6:** No em dashes in any doc or changelog line this issue writes.
- **NFR-7:** New tests add no `skipIf`, `.only` or `.skip`. The test-skip gate rejects them. New tests do not read source files as text, because the `lint:source-introspection` gate rejects that.
- **NFR-8:** The job name `build (22)` does not change. It is listed in `DEFAULT_MAIN_VERIFY_REQUIRED_CHECKS`.

## Rules this work intersects (restated)

- **Fake timers** for delay and retry tests: `vi.useFakeTimers()` plus `vi.advanceTimersByTimeAsync()`. Never real `setTimeout` waits.
- **Gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never the full `npm test` on the host.
- **No variables in `rm` targets** in any shell this issue writes. The script deletes nothing anyway (D8). It only creates `$WORK_DIR`.
- **No `/tmp` for files you need later.** Local runs use a work dir under the scratchpad or the repo's `.tmp/`.
- **Never `git stash`.** Worktree discipline: stay on `feature/pan-5176`.
- **Changelog:** add `changelog.d/pan-5176.md` with one `#### Improved` bullet, and never edit `changelog.mdx`. `npm run lint:docs` checks the format.
- **Codebase map:** correct stale statements in `.overdeck/context/codebase/*.md`, and leave the `<!-- last-verified: -->` date unchanged.

## Work items

### WI-1: Spawn ledger test helper (`spawn-ledger-helper`)

**What/why:** the shared foundation for WI-2, WI-3 and WI-4. It is the counting primitive the issue asks for in Work item 5.

**Files:**

- new `tests/helpers/spawn-budget.ts`
- new `tests/unit/helpers/spawn-budget.test.ts`
- `docs/TESTING.md`: add a subsection "Spawn budgets (PAN-5176)" under "### Mocking"

**API** (implement exactly):

```ts
// tests/helpers/spawn-budget.ts
export type SpawnApi = 'spawn' | 'execFile' | 'exec' | 'spawnSync' | 'execFileSync' | 'execSync';
export interface SpawnRecord { readonly api: SpawnApi; readonly program: string; /* basename */ readonly denied: boolean }
export const DENIED_HOST_TOOLS = ['docker', 'tmux', 'systemctl', 'journalctl', 'brew'] as const;
export interface SpawnLedger {
  readonly records: readonly SpawnRecord[];
  count(filter?: { programs?: readonly string[] }): number;
  reset(): void;
  restore(): void; // puts the original functions back and calls syncBuiltinESMExports()
}
export function installSpawnLedger(options?: { deny?: readonly string[] }): SpawnLedger; // default deny = DENIED_HOST_TOOLS
export async function spawnsPerTick(
  ledger: SpawnLedger, tick: () => unknown, opts: { ticks: number; betweenTicks?: () => Promise<void>; programs?: readonly string[] },
): Promise<number[]>;
export function expectSpawnBudget(perTick: readonly number[], budget: { max: number; label: string }): void; // vitest expect, message names label + tick index
```

## Hazards

- **GitHub's macOS concurrency.** GitHub's Free plan allows 5 concurrent macOS jobs on standard hosted runners, out of 20 total, and that applies to public repositories too ([Actions limits](https://docs.github.com/en/actions/reference/limits)). A busy PR day can queue the macOS job. The path filter and `ci.yml`'s `cancel-in-progress` concurrency limit the load.
- **Tarball publish with provenance under OIDC is unverified here.** The first release after merge proves it (WI-10 post-merge proof). If npm rejects it, the fallback is to publish from an extracted tarball directory: `tar -xzf "$TGZ" -C "$RUNNER_TEMP/x" && npm publish "$RUNNER_TEMP/x/package" --ignore-scripts --provenance ...`.
- **Network flake.** `npm install` and the Herdr installer get one retry each. A failure after the retry is a setup error (exit 2), shown as such, never as a detection.
- **Linux counts threads as PIDs.** Calibration (WI-9) absorbs it, because baseline and idle windows are measured the same way.
- **The canary depends on npm keeping `@overdeck/core@0.81.0` installable.** If it becomes uninstallable, the canary reports a setup error. Pin a newer known-bad version only if one exists. Otherwise retire the canary in a follow-up issue.
- **Workflow pushes need SSH** (NFR-5). `pan done`'s push may use HTTPS. Push over SSH first, so the branch already holds the workflow commits.
- **The canary's v0.81.0 rate on a GitHub macOS runner is not yet measured.** The rig measured 461 new PIDs in 30 s, far above the starting budget of 30. If the canary reports a net count at or under the budget, do not loosen its assertion. Report the numbers with `pan tell flywheel-orchestrator` and investigate why the runner differs from the rig (D9 applies to the smoke itself).
- **The ledger must be installed before imports** (`vi.hoisted`). A test that installs it in `beforeAll` silently misses module-scope `promisify(execFile)` captures in `runtime-census.ts`, `stack-health.ts` and `resource-discovery-shared.ts`.

## Critique response

### Port check misses listeners that pan up can kill

Accepted, and the design changed. D8 and FR-5 now detect a listener on any address with the same probe `pidsOnPort` uses: `lsof -nP -iTCP:<port> -sTCP:LISTEN -t`, then `ss -ltnH` when `lsof` is missing. The curl IPv4 check stays only as a second check. When no probe tool can run, the script fails closed with exit 2. AC-5 and the smoke script's ACs now include an IPv6-only listener on `::1` port 3010, and expect exit 2.

### Spawn-budget helper hides failed ticks

Accepted, and the design changed. `spawnsPerTick` no longer swallows rejections (WI-1 step 3). Each WI-2 tick asserts its poller's contract value:
- `collect()` resolves;
- `loadDockerContainers()` resolves `[]`;
- liveness resolves a set and `false`;
- the stack-health snapshot fails with `ENOENT`, converted explicitly through `Effect.result`;
- `listHostTmuxPanes()` rejects with `ENOENT`, through `expect(...).rejects`.

A poller that breaks before it reaches `child_process` now fails the test instead of reporting 0 spawns.

### Every main push is not covered

Accepted as a framing fix. Goal 2 and WI-7 now say "every CI-triggering push to main" and name `ci.yml`'s `paths-ignore` for `.pan/**` and `.overdeck/memory/**`. Those pushes change no code, so the trigger stays unchanged.

### Local smoke command omits the tarball directory

Fixed. The WI-5 header example now prefixes `.tmp/smoke/` to `npm pack`'s printed filename, and RELEASING.md repeats the header's command.
