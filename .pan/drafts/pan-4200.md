# PAN-4200 — deps(desktop): electron-builder 26 + @electron/notarize 3 to clear the critical tar advisory

**Issue:** [PAN-4200](https://github.com/eltmon/overdeck/issues/4200)
**Source:** dependency triage, 2026-09-25 (major upgrades).
**Planning mode:** `pan plan --auto` (no operator Q&A; defaults recorded under "Decisions").

## Glossary

- **`bun audit`** — Bun's advisory scanner. Run from the repo root, it prints one block per vulnerable package and a final summary line such as `218 vulnerabilities (1 critical, 91 high, 105 moderate, 21 low)`.
- **Critical tar advisory** — `GHSA-23hp-3jrh-7fpw` ("node-tar: Decompression/parse DoS via unlimited input"). Affects `tar <7.5.7`. It is the only critical advisory in the repo today.
- **electron-builder** — the desktop packaging tool (`apps/desktop`, devDependency). Version 25 drags in `app-builder-lib@25.1.8`, which depends on `tar@^6.1.12` directly and on `@electron/rebuild@3.6.1` → `node-gyp@^9` → `make-fetch-happen@10` → `cacache@16` → `tar@^6.1.11`. No patched `tar` 6.x exists, so the only fix is to leave electron-builder 25.
- **app-builder-lib** — electron-builder's core library; its version tracks electron-builder's. `app-builder-lib@26.16.1` depends on `tar@^7.5.7` and `@electron/rebuild@^4.0.4`.
- **AppImage advisory** — `GHSA-7g7r-gx96-252g` ("Uncontrolled search path elements within AppImage built by app-builder-lib"), high, fixed in `app-builder-lib >=26.15.0`. We ship a Linux AppImage.
- **afterSign hook** — `apps/desktop/scripts/notarize.cjs`, wired as `build.afterSign` in `apps/desktop/package.json`. electron-builder calls it after it signs the macOS `.app`. It notarizes with `@electron/notarize` only when `APPLE_API_KEY`, `APPLE_API_KEY_ID`, and `APPLE_API_ISSUER` are all set (the release workflow's macOS runner); otherwise it logs and returns.
- **`@electron/notarize` 3** — ESM-only (`"type": "module"`, `exports: "./lib/index.js"`, `engines.node: ">= 22.12.0"`). Its options type (`NotarizeOptions`) has no `tool` field; notarytool is the only mode. `notarize()` staples the ticket itself (`stapleApp` with 3 retries).
- **`require(esm)`** — Node ≥ 22.12 can `require()` an ES module that has no top-level `await`, without a flag. `@electron/notarize@3.1.1`'s `lib/index.js` has no top-level `await`.
- **Exact pin** — a dependency version with no range operator (`"electron": "40.6.0"`). `bun update` does not move exact pins; they must be edited by hand.
- **ABI 143** — the Node module ABI of Electron 40.x. It is fixed per Electron major, so 40.6.0 → 40.10.6 keeps ABI 143 and the node-pty rebuild in `prepare-server-resources.mjs` stays valid.
- **Virgin-environment launch** — starting the packaged AppImage with `env -i HOME=<scratch> PATH=/usr/bin:/bin xvfb-run -a …` so no developer `OVERDECK_HOME` or migrated DB leaks into the test (the v0.45.5 field failure passed on every dev machine for exactly that reason).

## Decisions (auto mode)

1. **Keep the `.cjs` hook; do not rename it to `.mjs`.** The issue's step 2 makes the rename conditional on Node 22 failing to load notarize 3. The probe above shows Node 22.22 `require()`s it. CI floats to the newest 22.x. Fallback, only if a work-agent run shows `ERR_REQUIRE_ESM`: replace line 36 with `const { notarize } = await import("@electron/notarize");` (the hook is already `async`), still in the `.cjs` file. Do not rename files.
2. **Drop the `tool: "notarytool"` key.** notarize 3's `NotarizeOptions` has no `tool` field. The hook runs only on the macOS release runner, so it cannot be exercised here; the hook must not depend on the library tolerating an unknown key.
3. **Keep the manual `xcrun stapler staple` call.** notarize 2.5.0 already stapled internally, so the second staple is pre-existing redundancy and re-stapling a stapled app succeeds. Removing it changes an untestable release path for no security gain.
4. **Keep the custom hook plus `notarize: false`; do not switch to electron-builder 26's built-in notarization.** The built-in path reads the same `APPLE_API_*` env vars, but switching contradicts issue steps 2–3 and would make the `@electron/notarize` 3 devDependency dead weight (app-builder-lib 26 pins its own `@electron/notarize@2.5.0`).
5. **Range spec `^26.15.3` for electron-builder, `^3.1.1` for @electron/notarize.** `26.15.3` is the npm `latest` dist-tag and ≥ 26.15.0 (the AppImage fix). The caret lets `bun install` resolve the newest 26.x (26.16.1 at planning time).
6. **Two `@electron/notarize` versions in `bun.lock` is expected.** Top-level 3.x (ours) and `app-builder-lib/@electron/notarize` 2.5.0 (electron-builder's internal pin). Do not add overrides.
7. **`electron-updater` stays at `^6.8.3`.** A separate high advisory (`builder-util-runtime <9.7.0`, GHSA-p2f4-r6v6-j797) reaches us through both electron-builder and electron-updater. electron-builder 26 clears its path; the electron-updater path remains. electron-updater ships inside the app (runtime), so bumping it is a separate change. The PR body names it as a follow-up.

## Repo rules that intersect this work

- **Quality gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.
- **Workspaces have their own `bun install`;** never symlink `node_modules`.
- **No `git stash`.** Commit or discard with named paths.
- **Commits carry an `Item: <item-id>` trailer** (checked by `pan task done`).
- **Desktop packaging invariants:** node-pty must be rebuilt for Electron's ABI (143 for Electron 40) — `prepare-server-resources.mjs` does this and self-verifies by loading `pty.node` under the real Electron binary; staged trees must stay hardlink-free. A Linux packaging run is the only local proof these still hold. mac/win packaging runs only in the release pipeline.
- **`pkill -f` self-matches the test shell;** when stopping the launched AppImage use `pkill -f "mount_Overd[e]"`.

   ```bash
   APP="$PWD/apps/desktop/dist/Overdeck-$(node -p "require('./apps/desktop/package.json').version").AppImage"
   SCR=$(mktemp -d)
   env -i HOME="$SCR" PATH=/usr/bin:/bin APP="$APP" SCR="$SCR" xvfb-run -a bash -c '
     "$APP" --no-sandbox >"$SCR/app.log" 2>&1 &
   ```
