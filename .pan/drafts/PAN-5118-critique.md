## blocks-the-design: MCP batches lose their JSON result

The PRD promises an `itemIds` batch of up to 500 and makes the self route invoke `pan task done ... --json` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5118/.pan/drafts/PAN-5118.md), lines 41–44 and 309–326). The existing self-job runner keeps only the final 16,384 bytes of stdout, even on exit 0 ([self-jobs.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5118/src/dashboard/server/services/self-jobs.ts), lines 10–12, 29–30, 82–85 and 135–137). I reproduced the mismatch with `node -e` using 500 minimal `{itemId,status,doneAt}` entries: `JSON.stringify(entries, null, 2)` was 51,392 bytes, and its final 16,384 bytes failed `JSON.parse`. The command would complete all items but return a truncated, invalid JSON array to `task_done`. Preserve the complete success stdout for `task-done` jobs within the existing 4 MiB child buffer, or revise the output contract and cap so every accepted batch returns a usable result. Add a 500-ID result test that exercises the real output retention path; the proposed route test only checks argv.
