# PAN-4456: Overdeck Anywhere docs describe what is shipped, and mark the rest as planned

**Issue:** [PAN-4456](https://github.com/eltmon/overdeck/issues/4456) (part of epic [PAN-2350](https://github.com/eltmon/overdeck/issues/2350))
**Kind:** documentation only. No source file under `src/` changes.
**Audit baseline:** `origin/main` at `8a82dad552b` (2026-10-01).

## Glossary

- **Overdeck Anywhere.** The set of features that let work leave one machine: Session Vault, machine identity and pairing, scoped API tokens, and later hosted services. Epic PAN-2350.
- **Session Vault.** `pan vault`: encrypted off-machine storage of agent transcripts in a backend the user owns, with cross-machine resume. Shipped in v0.64.0 (PR #4385 and follow-ups).
- **Backend.** Where the vault lives. A git remote URL, or `dir:<path>` for a local directory or NAS mount (`DIR_BACKEND_PREFIX = 'dir:'` in `src/lib/vault/open.ts`, line 47; accepted by `setup` at `src/cli/commands/vault/setup.ts`, line 42, and by `join`).
- **Pairing.** `pan pair` (or Settings → Anywhere → Pair a device) issues a one-time credential that gives another device its own revocable **device session**. Shipped from the terminal in v0.64.0 (PR #4417); the dashboard flow is in the next release.
- **Scoped API token.** `pan token create`: an `odk_…` bearer token limited to named scopes. Not released yet (PR #4441, PAN-2351).
- **Browse copy.** A read-only row in the dashboard conversation list for a Claude Code or Codex conversation that another machine owns, marked "from `<machine>`" (PAN-4436, PR #4448).
- **Continue here.** The button on a browse copy that adopts the conversation on this machine (PAN-4437, PR #4454).
- **Released / next release.** "Released" means in an npm release (`v0.64.0` is the latest tag). "Next release (v0.65.0)" means merged to `main` but listed under the `Unreleased` `<Update label="v0.65.0">` block in `changelog.mdx`. The Mintlify site deploys from `main`, so docs must say which features a user on npm `0.64.0` does not have yet.
- **Planned.** An open issue. Never describe planned work in the present tense.
- **Em dash.** The character `—` (U+2014). The issue's acceptance bars it from the user docs this change writes.

## Problem

A docs audit on 2026-10-01 found the shipped Anywhere pieces under-documented and some pages wrong:

1. `anywhere.mdx`, lines 8 to 12, says "Everything on this page is **planned and not yet available**", but Session Vault and pairing shipped in v0.64.0. The frontmatter `description` (line 3) ends "Planned, not yet available."
2. `anywhere.mdx`, lines 48 to 55 and 199 to 200, promise "moving your vault to another backend" and `pan vault migrate`. Neither exists: `src/cli/commands/vault/index.ts` registers only `setup, join, passphrase set|remove, rotate-key, status, save, sync, list, show, resume, exclude, include, allow-secret, evict, restore`.
3. `configuration/remote-access.mdx`, line 149 (Anywhere status table, row "Session Vault is set up, but this machine cannot open it."), says **Open Session Vault** "goes to its settings, where you unlock it with the vault passphrase or the recovery phrase." The dashboard has no unlock. Settings → Session Vault only prints `Run: pan vault join <backend>` (`src/dashboard/frontend/src/components/Settings/sections/SessionVaultSection.tsx`, lines 110 and 113). Dashboard set-up, join and unlock is [PAN-4446](https://github.com/eltmon/overdeck/issues/4446), open.
4. `changelog.mdx`, the `<Update label="v0.65.0" description="Unreleased">` block (line 14), lists only the TLDR removal (#4429). It is missing six merged Anywhere PRs: PAN-2351 (#4441), PAN-4307 (#4444), PAN-4445 (#4449), PAN-4436 (#4448), PAN-4435 (#4450), PAN-4437 (#4454).
5. `CHANGELOG.md` has no Anywhere coverage at all.
6. `cli/` has no reference page for `pan vault`, `pan pair`, `pan devices` or `pan token`.
7. `features/conversations.mdx` does not mention browse copies or **Continue here**.
8. `docs.json`, lines 56 to 61: the "Overdeck Anywhere" group holds only `anywhere`.
9. `sync-sources/skills/pan-vault/SKILL.md` describes only CLI flows; it does not mention the Settings → Session Vault panel, auto-save, browse copies or Continue here.

## Decisions

- **D-1. Version attribution.** Every "shipped" statement says where it shipped: `v0.64.0` (released) or "the next release (v0.65.0)". Released in v0.64.0: `pan vault` (all verbs above), passphrase unlock, key rotation, code snapshots, eviction, `pan pair`, `pan devices`, `GET /api/environment`, the LAN credential gate. Next release (v0.65.0): scoped tokens and `pan token` (#4441), Settings → Session Vault panel with dashboard auto-save every 30 s of quiet and sync every 5 min (#4444), Settings → Anywhere with the pair dialog, device list and status card (#4449), browse copies (#4448), Settings → Access Tokens and the **Require a token to sign in** toggle (#4450), **Continue here** (#4454).
- **D-2. One home per page in `docs.json`.** `configuration/session-vault` and `configuration/remote-access` move out of the Configuration group into the "Overdeck Anywhere" group (Vision tab). They are not listed twice. Page paths and URLs do not change, so `DOCS_PAGE = 'configuration/remote-access.mdx'` in `src/cli/commands/pair.ts` (line 32) and `src/cli/commands/token.ts` (line 22) stays correct. The four new CLI pages are listed only in the Anywhere group, and `cli/overview.mdx` links to them from its "Next Steps" list so the CLI Reference tab still leads to them.
- **D-3. `CHANGELOG.md` shape.** `docs/RELEASING.md`, line 120, names `changelog.mdx` as the public changelog and does not maintain `CHANGELOG.md`. Its `## Unreleased` section is stale developer content. Add one `### Added: Overdeck Anywhere` subsection directly under `## Unreleased` (before `### Breaking changes`) with one bullet per v0.65.0 PR, plus one bullet saying Session Vault and pairing were released in v0.64.0 and linking `changelog.mdx`. Do not restructure or correct anything else in the file.
- **D-4. Em dash rule.** `grep -c '—'` returns `0` for: `anywhere.mdx`, `configuration/remote-access.mdx`, `configuration/session-vault.mdx`, `cli/vault.mdx`, `cli/pair.mdx`, `cli/devices.mdx`, `cli/token.mdx`, `changelog.mdx`. - **D-5. Roadmap row 2 precision.** PAN-3762 is closed, but what landed is machine identity (`GET /api/environment`), pairing, device sessions, trusted origins and `require_token_mint`. A machine list and environment switcher ([PAN-4402](https://github.com/eltmon/overdeck/issues/4402)), advertised endpoints ([PAN-4403](https://github.com/eltmon/overdeck/issues/4403)) and SSH hosts ([PAN-3863](https://github.com/eltmon/overdeck/issues/3863), [PAN-4404](https://github.com/eltmon/overdeck/issues/4404)) are planned. Row 2 must not say "your machines can see each other" as a shipped fact.
- **D-6. Directory backend.** `dir:<path>` is real. `anywhere.mdx` may keep "git and directory backends". `configuration/session-vault.mdx` gains one sentence: a local directory or a NAS mount also works, as `pan vault setup dir:/path/to/dir`. The existing "Overdeck never provides or defaults a backend" stays true.
- **D-7. `pan vault migrate` and moving backends.** Keep them in `anywhere.mdx` only as planned, tied to the hosted vault ([PAN-4297](https://github.com/eltmon/overdeck/issues/4297)): the promise "you can always copy your records out of the hosted vault" is pricing policy, so it stays, phrased as "will", with "(planned)" after the command name. No code changes.** Stale code strings stay as they are and are out of scope: `anywhere-status.ts`, line 105 ("Unlock it with the vault passphrase or the recovery phrase."), and the `pan pair` loopback warning naming `OVERDECK_TRUSTED_ORIGINS` (`pair.ts`, line 35). ## Repo rules that apply

- **No em dashes** in the user docs this change writes (D-4). Operator memory also bars em dashes in external-facing prose.
- **Clear prose (STE standard and writing-style rule):** active voice, short sentences, one term per concept. Keep identifiers, paths, flags and numbers exact.
- **Surgical changes:** edit only the lines this PRD names. Do not reformat neighbouring text.
- **Issue links:** every issue reference in a doc is a markdown link to `https://github.com/eltmon/overdeck/issues/<n>`; every changelog PR reference links `/pull/<n>`.
- **Never codify destructive "acceptance tests"** in docs.
- **Quality gates for a docs-only diff:** `npm run lint` must still pass (it does not read `.mdx`, but run it). No `src/` change means no typecheck change; run `npm run typecheck` anyway as the gate requires.
