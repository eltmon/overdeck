# PAN-5427 — Markdown Preview renders YAML front matter as body text

**Issue:** https://github.com/eltmon/overdeck/issues/5427 · **Parent epic:** #5284 · **Found in:** live check of #5341 on :3011 (build `05aaa342d44`)

## Glossary

- **Front matter** — a YAML block at the very top of a Markdown/MDX file, opened by a line that is exactly `---` and closed by the next line that is exactly `---`. Every Mintlify page under `features/`, `configuration/` and `reference/` has one (e.g. `features/mission-control.mdx` lines 1–4).
- **Fence line** — a line whose content, after removing a trailing `\r` and trailing spaces/tabs, is exactly `---`.
- **Top-level key line** — a line inside the front matter that starts at column 0 and matches `^([A-Za-z0-9_][A-Za-z0-9_.-]*)\s*:(?:\s+(.*)|\s*)$`.
- **Continuation line** — any non-blank line inside the front matter that starts with a space, a tab or `- `; it belongs to the most recent top-level key.
- **Preview** — every Markdown rendering surface in the dashboard. All of them render through `MarkdownTab` (`src/dashboard/frontend/src/components/CommandDeck/ZoneCOverviewTabs/MarkdownTab.tsx`), which hands the body to `ChatMarkdown`.
- **Located preview** — a `MarkdownTab` with a `docLocation` prop. It renders through ReactMarkdown (`useStreamdown: false`). An unlocated preview renders through ReactMarkdown too unless the experimental `streamdownRenderer` setting is on (`ChatMarkdown.tsx`, `StreamdownRendererContext`).

## Problem

`MarkdownTab` passes the raw body straight to `ChatMarkdown`:

```tsx
// MarkdownTab.tsx (current, ~line 49)
<ChatMarkdown text={body} cwd={undefined} docLocation={docLocation} {...(docLocation ? { useStreamdown: false } : {})} />
```

No frontend code handles front matter (`grep -ri frontmatter src/dashboard/frontend/src` finds nothing). So for `features/mission-control.mdx`:

```
---
title: Mission Control
description: Unified monitoring dashboard for projects, features, and AI agent activity
---
```

the opening `---` renders as an `<hr>` and the two key lines plus the closing `---` become a setext `<h2>`-style bold block reading `title: Mission Control description: Unified …`, above the real `# Mission Control` heading.

Callers that inherit the fix with no change of their own (verified by `grep -rn "MarkdownTab" src/dashboard/frontend/src`):

- `src/components/explorer/code/CodePane.tsx` (~line 363) — code pane Preview tab.
- `src/components/diff/DiffMarkdownPreview.tsx` (~lines 21, 43, 59) — diff window and dock Changes Preview. The `patch` source's `text` is the new file's full content (`markdownPreviewSource.ts` line 11 comment: "The new file's full text"), not `+`-prefixed diff lines.
- `src/components/Stage/panes/EditorPane.tsx` (~line 244) — editor pane Preview.
- `src/components/Stage/panes/DocsPane.tsx` (~line 58), `src/components/Stage/cockpit/IssueDigTabs.tsx` (~line 37).

## Requirements

- **FR-1** A body whose first line (after an optional leading U+FEFF BOM) is a fence line, followed by a later fence line, with at least one top-level key line between them, is split into front matter and content. Only the content is passed to `ChatMarkdown`.
- **FR-2** The front matter renders above the content as a compact key/value list (`<dl data-testid="markdown-front-matter">`): keys in muted mono, values as plain text.
- **FR-3** Entries are ordered `title` first, `description` second (each only if present), then every other key in source order.
- **FR-4** A body that does not meet FR-1 renders exactly as today: no list, and `ChatMarkdown` receives the unchanged body. This covers: no leading fence; an opening fence with no closing fence; a fenced block with no top-level key line (e.g. `---\nSome prose\n---`, which stays an `<hr>` plus setext heading).
- **FR-5** A `---` anywhere other than line 1 still renders as an `<hr>`.
- **FR-6** Value rules (decided here, see "Value rules"): quoted scalars are unquoted; `|`/`>` block scalars and lists/maps show their indented lines as text; comment lines are dropped.
- **FR-7** When the content after the front matter is empty or whitespace-only, `MarkdownTab` renders the list and no empty-state label.
- **NFR-1** No new npm dependency. The parser is a pure, framework-free function that never throws.
- **NFR-2** Parsing is a single linear pass over the lines of the leading block; content after the closing fence is not scanned beyond locating it.
- **NFR-3** Styling follows `pan-style-guide`: no pill badges, no decorative color; keys use `font-mono-ui` and `text-muted-foreground`.

## Decisions

- **D1 — Hand-rolled splitter, not a YAML library.** The frontend declares no YAML package (`src/dashboard/frontend/package.json` has none; `yaml` resolves only by hoisting from the root). The issue asks for values "as plain text", so a full YAML parse buys nothing and a library adds bundle weight. Lists and nested maps render as their source text.
- **D2 — Strip only on a confident match.** FR-1's "at least one top-level key line" requirement is what keeps `---\nprose\n---` rendering as today.
- **D3 — Only `---` closes the block.** YAML's `...` document end marker is not accepted; Mintlify, Jekyll and this repo use `---`.
- **D4 — Empty front matter (`---\n---`) is not stripped**: it has no key line, so FR-4 applies and it renders as today (two `<hr>`s). Rare and harmless.
- **D5 — The list lives inside `MarkdownTab`'s `data-testid="markdown-tab"` container, above `ChatMarkdown`.** It is therefore part of the EditorPane Preview's citable surface; a selection inside it cites its visible text. Citations are text-quoted, never line-numbered (`resolveSelectionCitation.ts` returns `{ source: { kind: 'file', path }, quotedText }`), so removing the block from the rendered body shifts no citation.
- **D6 — MDX `import`/`export` lines and JSX components are untouched** (issue: out of scope). In `features/mission-control.mdx` the `import { ThemedImage } …` line still renders as text between the list and the heading.

### Value rules (FR-6)

For each top-level key line, the inline value is capture group 2 (empty when absent), trimmed. Then:

1. If the inline value is wrapped in matching `"…"` or `'…'`, drop the outer quotes (no escape processing).
2. If the inline value is a block-scalar indicator (`|`, `|-`, `|+`, `>`, `>-`, `>+`), the value is the continuation lines joined with `\n`, with their common leading indentation removed.
3. Otherwise, if continuation lines follow (a list or nested map), the value is the inline value (if non-empty) followed by the continuation lines, joined with `\n`, common indentation removed.
4. Lines inside the block whose first non-blank character is `#` at column 0 are dropped. Blank lines are dropped except inside a block scalar.
5. A non-blank, non-comment line at column 0 that is not a key line and not a list item is appended to the previous key as a continuation line (or ignored if no key has been seen yet).
6. Values render with `white-space: pre-wrap` so multi-line values keep their line breaks.
7. Duplicate keys: keep both entries in source order (no merging).

## Before / after

`src/dashboard/frontend/src/lib/frontMatter.ts` (new):

```ts
export interface FrontMatterEntry { key: string; value: string }
export interface FrontMatterSplit {
  /** Entries in display order: title, description, then source order. Empty when no front matter was found. */
  entries: FrontMatterEntry[]
  /** The Markdown to render: the body after the closing fence, or the unchanged body. */
  content: string
}
export function splitFrontMatter(body: string): FrontMatterSplit
```

`MarkdownTab.tsx` after:

```tsx
const { entries, content } = splitFrontMatter(body)
return (
  <div data-testid="markdown-tab" style={{ padding: 16, fontSize: 13, lineHeight: 1.55 }}>
    {entries.length > 0 ? <FrontMatterList entries={entries} /> : null}
    {content.trim() !== '' ? (
      <ChatMarkdown text={content} cwd={undefined} docLocation={docLocation} {...(docLocation ? { useStreamdown: false } : {})} />
    ) : null}
  </div>
)
```

The existing `!body || body.trim() === ''` empty check stays before the split. `FrontMatterList` is a small function in `MarkdownTab.tsx`:

```tsx
function FrontMatterList({ entries }: { entries: FrontMatterEntry[] }) {
  return (
    <dl data-testid="markdown-front-matter" className="mb-3 grid grid-cols-[max-content_1fr] gap-x-3 gap-y-1 border-b border-border pb-3 text-[12px]">
      {entries.map((e, i) => (
        <Fragment key={`${e.key}-${i}`}>
          <dt className="font-mono-ui text-muted-foreground">{e.key}</dt>
          <dd className="m-0 whitespace-pre-wrap">{e.value}</dd>
        </Fragment>
      ))}
    </dl>
  )
}
```
