# PAN-5413 — One Needs-you count on the Kanban board strip and the top bar

**Issue:** [PAN-5413](https://github.com/eltmon/overdeck/issues/5413)
**Parent rule:** [PAN-5284](https://github.com/eltmon/overdeck/issues/5284) N-D8 (one Needs-you count everywhere)
**Precedent:** [PAN-5371](https://github.com/eltmon/overdeck/issues/5371) (`.pan/drafts/PAN-5371.md`), merged as `9b693f24b76`. It made Simple Home use the shared selector and moved the extra Simple reasons into their own sections. This issue does the same for the Kanban board's strip and reuses PAN-5371's pure helpers.

## 1. Glossary

- **Top bar Needs-you count**: the `Needs you · N` button, `src/dashboard/frontend/src/components/flywheel/NeedsYouIndicator.tsx` (`data-testid="flywheel-needs-you-indicator"`). N is `useNeedsYouItems().length`.
- **Shared selector**: `useNeedsYouItems()` and the pure `buildNeedsYouItems()` in `src/dashboard/frontend/src/lib/selectors/needsYou.ts`. They return `NeedsYouItem[]` (exported type, same file): unresolved pending input of agents and conversations, issues whose `DerivedIssueState.attention === 'needs-you'`, Flywheel tick rows, and other decisions. Items are deduplicated by `key`: `issue:<ID>`, `conversation:<name>`, `agent:<id>`, `flywheel:<hash>`, `decision:<id>`. Each item has `title`, `ask`, `open()`, and optionally `subject` (a `PendingInputSubject` from `lib/store.ts`, with `agentId` and `source: 'agent' | 'conversation'`).
- **Needs-you strip** (or **strip**): `NeedsYouStrip` in `src/dashboard/frontend/src/components/KanbanBoard/NeedsYouStrip.tsx`, rendered by `components/KanbanBoard.tsx` line 795 (`<NeedsYouStrip onOpenIssue={openIssue} />`) above the board columns. Its row component is `NeedsYouRow` in the same file.
- **Simple derivation**: `deriveSimpleIssue()` in `src/dashboard/frontend/src/lib/simple/derive.ts`. When `display.state === 'needs-you'`, `display.needsYouReason` is one of `question | start-work | problems | stuck` (the type `NeedsYouKind` exported from `derive.ts`; note `needsYou.ts` exports a *different* `NeedsYouKind`).
- **Simple buckets**: `bucketSimpleHome()` in `lib/simple/derive.ts`. Its `needsYou` bucket holds every derivation with `display.state === 'needs-you'`, as `{ derivation, kind }`.
- **Displaced kinds**: the Simple reasons the shared selector does not count: `start-work` (plan ready, no work agent), `stuck` (agent problem status or `attention` `stuck`/`api-error`), `problems` (derived `changes-requested`).
- **PAN-5371 helpers**: the pure functions in `src/dashboard/frontend/src/lib/simple/needsYouCards.ts`:
  - `simpleNeedsYouCards(items, byIdentifier)` returns one `SimpleNeedsYouCard { item, derivation, card, title }` per item, in order. `card` is the derivation's `needsYouReason` when the derivation needs you, `'question'` when there is a derivation and `item.subject`, else `'item'`.
  - `simpleSecondarySections(bucketNeedsYou, items)` returns `{ readyToStart, trouble }`: displaced kinds whose issue is not already an `issue:` item. Bucket `question` entries are dropped.
  - `coveredIssueIds(items)`, `issueIdOfItem(item)`.
  These are already unit-tested in `lib/simple/needsYouCards.test.ts`; this issue does not change them.
- **Secondary groups**: the two new strip groups this issue adds, **Ready to start** and **Having trouble**, outside the Needs-you count.
- **CI frontend subset**: `scripts/frontend-test-subset.txt`. CI runs only the frontend Vitest files listed there. `src/App/__tests__/countAgreement.test.tsx` (line 12) and `src/__tests__/fr7-conversation-pending-input.test.tsx` (line 18) are already listed.

## 2. Problem (verified against `7d65fce248f`)

`NeedsYouStrip.tsx` builds its own list. Search `const needs = bucketSimpleHome(derivations).needsYou;`:

```tsx
const needs = bucketSimpleHome(derivations).needsYou;
...
const allItems: NeedsYouItem[] = [...needs.map((n) => ({ source: 'agent' as const, ...n, subjectId: n.derivation.pendingInputAgent?.id ?? '' }))];
for (const s of pendingSubjects ?? []) { ... /* conversation-only questions */ }
...
<span className="text-xl font-medium text-warning-foreground">{items.length}</span>
```

So the strip counts every planned-but-not-started issue (`start-work`), every stuck agent and every `changes-requested` issue, and it counts each conversation question on an issue separately. The top bar counts none of the displaced kinds unless they also carry pending input or `attention: 'needs-you'`, and it counts one item per issue. The strip also never lists Flywheel rows, system decisions, or pending input with no issue, which the top bar counts. The two numbers disagree on the same page.

## 3. Decision

Apply PAN-5371's option 1 to the strip. The strip's number is `useNeedsYouItems().length`, its Needs-you rows are exactly those items, and the displaced kinds render as two labelled groups in the same strip, outside the number. No selector change: PAN-5284 N-D8 rules pipeline states out of the Needs-you list, and PAN-5371 already rejected option 2.

Decision rules (the executor must not re-decide these):

1. **K-D1 Count.** The strip's number is `useNeedsYouItems().length` with no `projectKey` (all projects, like the top bar). The strip keeps ignoring the board's filter bar, as it does today. The number's `<span>` gets `data-testid="needs-you-strip-count"`.
2. **K-D2 Rows.** The Needs-you group renders one row per `simpleNeedsYouCards(needsItems, byIdentifier)` card, in the selector's order. `byIdentifier` is a `Map` from lower-case issue identifier to derivation, built from the `derivations` the strip already computes. Each row is wrapped in `<div data-testid="needs-you-strip-row" data-needs-you-key={card.item.key}>`. The existing cap stays: show the first 6 rows, then `+{n - 6} more`. The number is never capped.
3. **K-D3 Row choice.**
   - `card.card` is `question`, `start-work`, `stuck` or `problems`, and `card.derivation` exists: render `NeedsYouRow` with `item={card.derivation}`, `kind={card.card}`, `question` per K-D4, and answer routing per K-D4.
   - otherwise (`card.card === 'item'`, or no derivation): render the new `NeedsYouItemRow` (K-D5).
4. **K-D4 Question text and answer routing** (rows that have `card.item.subject`):
   - `question = card.item.subject ? card.item.ask : undefined`. The selector's `ask` is the first open question, else "Plan awaiting your approval", else the permission summary, else the kinds description: the same text the top bar shows. With no subject, `NeedsYouRow` falls back to `item.display.sentence`, as today.
   - `isConversation = card.item.subject?.source === 'conversation'`.
   - `conversationName = isConversation ? card.item.subject!.agentId : undefined`. For an agent subject, `NeedsYouRow` keeps answering `item.pendingInputAgent`, as today.
5. **K-D5 Generic row.** `NeedsYouItemRow({ item, onOpen })` is a local component in `NeedsYouStrip.tsx`. It has the same outer classes as `NeedsYouRow` (`flex-none w-[340px] rounded-xl border bg-card p-3 shadow-sm border-warning/40`). It shows `item.title` (the board is Advanced mode, so the selector's "Flywheel" title stays; the "A decision is waiting" rewrite is Simple-mode only) in `text-xs font-medium`, `item.ask` in `text-[11.5px] text-muted-foreground line-clamp-2`, and one **Open** button with the same classes as `NeedsYouRow`'s Open button, calling `item.open()`.
6. **K-D6 Open target.** `NeedsYouRow` rows keep `onOpen={onOpenIssue}` (the issue drawer). `NeedsYouItemRow` calls `card.item.open()`.
7. **K-D7 Secondary groups.** `const secondary = simpleSecondarySections(bucketSimpleHome(derivations).needsYou, needsItems)`. After the Needs-you group, in the same scrolling strip:
   - **Ready to start** (`SIMPLE_STRINGS.home.readyToStartTitle`): one `NeedsYouRow kind="start-work"` per `secondary.readyToStart` entry, in a group wrapper `data-testid="needs-you-strip-ready-to-start"`.
   - **Having trouble** (`SIMPLE_STRINGS.home.troubleTitle`): one `NeedsYouRow kind={t.kind}` per `secondary.trouble` entry, wrapper `data-testid="needs-you-strip-having-trouble"`.
   Each group renders only when non-empty. Each has its own label and count in the same style as the Needs-you label (`text-[11px] font-medium uppercase tracking-[0.1em] text-muted-foreground` label, count in `text-xl font-medium text-muted-foreground`, so only the Needs-you number is amber). Each group caps at 6 rows with its own `+k more`. A `NeedsYouRow` in these groups keeps its existing buttons: **Start work** (and PAN-4399's "Work agent not started" label), **Get it unstuck**, **Tell the agent to fix them**.
8. **K-D8 Empty strip.** The strip returns `null` only when the Needs-you count and both secondary groups are all zero. When the count is 0 but a secondary group has rows, the Needs-you label and its `0` still render (no rows), so the strip's number always matches the top bar whenever it is visible.
9. **K-D9 One row per issue.** The selector folds every pending-input subject on one issue into one `issue:<ID>` item (first subject wins). So two conversations asking questions on the same issue now show one row, as the top bar counts one. The fr7 case that expected two rows is rewritten (WI-1 step 3).
10. **K-D10 Dropped sources.** A bucket `question` entry that is not a shared item (answered, dismissed, or a kind-less phantom wait excluded by PAN-1591) is not shown, the same as Simple Home N-D6.
11. **K-D11 Unchanged.** `buildNeedsYouItems`, `useNeedsYouItems`, `bucketSimpleHome`, `deriveSimpleIssue`, `needsYouCards.ts`, `SimpleHomePage.tsx`, `NeedsYouIndicator.tsx` and `KanbanBoard.tsx` keep their code. `NeedsYouRow`'s props and rendering stay the same, so `NeedsYouStrip.test.tsx` (PAN-4399) passes unchanged.
12. **K-D12 Name collision.** Delete the strip's local `type NeedsYouItem` union. Import the selector's type as `import { useNeedsYouItems, type NeedsYouItem } from '../../lib/selectors/needsYou'`. Keep `type NeedsYouKind` imported from `../../lib/simple/derive` (it types `KIND_META` and `NeedsYouRow`); do not import the selector's `NeedsYouKind`.
