## Glossary

- **Panel** — `SkillOverridesPanel` in `src/dashboard/frontend/src/components/skills/SkillOverridesPanel.tsx`. One component, rendered at three levels.
- **Level** — the `level` prop: `global` (Skills page), `project` (Project settings → Skills), `issue` (issue view → "Skills for this issue"). This PRD changes `project` and `issue` only.
- **Override** — a value stored for one skill at one level. In the GET response it is `skill.global`, `skill.project` or `skill.issue`: `true` (on), `false` (off) or `null` (nothing stored).
- **Stored value** — the override at the level the panel is showing: `levelValue(skill, level)` (`SkillOverridesPanel.tsx:112`).
- **Inherit** — the stored value is `null`. The skill takes the value of the level above.
- **Inherited value** — what the skill resolves to with no stored value at this level, and the level it comes from: `inherited(skill, level)` (`SkillOverridesPanel.tsx:117`). Returns `{ on, from }`, `from` is `'project'` or `'global'`.
- **Effective state** — what an agent launches with: stored value if there is one, otherwise the inherited value. Equal to `skill.enabled` from the server.
- **Changed here** — a non-core skill whose stored value at this level is not `null`. Same predicate as today's `here` filter (`SkillOverridesPanel.tsx:198`).
- **Pin** — store an override equal to the inherited value. Nothing changes now; a later change at the level above no longer changes this skill here. The row reads `pinned here`.
- **Reset** — clear the stored value (PUT `enabled: null`). The skill inherits again.
- **Core skill** — one of the 11 skills the pipeline depends on (`skill.core === true`). Always on, the server rejects any override (`src/lib/skill-overrides/store.ts:641`). Below global they render as one locked summary group.
- **Pack** — a third-party skill set (PAN-4334), rendered by `SkillPacksSection` below the skill list. Out of scope here.
- **Home group** — the origin group a skill belongs to: Overdeck, Personal or Project (`groupOf`, `SkillOverridesPanel.tsx:38`).
- **Narrowing** — a search text or a filter other than All is active (`SkillOverridesPanel.tsx:191`).
- **Mockup** — the operator-approved interactive mockup, `docs/design/issue-view-conversation-first.html`, opened with `?scn=merged&tab=skills`. It is committed on `main`, so issue worktrees contain it; everything the implementation needs from it is also restated in this document.

## Background

At project and issue level each skill row carries a three-button group `Inherit (on via global) | On | Off` (`LevelChoice`, `SkillControls.tsx:56`) plus a two-line state cell (`on` / `default`). The issue view opens on the filter "Overridden here or off" (`FILTERS.issue[0]`, `SkillOverridesPanel.tsx:80`), which hides every skill the issue has not touched. A fresh issue shows an almost empty list and reads as read-only.

The operator approved a redesign on 2026-11-13: one switch per row showing the effective state, the source beside it, one icon button (Pin or Reset), a "Changed" group listed first, and All as the default filter.

Verified facts this design rests on:

1. **The three stored states already exist and stay.** `PUT /api/skills/overrides` takes `{ level, skill, enabled: true|false|null, projectKey?, issueId? }` (`src/dashboard/server/routes/misc/skill-overrides.ts:5`). `parseSkillOverrideUpdate` rejects anything else (`store.ts:355`, search `enabled must be true, false, or null`). `null` removes the key (`store.ts:72`, search `null = inherit (remove the key)`).
2. **A pin is storable today.** `setProject` and `setIssue` store whatever boolean they are given without comparing it to the inherited value (`store.ts:454`, search `overrides[skill] = enabled;`; `store.ts:543`, search `skills[skill] = enabled;`). Only the global level collapses a value equal to the default (`store.ts:419`). So `enabled: true` on a skill that already inherits on is written and kept.
3. **Effective state equals `current ?? inherited.on`.** `resolveOne` walks issue → project → global → default on (`src/lib/skill-overrides/resolve.ts:67`). `loadSkillOverrideLayers` never loads a conversation layer for this route (`store.ts:130`).
4. **`SkillPacksSection` uses `LevelChoice`** (`SkillPacksSection.tsx:288`), so `LevelChoice` stays exported.
5. **Both skills test files pass at this commit** (`npx vitest run src/components/skills/` from `src/dashboard/frontend`: 2 files, 24 tests). Neither is in `scripts/frontend-test-subset.txt`, so CI does not run them today.

## Requirements

- **FR-1** At `level="project"` and `level="issue"`, each non-core skill row has exactly one `role="switch"` control. It shows the effective state. `LevelChoice` is not rendered for skills at these levels.
- **FR-2** Beside the switch the row shows one mono source text, per the state table in WI-2: `on · global`, `off · global`, `on · project`, `off · project`, `on · this issue`, `off · this issue`, `on · this project`, `off · this project`, `on · pinned here`, `off · pinned here`.
- **FR-3** Toggling the switch computes `desired = !effective`. If `desired` equals the inherited value the panel PUTs `enabled: null`; otherwise it PUTs `enabled: desired`.
- **FR-4** A row with no stored value shows a Pin button. Pin PUTs `enabled: <inherited value>`.
- **FR-5** A row with a stored value shows a Reset button instead of Pin. Reset PUTs `enabled: null`.
- **FR-6** Saving, the row error with Retry, and the "Saved locally; push pending" notice behave as today for every new control.
- **FR-7** At project and issue level, with no search and the All filter, a "Changed" group renders above the skill list. It lists every non-core skill with a stored value at this level, shows their count, and each such skill also stays in its home group.
- **FR-8** The Changed group has a "Reset all" button when it has rows. It PUTs `enabled: null` for each row in order, one at a time, and stops at the first failure, which shows that row's error.
- **FR-9** An empty Changed group shows one line. Issue: "Nothing is changed. This issue's agents launch with the project's skills." Project: "Nothing is changed. This project's agents launch with the global skills."
- **FR-10** Filters: issue `All | Changed here | Off`; project `All | Changed here | Off at launch`. Every level opens on All. The `relevant` filter is removed.
- **FR-11** The summary line gains `· N changed here` at project and issue level.
- **FR-12** The live-agent message renders as an amber notice (8% background, 32% border of `--warning`). Text and `data-testid` are unchanged.
- **NFR-1** No server change, no new endpoint, no new polling. The only requests are the existing `GET` and `PUT /api/skills/overrides`.
- **NFR-2** `level="global"` and `SkillPacksSection` render and behave as today. `SkillPacksSection.test.tsx` passes without edits.
- **NFR-3** `SkillOverridesPanelProps` is unchanged and `SkillOverridesSections.tsx` is not edited, so PAN-5244 can move the mount point freely.
- **NFR-4** Every control has an accessible name containing the skill name; hints go in `title`.
- **NFR-5** The three skills test files run in CI (`scripts/frontend-test-subset.txt`).
- **NFR-6** Style guide rules in "Repo rules that apply" hold for all new markup.

## Decisions

1. **Levels.** `project` and `issue` change. `global` keeps its two-state switch.
2. **Pinned is derived, never stored as a flag.** A row reads `pinned here` when its stored value equals the inherited value. If the level above later changes, the same stored value reads `this issue` / `this project`. No new field.
3. **The switch always produces the smallest stored state.** Toggling back to the inherited value clears the override. Consequence: toggling a pinned row twice ends at inherit, the pin is gone. The operator pins again with the Pin button.
4. **The inherited level reads `global` even when global has no stored value.** `inherited()` already returns `from: 'global'` for the built-in default. The word `default` no longer appears in project and issue rows.
5. **A changed skill renders twice:** once in the Changed group, once in its home group. Both copies share saving and error state, so an error shows on both. Tests scope queries by group.
6. **Reset all has no confirmation dialog.** Each reset is a small write the operator can redo.
7. **Reset all refreshes the list once, after the loop,** not after every row. While it runs, every row control in the panel is disabled.
8. **The `off` filter keeps its current meaning** at both levels: effective state is off (`!skill.enabled`).
9. **The switch's accessible name is `<skill> for this <level>` and does not change with state.** `role="switch"` plus `aria-checked` carries the action; a name that flips with state is announced twice. Pin and Reset names carry their action.
10. **Packs keep `Inherit | On | Off`.** A follow-up issue covers them.
