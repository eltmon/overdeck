# PAN-4457 — Show linked pull requests where the operator looks

**Issue:** [PAN-4457](https://github.com/eltmon/overdeck/issues/4457)
**Builds on:** PAN-3822 (conversation PR links, a near port of t3code's thread PR links)
**t3code reference:** `apps/server/src/orchestration/ThreadPullRequestReactor.ts` at `094fb230e9` (~line 225)

## Glossary

- **PR link** — a row in the `conversation_pull_requests` table (overdeck.db) that ties one pull request
  (host, repository, number) to one conversation. Columns that matter here: `source`
  (`branch` | `created` | `manual` | `agent`), `dismissed_at` (unlink tombstone), `snapshot_json`.
- **Snapshot** — the stored `PullRequestSnapshot` (`packages/contracts/src/pull-request-links.ts`):
  state (`open` | `merged` | `closed`), draft, title, `reviewState`, `checks`, `mergeable`, timestamps.
- **PR sync sweep** — `runPullRequestSyncOnce` in `src/dashboard/server/services/pull-request-sync-service.ts`.
  Primary dashboard only; boot +30 s, then every 60 s. It inserts `branch` links and refreshes snapshots.
- **Branch link** — a PR link the sweep inserts because the PR's head branch equals the branch the
  conversation works on (`resolveConversationBranch`). Inserted once, never deleted by the sweep.
- **Created link** — a PR link with source `created`, written by `linkCreatedPullRequestToIssueConversations`
  when the pipeline opens a PR (`pan done`, or `createReviewArtifactsForIssue`).
- **Operator conversation** — a conversation whose name does NOT start with `agent-`, `planning-` or
  `specialist-` (`isAgentConversationName` in `src/lib/overdeck/conversations.ts`, line 453). Only
  operator conversations appear in Command Deck's conversation list.
- **Agent conversation** — the opposite: names starting `agent-`, `planning-`, `specialist-`. Hidden from
  `listConversations()` (`src/lib/overdeck/conversations.ts`, the `NOT LIKE 'agent-%'` filter ~line 583).
- **Primary checkout** — the project's main git checkout (the project `path` in `projects.yaml`), shared by
  every conversation whose cwd is inside it. `resolveConversationGitInfo(cwd).isWorktree === false` there.
- **Linked worktree / feature workspace** — `workspaces/feature-<issue>/` (a git worktree);
  `isWorktree === true`.
- **Derived issue state** — `DerivedIssueState` (`packages/contracts/src/derived-issue-state.ts`), computed by
  `loadIssueStatesForProject` (`src/lib/overdeck/derived-issue-state.ts`) and cached in
  `IssueDataService.derivedStatesCache`. It carries `pr?: DerivedPrState` = `{ url, number, reviewState,
  checks, mergeable, merged? }`. Reaches the browser as `issue_state.changed` events into
  `derivedIssueStateByIssueId`; read with `useDerivedIssueState(issueId)`.
- **Issue row** — a Command Deck project-tree row for one issue: `FeatureItem`
  (`src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureItem.tsx`).
- **Workspace row** — an issue-kind row in the sidebar's Workspaces rail: `renderWorkspaceRow` in
  `src/dashboard/frontend/src/components/Sidebar.tsx` (~line 455).
- **Live pane inventory** — `getBackendPanes()` in `src/dashboard/server/services/backend-inventory.ts`: every
  live agent/conversation pane on the active terminal backend (Herdr by default, tmux when configured).
  `paneAgentKey(pane)` (`packages/contracts/src/backend-pane.ts`) gives the agent id; for a conversation it is
  the conversation's `tmuxSession` (`conv-<name>`).

## Problem (verified 2026-10-01)

Overdeck stores PR links but the operator never sees them in Command Deck. Live DB: 159 links (122 `branch`,
37 `created`), all on agent conversations, none on operator conversations. Of 1411 operator conversations,
42 are live (non-archived, non-vault), and almost all sit in a primary checkout.

1. `listConversations()` drops every agent conversation, so the 159 links never render in the list.
2. `resolveConversationBranch` (`src/lib/overdeck/conversation-branch.ts`, line 34) ignores the branch of any
   operator conversation in a primary checkout:
   `let branch = info.branch && info.branch !== 'HEAD' && (info.isWorktree || isAgent) ? info.branch : null;`
3. Since the PAN-3917 Cut, work agents create no `agent-pan-NNNN` conversation rows (newest
   `agent-pan-3941`), so `linkCreatedPullRequestToIssueConversations`
   (`src/lib/overdeck/conversation-pull-requests.ts`, line 194; called from `src/cli/commands/done.ts`
   line 245 and `src/lib/review-artifacts.ts` line 140) reaches only `-review` conversations.
4. Issue rows show only a neutral `#NNNN` resource chip (`ResourceCluster.tsx`, the `pr` source) for
   **open** PRs, from a listing that converges every 5 minutes, with no checks or review state. Derived issue
   state does carry the PR with checks and review state, but it only refreshes when the tracker issue set
   changes, and the repo PR listing it reads is cached 30 s (5 min when the repo has no open PR,
   `PR_CACHE_IDLE_TTL_MS` in `src/lib/overdeck/pr-cache-policy.ts`). A freshly opened PR can therefore take
   minutes to reach the row.

## Scope

In scope: issue items 1–3. (1) PR badge on issue rows and workspace rows from derived issue state, refreshed
within 60 s of `pan done` opening the PR. (2) Branch matching for operator conversations in a primary checkout
on a non-default branch, with merged links kept after the checkout returns to the default branch.
(3) Created links also reach operator conversations whose cwd is inside the issue's feature workspace.

## Non-goals

- Item 4 of the issue: no agent-callable link tool, no PR side panel (checks, review, mergeability), and no
  extra refresh triggers on branch change, turn end, or window focus.
- Unhiding agent conversations in `listConversations()` or the Command Deck conversation list.
- No change to `packages/contracts` (`DerivedPrState`, `PullRequestSnapshot`, `PullRequestLink` stay as they are).
- No new HTTP route and no new or changed CLI verb or flag.
- No periodic derived-state refresh timer; PRs opened by hand without webhooks keep today's cadence.
- No change to auto-archive-on-merge, including its tmux-only liveness read (recorded as a concern).
- No GitLab merge-request badge on issue rows beyond what derived state already provides.
- Showing a `closed` (unmerged) PR on an issue row: `prFromGhRow` drops closed-unmerged PRs by design.

## Decisions

- **D1 — Issue/workspace row source is derived issue state.** Use `useDerivedIssueState(issueId)?.pr` (and the
  store map in Sidebar). It already carries checks and review state and reaches the browser over `/ws/rpc`.
  The `resourceDetails.prs` listing has no URL on the frontend type and converges only every 5 min.
- **D2 — One renderer.** Rows reuse `PullRequestBadge` (`src/dashboard/frontend/src/components/primitives/PullRequestBadge.tsx`)
  so PAN-3822's tone law stays single. Its prop type is widened to the four fields it reads
  (`url`, `number`, `repository`, `snapshot`), and a new frontend adapter builds that shape from `DerivedPrState`.
- **D3 — Badge state from derived PR.** `merged === true` ⇒ `merged`, otherwise `open`. Draft and title come
  from the `resourceDetails.prs` entry with the same number when present, else `false` / `''`. Counts and
  timestamps are `null`; `syncedAt` is `''`.
- **D4 — No duplicate fact.** When the row renders the PR badge, `ResourceCluster` gets `'pr'` in `omit`.
  When derived state has no PR, the row is unchanged (the neutral chip still shows).
- **D5 — Freshness via the one review door.** `startRequestReviewPipeline`
  (`src/dashboard/server/routes/workspaces/review-pipeline.ts`) is called by `pan done` right after it opens
  the PR, and by the GitHub `pull_request` webhook for PRs opened by hand. There, invalidate the project's PR
  listing cache and schedule a derived-state refresh for the issue. The badge appears in seconds.
- **D6 — Primary-checkout matching needs a live pane.** t3code keys PR detection on a per-thread recorded
  branch (`thread.branch`); Overdeck conversations record none. To stop every conversation in a shared
  checkout from collecting the PR of whatever branch the checkout drifts onto, an operator conversation in a
  primary checkout counts its cwd branch only when its pane is live at sweep time (in the live pane inventory,
  state not `exited`). When the inventory is degraded (`isBackendInventoryDegraded()`) or the read throws,
  liveness is unknown and primary-checkout operator matching is skipped for that sweep.
- **D7 — "Stays after merge" needs no new mechanism.** `upsertBranchPullRequestLink` only inserts, the sweep
  never deletes, and merged snapshots are never re-read (`isDue` returns false). A test proves it.
- **D8 — Created links by workspace prefix.** `linkCreatedPullRequestToIssueConversations(issueId, url, workspacePath?)`
  keeps the agent-by-`issue_id` selection and adds non-archived, non-vault operator conversations whose `cwd`
  equals `workspacePath` or starts with `workspacePath + '/'`. Matched with `instr(cwd, ?) = 1`, never `LIKE`
  (`_` and `%` are wildcards in `LIKE`).

## Requirements

- **FR-1** An issue row whose derived state has a PR renders `PullRequestBadge` with that PR's number, state
  (open/merged), review state (tone + label) and checks (× glyph + label), and clicking it opens the PR URL.
- **FR-2** An issue-kind workspace row in the sidebar Workspaces rail renders the same badge from the same source.
- **FR-3** The badge tooltip/aria-label names the checks state (`checks passing` / `checks failing` /
  `checks pending`) and the review state (`approved` / `changes requested` / `review requested` / `commented`;
  omitted for `none`).
- **FR-4** When `startRequestReviewPipeline` accepts a review request, the issue's derived state is recomputed
  from a fresh PR listing (cache invalidated), so an open PR shows on the issue row within 60 s of `pan done`.
- **FR-5** The sweep links an operator conversation in a primary checkout by its cwd branch when that branch is
  not the default branch, is not detached, and the conversation's pane is live.
- **FR-6** A branch link whose PR merged stays linked (and keeps its merged snapshot) after the conversation's
  checkout returns to the default branch or the workspace directory is removed.
- **FR-7** When the pipeline opens a PR, operator conversations whose cwd is the issue's workspace or inside it
  get a `created` link without waiting for a sweep, plus a `conversation.pull_requests_changed` event when the link
  is written inside the dashboard process (`review-artifacts.ts`). From `pan done` the CLI writes the row and the
  emit is a documented no-op; the next sweep or list read surfaces it. Tests assert stored rows, not events.
- **NFR-1** No new forge reads per sweep: liveness comes from the in-process pane inventory, and the review-door
  refresh costs at most one `gh pr list` per review request.
- **NFR-2** No file over the 1000-line ceiling grows (`issue-data-service.ts` is at its 1754 cap and is not edited).
- **NFR-3** Delay/schedule tests use fake timers (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`); no real waits.
- **NFR-4** Frontend tests added by this issue are listed in root `package.json` `test:frontend-subset`, or CI never runs them.
- **NFR-5** Every failure in the new paths is caught and logged; a failed refresh or link never fails the review request or the PR creation.

## Intersecting repo rules (restated)

- No `execSync` in dashboard-server-reachable code; all new server code is synchronous in-memory work or async.
- Fake timers for any delay/backoff/schedule test (NFR-3).
- File-size ratchet: files at or above 1000 lines may not grow past their `origin/main` count or allowlist row

- New HTTP routes need a no-loss matrix row — this issue adds none.
- Frontend style law (`pan-style-guide`): no new colors; the badge's existing tone classes are reused.
- Never `git stash`; never `git checkout` inside the workspace.
