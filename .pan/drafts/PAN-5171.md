# PAN-5171: Issue headers resolve the issue through a per-issue read, never the literal "Issue details"

**Issue:** https://github.com/eltmon/overdeck/issues/5171
**Related:** PAN-3659 (server backfill for aged-out issues), PAN-4717 (drawer tracker-URL fallback), PAN-2351 (route-scope table), PAN-4835 (phone surface inventory)

## Glossary

- **Issue list / `issuesRaw`**: the global issue array in the frontend dashboard store (`useDashboardStore`, `selectIssues` in `src/dashboard/frontend/src/lib/store.ts`, line 701: `export const selectIssues = (s: DashboardState): unknown[] => s.issuesRaw`). It is filled from the `/ws/rpc` snapshot and `issues.delta` events.
- **Snapshot cycle filter**: the server read model fills `issuesRaw` from `issueService.getIssues()` with no options (`src/dashboard/server/read-model.ts`, lines 425 and 639). The default `cycle` is `'current'`, and `computeIssues` (`src/dashboard/server/services/issue-data-service.ts`, around line 471) then drops every row whose canonical status is `backlog` or `canceled`. So a backlog or canceled issue is never in `issuesRaw`, even though the tracker poll fetched it.
- **Shared issue service**: the `IssueDataService` singleton returned by `getSharedIssueService()` (`src/dashboard/server/services/issue-service-singleton.ts`). It holds the polled tracker rows (`lastFetchedIssues` per tracker) plus `backfilledIssues`.
- **Backfill**: `IssueDataService.backfillIssue(issueId)` (`issue-data-service.ts`, line 807, quote: `async backfillIssue(issueId: string): Promise<void> {`). When no tracker row exists for the identifier, it resolves the issue through `resolveMissingIssue` and stores it in `backfilledIssues`, then pushes an update. It is a no-op when a polled row already exists (`hasIssueByIdentifier`).
- **Tracker door / `resolveMissingIssue`**: `src/dashboard/server/services/issue-title-fallback.ts`, line 68. Calls `tracker.getIssue(id)` with a 10 s timeout. It memoizes successes for the process lifetime and failures for 10 minutes (`FAILURE_RETRY_MS`). Today it returns `null` for every failure: not found, timeout, auth error and unconfigured tracker all look the same.
- **`IssueNotFoundError`**: the tagged error a tracker adapter fails with when the tracker reports that an issue does not exist (`src/lib/tracker/interface.ts`, line 233). GitHub maps HTTP 404 to it (`src/lib/tracker/github.ts`, line 33). Linear maps **every** `LinearApiError` to it (`src/lib/tracker/linear.ts`, lines 180-186).
- **Per-issue read**: the new route `GET /api/issues/:id` this PRD adds. It returns one dashboard-shaped issue row.
- **Issue record**: the frontend result of the new `useIssueRecord(issueId)` hook: `{ issue, status }`, where `issue` comes from the list entry when present and from the per-issue read otherwise.
- **Header surfaces**: the three places that render an issue's title as a header: the drawer (`IssueDrawer.tsx`), the cockpit (`IssueMissionControl.tsx`), and the phone sheet (`MobileIssueSheet.tsx`).
- **Route-scope table**: `ROUTE_SCOPES` in `src/dashboard/server/route-scopes.ts`. Non-root credentials need the listed scope per `METHOD path`. Unlisted routes need `admin`. Matching is **first match wins** (`requiredScopeFor`, line 305: `ROUTE_SCOPES.find(...)`), and `:param` matches one segment.
- **No-loss matrix**: `NO_LOSS_MATRIX` in `tests/unit/lib/overdeck/no-loss-matrix.ts`. Every HTTP route must have a row, and every route-scope row must name a matrix surface (`src/dashboard/server/__tests__/route-scopes.test.ts`, line 13).

## Problem

The drawer header reads `issue?.title ?? 'Issue details'` (`src/dashboard/frontend/src/components/drawer/IssueDrawer.tsx`, line 105). `issue` comes from `useIssueData` (`src/dashboard/frontend/src/components/drawer/useDrawerData.ts`, line 355, quote: `const issue = issues.find((candidate) => issueMatches(candidate, drawerIssueId)) ?? null;`), which only searches `issuesRaw`.

So the header shows the placeholder in three cases:

1. **While the snapshot loads.** Measured on 2026-11-13: 2.6 s to 4.0 s after first paint for listed issues (PAN-5170, PAN-5168, PAN-4294).
2. **A new issue before the next push.** The tasks count loaded but the title did not.
3. **An issue the list never holds.** Backlog and canceled issues are filtered out of the snapshot by the cycle filter (see Glossary), so `backfillIssue` is a no-op for them (a polled row exists) and the header shows the placeholder forever. Issues that aged out of the sync window were fixed by PAN-3659's backfill only after a round trip through `subscribeIssueEvents`.

The cockpit header has the same dependency: `CommandDeck/index.tsx` line 1333 resolves `issueTitles[key] || issueTitles[issueId] || issueId` from `issuesRaw`, so the cockpit `<h1>` (`IssueMissionControl.tsx`, line 604) shows the bare identifier instead. The phone sheet (`MobileIssueSheet.tsx`, lines 41-58) shows "Loading issue…" before the snapshot and "This issue is not in the pipeline." when the list lacks the row.

## Decisions (made in this document)

- **D-1 Route shape.** Add `GET /api/issues/:id` in a new route module `src/dashboard/server/routes/issue-read.ts`, same pattern as `routes/test-removal-waiver.ts`. Do not add it to `routes/issues.ts` (889 lines) or to `issue-data-service.ts` (1748 lines against a 1754 cap in `scripts/file-size-allowlist.txt`). The route uses only public service methods: `getIssues({ cycle: 'all', includeCompleted: true })` and `backfillIssue(id)`.
- **D-2 Lookup uses `cycle: 'all'`.** The route searches `getIssues({ cycle: 'all', includeCompleted: true })` by identifier, case-insensitive. This finds backlog and canceled rows the snapshot drops. The result is cached inside the service (`getIssuesCache`), so repeat calls cost a map lookup.
- **D-3 Status codes.** `200` with the bare issue row (same shape as an `issuesRaw` entry, serialized by `jsonResponse`). `400 { error: 'Invalid issue ID' }` when `parseIssueId(id)` is null. `404 { error: 'Issue not found', issueId }` only when the tracker lookup failed with `IssueNotFoundError`. `503 { error: 'Issue tracker unavailable', issueId }` for every other failure: timeout, API error, auth error, and no tracker configured for the prefix.
- **D-4 Failure memo applies.** The route reuses the 10-minute failure memo in `issue-title-fallback.ts`. A repeat request inside the window returns the memoized kind without a new tracker call. This protects the tracker from a drawer reopened in a loop.
- **D-5 Linear's broad mapping is accepted.** Linear turns every `LinearApiError` into `IssueNotFoundError`, so a Linear transport failure answers 404. The frontend shows the identifier plus a hint in both cases, so only the hint text differs. Fixing the Linear adapter is a NonGoal (other callers depend on it).
- **D-6 Route-scope rows.** Add `GET /api/issues/:id` at `read:state` (the phone and access tokens already read `GET /api/issues` at `read:state`). Because matching is first-match and `:id` also matches `resource-allocated`, add an explicit `GET /api/issues/resource-allocated` row at `admin` **before** the `:id` row, so the existing admin requirement for that route does not widen (same pattern as the PAN-4835 `pending-input` row). `GET /api/issues/:id/tasks` keeps needing `admin` (two segments never match `:id`).
- **D-7 Backfill exposure.** Today `backfillIssue` runs behind the `subscribeIssueEvents` RPC, which is not in `RPC_METHOD_SCOPES` and so needs `admin`. This route exposes a tracker lookup at `read:state`. Accepted: each identifier costs at most one tracker call per success (memoized forever) or per 10-minute failure window, and `read:state` holders are already trusted to read the whole issue list.
- **D-8 Router precedence.** Effect's `HttpRouter` uses `FindMyWay` (`node_modules/effect/dist/unstable/http/HttpRouter.js`, line 53), where a static segment beats a `:param`. So `GET /api/issues/resource-allocated` keeps reaching its own handler. A route test proves this (WI-2).
- **D-9 One frontend hook.** A new hook `useIssueRecord(issueId)` in `src/dashboard/frontend/src/components/issue-view/useIssueRecord.ts` is the only place that combines the list entry and the per-issue read. The drawer (through `useIssueData`), the cockpit and the phone sheet call it. React Query dedupes the key, so several callers cost one request.
- **D-10 Hook contract.**
  - Query key: `['issue', issueId.toUpperCase()]` (exported as `issueRecordQueryKey`).
  - `enabled: Boolean(issueId) && listed === null`. The fetch starts on the first render that lacks a list row, in parallel with everything else.
  - No `refetchInterval`. `staleTime: 30_000`. `retry: false`. The server memoizes tracker failures for 10 minutes (D-4), so a client retry would get the same answer; a query-level retry would also override the test clients' `retry: false` and add a real 1 s delay to every failure test. A 404 is returned as data (`null`), not thrown.
  - Payload validation: the body must be an object with a string `identifier` and a string `title`, or the read counts as unavailable. Existing test fetch mocks answer unknown URLs with `{ success: true }` or `{}`, which must not render as an issue.
  - Precedence: the list entry always wins when present. The per-issue read is a permanent source, not a stopgap: backlog and canceled issues never reach the list.
  - Status: `'ready'` (an issue is available), `'loading'` (enabled and no data or error yet), `'not-found'` (404), `'unavailable'` (any other failure, a malformed body, or a null `issueId`).
- **D-11 One header renderer.** A new component `IssueHeaderTitle` in `src/dashboard/frontend/src/components/issue-view/IssueHeaderTitle.tsx` renders the inside of each header element. Each caller keeps its own `<h1>`/`<h2>` and typography.
  - `ready`: the issue title text.
  - `loading`: a neutral skeleton bar (`data-testid="issue-title-skeleton"`, `aria-hidden="true"`) plus a screen-reader-only text `Loading issue title`.
  - `unavailable`: the identifier as text plus a small hint `<span data-testid="issue-title-hint">title unavailable</span>`.
  - `not-found`: the identifier as text plus the hint `not found on tracker`.
  - It never renders the string `Issue details`.
- **D-12 Cockpit fallback.** The cockpit header title is `record.issue?.title`, else the `title` prop when it is not equal to the identifier (case-insensitive), else the `IssueHeaderTitle` state. The `title` prop and `useIssueView(issueId, { title, … })` are unchanged. No new props are threaded through `CommandDeck/index.tsx` (1590 lines against a 1612 cap).
- **D-13 Phone sheet.** When the record has an issue (list or per-issue read), the full sheet renders exactly as today. `loading` replaces "Loading issue…" with the header skeleton. `not-found` and `unavailable` replace "This issue is not in the pipeline." with the identifier plus hint. The `hasSnapshot` gate is removed (the per-issue read does not need the snapshot). Remove the `useConnectionState` import if nothing else in the file uses it.
- **D-14 E2E.** The committed Playwright check extends `tests/e2e/styleguide-conformance.spec.ts`, which already serves the real frontend with a mocked `fetch` and a cached snapshot and opens `/pipeline?issue=PAN-1148`. A signed-in live-dashboard check is the test role's UAT, run in an isolated Playwright browser context (see Acceptance).
- **D-15 Docs.** `docs/ISSUE-VIEW.md` line 7 says the issue view "must not introduce another endpoint". This change deliberately adds one per-issue read, so WI-9 rewrites that sentence to name it as the one allowed header read.

## Requirements

### Functional

- **FR-1** `GET /api/issues/:id` returns `200` with the dashboard-shaped row for any issue the shared issue service holds, including backlog, canceled, completed and backfilled rows.
- **FR-2** When the service lacks the issue, the route awaits `backfillIssue(id)` and returns the backfilled row with `200`.
- **FR-3** The route returns `404` only when the tracker lookup failed with `IssueNotFoundError`; every other failure returns `503`; an id `parseIssueId` rejects returns `400`.
- **FR-4** `GET /api/issues/:id` needs `read:state`; `GET /api/issues/resource-allocated` still needs `admin`; the route has a no-loss-matrix row.
- **FR-5** `useIssueRecord(issueId)` returns the list entry when present, and otherwise the per-issue read, with the status contract in D-10.
- **FR-6** The drawer header renders the title from the per-issue read when `issuesRaw` lacks the issue.
- **FR-7** No header surface renders the literal string `Issue details` in any state.
- **FR-8** While neither source has answered, each header surface renders the identifier (already shown above or beside the title) and a skeleton bar of title height.
- **FR-9** When the per-issue read fails, each header surface renders the identifier as the title with a hint (`title unavailable`, or `not found on tracker` for a 404).
- **FR-10** The cockpit header and the phone sheet follow FR-6 to FR-9.

### Non-functional

- **NFR-1** The per-issue read starts on the drawer's first render, in parallel with other queries, and is skipped entirely when the list holds the row.
- **NFR-2** A listed issue's header shows its real title within 1 s of opening `?issue=<id>` on a running dashboard.
- **NFR-3** No file grows past its file-size allowance (`scripts/lint-file-size.sh`: 1000-line ceiling, or the `scripts/file-size-allowlist.txt` cap). No `execSync` in server code.

## Intersecting repo rules (restated)

- **No `execSync` in dashboard server code.** The route is async only.
- **Fake timers for delay-based tests.** Any test that waits on a delay or retry uses `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`. Hold a loading state with an unresolved promise (a fetch mock that returns a never-settling or manually-resolved promise), not a real timer.
- **TanStack `setQueryData` notifies asynchronously.** Wrap state changes in `await act(async () => …)` and wait for the DOM.
- **CI runs only listed frontend tests.** Every new frontend test file is added on its own line, in sorted position, to `scripts/frontend-test-subset.txt` (paths relative to `src/dashboard/frontend`).
- **No source-grep tests.** New tests must not read source files to assert on their text (lint rejects it). "Never shows Issue details" is a render assertion.
- **No added `skipIf` / `.only`.** The test-skip gate fails them.
- **New HTTP route ⇒ no-loss-matrix row**, or CI fails.
- **`lint:circular` counts `import type` edges.** `useIssueRecord.ts` must not import from `drawer/useDrawerData.ts`; the drawer imports the hook, never the reverse.
- **Style guide.** The skeleton is a neutral bar (`bg-muted`), no color signal; no new fonts or weights.
- **Changelog entries:** a user-facing change adds `changelog.d/pan-5171.md` in the `#### Fixed` format from `changelog.d/README.md`. No em dashes.

```ts
/**
 * `GET /api/issues/:id` (PAN-5171): one dashboard-shaped issue for the issue
 * view headers (drawer, cockpit, phone sheet), so a header never waits on, or
 * depends on, the full issue list. Reads the shared issue service with
 * `cycle: 'all'` (the snapshot drops backlog and canceled rows), backfills
 * through the tracker door when the service lacks the issue, and answers 404
 * only when the tracker says the issue does not exist.
 */
import { Effect, Layer } from 'effect';
import { HttpRouter } from 'effect/unstable/http';

import { parseIssueId } from '../../../lib/issue-id.js';
import { jsonResponse } from '../http-helpers.js';
import { getSharedIssueService } from '../services/issue-service-singleton.js';
import { missingIssueFailureKind } from '../services/issue-title-fallback.js';
import { httpHandler } from './http-handler.js';

function findIssueRow(key: string): unknown | null {
  const issues = getSharedIssueService().getIssues({ cycle: 'all', includeCompleted: true }) as Array<{ identifier?: unknown }>;
  return issues.find((issue) => typeof issue?.identifier === 'string' && issue.identifier.toUpperCase() === key) ?? null;
}

export async function readIssueRow(rawId: string): Promise<{ status: 200; issue: unknown } | { status: 404 | 503 }> {
  const key = rawId.toUpperCase();
  const listed = findIssueRow(key);
  if (listed) return { status: 200, issue: listed };
  await getSharedIssueService().backfillIssue(key);
  const backfilled = findIssueRow(key);
  if (backfilled) return { status: 200, issue: backfilled };
  return { status: missingIssueFailureKind(key) === 'not-found' ? 404 : 503 };
}

const getIssueRoute = HttpRouter.add(
  'GET',
  '/api/issues/:id',
  httpHandler(Effect.gen(function* () {
    const params = yield* HttpRouter.params;
    const id = params['id'] ?? '';
    if (!parseIssueId(id)) return jsonResponse({ error: 'Invalid issue ID' }, { status: 400 });
    const result = yield* Effect.promise(() => readIssueRow(id));
    if (result.status === 200) return jsonResponse(result.issue);
    const issueId = id.toUpperCase();
    return result.status === 404
      ? jsonResponse({ error: 'Issue not found', issueId }, { status: 404 })
      : jsonResponse({ error: 'Issue tracker unavailable', issueId }, { status: 503 });
  })),
);

export const issueReadRouteLayer = Layer.mergeAll(getIssueRoute);
```

### WI-3: `useIssueRecord` hook (FR-5, NFR-1)

**File:** new `src/dashboard/frontend/src/components/issue-view/useIssueRecord.ts`. **Test:** new `src/dashboard/frontend/src/components/issue-view/useIssueRecord.test.tsx`, added to `scripts/frontend-test-subset.txt`.

```ts
import { useQuery } from '@tanstack/react-query';

import { selectIssues, useDashboardStore } from '../../lib/store';
import type { Issue } from '../../types';

export type IssueRecordStatus = 'ready' | 'loading' | 'not-found' | 'unavailable';
export interface IssueRecord { issue: Issue | null; status: IssueRecordStatus }

export const issueRecordQueryKey = (issueId: string) => ['issue', issueId.toUpperCase()] as const;

/** Same match rule the drawer used (identifier or id, case-insensitive). */
export function findListedIssue(issues: readonly Issue[], issueId: string): Issue | null {
  const target = issueId.toLowerCase();
  return issues.find((issue) => issue.identifier.toLowerCase() === target || issue.id.toLowerCase() === target) ?? null;
}

function isIssueRow(value: unknown): value is Issue {
  return typeof value === 'object' && value !== null
    && typeof (value as { identifier?: unknown }).identifier === 'string'
    && typeof (value as { title?: unknown }).title === 'string';
}

/** One issue from `GET /api/issues/:id`; null means the tracker says it does not exist (404). */
export async function fetchIssueRecord(issueId: string): Promise<Issue | null> {
  const res = await fetch(`/api/issues/${encodeURIComponent(issueId)}`);
  if (res.status === 404) return null;
  if (!res.ok) throw new Error(`issue read failed: ${res.status}`);
  const body: unknown = await res.json();
  if (!isIssueRow(body)) throw new Error('issue read returned a malformed row');
  return body;
}

export function useIssueRecord(issueId: string | null): IssueRecord {
  const listed = useDashboardStore((s) => (issueId ? findListedIssue(selectIssues(s) as Issue[], issueId) : null));
  const query = useQuery({
    queryKey: issueRecordQueryKey(issueId ?? ''),
    queryFn: () => fetchIssueRecord(issueId as string),
    enabled: Boolean(issueId) && listed === null,
    staleTime: 30_000,
    retry: false,
  });
  if (!issueId) return { issue: null, status: 'unavailable' };
  if (listed) return { issue: listed, status: 'ready' };
  if (query.data) return { issue: query.data, status: 'ready' };
  if (query.data === null) return { issue: null, status: 'not-found' };
  if (query.isError) return { issue: null, status: 'unavailable' };
  return { issue: null, status: 'loading' };
}
```

```tsx
import type { IssueRecordStatus } from './useIssueRecord';

/**
 * The inside of an issue header (PAN-5171): the title, a neutral skeleton
 * while no source has answered, or the identifier with a short hint when the

 * heading element and its typography.

export function IssueHeaderTitle({ issueId, title, status }: { issueId: string; title: string | null; status: IssueRecordStatus }) {
  if (title) return <>{title}</>;
  if (status === 'loading') {
    return (
      <>

  );
}
```
