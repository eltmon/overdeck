# PAN-5585 — Phone-width conversation page: overlay Agents rail, compact top bar, wrapping header, keyboard-safe shell

**Issue:** [PAN-5585](https://github.com/eltmon/overdeck/issues/5585)
**Status:** draft (auto-planned 2026-11-21)

## Glossary

- **Agents rail** — `SubagentRail` (`src/dashboard/frontend/src/components/chat/SubagentRail.tsx`): the list of a conversation's subagents (Main agent first) at the right of the conversation pane. Collapsed it is a 30 px vertical **strip** button labelled "Agents" (`aria-label="Show agents rail"`); open it is an `<aside aria-label="Conversation agents">`.
- **Narrow pane** — the rail's host row (its `parentElement`) measures below `NARROW_PANE_PX = 760` px with a `ResizeObserver` (PAN-5329). `narrow` is the component state for this.
- **Inline rail** — today's open rail: a `w-64 shrink-0` (256 px) flex sibling of the timeline that takes width away from it.
- **Overlay rail** — new in this issue: on a narrow pane the open rail is drawn `absolute` over the right side of the pane, above a **scrim** (a full-pane button that closes the rail), and takes no width from the timeline.
- **Top bar / app bar** — the 48 px row rendered by `src/dashboard/frontend/src/App/AppChrome.tsx` on every desktop-SPA route (including `/conv/<id>`). It is **not** rendered on `/m` (the web phone shell) or in the native phone app: `App.tsx` returns `<MobileApp />` for `/m` before the chrome (App.tsx line 146, `if (terminalPath === '/m' ...`).
- **`sm` breakpoint** — Tailwind's default `sm` = 640 px. `max-sm:` utilities apply below 640 px. The repo uses Tailwind `^3.4.19` with default screens (no `theme.screens` override in `src/dashboard/frontend/tailwind.config.*`), so `max-sm:`, `sm:` and arbitrary `h-[var(--x,100dvh)]` values all work.
- **Exception chips** — the four conditional top-bar chips: `DeaconFrozenChip`, `StoppedAgentsBanner variant="pill"`, `LowCostModePill`, `StaleBuildChip`.
- **Conversation header** — `components/chat/header/ConversationHeader.tsx`: row 1 (`.conversationHeaderPrimary`) is the title plus actions (`.conversationHeaderActions`, which holds the `Conversation | Terminal` `ViewToggle`, dock buttons and ⋯). Styles live in `components/CommandDeck/styles/command-deck.module.css`; the header shell is a CSS container (`.conversationHeaderContainer { container-type: inline-size }`).
- **Visual viewport** — `window.visualViewport`: the part of the page the user can actually see. On iOS the software keyboard shrinks the visual viewport but not the layout viewport, and `100vh`/`100dvh` do **not** track the keyboard. Only `visualViewport.height` / `offsetTop` do.
- **Phone shells** — the two `fixed inset-0` roots used on a phone: `MobileApp` (`components/mobile/MobileApp.tsx` line 153, `data-component="mobile-app"`, used by web `/m` and by the native app) and the native app's outer `ShellApp` (`apps/mobile/src/shell/ShellApp.tsx` line 429, `data-component="mobile-shell"`). The native app renders `ShellApp → MachineView → MobileApp → MobileConversations → ConversationPanel`, so the Agents rail fix reaches the phone app, but the top-bar fix does not need to.

## Requirements

### Functional

- **FR-1** On a narrow pane (< 760 px), opening the Agents rail renders it as an overlay: `absolute` inside the conversation row, anchored to the right edge, width `min(100%, 320px)`, above a scrim. The timeline keeps its width (the 30 px strip stays in flow).
- **FR-2** On a narrow pane, tapping the scrim, the rail's X, the Main agent row, or any subagent row closes the overlay. Row taps still select (URL `?subagent=` set or cleared) before closing.
- **FR-3** On a pane ≥ 760 px the rail behaves exactly as before (inline, stored preference, `defaultCollapsed`, `toggleSignal`).
- **FR-4** Below 640 px the top bar hides the brand wordmark (keeps the mark), hides the crumb, shows the search button as an icon, shows the Agents menu and Needs-you triggers as a dot plus a number, and hides the exception chips. Nothing in the bar extends past the viewport's right edge at 360 px.
- **FR-5** Below 640 px the Agents menu, Needs-you menu and System-health popover open inside the viewport (left ≥ 0, right ≤ viewport width). Only the System-health popover needs a code change (D-7).
- **FR-6** When the conversation header is 520 px wide or less, the title takes its own line and the actions wrap below it, so the `Conversation | Terminal` switch never clips.
- **FR-7** The desktop root, `#root`, `body`, and both phone shells size to the visual viewport (`--app-height`, `--app-offset-top` CSS variables written from `window.visualViewport`), falling back to `100dvh` / `0px`. The desktop root pads `env(safe-area-inset-top)`.

## Decisions (made here; auto mode)

- **D-1 Overlay is `absolute`, not `fixed` or a portal.** Narrow panes also occur on desktop split layouts; `fixed` would cover the whole window. The row at `ConversationPanel.tsx` line 422 gains `relative`.
- **D-2 The 30 px strip stays in flow while the overlay is open.** Removing it would reflow the virtualized timeline on every open/close. The scrim covers it.
- **D-3 `hostRef` stays on in-flow elements.** The ResizeObserver measures `el.parentElement`. The strip carries `hostRef` in both narrow states; the inline aside carries it on wide panes (unchanged). The overlay aside and scrim are direct children of the same row, so even if they carried the ref, the parent is the row. They are never wrapped in an extra element.
- **D-4 Width `w-[min(100%,320px)]`**, from the issue's option list; on a 393 px pane it leaves a 73 px scrim strip on the left to tap.
- **D-5 No Escape-to-close and no focus trap** on the overlay. The X, scrim and row taps close it; adding a global Escape listener risks colliding with composer Escape handling.
- **D-6 Exception chips hide below 640 px** (`max-sm:hidden` wrapper). Deacon-frozen and stopped-agent state remain reachable in the System-health popover (Auto-resume and Stopped agents sections); low-cost mode and build-behind-main are not shown on a phone. Recorded as a NonGoal to surface them.
- **D-7 Only the System-health popover changes; it anchors to the top bar below 640 px.** Its wrapper becomes `max-sm:static`, so the `absolute` popover's containing block is the bar (`AppChrome.tsx` line 183 is already `relative`); the popover adds `max-sm:left-2 max-sm:right-2 max-sm:w-auto`. The Agents and Needs-you menus are left as they are because `MenuSurface` already keeps them in the viewport; the Playwright spec still checks all three.
- **D-8 Agents trigger gets `aria-label={agentsWorkingLabel(count)}`** so its accessible name stays "N agents working" when the visible text is the number.
- **D-9 Keyboard fix uses `visualViewport`, not `100dvh` alone.** `dvh` does not track the iOS keyboard. At pinch-zoom (`|scale − 1| > 0.01`) the hook removes the variables so the CSS falls back to `100dvh` / `0px` and a zoomed page does not drag the shell.
- **D-10 Composer footer (problem 3) is fixed by FR-1.** The picker chips already shrink with ellipsis (`.pickerContainer { min-width: 0; flex-shrink: 1 }`, `.pickerLabel { text-overflow: ellipsis }`, command-deck.module.css lines 4467–4515), so they truncate rather than overflow; at 137 px that produced `Clau…`, at full pane width they have room. The Playwright spec asserts the composer toolbar's right edge ≤ viewport width at 360 px; redesigning the toolbar is a NonGoal.
- **D-11 The Playwright spec runs WebKit via `test.use({ ...devices['iPhone 15 Pro'] })`** at file level and is not added to `test:playwright` (CI installs Chromium only, `.github/workflows/ci.yml` line 455, and the spec seeds git repositories like `pan-5295-conversation-turn.spec.ts`). Screenshots are committed to `docs/screenshots/pan-5585/` and linked from the PR body.
- **D-12 `MobileConversations.tsx` line 212's `[&_[class*=conversationHeaderPrimary]]:flex-wrap` arbitrary variants stay** (surgical change); FR-6 makes them redundant but harmless.
- **D-13 The hook is called in `App` (main body), `MobileApp`, and `ShellApp`** rather than in the two entry files, to keep the plan's file surface small. Multiple callers write identical values; cleanup removes only listeners.

### WI-6 Shells follow the visual viewport (FR-7)

Files: `src/dashboard/frontend/src/lib/visualViewport.ts` (new), `src/dashboard/frontend/src/lib/visualViewport.test.ts` (new), `src/dashboard/frontend/src/index.css`, `src/dashboard/frontend/src/App.tsx`.

1. New `lib/visualViewport.ts`:
   ```ts
   // PAN-5585: the iOS keyboard shrinks the visual viewport, not the layout
   // viewport, and 100vh/100dvh do not follow it. These variables do.
   import { useEffect } from 'react';

   export const APP_HEIGHT_VAR = '--app-height';
   export const APP_OFFSET_TOP_VAR = '--app-offset-top';

   type ViewportLike = Pick<VisualViewport, 'height' | 'offsetTop' | 'scale'>;

   export function applyVisualViewportVars(root: HTMLElement, vv: ViewportLike): void {
     if (Math.abs(vv.scale - 1) > 0.01) {
       root.style.removeProperty(APP_HEIGHT_VAR);
       root.style.removeProperty(APP_OFFSET_TOP_VAR);
       return;
     }
     // floor, never round up: a #root taller than a fractional viewport would scroll.
     root.style.setProperty(APP_HEIGHT_VAR, `${Math.floor(vv.height)}px`);
     root.style.setProperty(APP_OFFSET_TOP_VAR, `${Math.floor(vv.offsetTop)}px`);
   }

   export function useVisualViewportVars(): void {
     useEffect(() => {
       const vv = window.visualViewport;
       if (!vv) return;
       const root = document.documentElement;
       const update = () => applyVisualViewportVars(root, vv);
       update();
       vv.addEventListener('resize', update);
       vv.addEventListener('scroll', update);
       return () => {
         vv.removeEventListener('resize', update);
         vv.removeEventListener('scroll', update);
       };
     }, []);
   }
   ```

- Delay/retry tests use fake timers; none of these tests involve delays, so none are needed. Do not add real `setTimeout` waits in unit tests.
