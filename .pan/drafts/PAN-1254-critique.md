## blocks-the-design: a later Settings save reopens the Serve login hole

The proposed `saveRequireTokenMint()` serializes its own write ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/.pan/drafts/PAN-1254.md), lines 215–224), but `PUT /api/settings` passes a previously materialized whole settings object to `saveSettingsApi()` ([settings.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/src/dashboard/server/routes/settings.ts), lines 857–870). Its queued writer copies `settings.dashboard` into YAML ([settings-api.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/src/lib/settings-api.ts), lines 912–930 and 1050–1061), and the YAML writer merges that value into `dashboard` ([settings-api.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/src/lib/settings-api.ts), lines 864–869). Thus a Settings tab loaded before Serve was enabled can submit `require_token_mint: false` afterward; the queue preserves write order but does not preserve the new true value. Serve remains on, while the session mint again accepts loopback proxy traffic ([dashboard-auth.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/src/dashboard/server/routes/dashboard-auth.ts), lines 359–370). Smallest fix: make the settings write or session-mint path enforce token minting while this dashboard's Serve handler is active, and test a stale Settings PUT after enabling Serve.

## blocks-the-design: Protect the dashboard has no repair action

D-8 returns `ready` whenever Serve already proxies this dashboard, regardless of `require_token_mint` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/.pan/drafts/PAN-1254.md), lines 92–102). W-12 sends `tailscale-serve-unprotected` to the setup dialog as a **Protect the dashboard** action (lines 282–288), but W-14's `ready` panel only shows the URL and later content; `postServe()` is exposed only in the `serve` panel (lines 300–309). A manually enabled Serve with token minting off therefore leaves the security problem in place after the user clicks its fix button. The CLI likewise exits at `ready` without calling Serve (lines 272–279). Smallest fix: expose a protection action in the `ready` state when token minting is off, and make both UI and CLI invoke the idempotent Serve operation before claiming completion. Cover this starting state in acceptance tests.

## blocks-the-design: a failed self-check leaves the new origin stale

W-5 saves the Serve origin before executing Serve and then performs a fallible HTTPS self-check ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/.pan/drafts/PAN-1254.md), lines 226–233). W-9 invalidates the server's trusted-origin cache only when the overall result is `ok` (lines 253–260). If Serve starts but the self-check fails, its origin is on disk while the process keeps the old cached list; [origin-validation.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/src/dashboard/server/routes/origin-validation.ts), lines 49–51 and 85–96, shows that subsequent requests use that list until invalidation. A browser at the live Serve URL then fails the origin check on session creation ([dashboard-session.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/src/dashboard/server/routes/dashboard-session.ts), lines 76–83). Smallest fix: invalidate after the origin write even if a later Serve command or self-check fails, and test the `self-check-failed` path.

## blocks-the-design: the foreign-handler check omits TCP port 443

The planned `parseServeStatus()` recognizes the dashboard proxy and calls another `/` Web proxy foreign ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/.pan/drafts/PAN-1254.md), lines 169–190); W-5 relies on that result before running `tailscale serve --bg --https=443` (lines 226–233). Tailscale's Serve config also has a separate `TCP[443]` handler, and its `SetWebHandler` replaces that port entry ([Tailscale Serve source](https://github.com/tailscale/tailscale/blob/main/ipn/serve.go), `ServeConfig.TCP` and `SetWebHandler`). A pre-existing TCP forward on 443 can have no Web `/` proxy, so this parser would call the Serve command and replace another program's handler, violating NFR-5. Smallest fix: treat any occupied `TCP[443]` configuration other than this exact HTTPS dashboard handler as foreign, including TCP forwarding and other Web mounts; add fixtures for them.

## blocks-the-design: unreadable prefs can trap setup at operator

D-6 says a failed `tailscale debug prefs` should let login or Serve attempt the write and map access denial to `operator` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-1254/.pan/drafts/PAN-1254.md), line 90). D-8 instead checks `OperatorUser !== current user` before login (lines 92–100), while W-1 reads `debug prefs` only as one of the state inputs (lines 169–190). If that command fails, `OperatorUser` is unknown; treating it as unequal sends setup to `operator` repeatedly, including after a successful `set --operator`, and prevents the promised write-based fallback. Smallest fix: make operator knowledge three-state; when unknown, try login or Serve, then surface `operator` only on the mapped access-denied result. Test failed `debug prefs` with a usable operator and with access denied.
