# PAN-5615 — Role prompts escalate to a dead session name; the Flywheel is `conv-flywheel`

**Issue:** [PAN-5615](https://github.com/eltmon/overdeck/issues/5615)
**Planning mode:** `pan plan --auto` (no operator questions; defaults recorded under "Decisions").

## Glossary

- **Flywheel** — the `/pan-flywheel` loop skill running in one operator conversation. Its conversation name and its terminal session name are both `conv-flywheel`, the constant `FLYWHEEL_CONVERSATION_SESSION` in `src/lib/flywheel/constants.ts` (line 7: `export const FLYWHEEL_CONVERSATION_SESSION = 'conv-flywheel';`).
- **`flywheel-orchestrator`** — the retired session name of the pre-PAN-3964 Flywheel. No live session has it. The live database still holds one ended row named `flywheel-orchestrator` (verified read-only on 2026-11-23), so historical cost rows can still resolve to it.
- **Retired Flywheel name** — when `pan flywheel start --fresh` replaces a Flywheel conversation that other conversations link to, `vacateConversationName()` in `src/lib/overdeck/conversation-replace.ts` renames the old row to `` `${name}~${linked.id.slice(0, 8)}` ``, so old Flywheel runs are named `conv-flywheel~<8 hex chars>` (two such ended rows exist in the live database).
- **Role prompt** — a file `roles/<role>.md`. At launch, `roleSystemPromptInjection(definitionPath)` in `src/lib/agents/runtime-command.ts` strips the frontmatter and writes the **rendered role prompt** to `<OVERDECK_HOME>/role-prompts/<stem>.md` as `Source: <abs path>\n\n<body>`; Claude Code loads that file with `--append-system-prompt-file`.
- **Escalation tell** — the `pan tell <target> "<role> <issue>: …"` command every pipeline role prompt tells the agent to run before it parks ("Signal the flywheel before you stall").
- **Dead tell target** — a `pan tell` whose target is `flywheel-orchestrator` or `conv-flywheel-orchestrator`.
- **Cost bucket** — `classifySessionBucket()` in `src/lib/costs/attribution.ts` puts cost events with no issue into `FLYWHEEL`, `CONVERSATIONS`, or `UNATTRIBUTED`.
- **`Prompt-Change:` trailer** — a commit trailer that `scripts/check-prompt-change-trailer.sh` (`npm run lint:prompt-trailer`) requires on at least one branch commit whenever `roles/*.md` changes.

## Problem

Every pipeline role prompt tells the agent to escalate a stall with `pan tell flywheel-orchestrator "..."`. No session has that name. `pan tell` therefore fails with `Error: Agent flywheel-orchestrator not running` (thrown in `src/lib/agents/messaging.ts`, `throw new Error(\`Agent ${normalizedId} not running\`)`), and the escalation is lost. On 2026-11-23 the MIN-1144 review agent hit this and its blocker went unreported for about two hours.

The same paragraph in four role prompts also claims the tell "no-ops gracefully when no Flywheel run is active — the message just lands in an idle or absent session". That is false: a tell to an absent conversation throws. The false sentence makes the agent believe the signal landed.

Cost attribution has the same stale name: `classifySessionBucket()` only treats a conversation named `flywheel-orchestrator` as the Flywheel, so the live Flywheel's no-issue cost lands in `CONVERSATIONS`.

## Decisions

1. **Target literal, not a template.** Role prompts are plain Markdown with no template engine on the `--append-system-prompt-file` path, so they name `conv-flywheel` literally. FR-3's positive assertion compares against `FLYWHEEL_CONVERSATION_SESSION`, so a future rename of the constant fails the test instead of silently re-breaking escalation.
2. **Fix the false "no-ops gracefully" sentence (FR-5).** It sits in the same paragraph as the target and tells the agent a failed tell is harmless, which is how a blocker goes unreported. Replace only that sentence pair; leave the rest of each section as is.
3. **Attribution uses the constant plus two legacy forms.** Match `FLYWHEEL_CONVERSATION_SESSION` exactly, names starting with `` `${FLYWHEEL_CONVERSATION_SESSION}~` `` (retired runs), and the literal `'flywheel-orchestrator'` (historical rows). `src/lib/flywheel/constants.ts` has no imports, so importing it from `src/lib/costs/attribution.ts` cannot create a cycle.
4. **No backfill.** `reclassifyUnknownCostEvents()` only re-buckets `issue_id = 'UNKNOWN'` rows; rows already bucketed `CONVERSATIONS` stay as they are.
5. **FR-3 test home and shape.** New file `src/lib/agents/__tests__/role-escalation-target.test.ts`, next to the existing `role-mcp-parser.test.ts`, which already renders roles under a temporary `OVERDECK_HOME`. The temporary home is mandatory: `roleSystemPromptInjection` writes into `<OVERDECK_HOME>/role-prompts/`, and without it the test would overwrite the running machine's rendered prompts.
6. **sync-sources has no single renderer** (skills are copied as files, rules render through the context layers). The test walks `sync-sources/` and scans every text file directly, as `src/lib/__tests__/agent-text-cli-verbs.test.ts` already does. `scripts/lint-source-introspection.sh` only counts `readFile(...)` calls whose arguments contain a `.ts`/`.tsx` string literal; the new test passes a path variable and never reads `.ts` source, so NFR-1 holds.
7. **The detector is a pure exported-in-file function** with its own fixture test (positive and negative), so the guard cannot pass vacuously.
