## 1. Glossary

The parent's terms (explorer root, root id, code pane, port record) and D1's terms (viewer, viewer host, viewer router, viewer kind, Fake Worker; `.pan/drafts/pan-5188.md` §1) apply. Added here:

- **OOXML** — the Office Open XML formats: `.docx` (Word), `.xlsx` (Excel), `.pptx` (PowerPoint). They are zip archives of XML parts.
- **ODF** — the OpenDocument formats: `.odt` (text), `.ods` (spreadsheet), `.odp` (presentation). Also zip archives of XML.
- **betteroffice engines** — the npm packages `@betteroffice/docx`, `@betteroffice/xlsx` and `@betteroffice/pptx` (0.5.1, Apache-2.0). Each lays out and paints one OOXML format with WebAssembly in a Web Worker, onto canvases. They draw text only with the font faces they are handed, never system fonts.
- **betteroffice fonts** — `@betteroffice/fonts` and `@betteroffice/fonts-cjk` (0.4.0, `Apache-2.0 AND OFL-1.1`). Open font files (`.ttf`, `.otf`) that the engines load by URL when a document names a family. The CJK package holds the Chinese, Japanese and Korean faces.
- **OFL-1.1** — the SIL Open Font License 1.1. It lets software bundle and ship the fonts. It requires the license text to travel with the fonts and forbids selling the fonts on their own.
- **Office preview worker** — `viewers/office/officePreview.worker.ts`. A Web Worker that bounds and prepares an OOXML archive for its engine (`prepareOffice`) or parses an ODF archive into HTML pages or sheet rows (`openDocument`).
- **Archive bounding** — t3code's checks that refuse a zip before an engine sees it: at most 50 MB, at most 2,048 entries, and per-part size, tag and style budgets (`WORD_LIMITS` and friends). It defends the tab against zip bombs and pathological layouts.
- **Document pages** — `viewers/office/DocumentPages.tsx`. Renders sanitized HTML (an ODF page or a notebook HTML output) inside a sandboxed `srcDoc` iframe with its own Content-Security-Policy.
- **Inert notebook markdown** — notebook markdown rendered with no raw HTML, no images, no links and no file chips. Saved notebooks are untrusted: an image would make the dashboard fetch a URL, and a link or file chip would turn authored text into an app action.
- **Mermaid** — the diagram language of `.mmd` / `.mermaid` files, rendered by the `mermaid` npm package (MIT).
- **Lexical guard** — t3code's regular expression in `MermaidViewer.tsx` that refuses Mermaid source containing config blocks (`%%{`), front matter (`---`), markup, node metadata or URLs before Mermaid ever lays it out.

## 2. Summary

Tier 2 adds three viewers under `viewers/`, each lazily loaded by D1's viewer host (`FileViewer.tsx`):

1. **Office** — docx, xlsx and pptx render with the betteroffice engines (ported from t3code `apps/web/src/components/files/OpenXmlOfficeViewer.tsx` and `office/`). odt, ods and odp render through the office preview worker as HTML pages or sheet tables (ported from t3code `OfficeViewer.tsx` and `extendedDocumentPreview.ts`).
2. **Notebook** — `.ipynb` renders as read-only cells: inert markdown, code as plain text, and saved outputs (text, base64 images, sanitized HTML in a sandboxed iframe). Code never runs.
3. **Mermaid** — `.mmd` / `.mermaid` render as an SVG image, after the lexical guard and with Mermaid's `strict` security level.

The viewer router (`viewer-router.ts`) gains the `office`, `notebook` and `mermaid` rows before its `text` row. No server code changes: viewers read bytes through D1's download route, and Mermaid reads `read.text`.

## 3. Decisions (made in this document)

- **D-1 License checkpoint: all five betteroffice packages pass.** The parent rule (WI-10 step 3) drops a format whose package is not MIT, Apache-2.0, BSD or ISC. Measured on 2026-11-13 with `npm view <pkg>@<version> license`:
  - `@betteroffice/docx@0.5.1`, `@betteroffice/xlsx@0.5.1` and `@betteroffice/pptx@0.5.1`: `Apache-2.0`.
  - `@betteroffice/fonts@0.4.0` and `@betteroffice/fonts-cjk@0.4.0`: `(Apache-2.0 AND OFL-1.1)`. The loader code is Apache-2.0, and the `.ttf`/`.otf` font files are OFL-1.1.

  OFL-1.1 is outside the literal list, but it is a font license, not a code license. The rule exists to keep copyleft *code* out of the bundle (D1 D-2 applied it to `heic-to`, LGPL-3.0). The dashboard already ships OFL fonts: `src/dashboard/frontend/public/fonts/` holds Space Grotesk, Geist and DM Sans, and `package.json` depends on `@fontsource/jetbrains-mono` and `@fontsource/space-grotesk`, all OFL-1.1. So OFL font files are accepted, and their license texts ship in `licenses/` (WI-15). No format is dropped. The PR description records this outcome (parent AC-10).
- **D-2 Effect checkpoint: the office schemas compile on `effect 4.0.0-beta.73` after one rename.** t3code uses `effect 4.1.3` (`pnpm-workspace.yaml` catalog). A runtime probe confirmed every call the office code makes exists in beta.73 (`Schema.Struct/Array/NullOr/optional/Literals/Record/fromJsonString/decodeUnknownSync/decodeUnknownOption/encodeKeys/suspend`, `Option.match`, `pipe`), except `Schema.TaggedError`. A `tsc --strict` probe of `Schema.Codec<T>` with `Schema.suspend`, `encodeKeys` and `Schema.TaggedErrorClass` passed. So the schemas stay, and `Schema.TaggedError` becomes `Schema.TaggedErrorClass` (two classes in `engine/worker-rpc.ts`, search `extends Schema.TaggedError<`). Overdeck already uses that name (`src/lib/overdeck/merge.ts`, search `Schema.TaggedErrorClass<MergeSetNotFound>`). **Implementation checkpoint:** if `npm run typecheck:frontend` reports a new error inside a ported `Schema` block, rewrite that block as a plain TypeScript type guard (parent fallback) and say so in the PR description.
- **D-3 Ship every asset, including the CJK fonts.** The parent names all five packages. Their emitted assets are large: WASM about 49 MB (`docx_edit_bg.wasm` 24.4 MB, `docx_parse_bg.wasm` 6.4 MB, `xlsx_wasm_bg.wasm` 7.6 MB, `pptx_wasm_bg.wasm` 6.3 MB, `docx_layout_bg.wasm` 4.4 MB, `ooxml_opc_bg.wasm` 0.4 MB) and fonts about 49 MB (Latin 15 MB, CJK 34 MB). `dist/dashboard/public` is 99 MB today, and `@overdeck/core@0.82.2` unpacks to 121 MB. Every asset is fetched only when an Office file opens, so dashboard load time is unchanged. Only the install grows. No pack-size gate exists (no `scripts/` or `.github/workflows/` check reads a pack size). CJK documents need the CJK faces to show any CJK text, because the engines never use system fonts. So the CJK package ships. WI-1 and WI-13 measure the before and after sizes and puts them in the PR description. **Implementation checkpoint and fallback:** if CI's `npm pack` job (`.github/workflows/ci.yml`, search `npm pack --ignore-scripts`) or the release workflow fails on size, remove `@betteroffice/fonts-cjk` from `package.json`. `@betteroffice/fonts` imports it as an optional peer (`import("@betteroffice/fonts-cjk")` inside a `try`), so confirm `npx vite build` still passes; if it does not, add `'@betteroffice/fonts-cjk'` to `build.rolldownOptions.external`. CJK text then renders blank. Record the fallback in the PR description.
- **D-4 Notebooks do not ride the office worker.** t3code parses notebooks in the office preview worker. Here, `openNotebook` and its helpers move to `viewers/notebook/notebookParse.ts`, and `NotebookViewer` parses on the main thread. So the notebook and Mermaid viewers have no dependency on any Office item, and dropping Office later would leave them shippable. The viewer fetches the file from `src` with D1's `readBounded` (limit 8 MiB, t3code's notebook limit), so a notebook over the 5 MiB Monaco threshold (a `large-text` read with no `text`) still opens. Parsing 8 MiB of JSON on the main thread takes tens of milliseconds, which is acceptable.
- **D-5 Notebook markdown uses `react-markdown` plus the inert plugin, not `MarkdownTab`.** The parent asks for `MarkdownTab` (`src/dashboard/frontend/src/components/CommandDeck/ZoneCOverviewTabs/MarkdownTab.tsx`). `MarkdownTab` renders `ChatMarkdown` (`components/chat/ChatMarkdown.tsx`), which takes no plugin prop (props: `text, isStreaming, cwd, issueId, useStreamdown`). It renders markdown images, which would fetch remote URLs. It also turns bare file paths into clickable file chips (`remarkBareFileTextLinks`, search `[remarkBareFileTextLinks, { cwd }]`). Both break the inert rule for untrusted notebooks. So `viewers/notebook/NotebookMarkdown.tsx` renders `react-markdown` (`^10.1.0`, already a dependency) with `remark-gfm` and the ported `inertNotebookMarkdown` plugin, plus `skipHtml`. It uses `ChatMarkdown`'s typography class (`styles.chatMarkdown` from `components/CommandDeck/styles/command-deck.module.css`), so cells read like `MarkdownTab`. This is a recorded deviation from the parent.
- **D-6 Notebook code cells are plain `<pre>`.** t3code renders code cells with `ReadOnlySourcePreview` (`@pierre/diffs/react` `File`, a virtualized highlighter at a version Overdeck does not pin). Here a code cell is `<pre>` in the mono font, `max-h-[360px] overflow-auto`, matching t3code's 360 px cap. Syntax highlighting is a NonGoal.
- **D-7 Mermaid renders to an SVG image, never into the page DOM.** `mermaid@11.17.2` (MIT) is already in `bun.lock` as a transitive dependency of `streamdown@2.5.0` and `@excalidraw/mermaid-to-excalidraw`. Pinning that exact version adds no new package tree. The viewer:
  1. Refuses the source with t3code's lexical guard (D-8).
  2. Calls `mermaid.initialize({ startOnLoad: false, securityLevel: 'strict', theme: resolvedTheme === 'dark' ? 'dark' : 'default', htmlLabels: false, flowchart: { htmlLabels: false }, maxTextSize: 50_000 })`.
  3. Calls `await mermaid.render(id, text)`, where `id` is `mermaid-` plus `useId()` with every `:` removed (colons break Mermaid's CSS selectors).
  4. Shows the returned SVG as `<img src={"data:image/svg+xml;charset=utf-8," + encodeURIComponent(svg)}>`.

  An SVG inside `<img>` cannot run script or fetch anything, so even a Mermaid sanitizer bug cannot reach the page. `mermaid` loads with `await import('mermaid')` inside the effect, so it is a separate chunk. t3code's `pele`-based `MermaidDiagram` is not ported (parent: React 19 `use()`).
- **D-8 The lexical guard is ported verbatim.** From t3code `MermaidViewer.tsx`, search `/%%\s*\{|^\s*---|<\/?[A-Za-z]|`. Matching source shows the notice "This diagram contains resource URLs, markup, node metadata, or custom configuration, so it is not rendered." and nothing is passed to Mermaid. When the code pane offers Preview / Edit (`textEditable: true`), Edit shows the source in Monaco.
- **D-9 Scope is the parent's FR-9 list.** docx, xlsx, pptx, odt, ods, odp, ipynb, mmd, mermaid. t3code also previews `.rtf` and `.epub`; those are NonGoals. `openEpub`, `epubHtml` and `openRtf` are not ported, nor are any helpers only they use. `.rtf` reads as text and opens in Monaco. `.epub` shows the binary card.
- **D-10 Router rows.** The three rows go after D1's archive row and before its csv/tsv row (both extension rows, before the `read.kind === 'text'` row, per the correction comment on this issue):

  | # | Condition | Result |
  |---|---|---|
  | 7a | ext docx, xlsx, pptx, odt, ods, odp (any read kind) | `office` |
  | 7b | ext ipynb and read kind `text` or `large-text` | `notebook`, `textEditable: read.kind === 'text'` |
  | 7c | ext mmd, mermaid and read kind `text` | `mermaid`, `textEditable: true` |

  `ViewerChoice` keeps its shape `{ kind, delimiter, textEditable }`, because D1's router test compares whole objects with `toEqual`. The office format comes from a new export, `officeKindOf(path): OfficeDocumentKind | null`, which returns the lower-cased extension when it is one of the six. A binary read of `.ipynb` falls through to `binary`. A `large-text` `.mmd` falls through to `large-text`.
- **D-11 A viewer that cannot render shows the binary card with the reason.** t3code shows "No preview for this file". Here every tier-2 failure (bounds, damaged file, timeout, engine error, Mermaid parse error) renders D1's `BinaryCard` (`viewers/shared/BinaryCard.tsx`, props `{ name, size, downloadUrl, notice? }`) with `notice` set to the message. The operator can always download the file. So `OpenXmlOfficeViewer`, `OdfViewer`, `NotebookViewer` and `MermaidViewer` each take `name`, `size` and `downloadUrl` props.
- **D-12 Folder layout mirrors t3code, so relative imports survive.** t3code's `files/` level becomes `viewers/office/`, and `files/office/` becomes `viewers/office/engine/`. An engine file's `../officePreviewProtocol` import is unchanged. `../fileSurfaceChrome` becomes `../../shared/ViewerChrome`.
- **D-13 `officeArchive.ts` is split to stay under the 1,000-line ceiling.** Upstream it is 1,434 lines. It becomes four files along its own seams (WI-3). The `officeArchive.ts` export names (`boundedArchive`, `prepareOffice`, `WORD_LIMITS`) stay the same.
- **D-14 ES2023 array methods are rewritten.** `main`'s frontend compiles ES2021–ES2022 methods (`replaceAll`, `.at()`, `Object.hasOwn`; for example `components/HealthDashboard.tsx` uses `Object.hasOwn`). Nothing on `main` uses `toSorted` or `toReversed`, and the frontend `tsconfig.json` sets `"lib": ["ES2020", "DOM", "DOM.Iterable"]`. In ported files, `a.toSorted(f)` becomes `[...a].sort(f)` and `a.toReversed()` becomes `[...a].reverse()`. The upstream has 6 `toSorted` and 4 `toReversed` calls. `tsconfig.json` does not change.
- **D-15 — retired.** An earlier draft excluded the betteroffice packages from Vite's dev pre-bundling. t3code's own `apps/web/vite.config.ts` (lines 109–121) lists them in `optimizeDeps.include` instead, on the same Vite 8, so pre-bundling works. `vite.config.ts` does not change in this issue.

## 5. Repo rules that apply (restated)

- **No source-reading tests, no `skipIf`, no `.only`** (lint and test-skip gates).

- **Never `git stash`. Never `git checkout`** inside the workspace.

## 10. Out of scope (NonGoals)

- `.rtf` and `.epub` previews (D-9), `.doc`, `.xls`, `.ppt` (legacy binary Office), Apple iWork files and video.
- Editing any Office, notebook or Mermaid file inside its viewer. The viewers are read-only. The code pane's Preview / Edit toggle for `textEditable` kinds is PAN-5187's.
- Running notebook code, or rendering notebook widget, JavaScript or LaTeX outputs.
- Syntax highlighting in notebook code cells (D-6).
- Mermaid in notebook markdown (the inert plugin turns `mermaid` code fences into plain text, as upstream).
- Loading fonts or engines from a CDN.
- Mounting viewers in a pane or creating `CodePane.tsx` (PAN-5186, PAN-5187).
- Server changes, new routes or new RPC methods.
- Changing the frontend `tsconfig.json` `lib`, or raising any lint ratchet or file-size cap.
- The phone app (`apps/mobile`).
