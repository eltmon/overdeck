## Glossary

| Term | Definition |
| --- | --- |
| **Agent selector** | The list Claude Code draws at the very bottom of its pane, below the status lines, whenever the session has listed subagents. One row per agent. The first row is always `main`. |
| **Filled dot (`●`)** | Marks the agent whose transcript is shown and which **receives typed input**. Exactly one row has it. Every other row has `◯`. On macOS Claude Code may draw `⏺` instead of `●` (the bundle picks `"⏺"` on macOS and `"●"` elsewhere for its generic bullet); treat `⏺` as filled too. |
| **Footer focus** | The keyboard focus is on the selector instead of the prompt. Shown by a `❯ ` cursor prefix on one selector row and a hint line (`↑/↓ to select · Enter to view` or `Enter to view · x to stop`). While the footer has focus, **typed text is swallowed** and **`x` stops the highlighted subagent** (verified in the probe below). |
| **Prompt box** | The input area: a top rule (`────…`, optionally ending with a title such as `── Counter run ─`), one or more prompt lines (first starts with `❯ `), and a bottom rule made only of `─`. The selector and the status lines sit **below the bottom rule**. |
| **Subagent placeholder** | While a subagent receives input, the empty prompt shows the dim placeholder `Message @<agent-type>…`. A plain-text pane read cannot tell dim text from typed text, so the parser treats exactly this pattern as an empty prompt. |
| **Input target** | Where typed input currently goes: `'main'`, `{ subagent: '<description>' }`, or `'unknown'`. The wire shape the issue asks for. |
| **Selector state** | The parser's full reading of the screen (rows, filled index, cursor index, main index, prompt text, footer hint). `inputTarget` is derived from it. |
| **Ensure-main** | The closed-loop procedure that reads the pane, moves the selector back to `main` with arrow keys when needed, and verifies the result by re-reading before any message is pasted. |
| **Composer route** | `handleConversationMessage` in `src/lib/overdeck/conversation-message.ts` — the server side of the dashboard composer for conversations (`POST /api/conversations/:name/message`). |
| **`messageAgent`** | `src/lib/agents/messaging.ts:229` — the operator/orchestrator → agent message door. `pan tell`, the agent-panel composer (`routes/agents/messaging.ts:38`), and pipeline wakes all go through it. |
| **Pane read** | `readAgentPaneText(agentId, lines, backend?, source)` in `src/lib/terminal-backends/agent-pane-io.ts:26`. tmux: `capture-pane` (answers `''` for a missing session). Herdr: `pane.read`; it **throws** when Herdr holds no pane for the id. Use `source: 'visible'`. |

## Problem

PAN-4247 shipped a composer notice whenever a background subagent is running: `Background subagent "<description>" is running. Claude Code may route typed messages to it.` (`src/dashboard/frontend/src/components/chat/ComposerFooter.tsx:720`, computed by `subagentRoutingNotice` in `src/dashboard/frontend/src/lib/subagentRouting.ts`). It is a guess. The operator saw it while messages were in fact reaching the main agent, and found it confusing. Earlier the same day four messages landed in a subagent whose task had **already completed**, so "a subagent is running" is neither necessary nor sufficient. What decides routing is the agent selector's filled dot.

PAN-4247 also added after-the-fact detection (sidechain landing probe, "Delivered to subagent" bubble relabel, `pan tell` exit 1 on `landedInSubagent`). Those stay as backstops. This issue adds the **before-the-fact** check and the switch.

## Empirical findings (probe, 2026-09-27, Claude Code 2.1.280)

A throwaway session (`tmux -L pan4268probe`, `claude --model haiku`, own scratch cwd) started a background `general-purpose` subagent. Findings, each of which the design depends on:

1. **Selector appears only when agents are listed.** With subagents listed, the bottom of the pane shows `  ● main` / `  ◯ general-purpose  <description>  <elapsed> · ↓ <tokens>`. A completed subagent can stay listed. When none are listed the selector is absent (one state showed `/tasks to see subagents` in the status line instead) and input goes to main.
2. **Entering the footer:** `Down` on an **empty** prompt moves focus into the footer. The first `Down` is **not deterministic**: once it only dismissed the `· 1 shell` pill and a second `Down` reached the selector; another time the first `Down` put the cursor on `main` directly.
3. **In the footer:** `Up`/`Down` move the `❯` cursor between rows; `Enter` makes the cursor row the filled one ("view"). After `Enter` the footer **keeps focus**. `Escape` returns focus to the prompt and leaves the filled dot where it is.
4. **Escape alone never returns to main.** From the prompt while a subagent is filled, `Escape` does nothing to the selector.
5. **`Left` opens the fleet ("agents") view** (`← 1 agent` in the status line) — never send it.
6. **Typed characters with footer focus are swallowed** (`hi` vanished). The footer binds `x` to "stop" on a subagent row, so pasting text while the footer has focus can stop a subagent.
7. **The prompt-box title is not a routing signal.** It read `Sleep probe` while input went to main and `Counter run` while input went to that subagent.
8. **Transcript lines also start with `● `** at column 0 (`● OK.`, `● Agent(Sleep probe)`). Selector rows are indented two spaces or prefixed `❯ ` and sit below the prompt box's bottom rule.

Key names in the bundle confirm this: `Footer` context binds `up/down/ctrl+p/ctrl+n` → `footer:up/down`, `enter` → `footer:openSelected`, `escape` → `footer:clearSelection`, `x` → `footer:close`.

## Requirements

### Functional

- **FR-1** A pure parser reads a plain-text pane screen and returns the selector state: rows (each with cursor flag, filled flag, label, agent type, group count, description), the filled row, the cursor row, the `main` row, the prompt text, and the footer hint.
- **FR-2** `inputTarget` derives from the selector state: no selector rows → `'main'`; exactly one filled row and it is `main` → `'main'`; exactly one filled row and it is a subagent → `{ subagent: <description> }`; rows present but no `main` row, or zero or several filled rows → `'unknown'`.
- **FR-3** The parser only scans lines below the prompt box's bottom rule. Transcript bullets above the prompt box never count as selector rows.
- **FR-4** `ensureMainInputTarget(agentId, deps)` makes input go to main before a message is pasted, using only the keys `Down`, `Up`, `Enter`, `Escape`, re-reading the pane after every key, and succeeds only when a final read shows `●` on `main` and no footer cursor.
- **FR-5** Ensure-main refuses (returns `ok: false` with a human-readable reason, sends no message) when: a resolved pane cannot be read; Claude Code's agents overview (fleet view) stays on screen after one `Escape`; the selector state is `'unknown'`; the prompt holds unsent text while a subagent is filled; the footer cannot be entered within 4 `Down` presses; the cursor cannot be placed on `main` within `rows.length + 1` moves; `Enter` does not move `●` to `main`; `Escape` does not release footer focus.
- **FR-6** The composer route runs ensure-main for every `claude-code` conversation send. A refusal returns HTTP **409** with `code: 'input-target-not-main'`, `deliveryUnknown: false`, `retryable: true`, and the reason; no text is pasted. Success responses carry `inputTarget: 'main'` and, when a switch happened, `switchedFromSubagent: '<description>'`.
- **FR-7** `messageAgent` runs ensure-main for every `claude-code` target (agents and `conv-*` conversations) just before delivery. A refusal returns `delivered: false`, queues the message to mail as `queued`, and sets `inputTargetRefusal: { reason, inputTarget }`. A success sets `inputTarget: 'main'` and `switchedFromSubagent` when a switch happened.
- **FR-8** `pan tell` prints "Message delivered to `<id>`'s main agent" (plus "(turn confirmed)" when confirmed, and a dim line naming the subagent it switched away from), or, on refusal, a red "Message NOT delivered" line with the reason and exits 1. It never prints "turn confirmed" for input that reached a subagent (PAN-4247 behavior kept).
- **FR-9** The dashboard agent-message route (`routes/agents/messaging.ts`) returns HTTP 409 with the same body shape as FR-6 when `messageAgent` reports `inputTargetRefusal`.
- **FR-10** The conversation read model (`getEnrichedConversationList` rows and `getConversationRead`) carries `inputTarget` for live `claude-code` conversations whose session directory has a `subagents/` directory; it is omitted otherwise. It refreshes with the list's existing 2 s enrichment TTL / 10 s client poll, and the composer invalidates the `['conversations']` query after every acknowledged send.
- **FR-11** The composer shows a warning notice **only** when `conversation.inputTarget` is `{ subagent }`: `Typed messages are going to subagent "<description>", not the main agent.` with a **Send to main** button that submits the current draft through the normal send path (which switches, confirms, and sends). The button is disabled when there is nothing to send. The hedged "may route" notice, the evidence-based "routed" notice, and the "Send anyway" / "Wait" confirm gate are removed.

### Non-functional

- **NFR-1** Parser tests run against fixture files captured from Claude Code 2.1.280, stored under a version-named directory, so a Claude Code UI change breaks a test instead of misrouting silently.
- **NFR-2** Ensure-main never sends `x`, `Left`, printable characters, or `C-c` to the pane.
- **NFR-3** Tests never wait on real timers: ensure-main takes an injectable `sleep`, and tests pass a no-op or use `vi.useFakeTimers()` (repo rule `fake-timers-for-retry-tests`).
- **NFR-4** No `execSync`, no new `*Sync` tmux calls (repo rules `no-execsync-server`, `prefer-async`). Use `sendKeysAsync` / `sendHerdrPaneKeys` / `readAgentPaneText`.
- **NFR-5** `src/lib/agents/delivery.ts` is not modified (it is already at its allowlisted 1119 lines). No touched file crosses 1000 lines without an allowlist row (`scripts/lint-file-size.sh`, `CEILING=1000`); `ComposerFooter.tsx` (869) and `conversation-reads.ts` (872) must stay under it.
- **NFR-6** List enrichment does not read the pane for conversations without a `subagents/` directory, ended/dead sessions, or non-`claude-code` harnesses.

## Decisions (made here; recorded as `autoDecisions` in the xBRIEF)

1. **Two call sites, one helper.** Ensure-main lives in a new `src/lib/agents/input-target.ts` and is called from the composer route and `messageAgent` only. Not from `deliverAgentMessage`: kickoff, resume, and fork callers never have subagents, and `delivery.ts` is at its size ceiling.
2. **`'unknown'` refuses.** The issue's rule is "never silently misroute"; a selector we cannot read is exactly the case the fixture tests guard.
3. **Pane I/O follows the pane, and only a failed read of a resolved pane refuses.** On a Herdr host, `deliverAgentMessage` (`delivery.ts:417-437`) falls through to the supervisor/tmux cascade when Herdr holds no agent for the id (legacy tmux agents still live on `tmux -L overdeck`). Ensure-main must match: `resolveAgentPaneIo` (W2) picks Herdr only when `findHerdrAgentPane` finds the pane, and otherwise uses tmux `capturePane` + `sendKeysAsync` — so "Herdr holds no pane" is never a refusal. tmux `capturePane` answers `''` for a missing session → no rows → `'main'`, and the paste then fails on its own. A read that **throws** on a resolved pane refuses (fail closed); the operator retries.
4. **No selector rows → `'main'`, no keys sent.** The probe showed the selector hides when no agents are listed, and input then goes to main.
5. **PAN-4247's `routed` notice and its "Send anyway" / "Wait" gate are removed.** The gate protected against re-routing into the same subagent; the default switch now prevents that. The "Delivered to subagent" bubble relabel and `landedInSubagent` handling stay as backstops.
6. **"Send to main" submits the draft through the normal send path.** Every send already switches; the button names what will happen. It is disabled with an empty draft (no switch-only action).
7. **Agent-backed panels (`agentId` set) show no notice.** They are not in the conversation list, so they carry no `inputTarget`; their sends still switch via `messageAgent`.
8. **Refusal status 409.** `composerSend.ts` turns non-2xx into a `MessageSendError`; with `deliveryUnknown: false` the toast reads "Failed to send message (409): <reason>", the editor keeps the draft (it is cleared only on success, `ComposerFooter.tsx` ~565), and the failed-message outbox gets a Retry entry.
9. **Settle timing.** After each key, poll the pane every `SELECTOR_POLL_MS = 150` ms up to `SELECTOR_SETTLE_TIMEOUT_MS = 1500` ms for the expected change, then evaluate.
10. **Fixture versioning.** Fixtures live in `src/lib/agents/__fixtures__/claude-code-2.1.280/` — named by the captured version because the repo pins none.

```ts
export interface SelectorRow {
  readonly cursor: boolean;        // line starts with '❯ '
  readonly filled: boolean;        // glyph is ● or ⏺
  readonly label: string;          // text after the glyph, trimmed
  readonly agentType: string;      // 'main' | first ≥2-space segment without ' (+N)'
  readonly groupCount: number;     // N from ' (+N)', else 0
  readonly description: string;    // second ≥2-space segment, else agentType
}

export interface SelectorState {
  readonly rows: readonly SelectorRow[];
  readonly filledIndex: number | null;   // null when zero or several rows are filled
  readonly filledCount: number;
  readonly cursorIndex: number | null;
  readonly mainIndex: number | null;
  readonly promptText: string;           // '' when empty or the subagent placeholder
  readonly footerHint: boolean;          // '↑/↓ to select' or 'Enter to view' line present
  readonly fleetView: boolean;           // a line after the bottom rule contains 'enter to return'
}

export type InputTarget = 'main' | { readonly subagent: string } | 'unknown';

export function parseAgentSelector(screen: string): SelectorState;
export function inputTargetFromSelector(state: SelectorState): InputTarget;
```

3. Parsing rules:
   - Split on `\n`, strip ANSI (`/\x1b\[[0-9;?]*[ -/]*[@-~]/g`), `trimEnd()` each line.
   - Bottom rule = the **last** line matching `/^─+$/`. If none, return an empty state (no rows, `promptText: ''`) — `inputTarget` is then `'main'`.
   - Top rule = the nearest line above the bottom rule matching `/^─/`. Prompt text = the lines strictly between them, the first with its leading `❯` and an optional following space removed (captures trim the trailing space of an empty `❯ ` line), continuation lines trimmed, joined with `\n`, then `trim()`. If the result matches `/^Message @\S+…$/`, `promptText` is `''`.
   - Row regex, applied only to lines after the bottom rule: `/^(❯ | {2})([●◯⏺]) (.+)$/`. `↑ N more above` / `↓ N more below` lines are skipped (they do not match).
   - Label split: `label.split(/\s{2,}/)`. Segment 0 = `agentType` with `/ \(\+(\d+)\)$/` stripped into `groupCount`. Segment 1 (if present) = `description`, else `description = agentType`. A row is the main row when `agentType === 'main'`.
   - `footerHint` = any line after the bottom rule containing `to select · Enter to view` or starting with `Enter to view`.
   - `fleetView` = any line after the bottom rule containing `enter to return` (Claude Code's agents overview).
4. `inputTargetFromSelector`: `fleetView` → `'unknown'`; no rows → `'main'`; `mainIndex === null` or `filledCount !== 1` → `'unknown'`; `filledIndex === mainIndex` → `'main'`; else `{ subagent: rows[filledIndex].description }`.

### W2 — Backend-resolved pane I/O (`resolveAgentPaneIo`)

**Why:** FR-4, NFR-4, Decision 3. Ensure-main needs one read door and one key door that always address the **same** pane, on tmux and on Herdr, and that fall back to tmux exactly where delivery does.

**Files:** `src/lib/terminal-backends/agent-pane-io.ts`; new `src/lib/terminal-backends/__tests__/agent-pane-io-keys.test.ts`.

**Change** (after `sendHerdrPaneKeys`, `agent-pane-io.ts:91`):

```ts
/** The keys ensure-main may send (PAN-4268). Never printable text, `x`, or `Left`. */
export type SelectorKey = 'Up' | 'Down' | 'Enter' | 'Escape';

/** Read and key one agent's pane, bound to whichever backend holds it. */
export interface AgentPaneIo {
  readonly backend: 'herdr' | 'tmux';
  read(lines: number): Promise<string>;
  sendKey(key: SelectorKey): Promise<void>;
}

/**
 * Resolve the pane once (PAN-4268). On a Herdr host with a Herdr pane for the
 * agent: `pane.read` (source `visible`) and `pane.send_keys`. Otherwise — a tmux
 * host, or a Herdr host whose agent Herdr does not hold (legacy tmux agents on
 * `tmux -L overdeck`, the same fallback `deliverAgentMessage` takes) — tmux
 * `capturePane` and `sendKeysAsync`.
 */
export async function resolveAgentPaneIo(agentId: string, backend?: TerminalBackend): Promise<AgentPaneIo> {
  const { resolveLaunchBackend } = await import('./launch.js');
  const resolved = backend ?? (await resolveLaunchBackend());
  if (resolved.name === 'herdr') {
    const { findHerdrAgentPane, readHerdrPaneText } = await import('./herdr.js');
    const pane = await findHerdrAgentPane(agentId);
    if (pane) {
      return {
        backend: 'herdr',
        read: (lines) => readHerdrPaneText(pane.paneId, lines, 'visible'),
        sendKey: (key) => sendHerdrPaneKeys(pane.paneId, [key]),
      };
    }
  }
  const { capturePane, sendKeysAsync } = await import('../tmux.js');
  return {
    backend: 'tmux',
    read: (lines) => capturePane(agentId, lines),
    sendKey: (key) => sendKeysAsync(agentId, key, 'input-target'),
  };
}
```

**Tests:** mock `../tmux.js`, `./herdr.js`, `./launch.js` with `vi.mock` (or pass a fake `backend` object with `name`). Cases: tmux host → `backend: 'tmux'`, `sendKey('Down')` calls `sendKeysAsync('conv-x', 'Down', 'input-target')`; Herdr host with a pane → `backend: 'herdr'`, `read(60)` calls `readHerdrPaneText(paneId, 60, 'visible')`, `sendKey('Down')` sends `pane.send_keys` with `keys: ['down']`; Herdr host with **no** pane → `backend: 'tmux'` (falls back, does not throw).

### W3 — Ensure-main closed loop (`ensureMainInputTarget`)

**Why:** FR-4, FR-5, NFR-2, NFR-3. The switch the two doors call.

**Files:** `src/lib/agents/input-target.ts`; new `src/lib/agents/__tests__/input-target-ensure.test.ts`.

**API:**

```ts
export interface EnsureMainDeps {
  readonly io: (agentId: string) => Promise<Pick<AgentPaneIo, 'read' | 'sendKey'>>; // default: resolveAgentPaneIo (W2); resolved ONCE per call
  readonly sleep: (ms: number) => Promise<void>;                                     // default: setTimeout promise
}

export type EnsureMainResult =
  | { readonly ok: true; readonly check: 'no-selector' | 'already-main' | 'switched'; readonly switchedFromSubagent?: string }
  | { readonly ok: false; readonly reason: string; readonly inputTarget: InputTarget };

export async function ensureMainInputTarget(agentId: string, deps?: Partial<EnsureMainDeps>): Promise<EnsureMainResult>;
```

**Procedure** (resolve `const pane = await deps.io(agentId)` once — a throw here refuses like a read failure; each "read" = `parseAgentSelector(await pane.read(60))`, each key = `pane.sendKey(key)`; each "settle until P" = up to `SELECTOR_SETTLE_TIMEOUT_MS / SELECTOR_POLL_MS` iterations of `sleep(150)` + read, stopping when P holds):

1. Read. A throw → refuse `Could not read <agentId>'s pane to check which agent Claude Code sends typed input to: <error>`.
2. Fleet view (`fleetView: true`, see W1) → press `Escape` once and settle until `fleetView` is false; still true → refuse `Claude Code is showing its agents overview instead of this session, so the message was not sent.` Then continue with the new read.
2a. No rows → `{ ok: true, check: 'no-selector' }`.

- **Fake timers** for any delay-based test (`fake-timers-for-retry-tests`); here, inject a no-op `sleep`.
- **No `execSync`, no new `*Sync` tmux callers** (`no-execsync-server`, `prefer-async`); `sendKeysAsync` and `readAgentPaneText` are async.

## Hazards

- Keys sent through `sendKeysAsync` / `pane.send_keys` bypass the FR-17 prompt guard (`checkPrompt`, `herdrBackend.prompt`). The key set is restricted to `Up|Down|Enter|Escape` by type (`SelectorKey`).
- Two concurrent senders (dashboard and `pan tell`) can interleave arrow keys. No cross-process lock; every step re-reads and verifies before `Enter`, so the worst case is a refusal.
- The operator can type in the terminal between the final read and the paste. Accepted; documented.
- Switching while main is mid-turn is unverified — see the W3 checkpoint.
- Claude Code's agents overview (fleet view, opened by `Left`) has a prompt that starts a **new** session; the parser flags it (`fleetView`) and ensure-main leaves it with one `Escape` or refuses.
- Transcript bullets (`● …`) look like selector rows; the parser must only scan below the bottom rule (W1 fixture `transcript-bullets-only.txt`).
