# PAN-5617: One gate admission for the whole `npm run typecheck` chain

**Issue:** [PAN-5617](https://github.com/eltmon/overdeck/issues/5617)
**Status:** planned (auto mode, 2026-11-23)
**Depends on:** PAN-5248 (`scripts/tsc-admitted.mjs`, footprint memory rule), PAN-5285 (admitted-alone bound)

## Glossary

- **Admission / gate admission.** The machine-wide FIFO queue under
  `~/.overdeck/verification-workers/admission/`, implemented in
  `src/lib/cloister/quality-gate-admission.ts`. A caller calls
  `acquireQualityGateAdmission(request, deps)`, waits for CPU, memory and a free slot, and gets a
  `QualityGateAdmissionHandle` it must `release()`.
- **Slot.** One of `resources.quality_gate_slots` (default 2) concurrent admission leases.
- **Lane.** One `tsc` process run by one `typecheck:*` script step, for example
  `typecheck:acp` = `node scripts/tsc-admitted.mjs --noEmit -p packages/effect-acp/tsconfig.json`.
- **Chain.** An npm script that runs several lanes one after another with `&&`. Today there are
  two: `typecheck` (12 steps, 13 `tsc` processes because `typecheck:share` runs two) and
  `lint:effect-diagnostics` (4 `tsc` lanes in a bash loop).
- **`tsc-admitted.mjs`.** `scripts/tsc-admitted.mjs`, the per-lane wrapper. It takes its own admission
  unless `CI`, `OVERDECK_GATE_ADMISSION=0` or `OVERDECK_GATE_ADMITTED=1` is set.
- **Runner.** `runAdmittedCommand` in `src/lib/cloister/gate-admission-run.ts`: acquire, spawn the
  command with `OVERDECK_GATE_ADMITTED=1`, sample peak tree RSS, record the peak, release.
- **Footprint key.** The string under which a gate's peak RSS history is stored
  (`~/.overdeck/verification-workers/admission/footprints/`). Today: `tsc:<tsconfig>`, `vitest:…`,
  `gate:<name>:<command>`. This issue adds `chain:<npm script name>`.
- **Chain wrapper.** The new `scripts/gate-admitted.mjs` this issue adds.
- **Bypass.** Running a command without taking an admission because `CI`, `OVERDECK_GATE_ADMISSION=0`
  or `OVERDECK_GATE_ADMITTED=1` is set (`shouldBypassAdmission` in `gate-admission-run.ts`).

## Problem

Under memory pressure, one `npm run typecheck` takes close to an hour. `package.json` line 118
(`"typecheck": "node scripts/tsc-admitted.mjs --noEmit && npm run typecheck:hooks && …"`) chains 12
steps. Every step runs through `scripts/tsc-admitted.mjs`, which calls `runAdmittedCommand`, which
calls `acquireQualityGateAdmission`. When one lane finishes, it releases its slot, and the next lane
joins the queue at the back. With MemAvailable near the soft reserve, each head can wait up to
5 minutes before it may run alone (PAN-5285), and other agents' typechecks interleave between the
lanes of one chain.

Observed 2026-11-23 07:10Z (MemAvailable about 10.4 GB, soft reserve 10 GB): the PAN-5601 handoff's
typecheck had run 49 minutes and was on lane 6 of 12. Five other typechecks were interleaved with it.

`npm run lint` has the same shape in one step: `scripts/lint-effect-diagnostics.sh` lines 74-92 loop
over 4 lanes and call `node scripts/tsc-admitted.mjs` once per lane
(comment `# PAN-5248: one gate admission per lane (CPU and memory).`).

The verification gate is not affected. `src/lib/cloister/validation.ts` line 525
(`if (admission) env.OVERDECK_GATE_ADMITTED = '1';`) already admits `npm run typecheck` once as the
gate `typecheck` (footprint key `gate:typecheck:npm run typecheck`, recorded peak about 2.6 GiB), and
every lane inside it bypasses. The slow path is an agent running `npm run typecheck` in its own shell.

## Verified facts the design rests on

1. `runAdmittedCommand` is generic over the command. `src/lib/cloister/gate-admission-run.ts`
   line 150 takes `{ footprintKey, command, args, cwd }` (spawn at line 120) and spawns `command` with
   `{ cwd, env, stdio: 'inherit' }`. Nothing in it is `tsc`-specific.
2. The runner already marks children admitted: line 182,
   `const childEnv = handle ? { ...env, OVERDECK_GATE_ADMITTED: '1' } : env`.
3. `tsc-admitted.mjs` lines 33-35 and 52-53 run `tsc` directly, loading only Node built-ins, when
   `OVERDECK_GATE_ADMITTED === '1'`. npm passes the parent environment to nested `npm run` steps,
   so a chain started with that variable runs every lane unadmitted.
4. The peak sampler measures the whole process tree of the spawned child
   (`src/lib/system-health/process-tree-rss.ts` header: "the tree is every descendant of a root pid").
   Lanes in a chain run one after another, so the chain's recorded peak is the largest lane's peak
   plus the small npm/bash/node overhead. The host's footprint store confirms this:
   `gate:typecheck:npm run typecheck` peaks at 2.56-2.67 GiB, and the largest typecheck lane
   (`tsc:src/dashboard/server/tsconfig.json`) peaks at 2.39-2.45 GiB.
5. Stale-owner reclaim is age-based: `QUALITY_GATE_ADMISSION_STALE_MS = 25 * 60 * 1_000`
   (`quality-gate-admission.ts` line 66) and `ownerIsStale` (line 318) treats an owner as stale when
   `now - owner.acquiredAt > staleMs` or its pid is dead. Recent verification-gate typechecks, which
   already hold one slot for the whole chain, ran 110-270 s, with one outlier of 912 s
   (`~/.overdeck/verification-workers/pan-5*/worker-*.log`, `"typecheck" passed (…ms)`). A chain
   lease therefore stays far inside 25 minutes.
6. `scripts/run-lint-group.mjs` line 22-23 splits `scripts.lint` on `&&` and maps the exact step
   string `'npm run lint:effect-diagnostics'` (line 16) to a CI group. The `lint` string must not
   change; only the body of `lint:effect-diagnostics` changes.
7. `tests/unit/scripts/lint-effect-diagnostics.test.ts` copies only `lint-effect-diagnostics.sh` and
   `tsc-admitted.mjs` into a temp root and runs the `.sh` with `OVERDECK_GATE_ADMISSION: '0'`. So
   `tsc-admitted.mjs` must stay self-contained (no import of a new helper), and the `.sh` must not
   re-exec itself through the chain wrapper.
8. Vitest's `globalSetup` (`tests/vitest-cpu-admission.ts` line 102) sets
   `OVERDECK_GATE_ADMITTED=1` in `process.env`. Any subprocess a test spawns inherits it and bypasses.
9. `src/lib/flywheel/board.ts` line 116 `gateLabel` turns queue gate names into board labels
   (`tsc:tsconfig.json` → `typecheck`, `tsc:<path>` → `typecheck (<path>)`, `gate:<name>:…` → `<name>`).
   A new `chain:` key would otherwise show raw.

## Requirements

### Functional

FR-1 to FR-4 keep the meanings the issue gave them. FR-5 onward are added by this plan.

- **FR-1** `npm run typecheck` takes exactly one admission for the whole chain, under footprint key
  `chain:typecheck`, sized by the chain's recorded peak (its largest lane, see D4). Its lanes run
  inside that one slot with `OVERDECK_GATE_ADMITTED=1` and take no admission of their own. A lane run
  on its own (for example `npm run typecheck:frontend`) still admits itself through
  `tsc-admitted.mjs`, unchanged.
- **FR-2** `npm run lint:effect-diagnostics` (and therefore that step of `npm run lint`) takes exactly
  one admission for its 4 lanes, under footprint key `chain:lint:effect-diagnostics`.
- **FR-3** PAN-5248's protection holds: total concurrent admitted gates on the host never exceed
  `resources.quality_gate_slots`, because a chain holds one slot and runs its lanes in series inside it.
- **FR-4** Tests and docs: a chained run enters the queue once; a lone lane enters it once; children
  see `OVERDECK_GATE_ADMITTED=1`; queue waits in tests use fake timers or none at all.
  `docs/PIPELINE-GATES.md` describes one admission per chain, and `changelog.d/pan-5617.md` records
  the fix. (Also `CLAUDE.md`, `.overdeck/context/codebase/stack.md` and the wrapper header comments.)
- **FR-5** The chain wrapper honors the same bypass as the lanes: under `CI`,
  `OVERDECK_GATE_ADMISSION=0` or `OVERDECK_GATE_ADMITTED=1` it runs the command directly and takes no
  slot. So the verification gate (already admitted) keeps exactly one admission, CI keeps none, and a
  chain inside an admitted parent never takes a second slot (which would self-deadlock at
  `quality_gate_slots: 1`).
- **FR-6** Any admission timeout of a chain (last waiting on `memory`, `queue`, `slots` or `cpu`)
  makes the chain wrapper exit 75 without starting the chain, so a long queue never lets 13 `tsc`
  processes start unadmitted. A failure that is not a timeout (file-system error, tsx load failure)
  runs the chain unadmitted with `OVERDECK_GATE_ADMISSION=0` in the child environment, so its lanes
  do not each queue again. A lone lane keeps today's rule: only a memory timeout exits 75, and any
  other failure runs that one `tsc` unadmitted.
- **FR-7** The chain's exit code, stdout and stderr pass through unchanged. Wrapper messages go to
  stderr prefixed `[gate-admission]`.
- **FR-8** The Flywheel board labels a queued `chain:<script>` gate as `<script>`
  (`chain:typecheck` → `typecheck`, `chain:lint:effect-diagnostics` → `lint:effect-diagnostics`).
- **FR-9** A chain waits up to 60 minutes for admission (`CHAIN_MAX_WAIT_MS`), not the 30 minutes a
  single lane waits (D9).

### Non-functional

- **NFR-1** The chain wrapper's bypass path loads only Node built-ins (no `tsx`), as `tsc-admitted.mjs`
  does, because CI runs `npm run typecheck`.
- **NFR-2** No test drives the real admission queue or real timers. Tests inject `acquire`, `spawn`
  and `env`, or force the bypass. Repo rule (fake-timers-for-retry-tests): any test that needs a
  queue wait or delay uses `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync`, never a real
  `setTimeout`. The tests planned here need no delay at all because the injected `acquire` resolves
  immediately.
- **NFR-3** `scripts/tsc-admitted.mjs` stays self-contained (no new imports), and its behavior does
  not change. Only its header comment changes.

## Decisions (made here; auto mode)

- **D1 One generic wrapper, not a `tsc-admitted.mjs` mode.** A new `scripts/gate-admitted.mjs
  <footprint-key> -- <command> [args…]` wraps any command. `tsc-admitted.mjs` is untouched apart
  from its comment, because a test copies it standalone (fact 7) and its argv is raw `tsc` args.
- **D2 The chain moves to `typecheck:lanes`.** `typecheck` becomes
  `node scripts/gate-admitted.mjs chain:typecheck -- npm run typecheck:lanes`, and `typecheck:lanes`
  holds today's `typecheck` string byte for byte. The lane scripts (`typecheck:acp` and the rest) do
  not change, so a lone lane keeps admitting itself.
- **D3 `lint:effect-diagnostics` is wrapped in `package.json`, not inside the `.sh`.** Its body becomes
  `node scripts/gate-admitted.mjs chain:lint:effect-diagnostics -- bash scripts/lint-effect-diagnostics.sh`.
  `npm run lint:effect-diagnostics -- --update` still passes `--update` to the script, because npm
  appends extra args to the end of the command. A direct `bash scripts/lint-effect-diagnostics.sh`
  still admits per lane (accepted; see NonGoals).
- **D4 Footprint = the chain's own recorded tree peak.** The chain records its peak under
  `chain:<script>`. Because lanes run in series, that peak is the largest lane plus overhead (fact 4),
  which satisfies "sized for the largest lane". Peers read estimates by key, so a computed
  max-of-lane-estimates would be invisible to them; the chain's own key is the consistent choice.
  The first run on a host uses the 2.5 GiB default. For `chain:typecheck` that is close to the real
  2.6 GiB. For `chain:lint:effect-diagnostics` (lanes peak near 3.0 GiB) the first run under-reserves
  by about 0.5 GiB once; the soft reserve absorbs it, and the next run uses the measured peak.
- **D5 Lanes inside a chain stop recording their own peaks.** They run unadmitted, so the runner does
  not sample them. Their existing histories stay and are still used by lone lane runs, which keep
  recording.
- **D6 A chain fails closed on every admission timeout; only a setup failure runs it unadmitted.**
  `acquireQualityGateAdmission` throws its timeout with the *last* wait kind
  (`quality-gate-admission.ts` lines 755-756), and a waiter behind other gates reports `queue` or
  `slots` (lines 798-803) even while memory is the real reason the queue is slow. So "only a memory
  timeout fails closed" would let a chain that timed out behind other gates start all 13 `tsc`
  processes unadmitted (critique round 1). The runner therefore takes a
  `failClosedOnTimeout` option, which `scripts/gate-admitted.mjs` sets: any
  `QualityGateAdmissionTimeoutError` exits 75 without spawning. A failure that is not a timeout
  (admission root unreadable, tsx cannot load) cannot be fixed by waiting, so the chain runs
  unadmitted and its child environment gets `OVERDECK_GATE_ADMISSION=0`, which stops each of its
  lanes from failing the same way again. A lone `tsc` lane does not set the option and keeps
  PAN-5248's D15 rule; its child is `tsc` itself, which ignores the variable, so lane behavior does
  not change.
- **D7 No lease heartbeat.** The 25-minute stale bound (fact 5) is far above real chain run time
  (fact 5), and the verification gate already holds one slot for the same chain today. Lease renewal
  is out of scope.
- **D8 `typecheck:share` stays as is.** Run alone it still admits twice (its two `tsc` calls). Inside
  the chain it is covered by FR-1. Fixing the lone case is out of scope.
- **D9 A chain waits up to 60 minutes, not 30.** `acquireQualityGateAdmission` times out when
  `now() - createdAt > maxWaitMs` (`quality-gate-admission.ts` line 755), counted from the ticket's
  creation at any queue position. A lane used to get its own 30-minute budget and wait only behind
  short single-lane holders. A chain waits once, behind holders that keep a slot for a whole chain
  (2-4.5 minutes each). Under the issue's own conditions (memory near the soft reserve, so each head
  may wait 5 minutes and then run alone, and six typechecks queued) the last chain would wait about
  6 × (5 + 4) ≈ 54 minutes minus its own run, past 30. A memory-reason timeout would then exit 75 and
  fail a typecheck that used to succeed slowly. `gate-admission-run.ts` exports
  `CHAIN_MAX_WAIT_MS = 60 * 60_000`, and `scripts/gate-admitted.mjs` passes it as `maxWaitMs`. The
  memory refusal line then reads `waited 60 minutes for memory`, and any other timeout reads
  `waited 60 minutes for admission (last waiting on <kind>)`. Every timeout fails closed (D6), as
  PAN-5248 requires for memory.

Write the file with this structure, matching `scripts/tsc-admitted.mjs` style (2-space indent,
semicolons, single quotes, ESM, top-level await):

```js
#!/usr/bin/env node
/**
 * Run a chain of tsc lanes under ONE machine-wide gate admission (PAN-5617).
 *
 * Usage: node scripts/gate-admitted.mjs <footprint-key> -- <command> [args…]
 *
 * `npm run typecheck` and `npm run lint:effect-diagnostics` run several tsc
 * lanes in a row, each through scripts/tsc-admitted.mjs. Admitted one lane at
 * a time, every lane rejoined the queue at the back (PAN-5617). This wrapper
 * takes one admission for the whole chain and runs <command> with
 * OVERDECK_GATE_ADMITTED=1, so each lane runs tsc directly inside the chain's
 * one slot. The chain's peak RSS is recorded under <footprint-key>
 * (`chain:<npm script>`); lanes run in series, so it is the largest lane's.
 *
 * Under CI, OVERDECK_GATE_ADMISSION=0 or OVERDECK_GATE_ADMITTED=1 it runs the
 * command directly and loads nothing but Node built-ins. Any admission timeout
 * (memory, queue, slots or CPU) exits 75 without running the command. A setup
 * failure (tsx cannot load, admission root unreadable) runs it with
 * OVERDECK_GATE_ADMISSION=0, so the lanes do not each fail the same way again.
 */
import { spawn } from 'node:child_process';
import { constants as osConstants } from 'node:os';

const USAGE = 'usage: node scripts/gate-admitted.mjs <footprint-key> -- <command> [args…]';
const [footprintKey, separator, command, ...args] = process.argv.slice(2);
if (!footprintKey || footprintKey === '--' || separator !== '--' || !command) {
  process.stderr.write(`${USAGE}\n`);
  process.exit(2);
}

function bypassAdmission(env) {
  return Boolean(env.CI) || env.OVERDECK_GATE_ADMISSION === '0' || env.OVERDECK_GATE_ADMITTED === '1';
}

/** Run the command unadmitted with `env` and exit with its code (or 128 + signal number). */
function runDirect(env) {
  const child = spawn(command, args, { stdio: 'inherit', env });
  const forward = (signal) => () => { child.kill(signal); };
  for (const signal of ['SIGINT', 'SIGTERM', 'SIGHUP']) process.on(signal, forward(signal));
  child.once('error', (error) => {
    process.stderr.write(`[gate-admission] could not start ${command}: ${error.message}\n`);
    process.exit(1);
  });
  child.once('exit', (code, signal) => {
    const signalNumber = signal ? osConstants.signals[signal] : undefined;
    process.exit(code ?? (signalNumber === undefined ? 1 : 128 + signalNumber));
  });
}

if (bypassAdmission(process.env)) {
  runDirect(process.env);
} else {
  let run;
  try {
    const { register } = await import('tsx/esm/api');
    register();
    run = await import(new URL('../src/lib/cloister/gate-admission-run.ts', import.meta.url).href);
  } catch (error) {
    process.stderr.write(`[gate-admission] proceeding without admission: ${error instanceof Error ? error.message : String(error)}\n`);
  }
  if (run) {
    process.exitCode = await run.runAdmittedCommand(
      { footprintKey, command, args, cwd: process.cwd() },
      { maxWaitMs: run.CHAIN_MAX_WAIT_MS, failClosedOnTimeout: true },
    );
  } else {
    runDirect({ ...process.env, OVERDECK_GATE_ADMISSION: '0' });
  }
}
```

The file needs no executable bit; every caller runs it as `node scripts/gate-admitted.mjs`.

## Critique response

### Queue timeout bypasses the entire chain

Accepted. The critic is right: the timeout carries the last wait kind, which is `queue` or `slots` for
any waiter behind other gates, so "only a memory timeout fails closed" would let a chain that timed out
behind other gates start all 13 `tsc` processes unadmitted. That is worse than today, where only the
timed-out lane ran unadmitted. The design now fails closed on every admission timeout for a chain:
`runAdmittedCommand` gains a `failClosedOnTimeout` option that `scripts/gate-admitted.mjs` sets, and any
`QualityGateAdmissionTimeoutError` returns 75 without spawning, with the line
`[gate-admission] refusing to start <key>: waited 60 minutes for admission (last waiting on <kind>)`.
Only a setup failure that waiting cannot fix (admission root unreadable, tsx cannot load) still runs the
chain unadmitted with `OVERDECK_GATE_ADMISSION=0`. A lone lane keeps PAN-5248's D15 rule. Changed: FR-6,
D6, D9, WI-1 code and tests 3, 6 and 7, WI-2 call and header, the WI-6 failure-mode docs text, and AC-2b.

### The invariant still says every lane queues

Accepted (sharpens-framing). The WI-6 CLAUDE.md replacement now says standalone lanes enter the queue
individually and that `npm run typecheck` and `npm run lint:effect-diagnostics` enter it once as a
whole chain, with their lanes running inside that one admission.

### Unresolved after two critic rounds

- Contracts build runs before admission
- A live chain can lose its slot after 25 minutes
- Setup failure bypasses admission for every lane
