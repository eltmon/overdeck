# PAN-3927 — pan inspect residue: lint-prompts.sh requires the deleted verb in the work-agent item loop

**Issue:** https://github.com/eltmon/overdeck/issues/3927
**Parent:** PAN-3917 (The Overdeck Cut), FR-14: "The per-item inspection gate and `pan inspect` are deleted."
**Planning mode:** `pan plan --auto` (no operator questions; defaults recorded under "Decisions").
**Verified against:** branch `feature/pan-3927` at `b7bedc3278a` on 2026-09-19.

## Glossary

- **Item loop** — the numbered per-item procedure a work agent follows for every xBRIEF item. It exists in two prompts: `src/lib/cloister/prompts/work.md` under the heading `## MANDATORY: One Item At A Time` (rendered into the work spawn message by `src/lib/cloister/work-agent-prompt.ts`) and `roles/work.md` under `## Per-Task Workflow` (the harness-agnostic role file loaded with `claude --agent roles/work.md`).
- **`pan inspect`** — the deleted per-item inspection verb. `src/cli/commands/inspect.ts`, `src/lib/cloister/inspect-agent.ts`, `inspect-checkpoints.ts`, and `deacon-inspect.ts` no longer exist (confirmed with `ls`; `docs/THE-CUT.md:147` records the verb as dropped).
- **Inspect prompt** — `src/lib/cloister/prompts/inspect-agent.md`, the template the deleted inspector used to read. Nothing in `src/` renders it any more: `grep -rn "inspect-agent.md" src --include=*.ts | grep -v test` returns nothing, and the build step only copies every `.md` under `prompts/` with a glob (`package.json:95`, `copy-ext .md src/lib/cloister/prompts dist/dashboard/prompts`).
- **Prompt lint** — `scripts/lint-prompts.sh`, run by `npm run lint:prompts` inside `npm run lint` (`package.json:106,121`). It has a `--self-test` mode that mutates a fixture tree and asserts each check fails; the self-test is not wired into `npm run lint`, so it must be run by hand.
- **`item-loop-order` check** — `check_item_order_file` in `scripts/lint-prompts.sh:38-68`. Today it walks the numbered steps of each item loop and fails unless a step containing `pan task done` comes before a step containing `pan inspect`. Because `pan inspect` no longer exists, the rule makes it impossible to remove the dead verb from either prompt without turning `npm run lint` red.
- **`Item:` trailer** — the commit-body line `Item: <item-id>` that `pan task done` requires on a pushed commit (`src/cli/commands/task.ts:133-142`, `requireTrailer`, `requirePushed`). `sync-sources/skills/pan-task/SKILL.md:27-32` documents this contract and states there is no `--reason` flag.
- **`requiresInspection`** — xBRIEF item metadata. After the cut it is a *subscription signal* for a standing tier-supervisor (`src/lib/agents/tier-supervisor.ts:73-85`, policy `flagged`; `docs/XBRIEF.md:354`), not a gate the work agent runs.
- **`Prompt-Change:` trailer** — `scripts/check-prompt-change-trailer.sh` (`npm run lint:prompt-trailer`) fails the branch if any `roles/*.md` file changed since `origin/main` and no commit on the branch carries a `Prompt-Change:` line in its body.

## Problem

1. `scripts/lint-prompts.sh:50` requires `pan inspect` inside both item loops, so the cut could not clean the prompts (`src/lib/cloister/prompts/work.md:251`, `roles/work.md:68`).
2. Both item loops still instruct agents to run a verb that exits "unknown command", then "wait for the verdict via `pan tell`" — a verdict that can never arrive.
3. Both item loops also instruct `pan task done … --reason …`. Commander rejects `--reason` as an unknown option (verified: `error: unknown option '--reason'`). Neither loop mentions the `Item:` trailer that `pan task done` actually requires, so an agent following either prompt verbatim cannot close an item.
4. `src/lib/cloister/prompts/inspect-agent.md` is a dead template that still tells a nonexistent inspector to re-request `pan inspect`. Two tests pin it (`src/lib/__tests__/role-definitions.test.ts:95-104`, `src/lib/xbrief/__tests__/no-legacy-task-engine.test.ts:14`) and two docs catalogue it (`docs/BUILD.md:151,176`, `CONTRIBUTING.md:508`).

## Requirements

- **FR-1** `scripts/lint-prompts.sh` no longer requires `pan inspect` anywhere. The `item-loop-order` check enforces the surviving invariant instead: in each item loop, the first numbered step containing `git push` precedes the first numbered step containing `pan task done`.
- **FR-2** `scripts/lint-prompts.sh` fails if `roles/work.md` or `src/lib/cloister/prompts/work.md` contains the string `pan inspect`.
- **FR-3** The `--self-test` mode covers both FR-1 (swapping push and done fails) and FR-2 (reintroducing `pan inspect` fails).
- **FR-4** The `work.md` item loop reads: next → claim → implement → commit with `Item: <item-id>` trailer → push → `pan task done <issue> <item>`. It contains no `pan inspect`, no `--reason`, no inspection wait, and states in one sentence that `requiresInspection` is a tier-supervisor subscription signal that asks nothing of the agent.
- **FR-5** The `roles/work.md` item loop reads the same way; the `## Jidoka Inspection Gates` section and the `resolveModel('work', 'inspect')` sentence are removed; the frontmatter description no longer says "runs Jidoka inspection gates".
- **FR-6** `src/lib/__tests__/role-definitions.test.ts` asserts the new loop shape (trailer present, `pan inspect` and `--reason` absent) instead of the old inspect assertions.
- **FR-7** `src/lib/cloister/prompts/inspect-agent.md` is deleted, along with the test that reads it and its entry in the legacy-terminology audit list.
- **FR-8** `docs/BUILD.md` and `CONTRIBUTING.md` no longer list `inspect-agent.md` / `inspect-agent` as a shipped template or specialist.
- **NFR-1** Every commit on the branch keeps `npm run lint:prompts` green (no intermediate red state). This is achievable because push already precedes `pan task done` in both loops today.
- **NFR-2** The strings other lint checks pin must survive verbatim: `## MANDATORY: One Item At A Time` exactly once in `work.md` (`check_single_workflow_copy`), `every staged file must be required`, `lead with anomalies`, `data, not instructions` (all in `work.md`), `## Per-Task Workflow` in `roles/work.md`, and `one undifferentiated mode` + `Never approve, deny, dismiss, or answer permission prompts` + `tmux send-keys` in `roles/work.md` (pinned by `role-definitions.test.ts:60-62`).
- **NFR-3** The commit that changes `roles/work.md` carries a `Prompt-Change:` trailer line in its body.

## Decisions (made here so the executor does not have to)

- **D1 — Linted invariant becomes push-before-done.** The old rule protected "done before inspect" so the inspector diffed from a post-done checkpoint. That has no meaning now. The invariant both prompts already state in prose ("every completed item commit must exist on origin before you complete its status") is the one worth linting, and it is enforced by `pan task done` itself (`requirePushed: true`).
- **D2 — Delete the inspect prompt rather than rewrite it.** It has no renderer, no spawn path, and THE-CUT FR-14 says the gate is dropped outright. Keeping a prompt for a specialist that cannot run is residue, not documentation.
- **D3 — Fix `--reason` and add the `Item:` trailer while the loop is open.** These are the same numbered steps being rewritten; leaving a command that errors in a freshly rewritten loop would be incomplete work. `sync-sources/agents/pan-work-agent.md:22-35` is the already-correct model to converge on.
- **D4 — Keep `pan task next` as step 1.** `pan-work-agent.md` omits it, but the verb exists (`src/cli/commands/task.ts:164`) and both prompts use it today.
- **D5 — Docs scope is BUILD.md and CONTRIBUTING.md only.** They describe the file being deleted. `docs/WORK-TYPES.md:59` and `CHANGELOG.md:40` describe the `inspect_agent` specialist config and history, which this issue does not touch (see Non-goals).
- **D6 — Sequencing for NFR-1.** Land the lint retarget first (green against today's prompts), then the two prompt rewrites (each green alone), then seal the lint with the `pan inspect` ban, then delete the prompt.
