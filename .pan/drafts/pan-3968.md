# PAN-3968 — `pan close` still deletes `state.json`/`sessions.json`: the live deleter is the `close-out:prune-agent-rows` step in `lifecycle/workflows.ts`, not `close-out.ts` step 5

**Issue:** https://github.com/eltmon/overdeck/issues/3968 (follow-up to PAN-3950 / PR #3951; AC-1 of `.pan/drafts/pan-3950.md` is unmet on main)
**Baseline:** `main` at `d1744000a66` (2026-09-20). Every line number below was verified against that commit; where a number may drift, the quoted identifier is the grep anchor.
**Principle (PAN-3917 cut, CLAUDE.md):** Overdeck stores no status it can derive. Close-out prunes caches, never state or transcripts.

## Glossary

- **Agent directory** — `~/.overdeck/agents/<agent-id>/`. Holds `state.json` (launch metadata + last status), `sessions.json` (append-only JSON Lines index of harness session ids), `activity.jsonl`, `lifecycle.log`, `pending.lock`, `*.sock`, and for Codex agents `codex-home*/`.
- **Agent row** — the `state.json` of one agent directory, as read by `listAgentStatesSync()` (`src/lib/agents/agent-state-read.ts:284`). "Pruning a row" in older code means deleting `state.json`.
- **Close-out ceremony** — what `pan close <id>` and the dashboard `POST /api/issues/:id/close-out` run. Both call `closeOut()` in `src/lib/lifecycle/workflows.ts:159` (CLI: `src/cli/commands/close.ts:403`; dashboard: `src/lib/overdeck/issue-close-out.ts:130,253,321`).
- **Teardown** — `teardownWorkspace()` in `src/lib/lifecycle/teardown-workspace.ts`, step 4 of the ceremony. Its agent-state step `removeAgentStateImpl` (`teardown-workspace.ts:325-360`) already calls `pruneAgentStateDir` and prints `Pruned N agent directories (transcripts and state kept)`.
- **`pruneAgentStateDir(dir)`** — `src/lib/agents/state-dir-removal.ts:71`. Deletes only `pending.lock`, `*.sock`, and every entry under `codex-home*/` except `sessions/`. Keeps everything else. The PAN-3950 door.
- **`removeAgentStateDir(dir)`** — `src/lib/agents/state-dir-removal.ts:280`. Unlinks every non-`.jsonl` file (via `cleanDirectory`), so `state.json` and `sessions.json` die and only `activity.jsonl` survives. The destructive door; still legitimately used by deep-wipe (`agents/agent-state.ts:86`), legacy-row drop (`agents/queries.ts:131`), `removeAgent` (`agents/removal.ts:22`), and `pan admin db gc-agents` (`cloister/agent-gc.ts:214`).
- **Agent GC** — `src/lib/cloister/agent-gc.ts`. `pruneAgentRowsAfterTranscriptCleanup` (`:234`) calls `deps.cleanStateDir` = `removeAgentStateDir` and, when the directory is not fully removed, writes the `.retained-transcripts` marker (`markRetained`). Two entry points: `pruneStoppedAgentsForIssue` (`:278`, called only by the ceremony) and `pruneTerminalStoppedAgents` (`:291`, called only by `pan admin db gc-agents`, `src/cli/commands/db.ts:46`).
- **`executeCloseOut`** — `src/lib/close-out.ts:617`, the pre-lifecycle ceremony implementation. **Dead code:** its only importer is its own test `src/lib/__tests__/close-out.test.ts:62`. `workflows.ts:145-148` documents that `closeOut()` replaced it. `close-out.ts` is still live for `isBranchMerged` (`:97`), imported by `src/lib/cloister/reap-issue-residue.ts:7`.
- **Agent transcript route** — `GET /api/agents/:agentId/conversation` (`src/dashboard/server/routes/agents/conversation.ts:123-130`). Resolves the workspace via `getAgentWorkspace` (`src/lib/agent-enrichment.ts:204-231`: `state.json.workspace` first, then the tmux pane cwd, then `workspaces/feature-<issue>` if it exists, else the project root) and then `listAgentTranscriptCandidates` (`src/lib/agents/transcript-resolver.ts:225`) from `sessions.json`.

## Problem — corrected root cause

The issue attributes the deletion to `src/lib/close-out.ts` step 5 ("Clean up agent state", `close-out.ts:426-448`, which calls `removeAgentStateDir`). That code is dead: `executeCloseOut` has no production caller (`grep -rn executeCloseOut src --include=*.ts` hits only `close-out.ts` and its test). Migrating it would change nothing for `pan close`.

The live ceremony is `closeOut()` in `src/lib/lifecycle/workflows.ts`. Its step 4 teardown runs `removeAgentStateImpl`, which prunes with `pruneAgentStateDir` and prints the reassuring "transcripts and state kept" line. Then, after the tracker close, this block runs:

```ts
// src/lib/lifecycle/workflows.ts:384-389 (grep anchor: 'close-out:prune-agent-rows')
    {
      const pruned = yield* Effect.promise(() => pruneStoppedAgentsForIssue(ctx.issueId));
      allSteps.push(pruned.preserved.length > 0
        ? stepSkipped('close-out:prune-agent-rows', [`Preserved live agents or terminal rows with retained transcripts: ${pruned.preserved.join(', ')}`])
        : stepOk('close-out:prune-agent-rows', [`Pruned ${pruned.removed.length} stopped agent row(s)`]));
```

`pruneStoppedAgentsForIssue` (`agent-gc.ts:278-289`) selects every `stopped` row for the issue — and teardown's `persistIssueAgentsStopped` (`teardown-workspace.ts:47`) has just marked them all stopped — and hands them to `pruneAgentRowsAfterTranscriptCleanup`, whose `cleanStateDir` is `removeAgentStateDir` (`agent-gc.ts:214`). That unlinks `state.json` and `sessions.json`, leaves `activity.jsonl`, and because the directory is not empty writes `.retained-transcripts`.

Evidence on this machine: `~/.overdeck/agents/agent-pan-3950/` holds `activity.jsonl` (11:38) and an empty `.retained-transcripts` (16:21 local = 20:21:21Z, the timestamp of the PAN-3950 `Done`/`closed-out` event in `overdeck.db`). Only `pruneAgentRowsAfterTranscriptCleanup` and `removeAgent` write that marker; `pan close` reaches the former. PR #3951 (`1446555`) touched `state-dir-removal.ts`, `teardown-workspace.ts`, and their tests only — never `workflows.ts` or `agent-gc.ts`.

`agent-pan-3705` (closed 2026-09-19, before #3951) has no marker because back then teardown's `removeAgentStateDirs` was the deleter; the GC step found nothing left to prune.

- **FR-6** `docs/MERGE-WORKFLOW.md` states that the ceremony runs no agent-row GC and names the only paths that delete `state.json`.
- **NFR-1** Net production lines negative (this PRD deletes ~440 lines of dead ceremony and ~12 lines of GC glue; it adds one doc sentence and one test).
- **NFR-2** No new module, store, flag, or config. No change to `state-dir-removal.ts` or `teardown-workspace.ts` — they are already correct.
- **NFR-3** No backfill code for already-pruned directories (see Appendix A).

## Decisions (made here so the executor does not re-decide)

- **D-1 Fix the live path by deletion, not by swapping the door.** The `close-out:prune-agent-rows` block is removed outright rather than pointed at `pruneAgentStateDir`, because teardown already ran exactly that prune on the same directories two steps earlier; a second pass would be a no-op that keeps a second cleanup path alive — the shape of bug that produced this issue.
- **D-2 Delete `executeCloseOut` instead of migrating its step 5.** It is dead. Migrating a dead ceremony to the new door satisfies the grep AC while preserving the trap. Deleting it satisfies the same AC and removes the trap. **Fallback:** if the work agent finds a production importer of `executeCloseOut` that this PRD missed, do not delete; instead replace the two `removeAgentStateDir(...)` calls at `close-out.ts:432,437` with `pruneAgentStateDir(...)`, drop `preservedTranscripts`, and make the step message `Agent state directories pruned (transcripts and state kept)`. Report the importer in the PR body.
- **D-3 `pan admin db gc-agents` stays destructive.** `docs/MERGE-WORKFLOW.md:156-157` already says "Explicit wipe, garbage collection, and retention remain the destructive cleanup paths." Out of scope here; see Hazard H-3.
- **D-4 Already-pruned directories (`agent-pan-3705`, `agent-pan-3950`) are an operator one-off, not code.** PAN-3959 ships no backfill either. Recovery needs both `state.json` (for the workspace slug — without it `getAgentWorkspace` falls through to the project root once the worktree is gone and the Claude project dir is computed wrong) and `sessions.json`. Appendix A gives the exact recipe. The work agent must not run it.
- **D-5 Regression test seeds `getOverdeckHome()/agents/`, not the mocked `AGENTS_DIR`.** `tests/unit/lib/lifecycle/workflows.test.ts:102-111` mocks `paths.js` so `AGENTS_DIR` = `<tmpdir>/overdeck-wf-test-home/agents`, but `listAgentStatesSync`/`saveAgentStateSync` resolve `getOverdeckHome()` (per-worker `OVERDECK_HOME` from `tests/setup/overdeck-home.ts`). The deleted GC step read and deleted under `getOverdeckHome()`, so a fixture under the mocked root would pass before the fix and prove nothing.

## Appendix A — operator recipe for the two already-pruned directories (not a work item)

For `agent-pan-3705` and `agent-pan-3950` both `state.json` and `sessions.json` are gone; the Claude JSONLs still exist under `~/.claude/projects/-home-eltmon-Projects-overdeck-workspaces-feature-pan-<n>/` (three files for 3950, two for 3705). Because the worktrees are deleted, the resolver needs `state.json.workspace` to compute that slug. Recreate both files by hand (operator only; never from an agent):

```bash
id=pan-3950   # or pan-3705
d=~/.overdeck/agents/agent-$id
printf '%s\n' "{\"id\":\"agent-$id\",\"issueId\":\"${id^^}\",\"role\":\"work\",\"status\":\"stopped\",\"workspace\":\"/home/eltmon/Projects/overdeck/workspaces/feature-$id\",\"harness\":\"claude-code\",\"model\":\"claude\",\"startedAt\":\"2026-09-20T00:00:00.000Z\",\"stoppedAt\":\"2026-09-20T20:21:21.000Z\"}" > "$d/state.json"
for f in ~/.claude/projects/-home-eltmon-Projects-overdeck-workspaces-feature-$id/*.jsonl; do
  sid=$(basename "$f" .jsonl); at=$(date -u -r "$f" +%FT%TZ)
  printf '%s\n' "{\"sessionId\":\"$sid\",\"at\":\"$at\",\"source\":\"operator-backfill\",\"harness\":\"claude-code\",\"model\":\"claude\"}" >> "$d/sessions.json"
done
rm -f "$d/.retained-transcripts"
```
Then `GET /api/agents/agent-$id/conversation` resolves the newest existing JSONL. Order the loop by mtime (`ls -tr`) if the newest session should win.
