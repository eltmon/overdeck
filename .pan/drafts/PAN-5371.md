# PAN-5371 — One Needs-you count on Simple Home and the top bar

**Issue:** [PAN-5371](https://github.com/eltmon/overdeck/issues/5371)
**Parent rule:** [PAN-5284](https://github.com/eltmon/overdeck/issues/5284) N-D8 (`.pan/drafts/pan-5284.md`, line 61)
**Follow-up filed during planning:** [PAN-5413](https://github.com/eltmon/overdeck/issues/5413) (Kanban Needs-you strip, same bug, out of scope here)

## 1. Glossary

- **Top bar Needs-you count** — the `Needs you · N` button, `components/flywheel/NeedsYouIndicator.tsx`. N is `useNeedsYouItems().length`.
- **Shared selector** — `useNeedsYouItems()` / pure `buildNeedsYouItems()` in `src/dashboard/frontend/src/lib/selectors/needsYou.ts`. It returns `NeedsYouItem[]`: (a) unresolved pending input of agents and conversations, (b) issues whose `DerivedIssueState.attention === 'needs-you'`, (c) Flywheel tick rows, (d) other decisions. Items are deduplicated by `key` (`issue:<ID>`, `conversation:<name>`, `agent:<id>`, `flywheel:<hash>`, `decision:<id>`).
- **Simple Home** — `components/simple/SimpleHomePage.tsx`, rendered by `components/simple/HomeSwitch.tsx` when `useUiMode().mode === 'simple'` and no simple issue is open.
- **Simple derivation** — `deriveSimpleIssue()` in `lib/simple/derive.ts`, giving each issue a `display` from `lib/simple/userFacingState.ts`. When `display.state === 'needs-you'`, `display.needsYouReason` is one of `question | start-work | problems | stuck`.
- **Simple buckets** — `bucketSimpleHome()` in `lib/simple/derive.ts`. Its `needsYou` bucket holds every derivation whose `display.state === 'needs-you'`.
- **Displaced kinds** — the three Simple reasons that the shared selector does not count: `start-work` (a plan exists and no work agent runs: "The plan is ready … Nothing starts until you say go"), `stuck` (an agent has a problem status, or `attention` is `stuck`/`api-error`), and `problems` (derived state `changes-requested`).
- **Secondary sections** — the two new Simple Home sections this issue adds, **Ready to start** and **Having trouble**, which show displaced kinds outside the Needs-you count.
- **CI frontend subset** — `scripts/frontend-test-subset.txt`. CI runs only the frontend Vitest files listed there (paths relative to `src/dashboard/frontend`, sorted).

## 2. Problem (verified)

On :3011 (buildCommit `52e312dd0df`) Simple Home says "18 things need you." while the top bar on the same page says `Needs you · 8`.

- The top bar counts `useNeedsYouItems().length` (`NeedsYouIndicator.tsx`, search `const count = items.length`).
- Simple Home counts its own rule, `SimpleHomePage.tsx` line 239:

  ```tsx
  const needsCount = buckets.needsYou.length + extraQuestions.length;
  ```

  `buckets.needsYou` includes every derivation with `display.state === 'needs-you'`. In `userFacingState.ts` line 60 the `planning_done_awaiting_work` row is `state: 'needs-you', needsYouReason: 'start-work'`, and `derivePipelineState` (`lib/issuePipelineState.ts` line 74-75) maps every derived `planned` issue without a live plan pane to `planning_done_awaiting_work`. So every planned-but-not-started issue counts as "needs you" on Simple Home. Stuck agents (`isAgentProblemStatus`, which includes `unknown`) and `changes-requested` issues count too. The shared selector counts none of those unless they also carry pending input or `attention: 'needs-you'`.

- The Simple Home Needs-you section also fails to list three kinds the top bar counts: Flywheel rows, system decisions, and conversation/agent pending input that has no issue.

## 3. Decision

**Option 1 from the issue body.** Simple Home's headline number is `useNeedsYouItems().length`, its Needs-you section lists exactly those items, and the displaced kinds render in their own sections outside the count.

Why: PAN-5284 D-8 (`.pan/drafts/pan-5284.md` line 61) already rules that `isNeedsYouFeature`'s extra rules (`work-not-started`, `pr-outside-pipeline`, `ready`) "are pipeline states, not needs-you items". Option 2 would contradict N-D8 and would also change the number on the Advanced Home card, the project Home and the top bar, which PAN-5292 (FR-E8, FR-E9) just made agree.

Decision rules (the executor must not re-decide these):

1. **N-D1 Count.** Simple Home's h1 number and the number beside the "Needs you" h2 are both `useNeedsYouItems().length` (all projects, no `projectKey`).
2. **N-D2 One card per item.** The Needs-you section renders exactly one card per `NeedsYouItem`, in the selector's order, each wrapped in `data-testid="simple-needs-you-card"` with `data-needs-you-key={item.key}`.
3. **N-D3 Card choice** (pure function `simpleNeedsYouCards`, §5 WI-1). For each item, take the issue id from a key that starts with `issue:` and look up its Simple derivation:
   - derivation exists and `derivation.display.state === 'needs-you'` → card = `derivation.display.needsYouReason ?? 'problems'` (existing `QuestionCard` for `question`, existing `ProblemsCard` for `start-work` / `stuck` / `problems`);
   - else derivation exists and `item.subject` is set → card = `question` (`QuestionCard`, subject = `item.subject`);
   - else → card = `item` (new generic `NeedsYouItemCard`: title, ask, one **Open** button).
4. **N-D4 Open target.** A card with a derivation opens the simple issue page (`openIssue(derivation, openSimpleIssue)`, the existing helper). A card without a derivation calls `item.open()`.
5. **N-D5 Plain title.** A generic card's title is `SIMPLE_STRINGS.home.waitingDecisionTitle` ("A decision is waiting") when `item.kind === 'flywheel'` (the selector titles those "Flywheel", a banned word in simple mode); otherwise `item.title`. Runtime decision labels are not rewritten.
6. **N-D6 Displaced kinds** (pure function `simpleSecondarySections`, §5 WI-1). Walk `buckets.needsYou`. Skip an entry whose issue id (upper-cased) is the id of some item's `issue:` key (it is already a Needs-you card: an idle planner's `agentTurnEnded` subject makes a plan-ready issue a pending-input item, so this dedup is required). Of the rest: `start-work` → **Ready to start**; `stuck` and `problems` → **Having trouble**; `question` → not shown (outside the shared list it is answered, dismissed, or a kind-less phantom wait that PAN-1591 deliberately excludes).
7. **N-D7 Subline.** Under the h1: if either secondary section is non-empty → `S.othersWaitingSub`; else if the count > 0 → `S.everythingElseMoving`; else → `S.nothingNeedsYou`. The h1 text format stays `${n} thing(s) need(s) you.` / `S.greetingFallback`.
8. **N-D8 Section order.** Needs you → Ready to start → Having trouble → Just filed → Working now → Ready to merge → Finished. Each secondary section renders only when non-empty.
9. **N-D9 Unchanged.** `buildNeedsYouItems`, `useNeedsYouItems`, `bucketSimpleHome`, `deriveSimpleIssue`, `userFacingDisplay` and `NeedsYouStrip` keep their behavior.
10. **N-D10 Working now excludes Needs-you cards.** The "Working now" section and its "being worked on" stat use `buckets.working` minus any derivation whose upper-cased identifier is in `coveredIssueIds(needsItems)`. Its subtitle says "Nothing for you to do on these", so an issue that is a Needs-you card must not also appear there. "Ready to merge" and "Finished" are unchanged.
