# PAN-3308 — The file-size guard stops teaching the ceiling raise; raising a ceiling becomes operator-only

**Issue:** [PAN-3308](https://github.com/eltmon/overdeck/issues/3308)
**Design source:** `.pan/drafts/deft-adoption.md`, "Issue 1: The file-size guard teaches agents to raise the ceiling; make raises operator-only" (operator-approved 2026-09-28, posted on the issue 2026-09-29).
**Related:** #3322 (a temporary raise became permanent regrowth budget), #4344 and #4346 (will reuse the identity helper and the operator-only raise rule from this issue), #4345 (the matching bundled rule, out of scope here).

## Glossary

- **File-size guard** — `scripts/lint-file-size.sh`. It fails when a non-test `src/**/*.ts(x)` file exceeds its *allowed count*. It runs in `npm run lint` (working tree) and in `.husky/pre-push` (`--at <sha>`, the pushed tip).
- **CEILING** — `1000` lines (`scripts/lint-file-size.sh:38`). A file at or below it is never checked.
- **Allowlist** — `scripts/file-size-allowlist.txt`. Rows have the form `<lines> <path> # <ISSUE-REF>`. A path may have several rows.
- **Effective cap** — for one path at one revision, the `<lines>` value of the **last** row for that path. `lint-file-size.sh:71` stores rows in an associative array, so a later row overwrites an earlier one. The live allowlist has several paths with multiple rows (`src/cli/commands/start.ts`, `src/lib/config-yaml/schema.ts`, `src/lib/overdeck/conversations.ts`).
- **Allowance** — what the guard permits for a path at a revision `R`: the effective cap at `R` if the path has a row; otherwise `max(line count of the path at R, CEILING)`; if the path does not exist at `R`, `CEILING`. This mirrors `lint-file-size.sh:158-168`.
- **Ceiling raise** — a push whose head allowlist gives some path an effective cap greater than every *prior allowance* for that path (see FR-5). Adding a row at or below the prior allowance, or lowering a row, is not a raise.
- **Push range** — `<base>..<local_sha>` computed by `.husky/pre-push:56-60`: for a push to `main`, `base` is the remote's current `main` sha; for any other branch, `base = git merge-base origin/main <local_sha>`.
- **Remote tip** — `remote_sha` in the pre-push loop: the sha the remote branch pointed at before this push (`0000…` for a new branch).
- **Agent pusher** — the push runs in an agent context. Today (`scripts/guard-agent-main-push.sh:38-49`): `OVERDECK_AGENT_ID` is non-empty, or `git config user.name` ends in `[bot]`.
- **Operator conversation** — a human-supervised conversation. Marker: `OVERDECK_AGENT_ID` starts with `conv-` (`guard-agent-main-push.sh:21`). Exempt from the agent rules.
- **Flywheel** — the unsupervised orchestrator loop running in the conversation `conv-flywheel` (`src/lib/flywheel/constants.ts:7`, `docs/FLYWHEEL.md:3`). It is a conversation, so today it is exempt from the main-push guard, which is the gap this issue closes.
- **Operator escape hatch** — `OVERDECK_OPERATOR_PUSH=1 git push …`. Already honored by `guard-agent-main-push.sh:17-19`.

## Problem

`scripts/lint-file-size.sh:171-176` prints this on failure:

```bash
  if (( n > allowed )); then
    echo "✖ $f is $n lines (allowed $allowed) — god files must shrink, not grow."
    echo "  Shrink the file, or add an audited exception to $ALLOWLIST:"
    echo "  $n $f # <ISSUE-REF>"
    fail=1
  fi
```

It offers the raise as an equal option and prints the paste-ready row with the new, larger count. Three agents hit the guard on `src/lib/launcher-generator.ts` (1018 lines against a 1012 cap). Two raised the cap (`bd41256921`, `0a4914dd90`; the second one called the cap "stale"). One shrank the file, and only because its issue body forbade the raise. The trailers at lines 182 and 184 repeat the invitation ("without an issue-referenced allowlist entry"), and the planner prompt `src/lib/cloister/prompts/planning.md:168` tells planners to *prescribe* an allowlist row whenever an item grows a god file.

Nothing distinguishes an agent's raise from the operator's. Both look like a normal commit.

## Decisions (made here; the executor does not re-decide)

1. **The later operator-approved design supersedes the issue body's request #2.** The issue body asks for an absolute rule ("an allowlist entry greater than the `origin/main` count fails the guard"). The design comment makes raises *operator-only* instead: refused for agent pushers, allowed with `OVERDECK_OPERATOR_PUSH=1` or from an operator conversation. An absolute ban would also block the operator, which the design explicitly allows. Issue AC2 ("an entry greater than the `origin/main` count fails the guard, with a unit test") is satisfied for every agent pusher by WI-4.
2. **The enforcement point is `.husky/pre-push`**, via a new script `scripts/guard-allowlist-raise.sh`. `lint-file-size.sh` itself does not learn about identity; `npm run lint` in CI has no pusher identity.
3. **One shared identity helper**, `scripts/lib/pusher-identity.sh`, sourced by both `guard-agent-main-push.sh` and `guard-allowlist-raise.sh`. #4344 and #4346 will reuse it.
4. **Tighten only, never loosen.** The helper keeps today's `conv-*` exemption exactly on `OVERDECK_AGENT_ID`. It adds flywheel detection that overrides the exemption. It does *not* add `OVERDECK_CONVERSATION=conv-*` as a new exemption.
5. **Flywheel detection uses three tokens**, because `OVERDECK_AGENT_ID` is exported for conversations only under Herdr/supervisor/pi/codex/acp (`src/lib/overdeck/conversation-runtime.ts:799`), while `OVERDECK_CONVERSATION` is exported for every conversation (`conversation-runtime.ts:804`), and `OVERDECK_AGENT_STARTED_BY` is exported into every spawned agent environment (`src/lib/agents/spawn.ts:447`, `:866`; `src/lib/agents/resume.ts:475`). The pusher is the flywheel when **any** of these holds: `OVERDECK_AGENT_ID == conv-flywheel`, `OVERDECK_CONVERSATION == conv-flywheel`, or `OVERDECK_AGENT_STARTED_BY` starts with `flywheel:`. A flywheel pusher is always an agent pusher, regardless of git identity.
6. **Tightening the main-push guard for `conv-flywheel` is safe.** The flywheel skill pushes to `main` only `.pan/flywheel/state.md` and `.pan/flywheel/report.md` (`sync-sources/skills/pan-flywheel/SKILL.md:197-201`, `:228-232`). Those are not code paths (`guard-agent-main-push.sh:85` matches only `src|packages|roles|skills|scripts`), so they still pass.
7. **The remote tip is grandfathered.** Without it, an operator raise pushed to a feature branch with `OVERDECK_OPERATOR_PUSH=1` stays inside `merge-base..tip` forever, so every later push of that branch by its agent (`pan done`, server-side sync-main — both run as `[bot]` with no opt-in) would be refused. So a raise is measured against `max(allowance@base, allowance@remote_sha)`. The remote tip is used only when it is non-zero and exists locally (`git cat-file -e <sha>^{commit}`); otherwise only `base` is used. This is not in the Deft design; it follows from the pre-push loop semantics.
8. **The operator at their own terminal also needs the escape hatch.** The primary checkout commits as `overdeck-agent[bot]` (verified: `git -C ~/Projects/overdeck config user.name` → `overdeck-agent[bot]`), so the `[bot]` test classifies a plain terminal push as an agent push. A ceiling raise therefore always costs `OVERDECK_OPERATOR_PUSH=1 git push` or an operator conversation. This is the intended "costs more than a copy-paste."
9. **Lowering stays free.** `bash scripts/lint-file-size.sh --lower` and any hand edit that lowers or removes a row are never refused.

## Requirements

- **FR-1** — When the file-size guard fails, its output contains no line matching `^\s*\d+ \S+ # ` (no paste-ready allowlist row).
- **FR-2** — The failure output states that the file must shrink to its allowed count, that the allowlist number must not increase, and that raising a ceiling is an operator decision documented in `docs/codebase-health/A3-file-size-guard.md`.
- **FR-3** — `scripts/lib/pusher-identity.sh` defines `overdeck_pusher_is_agent`, which returns 0 for an agent pusher (including every flywheel token of Decision 5) and 1 otherwise, with the `conv-*` exemption applying only to non-flywheel conversations.
- **FR-4** — `scripts/guard-agent-main-push.sh` uses the helper, so `conv-flywheel` pushes of code paths to `main` are refused while other `conv-*` ids keep passing.
- **FR-5** — `scripts/guard-allowlist-raise.sh --range <base>..<head> [--prior <sha>]` exits 1 and names each raised path, its new cap, and its prior allowance when the pusher is an agent and some path's effective cap at `<head>` exceeds `max(allowance@<base>, allowance@<prior>)`. It exits 0 for operator pushers, `OVERDECK_OPERATOR_PUSH=1`, ranges that do not touch the allowlist, and ranges that only lower, remove, or keep rows.
- **FR-6** — `.husky/pre-push` runs `guard-allowlist-raise.sh` for every `refs/heads/*` push that has a base, passing `--prior <remote_sha>` when the remote tip is non-zero.
- **FR-7** — The planner prompt no longer instructs planners to add allowlist rows; it instructs them to plan an extraction that keeps the file at or under its allowed count.
- **FR-8** — `docs/codebase-health/A3-file-size-guard.md` gains a section "Raising a ceiling is an operator decision" with the exact recipe; `sync-sources/skills/pan-release/SKILL.md` states that `conv-flywheel` is not exempt.
- **NFR-1** — Nothing is stored: every decision derives from the push range, the two revisions' allowlists and line counts, and the caller's environment.
- **NFR-2** — The new scripts are bash with `set -euo pipefail`, read no stdin (the hook passes `</dev/null`), and fail closed on a missing or malformed `--range` (same shape as `guard-agent-main-push.sh:25-36`).
- **NFR-3** — No `src/**/*.ts` production code changes. Only `src/lib/cloister/prompts/planning.md` (a prompt text file) is touched under `src/`.

### WI-2 — Shared pusher-identity helper (FR-3, NFR-1)

**Files:** new `scripts/lib/pusher-identity.sh`, new `tests/unit/scripts/pusher-identity.test.ts`.

The helper is sourced, not executed. It defines one function and no top-level side effects:

```bash
#!/usr/bin/env bash
#
# pusher-identity.sh — who is pushing? Sourced by the push guards
# (guard-agent-main-push.sh, guard-allowlist-raise.sh).
#
# overdeck_pusher_is_agent → 0 when the push runs in an agent context, 1 otherwise.
#   - The Flywheel (conv-flywheel, PAN-2194 / docs/FLYWHEEL.md) is always an agent,
#     whatever its git identity: OVERDECK_AGENT_ID=conv-flywheel,
#     OVERDECK_CONVERSATION=conv-flywheel, or OVERDECK_AGENT_STARTED_BY=flywheel:*.
#   - Other operator conversations (OVERDECK_AGENT_ID=conv-*) are not agents.
#   - Any other non-empty OVERDECK_AGENT_ID is an agent.
#   - A `[bot]` git identity is an agent's (#4066 review). The primary checkout
#     also commits as overdeck-agent[bot], so an operator at a plain terminal
#     uses OVERDECK_OPERATOR_PUSH=1, which each guard checks itself.
overdeck_pusher_is_agent() {
  local agent_id="${OVERDECK_AGENT_ID:-}"
  if [[ "$agent_id" == "conv-flywheel" \
     || "${OVERDECK_CONVERSATION:-}" == "conv-flywheel" \
     || "${OVERDECK_AGENT_STARTED_BY:-}" == flywheel:* ]]; then
    return 0
  fi
  if [[ "$agent_id" == conv-* ]]; then
    return 1
  fi
  if [[ -n "$agent_id" ]]; then
    return 0
  fi
  local git_user_name
  git_user_name=$(git config user.name 2>/dev/null || true)
  if [[ "$git_user_name" == *"[bot]" ]]; then
    return 0
  fi
  return 1
}
```

The escape hatch `OVERDECK_OPERATOR_PUSH=1` is **not** inside the helper; each guard checks it first, as `guard-agent-main-push.sh:17` does today.

### WI-4 — New pre-push guard `scripts/guard-allowlist-raise.sh` (FR-5, NFR-1, NFR-2)

**Files:** new `scripts/guard-allowlist-raise.sh`, new `tests/unit/scripts/guard-allowlist-raise.test.ts`.

Interface: `bash scripts/guard-allowlist-raise.sh --range <base>..<head> [--prior <sha>]`.

Algorithm (step by step):

1. `set -euo pipefail`; `cd "$(dirname "$0")/.."`; `source scripts/lib/pusher-identity.sh`.
2. `CEILING=1000  # keep in step with scripts/lint-file-size.sh CEILING`; `ALLOWLIST="scripts/file-size-allowlist.txt"`; `ISSUE_REF_RE='([A-Z]+-[0-9]+|#[0-9]+)'` (same as `lint-file-size.sh:41`).
3. If `OVERDECK_OPERATOR_PUSH == 1`, exit 0.
4. Parse args. On a missing, empty or malformed range (no `..`, or leading/trailing `..`), print `✖ allowlist raise guard: missing or undeterminable push range '<r>'; refusing because this is a trust gate.` to stderr and exit 1 (same shape as `guard-agent-main-push.sh:25-36`). An unknown argument prints a usage line and exits 2.
5. If `! overdeck_pusher_is_agent`, exit 0.
6. `base=${RANGE%%..*}`, `head=${RANGE##*..}`. If either fails `git rev-parse -q --verify "<x>^{commit}"`, fail closed as in step 4 with `cannot resolve push range`.
7. If `git diff --name-only "$RANGE" -- "$ALLOWLIST"` is empty, exit 0.
8. `caps_at <rev>` prints `path cap` lines: read `git show "<rev>:$ALLOWLIST" 2>/dev/null`, skip blank and `#` lines, match the row regex from `lint-file-size.sh:70`, keep the **last** value per path (bash associative array). Unparseable rows are skipped (the file-size guard reports them).
9. `allowance_at <rev> <path>`: the effective cap at `<rev>` if present; else if `git cat-file -e "<rev>:<path>"`, `max(git show "<rev>:<path>" | wc -l, CEILING)`; else `CEILING`.
10. Prior revisions = `base`, plus `--prior <sha>` when it is non-empty, not all zeros, and `git cat-file -e "<sha>^{commit}"` succeeds.
11. For every path with a row at `head`: `prior = max(allowance_at r path for r in priors)`. If `head_cap > prior`, record `<path> <prior> → <head_cap>`.
12. If any were recorded, print to stderr:
    ```
    ✖ allowlist raise guard: this push raises file-size ceilings, and agents may not raise them:
      src/x.ts 1012 → 1018
    A failing file-size guard is fixed by shrinking the file, not by raising its cap.
    Raising a ceiling is an operator decision made in its own commit and pushed with
    OVERDECK_OPERATOR_PUSH=1 git push … — see docs/codebase-health/A3-file-size-guard.md.
    ```
    and exit 1. Otherwise exit 0.

The script prints no allowlist row either (the listing uses `→`, not the row format).

```markdown
## Raising a ceiling is an operator decision (PAN-3308)

When the file-size guard fails, the fix is to shrink the file to its allowed count. The guard's message names only that remedy and prints no allowlist row.

Lowering an allowlist row is always allowed: run `bash scripts/lint-file-size.sh --lower`, or edit the row down by hand.

Raising a row, or adding a row above the file's allowance on the base (its last row, else `max(line count, 1000)`), is an operator decision. `scripts/guard-allowlist-raise.sh` runs from `.husky/pre-push` and refuses the push when the pusher is an agent: `OVERDECK_AGENT_ID` is set (other than an operator `conv-*` conversation), the git identity ends in `[bot]`, or the pusher is the Flywheel (`conv-flywheel`, identified by `OVERDECK_AGENT_ID`, `OVERDECK_CONVERSATION`, or a `flywheel:` `OVERDECK_AGENT_STARTED_BY`). Identity comes from `scripts/lib/pusher-identity.sh`.

The operator raises a ceiling in its own commit that names the issue, then pushes with:

    OVERDECK_OPERATOR_PUSH=1 git push

The primary checkout commits as `overdeck-agent[bot]`, so a plain terminal push needs this too. A raise already on the remote branch is not re-checked on later pushes of that branch.
```

## Intersecting repo rules (restated)

- **Quality gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.
- **Tests that read source files** as strings fail lint (`lint-source-introspection`). The script tests execute the scripts in temp repos, which is the existing pattern; do not add tests that `readFileSync` a script to grep its text. (`lint-file-size.test.ts` and `pre-push-hook.test.ts` already copy the script into a temp repo and execute it; that pattern is allowed.)
- **No `skipIf` / `.only`** in new tests; the test-skip gate fails them.
- **No `git stash`**, no `git checkout` of other branches inside the workspace.
- **Delete commands name literal paths**, never variables (applies to any cleanup the tests do; prefer leaving temp dirs under `os.tmpdir()` as the existing tests do).
- **Shell guards fail closed** on an undeterminable range — they are trust gates.

## Non-goals

- `git push --no-verify` bypasses every pre-push guard; the agent git-guard shim does not intercept it. Closing that is separate work.
- CI (`npm run lint`) has no pusher identity and does not run the raise guard.
- The bundled rule "gate integrity" (#4345), the main-push guard for registered projects (#4344) and the context-budget ratchet (#4346) consume this issue's helper later; they are not built here.
- No change to how `lint-file-size.sh` computes allowed counts, and no absolute ban on raises.
- No new exemption: `OVERDECK_CONVERSATION=conv-*` without a `conv-*` agent id is not treated as an operator conversation.
- No edits to existing rows in `scripts/file-size-allowlist.txt`.
