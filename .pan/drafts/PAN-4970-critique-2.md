## blocks-the-design: Mixed queues still offer an assembly that cannot happen

The PRD's item 8 passes the total `featureCount` and `perPrCount` to `canRetryAssembly`, and only suppresses Retry when *all* features are per-PR. With two ready features, one per-PR and one unheld batch-owned (for example, a cancelled auto-merge), it therefore shows **Retry batch assembly** and `NO_BATCH_YET_LINE` promises a batch. The reconciler filters the per-PR feature first; its single-feature branch returns `single-feature` even with `force: true` when the remaining feature is unheld (`src/lib/cloister/uat-reconciler.ts:289-299`). The current UI counts all queue rows (`src/dashboard/frontend/src/components/merge-train/MergeTrainView.tsx:640,674-700`) and `canRetryAssembly` treats any two as enough (`src/dashboard/frontend/src/components/merge-train/mergeTrainCopy.ts:50-56`). Change the copy and Retry decision to use the filtered batch-owned count and the actual UAT hold of its sole member. Add a mixed two-row test where the sole batch-owned feature is unheld and assert that no batch or Retry is promised.

## blocks-the-design: One owner lookup failure hides the whole project queue

Item 5 prescribes `Promise.all` over every queue item's `mergePathOwner` call with no per-item error handling. `queueEntryForProject` is wrapped in project-level `Promise.allSettled`; any rejection replaces that project's already computed ready queue with `queue: []` (`src/dashboard/server/routes/merge-train.ts:126-144,152-166`). The new owner performs async policy and PR lookup, so one rejected read would hide every ready feature and its merge controls until the next successful poll. The reconciler's item 2 explicitly treats an owner error as batch-owned; apply that same per-item fallback in the queues mapping, log the failure, and test that one rejected lookup leaves the remaining queue visible with `mergesPerPr: false` for the failed item.
