# PAN-4465 — `pan tell` accepts conversation numbers and `/conv/<n>` URLs

**Issue:** https://github.com/eltmon/overdeck/issues/4465

## Glossary

- **Agent target** — the `<id>` argument of `pan tell`, `pan pause`, `pan unpause`, `pan untroubled` and `pan kill` (alias `pan stop`). It names one agent (or, for `pan kill`, one issue's whole agent set).
- **Agent ID** — the directory name under `~/.overdeck/agents/` and the terminal session name: `agent-pan-1148`, `strike-pan-1723`, `planning-pan-12`, `inspect-…`, `conv-20260928-7563`, or a singleton such as `flywheel-orchestrator`. A "qualified" agent ID is one `isQualifiedAgentId()` recognizes (known prefix or singleton).
- **Conversation number** — the integer shown in the dashboard URL `https://<host>/conv/2972`. It is the SQLite `rowid` of the `conversations` table in `overdeck.db`, returned as `LegacyConversation.id` and looked up by `getConversationById(n)`.
- **Conversation name** — the `conversations.name` column, `YYYYMMDD-NNNN` (for example `20260928-7563`). The dashboard also routes `/conv/<name>`.
- **Conversation agent ID** — `LegacyConversation.tmuxSession`. For a normal conversation it is `conv-<name>`; for an issue agent registered as a conversation row (`src/lib/agents/spawn.ts`, line 367, `tmuxSession: agentId,`) it is the issue agent's ID. Always use `tmuxSession`; never build `conv-${name}` yourself.
- **Explicit conversation form** — `conv/<key>`, `conv:<key>`, or a dashboard URL `http(s)://<host>[:port]/conv/<key>[?query][#hash]`, where `<key>` is a conversation number or name. Note `conv-<name>` (hyphen) is an agent ID, not this form.
- **Issue agent candidate** — an `agent-<prefix>-<n>` state directory with a readable `state.json` whose `issueId` ends in `-<n>`. This is the existing rule in `resolveBareNumericId` (`src/lib/issue-id.ts`). A state directory counts whether or not the agent is running.
- **Vault conversation** — a row with `origin = 'vault'` (Session Vault browse copy, PAN-4436). It cannot receive messages.

## Problem

The operator refers to conversations by their dashboard number, but the agent-target resolver only knows issue IDs and agent IDs:

```
$ pan tell 2972 "..."
Could not resolve agent target "2972"
Pass an issue ID like "PAN-1148" or a full agent ID like "strike-pan-1723"; the state dir must exist under ~/.overdeck/agents/.
```

The resolver is `resolveAgentTarget` in `src/lib/agents/identity.ts` (line 79, grep `export function resolveAgentTarget(input: string): string | null {`). It returns `null` only for bare digits with no matching issue agent; every other string becomes an issue or agent ID. The error text is duplicated verbatim in four commands:

- `src/cli/commands/tell.ts`, line 36 (grep `Could not resolve agent target`)
- `src/cli/commands/pause.ts`, line 20 (same grep)
- `src/cli/commands/unpause.ts`, line 26 (same grep)
- `src/cli/commands/untroubled.ts`, line 10 region (same grep)
- `src/cli/commands/kill.ts`, line 82 (grep `Could not resolve issue ID`) — kill does its own resolution with `isQualifiedAgentId` then `resolveBareNumericId`.

A second issue: a successful send to a conversation prints `[agents] Skipping tell intervention for conv-20260928-7563; state.json has no issueId`. That comes from `appendTellInterventionForUserSource` in `src/lib/agents/messaging.ts`, line 170 (grep `Skipping tell intervention for`). `console.debug` writes to stdout under Node, so the operator sees it. Conversations never carry an issueId, so the line is noise for them.

## Verified current behavior

- `resolveBareNumericId(input, overdeckHome?)` (`src/lib/issue-id.ts`, line 143) returns the single matching issueId, or `null` for **both** zero matches and multiple matches. For non-digit input it returns `resolveIssueId(input)` (uppercased, `agent-` stripped) — never null.
- The dashboard resolves a conversation key with `resolveConversationKey` (`src/lib/overdeck/conversation-reads.ts`, line 698): digits → `getConversationById(Number(key))` (rowid), otherwise `getConversationByName(key) ?? getConversationByTmuxSession(key)`. The CLI resolver uses the same digits → rowid, else name rule.
- `getConversationById` / `getConversationByName` are synchronous (better-sqlite3) exports of `src/lib/overdeck/conversations.ts` (lines 613 and 620). That module imports `dashboard/server/event-store.js`, so `tell.ts` already loads it with a dynamic `await import('../../lib/overdeck/conversations.js')` (in `laneVerdictRefusal`). The new code follows that precedent.
- Dashboard URLs can carry query strings: `buildConversationUrl('123','terminal')` yields `/conv/123?view=terminal&views=123%3Aterminal` (`src/dashboard/frontend/src/App.test.tsx`, line 273). `/conv/20260523-1234` is also a valid route (same file, line 245).
- `scripts/lint-circular-deps.sh` (madge over `src/`) fails on new cycles. A module in `src/cli/` that nothing in `src/lib/` imports cannot close a cycle.

## Decisions

1. **New CLI-side module `src/cli/agent-target.ts`.** `src/lib/agents/identity.ts` stays untouched. It is an import-cycle leaf and must not import `conversations.ts`. The new module imports `resolveAgentTarget` and `isQualifiedAgentId` through the `../lib/agents.js` barrel (so existing `vi.mock('../../../lib/agents.js')` in command tests keeps intercepting) and loads `../lib/overdeck/conversations.js` with a dynamic `import()` only when the input is a conversation form or bare digits.
2. **The resolver returns a discriminated result and never collapses an issue into one agent.** `pan kill` fans an issue out to every agent dir (`findAgentIdsForIssue`), while tell/pause/unpause/untroubled collapse it with `resolveAgentTarget`. The resolver returns `kind: 'issue'` and lets each command decide.
3. **Bare number rule** (input matches `/^\d+$/`):
   - Issue candidates = `listBareNumericIssueMatches(input)` (new, see WI-1). Conversation candidate = `getConversationById(n)` when the row exists **and** `origin !== 'vault'`. Archived and ended conversations count.
   - 1 issue, no conversation → `issue`.
   - 0 issues, conversation → `agent` with the conversation agent ID.
   - (≥1 issue and a conversation) or (≥2 issues) → `ambiguous`, listing every candidate with its explicit form. Exit non-zero.
   - 0 issues, no conversation → `unresolved`.
   - Conversation rowids (~3000) overlap issue numbers, and state dirs persist after work ends, so ambiguity will be common. That is intended: the explicit forms (`PAN-2972`, `conv/2972`) always resolve.
4. **Explicit conversation forms** resolve only to a conversation. `<key>` digits → `getConversationById`; otherwise `getConversationByName(key)`. A missing row, or a vault row, is `unresolved` with reason `no conversation <key>` (vault: `conversation <key> is a Session Vault copy and has no live agent`). No fallback to issues.
5. **Order of checks:** explicit conversation form → qualified agent ID (`isQualifiedAgentId`, lowercased, unchanged) → bare digits (rule 3) → anything else is `issue` with `resolveIssueId(input)` (today's behavior).
6. **A conversation DB failure** (the dynamic import or query throws) is treated as "no conversation row". A bare number then falls back to issue-only behavior; an explicit form becomes `unresolved` with reason `conversation lookup failed: <message>`.
7. **One shared failure printer** writes to stderr, in red: the headline, then the accepted-forms list (FR-5). Commands then `return exitCli(1)` as today.
8. **Verbs in scope:** `tell`, `pause`, `unpause`, `untroubled`, `kill`/`stop`. `untroubled` is included because it carries the identical duplicated error text and resolver call. `inbox`, `monitor` and `recover` stay as they are (their `?? rawTarget` / `?? normalizeAgentId(id)` fallbacks have different semantics).
9. **Intervention skip line:** `appendTellInterventionForUserSource` returns silently when `normalizedId.startsWith('conv-')`, before the `console.debug`. All other IDs keep the existing `console.debug` line unchanged (asserted by `src/lib/__tests__/message-agent-interventions.test.ts`, line 177).

## Requirements

- **FR-1** `conv/<n>`, `conv:<n>`, and `http(s)://<host>[:port]/conv/<n>[/][?…][#…]` resolve to conversation `<n>`'s agent ID (`tmuxSession`). The same forms accept a conversation name instead of `<n>`.
- **FR-2** A bare number with exactly one issue agent candidate and no (non-vault) conversation resolves to the issue, exactly as today.
- **FR-3** A bare number with no issue agent candidate and an existing non-vault conversation resolves to that conversation's agent ID.
- **FR-4** A bare number with an issue candidate and a conversation, or with two or more issue candidates, prints every candidate with its explicit form and exits 1. Nothing is sent, paused, or killed.
- **FR-5** Every resolution failure prints the accepted target forms: issue ID (`PAN-1148`), agent ID (`agent-pan-1148`, `strike-pan-1723`, `conv-20260928-7563`), conversation (`conv/2972`, `conv:2972`, dashboard URL `https://overdeck.localhost/conv/2972`), and the bare-number rule.
- **FR-6** `pan tell`, `pan pause`, `pan unpause`, `pan untroubled` and `pan kill`/`pan stop` all resolve targets through the one shared resolver and print failures through the one shared printer.
- **FR-7** `pan kill` keeps its issue-wide fan-out for an `issue` result and kills exactly one agent for an `agent` result (including conversation targets).
- **FR-8** A `pan tell` to a `conv-*` agent prints no `Skipping tell intervention` line. Non-conv agents with no issueId keep the existing `console.debug` line.
- **NFR-1** `src/lib/agents/identity.ts` gains no new imports; `npm run lint:circular` reports no new cycle.
- **NFR-2** `conversations.ts` loads only through dynamic `import()` from the resolver, and only for conversation forms and bare digits.
- **NFR-3** No file grows past its `scripts/lint-file-size.sh` limit (1000-line ceiling; existing files may not grow past their `origin/main` count when already over it). None of the touched files is near the ceiling (`messaging.ts` 864, `kill.ts` 205, `tell.ts` 124, `issue-id.ts` 179).

### WI-1 — `listBareNumericIssueMatches` in `src/lib/issue-id.ts` (FR-2, FR-4)

Why: `resolveBareNumericId` returns `null` for both zero and multiple matches. The bare-number rule must tell them apart, or `pan tell 12` with `agent-pan-12` and `agent-min-12` on disk would silently pick conversation 12.

Steps:

```ts
/**
 * Every issueId whose agent state dir matches a bare numeric input (PAN-4465).

export function listBareNumericIssueMatches(input: string, overdeckHome?: string): string[] {
  if (!/^\d+$/.test(input)) return [];
  // …existing scan, collecting `matches`…
  return [...new Set(matches)];
}
```

2. Rewrite `resolveBareNumericId`'s digit branch as:

```ts
if (/^\d+$/.test(input)) {
  const matches = listBareNumericIssueMatches(input, overdeckHome);
```

### WI-2 — Shared resolver and failure printer `src/cli/agent-target.ts` (FR-1…FR-5, NFR-1, NFR-2)

Create the module:

```ts
export type AgentTargetCandidate = {
  /** What the operator would type to pick this one: `PAN-2972` or `conv/2972`. */
  explicitForm: string;
  /** One-line description: `issue PAN-2972` or `conversation 2972 "Fernkite deploy" (conv-20260928-7563)`. */
  label: string;
};

export type AgentTargetResolution =
  | { kind: 'agent'; agentId: string; via: 'agent-id' | 'conversation' }
  | { kind: 'issue'; issueId: string }
  | { kind: 'ambiguous'; input: string; candidates: AgentTargetCandidate[] }
  | { kind: 'unresolved'; input: string; reason: string };

export async function resolveCliAgentTarget(input: string): Promise<AgentTargetResolution>;

/** For tell/pause/unpause/untroubled: an `issue` result becomes resolveAgentTarget(issueId). */
export async function resolveCliSingleAgentId(input: string):
  Promise<{ ok: true; agentId: string } | { ok: false; failure: Exclude<AgentTargetResolution, { kind: 'agent' } | { kind: 'issue' }> }>;

/** Prints the failure headline, candidates (ambiguous), and ACCEPTED_TARGET_FORMS to stderr. */
export function printAgentTargetFailure(failure: …, verb: string): void;

export const ACCEPTED_TARGET_FORMS: readonly string[];
```

Parsing rules (in this order):
1. `CONV_URL = /^https?:\/\/[^/]+\/conv\/([^/?#]+)\/?(?:[?#].*)?$/i` → key = `decodeURIComponent(m[1])`.
2. `CONV_PREFIX = /^conv[/:](.+)$/i` → key = `m[1]`. (Does not match `conv-…`, which is an agent ID.)
3. For a key: `/^\d+$/` → `getConversationById(Number(key))`; else `getConversationByName(key)`. Row missing → `unresolved` (`no conversation <key>`); `row.origin === 'vault'` → `unresolved` (`conversation <key> is a Session Vault copy and has no live agent`); else `{ kind: 'agent', agentId: row.tmuxSession, via: 'conversation' }`.
4. `isQualifiedAgentId(input)` → `{ kind: 'agent', agentId: input.toLowerCase(), via: 'agent-id' }`.
5. `/^\d+$/` → Decision 3, with `listBareNumericIssueMatches(input)` and `getConversationById(Number(input))` (non-vault). Candidate labels: issue → `explicitForm: issueId`, `label: issue <issueId>`; conversation → `explicitForm: conv/<n>`, `label: conversation <n> "<title ?? name>" (<tmuxSession>)`.
6. Otherwise → `{ kind: 'issue', issueId: resolveIssueId(input) }` (import from `../lib/issue-id.js`).

`resolveCliSingleAgentId` maps `issue` → `resolveAgentTarget(issueId)`; a `null` there becomes `unresolved` with reason `no agent for <issueId>`.

```

Accepted targets:
  issue ID       PAN-1148 (a bare 1148 works when it is unambiguous)
```
