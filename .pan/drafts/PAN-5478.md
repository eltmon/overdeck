## Glossary

- **Verb**: a top-level `pan` command (`pan conv`, `pan plan`). **Subcommand**: a command under a verb
  (`pan conv search`). Both are listed under `Commands:` in `pan <verb> --help`.
- **Help text**: the output of `pan <verb> [subcommand] --help`. It is generated from the Commander
  definitions in `src/cli/index.ts` and `src/cli/commands/*.ts`.
- **Hidden option**: an option registered with `.hideHelp()` (for example `pan shutdown --finish`,
  `src/cli/commands/dashboard-lifecycle-commands.ts`, anchor `new Option('--finish').hideHelp()`). Hidden
  options are internal and are never documented.
- **Reference section**: one `## pan <verb>` section built from the template in Decision D-3.
- **Owning page**: the feature or configuration page that explains a verb's concepts (for example
  `features/planning.mdx` for `pan plan`). The CLI section links to it.
- **Mint check**: `npx -y mint@4.3.49 validate` and `npx -y mint@4.3.49 broken-links`, run from the
  workspace root. Always pin `mint@4.3.49` (the version PAN-5483 standardized on). Never run
  `mint validate --fix`: it rewrites about 80 files that sibling issues edit in parallel. On `main`,
  `validate` prints `success build passed` and about 54 pre-existing warnings.
- **Dash rule**: no em dash (U+2014) or en dash (U+2013) in any line this issue adds or edits, and none
  in the frontmatter `title` or `description` of any page this issue touches. In the three new pages and
  in `cli/core-commands.mdx` and `cli/overview.mdx`, none anywhere in the file (D-8).
- **Help scratch dir**: `$HOME/.overdeck/tmp/pan-5478-help/`. Never `/tmp` (a reboot clears it).

### Facts the help text does not state (read from source)

- **`pan answer` is not the answer to `pan ask`.** `pan answer <id>` captures a numbered choice menu that
  is on screen in an agent's terminal pane and prints it; `pan answer <id> <n>` selects option `n`
  (`src/cli/commands/answer.ts`, `answerCommand`). The id may be an issue id (it becomes `agent-<id>`), a
  session name with a role prefix (`agent-`, `planning-`, `strike-`, `review-`, `test-`, `ship-`,
  `inspect-`, `conv-`), or a named singleton session such as `flywheel-orchestrator`
  (`normalizeAnswerSessionId`). Errors it prints: menu gone, menu changed (run `pan answer` again), or
  delivery unconfirmed (answer in the terminal).
- **`pan ask`** is run by a work agent. It records a blocking decision in the issue's pipeline journal; the
  dashboard shows it under Needs you; the operator's answer arrives as a message in the agent's session.
  `--withdraw` closes the agent's open request (`src/cli/commands/ask.ts` header comment).
- **`pan resume <id>` resumes an issue's work agent**, not a conversation: it restarts the saved harness
  session of a stopped work agent, named by issue id or agent id (`src/cli/commands/resume.ts`;
  `src/lib/work-agent-lifecycle.ts`, `assertCanResumeSession(agentOrIssueId)`). A paused, troubled or
  session-less agent is refused with the lifecycle reason; with no saved session it suggests
  `pan start <id>`. `--compact` summarizes the saved session and starts a fresh one seeded with the
  summary. `--host` bypasses the workspace Docker stack-health gate; `--yes` confirms `--host` without a
  prompt. A dashboard conversation is resumed with `pan conv resume <name>` instead.
- **`pan staffing <id>`** is read-only. It resolves the work model and swarm policy from `config.yaml` and
  the project's `projects.yaml` entry; there are no `--model` or `--swarm` overrides; a one-off model is
  passed at spawn time with `pan start --model` (`src/cli/commands/staffing.ts` header).
- **`pan parked`** prints every issue in a parked orbit (operator gates, zombie sessions, idle-running
  agents), oldest first, with why it is parked and what would release it (`src/cli/commands/parked.ts`
  header).
- **`pan scope` help text is stale.** Its subcommand descriptions say "Move xBRIEF to proposed/" and
  similar. The code rewrites status fields in place and never moves a file (`features/planning.mdx`
  line 248 already says so; `src/lib/xbrief/lifecycle-io.ts`, `transitionIssueXBrief`). Document the code
  behavior and link the planning page.
- **`pan reload`** works only from an Overdeck source checkout. It resolves the primary repo root of the
  current directory, fetches `origin/main`, builds that commit into a new dashboard deployment, and
  restarts the dashboard only if the build succeeds. Uncommitted changes and a local `HEAD` that differs
  from `origin/main` are excluded (`src/cli/commands/reload.ts`, anchor `resolvePrimaryRepoRoot`;
  `src/lib/deploy/build-from-origin.ts`, anchor `only origin/main is being deployed`). If the repo root
  cannot be resolved it prints the error with `old dashboard left running` and exits 1. `--no-deacon`
  is refused. An npm install updates with `pan update`, not `pan reload`.
- **Restart approval.** Dashboard restarts, reloads and post-merge deploy restarts wait for operator
  approval so they cannot interrupt live work. `pan restart approve` releases everything waiting, the
  same as the dashboard banner's `Restart now` button. `pan restart --now` approves what is waiting and
  restarts immediately (`dashboard-lifecycle-commands.ts` comment above `.command('approve')`).
- **Restart hold** (PAN-5007, v0.74.0): `pan restart hold [--reason <text>] [--until <when>]` makes every
  `pan reload`, `pan restart` and restart approval refuse, from any conversation, until
  `pan restart release` or until `--until` (a duration such as `90m`, `2h`, `1d`, or an ISO time) expires.
  `pan restart hold --status` shows the current hold (`restart-hold.ts`).
- **`pan restart` scopes**: default dashboard only (CLIProxy and Traefik keep running); `--cliproxy`;
  `--traefik`; `--full` (equal to `pan down` then `pan up`). The current `## pan restart` section in
  `cli/core-commands.mdx` (anchor `Frees ports (3010, 3011)`) is wrong and is replaced.
- **`pan update`** checks npm for the latest `@overdeck/core`, installs it globally, runs an automatic
  sync, and tells you to restart the dashboard and running agents (`src/cli/commands/update.ts`).
  `--check` only reports; `--force` reinstalls on the latest version. On a permission error it suggests
  `sudo npm install -g @overdeck/core@latest`.
- **`pan backup` / `pan restore`**: `pan sync` backs up the synced skill and command directories before
  each sync and prunes old backups (`src/cli/commands/sync.ts`, anchor `backupBeforeSync`;
  `src/lib/backup.ts`). Backups live in `~/.overdeck/backups/` (`src/lib/paths.ts`, `BACKUPS_DIR`).
  `pan backup list [--json]`, `pan backup clean [--keep <count>]` (default 10), and
  `pan restore [timestamp]` (no timestamp: pick from the 10 newest) which restores into the Claude Code
  skill and command directories (`src/cli/commands/restore.ts`, anchor `Claude Code only`).
- **`pan handoff start <conv>`** sends the kickoff of a handoff created with `--hold`. It is parsed inside
  `handoff.ts` (anchor `convRef === 'start'`) and does not appear in help.
- **Ignored and deprecated flags**: `pan handoff --harness` and `--author-harness` are accepted and
  ignored; `pan plan --auto-start` is deprecated in favor of `pan start <id>`; `pan reload --no-deacon` is
  refused. Document each in the options table with that status.
- **Cost text and `$`**: `scripts/lint-docs.js` fails on `$` in prose (write `&#36;`) and on `<` before
  a digit (write `&lt;`). Code blocks and inline code are exempt.
