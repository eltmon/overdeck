# PAN-2450 — Project-overview pipeline section redesign

**Issue:** https://github.com/eltmon/overdeck/issues/2450 · **Mockup (BINDING):** `docs/design/mockups/project-overview-pipeline.html` · **Author:** oversight conversation, 2026-07-07.
**Verified-Against:** main @ HEAD (component refs checked at writing time).

## Glossary

- **Project overview**: the page at `/command-deck/<project>` — component `src/dashboard/frontend/src/components/CommandDeck/ProjectOverview.tsx` (1074 lines; already over budget — this work must NOT grow it; extract).
- **Pipeline section**: the stage-grouped list (Review / Work / …) below the stat strip, currently one row per AGENT with raw status badges.
- **Phase chip**: the cockpit's plain-language state pill (building / in review / testing / waiting on you / lining up to ship) with the established color language (blue/violet/teal/amber).
- **Needs-you**: any issue whose next step is a human decision (readyForMerge with UAT-hold, needs-you pause, plan approval).

## The four defects (operator screenshot 2026-07-07)

1. Badge/name overlap ("REVIEW RUNNINGagent-pan-2095") — the status badge is positioned over the agent label.
2. No issue titles — rows show only ids although `feature.title` exists in the component data (lines ~44/187/199/208).
3. Row-per-agent instead of row-per-issue.
4. Jargon badges, truncated costs ("$28.8"), meaningless avatar circles, no needs-you priority.

## Decisions

- **D1 — Extract, don't grow.** New `PipelineSection.tsx` (+ `PipelineRow.tsx`) under `src/dashboard/frontend/src/components/CommandDeck/`; ProjectOverview.tsx swaps its current stage-list markup for the new components and must END SMALLER than 1074 lines. File-size ratchet respected; add baselines for the new files only if >— keep each new file well under the ceiling (~250 lines target).
- **D2 — Row model = issue.** Group the existing per-agent feature data by issueId; the who-line summarizes crew: `<model> ×N + supervisor` (reuse `compactModelName` from the cockpit's CrewStage; do not duplicate — export it to a shared util if needed).
- **D3 — Phase derivation reuses the cockpit's logic.** Import/share `deriveNarrative`'s stage mapping (`src/dashboard/frontend/src/components/Stage/cockpit/StatusNarrative.tsx`) rather than re-deriving; the chip label/color mapping is one shared table.
- **D4 — Grid layout, no absolute positioning** for the row internals: `[88px id | 1fr title block | 200px phase block | 90px cost | 34px avatar]` per the mockup — overlap becomes structurally impossible.
- **D5 — Ordering**: Needs-you group pinned first (amber), then Building / In review / Testing / Lining up to ship, rows within a group by last activity desc.
- **D6 — Costs** from the existing per-issue costs query (`useIssueCostsQuery` family) — full precision `$X.XX` + `· N sessions`; no new rollup (two-door rule).

## Requirements

- FR-1: `PipelineSection` renders stage groups per D5 from the same data sources ProjectOverview already queries (features + reviewStatus + agents), grouped per D2.
- FR-2: `PipelineRow` per mockup grid (D4): id · title (ellipsized, always present) · subline (plain-language state sentence) · phase chip + who-line · cost · avatar (primary model initials, ring = phase color). Click → issue cockpit route.
- FR-3: Plain-language chips only — the strings `WORK RUNNING`, `REVIEW RUNNING`, and any raw status enum must not appear in the DOM.
- FR-4: Needs-you detection: readyForMerge=1, needs-you paused agents, or plan-approval pending → amber group at top.
- FR-5: Stat-strip cards become links (Active→pipeline section anchor, Spend→/costs, Agents→agents view). CI health card unchanged.
- NFR-1: No new fetches beyond what the page already makes (compose existing queries); render cost of the section ≤ previous implementation.
- NFR-2: Both themes verified by Playwright screenshots at 1280px and 1680px; no overlap, titles visible (the acceptance mechanism — judge the screenshots, iterate until clean, per the cockpit precedent).
