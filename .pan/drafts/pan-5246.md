## Glossary

- **Stage issue tab (the cockpit)** — the issue view inside the Command Deck's centre pane, route `/command-deck/:project/:issue`. Component `components/Stage/cockpit/IssueMissionControl.tsx`, mounted by `components/Stage/IssueOverview.tsx:126` (search `<IssueMissionControl`), which `components/CommandDeck/index.tsx:1519` renders through `renderIssue`.
- **Drawer** — the issue slide-over, `components/drawer/IssueDrawer.tsx`, 980px wide.
- **Shell** — the frame around the issue view. Two exist: the drawer (scrim, slide-over, close button) and the Stage tab (a pane beside the Command Deck issue tree). A shell owns routing and frame chrome and nothing else.
- **Shared view** — `IssueDetail` (`components/issue-detail/IssueDetail.tsx`): the pipeline strip, banner slot, tab strip and tab bodies. PAN-5244 and PAN-5253 built it for the drawer; this issue makes the Stage tab render it.
- **Density** — the `density` prop of `IssueDetail`: `drawer`, `page`, `rail`. The drawer passes `drawer`; the Stage tab passes `page`. Before this issue `IssueDetail` has three return paths: the `rail` branch, the **drawer branch** (`if (density === 'drawer')`), and the **legacy page return** below it (the `IssueDetailShell` header, a 360px status rail, a toolbar `<select>`). A second vocabulary exists on `IssueView`: `console`, `cockpit`, `rail` (`components/issue-view/inventory.ts:9`). The drawer is `IssueDetail` `drawer` inside `IssueView` `console`; the Stage tab is `IssueDetail` `page` inside `IssueView` `cockpit`.
- **Title row** — the one-row header: issue id, title, state badge, cost, action strip, tracker link. PAN-5244 wrote it inline in `IssueDrawer.tsx`; this issue extracts it.
- **Tab entry**, **view**, **tab value** — an entry is one button in the tab strip; a view is a sub-view inside an entry; a tab value is the single string that selects both (`tab` prop, `?tab=`). `resolveIssueTab` (`components/issue-detail/issueTabs.ts`, PAN-5253) maps a value to `{ entry, view, value }`.
- **Banner slot** — `components/issue-view/IssueBannerSlot.tsx` (PAN-5253): one slot under the strip showing the needs-you banner or the paused banner.
- **Crew spine** — the cockpit's left lane listing the issue's sessions: `IssueTreeLane.tsx` → `AgentsLane.tsx`. Removed by this issue.
- **Awareness rail** — the cockpit's right rail (Now, Run details, Gates, Cost, Environment, Recent activity), `IssueMissionControl.tsx:864`. Removed by this issue. Not the same thing as the **Awareness column**, the Command Deck's own right column (`components/CommandDeck/index.tsx:1538`, search `Awareness rail (PAN-1591)`), which is not touched.
- **Agent** — an entry of the dashboard store's `agentsById`. **Backend pane** — a terminal-backend pane in the issue workspace (`BackendPane`, `packages/contracts/src/backend-pane.ts`). A pane can exist without an agent record.
- **Section marker** — an HTML attribute `data-section="<name>"` on a visible element.
- **No-loss inventory** — `ISSUE_VIEW_INVENTORY` (`components/issue-view/inventory.ts:21`) plus `DENSITY_SECTIONS` (`components/issue-view/densitySections.ts:3`). A locked list of sections per view: 16 console, 21 cockpit, 15 rail. Rows are never deleted. **Home** is a row's `home` field: a file that must exist on disk.
- **Launch composition** — the launcher, agent dock, action dock ("Quick tools") and conversation timeline that `IssueOverview.tsx:98-136` builds and `MissionConversationTab.tsx:16` lays out.
- **Deft issue** — an issue running on the Deft pipeline (`useDeftIssueSummary(issueId).isDeft`).

## Decisions

Each decision is final for this issue.

- **D-1 The shared view is `IssueDetail`; `density="page"` becomes the same composition as `density="drawer"`.** No new `IssueViewBody` component: the import gate, the three frame tests and the existing composition all point at `IssueDetail` (see Background). The id `page` is kept. The legacy page return is deleted. `density="rail"` is not touched.
- **D-2 The title row is one component, rendered by each shell outside `IssueDetail`.** New `components/issue-view/IssueTitleRow.tsx`. Each shell keeps its own `<header data-section="Header bar">` element and passes shell-specific slots.
- **D-3 Stage tab state.** The tab value is local state in `IssueMissionControl`, read once from `?tab=` at mount and normalised through `resolveIssueTab`, never written to the URL (as today). `?agent=` is not read by the Stage tab (as today).
- **D-4 Default tab.** The Stage tab opens Conversation when no tab is named and when the value is unknown. The cockpit rule "Overview when the issue has no session" (`IssueMissionControl.tsx:422`) is removed: with no agent, the Conversation tab shows the start surface (PAN-5244).
- **D-5 The crew spine and the awareness rail leave the Stage issue tab.** Operator rationale: the Command Deck's issue tree (left) and Awareness column (right) already carry them. Their inventory rows stay; each gets a new visible home (see "Section map").
- **D-6 Stage-only title-row extras:** the breadcrumb `project / Issues /` and the "Open tracker" link. No branch chip, no PR chip and no cost card in the Stage title row: the branch is in the conversation meta row with a copy button (PAN-5253), the PR is the pinned "Open pull request" action, the cost is the shared cost chip.
- **D-7 The launch composition stays, Stage tab only,** as a block at the end of the Details tab, passed through a new `IssueDetail` prop. The mockup does not show it; dropping it would remove the Stage's quick tools (Files on the issue's explorer root, PAN-5186) and the issue's conversation launcher.
- **D-8 Two Details additions for both shells,** which the cockpit has and the shared view lacks: a visible next-step line under the status sentence (the cockpit's Now panel shows "Next: …", `IssueMissionControl.tsx:386-389`) and a "Create PR" compare link when the issue has no pull request (line 655).
- **D-9 Removed cockpit decorations.** The Changes check badge, the Plan task count and the Session live dot on the cockpit tab band are removed with the band. Their facts are in the strip's checks chip, the Tasks count chip and the strip's live pulse.
- **D-10 Tasks count.** The Stage frame passes no `tasksBadge`. `IssueDetail` reads the count itself when the prop is absent, so the frame imports nothing from the drawer's data module.
- **D-11 Inventory.** No row is added to or removed from `ISSUE_VIEW_INVENTORY` or `DENSITY_SECTIONS`; counts stay 16 / 21 / 15 / 52. Cockpit rows whose marker moves get a new `home`: the file that holds the literal marker. A shared element that carries a console name and a cockpit name uses nested wrappers, one literal attribute each, because an element has one `data-section` attribute and the root test needs each name as a literal. Two rules follow from how that test parses a tag (`issue-view-no-loss.test.ts:37` and `:211`), and they bind every cockpit marker this issue writes:
  1. Write `data-section="<name>"` as the **first** attribute of its tag. The test's pattern stops at the first `>` in a tag, so an arrow function (`=>`) in an earlier attribute hides the marker.
  2. The marker's tag must not contain the word `hidden` in any attribute, class names included (`overflow-hidden`, `hidden @[900px]:inline-flex`). The test reads that as a hidden marker. When the element needs such a class, put the marker on a wrapper `<div data-section="<name>" className="contents">` around it. A `contents` wrapper has no box, so the child keeps its layout.
- **D-12 Deletions are limited to what this issue orphans,** including the cockpit copies of the duplicated code. Files that were already unmounted before this issue are not touched. See "Files".
- **D-13 Protected code is not edited:** `components/IssueActionMenu/*`, `components/chat/ConversationPanel.tsx`, `components/CommandDeck/ProjectTree/*`, the Command Deck's Awareness column, `NeedsYouSlot.tsx`, `IssueDetailShell.tsx`, `Stage/IssueOverview.tsx`, `Stage/cockpit/MissionConversationTab.tsx`.

## Requirements

- **FR-1** Both shells render the same title row, pipeline strip, banner slot, tab strip and tab bodies from the same components: `IssueTitleRow` and `IssueDetail`.
- **FR-2** The Stage tab's tab strip is the drawer's: Conversation, Tasks, Plan, Changes, Activity, Discussion, Skills, Details, with Decisions before Discussion for a Deft issue.
- **FR-3** For every tab value in "Tab values", the Stage frame passes that value's canonical form to `IssueDetail`. With no `?tab=` or an unknown value it passes `conversation`.
- **FR-4** The Stage issue tab renders no crew spine, no awareness rail, no phase-cell rail, no cost dialog and no cockpit tab band. `IssueMissionControl.tsx` contains the frame only.
- **FR-5** The Stage title row shows the breadcrumb and the "Open tracker" link; the drawer title row shows the "Issue" link and the close button. Both show id, title, state badge, cost and the action strip with "Open pull request" pinned.
- **FR-6** The Stage Details tab ends with the launch composition (launcher, agent dock, quick tools, conversation timeline). The drawer does not render it.
- **FR-7** In both shells, Details › Status shows the next step as visible text, and Details › Ship shows a "Create PR" link when the issue has no pull request and its tracker is GitHub.
- **FR-8** The Tasks tab chip shows the task count when the shell passes no `tasksBadge`.
- **FR-9** Every name in `DENSITY_SECTIONS.cockpit` is rendered as a `data-section` on a visible element in the Stage issue tab, in the tab given by "Section map". Every name in `DENSITY_SECTIONS.console` stays rendered in the drawer.
- **FR-10** The Stage issue tab fills its pane: the title row, strip and tabs stay in place and the tab body scrolls inside the pane; the conversation composer stays at the bottom of the pane.
- **FR-11** On the Stage route, an issue with backend panes and no agent records shows one pipeline row per pane-backed phase with the pane's model, and those phases live in the strip.
- **FR-12** The cockpit copies of duplicated code are gone: no `CheckRunList`, `GitHubCiPanel` or `StackDrawer` under `components/Stage/`, and no `useCockpitNeedsYouActions.ts`.
- **NFR-1** No server change, no new endpoint, no new query hook, no new store field.
- **NFR-2** The Stage frame does not re-render when an agent of another issue changes (`IssueMissionControl.render-count.test.tsx` passes with only its mock list pruned). - **NFR-3** `lib/__tests__/conformance-gates.test.ts` passes unedited: no new importer of a path ending in `issue-detail/IssueDetail`, `drawer/DrawerAgentSession` or `IssueDetailShell`.
- **NFR-4** Layout that depends on width uses container queries, never viewport breakpoints. At a Stage pane width of 750px there is no horizontal page scroll.
- **NFR-5** `npm run lint` passes, including `lint:file-size`, `lint:circular`, `lint:source-introspection` and `lint:docs`. `IssueMissionControl.tsx` ends under 200 lines.
- **NFR-6** New markup follows the style guide rules restated in "Repo rules that apply".
- **NFR-7** The drawer's rendered output changes only by FR-7 and by the cockpit-named marker wrappers; its title row is the same elements in the same order.

export function githubCompareUrl(issueUrl: string | null, branch: string): string | null {
