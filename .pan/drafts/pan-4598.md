# PAN-4598: Restore UAT batch assembly and give ready rows a Merge button

**Issue:** [PAN-4598](https://github.com/eltmon/overdeck/issues/4598) · **PR:** #4603

This PRD was written after the implementation, from the issue body and the root-cause investigation, so the plan checklist matches the shipped work.

## Glossary

- **Merge train:** the per-project flow that gathers ready PRs into a UAT batch.
- **UAT batch / generation:** a `uat/<name>` branch that merges the ready features onto current main, stored as a `uat_generations` row with a status (`assembling`, `ready`, `superseded`, `invalidated`, `promoted`, `failed`).
- **Reconciler:** `reconcileUatGenerations` in `src/lib/cloister/uat-reconciler.ts`, run every 60 s by `startUatTrainReconciler` (`src/dashboard/server/services/uat-train.ts`).
- **Consecutive-failure cutoff:** the PAN-3963 rule that stops assembling after 3 failed generations in a row (`MAX_CONSECUTIVE_FAILED_ASSEMBLIES`).
- **Flywheel UAT card:** `FlywheelUatBatchesCard`, which renders `MergeTrainView` (`src/dashboard/frontend/src/components/merge-train/MergeTrainView.tsx`).

## Root cause

On 2026-09-20, generations `uat/pan-onyx-0920-4/5/6` failed on `FOREIGN KEY constraint failed` (the `issue_id → issues` key). #3972 (PAN-3963) dropped that key the same day, but it also added the cutoff. The cutoff counted trailing `failed` rows with no age bound. Those three rows stayed newest in the chain, so every tick since returned `assembly-blocked` (1481 `BLOCKED` log lines up to 2026-10-24). The only force lever (↻) renders next to a live batch, so the operator could not clear it from the page.

## Requirements

- **FR-1:** A failed generation older than `FAILED_STREAK_WINDOW_MS` (6 hours) does not count toward the cutoff. `force` still bypasses the cutoff.
- **FR-2:** `POST /api/merge-train/merge-next` accepts an optional `issueId`. It merges that ready feature, returns 409 when the ID is not in the project's ready set, and returns 400 when it is malformed.
- **FR-3:** While no tested batch exists, each ready row on the Flywheel UAT card has a **Merge** button that posts `{ n: 1, project, issueId }` after a confirm. When a batch exists, **Merge batch to main** stays primary and the escape hatch remains.
- **FR-4:** When the newest generation failed and no batch is live, the card names the failure and its time and offers **Retry batch assembly** (a forced assemble). The card never promises a batch it will not build.
- **FR-5:** `docs/MERGE-WORKFLOW.md` describes the batch flow, the per-row merge and the age-bounded cutoff.

## Acceptance criteria

- Reconciler tests: three old failures with a UAT-held lone feature → `assembled`. Three failures inside the window → `assembly-blocked`.
- Route tests: an `issueId` merges only that feature. One outside the ready set → 409.
- `MergeTrainView.test.tsx` covers:
  - the row buttons and their request body;
  - the failed-assembly copy;
  - the retry POST;
  - row buttons hidden once a batch exists.
- `docs/MERGE-WORKFLOW.md` contains the "Merging from the Flywheel UAT card" section.
