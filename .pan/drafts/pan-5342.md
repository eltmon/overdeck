# PAN-5342 — Safe shutdown: `pan shutdown` drains agents at a tool boundary

**Issue:** [eltmon/overdeck#5342](https://github.com/eltmon/overdeck/issues/5342). **Design source:** conversation `20261115-3842` (id 3908), "Safe Overdeck shutdown with status banner". References verified against `main` at `72edab6a96b` on 2026-11-15.

## 1. Glossary

- **Drain.** The shutdown sequence: close admissions, stop every session at a turn boundary, wait for server-side writers, verify, then stop the services.
- **Shutdown record.** The file `<OVERDECK_HOME>/shutdown.json`. While it exists, Overdeck is draining: launches are refused and the pre-tool hook denies new tool calls. It also lists every session the drain stopped. It is the only stored shutdown state.
- **Session.** A live pane in the terminal backend that runs a harness: a pipeline agent (`agent-*`, `planning-*`, review, test and so on) or a conversation (`conv-<name>`).
- **Turn boundary.** The session's runtime snapshot `activity` is `idle`, `waiting` or `stopped`, and its transcript has not been written since that label was set. The harness has ended its turn, so no foreground tool call is in flight. See D-4.
- **Straggler.** A session or writer still pending when the deadline passes.
- **Server-side writer.** Work the dashboard process does itself that must not be cut off: an auto-merge row in `merging`, a post-merge lifecycle run, or a detached verification worker.
- **Final stage.** The detached process `pan shutdown --finish`. It stops the supervisor, the dashboard and the sidecars, then reboots when asked.
- **Resume offer.** The PAN-5091 Needs-you row (`BackendRestartCard`) with its Resume all and Dismiss buttons.
- **Reboot guard.** A logind block inhibitor that the dashboard holds while at least one session is mid-turn (working), and throughout a drain.
- FE means `src/dashboard/frontend/src`.

## 3. Decisions

- **D-1 One store: a file.** The drain flag is the shutdown record file, not `app_settings`. The bash hook must check it before every tool call with no network and no `sqlite3` binary, and every process (CLI, dashboard, deacon child) can stat a file. The file has no expiry. While it exists every launch is refused, so no new session can meet the deny. A leftover record after a crash or reboot is consumed by the next dashboard boot (D-10).
- **D-2 Admission chokepoints.**
  - `launchAgentPane` and `pan spawn` refuse every pane launch.
  - The conversation create, resume and message doors return a clean 409 before they reach the launch.
  - `isDeaconGloballyPaused()` returns true while the record exists. That freezes Deacon and every patrol with no flag to write or restore.
  - The auto-merge tick, the merge-train reconcile, the backlog sequencer trigger and `pan reload` refuse explicitly.
  - Agent messaging (`messageAgent`) is **not** gated. A message to a live agent starts a turn whose tools are all denied, so it writes nothing. A message to an agent the drain already stopped queues through the existing `stopped-by-user` gate.
- **D-3 Tool-boundary deny.** While the record exists, `pre-tool-hook` prints a deny for every tool call of a managed session, after `pan_resolve_agent_id` succeeds. Unmanaged Claude Code sessions are untouched. The in-flight call is not affected.
- **D-4 Stop rule.** A session is stopped on the first drain tick that sees it at a turn boundary. The rule is the same for every harness.
  - **The test.** `activity` must be `idle`, `waiting` or `stopped`, **and** the transcript heartbeat (`getTranscriptHeartbeatMs`, `liveness.ts:75`) must be null or no more than 5 s newer than the snapshot's `lastActivity`. The second check catches a stale `idle` label: a PreToolUse event that was buffered because the dashboard did not answer leaves the label at `idle` while the transcript already shows the new tool call.
  - **Why not watch the deny.** Seeing a deny is not enough. With parallel tool calls, one call is denied while a sibling still runs.
  - **No idle signal.** A harness that sends no idle signal, or a session with no runtime snapshot, stays pending as `unknown` and becomes a named straggler. That is safe. The read model seeds runtime snapshots at boot from the durable runtime history (`read-model.ts:513-514`), so `unknown` is rare. Checkpoint 4 measures it.
  - **Where it lives.** The predicate is in `src/lib/agents/liveness.ts`, the one liveness and idleness module. It answers a different question from `isIdle`: "has the turn ended" rather than "has work been stale for minutes".
  - **Known limit.** Background shells (`run_in_background`) and background subagents survive the end of a turn and die with the pane. The banner's docs say so.
- **D-5 Who runs what.**
  - The runtime mirror exists only in the dashboard process, so the drain runs as a dashboard service. It owns the phases, the stops, the banner snapshot and the verification.
  - Teardown runs in the final stage, a detached `systemd-run --user` unit (on macOS a detached spawn), because it stops the dashboard.
  - The final stage stops the supervisor before the dashboard, or the supervisor's watchdog would restart it. It reuses the `pan down` body.
- **D-6 Dashboard down.** `pan shutdown` refuses when the dashboard does not answer. It prints `The dashboard is not running. Start it with \`pan up\`, then run \`pan shutdown\`.` and exits 1. There is no offline drain.
- **D-7 Not stopped.** The Herdr server, the `tmux -L overdeck` server and workspace Docker stacks are left running. Once every session pane is closed they hold no Overdeck work. `herdr-setup/service.ts:12` states that nothing stops the Herdr server, and dockerd stops its containers itself at system shutdown.
- **D-8 Deadline and force.**
  - The deadline defaults to 120 s. `--deadline <seconds>` sets it, from 10 to 3600.
  - Without force, the drain keeps waiting past the deadline. It marks itself `overdue` and lists the stragglers with their tool and its description.
  - `--force` sets `force: 'at-deadline'`: at the deadline the drain force-stops the pending sessions and stops waiting for writers.
  - Force all (banner) or `pan shutdown --force` on a running drain sets `force: 'now'`.
  - Force never kills a writer. The drain only stops waiting for it, and the final stage's dashboard exit ends it. Boot already requeues orphaned `merging` rows (`requeueOrphanedMergingAutoMerges`, `merge-sync.ts:185`), and verification workers are re-adopted at boot.
- **D-9 Stop cause and resume set.**
  - Agents are stopped with `stopAgent(id, 'operator')`, so `stoppedByUser` blocks autonomous resume after boot. No new stop cause is added: the record already lists what the drain stopped.
  - Conversations are stopped with `handleConversationStop`.
  - The resume offer lists every agent the drain stopped, plus the conversations that were mid-turn at drain start (`wasWorking`). Idle conversations are not offered. They resume when the operator opens them.
- **D-10 One end path.** Cancel (in the same process) and dashboard boot (after a reboot, a `pan up` or a crash mid-drain) run the same `endShutdown(record)`. It deletes the record and seeds the resume offer. A drain interrupted by a dashboard restart therefore ends as a cancel.
- **D-11 Reload in flight.** `POST /api/shutdown` answers 409 while `readRestartLockHolder()` returns a holder: `A pan reload or pan restart is in progress (pid N). Wait for it to finish, then shut down.` During the drain, `pan reload` refuses to start.
- **D-12 Final screen without a close code.** The frontend keeps the last shutdown snapshot. When `phase === 'complete'`, the banner shows "Overdeck is shut down. It is safe to reboot." (or "Rebooting…"), and `AppChrome` hides `DegradedModeBanner`, so the reconnect loop never shows. No WebSocket close code is added.
- **D-13 Reboot guard host.** The dashboard holds the inhibitor, because the supervisor knows nothing about agents. The child is `systemd-inhibit --what=shutdown --mode=block --who=Overdeck --why=<text> cat`, with stdin piped. When the dashboard dies, the pipe closes, `cat` exits and the lock is released, so a stale lock is impossible. The text is `Overdeck has N agents running. Use Shut down Overdeck first.`, where N counts sessions that are mid-turn (not at a turn boundary, WI-3); live idle sessions do not count. The drain releases the guard when it enters `complete`.
- **D-14 Clean-shutdown marker.** Delete `setLastCleanShutdownAt`, `DASHBOARD_LAST_CLEAN_SHUTDOWN_AT_KEY`, the `main.ts` write and its test. This frees the `main.ts` lines that WI-7 needs.
- **D-15 Invoked from a session.** When `OVERDECK_AGENT_ID` or `OVERDECK_CONVERSATION` is set, `pan shutdown` starts the drain, prints one line and exits 0. If it waited, its own Bash call would stay in flight and the session would never reach a turn boundary.
- **D-16 Palette fix.** The palette's `emergency-stop` entry calls `triggerEmergencyStop()`, which opens the existing confirm, instead of the nonexistent route.

## 4. Requirements

- **FR-1** While the shutdown record exists, every pane launch, conversation create, resume and message, Deacon patrol, auto-merge tick, merge-train reconcile, backlog sequencer pass and `pan reload` is refused, each with a message that names `pan shutdown`.
- **FR-2** While the record exists, a managed Claude Code session's next tool call is denied with an instruction to end its turn. The call already in flight completes.
- **FR-3** The drain stops each session at a turn boundary (D-4), and stops nothing mid-turn without force (D-8).
- **FR-4** After all sessions stop, the drain waits for server-side writers, verifies, and reports `complete` with any warnings (leftover panes, `index.lock`, a half-done rebase or merge).
- **FR-5** At the deadline, the stragglers are listed by name with their tool and description. Nothing is killed unless force is set.
- **FR-6** The final stage stops the supervisor, the dashboard, Traefik, CLIProxy and smee. With `--reboot` it runs `systemctl reboot` on Linux.
- **FR-7** Every dashboard page shows a status banner: the phase, the time left, the pending sessions with their in-flight tool and its age, the pending writers, and a collapsed stopped count. It has Force stop per row, Force all, and Cancel shutdown.
- **FR-8** "Shut down Overdeck…" is in the agents menu under "Stop all agents…", both with sub-lines; in the health popover's System controls; and in the command palette, which matches shutdown, shut down, reboot, power off and quit. There is no hotkey and no left-column entry.
- **FR-9** A confirmation dialog lists what stops, shows the deadline, and has a "Reboot when done" checkbox.
- **FR-10** After boot or a cancel, the resume offer lists the sessions from D-9 as "Resume the N sessions shutdown stopped". Nothing resumes on its own.
- **FR-11** While at least one session is mid-turn on Linux (not merely live: an idle conversation or agent waiting at a prompt does not count), a logind block inhibitor carries the text `Overdeck has N agents running. Use Shut down Overdeck first.`, where N counts mid-turn sessions. Idle sessions alone never hold it, so an ordinary reboot with only idle sessions is not blocked.
- **NFR-1** Dashboard-reachable code uses async `execFile`/`spawn` only, never `execSync`. Terminal access goes through the async terminal-backend primitives.
- **NFR-2** No test runs a real drain, final stage, `systemd-inhibit` or reboot. All of them run through injected deps.
- **NFR-3** No file in `src` grows past its file-size cap (`scripts/lint-file-size.sh`).

## 5. Repo rules that apply (restated)

- **Quality gates.** Run `npm run typecheck`, `npm run lint`, and `npx vitest run <the test files you touched>`. Never run the full `npm test` on the host.
- **No `execSync`.** Do not use `execSync`/`spawnSync` in any code the dashboard server can reach. Use promisified `execFile` with a timeout. Terminal actions go through `terminal-backends/*` Effect/async primitives only.

   /** PAN-5342 (D-4): the turn ended (idle, waiting on a human, or stopped) and the transcript has not moved since. Null snapshot ⇒ unknown ⇒ false. */
   export const TURN_BOUNDARY_TRANSCRIPT_SLACK_MS = 5_000;
   export function isAtTurnBoundary(snapshot: Pick<AgentRuntimeSnapshot, 'activity' | 'lastActivity'> | null, transcriptHeartbeatMs: number | null): boolean {
     if (!snapshot || !(snapshot.activity === 'idle' || snapshot.activity === 'waiting' || snapshot.activity === 'stopped')) return false;
     const labelMs = Date.parse(snapshot.lastActivity);
     return transcriptHeartbeatMs === null || !Number.isFinite(labelMs) || transcriptHeartbeatMs <= labelMs + TURN_BOUNDARY_TRANSCRIPT_SLACK_MS;
   }
   /** In-process (dashboard) reader for the drain. */
