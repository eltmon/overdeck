# PAN-4438 — Restore the operator test-removal waiver: an untracked workspace store, a CLI verb, and a dashboard control

**Issue:** [PAN-4438](https://github.com/eltmon/overdeck/issues/4438)
**First consumer:** PAN-4429 (PR #4431, removes TLDR code and its tests; operator-approved)
**Planned against:** `main` at `76fba679f85` (2026-09-30)

## Glossary

- **Test-skip gate** — the required `test-skip` verification gate (`src/lib/cloister/test-skip-gate.ts`). It fails a diff that adds `.skip`/`.only`/`xit`/`xdescribe`/`xtest`, or removes more `it(`/`test(` calls across the whole diff than it adds.
- **`removed-test` violation** — the gate's net-removal violation kind. It is the only kind a waiver may demote. `skip` and `only` are never waivable.
- **Head anchor** — the string `snapshotWorkspaceHeads(issueId, workspacePath)` returns (`src/lib/git-utils.ts:391`). Monorepo: one 40-char sha. Polyrepo: space-joined `repoKey@sha` tokens. It returns `undefined` for a degraded polyrepo or unreadable roots.
- **Waiver** — an operator's judgment "these tests are gone and nothing replaces them", pinned to exactly one head anchor. Shape: `TestSkipWaiver { sha, reason, at, by? }` (`src/lib/cloister/test-skip-waiver.ts:17`). `sha` holds the head anchor.
- **Waiver store** — the new untracked file `<workspace>/.overdeck/test-removal-waiver.json`. One waiver per workspace; a new grant overwrites the old one.
- **Grant** — writing a waiver through one of the two doors below. Both doors call one lib function, `grantTestSkipWaiver`.
- **Door** — an entry point that writes the waiver: the CLI verb `pan review waive-test-removal`, or the dashboard route `POST /api/issues/:id/test-removal-waiver`.
- **Operator caller** — a process `verdictCallerFromEnv()` (`src/lib/cloister/verdict-caller.ts:76`) classifies as `{ kind: 'operator' }`: a plain shell with no `OVERDECK_AGENT_ID`, or a `conv-*` operator conversation. Every other id (`agent-*`, `planning-*`, `flywheel-*`, …) is `{ kind: 'agent' }`.
- **Re-run door** — `pan review request <id>` (or the dashboard Request review action), which POSTs `/api/review/:issueId/request` and, through `requestReviewGuarded` → `startRequestReviewPipeline`, re-runs verification on the current head.

## Problem

The test-skip gate honors a waiver only when it covers the exact head under verification. Since the Cut, no waiver can be granted that the gate honors.

1. **The writer was deleted.** `pan verify waive-test-removal` (`src/cli/commands/verify-waiver.ts`) was removed in `a1def1f8959` (PAN-3917 W9). `docs/PIPELINE-GATES.md:162` and the headers of `test-skip-waiver.ts:6` and `test-skip-gate.ts:19` still tell operators to run it.
2. **The read location deadlocks.** `resolveActiveTestSkipWaiver` (`test-skip-waiver.ts:41`) reads a `D-test-removal-waived:<anchor>` decision from the continue file through `readContinueStateForIssue`, which reads the **workspace** continue file first. That file (`.pan/continues/<ISSUE>.xbrief.json`) is tracked on the feature branch. Writing the decision there dirties the tree, and `POST /api/review/:issueId/request` refuses a dirty tree. Committing it moves HEAD, so the waiver is pinned to the previous sha. No sequence works.

PAN-4429 is blocked on this right now.

## Decisions (made here, not left to the executor)

- **D-1 Store location.** The waiver lives at `<workspace>/.overdeck/test-removal-waiver.json`. This follows the operator's design note on the issue ("an untracked workspace verification artifact … not in the tracked continue file"). It is a sibling of `.overdeck/verification/`, **not inside it**, because that directory is enumerated as run artifacts: `readRunArtifacts` (`src/lib/cloister/verification-cycles.ts:88`) parses every `.json` there as a `VerificationArtifact`, and `pruneVerificationRunArtifacts` (`src/lib/cloister/verification-artifact.ts:139`) deletes every `.json` older than 30 days.
- **D-2 Why an untracked file removes the deadlock.** The review-request dirty check runs `git status --porcelain -uno` (`src/dashboard/server/routes/workspaces/review-pipeline.ts:167`), which ignores untracked files. The `pan done` preflight drops `.overdeck/` paths (`filterUncommittedPorcelainLines`, `src/lib/work/done-preflight.ts:57`, via `isOverdeckWorkspaceRuntimePath`, `src/lib/state-plane.ts:77`). Writing the file never moves HEAD.
- **D-3 Gitignore.** The overdeck repo ignores `.overdeck/` runtime files by named entry (`.gitignore:242-263`), and `.overdeck/context/codebase/` is tracked. Add the line `.overdeck/test-removal-waiver.json*` next to `.overdeck/verification/` (`.gitignore:251`) so `git add -A` in an overdeck workspace never commits it. Other projects need no change: their workspace `.overdeck/` runtime files are already untracked and filtered the same way.
- **D-4 The continue-file path is deleted, not kept as a fallback.** `resolveActiveTestSkipWaiver` stops reading `D-test-removal-waived:` decisions. The issue allows "before (or instead of)"; deleting is simpler, and it removes a location a work agent can write through ordinary plan tooling. No live waiver exists there today (the deadlock made it impossible), so nothing is lost.
- **D-5 Verb name and group.** `pan review waive-test-removal <id> --reason "<text>"`, registered in `src/cli/commands/review-subcommands.ts`. `pan review` is the current verb group for the review/verification loop (`request`, `abort`, `restart`). The `pan verify` group no longer exists and is not revived.
- **D-6 Operator-only, CLI.** The CLI handler calls `verdictCallerFromEnv()` and refuses any `{ kind: 'agent' }` caller with exit code 1, before any file read or write. This refuses work, review, test, merge, planning **and** `flywheel-*` callers, which matches the deleted verb's "operator-conversation-only (conv-*)" bar. `by` is `caller.id ?? 'operator'`.
- **D-7 Operator-only, dashboard.** The POST route calls `validateOrigin(request)` (`src/dashboard/server/routes/origin-validation.ts:147`) first and returns 403 on failure. A bare `curl` POST with no `Origin`/`Referer` gets 403 `Missing origin`. This is the same bar as other dashboard mutations (`src/dashboard/server/routes/lanes.ts:72`). `by` is the literal `'dashboard'`.
- **D-8 Head pin, dashboard.** `GET` returns the current head anchor. `POST` must carry the `head` the operator saw. If it differs from the anchor computed at write time, the route returns 409 and writes nothing, so the operator never pins a head they did not see. The CLI has no such argument: it pins the anchor it computes and prints it.
- **D-9 One writer, two doors.** Both doors call `grantTestSkipWaiver` in `src/lib/cloister/test-skip-waiver.ts`. The CLI does not go through HTTP.
- **D-10 Re-running verification is a separate action.** Granting does not start verification. The CLI prints `Run pan review request <ISSUE> to re-run verification.`; the dashboard control shows the same hint. No new re-run button.
- **D-11 Local workspaces only.** A remote (Fly) workspace or a missing workspace directory is refused with a message. Remote verification is out of scope.
- **D-12 Forgery is documented, not solved.** A work agent has filesystem write access to its own workspace and could create the file directly. That is the same limit `verdict-caller.ts` already states for review verdicts. The gate evidence line prints `by` and `at`, so a forged waiver is visible to review. `docs/PIPELINE-GATES.md` states the limit in one sentence. No signing.

## Requirements

- **FR-1** The gate reads the waiver only from `<workspace>/.overdeck/test-removal-waiver.json`, and applies it only when its `sha` equals the head anchor under verification (trimmed, exact equality — `waiverCoversHead`, unchanged).
- **FR-2** A waiver still waives `removed-test` only; an added `.skip`/`.only` still fails the gate with a waiver present.
- **FR-3** `pan review waive-test-removal <id> --reason "<text>"` grants a waiver pinned to the workspace's current head anchor and prints the anchor (full, and short via `formatAnchorShort`).
- **FR-4** `--reason` is required; an empty or whitespace-only reason is refused with exit code 1 and nothing is written.
- **FR-5** The CLI verb refuses every agent caller (per `verdictCallerFromEnv`) with exit code 1 and writes nothing.
- **FR-6** `GET /api/issues/:id/test-removal-waiver` returns `{ issueId, head, headShort, waiver, active }`.
- **FR-7** `POST /api/issues/:id/test-removal-waiver` with `{ reason, head }` grants the waiver (201), refuses a missing/invalid Origin (403), an empty reason (400), a missing workspace (404), a remote workspace (409), an unreadable head (409), and a `head` that differs from the current anchor (409).
- **FR-8** The dashboard Test/Lint verification panel shows a waiver control when the `test-skip` gate failed: the head it will pin to, a required reason, and a Grant button.
- **FR-9** Re-running verification after a grant, with no commit, turns the `test-skip` gate green and its evidence contains the line `waiver: removed tests waived by <by> at <at> for <short anchor> — <reason>`.
- **FR-10** Docs describe the verb, the dashboard control, the store path, and the forgery limit.
- **NFR-1** Granting never modifies a tracked file and never moves HEAD.
- **NFR-2** `src/lib/cloister/verification-runner.ts` is at its file-size cap (961 lines, `scripts/file-size-allowlist.txt:158`). The change to it is a same-line edit with zero net lines.
- **NFR-3** No `execSync` in dashboard-reachable code; the route uses the async `snapshotWorkspaceHeads`.
