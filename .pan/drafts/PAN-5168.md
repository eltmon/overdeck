# PAN-5168 — Optional host tools: resolve once, skip missing tools, back off after ENOENT

**Issue:** [PAN-5168](https://github.com/eltmon/overdeck/issues/5168) — macOS: pollers that run missing binaries create ~10 dead processes per call (spawn storm, up to ~60/s).
**Siblings (fixed in parallel, do not overlap):** [PAN-5169](https://github.com/eltmon/overdeck/issues/5169) owns the herdr routing of the conversation pane reads (`capturePane`, `readConversationInputTarget`, `conversationNeedsTerminal`) and `ensureHostTools` in `src/lib/prereqs/registry.ts`. [PAN-5170](https://github.com/eltmon/overdeck/issues/5170) owns the Linux-only platform guards in `src/lib/systemd.ts` and `src/lib/cloister/memory-pressure-patrol.ts`. PAN-5168 owns the one shared host-tool module that both siblings may adopt later. Do not add a second tool cache anywhere.

## Glossary

- **Host tool** — an external binary Overdeck runs but does not ship: `docker`, `tmux`, `systemctl`, `journalctl`, `brew`. Typed as `HostToolName` in the new module.
- **PATH lookup** — searching each `PATH` directory for an executable file with `stat`/`access` calls only. It spawns no process. The existing primitive is `findExecutableOnPath(name, pathEnv)` in `src/lib/pan-cli-shim.ts` (grep anchor: `export function findExecutableOnPath(`).
- **Failed spawn** — `child_process.spawn`/`execFile` (or Effect's `ChildProcess.make`) of a bare command name that is not on `PATH`. On macOS, libuv calls `posix_spawn` once per `PATH` entry, and XNU creates a short-lived process for each try. One failed call leaves about 8–12 dead processes on a 12-entry `PATH`.
- **Poller** — code that runs a host tool on a timer or on every read-model refresh. In scope: the docker stats collector (every 5 s, two instances), resource discovery's `docker ps`, the stack-health lifecycle snapshot, the runtime census's `tmux list-panes` (3 s TTL), and the conversation-liveness tmux fallback (once per conversation per conversation-list poll).
- **Spawn ENOENT** — the error a failed spawn produces. Node: `err.code === 'ENOENT'` with `err.syscall === 'spawn <cmd>'`. Effect (`@effect/platform-node-shared` `NodeChildProcessSpawner`): a `PlatformError` whose `reason._tag === 'NotFound'` and `reason.cause.code === 'ENOENT'`. Wrapped errors such as `TmuxError` keep the original under `.cause`.
- **Re-check interval** — `HOST_TOOL_MISSING_RECHECK_MS = 60_000`. A tool recorded as missing is looked up again (PATH lookup, no spawn) at most once per interval.

## Problem

On a herdr-only Mac with no Docker and no tmux, an idle dashboard created 13–20 `node` processes per second, rising to about 60/s with many conversations. Verified call sites in this checkout:

1. `src/lib/docker-stats.ts` — `runDockerForOutput` (grep anchor: `ChildProcess.make('docker', [...args]`) spawns `docker stats --no-stream` and `docker ps -a` on every `collect()` tick (`Schedule.fixed(Duration.millis(intervalMs))`, default 5000 ms). Two singleton collectors run: `src/dashboard/server/routes/resources/shared.ts` (`getDockerStatsCollector`) and `src/dashboard/server/services/system-health-service.ts` (`function getDockerStatsCollector()`). That is 4 failed spawns per 5 s, roughly 8 dead processes per second.
2. `src/dashboard/server/services/resource-discovery-shared.ts` — `loadDockerContainers()` (grep anchor: `execFileAsync('docker', ['ps', '--format', '{{.Names}}']`) runs on every `captureSharedResourceSignals()`, which the project resource refresh queue calls repeatedly.
3. `src/lib/workspace/stack-health.ts` — `collectDockerContainerLifecycleSnapshot` (grep anchor: `execFileAsync('docker', ['ps', '-a', '--format', '{{json .}}']`) runs on each workspace stack-health batch request (`src/dashboard/server/routes/workspaces/workspace-data.ts`, `getWorkspaceStackHealthBatchRoute`).
4. `src/lib/runtime-census.ts` — the default `runtimeCensusService.listPanes` (grep anchor: `const { listAllPaneRecords } = await import('./tmux.js');`) runs `tmux -u list-panes -a` at most every `RUNTIME_CENSUS_TTL_MS = 3_000`, also under the herdr backend.

5. `src/lib/overdeck/conversation-liveness.ts` — under herdr, `conversationSessionAlive`/`conversationHarnessAlive` fall back to tmux when the Herdr probe answers `absent` (legacy tmux conversations), and `listLiveConversationSessions` always adds `tmuxSessionNames(deps)`. The default helpers `tmuxSessionExists`, `tmuxSessionNames` and `tmuxHarnessAlive` (grep anchor: `return Effect.runPromise(sessionExists(name)).catch(() => false);`) spawn tmux once per conversation per poll.

Every spawn above uses a bare command name and retries at the same interval forever when the tool is missing.

Not in scope, verified: the deacon hygiene patrols (`src/lib/cloister/hygiene-scheduler.ts`: `IDLE_STACK_INTERVAL_MS = 60_000`, `BRIDGE_POOL_INTERVAL_MS = 60_000`) run `docker` through `exec` (a shell). The shell does the PATH search inside one process, so each call costs about one process per minute, not one per PATH entry.

## Approach

Add one small, synchronous module, `src/lib/host-tools.ts`, that answers "where is this host tool?" with a cached PATH lookup, and records a missing tool so callers skip it without spawning. Pollers ask the module before they spawn, skip the tick when the tool is missing, and pass any spawn error back to the module so a tool that vanished is marked missing (the ENOENT back-off). Docker pollers spawn the resolved absolute path, which also removes libuv's per-PATH-entry failed tries when Docker is present.

### Decisions (made here, not left to the executor)

- **D1 — Build on `findExecutableOnPath`.** Do not use `resolveExecutableDetailed` in `src/lib/harness-binary.ts`: on a miss it spawns `npm prefix -g` and a login shell, which is the cost this issue removes. A PATH-only lookup also matches what libuv's spawn would find.
- **D2 — Cache semantics.** A found tool stays cached until `refreshHostTools()` runs or a spawn ENOENT is reported and a fresh lookup no longer finds it. A missing tool is cached as `null` and looked up again (no spawn) once `HOST_TOOL_MISSING_RECHECK_MS` (60 s) has passed. This fixed interval is the back-off: after an ENOENT, a poller skips the tool until a PATH lookup finds it again. There is no exponential schedule, because a PATH lookup costs a few `stat` calls.
- **D3 — The cache key includes the `PATH` value.** If `process.env.PATH` changes, the entry is stale and the module looks the tool up again.
- **D4 — An ENOENT marks a tool missing only when a fresh lookup also misses.** Node reports a missing `cwd` as `spawn <cmd> ENOENT` too. Marking the tool missing on that error would wrongly suppress a tool that exists.
- **D5 — Per-process cache, no new HTTP route.** The dashboard server, the deacon child, and the `pan doctor` CLI are separate processes. A doctor run re-checks by doing its own fresh lookup through the same module and printing the result. The dashboard re-checks on its own (D2) and on every settings save (D6). No route is added, so there are no `route-scopes.ts` or no-loss-matrix changes.
- **D6 — Settings-save re-check.** `PUT /api/settings` (`src/dashboard/server/routes/settings.ts`, `putSettingsRoute`) calls `refreshHostTools()` through a new helper. `settings.ts` is at its file-size cap (1104/1104), so the route's three post-save calls move into that helper and the route file shrinks.
- **D7 — Gate in the pollers, not in shared exec helpers.** Do not add a gate to `tmuxExecAsync` (`src/lib/tmux.ts`, at cap 1167/1167, and also used by launch paths) or to `systemctl()` in `src/lib/systemd.ts` (PAN-5170's file). The tmux gates go into the runtime census's default `listPanes` and into the three default tmux helpers in `conversation-liveness.ts`. A missing tmux then behaves exactly as today (the census receives a rejected `listPanes`; liveness reads answer "no tmux session"), but nothing spawns.
- **D8 — Test seam.** Production code never branches on test state except through one env var, `OVERDECK_TEST_ASSUME_HOST_TOOLS=1`. When it is set, a lookup with no injected finder returns the bare tool name (as if found), so existing tests that mock `child_process` for `docker`/`tmux` behave as before on CI runners without those tools. `tests/setup.ts` only sets the variable (next to `process.env.OVERDECK_TERMINAL_BACKEND ??= 'tmux';`). It does NOT import `src/` code: no setup file imports `src/` today, and a static import would load `pan-cli-shim` → `paths` before each test file's `vi.mock` calls. Under the env var a mocked ENOENT can never mark a tool missing (the re-lookup returns the bare name), so no test pollutes another. Tests that need a missing tool call `setHostToolFinderForTests(() => null)` and call `resetHostToolsForTests()` in their own `afterEach`. `setHostToolFinderForTests` also clears the cache, so a path cached earlier in the test cannot hide the new finder. An env var survives `vi.resetModules()`; module state does not.
- **D9 — Lookup precedence:** an explicit `deps.find` argument wins, then `setHostToolFinderForTests`, then `OVERDECK_TEST_ASSUME_HOST_TOOLS`, then the real `findExecutableOnPath(name, process.env.PATH)`.
- **D10 — Keep tmux spawned by bare name.** The census gate only decides whether to spawn. Switching tmux to absolute paths is out of scope, because many other tmux command lines (`pty.spawn`, Herdr) use the bare name.
- **D11 — Module shape.** Plain synchronous functions with no Effect wrapper (the `lint:effect-facades` ratchet). The module must import only `./pan-cli-shim.js` and Node built-ins, so `lint:circular` stays green.

## Requirements

- **FR-1** — `src/lib/host-tools.ts` exports `resolveHostTool(name, deps?)`, which returns an absolute path or `null` from a cached PATH lookup that never spawns a process.
- **FR-2** — A missing tool is looked up again only after `HOST_TOOL_MISSING_RECHECK_MS` (60 000 ms). Before that, `resolveHostTool` returns `null` without calling the finder.
- **FR-3** — `noteHostToolSpawnFailed(name, error)` drops the cached path on a spawn ENOENT and records the tool as missing when a fresh lookup also misses. It ignores errors that are not ENOENT.
- **FR-4** — `refreshHostTools()` clears every cached entry, so the next `resolveHostTool` does a fresh lookup.
- **FR-5** — With Docker missing, one `DockerStatsCollector.collect()` tick spawns 0 processes. With Docker present, it spawns the resolved absolute path.
- **FR-6** — With Docker missing, `loadDockerContainers()` (resource discovery) and `collectDockerContainerLifecycleSnapshot()` (stack health) spawn 0 processes and return their existing empty results: `[]` for discovery, and a failed Effect for the snapshot, as when Docker is unavailable today.
- **FR-7** — With tmux missing, the runtime census's default `listPanes` spawns 0 processes and rejects with an ENOENT error, so the census reports `tmuxAvailable: false` as it does today.
- **FR-10** — With tmux missing, the default tmux helpers in `conversation-liveness.ts` spawn 0 processes and answer "no tmux session" (`false` / `[]`). An injected `deps.*` seam still takes precedence.
- **FR-8** — `pan doctor` prints a "Host tools" row from a fresh lookup through the module. It lists each `HostToolName` as found (with its path) or missing.
- **FR-9** — A successful `PUT /api/settings` calls `refreshHostTools()`.
- **NFR-1** — No new `execSync`, and no sync child-process call in dashboard-reachable code. The module does only `stat`/`access` file checks.
- **NFR-2** — No file over 1000 lines grows past its `scripts/file-size-allowlist.txt` cap or its `origin/main` line count (`tmux.ts` is untouched; `settings.ts` shrinks).
- **NFR-3** — Back-off tests use an injected `now` (or `vi.useFakeTimers()`), never real waits.
- **NFR-4** — No new test reads source files (the `lint:source-introspection` rule). Every test asserts behavior.

## Work items

### WI-1 — Host-tool module (`host-tools-module`)

**Files:** new `src/lib/host-tools.ts`; new `tests/unit/lib/host-tools.test.ts`; `tests/setup.ts`.

Create `src/lib/host-tools.ts` with a module header that explains PAN-5168 (libuv on macOS creates one process per PATH entry on a failed spawn) and the D2/D4 semantics:

```ts
import { findExecutableOnPath } from './pan-cli-shim.js';

export type HostToolName = 'docker' | 'tmux' | 'systemctl' | 'journalctl' | 'brew';
export const HOST_TOOL_MISSING_RECHECK_MS = 60_000;

type Finder = (name: HostToolName, pathEnv: string | undefined) => string | null;
export interface HostToolDeps { find?: Finder; pathEnv?: string; now?: () => number }

interface Entry { path: string | null; pathEnv: string | undefined; recheckAt: number }
const entries = new Map<HostToolName, Entry>();
let testFinder: Finder | null = null;

function lookup(name: HostToolName, pathEnv: string | undefined, deps: HostToolDeps): string | null {
  if (deps.find) return deps.find(name, pathEnv);
  if (testFinder) return testFinder(name, pathEnv);
  if (process.env.OVERDECK_TEST_ASSUME_HOST_TOOLS === '1') return name;
  return findExecutableOnPath(name, pathEnv);
}

export function resolveHostTool(name: HostToolName, deps: HostToolDeps = {}): string | null {
  const pathEnv = deps.pathEnv ?? process.env.PATH;
  const now = (deps.now ?? Date.now)();
  const entry = entries.get(name);
  if (entry && entry.pathEnv === pathEnv) {
    if (entry.path !== null) return entry.path;
    if (now < entry.recheckAt) return null;
  }
  const path = lookup(name, pathEnv, deps);
  entries.set(name, { path, pathEnv, recheckAt: path === null ? now + HOST_TOOL_MISSING_RECHECK_MS : 0 });
  return path;
}

export function noteHostToolSpawnFailed(name: HostToolName, error: unknown, deps: HostToolDeps = {}): void {
  if (!isSpawnNotFoundError(error)) return;
  entries.delete(name);
  resolveHostTool(name, deps); // D4: stays present when a fresh lookup still finds it
}

export function refreshHostTools(): void { entries.clear(); }

/** Walks `.cause` (max 4 levels): Node `code === 'ENOENT'` or Effect `reason._tag === 'NotFound'`. */
export function isSpawnNotFoundError(error: unknown): boolean { /* … */ }

/** A Node-shaped ENOENT error for a skipped spawn (no process is created). */
export function hostToolNotFoundError(name: HostToolName): NodeJS.ErrnoException {
  return Object.assign(new Error(`spawn ${name} ENOENT (skipped: not on PATH)`), {
    code: 'ENOENT', errno: -2, syscall: `spawn ${name}`, path: name,
  });
}

export function setHostToolFinderForTests(find: Finder | null): void { testFinder = find; entries.clear(); }
export function resetHostToolsForTests(): void { entries.clear(); testFinder = null; }
```

In `tests/setup.ts`, set `process.env.OVERDECK_TEST_ASSUME_HOST_TOOLS = '1';` beside the `OVERDECK_TERMINAL_BACKEND` default, with a comment citing PAN-5168 D8. Add no import.

**Verified error shapes (probe run during planning against the installed `effect@4.0.0-beta.73`):** `Effect.runPromise` of an `Effect.tryPromise` whose `catch` wraps a failed `execFile` in a `TmuxError` rejects with the `TmuxError` itself, and its `.cause.code === 'ENOENT'` and `.cause.syscall === 'spawn <cmd>'`. A failed `ChildProcess.make` spawn rejects with a `PlatformError` where `reason._tag === 'NotFound'`, `reason.method === 'spawn'`, and both `.cause.code` and `reason.cause.code` are `'ENOENT'`. A `.cause` walk of up to 4 levels that checks `code === 'ENOENT'` or `reason._tag === 'NotFound'` therefore detects both.

Tests in `tests/unit/lib/host-tools.test.ts` pass explicit `deps` (`find`, `pathEnv`, `now`):
- `resolveHostTool caches a found path and calls the finder once`.
- `resolveHostTool caches a miss for 60 s, then looks again` — the finder returns `null`. At `now = 0` the call returns `null` (1 finder call). At `59_999` it returns `null` (still 1 call). At `60_000` it calls the finder again (2 calls).
- `a PATH change invalidates the cached entry`.
- `noteHostToolSpawnFailed marks a vanished tool missing` — found first, then the finder returns `null` and a Node ENOENT is reported, so the next resolve returns `null`.
- `noteHostToolSpawnFailed keeps a tool that a fresh lookup still finds` (the missing-cwd case).
- `noteHostToolSpawnFailed ignores non-ENOENT errors` (for example `{ code: 1 }`).
- `isSpawnNotFoundError recognizes an Effect PlatformError NotFound and a TmuxError-wrapped ENOENT`. Build the PlatformError with `PlatformError.systemError({ _tag: 'NotFound', module: 'ChildProcess', method: 'spawn', … })` from `effect/PlatformError`.
- `refreshHostTools forces a fresh lookup`.
- `OVERDECK_TEST_ASSUME_HOST_TOOLS returns the bare name when no finder is injected`.
- `the real PATH lookup returns null for an empty directory` — `vi.stubEnv('OVERDECK_TEST_ASSUME_HOST_TOOLS', '')`, no injected finder, `pathEnv` = a fresh `mkdtempSync` directory. Restore with `vi.unstubAllEnvs()`.

Each test file that calls `setHostToolFinderForTests` calls `resetHostToolsForTests()` in its own `afterEach`.

## Non-goals

- Routing conversation pane reads (`capturePane`, `readConversationInputTarget`, `conversationNeedsTerminal`) away from tmux under herdr, and changing `ensureHostTools`/`brew install` behavior (PAN-5169). The liveness fallback in WI-5b is a missing-tool gate, not backend routing: it keeps the fallback for legacy tmux conversations when tmux exists.
- Platform guards for `systemctl` and `journalctl` (PAN-5170). The module includes those names so PAN-5170 can adopt it later, but PAN-5168 wires no call site for them.
- Gating `tmuxExecAsync`, `systemctl()`, or any launch path. Only the five named pollers (WI-2 to WI-5b) are gated.
- Gating on-demand Docker calls (workspace create/remove, container routes, prune, doctor's own docker checks).
- Gating the deacon hygiene patrols (`idle-stack-reaper.ts`, `bridge-pool-patrol.ts`, `merged-docker-reconcile.ts`). They run `docker` through a shell every 60 s or slower, so each call costs about one process.
- Merging the two `DockerStatsCollector` singletons into one.
- Handling a Docker CLI that is present while the daemon is down (one spawn that exits 1 is not a storm).
- Handling a binary that is found on PATH but fails exec with ENOENT, such as a broken shebang interpreter.
- A dashboard HTTP route for `pan doctor` to reset the server's cache.

## Restated repo rules that apply

- No `execSync` in dashboard-reachable code (`no-execsync-server`). The module uses only sync `stat`/`access` file checks through `findExecutableOnPath`, which never spawns.
- Fake timers or an injected clock for back-off tests (`fake-timers-for-retry-tests`). No real 60 s waits.
- File-size ratchet: `scripts/lint-file-size.sh` checks files above 1000 lines against the last allowlist row (last row wins). Never raise a cap.
- One variant per operation in `src/lib`; no exported Effect wrapper around sync code (`lint:effect-facades`).
- New tests must not grep source (`lint:source-introspection`), and must not add `skipIf`/`.only`.
- A user-facing change adds `changelog.d/<issue>.md`. Never edit the top of `changelog.mdx`.
