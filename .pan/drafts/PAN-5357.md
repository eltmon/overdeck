# PAN-5357: Stop the sequencer's timestamp-only commits to main

**Issue:** [PAN-5357](https://github.com/eltmon/overdeck/issues/5357)
**Planned on:** main at `c4d4c268676` (2026-11-15)

## Summary

The dashboard starts a fresh `sequencer-runner` agent 30 seconds after any burst of issue deltas, and `pan backlog write-sequence` rewrites, commits and pushes `.pan/backlog/sequence.md` on every run. Each run stamps a new `generatedAt`, so a run that changes nothing still produces a two-line commit. On 2026-11-15 this produced 41 `chore(workspace): backlog sequence` commits on `main` in 3 hours. For example, `ad851b28070` changes only `_Last sequenced:` and `"generatedAt"`, 42 seconds after the previous run.

The 42-second spacing suggests the loop feeds itself: a sequence push moves `main`, the move changes derived PR and issue state in the dashboard read model, and that emits `issues.delta`, which starts another pass 30 seconds later. This is a hypothesis that was not verified while planning. The fix does not depend on it, because each layer below stops the churn on its own.

This plan fixes three layers:

1. **The writer.** It leaves `sequence.md` untouched when only the timestamp would change, so the commit step finds nothing to commit.
2. **The spawner.** The automatic path skips spawning when the backlog manifest is the same one the last pass examined.
3. **The trigger.** It limits automatic passes to one every 30 minutes.

## Glossary

- **Sequencer / sequencer pass.** A one-shot agent (`SEQUENCER_AGENT_ID = 'sequencer-runner'`, role `sequencer`) that ranks the open backlog. It submits a `SequenceDoc` JSON through `pan backlog write-sequence`.
- **SequenceDoc.** The ranked backlog document (`src/lib/backlog/types.ts`, `export type SequenceDoc`). Its fields are `version`, `project`, `generatedAt`, `model`, `pass`, `lastReviewPass?`, `openCount`, `nodes[]` and `edges[]`.
- **sequence.md.** `.pan/backlog/sequence.md` in the plan home. It holds a header, a ranked table, a rationale section and a machine-readable fenced JSON block. It is tracked on `main`.
- **manifest.json.** `.pan/backlog/manifest.json`, the compact list of open issues that each pass ranks. It is gitignored (`.gitignore` line 80) and rewritten by every `spawnSequencerAgent` call.
- **Manifest key.** A deterministic string built from a manifest (FR-5). It drops `ageMs`, which changes on every call, and sorts entries by `id` and labels alphabetically.
- **examined-manifest.json.** `.pan/backlog/examined-manifest.json`, a byte copy of `manifest.json` that only the sequencer's submission path writes (`writeSequenceMd` without `operatorEdit`, FR-11). It records the manifest of the last pass that actually submitted a ranking. It is the "nothing changed since" watermark for the automatic skip, and it is gitignored.
- **Automatic pass.** A pass started by `triggerDebouncedIncrementalPass` (`src/lib/backlog/backlog-auto-trigger.ts`). Operator passes come from `POST /api/backlog/sequence/regenerate` (the dashboard button) and are never rate-limited or skipped.
- **Automatic-pass window.** The 30-minute minimum interval after an automatic pass that actually spawned an agent.
- **Plan home.** The repo whose `.pan/` holds project-level planning artifacts (`resolvePlanHome`, `src/lib/pan-dir/paths.ts`).
- **Stranded commit.** A local sequence commit whose push failed earlier. `pushPlanArtifacts` pushes every pending `.pan/`-only commit on its next call.

## Requirements

### Functional

- **FR-1.** `writeSequenceMd` renders deterministically:
  - Nodes, in both the table and the JSON block, are sorted by `rank` ascending, then by `issue` (`localeCompare`), then by the node's `JSON.stringify` text. The last key makes even duplicate-issue nodes order-independent.
  - JSON-block `edges` are sorted by `from`, `to`, `type`, `source`, then `confidence` (numeric). Two edges equal on all five fields serialize identically, so their order cannot change the bytes.
- **FR-2.** `writeSequenceMd` returns `{ written: boolean }`.
  - It renders the merged doc a second time with `generatedAt` replaced by the prior file's parsed `generatedAt`.
  - If that rendering is byte-identical to the prior file, it does not write and returns `{ written: false }`.
  - In every other case it writes the file and returns `{ written: true }`: no prior file, an unparseable prior file, or any byte difference.
  - Every field except `generatedAt` counts as a change: `model`, `pass`, `lastReviewPass`, `openCount`, every node field, and the edge set.
- **FR-3.** On an unchanged AI write (`opts.operatorEdit` not true), `writeSequenceMd` sets the file's mtime and atime to now with `utimesSync` and leaves the bytes unchanged. This keeps `getSequencerRunStatus`'s `fresh-sequence` done signal working. On an unchanged operator edit it does not touch the file.
- **FR-4.** `pan backlog write-sequence` always calls `commitPlanArtifacts` after `writeSequenceMd`, as today. On a clean tree it returns `nothing to commit` and makes no commit; a sequence write that failed to commit earlier is still committed on a re-run. The command then pushes as today. Only the success line changes:
  - written: `✓ Wrote .pan/backlog/sequence.md (<n> nodes, pass=<pass>)` (unchanged);
  - not written, nothing committed: `✓ .pan/backlog/sequence.md unchanged (only generatedAt differs), not committed`;
  - not written, but an earlier uncommitted write was committed: `✓ .pan/backlog/sequence.md unchanged; committed an earlier uncommitted sequence write`.

  It exits 0 in all three cases. An unchanged ranking therefore adds no commit to the plan home.
- **FR-5.** `spawnSequencerAgent` accepts `skipWhenUnchanged?: boolean`. When the option is true, a prior sequence exists (`input.priorSequence !== null`), `.pan/backlog/examined-manifest.json` exists, and `manifestKeyFromText(examined) === backlogManifestKey(input.manifest)`, the function:
  - returns `null`;
  - does not write `manifest.json`, reap a finished run, or call `spawnRun`;
  - logs one line starting `[sequencer] skipped`.

  Without the option, behavior is unchanged and the return type stays `Promise<AgentState>`.
- **FR-6.** If any step after the `manifest.json` write throws (model resolution, reaping, the pause check, or `spawnRun`), `spawnSequencerAgent` restores the prior `manifest.json` bytes. If there was no prior file, it removes the new one. It then rethrows the original error. This matters for FR-11: a refused spawn must not overwrite the manifest that a still-running pass will copy into `examined-manifest.json` when it submits.
- **FR-7.** The auto-trigger enforces `MIN_AUTO_PASS_INTERVAL_MS = 30 * 60_000`, measured from the last automatic pass that spawned an agent (the spawn promise resolved non-null).
  - Inside the window, deltas coalesce into one fire at the window's end.
  - Outside the window, the 30-second debounce (`DEBOUNCE_MS = 30_000`) is unchanged.
  - The window is checked when scheduling and again when the timer fires.
  - While a spawn call is in flight, a fire reschedules itself `DEBOUNCE_MS` later.
- **FR-8.** The auto-trigger calls `spawnSequencerAgent('incremental', { projectRoot, skipWhenUnchanged: true })`. A suppressed, skipped (`null`) or failed (rejected) fire does not start the window.
- **FR-9.** The sequencer prompt (`buildSequencerPrompt` Output section) and `roles/sequencer.md` both say that the `unchanged … not committed` output is a successful finish, and that the agent must not retry or edit the JSON to force a write.
- **FR-10.** The docs describe the new behavior in `docs/XBRIEF.md`, `reference/troubleshooting.mdx` and `changelog.d/pan-5357.md` (WI-6).
- **FR-11.** On every AI write (`opts.operatorEdit` not true), written or unchanged, `writeSequenceMd` copies the bytes of `manifest.json` (in the same directory as `sequence.md`) to `examined-manifest.json` in that directory, when `manifest.json` exists. An operator edit never writes `examined-manifest.json`. `.gitignore` ignores `.pan/backlog/examined-manifest.json`.

### Non-functional

- **NFR-1.** No synchronous child processes. `sequence-io.ts` already uses synchronous `node:fs` and is called from the CLI and from routes. `sequencer-agent.ts` keeps using `node:fs/promises` for its new reads (`readFile`, `rm`).
- **NFR-2.** Every timing test uses `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`. Never use real waits (repo rule: fake timers for delay tests).
- **NFR-3.** No new config key. The dashboard regenerate button and its route stay immediate and are never skipped.
- **NFR-4.** `src/cli/index.ts` must not grow (its `origin/main` count is 1209 lines; the file-size ratchet compares against `origin/main`). WI-2 shrinks it.

## Decisions

- **D1. The skip watermark is `examined-manifest.json`, written only when a pass submits.** The issue comment suggested skipping when no issue has `updatedAt` after the prior `generatedAt`. FR-2 freezes `generatedAt` on unchanged passes, so an issue commented on without a rank change would stay "newer than generatedAt" forever, and every window would spawn a pass. `manifest.json` alone cannot be the watermark either, because it is written at spawn time: a pass that dies before submitting would leave a "matching" manifest behind. File mtimes cannot prove completion, because the operator gate and planning routes also write `sequence.md`. So the submission path copies the manifest it ranked into `examined-manifest.json` (FR-11), and only that copy counts. A dead pass or an operator edit leaves the copy at the last submitted manifest, so the next automatic fire sees a difference and spawns. The file is gitignored and adds no commits.
- **D2. The incremental prompt's re-read rule stays keyed on `generatedAt`.** It still says "read bodies for issues with `updatedAt` later than the prior `generatedAt`". With frozen timestamps the agent may re-read a few already-examined bodies. That costs some tokens but is never wrong. Any rank, `why` or `openCount` change advances `generatedAt`, and issues open and close several times a day.
- **D3. The CLI keeps calling `commitPlanArtifacts` and `pushPlanArtifacts` on an unchanged ranking.** The issue comment suggested skipping both. But `commitPlanArtifacts` can fail after a write and leave the change uncommitted in the worktree (`src/lib/overdeck/plan-artifact-commit.ts`, the failure path that resets staging). `reference/troubleshooting.mdx` also tells operators to recover a failed push by re-running `pan backlog write-sequence`. In both cases the re-run is "unchanged", and skipping either call would strand the earlier write. No-op commits stop anyway, because an untouched file gives `commitPlanArtifacts` nothing to commit. `pushPlanArtifacts` pushes nothing when nothing is ahead, so `origin/main` does not move.
- **D4. Byte comparison of a deterministic rendering, not a hand-written deep-equal.** Rendering with the prior `generatedAt` and comparing bytes avoids `undefined`-versus-missing-key mismatches (`rationale`, `isEpic`, `lastReviewPass`). FR-1's sorting removes false differences from array order. The first write after deploy may reorder edges once, which is expected.
- **D5. Bump the mtime on an unchanged AI write.** `getSequencerRunStatus` marks a run done when `sequence.md`'s mtime is at or after the run's `startedAt`. Without the bump, a no-op pass would finish only through the slower idle path (60 s of idle work plus a re-probe). Git ignores mtime, so the bump creates no commit. Operator edits never bump it, because they can run while a pass is live.
- **D6. The window starts only on a successful spawn.** A skipped check costs no agent, so it should not delay sequencing a real change that arrives a minute later. Failed fires ("already running", paused, empty manifest) spawn nothing and are cheap to retry on the next delta.
- **D7. The 30-minute interval is a constant, not a config key.** The issue asked for none, and the Karpathy rules forbid configuration nobody requested.
- **D8. The skip guard sits inside `spawnSequencerAgent` behind an option.** The guard needs the normalized, PAN-filtered manifest, and that function already builds it. The option keeps the operator route immediate. TypeScript overloads keep the route's return type as `AgentState`.

let _incrementalTimer: ReturnType<typeof setTimeout> | null = null;
let _lastAutoPassAt: number | null = null;
let _spawnInFlight = false;

const DEBOUNCE_MS = 30_000;
/** PAN-5357: at most one automatic pass per 30 minutes. Operator passes are immediate. */
export const MIN_AUTO_PASS_INTERVAL_MS = 30 * 60_000;

function windowEndMs(): number {
  return _lastAutoPassAt === null ? 0 : _lastAutoPassAt + MIN_AUTO_PASS_INTERVAL_MS;
}

function schedule(projectRoot: string, delayMs: number): void {
  if (_incrementalTimer !== null) clearTimeout(_incrementalTimer);
  _incrementalTimer = setTimeout(() => fire(projectRoot), delayMs);
}

function fire(projectRoot: string): void {
  _incrementalTimer = null;
  const wait = windowEndMs() - Date.now();
  if (wait > 0) return schedule(projectRoot, wait);
  if (_spawnInFlight) return schedule(projectRoot, DEBOUNCE_MS);
  if (autonomousSpawnSuppressed('incremental')) return;
  _spawnInFlight = true;
  spawnSequencerAgent('incremental', { projectRoot, skipWhenUnchanged: true })
    .then((agent) => {
      // FR-8: only a pass that actually spawned starts the window.
      if (agent) _lastAutoPassAt = Date.now();
    })
    .catch((err: unknown) => console.warn('[backlog-auto-trigger] incremental pass failed:', err))
    .finally(() => { _spawnInFlight = false; });
}

/**
 * PAN-1866: call on every backlog delta. Deltas within DEBOUNCE_MS collapse
 * into one pass; PAN-5357: deltas inside the 30-minute window after a spawned
 * automatic pass collapse into one pass at the window's end.
 */
export function triggerDebouncedIncrementalPass(projectRoot: string): void {
  schedule(projectRoot, Math.max(DEBOUNCE_MS, windowEndMs() - Date.now()));
}

  _incrementalTimer = null;
