## 1. Glossary

Terms from the parent PRD §2 (explorer root, root id, code pane, port record) apply. Added here:

- **Viewer** — a React component that shows one non-Monaco file kind (image, PDF, audio, font, table, large text, archive, SQLite). Viewers get a URL (`src`), never bytes over RPC.
- **Viewer host** — `FileViewer.tsx`, the one component a code pane renders for a non-text file. It picks the viewer with the viewer router and lazy-loads it. It is the seam between this issue and PAN-5187 (code pane) and PAN-5189 (tier 2).
- **Viewer router** — `viewer-router.ts`, a pure function `pickViewer(path, read)` that maps a root-relative path and its `explorerReadFile` result to a viewer kind.
- **Viewer kind** — one of `'text' | 'image' | 'svg' | 'pdf' | 'audio' | 'font' | 'table' | 'large-text' | 'archive' | 'sqlite' | 'binary'`. `'text'` means "not a viewer: open in Monaco". `'binary'` is the generic card (size plus Download).
- **Download route** — `GET /api/explorer/download`. Streams a file (with HTTP Range support) or a folder as `.tar.gz`.
- **Upload route** — `POST /api/explorer/upload`. Takes a raw `application/octet-stream` body and writes one new file.
- **Inline allow-list** — the passive content types the download route serves with `Content-Disposition: inline` when asked (`inline=1`). Everything else is `attachment`.
- **Range request** — an HTTP request with `Range: bytes=<start>-<end>`. The route answers `206 Partial Content` with `Content-Range: bytes <start>-<end>/<size>`. t3code's large-text viewer depends on it (§3 D-3).
- **Upload sink** — the server object that streams upload chunks to a temp file, counts bytes, and either commits (no-clobber link into place) or aborts (deletes the temp file).
- **Fake Worker** — a test class assigned to `globalThis.Worker` with `vi.stubGlobal`, which records `postMessage` calls and lets the test emit `message` events. happy-dom has no `Worker`.

## 3. Decisions (made in this document)

- **D-1 Mount point: this issue ships a props-only viewer host and never creates `CodePane`.** PAN-5188 depends only on PAN-5185; the `'code'` pane type is PAN-5186 (WI-5) and `CodePane.tsx` is PAN-5187 (WI-8), and both may land before or after this issue (order book `2026-11-13-file-explorer-pan-5183`, lane A, concurrency 2). Decision rule for WI-14: after `pan sync-main`, if `src/dashboard/frontend/src/components/explorer/code/CodePane.tsx` exists and does not import `../viewers/FileViewer`, wire it (WI-14). If the file does not exist, make no change and write in the PR description: "Viewer host not mounted: PAN-5187 wires `FileViewer` per the seam in `.pan/drafts/pan-5188.md` §6." The parent's AC-10 Playwright screenshot ("A PNG, a PDF and a CSV … render in code panes") therefore moves to whichever issue mounts the host; this issue proves the viewers with Vitest render tests.
- **D-2 Drop `heic-to`.** `npm view heic-to@1.5.2 license` returns `LGPL-3.0` (checked 2026-11-13). Overdeck is MIT (`package.json` `"license": "MIT"`), and `docs/ACKNOWLEDGEMENTS.md` keeps copyleft code out of the bundle (its OpenKnowledge entry: "no OpenKnowledge code is imported, linked, or bundled into Overdeck"). The parent PRD applies the same rule to tier-2 Office packages (WI-10 step 3: drop any package that is not MIT, Apache-2.0, BSD or ISC). So HEIC/HEIF files render with a plain `<img>` (Safari decodes HEIC natively); when the browser cannot decode it, the image viewer shows the generic binary card with the notice "This browser cannot show HEIC images." TIFF keeps its decoder (`tiff@7.1.3`, MIT).
- **D-3 The download route supports single-range requests.** t3code's `LargeTextViewer.tsx` sends `fetch(src, { headers: { Range: "bytes=0-16383" } })` and uses the answer only when the status is 206; `largeText.worker.ts` sends `Range: bytes=0-<256 MB>` and treats `416` with `Content-Range: bytes */0` as an empty file. Browsers also need ranges to seek in `<audio>`. Supported forms: `bytes=a-b`, `bytes=a-`, `bytes=-n`. A header with a comma (multiple ranges) or any other syntax is ignored and the full file is sent with 200 (RFC 9110 allows this). A range whose start is at or past the file size answers 416 with `Content-Range: bytes */<size>`.
- **D-4 PDF always renders with the ported pdf.js viewer.** t3code's `BrowserDocumentFrame.tsx` prefers the browser's built-in viewer in an `<iframe>`. The download route sends `Content-Security-Policy: sandbox` on every response, and Chromium refuses to run its PDF viewer in a sandboxed document. So `BrowserDocumentFrame` is not ported; `PdfViewer` is used for every PDF.
- **D-5 Upload CSRF: extend the existing guard with a content-type option.** `rejectUnsafeDashboardMutationRequest` (`src/dashboard/server/routes/dashboard-auth.ts`, search `export function rejectUnsafeDashboardMutationRequest(`) answers 400 to any body that is not `application/json`. That JSON-only rule is a CSRF defense: a cross-site page cannot send `application/json` without a CORS preflight. `application/octet-stream` is not a CORS-safelisted content type either, so requiring it exactly keeps the same defense. The function gains an optional second parameter `{ contentType?: string }` (default `'application/json'`); its 118 existing callers do not change. The upload route calls it with `{ contentType: 'application/octet-stream' }`, so it gets the same credential, Origin and CSRF-token checks as every other dashboard write.
- **D-6 Upload commits with link-then-unlink, never rename.** `rename` replaces an existing file. The upload sink writes to a temp file in the target directory, then `fs.link(temp, target)` (fails with `EEXIST` atomically when the name is taken, giving `ALREADY_EXISTS`), then `fs.unlink(temp)`. The temp file lives in the same directory, so the link never crosses filesystems.
- **D-7 Folder downloads spawn the system `tar`, with names fed on stdin.** `tar -czf - -C <parent> --null -T - --exclude=<name>…` with one NUL-separated member per kept top-level entry, each prefixed `<folder>/`. GNU tar and bsdtar (macOS, Windows 10+) accept these flags. `tar` never gets `-h`, so symlinks are archived as links and never followed out of the root. The npm `tar` package (root `package.json` `"tar": "^7.5.21"`) is not used: packing gigabytes in JavaScript would run on the dashboard event loop.
- **D-8 Vite workers build as ES modules.** t3code creates workers with `new Worker(new URL("./x.worker.ts", import.meta.url), { type: "module" })`, and two workers use dynamic `import()` (sql.js, tiff). Vite's default worker format is `iife`, which cannot code-split. Overdeck's `src/dashboard/frontend/vite.config.ts` sets no `worker` key today (search `worker` — no match). WI-6a adds `worker: { format: 'es' }`. The existing workers (`@pierre/diffs/worker/worker.js?worker` in `DiffWorkerPoolProvider.tsx`, `monaco-editor/esm/vs/editor/editor.worker?worker` in `context/ContextEditor.tsx`) must still load after the change (WI-6a verify step).
- **D-9 Viewer chrome is Overdeck's, not t3code's.** t3code's `fileSurfaceChrome.tsx` imports its own base-ui button, toggle, spinner and tooltip. The port re-implements the four exports (`Notice`, `Loading`, `Failure`, `Action`) in `viewers/shared/ViewerChrome.tsx` with Overdeck's Tailwind 3 tokens and `components/shared/Tooltip.tsx`. Before writing UI, the executor loads the `pan-style-guide` skill.
- **D-10 Audio and image viewers are written fresh, not ported.** t3code's `AudioPreview.tsx` is mostly a chat chip; the file view is one `<audio controls preload="metadata">`. Its React 19 ref-cleanup callbacks and context-as-provider (`AudioPreview.tsx` lines 34–36, 83–91; `MessagesTimeline.tsx:1358`) are not needed. The image viewer is a plain `<img>` with a CSS zoom toggle (parent WI-10: "Do not port `ExpandedImageDialog`"). These two files get no port header and no port record. The TIFF decode files (`imageDecode.worker.ts`, `decodeImagePreview.ts`) are ported and do get them.
- **D-11 `jszip` is used under its MIT option.** `npm view jszip@3.10.1 license` returns `(MIT OR GPL-3.0-or-later)`. `docs/ACKNOWLEDGEMENTS.md` records that Overdeck takes the MIT option.
- **D-12 No new RPC methods.** Viewers read bytes through the download route only (parent D-14). The only RPC result they consume is `ExplorerReadFileResult` from PAN-5185, passed in by the code pane.

## 4. Requirements

Numbering is local to this issue. Parent requirement ids are in brackets.

### Functional

- **FR-1** [parent FR-10 download, D-14] `GET /api/explorer/download?root=<rootId>&path=<rel>&inline=0|1` streams a regular file's exact bytes with `Content-Length`, `Accept-Ranges: bytes`, `Cache-Control: no-store`, a `Content-Type` from §6.2, and `Content-Disposition` per FR-3. Extra query parameters (the client's `rev`) are ignored.
- **FR-2** [D-3] The download route answers Range requests per D-3: 206 with `Content-Range: bytes <start>-<end>/<size>` and the matching `Content-Length`; 416 with `Content-Range: bytes */<size>` when unsatisfiable; 200 with the full body when the header is absent, malformed or multi-range.
- **FR-3** [parent WI-12 step 1 security] Every download response carries `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'`. `inline=1` gives `Content-Disposition: inline` only when the content type is on the inline allow-list (§6.2); every other response is `attachment`. No response ever has `Content-Type: text/html`, `application/xhtml+xml`, `text/xml` or `application/xml`: those files go out as `text/plain; charset=utf-8`. `.svg` goes out as `image/svg+xml` and always as `attachment`.
- **FR-4** [parent FR-10 folder download] When `path` names a directory (or is empty, meaning the root), the route streams `tar -czf` of it as `application/gzip` with `Content-Disposition: attachment; filename="<name>.tar.gz"`. Every entry named in the exclude list (§6.3) is left out at any depth, and `workspaces` is also left out at the top level of a `project` root.
- **FR-5** [parent FR-10 upload] `POST /api/explorer/upload?root=<rootId>&dir=<rel>&name=<filename>` with `Content-Type: application/octet-stream` writes the body to `<dir>/<name>` and answers 201 `{ path, size, mtimeMs }`. `dir` empty means the root.
- **FR-6** [parent D-12] Uploads over 100 MiB answer 413 `{ code: 'FILE_TOO_LARGE' }`: at once when `Content-Length` says so, otherwise as soon as the streamed count passes the cap. No partial file remains in the target directory.
- **FR-7** [D-6] An upload whose target name exists answers 409 `{ code: 'ALREADY_EXISTS' }` and leaves the existing file unchanged, including when the name appears while the body is streaming.
- **FR-8** [parent D-6, NFR-3] Both routes resolve paths only through PAN-5185's `resolveExplorerRoot` and `resolveInsideRoot`. Errors map to HTTP per §6.4: an upload to a `project` root answers 409 `EDIT_WORKSPACE_REQUIRED`; a path outside the root or inside a git dir answers 400.
- **FR-9** [D-5] The upload route refuses a request without a valid dashboard credential (401), with a cross-site `Origin` (403), without the CSRF token from a browser cookie session (403), or with a content type other than `application/octet-stream` (400).
- **FR-10** [parent FR-9 tier 1] `pickViewer(path, read)` returns the viewer kind for every tier-1 row of §6.6, and `'binary'` for every other binary file.
- **FR-11** [parent FR-9] `FileViewer` renders the viewer `pickViewer` selects, lazily loaded, with `src` built by `explorerDownloadUrl(rootId, path, { inline: true, rev: read.signature })`.
- **FR-12** Image viewer: browser-native formats (png, jpg/jpeg, gif, webp, avif, bmp, ico) render in `<img>` with a fit / 100 % toggle. SVG is fetched as text and shown as `<img src="data:image/svg+xml;base64,…">`. TIFF that the browser cannot show is decoded in a worker to PNG. HEIC/HEIF that the browser cannot show falls back to the binary card with the D-2 notice.
- **FR-13** PDF viewer: ported `PdfViewer` with page virtualization, zoom, find and page jump, documents up to 50 MB and 2,000 pages (t3code limits).
- **FR-14** Audio viewer: `<audio controls preload="metadata">` plus the file name and size.
- **FR-15** Font viewer: ported `FontViewer` (ttf, otf, woff, woff2), up to 10 MB, specimen in a sandboxed `srcDoc` iframe.
- **FR-16** Table and large-text viewers: CSV/TSV under the large-text threshold render in `DelimitedTablePreview` from `read.text`; large text (read kind `'large-text'`) renders in `LargeTextViewer` from `src`, with the delimiter for `.csv`/`.tsv`. Files over 256 MB (t3code `LARGE_TEXT_MAX_BYTES`) show the binary card.
- **FR-17** Archive and SQLite viewer: ported `BinaryViewer` lists zip/jar/tar/gz/tgz entries (folder navigation, entry preview for images and text) and SQLite tables (read-only, `PRAGMA query_only=ON`), within t3code's bounds (50 MB archive, 10 MB entry, 2,048 entries, ratio 200; 100 tables, 50 columns, 1,024 chars per cell).
- **FR-18** The binary card shows the file name, its size as t3code's `formatAttachmentSize` prints it (`2 KB`, `1.5 MB`), and a **Download** link (`explorerDownloadUrl(rootId, path, { inline: false })`).
- **FR-19** `uploadExplorerFile(rootId, dir, file)` posts `file` to the upload route with the CSRF header and returns `{ path, size, mtimeMs }`, or throws an `ExplorerHttpError` carrying the server `code` and HTTP status.
- **FR-21** [parent D-8] The download route checks the dashboard credential itself with `rejectUnauthorizedDashboardRequest` before touching the filesystem, as `routes/fs.ts` and `routes/artifacts.ts` do. The global remote request gate (`remote-request-gate.ts`) lets trusted local callers through with no credential, so the route-level check is what refuses a credential-less request (401).
- **FR-20** [parent FR-17, FR-18] Every ported file starts with the port header and has a record in `scripts/upstream-ports.json`; `docs/ACKNOWLEDGEMENTS.md` names the ported viewers and the third-party viewer packages with their licenses.

`isInlineAllowed` is true for exactly: `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/avif`, `image/bmp`, `image/x-icon`, `image/tiff`, `image/heic`, `image/heif`, `application/pdf`, any `audio/*`, any `font/*`, `text/plain`, `text/csv` (compared on the part before `;`). Viewers fetch with `fetch()`, which ignores `Content-Disposition`; the allow-list matters for `<img>`, `<audio>` and direct navigation.

`contentDisposition` writes `<kind>; filename="<ascii>"; filename*=UTF-8''<encodeURIComponent(name)>`, where `<ascii>` replaces every character outside printable ASCII, and every `"` and `\`, with `_`.

`downloadHeaders` returns `Content-Type`, `Content-Disposition` (inline only when `opts.inline && isInlineAllowed(type)`), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: DOWNLOAD_CSP`, `Cache-Control: no-store`, `Accept-Ranges: bytes`.

### 6.3 Download flow

0. `const authError = rejectUnauthorizedDashboardRequest(request); if (authError) return authError;` (FR-21).
1. Parse `root`, `path` (default `''`), `inline` (`'1'` → true) from `request.url`. Missing `root` → 400 `{ error: 'root is required' }`.
2. `root = await resolveExplorerRoot(rootId)`. If `path === ''`, the target is `root.absPath`; otherwise `abs = await resolveInsideRoot(root, path, { forWrite: false })`.
3. `stat(abs)` (follows the symlink that `resolveInsideRoot` already proved stays inside the root). A directory → folder flow (step 6). Anything that is neither file nor directory → 404 `NOT_FOUND`.
4. File flow: `handle = await open(abs, constants.O_RDONLY | constants.O_NONBLOCK)`; `st = await handle.stat()`; if `!st.isFile()` close and 404. Parse the range (`parseRange(header, st.size)` → `{ kind: 'full' } | { kind: 'partial', start, end } | { kind: 'unsatisfiable' }`, exported for tests).
5. Body: `Stream.fromReadableStream({ evaluate: () => Readable.toWeb(handle.createReadStream({ start, end })), onError: (e) => e })` (pattern: `routes/machines-peer.ts`, search `Stream.fromReadableStream<Uint8Array, unknown>`), answered with `HttpServerResponse.stream(body, { status, headers })`. The stream closes the handle when it ends (`createReadStream` `autoClose` default). Status 200 or 206. A 416 closes the handle before answering, has an empty body, and carries only `Content-Range` plus the FR-3 headers.
6. Folder flow (`services/explorer/folder-archive.ts`, `archiveFolder(root, abs, deps)` returning a web `ReadableStream<Uint8Array>`):
   - `name = basename(abs)`, `parent = dirname(abs)`.
   - Exclude names: if PAN-5185 exports the NFR-5 ignore list (search `'.dart_tool'` under `src/dashboard/server/services/explorer/`), import it; otherwise define `ARCHIVE_EXCLUDE_NAMES = ['.git', 'node_modules', 'dist', 'build', '.next', '.cache', 'target', '.venv', '__pycache__', '.dart_tool', '.gradle', '.turbo']` in `folder-archive.ts`.
   - The exclude list never contains the requested folder's own name: when `name` is in it (a download of `build/`, `dist/` or `node_modules/`), that name is removed from the `--exclude` flags for this archive. GNU tar matches `--exclude=build` against the leading `build/` component of every member, so without this rule the archive comes out empty (checked with GNU tar 1.35 on 2026-11-13). Nested folders with that same name are then included.
   - Members: `readdir(abs)`, drop names in the (adjusted) exclude list, and drop `workspaces` when `root.kind === 'project' && abs === root.absPath`. Each kept name becomes `<name>/<entry>`. If none is kept, the single member is `<name>` and `--no-recursion` is added, so the archive holds the empty folder.
   - `spawn('tar', ['-czf', '-', '-C', parent, ...excludes.map(n => `--exclude=${n}`), '--null', '-T', '-'], { stdio: ['pipe', 'pipe', 'pipe'] })`; write the members NUL-separated to stdin and end it. Never pass `-h`.
   - The response body is `Readable.toWeb(child.stdout)`. If the client disconnects, the stream's cancel kills the child (`child.kill('SIGTERM')`). A non-zero exit logs `[explorer] tar exited <code>: <first 200 chars of stderr>`; the response cannot change status once streaming has begun.
   - Headers: `Content-Type: application/gzip`, `Content-Disposition: attachment; filename="<name>.tar.gz"` (via `contentDisposition`), `X-Content-Type-Options`, CSP, `Cache-Control: no-store`. No `Content-Length`.

### 6.6 Viewer router table (`viewers/viewer-router.ts`)

```ts
export type ViewerKind = 'text' | 'image' | 'svg' | 'pdf' | 'audio' | 'font' | 'table' | 'large-text' | 'archive' | 'sqlite' | 'binary'
```

Evaluated in order; extension is the lower-cased text after the last `.` of the basename. Extension rows come before the read-kind rows, because PAN-5185 calls a file binary only when its first 8 KiB holds a NUL: an ASCII PDF or an uncompressed SVG reads as `'text'` and must still reach its viewer.

| # | Condition | Result |
|---|---|---|
| 1 | ext sqlite, sqlite3, db and read kind `binary` | `sqlite` |
| 2 | ext pdf (any read kind) | `pdf` |
| 3 | ext png, jpg, jpeg, gif, webp, avif, bmp, ico, tif, tiff, heic, heif (any read kind) | `image` |
| 4 | ext svg (any read kind) | `svg`, `textEditable: read.kind === 'text'` |
| 5 | ext mp3, wav, ogg, oga, opus, m4a, aac, flac, weba | `audio` |
| 6 | ext ttf, otf, woff, woff2 | `font` |
| 7 | ext zip, jar, tar, gz, tgz | `archive` |
| 8 | ext csv / tsv and read kind `text` | `table`, delimiter `,` / `\t`, `textEditable: true` |
| 9 | read kind `text` | `text` |
| 10 | read kind `large-text` and size > `LARGE_TEXT_MAX_BYTES` | `binary` |
| 11 | read kind `large-text` | `large-text`, delimiter `,` for csv, `\t` for tsv, else `null` |
| 12 | anything else | `binary` |
