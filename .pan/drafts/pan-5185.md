## 1. Summary

This issue builds the server half of the file explorer, with no UI:

1. The 14 explorer RPC contracts (all of them, so sibling issues only add handlers).
2. Root resolution (`project:` / `issue:` / `workspace:`) and path safety.
3. Directory listing with git-ignore flags, file reads (with a `HEAD` variant), git status and stage/unstage/discard, file-name search and content search.
4. A `@parcel/watcher` child process, its supervisor in the dashboard process, and the `pan.explorerWatch` stream.
5. The upstream port-record system (script, licenses, records for the files this issue ports).

The seven write-side RPC methods that later issues own get **stub handlers** that fail with `NOT_IMPLEMENTED` (§3 D-A1).

There is **no browser surface** in this issue. Nothing renders; UAT has nothing to look at. All acceptance criteria are server-observable (tests, a build check, a slow test).

## 2. Glossary (additions to the parent's §2)

- **Explorer root** — see parent §2. In code: `ExplorerRoot`, the resolved form returned by `resolveExplorerRoot`.
- **Root-relative path** — a POSIX path relative to the root directory, no leading `/`, no `.`/`..` segments, no empty segments. `''` names the root itself.
- **Stub handler** — an RPC handler registered so `PanRpcGroup.of({...})` type-checks, which always fails with `PanRpcError({ code: 'NOT_IMPLEMENTED' })`. A sibling issue replaces it.
- **Git runner** — `runGit(cwd, args, opts)` in `services/explorer/git-exec.ts`: the one async `spawn('git', …)` wrapper every explorer service uses. It always adds `-c core.fsmonitor=false --literal-pathspecs` and sets `GIT_OPTIONAL_LOCKS=0`.
- **Literal pathspecs** — `git --literal-pathspecs` makes `*`, `?`, `[` and a leading `:` in a path argument plain characters. Without it, `git add -- '*.ts'` stages every `.ts` file.
- **Optional locks** — `GIT_OPTIONAL_LOCKS=0` stops `git status` from rewriting `.git/index` to refresh stat data, so explorer reads never contend for `index.lock` with an agent running git in the same worktree.
- **Port header** — the first lines of a ported file, naming upstream, license and source (WI-A13 format).
- **Poll mode** — the supervisor's fallback when the watcher child keeps crashing: no child, and an `overflow` event every 5 s to each subscriber, so clients re-list.
- **Watch spec** — `{ id, absPath, kind }`, the part of an `ExplorerRoot` the supervisor needs.

## 3. Deviations from the parent PRD (decisions)

Each is also recorded in `plan.autoDecisions[]`.

- **D-A1 All 14 contracts land here; 7 get stub handlers.** `PanRpcGroup.of({...})` in `src/dashboard/server/ws-rpc.ts` (search `return PanRpcGroup.of({`) must cover every Rpc in the group, and parent AC-1 requires all 14 in the group. So this issue registers handlers for all 14. The 7 it implements: `explorerListDir`, `explorerReadFile`, `explorerGitStatus`, `explorerGitStage`, `explorerSearchFiles`, `explorerSearchContent`, `explorerWatch`. The 7 stubs and their owners: `explorerWriteFile`, `explorerCreate`, `explorerRename`, `explorerCopy`, `explorerDelete`, `explorerRestore` (PAN-5187, WI-11), `explorerBeginEdit` (PAN-5191, WI-14). Each stub fails with `PanRpcError({ code: 'NOT_IMPLEMENTED', message: 'pan.<method> ships in <issue>' })`.
- **D-A2 All 14 no-loss-matrix rows land here.** `no-loss-matrix.test.ts` regex-scans `packages/contracts/src/rpc.ts` for `pan.*` values (search `enumerateRpcMethods`), so a method in `WS_METHODS` without a row fails CI. The file has no `NEW` disposition. Read methods (`ListDir`, `ReadFile`, `GitStatus`, `SearchFiles`, `SearchContent`, `Watch`) get `READ`; the other eight get `WRITE`. Door string: `'Explorer door (src/dashboard/server/services/explorer/, PAN-5183)'`.
- **D-A3 Issue roots resolve the project first.** `getWorkspacePathForIssue` takes `(projectPath, rawIssueId)` (`src/dashboard/server/workspace-paths.ts:5`), not one argument. Resolve the project with `Effect.runPromise(resolveProjectFromIssue(id))` exactly as `readWorkspaceFile` does (`src/dashboard/server/services/read-workspace-file.ts`, search `resolveProjectFromIssue(input.issueId)`). Its thrown plain `Error` maps to `ROOT_NOT_FOUND`.
- **D-A4 Workspace roots use a derived isolation rule.** `WorkspaceRow` (`src/lib/workspaces/types.ts`, search `export interface WorkspaceRow`) has no `isolated` field. A non-isolated scratch row's `path` is the project's primary checkout (`src/lib/workspaces/create.ts`, search `intent.path = config.path;`), and a `targetPath` row is any directory. A `workspace:<id>` root is accepted only when **all** hold: `row.kind === 'scratch'`; `row.isArchived === false`; `row.branchName` starts with `scratch/`; the project `row.projectId` is in `listProjectsAsync()`; `realpath(row.path)` is a directory; it is not equal to `realpath(config.path)`; and it is inside `realpath(join(config.path, config.workspace?.workspaces_dir || 'workspaces'))`. This is the D-6 boundary: a scratch row pointing at the primary checkout must never become a writable root.
- **D-A5 Signature hashes the decoded string, not bytes.** Orca's `getDiskBaselineSignature(content: string)` hashes UTF-16 code units (`src/shared/file-write/disk-baseline-signature.ts`). The parent says `diskSignature(bytes: Uint8Array)`. We port Orca unchanged: the server decodes the file as UTF-8 (`new TextDecoder('utf-8')`, non-fatal) and hashes the string. The signature is opaque to clients: they only echo it back. Orca has no test file beside the source, so the test vectors in WI-A4 were computed on 2026-11-13 by running Orca's own file with `node --experimental-strip-types`.
- **D-A6 `explorerGitStatus` uses `--branch` and a fixed status mapping** (WI-A6). The parent's command has no `--branch`, but the result has `branch`.
- **D-A7 Git stage/unstage/discard are writes.** They write the repository index or worktree, so they resolve paths with `forWrite: true`: a `project` root fails with `EDIT_WORKSPACE_REQUIRED` and `.git` paths fail with `PATH_IN_GIT_DIR`. **Discard of a path that is not in `HEAD`** (untracked or newly added) needs the Overdeck trash from PAN-5187 (WI-11 `trashPaths`). Until then, a discard request containing any such path fails as a whole with `NOT_IMPLEMENTED` **before any git command runs**. Nothing is ever deleted with `rm` or `git clean`.
- **D-A8 Every git call uses literal pathspecs and no optional locks** (the git runner, §2).
- **D-A9 No sync calls.** `listProjectsSync` (used by `file-at-path.ts`) and `resolveDefaultBranchForRepo` (`src/lib/project-repos.ts`, calls `getProjectSync`) are sync. Use `listProjectsAsync()` (`src/lib/projects.ts`, search `export async function listProjectsAsync`), the pure `defaultBranchForRepo(project, repoRoot)` (`src/lib/project-repos.ts`, search `export function defaultBranchForRepo`), and `resolveBaseRef(cwd, branch)` (`src/lib/checkpoint/checkpoint-manager.ts`, search `export async function resolveBaseRef`). `getWorkspaceById` (`src/lib/workspaces/resolver.ts`) is a synchronous SQLite point read through the registry's read door, already used by `routes/workspace-registry.ts`; it is allowed.
- **D-A10 `committed` uses the same base as today's FilesPane.** Base ref = `resolveBaseRef(root.absPath, root.defaultBranch)`: the local default branch if it exists, else `origin/<default>`, else none (then `committed: []`). Diff = `git diff --name-status -z -M <baseRef>...HEAD`. This is what the vs-main diff panel uses (`src/lib/checkpoint/vs-default-branch.ts`), so the Changed filter in PAN-5186 keeps FilesPane's meaning. It replaces the parent's "default-branch lookup of WI-14 step 1", which belongs to a later issue.
- **D-A11 Watcher ignores use Orca's regex form, not leading-`**` globs.** Orca's `buildParcelWatcherIgnoreOptions` (`src/main/ipc/filesystem/watchers/filesystem-watcher-ignore.ts`) passes one anchored regex through parcel's `ignoreGlobs` option, because leading-`**` globs cause pathological `std::regex` costs. Probe on 2026-11-13 (parcel 2.6.0, inotify, a temp tree with 5 non-ignored and 14 ignored directories): no ignore → 19 inotify watches; plain path ignores → 8 (nested `node_modules` still watched); `**/name/**` globs → 5; Orca's regex → 5. So the regex form prunes ignored trees from the watch set.
- **D-A12 `isDirectory` is not set by this issue's watcher.** Parcel reports only `create|update|delete`. Orca stats every created path to fill `isDirectory`; we omit it (it is optional in the contract) because every client re-lists the parent directory on any event anyway. The watcher never emits `rename` either; PAN-5187's conflict code derives renames from delete+create (parent FR-8).
- **D-A13 Port headers and records only for files that port upstream logic:** `signature.ts`, `watch-batch.ts`, `watch-ignore.ts` (Orca) and `git-dir-guard.ts` (t3code). The git-dir guard is its own file so its header is accurate; `paths.ts` is Overdeck code. Files that only follow an upstream idiom (`read.ts` O_NONBLOCK open, the check-ignore stdin pattern, the supervisor design) get no record.
- **D-A14 Port-record validation is `scripts/upstream-port-diff.sh --check`, run in `npm run lint`.** A vitest file in `tests/unit/scripts/` (the root vitest include does not cover `scripts/__tests__/`) runs the script against fixtures. The source-introspection lint (`scripts/lint-source-introspection.sh`) counts only `readFile(` calls whose arguments contain a `.ts` literal; the test reads no source.
- **D-A15 NFR-2 is enforced at build time.** A `writeBundle` plugin in `src/dashboard/server/tsdown.config.ts` (the existing `deaconEntryChunkAssertion` is the precedent) fails the build if any chunk other than `explorer-watch-child.js` imports `@parcel/watcher`.
- **D-A16 Live checks move to the issues that have a UI.** Parent AC-3's "from a signed-in dashboard" clause and AC-4's "appears in the tree within 500 ms" clause need PAN-5186's tree. Here they become: handler tests against a real fixture repo (AC-3), and a slow test that runs the real supervisor, real child and real parcel and measures event latency and the `watcher.node` mapping (AC-4).
- **D-A17 No changelog entry.** `changelog.d/README.md` asks for an entry only when "users notice" a change. Nothing in this issue is visible. PAN-5186 ships the first visible explorer and its entry.
- **D-A18 Error codes.** `EXPLORER_ERROR_CODES` = the parent's ten plus `NOT_IMPLEMENTED` (stubs, D-A1/D-A7), `INVALID_QUERY` (a content-search regex git rejects) and `EXPLORER_FAILED` (any other failure, message carries the cause).

## 5. Repo rules that apply (restated)

- **Async only** in server-reachable code: `fs/promises`, async `spawn`. No `execSync`, `readFileSync`, `*Sync` project lookups (NFR-1, D-A9). Delays use `await new Promise(r => setTimeout(r, ms))`.
- **Fake timers** for every batching, heartbeat, debounce, idle or poll test: `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`. **Set a realistic clock** with `vi.setSystemTime(new Date('2026-01-01T00:00:00Z'))` in batching tests: Orca's `watchBatchFlushDelayMs` treats `lastFlushAt = 0` as "never flushed", which only gives the 75 ms leading delay when `now` is far from 0. A test that needs real time goes in `<name>.slow.test.ts`; CI runs no slow file unless a workflow names it, so slow tests are local evidence only.
- **No new skips:** never add `skipIf`, `.skip` or `.only` (the test-skip gate rejects them). A Linux-only assertion is guarded by `if (process.platform === 'linux')` inside the test.
- **No source-reading tests** (`scripts/lint-source-introspection.sh`).
- **One variant per operation in `src/lib`:** this issue adds no `src/lib` module. Server services export Promise functions; `ws-rpc-explorer.ts` wraps them with `Effect.tryPromise` at the handler, as `services/file-at-path.ts` does (search `export function readFileAtPathEffect`).
- **No new import cycles** (`npm run lint:circular`). `watch-protocol.ts` is type-only and imported by both the child and the supervisor; the child imports nothing from the server.
- **No-loss matrix:** every new RPC method has a row (D-A2).
- **Route scopes:** no `RPC_METHOD_SCOPES` entries; new methods default to `admin` (`src/dashboard/server/route-scopes.ts`, search `RPC_METHOD_SCOPES[tag] ?? 'admin'`). This issue adds no HTTP route.
- **Workspace doors:** read workspace rows only through `src/lib/workspaces/resolver.ts` (`getWorkspaceById`). No SQL.
- **File size:** every new file stays under 1,000 lines. `src/dashboard/server/ws-rpc.ts` is 1128 lines with cap 1221 (`scripts/file-size-allowlist.txt`); this issue adds at most 16 lines there.
- **Contracts style:** `packages/contracts/src/*.ts` uses double quotes and no semicolons; server code uses single quotes and semicolons. Match each file.
- **Rebuild contracts before typechecking.** The dashboard server's typecheck (`scripts/lint-dashboard-types.sh`, `src/dashboard/server/tsconfig.json`) resolves `@overdeck/contracts` through `node_modules` to `packages/contracts/dist/index.d.ts`, so it sees stale types until `npm run build:contracts` runs. Vitest and the frontend alias the source directly. Every verify step that typechecks runs `npm run build:contracts && npm run typecheck`. (`npm run typecheck` also runs `typecheck:contracts` on the package source.)
- **Quality gates** before `pan done`: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never the full `npm test`.
- **Never `git stash`**; no code path here stashes.

### WI-A7 — File-name and content search [`search-service`]  (FR-6 server side, parent WI-3 step 4)

**Files:** new `src/dashboard/server/services/explorer/search.ts`; new `__tests__/search.test.ts`.

**Steps:**

Fill with `runGit(root.absPath, ['ls-files', '--cached', '--others', '--exclude-standard', '-z'])`; exit ≠ 0 → `NOT_A_GIT_REPO`; dedupe.
2. `export function fuzzyScore(path: string, query: string): number | null` — exact algorithm:
   - `q` = `query` lower-cased with all whitespace removed; `p` = `path` lower-cased. Empty `q` → `null`.
   - Greedy left-to-right: for each char of `q`, find its next occurrence in `p` after the previous match. If any char is not found → `null`.
   - For each matched index `i`: `+1`; `+3` if `i === 0` or `p[i - 1]` is one of `/ _ - .` or space; `+5` if the previous query char matched at `i - 1`.
3. `export async function searchFiles(root, query, limit, opts?): Promise<{ paths: string[] }>`: `limit` clamped to `[1, 500]`; score every cached path; drop `null`; sort by score descending, then path length ascending, then `localeCompare`; return the first `limit`.
4. `export async function searchContent(root, input: { query; scopePath?; regex; caseSensitive; limit }): Promise<ExplorerSearchContentResult>`:
   - Empty `query` → `{ matches: [], truncated: false }`. `limit` clamped to `[1, 500]`.
   - `scopePath` (when non-empty) is validated with `resolveInsideRoot(root, scopePath, { forWrite: false })`.
   - `runGit(root.absPath, ['grep', '-n', '--column', '-I', '--untracked', '--no-color', '--max-count=20', '-z', input.regex ? '-E' : '-F', ...(input.caseSensitive ? [] : ['-i']), '-e', input.query, ...(scope ? ['--', scope] : [])], { timeoutMs: 5_000, maxBytes: 16 MiB })`.
   - Exit 1 → no matches. Exit 128 with `regex: true` → `INVALID_QUERY` (message = first stderr line). Other non-zero exit (not timed out, not truncated) → `EXPLORER_FAILED`.
