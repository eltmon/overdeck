# PAN-4267 — Memory governor locks out small Macs

**Issue:** [PAN-4267](https://github.com/eltmon/overdeck/issues/4267)
**Status:** planned (auto mode, 2026-09-27)

## Summary

On a 16 GB MacBook (v0.62.1) Overdeck reported "critical memory shedding" at
1.0 GiB available against a 4.0 GiB hard reserve and a 12.0 GiB recovery
reserve, while the header said "Healthy · 2.4 GB available". Three defects
combine:

1. The governor's reserve defaults have fixed floors (8/4/12/10 GB) sized for a
   large Linux host. On 8 GB the 12 GB recovery reserve is above total RAM, so
   the governor can never recover.
2. The governor and the header measure macOS "available memory" with two
   different formulas in two different files, so they disagree (1.0 GiB vs
   2.4 GB for the same moment).
3. On macOS the governor has no stall signal (Linux PSI does not exist there),
   and macOS swap grows on demand, so the `psi-unavailable` swap hold fires
   routinely and the PSI-calm re-admit path can never fire.

The spawn guardrail that gates `POST /api/agents` has the same fixed-floor
problem (`memoryWarnGb: 4`, `memoryBlockGb: 2`), and that guardrail — not the
governor — is what stops agents from starting.

**Discovery correction.** The issue assumes the governor's shedding blocks
conversations. It does not. Verified in code on 2026-09-27: the governor band
has exactly two readers — the memory-pressure patrol (activity feed only) and
`resumeYieldedAgents` in `src/lib/cloister/preemption.ts` (opt-in preemption).
`shed()` has no callers. No spawn path and no conversation path reads
`getCachedMemoryVerdict()`. The activity-feed text "Overdeck admits nothing while
shedding is active" is false, and it is what led the operator to link the
"Working…" conversations to the governor. The "Working…" / "Sent · waiting for
transcript" symptom therefore has a different, still-unknown cause and is split
into its own follow-up issue, [PAN-4269](https://github.com/eltmon/overdeck/issues/4269).

## Glossary

- **Governor** — the hysteresis memory governor in
  `src/lib/cloister/memory-governor.ts` (`assessMemoryPressure`). It has three
  modes: `admitting`, `holding`, `shedding`, exposed as bands `ok`/`soft`/`hard`.
- **Reserves** — the governor's four byte thresholds from
  `resources.governor{Soft,Hard,Recovery,Watch}ReserveGb`
  (YAML `resources.governor_{soft,hard,recovery,watch}_reserve_gb`).
  - HARD: below it the governor sheds.
  - SOFT: an admitting governor holds once available memory drops below it.
  - RECOVERY: a holding/shedding governor re-admits only at or above it.
  - WATCH: activity-feed warn level while still admitting; always above SOFT.
- **Floor** — today's absolute minimum per reserve (`Math.max(pct × total, floor)`).
- **Cap** — the new maximum share of total RAM per reserve (this PRD).
- **Spawn guardrail** — `evaluateSpawnGuardrails` in
  `src/dashboard/server/routes/agents/shared.ts`, the memory check on
  `POST /api/agents`. It uses `resources.memoryWarnGb` / `resources.memoryBlockGb`
  (YAML `memory_warn_gb` / `memory_block_gb`) via the system-health snapshot. It is
  unrelated to the governor's reserves.
- **Host health collector** — `createDarwinHostHealthCollector` in
  `src/lib/system-health/darwin.ts`; feeds the header ("Healthy · 2.4 GB available")
  and the spawn guardrail.
- **Governor reader** — `readProcMemoryDarwin` in
  `src/dashboard/server/services/system-health-service.ts`; feeds the governor.
- **PSI** — Linux Pressure Stall Information (`/proc/pressure/memory`,
  `full avg10`). Not present on macOS.
- **macOS pressure level** — the kernel's memory-pressure state read from
  `sysctl -n kern.memorystatus_vm_pressure_level`: `1` normal, `2` warn, `4` critical.
- **Stall signal** — PSI on Linux, macOS pressure level on darwin.
- **PSI-calm re-admit** — the existing path in `assessMemoryPressure` that moves
  `holding → admitting` after the stall signal stays calm for
  `governorPsiCalmWindowMs` (default 10 min) with available ≥ SOFT.
- **Yielded agent** — a work agent paused by the preemptive scheduler
  (`[concurrency] preemption = true`, PAN-2507).

## Decisions (made here, not left to the executor)

- **D1 — Cap rule.** Each governor reserve default is
  `min(max(pct × total, floor), cap × total)` with today's pct/floor and these
  caps: hard ≤ 10 %, soft ≤ 20 %, watch ≤ 25 %, recovery ≤ 35 % of total RAM.
  This lowers the reserves on every host under ~40 GB, **including 32 GB hosts**
  (soft 8 → 6.4, hard 4 → 3.2, recovery 12 → 11.2, watch 10 → 8). That is
  intended. Hosts at or above 40 GB keep today's values exactly.
- **D2 — Spawn guardrail thresholds scale too.** `memoryWarnGb` default =
  `min(4, total / 8)`, `memoryBlockGb` default = `min(2, total / 16)`. Hosts at
  or above 32 GB keep 4 / 2. This is the path behind "agents never start": the
  deferred planning hand-off retry sends no acknowledgement, so a permanent
  "RAM tight" warning blocks autonomous starts forever.
- **D3 — One macOS measure.** One exported function in
  `src/lib/system-health/darwin.ts` computes available bytes; both the header
  collector and the governor reader call it. Primary source: `memory_pressure -Q`
  free percentage × total (the header's source today; it is the kernel's own
  available measure). Fallback: the Activity Monitor formula from `vm_stat`:
  `available = total − (Anonymous pages − Pages purgeable + Pages wired down + Pages occupied by compressor) × page size`.
  If any of those four lines is missing, fall back to the existing
  `(Pages free + Pages inactive + Pages speculative) × page size`.
  Purgeable pages are not added to the free sum, because they are already
  counted in the active/inactive queues.
- **D4 — macOS stall signal.** On darwin the governor reads
  `sysctl -n kern.memorystatus_vm_pressure_level` and maps `1 → normal`,
  `2 → warn`, `4 → critical`, anything else → `null`. `critical` sheds (new
  trigger kind `mac-pressure-critical`); `normal` counts as calm for the
  PSI-calm re-admit; `warn` is neutral.
  Fallback: if the sysctl fails or its output does not parse, `macPressureLevel`
  is `null`; the governor then neither sheds on pressure nor calm-re-admits on
  that host, and a holding governor exits only at RECOVERY. Swap rules stay off
  on darwin either way (D5).
- **D5 — macOS swap is not runway.** macOS allocates swap files on demand, so
  `vm.swapusage` total is the current allocation and its free share is always
  low. On darwin the snapshot sets `swapGrowsOnDemand: true` and the governor
  skips both swap rules (`swap-psi` shed and `psi-unavailable` hold). Linux
  behavior is unchanged.
- **D6 — "Never lock out for good" is delivered by D1 + D4 + D7, not a timer.**
  With capped defaults, recovery is always below total RAM. With D4, the
  existing PSI-calm re-admit works on macOS. No new N-minute breaker is added.
- **D7 — Config normalization.** A pure `normalizeGovernorReserves` enforces:
  hard < soft (else hard = soft × 0.5), recovery > soft (existing: soft + 1),
  watch > soft (existing: soft + 1), and finally: if any of the four reserves is
  ≥ total RAM, all four are replaced by the host's scaled defaults. Every
  correction emits one `console.warn` naming the corrected YAML keys.
- **D8 — No conversation memory gate.** The governor does not gate
  conversations today and this issue does not add a gate. The issue's
  "Tell the user" item is delivered as truthful activity-feed text (WI-6).
- **D9 — The recorded vm_stat sample is synthesized.** No Mac is available to
  the planner or the work agent (both run on Linux). The fixture below uses the
  real macOS `vm_stat` line format with numbers chosen to reproduce the
  reported 1.0 GiB vs 2.4 GiB split. Live-Mac verification is an implementation
  checkpoint with the fixture test as fallback.

- **FR-1** Governor reserve defaults follow D1; at 8, 16, 32 and 64 GB they equal
  the table in WI-1 and never exceed the caps; ordering hard < soft < watch and
  soft < recovery < total holds.
- **FR-2** Spawn guardrail defaults follow D2; at 8, 16, 32 and 64 GB they equal
  the table in WI-2; memoryBlockGb < memoryWarnGb.
- **FR-3** User-set reserves are normalized per D7 with a warning naming the keys.
- **FR-4** On darwin the header collector and the governor reader report the same
  available bytes for the same `memory_pressure` / `vm_stat` output (D3).
- **FR-5** On darwin the governor uses the macOS pressure level as its stall
  signal (D4) and ignores swap runway (D5).
- **FR-6** Activity-feed governor messages state what the governor actually
  holds, never say "admits nothing", and name the macOS pressure level on darwin.
- **FR-7** `docs/PIPELINE-GATES.md` and a new `configuration/memory-governor.mdx`
  describe the scaled defaults, the caps, the macOS measure and stall signal, and
  what the governor does and does not gate.
- **NFR-1** Linux behavior is unchanged apart from the reserve/threshold defaults
  on hosts under 40 GB (32 GB for the spawn guardrail).
- **NFR-2** No `execSync` in server-reachable code (the governor reader runs in
  the deacon and dashboard); keep `execAsync`/`execFile` async.
- **NFR-3** All darwin behavior is testable on Linux through injected adapters or
  mocked `exec`; no test shells out to `vm_stat`, `memory_pressure`, or `sysctl`.

export function computeGovernorReserveDefaultsGb(totalGb: number): GovernorReserveDefaultsGb {

}
