## Glossary

- **Command palette** (or **palette**): the search dialog that `Ctrl+K` (`⌘K` on macOS) opens.
  Source: `src/dashboard/frontend/src/components/CommandPalette.tsx`.
- **Scope chip**: one of the filter buttons under the palette's input (`All`, `Actions`, `Files`,
  `Commands`, `Issues`, `Workspaces`, `Conversations`, `Memory`). Choosing one shows only that type.
- **Conversation search index**: the index the palette searches for conversation text. It holds chunks of
  Claude Code transcript files with a keyword (BM25) index and OpenAI embedding vectors, in
  `~/.overdeck/conversations/embeddings.db`. Configured by the `conversationSearch` block of
  `~/.overdeck/config.yaml` and the **Conversation Search** card in Settings.
- **Title match**: a conversation whose dashboard title contains every query term as the start of a
  word. Title matching reads the dashboard database, not the index, so it works with the index off.
- **Match tier**: the band a palette conversation result falls in: `title` (title match), `text`
  (the query matched prose in the transcript), `path` (the query matched only inside code, inline code
  or file paths). Tiers always sort title, then text, then path.
- **Discovered sessions**: the separate session catalog that `pan conv scan` builds in the dashboard
  database (`overdeck.db`). `pan conv search`, `pan conv enrich` and `pan conv embed` work on it.
- **Enrichment**: AI-written summaries and tags for a discovered session (`pan conv enrich`). Keyword
  `pan conv search` searches these summaries, tags and touched files.
- **Session embeddings**: one embedding vector per enriched discovered session (`pan conv embed`),
  configured by the `conversations.embedding*` keys and the **Semantic embeddings** rows in Settings.
  They power `pan conv search --semantic` and `--similar`. **They do not feed the palette.**
- **Mint check**: `npx -y mint@4.3.49 validate` and `npx -y mint@4.3.49 broken-links`, run from the
  workspace root. Always pin `mint@4.3.49` (the version PAN-5483 standardized on). Never run
  `mint validate --fix`: it rewrites about 80 files that sibling issues edit in parallel.
- **Dash rule**: no em dash (U+2014) or en dash (U+2013) in any line this issue adds or edits, and
  none in the frontmatter `title` or `description` of either touched page.

`FE/` below means `src/dashboard/frontend/src/`.

## Background: verified facts

### Opening the palette

- F-1. `Ctrl+K` (Linux, Windows) or `⌘K` (macOS) toggles the palette with every scope (`All`).
  `FE/App/hooks/useAppShortcuts.ts:43` (`keys: { mac: 'Meta+K', other: 'Ctrl+K' }`), label
  `Command palette`, scope `global`.
- F-2. `Ctrl+J` / `⌘J` opens the palette with the `Conversations` chip already selected.
  `useAppShortcuts.ts:55` (`keys: { mac: 'Meta+J', other: 'Ctrl+J' }`), label `Find a conversation`.
- F-3. Both keys are `global` shortcuts, so they work in text fields and code editors, but in a

- F-4. `/` is **not** the palette. It opens `SearchModal`, an issue search (`FE/App.tsx`, search

### What the palette lists

- F-6. Input placeholder: `Search commands, issues, conversations, memory…` (`CommandPalette.tsx:908`).
- F-7. With an empty query the palette lists built-in actions, workspaces, issues and running agents.
  The `pan` command catalog is hidden until you type (`CommandPalette.tsx:819`, search
  `!a.group.startsWith('Commands · ')`).
- F-8. Built-in actions include (labels from `CommandPalette.tsx`, search `label: '`): `New workspace…`,
  `New conversation with options…`, `Open Flywheel`, `Start Cloister`, `Stop Cloister`,
  `Emergency Stop All Agents` (opens the stop confirmation), `Shut down Overdeck`,
  `Restart All Conversations`, `Restart All Workspace Agents`, `Open Settings`, `Open Context`,
  `Go to Kanban Board`, `Open Terminal`, `View Agents`, plus Anywhere actions
  (`palette-anywhere-actions.ts`) and computer-use actions (`palette-computer-use-actions.ts`).
  Do not list every action; name four or five as examples and say the list is longer.
- F-9. Local filtering (actions, commands, issues, agents, workspaces) matches the typed text against
  the label, description and keywords, case-insensitively (`CommandPalette.tsx`, search
  `action.label.toLowerCase().includes(q)`).
- F-10. Server search (conversations, memory) starts when the query has 2 or more characters
  (`CommandPalette.tsx:405`, `trimmed.length < 2`) and waits 120 ms after the last keystroke
  (`CommandPalette.tsx:364`). It calls `GET /api/palette/search`. After 10 seconds without an answer the
  palette shows `Search timed out after 10 s. Try again.` (`CommandPalette.tsx:254` and `:955`). A failed
  request shows `Search unavailable (<reason>): sign in again / try again` instead of "No results"
  (search `Search unavailable`).
- F-11. Choosing a **command** row copies the command text to the clipboard and shows
  `Copied: <command>` (`CommandPalette.tsx:732`). It does not run the command.
- F-12. Choosing a **Memory**, **Memory · Summaries** or **Observations** row opens the issue it
  belongs to when it has one; otherwise it shows the excerpt in a toast (`CommandPalette.tsx`, search
  `openIssue(hit.issueId)`).
- F-13. The `Files` scope lists files only where a work dock is mounted (the Command Deck), from that dock's root,
  and only when you type something (`FE/components/palette/fileProvider.ts` header comment).
- F-14. Results from linked machines appear in groups headed `On <machine label>` and count as
  Conversations; choosing one opens `/conv/@<env>/<name>` (`FE/components/palette-fleet-hits.tsx`
  header). A machine that fails or runs an older Overdeck adds no rows.
- F-15. Group to chip mapping (`CommandPalette.tsx:203`, `function groupScope`):

  | Chip | Result groups it shows |
  | --- | --- |
  | `Actions` | Actions, Orchestration, Navigation, Anywhere and other built-in groups |
  | `Files` | Files |
  | `Commands` | every `Commands · <group>` group |
  | `Issues` | Issues, Active Workspaces, Running Agents |
  | `Workspaces` | Workspaces |
  | `Conversations` | Conversations and every `On <machine>` group |
  | `Memory` | Memory, Memory · Summaries, Observations |

  `New workspace…` appears under both `Actions` and `Workspaces` (search `alsoScopes`).
- F-16. Chips appear only for result types present in the current list, plus `All`. The
  `Conversations` chip is always offered (`CommandPalette.tsx:200`, `PINNED_SCOPES`), so `Ctrl+J`
  always has it. If the selected type drops out of the results, the palette returns to `All`.
- F-17. Footer keys: `↑↓` navigate, `↵` select, `Esc` close. `Esc` closes the palette from anywhere
  in it. A focused chip activates with Enter.

### Conversation results in the palette

- F-18. One row per conversation, labelled by its title (or the matching text when it has no title),
  with the best-matching excerpt highlighted (`FE/components/palette-conversation-hits.ts`,
  `describeConversationHit`). Shipped in v0.65.0 (changelog, search `#4375`).
- F-19. Row chips, in order: project (and workspace), the issue id when the transcript is in an issue
  workspace, the source (`Conversation <name>`, `Claude session <first 8 chars>`, or
  `Subagent of …`), date (`Today 18:30`, `Yesterday 09:12`, `Jun 9`), role, `<n> hits` when more than one
  chunk matched, and `archived` for archived conversations (`palette-conversation-hits.ts:149-150`).
- F-20. Ranking (`src/dashboard/server/routes/palette.ts` header comment;
  `src/lib/conversation-search/group-hits.ts`; `match-context.ts:30` `classifyChunkMatch`):
  1. Title matches first. A title matches when every query term starts a word of the title
     (`src/lib/overdeck/conversation-title-search.ts:10`, `titleMatchesQuery`).
  2. Then conversations whose transcript prose matched (keyword or semantic).
  3. Last, conversations where the query appears only inside code blocks, inline code or file paths.
  Inside the transcript tiers, keyword (BM25) and semantic (vector) hits are fused into one score.
- F-21. The `Newest first` button in the palette footer sorts conversation results newest first
  **inside** each tier; tiers still come first (`CommandPalette.tsx:167`,
  `compareConversationActionsNewestFirst`). It is on by default (`CommandPalette.tsx:376`) and the
  choice is remembered in this browser (localStorage key
  `overdeck.ui.paletteConversationsNewestFirst`). Do not print the key in the docs; say "this browser
  remembers it".
- F-22. Choosing a conversation row opens it in the Command Deck and scrolls to the matching message.
  A title-only match opens the conversation without a target message. A subagent match opens the
  parent conversation with that subagent selected (`FE/App.tsx`, search
  `const handleOpenConversationHit`).
- F-23. Archived conversations are included and carry the `archived` chip (changelog #4375).
- F-24. Only Claude Code transcripts are indexed for text search: the index reads
  `~/.claude/projects/` (`src/lib/conversation-search/indexer.ts:392`, `return [claudeProjectsRoot()]`),
  including subagent transcripts. Conversations on other harnesses are found by title only.
- F-25. Search stays responsive when a leg is slow: each keyword or vector scan has a 4 second budget
  (`src/dashboard/server/services/conversation-search-service.ts:20`) and the query embedding has 2.5
  seconds (`src/lib/conversation-search/ranker.ts:52`); a leg that misses its budget adds nothing and
  the rest still return (changelog v0.89.0 entry, search `#5447`). One sentence is enough.

### Searching from the command line (`pan conv`)

`pan conv` is the alias of `pan conversations` (`src/cli/commands/conversations/index.ts`). Help text
below is from `pan conv <verb> --help` on 0.89.0 and matches the source at
`index.ts:42` (scan), `:59` (search), `:226` (embed), `:239` (enrich). Re-run `pan conv <verb> --help`
and use its output if it differs.

- F-32. These commands use the **discovered sessions** catalog in `overdeck.db`, not the palette's index.
  `pan conv embed` does not make palette results better, and the palette's index does not make
  `pan conv search --semantic` work. State this plainly near the top of the CLI subsection.
- F-33. `pan conv scan [dirs...]`: scans `~/.claude/projects/` (the default) and records sessions.
  Options: `--watched` (scan the watch directories from `config.yaml`), `--system`, `--dry-run`,
  `--max-parallel <n>`.
- F-34. `pan conv enrich [ids...]`: AI-written summaries and tags. `--tier <n>` `1` quick (default),
  `2` detailed, `3` deep; `--deep` (tier 3); `--upgrade`; `--full`; `--with <model>`; `--prompt <text>`;
  `--limit <n>`; `--workspace <path>`; `--since <time>`; `--max-parallel <n>`; `--yes`. When the estimated
  cost passes `conversations.enrichment.cost_confirm_threshold` (default `1.00` US dollars,
  `defaults.ts:110`) it prints the estimate and asks to confirm unless you pass `--yes`.
  Ids are the numeric session ids that `pan conv list` prints.
- F-35. `pan conv search [query]`: keyword (FTS5) search over each session's summary, detailed summary,
  tags and touched files (`src/lib/overdeck/discovered-sessions.ts:33`), so enrich first. Filters:
  `--workspace`, `--model`, `--since`/`--after`, `--before`, `--min-cost`, `--max-cost`,
  `--min-messages`, `--managed`, `--unmanaged`, `--enriched`, `--not-enriched`, `--tag` (repeatable),
  `--tool` (repeatable), `--file` (repeatable), `--issue`. Semantic: `--semantic <query>` (sessions
  whose meaning is close to the text) and `--similar <id>` (sessions like that one). Output:
  `--format table|json|brief|ids` (default `table`), `--limit` (default 20), `--offset`.
- F-36. `pan conv embed [ids...]`: one vector per enriched session; required for `--semantic` and
  `--similar`. Options: `--status` (coverage: provider, model, total, enriched, embedded, percent),
  `--regenerate`, `--provider openai|voyage|ollama`, `--model <name>`, `--max-parallel <n>`.
  With `--provider ollama` (or `embedding_provider: ollama`) it installs Ollama when missing and starts it
  (`pan conv embed` passes `autoInstall: true`; `src/lib/ollama.ts:253`, `ensureOllama`).
- F-37. Session embedding settings (`defaults.ts:102-105`; YAML keys under `conversations:` in
  `~/.overdeck/config.yaml`, `merge.ts` search `embedding_provider`): `embeddings` (default `false`),
  `embedding_provider` (`openai` default, `voyage`, `ollama`), `embedding_model`
  (`text-embedding-3-small`; `voyage-code-3` and `nomic-embed-text` are the per-provider defaults),
  `embedding_auto_on_deep` (default `true`).
- F-38. `conversations.embeddings` does not gate `pan conv embed`. It turns on automatic embedding after
  a tier 2 or 3 enrichment, together with `embedding_auto_on_deep`
  (`src/lib/conversations/enrichment/index.ts:241`). It is also the **Session embeddings** feature in
  Settings → Background AI (`src/lib/background-ai/registry.ts:77`, off by default).
- F-39. Key for `pan conv embed` and `--semantic`: for OpenAI, the key saved in Settings → Providers →
  OpenAI (`config.apiKeys[provider]`, `embeddings/index.ts:199`, `search.ts:209`), else `OPENAI_API_KEY`
  from the environment (`embeddings/providers.ts:63`). For Voyage, set `VOYAGE_API_KEY` (`:115`); Settings
  → Providers has no Voyage row, so do not tell readers to add one there. Ollama needs no key.
  `pan` loads `~/.overdeck.env` into its environment before anything else (`src/cli/index.ts:12-34`,
  search `Load ~/.overdeck.env before any other imports`), so a key in that file works for `pan conv`.
- F-40. The same Settings card shows these rows below the Conversation Search block (same file, lines
  228-352): `Semantic embeddings` switch; when on: `Embedding provider` (OpenAI, Voyage AI,
  Ollama (local)), `Embedding model`, a note naming the key variable, `Auto-embed after deep enrichment`,
  `Test connection`, and `Save embeddings` (shown only after a change). The UI text says non-local
  providers receive session-derived summaries, tags, workspace paths and tool names (line 230).
