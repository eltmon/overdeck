## Glossary

- **Grok Build CLI / `grok`** — xAI's coding-agent CLI, npm package `@xai-official/grok`, verified at `grok 1.0.77 (50ca579fa996) [stable]` on this machine (`/home/eltmon/.config/nvm/versions/node/v22.22.0/lib/node_modules/@xai-official/grok/bin/grok-native`). Its home is `~/.grok/`.
- **ACP** — Agent Client Protocol: JSON-RPC 2.0 over stdio (`initialize`, `authenticate`, `session/new`, `session/load`, `session/prompt`, `session/set_config_option`, `session/update` notifications). Overdeck's client is `packages/effect-acp` plus `src/lib/acp/session-runtime.ts`.
- **ACP host** — `dist/acp-host.js` built from `src/lib/acp/host.ts`: the per-agent Node process Overdeck runs in a terminal pane. It spawns the ACP agent binary, owns the ACP session, listens on a Unix socket for messages, and writes the Overdeck transcript `~/.overdeck/agents/<id>/acp-session.jsonl`.
- **ACP provider** — the key into `ACP_PROVIDER_SUPPORT` (`src/lib/acp/providers.ts`) that tells the host which binary, args, auth method and model translation to use. Today: `kimi`, `opencode`, `opencode-go`. The launcher passes it as `--provider`, derived from `getProviderForModel(model).name` (`src/lib/agents/runtime-command.ts` line 145, `acpProvider: getProviderForModel(model).name`).
- **Harness** — Overdeck's name for the coding-agent program an agent runs in (`Harness` union, `packages/contracts/src/types.ts` line 51). This issue adds the literal **`grok`**.
- **Model provider** — Overdeck's routing/billing group for model ids (`ProviderName`, `src/lib/providers.ts` line 15). This issue adds provider **`grok`** ("Grok Build"), distinct from the existing **`xai`** provider (xAI API key routed through Claude Code).
- **Grok Build model id** — Overdeck's id for a model served by the `grok` CLI: `grok/<cli-model-id>`. The four ids: `grok/grok-4.7`, `grok/grok-4.7-build-fast`, `grok/grok-4.6`, `grok/grok-4.5`. The **CLI model id** is the part after `grok/` (what `session/set_config_option configId=model` accepts).
- **Turn usage** — the token counts and cost Grok returns for one prompt turn in `session/prompt` result `_meta.usage` (Grok extension; not the ACP spec's top-level `usage`).
- **Cost ticks** — `costUsdTicks` in Grok's turn usage. 1 tick = 10⁻¹⁰ USD (verified below).
- **Signed in** — `~/.grok/auth.json` holds at least one credential entry with a non-empty `key` and either an `expires_at` in the future or a non-empty `refresh_token` (Decision D7).
- **No-loss audit** — `tests/unit/lib/prime-agent-no-loss-audit.test.ts`: checks every harness in `KNOWN_HARNESSES` reaches every harness surface.
- **File-size ratchet** — `scripts/lint-file-size.sh`: a `src/**/*.ts(x)` file over 1000 lines may not exceed its `origin/main` line count (or its last row in `scripts/file-size-allowlist.txt`); a file at or under 1000 may grow to 1000.

## Problem

Grok appears in Overdeck only as an outside bot (`configuration/bots.mdx`, the `integrations/grok-build/` plugin) and as model ids reachable through OpenCode Zen (`opencode/grok-4.7`) or, with an xAI API key, the `xai` provider (`src/lib/settings.ts` line 249, `const xaiModels: GrokModel[] = settings.api_keys.xai`). An operator with a SuperGrok subscription and a signed-in `grok` CLI cannot run an Overdeck work agent, planning agent or conversation on it.

## Empirical findings (probed 2026-11-10 against grok 1.0.77)

All probes used a throwaway cwd in the session scratchpad and a hand-written ACP client (`node probe.mjs`). Findings the plan relies on:

1. **`grok agent stdio` speaks ACP v1.** `initialize` returns `protocolVersion: 1`, `agentCapabilities.loadSession: true`, `sessionCapabilities: { list, resume, close }`, `mcpCapabilities: { http: true, sse: true }`, `promptCapabilities.image: true`.
2. **Auth methods:** `[{ id: "cached_token", description: "Cached token from ~/.grok/auth.json" }, { id: "grok.com", name: "Grok" }]`, `_meta.defaultAuthMethodId: "cached_token"`. `authenticate { methodId: "cached_token" }` succeeds with a signed-in `auth.json`; its `_meta` carries the account email and `subscription_tier` (sensitive — must be scrubbed from fixtures).
3. **`session/new` returns `configOptions`:** `{ id: "model", category: "model", type: "select", options: grok-4.7 | grok-4.7-build-fast | grok-4.6 | grok-4.5 }` and `{ id: "reasoning_effort", category: "thought_level", options: xhigh | high | medium | low }`. `session/set_config_option { configId: "model", value: "grok-4.6" }` works.
4. **Turn usage + cost:** a one-word turn on `grok-4.6` returned `session/prompt` result `{ stopReason: "end_turn", _meta: { modelId: "grok-4.6", usage: { inputTokens: 31793, outputTokens: 32, cachedReadTokens: 640, cacheCreationTokens: 0, reasoningTokens: 31, costUsdTicks: 628180000, modelUsage: { "grok-4.6-build": {…} } } } }`. 628180000 × 10⁻¹⁰ = $0.062818 = 31153 × $2/M + 640 × $0.50/M + 32 × $6/M exactly. `grok-4.7-build-fast`: `costUsdTicks 1267680000` = 31165 × $4/M + 1664 × $1/M + 37 × $12/M exactly. `grok-4.5`: `627080000` for 31150 uncached / 640 cached / 36 out — within 0.3 % of the $2 / $0.50 / $6 rates. Note `modelUsage` is keyed by an internal id (`grok-4.6-build`); `_meta.modelId` carries the selectable id.
5. **Resume:** a fresh `grok agent stdio` process accepted `session/load { sessionId, cwd, mcpServers: [] }` for the earlier session, replayed it as `user_message_chunk` / `agent_message_chunk` updates, and kept the session's model (`currentModelId: "grok-4.6"`). Grok persists sessions under `~/.grok/sessions/<url-encoded cwd>/<sessionId>/`.
6. **MCP via ACP:** a stdio MCP server passed in `session/new.mcpServers` (`{ name, command: "node", args: [...], env: [] }`) reached `_x.ai/mcp/server_status … "status":"ready","reason":"initialized"`. So the existing PAN-4934 path (`readAcpMcpServers`, `src/lib/acp/mcp-config.ts`) delivers the managed `overdeck` MCP server to Grok with no `grok mcp` work.
7. **Launch flags parse:** `grok agent --always-approve --no-leader stdio` initializes and creates sessions. `--no-leader` forces a dedicated agent process even when `~/.grok/config.toml` enables leader mode (a leader shares one process across clients). `--always-approve` auto-approves tool calls inside Grok, including Grok subagents whose permission asks never reach the ACP client.
8. **Operator config bleeds in:** Grok merges the operator's `~/.grok` MCP servers (linear, sentry, … — they failed auth with stderr noise), plugins, hooks and `CLAUDE.md`/`AGENTS.md` files into every session. `~/.grok/config.toml` lists an `overdeck` plugin that is not in `~/.grok/installed-plugins/registry.json`.
9. **`grok models` is not a sign-in signal:** it printed `You are not authenticated.` while ACP `cached_token` auth succeeded; `grok whoami`/`grok status` fail without a TTY (`No such device or address (os error 6)`). `grok models` has no `--json`.
10. **API key precedence:** `~/.grok/README.md` ("API Key"): "The API key takes precedence over browser credentials." An `XAI_API_KEY` in the environment would silently switch a Grok agent from the subscription to API billing.
11. **Install/update:** README: `curl -fsSL https://x.ai/cli/install.sh | bash`; `grok update`. The installer also creates `~/.grok/bin/`.

## Decisions

- **D1 — New harness literal `grok` riding the ACP host (the OpenCode pattern), not a provider under the existing `acp` harness (the Kimi pattern).** Rejected alternative: `harness: acp` + provider `grok`. Reasons: `harnessBinaryName('acp')`/`resolveHarnessBinary('acp')` resolve the Kimi binary and `HarnessBinaryConfigKey` is `acp.kimi.binaryPath`; `HarnessCapabilities.binaryLabel/installHint/npmPackage/updateArgs` are per harness; `canUseHarness` denies non-Kimi models on `acp`; and the issue's acceptance text names `harness: grok` in pickers. Display name **"Grok Build"**.
- **D2 — New model provider `grok` with prefixed ids `grok/<cli-model-id>`; a fixed four-id union.** Rejected alternative: reuse the `xai` provider's bare ids. Auth and billing are provider properties: bare `grok-4.7` resolves to `xai` (API-key gate at `settings.ts` line 249, API-key routing), while the `grok` harness bills the Grok sign-in. OpenCode already keeps `opencode/grok-4.7` distinct from xai `grok-4.7`. Fixed union (not `grok/${string}`) because `grok models` has no machine-readable output (finding 9) and every other provider uses a fixed list. The `grok/` prefix does not match the xai rule `modelId.startsWith('grok-')` (`src/lib/model-fallback.ts` line 341), but it contains `/`, so it needs carve-outs before the OpenRouter slash catch-alls.
- **D3 — Cross-routing is strict, mirroring OpenCode.** `canUseHarness('grok', m)` allows only `grok/*` ids; any other harness denies `grok/*` ids. Reason text: `Grok Build model IDs require the Grok Build harness, and the Grok Build harness runs only grok/* models. Select a grok/* model.`
- **D4 — No hardcoded model fallback.** A Grok spawn without a model throws `Grok Build requires an explicit model` (mirrors `runtimes/acp.ts` line 178 `OpenCode requires an explicit model`). The CLI's own `[models] default` is never relied on: the host always calls `set_config_option model`.
- **D5 — Spawn input:** command = resolved binary path (else `grok`), args `['agent', '--always-approve', '--no-leader', 'stdio']`, env = caller env with `XAI_API_KEY` deleted (finding 10). Auth method: `cached_token` when advertised; otherwise throw `Grok sign-in is required. Run grok login, then retry.`
- **D6 — Effort:** `GROK_BEHAVIOR.effortLevels = ["low","medium","high","xhigh"]`, so the existing `clampEffort` maps `max` → `xhigh`. The host sets ACP config option `reasoning_effort` to the resolved effort after the model. Default stays `high` (effort-high-default rule). The config option id lives in the provider support table (`effortConfigId: "reasoning_effort"`), not in a new `provider === 'grok'` branch.
- **D7 — Sign-in rule (doctor + pickers):** read `$HOME/.grok/auth.json` (no subprocess). Signed in ⇔ the file parses to an object with ≥1 value that is an object with a non-empty string `key` AND (`expires_at` parses to a time after now OR a non-empty string `refresh_token`). README says tokens last 7 days and OIDC tokens refresh silently via `refresh_token`. Launch-time `authenticate` stays the authoritative check (D5 error).
- **D8 — Pickers:** the settings model catalog returns the `grok` group (all four ids) only when `resolveHarnessBinary('grok')` finds a binary AND the D7 rule says signed in; otherwise `[]`. The `grok` provider follows OpenCode's enable/harness config semantics everywhere `'opencode'` appears in provider handling.
- **D9 — Cost:** the ACP host copies Grok turn usage into the `turn_completed` transcript entry as a new optional `usage` field. A new collector sweeps `~/.overdeck/agents/*/acp-session.jsonl` and feeds `CostWriter.record()` through a new reconcile source `grok`. Event cost = `costUsdTicks / 1e10` when present (vendor number, includes the ≥200K-prompt double rate); otherwise the shared pricing table on the bare CLI id. Model recorded as `grok/<_meta.modelId>`; dedupe `requestId = grok:<sessionId>:<promptId>`. Overdeck does not read Grok's private `~/.grok/sessions/` store (OpenCode precedent: "without accessing its private stores", `src/lib/opencode-models.ts` line 1).
- **D10 — Pricing rows** (bare CLI ids, `src/lib/cost.ts` near line 192, `// xAI Grok (docs.x.ai/docs/models)`): add `grok-4.7-build-fast` ($4 / $1 cached / $12, verified) **above** the existing `grok-4.7` row (`getPricing` prefix-matches in table order), `grok-4.6` ($2 / $0.50 / $6, verified), `grok-4.5` ($2 / $0.50 / $6, approximate within 0.3 %; say so in the comment).
- **D11 — No ToS gate.** Grok Build is xAI's first-party CLI running xAI models on the operator's own xAI sign-in; its README documents ACP mode for "custom automation tools". The docs state this explicitly in the ToS section.
- **D12 — Operator `~/.grok` config is accepted, not isolated.** Isolating `GROK_HOME` would lose `auth.json`. Kimi and OpenCode also read their operator config. Documented as a known behavior (MCP-server noise, plugins, hooks).
- **D13 — Session index harness:** the host currently records `harness: "acp"` for every provider (`src/lib/acp/host.ts` line 196). For provider `grok` it records `harness: "grok"` (via a `harness` field on the provider support entry). OpenCode's existing `"acp"` value is out of scope.
- **D14 — Harness-name branch ratchet:** `scripts/lint-harness-branches.sh` pattern `N` does not list `grok`, and this issue does not add it (adding it would raise baseline rows, an operator decision). New behavior must still prefer capability fields and the provider support table over `=== 'grok'` comparisons; the only new name comparisons allowed are inside harness *lists/allowlists* that already enumerate `'opencode'`.
- **D15 — Scope stays one issue** (`sizeJustification`), following PAN-3668: adding a `Harness` literal forces coordinated edits across contracts, `src/lib`, CLI, server and frontend, and a selectable-but-unlaunchable harness delivers zero value. The work is decomposed into ~24 small items with real dependency edges.

## Requirements

### Functional

- **FR-1** `grok` is a member of `Harness`/`RuntimeName`/`KNOWN_HARNESSES` with its own `GROK_BEHAVIOR` (display name "Grok Build") and `GROK_CAPABILITIES`.

- **FR-4** The ACP host launches `grok agent --always-approve --no-leader stdio`, authenticates with `cached_token`, sets `model` to the CLI id and `reasoning_effort` to the resolved effort, and strips `XAI_API_KEY` from the child env.

- **FR-6** A restart/resume of a Grok agent or conversation passes the recorded `acp-session-id` as `--resume`, and the host issues `session/load` with it.
- **FR-7** The managed `overdeck` MCP server reaches Grok sessions through `session/new`/`session/load` `mcpServers` (existing PAN-4934 path; `GROK_CAPABILITIES.overdeckMcp = true`).
- **FR-8** Grok transcripts render in the conversation view through the existing ACP transcript adapter.
- **FR-9** Every Grok turn with usage produces exactly one cost event (provider `custom`, model `grok/<id>`, cost per D9) after a `grok` reconcile; re-running reconcile imports zero duplicates.
- **FR-10** The settings model catalog lists the `grok` group only when the CLI is installed and signed in (D8); harness pickers list "Grok Build".
- **FR-11** `pan doctor` reports Grok Build as: warn "Not installed (optional ACP harness)" + install hint; warn "Signed out" + `grok login`; or ok "<version>, signed in".

- **FR-13** Docs describe setup, models, effort, cost, resume, MCP, known config bleed and the no-ToS-gate decision.

## Restated repo rules that intersect this work

- Persistent agents only — never `claude -p`/`codex exec`-style one-shots (`no-oneshot-agents`).
- No hardcoded model fallback (`no-hardcoded-model-fallbacks`).
- Effort defaults to `high`; never default to `xhigh`/`max` (`effort-high-default`).
- No `execSync` in dashboard server code (`no-execsync-server`).
- Fake timers for delay tests (`fake-timers-for-retry-tests`).
- File-size ratchet: shrink, never raise (`scripts/lint-file-size.sh`, `docs/codebase-health/A3-file-size-guard.md`).
- New lib modules import `getAgentState` from `agent-state-read.js` to avoid `lint:circular` cycles.
- `npm run typecheck` skips `*.test.ts`; run the touched test files with `npx vitest run <files>`.
- A new HTTP route needs a `no-loss-matrix.ts` row; this plan adds **no** new route (the reconcile route gains a source value only).
- Quality gates per item: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never run the full `npm test` on the host.

## Non-goals

- A native terminal-UI `grok` harness (a `kimi-code`-style TUI) or a companion terminal attaching the Grok TUI to a conversation.
- Running Grok agents on Fly machines (`runsOnFlyMachine: false`).
- Isolating `GROK_HOME` or filtering the operator's Grok MCP servers, plugins or hooks.
- API-key (`XAI_API_KEY`) billing through the `grok` harness.
- Dynamic model discovery from `grok models`.
- Using Grok's `grok agent serve`, `headless`, or leader mode.
- Changing OpenCode's recorded session-index harness (`"acp"`) or recording OpenCode/Kimi ACP costs.
- Adding `grok` to `scripts/lint-harness-branches.sh` pattern `N` or raising any ratchet baseline or file-size allowlist row.
- Reading Grok's private `~/.grok/sessions/` store.
- Changing the `xai` provider or its bare `grok-*` ids.
- Distributing Overdeck skills or plugins into `~/.grok` (`pan sync` targets, `harness-skill-sync.ts`, Herdr integrations).

## Hazards

- **HZ-1** The Overdeck Grok Build bot plugin (`integrations/grok-build/`, server name `overdeck`) may be enabled in `~/.grok/config.toml`; its `overdeck` MCP server could collide with the managed per-agent `overdeck` server. WI-24 check 6 verifies the managed server answers; if the plugin wins, document "disable the Overdeck bot plugin on hosts that run grok-harness agents" in `configuration/harnesses.mdx` and file a follow-up.
- **HZ-2** Replay fixtures can capture the account email and team id from `authenticate`; NFR-6 + AC-22 guard it.
- **HZ-3** Grok streams large vendor notifications (`_x.ai/*`, `available_commands_update`, tool lists). The session runtime must ignore unknown `_x.ai/*` methods without failing; WI-22 replay proves it.
- **HZ-4** A Grok turn on a ≥200K-token prompt bills at double rates; only the reported `costUsdTicks` captures that. The table fallback under-reports such turns.
- **HZ-5** `grok-native` is the real process name (`bin/grok` resolves to `bin/grok-native`); `processNames` lists both.
- **HZ-6** Over-ceiling files: one added line fails the file-size ratchet; edit in place (NFR-3).
