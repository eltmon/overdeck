## 1. Glossary

| Term | Meaning in this document |
| --- | --- |
| **Conversation** | A row in the `conversations` table of `~/.overdeck/overdeck.db`. Operator chats AND agent sessions (work, review, test, ship, planning, sequencer) are rows in this one table. The DB row is the source of truth; there is no git mirror (`src/lib/overdeck/conversations.ts:1-11`). |
| **Operator conversation** | A conversation whose name does not start with `agent-`, `planning-`, or `specialist-` (`isAgentConversationName`, `src/lib/overdeck/conversations.ts:831-835`). Its `cwd` is wherever the operator opened it. |
| **Agent conversation** | A conversation created for a spawned agent. Specialists get a row at spawn (`src/lib/agents/spawn.ts:251-252`); `pan start` work agents get one from the backfill net in `src/dashboard/server/services/conversation-lifecycle.ts:49-60`. Its `cwd` is the issue workspace `workspaces/feature-<issue>` and its branch is `feature/<issue>` by convention (`src/lib/workspaces/resolver.ts:163-170`). |
| **Conversation branch** | The git branch the conversation's `cwd` is on right now, read by `resolveConversationGitInfo(cwd)` in `src/dashboard/server/services/git-info.ts:139`. Already computed for the list at `src/lib/overdeck/conversation-list.ts:169`. Not stored. |
| **Pull request (PR)** | A GitHub pull request or a GitLab merge request. One word, "PR", is used for both throughout. |
| **PR key** | The identity of a PR: `host` (for example `github.com`), `repository` (`owner/repo`), `number`. Two links with the same key are the same PR regardless of which project they came from. |
| **PR link** | One row in the new `conversation_pull_requests` table: a PR key attached to one conversation with a `source`, a `linked_at` time, and a `snapshot`. |
| **Source** | Why a link exists. One of: `manual` (operator linked it from the UI or `pan conv link-pr`), `agent` (an agent linked it with `pan conv link-pr`), `created` (the pipeline opened the PR for this conversation's issue), `branch` (the sweep detected a PR whose head branch equals the conversation branch). |
| **Explicit link** | A link whose source is `manual`, `agent`, or `created`. Explicit links override branch-detected links. |
| **Branch link** | A link whose source is `branch`. Written and refreshed only by the sweep. |
| **Dismissed link** | A branch link the operator unlinked. The row stays with `dismissed_at` set so the sweep does not re-add it. Linking the same key explicitly clears `dismissed_at`. |
| **Effective PR** | The one PR shown on a conversation row and header. Chosen by `resolveEffectivePullRequest` (§4.3): explicit links first, then branch links; open before merged before closed; then most recently updated. |
| **Snapshot** | The last known forge state of a PR, stored on the link as JSON: state, draft flag, title, branches, review decision, checks state, mergeability, additions/deletions/changed files, timestamps. |
| **Sweep** | The background job `pull-request-sync-service.ts` that (a) detects branch links for every conversation and (b) refreshes snapshots on a schedule. |
| **Forge** | `'github' | 'gitlab'`, resolved per project by `forgeForProject(projectPath)` (`src/lib/overdeck/derived-issue-state.ts:378`). Never inferred from the tracker. |
| **Read door / write door** | The single module through which routes read or write a domain. For conversations today the routes use the legacy sync functions in `src/lib/overdeck/conversations.ts` (`getConversationByName` at 1005, `setConversationProjectKey` at 1377). The Effect services `ConversationsResolver` (248) and `ConversationWriter` (391) exist but are not wired into the running server (see §2.1). Both get the new methods. |
| **Contract event** | An event declared in `packages/contracts/src/events.ts` and reduced in `packages/contracts/src/event-reducers.ts`. Only these reach the browser. Emitted with `getEventStore().emitOnly(...)` (`src/dashboard/server/event-store.ts:619`). |

## 2. Facts an implementer must know before touching code

### 2.1 Two doors, and only one of them is live

`grep -rn "ConversationsResolver\|ConversationWriter" src` hits exactly one source file: `src/lib/overdeck/conversations.ts`. `ConversationsResolverLive` and `ConversationWriterLive` are never provided at boot; `src/dashboard/server/server.ts:22-23` wires only `AgentsResolverLive` and `CostResolverLive`. Every route and CLI verb calls the legacy sync functions in the same file.

**Decision:** add the new methods to BOTH surfaces. The Effect services get typed methods (so the issue's architecture constraint is met and tests in `tests/unit/lib/overdeck/conversations.test.ts` can assert the surface); the legacy sync functions get the implementations the routes and CLI actually call. Do not wire the Effect layers into the server in this PRD.

## 3. What t3code does, and what we adopt

Studied files (absolute): `packages/contracts/src/orchestration.ts:702-788` (link schema), `apps/server/src/persistence/Migrations/050_ProjectionThreadPullRequests.ts:33-46` (link table), `apps/server/src/orchestration/decider.ts:1037-1169` (link/unlink/sync), `apps/server/src/orchestration/PullRequestSyncReactor.ts:111-327` (snapshot sweep), `apps/server/src/orchestration/ThreadPullRequestReactor.ts` (branch detection), `apps/server/src/git/GitManager.ts:1623-1629, 2111` (branch → PR), `packages/shared/src/threadPullRequests.ts:112-143` (effective PR choice), `apps/web/src/components/ThreadStatusIndicators.tsx:64-190` (badge), `apps/web/src/components/pullRequest/*` (dialog, panel, reverse links), `apps/server/src/pullRequest/linkedThreads.ts:16-45` (reverse index), `apps/server/src/orchestration/ThreadSettlementPolicy.ts:47-83` (auto-settle).

### 3.1 Adopted as-is

- Many links per conversation, keyed by host/repo/number, in a link table with a `source` column.
- Branch auto-detection on the server (their `gh pr list --head`; ours `listRepoPullRequests` + `headRefName === branch`), stored separately from explicit links.
- Effective PR rule: explicit before branch; open before terminal; most recent among equals.
- Status snapshot persisted on the link (state, title, branches, draft, review decision, checks, mergeability, diffstat, timestamps, `syncedAt`).
- Sweep every 60 s; open PRs on active conversations refreshed every sweep; closed PRs and archived conversations every 15 min; merged PRs never re-read; forced refresh right after a link is created.
- Badge on the conversation row and the open-conversation header, rendered from the persisted snapshot (no per-row live query).
- Link and unlink from the UI (dialog that accepts a URL or `#42`), from a right-click on a PR URL in the transcript, and from an agent-callable command.
- Reverse index: from a PR to the conversations linked to it.
- Dismissed tombstone for unlinked branch links so the sweep does not resurrect them.
- Search: conversation search matches `#42`, `owner/repo#42`, the URL, and the snapshot title.
- Auto-settle on merge as an opt-in setting, default off.

### 3.2 Adopted with an Overdeck-shaped substitute

| t3code | Overdeck |
| --- | --- |
| Thread carries `branch` + `worktreePath` | Conversation carries `cwd`; branch comes from `resolveConversationGitInfo(cwd)`; agent conversations fall back to `feature/<issue>` when the cwd read fails |
| `source: 'created'` from the in-app Create PR action | `source: 'created'` from the pipeline's `createReviewArtifact` call sites |
| Agent MCP tools `link_pull_request` etc. | `pan conv link-pr` / `unlink-pr` / `prs` (Overdeck has no MCP tool host; `src/lib/channels/overdeck-bridge.ts` only carries notifications) |
| Event-sourced `thread.pull-request-linked` | SQLite write + contract event `conversation.pull_requests_changed` |
| Global `/pull-requests` route with review UI | A read-only "Pull requests" list page (linked PRs across conversations, state filter, click opens conversation or PR). No in-app review UI. |

### 3.3 Deliberately dropped

- **Stacks** (`source: 'stack'`, `'stack-dismissed'`, chain layers). Overdeck has no PR stacks. The `dismissed_at` column covers the only behaviour we need from tombstones.
- **In-app PR review** (comments, reviewers, merge/close buttons, diff tabs). Out of scope; the existing issue cockpit `CodeCard` covers PR identity and diffstat for issues.
- **Thread-from-PR checkout** (`git.preparePullRequestThread`). Out of scope.

### 3.4 The one rule from the issue that overrides t3code

The issue says: "Closed or merged state is display and navigation metadata in this issue. Do not automatically archive or stop a conversation." t3code auto-settles. We ship auto-archive as a setting that defaults to **off** (WI-11) and never stop a session.

### 4.2 PR reference parsing (net-new)

New file `src/lib/overdeck/pull-request-ref.ts`:

```ts
export interface ParsedPullRequestRef { host: string; repository: string; number: number; url: string; forge: 'github' | 'gitlab'; }

/** Accepts: full PR/MR URL, "#42", "owner/repo#42". `#42` alone needs `defaultRepo`. Returns null when nothing matches. */
export function parsePullRequestRef(input: string, defaultRepo?: { host: string; repository: string; forge: 'github' | 'gitlab' }): ParsedPullRequestRef | null

export function canonicalPullRequestUrl(key: PullRequestKey, forge: 'github' | 'gitlab'): string
```

Accepted URL shapes (regex, anchored, trailing `/`, query, or fragment allowed and ignored):

- `https://github.com/<owner>/<repo>/pull/<n>` and any host when the path has `/pull/<n>` → forge `github`.
- `https://<host>/<group…>/<repo>/-/merge_requests/<n>` and the legacy `https://<host>/<group…>/<repo>/merge_requests/<n>` → forge `gitlab`.

Host and repository are lower-cased. The repository must match a repository configured for the conversation's project (`github_repo` / `gitlab_repo` in `src/lib/projects.ts:307-313`, or any `workspace.repos[].remote` for polyrepo projects via `src/lib/project-repos.ts:67-91`); otherwise the link is refused with `code: 'foreign_repository'` (FR-6).

### 4.3 Effective PR selection (pure function, shared by server and client)

New file `packages/contracts/src/pull-request-links.ts` also exports:

```ts
export function resolveEffectivePullRequest(links: readonly PullRequestLink[]): PullRequestLink | null {
  const live = links.filter((l) => l.dismissedAt === null);
  const explicit = live.filter((l) => l.source !== 'branch');
  const pool = explicit.length > 0 ? explicit : live;
  if (pool.length === 0) return null;
  const rank = (l: PullRequestLink) => l.snapshot === null ? 1 : l.snapshot.state === 'open' ? 0 : l.snapshot.state === 'merged' ? 2 : 3;
  const ts = (l: PullRequestLink) => Date.parse(l.snapshot?.updatedAt ?? l.linkedAt) || 0;
  return [...pool].sort((a, b) => rank(a) - rank(b) || ts(b) - ts(a))[0]!;
}
```

That implements `explicit ?? branch ?? none` from the issue and t3code's open-first rule.

### 4.4 Conversation branch resolution

New helper in `src/lib/overdeck/conversation-branch.ts`:

```ts
/** The branch a conversation's work lives on, or null. */
export async function resolveConversationBranch(row: LegacyConversation): Promise<string | null> {
  const info = await resolveConversationGitInfo(row.cwd);   // src/dashboard/server/services/git-info.ts:139
  if (info.branch) return info.branch;
  if (row.issueId && isAgentConversationName(row.name)) return `feature/${row.issueId.toLowerCase()}`; // convention, src/lib/workspaces/resolver.ts:163-170
  return null;
}
```

Rule: a conversation whose `cwd` is on the project's default branch (`main`, or `default_branch` from the repo config) has **no** branch for detection purposes. Otherwise every operator chat in the primary checkout would link to whatever PR `main` happened to match (none, in practice, but the rule must be explicit). Existing branch links on such a conversation are kept (the issue: "Preserve a terminal closed or merged association when a shared checkout returns to its default branch").

### 4.5 Sweep (`src/dashboard/server/services/pull-request-sync-service.ts`)

Copy the shape of `src/dashboard/server/services/conversation-rescan-scheduler.ts` (58 lines; `startX`/`stopX`, module-level timers with `unref()`, re-entrancy guard) and start it from `src/dashboard/server/main.ts` right after line 539 (`startConversationRescanScheduler()`), guarded like the auto-merge executor at `main.ts:777-783` so a peer dashboard never writes.

Constants:

```ts
const BOOT_DELAY_MS = 30_000;
const SWEEP_INTERVAL_MS = 60_000;
const SLOW_SYNC_INTERVAL_MS = 15 * 60_000;
```

One sweep does, in order:

1. **Load** all non-archived conversations plus archived ones whose links have an open snapshot (`listConversationsForPullRequestSync()` in `conversations.ts`, one SQL query).
2. **Group** by `(projectPath, forge)` so each repo's PR list is read once via `listRepoPullRequests(projectPath)` (GitHub) or `listOpenGitLabMergeRequests` + a merged/closed read (GitLab).
3. **Branch detection** per conversation: `branch = await resolveConversationBranch(row)`; if non-null and not the default branch, find rows with `headRefName === branch` (GitHub) or `source_branch === branch` (GitLab). For each match that has no row in `conversation_pull_requests` for this conversation, insert `{ source: 'branch', snapshot: <from the listing row> }`. Never insert when a row with `dismissed_at` set exists for that key. Never delete a branch link whose PR vanished from the listing (the 200-row cap can hide old PRs).
4. **Snapshot refresh** per distinct PR key (dedupe across conversations). A link is due when: `snapshot === null`; or `state === 'open'` and any linked conversation is not archived (every sweep); or `state === 'closed'`, or all linked conversations archived, and `now - syncedAt >= SLOW_SYNC_INTERVAL_MS`. `state === 'merged'` is never re-read. Source of the snapshot: the listing row when the PR is in it; otherwise one `gh pr view <n> --json <GH_PR_VIEW_FIELDS>` (`pull-requests.ts:27-57`) or the GitLab equivalent. Write only when the snapshot changed (compare JSON), and emit the event once per conversation that changed.
5. **Forced refresh**: `linkPullRequest` (§4.6) calls `syncPullRequestNow(key)` after the insert so the badge fills in within seconds.

Failures: a forge read that throws leaves the row untouched and logs once per sweep per repo with prefix `[pr-sync]`. No retries inside a sweep; the next sweep retries. Forge error backoff: after 3 consecutive failures for a repo, skip that repo for `SLOW_SYNC_INTERVAL_MS`.

## 5. Requirements

Functional:

- **FR-1** A conversation may hold zero or more PR links keyed by host/repository/number; the same key cannot be linked twice to one conversation.
- **FR-2** The sweep detects, for every conversation with a branch other than the default branch, every PR whose head branch equals that branch, and stores it as a `branch` link. Runs at boot (+30 s) and every 60 s with no dashboard client open.
- **FR-3** An operator can link a PR explicitly from the row/header menu, the link dialog, or a right-click on a PR URL in the transcript; an agent can link with `pan conv link-pr`.
- **FR-4** The effective PR is `explicit ?? branch ?? none`, open before merged before closed, most recent among equals (§4.3).
- **FR-5** Unlinking an explicit link removes it and falls back to a branch link when one exists; unlinking a branch link dismisses it so the sweep does not re-add it; linking the same key explicitly un-dismisses it.
- **FR-6** Refs that do not parse, hosts that are not GitHub or GitLab, and repositories not configured for the conversation's project are refused with a clear error and are never persisted.
- **FR-7** Each link carries a snapshot refreshed on the schedule in §4.5; merged PRs are never re-read; a forced refresh follows every explicit link.
- **FR-8** A snapshot change or a link change emits `conversation.pull_requests_changed`, and every connected client's list and open panel refresh.
- **FR-9** The badge shows number, state, draft, and review/checks attention on rows and the header, from the snapshot alone; tooltip names repository, number, and state.
- **FR-10** From a PR, the conversations linked to it are listed (cockpit and API); a Pull requests page lists all linked PRs.
- **FR-11** The pipeline's PR creation for an issue links the PR (`source: 'created'`) to every agent conversation with that `issue_id`.
- **FR-12** Links survive reload, restart, handoff (the successor conversation inherits explicit links; branch links are re-detected), and are identical from another browser client.
- **FR-13** Auto-archive on merge exists as a setting, default off, operator conversations only, never stops a session.
- **FR-14** Search matches `#n`, `repo#n`, URL, and snapshot title.

Non-functional:

- **NFR-1** The list endpoint adds at most one SQL query per page for links; no per-row forge or git reads.
- **NFR-2** The sweep reads each repo's PR list at most once per sweep and each distinct PR at most once per sweep; never `execSync`; timers `unref()`ed.
- **NFR-3** All timing tests use fake timers.
- **NFR-4** Badge colors follow the style law (§2.6); at most one colored signal per row.

## 8. Decisions made here (do not re-open during implementation)

- One table, many links per conversation, `source` column, `dismissed_at` tombstone. No stacks.
- Branch comes from the conversation's `cwd` at sweep time; nothing is stored on `conversations`.
- Default-branch conversations never get branch links; existing links are kept.
- Sweep: 60 s / 15 min / never-for-merged; forced refresh on explicit link.
- Explicit links override branch links; open before merged before closed.
- Auto-archive is a setting, default off, operator conversations only, never stops a session.
- Agent-facing door is the `pan conv` CLI, not MCP.
- Both the Effect services and the legacy sync functions get the methods; the Effect layers are still not wired into the server.
- Foreign-repository refs are refused, not stored.
