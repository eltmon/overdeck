# PAN-4756 — Move every dashboard dialog onto the shared Modal primitive

**Issue:** [PAN-4756](https://github.com/eltmon/overdeck/issues/4756). **Depends on:** PAN-4755 (closed, merged as `56e45bb0ff6`), which added the overlay tokens, `components/shared/Modal.tsx` and the New conversation dialog redesign. PRD of the dependency: `.pan/drafts/PAN-4755.md`.

All paths below are relative to `src/dashboard/frontend/src/` unless they start with `src/`, `design/`, `docs/`, `changelog.d/` or `.overdeck/`. Line numbers were verified on `feature/pan-4756` at `5dc1d1f2c01` (2026-11-16); each one also has a grep anchor because lines drift.

## Glossary

- **Modal** — the shared dialog primitive `components/shared/Modal.tsx` with its stylesheet `components/shared/Modal.module.css` (PAN-4755). It portals to `document.body`, draws the scrim and the raised panel (`--surface-overlay`, `--border-overlay`, `--shadow-overlay`), renders a header (title, optional description, Close button), a scrolling body, an optional `pinned` region and an optional `footer`, moves focus in, traps Tab, restores focus on close, closes on Escape and on a scrim click, and becomes a bottom sheet at ≤600px.
- **Bespoke frame** — a dialog that draws its own backdrop and panel, for example `<div className="fixed inset-0 … bg-black/50">` plus `<div className="bg-card … rounded-lg shadow-2xl">`, or the CSS-module classes `.forkOverlay`/`.modalOverlay`.
- **Scrim** — the dimmed full-viewport layer behind a dialog panel.
- **Overlay tokens** — `--surface-overlay`, `--surface-overlay-field`, `--border-overlay`, `--overlay-scrim` (PAN-4755 FR-1; `index.css` around line 780, grep `--surface-overlay-field: hsl(30 10% 96.8%)`).
- **ModalForm styles** — the new shared CSS module `components/shared/ModalForm.module.css` created by WI-2: the field, label, help-text and button classes every migrated dialog uses for its form controls. Today three near-copies exist: `components/Settings/anywhere/anywhereDialog.module.css`, `components/explorer/edit/editDialog.module.css`, and the field rules inside `components/newConversation/NewConversationDialog.module.css`.
- **Centered modal dialog** — a dialog that dims the whole page, centers a panel and blocks the page until closed. Side drawers, popovers, menus, command palettes, lightboxes and full-screen viewers are not centered modal dialogs (issue scope rules).
- **Accessible name** — what assistive technology announces for an element, and what Testing Library's `getByRole(role, { name })` matches.
- **Pending-input dialogs** — the dialogs that answer an agent: `AskUserQuestionDialog`, `PlanApprovalDialog`, `TerminalPermissionDialog`, `ChannelPermissionDialog`, `ConfirmationDialog` (rendered by `App/AppLiveStoreHost.tsx`).
- **UAT** — the test role's browser verification in an isolated Playwright profile against the running dashboard. It is not a committed e2e spec (same rule as PAN-4755 D16).
- **Allowlist** — the fixed list in FR-9 of files that the grep acceptance check may still match after this issue, each with its reason.

## Problem

The dashboard has 69 `.tsx` files that match `grep -rlE 'fixed inset-0|aria-modal|role="(alert)?dialog"'` (tests excluded). 15 dialogs already render through `Modal`. 44 centered modal dialogs still draw a bespoke frame: their own backdrop (`bg-black/32` … `bg-black/70`, three z-index values), their own panel (`bg-card`, `bg-popover` or `bg-background`), their own header and footer markup and their own Tailwind field classes. Under Broadsheet light `--popover` and `--card` are darker than the page, and few frames have a shadow, so the dialogs look sunken and none match each other. Each frame also re-implements (or lacks) Escape handling, scrim dismissal, focus entry, the Tab trap and focus restore.

Two more bespoke modals use CSS-module classes instead of Tailwind: `components/CommandDeck/FeatureMetadata/MarkdownModal.tsx` and `TranscriptUpload.tsx` (`.modalOverlay`/`.modalContent` in `components/CommandDeck/styles/command-deck.module.css` line 1687, grep `^\.modalOverlay`). `ForkModal.tsx` uses `.forkOverlay`/`.forkDialog` and `.forkHelpOverlay`/`.forkHelpDialog` (same file, lines 5448 and 5652).

## Decisions (made here; the executor does not re-decide)

- **D1 — One foundation item owns every Modal change.** WI-1 is the only item that edits `Modal.tsx`/`Modal.module.css`. Migration items never edit the primitive. If a migration item finds a need WI-1 does not cover, it stops and reports through `pan tell` instead of extending `Modal` itself.
- **D2 — Sizes.** `size?: 'narrow' | 'default' | 'wide' | 'xl'` replaces `wide?: boolean`. Max widths: narrow 440px, default 600px, wide 760px, xl 1000px. Map today's Tailwind width to a size with this rule: `max-w-md`, `min-w-[260px]`/`w-96` and an inline `maxWidth` of 500px or less → `narrow`; `max-w-lg`, `max-w-xl`, `max-w-2xl`, `max-w-[42rem]` and no width → `default`; `max-w-3xl` → `wide`; `max-w-5xl` and wider → `xl`. The phone bottom sheet ignores size.
- **D3 — `alert` boolean, not a `role` string.** `alert?: boolean` renders `role="alertdialog"`. A boolean keeps the literal `role="alertdialog"` out of caller files, so the FR-9 grep stays a clean signal. `SystemHealthPill.tsx` (grep `document.querySelector('[role="alertdialog"]')`) and the health-dot rule in `docs/DASHBOARD-ARCHITECTURE.md` (grep `Health-dot close rule`) keep working because `DialogProvider` passes `alert`.
- **D4 — Accessible names are preserved.** When a dialog's current accessible name differs from the title it will pass to `Modal`, it passes the old name as `ariaLabel`. When its close button is not named "Close" today, it passes the old name as `closeLabel`. The names to preserve are in the migration table. So no test query by name has to change, and the Playwright specs outside the CI list (`tests/pan-4437-continue-here.spec.ts`, `tests/pan-4754-decision-dialog.spec.ts` and others) keep matching.
- **D5 — Dismissal.** `onClose` is the action that today's close, cancel, dismiss, "Not now" or minimize control runs. `dismissible` is the condition that enables that control today (examples: `!busy`, `closable`, `isComplete`, `!isSubmitting`, `acknowledged`). A dialog that today closes only from a button now also closes on Escape and on a scrim click: the issue asks for Escape and scrim dismissal on every dialog. A dialog with no close path at all (only `ChannelPermissionDialog`: Allow and Deny) passes `dismissible={false}` and `onClose={onDeny}`; nothing calls `onClose` while `dismissible` is false.
- **D6 — Initial focus.** `Modal` focuses the first focusable element in its body unless focus is already inside the panel. A dialog that needs another start point keeps its own `useEffect` that focuses it: a parent's effect runs after `Modal`'s effect, so it wins, and `Modal` already captured the opener at render time. `autoFocus` attributes may stay (WI-1 makes `Modal` robust to them).
- **D7 — Header icons.** `Modal` has no icon slot. Decorative header icons (`List`, `FileText`, `BarChart3`, `GitBranchPlus`, `HelpCircle`, `Info`, `AlertTriangle`, `XCircle`, `CheckCircle`, `ShieldAlert` and the like) are removed with the bespoke header. Exception: the two pending-input dialogs that PAN-4754 FR-14 gave a needs-you header (`AskUserQuestionDialog`, `PlanApprovalDialog`) use `headless` and keep their own header row, restyled (D8).
- **D8 — Headless mode is for two cases only.** `headless` renders no header row, so the caller supplies its own heading and passes its id as `labelledBy`. Use it only for `AddProjectDialog` (its step components own their `h1` and Cancel button and are shared with the full-page variant) and for `AskUserQuestionDialog`/`PlanApprovalDialog` (PAN-4754 FR-13/FR-14 header: identity line, asked-age, warning icon, Minimize). Every other dialog uses the standard header.
- **D9 — ModalForm styles are a new shared file; the three existing copies stay.** WI-2 creates `components/shared/ModalForm.module.css` from `anywhereDialog.module.css` plus the `.textarea` and `.destructiveButton` rules of `editDialog.module.css`. The already-migrated Anywhere and edit dialogs keep their own modules (NonGoal). Migrated dialogs restyle only form controls and footer buttons: content such as markdown, tables, task lists, diffs, QR codes and status rows keeps its classes.
- **D10 — Delete unimported centered modals.** `DeepWipeDialog`, `SwitchModelModal`, `ProviderEnvOverrideDialog` and `GodView/FocusView` (`AgentFocusView`) have no importer in `src/` or `tests/` (verified with `grep -rln` on 2026-11-16). Migrating code nothing can render cannot be verified in a browser, and leaving it fails FR-9. `AgentDetailView` and `ContainerDetailPanel` are also unimported, but they are side drawers outside the scope rules, so they stay. The `FeatureMetadata` chain (`BadgeBar` → `MarkdownModal`, `TranscriptUpload`) is also unimported, but `CommandDeck.test.tsx` and `CommandDeck.render-count.test.tsx` `vi.mock` the `BadgeBar` path, so those two modals are migrated instead of deleted (WI-23).
- **D11 — Out of scope.** These stay as they are: command palettes (`CommandPalette`, `SearchModal`, `QuickOpen`; top-anchored with no header), `PlanDialog` (draggable, resizable, minimizes on scrim click), the side drawers, phone sheets, popovers, menus, lightboxes, full-screen viewers, the God View help overlay and `src/dashboard/frontend/src/recovery.tsx` (plain-DOM recovery shell that runs when React fails to load).
- **D12 — Browser checks are a work item plus UAT.** As PAN-4755 did with its `uat-browser-checks` item, the work agent runs the five-dialog browser check itself (WI-43) in an isolated Playwright profile against the running dashboard, and commits the ten screenshots under `design/style-guide/screenshots/pan-4756/`. The test role repeats the check during UAT. No e2e spec is committed.
- **D16 — Issue ordering.** The issue says to migrate `DialogProvider` and `ActionDialogFrame` first. The plan runs every migration in parallel after WI-1/WI-2 (they share no files), and marks those two items high priority so a sequential executor takes them first.
- **D13 — Stacking.** `Modal` keeps a single `z-index: 100`. Portaled modals stack in mount order, so a dialog opened from another dialog appears above it. Today's `z-[110]` (PrdViewer) and `z-[120]` (UpdateDialog, ResumableSessionDialog) values are dropped. A dialog that mounts later covers one that mounted earlier.
- **D14 — `size` replaces `wide` in the same item.** WI-1 changes the one `wide` caller, `components/Stage/HomePane/HomeHeader.tsx` line 74 (grep `<Modal title="Project settings" wide`), to `size="wide"`.
- **D15 — Warning tone.** `tone?: 'default' | 'warning'`. `warning` sets the panel border to `color-mix(in srgb, var(--warning) 40%, transparent)`, the PAN-4754 FR-14 needs-you tone. It is used by `AskUserQuestionDialog` (today `border-warning/40`) and `TerminalPermissionDialog` (today `border-warning/30`), and by no other dialog. `PlanApprovalDialog` (today `border-primary/30`) gets the default overlay border.

## Migration recipe (applies to WI-3 … WI-40)

For each dialog:

1. Import `Modal` from `components/shared/Modal` (relative path) and `formStyles` from `components/shared/ModalForm.module.css` (`import formStyles from '…/shared/ModalForm.module.css'`).
2. Delete the bespoke backdrop `div`, the panel `div`/`section`, the header row with its title and close button, the footer wrapper, and any `window`/`document` `keydown` listener or `onKeyDown` that only handled Escape. Delete a `useRef` that existed only for the backdrop target. Delete the dialog's own Tab trap and focus-restore effect if `Modal` now does the same (keep a focus effect that picks a specific start control, D6).
3. Render `<Modal title=… description=… onClose=… dismissible=… size=… footer=…>` with the body content as children. Put the action buttons (Cancel, Confirm, Save, Send, Close at the bottom) in `footer`. Put an error alert that must stay visible in `pinned`. Use `onSubmit` when the dialog is a form whose primary button submits; then the primary footer button has `type="submit"` and other buttons `type="button"`.
4. Keep conditional rendering as it is: `if (!isOpen) return null;` stays above the `Modal`.
4a. **Body padding.** `Modal`'s body pads only left and right (`padding: 0 20px 4px`). Put the body content in exactly one wrapper: `formStyles.form` for a form, `formStyles.content` for everything else (text, lists, markdown, tables, task panels). Both add the vertical padding. Remove the padding utilities (`p-*`, `px-*`, `py-*`) from the old body wrapper so padding is not doubled; keep its layout utilities (`space-y-*`, `flex`, `gap-*`).
5. Replace Tailwind field classes on `label`, `input`, `select`, `textarea`, help text and footer buttons with ModalForm classes: wrap the body in `<div className={formStyles.form}>` when it is a form, each label+control pair in `formStyles.field`, labels `formStyles.label`, inputs `formStyles.input` (add `formStyles.mono` for paths, tokens and URLs), selects `formStyles.select`, textareas `formStyles.textarea`, help text `formStyles.hint`, plain paragraphs `formStyles.text`, errors `formStyles.error`, secondary buttons `formStyles.button`, the primary button `formStyles.primaryButton`, a destructive primary button `formStyles.destructiveButton`. Keep every `id`, `htmlFor`, `aria-*`, `name`, `value`, `onChange`, `disabled` and `data-testid` attribute.
6. Pass `ariaLabel`/`closeLabel` where the table lists an old name to preserve (D4).
7. Run the dialog's test files; fix only structural queries (NFR-2).

### WI-1 Modal API extension (FR-1, NFR-1, D2–D8, D13–D15) — foundation

Files: `components/shared/Modal.tsx`, `components/shared/Modal.module.css`, `components/shared/__tests__/Modal.test.tsx`, `components/Stage/HomePane/HomeHeader.tsx`.

New `ModalProps` (keep the existing JSDoc style, one comment per prop):

```ts
export type ModalSize = 'narrow' | 'default' | 'wide' | 'xl';

export interface ModalProps {
  title: string;
  description?: string;
  onClose: () => void;
  dismissible?: boolean;
  onSubmit?: (event: FormEvent<HTMLFormElement>) => void;
  pinned?: ReactNode;
  footer?: ReactNode;
  /** Panel max width: narrow 440px, default 600px, wide 760px, xl 1000px. */
  size?: ModalSize;
  /** Renders role="alertdialog" (DialogProvider confirm/alert). */
  alert?: boolean;
  /** Accessible name when it must differ from the visible title (kept from a pre-Modal dialog). */
  ariaLabel?: string;
  /** Accessible name of the header close button (default "Close"). */
  closeLabel?: string;
  /** Extra header buttons, rendered before the close button. */
  headerActions?: ReactNode;
  /** Runs first for every key pressed inside the panel; call preventDefault() to skip Modal's own Escape/Tab handling. */
  onKeyDown?: (event: KeyboardEvent<HTMLElement>) => void;
  /** No header row: the caller renders its own heading and passes its id in labelledBy. */
  headless?: boolean;
  labelledBy?: string;
  /** aria-describedby target when the description is the caller's own element (AskUserQuestion's first question). Overrides `description`'s id. */
  describedBy?: string;
  /** "warning" draws the needs-you border (PAN-4754 FR-14). */
  tone?: 'default' | 'warning';
  children: ReactNode;
}
```

Behavior changes in `Modal`:

1. **Opener captured at render.** Replace `const previouslyFocused = document.activeElement …` inside the effect with `const [opener] = useState(() => (document.activeElement instanceof HTMLElement ? document.activeElement : null));` and restore `opener` in the effect cleanup (same `document.contains` guard).
2. **Initial focus kept.** In the mount effect, `if (panelRef.current?.contains(document.activeElement)) return cleanup-only;` before focusing the first body control. (A child's `autoFocus` has already run.)
3. **Keys from outside the panel are ignored.** First line of the panel `onKeyDown`: `if (!(event.target instanceof Node) || !panelRef.current?.contains(event.target)) return;`. React bubbles a nested portal's key events through the React tree; this stops an outer `Modal` from reacting to an inner one.
4. **Caller key handler first.** Next: `props.onKeyDown?.(event); if (event.defaultPrevented) return;`.
5. **Escape stops propagation.** When `Modal` handles Escape: `event.preventDefault(); event.stopPropagation(); onClose();`. When `dismissible` is false, still `stopPropagation()` and return.
6. **Clicks stop at the scrim.** `onScrimClick` calls `event.stopPropagation()` after its own logic, so a click inside a portaled modal never reaches a React ancestor's `onClick` (a kanban card, a tree row, a menu). The bespoke frames all did this with `onClick={(e) => e.stopPropagation()}` on the panel.
7. **Role and name.** `role={alert ? 'alertdialog' : 'dialog'}`; when `ariaLabel` is set use `aria-label={ariaLabel}` and omit `aria-labelledby`; else `aria-labelledby={labelledBy ?? titleId}`. `aria-describedby={describedBy ?? (description ? descriptionId : undefined)}`. Write `role` as an expression; `Modal.tsx` stays in the FR-9 allowlist either way.
8. **Header.** When `headless` is false: render `headerActions` in a `<div className={styles.headerActions}>` between `.titles` and the close button; the close button's `aria-label` is `closeLabel ?? 'Close'`. When `headless` is true: no header row; the body gets the extra class `styles.headlessBody`.
9. **Classes.** `const SIZE_CLASS: Record<ModalSize, string> = { narrow: styles.sizeNarrow, default: styles.sizeDefault, wide: styles.sizeWide, xl: styles.sizeXl };` and `className={[styles.panel, SIZE_CLASS[size], tone === 'warning' && styles.warning].filter(Boolean).join(' ')}` with `size` defaulting to `'default'`. The CSS class names avoid `default`, which is a reserved word and the module's default export name.
