## Glossary

- **Secure channel:** the encrypted byte stream between two Overdeck endpoints: a preamble, a Noise handshake (`noise-handshake@4.2.0`), then `@hyperswarm/secret-stream@6.9.2` framing. Server code today: `src/lib/anywhere/channel/`.
- **Initiator / responder:** the side that opens the transport and sends the preamble (initiator, `open.ts`), and the side that accepts it (responder, `accept.ts`). The phone is always an initiator.
- **Mode:** `link` (Noise IK, the initiator pins the responder's key), `pairing` (Noise XXpsk0 keyed by a one-time `odp_…` code), `approval` (Noise XX + SAS; machine-to-machine only).
- **Raw duplex:** the transport byte stream under the secure channel: a TCP socket, a `ws` WebSocket stream, a werift data channel (`RtcDuplex`) on the server, and a browser `RTCDataChannel` (`RtcDuplexWeb`, new) on the phone.
- **Crypto port:** a three-function interface (`sha256`, `randomBytes`, `timingSafeEqual`) that replaces the `node:crypto` calls in the protocol code, so the same source runs on Node and in a browser (pan-4823 D-7).
- **Node port / web port:** the two implementations of the crypto port. Node wraps `node:crypto`. Web uses `@noble/hashes/sha2.js` `sha256`, `globalThis.crypto.getRandomValues`, and a constant-time compare loop.
- **`b4a`:** Holepunch's "Buffer for Array" helper (`b4a@1.9.0`). On Node it returns `Buffer`s; in a browser it returns `Uint8Array`s. The channel libraries already use it.
- **`streamx`:** the stream library `secret-stream` is built on (`streamx@2.28.1`). It runs in browsers. It needs an `events` module: on Node it is the built-in; in a browser bundle it must be aliased to `bare-events`.
- **`sodium-universal` / `sodium-native` / `sodium-javascript`:** `sodium-universal@5.0.1` re-exports `sodium-native` (C addon, Node). Its `package.json` `browser` field maps `sodium-native` → `sodium-javascript` (pure JS). `sodium-javascript` is not installed today.
- **Golden vectors:** fixed inputs and their exact output bytes for the deterministic protocol functions, recorded from the code on `main` before the move.
- **Directory:** the overdeck.ai connection service (`services/connect`), `wss://connect.overdeck.ai/v1/directory`. The phone joins it as a **client** (`hello-client`, PAN-4828/PAN-4829) and uses it to pass WebRTC `signal` frames to a machine.
- **CP-1:** pan-4823's implementation checkpoint "sodium in the WebView": the pure-JS libsodium build must complete a pairing handshake and move 1 MiB in under 2 s in a phone WebView.

## Requirements

### Functional

- **FR-1 Package.** A private MIT workspace package `@overdeck/anywhere-channel` at `packages/anywhere-channel/` with three entry points: `.` (runtime-neutral protocol core), `./node` (Node crypto port), `./web` (web crypto port and browser pieces).
- **FR-2 Crypto port.** `interface CryptoPort { sha256(data: Uint8Array): Uint8Array; randomBytes(n: number): Uint8Array; timingSafeEqual(a: Uint8Array, b: Uint8Array): boolean }` with a Node implementation (`nodeCrypto`) and a web implementation (`webCrypto`). Both produce identical bytes for every golden vector.
- **FR-3 One protocol source.** `noise.ts` and `wire.ts` exist only in `packages/anywhere-channel/src/`. `src/lib/anywhere/channel/noise.ts` and `wire.ts` are deleted, and every server importer uses the package with `nodeCrypto`.
- **FR-4 One initiator sequence.** The initiator handshake (preamble, Noise messages, refusals, approval commit-then-reveal, deadline/abort) lives in `packages/anywhere-channel/src/initiator.ts`. The server's `openChannel` / `openChannelOverTransport` and the phone's `openSecureChannel` both call it.
- **FR-5 Web secure channel.** `openSecureChannel(raw, opts)` from `./web` opens a `link` or `pairing` channel over any raw duplex (streamx or Node), using `webCrypto`, and resolves with the plaintext `secret-stream` duplex and the channel marker.
- **FR-6 RTC duplex.** `RtcDuplexWeb` from `./web`: a `streamx` `Duplex` over a browser `RTCDataChannel` with the server's limits (messages ≤ 16 KiB; pause writes while `bufferedAmount` > 1 MiB; resume on `bufferedamountlow` at 256 KiB).
- **FR-7 Browser directory client.** `DirectoryWebClient` from `./web`: the phone's directory socket (`hello-client`, `signal`, `ice-servers`), authenticated by the WebSocket subprotocol `overdeck.bearer.<token>`, with the machine client's reconnect and keepalive rules.
- **FR-8 Machine dialer.** `createMachineDialer(directory)` from `./web`, with `dialMachine(environmentId, { relay, signal })`: an `RTCPeerConnection` per `(environmentId, relay)`, reused across dials, an ordered `ovdl` data channel per dial, offer/answer/candidates through `signal` frames, `iceTransportPolicy: 'relay'` when `relay`.
- **FR-9 CP-1 recorded.** A browser harness proves the web build (sodium-javascript) completes a pairing handshake with a real server responder and moves 1 MiB, and `packages/anywhere-channel/CP-1.md` records handshake and transfer times per engine.

### Non-functional

- **NFR-1 Byte compatibility.** Golden vectors pinned before the move pass unchanged after it, for both ports; a web-port initiator completes pairing and link handshakes with the server's Node-port `acceptChannel` (pan-4823 AC-5).
- **NFR-2 Browser-safe core.** No file under `packages/anywhere-channel/src/` except `crypto-node.ts`, `node.ts` and `__tests__/` imports `node:*`, calls `require(`, or names the global `Buffer`.
- **NFR-3 Server bundle unaffected.** No file under `src/` imports `@overdeck/anywhere-channel/web`; the server bundles never pull `@noble/hashes` or `sodium-javascript`. `noise-handshake`, `@hyperswarm/secret-stream`, `sodium-universal`, `sodium-native` stay external (existing `neverBundle`).
- **NFR-4 Existing behavior preserved.** Existing channel tests (`channel.test.ts`, `channel-capture.test.ts`, `rtc-transport.test.ts`, `channel-listener.test.ts`, `channel-rtc.test.ts`, `machines-exchange.test.ts`, the link-supervisor and directory-approval tests) pass with only import-specifier and crypto-port-argument edits; no assertion changes.

Exception: the CP-1 slow test drives real browsers and real sockets; it has no sleeps, only awaited events with a 60 s ceiling.
- **NFR-6 File size.** Every new file stays under 400 lines; `open.ts` (358 lines today) only shrinks. Never raise `scripts/file-size-allowlist.txt` (agents may not; the pre-push guard refuses it).
- **NFR-7 No Node-only timers in shared code.** Shared code types timers as `ReturnType<typeof setTimeout>`, never `NodeJS.Timeout`, and uses `AbortController` + `setTimeout`, never `AbortSignal.timeout` (it ignores fake timers under happy-dom; existing comment in `open.ts`).

## Decisions

- **D-1 Package shape (follows effect-acp).** `packages/anywhere-channel/package.json`: `"name": "@overdeck/anywhere-channel"`, `"private": true`, `"type": "module"`, `"license": "MIT"`, source exports, no build step:
  ```json
  "exports": {
    ".":     { "types": "./src/index.ts", "import": "./src/index.ts" },
    "./node": { "types": "./src/node.ts",  "import": "./src/node.ts" },
    "./web":  { "types": "./src/web.ts",   "import": "./src/web.ts" }
  }
  ```
  `dependencies`: `"noise-handshake": "4.2.0"`, `"@hyperswarm/secret-stream": "6.9.2"`, `"b4a": "1.9.0"`, `"streamx": "2.28.1"`, `"@noble/hashes": "2.4.0"`, `"sodium-javascript": "0.8.0"`, `"bare-events": "2.9.2"`, `"@overdeck/contracts": "workspace:*"`. `devDependencies`: `"vite": "^8.3.1"` (CP-1 harness only; same range as `src/dashboard/frontend/package.json`). Root `package.json`: add `"packages/anywhere-channel"` to `workspaces.packages` and `"@overdeck/anywhere-channel": "workspace:*"` to **`devDependencies`** (bundled, never installed by users; Fact 9). `src/dashboard/server/package.json`: add `"@overdeck/anywhere-channel": "workspace:*"` to `dependencies` next to `@overdeck/contracts`. No tsdown/vitest alias is needed: resolution goes through the workspace symlink to the source exports, as for effect-acp.
- **D-2 Two ports, as pan-4823 D-7 says.** The web port uses `@noble/hashes/sha2.js` and `crypto.getRandomValues`, not `sodium-universal`'s `crypto_hash_sha256`. Reason: the port must be usable before sodium loads and must not pull libsodium into callers that only hash; it also keeps the D-7 text true. `timingSafeEqual` stays in the port and `accept.ts` uses `nodeCrypto.timingSafeEqual`, so the port has no dead member.
- **D-3 The port is an explicit argument.** Protocol functions that hash or draw randomness take `crypto: CryptoPort` as their first parameter: `pairingSecrets(crypto, code)`, `approvalNonce(crypto)`, `approvalCommitment(crypto, hash, nonce)`, `approvalSas(crypto, hash, n1, n2)`. No module-global "current port": the cross-port test runs both ports in one process.
- **D-4 Bytes are `Uint8Array` in signatures; `b4a` at runtime.** Package signatures use `Uint8Array`. Implementations use `b4a.from/alloc/concat/equals/toString/copy`. On Node `b4a` returns `Buffer`, so server runtime values stay `Buffer`s; server code that calls a `Buffer`-only method on a package result converts with `Buffer.from(x.buffer, x.byteOffset, x.byteLength)` or uses `b4a.toString(x, 'hex')`. `approvalSas` reads the first four digest bytes with `new DataView(d.buffer, d.byteOffset, 4).getUint32(0, false)`. `PairingSecret.psk` (`accept.ts`) and the `psk` fields in `pairing-credentials.ts` become `Uint8Array`.
- **D-5 Structural raw duplex.** `wire.ts` replaces `import type { Duplex } from 'node:stream'` with an exported structural type that both Node `Duplex` and `streamx` `Duplex` satisfy:
  ```ts
  export interface RawDuplex {
    write(chunk: Uint8Array): boolean;
    on(event: string, listener: (...args: any[]) => void): unknown;
    off(event: string, listener: (...args: any[]) => void): unknown;
    destroy(error?: Error): void;
    readonly destroyed: boolean;
  }
  ```
- **D-6 The initiator seam (widening of W-WEB1, recorded as an auto-decision).** pan-4823 W-WEB1 step 3 keeps `open.ts` on the server. It still does: `openChannel`, `openChannelOverTransport`, transports (`tcp://`, `wss://`, `rtc://`), `setRtcDialer`, `FLY_INSTANCE_PARAM` stay there. Only the transport-agnostic handshake sequence moves into `initiator.ts`, because the phone needs exactly that sequence and a second copy would drift (NFR-1 of pan-4823). The seam is a **synchronous finisher**:
  ```ts
  export interface InitiatorDone<R extends RawDuplex = RawDuplex> {
    raw: R;
    handshake: HandshakeResult;
    /** Bytes that arrived behind the last handshake frame. */
    leftover: Uint8Array;
    channel: ChannelMarker;
  }
  /** Called in the same tick as the last handshake frame; must build the secure stream synchronously. */
  export type InitiatorFinish<T, R extends RawDuplex = RawDuplex> = (done: InitiatorDone<R>) => T;
  export function runInitiatorHandshake<T, R extends RawDuplex>(
    raw: R, label: string, opts: InitiatorOptions, crypto: CryptoPort,
    track: (raw: R, reader?: FrameReader) => void, finish: InitiatorFinish<T, R>,
  ): Promise<T>;
  export function withDeadline<T, R extends RawDuplex>(
    label: string, opts: { signal?: AbortSignal; timeoutMs?: number },
    run: (signal: AbortSignal, track: (raw: R, reader?: FrameReader) => void) => Promise<T>,
  ): Promise<T>;
  ```
  `finish` is invoked after `reader.detach()` and after the final handshake message (pairing message 3, or the approval nonce reveal) is written, exactly where `open.ts` `finish()` runs today. Returning a promise from the handshake and building the stream in the caller's `await` continuation is forbidden: bytes arriving between detach and stream construction would be lost (Fact 4).
  `ChannelOpenError`, `ChannelOpenErrorCode`, `ChannelOpenDetail`, `DEFAULT_OPEN_TIMEOUT_MS`, `OpenChannelOptions` (renamed `InitiatorOptions` in the package) and `ChannelMarker` move to the package; `open.ts` re-exports `ChannelOpenError`, `type ChannelOpenErrorCode`, `type ChannelOpenDetail`, `DEFAULT_OPEN_TIMEOUT_MS` and `type OpenChannelOptions` (alias of `InitiatorOptions`), and `channel-socket.ts` re-exports `type ChannelMarker`, so no importer listed in Fact 3 changes (class identity for `instanceof` is preserved because there is one class).
- **D-7 Web channel API.** `./web` exports:
  ```ts
  export type WebChannelOptions =
    | { mode: 'link'; localKey: StaticKeyPair; remoteKeyHex: string; signal?: AbortSignal; timeoutMs?: number }
    | { mode: 'pairing'; localKey: StaticKeyPair; pairingCode: string; signal?: AbortSignal; timeoutMs?: number };
  export interface SecureChannel { stream: Duplex /* streamx; the SecretStream, plaintext */; channel: ChannelMarker }
  export function openSecureChannel(raw: RawDuplex, opts: WebChannelOptions, label?: string): Promise<SecureChannel>;
  ```
  `StaticKeyPair = { publicKey: Uint8Array; secretKey: Uint8Array }` is defined in the package (`noise.ts`); the server's `MachineKeyPair` (`Buffer` fields) is assignable to it. Approval mode is not offered on the web (the phone never runs approvals). Default timeout 10 s (same as `DEFAULT_OPEN_TIMEOUT_MS`).
- **D-8 Dialer reuses one peer connection per machine.** Because the machine closes an older peer connection when a new offer arrives for the same key (Fact 12), `dialMachine` keeps a `Map<"<environmentId>|direct|relay", PeerEntry>` and opens additional `ovdl` channels on a live connection, mirroring `RtcTransport.dial`. The pan-4823 signature `dialMachine(environmentId, { relay })` becomes a method on `createMachineDialer(directory)`, because the dialer needs the directory socket and a cache.   4. An `error` frame whose `session` equals this entry's session closes the entry and rejects pending dials with `Error(frame.message)` (covers `peer_offline`).
  5. Later dials on a live entry call `pc.createDataChannel('ovdl', { ordered: true })` and await `open`.
  6. A dial resolves with `new RtcDuplexWeb(channel, environmentId)` on `open`. It rejects (and closes the channel; and closes the entry only if no channel on it ever opened) on: channel `close` before open, `connectionState` `failed`/`closed`, `signal` abort (an `Error` with `name = 'AbortError'`), or timeout (default 15,000 ms).
  7. `pc.ondatachannel` channels (the machine never opens one) are closed immediately.
  8. `close(id?)` closes the matching entries (all when omitted) and their handlers.

## Hazards

- **H-1 Same-tick stream construction.** Building the secret stream in an `await` continuation instead of inside `finish` loses bytes that arrive behind the last handshake frame. WI-4's leftover test guards it.
- **H-2 `Buffer`-only methods on `Uint8Array` results.** Typecheck catches most; runtime values on Node are still `Buffer`s, so a missed spot passes tests but would break in the browser. AC-12's grep covers the package; server code may keep `Buffer`.
- **H-3 Contracts not merged (D-9).** Use the D-9 fallback rather than stalling; review must check the temporary copy matches `origin/feature/pan-4828` and carries the deletion comment.
- **H-4 Emulator and Playwright on a shared host.** The emulator is CPU-heavy; run it once, stop it with `adb emu kill`, and never leave it running. Playwright WebKit here depends on locally copied libraries (machine memory `playwright-webkit-local-libs`); if WebKit fails to launch, record the launch error in `CP-1.md` and treat the leg as not run, not as a CP-1 failure.
- **H-5 tsdown resolution.** The server bundles must resolve `@overdeck/anywhere-channel` through the workspace symlink and inline it (`alwaysBundle`), while `noise-handshake` stays external. CI's build job proves it; locally `npm run build` is optional per repo policy.
- **H-7 Unhoisted dependencies.** `b4a`, `streamx`, `@noble/hashes`, `sodium-javascript`, `bare-events` and `vite` resolve only from `packages/anywhere-channel/` (Fact 8). Files under `tests/` and `src/` must not import them directly; import the package instead.
- **H-6 `bun.lock` churn.** `bun install` rewrites `bun.lock`; commit it in WI-2 only, and re-run `bun install` after any rebase that touches `package.json`.
