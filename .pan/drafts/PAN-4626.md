# PAN-4626 — Stop and archive show a visible "leaving" state on the conversation row

**Issue:** https://github.com/eltmon/overdeck/issues/4626
**Follow-up to:** PAN-4584 (merged in #4588, commit `21fe8c7b789`)
**Status:** design decided in the issue body; this PRD lowers it to executable steps.

## Glossary

- **Conversation row** — `ConversationRow` (`src/dashboard/frontend/src/components/CommandDeck/ConversationRow.tsx`). The row root is a `<button>` whose class is `itemClass` (line 313). It has two variants: `flat` (title on line 1, `conversationMetaLine` on line 2) and `nested` (one line, project tree).
- **Archive pending** — the archive POST for that conversation is in flight. Read through `mutations.isArchivePending(name)`, which reads TanStack's MutationCache through `useMutationState` filtered by `mutationKey: ['conversation-archive']` (PAN-4584).
- **Stop pending** — the same idea for `POST /api/conversations/:name/stop`. Today it does not exist per conversation; this issue adds `mutations.isStopPending(name)` with `mutationKey: ['conversation-stop']`.
- **Leaving state** — the one visual treatment shared by stop and archive: the row is dimmed (`opacity: 0.45`), non-interactive, and says in words what is happening (`Archiving…` / `Stopping…`).
- **Leaving kind** — `'archive' | 'stop' | null`. Archive wins when both are pending, because archive also ends the session.
- **Hold until refetch** — a mutation's `onSuccess` awaits (returns a promise chained on) the `invalidateQueries(...)` promise, so TanStack keeps the mutation `pending` until the `['conversations']` refetch resolves.
- **CI frontend subset** — CI runs only the frontend test files listed in root `package.json` script `test:frontend-subset`. A frontend test that is not listed there never runs on CI.

## Problem (verified against the code at `312995f9380`)

1. **Archive pending looks like a busy agent.** `ConversationRow.tsx` lines 459-464 render `Loader2` with `styles.conversationWorkingSpinner` in the status-dot slot:
   ```tsx
   {archivePending ? (
     <Loader2
       size={spinnerSize}
       className={styles.conversationWorkingSpinner}
       aria-label={`Archiving ${conv.name}`}
     />
   ) : conv.forkStatus && conv.forkStatus !== 'failed' ? (
   ```
   `.conversationWorkingSpinner` (`command-deck.module.css` ~line 2709) is `color: var(--success); animation: spin 1s linear infinite;` — the same green spinner `WorkingSpinner` uses for "agent is working". The only other cue is the `titleRegenerating` shimmer (lines 544 and 568), which is easy to miss.
2. **Stop has no pending state.** `stopMutation` (`useConversationMutations.ts` line 162) has no `mutationKey` and no `onError`. `stop` is gated on the hook-wide `stopIsPending` (line 338, used at line 352: `stop: (name) => { if (!stopIsPending) stopMutate(name); },`). While conversation A's stop is in flight, `stop(B)` is silently dropped. `stopConversation` (line 17) throws a fixed message and ignores the server's `{ error }` body, although `handleConversationStop` (`src/lib/overdeck/conversation-runtime.ts` line 1038) returns `{ error: 'Conversation not found' }` (404) and `{ error: 'Internal server error' }` (500).
3. **Snap-back gap.** `archiveMutation.onSuccess` (line 144) and `stopMutation.onSuccess` (line 165) call `queryClient.invalidateQueries({ queryKey: ['conversations'] });` without returning it. The mutation leaves `pending` as soon as the POST returns, before the refetched list (HTTP `fetchConversations`, observed in `ConversationList.tsx` line 375) removes or updates the row. Any pending treatment ends before the row changes.

## Design (decided in the issue — do not re-litigate)

1. Dim the whole row with `.conversationRowLeaving` (`opacity: 0.45; transition: opacity 150ms ease-out; pointer-events: none;`). Under `prefers-reduced-motion: reduce` drop the transition, keep the dim. Applied when `archivePending || stopPending`. Keep `aria-busy`.
2. Say it in words. Flat rows: replace the whole `conversationMetaLine` contents with `Loader2` (size 10) + `Archiving…` / `Stopping…` in `var(--muted-foreground)`. Nested rows: append the same label after the title.
3. Remove the confusable spinner: revert the PAN-4584 dot-slot `Loader2`; drop `titleRegenerating` for archive pending (retitle pending keeps it).
4. Stop button: while `stopPending`, swap `X` for `Loader2` and make it inert (`aria-disabled="true"`, no click or key handler).
5. Per-conversation stop pending: `mutationKey: ['conversation-stop']`, `isStopPending(name)` through `useMutationState`, per-name dedupe in `stop`, `onError` → `toast.error(<server message or 'Failed to stop conversation'>, { duration: 6000 })`. No success toast.
6. Hold until refetch for both mutations.
7. `ConversationPanel` header shows `Stopping…` while that conversation's stop is pending, the same way it shows `Archiving…`.

## Decisions made in this document

- **D1 — Archive wins over stop.** `leavingKind = archivePending ? 'archive' : stopPending ? 'stop' : null`. Archiving also ends the session, so "Archiving…" is the truer label.
- **D2 — New muted spinner class.** The label spinner must not use `.conversationWorkingSpinner` (green). Add `.conversationLeavingSpinner { flex-shrink: 0; color: var(--muted-foreground); animation: spin 1s linear infinite; }`. The stop-button spinner uses the same class.
- **D3 — The stop button stays visible while leaving.** `.conversationStopBtn` is `opacity: 0` and only shows on `:hover`. `pointer-events: none` on the row ends hover, so the stop spinner would be invisible. Add `.conversationRowLeaving .conversationStopBtn { opacity: 1; }`.
- **D4 — Inert means no handlers, not only CSS.** jsdom's `fireEvent.click` ignores `pointer-events`, and in a real browser keyboard Enter/Space on a focused element still fires. So while leaving: the stop `<span>` renders without `onClick`/`onKeyDown` and with `aria-disabled="true"`; the row root's `onClick` and `onContextMenu` return early (`if (leavingKind) return;` — keep `e.preventDefault()` in the context-menu handler so the browser menu does not appear).
- **D5 — Status label markup.** `<span className={styles.conversationLeavingStatus}><Loader2 size={10} className={styles.conversationLeavingSpinner} aria-hidden="true" /><span>{leavingKind === 'archive' ? 'Archiving…' : 'Stopping…'}</span></span>`. Use the ellipsis character `…` (U+2026), as PAN-4584 did. No `role="status"` inside the row (it is a `<button>`; `aria-busy` already carries the state).
- **D6 — Order in `onSuccess`.** Make `onSuccess` `async` and `await queryClient.invalidateQueries({ queryKey: ['conversations'] });` **first**, then run the side effects (close panes, deselect, toast). The row stays dimmed through the refetch, and the tab closes and the toast appears once the row is gone. Running the side effects first would close the pane hosting a `ConversationPanel` during the refetch; TanStack drops mutate-level callbacks (the panel's `onArchived`) when the calling component unmounts first. A failed refetch does not reject the invalidate promise (TanStack default `throwOnError: false`), so the mutation still succeeds.
- **D7 — Panel header.** Reuse the existing archive status span; render it when archive or stop is pending, with the text chosen by D1. Give it `aria-label` `Archiving conversation` / `Stopping conversation` so tests can tell it apart from the existing turn-abort button, which also reads `Stopping…` (`ConversationPanel.tsx` ~line 802). Keep `ConversationPanel.tsx` at or under its current 1520 lines.
- **D8 — Register hook suites in CI.** Add `src/components/CommandDeck/__tests__/useConversationMutations.archive.test.tsx` and `src/components/CommandDeck/__tests__/useConversationMutations.stop.test.tsx` to `test:frontend-subset` in root `package.json`.
- **D9 — Out of scope:** disabling the "Stop agent" items in `ConversationActionMenu.tsx` (line 313) and the panel header menu (line 946). The per-name dedupe in `stop()` already makes a second click a no-op.

## Requirements

- **FR-1** `useConversationMutations` exposes `isStopPending(name)`, backed by `mutationKey: ['conversation-stop']` and `useMutationState`, shared across hook instances on one `QueryClient`.
- **FR-2** `stop(name)` sends a request unless a stop for that same name is pending; a pending stop for another name does not block it.
- **FR-3** A failed stop toasts the server's `error` message, or `Failed to stop conversation` for a non-JSON body, with `{ duration: 6000 }`; pending clears so the row is restored. No success toast.
- **FR-4** Archive and stop mutations stay pending until the `['conversations']` refetch triggered in `onSuccess` resolves.
- **FR-5** While archive or stop is pending, the row root has `styles.conversationRowLeaving` and `aria-busy="true"`; row click and context menu do nothing.
- **FR-6** The status-dot slot never renders an archive spinner; archive pending no longer applies `titleRegenerating`.
- **FR-7** While stop is pending, the stop control renders `Loader2` instead of `X`, has `aria-disabled="true"`, and clicking or pressing Enter on it calls nothing.
- **FR-8** Flat rows replace the meta line with `Archiving…` / `Stopping…` plus a size-10 `Loader2`; nested rows append the same label after the title.
- **FR-9** The `ConversationPanel` header shows a `Stopping…` status while that conversation's stop is pending.
- **NFR-1** Under `prefers-reduced-motion: reduce`, `.conversationRowLeaving` has `transition: none` and keeps `opacity: 0.45`.
- **NFR-2** `ConversationPanel.tsx` stays ≤ 1520 lines; `ConversationRow.tsx` stays under the 1000-line ceiling.
- **NFR-3** The `useConversationMutations` return object keeps identity stable except when a pending list changes (PAN-4560 render-count tests stay green).
- **NFR-4** No raw `setTimeout` waits in tests; use deferred promises and `waitFor`.
