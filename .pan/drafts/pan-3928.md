# PAN-3928 — `pan start` prints a backend-aware attach hint (Herdr panes)

**Issue:** https://github.com/eltmon/overdeck/issues/3928
**Parent:** PAN-3917 (The Overdeck Cut) follow-up, from the cut's integration notes and the Codex review of the integrated diff.
**Status:** draft (planned 2026-09-19, `pan plan --auto`)

## Problem

After a Herdr launch, `pan start` still ends with `Attach:   tmux attach -t agent-<issue>`. On a
Herdr host that agent has no tmux session at all, so the printed command fails. Two of the four
print sites also omit the `-L <socket>` flag, so on a tmux host the command shows nothing either
(agents live on the `overdeck` socket, never the default one). The fix is one pure helper that
renders the backend, the pane's location, and the attach command from what the launch already
persisted on the agent state, used by every CLI site that prints an attach hint.

## Glossary

| Term | Meaning |
| --- | --- |
| **Terminal backend** | The adapter that owns agent terminals: **Herdr** (default) or **tmux**. See `docs/TERMINAL-BACKENDS.md`. |
| **Instance name** | The per-home name both backends namespace by: `overdeck` for `~/.overdeck`, `overdeck-<sha1[0..8]>` otherwise. `managedInstanceName()` in `src/lib/instance-name.ts`. tmux uses it as the socket (`tmux -L <instance>`), Herdr as the session (`herdr --session <instance>`). |
| **Herdr session** | A named persistent Herdr server. This host's `herdr session list` shows `default` (stopped) and `overdeck` (running), so every Herdr command aimed at Overdeck agents MUST pass `--session <instance>`; a bare `herdr agent attach` targets the `default` session. |
| **Herdr workspace** | A Herdr container of panes. `workspaceFor(issueId, cwd)` creates one per issue with `label: issueId` and stamps the `issue` token on it. Its id looks like `wG`. |
| **Pane id** | Herdr's pane handle, `<workspaceId>:p<n>`, e.g. `wG:p2`. On tmux the "pane" is the session named after the agent id. |
| **Agent id** | `agent-<issue-lowercase>`, e.g. `agent-pan-3705`. It is the tmux session name **and** the live Herdr agent name (`agent.rename` binds it at launch), so `herdr agent attach <agent-id>` resolves it directly. |
| **`AgentState`** | The per-agent record at `~/.overdeck/agents/<id>/state.json`, typed in `src/lib/agents/agent-state-read.ts`. |
| **Attach hint** | The `Backend:` and `Attach:` lines a CLI command prints so a human can open the agent's terminal. |
| **Print site** | A `console.log` in a CLI command that emits the attach hint. There are four (below). |

## Decisions

- **D1 — One pure helper, four callers.** `src/lib/terminal-backends/attach-hint.ts` exports
  `describeAttach()` and `attachHintLines()`. No subprocess, no socket, no config load beyond the
  instance-name helpers, so it is safe in every CLI path including the already-running fast exit.
- **D2 — Backend rule.** `backend === 'herdr'` ⇒ Herdr form. `backend === 'tmux'` **or undefined**
  (an agent spawned before PAN-3917 W12) ⇒ tmux form. A Herdr agent with no `paneId` still gets the
  Herdr attach command (its target is the agent name); its location line says `pane not recorded`.
- **D3 — Persist the Herdr workspace id** as a new optional `AgentState.paneWorkspaceId`, stamped
  next to `paneId`. Named to avoid the existing registry-row `workspaceId`. Chosen over parsing the
  `<workspace>:p<n>` prefix off the pane id, which would treat an opaque Herdr handle as a format.
- **D4 — Never a literal instance name.** The tmux form uses `getManagedTmuxSocketName()`; the Herdr
  form uses `herdrSessionName()`. `-L overdeck` literals at S2/S3 are removed.
- **D5 — `pan recover` always prints the tmux form** by passing only `{ id: state.id }` to the helper,
  because `recoverAgent` relaunches through tmux `createSession` regardless of the original backend.
  Restamping `backend`/`paneId` on relaunch is a separate defect (NonGoal).
- **D6 — Output shape.** Two lines replace the one `Attach:` line at every site: a `Backend:` line
  naming the backend and pane location, then the `Attach:` command. The already-running branch (S2)
  keeps its `chalk.dim` label / `chalk.cyan` command styling by using `describeAttach()`; the other
  three use `attachHintLines()` and stay unstyled, as their blocks are today.
- **D7 — `start-fresh-session.ts:104`** keeps its `tmux -L overdeck attach -t` error text: it only
  fires when a **live tmux session** survives a stop, so it is correct where it runs. NonGoal.

### W2 — The attach-hint helper and its unit test (FR-1, FR-2, FR-6, NFR-1)

**Files:** `src/lib/terminal-backends/attach-hint.ts` (new),
`tests/unit/lib/terminal-backends/attach-hint.test.ts` (new).

Create the module exactly as follows (adjust nothing but comments):

```ts
/**
 * The attach hint a CLI command prints after it starts or finds an agent
 * (PAN-3928). Rendered from what the launch persisted on the agent state:
 * a Herdr agent has no tmux session, so the hint must name the backend the
 * pane really lives on. Pure — no subprocess, no socket — so every CLI path
 * can print it.
 */
import { getManagedTmuxSocketName } from '../tmux.js';
import { herdrSessionName } from './select.js';
import type { TerminalBackendName } from './types.js';

export interface AttachHintAgent {
  readonly id: string;
  readonly backend?: TerminalBackendName;
  readonly paneId?: string;
  readonly paneWorkspaceId?: string;
}

export interface AttachHint {
  readonly backend: TerminalBackendName;
  /** Where the pane lives: `herdr (workspace wG, pane wG:p2)` or `tmux (session agent-pan-1)`. */
  readonly location: string;
  /** The shell command that opens the agent's terminal. */
  readonly command: string;
}

/**
 * `backend === 'herdr'` renders the Herdr form; `'tmux'` and an absent backend
 * (an agent spawned before PAN-3917 W12) render the tmux form. Recovery and
 * resume relaunch on tmux, so `pan recover` passes only `{ id }`.
 */
export function describeAttach(agent: AttachHintAgent): AttachHint {
  if (agent.backend === 'herdr') {
    const parts = [
      agent.paneWorkspaceId ? `workspace ${agent.paneWorkspaceId}` : null,
      agent.paneId ? `pane ${agent.paneId}` : null,
    ].filter((part): part is string => part !== null);
    return {
      backend: 'herdr',
      location: parts.length > 0 ? `herdr (${parts.join(', ')})` : 'herdr (pane not recorded)',
      command: `herdr --session ${herdrSessionName()} agent attach ${agent.id}`,
    };
  }
  return {
    backend: 'tmux',
    location: `tmux (session ${agent.id})`,
    command: `tmux -L ${getManagedTmuxSocketName()} attach -t ${agent.id}`,
  };
}

/** The two `Commands:` lines, indented like the surrounding block. */
export function attachHintLines(agent: AttachHintAgent, indent = '  '): string[] {
  const hint = describeAttach(agent);
  return [`${indent}Backend:  ${hint.location}`, `${indent}Attach:   ${hint.command}`];
}
```
