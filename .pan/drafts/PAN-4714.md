- **Plain click** — a primary-button (`button === 0`) click with no Ctrl, Meta (Cmd), Shift or
  Alt modifier and not already `defaultPrevented`.

## Problem

Agents are told to link every issue ID, so conversations are full of links like
`[PAN-4645](https://github.com/eltmon/overdeck/issues/4645)`. Today `TranscriptLink` renders
every link as `<a href target="_blank" rel="noopener noreferrer">`, so a click opens GitHub in a
new browser tab and the operator leaves the dashboard. The operator wants a click to open that
issue's pop-out drawer inside the dashboard, so they keep their place in the conversation.

## Decisions (made here; auto mode)

1. **Scope: conversation transcripts only, in a layout that mounts the issue drawer.**
   **Correction (first review cycle, PAN-4714):** the conversation-context gate alone is not
   enough. `ConversationPanel` always wraps its content in `ConversationPullRequestProvider`, but
   `<IssueDrawer />` is mounted only in the main dashboard layout (`App.tsx`) — not in the
   standalone pop-outs (`/popout/conversation/<id>`, `/popout/flywheel-conversation`) or the
   mobile app (`/m`), which also render `ConversationPanel`. The fix adds
   `IssueDrawerAvailableContext` (`components/drawer/IssueDrawer.tsx`), provided `true` only by
   the layout that renders `<IssueDrawer />`; `TranscriptIssueLink` falls back to a plain new-tab
   anchor when the context is absent/`false`. `ChatMarkdown` also renders inside `PrdViewer`
   (`z-[110]`, above the drawer's `z-[100]`) and `PlanApprovalDialog` (`z-[100]`); an ungated
   click there would open the drawer behind the modal and rewrite the URL with nothing visible —
   both are outside the main layout's provider, so they fall back correctly too. Outside a
   conversation, or in a conversation host without the drawer mounted, issue links keep today's
   new-tab behaviour.
2. **Seam: `TranscriptLink`.** `ChatMarkdown`'s `a` renderer stays unchanged in behaviour.
   `TranscriptLink` checks PR refs first (unchanged), then tracker issue URLs, and delegates
   issue URLs to a new `TranscriptIssueLink` component.
3. **Parser + resolver live in `@overdeck/contracts`** beside `parsePullRequestRef`, as a new
   module `packages/contracts/src/tracker-issue-ref.ts`. It is pure, testable without React,
   and reusable by the server later. The frontend must NOT import `src/lib/issue-id.ts` (it
   contains `require('node:fs')`). `src/dashboard/frontend/src/lib/issueLinks.ts` is not
   extended: it maps ID→URL from a hardcoded prefix table, which is the wrong direction.
4. **Project resolution uses the registered projects, not a new table.** The prefix comes from
   each project's `issue_prefix` (`linearTeam`), the repo from `github_repo`, and the tracker
   from a new `tracker` field on `/api/registered-projects` computed by the existing
   `tryResolveProjectTrackerType`. A GitHub issue URL resolves only for a project whose
   `tracker === 'github'`; a Linear URL resolves only for a project whose
   `tracker === 'linear'` and whose prefix equals the identifier's prefix.
5. **Projects without `issue_prefix` do not resolve** (e.g. `papers-please`, `orca`: their
   `linearTeam` is `null`). Their links keep today's behaviour.
6. **Linear workspace slug is ignored.** Overdeck does not store it; the prefix match is enough.
7. **GitHub host must be `github.com`** (registered `github_repo` carries no host). GitHub
   Enterprise, `www.github.com`, GitLab and Rally issue URLs are out of scope.
8. **URL tails are allowed.** `/issues/4645#issuecomment-1`, `/issues/4645/` and `?foo` still
   resolve to `PAN-4645`. `/issues`, `/issues/new` and `/issues/0` do not resolve.
9. **Click semantics.** Only a plain click is intercepted: `preventDefault()` then
   `openIssue(issueId, 'overview')`. The anchor keeps `href`, `target="_blank"` and
   `rel="noopener noreferrer"`, so Ctrl/Cmd-click, Shift-click, middle-click (browsers fire
   `auxclick`, which never reaches `onClick`) and the browser context menu behave exactly as
   today.
10. **Same-issue click.** Inside the drawer's own conversation tab (`DrawerAgentSession` renders
    `ConversationPanel`), a click on another issue's link swaps the drawer to that issue; a click
    on the open issue's own link switches the drawer to its `overview` tab. Both follow
    directly from `openIssue(id, 'overview')`; no special case is added.
11. **Registered projects not loaded yet.** Until the `['registered-projects']` query resolves,
    the link cannot resolve and a click falls through to the new-tab default. Accepted: the
    sidebar loads that query at app start, so in practice it is already cached.
12. **Resolved marker.** A resolved link carries `data-issue-id="<ISSUE-ID>"`, which tests and
    the Playwright check use to find it and to wait for resolution.
13. **CI subset.** Add the new component test file and the existing
    `ChatMarkdown.pull-request-links.test.tsx` (the `TranscriptLink` change can regress it) to
    `scripts/frontend-test-subset.txt` in sorted position.
14. **Playwright check is a UAT checkpoint, not a committed spec.** The existing e2e harness

    conversation; the work agent instead drives a workspace Vite dev server in an isolated

```ts
/**
 * Tracker issue references (PAN-4714): parse a tracker issue URL found in a
 * conversation (GitHub `/issues/<n>`, Linear `/issue/<KEY-n>`) and resolve it to
 * the Overdeck issue ID of a registered project, so the dashboard can open that
 * issue's drawer instead of the tracker. Resolution reads the project registry
 * (`/api/registered-projects`); there is no prefix table here.
 */

export type TrackerIssueUrlRef =
  | { readonly tracker: 'github'; readonly repository: string; readonly number: number }
  | { readonly tracker: 'linear'; readonly identifier: string };

/** The `/api/registered-projects` fields resolution reads. `linearTeam` is the issue prefix. */
export interface TrackerIssueProject {
  readonly linearTeam?: string | null;
  readonly githubRepo?: string | null;
  readonly tracker?: string | null;
}

const GITHUB_ISSUE = /^(?:https?:\/\/)?github\.com\/([\w.-]+\/[\w.-]+)\/issues\/(\d+)\/?(?:[?#].*)?$/i;
const LINEAR_ISSUE = /^(?:https?:\/\/)?linear\.app\/[\w.-]+\/issue\/([A-Za-z]+-\d+)(?:\/[^?#]*)?(?:[?#].*)?$/i;

export function parseTrackerIssueUrl(input: string): TrackerIssueUrlRef | null {
  const text = input.trim();
  const github = GITHUB_ISSUE.exec(text);
  if (github) {
    const number = Number(github[2]);
    if (!Number.isSafeInteger(number) || number <= 0) return null;
    return { tracker: 'github', repository: github[1]!.toLowerCase().replace(/\.git$/, ''), number };
  }
  const linear = LINEAR_ISSUE.exec(text);
  if (linear) return { tracker: 'linear', identifier: linear[1]!.toUpperCase() };
  return null;
}

export function resolveTrackerIssueId(ref: TrackerIssueUrlRef, projects: readonly TrackerIssueProject[]): string | null {
  for (const project of projects) {
    const prefix = typeof project?.linearTeam === 'string' ? project.linearTeam.trim().toUpperCase() : '';
    if (!prefix || project.tracker !== ref.tracker) continue;
    if (ref.tracker === 'github') {
      if (project.githubRepo?.toLowerCase() === ref.repository) return `${prefix}-${ref.number}`;
    } else if (ref.identifier.slice(0, ref.identifier.lastIndexOf('-')) === prefix) {
      return ref.identifier;
    }
  }
  return null;
}
```

```tsx
import type { MouseEvent, ReactNode } from 'react';
import { useQuery } from '@tanstack/react-query';
import { resolveTrackerIssueId, type TrackerIssueProject, type TrackerIssueUrlRef } from '@overdeck/contracts';
import { useDashboardStore } from '../../lib/store';

/**
 * PAN-4714: a tracker issue link inside a conversation transcript opens that
 * issue's drawer on a plain click. Modified clicks, middle-click and the context
 * menu keep the browser's new-tab behaviour; a link no registered project
 * resolves stays a plain link.
 */
export function TranscriptIssueLink({ href, issueRef, className, children }: {
  href: string;
  issueRef: TrackerIssueUrlRef;
  className?: string;
  children: ReactNode;
}) {
  const openIssue = useDashboardStore((s) => s.openIssue);
  const { data } = useQuery<unknown>({
    queryKey: ['registered-projects'],
    queryFn: async () => {
      const res = await fetch('/api/registered-projects');
      if (!res.ok) throw new Error('Failed to fetch registered projects');
      return res.json();
    },
    staleTime: 60_000,
  });
  const projects = Array.isArray(data) ? (data as TrackerIssueProject[]) : [];
  const issueId = resolveTrackerIssueId(issueRef, projects);
  const onClick = (event: MouseEvent<HTMLAnchorElement>) => {
    if (!issueId || event.defaultPrevented || event.button !== 0
      || event.metaKey || event.ctrlKey || event.shiftKey || event.altKey) return;
    event.preventDefault();
    openIssue(issueId, 'overview');
  };
  return (
    <a href={href} target="_blank" rel="noopener noreferrer" className={className}
      data-issue-id={issueId ?? undefined} onClick={onClick}>
      {children}
    </a>
  );
}
```
