# PAN-5298: Isolate and instrument the e2e Vite harnesses so `issue-tree.spec.ts` stops timing out on CI

**Issue:** [PAN-5298](https://github.com/eltmon/overdeck/issues/5298)
**Status:** planned (auto mode, 2026-11-14)
**Related:** PAN-5246 (last change to the spec), PAN-4733 (open: move browser specs to a serial lane), PAN-4767 (page-load budget)

## Glossary

- **e2e harness**: a `tests/e2e/*.spec.ts` file that starts its own Vite dev server (`createServer` with `configFile: false`, `root: src/dashboard/frontend`) in `beforeAll`, then drives Chromium through Playwright against it. Four exist: `issue-tree`, `merge-train`, `styleguide-conformance`, `linked-conversation-title-bar`. They run inside the root Vitest suite, so on CI they run inside the four `test-shard` jobs (4 Vitest workers per shard).
- **dependency optimizer / pre-bundling**: Vite bundles npm dependencies into `<cacheDir>/deps/*.js` and serves them at `/node_modules/.vite/deps/<name>.js?v=<hash>` (or `/@fs/<abs cacheDir>/deps/...` when the cache is outside the Vite root).
- **cacheDir**: Vite's cache folder. With no `cacheDir` option it is `<nearest package dir of root>/node_modules/.vite`, so every harness in one checkout uses `src/dashboard/frontend/node_modules/.vite`.
- **optimizer commit**: the end of an optimizer run. Vite 8.3.1 (`node_modules/.bun/vite@8.3.1/node_modules/vite/dist/node/chunks/node.js`, function `commit`, search `renaming ${depsCacheDir} to ${temporaryPath}`) renames the live `deps/` folder to `deps_temp_<hash>`, renames its new run into `deps/`, then deletes the old folder. One commit replaces the whole `deps/` folder.
- **dependency scan**: the optimizer's first step. It crawls `index.html` to find dependencies before any request. If it fails, Vite logs `(!) Failed to run dependency scan. Skipping dependency pre-bundling.` and finds dependencies only as the browser requests them. Each late find re-runs the optimizer, answers stale requests with `504 Outdated Optimize Dep`, and reloads the page.
- **pdfjs alias**: `{ find: 'pdfjs-dist-assets', replacement: <pdfjs-dist package dir> }`. `vite.config.ts` declares it. `pdfDocument.ts` uses it in `import.meta.glob`. A harness with `configFile: false` that lacks it fails the dependency scan.
- **Details tab**: `[data-testid="drawer-tab-overview"]` in the Stage issue view. Both issue-tree tests first wait for it (`tests/e2e/issue-tree.spec.ts` lines 315 and 337).
- **private cache dir**: a fresh folder `<projectRoot>/.cache/vite-e2e/<label>-XXXXXX` (from `mkdtemp`) that one harness passes as `cacheDir` and deletes in `afterAll`. `.cache/` is already gitignored (`.gitignore` lines 99 and 202).

## Problem

`tests/e2e/issue-tree.spec.ts` failed twice on main CI on 2026-11-14, both times on `test-shard (4/4)`, on commits that change no code:

| Run (attempt 1) | Commit | Test 1 | Test 2 |
| --- | --- | --- | --- |
| 43609143655, job 132490130335 | `d0c9b93efe2` (version bump) | 72 043 ms, retry x1, failed | 49 922 ms, retry x1, failed |
| 43629012750, job 132551221446 | `5487b6ad9dd` (docs mockup) | 69 260 ms, retry x1, failed | 48 426 ms, retry x1, failed |

All four failures in each run are the same assertion: `expected +0 to be 1` with `Matcher did not succeed in time`. They fail at line 315 (`await expect.poll(() => detailsTab.count(), renderPoll).toBe(1);`) and at line 337, the same line in test 2. So the Details tab never appeared within the 20 s `renderPoll` (line 113). Test 2 used about 24 s per attempt: about 4 s for `page.goto` and the full 20 s poll. Its page loaded fast, and the view still never rendered. So the Vite server was **persistently** unusable, not slow. Vitest's CI `retry: 1` reruns a test against the same server, because `beforeAll` does not run again, and the retries failed the same way. A rerun of run 43609143655 passed (job 132504466242, issue-tree 26.6 s).

### What the investigation established

1. **The specs share one optimizer cache, and they all commit to it.** In both failing runs, `styleguide-conformance` and `merge-train` ran in the same shard, overlapping `issue-tree` (run 2: styleguide 18:55:16 to 18:57:01, issue-tree 18:55:51 to 18:57:48, merge-train 18:56:08 to 18:56:56). Locally, `DEBUG=vite:deps npx vitest run tests/e2e/issue-tree.spec.ts tests/e2e/merge-train.spec.ts tests/e2e/styleguide-conformance.spec.ts` logged five `renaming .../src/dashboard/frontend/node_modules/.vite/deps_temp_* to .../.vite/deps` commits from three servers within 7 seconds, while their pages were loading. Each commit replaces the folder the other servers are serving from.
2. **merge-train and styleguide-conformance fail the dependency scan.** Both CI logs show `Invalid glob: "pdfjs-dist-assets/standard_fonts/*"` for those two specs. PAN-5246 added the pdfjs alias only to issue-tree (`tests/e2e/issue-tree.spec.ts` lines 235-241). A local probe showed the effect: a server without the alias answered its first page load with 6-14 `504 Outdated Optimize Dep` responses on `effect*` modules and then re-optimized. The server with the alias had zero.
3. **A private cache dir under `.cache/` works.** A probe server with `cacheDir: <projectRoot>/.cache/vite-e2e-probe/a` served its dependencies over `/@fs/...` with zero failed requests and rendered the Details tab. Vite's default `server.fs.allow` is the workspace root (the repo root, whose `package.json` has `workspaces`), so it allows the folder.
4. **Not proven: that the shared cache causes the timeout.** Five bounded local probes could not make the issue-tree server fail after another server committed. The probes tried the same route, a different route, a forced re-optimization from scratch, and the CI order: the issue-tree server optimizes first, a second server then commits a fresh set, and only then does the issue-tree page load for the first time. In every probe the issue-tree server rendered the Details tab with zero failed dependency requests. The CI logs cannot settle it either. Every harness runs Vite at `logLevel: 'error'` and records no failed requests, and test 1 fails before it reads `pageErrors`. So the failing runs left no evidence of what the page received.

### Decision

The fix does two things. It **removes the one cross-test variable** the investigation proved: shared optimizer commits, plus the scan failure that makes two harnesses re-optimize during page loads. It also **makes the next failure diagnosable**: when the issue view does not mount, the failure message carries the Vite log, the failed requests, and the page errors. If issue-tree still fails on CI after this change, that message names the cause, and a follow-up issue fixes it. Raising timeouts would hide the problem, so it is out of scope.

## Requirements

- **FR-1** Every e2e harness passes Vite a private cache dir that no other harness or Vitest run uses. The harness creates it with `mkdtemp` under `<projectRoot>/.cache/vite-e2e/` and deletes it in `afterAll`.
- **FR-2** Every e2e harness declares the pdfjs alias, so its dependency scan succeeds. One shared helper builds the alias.
- **FR-3** When the issue-tree spec's Details tab does not appear within `renderPoll`, the test fails with a message that lists, in this order: the HTTP responses with status >= 400 and the failed requests the page saw, the page errors, and the last 40 Vite log lines (info level and above) the harness recorded.
- **FR-4** Each issue-tree test closes its browser context even when an assertion fails, so a failed attempt leaves no live page running during the retry.
- **FR-5** `docs/TESTING.md` and `.overdeck/context/codebase/conventions.md` state the private-cache and alias rules for e2e harnesses and name the helper module.
- **NFR-1** No assertion changes, and no timeout is raised: `renderPoll` stays `{ timeout: 20_000, interval: 100 }`, and the test and hook timeouts keep their current values.
- **NFR-2** The PR records the repeat evidence that the issue asks for (work item WI-8).
- **NFR-3** No test reads source files to check the change. `scripts/lint-source-introspection.sh` flags any `readFile(...'.ts')` in `tests/**`.

### WI-1: Shared e2e Vite harness helper (`tests/e2e/fixtures/vite-harness.ts`)

**What/why:** One module for the three pieces every harness needs (FR-1, FR-2, FR-3 logger). Without it, four copies drift, which is how merge-train and styleguide-conformance missed PAN-5246's alias.

**Create** `tests/e2e/fixtures/vite-harness.ts`:

```ts
/**
 * Shared pieces of the tests/e2e Vite harnesses (PAN-5298).
 *
 * Every harness serves src/dashboard/frontend. Without a cacheDir they all share
 * its node_modules/.vite, and each optimizer commit replaces that deps/ folder,
 * so specs running in one CI shard swap the dependency files each other serve.
 * Each harness therefore gets a private cache dir, deleted in afterAll.
 */
import { mkdir, mkdtemp, rm } from 'node:fs/promises';
import { dirname, join } from 'node:path';
import { realpathSync } from 'node:fs';

/** A fresh, private Vite cacheDir under <projectRoot>/.cache/vite-e2e/ (gitignored). */
export async function createViteCacheDir(projectRoot: string, label: string): Promise<string> {
  const parent = join(projectRoot, '.cache', 'vite-e2e');
  await mkdir(parent, { recursive: true });
  return mkdtemp(join(parent, `${label}-`));
}

/** Delete a cache dir made by createViteCacheDir; a no-op for undefined. */
export async function removeViteCacheDir(cacheDir: string | undefined): Promise<void> {
  if (cacheDir) await rm(cacheDir, { recursive: true, force: true });
}

/**
 * vite.config.ts's pdfjs-dist-assets alias. pdfDocument.ts's import.meta.glob
 * needs it; without it the dependency scan fails and Vite re-optimizes during
 * page loads (504 Outdated Optimize Dep, then a reload).
 */
export function pdfjsAssetsAlias(resolvePackage: (specifier: string) => string): { find: string; replacement: string } {
  return { find: 'pdfjs-dist-assets', replacement: dirname(realpathSync(resolvePackage('pdfjs-dist/package.json'))) };
}

type ViteLogger = {
  info(msg: string, options?: unknown): void;
  warn(msg: string, options?: unknown): void;
  warnOnce(msg: string, options?: unknown): void;
  error(msg: string, options?: unknown): void;
  clearScreen(type: string): void;
  hasErrorLogged(error: unknown): boolean;
  hasWarned: boolean;
};

/**
 * A Vite customLogger that records every info/warn/error line into `lines`
 * (for failure messages) and forwards every call to an error-level Vite
 * logger. The base logger keeps Vite's own state (hasWarned, warnOnce
 * de-duplication, hasErrorLogged) and prints only errors, as logLevel 'error'
 * did. Vite uses a customLogger as-is (createLogger returns it unchanged), so
 * the wrapper must keep that state itself by forwarding. `createLogger` is
 * vite's own export, passed in because the harness imports vite dynamically.
 */
export function createRecordingLogger(
  createLogger: (level: 'error') => ViteLogger,
  lines: string[],
): ViteLogger {
  const base = createLogger('error');
  const warnedOnce = new Set<string>();
  return {
    info(msg, options) { lines.push(`info  ${msg}`); base.info(msg, options); },
    warn(msg, options) { lines.push(`warn  ${msg}`); base.warn(msg, options); },
    warnOnce(msg, options) {
      if (!warnedOnce.has(msg)) { warnedOnce.add(msg); lines.push(`warn  ${msg}`); }
      base.warnOnce(msg, options);
    },
    error(msg, options) { lines.push(`error ${msg}`); base.error(msg, options); },
    clearScreen(type) { base.clearScreen(type); },
    hasErrorLogged(error) { return base.hasErrorLogged(error); },
    get hasWarned() { return base.hasWarned; },
    set hasWarned(value: boolean) { base.hasWarned = value; },
  };
}
```

Write the returned object member by member as shown; do not spread `base`. A spread would copy `hasWarned` once as a plain value and stop tracking Vite's flag.
