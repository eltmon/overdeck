## Glossary

- **Connector** — the process a self-hosted bot runs to reach one machine's MCP tools
  (`pan mcp connector …`). It pairs once with a one-time code, then holds a `kind: 'connector'`
  access-token record on the machine.
- **Pairing code** — a one-time `odp_<64 hex>` credential, kept only in dashboard memory
  (`src/dashboard/server/pairing-credentials.ts`). Its **pairingId** (32 hex) and Noise PSK are
  derived from the code. `takePairingById` consumes it at the channel handshake, on any outcome.
- **Pairing string** — `overdeck-connector:/pair#v=1&e=…&k=…&c=<code>[&n=<machine label>]`
  (`packages/contracts/src/connector-pairing.ts`, `buildConnectorPairLink`). `'` in the label is
  already encoded as `%27`.
- **Connector request** — this issue's replacement for the old **connector intent**: the
  dashboard's in-memory record, by request id and by pairingId, that a root viewer minted a pairing
  code for a named bot with chosen scopes and platform (`src/dashboard/server/connector-pairing.ts`).
- **Request state** (derived, never stored) — for a request that has not paired: `live` (code
  unexpired and still held), `expired` (past `expiresAt`), `used` (not expired, but the code was
  consumed or taken without a finished exchange).
- **Connect platform id** — one of `grok-bot | grok-build | hermes | openclaw | other`, the
  `--platform` values of `pan mcp connector connect` (`CONNECT_PLATFORMS` in
  `src/lib/mcp/connector/connect-output.ts`).
- **Copy message** — the one text the dashboard copies for the operator to paste into the bot,
  built by `connectMessage(...)`. It carries the pairing string and the `connect` command.
- **Root viewer** — the internal token or the root browser session (`rejectNonRoot` in
  `routes/connectors.ts`). Only a root viewer can mint, list, cancel or dismiss.
- **Needs-you** — the Decisions panel (`components/DecisionsPanel.tsx`) fed by
  `lib/useDecisions.ts`. A **notice** here is a non-blocking row with no agent behind it.
- **Connected notice** — the Needs-you row "<name> connected with Read + Tell" shown for 24 h
  after a connector request pairs, with **Revoke** and **Dismiss**.

## Problem

Today "Connect a bot" with the connector reach shows a pairing string plus four `npx` commands,
an `export` line and a config block (`ConnectBotOutput.tsx`). Closing the dialog loses the pairing
string: Bots shows "No bots connected" and nothing pending. Grok Bot offers only Public MCP
(`botSnippets.ts` line 21). After a bot pairs, nothing tells the operator. PAN-5069 built the bot
side (`pan mcp connector connect`, one resumable command with a status line); this issue builds
the dashboard side so the operator copies one message, pastes it, and approves once.

## Decisions

1. **The request store keeps a request after the exchange takes it.** `takeConnectorIntent`
   returns the request's `{ requestId, name, scopes }` once and stamps `takenAt`; a second call
   returns null. The request stays so the exchange can mark it `paired` afterwards and so
   `hasConnectorIntent` keeps answering true. Reason: the token id is known only after
   `createAccessToken`, which runs after the take.
2. **Cancel deletes the request and burns its code.** No `cancelled` status is stored (Part B listed
   one; nothing reads it). `hasConnectorIntent` then answers false, which is safe because the code
   no longer exists.
3. **A code that was consumed or taken without a finished exchange is `used`, not `live`.**
   `takePairingById` burns a code at the handshake on any outcome. Offering **Copy again** for it
   would hand the bot a dead code that fails with `pairing-code-refused`. `used` and `expired` rows
   offer **Copy new**; only `live` rows offer **Copy again** and carry the pairing string.
4. **Retention: 24 hours.** `CONNECTOR_REQUEST_RETENTION_MS = 24 * 60 * 60_000`. A request that never
   paired is listed until `expiresAt + 24 h`, then pruned. A paired request lives until
   `pairedAt + 24 h`; that is the notice window. Pruning runs on issue, on list, and on notices.
   This keeps every request at least as long as its code (code life is `expiresAt + 10 min`), so
   `hasConnectorIntent` stays true for as long as the code could be used anywhere.
5. **A notice disappears when its connector is no longer active.** `GET /api/connectors/notices`
   keeps only notices whose `connectorId` is an active `connector` record. Revoke from the notice or
   from Bots, or a re-pair with the same `clientId` (which revokes the older record), removes the
   notice, so Revoke never targets a dead id.
6. **`platform` is optional in `POST /api/connectors/pairing`; absent means `other`.** Present, it
   must be one of `CONNECT_PLATFORMS`, else 400. Reason: callers and tests that post `{ name }`
   keep working.
7. **The button label uses the platform label:** "Copy for Hermes", "Copy for OpenClaw",
   "Copy for Grok Build", "Copy for Grok Bot". After a successful copy the dialog shows
   "Copied — paste it into <platform label>."
8. **Clipboard fallback.** The click awaits a `fetch` before writing the clipboard, and some
   browsers (Safari) refuse a write after an await. When the write fails, the request already
   exists, so the dialog shows "Could not copy automatically. Copy the message below." and the
   message in a `CopyField` whose Copy button is a fresh click. The dialog always shows the message
   in that `CopyField`, so the operator can re-copy either way.
9. **The manual path stays, collapsed.** Under the copied state, a `<details>` titled
   "Set up by hand instead" holds today's pairing string, connector commands and config block.
   For Grok Bot that block has no config field (today's fallthrough would show Grok Build's
   `mcp.json`, which is wrong for Grok Bot); `connect` prints Grok Bot's registration itself.
10. **The connected notice sits in Needs-you's "System" group, non-blocking**, like PAN-5108's
    harness-update card: no agent waits on it. It is shown only to a root viewer (same gate as MCP
    sign-ins), because its routes are root only.
11. **Access label:** `connectorAccessLabel(scopes)` joins, in this order, `Read` (always — every
    connector holds `read:state`), `Tell` (when `tell`), `Operate` (when `operate`), `Approve` (when
    `approve`) with `" + "`. `read:conversations` folds into `Read`. Defaults give `Read + Tell`.
12. **`connectMessage.ts` stays pure and deterministic.** It imports only `botSnippets.ts` and
    `@overdeck/contracts`, uses no time and no browser global at module level, so PAN-5072's Node
    tests can embed its output verbatim. The clipboard helper in the same file touches `navigator`
    only inside its function body.
13. **The message's version is the dashboard's `serverVersion`, else `latest`** (PAN-4951 D-11,
    unchanged). Machine label: the environment label, else the pairing string's `machineLabel`,
    else `this machine`.
14. **No machine-side confirm card, no phone push** (parent PRD decision 6 and non-goals).
15. **File budget.** 25 distinct files across 5 subsystems. `docs/ANYWHERE-ARCHITECTURE.md`'s
    "Intent store" bullet stays accurate at its level (name, scopes, expiry by pairingId, dropped on
    restart) and points to `docs/DASHBOARD-AUTH.md`, which this plan updates; it is not edited.

   /** 'live' before expiry, 'expired' after, 'gone' once used, revoked or pruned. Never consumes. */
   export function pairingCredentialState(pairingId: string): 'live' | 'expired' | 'gone' {
     const hash = byPairingId.get(pairingId);
     const entry = hash === undefined ? undefined : pending.get(hash);
     if (entry === undefined) return 'gone';
     return Date.now() > entry.expiresAt ? 'expired' : 'live';
   }

   /** Burn the credential behind `pairingId` (a cancelled connector request). True when one was removed. */
   export function revokePairingById(pairingId: string): boolean {
     const hash = byPairingId.get(pairingId);
     return hash !== undefined && remove(hash) !== undefined;
   }

### W-2. The connector request store (FR-14, FR-25, FR-27) — foundation

File: `src/dashboard/server/connector-pairing.ts`, `src/dashboard/server/__tests__/connector-pairing.test.ts`.

```ts
import { randomUUID } from 'node:crypto';
import { CONNECT_PLATFORMS, type ConnectPlatform } from '../../lib/mcp/connector/connect-output.js';
import { issuePairingCredential, pairingCredentialState, revokePairingById } from './pairing-credentials.js';

export const CONNECTOR_PAIRING_TTL_MS = 30 * 60_000;
export const CONNECTOR_REQUEST_RETENTION_MS = 24 * 60 * 60_000;
export { CONNECT_PLATFORMS, type ConnectPlatform };

interface ConnectorRequest {
  id: string;              // randomUUID()
  pairingId: string;
  name: string;
  platform: ConnectPlatform;
  scopes: AccessTokenScope[];
  pairingString: string;
  createdAt: number;       // epoch ms
  expiresAt: number;       // the code's own expiry
  takenAt?: number;        // set by takeConnectorIntent
  status: 'pending' | 'paired';
  connectorId?: string;    // set by markConnectorRequestPaired
  pairedAt?: number;
  dismissedAt?: number;
}

/** What GET /api/connectors lists for one unpaired request. `pairingString` only when live. */
export interface ConnectorRequestView {
  id: string; name: string; platform: ConnectPlatform; scopes: AccessTokenScope[];
  createdAt: string; expiresAt: string; state: 'live' | 'expired' | 'used'; pairingString?: string;
}
/** What GET /api/connectors/notices lists. Never carries a pairing string. */
export interface ConnectorNoticeView {
  id: string; connectorId: string; name: string; scopes: AccessTokenScope[]; pairedAt: string;
}

const requests = new Map<string, ConnectorRequest>();   // id → request
const byPairingId = new Map<string, string>();          // pairingId → id

/** `platform` defaults to 'other', so routes/connectors.ts keeps compiling until W-3 passes it. */
export async function issueConnectorPairing(input: { name: string; scopes: readonly AccessTokenScope[]; platform?: ConnectPlatform }):
  Promise<{ requestId: string; pairingString: string; expiresAt: string }>;
/** The request behind `pairingId` once: null when unknown, already taken, paired, or expired. Stamps takenAt; never deletes. */
export function takeConnectorIntent(pairingId: string): { requestId: string; name: string; scopes: AccessTokenScope[] } | null;
/** The exchange minted `connectorId` for `requestId`: status 'paired', pairedAt = now. No-op for an unknown id. */
export function markConnectorRequestPaired(requestId: string, connectorId: string): void;
/** True when `pairingId` belongs to a connector request (any status). Never removes it. */
export function hasConnectorIntent(pairingId: string): boolean;
export function isConnectorCode(code: string): boolean;  // unchanged body
/** Unpaired requests within retention, newest first. */
export function listConnectorRequests(): ConnectorRequestView[];
/** Burn the code and delete an unpaired request. False for an unknown or paired id. */
export function cancelConnectorRequest(id: string): { name: string } | null;
/** Paired, undismissed requests with pairedAt within 24 h, oldest first. The route filters by active connector. */
export function listConnectorNotices(): ConnectorNoticeView[];
/** Stamp dismissedAt on a paired request. False for an unknown or unpaired id. */
export function dismissConnectorNotice(id: string): boolean;
export function _resetConnectorPairingForTests(): void;  // clears both maps
```

Rules:

- `prune(now)` deletes a `pending` request when `now > expiresAt + CONNECTOR_REQUEST_RETENTION_MS`
  and a `paired` request when `now > pairedAt + CONNECTOR_REQUEST_RETENTION_MS`, removing its
  `byPairingId` entry. `issueConnectorPairing`, `listConnectorRequests` and `listConnectorNotices`
  call it first.
- State for a `pending` request: `now > expiresAt` → `expired`; else `takenAt !== undefined` or
  `pairingCredentialState(pairingId) !== 'live'` → `used`; else `live`.
- `cancelConnectorRequest` calls `revokePairingById(pairingId)` before deleting.
- `takeConnectorIntent` for an expired request returns null and does not stamp.
- `cancelConnectorRequest` returns `{ name }` so the route can log the name without a second read.

Tests (rewrite in `connector-pairing.test.ts`; keep the W-7 cross-refusal tests unchanged):

- "hands out an intent once and keeps the request": first `takeConnectorIntent` returns
  `{ requestId, name, scopes }`, second returns null, `hasConnectorIntent` stays true.
- Replaces "refuses an expired intent but keeps marking its code until a later issue prunes it":
  with fake `Date`, an untaken request is `live`, then `expired` 30 min + 1 ms later and still
  `hasConnectorIntent`; at `expiresAt + 24 h + 1 ms` the next `listConnectorRequests()` drops it and
  `hasConnectorIntent` answers false.
- A taken but unpaired request lists as `used` with no `pairingString`; a request whose code was
  consumed by `takePairingById` lists as `used`.
- `cancelConnectorRequest` burns the code (`takePairingById` → `'unknown'`) and removes the row;
  a second cancel returns null.
- `markConnectorRequestPaired` removes the request from `listConnectorRequests()` and adds it to
  `listConnectorNotices()`; `dismissConnectorNotice` removes it from notices; a paired request is
  gone from notices 24 h + 1 ms after pairing.
