# PAN-3956 — `pan install` / `pan sync` / `pan doctor` own Herdr; no silent tmux fallback

**Issue:** https://github.com/eltmon/overdeck/issues/3956
**Research:** `.pan/notes/pan-3956-herdr-research.md` (Herdr 0.9.1 capability audit, 2026-09-20)
**Planned:** 2026-09-20 (`pan plan --auto`), against workspace HEAD `b54cbc346ca`
**Host facts verified while planning:** `herdr 0.9.1`, protocol 22, socket
`~/.config/herdr/sessions/overdeck/herdr.sock`, config `~/.config/herdr/config.toml` (19 bytes:
`onboarding = false`), server run by a hand-written `~/.config/systemd/user/overdeck-herdr.service`,
`herdr integration status` → every target `not installed`.

## 1. Glossary

| Term | Meaning |
| --- | --- |
| **Herdr** | The terminal workspace manager Overdeck uses as its default terminal backend since the Cut (PAN-3917). Binary `herdr`, headless server per named session, NDJSON socket API. |
| **Terminal backend** | The adapter that hosts agent panes: `herdr` or `tmux`. Contract in `src/lib/terminal-backends/types.ts`; adapters `herdr.ts` / `tmux.ts`. |
| **Selection (policy)** | *Which* backend this host is supposed to use. After this issue: `OVERDECK_TERMINAL_BACKEND` env → `terminal.backend` in `~/.overdeck/config.yaml` → default `herdr`. Never a host probe. |
| **Availability (probe)** | *Whether* the selected Herdr backend can actually serve: the `herdr` binary resolves and this home's session socket exists. Separate from selection after this issue. |
| **Session name / instance name** | `managedInstanceName(OVERDECK_HOME)` (`src/lib/instance-name.ts`): `overdeck` for `~/.overdeck`, `overdeck-<sha1(home)[0:8]>` for any other home. Also the Herdr `--session` name and the tmux `-L` socket name. |
| **Session socket** | `~/.config/herdr/sessions/<session>/herdr.sock` (honors `XDG_CONFIG_HOME`); `herdrSocketPath()` in `select.ts`. |
| **Session server** | `herdr --session <session> server` — the headless process that owns the socket. One per Overdeck home. |
| **Herdr config** | `~/.config/herdr/config.toml` (XDG; **not** `~/.herdr/config.toml` as the issue body says — `~/.herdr` does not exist on the host and `herdr --default-config` documents the XDG file). Global to the user, shared by every session. |
| **`resume_agents_on_restore`** | Herdr `[session]` key (`herdr --default-config` lines 327–330, default `true`). When true, Herdr relaunches every agent pane after a server restart with the agent's native resume. Must be `false` under Overdeck (FR-4). |
| **Integration** | A Herdr-installed hook/extension/plugin inside a harness's own config dir that reports lifecycle and/or session identity to Herdr (`herdr integration install <target>`). Targets Overdeck cares about: `pi`, `omp`, `claude`, `codex`, `kimi`, `opencode`, `hermes`. |
| **Pilot set** | The integrations this issue installs: `pi`, `omp`, `kimi`, `opencode` (lifecycle authority — they replace screen scraping). `claude`, `codex`, `hermes` are session-identity-only and are **not** installed (see D2). |
| **Unit** | A systemd `--user` service unit under `~/.config/systemd/user/`. Existing helper: `src/lib/systemd.ts` (supervisor only). |
| **Explicit tmux** | `OVERDECK_TERMINAL_BACKEND=tmux` or `terminal.backend: tmux`. The only way to run tmux after this issue. Every isolated test stack already sets the env form (`docs/TERMINAL-BACKENDS.md` "Selection"). |
| **CheckResult** | `{ name, status: 'ok'|'warn'|'error', message, fix? }` — the `pan doctor` row shape (`src/cli/commands/doctor.ts:205`). |

## 2. Problem

`select.ts:170-183` (grep anchor: `The '${HERDR_BINARY}' binary is not on PATH, so tmux is the backend`)
turns a missing binary or socket into a **tmux selection with a diagnostic nobody reads**.
`hostTerminalBackendName` (`select.ts:135`, anchor `.catch((): TerminalBackendName => 'tmux')`) and
`deliveryBackendName` (`src/lib/agents/delivery.ts:82`, anchor `.catch(() => 'tmux' as const)`) do the
same on any exception, and `listBackendPanes` (`backend-inventory.ts:183-203`) reads the *tmux* server's
sessions whenever the Herdr `list()` fails. A second, pre-existing defect: `loadConfigSync()` returns
`{ config, migration }` (`src/lib/config-yaml/schema.ts:1077`), but `select.ts:128` and `delivery.ts:46`
cast that **wrapper** to `TerminalBackendConfig`, so `configured.terminal` is always `undefined` on the
memoized policy paths — `terminal.backend: tmux` in `config.yaml` is dead for launch, liveness and
delivery today (only `spawn.ts:61` passes `.config` correctly). W1 fixes it. So a fresh machine is a tmux install with a Herdr default on
paper, and a Herdr outage on a Herdr host makes every agent look dead.

Nothing in Overdeck installs Herdr: `grep -ril herdr src/cli/commands/install.ts src/cli/commands/sync.ts
src/cli/commands/doctor.ts` is empty (verified). The binary, the systemd unit and the config on this host
were all placed by hand. No integration is installed, so every non-Claude harness stays `unknown` in
Herdr's agent state, and `resume_agents_on_restore` is at its default `true`, which would let a Herdr
restart relaunch agents that Overdeck has paused, stopped, or gated (`docs/PIPELINE-GATES.md:88-115`).

## 3. Decisions (made here; do not re-decide during implementation)

- **D1 — Selection is policy; availability is a probe.** `selectTerminalBackend` returns
  `env → config → default 'herdr'` and never touches the filesystem. A new `probeHerdrAvailability`
  answers binary + socket. Unavailable Herdr is a **spawn-time error naming `pan install`**, a
  **boot-log error**, and a **doctor FAIL** — never a tmux selection. The policy result stays memoized
  per process; the probe is **never memoized**, so a session server started after dashboard boot becomes
  usable without a restart.
- **D2 — Pilot set = `pi`, `omp`, `kimi`, `opencode`, each only when its binary resolves.** The issue
  body lists all seven; the operator's later comment ("pilot Pi/OMP/Kimi/OpenCode; defer Claude; do not
  install Codex for status; Hermes defer") refines it. `claude`, `codex`, `hermes` are not installed and
  not uninstalled; doctor reports all seven. Binary names: `pi`→`pi`, `omp`→`omp`, `kimi`→`kimi`,
  `opencode`→`opencode`, resolved in `herdr-setup/integrations.ts` with `resolveExecutable(name,
  { allowLoginShell: false })` (`src/lib/harness-binary.ts:130`) so `~/.local/bin`, `~/.kimi-code/bin`,
  `~/.opencode/bin` are found under a bare PATH without spawning a shell.
- **D3 — Config path is `~/.config/herdr/config.toml`**, resolved like `herdrSocketPath` (honors
  `XDG_CONFIG_HOME`). Edited **line-by-line** so comments and user keys survive; verified by parsing with
  `@iarna/toml` (already a dependency) and then `herdr config check`; a running server gets
  `herdr server reload-config`.
- **D4 — Binary install path is the vendor installer**: `sh -c 'curl -fsSL https://herdr.dev/install.sh | sh'`
  with `HERDR_INSTALL_DIR=$HOME/.local/bin` (the installer's own default; verified in the script). Channel is
  verified via `herdr status --json` → `client.channel`; `herdr channel set stable` runs only when it is
  not `stable` **and** the binary lives under `~/.local/bin` (a brew/mise/nix install is verify-only).
- **D5 — Update policy.** Latest stable = `version` in `https://herdr.dev/latest.json` (10 s timeout;
  unreachable ⇒ skip with an info line, never a failure). `pan install` runs `herdr update` (no
  `--handoff`) when the manifest is newer. `pan sync` runs `herdr update` only when **no session server
  is running for this home**; when one is running it prints a warning naming the manual steps. **Nothing
  ever restarts the session server automatically** — a restart closes every agent pane. Doctor reports
  `server_binary_stale`/`restart_needed` as `warn`.
- **D6 — Service = `<session>-herdr.service`** (`overdeck-herdr.service` for the default home — the same
  name as the hand-written unit on this host, whose text the rendered unit replaces once) when
  `systemdUserAvailable()` is true; `systemctl --user enable --now` it. Otherwise a detached
  `herdr --session <session> server` (stdio to `~/.overdeck/logs/herdr-<session>.log`). Either way, wait
  for the socket ≤ 10 s, then verify `status --json` says `server.running && server.endpoint_compatible`.
- **D7 — `pan up` also ensures the session server** (post-launch sidecars), because
  `pan sync --if-changed` returns before any step when inputs are unchanged.
- **D8 — Inventory never consults tmux on a Herdr host.** When the resolved adapter is `herdr` and
  `list()` throws or reports unsupported, serve the previous cache's panes (or `[]` with no cache) and
  `console.warn` once per failure streak. tmux probes run only when the resolved adapter is `tmux`/null.
- **D9 — Claude hook coexistence without installing the Claude integration.** Overdeck's registration is
  delta-only and keeps foreign entries (`claude-hooks-registration.ts:187-205`,
  `applyOverdeckHookRegistrations`); this issue adds the test that proves it for a Herdr `SessionStart`
  entry, and a doctor check that Overdeck's own `SessionStart` hook is still registered whenever the
  Herdr claude integration *is* installed. Order: Claude Code runs all matching hooks for an event **in
  parallel**; the two `SessionStart` entries are independent (Herdr's reports the session id to Herdr,
  Overdeck's inject context/heartbeat) — documented, not enforced.
- **D10 — Skip conditions for the whole Herdr step**: explicit tmux, `process.env.CI`, `process.env.VITEST`,
  or `pan install --skip-herdr`. Skipping prints one line naming the reason.
- **D11 — Kimi integration needs Kimi ≥ 0.14.0.** Reuse the version `checkKimi` already reads
  (`doctor.ts:65`, `checkSystemPrerequisite('kimi')`); below 0.14.0 skip `kimi` with a warn.

export type TerminalBackendSource = 'env' | 'config' | 'default';

export interface TerminalBackendSelection {
  readonly backend: TerminalBackendName;
  readonly source: TerminalBackendSource;
  readonly diagnostic: string;
}

/** Policy only: env → config → default herdr. No filesystem access, never throws. */
export async function selectTerminalBackend(
  config: TerminalBackendConfig = {},
  deps: SelectTerminalBackendDeps = {},
): Promise<TerminalBackendSelection> {
  const override = deps.backendEnv ?? process.env.OVERDECK_TERMINAL_BACKEND;
  if (override) {
    if ((BACKEND_NAMES as readonly string[]).includes(override)) {
      return { backend: override as TerminalBackendName, source: 'env',
        diagnostic: `OVERDECK_TERMINAL_BACKEND is set to '${override}'.` };
    }
    console.warn(`[terminal] Ignoring OVERDECK_TERMINAL_BACKEND='${override}': expected one of ${BACKEND_NAMES.join(', ')}.`);
  }
  const configured = config.terminal?.backend;
  if (configured) {
    return { backend: configured, source: 'config',
      diagnostic: `terminal.backend is set to '${configured}' in config.yaml.` };
  }
  return { backend: 'herdr', source: 'default', diagnostic: `Herdr is the default terminal backend.` };
}

export interface HerdrAvailability {
  readonly binary: string | null;
  readonly session: string;
  readonly socket: string;
  readonly socketExists: boolean;
  readonly available: boolean;
  /** Present when !available; one sentence for logs, doctor and spawn errors. */
  readonly reason?: string;
}

/** Host probe: binary on PATH or in the well-known dirs, plus THIS home's session socket. Never memoized. */
export async function probeHerdrAvailability(deps: SelectTerminalBackendDeps = {}): Promise<HerdrAvailability>

export class TerminalBackendUnavailableError extends Error {
  readonly backend: TerminalBackendName;
  readonly reason: string;
  constructor(backend: TerminalBackendName, reason: string) {
    super(
      `Terminal backend '${backend}' is selected but unavailable: ${reason} `
      + `Run \`pan install\` to install Herdr and start its session server, `
      + `or set terminal.backend: tmux in ~/.overdeck/config.yaml to opt into tmux.`,
    );
    this.name = 'TerminalBackendUnavailableError';
    this.backend = backend;
    this.reason = reason;
  }
}

export async function resolveLaunchBackend(): Promise<TerminalBackend> {
  const name = await hostTerminalBackendName();
  if (name === 'herdr') {
    const probe = await probeHerdrAvailability();
    if (!probe.available) throw new TerminalBackendUnavailableError('herdr', probe.reason ?? 'unknown');
  }
  return resolveTerminalBackend(name);
}
