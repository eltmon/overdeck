# PAN-4330 — Optional overdeck.ai sign-in client: `pan account login`, `status` and `logout`

**Issue:** [PAN-4330](https://github.com/eltmon/overdeck/issues/4330). **Parent PRD:** `.pan/drafts/pan-2350.md` (Overdeck Anywhere, revision 5), work item **W-LINK4**, requirement FR-20 (sign-in is its prerequisite), NFR-8, decisions D-3 and D-15.
**Service docs:** `docs/ACCOUNT-SERVICE.md` (the account service shipped by PAN-4293).
**Planned:** 2026-11-01, auto mode, against `feature/pan-4330` at `7dcd0bebe41`.

## Glossary

- **Account service.** The Cloudflare Worker in `services/account/` that will run at `https://account.overdeck.ai`. It signs people in with GitHub, keeps the invite-only allowlist and mints device tokens. It is built (PAN-4293) but **not deployed yet**.
- **Device token.** `odd_` + 64 lowercase hex characters. The service stores only its SHA-256 hash. The plaintext exists only in the `/oauth/token` response and, after this issue, in the client's token file.
- **Device flow.** RFC 8628 device authorization. The CLI asks for a code (`POST /oauth/device/code`), the person approves it in a browser at `verification_uri`, and the CLI polls `POST /oauth/token` until it gets a token or a terminal error.
- **Token file.** `${OVERDECK_HOME}/account.json`, mode `0600`, written atomically. Holds the device token and what the client learned at sign-in. Never sent to the frontend, never printed.
- **Base URL.** The account service origin the client talks to. Default `https://account.overdeck.ai`.
- **`environmentId`.** The machine's lowercase UUID v4 from `${OVERDECK_HOME}/environment-id.json` (`src/lib/environment-identity.ts`). The service uses `(user, environmentId)` to rotate a machine's token in place on re-sign-in.
- **`AccountRpc.verifyDevice`.** The service-binding RPC other Workers call to check a device token (`services/account/src/index.ts`). Its result type is `VerifyResult` in `services/account/src/contract.ts`.
- **Operator checkpoint.** A step only the human operator may run (GitHub OAuth app, Cloudflare D1, DNS, `wrangler deploy`). Agents never run it (`docs/ACCOUNT-SERVICE.md` "Deploy").
- **Light CLI module.** A module that imports only Node built-ins and a few leaf modules (`src/lib/paths.ts`, `src/lib/environment-identity.ts`), so the command loads without the dashboard, Effect, the terminal backends or `src/lib/config-yaml/**` (PAN-2609 NFR-7, same rule as `pan vault`).

## Problem

PAN-4293 built the account service but nothing on a user's machine can sign in to it, and it is not deployed. The directory (W-LINK5, [PAN-2356](https://github.com/eltmon/overdeck/issues/2356)) and Shared Sessions need a signed-in machine and need the account service to report the GitHub login of a token's owner. Today `AccountRpc.verifyDevice` returns `userId`, `githubId`, `deviceId` and `entitlement` but not `githubLogin`, so `services/share/src/account.ts` already treats a missing login as `account_service_outdated` (inventory gap G-H1). There is no `pan account` verb (gap G-H2).

## Requirements

- **FR-1** `AccountRpc.verifyDevice(token)` returns `githubLogin: string` (the user's current GitHub login from `users.github_login`) on every `ok: true` result. Error results are unchanged.
- **FR-2** `pan account login` runs the device flow: requests a code, prints `verification_uri`, `verification_uri_complete` and the user code, polls `/oauth/token` at the server's interval, and on success writes the token file and prints `Signed in to <baseUrl> as <githubLogin> (device <label>, <deviceId>).`
- **FR-3** The login poll honors every RFC 8628 answer the service gives (`authorization_pending`, `slow_down` with `interval`, `access_denied`, `expired_token`) and the service's 429 `{"error":"rate_limited"}` with `Retry-After`.
- **FR-4** After a token is received, `login` calls `GET /v1/me` with it and stores `githubLogin` and `githubId` in the token file. The token response alone carries no login.
- **FR-5** `pan account status` reports "not signed in" when there is no token file, and otherwise calls `GET /v1/me` against the stored base URL and prints login, device, base URL and access status. `--json` prints the same data as JSON without the token.
- **FR-6** `pan account logout` revokes this machine's device on the service (`DELETE /v1/devices/<deviceId>`) and deletes the token file. It deletes nothing else under `OVERDECK_HOME`.
- **FR-7** The operator receives a single hand-off comment on PAN-4330 listing the deploy steps and the post-deploy smoke test, after the Worker bundle is proven to build.
- **NFR-1** The token file is mode `0600`, written via temp file + rename in the same directory, and the token never appears in stdout, stderr, `--json` output or error messages.
- **NFR-2** `src/lib/account/**` and `src/cli/commands/account/**` are light CLI modules (see Glossary); an import-graph test enforces it.
- **NFR-3** Sign-in is optional (parent NFR-8). No other command reads the token file in this issue, and nothing prompts for sign-in.
- **NFR-4** The client never hardcodes the activation host: it prints `verification_uri` from the service response.
- **NFR-5** Every delay-based test uses fake timers (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync`); see "Repo rules that apply".

## Decisions

- **D-1 Device flow only.** `pan account login` always uses the device flow; there is no `--device-code` flag because there is no other flow. The PKCE loopback flow serves a dashboard sign-in, which is out of scope.
- **D-2 Base URL precedence.** `login` uses, in order: `--base-url <url>`, then env `OVERDECK_ACCOUNT_URL`, then `https://account.overdeck.ai`. The URL must parse, have no path other than `/`, no query, no fragment, and be `https:`; `http:` is accepted only for host `127.0.0.1`, `localhost` or `[::1]` (for `wrangler dev --local`). Anything else exits 1 with `Invalid account service URL: <url>` before any network call. The base URL used is stored in the token file, and `status` and `logout` always use the stored one. The default is a product URL, not a model, so the no-hardcoded-model-fallback rule does not apply.
- **D-3 Platform check is local.** The platform string is `` `${process.platform}-${process.arch}` ``. If it does not match `^(linux|darwin|win32)-(x64|arm64)$` (the service's `PLATFORM_RE`), `login` exits 1 with `This platform (<value>) cannot sign in to overdeck.ai; supported: linux, darwin, win32 on x64 or arm64.` before any network call.
- **D-4 `environment_id`** comes from `ensureEnvironmentIdentity()` (`src/lib/environment-identity.ts:86`). If that throws (corrupt identity file), `login` prints the error message and exits 1.
- **D-5 Poll loop rules.** Start with the response's `interval` (seconds) and wait one `interval` before the first poll (RFC 8628 §3.4). `authorization_pending` → wait `interval`, poll again. `slow_down` → set `interval` to the response's `interval` field (or `interval + 5` when absent), wait, poll. 429 → wait `Retry-After` seconds (or `interval` when absent or unparsable), poll. `access_denied` → exit 1 with `This GitHub account is not on the overdeck.ai invite list, or sign-in was cancelled. Ask the operator to allow it, then run: pan account login`. `expired_token` → exit 1 with `The sign-in code expired. Run: pan account login`. A thrown fetch (network error) or a 5xx is retried at the current interval; three consecutive failures exit 1 with `Cannot reach <baseUrl>: <message>`. Any other 400 error code exits 1 with `Sign-in failed: <error>`. The loop also stops with the expired message once `expires_in` seconds have elapsed locally.
- **D-6 Token file shape** (`v: 1`): `{ v, baseUrl, accessToken, deviceId, label, githubLogin, githubId, signedInAt }` where `signedInAt` is ISO-8601 UTC. A file that is unreadable, not JSON, or the wrong shape makes `status` and `logout` exit 1 with `Cannot read <path>: <reason>. Delete it to sign out locally.`; the client never rewrites it silently.
- **D-7 Re-login.** When a token file exists, `login` prints `Already signed in as <login>; signing in again replaces this machine's token.` and runs the flow. The service rotates the token in place for the same `environmentId`, so `deviceId` and `label` stay the same. The new file replaces the old one only after `/v1/me` succeeds; a failed login leaves the old file untouched.
- **D-8 `/v1/me` failure after a token arrives.** If `GET /v1/me` fails after the token response, `login` still writes the token file with `githubLogin: null` and `githubId: null`, prints `Signed in (device <label>, <deviceId>), but could not read the account: <reason>. Run: pan account status`, and exits 1. Dropping a valid token would leave an orphaned device on the service.
- **D-9 `status` exit codes.** No token file → prints `Not signed in. Run: pan account login` and exits 0 (sign-in is optional, matching `pan vault status` when the vault is off). `/v1/me` 200 → exit 0. 401 (`invalid_token`, `device_revoked`, `account_deleted`) → prints `This machine's sign-in is no longer valid (<error>). Run: pan account login`, exits 1, keeps the file. 403 `grant_expired` cannot occur on `/v1/me` (it allows expired grants); `access.status: "grant_expired"` prints `Access: expired on <date>; ask the operator to renew the invite.` and exits 0. Network error or 5xx → prints the cached login with `(account service unreachable: <reason>)` and exits 1.
- **D-10 `logout` semantics.** No token file → prints `Not signed in.` and exits 0. Otherwise call `DELETE /v1/devices/<deviceId>`. 204, 401 or 404 → the device is gone or already invalid; delete the file, print `Signed out. This machine's device token was revoked.`, exit 0. Network error or 5xx → delete the file anyway, print `Signed out locally, but could not revoke the device on <baseUrl>: <reason>. Revoke it from another signed-in machine or ask the operator.` to stderr, exit 1. Logout touches only the token file (never `vault/`, never `environment-id.json`).
- **D-11 No browser auto-open.** `login` prints the URLs; it does not spawn `xdg-open`/`open`. This works the same over SSH and keeps the module free of child processes.
- **D-12 `githubLogin` stays optional in `services/share`.** `services/share/src/account.ts` keeps `githubLogin?: string` because a share Worker may run against an older account deployment (its D-R3-5). This issue does not touch `services/share/`.
- **D-13 No telemetry change, no wrapper skill.** `pan account` follows the default CLI telemetry path (no token is ever an argument). No `sync-sources/skills/pan-account/` skill is added (`pan vault` has none either); the Mintlify page is the documentation.
- **D-14 Own IO type.** `src/cli/commands/account/shared.ts` defines its own `AccountIo { out, err, exit }` instead of importing `defaultIo` from `src/cli/commands/vault/shared.ts`, which would pull `src/lib/vault/**` into the import graph. Tests reuse `captureIo` from `tests/unit/cli/vault/helpers.ts` (structurally compatible superset).

## Repo rules that apply (restated)

- **Fake timers for delay tests.** Any test of the poll loop uses `vi.useFakeTimers()` in `beforeEach`, `vi.useRealTimers()` in `afterEach`, and `await vi.advanceTimersByTimeAsync(ms)` to move time. Never wait real seconds. Use `AbortController` + `setTimeout`, not `AbortSignal.timeout` (it ignores fake timers in happy-dom).
- **No new source-reading tests.** `npm run lint` runs `lint:source-introspection`, which fails on a new test file that calls `readFile`/`readFileSync`. The import-graph guard therefore extends `ENTRY_DIRS` in the existing `tests/unit/lib/vault/import-graph.test.ts` instead of adding a new walker file.
- **No `it.skip` / `skipIf` / `.only`.** The test-skip gate fails any added one. Platform-specific assertions (file mode on win32) branch inside the test.
- **Account service code uses Web APIs only**; only `services/account/src/index.ts` imports `cloudflare:workers`. Unit tests use the `node:sqlite` D1 shim and may use only `prepare/bind/first/all/run/batch`.
- **Agents never deploy.** Allowed: `wrangler dev --local`, `wrangler d1 migrations apply overdeck-account --local`, `wrangler deploy --dry-run`. Nothing else.
- **One variant per operation in `src/lib`.** Plain async functions; no Effect wrapper, no sync twin.
- **File-size ratchet.** `src/cli/index.ts` is 1280 lines with an allowlist cap of 1379; one added line is fine. New files must stay small (each verb module under ~150 lines).
- **Quality gates before `pan done`:** `npm run typecheck`, `npm run typecheck:account`, `npm run lint`, and `npx vitest run <touched test files>`. Never the full `npm test` on the host.
