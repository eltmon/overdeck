**Issue:** [PAN-4259](https://github.com/eltmon/overdeck/issues/4259), slice S7 of [PAN-4249](https://github.com/eltmon/overdeck/issues/4249). Program PRD: `.pan/drafts/PAN-4249.md` ("Sibling issues"). Audit: first comment on #4249, sections 4 and 5.

**Split-off sibling:** [PAN-4510](https://github.com/eltmon/overdeck/issues/4510) (filed in this planning session) takes the issue-view agent rows, `ConversationList` rows, and Agents-page *conversation* entries. See [Scope and split](#scope-and-split).

Every reference below was checked on `feature/pan-4259` at `b8853b45510` (2026-10-03). Where a line number may drift, search for the quoted code.

## Glossary

- **Effort** — the reasoning-effort level a harness runs at. Canonical levels, lowest to highest: `low`, `medium`, `high`, `xhigh`, `max`. Type `EffortLevel`, list `EFFORT_LEVELS`, guard `isEffortLevel()`, schema `EffortLevelSchema` — all in `packages/contracts/src/effort.ts`, imported as `@overdeck/contracts`.
- **Effort source** — which precedence layer supplied the level: `explicit`, `item`, `plan`, `tier`, `sub-role`, `role`, `project`, `default`. Type `EffortSource` in the same file. There is no runtime list or schema of sources.
- **Launch effort** — the effort an agent session was started at. Since PAN-4253 it is persisted as `AgentState.effort` / `AgentState.effortSource` in `~/.overdeck/agents/<id>/state.json` (`src/lib/agents/agent-state-read.ts`, `cleanAgentState` validates with `isEffortLevel`). `state.json` always describes the **most recent** launch.
- **Observed effort** — the level a claude-code transcript record shows. claude-code ≥ 2.1.280 writes `effort` (or `perTurnEffort`) on every assistant record. `observedEffortFromRecord(record)` in `src/lib/claude-effort-transcript.ts` reads it (PAN-4255).
- **sessions.json** — the append-only per-agent session index at `~/.overdeck/agents/<id>/sessions.json`, one JSON object per line, written by `appendSessionIdToHistory` in `src/lib/session-history.ts`. It is sacred: never truncate or rewrite it.
- **Cost ledger** — the `cost_events` table in `~/.overdeck/overdeck.db` plus the durable archive `~/.overdeck/costs/events.jsonl`. Rows are built at **ingestion** time by reconcilers that parse transcripts, not at launch.
- **Two cost-event shapes.** `CostEvent` in `src/lib/overdeck/cost.ts` (an Effect `Schema.Struct`, `ts: Date`; this PRD calls it the *overdeck CostEvent*) and the older `interface CostEvent` in `src/lib/costs/events.ts` (`ts: string`; the *legacy CostEvent*). Reconcilers build legacy events and convert them with `toOverdeckCostEvent`.
- **Schema top-up** — overdeck.db has one init migration (`drizzle/overdeck/0000_overdeck_init.sql`) that runs only on a fresh DB. Existing DBs get new columns through idempotent `runSchemaTopUp(db, 'ALTER TABLE …')` calls in `ensureRuntimeIndexesSync` (`src/lib/overdeck/infra.ts`), which ignore "duplicate column name".
- **Agents page** — `/agents`. `FleetAgentsView` switches between the Live view (`LiveAgentsView`) and the History view (`/agents?view=history`, `AgentsDirectory`). History rows are drawn by `DirectoryList.tsx`; the selected entry's header by `DirectoryDetail.tsx`. Both read `DirectoryEntry` from `GET /api/agent-directory`.
- **`unrecorded`** — the bucket name the effort cost report uses for ledger rows with no effort (legacy rows, background AI, global roots).

## Problem

Effort is now resolved, persisted, and changeable (PAN-4249, PAN-4253–PAN-4255), but nothing records which effort a dollar was spent at, and only the conversation composer chip shows it. Audit §5: no effort in `CostEvent`, `sessions.json`, or any cost report. Audit §4: the Agents page, `pan status`, and `pan show` show none. So nobody can answer "what does `xhigh` cost us compared to `high`?" or see at a glance which level an agent runs at.

## Scope and split

The full S7 surface (ledger, sessions.json, report, Agents rows, issue view, conversation header, `ConversationList`, `pan status`, `pan show`, docs, tests) projects to about 40 files. Plan finalize lints a plan at 25 files and 6 subsystems. So this planning session filed [PAN-4510](https://github.com/eltmon/overdeck/issues/4510) for the surfaces none of PAN-4259's three acceptance criteria name and that share no data path with the ledger work: issue-view agent rows, `ConversationList` rows, and Agents-page conversation entries.

**This issue keeps** everything its three stated acceptance criteria need, plus the two CLI surfaces that sit in the `src/cli` subsystem the `pan cost effort` report already touches:

1. Effort on `sessions.json` entries, recorded at launch.
2. Effort on every new cost-ledger row.
3. A cost report grouped by effort (`pan cost effort`).
4. Effort on native-agent rows of the Agents page (History rows and the detail header).
5. Effort in `pan status` and `pan show`.
6. Docs for each of those surfaces.

**The conversation header** already shows the effective effort and its source through the composer effort chip (PAN-4255, `ConversationPanel.tsx` passes `effortResolution`/`observedEffort` to `ComposerFooter`). No second display is added.

Even after the split, this plan touches 37 files (17 of them tests or docs) across more than 6 subsystems (a column add alone needs `drizzle/overdeck`, `src/lib`, tests, and a docs page). `plan.metadata.sizeJustification` records why: the three acceptance criteria the operator wrote for this issue are kept together, and further splitting would move one of them out.

## Decisions

- **D1 — Where a ledger row's effort comes from.** Cost rows are built at ingestion, so each reconciler picks the effort with this rule, first match wins:
  1. **claude-code only:** the observed effort on the same transcript record that carries the usage (`observedEffortFromRecord(entry)`). It is the level that request actually ran at, including after a live `/effort` change.
  2. The `effort` on the `sessions.json` entry whose `sessionId` matches the row's session (the launch effort).
  3. `state.json` `effort` — **only** when the row's session is the agent's newest indexed session, or the index is empty. `state.json` describes the most recent launch, so applying it to an older session would mislabel history.
  4. Otherwise no effort (the row stores `NULL`).
- **D2 — sessions.json carries `effort` only**, not `effortSource`. The issue names only `effort`; the source stays on `state.json`. The key is omitted (not `"unknown"`) when no effort is known, so legacy and effort-less lines look the same.
- **D3 — `createFreshSessionIdentity` takes effort explicitly.** In `spawn.ts` it runs inside the state literal, before `saveAgentStateSync(state)`; in `recovery.ts` it runs before the relaunch effort is saved. A `state.json` fallback would read the previous launch's effort there.
- **D4 — One report variant.** `pan cost` reads `cost-sync.ts` raw SQL, not `CostResolver`. Add `getEffortRollup(issueId?)` next to `getModelRollup` and a `pan cost effort` subcommand. Do **not** add `CostResolver.byEffort` (one variant per operation; the "all 11 resolver methods" test in `tests/unit/lib/overdeck/cost.test.ts` stays as is). No new HTTP route, so no `no-loss-matrix.ts` row is needed.
- **D5 — Report buckets.** Rows group by `effort`; `NULL` groups as `unrecorded`. Buckets are ordered by `EFFORT_LEVELS` rank (low → max), then `unrecorded` last. Ordering uses `EFFORT_LEVELS.indexOf`, never a copied list.
- **D6 — No backfill.** Existing `cost_events` rows keep `effort = NULL`; dedup by `requestId` means a re-reconcile never rewrites them. The report shows them as `unrecorded`.
- **D7 — Display format.** UI: `<level> (<source label>)`, for example `xhigh (role)`, with source labels from the existing `EFFORT_SOURCE_LABELS` in `src/dashboard/frontend/src/components/chat/effortChip.ts` (`explicit` renders as `set`). Level only (`high`) when the source is missing. Nothing when effort is missing. CLI: `<level> (<source>)` with the raw `EffortSource` string, for example `high (explicit)`.
- **D8 — Agents page placement.** Effort goes on the History row's runtime span (`harness · model · effort`) and the detail header's runtime span. Live rows show no model or harness today, so they stay unchanged; selecting a live row still shows effort in the detail header. Only native agents (`kind: 'agent'`, `source: 'overdeck'`) get effort here; conversation entries are PAN-4510.
- **D9 — `DirectoryEntry` fields are optional** (`Schema.optional`), so older servers, pane-only entries, external entries, and subagents need no change. `effortSource` is `Schema.optional(Schema.String)` because contracts has no source schema; the frontend narrows it with `in EFFORT_SOURCE_LABELS`.
- **D10 — `strike.ts` stays out.** `scripts/lint-effort.sh` baselines `src/cli/commands/strike.ts` with a `# PAN-4259` comment, but [PAN-4258](https://github.com/eltmon/overdeck/issues/4258)'s body owns that line (`pan strike` dry-run prints `medium`). This issue does not touch `strike.ts` or its baseline row.

## Intersecting repo rules (restated)

- **Effort defaults stay `high`, never `xhigh`/`max`.** This slice adds no defaults at all: an unknown effort is recorded as missing.
- **`lint:effort` ratchet** (`scripts/lint-effort.sh`): no `effort ?? 'high'` style fallback, no `'low' | 'medium'` union, no `['low', 'medium', …]` array, no `low|medium|high` regex in new code. Use `EFFORT_LEVELS` / `isEffortLevel` / `EffortLevelSchema` from `@overdeck/contracts`.
- **No `execSync` in dashboard server code.** The agent-directory change only reads the already-loaded `state` object.
- **Import cycles:** new `src/lib` code that needs agent state imports from `agent-state-read.js` (the leaf), never `agents.js`. `session-history.ts` reads `state.json` with `readFileSync` directly, as it already does.
- **sessions.json is append-only.** Only append; never rewrite or truncate.
- **File-size ratchet:** files over 1000 lines may not grow past their `origin/main` count or allowlist cap. `spawn.ts` is 1074 lines, cap 1081 — keep the change to argument additions on existing lines.
- **Quality gates before `pan done`:** `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Do not run the full `npm test` on the host. `npm run typecheck` skips `*.test.ts`, so run the touched tests.
- **Fake timers** for any delay-based test (none expected here).
- **Playwright** runs in Playwright's fresh per-test browser context (an isolated profile) with every API route-mocked; it never shares another agent's browser state.

   ```ts
   /**
    * Launch effort per session for one agent (PAN-4259 D1 rules 2–3): the
    * sessions.json entry's effort, else state.json's effort for the newest
    * indexed session (or any session when the index is empty). Reads both
    * files once; the returned lookup does no I/O.
    */
   export function readLaunchEfforts(agentId: string): (sessionId?: string | null) => EffortLevel | undefined {
     const entries = readSessionIndexWithLegacy(agentId);
     const byId = new Map(entries.map((entry) => [entry.sessionId, entry.effort]));
     const newest = entries.at(-1)?.sessionId;
     let stateEffort: EffortLevel | undefined;
     try {
       const raw = JSON.parse(readFileSync(join(getOverdeckHome(), 'agents', agentId, 'state.json'), 'utf8')) as { effort?: unknown };
       if (isEffortLevel(raw.effort)) stateEffort = raw.effort;
     } catch { /* legacy/no state */ }
     return (sessionId) => {
       const indexed = sessionId ? byId.get(sessionId) : undefined;
       if (indexed) return indexed;
       if (entries.length === 0 || (sessionId && sessionId === newest)) return stateEffort;
       return undefined;
     };
   }
   ```
   `readSessionIndexWithLegacy`, `readFileSync`, `join`, `getOverdeckHome` are already imported/defined in this file.

          ${where}
          GROUP BY effort`,
