# PAN-4212: Plan-freshness preflight refuses plans that create new files

**Issue:** [PAN-4212](https://github.com/eltmon/overdeck/issues/4212)
**Status:** planned (auto mode, 2026-09-25)

## Glossary

- **Plan-freshness preflight** — the check `pan start` runs right before it spawns a work agent (added by PAN-3917). It reads the workspace xBRIEF plan and refuses to spawn when the plan names files that are gone, printing `The plan for <ID> references files that no longer exist`. `--skip-freshness` bypasses it.
- **`files_scope`** — `plan.items[].metadata.files_scope`, the list of repo-relative paths an xBRIEF item expects to touch. It mixes files the item edits and files the item creates.
- **Missing path** — a non-glob `files_scope` entry that does not exist in the workspace checkout.
- **Drift** — a missing path that the codebase deleted (or renamed away) *after* the plan was written. This is the only case the preflight exists to catch: the plan was authored against a tree that has since moved.
- **Creation** — a missing path the plan intends to create. It either never existed on `HEAD`'s history, or `HEAD` deleted it *before* the plan was written (a deliberate restore).
- **Plan baseline** — `plan.plan.created`, the ISO 8601 time the plan was authored. Converted to epoch seconds for comparison with git commit times.
- **Turn-checkpoint refs** — `refs/pan/turn/<agent>/<turn-id>`, commits Overdeck writes to snapshot a session's tree each turn. The overdeck repo holds tens of thousands of them (18,583 under `refs/pan/turn/flywheel-orchestrator` alone on 2026-09-25).

## Problem

`pan start PAN-4199` and `pan start PAN-1641` were refused as stale. Every flagged path is a file those plans create. Both needed `--skip-freshness`, and on the auto-start path (the dashboard launches a detached `pan start <id> --local`) the refusal only lands in `spawn.log`, so the handoff silently fails.

### Root cause (verified 2026-09-25)

The preflight already tries to exclude creations. [start.ts](/home/eltmon/Projects/overdeck/src/cli/commands/start.ts), lines 1159–1165, passes an `isNewFile` predicate that means "this path has no git history":

```ts
      // A missing path with no git history is a file the plan creates, not drift.
      const everTracked = (scope: string): boolean => {
        try {
          return execFileSync('git', ['log', '--all', '--oneline', '-1', '--', scope], { cwd: workspace, encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'] }).trim().length > 0;
        } catch { return false; }
      };
      const freshness = plan ? checkPlanFreshness(plan, workspace, existsSync, (scope) => !everTracked(scope)) : null;
```

That predicate has two defects:

1. **`--all` walks the turn-checkpoint refs.** A file that any planning or work session ever drafted is captured in some `refs/pan/turn/*` commit, so it counts as "tracked". `docs/audits/pan-1641-local-ollama-verification.md` exists only in `refs/pan/turn/planning-pan-1641/turn-1788964048590-826dc5c2`, never on `main`, yet it was flagged. The walk over ~30k refs is also slow.
2. **No time comparison.** `src/dashboard/frontend/src/lib/flywheelReveal.ts` was on `main` and was deleted on 2026-09-18 by commit `3fb710042dd` (PAN-3917 W7). The PAN-4199 plan was created on 2026-09-25T05:57:04Z. The file was already gone when the plan was written, so restoring it is intended work, not drift. "Was ever tracked" cannot tell those apart.

Empirical check against the two real plans (script run in the planning session):

| Plan | Missing paths | Flagged by current rule | Flagged by new rule |
| --- | --- | --- | --- |
| PAN-4199 (`created` 2026-09-25T05:57:04Z) | 8 | 1 (`flywheelReveal.ts`) | 0 |
| PAN-1641 (`created` 2026-09-25T05:54:44Z) | 14 | 4 (`docs/audits/pan-1641-…md`, `doctor-ollama.test.ts`, `install-ollama.test.ts`, `messaging-ollama-preflight.test.ts`) | 0 |

Positive control: `src/lib/runtimes/muse-session.ts` was deleted (renamed away) on `HEAD` at epoch `1790217944` (2026-09-23). Against a plan created 2026-09-20 (epoch `1789862400`) the new rule still flags it.

## Decision

**A missing path is drift if and only if `HEAD`'s history shows a commit that deleted it after the plan baseline.** Everything else missing is a creation.

- Probe: `git log -1 --no-renames --diff-filter=D --format=%ct HEAD -- <path>`, run in the workspace. Empty output means no commit on `HEAD`'s history ever deleted the path. `%ct` is committer time in epoch seconds, so the comparison is integer math. `--no-renames` makes a rename count as a deletion of the old path regardless of the user's `diff.renames` git config.
- Rule: `deletedAt !== null && (baseline === null || deletedAt > baseline)`. Equal seconds are not drift.
- Baseline: `plan.plan.created` parsed with `Date.parse`, floored to seconds. Use `created`, never `updated`: `updated` is bumped by later plan writes (`src/lib/xbrief/lifecycle-io.ts`, line 225, `doc.plan.updated = now;`) and would hide drift that happened after planning. If `created` is absent or unparseable the baseline is `null`, and any deletion on `HEAD` counts as drift (the conservative fallback). `writeAutoStartXBrief` in `src/lib/xbrief/auto-synthesize.ts` stamps `created: now`, so synthesized auto-start plans have a baseline.
- Git failure (not a repo, git missing) makes the probe return `null` → creation → not flagged. This matches today's behavior, where a failing `git log` also makes the path count as new.

### Alternatives rejected (auto mode)

- **Parent directory exists ⇒ creation.** A deleted file's directory almost always survives, so this would silence most real drift and make the preflight nearly useless.
- **Explicit new-file marker in item metadata** (for example a `files_create` list). It changes the xBRIEF schema, every planner prompt must learn it, and existing plans (PAN-4199, PAN-1641) do not carry it. The temporal git rule fixes both reported cases with no schema change.

## Requirements

- **FR-1** — The preflight flags a missing `files_scope` path only when a commit on the workspace `HEAD` history deleted that path after `plan.created`.
- **FR-2** — A missing path that no commit on `HEAD` history ever deleted is treated as a creation and not flagged, even if the path appears in other refs (turn-checkpoint refs, other branches).
- **FR-3** — A missing path deleted on `HEAD` before `plan.created` is treated as a creation (restore) and not flagged.
- **FR-4** — When `plan.created` is absent or unparseable, any deletion on `HEAD` history flags the path.
- **FR-5** — The decision rule lives in the pure module `src/lib/xbrief/freshness.ts` and is unit-testable without git; the git probe lives at the CLI boundary.
- **FR-6** — `checkPlanFreshness` called without a history probe keeps today's default: every missing path is flagged.
- **FR-7** — Docs describe the preflight, the drift rule, and `--skip-freshness`.
- **NFR-1** — The probe never walks refs other than `HEAD` (no `--all`), so its cost does not grow with the turn-checkpoint ref count.
- **NFR-2** — `src/cli/commands/start.ts` does not grow past its `scripts/file-size-allowlist.txt` row (1265 lines).

## Work items

### WI-1 — Git deletion-time probe at the CLI boundary (FR-2, FR-3, NFR-1)

New file `src/cli/commands/start-freshness.ts`, a sibling of `start-status.ts` and `start-prep-progress.ts`:

```ts
/**
 * Git history probe for the plan-freshness preflight (PAN-4212).
 *
 * Answers one question per path: when did a commit on the workspace's HEAD
 * history last delete it? Only HEAD is consulted — `--all` would walk the
 * turn-checkpoint refs under refs/pan/turn/*, where any file a session ever
 * drafted appears "tracked". Synchronous caller: `pan start` (CLI only).
 */

import { execFileSync } from 'node:child_process';

/** Returns a probe giving the epoch seconds of the last commit on HEAD that deleted `scope`, or null. */
export function headDeletionEpoch(workspace: string): (scope: string) => number | null {
  return (scope) => {
    try {
      const out = execFileSync('git', ['log', '-1', '--no-renames', '--diff-filter=D', '--format=%ct', 'HEAD', '--', scope], { cwd: workspace, encoding: 'utf8', stdio: ['ignore', 'pipe', 'ignore'] }).trim();
      return out ? Number(out) : null;
    } catch {
      return null;
    }
  };
}
```

Test: new file `src/cli/commands/__tests__/start-freshness.test.ts`, using a real temporary git repo (`mkdtempSync` under `os.tmpdir()`, `git init`, `git -c user.name=t -c user.email=t@t commit`). Pin commit times with the `GIT_COMMITTER_DATE` / `GIT_AUTHOR_DATE` env vars so assertions are exact. No timers are involved, so the fake-timers rule does not apply. Cases:

1. A path committed and never deleted → `null`.
2. A path that never existed → `null`.
3. A path added then deleted in a commit with `GIT_COMMITTER_DATE=@1790000000 +0000` → `1790000000`.
4. A path renamed with `git mv a.ts b.ts` then committed at a pinned time → the probe for `a.ts` returns that time.
5. A path that exists only in a commit reachable from `refs/pan/turn/x/y` (create a commit on a detached side ref with `git commit-tree` + `git update-ref refs/pan/turn/x/y <sha>`, never merged into HEAD) → `null`.
6. A directory that is not a git repo → `null`.

Clean up the temp dir in `afterEach` with `rmSync(dir, { recursive: true, force: true })`.

/**
 * A missing path is drift only when history deleted it after the plan was
 * written. Never deleted ⇒ the plan creates it; deleted before the plan ⇒
 * the plan restores it. With no plan baseline, any deletion counts as drift.
 */
export function isDriftedPath(deletedAtEpoch: number | null, planCreatedEpoch: number | null): boolean {
  if (deletedAtEpoch === null) return false;
  return planCreatedEpoch === null || deletedAtEpoch > planCreatedEpoch;
}

/** `plan.created` as epoch seconds, or null when absent or unparseable. */
export function planCreatedEpoch(plan: XBriefDocument): number | null {
  const ms = plan.plan.created ? Date.parse(plan.plan.created) : Number.NaN;
  return Number.isNaN(ms) ? null : Math.floor(ms / 1000);
}

      if (existsFn(join(workspaceRoot, scope))) continue;

## Intersecting repo rules

- **No `execSync` in dashboard server code.** `start-freshness.ts` uses `execFileSync`, which is allowed only because it is CLI code: its only importer is `src/cli/commands/start.ts`, which the dashboard runs as a separate `pan start` process. Do not import it from `src/lib/` or `src/dashboard/`.
- **One variant per operation in `src/lib`.** Do not add an async twin of the probe or an Effect wrapper around it.
- **File-size ratchet.** `start.ts` has an allowlist row at 1265 lines. The change must not grow it; see WI-2.
- **Quality gates before `pan done`:** `npm run typecheck`, `npm run lint`, and `npx vitest run` on the touched test files only. Do not run the full `npm test` on the host.

## Non-goals

- Surfacing a `pan start` refusal in the dashboard UI on the auto-start path. The refusal still lands in `spawn.log` only; that is a separate issue.
- Changing `--skip-freshness`, the refusal text of `formatPlanFreshnessRefusal`, or the glob-skipping rule.
- Adding a new-file marker or any new field to the xBRIEF schema or planner prompts.
- Following renames to suggest the new path of a moved file.
- Checking `files_scope` paths against branches other than the workspace `HEAD`.
