# PAN-4655 — Auto-settle idle conversations after a configurable number of days

**Issue:** [PAN-4655](https://github.com/eltmon/overdeck/issues/4655)
**Builds on:** [PAN-4639](https://github.com/eltmon/overdeck/issues/4639) (merged in `8e7ead8a0aa`, PR #4709) — the `settled_at` / `settle_reason` / `snoozed_until` columns, the triage store, and the Settled section.
**Sibling:** [PAN-4653](https://github.com/eltmon/overdeck/issues/4653) — auto-settle on merge (not touched here).
**Supersedes:** the archive-after-idle part of [#1485](https://github.com/eltmon/overdeck/issues/1485).

## Scope note

This issue adds one automatic path into the PAN-4639 Settled section: a sweep in the primary dashboard settles an operator conversation that has had no activity for `conversations.auto_settle_idle_days` days (default 3, `0` = off). It adds the setting (app_settings key, Settings control, CLI verb, HTTP route), one storage column so an unsettle or unsnooze restarts the idle clock, the sweep, and its timer host. It does not change the list UI's section rules, the manual triage route semantics, or anything PAN-4653 owns.

## Glossary

- **Operator conversation** — a row returned by `listConversations()` (`src/lib/overdeck/conversations.ts:553`): not archived, `origin <> 'vault'`, and name not starting `agent-`, `planning-` or `specialist-`. Only these rows can be idle-settled.
- **Agent conversation** — a `conversations` row whose name starts with one of `AGENT_CONVERSATION_PREFIXES = ['agent-', 'planning-', 'specialist-']` (`conversations.ts:417`). Never idle-settled.
- **Settle** — PAN-4639 operator triage state: `conversations.settled_at` (epoch ms) + `settle_reason` (`manual` | `merge` | `idle`). The session keeps running; only list placement changes. Undoable.
- **Snooze** — `conversations.snoozed_until` (epoch ms). Snoozed while `snoozed_until > now`. When the time passes nothing is written: the column keeps the past value and the client moves the row back to Inbox (PAN-4639 D13).
- **Idle-settle** — a settle written by this issue's sweep with `settle_reason = 'idle'`.
- **Idle clock reset** — new nullable column `conversations.idle_reset_at` (epoch ms). Written to `now` whenever the operator unsettles or unsnoozes. The sweep never idle-settles a conversation whose reset is newer than the cutoff.
- **Idle days (N)** — the value of app_settings key `conversations.auto_settle_idle_days`: integer 0..365, default 3 when unset. `0` = off.
- **Cutoff** — `cutoffMs = nowMs - N * 86_400_000`. A timestamp `<= cutoffMs` is "at least N days old".
- **Group** — a top-level conversation row plus every row nested under it in the Command Deck tree. The display parent of a row is its `criticOfConversationId` when that row is in the list, else its `parentConversationId` when that row is in the list, else none (the D27 rule in `src/dashboard/frontend/src/components/CommandDeck/conversation-tree.ts:66-71`, `displayParentId`). A row with no display parent is a **root**. PAN-4639 decides a group's section from its root (`sectionOf`, `CommandDeck/conversation-triage.ts:41-46`), so the sweep settles roots only.
- **Last activity of a row** — the newest of: `createdAt`, `lastAttachedAt` (written by resume/reattach, `conversations.ts:840 updateLastAttached`, called from `conversation-runtime.ts:1092`), and the transcript activity time (below).
- **Transcript activity time** — read by `readTranscriptLastActivityMs(path, cutoffMs)`: `stat(path).mtimeMs`; when that is `<= cutoffMs` it is returned directly (a record cannot be newer than the file's modified time); otherwise the timestamp of the last `user`/`assistant` record in the 512 KB tail via the existing `scanPendingInputs(path).lastRecordAt` (`src/lib/agent-enrichment.ts:536`), falling back to `mtimeMs` when no record parses. Claude Code touches a running transcript hourly without writing a record (PAN-4515, `conversation-list.ts:284-286`; `concerns.md` "A Claude Code transcript's modified time is not activity"), so mtime alone is never trusted when it is recent.
- **Waiting on the operator** — the conversation name appears in the pending-input feed `getConversationsPendingInputFeed` (`src/lib/overdeck/conversation-reads.ts:377`): an open AskUserQuestion / plan approval (transcript scan), a Codex approval, a terminal permission prompt, a pane choice menu, or a held handoff kickoff. This is a superset of the list's `pendingInputCount > 0`.
- **Sweep** — `sweepIdleConversations()` in the new `src/lib/overdeck/conversation-idle-settle.ts`, one pass over all operator conversations.
- **Host / patrol** — `src/dashboard/server/services/conversation-idle-settle-service.ts`, the timer that runs the sweep in the primary dashboard (pattern of `services/scheduled-message-patrol.ts`).
- **Peer dashboard** — a second dashboard process sharing the database (`isPeerDashboardProcess()`, `src/lib/boot-gates.ts:36`). Never runs the sweep.
- **Deacon freeze** — app_settings `deacon.globally_paused` (`isDeaconGloballyPaused()`, `control-settings.ts:166`), the operator's emergency stop. The sweep does nothing while it is on.

## Decisions

- **D1 — Activity definition.** A row's last activity is `max(createdAt, lastAttachedAt, transcriptActivity)`. Transcript activity covers both agent output and operator messages, because an operator message is written to the transcript as a `user` record. `lastAttachedAt` counts because it is written only by an operator resume/reattach. Opening or reading a conversation in the dashboard without resuming does not count.
- **D2 — Cheap read.** The sweep does not call the list enrichment. Per row it does one `stat`; only when the modified time is newer than the cutoff does it read the transcript tail (`scanPendingInputs`, 512 KB) to find the last turn record. The list's PAN-4515 rule (`lastRecordAt ?? mtime`) is the same definition.
- **D3 — Idle clock restart.** New column `idle_reset_at integer` on `conversations`. `unsettleConversation` and `unsnoozeConversation` set it to `nowMs`. A snooze that ends by time needs no write: the past `snoozed_until` value is itself the restart point. The group anchor is `max(member last activities, root.idle_reset_at, root.snoozed_until when <= now)`. A group is idle when `anchor <= cutoffMs`.
- **D4 — Groups, roots only.** The sweep builds groups with the D27 display-parent rule and settles only roots. A group is idle only when every member is idle. A root with a busy lane or successor stays in Inbox. Children are never written.
- **D5 — Never settled.** Skipped: agent conversations (excluded by `listConversations()`, plus a defensive `isAgentConversationName` check); roots already settled; roots snoozed (`snoozed_until > now`); roots with `releasedTo` set (continued on another machine, read-only here); groups where any member is waiting on the operator (pending-input feed); groups where any member has a fork in progress (`forkStatus` set and not `'failed'`); groups where a live member has no resolvable transcript (activity unknown).
- **D6 — Unknown means skip.** If `listLiveConversationSessions()` returns `null`, or the pending-input feed returns status 500 or a non-array body, the whole sweep settles nothing and logs once. A failed read of the setting reads as `0` (off).
- **D7 — Atomic guarded write.** The sweep settles through a new store function `settleIdleConversation(name, cutoffMs, nowMs)` whose `UPDATE` re-checks `settled_at IS NULL`, `archived_at IS NULL`, snooze ended at or before the cutoff, and `idle_reset_at` at or before the cutoff. An operator unsettle that lands between the sweep's read and its write therefore wins.
- **D8 — Host and cadence.** A dashboard-process patrol, not a deacon-lite routine, because the pending-input feed and the list cache live in the dashboard process. First sweep 2 minutes after boot (`IDLE_SETTLE_BOOT_DELAY_MS = 120_000`), then every 15 minutes (`IDLE_SETTLE_INTERVAL_MS = 900_000`). Skipped on a peer dashboard, while the Deacon is frozen, with `OVERDECK_DISABLE_IDLE_SETTLE=1`, and while a previous sweep is still running. The setting is read on every sweep, so a change applies on the next sweep with no restart.
- **D9 — Make room in `main.ts` first.** `main.ts` is at 997 of 1000 lines, so registering a fourth patrol there would break the file-size lint (and any concurrent merge would push it over). WI-5 extracts the two existing conversation sweep starts/stops into `services/conversation-sweeps.ts`; WI-6 adds the idle-settle host there. `main.ts` shrinks.
- **D10 — Setting storage and validation.** app_settings key `conversations.auto_settle_idle_days`, stored as a decimal string. One validator, `parseAutoSettleIdleDays(value: unknown): number | null`, accepts an integer number or a string of digits in `0..365` and is used by the CLI, the route, and the getter. Unset → 3. A stored value the validator rejects → 3 with one `console.warn`.
- **D11 — Route.** `GET` and `PUT /api/conversations/triage/auto-settle` in `routes/conversation-triage.ts`, body/response `{ idleDays: number }`. The two-segment path cannot be read as a conversation name by `GET /api/conversations/:id`, and the object shape leaves room for PAN-4653 to add an `onMerge` field without a second route.
- **D12 — CLI verb.** `pan conversations auto-settle-idle-days [days]` in a new file `src/cli/commands/conversations/auto-settle.ts`, writing app_settings directly like `auto-archive-on-merge` (works with the dashboard down; the sweep reads the value each pass).
- **D13 — Default on.** The default is 3 (from the issue). After upgrade the first sweep settles every operator conversation already idle for 3 days. Settling is display-only and undoable, so no confirmation or warning stage is added (the issue drops #1485's 7-day warning).
- **D14 — #1485.** The work agent comments on #1485 that its archive-after-idle part is superseded by idle-settle (PAN-4655) and its warning stage is dropped because settling is undoable. It does not close #1485: the archive-at-day-10 and favorite-clearing parts are not delivered here, and closing is the operator's call.
- **D15 — Sizing.** One xBRIEF, not sibling issues. The plan touches ~24 files, but the subsystem count (first two path segments) is inflated by single files (`drizzle/overdeck`, `sync-sources/skills`, `features/conversations.mdx`, `docs/DASHBOARD-ARCHITECTURE.md`, `scripts/frontend-test-subset.txt`, `tests/unit`). Splitting the Settings control or CLI verb into a sibling would not reduce that count, and the issue requires them with the sweep.

## Requirements

- **FR-1** — `conversations` has a nullable `idle_reset_at integer` column on fresh and existing databases.
- **FR-2** — Unsettle and unsnooze (store functions and therefore `POST /api/conversations/triage`) set `idle_reset_at` to the request time.
- **FR-3** — `settleIdleConversation(name, cutoffMs, nowMs)` writes `settled_at = nowMs`, `settle_reason = 'idle'`, `snoozed_until = NULL` only when the row is unarchived, unsettled, its snooze ended at or before `cutoffMs` (or it has none), and its `idle_reset_at` is null or at or before `cutoffMs`; it returns whether a row changed.
- **FR-4** — `getConversationsAutoSettleIdleDays()` returns 3 when the key is unset, the stored integer when valid (0..365), 3 for an invalid stored value, and 0 when the read throws; `setConversationsAutoSettleIdleDays(days)` stores a valid value and throws `RangeError` otherwise.
- **FR-5** — With N = 3, a root operator conversation whose group anchor is 3 days old is settled with reason `idle`; one whose anchor is 2 days old is not. With N = 0 nothing is settled and no transcript is read.
- **FR-6** — A conversation the operator unsettled (or unsnoozed) at time T is not idle-settled before T + N days, even when its transcript is older.
- **FR-7** — A snoozed root (`snoozed_until > now`) is never idle-settled; after its snooze ends at time S it is not idle-settled before S + N days.
- **FR-8** — Agent conversations, released roots, groups waiting on the operator, groups with a fork in progress, and groups with a live member whose transcript cannot be resolved are never idle-settled.
- **FR-9** — A group is idle only when every member is idle; only the root is written.
- **FR-10** — When liveness or the pending-input feed is unknown, the sweep settles nothing.
- **FR-11** — The host runs the sweep 2 minutes after start and every 15 minutes after, only in the primary dashboard, never while the Deacon is frozen or `OVERDECK_DISABLE_IDLE_SETTLE=1`, never overlapping, and invalidates the conversation-list cache after any settle.
- **FR-12** — `GET /api/conversations/triage/auto-settle` returns `{ idleDays }`; `PUT` with a valid `idleDays` stores it and returns it; an invalid value returns 400; a failed origin check returns 403.
- **FR-13** — Settings → Conversations shows an "Auto-settle idle conversations" number input (0–365, days) bound to the route.
- **FR-14** — `pan conversations auto-settle-idle-days [days]` prints or sets the value; invalid input exits 1.
- **FR-15** — Docs describe idle auto-settle: `features/conversations.mdx`, `docs/DASHBOARD-ARCHITECTURE.md`, `sync-sources/skills/pan-conversations/SKILL.md`; #1485 carries a supersession comment.
- **NFR-1** — The sweep never runs `execSync` or any synchronous child process; file reads are `fs/promises` (`stat`) and the existing async tail reader. Per-row work runs through `withConcurrencyLimit` (limit 8).
- **NFR-2** — Every delay- or time-dependent test uses `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` or an injected `now`; no real waits.
- **NFR-3** — `src/dashboard/server/main.ts` ends with fewer lines than on `origin/main`; no file crosses the 1000-line ceiling and no allowlist row changes.

Algorithm (in this order — cheap checks first, IO last):
1. `days = idleDays()`; if `days <= 0` return `[]` (no other dep is called).
2. `nowMs = now()`, `cutoffMs = nowMs - days * DAY_MS`.
3. `rows = listRows()`, `clocks = listIdleClocks()`, `groups = groupByDisplayRoot(rows)`.
4. Candidate roots: keep a group when all hold — `!isAgentConversationName(root.name)`; `!root.releasedTo`; root clock `settledAtMs === null`; root `snoozedUntilMs === null || snoozedUntilMs <= cutoffMs` (a future snooze, or one that ended less than N days ago, fails); root `idleResetAtMs === null || idleResetAtMs <= cutoffMs`; every member `Date.parse(createdAt) <= cutoffMs` and (`lastAttachedAt` null or `<= cutoffMs`); no member has `forkStatus` set and `!== 'failed'`.
5. No candidates → return `[]` (liveness and the feed are not read).
6. `live = await listLiveSessions()`; `null` → log `[idle-settle] terminal sessions could not be listed; skipping this sweep` and return `[]`.
