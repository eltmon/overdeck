# PAN-4562 — Replace harness-name branches with declared harness capabilities

**Issue:** [PAN-4562](https://github.com/eltmon/overdeck/issues/4562)
**Status:** planned (auto mode, 2026-10-19)

## Glossary

- **Harness / runtime** — the coding-agent program Overdeck launches (`claude-code`, `ohmypi`, `codex`, `acp`, `kimi-code`, `opencode`, `muse`, `prime-agent`). `RuntimeName` (in `packages/contracts/src/harness-behavior.ts`, aliased to `Harness` in `packages/contracts/src/types.ts`) is the closed union of those names. `pi` is a legacy stored alias for `ohmypi`.
- **Harness-name branch** — a comparison of a harness name or transcript kind against a string literal, such as `harness === 'kimi-code'` or `transcriptKind !== 'claude-jsonl'`. This is the code shape the issue removes.
- **Behavior table** — `HarnessBehavior`, the per-runtime declaration record in `packages/contracts/src/harness-behavior.ts` (`CLAUDE_CODE_BEHAVIOR`, `OHMYPI_BEHAVIOR`, …, looked up with `getHarnessBehavior(name)` / `getRuntimeBehavior(name)`). It already carries identity fields (`displayName`, `executableName`), **adapter-kind selectors** (`launchCommandKind`, `deliveryKind`, `readinessKind`, `transcriptKind`, `sessionIdSource`) and a few capability booleans (`supportsPtySupervisor`, …). The frontend imports it from `@overdeck/contracts`.
- **HarnessCapabilities** — the new record this issue adds: one required field per behavior decision that the ten target files currently make by harness name. It lives at `HarnessBehavior.capabilities`.
- **Adapter selection** — a branch whose only job is to pick a harness-specific parser, resolver, or launcher-field builder. The issue exempts these from "no name branches". This plan expresses them as an exhaustive `Record<HarnessTranscriptKind, …>` table or a `switch` on an adapter-kind field, so no string comparison remains and `tsc` fails when a new kind has no entry.
- **Ratchet** — a shrink-only lint baseline: a per-file count that may go down freely and may go up only in a commit that carries an issue reference (`scripts/lint-ratchet-audit.sh`). Model: `scripts/lint-effect-facades.sh` + `scripts/effect-facades-baseline.txt`.
- **Fake runtime** — a test-only harness definition (name `fake-harness`) injected by mocking the definition lookups in `@overdeck/contracts`. If consumer code reads only declared fields, the fake drives behavior with no consumer code change.

## Problem

Harness-specific behavior is decided by name comparisons spread over the codebase. `grep -rnE "harness === '|transcriptKind ===" src` (tests excluded) finds 208 lines in 74 files. Every new harness means finding each check by hand, and a missed one becomes a silent gap. Two live examples found during planning:

- `src/dashboard/frontend/src/components/CommandDeck/ConversationRow.tsx`, `shortHarness()` (line 38): there is no `muse` branch, so a Muse conversation shows the raw id `muse` instead of `Muse Code`.
- `src/lib/launcher-generator.ts` line 410 (`const receiptChannel = config.harness === 'codex'`): `opencode` has no branch, so an OpenCode launch records the Claude channel `append-system-prompt-file` in its context receipt even though it launches through `acp-host --context-file`, exactly like `acp`.
- `src/lib/conversations/scanner.ts` `parseMetadata` (line 81): `kimi-code` and `prime-agent` transcripts fall through to the Claude JSONL parser.

## Goals

1. Declare every behavior decision of the ten target files once per runtime, in `HarnessCapabilities`.
2. Make the ten files read declarations, never names.
3. Add a ratchet so the count of name branches in `src/` can only go down.
4. Prove with a fake runtime definition (a `HarnessBehavior` with its `capabilities` and adapter-kind fields) that a new definition changes CLI and dashboard behavior with no consumer code change.
5. Document the model and how a new harness declares it.

## Non-goals

- Converting files outside the ten in the issue table. Known dense leftovers for a follow-up issue: `src/lib/overdeck/conversation-delivery.ts` (8), `src/lib/overdeck/conversation-forks.ts` (6), `src/lib/agents/spawn.ts`, `src/lib/agents/recovery.ts`, `src/lib/settings-api.ts`, `src/lib/overdeck/conversations.ts` (`normalizeHarness`), `src/lib/overdeck/conversation-restart-all.ts`. The ratchet holds them at their current counts.
- Changing `src/lib/harness-policy.ts`. It keys on names on purpose (ToS rules). The ratchet excludes it.
- Moving the existing top-level capability booleans of `HarnessBehavior` (`supportsPtySupervisor`, `supportsChannelsBridge`, `supportsConversationStreaming`, `supportsPatchProjection`, `usesRpcFifo`, `usesCodexHome`, `injectsPromptTimeMemory`, `steerKind`) into `capabilities`. They are already declarative; moving them touches ~25 call sites outside scope.
- Making `HarnessBehavior.nativeCommands?` and `HarnessBehavior.effortLevels?` required. The "no optional fields" acceptance criterion applies to the new `HarnessCapabilities` type.
- Changing the legacy default "missing or unknown harness ⇒ claude-code". Pre-PAN-636 rows rely on it.
- Counting `switch (harness) { case 'codex': … }` statements in the ratchet. The ratchet counts `===`/`!==` comparisons only, as the issue specifies.
- Any behavior change other than the three named in FR-12 and FR-13.

## Ratchet definition

`scripts/lint-harness-branches.sh` counts, per file, the occurrences of either regex (POSIX ERE, `grep -oE`), after dropping lines whose first non-blank characters are `//`, `*`, or `/*`:

```
N='claude-code|claude|ohmypi|pi|codex|acp|kimi-code|opencode|muse|prime-agent|[a-z-]+-jsonl'
P1="[A-Za-z0-9_\$.]*([Hh]arness|transcriptKind)[[:space:]]*[!=]==[[:space:]]*['\"]($N)['\"]"
P2="['\"]($N)['\"][[:space:]]*[!=]==[[:space:]]*[A-Za-z0-9_\$.]*([Hh]arness|transcriptKind)"
```

This catches `conv.harness`, `config.harness`, `file.harness`, `requestedHarness`, `launchHarness` and both operand orders, and it ignores `typeof entry.harness === 'string'` (the literal is not a harness name). It counts occurrences, so `harness === 'acp' || harness === 'opencode'` counts 2.

Scanned: every `src/**/*.ts` and `src/**/*.tsx`. Excluded: `*.test.ts`, `*.test.tsx`, any path containing `/__tests__/`, `src/lib/harness-policy.ts`, `src/lib/runtimes/storage/*`, and the runtime adapter files `src/lib/runtimes/{acp,claude-code,codex,kimi-code,muse,ohmypi,pi,prime-agent}.ts` (runtime definitions). `src/lib/runtimes/index.ts` is scanned. `packages/contracts/` is outside `src/`, so the behavior table is not scanned.

On the planning tree (2026-10-19, commit `6f80870ebfc`) this definition gives 408 occurrences in 90 files; the ten target files account for 112 (conversation-runtime 39, scanner 12, harness-binary 9, runtimes/index 8, launcher-generator 8, activity-summary 8, ConversationRow 8, session-history 7, conversation-reads 6, conversation-message 6).

Baseline rows: `<count> <path>`, sorted by path, two `#` header lines. Modes mirror `lint-effect-facades.sh`: check (fail on a raised row or a file with no row; lower counts pass with a hint), `--update` (lower to `min(baseline, current)`, drop rows at 0, never add, initialize a missing file). Pass message: `✓ harness-branch ratchet passed (<total> in <files> files; none new)`. Failure lines: `✖ <path>: <current> harness-name branches (baseline <n>)` and `✖ <path>: NEW file with <n> harness-name branches`, followed by `Replace the branch with a HarnessCapabilities field — see configuration/harnesses.mdx "Harness capabilities".`
