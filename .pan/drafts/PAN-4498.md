# PAN-4498 — Conversation bookmarks: mark a message by clicking its role icon and jump back to it later

**Issue:** [PAN-4498](https://github.com/eltmon/overdeck/issues/4498)
**Planned:** 2026-10-03 (auto planning; no operator Q&A — defaults recorded under "Decisions")
**Base commit:** `b8853b45510` on `feature/pan-4498`

## Glossary

- **Conversation** — a row in the `conversations` table of `overdeck.db`, addressed in HTTP routes by its unique `name` (for example `conv-flywheel`). Its primary key `conversations.id` is a text UUID; the `LegacyConversation.id` number returned by `getConversationByName` is a different, legacy id and must not be used as a foreign key.
- **Transcript message** — a `ChatMessage` (`src/dashboard/frontend/src/components/chat/chat-types.ts`) parsed from the harness transcript by the server. Its `id` is the **stable message id**: the JSONL `uuid` for Claude Code (`src/dashboard/server/services/conversation/parser.ts`, `id: entry.uuid ?? …`), `entry.id` for ohmypi, and `<harness>-<role>-<sequence>` (line order in an append-only file) for Codex, Kimi and ACP.
- **Optimistic message** — a client-side placeholder whose `id` starts with `optimistic-` (a message the operator sent that the transcript has not echoed yet). It has no stable id and cannot be bookmarked.
- **Bookmark** — an operator annotation: `(conversation, messageId, label, messageCreatedAt, createdAt)`. Stored by Overdeck in `overdeck.db`; never written into the harness transcript.
- **Role icon** — the 14 px icon at the left of an assistant message (lucide `Bot`, today `messageRows.tsx` line 220) and, new in this issue, a lucide `User` icon at the right of a user message bubble.
- **Main timeline** — the `MessagesTimeline` rendered by `ConversationView` inside `ConversationPanel`. Other `MessagesTimeline` mounts (subagent transcript, `SessionTranscript`, `DirectoryTranscript`, `TerminalPanel`) are **not** main timelines and never offer bookmarking.
- **Bookmarks drawer** — the new list of a conversation's bookmarks, rendered under the conversation header (same slot style as the existing "About" drawer), opened by a new **Bookmarks** header toggle.
- **Jump** — clicking a bookmark in the drawer: the main timeline scrolls that message into view (centered) and **flashes** it (a 2 px primary outline for 1600 ms).
- **Door** — Overdeck's term for the single module that owns all reads and writes of one table (for example `src/lib/overdeck/conversation-pull-requests.ts`).

## Problem

Long conversations (hundreds of messages) bury the moments worth returning to: a finding, a decision, a draft to reuse. The timeline has text search (Ctrl+F) and palette search, but no way to mark a message and come back to it after a reload.

## Goals

1. Click a message's role icon to bookmark it, with a default label from the message's first line.
2. See all bookmarks for the conversation in a drawer; click one to jump to the message and highlight it briefly.
3. Rename and remove bookmarks from the drawer, and from a popover opened by clicking the role icon of a bookmarked message.
4. Bookmarks survive dashboard reloads, virtualization, and new messages, because they key on the stable message id.

## Non-goals

- Bookmarks across conversations (a global list) — later issue.
- Offering bookmarked messages as handoff context — later issue.
- Carrying bookmarks to a fork/handoff successor conversation.
- Bookmarking work-log (tool call) rows, slash-command dividers, fork-summary or review-context blocks, command results, system rows, optimistic/held/subagent-routed user messages, or a message that is still streaming.
- Bookmarking inside a subagent transcript, `SessionTranscript`, `DirectoryTranscript`, or `TerminalPanel`.
- Live cross-tab or cross-device sync of bookmarks (no event emission; another tab sees changes on its next fetch).
- A `pan` CLI verb for bookmarks.
- Writing anything into the harness transcript (JSONL or other session files).
- Server-side verification that a message id exists in the transcript.
- Auto-switching the view (terminal → conversation, subagent → main) when a bookmark is clicked.

## Requirements

### Functional

- **FR-1** — `overdeck.db` has a `conversation_bookmarks` table: `conversation_id text NOT NULL` (FK → `conversations.id`, `ON DELETE cascade`), `message_id text NOT NULL`, `label text NOT NULL`, `message_created_at text` (nullable ISO string), `created_at integer NOT NULL` (epoch ms), `updated_at integer NOT NULL` (epoch ms), `PRIMARY KEY(conversation_id, message_id)`. Present in the init migration and added to existing databases by a schema top-up.
- **FR-2** — A door module `src/lib/overdeck/conversation-bookmarks.ts` is the only code that reads or writes `conversation_bookmarks`. It exports `listConversationBookmarks(name)`, `upsertConversationBookmark(name, input)`, `removeConversationBookmark(name, messageId)` and the validation helper `validateBookmarkInput(input)`.
- **FR-3** — `GET /api/conversations/:name/bookmarks` returns `{ bookmarks: ConversationBookmark[] }` ordered by `message_created_at` ascending (nulls last), then `created_at` ascending; 404 `{ error: 'Conversation not found' }` for an unknown name.
- **FR-4** — `PUT /api/conversations/:name/bookmarks/:messageId` with body `{ label: string, messageCreatedAt?: string }` creates the bookmark or renames it (upsert; `created_at` kept on rename, `updated_at` refreshed) and returns `{ bookmark }`. It returns 400 for an invalid body (rules in FR-6), 404 for an unknown conversation, and 409 `{ error: 'Bookmark limit reached (500)' }` when creating a 501st bookmark.
- **FR-5** — `DELETE /api/conversations/:name/bookmarks/:messageId` removes the bookmark and returns `{ removed: true }`, or `{ removed: false }` when none existed; 404 for an unknown conversation.
- **FR-6** — Validation: `messageId` (URL-decoded) is 1–256 chars and does not start with `optimistic-`; `label` is trimmed, then must be 1–200 chars; `messageCreatedAt`, when present, must be a string that `Date.parse` accepts.
- **FR-7** — In the main timeline, every bookmarkable message renders its role icon as a button. Assistant messages keep the `Bot` icon on the left; user messages gain a `User` icon to the right of the bubble. Clicking the role icon of a message that is **not** bookmarked creates a bookmark whose label is `defaultBookmarkLabel(message.text)`.
- **FR-8** — A bookmarked message's role icon renders as a filled lucide `Bookmark` icon in `var(--primary)` with `aria-pressed="true"` and `title="Bookmarked: <label>"`. That is the timeline marker.
- **FR-9** — Clicking the role icon of a bookmarked message opens a popover anchored to the icon with a label input (pre-filled with the current label), a **Save** button (Enter also saves), a **Remove** button, and Escape or outside-click to close.
- **FR-10** — The conversation header (non-embedded `ConversationPanel`) has a **Bookmarks** toggle button (lucide `Bookmark` icon, text `Bookmarks`, plus the count when > 0) styled with the existing `conversationAboutToggle` / `conversationAboutToggleActive` classes. It opens and closes the bookmarks drawer.
- **FR-11** — The bookmarks drawer lists each bookmark with its label, its message time (`formatTimestamp(messageCreatedAt)`, or the bookmark's `createdAt` when `messageCreatedAt` is null), a rename control (pencil → inline input, Enter saves, Escape cancels) and a remove control (×). With no bookmarks it shows: `No bookmarks yet. Click the icon beside a message to bookmark it.`
- **FR-12** — Clicking a bookmark's label in the drawer jumps the main timeline: the row scrolls into view (centered, including rows inside the virtualized region) and is flashed with a 2 px `var(--color-primary)` outline for 1600 ms, then the outline is removed.
- **FR-13** — When the bookmarked message is not among the loaded timeline rows, the drawer shows `This message is not in the loaded transcript.` under that bookmark instead of scrolling.
- **FR-14** — After a reload, or after new messages arrive, existing bookmarks still mark the same messages and jump to them, because both the marker lookup and the jump look rows up by message id, never by index or scroll offset.

### Non-functional

- **NFR-1** — No change to any harness transcript file, transcript parser, or message id derivation.
- **NFR-2** — The bookmarks fetch never breaks the conversation view: a non-OK response or network error yields an empty list (no toast, no thrown render error).
- **NFR-3** — `src/dashboard/frontend/src/components/chat/ConversationPanel.tsx` grows by at most 10 lines net (allowlist cap 1531, file is 1518 at base); `src/dashboard/server/routes/conversations.ts` is not touched. `npm run lint` (which runs `scripts/lint-file-size.sh`) passes.
- **NFR-4** — At most 500 bookmarks per conversation (enforced by the door, FR-4).
- **NFR-5** — Delay-based behavior (the 1600 ms flash) is tested with `vi.useFakeTimers()` + `vi.advanceTimersByTime*`, never real waits.
- **NFR-6** — Dashboard-server-reachable code uses no `execSync` (the door and route are synchronous SQLite through `getOverdeckDatabase()`, which is the existing pattern; no child processes).

## Decisions (auto mode)

- **D1 Storage** — A dedicated `conversation_bookmarks` table in `overdeck.db` behind a door, mirroring `conversation_pull_requests` (PAN-3822). Bookmarks are operator-authored facts that cannot be derived from git, the tracker, the PR, or the terminal, so storing them is consistent with "store no status you can derive". Rejected: a JSON column on `conversations` (row churn, no per-bookmark upsert), browser `localStorage` (does not survive a different browser/device; the issue says "stored by Overdeck").
- **D2 Foreign key by name subquery** — The door resolves `conversations.id` with `(SELECT id FROM conversations WHERE name = ?)`; routes 404 first via `getConversationByName(name)`. Never use `LegacyConversation.id` (a legacy number).
- **D3 Default label** — computed client-side by `defaultBookmarkLabel(text)`: take the first non-empty line, strip a leading markdown prefix matching `/^\s*(#{1,6}\s+|>\s*|[-*+]\s+|\d+\.\s+)/`, remove backticks and `**`, collapse whitespace, and cut to 80 chars with a trailing `…` when longer. Empty result → `Bookmarked message`. The server only enforces FR-6.
- **D4 Second click opens a popover** — The issue says both "Remove or rename … by clicking the icon again" and that the first click bookmarks. A popover with rename + remove satisfies both without making accidental removal one click away.
- **D5 Marker** — The role icon itself becomes a filled `Bookmark` glyph in primary color (FR-8). Rejected: a second glyph beside the timestamp (adds a visual element to every row, and the timestamp line differs between user and assistant rows).
- **D6 User role icon renders everywhere** — the new `User` icon renders on user message bubbles in every `MessagesTimeline` mount (mirroring how `Bot` already renders everywhere); it is a button only in the main timeline.
- **D7 Context provider, not prop drilling** — `ConversationBookmarksProvider` wraps the panel next to the existing `ConversationPullRequestProvider` (`ConversationPanel.tsx` line 698). Header toggle, drawer, role icons, and the main timeline read the context. The main timeline opts in with a `bookmarksEnabled` prop set only by `ConversationView`, so the subagent transcript (rendered inside the same provider) never shows bookmark controls. This keeps `ConversationPanel.tsx` growth within NFR-3.
- **D8 Jump channel** — the drawer calls `jumpTo(messageId)` on the context, which stores `jumpRequest = { messageId, nonce }`. The main timeline handles each nonce once (same idiom as `handledTargetKeyRef` at `MessagesTimeline.tsx` line 388) and reports `resolveJump(nonce, found)`. A request made while the main timeline is not mounted (terminal view or subagent open) is handled when it mounts.
- **D9 Route scopes** — `GET /api/conversations/:name/bookmarks` is added to `ROUTE_SCOPES` as `read:conversations` (same as the kickoff GET). `PUT`/`DELETE` stay unlisted, so registry credentials need `admin` (the table's fail-closed default); dashboard root credentials always pass.
- **D10 No events** — mutations update the react-query cache from the response and invalidate `['conversation-bookmarks', name]`; no `conversation.*` event is emitted (cross-tab sync is a non-goal).
- **D11 Not bookmarkable** — a message is bookmarkable only when: it is in the main timeline; `role` is `user` or `assistant`; it has no `commandResult`; its id does not start with `optimistic-`; it is not `deliveryState` `held` or `subagent`; and it is not streaming (`streaming !== true`, and for assistant rows `!(isStreaming && !message.completedAt)`). Slash-command dividers and fork-summary/review-context blocks have no role icon and stay unchanged.
- **D12 No CI frontend-subset entry** — the new frontend tests are not added to `test:frontend-subset` in the root `package.json` (matching PAN-4499's chat tests); each item's `verify_commands` run them explicitly.
