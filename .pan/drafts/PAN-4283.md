# PAN-4283 — Close-out settings in the dashboard, disk cost and cleanup, and an honest teardown row

**Issue:** https://github.com/eltmon/overdeck/issues/4283
**Planned:** 2026-09-28 (auto planning, `pan plan --auto`), base `affa628a9b6`

## Glossary

- **Close-out** — the ceremony `closeOut()` in `src/lib/lifecycle/workflows.ts` (run by `pan close <id>` and the dashboard Close Out button). It verifies the merge, archives planning, completes the xBRIEF, tears down the workspace, and closes the tracker issue with a Definition-of-Done comment.
- **`[close_out]` block** — the table in `~/.overdeck/cloister.toml` typed as `CloseOutConfig` (`src/lib/cloister/config.ts:321`, search `export interface CloseOutConfig`). Four keys: `remove_workspace`, `delete_feature_branch`, `auto`, `auto_delay_minutes`. Defaults live in `DEFAULT_CLOISTER_CONFIG.close_out` (`config.ts:533`, search `close_out: {`).
- **Effective value** — the value close-out actually uses: `deepMerge(DEFAULT_CLOISTER_CONFIG, parsedFile)` (`loadCloisterConfig`, `config.ts:670`).
- **Source** — where the effective value came from: `cloister.toml` when the raw parsed file has the key under `[close_out]`; `default` otherwise.
- **DoD row 9 / teardown row** — the ninth Definition-of-Done row, `id: 'teardown'` in `DOD_ROWS` (`src/lib/lifecycle/dod.ts:74`). `closeOut()` pushes it at `workflows.ts:345-350` (search `const teardownDef = DOD_ROWS.find`). `formatDodGateComment` (`workflows.ts:426`) renders `| num | title | status | observed |` into the tracker close comment.
- **Closed-issue workspace** — a directory `<project>/<workspaces_dir>/feature-<issue>[ -strike | -slot-N ]` (shapes from `resolveIssueWorkspaceDirs`, `src/lib/workspaces/shapes.ts:49`) whose tracker issue is closed.
- **Closed-issue reaper** — `reconcileClosedIssueAgents` (`src/lib/cloister/closed-issue-reaper.ts:156`), run every 60 s by deacon-lite (`src/lib/cloister/deacon-lite.ts:515`). For every closed issue it calls `reapIssueResidue` (`src/lib/cloister/reap-issue-residue.ts`), which — when `isBranchMerged` is not `unmerged` — removes the workspace and deletes the local and remote feature branch **regardless of `[close_out]`**.
- **Inert key** — a config key nothing in `src/` reads.

## Problem

1. None of the `[close_out]` keys is in the dashboard. With `remove_workspace = false` (default, `config.ts:534`; fallback `?? false` at `workflows.ts:336`), 21 closed issues kept 3.5–5 GB worktrees (~47 GB). The operator asked for a UI setting.
2. DoD row 9's `expected` text says "workspace and configured branches removed …" and the row reports `pass` with step details, even when the workspace was kept on purpose.
3. The default was never chosen deliberately.

### Verified facts that shape the plan

- **F1 — `auto` and `auto_delay_minutes` are inert.** Their only consumer was the automatic close-out routine inside the old `deacon.ts`, deleted in the Cut (commit `94255f055fe`, "cut deacon.ts to deacon-lite + hygiene-scheduler (PAN-3917 W4)"). `git grep -n "close_out" src` finds only `config.ts` and `workflows.ts:334`, which reads `remove_workspace` and `delete_feature_branch` only. The Cut's design (docs/THE-CUT.md: "deacon-lite: 4 fixed routines") is authoritative. `sync-sources/skills/pan-close/SKILL.md` ("Close-Out Configuration") falsely says `auto` lets the reaper close out automatically, and shows `remove_workspace: false` as YAML.
- **F2 — the existing write path clobbers the file.** `PUT /api/cloister/config` (`src/dashboard/server/routes/cloister.ts:189`) calls `saveCloisterConfigSync(updates)` which `stringify`s the whole object the frontend sends (the merged config from GET). One UI save materializes every default into the file (so every key reads as `cloister.toml`-sourced) and drops all comments. The live operator file is hand-written with dated comments.
- **F3 — the reaper overlaps these settings.** See glossary. `delete_feature_branch = false` and "branches are kept" hold for the ceremony only; within ~60 s the reaper may still delete a merged branch and remove the workspace. The plan must not depend on the reaper working: 21 workspaces piled up despite it. The likely mechanism is the Deacon freeze — `deacon.globally_paused` (PAN-4210) makes `runDeaconLite()` return before any routine, closed-issue reaping included — and a GitHub quota pause also makes the reaper treat every issue as open. The disk line and "Clean up now" are the backstop for exactly those states.
- **F4 — the stale-list merge check misses squash merges.** `collectStaleWorkspaceRows` (`src/cli/commands/workspace-list.ts`, search `isBranchMerged(projectRoot`) uses only `git merge-base --is-ancestor`. The squash-aware check is `isBranchMerged(branchName, projectPath)` in `src/lib/close-out.ts` (returns `{ status: 'merged' | 'unmerged' | 'no-branch' }`).
- **F5 — `pan workspace destroy <id>`** (`destroyCommand`, `workspace-list.ts`, search `export async function destroyCommand`) removes every shape and also runs `git branch -D` on each shape's local branch. It does not check for uncommitted changes itself.
- **F6 — `src/lib/lifecycle/workflows.ts` is at its file-size ceiling** (1158 lines, `scripts/file-size-allowlist.txt` row `1158 src/lib/lifecycle/workflows.ts # PAN-3727`). Growth needs that row updated in the same commit to `<new count> src/lib/lifecycle/workflows.ts # PAN-4283`.
- **F7 — every new HTTP route needs a row in `tests/unit/lib/overdeck/no-loss-matrix.ts`** or the no-loss test fails CI. Existing cloister rows are at lines ~131-141 (search `// ── cloister.ts`).
- **F8 — frontend tests run in CI only when listed** in root `package.json` script `test:frontend-subset`.
- **F9 — `closeOut()` re-reads `cloister.toml` on every run** (`loadCloisterConfig()` at `workflows.ts:334`, no cache), so a saved setting takes effect on the next close-out without a restart.

## Decisions

- **D1 — Do not resurrect automatic close-out.** It contradicts the Cut. The section renders all four controls, but `auto` and `auto_delay_minutes` render **disabled** with the text: "Not in effect. Automatic close-out was removed in PAN-3917; nothing reads this key. Close out with `pan close <id>` or the Close Out button." The PUT endpoint rejects writes to them (HTTP 400). The config type marks them `@deprecated`; the stale rationale comment above `auto: true` in `DEFAULT_CLOISTER_CONFIG` is replaced. The keys stay in the type so existing files still parse.
- **D2 — New narrow endpoints, not the clobbering PUT.** `GET /api/cloister/close-out` and `PUT /api/cloister/close-out` read/write only `[close_out]` keys through a new lib module. The PUT parses the raw file, sets one key, and writes the raw object back — it never materializes defaults. TOML comments are still lost on write (`@iarna/toml` `stringify`); documented, out of scope.
- **D3 — PUT refuses to overwrite an unparseable file.** If `cloister.toml` exists and fails to parse, the PUT returns HTTP 409 with `cloister.toml does not parse; fix it by hand before saving from the dashboard` and writes nothing.
- **D4 — Default `remove_workspace = true`.** A kept workspace has no known use once its issue is merged and closed. Flip `DEFAULT_CLOISTER_CONFIG.close_out.remove_workspace` and the `?? false` fallback at `workflows.ts:336`. This applies to every install whose file does not set the key (deepMerge), not only fresh installs — the docs say so. `delete_feature_branch` stays `false`.
- **D5 — Honest DoD row 9.** Status stays `pass` (row is non-overridable; keeping the workspace on purpose is not a miss). The `observed` text is built by a pure helper `describeTeardownObserved` in `src/lib/lifecycle/dod.ts`; `expected` becomes neutral.
- **D6 — Disk line counts closed issues, cleanup requires closed AND merged AND clean.** Closed = `isTrackerIssueClosed(issueId)` (`src/lib/cloister/issue-closed.ts`, 5-min cache, warmed by the reaper) inside `withGitHubCaller('close-out', …)` (non-essential; during a quota pause it answers "not closed", so nothing is counted or removed). Merged = `isBranchMerged('feature/<issue-lower>', projectPath).status === 'merged'`. Clean = `git status --porcelain` prints nothing (untracked `??` files count as dirty).
- **D7 — Cleanup shells `pan workspace destroy <ISSUE> --project <projectPath>`** via async `execFile` (pattern: `src/cli/commands/start.ts:665`), timeout 180 000 ms, concurrency 2, synchronous HTTP response (precedent: `bulkCloseOut`, concurrency 3, `src/lib/overdeck/issue-close-out.ts:233`). Never `--force`, never `--purge-memory`. UI copy says destroy also deletes the local branch.
- **D8 — Polyrepo projects are skipped by cleanup** (`config.workspace?.type === 'polyrepo'`) with reason `polyrepo workspace — run pan workspace destroy by hand`. They are still counted in the disk line. `isBranchMerged` runs git in the project root, which is wrong for a polyrepo wrapper.
- **D9 — Size cache.** `du -sb` runs via async `execFile`, concurrency 4, results cached in memory for 60 s; the cache is cleared after a cleanup. The frontend fetches on section mount and after cleanup — no polling.
- **D10 — Section placement.** No "Pipeline" settings section exists. Add a new section `close-out` ("Close-out", `Trash2` icon) in `SETTINGS_NAV_ITEMS` right after `cloister`, rendered right after `<CloisterSection>` in `SettingsPage.tsx`. It uses its own query keys (`['close-out-settings']`, `['close-out-disk']`), never `['cloister-config']`.
- **D11 — Do not touch the CLI.** The server must never import `src/cli`, so the new lib module defines its own private async `dirSizeBytes` (same `execFile('du', ['-sb', path])` body as `workspace-list.ts`, search `async function dirSizeBytes`). The ~10-line duplicate is accepted to keep the plan inside the 25-file finalize limit; de-duplicating it is a follow-up, not part of this issue.

## Requirements

- **FR-1** `GET /api/cloister/close-out` returns, for each of the four keys, `{ value, source }` where `source ∈ {'default','cloister.toml'}`; `auto` and `auto_delay_minutes` also carry `inert: true`.
- **FR-2** `PUT /api/cloister/close-out` with body `{ key, value }` accepts only `remove_workspace` and `delete_feature_branch` with boolean values, writes only that key under `[close_out]`, preserves every other key already in the file, calls `reloadDurableCloisterConfig()`, and returns the new view.
- **FR-3** The PUT rejects `auto`, `auto_delay_minutes`, unknown keys, and non-boolean values with HTTP 400, and an unparseable file with HTTP 409, writing nothing.
- **FR-4** New installs and files without the key default `remove_workspace` to `true`; `delete_feature_branch` defaults to `false`.
- **FR-5** DoD row 9 `observed` starts with `workspace kept (close_out.remove_workspace is off)` when the setting is off, and with `workspace removed` (or `no workspace on disk`) when on; it adds `feature branch kept (close_out.delete_feature_branch is off)` when that setting is off.
- **FR-6** `GET /api/cloister/close-out/disk` returns the count of closed issues with workspaces on disk, their total size in bytes, the count whose size is unknown, and per-issue rows.
- **FR-7** `POST /api/cloister/close-out/cleanup` runs `pan workspace destroy` for each closed, merged, clean, non-polyrepo issue workspace and returns `removed[]` and `skipped[]` (each skip with a reason).
- **FR-8** Settings renders a Close-out section with four controls, each showing its effective value and a source label; the two live toggles save immediately; the two inert controls are disabled with the D1 text.
- **FR-9** The Close-out section shows "N closed issues still have workspaces (X GB)" next to the workspace toggle and a "Clean up now" button that calls FR-7 and lists removed and skipped issues with reasons.
- **FR-10** Docs describe the four keys, the new default, the inert keys, the reaper overlap, and the dashboard section.
- **NFR-1** No `execSync`/sync fs in any server-reachable code added here; child processes use async `execFile`.
- **NFR-2** Any test that waits on time uses `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` — never real waits.
- **NFR-3** The UI follows `pan-style-guide`: no pill badges, no decorative color; the source label uses `SettingsRowStatus` with `variant="neutral"`.
- **NFR-4** Light- and dark-mode screenshots of the section are captured with an isolated Playwright browser and committed as docs images.
