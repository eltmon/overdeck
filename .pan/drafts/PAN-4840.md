## Glossary

- **FCM:** Firebase Cloud Messaging, Google's push service. The only way to wake a closed Android app.
- **Data-only message:** an FCM message with a `data` map and no `notification` key. Android does not display it. It calls the app's `FirebaseMessagingService.onMessageReceived`, also when the app is closed (but not after "Force stop"). The directory sends `{"data":{"s":"<sealed>"}}` (`services/connect/src/push/fcm.ts`, `fcmBody`, line 77-82), with `android.priority` `HIGH` or `NORMAL`.
- **Sealed payload / `s`:** base64 of libsodium `crypto_box_seal` of a `PhonePushPayload` JSON (`packages/contracts/src/connect.ts`, `export interface PhonePushPayload`, line 106) to the phone's push public key. The machine seals it in `src/lib/push/native-provider.ts` with `sealTo` (`src/lib/anywhere/sealed-box.ts`). Plaintext at most 2,256 bytes (`PUSH_PLAINTEXT_MAX_BYTES`).
- **Push key pair:** one X25519 pair per install, made by `OverdeckKeysPlugin.ensureKeys` (`apps/mobile/android/app/src/main/java/ai/overdeck/app/OverdeckKeysPlugin.java`, line 36-58) and stored hex-encoded in `SecureStore` under the names `pushPublicKey` and `pushSecretKey`. The secret half never reaches JavaScript. The public half reached each machine at pairing as `pushKeyHex` (`src/dashboard/server/routes/phones.ts`, line 90: `pushKey: body.pushKeyHex`).
- **`SecureStore`:** `SharedPreferences` whose values are AES-GCM encrypted with an AndroidKeyStore key (`SecureStore.java`). Readable from any component of the app process, including a `FirebaseMessagingService`.
- **`@capacitor/push-notifications`:** the Capacitor 8 plugin MYN uses (`^8.1.2`). On Android it asks for `POST_NOTIFICATIONS`, fetches the FCM token (`register()` → JS event `registration { value }`), and **declares its own** `com.capacitorjs.plugins.pushnotifications.MessagingService` for the `com.google.firebase.MESSAGING_EVENT` action. That service only forwards messages to JavaScript; it never posts a notification when the app is closed.
- **Channel:** an Android 8+ notification channel. This PRD adds two: `needs-you` (importance high) and `updates` (importance default).
- **Open link:** a new app URL, `ai.overdeck.app:/open#v=1&e=<environmentId>&p=<path>&t=<ts>`, that a notification tap delivers to the shell. Defined in FR-6.
- **Placeholder:** the notification shown when a push arrives for this phone but cannot be opened: title `Overdeck`, body `Something needs you` (the same text iOS shows, `pan-4823.md` D-5).
- **Robolectric:** a JVM test runner that simulates the Android framework, so notification posting can be asserted in `./gradlew testDebugUnitTest` without an emulator.
- **`lazysodium`:** the libsodium binding the app already uses (`com.goterl:lazysodium-android:5.1.0@aar`, `app/build.gradle`). `lazysodium-java` is its desktop twin with Linux/macOS natives, for JVM tests.

## Facts this plan is built on (verified 2026-11-03 against `bb0e166cd04`)

1. **The Android app code is Java.** `apps/mobile/android/app/src/main/java/ai/overdeck/app/` holds `MainActivity.java`, `OverdeckKeysPlugin.java`, `SecureStore.java`, `Hex.java`. There is no Kotlin Gradle plugin. The epic's `OverdeckMessagingService.kt` becomes `OverdeckMessagingService.java` (D-1).
2. **Firebase is wired but inert.** `apps/mobile/android/build.gradle` has `classpath 'com.google.gms:google-services:4.4.4'`. `app/build.gradle` ends with the Capacitor template block that applies `com.google.gms.google-services` only when `google-services.json` exists:
   ```groovy
   try {
       def servicesJSON = file('google-services.json')
       if (servicesJSON.text) {
           apply plugin: 'com.google.gms.google-services'
       }
   ```
   `apps/mobile/android/.gitignore` keeps `# google-services.json` commented out, so the file can be committed. No `google-services.json` exists anywhere in the repo.
3. **No push plugin yet.** `apps/mobile/package.json` has `@capacitor/app` and `@capacitor/browser` only; `apps/mobile/android/app/capacitor.build.gradle` and `apps/mobile/android/capacitor.settings.gradle` (generated by `cap sync`, committed) list only `capacitor-app` and `capacitor-browser`.
4. **The plugin crashes without Firebase.** `PushNotificationsPlugin.register()` calls `FirebaseMessaging.getInstance()` directly. Without `google-services.json` there is no default `FirebaseApp`, `getInstance()` throws `IllegalStateException`, and the Capacitor bridge rethrows it as a fatal error. JavaScript must not call `register()` unless Firebase is configured (D-5).
5. **The plugin's `onNewToken` is public static.** `PushNotificationsPlugin.onNewToken(String)` sends the token to JavaScript as the `registration` event when the bridge is alive. Our service calls it, so token rotation still reaches JS after we remove the plugin's service (D-2).
6. **The plugin's Firebase dependency is not visible to the app module.** The plugin's `android/build.gradle` declares `implementation "com.google.firebase:firebase-messaging:$firebaseMessagingVersion"` (default `25.0.1`, read from `rootProject.ext.firebaseMessagingVersion`). `implementation` does not leak to the app, so the app must declare `firebase-messaging` itself to compile a `FirebaseMessagingService`.
7. **The manifest has no notification permission.** `apps/mobile/android/app/src/main/AndroidManifest.xml` declares `INTERNET` and `CAMERA` only, and its root element has no `xmlns:tools`.
8. **The push key never rotates.** It is made once per install and deleted only by `reset()` (sign-out). Every machine received it at pairing. `PUT /api/phones/self/push-key` (W-MAC1 step 5) exists but Android has no reason to call it (NonGoal).
9. **`push-register` needs an online socket.** `DirectoryWebClient.send` returns `false` unless `state === 'online'` (`packages/anywhere-channel/src/directory-web.ts`, `send(frame: ClientToDirectoryFrame): boolean`, line 147-151). The directory keeps the registration across re-hellos (`services/connect/src/client-state.ts`, line 79: "A re-hello keeps the push registration"), and accepts tokens matching `/^[0-9A-Za-z:_.-]+$/`, at most 4,096 characters (`services/connect/src/protocol.ts`, line 24 and 40). FCM tokens match.
10. **The shell already routes app URLs.** `ShellApp.tsx` `handleUrl` (line 76-91) handles pair links and the sign-in callback; cold launches go through `App.getLaunchUrl()` and the `takeLaunchUrl` session-storage guard (line 44-52); warm opens through `App.addListener('appUrlOpen', …)`. `MainActivity` is `singleTask` with a `VIEW` intent filter for scheme `ai.overdeck.app`. Opening a machine is `setCurrentMachineId(id)` then `navigate('/m…')`, a full page reload (C-7 of PAN-4837).
11. **Notification URLs are `/m?…` paths.** `PhonePushPayload.url` is a "same-origin dashboard path, e.g. `/m?subject=my-conv`" (`connect.ts`, line 113-114). `MobileApp.tsx` reads `?subject=`, `?issue=`, `?conversation=` and `?tab=` (line 8 and 38-52).
12. **Urgency rule.** `webPushUrgency` (`src/lib/push/webpush-provider.ts`, line 40-42): `question`, `approval`, `failed` are `high`; everything else is `normal`. The directory maps `high` to FCM `android.priority: "HIGH"`.
13. **CI builds but does not unit-test Android.** `.github/workflows/ci.yml` job `mobile-android` (line 352-391) runs the app's Vitest tests, the web build, `cap:sync -- android` and `./gradlew assembleDebug --no-daemon`. It does not run `testDebugUnitTest`. The aggregate `test` job requires `mobile-android`.
14. **Test lint scope.** `scripts/lint-source-introspection.sh` scans only `tests/**/*.ts(x)` and `src/**/__tests__`; `scripts/lint-file-size.sh` scans only `src/`. `apps/mobile/src/__tests__/native-config.test.ts` already asserts manifest text, so extending it is allowed.
15. **The emulator has Play services.** The `galaxyA16*` AVDs on this host are `system-images/android-36/google_apis/x86_64`, which include Google Play services, so FCM works on them once Firebase is configured.

## Requirements

### Functional

- **FR-1 Receive.** `OverdeckMessagingService` is the only service bound to `com.google.firebase.MESSAGING_EVENT` in the merged manifest. For a data message with key `s` it opens the sealed payload and posts a notification, also when the app is closed.
- **FR-2 Decrypt.** The payload is opened with `crypto_box_seal_open` using the push key pair from `SecureStore`. A payload sealed by `sodium-native` on the machine opens on the phone (shared fixture).
- **FR-3 Channels.** Kinds `question`, `approval`, `failed` post on channel `needs-you` (name "Needs you", importance high). Kinds `finished`, `summary`, `test` post on `updates` (name "Updates", importance default).
- **FR-4 Content.** The notification shows the payload `title` and `body` (big-text style), uses the monochrome small icon `ic_stat_overdeck`, auto-cancels on tap, and uses notification tag `<machine>:<tag>` with id `1`, so a newer push for the same tag replaces the older one.
- **FR-5 Failure behaviour.** No `s` key: nothing is posted. No push key in storage (signed out): nothing is posted. Key storage throws, base64 is malformed, the box does not open, or the JSON is invalid: the placeholder is posted on `needs-you` when the FCM message priority was high, else on `updates`, tag `overdeck:placeholder`, and a tap opens the app with no route.
- **FR-6 Tap opens the right screen.** A tap delivers the open link `ai.overdeck.app:/open#v=1&e=<machine>&p=<url-encoded payload.url>&t=<url-encoded payload.ts>` to `MainActivity`. The shell opens the paired machine `e` at path `p`. An unpaired `e`, a path that is not `/m` with an optional query, or a link before sign-in opens the machine list instead.
- **FR-7 Permission.** On Android 13+ the app asks for `POST_NOTIFICATIONS` on the first launch after sign-in. Denying it leaves the app fully usable (epic H-4).
- **FR-8 Registration.** After permission is granted and Firebase is configured, the app sends `push-register { platform: 'android', token }` to the directory each time the directory socket becomes online, and again whenever the FCM token changes.
- **FR-9 Settings row.** Settings shows a "Notifications" row: `On`; `Off — turn them on in Android Settings → Apps → Overdeck → Notifications`; `Not set up in this build`; or a `Turn on` button when the permission was never asked.
- **FR-10 Sign-out.** Sign-out deletes the FCM token (`PushNotifications.unregister()`) before the existing `push-unregister` step. After sign-out the key pair is gone, so a late push is dropped (FR-5).
- **FR-11 Firebase config.** `apps/mobile/android/app/google-services.json` (package `ai.overdeck.app`, from PAN-4841) is committed, as MYN does; with it the debug build applies the google-services plugin.

### Non-functional

- **NFR-1 No plaintext leaves the phone.** Nothing in this change logs the payload, title, body, token or keys. Log lines carry only an outcome name.
- **NFR-2 No crash without Firebase.** A build without `google-services.json` starts, signs in, pairs and runs with notifications shown as "Not set up in this build".
- **NFR-3 minSdk 24.** New Java code calls only APIs available on API 24, or guards them with `Build.VERSION.SDK_INT` (channels need API 26; `java.util.Base64`, `java.time` and `URLEncoder.encode(String, Charset)` are not allowed in app code).
- **NFR-4 Testable without a device.** Decrypt, parse, channel choice, link building and posting are covered by `./gradlew testDebugUnitTest` (plain JUnit + Robolectric), and CI runs it.
- **NFR-5 Fake timers.** JS tests that involve delays or state transitions over time use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()` (repo rule `fake-timers-for-retry-tests`). Never real waits.
- **NFR-6 Background work only.** The service does its work in `onMessageReceived`, which FCM already runs off the main thread. No new threads, no WorkManager.

## Decisions

- **D-1 Java, not Kotlin.** All Android app code is Java (Fact 1). Adding the Kotlin toolchain for one class is scope creep and CI risk. The epic's `.kt` file name is corrected to `.java`.
- **D-2 One messaging service, ours.** Keep `@capacitor/push-notifications` for the permission and the token (so PAN-4838 shares the same JS API on iOS). Remove the plugin's `MessagingService` from the merged manifest with `tools:node="remove"`, and declare `ai.overdeck.app.OverdeckMessagingService` for `com.google.firebase.MESSAGING_EVENT`. Our `onNewToken` calls `PushNotificationsPlugin.onNewToken(token)`. Reason: two services bound to one action is resolved arbitrarily at runtime; only ours posts when the app is closed.
- **D-3 Firebase dependency.** Add `firebaseMessagingVersion = '25.0.1'` to `android/variables.gradle` (the plugin reads `rootProject.ext.firebaseMessagingVersion`) and `implementation "com.google.firebase:firebase-messaging:$firebaseMessagingVersion"` to `app/build.gradle`. No Firebase BoM, no analytics.
- **D-4 Placeholder on failure, silence when signed out.** FR-5. The placeholder matches iOS, and a high-priority FCM message that produces no visible notification is a pattern Android may deprioritize. Signed out means the keys are gone and the directory registration was removed, so nothing should show.
- **D-5 Firebase-configured check.** A new Android plugin `OverdeckPush` with one method `status() → { configured: boolean }` returns `!FirebaseApp.getApps(context).isEmpty()`. JavaScript calls `PushNotifications.register()` only when `configured` is true (Fact 4). Its `load()` also creates the two channels so they show in Android Settings after first launch.
- **D-6 Resend `push-register` on every online transition.** No local "last sent" record. The frame is idempotent (`UPDATE clients SET push_platform = ?, push_token = ? …`), and resending heals a registration the directory cleared after a dead token.
- **D-7 Open link in a URL fragment, with the timestamp.** It follows the pair link style (`ai.overdeck.app:/pair#…`). `t` makes every push's link unique, so the `takeLaunchUrl` guard (which stops a reload from re-handling the same launch URL) never swallows a second, different notification for the same screen. The placeholder's tap uses the launcher intent (no data), so it just opens the app.
- **D-8 Real crypto in plain JUnit, posting in Robolectric.** `SealedBox` depends only on lazysodium's `Box.Native` interface, so `SealedBoxTest` runs with `lazysodium-java` on the JVM. `PushHandlerTest` runs under Robolectric with a stubbed opener and asserts the posted notifications through `ShadowNotificationManager`. Implementation checkpoint CP-1 covers the classpath risk.
- **D-9 Settings row, no in-app switch.** The system notification setting is the switch. The app only shows state and, when Android still allows a prompt, a `Turn on` button (FR-9).
- **D-10 The shared JS module is platform-neutral.** `src/native/push.ts` takes the platform from `shellPlatform()`; for this issue `pushState()` returns `unavailable` on iOS with the comment `// iOS: PAN-4838`. PAN-4838 replaces that branch and adds `apsEnvironment` to the frame; the rest of the module is reused.
- **D-11 The fixture is owned here.** `tests/fixtures/phone-push/` holds a Node generator and one committed JSON fixture sealed by `sodium-native`. PAN-4838's Swift test can read the same file.

     /** `crypto_box_seal_open` through lazysodium (PAN-4840 FR-2). Null when the box is short, tampered or for another key. */
     final class SealedBox {
         static byte[] open(Box.Native sodium, byte[] sealed, byte[] publicKey, byte[] secretKey) {
             if (sealed.length < Box.SEALBYTES) return null;
             byte[] out = new byte[sealed.length - Box.SEALBYTES];

- The Live Activity (PAN-4839).
- Creating the Firebase project, the FCM service account, `wrangler secret put`, the upload keystore or store listings (PAN-4841).
- `PUT /api/phones/self/push-key` from Android: the push key never rotates (Fact 8).
- An in-app notifications on/off switch (D-9); the system setting is the switch.
- Suppressing the system notification while the app is in the foreground, or an in-app toast.
- Notification actions (answer buttons on the notification), grouping/summary notifications, per-machine channels, custom sounds.
- Fixing Android "Force stop" blocking FCM; it is documented only.
- Direct-boot (before first unlock) delivery; the service is not `directBootAware`.
- Any change to `services/connect`, the machine's native provider, or `packages/contracts`.
- Adding Kotlin to the Android project.

## Hazards

- **H-1 Concurrent sibling PAN-4838.** It also names `apps/mobile/src/native/push.ts`, adds `@capacitor/push-notifications`, and may use `tests/fixtures/phone-push/`. If either already exists on `main` when work starts, extend it rather than re-create: keep the exported names in WI-5 and add the Android branch. Expect a `package.json`/`bun.lock` rebase conflict; resolve by keeping both changes and re-running `bun install`.
- **H-2 Firebase-less builds crash on `register()`** (Fact 4). WI-5's `pushState()` must check `OverdeckPush.status()` first; a test asserts it.
- **H-3 minSdk 24 APIs** (NFR-3). `assembleDebug` does not run Android lint, so a `java.util.Base64` or `URLEncoder.encode(String, Charset)` call compiles and then crashes on old devices. Use the forms named in WI-2.
- **H-4 Generated Gradle files.** `capacitor.build.gradle` and `capacitor.settings.gradle` say "DO NOT EDIT"; regenerate them with `cap:sync` and commit the result. The settings file pins bun store paths such as `@capacitor+push-notifications@8.1.2`; CI regenerates it in "Sync Capacitor (Android)", so a path drift is self-healing.
- **H-5 Workflow push.** WI-8 edits `.github/workflows/ci.yml`; push it over SSH.
- **H-6 External prerequisite** (WI-9). Do not mark the issue done until AC-9 has real evidence.
