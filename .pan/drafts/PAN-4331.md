# PAN-4331 — Spike: `npx @overdeck/core` and Session Vault resume on native Windows

**Issue:** [PAN-4331](https://github.com/eltmon/overdeck/issues/4331) · **Epic:** PAN-2350 · **Design:** `.pan/drafts/anywhere-accounts.md` §6.8 (lines 252–261) · **Depends on:** PAN-2609 (closed, merged as `7150767e255`), PAN-4329 (merged as `8a753596a8a`) · **Related:** #531, PAN-3762 NFR-9

This is a spike. Its deliverable is evidence: a results table, one filed issue per blocking
failure, and docs that state only what was verified. It fixes nothing in the vault, the
dashboard or the terminal backends. The code it adds is test harness only: two fixture/probe
scripts, one summarizer and one manually re-runnable GitHub Actions workflow.

## Glossary

| Term | Meaning |
| --- | --- |
| **B-flow** | The standalone continue flow from §6.8: `vault join <git-url>` → `vault list` → `vault resume <id>` on a machine that did not create the conversation. |
| **Subject tarball** | `overdeck-core-<version>.tgz`, produced by `npm pack --ignore-scripts` after `bun install --frozen-lockfile && bun run build` on branch HEAD. | **Published latest** | `@overdeck/core@latest` on npm. At planning time this is `0.63.0` (`npm view @overdeck/core dist-tags` → `latest: '0.63.0'`). |
| **Fixture** | The Linux-side state the Windows side continues: a bare project origin, a vault backend, a saved Claude Code conversation and its uncommitted code. Built by `scripts/windows-smoke/make-fixture.sh`. |
| **Probe** | A script that runs the numbered steps below in one environment and writes one results JSON file (schema below). Never stops at the first failure. |
| **Environment (env)** | One column of the results table: `windows-pwsh`, `windows-gitbash`, `wsl2`. |
| **Blocking failure** | A step result that prevents the operator's case (continue a Linux conversation on Windows) on that path. Defined mechanically in FR-7. |
| **Hosted runner** | A GitHub-hosted Actions VM. `windows-2022` is Windows Server 2022 Datacenter, not Windows 11. |

## Verified facts (checked 2026-09-29 against `fe481f81fdc`)

1. **`pan vault` is not in the published package.** `git merge-base --is-ancestor 7150767e255 v0.63.0` fails (PAN-2609 landed after `0.63.0`), and so does PAN-4329 (`8a753596a8a`). So `npx @overdeck/core vault …` against published latest can only report an unknown command today. Every B-flow step must run against the subject tarball.
2. **Bare `npx @overdeck/core` runs `serve`.** `src/cli/index.ts` (search `// Default action: no args → serve`) pushes `serve` when `process.argv.length === 2`. `serve` (search `.command('serve')`) starts `dist/dashboard/server.js`, prints `Starting server on port <port> (Node <v>)...`, then calls `openBrowser(browserUrl)`; on failure it prints `Open your browser to: <url>`. It accepts `OVERDECK_INTERNAL_TOKEN` from the environment and uses it in the browser URL.
3. **Conversation launch route.** `POST /api/conversations` (`src/dashboard/server/routes/conversations.ts`, search `const postConversationRoute`) runs `validateOrigin(request)` first and returns 403 without a valid `Origin`. Body: `{ message, model?, effort?, issueId? }`. The internal token header is `x-overdeck-internal-token` (`src/dashboard/server/server.ts`, search `x-overdeck-internal-token`).
4. **Other GET APIs that exist:** `/api/health` (`server.ts`), `/api/conversations`, `/api/projects`, `/api/settings`, `/api/issues` (`src/dashboard/server/routes/*.ts`).
5. **Claude Code slug.** Overdeck encodes a cwd as `cwdPath.replace(/[^a-zA-Z0-9-]/g, '-')` (`src/lib/runtimes/storage/claude-code.ts`, `encodeClaudeProjectDir`). For `C:\w\proj` that gives `C--w-proj`. The spike must not treat this function as the oracle for Claude Code's own Windows behavior (that would test the code against itself); see checkpoint CP-2.
6. **Home resolution.** `claudeProjectsRoot(home = homedir())` in `claude-code.ts`; Codex home is `CODEX_HOME || join(homedir(), '.codex')` (`src/lib/vault/materialize.ts`, `codexHomeDir`). On Windows `os.homedir()` reads `USERPROFILE`; Git Bash additionally exports `HOME=/c/Users/<user>`.
7. **Resume launch.** `src/cli/commands/vault/resume.ts` `defaultSpawn` calls `spawn(command, args, { stdio: 'inherit', cwd })` with `command = 'claude'` and no `shell` option. npm installs Claude Code on Windows as `claude.cmd`; Node ≥ 20.12 refuses to spawn `.cmd`/`.bat` without `shell: true` (`EINVAL`), and a bare `claude` without the extension may give `ENOENT`. Expect a failure at step 3g. With `--no-launch` it prints `cd <shellQuote(cwd)> && claude --resume <id>`; `shellQuote` uses POSIX single quotes, which `cmd.exe` does not understand. After materializing it prints `Materialized <n> lines to <path>`.
8. **Resume on the owning machine** does not materialize again: it reuses the machine's own segment and launches (`resume.ts`, search `record.owner.environmentId === me.environmentId && mine`).
9. **Setup/join flags.** `pan vault setup <git-url> --passphrase-file <p>` and `pan vault join <git-url> --passphrase-file <p>` exist (`src/cli/commands/vault/setup.ts`, `join.ts`). A typed passphrase must be ≥16 code points and use ≥6 distinct characters. `pan vault list --json` exists (`list.ts`).
10. **WIP apply** fetches the target checkout's own `origin` (`src/lib/vault/wip-apply.ts`, search `['fetch', '--quiet', 'origin']`), unbundles, checks out the branch, applies changes unstaged. The target checkout must be clean.
11. **Transcript line shape** used by vault tests: `{ type, sessionId, cwd, uuid, message: { role, content } }` (`tests/unit/lib/vault/materialize.test.ts`, function `line`, lines 19–21).
12. **No usable local Windows VM.** `virsh list --all` shows `win11-snapcam` (shut off), but its disk `/home/eltmon/VMs/win11-snapcam.qcow2` does not exist (`~/VMs` is empty). It is operator-owned and has no guest agent or SSH.
13. **Hosted WSL2.** `Vampire/setup-wsl` (latest major `v7`) documents WSL2 as available on later `windows-2022` images, with `wsl-version: 2` as the default.
14. **Docs targets.** `docs/SESSION-VAULT.md` (320 lines) has no Windows section. `configuration/anywhere-sign-in.mdx` does **not** exist; it is owned by PAN-4293 (`anywhere-accounts.md` line 452). The user-facing vault page is `configuration/session-vault.mdx`.
15. **PAN-3762 NFR-9** is at `.pan/drafts/pan-3762.md` line 101: "Linux/macOS desktop and headless Linux are v1. Windows direct connections are supported if the server already runs; …".
16. **Repo is public**, so hosted Windows minutes are free. `release.yml` already uses `windows-latest` (precedent). Previous bot pushes of workflow files succeeded (`fa58a13446b`, 2026-09-18).

## Decisions (made here; auto-planning mode)

- **D-1 Vehicle: GitHub Actions `windows-2022` hosted runners, not a Windows 11 VM.** The only local VM has no disk (fact 12) and nobody is available to drive one. The results and docs name the real environment ("Windows Server 2022, GitHub `windows-2022` runner, Node 22.x, Git for Windows 2.x") and never claim Windows 11.
- **D-2 Subject: the branch-HEAD tarball** for every step except 1a/1b, which run published latest to answer the operator's literal question.
- **D-3 Two native shells.** The Windows probe runs twice: under `pwsh` (no `HOME`, so `USERPROFILE` path) and under Git Bash (`HOME=/c/Users/...`). Same script, `probe.ps1`, invoked from `pwsh` directly and from `bash` via `pwsh -File` with `HOME` exported by Git Bash. Env names `windows-pwsh`, `windows-gitbash`.
- **D-4 WSL2 on the hosted runner** via `Vampire/setup-wsl@v7`, `distribution: Ubuntu-24.04`, `wsl-version: 2`. Checkpoint CP-3 covers the case where it fails.
- **D-5 Join by passphrase.** The fixture sets a fixed test passphrase (`--passphrase-file`); the probes join with `--passphrase-file`. The vault key is throwaway and exists only in the workflow artifact.
- **D-6 Vault backend is a local bare git repo** passed by path on both sides (`<dir>/vault.git` on Linux, `D:\…\vault.git` on Windows), so `vault join <git-url>` is exercised with a real git backend and a Windows path.
- **D-7 Docs substitution.** The issue names `configuration/anywhere-sign-in.mdx`, which does not exist (fact 14). The user-facing Windows section goes in `configuration/session-vault.mdx`; creating the sign-in page stays with PAN-4293.
- **D-8 The workflow stays** as `.github/workflows/windows-smoke.yml`, triggered by `workflow_dispatch` and by `push` with a `paths:` filter on the workflow and `scripts/windows-smoke/**`. It is not added to `ci.yml` and not required for merge. Filed blocker issues can re-run it to verify their fixes.
- **D-9 No fixes.** Every failure is reported and filed; nothing under `src/` changes in this issue.
- **D-10 The results table is durable in the repo** as the `## Results` section appended to this PRD, and posted on the issue.

## Results JSON schema (the contract between probes and summarizer)

One file per env, `results/<env>.json`, UTF-8, no BOM:

```json
{
  "env": "windows-pwsh",
  "runner": "windows-2022 (Microsoft Windows Server 2022 Datacenter 10.0.20348)",
  "node": "v22.x.y",
  "git": "git version 2.x.y.windows.1",
  "subject": "overdeck-core-0.63.0.tgz @ <commit sha>",
  "steps": [
    {
      "id": "3c",
      "status": "pass",
      "command": "npx --yes D:\\a\\_temp\\overdeck-core-0.63.0.tgz vault resume ...",
      "exitCode": 0,
      "evidence": "<last 4000 chars of combined stdout+stderr, verbatim>",
      "note": ""
    }
  ]
}
```

`status` ∈ `pass | fail | partial | not-run`. `exitCode` is `null` when no process ran. Every id in the step catalogue appears exactly once per file.

## Work items

### W1 — `scripts/windows-smoke/make-fixture.sh` (FR-1, NFR-2, NFR-3)

Bash, `set -euo pipefail`, one argument: output directory `OUT`. Requires `node` 22 and the subject tarball path in `$SUBJECT_TGZ`. Uses an isolated `HOME="$OUT/home"` and `OVERDECK_HOME="$OUT/home/.overdeck"` so it never touches the runner's real home.

1. `git init --bare "$OUT/origin.git"`; clone to `"$OUT/src/proj"`; set `user.name`/`user.email` locally; commit `README.md` and `lf.txt` (`printf 'a\nb\n'`), push to `origin main`.
2. Uncommitted and unpushed work, in this order: commit `unpushed.txt` with subject `fixture: unpushed commit` (do not push); modify `lf.txt` to `printf 'a\nb\nc\n'`; add `crlf.txt` with `printf 'x\r\ny\r\n'` and `git add` it (staged-new is fine; everything arrives unstaged); add `run.sh` (`#!/bin/sh\necho ok\n`, `chmod 755`, `git add`); `ln -s lf.txt link-to-lf` and `git add`; create untracked `notes-untracked.txt`.
3. Write a Claude Code transcript at `"$HOME/.claude/projects/$(slug)/<SESSION_ID>.jsonl"` where `SESSION_ID` is a fixed UUID (`11111111-2222-4333-8444-555555555555`) and `slug` is the cwd with every character outside `[A-Za-z0-9-]` replaced by `-`. Four lines alternating user/assistant with the shape of fact 11 and `cwd` set to the checkout path.
4. Write the passphrase file `"$OUT/passphrase.txt"` containing `windows smoke fixture passphrase 42` (no trailing newline issues: `printf '%s'`).
5. `git init --bare "$OUT/vault.git"`; `npx --yes "$SUBJECT_TGZ" vault setup "$OUT/vault.git" --passphrase-file "$OUT/passphrase.txt"`; then `npx --yes "$SUBJECT_TGZ" vault save "$SESSION_ID"`. The save output must contain `appended`; fail the script otherwise. Then run `vault sync` so the Linux list cache includes the record (`list` reads the cache that `sync`, `setup` and `join` refresh — `src/lib/vault/sync.ts` `syncOnce`; `save` does not refresh it).
6. Write `"$OUT/fixture.json"`: `{ "sessionId", "originBranch": "main", "expected": { "lf.txt": "a\nb\nc\n", "unpushedSubject": "fixture: unpushed commit", "changedPaths": [...] } }`. `changedPaths` is the output of `git status --porcelain` in the Linux checkout, parsed into paths.
7. Delete `"$OUT/home"` from the artifact list (the workflow uploads only `origin.git`, `vault.git`, `passphrase.txt`, `fixture.json`).

Verify locally: `bash scripts/windows-smoke/make-fixture.sh "$(mktemp -d)"` with a locally packed tarball exits 0 and writes `fixture.json`.

### W2 — `scripts/windows-smoke/probe.ps1` (FR-2, NFR-1)

PowerShell 7, parameters `-Env <name> -Subject <tgz> -Fixture <dir> -Out <json>`. A helper `Invoke-Step -Id -Command { … }` runs a script block with `try/catch`, captures combined output with `2>&1 | Out-String`, trims to the last 4000 characters, records `$LASTEXITCODE`, and appends to the steps list. The final write uses `[IO.File]::WriteAllText($Out, $json, [Text.UTF8Encoding]::new($false))`.

- Clone target: `git clone "$Fixture\origin.git" "$env:RUNNER_TEMP\w\proj"` before step 3a. Record `git config --get core.autocrlf|core.symlinks|core.filemode` from the clone.
- 1c starts `serve` with `Start-Process` (redirect stdout/stderr to files, `OVERDECK_INTERNAL_TOKEN` set to a fixed value), polls with `Invoke-WebRequest -SkipHttpErrorCheck` every 3 s for 90 s. 1d reads the redirected stdout file. After 2b, stop the process tree (`Stop-Process -Id <pid>`, then `taskkill /T /F /PID <pid>`).
- 3c parses `Materialized \d+ lines? to (.+)$` and `claude --resume (\S+)` from the output for 3d/3e.
- 4b–4f compare against `fixture.json`.
- 3e/3g use `claude` from `npm i -g @anthropic-ai/claude-code` installed by the workflow before the probe.

### W3 — `scripts/windows-smoke/probe-wsl.sh` (FR-3, NFR-1)

Bash run inside the WSL distro (`wsl.exe -d Ubuntu-24.04 -- bash /mnt/d/.../probe-wsl.sh …` via the setup-wsl shell). Installs Node 22 (the official tarball into `~/node`) and `npm i -g @anthropic-ai/claude-code` inside the distro (needed by 3e/3g), runs the same step ids 3a–4f against a copy of the fixture copied into the Linux filesystem (`cp -r /mnt/<drive>/… ~/fx`, not run from `/mnt/c`), writes `results/wsl2.json` to a `/mnt/<drive>` path the workflow uploads. Step 5a is recorded by the workflow step before it (W5) and passed in as `--wsl-status <file>`; the script embeds that output as the 5a evidence. Steps 1a–2b are emitted as `not-run` with the note from the step catalogue. Use a `step` bash function with `set +e` inside so failures never abort (NFR-1); build the JSON with `node -e` to get correct escaping.

### W4 — `scripts/windows-smoke/summarize.mjs` (FR-4)

Node ESM, no dependencies. `node scripts/windows-smoke/summarize.mjs <results-dir> > table.md`. Reads every `*.json`, validates each against the schema (missing step id → the cell shows `missing`), and prints:

1. A header naming run URL (`$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID` when set), subject, and per-env runner/node/git versions.
2. The table: first column `Step` (id + short title from a constant map), one column per env in the order `windows-pwsh, windows-gitbash, wsl2`; cell = `✅ pass`, `❌ fail: <first line of evidence, ≤120 chars, pipes escaped>`, `⚠️ partial: <note>`, `— not-run`.
3. `## Details`: for every non-pass cell, a `<details>` block with the command, exit code and the verbatim evidence in a fenced block.

Add a unit test `tests/unit/scripts/windows-smoke-summarize.test.ts` that feeds two small in-memory results objects through the exported `renderTable(results)` function and asserts the cell text for a pass, a fail with a `|` in its evidence, and a missing step.
