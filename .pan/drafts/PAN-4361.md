## 1. Glossary

| Term | Meaning in this document |
|---|---|
| **Live eval** | An Evalite `*.eval.ts` file under `evals/` that calls a real model. Run with `npm run eval` (`package.json` line 85: `"eval": "cd evals && evalite ."`). Not part of CI. |
| **Harness** | `evals/lib/prompt-harness.ts`. It exports `loadPromptFile`, `runPromptScenario` and `extractJsonArray`. |
| **Eval model** | The model id in the env var `OVERDECK_EVAL_MODEL`. It is mandatory. There is no fallback model. |
| **Catalog** | `MODEL_CAPABILITIES` in `src/lib/model-capabilities.ts` line 68. It spreads `AUDITED_MODEL_ADDITIONS` from `src/lib/model-capability-additions.ts` first. One row per model id (`ModelCapability`, `src/lib/model-capability-types.ts`). |
| **Catalogued id** | An id that has a catalog row, or a dated snapshot (`<id>-YYYYMMDD`) whose undated base has a row. Example: `claude-haiku-4-5-20251001` → base `claude-haiku-4-5`. |
| **Deprecated id** | An id that is a key in `MODEL_DEPRECATIONS` (`src/lib/model-deprecations.ts`). `resolveModelId(id)` returns its replacement. |
| **Sampling params** | `temperature`, `top_p`, `top_k`. Catalog field `supportsSamplingParams`; helper `modelSupportsSamplingParams(model)` at `src/lib/model-capabilities.ts` line 1419 returns `false` only when the row says `false`. |
| **Effort** | The reasoning-effort level: `low`, `medium`, `high`, `xhigh`, `max` (`EFFORT_LEVELS`, `packages/contracts/src/effort.ts` line 9). `DEFAULT_EFFORT` is `"high"` (line 12). Anthropic wire field: `output_config.effort`. OpenAI wire field: `reasoning.effort`. |
| **Effort-capable model** | A catalog row whose `effortLevels` array is defined and non-empty. |
| **Adaptive thinking** | Anthropic request field `thinking: { type: 'adaptive' }`. The model decides how much to think. |
| **Responses API** | OpenAI `POST /v1/responses`. Body fields used: `model`, `instructions`, `input`, `reasoning.effort`, `max_output_tokens`. |
| **CLIProxy** | The local sidecar at `CLIPROXY_BASE_URL` (`http://127.0.0.1:8317`) with bearer token `CLIPROXY_AUTH_TOKEN` (`'overdeck-local-cliproxy-key'`). Both are exported from `src/lib/cliproxy.ts` lines 45–46. It bills a ChatGPT subscription, not the API. |
| **Run info** | The new `PromptScenarioRun` object each harness call returns: model, provider, effort, thinking, temperature, max tokens, OpenAI route, token usage, cost, cost basis, stop reason, duration. |
| **Cost basis** | `'api'` = the cost is what the provider bills per token. `'api-equivalent'` = the call went through CLIProxy on a subscription, so the number is what the same tokens would cost on the API. |

## 2. Problem (verified against the code)

`evals/lib/prompt-harness.ts` lines 24–45 today:

```ts
export async function runPromptScenario(opts: RunPromptScenarioOptions): Promise<string> {
  const model = process.env['OVERDECK_EVAL_MODEL'];
  if (!model) {
    throw new Error(
      'OVERDECK_EVAL_MODEL is not set — live prompt evals require an explicit eval model (no hardcoded fallback). Example: OVERDECK_EVAL_MODEL=claude-haiku-4-5-20251001 npm run eval',
    );
  }

  const client = new Anthropic();
  const response = await client.messages.create({
    model,
    max_tokens: opts.maxTokens ?? 4096,
    temperature: 0,
    system: opts.system,
    messages: [{ role: 'user', content: opts.user }],
  });
  ...
```

Defects:

1. **`temperature: 0` is always sent.** The Claude API returns 400 for non-default sampling params on Sonnet 5.5, Opus 5, Opus 5.5 and Fable. Their catalog rows set `supportsSamplingParams: false` (`src/lib/model-capabilities.ts` lines 94, 119, 143, 167, 191, 240; `src/lib/model-capability-additions.ts` lines 31, 57). With adaptive thinking on, the API also rejects any temperature other than the default on every model.
2. **Anthropic only.** `new Anthropic()` is the only client. `gpt-6-sol`, `gpt-6-luna` and `gpt-6-astra` cannot be evaluated.
3. **`max_tokens: 4096`.** That truncates thinking-model output. Sonnet 5.5, Opus 5.5 and GPT-6 rows declare `maxOutputTokens` of 128000.
4. **No effort.** Opus 5.5's API default effort is `medium`, one level below Overdeck's `high`. Without an explicit effort, runs are not at the level Overdeck launches.
5. **No usage or cost.** Runs cannot be compared.
6. **Non-streaming.** The installed SDK (`@anthropic-ai/sdk` 0.96.0, `node_modules/@anthropic-ai/sdk/client.js` `calculateNonstreamingTimeout`) throws `Streaming is required for operations that may take longer than 10 minutes` when a non-streaming request has `max_tokens` above about 21,333. Fixing defect 3 without streaming breaks every call.

Consequence: `evals/flywheel-launch.eval.ts` and `evals/review-synthesis.eval.ts` cannot confirm any model placement from the parent PRD.

## 4. Requirements

### Functional

- **FR-1** `runPromptScenario` rejects before constructing any client or calling `fetch` when `OVERDECK_EVAL_MODEL` is unset or blank. The message keeps the existing text `OVERDECK_EVAL_MODEL is not set`.
- **FR-2** `runPromptScenario` rejects before any network call when the eval model is not a catalogued id. The error names the id.
- **FR-3** `runPromptScenario` rejects before any network call when the eval model is a deprecated id. The error names the id and its replacement.
- **FR-4** The provider comes from `getModelProvider` (`src/lib/model-fallback.ts` line 259), and only after FR-2 passes. Providers other than `anthropic` and `openai` reject before any network call, naming the id and the provider.
- **FR-5** Effort comes from `OVERDECK_EVAL_EFFORT`, or from `DEFAULT_EFFORT` (imported from `@overdeck/contracts`) when the variable is unset or blank. An invalid value rejects, listing `EFFORT_LEVELS`.
- **FR-6** For an effort-capable model, the effort must be in the row's `effortLevels`, or the call rejects before any network call, naming the model, the effort and the allowed levels. For a model that is not effort-capable, the default effort is dropped (not sent, run info records `effort: null`). An explicitly set `OVERDECK_EVAL_EFFORT` with such a model rejects.
- **FR-7** Anthropic: an effort-capable model gets `thinking: { type: 'adaptive' }` and `output_config: { effort }`. A model that is not effort-capable gets neither.
- **FR-8** Anthropic: `temperature: 0` is sent only when thinking is not sent **and** `modelSupportsSamplingParams(catalogId)` is `true`. Otherwise no `temperature`, `top_p` or `top_k` key is present in the request body.
- **FR-9** `max_tokens` (Anthropic) and `max_output_tokens` (OpenAI) equal the row's `maxOutputTokens`, or `EVAL_DEFAULT_MAX_OUTPUT_TOKENS` (16000) when the row has none, capped by `opts.maxTokens` when the caller passes it.
- **FR-10** The Anthropic call uses `client.messages.stream(params).finalMessage()`.
- **FR-11** OpenAI: the call is `POST <base>/v1/responses` with `instructions` = system prompt, `input` = one user message, `reasoning: { effort }` when effort is not null, `max_output_tokens`, and no `temperature`. Route by `OVERDECK_EVAL_OPENAI_VIA`: unset, blank or `api` → `https://api.openai.com` with `Bearer $OPENAI_API_KEY`; `cliproxy` → `CLIPROXY_BASE_URL` with `Bearer CLIPROXY_AUTH_TOKEN`. Any other value rejects. Route `api` with `OPENAI_API_KEY` unset rejects before any network call and names both `OPENAI_API_KEY` and `OVERDECK_EVAL_OPENAI_VIA=cliproxy`.
- **FR-12** An OpenAI HTTP error or a body with a non-null `error` rejects with the HTTP status, the model id and the provider's error message.
- **FR-13** `runPromptScenario` returns `{ text, run }`. `run` carries model, provider, effort, thinking, temperature, maxTokens, openaiVia, usage (`inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `reasoningTokens`), `costUsd`, `costBasis`, `stopReason` and `durationMs`.
- **FR-14** Cost uses `getPricing(provider, model)` and `calculateCost(usage, pricing)` from `src/lib/cost.ts`. No pricing row → `costUsd: null`. OpenAI `input_tokens` includes cached tokens, so uncached input = `input_tokens − cached_tokens`.
- **FR-15** Both live evals put `run` into their Evalite task output, so every stored result shows model, provider, effort, tokens and cost.

### Non-functional

- **NFR-1** No hardcoded model fallback anywhere (repo rule `no-hardcoded-model-fallbacks`). `EVAL_DEFAULT_MAX_OUTPUT_TOKENS` is a token count, not a model, and is a named constant.
- **NFR-2** No new npm dependency.
- **NFR-3** Unit tests make no real network call and need no credentials: they mock `@anthropic-ai/sdk` with `vi.mock` and stub `fetch` with `vi.stubGlobal`. They use `vi.stubEnv` and `vi.unstubAllEnvs()` for env vars. No `it.skip`, `skipIf` or `.only` (the test-skip gate rejects them). No real timers; nothing in this change waits on a delay.
- **NFR-4** `npm run typecheck` and `npm run lint` pass after every work item. Tests run as `npx vitest run tests/unit/evals/lib/`, never the full `npm test` on the host.
- **NFR-5** Pure resolution and usage logic live in `evals/lib/*.ts` modules that tests import directly. This follows the parent PRD's "keep scorer logic in `evals/lib/*.ts`" rule.

## 5. Decisions (made here, not left to the implementer)

- **D1 — Catalog membership gates "known".** `getModelProvider` returns `'anthropic'` for any unrecognized id (line 279), so it cannot detect unknown ids. The harness first requires a catalog row (dated-snapshot suffix `-\d{8}$` stripped as a second try), then calls `getModelProvider`.
- **D2 — Deprecated ids reject.** Silently evaluating the replacement would measure a different model than the operator named.
- **D3 — Thinking and effort are gated on `effortLevels`.** Every effort-capable Anthropic row (Fable 5/5.1, Opus 5.5/5/4.8/4.7/4.6, Sonnet 5.5/5/4.6) accepts adaptive thinking and `output_config.effort`. Haiku 4.5 and Sonnet 4.5 have no `effortLevels`, and the API errors on `effort` for them. Sending adaptive thinking explicitly also makes Opus 4.7/4.8 think, as they do in Claude Code. Without it they run with no thinking, which would make the Opus 4.8 vs 5.5 comparison unfair.
- **D4 — The temperature rule is tighter than the issue text.** The issue says to omit temperature when `supportsSamplingParams === false`. The harness also omits it whenever thinking is sent, because the API rejects non-default temperature with thinking on (Sonnet 4.6 and Opus 4.6 allow sampling but would 400 with `temperature: 0` plus adaptive thinking).
- **D5 — Stream the Anthropic call** (see defect 6).
- **D6 — Use `fetch` for OpenAI** because `openai` is not installed. The issue permits this.
- **D7 — `OVERDECK_EVAL_OPENAI_VIA` defaults to `api`.** A missing `OPENAI_API_KEY` rejects with a message that points at `cliproxy`. The default follows the issue text ("with `OPENAI_API_KEY`, or with the local CLIProxy endpoint when `OVERDECK_EVAL_OPENAI_VIA=cliproxy`").
- **D8 — `EVAL_DEFAULT_MAX_OUTPUT_TOKENS = 16_000`** applies when a row has no `maxOutputTokens` (Haiku 4.5). It is the non-streaming default recommended in the Claude API guidance and sits well under Haiku 4.5's real cap. The call streams anyway.
- **D9 — Explicit effort on a model without effort levels rejects.** A silently ignored env var would make a run look like it tested something it didn't.
- **D10 — Effort validation is catalog-driven for OpenAI too.** The OpenAI wire id is `apiLaunchModelId(model)` (re-exported from `src/lib/model-capabilities.ts` line 56), so catalog aliases such as `gpt-5.6-sol[372k]` map to their API id.
- **D11 — `costBasis` is `'api-equivalent'` for CLIProxy calls and `'api'` otherwise.** Show hypothetical API cost even when a subscription pays.
- **D12 — Module split.** `eval-model.ts` (resolution), `eval-usage.ts` (usage + cost), `openai-responses.ts` (OpenAI call) and `prompt-harness.ts` (dispatch + Anthropic call). Each pure piece is unit-testable without mocks.
- **D13 — The return-type change and both eval consumers land in one work item.** Changing `runPromptScenario` to return `{ text, run }` breaks `typecheck:evals` until both eval files use `.text`. Folding keeps every commit green.
- **D14 — `evals/vitest.config.ts` gets the `@overdeck/contracts` alias** that the root config already has. The runtime import of `DEFAULT_EFFORT` then resolves to source, not a possibly stale `dist/`.
- **D15 — The eval harness only reads `process.env` inside `runPromptScenario`.** The pure resolver takes `env` as a parameter, so tests pass a plain object.

**Steps inside `resolveEvalModelConfig` (in this order; each throw happens before any I/O):**

1. `model = env['OVERDECK_EVAL_MODEL']?.trim()`. Empty → throw the existing message verbatim: `OVERDECK_EVAL_MODEL is not set — live prompt evals require an explicit eval model (no hardcoded fallback). Example: OVERDECK_EVAL_MODEL=claude-haiku-4-5-20251001 npm run eval`.
2. `resolved = resolveModelId(model)`. `resolved !== model` → throw `Eval model "${model}" is deprecated; set OVERDECK_EVAL_MODEL=${resolved} to evaluate its replacement.`
3. `catalogId = hasModelCapability(model) ? model : (/-\d{8}$/.test(model) && hasModelCapability(model.replace(/-\d{8}$/, '')) ? model.replace(/-\d{8}$/, '') : null)`. `null` → throw `Unknown eval model "${model}": no MODEL_CAPABILITIES row. Use a catalogued model id (src/lib/model-capabilities.ts, src/lib/model-capability-additions.ts).`
4. `provider = getModelProvider(model)`. Not `'anthropic'` or `'openai'` → throw `Eval model "${model}" uses provider "${provider}", which the eval harness does not support (supported: anthropic, openai).`
5. `rawEffort = env['OVERDECK_EVAL_EFFORT']?.trim()`; `explicit = Boolean(rawEffort)`; `requested = rawEffort || DEFAULT_EFFORT`. `!isEffortLevel(requested)` → throw `OVERDECK_EVAL_EFFORT="${requested}" is not an effort level (allowed: ${EFFORT_LEVELS.join(', ')}).`
6. `levels = MODEL_CAPABILITIES[catalogId as ModelId].effortLevels`.
   - `levels && levels.length > 0`: `!levels.includes(requested)` → throw `Eval model "${model}" does not accept effort "${requested}" (allowed: ${levels.join(', ')}).` Otherwise `effort = requested`.
   - otherwise: `explicit` → throw `Eval model "${model}" accepts no effort setting; unset OVERDECK_EVAL_EFFORT.` Otherwise `effort = null`.
7. `thinking = provider === 'anthropic' && effort !== null ? 'adaptive' : null`.
8. `temperature = provider === 'anthropic' && thinking === null && modelSupportsSamplingParams(catalogId) ? 0 : null`.
9. `catalogCap = MODEL_CAPABILITIES[catalogId as ModelId].maxOutputTokens ?? EVAL_DEFAULT_MAX_OUTPUT_TOKENS`. If `opts.maxTokens !== undefined`: not a positive integer → throw `maxTokens must be a positive integer (got ${opts.maxTokens}).`; else `maxTokens = Math.min(opts.maxTokens, catalogCap)`. Otherwise `maxTokens = catalogCap`.
10. `openaiVia`: for `anthropic` → `null`. For `openai`: `via = env['OVERDECK_EVAL_OPENAI_VIA']?.trim() || 'api'`; not `api`/`cliproxy` → throw `OVERDECK_EVAL_OPENAI_VIA="${via}" is not supported (use api or cliproxy).`; `via === 'api' && !env['OPENAI_API_KEY']?.trim()` → throw `OPENAI_API_KEY is not set; set it, or set OVERDECK_EVAL_OPENAI_VIA=cliproxy to use the local CLIProxy.`
11. `apiModel = provider === 'openai' ? apiLaunchModelId(model) : model`.

### WI-2 — Usage normalization and cost module (`eval-usage-cost`)

**What/why:** One place that converts each provider's usage object into Overdeck's `TokenUsage` shape and prices it (FR-13, FR-14).

**Files:** new `evals/lib/eval-usage.ts`, new `tests/unit/evals/lib/eval-usage.test.ts`.

```ts
import { calculateCost, getPricing } from '../../src/lib/cost.js';

// Declared inline (not imported from eval-model.ts) so WI-1 and WI-2 can land in parallel.

export interface EvalUsage {
  inputTokens: number;       // uncached input
  outputTokens: number;      // includes reasoning/thinking tokens
  cacheReadTokens: number;
  cacheWriteTokens: number;
  reasoningTokens: number | null; // OpenAI reports it; Anthropic does not → null
}

export interface AnthropicUsageLike {
  input_tokens: number;
  output_tokens: number;
  cache_read_input_tokens?: number | null;
  cache_creation_input_tokens?: number | null;
}

export interface OpenAIUsageLike {
  input_tokens: number;
  output_tokens: number;
  input_tokens_details?: { cached_tokens?: number | null } | null;
  output_tokens_details?: { reasoning_tokens?: number | null } | null;
}

export function usageFromAnthropic(u: AnthropicUsageLike): EvalUsage;
export function usageFromOpenAI(u: OpenAIUsageLike): EvalUsage;   // inputTokens = input_tokens - cached
export function evalCostUsd(provider: 'anthropic' | 'openai', model: string, usage: EvalUsage): number | null;
```

`evalCostUsd` calls `getPricing(provider, model)` (the `AIProvider` union includes both values) and returns `null` when no row matches. Otherwise it returns `calculateCost({ inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens }, pricing)`.

**Tests:**
- `usageFromAnthropic maps cache read and creation tokens, defaulting null to 0`.
- `usageFromOpenAI subtracts cached tokens from input and records reasoning tokens` → `{ input_tokens: 314, output_tokens: 5, input_tokens_details: { cached_tokens: 100 }, output_tokens_details: { reasoning_tokens: 0 } }` → `inputTokens: 214, cacheReadTokens: 100, reasoningTokens: 0`.
- `evalCostUsd prices claude-sonnet-5-5` → 1,000,000 input + 1,000,000 output → `12` (2 + 10 USD).
- `evalCostUsd prices gpt-6-luna` → 1,000,000 input + 1,000,000 output → `0.6`.
- `evalCostUsd prices a dated snapshot through prefix match` → `claude-haiku-4-5-20251001` returns a number.
- `evalCostUsd returns null when no pricing row exists`.

```ts
import Anthropic from '@anthropic-ai/sdk';
import type { EffortLevel } from '@overdeck/contracts';
import { resolveEvalModelConfig, type EvalModelConfig, type EvalProvider, type OpenAIVia } from './eval-model.js';
import { evalCostUsd, usageFromAnthropic, type EvalUsage } from './eval-usage.js';

export interface PromptScenarioRun {
  model: string;
  provider: EvalProvider;
  effort: EffortLevel | null;
  thinking: 'adaptive' | null;
  temperature: 0 | null;
  maxTokens: number;
  openaiVia: OpenAIVia | null;
  usage: EvalUsage;
  costUsd: number | null;
  costBasis: 'api' | 'api-equivalent';
  stopReason: string | null;
  durationMs: number;
}

export interface PromptScenarioResult {
  text: string;
  run: PromptScenarioRun;
}

interface ProviderCallResult { text: string; usage: EvalUsage; stopReason: string | null }

async function callAnthropic(config: EvalModelConfig, opts: RunPromptScenarioOptions): Promise<ProviderCallResult> {
  const client = new Anthropic();
  const message = await client.messages
    .stream({
      model: config.apiModel,
      max_tokens: config.maxTokens,
      system: opts.system,
      messages: [{ role: 'user', content: opts.user }],
      ...(config.temperature !== null ? { temperature: config.temperature } : {}),
      ...(config.thinking !== null ? { thinking: { type: config.thinking } } : {}),
      ...(config.effort !== null ? { output_config: { effort: config.effort } } : {}),
    })
    .finalMessage();
  return {
    text: message.content.filter((block) => block.type === 'text').map((block) => block.text).join('\n'),
    usage: usageFromAnthropic(message.usage),
    stopReason: message.stop_reason ?? null,
  };
}

export async function runPromptScenario(opts: RunPromptScenarioOptions): Promise<PromptScenarioResult> {
  const config = resolveEvalModelConfig(process.env, { maxTokens: opts.maxTokens });
  const startedAt = Date.now();
  const result = await callAnthropic(config, opts); // WI-4 adds the openai branch here
  return {
    text: result.text,
    run: {
      model: config.model,
      provider: config.provider,
      effort: config.effort,
      thinking: config.thinking,
      temperature: config.temperature,
      maxTokens: config.maxTokens,
      openaiVia: config.openaiVia,
      usage: result.usage,
      costUsd: evalCostUsd(config.provider, config.model, result.usage),
      costBasis: config.openaiVia === 'cliproxy' ? 'api-equivalent' : 'api',
      stopReason: result.stopReason,
      durationMs: Date.now() - startedAt,
    },
  };
}
```

export const OPENAI_API_BASE_URL = 'https://api.openai.com';

export interface OpenAIResponsesCall { text: string; usage: EvalUsage; stopReason: string | null }

export async function callOpenAIResponses(
  config: EvalModelConfig,
  prompt: { system: string; user: string },

**Behavior:**
1. `base = config.openaiVia === 'cliproxy' ? CLIPROXY_BASE_URL : OPENAI_API_BASE_URL`. `token = config.openaiVia === 'cliproxy' ? CLIPROXY_AUTH_TOKEN : env['OPENAI_API_KEY']`. WI-1 already guaranteed the key exists for `api`.
2. `fetchImpl(\`${base}/v1/responses\`, { method: 'POST', headers: { Authorization: \`Bearer ${token}\`, 'Content-Type': 'application/json' }, body: JSON.stringify(body) })` where
   `body = { model: config.apiModel, instructions: prompt.system, input: [{ role: 'user', content: prompt.user }], max_output_tokens: config.maxTokens, ...(config.effort !== null ? { reasoning: { effort: config.effort } } : {}) }`. No `temperature`.
3. Parse JSON. If `!response.ok` or `json.error` is non-null → throw `OpenAI Responses call for "${config.model}" via ${config.openaiVia} failed (HTTP ${status}): ${json.error?.message ?? statusText}`.
4. `text` = every `output[]` item with `type === 'message'`, every `content[]` part with `type === 'output_text'`, joined with `'\n'`.
5. `stopReason` = `json.incomplete_details?.reason ?? json.status ?? null`.
6. `usage = usageFromOpenAI(json.usage as OpenAIUsageLike)`. A missing `usage` → throw `OpenAI Responses call for "${config.model}" returned no usage`.
