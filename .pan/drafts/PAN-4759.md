## 1. Glossary

- **Skill pack** — a third-party git repository of skills that Overdeck registers with `pan skills pack add`, pins to one trusted commit, caches under `~/.overdeck/packs/`, and mounts per launch through the harness plugin system. This is the only term the new docs use after one sentence that says operators also call these **skill bundles**.
- **Skill bundle** — the operator's informal name for a skill pack. Also the name of a separate, unbuilt proposal (`pan bundle`, PAN-1357) in `reference/template-conversations.mdx`. The docs connect the two terms once, in a terminology note.
- **Known pack** — a pack id with defaults in `KNOWN_PACKS` (`src/lib/skill-packs/adapters.ts`, grep anchor `export const KNOWN_PACKS`): `mattpocock`, `deft`, `sageox`, `gstack`, `pstack`. Defaults are keyed by pack id, not by url.
- **Ad-hoc pack** — any other git repo registered under an id of the operator's choice. Example on the operator's host: `impeccable` (`https://github.com/pbakaus/impeccable`, ref `skill-v4.7.0`, commit `aeeb3d8`, adapter detected as `claude-plugin`, 1 skill, license Apache, 1 executable not applied).
- **Adapter** — the reader that turns a pack checkout into a manifest (skills plus capabilities). `PackAdapterId = 'plain' | 'claude-plugin' | 'deft-readonly' | 'gstack-runtime'` (`adapters.ts`, grep `export type PackAdapterId`).
- **Trusted commit** — the commit the operator approved at `add` or `update`. Stored as `commit` in `config.yaml` `skills.packs.<id>`. Every launch mounts exactly this commit.
- **Mount** — the content-addressed directory `~/.overdeck/packs/mounts/<sha256>/` that holds copies of the enabled pack skills for one launch selection (`src/lib/skill-packs/mount.ts` header).
- **Launch link** — the per-launch symlink `<OVERDECK_HOME>/launch/<launchKey>/skill-packs` that points at `<mount>/plugins`; Claude Code receives it as `--plugin-dir` (`launcher-lines.ts` header; `mount.ts` `linkClaudeMount`).
- **Render** — gstack's pack-mode output `~/.overdeck/packs/gstack/render/<commit>/`, produced by the fork's `bash setup --pack-root <render> --pack-state-root <state>` (`src/lib/skill-packs/render.ts`).
- **Browser runtime** — gstack's optional `browse`/`design`/`make-pdf` binaries plus Chromium, built by `bash setup --pack-browser <render> --pack-browser-cache <cache>` after a second consent (`src/lib/skill-packs/browser.ts`).
- **Opt-in skill** — a pack skill that the pack toggle never turns on; only a per-skill `on` does.
- **Fork-first policy** — Overdeck sources known packs from operator-controlled forks under `github.com/eltmon/…`; agents never open issues, PRs or comments on, or push to, an upstream repo (PAN-4424 D2, PAN-4727 NFR-1, `docs/SAGEOX-FORK.md` line 9 "No agent contacts upstream").
- **STE** — ASD-STE100 Simplified Technical English clarity rules: active voice, short sentences, one term per concept.

### 7.2 Quickstart (section 2)

Use `mattpocock` (verified: skill `grilling` exists at `6acc160`; there is no default ref, so `--ref` is required) and a placeholder project key `myapp`:

```bash
pan skills pack add mattpocock --ref v1.2.3          # preview, then: Trust this commit? [y/N]
pan skills list --project myapp                      # pack skills show as off
pan skills set --pack mattpocock on --project myapp  # turn the pack on for one project
# start an agent or conversation in myapp, then type: /mattpocock:grilling
pan skills set --pack mattpocock inherit --project myapp   # turn it off again
pan skills pack remove mattpocock                    # unregister and delete the cache
```

State after the block: changes apply at the next launch; a running agent keeps the skills it launched with. Link `#when-pack-changes-apply`.

### 7.4 Trust and safety (section 5)

After the moved `### Adding a pack` and `### What is not applied`, add `### The trust model` with these bullets (each one sentence or two, each links to the section that holds the detail):

- Adding a pack trusts one commit and turns nothing on. Without a terminal, `--yes` is required, else nothing is written.
- Every launch mounts exactly the trusted commit; `update` shows the preview again and moves the commit only after you confirm.
- A repository cannot register itself; only `pan skills pack add` can.
- Overdeck mounts skill directories only. Hooks, MCP servers, commands, agents, context injection, git hooks and scripts are **Not applied**; scripts inside a skill directory are copied but never run by Overdeck.
- Runtime packs are the exception: gstack runs its pack-mode setup once per trusted commit (at add, update or sync) and its scripts when you invoke a skill; the preview lists every script before you trust it.
- The gstack browser runtime is a second, separate consent that lists every download and path it writes.
- Opt-in skills change files Overdeck owns or reach paid, cloud or push actions; the pack toggle never turns them on.
- A launch never touches the network: it mounts from the cache or skips the pack with a warning.
- Pack skills never land in `~/.claude/skills` or `~/.agents/skills`, so they cannot reach sessions you start outside Overdeck.
- Disclosures: the `sageox` and `gstack` pack rows show what leaves the machine. Quote both texts verbatim from `SAGEOX_DISCLOSURE` (`src/lib/sageox/disclosure.ts`) and `GSTACK_DISCLOSURE` (`src/lib/skill-packs/gstack.ts:150`).
- Deft skills carry a host notice, and outside a Directive project Claude Code launches deny Deft's CLIs.
- `pan skills pack remove <id>` deletes the cache, every mount that holds the pack, dangling launch links, and Codex plugin caches.
