## Glossary

- **Bot:** an MCP client Overdeck did not launch: Hermes, OpenClaw, Grok Build, Grok Bot, or a script calling the xAI API.
- **Platform:** which bot the operator is connecting. Type `BotPlatform = 'hermes' | 'openclaw' | 'grok-build' | 'grok-bot' | 'xai-api'`.
- **Reach:** how the bot reaches this machine. Type `BotReach = 'connector' | 'tailscale' | 'this-computer' | 'public'`.
  - **connector:** the Overdeck connector process (`pan mcp connector serve`, W-CONN2) runs beside the bot, pairs once with a **pairing string**, and serves MCP on `http://127.0.0.1:7466/mcp` with a **local token**.
  - **tailscale:** the bot calls `https://<machine>.<tailnet>.ts.net/mcp` with an access token (`odk_…`).
  - **this-computer:** Grok Build on this machine runs `pan mcp serve` over stdio with an access token in a 0600 file.
  - **public:** a hosted bot calls the public `/mcp` through Tailscale Funnel and signs in with OAuth (W-FUN1, W-OAUTH1).
- **Pairing string:** `overdeck-connector:/pair#v=1&e=<environmentId>&k=<machineKeyHex>&c=<odp_code>`, returned by `POST /api/connectors/pairing`. Parsed by `parseConnectorPairLink` (`packages/contracts/src/connector-pairing.ts`). Works once, expires in 10 minutes.
- **Local token:** `odl_<64 hex>`, written by the connector to `<connectorHome>/local-token` (default `~/.overdeck-connector/local-token`). The bot sends it as `Authorization: Bearer ${OVERDECK_CONNECTOR_LOCAL_TOKEN}`.
- **Access token:** a `kind: 'token'` record minted by `POST /api/access-tokens` (`src/dashboard/server/routes/access-tokens.ts:62-98`). Plaintext returned once.
- **Bot scopes:** the five scopes a bot may hold: `read:state`, `read:conversations`, `tell`, `operate`, `approve`. Defaults `read:state, read:conversations, tell` (PAN-4927 D-4). Never `admin`, `forward`, `read:settings`, `read:costs`, `read:events` (NFR-11).
- **OAuth level:** the access level of an OAuth sign-in (PAN-4927 D-15): `read` (Read only), `message` (+`tell`), `operate` (+`operate`), `approve` (+`operate, approve`).
- **Root viewer:** a browser on this machine (`viewer.kind === 'root-session'` in `GET /api/anywhere/status`). Only a root credential may mint pairing codes or tokens or list connectors.
- **Snippet:** the platform config text the dialog shows. Produced by pure functions in `botSnippets.ts`.

## Requirements

### Functional

- **FR-1 Bots panel.** Settings → Anywhere shows a "Bots" panel after "Access tokens": the active connectors (name, scopes, created, last used) with Remove, and a "Connect a bot" button. A non-root viewer sees "Only a browser on this machine can manage bots." and no button.
- **FR-2 Dialog entry points.** "Connect a bot" opens through `openAnywhereDialog('connect-bot')` from the Bots panel and from a command-palette row "Connect a bot".
- **FR-3 Platform and reach.** The dialog offers Hermes, OpenClaw, Grok Build, Grok Bot and xAI API. Reaches per platform: Hermes and OpenClaw → connector (default), tailscale; Grok Build → this-computer (default), connector, tailscale; Grok Bot and xAI API → public only.
- **FR-4 Access.** Checkboxes for the five bot scopes. Default ticked: exactly `read:state`, `read:conversations`, `tell`. `read:state` is ticked and disabled ("always on"). `operate` ("can start and stop work") and `approve` ("can answer questions and permission prompts") are unticked by default. For Grok Bot the checkboxes are replaced by the sentence "You choose the access level when you approve the sign-in in this dashboard."
- **FR-5 Name.** A name field, default `defaultBotName(platform)`, at most 64 characters, trimmed; empty after trim disables the create button.
- **FR-6 Connector output.** Calls `POST /api/connectors/pairing` with `{ name, scopes }` and shows the pairing string, its expiry, the connector commands and the platform snippet.
- **FR-7 Token output.** For tailscale and this-computer, calls `POST /api/access-tokens` with `{ name, scopes }` (clamped to bot scopes), shows the token once inside the token setup lines, and the platform snippet.
- **FR-8 Public output.** For Grok Bot and xAI API, reads `GET /api/mcp/public`. When enabled, shows the public URL and the Grok Bot `mcp.json` or the xAI `pan mcp oauth issue` command plus the API example. When off or the route is absent (404), shows the "Public MCP is off" guidance and a "Show Public MCP settings" button.
- **FR-9 Snippets.** `botSnippets.ts` exposes pure functions whose output is the exact text in "Snippet text" below. Only `tokenSetup` may contain token text.
- **FR-10 Docs.** `configuration/mcp.mdx` gains a "Connect a bot" section describing FR-1..FR-8 and the snippet shapes.

### Non-functional

- **NFR-1 Least privilege (PAN-4927 NFR-11).** The dialog never sends a scope outside the five bot scopes, and always sends `read:state`.
- **NFR-2 Token hygiene.** Config snippets carry `${OVERDECK_MCP_TOKEN}` / `${OVERDECK_CONNECTOR_LOCAL_TOKEN}` placeholders, never token text. The minted token appears only in the once-shown "Token setup" field. No token in a URL.
- **NFR-3 File size.** Every new file stays under 400 lines; edited files grow by at most the budget named in each work item.
- **NFR-4 Tests.** Frontend Vitest with mocked `fetch`; no real timers waits; no source-reading tests; no skips. Each new test file is listed in `scripts/frontend-test-subset.txt`.
- **NFR-5 Style.** Match `McpUrlDialog.tsx`: Tailwind classes, `role="dialog"`, `aria-modal`, `data-component` attributes, `sonner` toasts, `lucide-react` icons. No new dependency.

## Decisions

- **D-1 Snippets are specified here; the READMEs follow them.** The platform READMEs (W-INT1..4) do not exist. "Snippet text" below copies the README text the epic PRD already fixes (pan-4927.md W-INT1 step 5, W-INT2 step 6, W-INT3 step 2, W-INT4 steps 2-3). AC-23's "matches the integration README" is checked here against that quoted text; W-INT1..4 own keeping their READMEs equal to `botSnippets.ts`.
- **D-2 Snippets never carry a token.** Config snippets always use the env placeholders the READMEs use. The token (Tailscale, This computer) appears only in `tokenSetup` output, which the dialog shows once in its own field. This is stricter than pan-4927 W-BOT1's test sentence ("no token text unless the reach is Tailscale or This computer") and satisfies it.
- **D-3 Scope clamp in the client.** `botScopes(chosen)` filters to `BOT_SCOPE_CHOICES`, always adds `read:state`, and returns choice order. Both the pairing call and the token call send `botScopes(...)`. Why: `POST /api/access-tokens` accepts every scope.
- **D-4 `read:conversations` and `tell` are default-on, not locked.** AC-23 and FR-14 say "defaults"; the operator may untick them. Only `read:state` is locked (PAN-4949 D-14).
- **D-5 One form, three numbered sections.** The dialog is a single form with "1. Platform", "2. Reach", "3. Access", a Name field and one action button, like `McpUrlDialog`. Not a Next/Back wizard. After the action succeeds, the form is replaced by the output.
- **D-6 Public MCP without W-FUN1.** `loadPublicMcp()` maps a 404 to `{ available: false, enabled: false, url: null }`, rendered the same as "off". The URL comes only from that route's `baseUrl`; never derived client-side. When `enabled` is true and `baseUrl` is null, use the placeholder `https://YOUR-MACHINE.YOUR-TAILNET.ts.net:8443/mcp` and show "Tailscale is not set up, so the public URL is unknown."
- **D-7 "Show Public MCP settings".** The button calls `requestSettingsSection('anywhere')`, closes the dialog, then `document.querySelector('[data-component="public-mcp-panel"]')?.scrollIntoView({ block: 'center' })`. W-FUN1 must give `PublicMcpPanel` that `data-component` (recorded as a hazard for PAN-4947).
- **D-8 xAI level from checkboxes.** `oauthLevelForScopes(scopes)`: `approve` ticked → `approve`; else `operate` → `operate`; else `tell` → `message`; else `read`. The dialog mints nothing for xAI; it shows the `pan mcp oauth issue` command (W-OAUTH1 provides the verb).
- **D-9 Grok Bot mints nothing.** Output is the `mcp.json` with the public URL; the OAuth approval card (W-OAUTH2) picks the level.
- **D-10 Tailscale URL.** `origin = status.tailscale.serveUrl` with trailing slashes removed, else `TAILSCALE_PLACEHOLDER_ORIGIN = 'https://YOUR-MACHINE.YOUR-TAILNET.ts.net'` plus the note "Tailscale Serve is not set up on this machine yet. Set up Tailscale, then replace the placeholder." The MCP URL is `${origin}/mcp`.
- **D-11 Version.** `version = environment.serverVersion`; while loading or on error, use `latest` so the commands stay runnable.
- **D-12 Entry points.** Add `'connect-bot'` to `AnywhereDialog`, render `ConnectBotDialog` in `AnywhereDialogHost`, and add a palette row (id `anywhere-connect-bot`, label `Connect a bot`, icon `Bot` from lucide-react, description `Give Hermes, OpenClaw or Grok access to this machine`, keywords `['anywhere', 'bot', 'mcp', 'hermes', 'openclaw', 'grok']`) after "Set up Tailscale". The Bots panel button calls `openAnywhereDialog('connect-bot')`; `AnywhereSection` holds no dialog state for it.
- **D-13 Root-only rendering.** A 403 from any bots call renders "Only a browser on this machine can connect bots." in the dialog (the McpUrlDialog pattern) and "Only a browser on this machine can manage bots." in the panel.
- **D-14 Reuse `CopyField`.** Export `CopyField` from `McpUrlDialog.tsx` (add the `export` keyword, nothing else) and import it in `ConnectBotOutput.tsx`.
- **D-15 Docs home.** The doc change goes in the existing `configuration/mcp.mdx` as a "Connect a bot" section after "Revoking". W-DOC (PAN-4958) creates `configuration/bots.mdx` later and may move or link it. No `docs.json` change here.
