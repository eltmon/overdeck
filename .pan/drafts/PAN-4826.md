## Glossary

- **Capability entry** — one `MODEL_CAPABILITIES` row (`src/lib/model-capabilities.ts`, or `AUDITED_MODEL_ADDITIONS` in `src/lib/model-capability-additions.ts`, which is spread into the matrix). Its `contextWindow` is the window Overdeck *launches* the model with. It feeds the dashboard context meter (`src/dashboard/server/services/conversation/context-usage.ts`), the Deacon's 85% proactive-compaction high-water, and the Claude Code env pin from `getClaudeCodeContextPolicyForModel()` (`src/lib/agents/provider-env.ts:150`).
- **`costPer1MTokens`** — the capability entry's blended price: `(input $/M + output $/M) / 2`. Pickers show it as a badge. It is not used for billing.
- **Cost row** — one `DEFAULT_PRICING` entry in `src/lib/cost.ts` (`inputPer1k`, `outputPer1k`, `cacheReadPer1k`, per 1K tokens). Billing reads it through `getPricing(provider, model)` (`src/lib/cost.ts:267`): exact id match first, then the first row whose `model` is a **prefix** of the id.
- **`MODEL_DEPRECATIONS`** — `src/lib/model-deprecations.ts`. A single-hop map from a retired id to its replacement. `resolveModelId()` applies it. Retired ids keep their capability and cost rows so old transcripts still price.
- **Operator-retired id** — an id retired from new selections by an operator decision in September 2026 (`gpt-5.5`, `gpt-5.5-pro`, `gpt-5.4*`, `gpt-5.2`, `o3`, `gpt-4o*`, `gpt-5.3-codex*`). They stay retired. This issue reprices some of them, because old transcripts still price through them.
- **Provider-retired id** — an id the provider shuts down. Here: `claude-sonnet-4-5` (Anthropic retires it on 2026-11-30).
- **Codex route** — the `codex` harness (`PROVIDERS.openai.defaultHarness`). `gpt-6.1-terra` launches only on this route; it is **not** in `GPT_56_MODELS` (`src/lib/agents/provider-env.ts:142`), so it is not offered through CLIProxy (PAN-4633 D8).
- **Codex floor** — `CODEX_MODEL_MINIMUM_VERSIONS` (`src/lib/codex/model-floors.ts:22`). This is the oldest Codex CLI that OpenAI accepts for a model under ChatGPT sign-in. Every row in it was measured live.
- **272K pin** — `CLIPROXY_GPT56_CONTEXT_WINDOW = 272_000` (`src/lib/model-context-windows.ts`). `src/lib/runtimes/codex.ts:296` writes `model_context_window = 272000` into the managed Codex config for every model id that starts with `gpt-6-`, `gpt-6.` or `gpt-5.6-`. The capability `contextWindow` must equal it.
- **`[1m]` variant** — Claude Code syntax (`claude-sonnet-4-6[1m]`) that selects the 1M window for models that do not run at 1M by default.

## Decisions (made in this document)

- **D1 — Opus 4.6 / Sonnet 4.6 stay at `contextWindow: 200000`.** This deviates from issue AC #4. Overdeck launches these ids bare; no `[1m]` ModelId exists. In Claude Code a bare launch runs at 200K. `contextWindow` is the window Overdeck launches with, so it must stay 200K. Raising it to 1M would repeat PAN-3057: a 190K session would read 19% full, and the Deacon's 85% high-water would never fire. The `claude-api` skill's 1M is the API window. The Claude Code page is official, and the issue's decision rule 1 says the official page wins. The PR body must list AC #4 under "Not changed (contradicted by official docs)" and quote the Claude Code sentence. No `minClaudeCodeVersion` is added because the docs name none.
- **D2 — `claude-sonnet-4-5` keeps migrating to `claude-sonnet-4-6`.** `MODEL_DEPRECATIONS['claude-sonnet-4-5']` is unchanged. Issue AC #3 names this target, `claude-sonnet-4-6` is Active until at least 2027-02-17, and existing tests (`tests/lib/model-deprecation.test.ts:15-31`, `tests/unit/evals/lib/eval-model.test.ts:26`) assert it. The PR body must say that Anthropic recommends `claude-sonnet-5-5`, and that this PR keeps the issue's target.
- **D3 — `claude-sonnet-4-5` is removed only from `PROVIDERS.anthropic.models`** (`src/lib/providers.ts:98`). `getAvailableModels()` in `src/lib/settings.ts:200-212`, `getAvailableModels()` in `src/lib/model-fallback.ts:497` (it filters `MODEL_DEPRECATIONS` keys), `settings-model-catalog.ts` (it skips `MODEL_DEPRECATIONS` keys), `ModelPicker.tsx` and `modelCatalog.ts` **already omit it**. It stays in the `AnthropicModel` union (`src/lib/settings.ts:6`), in the `getProviderForModelSync` id array (`src/lib/providers.ts:471`, same as retired GPT ids, so a saved config still resolves to Anthropic and the migration fires), and in `MODEL_PROVIDERS`, capability, class and cost rows. One side effect is intended: `knownModelIds()` in `src/lib/agents/tier-table.ts:179` reads only `PROVIDERS.*.models`, so a tiered-execution config that names `claude-sonnet-4-5` now fails as unknown.
