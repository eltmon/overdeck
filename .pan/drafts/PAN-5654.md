# PAN-5654 — Run Robolectric offline so the `mobile-android` CI job never downloads `android-all` at test time

**Issue:** [PAN-5654](https://github.com/eltmon/overdeck/issues/5654)

## Glossary

- **Robolectric** — the JVM test runner that simulates the Android framework. `apps/mobile/android/app/build.gradle` pulls `org.robolectric:robolectric:4.15.1` as a `testImplementation` dependency.
- **`android-all-instrumented` jar** — the Android framework jar that Robolectric runs tests against, one per SDK level. For SDK 35 with Robolectric 4.15.1 its Maven coordinate is `org.robolectric:android-all-instrumented:15-robolectric-12650502-i7` (about 200 MB). It has no transitive dependencies (its POM lists none).
- **Online resolution (today's default)** — at test run time Robolectric's own `MavenDependencyResolver` / `MavenArtifactFetcher` downloads the jar from Maven Central into `~/.m2/repository/org/robolectric/…`. This is outside Gradle, so Gradle's cache and retries do not cover it.
- **Offline resolution** — when the test JVM has the system property `robolectric.offline=true`, Robolectric's `LegacyDependencyResolver` uses a `LocalDependencyResolver` instead. It looks for `<robolectric.dependency.dir>/<artifactId>-<version>.jar` (for example `android-all-instrumented-15-robolectric-12650502-i7.jar`) and, if the file is missing, logs `Unable to locate dependency: '<path>'` through `Logger.error` and then throws `IllegalArgumentException` with `Path is not a file:`. It never touches the network. (Verified by disassembling `robolectric-4.15.1.jar`: `LegacyDependencyResolver` reads the string constants `robolectric.offline` and `robolectric.dependency.dir`; `LocalDependencyResolver` builds the file name as `artifactId + "-" + version [+ "-" + classifier] + "." + type`.)
- **`robolectricRuntime` configuration** — a new Gradle configuration, added by this issue, that resolves only the `android-all-instrumented` jar through Gradle.
- **`fetchRobolectricRuntime` task** — a new Gradle `Sync` task that copies the `robolectricRuntime` files into `app/build/robolectric-runtime/`, the directory passed as `robolectric.dependency.dir`.
- **setup-java Gradle cache** — `actions/setup-java@v4` with `cache: gradle` saves and restores `~/.gradle/caches` and `~/.gradle/wrapper`, keyed on a hash of `**/*.gradle*` and `**/gradle-wrapper.properties`. PR runs can restore caches written by runs on `main`.
- **`test` aggregate check** — the `test` job in `.github/workflows/ci.yml` (`needs: [test-shard, test-e2e, mobile-android, integrations]`). It is red whenever `mobile-android` fails, and it is a required check.

## Problem

The `mobile-android` job fails before any Android unit test runs when Robolectric cannot download its `android-all-instrumented` jar. The `test` check then goes red on PRs that touch no mobile code. It happened twice on 2026-11-23 (PR #5607 for PAN-5598: `PushHandlerTest` and `PushNoticeTest` failed at class setup with an `AssertionError` from `MavenArtifactFetcher.java:129`; PR #5651 for PAN-5250, job 45293677453: the same `MavenArtifactFetcher` `IOException`). The job logs were not re-read during planning (the API returned nothing); the issue body's description is the evidence.

Root cause, verified in the tree:

- `apps/mobile/android/app/build.gradle`, line 64: `testImplementation 'org.robolectric:robolectric:4.15.1'`.
- Both Robolectric tests pin SDK 35: `apps/mobile/android/app/src/test/java/ai/overdeck/app/PushHandlerTest.java`, line 30, and `PushNoticeTest.java`, line 15: `@Config(sdk = 35)`. `HexTest`, `SealedBoxTest` and `com/getcapacitor/myapp/ExampleUnitTest` are plain JUnit and need no framework jar.
- `.github/workflows/ci.yml`, job `mobile-android` (search `  mobile-android:`, about line 546): `actions/setup-java@v4` with `cache: gradle`, then `./gradlew testDebugUnitTest --no-daemon` in step `Android unit tests`. Nothing caches `~/.m2`, so every run downloads the 200 MB jar, and one transient network error fails the job.

Cache seeding: the workflow runs on `push` to `main` (`on.push.branches: [main, 'uat/**']`, with `paths-ignore: ['.pan/**', '.overdeck/memory/**']`) and on `pull_request` to `main`. So `main` runs write the Gradle cache and PR runs restore it. A PR that changes a `*.gradle*` file gets a different cache key and starts cold.

## Decisions

- **D-1. Use Gradle-managed offline Robolectric, not an `actions/cache` step on `~/.m2`.** The issue offers both options and says to pick the one that also removes the download from local runs if it is no harder. The offline option does that: after one Gradle fetch, local runs and CI runs read the jar from Gradle's cache, and Robolectric never calls the network. Gradle's resolution also has its own HTTP retry for transient errors, which Robolectric's fetcher lacks.
- **D-2. Use a dedicated configuration and a `Sync` task, not `testRuntimeOnly`.** `testRuntimeOnly` would put the 200 MB framework jar on the unit-test classpath, next to Robolectric's own sandbox classloader. A separate configuration keeps it off the classpath. The `Sync` task gives Robolectric one directory that holds exactly the expected file name; Gradle's own cache path has a SHA-1 directory per file.
- **D-3. Keep one retry for a cold cache, on a separate prefetch step.** A cold Gradle cache still downloads the jar (through Gradle), so the issue's rule 2 applies. The retry wraps only `./gradlew :app:fetchRobolectricRuntime`, never the test step, so a flaky test is not hidden by a rerun.
- **D-4. Add a CI guard step that asserts Robolectric did not download anything.** After the tests, `test ! -e "$HOME/.m2/repository/org/robolectric"` proves the offline properties reached the test JVM. On a fresh runner that directory exists only if Robolectric fell back to online resolution. The step deletes nothing.
- **D-5. Keep the version coordinates in `app/build.gradle`, next to the Robolectric dependency.** Two `def` variables (`robolectricVersion`, `robolectricAndroidAllVersion`) with a comment that says they move together and where the `android-all` string comes from. No move to `variables.gradle` (Capacitor owns that file's shape; the app module is the only user).
- **D-6. No `changelog.d` entry.** The change touches only the CI job and the Android test build; no user-facing behavior changes.
- **D-7. Draft name.** This file is `.pan/drafts/PAN-5654.md`, matching the planning prompt and the majority of existing drafts.

### Implementation checkpoint (WI-1)

Confirm that offline mode works under Gradle with Robolectric 4.15.1: `PushHandlerTest` and `PushNoticeTest` pass with the new wiring, and they fail with `Unable to locate dependency` or `Path is not a file:` when `robolectric.dependency.dir` points at an empty directory (see WI-1 step 6). **Fallback** if offline mode cannot be made to work: drop WI-1's Gradle changes and instead add an `actions/cache@v4` step to the `mobile-android` job before `Android unit tests`, with `path: ~/.m2/repository/org/robolectric` and `key: robolectric-4.15.1-android-all-15-robolectric-12650502-i7`, replace WI-2's prefetch step with a fetch-only step that never runs tests: `mvn -B dependency:get -Dartifact=org.robolectric:android-all-instrumented:15-robolectric-12650502-i7 || mvn -B dependency:get -Dartifact=org.robolectric:android-all-instrumented:15-robolectric-12650502-i7` (Maven is preinstalled on `ubuntu-latest` and writes to `~/.m2/repository`, where Robolectric's online resolver looks first), and drop WI-2's `~/.m2` guard step. The `Android unit tests` step still runs once. If no fetch-only command works, stop and record the blocker in continue.json for plan revision; never retry the test task. Record the switch in continue.json.

## Requirements

- **FR-1.** The Android unit-test JVM receives `robolectric.offline=true` and `robolectric.dependency.dir=<app>/build/robolectric-runtime`.
- **FR-2.** Gradle resolves `org.robolectric:android-all-instrumented:15-robolectric-12650502-i7` through a dedicated, non-transitive `robolectricRuntime` configuration, and a `fetchRobolectricRuntime` `Sync` task copies it into `app/build/robolectric-runtime/`. Every `Test` task in the app module depends on that task.
- **FR-3.** The `mobile-android` CI job runs `./gradlew :app:fetchRobolectricRuntime --no-daemon` as its own step before the unit tests, retrying exactly once on failure.
- **FR-4.** The `mobile-android` CI job fails if `~/.m2/repository/org/robolectric` exists after the unit tests.
- **FR-5.** `apps/mobile/README.md` says that the Robolectric tests run offline, where the jar comes from, and what to change when Robolectric or the pinned SDK changes.
- **NFR-1.** The jar is not on the unit-test compile or runtime classpath.
- **NFR-2.** No step, retry or `continue-on-error` hides a failing test: the test step itself runs once.
- **NFR-3.** The job's other steps (app Vitest, web build, Capacitor sync, `assembleDebug`, APK upload) are unchanged.

## Work items

### WI-1 — Gradle: resolve the `android-all` jar through Gradle and run Robolectric offline

**Files:** `apps/mobile/android/app/build.gradle` only.

**Why:** FR-1, FR-2, NFR-1. This removes Robolectric's runtime download on CI and locally.

**Steps:**

1. Above `android {` (after the four `def upload…` lines), add the version variables:

   ```groovy
   // PAN-5654: Robolectric runs offline. These two versions move together: the android-all
   // version is the one robolectric's DefaultSdkProvider maps to SDK 35, the level the tests pin
   // with @Config(sdk = 35). A mismatch fails the tests with "Unable to locate dependency".
   def robolectricVersion = '4.15.1'
   def robolectricAndroidAllVersion = '15-robolectric-12650502-i7'
   ```

2. Immediately before `dependencies {`, declare the configuration:

   ```groovy
   configurations {
       robolectricRuntime { transitive = false }
   }
   ```

3. In `dependencies { … }`, replace

   ```groovy
   testImplementation 'org.robolectric:robolectric:4.15.1'
   ```

   with

   ```groovy
   testImplementation "org.robolectric:robolectric:$robolectricVersion"
   robolectricRuntime "org.robolectric:android-all-instrumented:$robolectricAndroidAllVersion"
   ```

4. After the closing `}` of `dependencies { … }` and before `apply from: 'capacitor.build.gradle'`, add:

   ```groovy
   // PAN-5654: Gradle fetches Robolectric's android-all jar (cached in ~/.gradle, and by
   // setup-java's Gradle cache in CI), so a test run never downloads it through Robolectric's
   // own MavenArtifactFetcher.
   def robolectricDependencyDir = layout.buildDirectory.dir('robolectric-runtime').get().asFile
   def fetchRobolectricRuntime = tasks.register('fetchRobolectricRuntime', Sync) {
       from configurations.robolectricRuntime
       into robolectricDependencyDir
   }
   tasks.withType(Test).configureEach {
       dependsOn fetchRobolectricRuntime
       systemProperty 'robolectric.offline', 'true'
       systemProperty 'robolectric.dependency.dir', robolectricDependencyDir.absolutePath
   }
   ```

5. Do not touch `testOptions { unitTests { includeAndroidResources = true } }` or any other block.

6. Verify (implementation checkpoint). The local Gradle build needs this chain first, from the workspace root: `bun install --frozen-lockfile`, `npm --prefix apps/mobile run build`, `npm --prefix apps/mobile run cap:sync -- android`. It needs the Android SDK: export `ANDROID_HOME=$HOME/Android/Sdk` (the SDK is installed there on this machine; `ANDROID_HOME` is unset and the workspace has no `local.properties`). Then, in `apps/mobile/android`:
   - `./gradlew :app:fetchRobolectricRuntime --no-daemon` exits 0 and `app/build/robolectric-runtime/android-all-instrumented-15-robolectric-12650502-i7.jar` exists.
   - `./gradlew :app:testDebugUnitTest --no-daemon` exits 0, and `app/build/test-results/testDebugUnitTest/` holds passing `TEST-ai.overdeck.app.PushHandlerTest.xml` and `TEST-ai.overdeck.app.PushNoticeTest.xml`.
   - Negative check (proves offline mode is active, because this machine already has the jar in `~/.m2` and a plain pass proves nothing): make a one-off, uncommitted edit that changes only the `systemProperty 'robolectric.dependency.dir', …` value to `layout.buildDirectory.dir('robolectric-empty').get().asFile.absolutePath` (a directory that holds no jar), then run `./gradlew :app:testDebugUnitTest --no-daemon --tests 'ai.overdeck.app.PushNoticeTest'`. The test must fail, and either the Gradle output or `app/build/test-results/testDebugUnitTest/TEST-ai.overdeck.app.PushNoticeTest.xml` must contain `Unable to locate dependency` or `Path is not a file:` naming `robolectric-empty`. Revert the one-off edit before committing. Never delete or move `~/.m2` to test this.

**Tests:** the existing `PushHandlerTest` and `PushNoticeTest`. No new test file.

### WI-2 — CI: prefetch with one retry, then assert Robolectric stayed offline

**Files:** `.github/workflows/ci.yml` only, job `mobile-android`.

**Why:** FR-3, FR-4, NFR-2, NFR-3.

**Steps:** between the existing steps `Sync Capacitor (Android)` and `Android unit tests`, insert:

```yaml
      # PAN-5654: Gradle fetches Robolectric's android-all jar (the setup-java Gradle
      # cache restores it on later runs). One retry covers a transient error on a cold
      # cache; the test step below is never retried.
      - name: Fetch the Robolectric runtime
        working-directory: apps/mobile/android
        run: ./gradlew :app:fetchRobolectricRuntime --no-daemon || ./gradlew :app:fetchRobolectricRuntime --no-daemon
```

After the existing `Android unit tests` step and before `Assemble the debug APK`, insert:

```yaml
      # PAN-5654: Robolectric runs offline. If it fell back to its own download, it
      # would have written this directory on the fresh runner.
      - name: Check Robolectric ran offline
        run: test ! -e "$HOME/.m2/repository/org/robolectric"
```

Do not change the `Android unit tests` step, any other step, or the job's triggers.

**Push hazard:** `.github/workflows/` edits must be pushed over SSH, because the gh OAuth token lacks the `workflow` scope. If `git push` over HTTPS is refused for this reason, push with `git push git@github.com:eltmon/overdeck.git HEAD:feature/pan-5654`.

**Tests:** the `mobile-android` job on this PR's CI run. Its log shows the `Fetch the Robolectric runtime` and `Check Robolectric ran offline` steps succeeding, and `Android unit tests` passing.

## Critique response

### Fallback retries tests

Accepted. The WI-1 fallback no longer retries anything that runs tests. It uses a fetch-only step, `mvn -B dependency:get -Dartifact=org.robolectric:android-all-instrumented:15-robolectric-12650502-i7`, retried once with `||`; Maven writes the jar to `~/.m2/repository`, where Robolectric's online resolver finds it without a network call. The `Android unit tests` step still runs exactly once (NFR-2). If no fetch-only command works, the work agent stops and records the blocker for plan revision instead of retrying test setup.

### Negative check expects a log message

Accepted. WI-1 step 6 and AC-3 now accept either the `Unable to locate dependency` log line or the thrown `Path is not a file:` error, in the Gradle output or the JUnit XML.

### One runtime jar covers one SDK

Accepted. WI-3 now says every Robolectric test must pin the same SDK with this setup, and that a second SDK needs a second `robolectricRuntime` coordinate.

### Unresolved after two critic rounds

- Fallback cannot satisfy the plan's acceptance criteria
