## 2. What is wrong (verified)

1. **Groups open by default.** `FE/components/CommandDeck/ConversationList.tsx` lines 536–540:
   ```ts
   const isGroupCollapsed = useCallback((node: ConversationTreeNode<Conversation>) => {
     if (collapsedGroups.has(node.conv.name)) return true;
     if (expandedGroups.has(node.conv.name)) return false;
     return !node.descendants.some((child) => isConversationActive(child.conv));
   }, [collapsedGroups, expandedGroups]);
   ```
   `isConversationActive` (`conversation-tree.ts` line 57) is true for any child with `sessionAlive`, so the Flywheel group (20 handoff children, most alive and idle) opens. Its 20 two-line rows push the Issues section to y≈1830 on a 1000px screen. Parent §6.6 item 4 says successor chains collapse to one line.
2. **Cost clipped mid-number.** `.conversationMetaLine` (`FE/components/CommandDeck/styles/command-deck.module.css` line 2403) is `display:flex; white-space:nowrap; overflow:hidden`. The part spans (`ConversationRow.tsx` lines 622–631) have the flex default `min-width:auto`, so they never shrink and the line clips at its right edge. Cost is the last part, so it is cut: `Working · no file changes · $2` for $26.73.
3. **Footer "Mac…".** `FE/components/sidebar/MachinesNavItem.tsx` footer branch (lines 25–40) renders `{!collapsed && <span className="truncate">Machines</span>}`, the one footer label that shrinks.
4. **Two current nav items.** `FE/components/frame/LeftNav.tsx`: Project home is `active={activeTab === 'command-deck'}` (line 86) and `moreActive` (line 77) is true when any visible More item's id equals `activeTab`. `FE/components/frame/navGroups.ts` line 30 lists `{ id: 'command-deck' as Tab, label: 'Command Deck', icon: Compass }` under Operations, so on every deck tab both are current. The same happens on `/settings`: More lists Settings (line 61) and the footer Settings button (`LeftColumnFooter.tsx` line 62) is also current.
5. **Project lost on a fresh load of a global page.** `FE/App.tsx` lines 180–182 initialize `selectedProjectKey` from the route only (`initialCockpitRoute?.project ?? initialProjectRoute`). Loading `/activity` gives `null`, and `LeftColumn.tsx` line 177 shows "Pick a project to see its conversations and issues".
6. **Feed tab repeats itself.** `FE/components/ActivityFeedTab.tsx` renders `SessionFeedSidebar` with `heading="Feed"` inside `max-w-3xl`, under a page tab already named Feed. With no project, the scope switcher (`SessionFeedSidebar.tsx` lines 117–141) still offers Project, and `readStoredScope` (line 412) defaults to `'project'`, which then shows unscoped items.

## 3. Decisions

- **D-1** A group is collapsed by default. It opens by default only when a descendant needs the operator: `(child.conv.pendingInputCount ?? 0) > 0`. The toggle already shows `N working` / `N needs you`, so nothing is hidden silently. The persisted collapsed set (`commandDeck.groups.collapsed`) and the session expanded set keep working as today.
- **D-1a (planning, 2026-11-15)** A collapsed group still renders its **selected** descendant (`child.conv.name === selectedConversation`), and only that one, under the toggle. Reason: a handoff chain's live successor is a descendant; without this, opening it from the feed or a deep link would hide its own row. Opening the whole group instead would show all 20 Flywheel successors again (defect 1), so selection does not change `isGroupCollapsed`.
- **D-2** In the meta line the cost part never shrinks (`flex-shrink:0`). Every other text part may shrink and ends in an ellipsis. Badges after the parts are unchanged.
- **D-3** The footer Machines button becomes icon-only, like Settings. It keeps `data-testid="sidebar-machines"`, `aria-label="Machines"` and the title `Machines · N online` / `Machines`. The `nav` variant is unchanged.
- **D-4** Project home is current only when `activeTab === 'command-deck'` and the deck's active pane is Home: `usePanesStore(selectActivePane(selectedProject ?? ''))` returns a pane with `paneType === 'home'`, or returns `null` (no pane recorded yet — the Stage then shows Home, as `Breadcrumb.tsx` line 20 assumes). Remove `command-deck` from the More menu in `navGroups.ts`: Project home is its door, and the command palette (`CommandPalette.tsx` line 551) and `g c` still reach it with no project. More is current only when a remaining More item other than `settings` is the active tab; on `/settings` only the footer Settings button is current.
- **D-5** Remember the last selected project in `localStorage['overdeck.ui.lastProjectKey']`.
  - **Write:** whenever `selectedProjectKey` is non-null (a project name/key, or `NO_PROJECT_KEY`), write it. `null` writes nothing.
  - **Read (initial state only):** route project first (cockpit, then `/command-deck/<project>`). Otherwise, if the path is exactly `/command-deck` or starts with `/conv/`, start with `null` as today (a bare deck URL means no project; a conversation deep link sets its own project). Otherwise use the stored value.
  - **Validate:** only a value that came from storage, only once, only after the `['registered-projects']` query succeeds (`isSuccess`). It is valid when it equals `NO_PROJECT_KEY` or matches a registered project's `key` or `name`. If invalid, set the selection to `null` and remove the stored key (`clearLastProjectKey()`), so the dead project neither flashes on the next reload nor reaches PAN-5343's `readLastProjectKey()`. A route-supplied project is never validated here (the deck already shows `UnknownProjectState`).
  - The popstate handler (lines 626–629) is unchanged.
  - Helpers live in a new `FE/lib/lastProject.ts` so `App.tsx` grows by only a few lines. PAN-5343 calls `readLastProjectKey()` and `writeLastProjectKey()` by these names.
- **D-6** The Feed tab shows no inner header row. Add `hideHeader?: boolean` to `SessionFeedSidebar`; `ActivityFeedTab` passes `hideHeader` and drops `heading`. Widen the box to `max-w-5xl`. Add `projectScopeAvailable?: boolean` (default `true`); `ActivityFeedTab` passes `projectScopeAvailable={scoped}`, so it is false for both `null` and `NO_PROJECT_KEY`. When false, the Project chip is not rendered (grid becomes `grid-cols-2`) and the effective scope is `scope === 'project' ? 'global' : scope`. The stored preference is **not** rewritten, so Project comes back when a project is selected.
- **D-7 (operator request, 2026-11-15)** The New conversation button shows the model it will use. The main part becomes two lines: line 1 is today's `+ New conversation` with the `N` keycap; line 2 (`text-[11px] text-muted-foreground`, one text line) shows the provider icon, the short model name, the harness label only when the harness is not `claude-code`, and the effort word, joined by ` · `: `Opus 5.5 · High`, `GPT-5.5 · Codex · High`.
  - Values: `useNewConversationDefaults` `model`, `harness`, `effort` (already read in the component), so a caret-menu change updates the line at once.
  - Model: find the model in `useAvailableModels().groups` (`FE/components/shared/ModelPicker`). `fullLabel` = that model's `label`; `provider` = `getProviderForPickerModel(model, groups)` (`shared/ModelPicker/ModelPicker.tsx` line 36); `providerLabel` = the matching group's `label`, else the provider id. Unknown model id: `fullLabel = shortName = compactModelName(model)` (`FE/lib/model-names.ts` line 7).
  - Short name: `fullLabel` with a leading `Claude ` and a trailing ` (…)` removed (`Claude Opus 5.5 (1M context)` → `Opus 5.5`).
  - Icon: `ProviderIcon` from `FE/components/shared/branding` with `provider` and `label={providerLabel}`, `className="h-3 w-3"`. When `provider` is undefined, no icon.
  - Harness word: `shortHarness(harness)` from `FE/components/CommandDeck/conversationMeta.ts` line 19, only when `harness !== 'claude-code'`.
  - Effort word: `SHORT_LABELS[effort]` (export it from `FE/components/chat/EffortPicker.tsx` line 22). It is omitted when the model takes no effort, using the exact rule `useCreateConversation.ts` lines 42–43 uses to decide whether to send effort: `const levels = pickerEffortLevels(model) ?? MODEL_EFFORT_SUPPORT[model]; show = levels?.length !== 0`. The line therefore names exactly what quick create sends.
  - Title: `New conversation with <fullLabel>[ · <harness>][ · <effort>] (N)`; `aria-label` stays `New conversation`. The collapsed 48px column keeps the `+` icon only, with the same title.
  - Requests: `useAvailableModels()` loads the catalog through one module-level promise (`shared/ModelPicker/ModelPicker.tsx` line 117, `availableModelsPromise`), shared with every other picker, after mount. The button is on every route, so a page load that never opened a picker now sends that one set of catalog requests. It is not on the pre-mount boot list (`FE/lib/bootRequests.ts`), and no test budgets it. Until it resolves, `FALLBACK_GROUPS` names the common models.
- **D-8 (operator request, 2026-11-15)** Every project gets a colored mark, as in `docs/design/multi-conversation-mockup.html` (`.pmark`). A rounded square with `projectInitials(name)` (`ProjectSwitcher.tsx` lines 38–43) in white, `font-mono font-semibold`, on a color from an 8-color palette, picked from the project key:
  - Palette (operator-sanctioned in the issue comment of 2026-11-15; no lint enforces the no-hex rule, and `shared/branding` already holds brand hex values): `#4f46e5`, `#0f766e`, `#7c3aed`, `#be185d`, `#92400e`, `#4d7c0f`, `#0369a1`, `#86198f`. White text contrast is 4.99:1 or better on each (checked).
  - Hash: `index = (sum of key.charCodeAt(i) for every i) * 31 % 8`. On the 21 keys in `.overdeck/projects.yaml` this spreads 4,1,2,3,2,3,3,3 — collisions are unavoidable with 8 colors. Pinned values for tests: `panopticon-cli` → `#4f46e5`, `mind-your-now` → `#be185d`, `dfai` → `#92400e`, `krux` → `#0369a1`.
  - Shown in (1) the closed switcher button at 28px (`h-7 w-7`) when a project is selected, colored by `selected.key`; (2) every project row in the switcher menu at 18px before the name, colored by `project.key`; (3) the No project row and the unselected button as today's muted `–` square. Rows from other machines (`OtherMachineProjects`) get no mark.
  - PAN-5343 reuses the component (`<ProjectMark size="sm">`).
