# PAN-5169 — Herdr backend: conversation pane reads must not call tmux, and `pan up` must not require tmux

**Issue:** [PAN-5169](https://github.com/eltmon/overdeck/issues/5169)
**Related:** PAN-5168 (shared host-tool lookup module, in parallel — do not duplicate it), #4097, #3926, #4282.
**Base commit verified against:** `898acac3f28` (main, release 0.81.0).

## Glossary

- **Host backend** — the terminal backend this host is configured to use: `herdr` (default) or `tmux`. Answered by `hostTerminalBackendName()` in `src/lib/terminal-backends/select.ts` (env `OVERDECK_TERMINAL_BACKEND` → config `terminal.backend` → default `herdr`; memoized per process; never touches the filesystem).
- **Herdr pane** — the Herdr-hosted pane that holds an agent or conversation, found by `findHerdrAgentPane(name)` in `src/lib/terminal-backends/herdr.ts`. That function **swallows all errors and returns `null`**, so "Herdr holds no pane" and "the Herdr socket was slow" look the same to callers.
- **Legacy tmux fallback** — the branch in `resolveAgentPaneIo` (`src/lib/terminal-backends/agent-pane-io.ts`) that, on a Herdr host where `findHerdrAgentPane` returned `null`, reads and keys the pane through tmux instead (`capturePane`, `sendKeysAsync`). It exists for agents launched on tmux before the host moved to Herdr.
- **Polled conversation pane read** — a pane read the dashboard runs on every conversation-list poll, every pending-input feed poll, or every single-conversation read, for each live conversation. There are four: the input target (`readConversationInputTarget`), the boot-blocking-screen check (`conversationNeedsTerminal`), the pane permission prompt (`readConversationPermission`), and the numbered-choice menu (`claudeConversationPaneChoice`).
- **Strict read** — a polled conversation pane read that, on a Herdr host, reads only the Herdr pane and **throws** when Herdr holds no pane, instead of taking the legacy tmux fallback.
- **Spawn storm** — on macOS, each `spawn` of a binary that is not on PATH leaves ~8–12 dead `node` processes (one `posix_spawn` attempt per PATH entry). Per-conversation-per-poll tmux calls on a tmux-less Mac multiply this (PAN-5168 measures it).
- **`ensureHostTools`** — the boot-time host-tool step `pan up` runs (`src/lib/prereqs/registry.ts`). It checks tmux and jq, auto-installs a missing one, and today exits the process when tmux cannot be installed.

## Problem

On a Herdr host with no tmux binary (the reporter's Mac: macOS 27.2, Overdeck 0.77.0, Herdr at `~/.local/bin/herdr`, no tmux, no Homebrew):

1. **Conversation polls still spawn tmux.** Verified on `898acac3f28`:
   - `conversationNeedsTerminal` calls tmux `capturePane` **directly** — `src/lib/overdeck/conversation-reads.ts`, line 207–208:
     ```ts
     const captureVisiblePane = (sessionName: string): Promise<string> =>
       capturePane(sessionName, 0);
     ```
     It runs on every conversation-list poll (`src/lib/overdeck/conversation-list.ts`, line 284, `needsTerminal: await conversationNeedsTerminal(row, sessionAlive, convSf)`) and every single read (`conversation-reads.ts`, line 556), for every live claude-code conversation whose transcript file does not exist yet.
   - `claudeConversationPaneChoice` calls tmux `capturePane` through `captureSessionPaneChoice`'s default (`src/lib/session-pane-choice.ts`, line 49–51, `capture: (...) => Promise<string> = capturePane`). The pending-input feed calls it with `{}` whenever `permission.tmuxPaneText` is `null`, which is **always** on a Herdr host (`conversation-reads.ts`, line 428):
     ```ts
     paneChoice = await claudeConversationPaneChoice(conv, sharedPane !== null ? { capture: async () => sharedPane } : {});
     ```
     The single read calls it with no options at all (`conversation-reads.ts`, line 533, `pendingPaneChoice = await claudeConversationPaneChoice(conv);`). So on Herdr every live claude-code conversation with nothing else pending costs one failed tmux spawn per feed poll. This is the largest per-conversation leak; the issue text does not name it, but it is the same class.
   - `readConversationInputTarget` (`src/lib/overdeck/conversation-input-target.ts`, line 35) and `readConversationPermission` (`src/lib/overdeck/conversation-permission.ts`, line 183) go through `resolveAgentPaneIo`, which takes the legacy tmux fallback whenever `findHerdrAgentPane` returns `null` — including when the Herdr socket merely timed out.
2. **`pan up` refuses to start without tmux.** `ensureHostTools()` (`src/lib/prereqs/registry.ts`, line 200) lists `{ tool: "tmux", label: "tmux", fatal: true }`, tries `installTmux()`, which on darwin runs `brew install tmux` (line 233) even when `brew` is not on PATH, fails with "Failed to install tmux", prints `Install manually: brew install tmux` (useless without Homebrew), and calls `process.exit(1)`.

## Goals

- Under the Herdr host backend, no polled conversation pane read ever calls tmux.
- Under the tmux host backend, every polled conversation pane read behaves exactly as today.
- `pan up` requires tmux only under the tmux host backend; under Herdr a missing tmux is a warning and boot continues.
- No automatic `brew install` when `brew` is not on PATH; print a manual hint that works without Homebrew.
- A `changelog.d/pan-5169.md` entry (operator comment).

## Non-goals

- **Conversation liveness** (`src/lib/overdeck/conversation-liveness.ts`): its tmux reads on a Herdr host (`absent` → tmux `has-session`, `tmuxSessionNames` in `listLiveConversationSessions`) are the deliberate rollback-safety path (PAN-3921). Removing them would read legacy tmux conversations as dead. They run once per poll, not once per conversation; PAN-5168's host-tool lookup removes their spawn when tmux is absent.
- **A host-tool cache or PATH-lookup module.** PAN-5168 owns that. This issue adds no cache (operator comment: "Do not add a second tool cache").
- The `execSync('tmux … set-environment -gu …')` loop in `src/cli/index.ts` right after `ensureHostTools` (already try/catch-guarded).
- `PREREQ_REGISTRY.spawnAgent: ["tmux"]` and the `/api/prereqs` route.
- Other `capturePane` callers under `src/dashboard/server/routes/` and `services/` (agent output, reviewer tree, command deck, workspace data, ws-terminal).
- The user-initiated paths keep the legacy tmux fallback (`resolveAgentPaneIo` default unchanged): `answerConversationPermission` (`conversation-permission.ts`, line 243), the message-send permission hold (`conversation-message.ts`, line 619, which guards ensure-main's keys), the pane-choice answer route, scheduled-message delivery and ensure-main.
- Routing pane-choice **detection** through Herdr. The answer path is tmux-only, so a detected menu on a Herdr pane could not be answered from the dashboard.
- `pan install`'s prerequisite warning wording in `src/cli/commands/install-prereqs.ts`.
- The pre-existing `installTtyd` darwin download fallback (downloads a Linux binary); only its brew attempt is guarded.

## Decisions (made here; the executor does not re-decide)

- **D1 — Strict reads, opt-in.** Add an options parameter to `resolveAgentPaneIo`: `{ legacyTmuxFallback?: boolean }`, default `true` (every existing caller unchanged). With `legacyTmuxFallback: false`, on a Herdr host where `findHerdrAgentPane` returns `null`, it **throws** `new Error(\`herdr holds no pane for ${agentId}\`)` and never imports or calls tmux. On a tmux host the option has no effect. This mirrors `readAgentPaneText`, which already throws on a Herdr miss.
- **D2 — Consequence accepted.** A legacy tmux conversation on a Herdr host loses its pane-derived fields: `inputTarget` reads `'unknown'`, `needsTerminal` reads `false`, the pane permission prompt is not detected (the hook registry still reports it), and pane-choice menus are not reported. A Herdr socket timeout produces the same "unreadable" result instead of a tmux spawn.
- **D3 — Pane-choice detection is skipped under Herdr**, inside `claudeConversationPaneChoice`, when the caller supplies no `capture`. This covers both callers (feed line 428 and single read line 533) with one change.
- **D4 — `needsTerminal` screen size.** On tmux keep `capturePane(name, 0)` (visible screen only) exactly: scrollback could still hold an answered onboarding screen and flip the view to terminal. On Herdr read `source: 'visible'` with an explicit 60 lines (no Herdr read uses `lines = 0` anywhere today; do not introduce one).
- **D5 — `pan up` under Herdr** does not try to install a missing tmux. It prints one yellow warning and continues. Under tmux, behavior is unchanged (install, then exit 1 on failure). Backend comes from `hostTerminalBackendName()`, as `pan install` (`src/cli/commands/install.ts`, line 258) and `pan doctor` (`src/cli/commands/doctor.ts`, line 701) already do.
- **D6 — Brew detection** uses the existing uncached, spawn-free `findExecutableOnPath('brew', process.env.PATH)` from `src/lib/pan-cli-shim.ts` (line 131). No new module, no cache.

## Requirements

- **FR-1** — On a Herdr host, `conversationNeedsTerminal` never calls tmux `capturePane`; it reads the Herdr pane (`source: 'visible'`, 60 lines) and returns `false` when Herdr holds no pane.
- **FR-2** — On a Herdr host, `readConversationInputTarget` never calls tmux; when Herdr holds no pane it returns `'unknown'`.
- **FR-3** — On a Herdr host, the polled permission reads (pending-input feed and single conversation read) never call tmux; when Herdr holds no pane they return `tmuxPaneText: null` and treat the pane as unreadable. The message-send permission hold keeps the default fallback.
- **FR-4** — On a Herdr host, `claudeConversationPaneChoice` without a `capture` option returns `null` without capturing.
- **FR-5** — On a tmux host, FR-1..FR-4 paths make exactly the same tmux calls as before (same session name, same line counts).
- **FR-6** — `ensureHostTools` treats tmux as required only when the host backend is `tmux`; under `herdr` a missing tmux prints a warning, runs no installer and does not exit.
- **FR-7** — On darwin, `installTool('tmux' | 'jq' | 'mkcert')` returns `success: false` without running any `brew` command when `brew` is not on PATH; `installTool('ttyd')` skips its brew attempt.
- **FR-8** — On darwin without `brew` on PATH, `ensureHostTools`'s manual hint names a download URL and Homebrew, never a bare `brew install <tool>`.
- **FR-9** — Docs and changelog describe the new behavior (WI-8).
- **NFR-1** — No new host-tool cache or PATH-lookup module (PAN-5168 owns it).
- **NFR-2** — `resolveAgentPaneIo`'s default behavior is unchanged for every existing caller.
- **NFR-3** — `src/lib/overdeck/conversation-reads.ts` stays at or under 1000 lines (it is 982 on main; `scripts/lint-file-size.sh` ceiling is 1000). Never raise a `scripts/file-size-allowlist.txt` row.
