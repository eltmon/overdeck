# PAN-5281 — Commit attribution trailers for agents and conversations

**Issue:** https://github.com/eltmon/overdeck/issues/5281
**Context:** first backend slice of the file-management and change-review redesign (parent #5183). The operator approved the conversation **Changes** mockup on 2026-11-14 (`.tmp/conversation-changes-files-mockup.html`, not committed). That view lists "this conversation's commits", which needs exact attribution. This issue adds the attribution and a reader. The UI comes in a later issue.

## 1. Summary

Every `git commit` run by an Overdeck agent or conversation gets one trailer line naming who made it:

- a conversation: `Overdeck-Conversation: <conversation session name>` (for example `Overdeck-Conversation: conv-20261113-6031`);
- an agent: `Overdeck-Agent: <agent id>` (for example `Overdeck-Agent: agent-pan-5185`).

The trailer is added by the `git` shim that is already on the PATH of agents, and by a new git shim on the PATH of conversations. A new library function lists the commits a conversation or agent made in a repository, by reading those trailers.

## 2. Glossary

- **Trailer** — a `Key: value` line in the last paragraph of a commit message (git's term). Git adds one with `git commit --trailer "Key: value"` (git 2.32 or later; this machine has 2.43).
- **Git shim / guard** — the shell script named `git` that the launcher writes into `<OVERDECK_HOME>/agents/<agentId>/git-guard/` and puts first on the agent's PATH. It is generated by `buildGitGuardLines` in `src/lib/launcher-git-guard.ts` (search `export function buildGitGuardLines`). It finds the git subcommand with `_overdeck_git_find_command`, blocks some commands, and `exec`s the real git.
- **Conversation gh shim** — `buildConversationGhShimLines` in the same file (search `export function buildConversationGhShimLines`). It writes only a `gh` shim into `<OVERDECK_HOME>/conversations/<id>/git-guard/`. Conversations have no git shim today.
- **Conversation session name** — the value the launcher exports as `OVERDECK_CONVERSATION` (`src/lib/overdeck/conversation-runtime.ts`, search `export OVERDECK_CONVERSATION=`). The same value is passed as `ghShim.id` (search `ghShim: { id: tmuxSession`).
- **Agent id** — the value exported as `OVERDECK_AGENT_ID` (`src/lib/launcher-generator.ts`, search `export OVERDECK_AGENT_ID=`).
- **Bypass** — `OVERDECK_PAN_GIT_OP=1` makes the shim exec the real git unchanged (search `OVERDECK_PAN_GIT_OP` in `launcher-git-guard.ts`). `pan`'s own git operations set it.

## 3. Decisions

- **D-1 The shim adds the trailer; no git hook is used.** Projects own `core.hooksPath` (overdeck uses husky). An Overdeck hook would replace or race the project's hooks. The shim already sees every PATH-resolved `git` call of the agent, so it is the one place that works for every harness (Claude Code, Codex, Pi, Kimi, OpenCode, …) without touching the repository.
- **D-2 Trailer keys and values.** Conversation: `Overdeck-Conversation: $OVERDECK_CONVERSATION`. Agent: `Overdeck-Agent: $OVERDECK_AGENT_ID`. When both variables are set (an agent launched from inside a conversation inherits `OVERDECK_CONVERSATION`), the agent shim writes only `Overdeck-Agent`, because the agent made the commit. The value is the raw environment value; if it is empty or unset, no trailer is added.
- **D-3 Only `git commit`.** The shim adds `--trailer` only when the subcommand found by `_overdeck_git_find_command` is exactly `commit`. `merge`, `cherry-pick`, `revert`, `rebase` and `am` are not changed. A cherry-picked or rebased commit keeps whatever trailers its message already has.
- **D-4 Placement.** The shim inserts `--trailer "<Key>: <value>"` immediately after the `commit` token, keeping every other argument in order, including arguments after `--`. Git's default `trailer.ifExists=addIfDifferentNeighbor` means `git commit --amend` on a commit that already ends with the same trailer does not add a duplicate. The executor must not set `trailer.*` config.
- **D-5 Conversations get a git shim that only adds the trailer.** Conversations are operator sessions: the conversation git shim must not block `rebase`, `stash`, `reset --hard` or anything else, and must not run the branch check. It finds the subcommand, adds the trailer for `commit`, and `exec`s the real git. It lives in the same `<OVERDECK_HOME>/conversations/<id>/git-guard/` directory as the conversation `gh` shim, so the existing `dropInheritedGuardDirLines` prelude and `pan restart` PATH stripping already handle it.
- **D-6 The bypass also skips the trailer.** With `OVERDECK_PAN_GIT_OP=1` the shim execs the real git unchanged, as today.
- **D-7 Remote (Fly) agents are out of scope.** `spawnMode === 'remote'` launchers are unchanged.
- **D-8 Reader is a library function, not a route.** The Changes view issue will add the HTTP route. This issue adds `listAttributedCommits` and its tests only.

## 4. Requirements

- **FR-1** A `git commit` run through an agent's git shim, with `OVERDECK_AGENT_ID` set, produces a commit whose message ends with the trailer `Overdeck-Agent: <OVERDECK_AGENT_ID>`.
- **FR-2** A `git commit` run in a conversation, with `OVERDECK_CONVERSATION` set, produces a commit whose message ends with `Overdeck-Conversation: <OVERDECK_CONVERSATION>`.
- **FR-3** Every other git subcommand behaves exactly as before in both shims, including all existing agent-guard refusals.
- **FR-4** `git commit --amend --no-edit` on a commit that already carries the same trailer leaves exactly one such trailer.
- **FR-5** With `OVERDECK_PAN_GIT_OP=1`, no trailer is added.
- **FR-6** `listAttributedCommits({ repoPath, key, value, since?, maxCount? })` returns the commits in `repoPath` reachable from `HEAD` whose trailer `key` equals `value`, newest first, each as `{ sha, subject, authoredAt, files: { path, status, additions, deletions }[] }`.
- **NFR-1** The reader uses async process execution only (`execFile` promisified or the repo's existing async git helper). No `execSync` (it is reachable from the dashboard server later).
- **NFR-2** Tests that touch git create temporary repositories; they never commit in the overdeck checkout.

## 6. Work items

### WI-1 — Trailer insertion in the agent git shim (FR-1, FR-3, FR-4, FR-5)

File: `src/lib/launcher-git-guard.ts`.

1. Add a POSIX-sh fragment constant `TRAILER_SH` (same style as `BRANCH_CHECK_SH`: an array of lines with `\\$` escapes for the unquoted heredoc). It defines a function `_overdeck_add_trailer` that takes the trailer text and the original arguments, walks them with the same option-skipping rules as `_overdeck_git_find_command`, and rebuilds the argument list with `--trailer "<text>"` inserted right after the first non-option token when that token is `commit`. POSIX sh has no arrays; rebuild with the rotate pattern: loop `n=$#` times, `arg=$1; shift; set -- "$@" "$arg"`, and when the rotated `arg` is the subcommand token `commit` (first one only), also `set -- "$@" --trailer "$text"`.
2. In the agent shim (`buildGitGuardLines`, default and read-only modes), after the existing refusal checks and just before the final `exec "$_OVERDECK_REAL_GIT" "$@"`, add: if `OVERDECK_AGENT_ID` is non-empty and the found command is `commit`, call the rebuild with `Overdeck-Agent: $OVERDECK_AGENT_ID`. Read-only mode already refuses commits in the guarded repository; commits elsewhere (test fixtures) get the trailer too, which is fine.
3. Keep the bypass branch (`OVERDECK_PAN_GIT_OP=1`) first, unchanged.

Tests (extend `src/lib/__tests__/launcher-git-guard-behavior.test.ts`, which already runs the generated shim against a temporary repo through `runGuardedGit`):
- `adds an Overdeck-Agent trailer to git commit` — commit with `-m msg`, then `git log -1 --format=%(trailers:key=Overdeck-Agent,valueonly)` prints the agent id.
- `keeps arguments after -- and -m values with spaces` — `commit -m "two words" -- file.txt` commits only `file.txt` with subject `two words` and the trailer.
- `does not duplicate the trailer on amend --no-edit`.
- `adds no trailer with OVERDECK_PAN_GIT_OP=1`.
- `does not touch git merge` — a merge commit has no Overdeck trailer.

### WI-3 — Reader: `listAttributedCommits` (FR-6, NFR-1, NFR-2)

New file: `src/lib/git/attributed-commits.ts`.

```ts
export type AttributionKey = 'Overdeck-Conversation' | 'Overdeck-Agent';
export interface AttributedCommitFile { path: string; status: 'A' | 'M' | 'D' | 'R'; additions: number; deletions: number }
export interface AttributedCommit { sha: string; subject: string; authoredAt: string; files: AttributedCommitFile[] }
export async function listAttributedCommits(opts: {
  repoPath: string; key: AttributionKey; value: string; since?: string; maxCount?: number;
}): Promise<AttributedCommit[]>
```

1. Use two git calls, which are simpler to parse than one combined call. Step 1: `git -C <repoPath>` `git log HEAD [--since=<since>] [--max-count=<maxCount, default 200>] --format=%H%x1f%s%x1f%aI%x1f%(trailers:key=<key>,valueonly,separator=%x2c)` and keep lines whose trailer list (split on `,`, trimmed) contains `value`. Step 2, for each kept sha: `git show --format= --numstat -M <sha>` for additions and deletions and `git show --format= --name-status -M <sha>` for status; join by path. Binary files report `-` in numstat; record 0 and 0.
2. Use the repo's existing async git runner if one exists in `src/lib/git/` (check `src/lib/git/operations.ts` for an exported async exec helper); otherwise `promisify(execFile)` with `maxBuffer: 16 * 1024 * 1024`.
3. Return newest first (git log order).

Tests (`src/lib/git/__tests__/attributed-commits.test.ts`): a temp repo with four commits: two with `Overdeck-Conversation: conv-a`, one with `conv-b`, one with none. Assert the `conv-a` call returns exactly the two, newest first, with correct files and counts; a rename shows `R`; `maxCount: 1` returns one.
