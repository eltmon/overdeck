# PAN-5281 — Commit attribution trailers for agents and conversations

**Issue:** https://github.com/eltmon/overdeck/issues/5281
**Context:** first backend slice of the file-management and change-review redesign (parent #5183). The operator approved the conversation **Changes** mockup on 2026-11-14 (`.tmp/conversation-changes-files-mockup.html`, not committed). That view lists "this conversation's commits", which needs exact attribution. This issue adds the attribution and a reader. The UI comes in a later issue.

## 1. Summary

Every `git commit` run by an Overdeck agent or conversation gets one trailer line naming who made it:

- a conversation: `Overdeck-Conversation: <conversation session name>` (for example `Overdeck-Conversation: conv-20261113-6031`);
- an agent: `Overdeck-Agent: <agent id>` (for example `Overdeck-Agent: agent-pan-5185`).

The trailer is added by the `git` shim that is already on the PATH of agents, and by a new git shim on the PATH of conversations. A new library function lists the commits a conversation or agent made in a repository, by reading those trailers.

## 2. Glossary

- **Trailer** — a `Key: value` line in the last paragraph of a commit message (git's term). Git adds one with `git commit --trailer "Key: value"` (git 2.32 or later; this machine has 2.43). When the message's last paragraph is already a trailer block (for example `Co-Authored-By: …`), git appends the new line to that block; otherwise it adds a blank line and a new block.
- **Git shim / guard** — the POSIX `sh` script named `git` that the launcher writes into `<OVERDECK_HOME>/agents/<agentId>/git-guard/` and puts first on the agent's PATH. It is generated by `buildGitGuardLines` in `src/lib/launcher-git-guard.ts` (search `export function buildGitGuardLines`). It finds the git subcommand with `_overdeck_git_find_command`, blocks some commands, and `exec`s the real git. The script is written through an **unquoted heredoc**, so every runtime `$` in the TypeScript source is written `\\$` (or written plain in a `*_SH` constant and escaped by a `.map(line => line.replace(/\$/g, '\\$'))` helper, as `BRANCH_CHECK_SH` / `branchCheckShimLines` do).
- **Conversation gh shim** — `buildConversationGhShimLines` in the same file (search `export function buildConversationGhShimLines`). It writes only a `gh` shim into `<OVERDECK_HOME>/conversations/<id>/git-guard/`. Conversations have no git shim today.
- **Conversation session name** — the value the conversation launcher exports as `OVERDECK_CONVERSATION` (`src/lib/overdeck/conversation-runtime.ts`, search `` `export OVERDECK_CONVERSATION=${JSON.stringify(tmuxSession)}` ``). The same value is passed as `ghShim.id` (search `ghShim: { id: tmuxSession`). It is also exported as `OVERDECK_AGENT_ID` for Herdr, Pi, Codex, ACP and supervisor conversations (search `agentId: tmuxSession`), so inside a conversation both variables can hold the same name.
- **Agent id** — the value exported as `OVERDECK_AGENT_ID` by agent launchers (`src/lib/launcher-generator.ts`, search `` `export OVERDECK_AGENT_ID=${shellQuote(config.overdeckEnv.agentId)}` ``). `buildGitGuardLines` receives the same value as its `agentId` argument (search `buildGitGuardLines(config.overdeckEnv.agentId`).
- **Bypass** — `OVERDECK_PAN_GIT_OP=1` makes the shim exec the real git unchanged (search `OVERDECK_PAN_GIT_OP` in `launcher-git-guard.ts`). Some `pan` git operations set it (`src/lib/rebase-helper.ts`, `src/lib/memory/facts/operator-sync.ts`).
- **Exit sites** — the places where the agent shim `exec`s the real git. For `commit` there are four, not one: the guard-root check (`_overdeck_git_target` outside `_OVERDECK_GUARD_ROOT`, search `'  *) exec "\\$_OVERDECK_REAL_GIT" "\\$@" ;;'` after `_overdeck_git_target=`), the `exec` inside `BRANCH_CHECK_SH` (search `'    exec "$_OVERDECK_REAL_GIT" "$@"'`), and in read-only mode the two `exec`s in `READ_ONLY_SHIM_SH` (search `exec "$_OVERDECK_REAL_GIT" "$@"' ` and `*) exec "$_OVERDECK_REAL_GIT" "$@" ;;`). A commit never reaches the final `exec` at the end of default mode.

## 3. Decisions

- **D-1 The shim adds the trailer; no git hook is used.** Projects own `core.hooksPath` (overdeck uses husky). An Overdeck hook would replace or race the project's hooks. The shim already sees every PATH-resolved `git` call of the agent, so it is the one place that works for every harness (Claude Code, Codex, Pi, Kimi, OpenCode, …) without touching the repository.
- **D-2 Trailer keys and values (revised in planning).** Conversation: `Overdeck-Conversation: <conversationId>`. Agent: `Overdeck-Agent: <agentId>`. The value is **written into the shim at launch** as a literal, from the `agentId` / `conversationId` argument the builder already receives, quoted with the existing `heredocShellQuote` helper. The shim does not read `OVERDECK_AGENT_ID` or `OVERDECK_CONVERSATION` at commit time. Reason: the `gh` shim already writes its id in at launch for the same robustness (search `const agentArg = heredocShellQuote`). An environment variable cleared or overwritten in a harness shell cannot change the attribution, and the "both variables set" case disappears: the agent shim always writes `Overdeck-Agent`, the conversation shim always writes `Overdeck-Conversation`. An agent launched from inside a conversation drops the conversation guard dir from PATH (`dropInheritedGuardDirLines`), so its commits carry only `Overdeck-Agent`.
- **D-3 Only `git commit`.** The shim adds the trailer only when the subcommand found by `_overdeck_git_find_command` is exactly `commit`. `merge`, `cherry-pick`, `revert`, `rebase` and `am` are not changed. A cherry-picked or rebased commit keeps whatever trailers its message already has. A conflicted merge that is concluded with `git commit` does get the trailer (the subcommand is `commit`); the reader excludes merge commits (D-9), so this has no effect on the reader.
- **D-4 Placement and de-duplication (revised in planning).** The shim inserts `--trailer "<Key>: <value>"` immediately after the `commit` token, keeping every other argument in order, including arguments after `--`. It also prepends the per-invocation option `-c trailer.<Key>.ifexists=addIfDifferent` to the argument list. Verified on git 2.43: git's default `addIfDifferentNeighbor` only skips a duplicate when the **last** trailer is identical, so `amend` after a different trailer (for example `Overdeck-Agent: a`, then `Overdeck-Conversation: c`, then an agent amend) writes `Overdeck-Agent: a` twice; with the per-invocation `-c` it does not. The `-c` is passed on the command line for that one call only. The executor must not write any `trailer.*` setting with `git config`.
- **D-5 Conversations get a git shim that only adds the trailer.** Conversations are operator sessions: the conversation git shim must not block `rebase`, `stash`, `reset --hard` or anything else, and must not run the branch check. It finds the subcommand, adds the trailer for `commit`, and `exec`s the real git. It lives in the same `<OVERDECK_HOME>/conversations/<id>/git-guard/` directory as the conversation `gh` shim, so the existing `dropInheritedGuardDirLines` prelude, `pan restart` PATH stripping (`src/cli/commands/restart.ts`, search `endsWith('/git-guard')`) and the systemd PATH filter (`src/lib/systemd-user-session.ts`, same search) already handle it. The shim is written only when `command -v git` resolves, the same way the `gh` shim is written only when `command -v gh` resolves.
- **D-6 The bypass also skips the trailer.** With `OVERDECK_PAN_GIT_OP=1` the shim execs the real git unchanged, as today. The bypass check stays the first statement of both shims.
- **D-7 Remote (Fly) agents are out of scope.** The remote launcher (`src/lib/remote/remote-agents.ts`, search `spawnMode: 'remote'`) passes no `overdeckEnv`, so `buildGitGuardLines` never runs for it. Nothing changes there.
- **D-8 Reader is a library function, not a route.** The Changes view issue will add the HTTP route. This issue adds `listAttributedCommits` and its tests only.
- **D-9 The reader excludes merge commits (added in planning).** `git log --no-merges`. A merge commit's diff against its first parent shows everything the merge brought in, not what the conversation wrote, so it would mislead the Changes view.
- **D-10 Git without `--trailer` falls back to no trailer (added in planning).** `git commit --trailer` needs git 2.32; the shim's existing `branch --show-current` needs only 2.22. On a host with git 2.22–2.31 an unconditional `--trailer` would make every agent commit fail. The launcher probes once at launch, in the bash prelude, with `case "$("$_OVERDECK_REAL_GIT" commit -h 2>&1)" in *--trailer*) _OVERDECK_GIT_TRAILERS=1 ;; esac` (verified: prints usage and exits 129 outside a repository; the `case` form survives `bash -e` and `pipefail`). The shim adds the trailer only when that baked flag is `1`.
- **D-11 Rename the conversation builder.** `buildConversationGhShimLines` becomes `buildConversationShimLines`, because it now writes two shims. The `LauncherConfig.ghShim` field keeps its name (renaming it is churn with no reader benefit).
- **D-12 Fixture commits are stamped too (accepted).** The agent shim adds the trailer to commits in any repository, including test fixtures in temp directories, exactly as PAN-3189 lets fixture commits through. A search of `*.test.ts` found no test that reads whole commit messages (`%B`, `%b`); the tests that read messages read `%s`. This is recorded as a hazard, not designed around.

## 4. Requirements

IDs FR-1…FR-6 and NFR-1, NFR-2 are kept from the original draft; their text was tightened in planning. FR-7, FR-8 and NFR-3 are new.

- **FR-1** A `git commit` run through an agent's git shim produces a commit whose message ends with the trailer `Overdeck-Agent: <agentId>`, where `<agentId>` is the `agentId` given to `buildGitGuardLines`. This holds in default mode inside the guarded worktree (through the branch check), in default mode outside it, and in read-only mode outside the guarded repository.
- **FR-2** A `git commit` run in a conversation produces a commit whose message ends with `Overdeck-Conversation: <conversationId>`, where `<conversationId>` is the id given to `buildConversationShimLines`.
- **FR-3** Every other git subcommand behaves exactly as before in the agent shim, including all existing refusals; every test in `src/lib/__tests__/launcher-git-guard-behavior.test.ts` passes unchanged. The conversation shim refuses nothing.
- **FR-4** Repeated `git commit --amend --no-edit` never adds a second copy of the same `Overdeck-*` trailer, including when a different trailer was added in between.
- **FR-5** With `OVERDECK_PAN_GIT_OP=1`, no trailer is added.
- **FR-6** `listAttributedCommits({ repoPath, key, value, since?, maxCount? })` returns the non-merge commits in `repoPath` reachable from `HEAD` whose trailer `key` has the value `value`, newest first, at most `maxCount` (default 200) **matching** commits, each as `{ sha, subject, authoredAt, files: { path, status, additions, deletions }[] }`. A repository without commits returns `[]`; an empty `value` returns `[]` without running git; a path that is not a git repository rejects.
- **FR-7** When the real git does not list `--trailer` in `git commit -h`, the shim adds no trailer and commits still succeed.
- **FR-8** Arguments are preserved: `-m` values with spaces, global options before the subcommand (`-C <dir>`, `-c k=v`, `--git-dir=…`), a `-C` directory literally named `commit`, and paths after `--` all reach the real git in their original order.
- **NFR-1** The reader uses async process execution only (`promisify(execFile)`). No `execSync` or other `*Sync` process call: it becomes reachable from the dashboard server in the follow-up issue.
- **NFR-2** Tests that touch git create temporary repositories; they never commit in the overdeck checkout.
- **NFR-3** Test results do not depend on whether the tests run inside an agent or conversation. Every spawned shell, shim and fixture git call gets an `env` built from `process.env` with: `PATH` filtered to drop every segment ending in `/git-guard` (`process.env.PATH.split(':').filter((s) => !s.endsWith('/git-guard')).join(':')`, the same filter as `src/cli/commands/restart.ts`), so "real git" is never the running agent's own shim; `OVERDECK_AGENT_ID` and `OVERDECK_CONVERSATION` deleted; `OVERDECK_PAN_GIT_OP` set explicitly (`'1'` for fixture setup, `''` when exercising a shim); and fixed `GIT_AUTHOR_NAME/EMAIL` and `GIT_COMMITTER_NAME/EMAIL` (same pattern as the `const env = {` block in the `branch check (PAN-4337)` describe of `launcher-git-guard-behavior.test.ts`). A fake git used by a test execs the real git by the absolute path resolved with `command -v git` under that filtered PATH.

   ```ts

    * PAN-5281: add `--trailer "<key>: <value>"` right after the `commit`
    * subcommand, and prepend `-c trailer.<key>.ifexists=addIfDifferent` so an
    * amend never duplicates it. The option walk mirrors
    * `_overdeck_git_find_command`. POSIX sh has no arrays, so the arguments are
    * rotated through `set --`: each one is shifted off the front and appended
    * to the back, and the trailer is appended right after the subcommand.
    * Inline on purpose: `set --` inside a function cannot change the script's
    * `"$@"`. Every `$` is a runtime expansion, escaped by `trailerShimLines`.
    */
   const TRAILER_SH = [
     'if [ "$_overdeck_git_command" = "commit" ] && [ "$_OVERDECK_GIT_TRAILERS" = "1" ]; then',
     '  _ot_n=$#',
     '  _ot_state=opts',
     '  while [ "$_ot_n" -gt 0 ]; do',
     '    _ot_arg="$1"',
     '    shift',
     '    _ot_n=$((_ot_n - 1))',
     '    set -- "$@" "$_ot_arg"',
     '    case "$_ot_state" in',
     '      value) _ot_state=opts ;;',
     '      opts)',
     '        case "$_ot_arg" in',
     '          -C|-c|--git-dir|--work-tree|--namespace|--config-env|--super-prefix|--attr-source) _ot_state=value ;;',
     '          --) _ot_state=cmd ;;',
     '          -*) ;;',
     '          *) set -- "$@" --trailer "$_OVERDECK_TRAILER_KEY: $_OVERDECK_TRAILER_VALUE"; _ot_state=done ;;',
     '        esac',
     '        ;;',
     '      cmd) set -- "$@" --trailer "$_OVERDECK_TRAILER_KEY: $_OVERDECK_TRAILER_VALUE"; _ot_state=done ;;',
     '    esac',
     '  done',
     '  set -- -c "trailer.$_OVERDECK_TRAILER_KEY.ifexists=addIfDifferent" "$@"',
     'fi',
   ];

   /** The trailer rewrite with its key and value baked in, escaped for the unquoted heredoc. */
   function trailerShimLines(key: 'Overdeck-Agent' | 'Overdeck-Conversation', value: string): string[] {
     return [
       `_OVERDECK_TRAILER_KEY=${key}`,
       `_OVERDECK_TRAILER_VALUE=${heredocShellQuote(value)}`,
       ...TRAILER_SH.map((line) => line.replace(/\$/g, '\\$')),
     ];
   }
   ```

### WI-3 — Reader: `listAttributedCommits` (FR-6, NFR-1, NFR-2, NFR-3)

New file: `src/lib/git/attributed-commits.ts`. Imports only `node:child_process` and `node:util` (no other `src/lib` module, so no import cycle). Do not use `src/lib/git/operations.ts`: its helpers write `git_operations` database rows and only cover push/fetch/rev-parse.

```ts
export type AttributionKey = 'Overdeck-Conversation' | 'Overdeck-Agent';
export interface AttributedCommitFile { path: string; status: 'A' | 'M' | 'D' | 'R'; additions: number; deletions: number }
export interface AttributedCommit { sha: string; subject: string; authoredAt: string; files: AttributedCommitFile[] }
export async function listAttributedCommits(opts: {
  repoPath: string; key: AttributionKey; value: string; since?: string; maxCount?: number;
}): Promise<AttributedCommit[]>
```

1. `const execFileAsync = promisify(execFile);` and a local `git(args)` helper that runs `execFileAsync('git', ['-C', repoPath, '-c', 'log.showSignature=false', ...args], { encoding: 'utf8', maxBuffer: 16 * 1024 * 1024 })`. The `-c` keeps a user's global `log.showSignature=true` from injecting GPG lines into the parsed output.
2. If `opts.value.trim() === ''`, return `[]`. Then `git rev-parse --verify --quiet HEAD`; if it rejects, run `git rev-parse --git-dir`: when that also rejects, rethrow (not a repository); otherwise return `[]` (a repository with no commits).
3. List the candidates **filtered by git**, then cap in JS, so `maxCount` counts confirmed matches (verified on git 2.43):
   `git log HEAD --no-merges --no-color -E --grep=^<escKey>:[[:space:]]*<escValue>[[:space:]]*$ [--since=<since>] --format=%H%x1f%s%x1f%aI%x1f%(trailers:key=<key>,valueonly,separator=%x1d)`
   with **no `--max-count`**: git applies `--max-count` after `--grep` but before the trailer check below, so a newer commit that matches only through a body line would take the only slot and `maxCount: 1` would return `[]` (reproduced in planning). The output is one short line per grep match, so it stays small. `esc` escapes ERE metacharacters with `value.replace(/[\\^$.*+?()[\]{}|]/g, '\\$&')` (the same expression as `escapeRegExp` in `src/lib/xbrief/continue-state.ts`; copy it, it is not exported). Split stdout on `\n`, drop empty lines, split each on `\x1f` into `sha, subject, authoredAt, trailers`. Keep a line only when `trailers.split('\x1d').map((v) => v.trim())` includes `opts.value` (the grep also matches a `Key: value` line outside the final trailer paragraph). Keep git's order (newest first), then take the first `maxCount ?? 200` kept lines.
4. For each sha in that slice (and only those), sequentially, run two calls (verified formats on git 2.43):
   - `git diff-tree --root -r -M -z --no-commit-id --numstat <sha>` → NUL-separated. A normal entry is one field `"<add>\t<del>\t<path>"`. A rename is `"<add>\t<del>\t"` (empty path) followed by two fields `<old>`, `<new>`; key it by `<new>`. Binary files print `-` for both counts: record `0` and `0`.
   - `git diff-tree --root -r -M -z --no-commit-id --name-status <sha>` → NUL-separated pairs `<status>`, `<path>`; a status starting with `R` (for example `R075`) is followed by `<old>`, `<new>`; use `<new>`.
   Status mapping: `A`→`A`, `D`→`D`, `R…`→`R`, every other letter (`M`, `T`, …)→`M`. Build `files` in name-status order, joining counts by path (missing counts → 0). `--root` makes a root commit list its files as `A`.
5. Add a module header comment: what the trailers are, that the shim writes them (PAN-5281), that merges are excluded (D-9), and that the reader is async-only because the dashboard server will call it.

Tests (`src/lib/git/__tests__/attributed-commits.test.ts`, NFR-3: every fixture git call uses `OVERDECK_PAN_GIT_OP=1` and fixed `GIT_AUTHOR_*`/`GIT_COMMITTER_*`; trailers are written with real `git commit --trailer`):
- A temp repo with, oldest to newest: (1) a root commit adding `a.txt` with `Overdeck-Conversation: conv-a`; (2) a commit with no trailer; (3) a commit with `Overdeck-Conversation: conv-b`; (4) a commit that renames `a.txt` to `b.txt`, edits it and adds a binary file, with `Overdeck-Conversation: conv-a`; (5) a commit whose **body** (not its last paragraph) contains `Overdeck-Conversation: conv-a` and whose last paragraph is `Signed-off-by: x`.
- `returns only the matching commits, newest first` — `conv-a` returns exactly commits 4 and 1 in that order (commit 5 is excluded by the trailer check).
- `reports renames, counts and binary files` — commit 4's files contain `{ path: 'b.txt', status: 'R' }` with the right additions/deletions, and the binary file with `status: 'A', additions: 0, deletions: 0`; commit 1's files are `[{ path: 'a.txt', status: 'A', … }]`.
- `maxCount counts confirmed matches` — `maxCount: 1` returns exactly commit 4, even though the newer commit 5 matches the grep through its body.
- `excludes merge commits` — a `--no-ff` merge whose message carries `Overdeck-Conversation: conv-a` is not returned.
- `returns [] for an empty repository and for an empty value`, and `rejects for a path that is not a repository`.
