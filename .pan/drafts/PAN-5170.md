# PAN-5170: darwin — skip Linux-only systemctl/journalctl checks (supervisor unit status, OOM canary)

**Issue:** https://github.com/eltmon/overdeck/issues/5170
**Related:** [PAN-5168](https://github.com/eltmon/overdeck/issues/5168) (shared host-tool lookup module, in parallel)

## Glossary

- **darwin** — Node's `process.platform` value on macOS.
- **Failed spawn** — a `child_process` call for a binary that is not on PATH. On darwin, libuv tries
  `posix_spawn` once per PATH entry, and XNU creates one short-lived `node` process per try, so one
  failed spawn leaves about ten dead processes (PAN-5168 measured 42 dead processes for five `docker`
  spawns).
- **Supervisor** — the sidecar `dist/supervisor/server.js` that watches the dashboard and serves
  `POST /restart-dashboard` (Force Restart). On Linux with a usable systemd user manager it runs as
  `overdeck-supervisor.service`. On darwin it runs as the launchd agent `ai.overdeck.supervisor`
  (after `pan connect`) or as a plain detached process that `startSupervisorProcess()` starts and
  records in `~/.overdeck/supervisor.pid`.
- **Unit-failed check** — `isSupervisorUnitFailed()` in `src/lib/systemd.ts`, which runs
  `systemctl --user is-failed overdeck-supervisor.service`. "failed" means systemd hit the unit's
  restart limit (`StartLimitBurst=3`) and stopped restarting the supervisor.
- **Restart announcer** — `src/dashboard/server/services/restart-announcer.ts`. It polls every 1 s for
  the first 30 passes after boot, then every 15 s, and turns new `restart-status.json` entries into
  activity-feed rows. Each pass first runs `syncSupervisorUnitFailureStatus`, which calls the
  unit-failed check.
- **OOM canary** — `readNewKernelJournal()` in `src/lib/cloister/memory-pressure-patrol.ts`. It runs
  `journalctl -k --cursor-file ~/.overdeck/oom-canary.cursor --no-pager -o cat` on every 15 s
  memory-pressure patrol pass (deacon child) and parses kernel OOM-kill lines.
- **Supervisor reachability check** — the new darwin replacement for the unit-failed check: an HTTP
  `GET /health` to the supervisor port. It starts no child process.
- **Down window** — the time the supervisor must stay unreachable, after this dashboard process has
  seen it answer once, before the announcer reports it down: 60 000 ms (`SUPERVISOR_DOWN_WINDOW_MS`).

## Problem

Two Linux-only checks run on darwin, where `systemctl` and `journalctl` do not exist:

1. The restart announcer calls the unit-failed check on every pass: 30 times in the first 30 s after
   boot, then every 15 s. Each call is a failed spawn, so about ten dead processes per call.
   `src/lib/systemd.ts` lines 201-208:

   ```ts
   export async function isSupervisorUnitFailed(): Promise<boolean> {
     try {
       const { stdout } = await systemctl(`is-failed ${SUPERVISOR_UNIT_NAME}`);
       return stdout.trim() === 'failed';
     } catch {
       return false;
     }
   }
   ```

   The caller is `restart-announcer.ts` line 184-185
   (`const readSupervisorUnitFailed = deps.readSupervisorUnitFailed ?? (() => isSupervisorUnitFailed());`)
   and line 193 (`await syncSupervisorUnitFailureStatus({ readStatus, writeStatus, readSupervisorUnitFailed, now });`).

2. The OOM canary spawns `journalctl` once at boot. On darwin it fails with ENOENT, and the catch
   block (`memory-pressure-patrol.ts` line 215) writes the whole error object to the log:

   ```ts
   } catch (err) {
     console.warn('[memory-pressure-patrol] Journal reader failed, disabling OOM canary:', err);
     oomCanaryDisabled = true;
     return '';
   }
   ```

Every other `systemctl` caller of the supervisor unit (`startSupervisorUnitIfAvailable`,
`stopSupervisorUnitIfActive`, `shouldRunManualSupervisorCycle` in `src/cli/commands/restart.ts`) is
already behind `systemdUserAvailable()`, whose first check is `process.platform !== 'linux'`
(`src/lib/systemd.ts` line 234). `spawnDashboardSystemdUnit` in `src/cli/commands/restart.ts` already
returns early off Linux. So the two sites above are the only pollers left.

## Decisions

- **D1 — Guard by platform only.** Each Linux-only check gets a `process.platform !== 'linux'` early
  return at the top of the function, before any `stat`, spawn or log. "Is systemd present on this
  Linux host" is not checked here: on Linux a failed spawn costs one process, and PAN-5168 owns host-tool
  lookup. Do not add a tool cache (issue comment: "Do not add a second tool cache").
- **D2 — Do not use `systemdUserAvailable()` in the announcer.** It runs `systemctl --user --version`
  and `systemctl --user is-system-running`, which would add two spawns per pass on Linux.
- **D3 — Linux behavior stays exactly as today.** The unit-failed check, `restart-status.json` write,
  and "GAVE UP" activity row are unchanged on Linux.
- **D4 — On darwin (every non-Linux platform), report the supervisor from its liveness, not its
  pidfile.** Only `startSupervisorProcess()` writes `supervisor.pid`; a launchd-run supervisor has no
  pidfile, so a pidfile check would report a healthy launchd supervisor dead forever. The liveness
  signal is `GET <getSupervisorUrl()>/health` (served by `src/supervisor/server.ts`, returns
  `{ ok: true, port }`), with a 2 000 ms timeout. It starts no child process and no `launchctl` call.
- **D5 — "Not answering" is not "failed".** A dashboard started with plain `node
  dist/dashboard/server.js` has no supervisor; `pan reload` and `pan restart` cycle the supervisor;
  launchd restarts a crashed agent after `THROTTLE_INTERVAL_SEC = 5` (`src/lib/launchd.ts` line 21).
  So the announcer reports the supervisor down only when **both** hold:
  1. This dashboard process has seen `/health` answer at least once since the announcer started.
  2. Every probe since the first failed probe has failed, and at least `SUPERVISOR_DOWN_WINDOW_MS =
     60_000` ms have passed (measured with the announcer's `now()` dep, because the poll cadence
     switches between 1 s and 15 s).
  It reports once per down episode. A successful probe ends the episode and clears the timer.
- **D6 — Darwin emits an activity row directly and writes no `restart-status.json`.** The systemd text
  (`buildSupervisorUnitFailureStatus`: `attempts: 3`, "systemd restart limit") and the `describeRestart`
  "GAVE UP … after 3 attempt(s)" message are wrong for darwin. The darwin row is:
  - `source: 'supervisor'`, `level: 'error'`, `desktop: false`
  - `message`: `` `The supervisor at ${url} has not answered for ${seconds} s. Force Restart and the dashboard watchdog do not work until it runs again. Run \`pan up\` to start it.` `` where `url` is the supervisor base URL and `seconds` is the whole seconds since the first failed probe.
  No recovery row is emitted (NonGoal).
- **D7 — The canary logs one line.** On non-Linux it returns `''` with no log and no `stat`. On Linux,
  a failure logs exactly one string: `` `[memory-pressure-patrol] OOM canary disabled: journalctl failed (${code ?? message})` `` where `code` is the error's `code` property (for example `ENOENT`) and `message` is its message. No error object is passed to the logger.
- **D8 — `findManagedServerPid` (`src/lib/tmux.ts` line 156) is out of scope.** It also calls
  `systemctl` unguarded, but only on conversation stop and tmux founder warnings, not in a poller, and the
  issue comment limits this change to the two named checks.
- **D9 — The reachability rule is a pure tracker in its own module**
  (`src/dashboard/server/services/supervisor-reachability.ts`), so it is tested with explicit
  timestamps and needs no fake timers.

## Requirements

- **FR-1** On a non-Linux platform, `isSupervisorUnitFailed()` resolves `false` and starts no child process.
- **FR-2** On Linux, `isSupervisorUnitFailed()` behaves as today (`systemctl --user is-failed …`).
- **FR-3** On a non-Linux platform, a restart-announcer pass starts no child process and does not call the unit-failed check.
- **FR-4** On a non-Linux platform, the announcer emits one supervisor-down activity row (D6) when the D5 rule holds, and no row otherwise.
- **FR-5** On Linux, the announcer's unit-failed behavior (restart-status write, GAVE UP row) is unchanged.
- **FR-6** On a non-Linux platform, the OOM canary returns `''` without spawning `journalctl`, stat-ing the cursor file, or logging.
- **FR-7** On Linux, an OOM canary failure logs exactly one string line (D7) and disables the canary.
- **FR-8** The docs and the changelog describe the macOS behavior of both checks.
- **NFR-1** Zero child processes per announcer pass and per patrol pass on darwin.
- **NFR-2** No new tool cache or host-tool lookup (PAN-5168 owns that).
- **NFR-3** No sync child-process calls and no new `*Sync` calls in dashboard-server-reachable code. One exception is allowed: the existing `getSupervisorUrl()` (a small synchronous `config.toml` read) runs once per process, memoized, for the macOS probe URL.

### WI-2 — Pure supervisor reachability tracker (`supervisor-reachability-tracker`) — FR-4

New file: `src/dashboard/server/services/supervisor-reachability.ts`.

```ts
/**
 * PAN-5170: the darwin replacement for the systemd unit-failed check. Decides,
 * from successive /health probe results, when the supervisor counts as down.
 * Pure: the caller passes the clock. See docs/ANYWHERE-ARCHITECTURE.md D-10.
 */
export const SUPERVISOR_DOWN_WINDOW_MS = 60_000;

export interface SupervisorDownReport {
  /** Milliseconds since the first failed probe of this episode. */
  unreachableForMs: number;
}

export interface SupervisorReachabilityTracker {
  /** Record one probe. Returns a report exactly once per down episode, else null. */
  observe(answered: boolean, nowMs: number): SupervisorDownReport | null;
}

export function createSupervisorReachabilityTracker(
  windowMs: number = SUPERVISOR_DOWN_WINDOW_MS,
): SupervisorReachabilityTracker {
  let seenAlive = false;
  let unreachableSince: number | null = null;
  let reported = false;
  return {
    observe(answered, nowMs) {
      if (answered) {
        seenAlive = true;
        unreachableSince = null;
        reported = false;
        return null;
      }
      if (!seenAlive) return null;
      unreachableSince ??= nowMs;
      const unreachableForMs = nowMs - unreachableSince;
      if (reported || unreachableForMs < windowMs) return null;
      reported = true;
      return { unreachableForMs };
    },
  };
}
```

Test: new `src/dashboard/server/services/__tests__/supervisor-reachability.test.ts` with these cases:

2. Answered at t=0, failed at t=1 000 and t=59 999 → `null`; failed at t=61 000 → `{ unreachableForMs: 60_000 }`; failed at t=120 000 → `null` (once per episode).

### WI-4 — Skip the OOM canary off Linux and log one line (`oom-canary-platform-guard`) — FR-6, FR-7, NFR-1

```ts
export interface KernelJournalDeps {
  platform: NodeJS.Platform;
  /** Runs journalctl with these args and resolves its stdout. */
  runJournalctl: (args: string[]) => Promise<string>;
  warn: (line: string) => void;
}

/**
 * WI-4: Read new kernel journal entries via journalctl with cursor-file persistence.
 * On first call (cursor file absent), uses -n 0 to initialize and returns empty string.
 * Linux only (PAN-5170): macOS has no kernel journal and no journalctl, so off Linux
 * this returns '' without a stat, a spawn or a log line.
 * On ANY error, logs one line and disables the canary permanently.
 */
export async function readNewKernelJournal(deps: Partial<KernelJournalDeps> = {}): Promise<string> {
  const platform = deps.platform ?? process.platform;
  if (platform !== 'linux') return '';
  if (oomCanaryDisabled) return '';
  const warn = deps.warn ?? ((line: string) => console.warn(line));
  const runJournalctl = deps.runJournalctl ?? (async (args: string[]) =>
    (await promisify(execFile)('journalctl', args, { timeout: 10000 })).stdout);
  try {
    // … existing cursor-file logic unchanged, then:
    return await runJournalctl(args);
  } catch (err) {
    const { code, message } = err as { code?: unknown; message?: unknown };
    warn(`[memory-pressure-patrol] OOM canary disabled: journalctl failed (${String(code ?? message ?? err)})`);
    oomCanaryDisabled = true;
    return '';
  }
}
```
