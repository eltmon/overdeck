## Glossary

| Term | Meaning |
| --- | --- |
| **Deacon** | The Cloister supervisor process. Runs a 60s patrol loop (`startDeacon()` at `src/lib/cloister/deacon.ts:3513`, `setInterval` at `:3537`, `patrolIntervalMs = 60_000` at `:214`) plus reactive event handlers (`handleCloisterDomainEventPromise`, `src/lib/cloister/service.ts:440`). |
| **Patrol reconciler** | One of the ~50 checks inside `runPatrol()` (`deacon.ts:2713`) that derives desired state from durable records and re-drives a missing step. Patrols are "thin safety nets for dropped events" (PAN-1908). |
| **Pipeline obligation** | A step the pipeline owes an in-flight issue: dispatch review, dispatch re-review, dispatch test, start work agent after planning, requeue a swarm slot, merge, close out, clear a stale label. |
| **Re-drive** | Idempotently performing an obligation that a dropped event or hung call left undone. |
| **Derive** | Computing what obligation is owed from durable state (review-status DB, per-issue records, GitHub PR/issue truth, vBRIEF specs) — never from remembered in-process state. |
| **Gate** | A flag that blocks autonomous re-drive of an agent: `paused` (operator/scheduler hold), `stoppedByUser` (deliberate user stop), `troubled` (circuit-breaker output). Schema: `src/lib/agents/agent-state.ts:51` (`stoppedByUser`), `:53` (`paused`), `:73-74` (`troubled`/`troubledAt`). |
| **Circuit breaker** | A bounded retry counter (e.g. the 25-requeue breaker in `checkDeadEndAgents`, `deacon.ts:1920`) that converts a loop into a one-time needs-you escalation. |
| **needs-you** | The operator-attention surface (dashboard Needs-you lane + notification). The terminal state of every tripped breaker — never silent. |
| **Admission gate** | The memory governor (`assessMemoryPressure()`, `src/lib/cloister/memory-governor.ts:116`) plus concurrency ceiling that every autonomous spawn/resume must pass (PAN-2500/PAN-2507). |
| **runId idempotency guard** | The dispatch-dedup check in `spawnReviewRoleForIssuePromise` (`src/lib/cloister/review-agent.ts:432-489`): a review session tagged `agent-<issue>-review-<head8>` is stale if its persisted `reviewRunId` mismatches the current HEAD. |
| **Read model** | The dashboard's in-memory/SQLite view of issue state (labels, stages), rebuildable from GitHub + git records. |

## Background & motivation

On 2026-07-08/09 the pipeline stalled repeatedly with **agents alive and main green** — every stall traced to the same architectural gap: pipeline advancement depends on **one-shot event triggers and blocking signal calls**, and when a trigger is dropped or a call hangs, either no patrol re-derives the obligation, or the patrol that exists is blocked by an inconsistently-checked gate. Fourteen open issues are individual edges of this one gap:

1. **Gate inconsistency** — `checkDeadEndAgents` checks `paused` (`deacon.ts:1966-1969`) but not `stoppedByUser`, so a user-stopped review-failed agent loops rebuild-and-start forever ([PAN-2536](https://github.com/eltmon/overdeck/issues/2536)); the boot-reconciliation empty-candidate race terminally commits `resume_all` before crashed agents are even marked stopped ([PAN-2502](https://github.com/eltmon/overdeck/issues/2502)).
2. **Signal fragility** — the review-verdict signal can hang after printing success, and nothing reconciles `review.approved` afterward ([PAN-2524](https://github.com/eltmon/overdeck/issues/2524)); `pan specialists done` hung on an unbounded comment POST ([PAN-2518](https://github.com/eltmon/overdeck/issues/2518), now partially bounded); `pan admin db restore-verdicts` hangs after finishing its work ([PAN-2475](https://github.com/eltmon/overdeck/issues/2475)).
3. **Dispatch gaps** — re-review silently no-ops while a finished reviewer lingers idle-alive ([PAN-2534](https://github.com/eltmon/overdeck/issues/2534)); auto-plan finalizes but the work agent never starts ([PAN-2522](https://github.com/eltmon/overdeck/issues/2522)); stack-unhealthy defers respawn forever ([PAN-2520](https://github.com/eltmon/overdeck/issues/2520)); failed swarm WORK slots are logged and dropped, never requeued ([PAN-2498](https://github.com/eltmon/overdeck/issues/2498), [PAN-2485](https://github.com/eltmon/overdeck/issues/2485)).
4. **Wedge blindness** — liveness = "tmux session exists ∧ pane not dead", so modal-blocked agents look idle-alive: codex's rate-limit dialog wedged three agents for hours and its default silently downgraded them to gpt-5.4-mini ([PAN-2486](https://github.com/eltmon/overdeck/issues/2486)); wedged rework agents were parked as `troubled` instead of killed for respawn ([PAN-2519](https://github.com/eltmon/overdeck/issues/2519) — partially landed, see WI-9).
5. **Missing reconcilers** — no patrol reconciles pipeline labels or the read model against durable/terminal truth: ~90 issues wear stale `verifying-on-main`/`planning` labels ([PAN-2537](https://github.com/eltmon/overdeck/issues/2537)); 729 agent rows accumulate because terminal detection is broken and gc is manual-only ([PAN-2503](https://github.com/eltmon/overdeck/issues/2503)).

**This epic is NOT a new engine.** The deacon already implements derive-and-re-drive ~50 times (see the patrol inventory in `runPatrol`, `deacon.ts:2713-3321`). The epic completes the net: one shared gate predicate applied everywhere, bounded-and-exiting signal paths, the missing re-drive branches, wedge-aware liveness, the two absent reconcilers, and deterministic (never `Math.random()`) recovery cadence.

## Decisions (made here — do not re-litigate downstream)

| # | Decision | Rationale |
| --- | --- | --- |
| D1 | **One gate predicate.** Every autonomous spawn/resume/rebuild path consults a single shared function (extend `getAgentResumeGateBlockReason`, `src/lib/agents/agent-state.ts:679`) covering `paused`, `troubled`, AND `stoppedByUser`. No path hand-rolls its own subset. | Gate inconsistency is the root of PAN-2536: `checkDeadEndAgents` checks `paused` only. A single predicate makes the next gate impossible to forget. |
| D2 | **`stoppedByUser` semantics:** blocks all *autonomous* re-drive of that issue's work agent; any *explicit operator action* (`pan start`, dashboard Rebuild & Start, `pan swarm recover`) **clears the flag** (pattern already exists: `src/lib/cloister/concurrency.ts:325-330`). When an autonomous path skips on `stoppedByUser` it surfaces needs-you **once** (deduped per issue), never loops. | The operator's stop must stick against automation but their next explicit start must not "appear to fail" (the PAN-2536 incident). |
| D3 | **Every breaker trips to needs-you.** No recovery path may be silent-terminal: when a circuit breaker opens (25-requeue, N-failed-redispatch, rebuild-fails-repeatedly), the issue gets a needs-you entry naming the breaker and the last error. | PAN-2498's swarm sat dead for a day invisibly; silence is the failure mode. |
| D4 | **Signal paths are durable-first, bounded, and exiting.** Every `pan` CLI verb that records a verdict/completion writes durable state FIRST, wraps every subsequent network/exec call in a bounded timeout (`AbortController` / `execAsync` `timeout` + `killSignal`, patterns at `src/cli/commands/done.ts:952` and `src/lib/review-verdict-feedback.ts:93`), treats post-durable failures as non-fatal warnings, and **guarantees `process.exit`** (explicit exit after flush; no open handles keeping the loop alive). | PAN-2524/2518/2475 are one family: work done, process never returns, agent waits forever. |
| D5 | **Stale-reviewer rule:** an idle-alive review session whose persisted `reviewRunId` is absent OR mismatches the current HEAD runId is **stale → kill & respawn** on a re-review request. This inverts the conservative skip at `review-agent.ts:459-462` ("If it carries no runId at all … keep the 'skip' behaviour"). | The conservative branch is exactly PAN-2534. A finished reviewer that never terminates (comment at `review-agent.ts:437-442`) must not block re-review. Verdict artifacts are already durable before idling, so killing loses nothing. |
| D6 | **Deterministic cadence.** Correctness-critical recovery sweeps run on a fixed cycle-modulo, never `Math.random()` gates. Today `cleanupStaleAgentState` and `cleanupAbandonedFeedback` fire at `Math.random()<0.003` (`deacon.ts:3196`, `:3205`) and `cleanupOrphanReviewerSessions` at `<0.01` (`:3214`) — i.e. roughly once per 5.5 hours *in expectation*, unbounded in the tail. | A dropped verdict-feedback file must be recovered within a bounded number of patrols, not "eventually with probability 1". |
| D7 | **Wedge detection is pane-content-aware.** Liveness gains a third signal beyond session-exists and pane-dead: known-modal pattern match on captured pane content (the codex rate-limit dialog first; the detector is a table of patterns → actions so future modals are additions, not new machinery). Same family as the existing AUQ/consent detection. | PAN-2486/2519: "alive" without "responsive" is the blind spot. |
| D8 | **Harness dialogs never make model decisions.** The codex rate-limit dialog is auto-answered "Keep current model"; the underlying rate limit surfaces as the existing usage-limit halt class (pause + needs-you + auto-resume at window reset). If codex config supports disabling the reminder at spawn, that is done too (belt and suspenders). A recorded-vs-live model divergence check flags silent downgrades. | No-hardcoded-model-fallback rule: model choice belongs to Cloister config, never a TUI default. |
| D9 | **Label reconciliation derives from records + GitHub, repairs labels — not vice versa.** The patrol treats the per-issue permanent record (`pipeline` block) and GitHub issue/PR state as truth; pipeline labels (`verifying-on-main`, `planning`, `in-progress`, `in-review`) on issues whose truth is terminal (merged/closed/completed) are removed. Read-model rows that contradict GitHub are re-derived. Dry-run mode first; the initial ~90-issue sweep runs once with a log of every change. | Two-door tenet: labels are a projection, records are canonical. |
| D10 | **Agents-table terminal detection keys off the permanent record, not `review_status`.** `pan admin db gc-agents` currently filters on `isTerminalIssueStage(getIssueStageSync(...))` which returns non-terminal forever because close-out prunes `review_status` (PAN-2503 root cause). Terminal = issue record `closeOut`/`pipeline` terminal OR GitHub issue closed. gc covers ALL roles (work/plan/review/test/strike), runs scheduled (deacon patrol, cycle-modulo), stopped-rows-only, with `--dry-run` preserved. | The runtime plane is rebuildable by design (PAN-1908); pruning terminal rows is safe and shrinks every hot patrol. |
| D11 | **Boot reconciliation waits for liveness truth.** On an empty candidate snapshot, `startBootReconciliation()` opens the grace window in `pending` instead of terminally committing `resume_all`; candidates arriving from `reconcileAgentLiveness` (which runs ~1s later in the deacon child) join the pending set; the window closes on decision or timeout. | PAN-2502: the empty→`resume_all` fast path races the liveness reconcile on full reboots and ungates the exact post-reboot flood the dialog exists to prevent. |
| D12 | **Every new re-drive passes the admission gate.** Any respawn/resume/dispatch added by this epic calls through `assessMemoryPressure()` / the concurrency ceiling exactly as `deacon-auto-resume.ts` and `concurrency.ts` do, and honors the preemptive scheduler's `paused` (PAN-2507). Read the cached verdict (`memory-verdict-cache.ts`) — don't re-poll. | The reconciler must not fight the resource governor (PAN-2500) or the preemptive scheduler. |
| D13 | **Swarm failed-slot requeue reuses wave dispatch.** A slot classified `failed` (`missing-agent` `deacon-swarm.ts:383`, `vanished-session` `:398`, `pane-exit-nonzero`/`unknown` `:455-460`) with no FailedMergeBlock is requeueable: clear the slot assignment, reset the item to dispatchable, let `dispatchNextWave` (`:723`) fill it — subject to a per-item redispatch breaker (D3). `pan swarm recover --action retry` gains the same path for manual use. `gcMergedSlots` reaps merged+idle slots promptly so capacity frees. | PAN-2498/2485: `failed` is currently a terminal classification with no consumer (`coordinateSwarmSlots` `:335-346` only acts on `stalled` and `ready-to-merge`). |

## Requirements

### Functional

- **FR-1** All autonomous spawn/resume/rebuild paths (dead-end respawn, orphan-proposed reconciler, rebuild-and-start, auto-resume, swarm requeue, boot recovery) consult the single shared gate predicate (D1) and respect `stoppedByUser` per D2.
- **FR-2** Explicit operator start actions clear `stoppedByUser`; the dashboard Rebuild & Start and `pan start` succeed on a user-stopped agent without `--force` gymnastics.
- **FR-3** Every tripped circuit breaker produces exactly one needs-you entry per issue per trip (D3); no recovery loop runs more than its bounded attempts. *(Trace accounting: FR-3 is realized in WI-1, WI-7, WI-8, and WI-9 — plan items for all four must carry it in `metadata.traces`, not WI-1 alone.)*
- **FR-4** The review-verdict signal path and every specialist-completion CLI verb is durable-first, bounded, and exiting (D4); a hung/failed post-durable call is recovered by a deterministic patrol within 2 patrol cycles.
- **FR-5** `pan review request` on an issue with rework committed dispatches a fresh review within one patrol cycle even when the prior review session lingers idle-alive (D5).
- **FR-6** After `complete-planning` finalizes with auto-start requested, a work agent spawns within one patrol cycle; a dropped finalize→spawn handoff is re-derived from the proposed spec + auto-start stamp (not from the lost event).
- **FR-7** A respawn deferred on `stack-unhealthy` triggers rebuild-and-start automatically under its existing breaker/cooldown ([PAN-2520](https://github.com/eltmon/overdeck/issues/2520)'s spec).
- **FR-8** Failed swarm WORK slots requeue automatically per D13; `pan swarm recover --action retry` covers non-merge failures; merged idle slots are reaped promptly; N-failures escalate to needs-you.
- **FR-9** A wedged-but-alive work agent owing rework is killed for respawn (not parked) under the requeue ceiling; known harness modals are detected and answered per D7/D8; recorded-vs-live model divergence is flagged.
- **FR-10** A label-reconciliation patrol removes stale in-flight pipeline labels from terminal issues and repairs read-model drift against GitHub (D9), with dry-run support and per-change logging.
- **FR-11** Terminal agent rows are detected via the permanent record (D10) and pruned on a scheduled cadence across all roles; `listAllAgentsSync()` row count stays bounded to in-flight issues plus a small tail.
- **FR-12** Boot reconciliation on a full reboot presents the operator dialog (or holds pending) instead of terminally committing `resume_all` on an empty racing snapshot (D11).
- **FR-13** All recovery sweeps currently gated on `Math.random()` run on deterministic cycle-modulo cadence (D6).
- **FR-14** The GitHub label/comment calls on the `pan done` path (`done.ts:190`, `:205`, `:212` — currently unbounded `fetch`) and the remaining unbounded exec sites on dispatch paths (`review-agent.ts:453`, `:574`; `deacon.ts:3254`) gain bounded timeouts using the existing wrapper patterns.
- **FR-15** `pan admin db restore-verdicts` completes and exits on real runs (root-cause the hang — likely an open handle after work completes — under D4's exit discipline).

### Non-functional

- **NFR-1** The whole epic ships as one issue — no partial delivery (operator direction; phases below are organizational).
- **NFR-2** Every retry/backoff/delay test uses `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` — never real timers (repo rule).
- **NFR-3** No `execSync` in server-reachable code; async `execFile`/`spawn`/`execAsync` only; tmux via `sendKeysAsync` (repo rules).
- **NFR-4** New patrol work must not measurably extend the 60s patrol budget: expensive sweeps (labels, gc) run on cycle-modulo cadence and are single-flighted alongside `deaconPatrolGuard` (`deacon.ts:3351`).
- **NFR-5** Every behavior change lands with a regression test named in its work item; the pre-existing in-flight-guard test (`tests/unit/lib/cloister/in-flight-guard.test.ts`) and postMergeLifecycle idempotency stay green.

## Design

The epic is four completions of the existing net plus two new reconcilers:

1. **Gates** (WI-1, WI-2): one predicate, consistent semantics, boot race fixed.
2. **Signals** (WI-3, WI-4): durable-first + bounded + exiting CLI verbs; deterministic post-hoc recovery patrols.
3. **Dispatch** (WI-5–WI-8): the four missing re-drive branches (re-review, plan→work, stack rebuild, swarm requeue).
4. **Wedges** (WI-9, WI-10): pane-content-aware liveness; modal table; model-divergence check.
5. **New reconcilers** (WI-11, WI-12): labels/read-model; agents-table gc.
6. **Cross-cutting** (WI-13–WI-16): deterministic cadence, admission-gate compliance audit, docs, close-out sweep.

Interaction contract for every re-drive (restated from D1/D3/D12): `derive obligation from durable state → shared gate predicate → admission gate → act idempotently → count attempt → breaker trips to needs-you`.

### WI-1 — Unified gate predicate + `stoppedByUser` semantics ([PAN-2536](https://github.com/eltmon/overdeck/issues/2536))
**Files:** `src/lib/agents/agent-state.ts` (`getAgentResumeGateBlockReason`, line 679), `src/lib/cloister/deacon.ts` (`checkDeadEndAgents` gate at 1966-1969 — search "agentState?.paused === true"), `src/lib/cloister/orphan-proposed-reconciler.ts` (spawn/rebuild gates at 242, 459-460; `classifySpawnSkip` 277-280; `triggerRebuildAndStart` 326), `src/lib/cloister/deacon-auto-resume.ts` (`deliberatelyStopped` at 732), `src/lib/cloister/concurrency.ts` (flag-clear pattern 325-330), `src/dashboard/server/routes/workspaces.ts` (rebuild-and-start route ~992), `src/cli/commands/start.ts`.
**Steps:**
1. Extend `getAgentResumeGateBlockReason` to return a typed reason covering `paused`, `troubled`, `stoppedByUser` (+ failure counters). This is THE predicate; export it as such. **The contract (decided here, do not redesign):**
   ```ts
   type ResumeGateBlock =
     | { gate: 'paused'; reason: string; pausedReason?: string; yieldedByScheduler?: boolean }
     | { gate: 'troubled'; reason: string; troubledAt?: string }
     | { gate: 'stopped-by-user'; reason: string }
     | { gate: 'failure-backoff'; reason: string; consecutiveFailures: number };
   // null ⇒ no gate blocks; caller may proceed to the admission gate (D12).
   ```
   The current `string | undefined` callers migrate to `block === null` checks; `block.gate` drives the needs-you dedup key and log wording. A discriminated union — not an enum — so each gate carries its own context fields.
2. Route `checkDeadEndAgents`, `orphan-proposed-reconciler` spawn + rebuild paths, and swarm requeue (WI-8) through it. On `stoppedByUser` skip: emit needs-you once per issue (deduped — reuse the dead-end cooldown map), do NOT loop rebuild-and-start.
3. Explicit operator actions clear the flag before dispatch: `pan start` (already partially via concurrency.ts:325-330 — verify), dashboard Rebuild & Start route, `pan swarm recover`.
**Tests:** unit tests on the predicate (all 8 flag combinations); a deacon-loop test: user-stopped + review-failed agent → exactly one needs-you, zero rebuild-and-start invocations across N simulated patrols (fake timers); operator start on the same fixture clears the flag and spawns.
