# PAN-4681 — Address CodeRabbit findings on merged PR #4667

**Issue:** https://github.com/eltmon/overdeck/issues/4681
**Background:** PR #4667 (PAN-4642, "cite selected reply text") merged at 07:02 UTC with two
late CodeRabbit findings unaddressed. PAN-4671 tracks the race that let it merge first; this
issue only fixes the two findings.

## Glossary

- **Frontend subset** — the `test:frontend-subset` script in the root `package.json`. It is an
  explicit list of frontend test files (paths relative to `src/dashboard/frontend`). CI's
  frontend job (`.github/workflows/ci.yml` line 245, `run: npm run test:frontend-subset`) runs
  only these files. A frontend test file that is not listed never runs on CI.
- **Cite toolbar** — the "Cite" button that appears over a text selection in the conversation
  timeline (PAN-4642). It is shown only when `MessagesTimeline` receives
  `citationsEnabled={true}` (`MessagesTimeline.tsx` lines 612, 657, 671).
- **Citation chips** — the strip of pending citations rendered inside `ComposerFooter`. Chips are
  the only place a user can see, edit, remove, or send a citation.
- **Mounted composer** — `ConversationView` renders `ComposerFooter` with an input box. This is
  the last branch of the footer ternary chain in `ConversationPanel.tsx`.
- **Resume bar** — `ConversationResumeControls`, shown in place of the composer when
  `onResume` is set (an ended conversation that can be resumed).
- **Vault copy** — a conversation with `conversation.origin === 'vault'`. `ComposerFooter`
  returns `VaultReadOnlyNotice` for it instead of the composer (`ComposerFooter.tsx` line 921:
  `if (props.conversation.origin === 'vault') return <VaultReadOnlyNotice …/>;`).

## Problem

1. `src/dashboard/frontend/src/components/chat/messagesTimeline/messageRows.test.tsx` is not in
   the frontend subset, so CI never runs it. PAN-4642 added the "PAN-4642 cite-row gate" and
   "PAN-4642 citation highlight (data-cited)" suites to it. Verified 2026-11-01: the file
   passes locally (19/19 tests) on `7fc87456019`.
2. `ConversationPanel.tsx` line 1471 passes `citationsEnabled={!hideComposer}` to
   `MessagesTimeline`. The composer is not mounted in four other states where the timeline still
   renders, so the Cite toolbar offers an action whose result (a chip) has nowhere to appear:
   - `conversation.clearedToConvId` is set (cleared banner instead of a footer);
   - `isForking` is true (no footer);
   - `onResume` is set (resume bar instead of composer) — every resumable ended conversation;
   - `conversation.origin === 'vault'` (`ComposerFooter` renders `VaultReadOnlyNotice`).
   In those states a user can save a citation: the quote is highlighted and stored in
   `localStorage`, but no chip is visible until a composer mounts.

## Decisions

- **D1 Gate expression (auto-decision).** Use CodeRabbit's proposed expression verbatim:
  `citationsEnabled={!hideComposer && !onResume && !isForking && !conversation.clearedToConvId && conversation.origin !== 'vault'}`.
  It is the exact `ComposerFooter` branch condition. The issue's acceptance criteria name only
  `onResume` and vault; those are the minimum tested cases, and the title ("gate citations on a
  mounted composer") requires all of them. Keep the original `!hideComposer` term.
- **D2 No helper constant.** A `const composerMounted = …` line would add lines to a god file
  and would not simplify the footer ternary (it chooses between different footers). One line.
- **D3 Test location.** Add the gate tests to the existing `ConversationPanel.test.tsx` (already
  in the subset), in a new `describe('ConversationPanel citation gate (PAN-4681)')` block that
  reuses `renderPanel`, `defaultConversationResponse`, and `timelineMock.props`.
- **D4 Other unlisted frontend tests are out of scope.** `messagesTimeline/dividers.test.tsx` is
  also not in the subset; this issue registers only `messageRows.test.tsx`.
