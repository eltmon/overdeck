# PRD: PAN-1641 — Run agents on local GPU models via a managed Ollama sidecar

**Issue:** https://github.com/eltmon/overdeck/issues/1641
**Status:** replanned 2026-09-25 from current `main` (`fd9cb0d57ad`). This PRD replaces the
2026-08-13 delta PRD, which described an ohmypi implementation that never reached `main`
(archived at `origin/archive/pan-1641-pre-cut`, 22 commits, PR #1679).

## Glossary

- **Ollama** — local model server (`ollama serve`, default `http://localhost:11434`). Runs models on
  the local GPU (CUDA on Linux, Metal on Apple Silicon). `ollama pull <tag>` downloads a model.
- **Ollama tag** — Ollama's model name, e.g. `gemma4:12b`, `qwen3:1.7b`,
  `hf.co/mradermacher/foo-GGUF:Q4_K_M`. Tags can contain `:` and `/`.
- **Overdeck Ollama model id** — the string an operator writes in config or passes to `--model`:
  `ollama:<tag>`, e.g. `ollama:gemma4:12b`. The `ollama:` prefix is Overdeck-only routing; it is
  removed before the id reaches the harness or the Ollama server.
- **Wire model id** — the id sent to the harness CLI (`claude --model <id>`) and on to the backend.
  For Ollama it is the bare tag (`gemma4:12b`).
- **Anthropic-compatible endpoint** — an HTTP server that accepts Anthropic Messages API requests at
  `POST <base>/v1/messages`. Ollama ≥ 0.14.0 serves one natively. Claude Code reaches any such server
  through `ANTHROPIC_BASE_URL=<base>` (Claude Code appends `/v1/messages` itself).
- **claude-code harness** — Overdeck's default harness (the `claude` CLI). Already drives non-Anthropic
  models (Kimi, MiniMax, Z.AI, OpenRouter, QuantumLlama) by setting `ANTHROPIC_BASE_URL` +
  `ANTHROPIC_AUTH_TOKEN` in the launcher (`getProviderEnv`, `src/lib/providers.ts:514`).
- **Preflight** — the checks that run inside `getProviderEnvForModel()`
  (`src/lib/agents/provider-env.ts:26`) before any launcher is generated. Every spawn, resume,
  recovery, relaunch, conversation, and planning path calls this function (verified by grep: spawn.ts,
  spawn-prep.ts, recovery.ts, messaging.ts, spawn-planning-session.ts, conversation-runtime.ts,
  routes/conversations.ts, conversation-compaction.ts).
- **Warm-load** — `POST /api/generate {"model":"<tag>","prompt":""}` makes Ollama load the model into
  memory without generating text. After it, `GET /api/ps` reports the loaded model's
  `context_length` (the real `num_ctx` the server will enforce).
- **num_ctx / context length** — the maximum prompt+output tokens Ollama serves for a loaded model.
  Ollama **silently truncates** prompts longer than this. Set server-wide by the
  `OLLAMA_CONTEXT_LENGTH` environment variable of the `ollama serve` process.
- **Zero cloud model calls** — no request carrying model input/output leaves the machine. Non-model
  traffic that the agent's task itself causes (e.g. `git push` to GitHub) is allowed and attributed.
- **PAN-3684** — the existing acceptance issue ("PAN-1641 acceptance: local Ollama work-agent spawn",
  open, spec `.pan/specs/2026-08-13-PAN-3684-*.xbrief.json`, status `proposed`). Its task: a work agent
  on `ollama:gemma4:12b` creates `LOCAL_OLLAMA_OK.txt` containing `LOCAL_OK`, commits, pushes, and runs
  `pan task done`. Its body still says "Pi work agent"; this PRD re-points it to claude-code.

## Background and the harness decision

The issue targeted the Pi harness. That target no longer exists:

- `pi` is not a runtime on `main`. `packages/contracts/src/types.ts:89` defines
  `Harness = 'claude-code' | 'ohmypi' | 'codex' | 'acp' | 'kimi-code' | 'opencode' | 'muse'`, and
  `getHarness()` (`types.ts:98-100`) folds legacy `'pi'` into `'ohmypi'`.
- `ohmypi` is being removed (PAN-4003, "Remove Oh My Pi (ohmypi/omp) harness support; keep Pi only",
  operator decision 2026-09-23). No time may go into OMP-specific code.
- The issue's "do NOT route Ollama through `ANTHROPIC_BASE_URL`" rule assumed Ollama had no
  Anthropic-compatible API. That is no longer true. Verified on this host (Ollama 0.19.0) on
  2026-09-25:
  - `POST http://localhost:11434/v1/messages` returns an Anthropic `message` object.
  - With `"stream": true` and a `tools` array, the stream emits `content_block_start` with
    `"type":"tool_use"`, an `input_json_delta` carrying `{"cmd":"echo PROBE_OK"}`, and
    `stop_reason: "tool_use"`.
  - `claude --print --model qwen3:1.7b` with `ANTHROPIC_BASE_URL=http://localhost:11434`,
    `ANTHROPIC_AUTH_TOKEN=ollama`, and all tier-model env vars set to `qwen3:1.7b` completed a turn
    (`"subtype":"success"`, `inputTokens: 21690`, `contextWindow: 200000`). Claude Code printed
    "claude.ai connectors are disabled because ... another auth source is set", so claude.ai MCP
    connectors do not load in this mode.
- `curl -sI https://registry.ollama.ai/v2/library/gemma4/manifests/12b` returns `HTTP/2 200`, so the
  default tag `gemma4:12b` exists.

**Decision D1: v1 runs Ollama models on the `claude-code` harness**, using the same
`ANTHROPIC_BASE_URL` pattern as every other non-Anthropic claude-code provider. No proxy, no
OpenAI-compatible shim, no `~/.omp` provisioning. The `ohmypi`/`pi`, `codex --oss`, and `opencode`
routes are out of scope.

Two observations from the probe drive design decisions below:

1. Claude Code assumed a 200K window for the unknown model id, while the server enforced 32768
   (`ollama ps` → `CONTEXT 32768`). One bare Claude Code turn already used 21,690 input tokens; an
   Overdeck work agent adds role prompts, rules, and CLAUDE.md on top. Without a context pin, Claude
   Code overruns `num_ctx` and Ollama truncates silently. → D5.
2. Claude Code computed `costUSD: 0.117` for the local run from its own default table. Overdeck's cost
   path does not use that number: `getPricing()` (`src/lib/cost.ts:229`) returns `null` for an unknown
   model and `jsonl-parser.ts:390-391` records `cost = 0`. → D9.

## Decisions

- **D1 — Harness:** claude-code only (see Background). `canUseHarness()` pins `ollama:` models to
  claude-code the same way it pins `opencode/*` to opencode and Meta models to muse.
- **D2 — Model id namespace:** `ollama:<tag>`. Matches PAN-3684 and the archived branch. The carve-out
  is the **first** check in `getProviderForModel()` and `getModelProvider()`, before the
  `includes('/')` OpenRouter heuristic, because tags can contain `/`.
- **D3 — Single strip point:** `apiLaunchModelId()` (`src/lib/model-context-windows.ts:99`) removes the
  `ollama:` prefix. Its own doc says it is "the single launch-arg door": `shellQuoteModelId()`
  (`src/lib/model-validation.ts:27`) calls it, and every claude `--model` flag goes through
  `shellQuoteModelId` (`launcher-generator.ts:677`, `runtime-command.ts:689,881`).
- **D4 — Endpoint and env:** base URL is `http://localhost:11434` with **no `/v1`** (Claude Code
  appends `/v1/messages`; the OpenRouter comment at `providers.ts:200` records the double-`/v1` bug).
  Env for an Ollama launch is exactly:
  `ANTHROPIC_BASE_URL=<baseUrl>`, `ANTHROPIC_AUTH_TOKEN=ollama`,
  `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`,
  `ANTHROPIC_SMALL_FAST_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL` (all = the bare tag, so Claude Code
  subagents stay on the local model), `API_TIMEOUT_MS=600000` (cold loads and slow local decoding),
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (turns off Claude Code telemetry, error reporting, and
  auto-update calls), and the two context pins from D5. No `ANTHROPIC_API_KEY`, no cloud URL.
- **D5 — Context length source is the server.** Preflight warm-loads the model, reads its
  `context_length` from `GET /api/ps`, and pins `CLAUDE_CODE_MAX_CONTEXT_TOKENS` and
  `CLAUDE_CODE_AUTO_COMPACT_WINDOW` to that number, so Claude Code compacts before Ollama truncates.
  The YAML value `ollama.context_length` (default `65536`) is used only as `OLLAMA_CONTEXT_LENGTH`
  when **Overdeck itself** starts `ollama serve`. For an externally managed server (systemd unit,
  Ollama.app), docs explain how to set `OLLAMA_CONTEXT_LENGTH`, and `pan doctor` warns when the loaded
  context is below 65536.
- **D6a — No provider-enable gate.** Role and workhorse resolution does not consult
  `enabledProviders` (verified: in `src/lib/config-yaml*` it is only built in `merge.ts` and passed to
  conversation watch-dir resolution in `load.ts:465`; `applyFallback` is used only by conversation
  enrichment). So `roles.work.model: ollama:gemma4:12b` reaches spawn unchanged, with no silent
  Anthropic fallback, and no enable toggle is needed.
- **D6 — Config shape:** a new top-level YAML block, not `models.providers.ollama`:
  ```yaml
  ollama:
    base_url: http://localhost:11434   # optional; must be localhost / 127.x / [::1]
    context_length: 65536              # optional; used when Overdeck starts `ollama serve`
  ```
  Reason: `models.providers` is typed `Partial<Record<ConfigurableProvider, …>>`
  (`schema.ts:489`), and `CONFIGURABLE_PROVIDERS` (`src/lib/configurable-providers.ts`) also derives
  the dashboard Settings provider union and the tier-fitness `provider-not-enabled` warning. Adding
  `ollama` there pulls dashboard UI into scope, which the follow-up issue owns. Ollama needs no API key
  and no enable toggle: using an `ollama:` model is the opt-in. A non-localhost `base_url` is a config
  load error.
- **D7 — Lazy lifecycle, never a global GPU start.** The server is started (a) during preflight when
  an Ollama model is about to launch and the endpoint is unreachable, and (b) by `pan up` only when the
  config names an `ollama:` model (workhorses, role models, sub-role models). Hosts that never
  configured a local model never start `ollama serve`.
- **D8 — Install is guidance, not auto-install.** `pan install` detects `ollama --version`; if missing
  it prints platform guidance (Linux: `curl -fsSL https://ollama.com/install.sh | sh`; macOS:
  `brew install ollama`) and continues. It never runs `curl | sh` (commit `625bb71f62b`). If Ollama is
  present and stdin is a TTY, it asks (default **No**) whether to pull `gemma4:12b`; on non-TTY it
  prints the `ollama pull gemma4:12b` command. `--skip-ollama` skips the whole step.
- **D9 — Cost:** local runs record $0 through the existing null-pricing path. No pricing rows are added.
  A unit test pins `getPricing(normalizeModelName('gemma4:12b'))` → `null`.
- **D10 — No hardcoded model fallback.** `DEFAULT_OLLAMA_AGENT_MODEL = 'gemma4:12b'` is only the
  recommended pull target shown by install, doctor, and docs. Model resolution never falls back to it.
  An agent runs on Ollama only when a role, workhorse, or `--model` names an `ollama:` id.
- **D11 — Minimum Ollama version `0.14.0`** (first release with the Anthropic Messages endpoint).
  Preflight reads `GET /api/version` and fails with an upgrade message below it.
- **D12 — E2E runs through PAN-3684 with the workspace-built CLI.** `pan reload` deploys CI-green
  `origin/main`, not the feature branch, so the production dashboard cannot route `ollama:` ids before
  merge. The E2E runs `node <workspace>/dist/cli/index.js start PAN-3684 --model ollama:gemma4:12b`,
  which executes the new spawn code in the CLI process. The E2E agent is killed right after the
  evidence is captured, so the production Deacon never tries to recover it with old code.

## Requirements

Functional:

- **FR-1** `getProviderForModel('ollama:<tag>')` returns the `ollama` provider for any tag, including
  tags with `/` (e.g. `ollama:hf.co/org/model-GGUF:Q4_K_M`); `getModelProvider` returns `'ollama'`.
- **FR-2** `apiLaunchModelId('ollama:gemma4:12b')` returns `gemma4:12b`, so every claude `--model`
  argument carries the bare tag.
- **FR-3** `canUseHarness(h, 'ollama:<tag>', …)` is allowed only for `h === 'claude-code'`; any other
  harness gets a block reason naming claude-code.
- **FR-4** Preflight for an `ollama:` model, in order: resolve base URL from config; probe health
  (bounded); if unreachable, start `ollama serve` (with `OLLAMA_CONTEXT_LENGTH=<context_length>`) and
  wait within one overall deadline; check version ≥ 0.14.0; check the tag is in `/api/tags`; warm-load
  and read `context_length`. Any failure throws an `Error` whose message names the fix
  (`ollama serve`, `ollama pull <tag>`, upgrade Ollama).
- **FR-5** On success, `getProviderEnvForModel` returns exactly the env of D4, with both context pins =
  the warm-loaded `context_length`.
- **FR-6** YAML `ollama.base_url` / `ollama.context_length` normalize into
  `NormalizedConfig.ollama = { baseUrl, contextLength }` with defaults
  `http://localhost:11434` / `65536`; a non-localhost `base_url` throws at config load.
- **FR-7** `pan install` has `--skip-ollama`; without it the step detects Ollama, prints guidance when
  missing, and offers the `gemma4:12b` pull per D8.
- **FR-8** `pan doctor` reports Ollama when the config names an `ollama:` model or the binary is
  installed: installed?, reachable?, version ≥ 0.14.0?, configured tags present?, loaded context ≥
  65536?
- **FR-9** `pan up` ensures `ollama serve` is running when, and only when, the config names an
  `ollama:` model; failure is a printed warning, never a failed `pan up`.
- **FR-10** An Overdeck-spawned claude-code work agent on `ollama:gemma4:12b` completes PAN-3684's task,
  with evidence of zero cloud model calls recorded in `docs/audits/pan-1641-local-ollama-verification.md`.
- **FR-11** Docs describe install → pull → configure → run for Linux/CUDA and Apple Silicon.
- **FR-12** The stopped-agent relaunch fallback in `messageAgent()` runs the Ollama preflight before it
  recreates the terminal session (pinned by a regression test).

Non-functional:

```ts
export const MIN_OLLAMA_VERSION = '0.14.0';
export const OLLAMA_MODEL_PREFIX = 'ollama:';
export const SAFE_OLLAMA_HOST_RE = /^https?:\/\/(localhost|127(?:\.\d+){3}|\[::1\]|::1)(:\d+)?\/?$/; // was a non-exported const at line 7

export interface OllamaHealth {
  endpointReachable: boolean;
  version?: string;
  versionSupported: boolean;   // version >= MIN_OLLAMA_VERSION
  modelPresent: boolean;       // tag listed in /api/tags (exact name match, or `<tag>:latest` when tag has no ':')
  message?: string;            // actionable text when anything is false

```

Rules:
- `checkOllamaHealth`: one `AbortController` with `timeoutMs` (default 5000) covers `GET /api/version`
  and `GET /api/tags` including `await response.json()`; on timeout call `controller.abort()` and
  return `endpointReachable: false`. Compare versions numerically per dot segment.
- `ensureOllamaServeRunning`: if `knownUnhealthy` is not true, probe once and return if healthy. Start
  the server with the existing detached spawn, passing
  `{ ...process.env, OLLAMA_HOST: <host:port from baseUrl>, OLLAMA_CONTEXT_LENGTH: String(contextLength) }`.
  Then poll until healthy or until `deadlineMs` (default 30000) elapses, each probe's timeout =
  `min(5000, remaining)`, 1000 ms between attempts. On deadline throw
  `OllamaEnsureError('Ollama did not become healthy at <baseUrl> within 30s. Start it with `ollama serve` and retry.')`.
- `warmOllamaModel`: `POST /api/generate` `{ model: tag, prompt: '' }` with timeout default 120000
  (cold load of an 8 GB model), then `GET /api/ps`, find the entry whose `name` or `model` equals the
  tag, return its `context_length`. Missing entry or field → throw with the tag in the message.

Tests: extend `src/lib/__tests__/ollama.test.ts` (inject `fetchImpl`/`startServer`/`sleep`/`now`;

```ts
export async function getOllamaLaunchEnv(model: string, ollama: { baseUrl: string; contextLength: number }): Promise<Record<string, string>> {
  const tag = stripOllamaPrefix(model);
  let health = await checkOllamaHealth(tag, ollama.baseUrl);

  return {
    ANTHROPIC_BASE_URL: ollama.baseUrl,
    ANTHROPIC_AUTH_TOKEN: 'ollama',
    ANTHROPIC_DEFAULT_OPUS_MODEL: tag,
    ANTHROPIC_DEFAULT_SONNET_MODEL: tag,
    ANTHROPIC_DEFAULT_HAIKU_MODEL: tag,
    ANTHROPIC_SMALL_FAST_MODEL: tag,
    CLAUDE_CODE_SUBAGENT_MODEL: tag,
    API_TIMEOUT_MS: '600000',
    CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC: '1',
    CLAUDE_CODE_MAX_CONTEXT_TOKENS: String(contextLength),
    CLAUDE_CODE_AUTO_COMPACT_WINDOW: String(contextLength),
```

## Hazards

- **H1 Context truncation.** Ollama truncates silently past `num_ctx`. D5 pins Claude Code to the real
  loaded value; doctor warns below 65536. An Overdeck work agent's first prompt is large (bare Claude
  Code already used ~21.7K tokens).
- **H2 Production dashboard runs old code.** `pan reload` ships `origin/main`, so before merge the
  dashboard and Deacon throw `UnknownModelError` for `ollama:` ids on any recovery/resume. Kill the E2E
  agent right after evidence capture (WI-10 step 6). Do not run `pan reload` or `pan restart` while the
  E2E agent's state row exists.
- **H3 Double preflight per spawn.** `spawn.ts:287-288` calls both `getProviderExportsForModel` and
  `getProviderEnvForModel`; the second call hits a loaded model and returns quickly. Do not add caching.
- **H4 `--effort`.** claude-code passes `--effort`; Ollama ignores unknown request fields in the probe,
  but record any error seen in the E2E.
- **H4b The tool loop is unproven.** The curl probe proved Ollama *emits* `tool_use` blocks. The
  `claude --print` probe returned `num_turns: 1`, so the 1.7B model most likely answered without running
  Bash; the `tool_result` → continuation round-trip through Ollama's Anthropic shim has not been
  exercised. WI-10 is the first real test of it, not a confirmation.
- **H5 GPU load.** Keep the E2E to the single PAN-3684 task; do not run other GPU-heavy jobs in parallel
  on this host.
- **H6 Ratchets.** `src/cli/index.ts`, `doctor.ts`, `schema.ts` are over 1000 lines; each growth needs
  an allowlist row in the same commit.
