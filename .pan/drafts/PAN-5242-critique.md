## blocks-the-design: zero candidates do not prove bot egress is blocked

The PRD's own closed-port test expects `no-webrtc-egress` when the TURN server is unreachable ([PAN-5242.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 340–345), while WI-4 makes that code non-retryable and says the bot cannot send UDP (lines 355–365). The same zero-candidate observation can result from a TURN outage, expired or invalid TURN credentials, DNS failure, or local filtering; the proposed machine-side doctor probe runs on a different host and cannot prove which happened on the bot. This would tell the operator a transient relay failure cannot recover. Smallest change: treat zero candidates as an observed allocation failure, and reserve the definitive non-retryable `no-webrtc-egress` result for a check that distinguishes local egress failure from TURN or credential failure. Otherwise make the status and next action acknowledge the uncertainty and allow a retry after relay recovery.

## blocks-the-design: dial setup errors still lack a route

FR-1 says every `RtcTransport` dial error names `direct` or `relay`, but WI-1 changes only abort and `awaitOpen` messages ([PAN-5242.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 175–205). `create()` awaits `peerIceServers()` before its catch and rethrows `createOffer()` or `setLocalDescription()` errors unchanged ([rtc-transport.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/lib/anywhere/channel/rtc-transport.ts), lines 141–160). The existing directory ICE-server request can reject with `the directory did not answer the ICE server request` ([directory-rtc.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/dashboard/server/services/directory-rtc.ts), lines 31–51), which contains no route. Smallest change: cover setup failures in the route-labeling work item, preserving `ChannelOpenError.code` and `detail` when adding the route, and test a relay `iceServers()` rejection.

## blocks-the-design: doctor fix has no TURN host for one failed result

WI-7 explicitly returns `failed` with `turnUrl: null` when the directory supplies no TURN URL ([PAN-5242.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 488–492). WI-9 then requires every `failed` row's fix to name the host and port of `turnUrl` (lines 594–597), and its tests cover only a failed result with a URL (lines 611–615). There is no host or port to extract in this valid result, so the doctor row could throw or give a false network fix. Smallest change: specify a separate `turnUrl: null` warning and fix for a missing TURN server, with an acceptance test.

## sharpens-framing: directory timeout is labeled a refusal

The new route maps every `rtc.iceServers(true)` rejection to state `refused` ([PAN-5242.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 540–558). The existing `requestIceServers()` also rejects after 10 seconds without an answer ([directory-rtc.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/dashboard/server/services/directory-rtc.ts), lines 31–40), and WI-9 renders all `refused` results as `overdeck.ai refused relay credentials` (PRD lines 594–600). A timeout is not a refusal, so this sends the operator to the wrong cause. Smallest change: give timeout or transport errors a distinct failed response and doctor text; reserve `refused` for an actual directory refusal frame.
