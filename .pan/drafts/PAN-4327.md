# PAN-4327 — Add Claude Sonnet 5.5 (`claude-sonnet-5-5`)

**Issue:** [PAN-4327](https://github.com/eltmon/overdeck/issues/4327)
**Planned:** 2026-09-28 (auto mode, planner `claude-opus-5-5`)
**Operator priority:** ship today, one PR, then release `v0.63.0` from main.

Add Claude Sonnet 5.5 everywhere Overdeck knows Claude models, stop Overdeck's own direct API calls from sending sampling parameters to models that reject them, move the Sonnet-tier defaults to Sonnet 5.5, fix the `sonnet` alias drift that Sonnet 5.5 causes, and document it.

## Glossary

- **Sonnet 5.5** — Anthropic model `claude-sonnet-5-5`, released 2026-09-28. 1M context, 128K max output, $2/M input, $10/M output, $0.20/M cache read, $2.50/M 5-minute cache write, $4/M 1-hour cache write (identical to Sonnet 5). Adaptive thinking, default effort `high`, effort levels `low`/`medium`/`high`/`xhigh`/`max`. Source: https://platform.claude.com/docs/en/models/sonnet-5-5/overview.
- **Sampling parameters** — the request fields `temperature`, `top_p`, `top_k`. The Claude API returns HTTP 400 when a model that removed them receives a non-default value.
- **Sampling-restricted model** — a model whose capability entry sets `supportsSamplingParams: false`. Per the Claude API model table (thinking/sampling matrix), these are: `claude-fable-5-1`, `claude-fable-5`, `claude-opus-5-5`, `claude-opus-5`, `claude-opus-4-8`, `claude-opus-4-7`, `claude-sonnet-5`, and `claude-sonnet-5-5`. `claude-opus-4-6`, `claude-sonnet-4-6`, `claude-sonnet-4-5` and `claude-haiku-4-5` still accept sampling parameters.
- **Capability table** — `MODEL_CAPABILITIES` in `src/lib/model-capabilities.ts`, which spreads `AUDITED_MODEL_ADDITIONS` from `src/lib/model-capability-additions.ts` first. New models land in the additions file.
- **`ModelId`** — the TypeScript union in `src/lib/settings.ts`. `AnthropicModel` is one member. Adding an ID to the union forces an entry in every `Record<ModelId, …>` map (`MODEL_CAPABILITIES`, `MODEL_PROVIDERS` in `src/lib/model-fallback.ts`).
- **Claude flag** — the string `getClaudeModelFlag()` (`src/lib/settings.ts`) passes to `claude --model`. Callers: `getAgentCommand()` → Command Deck status review (`src/dashboard/server/routes/command-deck.ts:970`) and planning message relaunch (`src/dashboard/server/routes/misc/planning.ts:328`). Work-agent spawns pass the raw model ID and do not use this function.
- **`sonnet` alias drift** — Claude Code's short alias `sonnet` resolves to the newest Sonnet the installed Claude Code knows. Verified 2026-09-28: on Claude Code 2.1.280 `--model sonnet` runs `claude-sonnet-5`; on Claude Code 2.1.284 it runs `claude-sonnet-5-5`.
- **File-size ratchet** — `scripts/lint-file-size.sh`. A file over 1000 lines may not grow past its `origin/main` line count unless `scripts/file-size-allowlist.txt` has a row `<lines> <path> # <ISSUE>`. The last row for a path wins.
- **Workhorse `mid` slot** — `DEFAULT_WORKHORSES.mid` in `src/lib/config-yaml/roles.ts`; `workhorse:mid` refs (the `work` role, review sub-roles, `test`, `ship`, `worker`) resolve through it.

## Verified facts (probed 2026-09-28)

1. Installed Claude Code on this host is **2.1.280**. `claude -p --model claude-sonnet-5-5` succeeds (API serves the model) but prints `[claude-code:unrecognized_model]`, disables the advisor, reports `contextWindow: 200000` and `costBasis: "unknown"`. `claude-sonnet-5-5[1m]` reports `contextWindow: 1000000`.
2. Claude Code **2.1.284** (published 2026-09-28T17:11Z) contains `claude-sonnet-5-5` natively: `--model claude-sonnet-5-5` reports `contextWindow: 1000000`, `costBasis: "list"`, no warnings; `--model sonnet` resolves to `claude-sonnet-5-5`.
3. So Sonnet 5.5 **requires Claude Code 2.1.284 or newer** for the 1M window and list pricing, the same pattern as "Fable 5.1 requires Claude Code 2.1.255 or newer" (`src/lib/model-capability-additions.ts:31`).
4. No Overdeck code sends a forced `tool_choice` to a Claude model. The only `tool_choice` site is `src/lib/openai-compatible-proxy.ts:232`, which forwards only `'auto'` to an OpenAI-compatible upstream.
5. Sampling parameters are sent in exactly three places: `src/lib/memory/providers/anthropic.ts:31` (`temperature: options.temperature ?? 0`), `src/lib/memory/providers/cliproxy.ts:53` (same), and `src/dashboard/server/services/tts-summarizer.ts:103` (`temperature: 0.4`). `src/lib/memory/query-expansion.ts:96` and `src/lib/registry/feature-registry-population.ts:96` only pass `temperature: 0` into `extractWithProviderPolicy()`, which hands it to `provider.extract()`; the provider guard fixes both transitively, so **those two files need no edit**.
6. `src/dashboard/server/services/tts-summarizer.ts` POSTs to `https://api.openai.com/v1/chat/completions` with an OpenAI key. A Claude model cannot succeed there regardless of temperature. The guard is applied for consistency only.
7. `src/dashboard/server/routes/settings.ts` `MODEL_API_IDS` (line ~107) holds only OpenAI/other-provider IDs, no Anthropic IDs, and `src/lib/router-config.ts` no longer exists. The issue lists both; **neither needs an edit**.
8. `sync-sources/hooks/record-cost-event.js` is a committed bundle rebuilt only by `npm run build:scripts` (deliberately off the default build, PAN-2699; it does not even contain `claude-opus-5-5`). `getPricing()` (`src/lib/cost.ts:232`) falls back to `model.startsWith(p.model)`, so the stale bundle prices `claude-sonnet-5-5` with the `claude-sonnet-5` row — the same $2/$10 — and records the raw model string. **No hook rebuild is needed.**
9. `model-capabilities.ts` is 1406 lines with allowlist rows at 1406 (`scripts/file-size-allowlist.txt:68`). `smart-compaction.ts` is 1147 lines. Any growth in either needs a new allowlist row.

## Decisions

1. **Checkpoint outcome: ship defaults (item 3 of the issue).** The issue's condition was "installed Claude Code launches with `--model claude-sonnet-5-5`". It does (fact 1). The degraded 200K window on 2.1.280 is fixed by upgrading Claude Code, not by withholding defaults; the requirement goes into capability notes, docs and the changelog.
2. **Do not export `CLAUDE_CODE_MAX_CONTEXT_TOKENS` for Sonnet 5.5.** A probe with `CLAUDE_CODE_MAX_CONTEXT_TOKENS=1000000` on 2.1.280 still reported a 200K window, so the workaround is unverified. Requiring 2.1.284 is the fix.
3. **Sonnet 5.5 capability entry lives in `model-capability-additions.ts`,** directly after `claude-fable-5-1`. Because additions spread first, it lands before `claude-sonnet-5` in `getAvailableModelsApi().anthropic`, satisfying "Sonnet 5.5 first among Sonnet models".
4. **Flag name and semantics:** `supportsSamplingParams?: boolean`, tri-state like `supportsImages`: `false` = proven to reject non-default `temperature`/`top_p`/`top_k`; `undefined`/`true` = send them. Helper `modelSupportsSamplingParams()` sits next to `modelSupportsImages()` in `model-capabilities.ts` and resolves deprecated IDs first.
5. **No GPT/other-provider model gets the flag.** There is no verified source for OpenAI's behavior here. Follow-up, not this issue.
6. **Sonnet alias fix covers the whole Sonnet family, not Opus.** `claude-sonnet-4-6 → 'sonnet'` already launches Sonnet 5 today. The Opus rows (`claude-opus-4-8/4-7/4-6 → 'opus'`) have the same bug class but a different family; they are a follow-up.
7. **`query-expansion.ts`, `feature-registry-population.ts`, `routes/settings.ts`, `router-config.ts`, `record-cost-event.js` are not edited** (facts 5, 7, 8).
8. **Changelog:** pre-seed a `<Update label="v0.63.0" description="2026-09-28">` block at the top of `changelog.mdx` with a `#### New` Sonnet 5.5 bullet and a compare link `v0.62.1...v0.63.0`. The release step reconciles the label if another release ships first.
9. **Release to npm is not the work agent's job.** After merge, from main: `pan release stable --version 0.63.0`, then push main and the tag (CLAUDE.md: never manual tags).
10. **Size justification:** the change is a mechanical model addition across the catalog, cost, memory and defaults layers plus docs (~40 files with tests). Sibling issues would force several releases for one model launch the operator wants shipped today.
