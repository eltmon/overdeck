## blocks-the-design: Finalize timeout can leave no recoverable handoff

`promotePlanning` aborts its `complete-planning` request after 90 seconds (`src/cli/commands/plan-finalize.ts:558-570`) and writes a pending-promotion marker on failure (`:439-452`). The server does not append `handoff.requested` until after PRD/spec promotion, a git commit, tracker updates, and the branch push (`src/lib/overdeck/planning-promotion.ts:648-755,826-841`). If the dashboard dies after the CLI timeout but before line 840, there is no handoff entry for deacon-lite to resume. I checked `rg -n 'pending-promotion|PENDING_PROMOTION_FILENAME' src --glob '*.ts'`: the marker is written in `plan-finalize.ts` and removed in `planning-promotion.ts`, with no reader or retry consumer. The marker also records `autoSpawnRequested: false` for the v2 consent record: `readAutoSpawnOnFinalize` reads only the legacy `autoSpawnOnFinalize` field (`plan-finalize.ts:152-158`), while `writeAutoSpawnOnFinalizeFlag` writes `status: 'granted'` (`src/lib/planning/auto-spawn-consent.ts:135-143`). Add a recovery path that consumes the pending promotion marker and preserves the v2 auto-start intent, or obtain an explicit scope change that excludes timeouts before the spawn POST.

## sharpens-framing: A failed journal write is reported as durable

`appendPipelineEntry` catches write errors and returns a stamped entry even when nothing reached disk (`src/lib/cloister/pipeline-journal.ts:66-101`). `journalHandoffRequest` treats that call as success and returns `true` (`src/lib/overdeck/planning-handoff-journal.ts:37-45`), while deacon-lite only resumes entries it can read from disk (`src/lib/cloister/deferred-handoff.ts:235-242`). Thus the plan's recovery promise silently fails when the workspace journal cannot be written. Make persistence observable to this caller and report the handoff as unrecoverable when it fails; state the writable-journal precondition in the PRD.
