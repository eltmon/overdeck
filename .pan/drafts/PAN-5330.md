# PAN-5330 — Workspace frontends proxy to their own server, never another stack's

**Issue:** [PAN-5330](https://github.com/eltmon/overdeck/issues/5330)
**Status:** planned (auto mode, 2026-11-16)

## Glossary

- **Workspace stack** — the Docker Compose project rendered for one Overdeck feature workspace
  (`workspaces/feature-<issue>/.devcontainer/docker-compose.devcontainer.yml`) or one UAT batch
  worktree. It has the services `dev`, `init-perms`, `init`, `frontend` and `server`.
- **Template** — `infra/.devcontainer-template/docker-compose.devcontainer.yml.template`, the
  Overdeck project's `workspace.docker.compose_template`. Every workspace stack is rendered from it.
- **Renderer** — `src/lib/workspace/devcontainer-renderer.ts` (`renderDevcontainer`,
  `createWorkspacePlaceholders`, `processTemplates`). It replaces `{{PLACEHOLDER}}` tokens in the
  template. The issue calls this "the generator".
- **`{{FEATURE_FOLDER}}`** — placeholder that is unique per stack: `feature-<issue>` for a feature
  workspace (`createWorkspacePlaceholders`, `const featureFolder = \`feature-${featureName}\``), or the
  worktree leaf `uat-<label>-<codename>-<mmdd>` for a UAT batch (`ensure-devcontainer.ts`,
  `placeholderOverrides: { FEATURE_FOLDER: workspaceLeaf, … }`). The Traefik routers already key on it,
  so two live stacks never share it.
- **`devnet`** — the stack's private bridge network (`overdeck-<FEATURE_FOLDER>_devnet`). Only that
  stack's containers (and Traefik, which `reconcileTraefikNetworks` connects) are on it.
- **`overdeck` network** — the shared external Docker network. Every workspace stack's `dev`,
  `frontend` and `server` join it, and Traefik routes over it (`sync-sources/templates/traefik/traefik.yml`,
  `providers.docker.network: overdeck`, line 36).
- **Service-name alias** — Docker Compose registers each service's key (for example `server`) as a DNS
  name on **every** network the service joins. Compose has no option to suppress it.
- **Network-scoped alias** — an extra DNS name declared under `networks: <net>: aliases:`. Docker
  answers it only for containers attached to `<net>`.
- **`VITE_PROXY_TARGET`** — env var read by `resolveProxy()` in `src/dashboard/frontend/vite.config.ts`
  (line 32). When set, the Vite dev server proxies `/api` and `/ws` to it.

## Problem

A workspace frontend can proxy its API calls to a different workspace's server. PAN-5329's work agent
hit this on 2026-11-15: its browser checks reached the wrong backend and flaked.

### Cause (observed live, 2026-11-16)

The template sets the frontend proxy to the bare service name (template line 121):

```yaml
      - VITE_PROXY_TARGET=http://server:3013
```

and joins `server` to both networks (template lines 188–190):

```yaml
    networks:
      - devnet
      - overdeck
```

Read-only inspection of the two stacks running on this host (PAN-5343 and PAN-5370):

```text
$ docker inspect overdeck-feature-pan-5343-server-1 …
overdeck=192.168.48.5  dnsnames=[overdeck-feature-pan-5343-server-1 server …]
overdeck-feature-pan-5343_devnet=172.19.0.4 dnsnames=[… server …]
$ docker inspect overdeck-feature-pan-5370-server-1 …
overdeck=192.168.48.11 dnsnames=[overdeck-feature-pan-5370-server-1 server …]
overdeck-feature-pan-5370_devnet=172.24.0.4 dnsnames=[… server …]

$ docker exec overdeck-feature-pan-5370-frontend-1 getent ahosts server
192.168.48.11  server      # PAN-5370's own server, via the shared network
192.168.48.5   server      # PAN-5343's server
```

The PAN-5370 frontend resolves `server` to **two** `overdeck` addresses and never to its own `devnet`
address (172.24.0.4). Docker's embedded DNS finds the name on the shared network first, and returns
every container that carries it there. Repeated `getent hosts server` calls alternate between
`.11` and `.5`, so about half the proxied requests go to the other workspace's backend.

### Proof that a network-scoped alias fixes it (throwaway probe, 2026-11-16)

Two compose projects (`pan5330probe-a`, `pan5330probe-b`) on a shared external network named
`pan5330probe`. That name sorts before `pan5330probe-a_devnet`, just as `overdeck` sorts before
`overdeck-feature-<x>_devnet`, so the probe reproduces the live lookup order. Each project declared
`server` with `networks: { devnet: { aliases: [server-feature-probe-<x>] }, shared: {} }`. Probe
resources were removed afterwards.

```text
A server: shared=172.21.0.3  devnet=172.27.0.2
B server: shared=172.21.0.4  devnet=172.29.0.2
A frontend: getent ahosts server                  -> 172.21.0.3, 172.21.0.4   (bug reproduced)
A frontend: getent ahosts server-feature-probe-a  -> 172.27.0.2               (A's own devnet IP only)
A frontend: getent ahosts server-feature-probe-b  -> (no answer)
A server dnsnames on shared network: [pan5330probe-a-server-1 server <id>]   # alias absent
```

The probe also confirms that Compose always registers the bare `server` name on the shared network.
So the issue's second option ("give the server only a unique alias on `overdeck`") cannot be done as
worded: the bare name cannot be removed from `overdeck` without renaming the service key.

## Decisions

- **D-1 Fix = a unique, devnet-scoped alias.** `server` gets the extra alias `api-{{FEATURE_FOLDER}}`
  on `devnet` only. The frontend's `VITE_PROXY_TARGET` becomes `http://api-{{FEATURE_FOLDER}}:3013`.
  This combines both options from the issue: the name is unique per stack (option 1), and the
  frontend-to-server traffic stays on the private network (option 2). A frontend cannot see another
  stack's `devnet`, so even a collision on the name could not route across stacks.
- **D-2 Alias name `api-{{FEATURE_FOLDER}}`, not `server-{{FEATURE_FOLDER}}`.** It is exactly the
  first label of the stack's existing public API host `api-{{FEATURE_FOLDER}}.overdeck.localhost`
  (Traefik router rule). That label must already be a valid DNS label of 63 characters or fewer for
  Traefik routing to work, so this alias adds no new length limit. `server-` is 3 characters longer
  and could exceed 63 where the public host does not.
- **D-3 Not the container name.** `overdeck-<FEATURE_FOLDER>-server-1` depends on the compose project
  name, which callers can override with `-p` (`rebuild-stack.ts`, `uat-stack.ts`), and on the replica
  index. An explicit alias depends only on the template.
- **D-4 No renderer code change.** `{{FEATURE_FOLDER}}` already exists, and the UAT path already
  overrides it. The issue's "update the generator" is satisfied by the template edit plus a test that
  drives the real renderer functions (`createWorkspacePlaceholders` + `processTemplates`).
- **D-5 Network membership is unchanged.** `frontend` and `server` keep joining both `devnet` and
  `overdeck`. Traefik needs them on `overdeck`. Only the `server` entry changes from list form to map
  form so it can carry the `devnet` alias.
- **D-6 `vite.config.ts` stays as is.** Its container fallback `http://server:3011` runs only when
  `VITE_PROXY_TARGET` is unset, and every rendered stack sets it. A fallback cannot know the
  workspace's folder name, so it cannot be made unique.
- **D-7 No `changelog.d` entry.** The template is the Overdeck repository's own workspace template.
  It does not ship to Overdeck users' projects, so users see no change.
- **D-8 Existing stacks pick the fix up only through a re-render.** The renderer reads the template
  from the primary checkout (`concerns.md`, PAN-4663 entry), so the change reaches stacks only after
  merge. These paths re-render `.devcontainer/` from the template:
  - `pan workspace rebuild <issue>`: `rebuildWorkspaceStack` in `src/lib/workspace/rebuild-stack.ts`
    deletes `.devcontainer/`, calls `ensureDevcontainer`, then runs `up -d --build`.
  - Creating a new workspace.
  - Starting a UAT stack (`uat-stack.ts`).
  - The dashboard start/restart self-heal (`container-ops.ts`, `workspace-service.ts`), but only when
    the compose file is missing.

  `./dev rebuild`, `./dev up`, `docker compose up -d` and `docker restart` reuse the already-rendered
  file, so they keep `http://server:3013`.

## Requirements

- **FR-1** The rendered compose file sets the frontend's `VITE_PROXY_TARGET` to
  `http://api-<FEATURE_FOLDER>:<server PORT>`, a host that differs for every stack.
- **FR-2** The rendered `server` service declares that host as an alias on `devnet` and on no other
  network.
- **FR-3** `frontend` and `server` still join both `devnet` and `overdeck`. The Traefik labels are
  unchanged.
- **FR-4** A unit test renders two feature workspaces and one UAT batch through the renderer and
  checks FR-1 to FR-3. The test fails against the current template.
- **FR-5** The template README's Networks section explains the alias and why the bare `server` name
  must never be used as a target. The codebase map (`concerns.md`) records the hazard.
- **NFR-1** No change to `devcontainer-renderer.ts` and no new placeholder.
- **NFR-2** The alias is the same DNS label as the first label of the existing Traefik API host.
- **NFR-3** `docker compose config -q` accepts the rendered file (exit 0).

### WI-2 — Test: two rendered stacks never share a proxy target (FR-4)

New file: `tests/unit/lib/workspace/devcontainer-proxy-target.test.ts`.

Render through the real renderer functions. Do not call `renderDevcontainer`: it creates directories
under the real `~/.cache`. Use `createWorkspacePlaceholders` and `processTemplates` from
`src/lib/workspace/devcontainer-renderer.ts`, with a mapping so only the compose template is rendered:

```ts
import { mkdtempSync, readFileSync, rmSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join, resolve } from 'node:path';
import { afterEach, describe, expect, it } from 'vitest';
import { parse as parseYaml } from 'yaml';
import {
  createWorkspacePlaceholders,
  processTemplates,
} from '../../../../src/lib/workspace/devcontainer-renderer.js';
import type { ProjectConfig, TemplatePlaceholders } from '../../../../src/lib/workspace-config.js';

const TEMPLATE_DIR = 'infra/.devcontainer-template';
const COMPOSE = 'docker-compose.devcontainer.yml';

function render(featureName: string, overrides: Partial<TemplatePlaceholders> = {}) {
  const projectConfig = {
    name: 'overdeck',
    path: process.cwd(),
    workspace: { docker: { compose_template: TEMPLATE_DIR } },
  } as ProjectConfig;
  const out = mkdtempSync(join(tmpdir(), 'pan-5330-'));
  const placeholders = createWorkspacePlaceholders(projectConfig, featureName, out, overrides);
  processTemplates(resolve(TEMPLATE_DIR), out, placeholders, [
    { source: `${COMPOSE}.template`, target: COMPOSE },
  ]);
  return parseYaml(readFileSync(join(out, COMPOSE), 'utf-8'));
}
```

(Track the temp dirs and remove them in `afterEach` with `rmSync(dir, { recursive: true, force: true })`.
`readFileSync` here reads a rendered `.yml`, so `scripts/lint-source-introspection.sh` does not flag it.)

`render('alpha-bravo-1115', { FEATURE_FOLDER: 'uat-alpha-bravo-1115' })`. Write a small helper
