The project docs explicitly identify team-owned `.claude/commands/` and `.claude/agents/` files ([meta-repos.mdx](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5199/configuration/meta-repos.mdx), lines 33–42). Under WI-6, `?? .claude/agents/my-agent.md` or a manually created `?? .mcp.json` in a monorepo passes the start gate even though neither is proven Overdeck output. This breaks FR-6's real-change refusal. Scope the new tolerance to a confirmed polyrepo wrapper (or prove file provenance), and add a monorepo rejection case.

## blocks-the-design: Heal commits unrelated staged files

WI-4 reuses `commitPolyrepoWorkspaceGitignoreAsync` after checking only the status of `.gitignore`. That helper runs `git add .gitignore`, checks the *whole* index with `git diff --cached --quiet`, and runs `git commit` without a path restriction ([create.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5199/src/lib/workspace-manager/create.ts), lines 135–160). A wrapper with clean `.gitignore` and staged `notes.txt` passes the proposed precondition; the heal then commits `notes.txt` as workspace housekeeping, so the later dirty gate no longer sees it. Commit only `.gitignore` while preserving other staged entries, or refuse healing when the rest of the index is nonempty. Test with an unrelated staged file and verify it remains staged and the start gate still refuses it.

## sharpens-framing: Wrapper tracked-file claim is too broad

WI-8 requires the docs to say the wrapper's only tracked file is `.gitignore`. Planning can write the issue spec into the workspace's `.pan/specs/` ([planning-promotion.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5199/src/lib/overdeck/planning-promotion.ts), lines 196–209), and its commit function stages `.pan/` whenever that directory exists ([planning-promotion.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5199/src/lib/overdeck/planning-promotion.ts), lines 225–235 and 268–283). Say the wrapper tracks `.gitignore` and any planning artifacts committed there; code changes live in sub-repos. This also removes the false premise behind the heal's index-safety rationale.
