## Glossary

- **Model id** — the exact string Overdeck stores in config and passes to a harness, for example `mimo-v2.6-pro`.
- **`ModelId`** — the TypeScript union in `src/lib/settings.ts` (line 47). `MODEL_CAPABILITIES` is typed `Record<ModelId, ModelCapability>`, so every member of the union needs a capability row, and every capability row's key must be a member. This is why a retired id stays in its type union.
- **Capability row** — an entry in `MODEL_CAPABILITIES`. New rows go in `src/lib/model-capability-additions.ts` (`AUDITED_MODEL_ADDITIONS`). `src/lib/model-capabilities.ts` is at its file-size cap of 1422 lines and must not grow.
- **Retired id** — an id the provider shut down. It gets a `MODEL_DEPRECATIONS` row (`src/lib/model-deprecations.ts`), which is a **single-hop** map from the retired id to a live replacement. It leaves `PROVIDERS.<name>.models`, the settings available list and the pickers. Its capability, cost and class rows stay, so old transcripts still price.
- **Routing list** — the `[...].includes(modelId)` branch per provider in `getProviderForModel` (`src/lib/providers.ts`, lines 444–530). The issue text calls it `getProviderForModelSync`; that name exists only in comments. Retired ids **stay** in routing lists, following the OpenAI and Kimi precedent ("still routed so the deprecation-migration path can fire before remap").
- **`tierModels`** — the per-provider opus/sonnet/haiku slots. Claude Code launches export them as `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL`. `haikuModel` is the separate small-model field. Neither may name a dead id.
- **Slash carve-out** — an explicit check placed *before* the `modelId.includes('/')` OpenRouter catch-all, so a provider-native id that contains `/` does not route to OpenRouter. Precedent: `qwen/qwen3.6-plus` → Nous (`providers.ts:452`, `model-fallback.ts:267`).
- **Unranked skills** — the Muse precedent in `model-capability-additions.ts`: every skill is `0` except `'context-length'`, with notes saying "Capability scores are unranked pending evaluation." A score of zero keeps a model from being chosen automatically by skill, so the model stays opt-in.
- **Verification ledger** — the list of every verified fact with its URL, plus every item not changed because it could not be verified. It goes in `docs/MODEL-CONTEXT-AUDIT.md` and is copied into the PR body (issue AC 4).
- **Picker rows** — the dashboard catalog `MODELS_BY_PROVIDER` in `src/dashboard/frontend/src/components/Settings/modelCatalog.ts`. The server-derived catalog in `src/lib/settings-model-catalog.ts` builds rows only for providers in its `AvailableModelsApi` type. That type has no `xai`, `groq`, `cerebras` or `mistral` key, so those providers have rows only in `modelCatalog.ts`.

## Problem

MiMo, Groq and Cerebras ship only dead ids today, including in `tierModels` and `haikuModel` (`src/lib/providers.ts` lines 196–198, 266–268, 279–281). Every launch on those providers fails, and every Claude Code subagent on them fails. The dashboard's MiMo connection test also probes the dead `mimo-v2.5-pro` (`src/dashboard/server/routes/settings.ts` lines 426 and 675). The MiniMax, xAI, Mistral, Meta and Kimi entries are stale: current models are missing, and `kimi-code/kimi-for-coding` reports K2.7 facts while the CLI now serves K2.8 Preview with a 1M window and adjustable effort.

## Requirements

- **FR-1** No id in `PROVIDERS.mimo|groq|cerebras` `models`, `haikuModel` or `tierModels` is a retired id.
- **FR-2** Each retired id has a `MODEL_DEPRECATIONS` row whose target is a live id in the same provider's `models`, and a test asserts the migration.
- **FR-3** Each new id has a capability row, a `cost.ts` row, a class row, a `MODEL_PROVIDERS` row, a `FALLBACK_MAP` row and a picker row, and a test asserts `getProviderForModel(id).name`.

- **NFR-2** `src/lib/model-capabilities.ts` stays ≤1422 lines and `src/dashboard/server/routes/settings.ts` stays ≤1104 lines (file-size caps; check with `wc -l`).
