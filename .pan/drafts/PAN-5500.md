## Summary

The issue asks for a line-by-line accuracy audit of every published page in the **Overdeck Anywhere** navigation
groups (21 pages). The planning session already did the audit. Eight research passes read all 21 pages (6,122 lines)
against the code on the base. The planner then checked every change-table row mechanically: each grep anchor matches
its page exactly once, and each evidence file exists. The planner also re-checked these high-stakes claims by hand against primary
sources: the billing and plan claims (`services/account/src/entitlement.ts`, `grants.ts`,
`migrations/0001_init.sql`, `billing/catalog.ts`, `wrangler.jsonc`); the `## What comes next` deletion on
`remote-access` (`gh issue view` shows #4402, #4403, #4404 and #4645 closed); the webhook-triggers release
(`changelog.mdx:511`, v0.73.0); the v0.73.0 known limitations (`changelog.mdx:515`, with #4863 still open); the phone
store status (`apps/mobile/RELEASE.md:186`); the Grok MCP claim (`packages/contracts/src/harness-capabilities.ts:281-282`);
the `pan triggers remove` inbox gap (`src/dashboard/server/routes/triggers.ts:148`); and the anchor slug (probe below).

This PRD lists every wrong, stale or removed claim per page. Each one has the exact current text, the replacement text
and the code evidence (Appendices A to U). The planner's overrides are already patched into the appendix rows; the
Overrides section is the record of what changed and why. Every Missing bullet carries an `[ADD]` or `[SKIP]` tag. The
implementation agent applies the change tables and the overrides. It also removes the en and em dashes, fixes the
frontmatter, adds the help links, runs the Mintlify validators and writes a PR body with one note per page. It does not
need to re-research. It re-checks a claim only when a grep anchor no longer matches or when the code contradicts a
row (Common procedure step 0).

## Glossary

- **Anywhere group**: the two `docs.json` navigation groups that hold the 21 pages. `"group": "Overdeck Anywhere"`
  holds `anywhere` and ten `configuration/` pages (`session-vault`, `remote-access`, `linked-machines`,
  `shared-sessions`, `triggers`, `tailscale`, `mcp`, `bots`, `phone`, `push-notifications`). `"group": "Anywhere CLI"`
  holds ten `cli/` pages (`vault`, `pair`, `tailscale`, `account`, `share`, `devices`, `machines`, `token`, `mcp`,
  `triggers`). Each slug `<x>` is the file `<x>.mdx` at the repo root.
- **Claim**: any statement on a page a reader could act on. That includes a command or flag, a config key or default,
  a UI label or location, a file path, a behavior, a limit, a price, a list of supported harnesses or platforms, or a
  maturity label ("next release", "planned", "TestFlight", "experimental").
- **Primary source**: the code on the base (`git grep`), the commander definitions under `src/cli/`, `pan <verb>
  --help` (installed `pan` is 0.89.1, the same as the base; when `--help` and the commander source disagree, the
  source on the branch wins), `src/lib/config-yaml/defaults.ts`, the dashboard source under
  `src/dashboard/frontend/src/` and `src/dashboard/server/`, the Workers under `services/`, the phone app under
  `apps/mobile/`, and `changelog.mdx`. Other `.mdx` pages, `docs/*.md` and `README.md` are never proof.
- **Grep anchor**: the quoted current text in each change-table row (the "Current text" column). Line numbers drift as
  earlier edits land, so find the text with `grep -n -F '<anchor>' <page>.mdx`, not by line number. A few anchors are
  given as "the table row containing X" or as a `<Step title=...>` line: find those by that text.
- **Evidence line numbers are approximate.** The research passes cited `file:line`. Some cited lines are off by a few
  lines, and a few are off by more: the planner found `src/cli/commands/sharing/join.ts:216` (the URL line is really at
  146-152), `src/cli/commands/pairing-link.ts:85` (the `LOOPBACK_WARNING` constant is at line 16), and
  `src/lib/triggers/deliver.ts:189,339,358` (the rate-limit code is at about 39 and 186-207). Evidence given only as a
  file basename (for example `resume.ts`, `join.ts`, `triggers.ts`, `classify.ts`) means the file in the directory the
  same row or appendix names, found with `git ls-files | grep '/<basename>$'`. Search for the quoted code, not the line.
- **Dash rule**: no U+2013 (en dash) or U+2014 (em dash) anywhere in a touched page, frontmatter and body. Check:
  `grep -nP '[\x{2013}\x{2014}]' <page>.mdx` prints nothing. Replace a dash with a comma, colon, period, parentheses, or
  the word "to" for a range. Box-drawing characters such as `─` (U+2500) and the arrow `→` are not dashes.
- **Frontmatter rule**: `title` is specific and searchable; `description` is 50 to 160 characters (count the text
  between the quotes); neither contains a dash; a value that contains `: ` is double-quoted. When this PRD retitles a
  page, it also adds `sidebarTitle: "<the old title>"` so the navigation label stays short. All 21 descriptions already
  pass (measured below); none changes.
- **Help sentence**: the exact sentence D3 adds: "Still stuck? Ask on the [Overdeck
  Discord](https://discord.gg/ZpHE2ZTv5P) or file a [GitHub Issue](https://github.com/eltmon/overdeck/issues)."
- **Experimental**: a dashboard view hidden unless **Settings → Experimental → Experimental features** is on. The
  gated views are listed in `EXPERIMENTAL_TAB_IDS` in `src/dashboard/frontend/src/lib/experimentalFeatures.ts:4-15`
  (agents, autopreso, resources, sessions, metrics, costs, health, god-view). Two Anywhere pages mention gated views:
  the Costs page's **Machines** tab (`linked-machines`, Appendix C row 14) and the **Health** page (`remote-access`,
  Appendix N row 5). Nothing else in the group is experimental.
- **Follow-ups**: code bugs or out-of-scope doc problems found during the audit. They go in a `## Follow-ups` list in
  the PR body. This issue changes no code.
- **PR note**: a one-line summary of what changed on a page, or "verified, no change". Each page item puts its note in
  its commit message as a line `PR-note: <page>.mdx: <note>`; WI-Z1 collects them into the PR body.

## Common procedure for every page item

0. **Code wins.** If a primary source contradicts a row in this PRD (the research was wrong, or main moved), skip the
   row and record it in the PR note. Leave that row's acceptance criterion unticked with the evidence in the commit
   message (`pan task block` with the reason). Never write a claim the code contradicts to satisfy a row. Figures the
   code cannot confirm (competitor prices, storage costs, measured latencies) stay as they are unless a row changes them.
1. **Apply the change table** of the page's appendix, with the Overrides. For each row, find the grep anchor with
   `grep -n -F`, make the change, and keep the evidence in mind for the replacement wording. If an anchor no longer
   matches (another edit moved or reworded it), find the claim by meaning; if the claim is gone, skip the row and say
   so in the PR note. Literal `|` inside a table-cell replacement is written as a real pipe in the page table (the
   appendix escapes it as `\|` or `&#124;`).
2. **Add the Missing bullets** (FR-2, D9).
3. **Residual rule.** Read the whole page once. For a claim the appendix does not list that looks doubtful, verify it
   against a primary source; if the code disagrees, change the page to match the code. Do not chase claims that look
   right; the research passes verified them.
4. **Dashes.** Remove every en and em dash in the page or in the item's line range (dash rule), in the same commit.
5. **Frontmatter.** Apply the D4 title change with `sidebarTitle` if the page is in the D4 table; confirm the
   description is still 50 to 160 characters and dash-free.
6. **Help link.** Add the help sentence per D3.
7. **Links.** For each internal link, `ls <path>.mdx` (and `grep -n "^#.*<heading words>"` for an anchor), counting
   `docs.json` redirects. Fix any that fail. `npx -y mint@4.3.49 broken-links --check-anchors --files <page>.mdx` is
   the authoritative check.
8. **MDX safety.** Keep any new `<word>` placeholder inside backticks; write a new `$` price as `&#36;`.
9. **Commit** with `Item: <id>`, its AC trailers and `PR-note: <page>.mdx: <one line>`; push; `pan task done`.

#### Follow-ups
- Likely bug: after a dashboard restart, an agent's pending permission prompt notifies again, because its item has `askedAt: null` (`classify.ts:126`) and `primed()` returns false for null (`dispatcher.ts:285`), so it is dispatched instead of adopted. Untested (`tests/unit/lib/push/dispatcher.test.ts`). The doc row 3 states today's behavior.
- ntfy `Click` header sends `clickBaseUrl` + the item URL, which for a conversation item is `/m?subject=<conversation name>` (`ntfy-provider.ts:47`, `classify.ts:92-94,138`), so the conversation name does reach the ntfy server even though the page promises "Conversation titles ... never reach ntfy". Names are usually not titles, but check whether a user-named conversation leaks through.
- An agent that stops responding with no issue gets the public title `Failed · a conversation` (`classify.ts:164-166,198-216`), which is misleading for an agent; consider `Failed · an agent`.
- Low-disk notifications ignore the ntfy "titles only: kind plus issue id" rule by design (free GiB in the title); fine, but the classifier comment in `classify.ts:7-10` implies otherwise.
