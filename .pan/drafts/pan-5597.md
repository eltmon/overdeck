# PAN-5597: Order books page rework

**Issue:** https://github.com/eltmon/overdeck/issues/5597
**Clickable mockup (the visual spec):** `docs/design/mockups/order-books-rework-pan-5597.html`. Open it in a browser before you write any UI. Every screen, label and button in this PRD is in that file.

## Problem

The operator called the Order books page "really confusing". An audit of the live page on 2026-11-22 found these causes. Each one is verified against the code.

1. **The page never says which book is live.** The Flywheel releases work from one book: the first book with status `ready` (`currentOrderBook` in `src/lib/cloister/flywheel.ts`). The page shows four books as "Queued" and marks none of them. On the audit day the live book was a stale July book, and nothing on the page showed it.
2. **Three of the five lifecycle steps can never light up.** `LifecycleStrip.tsx` draws Draft → Ready → Running → Drained → Complete. Nothing in the product writes `running`, `drained` or `complete`: the only status write is `setStatus(…, 'ready')` (`src/dashboard/server/routes/orders.ts`, `src/cli/commands/orders.ts`), and `advanceQueue` in `src/lib/orders/writer.ts` has no caller.
3. **A finished book cannot be put away.** There is no way to unqueue, archive or rename a book from the page. A finished book stays `ready` and keeps the live slot. Old test books stay in the strip forever.
4. **A finished book looks broken.** `validateBookForStart` reports every closed issue as a blocking `issue-not-open` finding. A book with 23 of 23 issues landed shows 23 red errors, and a book with 26 of 28 landed cannot be started because "Start run" is disabled.
5. **Issue rows hide the issue.** Lanes sit side by side, so each row is narrow. Chips (`A1 · book`, `after PAN-…`, `PRD ✓`, state, three buttons) take the space and titles truncate to nothing. The Progress view shows no titles at all.
6. **Two views of one list.** Setup and Progress show the same issues with different columns. The Setup row state never shows "in pipeline" because `OrderBookPage.tsx` never passes `inFlightIssues` to `LaneEditor`.
7. **Jargon.** "Operator special orders executed with lane semantics", "Pickup posture OPEN", "DRAIN", "holds", "Drained = run ends", "Serial B-slot free" (shown on Lane A items too).
8. **Wrong copy.** Run settings says off-book pickup is "Blocked while this book runs" and names `pan start <id> --off-book`. `pan start` has no such flag (`src/cli/commands/start-register.ts`), and a manual `pan start` is not blocked (`configuration/order-books.mdx` says so).
9. **The main action is at the bottom.** Queue and Start live in the "Start validation" panel under the fold. Pickup posture appears twice: a read-only banner at the top and the real control at the bottom.
10. **Adding issues is split in two.** Two rails, each with its own lane toggle. The backlog rail shows the sequencer's `why` text, not the title, and the text overflows the card. "Drop issues here" suggests dragging from the rails, but rail rows are not draggable.

## Glossary

- **Book**: an order book. A JSON file under `<planHome>/.pan/orders/`, type `OrderBook` in `packages/contracts/src/orders.ts`.
- **Stored status**: the `status` field in the book file. Values in the schema: `draft`, `ready`, `running`, `drained`, `complete`. Only `draft`, `ready` and (after this change) `complete` are ever written.
- **Phase**: what the page shows for a book. Derived on every read, never stored. Values: `draft`, `active`, `queued`, `archived`.
- **Active book**: the book `currentOrderBook(books)` returns: the first book in index order with status `running`, else the first with status `ready`. Its issues count as operator-released for automatic pickup.
- **Queued book**: any other book with status `ready`.
- **Archived book**: a book with status `complete`. Its issues are free to join another book (`membership` in `src/lib/orders/resolver.ts` already skips `complete` books).
- **Finished**: every issue in the book is terminal (`progress.drained === true`) and the book has at least one issue. Derived.
- **Landed**: an issue that is closed. **Terminal**: closed, or carries the `parked` label.
- **Parallel lane**: Lane `A`. Up to `settings.laneAConcurrency` issues run at once.
- **One-at-a-time lane**: Lane `B`. One issue at a time, top to bottom.
- **Pickup paused**: `settings.posture === 'drain'`. **Pickup open**: `settings.posture === 'open'`.
- **Index order**: the order of entries in `.pan/orders/index.json`. `listBooks(panDir)` returns books in this order.
- **Plan home**: the repo that holds `.pan/` for a project.

## Decisions

- **D1. No new stored state.** The stored statuses and the book file shape do not change. Phase, queue position and "finished" are derived. This follows the repo's first rule: Overdeck stores no status it can derive.
- **D2. Dispatch does not change.** `currentOrderBook` keeps its rule. A finished book still holds the active slot until the operator archives it. The page makes that visible and fixes it in one click. Auto-advancing the queue is out of scope.
- **D3. No new HTTP routes.** The three new operator actions (unqueue, archive, restore) go through the existing `PATCH /api/orders/:id` route. No row is added to `tests/unit/lib/overdeck/no-loss-matrix.ts` and no entry to `route-scopes.ts`.
- **D4. One view.** The Setup/Progress toggle is removed. One issue list shows order, options and live state.
- **D5. Lane letters stay as a secondary label.** The CLI and the Flywheel skill use `--lane A|B` and positions like `B3`. The page names lanes in plain words and shows `Lane A` / `Lane B` as a small tag.
- **D6. Queue order is index order.** Reordering the queue is out of scope. To run a later book first, move the earlier books back to draft.
- **D7. The server computes the phase.** The frontend must not re-derive it, so the page cannot disagree with dispatch.

   ```ts

   export interface OrderBookPhaseView {
     phase: OrderBookPhase;
     /** 1-based place among books with status running or ready, in index order. Null for draft and archived. */
     queuePosition: number | null;
     /** Every issue is terminal and the book has at least one issue. */
     finished: boolean;
   }

   export function deriveBookPhases(
     books: readonly OrderBook[],
     progressOf: (book: OrderBook) => { total: number; drained: boolean },
   ): Map<string, OrderBookPhaseView>
   ```

   Rules, in this order, for each book:

   - `finished = progress.total > 0 && progress.drained` for every phase.
