# PAN-4320 — Dashboard serves every Herdr agent as stopped

**Issue:** [PAN-4320](https://github.com/eltmon/overdeck/issues/4320)
**Planned against:** `feature/pan-4320` @ `48cff86be2e` (2026-09-28)

## Summary

On the Herdr terminal backend the dashboard shows every managed agent as stopped. The issue
blamed the event-driven pane inventory for dropping `agentId`. Live investigation shows that is
a secondary defect. The primary defect is a **join-key bug**: six server sites join an agent id
to a backend pane by `pane.terminalId ?? pane.id`. On Herdr those values are `term_65c8…` and
`wKZ:p3`, never an agent id. `docs/TERMINAL-BACKENDS.md` (section "Pane metadata") already
states the correct rule: *match `pane.agentId === agent.id`, never `pane.id`*. The six sites
violate it.

The fix adds one shared join helper in `@overdeck/contracts`, moves every violating site onto
it, makes the Herdr event path carry `agentId` (and the real `terminalId`), and stops the
enrichment poller from skipping on a Herdr host that has no tmux server.

## Glossary

- **Herdr** — the default terminal backend. Agents run in Herdr panes. A pane has a pane id
  (`wKZ:p3`), a terminal id (`term_65c8b78d3f05a5df`), and metadata tokens.
- **Pane tokens** — key/value strings each launcher stamps on its pane: `issue`, `role`,
  `harness`, `model`, and `agentId` (the Overdeck agent id, e.g. `agent-pan-4311`).
- **`BackendPane`** — one pane as the dashboard's inventory sees it
  (`packages/contracts/src/backend-pane.ts`). Fields: `id` (backend pane handle), `agentId?`,
  `issue?`, `role`, `harness`, `model`, `state`, `stateSince?`, `terminalId?`, `workspace?`.
- **Backend inventory** — `src/dashboard/server/services/backend-inventory.ts`. It reads the
  backend's `list()` snapshot (TTL 5 s, `getBackendPanes()`) and folds the backend's event
  stream onto it (`BackendPaneCache.apply`). The read model holds the result as
  `backendPanesById`.
- **List path** — `HerdrBackend.list()` in `src/lib/terminal-backends/herdr.ts` →
  `paneFromBackendSnapshot()` in `src/lib/overdeck/derived-issue-state.ts`. Sets
  `agentId` from `agentIdOf(pane)` and `terminalId` from Herdr's `terminal_id`.
- **Event path** — `toBackendEvents()` in `herdr.ts` → `BackendPaneCache.apply()`. Today it sets
  neither `agentId` nor the real `terminalId`.
- **`agentsById`** — the read model's agent rows. Seeded once at dashboard boot from the agents
  resolver. Rows for agents started *after* boot enter only through an `agent.created` or
  `agent.started` event.
- **Served status** — the agent status the dashboard actually sends. `GET /api/agents` computes
  it per request in `routes/agents/listing.ts`. The `/ws/rpc` snapshot computes it in
  `deriveServedAgentStatuses()` (`src/dashboard/server/read-model.ts`), which only *downgrades*
  a stored `running`/`starting` row to `stopped` when no live pane matches.
- **Enrichment poller** — `src/dashboard/server/services/agent-enrichment-service.ts`
  `pollOnce()`, every 10 s. For each registered agent with a live pane it emits `agent.created`
  the first time it sees the agent, then `agent.enrichment_changed`.
- **PTY supervisor** — `dist/pty-supervisor.js`, a wrapper that posts `session-started` →
  `agent.started`. **Herdr work agents do not run under it** (the launcher `exec`s Claude Code so
  Herdr can detect it), so on Herdr the enrichment `agent.created` is the *only* way a
  post-boot agent enters `agentsById`.
- **Agent key** — the id a pane answers for: `pane.agentId ?? pane.terminalId ?? pane.id`.
- **Peer dashboard** — a second dashboard process started with `OVERDECK_DISABLE_DEACON=1`. It
  serves read-only, polls no trackers, and emits enrichment events in memory only (PAN-1817,
  PAN-3931). Used here for live verification on a spare port.

5. `agent-pan-4311`'s `claude` process has parent `/bin/bash` under the Herdr server (pid 2023),

### Root-cause chain

- `pollOnce()` builds `livePaneIds` from `pane.terminalId ?? pane.id`
  (`agent-enrichment-service.ts`, line 196), so no Herdr agent passes
  `livePaneIds.has(a.id)`, and `agent.created` never fires → the agent never enters
  `agentsById` → the `/ws/rpc` snapshot, God View, and Command Deck never see it.
- `GET /api/agents` keys `paneById` by `pane.terminalId ?? pane.id`
  (`routes/agents/listing.ts`, line 79), so every Herdr agent reads "no pane" → `stopped`.
- Same wrong key in `/api/agents/:id/tmux-alive` (`listing.ts`, line 330),
  `agent-state-service.ts` runtime seed (line 139), `agent-projection.ts` `paneAlreadyExited`
  (line 220), and `resource-refresh-triggers.ts` `issueForAgent` (line 87).
- Latent co-cause: `shouldSkipEnrichmentCycle()` (`agent-enrichment-service.ts`, line 128) skips
  the whole poll when `tmux -L overdeck list-panes -a` fails. This host still runs legacy `conv-*`
  tmux sessions, so it passes here. On a clean Herdr host with no tmux server the poller never
  runs, and no post-boot agent could ever get `agent.created` even with the key fixed.
- Secondary: the event path. `pane-created` stores `terminalId: event.paneId` and no `agentId`;
  `metadata` copies `issue`/`role`/`harness`/`model` but not `agentId`. The next 5 s TTL
  refresh replaces the cache from `list()` and repairs it, which is why the snapshot panes
  showed `agentId`. Between refreshes, an event-created pane answers for no agent.

### Answers to the issue's "confirm" questions

- **Which path feeds `backendPanesById` at serve time?** Both. `getBackendPanes()` rebuilds the
  cache from `list()` whenever a caller asks after the 5 s TTL. The enrichment poller calls it
  every 10 s, and `GET /api/agents` and `getSnapshot` call it too, so the refresh does run
  without a UI caller. Events fold onto the cache between refreshes. Both paths publish through
  `publishDelta` → `onBackendPanesChanged` (`read-model.ts`, around line 709).
- **Do pane keys collide or duplicate?** No. Both paths key the cache by the Herdr pane id
  (`snapshot.paneId` / `event.paneId`), so one pane is one row.
- **`deriveServedAgentStatuses()`** already consults `pane.agentId` (`read-model.ts`, lines
  301–305). It is correct and is not changed. It serves `stopped` only because the rows are
  missing or the stored status is stale, which the enrichment fix addresses.

## Requirements

- **FR-1** — One shared join rule. `packages/contracts/src/backend-pane.ts` exports
  `paneAgentKey(pane)` = `pane.agentId ?? pane.terminalId ?? pane.id` and
  `indexPanesByAgentKey(panes)`, which returns a `Map<string, BackendPane>` where, when two panes
  share a key, a non-exited pane replaces an exited one and never the reverse.
- **FR-2** — `GET /api/agents` and `GET /api/agents/:id/tmux-alive` find an agent's pane through
  `indexPanesByAgentKey`. A Herdr agent with a live pane is served with `hasLivePane: true` and a
  live status (`healthy`/`warning`); an agent whose only pane is exited is served `stopped`.
- **FR-3** — The enrichment poller treats an agent as live when `indexPanesByAgentKey` maps its id
  to a non-exited pane **and** its stored status is `running` or `starting`. A Herdr agent started
  after boot gets `agent.created` on the first poll that sees its live pane; a stored-`stopped`
  agent whose Herdr pane outlived the stop gets nothing.
- **FR-4** — The agent-state runtime seed keys each runtime snapshot by `paneAgentKey(pane)`.
- **FR-5** — `paneAlreadyExited` (agent projection) and the default `issueForAgent` (resource
  refresh triggers) find the pane through `indexPanesByAgentKey`.
- **FR-6** — The Herdr `pane-created` and `metadata` backend events carry optional `agentId`
  (computed by `agentIdOf`, the same rule as `list()`) and `pane-created` carries the Herdr
  `terminalId`. `BackendPaneCache.apply` records them, so an event-created pane answers for its
  agent without waiting for the TTL refresh.
- **FR-7** — The enrichment skip gate follows the host backend policy: under Herdr it skips only
  while the backend inventory is degraded (`isBackendInventoryDegraded()`); under tmux it keeps
  skipping when tmux census evidence is unavailable.
- **FR-8** — Docs state the agent-key rule, the prefer-live collision rule, and the immediate
  event-path `agentId`.
- **NFR-1** — Every new test builds Herdr-shaped panes: `id: 'wKZ:p3'`,
  `terminalId: 'term_65c8b78d3f05a5df'`, `agentId: 'agent-pan-4311'`. A tmux-shaped fixture
  (`terminalId` equal to the agent id) is what let this bug pass the existing suite.
- **NFR-2** — `src/lib/terminal-backends/herdr.ts` is exactly 1000 lines, the file-size ceiling.
  The change to it must be net-zero lines (see Work Item 7).
- **NFR-3** — No new synchronous child-process calls in server-reachable code; no frontend
  change.

## Decisions (made here; do not re-decide)

1. **Helper lives in `@overdeck/contracts`.** Server code already imports `BackendPane` from
   there, and a later frontend consumer can reuse it. File: `packages/contracts/src/backend-pane.ts`
   (already re-exported by `packages/contracts/src/index.ts`, line 29).
2. **Key fallback `pane.agentId ?? pane.terminalId ?? pane.id`.** Real tmux panes always carry
   `agentId` (`tmuxProbeToPane` sets it to the session name). On Herdr, `term_…`/`wX:pN` never
   equal an agent id, so the fallback is harmless for untokened panes and keeps existing
   tmux-shaped test fixtures valid.
3. **Collision rule: non-exited wins.** A restarted Herdr agent can leave an exited pane with the
   same `agentId` token beside its live one. A plain `new Map(panes.map(...))` keeps whichever
   comes last and could serve a live agent as stopped. Among several non-exited panes, the first
   one seen is kept.
4. **`deriveServedAgentStatuses()` is not changed.** It already matches `pane.agentId`.
5. **Census gate is in scope (FR-7).** Without it, AC-1 is false on any Herdr host with no tmux
   server. The PAN-3055 rationale ("no liveness evidence ⇒ no liveness claims") is kept: on Herdr
   the evidence is a non-degraded backend inventory.
6. **`herdr.ts` edit is net-zero lines.** The spreads go onto the existing `return`/`push` lines
   in `toBackendEvents`. If formatting makes that impossible, add the audited allowlist row
   `<new line count> src/lib/terminal-backends/herdr.ts # PAN-4320` to
   `scripts/file-size-allowlist.txt` in the same commit (fallback only).
7. **Live verification uses a peer dashboard on port 3497**, never a restart or reload of the
   primary dashboard on :3011 (only the flywheel deploys).

### WI-1 — Shared agent-key helper (FR-1, NFR-1)

**File:** `packages/contracts/src/backend-pane.ts`. Append after `export type BackendPane = …`:

```ts
/**
 * The agent id a pane answers for (PAN-4320). On Herdr `id` (`w1:p1`) and
 * `terminalId` (`term_…`) are backend handles, never agent ids, so the
 * `agentId` token decides; tmux panes carry `agentId` = session name.
 */
export function paneAgentKey(pane: BackendPane): string {
  return pane.agentId ?? pane.terminalId ?? pane.id
}

/**
 * Panes by agent key. When two panes answer for one agent (a restarted Herdr
 * agent beside its exited pane), a non-exited pane wins, never the reverse.
 */
export function indexPanesByAgentKey(panes: Iterable<BackendPane>): Map<string, BackendPane> {
  const byKey = new Map<string, BackendPane>()
  for (const pane of panes) {
    const key = paneAgentKey(pane)
    const prior = byKey.get(key)
    if (!prior || (prior.state === "exited" && pane.state !== "exited")) byKey.set(key, pane)
  }
  return byKey
}
```

Match the file's style: no semicolons, double-quoted strings (as in the snippet).

**Test (new):** `packages/contracts/src/__tests__/backend-pane.test.ts` (root vitest includes
`packages/**/src/__tests__/**/*.test.ts`). Cases:

- Exited pane then live pane with the same `agentId` → index holds the live pane; the reverse
