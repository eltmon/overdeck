## Glossary

- **Overlay surface:** the background of a modal dialog panel. It must be lighter than `--background` in both light and dark mode so the panel reads as raised.
- **Overlay tokens:** the four new CSS custom properties `--surface-overlay`, `--surface-overlay-field`, `--border-overlay`, `--overlay-scrim`.
- **Four-scope contract:** a theme-varying token is declared in four blocks placed after `:root`/`.dark` in `index.css`: `[data-theme="ledger"]`, `[data-theme="broadsheet"]`, `.dark[data-theme="ledger"], .dark [data-theme="ledger"]`, `.dark[data-theme="broadsheet"], .dark [data-theme="broadsheet"]`. Source: `design/style-guide/STYLE-GUIDE.md` §4a and the banner comment at `src/dashboard/frontend/src/index.css` line ~319 (`PAN-3706 — Broadsheet completion`).
- **Ledger / Broadsheet:** the two design languages. Ledger is frozen legacy; it receives the new tokens with values that keep its current look. Broadsheet is the default.
- **Scrim:** the translucent full-viewport layer behind a modal.
- **Modal primitive:** the new shared component `src/dashboard/frontend/src/components/shared/Modal.tsx`.
- **Bottom sheet:** the Modal's layout below 600px viewport width: panel aligned to the viewport bottom, full width, top corners rounded, no bottom border.
- **Pinned slot:** a Modal region between the scrolling body and the footer that never scrolls (used for the error alert).
- **Frontend test subset:** `scripts/frontend-test-subset.txt`. CI runs ONLY the frontend Vitest files listed there (root Vitest excludes `src/dashboard/frontend/**`). A new frontend test file is invisible to CI unless it is added there, one path per line, relative to `src/dashboard/frontend`, in sorted position. The file is `merge=union` in `.gitattributes`, so concurrent additions merge cleanly.
- **FR-5 of PAN-4486:** the dialog never writes the sidebar's stored model/harness/effort/context choices (localStorage).

## Problem (verified 2026-11-01 at `f0fbe1d4a8d`)

1. `.dialog` in `src/dashboard/frontend/src/components/newConversation/NewConversationDialog.module.css` uses `background: var(--popover, var(--background))`. Under Broadsheet light, `--popover` is `hsl(30 8% 94.5%)` and `--background` is `hsl(0 0% 96.5%)` (`index.css` line 426/430, block `[data-theme="broadsheet"] {` starting line 425). The dialog is darker than the page.
2. The dialog has no `box-shadow`, although `--shadow-overlay` exists (`index.css` lines 741/751/762/773). The backdrop is `rgb(0 0 0 / 0.32)`.
3. Imported themes repeat the flaw: `applyUiTokens` (`src/dashboard/frontend/src/hooks/useColorTheme.ts` line 60, grep `function applyUiTokens`) sets `--popover` from `ui.surface`, and `src/lib/color-themes/vscode-import.ts` (grep `sideBar.background`) fills `ui.surface` from VS Code's `sideBar.background`. VS Code's own dialog surface is `quickInput.background` (fallback `editorWidget.background`).
4. Ragged layout: `.row` is `display: flex; justify-content: space-between` with `white-space: nowrap` labels, so each control starts at a different x. The First message field sits under a long skills list and falls below the viewport.

## Decisions (made here; the executor does not re-decide)

- **D1 — Weights.** The mockup's 620 (title) and 550 (option labels) are outside the Broadsheet tiers. Use 600 for the Modal `h2` and section `h3`; 500 for labels, option labels, buttons and segmented items; 400 for body text.
- **D2 — No theme-branched CSS.** The mockup's `.dark .after .segmented button[aria-checked="true"] { background: hsl(30 3% 26%) }` is dropped. The checked segment is `background: var(--surface-overlay); box-shadow: var(--shadow-sm), 0 0 0 1px var(--border-overlay)` in every mode. The mockup's `.harness-glyph { color: #d97757 }` is dropped (HarnessSelect already renders `HarnessLogo`).
- **D3 — Modal is portaled** to `document.body` with `createPortal`, so a future caller inside an `overflow: hidden` or transformed container still covers the viewport. z-index of the scrim: 100 (unchanged from today).
- **D4 — Form panel.** Modal takes an optional `onSubmit`. When present, the panel element is a `<form onSubmit>` so a `type="submit"` button in the footer slot submits it. Otherwise the panel is a `<div>`.
- **D5 — Escape is handled by React `onKeyDown` on the panel** (panel has `tabIndex={-1}`), not a window listener. A child that calls `event.stopPropagation()` on Escape (IssuePickerField does when its list is open, `IssuePickerField.tsx` grep `if (open) event.stopPropagation()`) keeps the dialog open, as today.
- **D6 — Scrim click** closes only when the press started on the scrim (`onMouseDown` target === currentTarget) and the click target is the scrim. A text selection dragged out of the panel does not close the dialog.
- **D7 — Initial focus**: the first focusable element inside the body slot; if none, the panel itself. Focusable = `a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])`, excluding elements inside a `[hidden]` ancestor.
- **D8 — Tab trap** is hand-rolled (no focus-trap dependency exists in `src/dashboard/frontend/package.json`). On Tab from the last focusable → focus the first; Shift+Tab from the first (or from the panel) → focus the last; `preventDefault()` in both cases. The close button is part of the cycle.
- **D9 — `dismissible={false}`** disables Escape, scrim click AND the close button (`disabled`). The dialog passes `dismissible={!submitting}`.
- **D10 — Unscoped fallbacks.** No `:root`/`.dark` rows are added for the overlay tokens (so the existing no-loss test in `src/dashboard/frontend/src/__tests__/index-css-theme-scopes.test.ts` is untouched). Instead, every overlay-token read in module CSS carries a fallback: `var(--surface-overlay, var(--popover))`, `var(--surface-overlay-field, var(--background))`, `var(--border-overlay, var(--border))`, `var(--overlay-scrim, rgb(0 0 0 / 0.4))`.
- **D11 — Model/Harness pickers in the grid.** `ModelSelect` and `HarnessSelect` (`components/shared/ModelPicker/ModelPicker.tsx` lines 238/321) get an optional `labelId?: string` prop. When set, the component renders only the `.pickerWrap` (no `.field` wrapper, no `.fieldLabel` span), and the trigger button gets `id={buttonId}` (from `useId`) and `aria-labelledby={`${labelId} ${buttonId}`}` so its name is "Model <current value>". Visual fit comes from CSS custom properties with fallbacks in `ModelPicker.module.css` `.pickerBtn`: `background: var(--picker-bg, var(--muted)); border: 1px solid var(--picker-border, var(--border)); border-radius: var(--picker-radius, 4px); min-height: var(--picker-height, auto); font-size: var(--picker-font-size, 12px);`. The dialog's grid sets those variables. Every other caller (ForkModal, ModelHarnessPicker, sidebar) renders identically because the fallbacks equal today's values.
- **D12 — Skills summary data.** `ConversationSkillsField.tsx` exports `useConversationSkillGroups(projectKey?, issueId?)` (the existing `useQuery` with the existing key `['new-conversation-skills', projectKey ?? '', issueId ?? '']`) and a pure `summarizeSkills(groups, overrides) → { on, total, overrides }`. The field and the dialog both call the hook; React Query dedupes the fetch. The field stays mounted while collapsed (inside `<div hidden>`), so its existing prune effect (drop overrides for skills no longer listed) keeps running.
- **D13 — Effort radios** are plain buttons, all in the tab order (the same pattern as the skills Inherit/On/Off radiogroup in `ConversationSkillsField.tsx`). No roving tabindex, no arrow-key handling. The resolved default level carries `data-default="true"` and a 3px dot `<span aria-hidden="true">`.
- **D14 — Footer summary** is one plain string joined by `' · '` (space, U+00B7, space): `<model> · <harness label> · <effort> · <project key | "No project">`. `<model>` is the raw model id state (e.g. `claude-opus-5-5`). `<harness label>` comes from `HARNESS_OPTIONS` (exported from `components/shared/ModelPicker`), falling back to the raw id. `<effort>` is `effort ?? effortDefault?.effort ?? '…'`; the segment is omitted when the model has no effort levels. Hidden below 600px.
- **D15 — Imported overlay is opaque.** `vscode-import.ts` passes the mapped overlay color through `toOpaqueHex` (exported from `@overdeck/contracts`), because a translucent modal surface would show the page through it. Other `ui` keys are unchanged.
- **D16 — Browser checks are UAT, not a committed e2e spec.** The issue's Playwright checks (computed background, shadow, structure at 360px) are verified by the test role in an isolated Playwright browser profile against the running dashboard. The token-level half (overlay lighter than background, contrast) is committed as a parse-and-assert unit test.
- **D17 — Size.** The issue is operator-approved as one unit. It touches about 29 files across 7 path-subsystems, but code lives in three (`src/dashboard`, `src/lib`, `packages/contracts`); the rest are docs and the test-subset list. The plan sets `plan.metadata.sizeJustification` rather than splitting FR-4 into a sibling issue.

API:

```tsx
export interface ModalProps {
  title: string;
  description?: string;
  onClose: () => void;
  /** false disables Escape, scrim click and the close button (default true). */
  dismissible?: boolean;
  /** When set, the panel renders as a <form> so a submit button in `footer` submits it. */
  onSubmit?: (event: FormEvent<HTMLFormElement>) => void;
  /** Non-scrolling region above the footer, e.g. an error alert. */
  pinned?: ReactNode;
  footer?: ReactNode;
  children: ReactNode;
}
export function Modal(props: ModalProps): ReactPortal
```

Structure (rendered with `createPortal(…, document.body)`):

```tsx
<div className={styles.scrim} data-component="modal-scrim" onMouseDown={…} onClick={…}>
  <Panel /* form when onSubmit, else div */ ref={panelRef} role="dialog" aria-modal="true"
    aria-labelledby={titleId} aria-describedby={description ? descriptionId : undefined}
    tabIndex={-1} className={styles.panel} data-component="modal" onKeyDown={onKeyDown} onSubmit={onSubmit}>
    <div className={styles.header}>
      <div className={styles.titles}>

      </div>
      <button type="button" className={styles.close} aria-label="Close" onClick={onClose} disabled={!dismissible}><X size={16} /></button>

    <div ref={bodyRef} className={styles.body}>{children}</div>
```

### WI-4 Skills summary data (D12)

Files: `components/newConversation/ConversationSkillsField.tsx`, `__tests__/ConversationSkillsField.test.tsx`.

```ts
export function useConversationSkillGroups(projectKey?: string, issueId?: string) {
  return useQuery({
    queryKey: ['new-conversation-skills', projectKey ?? '', issueId ?? ''],
    queryFn: () => fetchSkillGroups(projectKey, issueId),
  });
}

export function summarizeSkills(groups: readonly SkillGroup[], overrides: Record<string, boolean>): { on: number; total: number; overrides: number } {
  const rows = groups.flatMap((group) => group.rows);
  const on = rows.filter((row) => (Object.prototype.hasOwnProperty.call(overrides, row.id) ? overrides[row.id] : row.enabled)).length;
  return { on, total: rows.length, overrides: Object.keys(overrides).length };
}
```
