## 1. Glossary

| Term | Meaning in this document |
|------|--------------------------|
| **Deft / Directive** | Deft Directive, the process engine at `github.com/eltmon/directive` (fork of `deftai/directive`). Its CLI is `directive` (global launcher npm package `@deftai/directive`) plus `deft` (project runtime `@deftai/directive-runtime`). |
| **Deposit** | The files `directive install` (alias `init`) writes into a repository (section 3.2). |
| **Directive project** | A repository whose committed tree already holds a deposit. Detected by `detectDirectiveProject()` in `src/lib/deft/detect.ts`. |
| **Pipeline (of an issue)** | Which process drives an issue: `overdeck` (default; plan → work → verification → review → test → merge) or `deft` (Deft's build → pre-PR → PR; Overdeck only merges). |
| **Issue override file** | `<planHome>/.pan/skill-overrides/<ISSUE>.yaml`, written only by `src/lib/skill-overrides/store.ts`. Today it holds `skills:` and `packs:` maps. This issue adds a `pipeline:` key. |
| **Temporary install** | A deposit that Overdeck creates inside one issue worktree of a project that is **not** a Directive project, then hides from git. |
| **Install snapshot** | The JSON record `<worktree>/.overdeck/deft-install.json` written right after a temporary install. It lists every path the install touched, the pre-install and post-install content of each, and the git config Overdeck changed. Undo, the lift, the drift detector, and the merge guard read it. |
| **Hide** | The three git operations that make a temporary install invisible to `git status`: a worktree-scoped exclude file, `skip-worktree` flags, and a worktree-scoped `core.hooksPath`. |
| **Worktree config** | git's per-worktree config file (`<gitdir>/config.worktree`), enabled by `extensions.worktreeConfig=true` and written with `git config --worktree`. |
| **Lift** | Temporarily undoing the hide around an Overdeck git operation in the worktree (rebase, sync-main), then re-applying it (section 6, WI-4). |
| **Merge guard** | The pre-merge check that refuses a Deft issue's PR when its diff contains a deposit path, when hidden files drifted, or when the Deft state archive is stale (WI-5, WI-6). |
| **Drift** | A skip-worktree path whose current worktree content differs from its post-install content. git silently ignores such edits, so they would never reach a commit. |
| **Deft state archive** | `<worktree>/.pan/deft/<ISSUE>/`, committed on the feature branch: copies of the issue's scope xBRIEFs, decision records, approved-scope records, and escalations (WI-12). |
| **Scope xBRIEF** | Deft's unit of work: `xbrief/{proposed,pending,active,completed,cancelled}/*.xbrief.json`. Folder and `plan.status` must agree. |
| **Escalation** | `.deft/escalations/<id>.json`, Deft's request for a human decision (section 3.3). |
| **Deterministic menu** | Deft's numbered plain-text menu whose last two options are `N-1. Discuss` and `N. Back` (section 3.4). |
| **Heartbeat** | `.deft-scratch/subagent-status/<agent-id>.json`, a Deft subagent's status record. |
| **Run summary** | Deft's JSONL telemetry stream, enabled by `DEFT_RUN_SUMMARY_PATH`. Its `check_invocation` events carry gate results. |
| **Approval at head** | Overdeck's merge rule that a trusted verdict marker or GitHub review must approve the PR's exact head commit (`evaluateIssueMergeGate`, `src/lib/cloister/merge-gate.ts`). |
| **Operator decision** | A `pan ask`-style journal entry (`requestOperatorDecision`, `src/lib/cloister/operator-decision.ts:107`) that shows in Needs-you until answered. |

## 2. Problem and goal

An operator wants to run **one issue** on Deft Directive's own way of working inside Overdeck, see Deft's state on the dashboard's existing surfaces, and switch the issue back to Overdeck's pipeline at any time. Nothing from the Directive install may be merged into the repository. Other issues in the same project keep Overdeck's pipeline.

Today `features/skill-packs.mdx` ("Deft Directive", the level table) says Overdeck "never runs a Deft CLI" and does not target "Full Deft". This issue changes that decision for the per-issue Deft mode only. The read-only `deft` pack keeps its rule.

### 3.2 Directive v0.129.3 (read from source)

- **Install command:** `directive install [--repair] [--target-version <exact>] [--package-manager npm|pnpm] [--dry-run] [--yes] [--root <path>]`. `init` is an alias (`packages/cli/src/launcher.ts:45-51`).
  - Without a TTY it requires `--yes` (`bookends.ts:410-438`, exit 2).
  - It needs the network: `npm view @deftai/directive-runtime version` unless `--target-version` is given, then `npm install --save-dev --save-exact --ignore-scripts …` (`cli/src/pm.ts:611-618`).
  - There is no harness flag: hosts come from policy, and all four are on by default.
  - `--root` must be the git toplevel.
  - The `directive` binary is **not** on this machine's PATH. Run it with `npx --yes @deftai/directive`.
- **What install writes:**
  - `package.json` (created as `{ "private": true }` if absent) with an exact devDependency pin on `@deftai/directive-runtime`, plus a lockfile.
  - `.gitignore` gets `node_modules/` and `.deft/directive/wiring-ready.*.json` appended.
  - `AGENTS.md` gets a managed section between `<!-- deft:managed-section` and `<!-- /deft:managed-section -->`.
  - Pointer skills `deft` and `deft-directive-{setup,build,review-cycle,refinement,swarm,interview,portfolio-priority,pre-pr,sync}` under each of `.agents/skills`, `.claude/skills`, `.cursor/skills`, `.codex/skills`, `.github/skills`.
  - Slash wrappers named `deft-*` under `.claude/commands/`, `.cursor/commands/`, `.grok/commands/`, `.codex/prompts/`.
  - Hook registrations in `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`, `.grok/hooks/deft.json`, with outer scripts `.claude/deft-hook-<sha8>.mjs`, `.codex/deft-hook-<sha8>.mjs`, `.cursor/hooks/deft-hook-<sha8>.mjs`, `.grok/hooks/deft-hook-<sha8>.mjs`.
  - `.githooks/{_directive-run.sh,pre-commit,pre-push}`, then `git config core.hooksPath .githooks`. That command writes the **shared** repo config, and install refuses when the key holds any other value.
  - `Taskfile.yml` gets an `includes.deft` entry.
  - The `xbrief/` tree: `.directive-seed-placeholder`, five lifecycle folders with `.gitkeep`, and a minimal `PROJECT-DEFINITION.xbrief.json`.
  - `.deft/directive/data-schema.json`, `.deft/GENERATION.json`, `.deft/directive/wiring-ready.<V>.json`.
  - It then **runs `git add` on the files it wrote** and does not commit (`runtime/src/setup.ts:502-507`).
- **Uninstall** keeps `xbrief/` and settings. Overdeck does not use it: our own snapshot-based undo is exact.
- **`DEFT_ORCHESTRATOR`** has zero references. **`.deft-directive-disable`** is honored from v0.92.0 when untracked.
- **Pre-push hook** refuses a push unless a `pre-pr:run` pass is bound to HEAD (`pre-pr/SKILL.md:104-108`). Any Overdeck push from the worktree hits it unless the hooks path is lifted.

### 3.3 Directive file shapes (fixture sources)

- **Escalation** `.deft/escalations/<id>.json`:
  - Fields: `schemaVersion: 1`, `id` (`esc-<YYYYMMDDHHMMSS>-<6hex>`), `agentId`, `type`, `title`, `body`, `contextRefs: string[]`, `createdAt`, `slaHours`, `status: "open"|"resolved"`, `dangerous: boolean`, `resolution: null | { decision, resolvedAt, resolvedBy, note, answer }`.
  - `type` is one of `cmd_approval`(1h), `design_decision`(4h), `approval`(4h), `resource`(4h), `external`(72h), `question`(24h). `decision` is one of `approved|denied|answered|dismissed`.
  - Resolution rewrites the same file in place. The agent polls the file.
  - Snake_case aliases are accepted on read.
- **Heartbeat:**
  - Required: `agent_id`, `parent_id`, `last_heartbeat_at`, `last_message`, `phase` (one of `starting|implementing|validating|committing|pushing|polling|fixing|terminal`).
  - Optional: `terminal_state`, `pr_number`, `extra`, `wait_kind`, `head_sha`.
- **Scope xBRIEF:**
  - Per item: `x-directive/evidence = { kind, pointer, recorded_at, recorded_by }` and `x-directive/disposition = { disposition: waived|deferred|not_applicable, reason, provenance: { kind: operator-cli|operator-session|human-event, actor }, recorded_at }`.
  - Swarm metadata: `plan.metadata.swarm.{readiness, parallel_safe, file_scope[], verify_commands[], expected_outputs[], depends_on[], conflict_group, size, file_scope_confidence, model_tier}`.
  - Delivery: `plan.metadata.handoffState` (`implemented|pr_open|merged_to_integration|delivered`), `plan.metadata.deliveryDisposition`, `plan.metadata.productPullRequest`.
- **Decision record** `xbrief/decisions/*.decision.json`: `schemaVersion: "deft.decision.v1"`, `id`, `decision`, `governingRule{description,path?,rfc2119?}`, `alternativesConsidered[{option,whyNot?}]`, `whyWinner`, `confidence`, `activeScopeRefs[]`, `timestamp`, `revisitTrigger`, `tags?`, `relatedIssues?`.
- **Approved scope** `.deft/approved-scope/<planId>.json`: `schemaVersion:1`, `xbriefRelPath`, `planId`, `approvedAt`, `fileScope[]`, `fileScopeDigest`, `humanApproval?{kind,actor,mintedAt,mintedVia?}`.
- **Policy:** `plan["x-directive/policy"]` in `xbrief/PROJECT-DEFINITION.xbrief.json` (legacy key `plan.policy`).
  - `requireHumanMerge` resolution: a typed boolean wins; a malformed value fails closed to true; else `autoDeployOnMerge === true` gives true; else false.
- **Spec drift ledger** `xbrief/.audit/spec-drift-ledger.json`: `unresolved[] {scopeId, reason, specImpact, completedAt, uncoveredItemIds?}`, `coverage[]`, `baselineRevision`.
- **Finish loop** `.deft-cache/finish-loop-progress.jsonl`, one object per line: `schemaVersion:1, ts, phase (gate|queue-scan|implement|pr-open|pr-watch|address|merge|halt), iteration, haltReason|null, message, prNumber|null, exitCode|null`.
- **Run summary:** `DEFT_RUN_SUMMARY_PATH=<path>` appends JSONL. Base fields: `schema_version, session_id, framework_version, seq, ts, event`.
- **Deft installs no PostToolUse hook.** Its hook events are `session.start, session.compact, tool.before, prompt.submit, agent.response`.

### 3.4 Deterministic menu rule (Directive `content/contracts/deterministic-questions.md:18-24`)

- Each option label visibly includes its canonical number (`1. Accept`).
- The final two labels are `N-1. Discuss` and `N. Back`.
- A reply matches only the displayed number or the exact displayed label.
- Deft renders the menu as plain chat text, because Overdeck's host UI is not on its known-preserving list. So the menu reaches Overdeck only as assistant transcript text.

### 3.5 git behavior (probed on a scratch repo with two worktrees, git 2.43.0)

- With `extensions.worktreeConfig=true`, `git config --worktree core.hooksPath .githooks` and `git config --worktree core.excludesFile <file>` apply to that worktree only. A sibling worktree shows no `core.hooksPath` and no skip-worktree entries, and the main checkout shows none.
- `git update-index --skip-worktree <file>` affects only that worktree's index.
- **`git merge main` and `git rebase main` abort** ("Please commit your changes or stash them…") when the target branch changed a skip-worktree file. This is hazard H1 and is handled by the lift (WI-4).
- A worktree `core.excludesFile` **replaces** the user's global excludes file (this machine has `~/.config/git/ignore`). The worktree exclude file must start with a copy of the effective global excludes.

It does not install. | One write door for the install. The prompt builder stays free of side effects. |
| AD-3 | A Deft issue with no workspace xBRIEF gets a one-item **placeholder plan** written by `writeAutoStartXBrief` with title `Deliver through Deft Directive`, so the existing `pan start` and dashboard 422 checks pass without edits. `start.ts` cannot grow. `back` deletes the placeholder, so `pan start` then routes the issue to Overdeck planning. | AD-4 | **Approval waiver.** For a Deft issue, `evaluateIssueMergeGate` defaults `requireApprovalAtHead` to `false`, and `deriveState` treats `deftPipeline === true` as approved. The strike-merge waiver is the precedent. The person clicking Merge is the approval. |
| AD-5 | Overdeck's verification gate (typecheck/lint before review) is **not** run for Deft issues. `startRequestReviewPipeline` returns `{ started: false, reason: 'deft-pipeline' }` before it transitions the issue or journals anything. | Deft's pre-push hook already enforces `pre-pr:run` at HEAD. CI still gates the merge. Journaling `review.requested` would make the Deacon re-request every tick. |
| AD-6 | `spawnRun` throws `DeftPipelineRoleRefusedError` for roles `review` and `test` when the issue's pipeline is `deft`, as the backstop. `spawnReviewRoleForIssueBody` returns `{ success: true, message }` before it spawns. | Covers every review and test entry point (webhook, lifecycle, Deacon, convoy, direct). |
| AD-7 | The **lift** (WI-4) runs inside `rebaseFeatureBranch` and around each `syncRepo` call. It is a no-op when no install snapshot exists. | H1: skip-worktree aborts rebase and merge. H2: Deft's pre-push hook blocks Overdeck's own push. |
| AD-8 | **Switch-back restores the pre-install content** recorded in the snapshot for tracked files. For a file that the lift re-based, it restores the snapshot's `restoreContent`, which the lift updates to the new HEAD content. | D7 says "pre-install content". The lift keeps that value correct across rebases. |
| AD-9 | **Gate telemetry** comes from Deft's run summary, not from a PostToolUse hook. In Deft mode the env file carries the literal token line `DEFT_RUN_SUMMARY_PATH=overdeck`. The launcher allowlist maps it to `export DEFT_RUN_SUMMARY_PATH="$PWD/.overdeck/deft-run-summary.jsonl"`. | Deft has no PostToolUse hook (3.3). The run summary carries per-gate status and exit codes for both Claude Code and Codex. The literal token keeps the allowlist injection-proof. |
| AD-10 | **Escalation answers:** Overdeck rewrites the escalation file in place with `status: "resolved"` and `resolution: { decision, resolvedAt, resolvedBy: "operator:<name>", note, answer }`, using an atomic temp file plus rename. It then delivers a one-line notice to the agent with `deliverAgentMessage`. It refuses an already-resolved escalation (409). | This matches `deft escalation:resolve` semantics without running a Deft CLI from the server. The agent polls the file. The notice is the fallback the issue names. |
| AD-11 | **Deterministic menus** are parsed from the last assistant text in the agent's Claude Code transcript (`getAgentJsonlPath`). They are offered as a pending question with tool id prefix `deft-menu:` and a single select. The answer delivers the exact label text, for example `2. The dialog keeps labels verbatim, but the generic answer path wraps them in prose. |
| AD-12 | **Acceptance sign-off:** for a scope item whose `x-directive/disposition` has no provenance, or whose `provenance.kind` is not one of `operator-cli|operator-session|human-event`, the xBRIEF tab shows **Sign off**. | AD-13 | The **Deft state archive** is written by `pan skills deft save <ISSUE>` into `<worktree>/.pan/deft/<ISSUE>/` with subfolders `scopes/<folder>/`, `decisions/`, `approved-scope/`, `escalations/`, then committed on the feature branch. The merge guard refuses when the archive at the PR head differs from what `save` would write. | D5 says "at completion and at switch-back". ## 5. Requirements

### Functional

- **FR-1** An issue's pipeline is read from `pipeline:` in its issue override file. Absent or `overdeck` means Overdeck. `deft` means Deft. Skill and pack toggle writes preserve the key.
- **FR-2** `pan skills deft use <ISSUE>` in a non-Directive project creates the workspace if missing, runs the Directive install in that worktree, and hides every change. Right afterwards `git status --porcelain` in the worktree prints nothing.
- **FR-3** After FR-2, no other worktree of the repository and not the primary checkout shows a Deft hook path, a skip-worktree flag, or a Deft file.
- **FR-4** `pan skills deft back <ISSUE>` stops the issue's agents and saves the Deft state archive. - **FR-5** The merge guard refuses a Deft issue's PR whose diff contains a snapshot path or a known deposit path, whose hidden files drifted, or whose archive is stale. Every merge door (Merge button, auto-merge, queue, merge-ready set, forge-merge) applies it.
- **FR-6** A Deft issue's open, green, mergeable PR derives `ready` (awaiting merge) without an Overdeck approval. Merge needs no approval at head.
- **FR-7** Overdeck dispatches no review, test, or verification for a Deft issue. A PR-opened webhook leaves no `review.requested` journal entry.

- **FR-10** A Deft issue's work kickoff points the agent at the `deft-directive-build` skill and the issue's scope xBRIEF in `xbrief/active/`, tells it to continue into Deft's review cycle after PR open when a supported bot reviewer exists and otherwise stop, and never refers to Overdeck's plan checklist.
- **FR-11** In a Directive project, Deft mode performs no install and no hide, and turns the kill switch off. Overdeck mode keeps the existing kill-switch behavior.
- **FR-12** Rebase and sync-main in a Deft worktree succeed when main changed a skip-worktree file, and the install stays hidden afterwards.
- **FR-13** *(Moved to PAN-4849; retired here.)* `GET /api/issues/:id/deft` returns the issue's Directive state parsed from its worktree files: scopes, escalations, heartbeats, decisions, approved scope, policy, spec drift, finish loop, and gate runs. ### WI-2 `install-and-hide` — temporary install, snapshot, hide (foundation)

**Files:** new `src/lib/deft/install.ts`, new `src/lib/deft/install-snapshot.ts`.

**Snapshot type** (`install-snapshot.ts`), stored at `<worktree>/.overdeck/deft-install.json`:

```ts
export interface DeftInstallSnapshot {
  version: 1;
  issueId: string;
  installedAt: string;
  runtimeVersion: string | null;          // from package.json devDependencies['@deftai/directive-runtime']
  /** Paths that did not exist before install (relative, '/'-separated; dirs end with '/'). */
  createdPaths: string[];
  /** Tracked paths whose content install changed; skip-worktree'd. */
  modifiedTracked: Array<{ path: string; restoreContentB64: string; postInstallSha256: string; baseBlob: string }>;
  /** Pre-existing untracked or ignored files whose content install changed (for example an ignored .claude/settings.json). */
  modifiedUntracked: Array<{ path: string; restoreContentB64: string; postInstallSha256: string }>;
  /** Pre-existing untracked/ignored directories install wrote into (for example node_modules/): never deleted wholesale. */
  touchedPreexisting: string[];
  sharedHooksPathBefore: string | null;   // value of `git config --local --get core.hooksPath` before install
  excludeFile: string;                    // absolute path of the worktree exclude file
}
export function deftSnapshotPath(worktree: string): string;
export async function readDeftSnapshot(worktree: string): Promise<DeftInstallSnapshot | null>;
export async function writeDeftSnapshot(worktree: string, s: DeftInstallSnapshot): Promise<void>; // temp + rename
```

**`installDeftIntoWorktree(worktree, issueId, deps)`** steps. `deps.runInstall` defaults to the AD-1 command; tests inject it.
1. Return early in three cases:
   - `readDeftSnapshot` already returns a snapshot: return it (idempotent).
   - `detectDirectiveProject(worktree).isDirectiveProject` is true: return `{ mode: 'directive-project' }`.
   - `git diff --cached --quiet` exits non-zero (staged changes) or `git ls-files -u` prints anything (unmerged paths): refuse with "commit or discard staged changes first". Step 5's `git reset -q` would otherwise unstage the operator's work.
   Pre-existing unstaged or untracked changes are allowed. They are recorded in step 2. A fresh Overdeck workspace normally has none.
2. Record `before`:
   - the file list from `git status --porcelain=v1 -z --ignored=matching --untracked-files=all`;
   - a map path → sha256 (plus the bytes, kept in memory) of the worktree content for every **file** that is tracked (`git ls-files -z`), untracked, or ignored in that listing. Skip entries the listing collapses to a directory (for example `node_modules/`).
   - `sharedHooksPathBefore = git config --local --get core.hooksPath`.
   If the shared value is set and is not `.githooks`, set `git config --worktree core.hooksPath .githooks` first (after enabling `extensions.worktreeConfig`), so install sees `.githooks` and does not refuse.
3. Run the install (AD-1). On non-zero exit, return an error with the last 20 lines of stderr. Undo with WI-3's restore using a snapshot computed from steps 4-5 when any change exists.
4. Restore the shared config:
   - if `sharedHooksPathBefore === null`, run `git config --local --unset core.hooksPath`; otherwise run `git config --local core.hooksPath <before>`.
   - Then run `git config extensions.worktreeConfig true` and `git config --worktree core.hooksPath .githooks`.
5. Run `git reset -q` (unstage what install added; the index is per worktree). Run `installPreRebaseHook(worktree)` again (its target followed the hooks path).
6. Compute `after` with the same commands as step 2.
   - `createdPaths` = paths in `after` not in `before`. Collapse a directory to `dir/` when every file under it is new.
   - `modifiedTracked` = tracked paths whose sha256 changed. Store `restoreContentB64` = the bytes before install (read in step 2; for tracked files, read `git show :<path>` when the worktree file was clean), `postInstallSha256`, and `baseBlob` = `git rev-parse HEAD:<path>`.
   - `modifiedUntracked` = untracked or ignored **files** from `before` whose sha256 changed. Store the pre-install bytes and `postInstallSha256`. They are not hidden: they showed in the same state before the install.
   - `touchedPreexisting` = ignored or untracked directories in `before` whose subtree now contains `node_modules/@deftai/`.
7. Hide:
   - Write the exclude file at `<gitdir>/info/overdeck-deft-exclude` (`git rev-parse --git-dir`, which is per worktree). Its content: a copy of the effective global excludes file (`git config --global --get core.excludesFile`, else `$XDG_CONFIG_HOME/git/ignore`, else `~/.config/git/ignore`, when it exists), a `# overdeck:deft <ISSUE>` marker line, the three Overdeck runtime lines `/.overdeck/deft-install.json`, `/.overdeck/deft-run-summary.jsonl` and `/.overdeck/deft-lift/` (`.overdeck/` is not ignored in every project, and is partly tracked in this repo), then one anchored line `/<path>` per created path.
   - Run `git config --worktree core.excludesFile <file>`.
   - Run `git update-index --skip-worktree -- <each modifiedTracked path>`.
8. Write the snapshot, then assert that every `git status --porcelain` line after hiding was already present in the `before` listing, and that no line names a snapshot path. In a clean worktree that means the status is empty. If not, return an error that lists the extra lines (the snapshot stays so `back` can undo).

**Tests** (`install.test.ts`): a scratch repo, two worktrees, and a fake `runInstall` that writes a representative deposit (AGENTS.md section, `.claude/settings.json` change, `.githooks/pre-push`, `xbrief/active/.gitkeep`, `package.json` pin, `git add -A`, `git config core.hooksPath .githooks`). ### WI-3 `uninstall-restore` — undo a temporary install

**File:** new `src/lib/deft/uninstall.ts`.

**`removeDeftInstall(worktree): Promise<{ removed: string[]; restored: string[] }>`:**
1. Read the snapshot. With none, return empty.
2. For each `modifiedTracked` path: `git update-index --no-skip-worktree -- <path>`, then write `restoreContentB64` bytes to the file.
3. For each `createdPaths` entry: resolve it inside the worktree, refuse anything that escapes (`path.relative` starts with `..`), then `rm({ recursive: true, force: true })`.
4. For each `modifiedUntracked` entry, write `restoreContentB64` bytes back. For each `touchedPreexisting` entry, remove only `<entry>/@deftai/` (for example `node_modules/@deftai/`). Delete `.overdeck/deft-run-summary.jsonl` and `.overdeck/deft-lift/` when present.
5. `git config --worktree --unset core.hooksPath` and `git config --worktree --unset core.excludesFile` (ignore exit 5, "key not set"). Delete the exclude file. Leave `extensions.worktreeConfig` on (AD-17).
6. Run `installPreRebaseHook(worktree)` again, then delete the snapshot file.

### WI-4 `lift-around-git-ops` — rebase and sync-main with a hidden install

**Files:** new `src/lib/deft/lift.ts`, `src/lib/cloister/merge-rebase.ts`, `src/lib/cloister/sync-main-workspace.ts`.

**`withDeftInstallLifted<T>(worktree, targetRef: string, fn: () => Promise<T>): Promise<T>`:**
1. With no snapshot, return `fn()`.
2. Refuse with `DeftLiftError` when any `createdPaths` entry exists in `targetRef` (`git cat-file -e <targetRef>:<path>`). Message: `main now tracks Deft install path <p>; switch the issue back to Overdeck`.
3. Prepare the worktree:
   - Save each `modifiedTracked` file's current bytes in memory.
   - Run `git update-index --no-skip-worktree` on it, then `git checkout HEAD -- <path>`.
   - Run `git config --worktree --unset core.hooksPath`.
4. `try { return await fn() } finally {` re-apply: for each modified file, if `git rev-parse HEAD:<path>` equals `baseBlob`, write the saved bytes back. Otherwise write the three versions to temp files under `<worktree>/.overdeck/deft-lift/` (`current` = the new HEAD content from `git show HEAD:<path>`, `base` = `git cat-file blob <baseBlob>`, `other` = the saved bytes) and run `git merge-file -p <current> <base> <other>`, async `execFile`; exit 0 is a clean merge, a positive exit is the conflict count:
   - Clean merge → write the result, set `baseBlob` to the new blob and `restoreContentB64` to the new HEAD content, and update `postInstallSha256`.
   - Conflict → write the saved bytes and add the path to `snapshot.liftConflicts`.
   Then `git update-index --skip-worktree`, `git config --worktree core.hooksPath .githooks`, and write the snapshot. `}`

**Call sites:**
- `rebaseFeatureBranch` wraps its `rebaseFeatureBranchBody(...)` call: `try: () => withDeftInstallLifted(workspacePath, \`origin/${baseBranch}\`, () => rebaseFeatureBranchBody(...))`.
- `syncMainAcrossWorkspaceRepos` wraps `syncRepo(root.dir, …)` the same way, with `origin/${root.targetBranch}`.

**Rules, in order:**
1. `directiveProject` → `{ ok: true }` (AD-14).
2. `drifted.length > 0` → refuse: `Deft-hidden files were edited and are in no commit: <paths>. Switch back to Overdeck or ask the operator.`
3. Deposit paths. All prefix matches are from the repo root; `.pan/deft/<ISSUE>/…` never matches. A changed path matches when it:
   - equals or sits under any snapshot `createdPaths`/`modifiedTracked` path;
   - starts with `.deft/`, `.deft-scratch/`, `.deft-cache/`, `xbrief/`, or `.githooks/`;
   - matches `^\.(agents|claude|cursor|codex|github)/skills/deft(-directive-[^/]+)?/`, `^\.(claude|cursor|grok)/commands/deft-` or `^\.codex/prompts/deft-`, or `^\.(claude|codex)/deft-hook-[^/]+\.mjs$` or `^\.(cursor|grok)/hooks/deft`;
   - is `AGENTS.md` and its head content contains `<!-- deft:managed-section`;
   - is `package.json` and its head content contains `"@deftai/directive`;
   - is `Taskfile.yml` and its head content contains `@deftai/directive-runtime`;
   - is `.gitignore` and its head content contains `.deft/directive/wiring-ready`.
   On a match, refuse: `PR contains Deft install paths: <paths>`.
4. `!archiveCurrent` → refuse: `Deft state is not saved at the PR head; run pan skills deft save <ISSUE>`.

**Reads:**
- `readPrChangedPaths(worktree, baseRef, headSha)`: `git diff --name-only -z <baseRef>...<headSha>`, async `execFile`, 15 s.
- `readHeadFile(worktree, headSha, path)`: `git show <headSha>:<path>`, null on error.
- `detectDrift(worktree, snapshot)`: sha256 of each `modifiedTracked` file in the worktree compared with `postInstallSha256`.

**`deftMergeGuardForIssue(issueId, headSha | null): Promise<DeftGuardVerdict & { drifted: string[] }>`** composes the reads. ### WI-13 `switch-use-back` — the two switch operations

**File:** new `src/lib/deft/switch.ts`.

**`useDeftPipeline(issueId, { deps })`:**

1. Stop the agents (same as use step 2).

3. Run `removeDeftInstall`.
4. `setIssuePipeline(issueId, 'overdeck')`.

## 8. Hazards

- **H1 Skip-worktree vs rebase.** Handled by WI-4. A conflict in `git merge-file` keeps the old install content and records `liftConflicts`, which `show` prints.
- **H2 Deft pre-push hook blocks Overdeck pushes.** The lift unsets the worktree hooks path for the duration. The work agent's own pushes are meant to go through Deft's hook.
- **H3 `git add` ignores skip-worktree files.** An agent edit to a hidden tracked file is silently dropped. Drift detection (WI-5) plus the kickoff text (WI-11) and the operator decision (WI-6) cover it.
- **H4 Install writes the shared `core.hooksPath`.** WI-2 step 4 restores it within the same call. For a few seconds during install, sibling worktrees see `.githooks`. That window is accepted and documented.
- **H5 Global excludes replaced.** WI-2 step 7 seeds the exclude file with the global excludes.
- **H6 Detection flips after install.** `resolveDeftLaunch` would compute a kill switch for the worktree. WI-10 makes the pipeline input win.
- **H7 Network and package manager.** Install needs npm and the registry. A Bun project gets npm's `package-lock.json` (hidden as a created path). Recorded by WI-0.
- **H8 roles/work.md still loads for Deft work agents.** It describes Overdeck's task loop. The Deft kickoff says explicitly that those steps do not apply.
- **H9 File-size caps.** See the table in 3.1. `start.ts` is not touched. If an edit would exceed a cap, extract a helper into a new module in the same item. Never raise an allowlist row.
- **H10 Polyrepo, remote.** Refused (AD-16).
- **H11 Agent-run rebase.** Deft tooling or the agent may run `git rebase` itself, which aborts on skip-worktree files. The kickoff tells the agent to use `pan sync-main`, which is lifted.
- **H12 Conflict repair.** `evaluateConflictRepairGate` still requires approval at head, so a conflicting Deft PR is not auto-repaired. The agent resolves conflicts through `pan sync-main`. This is accepted for v1.
- **H14 Loader file reads.** WI-7 adds one `readIssuePipeline` call per issue in `loadIssueStatesForProject`. That is one small file read per issue per board refresh, and most return ENOENT. This is expected and is not a regression.
- **H13 Guard cost.** The merge-ready set evaluates the gate often. Each Deft evaluation runs one local `git diff --name-only` plus small `git show` reads, with no forge call. This is accepted.
