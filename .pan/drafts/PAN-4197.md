# PAN-4197 — Agents page: a live view of what is running and what is waiting

**Issue:** [PAN-4197](https://github.com/eltmon/overdeck/issues/4197)
**Status:** planned (auto-planning, 2026-09-25)
**Operator direction:** the issue body plus the 2026-09-25 "scope narrowed" comment. Where they differ, the comment wins (it is later and narrower).

## Summary

`/agents` today opens a three-pane Directory (default) with Grid / Table / Timeline behind a segmented control. The Grid is a graveyard: it keeps every strike agent that is not `dead` and labels it `STRIKE RUNNING` by role alone, so 119 finished strikes render as running while the header says "1 active". Table and Timeline are "Coming soon" stubs. The Directory mixes finished rows with live ones behind a 24h/7d window nobody explains, and every pane has a fixed width. The palette gives no state signal.

This issue replaces the page with a **Live view** that answers four questions at a glance: what is running now and is it progressing, what is stuck or needs me, what is waiting in the pipeline and on what, and where the finished history went. The existing Directory survives as the **History** view behind one link, with resizable panes and an explained window. A small system-wide set of **state color tokens** gives running, needs-you, stuck, waiting and done one color each, in light and dark, with checked contrast.

## Glossary

- **Live view** — the new default content of `/agents`: three sections (Needs you, Live, Waiting) in a resizable list pane, plus a resizable, collapsible preview pane.
- **History view** — the existing Agents Directory (`components/Agents/directory/AgentsDirectory.tsx`), reached at `/agents?view=history`. It keeps its tree/list/detail panes and its 24h/7d window.
- **Directory entry** — one row of `GET /api/agent-directory` (`DirectoryEntry` in `packages/contracts/src/agent-directory.ts`). Its `state` (`working | idle | blocked | done | stopped | unknown`) is derived from the terminal backend's pane inventory on every read, never from stored status.
- **Live scope** — the new `GET /api/agent-directory?scope=live` answer: only the entries the Live view shows (rule in FR-2).
- **Pause gate** — the `paused` / `pausedBy` / `yieldedByScheduler` / `pausedReason` / `pausedAt` fields in `~/.overdeck/agents/<id>/state.json`. The gate is itself the stored fact (it is what blocks resume), so reading it is not "reading stored status". `isOperatorPause()` (`src/lib/agents/agent-state-read.ts`, line 230) is the one test for an operator pause.
- **Held** — a pause gate set by a machine: the preemptive scheduler's yield (`yieldedByScheduler: true`) or any other non-operator pause (memory-governor shed, post-merge, escalation, Fly migration). "Resource governor" in the issue maps here.
- **Derived issue state** — `DerivedIssueState` (`packages/contracts/src/derived-issue-state.ts`): `state` (`backlog … working, in-review, changes-requested, ready, merged, closed`), optional `attention` (`needs-you | stuck | api-error`), optional `pr` with `checks` (`green | red | pending`). Computed at read time; the server holds it in `getSharedIssueService().listDerivedStates()` (`src/dashboard/server/services/issue-data-service.ts`, line 1049); the frontend holds it in the store as `derivedIssueStateByIssueId` (`useDerivedIssueState`, `src/dashboard/frontend/src/lib/store.ts`, line 313).
- **Runtime snapshot** — `agentRuntimeById[agentId]` in the store (`AgentRuntimeSnapshot`, `packages/contracts/src/types.ts`, line 268): `activity` (`working | thinking | waiting | idle | stopped`), `currentTool`, `thinking.since`, `lastActivity`. Updated in real time over `/ws/rpc`.
- **Agent output** — `agentOutputById[agentId]` in the store: the latest terminal lines per agent.
- **Issue agent** — a directory entry with `kind: 'agent'`, a non-null `issueId`, and `role` `work` or `strike`. Derived issue attention and pipeline state describe this agent (same rule as `ISSUE_AGENT_ROLES` in `components/Agents/directory/directory-state.ts`, line 32).
- **State tokens** — the new CSS custom properties `--state-live`, `--state-needs-you`, `--state-stuck`, `--state-waiting`, `--state-done`, each with a `-foreground` text variant.
- **Four-scope contract** — the style guide's rule that a token that differs by *theme* (Ledger vs Broadsheet) needs four selector blocks. State tokens differ only by light/dark, like `--info` today, so they live in `:root` and `.dark` only.

## Requirements

### Functional

- **FR-1** `/agents` with no `view` param renders the Live view. `/agents?view=history` renders the existing Directory. Any other `view` value (`directory`, `grid`, `table`, `timeline`, junk) renders the Live view; `?view=directory` is treated as `history` for old links.
- **FR-2** `GET /api/agent-directory?scope=live` returns `{ generatedAt, windowHours: 0, scope: 'live', entries }` where an entry is kept when any of these holds, then every ancestor of a kept entry is re-added:
  1. `isLiveDirectoryState(entry.state)` (working, idle, blocked, unknown);
  2. the entry is a native agent with a pause gate (`entry.pause` present) and its issue's derived state is not `merged` or `closed` (an entry with no issue is kept);
  3. the entry is the newest (by `startedAt`, then `id`) issue agent (`role` `work` or `strike`, `kind: 'agent'`) of an issue whose derived state is `in-review`, `changes-requested` or `ready`.
  A subagent entry with state `done` and any other `stopped`/`done` entry is dropped. `windowHours` is ignored when `scope=live`; a `scope` value other than `live` answers 400.
- **FR-3** Every native agent entry whose state.json has `paused: true` carries `pause: { by, reason, since }` with `by` = `operator` when `isOperatorPause(state)`, `scheduler` when `yieldedByScheduler === true`, else `machine`; `reason` = `pausedReason ?? null`; `since` = `pausedAt ?? yieldedAt ?? null`. No other entry carries `pause`. The windowed (history) answer carries it too.
- **FR-4** The Live view groups rows into three sections in this order: **Needs you**, **Live**, **Waiting**. Each row gets exactly one reason from the precedence table in Work item 3; the reason decides the section and the state tone.
- **FR-5** A Live row shows what the agent is doing now: `running <tool>` from the runtime snapshot's `currentTool`, `thinking` while `activity === 'thinking'`, else `working`; the last non-empty line of its agent output (ANSI stripped, one line, truncated); and the time since it last produced anything. When that time exceeds 5 minutes the row adds `· quiet <age>` in muted text.
- **FR-6** A Needs-you or Waiting row states exactly what it waits on, in words: `question waiting`, `permission prompt`, `plan approval`, `paused by you`, `API error or usage limit`, `stuck · idle <N>h`, `ready to merge`, `CI failed`, `changes requested`, `in review`, `CI running`, `held by Overdeck`, `idle — no known blocker`, `agent stopped`. `paused by you` and `held by Overdeck` show `pause.reason` as detail when present; a question shows the pending question prompt as detail when the agent snapshot has one.
- **FR-7** Rows sort: Needs you oldest wait first; Live and Waiting most recent activity first; ties by entry id.
- **FR-8** Subagent entries render nested (indented, `↳`) directly under their parent row and are not counted as their own rows. A subagent whose parent is not on the page is dropped.
- **FR-9** Selecting a row (click, or ↑/↓ in the focused list) shows it in the preview pane using the existing `DirectoryDetail` (header, issue context, live transcript, composer where allowed). Enter, double-click, or the row's **Open** button navigates to the agent's live pane or conversation via `navigateToDecisionSubject`; the button is hidden when `decisionSubjectPath` returns null. The selected entry id lives in the URL as `?entry=<id>` (replaceState).
- **FR-10** The Live view's list and preview panes are resizable with `react-resizable-panels`; sizes persist in `localStorage` under the layout id `agents-live`; the preview pane is collapsible (drag below min, or a **Hide preview / Show preview** button).
- **FR-11** The page header shows `<n> live · <m> need you · <k> waiting` and one link, **History**, to `/agents?view=history`. The History view header shows one link, **Live**, back to `/agents`. The Grid, Table, Timeline, metric tiles, phase/project/model filters and the segmented control are removed.
- **FR-12** The History view's tree, list and detail panes are resizable with `react-resizable-panels`, persisted under layout id `agents-directory`; the tree pane is collapsible.
- **FR-13** The History view explains its window and counts: under the 24h/7d toggle the tree shows `Live agents always show. Finished ones show if active in the last 24 hours.` (or `7 days`), and each node's count carries `title="<live> live of <total> shown"` and an `aria-label` with the same words.
- **FR-14** State tokens `--state-live`, `--state-needs-you`, `--state-stuck`, `--state-waiting`, `--state-done` and their `-foreground` variants exist in `index.css` `:root` and `.dark`, with utilities `.badge-bg-state-<s>`, `.badge-border-state-<s>`, `.text-state-<s>` and `.bg-state-<s>` for each of the five states. The Live view and `DirectoryStateBadge` use them; running is blue, never green.
- **FR-15** Empty Live view (no rows) reads `Nothing is running or waiting. Finished work is in History.` with the History link.

### Non-functional

- **NFR-1** Every `-foreground` state token has WCAG contrast ≥ 4.5:1 against `--background` and `--card` of all four surfaces (Ledger light `#ffffff`, Broadsheet light `hsl(0 0% 96.5%)` / `hsl(30 8% 94.5%)`, Ledger dark `#080b10` / `#0c1018`, Broadsheet dark `hsl(0 0% 12.5%)` / `hsl(0 0% 17%)`), enforced by a unit test that parses `index.css`.
- **NFR-2** One colored signal per row (style guide "Color restraint"): the state glyph and its left rail share one tone; all other row text is `text-foreground` / `text-muted-foreground`.
- **NFR-3** No new stored state. The live scope is derived on read and memoized 3 s like the window answer; nothing is written.
- **NFR-4** The Live view polls `scope=live` every 5 s while visible and refetches early on pane-inventory changes, reusing `useAgentDirectory`'s throttle; activity text updates in real time from the store without waiting for a poll.
- **NFR-5** Light and dark both render correctly under Broadsheet (the default theme) and Ledger; no theme-conditional markup.

## Decisions

- **D1 — The Live view reads the directory, not a new model.** It fetches `GET /api/agent-directory?scope=live` so it reuses the existing liveness-derived `state` (pane inventory = what `src/lib/agents/liveness.ts` and the backend adapter answer), labels, issue titles, transcript refs, subagents, workers, conversations and remote agents, and reuses `DirectoryDetail` for the preview. Section and reason are classified on the client from the entry plus real-time store facts (runtime snapshot, agent output, derived issue state, agent snapshot pending inputs), in one pure module.
- **D2 — Delete the Grid, Table and Timeline; don't fix them.** The Grid is the graveyard bug and duplicates Command Deck; Table and Timeline are stubs. `primitives/AgentCard.tsx` and its test go with the Grid (our change orphans them). `VerbBadge` stays (other surfaces use it).
- **D3 — The Directory is the History link.** The operator allowed "one small link out to the existing history views"; the Directory is that view and keeps its behavior. It gains resizable panes and window/count wording only.
- **D4 — Reason precedence** is fixed in Work item 3's table. It puts human-actionable facts first (blocked input, operator pause, broken agent, ready to merge), then machine work, then pipeline waits.
- **D5 — `ready` is Needs you.** The shipping role prepares a merge "for human merge"; an approved PR with green checks waits on the operator.
- **D6 — CI failed is Waiting with the stuck (red) tone.** Red means broken; the work agent, not the operator, is sent the failure, so the row does not sit in Needs you.
- **D7 — Held (scheduler/machine pause) is Waiting, neutral; operator pause is Needs you, amber.** Amber means a human must act; only an operator pause needs the operator to unpause.
- **D8 — Colors: five state tokens aliased to the signal semantics.** live = info blue, needs-you = warning amber, stuck = destructive red, waiting = warm neutral, done = success emerald. Exact values (all pass NFR-1; ratios computed in planning):

  | Token | Light base / foreground | Dark base / foreground |
  | --- | --- | --- |
  | `--state-live` | `#2563eb` / `#1d4ed8` | `#3b82f6` / `#60a5fa` |
  | `--state-needs-you` | `#d97706` / `#92400e` | `#f59e0b` / `#fbbf24` |
  | `--state-stuck` | `#dc2626` / `#b91c1c` | `#ef4444` / `#f87171` |
  | `--state-waiting` | `#78716c` / `#57534e` | `#78716c` / `#a8a29e` |
  | `--state-done` | `#059669` / `#047857` | `#10b981` / `#34d399` |

  Global neutrals (`--background`, `--card`, …) do not change. The page gets hierarchy from section headers on `--card`, rows on `--background`, a 3px left rail in the row's tone, and the selected row on `--accent`.
- **D9 — Glyphs** (Agent Deck vocabulary, one per tone): live `●` (with the existing `pulse` animation), needs-you `◐`, stuck `✕`, waiting `○`, done `✓`. The glyph is `aria-hidden`; the reason text carries the meaning.
- **D10 — A single click previews, it does not navigate.** The preview pane shows the agent's live transcript beside the list (the Agent Deck pattern), which is its live conversation. Open / Enter / double-click navigate to the full live pane. This keeps the list in view while scanning.
- **D11 — Pipeline-waiting inclusion lives on the server** (FR-2 rule 3) using `listDerivedStates()`, so the client never receives the full agent history to filter.
- **D12 — Mockup first, in `.tmp/`.** Before production UI code, the work agent builds a clickable standalone HTML mockup at `/home/eltmon/Projects/overdeck/.tmp/pan-4197-agents-live-mockup.html` (the repo root's gitignored `.tmp/`, per the issue), using the real tokens (copy the `@font-face` rules and the `:root`/`.dark` and Broadsheet blocks from `index.css`, self-hosted fonts, no Google Fonts link). It must show all three sections, the preview pane, light and dark. The mockup is not committed.

| 7 | `entry.state === 'unknown'` and `entry.location === 'remote'` | remote | live | live | `running on Fly` |
| 8 | `entry.pause` present (scheduler/machine) | held | waiting | waiting | `held by Overdeck` (detail: `pause.reason`) |
