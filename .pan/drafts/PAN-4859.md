# PAN-4859: Open in editor on an SSH-host machine targets the SSH host, not the local forward

**Issue:** [PAN-4859](https://github.com/eltmon/overdeck/issues/4859). Found by the Overdeck Anywhere release
acceptance run (#4774, AC-15 / W-CONV9). Size S. Verified against `feature/pan-4859` at `743046794be`.

## Glossary

- **Linked conversation.** A conversation owned by another machine that this dashboard shows through a
  machine link (PAN-4650). Its working directory (`row.cwd`) comes from the cached shared row.
- **Open in editor (remote).** `POST /api/linked-conversations/open-in-editor { conversation, editor }`. It
  spawns `<code|code-insiders|codium> --remote ssh-remote+<authority> <cwd>` on the viewing machine.
- **SSH machine / SSH host.** A machine linked with `pan machines add-ssh <destination>` or
  **Add an SSH machine** (PAN-4404). The dashboard opens an `ssh -L` forward and links over
  `tcp://127.0.0.1:<localPort>` with route kind `ssh`. The record lives in `${OVERDECK_HOME}/ssh-machines.json`.
- **Destination.** The validated string the operator typed for an SSH machine: an SSH config alias, `host`,
  `user@host`, or `ssh://[user@]host[:port]`; a host may be an IPv6 literal in brackets (`[fd00::5]`). Grammar:
  `DESTINATION_RE` in `src/lib/anywhere/ssh/target.ts`. Stored as `SshMachineRecord.destination`.
- **Remote authority.** The part after `ssh-remote+` that the Remote-SSH extension resolves. Two forms:
  - **plain**: `[user@]host`, for example `ssh-remote+root@build-box` or `ssh-remote+build-box`;
  - **hex JSON**: lowercase hex of the UTF-8 bytes of `JSON.stringify({ hostName, user, port })` with absent
    keys omitted, for example `{"hostName":"build-box","user":"root","port":2222}` →
    `7b22686f73744e616d65223a226275696c642d626f78222c2275736572223a22726f6f74222c22706f7274223a323232327d`.
- **Local forward.** `tcp://127.0.0.1:<localPort>` — the loopback end of the SSH tunnel on the viewing
  machine. It is never an SSH host.

## Problem

`addSshMachine` links over the local forward
(`src/dashboard/server/services/ssh-machine-service.ts`, line 301,
grep `transport: { url: \`tcp://127.0.0.1:${current.localPort}\`, kind: 'ssh'`).
`sshHostFor` (`src/dashboard/server/services/open-remote.ts`, lines 37–47, grep
`const ssh = link.routes.find((route) => route.kind === 'ssh');`) takes the hostname of the first `ssh`
route, so it returns `127.0.0.1`, and the editor opens `ssh-remote+127.0.0.1` — the viewing machine's own
SSH server. The module header (lines 5–6) still says ssh routes "none exist until #4404".

Reproduction:

```ts
resolveRemoteEditorLaunch({ editor: 'vscode', link: { routes: [{ kind: 'ssh', url: 'tcp://127.0.0.1:40123' }] }, cwd: '/home/root/project' });
// → {"command":"code","args":["--remote","ssh-remote+127.0.0.1","/home/root/project"]}
```

## Research findings (verified 2026-11-02)

1. **Every `ssh` route is a loopback forward.** `kind: 'ssh'` is assigned in exactly one place,
   `ssh-machine-service.ts:301`, and rewritten only by `ssh-forward-supervisor.ts:339`
   (`route.kind === 'ssh' && route.url === oldUrl ? { ...route, url: \`tcp://127.0.0.1:${port}\` }`).
   Manual routes are classified by `classifyHost` (`src/lib/anywhere/routes.ts:106`), which never returns
   `ssh`. An `ssh` route URL is a dashboard transport, never an SSH server address, so its host is never a
   valid editor host.
2. **The real host is the record's destination.** `getSshMachineByLinkId(linkId)`
   (`src/lib/anywhere/ssh/machine-store.ts`, grep `export async function getSshMachineByLinkId`) returns the
   record carrying the link id, never a provisional record (`linkId: null`), and returns null when
   `ssh-machines.json` is corrupt (`listSshMachines` yields `[]`).
3. **The dashboard server's own OpenSSH client, keys and `~/.ssh/config` reach the destination**
   (`configuration/linked-machines.mdx`, "SSH machines"). The editor spawned by the same server runs as the
   same user, so a config alias in the destination resolves the same way for Remote-SSH.
4. **Remote-SSH authority grammar.** VSCodium's Remote-SSH (`jeanp413/open-remote-ssh`,
   `src/ssh/sshDestination.ts`) `parseEncoded` first tries hex JSON `{ hostName, user, port }`, then falls back
   to a plain parse that splits the user on the last `@` and the port on the last `:`. Its comment explains the
   hex form exists because `vscode.uri` lowercases the authority. The Remote-SSH extension installed on this
   machine (`~/.cursor/extensions/anysphere.remote-ssh-1.1.17/dist/main.js`, `parseAuthorityNew` /
   `toEncodedString`) has the same shape: hex JSON with keys `hostName`, `user`, `port`. Consequences:
   - a port is safe only in hex form (VS Code's plain `host:port` handling is not guaranteed);
   - an IPv6 literal must be hex (the plain parser would read the last `:` group as a port);
   - an uppercase user would be lowercased in the plain form, so any uppercase character forces hex.
     (OpenSSH lowercases host names itself, so this only matters for users, but one rule is simpler.)
5. **The `commandLine` echo.** `PanOpenInPicker.tsx` (line 55, `setLastCommand(body?.commandLine ?? null)`)
   shows the command line the server returns. A hex authority makes it long; that is accepted (Non-goals).

## Decisions

- **D-1 Host source order.** For a link, the editor authority comes from, in order:
  1. the SSH machine record whose `linkId` equals `link.id` → its `destination`;
  2. the `tailnet` route whose URL is `wss://<name>/ws/link` → `<name>`;
  3. any other `tailnet` route → its host;
  4. otherwise `no-ssh-host` (409).
  **`ssh` routes are never used as a host source** (finding 1). The old branch that read the first `ssh`
  route's hostname is deleted, not kept as a fallback. A link that has an `ssh` route but no SSH record
  (corrupt `ssh-machines.json`) falls through to steps 2–4; it never yields `127.0.0.1`.
- **D-2 Authority encoding rule.** Parse the destination into `{ user?, host, port? }` (brackets removed
  from an IPv6 host, `ssh://` removed). Use the **hex JSON** form when any of these holds: `port` is set; the
  host contains `:` (IPv6 literal); `user` or `host` contains an uppercase ASCII letter. Otherwise use the
  **plain** form `[user@]host`. JSON key order is exactly `hostName`, `user`, `port`, and `JSON.stringify`
  omits undefined keys; `port` is a JSON number. Tailnet hosts (steps 2–3) keep the current plain
  `ssh-remote+<host>` output unchanged.
- **D-3 Parser location.** The destination parser lives in `src/lib/anywhere/ssh/target.ts`, whose header
  says every string that reaches `ssh` is built there. It is a pure function over an already-validated
  destination and throws `SshMachineError('bad-destination', …)` for anything `validateSshDestination` would
  reject (it calls `validateSshDestination` first).
- **D-4 Purity.** `open-remote.ts` stays pure and synchronous. The route handler does the record lookup
  through a new injectable dependency and passes the destination in.
- **D-5 409 message.** The `no-ssh-host` message becomes
  `` `${link.label} has no SSH host (not an SSH machine and no tailnet route)` ``; the `code` stays
  `no-ssh-host`.
- **D-6 Implementation checkpoint — Microsoft Remote-SSH and hex.** VS Code's Microsoft Remote-SSH is not
  installed on the build machine, so the hex form cannot be launched here. The hex shape is verified against
  two Remote-SSH implementations (finding 4). Fallback if a later live check shows Microsoft's extension
  rejects hex: no code change in this issue; file a follow-up. Do not add per-editor encodings.

## Requirements

- **FR-1** For a link that has an SSH machine record, Open in editor uses the record's destination as the
  remote authority, never the host of an `ssh` route.
- **FR-2** The authority is plain `[user@]host` when D-2's hex conditions do not hold, and hex JSON
  `{hostName,user,port}` when they do.
- **FR-3** An `ssh` route alone never produces an editor host; without a record and without a tailnet route
  the answer is 409 `no-ssh-host`.
- **FR-4** Tailnet-only links behave exactly as before (same command line).
- **FR-5** `parseSshDestination` returns `{ user?, host, port? }` for every destination form
  `validateSshDestination` accepts, and throws `bad-destination` for anything it rejects.
- **FR-6** The user-facing docs state the host order and the encoding rule.
- **NFR-1** No new I/O in `open-remote.ts`; the handler performs one `getSshMachineByLinkId` read per request.
- **NFR-2** Tests are synchronous unit tests with injected dependencies; no real `ssh`, no spawned editor, no
  timers.

### WI-1 `parseSshDestination` in `target.ts` (FR-5)

**Files:** `src/lib/anywhere/ssh/target.ts`, `src/lib/anywhere/ssh/__tests__/target.test.ts`.

Add after `isValidSshDestination` (grep `export function isValidSshDestination`):

```ts
export interface ParsedSshDestination {
  /** Login user, when the destination names one. */
  user?: string;
  /** Host name, alias or IP; an IPv6 literal without its brackets. */
  host: string;
  /** Port, only for `ssh://…:port`. */
  port?: number;
}

/** Split a destination (validated first, D-4404-6) into user, host and port. Throws `bad-destination`. */
export function parseSshDestination(input: string): ParsedSshDestination {
  const dest = validateSshDestination(input);
  const rest = dest.startsWith(SSH_URL_PREFIX) ? dest.slice(SSH_URL_PREFIX.length) : dest;
  const at = rest.indexOf('@');
  const user = at >= 0 ? rest.slice(0, at) : undefined;
  let hostPort = at >= 0 ? rest.slice(at + 1) : rest;
  let port: number | undefined;
  if (hostPort.startsWith('[')) {
    const close = hostPort.indexOf(']');
    const tail = hostPort.slice(close + 1);
    if (tail.startsWith(':')) port = Number(tail.slice(1));
    hostPort = hostPort.slice(1, close);
  } else {
    const colon = hostPort.lastIndexOf(':');
    if (colon >= 0) {
      port = Number(hostPort.slice(colon + 1));
      hostPort = hostPort.slice(0, colon);
    }
  }
  return { ...(user !== undefined ? { user } : {}), host: hostPort, ...(port !== undefined ? { port } : {}) };
}
```

### WI-2 `sshRemoteAuthority` in `open-remote.ts` (FR-2)

**Files:** `src/dashboard/server/services/open-remote.ts`, `src/dashboard/server/services/__tests__/open-remote.test.ts`.

```ts
import { parseSshDestination } from '../../../lib/anywhere/ssh/target.js';

/** The `ssh-remote+` authority for an SSH machine destination (D-2): plain `[user@]host`, or hex JSON when a port, an IPv6 host or an uppercase letter would not survive the plain form. */
export function sshRemoteAuthority(destination: string): string {
  const { user, host, port } = parseSshDestination(destination);
  const plain = user !== undefined ? `${user}@${host}` : host;
  if (port === undefined && !host.includes(':') && !/[A-Z]/.test(plain)) return plain;
  return Buffer.from(JSON.stringify({ hostName: host, user, port }), 'utf8').toString('hex');
}
```
