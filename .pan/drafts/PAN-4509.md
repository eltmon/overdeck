# PAN-4509 — Docs lint: fail on dollar signs Mintlify renders as math, and bare `<` before a digit

**Issue:** [PAN-4509](https://github.com/eltmon/overdeck/issues/4509)
**Status:** draft (planning, `--auto` mode)

## Glossary

- **Published page** — a page path listed anywhere under `navigation` in the repo-root `docs.json` (Mintlify config). Each path resolves to `<path>.mdx` (or `<path>.md` if no `.mdx` exists) relative to the repo root. On main at `b8853b45510` there are 59 published pages, all `.mdx`. The repo has 65 `.mdx` files; the other 6 are not published and are out of scope.
- **Math pairing** — Mintlify renders text between two `$` signs on one line as inline LaTeX. On a line that also contains inline code it does this even for `\$`. Model prices such as "$2/M input, $10/M output" rendered as italic formula glyphs (fixed by hand in commits `2050875` and `bb8ffba`).
- **`&#36;`** — the HTML numeric entity for `$`. It never reaches the math parser as a delimiter, so it is the only safe way to write a currency dollar in prose.
- **Bare less-than before a digit** — `<` immediately followed by `0`–`9` (for example `<60s`). Strict MDX parses `<` as the start of a JSX tag and rejects a digit there. The safe spelling is `&lt;`.
- **Prose** — every part of a published page that is not frontmatter, not inside a fenced code block, and not inside an inline code span.
- **Fenced code block** — a line whose first non-whitespace characters are 3 or more backticks or 3 or more tildes opens a fence; the fence closes at the next line whose trimmed content is only the same character repeated at least as many times. Leading whitespace is allowed on both lines (fences are indented inside `<Steps>`, `<Tab>`, etc.).
- **Inline code span** — on a single line, a run of N backticks opens a span that closes at the next run of exactly N backticks. A run with no matching closer is literal text.
- **Frontmatter** — when line 1 is exactly `---`, every line up to and including the next `---` line.
- **Lint chain** — the `lint` script in `package.json` (line 114). CI runs it through `scripts/run-lint-group.mjs`, which splits it into groups; any step not named in that file's `HEAVY_STEPS` map (lines 15–19) runs in the `core` group automatically. So adding a step to the `lint` script adds it to CI with no `.github/workflows/ci.yml` edit.

## Problem

Mintlify renders paired `$` as math, so every new model price in a changelog entry or doc page risks breaking the live site again. Nothing in `npm run lint` or CI catches it. A bare `<` before a digit is a second latent breakage: strict MDX rejects it (one was found and fixed in `configuration/harnesses.mdx`, which now uses `&lt;` at lines 593 and 915).

Four lines on main fail the proposed rule today (verified with a prototype scan over the 59 published pages):

| File | Line | Text |
| --- | --- | --- |
| `guides/legacy-codebases.mdx` | 95 | `- $200K/year senior developer spends 2 hours/day correcting AI on legacy code` |

No published page has a bare `<` before a digit in prose today.

## Decisions

1. **Extend `scripts/lint-docs.js`; do not create a second docs lint.** It is the existing docs lint home, its old checks pass, and wiring it brings them back into CI for free. Keep the file name and the old checks unchanged.
2. **Wire it as `lint:docs`.** Add `"lint:docs": "node scripts/lint-docs.js"` to `package.json` scripts and append ` && npm run lint:docs` to the end of the `lint` chain. Do not edit `scripts/run-lint-group.mjs` or `.github/workflows/ci.yml`; the step lands in the `core` CI group automatically.
3. **Fail on any `$`, not only pairs.** The issue proposes "any `$` or `\$`". A single `$` is safe today but becomes a pair the moment someone adds a second price on the same line, so the rule must not depend on counting. `\$` fails too (it still pairs on lines with inline code).
4. **Page set = the `docs.json` navigation walk.** Recursively collect every string inside `navigation` reached through `tabs`, `groups` and `pages` arrays (a `pages` entry may itself be a `{ group, pages }` object). Resolve each to `<root>/<path>.mdx`, else `<root>/<path>.md`. A listed page with neither file is a lint error (`docs.json lists "<path>" but no <path>.mdx or <path>.md exists`).
5. **Skip frontmatter.** YAML frontmatter is not parsed as MDX prose; writing `&#36;` there would show the literal entity in page metadata.
6. **No exemptions beyond code and frontmatter.** JSX attribute strings, `{…}` expressions and `{/* */}` comments are checked like prose. No opt-out marker: no published page uses real LaTeX.
7. **Messages name file, line and fix.** Format: `<relative-path>:<line>: dollar sign in prose renders as math on Mintlify — write &#36; instead` and `<relative-path>:<line>: bare "<" before a digit breaks strict MDX — write &lt; instead`. One message per offending line per rule. Exit code 1 when any error exists; exit 0 otherwise.
8. **`--root <dir>` flag** (default `process.cwd()`) selects the repo root for `docs.json`, the pages, and the existing `docs/` checks, so the CLI test can run against a tmpdir fixture.
9. **Fix the four offending lines by replacing each `$` with `&#36;`.** Wording is otherwise unchanged.

```js
const DOLLAR_MESSAGE = 'dollar sign in prose renders as math on Mintlify — write &#36; instead';
const LT_DIGIT_MESSAGE = 'bare "<" before a digit breaks strict MDX — write &lt; instead';

// Remove inline code spans: a run of N backticks closes at the next run of exactly N.
export function stripInlineCode(line) {
  let out = '';
  let i = 0;
  while (i < line.length) {
    if (line[i] !== '`') { out += line[i++]; continue; }
    let n = 0;
    while (line[i + n] === '`') n++;
    const opener = '`'.repeat(n);
    let j = i + n;
    let close = -1;
    while ((j = line.indexOf(opener, j)) !== -1) {
      if (line[j + n] !== '`' && line[j - 1] !== '`') { close = j; break; }
      while (line[j] === '`') j++;
    }
    if (close === -1) { out += opener; i += n; continue; }
    i = close + n;
  }
  return out;
}

export function findMdxProblems(content) {
  const problems = [];
  const lines = content.split('\n');
  let fence = null;
  let inFrontmatter = lines[0]?.trim() === '---';
  lines.forEach((line, index) => {
    const lineNo = index + 1;
    if (inFrontmatter) {
      if (index > 0 && line.trim() === '---') inFrontmatter = false;
      return;
    }
    const trimmed = line.trim();
    if (fence) {
      if (trimmed.length >= fence.length && [...trimmed].every((c) => c === fence[0])) fence = null;
      return;
    }
    const open = /^(`{3,}|~{3,})/.exec(trimmed);
    if (open) { fence = open[1]; return; }
    const prose = stripInlineCode(line);
    if (prose.includes('$')) problems.push({ line: lineNo, message: DOLLAR_MESSAGE });
    if (/<\d/.test(prose)) problems.push({ line: lineNo, message: LT_DIGIT_MESSAGE });
  });
  return problems;
}
```

## Non-goals

- Checking unpublished `.mdx` files or `snippets/*.mdx`.
- Checking frontmatter.
- Special handling for JSX expressions, attribute strings or `{/* */}` comments.
- An opt-out marker for intentional LaTeX.
- Multi-line inline code spans (a span is matched within one line).
- Any other MDX validation (unclosed tags, broken links).
- Changing the existing `docs/*.md` empty/newline checks.
