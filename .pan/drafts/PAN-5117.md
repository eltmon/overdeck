# PAN-5117: Flaky main CI: `pan-hook-lib-guards` "pure-bash fallback" test runs real 1-3 s bash sleeps and times out under CI load

**Issue:** [PAN-5117](https://github.com/eltmon/overdeck/issues/5117)
**Status:** planned (auto mode), 2026-11-10

## Glossary

- **Hook lib** — `sync-sources/hooks/pan-hook-lib.sh`, the bash library that Overdeck's shell hooks `source`. `pan sync` distributes it.
- **`pan_run_with_timeout`** — hook lib function (line 143) that runs a command with a hard deadline and returns `124` on expiry. It uses GNU `timeout`, then `gtimeout`, then a **pure-bash fallback**.
- **Pure-bash fallback** — the branch of `pan_run_with_timeout` that runs when neither `timeout` nor `gtimeout` is on `PATH` (stock macOS). It starts the command in the background, plus a **watchdog** subshell.
- **Watchdog** — the `( … ) &` subshell at lines 165-183. It sleeps for the deadline, then sends `TERM` to the command, then sleeps a 5 s **grace sleep**, then sends `KILL`. The parent kills the watchdog when the command exits.
- **Race window** — the time between a `/bin/sleep … &` fork in the watchdog and the next line `sleep_pid=$!`. There are two: the **start window** (lines 169-170) and the **grace window** (lines 177-178).
- **Orphaned sleep** — a `/bin/sleep` the watchdog forked but never killed. It inherits the caller's stdout, so a caller that captures stdout (`$(…)`, Node `execFile`) waits until the sleep ends.
- **Slow test file** — a Vitest file named `*.slow.test.ts`. `vitest.config.ts` lines 56-57 exclude `**/*.slow.test.ts` unless `VITEST_INCLUDE_SLOW=1`, so the default run and the CI shards never run it.
- **Default run** — `npx vitest run` without `VITEST_INCLUDE_SLOW=1`; this is what the four CI test shards run (`.github/workflows/ci.yml`, step "Test (shard N/4)").
- **Test-skip gate** — `src/lib/cloister/test-skip-gate.ts`. It fails verification when the whole diff removes more `it(`/`test(` calls than it adds.

## Background and evidence

### The CI failure

Main CI run 42862542293 (commit `914cad80c77`), attempt 1, job `test-shard (4/4)` (job id 129992196053). The per-test timings from that log, with ANSI codes stripped:

```
❯ root tests/scripts/pan-hook-lib-guards.test.ts (17 tests | 1 failed) 13470ms
  ✓ returns 124 before the deadline and kills the timed-out child  1014ms
  × uses the pure-bash fallback when timeout commands are absent 10013ms (retry x1)
  ✓ fails closed without changing the bucket when its live lock cannot be acquired  1470ms
Error: Test timed out in 5000ms.  ❯ tests/scripts/pan-hook-lib-guards.test.ts:227:3
```

The `timeout`-command case (line 200) took 1014 ms on the same runner, so the machine was not too slow to finish 1 s of work. The fallback case timed out at 5000 ms twice in a row (first try and CI retry). That shape points at something inside the fallback path, not only at load.

### Root cause: the watchdog can orphan a sleep that holds the caller's stdout

Current code, `sync-sources/hooks/pan-hook-lib.sh` lines 162-184 (grep anchor: `trap '[ -n "$sleep_pid" ] && kill "$sleep_pid" 2>/dev/null; exit 0' TERM INT`):

```bash
  local expired_file="${TMPDIR:-/tmp}/pan-hook-timeout.$$.$RANDOM"
  "$@" &
  local command_pid=$!
  (
    local sleep_pid=""
    trap '[ -n "$sleep_pid" ] && kill "$sleep_pid" 2>/dev/null; exit 0' TERM INT

    /bin/sleep "$timeout_seconds" &
    sleep_pid=$!
    wait "$sleep_pid" 2>/dev/null || exit 0
    sleep_pid=""

    if kill -0 "$command_pid" 2>/dev/null; then
      : > "$expired_file"
      kill -TERM "$command_pid" 2>/dev/null || true
      /bin/sleep 5 &
      sleep_pid=$!
      wait "$sleep_pid" 2>/dev/null || exit 0
      sleep_pid=""
      kill -KILL "$command_pid" 2>/dev/null || true
    fi
  ) &
  local watchdog_pid=$!
```

Bash runs a pending trap between commands. Suppose the parent's `kill "$watchdog_pid"` (line 193) arrives after `/bin/sleep 5 &` has forked but before `sleep_pid=$!` runs. Then the trap sees `sleep_pid=""`, kills nothing, and exits. The grace sleep lives on for 5 s with the caller's stdout open. In the timeout scenario the call then takes 1 s + 5 s = 6 s, which is longer than Vitest's 5 s `testTimeout` (`vitest.config.ts` line 73). The same race exists at the start window: if the command exits before the watchdog records its first sleep, a sleep of the full deadline is orphaned.

The race is real on both bash 5.2 (Linux) and bash 3.2 (the stock macOS shell this fallback exists for). A scratch copy with `/bin/sleep 0.3` inserted inside each window reproduces it every time:

| Scenario (stdout captured) | Current lib | With the WI-1 fix |
|---|---|---|
| Start window widened, `pan_run_with_timeout 5` on a command that exits at once | 5004 ms | 306 ms |
| Grace window widened, `pan_run_with_timeout 1` on `sleep 3` | 6005 ms | 1308 ms |

The unmodified lib did not reproduce the slow call naturally in 60 runs pinned to 2 loaded CPUs on the planning host. So the CI failure is **consistent with** this race (two 5 s timeouts while the sibling case took 1 s), but this is a demonstrated mechanism, not a reproduced CI failure. The plan fixes both the race and the test placement, so it does not depend on which one caused the run to fail.

### Zero callers

`pan_run_with_timeout` and `pan_llm_rate_check` have had no callers since commit `7b953449633` (PAN-3917 W10, 2026-09-18), which deleted `work-agent-stop-hook`, their only user. `git grep -n pan_run_with_timeout` returns only the definition and the test file. This plan keeps both functions (see Decisions D3); production behavior does not change today.

## Decisions

- **D1 — Fix the lib race, and move the timing tests.** The issue asks only for the test move. The move alone does not reliably meet the issue's own acceptance line ("the slow file still passes when run explicitly"): whenever the race hits, an orphaned sleep makes the call take about 6 s, which fails the `< 2_500` ms deadline assertion in either file. So WI-1 fixes the watchdog.
- **D2 — The fix: the trap kills every background job of the watchdog.** Replace the trap with `trap 'kill $(jobs -p) 2>/dev/null; exit 0' TERM INT`. `jobs -p` lists a job from the moment it forks, so the trap no longer depends on `sleep_pid` being recorded. Waited jobs leave the `jobs -p` list (verified on bash 5.2 and 3.2), so a finished sleep is never signalled. The two `sleep_pid=""` resets exist only to tell the old trap that the sleep finished; with the new trap they do nothing, so delete them. Keep `local sleep_pid=""` and `sleep_pid=$!` because `wait "$sleep_pid"` still uses them. Rejected alternative: redirecting the watchdog's stdio to `/dev/null`. That removes the caller-visible delay but still leaves orphaned sleep processes.
- **D3 — Do not delete the caller-less functions.** Deleting them contradicts the issue's acceptance ("the slow file still passes") and removes shipped lib code nobody asked to remove. The zero-caller finding goes to the codebase map (`concerns.md`) as a follow-up note.
- **D4 — Which cases move to the slow file.** Rule: a case moves when its expected wall-clock time is about 1 s or more because of real sleeps or real deadlines. Three cases match:
  1. `returns 124 before the deadline and kills the timed-out child` (line 200) — 1 s `timeout` deadline.
  2. `uses the pure-bash fallback when timeout commands are absent` (line 227) — 1 s fallback deadline.
  3. `fails closed without changing the bucket when its live lock cannot be acquired` (line 306) — `pan_llm_rate_check` retries the lock 10 times with `/bin/sleep 0.1` between tries (about 0.9 s of real sleep; 1470 ms on CI).
  All other cases stay. The lock-holder cases (lines 75, 100, 135) poll with `/bin/sleep 0.01` only until a file appears, and they took 139-166 ms on CI.
- **D5 — Keep fallback coverage in the default run.** After the move, nothing in the default run exercises the pure-bash fallback. Add one fast default-run case that forces the fallback (empty `PATH`) on a command that exits at once, and assert stdout and exit code. It sleeps for no time and does not assert wall-clock time.
- **D6 — Per-test timeout in the slow file.** Each moved case gets `{ timeout: 20_000 }` (Vitest 4 `it(name, options, fn)` form). Keep the `< 2_500` ms deadline assertions: they are the behavior under test (the call returns before the wrapped 3 s sleep ends).
- **D7 — No config change.** `vitest.config.ts` already excludes `**/*.slow.test.ts`. Do not edit it.
- **D8 — No CI step for the slow file.** `.github/workflows/ci.yml` runs one named slow file (`two-machine-ac1.slow.test.ts`, test-e2e job). The new slow file is not added there. Pushing a workflow edit needs a token with the `workflow` scope, and the issue only requires the file to pass when run explicitly. Recorded as a NonGoal.
- **D9 — Duplicate the small helpers in the slow file.** The slow file copies `runBash`, `startBash`, and `waitForFile` (lines 11-40 of the current file) instead of importing a new shared helper module. This keeps both files self-contained, like every other file in `tests/scripts/`, and keeps the default file's diff to the moved cases plus one added case.

## Requirements

- **FR-1** — When the parent kills the watchdog at any point, including inside either race window, `pan_run_with_timeout`'s pure-bash fallback leaves no background `/bin/sleep` alive that holds the caller's stdout.
- **FR-2** — The fallback still returns `124` when the deadline expires and kills the timed-out command. It still returns the command's own exit code and stdout when the command finishes first.
- **FR-3** — The default Vitest run contains no case from `tests/scripts/pan-hook-lib-guards.test.ts` whose wall-clock time depends on a real deadline or sleep of about 1 s or more.
- **FR-4** — `tests/scripts/pan-hook-lib-guards.slow.test.ts` holds the three moved cases and passes with `VITEST_INCLUDE_SLOW=1 npx vitest run tests/scripts/pan-hook-lib-guards.slow.test.ts`.
- **FR-5** — The default run still exercises the pure-bash fallback through one fast case.
- **FR-6** — `docs/TESTING.md` documents the `*.slow.test.ts` convention, and the fake-timers rule names that mechanism.
- **NFR-1** — The fix runs on bash 3.2 (stock macOS) and bash 5.x.
- **NFR-2** — The diff keeps the test-skip gate balanced: the whole diff adds at least as many `it(` calls as it removes, and adds no `.skip`, `.only`, `skipIf`, or `skip: true`.

## Intersecting repo rules (restated)

- **Fake timers rule** (`sync-sources/rules/fake-timers-for-retry-tests.md`): retry and delay tests use fake timers. Fake timers cannot control real child processes, so the rule's own escape applies: a test that must wait for real wall-clock time goes in a separate file excluded from the default run.
- **Quality gates** (CLAUDE.md): run `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.
- **Test-skip gate** (`src/lib/cloister/test-skip-gate.ts`, PAN-3906): a net removal of `it(` calls across the whole diff fails verification. Moving 3 cases out and adding 3 cases in the slow file plus 1 new default case is a net gain of 1. Never add `skipIf` or `.skip` to pass it.
- **No variables in `rm` targets** (universal rule): the probe script deletes nothing, so no `rm` is needed.
- **Keep files out of `/tmp`** (universal rule): the probe lives in the gitignored `.tmp/` and makes its work directory under `~/.overdeck/tmp/`.

**What/why:** fixes the root cause (FR-1, FR-2, NFR-1). See D2.

**File:** `sync-sources/hooks/pan-hook-lib.sh`, function `pan_run_with_timeout` (line 143), watchdog at lines 165-183.

```bash
  local expired_file="${TMPDIR:-/tmp}/pan-hook-timeout.$$.$RANDOM"

```

Steps:
1. Replace the trap line exactly as shown, and add the three comment lines above it.
2. Delete the two `sleep_pid=""` lines (one after each `wait "$sleep_pid" 2>/dev/null || exit 0`).

**Proof (implementation checkpoint):** no Vitest case can hit the race window on demand, so the proof is this probe script. Save it as `.tmp/pan-5117-probe.sh` in the workspace (`.gitignore` line 175 ignores `.tmp/`, so it is never committed) and run it from the workspace root: `bash .tmp/pan-5117-probe.sh`. On the current lib it prints `FAIL start-window … ~5000ms` and `FAIL grace-window … ~6000ms` and exits 1. After the fix it prints two `PASS` lines and exits 0. The planner ran it against the current lib and against a copy with exactly the after-snippet above applied (`PASS start-window 307ms`, `PASS grace-window 1309ms`).

```bash
#!/usr/bin/env bash
# PAN-5117 race probe. Run from the workspace root.
# Widens each watchdog race window in a scratch copy of pan-hook-lib.sh, runs
# the pure-bash fallback with stdout captured, and fails when a call is slow.
set -u
lib=sync-sources/hooks/pan-hook-lib.sh
work=$(mktemp -d "${HOME}/.overdeck/tmp/pan-5117-probe.XXXXXX") || exit 2
mkdir "$work/empty-path"
sed 's|^\(    /bin/sleep "\$timeout_seconds" &\)$|\1\n    /bin/sleep 0.3|' "$lib" > "$work/start.sh"
sed 's|^\(      /bin/sleep 5 &\)$|\1\n      /bin/sleep 0.3|' "$lib" > "$work/grace.sh"
for f in "$work/start.sh" "$work/grace.sh"; do
  n=$(grep -c '^ *\/bin\/sleep 0\.3$' "$f")
  [ "$n" = 1 ] || { echo "FAIL anchor: $f has $n injected sleeps (need 1)"; exit 3; }
done
fail=0
check() { # name lib script max_ms expected
  local s e ms out
  s=$(date +%s%N)
  out=$(env -i HOME="$work" PATH="$work/empty-path" LIB_PATH="$2" /bin/bash -c "source \"\$LIB_PATH\"; $3")
  e=$(date +%s%N); ms=$(( (e - s) / 1000000 ))
  if [ "$out" = "$5" ] && [ "$ms" -lt "$4" ]; then echo "PASS $1 ${ms}ms"; else echo "FAIL $1 out='$out' ${ms}ms"; fail=1; fi
}
check start-window "$work/start.sh" 'r=$(pan_run_with_timeout 5 /bin/bash -c "printf alpha; exit 7"); printf "%s rc=%s" "$r" "$?"' 2000 'alpha rc=7'
check grace-window "$work/grace.sh" 'pan_run_with_timeout 1 /bin/bash -c "exec /bin/sleep 3"; printf "rc=%s" "$?"' 2500 'rc=124'
echo "probe scratch left at $work"
exit "$fail"
```

The anchor loop exits 3 with `FAIL anchor` unless each scratch copy holds exactly one injected `/bin/sleep 0.3`. If it does, the `sed` anchor no longer matches the lib text and the probe would prove nothing: fix the anchor to match the current indentation, never delete the check. The probe leaves its small `~/.overdeck/tmp/pan-5117-probe.XXXXXX` directory in place on purpose; it never deletes anything.

Optional bash 3.2 check (needs Docker): `docker run --rm -v "$PWD":/w -w /w bash:3.2 bash -c 'source sync-sources/hooks/pan-hook-lib.sh; PATH=/nonexistent pan_run_with_timeout 1 /bin/sh -c "exec /bin/sleep 3"; echo rc=$?'` prints `rc=124`. Bash 3.2 also prints a `Terminated "$@"` job notice on stderr; that notice exists before the fix too and is not a failure. The planner ran this against the after-snippet. Docker is not required; skip this check if it is unavailable.
