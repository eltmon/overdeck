# PAN-4299 — Bind Traefik to loopback and stop trusting a forged `Host` from the Docker bridge

**Issue:** [PAN-4299](https://github.com/eltmon/overdeck/issues/4299) · **Epic PRD:** `.pan/drafts/pan-2350.md` (Overdeck Anywhere, revision 5), work item **W-SEC3**, requirement **NFR-2** ("No root credential leaves a machine").

**Done when (epic row):** a LAN request with `Host: overdeck.localhost` gets 401.

## Glossary

- **Traefik** — the shared reverse proxy container `overdeck-traefik`. Its compose file is copied from `sync-sources/templates/traefik/docker-compose.yml` into `~/.overdeck/traefik/docker-compose.yml` by `pan install`. It fronts `https://overdeck.localhost` and forwards to the dashboard at `http://host.docker.internal:3011`.
- **Published port** — a Docker `ports:` mapping. `"443:443"` publishes on every host interface (`0.0.0.0` and `::`). `"127.0.0.1:443:443"` publishes on IPv4 loopback only.
- **Bind address** — the host IP in a published port. This plan adds the config key `traefik.bind` that chooses it.
- **Session mint** — `POST /api/dashboard/session`. It sets the root `overdeck_session` cookie. Gate: `rejectUnauthorizedDashboardSessionMintRequest` in `src/dashboard/server/routes/dashboard-auth.ts`.
- **Remote request gate** — the global middleware in `src/dashboard/server/remote-request-gate.ts`. It lets an uncredentialed `/api/*` request through when `isTrustedLocalRequest` is true.
- **Loopback peer** — `isLoopbackPeer(request)` in `dashboard-auth.ts`. True when the real TCP peer is `127.0.0.1`/`::1`, an IP inside a host Docker bridge subnet (`peerIsHostLocalDockerBridge`), or, inside a container, an IP in one of the container's own subnets (`peerIsLocalContainerNetwork`).
- **Docker-bridge peer** — a peer that passes `peerIsHostLocalDockerBridge`. Every request that Traefik forwards to the host dashboard is one.
- **Forwarded client** — the last (rightmost) entry of the `X-Forwarded-For` header. Traefik appends the IP of the client that connected to it. The rightmost entry is what Traefik itself saw, so a client cannot forge it by sending its own `X-Forwarded-For`.
- **Local forwarded client** — a forwarded client that is `127.0.0.1`, `::1`, or an IP inside a host Docker bridge subnet. A local browser reaches Traefik through docker-proxy, so Traefik sees the bridge gateway IP (for example `172.23.0.1`), not `127.0.0.1`.

## Problem and verified before-state

The template publishes Traefik on every interface (`sync-sources/templates/traefik/docker-compose.yml`, lines 6-9):

```yaml
    ports:
      - "80:80"       # HTTP (redirects to HTTPS)
      - "443:443"     # HTTPS
      - "8080:8080"   # Traefik Dashboard
```

`isLoopbackPeer` (`dashboard-auth.ts`, search `if (peerIsHostLocalDockerBridge(addr, networkInterfaces())) return true;`) trusts every Docker-bridge peer. Traefik always connects from a Docker-bridge IP. So the dashboard treats every request that Traefik forwards as "this machine", whoever the original client was. Both the session mint and the remote request gate use this check.

**Probe on the planning host (2026-11-01).** The host LAN IP is `192.168.1.64`. Its live Traefik publishes `0.0.0.0` and `[::]` on 80/443/8080.

```
$ curl -ks -X POST -H 'Host: overdeck.localhost' -H 'Origin: https://overdeck.localhost' \
    -H 'Content-Type: application/json' -D - https://192.168.1.64/api/dashboard/session
HTTP/2 200
set-cookie: overdeck_session=<redacted>; Path=/; HttpOnly; SameSite=Strict; Max-Age=2592000; Secure
```

The Traefik access log recorded the source as `192.168.1.64`. For local browser traffic, the log shows `172.23.0.1`, which is the bridge gateway that docker-proxy uses. So:

1. The attack works. The request carries no credential and still gets a root session.
2. When the request arrives over IPv4, the forwarded client separates a LAN client (`192.168.1.64`) from a local one (`172.23.0.1`).
3. IPv6 connections reach Traefik through the `[::]` docker-proxy listener, so they appear as the bridge gateway too. The dashboard cannot tell these clients apart. Only loopback binding closes this path.

The Traefik dashboard on `:8080` (`api.insecure: true`) is LAN-exposed in the same way.

## Decisions

- **D-1 Default bind is loopback.** The template publishes `127.0.0.1:80:80`, `127.0.0.1:443:443` and `127.0.0.1:8080:8080`.
- **D-2 IPv4 loopback only, no `[::1]` lines.** A `[::1]` binding fails to start the container on hosts with IPv6 disabled. Browsers, curl and Node 22 `fetch` (autoSelectFamily) fall back from a refused `::1` to `127.0.0.1` at once. The DNS methods write `127.0.0.1` (`src/lib/dns.ts`, `addHostsFileEntry(hostname, ip = '127.0.0.1')`).
- **D-3 Explicit opt-in key `traefik.bind`.** In `~/.overdeck/config.toml`: `[traefik] bind = "loopback" | "all"`. Unset or unrecognized means `"loopback"`. `"all"` renders `0.0.0.0`. This follows the issue: "make LAN exposure an explicit opt-in config key rather than the default". There is no free-form IP value, so config can never inject arbitrary text into the compose file.
- **D-4 One migration helper.** `migrateTraefikCompose()` in `src/lib/traefik.ts` replaces the two duplicate `external: true` regex patches (`src/cli/commands/install.ts`, `src/cli/index.ts`). It also rewrites the three Overdeck port lines to the configured bind address. It rewrites only lines whose host and container ports are both exactly `80`, `443` or `8080`. Other operator mappings, such as `"8443:443"`, stay untouched.
- **D-5 Migration runs wherever Traefik starts or is installed:** `pan install`, `pan sync` (file rewrite only, with a hint), `pan up`, `pan dev`, and `startTraefikBody` (`pan restart --traefik` / `--full`). `pan up` currently skips `docker compose up -d` when the container is already running. When the migration changed the file, `pan up` must run `docker compose up -d` anyway, because Compose recreates a container whose config changed.
- **D-6 Defense in depth in the dashboard.** A Docker-bridge peer counts as local only when the request has no `X-Forwarded-For` header, or its forwarded client is local. This change is limited to the host bridge branch of `isLoopbackPeer`, so the mint and the remote gate both inherit it. `dashboard.require_token_mint` stays layered above it, unchanged.
  - With no header, the peer is a host-local container calling the API directly. That stays trusted, as it is today. The "Does NOT defend: any process on this machine" boundary in `docs/DASHBOARD-AUTH.md` is unchanged.
- **D-7 The in-container branch (`peerIsLocalContainerNetwork`) is unchanged.** Inside a UAT stack container, Traefik's ingress gateway is not always on one of the container's subnets. On the planning host, Traefik's ingress is `172.23.0.0/16` while the `overdeck` network is `192.168.48.0/20`. Applying D-6 there could 401 every in-container mint again (the PAN-1737 regression). The loopback binding closes the LAN path for those stacks.
- **D-8 Doctor reports exposure.** A new `pan doctor` check reads the live `overdeck-traefik` published ports.
  - **error:** the effective bind is loopback, but the container publishes on `0.0.0.0` or `[::]`. This is a stale container. The fix is `pan restart --traefik`.
  - **warn:** `traefik.bind = "all"`. The operator opted in to LAN reach.
  - **ok:** loopback only.
  - **skipped:** Traefik is disabled, or Docker is unavailable.
- **D-9 WSL2 consequence (documented, not engineered).** `infra/wsl2hosts/sync-wsl2hosts.ps1` (line 11, `$wslIp = (wsl hostname -I)...`) maps hostnames to the WSL VM IP. A loopback-bound Traefik refuses that IP. WSL2 users on the `wsl2hosts` DNS method must set `traefik.bind = "all"`. Even then, their Windows browser is a non-local forwarded client under D-6, so it mints through the `#overdeck_token` bootstrap that `pan up` opens, not peer trust. `docs/DNS_SETUP.md` states this. Changing the PowerShell sync to map `127.0.0.1` through WSL localhost forwarding is a follow-up, because it cannot be tested from Linux.
- **D-10 Docs scope.** The new issue body says "Docs: None". That line is overridden for three reasons: `docs/DASHBOARD-AUTH.md` names PAN-4299 in its "Does NOT defend" list, the original issue AC requires that section to change, and finalize requires a docs item.

## Requirements

- **FR-1** A fresh `pan install` writes a Traefik compose file whose three Overdeck ports publish on `127.0.0.1` only.
- **FR-2** An existing install with `"80:80"`, `"443:443"` or `"8080:8080"` port lines gets those lines rewritten to the configured bind address by `pan install`, `pan sync`, `pan up`, `pan dev`, `pan restart --traefik` and `pan restart --full`.
- **FR-3** After a migration that changed the file, `pan up` runs `docker compose up -d` even when the container is already running, so the new bindings take effect.
- **FR-4** `traefik.bind = "all"` in `config.toml` renders `0.0.0.0` for the three ports. Unset or any other value renders `127.0.0.1`.
- **FR-5** A session mint from a Docker-bridge peer whose rightmost `X-Forwarded-For` entry is not local returns 401 with no `Set-Cookie`.
- **FR-6** An uncredentialed `/api/*` request from a Docker-bridge peer whose forwarded client is not local returns 401 from the remote request gate.
- **FR-7** A Docker-bridge peer with no `X-Forwarded-For` header, or whose forwarded client is `127.0.0.1`, `::1` or a host Docker bridge IP, stays trusted (mint 200, gate passes).
- **FR-8** `pan doctor` reports the Traefik binding state as described in D-8.
- **NFR-1** No `execSync` is added to code reachable from the dashboard server. `dashboard-auth.ts` stays pure, with no child processes. Doctor uses async exec.
- **NFR-2** (epic NFR-2) A LAN client cannot obtain a root `overdeck_session` through Traefik.
- **NFR-3** `src/cli/index.ts` must not grow. It is capped by `scripts/file-size-allowlist.txt`, so the inline migration block it loses must offset the new call.

```ts
/** Host IP for Traefik's published ports (PAN-4299 D-3). Anything but 'all' is loopback. */
export function resolveTraefikBindAddress(bind: unknown): '127.0.0.1' | '0.0.0.0' {
  return bind === 'all' ? '0.0.0.0' : '127.0.0.1';
}

const TRAEFIK_PORT_LINE = /^(\s*-\s*["']?)(?:(?:\d{1,3}\.){3}\d{1,3}:|\[[0-9a-fA-F:]*\]:)?(80|443|8080):(80|443|8080)(["']?.*)$/;

/** Rewrite only the 80:80 / 443:443 / 8080:8080 lines to `<address>:<port>:<port>`. Pure. */
export function rewriteTraefikComposePorts(content: string, address: string): string {
  return content.split('\n').map((line) => {
    const m = TRAEFIK_PORT_LINE.exec(line);
    if (!m || m[2] !== m[3]) return line;
    return `${m[1]}${address}:${m[2]}:${m[3]}${m[4]}`;
  }).join('\n');
}

/** The pre-external-network upgrade, moved verbatim from install.ts / cli/index.ts. Pure. */
export function rewriteTraefikComposeNetwork(content: string): string {
  if (!content.includes('overdeck:') || content.includes('external: true')) return content;
  return content.replace(
    /networks:\s*\n\s*overdeck:\s*\n\s*name: overdeck\s*\n\s*driver: bridge/,
    'networks:\n  overdeck:\n    name: overdeck\n    external: true  # Network created by \'pan install\'',
  );
}

/**
 * Bring ~/.overdeck/traefik/docker-compose.yml up to date: external network and
 * ports on the configured bind address. Returns true when the file changed —
 * the caller must recreate a running container for new ports to apply.
 */
export function migrateTraefikCompose(composePath = join(TRAEFIK_DIR, 'docker-compose.yml')): boolean {
  if (!existsSync(composePath)) return false;
  const before = readFileSync(composePath, 'utf-8');
  const address = resolveTraefikBindAddress(loadConfigSync().traefik?.bind);
  const after = rewriteTraefikComposePorts(rewriteTraefikComposeNetwork(before), address);
  if (after === before) return false;
  writeFileSync(composePath, after, 'utf-8');
  return true;
}
```

### W-6 Dashboard rejects a non-local forwarded client from the Docker bridge (`forwarded-client-check`)

Files: `src/dashboard/server/routes/dashboard-auth.ts`, `src/dashboard/server/routes/__tests__/dashboard-auth.test.ts`, `src/dashboard/server/__tests__/remote-request-gate.test.ts`.

Add a pure exported function:

```ts
/**
 * PAN-4299: Traefik appends the IP it accepted the connection from to
 * X-Forwarded-For, so the LAST entry is the client Traefik saw — a caller can
 * prepend fake entries but never replace that one. A local browser reaches
 * Traefik via docker-proxy and shows up as the bridge gateway, so "local" is
 * loopback or a host Docker-bridge IP. No header = a host-local container
 * calling the API directly (unchanged trust).
 */
export function forwardedClientIsLocal(
  headers: HeaderMap,
  interfaces: NodeJS.Dict<NetworkInterfaceInfo[]>,
): boolean {
  const forwardedFor = getHeaderFromMap(headers, 'x-forwarded-for');
  if (forwardedFor === undefined) return true;
  const last = forwardedFor.split(',').pop()?.trim() ?? '';
  const client = last.startsWith('::ffff:') ? last.slice('::ffff:'.length) : last;
  if (client === '127.0.0.1' || client === '::1') return true;
  return peerIsHostLocalDockerBridge(client, interfaces);
}
```

- **AC-W5:** the lifecycle test proves `migrateTraefikCompose` runs before `docker compose up -d` in `startTraefikBody`.
- **AC-W6:** a bridge peer with forwarded client `192.168.1.50` gets 401 from the mint and from the remote gate. A bridge peer with forwarded client `172.18.0.1` or no header still mints and passes the gate. A literal `127.0.0.1` peer behaves as before.
- **AC-W7:** the `classifyTraefikPorts` tests pass, and `pan doctor` on a host whose container publishes `0.0.0.0` prints `Traefik port binding` with status error and fix `pan restart --traefik`.
- **AC-W8:** the "Does NOT defend" list in `docs/DASHBOARD-AUTH.md` no longer mentions PAN-4299. `guides/docker-setup.mdx` and `docs/DNS_SETUP.md` both name `bind = "all"`.

## Repo rules that apply

- **No `execSync` in dashboard-server-reachable code.** `dashboard-auth.ts` stays pure. Doctor uses `execAsync`. CLI-only paths such as `src/cli/index.ts` `pan up` may keep their existing `execSync`.
- **No source-reading tests.** A test must not read the template or a `.ts` file to grep it, because the lint rejects that. Use inline compose strings.
- **No added `skipIf` or `.only`.**
- **File-size ratchet.** Files over 1000 lines may not grow past their allowlist cap: `src/cli/index.ts` (keep it net-zero or smaller) and `doctor.ts` (cap 1042). Never raise an allowlist row.
- **Quality gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.
- **The dashboard runs Node 22 dist only.** No server restart is needed to test this change, because the unit tests cover it.

## Non-goals

- No Traefik `ipAllowList` middleware. It would answer 403 rather than the epic's 401, and it would duplicate W-6.
- No change to `api.insecure: true` on `:8080`. Loopback binding makes it host-local.
- No change to the in-container trust branch (`peerIsLocalContainerNetwork`), per D-7.
- No change to trust for literal-loopback peers behind Tailscale Serve or cloudflared. W-SEC4 ([PAN-4645](https://github.com/eltmon/overdeck/issues/4645)) owns that.
- No defense against host-local containers that call the API directly with a self-set `X-Forwarded-For`. That is the existing "any process on this machine" boundary.
- No rewrite of `infra/wsl2hosts/sync-wsl2hosts.ps1` (D-9 follow-up).
- No `[::1]` port bindings (D-2).
- No automatic `pan restart --traefik` on this machine. The live Traefik is recreated by the operator, or by the next `pan up` or `pan restart --traefik`.
