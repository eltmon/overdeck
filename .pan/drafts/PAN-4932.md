# PAN-4932 — Claude Code: inject the `overdeck` MCP server into agents, role runs and conversations (W-INJ1)

**Status:** planned (`pan plan --auto`) · **Revision:** 1 (2026-11-03) · **Author:** Claude Opus 5.5 (planning agent)
**Issue:** [PAN-4932](https://github.com/eltmon/overdeck/issues/4932) · **Epic:** [PAN-4927](https://github.com/eltmon/overdeck/issues/4927), PRD `.pan/drafts/pan-4927.md`, work item **W-INJ1**
**Depends on (both merged on `main`):** W-TOK1 = [PAN-4930](https://github.com/eltmon/overdeck/issues/4930) (`99f28c3e222`, agent tokens), W-MCP1 = [PAN-4931](https://github.com/eltmon/overdeck/issues/4931) (`8bdce46e72a`, tool visibility and `OVERDECK_MCP_TOKEN_FILE`).
**Unblocks:** W-INJ2 (Codex), W-INJ3 (ACP), W-INJ4 (instructions blocks), W-FUN1 (reads the `mcp` config module this item adds).

Every Claude Code agent Overdeck launches on this host (work agent, role run, planning session, conversation) starts with an MCP server named `overdeck`. The server is `pan mcp serve` over stdio. It reads the agent's own token from a 0600 file that W-TOK1's `ensureAgentMcpToken` writes. The launcher and the MCP JSON carry only the file path, never the token.

---

## Glossary

- **Overdeck MCP server:** the tool module in `src/lib/mcp/` served over stdio by `pan mcp serve` (`src/cli/commands/mcp.ts`, `runMcpServe`). Every tool calls a dashboard HTTP route with the caller's token.
- **Agent token:** a `kind: 'token'` access-token record with `agentId`, `agentKind` (`'agent' | 'conversation'`) and `role` (W-TOK1). `ensureAgentMcpToken(owner)` in `src/lib/mcp/agent-token.ts` reuses or mints one and writes `<dir>/mcp-token` (mode 0600).
- **Token file:** `<dir>/mcp-token`. `<dir>` is `~/.overdeck/agents/<agentId>/` for an agent and `conversationStateDir(tmuxSession)` = `~/.overdeck/conversations/conv-<name>/` for a conversation.
- **Overdeck MCP config:** a new JSON file `<dir>/overdeck-mcp.json` (mode 0600) of the form `{ "mcpServers": { "overdeck": { "type": "stdio", "command", "args", "env" } } }`. It holds the token file path, never the token.
- **Launch site:** a call of `generateLauncherScript` (`src/lib/launcher-generator.ts:300`) that can produce a Claude Code command line.
- **Claude Code launch kind:** `getHarnessBehavior(harness).launchCommandKind === 'claude-code'`. This is the adapter selector the launcher already switches on; it is not a harness-name comparison.
- **Harness capability:** a field of `HarnessCapabilities` (`packages/contracts/src/harness-capabilities.ts:21`). Code reads a capability instead of comparing harness names (`configuration/harnesses.mdx`, "Harness capabilities").
- **Pane role:** a conversation's `AgentRole` (`work | worker | review | test | uat | strike | plan | conversation`, `packages/contracts/src/terminal-backend.ts:18`), stored in `<stateDir>/pane-role` (`src/lib/overdeck/conversation-pane-role.ts`).
- **Token role:** the key of `AGENT_TOKEN_SCOPES` (`src/lib/mcp/agent-token.ts`): a `Role` (`src/lib/agents/role.ts:6`) or `'conversation'`. It decides the token's scopes (epic D-8).
- **Lane row:** a conversation row with `laneRole !== null` (`src/lib/overdeck/conversations.ts:290`), started by `pan lane start`.
- **Sweep:** `src/dashboard/server/services/agent-token-sweep.ts` (W-TOK1). It revokes tokens whose owner is gone.
- **CP-1:** epic implementation checkpoint "two `--mcp-config` flags in Claude Code, no permission prompt".

## Requirements

### Functional

- **FR-1 Claude Code agents get the server.** A Claude Code launch at S1-S7 on this host appends `--mcp-config=<dir>/overdeck-mcp.json` to the `claude` command when injection is enabled (FR-5). The file defines exactly one server, `overdeck`, which runs `pan mcp serve` with the token file path.
- **FR-2 Per-owner token.** Each launch calls `ensureAgentMcpToken` for its owner: `agentKind: 'agent'` with the agent's role for S1-S6; `agentKind: 'conversation'` with the conversation name for S7. The token role follows the table in D-4.
- **FR-3 No prompt for the tools.** A launch that adds the server also allows `mcp__overdeck`: as `--allowedTools=mcp__overdeck` when the command has no `--allowedTools` flag, else as an extra entry in the role's existing allow-list. A command never carries two `--allowedTools` flags.
- **FR-4 No secret in launchers or configs.** Neither the launcher script nor `overdeck-mcp.json` contains `odk_`. The token exists only in `<dir>/mcp-token` (mode 0600).
- **FR-5 Switches.** Injection happens only when all hold: the launch kind is Claude Code; the harness declares `capabilities.overdeckMcp`; config `mcp.agents` is `true` (default `true`); neither `OVERDECK_DOCKER_WORKSPACE=1` nor `PAN_DOCKER=1` is set in the spawning process; and, for S7, the conversation is not `bareContext` and has a row.
- **FR-6 Degrade, never block.** When minting or writing the config fails, the launch proceeds without the server and logs one warning that names the agent id and the error message (never a token).
- **FR-7 Relaunch keeps the server.** A resume, recovery or fallback relaunch of a Claude Code agent (S1 via its callers, S3, S4) carries the same `--mcp-config=`; `ensureAgentMcpToken` reuses the live token.
- **FR-8 Config module.** `config.yaml` accepts `mcp: { agents?: boolean; public?: { enabled?: boolean } }`, normalized to `{ agents: boolean; public: { enabled: boolean } }` with defaults `agents: true`, `public.enabled: false`. Invalid values keep the earlier value; loading never throws.
- **FR-9 Docs.** `configuration/mcp.mdx` and `configuration/harnesses.mdx` describe the injection, the switch, the capability and the CP-1 result.

### Non-functional

- **NFR-1 Async only.** No `execSync`, `spawnSync`, `execFileSync`; no new `*Sync` function (repo rules `no-execsync-server`, `prefer-async`). Existing sync callers stay.
- **NFR-2 No harness-name comparison** in any new or changed line; `npm run lint:harness-branches` passes with no baseline change.
- **NFR-3 No import cycle.** `launcher-generator.ts` imports only the leaf `src/lib/mcp/overdeck-mcp-args.ts` (which imports only `../shell-quote.js`). `npm run lint:circular` passes with no baseline change.
- **NFR-4 File budgets** (Fact 14) hold; `npm run lint:file-size` passes; the allowlist is never raised.
- **NFR-5 Tests assert behavior** (launcher strings, files in the temp `OVERDECK_HOME`), never read source files (`lint:source-introspection`); no new `skipIf` or `.only`. Delay tests use fake timers (repo rule `fake-timers-for-retry-tests`).
- **NFR-6 Effect boundary.** No new exported Effect wrapper; `npm run lint:effect-facades` does not rise.
- **NFR-7 New modules** stay under 600 lines and start with a header naming PAN-4927 W-INJ1 / PAN-4932 and the decision they implement.

## Decisions

- **D-1 Capability, not names.** Add `readonly overdeckMcp: boolean` to `HarnessCapabilities`, append `"overdeckMcp"` to `HARNESS_CAPABILITY_KEYS`, and declare it in all eight `*_CAPABILITIES` constants. In this item only `CLAUDE_CODE_CAPABILITIES` declares `true`; the other seven declare `false`. W-INJ2 flips `CODEX_CAPABILITIES` and W-INJ3 flips `ACP_CAPABILITIES` and `OPENCODE_CAPABILITIES` when they wire their harness. Why: a capability says what the harness does now; a `true` before the wiring exists would make W-INJ4's instructions block promise tools the agent does not have.
- **D-2 One helper per launch.** `prepareClaudeOverdeckMcp(owner)` returns `{}` when FR-5 says no, else mints, writes the config and returns `{ overdeckMcpConfig }`. Each site spreads its result into the `generateLauncherScript` config with one line. Why: fits the spawn.ts budget (+3) and keeps S1-S7 identical.
- **D-3 Mint failure.** `prepareClaudeOverdeckMcp` catches every error, logs `[agent-injection] overdeck MCP skipped for <agentId>: <message>` with `console.warn`, and returns `{}`. Why: tokens give identity, not a sandbox (epic H-1); a corrupt registry must not stop every agent launch, and the agent still has `pan`.
- **D-4 Token role.**

  | Launch | `agentKind` | `agentId` | Token role |
  |---|---|---|---|
  | S1 | `agent` | `opts.agentId` | `launchRole` (`opts.isPlanning ? 'plan' : opts.role`) |
  | S2 | `agent` | `agentId` | `role` |
  | S3 | `agent` | `normalizedId` | `recoveryRole` |
  | S4 | `agent` | `normalizedId` | `resumeRole` |
  | S5, S6 | `agent` | `sessionName` | `'plan'` |
  | S7 | `conversation` | the row's `name` | `conversationTokenRole(row, paneRole, tmuxSession)` |

  `conversationTokenRole` checks in this order: `row.laneRole !== null` → `'worker'` (PAN-4930 H-8: a lane is not the operator's chat, so no `approve`); `tmuxSession === FLYWHEEL_CONVERSATION_SESSION` (`'conv-flywheel'`, `src/lib/flywheel/constants.ts:7`) → `'flywheel'` (epic D-8 gives flywheel no `approve`); pane role `'uat'` → `'test'`; pane role `'conversation'` → `'conversation'`; any other pane role (`work`, `worker`, `review`, `test`, `strike`, `plan`) → the same name.
- **D-5 Directories.** Agents: `getAgentDir(normalizeAgentId(agentId))` (`src/lib/agents/agent-state-read.ts`), the same directory `revokeAgentMcpTokens` unlinks. Conversations: the caller passes `stateDir` (= `conversationStateDir(tmuxSession)`). `overdeck-mcp.json` sits next to `mcp-token`.
- **D-6 Conversation lookup.** S7 finds the row with `getConversationByTmuxSession(tmuxSession)` (already imported at `conversation-runtime.ts:17`). No row ⇒ no injection: a token minted for a missing row is revoked by the next sweep.
- **D-7 Bare conversations get no server.** `ConversationLaunchContext.bareContext` means "skip every Overdeck-injected layer" (`conversation-launch-context.ts:10`). Play lanes use it to see the product as a new user does. The `overdeck` server is an Overdeck-injected layer. `plainFork` conversations do get it.
- **D-8 The role allow-list always names `mcp__overdeck`.** `roleSystemPromptInjection` appends `mcp__overdeck` whenever it emits `--allowedTools`, even when injection is off. An allow rule for an absent server grants nothing.
- **D-9 Sweep grace for a missing state.** In the sweep's `agent` branch, a token whose agent state is missing is kept while `Date.parse(record.createdAt) >= now - AGENT_TOKEN_SWEEP_GRACE_MS` (10 minutes), and revoked after that. Why: C-4. The stop paths still revoke at once; the sweep is only the crash backstop.
- **D-10 `mcp.public.enabled` ships here, unused.** The epic gives the `mcp` config module to W-INJ1 and W-FUN1 builds on it. This item adds and tests the field and reads only `mcp.agents`.
- **D-11 Keep the flag even where hooks approve.** Fact 7's control run shows this machine already approves the call without the flag. `--allowedTools=mcp__overdeck` stays, because a host without those hooks would stop at a permission prompt in `auto` mode (`--permission-mode default`, `src/lib/claude-permissions.ts:79-88`).
