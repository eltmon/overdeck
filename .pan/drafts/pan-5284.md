# PAN-5284 — Workflow redesign: one left column, a Files/Changes/Search dock, code beside the chat, per-conversation changes, rebuilt project Home

**Issue:** https://github.com/eltmon/overdeck/issues/5284
**Approved mockup:** `docs/design/workflow-redesign-mockup.html` (open it in a browser; the bottom-left box switches between the three screens and lists every change). The operator approved it on 2026-11-14 ("I love it, let's do it"). Where this PRD and the mockup disagree, this PRD wins; each such place is called out as a decision.
**Evidence:** the UI audit (`.tmp/file-ux-audit/AUDIT.md`, 131 screenshots, not committed) and four code maps made 2026-11-14 (their findings are folded into the references below).
**Builds on:** #5183 (file explorer, merged), #5281 (commit attribution trailers, in progress). **Supersedes:** #5274.

## 1. Summary

A year of features exists — diffs, a file explorer, edit workspaces, one-click PRs — but none of it is obvious to reach from where people work. From a conversation tab there is no way to see what the agent changed or to browse the project; project Home puts its launchers three screens down; three always-open side columns (left nav 256 px, Command Deck 320 px, Awareness 300 px) leave the chat about 750 px wide at 1920 px.

This epic rebuilds the frame and the conversation workflow to the mockup:

1. **One left column** (264 px): project switcher, nav, New conversation, and this project's conversations and issues. The separate Command Deck column goes.
2. **A slim top bar**: breadcrumb, `Ctrl K` search that also finds files, one agents menu (Stop all inside), one Needs-you count that every surface agrees with, one health dot.
3. **A right dock** with three tabs — **Files**, **Changes**, **Search** — that follows the active tab (a conversation, an issue, project Home, an edit workspace). It replaces the explorer's Stage tab and the Awareness panel.
4. **Code opens beside the chat** in a Stage split; the tree stays visible; lines the conversation changed are marked.
5. **Per-conversation changes**: a server API that lists what a conversation changed — its commits (exact, from #5281 trailers) and its uncommitted edits (best effort) — and a conversation header, status line and per-turn card that use it.
6. **The edit-workspace and PR flow lives in the editor**: a bar that always says where edits go and what to do next, a Create PR dialog that shows the files and asks "How should it land?", and PR status through to merged.
7. **A rebuilt project Home**: actions first, five labelled facts that agree with the top bar, Needs-you items, the pipeline as full-width rows, and recent changes labelled with who made them.

## 2. Glossary

- **Frame** — the always-visible chrome: left column, top bar, Stage, dock.
- **Left column** — the new single 264 px column on the left (replaces `components/Sidebar.tsx`'s nav column plus the Command Deck column in `components/CommandDeck/index.tsx`).
- **Stage** — the tabbed pane area (`components/Stage/index.tsx`); tabs are panes stored per deck in `lib/panesStore.ts`; the layout is a binary split tree (`PaneLayout`, PAN-1591).
- **Deck / deck key** — the per-project Stage instance; `deckKey` is the project key (for overdeck the key is `panopticon-cli`, `App.tsx` search `panopticon-cli`).
- **Dock** — the new right column with the Files, Changes and Search tabs.
- **Dock scope** — what the dock shows: derived from the active Stage tab (§6.3).
- **Explorer root / root id** — `project:<key>` (primary checkout, read-only), `issue:<ID>` (feature workspace), `workspace:<id>` (scratch edit workspace). Resolved server-side in `src/dashboard/server/services/explorer/roots.ts`.
- **Edit workspace** — a scratch worktree on `scratch/edit-<slug>` that receives the operator's hand edits so the primary checkout never changes (#5191).
- **Attribution trailer** — `Overdeck-Conversation: <name>` / `Overdeck-Agent: <id>` at the end of a commit message (#5281).
- **Conversation changes** — what one conversation changed: its attributed commits plus its uncommitted edits (§6.1).
- **Needs-you item** — something a human must act on (style-guide meaning of amber). Exactly one selector produces them (§6.4).
- **Agents working** — live agent and conversation sessions in a working state. Exactly one selector counts them (§6.4).
- **Capture-phase shortcut** — a `window.addEventListener('keydown', h, true)` handler; it runs before Monaco's own key handling (§6.5).
- **No-loss table** — §7: every function of a removed or moved surface and its new home.
- **Owner (of a file)** — the one child issue allowed to change a file at a time (§8).

## 3. Decisions

- **D-1 The mockup is the visual and behavioral spec.** Layout, wording and interactions follow `docs/design/workflow-redesign-mockup.html`. Executors open it in a browser and match it, using the Broadsheet tokens and components already in `src/dashboard/frontend/src/index.css` (load the `pan-style-guide` skill first). The mockup's hand-written CSS is a reference, not code to copy.
- **D-2 The dock lives inside the Stage area, not in the app grid.** It mounts as a sibling of the Stage pane area (`Stage/index.tsx`, search `styles.paneArea`). So it does not depend on the left-column rewrite, and the file/changes track can ship first.
- **D-3 The explorer stops being a Stage tab.** `paneType: 'files'` panes are migrated: on deck load each is closed and the dock opens on its root. `PaneType` keeps `'files'` only as a migration input. `'code'` panes stay Stage tabs.
- **D-4 Files open beside the chat.** Opening a file from the dock, a diff, a chat link or Quick Open places the code pane in the Stage region next to the active conversation; when the deck is not split, it splits it (`row`, file on the right). It never replaces the conversation. A second file reuses that region (preview tab rules from #5187 stay).
- **D-5 Commit attribution is exact; uncommitted attribution is best effort and labelled.** Commits: from #5281 trailers, plus a fallback that reads `git commit` output in the conversation's own shell tool results for commits made before trailers existed. Uncommitted lines: only Claude Code transcripts carry edit records (`old_string`/`new_string`/`content`); other harnesses and shell edits record nothing. So:
  - Claude Code: the panel counts this conversation's lines in a shared file ("9 of 621 uncommitted lines in this file are from this conversation").
  - Other harnesses: the file is listed as "edited by this conversation" with no per-line split, and the note says line attribution needs edit records.
  - Shell-only edits never appear as uncommitted changes of a conversation.
  The mockup's line "come from Fort #23 Overseer and Fort #20 Manager" names other conversations; that is only possible when they are Claude Code. The executor implements naming only when the other conversation's edit records match; otherwise the note says "from other sessions".
- **D-6 "Send: when idle" in the mockup becomes a labelled Send control with the real modes.** The composer's delivery mode (`chat/DeliveryModeSelect.tsx`, values `auto`, `steer`, `follow_up`, `when_limit_resets`) becomes a menu button reading **Send: normally** / **Send: interrupt now** / **Send: after this turn** (Pi only) / **Send: when the limit resets**, mapped 1:1 to those values. The ⋯ menu's transport selector ("Delivery method": auto/channels/tmux) is a different control and moves under ⋯ → **Advanced** unchanged.
- **D-7 Browser-reserved shortcuts are not used.** Chrome does not deliver `Ctrl+N`, `Ctrl+T`, `Ctrl+W`, `Ctrl+Shift+N/T/W` or (on Linux/Windows) `Ctrl+1..9` to pages. The mockup's "Ctrl N" keycap is replaced:
  - New conversation: **`N`** when focus is not in an editable element, terminal or Monaco (Linear-style single key). The button shows the keycap `N`.
  - Switch Stage tab: **`Alt+1..9`** on Linux/Windows, **`⌘1..9`** on macOS (unchanged there).
  - Close Stage tab: **`Alt+W`** on Linux/Windows, **`⌘W`** on macOS (unchanged).
  - Files / Changes / Search / Go to file: **`Ctrl+Shift+E` / `Ctrl+Shift+G` / `Ctrl+Shift+F` / `Ctrl+P`** (macOS: `⌘⇧E` / `⌘⇧G` / `⌘⇧F` / `⌘P`), handled in the capture phase so they work inside Monaco; on macOS `⌘⇧G` is Monaco's Find Previous and is overridden deliberately.
  - Palette: `Ctrl K` / `⌘K` (unchanged). `/` keeps opening search.
  This overrules the comment in `explorer/code/MonacoCodeEditor.tsx` (search `` `addCommand` (global across editors) or a window listener``) for these app-level keys only; update that comment.
- **D-8 One canonical Needs-you selector.** Today eight places compute it differently (§6.4). The canonical items are the union of: (a) unanswered pending input of agents and conversations (`usePendingInputSubjects`, minus answered/dismissed, as `NeedsYouSection` does); (b) issues whose derived attention is `needs-you` (`DerivedIssueState.attention`); (c) each Flywheel tick needs-you row (`needsYouRows`); (d) the non-pending-input decisions from `lib/useDecisions.ts` (fleet, unreachable machines, disk alert, harness-update failures, restart recovery, MCP sign-ins, connector notices, agent requests). Dedupe by subject (issue id, conversation name, decision id). `isNeedsYouFeature`'s extra rules (`work-not-started`, `pr-outside-pipeline`, `ready`, planning awaiting input, pending plan approval) are pipeline states, not needs-you items, except planning awaiting input and pending plan approval, which are already pending input in (a). An uncommitted file is **not** a needs-you item (it is shown in the conversation's status line); the mockup's second Needs-you row is replaced by whatever (a)–(d) produce.
- **D-9 One canonical Agents-working selector.** Count = store agents whose status is in `RUNNING_AGENT_STATUSES` (`components/AgentPillPopoverRow.tsx`, `['running','active','starting','thinking','working']`) plus conversations with `isWorking`, deduplicated by session name (store agents may include `conv-<name>` rows; `src/dashboard/server/services/agent-projection.ts`, search `conv-`). Per project: agents by issue prefix → project (`projects.yaml` `issue_prefix`), conversations by `projectKey`. Breakdown by role (planning, building, review, test, conversation). The top bar, project Home and the Home page all use it.
- **D-10 Spend includes conversations.** Project spend this week and today = issue-attributed cost events (by issue prefix) plus conversation cost events whose conversation belongs to the project (cost events carry `agentId: conv-<name>`, `issueId: UNKNOWN`). "This week" is the rolling 7 days the costs summary already uses; "today" is the local calendar day of the server (change from UTC).
- **D-11 "Merged this week" becomes "Landed this week".** Count = commits on the project's default branch in the last 7 days (`git log --since=7.days --first-parent origin/<default>`), no GitHub calls. Subline: "N via PRs" (commits whose subject ends in `(#<n>)`), or "commits go to main" when none.
- **D-12 Real-GitHub verification of the PR flow is done by the epic owner, not by pipeline agents.** Pipeline UAT keeps its fixture project. After child C merges, the epic owner runs one throwaway docs edit through Open PR → Merge and one through Send through pipeline on `eltmon/overdeck`, with the operator's go-ahead.
- **D-13 Every child leaves the dashboard usable when merged alone.** The Flywheel reloads the dashboard after each merge. A child that removes a surface ships its replacement in the same PR (the child that removes the `files` tab ships the dock and its entry points; the child that removes the Command Deck column moves its lists in the same PR).
- **D-14 Nothing is deleted without a home.** §7 gives every function a home. Two functions are intentionally dropped, both replaced: dragging a conversation onto a project row (replaced by the existing row menu **Move to project…**), and the footer "Lens: g + p b a c" hint (replaced by the `?` keyboard-shortcuts sheet).

## 4. Requirements

### Functional
- **FR-1** A conversation header shows **Changes** (with +/−) and **Files** buttons; ⋯ holds About, Bookmarks, Show tool calls, Subagents, Open folder in…, Copy conversation id, Advanced (delivery transport), Pull requests, Hand off, Summary fork, Export, Pull here, Continue on another device, Share, handoff doc/target (when present), Favorite, Regenerate title, Archive, Stop the agent.
- **FR-2** The conversation status line reads in words, and each part acts: state; folder (opens Files); branch; "N commits pushed" / "N commits not pushed" (opens Changes); "N files not committed" (opens Changes filtered); cost. The session id moves to ⋯.
- **FR-3** Each assistant turn that changed files ends with one card: "N files changed", +/−, "N commits pushed", "N not committed", **Show in files**, **Review**; file rows with diff / open beside / reveal actions. It replaces the "Changed files" card.
- **FR-4** Every file path chip in assistant text and tool rows opens that file's diff in the dock when the file is in the conversation's changes, otherwise opens the file beside the chat. Its context menu keeps today's items and adds Open diff, Open beside, Reveal in files.
- **FR-5** `GET /api/conversations/:name/changes?scope=conversation|turn|uncommitted|main&turnId=` returns conversation changes per §6.1.
- **FR-6** `GET /api/projects/:key/changes?since=` returns recent commits on the default branch with their attribution (conversation or agent, from trailers, else "unattributed").
- **FR-7** The dock has Files, Changes and Search tabs; it opens from the header buttons, the status line, the turn card, the Stage + menu, project Home, the issue overview, and the shortcuts in D-7; it can be resized (260–720 px, persisted) and closed.
- **FR-8** The dock's scope follows the active Stage tab per §6.3, and its header says what it is scoped to.
- **FR-9** Files tab: human root name and branch; per-extension icons; chevrons; 16 px indent with indent guides; git letter right after the name; a dot on files (and folders containing files) changed by the scoped conversation; git-ignored files hidden by default; a View options menu (Show all files, Only changed files, Only what this conversation changed, Show git-ignored files, Show dotfiles); the active code pane's file revealed and selected.
- **FR-10** Changes tab: scope chips (This conversation, Last turn, Not committed, All of main today) for conversations; groups "Not committed yet" then one group per commit (sha, subject, pushed/not pushed, time); file rows with diff / open beside / reveal; a diff view with previous/next file (`J`/`K`); the attribution footnote; the shared-file note per D-5.
- **FR-11** Search tab: content search (today's `ContentSearch`) scoped to the dock root; results marked with the changed-here dot.
- **FR-12** Go to file (`Ctrl+P`) and the `Ctrl K` palette find files: exact basename first, then basename prefix, then basename contains, then path contains; matches highlighted; files changed by the scoped conversation ranked first among equals and tagged "changed here".
- **FR-13** Opening a file places it beside the chat per D-4; the code pane shows a breadcrumb (root name › path), a File/Changes toggle, a Reveal-in-files button, and marks lines changed by the scoped conversation with a gutter bar.
- **FR-14** A code pane on a project root shows the read-only bar ("This is the main checkout… Start editing"); the first edit or **Start editing** creates or reuses an edit workspace without moving the cursor; from then on the bar shows the edit workspace, branch, changed-file count, +/−, save state, **Discard…** and **Create PR**.
- **FR-15** Create PR shows the title, the exact files with +/−, the question "How should it land?" with two described choices (Open a pull request / Send through the pipeline), "Open as a draft", and one primary button whose label follows the choice.
- **FR-16** After a PR opens, the editor bar shows its state: checks running (Merge disabled with the reason) → no conflicts (Merge enabled) → merged (workspace removed, tab now shows main, with a note). Send through pipeline shows the new issue and PR. Discard closes the edit workspace's tabs or switches them to main with a note.
- **FR-17** A code tab whose root no longer exists (`ROOT_NOT_FOUND`) shows "This edit workspace was merged or discarded" with **Open on main** and **Close tab**, never the generic "Couldn't open file".
- **FR-18** Stage tabs are 120–230 px with a kind icon and ellipsis, show no shortcut chips, and end with an "N tabs ▾" list of every tab; the + menu offers New conversation, Files, Changes in <project>, Go to file…, Terminal, Web page, each with its shortcut. A conversation tab with no title shows "New conversation", never `Chat <hash>`.
- **FR-19** The composer's controls share one style: attach (+), model, "Thinking: <level>", "Send: <mode>" (D-6), context %, mic, send. The model control looks enabled and, when the model cannot change mid-session, says why in its menu.
- **FR-20** The in-conversation subagents rail is closed by default; ⋯ → Subagents (N) opens it.

- **FR-22** The top bar per §6.7: breadcrumb, search, agents menu (list + Open Agents page + Stop all agents…), Needs-you button (count from D-8, menu of items across projects), health dot (popover with every system widget), theme.

### Non-functional
- **NFR-1** No server code uses `execSync` or other blocking process calls.
- **NFR-2** The changes API answers in under 500 ms for a conversation with 50 commits and 200 edited files on a warm cache; results are cached per conversation keyed by transcript size/mtime and repository HEAD, as `conversation-diffs.ts` does today.
- **NFR-3** No file grows past `scripts/lint-file-size.sh`'s ceiling or its allowlist row; owners extract first (§8).
- **NFR-4** No new polling loops faster than today's 5 s diff poll; the dock refreshes changes on the existing domain events and on the explorer watch stream.
- **NFR-5** Light and dark themes both match the mockup.
- **NFR-6** Every UI child's acceptance includes Playwright screenshots of the real dashboard at 1920×1000 in two states the operator reported: (1) a conversation running in a primary checkout on `main` with commits and an uncommitted file; (2) project Home in cockpit mode with issues loaded.

## 5. Repo rules that apply (restated)

- Dashboard runs Node 22 from `dist`; after server changes run `npm run build` before any live check. Never `bun run` the server, never `tsx`.
- No `execSync` in server-reachable code; use async `execFile` or the repo's async git helpers.
- Delay-based tests use `vi.useFakeTimers()`; never real `setTimeout` waits.
- Frontend test files must be listed in `scripts/frontend-test-subset.txt` or CI never runs them.
- A new HTTP route needs a `tests/unit/lib/overdeck/no-loss-matrix.ts` row, and a `route-scopes.ts` row unless it should stay at the `admin` default; a new `/api/conversations/*` route also needs an entry in `EXPECTED_CONVERSATION_ROUTES` (`tests/unit/dashboard/server/routes/conversations-no-loss.test.ts`).
- File size: ceiling 1000 lines for new files; a listed file may not grow past its last allowlist row; agents cannot raise rows — extract a module instead.
- Style guide: Broadsheet tokens only; no hardcoded hex; `font-medium`/tier rules; one colored signal per row; amber = human, blue = machine, emerald = outcome, red = broken, cyan = money; running is blue, never green.
- `components/chat/ChangedFilesTree.tsx` contains NUL bytes in its first 8 KB; tools that refuse binary files must rewrite it whole (it is replaced in child D anyway).
- A user-facing change adds `changelog.d/<issue>.md`.
- Workspaces are git worktrees; never `git checkout` other branches inside one; never `git stash`.

## 6. Architecture

### 6.1 Conversation changes (server)

New module `src/lib/overdeck/conversation-changes.ts` and route in `src/dashboard/server/routes/conversation-diffs.ts` (add to its `Layer.mergeAll`, search `Layer.mergeAll`).

```ts
// packages/contracts/src/conversation-changes.ts (new; exported from the package index)
export type ChangeScope = 'conversation' | 'turn' | 'uncommitted' | 'main';
export interface ChangedFile { path: string; status: 'A' | 'M' | 'D' | 'R'; additions: number; deletions: number; oldPath?: string }
export interface UncommittedFile extends ChangedFile {
  /** 'lines' when edit records attribute specific lines; 'file' when only the file is known. */
  attribution: 'lines' | 'file';
  /** Lines in the working-tree diff of this file that this conversation did NOT write (only when attribution === 'lines'). */
  otherLines?: number;
  /** Other conversations whose edit records match the other lines (Claude Code only; may be empty). */
  otherConversations?: { name: string; title: string }[];
}
export interface ChangeCommit {
  sha: string; shortSha: string; subject: string; authoredAt: string;
  pushed: boolean;
  /** How the commit was tied to the conversation. */
  attribution: 'trailer' | 'tool-output';
  files: ChangedFile[];
  /** Assistant message id of the turn that made it, when known. */
  turnId?: string;
}
export interface ConversationChanges {
  conversation: string; repoRoot: string; rootId: string | null; branch: string | null;
  scope: ChangeScope; turnId?: string;
  uncommitted: UncommittedFile[];
  commits: ChangeCommit[];
  totals: { files: number; additions: number; deletions: number; commitsPushed: number; commitsLocal: number; uncommittedFiles: number };
}
export interface ProjectCommit { sha: string; shortSha: string; subject: string; authoredAt: string; by: { kind: 'conversation' | 'agent' | 'unattributed'; id?: string; title?: string } }
export interface ProjectChanges { projectKey: string; branch: string; commits: ProjectCommit[] }
```

Algorithm for `getConversationChanges(name, { scope, turnId })`:
1. `lookupConversation` and `repoRootForDir(conv.cwd)` from `conversation-diffs.ts` (search `function lookupConversation`, `function repoRootForDir`).
2. Commits: `listAttributedCommits({ repoPath, key: 'Overdeck-Conversation', value: <session name>, since: conv.createdAt })` from #5281 (`src/lib/git/attributed-commits.ts`). Then the fallback: scan the conversation's work log (`getCachedMessages(sessionFile, false).workLog`, `src/lib/overdeck/conversation-reads.ts`) for shell tool entries whose `toolInput.command` contains `git commit` and whose `result` matches `/^\[(?<branch>[^\s\]]+)(?: \(root-commit\))? (?<sha>[0-9a-f]{7,40})\] (?<subject>.+)$/m`; resolve each sha with `git rev-parse --verify <sha>^{commit}` and drop ones that no longer resolve (amended or rebased). Union by sha; `attribution` = `trailer` if both.
3. Pushed: one `git rev-list @{u}..HEAD` per repo (no upstream ⇒ every commit `pushed: false`); a commit is pushed when it is not in that set.
4. Turn mapping: a commit's `turnId` is the assistant message whose time window contains the commit's authored time (tool-output commits: the message that owns the tool entry, by `createdAt`/`sequence`).
5. Uncommitted: `git status --porcelain=v2 -z` ∩ files this conversation edited (`fileEditsByAssistantId` paths for Claude Code; for other harnesses, files named in edit tool inputs if the parser exposes them, else none). For Claude Code, compute `attribution: 'lines'`: count working-tree diff `+` lines of the file that appear in this conversation's `new_string`/`content`/`edits[].new_string`; `otherLines` = the rest. `otherConversations`: for each other Claude Code conversation of the same project active in the last 7 days, the same match; list those that match ≥1 line. Non-Claude: `attribution: 'file'`.
6. Scope filters: `turn` = commits and uncommitted files of `turnId` (default: the last assistant turn with changes); `uncommitted` = uncommitted only; `main` = every commit on the current branch since the start of the server's local day, attributed per FR-6 (this is `ProjectChanges` shaped as `commits` with `attribution` set; the panel marks this conversation's).
7. Cache per (conversation, scope, turnId) keyed by transcript size+mtime and `git rev-parse HEAD`, 30 s TTL like `conversation-diffs.ts` (search `DIFFS_CACHE_TTL_MS`).
8. Per-file diffs for the panel reuse the existing endpoints: committed file = `GET /api/diffs/compare?repo&base=<sha>^&head=<sha>&file=` (`src/lib/diffs/compare.ts`, `compareRefs`); uncommitted file = `GET /api/conversations/:name/diffs/full?file=` (existing). Do not add a third diff renderer.

`getProjectChanges(key, { since })`: `git log --first-parent --since=<since> origin/<default>` with `%(trailers:key=Overdeck-Conversation,valueonly)` and `%(trailers:key=Overdeck-Agent,valueonly)`; map conversation names to titles via the conversation list and agent ids to issue ids.

Routes:
- `GET /api/conversations/:name/changes` — scope `read:conversations`, row in `route-scopes.ts` next to the other conversation diff rows (search `'/api/conversations/:name/diffs'`).
- `GET /api/projects/:key/changes` — no `route-scopes.ts` row: unlisted routes default to `admin` (search `return row?.scope ?? 'admin'`), like every other `/api/projects/*` route.
- no-loss-matrix rows: `{ surface: 'GET /api/conversations/:name/changes', kind: 'http', disposition: 'RELOCATE', door: 'Diffs' }` and the projects one, next to the existing diff rows (search `GET /api/conversations/:name/diffs`).

### 6.3 Dock scope

`deriveDockScope(activePane, deckKey, conversations, projects): DockScope` in `components/dock/dockScope.ts`:
- active pane is a conversation (`paneType: 'agent'` with a conversation id): root from `rootIdForConversation(conv)`; changes = that conversation.
- active pane is an issue overview / issue-scoped pane: `issue:<ID>`; changes = the issue workspace's uncommitted + commits since the default branch (explorer `gitStatus`).
- active pane is a `code` pane: its `explorerRootId`; reveal its `explorerPath`; changes = the scope of the pane the file was opened beside, else the root.
- active pane is project Home or anything else: `project:<deckKey>`; changes = **All of main today**.
- `rootOverride` (set when the operator picks another root in the Files tab header menu) wins until the active tab changes.

`rootIdForConversation(conv)` in `components/explorer/rootForConversation.ts`: `conv.issueId` → `issue:<ID>`; `conv.workspaceId` of a scratch edit workspace → `workspace:<id>`; `conv.cwd` equal to (or inside) the project's primary checkout, or a `main` registry row → `project:<projectKey>`; else `null` (dock shows "This conversation's folder is outside the project" with **Open project files**).

Root labels: replace `rootLabel()` in `explorer/explorer-rpc.ts` (search `export function rootLabel`) with a hook `useRootLabel(rootId)` returning the project's display name (from the projects list), the issue id + short title, or the edit workspace's `name` — never the project key `panopticon-cli` or a UUID.
