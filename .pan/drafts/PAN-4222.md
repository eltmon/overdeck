## Glossary

- **Agents page / Live view.** `/agents`, rendered by `src/dashboard/frontend/src/components/Agents/live/LiveAgentsView.tsx`. It lists rows in three counted sections (**Needs you**, **Live**, **Waiting**) and one uncounted **Idle footer** (`▸ N idle sessions · History`).
- **Row line 2.** The second text line of a `LiveAgentRow` (`data-component="agents-live-line"`): reason label (`agents-live-reason`), activity (`agents-live-activity`), then the age (`agents-live-age`) and, when quiet, `agents-live-quiet`.
- **Reason.** The one classification `classifyEntry()` in `live/live-model.ts` gives each row (kind, section, tone, label, detail).
- **Runtime snapshot.** `AgentRuntimeSnapshot` in `packages/contracts/src/types.ts`, folded per agent into `agentRuntimeById` by the shared reducer in `packages/contracts/src/event-reducers.ts` from `agent.*` runtime events.
- **Heartbeat ingestion.** Claude Code hook scripts in `sync-sources/hooks/` POST a body `{kind, ...}` to `POST /api/agents/:id/heartbeat`; `bodyToEvent()` in `src/dashboard/server/services/agent-event-utils.ts` turns it into a DomainEvent.
- **Tool description.** A short human label for the tool call a Claude Code agent is running, taken from the hook payload's `tool_input` (for Bash, the `description` the model wrote, such as `Commit WI-7`).
- **Quiet.** A Live row whose newest activity is older than `LIVE_QUIET_AFTER_MS` (5 minutes) shows `quiet <age>` in the stuck (red) tone.
- **Subagent rail.** The `Agents` side panel (`SubagentRail`, `components/chat/SubagentRail.tsx`, `w-64` = 256px) that `ConversationPanel` renders beside a transcript when the conversation has subagents.
- **Preview.** The right-hand panel of the Live view (and the detail pane of the History view), both `DirectoryDetail` → `DirectoryTranscript` → `ConversationPanel embedded`.
- **Provider error.** A Claude Code transcript record `{"type":"assistant","isApiErrorMessage":true,"apiErrorStatus":<n>,"error":"<code>","message":{"content":[{"type":"text","text":"API Error: ..."}]}}`, written when the provider rejects a turn (billing, rate limit, invalid request). Verified on this host, e.g. `~/.claude/projects/-home-eltmon-Projects-overdeck-workspaces-feature-pan-3841/582d6121-….jsonl`.
- **`runtimeId`.** New optional `DirectoryEntry` field: the id the entry's runtime events are keyed under when it differs from `id`. Conversations are keyed by their tmux session (`conv-<name>`), while their entry id is `conv:<name>`.

## Problem (verified against code at `5a27ee12bc6`)

1. **P0 — Live rows show no activity.** `LiveAgentRow.tsx` lines 141–143 read the last pane-output line:
   ```ts
   useAgentOutputSubscription(entry.id, live && entry.kind === 'agent' && entry.location === 'local');
   const lines = useDashboardStore((state) => state.agentOutputById[entry.id] ?? EMPTY_LINES);
   const activity = live ? lastOutputLine(lines) : reason.detail;
   ```
   In the critic's 45 s soak no row ever rendered an output line; every busy row read `running Bash · 1m`. A Claude Code TUI pane's last line is chrome (prompt, status bar), not activity, so even a working pane stream would not say what the agent is doing. The runtime snapshot carries only the tool **name**: `sync-sources/hooks/pre-tool-hook` line 22 extracts `.tool_name` and drops `tool_input`. Conversation rows get no runtime facts at all, because `LiveAgentsView.tsx` line 102 looks up `runtimeById?.[entry.id]` with `entry.id = conv:<name>`, while conversation hooks report under the tmux session `conv-<name>` (`agent-projection.ts` "keyed by the tmux session id").
2. **P1 — the preview is unusable at 1280px** for a conversation with subagents. `ConversationPanel.tsx` line 1108 always renders `<SubagentRail …/>`; the rail is `w-64` (256px) and reads its collapsed state from the global key `overdeck.ui.agentsRailCollapsed` (`SubagentRail.tsx` line 7). With the 360px list floor, the transcript shrinks to about 70px (`critic-4197/final/light-1280.png`).
3. **P2 — false quiet alarm and a doubled age.** `LiveAgentRow.tsx` `isQuiet()` (line 104) dates a row from `row.since` only. For a conversation, `since` is its transcript mtime, which does not move while the parent waits on working subagents (their transcripts are separate files). Lines 203–204 render both the age and `quiet <age>`, so the row reads `8m quiet 8m`.
4. **Empty state and provider errors.**
   - With zero rows the list says `Nothing is running or waiting. Finished work is in History.` (`LiveAgentsView.tsx` line 221) while the preview beside it says `Select an agent to see its transcript.` (`DirectoryDetail.tsx` line 61): two messages. The `History` link (line 183) has no underline until hover.
   - A conversation whose last turn failed with a provider error sits in the Idle footer (`classifyEntry` rule 13, `idle — no known blocker`). The existing `api-error` reason (live-model.ts line 119) fires only for issue agents, and only from tmux pane text.
   - **Correction to the issue's example.** `conv:20260924-3870` did **not** stop on a billing error. Its conversation title is `Debugging OpenCode workspace and billing issues`; Claude Code writes the session topic into the terminal title, which is where the critic read `OpenCode credits insufficient balance`. Its last transcript record (2026-09-25T23:01Z) is a normal assistant reply. The requirement stands, but the signal must be the transcript's provider-error record, never pane or title text. This conversation is the negative test case.

## Requirements

- **FR-1** A Live row for an agent running a tool shows line 2 as `<tool> · <tool description> · <age>`, for example `Bash · Commit WI-7 · 14s`. With no description it shows `<tool> · <age>`; while thinking, `thinking · <age>`; otherwise `working · <age>`.
- **FR-2** The tool description reaches the runtime snapshot from the Claude Code PreToolUse and PostToolUse hooks, and is cleared whenever `currentTool` is cleared.
- **FR-3** A conversation's Live row reads the runtime snapshot keyed by its tmux session, so it gets the same line 2 as an agent.
- **FR-4** A Live row's newest activity is the newest of its own activity and every nested subagent's `lastActivityAt`. A parent with a recently active subagent is never quiet.
- **FR-5** When a Live row is quiet, line 2 shows `quiet <age>` in place of the age, never both.
- **FR-6** Inside the Agents page preview (Live and History), the transcript's subagent rail starts collapsed to its 30px tab, without reading or writing `overdeck.ui.agentsRailCollapsed`.
- **FR-7** With no visible rows, the Live view shows exactly one empty-state message and no preview pane; the Idle footer still shows when idle sessions exist, and the `History` link is underlined.
- **FR-8** A live, idle conversation whose newest `user`/`assistant` transcript record is a Claude Code provider error goes to **Needs you** with the `API error or usage limit` reason (stuck tone), the error text as its detail, and the error's timestamp as its wait start.
- **NFR-1** Each classification change has a unit test: FR-1 labels, FR-4/FR-5 quiet, FR-8 provider error (including the conv-3870 negative case).
- **NFR-2** Old persisted `agent.activity_changed` events without the new field still decode (the field is optional).
- **NFR-3** No new per-row polling: the pane-output subscription leaves the Live row, and provider-error detection reads at most the last 64 KB of one transcript per live idle conversation, inside the existing conversation-list enrichment (TTL-cached).
- **NFR-4** Before/after Playwright screenshots in light and dark at 1600px and 1280px, linked from the PR body.

## Decisions (auto mode — also in `plan.autoDecisions`)

- **D1** Line 2's activity comes from the hook's `tool_input`, not pane output. The row drops `useAgentOutputSubscription`, `agentOutputById` and `lastOutputLine` (remove the now-unused export and its test).
- **D2** Description precedence, in `pan_tool_description` (bash, jq): `.tool_input.description` → basename of `.tool_input.file_path` → `.tool_input.pattern` → `.tool_input.url` → `.tool_input.skill` → empty. First line only, trimmed, cut to 120 characters. Without `jq`, the description is empty (the event still posts).
- **D3** The reason **label** becomes the bare tool name (`Bash`), not `running Bash`, to match the issue's `Bash · Commit WI-7 · 14s`. The description is the reason's `detail`.
- **D4** Conversation runtime lookup uses a new optional `DirectoryEntry.runtimeId`, set to the conversation row's `tmuxSession`. The frontend reads `runtimeById[entry.runtimeId ?? entry.id]`.
- **D5** Quiet uses **all** nested children, not only the three displayed. This also moves the preview header's `active … ago` for live rows (it is dated from `since`, `LiveAgentsView.tsx` lines 129–133). That is intended.
- **D6** The rail default is a prop (`defaultCollapsed`) on `SubagentRail`, passed through a new `ConversationPanel` prop `subagentRailCollapsed`. `DirectoryTranscript` sets it for the `agent` and `conversation` routes, so both the Live preview and the History detail get it. The rail stays expandable in place; that choice is not persisted.
- **D7** Empty state: when `rows.length === 0` (no Needs you, Live or Waiting rows, and the Idle footer collapsed or empty), render a single column with no `Group`/preview. It shows the one message plus the Idle footer if idle sessions exist. The header's preview toggle keeps its state and applies again once rows appear.
- **D8** Provider-error scope: `claude-jsonl` transcripts only, conversations only, and only when `sessionAlive && !isWorking && pendingInputCount === 0`. It reuses reason kind `api-error` and label `API error or usage limit`; no new kind. A stopped session is outside the live scope and is not surfaced.
- **D9** Evidence: screenshots are pushed to an orphan branch `evidence/pan-4222`, created in a throwaway worktree under the workspace's gitignored `.tmp/`, never by `git checkout` in the workspace. The PR body embeds `https://github.com/eltmon/overdeck/blob/evidence/pan-4222/<file>.png?raw=true` links. Screenshots are not committed on the feature branch.
- **D10** One issue, one PR. The four defects share one acceptance (one screenshot set). The plan sets `sizeJustification`: the first-two-path-segments rule counts each doc file as its own subsystem, and roughly half the files are tests and docs.

## Repo rules that intersect this work (restated)

- **Fake timers** for any time-based test (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`); the Live view tests already use them. Never real waits.
- **No `execSync`** in server-reachable code; the provider-error reader uses `node:fs/promises` `open`/`read` (pattern: `src/lib/agents/transcript-turn.ts` `readTailRecordsNewestFirst`).
- **Style guide:** running is blue (`--state-live`), never green; stuck red is `text-state-stuck`; no pill badges; one colored signal per row.
- **Quality gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host. Rebuild `packages/contracts` after touching it.
- **Never run `pan sync`, `pan reload` or `pan restart` from the workspace.** `pan sync` distributes hooks machine-wide; the dashboard is the flywheel's to deploy.
- **Playwright isolation:** use a fresh isolated browser context, and abort every non-GET `/api/*` request in it (`page.route`), so screenshots never mutate the production dashboard (theme PUT, session POST).
- **JSONL transcripts are read-only.** Never write or truncate `~/.claude/projects/**`.
