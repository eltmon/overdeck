## Glossary

- **Internal token** — the root secret at `~/.overdeck/internal-token` (mode 0600), read by `getInternalToken()` in `src/lib/internal-token.ts`. Sent as header `x-overdeck-internal-token` (`INTERNAL_TOKEN_HEADER`) or `Authorization: Bearer <token>`.
- **Session cookie** — `overdeck_session` (`DASHBOARD_SESSION_COOKIE`, `src/dashboard/server/routes/dashboard-auth.ts:12`). Its value is an HMAC of the internal token with context `overdeck-dashboard-session-v1` (`dashboard-auth.ts:43-46`, search `'overdeck-dashboard-session-v1'`). Because it is derived, a dashboard restart does NOT invalidate open tabs' cookies (already locked by `dashboard-auth.test.ts:51`, "keeps a previously-minted session cookie valid across a restart"). Attributes: `Path=/; HttpOnly; SameSite=Strict; Max-Age=2592000` (30 days, rolling), host-only.
- **Credential check** — `hasDashboardAuthHeaders(headers: HeaderMap): boolean` (`dashboard-auth.ts:123-125`). True when the headers carry the internal token (header or Bearer) OR a valid session cookie. Constant-time comparison. This is THE credential check this issue reuses; do not write a new one.
- **Session mint** — `POST /api/dashboard/session` (`src/dashboard/server/server.ts:202-231`, search `const dashboardSessionRouteLayer`). Passes when origin is valid AND (internal token OR loopback peer OR existing valid session). Sets the session cookie and returns `{ ok: true, csrfToken }`.
- **Loopback peer** — `isLoopbackPeer(request)` (`dashboard-auth.ts:275-288`): TCP peer is `127.0.0.1`/`::1`, OR an IP inside a host-local RFC1918 Docker bridge subnet (`peerIsHostLocalDockerBridge`), OR (in a container) inside one of the container's own subnets. Reads only the real TCP peer, never `X-Forwarded-For`. Host-local Traefik reaches the dashboard from a Docker-bridge IP, so every `overdeck.localhost` browser auto-mints with zero steps.
- **Origin check** — `validateOriginHeaders(headers, method)` (`src/dashboard/server/routes/origin-validation.ts:113-145`). A present `Origin` (or `Referer`) must be in `getTrustedOrigins()`. **A GET with neither header passes** (`if (!origin && !referer) { … if (upperMethod === 'GET' …) return { ok: true }`). WebSocket upgrades are GETs.
- **The hotfix** — the PAN-457 cookie/token gate was removed from `/ws/terminal` and `/ws/rpc`, leaving origin-only checks:
  - `/ws/terminal`: `authorizeTerminalUpgrade()` at `src/dashboard/server/ws-terminal.ts:120-133` (comment starts `// Hotfix for #1166`).
  - `/ws/rpc`: inline check at `src/dashboard/server/ws-rpc.ts:1208-1216` (comment starts `// Hotfix for #1166`).
  - `/ws/voice`: private `isTrustedWebSocketOrigin` at `src/dashboard/server/ws-voice.ts:27-31`, used at `:53`.
  - `/ws/autopreso`: private `isTrustedWebSocketOrigin` at `src/dashboard/server/ws-autopreso.ts:18-22`, used at `:43`.
- **Upgrade authorizer** — the new shared function this PRD introduces: `authorizeDashboardUpgrade` in `src/dashboard/server/ws-auth.ts`.
- **Connection store / phase** — `src/dashboard/frontend/src/lib/connectionState.ts` (PAN-4279). A Zustand store of inputs; the phase (`live | delayed | unreachable | restarting`) is derived, never stored. `DegradedModeBanner.tsx` and `App/BackendConnectionBoundary.tsx` (`FirstLoadScreen`) render it.
- **Bootstrap token** — `pan up` opens `${url}#overdeck_token=<internal token>` (`src/cli/index.ts:1238`); `pan dev` does the same (`src/cli/commands/dev.ts:630`). The frontend consumes it in `consumeDashboardBootstrapToken()` (`src/dashboard/frontend/src/lib/wsTransport.ts:57-69`) and sends it on the mint.
- **Silent 401** — `ensureDashboardSession()` (`wsTransport.ts:71-91`) mints on one or two hosts (`dashboardSessionUrls`, `:47-52`, two hosts when `VITE_API_URL` points at a different host — PAN-3711) and does `if (response.status === 401) return null` (`:80`), so a failed mint is invisible.
- **Reauth token** — `reauth-*` terminal sessions also require a one-time `pan_codex_reauth` cookie (`ws-terminal.ts:287-305`, `consumeReauthTerminalToken`). Unchanged; it runs AFTER the upgrade authorizer.

## Problem

`/ws/terminal` (PTY read/write), `/ws/rpc` (all domain events + RPC), `/ws/voice` (microphone transcription into the composer), and `/ws/autopreso` (whiteboard stream) authorize upgrades by origin only. A GET upgrade with no `Origin` header passes `validateOriginHeaders`. The dashboard API binds `0.0.0.0`, so **any machine on the LAN that can reach the port gets a live PTY on `/ws/terminal` by simply omitting the Origin header** — no browser, no credential. Origin checks stop cross-site *browser* attacks only; they stop nothing that sets its own headers.

The gate was removed in 2026-05 because it broke every Traefik (`overdeck.localhost`) terminal. The three root causes are understood and two are already fixed on `main`:

1. Mint required the URL-hash token that only `pan up` injects → **fixed**: loopback/Docker-bridge peers auto-mint (`isLoopbackPeer`).
2. Session token was random per boot → **fixed**: HMAC-derived (`dashboard-auth.ts:43-46`), test at `dashboard-auth.test.ts:51`.
3. The frontend swallows the mint 401 → **still present** (`wsTransport.ts:80`). This PRD fixes it.

So the gate can come back now, provided the frontend mints before it connects and shows a failed mint loudly.

## Requirements

- **FR-1** All four realtime surfaces — `/ws/terminal`, `/ws/rpc`, `/ws/voice`, `/ws/autopreso` — authorize upgrades through ONE shared function, `authorizeDashboardUpgrade`: origin check (403 on failure), then internal-token configured (503 if not), then credential = `hasDashboardAuthHeaders` (session cookie OR internal token header/Bearer; 401 on failure). The reauth one-time token stays an additional check for `reauth-*` sessions.
- **FR-2** Browsers authenticate WebSocket upgrades with the session cookie only (browsers attach same-site cookies to upgrade requests automatically). Non-browser clients authenticate with the internal token in a header. No credential ever travels in a WebSocket URL in this issue.
- **FR-3** Peer-based trust lives ONLY in the session mint. The upgrade authorizer does NOT consult `isLoopbackPeer`; a loopback client without a cookie or internal token gets 401 on upgrade. (One chokepoint, so PAN-2351's `require_token_mint` switch closes peer trust everywhere at once.)
- **FR-4** The frontend mints before it connects: `/ws/rpc` (already — `WsTransport` constructor, `wsTransport.ts:157`), `/ws/terminal` (`XTerminal.tsx`), `/ws/voice` and `/ws/autopreso` (`useAutoPresoWebSocket.ts`, `useVoiceTranscription.ts`) all await `ensureDashboardSession()` before `new WebSocket(...)`.
- **FR-5** A 401 from ANY mint host rejects `ensureDashboardSession()` with a typed `DashboardSessionUnauthorizedError`, sets the connection-store input `sessionAuthFailed = true`, and the dashboard shows an `unauthorized` phase banner naming `docs/DASHBOARD-AUTH.md`. A later successful mint sets `sessionAuthFailed = false`.
- **FR-6** `XTerminal` does not reconnect-loop on a failed mint: on `DashboardSessionUnauthorizedError` it sets its status to `'failed'` and schedules no reconnect timer.
- **FR-7** `docs/DASHBOARD-AUTH.md` states the threat model: what the gate defends (LAN clients reaching the `0.0.0.0` port; non-browser clients that can set their own `Origin`), what it does NOT defend (any process on this machine — it can mint as a loopback peer; LAN clients via Traefik with a forged `Host` → PAN-4299), and the 2026-05 post-mortem.
- **NFR-1** No behavior change for the standard flows: `pan up` bootstrap, Traefik `overdeck.localhost`, plain `localhost:3011`, `pan dev` on Vite, Electron desktop (window served from the embedded server's HTTP origin — `apps/desktop/src/main.ts:116-129`, same-origin, so cookies attach).
- **NFR-2** Tests that exercise reconnect/backoff/delays use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`; no real-clock waits (repo rule `fake-timers-for-retry-tests`).
- **NFR-3** No `execSync` anywhere in server-reachable code (repo rule `no-execsync-server`).

## Decisions (made here, not left to the implementer)

- **D-1 Credential = cookie OR internal token; no raw loopback trust on upgrade.** Rationale: FR-3. Consequence: a local script must mint first (POST the mint from loopback, keep the cookie) or send the internal token header. `src/dashboard/frontend/tests/terminal-latency.spec.ts` opens `/ws/terminal` inside `page.evaluate` on a page already loaded from `localhost:3011`, so the page's cookie attaches and it keeps working.
- **D-2 Origin rule = `validateOriginHeaders`.** A present `Origin` must be trusted (403 otherwise). An absent `Origin` is allowed through to the credential check (non-browser clients). This relaxes `/ws/voice` and `/ws/autopreso`, which today 403 an absent `Origin`, but the credential check now runs after it, so a credential-less request still fails (401). Browsers always send `Origin` on upgrades, so cross-site WebSocket hijacking stays blocked.
- **D-3 Status codes:** 403 bad origin, 503 no internal token configured (mirrors `rejectUnauthorizedDashboardRequest`, `dashboard-auth.ts:303-314`), 401 no credential. Raw-upgrade endpoints write `HTTP/1.1 <status> <message>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n` and destroy the socket (the existing `rejectUpgrade` shape, `ws-terminal.ts:97-100`), which moves into `ws-auth.ts` as `rejectUpgrade` and is reused by all three raw endpoints. `/ws/rpc` returns `jsonResponse({ error: message }, { status })`.
- **D-4 Any-host 401 = failure.** With two mint hosts (PAN-3711), `XTerminal` connects to `window.location.host`, which may be the second host. A 401 on either host means some socket will fail, so either one rejects `ensureDashboardSession()`.
- **D-5 `unauthorized` phase precedence:** `restarting` > `unauthorized` > `unreachable` > `delayed` > `live`. `unauthorized` is included in `isWriteBlockedPhase` (writes would fail CSRF anyway). The banner has a **Retry** button (re-runs the mint via `requestReconnect`; `ensureDashboardSession` already clears its cached promise on rejection, `wsTransport.ts:86-89`) and no Force Restart.
- **D-6 Scope of PAN-2351 coupling:** none in code. `ws-auth.ts` carries a single comment line at the credential step: `// PAN-2351 adds scoped access tokens (?token=) here.` Nothing else.

### W1 — Shared upgrade authorizer `src/dashboard/server/ws-auth.ts` (new)

```ts
// src/dashboard/server/ws-auth.ts
import type { Socket } from 'node:net';
import { getInternalToken } from '../../lib/internal-token.js';
import { hasDashboardAuthHeaders } from './routes/dashboard-auth.js';
import { validateOriginHeaders, type HeaderMap } from './routes/origin-validation.js';

export type UpgradeAuthResult = { ok: true } | { ok: false; status: 401 | 403 | 503; message: string };

export function authorizeDashboardUpgrade(headers: HeaderMap, method: string): UpgradeAuthResult {
  const origin = validateOriginHeaders(headers, method);
  if (!origin.ok) return { ok: false, status: 403, message: origin.error };
  if (!getInternalToken()) return { ok: false, status: 503, message: 'dashboard session token not configured' };
  // PAN-2351 adds scoped access tokens (?token=) here.
  if (!hasDashboardAuthHeaders(headers)) return { ok: false, status: 401, message: 'Unauthorized' };
  return { ok: true };
}

export function rejectUpgrade(socket: Socket, status: number, message: string): void {
  socket.write(`HTTP/1.1 ${status} ${message}\r\nConnection: close\r\nContent-Length: 0\r\n\r\n`);
  socket.destroy();
}
```

Module header comment: one paragraph naming FR-1/FR-3 and pointing at `docs/DASHBOARD-AUTH.md`.

Cases:
1. trusted origin `http://localhost:3011` + no credential ⇒ `{ ok: false, status: 401 }`.
2. untrusted origin `https://evil.example` + valid cookie ⇒ 403.
3. trusted origin + valid session cookie (from `dashboardSessionCookieHeader()`) ⇒ ok.
4. no origin + `x-overdeck-internal-token` ⇒ ok.

6. no origin + no credential ⇒ 401.
7. no internal token configured (env unset, cache reset) ⇒ 503.
8. trusted origin + cookie minted under a different internal token ⇒ 401.
