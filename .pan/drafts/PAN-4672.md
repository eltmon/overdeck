# PAN-4672: Address CodeRabbit findings missed on merged PRs #4662 and #4637

**Issue:** https://github.com/eltmon/overdeck/issues/4672
**Status:** planned (auto mode, 2026-11-01)
**Base:** `feature/pan-4672` at `d2969326eac` (no drift on the touched files versus `origin/main` at planning time)

## Glossary

- **Compose file** — `~/.overdeck/traefik/docker-compose.yml`, the Docker Compose file that starts the `overdeck-traefik` container.
- **Compose migration** — `migrateTraefikCompose(composePath)` in `src/lib/traefik.ts`. It rewrites the compose file's network block and its 80/443/8080 port lines to the configured bind address (PAN-4299). It returns `true` when the file changed.
- **Atomic write** — write the new content to a temporary file in the same directory, then `renameSync` it over the target. POSIX `rename` within one filesystem replaces the target in one step, so a crash leaves either the old file or the new file, never a truncated one.
- **Bind address** — `traefik.bind` in `~/.overdeck/config.toml`. `"all"` maps to host IP `0.0.0.0`; anything else maps to `127.0.0.1` (`resolveTraefikBindAddress`).
- **Hold** — `holdRequestsUntilServed(server, timeoutMs)` in `src/dashboard/server/server-bind.ts`. It installs a temporary `request` listener on the dashboard's Node HTTP server that queues requests until Effect's `HttpRouter.serve` attaches the real handler, then replays them to it.
- **Expired hold** — the state after the hold's timer (default 120 s) fires with no real handler attached.
- **`pan up` Traefik start** — the inline block in the `up` command action in `src/cli/index.ts` (around line 720).
- **`pan dev` Traefik start** — the inline block in `devCommand` in `src/cli/commands/dev.ts` (around line 292).

## Problem

CodeRabbit posted five Minor findings on PR #4662 (PAN-4299) and PR #4637 after both had merged. Operator policy is to act on CodeRabbit findings. Each finding was re-verified against the code at `d2969326eac`:

1. **Non-atomic compose write.** `src/lib/traefik.ts:277` — `writeFileSync(composePath, after, 'utf-8');`. A crash or full disk during the write truncates the compose file, and the next `docker compose up -d` fails.
2. **Migration shares the start's try/catch (`pan dev`).** `src/cli/commands/dev.ts:293-301`: `migrateTraefikCompose(...)` and `execSync('docker compose up -d', ...)` sit in one `try`. A migration throw skips the start and prints "Failed to start Traefik".
3. **Same defect in `pan up`.** `src/cli/index.ts:722-742`: `const migrated = (await import('../lib/traefik.js')).migrateTraefikCompose(...)` is the first statement of the `try` whose `catch` prints "⚠ Failed to start Traefik". `src/lib/platform-lifecycle.ts:550-556` (`startTraefikBody`) already isolates the migration in its own `try/catch`.
4. **Wrong IPv6 claim, duplicated.** `docs/DASHBOARD-AUTH.md:377-379` says "IPv6 LAN clients reach Traefik through the `[::]` docker-proxy listener and appear as the bridge gateway". `guides/docker-setup.mdx:62` says "IPv6 LAN clients look like local traffic". The migration writes explicit `0.0.0.0:` host addresses. **Planning probe (Docker 29.3.0, this host):** `docker run -d --rm -p 0.0.0.0:18731:6379 redis:7-alpine` → `docker port` printed only `6379/tcp -> 0.0.0.0:18731`, and `ss -ltnp` showed only `0.0.0.0:18731`. An explicit `0.0.0.0` mapping requests no IPv6 listener. Only a port line with no host address (the pre-PAN-4299 form, `"80:80"`) publishes on `[::]` too — this host's live `overdeck-traefik` still shows `80/tcp -> [::]:80`, because its container predates the migration.
5. **Hold goes silent after its timeout.** `src/dashboard/server/server-bind.ts:44-76`. When the timer fires, `release(null)` answers 503 to the requests already held, then `server.off('request', hold)` and `server.off('newListener', onNewListener)`. A request that arrives after the timeout but before `HttpRouter.serve` attaches finds no `request` listener and is never answered — the original PR #4637 hang.

## Requirements

### Functional

- **FR-1** `migrateTraefikCompose` writes the compose file atomically: temp file in the same directory, then `renameSync`. A failed write or rename leaves the original file byte-identical and leaves no temp file behind. The original file mode is preserved even under a restrictive umask (the temp file is `chmodSync`'d to the original mode before the rename).
- **FR-2** In `pan dev`, a compose migration throw is logged as a warning and `docker compose up -d` still runs.
- **FR-3** In `pan up`, a compose migration throw is logged as a warning and Traefik still starts: `docker compose up -d` runs unless the `docker ps` check positively finds the container running. A thrown migration counts as "file unchanged", so a running container is left alone. A failed `docker ps` check establishes nothing, so `up -d` is attempted.
- **FR-4** After the hold expires, every request that arrives before a real handler attaches gets `503` with `Retry-After: 5`. When a real handler attaches later, the hold listener is removed and later requests reach the handler.
- **FR-5** `docs/DASHBOARD-AUTH.md` and `guides/docker-setup.mdx` each state the IPv6 behaviour once and correctly, scoped to the three managed port lines: Overdeck writes the 80, 443 and 8080 lines with an explicit IPv4 host address, which requests no IPv6 `[::]` listener; any other port line without a host address still publishes on IPv6 as well. Neither doc claims categorically that IPv6 clients cannot connect.
- **FR-6** `docs/DASHBOARD-ARCHITECTURE.md` documents the startup hold: requests that arrive before the router attaches are held and replayed; after 120 s they get 503 + `Retry-After: 5` until the router attaches.

### Non-functional

- **NFR-1** No `execSync` is added in dashboard-server-reachable code. The new CLI helper uses `promisify(exec)`.
- **NFR-2** The new hold test uses fake timers and an in-memory server/response double — no sockets, no real delay (fake-timers rule). The existing socket tests in `server-bind.test.ts` stay as they are.
- **NFR-3** No file grows past its file-size cap. `src/cli/index.ts` is 1267 lines (cap 1379) and shrinks; `src/cli/commands/dev.ts` (680) shrinks; the new module stays far under the 1000-line ceiling.

## Decisions

- **D-1 Shared helper in `src/cli/commands/traefik-start.ts`.** The issue's AC requires tests for both `pan dev` and `pan up`, and neither inline block is testable (`devCommand` kills processes and is ~480 lines; the `up` block is inside a commander action). Extract one helper, `startTraefikContainer(traefikDir, { skipWhenRunning }, deps?)`, beside `up-ollama.ts`, with injectable `migrate`/`exec`/`log` like `ensureOllamaForUp`. It does **not** go in `src/lib/traefik.ts`: that keeps the atomic-write item and this item on disjoint files, and keeps the existing `vi.mock('../../../src/lib/traefik.js', () => ({ migrateTraefikCompose }))` in `tests/unit/lib/platform-lifecycle-traefik.test.ts` valid.
- **D-2 Preserve both callers' behaviour.** `pan dev` passes `skipWhenRunning: false` (always runs `up -d`, as today). `pan up` passes `skipWhenRunning: true` (skips `up -d` only when the container is running **and** the migration reported no change, as today). A thrown migration yields `migrated = false`. The `docker ps` check has its own `try/catch`: only a successful check that finds `overdeck-traefik` skips `up -d`; a rejected check falls through to `up -d`.
- **D-3 Inline atomic write in `traefik.ts`.** Do not reuse `atomicWriteProjectsConfigSync` (`src/lib/projects-config-write.ts` header: "Do not add new synchronous callers") or `atomicWriteJson` (JSON-shaped). Temp name `${composePath}.${process.pid}.tmp`, mode read from `statSync(composePath).mode & 0o777` and applied with `chmodSync(tmpPath, mode)` before the rename (a `mode` option on `writeFileSync` is masked by the umask), `rmSync(tmp, { force: true })` on failure, then rethrow. No fsync (matches CodeRabbit's suggestion; the compose file is regenerable).
- **D-4 Hold follows CodeRabbit's `expired` shape.** Keep `hold` and `onNewListener` installed after the timeout; `hold` answers 503 while `expired` is true. `release` loses its `null` branch and only runs when a real handler attaches.
- **D-5 IPv6 doc wording** is fixed text (Work item 5), grounded in the Docker 29.3.0 probe above and scoped to the three managed port lines: `rewriteTraefikComposePorts` rewrites only same-port 80/443/8080 lines (`src/lib/traefik.ts:245-255`) and preserves any other mapping, such as the `8443:443` line in the test fixture. The shipped template (`sync-sources/templates/traefik/docker-compose.yml:9-11`) has only the three managed lines. Keep the stale-container caveat: a container created from a pre-migration compose file can still publish on `[::]` until `pan restart --traefik` recreates it, and `pan doctor` reports it.
- **D-6 `platform-lifecycle.ts` is not changed.** It already isolates the migration and throws `StageError` on a failed start — different error semantics from the CLI's warn-and-continue.

```ts
 * Bring ~/.overdeck/traefik/docker-compose.yml up to date: external network and
 * ports on the configured bind address. Returns true when the file changed —
 * the caller must recreate a running container for new ports to apply.
 * The write is atomic (temp file + rename, PAN-4672): a crash leaves the old file.
 */
export function migrateTraefikCompose(composePath = join(TRAEFIK_DIR, 'docker-compose.yml')): boolean {
  if (!existsSync(composePath)) return false;
  const before = readFileSync(composePath, 'utf-8');
  const address = resolveTraefikBindAddress(loadConfigSync().traefik?.bind);
  const after = rewriteTraefikComposePorts(rewriteTraefikComposeNetwork(before), address);
  if (after === before) return false;
  const mode = statSync(composePath).mode & 0o777;
  const tmpPath = `${composePath}.${process.pid}.tmp`;
  try {
    writeFileSync(tmpPath, after, 'utf-8');
    chmodSync(tmpPath, mode); // explicit: a writeFileSync `mode` option is masked by the umask
    renameSync(tmpPath, composePath);
  } catch (error) {
    rmSync(tmpPath, { force: true });
    throw error;
  }
  return true;
}
```

```ts
import chalk from 'chalk';
import { exec } from 'child_process';
import { join } from 'path';
import { promisify } from 'util';
import { migrateTraefikCompose } from '../../lib/traefik.js';

const execAsync = promisify(exec);

export type TraefikStartResult = 'started' | 'already-running' | 'failed';

export interface TraefikStartDeps {
  migrate?: (composePath: string) => boolean;
  exec?: (command: string, cwd: string) => Promise<{ stdout: string }>;
  log?: (line: string) => void;
}

/**
 * Start the Traefik container for `pan up` and `pan dev` (PAN-4672). The compose
 * migration runs in its own try/catch, as in platform-lifecycle's startTraefikBody:
 * a throw is logged and never skips `docker compose up -d`. A thrown migration
 * counts as "file unchanged", so `skipWhenRunning` leaves a running container alone;
 * only a successful `docker ps` that finds it skips the start. Never rejects.
 */
export async function startTraefikContainer(
  traefikDir: string,
  options: { skipWhenRunning: boolean },
  deps: TraefikStartDeps = {},
): Promise<TraefikStartResult> {
  const migrate = deps.migrate ?? migrateTraefikCompose;
  const run = deps.exec ?? ((command: string, cwd: string) => execAsync(command, { cwd }));
  const log = deps.log ?? ((line: string) => console.log(line));
  let migrated = false;
  try {
    migrated = migrate(join(traefikDir, 'docker-compose.yml'));
  } catch (error) {
    log(chalk.yellow(`⚠ Traefik compose migration failed: ${error instanceof Error ? error.message : String(error)}`));
  }
  if (options.skipWhenRunning && !migrated) {
    try {
      const { stdout } = await run('docker ps --filter "name=overdeck-traefik" --format "{{.Names}}" 2>/dev/null', traefikDir);
      if (stdout.trim().includes('overdeck-traefik')) return 'already-running';
    } catch {
      // A failed check proves nothing about the container; attempt the start below.
    }
  }
  try {
    await run('docker compose up -d', traefikDir);
    return 'started';
  } catch {
    return 'failed';
  }
}
```

After:

```ts
export function holdRequestsUntilServed(
  server: Server,
  timeoutMs: number = HOLD_REQUESTS_TIMEOUT_MS,
): () => number {
  const held: Array<[IncomingMessage, ServerResponse]> = [];
  let released = false;
  let expired = false;
  const respondStarting = (res: ServerResponse) => {
    if (res.headersSent) return;
    res.writeHead(503, { 'Content-Type': 'text/plain', 'Retry-After': '5' });
    res.end('Overdeck dashboard is still starting');
  };
  const hold: RequestListener = (req, res) => {
    if (expired) respondStarting(res);
    else held.push([req, res]);
  };
  const release = (handler: RequestListener) => {
    if (released) return;
    released = true;
    clearTimeout(timer);
    server.off('request', hold);
    server.off('newListener', onNewListener);
    for (const [req, res] of held.splice(0)) handler(req, res);
  };
  const onNewListener = (event: string | symbol, listener: unknown) => {
    if (event !== 'request' || listener === hold) return;
    // newListener fires before the listener is added; replay once it is.
    queueMicrotask(() => release(listener as RequestListener));
  };
  const timer = setTimeout(() => {
    // Keep `hold` installed: until a real handler attaches, every request gets 503.
    expired = true;
    for (const [, res] of held.splice(0)) respondStarting(res);
  }, timeoutMs);
  timer.unref();
  server.on('request', hold);
  server.on('newListener', onNewListener);
  return () => held.length;
}
```
