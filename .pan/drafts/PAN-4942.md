## Glossary

- **Agent token:** a `kind: 'token'` access-token record with `agentId`, `agentKind` (`'agent' | 'conversation'`) and `role` (W-TOK1). Its dashboard credential is `{ kind: 'token'; tokenId; scopes; agentId?; agentKind?; role? }`.
- **Self route:** a route under `/api/self/` that acts for the agent whose token calls it. `selfCallerFromCredential` (`src/dashboard/server/self-caller.ts:52`) turns a credential into a `SelfCaller` (`agentId`, `agentKind`, `role`, `cwd`, `issueId`, `tmuxSession`, lines 20-31) or a 403 `not-an-agent-token` / 404 `agent-gone` refusal.
- **Root credential:** `internal-token` or `root-session`. Only a browser on this machine (root session) or the `pan` CLI (internal token) holds one.
- **Agent request:** a pending question from an agent to the operator, answered in the dashboard. The in-memory store is `src/dashboard/server/services/agent-requests.ts` (W-SEC1). W-SEC1 built the `secret` kind; this item adds the `machine-link` kind.
- **Machine-link request:** an agent request of kind `machine-link`. It carries a `hint` (the operator's own words for the machine, such as "my desk Mac") and, once settled `linked`, the new link's `environmentId` and `label`.
- **Link a machine flow:** the existing dialog `LinkMachineDialog` (`src/dashboard/frontend/src/components/Settings/anywhere/LinkMachineDialog.tsx`). The operator pastes a pairing link that `pan pair` printed on the other machine, picks an access level, and the dialog posts `POST /api/machines/link` (`machinesApi.ts:61`). The answer is a `MachineLinkView` with `environmentId` and `label` (`packages/contracts/src/machines.ts:166-169`).
- **Pairing link / pairing code:** the `#pair=…` URL (with its one-time `odp_` code) that `pan pair` prints. It authorizes a link. It must never reach an agent (FR-8).
- **Machine link record:** a `MachineLink` in `~/.overdeck/machine-links.json`, read through `listLinks()` (`src/lib/anywhere/link-store.ts:221`). It has `environmentId`, `label` and `revokedAt` (`link-store.ts:35-51`). `getLink(idOrEnvOrLabel)` (line 233) matches id, environment id or label, and returns revoked links too.
- **Anywhere dialog store:** the zustand store `useAnywhereDialogStore` (`components/Settings/anywhere/anywhereDialogStore.ts`) that says which Settings → Anywhere dialog is open from outside Settings. `AnywhereDialogHost` (`AnywhereDialogHost.tsx`, mounted once in `main.tsx`) renders it.
- **Decisions panel:** `components/DecisionsPanel.tsx`, the list of everything waiting on the operator, fed by `useDecisions` (`lib/useDecisions.ts`). It renders `AgentRequestCard` for any decision with `agentRequest` set (`DecisionsPanel.tsx:245-248`).
- **Wait chunk:** one blocking call of at most 50 s (`WAIT_CHUNK_MS`, `src/lib/mcp/tool.ts`). A wait answers `pending` with `next`, the call to make again.
- **No-loss matrix:** `tests/unit/lib/overdeck/no-loss-matrix.ts`. Every HTTP route in a top-level file of `src/dashboard/server/routes/` needs a row, or `no-loss-matrix.test.ts` fails.
- **Route-scope table:** `ROUTE_SCOPES` in `src/dashboard/server/route-scopes.ts`. An unlisted route needs `admin`, so a registry credential without `admin` gets 403 `insufficient_scope` at the gate.

## Requirements

### Functional

- **FR-1 Ask.** An agent with an agent token holding `tell` can create a machine-link request with a `hint` of 1 to 200 characters. The answer is `{ requestId, status: 'pending', expiresAt, next }`, where `next` is the `link_machine_wait` call. (Epic FR-8.)
- **FR-2 Wait.** The requesting agent can wait on its request for at most 50 s per call. The wait answers `pending` with `next`, `linked` with `machine: { environmentId, label }`, `declined` or `expired`. No other agent can wait on it.
- **FR-3 Card.** The Decisions panel shows a pending machine-link request as a blocking card with the badge "Machine link requested" and the text "<label> asks you to link a machine: <hint>". A root-session viewer gets **Link a machine…** and **Dismiss**; any other viewer reads "Answer this on <machine>'s own dashboard".
- **FR-4 Link through the existing flow.** **Link a machine…** opens the existing Link a machine dialog with the request id. After the dialog links a machine, it resolves the request with the new link's environment id, and the agent's wait answers `linked` with that machine's label.
- **FR-5 Dismiss.** **Dismiss** settles the request `declined`.
- **FR-6 No pairing code reaches the agent.** The agent's tool inputs and outputs carry only the `hint`, the request id, the status, `expiresAt`, `next` and `{ environmentId, label }`. The pairing link stays in the dialog and the `POST /api/machines/link` body.
- **FR-7 Tools.** `link_machine` (`{ hint }`) and `link_machine_wait` (`{ requestId }`) are agent-only MCP tools (`audience: 'agent'`) over the two self routes.

### Non-functional

- **NFR-1 One authority.** The tools call self routes; `route-scopes.ts` judges them; the handlers require an agent token. The resolve route accepts only root credentials.
- **NFR-2 Truth from the link store.** The resolve route answers the label from the active machine link record, never from the request body.
- **NFR-3 Async only.** No `execSync`, `spawnSync` or `execFileSync`; no new `*Sync` function (repo rules `no-execsync-server`, `prefer-async`).
- **NFR-4 Fake timers.** Tests of expiry and waits use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`, never real sleeps (repo rule `fake-timers-for-retry-tests`). Frontend tests that need a timeout use an `AbortController` plus `setTimeout`, not `AbortSignal.timeout`.
- **NFR-5 File size.** Every touched file stays under 600 lines.
- **NFR-6 Route rules.** Every new HTTP route lives in an existing top-level `routes/` file, has a `no-loss-matrix.ts` row, and has a `route-scopes.ts` row unless it is root-only (then a comment says so, as W-SEC1 did).
- **NFR-7 Effect boundary.** No new exported Effect wrapper; `npm run lint:effect-facades` must not rise.

## Decisions

- **D-1 One generalized insert, two creators.** The store gains `createMachineLink(caller, { hint, label })` next to `createSecret`. Both call one private `insert(...)` helper, so expiry, ids and waiters stay in one place. *(Auto decision.)*
- **D-2 Dedupe by identical hint.** A second `link_machine` call from the same owner whose trimmed hint equals (case-insensitive) a pending machine-link request's hint answers that request with `created: false` (HTTP 200). A different hint makes a new request, because an agent can need two machines. Every pending request of the owner, of either kind, counts against the shared limit of 20. *(Auto decision; mirrors W-SEC1's same-name rule.)*
- **D-3 Fixed 24-hour expiry.** `MACHINE_LINK_REQUEST_TIMEOUT_MS = 24 * 60 * 60_000`. The ask takes no `timeoutMs`: linking needs the operator at the other machine, which can take hours, and the epic fixes 24 h. *(Auto decision.)*
- **D-4 Widen `result`, do not add a field.** `AgentRequestView.result` and `settle(...)`'s `result` become `{ file?: string; machine?: { environmentId: string; label: string } }`. *(Auto decision.)*
- **D-5 Each wait route answers only its own kind.** Both wait handlers first read `getForCaller(id, caller)`. A request of the other kind answers 404 `unknown-request`, the same as an unknown id, before any wait starts. This also changes the secret wait, so a `secret_wait` on a machine-link id no longer blocks for 50 s and then answers `linked`. *(Auto decision.)*
- **D-6 Resolve body: environment id only.** `POST /api/agent-requests/:id/linked` reads `environmentId` (a string of 1 to 200 characters) from the body and ignores every other field, including `label`. It finds the active link with `(await listLinks()).find((link) => link.environmentId === environmentId && link.revokedAt === null)`. It does not use `getLink`, which also matches ids and labels and returns revoked links. The label it answers and stores is the link record's label. *(Auto decision; corrects the epic's `{ environmentId, label }`.)*
- **D-7 Stopped agent.** The resolve route checks `hasActiveAgentToken(agentId, agentKind)` like the secret route. When the agent no longer holds an active token, it settles the request `expired` and answers 409 `agent-stopped`. The machine stays linked; the dialog tells the operator the agent has stopped. *(Auto decision; parity with W-SEC1 D-7.)*
- **D-8 Dismiss is the existing decline route.** `POST /api/agent-requests/:id/decline` accepts a pending request of either kind. The activity message is `Secret <name> declined for <label>` for a secret and `Machine link declined for <label>` for a machine-link request. No new `/dismiss` route. *(Auto decision.)*
- **D-9 The card stays one component.** `AgentRequestCard` branches on `request.kind`: the secret branch is unchanged; a new `MachineLinkRequestBody` function in the same file renders the machine-link branch. `Decision.agentRequest` becomes a discriminated union on `kind`. *(Auto decision.)*
- **D-10 `machineLink` is blocking.** The agent is parked in `link_machine_wait`, so `'machineLink'` joins `BLOCKING_KINDS`. *(Auto decision.)*
- **D-11 The dialog store carries the request id.** `AnywhereDialogState` gains `agentRequestId: string | null`. `openDialog(dialog, opts?)` sets it from `opts?.agentRequestId ?? null`; `close()` clears it. So opening the dialog from the command palette after a card never resolves an old request. *(Auto decision.)*
- **D-12 The dialog resolves, then closes.** After `linkMachine` succeeds and `agentRequestId` is set, `LinkMachineDialog` posts the resolve with `result.body.environmentId`. On 409 `agent-stopped` it shows `toast.info(\`Linked ${label}, but the agent that asked has stopped.\`)`; on any other failure it shows `toast.error(\`Linked ${label}, but could not tell the agent: ${apiError(result)}\`)`. It always invalidates `['agent-requests']` and closes. A resolve failure never undoes the link. *(Auto decision.)*
- **D-13 Only the card's dialog resolves a request.** A link made through `pan machines link`, Settings → Anywhere → Machines, the SSH or Fly dialogs, or the command palette does not resolve a pending request. The operator then uses **Dismiss**, or the request expires after 24 h. The tool description tells the agent the operator must use the card. *(Auto decision; auto-matching links to requests is out of scope.)*
- **D-14 The tool points at existing machine parameters.** `link_machine_wait`'s description tells the agent to pass the label as `machine` to `start_worker` or `start_conversation`. The epic's `delegate_task` does not exist yet (W-DEL1, PAN-4938, open); W-DEL1 may add it to the description. *(Auto decision.)*
- **D-15 Hint text.** The ask trims the hint and refuses an empty hint, a hint over 200 characters, or one with control characters (`/[\u0000-\u001f\u007f]/`) with 400 `bad-hint`. React renders it as text, so no other escaping is needed. *(Auto decision.)*
- **D-16 The CI subset gains the card test.** `scripts/frontend-test-subset.txt` gains `src/components/__tests__/AgentRequestCard.test.tsx` and the new `src/components/Settings/anywhere/__tests__/LinkMachineDialog.test.tsx`, so CI runs both. *(Auto decision; W-SEC1 shipped the card test without a subset row, Fact 17.)*

- **H-7 MDX placeholders.** In `.mdx` files, write placeholders such as `<label>` or `<machine>` inside backticks or quotes as the existing "Secrets" section does; `npm run lint:docs` flags a bare `<` before a digit, and strict MDX parses a bare `<word>` as JSX.
