## Glossary

- **React Compiler**: a build-time transform that memoizes React components and hooks automatically when they follow the Rules of React. Its output imports `react/compiler-runtime` (React 19) or `react-compiler-runtime` (React 17/18).
- **oxc compiler**: the Rust port of the React Compiler in the npm package `oxc-transform-react`. `@vitejs/plugin-react` runs it when you pass `react({ compiler: ... })`. It needs no Babel.
- **Babel compiler**: `babel-plugin-react-compiler`. This plan never adds it to the Vite or Vitest pipeline. `eslint-plugin-react-hooks@7` bundles its own copy for linting, which is separate and allowed.
- **Diagnostic**: one entry in `TransformResult.errors` returned by `transformSync(file, code, { reactCompiler: { reportDiagnostics: true } })` from `oxc-transform-react`. With the default `panicThreshold: 'none'`, a diagnostic means the compiler left that component or hook uncompiled ("bailed out") and the file still builds.
- **Opt-out directive**: the string directive `"use no memo"` or `"use no forget"` inside a function. The compiler skips that function silently, with **no** diagnostic (verified in the planning probe), so the scan must find it in the source text.
- **Skip count** of a file: number of diagnostics plus number of opt-out directives in that file. A file is **skipped** when its skip count is greater than 0.
- **Skip baseline**: `scripts/react-compiler-skip-baseline.txt`, rows `<count> <path>` (path relative to the repo root). It is shrink-only.
- **Manual memo**: a call site of `useMemo`, `useCallback`, `memo` (or the `React.`-qualified forms) in frontend source.
- **Manual-memo baseline**: `scripts/manual-memo-baseline.txt`, rows `<count> <path>`. It is shrink-only.
- **Compiler lint allowlist**: `eslint-react-compiler-allowlist.json`, a sorted JSON array of file paths where the `react-hooks/*` compiler lint rules are switched off. It is shrink-only.
- **Ratchet**: a check whose baseline may go down freely but goes up only by a hand edit in a commit whose message names an issue (`scripts/lint-ratchet-audit.sh` enforces that).
- **Frontend source**: every `.ts`/`.tsx` file under `src/dashboard/frontend/src/` except test files (see the exclusion rule in WI-5).
- **Burn-down**: later work that fixes skipped files and removes manual memo, which lowers the baselines. This plan files it as sibling issues and does not do it.

## Scope decision

The literal reading of AC 3 ("a test fails when the compiler skips any file") would mean fixing 159 files across about 50 directories in this issue, and AC 4 plus Proposal step 4 add manual-memo removal in about 200 files. That exceeds what one reviewable PR can carry, and finalize rejects plans over 25 files or 6 subsystems. The issue title already says "ratchet" and step 4 says "file by file". So:

- **This issue** upgrades React, turns the compiler on, adds three shrink-only ratchets (compiler skips, manual memo, compiler lint rules) with their baselines, records timings and writes docs.
- **The test for AC 3** fails when any file is skipped that is not in the skip baseline, when a baselined file gets more skips, or when a baseline row is stale. The baseline only shrinks, so new skips are impossible from the day this lands.
- **Burn-down** is filed as six sibling issues (WI-11), one per directory group. Each one fixes the skipped files in its group, removes manual memo there and lowers the three baselines.

**Ordering rule for burn-down (write it into every sibling issue):** remove a file's manual memo only after that file has no row in the skip baseline. In a skipped file the compiler adds no memoization, so removing the hand-written memo there would undo PAN-4560's render fixes.

## Decisions

1. **Versions.** `react` and `react-dom` `^19.3.1` (released 2026-10-14), `@types/react` and `@types/react-dom` `^19.3.0` (2026-09-09). `@vitejs/plugin-react` exactly `6.1.2` (2026-10-05, the latest 6.1.x the issue names; its peer range is `oxc-transform-react ^0.152.0`, which means 0.152.x only). `oxc-transform-react` exactly `0.152.0` (2026-09-29). `eslint-plugin-react-hooks` exactly `7.1.1`. `@visx/*` `^4.0.0`.
2. **Compiler options.** One module, `src/dashboard/frontend/reactCompiler.ts`, exports `reactCompilerOptions = { target: '19', panicThreshold: 'none' }`. Builds never fail on a recoverable diagnostic. The coverage test is the gate.
3. **Tests run compiled code.** `vitest.config.ts` enables the compiler with the same options, so the frontend suite tests what ships. If a test fails only with the compiler on, the component breaks a Rule of React that the compiler did not detect: fix the component. **Fallback (checkpoint):** if the fix is out of scope for this issue, add `"use no memo"` as the first statement of that one component, raise that file's skip-baseline row by 1 (the coverage scan counts directives), and name the component in the PR body. Never turn the compiler off in `vitest.config.ts`.
4. **oxc is the authority for "skipped".** The coverage test uses the same `oxc-transform-react` version and options as the build. The ESLint plugin's Babel compiler disagrees on 84 files (probe 2), so its findings go into their own allowlist and never into the skip baseline.
5. **Manual-memo check is a count ratchet script, not an ESLint rule.** Lint runs with `--no-inline-config`, so ESLint cannot exempt single lines, and a per-file ESLint exemption would let new memo calls into the 200 files that already have one. The script counts call sites per file like `scripts/lint-harness-branches.sh`.
6. **`exhaustive-deps` stays off.** It would flag hundreds of existing effects as warnings, and the compiler validates memo dependencies itself. Turning it on is a non-goal.
7. **Timings.** "Before" is measured at the branch base, on React 18 with no compiler (WI-1, before any dependency change). "After" is measured at the end on React 19 with the compiler (WI-9). Each number is the median of 3 runs. Build time is `vite build` alone, without the `tsc` step of `npm run build`. Dev cold start is the time from spawning `vite` with an empty `node_modules/.vite` cache to the `#root` element having a child in headless Chromium.
8. **Burn-down partition** (WI-11), by path under `src/dashboard/frontend/src/`:
   1. Everything outside `components/`: `App.tsx`, `App/`, `main.tsx`, `pages/`, `hooks/`, `lib/` and any other top-level directory.
   2. `components/chat/`
   3. `components/Settings/`
   4. `components/CommandDeck/`, `components/Stage/`, `components/frame/`, `components/dock/`
   5. `components/explorer/`, `components/GodView/`, `components/conversations/`, `components/workspace/`, `components/project/`
   6. Every other path under `components/`.
