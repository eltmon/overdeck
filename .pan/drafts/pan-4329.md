# PAN-4329: Session Vault — carry uncommitted work with a conversation (encrypted WIP snapshots)

**Issue:** [PAN-4329](https://github.com/eltmon/overdeck/issues/4329) · **Parent:** PAN-2350 · **Depends on:** PAN-2609 Phase A (landed on main as `7150767e255`) · **Dashboard side:** PAN-4307
**Design:** `.pan/drafts/anywhere-accounts.md` §6.7 · **Planning mode:** `pan plan --auto` (decisions below are recorded, not asked)

## 1. Glossary

| Term | Meaning in this document |
| --- | --- |
| **Owner machine** | The machine whose `environmentId` equals `record.owner.environmentId` of a Session Vault record. Only the owner captures snapshots. |
| **Settlement** | One `settle()` call (`src/lib/vault/settle.ts`) that appends new transcript lines to a record and pushes a new `Settlement` entry (`src/lib/vault/format.ts`, `interface Settlement`). |
| **WIP commit** | A commit object built from a *temporary* index: `GIT_INDEX_FILE=<tmp> git add -A`, `git write-tree`, `git commit-tree <tree> -p HEAD`. It is never on any branch. |
| **base** | The full HEAD sha of the owner's checkout at capture time. The WIP commit's parent. |
| **tree** | The tree id of the WIP commit (full working-tree content minus ignored files). |
| **(base, tree) pair** | The identity of a snapshot. Two captures with equal base and equal tree are "unchanged". HEAD alone or tree alone is not enough: committing the WIP moves HEAD with an identical tree. |
| **Bundle** | `git bundle create <file> refs/overdeck/wip/<vaultId> --not --remotes`: the WIP commit plus every local commit the remote-tracking refs do not contain. |
| **Part** | One encrypted slice (≤ 8 MiB of bundle bytes) stored as a vault object. `wip.objects` lists part ids in order. |
| **WIP entry** | The optional `wip` field on a `Settlement`, type `WipSnapshotRef` (`format.ts`): either a captured snapshot `{ base, branch, tree, objects, bytes, at }` or a skip `{ skipped, bytes?, reason?, base?, tree? }`. |
| **Latest WIP entry** | The WIP entry of the most recent settlement that *has* a `wip` field. Later settlements may carry none (unchanged or throttled). |
| **Capture mode** | `'auto'` (throttled; auto-settle and `pan vault sync`), `'force'` (Stop hook, `pan vault save`, session end, dashboard shutdown), `'off'`. |
| **Apply** | Recreate the snapshot on the continuing machine: check out `branch` at `base`, then `git apply` the `base..wip` diff so every change lands unstaged. |
| **Clean checkout** | `readCwdState(cwd).dirty === false` (`src/lib/vault/cwd-state.ts`): no staged, unstaged, untracked or conflicted paths. |

## 2. Problem

"Continue here" / `pan vault resume` moves the conversation but not the code. If the conversation was mid-edit, the new machine continues against a checkout that lacks those edits; the FR-12 drift prompt can only warn. When the origin machine is off (dual boot), the edits cannot be fetched later.

### Empirical probe (run 2026-09-29, git 2.43.0, in the planning scratchpad)

Fixture: bare remote, one pushed commit, one unpushed commit, a force-added file matching `.gitignore` (`forced.log`), a staged new file, an unstaged edit, an untracked file, a deleted file, a binary file, an ignored file.

1. `GIT_INDEX_FILE=<empty tmp> git add -A` **drops** `forced.log` (tracked but ignored) from the tree, which would delete it on the continuing machine. Seeding the temp index with a **copy** of the user's index (`git rev-parse --git-path index`) keeps it. ⇒ Always seed the temp index from a copy.
2. `git bundle create <f> <sha> --not --remotes` fails: `fatal: Refusing to create empty bundle.` ⇒ Capture creates `refs/overdeck/wip/<vaultId>` with `git update-ref`, bundles that ref, then `git update-ref -d` it.
3. The user's index file hash and `git status --porcelain` were identical before and after capture.
4. A raw bundle begins with the plaintext line `# v2 git bundle`, then `-<sha> <commit subject>` prerequisite lines and `<sha> refs/overdeck/wip/<id>`. ⇒ The backend byte-scan test looks for these markers.
5. Apply on a fresh clone: `git fetch origin`; `git fetch --no-tags <bundle> refs/overdeck/wip/x:refs/overdeck/wip/x`; `git switch main`; `git merge --ff-only <base>`; `git diff --binary <base> refs/overdeck/wip/x > p.patch`; `git apply p.patch`; `git update-ref -d refs/overdeck/wip/x`. Result: `diff -r --exclude=.git` of A and B was empty except the ignored file, and `git rev-parse HEAD` matched.

## 4. Decisions (made in this document)

- **D-1 Capture modes.** `SettleOptions.wip?: 'auto' | 'force' | 'off'`, default `'auto'`.
  - Every persisted WIP entry (captured or skipped) carries `base`, `tree` and `at` (the capture time). The throttle clock is the latest entry's **`wip.at`**, never the settlement's `at` (a D-2 in-place amend refreshes `wip.at` without touching the settlement).
  - `'auto'`: if the latest WIP entry's `wip.at` is less than `WIP_MIN_INTERVAL_SEC` (300) seconds before `now()`, return `throttled` without running git. Otherwise compute (base, tree); if it equals the latest WIP entry's (base, tree) (captured **or** skipped), return `unchanged`.
  - `'force'`: always compute (base, tree). Return `unchanged` when the latest entry is a captured snapshot with the same pair, or a skip with reason `clean` or `too-large` and the same pair. A skip with reason `secret` or `error` is retried even when the pair is unchanged (so `pan vault save` after `allow-secret` works).
  - Callers: Stop hook (`save --hook`) and `pan vault save` pass `'force'`. `pan vault sync` keeps the default `'auto'`. PAN-4307 passes `'auto'` for debounced auto-settle and `'force'` for session end and dashboard shutdown.
- **D-2 Noop settlements.** When the transcript did not grow (`verdict: 'noop'`) and mode is `'force'` and this machine owns the record, capture runs and, if it produces a captured or skipped entry, the **latest settlement's `wip` is replaced in place** and the record is CAS-written. No new settlement (and so no new version number) is appended; `versionAtLineCount` and `pan vault show` are unaffected. A CAS conflict drops the WIP update silently (the next trigger retries). `'auto'` never captures on noop.
- **D-3 Ownership.** Capture writes only into the record this machine owns: the normal target, or in the P-6 path the new fork record (settle already retargets to the fork). A non-owner never writes `wip` to someone else's record.
- **D-4 Secret-scan scope (deliberate widening of the issue text).** The issue names `git diff --binary HEAD <wip>`. That misses unpushed local commits, which the bundle also carries. Scan instead the patch of every commit the bundle carries: `git log -p --no-color --format=%H <wip> --not --remotes` (non-`--binary`, so binary files appear as `Binary files … differ` and are not scanned). Only added lines (`+` but not `+++`) are scanned. Hits name the file (from the `+++ b/<path>` header) and the pattern, never the value. A hit writes no object and records `wip: { skipped: 'secret', reason: '<n> secret hit(s)', base, tree }`. The transcript settlement still lands.
- **D-5 Code allow flow.** Extend the existing verb: `pan vault allow-secret <vaultId> --file <path>` (the `<line>` positional becomes optional; exactly one of `<line>` or `--file` is required). It rebuilds the WIP commit in the record's cwd, rescans, and stores the line hash of every blocked added line in that file under the same `vaultId` key of `allowed-secrets.json` (`allowSecret(vaultId, hash)`). Hash = `lineHash(<added line without the leading '+'>)`.
- **D-6 Size cap.** `VaultConfig.wipMaxBytes`, default `50 * 1024 * 1024`, measured on the bundle file (the git pack inside is already compressed). Over the cap: no object written, `wip: { skipped: 'too-large', bytes, base, tree }`.
- **D-7 Storage.** Split bundle bytes into parts of `WIP_PART_BYTES = 8 * 1024 * 1024` (keeps git-backend object files far under GitHub's 50 MB warning; `maxChunkBytes` is not reused). Each part: id = `hex(HMAC-SHA256(K_id, "overdeck-wip-part-v1\0" || bytes))[:40]` (domain-separated so a part id can never equal a transcript chunk id); stored = `seal(K_enc, aad = id, zstd(bytes))`. `wip.bytes` = bundle byte length.
- **D-8 Retention.** When a new captured snapshot is attached, every captured WIP entry older than the 5 most recent captured entries in `record.settlements` is **deleted** (the `wip` field removed). Skipped entries are kept (no objects). Unreferenced part objects stay in the backend; collecting them is out of scope. Forks (`forkRecordAtVersion`, P-6 fork) copy settlements and therefore inherit snapshot references; that is intended.
- **D-9 Skip vocabulary.**
  - `clean` (new value): the WIP tree equals `HEAD^{tree}` **and** `git rev-list --count <base> --not --remotes` is `0` (nothing uncommitted, nothing unpushed). No bundle is built and no object is written. Recording it matters: without it, a later resume would apply an older dirty snapshot after the owner committed and pushed. A repo with no remote-tracking refs is never `clean` (everything is unpushed), so it is bundled, per the design.
  - `too-large`, `secret` as in D-4/D-6. `error`: any other git failure after the WIP commit was built; `reason` = the first stderr line truncated to 200 chars.
  - `no-git` (cwd not inside a git work tree, git unavailable, unborn HEAD) is returned as capture status `no-git` and **not persisted**: there is nothing to carry, and settlements of non-git sessions stay byte-for-byte what Phase A wrote.
  - The skipped variant becomes `{ skipped: 'clean' | 'too-large' | 'secret' | 'no-git' | 'error'; base?: string; tree?: string; at?: string; bytes?: number; reason?: string }` (additive; readers ignore unknown fields; still no format bump because Phase A never wrote `wip`). Capture always writes `base`, `tree` and `at` on a persisted skip.
- **D-10 Git invocation.** Every git call goes through one helper in `wip-capture.ts` (exported for `wip-apply.ts`) using promisified `execFile` (never `execSync`, never `git stash`), with env `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, and fixed `GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_NAME/EMAIL` = `Overdeck Session Vault` / `vault@overdeck.invalid` (a machine with no `user.name` must not fail `commit-tree`). Pipes are replaced by temp files under `mkdtemp(join(tmpdir(), 'overdeck-wip-'))`, removed in `finally`. The capture-side temporary ref is `refs/overdeck/wip/<vaultId>-<process.pid>` so two concurrent captures of the same repo (Stop hook and a PAN-4307 auto-settle) never delete each other's ref; apply reads the head name from the bundle (D-13), so the name is not a contract.
- **D-11 Which snapshot resume uses.** The latest WIP entry (D-1 vocabulary). A captured entry is applied. A `clean` skip prints nothing and resume runs the FR-12 drift prompt (the pushed HEAD is compared as today). Any other skip prints `No code snapshot: skipped (<skipped>[, <reason>])` and resume runs the FR-12 drift prompt. No entry: FR-12 drift prompt as today.
- **D-12 Apply checkout rules** (HEAD ends equal to `base` in every case; no branch ever moves backward or loses commits):
  1. `branch === null` → `git switch --detach <base>`.
  2. branch missing locally → `git switch -c <branch> <base>`.
  3. branch exists and is checked out in *another* worktree (`git worktree list --porcelain`) → `git switch --detach <base>`, print why.
  4. branch tip == base → `git switch <branch>`.
  5. branch tip is an ancestor of base (`git merge-base --is-ancestor`) → `git switch <branch>` then `git merge --ff-only <base>`.
  6. otherwise (diverged) → `git switch --detach <base>`, print that local branch `<branch>` has commits the snapshot lacks.
- **D-13 Bundle ref name on apply.** Apply reads the head from `git bundle list-heads <file>` (exactly one expected) and fetches `<head>:refs/overdeck/wip/<vaultId>`; it never assumes the capture-time vaultId (forks carry snapshots captured under the parent id). It checks that the fetched commit's tree equals `wip.tree` and its parent equals `wip.base`, else fails with `snapshot does not match its record`.
- **D-14 Dirty target (standalone CLI).** Resume never writes into a dirty checkout. On a TTY it asks `The checkout at <cwd> has uncommitted changes. Create a fresh worktree at <default> instead? [y/N]` with default dir `<cwd>-vault-<vaultId first 8>`; non-TTY (or "no") exits 1 with `Refusing to apply the code snapshot: <cwd> has uncommitted changes. Commit or move them, or re-run with --worktree <dir>.` `--worktree <dir>` skips the prompt. The worktree path: in the dirty repo, fetch origin and the bundle (refs and objects only), `git worktree add --detach <dir> <base>`, then apply D-12 + diff inside `<dir>`. The dirty checkout's index, worktree and stash are not touched. Overdeck-mode "fresh worktree" through workspace creation is PAN-4307.
- **D-15 Resume order with a snapshot.** Resolve cwd → (no `--no-code`, captured entry present) clean check / D-14 → download + decrypt + write the bundle file → **fetch origin first** (failure is non-fatal) → `bundle verify` (it checks that the bundle's prerequisite commits exist locally, so a clone that is behind origin must fetch before verifying; a failure reports `This code snapshot needs commits your clone does not have and could not fetch from origin: <first stderr line>`) → `bundle list-heads` → fetch bundle → D-12 checkout → apply diff → delete temp ref → adopt/materialize (CAS) → launch. The FR-12 drift prompt is skipped when a snapshot was applied. If adopt then returns `alreadyContinuedOn`, print `Code snapshot applied in <dir>, but the conversation was already continued on <label>; it was not adopted.` and exit 1 (the applied changes are left for the user).
- **D-16 `--no-code`.** Skips every step of D-14/D-15 code handling and keeps today's behavior (FR-12 drift prompt included).
- **D-17 Stop hook stays the standalone session-end trigger.** Claude Code fires `Stop` after every turn, including the last, so no `SessionEnd` hook is added. Managed session end and dashboard shutdown are PAN-4307 call sites of the D-1 API.

## 5. Requirements

- **FR-1** Capture builds the WIP commit from a temporary index seeded with a copy of the user's index, bundles it `--not --remotes` via a temporary `refs/overdeck/wip/<vaultId>-<pid>` ref, and deletes that ref; a clean, fully pushed checkout records `skipped: 'clean'` without bundling.
- **FR-2** Capture never modifies the user's index file, worktree, stash list or refs (other than creating and deleting its own temporary ref).
- **FR-3** Capture scans every commit the bundle carries (D-4); a hit writes no object, records `skipped: 'secret'`, and reports file + pattern only.
- **FR-4** A bundle larger than `wipMaxBytes` records `skipped: 'too-large'` with `bytes` and writes no object.
- **FR-5** Bundle bytes are stored as zstd + AES-256-GCM parts through `VaultStore.putObjects` (D-7); no plaintext file content, bundle header or WIP sha reaches the backend.
- **FR-6** Settlement attaches the capture result per D-1, D-2, D-3 and keeps the 5 most recent captured entries (D-8).
- **FR-7** `pan vault save` (both modes) captures in `'force'` mode and the CLI prints the WIP outcome; a secret block names file and pattern and the allow command.
- **FR-8** `pan vault allow-secret <vaultId> --file <path>` allows the blocked code lines of that file (D-5).
- **FR-9** Apply refuses a dirty target without changing it, fetches origin, unbundles into `refs/overdeck/wip/<vaultId>`, checks out per D-12, applies the diff unstaged (untracked, deleted and binary included), and deletes the temp ref.
- **FR-10** `pan vault resume` applies the latest captured snapshot per D-11, D-14, D-15; `--no-code` skips it; `--worktree <dir>` applies into a fresh worktree.
- **FR-11** Docs describe what is captured, what is excluded, the size cap, that snapshots never go to the git host, and `--no-code`.
- **NFR-1** All new modules live in `src/lib/vault/**` and import only Node built-ins, sibling vault modules and `../secret-redaction.js` (import-graph test stays green).
- **NFR-2** Async `execFile` only; no `execSync`, no `git stash`, no shell pipes.
- **NFR-3** Snapshots are never pushed to the project's origin.
- **NFR-4** Tests use real git on temp fixture repos with a bare remote and a `dir:` vault backend; time is injected through `now`, never real timers (repo rule: fake/injected time for delay logic).

## 6. Integration contract for PAN-4307 (dashboard)

- Auto-settle: `settle({ …, wip: 'auto' })`. Session end and dashboard shutdown: `settle({ …, wip: 'force' })`. `SettleResult` for `append` and `noop` carries `wip?: WipCaptureResult`.
- "Continue here": `findLatestWip(record)` → if captured, `applyWipSnapshot({ cwd, vaultId, wip, store, keys })` in a clean checkout; on `{ status: 'dirty' }` create a workspace through the normal workspace path, then call `applyWipSnapshot` there. `applyWipSnapshotInWorktree` is the standalone-CLI variant and is not required by the dashboard.

## 9. Repo rules restated for the executor

- No `execSync` anywhere reachable from the dashboard; this code will be (PAN-4307). Use promisified `execFile`.
- Agents never run `git stash`; the code under test must not either, and tests assert `git stash list` is empty.
- Time-dependent logic (the 5-minute throttle) is tested with an injected `now`, never real `setTimeout` delays.
- Quality gates: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.
- `npm run typecheck` skips `*.test.ts`; make sure test files compile by running them.
- CLI option changes need the regenerated `packages/contracts/src/composer-commands.generated.ts` (build → `node scripts/generate-slash-commands.mjs` → commit).
- New source-reading tests (tests that `readFileSync` a `.ts` source to grep it) fail lint; assert behavior instead. No `skipIf`/`.only`.
- File-size guard: new files stay under 1000 lines; none of the touched files is near the cap.
