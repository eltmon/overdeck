## Glossary

- **Tailscale CLI:** the `tailscale` command. It talks to the **daemon** `tailscaled` over a local socket.
- **System mode:** `tailscaled` runs as root, installed by the platform installer (Linux `install.sh`, the macOS app, Windows MSI). The CLI uses the default socket.
- **App mode:** macOS only. The CLI is the binary inside the Tailscale app: `/Applications/Tailscale.app/Contents/MacOS/Tailscale`.
- **Userspace mode:** Linux only, no administrator password. Overdeck downloads the static Tailscale tarball into `${OVERDECK_HOME}/tailscale/bin/` and runs `tailscaled --tun=userspace-networking` as the user under a systemd user unit, `overdeck-tailscaled.service`. Every CLI call then passes `--socket=${OVERDECK_HOME}/tailscale/tailscaled.sock`. There is no TUN device, so outbound connections to tailnet addresses go through tailscaled's HTTP proxy on `127.0.0.1:1055`.
- **Tailscale operator:** on Linux system mode, the one non-root user allowed to change Tailscale preferences (`login`, `up`, `serve`). Set once with `sudo tailscale set --operator=<user>`.
- **Backend state:** `BackendState` in `tailscale status --json`: `NoState`, `NeedsLogin`, `NeedsMachineAuth`, `Stopped`, `Starting`, `Running`.
- **MagicDNS name:** this machine's tailnet DNS name, `Self.DNSName` in `status --json` with the trailing dot removed, e.g. `desk.tailnet-1234.ts.net`.
- **Tailscale Serve HTTPS:** `tailscale serve --bg --https=443 http://127.0.0.1:<api_port>`. Tailscale terminates HTTPS with a Let's Encrypt certificate for the MagicDNS name and proxies to the dashboard. `--bg` persists the setting in tailscaled, so it survives restarts with no Overdeck lifecycle hook.
- **Serve URL:** `https://<MagicDNS name>` — the address another tailnet device opens.
- **Descriptor:** the unauthenticated `GET /api/environment` answer (`buildEnvironmentDescriptor()`, `src/dashboard/server/routes/environment.ts`), validated by `EnvironmentDescriptor` in `packages/contracts/src/environment.ts:27`.
- **Peer:** another device in `status --json` `Peer` map. An **Overdeck peer** is a peer whose descriptor answers.
- **Pane:** an ad-hoc terminal session created by the existing `POST /api/terminals` route with a single-line `command` (`src/dashboard/server/routes/terminals.ts`), rendered in the browser by `<XTerminal sessionName=…>`. The operator types any `sudo` password there; Overdeck never sees it.
- **Root session:** the operator's browser on this machine (`resolveDashboardCredential(...).kind === 'root-session'`). **Internal token:** the credential the `pan` CLI and pipeline agents use (`kind === 'internal-token'`).
- **`require_token_mint`:** `dashboard.require_token_mint` in `~/.overdeck/config.yaml` (`src/lib/remote-access/config.ts`). When false, any loopback peer may mint the root session — and Tailscale Serve makes every tailnet visitor a loopback peer.

## Requirements

### Functional

- **FR-1 Read Tailscale state.** One lib call, `readTailscaleState()`, reports: whether a CLI exists and in which mode (`system`, `app`, `userspace`), its version, backend state, sign-in URL when one is pending, this machine's MagicDNS name and tailnet IPv4 addresses, the signed-in login name, whether MagicDNS and HTTPS certificates are on for the tailnet, whether this user is the operator (Linux system mode only), whether Serve HTTPS proxies to this dashboard, the online peers, and the **next step** (`install`, `start-daemon`, `operator`, `login`, `enable-https`, `serve`, `protect`, `ready`). A missing CLI is a normal state, never an error.
- **FR-2 Install plan.** For each platform the lib returns how to install: a pane command (Linux system, macOS with Homebrew), a userspace install (Linux with no `sudo` on PATH, or when the operator chooses it), or a manual instruction with a URL (macOS without Homebrew, WSL2, native Windows).
- **FR-3 Userspace install.** On Linux without an administrator password, Overdeck downloads the static tarball, installs `tailscale` and `tailscaled` under `${OVERDECK_HOME}/tailscale/bin/`, and starts `overdeck-tailscaled.service` as a systemd user unit. When systemd user units are unavailable or the architecture has no tarball, it returns the manual fallback (D-17 fallback) instead.
- **FR-4 Operator.** On Linux system mode, when this user is not the operator, Overdeck offers `sudo tailscale set --operator=<user>` in a pane.
- **FR-5 Sign in.** Overdeck starts `tailscale login` (or `tailscale up` when the backend is `Stopped`), returns the sign-in URL Tailscale prints, and the UI shows **Open sign-in**. Completion is detected by polling the backend state until `Running`.
- **FR-6 Serve HTTPS, protected.** **Turn on HTTPS access** does, in this order: turn on `dashboard.require_token_mint`, trust the Serve URL as an origin, run `tailscale serve --bg --https=443 http://127.0.0.1:<api_port>`, then check that `https://<MagicDNS name>/api/environment` answers with this machine's environment id. It refuses to replace a Serve handler on 443 that proxies elsewhere. When MagicDNS or HTTPS certificates are off, it links `https://login.tailscale.com/admin/dns` instead of running.
- **FR-7 Peer discovery.** For every online peer, Overdeck probes the peer's descriptor at `https://<peer MagicDNS name>/api/environment` and at `http://<peer tailnet IPv4>:<this api_port>/api/environment`, in parallel, 2.5 s each. Peers whose descriptor answers are listed with label, server version and URL. No **Link** button is shown until #4645 ships machine links.
- **FR-8 Phone.** When Tailscale is ready, the setup dialog shows a QR code for `https://tailscale.com/download` and the text "Sign in as <login name>", then **Pair a device**, which opens the existing pair dialog.
- **FR-9 Status everywhere.** `GET /api/anywhere/status` gains a `tailscale` summary, the status card shows a **Tailscale** row, and a new problem `tailscale-serve-unprotected` appears when Serve proxies to this dashboard while `require_token_mint` is off, with a **Protect the dashboard** button.
- **FR-10 CLI.** `pan tailscale status [--json]` prints FR-1 plus FR-7. `pan tailscale setup [--userspace]` walks the same steps in the terminal: it runs pane commands with inherited stdio (the operator types `sudo` passwords in their own terminal), prints the sign-in URL, waits for `Running`, then asks the running dashboard to turn on Serve (FR-6) and prints the Overdeck peers.
- **FR-11 Routes.** `GET /api/tailscale/status`, `GET /api/tailscale/peers`, `POST /api/tailscale/userspace`, `POST /api/tailscale/login`, `POST /api/tailscale/serve`.

### Non-functional

- **NFR-1 No password handling.** Overdeck never asks for, stores, logs or passes an administrator password. Elevation happens only inside a pane or the operator's own terminal.
- **NFR-2 Async only.** Every Tailscale call reachable from the dashboard server uses `execFile`/`spawn` from `node:child_process` (promisified) or `fetch`. No `execSync`, no `*Sync` child processes, no new tmux `*Sync` calls.
- **NFR-3 Bounded latency.** CLI reads time out at 1.5 s (`status`, `serve status`, `debug prefs`, `version`), write commands at 10 s, peer probes at 2.5 s, the Serve self-check at 15 s (the first HTTPS request provisions a certificate). Timeouts use `AbortController` + `setTimeout`, never `execFile`'s `timeout` option or `AbortSignal.timeout` (both ignore Vitest fake timers).
- **NFR-4 No root widening.** Only the root session or the internal token may call the POST routes; a paired device or a scoped token gets 403.
- **NFR-5 Never clobber.** Overdeck never replaces another program's Serve handler and never turns Serve off.
- **NFR-6 Derived state.** Nothing about Tailscale is stored by Overdeck except the files it installs in userspace mode. The mode is derived: `userspace` when `${OVERDECK_HOME}/tailscale/bin/tailscale` exists.

## Decisions

- **D-1 Location and style.** New code lives in `src/lib/tailscale/` as plain async functions modeled on `src/lib/sageox/probe.ts`. It is not a port of t3code's Effect module: the repo rule "one variant per operation in src/lib" (docs/EFFECT-BRIDGING.md) forbids an Effect wrapper over Promise code, and the issue's old body is history.
- **D-2 Serve turns on `require_token_mint` first.** W-SEC4 (automatic token mint, #4645) has not shipped. Turning on Serve without it lets every tailnet visitor mint the root session. So the Serve operation writes `require_token_mint: true` before it runs `tailscale serve`, and leaves it on if Serve fails (the safe direction). Consequence the UI states before the button: a browser that already has a session keeps working; a new browser — including one at the Serve URL — must pair. W-SEC4 later generalizes this; it does not conflict.
- **D-3 The CLI calls the dashboard for Serve.** The token-mint and trusted-origin caches live in the server process, so `pan tailscale setup` turns Serve on through `POST /api/tailscale/serve` with the internal token (via `callDashboard` from `src/cli/commands/pair.ts`). When the dashboard is not running it stops with "Overdeck dashboard is not running; start it with `pan up`." It never writes those files itself.
- **D-4 Route auth mirrors pairing.** POST routes accept `root-session` and `internal-token` only (`pairing.ts:74-77` precedent); `device` and `token` get 403 `{ error: 'Only this machine can change Tailscale settings.' }`. GET routes use `rejectUnauthorizedDashboardRequest` (default `admin` scope).
- **D-5 Panes reuse `POST /api/terminals`.** The status response carries the exact pane commands (`install.command`, `operatorCommand`). The dialog creates the pane through the existing route and renders `<XTerminal>`; it deletes the pane on close. No new tmux code.
- **D-6 Operator detection is three-state.** `operator: 'self' | 'other' | 'unknown'`: `tailscale debug prefs` (JSON) field `OperatorUser` equal to `os.userInfo().username` ⇒ `self`; a different or empty value ⇒ `other`; `debug prefs` failing or unparseable ⇒ `unknown`. Only `other` routes to the operator step. With `unknown`, setup proceeds to `login`/`serve`, and stderr matching `/access denied|permission denied|prefs write access denied/i` from that write maps to `operator` (login route 409 `{ nextStep: 'operator' }`; the dialog and the CLI then show/run the operator command and retry the write once). Root (uid 0) and non-Linux platforms are always `self`.
- **D-7 Binary resolution order.** (1) `${OVERDECK_HOME}/tailscale/bin/tailscale` → `userspace` with `--socket=${OVERDECK_HOME}/tailscale/tailscaled.sock`; (2) `tailscale` on `PATH` → `system`; (3) on macOS `/Applications/Tailscale.app/Contents/MacOS/Tailscale` → `app`; else not installed. Overdeck-installed binaries win because Overdeck manages that daemon.
- **D-8 Next-step rules,** evaluated in order (first match wins):

  | # | Condition | nextStep |
  | --- | --- | --- |
  | 1 | no binary | `install` |
  | 2 | `status --json` fails with "failed to connect"/"is Tailscale running?", or no daemon socket | `start-daemon` |
  | 3 | platform `linux`, mode `system`, uid ≠ 0, `operator === 'other'` (never when `unknown`, D-6) | `operator` |
  | 4 | backend `NeedsLogin`, `NeedsMachineAuth`, `NoState` or `Stopped` | `login` |
  | 5 | backend `Running` and (`CurrentTailnet.MagicDNSEnabled` false or `CertDomains` empty) | `enable-https` |
  | 6 | backend `Running` and Serve does not proxy `/` on `<MagicDNS>:443` to `http://127.0.0.1:<port>` or `http://localhost:<port>` | `serve` |
  | 7 | Serve proxies this dashboard and `readRemoteAccessConfig().requireTokenMint` is false | `protect` |
  | 8 | otherwise | `ready` |

  `start-daemon` remedy text: Linux system → pane `sudo systemctl enable --now tailscaled`; userspace → `systemctl --user restart overdeck-tailscaled.service` (run by `POST /api/tailscale/userspace`); macOS → "Open the Tailscale app".
- **D-9 Install commands** (`installPlan()`):

  | Platform | Condition | Plan |
  | --- | --- | --- |
  | linux | uid 0 | pane: `curl -fsSL https://tailscale.com/install.sh \| sh` |
  | linux | `sudo` on PATH and not `userspace` requested | pane: `curl -fsSL https://tailscale.com/install.sh \| sh && sudo tailscale set --operator=<user>` |
  | linux | no `sudo` on PATH, or `userspace` requested | userspace |
  | darwin | `brew` on PATH | pane: `brew install --cask tailscale-app && open -a Tailscale` |
  | darwin | no `brew` | manual: url `https://pkgs.tailscale.com/stable/#macos`, message "Download and open the Tailscale package, open Tailscale, allow its VPN configuration, then press Check again." |
  | wsl | always | manual: url `https://tailscale.com/download/windows`, message "Install Tailscale on Windows (not inside WSL). Then run `tailscale serve --bg --https=443 http://127.0.0.1:<port>` in Windows PowerShell." |
  | win32 | always | manual: command `winget install tailscale.tailscale`, url `https://tailscale.com/download/windows` |

  `<user>` is `os.userInfo().username`, accepted only if it matches `/^[a-z_][a-z0-9_.-]*\$?$/i`; otherwise the plan is manual. `sudo`/`brew` presence is a PATH scan with `fs.promises.access(X_OK)`, injectable for tests.
- **D-10 Userspace layout.** Directory `${OVERDECK_HOME}/tailscale/` (mode 0700): `bin/tailscale`, `bin/tailscaled` (0755), `state/`, `tailscaled.sock`. Unit `overdeck-tailscaled.service`:

  ```ini
  [Unit]
  Description=Overdeck userspace Tailscale
  After=network-online.target

  [Service]
  ExecStart=<home>/tailscale/bin/tailscaled --tun=userspace-networking --statedir=<home>/tailscale/state --socket=<home>/tailscale/tailscaled.sock --outbound-http-proxy-listen=127.0.0.1:1055
  Restart=on-failure
  RestartSec=5

  [Install]
  WantedBy=default.target
  ```

  Download: `GET https://pkgs.tailscale.com/stable/?mode=json`, pick `Tarballs[<arch>]` (Node arch `x64`→`amd64`, `arm64`→`arm64`, `arm`→`arm`, `ia32`→`386`), fetch `https://pkgs.tailscale.com/stable/<file>`, verify against `https://pkgs.tailscale.com/stable/<file>.sha256` (implementation checkpoint C-2), extract with async `execFile('tar', ['-xzf', file, '-C', tmpDir])`, copy the two binaries. The unit is installed with `installUserUnit` + `enableUserUnitNow`, then the lib waits up to 10 s (poll 250 ms) for the socket.
- **D-11 Login capture.** `startTailscaleLogin()` spawns the CLI (`login`, or `up` when backend is `Stopped`) with piped stdout/stderr, resolves with the first match of `/https:\/\/\S+/` within 15 s, and leaves the child running so Tailscale can finish the sign-in; the child is killed after 10 minutes if it has not exited. At most one login child per process (a second call returns the pending URL). `up` that exits 0 with no URL resolves `{ authUrl: null }`.
- **D-12 Serve URL is the origin.** The trusted origin added is exactly `https://<MagicDNS name>` (port 443, no path). The Serve target is `http://127.0.0.1:<api_port>`, bypassing Traefik.
- **D-13 Discovery transport.** System and app mode: global `fetch`. Userspace mode: probe only the `http://<ip>:<port>` candidate, sent through `127.0.0.1:1055` as an absolute-form HTTP request with `node:http`; the HTTPS candidate is skipped. Responses are decoded with `Schema.decodeUnknownSync(EnvironmentDescriptor)`; a peer whose `environmentId` equals this machine's is dropped. At most 16 probes run at once.
- **D-14 No lifecycle hooks.** `--bg` persists Serve in tailscaled; `pan up`/`pan down` do not touch Tailscale. Overdeck never runs `tailscale serve … off`.
- **D-15 QrImage extraction.** The setup dialog would be the third copy of `QrImage`, so the anywhere copy moves to `components/Settings/anywhere/QrImage.tsx` with an `alt` prop; `PairDeviceDialog` imports it. `OpenOnScreenTab.tsx` is left alone (surgical).
- **D-16 Size.** This issue is already the decomposed W-TS1 leaf of the #2350 epic. It exceeds the projected-surface lint (≈45 files, 8 two-segment "subsystems" because every top-level doc file counts as its own subsystem), so the plan sets `plan.metadata.sizeJustification`. Splitting CLI from UI would be the horizontal layering the swarm contract rejects; the items below are vertical and individually reviewable.

### Implementation checkpoints

- **C-1 Userspace inbound and Serve (D-17 of the parent PRD).** On a Linux host with no `sudo` use, install in userspace mode, sign in, and from another tailnet device run `curl -s http://<tailnet-ip>:<api_port>/api/environment` and `curl -s https://<MagicDNS>/api/environment`. Both must print this machine's descriptor. Record the commands and outputs in the PR body. **Fallback:** if the plain-IP probe fails, `installPlan()` stops offering userspace (Linux without `sudo` returns the manual plan: the installer command) and `configuration/tailscale.mdx` says userspace mode is unavailable. If only Serve fails in userspace mode, the Serve step in userspace mode returns `{ ok: false, reason: 'userspace-serve-unsupported' }` with that message. A sign-in needs the operator's tailnet. If the work agent has no tailnet sign-in, auth key or second tailnet device, it cannot run the check, and that case takes the same fallback: `installPlan()` stops offering userspace, `configuration/tailscale.mdx` says userspace mode is off until a live check passes, and the PR body says why. The agent also sends `pan tell flywheel-orchestrator "PAN-1254: C-1 live check needs a tailnet sign-in; userspace mode shipped off"`. It never fakes evidence. Nothing unsafe ships, and the operator can re-enable userspace after a real check.
- **C-2 Tarball checksum.** If `<file>.sha256` is not published, verify nothing extra (HTTPS only) and say so in a code comment and in the PR body.
- **C-3 `tailscale set --operator`.** Confirm on the installed version that `sudo tailscale set --operator=<user>` succeeds before sign-in. **Fallback:** the pane command becomes `… && sudo tailscale up --operator=<user>`, which also signs in and prints the URL in the pane; the dialog then skips the login step when the backend reaches `Running`.
- **C-4 Serve syntax.** Run `tailscale serve --help` on the installed version. The modern form (≥ 1.52) is `tailscale serve --bg --https=443 http://127.0.0.1:<port>`; `serve status --json` returns `{ "TCP": { "443": { "HTTPS": true } }, "Web": { "<name>:443": { "Handlers": { "/": { "Proxy": "http://127.0.0.1:3011" } } } } }`. A version below 1.52 makes the Serve step return "Update Tailscale to 1.52 or later".

- Quality gates: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never run the full `npm test` locally.
- Commits carry an `Item: <item-id>` trailer; conventional subjects ≤100 chars.

## Critique response

### a later Settings save reopens the Serve login hole

Accepted. Accepted. D-8 gains row 7, next step `protect` (Serve proxies this dashboard while `require_token_mint` is off), evaluated before `ready`. The dialog renders a `protect` panel whose **Protect the dashboard** button calls the same idempotent `POST /api/tailscale/serve`, and `pan tailscale setup` handles `protect` exactly like `serve`. The status card's fix action opens the dialog on that panel.

### a failed self-check leaves the new origin stale

Accepted. W-9 now calls `invalidateTrustedOriginsCache()` after every `POST /api/tailscale/serve`, whatever the result, and the route tests cover the `self-check-failed` path.

### the foreign-handler check omits TCP port 443

Accepted. `parseServeStatus` treats any `TCP["443"]` entry other than `{ HTTPS: true }` (TCP forwarding, TLS termination) and any `Web["<name>:443"]` mount other than `/` → this dashboard as a foreign handler. Fixtures for TCP forwarding and an extra web mount are part of W-1's tests.

### unreadable prefs can trap setup at operator

Accepted. D-6 makes operator knowledge three-state (`self`, `other`, `unknown`); only `other` routes to the operator step. With `unknown`, setup tries the write and maps an access-denied result to the operator step, then retries once. W-1 and W-4 tests cover a failed `debug prefs` with a working operator and with access denied.

- Userspace fallback leaves the failed mode active
