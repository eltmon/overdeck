## Glossary

- **Machine:** one running Overdeck server with its own `OVERDECK_HOME`. Its identity is the **environment id** (`environment-id.json`, `src/lib/environment-identity.ts`).
- **Machine key:** a long-term X25519 key pair stored in `${OVERDECK_HOME}/machine-key.json` (0600), created once, never rewritten. Its public half goes in the descriptor.
- **Fingerprint:** the first 10 bytes of SHA-256 over the raw 32-byte public key, as lowercase hex in five dash-separated groups of four: `1a2b-3c4d-5e6f-7a8b-9c0d`.
- **Descriptor:** the unauthenticated `GET /api/environment` body (`buildEnvironmentDescriptor()`, `src/dashboard/server/routes/environment.ts:26`).
- **Noise:** the Noise Protocol Framework. **IK** and **XXpsk0** are handshake patterns. IK needs the responder's static key in advance (used once keys are pinned). XXpsk0 exchanges both static keys and mixes a pre-shared key (PSK) into the first message (used for pairing, PSK derived from the pairing code).
- **Secure channel:** one Noise session over one transport connection. After the handshake, bytes flow inside `@hyperswarm/secret-stream` (XChaCha20-Poly1305 secretstream framing keyed from the Noise split).
- **ChannelSocket:** the Node `stream.Duplex` subclass that wraps one secure channel and carries a `channel` marker (mode, remote key). The server hands it to the dashboard HTTP server with `nodeServer.emit('connection', socket)`; the client gives it to `http.request` / `ws` through `createConnection`.
- **Transport:** how channel bytes reach the other machine. `tcp` = raw TCP to the dashboard port, recognised by a 7-byte preamble whose first byte is `0x00`. `wss` = a WebSocket at `/ws/link` inside HTTPS (Tailscale Serve).
- **Route:** one way to reach a linked machine: `{ kind, url, source }`. Kinds rank `lan < tailnet < ssh < public < direct < relay` (D-10). This issue creates `lan`, `tailnet` and `public` routes; `ssh`, `direct` and `relay` arrive in #4404 and #2356.
- **Machine link** (or **link**): a record in `${OVERDECK_HOME}/machine-links.json` that lets this machine's server reach another machine: peer environment id, label, pinned machine key, the `odk_` token the peer issued us, access level, routes. The machine that holds the link is the **linking machine**; the other is the **linked machine**.
- **Machine token:** an `access-tokens.json` record with `kind: 'machine'`, minted by the linked machine for one linking machine, bound to that machine's key. It authenticates only inside a channel whose remote key equals the bound key.
- **Inbound access:** the machine tokens this machine has issued to others (shown on the Machines list next to outbound links).
- **Operator-level / agent-fenced:** the two access levels of a link (FR-4).
- **Actor stamp:** headers the linking server adds to every request it forwards: `x-overdeck-link-actor: operator | agent:<id>` and optional `x-overdeck-link-ceiling: <scope,scope>`.
- **Link supervisor:** the dashboard service that keeps one secure channel open per link on the best answering route, and owns link state.
- **Heartbeat:** the server-sent event stream `GET /api/machines/heartbeat` the linked machine sends every 15 s over the supervisor's channel.
- **Stall:** a period of at least 1 s where the dashboard event loop did not run timers.
- **Primary dashboard:** a dashboard where `isPeerDashboardProcess()` is false. Peer dashboards (workspace containers, `OVERDECK_DISABLE_DEACON=1`) never run the link supervisor or accept channels.

## Requirements

### Functional (from pan-2350 FR-1 to FR-4, scoped to this issue)

- **FR-1 Link machines.** `pan machines link <pairing-url>` and Settings → Anywhere → Machines → **Link a machine** take a `pan pair` link from the other machine. Pairing runs inside a `Noise_XXpsk0` channel keyed by the pairing code. Each side pins the other's machine key and holds a `machine` token for the other. **Link both ways** (default on) creates both directions in one action. Either side can unlink; an unlink closes live channels within 5 s.
- **FR-2 Routes.** Each link keeps an ordered route list from three sources: the pairing URL, **Add route**, and endpoints the linked machine advertises (`lan`, `tailnet`, Tailscale Serve HTTPS). A channel opens only on a route whose IK handshake proves the pinned key; no token is sent before that.
- **FR-3 Link supervisor.** One channel per link on the best answering route; parallel probes with a 2.5 s timeout; reconnect back-off 1 s doubling, jittered, capped (D-4645-6); better routes re-checked every 60 s; states `online`, `connecting`, `offline`, `unsupported`, `revoked`; no user-facing call waits more than 2.5 s on an unreachable machine.
- **FR-4 Access levels, actor stamp, limits.** A link is operator-level (default) or agent-fenced. The linking server stamps forwarded requests with the actor; the linked server trusts the stamp only inside a channel, lets it only narrow scopes, and treats a missing stamp as `agent`. No link can pair devices, mint tokens, change settings, or use the linked machine's links. (Fencing of agent mutations to link-started conversations is W-WORK2, #4651.)
- **FR-5 Owner column.** `conversations.environment_id` names the owner machine of every row; `conversations.released_to` exists for #4650's Pull here.
- **FR-6 Token-mint hardening.** `require_token_mint` is on whenever any trusted remote address, active paired device or machine link exists, whatever the YAML says; a remote browser on plain HTTP gets a "Use HTTPS" page.
- **FR-7 Machine token scopes.** `machine` tokens carry `read:events, read:state, read:conversations, read:costs, read:settings, tell, operate`, plus `forward` on operator-level links; never `admin`.
- **FR-8 Scoped `/ws/rpc`.** A machine (or scoped) credential may open `/ws/rpc` and call exactly the methods its scopes allow (`subscribeConversationMessages` needs `read:conversations`, `subscribeDomainEvents` needs `read:events`); a revoke closes the socket with code 4401.
- **FR-9 Freeze vs network.** The heartbeat carries the linked machine's last event-loop stall; a gap explained by a stall is shown as "froze", not as a network failure.

### Non-functional

- **NFR-1 No plaintext between machines.** Every byte between machines (except the 7-byte transport preamble and the Noise handshake, which carry no application data) is inside a secure channel. A byte capture of a link's TCP traffic contains no `HTTP/1.1`.
- **NFR-2 No root credential leaves a machine.** Links hold only `machine` tokens. Internal token and root session presented over a channel are refused.
- **NFR-3 Bounded idle traffic.** An idle link costs one heartbeat per 15 s, no polling of lists.
- **NFR-4 Compatibility.** A peer whose descriptor lacks `capabilities.machineLinks` or reports another `linkProtocol` shows `unsupported` with the exact version to install and is never retried in a loop.
- **NFR-5 Async only.** No `execSync`, no new `*Sync` exports, no `*Sync` tmux; `tailscale status --json` runs through async `execFile` with a 5 s timeout.
- **NFR-6 Pre-auth surface is bounded.** Unauthenticated channel handshakes: 10 s timeout, at most 32 pending at once, handshake frames at most 1024 bytes, failed pairing handshakes count toward the existing pairing rate limiter (`recordPairingExchangeFailure`).
- **NFR-7 Primary only.** Only a primary dashboard accepts channels or runs the supervisor.

## Decisions (made here; the executor does not revisit them)

- **D-4645-1 Noise library (W-SEC1 implementation checkpoint, resolved by live probe on 2026-11-01).** Use `noise-handshake@4.2.0` (Holepunch, Apache-2.0) with its default `dh` module (X25519 via libsodium) for `XXpsk0` and `IK`, and `@hyperswarm/secret-stream@6.9.2` (Apache-2.0) for transport framing through its `handshake: { tx, rx, hash, publicKey, remotePublicKey }` option. Protocol names are `Noise_XXpsk0_25519_ChaChaPoly_BLAKE2b` and `Noise_IK_25519_ChaChaPoly_BLAKE2b`. The library supports the psk modifier, so the pairing code authenticates the XX handshake directly (no workaround). Nothing is hand-rolled on raw primitives: our only framing is a 3-byte little-endian length prefix around opaque handshake messages, the same wire shape secret-stream uses for its own handshake. Probe results (scratchpad `noiseprobe/probe.cjs`): XXpsk0 completes and both sides learn the other's static key; a wrong PSK fails; IK to the right key completes; IK to an impostor fails; HTTP over secret-stream through `http.request({ createConnection })` and `server.emit('connection')` returns 200 with ciphertext on the wire.
- **D-4645-2 Native dependency.** `noise-handshake` pulls `sodium-universal` → `sodium-native@5.2.0` (prebuilt N-API binaries for linux/darwin/win32 x64+arm64, about 25 MB, no install script). Pin `noise-handshake` and `@hyperswarm/secret-stream` exactly in root `package.json` `dependencies`. Add `noise-handshake`, `@hyperswarm/secret-stream`, `sodium-universal` and `sodium-native` to `deps.neverBundle` in both `tsdown.config.ts:48` and `src/dashboard/server/tsdown.config.ts:145` (bundling breaks `require-addon`'s prebuild lookup). No `trustedDependencies` entry is needed because there is no install script.
- **D-4645-3 One Noise session per transport connection, no multiplexer.** Each `createConnection` opens a new transport connection and does a 1-round-trip IK handshake. HTTP keep-alive pools amortise it (`LinkAgent`, WI-17). WebSocket upgrades (`/ws/rpc`, `/ws/terminal`) take a connection each. Reason: no vetted stream multiplexer fits, and every planned route kind (TCP, SSH forward, WebRTC data channels) opens extra connections cheaply.
- **D-4645-4 Raw TCP on the dashboard port.** `lan`/`tailnet`/`public` routes use the `tcp` transport to the dashboard's own port, so no new port is opened or advertised. A `connection` dispatcher installed in the `NodeHttpServer.make` factory reads the first byte: `0x00` ⇒ channel; anything else ⇒ `socket.unshift(chunk)` and hand the socket to Node's original HTTP `connection` listeners. Probe `noiseprobe/sniff.cjs` showed keep-alive, a 200 KB POST and an HTTP request whose first byte arrived alone all work on Node 22. **Implementation checkpoint:** if the dispatcher breaks any existing dashboard test or the live `pan up` smoke, fall back to a dedicated link listener on `anywhere.link_port` (default `3017`), advertised in descriptor endpoints. The `wss` transport (`/ws/link` upgrade) exists only for HTTPS routes (Tailscale Serve), where TLS hides the upgrade.
- **D-4645-5 Wire format (transport `tcp`, and the payload of `wss`).**
  1. Initiator sends the preamble `00 4F 56 44 4C <linkProtocol=01> <mode>`; mode `01` = link (IK), `02` = pairing (XXpsk0). Pairing mode appends the 16-byte pairing id.
  2. Handshake messages travel as `uint24le length` + message. A frame of length `0` followed by one code byte is a refusal: `01` unknown peer key, `02` unsupported link protocol (followed by `uint8` responder link protocol and a `uint8`-length-prefixed UTF-8 server version), `03` unknown or expired pairing id, `04` busy (pending-handshake limit).
  3. The Noise prologue is `overdeck-link/1\0<mode byte>\0<pairing id hex or empty>`.
  4. After the last handshake message both ends construct `SecretStream` synchronously in the same tick (no data may be read between the handshake and the stream).
- **D-4645-6 Back-off cap is 45 s, not 300 s.** W-LINK3's contract "online within 60 s of plugging back" cannot hold with a 300 s back-off cap. Network failures back off 1 s doubling to 45 s with ±20% jitter. A route that answers with the wrong key (`identity-refused`) backs off doubling to 300 s. `unsupported` is re-checked only on **Reconnect**, a dashboard restart, or a heartbeat from that peer on another link; never in a timer loop.
- **D-4645-7 Heartbeat thresholds.** Interval 15 s. Late at 17.5 s ⇒ state `connecting` and parallel probes of every route, keeping the old channel open. No heartbeat by 20 s ⇒ `offline`, old channel closed. Unplugging is therefore detected in 5–20 s. A heartbeat arriving after a gap whose payload reports a stall of at least 2000 ms that ended within the gap ⇒ incident `froze`; otherwise `network`.
- **D-4645-8 Stall timing is relative.** Clocks differ between machines, so the heartbeat sends `lastStall: { durationMs, endedAgoMs }`; the receiver computes `stallEnd = receivedAt - endedAgoMs`, `stallStart = stallEnd - durationMs`.
- **D-4645-9 Machine credential resolution needs the channel.** `resolveDashboardCredential` gains a second parameter `channel: ChannelMarker | null`. A `machine` record resolves only when `channel?.mode === 'link'` and `channel.remoteKeyHex === record.machineKey`. With a non-null channel, the internal token, the root session cookie, device cookies and `token`-kind bearers all resolve to `null`.
- **D-4645-10 Channel sockets are never local.** `ChannelSocket.remoteAddress` is `link:<first 16 hex of remote key>`; `isLoopbackPeer`, `isTrustedLocalRequest` and the session mint therefore treat every channel request as remote.
- **D-4645-11 No protocol bump.** `ENVIRONMENT_PROTOCOL_VERSION` stays `1` (bumping would break existing desktop-app clients). The descriptor gains optional `machineKey`, `linkProtocol` (`LINK_PROTOCOL_VERSION = 1`, `packages/contracts/src/machines.ts`), `endpoints`, and capability `machineLinks`. Optional fields keep older descriptors decodable; a missing capability ⇒ `unsupported`.
- **D-4645-12 `require_token_mint` can only add.** Effective value = `yaml === true || hasTrustedRemoteOrigin || activeDeviceCount > 0 || activeMachineLinkOrToken`. An explicit `false` cannot turn it off while remote access exists, because the lossy whole-document Settings save writes the current value back (concerns.md) and would otherwise freeze `false` after a link appears. Settings shows the toggle checked and disabled with the reason.
- **D-4645-13 Plain HTTP refusal.** The static SPA route answers 403 with the "Use HTTPS" page when `!isLoopbackPeer && !isHttpsRequest && channel === null`. `POST /api/pairing/exchange` with `delivery: 'cookie'` under the same condition answers 403 `{ error: 'use-https' }`. Always on (not tied to D-4645-12): a session cookie over plain LAN HTTP was never safe. `GET /api/environment` stays available on plain HTTP.
- **D-4645-14 `/ws/rpc` scoping by restricted group.** RPC middleware sees per-message headers, not upgrade headers, so scope is chosen at upgrade: admin credentials get `PanRpcGroup`; any other credential gets `PanRpcGroup.omit(<every tag whose RPC_METHOD_SCOPES entry its scopes do not satisfy>)`, memoised per allowed-tag set. The upgrade itself needs `read:events` or `read:conversations` (else 403). Methods absent from `RPC_METHOD_SCOPES` need `admin`.
- **D-4645-15 4401 on `/ws/rpc`.** In the revoke branch, take the raw socket from `NodeHttpServerRequest.toIncomingMessage(request).socket` (a `net.Socket` or a `ChannelSocket`), find the `ws` WebSocket that `ws` stores on it (`node_modules/ws/lib/websocket.js:233` sets `socket[kWebSocket] = this`; there is one `ws@8.21.3` copy, no nested copy under `@effect/platform-node`) with `Object.getOwnPropertySymbols(socket).find((s) => s.description === 'websocket')`, and call `.close(4401, 'device revoked')`, which is frame-safe. Do **not** yield `request.upgrade` a second time: `upgradeEffect` is not cached (`NodeHttpServer.js:186`), so it would re-run `handleUpgrade` on an upgraded socket. **Implementation checkpoint:** if the symbol lookup finds nothing in the test, ship the existing close-without-code path and record the deviation in continue.json; the client treats the follow-up 401 as revoked.
- **D-4645-16 Cross-process revoke closes sockets.** `refreshAccessTokens()` compares the new snapshot with the old one and calls listeners registered with `onAccessTokensRevoked(listener)` for every record that became revoked or disappeared. The dashboard registers one listener that calls `closeDeviceConnections(id)` and, for `machine` records, `closeChannelsForPeer(machineKey)`. A revoke from another process therefore closes sockets within one refresh (5 s).
- **D-4645-17 Pairing PSK and id.** `psk = SHA-256("overdeck-pair-psk/1" || 0x00 || code)`; `pairingId = first 16 bytes of SHA-256("overdeck-pair-id/1" || 0x00 || code)`. `issuePairingCredential()` also stores `{ psk, pairingId }`. A successful XXpsk0 handshake consumes the credential (same single-use rule as `/api/pairing/exchange`). The same `pan pair` link pairs a browser device or a machine; whichever uses it first consumes it.
- **D-4645-18 Re-linking replaces.** Linking to an environment id that already has a link revokes the old reverse token and overwrites the link; on the linked side, minting a machine token for an environment id revokes that id's previous active machine token.
- **D-4645-19 Owner column backfill.** Columns are nullable `ALTER TABLE` top-ups. A primary-only boot step (every boot, idempotent, no marker needed because it only fills `NULL`s) sets `environment_id` on `origin = 'local'` rows to this machine's id. New local rows get it at insert from `setLocalEnvironmentId()` (set at boot before listening); vault rows get the record owner's id through the browse manifest. A vault row created from a manifest written before this change gets its id on the next browse refresh.
- **D-4645-20 Machines UI polling.** The Machines panel refetches `GET /api/machines` every 5 s while mounted (Settings only). No new domain event in this issue.
- **D-4645-21 The supervisor and channel listener run on primary dashboards only** (NFR-7), started from one boot module `src/dashboard/server/services/anywhere-boot.ts`. The link-store snapshot refresh runs on every dashboard.
- **D-4645-22 Live two-machine checks are a script, not CI.** The two-dashboard smoke (WI-21) starts two built dashboards with separate `OVERDECK_HOME`s on ports 3041/3042 and is run by the work agent and the test role; unit tests cover each mechanism with in-process fakes.

## Intersecting repo rules (restated)

- Dashboard server runs `node dist/dashboard/server.js` under Node 22 only; run `npm run build` before restarting it. Never Bun or tsx.
- No `execSync` in server-reachable code; no new `*Sync` exports (`lint:effect-facades`); `tailscale` runs through async `execFile`.
- Retry, back-off, heartbeat, watchdog, handshake-timeout and probe tests use `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()`; timeouts are `AbortController` + `setTimeout`, never `AbortSignal.timeout` (ignores fake timers under happy-dom).
- Every new HTTP route needs a row in `tests/unit/lib/overdeck/no-loss-matrix.ts`, and a row in `route-scopes.ts` when a non-admin credential may call it.
- New lib modules that need agent state import from the leaf modules; `lint:circular` must pass. `channel-peer.ts` and `link-actor.ts` are leaves.
- File-size ceiling: `conversations.ts`, `ws-rpc.ts`, `settings-api.ts`, `cli/index.ts` may not grow; never raise an allowlist cap.
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never run the full `npm test` locally.
- Never send a destructive HTTP request speculatively; never call deep-wipe.
- Tests must not read source files to assert on them (source-grep tests fail lint) and must not add `skipIf`/`.only`.
- Agents never `git stash`; worktree stays on `feature/pan-4645`.
