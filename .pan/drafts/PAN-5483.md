## Glossary

- **Mintlify**: the hosted docs platform that builds docs.overdeck.ai from this repo's root on
  every push to `main`. Its CLI is the npm package `mint`.
- **`docs.json`**: Mintlify's site config at the repo root. Its schema is
  `https://mintlify.com/docs.json`. For `"theme": "maple"` the schema sets
  `additionalProperties: false` and allows only these top-level keys: `theme`, `$schema`, `name`,
  `public`, `description`, `colors`, `logo`, `favicon`, `api`, `appearance`, `background`,
  `navbar`, `navigation`, `footer`, `search`, `seo`, `fonts`, `icons`, `styling`, `redirects`,
  `integrations`, `banner`, `errors`, `contextual`, `thumbnails`, `interaction`, `metadata`,
  `variables`, `markdown`.
- **Legacy keys**: keys from Mintlify's old `mint.json` format that the live site ignores:
  `topbarLinks`, `topbarCtaButton`, `footerSocials`, `feedback`, `layout`. `metadata` is a valid
  key in the new schema but only accepts `{ "timestamp": boolean }`; our `og:image`/`og:type`
  values under it are ignored.
- **Published page**: a page listed under `docs.json` `navigation.tabs[].groups[].pages`.
  `scripts/lint-docs.js` `collectPublishedPages()` computes the list (84 pages today).
- **Frontmatter**: the YAML block between the first two `---` lines of an `.mdx` page. Mintlify
  reads `title`, `sidebarTitle` and `description` from it. `title` renders as the page H1 and the
  `<title>` prefix; `sidebarTitle` (optional) replaces `title` in the left navigation only;
  `description` becomes the meta description and search snippet.
- **Body H1**: a `# Heading` line in the page body. Mintlify already renders `title` as the H1, so
  a body H1 is a second H1 on the page. `mint validate` warns `duplicate-h1` when it repeats the
  title.
- **Dash rule**: no em dash (U+2014) or en dash (U+2013) in any `title`, `sidebarTitle` or
  `description` we write. Use a colon, comma or period.
- **Description rule**: every `description` we write is 50 to 160 characters.
- **mint@4.3.49**: the exact `mint` version used for every check in this plan. Always run
  `npx -y mint@4.3.49 <cmd>` from the workspace root. Do not use `mint@latest`.

## Decisions

- **D-13 "Remove them from bodies you edit".** Read as: every body line this PR adds or
  modifies is dash-free (FR-15), checked mechanically on the diff. Untouched paragraphs on the
  same pages keep their dashes: the pages this PR touches carry about 549 em/en dashes, most on
  pages that #5472, #5479 and #5470 are rewriting, and a site-wide de-dash here would conflict
  with all of them. Where a line this PR must change already has a dash, replace that dash with a
  colon, comma or period on the same line.
- **D-14 Broken links.** Point each relative link to a file outside the docs site at
  `https://github.com/eltmon/overdeck/blob/main/<path>`. Drop the `#reading-the-stats-panel`
  anchor (no such heading exists in `docs/FLYWHEEL.md`). For the two targets that no longer
  exist (`docs/flywheel-brief.md`, `docs/FLYWHEEL-STATE.md`) remove the link and keep the
  backticked file name as plain inline code.
- **D-15 PR evidence.** `pan done` reuses an open PR for the branch (`src/lib/forge.ts`,
  `getExistingGitHubArtifact`). So the last work item pushes the branch, opens the PR itself with
  `gh pr create` carrying the check output, and only then runs `pan done`.
- **D-1 Scope.** This PR covers issue items 2 to 16 and item 18. Item 1 (primary domain in the
  Mintlify dashboard) is the epic owner's. Item 17 (published pages that link to the unpublished
  `meta-repos`, `progressive-polyrepo`, `setup-wizard` pages) belongs to #5482 G18, which decides
  whether those pages are rewritten, published or deleted.
- **D-2 OG image.** Reference `https://overdeck.ai/assets/og-image.png` directly in
  `seo.metatags` instead of copying a PNG into this repo. The issue asks for "a current 1200x630
  card (the overdeck.ai assets/og-image.png style)"; that file is the card, it is current, and
  linking it keeps the docs in step when overdeck.ai changes its card. A setting `og:image`
  replaces Mintlify's per-page generated cards on every page; that is what the issue asks for.
- **D-3 Install button target.** `/quickstart` (a relative path, so it works on every docs
  domain and under `mint dev`), not the npm page.
- **D-4 Colors.** primary `#4f46e5` (logo ring on light), light `#818cf8` (Mintlify uses `light`
  as the primary color in dark mode; `#818cf8` reads better on a dark background than
  `#6366f1`), dark `#4f46e5`. Keep `background` unchanged: the issue asks only for the palette.
- **D-5 Vision tab.** Rename the tab to "Anywhere" and split it into an "Overdeck Anywhere" group
  (the `anywhere` page and the `configuration/*` pages) and an "Anywhere CLI" group (the `cli/*`
  pages), keeping their current order. Put `vision` and `reference/template-conversations` in a
  new "Roadmap" group, the last group of the Reference tab. This also settles item 18 (the
  proposal page leaves the Reference group). #5482 G19 then has nothing left to move.
- **D-6 Features order.** The issue's target order starts with Issue pipeline, Planning (pages
  #5468 and #5469 add) and includes Flywheel (#5470). Those pages do not exist yet, so order the
  existing pages by the issue's sequence and let each sibling insert its page. Exact order in
  Work item 3.
- **D-7 State branch.** #5472 owns removing `configuration/state-branch` from navigation and its
  redirect to `/reference/state-model`. Here, only replace the em dash in its `description`
  (item 15). Its nav entry, body and H1 stay.
- **D-8 Body H1s.** On every page whose frontmatter this issue edits, delete the first body H1
  line (listed per page in the tables), except `configuration/state-branch.mdx` (D-7). On a
  retitled page the old H1 would contradict the new title; on the others it duplicates the title.
  Do not run `mint validate --fix` across the site: it rewrites about 80 files that sibling
  issues are editing in parallel.
- **D-9 `sidebarTitle`.** When a new title is longer than the nav needs, set `sidebarTitle` to the
  old short label so the left navigation stays compact. The tables give the exact values.
- **D-10 `feedback` and `layout`.** Delete both. They are ignored today, so deleting them changes
  nothing on the live site. Thumbs ratings and "suggest edit" are configured in the Mintlify
  dashboard, not in `docs.json`.
- **D-11 No new lint.** Checks are command one-liners in each item's verify commands, not new
  code in `scripts/lint-docs.js` (NFR-1). A bare-tag lint was probed and rejected: a per-line
  heuristic gave 16 false positives on inline code spans that wrap across lines.
- **D-12 Descriptions name no unverified command.** Every `pan` verb named in a new description
  was checked with `pan <verb> --help` at planning time (`install`, `sync`, `doctor`, `up`,
  `down`, `restart`, `health`, `start`, `status`, `tell`, `kill`, `reopen`, `pause`,
  `workspace create|list|destroy`).
