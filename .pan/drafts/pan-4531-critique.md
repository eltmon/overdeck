## blocks-the-design: Recheck after admission and before retries

The PRD's FR-3 says CI turning red during a gate stops before the next gate, and FR-1 says a decided run does not consume another CPU slot. The proposed `shouldStop` hook runs only once at the top of each gate ([validation.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4531/src/lib/cloister/validation.ts), lines 284–290). A gate can then wait in `acquireQualityGateAdmission` (lines 419–429), which has an unbounded poll loop when `maxWaitMs` is absent ([quality-gate-admission.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4531/src/lib/cloister/quality-gate-admission.ts), lines 368–395). If CI turns red during that wait, the gate starts after admission without another check (validation.ts, lines 430–457) and occupies a slot despite the known failure. A configured `retry: N` has the same problem: the retry loop (lines 409–415, 468–472) requests admission for another attempt without rechecking. Add a stop check immediately after admission and before spawning the command, releasing the acquired handle on stop; also check before each retry. Test a CI flip during admission and between attempts.

## blocks-the-design: A failing gate hides a superseding commit

FR-5 and `superseded-restart.ac2` say an agent commit during a gate must supersede the run so the supervisor verifies the new head. The runner calls `decided.isDecided()` after the gates only when no required local gate failed ([verification-runner.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4531/src/lib/cloister/verification-runner.ts), line 580). If the agent commits during the final gate and that gate fails, there is no next gate to invoke `shouldStop`; the runner skips the superseded check and proceeds to record and deliver a failure for the old head (lines 622, 675–716). The existing test commits during a *passing* first gate ([verification-tests-on-ci.test.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4531/tests/unit/lib/cloister/verification-tests-on-ci.test.ts), lines 406–417), so it misses this case. Recheck merged/superseded after every gate result, including a failed last gate, before failure accounting and feedback; test a commit during a failing final gate and assert the supervisor restarts.

## sharpens-framing: Limit notRun to scheduled gates

The PRD calls `notRun` the local gates skipped by a ci-red stop. The implementation computes it from every key in `gates` ([verification-runner.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4531/src/lib/cloister/verification-runner.ts), lines 589–591), while `runQualityGates` skips gates outside `pre_push` ([validation.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4531/src/lib/cloister/validation.ts), lines 262–286). A configured `post_push` gate would be reported as skipped by CI red even though this run never scheduled it. Define `notRun` as the remaining `pre_push` gates, and calculate it with the same phase rule used by `runQualityGates`.
