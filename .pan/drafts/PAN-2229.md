# PAN-2229 — feat(evals): prompt-regression protection for roles/*.md and the flywheel brief

**Issue:** https://github.com/eltmon/overdeck/issues/2229
**Author:** planning agent (claude-fable-5), auto mode, 2026-07-10
**Status:** draft

## Glossary

- **Prompt surface** — a markdown file whose text is injected into an agent's context and
  governs its behavior: the role files `roles/*.md` and the standing flywheel brief
  `docs/flywheel-brief.md` (`DEFAULT_BRIEF_PATH` in `src/lib/flywheel-start.ts:8`).
- **Load-bearing rail** — a safety constraint that exists ONLY in prompt prose, with no code
  enforcement. Verified at writing time: the flywheel author/assignee allowlist
  (`roles/flywheel.md:302-305`, "Author/assignee gate (security-critical)... `author.login ∈
  {eltmon, panopticon-agent[bot]}`"), "`vetoed` is absolute" (`roles/flywheel.md:306`),
  "Never spawn past `maxAgents`" (`roles/flywheel.md:309`), the `auto_pickup_backlog`
  default-OFF semantics (`docs/flywheel-brief.md`, "This run" section), and the review
  synthesis canonical verdict header `## Verdict: APPROVED / CHANGES REQUESTED — <one-line
  top blocker>` (`roles/review.md:158`).
- **Soul-degradation incident** — 27–44 well-intentioned commits that lobotomized
  `roles/flywheel.md` and the brief (suggest-only rewrite, scar-tissue accretion, a Release
  gate that quietly neutered auto-pickup). The motivating failure.
- **Evalite suite** — the existing eval harness: `npm run eval` = `cd evals && evalite .`
  (`package.json:77`), typechecked by `tsconfig.evals.json` via `npm run typecheck:evals`.
  One offline eval exists today (`evals/memory-status-rollup.eval.ts`). Policy in
  `evals/README.md`: structural scorers first, small datasets, live evals must document
  cost, CI wiring deliberately deferred.
- **Golden-scenario prompt eval** — a live-model eval: feed the actual prompt-surface text
  plus a fixture scenario to a model at temperature 0 and score structural facts about the
  output (did it decide to launch? is the verdict header canonical?).
- **Prompt-invariant test** — a deterministic vitest that asserts the load-bearing rail
  anchors still exist in the prompt text. Zero API cost; runs in the default `npm test`.
- **Prompt-Change trailer** — a git commit footer line `Prompt-Change: <what changed and
  which eval run validated it>` required by CI on any PR that diffs a gated prompt surface.
- **prompt-gate** — the new standalone CI job in `.github/workflows/ci.yml` enforcing the
  trailer. Standalone because the existing `test` job may skip vitest when an Overdeck test
  specialist already validated the SHA (`skip_vitest` step, `ci.yml:~115-134`).

## Problem

Prompt surfaces are load-bearing safety surfaces with zero mechanical protection. The
author allowlist and the release/pickup gates exist only as prose; nothing fails when a
commit deletes or dilutes them. The soul-degradation incident proved drift is silent and
cumulative. We need (a) behavioral regression evals that detect when a prompt stops
producing the intended decisions, and (b) a CI gate that makes every prompt diff visible
and deliberate.

## Requirements

- **FR-1** — `npm run eval` includes a flywheel golden-scenario eval: given a fixture board
  state with a released, ready+planned, allowlisted-author backlog issue and free slots
  (auto-pickup ON), the flywheel prompt must yield launch decisions, not just a report;
  given a third-party-authored issue it must NOT launch it; given auto-pickup OFF and no
  release it must NOT launch backlog.
- **FR-2** — `npm run eval` includes a review-synthesis golden-scenario eval: given four
  fixture convoy reviewer reports, the review prompt must yield the canonical
  `## Verdict:` header, consolidate all in-diff blockers in one report, demote
  out-of-PR-diff findings, and respect the requirements `Scope:` classification.
- **FR-3** — CI fails a pull request whose diff touches `roles/*.md` or
  `docs/flywheel-brief.md` when no commit in the PR range carries a `Prompt-Change:`
  trailer. `docs/flywheel-briefs/*` (per-run order books) are not gated.
- **FR-4** — A deterministic prompt-invariant vitest suite asserts the load-bearing rail
  anchors (allowlist identities, vetoed, maxAgents, auto_pickup_backlog OFF/ON,
  require_uat_before_merge, verdict header, blocked-signal command) and runs in the
  default `npm test` path.
- **NFR-1** — No live-model calls in blocking CI. The live evals run locally/on-demand.
- **NFR-2** — No hardcoded model fallback: the eval model comes only from
  `OVERDECK_EVAL_MODEL`; the harness fails loudly, before any network call, when unset.

## Design decisions (made here, not left to the executor)

1. **Live evals drive prompt files as text.** Read `roles/flywheel.md`,
   `docs/flywheel-brief.md`, `roles/review.md` from the repo, splice in fixtures, call
   `@anthropic-ai/sdk` (already a dependency, `package.json:131`) directly. No refactor of
   flywheel/review logic into callable functions (the alternative floated in
   `evals/README.md` is deferred).
2. **Model resolution:** `process.env.OVERDECK_EVAL_MODEL`, else throw naming the variable.
   Do NOT copy the `DEFAULT_MODEL` literal pattern from
   `src/lib/memory/providers/anthropic.ts:13` — it predates the no-hardcoded-fallback rule.
3. **Scorers are structural and binary** (parse a JSON action array; regex anchors on the
   synthesis report). No LLM-as-judge. Temperature 0. Small datasets (3 flywheel
   scenarios, 1 review scenario with 4 scorers).
4. **CI teeth are deterministic:** the invariant suite (FR-4) plus the trailer gate (FR-3).
   The trailer is the operator's assertion that `npm run eval` was run; CI does not verify
   the live run itself (NFR-1).
5. **Gate placement:** standalone `prompt-gate` job, `pull_request` events only,
   `timeout-minutes: 5`, `fetch-depth: 0`, pure git+bash (no Node/Bun setup). Failure
   message is operator-facing per the explain-fully rule: names the changed gated files,
   states the requirement in full sentences, shows a `git commit --allow-empty` example,
   never suggests amending pushed history.

## Acceptance criteria (map 1:1 to work items)

1. `runPromptScenario` rejects before any network call, naming `OVERDECK_EVAL_MODEL`, when
   the variable is unset; `npm run typecheck:evals` passes; no model-id fallback literal.
2. `npm run eval` executes the flywheel eval; the three scorers return 1/0 exactly per the
   fixture contracts above (report-only output scores 0 on `launches-released-backlog`).
3. `npm run eval` executes the review eval; the four scorers return 1/0 exactly per the
   fixture contracts above.
4. The invariant suite passes on current prompts, runs under plain `npm test` with no
   config change, and removing the allowlist line in a scratch copy fails the matching
   `it()` with a message naming the rail and PAN-2229.
5. In a temp git repo: gated diff without trailer → script exit 1 with the full
   operator-facing message; same diff plus a `Prompt-Change:` commit → exit 0; `src/`-only
   or `docs/flywheel-briefs/*` diff → exit 0. `ci.yml` has the standalone `prompt-gate`
   job (pull_request only, timeout capped, fetch-depth 0).
6. Docs updated as specified; nothing instructs running live evals in CI or amending
   pushed commits.

## Non-goals

See vBRIEF `narratives.NonGoals` (authoritative): no live evals in CI, no git hooks for
the trailer, no prompt-logic extraction refactor, no golden-scenario evals for the other
role files, no gating of per-run order books, no eval baseline/threshold policy, no edits
to the prompt files themselves, no new model-routing machinery.

## Intersecting repo rules restated for the executor

- Never hardcode a model fallback; fail loudly on missing `OVERDECK_EVAL_MODEL`.
- No `execSync` anywhere server-reachable; the trailer-gate unit test uses async
  `execFile`. No timers involved anywhere in this issue, so the fake-timers rule is not
  triggered — do not add real sleeps.
- Conventional commits (commitlint); trailers are footers and pass `config-conventional`.
- Every CI job caps `timeout-minutes` (PAN-1651).
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint`, `npm test`.
- Do not weaken or bypass husky hooks; never `--no-verify`.
