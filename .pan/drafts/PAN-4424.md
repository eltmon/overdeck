# PAN-4424 — Matt Pocock skills as a fork-sourced pack (`eltmon/skills`)

**Issue:** [PAN-4424](https://github.com/eltmon/overdeck/issues/4424) · **Base:** `origin/main` @ `a54b4cba736` · **Planned:** 2026-09-29 (auto mode)
**Builds on:** PAN-4334 (#4353, skill packs, merged) and PAN-3942 (per-skill levels). Covers the managed-launch check of #4352.

## 0. Glossary

- **Pack.** A third-party git repo of Agent Skills registered with `pan skills pack add <id> <url> --ref <ref>` (PAN-4334). Stored in `~/.overdeck/config.yaml` under `skills.packs.<id>: { url, ref, commit }`.
- **Fork.** `eltmon/skills`, the operator's GitHub fork of `mattpocock/skills` (MIT). On 2026-09-29 it is **identical** to upstream `main` (`gh api repos/mattpocock/skills/compare/main...eltmon:skills:main` → `status: identical, ahead 0, behind 0`) and carries the upstream tags (`v1.2.3` → `6acc160e4e0cd062dbbbd7a1b26ae92855edf07e`).
- **Trusted commit.** The 40-hex commit the operator approved at add time; every launch mounts exactly this commit.
- **`KNOWN_PACKS`.** Table in `src/lib/skill-packs/adapters.ts` (line 54) with per-pack-id defaults: adapter and opt-in skills. It is keyed by **pack id**, not URL, so the `mattpocock` defaults (adapter `claude-plugin`, opt-in `setup-matt-pocock-skills`) apply to any URL registered under id `mattpocock`, including the fork.
- **Opt-in skill.** A pack skill the pack toggle never turns on; only a per-skill `on` does. `setup-matt-pocock-skills` is the only one (it edits `CLAUDE.md`/`AGENTS.md` and writes `docs/agents/*.md`).
- **Pack toggle / levels.** On/off for a whole pack at global (`skills.pack_overrides.<id>`), project (`projects.yaml` `skill_pack_overrides.<id>`), issue (`<planHome>/.pan/skill-overrides/<ISSUE>.yaml` `packs.<id>`). Pack skills are off unless turned on.
- **Launch step.** `pan skills launch-settings --harness <h> --cwd <dir> [--issue <id>] [--plugin-link <p>] [--codex-home <d>]` — the bash step every local managed Claude Code / Codex launcher runs before the harness starts (`src/lib/skill-overrides/launcher-lines.ts`). For Claude it points `--plugin-link` at the mount; for Codex it writes the `# overdeck:skill-packs:begin/end` block into the per-agent `config.toml`.
- **Managed launch.** An agent Overdeck spawns in a terminal-backend pane through `launcher-generator.ts` (here: `pan worker run`, role `worker`).
- **Harness-visible name.** `mattpocock:<skill>` — Claude Code and Codex namespace plugin skills as `plugin:skill`.
- **Checkpoint doc.** `.pan/drafts/PAN-4424-live-checkpoint.md`, the transcript of the live verification (same shape as `.pan/drafts/PAN-4334-live-checkpoint.md`).

## 1. Verdict

The mechanism already shipped in PAN-4334 and is live in the deployed `pan` 0.63.0 (`pan skills launch-settings --help` lists `--plugin-link`). This issue is a **re-point plus a live verification**, not new machinery:

1. Point Overdeck's `mattpocock` defaults (the `KNOWN_PACKS` url, the CLI empty-list hint, the dashboard add command, the docs) at `https://github.com/eltmon/skills`.
2. Register the pack on this host from the fork at tag `v1.2.3` (commit `6acc160`). Registering enables nothing.
3. Verify the three toggle levels through the launch step, and verify managed Claude Code and Codex launches at issue level on PAN-4424. Record everything in the checkpoint doc. Leave every toggle off/inherit at the end so the operator tests it.

**No fork changes are needed.** Overdeck already mounts only skill directories and already makes `setup-matt-pocock-skills` opt-in by pack id, so the fork stays identical to upstream and there is nothing to rebase or upstream.

## 3. Decisions (auto mode)

- **D1 — Pin `v1.2.3` (`6acc160`).** It is the latest release tag, present on the fork, and the exact commit PAN-4334 audited (25 skills, 1 opt-in, 2 template scripts not applied). Fork `main` is an untagged v1.3 merge; moving to it is an operator `pan skills pack update mattpocock --ref <ref>` later.

- **D3 — Re-point the defaults, keep `KNOWN_PACKS` keyed by id.** Set `KNOWN_PACKS.mattpocock.url` to the fork and make the CLI hint read that url, so the CLI has one source. The dashboard cannot import `src/lib` (separate package), so `ADD_COMMAND` stays a literal, updated to the fork.
- **D4 — Level verification scope.** The launch step resolves the project from `--cwd` (`resolveProjectKeyForCwdAsync`, `src/lib/skill-overrides/launch.ts:37`); this workspace lies under project key `panopticon-cli` (`~/.overdeck/projects.yaml` line 2, path `/home/eltmon/Projects/overdeck`). Global and project toggles affect every agent launched on this host (global) or in project `panopticon-cli` (project) while they are on. Verify those two levels through the launch step itself (`pan skills launch-settings`, the literal command every managed launcher runs) inside a window of seconds, then revert. Run the real managed launches (Claude Code and Codex) at **issue level on PAN-4424** only, where the blast radius is this issue. AC-2 is satisfied by: each level changes what the launch step mounts, and managed launches of both harnesses show `mattpocock:<skill>` with no dialog.
- **D5 — End state is "registered, off".** After verification: global pack `off`, project `inherit`, issue `inherit`, `pan skills pack gc --max-age-days 0`. The docs give the operator the enable commands. The issue says the operator tests it; nothing is left on.
- **D6 — Vendored copies stay.** Overdeck's bundled `grilling`, `codebase-design`, `domain-modeling`, `improve-codebase-architecture` (MIT-attributed in `cf9773cb56b`) are default-on; the pack is default-off. Retiring them changes what every user gets out of the box, so that decision waits until the operator has evaluated the pack. Out of scope here.
- **D7 — #4352.** Its checklist is WI-6 below. The PR body says "Covers #4352" and the work agent comments on #4352 (an `eltmon/overdeck` issue, allowed) with the checkpoint doc path. The operator closes #4352.
