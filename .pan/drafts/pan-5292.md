## 1. Summary

The app bar today is a row of eleven unrelated pills: a Deacon freeze toggle, a green "N agents" pill, a red "Stop all" button, a stopped-agents pill, a low-cost pill, a stale-build text, a GitHub quota pill, a system-health pill, a Decisions badge, a Flywheel "Needs you" badge and a System-controls menu. Two of them count "needs you" with different rules (the Decisions badge counts `useDecisions()`, the Flywheel badge counts the tick line plus in-flight rows), and the Home page counts a third way (`derived.attention === 'needs-you'`). The agents pill counts store agents only, while the Home page counts `hasLivePane || running || starting`.

This child replaces the right side of the bar with the mockup's four controls — **agents menu**, **Needs you · N**, **health dot**, **theme** — plus quiet exception chips, makes the search box open the command palette, makes the crumb read `project / active tab`, and switches the top bar and the Home page to the two shared selectors from child S so every count agrees.

## 2. Glossary

- **Top bar / app bar** — the 48 px row rendered by `App/AppChrome.tsx` (search `App bar (PAN-1591)`), above the routed page and to the right of `components/Sidebar.tsx`.
- **System-notices row** — the banner row at the top of `AppChrome` (search `data-component="system-notices-row"`) plus the banners below it (`DegradedModeBanner`, `NewBuildBanner`, tracker-key banner, CLIProxy banner). **Not changed by this child.**
- **Agents working** — the count from `useAgentsWorking()` (`lib/selectors/agentsWorking.ts`): store agents with a running status plus conversations with `isWorking`, one row per session (parent D-9).
- **Needs-you item** — one entry of `useNeedsYouItems()` (`lib/selectors/needsYou.ts`): pending input, issue attention, Flywheel rows and decisions, deduplicated (parent D-8).
- **Agents menu** — the new top-bar button "N agents working ▾" and its dropdown.
- **Needs-you menu** — the new top-bar button "Needs you · N" and its dropdown.
- **Health dot** — the new top-bar 9 px dot button whose color follows `useSystemHealth()` and whose popover hosts every system widget that used to be its own pill.
- **Exception chip** — a small text chip left of the health dot that renders only while something abnormal is true (low-cost mode on, server build behind main, Deacon auto-resume frozen, stopped agents). Normal state shows no chip.
- **Section** — one labelled block inside the health-dot popover (System health, GitHub quota, Auto-resume, Stopped agents, System controls).
- **Palette** — `components/CommandPalette.tsx`, opened today by `Ctrl K` / `⌘K` through `App/hooks/useAppShortcuts.ts` (`id: 'app.palette'`).
- **Search modal** — `components/search/SearchModal.tsx`, opened today by the bar's search button and by `/`.
- **CI subset** — `scripts/frontend-test-subset.txt`; CI runs only the frontend Vitest files listed there (one path per line, relative to `src/dashboard/frontend`, sorted, `merge=union`).
- **Aggregate chrome** — the components `docs/DASHBOARD-ARCHITECTURE.md` "Render discipline (PAN-4560)" allows to subscribe to whole agent/issue slices because they show cross-issue totals.

## 3. Decisions (made here; the executor does not re-decide them)

- **E-D1 Selectors are called only in leaf components.** `useAgentsWorking()` and `useNeedsYouItems()` are called inside `App/topbar/AgentsMenu.tsx`, `components/flywheel/NeedsYouIndicator.tsx`, `pages/HomePage.tsx` and nowhere in `App.tsx` or `AppChrome.tsx`. Reason: "Render discipline (PAN-4560)" — `App` must not subscribe to slices, and `AppChrome` renders every banner, so a slice subscription there re-renders all of them on each agent event.
- **E-D2 `countRunningAgents` stays, for `UpdateDialog` only.** `App.tsx` keeps `const runningAgentCount = useDashboardStore((s) => countRunningAgents(s.agentsById))` because `components/UpdateDialog.tsx` (search `runningAgentCount > 0`) asks a different question: how many store agents an update restart would interrupt. `AppChrome` loses its `runningAgentCount` prop. The doc comment on `countRunningAgents` in `App/AppLiveStoreHost.tsx` (search `Live agent count for the app-bar status pill`) is rewritten to say it feeds the update dialog, not the top bar.
- **E-D3 The Activity-feed (History) toggle stays in the bar in this child.** Parent §7 assigns "Off-deck History toggle" to child F, which ships its replacement (the `/activity` Feed tab). Removing it here would leave the off-deck feed unreachable until F merges (parent D-13, D-14). AC-E's "only the elements in §6.7" therefore reads "§6.7's elements plus the History toggle, which child F removes".
- **E-D4 No brand in the top bar in this child.** The mockup's top bar spans the full window with the brand above the left column. Today `AppChrome` sits right of `Sidebar.tsx`, which already shows the logo and version, and the window-spanning grid is child F's layout change (parent §8: `App.tsx` layout is F's). E adds no brand; F moves it.
- **E-D5 The health-dot popover hosts inline sections, never nested popovers.** Each hosted widget renders its body inline in the popover (no inner trigger, no inner absolute popover). The only nested floating UI allowed is what `CloisterStatusBar` already portals to `document.body` (its restart popover and restart-config modal).
- **E-D6 The health-dot popover close rule.** It closes on: Escape; a second click on the dot; a click on any navigation row inside it; a pointer-down outside the dot's wrapper **unless** the target is inside an element matching `[role="dialog"], [role="alertdialog"]` (the Cloister portals and the emergency-stop confirm). To make that rule cover the Cloister restart-config modal and its backdrop, the outer `fixed inset-0` container in `components/CloisterStatusBar.tsx` (search `Restart with Current Config Modal`) gains `role="dialog" aria-modal="true" aria-label="Restart agents with current config"`. Today's guard `if (document.querySelector('[role="alertdialog"]')) return;` in `SystemHealthPill.tsx` **stays** (it keeps the popover open while any confirm is up, including clicks on a confirm's backdrop); the target-based rule is added after it.
- **E-D7 Dot colors.** `healthy` → `bg-success` (emerald), `warning` → `bg-warning` (amber), `critical` → `bg-destructive` (red) with `motion-safe:animate-pulse`, `measuring` → `bg-info`, `unavailable` and loading and fetch error → `bg-muted-foreground`. These are today's `stateDotClass()` values in `SystemHealthPill.tsx`; reuse that function. The dot follows `useSystemHealth()` only — exception chips carry every other abnormal state.
- **E-D8 The dot is a button in every state.** Loading, fetch error and `unavailable` still render the dot as a button that opens the popover; the System-health section then reads "Measuring system health…" (loading) or "Health unavailable" (error/no data), and every other section still renders. Reason: the Deacon toggle, quota, stopped agents and Cloister controls must stay reachable when the health endpoint fails.
- **E-D9 Four exception chips, left of the dot, in this order:** (1) **Auto-resume frozen** — `DeaconFrozenChip`, the existing compact Deacon toggle, rendered only while Deacon is paused; clicking it resumes (today's compact behavior). (2) **N stopped** — the existing `StoppedAgentsBanner variant="pill"`, unchanged, rendered only while stopped agents exist. (3) **Low-cost mode** — the existing `LowCostModePill`, unchanged. (4) **Build behind main** — `StaleBuildChip`. Parent §6.7 names only (3) and (4). (1) is added because `DeaconPauseBanner` is mounted nowhere (grep `DeaconPauseBanner` finds only its definition and tests), so the bar's compact toggle is today the only visible "auto-resume is off" signal, and "Stop all agents…" freezes Deacon. (2) is added because the stopped pill is today's only visible stopped-agents signal. Both follow §6.7's own rule "exceptions surface, normal state stays quiet".
- **E-D10 The stale-build chip reads "Build behind main", not "Reload to update".** `StaleBuildChip` (via `hooks/useDeployStaleness.ts`) reports that the **server** build is behind `origin/main`; a browser reload does not fix it (`NewBuildBanner` owns the browser-reload case, PAN-5236). Its `title` keeps today's facts and adds the count and the remedy: `Running build <8> · origin/main <8> · <behindBuildInputs> build-input commit(s) behind · <behindTotal> total commit(s) behind · Run pan reload to build and restart the dashboard.`
- **E-D11 Stopped agents also get an inline section.** Parent §7 maps "Stopped-agents restart" to the health-dot popover. `StoppedAgentsBanner` gains `variant: 'section'`: the same list and **Restart all** button the pill's popover shows, inline, `null` at zero. The api-error toast effect (search `Show toast when an agent hits an API error`) runs only when `variant !== 'section'`, so the always-mounted pill keeps firing it once and opening the popover never re-fires it.
- **E-D12 GitHub quota becomes a section; the pill is removed.** `components/GitHubQuotaPill.tsx` exports `GitHubQuotaSection` (the label line, the callers list with `data-testid="github-quota-callers"`, the unattributed row, warning tone while paused, `null` until the publisher reports) and no longer exports `GitHubQuotaPill`. The file name stays, so blame and the test file path stay. `topGitHubQuotaCallers` stays exported.
- **E-D13 System controls become a section.** The popover's last section renders `<CloisterStatusBar onOpenSettings={onOpenSettings} />` directly (what `SystemMenu` hosted). `components/SystemMenu.tsx` and `components/SystemMenu.test.tsx` are deleted: the component has no other consumer (`Sidebar.tsx` only mentions it in a comment), and the test-skip gate's deleted-subject exemption covers a test deleted with its subject.

Reason: 16 pinned tests in `SystemHealthPill.test.tsx` and `system-health-ui-no-loss.test.tsx` query that test id and the dialog behavior; a rename adds churn and no behavior. The file header comment states it is the top bar's health dot.
- **E-D13a Deleted orphans.** `components/RunningAgentsPill.tsx` + `components/RunningAgentsPill.test.tsx` (replaced by `App/topbar/AgentsMenu.tsx` + its test, which covers the same two behaviors), and `components/DecisionsIndicator.tsx` (no test; its only consumer is `AppChrome`; decisions are part of the Needs-you menu). `components/DecisionsPanel.tsx` stays (Awareness uses it until child F).
- **E-D15 The search box opens the palette.** The bar's search button calls a new `onPaletteOpen` prop; `App.tsx` passes `() => { setPaletteInitialScope('all'); setIsPaletteOpen(true); }`. Its text is the constant `PALETTE_SEARCH_PLACEHOLDER = 'Search issues, conversations, commands…'` and its keycap is `formatSpec(currentPlatform() === 'mac' ? 'Meta+K' : 'Ctrl+K', currentPlatform())` from `lib/shortcuts/keys.ts`. The palette is global, so the placeholder no longer names the project. `/` keeps opening the search modal (parent D-7). The palette's Files scope is child B's (B owns `CommandPalette.tsx`); when B adds it, B changes `PALETTE_SEARCH_PLACEHOLDER` in `App/appChromeLabels.ts` to "Go to file, conversation, issue or command" — this hand-off is written into `docs/DASHBOARD-ARCHITECTURE.md` (WI-E13).

- **E-D18 Needs you and agents are always visible.** "Needs you · 0" renders neutral (no amber border/background, gray dot); amber only when N > 0 (parent §6.7). The agents button reads "No agents working" at 0, "1 agent working" at 1, "N agents working" otherwise; its dot is `bg-state-live` (blue — "running is blue, never green") when N > 0 and `bg-state-waiting` at 0. ## 5. Repo rules that apply (restated)

- Frontend tests must be listed in `scripts/frontend-test-subset.txt` or CI never runs them (sorted position; `merge=union`).
- Run only the test files you touched: `npx vitest run <files>` from `src/dashboard/frontend` (or `npm --prefix src/dashboard/frontend exec vitest run <files>`). Never run the full `npm test` on the host.
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint` (includes `lint:docs` and `lint:file-size`).
- Frontend typecheck skips test files (`src/dashboard/frontend/tsconfig.json` excludes `*.test.*`), so a mock that still names a removed export passes typecheck and fails only at test time — run every touched test.
- Delay-based tests use `vi.useFakeTimers()`; never real waits.
- A test that reads source files or adds `skipIf`/`.only` fails lint / the test-skip gate; assert behavior.
- The test-skip gate counts deleted tests across the whole diff: replace pinned tests, do not delete them, except a test deleted together with its subject component (deleted-subject exemption).
- No hardcoded model ids; no `execSync`; workspaces are worktrees — never `git checkout` another branch, never `git stash`.
- A user-facing change adds `changelog.d/pan-5292.md` (lowercase), format in `changelog.d/README.md`.
