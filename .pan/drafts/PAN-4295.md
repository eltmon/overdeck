# PAN-4295: Fly remote — restore auto-reap, heartbeat and credential refresh; stop copying SSH keys to VMs

**Issue:** [PAN-4295](https://github.com/eltmon/overdeck/issues/4295) · **Parent PRD:** `.pan/drafts/pan-2350.md` (Overdeck Anywhere, revision 5), work item **W-FLY1**, decision **D-12**, groundwork for **FR-18**.
**Planned:** 2026-11-01, auto mode, against `main` at `356ce40ec91`.

## Glossary

- **Remote agent** — a Claude Code work agent that runs in a tmux session on a Fly.io Machine (a "VM"), not on this host. Its host-side record is `~/.overdeck/agents/agent-<issue>/remote-state.json` (`RemoteAgentState`, `src/lib/remote/remote-agents.ts:285`).
- **Active remote agent** — a `remote-state.json` whose `status` is `running` or `starting`. `listActiveRemoteAgentStates()` (`remote-agents.ts:334`) finds them by a local file scan with no Fly API call.
- **Ephemeral tier / durable tier** — the two remote resiliency tiers. Ephemeral machines have `restart.policy: 'no'` and get a VM-side watchdog; durable machines mount a Fly volume at `/workspace` and get no watchdog.
- **Ephemeral watchdog** — the Node script `generateEphemeralWatchdogScript()` (`remote-agents.ts:185`) installed on every ephemeral VM at spawn (`remote-agents.ts:674-676`). Every 60 s it reads the mtime of `/workspace/.pan/host-heartbeat`; when the file is older than 300 s it runs `kill 1`, which stops the machine. While the file does not exist it only logs "waiting for host" and never stops the machine.
- **Host heartbeat** — the host writing the current time into `/workspace/.pan/host-heartbeat` on every active ephemeral VM. Function: `refreshHostHeartbeatForEphemeralVms()` (`remote-agents.ts:353`). It exists but nothing calls it.
- **Credential refresh** — the host re-copying `~/.claude/.credentials.json` (or the macOS Keychain item) to every active VM when the host file changes, or every 15 min at most. The function `refreshClaudeCredentialsForActiveRemoteAgents()` was deleted by commit `441e2ef5078` (PAN-4014 CH-8a) after the Cut left it without a caller.
- **Reap** — `reapCompletedRemoteAgents()` (`src/lib/remote/remote-completion.ts:182`): the one host-side function that hands a finished remote agent to review (salvage, forensics copy, worktree materialization, review artifacts, machine destroy). Today only `pan admin remote reap` (`src/cli/commands/remote/reap.ts`) calls it.
- **REMOTE_DONE sentinel** — the file `/workspace/.pan/REMOTE_DONE` that the remote agent creates after its final push (`src/lib/cloister/prompts/work.md:340-344`).
- **The Cut** — PAN-3917. Commit `94255f055fe` (W4) replaced `deacon.ts` with `deacon-lite.ts` + `hygiene-scheduler.ts` and dropped the three remote patrol calls (old `deacon.ts` lines ~2763-2808).
- **Deacon child** — the separate Node process (`src/dashboard/server/deacon-main.ts`) that runs `CloisterService`, which starts deacon-lite and the hygiene scheduler (`src/lib/cloister/service.ts:347-348`). All loops in this PRD run there.
- **Deacon freeze** — `isDeaconGloballyPaused()` (`src/lib/overdeck/control-settings.js`); `runDeaconLite()` returns early when it is set (`deacon-lite.ts:547`). The hygiene scheduler ignores it.
- **Positive evidence** — a probe result that came from a successful exec (exit code 0 with an expected stdout token). A failed or garbled exec is *indeterminate*, never "dead" or "absent".

## Problem

The Cut deleted the three host loops that kept Fly remote agents safe and moving:

1. **Auto-reap** — old `deacon.ts` called `reapCompletedRemoteAgents()` every 60 s. Now a finished agent sits on a running machine until the operator runs `pan admin remote reap`, and the review route refuses the issue with HTTP 409 (`src/dashboard/server/routes/workspaces/review-pipeline.ts:381-388`).
2. **Ephemeral-VM heartbeat** — old `deacon.ts` called `refreshHostHeartbeatForEphemeralVms()` every 60 s. Now no host ever writes `/workspace/.pan/host-heartbeat`, so the watchdog waits forever and an ephemeral VM never self-stops when the host goes away.
3. **Credential refresh** — old `deacon.ts` called `refreshClaudeCredentialsForActiveRemoteAgents()` every 60 s. Now a long run stalls on `API Error: 401 · Please run /login` when the host's OAuth refresh rotates the token (seen live on PAN-1762), and only the reactive heal inside the reap (which nobody calls) could fix it.

Two more defects block a working end-to-end run:

4. **The reap no longer starts review.** It writes `~/.overdeck/agents/<id>/completed` for "the cloister's `checkCompletionMarkers()` patrol" (`remote-completion.ts:18-20, 359-369`). That patrol was deleted in the Cut. After the Cut, `pan done` starts review by calling `POST /api/review/:issueId/request` (`src/cli/commands/done.ts:281-311`). The reap never makes that call, so a reaped issue gets a PR but no review.
5. **The reap is unsafe to run automatically.** It treats a failed exec as a dead session (`isRemoteAgentRunning` returns `false` when the Machines exec API errors, because `FlyProvider.sshImpl` turns a non-429 `FlyApiError` into `{ exitCode: 1 }`, `fly-provider.ts:391-397`), and its sentinel command `[ -f … ] && echo present` exits 1 both when the file is absent and when the exec fails. One Fly API blip therefore sends a healthy agent down the crash path, which stops its machine. It also scans `starting` agents, so a tick that lands mid-spawn (before the tmux session exists) stops a machine that is still being provisioned.

Separately, `pan workspace create --remote` copies the operator's private SSH key to the VM (`src/cli/commands/workspace-remote.ts:166-179`: `~/.overdeck/ssh/exe-dev-key`, `~/.ssh/id_ed25519`, `~/.ssh/id_rsa`). A VM is a shared cloud machine; it must never hold a key that opens every repo the operator can reach. That code path is also broken on the current image: it clones into `~/workspace` and then runs `sudo ln -sf ~/workspace /workspace || true`, but `docker/pan-workspace/Dockerfile` installs no `sudo` and already creates `/workspace`, so `/workspace` stays empty while the agent prompt and spawn path assume `/workspace` is the repo. `pan start <id> --remote` uses a second, newer creator (`src/lib/remote-workspace.ts`) that clones over HTTPS with the synced `gh` token and copies no key.

Fly remote agents have not been run live since the Cut.

## Goals

- `pan start <id> --remote` completes end to end — spawn, work, `REMOTE_DONE`, automatic reap, review requested — with no operator command. The new code's reap and key-free spawn are proven live before merge (WI-9); the automatic tick is confirmed by the filed post-merge check once the Flywheel deploys the merge.
- No VM ever receives an operator SSH private key, by any creation path.
- An ephemeral VM stops itself within ~6 min of the host going away.
- A long remote run gets fresh Claude credentials before it stalls.

## Non-goals

- Running `pan serve` on the VM or linking it at spawn (W-FLY2, [#4652](https://github.com/eltmon/overdeck/issues/4652)); Codex on Fly (W-FLY3, [#4296](https://github.com/eltmon/overdeck/issues/4296)).
- Remote agents as session rows / live transcripts ([PAN-1775](https://github.com/eltmon/overdeck/issues/1775)); overflow scheduling ([PAN-1676](https://github.com/eltmon/overdeck/issues/1676)).
- GitLab-hosted or polyrepo projects on Fly. Without an SSH key, a GitLab clone needs a `glab` credential helper, and the image ships no `glab`. Polyrepo-on-Fly only existed in the broken `pan workspace create --remote` path.
- Reconciling a `remote-state.json` whose machine was destroyed outside Overdeck (it stays "indeterminate" and is retried each tick at the cost of one Fly API call).
- A cross-process lock between the automatic reap (deacon child) and a concurrent manual `pan admin remote reap`.
- Settling copied remote transcripts into the Session Vault ([PAN-2609](https://github.com/eltmon/overdeck/issues/2609) WI-9).
- Fixing smoke-test failures that lie outside the three loops, the reap hand-off and the key removal (see WI-9 decision rule).

## Requirements

### Functional

- **FR-1** Every 60 s the deacon child writes the current ISO time to `/workspace/.pan/host-heartbeat` on every active remote agent whose `tier` is not `durable`, whether or not the deacon freeze is set.
- **FR-2** A heartbeat write whose exec returns a non-zero exit code is reported as a failure, never as "refreshed".
- **FR-3** Every 60 s the deacon child runs the credential refresh; it copies host Claude credentials to an active VM when the host credentials fingerprint (`mtimeMs:size` of `~/.claude/.credentials.json`) changed since that VM's last successful sync, or 15 min have passed since it, or the VM has never been synced. A failed sync leaves that VM's watermark untouched so the next tick retries it. It runs whether or not the deacon freeze is set.
- **FR-4** Every deacon-lite tick (60 s) reaps finished remote agents through `reapCompletedRemoteAgents()`, unless the deacon freeze is set. A reap that is still running when the next tick fires is not started again.
- **FR-5** Without `--issue`, the reap considers only `status: 'running'` agents; `starting` agents are skipped.
- **FR-6** The reap classifies each agent from positive evidence only (decision table in WI-3). An indeterminate probe yields the new result status `indeterminate` and takes no action on the machine or the state file.
- **FR-7** After a successful hand-off the reap requests review through `requestReviewThroughRoute()` with source `'remote-reap'`, after the remote workspace metadata is deleted. A refused or unreachable request is recorded in the result details with the `pan review request <id>` remedy; the hand-off still reports `handed-off`.
- **FR-8** `'remote-reap'` is a `RequestReviewSource`, and the review route journals it as `remote-reap`, not `api`.
- **FR-9** Handed-off and error reap results produce one activity entry each (`source: 'cloister'`), and one console line in the deacon child.
- **FR-10** No Overdeck code path copies a file from `~/.ssh/` or `~/.overdeck/ssh/` to a VM. `pan workspace create --remote` creates the VM through `src/lib/remote-workspace.ts`'s `createRemoteWorkspace()`, the same creator `pan start --remote` and `pan workspace migrate --to remote` use.
- **FR-11** `createRemoteWorkspace()` clones over HTTPS for any `git@<host>:<path>` origin (`https://<host>/<path>`), not only GitHub.
- **FR-12** The 409 message of the review route for a remote issue says the reap runs automatically and names `pan admin remote reap --issue <id>` only as the way to force it.

### Non-functional

- **NFR-1** With zero active remote agents, no tick of any of the three loops constructs a Fly provider or makes a Fly API call (the local `remote-state.json` scan short-circuits first).
- **NFR-2** Every test of a delay or interval uses `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()`; no test waits on a real `setTimeout` (repo rule: fake timers for retry/backoff/delay tests).
- **NFR-3** No new `execSync` anywhere reachable from the deacon child or dashboard server (repo rule: no `execSync` in server code).
- **NFR-4** No file grows past the file-size guard (`scripts/lint-file-size.sh`: ceiling 1000 lines for files at or below it on `origin/main`). `review-pipeline.ts` is 992 lines; its change is a same-line edit plus at most a net +4 lines. `remote-agents.ts` (839) takes only the FR-2 fix.
- **NFR-5** Every new export has a production caller, or carries the documented test-seam comment form `/** Test seam: no production caller; … */` (dead-export scan, PAN-3958).

## Decisions (made here, not deferred)

- **D-1 Placement.** Heartbeat and credential refresh go into `hygiene-scheduler.ts` as two more 60 s routines. They touch no pipeline status (that module's contract) and must keep running under the deacon freeze: a frozen deacon that stopped heartbeats would make every ephemeral watchdog kill its machine within 5 min. The reap goes into `runDeaconLite()` as its last routine, through a small wrapper module with an in-flight guard, because it writes agent state and requests review (pipeline actions that the freeze must stop).
- **D-2 Restore, don't rewrite.** The credential refresh is restored verbatim from `git show 441e2ef5078^:src/lib/remote/remote-completion.ts` into a new module `src/lib/remote/remote-credential-refresh.ts` (keeps `remote-completion.ts` free for WI-3/WI-4 and lets the items run in parallel). Its test is restored from `git show 441e2ef5078^:tests/lib/remote/remote-completion.test.ts`.
- **D-3 One creator.** The duplicate `createRemoteWorkspace()` in `src/cli/commands/workspace-remote.ts` is deleted along with `convertToSshUrl()`, the `ssh-keyscan` step and the key copy. `workspace-create.ts` calls the lib creator. This removes the key copy and the broken `~/workspace` + `sudo ln` layout in one deletion. Cost: `pan workspace create --remote` no longer clones polyrepo sub-repos or syncs `glab` config (both non-goals).
- **D-4 All private keys, not only `id_*`.** `~/.overdeck/ssh/exe-dev-key` is also a private key that opens the operator's repos; it stops being copied too.
- **D-5 Keep the `completed` marker.** `supervisor-channels.ts:50`, `agents/messaging.ts:336`, `parked/resolver.ts:124` and `agents/resume.ts:291` still read `agents/<id>/completed` as "the work agent finished". Only its stale comment changes.
- **D-6 New review source.** `'remote-reap'` instead of reusing `'deacon-lite'`, because the manual CLI reap calls the same function and the journal must not claim deacon-lite did it.
- **D-7 Live smoke test is an operator-consented checkpoint.** It spends Fly money, flips `remote.enabled` in the operator's `~/.overdeck/config.toml` (currently `false` on this host) and opens a throwaway PR, so the work agent asks the operator before running it (WI-9). Because only the Flywheel deploys (`pan reload` builds `origin/main`), the pre-merge smoke uses the workspace's own `dist/` build for the reap, and the automatic-tick observation becomes a filed post-merge check.

1. New module:
   ```ts
   /**
    * Deacon-lite's remote reap (PAN-4295): hand finished Fly remote agents to
    * review. Restores the PAN-1676 patrol call the Cut dropped. One reap at a
    * time: a tick that fires while the previous reap is still materializing a
    * worktree is skipped, never run in parallel.
    */
   import { emitActivityEntry } from '../activity-logger.js';

   let reapInFlight = false;

   export async function reapFinishedRemoteAgents(): Promise<string[]> {
     if (reapInFlight) return [];
     reapInFlight = true;
     try {
       const { reapCompletedRemoteAgents } = await import('../remote/remote-completion.js');
       const actions: string[] = [];
       for (const r of await reapCompletedRemoteAgents()) {
         if (r.status !== 'handed-off' && r.status !== 'error') continue;
         const message = `Remote reap ${r.issueId}: ${r.status} (${r.details.join('; ')})`;
         actions.push(message);
         console.log(`[deacon-lite] ${message}`);
         emitActivityEntry({ source: 'cloister', level: r.status === 'error' ? 'warn' : 'info', message });
       }
       return actions;
     } finally {
       reapInFlight = false;
     }
   }
   ```

## Repo rules restated

- Fake timers for every retry/delay test (`vi.useFakeTimers()`, `vi.advanceTimersByTimeAsync`); never real `setTimeout` waits.
- No `execSync` in code reachable from the dashboard or deacon child.
- Quality gates: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`; never the full `npm test` on the host. `npm run typecheck` skips `*.test.ts`, so run the touched tests explicitly.
- File-size guard: shrink, never raise an allowlist row.
- Commits carry `Item: <item-id>` trailers; never `git stash`; never `git checkout` another branch in the workspace.
- Work agents never run `pan reload` or `pan restart`: the Flywheel deploys, and `pan reload` builds CI-green `origin/main`, not the workspace. New deacon-child code is live only after merge + the Flywheel's reload.

## Hazards

- The loops run in the deacon child. Fly auth there comes from `FLY_API_TOKEN` (or `remote.fly.api_token_env`) in the child's env, else `~/.fly/config.yml` via `readFlyctlConfigToken()` (`fly-api.ts:342`). `copyFromVm` shells out to `fly ssh sftp`, so `fly` must be on the child's `PATH`.
- `createWorkspace()` in the hand-off can run for minutes (worktree + install); the in-flight guard in WI-6 is what stops a second tick from repeating the hand-off.
- A concurrent manual `pan admin remote reap` and the automatic reap can both hand off the same agent. The steps are mostly idempotent (`createWorkspace` resumes, the PR adapter returns the open PR, the second `deleteVm` only warns, the review route's breaker absorbs a duplicate request). Not locked (non-goal).
- `branchExistsOnOrigin()` returns `false` on a host network error, so a finished agent can still take the "sentinel present but branch not on origin" error path during a host network blip. That path salvages (pushes from the VM) before stopping, so no work is lost; the operator recovers with `pan admin remote reap --issue <id>`.
- The remote prompt still tells the agent to run `pan task done`, and the image has no `pan` (W-FLY2 ships it). Expect that in the smoke test; it falls under the WI-9 decision rule.
