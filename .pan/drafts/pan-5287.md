## 1. Summary

S adds the shared types, store, hooks and keyboard registry that every later child of the workflow redesign uses, so no child invents its own. After S merges, the dashboard looks the same. The user-visible changes are these:

1. On Linux and Windows, switching Stage tabs moves from `⌘1..9` (which never reached the page there) to `Ctrl+Alt+1..9`, and closing a tab moves from `⌘W` to `Ctrl+Alt+W`. macOS keeps `⌘1..9` and `⌘W`.
2. `?` opens a keyboard-shortcuts sheet.
3. `N` (when focus is not in a text field, terminal or code editor) creates a new conversation in the current project on the Command Deck.
4. The `⌘N` hints on Stage tabs show only on macOS.
5. The explorer's quick open and content search answer `⌘P`/`⌘⇧F` on macOS and `Ctrl+P`/`Ctrl+Shift+F` elsewhere (before: either modifier on every platform).

## 2. Glossary

- **Stage** — the tabbed pane area, `src/dashboard/frontend/src/components/Stage/index.tsx`. Tabs are panes stored per deck in `lib/panesStore.ts`. The split layout is a binary tree (`PaneLayout`, `lib/paneLayout.ts`) saved in `localStorage` under `pan-layout:<deckKey>`.
- **Deck / deck key** — one Stage instance per project. `deckKey` is the project key (for overdeck it is `panopticon-cli`).
- **Dock** — the future right column with Files, Changes and Search tabs. Child B builds its UI. S adds only its store (`workDockStore`).
- **Explorer root id** — `project:<key>` (primary checkout, read-only), `issue:<ID>` (feature workspace), `workspace:<id>` (scratch edit workspace). Resolved server-side in `src/dashboard/server/services/explorer/roots.ts` (`resolveExplorerRoot`).
- **Code pane** — a Stage pane with `paneType: 'code'`, `explorerRootId`, `explorerPath`; opened by `openCodePane` (`components/explorer/openCodePane.ts`). A **preview** code pane (`explorerPreview: true`) is reused by the next preview open of the same root.
- **Conversation changes** — what one conversation changed: its attributed commits plus its uncommitted edits. Child A computes them; S only defines the types.
- **Needs-you item** — something a human must act on. Exactly one selector produces them (§6.5).
- **Agents working** — live agent and conversation sessions in a working state. Exactly one selector counts them (§6.6).
- **Shortcut registry** — `lib/shortcuts/registry.ts`: the one place app-level keyboard shortcuts are declared and dispatched (§6.7).
- **Capture phase / bubble phase** — a `keydown` listener added with `addEventListener('keydown', h, true)` runs while the event travels down from `window` to the focused element (capture), before the element's own handlers. One added without `true` runs on the way back up (bubble), after them. An element that calls `stopPropagation()` hides the event from later bubble listeners.
- **Not-editing focus** — focus that is not in an `input`, `textarea`, `select`, `[contenteditable]` element, not inside an xterm terminal (`.xterm`) and not inside a Monaco editor (`.monaco-editor`).
- **Platform** — `mac` when `navigator.platform` contains `Mac`, else `other` (Linux and Windows).
- **Fixture** — the shared workflow UAT fixture that `scripts/dev/seed-workflow-fixture.ts` creates (§6.8); UI children use it for their screenshots.

## 4. Decisions

Decisions inherited from the parent and restated: **D-7** (shortcuts, §6.7 below), **D-8** (needs-you, §6.5), **D-9** (agents working, §6.6), §6.1–§6.5 of the parent. Decisions made here for S:

- **S-D1 Contracts are plain TypeScript interfaces.** The parent §6.1 block is copied as-is (no Effect Schema). Child A adds schemas if its route needs decoding.
- **S-D2 `openDock` writes only the store.** No dock UI exists until child B, so `openDock` sets `open: true` and the tab; nothing renders it yet. Nothing in S calls `openDock` from a key or button, so no user can reach that invisible state.
- **S-D3 `useRootLabel` is added; `rootLabel()` stays.** The parent says "replace `rootLabel()`", but AC-S says no visible change and `explorer/__tests__/explorer-rpc.test.ts` pins `rootLabel`. S adds the hook; child B switches `ExplorerPane` to it when it moves the explorer into the dock.
- **S-D4 Selectors only; no surface switches.** `useNeedsYouItems` and `useAgentsWorking` are added with tests. No component uses them in S (children E, F, G switch).
- **S-D5 The registry uses two window listeners, not one.** The parent says "one capture-phase listener". A pure capture listener changes behavior in two places today's code depends on:
  - `components/home/useTypeToFocus.ts` (a document capture listener) lets a printable key typed on the Home page body land in the Home composer; its test (`home/__tests__/useTypeToFocus.test.tsx`, "bubbleListener" case) pins that `g` and `/` go to the composer, not to App's shortcuts. A window capture listener would run first and steal them.
  - xterm cancels (preventDefault + stopPropagation) every key it turns into terminal input (`@xterm/xterm` `CoreBrowserTerminal._keyDown` → `cancel`), so today `Ctrl+K`, `Ctrl+J`, `Ctrl+W` typed in a terminal reach the shell, not App. A capture listener would take them from the shell.
  So the registry installs a **capture** listener on `window` for `global` shortcuts and a **bubble** listener on `window` for `not-editing` shortcuts. A `global` shortcut whose event target is inside `.xterm` is skipped in capture and tried in bubble, so it runs only when the terminal did not consume the key. Monaco gets no such exception: app-level `global` keys win inside Monaco (D-7).
- **S-D6 Which D-7 keys S binds.**
  - Bound in S: Stage tab switch (`⌘1..9` mac, `Ctrl+Alt+1..9` other), close tab (`⌘W` mac, `Ctrl+Alt+W` other), terminal drawer (`⌘T` mac only; other platforms unbound because Windows and GNOME take `Super+T`), palette (`⌘K`/`Ctrl+K`), conversations palette (`⌘J`/`Ctrl+J`), search (`/`), lens chords (`g p`, `g b`, `g a`, `g c`), collapse sidebar (`[`), emergency stop (`⌘⇧.`/`Ctrl+Shift+.`), new conversation (`N`), shortcuts sheet (`?`), explorer quick open (`⌘P`/`Ctrl+P`) and content search (`⌘⇧F`/`Ctrl+Shift+F`) while focus is inside an explorer pane.
  - Not bound in S: `Ctrl+Shift+E` (Files), `Ctrl+Shift+G` (Changes), global `Ctrl+P` (Go to file), global `Ctrl+Shift+F` (dock Search). Child B binds them when the dock exists. With no explorer pane focused, `Ctrl+P` keeps the browser default, as today.
- **S-D7 `N` lives on the Command Deck in S.** The quick-create action (`handleNewConversation`, `components/CommandDeck/index.tsx`, search `const handleNewConversation = useCallback`) exists only there. S registers `N` next to it (≤12 lines). Child F moves the registration to the left column's New conversation button with the rest of the Command Deck. `N` does nothing on pages without the Command Deck.
- **S-D8 The `?` sheet yields to God View.** `GodViewConfluence.tsx` (search `event.key === 'h' || event.key === '?'`) uses `?` for its own help and skips events already `defaultPrevented`. The registry's `?` entry has `when: () => activeTab !== 'god-view'` (App's `activeTab` state).
- **S-D9 Stage tab hints show only on macOS.** `PaneBar.tsx` renders `⌘{n}` on every tab (search `⌘{index + 1}`). After D-7 that is wrong on Linux and Windows, and a `Ctrl Alt 1` chip on every tab would crowd the bar. S shows the chip only when the platform is `mac`. Child D2 removes the chips entirely.
- **S-D10 Explorer shortcuts narrow to the platform modifier.** Today `isQuickOpenKey` accepts Ctrl or Meta on every platform. Through the registry they follow D-7 (`⌘P` mac, `Ctrl+P` other). The predicates stay exported (they are pinned by tests and B may reuse them) but are no longer used by `ExplorerPane`.
- **S-D11 Seeding refuses the operator's real Overdeck home.** `seed-workflow-fixture.ts` exits with an error when `OVERDECK_HOME` is unset or resolves to `<os.homedir()>/.overdeck`. It writes the fixture conversations' Claude Code transcripts under `<home>/.claude/projects/<encoded fixture repo path>/`, where `<home>` is `--home` (default: `process.env.HOME`), because `resolveSessionFile` (`src/lib/overdeck/conversation-reads.ts`, search `export async function resolveSessionFile`) finds a Claude transcript only at `sessionFilePath(conv.cwd, sessionId)` under `os.homedir()` or by scanning that home's projects root. The encoded directory is new and unique to the fixture repo path, so writing it never touches an existing transcript.
- **S-D12 Needs-you items carry their source.** `NeedsYouItem` adds optional `subject?: PendingInputSubject` and `decision?: Decision` beyond the parent's shape, so child E can render answer controls without re-deriving them.

`openBeside` algorithm. Read the beside pane **before** calling `openCodePane`, because `openCodePane` itself calls `setActivePane` on the new pane:

```ts
const openBeside = useCallback((input: OpenBesideInput): string => {
  const beside = input.besidePaneId ?? activeId            // 1. capture first
  const id = openCodePane(deckKey, { rootId: input.rootId, path: input.path, line: input.line, preview: input.preview })
  if (layout && leafCount(layout) > 1) {                   // 2. already split
    if (!hasLeaf(layout, id)) {
      const leaves = collectLeafIds(layout)
      // A region already showing a code pane is reused before any other, so the chat keeps its region.
      const codeRegion = leaves.find((leafId) => leafId !== beside && panesById.get(leafId)?.paneType === 'code')
      const target = codeRegion ?? leaves.find((leafId) => leafId !== beside) ?? leaves[0]
      if (target) setLayout(replaceLeaf(layout, target, id))
    }
  } else if (beside && beside !== id) {                    // 3. not split: chat left, file right
    setLayout({ kind: 'split', dir: 'row', a: leaf(beside), b: leaf(id), ratio: 0.5 })
  }
  setActivePane(deckKey, id)
  return id
}, [deckKey, activeId, layout, panesById, setActivePane, setLayout])
```

Rules this encodes (the tests check each): the beside pane is never replaced; a second preview open of the same root returns the same pane id (from `openCodePane`) and therefore stays in its region; when the beside pane is itself the code pane being reused (`beside === id`), nothing splits. `panesById` is declared later in the component (search `const panesById = useMemo`); move the `openBeside` definition below it, or move `panesById` up. Do not change `openInSplit` or `revealPane`.

### 6.4 Root helper (WI-S4)

New `components/explorer/rootForConversation.ts`. Pure functions first, then one hook:

```ts
export interface RootContext {
  projects: readonly { key: string; name?: string; path: string; linearTeam?: string | null }[]   // GET /api/registered-projects
  workspaces: readonly { id: string; projectId: string; kind: 'main' | 'issue' | 'scratch'; name: string; issueId: string | null }[]  // GET /api/workspace-registry
}
export function rootIdForConversation(
  conv: { cwd?: string | null; issueId?: string | null; workspaceId?: string | null; origin?: string | null },
  ctx: RootContext,
): string | null
```

Rules, in order (first match wins):
1. `conv.origin === 'linked'` → `null` (the explorer reads this machine's disk; the conversation runs on another machine).
2. `conv.issueId` → `issue:<conv.issueId upper-cased>`.
3. `conv.workspaceId` names a row in `ctx.workspaces`: `kind 'scratch'` → `workspace:<id>`; `kind 'main'` → `project:<row.projectId>`; `kind 'issue'` with `issueId` → `issue:<issueId upper-cased>`.
4. `conv.cwd` is inside a project's workspaces folder, `<project.path>/workspaces/feature-<slug>` or below → `issue:<slug upper-cased>`. Any other path under `<project.path>/workspaces/` → `null`.
5. `conv.cwd` equals a project's `path` or starts with `path + '/'` → `project:<key>`. When several projects match, the longest `path` wins.
6. Otherwise → `null`.

Rule 4 exists because a feature workspace lives inside the project folder (`/home/u/Projects/overdeck/workspaces/feature-pan-5287` is inside `/home/u/Projects/overdeck`). Without it, rule 5 would show the main checkout for a conversation working in a feature workspace. Strip trailing `/` from paths before comparing.

```ts
export function rootLabelFor(rootId: string, ctx: RootContext & { issueTitles: ReadonlyMap<string, string> }): string
```
- `project:<key>` → the project's `name`, else its `key`, but never `panopticon-cli` when a `name` exists. (Overdeck's project has key `panopticon-cli`, name `overdeck`.)
- `issue:<ID>` → `<ID> · <title truncated to 40 chars with …>` when the title is known, else `<ID>`.
- `workspace:<id>` → the registry row's `name`; when the row is missing, `Edit workspace` (never the raw id).
- an unparseable id → the id as given.

#### Key specs (`keys.ts`)
A spec is a string. Modifiers `Meta`, `Ctrl`, `Alt`, `Shift` joined by `+` before one key, for example `Meta+K`, `Ctrl+Alt+1`, `Ctrl+Shift+.`, `N`, `?`, `/`, `[`. A two-step chord is two specs separated by one space: `G P`.

```ts
export type Platform = 'mac' | 'other'
export function currentPlatform(): Platform   // navigator.platform includes 'Mac' → 'mac'; read on every call so tests can stub it
export interface ShortcutKeys { mac: string | null; other: string | null }   // null = unbound on that platform
export function matchesSpec(event: KeyboardEvent, spec: string): boolean
export function formatSpec(spec: string, platform: Platform): string
```

`matchesSpec` for one step: every modifier named must be pressed and every modifier not named must not be pressed (`metaKey`, `ctrlKey`, `altKey`, `shiftKey`), with one exception: for the keys `?`, `>` and other characters that need Shift on a US layout, `shiftKey` is ignored. Key comparison: a letter compares `event.key.toLowerCase()` with the letter or `event.code === 'Key<LETTER>'` (Alt changes `event.key` on macOS); a digit compares `event.key` or `event.code === 'Digit<d>'`; `.` matches `event.code === 'Period'` or `event.key` `.` or `>`; any other key compares `event.key` exactly.

`formatSpec`: mac uses `⌘ ⌃ ⌥ ⇧` with no separators (`⌘⇧.`); other uses words joined by spaces (`Ctrl Shift .`), matching the mockup's keycaps (`Ctrl Shift E`). Letters print upper-case. A chord prints as `G then P`.

#### Registration (`registry.ts`)

```ts
export type ShortcutScope = 'global' | 'not-editing'
export interface ShortcutDef {
  id: string                        // unique per meaning, e.g. 'stage.close-tab'
  keys: ShortcutKeys
  scope: ShortcutScope
  label: string                     // shown in the ? sheet
  group: 'General' | 'Navigation' | 'Tabs' | 'Files' | 'Safety'
  run(event: KeyboardEvent): void
  /** Extra condition evaluated at dispatch; false lets the event pass untouched. */
  when?: () => boolean
  /** Hidden from the ? sheet (e.g. one of nine 'focus tab N' entries after the first). */
  hidden?: boolean
}
export function registerShortcut(def: ShortcutDef): () => void   // returns unregister
export function useShortcut(def: ShortcutDef | null): void        // registers in an effect; re-registers when def identity changes; null = none
export function installShortcutListener(target?: Window): () => void
export function useShortcutList(): readonly ShortcutDef[]         // useSyncExternalStore over the registrations, for the sheet
export function resetShortcutsForTests(): void
```

Dispatch rules (the registry test pins each):
1. `installShortcutListener` adds exactly two listeners to `window`: `keydown` capture and `keydown` bubble. Calling it twice without the returned uninstall is a no-op the second time.
2. The **focus element** is `event.target` when it is an `Element`, else `document.activeElement`. (Tests dispatch on `window` and `document`.)
3. **Capture listener:** consider `global` shortcuts only, and skip the event entirely when the focus element is inside `.xterm`.
4. **Bubble listener:** consider `not-editing` shortcuts when the focus is not-editing (§2), plus `global` shortcuts when the focus element is inside `.xterm` (the terminal did not cancel the key, or the bubble listener would not see it). Skip events with `event.defaultPrevented === true` (another handler already claimed them) and events with `event.isComposing`.
5. Within a phase, registrations are tried newest first. The first one whose key spec for the current platform matches and whose `when()` is not false runs: the registry calls `preventDefault()` and `stopPropagation()`, then `run(event)`. If none matches, the event is untouched.
6. **Chords.** A `not-editing` registration whose spec is `X Y` arms on `X`: the registry calls `preventDefault()`, remembers `X` for 1500 ms (`CHORD_TIMEOUT_MS`), and the next keydown either completes a chord starting with `X` (that shortcut runs) or cancels the pending chord and is then dispatched normally. (Today's code returns after an unbound second key without dispatching it; keep that: an unbound second key is consumed by the cancel, as `App.test.tsx` "cancels the chord on an unbound second key" pins — read that test and keep it green.)
7. `when()` that throws is treated as false.
