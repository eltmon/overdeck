# PAN-5364: Merge train board shows the merge as the outcome, folds voided rebuilds, and ages out old batches

**Issue:** [PAN-5364](https://github.com/eltmon/overdeck/issues/5364)
**Base checked:** `feature/pan-5364` at `52e312dd0df` (main content identical to `origin/main` `08d4912194c` for every file named here).

## 1. Problem

On the `overdeck` merge train card, after batch `uat/pan-train-moss-1115-11` merged to main, the
card shows no hero batch. All ten stored batches render as "Older batch" rows, newest first by
creation time: `-12` voided, `-11` merged, `-10` … `-3` voided. `-12` is a rebuild of the exact
members that merged, voided only because its sibling `-11` merged. The card lists it first, so it
reads as if the work did not land. Voided batches also never leave the board: the payload is the
newest 10 rows of the chain with no age or status filter, so a quiet project shows a voided batch
from weeks ago, and a churn burst can push the merged batch out of the 10 entirely.

The rebuild churn itself (ten batches in 25 minutes) is PAN-5356 / PAN-5357 and is out of scope.
This issue changes only how the board selects and presents the chain.

## 2. Glossary

| Term | Meaning |
| --- | --- |
| **Batch / generation** | One row of `uat_generations`: a `uat/<label>-<codename>-<MMDD>-<n>` branch merging several ready features. Payload type `UatGenerationPayload`. |
| **Chain** | All generations of one project, newest `created_at` first (`listUatGenerations`, `src/lib/overdeck/merge-sync-uat.ts`, `ORDER BY created_at DESC, name DESC`). |
| **Live batch** | Status `assembling`, `ready` or `superseded`. |
| **Voided** | Status `invalidated`. UI label "voided". |
| **Merged** | Status `promoted`. |
| **Live hero** | The batch `pickHeroBatch` returns today: newest `assembling`/`ready`, else newest `superseded`, else null. Unchanged by this issue. |
| **Outcome hero** | NEW. A `promoted` batch shown in the hero slot when there is no live hero and nothing happened in the chain after its merge (rule in FR-4). |
| **Merge time** (`mergedAt`) | NEW derived value: the latest non-null `repos[].promotedAt` of a promoted batch; falls back to `updatedAt` when no repo carries one. |
| **voidedBy** | NEW structured field: the name of the batch whose promote voided this batch. Written only by the promote void loop. |
| **Folded rebuild** | A voided batch whose `voidedBy` equals the outcome hero's name. Not shown as an older row; listed in one line under the outcome hero. |
| **Covered voided batch** | A voided batch (status `invalidated`) whose member set is a non-empty subset of some promoted batch P's member set, where `mergedAt(P) >= createdAt(this batch)`. Every feature it carried merged later. Hidden behind a "show" toggle. |
| **Identical run** | Two or more consecutive voided rows (in chain order, after folding and hiding) whose member sets are equal. Rendered as one row. |
| **Board payload** | `GET /api/merge-train/board` → `BoardProject.batches`, built by `getUatGenerationsPayload` via `merge-train-board.ts` deps. |

## 4. Requirements

### Functional

- **FR-1** Promote records the merged batch's name on every sibling it voids, in a new `voidedBy` field (`uat_generations.voided_by` column), in the same store update that sets `status: 'invalidated'` and the existing reason string. The reason string is unchanged.
- **FR-2** `voidedBy` reads back from the store (null when the column is null or absent) and is carried in `UatGenerationPayload.voidedBy` — the value when `status === 'invalidated'`, else `null` — on both the server type and `boardTypes.ts`.
- **FR-3** The board payload (only the board; `/api/merge-train/generations` is unchanged) drops `invalidated` batches whose `updatedAt` is older than 24 hours and `promoted` batches whose merge time is older than 24 hours; drops a `failed` batch whose `updatedAt` is older than 24 hours unless it is the newest row (index 0) of the scanned chain; keeps `assembling`, `ready` and `superseded` batches regardless of age; returns at most 10 batches, newest first; and always includes the newest promoted batch that survived the age filter, even when ten newer batches exist. (The failed rule keeps today's Retry semantics: an old failure behind newer, aged-out rows must not become `batches[0]` and re-offer Retry.)
- **FR-4** The card shows an outcome hero when, and only when: `pickHeroBatch` returns null; the chain has a promoted batch; P is the promoted batch with the latest merge time; and no other batch was **created** after `mergedAt(P)`, except voided batches whose non-empty member set is a subset of P's (a rebuild of already-merged members assembled just after the merge and then voided). Creation time is used, not `updatedAt`, because `updated_at` also moves on stack start/stop (`setUatGenerationStackStartedAt`, `merge-sync-uat.ts` line ~607) and on the probe's stale-record heal, which can touch unrelated batches after a merge.
- **FR-5** The outcome hero renders in the hero slot (`data-testid="hero-batch-<projectKey>"`, `data-outcome="true"`) with an outcome line: `merged to <targetBranch> · <sha7> · <ago>` for one repo, `merged · <repoKey>@<sha7> · <repoKey>@<sha7> · <ago>` for several repos, and `merged to main · <ago>` when no merge SHA is stored. The batch card's status badge for a promoted batch reads `merged` with tone `success` when the project has no version sync configured (`versionSyncConfigured !== true`). With version sync configured, the badge is unchanged.
- **FR-6** Batches with `voidedBy === outcome.name` are not older rows. One line under the outcome hero names them: `<n> rebuild(s) voided when this merged: <shortName>, <shortName>` (chain order), with a **show** button that expands each one as an `OlderBatchRow`.
- **FR-7** Covered voided batches are not shown as older rows. One line after the older rows, `<n> voided batch(es) whose features all merged later`, has a **show** / **hide** toggle that renders them (with identical-run collapsing, FR-8) below the line.
- **FR-8** In the visible older rows, an identical run (2+ consecutive voided batches with equal member sets) renders as one row: `<n> rebuilds voided, <oldest shortName> to <newest shortName>, same members`, with a **show** button that expands each batch as its own `OlderBatchRow`.
- **FR-9** The older list shows at most 3 rows (a run counts as one row). Rows past the third are hidden behind `show <n> more` / `show fewer`. A single `failed` batch row is never hidden by this cap.
- **FR-10** Precedence is fixed: (1) live hero, else outcome hero; (2) remove the hero/outcome from the older list; (3) remove folded rebuilds (FR-6); (4) remove covered voided batches (FR-7); (5) collapse identical runs (FR-8); (6) apply the 3-row cap (FR-9). Superseded and failed batches are never folded, hidden as covered, or collapsed.
- **FR-11** Retry batch assembly keeps its current rule: it is keyed on the live hero (`!hero`), never on the outcome hero. With a promoted batch and a newer failed batch, there is no outcome hero and Retry batch assembly is offered.

### Non-functional

- **NFR-1** No generation row is ever deleted or rewritten by the board; age-out is a read-time filter. The database keeps the full audit trail.
- **NFR-2** The board's frontend grouping is a pure module with no React, so its rules are unit-tested without rendering.
- **NFR-3** No file grows past its file-size allowance (`scripts/lint-file-size.sh`: ceiling 1000 lines, or the file's `origin/main` count when larger). `infra.ts` (980) gains exactly one top-up line plus at most one comment line; the board chain selection lives in a new module, not in `uat-train.ts`.
- **NFR-4** Time-dependent tests inject `now` (a parameter), never real wall-clock time and never `setTimeout` (repo rule: fake timers for delay-based tests; here a parameter is enough).
- **NFR-5** No `execSync` or new sync child-process calls in dashboard server code (repo rule). The changes here are pure functions plus one existing SQLite accessor.

## 5. Decisions (made here; the executor does not re-decide)

- **D1 No backfill.** Rows voided before this change have `voided_by = NULL`. They are never parsed from the reason string. On the live board they are handled by the covered rule (FR-7) and by FR-4's covered exclusion, and they age out after 24 hours (FR-3).
- **D2 Age-out is in the board payload only**, 24 hours, measured from `updatedAt` for `invalidated` (the void time; cleanup-only patches do not move `updated_at`) and from merge time for `promoted`, and from `updatedAt` for `failed` except the newest row. A stack start/stop or stale-record heal can move a voided batch's `updated_at` and keep it a little longer; that is accepted. The outcome hero expires with it; the "Last merged" strip (`RecentMergesStrip`, fed by a separate promoted listing) is unaffected.
- **D3 Selection scans 50 rows** (`BOARD_SCAN_LIMIT = 50`) and then applies FR-3, so age-out frees slots for newer rows and the newest promoted batch can be appended. The appended promoted batch is older than every other selected row by `created_at`, so appending at the end keeps newest-first order.
- **D4 This reverses PAN-4753 FR-7 ("none is hidden").** Superseded batches stay always visible (they are promotable). Only voided batches can be folded, hidden as covered, or collapsed, and every one stays reachable through a **show** control.
- **D5 Copy uses `shortName`** (strips only `uat/`), so names read `pan-train-moss-1115-12`, matching the existing older rows.
- **D6 Badge fix is narrow.** Only the promoted badge for projects without version sync changes (`merged`, success tone). It is needed because the outcome hero would otherwise show "merged · version not shipped" in warning tone on every project, since the server always sends `shipStatus: null`.
- **D7 Member-set comparison** uses upper-cased `issueId`s; an empty member set is never "covered" and never part of an identical run.

   ```ts
   /**
    * Which generations the merge-train board shows (PAN-5364). Pure: the chain
    * arrives newest first; rows are never deleted, only left out of the payload.
    */
   export const BOARD_SCAN_LIMIT = 50;
   export const BOARD_CHAIN_LIMIT = 10;
   export const BOARD_TERMINAL_MAX_AGE_MS = 24 * 60 * 60 * 1000;

   /** Latest repo promote stamp of a promoted generation, else its updatedAt. */
   export function generationMergedAt(gen: UatGeneration): string { … }

   export function selectBoardChain(chain: readonly UatGeneration[], now: number): UatGeneration[] {
     const cutoff = now - BOARD_TERMINAL_MAX_AGE_MS;
     const fresh = chain.filter((g, index) => {
       if (g.status === 'invalidated') return Date.parse(g.updatedAt) >= cutoff;
       if (g.status === 'promoted') return Date.parse(generationMergedAt(g)) >= cutoff;
       if (g.status === 'failed') return index === 0 || Date.parse(g.updatedAt) >= cutoff;
       return true;
     });
     const selected = fresh.slice(0, BOARD_CHAIN_LIMIT);
     const newestPromoted = fresh
       .filter((g) => g.status === 'promoted')
       .sort((a, b) => Date.parse(generationMergedAt(b)) - Date.parse(generationMergedAt(a)))[0];
     if (newestPromoted && !selected.includes(newestPromoted)) selected.push(newestPromoted);
     return selected;
   }
   ```
