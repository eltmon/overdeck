# PAN-5339 — Conversation messages: make references to other conversations clickable

**Issue:** [PAN-5339](https://github.com/eltmon/overdeck/issues/5339)
**Planned against:** `c9906c2370a` (main, 2026-11-15)

## Glossary

- **Conversation reference** — text in a rendered message that names another conversation, in one of
  the forms of FR-1: a *name form* (`20261113-6031`, `conv-20261113-6031`), a *numbered form*
  (`conv 3904`, `conversation 3904`, `conv #3904`), or a *path form* (`/conv/3904`,
  `/conv/20261113-6031`, `https://<dashboard host>/conv/3904`).
- **Conversation name** — the `conversations.name` column (`overdeck.db`). Two generators exist:
  `generateConversationName` (`src/lib/overdeck/conversation-runtime.ts:315`) makes
  `YYYYMMDD-NNNN` with four decimal digits; summary forks (`src/lib/overdeck/conversation-forks.ts:834`)
  and vault continues (`src/lib/overdeck/conversation-vault-continue.ts:44`) make
  `YYYYMMDD-<4 lowercase hex>` from `randomUUID().slice(0, 4)`. On this machine 1739 of 3905 names
  match `\d{8}-[0-9a-f]{4}`; 1331 of those have an all-digit suffix and about 400 carry a letter
  (`20260824-343d`), so the name pattern is `\d{8}-[0-9a-f]{4}`. The tmux session is `conv-<name>`, which is why agents write `conv-…`.
- **Conversation id / route key** — the numeric SQLite `rowid`, exposed as `Conversation.id` in the
  list API and used in `/conv/<id>` URLs (`conversationRouteKey`,
  `src/dashboard/frontend/src/lib/linkedConversation.ts`). Linked (other-machine) rows use their
  `@<env>/<name>` name as route key; they are out of scope (NonGoal).
- **Reference key** — the normalized lookup key for a reference: the decimal id (`"3904"`) for the
  numbered and numeric-path forms, the bare name without `conv-` (`"20261113-6031"`) for the name
  forms. The two never collide: ids have no dash, names always have one.
- **Resolved reference** — a reference key the dashboard maps to a real conversation row (archived
  rows included). Only resolved references render as links (FR-3).
- **Transcript context** — `ConversationPullRequestContext` in
  `src/dashboard/frontend/src/components/chat/TranscriptPullRequestLink.tsx:30`, provided by
  `ConversationPanel` (`ConversationPanel.tsx:497`) around every rendered conversation transcript. It
  carries `conversationName`, the conversation being viewed. Its presence is the gate for this feature.
- **Opener** — the one in-app "open this conversation" callback, the one the left column's rows use:
  `useOpenConversation` (`src/dashboard/frontend/src/components/frame/deck/useOpenConversation.ts`).
- **Deck navigation** — `DeckNavigationContext` (`components/frame/deck/deckNavigation.tsx:73`),
  provided only by `App.tsx:792`. `useDeckNavigation()` throws outside it.

## Problem

An agent wrote "Conversation `20261113-6031` owns it … Tell `20261113-6031` your tweaks". Both
mentions render as inline code and the operator cannot click them. `ChatMarkdown.tsx` turns file
paths into file chips (`remarkBareFileTextLinks`, `ChatMarkdown.tsx:338`) and tracker / PR URLs into
rich links (`TranscriptLink`, `TranscriptPullRequestLink.tsx:43`); nothing recognises a
conversation reference.

## Requirements

- **FR-1** Inside a transcript context, these render as a link to the conversation when resolved:
  `conv-20261113-6031`, `20261113-6031` (and hex suffixes such as `20260824-343d`); `conv 3904`,
  `conversation 3904`, `conv #3904` (case-insensitive word); `/conv/3904`, `/conv/20261113-6031`;
  `https://<dashboard host>/conv/3904` (GFM autolink or Markdown link).
- **FR-2** A reference links when written as plain text, and when an inline code span's whole trimmed
  value is one reference; the code keeps its monospace `<code>` element inside the `<a>`. Text inside
  a fenced or indented code block never links.
- **FR-3** A reference links only when it resolves to a known conversation (listed or archived).
  Until resolved, and when it never resolves, it renders as the original text or code.
- **FR-4** A plain left click opens the conversation in the dashboard through the same opener the
  left column uses, without reload or `window.open`. Ctrl/Cmd/Shift/Alt-click and middle-click keep
  the browser's new-tab behaviour on the `/conv/<id>` href.
- **FR-5** The link's `title` is the conversation title, or its name when the title is null.
- **FR-6** A generated reference to the conversation being viewed is not a link.
- **FR-7** A hand-written Markdown link to a `/conv/…` URL (relative or dashboard host) whose key
  resolves gets the same in-dashboard click and tooltip. Unresolved hand-written links keep today's
  plain new-tab anchor.
- **FR-8** Outside a transcript context (PRD viewer, dialogs, activity feed), ChatMarkdown output is
  unchanged. In a transcript rendered without deck navigation (pop-out windows, `/m`, the issue
  drawer), a resolved reference is still a link, but a plain click opens `/conv/<id>` in a new tab.
- **NFR-1** No new HTTP route and no second Markdown pipeline: one extra remark plugin in the existing
  `remarkPlugins` array and the existing `a` component.
- **NFR-2** A message with no candidate keys does no lookups and does not re-render when the
  `['conversations']` list refetches (the list observer uses `select` returning a stable empty map).
- **NFR-3** At most 20 distinct reference keys per ChatMarkdown instance are looked up; further keys
  stay text. Each unlisted key is fetched at most once per 5 minutes (`staleTime`), with
  `retry: false`; a 404 caches as "unknown".
- **NFR-4** Both renderers (ReactMarkdown and Streamdown) produce the same links; tests cover both.

## Decisions

- **D1 (resolution source).** Listed conversations resolve from the `['conversations']` query (shared
  cache, `select` per instance). Keys missing from the settled list are fetched with
  `GET /api/conversations/<key>` under the query key `['conversation-reference', key]` (not
  `['conversation', key]`, which `usePriorityConversation` owns with `retry: 5` and throw-on-404).
  The query function returns `null` on 404 and throws on other errors.
- **D2 (text until resolved).** The issue's checkpoint suggests rendering a title-less link until
  resolved; FR-3 and its test ("an unknown one renders text") win. A reference is text until its key
  resolves, as `MaybeFileLinkChip` does for file chips.
- **D3 (no marker).** ChatMarkdown resolves keys *before* the remark plugin runs and passes the
  resolved map to the plugin and to `makeComponents`. The plugin only creates links for resolved
  keys, so no generated link is ever unresolved and no `data-*` marker has to survive Streamdown's
  sanitizer. The `a` component handles generated and hand-written `/conv/` links the same way.
- **D4 (gate).** `ChatMarkdown` reads the transcript context through a new exported hook
  `useTranscriptConversation()` in `TranscriptPullRequestLink.tsx`. With context it renders an inner
  component that calls the resolution hook; without it renders the body with an empty map. The
  context never changes during a message's life, so the branch never remounts the body. Tool rows
  inside a transcript (work-log rows) are inside the context and also link; NFR-3 bounds their cost.
- **D5 (inline code).** Only a whole-value inline code span links (`` `20261113-6031` `` or
  `` `conv-20261113-6031` ``). A span such as `` `pan tell 20261113-6031 "x"` `` stays plain code.
  The plugin wraps the `inlineCode` node: `{ type: 'link', url, children: [inlineCodeNode] }`, which
  both renderers render as `<a><code>…</code></a>`. No `code` component is added.
- **D6 (link text).** The numbered form links the whole phrase (`conv 3904`), not only the number.
- **D7 (dashboard host).** An absolute `http(s)` URL is a conversation reference when its path is
  `/conv/<key>` and either its origin equals `window.location.origin`, or both its hostname and
  `window.location.hostname` are loopback (`localhost`, `127.0.0.1`, `::1`, or ending in
  `.localhost`, which covers `overdeck.localhost`). Numeric ids are machine-local, so any other host
  stays a plain link.
- **D8 (opener).** `useOpenConversation`'s callback accepts `string | Conversation | null`. Given an
  object it uses the list row with that name if present, else the object itself, so an archived
  conversation resolves its project from its own `projectKey`/`cwd` and `openInDeck` writes
  `/conv/<id>`. A new `ConversationLinkOpenerProvider` calls `useOpenConversation(null)` once and
  provides the callback through a nullable `ConversationLinkOpenerContext`; it is mounted in
  `App.tsx` inside `DeckNavigationProvider`. Links read the nullable context; `null` ⇒ FR-8 fallback.
- **D9 (current conversation).** The resolved map marks `isCurrent` when the row's `name` equals the
  transcript context's `conversationName`. The plugin skips `isCurrent` refs (FR-6). A hand-written
  link to the current conversation still renders as an in-app link (the agent chose to link it).
- **D10 (candidate scan).** `collectConversationReferenceKeys(markdown)` scans the raw Markdown with
  fenced blocks (```` ``` ```` and `~~~`) removed, using the strict patterns plus a loose
  `/conv/<key>` pattern for link destinations and URLs. Dedupe, keep first 20 (NFR-3).
- **D11 (patterns).** In `lib/conversationReferences.ts`:
  - name: `/(?<![\w/.-])(conv-)?(\d{8}-[0-9a-f]{4})(?![\w-]|[./]\w)/g` — rejects UUIDs
    (`12345678-1234-…`), `20260706-3577-post-clear-78e2e542`, `2026-11-13`, shas, and names inside
    file paths (`conv-20261113-6031/state.json`, `20261113-6031.md`) so file chips keep working.
    A trailing sentence period (`… 20261113-6031.`) still matches.
  - numbered: `/\b(?:conversation|conv)[ \t]+#?(\d{1,7})(?![\w-])/gi`.
  - path: `/(?<![\w.:/-])\/conv\/(\d{1,9}|\d{8}-[0-9a-f]{4})(?![\w/-]|\.\w)/g`.
  A combined splitter applies them left to right, earliest match wins, no overlaps.
- **D12 (fetch helper).** The resolution hook imports `fetchConversations` and `type Conversation`
  from `components/CommandDeck/ConversationList` (as `WorkspaceView.tsx` and `AgentsMenu.tsx` do).
  **Implementation checkpoint:** if `npm run lint:circular` reports a new cycle, define a local
  `fetch('/api/conversations')` query function in the hook module instead (same JSON shape) and
  import only the type.

### WI-5 Conversation link component — FR-4, FR-5, FR-8

New file `components/chat/ConversationReferenceLink.tsx`:

```tsx
export function ConversationReferenceLink({ conversationRef, className, children }: { conversationRef: ConversationRef; className?: string; children: ReactNode }) {
  const open = useConversationLinkOpener();
  const href = `/conv/${conversationRef.routeKey}`;
  const onClick = (event: MouseEvent<HTMLAnchorElement>) => {
    if (!open || event.defaultPrevented || event.button !== 0
      || event.metaKey || event.ctrlKey || event.shiftKey || event.altKey) return;
    event.preventDefault();
    open(conversationRef.conversation);
  };
  return <a href={href} target="_blank" rel="noopener noreferrer" className={className}
    title={conversationRef.title ?? conversationRef.name} data-conversation-id={conversationRef.routeKey} onClick={onClick}>{children}</a>;
}
```

  `20260706-3577-post-clear-…`) are not recognised.
- A linked conversation's own transcript links nothing (its ids belong to the owner machine).
- Host-less text such as `overdeck.localhost/conv/3904` (no scheme) is not linked.
- Inline code spans containing a reference plus other text are not split.
- No new server route, no server changes, no change to `usePriorityConversation`.
- Messages over 50,000 characters (`LARGE_MESSAGE_CHARS`) render as plain text and never link.
- ChatMarkdown outside a transcript (PRD viewer, plan/AUQ dialogs, activity feed) is unchanged.
- No hover prefetch or title-less optimistic links.
