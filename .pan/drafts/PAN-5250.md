# PAN-5250: Idle workspace frontend and dev containers stop after 20 minutes unused, and restart on demand

**Issue:** [PAN-5250](https://github.com/eltmon/overdeck/issues/5250) (split from [PAN-5248](https://github.com/eltmon/overdeck/issues/5248))
**Builds on:** [PAN-5623](https://github.com/eltmon/overdeck/issues/5623) (merged at `334886c013a`): label-scoped container listing, the `stack.reclaimed` / `stack.restored` journal entries, the per-workspace stack lock and the restore door. This issue reuses all of them.
**Sibling (split during planning):** [PAN-5649](https://github.com/eltmon/overdeck/issues/5649): opening a stopped workspace's app URL starts it again (Traefik fallback wake page and a dashboard "start app" action). See D1.
**Related:** [PAN-3050](https://github.com/eltmon/overdeck/issues/3050) (the old idle-stack reaper's naming coverage; its full-stack tier never matches).

## Glossary

- **Workspace stack.** The Docker Compose containers of one issue workspace. They all carry the label `com.docker.compose.project=<compose project>`. The compose project comes only from `tryComposeProjectNameForWorkspace(workspacePath, issueId)` (`src/lib/workspace/stack-health.ts:180`, grep `export function tryComposeProjectNameForWorkspace(`).
- **Service.** A container's `com.docker.compose.service` label, for example `frontend`, `fe`, `dev`, `server`, `api`, `postgres`.
- **Idle-stop services.** The services this feature may stop. Per project, from `workspace.docker.idle_stop.services` in `~/.overdeck/projects.yaml`. Default `['frontend', 'fe', 'dev']`.
- **Idle-stop minutes.** Per project, `workspace.docker.idle_stop.minutes`. Default `20`. `0` disables the idle stop for that project.
- **Target containers.** The **running** containers whose compose project label equals the workspace's compose project and whose service is an idle-stop service.
- **In use.** A workspace is in use when any rule in FR-3 holds. A live `work` agent pane does not make a workspace in use.
- **Idle clock.** In-memory map, upper-case issue id → epoch ms when the service first saw the workspace not in use. Cleared when the workspace is in use or has no target containers.
- **Idle stop.** Overdeck stops the target containers of one workspace whose idle clock has run for at least the idle-stop minutes. It journals a `stack.reclaimed` entry with `data.reason: 'idle'`.
- **Memory reclaim.** PAN-5623's stop of a parked issue's `api`/`fe`/`frontend`/`server` containers while the gate admission queue is starved. Its `stack.reclaimed` entries carry `data.reason: 'gate-starvation'`.
- **Reclaim reason.** `data.reason` of a `stack.reclaimed` entry: `'idle'` or `'gate-starvation'`. An entry with no `reason` (written before this issue) reads as `'gate-starvation'`.
- **Open reclaim.** All `stack.reclaimed` entries after the newest `stack.restored` entry in an issue's pipeline journal (`<workspace>/.overdeck/pipeline.jsonl`). Its container list is the union of their names. Changed by WI-1; PAN-5623 read only the newest entry.
- **Restore door.** `restoreReclaimedStack({ issueId, workspacePath, trigger })` in `src/lib/workspace/stack-restore.ts:120`. It starts exactly the containers of the open reclaim, then journals `stack.restored`.
- **Wake.** New in WI-4: `wakeWorkspaceStack({ issueId, workspacePath?, trigger })`. It runs the restore door, then starts any other **exited** container of the workspace's compose project whose service is restorable. `pan workspace up` uses it.
- **Restorable container (restore door).** A container of the open reclaim whose listed compose project equals the workspace's, and whose service is in `RECLAIMABLE_STACK_SERVICES` (`api`, `fe`, `frontend`, `server`; `src/lib/workspace/stack-reclaim-docker.ts`) or equals the service the reclaim entry **recorded** for that container name (`data.services[i]` paired with `data.containers[i]`). The current idle-stop config plays no part, so changing or emptying it never strands a stopped container.
- **Wakeable service (wake).** A service in `RECLAIMABLE_STACK_SERVICES`, in `DEFAULT_IDLE_STOP_SERVICES`, or in the project's configured idle-stop services.
- **Stack lock.** `<workspace>/.overdeck/stack-reclaim.lock`, taken with `withStackLock` (`stack-restore.ts`, grep `export async function withStackLock`). Every stop sequence and every restore runs inside it.
- **Pin.** The file `<workspace>/.overdeck/stack-pin.json`. While it exists, neither the idle stop nor the memory reclaim stops that workspace's containers. Written by `pan workspace pin`, removed by `pan workspace unpin`.
- **Exec session.** A process started in a container with `docker exec` (VS Code attach, a container quality gate, an agent's `docker exec`). `docker inspect --format '{{len .ExecIDs}}'` counts the running ones (verified on this host 2026-11-23: `0` at rest, `1` while `docker exec -d <c> sleep 20` ran).
- **Inbound connection.** A TCP connection in state `ESTABLISHED` (`01`) in the container's `/proc/<pid>/net/tcp` or `tcp6` whose local port is also a port the container listens on (state `0A`), and whose remote address is not loopback. A browser tab with the app open holds one (the Vite HMR WebSocket through Traefik).
- **Primary dashboard.** The dashboard process with `!isPeerDashboard` in `src/dashboard/server/main.ts`. The PAN-5623 service starts only there (`main.ts:297`, grep `startStackReclaimService(); // PAN-5623`).

## Problem

On 2026-11-14 seven workspace Vite containers ran with no viewer, about 1.3 GB each (9.1 GB in total). Two had run for two hours. The host has 62 GB of RAM and runs a live stream that needs MemAvailable at or above 8 GiB.

Two stoppers exist today, and neither covers this case:

- `src/lib/cloister/idle-stack-reaper.ts` stops `server` and `frontend` only when **no** live agent pane exists for the issue (10-minute grace), matches containers by name pattern, and never stops `dev`. While an agent lives, its frontend runs forever.
- PAN-5623's memory reclaim acts only while the gate admission queue is starved and only on parked issues.

Nothing restarts a stopped frontend except a spawn (spawn gate, PAN-5623 D10) or a verification start (PAN-5623 D11), and only when a memory reclaim stopped it.

## Requirements

### Functional

- **FR-1 Configuration.** `workspace.docker.idle_stop` in a project's `projects.yaml` entry: `{ minutes?: number; services?: string[] }`. Defaults: `minutes: 20`, `services: ['frontend', 'fe', 'dev']`. `minutes: 0`, an empty `services`, or the environment variable `OVERDECK_DISABLE_STACK_IDLE_STOP=1` disables the idle stop. A `minutes` that is not a finite number ≥ 0 falls back to 20. A service name that fails `/^[A-Za-z0-9][A-Za-z0-9_.-]*$/` is dropped.
- **FR-2 Candidates.** A workspace is an idle-stop candidate only when all hold: its workspace row is not `kind: 'main'` and has an `issueId`; its path exists; its issue resolves to a registered project; the idle stop is enabled for that project (FR-1); `tryComposeProjectNameForWorkspace` returns a name; and at least one target container exists. Containers are matched only by the exact compose project label and service label, never by name pattern.
- **FR-3 In use.** A candidate is in use when any of these holds. Each rule names its reason string:
  1. `browser`: a target container has at least one inbound connection.
  2. `exec-session`: a target container has at least one exec session.
  3. `test-agent`: a live pane for the issue (`issuePanes`, `src/lib/workspace/stack-reclaim.ts`) has role `test` or `uat`.
  4. `verification`: `isVerificationWorkerActive(issueId)` is true or `readVerificationDispatchOwed(issueId) !== null` (`src/lib/cloister/verification-worker-supervisor.ts`).
  5. `gate-queue`: a gate-queue owner or waiter belongs to the issue (`issueInGateQueue`, `stack-reclaim.ts`).
  6. `pinned`: the pin file exists (a pin file that cannot be parsed still counts as pinned).
  7. `probe-unknown`: the usage probe could not read a target container (deny by default, NFR-3).
  A live `work`, `review`, `plan`, `worker`, `strike` or `conversation` pane does **not** make a workspace in use.
- **FR-4 Idle clock.** The service polls every 60 s (`STACK_IDLE_POLL_MS = 60_000`). In use → clear the clock. Not in use and no clock → set it to now. Not in use and `now - clock ≥ minutes × 60_000` → stop (FR-5). A candidate with no target containers clears its clock. The clock is in memory, so a dashboard restart starts every clock again (the conservative direction).
- **FR-5 Stop sequence.** Inside the stack lock (`withStackLock`, timeout 5 s; a busy lock skips the issue this poll): re-list running containers fresh; every target must still exist with the same id, state `running`, the same compose project and an idle-stop service; re-evaluate FR-3 from fresh reads (pins, panes, verification, gate queue, usage probe); read target memory with `readContainerMemoryBytes` (unreadable → skip this poll). Then append `stack.reclaimed` with `data: { containers, containerIds, services, composeProject, memoryBytes, reason: 'idle', idleMs }`, read the journal back and continue only when the newest reclaim entry has the same `at` and the same containers; then `docker stop <id>` each target (`stopContainer`); then emit one activity entry (FR-6). It never stops a container outside the workspace's compose project or a service outside the idle-stop services.
- **FR-6 Activity feed.** One entry per idle stop: `emitActivityEntry({ source: 'cloister', level: 'info', issueId, message: 'stack-idle-stopped: <ISSUE>', details })` with `details` = `Stopped <names joined ", "> after <M> min unused, freeing <X.X> GiB. They start again when a test or UAT agent is spawned for <ISSUE>, its verification starts, or you run: pan workspace up <ISSUE>.` plus ` docker stop failed for <names>.` when any stop failed. `<M>` is `Math.round(idleMs / 60000)`; `<X.X>` is GiB with one decimal of the summed `memoryBytes` read just before the stop.
- **FR-7 Open reclaim is a union with reasons.** `openStackReclaim(entries)` returns the union of the container names of every `stack.reclaimed` entry after the newest `stack.restored`, the distinct reasons, and the newest entry's `at`, containers and compose project. Every existing reader keeps working: the health leniency (`stack-health.ts:480`) and the restore door now see the union.
- **FR-8 Restore triggers per reason.** The restore door starts the whole union. PAN-5623's `turn` trigger (restore poll in `stack-reclaim-service.ts`) restores an open reclaim only when its reasons include `gate-starvation`. An open reclaim whose only reason is `idle` restores on spawn (any role except `review`, existing spawn gate and spawn route), on verification start (existing), on polyrepo post-rebase merge verification (WI-8, new), and on `pan workspace up` (new). When both reasons are open, a `turn` restore starts the union, including idle-stopped containers; the idle stop stops them again after 20 unused minutes.
- **FR-9 Restore accepts recorded services.** The restore door accepts a journaled container when it is restorable (glossary): reclaimable, or carrying the service its reclaim entry recorded. Before this issue it refused `dev`. Restore never reads the current idle-stop config (critique response 1).
- **FR-10 Pins also hold the memory reclaim.** A pinned workspace is never a memory-reclaim candidate (`buildCandidates` and `recheckBeforeStop` in `stack-reclaim-service.ts`).
- **FR-11 `pan workspace up <issueId>`.** Runs `wakeWorkspaceStack` with trigger `operator` and prints what it started. Exit code 0 when nothing failed (including "nothing to start"), 1 on a failure or when the issue has no workspace or no compose project.
- **FR-12 `pan workspace pin <issueId>` / `pan workspace unpin <issueId>`.** Write / remove the pin file. Each prints the resulting state. Pinning does not start a stopped stack; it prints the hint `Run pan workspace up <ISSUE> to start a stopped stack.` when target containers are exited.
- **FR-13 Documentation and changelog** (WI-10).
- **FR-14 The old reaper honors the same protections.** Before `src/lib/cloister/idle-stack-reaper.ts` stops containers in either tier, it skips the issue (and clears its grace clock) when the workspace is pinned or the usage probe shows an inbound connection, an exec session, or an unreadable container (WI-11).
- **FR-15 Rollout.** The idle stop is on by default (20 minutes). Until [PAN-5649](https://github.com/eltmon/overdeck/issues/5649) ships the browser wake, the operator restarts a stopped app with `pan workspace up <ISSUE>`, which every idle-stop activity entry names; the user-facing page and the changelog state this gap. A workspace is never stopped while a browser has its app open (FR-3 rule 1).

### Non-functional

- **NFR-1 Fake timers.** Every poll and clock test uses `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()`. No test waits on a real 60 s poll or a real 20-minute grace (repo rule `fake-timers-for-retry-tests`).
- **NFR-2 No synchronous child processes** in dashboard-reachable code: no `execSync`, no `*Sync` tmux helper (repo rules `no-execsync-server`, `prefer-async`). Docker calls use promisified `execFile` with an argument array through `resolveHostTool('docker')`, like `stack-reclaim-docker.ts`. `/proc` reads use `fs/promises`.
- **NFR-3 Deny by default.** Any unreadable fact means "do not stop": docker listing (whole poll), pane inventory (whole poll), gate queue `readError` (whole poll), usage probe (that workspace, reason `probe-unknown`), container memory (that workspace's stop). A poll error is logged and never thrown out of the timer.
- **NFR-4 Primary dashboard only.** The idle-stop service starts from `startStackReclaimService` (primary dashboard only, `main.ts:297`) and stops from `stopStackReclaimService`. No new line in `main.ts` (997 of 1000 lines).
- **NFR-5 File-size ratchet** (`scripts/lint-file-size.sh`, 1000 lines for files not on the allowlist). `stack-reclaim-service.ts` is 489 lines; `stack-restore.ts` 229; `pipeline-journal.ts` 208; `merge-ops.ts` 1768 (allowlist cap 1835). `src/lib/projects.ts` is 1212: check its cap in `scripts/file-size-allowlist.txt` before editing; WI-2 changes one existing line and adds no lines. Never raise an allowlist cap.
- **NFR-6 Container names** reaching `docker` pass `CONTAINER_NAME_RE` (`stack-reclaim-docker.ts`); `stopContainer`/`startContainer` already enforce it.
- **NFR-7 Import hygiene.** New `src/lib/workspace/*` modules import nothing from `src/dashboard/`. `stack-idle-config.ts` imports only `projects.ts`, Node built-ins, `stack-reclaim-docker.ts` (for `CONTAINER_NAME_RE`, `RECLAIMABLE_STACK_SERVICES`) and `stack-health.ts` (for `defaultWorkspacePath`); `stack-health.ts` must never import it. `stack-restore.ts` and `idle-stack-reaper.ts` may import `stack-idle-config.ts` and `stack-usage-probe.ts`. `npm run lint:circular` passes.
- **NFR-8 Linux only.** The inbound-connection probe reads host `/proc`. On a host where the read fails, every workspace reads `probe-unknown` and nothing is stopped.

## Design decisions

- **D1. Split.** All requirements of the issue fit in 23 files except "the operator opening the workspace's app". That path needs a Traefik fallback router, a host-dispatched dashboard handler with its own auth model, and a dashboard chip action plus a new REST route. It moved to [PAN-5649](https://github.com/eltmon/overdeck/issues/5649), which depends on this issue's wake door. **Until PAN-5649 lands, an idle-stopped app URL returns Traefik's 404 and the `app ↗` chip is hidden;** the operator runs `pan workspace up <ISSUE>` (named in every activity entry). Today the old reaper already produces the same 404 for agent-less workspaces.
- **D2. Reuse PAN-5623's record.** An idle stop writes `stack.reclaimed` with `data.reason: 'idle'`. Reusing the type gives the health leniency, the spawn and verification restores, crash safety (journal before stop) and the stack lock for free. The reason keeps the `turn` restore away from idle stops (FR-8).
- **D3. Union semantics (FR-7).** Both orders work. Idle stop then memory reclaim: the union holds the idle-stopped `fe`/`dev` and the reclaimed `api`; a `turn` restore (reason `gate-starvation` present) starts all of them. Memory reclaim then idle stop of the remaining `dev`: same union. Without the union, the second entry would hide the first and its containers would never start again.
- **D4. Readback compares the newest entry.** `OpenStackReclaim` gains `latestAt` and `latestContainers`. Both stop sequences compare the entry they just wrote against `latestAt` / `latestContainers`, not against the union.
- **D5. Where it runs.** A new primary-dashboard service, `src/dashboard/server/services/stack-idle-stop-service.ts`, started and stopped by `startStackReclaimService` / `stopStackReclaimService` (NFR-4). It is not part of the deacon child's hygiene scheduler, because the pane inventory reader and the PAN-5623 service it pairs with live in the main process.
- **D6. "In use" is measured, not inferred.** Inbound connections and exec sessions are kernel and daemon facts. Phase labels are not used, because a held-for-UAT PR can sit for days with nobody looking. The operator's open tab (`browser`), a `test`/`uat` agent (`test-agent`), a running gate (`verification`, `gate-queue`, `exec-session`) or a pin protects a UAT session. This is how "in a UAT or test phase that uses the stack" is decided.
- **D7. Usage probe.** One `docker inspect --format '{{.Name}}\t{{.State.Pid}}\t{{len .ExecIDs}}' <ids…>` for all targets of a poll (verified on this host 2026-11-23; `.Name` prints with a leading `/`, strip it), then `readFile('/proc/<pid>/net/tcp')` and `readFile('/proc/<pid>/net/tcp6')` per container (host read of a root-owned container's `/proc/<pid>/net/tcp` verified on this host 2026-11-23). A missing `tcp6` (`ENOENT`) counts as empty; any other read error, a pid of 0, or a container missing from the inspect output gives `unknown`.
- **D8. Loopback.** In `/proc/net/tcp` an IPv4 address is 8 hex digits in little-endian byte order, so `127.x.x.x` ends in `7F` (`0100007F` is 127.0.0.1). In `tcp6`, `00000000000000000000000001000000` is `::1` and `0000000000000000FFFF0000xxxxxx7F` is `::ffff:127.x.x.x`. Docker healthchecks and in-container tools connect over loopback; they never count.
- **D9. Healthcheck execs.** A Docker healthcheck runs as an exec session for under a second. A poll that samples one reads `exec-session` and resets the clock. That only delays a stop (the safe direction), so it is accepted.
- **D10. Pin as a workspace file.** The pin is operator intent that cannot be derived, so it is stored, in `<workspace>/.overdeck/stack-pin.json` (`{ "pinnedAt": "<ISO>" }`). It dies with the workspace. It is not a journal entry, because a `stack.*` entry would close an open reclaim (FR-7 reads `stack.restored` as the close).
- **D11. Wake starts more than the open reclaim.** `pan workspace up` means "start my stack". After the restore door, the wake starts every exited container of the compose project with a restorable service, which also covers a `server`/`frontend` the old reaper stopped without a journal entry. One-shot services (`init`, `init-perms`) are not restorable, so they never re-run.
- **D12. The old reaper stays, but honors pins and use.** `idle-stack-reaper.ts` keeps its no-agent tiers, its name-pattern matching and its broken full-stack tier (PAN-3050 owns those). WI-11 adds one protection check before each of its stops, so a pin or an open browser holds it too (FR-14). The wake starts what it stopped.
- **D13. Default services include `fe`.** The issue proposes a `frontend`/`dev` default. MYN's frontend service is `fe` (verified: `myn-feature-*-fe-1` containers), and `fe` is already a PAN-5623 reclaimable service, so the default is `['frontend', 'fe', 'dev']`. A project overrides it in `projects.yaml`.
- **D14. All due workspaces stop in one poll**, each under its own stack lock, in issue-id order. An idle stop frees memory that is unused by definition, so there is no reason to ration it to one per poll.

function reclaimReason(entry: PipelineJournalEntry): StackReclaimReason {

/**
 * PAN-5623/PAN-5250: every `stack.reclaimed` entry after the newest `stack.restored`,
 * merged. Entries without a valid container name are skipped. Null when nothing is open.
 */
export function openStackReclaim(entries: readonly PipelineJournalEntry[]): OpenStackReclaim | null {
  const open: { entry: PipelineJournalEntry; containers: string[] }[] = [];
  for (let index = entries.length - 1; index >= 0; index -= 1) {
    const entry = entries[index];
    if (entry.type === 'stack.restored') break;
    if (entry.type !== 'stack.reclaimed') continue;
    const raw = entry.data?.containers;
    const containers = Array.isArray(raw) ? raw.filter((name): name is string => typeof name === 'string' && name.length > 0) : [];
    if (containers.length > 0) open.unshift({ entry, containers });
  }
  if (open.length === 0) return null;
  const latest = open[open.length - 1];
  const project = latest.entry.data?.composeProject;
  return {
    at: latest.entry.at,
    containers: [...new Set(open.flatMap((item) => item.containers))],
    composeProject: typeof project === 'string' ? project : null,
    reasons: [...new Set(open.map((item) => reclaimReason(item.entry)))],
    latestAt: latest.entry.at,
    latestContainers: latest.containers,
    recordedServices: Object.fromEntries(open.flatMap(({ entry }) => {
      const names = Array.isArray(entry.data?.containers) ? entry.data.containers : [];
      const services = Array.isArray(entry.data?.services) ? entry.data.services : [];
      return names.flatMap((name, i) => (typeof name === 'string' && typeof services[i] === 'string' ? [[name, services[i] as string]] : []));
    })),
  };
}

/** PAN-5250 FR-8: whether the open reclaim may be restored by an agent turn. */
export function reclaimRestoresOnTurn(open: OpenStackReclaim | null): boolean {
  return open !== null && open.reasons.includes('gate-starvation');
}

## Critique response

### Config changes can strand stopped services

Accepted. The restore door no longer reads the current idle-stop config. A journaled container is restorable when it is in the workspace's compose project and its service is reclaimable or equals the service its reclaim entry recorded (`OpenStackReclaim.recordedServices`, WI-1; FR-9; WI-4 step 2). Emptying or changing `workspace.docker.idle_stop.services` after a stop therefore never strands it; WI-4 tests exactly that. `wakeWorkspaceStack` uses `wakeableServicesForIssue`, which always includes the default idle-stop services.

### Old reaper bypasses browser use and pins

Accepted. WI-11 (FR-14) adds an `isProtected` check before each of the old reaper's stops: a pinned workspace, an inbound connection, an exec session, or an unreadable probe skips the stop and restarts its grace clock. Its tiers and name matching otherwise stay (PAN-3050). This takes the plan to 27 files and 7 path groups; `plan.metadata.sizeJustification` records why the protection cannot ship separately (a pin that the old reaper ignores is a broken promise on day one).

### Default stop has no browser wake path

Kept on by default, with the rollout stated as FR-15. Reasons: the issue asks for a 20-minute default stop; a workspace whose app is open in a browser is in use and never stops (FR-3 rule 1), so no active session is interrupted; any agent spawn except review, every verification start and `pan workspace up` restart the stack; every idle-stop activity entry names `pan workspace up <ISSUE>`; and the old reaper already yields the same Traefik 404 for agent-less workspaces today. The browser wake is PAN-5649, filed during planning, commented on both issues, and the Flywheel was told to sequence it directly after this one. WI-9's user page and WI-10's changelog state the gap (WI-9 AC, WI-10 AC).
