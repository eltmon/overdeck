## Glossary

- **OKF skill** — the `/okf` agent skill: `SKILL.md`, `README.md`, `docs/`, `references/`, `scripts/`, `templates/`. Today it sits at `sync-sources/skills/okf/` in this repo.
- **eltmon/okf** — the public GitHub repo for the skill. Local primary checkout: `/home/eltmon/Projects/okf` (registered as Overdeck project `okf`, `issue_prefix: OKF`). After this issue it is the **canonical** home: all skill edits land there first.
- **Vendored tree** — the copy of an eltmon/okf release tag that Overdeck commits at `sync-sources/skills/okf/`. It is produced only by `scripts/vendor-okf-skill.sh`; nobody edits it by hand.
- **Pin file** — `sync-sources/skills/okf/.okf-skill-version`. One line: the vendored tag, e.g. `v0.1.0`, followed by a newline.
- **Exclude list** — the tag-root paths the vendor script drops: `.github/`, `.pan/`, `.overdeck/`, `tests/`, `CHANGELOG.md`, `.gitignore`, `.gitattributes`. Every entry is **anchored to the tarball root**; `templates/repo/.github/` and `templates/repo/.gitignore` are skill content and must survive.
- **Pin check** — `scripts/vendor-okf-skill.sh --check`: re-derive the filtered tree of the tag named in the pin file and `diff -r` it against `sync-sources/skills/okf/`. The CI workflow `okf-vendor-pin.yml` runs it.
- **Cache copy** — `~/.overdeck/skills/okf/` (`SKILLS_DIR`, `src/lib/paths.ts:30`). `refreshCache()` always overwrites it from `sync-sources`.
- **Installed copies** — the harness skill directories `pan sync` writes: `~/.claude/skills/okf/` (Claude Code; `executeSync`, `src/lib/sync.ts`) and `~/.agents/skills/okf/` (`AGENT_SKILLS_DIR`, `src/lib/paths.ts:59`; Codex, Pi, kimi-code; `executeAgentSkills`, `src/lib/harness-skill-sync.ts`). Per-agent `CODEX_HOME/skills` copies are refreshed from `~/.agents/skills` at every Codex spawn by `syncCodexSkillsIntoHome` (`src/lib/runtimes/codex-skills.ts`, `cpSync … force: true`).
- **Manifest** — `<target>/.overdeck-manifest.json` (`~/.claude/…` and `~/.agents/…`). It records the sha256 of each file Overdeck placed. `compareFileToManifest` (`src/lib/manifest.ts:257`) returns `new`, `update` (hash matches manifest), `modified` (hash differs from manifest) or `user-owned` (no manifest entry).
- **Converge** — make an installed copy byte-identical to the cache copy, ignoring `__pycache__/` (Python writes it at run time).
- **Item trailer** — `pan task done <issue> <item>` requires a commit carrying `Item: <item-id>` on a pushed branch **of this repo** (`markItemDone`, `src/lib/xbrief/continue-state.ts:~395`, searches `repoRoots`, which default to the plan home). Commits in eltmon/okf never satisfy it.

## Decisions (made here; mirrored in the xBRIEF `autoDecisions`)

- **D1 — Tag v0.1.0 on a release commit, not on `fe73d46`.** The issue says "tag `v0.1.0` at `fe73d46`", but its acceptance criterion requires the v0.1.0 filtered tree to contain `LICENSE` and `NOTICE`, which `fe73d46` lacks. Resolution: branch `release/v0.1.0` off `fe73d46`, commit `LICENSE`, `NOTICE`, `.github/workflows/ci.yml` and the README install rewrite, and tag **that** tip `v0.1.0` (annotated). The tagged tree has no `.pan/`, has LICENSE/NOTICE, and its skill content equals `fe73d46` except `README.md`. Then merge `release/v0.1.0` into okf `main` with a **merge commit** (never squash) so the tagged commit stays reachable from `main`.
- **D2 — The README install rewrite happens in eltmon/okf, before the tag.** The issue names `sync-sources/skills/okf/README.md`, but that file is vendored: a local edit would fail the pin check forever. It reaches Overdeck through the vendor step (WI-6).
- **D3 — Cross-repo items are corroborated by an empty commit here.** For each eltmon/okf item, after the okf commit is pushed, the work agent makes `git commit --allow-empty` on `feature/pan-4408` with subject `chore(okf): <what> in eltmon/okf`, a body naming the okf commit SHA (and for WI-4 the tag and merge URL), and the `Item: <item-id>` trailer, then pushes. The squash merge folds these away.
- **D4 — One exclude list, one comparison.** The workflow calls `scripts/vendor-okf-skill.sh --check`; it never re-implements the filter. The exclude list lives in exactly one bash array in the script.
- **D5 — Filtering uses `rsync -a --delete` with root-anchored `--exclude='/<path>'` filters** from the extracted tag into the destination. This gives replace semantics (stale files are deleted) without `rm -rf` on the destination and without matching nested paths such as `templates/repo/.github/`. The only `rm` in the script is the `trap` cleanup of its own `mktemp -d` directory, written as `rm -rf -- "${tmp:?}"`.
- **D6 — Offline testability.** The script accepts `--tarball <file>` to read a local `.tar.gz` instead of downloading, and `--dest <dir>` to write somewhere other than `<repo>/sync-sources/skills/okf`. Tests use both and never touch the network.
- **D7 — Pin file format:** exactly the tag plus `\n` (e.g. `v0.1.0\n`). Tag argument must match `^v[0-9]+\.[0-9]+\.[0-9]+$`.
- **D8 — Vendored skills converge on `pan sync`.** A skill listed in `VENDORED_SKILLS` (only `okf`) is Overdeck-managed in a harness skills dir **when its skill root is a real directory**. For such files `executeSync` and `executeAgentSkills` overwrite `modified` targets (and, in `executeAgentSkills`, differing `user-owned` targets) without `--force`, record the new hash in the manifest, and report the path in a new `SyncResult.replacedVendored` list. When the skill root is a **symlink**, behavior is unchanged (conflict / skip), so sync never writes local edits through into a user's own checkout. `planSync`/`planAgentSkills` report the converging files as updatable (`'symlink'`, which in `SyncItem` means "managed, safe to update") instead of `'conflict'`.
- **D9 — `__pycache__/` is ignored for convergence checks.** Every `diff -r` in ACs uses `-x __pycache__`. Sync does not delete `__pycache__/`.
- **D10 — Doctor check lives in its own module**, `src/cli/commands/doctor-okf-skill.ts`, wired into `doctor.ts` by editing the existing line 828 with the dynamic-import pattern already used on line 771. `doctor.ts` stays at 1042 lines.
- **D11 — CI proof.** `okf-vendor-pin.yml` triggers on `pull_request` and `push: branches: [main]` (both paths-filtered) and on `workflow_dispatch`. The negative proof is (a) mechanically, a Vitest case running `--check` against an edited tree, and (b) an **implementation checkpoint** on this PR: push a commit that edits one line of `sync-sources/skills/okf/SKILL.md`, confirm the `okf-vendor-pin` check fails, revert it with a second commit, confirm it passes, and record both run URLs in the PR body. Fallback if the pipeline refuses a deliberately red push: skip (b), record that in the PR body, and leave a note for the operator to run `gh workflow run okf-vendor-pin.yml --ref <branch-with-edit>` after merge.

Pre-merge proof is a Vitest test with mocked paths (`tests/unit/lib/sync-adopt-legacy.test.ts` style) seeded with the exact stale state from Background 5. Never run a real `pan sync` from the workspace under a substituted `HOME`/`OVERDECK_HOME`: `pan sync` also manages the Herdr systemd unit and shared state.

## Requirements

### Functional

- **FR-1** eltmon/okf carries `LICENSE` (MIT, byte-identical to this repo's `LICENSE`) and `NOTICE` (Apache-2.0 attribution for `references/spec.md`) at tag `v0.1.0` and on `main`.

- **FR-5** `scripts/vendor-okf-skill.sh <tag>` replaces the destination with the tag's tree minus the root-anchored exclude list, fails if `LICENSE` or `NOTICE` is missing, and writes the pin file.
- **FR-6** `scripts/vendor-okf-skill.sh --check` exits 0 when the destination equals the filtered tree of the pinned tag plus the pin file, and exits 1 naming the differing paths otherwise (or when the pin file is missing).
- **FR-7** `sync-sources/skills/okf/` equals the v0.1.0 filtered tree plus `.okf-skill-version` = `v0.1.0`.
- **FR-8** `.github/workflows/okf-vendor-pin.yml` runs the pin check and fails CI when a file under `sync-sources/skills/okf/` differs from the pinned tag.
- **FR-9** `pan sync` converges real-directory installed okf copies in `~/.claude/skills` and `~/.agents/skills` to the cache copy, including files the manifest marks as modified, and reports them as replaced.
- **FR-10** `pan sync` never writes over modified files through a symlinked vendored skill root.
- **FR-11** `pan doctor` shows an `OKF Skill Version` check that WARNs when an installed copy's `.okf-skill-version` is missing or differs from the vendored one, and is `ok` when all installed copies match.
- **FR-12** Docs state where the skill lives and how to change it: `configuration/knowledge.mdx` "Where the skill lives", a `CLAUDE.md` one-liner, and a corrected `.husky/pre-push` comment.

### WI-5 `vendor-script` — `scripts/vendor-okf-skill.sh` and its Vitest test

New file `scripts/vendor-okf-skill.sh` (bash, `set -euo pipefail`, executable). Interface:
```text
scripts/vendor-okf-skill.sh <tag> [--tarball <file>] [--dest <dir>]
scripts/vendor-okf-skill.sh --check [--tarball <file>] [--dest <dir>]
```
- Default `--dest`: `"$(git rev-parse --show-toplevel)/sync-sources/skills/okf"`.
- Usage errors (no args, unknown flag, flag missing its value, tag not matching `^v[0-9]+\.[0-9]+\.[0-9]+$`, both a tag and `--check`) print a `usage:` line to stderr and exit 2.
- Single exclude array near the top:
  ```bash
  # Tag-root paths that are repo tooling, not skill content. Anchored to the
  # root: templates/repo/.github/ and templates/repo/.gitignore are skill content.
  EXCLUDES=(.github .pan .overdeck tests CHANGELOG.md .gitignore .gitattributes)
  ```
- Fetch: with `--tarball`, use that file; otherwise `curl -fsSL "https://github.com/eltmon/okf/archive/refs/tags/${tag}.tar.gz" -o "$tmp/okf.tgz"`.
- `tmp="$(mktemp -d)"; trap 'rm -rf -- "${tmp:?}"' EXIT`. Extract with `tar -xzf "$tgz" -C "$tmp/src" --strip-components=1`.
- Build rsync filter args from `EXCLUDES` as `--exclude=/<entry>` each (leading slash anchors to the transfer root).
- Vendor mode: fail with exit 1 and `error: <tag> tarball has no LICENSE` (or `NOTICE`) if either is missing in `$tmp/src`; `mkdir -p "$dest"`; `rsync -a --delete "${filters[@]}" "$tmp/src/" "$dest/"`; `printf '%s\n' "$tag" > "$dest/.okf-skill-version"`; print `vendored eltmon/okf <tag> into <dest>`.
- Check mode: read the tag from `"$dest/.okf-skill-version"` (missing → exit 1 with `::error::` message telling the reader to run `scripts/vendor-okf-skill.sh <tag>`); fetch and extract as above; `rsync -a --delete "${filters[@]}" "$tmp/src/" "$tmp/expected/"`; write the pin file into `$tmp/expected`; `diff -r -x __pycache__ "$tmp/expected" "$dest"`. On difference print `::error::sync-sources/skills/okf differs from eltmon/okf <tag>. Edit the skill in eltmon/okf, tag a release, and re-vendor with scripts/vendor-okf-skill.sh <tag>.` plus the diff output, and exit 1. On match print `okf skill matches eltmon/okf <tag>` and exit 0.
