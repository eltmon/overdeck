# PAN-4642 — Cite selected reply text with a comment and send it with the next prompt

**Issue:** [PAN-4642](https://github.com/eltmon/overdeck/issues/4642)
**Status:** planned (auto mode, 2026-11-01)
**Related:** #2685 (annotated live preview), #4498 (message bookmarks), #1592 (reload-durable attachments)

## Glossary

- **Citation** — one saved annotation: a span of text the operator selected in a conversation message, plus an optional comment. Type `PendingCitation` (WI-2).
- **Pending citations** — the ordered list of citations for one conversation that have not been sent yet. Shown as chips above the composer.
- **Cite toolbar** — the small floating "Cite" button that appears over a text selection in the timeline, and the inline comment box it opens (WI-5).
- **Citation chip** — the compact card above the composer that shows one pending citation, with expand, edit-comment and remove controls (WI-6).
- **Citation block** — the text the client prepends to the prompt on send: the header line `Notes on your previous reply:` followed by numbered quote/comment entries (WI-2 defines the exact bytes).
- **Composed message** — the final string the composer POSTs as `message`: attachment `@path` lines, then the citation block, then the operator's prompt text.
- **Citable row** — a timeline message row whose text can be cited: a settled user message or a completed assistant message in the main conversation timeline (WI-4 defines the gate).
- **Outbox** — the failed-send list in `composerStore` (`ComposerSlice.failed`), rendered in the timeline with Retry/Discard.
- **Custom Highlight API** — the browser API `CSS.highlights` + `new Highlight(...ranges)` + the `::highlight(name)` pseudo-element. It paints DOM `Range`s without changing the DOM. TypeScript 5.9's `lib.dom.d.ts` already declares it (`highlights: HighlightRegistry`), so no ambient declaration is needed.
- **Main timeline** — the `MessagesTimeline` mounted by `ConversationPanel.tsx` (the one that already passes `bookmarksEnabled`). Subagent transcripts and other mounts are not the main timeline.

## Problem

To push back on part of an agent reply, the operator copies the text by hand and pastes it into the composer. There is no way to select a span, attach a comment, and have it travel with the next prompt. t3code ships exactly this ("cite"). Overdeck already has per-conversation pending composer state (attachments in `src/dashboard/frontend/src/lib/composerStore.ts`) and per-conversation drafts in `localStorage`, so the pieces exist; the citation flow does not.

## Decisions (made here; auto mode)

- **D1 — Serialization is client-side and harness-agnostic.** The citation block is built in the browser and becomes part of the `message` string. The server, delivery doors and harness adapters are untouched, so Claude Code, Codex, Pi, ACP/OpenCode, Kimi and Muse all receive identical bytes (FR-7).
- **D2 — Exact format.** See WI-2. Header is the literal `Notes on your previous reply:` for every citation, even one taken from the operator's own message (the issue fixes this string). Numbering is `1.`, `2.`, … in add order. Each quote line starts with `> `; continuation lines are indented by the width of the number prefix so the list item holds. Comment lines are indented the same width. No comment ⇒ no comment line. One blank line separates the block from the prompt.
- **D3 — Composed message order.** `[attachmentPrefix, composePromptWithCitations(messageText, citations)].filter(Boolean).join('\n')`. The attachment join stays a single `\n`, exactly as today; attachments behave byte-for-byte as before when there are no citations.
- **D4 — Citations-only sends are allowed** (no prompt text), mirroring the attachments-only rule at line 488.
- **D5 — Slash text keeps citations pending.** When the trimmed prompt starts with `/` (the `/pan` portable lane, the `/handoff` intercept that returns earlier, or a harness slash command such as `/compact`), citations are neither included nor consumed.
- **D6 — Chips clear the moment the composed text is handed off.** After the conversation-switch abort check, if citations were included, `consumeCitations(conversationName)` runs once — before `holdSend`, `onSend`, `hold` or `onSendFailed` can run. Every one of those stores keeps the composed text (optimistic bubble, held bubble, offline hold, or outbox), so the citations live on with that message, and Retry re-sends them. This deliberately differs from attachments, which stay pending after a plain failure. Leaving chips pending after a failure would double-send them (once on Retry, once on the next prompt).
- **D7 — No source pointer in the delivered text.** `source.messageId` stays client-side (used only for the highlight). This answers the issue's first open question: the agent cannot use a dashboard message id, and the issue's format has no pointer. `GET /api/conversations/:name/message-locator` is not used.
- **D8 — Message prose only.** Citable text is a settled user message or a completed assistant message in the main timeline. Tool output (work-log rows), plan cards, choice cards, optimistic/held/subagent-delivered bubbles and streaming assistant text are not citable. This answers the issue's second open question.
- **D9 — One row per citation.** A selection whose anchor and focus fall in different citable rows (or outside any citable row) shows no Cite button.
- **D10 — Persistence mirrors drafts.** `localStorage` key `conv-citations:<conversationName>`, JSON `{ "v": 1, "citations": PendingCitation[] }`. Last write wins across windows (same as drafts). Invalid or unparseable storage reads as an empty list.
- **D11 — Shared list for #2685.** `PendingCitation.source` is a discriminated union whose only member today is `{ kind: 'message'; messageId; role }`. #2685 adds its own kind (for example `{ kind: 'preview-element', … }`) to the same list and the same serializer, so preview annotations ride with the next prompt too.
- **D12 — Highlight is best-effort.** Painted with the Custom Highlight API from inside each row, re-found on every mount (rows unmount under virtualization). Matching ignores whitespace; the first occurrence is painted. If `CSS.highlights` is missing or the text is not found, nothing is painted and nothing fails.
- **D13 — Keyboard rule for `C`.** While the Cite button is visible, a document `keydown` of `c`/`C` with no Ctrl/Meta/Alt opens the comment box, but only if `document.activeElement` is not an `input`, `textarea`, `select` or `[contenteditable]` element. The listener exists only while the button is visible.
- **D14 — Comment box keys.** Enter saves, Shift+Enter inserts a newline, Escape cancels. Saving with an empty comment is allowed (quote-only citation). A chip edits the comment only; the quoted text is fixed once saved.
- **D15 — Surfaces deferred.** BrowserPane citing is out (sandboxed iframe; belongs to #2685). EditorPane preview citing is out of this issue because the Stage has no target conversation for an editor pane; it is filed as #4658.

## Requirements

### Functional

- **FR-1** Selecting text inside one citable row of the main timeline shows a floating "Cite" button near the selection. Pressing `C` under the D13 rule does the same as clicking it.
- **FR-2** Clicking Cite opens an inline comment box with Save and Cancel. Save adds exactly one pending citation (quote, source, comment, time) for the current conversation and clears the selection. Cancel adds nothing.
- **FR-3** Pending citations render as chips above the composer, in add order. A chip can be expanded to show the full quote and comment, its comment can be edited and saved, and it can be removed.
- **FR-4** Sending composes the message per D2/D3: the citation block in add order, then the prompt. A citation without a comment is a quote with no comment line. A removed chip is absent from the message.
- **FR-5** Pending citations survive switching to another conversation and back, and a page reload.
- **FR-6** After a successful send the chips are gone. After a failed send the composed text (with citations) sits in the outbox, the chips are gone, and Retry re-sends the same text.
- **FR-7** The delivered text is identical for every harness (D1).
- **FR-8** The quoted span stays highlighted in its row while its citation is pending (D12).
- **FR-9** Slash-prefixed prompts leave citations pending (D5). Citations-only sends are allowed (D4).

### Non-functional

- **NFR-1** No file grows past its file-size limit; `ComposerFooter.tsx` ends at or under 1000 lines and `ConversationPanel.tsx` grows by exactly one line.
- **NFR-2** `localStorage` failures never throw out of the citation store.
- **NFR-3** No server, contracts or delivery-path change.
- **NFR-4** Every new frontend test file is listed in `test:frontend-subset`.
- **NFR-5** The feature is documented in the user guide and the dashboard architecture doc.

### WI-2 — Citation type and serializer (`lib/citationFormat.ts`)

**Files:** new `lib/citationFormat.ts`, new `lib/__tests__/citationFormat.test.ts`.

**Code:**

```ts
export type CitationSource = { kind: 'message'; messageId: string; role: 'assistant' | 'user' };

export interface PendingCitation {
  id: string;            // crypto.randomUUID()
  source: CitationSource;
  quotedText: string;    // trimmed selection text, never empty
  comment: string;       // trimmed; '' means no comment
  createdAt: string;     // ISO 8601
}

export const CITATION_BLOCK_HEADER = 'Notes on your previous reply:';

export function formatCitationBlock(citations: readonly PendingCitation[]): string;
export function composePromptWithCitations(prompt: string, citations: readonly PendingCitation[]): string;
```

**Rules (exact):**
- `formatCitationBlock([])` returns `''`.
- Otherwise the first line is `CITATION_BLOCK_HEADER`. For citation number `n` (1-based, add order) let `prefix = `${n}. `` and `indent = ' '.repeat(prefix.length)`.
- Quote: `quotedText.trim()` split on `\n`; each line has trailing whitespace removed. Line 1 is `${prefix}> ${line}`; every later line is `${indent}> ${line}`, or `${indent}>` when the line is empty.
- Comment: if `comment.trim()` is non-empty, split on `\n`, trailing whitespace removed per line; each line is `${indent}${line}`, or `''` when the line is empty.
- Lines join with `\n`. No trailing newline.
- `composePromptWithCitations(prompt, [])` returns `prompt` unchanged. With citations: `prompt.trim() === '' ? block : `${block}\n\n${prompt}``.

**Fixture (must appear in the test verbatim):** two citations — first quote `"First line\nsecond line"` with comment `"I don't agree"`, second quote `"Use X"` with no comment — and prompt `"Please revise."` produce:

```
Notes on your previous reply:
1. > First line
   > second line
   I don't agree
2. > Use X

Please revise.
```

**Tests:** the fixture; empty list returns prompt unchanged; prompt-less compose returns the block alone; a tenth citation uses a 4-space indent; blank quote line renders as `   >`.

### WI-3 — Pending-citation store with `localStorage` persistence (`lib/composerCitations.ts`)

**Files:** new `lib/composerCitations.ts`, new `lib/__tests__/composerCitations.test.ts`.

**API:**

```ts
export function useCitationStore: UseBoundStore<…>   // zustand: { byConversation: Record<string, PendingCitation[]> }
export function useConversationCitations(conversationName: string): PendingCitation[]; // selector, stable empty array
export function getConversationCitations(conversationName: string): PendingCitation[]; // sync read for event handlers
export function addCitation(conversationName: string, input: { source: CitationSource; quotedText: string; comment: string }): PendingCitation | null; // null when quotedText.trim() is empty
export function updateCitationComment(conversationName: string, id: string, comment: string): void;
export function removeCitation(conversationName: string, id: string): void;
export function consumeCitations(conversationName: string): void; // clears list and removes the storage key
export function resetCitationStore(): void; // test-only: rebuilds the in-memory map from localStorage (reload simulation)
```

**Rules:**
- Storage key `conv-citations:<conversationName>`; value `JSON.stringify({ v: 1, citations })`. An empty list removes the key.
- Hydration happens once, when the store module is created: iterate `localStorage` keys, and for every key starting with `conv-citations:` parse the value into `byConversation[<name>]`. Never hydrate lazily inside a selector or render (that would call `setState` during render). `resetCitationStore()` re-runs the same load. Accept only `v === 1` and entries whose `id`, `quotedText`, `comment`, `createdAt` are strings and whose `source.kind === 'message'` with string `messageId` and `role` of `'assistant' | 'user'`. Drop invalid entries. Any `JSON.parse` or storage error ⇒ empty list.
- `useConversationCitations` uses a stable empty array (like `EMPTY_ATTACHMENTS` in `composerStore.ts` line 78). Because hydration runs at module creation, a reload renders chips on the first frame.
- Every mutation writes storage inside `try/catch`.
- `addCitation` stores `quotedText.trim()` and `comment.trim()`.

**Test isolation:** because `resetCitationStore()` reloads from storage and happy-dom's `localStorage` persists within a test file, every test file that touches the citation store (WI-3, WI-5, WI-6, WI-7, WI-8) runs `localStorage.clear(); resetCitationStore();` in `beforeEach`.

**Tests:** add/update/remove/consume; order preserved; reload simulation (`resetCitationStore()` then `getConversationCitations` returns the saved list); conversation isolation (two names do not see each other's list); corrupt JSON and wrong `v` read as empty; a throwing `localStorage.setItem` does not throw out of `addCitation`.
