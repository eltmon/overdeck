# PAN-4211 — Restore a door that clears a troubled agent

**Issue:** [PAN-4211](https://github.com/eltmon/overdeck/issues/4211)
**Status:** planned (auto mode, 2026-09-25)
**Base commit:** `51f2928982d` (feature/pan-4211)

## Summary

The Cut (PAN-3917, commit `a1def1f8959`, item `w9-cli`) deleted `pan untroubled`
on the premise that there was "no stored troubled flag" (`docs/THE-CUT.md` line 158).
That premise is false: `troubled` is still written to the agent state row after three
failures inside ten minutes (`applyAgentFailure`, `src/lib/agents/agent-state.ts`
lines 546-579) and still blocks `pan start`, `pan resume`, dashboard Start, and MERGE.
Four operator messages still tell the operator to run `pan untroubled`, which now
prints `unknown command`. `pan start --force` clears only the paused gate, so the only
way through today is hand-editing `~/.overdeck/agents/<agent>/state.json`.

This change restores `pan untroubled <id>` as a clear-only door, makes
`pan start <id> --force` also clear the troubled gate (parity with the dashboard's
`clearGates`), records both as `untroubled` operator interventions, and adds a test
that fails whenever a troubled/paused gate message names an unregistered `pan` verb.

## Glossary

- **Troubled gate** — `state.troubled === true` (plus `troubledAt`) on an agent state
  row. Set by `applyAgentFailure` when `consecutiveFailures >= 3` within
  `TROUBLED_WINDOW_MS` (10 min), and by `markAgentTroubled`. It blocks every start and
  resume path until cleared.
- **Failure tracking fields** — `consecutiveFailures`, `firstFailureInRunAt`,
  `lastFailureAt`, `lastFailureReason`, `lastFailureNextRetryAt`. Cleared together with
  the troubled flag by `applyAgentUntroubled` (`agent-state.ts` line 464).
- **Paused gate** — `state.paused === true`; the sibling operator gate cleared by
  `pan unpause` and by `pan start --force`.
- **Clearing door** — a single operator-invoked command or route that clears a gate
  through `clearAgentTroubled` / `clearAgentPaused` and records an operator intervention.
- **Operator intervention** — an `operator.intervention` domain event appended by
  `appendOperatorInterventionEvent({ issueId, kind, source })`
  (`src/lib/operator-interventions.ts` line 28). `'untroubled'` is already a member of
  `OperatorInterventionKind` (line 5) and of the contracts schema
  (`packages/contracts/src/events.ts` line 723).
- **Composer command manifest** — `COMPOSER_COMMAND_MANIFEST` in
  `packages/contracts/src/composer-commands.generated.ts`, generated from the CLI
  registry by `npm run generate:slash-commands` (needs `npm run build:cli` first) and
  drift-gated by `scripts/lint-slash-commands.sh` (part of `npm run lint`). It is the
  registry the verb tests check against.
- **Message site** — a place in source that tells the operator to run a `pan` command
  to clear a gate.

## Decisions

- **D1 — Restore `pan untroubled <id>` as a clear-only verb.** It clears the troubled
  gate and failure tracking fields, records an intervention only when something was
  cleared, and prints the next step. It does not resume or spawn: the gate exists
  because the agent crashed repeatedly, so the operator should choose when to run it
  again. This keeps M2–M5 correct without rewording them.
- **D2 — `pan start <id> --force` also clears the troubled gate.** The dashboard's
  `clearGates` already clears both gates, and `--force` is the CLI's "clear the gates
  and start" flag, so the CLI now matches. `--fresh` alone does not clear the gate:
  it replaces the session and is not a gate override. `--fresh --force` clears it.
- **D3 — Record the clear as an operator intervention.** `pan untroubled` records
  `{ kind: 'untroubled', source: 'pan untroubled' }`. `pan start --force` records
  `{ kind: 'untroubled', source: 'pan start --force' }`. The pause clear that `--force`
  already performs keeps its current behavior (no intervention recorded); changing it
  is out of scope.
- **D4 — No rewording of M2–M5.** Once D1 lands, their text names a real command. M1
  is reworded to name both doors (see WI-2).
- **D5 — Guard against recurrence with the registry test.** Extend
  `src/lib/__tests__/agent-text-cli-verbs.test.ts` (which already checks prompt/skill
  text against `COMPOSER_COMMAND_MANIFEST`) with a block that calls the pure gate
  message producers (M2–M5, plus the paused variants) and fails on any unregistered
  verb. M1 lives inside the `issueCommand` flow, so it is covered by an exact-string
  assertion in `start-running-noop.test.ts` instead.
- **D6 — The skill comes back.** `sync-sources/skills/pan-untroubled/SKILL.md` was
  deleted with the verb (commit `7b953449633`). Restore it with text that does not
  promise Deacon auto-resume, because the Cut removed auto-resume escalation (see the
  comment at `agent-state.ts` lines 537-540).
- **D7 — Dashboard frontend is unchanged.** `StartAgentCta` only offers a recovery
  dialog for `paused` (`src/dashboard/frontend/src/lib/resumeRecovery.ts` line 9). A
  troubled Start still shows the 409 error inline. Adding a troubled recovery dialog is
  a separate UI change and out of scope. The docs are corrected to describe the actual
  behavior.

## Requirements

### Functional

- **FR-1** `pan untroubled <id>` is a registered CLI command. It accepts an issue ID
  (`PAN-1641`) or a full agent ID (`agent-pan-1641`, `strike-pan-1723`), resolved with
  `resolveAgentTarget` exactly as `pan unpause` does.
- **FR-2** On a troubled agent, `pan untroubled` clears `troubled`, `troubledAt`, and
  all failure tracking fields through `clearAgentTroubled`, exits 0, and prints
  `Cleared troubled state for agent: <agentId>` followed by
  `Run pan start <issueId> to spawn it.`
- **FR-3** On an agent with no troubled flag and `consecutiveFailures` of 0 or unset,
  `pan untroubled` exits 0, prints `Agent <agentId> is already untroubled.`, and
  records no intervention.
- **FR-4** An unresolvable target or a missing state row exits 1 with the same messages
  `pan unpause` uses (`Could not resolve agent target "<id>"` / `Agent <agentId> not found.`).
- **FR-5** `pan untroubled` records `appendOperatorInterventionEvent({ issueId, kind: 'untroubled', source: 'pan untroubled' })`
  exactly once when it cleared a troubled flag or non-zero failure counter.
- **FR-6** `pan start <id> --force` on a troubled agent does not refuse. It clears the
  troubled gate right before spawn (local and remote paths) and records
  `{ kind: 'untroubled', source: 'pan start --force' }`.
- **FR-7** `pan start <id>` without `--force` on a troubled agent still exits 1, and its
  last stderr line reads:
  `Investigate the crash cause, then run pan untroubled <id> to clear the gate, or pan start <id> --force to clear it and start now.`
- **FR-8** `assertCanStartFresh` accepts `allowTroubledForce`. When it is true, the agent
  is troubled, and `requiresSessionResetBeforeFreshStart` is true, it does not throw —
  mirroring `allowPausedForce`. `pan start --force` passes it.
- **FR-9** The `--force` option description reads
  `Clear paused, troubled, and pending-operator-decision gates and start anyway`.
- **FR-10** A unit test fails if any of the gate messages M2–M5 (and their paused
  siblings) names a `pan` command missing from `COMPOSER_COMMAND_MANIFEST`.
- **FR-11** The restored `pan-untroubled` skill and the docs listed in WI-4 describe the
  two clearing doors.

- **NFR-3** `packages/contracts/src/composer-commands.generated.ts` is regenerated, not

   export async function untroubledCommand(id: string): Promise<void> {
     // PAN-1760: resolve through normalizeAgentId so full agent IDs

       if (wasTroubled) {

         console.log(chalk.green(`Cleared troubled state for agent: ${agentId}`));
         console.log(chalk.dim(`Run pan start ${issueId} to spawn it.`));
       } else {
         console.log(chalk.dim(`Agent ${agentId} is already untroubled.`));
       }
     } catch (error: unknown) {
       console.error(chalk.red('Error: ' + (error instanceof Error ? error.message : String(error))));
       return exitCli(1);
     }
   }
