## 1. Glossary

- **Stage / deck** — the tabbed pane area (`components/Stage/index.tsx`). A component inside a Stage pane gets `useStageDeck()` (`components/Stage/StageDeckContext.tsx`), which returns `null` outside a Stage. A Stage deck offers `openDock` and `openBeside`.
- **Dock** — the right column with the Files, Changes, Search and Live tabs (`components/dock/WorkDock.tsx`), state in `components/dock/workDockStore.ts` keyed by deck.
- **Conversation changes** — `GET /api/conversations/:name/changes?scope=conversation` (child A). Type `ConversationChanges` in `packages/contracts/src/conversation-changes.ts`: `uncommitted: UncommittedFile[]` (each with `turnIds: string[]`), `commits: ChangeCommit[]` (each with optional `turnId`), `repoRoot`, `totals`. Every path in it is a **repo path** (relative to `repoRoot`).
- **Root path** — a path relative to an explorer root (`project:<key>`, `issue:<ID>`, `workspace:<id>`). `toRootPath(repoRoot, rootAbs, repoPath)` in `components/dock/changes-model.ts` converts a repo path to a root path.
- **User turn** — the messages from one `role: 'user'` message up to (not including) the next `role: 'user'` message. Its **assistant ids** are the ids of its `role: 'assistant'` messages; its **anchor** is the last of them.
- **Turn card** — the new per-turn "what changed" card (FR-3) that replaces the "Changed files" card.
- **File chip** — a file path rendered by `components/chat/MarkdownFileLink.tsx` (assistant text and tool rows both render through `ChatMarkdown` → `MarkdownFileLink`).
- **Diff window** — the standalone `/popout/diff` route (`App/StandaloneRoutes.tsx`, `StandaloneDiffPopoutRoute`) that mounts the full `DiffPanel` (All turns, per-turn chips, vs main, Compare…, ignore whitespace, Markdown preview).
- **Send mode** — the composer's delivery value `DeliverAs = 'auto' | 'steer' | 'follow_up' | 'when_limit_resets'` (`components/chat/DeliveryModeSelect.tsx`).
- **Registry** — the keyboard shortcut registry `lib/shortcuts/registry.ts` (`useShortcutList()` returns every registered `ShortcutDef`; `formatSpec(spec, platform)` in `lib/shortcuts/keys.ts` prints keycaps).
- **Fixture** — the shared workflow fixture `scripts/dev/seed-workflow-fixture.ts`: project `workflow-fixture`, conversation `fixture-1` ("Fixture conversation") with pushed commits, a local trailer commit, and uncommitted edits to `docs/shared.md`.

## 3. Decisions

- **D2-1 One changes query per panel, shared with the header.** `ConversationPanel` wraps its whole content in a new `ConversationChangesScope` that calls `useConversationChanges(conversation, 'conversation', …)` once — the dock's own hook and query key (`['conversation-changes', name, 'conversation', null]`), so the header, the turn cards, the chips and the dock share one cache entry and one request. Chips and cards never call the hook themselves.
- **D2-2 Which conversations query.** Enabled only when `conversation.id >= 0`, `conversation.origin !== 'linked'` and `conversation.origin !== 'vault'` (D1-8's guard). Otherwise there is no turn card. Agent panes (synthetic ids) had no "Changed files" card before either.
- **D2-3 Outside a Stage the turn card still shows; its actions open the diff window.** Today's card and inline diff show in every mount (popout window, drawer, mobile, directory, Flywheel pane), and the parent's no-loss rule (D-14) forbids dropping that. So outside a Stage the scope queries `/changes` with `rootId: null` (no explorer watch, no `useRootContext()` call, so no `/api/registered-projects` or `/api/workspace-registry` request), the card renders the same counts and rows, a row click or **Review** opens the diff window, and **Show in files**, Open beside and Reveal are not shown. This replaces the `/diffs` request those mounts made, at the same 5 s cadence. The D1 test at `ConversationPanel.test.tsx` line 262 changes from "no `/changes` request" to "no Changes/Files buttons, no registered-projects or workspace-registry request, and exactly one `/changes?scope=conversation` request".
- **D2-4 The diff window gets a permanent entry point.** Removing the inline `DiffPanel` would leave Compare…, vs main, All turns, ignore whitespace and Markdown preview unreachable. The ⋯ menu gains **Full diff in a new window** (after "Open in new window"), shown for every conversation that passes D2-2. It opens `/popout/diff` exactly as DiffPanel's pop-out button does. One helper, `components/chat/diffWindow.ts`, builds the URL for the menu item and for the card outside a Stage.
- **D2-5 Cards group by user turn.** One user turn can spread its changes across several assistant ids (commits on the last edited message, uncommitted edits on the message that made them). The card for a turn aggregates every commit whose `turnId` is one of the turn's assistant ids and every uncommitted file whose `turnIds` contains one of them. It renders once, under the turn's anchor (last assistant message). Grouping reads the server messages (`messagesData.messages`), never optimistic echoes. `role: 'system'` messages do not end a turn. A turn with no matching changes has no card.
- **D2-6 Review opens the turn's files in the dock diff view, not `scope=turn`.** Because the server's `turn` scope filters by one assistant id (§2), **Review** calls `openDock({ tab: 'changes', changesScope: 'conversation', diff: <first file>, diffList: <this turn's files> })`. The dock opens on the first file's diff with "1/N" and previous/next (`J`/`K`) across exactly this turn's files; Back shows the This conversation list. No dock store change is needed for Review.
- **D2-7 Show in files filters the Files tab to this conversation's files.** `OpenDockInput` and `DockState` gain `filesFilter?: 'mine'`, cleared by every `openDock` that does not pass it (like `changesScope`). `ExplorerFiles` applies it on each `openSeq` change when its scope is a conversation (the same resync pattern `ConversationChangesList` uses for `changesScope`, PAN-5291 D1-15). **Show in files** calls `openDock({ tab: 'files', filesFilter: 'mine' })`.
- **D2-8 Card content.** Header: icon, "N files changed" (distinct repo paths), `+a −d` (sum over the turn's file rows), then tags in this order, each only when non-zero: "N commit(s) pushed", "N commit(s) not pushed", "N not committed" (the only amber tag, `badge-bg-state-needs-you`). Right side: **Show in files** (ghost, Stage only) and **Review**. Rows: uncommitted files first, then each commit's files in the response's commit order; one row per path (first occurrence wins). The first 8 rows show; more rows add a "Show all N files" button. Rows reuse `ChangeFileRow` with a new `inset={false}` prop (card padding `pl-3` instead of `pl-8`).
- **D2-9 File chips inside a Stage.** A chip whose absolute path lies inside the conversation's `repoRoot` and maps to a root path:
  - is in the conversation's changes ⇒ click opens its diff in the dock (`openDock({ tab: 'changes', changesScope: 'conversation', diff, diffList: <all conversation targets> })`; an uncommitted entry wins over a committed one; among commits the newest wins);
  - is not in the changes and is not Markdown ⇒ click calls `openBeside({ rootId, path, line })`;
  - is Markdown and not in the changes ⇒ click keeps today's PAN-3260 behavior (the persisted Markdown open target; the operator's saved choice outranks the parent's FR-4 default).
  The context menu keeps every item it has today and adds, at the top: **Open diff** (only when in the changes), **Open beside**, **Reveal in files**. A chip that cannot map (no context, outside the repo or root, or rootId `null`) behaves exactly as today. Outside a Stage chips behave exactly as today (parent FR-4).
- **D2-10 The composer toolbar moves to its own file first.** ComposerFooter has 14 lines of budget. WI-6 moves the toolbar JSX, unchanged, into `components/chat/ComposerToolbar.tsx`; later composer items edit only that file.
- **D2-11 Send menu (parent D-6).** `DeliveryModeSelect.tsx` is deleted and replaced by `components/chat/SendModeMenu.tsx`, a menu button in the picker style (`styles.pickerBtn`, portal dropdown like `EffortPicker`). Button text `Send: <label>`, `title="How your message reaches a busy agent"`, `aria-haspopup="menu"`, disabled when `!sessionAlive` (as today). Items are `role="menuitemradio"` with `aria-checked`:
  | value | label | description | shown when |
  |---|---|---|---|
  | `auto` | normally | "Delivered the usual way for this agent." | always |
  | `steer` | interrupt now | "Stops the current turn and sends now." plus the keycap `Ctrl Enter` (`⌘ Enter` on mac) | always |
  | `follow_up` | after this turn | "Waits until the current turn ends." | `steerKind === 'control-channel'` (Pi) |
  | `when_limit_resets` | when the limit resets | "Holds the message on the server until the usage limit resets." | `scheduleAvailable` |
  The posted values are unchanged. The Steer tooltip text `CLAUDE_STEER_TOOLTIP` moves into SendModeMenu as the `steer` item's `title`. The ⋯ menu's transport selector ("Delivery method", D1) is a different control and does not change.
- **D2-12 "Thinking: <level>" everywhere EffortPicker renders.** The trigger reads `Thinking: <level>` with the level in lower case (`low`, `medium`, `high`, `extra high`, `max`), or `Applying…` while pending. The source moves to the tooltip: `title` = the `title` prop, then (when `chip?.source`) `Source: <EFFORT_SOURCE_LABELS[source]>`, joined by " · ". The dropdown options do not change. This applies in the composer, the New conversation pickers and HomeComposer, because it is the same control.
- **D2-13 The model control looks enabled and explains itself.** `ModelPicker` gains `lockedReason?: string`. When set, the trigger is not `disabled`; a click opens the dropdown containing only a paragraph `data-testid="model-picker-locked-reason"` with the reason, and no model can be picked. The composer passes `disabled={isDisabled}` and `lockedReason` when `!canEditModelBeforeStart`: `agentId` set ⇒ "An agent's model is fixed when it starts."; otherwise ⇒ "The model is fixed once a conversation starts. To use another model, hand off to a new conversation (⋯ → Hand off)." Other ModelPicker callers pass nothing and do not change.
- **D2-14 Toolbar order and style (mockup c5).** Left: attach (`Plus` icon, `title="Attach files"`), ModelPicker, the model-drift chip (kept), EffortPicker, SendModeMenu, the Pi Compact button (kept). Right (after the spacer): ContextWindowMeter, mic, send. The divider (`styles.composerToolbarDivider`) is removed. Attach and mic keep `styles.voiceToolbarButton`.
- **D2-15 Rail closed by default means the collapsed strip.** An unset `overdeck.ui.agentsRailCollapsed` key means collapsed (`!== 'false'`); a stored `'false'` still opens it, a stored `'true'` keeps it collapsed. "Closed" is today's 30 px collapsed strip, which carries the rail's width measurement (`hostRef`) and the reopen click; ⋯ → Subagents (D1) toggles it. `defaultCollapsed` and `toggleSignal` keep their behavior.
- **D2-16 Tabs (mockup c6).** Tabs are 120–230 px (`min-width: 120px; max-width: 230px`; the Home tab has no minimum) with the kind icon, a label that ends in an ellipsis, and `title` = the full label. No shortcut chips on any platform (the bindings stay in the registry and the `?` sheet). The overflow scroll arrows are removed (wheel scrolling and scroll-into-view of the active tab stay). An "N tabs ▾" button sits after the scrolling strip (outside it, so it never scrolls away) and opens a menu listing every tab (icon, label, the active one `aria-checked`); choosing one selects it.
- **D2-17 + menu.** Items, in order: New conversation, Files, Changes in <project> (when the deck has a project), Go to file…, separator, Terminal, Web page. Each shows the keycap of its registered shortcut, read from the registry by id (`deck.new-conversation`, `dock.files`, `dock.changes`, `explorer.quick-open`, `stage.toggle-terminal`) and printed with `formatSpec` for the current platform; an id with no registration or no key for the platform shows no keycap. Labels change: "New terminal" → "Terminal", "Web" → "Web page".
- **D2-18 Untitled conversation tabs read "New conversation".** The `Chat <hash>` fallback is removed (parent FR-18).
- **D2-19 Removed with the inline panel:** the `/diffs` query in `ConversationPanel`, `turnDiffSummaryByAssistantMessageId`, the `?diff=1` URL state, `ConversationDiffPanel`, and `effectiveViewMode`'s diff override (the header gets `effectiveViewMode={viewMode}`). The `/diffs` routes, `DiffPanel`, `lib/turnDiffTree.ts` and the `/popout/diff` route stay; the diff window uses them. A stale `?diff=1` in a URL is ignored.

## 4. Requirements

### Functional
- **FR-1** On a conversation with changes, each user turn whose assistant messages made commits or uncommitted edits ends with one turn card per D2-5/D2-8; the "Changed files" card and `ChangedFilesTree.tsx` are gone.
- **FR-2** Inside a Stage, the card's Review, Show in files, row diff, row Open beside and row Reveal call the dock per D2-6/D2-7/D2-9.
- **FR-3** Outside a Stage, the card shows the same counts and rows; Review and a row click open the diff window (D2-3); Show in files, Open beside and Reveal do not show.
- **FR-4** ⋯ → **Full diff in a new window** opens `/popout/diff` for the conversation (D2-4).
- **FR-5** Inside a Stage, file chips open per D2-9 and their context menu adds Open diff / Open beside / Reveal in files; outside a Stage chips are unchanged.
- **FR-6** The composer's Send control is a menu button with the modes of D2-11, posting the same `deliverAs` values as today.
- **FR-7** The effort control reads "Thinking: <level>" with the source in its tooltip (D2-12).
- **FR-8** The composer's model control is never shown disabled for a started conversation; its menu says why the model cannot change (D2-13).
- **FR-9** The toolbar order is D2-14.
- **FR-10** The subagents rail starts collapsed when nothing is stored (D2-15).
- **FR-11** Stage tabs clamp, show no shortcut chips, and end with "N tabs ▾" (D2-16); the + menu matches D2-17; untitled conversation tabs read "New conversation" (D2-18).

### Non-functional
- **NFR-1** No new polling faster than 5 s: the panel's `/changes` query keeps `useConversationChanges`'s cadence (every 5 s only while `conversation.isWorking`, plus explorer watch batches inside a Stage). The `/diffs` poll is removed from `ConversationPanel`.
- **NFR-2** No file grows past `scripts/lint-file-size.sh`: ComposerFooter ≤ 1000 lines after WI-6; ConversationPanel shrinks; new files ≤ 1000 lines (target ≤ 250).
- **NFR-3** Broadsheet tokens only (load the `pan-style-guide` skill first): no hex colours, one coloured signal per row, amber only for "not committed", additions/deletions with `text-success-foreground` / `text-destructive-foreground` as D1's header does.
- **NFR-4** Light and dark themes both match mockup screen 1 (parent NFR-5); screenshots per parent NFR-6.

## 5. Repo rules that apply (restated)

- The dashboard runs Node 22 from `dist`; run `npm run build` before any live or Playwright check. Never `bun run` the server, never `tsx`.
- Delay-based tests use `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync`; never real `setTimeout` waits.
- Every new frontend test file is added to `scripts/frontend-test-subset.txt` or CI never runs it.
- The test-skip gate counts deleted tests: replace pinned tests, never delete them, and add no `.skip`/`.only`/`skipIf`. New tests must not read source files as text (lint rejects source-grep tests).
- File size: a listed file may not grow past its last allowlist row; agents cannot raise rows — extract a module instead.
- Style guide: `font-medium` for emphasis, no pill badges, no decorative colour, running is blue never green.
- A user-facing change adds `changelog.d/pan-5295.md` (lowercase, per `changelog.d/README.md`; the child stub's `5295.md` is wrong).
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>` from `src/dashboard/frontend`. Never run the full `npm test` on the host.
- Workspaces are git worktrees: never `git checkout` another branch inside one, never `git stash`.

### WI-2 `turn-grouping` — per-user-turn aggregation (pure) — FR-1, D2-5, D2-8

  ```ts
  export interface TurnFileRow { file: ChangedFile; commit?: ChangeCommit; uncommitted?: UncommittedFile }
  export interface TurnChanges {
    anchorId: string            // last assistant id of the user turn
    assistantIds: string[]
    rows: TurnFileRow[]         // uncommitted first, then commits in response order, one row per path
    files: number; additions: number; deletions: number
  ```
