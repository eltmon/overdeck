# PAN-5358: Memory facts: select by relevance into prompts, not only a budget-cut launch list

**Issue:** [PAN-5358](https://github.com/eltmon/overdeck/issues/5358)
**Related:** #293 (semantic memory), #4373 (relevance filter for injection candidates, still open), #1121 (context bloat)
**Planning mode:** `pan plan --auto` (no operator questions; every inferred choice is recorded under "Planning Q&A (auto decisions)").

## Summary

Curated memory facts reach an agent today only through the launch index, which stops at a fixed
character budget in a task-independent order. In the dfai project 89 of 171 active facts never reach
the agent. This change adds curated facts as a ranked candidate source of prompt-time memory
injection (the same path that already injects observations), with its own token budget and a
relevance floor, logs fact selections in `rag-runs`, adds an `always` frontmatter flag whose facts
always lead the launch index, and adds optional semantic re-ranking from fact vectors that the CLI
computes at write time with the docs index's existing `gte-small` embedding path.

Lexical ranking alone satisfies every acceptance criterion. Vectors are additive and best-effort: a
fact with no stored vector is still ranked lexically, and the dashboard server never loads an
embedding model.

## Glossary

- **Curated fact (fact):** one markdown file with YAML frontmatter, parsed into `MemoryFact`
  (`src/lib/memory/facts/store.ts`, `export interface MemoryFact {`, line 26). Three stores:
  project (`<planHome>/.overdeck/memory/`), operator (`~/.overdeck/context/memory/`), machine
  (`~/.overdeck/context/machine-memory/`).
- **Active fact:** a fact whose `review` list is empty (`isActiveFact`, store.ts line 216).
- **Launch index:** the `## Project memory` / `## Operator memory` / `## Machine memory` sections that
  `renderManagedMemorySections` (`src/lib/memory/facts/render.ts`, line 116) renders into every managed
  harness at launch. Budgets: `PROJECT_MEMORY_CHAR_BUDGET = 12_000`, `OPERATOR_MEMORY_CHAR_BUDGET =
  4_000`, `MACHINE_MEMORY_CHAR_BUDGET = 2_000` (render.ts lines 23-25).
- **Omitted fact:** an active fact the launch index did not list because the budget ran out (the index
  ends with `- … N more facts: run \`pan memory list\``).
- **Prompt-time injection:** `injectPromptTimeMemory` (`src/lib/memory/injection.ts`, line 74). It
  gathers candidates (status, OKF knowledge index, pinned docs, observation/summary FTS hits, sibling
  hits), cuts each candidate group to its token budget (`PROMPT_TIME_MEMORY_BUDGETS`, line 14), wraps
  the result in `<overdeck-memory-context format="json">`, and appends one `rag-decision` JSON line to
  `rag-runs/<date>.jsonl`. Surfaces: `user-prompt` (Claude Code `UserPromptSubmit` hook via
  `POST /api/memory/inject`, Pi prompts via `src/lib/agents/runtime-command.ts`) and `spawn`
  (`src/lib/agents/spawn-prep.ts` line 905, the first prompt of every spawned agent).
- **Candidate group (BudgetKey):** the `key` of a `CandidateContext`; each key has its own token budget.
  This change adds the key `facts`.
- **rag-runs log:** `~/.overdeck/memory/<projectId>/<workspaceId>/rag-runs/<YYYY-MM-DD>.jsonl`
  (`resolveRagRunsFile`, `src/lib/memory/paths.ts` line 56). One `PromptTimeRagDecisionLogEntry` per
  injection. Nothing in `src/` reads it back today.
- **Search query:** `buildPromptKeywordQuery(expansion.query)` (`src/lib/memory/search.ts` line 189):
  lowercased distinct content words of the prompt (or of the expanded query), stopwords and words under
  3 characters dropped, at most 12 kept, joined by spaces. When query expansion is off or fails,
  `expansion.query` is the raw prompt. Observation search uses it; fact ranking does not (FR-2).
- **Fact query:** the distinct normalised content words of the full `expansion.query` text, stopwords
  removed, at most 400 (FR-2). It is what the fact ranker scores against.
- **Fact head:** a fact's id words, title, description and tags — the text that names its topic. The
  relevance floor (FR-3) counts only matches in the head.
- **BM25:** the Okapi BM25 lexical relevance score (k1 = 1.2, b = 0.75).
- **Relevance floor:** the rule (FR-3) that decides whether a fact with a non-zero BM25 score may be
  injected at all.
- **Always fact:** a fact whose frontmatter carries `always: true` (new in this change). It leads the
  launch index and is not a prompt-time candidate.
- **Fact vector:** an L2-normalised embedding of one fact's text, computed by the docs embedding
  config (`docs.embedding`, default provider `local`, model `gte-small`, 384 dimensions,
  `src/lib/config-yaml/defaults.ts` lines 135-139).
- **Content hash:** `sha256` hex of the fact's embedding text (FR-11). It keys the vector cache, so the
  same fact text written in a workspace and later merged into the primary checkout reuses one vector.
- **Vector cache:** the derived file `~/.overdeck/cache/memory-fact-vectors.json` (FR-11). It is a cache:
  deleting it only loses semantic re-ranking until the next `pan memory reindex`.
- **Pseudo-relevance centroid:** the technique `src/lib/docs/query.ts` already uses
  (`queryStoredVectorRows`, `centroidVector`): no query embedding; the mean of the stored vectors of
  the top lexical hits stands in for the query vector, and every stored vector is ranked by cosine
  similarity to it.
- **RRF:** reciprocal-rank fusion, `1 / (60 + rank)` summed over the lexical and vector rankings
  (`RRF_K = 60`, the same constant as `src/lib/docs/query.ts`).

## Requirements

### Functional

- **FR-1** Prompt-time injection (both `user-prompt` and `spawn` surfaces) adds curated facts as
  candidates with `key: 'facts'`, read from the project store of the identity's primary checkout
  (`projectMemoryDir(getProjectByKey(identity.projectId).primaryPath)`), the operator store
  (`userMemoryDir()`) and the machine store (`machineMemoryDir()`). Only active facts with
  `always !== true` are candidates.
- **FR-2** Facts are ranked by BM25 against the **fact query**: the distinct `tokenizeForFacts` tokens
  of the full `expansion.query` text (the raw prompt when expansion is off or fails), minus
  `PROMPT_KEYWORD_STOPWORDS`, at most `FACT_QUERY_MAX_TERMS = 400`. It is *not* the 12-term
  `searchQuery`, because that cap keeps only the first 12 words in prompt order: on the spawn surface
  those are orchestration boilerplate, and a long prompt that names its topic late loses it. Id, title,
  description and tags are weighted 2 and body 1.
- **FR-3** Relevance floor, based on the fact's **head** (id words, title, description, tags), which
  states the fact's topic. Let `N` be the number of candidate facts and `df(t)` the number of facts whose
  text contains term `t`. A query term is *discriminating* when `df(t) <= ceil(N / 2)` and *rare* when
  `df(t) <= RARE_DF = max(2, ceil(N * 0.02))`. A fact is eligible only when its BM25 is above 0 and either
  (a) at least 2 distinct discriminating query terms occur in its head, or (b) at least 1 rare query term
  occurs in its head. So "commit and push" needs a fact whose head names both, while a long prompt that
  mentions "elevenlabs" once reaches the one fact whose head names it. At most `FACT_RETRIEVAL_LIMIT = 6`
  facts are returned.
- **FR-4** `PROMPT_TIME_MEMORY_BUDGETS.facts = 1500` tokens. Fact candidates are cut to it by the
  existing `selectWithinBudgets`.
- **FR-5** Each injected fact's content is its description, its body truncated to 1,200 characters
  (with `…` appended when truncated), and a final line `Full fact: pan memory show <flag><id>` where
  `<flag>` is `''`, `'--user '` or `'--machine '` for the project, operator and machine scope.
  Its `source` is `{ id: 'fact:<scope>:<id>', docType: 'fact', scope: <scope>, score, tokens }`.
- **FR-6** The `rag-decision` log entry carries `hitCounts.facts`, `budgets.facts`,
  `allocationBytes.facts`, `allocations.facts`, and one `sources[]` entry with `docType: 'fact'` per
  injected fact.
- **FR-7** A missing, empty or unreadable fact store yields zero fact candidates and never fails or
  delays injection; every other candidate group renders exactly as before.
- **FR-8** Frontmatter accepts `always: true | false`. `parseMemoryFact` rejects a non-boolean value
  with the reason `always must be true or false`. `MemoryFact.always` is `false` when the key is absent.
  `serializeMemoryFact` writes `always: true` only when true, after `tags`.
- **FR-9** The launch index lists always facts first (in the existing type/updated/id order among
  themselves), then the other active facts in the existing order, under the same budget and overflow
  line. Budgets and the overflow line text do not change.
- **FR-10** `pan memory add --always` creates an always fact. `pan memory edit <id> --always` sets the
  flag and `pan memory edit <id> --no-always` clears it; either flag alone counts as a change.
- **FR-11** The vector cache `~/.overdeck/cache/memory-fact-vectors.json` holds
  `{ version: 1, provider, model, dimensions, vectors: { <contentHash>: <base64 Float32 LE> } }`.
  Embedding text is `[title, description, tags.join(', '), body].join('\n').slice(0, 2000)`; the content
  hash is `sha256` hex of that text. A cache whose provider, model or dimensions differ from the current
  `docs.embedding` config is treated as empty. Writes are atomic (temp file + `rename`). Entries are
  never pruned automatically.
- **FR-12** When the vector cache holds vectors for some candidates, the ranker fuses lexical and vector
  rankings by RRF. The query vector is the pseudo-relevance centroid of the vectors of the top 3
  eligible lexical facts. A fact that fails the relevance floor joins the result only when its cosine
  similarity to the centroid is at least `VECTOR_ONLY_MIN_SIMILARITY = 0.90`. With no eligible lexical
  fact, or no vectors, the result equals the lexical-only result.
- **FR-13** `pan memory add` and `pan memory edit` refresh the vector cache for the written store after a
  successful write, best-effort, bounded by `FACT_VECTOR_REFRESH_TIMEOUT_MS = 30_000`. A failure or
  timeout prints `vector index not refreshed: <reason>; run pan memory reindex` to stderr and never changes
  the exit code or the JSON output. The timeout cannot cancel a model load or download, and the CLI does
  not force-exit after a successful command (`runCliWithTelemetry`, `src/cli/telemetry.ts`), so on a
  **timeout** the command finishes its output and then calls `await exitCli(0)` (`src/cli/exit.ts`); a
  still-running load can then never keep `pan memory add` (or an MCP `memory_add` job) alive.
- **FR-14** New command `pan memory reindex [--project <key>] [--json]` refreshes the vector cache for the
  project store (the same target `pan memory list` reads) plus the operator and machine stores, prints
  one line per store (`project: <embedded> embedded, <reused> reused`), and exits 1 when embedding fails.
- **FR-15** `pan memory sync`, after a `synced` outcome, refreshes the operator store's vectors
  best-effort (same rule as FR-13).

### Non-functional

- **NFR-1** The dashboard server process never imports `@huggingface/transformers` and never calls an
  embedding API. Prompt-time ranking reads stored vectors only.
- **NFR-2** Fact retrieval adds no network call to prompt-time injection and at most 25 ms on a store of
  200 facts (sync reads of small files plus in-memory BM25; the vector cache is parsed once per
  `mtimeMs`/`size` pair and memoised in-process).
- **NFR-3** With no fact candidates, the context string of every existing test is byte-identical (the
  `injection.test.ts` snapshot stays unchanged).
- **NFR-4** Tests use injected embedding functions and never load a model or touch the network; any test
  of the refresh timeout uses `vi.useFakeTimers()`.

## Decisions

- **D1 Lexical first, vectors additive.** All three acceptance criteria are met by BM25 plus the floor.
  Vectors only re-rank and can add near-duplicates of lexical hits.
- **D2 No query embedding.** Measured cold load is ~630 ms and +~250 MB RSS (Current state 6), so the
  prompt is never embedded. The pseudo-relevance centroid reuses the docs index technique.
- **D3 Reuse the docs embedding path.** A new export `embedText(text, config)` in
  `src/lib/docs/index-builder.ts` wraps `createDocsEmbeddingFunction(config)`; facts follow the operator's
  `docs.embedding` setting (default local `gte-small`). No third embedding stack.
- **D4 The launch index does not shrink.** Codex, opencode, kimi-code, grok and acp agents have no
  per-turn injection, and per-turn injection is also absent when `memory.features.prompt_time_injection`
  is off or the hook times out. On day one no fact carries `always`. So budgets and the overflow line stay;
  always facts only move to the front. Shrinking the budget is a follow-up once `rag-runs` fact logs show
  retrieval coverage.
- **D5 Always facts are excluded from prompt-time candidates** because the launch index always lists them
  first. Other facts already listed in the launch index stay candidates: the index carries one line, the
  injection carries the body, which is the detail the index tells agents to open.
- **D6 No per-session dedupe.** A relevant fact may be injected on several turns, the same as observations
  today.
- **D7 Same wrapper.** Facts go inside the existing `<overdeck-memory-context>` JSON wrapper and its
  notice. The launch index already frames facts as curated; changing trust framing is out of scope.
- **D8 Primary checkout for the project store,** the same store the launch index renders (and the same
  `getProjectByKey(...).primaryPath` that `readPinnedDocCandidates` uses).
- **D9 Global content-hash vector cache, no automatic pruning.** One entry per distinct fact text
  (~2 KB each); facts change rarely. Model/config change discards it.
- **D10 Contract change is additive.** `docType` gains `"fact"`; `allocations.facts` is
  `Schema.optional(Schema.Number)` so any stored payload without it still decodes.
- **D11 `matchMemoryFacts` and `pan memory search` keep their current AND semantics** in this change.
- **D12 New code lives in new modules** `src/lib/memory/facts/rank.ts` (pure ranking) and
  `src/lib/memory/facts/vectors.ts` (cache I/O and refresh); `injection.ts` gains only the default loader.

## Design

### Ranker (`src/lib/memory/facts/rank.ts`)

```ts
export const FACT_RETRIEVAL_LIMIT = 6;
export const FACT_QUERY_MAX_TERMS = 400;
export const VECTOR_ONLY_MIN_SIMILARITY = 0.9;

export interface RankedFact {
  readonly fact: MemoryFact;
  readonly score: number;          // RRF score when fused, BM25 otherwise
  readonly bm25: number;
  readonly headMatches: number;    // distinct discriminating query terms found in the fact's head
  readonly similarity?: number;    // cosine to the centroid, when vectors were used
}

/** Lowercased letter/number runs of length >= 3, with a light suffix strip. */
export function tokenizeForFacts(text: string): string[];

export function rankFactsForQuery(input: {
  facts: readonly MemoryFact[];
  query: string;                                   // the full expansion.query text (raw prompt by default)
  vectors?: ReadonlyMap<string, Float32Array>;     // keyed by fact.file; absent → lexical only
  limit?: number;                                  // default FACT_RETRIEVAL_LIMIT
}): RankedFact[];
```

Algorithm (all deterministic):

1. `tokenizeForFacts(text)`: `text.toLowerCase().match(/[\p{L}\p{N}]+/gu) ?? []`, keep tokens of length
   >= 3, then normalise each token in two steps, applied identically to query and fact text:
   (a) strip at most one suffix, first match wins: `ing` when the remainder is >= 4 characters, else `ed`
   when the remainder is >= 4, else a final `s` that is not part of `ss` when the remainder is >= 3;
   (b) then drop one final `e` when the remainder is >= 4. Results: `merge`, `merges`, `merged`,
   `merging` → `merg`; `cache`, `caches`, `cached` → `cach`; `issue`, `issues` → `issu`; `update`,
   `updated` → `updat`; `reconnect`, `reconnecting` → `reconnect`. Do not strip `es` as one suffix: that
   splits e-stems (`merges` → `merg` while `merge` stays `merge`).
2. Query terms = distinct `tokenizeForFacts(query)` tokens whose *raw* lowercase form is not in
   `PROMPT_KEYWORD_STOPWORDS`, in first-seen order, at most `FACT_QUERY_MAX_TERMS`. No terms → `[]`.
   `PROMPT_KEYWORD_STOPWORDS` is the existing `KEYWORD_STOPWORDS` set in `src/lib/memory/search.ts`
   (line 179), renamed and exported read-only (`export const PROMPT_KEYWORD_STOPWORDS: ReadonlySet<string>`);
   `buildPromptKeywordQuery` keeps using it, so its behaviour does not change.
3. Per fact: `head = tokenizeForFacts([id.replace(/-/g, ' '), title, description, tags.join(' ')].join(' '))`,
   `body = tokenizeForFacts(body)`. `tf(t) = 2 * count(head, t) + count(body, t)`;
   `len = 2 * head.length + body.length`; `avgLen` = mean `len` (use 1 when 0).
4. `df(t)` = number of facts with `tf(t) > 0`; `N = facts.length`;
   `idf(t) = ln(1 + (N - df + 0.5) / (df + 0.5))`;
   `bm25 = Σ idf(t) * tf * 2.2 / (tf + 1.2 * (0.25 + 0.75 * len / avgLen))`.
5. Floor (FR-3): `discriminating(t) = df(t) <= Math.ceil(N / 2)`;
   `rare(t) = df(t) <= Math.max(2, Math.ceil(N * 0.02))`. `headMatches` = distinct discriminating query
   terms with `count(head, t) > 0`. Eligible when `bm25 > 0 && (headMatches >= 2 || some query term t
   has rare(t) && count(head, t) > 0)`.
6. Lexical order: eligible facts by `bm25` desc, then `fact.id` asc, then `fact.file` asc.
7. Without vectors (or with no eligible fact that has a vector): return the first `limit` of the lexical
   order with `score = bm25`.
8. With vectors: centroid = normalised mean of the vectors of the first 3 eligible facts that have one.
   `similarity = dot(centroid, v)` for every fact with a vector. Vector order: facts with a vector whose
   `similarity >= VECTOR_ONLY_MIN_SIMILARITY` or that are eligible, by `similarity` desc.
   `score = Σ 1 / (60 + rank)` over the lists the fact appears in. Return the union sorted by `score`
   desc, then `bm25` desc, then `id`, first `limit`.

**Implementation checkpoint (WI-8):** before committing, run the ranker over this machine's operator
store with vectors built by `pan memory reindex` and print the similarity distribution for three
prompts. If more than 3 vector-only facts per prompt clear 0.90, raise the constant to the lowest value
in `{0.92, 0.94}` that brings it to 3 or fewer and record the measurement in the commit message.
Fallback when no vectors can be built on the machine: keep 0.90.

`DocsEmbeddingConfig` is `NormalizedDocsConfig['embedding']` from `src/lib/config-yaml.js`.
`readFactVectors` memoises the parsed map keyed by `${mtimeMs}:${size}` of the file and returns an empty
map when the file is missing, unparseable, has `version !== 1`, or its provider/model/dimensions differ
from `config`. Vectors are stored as base64 of little-endian Float32 bytes; use
`float32ArrayToBuffer`/`bufferToFloat32Array` from `src/lib/docs/index-builder.ts`.

### Embedding export (`src/lib/docs/index-builder.ts`)

```ts
/** PAN-5358: embed one text with the docs embedding config; returns a normalised vector. */
export async function embedText(text: string, config: NormalizedDocsConfig['embedding']): Promise<Float32Array> {
  const output = await createDocsEmbeddingFunction(config)({
    chunk: { docPath: '', docKind: 'docs', sectionHeading: null, sectionAnchor: null, headingPath: [], content: text, tokenCount: 0 },
    dimensions: config.dimensions,
    model: config.model,
    provider: config.provider,
  });
  return normalizeFloat32Embedding(resolveDocsEmbeddingOutput(output).embedding, config.dimensions);
}
```
