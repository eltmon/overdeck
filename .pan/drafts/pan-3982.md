# PAN-3982 — Palette conversation hits 404: restore unregistered-session reads, open subagent hits through the parent conversation

**Issue:** https://github.com/eltmon/overdeck/issues/3982
**Branch:** `feature/pan-3982` · planned 2026-09-21 against `b42c8a7829c`
**Mode:** `pan plan --auto` (decisions recorded in the xBRIEF `autoDecisions`)

## Glossary

- **Palette hit** — one row in the Cmd-K palette's *Conversations* group. Produced server-side by `runPaletteSearch` (`src/dashboard/server/routes/palette.ts`) from a **chunk** in the conversation-search index; the frontend opens it through `handleOpenConversationHit` (`src/dashboard/frontend/src/App.tsx`).
- **Chunk** — one row of the `chunks` table in the embeddings sidecar DB (`src/lib/database/conversation-embeddings-db.ts`), keyed `UNIQUE(session_id, byte_offset)`. `byte_offset` points into the JSONL file the chunk came from.
- **Session id (index)** — `chunks.session_id`. Today it is always the JSONL basename without `.jsonl` (`sessionIdFromPath`, `src/lib/conversation-search/indexer.ts:370`). For a top-level Claude session that is the session UUID; for a subagent transcript it is `agent-<hex>`.
- **Registered conversation** — a row in the `conversations` table, looked up by `getConversationByName` / `getConversationByClaudeSessionId` (`src/lib/overdeck/conversations.ts`). Its `name` (e.g. `20260920-9886`) is what the frontend routes on.
- **Unregistered session** — an indexed top-level Claude transcript (`~/.claude/projects/<enc-cwd>/<uuid>.jsonl`) with no `conversations` row. Most of the index is this (Jul 30 census: 70 %). The Stage already synthesizes a read-only conversation for a UUID-shaped `conversationId` (`src/dashboard/frontend/src/components/Stage/index.tsx:126-160`, `:288-291`); only the server read paths are missing.
- **Subagent transcript** — `~/.claude/projects/<enc-cwd>/<parent-uuid>/subagents/agent-<hex>.jsonl`, with a sibling `agent-<hex>.meta.json` (`docs/CONVERSATION-SUBAGENTS.md`). Verified 2026-09-21: 2 117 such files on this machine, every one with a meta file; 2 115 of the 3 996 `file_cursors` rows in the live index are subagent files.
- **Bare subagent id** — the `<hex>` part after `agent-`. This is `SubagentSummary.agentId` (`src/dashboard/server/services/conversation/subagents.ts:70`), the `?agentId=` value on `GET /api/conversations/:name/messages` (`subagentTranscriptPath` re-adds the `agent-` prefix, `subagents.ts:84`), and the `?subagent=` URL param the rail selects with (`src/dashboard/frontend/src/components/chat/SubagentRail.tsx:17-27`).
- **Parent session id** — the `<parent-uuid>` directory name a subagent transcript sits under. New in this issue: stored on every subagent chunk as `chunks.parent_session_id`.
- **Locator** — `GET /api/conversations/:name/message-locator?byteOffset=N` → `{ messageId, messageIndex, sequence, byteOffset }` (`src/dashboard/server/services/conversation-message-resolver.ts`). The frontend uses it to scroll the timeline to the hit.
- **Message target** — the pane fields `targetMessageId` / `targetMessageIndex` / `targetMessageNonce` (`src/dashboard/frontend/src/lib/panesStore.ts:47-49`) that `MessagesTimeline` consumes once and then reports via `onTargetMessageHandled` (`src/dashboard/frontend/src/components/chat/messagesTimeline/MessagesTimeline.tsx:372-377`).

## Problem

Clicking a *Conversations* palette hit toasts `Unable to locate matching message (404) · no dashboard conversation row` for two classes of indexed transcripts.

1. **Regression — unregistered top-level sessions.** PAN-3950 (`1446555ff40`) deleted `resolveUnregisteredClaudeSessionFile` and its `CLAUDE_SESSION_UUID_PATTERN` from `src/lib/overdeck/conversation-reads.ts`. Both read paths now return 404 for any name that is not a `conversations` row:
   - `getConversationMessagesRead` (`conversation-reads.ts:471-479`): `if (!conv) return result({ error: 'Conversation not found', lookedUp: name }, 404);`
   - `getConversationMessageLocator` (`conversation-reads.ts:555-563`): same guard after `getConversationByName(name) ?? getConversationByClaudeSessionId(name)`.
   The PAN-3950 PRD (`.pan/drafts/pan-3950.md` W3) asked only to delete "the global session-UUID scan for `agent-*` names"; the implementation also removed the bare-UUID fallback that `5d9ed79423` (Jul 30) added to fix exactly this 404.
2. **Subagent transcripts were never openable end-to-end.** The indexer sweeps `subagents/` dirs (`indexer.ts:336-352 collectJsonlFiles`), so hits carry `sessionId = agent-<hex>`. A by-id sweep for that shape existed Aug 9 → Sep 20 (`1901ffb69d2`, also removed by PAN-3950), but the Stage only synthesizes a read-only conversation for UUID-shaped ids (`Stage/index.tsx:289`), so even when the locator returned 200 the pane spun on "Starting…". The operator directive replaces that design: a subagent hit opens the **parent** conversation with the subagent selected.

## Desired behaviour (operator directive, verbatim intent)

- A subagent-transcript hit opens the parent agent's conversation (parent UUID → `conversations` row when one exists, else the read-only unregistered view), with that subagent selected in the conversation view's Agents rail and the timeline scrolled to the hit.
- When the parent conversation belongs to a project, the existing `handleOpenConversationHit` routing (project + pane) applies unchanged — it only needs resolution to succeed.
- Unregistered UUID sessions open read-only again (restore the Jul 30 fallback, exact-UUID sweep only, no composer).

## Decisions

- **D-1 Add a nullable `parent_session_id` column; never overload `session_id`.** `UNIQUE(session_id, byte_offset)` (`conversation-embeddings-db.ts:144`) means a parent chunk and a subagent chunk at the same byte offset would overwrite each other if the subagent chunk stored the parent UUID in `session_id`. `filterLiveHits` (`src/dashboard/server/services/conversation-search-service.ts:105-119`) and `pruneStaleIndexedSessions` (`indexer.ts:296-311`) both match `hit.sessionId` against `sessionIdFromPath(cursorPath)`, which only holds while `session_id` stays the file basename. So `session_id` keeps meaning "the indexed file"; `parent_session_id` is the new, nullable pointer.
- **D-2 Backfill existing subagent chunks in a one-shot schema migration, not by reindexing.** 2 115 cursors are already at EOF, so incremental indexing never rewrites their chunks, and a full reindex re-embeds every chunk (embedding credits are exhausted on this machine). `file_cursors.file_path` is absolute, and `UPDATE chunks SET parent_session_id = ? WHERE session_id = ?` is served by the UNIQUE index, so the backfill is ~2 k indexed updates run once inside `openEmbeddingsDb`.
- **D-3 One subagent id spelling on the wire: bare `<hex>` everywhere except filenames.** The index keeps `session_id = agent-<hex>` (D-1); the palette route strips the prefix once (`subagentId`); `?agentId=` on both `/messages` and `/message-locator` and the pane's `targetSubagentId` are bare; `subagentTranscriptPath` re-adds the prefix when it builds the path. Rule: `subagentId = sessionId.replace(/^agent-/, '')`.
- **D-4 The unregistered fallback accepts only the exact Claude UUID shape.** `CLAUDE_SESSION_UUID_PATTERN = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`, calling `findClaudeSessionFileById` (`src/lib/overdeck/claude-session-file-search.ts:64`, memoized). `agent-*` names (work agents and subagents alike) never trigger a sweep and keep returning `{ error: 'Conversation not found', lookedUp }` 404 — this preserves the PAN-3950 W3 contract.
- **D-5 Delete `findSubagentTranscriptById`.** It has no production caller since PAN-3950, and this issue decides that subagent transcripts are reached through the parent. Keeping it invites a future re-add of the 404-then-spin path.
- **D-6 Scope the message target to the subagent on the pane.** `MessagesTimeline.targetMessageRow` (`MessagesTimeline.tsx:321-336`) falls back to `targetMessageIndex` when `targetMessageId` misses, then calls `onTargetMessageHandled`, which `AgentPane` uses to clear the pane target (`Stage/panes/AgentPane.tsx:37-41`). A subagent locator handed to the main `ConversationView` while `subagents` is still loading would scroll the wrong transcript and consume the target. So the pane carries `targetSubagentId`; `ConversationView` receives target props only when it is unset; `SubagentTranscript` receives them only when its subagent matches.
- **D-7 Apply the subagent selection from inside `ConversationPanel`, not `App`.** `setConversationRoute` runs `history.replaceState` inside a `setConversationViewModes` updater (`App.tsx:198-211`), while `updateSelectedSubagent` does `pushState` + a synthetic `popstate` (`SubagentRail.tsx:20-27`); calling both from `handleOpenConversationHit` is order-fragile under React batching. `ConversationPanel` calls `updateSelectedSubagent(targetSubagentId)` once `messagesData.subagents` contains that id, keyed on `targetMessageNonce` so it fires once per open.
- **D-8 Codex subagents are out of scope.** The indexer's only root is `~/.claude/projects` (`indexer.ts:366-368 defaultConversationRoots`), so Codex child threads never appear as hits.
- **D-9 Migration must tolerate concurrent handles.** `openEmbeddingsDb` is called by the indexer, the search service, the settings route, and tests, often overlapping. The migration guards on `PRAGMA table_info(chunks)` *and* catches SQLite's `duplicate column name` error, and the backfill is idempotent (`WHERE parent_session_id IS NULL`).

## Requirements

- **FR-1** `GET /api/conversations/<uuid>/messages` for an indexed top-level Claude session with no `conversations` row returns the transcript messages (HTTP 200), resolved by an exact `<uuid>.jsonl` search under `~/.claude/projects/`.
- **FR-2** `GET /api/conversations/<uuid>/message-locator?byteOffset=N` for the same session returns the locator (HTTP 200). A UUID with no transcript anywhere, a non-UUID name, and any `agent-*` name return 404 without calling `resolveSessionFile` or sweeping.
- **FR-3** Every chunk indexed from `<projects>/<enc>/<parent-uuid>/subagents/agent-<hex>.jsonl` stores `parent_session_id = <parent-uuid>`; chunks from top-level transcripts store `NULL`.
- **FR-4** Opening an existing schema-v1 embeddings DB adds the column and backfills `parent_session_id` for every subagent file already in `file_cursors`, once, without re-embedding; a second open is a no-op.
- **FR-5** A palette hit whose chunk has a `parent_session_id` reports `conversationId` = the parent's conversation name (or the parent UUID when unregistered), `projectKey` resolved from the parent, `parentSessionId`, and a bare `subagentId`. Hits without a parent are unchanged.
- **FR-6** `GET /api/conversations/:name/message-locator?byteOffset=N&agentId=<bare>` resolves the byte offset against `<parent-session-dir>/subagents/agent-<bare>.jsonl`; an id that fails `subagentTranscriptPath` returns HTTP 400 `{ error: 'Invalid subagent id' }`; a parent that cannot be resolved returns 404 carrying `lookedUp`.
- **FR-7** Clicking a subagent hit opens the parent conversation pane in the parent's project deck, selects that subagent in the Agents rail, and scrolls the subagent transcript to the hit message. The main-agent timeline never consumes the target.
- **FR-8** The palette row for a subagent hit is labelled `Subagent of Conversation <name>` or `Subagent of Claude session <8 chars of parent uuid>`.
- **NFR-1** No new polling or timers: the migration is synchronous at open; the frontend selection is an effect keyed on data already fetched.
- **NFR-2** All new tests use the existing fixture patterns (fake `homedir` via `OVERDECK_TEST_FAKE_HOMEDIR`, temp dirs, `fakeDb`/`fakeProvider`). No test touches `~/.claude` or the live embeddings DB.
- **NFR-3** `docs/DASHBOARD-ARCHITECTURE.md` and `docs/CONVERSATION-SUBAGENTS.md` state the new rules (see W8); the `conversation-reads.ts` module header stops claiming the module never scans global transcript directories.

### W3 — Schema v2 migration with one-shot backfill (FR-4) · `migrate-backfill-parent`

Files: `src/lib/database/conversation-embeddings-db.ts`, `src/lib/database/__tests__/conversation-embeddings-db.test.ts`.

2. New `migrateSchema(db)` called from `openEmbeddingsDb` right after `initSchema(db, dimensions)` (`:350`), inside the same try/catch:
   ```ts
   function hasColumn(db: SqliteDatabase, table: string, column: string): boolean {
     return (db.pragma(`table_info(${table})`) as Array<{ name: string }>).some((c) => c.name === column);
   }

   /** v1 → v2: nullable parent pointer for subagent chunks, backfilled from the
    *  absolute cursor paths so already-indexed subagent files need no re-embed. */
   function migrateSchema(db: SqliteDatabase): void {
     if (!hasColumn(db, 'chunks', 'parent_session_id')) {
       try {
         db.exec('ALTER TABLE chunks ADD COLUMN parent_session_id TEXT');
       } catch (err) {
         // Another handle on the same file won the race (D-9).
         if (!/duplicate column name/i.test(String(err))) throw err;
       }
     }
     const backfill = db.prepare('UPDATE chunks SET parent_session_id = ? WHERE session_id = ? AND parent_session_id IS NULL');
     const cursors = db.prepare('SELECT file_path FROM file_cursors').all() as Array<{ file_path: string }>;
     db.transaction(() => {
       for (const { file_path } of cursors) {
         const parent = parentSessionIdFromPath(file_path);
         if (parent) backfill.run(parent, sessionIdFromPath(file_path));
       }
     })();
     db.prepare('INSERT OR REPLACE INTO db_config(key, value) VALUES (?, ?)').run('schema_version', String(SCHEMA_VERSION));
     if ((db.pragma('user_version', { simple: true }) as number) < SCHEMA_VERSION) db.pragma(`user_version = ${SCHEMA_VERSION}`);
   }
   ```
   Gate the backfill loop on `user_version < 2` so a fully migrated DB pays one `PRAGMA` per open, not 4 k `UPDATE`s. `initSchema` keeps its own `schema_version`/`user_version` writes but must not bump past what `migrateSchema` sets (simplest: move both stamps into `migrateSchema` and delete them from `initSchema` `:189-192`).
