# PAN-4263 — Forge PR lookups: failure is not absence, the open PR wins, lost verdicts are replayed

**Issue:** [PAN-4263](https://github.com/eltmon/overdeck/issues/4263)
**Planned:** 2026-09-27 against `main` @ `6faff792632`

## Glossary

- **Forge** — the code host that owns the review artifact: GitHub (`gh` CLI or the GitHub App REST client) or GitLab (`glab`).
- **Review artifact** — the PR (GitHub) or MR (GitLab) for an issue's `feature/<issue>` branch.
- **`discoverArtifact`** — `ForgeAdapter.discoverArtifact` in `src/lib/forge.ts`, plus the Effect wrapper of the same name at the bottom of that file. Answers "which review artifact stands for this branch?"
- **App path / gh path** — the two branches of `getExistingGitHubArtifact` (`src/lib/forge.ts`). The App path runs only when `isGitHubAppConfigured()` is true **and** the caller passed `repository` (`owner/repo`). The gh path runs otherwise.
- **Absence** — the forge answered and there is no artifact. **Failure** — the forge did not answer (rate limit, network, auth, timeout).
- **Transient forge failure** — a failure that can succeed on retry: rate limit (primary or secondary), network reset/timeout/DNS, HTTP 502/503/504.
- **Merge gate** — `evaluateIssueMergeGate` → `getPrFacts` → `fetchIssuePullRequest` → `resolveIssuePullRequestRef` → `lookupPullRequestForBranch` (`src/lib/github-pr-lookup.ts`). Its `facts.url` is the PR the gate judged.
- **Merge set** — the `merge_sets` / `merge_set_repos` rows in `~/.overdeck/overdeck.db` (`src/lib/merge-set.ts`, `src/lib/overdeck/merge-sync.ts`). `merge_set_repos.artifact_url` is a URL persisted when a PR was first opened; nothing refreshes it.
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl` (`src/lib/cloister/pipeline-journal.ts`): append-only, never authority, never fatal.
- **deacon-lite** — the 60 s patrol in the deacon child process (`src/lib/cloister/deacon-lite.ts`). `recoverStalledReviews` is its review routine.
- **Deferred verdict** — a review verdict whose recording failed for a transient forge reason, saved as a `review.verdict-deferred` journal entry so deacon-lite can record it later.

## Root cause (verified during planning)

### Stall 1 — approved reviews never recorded (PAN-4222, PAN-3634)

`src/cli/commands/specialists/done.ts` lines 162–170:

```ts
  const artifact = await Effect.runPromise(
    discoverArtifact(forge, { sourceBranch, cwd: workspacePath }),
  );
  if (!artifact?.url) {
    console.error(chalk.red(
      `No open review artifact for ${sourceBranch}; run \`pan done ${normalizedIssueId}\` to open one before recording a verdict.`,
```

No `repository` is passed, so `getExistingGitHubArtifact` takes the **gh path** (`src/lib/forge.ts` lines 174–187):

```ts
  const { stdout } = await execAsync(
    `gh pr view ${branchName}${buildRepositoryFlag(repository)} --json url,number 2>/dev/null || true`,
```

`2>/dev/null || true` turns every gh failure — including `GraphQL: API rate limit already exceeded` — into empty stdout, which returns `null`, which prints "No open review artifact". Verified on this machine: gh 2.92.0 prints `no pull requests found for branch "<branch>"` on stderr with exit 1 for true absence.

Once the reviewer's `specialists done` fails, nothing retries it. The journal tail stays `review.dispatched`, the synthesis parent is still alive at its prompt, so `recoverDeadSynthesis` returns `cool-down` forever (`deacon-lite.ts`, `if (verdict.alive) return { action: 'cool-down' };`).

### Stall 2 — merge targets a closed PR (PAN-3668)

The issue body blames the App path's `prs[0]` (`forge.ts` line 164). **That code is unreachable in the stalled flows**: no production caller of `discoverArtifact` or `createReviewArtifact` passes `repository` (verified: `grep -rn "repository:" src` finds none at forge call sites). The actual cause is in `src/dashboard/server/routes/workspaces/merge-ops.ts` line 867:

```ts
    const artifactUrl = primaryRepo?.artifactUrl || prResult.prUrl;
```

`primaryRepo` is the persisted merge-set row. For PAN-3668 it reads (verified in `overdeck.db`):

```
merge_set_repos: issue_id=PAN-3668 artifact_url=https://github.com/eltmon/overdeck/pull/3670 artifact_id=3670
```

#3670 is the first, now-CLOSED PR. `ensurePRExists` (which already prefers `OPEN`) returned #4251, but the stale stored URL won, and `mergeTargetRefusal` then refused: "the merge gate passed #4251, but the merge would land #3670". The remote-workspace twin at line 466 has the same shape (`remotePrimaryRepo?.artifactUrl || prResult.prUrl`).

The `prs[0]` pattern is still a real latent bug in two places and is fixed here too: `forge.ts` line 164 (App path) and `src/lib/github-pr-lookup.ts` line 24 (`lookupPullRequestForBranch`, which the **merge gate** uses; its gh twin uses `--limit 1`). GitHub REST `GET /pulls?head=…&state=all` and `gh pr list` both sort by creation date, so a newer closed PR beats an older open one today.

## Requirements

- **FR-1** — The gh path of `discoverArtifact` returns `null` only when gh reports `no pull requests found for branch`; every other gh failure throws an `Error` whose message contains gh's stderr.
- **FR-2** — `discoverArtifact` returns only an **open** artifact or `null` on every path (gh, App, glab). On the App path, with several open PRs on one head, it returns the most recently updated; on the gh path the choice among several open PRs is gh's own (rare: it needs different bases). Closed and merged PRs are returned only by `findMergedArtifact`.
- **FR-3** — The merge gate's branch lookup (`lookupPullRequestForBranch`) ranks open (most recently updated) above merged (most recent merge) above closed (most recently updated), on both the App and gh paths.
- **FR-4** — Transient forge failures in `discoverArtifact` retry with backoff (3 attempts total, delays 2 s then 8 s) before the error surfaces.
- **FR-5** — The merge path lands the PR it freshly resolved, never a stale persisted `artifact_url`; a stale stored URL is overwritten.
- **FR-6** — `pan admin specialists done` separates failure from absence: a lookup failure prints `Couldn't reach <forge> to find the review artifact for <branch>: <reason>` and exits 1; only true absence prints "No open review artifact".
- **FR-7** — A review verdict whose recording fails for a transient reason is journaled as `review.verdict-deferred` and deacon-lite replays it through the same CLI door until it records, is superseded, or the replay cap is reached.
- **FR-8** — `getExistingGitLabArtifact` stops swallowing `glab` failures the same way (absence = empty list).
- **NFR-1** — Retry/backoff tests use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`; no real waits (repo rule `fake-timers-for-retry-tests`).
- **NFR-2** — No `execSync` anywhere these changes reach (the forge module is dashboard-server-reachable; repo rule `no-execsync-server`).
- **NFR-3** — The review-verdict trust gate (`reviewVerdictRefusal` / `verdictCallerFromEnv`) is never weakened: a replay runs the full guard chain again under the original caller's identity.
- **NFR-4** — `docs/PIPELINE-GATES.md` describes the retry, the deferred-verdict entry types and the replay.

## Decisions (made here, not left to the implementer)

- **D1 — `discoverArtifact` means "the open artifact".** Both GitHub paths return open-only. Per-caller consequence: `createReviewArtifact` (`pan done`, `review-artifacts.ts`) now opens a fresh PR when the only existing PR is closed (matches `ensurePRExists`' comment "A closed unmerged PR must not prevent a fresh PR"); `merge-ops.ts` lines ~546 and ~1452 fall through to `assessRepoMergeCompleteness` for a merged-only branch, which classifies it `merged` — the correct answer. `merge-ops.ts` ~1347 (forge-approve) already treats null and throw the same (`approved: true`).
- **D2 — Keep `gh pr view <branch>`** for the gh path (it already prefers an open PR; verified: `gh pr view feature/pan-3668` → `{"number":4251,"state":"OPEN"}`). Add `state` to `--json` and return `null` unless `state === 'OPEN'`. Do not switch to `gh api` REST.
- **D3 — Transient classifier** lives in a new module `src/lib/forge-transient.ts`: `isTransientForgeError(err: unknown): boolean` matches the error message (plus `stderr` when present) against `/rate limit|secondary rate|abuse detection|ECONNRESET|ETIMEDOUT|ENOTFOUND|EAI_AGAIN|ECONNREFUSED|socket hang up|timed out|(?:failed: |HTTP )50[234]\b/i`. The status-code alternative is anchored to how the clients format it (`githubApiWithToken` throws `… failed: 503 <text>`; gh prints `HTTP 502: …`) so a PR number such as `/pull/504` inside a message never classifies as transient. `retryTransientForgeOp<T>(op: () => Promise<T>, delaysMs = [2000, 8000]): Promise<T>` retries only transient errors; a non-transient error throws immediately.
- **D4 — Retry wraps `discoverArtifact` only** (both adapters' `discoverArtifact` methods). `createReviewArtifact`'s pre-create lookup is not retried (a failure aborts `pan done` with the real error, which is already honest).
- **D5 — Post-create id lookup cannot lose a PR.** In `githubForgeAdapter.createReviewArtifact`, the lookup after `gh pr create` is wrapped: on throw, `id` comes from `parseArtifactRef(url)?.number`.
- **D6 — Merge path uses the fresh URL.** `merge-ops.ts` monorepo (~867) and remote (~466) set `artifactUrl = prResult.prUrl` and `artifactId = String(parseGitHubPullRequestUrl(prResult.prUrl)?.number ?? '')` (or `undefined` when unparsable). When the stored row's `artifactUrl` is set and differs (case-insensitive, trailing slash ignored), rewrite it with `withRepoArtifactUrl(mergeSet, primaryRepo.repoKey, prResult.prUrl, artifactId)` + `upsertMergeSet(...)` and log `[merge] replacing stale stored artifact <old> with <new> for <issue>`.
- **D7 — Identity check before any forge call in `specialists done`.** For role `review`, compute `caller = verdictCallerFromEnv(process.env, readAncestorAgentIds)` before `discoverArtifact`. If `caller.kind === 'agent'` and `!isIssueReviewSession(caller.id, issueId)`, refuse immediately with the existing refusal path (journal `review.verdict-refused`, activity warn, exit 1). Only a caller that passed this check can leave a deferral behind.
- **D8 — What defers.** Role `review` only. Two triggers: (a) `discoverArtifact` throws and `isTransientForgeError(err)`; (b) `postReviewVerdict` returns `posted: false` and `isTransientForgeError(result.reason)`. Test/UAT verdicts get the honest error and exit 1 but no deferral (NonGoal).
- **D9 — Deferred entry shape.** `appendPipelineEntry(workspacePath, { type: 'review.verdict-deferred', issueId, source: 'pan-specialists-done', data: { status, runId, notes, callerId, reason } })`. `runId` = `options.runId` or the review parent's `reviewRunId` (same fallback `done.ts` already uses). `notes` is capped at 100 000 **bytes** (`Buffer.byteLength(notes, 'utf-8')`), truncated on a character boundary, with the suffix `\n\n[notes truncated by deferred-verdict replay]` (Linux `MAX_ARG_STRLEN` is 131 072 bytes per argv string). `callerId` = `caller.id` (`null` for operator). The CLI then prints `Couldn't reach <forge>: <reason>. The verdict is saved and deacon-lite will retry recording it.` and exits 1.
- **D10 — Replay module** `src/lib/cloister/deferred-verdict-replay.ts` exports `replayDeferredReviewVerdict(issueId, workspacePath, entry, now, deps?)`. `recoverStalledReviews` calls it when the **last** journal entry is `review.verdict-deferred`, after the existing issue-pause hold (a paused issue holds), before the reviewer-liveness check. Rules:
  - Wait until the entry is ≥ 10 minutes old (`DEFERRED_VERDICT_MIN_AGE_MS = 10 * 60_000`). Each failed replay appends a fresh deferred entry, so the tail's age is the cooldown; no in-memory map.
  - An in-process `Set` of issues with a replay in flight makes an overlapping tick do nothing.
  - **Supersession:** if `entry.data.runId` is set and differs from `getAgentState('agent-<issue>-review')?.reviewRunId`, do not replay; journal `review.verdict-replay-gave-up` with `data: { runId, reason: 'superseded' }`.
  - **Cap:** count `review.verdict-deferred` entries with the same `runId` in the journal; when ≥ 7 (the original + 6 replays ≈ one hour, which covers GitHub's hourly GraphQL reset), journal `review.verdict-replay-gave-up` with `reason: 'cap'` and `emitActivityEntry({ source: 'review', level: 'warn', issueId, message: '<issue>: a <status> review verdict could not be recorded after <n> attempts — the review needs the operator' })`.
  - **Replay:** `execFileAsync('pan', ['admin', 'specialists', 'done', 'review', issueId, '--status', status, ...(runId ? ['--run-id', runId] : []), ...(notes ? ['--notes', notes] : [])], { env, timeout: 5 * 60_000 })` where `env` = `process.env` with `OVERDECK_AGENT_ID` set to `callerId` when it is non-null, and with `OVERDECK_AGENT_ID`, `OVERDECK_ISSUE_ID` and `OVERDECK_SESSION_TYPE` deleted when `callerId` is null. The child is the same door, so it re-runs `reviewVerdictRefusal`, posts, journals `review.verdict` on success, or appends a new `review.verdict-deferred` on another transient failure.
  - A replay that exits non-zero with no new deferred entry (a non-transient failure or a refusal the child already journaled) logs `[deacon-lite] <issue>: deferred verdict replay failed: <stderr tail>` once and journals `review.verdict-replay-gave-up` with `reason: 'failed'` so the patrol stops.
- **D11 — Forgery.** The journal lives in the work agent's worktree and is not authority. A forged `passed` deferral with a fabricated `callerId` of the review session is replayed under that id — which is exactly what an agent can already do by exporting `OVERDECK_AGENT_ID` itself; the replay grants nothing new. The supersession check ties the replay to the review parent's current `reviewRunId`, and `reviewVerdictRefusal` re-runs in full. Recorded as hazard H3.
- **D12 — Head moved.** A push after the deferral makes `verification.*` or `review.requested` the tail; the deferred verdict is then never replayed. That is correct: the verdict was for the old head.
- **D13 — GitLab** gets the same failure/absence split (FR-8). `glab mr list --source-branch` already lists open MRs only, so absence is `[]` and there is no semantic change.
- **D14 — No new CLI flag.** The replay uses the existing `--status`, `--run-id`, `--notes`, so no skill file changes.

## Repo rules restated

- Fake timers for every retry/backoff test (`vi.useFakeTimers()` / `vi.advanceTimersByTimeAsync()`); never real waits, never `maxForks: 1`.
- No `execSync` in server-reachable code — `forge.ts`, `github-pr-lookup.ts`, `merge-ops.ts` and deacon-lite all are; use `execAsync`/`execFileAsync`.
- Quality gates: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never the full `npm test` on the host.
- Never weaken the review-verdict guard (`reviewVerdictRefusal`, `verdictCallerFromEnv`).
- The pipeline journal is append-only and never authority: write new entries, never edit old ones.
- File-size ratchet: if `done.ts`, `deacon-lite.ts` or `merge-ops.ts` grow past their `origin/main` line count, add a `scripts/file-size-allowlist.txt` row `<lines> <path> # PAN-4263` in the same commit.

## Non-goals

- Deferral and replay for `test` and `uat` verdicts (they get the honest error and exit 1).
- Changing `ensurePRExists`' swallowed `gh pr list` error (`merge-ops.ts` ~198): under a rate limit it reports `gh pr create`'s real error, which is honest.
- Switching the gh path to `gh api` REST, or adding GraphQL-quota awareness.
- Refreshing or migrating other stale `merge_set_repos.artifact_url` rows outside the merge path.
- Retrying `createReviewArtifact`, `mergeReviewArtifact`, `commentOnArtifact` or `approveReviewArtifact`.
- Fixing `merged-pr-verification.ts` / `merge-verification.ts` (they already scan all PRs for a merged one; `prs[0]` is not used there).
