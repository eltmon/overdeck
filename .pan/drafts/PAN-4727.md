## 0. Glossary

- **gstack.** Garry Tan's skill collection (MIT). Upstream `garrytan/gstack`; operator fork `eltmon/gstack`, forked 2026-11-01 at `1cac25cb8eb1b394136e98ab76ecd2b8fcec458e` (`VERSION` = `1.92.33.0`). 63 top-level directories hold a `SKILL.md`.
- **Fork.** `https://github.com/eltmon/gstack`. The only place gstack code changes. No agent opens issues, PRs or comments on `garrytan/*`.
- **Fork clone.** The work agent's checkout of the fork at `$HOME/Projects/gstack` (the "operator's fork clone" the acceptance exempts). Branch `overdeck/pack-mode`.
- **Pack.** A third-party git repo of skills registered with `pan skills pack add <id> <url> --ref <ref>` (PAN-4334). Registry: `~/.overdeck/config.yaml` `skills.packs.<id>: { url, ref, commit, adapter? }`.
- **Trusted commit.** The 40-hex commit the operator approved at add time. Launches use exactly this commit.
- **Extraction.** `~/.overdeck/packs/<id>/<commit>/` — `git archive` of the trusted commit (`packExtractDir`, `src/lib/skill-packs/sources.ts`). Read-only source.
- **Pack mode.** New fork feature (WI-F1..F3): `bash setup --pack-root <R> --pack-state-root <S>` renders every skill and its runtime into `R`, keeps all state in `S`, and writes nothing else.
- **Render root (`R`).** `~/.overdeck/packs/gstack/render/<commit>/`. A full runtime copy of the extraction whose skill files name `R` instead of `~/.claude/skills/gstack`. Helper: `packRenderDir(id, commit)` (new, `src/lib/skill-packs/sources.ts`).
- **State root (`S`).** `~/.overdeck/packs/gstack/state/`. gstack's `GSTACK_STATE_ROOT` in pack mode (config, sessions, learnings, project reports). Helper: `packStateDir(id)` (new, `sources.ts`). Survives re-renders; deleted by `pan skills pack remove gstack`.
- **Render marker.** `R/.gstack-pack.json`, written last by pack mode. A render is **ready** only when it exists and holds `packMode: 1`.
- **State-root marker.** `R/.gstack-pack-state-root`, one line holding the absolute `S`. gstack's state-root resolver reads it (WI-F2), so every bin script uses `S` with no environment variable, in every harness.
- **Pack-mode descriptor.** `pack-mode.json` at the fork's repo root: `{"packMode": 1}`. Overdeck checks it **before consent**; a commit without it cannot be added.
- **`gstack-runtime` adapter.** New `PackAdapterId`. Reads the skill map, lists runtime executables, renders after consent, mounts from `R`.
- **Skill map.** `GSTACK_SKILL_MAP` in new `src/lib/skill-packs/gstack.ts`: every gstack skill name → class `default` | `opt-in` | `excluded` | `needs-binary`, with a reason. Unknown names are excluded as `unreviewed` (Deft pattern, `src/lib/skill-packs/deft.ts`).
- **Mount.** `~/.overdeck/packs/mounts/<sha256>/` (`src/lib/skill-packs/mount.ts`): the per-launch plugin wrapper. Claude Code gets it through `--plugin-dir`; Codex through the `overdeck-packs` local marketplace and `$CODEX_HOME/plugins/cache/overdeck-packs/`.
- **Harness-visible name.** `gstack:<skill>` (plugin namespacing). Overdeck id: `gstack/<skill>`.
- **Opt-in skill.** The pack toggle never turns it on; only a per-skill `on` does (`resolvePackSkill`, `src/lib/skill-overrides/resolve.ts:90-107`).
- **Live checkpoint doc.** `.pan/drafts/PAN-4727-live-checkpoint.md` — verbatim transcript of the fork test run and the live acceptance run (same shape as `.pan/drafts/PAN-4424-live-checkpoint.md`).
- **`$B` / `$D` / `$P`.** gstack's compiled `browse`, `design` and `make-pdf` binaries (`scripts/build.sh:53-57` in the fork), built only by a full `./setup` with `bun install` + `bun run build`.

## 1. Verdict

Mount gstack's full **bash + bun runtime** through a new pack mode in the fork and a new `gstack-runtime` adapter in Overdeck. The rendered skills call `R/bin/...` by absolute path, the runtime keeps its state in `S`, and both live under `~/.overdeck/packs/gstack/`, so `pan skills pack remove gstack` deletes everything with the existing `rm -rf packs/<id>` plus one new sweep of mounts and Codex caches.

Pack mode does **not** run `bun install`, `bun run build` or the Playwright download (the issue requires no network at setup). So the 21 skills that need `$B`/`$D`/`$P` are classified `needs-binary` and not mounted; [PAN-4730](https://github.com/eltmon/overdeck/issues/4730) adds them behind a second consent. This is a deliberate trade against the operator's "qa should work" note — see autoDecision A1.

## 3. Decisions

- **D1 — Render, don't install.** Pack mode copies the runtime and runs the generator; it never runs `bun install`, `bun run build`, Playwright, font or `brew` steps, never writes harness dirs or settings, never calls the network. It dispatches from `setup` right after argument parsing (setup:213-239) and `exit`s before any other setup code runs.
- **D2 — State root by marker file, not env.** `R/.gstack-pack-state-root` is read by the fork's resolver. No Overdeck launcher env work for Claude or Codex, and a hand-run `R/bin/...` also lands in `S`. Precedence: `GSTACK_STATE_ROOT` → `GSTACK_HOME` → `GSTACK_STATE_DIR` → **pack marker** → `CLAUDE_PLUGIN_DATA` rule → `$HOME/.gstack`.
- **D3 — Locations.** `R = ~/.overdeck/packs/gstack/render/<commit>/`, `S = ~/.overdeck/packs/gstack/state/`. Both sit inside `packCacheDir('gstack')`, so `removePack` deletes them. Renders are per commit; state is shared across commits.
- **D4 — Render only in CLI write paths.** `add` and `update` render after consent and before writing the registry; `sync` renders when the trusted commit's render is not ready. Catalog and launch stay read-only (PD-4): a pack whose render is not ready is reported as not cached and skipped with `run pan skills pack sync gstack`.
- **D5 — Consent shows what runs.** The preview prints a `Runs` row with the exact `bash setup --pack-root … --pack-state-root …` command and lists **every** runtime executable, one per line, because runtime packs run them. Non-runtime packs keep the 3-item truncation.
- **D6 — Codex uses the Claude render.** One mount serves both harnesses. The rendered paths are absolute, so they work from the Codex plugin cache copy. Claude-only prompt features (AskUserQuestion) fall back to gstack's prose path in Codex. No Codex-specific render.
- **D7 — Skill classes.** Fixed table (§6, WI-O1). `default` = on with the pack toggle; `opt-in` = needs a per-skill `on`; `excluded` and `needs-binary` = never mounted, shown as "Not mounted" with reasons. Unknown names = excluded `unreviewed`, so a pack update that adds skills mounts nothing new until the map is reviewed.
- **D8 — Removal.** `pan skills pack remove gstack` deletes `packs/gstack/` (render, state, extractions, repo), every mount that contains `plugins/gstack`, launch links left dangling by that, and `plugins/cache/overdeck-packs/gstack` in every `~/.overdeck/agents/*/codex-home*/`. Running agents that used a deleted mount lose pack skills until their next launch; removal is an explicit operator act.
- **D9 — Project-local `.gstack/` is skill output.** Skills write `.gstack/tmp/…` and reports in the project only when invoked (the issue's scope allows this). `remove` does not delete them; it prints each `.gstack/` or `.gstack-worktrees/` it finds directly under registered project roots, with the `rm -rf` command for the operator.
- **D10 — gc.** `pan skills pack gc` also removes render dirs for commits other than the trusted commit when older than `--max-age-days` (same age rule as mounts, so a running agent's render survives the default 7 days), and removes `render/` and `state/` under any `packs/<id>/` whose id is not registered (left by an interrupted remove). It never touches the trusted commit's render or a registered pack's state.
- **D11 — No hardcoded pin.** `KNOWN_PACKS.gstack` carries the fork url and adapter; the trusted commit is chosen at `add`. Docs and the CLI hint use `--ref main`; until the fork PR merges, `main` has no `pack-mode.json` and `add` fails with the D12 message.
- **D12 — Unsupported commit.** No `pack-mode.json` with `"packMode": 1` at the commit ⇒ `PackSourceError('render', 'pack gstack: <sha7> has no pack mode (pack-mode.json); use https://github.com/eltmon/gstack at a commit with pack mode')`, raised before the preview is shown, nothing written.
- **D13 — bun is required.** `bun --version` fails ⇒ `PackSourceError('render', 'pack gstack needs bun on PATH (https://bun.sh)')` before consent.
- **D14 — Fork delivery.** The work agent commits on branch `overdeck/pack-mode` in the fork clone, pushes to `eltmon/gstack`, and opens a PR **inside the fork**: `gh pr create --repo eltmon/gstack --base main --head overdeck/pack-mode`. It never merges it; merging is the operator's call. Fork evidence (SHA, test output) is committed to the live checkpoint doc in this repo with the item's `Item:` trailer, because `pan task done` checks trailers on this branch.
- **D15 — Live acceptance runs isolated.** The live run uses this workspace's build (`node dist/cli/index.js`, the deployed `pan` lacks the adapter) with `OVERDECK_HOME=/tmp/pan-4727-live/overdeck-home` and a scratch project clone, then `claude -p --plugin-dir <link>` as a one-off verification probe (no code path spawns `-p`). It never touches the operator's real `~/.overdeck`, global toggles or projects. `GSTACK_SESSION_KIND=spawned` is set for the probe so gstack auto-decides its questions.

- **FR-16** `features/skills.mdx` has a `### gstack` section (setup, consent, classes, state, removal, limits) and `CHANGELOG.md` `## Unreleased` has a gstack entry.
- **FR-17** Live: with the pack on for one project, a Claude Code run with that launch's plugin dir runs `/gstack:test-audit` and `/gstack:deslop-shared-libs` to completion; `~/.claude/settings.json` and the `~/.claude/skills` listing are byte-identical before and after; `~/.gstack` does not exist; turning the pack off for the project removes gstack from the next launch; `pan skills pack remove gstack` leaves no `*gstack*` path under the isolated Overdeck home.

### Non-functional

- **NFR-1** No git operation, issue, PR or comment touches `garrytan/*`. Fork changes are additive and behind `--pack-root`; a normal `./setup` run behaves exactly as before.
- **NFR-2** Overdeck's launch path runs no git, no bun and no render (PD-4). All new fs/process calls are async (`execFile` + promisify); no `execSync`.
- **NFR-3** `src/lib/skill-packs/` keeps importing nothing from `src/lib/skill-overrides/` (madge). `gstack.ts` imports nothing from `src/lib`; `render.ts` imports only `node:*` and `./gstack.js`; `sources.ts` imports `render.ts`, never the reverse.
- **NFR-4** No file grows past its `origin/main` line count + headroom under 1000; `src/lib/launcher-generator.ts` is not touched.
- **NFR-5** Tests use temp `OVERDECK_HOME` dirs and a fake `setup` script fixture; no Overdeck test runs real gstack, bun-installs, or touches the network.

## 5. Fork contract (pack mode, version 1)

Invocation, from the source tree (Overdeck runs it with `cwd` = the extraction):

```bash
bash setup --pack-root /home/u/.overdeck/packs/gstack/render/<sha> --pack-state-root /home/u/.overdeck/packs/gstack/state
```

- Both paths absolute and matching `^/[A-Za-z0-9_.@+/-]*$`; otherwise exit 2 with `pack mode: --pack-root and --pack-state-root must be plain absolute paths`.
- `R` must be absent or empty (exit 2 otherwise). `S` may exist.
- Writes only under `R` and `S`. Never writes inside the source tree (`cwd`), so the shared extraction stays pristine.
- Steps: (1) copy the source tree into `R` without symlinks, excluding `.git/`, `test/`, `node_modules/`, `.github/`; (2) `bun run scripts/gen-skill-docs.ts --host claude --out-dir R --install-root R --link-root R` (plain `gen:skill-docs`, never `:user`, so no detection file is read); (3) write `R/.gstack-pack-state-root`; (4) seed `S/config.yaml` (FR-4); (5) write `R/.gstack-pack.json` = `{"packMode":1,"stateRoot":"<S>","version":"<VERSION file>"}` last.
- No `--prefix`: skills keep bare names; Overdeck's plugin namespace adds `gstack:`.
