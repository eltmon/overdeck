# PAN-5316: `pan start --plan skip` writes the synthesized xBRIEF into the issue workspace, never the primary checkout

**Issue:** [PAN-5316](https://github.com/eltmon/overdeck/issues/5316)

## Glossary

- **Primary checkout** — the project's registered repo root (`~/Projects/overdeck`), checked out on `main`. It is shared by every session. An untracked file there makes the tree dirty, and `pan release stable` refuses to run.
- **Issue workspace / base workspace** — the git worktree `<projectRoot>/workspaces/feature-<issue-lowercase>/`, on branch `feature/<issue-lowercase>`. Its own `.pan/` holds the issue's per-issue planning artifacts, which are committed on the feature branch.
- **Plan home** — the checkout that holds `.pan/`. `resolvePlanHome(path)` (`src/lib/pan-dir/paths.ts`, line 46) maps a path to it. For a monorepo project, the plan home of a workspace is the workspace itself. For a polyrepo project with `pan_records.repo`, it is that sub-repo inside the workspace.
- **Skip-plan start** — `pan start <id> --plan skip` (also the deprecated `--auto`). The resolved planning mode is `skip`, and `start.ts` sets `options.auto = true` (`src/cli/commands/start.ts`, line 590: `options.auto = resolvedPlanningMode === 'skip';`). No planning agent runs. Instead a minimal one-item xBRIEF is synthesized from the issue title and body.
- **Auto-synthesized spec** — the file `writeAutoStartXBrief` writes: `.pan/specs/<YYYY-MM-DD>-<ISSUE>-<slug>.xbrief.json`, built by `synthesizeMinimalXBrief`.
- **`findPlanSync(workspace)`** — `src/lib/xbrief/io.ts`, line 223. Reads the spec from the workspace's plan home first, then falls back to the main checkout two levels up (`resolve(workspacePath, '..', '..')`), then the workspace draft.
- **plan-integrity** — the verification check in `src/lib/cloister/plan-integrity-run.ts`. Its reference chain already has a `first-add` kind (lines 17–18: "the first branch commit that added a spec for the issue (`pan start --auto` specs, which never get a finalize commit)"), so a synthesized spec committed on the feature branch is a supported shape.

## Problem

On 2026-11-15 at 00:40 UTC the Flywheel ran `pan start PAN-5095 --plan skip --host --yes` from the primary checkout. Afterwards the primary checkout had an untracked `.pan/specs/2026-11-15-PAN-5095-….xbrief.json`, and `workspaces/feature-pan-5095/.pan/specs/` had no spec. The work agent's plan was in the wrong tree, and the dirty primary tree blocked `pan release stable`.

### Root cause (verified)

`writeAutoStartXBrief` in `src/lib/xbrief/auto-synthesize.ts` (lines 137–162) takes the workspace path but ignores it. It is named `_workspacePath`, and the spec goes to `projectRoot`:

```ts
export const writeAutoStartXBrief = (
  projectRoot: string,
  _workspacePath: string,
  issue: AutoSynthesizeIssueInput,
): Effect.Effect<AutoSynthesizeResult, FsError> =>
  Effect.gen(function* () {
    ...
    const written = yield* writeSpecForIssue(
      projectRoot,
      projectDocument,
      'proposed',
      canonicalFilename,
    );
```

`writeSpecForIssue(root, …)` (`src/lib/pan-dir/specs.ts`, line 254) writes into `getProjectPanPaths(root).specsDir`, which is `<resolvePlanHome(root)>/.pan/specs`. With `root = projectRoot`, that is the primary checkout.

The function has not changed since PAN-3230 (2026-07-28, commit `0297fa8f4bc`). That was before PAN-3917 W9 moved per-issue artifacts into the workspace's own `.pan/`. It is a leftover of the old "canonical spec lives on main" model. Its doc comment still says "workspace-local spec copies are migration compatibility only", which is now false.

The bug stays hidden because `findPlanSync(workspace)` falls back to the main checkout (`src/lib/xbrief/io.ts`, lines 226–228). So the post-synthesis check in `start.ts` (`if (!findPlanSync(workspace))`) passes, and the agent spawns against a spec in the primary tree.

There are three callers. All of them pass the primary root and the workspace:

| Caller | Location | Grep anchor |
| --- | --- | --- |
| `pan start` skip path | `src/cli/commands/start.ts`, line 960 | `await Effect.runPromise(writeAutoStartXBrief(projectRoot, workspace, issue));` |
| Dashboard spawn route (`autoStart`) | `src/dashboard/server/routes/agents/spawn-issue.ts`, line 367 | `yield* writeAutoStartXBrief(projectPath, workspacePath, {` |
| Deft placeholder plan | `src/lib/deft/switch.ts`, line 117 | `const written = await Effect.runPromise(writeAutoStartXBrief(projectPath, workspace, { issueId, title: DEFT_PLACEHOLDER_TITLE }));` |

The precedent for the correct target already exists. `src/lib/overdeck/planning-promotion.ts`, line 209, promotes a planned spec with `writeSpecForIssue(workspacePath, workspaceDoc, 'proposed')`.

Two existing tests pin the buggy location, and both must be rewritten:

- `src/lib/xbrief/__tests__/auto-synthesize.test.ts`, test `writes a registered project spec into <planHome>/.pan/specs where findPlanSync resolves it`. It asserts `expect(result.projectSpecPath).toBe(join(projectRoot, '.pan', 'specs', result.canonicalFilename));`.
- `src/lib/deft/__tests__/switch.test.ts`, test `marks the stand-in plan it writes with deftPlaceholder`. It reads `readdirSync(join(projectPath, '.pan', 'specs'))`.

## Decisions

1. **Write target rule.** The synthesized spec goes to `writeSpecForIssue(workspacePath, …)`, so it lands in `<resolvePlanHome(workspacePath)>/.pan/specs/`. That is exactly the directory `findPlanSync(workspacePath)` reads first (`findSpecByIssue(planCheckoutFromWorkspace(workspacePath), …)`, where `planCheckoutFromWorkspace` returns the workspace). For the base workspace it is also the directory `resolveIssueWorkspacePlanHome(projectRoot, issueId)` returns. Polyrepo `pan_records.repo` routing comes for free through `resolvePlanHome`.
2. **Signature.** `writeAutoStartXBrief(workspacePath, issue)`. The `projectRoot` parameter is removed: it is the footgun that caused this bug, and nothing else uses it. All three callers are updated.
3. **Result shape.** `AutoSynthesizeResult` becomes `{ document, specPath, canonicalFilename }`. The duplicate `workspaceSpecPath` / `projectSpecPath` fields both held the same path, and `projectSpecPath` would now be a misleading name. The only production reader is `deft/switch.ts` (`written.projectSpecPath`), which switches to `written.specPath`.
4. **Guard (regression lock).** `writeAutoStartXBrief` fails with `FsError({ path: workspacePath, operation: 'writeAutoStartXBrief', cause })` and writes nothing in two cases:
   - when `issueIdFromWorkspacePath(workspacePath)` (from `src/lib/xbrief/io.ts`, line 129) is not equal to `issue.issueId.toUpperCase()`. This covers a primary root, a wrong issue's workspace, and any non-`feature-<id>` path.
   - when `workspacePath` does not exist on disk (`existsSync`). Without this, the recursive `mkdir` in `ensurePanDirs` would fabricate `workspaces/feature-<id>/.pan/specs/` inside the primary tree, and a later `pan workspace create` would trip over a non-git directory.
   - when the workspace's real path is not the canonical workspace location under the real main checkout. The check is `realpathSync(workspacePath) !== join(realpathSync(resolve(workspacePath, '..', '..')), 'workspaces', basename(workspacePath))`. This refuses a `workspaces/feature-<id>` symlink that points at the primary checkout (or anywhere else), which would otherwise pass the basename and existence checks and dirty the primary. A symlinked ancestor such as a symlinked `~/Projects` still passes, because both sides go through `realpathSync`. `resolve(workspacePath, '..', '..')` is the same main-checkout derivation `findPlanSync` uses (`mainCheckoutFromWorkspace`, `src/lib/xbrief/io.ts`, line 153). The guard does not require a `.git` gitfile: polyrepo wrapper workspaces need not be linked worktrees at their top level.
5. **Dashboard route, missing local workspace.** In `spawn-issue.ts` the synthesis branch runs only when the local workspace exists: `if (autoStart && !planPath && existsSync(workspacePath))`. The local workspace can be missing only when `remoteRequested` is true, because local workspace creation is skipped for that case at line 344. In that case the route falls through to its existing 422 `No workspace xBRIEF found for <id>` response instead of failing with an FsError. This edge is effectively unreachable: a consent-bearing remote spawn comes after planning, and planning writes the spec into a local workspace. `existsSync` is already imported and used in this file (line 702).
6. **Index invalidation needs no change.** `writeSpecForIssue(workspacePath)` calls `invalidateXBriefIndex(workspacePath)`. The project-root index (`src/lib/xbrief/xbrief-index.ts`, `scanPanSpecs(projectRoot)`) scans only the primary `.pan/specs`, so it never held this spec. This matches the planning-promotion precedent.
7. **Committing the spec needs no change.** Once the spec is in the workspace it is an untracked file under `.pan/specs/`. `isOverdeckOwnedOnlyStatus` already exempts that path from "uncommitted work" gates. `commitPendingIssueArtifacts` (`src/lib/overdeck/plan-artifact-commit.ts`, line 88) runs `git add -- .pan/continues .pan/specs`, which stages untracked files, at `pan done`. plan-integrity accepts it as a `first-add` reference.
8. **Test seam (auto decision).** The issue asks for "a test that runs a skip-plan start from the primary root". `startCommand`'s skip path reaches line 960 only after workspace resolution, branch validation, sync-main, state validation and a tracker fetch. Driving it from a test would need about 20 module mocks, and the mocks would replace the very filesystem behavior under test. So the regression test drives `writeAutoStartXBrief` against a real topology: a real `git init` primary with `workspaces/` in `.gitignore`, and a real `git worktree add -b feature/pan-<n> workspaces/feature-pan-<n>`. It asserts that the primary `git status --porcelain` is empty, that the primary has no `.pan/specs`, and that the workspace holds the spec. The process cwd does not matter: no code in this path reads `process.cwd()`. The `start.ts` call site changes only by dropping the first argument. The guard in Decision 4 makes a primary-root target fail even if a future caller passes it.

## Requirements

- **FR-1** — `writeAutoStartXBrief(workspacePath, issue)` writes the synthesized spec into `<resolvePlanHome(workspacePath)>/.pan/specs/<canonicalFilename>` and returns that path as `specPath`.
- **FR-2** — After a skip-plan synthesis, the primary checkout's working tree is unchanged: `git status --porcelain` in the primary is empty, given `workspaces/` is ignored there.
- **FR-3** — `findPlanSync(workspacePath)` returns the workspace spec path written by FR-1. It does not return a primary-checkout path.
- **FR-4** — `writeAutoStartXBrief` fails with `FsError` (operation `writeAutoStartXBrief`) and creates no file or directory in three cases: `basename(workspacePath)` does not name the issue's `feature-<id>` workspace; `workspacePath` does not exist; or its real path is not `<realpath(main checkout)>/workspaces/feature-<id>`, for example a symlink to the primary.
- **FR-5** — All three callers (`start.ts`, `spawn-issue.ts`, `deft/switch.ts`) pass the issue workspace. The Deft placeholder plan lands in the workspace's `.pan/specs/` with `plan.metadata.deftPlaceholder: true`.
- **FR-6** — The dashboard spawn route synthesizes only when the local workspace exists. Otherwise it returns its existing 422 `No workspace xBRIEF found` response.
- **FR-7** — The docs say where the skip-plan spec is written: `docs/XBRIEF.md`, `sync-sources/skills/pan-start/SKILL.md`, `changelog.d/pan-5316.md`, and the codebase map `concerns.md` bullet.
- **NFR-1** — No new `execSync` in server-reachable code. `existsSync` is a stat, which is allowed and already used in `spawn-issue.ts`.
- **NFR-2** — No file grows past its ratchet. `start.ts` (1088 lines) must not grow, and the edit there only removes an argument. `spawn-issue.ts` (939 lines) stays under 1000.
- **NFR-3** — Tests use real temp git repos under `os.tmpdir()` via `mkdtemp` and clean them up. They need no timers, so no fake-timer requirement applies. Do not add `skipIf` / `.only`, and do not write source-grep tests (the test-skip and lint gates reject them).

2. Replace `writeAutoStartXBrief`:

   ```ts
   /**
    * Synthesize a proposed spec and write it into the issue workspace's plan
    * home (`<resolvePlanHome(workspacePath)>/.pan/specs/`), where
    * `findPlanSync(workspacePath)` reads it and the work agent commits it on the
    * feature branch. Never the primary checkout (PAN-5316). Fails, writing
    * nothing, unless `workspacePath` is the existing `feature-<id>` workspace of
    * `issue.issueId`.
    */
   export const writeAutoStartXBrief = (
     workspacePath: string,
     issue: AutoSynthesizeIssueInput,
   ): Effect.Effect<AutoSynthesizeResult, FsError> =>
     Effect.gen(function* () {
       const issueId = issue.issueId.toUpperCase();
       if (issueIdFromWorkspacePath(workspacePath) !== issueId) {
         return yield* Effect.fail(new FsError({
           path: workspacePath,
           operation: 'writeAutoStartXBrief',
           cause: new Error(`${workspacePath} is not the feature-${issueId.toLowerCase()} workspace for ${issueId}`),
         }));
       }
       if (!existsSync(workspacePath)) {
         return yield* Effect.fail(new FsError({
           path: workspacePath,
           operation: 'writeAutoStartXBrief',
           cause: new Error(`workspace ${workspacePath} does not exist`),
         }));
       }
       // A symlink to the primary (or elsewhere) passes the two checks above; refuse it.
       const canonical = join(realpathSync(resolve(workspacePath, '..', '..')), 'workspaces', basename(workspacePath));
       if (realpathSync(workspacePath) !== canonical) {
         return yield* Effect.fail(new FsError({
           path: workspacePath,
           operation: 'writeAutoStartXBrief',
           cause: new Error(`${workspacePath} resolves to ${realpathSync(workspacePath)}, not the issue workspace ${canonical}`),
         }));
       }
       const document = synthesizeMinimalXBrief(issue);
       const canonicalFilename = document.plan.metadata?.canonicalFilename as string;
       const written = yield* writeSpecForIssue(
         workspacePath,
         { ...document, plan: { ...document.plan, status: 'proposed' } },
         'proposed',
         canonicalFilename,
       );
       return { document, specPath: written.path, canonicalFilename };
     });
   ```

   `FsError` is currently imported with `import type`. Change it to a value import (`import { FsError } from '../errors.js';`) because it is now constructed.

Skip-plan synthesizing over a plan that lives only on a feature-branch ref is a separate question.
- Do not run a full `startCommand` integration test (see Decision 8).

## Hazards

- The Deft placeholder now lives in the tree that ships. `backToOverdeck` deletes it through `findPlanPath(workspace)` (`rm(planPath)`), which now resolves the workspace copy. If the placeholder was committed in between, the deletion shows up as a tracked-file removal on the branch. That is correct, and the work agent should not "fix" it.
- `pan sync-main` auto-commits the whole dirty tree as a "pre-sync commit". Commit each item's work before syncing.

## Critique response

### Guard accepts a symlink to the primary

Accepted. Decision 4 now has a third check: the workspace's real path must equal `join(realpathSync(resolve(workspacePath, '..', '..')), 'workspaces', basename(workspacePath))`. A `workspaces/feature-<id>` symlink to the primary resolves to the primary and is refused before any write. WI-2 adds the test `refuses a workspace symlink that points at the primary checkout`, and FR-4 and AC-6 cover it. I did not adopt "verify it is a distinct git worktree" (for example by requiring a `.git` gitfile). Polyrepo wrapper workspaces need not be linked worktrees at their top level, so that check could refuse a legitimate workspace. An arbitrary non-symlink directory at the canonical `workspaces/feature-<id>` location still passes. That is the location `pan workspace create` owns, and it sits under the primary's ignored `workspaces/`, so a write there cannot dirty the primary tree. The dashboard route's reliance on `workspaceNeedsSetup` is unchanged, because the writer's own guard now refuses the symlink case on every caller.

### Real-git test omits project registration

Accepted. WI-2 test 1 now registers the temporary primary in `projectRegistry.entries` and sets `OVERDECK_HOME` before synthesis, so it exercises the registered-project `resolveInfraRepo` branch that production `pan start` takes. It keeps the primary-status and workspace-path assertions.
