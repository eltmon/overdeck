## Glossary

| Term | Meaning |
| --- | --- |
| **Agent runtime plane** | The proposed git-backed, per-agent durable state on `overdeck-state`: identity, launch metadata, session-id history, lifecycle timestamps, and GC audit entries. Lives at `agents/<agentId>.json`. |
| **Agent state dir** | `~/.overdeck/agents/<agentId>/` — local-only runtime files: `state.json`, `session.id`, `sessions.json`, `launcher.sh`, `runtime.json`, `spawn.log`, `mail/`, `ready.json`, `activity.jsonl`, etc. After this design lands, a **cache** of the plane plus genuinely disposable residue. |
| **Session pointer** | Any file that records which harness session an agent owns: `session.id`, `sessions.json`, `runtime.json:claudeSessionId`, `state.json:sessionId`, `codex-thread-id`, `kimi-session-id`. Small, resume-critical. |
| **Transcript** | The harness-owned conversation JSONL (e.g. `~/.claude/projects/<slug>/<sessionId>.jsonl`). Never committed to git anywhere. Fetchable on demand from the origin machine (D5). |
| **Origin machine** | The machine where an agent ran and where its workspace, tmux sessions, and transcripts physically live. Each agent doc has exactly one origin machine, which is its sole writer (D8). |
| **Relay** | The Anywhere Phase-3 outbound-only daemon ([PAN-2356](https://github.com/eltmon/overdeck/issues/2356)). Serves transcripts and commands from the origin machine to remote surfaces. |
| **Tombstone** | A terminal lifecycle entry on an agent's plane doc recording that local state was reaped, why, and by what predicate inputs. Makes deletion audible and recoverable. |
| **Live terminality** | The GC eligibility test: tracker state is closed/canceled *right now*, no live tmux session, no open MRs, no in-flight review/test runs, no recent activity. Contrasts with reading a cached record boolean. |

## Background & motivation

### The MIN-839 incident (2026-08-01/02)

The deacon's hourly agent GC (`pruneTerminalStoppedAgents`, wired at `src/lib/cloister/deacon.ts:3146`, every 60 patrol cycles) deleted the state dirs of `agent-min-839`, `agent-min-864`, and `agent-min-874` **while those issues were mid-review-loop**. The predicate (`src/lib/cloister/agent-gc.ts`, default `isTerminalAgent`) trusts `record.pipeline.closedOut === true`; all three records carried a stale `closedOut: true` minted by the July 18 batch close-out, and nothing resets the flag when an issue reopens in the tracker.

The transcript-preserving removal door (`src/lib/agents/state-dir-removal.ts`, PAN-3357) worked as designed for `*.jsonl` bytes — `activity.jsonl` and `pending-events.jsonl` survived, and each dir carries a `.retained-transcripts` marker stamped at the sweep moment. But every session pointer is a non-JSONL file, so the sweep preserved transcript *bytes* while shredding transcript *reachability*. Resume (`getLatestSessionIdSync`, `src/lib/agents/activity.ts`) resolves pointers only from inside the deleted dir — no fallback scans the workspace's transcript dir and nothing consults the event store, which had durably recorded `claudeSessionId` in `model_set` events — so it blocked with "no recoverable session transcript on disk" while the transcript sat intact. The GC emitted no domain event and wrote no durable audit line; the loss was invisible until the operator noticed a missing conversation.

### The category error

PAN-2541 drew the state-plane boundary as records/continues/specs/drafts/review/test/feedback/backlog/beads (`STATE_BRANCH_PATHS`, `src/lib/state-plane.ts`) and classified everything operational as "workspace-local runtime files — never committed anywhere." Session pointers fell on the wrong side of that line. The system's own doctrine — *the DB is a disposable cache rebuilt from sources of truth; durable state lives on the state branch* — was never extended to the agent plane. The agent dir was therefore durable when convenient (resume reads it) and disposable when convenient (the GC deletes it). That ambiguity, not the GC's existence, is the defect.

### Anywhere needs this

The Anywhere epic (PAN-2350) phases 0–3 are all transport: scoped tokens, Cloudflare Tunnel, Hermes bridge, push, relay. PAN-2541's D14 already blocks Fly remote workspaces "until remote state sync is redesigned," and PAN-1676 tracks the remote-gap list. Today a remote dashboard can show *issues* from anywhere because records travel; it cannot coherently show *agents* because agent state does not. The relay answers "how does a command reach the origin machine"; only a git-backed agent plane answers "how does any machine know what exists and where to find it."

**Operator direction (2026-08-02):** transcripts must be fetchable on demand to another machine — continue work from a laptop, view conversations on a phone — without going through git. A permanent transcript archive is a foreseen future possibility, explicitly not in scope now; the schema must leave the door open (D6).

## Decisions (made in this document — do not re-litigate downstream)

| # | Decision | Rationale |
| --- | --- | --- |
| D1 | New **`agents/` root** on `overdeck-state`, one JSON doc per agent (`agents/<agentId>.json`), added to `STATE_BRANCH_PATHS`. | Flat tree per PAN-2541 D2. One doc per agent keeps writes small and conflicts structurally impossible under D8. |
| D2 | Writes go through the **state write door** (domain writer + `queueAutoCommit`/`flushAutoCommits`); reads through a new **`src/lib/pan-dir/agents.ts` read door**. No route handler, hook, or script reads/writes these files directly. | Single-source-of-truth tenet. The agent plane gets the same two doors every other domain has. |
| D3 | The **`sessions` list is append-only** and is the canonical resume reconstruction source. Every session id an agent has owned lands here with a timestamp, at spawn and at every rotation, regardless of harness. | `getLatestSessionIdSync` currently resolves from per-agent pointer files only; when they die, nothing reconstructs. An append-only history survives every local-loss scenario and doubles as the audit trail for session rotation (PAN-1980). |
| D4 | **Transcripts never enter git.** They remain harness-owned in `~/.claude/projects` (sacred-JSONL rule unchanged). | Size, churn, and ownership. Git is the wrong substrate; the pointer makes them locatable. |
| D5 | **Transcript fetch is on-demand via the relay**, served by the origin machine. Two consumption modes: *view* (phone/remote dashboard streams or pages the transcript — read-only) and *continue* (a laptop fetches the transcript into its local `~/.claude/projects/<slug>/` before resuming). | Operator requirement 2026-08-02. Fetch-on-demand covers the stated cases without an archive substrate. Continue-mode preconditions are stated honestly in FR-6. |
| D6 | The agent doc schema is **versioned** and carries an optional `archiveRef` field, reserved for a future permanent transcript record (content-addressed store or object storage). Not built now. | Operator foresees wanting transcripts as a permanent record eventually. Reserving the field now avoids a schema break later without committing to a substrate. |
| D7 | **GC becomes cache eviction.** Eligibility requires live terminality (tracker closed/canceled now + no live tmux + no open MRs + no in-flight review/test), evaluated at sweep time — never a cached record boolean alone. Every prune appends a tombstone entry (timestamp, predicate inputs, files removed) to the agent's plane doc before local deletion. | The stale-`closedOut` misfire class disappears. Deletion becomes audible in git history and recoverable: the plane doc survives, so resume-critical pointers can be re-materialized locally. |
| D8 | **Per-doc single writer:** each agent doc is written only by its origin machine's deacon/runtime. Non-origin machines are read-only for that doc. | The single-Deacon-per-`OVERDECK_HOME` invariant extends naturally. Multi-machine conflict resolution (PAN-2541 D10) degenerates to "only the owner writes" — no field-merge needed. |
| D9 | **Reopen and close-out are recorded as transitions** appended to the issue record's history on the state branch; `closedOut` becomes derived from the latest transition, not a bare mutable boolean. | The July-18 staleness bug — flag set by batch close-out, never reset on reopen — is impossible by construction when the current state is derived from an ordered transition log. |
| D10 | **Backfill migration:** plane docs are reconstructed for existing agents from (a) live state dirs, (b) the event store (`model_set` events carry `claudeSessionId`; `agent.created` projections carry identity), and (c) transcript-dir scans. Agents whose dirs were already reaped (min-839/864/874 class) get docs marked `recovered: true` with whatever the event store yields. | The incident proved the event store holds enough to reconstruct the essentials — the recovery done by hand for MIN-839 is exactly what the migrator does mechanically. |

## Requirements

### Functional

- **FR-1.** Every agent spawn, session rotation, stop, and tombstone appends to `agents/<agentId>.json` on `overdeck-state` through the write door, coalesced by the auto-commit queue. Write latency must not block spawn (queue is already async).
- **FR-2.** `getLatestSessionIdSync` gains an ordered fallback: local pointer files → agents plane `sessions` list (freshest first) → transcript-dir scan of `~/.claude/projects/<workspace-slug>/` filtered by recency. The resume BLOCKED message must enumerate which sources were checked.
- **FR-3.** The GC predicate evaluates live terminality at sweep time (tracker state, tmux liveness, open MRs, in-flight review/test runs). The record's `closedOut` may inform but never decide.
- **FR-4.** Every local state-dir reap first appends a tombstone entry to the agent's plane doc (predicate inputs, file list, timestamp). No silent deletion anywhere in `agent-gc.ts` / `state-dir-removal.ts` / lifecycle workflows.
- **FR-5.** Transcript *view* fetch: a remote surface (phone PWA, remote dashboard) requests a transcript through the relay; the origin machine serves it (streamed or paged) without the transcript transiting git.
- **FR-6.** Transcript *continue* fetch: `pan` on machine B can pull an agent's transcript(s) from origin machine A into B's local transcript dir and reconstruct local pointer files from the plane doc, making the agent resumable on B. Preconditions stated to the user: the project repo and `overdeck-state` are cloned/fetched (both git — already distributable), the workspace branch exists on B or is checked out fresh, and machine-local prerequisites (dependencies, docker stack, secrets) are B's responsibility — the plane makes state portable, not the environment.
- **FR-7.** Issue reopen and close-out append transitions to the record; `closedOut` is derived from the latest transition. The 7/18-class stale-flag bug must be reproducible as a failing test before the fix and impossible after.
- **FR-8.** Backfill migrator (D10) runs as a one-time `pan doctor`/`state-migrate` step, reporting per-agent: reconstructed / recovered-partial / skipped-live.

### Non-functional

- **NFR-1.** Plane docs are small (KBs) and append-mostly; state-branch history growth from agent writes stays negligible versus records churn.
- **NFR-2.** No transcript bytes in any git object, ever. A CI guard greps the state branch for transcript-shaped paths/content.
- **NFR-3.** Non-origin machines never write agent docs (D8); the write door rejects cross-origin writes by construction, not convention.
- **NFR-4.** The local agent dir may be destroyed at any time after FR-1–FR-4 land with zero resume-capability loss — the property the GC assumed, made true.

## Phasing

- **P0 — stop the bleeding (this issue's core):** schema + write door + read door (FR-1); resume fallback (FR-2); GC live-terminality predicate (FR-3); GC tombstone audit (FR-4); backfill migrator (FR-8).
- **P1:** record transitions and derived `closedOut` (FR-7); reconciliation sweep for pre-existing tombstones.
- **P2 — Anywhere consumption:** relay transcript *view* fetch (FR-5, lands with PAN-2356); *continue* fetch + remote resume (FR-6); remote dashboard agent enumeration from the plane (PAN-2352). Unblocks PAN-2541 D14's Fly remote workspaces and burns down PAN-1676.

## Acceptance criteria

1. Kill -9 an agent's state dir on a test issue; `pan resume <id>` reconstructs pointers from the plane and resumes the same session. (FR-2, NFR-4)
2. Force a record with `closedOut: true` on an open tracker issue with a stopped agent; run the GC; the agent is **not** reaped, and the sweep log records the live-terminality refusal. (FR-3, FR-7 test predicate)
3. Reap any agent; `git log overdeck-state -- agents/<id>.json` shows the tombstone entry with predicate inputs. (FR-4)
4. Backfill on this machine produces plane docs for all current agents, with min-839/864/874-class agents marked `recovered: true` and carrying their event-store-derived session ids. (FR-8)
5. `git grep` guard: no path under `~/.claude/projects` and no transcript content on `overdeck-state`. (NFR-2)
6. From a second checkout, read the plane and enumerate all agents with their origin machines and session histories without touching `~/.overdeck/agents`. (FR-1, P2 readiness)

## Out of scope

- Permanent transcript archive substrate (D6 reserves the field only).
- Cross-machine workspace/environment sync (FR-6 states the honest preconditions).
- Multi-writer agent docs, cross-origin agent migration, machine failover (D8; future Anywhere phases).
