## Glossary

| Term | Meaning in this document |
| --- | --- |
| **Share** | A room on the share service for one conversation. The host's dashboard creates it with `POST /api/shares` (slice 2). |
| **Short code** | The 8-symbol room address from the alphabet `BCDFGHJKLMNPQRSTVWXZ23456789`, for example `BCDFGHJK`. |
| **Join code** | The short code shown to people as `BCDF-GHJK` (4 + dash + 4). Every parser strips spaces and dashes and uppercases, so both forms work. |
| **Join link** | `https://share.overdeck.ai/s/<shortCode>` (`ShareView.joinUrl`). |
| **Join target** | What a user passes to `pan join`: a join code, a short code, or a join link. |
| **Join intent** | `POST /api/joins { code }` on the viewer's own dashboard. It makes the viewer server open the join socket, which shows the viewer's GitHub login to the host (slice 4, PAN-4475 D-1). |
| **Lobby** | The waiting room. A joiner's state is `lobby` until the host admits them. |
| **Live join state** | One of `connecting`, `lobby`, `admitted`, `host-disconnected` (`LIVE_JOIN_STATES` in `useSharedJoin.ts`). |
| **Device flow** | The RFC 8628 sign-in that `pan account login` runs (`loginCommand`, PAN-4330). It writes `${OVERDECK_HOME}/account.json`. |
| **Internal token** | The `x-overdeck-internal-token` header secret in `${OVERDECK_HOME}/internal-token`. A request carrying it skips the browser CSRF and Origin checks (`rejectUnsafeDashboardMutationRequest`). CLI verbs use it through `callDashboard`. |
| **Bundled server** | `<packageRoot>/dist/dashboard/server.js`, run under `process.execPath` (Node 22). `pan serve` and `pan up` both run it. |
| **Zero-install join** | `npx @overdeck/core join <code>` on a machine that never installed Overdeck: Node 22+, no global `pan`, empty `OVERDECK_HOME`, no Herdr, no tmux. |
| **Auto-start** | `pan join` starting the bundled server, detached, when no dashboard answers on the local API URL. |
| **Cold-start test** | The slow integration test that runs the built CLI's `join` in a temp `HOME`/`OVERDECK_HOME` with tmux, Herdr and `pan` shadowed on `PATH`. |

## Problem

Slices 1–4 let a host share a conversation from the dashboard and let a viewer join from the browser, but there is no terminal path. The share Worker's invite page tells a joiner to start Overdeck with `pan up` and reload. A person who has never installed Overdeck has no way in at all: `pan up` needs tmux (`ensureHostTools()` exits when tmux cannot be installed, `src/lib/prereqs/registry.ts` line 200) and a global install. The operator requirement (2026-10-02) is that `npx @overdeck/core join <code>` works cold.

## Goal

1. `pan share <conversation>` creates (or finds) the share for a conversation and prints the join link and the join code.
2. `pan join <link-or-code>` signs in through the device flow when needed, starts the local dashboard when it is down, posts the join intent, waits until the join leaves `connecting`, and opens `/#/shared/<CODE>` in the browser, where the user is in the lobby.
3. `npx @overdeck/core join <code>` does the same on a machine with only Node 22.
4. The share Worker invite page shows `pan join <CODE>` and `npx @overdeck/core join <CODE>`.
5. Wrapper skills `pan-share` and `pan-join` ship in the same change as the verbs.

## Requirements

Functional:

- **FR-1** `pan share <conversation>` accepts a conversation id (the number in `/conv/<id>`) or a conversation name, resolves it to the conversation name, calls `POST /api/shares { conversationName }` on the running dashboard, and prints the join link, the join code (`BCDF-GHJK`) and both join commands. It exits 0 on HTTP 201 or 200.
- **FR-2** `pan share --json` prints the `ShareView` JSON from the dashboard and nothing else on stdout.
- **FR-3** `pan share` exits 1 with a one-line reason when the conversation does not resolve, when no dashboard answers (`Start it with pan up`), or when the dashboard answers non-2xx (the body's `message`, else `error`, else `HTTP <status>`). It never starts a dashboard.
- **FR-4** `pan join <target>` rejects a target that does not normalize to a short code with exit 1 before any network call or file write.
- **FR-5** When `${OVERDECK_HOME}/account.json` does not exist, `pan join` runs the device flow (`loginCommand`) before it touches the dashboard. A failed sign-in exits 1 with `loginCommand`'s own message. The poll honours `slow_down` (the interval grows to the server's `interval`, else `interval + 5`).
- **FR-6** When no dashboard answers `GET <apiUrl>/api/health`, `pan join` starts the bundled server detached on the API URL's port and waits for `/api/health` to answer 200 from the spawned PID (timeout 120 s). Any HTTP answer, even 503, counts as "running" and nothing is spawned.
- **FR-7** Auto-start runs only when the API URL is `http:` on `localhost`, `127.0.0.1` or `[::1]` with an explicit port; otherwise `pan join` exits 1 with `No Overdeck dashboard answers at <apiUrl>. Start it with pan up.`
- **FR-8** `pan join` posts `POST /api/joins { code }` through `callDashboard`, then polls `GET /api/joins/<code>` every 500 ms while the state is `connecting`, for at most 15 s.
- **FR-9** For a live join state (or a poll that times out in `connecting`), `pan join` opens `<apiUrl>/#/shared/<CODE>` in the default browser (unless `--no-open`), prints the state in words and the URL, and exits 0.
- **FR-10** For a terminal join state, `pan join` prints the mapped message (table in WI-4), does not open a browser, and exits 1.
- **FR-11** Zero-install: `node <package>/dist/cli/index.js join <code> --no-open`, run from a temp directory with a temp `HOME` and `OVERDECK_HOME`, with `tmux`, `herdr` and `pan` resolving to stubs that exit 127, signs in, starts the dashboard and leaves the join in `lobby`.
- **FR-12** `GET /s/:code` for an active room shows `pan join <CODE>` and `npx @overdeck/core join <CODE>`. The 404 page still shows neither.
- **FR-13** `sync-sources/skills/pan-share/SKILL.md` and `sync-sources/skills/pan-join/SKILL.md` exist and pass `npm run lint:skills`.

Non-functional:

- **NFR-1** No device token, host token or internal token appears in any `pan share` / `pan join` output, error message, or browser URL.
- **NFR-2** Every wait in the new CLI code is a `setTimeout` promise or an injected function, so unit tests drive it with `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`. No unit test sleeps. Do not use `AbortSignal.timeout` in code a fake-timer test drives (it ignores fake timers); use `AbortController` + `setTimeout`.
- **NFR-3** The new group module `src/cli/commands/sharing/index.ts` imports only `commander` types and `../../lazy-action.js`, so registering the group costs nothing until a verb runs (PAN-4195).
- **NFR-4** No `execSync` anywhere in the new code. Spawning is `child_process.spawn` with `detached: true` and `child.unref()`.
- **NFR-5** No new dashboard HTTP route and no change to `/api/shares*` or `/api/joins*` behavior. (A new route would need a `no-loss-matrix.ts` row.)

## Decisions

- **D-1 Auto-start is modelled on `pan serve`, not `pan up`.** `pan up` (`src/cli/index.ts` line 547 onward) refuses non-primary cwds, makes tmux fatal through `ensureHostTools()`, starts Herdr, Traefik and the Electron app, and stops existing dashboards. A viewer needs none of that. `pan serve` (`src/cli/commands/serve.ts`) already runs the bundled server under `process.execPath` with `ensureInternalToken()`, but it runs in the foreground with inherited stdio and never waits for health. The new helper (WI-2) spawns the same bundle detached, logs to `dashboard.log` through `openDashboardLogStdio()`, and waits with `waitForDashboardHealth(port, { expectedPid })`. `serve.ts` is not changed. A later `pan up` replaces the auto-started server, because `stopDashboard` frees the ports by PID (`src/lib/platform-lifecycle.ts` line 381).
- **D-2 The npx command is `npx @overdeck/core join <CODE>`.** Verified against npm 10.9.4's `libnpmexec/lib/get-bin-from-manifest.js`: when every `bin` value is the same file, npx runs it. `package.json` maps both `overdeck` and `pan` to `./dist/cli/index.js`. Hazard H-1 guards this.
- **D-3 `pan share` never auto-starts a dashboard.** The host hub lives in the dashboard and must be the full `pan up` stack (Herdr, the conversation's terminal session). A share from a bare auto-started server would be wrong, so `pan share` exits 1 with `Start it with pan up`.
- **D-4 `pan join` reuses `loginCommand` unchanged.** `loginCommand(options, io, deps)` (`src/cli/commands/account/login.ts` line 32) prints the device-flow lines, calls `io.exit(1)` on failure and returns on success. `pan join` calls it only when `readAccount()` returns `null`, so the "Already signed in" line never prints. `pollForToken` already implements `slow_down` (`src/lib/account/client.ts`, `case 'slow_down'`).
- **D-5 The join intent goes through the internal token.** `callDashboard` (`src/cli/commands/dashboard-call.ts`) sends `x-overdeck-internal-token`; `rejectUnsafeDashboardMutationRequest` returns `null` for `internal-token` credentials, so no CSRF token is needed. Posting from the CLI keeps PAN-4475 D-1: the user ran an explicit command, and PAN-4475's glossary already names "`pan join` in slice 9" as a join-intent sender.
- **D-6 The browser URL carries no token.** It is `<apiUrl>/#/shared/<CODE>`. `consumeDashboardBootstrapToken` parses the whole hash as `URLSearchParams`, so appending `&overdeck_token=` would corrupt the `#/shared/` route. A loopback browser mints its session without a token (`rejectUnauthorizedDashboardSessionMintRequest`, `peerTrusted`). With `dashboard.require_token_mint: true` the browser must already hold a session (NonGoal; documented).
- **D-7 The browser lands in the lobby without a second click.** `useSharedJoin` (`src/dashboard/frontend/src/components/chat/sharing/useSharedJoin.ts` lines 196–201) subscribes to a live join without posting, and re-posts an `away` join automatically. So `pan join` posts first, then opens the page.
- **D-8 `--no-open` does not hold the event stream.** A join with no subscriber becomes `away` after 60 s (`JOIN_UNSUBSCRIBED_GRACE_MS`, `share-join.ts` line 30). Opening the URL later re-posts it (D-7), so the CLI need not stay attached. `--no-open` prints the URL and says the page rejoins when opened.
- **D-9 `pan join` settles before it opens the browser.** It polls `GET /api/joins/<code>` while `connecting` (500 ms, at most 15 s). A wrong or ended code becomes `ended` within that window, so the user gets a terminal message instead of a browser page that says the same thing.
- **D-10 The share-code parsers move to a leaf module.** The CLI must not import `src/dashboard/server/routes/*.ts` (they pull in the Effect HTTP router and the share managers). `normalizeShareCode` (`routes/shares.ts` line 51) and `parseJoinTarget` (`routes/joins.ts` line 66) move verbatim to `src/lib/sharing/share-code.ts` with a new `formatShareCode`. Both route modules re-export them under the same names, so `tests/unit/dashboard/server/routes/{shares,joins}.test.ts` stay unchanged.
- **D-11 Both verbs are one lazy command group.** `COMMAND_GROUPS.sharing` with `names: ['share', 'join']` in `src/cli/command-groups.ts`, registered by `registerSharingCommands` in `src/cli/commands/sharing/index.ts`. The actions reuse `AccountIo` from `src/cli/commands/account/shared.ts` (a structural `{ out, err, exit }`), so no new IO type is added.
- **D-12 The auto-started server's environment.** `{ ...process.env }` minus `DASHBOARD_URL` and `OVERDECK_DASHBOARD_URL` (an inherited public URL would change trusted origins and child API targets, PAN-3331), plus `PORT=<port>`, `API_PORT=<port>`, `OVERDECK_MODE=production`. `cwd` is `getOverdeckHome()` (created with `mkdir -p` first), never a repository.
- **D-14 The auto-started server boots with agent auto-resume off.** Its env goes through `applyBootGateEnv(env, { resume: false })` (`src/lib/boot-gates.ts` line 99), which sets `OVERDECK_NO_RESUME=1`. On an installed machine whose dashboard is down, joining a share must not resume the user's stopped agents as a side effect; an explicit no-resume fast-paths boot reconciliation to `hold_all`. The Deacon gate keeps its default. A later `pan up` restores the user's normal gates.
- **D-13 Size justification.** The issue requires the verbs, the wrapper skills (same commit, `scripts/lint-skills.sh`), the invite page in `services/share/`, the zero-install test and the docs. That spans `src/lib`, `src/dashboard`, `src/cli`, `tests/unit`, `tests/integration`, `services/share`, `sync-sources`, `packages/contracts` (the drift-gated composer manifest) and the doc roots. The files total 25. Splitting the invite-page line or the skills into sibling issues would ship a page that names a command that does not exist, or verbs that fail `lint:skills`.

A `waitForHealth` rejection → `LocalDashboardError('The dashboard did not become ready within 120 s. See <DASHBOARD_LOG_FILE>.')`. The child is never killed (a slow boot may still finish).

### WI-4 — `pan join` implementation

*Traces: FR-4, FR-5, FR-8, FR-9, FR-10, NFR-1, NFR-2, D-4, D-5, D-6, D-7, D-8, D-9.*

Create `src/cli/commands/sharing/join.ts`:

```ts
export const JOIN_SETTLE_POLL_MS = 500;
export const JOIN_SETTLE_TIMEOUT_MS = 15_000;
export interface JoinOptions { open?: boolean }   // Commander --no-open → open: false
export interface JoinDeps {
  fetch?: typeof fetch;                                  // account service, passed to loginCommand
  ensureDashboard?: () => Promise<LocalDashboard>;       // default ensureLocalDashboard()
  callDashboard?: typeof callDashboard;
  openUrl?: (url: string) => Promise<void>;              // default openDashboardUrl
}
export async function joinCommand(target: string, options: JoinOptions, io: AccountIo = defaultAccountIo, deps: JoinDeps = {}): Promise<void>;
```

1. `code = parseJoinTarget(target)`; `null` → `io.err('Not a share link or join code: <target>. A join code looks like BCDF-GHJK.')`, `io.exit(1)`.
2. `readAccount()` throws → `io.err(message)`, exit 1. `null` → `io.out('Sign in to overdeck.ai to join this conversation.')`, `await loginCommand({}, io, { fetch: deps.fetch })`, then `readAccount()` again; still `null` → `io.err('Sign-in did not complete. Run: pan account login')`, exit 1.
3. `dashboard = await ensureDashboard()`; `LocalDashboardError` → `io.err(message)`, exit 1. When `dashboard.started`, print `Started Overdeck at <apiUrl>.`
4. `callDashboard('/api/joins', { method: 'POST', body: { code } })`. Unreachable → exit 1 naming `pan up`. Not 200/201 → `io.err('Cannot join: ' + errorText)`, exit 1.
5. Settle: while `view.state === 'connecting'` and less than `JOIN_SETTLE_TIMEOUT_MS` has elapsed, wait `JOIN_SETTLE_POLL_MS` (a `setTimeout` promise) and `GET /api/joins/<code>`. Elapsed time is counted by summing the waits, not by `Date.now()`.
6. Map the final state:

| State | Output | Browser | Exit |
| --- | --- | --- | --- |
| `lobby` | `Waiting for the host to let you in (BCDF-GHJK).` | open | 0 |
| `admitted` | `You are in (BCDF-GHJK).` | open | 0 |
| `host-disconnected` | `You are in, but the host is disconnected. The page reconnects when the host returns.` | open | 0 |
| `connecting` (settle timed out) | `Still connecting to the share service. The page shows the lobby when it connects.` | open | 0 |

| `rejected` | `overdeck.ai rejected this sign-in. Run: pan account login` | no | 1 |

}

## Hazards

- **H-1 npx bin aliasing.** `npx @overdeck/core join` works only while every `bin` entry in `package.json` points at the same file. Adding a bin with a different target breaks zero-install join with "could not determine executable to run".
- **H-2 Workspace bundles.** In a workspace checkout, `packageRoot` is the workspace, so a `pan join` run from a workspace CLI would auto-start the workspace's `dist`. Tests use temp homes and free ports; never run the cold-start flow against the operator's home.
- **H-3 Grace timer.** A join with no browser subscribed becomes `away` after 60 s. The cold-start test asserts `lobby` well inside that window (`--no-open`).
- **H-4 Allowlist.** overdeck.ai is invite-only (parent OD-2). A viewer not on the allowlist fails the device flow with `ACCESS_DENIED_MESSAGE`; that is expected, not a bug.

- Auto-starting a dashboard from `pan share`.
