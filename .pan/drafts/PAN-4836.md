## Glossary

- **Set up a phone dialog:** `SetUpPhoneDialog`, opened from Settings → Anywhere → **Set up a phone** (`src/dashboard/frontend/src/components/Settings/sections/AnywhereSection.tsx:70-76`) and from the command palette action `anywhere-set-up-phone` (`src/dashboard/frontend/src/components/palette-anywhere-actions.ts:48-51`, rendered by `AnywhereDialogHost.tsx:44`). Today it only sets up the PWA over Tailscale.
- **PWA flow / "Browser on the phone":** the existing four-step dialog body (install Tailscale, choose https address, require token mint, scan `<origin>/m#pair=<code>`). This issue moves it behind a second tab, unchanged.
- **Phone app / "Overdeck app":** the native iOS and Android app (bundle id `ai.overdeck.app`) the epic builds in `apps/mobile` (PAN-4837). It is not yet published (PAN-4841 owns the store records).
- **Pairing code:** a one-time `odp_<64 lowercase hex>` credential from `POST /api/pairing/credentials` (`src/dashboard/server/pairing-credentials.ts:24,66-75`). Single use, expires 10 minutes after issue, shared by browser, machine and phone pairing (epic hazard H-1).
- **Environment descriptor:** the unauthenticated `GET /api/environment` body (`packages/contracts/src/environment.ts:33-50`, built by `src/dashboard/server/routes/environment.ts:28-48`). It carries `environmentId` (lowercase UUID v4), `machineKey` (64 lowercase hex, optional in the schema) and `capabilities.phoneApp`.
- **Phone pair link:** the string the QR encodes, defined by epic W-MAC2 step 3: `ai.overdeck.app:/pair#v=1&e=<environmentId>&k=<machineKeyHex>&c=<odp_code>`. Note the single slash after the colon (RFC 8252 private-use scheme form, same as the sign-in redirect `ai.overdeck.app:/oauth/callback`). The phone app (PAN-4837) parses it.
- **Directory sign-in:** whether this machine is signed in to overdeck.ai, read from `GET /api/directory` → `DirectoryResponse.signedIn` (`packages/contracts/src/connect-view.ts:82-93`). `pan account login` signs a machine in.
- **Phone row:** a `DeviceRow` with `kind === 'phone'` from `GET /api/devices` (`src/dashboard/frontend/src/components/Settings/anywhere/anywhereApi.ts:13-22`).

## Requirements

### Functional

- **FR-1 Two tabs.** The Set up a phone dialog has a tab list with "Overdeck app" first (selected when the dialog opens) and "Browser on the phone" second. "Browser on the phone" shows the existing PWA flow with unchanged behavior.
- **FR-2 Sign-in gate.** When `GET /api/directory` reports `signedIn: false`, the Overdeck app tab shows `Sign in to overdeck.ai on this machine first: pan account login` and offers no pairing code.
- **FR-3 Pair link format.** When signed in, the tab creates a pairing code with `POST /api/pairing/credentials` and shows a QR whose encoded text is exactly `ai.overdeck.app:/pair#v=1&e=<environmentId>&k=<machineKeyHex>&c=<odp_code>`, using `environmentId` and `machineKey` from `GET /api/environment`.
- **FR-4 Store links.** The tab shows a Google Play link and an App Store link, opening in a new browser tab.
- **FR-5 Paired phones.** The tab lists the phones paired with this machine (active phone rows from `GET /api/devices`) with label, paired time and last-seen time, refreshes every 5 s while the dialog is open, and offers **Remove** with an in-app confirmation.
- **FR-6 Code lifecycle.** The tab shows the code's expiry ("Expires in N minutes · works once"), replaces the QR with "This code expired." when it expires, and offers "Create another code".
- **FR-7 Failure states.** A 403 from the pairing route shows `Pairing codes can be created only from a browser on this machine.` A failed `/api/environment` read, or a descriptor without `machineKey`, shows `Could not read this machine's identity: <error>` and no create button. When signed in but the directory `state` is `refused`, the tab shows the `refusal` text; when it is `connecting` or `off`, it shows `This machine is not connected to overdeck.ai right now. A phone can pair once it is.` These two notes do not block code creation.

### Non-functional

- **NFR-1 One format definition.** The pair-link string is built by one exported function in `@overdeck/contracts`, so the dashboard and the phone app (PAN-4837) cannot drift.
- **NFR-2 No server change.** All data comes from existing routes: `/api/environment`, `/api/directory`, `/api/pairing/credentials`, `/api/devices`, `DELETE /api/devices/:id`. No new route, so no `no-loss-matrix` row.
- **NFR-3 Tests run in CI.** Every new frontend test file is added to `scripts/frontend-test-subset.txt` in alphabetical position.
- **NFR-4 Style guide.** Use the existing dialog classes (`text-xs text-muted-foreground`, `rounded-md border border-border px-2.5 py-1 text-xs`, destructive Remove `text-destructive hover:bg-destructive/10`). No pill badges, no green, no Inter, no new colors.
- **NFR-5 No import cycle.** `SetUpPhoneAppPanel.tsx` and `PairedPhonesList.tsx` never import from `SetUpPhoneDialog.tsx` (the dialog imports the panel; a back-import is a new cycle and `npm run lint:circular` refuses it).

## Decisions

- **D-1 Read the QR inputs from `GET /api/environment`.** It is unauthenticated and carries both `environmentId` and `machineKey`. `AnywhereStatus` lacks the machine key. Add `ENVIRONMENT_QUERY_KEY = ['anywhere-environment']`, `fetchEnvironment()` and `loadEnvironment()` to `anywhereApi.ts`, typed with `EnvironmentDescriptor` from `@overdeck/contracts`.
- **D-2 Gate on `signedIn` only.** The issue and AC-8 require the machine to be signed in. A signed-in machine whose directory socket is `connecting`, `off` or `refused` still gets a QR, with a note (FR-7), because the state can recover while the code is valid (10 minutes).
- **D-3 The link builder lives in `packages/contracts/src/phone-pairing.ts`.** It validates its inputs and throws on a malformed one, so the dashboard never shows a QR the phone would reject. No URL encoding is applied: all three values match `[0-9a-f-]` or `odp_[0-9a-f]{64}` and are validated first. The parser is PAN-4837's job (it imports `PHONE_PAIR_LINK_PREFIX` and the regexes from the same module).
- **D-4 Store links.** `GOOGLE_PLAY_URL = 'https://play.google.com/store/apps/details?id=ai.overdeck.app'` (derived from the package id). `APP_STORE_URL = 'https://overdeck.ai/configuration/phone-app'` (the install guide PAN-4842 publishes) until PAN-4841 creates the App Store record; a code comment names PAN-4841 as the owner of the swap to `https://apps.apple.com/app/id<n>`. No Apple id is invented. Both constants live in `SetUpPhoneAppPanel.tsx` and are exported so PAN-4841 changes one line.
- **D-5 Component split.** New `SetUpPhoneAppPanel.tsx` (the tab body) and `PairedPhonesList.tsx` (list plus Remove, rendered by the panel). `SetUpPhoneDialog.tsx` becomes the tab shell; the existing body becomes a local `BrowserPhoneSetup` component in the same file, behavior unchanged. The panel reuses the shared `QrImage.tsx`, which gains a `data-qr-value={link}` attribute so tests can read the encoded text (the dialog's private `QrImage` already sets it). The dialog's private `QrImage` stays; removing that duplicate is out of scope.
- **D-6 Expiry text helper.** `expiresInText` moves out of `SetUpPhoneDialog.tsx` into `anywhereApi.ts` as `pairingExpiresInText(expiresAt: number): string`, imported by both the dialog and the panel (the panel cannot import from the dialog, NFR-5). `PairDeviceDialog.tsx:49-52` keeps its own copy (out of scope).
- **D-7 Tab control.** Use `ViewToggle` from `components/shared/ViewToggle.tsx` with `ariaLabel="Phone setup"` and options `[{ id: 'app', label: 'Overdeck app' }, { id: 'browser', label: 'Browser on the phone' }]`. Only the selected tab's body is mounted, so each tab's queries run only while it is visible.
- **D-8 Remove wording.** Confirmation title `Remove <name>?`, message `The phone app is signed out of this machine and its open connections close now.` (same message as `DevicesPanel.tsx:29-31`), confirm label `Remove`, variant `destructive`.
- **D-9 Docs.** This issue updates the "Set up a phone" section of `configuration/phone.mdx`. The app's own page (`configuration/phone-app.mdx`) and the wider sweep belong to PAN-4842; this issue does not link to `phone-app.mdx` from the docs, because that page does not exist yet and a dead link fails the docs check.

### W-1 `phone-pair-link` — the pair-link format in `@overdeck/contracts`

- **What and why:** NFR-1, FR-3. One definition of the QR text for the dashboard and the phone app.
- **Files:** new `packages/contracts/src/phone-pairing.ts`; `packages/contracts/src/index.ts` (add `export * from "./phone-pairing"` after `export * from "./connect-view"`, line 43); new `packages/contracts/src/__tests__/phone-pairing.test.ts`.
- **Steps:**
  1. Create `phone-pairing.ts`:
     ```ts
     // The phone app pair link (PAN-4823 W-MAC2, PAN-4836): the text of the QR a machine shows in
     // Settings → Anywhere → Set up a phone → Overdeck app. The phone app (PAN-4837) parses it.

     /** The phone app's bundle id and private-use URI scheme (RFC 8252 §7.1). */
     export const PHONE_APP_SCHEME = "ai.overdeck.app"
     export const PHONE_PAIR_LINK_VERSION = 1
     /** Everything before the fragment. Single slash after the colon. */
     export const PHONE_PAIR_LINK_PREFIX = `${PHONE_APP_SCHEME}:/pair#`

     export const PHONE_PAIR_ENVIRONMENT_ID_RE = /^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/
     export const PHONE_PAIR_MACHINE_KEY_RE = /^[0-9a-f]{64}$/
     export const PHONE_PAIR_CODE_RE = /^odp_[0-9a-f]{64}$/

     export interface PhonePairLinkInput {
       environmentId: string
       machineKeyHex: string
       code: string
     }

     /** `ai.overdeck.app:/pair#v=1&e=<environmentId>&k=<machineKeyHex>&c=<code>`; throws on a malformed input. */
     export function buildPhonePairLink(input: PhonePairLinkInput): string {
       if (!PHONE_PAIR_ENVIRONMENT_ID_RE.test(input.environmentId)) throw new Error("environmentId must be a lowercase UUID v4")
       if (!PHONE_PAIR_MACHINE_KEY_RE.test(input.machineKeyHex)) throw new Error("machineKeyHex must be 64 lowercase hex characters")
       if (!PHONE_PAIR_CODE_RE.test(input.code)) throw new Error("code must be an odp_ pairing code")
       return `${PHONE_PAIR_LINK_PREFIX}v=${PHONE_PAIR_LINK_VERSION}&e=${input.environmentId}&k=${input.machineKeyHex}&c=${input.code}`
     }
     ```
     Match the contracts package style (double quotes, no semicolons, as in `environment.ts`).
  2. Export it from `index.ts`.
- **Tests (`phone-pairing.test.ts`):** with `ENV = "0b5c6c1e-3f2a-4d8e-9a7b-1c2d3e4f5a6b"`, `KEY = "ab".repeat(32)`, `CODE = "odp_" + "cd34".repeat(16)`: `buildPhonePairLink({ environmentId: ENV, machineKeyHex: KEY, code: CODE })` equals `` `ai.overdeck.app:/pair#v=1&e=${ENV}&k=${KEY}&c=${CODE}` ``; it starts with `ai.overdeck.app:/pair#` and does not contain `://`; an uppercase key, a 63-char key, a non-v4 UUID, and a code without `odp_` each throw.
- **Verify:** `npx vitest run packages/contracts/src/__tests__/phone-pairing.test.ts`; `npm run typecheck:contracts`.
