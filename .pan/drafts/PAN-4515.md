# PAN-4515: Chats: idle Claude Code conversations jump to "active just now" hourly

**Issue:** [PAN-4515](https://github.com/eltmon/overdeck/issues/4515)
**Planning mode:** `pan plan --auto` (decisions are recorded below and in the xBRIEF `autoDecisions[]`).

## Glossary

- **Transcript** — the JSONL file a Claude Code session appends one JSON record per line to (`~/.claude/projects/<dir>/<session-uuid>.jsonl`). `resolveSessionFile(row)` in `src/lib/overdeck/conversation-reads.ts` returns its path for a conversation row; in `conversation-list.ts` that path is the local `convSf`.
- **Record** — one parsed line of a transcript. Claude Code writes several record types. `user` and `assistant` records are conversation turns (tool results are `user` records). Other types are housekeeping: `attachment`, `queue-operation`, `system` (`turn_duration`, `stop_hook_summary`), `file-history-snapshot`, and timestamp-less `mode`, `permission-mode`, `last-prompt`, `ai-title`, `atis-latch`.
- **Qualifying record** — a record whose top-level `type` is `"user"` or `"assistant"` AND whose top-level `timestamp` is a string that `Date.parse` turns into a finite number.
- **Modified time (mtime)** — the file system's last-modified time for the transcript, read today with `stat(convSf).mtimeMs`.
- **Touch** — Claude Code's background housekeeping (`touchSessionTranscript`, present in the installed `claude.exe` binary) sets a running session's transcript mtime at startup and then every hour so the cleanup routine does not prune a quiet live session. A touch changes the mtime and adds no record.
- **`lastActivityAt`** — the ISO timestamp field each row of `GET /api/conversations` carries. The Chats tab dates and sorts rows by `lastActivityAt ?? lastAttachedAt ?? createdAt` (`src/dashboard/frontend/src/components/sessionFeed/useConversationFeed.ts`, line 33).
- **Live row** — a conversation row where `sessionAlive` is true in `enrichConversationList` (`src/lib/overdeck/conversation-list.ts`).
- **Pending-input scan** — `scanPendingInputs(jsonlPath)` in `src/lib/agent-enrichment.ts`. It reads the last 512 KB of a transcript (`readFileTail(jsonlPath, 512_000)`) and parses each line to find unanswered AskUserQuestion / plan-mode tool calls. It returns a `PendingInputsScan`.

## Problem

An idle Claude Code conversation jumps to the top of the Chats list as "active just now" about once an hour with no new messages. The cause is `src/lib/overdeck/conversation-list.ts`, lines 278-285:

```ts
      let lastActivityAt: string | null = null;
      if (convSf && existsSync(convSf)) {
        try {
          lastActivityAt = new Date((await stat(convSf)).mtimeMs).toISOString();
        } catch {
          // non-fatal — fall back to lastAttachedAt/createdAt downstream
        }
      }
```

`lastActivityAt` is the transcript's mtime, and Claude Code's touch moves the mtime hourly.

**Verified on real data (2026-10-03).** Transcript `~/.claude/projects/-home-eltmon-Projects-overdeck/ad049b8a-fe95-4002-83b5-70714049bcb8.jsonl` had mtime `2026-10-03 21:54:07.137` (millisecond precision — the touch's signature), but its last `user`/`assistant` record was 136,462 s (about 38 h) older. Several other live transcripts showed gaps of 5-10 h. A transcript in active use showed mtime and last record within 0.5 s of each other.

## Approach

Add the last qualifying record's timestamp to the pending-input scan, which already reads and parses the transcript tail for every live row. For live rows, `lastActivityAt` becomes that timestamp; it falls back to the mtime only when the scan found no qualifying record. Rows that are not live keep today's mtime behavior.

### Decisions

- **D1 — Live rows only; no new I/O.** The pending-input scan runs only under `if (sessionAlive && convSf && existsSync(convSf))` (`conversation-list.ts`, line 259). The touch only affects running sessions: an ended conversation's Claude process is gone, so nothing touches its transcript and its mtime stays equal to its last write. So live rows take `scan.lastRecordAt ?? mtime`, and other rows keep `mtime`. **Rejected alternative:** tail-reading every row's transcript. A list page can be 500 rows; 500 × 512 KB per enrichment would reintroduce the load problem PAN-1705 fixed (see the comment above `LIST_ENRICHMENT_TTL_MS` in the same file).
- **D2 — Qualifying records are Claude `user`/`assistant` only.** Housekeeping records are excluded: several carry no timestamp, and `attachment`/`queue-operation`/`system` records are not turns. Within the 512 KB tail, take the LAST qualifying record in file order (records are appended in order). Normalize the value with `new Date(Date.parse(ts)).toISOString()`.
- **D3 — Other harnesses fall back to mtime (unchanged behavior).** Codex rollout records (`type: "response_item"`, `"event_msg"`, …), ACP JSONL records and pi/ohmypi `type: "message"` records do not match D2, so the scan returns no `lastRecordAt` and those rows keep the mtime. Claude Code is the only harness that touches transcripts. Pi is left out deliberately (ohmypi support is being removed).
- **D4 — The value lives on `PendingInputsScan` as an optional field** `readonly lastRecordAt?: string`. Optional keeps `EMPTY_PENDING_INPUTS_SCAN` and every existing fixture valid. The field is present only when a qualifying record was found.
- **D5 — The pending-input feed is out of scope.** `src/lib/overdeck/conversation-reads.ts`, lines 399-404, also reads the mtime, but there it feeds only the codex `askedAt` fallback (`codexConversationPendingInput(conv, true, lastActivityAt ?? …)`). Claude touches do not reach codex transcripts, so it stays as is.
- **D6 — No frontend change.** `useConversationFeed.ts` line 33 already prefers `lastActivityAt`.
- **D7 — Unit tests target the scan, not the list.** The existing list tests (`src/lib/overdeck/__tests__/conversation-list-*.test.ts`) mock `resolveSessionFile` to `null` and would need `agents.js`, `runtimes/behavior.js`, `conversation-service.js`, `conversation-compaction.js` and `conversation-provider-error.js` mocks to reach the scan. The wiring change is a three-line expression reviewed from the diff. A list-level test is optional, not required.

### Side effect (intended)

`src/lib/lanes/views.ts` line 204 copies the list row's `lastActivityAt` into lane views, and `src/lib/lanes/wait.ts` line 86 uses it for idle timing. Lane conversations running Claude Code get the corrected value too. No code change is needed there.

## Requirements

- **FR-1** — `scanPendingInputs` returns `lastRecordAt`: the ISO timestamp of the last qualifying record (D2) in the 512 KB tail it already reads, or no `lastRecordAt` field when no qualifying record exists.
- **FR-2** — For a live row, `GET /api/conversations` sets `lastActivityAt` to the scan's `lastRecordAt` when present, else to the transcript mtime.
- **FR-3** — A touch (mtime change with no new record) does not change a live row's `lastActivityAt`.
- **FR-4** — When a `user` or `assistant` record is appended, a live row's `lastActivityAt` becomes that record's timestamp.
- **FR-5** — Rows that are not live, and transcripts with no qualifying record, keep the mtime value (today's behavior).
- **FR-6** — `docs/DASHBOARD-ARCHITECTURE.md` describes `lastActivityAt` as the last turn record's timestamp with an mtime fallback, and says why the mtime alone is wrong.
- **NFR-1** — No additional file reads or `stat` calls per row: the timestamp comes from the existing 512 KB tail parse.
- **NFR-2** — `src/lib/agent-enrichment.ts` stays under the 1000-line file-size ceiling (835 lines today; this adds about 15).

   function turnRecordTimestamp(entry: unknown): string | undefined {
