## 1. Summary

Child A adds the server side of "what did this conversation change":

1. `GET /api/conversations/:name/changes?scope=conversation|turn|uncommitted|main&turnId=` returns a `ConversationChanges` (contract already in `@overdeck/contracts`): the conversation's commits (exact from `Overdeck-Conversation` trailers, plus a fallback that reads `git commit` output in the conversation's own shell tool results) and its uncommitted edits (best effort; per-line counts only where the transcript carries edit text).
2. `GET /api/projects/:projectKey/changes?since=` returns a `ProjectChanges`: recent commits on the project's default branch with who made them.
3. `GET /api/conversations` rows gain `changeTotals` for conversations active in the last 24 h, read from a totals map, never computed inside the list request.
4. `GET /api/costs/summary?project=<PREFIX>` adds conversation spend for that project, and "today" becomes the server's local calendar day.

No frontend code changes. Children B, D1, D2, F and G consume these endpoints.

## 2. Glossary

- **Conversation** — a row from `src/lib/overdeck/conversations.ts` (`LegacyConversation`, search `export interface LegacyConversation`). Fields used here: `name`, `tmuxSession`, `cwd`, `issueId`, `workspaceId`, `projectKey`, `createdAt`, `endedAt`, `title`, `origin`.
- **Session name** — `conv.tmuxSession`, always `conv-<name>` for dashboard conversations. It is the value of the `Overdeck-Conversation` trailer and the `agentId` of conversation cost events (parent D-16).
- **Attribution trailer** — `Overdeck-Conversation: <session name>` or `Overdeck-Agent: <agent id>` in the final paragraph of a commit message (#5281; `src/lib/launcher-git-guard.ts`, search `trailerShimLines('Overdeck-Agent', agentId)`).
- **Tool-output commit** — a commit tied to a conversation because the conversation's own shell tool result contains git's `[<branch> <sha>] <subject>` line. Used for commits made before trailers existed.
- **Parse result** — what `getCachedMessages(sessionFile, false)` in `src/lib/overdeck/conversation-reads.ts` returns: `messages` (`ChatMessage[]`), `workLog` (`WorkLogEntry[]`, full tool inputs and results, not the wire-trimmed copy), `fileEditsByAssistantId` (Claude Code only: assistant id → `{ tool, filePath }[]`; other harness parsers return an empty `Map`).
- **Edit record with text** — a work-log entry whose `toolInput` has a string `file_path` and at least one of: string `new_string` (Edit), string `content` (Write), array `edits` of `{ new_string }` (MultiEdit), string `new_source` (NotebookEdit). Only Claude Code transcripts produce these today.
- **Turn** — the assistant messages between two user messages in `parsed.messages` (user `tool_result` records are not messages; `src/dashboard/server/services/conversation/parser.ts` emits `role: 'user'` only for user text). A turn's id is an assistant message id (§4 A-D6).
- **Repo root** — `git rev-parse --show-toplevel` of `conv.cwd`.
- **Local set** — the full shas printed by `git rev-list @{u}..HEAD` in the repo root: commits not yet on the upstream.
- **Full result** — the scope-`conversation` `ConversationChanges` of one conversation; every other scope except `main` is a filter of it.
- **Totals map** — a server-memory `Map<conversation name, { totals: ConversationChangeTotals; at: number }>` that backs `changeTotals` on list rows.
- **Local day start** — midnight of the server's local calendar day, as an ISO UTC string: `new Date(y, m, d).toISOString()`.

## 4. Decisions

Parent decisions that apply: D-5 (exact commits, best-effort uncommitted, naming others only from cached parses), D-10 (spend includes conversations; local "today"), D-16 (join key is `conv.tmuxSession`).

- **A-D1 Module split.** The parent names one new module. It is split so each part has its own tests and no file nears the 1000-line ceiling:
  - `src/lib/overdeck/conversation-change-commits.ts` — trailer commits, tool-output commits, pushed state, turn mapping.
  - `src/lib/overdeck/conversation-change-uncommitted.ts` — uncommitted files, line attribution, other conversations.
  - `src/lib/overdeck/project-changes.ts` — branch log with attribution (`getProjectChanges`, and the helper scope `main` uses).
  - `src/lib/overdeck/conversation-changes.ts` — `getConversationChanges`, scopes, totals, cache, totals map, `stampChangeTotals`.
- **A-D2 Dependency injection, like `conversation-diffs.ts`.** The four modules never import `conversation-reads.ts`. Callers pass `ConversationChangesDependencies` (§6.4). The route file and the list service build it from `conversation-reads.ts`. This avoids an import cycle through the list service and lets tests inject parse results.
- **A-D3 `since` for trailer commits** = 10 minutes before the earliest of `conv.createdAt` and the earliest `createdAt` in `parsed.messages` and `parsed.workLog`. When the transcript is missing, 10 minutes before `conv.createdAt`. Why: conversation rows can be created after the transcript starts (discovered, imported or seeded rows); the margin absorbs clock skew.
- **A-D4 Line attribution is decided from data, not harness name.** A file is `attribution: 'lines'` when at least one edit record with text (glossary) in this conversation's work log targets it; otherwise `'file'`. In practice only Claude Code produces `'lines'`, which is what parent D-5 requires, and no harness literal appears in code.
- **A-D5 Which non-Claude entries count as edits.** A work-log entry counts as an edit of a file when `(entry.toolTitle ?? entry.label).toLowerCase()` is one of `edit`, `write`, `multiedit`, `notebookedit`, and `entry.toolInput` has a string `file_path` or `path` (a relative `path` resolves against `conv.cwd`). This covers Pi and Oh-my-Pi (`edit`/`write` with `path`). Codex keeps shell and patch calls in `command`/`detail` with no `toolInput`, so Codex conversations list no uncommitted files (parent D-5: "else none"). Shell-only edits never appear.
- **A-D6 Turn mapping rule.** `turnIdAt(messages, at, editTurnIds?)`: sort `messages` by `createdAt`; take the last user message with `createdAt <= at` (none ⇒ the turn starts at the beginning) and the next user message after it (none ⇒ open end); the candidates are the assistant messages strictly between those two user messages. Return the id of the last candidate that is in `editTurnIds` when given and present, else the id of the last candidate, else `undefined`. A `turnId` query parameter may carry the `conv-turn-` prefix the diffs API uses; it is stripped.
- **A-D7 Tool-output fallback.** For each work-log entry: the command is `entry.toolInput.command` when it is a string, else `entry.command`. When the command matches `/\bgit\b[\s\S]*\bcommit\b/` and `entry.result` matches `/^\[(?<branch>[^\s\]]+)(?: \(root-commit\))? (?<sha>[0-9a-f]{7,40})\] (?<subject>.+)$/m` (every match in the result counts), the sha is a candidate. A candidate is kept only when `git rev-parse --verify --quiet <sha>^{commit}` resolves **and** `git merge-base --is-ancestor <full sha> HEAD` exits 0. The parent says "drop ones that no longer resolve"; an amended commit's old object still resolves until `git gc`, so reachability from `HEAD` is the rule that actually drops it, and it also keeps the pushed computation valid. Codex results keep the head of long output, so the `[branch sha]` first line survives; Codex coverage is still best effort because its work log is windowed.
- **A-D8 Union.** Commits from trailers and from tool output are merged by full sha. `attribution` is `'trailer'` when the trailer found it (with or without tool output), else `'tool-output'`. Newest first by `authoredAt`.
- **A-D9 Contract gaps, decided without changing the contract.**
  - A conversation whose cwd is not in a git repository returns 200 with `repoRoot: conv.cwd`, `branch: null`, `rootId` per A-D10, empty `commits` and `uncommitted`, and zero totals.
  - In scope `main`, `ChangeCommit.attribution` is `'tool-output'` only for commits tied to this conversation by tool output alone; every other commit is `'trailer'`, including ones with `by.kind: 'unattributed'` (the trailer lookup found nothing).
  - `branch` is `git rev-parse --abbrev-ref HEAD`, or `null` when that prints `HEAD` (detached) or fails.
- **A-D10 Server `rootId`.** The authoritative rules live in the frontend helper, which child A may not edit. The server applies the subset it can answer from the conversation row and `listProjectsAsync()`, first match wins: `conv.origin === 'vault'` ⇒ `null`; `conv.issueId` ⇒ `issue:<ISSUEID upper-cased>`; `conv.workspaceId` set ⇒ `null` (the client resolves workspace-registry roots); cwd under `<project path>/workspaces/feature-<slug>` ⇒ `issue:<SLUG upper-cased>`, other paths under `<project path>/workspaces/` ⇒ `null`; cwd at or under a project path ⇒ `project:<key>` (longest path wins); else `null`. Clients that already know a conversation's root keep using `rootIdForConversation`.
- **A-D11 Project commit attribution precedence.** For each commit: (1) the first final-paragraph `Overdeck-Conversation` value; (2) the first final-paragraph `Overdeck-Agent` value; (3) the first body line matching `/^\s*Overdeck-Conversation:\s*(\S+)\s*$/m`; (4) the first body line matching `/^\s*Overdeck-Agent:\s*(\S+)\s*$/m`; (5) unattributed. Steps 3–4 exist because squash merges move sub-commit trailers into the body.
  - Conversation value `v`: `c = getConversationByTmuxSession(v)`; `by = { kind: 'conversation', id: c?.name ?? v.replace(/^conv-/, ''), title: c?.title ?? c?.name ?? v }`.
  - Agent value `v`: `by = { kind: 'agent', id: v, title: <first /[a-z][a-z0-9]*-\d+/i match in v, upper-cased> ?? v }` (agent ids look like `agent-pan-5288`, `planning-pan-5288`).
- **A-D12 Project route path is `/api/projects/:projectKey/changes`.** The parent writes `:key`; every sibling project route names the parameter `projectKey`, so the URL is the same and the router stays consistent.
- **A-D13 Project branch ref.** `branch = resolveDefaultBranchForRepo(project.path, projectKey)`. The log runs on `origin/<branch>` when `git rev-parse --verify --quiet origin/<branch>^{commit}` resolves, else on `<branch>`, else the response is `{ projectKey, branch, commits: [] }`. Unknown project key ⇒ 404 `{ error: 'Project not found' }`.
- **A-D14 `since` query value** (project route): `^(\d{1,4})([dh])$` ⇒ now minus that many days or hours, at most 90 days; any other value that `Date.parse` accepts ⇒ that instant; missing ⇒ `7d`; anything else, or more than 90 days ⇒ 400 `{ error: 'Invalid since' }`. Git always receives an ISO string. At most 500 commits.
- **A-D15 Cache.** One full result per conversation, key `name`, max 64 entries (oldest insertion evicted), valid while the transcript size and mtime and `git rev-parse HEAD` are unchanged and less than 30 s old (same TTL as `DIFFS_CACHE_TTL_MS`). Scopes `turn` and `uncommitted` filter the cached full result. Scope `main` has its own entry, key `<name>\0main`, valid while HEAD is unchanged and less than 30 s old. Working-tree edits are covered by the TTL.
- **A-D16 List totals never block the list.** `changeTotals` comes only from the totals map, filled by every full-result computation. The list stamps rows from it and schedules background computations for rows active in the last 24 h whose entry is missing or older than 30 s: at most 2 running at once, at most 20 queued per list call, deduplicated by name, errors logged and swallowed. Rows inactive for 24 h get no `changeTotals`.
- **A-D17 Spend membership.** `?project=<PREFIX>` stays an issue prefix (the only caller, `CommandDeck/ProjectOverview.tsx`, sends one). Project keys for the prefix: projects whose `issue_prefix` or any `issue_prefixes` entry equals it, case-insensitive. A conversation belongs to the project when `projectKey` is one of those keys, or `projectKey` is null and its `cwd` is at or under one of those projects' paths (longest path wins across all projects). Conversations come from `listConversations()` plus `listArchivedConversations()`, so archiving does not hide this week's spend. An event counts when its `issueId` starts with `<PREFIX>-` **or** its `agentId` is one of those conversations' `tmuxSession`; one event is counted once.
- **A-D18 One "today".** `localDayStartIso(now)` is defined once in `src/lib/costs/request-digest.ts`. `usageWindowStarts(now).today` returns it (the fleet usage windows), and the costs summary uses `usageWindowStarts` for all three windows, so the summary and `/api/fleet/usage` agree on this machine. `week` and `month` keep today's UTC-date rule. Machines in different time zones still disagree about "today" in the fleet view; that stays out of scope.
- **A-D19 Untracked and large files.** Untracked files read their content only when 2 MiB or smaller; a larger untracked file reports `additions: 0` and `attribution: 'file'`.

## 5. Requirements

### Functional
- **FR-1** `GET /api/conversations/:name/changes` returns `ConversationChanges` for scopes `conversation` (default), `turn`, `uncommitted` and `main`; unknown conversation ⇒ 404; unknown scope ⇒ 400 `{ error: 'Invalid scope' }`. (Parent FR-5.)
- **FR-2** Commits: trailer commits found with the session name (D-16), never the bare name; tool-output commits per A-D7; union per A-D8; `pushed` from the local set (no upstream ⇒ all `false`); `turnId` per A-D6; `files` from `git diff-tree` per commit.
- **FR-3** Uncommitted: files in `git status --porcelain=v2 -z --untracked-files=all` that this conversation edited (Claude `fileEditsByAssistantId` paths ∪ A-D5 entries), with `status`, numstat additions/deletions, `attribution` per A-D4, `turnIds`, and for `'lines'` files `otherLines` and `otherConversations` per D-5.
- **FR-4** Scopes: `conversation` = everything, every commit and file carrying its turn ids; `turn` = commits whose `turnId` equals the requested turn and uncommitted files whose `turnIds` include it (default turn: the last turn that has a commit or an uncommitted file); `uncommitted` = uncommitted only; `main` = first-parent commits on `HEAD` since the local day start, attributed per A-D11, with `by.isThisConversation`.
- **FR-5** `totals` per response: `files` = distinct paths across the returned commits and uncommitted files; `additions`/`deletions` = sums over all returned commit files plus uncommitted files; `commitsPushed`, `commitsLocal`, `uncommittedFiles` = counts.
- **FR-6** `GET /api/projects/:projectKey/changes?since=` returns `ProjectChanges` per A-D11, A-D13 and A-D14. (Parent FR-6.)
- **FR-7** `GET /api/conversations` local rows carry `changeTotals?: ConversationChangeTotals` per A-D16.
- **FR-8** `GET /api/costs/summary?project=<PREFIX>` includes conversation cost events per A-D17; `today` starts at the local day start (A-D18). (Parent D-10.)
- **FR-9** `getConversationDiffTurn` finds the repository of a conversation whose cwd is a subdirectory of the repo. `ConversationDiffParseResult` carries `workLog`.
- **FR-10** Route scopes: `GET /api/conversations/:name/changes` is `read:conversations`; `GET /api/projects/:projectKey/changes` has no row (admin default). Both have no-loss rows.

### Non-functional
- **NFR-1** All git and process calls in new code use async `execFile` with argument arrays (no shell strings, no `execSync`, no `exec`). Reusing the existing `repoRootForDir` (a constant-string async `exec`) is allowed.
- **NFR-2** A second request for the same conversation within 30 s, with the transcript and HEAD unchanged, returns the cached result without running `git diff-tree`, `git status` or `git log` (parent NFR-2).
- **NFR-3** No file passes `scripts/lint-file-size.sh`; `conversation-reads.ts` grows by at most 8 lines.
- **NFR-4** No new polling; the list never awaits a changes computation.
- **NFR-5** One clock: every TTL, 24 h and local-day comparison in the new modules reads `deps.now()` (production: `Date.now`); tests drive time by changing the value `now()` returns, never with real delays. Functions outside the deps (`localDayStartIso(now)`) take `now` as an argument.

### 6.1 `src/lib/git/attributed-commits.ts` — export the per-commit file list

Before (search `async function listCommitFiles(git:`): private. After, add one export below `listAttributedCommits`, reusing the private function:

```ts
/** The files one commit changed (diff-tree against its first parent; root commits against the empty tree). */
export async function listCommitFilesAt(repoPath: string, sha: string): Promise<AttributedCommitFile[]> {
  const git = async (args: string[]): Promise<string> =>
    (await execFileAsync('git', ['-C', repoPath, ...args], { encoding: 'utf8', maxBuffer: 16 * 1024 * 1024 })).stdout;
  return listCommitFiles(git, sha);
}
```

### 6.6 `conversation-change-uncommitted.ts` (WI-3)

Exports:

```ts
/** Repo-relative path → the conversation's edit evidence (A-D4, A-D5). */
export function editedFiles(input: { repoRoot: string; cwd: string; parsed: ConversationDiffParseResult }):
  Map<string, { turnIds: Set<string>; writtenLines: Set<string>; hasText: boolean }>;
export function writtenLinesOf(toolInput: Record<string, unknown>): Set<string>;
export async function listUncommittedFiles(input: {
  repoRoot: string; cwd: string; parsed: ConversationDiffParseResult;
  others: () => Promise<Array<{ name: string; title: string; parsed: ConversationDiffParseResult }>>;
}): Promise<UncommittedFile[]>;
```

Rules:
1. Status: `git -c core.quotePath=false status --porcelain=v2 -z --untracked-files=all`. Records: `1 <XY> …  <path>`, `2 <XY> … <path>\0<origPath>` (`'R'`, `oldPath` set), `u …` (`'M'`), `? <path>` (`'A'`). For `1`: `'D'` when X or Y is `D`, `'A'` when X is `A`, else `'M'`.
2. Keep only paths in `editedFiles(...)`. Absolute edit paths become repo-relative by stripping `<repoRoot>/`; paths outside the repo are dropped. Compare with `realpath` of the repo root and of each edited file's parent directory when it exists (cached per directory), because transcripts may record a symlinked path.
3. `writtenLinesOf`: Edit ⇒ `lines(new_string) − lines(old_string)`; MultiEdit ⇒ the same per `edits[]` entry, unioned; Write ⇒ `lines(content)`; NotebookEdit ⇒ `lines(new_source)`. `lines(s)` = `s.split('\n').map(l => l.trim()).filter(l => l !== '')`.
4. Additions/deletions: one `git diff HEAD --numstat -z --no-renames -- <tracked kept paths>`; untracked ⇒ additions = the content's line count (`content.split('\n').length`, minus one when the content ends with `\n`), deletions 0. A repository with no `HEAD` treats every kept path as untracked.
5. Line attribution for `hasText` files: one `git diff HEAD -U0 --no-color --no-renames -- <those paths>`, split per `diff --git a/<p> b/<p>` section; plus-lines = lines starting with `+` but not `+++`, text after `+`, trimmed, non-empty (untracked: all trimmed non-empty content lines). `matched` = plus-lines whose text is in `writtenLines`; `otherLines = plusLines − matched`. `attribution: 'lines'`. Files without `hasText` get `attribution: 'file'` and no `otherLines`/`otherConversations`.
6. `otherConversations` only when `otherLines > 0`: for each entry of `others()`, compute that conversation's `writtenLines` for the same path; include `{ name, title }` when any unmatched plus-line is in it. Empty array when none match.
7. `others()` (built by the assembly): conversations from `deps.listConversations()` with a different name, `cwd` at or under the repo root, and `endedAt === null` or ended within 7 days; at most 50; for each, `deps.resolveSessionFile(c)` then `deps.peekCachedMessages(file)`; a cache miss is skipped (never parsed).

Hand-off rule: `turnIds` = the `fileEditsByAssistantId` keys whose edits include the path, plus `turnIdAt(messages, entry.createdAt)` for A-D5 entries; deduplicated, in first-seen order.
