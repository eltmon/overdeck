## Glossary

- **Operator:** the human who owns the Apple, Google, Firebase and Cloudflare accounts. Only the operator can log in to those consoles.
- **Work agent:** the Overdeck `work` role agent that executes this plan in `workspaces/feature-pan-4841/`.
- **Operator checklist:** one numbered list of console steps in `apps/mobile/RELEASE.md` that the operator does once (WI-1). It is also posted as a comment on PAN-4841.
- **Secret request:** the Overdeck MCP tool pair `request_secret` → `secret_wait`. The operator types the value into the Overdeck dashboard. The agent receives a path to a private mode-0600 file and reads it straight into the program that needs it. The value never appears in chat, a tool argument, the repo or an issue comment. There is **no** `pan secret` CLI verb (`pan secret` answers `unknown command`; verified 2026-11-04).
- **Directory / connect Worker:** the Cloudflare Worker `overdeck-connect` at `https://connect.overdeck.ai` (`services/connect`). It forwards sealed push payloads to APNs and FCM (PAN-4830).
- **Push secrets:** the five Worker secrets `APNS_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `FCM_SERVICE_ACCOUNT_JSON`, `FCM_PROJECT_ID` (`services/connect/src/env.ts` lines 25-31).
- **`healthz`:** `GET https://connect.overdeck.ai/healthz`. It answers `{ ok, configured, turn, apns, fcm }` (`services/connect/src/routes.ts` line 33). `apns`/`fcm` are true when the secrets are present and parse; they do not prove that Apple or Google accept the key. Only a delivered push proves that (WI-14).
- **Upload key / upload keystore:** the key that signs the Android App Bundle (`.aab`) before it goes to Google Play. Google re-signs the app with its own app-signing key (Play App Signing). Losing the upload key is recoverable through Play Console support, but it is slow.
- **AAB:** Android App Bundle, the file format Google Play accepts.
- **Mac rig:** the operator's MacBook used for iOS builds. SSH key `~/.ssh/gauntlet_air`, user `eltmon`, address from DHCP (it was `192.168.1.83` on 2026-11-01; machine memory `mac-rig-safari-testing`). Non-interactive shells need `export PATH=/opt/homebrew/bin:$PATH`.
- **Console session:** a Terminal window on the Mac's logged-in desktop. A script started there with `open -a Terminal <file>.command` can use the unlocked login keychain. An SSH session cannot, so `codesign` fails there with `errSecInternalComponent` (skill `myn-rig-release`, "Gotchas"; machine memory `mac-rig-ios-upload`).
- **Xcode Apple ID session:** the Apple ID signed in under Xcode → Settings → Accounts on the rig. `xcodebuild -exportArchive` with `destination: upload` needs it. App Store Connect API keys do not work for this team (machine memory `mac-rig-ios-upload`: keys `K65TAD5ZTR`, `G558A7KH82`, `N4LW5ZFKXK` all failed on 2026-11-01).
- **Team id:** the Apple Developer team `KUU2VM9GB9` (skill `myn-rig-release`, "The rig"). Not a secret.
- **Build number:** Android `versionCode` and iOS `CFBundleVersion`. Each store upload needs a new, higher number. **Version name:** Android `versionName` and iOS `CFBundleShortVersionString` (`MARKETING_VERSION`), `1.0` for this issue.
- **Required-reason API:** an iOS API (for example `UserDefaults`) that Apple requires an app to declare, with a reason code, in `PrivacyInfo.xcprivacy`.

## Decisions

- **D-1 Build numbers come from the command line.** Both scripts take `--build <n>` (a positive integer). Android passes `-PoverdeckVersionCode=<n>`; iOS passes `CURRENT_PROJECT_VERSION=<n>` on the `xcodebuild archive` command line, which applies to the app and both extensions (Apple requires them to match). Version name stays `1.0` (`--version-name` overrides it). Nothing is committed per build. The first upload on each store uses `--build 1`. The stores refuse a reused number, so no local counter is needed.
- **D-2 Upload keystore.** PKCS12 at `~/.overdeck/secrets/android-upload.jks`, alias `overdeck-upload`, RSA 4096, validity 10000 days, dname `CN=Overdeck Upload, O=Overdeck`. The store password is 32 random bytes, base64, in `~/.overdeck/secrets/android-upload.password` (PKCS12 uses one password for the store and the key). The work agent generates both (no account login is needed). The committed pin is `apps/mobile/android/upload-certificate.sha1`: one line, the certificate's SHA-1 in `AA:BB:…` form. The operator copies the password file's content into their password manager (checklist step).
- **D-3 The work agent sets the five push secrets.** Rule: values arrive through secret requests; the agent pipes each file into `npx wrangler secret put <NAME>` from `services/connect`; it never runs `wrangler deploy`. Why: the operator's 2026-11-04 decision routes these secrets to the agent, and PAN-4838's comment asks this issue to set them and confirm `healthz`. `wrangler secret put` creates a Worker version from the code already deployed, so the operator-only rule for code deploys still holds. `docs/CONNECT-SERVICE.md` "Deploy" gains this one exception in WI-15.
- **D-4 `FCM_PROJECT_ID` is derived,** not requested: it is `project_info.project_id` from `google-services.json`. The agent checks that it equals the `project_id` field of the service-account JSON and stops with an error if they differ.
- **D-5 `APNS_TEAM_ID` defaults to `KUU2VM9GB9`** (the rig's signing team). It is still requested through a secret request so the operator confirms which team owns the key; the prompt names the default.
- **D-6 First builds do not wait for PAN-4840.** PAN-4840 waits for this issue's `google-services.json` and FCM secret; waiting for its merge here would make the two issues wait on each other. The first Play internal build is made from this branch after WI-9 and WI-10 land. A later build ships Android push decryption after PAN-4840 merges. iOS push (PAN-4838) and the Live Activity (PAN-4839) are already on `main`, so the first TestFlight build includes them.
- **D-7 The privacy policy source lives in this repo** at `apps/mobile/store/privacy-app.html`, so review sees it. The work agent copies it byte for byte to `site/privacy/app/index.html` in `eltmon/overdeck-landing` and opens a PR there. The live page appears when that PR merges (Vercel deploys `main`).
- **D-8 Icons and splash are generated** by a committed script, `apps/mobile/scripts/generate-brand-assets.mjs`, from `src/dashboard/frontend/public/favicon.svg` on `#202020`. It overwrites each existing PNG at its current pixel size, so no Xcode or Android resource list changes.
- **D-9 Export compliance is the operator's answer.** `ITSAppUsesNonExemptEncryption` is **not** added to `Info.plist`, so App Store Connect asks on the first build. The checklist states the facts: the app uses standard algorithms (X25519, ChaCha20-Poly1305 and XChaCha20-Poly1305, SHA-256, through libsodium and the Noise protocol) to end-to-end encrypt user data. MYN's answer ("none of the algorithms") does not apply to this app.
- **D-10 App Store name fallback.** If "Overdeck" is taken in App Store Connect or Play, use "Overdeck Anywhere". The bundle id and the name under the icon (`CFBundleDisplayName`, Android `app_name`) stay "Overdeck".
- **D-11 APNs key.** Create a new APNs auth key for the team. Apple allows two per team; if the cap is reached, reuse the team's existing key (a key is team-wide; the `apns-topic` header scopes each push to `ai.overdeck.app`). The checklist records which one was used, never the key itself.
- **D-12 FCM service account.** A dedicated service account in the Overdeck Firebase project's Google Cloud console with only the role **Firebase Cloud Messaging API Admin** (`roles/firebasecloudmessaging.admin`). Fallback when the console refuses key creation or the operator prefers it: the Firebase console's "Generate new private key" for the `firebase-adminsdk` account of the same project.
- **D-13 Rig address is a required flag** (`--rig eltmon@<ip>`), because DHCP changes it. The SSH key defaults to `~/.ssh/gauntlet_air`.
- **D-14 Device checks are evidence, not code.** The agent cannot hold the iPhone. It drives the desktop side (asking the AskUserQuestion, `wrangler tail`) and asks the operator to do the phone steps and report what they saw. The results go into `apps/mobile/ACCEPTANCE.md`.

## Hazards
