## Summary

The issue asks for a line-by-line accuracy audit of every published page in the **CLI Reference** navigation group. The
planning session already did the audit: six parallel research passes read all ten pages (2,657 lines) against current
code and `pan <verb> --help` (the installed `pan` is 0.89.1 and matches this tree), and the planner re-checked the
headline findings by grep and by viewing the screenshots. This PRD lists every wrong, stale, removed or missing claim per
page with the exact current text, the replacement text and the code evidence (Appendices B to J2). The implementation
agent applies those changes, removes the stale screenshots, fixes frontmatter, checks links, runs the Mintlify validators,
and writes a PR body with one note per page. It does not need to re-research; it re-checks a claim only when a grep anchor
no longer matches or the Common procedure tells it to.

## Glossary

- **CLI Reference group**: the `"group": "CLI Reference"` block in `docs.json` (line 84 on the base). On the base it lists
  ten pages: `cli/overview`, `cli/core-commands`, `cli/hygiene`, `cli/agent-commands`, `cli/conversation-commands`,
  `cli/pipeline-commands`, `cli/workspace-commands`, `cli/review-commands`, `cli/skills-commands`, `cli/memory-commands`.
  The separate `Anywhere CLI` group (`cli/share`, `cli/machines`, `cli/vault`, …) belongs to #5500, not this issue.
- **Claim**: any statement on a page a reader could act on: a command, subcommand or flag, a default, a config key, a UI
  label or location, a file path, a port, a behavior, a limit, a list of supported trackers, harnesses or platforms, or a
  maturity label.
- **Primary source**: the code on the base (`git grep`, the Commander definitions in `src/cli/index.ts` and
  `src/cli/commands/*.ts`), `pan <verb> [sub] --help`, `src/lib/config-yaml/defaults.ts`, the dashboard source under
  `src/dashboard/frontend/src/`, and `changelog.mdx`. Other `.mdx` pages, `docs/*.md` and `README.md` are never proof.
- **Grep anchor**: the quoted current text in each appendix row. Line numbers drift as earlier edits land, so find the
  text with `grep -n -F '<anchor>' cli/<page>.mdx`, not by line number.
- **Dash rule**: no U+2013 (en dash) or U+2014 (em dash) anywhere in a touched page, frontmatter and body. Check:
  `grep -nP '[\x{2013}\x{2014}]' cli/<page>.mdx` prints nothing. Replace a dash with a comma, colon, period, parentheses,
  or the word "to" for a range. On the base only `agent-commands.mdx` (2 lines) and `workspace-commands.mdx` (2 lines)
  have dashes. A plain ASCII hyphen-minus `-` (used in "**Frontend** - React dashboard" style bullets) is not a dash.
- **Frontmatter rule**: `title` is specific and searchable; `description` is 50 to 160 characters (the text between the
  quotes); neither contains a dash; a value containing `: ` is double-quoted. When this PRD retitles a page it also adds
  `sidebarTitle: "<the old title>"` so the navigation label stays short (the pattern `cli/pipeline-commands.mdx` already
  uses).
- **Experimental**: a dashboard view hidden unless Settings → Experimental → **Experimental features** is on. The gated
  views are listed in `EXPERIMENTAL_TAB_IDS` in `src/dashboard/frontend/src/lib/experimentalFeatures.ts:4-15`: agents,
  autopreso, resources, sessions, metrics, costs, health, god-view. The Pipeline, Board, Awaiting Merge, Activity and
  Skills views are not gated.
- **Stale screenshot**: one of the five dashboard PNGs the CLI pages embed (`command-deck-hero`, `pipeline`, `agents`,
  `resources`, `awaiting-merge`, each `-light.png` and `-dark.png` under `images/dashboard/`). All five last changed on
  2026-06-04 and show the pre-rebrand "Panopticon v0.21.0" sidebar and UI that has since moved (the planner viewed
  `awaiting-merge-light.png` and `resources-light.png`; the research passes viewed the other three). See Decision D3.
- **Follow-ups**: code bugs or out-of-scope doc problems found during the audit. They go in a `## Follow-ups` list in the
  PR body. This issue changes no code.
- **PR note**: a one-line summary of what changed on a page, or "verified, no change". Each page's last item puts its note
  in its commit message as a line `PR-note: cli/<page>.mdx: <note>`; the final item collects them into the PR body.
- **Appendix row**: a row in Appendices B to J2, referenced as `<Appendix>.<table>.<row>`, where table is `W` (wrong or
  stale), `R` (removed, delete), `M` (missing, add) or `L` (broken links). For example `B.W.13` is row 13 of the "Wrong or
  stale claims" table of Appendix B.

## Shared facts (use this wording on every page)

Several pages state the same facts. Use these exact facts so parallel page items agree. Each was verified by the planner.

- **S1 Dashboard URL.** `pan up` serves the dashboard and its API from one Node server. With Traefik enabled (the
  `pan install` default) it is `https://overdeck.localhost`; without Traefik (`pan install --minimal`, or
  `pan up --skip-traefik`) it is `http://localhost:3011`. There is no separate frontend on port 3010 in production.
  Evidence: `src/dashboard/server/config.ts:71` (`process.env['API_PORT'] ?? process.env['PORT'] ?? '3011'`),
  `src/cli/up-readiness.ts:23-28`, `src/cli/commands/install.ts:598-611`. (Port 3010 is only the Vite dev server from
  `pan dev`, `src/cli/commands/dev.ts:54`.)
- **S2 Issue IDs.** An issue ID is `<PREFIX>-<number>` such as `MIN-123`, case-insensitive. A GitHub issue uses its
  project's `issue_prefix`, so `eltmon/overdeck#42` is `PAN-42`. Rally IDs look like `F29698`, `US1234`, `DE123`
  (`src/lib/issue-id.ts:56`). Jira keys use the standard `PROJ-123` form. A bare number such as `42` works only for
  commands that act on an existing agent (`pan tell`, `pan kill`, `pan show`, `pan close`, `pan reopen`, …) and only when
  exactly one agent on this machine matches (`src/lib/issue-id.ts:183-187`); `pan start` needs the full ID
  (`src/cli/commands/start.ts` never calls `resolveBareNumericId`). `#42` and `!42` are not CLI issue IDs.
- **S3 Trackers.** Issue trackers are GitHub, Linear, Rally and Jira. GitLab is supported as a code host (merge requests,
  the merge train) but its issue tracker is a stub that throws "GitLab tracker is not yet implemented. Coming soon!"
  (`src/lib/tracker/gitlab.ts:2,39,43`). Never list GitLab as an issue tracker.
- **S4 Experimental label.** When a page names an experimental view (Agents, Resources, Sessions, Costs, Health, Metrics,
  AutoPreso, God View), add once per page, at the first mention: "(experimental: turn on Settings → Experimental →
  **Experimental features** to show it)". Later mentions on the same page may say "(experimental)".
- **S5 Compact recovery.** `pan recover <id> --compact` compact-respawns a context-wedged agent. `pan resume --compact` is
  still listed by `--help` but is always refused, because session rotation on resume is disabled
  (`src/lib/session-rotation.ts:18` `ALLOW_SESSION_ROTATION_ON_RESUME = false`; only `src/cli/commands/recover.ts:108`
  passes `recoverGated: true`). Pages document `pan recover --compact` and do not document `pan resume --compact`.
- **S6 Terminal backend.** Herdr is the default terminal backend; tmux is supported with `terminal.backend: tmux`
  (`src/lib/terminal-backends/select.ts:204`). Do not say agents run "in tmux sessions" without that qualifier.
- **S7 Help links.** The Overdeck Discord is https://discord.gg/ZpHE2ZTv5P and GitHub Issues is
  https://github.com/eltmon/overdeck/issues (both already in the `docs.json` footer).

## Common procedure for every page item

0. **Code wins.** If a primary source contradicts a row in this PRD (the research was wrong, or main moved), skip the row,
   record it in the PR note, and say why in the commit message. If the skipped row is named in an acceptance criterion,
   block that criterion with `pan task block` and the evidence instead of writing a claim the code contradicts.
1. **Apply the rows.** For each row the work item names, find the grep anchor with `grep -n -F`, make the change, and keep
   the evidence in mind for the wording. If an anchor no longer matches, find the claim by meaning; if the claim is gone,
   skip the row and say so in the PR note.
2. **Spot-check before deleting.** Before deleting a section or a feature claim, re-run the row's evidence grep once. If
   the evidence no longer holds (main moved), keep the text and note it as a Follow-up.
3. **Residual rule.** Read the whole section once. For a claim no row lists that looks doubtful, verify it against a
   primary source; if the code disagrees, change the page to match the code. Do not chase claims that look right; the
   "Verified, keep" lists already cover most of them.
4. **Dashes.** Remove every en and em dash in your section (dash rule), in the same commit.
5. **Frontmatter** (the page's last item only): apply D4.
6. **Links.** For each internal link you add or touch, `ls <path>.mdx` (and `grep -n "^#.*<heading words>"` for an anchor),
   counting `docs.json` redirects.
7. **MDX safety.** Keep every new `<word>` placeholder inside backticks. A `<Tip>` or `<Note>` tag must stay balanced.
8. **Commit** with `Item: <id>`, its AC trailers and, on the page's last item, `PR-note: cli/<page>.mdx: <one line>`;
   push; `pan task done`.
