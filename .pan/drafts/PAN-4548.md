# PAN-4548: lint-docs test resolves its script with `URL.pathname`; use `fileURLToPath`

**Issue:** [PAN-4548](https://github.com/eltmon/overdeck/issues/4548) · Origin: SHOULD finding on PR #4513 (PAN-4509), flagged by CodeRabbit and the Overdeck reviewer, merged unaddressed.

## Glossary

- **`import.meta.url`** — the `file://` URL of the current ES module. Characters such as spaces appear percent-encoded (`%20`).
- **`URL.pathname`** — the path component of a URL, still percent-encoded. For `file:///tmp/a%20b/x.js` it returns `/tmp/a%20b/x.js`, which is not a real filesystem path.
- **`fileURLToPath(url)`** — from `node:url`; decodes a `file://` URL into an OS filesystem path (`/tmp/a b/x.js`).
- **`SCRIPT`** — the constant in the test file that holds the path of `scripts/lint-docs.js`; it is passed to `node` via `execFileSync` by the CLI tests.

## Problem

`tests/unit/scripts/lint-docs.test.ts` line 11 (grep anchor: `const SCRIPT = new URL('../../../scripts/lint-docs.js', import.meta.url).pathname;`) builds the CLI path with `.pathname`. Line 156 (grep anchor: `execFileSync('node', [SCRIPT, '--root', root]`) passes it to Node. When the checkout path contains a space, `SCRIPT` holds `%20`, Node is told to run a file that does not exist, and the three tests in the `lint-docs CLI` describe block fail.

Verified at planning time (2026-10-04):

```
$ node -e "const {fileURLToPath,pathToFileURL}=require('node:url'); const u=pathToFileURL('/tmp/a b/scripts/lint-docs.js'); console.log(new URL('../scripts/lint-docs.js', u).pathname, '|', fileURLToPath(new URL('../scripts/lint-docs.js', u)))"
/tmp/a%20b/scripts/lint-docs.js | /tmp/a b/scripts/lint-docs.js
```

There is a second, latent reason the decoded path matters: `scripts/lint-docs.js` line 139 (grep anchor: `const isMain = process.argv[1] && fileURLToPath(import.meta.url) === process.argv[1];`) compares its own decoded path to `process.argv[1]`. A percent-encoded argv would never match, so the CLI body would not run even if the file were found. Passing a decoded path makes both sides agree.

## In-repo precedent

`scripts/lint-docs.js` line 10 (`import { fileURLToPath } from 'node:url';`) and line 139 already use `fileURLToPath`. Other tests use the exact `fileURLToPath(new URL(` shape, e.g. `tests/unit/scripts/audit-effect-boundary.test.ts`.

## Requirements

- **FR-2:** `npx vitest run tests/unit/scripts/lint-docs.test.ts` exits 0 with every test passing.

## Decisions

- **Scope is the one file the issue names.** The same `.pathname` pattern exists in `tests/unit/scripts/vendor-okf-skill.test.ts` (line 15, `SCRIPT_SOURCE.pathname`), `tests/unit/scripts/lint-dist-externals.test.ts` (lines 13 and 295), and `tests/unit/scripts/canonicalize-circular-deps.test.ts` (line 7). They are out of scope for this issue and must not be edited here; they belong in a follow-up issue.
- **No new regression test.** Reproducing a space in the checkout path would require a second full checkout with `node_modules`. The fix is mechanically checkable by grep plus the existing CLI tests, and the planning-time node probe above proves the encoding difference.
