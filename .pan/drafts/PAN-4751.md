# PAN-4751 — Flywheel page: clicking NEEDS YOU reopens the pending question dialog

**Issue:** [PAN-4751](https://github.com/eltmon/overdeck/issues/4751)
**Status:** draft (auto-planned 2026-11-02)

## Glossary

- **Flywheel conversation** — the conversation named `conv-flywheel` (`FLYWHEEL_CONVERSATION_NAME` in `src/dashboard/frontend/src/lib/flywheelApi.ts`, line 14) that runs the `/pan-flywheel` loop skill.
- **Tick marker** — the line `flywheel-tick: tick=<n> pick=<ID|none> phase=<phase> in-flight=<…> needs-you=<text|none>` the loop prints at the end of every tick. `findLastTick()` in `src/lib/flywheel/tick-marker.ts` returns the newest one from an **assistant** message.
- **Last tick** — `FlywheelDerivedStatus.lastTick` (`packages/contracts/src/flywheel-derived.ts`, `FlywheelLastTick`), served by `GET /api/flywheel/status`.
- **NEEDS YOU banner** — the block in the Flywheel page's Status tab that shows `lastTick.needsYou`. Today it is a `<div role="note" data-testid="flywheel-needs-you">` in `src/dashboard/frontend/src/components/flywheel/FlywheelStatusPane.tsx`, lines 118–123. It is **not** the app-header `NeedsYouIndicator` (a separate component, out of scope).
- **AUQ** — a Claude Code `AskUserQuestion` tool call that is waiting for an answer.
- **Pending-input feed** — `GET /api/conversations/pending-input`, polled by the frontend under the shared React Query key `['conv-ask-user-question']` with `fetchConversationPendingInput()` (`src/dashboard/frontend/src/lib/useDecisions.ts`, line 158). Each row (`ConversationPendingInputRow`, line 32) has `name` and an optional `pendingAskUserQuestion: { toolUseId, askedAt, questions }`.
- **AUQ dialog** — `AskUserQuestionDialog`, mounted once app-wide by `AppLiveStoreHost` (`src/dashboard/frontend/src/App/AppLiveStoreHost.tsx`) from `usePendingInputDialogs()` (`src/dashboard/frontend/src/App/hooks/usePendingInputDialogs.ts`).
- **Reopen channel** — `useAskUserQuestionUiStore.requestReopen(subjectId)` (`src/dashboard/frontend/src/lib/askUserQuestionUiStore.ts`, line 93). The effect in `usePendingInputDialogs.ts` (lines 91–144) un-dismisses and focuses that subject, so the AUQ dialog shows it again. `DecisionsPanel`, `SessionFeedSidebar`, `ConversationRow` and `SessionPanel` already use it.
- **Optimistically answered** — `useAskUserQuestionUiStore.answeredToolUseIds`: toolUseIds the operator answered but the feed has not yet dropped.
- **Message jump** — `ConversationPanel` props `targetMessageId`, `targetMessageNonce`, `onTargetMessageHandled` (`src/dashboard/frontend/src/components/chat/ConversationPanel.tsx`, lines 116–120). `MessagesTimeline` scrolls to the row with that message id and pages older history in when the row is not loaded (PAN-4558).

## Problem

The NEEDS YOU banner is plain text. When the Flywheel conversation asks the operator a question with AskUserQuestion, the dashboard shows the AUQ dialog (PAN-1520). Once the operator dismisses it (ESC) or loses it, nothing on the Flywheel page brings the question back. When the loop is waiting on a decision it wrote only into the tick line, the operator also has no quick way to find the message that said it.

## Requested behavior (operator, 2026-11-02)

1. Clicking the banner reopens the AUQ dialog for the Flywheel conversation's unanswered AskUserQuestion, with the same questions and options. Answering it there reaches the conversation through the same path as the original dialog.
2. When the conversation has no unanswered question, clicking the banner shows the Flywheel conversation scrolled to the message that produced the tick.

## Decisions

- **D1 — Reuse, do not rebuild.** The reopen branch calls `requestReopen(FLYWHEEL_CONVERSATION_NAME)` and nothing else. The app-level host renders the existing AUQ dialog; answering uses the existing `postPendingAnswer` path. No new dialog, no new route.
- **D2 — The page decides the branch itself.** For a conversation subject, the reopen effect silently does nothing when no question is pending (it toasts only for known agents). So the page reads the pending-input feed with the shared key `['conv-ask-user-question']` and `fetchConversationPendingInput` (refetchInterval 5000, same as `useDecisions`), so React Query dedupes the poll.
- **D3 — Branch rule.** Let `row` be the feed row with `name === 'conv-flywheel'`. Let `toolUseId = row?.pendingAskUserQuestion?.toolUseId`. If `toolUseId` is a non-empty string and is not in `answeredToolUseIds` ⇒ action `reopen-question`. Otherwise ⇒ action `show-tick`. A non-array feed body counts as "no rows".
- **D4 — Only AskUserQuestion triggers the reopen.** `pendingProposedPlan`, `pendingPermission`, `pendingPaneChoice` and `heldKickoff` do not change the branch. (If a permission prompt and an AUQ are both pending, the existing reopen effect opens the permission dialog first; that is correct and unchanged.)
- **D5 — "Navigates to the Flywheel conversation" means the embedded pane on the same page.** The Flywheel page already shows `conv-flywheel` in its right column. `show-tick` switches that pane to its Conversation view (from Terminal, if selected) and jumps its timeline to the tick message. The page does not navigate away. The pop-out window is not driven.
- **D6 — Carry the tick message id in the contract.** Add optional `messageId` to `FlywheelLastTick`. Optional, so a transcript row with no id still decodes and existing `toEqual` tests that build messages without `id` keep passing. When `messageId` is absent, `show-tick` still switches the pane to Conversation view but requests no jump.
- **D7 — Keep `FlywheelStatusPane` pure.** Its tests render it without a `QueryClientProvider`. It gets one new optional prop, `onNeedsYouClick?: () => void`; the query, the branch rule and the jump state live in `FlywheelPage`.
- **D8 — The branch rule is a pure function** `resolveNeedsYouAction(rows, answeredToolUseIds)` in a new module, `src/dashboard/frontend/src/lib/flywheelNeedsYou.ts`, so both branches have a unit test without rendering.
- **D9 — Jump uses a monotonic nonce and is cleared after it lands.** `FlywheelPage` holds `tickJump: { messageId?: string; nonce: number } | null`; each click increments the nonce, so a second click scrolls again. When `ConversationPanel` reports the jump handled (`onTargetMessageHandled`), the page clears **only the id**: `setTickJump(prev => prev ? { nonce: prev.nonce, messageId: undefined } : prev)`. Reason: toggling the pane to Terminal and back remounts `ConversationPanel`; a still-set target would scroll to the old tick again uninvited (the same reason `App.tsx` line 534 and `AgentPane.tsx` line 40 clear `targetMessageId` on handled). The nonce is never reset to `null`/0: a reused nonce produces the same `${nonce}:${id}` key and `MessagesTimeline` would skip the jump.
- **D10 — Keep `data-testid="flywheel-needs-you"` on the banner.** The header indicator's reveal effect in `FlywheelPage` (`document.querySelector('[data-testid="flywheel-needs-you"]')`) scrolls to it.

## Requirements

- **FR-1** — `FlywheelLastTick` carries an optional `messageId: string`. `findLastTick()` sets it to the tick message's `id` when that message has one, and omits the key otherwise.
- **FR-2** — The NEEDS YOU banner in the Status tab renders as a `<button type="button">` with `data-testid="flywheel-needs-you"`, the same "Needs you" label and the `needsYou` text, and calls `onNeedsYouClick` on click.
- **FR-3** — `resolveNeedsYouAction(rows, answeredToolUseIds)` returns `{ kind: 'reopen-question', toolUseId }` when the `conv-flywheel` row has a pending, not optimistically answered `pendingAskUserQuestion.toolUseId`, and `{ kind: 'show-tick' }` otherwise.
- **FR-4** — With a pending question, a banner click on the Flywheel page calls `useAskUserQuestionUiStore.getState().requestReopen('conv-flywheel')` exactly once, and the app-level AUQ dialog shows that conversation's question.
- **FR-5** — With no pending question, a banner click sets the conversation pane to its Conversation view and passes `targetMessageId = status.lastTick.messageId` and a new `targetMessageNonce` to the embedded `ConversationPanel`.
- **FR-6** — `FlywheelConversationPane` accepts optional `tickTarget?: { messageId?: string; nonce: number } | null` and `onTickTargetHandled?: () => void`. When `tickTarget.nonce` changes, it sets `viewMode` to `'conversation'`. It forwards `tickTarget.messageId`, `tickTarget.nonce` and `onTickTargetHandled` to `ConversationPanel` as `targetMessageId` / `targetMessageNonce` / `onTargetMessageHandled`.
- **FR-8** — After the jump is handled, `FlywheelPage` clears the target id but keeps the nonce, so a pane remount does not re-scroll and the next click still gets a larger nonce.
- **FR-7** — `docs/FLYWHEEL.md` describes the banner's click behavior and the `messageId` field.
- **NFR-1** — No new network poll: the page reads the pending-input feed under the existing `['conv-ask-user-question']` key.
- **NFR-2** — No second dialog component and no new HTTP route.
- **NFR-3** — A missing `messageId`, a missing conversation, or a malformed feed body never throws; the click falls back as D6/D3 state.

### WI-4 — The branch rule (`resolveNeedsYouAction`)

Files: `src/dashboard/frontend/src/lib/flywheelNeedsYou.ts` (new), `src/dashboard/frontend/src/lib/__tests__/flywheelNeedsYou.test.ts` (new), `scripts/frontend-test-subset.txt`.

1. New module:
   ```ts
   /**
    * What a click on the Flywheel page's NEEDS YOU banner does (PAN-4751): reopen
    * the flywheel conversation's unanswered AskUserQuestion, or show the tick
    * message. Pure, so both branches are tested without rendering.
    */
   import type { ConversationPendingInputRow } from './useDecisions';
   import { FLYWHEEL_CONVERSATION_NAME } from './flywheelApi';

   export type NeedsYouAction = { kind: 'reopen-question'; toolUseId: string } | { kind: 'show-tick' };

   export function resolveNeedsYouAction(rows: unknown, answeredToolUseIds: ReadonlySet<string>): NeedsYouAction {
     const list = Array.isArray(rows) ? (rows as ConversationPendingInputRow[]) : [];
     const toolUseId = list.find((row) => row?.name === FLYWHEEL_CONVERSATION_NAME)?.pendingAskUserQuestion?.toolUseId;
     return typeof toolUseId === 'string' && toolUseId.length > 0 && !answeredToolUseIds.has(toolUseId)
       ? { kind: 'reopen-question', toolUseId }
       : { kind: 'show-tick' };
   }
   ```
   If importing `flywheelApi` from this module creates a circular import (`npm run lint` runs `lint:circular`), inline the constant `'conv-flywheel'` with a comment pointing at `FLYWHEEL_CONVERSATION_NAME`.
