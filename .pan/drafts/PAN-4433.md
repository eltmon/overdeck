# PAN-4433 — Detect and re-dispatch silent review agents

**Issue:** [PAN-4433](https://github.com/eltmon/overdeck/issues/4433)
**Status:** planned (auto mode, 2026-09-30)
**Base commit:** `76fba679f85` (feature/pan-4433)

## Glossary

- **Reviewer** — any review-role agent Overdeck dispatches for one issue: the
  **review parent** `agent-<issue>-review` (does the whole review in `quick`
  mode, writes the synthesis in `full` mode) and the four **convoy lanes**
  `agent-<issue>-review-<security|correctness|performance|requirements>`
  (`full` mode only).
- **Review mode** — `roles.review.mode` (`quick` default, `full`, `none`),
  resolved by `resolveReviewMode` in `src/lib/cloister/review-agent.ts`.
- **Run / runId** — one review of one head: `agent-<issue>-review-<head8>`,
  built by `deriveReviewRunHead8` (`src/lib/cloister/review-agent.ts`, ~line 84).
  Stored on every reviewer's `state.json` as `reviewRunId`.
- **Review report** — the file a reviewer writes for its run under
  `<workspace>/.pan/review/<runId>/`: `review.md` (quick parent,
  `selfReviewReportPath`), `synthesis.md` (full-mode parent,
  `reviewSynthesisPath`), `<subRole>.md` (a lane, `reviewerOutputPath` /
  `state.reviewOutputPath`).
- **Dispatch** — the moment Overdeck spawns or warm-resumes a reviewer with a
  run's prompt. Today five code sites do this (listed in WI-1).
- **Dispatch stamp** — new `AgentState.reviewDispatchedAt` (ISO string), taken
  immediately BEFORE the spawn/resume call of each dispatch.
- **Transcript activity** — the time of the reviewer's last transcript write,
  from `getRuntimeForAgent(agentId)?.getHeartbeat(agentId)?.timestamp`
  (`src/lib/runtimes/index.ts` ~line 169). For Claude Code this is the session
  JSONL's mtime (`getPassiveHeartbeat` in `src/lib/runtimes/claude-code.ts`
  ~line 228; `heartbeat-hook` no longer writes `~/.overdeck/heartbeats/*.json`).
  `null` when no transcript exists.
- **Silent reviewer** — a reviewer whose run is current, whose dispatch stamp
  is at least `stallMs` old, that has written no report for the run since the
  stamp, and whose transcript has not been written since the stamp.
- **stallMs** — `roles.review.stallMinutes` × 60 000; default 15 minutes.
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl`, append-only,
  `src/lib/cloister/pipeline-journal.ts`. Readers take the last entry plus the PR.
- **deacon-lite** — the 60 s patrol loop, `runDeaconLite()` in
  `src/lib/cloister/deacon-lite.ts`. It runs in the forked deacon child
  (`src/dashboard/server/deacon-main.ts`).
- **Needs-you** — for this issue: `surfaceIssueFeedbackNeedsYou(issueId, reason, details)`
  in `src/lib/cloister/feedback-target.ts` (~line 306), which emits an activity
  entry `{ source: 'cloister', level: 'warn', message: '<ISSUE> needs you: <reason>' }`.
  `verification-escalation.ts` and `conflict-repair.ts` use the same door.

## Problem

`agent-pan-4383-review` was dispatched 2026-09-29 14:37Z and never ran. No
transcript and no `review.md` were written, its pane sat idle for about 21 h,
and nothing noticed. PR #4387 had no approval, so the PAN-4384 conflict-repair
path skipped it.

The PAN-4383 journal tail (verified in
`workspaces/feature-pan-4383/.overdeck/pipeline.jsonl`) is:

```
{"at":"2026-09-29T14:37:35.173Z","type":"verification.passed","issueId":"PAN-4383","source":"request-review","data":{"head":"0e9e390c"}}
```

The review mode is `quick` (`~/.overdeck/config.yaml` `roles.review.mode: quick`).
Quick mode writes no `review.dispatched` entry. Both existing recovery routines
therefore skip it:

1. `recoverStalledReviews` (`deacon-lite.ts`, ~line 391) acts only on a
   `review.dispatched` / `review.redispatched` / `review.requested` tail
   (`stalledReviewReason`, ~line 257). A `verification.*` tail is skipped on purpose.
2. `recoverUndispatchedReviews` (`undispatched-review-recovery.ts`) acts on the
   `verification.passed` tail, but skips when the parent pane is live:

   ```ts
   const parentId = `agent-${issueId.toLowerCase()}-review`;
   const reviewerPrefix = `${parentId}-`;
   if (livePaneIds.some((agentId) => agentId === parentId || agentId.startsWith(reviewerPrefix))) continue;
   ```

The same hole exists for convoy lanes: `recoverStalledReviews` skips the issue
while any `agent-<issue>-review-*` pane is live, even an idle one that never
started.

This is a regression from the Cut. `deacon-review-signals.ts` (deleted in
`94255f055fe`, PAN-3917 W4) retried "warm-resume kickoffs that never start a
turn" and "elapsed reviewer deadlines" using `reviewDeadlineAt`. The Cut kept
the writers of `reviewDeadlineAt` (five sites) and deleted its only reader. It
is now write-only.

## Goals / acceptance (from the issue)

- A dispatched reviewer with no transcript activity and no review output within
  N minutes (configurable, default 15) is detected, recorded in the pipeline
  journal, and re-dispatched once.
- A second failure surfaces to the operator as needs-you with the reviewer name
  and pane state.
- Fake-timer tests cover: normal review, stuck-then-redispatched, stuck twice → needs-you.

## Requirements

- **FR-1** Every reviewer dispatch persists `reviewDispatchedAt` on the
  reviewer's `state.json`, captured before the spawn/resume call.
- **FR-2** `roles.review.stallMinutes` (positive integer, default 15) sets
  `stallMs`. Config load and the Settings API reject a non-positive or
  non-integer value.
- **FR-3** A pure detector decides "silent" from facts: report exists since the
  stamp → not silent; stamp younger than `stallMs` → not silent; any transcript
  activity at or after the stamp → not silent; otherwise silent.
- **FR-4** A new deacon-lite routine `recoverSilentReviewers` finds silent
  reviewers of the issue's current run whose pane is alive and not blocked,
  journals `review.stalled`, closes the silent pane, resets that reviewer's
  state dir, and re-dispatches once.
- **FR-5** When a re-dispatched reviewer of the same run is silent again, or is
  confirmed dead without a report, `stallMs` after its re-dispatch, the routine
  journals `review.stall-escalated` and surfaces needs-you naming the reviewer
  id, the run, and the pane state. It never re-dispatches that reviewer for that
  run again, and it leaves the pane alive.
- **FR-6** When the first re-dispatch cannot happen (pane close failed, spawn
  returned `success: false`, spawn threw), the routine escalates at once
  (FR-5 output) instead of waiting for a second detection.
- **FR-7** Two new journal types `review.stalled` and `review.stall-escalated`
  exist in `PipelineJournalEntryType` and render in `pan show`.
- **FR-8** The review parent's warm resume treats `messageDelivered === false`
  as a failed resume: it stops the parent and falls through to the fresh spawn,
  the same guard convoy lanes already have (`review-convoy.ts` ~line 205/230).
- **NFR-1** The routine never acts on an indeterminate liveness answer, a paused
  issue, an operator-held reviewer (`decideResumeGate`), an aborted review, or a
  stale run (runId ≠ current head's runId).
- **NFR-2** No GitHub or tracker call in the patrol path; journal and state
  files only, plus the liveness oracle.
- **NFR-3** Tests use fake timers (`vi.useFakeTimers` + `vi.setSystemTime` /
  `vi.advanceTimersByTime`) and inject `now`; no real delays.

## Decisions (made here, auto mode)

- **D1 — Anchor to dispatch, not to "idle for N minutes".** A convoy parent
  legitimately sits in STANDBY for a long time after reading its prompt. "No
  activity since the dispatch stamp" catches the never-started reviewer (the
  PAN-4383 shape) and never flags a reviewer that started. A reviewer that
  started and later hung is out of scope (NonGoal; `checkApiErrorAgents` owns
  the provider-error shape).
- **D2 — New state field, not a derived clock.** `reviewDispatchedAt` is added
  instead of computing `reviewDeadlineAt − PARENT_REVIEW_TIMEOUT_MS` /
  `REVIEWER_TIMEOUT_MS`, which would silently couple two constants in two
  modules. `reviewDeadlineAt`, `reviewRetryAttempt` and `reviewMonitorSignaled`
  stay untouched (dead fields; not reused — the attempt count lives in the journal).
- **D3 — Transcript activity only; not `isIdle`, not `idleAgeMs`.** The
  PAN-4383 reviewer was fresh-spawned at 14:38:40Z and its Claude session
  started: `~/.overdeck/agents/agent-pan-4383-review/sessions.json` records
  `session-start-hook` at 14:38:44Z with transcript path
  `…/5151c4b4-7d68-4aca-a2f9-91cec1e200bf.jsonl`, and `lifecycle.log` shows
  `transcript resolution: failed` for that path through 2026-09-30 — the prompt
  never reached the model, so no JSONL was ever written. The runtime mirror's
  `lastActivity` is bumped by many non-work events (`agent.created`
  projections, which that `lifecycle.log` shows repeating; session start), so
  `idleAgeMs` — which folds in the mirror — could read this reviewer as active.
  `isIdle` returns `false` when there is no runtime.json and no heartbeat
  (`liveness.ts` ~line 370). The issue asks for "no transcript activity", so the
  detector uses the transcript heartbeat alone:
  `getRuntimeForAgent(id)?.getHeartbeat(id)?.timestamp.getTime() ?? null`,
  reached by a dynamic `import('../runtimes/index.js')` inside the default dep
  (a static import from a cloister module risks `lint:circular`). A resumed
  session appends to its existing JSONL, so a delivered prompt moves the mtime
  past the stamp; an undelivered one leaves it before the stamp.
- **D4 — A report counts only if written since the stamp.** A report file for
  the same run from an earlier dispatch (same head re-reviewed) must not mask a
  silent re-dispatch: `reportExists = existsSync(path) && mtimeMs >= dispatchedAtMs`.
  The parent counts as reported when either `review.md` or `synthesis.md` qualifies.
- **D5 — Pane states.** From `isAlive(agentId)`:
  `alive` with `backendState === 'blocked'` → skip (already surfaced as
  needs-you by `derived-issue-state.ts` ~line 193; a re-dispatch would not
  answer a permission prompt). Runtime mirror `waiting-on-human` → skip, same
  reason. `alive` otherwise → candidate. Confirmed dead
  (`isConfirmedDead`) → candidate ONLY for the second-failure check (FR-5);
  a first-time dead reviewer stays with `recoverStalledReviews` /
  `recoverUndispatchedReviews`. Indeterminate → skip. The journaled `paneState`
  string is `backendState ?? 'alive'` for a live pane, the dead `reason`
  (`no-session` | `pane-dead` | `runtime-missing`) for a dead one.
- **D6 — Never write `review.redispatched` from this routine.** That tail makes
  `recoverStalledReviews` call `recoverMissingConvoyReviewers`, which would
  launch four lanes on a quick-mode issue. The routine writes only
  `review.stalled` and `review.stall-escalated`. Neither is in
  `stalledReviewReason`, so `recoverStalledReviews` ignores both tails.
- **D7 — The routine owns what the new tail hides.** Once `review.stalled` is a
  quick-mode issue's tail, `recoverUndispatchedReviews` no longer covers a
  re-dispatched parent that dies (its tail is not `verification.passed`). FR-5
  therefore counts "confirmed dead without a report" after a re-dispatch as the
  second failure.
- **D8 — Journal before acting.** `review.stalled` is appended BEFORE the pane
  close and the re-dispatch. It is the durable one-shot marker that survives a
  deacon restart (same pattern as `recoverUndispatchedReviews`, which sets its
  cooldown before the request). Any failure after that point escalates (FR-6),
  so a wiped state dir can never leave the issue silent.
- **D9 — Re-dispatch doors.** Lane: `closeAgentPaneDetailed(laneId)` →
  `stopAgent(laneId)` → `removeAgentStateDir(join(AGENTS_DIR, laneId))` →
  `recoverMissingConvoyReviewers(issueId, { source: 'silent-reviewer-recovery' })`
  (relaunches only lanes with no pane and no report; appends `review.dispatched`).
  Parent: `closeAgentPaneDetailed(parentId)` → `stopAgent(parentId)` →
  `removeAgentStateDir(join(AGENTS_DIR, parentId))` →
  `Effect.runPromise(spawnReviewRoleForIssue({ issueId, workspace, branch: \`feature/${issueId.toLowerCase()}\`, force: true, operatorRequested: saved.reviewOperatorRequested === true }))`.
  Removing the state dir makes the door fresh-spawn: the saved session is the
  prime suspect. `reviewResumeDecision` (`review-resume-decision.ts`) resumes
  only when `hasSavedState && hasSavedSession`; `removeAgentStateDir` deletes
  `state.json` (and every non-`*.jsonl` file), so `hasSavedState` is false and
  both doors fresh-spawn. The routine calls these doors directly instead of
  `requestReviewThroughRoute` because the route re-verifies the head
  (verification took 75 minutes on PAN-4383), and the head is unchanged — the
  run id proves it — so the existing `verification.passed` still covers it. A
  `gated: true` result (merge conflict) escalates like any failed re-dispatch
  (FR-6): "conflict + no approval" is the PAN-4383 / PAN-4384 deadlock, and the
  operator must see it. `removeAgentStateDir` preserves every `*.jsonl` transcript
  (`state-dir-removal.ts` ~line 275). `force: true` also restarts live lanes in
  `full` mode; that cost is accepted for a rare recovery path.
- **D10 — Escalation door.** `surfaceIssueFeedbackNeedsYou` (activity warn
  entry). The PAN-4383 PR (#4387) adds journal-derived operator decisions to
  Needs-you; it is not on main at `76fba679f85`. If it lands before this work,
  the work agent checks whether `review.stall-escalated` should also ride that
  surface and notes the answer in the PR body; the activity emission stays either way.
- **D11 — Attempt key is (runId, reviewer id).** A new push is a new run and
  gets a fresh budget. Attempts are counted from the journal, never from
  in-memory state or `state.json`.
- **D12 — Config key location.** `roles.review.stallMinutes`, next to
  `roles.review.mode`. `camelCase` matches the other role keys (`minAgents`).
  Only the review role reads it. The dashboard Settings round-trip preserves
  unknown role keys (`normalizeRoleConfig` spreads the input,
  `settings-api.ts` ~line 419; `mergeRoles` ~line 392; `seededRoles` ~line 311),
  so no Settings UI work is needed. The Settings API only gains validation.
- **D13 — FR-8 is in scope.** `review-agent.ts` ~line 545 checks only
  `resumeResult.success` for the parent's warm resume, while convoy lanes also
  check `messageDelivered === false` and stop the agent. A resumed parent whose
  kickoff prompt never landed is a plausible mechanism for a live, idle,
  transcript-less parent. The guard is small and removes a cause, not only the symptom.

### WI-5 — Pure silent-reviewer detector (FR-3, D1, D4, D11)

New file: `src/lib/cloister/silent-reviewer-detect.ts`. No I/O, no imports
beyond types and `node:path`.

```ts
export interface SilentReviewerFacts {
  agentId: string;
  runId: string;
  dispatchedAtMs: number;
  /** Last transcript write in ms; null = no transcript (never started). */
  lastTranscriptActivityMs: number | null;
  /** A report for this run with mtime >= dispatchedAtMs exists. */
  reportSinceDispatch: boolean;
}

export type SilentVerdict =
  | { silent: false; reason: 'reported' | 'too-young' | 'active' }
  | { silent: true; silentForMs: number };

export function classifyReviewer(facts: SilentReviewerFacts, stallMs: number, now: number): SilentVerdict;

/** Journal entries for (runId, reviewer): count of review.stalled, last review.stalled `at` ms, whether escalated. */
export function stallHistory(
  entries: readonly PipelineJournalEntry[],
  runId: string,
  reviewer: string,
): { stalledCount: number; lastStalledAtMs: number | null; escalated: boolean };

/** Report paths that count for a reviewer: lane → state.reviewOutputPath ?? <reviewDir>/<subRole>.md; parent → review.md and synthesis.md. */
export function reviewerReportPaths(opts: { workspace: string; runId: string; subRole?: string; reviewOutputPath?: string }): string[];
```

Rules for `classifyReviewer`, evaluated in this order:
1. `reportSinceDispatch` → `{ silent: false, reason: 'reported' }`.
2. `now - dispatchedAtMs < stallMs` → `too-young`.
3. `lastTranscriptActivityMs !== null && lastTranscriptActivityMs >= dispatchedAtMs` → `active`.
4. Otherwise `{ silent: true, silentForMs: now - dispatchedAtMs }`.

`stallHistory` counts entries whose `type` is `review.stalled` and whose
`data.runId === runId && data.reviewer === reviewer`; `escalated` is true when
any `review.stall-escalated` entry matches the same pair.

Tests: `src/lib/cloister/__tests__/silent-reviewer-detect.test.ts` —
each rule, including a warm-resumed reviewer whose last activity predates the
stamp (silent) and one active one second after the stamp (not silent); a
report older than the stamp does not count (the caller computes
`reportSinceDispatch`, so this is covered in WI-6's test); `stallHistory`
ignores entries for another run or another reviewer.

Per review state `s` with `s.issueId`, `s.workspace`, `s.reviewRunId`,
`s.reviewDispatchedAt` all present and `existsSync(s.workspace)` (others are
skipped — reviewers dispatched before this change have no stamp):

1. `issueId = s.issueId.toUpperCase()`. Skip when an in-memory in-flight set
   holds `issueId` (one action per issue per tick; cleared in `finally`).
2. Skip unless `await currentRunId(issueId, s.workspace) === s.reviewRunId` (NFR-1 stale run).
3. Skip unless `getIssuePause(issueId).status === 'unpaused'` and
   `resumeGateAllows(s)`.
4. Read the journal once (`readPipelineJournal(s.workspace)`). Skip when a
   `review.verdict` entry has `data.runId === s.reviewRunId`, or has no runId
   and `at >= reviewDispatchedAt`; skip when a `review.aborted` entry has
   `at >= reviewDispatchedAt`.
5. `history = stallHistory(entries, s.reviewRunId, s.id)`. Skip when
   `history.escalated`. When `history.stalledCount >= 1`, skip unless
   `dispatchedAtMs > history.lastStalledAtMs` (the verdict below must be about
   the re-dispatched reviewer).
6. Facts: `reportSinceDispatch` = any path from `reviewerReportPaths` with
   `reportMtimeMs(path) >= dispatchedAtMs`; `lastTranscriptActivityMs` =
   `await transcriptActivityMs(s.id)`. `verdict =
   classifyReviewer(facts, stallMs(), now)`. Skip unless `verdict.silent`.
7. Pane: `v = await isAlive(s.id)`. Indeterminate (`!v.alive && !isConfirmedDead(v)`) → skip.
   Alive with `backendState === 'blocked'` or `runtimeWaitingOnHuman(s.id)` → skip.
   Confirmed dead with `history.stalledCount === 0` → skip (existing routines own it).
   `paneState = v.alive ? (v.backendState ?? 'alive') : v.reason`.
8. Act inside `withReviewLifecycleGuard(issueId, …)`; re-read the state
   (`getAgentState` from `../agents/agent-state-read.js`) and the journal and
   re-check steps 4–5; bail if either changed.
   - **Second failure** (`history.stalledCount >= 1`): append
     `{ type: 'review.stall-escalated', issueId, source: 'deacon-lite', data: { runId, reviewer: s.id, paneState, attempt: 2, reason: 'silent again after re-dispatch' | 'died without a report after re-dispatch' } }`,
     then `surfaceNeedsYou(issueId, \`review agent ${s.id} produced no output for run ${runId} after a re-dispatch (pane ${paneState})\`, { reviewer: s.id, runId, paneState, attempts: 2 })`.
     Do not touch the pane. Push an action string.
   - **First failure**: append
     `{ type: 'review.stalled', issueId, source: 'deacon-lite', data: { runId, reviewer: s.id, paneState, dispatchedAt: s.reviewDispatchedAt, silentForMs: verdict.silentForMs, attempt: 1 } }`
     FIRST (D8). Then `s.reviewSubRole ? redispatchLane(issueId, s.id) : redispatchParent(issueId, s.workspace, s)`.
     On `success: false` or a throw: append `review.stall-escalated` with
     `reason: \`re-dispatch failed: ${message}\`` and surface needs-you (FR-6).
     On success push `recoverSilentReviewers: re-dispatched silent ${s.id} for ${issueId} — ${message}`.
   - Emit `emitActivityEntry({ source: 'review', level: 'warn', message, issueId })`
     for the first-failure detection too, so the activity feed shows it.

  `recoverStalledReviews` (convoy) and `recoverUndispatchedReviews` (quick).

  deleting them.
