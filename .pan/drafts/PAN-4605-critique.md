## blocks-the-design: Retry route can bypass adoption

The PRD promises that `POST /api/review/:issueId/request` adopts an open pipeline-branch PR when the workspace is missing ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/.pan/drafts/PAN-4605.md), lines 111–115 and 156–158), but WI-7 only replaces the `no-workspace` switch arm. The route calls `requestReviewGuarded` first ([review-pipeline.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/dashboard/server/routes/workspaces/review-pipeline.ts), lines 887–924). That guard returns `tests-requeued` or `already-passed` for an approved PR, and `circuit-breaker` before it checks workspace existence (lines 640–705); it only reaches `startRequestReviewPipeline` at line 713. Thus `pan review request` can report success or a breaker without creating the missing workspace or starting verification. Move the missing-workspace adoption decision ahead of those shortcuts, while retaining the merged-issue guard, and test the approved-PR and breaker cases.

## blocks-the-design: PR lookup can falsely report no PR

WI-5 makes `findOpenPipelinePr` use `listRepoPullRequests` and turns no match into a 400 saying no open PR ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/.pan/drafts/PAN-4605.md), lines 470–477). That listing is cached for five minutes when it previously had no open PR ([pr-cache-policy.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/lib/overdeck/pr-cache-policy.ts), lines 50–63), converts a failed forge read into `[]`, and requests only the latest 100 PRs across *all* states ([derived-issue-state.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/lib/overdeck/derived-issue-state.ts), lines 342–368). The webhook only bumps the separate PR-tab cache ([webhook-handlers.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/lib/webhook-handlers.ts), line 296; [pr-tab-cache.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/dashboard/server/services/pr-tab-cache.ts), lines 28–35). A newly opened PR can therefore be absent from both the retry lookup and the derived Needs you state; a forge failure is incorrectly described as no PR. On a cached miss, use a fresh, branch-targeted open-PR lookup that distinguishes read failure from absence, and invalidate or refresh the derived listing on PR webhooks. Cover a cached empty listing and a failed forge read.

## blocks-the-design: Review start failure clears the alert

The planned derived rule reports `pr-outside-pipeline` only when there is no workspace or the workspace journal's *last* entry is `workspace.adoption-failed` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/.pan/drafts/PAN-4605.md), lines 295–303). WI-5 explicitly permits `createWorkspace` to succeed and then the review starter to be absent or return `started:false`, including `dirty-workspace`; those paths only announce an activity entry (lines 462–467). The journal then ends at `workspace.adopted` (lines 382–383), so the new Needs you item and `pan show` fix disappear although verification and review never started. Activity announcements do not set derived attention ([feedback-target.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/lib/cloister/feedback-target.ts), lines 299–323). Journal a review-start refusal with its fix and include it in the derived rule until `review.requested` or another successful start supersedes it; test `dirty-workspace` and no-starter after successful adoption.

## blocks-the-design: A registry row can hide a missing workspace

WI-3 defines `pipelineWorkspacePath` as accepting a registry row path, while requiring `.git` only for the conventional path ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/.pan/drafts/PAN-4605.md), lines 271–275). `getWorkspaceForIssue` returns a row without checking its path ([resolver.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/lib/workspaces/resolver.ts), lines 114–123). `createWorkspace` writes that row before creating the worktree ([create.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/lib/workspace-manager/create.ts), lines 209–257); compensation is conditional and may itself fail (lines 760–767). If that row survives without a worktree, WI-3 reads an empty journal and returns no alert, while the review route still sees no workspace ([workspaces.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/src/dashboard/server/routes/workspaces.ts), lines 394–406). Require the registry path to exist and contain `.git` before treating it as a usable workspace, and test a stale row with no directory.

## blocks-the-design: Diverged-branch fix can destroy commits

D4 says a diverged local branch may hold unpushed work ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4605/.pan/drafts/PAN-4605.md), lines 95–98), yet WI-4's exact operator-facing fix tells the user to run `git branch -D` on it (line 394). `-D` force-deletes precisely the ref that protects those commits, and adoption has already confirmed the branch is not checked out elsewhere, so Git will allow the deletion. Remove that command from the generated fix. Tell the operator to preserve or inspect the local commits first, then reconcile the branch and retry; add a test that the refusal text contains no force-delete instruction.
