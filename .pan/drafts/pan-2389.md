## Glossary

- **Cost event** — one JSONL row in `~/.overdeck/costs/events.jsonl` (and mirrored into the `cost_events` SQLite cache) recording tokens + USD for one API call or session. Schema: `CostEvent` in `src/lib/costs/events.ts:17`.
- **CostWriter door** — the single write door for cost state: `CostWriter` in `src/lib/overdeck/cost.ts:449`. Its `record()` is "the ONLY ingest primitive — owns archive fan-out and dedup". Dedup (`checkDuplicate`, `src/lib/overdeck/cost.ts:478`): exact `requestId` when present, `sourceFile` fallback for events without one (codex dumps). Per the single-source-of-truth tenet, the backfill MUST write through this door only.
- **Session store** — an on-disk directory of harness conversation transcripts (JSONL). Distinct per harness (see Coverage table below).
- **Reconciler** — `src/lib/costs/reconciler.ts`. `reconcilePromise()` (line 561) is a full sweep of `~/.claude/projects/` (top-level + `subagents/`), inferring issueId from the transcript directory path, tracking per-session byte offsets in `~/.overdeck/costs/state/`, writing through the door. Exported as `reconcile()` (line 717) — **it currently has ZERO callers**. Only `reconcilePiTranscripts()` is scheduled (`src/dashboard/server/services/cost-reconcile-service.ts:1`).
- **Door reconcile** — `CostWriter.reconcile({source: 'ohmypi' | 'codex'})` in `src/lib/overdeck/cost.ts` (~line 536): walks `$OVERDECK_HOME/agents/<id>/sessions/**/*.jsonl` (pi) or `<id>/codex-home/sessions/**/*.jsonl` (codex) and feeds `record()`.
- **Backfill** — a one-command historical sweep of ALL known session stores that imports every derivable cost event not already in the store. Idempotent (door dedup), resumable (offsets + dedup), read-only on session files.
- **Coverage boundary** — the earliest date the reconstruction reaches, per harness. Must be reported honestly in the regenerated report.
- **Rebrand** — the Panopticon→Overdeck cutover (~2026-06-19) that moved state from `~/.panopticon/` to a fresh `~/.overdeck/`. Legacy cost data was deliberately not imported.

## Problem

The public token spend report (`docs/token-spend-report/index.html`, target URL https://eltmon.github.io/overdeck/token-spend-report/) is stale and unpublished:

1. **Data gap.** The current store `~/.overdeck/costs/events.jsonl` starts exactly at the rebrand — min ts `2026-06-19T18:30:25Z` (verified 2026-07-05, 37,080 events). Everything before that is absent because legacy cost events were deliberately not imported.
2. **Publish 404.** `gh api repos/eltmon/overdeck/pages` returns 404 — no GitHub Pages site is configured on the repo at all, and `.github/workflows/` has no Pages workflow. The Pages configuration did not survive the rebrand.
3. **Stale content.** The checked-in `index.html` still carries the pre-rebrand era data (734,117 calls / ~$54k hero stats) with old branding assumptions and a two-source (SQLite + JSONL) generation procedure that no longer applies.

The operator's architectural bet (this issue proves or falsifies it): everything we care about, as far back as we care about, is derivable from the session transcripts still on disk — no legacy DB import needed.

## Proposal

Ship a durable `pan cost backfill` CLI command that runs a full historical sweep across all five session stores through the existing reconciler + CostWriter door, run it on this machine, regenerate the static report from the merged store (single source — no SQLite combine), fix the Pages 404 with a workflow-based deploy, and label the coverage boundary honestly.

Precedent: `scripts/backfill-costs-pan1570.mts` (a one-off dry-run-default backfill for a prior gap) — this issue makes the capability durable instead of another throwaway script.

## Design decisions (made here, not left to the work agent)

- **D1 — Durable CLI, not a script.** `pan cost backfill` under the existing `cost` command group. Cache-derivability is a maintained property; the capability must survive this issue.
- **D2 — Dry-run default.** The command writes thousands of events; default prints the plan, `--write` executes. Dry-run must bypass BOTH `record()` AND `saveSessionOffset()`/seen-set persistence — persisting offsets in a dry run would make the subsequent `--write` run skip those bytes. Thread a `dryRun` flag through `reconcilePromise()`; count would-be imports via `checkDuplicate`-equivalent logic or simply count extracted events minus known duplicates.
- **D3 — Roots parameterization lives in the door.** Extend `CostWriter.reconcile` opts to `{source, extraRoots?: string[]}` (or equivalent) in `src/lib/overdeck/cost.ts`, so global codex, global pi, and legacy pi roots reuse the existing walk+parse+record loop. Do NOT rewrite `codex-parser.ts`/`ohmypi-parser.ts` internals — PAN-2388 owns parser accuracy and is in flight; keep this issue's parser diff to the minimum needed to surface the session `cwd` for attribution (if not already available).
- **D4 — Codex granularity stays per-session.** The door already emits one event per codex session file with `sourceFile` dedup and `ts` = session start. Keep that shape; PAN-2388 refines accuracy later. Re-runs stay idempotent either way.
- **D5 — Do not block on PAN-2387/PAN-2388.** The issue frames it as "should land first OR the backfill inherits the UNKNOWN bucket". Proceeding with current parsers is the smallest acceptable option; the report's coverage note discloses attribution limits. Because the store is append-only with dedup, re-running the backfill after those issues land cannot double-count — but it also will NOT retro-correct attribution of already-written events; that is disclosed too.
- **D6 — Report data extraction is scripted, not hand-typed.** The regeneration bead computes aggregates with a small `node -e` / script pass over `events.jsonl` (sorting by `ts` — backfill appends out of chronological order) and pastes them into `reportData`. Totals in the HTML must equal the script output exactly.
- **D7 — Pages via workflow, publishing only the report dir.** The repo root is a Mintlify docs source (published at overdeck.ai); GitHub Pages must NOT serve the whole `docs/` tree — stage `docs/token-spend-report/` into `_site/token-spend-report/` and upload `_site`.
