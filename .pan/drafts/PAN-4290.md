# PAN-4290 — Ended agent sessions show their outcome instead of a bare "Session ended"

**Issue:** [PAN-4290](https://github.com/eltmon/overdeck/issues/4290)
**Status:** planned (auto planning, 2026-09-28)
**Code verified against:** `feature/pan-4290` @ `0b5162d78f9`

## Glossary

- **Ended session** — an agent session whose terminal is gone. On a `SessionNode` this is `presence === 'ended'`; on a `SessionAgent` (the drawer's agent shape) this is `isEndedAgent(agent)` (`status` in `stopped | dead | failed`, `src/dashboard/frontend/src/lib/agentConversation.ts`, `ENDED_AGENT_STATUSES`).
- **Outcome** — a short label that says how an ended session finished: `Merged`, `Review approved`, `Changes requested`, `Tests passed`, `Tests failed`, `Plan finalized`, `Stopped by operator`, `Stopped by close-out`, `Ended unexpectedly`. It is computed at render time from facts the dashboard store already holds. It is never written anywhere.
- **Fallback** — the plain text `Session ended`, used only when the facts needed to pick an outcome are absent.
- **Tone** — `quiet` (rendered with `--muted-foreground`, the style guide's rest state) or `attention` (rendered with the existing error/`--destructive` treatment). Only `Ended unexpectedly` has `attention` tone.
- **Derived issue state** — `DerivedIssueState` (`packages/contracts/src/derived-issue-state.ts`), recomputed from tracker + forge + terminal backend and pushed to the store (`derivedIssueStateByIssueId`, read with `useDerivedIssueState(issueId)` in `src/dashboard/frontend/src/lib/store.ts`). It is `emitOnly`: never persisted.
- **Agent snapshot** — `AgentSnapshot` in the store (`agentsById`), which carries `status`, `role`, and `stoppedByUser` (`packages/contracts/src/types.ts` line 334, `stoppedByUser: Schema.optional(Schema.Boolean)`).
- **Primary agent** — the issue's own plan, work, or strike agent: the agents whose job has an observable finish (plan finalized, PR merged). Specialists (review coordinator, reviewers, test), workers, knowledge, ship, lint, and legacy nodes are not primary.
- **Synthesized specialist row** — the Review and Test `SessionNode`s built by `buildSpecialistSessionNodes` (`src/dashboard/server/routes/session-tree-specialists.ts`). They exist because a PR exists, even if no review or test agent ever ran, and their `status` is derived from the PR, not from an agent.

## Problem

Every agent whose terminal is gone shows "Session ended", whether it finished its job or died. Most ended sessions finished normally: reviewers exit after their verdict, close-out stops an issue's agents, and a work agent ends after its PR merges. The operator cannot tell a normal finish from a crash at a glance, so every "Session ended" row looks like something to investigate.

A second defect sits under the first. `normalizeAgentStatus` (`src/dashboard/server/services/agent-status.ts`) maps a review row's `blocked` (changes requested) and a test row's `failed` to `error`. So an ended Review row whose PR has "changes requested" renders today in the cockpit with the red `bad` status class (`AgentStepRow.tsx`, `statusClassForCockpit`), as if the reviewer crashed. The outcome derivation below must read the PR facts directly and let tone, not the lossy `status`, pick the color for ended rows.

**Why `Merged` needs WI-1.** `deriveState` returns `closed` before `merged`, and the two fact-assembly sites build `pr` without the merged flag (`src/lib/overdeck/derived-issue-state.ts` line 731 and line 857: `pr: { url: pr.url, number: pr.number, reviewState: pr.reviewState, checks: pr.checks, mergeable: pr.mergeable }`). After close-out the wire says `state: 'closed'` and the merge is gone — exactly when the operator looks at a finished issue. WI-1 adds an optional `merged` field to `DerivedPrState`. It is a derived, `emitOnly` wire field, like the rest of `DerivedIssueState`; it is not a persisted status (NFR-1).

## Requirements

### Functional

- **FR-1** — Given an ended session, every surface in the table above renders the derived outcome label in place of "Session ended". The plain text "Session ended" appears only when the outcome is the fallback.
- **FR-2** — The outcome is chosen by the precedence table in WI-2 (first matching row wins). PR-derived outcomes (`Merged`, review verdict, test result) rank above every stop-cause outcome, so where sources disagree, the PR wins.
- **FR-3** — `Merged` is derivable after the issue is closed: `DerivedIssueState.pr.merged === true` survives `state: 'closed'`.
- **FR-4** — Only `Ended unexpectedly` renders with attention tone. Every other outcome, and the fallback, renders with `--muted-foreground`. For ended rows, tone overrides the color the lossy `status` would otherwise pick (an ended Review row with changes requested is no longer red).
- **FR-5** — `Ended unexpectedly` is claimed only on positive evidence (WI-2 rows 8–10). A synthesized specialist row with no verdict and no failure evidence gets the fallback, never `Ended unexpectedly`.
- **FR-6** — AgentStepRow shows the outcome label as visible text in both densities (cockpit and rail) and as the first sentence of the status tooltip.

### Non-functional

- **NFR-1** — No new persisted status. The outcome is computed in the browser at render time. The only contract change is the optional derived `DerivedPrState.merged`, which is `emitOnly` like the rest of `DerivedIssueState`.
- **NFR-2** — One derivation. All surfaces call the same pure function in `src/dashboard/frontend/src/lib/sessionOutcome.ts`; no surface hard-codes an outcome string.
- **NFR-3** — No new endpoint, polling loop, query, or store slice. Facts come from `useDerivedIssueState` and `agentsById`, which the dashboard already maintains.
- **NFR-4** — Unit tests cover every precedence row, the fallback, the merged-after-close case, and the synthesized-specialist no-false-alarm case.

## Decisions (made here; implementers do not re-decide)

- **D1 — Derive in the frontend, not in the server node builders.** The store already holds every fact (derived issue state, agent snapshots), and the drawer works from `SessionAgent`, not `SessionNode`. A server-side field would have to be added to two node builders (`routes/projects.ts` `collectSessionTreeNodes` and `routes/command-deck.ts`) plus the specialist and reviewer builders, and the drawer would still need a frontend path. One pure function with two fact adapters covers all surfaces.
- **D2 — The pipeline journal is not read.** Its review verdicts are also on the PR (marker comments are read back into `reviewState`), its merge fact is covered by WI-1, and the journal dies with the workspace at close-out. The PR wins on disagreement anyway, so reading the journal would add a server read path for no new outcome.
- **D3 — Test outcome reads `pr.checks`.** `green` → `Tests passed`, `red` → `Tests failed`, `pending` → no test outcome. This is the fact the Test row's own status already comes from. The test agent's own `uat.verdict` journal entry is not consulted (NonGoal).
- **D4 — Reviewer verdict source.** For a `reviewer` node: `roundMetadata.latestReviewResult` first (the reviewer's own verdict), then `pr.reviewState`. For the `review` coordinator node and for drawer review agents: `pr.reviewState` first, then `roundMetadata.latestReviewResult` when present.
- **D5 — Where "unexpected" starts.** "Ended unexpectedly" needs positive evidence: a recorded `error` status on agent-backed facts, an agent-backed session that ended while its recorded status is still `running`/`starting` (the pane vanished and nobody recorded a stop), or a primary agent (plan/work/strike) that ended cleanly with no outcome while the issue is known to be neither closed nor merged. A synthesized specialist row, a worker, a knowledge/ship/lint/legacy row, or any session whose issue state is unknown gets the fallback. Rationale: the operator's complaint is false alarms; synthesized specialist rows can exist without the agent ever running, and `SessionNode.status` for them is PR-derived (`normalizeAgentStatus` maps `blocked`/`failed` to `error`), so it is not failure evidence.
- **D6 — Plan finalized in the drawer.** The drawer has no `planningComplete`. The drawer adapter treats planning as finalized when `derived.state` is one of `planned`, `working`, `in-review`, `changes-requested`, `ready`, `merged` (each implies the spec exists or work went past planning). `closed` is excluded so a closed issue falls through to `Stopped by close-out`.
- **D7 — Unmounted surfaces are kept and routed through the helper.** `ConversationTerminal` and `TerminalSessionWrapper` are not mounted in production, but the issue lists them. They are not deleted (surgical-change rule). Conversations have no pipeline facts, so both render the fallback through the shared helper, in quiet tone. `TerminalSessionWrapper` gains an optional `outcome` prop; its orange `accentOrange` treatment is used only when the outcome tone is `attention`.
- **D8 — AgentStepRow color.** For an ended row, the outcome replaces `displayStatus` as visible text. `attention` tone reuses the existing error path (`statusClassForCockpit` → `'bad'`, `cockpitDotStatus` → `'error'`, rail class `sessionStatus_error`). `quiet` tone uses `'muted'` / `'done'` and a muted rail status span. No new color token and no second colored signal on the row.

Exports (names are fixed; later items import them):

```ts
export type SessionOutcomeKind =
  | 'merged' | 'review-approved' | 'changes-requested' | 'tests-passed' | 'tests-failed'
  | 'plan-finalized' | 'stopped-by-operator' | 'stopped-by-close-out' | 'ended-unexpectedly' | 'ended';

export type SessionOutcomeTone = 'quiet' | 'attention';

export interface SessionOutcome {
  kind: SessionOutcomeKind;
  label: string;   // visible text, e.g. 'Merged'
  detail: string;  // one tooltip sentence, e.g. "The work agent's PR merged."
  tone: SessionOutcomeTone;
}

export type SessionOutcomeRole =
  | 'plan' | 'work' | 'strike' | 'review' | 'reviewer' | 'test' | 'worker' | 'other';

export interface SessionOutcomeFacts {
  role: SessionOutcomeRole;
  /** True when the row exists because of PR facts, not an agent (Review/Test specialist rows). */
  synthesized: boolean;
  planningComplete?: boolean;
  reviewerVerdict?: 'APPROVED' | 'CHANGES_REQUESTED';   // per-session verdict (round artifact)
  prReviewState?: PrReviewState;
  prChecks?: PrChecksState;
  prMerged?: boolean;
  issueState?: IssueState;          // undefined = derived state not loaded / unknown
  stoppedByUser?: boolean;
  /** A pause is recorded on the agent (operator or machine: memory shed, scheduler yield). */
  paused?: boolean;
  /** Recorded agent status, only from agent-backed facts (AgentSnapshot, or an agent-backed SessionNode). */
  recordedStatus?: string;
}

export const SESSION_ENDED_FALLBACK: SessionOutcome; // kind 'ended', label 'Session ended', tone 'quiet'
export function deriveSessionOutcome(facts: SessionOutcomeFacts): SessionOutcome;
export function outcomeFactsFromSessionNode(node: SessionNode, derived: DerivedIssueState | undefined, agent: AgentSnapshot | undefined): SessionOutcomeFacts;
export function outcomeFactsFromAgent(agent: SessionAgent & { stoppedByUser?: boolean }, derived: DerivedIssueState | undefined): SessionOutcomeFacts;
```

`deriveSessionOutcome` is called only for ended sessions. **Precedence (first match wins):**

| # | Condition | kind | label | detail | tone |
|---|---|---|---|---|---|
| 1 | role ∈ {work, strike} and `prMerged` (or `issueState === 'merged'`) | merged | Merged | The work agent's PR merged. | quiet |
| 2 | role ∈ {review, reviewer} and verdict (D4) = approved | review-approved | Review approved | The reviewer exited after approving. | quiet |
| 3 | role ∈ {review, reviewer} and verdict (D4) = changes requested | changes-requested | Changes requested | The reviewer exited after requesting changes. | quiet |
| 4 | role = test and `prChecks === 'green'` | tests-passed | Tests passed | The test run finished green. | quiet |
| 5 | role = test and `prChecks === 'red'` | tests-failed | Tests failed | The test run finished red. | quiet |
| 6 | role = plan and `planningComplete === true` | plan-finalized | Plan finalized | The planning agent finalized the plan. | quiet |
| 7 | `stoppedByUser === true` | stopped-by-operator | Stopped by operator | An operator stopped this session. | quiet |
| 8 | `issueState === 'closed'` | stopped-by-close-out | Stopped by close-out | Close-out stopped this session after the issue closed. | quiet |
| 9 | `recordedStatus` ∈ {error, failed, dead} | ended-unexpectedly | Ended unexpectedly | The session recorded an error before it ended. | attention |
| 10 | `recordedStatus` ∈ {running, starting} (pane gone, no stop recorded) | ended-unexpectedly | Ended unexpectedly | The session ended without recording a stop. | attention |
| 11 | role ∈ {plan, work, strike}, not synthesized, `paused !== true`, and `issueState` is defined and not `merged` | ended-unexpectedly | Ended unexpectedly | The agent ended before its job finished. | attention |
| 12 | otherwise | ended | Session ended | This session ended; no outcome could be derived. | quiet |

Adapter rules:

- `outcomeFactsFromSessionNode`: when `agent?.role === 'worker'`, role is `worker` (worker sessions are pushed as `type: 'work'` nodes with no `role` by `collectSessionTreeNodes`, `routes/projects.ts`, so `node.type` alone would mislabel a finished worker). Otherwise role from `node.type` — `planning`/`legacy` → `plan`; `work` → `work`; `strike` → `strike`; `review` → `review`; `reviewer` → `reviewer`; `test` → `test`; everything else (`knowledge`, `lint`, `ship`, `merge`) → `other`. `synthesized = node.type === 'review' || node.type === 'test'`. `recordedStatus` = `agent?.status` when an agent snapshot exists; otherwise `node.status` only when not synthesized and `node.type` ∉ {`reviewer`, `lint`, `legacy`}; otherwise undefined. `reviewerVerdict` from `node.roundMetadata?.latestReviewResult` when it is `APPROVED` or `CHANGES_REQUESTED`. PR facts from `derived?.pr`; `issueState` from `derived?.state`; `stoppedByUser` from `agent?.stoppedByUser`; `paused` from `agent?.paused`. The legacy node (`status: 'stopped'`, synthetic) must reach row 12, not row 11 — map `legacy` to `plan` but set `synthesized: true`.
- `outcomeFactsFromAgent`: role from `agent.role` — `plan` → `plan`; `work` → `work`; `strike` → `strike`; `test` → `test`; `worker` → `worker`; `review` → `reviewer` when `agent.id` matches `/-review-[a-z]+$/i`, else `review`; anything else → `other`. `synthesized = false`. `recordedStatus = agent.status`. `paused = agent.paused`. `planningComplete` per D6. For the drawer, a clean `stopped` status is not in rows 9–10, so only row 11 can make a stopped primary agent unexpected.

Tests (`sessionOutcome.test.ts`, pure, no store): one `it` per precedence row 1–12; "merged after close" (`issueState: 'closed'`, `prMerged: true`, role work → Merged); "PR wins over operator stop" (role reviewer, verdict approved, `stoppedByUser: true` → Review approved); "synthesized review row with no verdict and PR-derived `error` status → Session ended"; "changes-requested review row is quiet"; "unknown issue state for a stopped work agent → Session ended"; each adapter's role mapping including the legacy node and the `-review-<role>` id; "work-typed node whose snapshot role is `worker`, open issue, clean stop → Session ended"; "paused work agent (machine pause, no `stoppedByUser`), open issue → Session ended" (the pause is already surfaced by `PausedBanner`).
