# PAN-4805 — Isolated-dashboard e2e fixture: OS-assigned free port and one retry on EADDRINUSE

**Issue:** https://github.com/eltmon/overdeck/issues/4805
**Planned:** 2026-11-02 (auto mode), against `feature/pan-4805` at `04c2f78e462`.

## Glossary

- **Isolated dashboard fixture** — `src/dashboard/frontend/tests/fixtures/isolated-dashboard.ts`. A Playwright helper that boots a private `node dist/dashboard/server.js` on its own port with a throwaway `OVERDECK_HOME`, so a spec never writes to the operator's live dashboard. Eighteen specs under `src/dashboard/frontend/tests/` import it.
- **`pickPort`** — the fixture function that chooses the port the child server binds. Today it is a random number in 39000–39899.
- **OS-assigned port** — the port the kernel hands out when a socket listens on port `0`. The kernel only returns a port no other socket holds at that moment.
- **EADDRINUSE** — the Node error code for "address already in use": the child server could not bind its port because another socket holds it.
- **Explicit port** — a caller passes `opts.port` to `startIsolatedDashboard`. Today only `pan-4279-degraded-mode.spec.ts:50` does this, to restart a stopped server on the same port that an open browser page still points at.
- **Host dashboard port** — `3011`, the default `dashboard.api_port` of the operator's live dashboard.
- **Health PID** — the `pid` field in the JSON body of `GET /api/health`. It is the PID of the process that answered (`getDashboardIdentity()` in `src/dashboard/server/identity.ts` lines 19–26, spread into both the 200 and 503 bodies in `src/dashboard/server/health-response.ts` lines 70–91). The fixture spawns `node` directly, so `child.pid` is the server's PID.
- **Fatal bind line vs. bind warning** — when the child cannot bind, the server first logs up to three warnings `[overdeck] HTTP bind failed with EADDRINUSE; retry N/3 in 250ms` (`src/dashboard/server/server.ts` line 200), then, if all retries fail, `runMain` prints the fatal Node error `listen EADDRINUSE: address already in use 0.0.0.0:<port>` and exits 1. Only the fatal line means the child lost the port for good.
- **Root vitest** — `vitest.config.ts` at the repo root (node environment, forks pool, runs in the CI `test-shard` jobs). It discovers `tests/**/*.test.ts` and excludes `src/dashboard/frontend/**` from discovery only; tests may still import files under that tree.

## Problem

`main` CI run #12576 (`4d5461bfccd`) failed `test-e2e`: `tests/pan-4523-river-bands.spec.ts:166` reported "Fixture dashboard exited early (code 1)". The child server's output showed `listen EADDRINUSE: address already in use 0.0.0.0:39366` after its three in-process bind retries.

The cause is `pickPort` (current code, `isolated-dashboard.ts` lines 60–63):

```ts
/** A high port, chosen per run so two suites can never collide. */
function pickPort(): number {
  return 39_000 + Math.floor(Math.random() * 900);
}
```

and its use at line 100: `const port = opts.port ?? pickPort();`. Nothing checks that the port is free. Playwright runs two workers on CI, several specs each boot a fixture, and the 900-port range is small, so two fixtures can draw the same port, or a port still held by an earlier process. The losing child exits with code 1. The collision chance grows with each new spec (PAN-4661 added `pan-4661-mobile-pipeline.spec.ts`).

The server itself already retries a busy bind three times, 250 ms apart (`src/dashboard/server/server-bind.ts`, `retryDashboardBind`). That cannot help when another live fixture owns the port for the whole test.

## Requirements

- **FR-1** `pickPort` returns a port the operating system reports as free at the time of the call: it listens on port `0`, reads `address().port`, closes the probe server, and resolves that port.
- **FR-2** `pickPort` never returns `3011` or any port in its `exclude` list. If the probe yields such a port, it probes again (bounded: at most 5 probes, then it throws an `Error` naming the problem).
- **FR-3** When the fixture chose the port itself (no `opts.port`), the child **exited** early, and its captured output contains the fatal bind line (`listen EADDRINUSE: address already in use`), `startIsolatedDashboard` retries the boot exactly once on a new `pickPort({ exclude: [firstPort] })` port with the same home directory. A bind *warning* alone never triggers a retry.
- **FR-7** `waitForHealth` accepts a health response only when its body's `pid` equals the spawned child's PID. A healthy response from any other process (for example another fixture that grabbed the port in the gap between probe and spawn) is treated as "not ready yet", so polling continues until this child either answers or exits.
- **FR-4** When the caller passed `opts.port`, `startIsolatedDashboard` never substitutes a different port. A failure on an explicit port fails as it does today.
- **FR-5** Any boot failure other than EADDRINUSE fails as it does today (no retry), and a failed final attempt still prints the server output and removes the home directory, exactly as the current `catch` block at lines 141–149 does.
- **FR-6** `pickPort` and the EADDRINUSE detector are exported so a root-vitest unit test can exercise them.
- **NFR-1** The fixture keeps importing only Node built-ins (`node:child_process`, `node:fs`, `node:net`, `node:os`, `node:path`, `node:url`). No import from `src/dashboard/server` or `src/lib`.
- **NFR-2** No change to `playwright.config.ts`, to `src/dashboard/server/server-bind.ts`, or to any spec file.
- **NFR-3** `docs/TESTING.md` states how the fixture picks its port and when it retries.

## Decisions (made here; the executor does not revisit them)

1. **Probe with `server.listen(0)` and no host argument.** Node then binds the unspecified address (`::` dual-stack, or `0.0.0.0` without IPv6). That is at least as strict as the child's own bind on `0.0.0.0`, and it matches the issue's acceptance check `net.createServer().listen(port)` exactly. Follow the existing pattern in `scripts/anywhere/directory-smoke.mjs` (function `freePort`, line 94), minus the `127.0.0.1` host.
2. **Reject only `3011` explicitly.** The fixture does not read the host's `config.toml`. An OS-assigned port can never equal a port the running host dashboard holds, so a non-default host `api_port` is excluded by construction while that dashboard runs; and Linux's ephemeral range (32768–60999) never contains `3011` anyway. The `3011` check is a cheap explicit guard that keeps the old "never 3011" promise. Importing `readHostDashboardApiPort` from `src/dashboard/server/identity.ts` would pull `src/lib/paths.ts`, `@iarna/toml` and build-info into every fixture load (NFR-1), so we do not.
3. **Detect EADDRINUSE from the in-memory `chunks` array** (the child's piped stdout and stderr), not from `readLog(logPath)`. The server writes its bind error to stderr; `server.log` in the temp home is not guaranteed to exist. Before reading `chunks`, wait for the child's `close` event (all stdio drained), capped at 2 s, because `exitCode` becomes non-null on `exit`, which can fire before the last stderr chunk arrives.
4. **Retry once, keep the home.** The failed attempt stops the child with `stop({ keepHome: true })`; the retry boots on the same `home` (callers such as `pan-4307-session-vault.spec.ts:87` pass a pre-seeded home that must survive). Only the final failure removes the home, matching today's behavior.
4a. **Health must come from our own child (FR-7).** `pickPort` releases the probe socket before the child binds, so in that gap another fixture can take the port. Without a PID check, our child's health poll would get the other server's 200 and the fixture would return a dashboard backed by someone else's home. So `waitForHealth` parses the JSON body and compares `body.pid` with `child.pid`; a mismatch, a missing `pid`, or an unparsable body all count as "not ready". This also guarantees the EADDRINUSE path is reached: our child exits, `exitCode` becomes non-null, and the retry runs.
4b. **Retry eligibility is narrow (FR-3).** Retry only when all hold: no `opts.port`, the failure came from the "exited early" branch (child `exitCode !== null`), and the output matches `/listen EADDRINUSE: address already in use/`. The server's transient warnings (`HTTP bind failed with EADDRINUSE; retry …`) do not match that pattern, so a child that bound after a warning and later failed health for another reason is not retried.
4c. **The retry port excludes the first port.** `pickPort` takes `{ probe?, exclude? }`; the retry passes `exclude: [firstPort]` because the kernel can hand a just-released port out again.
5. **No retry for an explicit port** (FR-4): `pan-4279-degraded-mode.spec.ts:50` restarts on `dashboard.port` because the open page still points there; a different port would silently break that spec's premise.
6. **Unit test lives in root vitest** at `tests/unit/dashboard/frontend/isolated-dashboard-port.test.ts`. The frontend vitest config excludes `**/tests/**` and runs happy-dom, so it cannot host this test. Precedent for importing frontend files from root tests: `tests/unit/dashboard/frontend/issue-view-no-loss.test.ts`. Do not add it to `scripts/frontend-test-subset.txt`; the CI `test-shard` jobs pick it up automatically.
7. **Workers stay as configured.** `playwright.config.ts` is not pinned to a worker count; the fix must hold for any count.

## Work items

### WI-1 — `pickPort` asks the OS for a free port (FR-1, FR-2, FR-6, NFR-1)

**File:** `src/dashboard/frontend/tests/fixtures/isolated-dashboard.ts`

Steps:

1. Add `import { createServer } from 'node:net';` to the imports (lines 32–36).
2. Replace lines 60–63 with an exported async function:

```ts
/** The operator's live dashboard port; an isolated fixture must never bind it. */
const HOST_DASHBOARD_PORT = 3011;
const MAX_PORT_PROBES = 5;

/** One OS-assigned port: listen on 0, read the port, release it. */
function probeFreePort(): Promise<number> {
  return new Promise((resolvePort, reject) => {
    const probe = createServer();
    probe.once('error', reject);
    probe.listen(0, () => {
      const address = probe.address();
      const port = typeof address === 'object' && address ? address.port : 0;
      probe.close(() => resolvePort(port));
    });
  });
}

/**
 * A port the OS reports free right now, never the host dashboard's 3011.
 * The port is released before the child binds it, so a tiny race remains;
 * `startIsolatedDashboard` covers it with one retry on EADDRINUSE.
 */
export interface PickPortOptions {
  /** Test seam: where candidate ports come from. */
  probe?: () => Promise<number>;
  /** Ports to skip, e.g. the one a failed first boot just lost. */
  exclude?: readonly number[];
}

export async function pickPort({ probe = probeFreePort, exclude = [] }: PickPortOptions = {}): Promise<number> {
  for (let attempt = 0; attempt < MAX_PORT_PROBES; attempt += 1) {
    const port = await probe();
    if (port > 0 && port !== HOST_DASHBOARD_PORT && !exclude.includes(port)) return port;
  }
  throw new Error(`pickPort: no usable free port after ${MAX_PORT_PROBES} probes`);
}
```

3. Change line 100 from `const port = opts.port ?? pickPort();` to `const port = opts.port ?? (await pickPort());` (WI-2 restructures this further; if WI-2 lands in the same commit, follow WI-2's shape).
4. Rewrite the header bullet at lines 18–20 ("a port that is never 3011 …") to say: the port is OS-assigned and free when picked, never 3011, and a boot that loses the port race retries once on a fresh port.

### WI-1b — `waitForHealth` accepts only the spawned child's health response (FR-7)

**File:** `src/dashboard/frontend/tests/fixtures/isolated-dashboard.ts` (same file as WI-1; depends on WI-1 only because they share the file).

Steps:

1. Export `waitForHealth` and change its signature to take a minimal child shape and optional timing, so a unit test can drive it without spawning a dashboard:

```ts
export interface HealthWaitChild {
  readonly pid?: number;
  readonly exitCode: number | null;
}

export async function waitForHealth(
  baseUrl: string,
  child: HealthWaitChild,
  opts: { logPath?: string; timeoutMs?: number; pollMs?: number } = {},
): Promise<void> {
  const { logPath, timeoutMs = BOOT_TIMEOUT_MS, pollMs = 500 } = opts;
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    if (child.exitCode !== null) {
      throw new Error(`Fixture dashboard exited early (code ${child.exitCode}).\n${logPath ? readLog(logPath) : ''}`);
    }
    try {
      const response = await fetch(`${baseUrl}/api/health`, { signal: AbortSignal.timeout(2_000) });
      if (response.ok) {
        const body = (await response.json()) as { pid?: unknown };
        // Another process may hold this port (the probe released it before spawn).
        if (body.pid === child.pid) return;
      }
    } catch {
      // Not listening yet, or not JSON.
    }
    await new Promise((r) => setTimeout(r, pollMs));
  }
  throw new Error(`Fixture dashboard did not become healthy.\n${logPath ? readLog(logPath) : ''}`);
}
```

2. The call site in `bootOnce` (WI-2) passes the real `ChildProcess` (it satisfies `HealthWaitChild`) and `{ logPath }`.

Keep the error message prefixes `Fixture dashboard exited early (code N).` and `Fixture dashboard did not become healthy.` exactly; WI-2 tells the two apart by the exit code, not the text.

### WI-2 — Retry the boot once on EADDRINUSE when the fixture chose the port (FR-3, FR-4, FR-5, FR-6)

**File:** `src/dashboard/frontend/tests/fixtures/isolated-dashboard.ts` (same file as WI-1; depends on WI-1).

Steps:

1. Add an exported pure detector that matches only the fatal bind line, never the server's retry warning:

/**
 * True when the child's captured output holds the fatal bind error. The
 * server's transient `HTTP bind failed with EADDRINUSE; retry N/3` warnings
 * do not match: a child can log one and still bind.

export function isAddressInUseOutput(output: string): boolean {
  return /listen EADDRINUSE: address already in use/.test(output);
}

2. Split the current body of `startIsolatedDashboard` (lines 98–152) into a private `bootOnce(home: string, port: number, env: Record<string, string> | undefined)` that spawns the child, waits for health, and on failure:
   - waits for the child's `close` event, capped at 2 000 ms (`await Promise.race([closed, new Promise((r) => setTimeout(r, 2_000))])`, where `closed` is a promise created right after `spawn` with `child.once('close', …)`);
   - calls `stop({ keepHome: true })`;
   - throws a `FixtureBootError` carrying the captured output and whether the child exited, with the same message text as today:

```ts
class FixtureBootError extends Error {
  constructor(message: string, readonly output: string, readonly exited: boolean) {
    super(message);
  }
}
```

   `exited` is `child.exitCode !== null` (or a signal code set) after the capped `close` wait.
3. `startIsolatedDashboard(opts)` becomes:

```ts
export async function startIsolatedDashboard(opts: IsolatedDashboardOptions = {}): Promise<IsolatedDashboard> {
  const home = opts.home ?? mkdtempSync(join(tmpdir(), 'overdeck-e2e-home-'));
  const explicitPort = opts.port !== undefined;
  const firstPort = opts.port ?? (await pickPort());
  try {
    try {
      return await bootOnce(home, firstPort, opts.env);
    } catch (err) {
      // A fresh port only when we chose the first one: an explicit port is a
      // restart the open page depends on (pan-4279-degraded-mode.spec.ts).
      const lostPort =
        err instanceof FixtureBootError && err.exited && isAddressInUseOutput(err.output);
      if (explicitPort || !lostPort) throw err;
      return await bootOnce(home, await pickPort({ exclude: [firstPort] }), opts.env);
    }
  } catch (err) {
    if (err instanceof FixtureBootError) {
      // eslint-disable-next-line no-console
      console.error(err.output.split('\n').slice(-40).join('\n'));
    }
    rmSync(home, { recursive: true, force: true });
    throw err;
  }
}
```

   The returned `IsolatedDashboard.stop` is the one `bootOnce` built, unchanged in behavior (`keepHome` still respected).
4. Do not change the `IsolatedDashboard` / `IsolatedDashboardOptions` interfaces.

Decision rules restated: retry at most once; retry only when `opts.port` is undefined **and** the child exited **and** the captured output contains the fatal line `listen EADDRINUSE: address already in use`; the retry port excludes the first port; any other failure, or a second failure, prints the last 40 output lines, removes the home, and rethrows.

## Critique response

The plan critic (round 1, `.pan/drafts/PAN-4805-critique.md`) raised two design blockers and one sharpening. All three are accepted and folded into the work items above.

### health can validate the wrong dashboard

Accepted. New FR-7 and WI-1b: `waitForHealth` parses the health body and returns only when `body.pid === child.pid` (the health body carries the serving PID via `getDashboardIdentity()`). A foreign healthy response keeps the poll going, so our child's bind failure still surfaces as an early exit and reaches the retry. `waitForHealth` takes a minimal `{ pid, exitCode }` child plus `pollMs`, and unit tests 6 and 7 cover the mismatch and match cases deterministically with a local `node:http` server.

### transient bind warnings trigger unrelated retries

Accepted. `isAddressInUseOutput` now matches only the fatal Node error `listen EADDRINUSE: address already in use`, which the server's retry warning (`HTTP bind failed with EADDRINUSE; retry N/3`) does not contain. Retry eligibility additionally requires `FixtureBootError.exited` (the child process actually ended), so a child that bound after a warning and then failed health for another reason is not retried (FR-3, FR-5). Unit test 5 asserts a warning followed by an unrelated failure is not eligible.

### second port is not guaranteed fresh

Accepted. `pickPort` takes `exclude`, and the retry calls `pickPort({ exclude: [firstPort] })`. Unit test 3b covers a probe that returns the excluded port before a different one.

### Unresolved after two critic rounds

- missing PID can pass health
- port-probe failure leaks the temp home
