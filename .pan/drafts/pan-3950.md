# PAN-3950 — Transcripts stay discoverable: keep agent state at close-out, drop `session.id`, issue panel uses the agent transcript route

**Issue:** https://github.com/eltmon/overdeck/issues/3950
**Baseline:** `main` at `cd294a6ac2d` (2026-09-20). Line numbers below were verified against that commit by the lifecycle audit (`.tmp/transcript-resume-audit.md`, Codex gpt-5.6-sol, 2026-09-20); if a number has drifted, search for the quoted identifier.
**Principle (from the PAN-3917 cut):** Overdeck stores no status it can derive. Append-only records of facts are allowed; mutable "current" pointers that something must keep true are not.

## Glossary

- **Agent directory** — `~/.overdeck/agents/<agent-id>/`. Holds `state.json` (launch metadata + last status), `sessions.json` (append-only list of harness session ids, written by the SessionStart hook), `session.id` (single "current" session pointer — **to be deleted by this PRD**), `lifecycle.log`, `activity.jsonl`, `codex-thread-id`, and for codex agents a per-agent `codex-home*/` with `sessions/**/rollout-*.jsonl` transcripts.
- **Claude transcript** — `~/.claude/projects/<cwd-slug>/<session-id>.jsonl`, written by Claude Code, never by Overdeck. Sacred: never deleted or truncated by Overdeck (CLAUDE.md).
- **Codex rollout** — `<agent dir>/codex-home*/sessions/YYYY/MM/DD/rollout-*.jsonl`. Its first record is `session_meta` with `cwd` = the workspace path.
- **Agent transcript route** — `GET /api/agents/:agentId/conversation` (`src/dashboard/server/routes/agents/conversation.ts:102-197`). Resolves the transcript from agent state (`getAgentJsonlPath`) and the launcher-pinned path.
- **Generic conversation route** — `GET /api/conversations/:name/messages` (`src/dashboard/server/routes/conversations.ts:466-480`) backed by `src/dashboard/server/services/conversation-reads.ts:526-682`. Looks up a `conversations` row by name; work agents never have one.
- **Close-out** — `pan close`; teardown in `src/lib/close/teardown-workspace.ts`, state deletion in `src/lib/agents/state-dir-removal.ts`.

## Problem

1. **Live agent, empty panel.** The issue Session tab builds a synthetic conversation named `agent-<issue>` and fetches it through the generic route (`ConversationPanel.tsx:243-265`, URL at `:1133-1147`). The exact-name lookup (`src/lib/conversations.ts:1019-1023`) misses because work-agent launch registers no conversation row (`src/lib/agents/spawn.ts:99-166`; rows only for specialists at `:247-254`, `:326-380`). The fallback scan may miss; the frontend converts the 404 into an empty "How can I help you?" instead of an error.
2. **Closed issue, no history.** `removeAgentStateDirs` keeps only regular files ending in `.jsonl` (`state-dir-removal.ts:33-93`, batch at `:178-220`; invoked by close-out at `teardown-workspace.ts:306-340`, reported at `:743-757`). `state.json`, `sessions.json`, `codex-thread-id` are deleted, so no issue→agent→session chain survives even though the Claude JSONL does.
3. **Pointer drift.** `session.id` is a single mutable pointer. Restart never clears it (`src/lib/agents/recovery.ts:218-234`); the hook appends the new id to `sessions.json` (`src/lib/agents/agent-state-service.ts:145-159`); resolvers prefer the stale `session.id`. `resume.ts:474-497` exists only to "repair" this pointer.
4. **Retention skips orphans.** `src/lib/agents/transcript-retention.ts:218-245` skips agent dirs without usable state, so a dir left with only `.jsonl` is never managed again.

## Requirements

- **FR-1** After `pan close`, the issue's Session tab lists every agent that ran on the issue (work, review, review lanes, test, planning, strike) and renders each transcript read-only, with the same fidelity as while live.
- **FR-2** While an agent is live or paused, the Session tab renders its transcript; a resolver miss renders an explicit message naming the agent id and the paths checked, never an empty chat.
- **FR-3** The issue panel reaches transcripts through the agent transcript route only. The generic route no longer attempts agent fallback resolution for `agent-*` names.
- **FR-4** `session.id` is neither written nor read anywhere. The current session of an agent is the newest entry of `sessions.json` (last line); "live" is decided by liveness (`src/lib/agents/liveness.ts`), not by the pointer.
- **FR-5** Close-out deletes only regenerable weight from an agent directory: `*.sock` references, `pending.lock`, and everything under `codex-home*/` except `sessions/`. It keeps `state.json`, `sessions.json`, `lifecycle.log`, `activity.jsonl`, `cv.json`, `codex-thread-id`, `context-receipt.json`, and all transcripts.
- **FR-6** Transcript retention enumerates agent directories regardless of whether `state.json` is present, ages them by the newest transcript mtime, and applies the configured `retention.transcript_days` to codex rollouts and the agent directory. It never touches `~/.claude/projects`.
- **NFR-1** No new store, table, cache, manifest, or module. Net lines deleted > lines added outside tests.
- **NFR-2** No polling added; the panel keeps its existing WS/RPC + fetch pattern.
- **NFR-3** Backward compatibility for one release: a reader that finds `session.id` but no `sessions.json` treats its content as the single entry; nothing writes `session.id`.

### W2 — Delete `session.id`; `sessions.json` is the index (FR-4, NFR-3)

Files: `src/lib/agents/agent-state-service.ts` (`saveSessionId`, `getLatestSessionIdSync`, `resolveLatestSessionIdSync`), `src/lib/agents/resume.ts` (Step 3 pointer repair `:474-497`, the `unlinkSync(... 'session.id')` at `~:404`), `src/lib/agents/recovery.ts` (`:218-234`), `src/lib/agents/spawn.ts` (wherever `saveSessionId` is called at launch), the `session-start` hook under `sync-sources/hooks/` (must only append to `sessions.json`), and every `grep -rn "session.id" src sync-sources --include=*.ts` hit outside tests.

Rules:
- `saveSessionId(agentId, id)` appends `{ sessionId, at, source }` to `sessions.json` (dedupe on sessionId) and writes nothing else.
- `getLatestSessionIdSync(agentId)` = last entry of `sessions.json`; if the file is absent and a legacy `session.id` exists, return its content (NFR-3). Never create `session.id`.
- `resolveLatestSessionIdSync` loses its `needsPointerRepair` branch; `resume.ts` deletes the block at `:474-497` and the `session.id` unlink; restart (`recovery.ts:218-234`) allocates the fresh Claude session id and appends it to `sessions.json` **before** launching, so the newest entry is the running one.
- `getAgentJsonlPath` (used by the agent transcript route) resolves from the newest `sessions.json` entry whose JSONL exists; falls back to older entries.

Tests: `tests/unit/lib/agents/session-index.test.ts` (new): append/dedupe, newest-wins, legacy `session.id` read-only fallback, restart ordering (entry present before launch). Update every test that asserts on `session.id` writes.

### W3 — Issue panel uses the agent transcript route; no fallback, no swallow (FR-1, FR-2, FR-3)

Files: `src/dashboard/frontend/src/components/ConversationPanel.tsx` (`:243-265`, `:1133-1147`), the `DrawerAgentSession` component that builds the agent-backed conversation (grep `DrawerAgentSession`), `src/dashboard/server/services/conversation-reads.ts` (`:526-682`), `src/dashboard/server/routes/agents/conversation.ts` (`:102-197`), tests beside each.

Rules:

Checked: <paths>` using the `checked` array the agent route returns (add it to its 404 body: the `sessions.json` entries tried and the launcher-pinned path).

Tests: frontend `ConversationPanel.test.tsx`/`DrawerAgentSession` test: agent-backed conversation calls the agent route; 404 renders the explicit message with the checked paths. Server: `conversation-reads` test asserting the fallback code is gone (404 for an unknown `agent-*` name); agent route test for a stopped agent with two `sessions.json` entries where only the older JSONL exists → resolves the older one.
