**Branch:** `feature/pan-3926` (at `b7bedc3278a`, one docs commit behind `origin/main`; every file cited below is byte-identical on both).
**Planning mode:** `pan plan --auto` — no operator questions; defaults are recorded under "Decisions".

## Glossary

- **Terminal backend** — the thing that owns agent terminals. Two adapters implement `src/lib/terminal-backends/types.ts` `TerminalBackend`: **Herdr** (default since the cut) and **tmux**. The host's selection is memoized per process by `hostTerminalBackendName()` in `src/lib/terminal-backends/select.ts` (line 123). Under Herdr an agent has **no tmux session at all**.
- **Inventory** — the selected backend's live list of agent panes: `liveAgentInventory()` / `listLiveAgentIds()` / `captureLiveAgentPaneText()` in `src/lib/terminal-backends/inventory.ts`. Exited panes are excluded. **`null` means indeterminate** (the backend could not be read), never "nothing is running".
- **Liveness oracle** — `src/lib/agents/liveness.ts`. `isAlive(agentId)` (line 149) is async and backend-aware: on Herdr it asks `probeHerdrAgentLiveness`; on tmux it runs the three-check probe (`isAliveOnTmux`). `isAliveSync` (line 224) is the **synchronous, tmux-only** variant this issue removes. `isConfirmedDead(verdict)` (line 86) is the remediation gate: `runtime-indeterminate` is never death.
- **Lifecycle classifier** — `src/lib/work-agent-lifecycle.ts`. `getWorkAgentLifecycleStateSync` (line 85) and the private async `getWorkAgentLifecycleStateSnapshot` (line 197) compute `WorkAgentLifecycleState` (`hasLiveTmuxSession`, `isRunning`, `canResumeSession`, `canStartFresh`, `recommendedAction`, …). The Effect export `getWorkAgentLifecycleState` (line 357) already wraps the async snapshot. `assertCanStartFreshSync` (line 323) and `assertCanResumeSessionSync` (line 338) are the sync guards; their Effect wrappers (lines 363, 377) wrap the *sync* guards today.
- **Async door / sync door** — the async snapshot additionally asks the forge whether the PR has `CHANGES_REQUESTED` (`issueOwesRework`, line 30; PAN-3555) and lifts the handoff gate when it does. The sync door cannot make that call and answers conservatively (comment at lines 114–118).
- **`hasLiveTmuxSession`** — the classifier field name. It is wired into frontend types (`src/dashboard/frontend/src/types.ts:70`) and route payloads; it is **not renamed** by this issue. After this issue it means "the liveness oracle did not confirm death", on either backend.
- **`tmuxActive`** — a per-row flag `listRunningAgentsSync()` (`src/lib/agents/queries.ts:17`) computes from the tmux census. Under Herdr it is `false` for every live agent (or `true` for all of them when tmux is unavailable and the census fails open). Filtering on it is the concurrency bug.
- **Swarm** — the dormant parallel-slot machinery (`pan swarm`, `agent-<issue>-slot-N` work agents, foreman). PAN-3917 **D11**: it stays in the tree, is not wired into the default work path, and the default policy mode is `'off'` (`src/lib/swarm-policy.ts:20`).
- **`swarmJanitorPass`** — `src/lib/cloister/deacon-swarm.ts:353`. Enumerates feature workspaces and, per issue: merged-slot GC (`gcMergedSlots`), orphan-slot GC (`gcOrphanedSlots`), foreman maintenance (`maintainSwarmForeman`, policy-gated), and stall events for in-flight slots. Its default deps (`defaultDeps`, line 107) are tmux primitives. It ran on the deleted `deacon.ts` 60 s patrol (`runBudgetedPatrol('swarmJanitorPass', …)`, old line 2918); since commit `94255f055fe` **nothing calls it** — only the orphan-GC half survived as `sweepOrphanedSwarmSlots` (`src/lib/cloister/swarm-orphan-sweep.ts`) on the hygiene scheduler.
- **deacon-lite** — `src/lib/cloister/deacon-lite.ts`. The surviving 60 s patrol: `checkStuckWorkAgents`, `checkApiErrorAgents`, `reconcileAgentLiveness`, `reapClosedIssueAgents`, run in order by `runDeaconLite()` (line 162), skipped entirely while `isDeaconGloballyPausedSync()` (D7).
- **Hygiene scheduler** — `src/lib/cloister/hygiene-scheduler.ts`. Plain `setInterval` routines for host hygiene only; its header says they "never read or write pipeline status" and it does not honor the deacon pause.
- **Fail-open count** — the `countRunningAgents()` convention (`src/lib/cloister/concurrency.ts:177`): when the inventory is `null`, every `status: 'running'` state file counts, because the ceiling's job is to hold work back.

## Problem

Three places still assume "alive ⇔ has a tmux session", so on a Herdr host they are wrong in the direction that matters:

1. **Sync liveness door.** `isAliveSync` is tmux-only. Its two callers — `getWorkAgentLifecycleStateSync` (`work-agent-lifecycle.ts:97`) and `resolveParkedPopulation` (`parked/resolver.ts:258`) — read every healthy Herdr agent as `no-session`, a *confirmed* death. Consequences: `pan start` offers a fresh start over a running agent; `pan resume` / `pan unpause` misjudge; `pan reset-session` proceeds against a live agent; the merge-strike route spawns a second work agent; the parked sweeper never sees a live agent (no `zombie-session` / `idle-running` rows). `docs/TERMINAL-BACKENDS.md:188` records this as a known gap.
2. **Swarm concurrency counts.** `countRunningSwarmSlotsForIssue` (`concurrency.ts:126`), `describeRunningAgents` (line 93) and `emergencyBrake` (line 355) filter `listRunningAgentsSync()` rows on `tmuxActive`. Under Herdr live slots count as zero, so `registeredSlotCapacityAvailable` (`deacon-swarm.ts:1082`) over-admits, the diagnostic line reports an empty box, and the brake trims nothing.
3. **Unscheduled janitor.** `swarmJanitorPass`'s remainder — merged-slot GC, foreman maintenance, stall events — has no caller since the cut, and its default deps would be tmux-only if it were called.

Swarm is dormant (D11), but the issue requires all three to be backend-aware before it is re-enabled.

## Proposal (summary)

- **Liveness (gap 1):** there is no synchronous Herdr client and the repo forbids new sync primitives, so the sync door is retired rather than patched. Every caller of the sync classifier is already inside an `async` function. Export Promise variants of the classifier and both guards over the existing async snapshot, move the six callers to them, switch the parked sweeper to `isAlive`, then delete `isAliveSync`, the sync classifier/guards and the sync pid probe as orphans.
- **Counts (gap 2):** the swarm-slot count, the diagnostic line and the brake read liveness from `listLiveAgentIds()` with the same fail-open rule `countRunningAgents()` uses. The pure per-issue counter keeps its shape and takes a `liveIds` set instead of the row flag.
- **Janitor (gap 3):** a new `runSwarmJanitor()` reads the inventory once, builds backend-aware deps on top of the exported swarm defaults (the `swarm-orphan-sweep.ts` pattern), skips on an unreadable inventory, and runs `swarmJanitorPass`. deacon-lite runs it as its fifth routine, gated off unless a swarm policy mode other than `'off'` is configured globally or on any project — dormant by default, per D11.

## Decisions

- **D1 — Retire the sync liveness door; do not add a sync Herdr probe.** `sync-sources/rules/prefer-async.md`: sync variants are legacy debt, no new sync functions or callers. A sync Herdr client would be a `spawnSync` of the `herdr` CLI in server-reachable code (`merge-strike.ts` is a dashboard route), which `no-execsync-server` forbids.
- **D2 — Promise variants carry the `Async` suffix** (`getWorkAgentLifecycleStateAsync`, `assertCanStartFreshAsync`, `assertCanResumeSessionAsync`), matching `sendKeysAsync` / `dropLegacyAgentStatesMissingRoleAsync`. The un-suffixed `getWorkAgentLifecycleState` stays the Effect export (five dashboard routes use it). The Effect guards `assertCanStartFresh` / `assertCanResumeSession` are rebuilt over the async variants with `Effect.tryPromise`; they have no production callers today, so no route changes.
- **D3 — The CLI inherits PAN-3555 semantics.** Moving `pan start` / `pan resume` / `pan unpause` to the async door means a handed-off agent whose PR has `CHANGES_REQUESTED` becomes resumable from the CLI, as it already is from the dashboard. The forge call happens only when `handedOff` is true (`handedOff && await issueOwesRework(...)`, line 228), and a failed forge call already reads as `false` (line 34). This is the intended PAN-3555 behavior reaching the CLI, recorded here as a deliberate change.
- **D4 — Parked probes run in parallel.** `Promise.all` over `isAlive` so a Herdr socket outage costs one `HERDR_PROBE_TIMEOUT_MS` (2 s), not 2 s × N agents.
- **D5 — Per-issue slot counting takes a `liveIds: ReadonlySet<string> | null` parameter.** `null` fails open (every running row counts), exactly like `countRunningAgents()`. The pure function keeps a synchronous signature so `registeredSlotCapacityAvailable` stays pure and unit-testable; a thin async wrapper `countLiveSwarmSlotsForIssue(issueId)` fetches the inventory.
- **D6 — `emergencyBrake` is in scope.** The issue names two `tmuxActive` filters in `concurrency.ts`; the brake is the third, in the same file, with the same failure (under Herdr it sees zero work agents and trims nothing). Leaving it would ship a known Herdr gap in the file this issue exists to fix. It becomes async and stops agents through the Effect `stopAgent` (`termination.ts:200`), which also removes a sync tmux kill from a dashboard route.
- **D7 — The janitor is a deacon-lite routine, not a hygiene routine.** Foreman respawn and stall events are pipeline behavior; the hygiene scheduler's contract excludes pipeline routines and ignores the deacon pause. deacon-lite is the patrol's successor and honors D7's pause.
- **D8 — Dormancy gate.** The routine returns `[]` without enumerating workspaces unless `resolveSwarmPolicy().mode !== 'off'` or some registered project sets `swarm.mode` to a value other than `'off'`. Config reads only; a default host pays nothing. PAN-3917 FR-11 says every other patrol is deleted; this issue (newer, same author lineage) asks for the remainder to be backend-aware before re-enable — the gate is how both hold.
- **D9 — Double orphan GC is accepted.** `swarmJanitorPass` still calls `gcOrphanedSlots` and `sweepOrphanedSwarmSlots` also does at 60 s. GC of a slot with nothing to remove is a no-op, and the janitor is inert by default. Not stripped, to keep the janitor's existing tests intact.
- **D10 — Import the janitor module dynamically from deacon-lite** (`await import('./swarm-janitor.js')` inside the routine, the `inventory.ts` pattern). A static edge would pull `spawnRun`/`messageAgent` into the patrol module graph; `liveness.ts`'s header documents the runtimes cycle this avoids.
- **D11 — Out of scope (NonGoals).** Renaming `hasLiveTmuxSession`; other `tmuxActive` consumers (`memory-governor.ts:450`, `recovery.ts:360`, `reconstruct-cache.ts:81`, `health.ts:141`, `listRunningAgentsSync` itself); `coordinateSwarmSlots`'s tmux default deps and `swarm-status.ts`'s `listSessionNamesSync` / default `classifyInFlightSlots`; the `useSupervisor: true` hardcodes in `runtimes/muse.ts`, `runtimes/kimi-code.ts`, `overdeck/conversation-runtime.ts` (a separate gap named in the same doc paragraph).
