## blocks-the-design: Config changes can strand stopped services

The PRD's WI-2 says the current configured services remain restorable when idle stop is disabled, but `services: []` is itself a documented disable switch ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5250/.pan/drafts/PAN-5250.md), lines 45 and 230–244). WI-4 changes the restore door to accept only `restorableServices(issueId)` from the *current* project config (lines 273–298). The existing door refuses names outside that set and then writes `stack.restored` even when `refused` is nonempty ([stack-restore.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5250/src/lib/workspace/stack-restore.ts), lines 147–182). Thus an idle-stopped `dev` stays stopped if the operator disables the feature with `services: []` or removes `dev` from the list; the restore journal closes, so later attempts lose the open reclaim. Make restore eligibility derive from the recorded idle-stop service and container identity as well as the compose-project label, independent of the current idle-stop setting. Add a test that changes or empties `services` between stop and restore.

## blocks-the-design: Old reaper bypasses browser use and pins

FR-3 says a browser connection or pin protects a workspace, and the CLI promises pinning keeps its containers running ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5250/.pan/drafts/PAN-5250.md), lines 47–64 and 404–425). The existing reaper is left unchanged by D12 (line 137), but its 10-minute tier checks only live agent IDs and main-workspace status before stopping `server`/`frontend`; it does not inspect connections or the new pin file ([idle-stack-reaper.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5250/src/lib/cloister/idle-stack-reaper.ts), lines 234–269). Its full-stack tier has the same omission (lines 303–325). With no agent pane, it can stop a frontend while the operator has the app open or after `pan workspace pin`, regardless of the new service's decision. Make the old reaper honor the same pin and usage protections for overlapping workspaces, or retire its overlapping stop path as part of this work; test the no-agent browser and pinned cases.

## blocks-the-design: Default stop has no browser wake path

The PRD enables the 20-minute stop by default (line 45) while D1 explicitly moves app-URL wake to a later issue and says the stopped URL returns Traefik 404 ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5250/.pan/drafts/PAN-5250.md), line 126). The existing dashboard also removes the `app ↗` entry when the stack is not live ([FeatureAppLink.tsx](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5250/src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureAppLink.tsx), lines 25–30). This makes the normal operator path to an idle app disappear by default, even though the issue calls for restart on demand. Include browser/dashboard wake in this release, or keep automatic stopping opt-in until the sibling wake path ships. State that rollout dependency in the requirements and acceptance criteria.
