## Glossary

- **Herdr** — the default terminal backend. A session server reached over a Unix socket, plus a
  `herdr` CLI binary. The vendor installer puts the binary at `~/.local/bin/herdr`.
- **Terminal stream** — a `herdr --session <s> terminal session observe|control <terminalId>`
  child process that emits NDJSON frames. Spawned by `startStream()` in
  `src/lib/terminal-backends/herdr-stream.ts`. Three public callers: `observeTerminal`,
  `controlTerminal`, `sizeHerdrTerminal`.
- **Probe** — `probeHerdrAvailability()` / `findHerdrBinary()` in
  `src/lib/terminal-backends/select.ts`: checks for the binary with `fs.access` (no subprocess)
  across a directory list, then checks the session socket.
- **Search dirs** — `herdrSearchDirs()`: the probe's directory list. `PATH` entries in order,
  then `~/.local/bin`, with empty entries dropped.
- **npx PATH** — the `PATH` a dashboard started through `npx @overdeck/core` inherits. It does
  not contain `~/.local/bin`.
- **Read-only fallback** — `HerdrTerminalProcess` treats a `control` stream that ends before its
  first frame as "controlled by another client" and serves `observe` only.

## Root cause

`startStream()` spawned the bare command `herdr` with the dashboard's own environment. Node
resolves a bare command through the child's `PATH`. Under the npx PATH, `~/.local/bin` is
missing, so the spawn emits `error` with `ENOENT`. The probe did not catch this because
`findHerdrBinary` already falls back to `~/.local/bin`, so Herdr was selected and socket calls
worked. Only the stream spawns failed, which presented as:

1. `control` ends before its first frame → log line
   `Herdr terminal <id> is controlled by another client; serving it read-only`.
2. `observe` fails the same way → WebSocket closes with code 1000.
3. Client reconnects with backoff, then gives up after 5 minutes with "Connection lost".
4. `sizeHerdrTerminal` at launch → `[herdr] could not size w1:pN to its layout: sizing attach refused`.

### `src/lib/terminal-backends/herdr-stream.ts` (grep anchor: `herdrSearchDirs().join(delimiter)`)

Before:

```ts
const spawnFn = deps.spawn ?? ((cmd, argv) => nodeSpawn(cmd, [...argv]) as ChildProcessWithoutNullStreams);

```

After:

```ts
const spawnFn = deps.spawn ?? ((cmd, argv, options) => nodeSpawn(cmd, [...argv], options) as ChildProcessWithoutNullStreams);

```

`HerdrSpawn` gained a third parameter `options: { env: NodeJS.ProcessEnv }`. The command stays
`deps.binary ?? HERDR_BINARY` (bare `herdr`), so PATH resolution does the lookup.

## Requirements

- **FR-1** — Every Herdr terminal stream (`observe`, `control`, and the `sizeHerdrTerminal`
  sizing attach) spawns with `env.PATH` equal to `herdrSearchDirs().join(delimiter)`, so a
  dashboard whose `PATH` omits `~/.local/bin` still finds `~/.local/bin/herdr`.
- **FR-2** — `herdrSearchDirs()` is exported from `select.ts` and is the single directory list
  both the availability probe and the stream spawns use. Order: `PATH` entries first, then
  `<homeDir>/.local/bin`. Empty entries are dropped.
- **FR-3** — The rest of the child environment is preserved (`{ ...process.env, PATH }`).
- **FR-4** — Developer and user docs state that the streams spawn with the probe's search dirs
  as `PATH`.
- **NFR-1** — No new subprocess, no blocking call, no change to probe order or to the spawned
  command name. `deps.binary` still overrides the command.
- **NFR-2** — Tests touching `PATH` use `vi.stubEnv` / `vi.unstubAllEnvs` and never mutate
  `process.env` directly. `sizeHerdrTerminal` tests keep the existing `vi.useFakeTimers()`
  setup (repo rule: fake timers for delay-based tests).
