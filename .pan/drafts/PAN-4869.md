# PAN-4869: Anywhere is hard to find: add a sidebar entry and command-palette actions

**Issue:** https://github.com/eltmon/overdeck/issues/4869
**Scope:** dashboard frontend plus user docs. No server, route, schema or CLI change.

## Problem

The operator asked how to reach Overdeck Anywhere in the dashboard (2026-11-03). Today every
Anywhere action lives only in **Settings → Anywhere** (sidebar → More → System → Settings, then
scroll to the Anywhere section), plus the Anywhere status card on the Health page. The sidebar
has no entry for it, and the command palette has no Anywhere action: the only Anywhere-related
palette code is `components/palette-fleet-hits.tsx`, which lists linked machines' conversation
search hits.

This change adds three entry points and documents them:

1. A **Machines** row in the sidebar's primary rail that opens Settings → Anywhere and shows how
   many linked machines are online.
2. Seven command-palette actions that open the same Anywhere dialogs as the Settings buttons.
3. A **Reach this machine from anywhere** row on the Home page's **Get set up** card.

## Decisions (made here; the executor does not re-decide them)

- **D1 — Palette actions open the dialog in place, through a dialog host.** A new zustand store
  `anywhereDialogStore` and a new `AnywhereDialogHost` mounted in `main.tsx` render the same
  dialog components the Settings buttons render. This follows the documented dialog-host
  convention and keeps the operator on the page they were on. The Settings buttons keep their
  own local state; they are not rewired.
- **D2 — "Open Anywhere settings" navigates.** It calls `requestSettingsSection('anywhere')` and
  `onNavigate('settings')`. It opens no dialog.
- **D3 — "Machines" is an action row, not a `Tab`.** Every `Tab` maps to a URL in
  `App/routes.ts`; a fake tab would break routing. The row calls
  `requestSettingsSection('anywhere')` then the sidebar's `onTabChange('settings')` and closes
  the mobile drawer. It never shows the active highlight (it is a shortcut into a Settings
  section, and Settings has its own row under More → System).
- **D4 — Badge counts online links.** Count = `links.filter((l) => l.state === 'online').length`,
  hidden links included (`hidden` only removes a machine's conversations from the list). The
  badge is hidden when the count is 0, when the query has not resolved or failed, and when the
  sidebar is collapsed. In the collapsed sidebar the row's `title` is `Machines · N online`
  (just `Machines` when N is 0).
- **D5 — Badge data.** `useQuery({ queryKey: MACHINES_QUERY_KEY, queryFn: loadMachines,
  staleTime: 15_000, refetchInterval: 30_000 })`. Sharing `MACHINES_QUERY_KEY` means every
  existing invalidation (Link/SSH/Fly dialogs, MachinesPanel) refreshes the badge. 30 s is the
  same cadence as `useFleetProjects` in the same sidebar.
- **D6 — Badge style.** The online tone used by `LinkStateBadge` (`MachinesPanel.tsx` line 59):
  `ml-auto inline-flex items-center rounded-md border px-1.5 text-[10px] font-medium bg-info/8
  border-info/32 text-info-foreground`. Never green (style guide: running/online is not green).
- **D7 — Tailscale gate lives in the host.** For `tailscale-setup`, the host reads
  `ANYWHERE_STATUS_QUERY_KEY` / `loadAnywhereStatus` (enabled only while that dialog is
  requested). While the status is loading the host renders nothing. When it resolves with
  `viewer.kind === 'root-session'` the host renders `TailscaleSetupDialog`. Otherwise (other
  viewer kind, or a query error) it calls
  `toast.info('Tailscale can be set up only from a browser on this machine.')` and closes. The
  palette always lists "Set up Tailscale" (it cannot query; see CommandPalette test harness).
- **D8 — Tailscale "Pair a device" hand-off.** The host passes
  `onPair={() => openAnywhereDialog('pair-device')}`, mirroring `AnywhereSection` lines 99-102.
- **D9 — Phone dialog's settings link navigates from anywhere.** Add
  `openSettingsSection(sectionId)` to `lib/settingsSection.ts`: it calls
  `requestSettingsSection(sectionId)`, and when `window.location.pathname !== '/settings'` it
  goes through the URL door (`pushState({ tab: 'settings' }, '', '/settings')` + `popstate`).
  `SetUpPhoneDialog`'s **Open the setting** calls it instead of `requestSettingsSection`.
  Without this, the button does nothing visible when the dialog is opened from the palette on
  another page.
- **D10 — Palette group "Anywhere".** The seven rows use group `'Anywhere'`, inserted into the
  `preferred` order right after `'Navigation'`. They appear in the empty-query default view
  (the point of the issue is discoverability). `groupScope('Anywhere')` already returns
  `'actions'`; no change there.
- **D11 — Palette module has no React-Query dependency** and does not import from
  `CommandPalette.tsx` (avoids an import cycle). It returns structurally typed rows, as
  `palette-fleet-hits.tsx` does.
- **D12 — Home row is advanced-mode only.** `GetSetUpCard` gains an optional
  `onOpenSettings?: () => void` prop. The Anywhere row renders only when that prop is given.
  `HomePage` passes it; `SimpleHomePage` does not, so simple mode never shows the row (simple
  mode has no Settings navigation callback and targets non-technical users).
- **D13 — Home row condition.** The row renders only when `GET /api/machines` resolved with
  `Array.isArray(links) && links.length === 0` **and** `GET /api/anywhere/status` resolved with
  `tailscale.nextStep !== 'ready'` (a string). Loading, error, or malformed data ⇒ no row. The
  row never feeds `hasRequiredFailing`, so it never keeps a dismissed card visible.
- **D14 — Home row look.** Same markup as the existing todo rows: the `AlertTriangle` todo icon
  (as the optional Docker row uses), label `Reach this machine from anywhere`, and a button
  labelled with `strings.setUp` ("Set up"). Clicking calls `requestSettingsSection('anywhere')`
  then `onOpenSettings()`. The label is a constant in the new component, not in `SetupStrings`
  (`SIMPLE_STRINGS` is `as const` and the row is advanced-only).
- **D15 — Docs.** `anywhere.mdx` has no "Getting started" section (it is the plans-and-pricing
  page). Add one between the epic paragraph (ends line 37) and `## Plans` (line 39). Also name the
  new entry points in `configuration/linked-machines.mdx` and `configuration/remote-access.mdx`.
- **D16 — CI test subset.** Each new frontend test file is added to
  `scripts/frontend-test-subset.txt` in sorted position by the item that creates it. The file is
  `merge=union`, so parallel items merge cleanly; no ordering edge is needed.

- **FR-2** The Machines row shows the number of online linked machines as a badge when that number
  is above 0 and the sidebar is expanded.
- **FR-3** The command palette lists seven actions in an **Anywhere** group: "Link a machine",

  "Set up Tailscale", "Open Anywhere settings".

  Settings → Anywhere button opens, over the current page.
- **FR-5** "Open Anywhere settings" shows the Settings tab scrolled to the Anywhere section.

  dialog.

   import { create } from 'zustand';

   export type AnywhereDialog =
     | 'link-machine'
     | 'add-fly-machine'
     | 'add-ssh-machine'
     | 'set-up-phone'
     | 'pair-device'
     | 'tailscale-setup';

   interface AnywhereDialogState {
     dialog: AnywhereDialog | null;
     openDialog: (dialog: AnywhereDialog) => void;
     close: () => void;
   }

   export const useAnywhereDialogStore = create<AnywhereDialogState>((set) => ({
     dialog: null,
     openDialog: (dialog) => set({ dialog }),
     close: () => set({ dialog: null }),
   }));

   export function openAnywhereDialog(dialog: AnywhereDialog): void {
     useAnywhereDialogStore.getState().openDialog(dialog);

2. Host:

   ```tsx
   export function AnywhereDialogHost() {
     const dialog = useAnywhereDialogStore((s) => s.dialog);
     const close = useAnywhereDialogStore((s) => s.close);
     const wantsTailscale = dialog === 'tailscale-setup';
     const { data: status, isError } = useQuery({
       queryKey: ANYWHERE_STATUS_QUERY_KEY,
       queryFn: loadAnywhereStatus,
       enabled: wantsTailscale,
     });
     const tailscaleAllowed = status?.viewer?.kind === 'root-session';
     useEffect(() => {
       if (!wantsTailscale) return;
       if (isError || (status && !tailscaleAllowed)) {
         toast.info('Tailscale can be set up only from a browser on this machine.');
         close();
       }
     }, [wantsTailscale, isError, status, tailscaleAllowed, close]);
     return (
       <>
         <LinkMachineDialog open={dialog === 'link-machine'} onClose={close} />
         <AddFlyMachineDialog open={dialog === 'add-fly-machine'} onClose={close} />
         <AddSshMachineDialog open={dialog === 'add-ssh-machine'} onClose={close} />
         <SetUpPhoneDialog open={dialog === 'set-up-phone'} onClose={close} />
         <PairDeviceDialog open={dialog === 'pair-device'} onClose={close} />
         <TailscaleSetupDialog
           open={wantsTailscale && tailscaleAllowed}
           onClose={close}
           onPair={() => openAnywhereDialog('pair-device')}
         />
       </>
     );
   }
   ```

## Planning Q&A

Auto planning mode (`pan plan --auto`): no questions were asked. Every choice a question would
have settled is recorded under Decisions (D1-D16) and in the xBRIEF `plan.autoDecisions[]`.
The main one: palette actions open the dialogs over the current page through a dialog host
(D1), following the repo's documented convention for dialogs opened from menus, instead of
navigating to Settings and opening the dialog there through a sessionStorage intent. The
intent approach needed a TTL for stale intents, two consumers sharing one intent, and late-mount
handling; the host approach needs none of that and leaves the Settings components untouched.
