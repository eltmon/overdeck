## 0. Glossary

- **Fork / fork clone.** `https://github.com/eltmon/gstack`; the work agent's checkout at `$HOME/Projects/gstack`. All gstack code changes land there, on branch `overdeck/pack-browser`, through a PR inside the fork. Never `garrytan/*`.
- **Render root `R`.** `~/.overdeck/packs/gstack/render/<commit>/` — PAN-4727's pack-mode output (`packRenderDir(id, commit)`, `src/lib/skill-packs/sources.ts`). Ready when `R/.gstack-pack.json` holds `packMode: 1`.
- **State root `S`.** `~/.overdeck/packs/gstack/state/` (`packStateDir(id)`).
- **Browser cache `C`.** New: `~/.overdeck/packs/gstack/browser/`, shared across commits. Holds `C/bun-cache/` (bun's package cache, `BUN_INSTALL_CACHE_DIR`) and `C/playwright/` (Chromium, `PLAYWRIGHT_BROWSERS_PATH`). Helper `packBrowserDir(id)` (new, `sources.ts`).
- **Browser runtime.** What the new fork step adds inside `R`: `R/node_modules/` (production deps), the compiled binaries `R/browse/dist/browse`, `R/browse/dist/find-browse`, `R/design/dist/design`, `R/make-pdf/dist/pdf`, `R/bin/gstack-global-discover`, `R/extension/lib/xterm*` (vendored), and Chromium in `C/playwright/`.
- **`$B` / `$D` / `$P`.** The browse, design and make-pdf binaries. Rendered skills resolve them to `R/browse/dist/browse`, `R/design/dist/design`, `R/make-pdf/dist/pdf` (fork `qa/sections/browser-setup.md:75-77`, `make-pdf/SKILL.md:48-51`; pack mode already rewrites `$HOME/.claude/skills/gstack` to `R`).
- **Pack-browser step.** New fork entry point: `bash setup --pack-browser <R> --pack-browser-cache <C>` (cwd = the extraction, like the render). Builds the browser runtime into an existing ready render.
- **Browser marker.** `R/.gstack-pack-browser.json` = `{"packBrowser":1,"browsersPath":"<C>/playwright","version":"<VERSION>"}`, written last by the pack-browser step. The browser runtime is **ready** only when it exists with `packBrowser: 1`.
- **Browsers-path marker.** `R/.gstack-pack-browsers-path`, one line: `<C>/playwright`. Read by the fork's pack env helper and by `bin/gstack-browser-ensure`, so no Overdeck launch env is needed.
- **Pack env helper.** New fork module `lib/pack-env.ts`: finds the pack root of the running code (from `import.meta.dir`, or from `process.execPath` inside a compiled binary) and, when it is a pack render, sets unset env vars `GSTACK_STATE_ROOT`, `PLAYWRIGHT_BROWSERS_PATH`, `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0`.
- **Pack-mode descriptor.** Fork `pack-mode.json`. Today `{"packMode": 1}`; this issue adds `"packBrowser": 1`. Overdeck refuses the browser step for a commit without it, before consent.
- **Browser classes.** New skill-map classes: `browser` (mounted with the pack toggle once the browser runtime is ready) and `browser-opt-in` (needs the browser runtime **and** a per-skill `on`). They replace PAN-4727's `needs-binary`.
- **Browser consent.** The second, separate consent: `pan skills pack browser gstack on` (or `pan skills pack add gstack … --browser`, which asks twice). Stored as `browser: true` in the registry entry `skills.packs.gstack`.
- **Browse daemon.** `$B` starts a background server (`bun run R/browse/src/server.ts`, fork `browse/src/cli.ts:793-797`) that keeps per-project state in `<project>/.gstack/` (`browse/src/config.ts:72-74`) and exits after 30 idle minutes (`BROWSE_IDLE_TIMEOUT`, `browse/src/server.ts:133`) or on `$B stop`.

## 1. Verdict

Add a second, separately consented step that builds gstack's browser runtime **inside the existing render `R`**, with bun's package cache and Chromium in `C = ~/.overdeck/packs/gstack/browser/`. The fork gets a `--pack-browser` entry point that runs `bun install --production --frozen-lockfile`, the five `bun build --compile` lines and `bun x playwright install chromium` directly — never `scripts/build.sh`, which would re-render every skill with the `~/.claude` install root — plus markers and an env helper so the compiled binaries, the daemon and `gstack-browser-ensure` find `S` and `C` with no launch env. Overdeck adds `pan skills pack browser <id> on|off`, an `add --browser` shortcut, rebuilds on `update`/`sync` when consent is recorded, and mounts the 18 browser-class skills only when the browser runtime is ready. Three skills that touch the operator's real browser data, open a visible browser writing `~/.gstack`, or open an internet tunnel stay excluded.

## 3. Decisions

- **D1 — Build inside `R`, caches in `C`.** The pack-browser step installs `node_modules` and compiles binaries into the ready render `R`, so the paths pack mode already wrote into the skills (`R/browse/dist/browse` etc.) just work. `C` holds the shared bun cache and Chromium. Both sit inside `packCacheDir('gstack')`, so `pan skills pack remove gstack` (which already deletes `packs/gstack/`) leaves nothing.
- **D2 — Never `scripts/build.sh`.** The step runs `bun run vendor:xterm`, the five `bun build --compile` lines from `build.sh` verbatim (flags `--no-compile-autoload-dotenv --no-compile-autoload-bunfig`), `chmod +x`, and writes `browse/dist/.version`, `design/dist/.version`, `make-pdf/dist/.version` from `R/VERSION` (R has no `.git`). It skips CSO, `browse/scripts/build-node-server.sh` (Windows only), fonts, and every skill-doc render.
- **D3 — Install exactly.** `bun install --production --frozen-lockfile` in `R` with `BUN_INSTALL_CACHE_DIR=C/bun-cache` and `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0`. No `--lockfile-only` fallback: a frozen-lockfile failure fails the step. Bun below `GSTACK_BUN_FLOOR` fails the step before any write (exit 1, `pack browser: bun <v> is below gstack's security floor <floor>`).
- **D4 — Chromium.** `PLAYWRIGHT_BROWSERS_PATH=C/playwright bun x playwright install chromium` from `R` (uses `R/node_modules/playwright`), with the Ubuntu 26.04 `PLAYWRIGHT_HOST_PLATFORM_OVERRIDE` rule copied from `bin/gstack-browser-ensure` and a timeout of `GSTACK_PLAYWRIGHT_INSTALL_TIMEOUT` (default 600 s). No `--with-deps`, no system packages, no fonts.
- **D5 — No launch env; markers.** Overdeck sets no gstack env at launch (PAN-4727 D2 and NonGoals stand). The fork's pack env helper (`lib/pack-env.ts`) runs first in the `browse`, `design` and `make-pdf` CLIs; it locates the pack root from `import.meta.dir` (source) or `process.execPath` (compiled: `R/<tool>/dist/<bin>` → `R`) and sets, only when unset: `GSTACK_STATE_ROOT` from `R/.gstack-pack-state-root`, `PLAYWRIGHT_BROWSERS_PATH` from `R/.gstack-pack-browsers-path`, and `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0`. The daemon inherits them (`cli.ts:797`). `bin/gstack-browser-ensure` applies the same two markers in bash.
- **D6 — Pack renders never self-install.** In a render (`R/.gstack-pack.json` present next to the script's root): `gstack-browser-ensure` never runs `bun install` or `playwright install`; when Playwright or Chromium is missing it fails with `BROWSER_UNAVAILABLE pack browser runtime not built` and fix `pan skills pack browser gstack on`. And a plain `./setup` (no `--pack-*` flag) run inside a render exits 2 with `setup: this is a host-managed pack render (<R>); the host installs it` before any write, so an agent following the `NEEDS_SETUP` text cannot do a full `~/.claude`/`~/.gstack` install.
- **D7 — Rewrite literal `~/.gstack` in rendered docs.** `scripts/pack-render.sh` gains one rewrite after the generator: in `R/*/SKILL.md` and `R/*/sections/*.md`, `~/.gstack/`, `$HOME/.gstack/` and `${HOME}/.gstack/` become `<S>/`. Binary-side: `design/src/auth.ts` `configPath` uses `resolveStateRoot()` (keys and `$D setup` go to `S`), and `browse/src/project-slug.ts` prefers `<pack root>/bin/gstack-slug` when the pack env helper finds a pack root. Headed mode's `~/.gstack/.auth.json` and ngrok's config reads stay (their skills are excluded, D9) and are listed under Limits.
- **D8 — Consent is stored, readiness is derived.** `browser: true` in `skills.packs.gstack` records the operator's consent (an operator decision, like the trusted commit). Readiness is derived from the browser marker in the trusted commit's render. Catalog/launch never build (PAN-4727 PD-4): consent recorded but runtime not ready ⇒ browser skills are not mounted and the launch warns `[launcher] WARNING: gstack browser runtime not built; run pan skills pack sync gstack`.
- **D9 — Classes (decision rule).** A skill that reads the operator's real browser data, opens a visible browser that writes `~/.gstack`, or exposes the browser through an internet tunnel ⇒ `excluded`. A skill that pushes, merges, deploys, or calls a paid model/image API ⇒ `browser-opt-in`. Everything else that calls `$B`/`$D`/`$P` ⇒ `browser`. Applied in §6. `canary` reads as monitoring-only in the fork, but the issue names it opt-in; the issue wins (autoDecision A3).
- **D10 — CLI shape.** New verb `pan skills pack browser <id> [on|off] [--yes]` (default `on`). `pan skills pack add <id> … --browser` runs the `on` flow right after a successful add, with its own preview and its own confirmation. `update` rebuilds the browser runtime for the new commit when consent is recorded (the browser preview rows join the update preview, one confirmation); `sync` builds it when consent is recorded and it is not ready. `update` keeps its early return for an unchanged commit.
- **D11 — `off` restores a plain render.** `pan skills pack browser gstack off` clears `browser` in the registry, deletes the trusted commit's `R` and renders it again with the existing offline pack render (so `R` is byte-identical in kind to a fresh add, without `node_modules` or binaries), and deletes `C`. Older commits' renders that still hold a browser runtime are left to `gc` (they are not the trusted commit).
- **D12 — Unsupported commit / no bun.** No `"packBrowser": 1` in the extraction's `pack-mode.json` ⇒ `PackSourceError('render', 'pack gstack: <sha7> has no browser step (pack-mode.json packBrowser); update to an eltmon/gstack commit with it')`, before the preview, nothing written. bun missing ⇒ the PAN-4727 D13 message.
- **D13 — Consent preview lists every download.** Rows: `Runs` (exact command), `Downloads` (one line per production dependency from the extraction's `package.json` `dependencies` as `name@spec`, then one line `+ their locked dependencies from bun.lock (registry.npmjs.org)`, then one line `Chromium and Chromium headless shell for playwright <spec> (Playwright CDN, ~115 MiB download)`), `Writes` (`R/node_modules`, the five binaries, `C/bun-cache`, `C/playwright`), `Size` (`about 1 GB on disk`). Never truncated.
- **D14 — Daemons are reported, never killed.** `remove` and `browser off` print, for each registered project whose `.gstack/browse.json` names a live pid, `Browse daemon still running in <project>: pid <n> — stop with: kill <n>` (it also exits by itself after 30 idle minutes). Consistent with PAN-4727 D9 and the "surfaced, never killed" invariant.
- **D15 — Fork delivery.** Branch `overdeck/pack-browser` from `origin/main` (`1b778f78`) in the fork clone; PR inside the fork only (`gh pr create --repo eltmon/gstack --base main --head overdeck/pack-browser`); never merged by the agent. Evidence goes in `.pan/drafts/PAN-4730-live-checkpoint.md` with `Item:` trailers on this branch.
- **D16 — Live acceptance runs isolated** (PAN-4727 D15 pattern), and is the only place the real install and Chromium download happen.
- **D17 — Version bumps.** `GSTACK_RENDER_VERSION` 2 → 3 (the mounted set changes meaning). `GSTACK_SKILL_MAP_VERIFIED_AT` moves to fork `1b778f78602ae4793f426164a9ff49fafbd83157` (same 63 dirs). New `GSTACK_PACK_BROWSER_VERSION = 1`.

## 5. Fork contract (pack browser, version 1)

```bash
# cwd = the trusted extraction (read-only); R and C absolute
bash setup --pack-browser /home/u/.overdeck/packs/gstack/render/<sha> --pack-browser-cache /home/u/.overdeck/packs/gstack/browser
```

Order inside `scripts/pack-browser.sh` (`set -euo pipefail`):
