## Glossary

- **Jev** — TypeSafe AI's "System One" judgment model (`jev-1.13`). It answers typed questions about a `state` and never generates text.
- **TypeSafe** — the vendor, TypeSafe AI (typesafe.ai). Not Typesafe/Lightbend.
- **SDK** — the npm package `@typesafe-ai/sdk`, pinned to exactly `0.6.0`. Its client class is `TypeSafeClient`; the call is `client.systemOne({ state, questions, model }, { signal })`.
- **Noul / Choice / Score** — the three SDK question types (`noul(...)`, `choice(...)`, `score(...)` helpers). A Noul answer is `{ type: 'noul', noul: <probability 0..1> }`.
- **Zen route** — calling Jev through OpenCode Zen: `jev.base_url: https://opencode.ai/zen`, an OpenCode Zen key, model `jev-1.13-free` or `jev-1.13`. The SDK posts to `<base_url>/v1/systemone`.
- **Direct route** — calling `https://api.typesafe.ai` (the SDK default) with a TypeSafe console key, model e.g. `jev-1.13.0`.
- **Background AI feature** — an entry in `src/lib/background-ai/registry.ts`. Every automatic model call is gated by `isBackgroundFeatureEnabled(feature)` (`src/lib/background-ai/features.ts`), which returns `false` when `background_ai.cheap_mode` is on (the default is **on**: `src/lib/config-yaml/defaults.ts`, `cheapMode: true`) or the feature toggle is off.
- **jev\* features** — the three new background AI features `jevTurnEndAssessment`, `jevAcceptanceCriteriaReview`, `jevMemoryRelevance`. All default **off**.
- **`assess()`** — the single public entry point of `src/lib/jev/`. It never throws and returns an `answered`, `unavailable` or `failed` result.
- **Memo** — an in-process LRU of `answered` results plus an in-flight dedupe map and a concurrency cap of 4, in `src/lib/jev/memo.ts`.
- **Question set version** — `QUESTION_SET_VERSION` in `src/lib/jev/questions.ts`. Bump it whenever any question text, criterion or threshold in that file changes, so memo entries built on old questions stop matching.
- **Disclosure surface** — the "What is sent to TypeSafe" section of `configuration/jev.mdx` plus the Settings description text of each jev\* toggle.
- **File-size guard** — `scripts/lint-file-size.sh` (part of `npm run lint`). A non-test `src/` file over 1000 lines may not grow past its `origin/main` count or its `scripts/file-size-allowlist.txt` cap (the **last** row for a path wins). Raising a cap is an operator decision; the pre-push hook refuses agent raises.

## Requirements

### Functional

- **FR-1** The root `package.json` depends on `@typesafe-ai/sdk` at exactly `0.6.0` (no `^`/`~`), and `bun.lock` records it.
- **FR-2** `assess(featureKey, state, questions, options)` returns `{ status: 'answered', answers, model, usage }`, `{ status: 'unavailable', reason }` or `{ status: 'failed', reason, message }`. It never rejects.
- **FR-3** Gate order inside `assess()`, first match wins, no network call for any of them: (1) `isBackgroundFeatureEnabled(featureKey)` false → `unavailable/disabled`; (2) no `jev:` block in any config layer → `unavailable/not-configured`; (3) `jev.model` unset or blank → `unavailable/model-not-configured`; (4) no API key resolved → `unavailable/no-api-key`.
- **FR-4** A `jev:` config block with `base_url?`, `model?`, `api_key_ref?` (default `TYPESAFE_API_KEY`), `timeout_ms` (default 2000) is parsed and normalized. `api_keys.typesafe` is a new key slot, with a `TYPESAFE_API_KEY` env fallback in `applyEnvironmentFallbacks`. Key resolution: `apiKeys.typesafe` first, else `process.env[jev.apiKeyRef]`.
- **FR-5** The model comes only from `jev.model`. Every request passes `model` explicitly and the client is built with `defaultModel` set to the same value, so the SDK's `TYPESAFE_DEFAULT_MODEL` / `jev-latest` default can never apply. `src/lib/jev/` (non-test files) contains no model id literal.
- **FR-6** SDK errors map to a closed `failed` reason set: 401/403 → `auth-failed`, 429 → `rate-limited`, timeout → `timeout`, caller abort → `aborted`, other connection failure → `connection-error`, 400/404/422 → `bad-request`, 5xx/529 → `server-error`, anything else → `error`.
- **FR-7** Identical `(featureKey, model, QUESTION_SET_VERSION, state, questions)` requests are served from the memo after the first `answered` result; concurrent identical requests share one in-flight request; at most 4 Jev requests run at once.
- **FR-8** Each real (non-memo) `answered` call records exactly one cost event through `recordBackgroundAiCost({ feature, provider: 'custom', model, usage })`, source `background:<featureKey>`.
- **FR-9** `DEFAULT_PRICING` has `jev-1.13` (input 0.000042/1k, output 0) and an exact `jev-1.13-free` row (0/0).
- **FR-10** The three jev\* features exist in the backend registry and in the Settings UI, all `defaultEnabled: false`, each with a description that names the data it will send to TypeSafe.
- **FR-11** Settings → Background AI has a TypeSafe API key input that reads and writes `api_keys.typesafe`, and the settings save path persists it.
- **FR-12** `evals/jev-smoke.eval.ts` runs a small labeled fixture set against live Jev when config resolves to a usable key and model, and is skipped (with the reason printed) otherwise.
- **FR-13** `configuration/jev.mdx` documents Jev, both routes, the config keys, the "What is sent to TypeSafe" section, and cost. It is in the Mintlify nav and the CLAUDE.md topic index.

### Non-functional

- **NFR-1** Off by default: with no `jev` block, or cheap mode on, or the jev\* toggle off, behavior is exactly today's. No startup check, no warning, no error.
- **NFR-2** The API key is never logged: the client is built with `logLevel: 'warn'` explicitly (this also overrides a `TYPESAFE_LOG_LEVEL=debug` env), and no Overdeck code logs the key or the request body.
- **NFR-3** No Effect façade around the Promise client (`npm run lint:effect-facades`). No `execSync`, no sync I/O on the request path.
- **NFR-4** `src/lib/config-yaml/schema.ts` grows by at most 4 lines (1092 → ≤ 1096, the allowlist cap). No allowlist edits.
- **NFR-5** Tests use a fake `fetch` injected through the SDK `fetch` option and `vi.useFakeTimers()` for the timeout case. No real network, no real `setTimeout` waits.
- **NFR-6** No test reads source text (`lint:source-introspection`). The "no model literal" check is a `grep` verify command, backed by runtime tests.

## Decisions (made here, not left to the implementer)

1. **Where `assess()` lives.** `src/lib/jev/client.ts` exports both `createJevClient()` (the thin SDK wrapper) and `assess()`. No `index.ts` barrel.
2. **Config shape.** A new pure module `src/lib/config-yaml/jev.ts` follows the `src/lib/config-yaml/ollama.ts` pattern: `YamlJevConfig`, `NormalizedJevConfig`, `DEFAULT_NORMALIZED_JEV`, `normalizeJevConfig(raw, current)`. It imports nothing from `src/lib/jev/` (keeps `lint:circular` green). Resolution with reasons lives in `src/lib/jev/config.ts`.
3. **"No block" is represented** by `NormalizedJevConfig.configured: false`. Any config layer whose `jev` value is a mapping (even `{}`) sets `configured: true`. A `null`/absent `jev` leaves it unchanged.
4. **Invalid values throw at config load**, matching `registry.classification` and `ollama` precedent in `merge.ts`: non-string `model`/`base_url`/`api_key_ref`, or `timeout_ms` that is not a positive integer ≤ 30000. A blank `model` string normalizes to `undefined` (then FR-3 step 3 applies).
5. **schema.ts line budget (NFR-4).** Use inline import types on the two `jev` fields so no import line is added (precedent: `src/lib/cloister/verification-runner.ts:506`, `src/lib/runtimes/kimi-code.ts:412`). Exactly 4 added lines, no doc comments on them.
6. **Retries off.** The client is built with `retry: { maxRetries: 0 }` and `timeout: jev.timeoutMs`. Callers schedule assessments off hot paths, so fail-fast beats SDK backoff; it also keeps the 429 test free of backoff timers.
7. **`baseURL`** is passed only when `jev.base_url` is set. Otherwise the SDK uses `TYPESAFE_BASE_URL` or `https://api.typesafe.ai`. (The base URL is not a model id; honoring the SDK env var is harmless.)
8. **`apiKey` is always passed explicitly** from the resolved key, so the SDK never reads `TYPESAFE_API_KEY` itself and never throws "missing key" from the constructor on the normal path.
9. **Memo key is a superset of the issue's key.** Issue: `(sha256(state), questionSetVersion, model)`. That collides when two consumers send the same state with different question maps. Key used: `` `${featureKey}:${model}:${QUESTION_SET_VERSION}:${sha256(JSON.stringify({ state, questions }))}` ``. Only `answered` results are cached (a transient 429 must not stick). LRU cap 256 entries, no TTL (the key is content-addressed). In-flight dedupe shares any result, including `failed`.
10. **Shared in-flight request uses the first caller's `signal`.** A later identical caller that joins the in-flight promise inherits its outcome, including `aborted`. Documented in the `memo.ts` header.
11. **Cost model name** is the model the response reports (`result.model`), falling back to the requested model when the response field is empty. Zen echoes `jev-1.13-free`; the direct API's `jev-1.13.0` prefix-matches the `jev-1.13` row.
12. **Settings key input lives in the Background AI section** (`BackgroundAiSection.tsx`), below the feature rows, as one password field labeled "TypeSafe API key (Jev)". There is no page literally named "API Keys"; provider keys live in `ProviderManagementSection`, but TypeSafe is not a model provider (it has no `ModelProvider` entry), so it does not belong there. The same slot holds either a direct TypeSafe key or an OpenCode Zen key.
13. **Toggle descriptions live in `src/dashboard/frontend/src/components/Settings/types.ts`** (`BACKGROUND_AI_FEATURE_META`), not in `settingsPageConstants.ts` as the issue text says. `settingsPageConstants.ts` holds only `BG_FEATURE_COST_SOURCE`, which needs the three new keys to typecheck. The backend `registry.ts` descriptions carry the same text. The "test on the constants" AC is met by a frontend test on `BACKGROUND_AI_FEATURE_META`.
14. **The legacy `src/lib/settings.ts`** (`settings.json` loader used only by `config-migration.ts`) is **not** touched. It has no `voyage` slot either.
15. **Eval model source.** The eval reads `jev.model` and the key through the same `resolveJevConfig()` as production (config wins; no eval-specific model env var, no literal). It calls `createJevClient()` + `client.systemOne()` directly, bypassing the feature toggle and cost recording, because the operator runs evals deliberately. It uses `evalite.skip` when resolution reports any unavailable reason other than `disabled`. (`evalite.skip` exists in evalite 0.19.0; the test-skip gate only scans `*.test.*`/`*.spec.*`, so `evals/*.eval.ts` is outside it.)
16. **`sync-sources/hooks/record-cost-event.js`** is a committed bundle that inlines the registry. It is not regenerated by `npm run build` and has no drift check (last touched by PAN-4002). Do **not** edit or regenerate it.

- **`src/lib/jev/client.ts`**

```ts
import { TypeSafeClient, type Fetch, type Questions, type EntryType, type SystemOneResult, type Usage } from '@typesafe-ai/sdk';

export type JevFailureReason = 'auth-failed' | 'rate-limited' | 'timeout' | 'aborted' | 'connection-error' | 'bad-request' | 'server-error' | 'error';
export type JevAssessment<Q extends Questions> =
  | { status: 'answered'; answers: SystemOneResult<Q>['answers']; model: string; usage: Usage }
  | { status: 'unavailable'; reason: JevUnavailableReason }
  | { status: 'failed'; reason: JevFailureReason; message: string };
export interface JevAssessOptions { signal?: AbortSignal; config?: JevConfigInput; fetch?: Fetch; env?: NodeJS.ProcessEnv }

export function createJevClient(resolved: ResolvedJevConfig, opts: { fetch?: Fetch } = {}): TypeSafeClient {
  return new TypeSafeClient({
    apiKey: resolved.apiKey,
    defaultModel: resolved.model,
    ...(resolved.baseUrl ? { baseURL: resolved.baseUrl } : {}),
    logLevel: 'warn',
    timeout: resolved.timeoutMs,
    retry: { maxRetries: 0 },
    ...(opts.fetch ? { fetch: opts.fetch } : {}),
  });
}

export async function assess<const Q extends Questions>(featureKey: JevFeature, state: EntryType, questions: Q, options: JevAssessOptions = {}): Promise<JevAssessment<Q>>;
```
  `assess()` steps:
  1. `const config = options.config ?? loadConfigSync().config;` then `resolveJevForFeature(featureKey, config, options.env)`. Not ok → return `{ status: 'unavailable', reason }`.
  2. `key = jevMemoKey({ featureKey, model, questionSetVersion: QUESTION_SET_VERSION, state, questions })`; memo hit → return it.
  3. `return dedupeInFlight(key, () => withJevSlot(async () => { ... }))` where the body wraps everything in `try/catch`:
     - `const result = await createJevClient(resolved, { fetch: options.fetch }).systemOne({ state, questions, model: resolved.model }, { signal: options.signal });`

## Hazards

- **schema.ts budget** is exactly 4 lines. A doc comment on any new field breaks `lint:file-size`.
- **Cheap mode defaults on**, so every non-`disabled` `assess()` test must pass `backgroundAi: { cheapMode: false, features: { ...defaultBackgroundAiFeatures(), <jevKey>: true } }`.
- **SDK reads env vars** (`TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL`, `TYPESAFE_DEFAULT_MODEL`, `TYPESAFE_LOG_LEVEL`). Always pass `apiKey`, `defaultModel`, `logLevel` explicitly; tests that depend on env use `vi.stubEnv` + `vi.unstubAllEnvs()`.
- **The SDK refuses to run in a browser-like global** (`window` + `document` + `navigator`). `src/lib/**` tests run in the root vitest `node` environment; do not put `client.test.ts` under a happy-dom environment.
- **Frontend `featureOn` defaults to `true`** when a key is missing (`BackgroundAiSection.tsx`, `?? true`). The GET payload fills every feature from `defaultBackgroundAiFeatures()` (`settings-api.ts:736`), so jev rows show off; do not change that default.
- **Settings save lists keys by hand** (`settings-api.ts:945`). Missing `typesafe` there would silently drop the key typed in the UI.
