## Glossary

| Term | Definition |
| --- | --- |
| **Share service** | The Cloudflare Worker in `services/share/` (`ShareRoom` Durable Object per room). It relays signaling and mints TURN credentials. It must never see content. |
| **Signaling traffic** | Everything a local Overdeck server exchanges with the share service: HTTP `POST /v1/rooms` and `DELETE /v1/rooms/:code`, and the JSON text frames on the host socket (`/v1/rooms/:code/host`) and the viewer join socket (`/v1/rooms/:code/join`). Frame types are listed in `docs/SHARED-SESSIONS.md` "WebSocket protocol". |
| **Content** | Conversation messages (history, append, update), the stream label (conversation title), prompt drafts, contributor submits, controller sends, and terminal bytes. Content may travel only on WebRTC DataChannels (NFR-1). |
| **Canary** | A unique random string planted in one kind of content (for example `PRIVACY-CANARY-DRAFT-<uuid>`). The privacy test proves each canary reaches its destination over a DataChannel and never appears in signaling traffic. |
| **Signaling capture** | The new test helper `SignalingCapture` (`tests/helpers/share/signaling-capture.ts`). It wraps the injected `openSocket`, `createRoom` and `deleteRoom` dependencies of `ShareManager` and `JoinManager`, and records every decoded frame and HTTP body in memory. |
| **Positive control** | An assertion that the planted content did arrive where it should. Without it, a "no canary in signaling" assertion passes even when no content flowed at all. |
| **Forced relay** | `iceTransportPolicy: 'relay'` on a peer connection: it gathers only TURN relay candidates, so every packet goes through the TURN server. Forcing it on both ends reproduces two peers behind symmetric NATs. |
| **Relay candidate** | An ICE candidate whose `typ` field is `relay` (for example `candidate:1 1 udp 2 1.2.3.4 50000 typ relay raddr …`). |
| **Operator checkpoint** | A step that needs operator-held secrets (here the Cloudflare Realtime TURN key). The work agent writes the test and the runbook; only the operator runs it. |
| **Miniflare** | The local workerd runtime the share integration tests use (`services/share/node_modules/miniflare`, pinned `5.20261001.0-alpha`). |
| **LoopbackViewer** | `src/dashboard/server/sharing/__tests__/loopback-viewer.ts`, a werift stand-in for the browser viewer, used by the integration tests. |
| **AC sweep** | Re-checking every PAN-658 acceptance criterion against named, existing tests and recording the evidence in `docs/SHARED-SESSIONS.md`. |

## Problem

Shared Sessions v0 is fully merged. Two security claims in the PAN-658 PRD still have no proof:

1. **NFR-1 / AC-17 — the share service never sees content.** Today the only evidence is structural: `services/share/src/protocol.ts` rebuilds frames from known keys, and `tests/integration/services/share/peer-hub.test.ts` asserts a lobby viewer gets no `signal` frame. No test plants content and checks the signaling traffic for it.
2. **NFR-7 / AC-15 — sessions work through symmetric NATs via Cloudflare Realtime TURN.** Today `tests/unit/services/share/turn.test.ts` covers the credential request and `src/dashboard/server/sharing/__tests__/peer-hub.test.ts` ("passes TURN credentials through to the peer connection") covers the hand-off to werift. Nothing forces relay-only ICE against a real TURN server.

The rev-2 WI-12 also asks for rate-limit verification and a full acceptance-criteria sweep. The room-creation rate limit (10 per 60 s per GitHub id) is tested only with a stub limiter in `tests/unit/services/share/routes.test.ts` ("a refused rate limit is 429 rate_limited with Retry-After: 60, keyed by githubId"). No test checks the committed binding in `services/share/wrangler.jsonc`.

## Goal

- A CI-run integration test that plants a canary in every content kind, proves each canary arrives over a DataChannel, and proves no canary and no unknown frame or key appears in any signaling traffic.
- An operator-run forced-relay test through real Cloudflare Realtime TURN, with relay forced on both peers.
- A CI-run test that the committed rate-limit binding returns 429 on the 11th room creation in a minute on real workerd.
- An acceptance sweep table in `docs/SHARED-SESSIONS.md`, with one follow-up issue for the one real product gap the sweep found (AC-7, see *Acceptance sweep*).

## Requirements

- **FR-1** A signaling-privacy integration test runs in the default vitest run (CI). It drives one share through lobby, admission as contributor, history, a live append, a viewer draft, a contributor submit, a host controller send, a viewer-controller send, and the read-only terminal, with a second viewer kept in the lobby throughout.
- **FR-2** The privacy test records all signaling traffic of both local servers as decoded text (never raw TCP bytes) and asserts: every canary reached its destination; no canary appears in any recorded frame or HTTP body, in plain, case-folded or base64 form; every frame's `type` and keys belong to the documented protocol for its socket and direction; no binary frame crossed.
- **FR-3** The privacy test proves the capture sat on the live path: it recorded at least one SDP offer from the host, one SDP answer from the viewer, one ICE candidate in each direction, one `room` snapshot, the `POST /v1/rooms` request and the `DELETE /v1/rooms/:code` request.
- **FR-4** The lobby viewer receives exactly one frame (`status lobby`) on its join socket while the admitted viewer receives all content, and its socket closes with 4004 when the share ends (AC-4 end-to-end).
- **FR-5** A forced-relay test forces `iceTransportPolicy: 'relay'` on the host's werift peer (through the `createPeerConnection` seam) and on the viewer, gets real TURN credentials from Cloudflare through the share Worker, and asserts the conversation history arrives and every ICE candidate either side sent is a relay candidate.
- **FR-6** The forced-relay test is opt-in (`*.slow.test.ts`) and fails with a named precondition error when `TURN_KEY_ID` or `TURN_KEY_API_TOKEN` is missing. It never skips and never prints a TURN credential.
- **FR-7** A rate-limit integration test reads the `ROOM_CREATE_LIMIT` entry from `services/share/wrangler.jsonc`, binds it in Miniflare, and asserts 10 room creations return 201, the 11th returns 429 `rate_limited` with `Retry-After: 60`, and another GitHub id still gets 201.
- **FR-8** `docs/SHARED-SESSIONS.md` gains a *Verification* section (privacy test, forced-relay runbook, rate-limit test) and an *Acceptance sweep* table covering AC-1…AC-20 and NFR-1…NFR-9. `configuration/shared-sessions.mdx` gains a short *Networks and privacy* section.
- **FR-9** The AC-7 gap (a plain viewer does not see every participant) is filed as a GitHub issue and linked from the sweep table.
- **NFR-1** No test sleeps. Every wait resolves on an event or `vi.waitFor`. Integration tests use real timers because real sockets and real UDP are involved; nothing calls `setTimeout` to wait.
- **NFR-2** No production code changes. Every instrument goes through an existing injected seam (`ShareManagerDeps`, `JoinManagerDeps`, `PeerHubDeps`). If the privacy test finds a real leak, the decision rule in WI-3 applies.
- **NFR-3** Captured traffic stays in memory. No test writes captured frames or ICE credentials to disk, and no assertion message contains a TURN `username` or `credential`.
- **NFR-4** No agent runs anything against Cloudflare: no `wrangler deploy`, `wrangler secret put`, `wrangler login`, and no forced-relay run. The forced-relay run is an operator checkpoint.

## Decisions

- **D-1 Capture at the message layer, by wrapping the injected seams.** `ShareManagerDeps.openSocket`, `JoinManagerDeps.openSocket`, `ShareManagerDeps.createRoom` and `ShareManagerDeps.deleteRoom` are the only paths from a local server to the share service. (`src/dashboard/server/services/share-join.ts` makes no HTTP call; `git grep -n "fetch(" src/dashboard/server/services/share-join.ts` finds nothing.) Wrapping them records decoded text with no network change. Rejected: (a) reusing `startProxy` from `tests/helpers/anywhere/two-dashboards.ts`, a raw TCP byte logger. RFC 6455 masks every client-to-server frame with a random XOR key, and `ws` may negotiate permessage-deflate, so a canary sent by the host or the viewer never appears in raw bytes. That assertion would pass vacuously. (b) A WebSocket-terminating proxy. It works, but needs upgrade-refusal and close-code forwarding and its own tests, for no extra coverage in this topology.
- **D-2 "e2e" means real workerd plus real werift, in the default run.** The test uses the `join-manager.test.ts` topology: a real `ShareManager` with a real `PeerHub` on werift, and a real `JoinManager` with a `LoopbackViewer`, both talking to the bundled share Worker in Miniflare. The browser never talks to the share service in the dashboard path (parent D-R3-2), and `src/dashboard/frontend/tests/pan-4475-shared-viewer.spec.ts` is excluded from `test:playwright` (PAN-4475 D-20). A Playwright variant is a non-goal.
- **D-3 Canaries plus structure.** A canary scan alone only catches the exact strings we planted. The structural check (type and key allow-lists per socket and direction, `signal.data` keys ⊆ `{sdp, candidate}`, `room.snapshot` keys ⊆ `RoomSnapshot`) catches a new field that smuggles any content. Both run.
- **D-4 A shared Miniflare harness for the new tests only.** The five existing integration tests copy their Miniflare bootstrap by convention ("not imported: that file owns its own lifecycle"). Three new tests need it, so it moves into `tests/helpers/share/share-worker.ts`. The five existing files are not touched.
- **D-5 Forced relay is an operator checkpoint, with no local TURN server.** The issue scopes it so. werift ships no TURN server (`node_modules/werift/lib/ice-server/src/turn/` holds frame and auth helpers only), and adding a TURN server dependency for CI is out of scope. CI covers the pieces around it: the relay-candidate classifier has unit tests, and the test file's precondition failure is checked.
- **D-6 Relay forced on both ends.** One forced end already routes media through TURN, but both ends forced is the faithful model of two symmetric NATs. The host is forced through the `PeerHubDeps.createPeerConnection` seam. The viewer is forced with a new optional `LoopbackViewer` constructor argument. Its ICE servers come from `JoinManager.iceServers(code)`, the same path the browser viewer uses (`POST /api/joins/:code/ice-servers`, `src/dashboard/server/routes/joins.ts` line 8).
- **D-7 Relay is proven from the candidates, not from `getStats()`.** werift's stats API is not relied on. If every candidate both sides signaled is `typ relay`, at least one exists on each side, and content arrives, then the nominated pair is relay-to-relay. Candidates are read from `signal` frames and from `a=candidate:` lines inside each SDP.
- **D-8 The rate-limit test binds the committed config.** It parses `services/share/wrangler.jsonc` with `jsonc-parser` (a root dependency, `package.json` line 198), so a change to the committed limit is caught. Probe at plan time (2026-11-03): with `ROOM_CREATE_LIMIT: { type: 'rate-limit', namespace: '1001', simple: { limit: 10, period: 60 } }` in `workers[0].config.env`, the bundled Worker answered `201 ×10, 429 (Retry-After: 60)` for one GitHub id and `201` for another. The keys `type: 'ratelimit'` and `namespace_id` are rejected with `ERR_VALIDATION`.
- **D-9 The sweep fixes nothing in product code.** It records evidence. A behavior gap becomes a GitHub issue that goes through its own pipeline with full review, test and UAT. Missing tests for already-shipped behavior are added only where this PRD names them (WI-3, WI-6, WI-7).
- **D-10 The forced-relay test passes the Worker's ICE list unchanged.** werift 0.25.1 uses only the first TURN URL it finds (`src/lib/anywhere/channel/relay-ice-servers.ts`, header comment). The test keeps production behavior. If the operator run fails because the network blocks the first TURN transport, that is a real finding: the operator files an issue to order the hub's TURN URLs (as PAN-4862 did for Anywhere) and the checkpoint is re-run after it lands.

### WI-2 — Signaling capture and leak checks

*Traces: FR-2, FR-3, NFR-3.* New file `tests/helpers/share/signaling-capture.ts`, plus `tests/helpers/share/__tests__/signaling-capture.test.ts`.

```ts
export type SocketRole = 'host' | 'viewer';
export type Direction = 'to-service' | 'from-service';

export type CaptureEntry =
  | { readonly kind: 'ws-text'; readonly role: SocketRole; readonly label: string; readonly direction: Direction; readonly text: string }
  | { readonly kind: 'ws-binary'; readonly role: SocketRole; readonly label: string; readonly direction: Direction; readonly bytes: number }
  | { readonly kind: 'ws-close'; readonly role: SocketRole; readonly label: string; readonly code: number }
  | { readonly kind: 'http'; readonly method: string; readonly path: string; readonly status: number; readonly requestBody: string; readonly responseBody: string };

export class SignalingCapture {
  readonly entries: CaptureEntry[];
  /** Wraps `open` (normally `defaultOpenSocket`): records every `send(text)` and every `message` and `close` event. */
  openSocket(role: SocketRole, label: string, open: ShareManagerDeps['openSocket']): ShareManagerDeps['openSocket'];
  /** `createRoom` / `deleteRoom` with a recording `fetch` passed through their `opts.fetch` parameter. */
  readonly createRoom: typeof createRoom;
  readonly deleteRoom: typeof deleteRoom;
  /** Inbound text frames on one socket label, in order (for the lobby viewer assertion). */
  framesFor(label: string, direction: Direction): unknown[];
}

export interface Leak { readonly canary: string; readonly form: 'plain' | 'case-folded' | 'base64'; readonly where: string }
export function findLeaks(entries: readonly CaptureEntry[], canaries: readonly string[]): Leak[];

export interface FrameViolation { readonly where: string; readonly problem: string }
export function frameViolations(entries: readonly CaptureEntry[]): FrameViolation[];

export interface CaptureSummary { offers: number; answers: number; hostCandidates: number; viewerCandidates: number; roomSnapshots: number; posts: number; deletes: number }
export function summarize(entries: readonly CaptureEntry[]): CaptureSummary;
```

Rules:

- **Socket wrapping.** `openSocket(role, label, open)` returns `(url, headers) => { const socket = open(url, headers); … return socket; }`. It replaces `socket.send` with a function that records `{ kind: 'ws-text', direction: 'to-service', text }` and then calls the original. It adds `socket.on('message', (data, isBinary) => …)` that records `ws-binary` with the byte length when `isBinary` is true, and otherwise `ws-text` `from-service` with `data.toString('utf8')` (for a `Buffer[]` use `Buffer.concat`). It adds `socket.on('close', (code) => …)`. It never changes what the socket does.
- **HTTP wrapping.** `createRoom` is `(base, token, scope) => createRoom(base, token, scope, { fetch: recordingFetch })`, and `deleteRoom` the same. `recordingFetch(url, init)` calls the global `fetch`, records the method, the URL path, the status, `String(init?.body ?? '')` and the response text read from `res.clone().text()`, then returns the original response.
- **`findLeaks`.** It scans the `text` of every `ws-text` entry, and `requestBody` and `responseBody` of every `http` entry. For each canary it checks: `plain` (`includes`); `case-folded` (both lowercased); `base64` (for offsets 0, 1 and 2, take `Buffer.from('x'.repeat(offset) + canary).toString('base64')`, drop the first 4 characters when `offset > 0` and the last 4 characters always, and check `includes` of what remains, provided it is at least 8 characters). `where` names the entry index, role, label and direction. It never puts the scanned text in `where`.
- **`frameViolations`.** Every `ws-binary` entry is a violation. Every `ws-text` entry must be JSON with a string `type`, except the exact texts `ping` (viewer, `to-service`) and `pong` (viewer, `from-service`) used by the hosted web viewer (PAN-4481). Allowed types and their exact top-level key sets, per role and direction (from `packages/contracts/src/sharing.ts` lines 48–79):

  | Role, direction | Type → allowed keys |
  | --- | --- |
  | host, to-service | `admit` → type, githubId, contributor · `kick` / `revoke` / `unrevoke` / `set-controller` → type, githubId · `set-contributor` → type, githubId, contributor · `signal` → type, githubId, data · `ice-servers` → type · `end` → type |
  | host, from-service | `room` → type, snapshot · `signal` → type, githubId, data · `ice-servers` → type, iceServers · `error` → type, code, githubId |
  | viewer, to-service | `signal` → type, data · `ice-servers` → type · `leave` → type |
  | viewer, from-service | `status` → type, status, contributor · `signal` → type, data · `ice-servers` → type, iceServers · `error` → type, code |

  A key outside the set is a violation; a missing optional key is fine. For every `signal`: `data` keys ⊆ `{sdp, candidate}`; `sdp` keys ⊆ `{type, sdp}` with `type` `offer` or `answer`; `candidate` keys ⊆ `{candidate, sdpMid, sdpMLineIndex}`. For every `room`: `snapshot` keys ⊆ `{shortCode, scope, dataOwner, controllerGithubId, hostConnected, participants, blocked}`, and `scope` keys ⊆ `{kind, conversationId}`. A `problem` names the type and the offending key, never a value.
- **`summarize`** counts host `signal` frames to the service with `data.sdp.type === 'offer'`, viewer `signal` frames to the service with `answer`, `signal` frames carrying `data.candidate` per role (to the service), `room` frames, and `http` entries with `POST` and `DELETE`.

Tests, `tests/helpers/share/__tests__/signaling-capture.test.ts` (no network; a fake socket is a Node `EventEmitter` with a `send` method that records calls):

- "records sends and messages in both directions without changing the socket": the wrapped socket's original `send` still receives the text; an emitted `message` (`Buffer`, `isBinary: false`) is recorded `from-service`; an emitted binary message is recorded as `ws-binary`; `close` 4004 is recorded.
- "findLeaks reports a planted canary in plain, case-folded and base64 form, and nothing for clean traffic": entries with `{"type":"signal","data":{"sdp":{"type":"offer","sdp":"…CANARY…"}}}` (plain), the lowercased canary (case-folded) and `Buffer.from('ab' + canary).toString('base64')` (base64, offset 2) are each found; a clean entry set returns `[]`.
- "frameViolations accepts every documented frame and rejects unknown types, extra keys and binary": one valid frame of every type in the table returns `[]`; `{"type":"chat","text":"x"}`, a `signal` with `data.content`, a `room` snapshot with an extra `messages` key, a viewer `admit`, non-JSON `hello`, and a `ws-binary` entry each give exactly one violation.
- "summarize counts offers, answers, candidates, snapshots and HTTP calls".
