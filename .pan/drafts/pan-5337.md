# PAN-5337 — Relative links in a Markdown file preview open the linked file in the dashboard

**Issue:** [PAN-5337](https://github.com/eltmon/overdeck/issues/5337)
**Status:** planned (auto planning, 2026-11-15, base `c9906c2370a`)

## Glossary

- **Markdown preview** — the rendered view of a Markdown document. It is `MarkdownTab` (`src/dashboard/frontend/src/components/CommandDeck/ZoneCOverviewTabs/MarkdownTab.tsx`), which renders `ChatMarkdown`. Four callers mount it: the code pane's Preview view, the editor pane's Preview tab, the Docs pane and the cockpit's PRD/STATE dig tabs.
- **Code pane** — a Stage tab with `paneType: 'code'` that shows one file of an explorer root (`components/explorer/code/CodePane.tsx`). It holds `rootId` and a root-relative `path`.
- **Editor pane** — a Stage tab with `paneType: 'editor'` that edits one Markdown file by absolute path (`components/Stage/panes/EditorPane.tsx`). A chat file chip on a `.md` file opens this pane (`MarkdownFileLink.tsx`, `deck.openOrFocusEditorPane(filePath, …)`). **This is the operator's repro path.**
- **Explorer root** — a folder the file explorer serves. Its id is `project:<key>` (primary checkout), `issue:<ID>` (feature workspace) or `workspace:<id>` (edit workspace). Explorer paths are root-relative POSIX paths with no leading `/`, no `.`/`..` segments and no empty segments; `""` is the root (`packages/contracts/src/explorer.ts` header).
- **Document location** — the explorer root and root-relative path of the file a preview shows: `{ rootId, path }`. A preview has one when it shows a file in an explorer root. The Docs pane and the dig tabs have none: the planning response (`PlanningResponse` in `components/CommandDeck/ZoneCOverviewTabs/queries.ts`) carries the PRD text, not its path.
- **Document-relative href** — an href with no URL scheme that does not start with `/`, `//` or `#`. Examples: `fort3d.md`, `reviews/x.md`, `levels/`, `../a.md`, `./b.md:12`, `~/x.md`, `?q`. Anything else is **absolute** (`https://…`, `mailto:…`, `/conv/123`, `/home/u/f.ts`) or a **fragment** (`#heading`).
- **Inert link** — link text rendered as a plain `<span>` with no `href` and no click handler.
- **openBeside** — the Stage deck call (`StageDeckContext.openBeside`, implemented in `components/Stage/index.tsx`, search `const openBeside = useCallback`) that the Files tree uses to open a file: `deck.openBeside({ rootId, path, line, preview })` (`components/explorer/ExplorerPane.tsx`, search `if (deck?.openBeside) deck.openBeside(`). A single click in the tree passes `preview: true` (search `openFile({ rootId, path, preview: true })`).
- **Heading slug** — the id-like string a `#heading` fragment names, computed from the heading's text (rule in WI-2).

## Problem

Clicking any relative link in a Markdown preview opens a browser tab on a dashboard URL that does not exist. The operator opened `~/Projects/dfai/docs/index.md` from a chat file chip in conversation 3904, switched to **Preview** and clicked `fort3d.md`. The browser opened `https://overdeck.localhost/conv/fort3d.md`, which returns HTTP 404 `Not Found`. All 93 links in that preview are relative and none works.

### Cause (verified at `c9906c2370a`)

1. `MarkdownTab.tsx` line 43 renders `<ChatMarkdown text={body} cwd={undefined} />`. It takes only `body` and never learns which file the text came from.
2. `resolveMarkdownFileLinkTarget` in `src/dashboard/frontend/src/markdown-links.ts` returns `null` for a relative path when there is no `cwd` (search `if (!cwd) return null;`).
3. `makeComponents().a` in `src/dashboard/frontend/src/components/chat/ChatMarkdown.tsx` (line 396, search `a({ href, children }`) then falls through to line 417, `return <TranscriptLink href={safeHref} className={styles.mdLink}>{children}</TranscriptLink>;`. `TranscriptLink` (`components/chat/TranscriptPullRequestLink.tsx`) renders `<a href={href} target="_blank">`. The browser resolves the relative href against `/conv/3904`.

Callers (all four have the fault):

| Caller | File | Line | Knows the file? |
| --- | --- | --- | --- |
| Code pane Preview | `components/explorer/code/CodePane.tsx` | 302 `<MarkdownTab body={text ?? result.text ?? ''} />` | yes: `rootId`, `path` |
| Editor pane Preview | `components/Stage/panes/EditorPane.tsx` | 236 `<MarkdownTab body={draft} />` | yes: absolute `filePath` |
| Docs pane | `components/Stage/panes/DocsPane.tsx` | 58 | no |
| Cockpit dig tabs | `components/Stage/cockpit/IssueDigTabs.tsx` | 37 | no |

The same fall-through also hits chat transcripts: a relative href that is not path-shaped (for example `levels/`, or any relative link when the conversation has no `cwd`) reaches `TranscriptLink` and opens a 404 tab.

## Decisions

- **D1 — No `cwd` for previews.** Passing `cwd` would turn relative links into chat file chips (`MaybeFileLinkChip`), run `remarkBareFileTextLinks` over the prose (bare words like `notes.md` become chips), and fire one `resolveFilePathExists` RPC per token. The path regexes in `markdown-links.ts` also reject `levels/` and names with spaces, so those would still reach `TranscriptLink`. Instead, `ChatMarkdown` gets a new optional prop `docLocation?: { rootId: string; path: string }`, and a total classifier decides every href (WI-1).
- **D2 — The editor pane maps its absolute path to an explorer root on the client.** A new pure function `explorerLocationForPath(absPath, ctx)` in `components/explorer/rootForConversation.ts` reuses the existing rules 4 and 5 of `rootIdForConversation` (feature workspace under `<project.path>/workspaces/feature-<slug>` → `issue:<SLUG>`; otherwise the longest registered project path → `project:<key>`). It returns `{ rootId, path }` with the root-relative path, or `null`. When it returns `null` (a file outside every registered project, for example under `~/.overdeck`), the editor pane passes no document location and its relative links are inert. No new server route or RPC.
- **D3 — Open the target the way the Files tree's single click does:** `deck.openBeside({ rootId, path, line, preview: true })`. When `deck.openBeside` is absent, call `openCodePane(deck.deckKey, { rootId, path, line, preview: true })`. When there is no deck (`useStageDeck()` is `null`), the link is inert. `preview: true` reuses the root's one preview pane, so reading through 93 links does not add 93 tabs.
- **D4 — A Markdown target opens the way the Files tree opens it (Edit view).** Opening a Markdown target in Preview needs a new pane field and touches six more files (`panesStore.ts`, `openCodePane.ts`, `StageDeckContext.tsx`, `Stage/index.tsx`, two tests). That would push this plan past the 25-file limit and into PAN-5290's lines, and it must not apply when the link carries a line (the line reveal runs only once Monaco mounts). It is split out to [PAN-5340](https://github.com/eltmon/overdeck/issues/5340). This plan passes no `view`.
- **D5 — Existence is checked eagerly with `listDir` on the target's parent folder.** `listDir(rootId, parentDir)` (`components/explorer/explorer-rpc.ts`) returns the folder's entries with `kind: 'file' | 'dir' | 'symlink'`. A module-level cache keyed by `rootId + '\0' + parentDir` holds the in-flight or settled promise for 10 seconds, so a preview with 93 links in 6 folders sends 6 requests. A `listDir` error (including `NOT_FOUND`) means "missing". A `truncated: true` listing that does not contain the name means "unknown", which renders as a clickable file link (the code pane then shows its own "This file no longer exists." placeholder).
- **D6 — Folder links reveal the folder in the Files dock.** Click: if `useActiveDock.getState().current` is this deck's dock and its `rootId` differs from the link's root, call `useWorkDockStore.getState().setRootOverride(deckKey, rootId, activePaneId)` first (the pattern of `WorkDock.tsx` `revealFile`). Then call `deck.openDock({ tab: 'files', reveal: { rootId, path } })`. `explorerStore.revealPath` expands the folder's ancestors and selects it. When `deck.openDock` is absent, the folder link is inert.
- **D7 — Fragment links scroll inside the preview, never through the URL.** Headings in a preview with a document location get a `data-heading-slug` attribute. A `#slug` click calls `event.preventDefault()`, finds `[data-heading-slug="<slug>"]` inside the closest `[data-testid="markdown-tab"]` element and calls `scrollIntoView({ block: 'start' })`. It never writes `location.hash` and never changes the page URL. A fragment with no matching heading does nothing. In a preview without a document location, and in chat, headings get no attribute and fragment links keep today's behaviour.
- **D8 — `other.md#heading` opens `other.md` and ignores the heading,** except `#L<n>` or `#L<n>C<m>`, which set the line (and column), as `appendLineColumnFromHash` does today for chat links. A `:<line>[:<col>]` suffix also sets the line.
- **D9 — The chat guard.** In every `ChatMarkdown`, a document-relative href that no earlier branch handled renders as an inert link. Root-relative hrefs (`/conv/123`, `/issues/PAN-1`) count as absolute and keep today's `TranscriptLink` behaviour, so dashboard links in transcripts still work. Absolute filesystem paths keep today's file-chip behaviour.
- **D10 — No document location means inert relative links.** The Docs pane and the dig tabs pass no location. Their relative links render inert. Exposing the PRD's real path from the server is out of scope.
- **D11 — File previews use the ReactMarkdown renderer.** `MarkdownTab` passes `useStreamdown={false}` when it has a document location. The experimental Streamdown renderer runs rehype-sanitize and rehype-harden before the `a` component, which could strip `data-heading-slug` or rewrite relative hrefs. Chat keeps the setting.
- **D12 — Missing and outside-root links look different from working links.** They render as a `<span>` with `data-doc-link-state="missing"` (or `"outside"`), muted text, a dashed underline (`text-muted-foreground underline decoration-dashed`), `aria-disabled="true"` and `title="Link target not found: <root-relative path or href>"`. No `href`, no click handler. Use Tailwind classes; do not add rules to `components/CommandDeck/styles/command-deck.module.css` (6,515 lines, far over the 1,000-line file-size ceiling).
- **D13 — PAN-5290 is not a dependency.** `openBeside` and `openDock` are already on `main` (PAN-5287). PAN-5290 (open, in planning) edits `CodePane.tsx` (`onOpenRenamed`, the editor bar) and `Stage/index.tsx`; this issue touches different lines of both. Rebase conflicts, if any, are textual.

## Requirements

- **FR-1** In a code pane Preview, a document-relative link resolves against the file's folder inside the same explorer root: `fort3d.md` in `docs/index.md` resolves to `docs/fort3d.md`; `../a.md` in `docs/x/y.md` resolves to `docs/a.md`.
- **FR-2** Clicking a resolved file link opens it through `openBeside` with the same `rootId`, the resolved path and `preview: true`. It opens no browser tab and does not change the page URL.
- **FR-3** Clicking a resolved folder link (`levels/`, or `levels` when the entry is a folder) reveals that folder in the Files dock.
- **FR-4** A `#heading` link scrolls the preview to the heading with that slug. `other.md#heading` opens `other.md`.
- **FR-5** A `:line[:col]` suffix or `#L<n>[C<m>]` fragment opens the file at that line.
- **FR-6** `http:`, `https:` and other scheme links still render through `TranscriptLink` and open in a new tab.
- **FR-7** A link whose target is missing, or whose normalized path leaves the root, opens nothing and renders the not-found state (D12).
- **FR-8** A preview with no document location never renders a document-relative href as a browser link; it renders inert text.
- **FR-9** The editor pane Preview resolves links the same way as the code pane when its absolute path is inside a registered project (D2). The operator's repro (chat chip → editor pane → Preview → `fort3d.md`) opens `docs/fort3d.md` in a code pane.
- **FR-10** *(retired — moved to [PAN-5340](https://github.com/eltmon/overdeck/issues/5340))*.
- **FR-11** In chat, `TranscriptLink` never receives a document-relative href (D9).
- **NFR-1** No new server route, RPC or contract schema. Existence checks use `listDir`, at most one request per (root, folder) per 10 seconds.
- **NFR-2** No new npm dependency (no `github-slugger`, no `rehype-slug`).
- **NFR-3** No file grows past its file-size limit (`scripts/lint-file-size.sh`; 1,000-line ceiling, measured against `origin/main`). New logic goes in new modules.
- **NFR-4** Tests are render or unit tests that exercise behaviour. Source-grep tests fail lint in this repo, and any added `skipIf`/`.only` fails the test-skip gate.

## Work items

### WI-1 — The href classifier and path resolver (pure)

New file `src/dashboard/frontend/src/lib/markdownDocLinks.ts`, test `src/dashboard/frontend/src/lib/__tests__/markdownDocLinks.test.ts`. No React.

```ts
export type DocHref =
  | { kind: 'empty' }
  | { kind: 'fragment'; slug: string }            // '#Install' → slug 'Install' (decoded, not lowercased)
  | { kind: 'absolute' }                          // scheme, '//', or leading '/'
  | { kind: 'relative'; path: string; line?: number; column?: number; trailingSlash: boolean }

export function classifyDocHref(href: string | undefined): DocHref
export function isDocumentRelativeHref(href: string | undefined): boolean // classifyDocHref(href).kind === 'relative'
export type ResolvedDocPath = { kind: 'inside'; path: string } | { kind: 'outside' }
export function resolveDocPath(fromDir: string, relPath: string): ResolvedDocPath
export function docDirOf(path: string): string     // 'docs/index.md' → 'docs'; 'README.md' → ''
```

Rules for `classifyDocHref`:
1. Trim; unwrap `<…>`. Empty → `empty`.
2. Starts with `#` → `fragment` with `safeDecode(rest)`.
3. Starts with `/` → `absolute`. A Windows drive path (`/^[A-Za-z]:[\\/]/`) → `absolute`. Matches `/^([A-Za-z][A-Za-z0-9+.-]*):(.*)$/` → `absolute`, **except** when the remainder after the first `:` is only a position (`/^\d+(?::\d+)?$/`): `fort3d.md:12` and `fort3d.md:12:3` are relative files with a line, not schemes. This is the same exception `hasExternalScheme` makes in `markdown-links.ts`.
4. Otherwise `relative`: drop `?query`; split off `#hash`; `safeDecode` the path; record `trailingSlash = path.endsWith('/')`; strip a `:line[:col]` suffix (`/:(\d+)(?::(\d+))?$/`); if no suffix and the hash matches `/^L(\d+)(?:C(\d+))?$/i`, take line/column from it; any other hash is dropped (D8). `~/x` is `relative` (it can never resolve in a root, so `resolveDocPath` returns `outside` for a leading `~` segment).

Rules for `resolveDocPath(fromDir, relPath)`: split `fromDir` and `relPath` on `/`; skip empty and `.` segments; `..` pops one segment and returns `{ kind: 'outside' }` when there is nothing to pop; a `~` first segment returns `outside`. Join with `/`. `resolveDocPath('docs', 'levels/')` → `{ kind: 'inside', path: 'docs/levels' }`; `resolveDocPath('docs', '../')` → `{ kind: 'inside', path: '' }` (the root).

Tests (named): `classifies fort3d.md as relative`, `classifies fort3d.md:12 as relative with line 12`, `classifies https and mailto as absolute`, `classifies /conv/123 as absolute`, `classifies #h as fragment`, `splits x.md#h into path x.md with no line`, `reads x.md:12:3 and x.md#L12C3 as line 12 column 3`, `keeps the trailing slash flag on levels/`, `decodes %20 in a path`, `resolves a sibling`, `resolves ../x.md upward`, `returns outside for a path that leaves the root`, `returns outside for ~/x.md`, `docDirOf of a root file is empty`.

### WI-2 — Heading slugs (pure remark plugin)

New file `src/dashboard/frontend/src/lib/remarkHeadingSlugs.ts`, test `src/dashboard/frontend/src/lib/__tests__/remarkHeadingSlugs.test.ts`.

`export function headingSlug(text: string): string` — GitHub style: lowercase; remove every character that is not a Unicode letter, number, space, `-` or `_` (`/[^\p{L}\p{N}\s_-]/gu`); replace each whitespace character with `-`. `Fort 3D — Supply!` → `fort-3d--supply`.

`export function remarkHeadingSlugs()` — a remark plugin: walks the mdast tree, and for each `heading` node collects the text of its `text` and `inlineCode` descendants, computes `headingSlug`, de-duplicates within the document (second `intro` → `intro-1`, third → `intro-2`) and sets `node.data = { ...node.data, hProperties: { ...node.data?.hProperties, 'data-heading-slug': slug } }`.

Fragment matching (used in WI-3): a `#X` link matches the heading whose slug equals `X`; when none does, it matches the heading whose slug equals `headingSlug(X)`.

**Implementation checkpoint:** after wiring the plugin into `ChatMarkdown` (WI-3), the WI-3 test `adds data-heading-slug to headings in a located preview` must find the attribute on the rendered `<h2>`. If `hProperties` with the dashed key does not reach the DOM, use the hast property name `dataHeadingSlug` instead. If neither works, fall back to `h1`…`h6` components in `makeComponents` that compute the slug from `node` text without de-duplication.

Tests: `slugs punctuation and spaces like GitHub`, `keeps unicode letters`, `de-duplicates repeated headings`, `sets hProperties on heading nodes`.
