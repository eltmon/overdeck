## Glossary

- **Directory** — the overdeck.ai Cloudflare Worker `services/connect/`, one `AccountDirectory` SQLite Durable Object per account. See `docs/CONNECT-SERVICE.md`.
- **Machine** — an Overdeck install that says `hello`. Free accounts hold 3 (`machine_limit`, close 4009).
- **Client** — a socket that says `hello-client`. Its row lives in `state.clients` and the `clients` SQLite table. Clients never count as machines.
- **Phone** — a client whose `platform` is `ios` or `android`. Capped at `CLIENT_LIMIT = 5` per account on every plan.
- **Connector** — a client whose `platform` is `node`: the bot process W-CONN2 builds (`pan mcp connector`). Capped at `CONNECTOR_LIMIT = 10` per account on every plan (new here).
- **Family** — `phone` (`ios`, `android`) or `connector` (`node`). Each family has its own cap; the caps never share slots.
- **`PhonePlatform`** — new contracts type `"ios" | "android"`: the platforms that can hold a push registration.
- **`ClientPlatform`** — contracts type, widened to `PhonePlatform | "node"`.
- **Rehydration** — the Durable Object rebuilding its reducer state from SQLite (`loadDirectory`) after it hibernates or restarts.
- **CP-5** — epic implementation checkpoint: the directory deploy must happen before any `@overdeck/core` release with the connector. The deploy is operator-only.

## Requirements

### Functional

- **FR-1** `ClientPlatform` accepts `"node"`. A new `PhonePlatform = "ios" | "android"` types `push-register.platform` and `PushRegistration.platform`.
- **FR-2** `CONNECTOR_LIMIT = 10` and `CONNECTOR_LIMIT_MESSAGE = "This account already has 10 Overdeck connectors. Remove one in Settings → Anywhere → Bots."` are exported from contracts.
- **FR-3** The directory decoder accepts `hello-client` with `platform: "node"`. It still refuses `push-register` with `platform: "node"` as `bad_frame`.
- **FR-4** The client reducer counts phones against `CLIENT_LIMIT` and connectors against `CONNECTOR_LIMIT`, separately. A refused hello sends `error client_limit` with the family's message and closes with 4013.
- **FR-5** A re-hello whose platform moves a row to the other family is counted against the new family's cap, and the row's push registration is cleared.
- **FR-6** `loadDirectory` reloads `node` rows, so connectors survive rehydration.
- **FR-7** `DirectoryWebClient` accepts `platform: ClientPlatform`. On close 4013 a `node` client's `refusal` is `CONNECTOR_LIMIT_MESSAGE`; a phone's stays `CLIENT_LIMIT_MESSAGE`.
- **FR-8** `CONNECT_PROTOCOL_VERSION` stays `1`.

### Non-functional

- **NFR-1** No phone behavior changes: the 6th phone still gets the exact phone message, and every existing test in the five test files still passes unchanged except where a test asserts a comment-free type change.
- **NFR-2** No new close code, error code, frame type or SQLite column.
- **NFR-3** No agent deploys the directory. The PR description states that connect.overdeck.ai must be redeployed (operator step, `docs/CONNECT-SERVICE.md` "Deploy") before W-CONN2 ships.

## Decisions

- **D-1 Split the platform type.** `PhonePlatform` types push; `ClientPlatform = PhonePlatform | "node"` types hellos and rows. Rejected alternative: widen everything and rely on the runtime checks in `protocol.ts:271` and `push-state.ts:55`. That leaves `deliver.ts` routing a type-legal `node` registration to FCM and hides the rule from the compiler. The split makes "push-register from node is bad_frame" true at compile time too.
- **D-2 Family change on re-hello: recount and clear push.** If `existing` has a different family than the new hello, treat the hello as a new member of the new family for the cap, and set `push: null`. Rejected: refusing the change as `bad_frame` needs a new error path and decides what happens to the socket. Client ids are per-install UUIDs, so this case is rare; recounting is three lines and keeps the caps exact.
- **D-3 Reuse close 4013 and error code `client_limit`** for both families (epic D-18). The message tells them apart.
- **D-4 The web client picks the limit message by `deps.platform`**, not from the earlier `error` frame. It is deterministic and also covers a close with no `error` frame (the existing 4013 test shape).
- **D-5 Mobile stays on `ClientPlatform`.** It compiles unchanged because `PhonePlatform` is a subset. Moving `shellPlatform()` to `PhonePlatform` belongs with the mobile push work, not here.
- **D-6 The `node` client's `publicKeyHex` is its install key**, not a push key. Document it on `hello-client.publicKeyHex`. The directory stores it the same way.
- **D-7 `forget-client` and the `forgotten` refusal message keep their phone wording.** W-CONN2 owns how the connector reports a removal.
