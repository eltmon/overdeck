## Glossary

- **PR link:** a row in the `conversation_pull_requests` table of `overdeck.db`. It ties one conversation to one pull request (PR) and stores the last snapshot of that PR. Code: `src/lib/overdeck/conversation-pull-requests.ts`.
- **PR key:** `PullRequestKey = { host, repository, number }` (`packages/contracts/src/pull-request-links.ts:17-22`), for example `{ host: 'github.com', repository: 'eltmon/overdeck', number: 4943 }`. Its string form in the sweep is `${host}/${repository}#${number}` (`keyString`, `pull-request-sync-service.ts:131-133`).
- **Snapshot:** `PullRequestSnapshot` (`pull-request-links.ts:27-46`): `state` (`open | merged | closed`), `checks` (`green | red | pending`, `PrChecksState`, `packages/contracts/src/derived-issue-state.ts:53`), `reviewState` (`approved | changes-requested | review-requested | commented | none`, same file lines 43-49), `mergeable` (`true | false | null`; null = GitHub has not computed it), and other fields.
- **PR sync sweep:** `runPullRequestSyncOnce` in `src/dashboard/server/services/pull-request-sync-service.ts:406-451`. It runs 30 s after boot and then every 60 s (`PR_SYNC_INTERVAL_MS`, line 72), only on the primary dashboard (`main.ts:603`: `if (!isPeerDashboard) startConversationSweeps();`).
- **Listing:** one `gh pr list --state all` per project per sweep (`readRepoPullRequests`, cached 30 s), at most 100 rows.
- **Fallback read:** one `gh pr view` per linked PR the listings did not cover (`refreshUnlistedLinks`, lines 334-358), with a 3-strike, 15-minute per-repository backoff (`repoInBackoff` / `recordRepoFailure`, lines 313-325).
- **Watch:** new in this issue. A row in `~/.overdeck/pr-watches.json` that says "agent A wants a message when PR K changes". It belongs to exactly one **owner** (an agent token's `agentId` + `agentKind`).
- **Baseline (`last`):** the four snapshot fields a watch compares against: `{ state, checks, reviewState, mergeable }`. It is stored on the watch row, not read from a PR link.
- **Wake:** one message the notifier delivers for one watch after one snapshot change. A wake may name several events.
- **Quiet wake:** a wake whose events include `review-changed` and include neither `checks-failed` nor `checks-passed`.
- **Covered key / uncovered key:** a watched PR key whose snapshot the sweep already has this pass (from a listing row or a fallback read) is covered; any other watched key is uncovered and needs its own `gh pr view`.
- **Agent token, self route, self caller:** see the epic glossary. A self route under `/api/self/` acts for the agent named by the caller's agent token (`resolveSelfCaller`, `src/dashboard/server/self-caller.ts:74-76`); anything else gets 403 `not-an-agent-token`, and a token whose agent is gone gets 404 `agent-gone`.
- **Owner key:** the string `${agentKind}:${agentId}` that identifies a watch owner.

## Corrections to W-PR1

- **C-1 Body shape.** The link route takes `{ ref, source? }` (Fact 2). `link_pull_request` takes `ref` (a URL, `#42` or `owner/repo#42`) and sends `source: 'agent'` when the caller is an agent token.
- **C-2 Six routes, six rows.** W-PR1 step 1 names five routes; the file has six (Fact 1). The sixth, `GET /api/pull-requests/conversations` (reverse index), gets `read:state`, the same as `GET /api/pull-requests`.
- **C-3 No "agent's own conversation" for work agents.** Work agents have no conversation row (Fact 3). The default target of `link_pull_request` is resolved server-side by a new self route `POST /api/self/pull-requests`: a conversation token links to its own conversation; an agent token links to the conversation named by its `agentId` only when that row exists (specialists); otherwise 404 `no-conversation`.
- **C-4 Watches do not depend on PR links.** A watch must work for a work agent that has no conversation (Fact 3) and for a PR no conversation links (Fact 4). The watch row stores its own key and baseline. Linking during watch creation is best effort and never fails the watch.
- **C-5 Watched keys are read inside the existing sweep.** At the end of `runPullRequestSyncOnce`, the sweep resolves a snapshot for each watched key: from this pass's listing rows or fallback reads when it has one, else one `gh pr view` under the same pause gate and 3-strike backoff as `refreshUnlistedLinks`. This is reuse of the sweep (same timer, same gates, same fallback mechanism), not new polling: FR-9 forbids another timer or cadence, and this adds none.
- **C-6 Watch-local baseline instead of `(key, before, after)`.** `link.snapshot` is ambiguous across conversations (Fact 5) and absent for unlinked PRs. Each watch stores `last`. The two call-site hooks of W-PR1 step 6 (lines 181 and 387) are replaced by one watch pass at sweep end. `refreshPullRequestLinkNow` (line 378, used by the link and sync routes) is not hooked: the next sweep re-reads any open watched key anyway, and the watch-local baseline makes the result identical.
- **C-7 Baseline at creation.** "A first snapshot notifies nothing" (step 5) would miss a failure that lands between creation and the first sweep. The watch route reads the PR once and stores the result as `last`. A failed read refuses the watch (502 `pr-read-failed`); a PR already merged or closed refuses it (409 `pr-finished`).
- **C-8 In-process delivery.** Step 5's loopback `fetch` with the internal token is replaced by the same in-process doors those two routes call: `messageAgent` for agents and `handleConversationMessage` for conversations (Fact 8). NFR-1 ("every tool calls a route") governs tools, not a server-internal notifier; the schedule service is the precedent.
- **C-9 Test file location.** The notifier test lives at `src/dashboard/server/services/__tests__/pull-request-watch-notifier.test.ts`, beside `pull-request-sync-service.test.ts`, not under `src/dashboard/server/__tests__/`.
- **C-10 Peer-dashboard test.** W-PR1's test "the notifier never runs on a peer dashboard" is not written as a test: a test that reads source fails lint (`lint:source-introspection`). The guarantee is structural (`main.ts:603`), and the verify step checks the single caller with `grep`.

## Requirements

### Functional

- **FR-1 Scope rows.** The six existing PR-link routes are callable with a scoped token: `GET /api/conversations/:name/pull-requests` → `read:conversations`; `POST /api/conversations/:name/pull-requests` → `tell`; `DELETE /api/conversations/:name/pull-requests` → `tell`; `POST /api/conversations/:name/pull-requests/sync` → `tell`; `GET /api/pull-requests` → `read:state`; `GET /api/pull-requests/conversations` → `read:state`.
- **FR-2 Link tool.** `link_pull_request` (`audience: 'any'`, scope `tell`) links a PR to a named conversation, or, for an agent token without `conversation`, to the caller's own conversation through `POST /api/self/pull-requests`.
- **FR-3 Watch store.** `~/.overdeck/pr-watches.json` holds watches, mode 0600, written atomically under a cross-process lock. At most 20 watches per owner and 50 in total.
- **FR-4 Watch routes.** `POST /api/self/pull-request-watches` (`tell`), `GET /api/self/pull-request-watches` (`read:state`), `DELETE /api/self/pull-request-watches/:id` (`tell`), `POST /api/self/pull-requests` (`tell`). Agent tokens only.
- **FR-5 Watch tools.** `watch_pull_request`, `list_pull_request_watches`, `unwatch_pull_request`, all `audience: 'agent'`.
- **FR-6 Notifications.** A watched PR's change is delivered to the owner as one message per wake. Events: `checks-failed`, `checks-passed`, `review-changed`, `conflicting`, `merged`, `closed`. `merged`, `closed` and the 11th consecutive quiet wake end the watch.
- **FR-7 Watch cleanup.** Revoking an owner's agent token removes its watches; the notifier also drops watches whose owner holds no active agent token.
- **FR-8 Documentation.** `configuration/mcp.mdx`, `docs/DASHBOARD-AUTH.md` and `features/conversations.mdx` describe the new tools, routes, scopes, limits and messages.

### Non-functional

- **NFR-1 One authority.** Every tool calls a dashboard route; `route-scopes.ts` judges it; self routes additionally require an agent token (`resolveSelfCaller`).
- **NFR-2 No new poller.** No new timer, interval or service. Watched keys are read only inside `runPullRequestSyncOnce`.
- **NFR-3 Zero cost when unused.** With no watches, the sweep makes no extra `gh` call and no extra `listAccessTokens()` call.
- **NFR-4 Exactly once.** One snapshot change produces at most one message per watch, across concurrent sweeps, route calls and dashboard restarts.
- **NFR-5 Async only.** No `execSync`, `spawnSync`, `execFileSync` and no new `*Sync` function (repo rules `no-execsync-server`, `prefer-async`).
- **NFR-6 Fake timers** for any test that advances time (repo rule `fake-timers-for-retry-tests`): `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`, never real sleeps.
- **NFR-7 File size.** New modules stay under 600 lines; `pull-request-sync-service.ts` grows by at most 45 lines; `src/dashboard/server/server.ts` by at most 2 lines.
- **NFR-8 Import boundary.** `src/lib/overdeck/pull-request-watches.ts` imports only Node built-ins, `../paths.js`, `../vault/file-lock.js` and type-only `@overdeck/contracts`, because `revokeAgentMcpTokens` loads it in CLI processes; `npm run lint` (`lint:circular`) stays green.
- **NFR-9 Every new HTTP route** is in a top-level file of `src/dashboard/server/routes/`, has a row in `tests/unit/lib/overdeck/no-loss-matrix.ts` and a row in `route-scopes.ts`.
- **NFR-10 Effect boundary.** No new exported Effect wrapper around in-repo Promise code; `npm run lint:effect-facades` does not rise.

## Decisions

- **D-1 Owner identity** is the token's `agentId` and `agentKind` exactly as `selfCallerFromCredential` returns them (normalized agent id, or conversation name). `revokeAgentMcpTokens` removes watches with `ownerId(agentId, agentKind)`, the same id it revokes.
- **D-2 Baseline fields.** `last = { state, checks, reviewState, mergeable }`. `mergeable` stores the last known non-null value: a snapshot with `mergeable: null` leaves `last.mergeable` unchanged.
- **D-3 Events.** Compare the snapshot `s` with `last`, in this order:
  1. `merged`: `last.state === 'open' && s.state === 'merged'`.
  2. `closed`: `last.state === 'open' && s.state === 'closed'`.
  3. `checks-failed`: `s.checks === 'red' && last.checks !== 'red'`.
  4. `checks-passed`: `s.checks === 'green' && last.checks !== 'green'`.
  5. `conflicting`: `s.mergeable === false && last.mergeable !== false`.
  6. `review-changed`: `s.reviewState !== last.reviewState`.
  A move to `checks: 'pending'` produces no event but updates `last.checks`, so pending → red later fires again.
- **D-4 One message per wake.** All events of one comparison go into one message. Text: `[Overdeck] <repository>#<number>: <phrase>; <phrase>. <url>` where the phrases are: `merged`; `closed without merging`; `checks failed (was <last.checks>)`; `checks passed (was <last.checks>)`; `has merge conflicts`; `review is now <s.reviewState> (was <last.reviewState>)`. A wake that ends the watch appends ` The watch has ended.` (merged, closed) or ` The watch has ended after 10 review-only updates; call watch_pull_request again to keep watching.` (quiet limit). Example: `[Overdeck] eltmon/overdeck#4943: checks failed (was pending). https://github.com/eltmon/overdeck/pull/4943`.
- **D-5 Quiet wakes.** `MAX_QUIET_WAKES = 10`. After a wake: if its events include `checks-failed` or `checks-passed`, set `quietWakes = 0`; else if they include `review-changed`, add 1; otherwise leave it. A wake that makes `quietWakes` equal 11 ends the watch. So wakes 1-10 only notify; the 11th notifies and ends.
- **D-6 Persist, then deliver.** The notifier computes all wakes and writes the new store under the file lock first, then delivers outside the lock. A crash after the write and before delivery loses that message rather than sending it twice (the same rule as the schedule service, `conversation-schedule-service.ts:10-15`). Agent deliveries pass `dedupKey: 'pr-watch:<watchId>:<wakes>'`, where `wakes` is the watch's wake counter after this wake.
- **D-7 Delivery doors.** `agentKind: 'agent'` → `messageAgent(agentId, text, 'pr-watch', { dedupKey })`; success = `outcome.delivered || outcome.queuedToMail`. `agentKind: 'conversation'` → `getConversationByName(name)`; missing → failure; a superseded `/clear` row resolves to its chain head exactly as `fireScheduledPrompt` does (`conversation-schedule-service.ts:118-123`: `isSupersededConversation` then `resolveClearChainHead`, failure when null); else `handleConversationMessage(name, { message: text, ...(isPiControlChannelHarness(conv.harness ?? 'claude-code') ? { deliverAs: 'follow_up' } : {}) }, { resolveSessionFile, generateAiTitle: async () => {} })`; success = HTTP status 2xx. The notifier never resumes a stopped harness: a stopped owner's token is revoked, which removes its watches. A failed delivery logs one line `[pr-watch] delivery to <owner> failed: <reason>` and is not retried.
- **D-8 Limits.** `PR_WATCH_LIMIT_PER_OWNER = 20` (epic W-PR1). `PR_WATCH_LIMIT_TOTAL = 50`. Why 50: an uncovered key costs one `gh pr view` per sweep (about one GraphQL point), so 50 uncovered keys cost at most 50 points a minute, 3,000 an hour, inside the 5,000-point hourly user bucket; most watched keys are covered by a project listing at no extra cost, and the PAN-4264 pause skips the whole sweep before the bucket runs out.
- **D-9 Duplicate watch.** A second `POST` for the same owner and key returns the existing watch with 200 and `created: false`. It does no `gh` read.
- **D-10 Linking during watch creation.** The route links the PR to the caller's own conversation when one exists (a conversation token always; an agent token when `getConversationByName(agentId)` finds a row), with source `agent`, then stores the creation snapshot on that link. A refused link (for example `foreign_repository`) answers `linked: false, linkError: '<code>'` and the watch is still created.
- **D-11 GitHub only.** A watch URL must parse with `githubPullRequestKeyFromUrl` (`pull-request-sync-service.ts:98-105`). GitLab merge requests are refused with 400 `invalid-url`, because the sweep reads GitHub only.
- **D-12 Corrupt store.** Like `machine-store.ts`, a store file that does not parse makes every read throw and nothing rewrites it. The sweep's watch pass catches and logs it (`[pr-sync] watch pass failed:`); routes answer 500 through `httpHandler`.
- **D-13 Orphan backstop.** When the store is non-empty, the notifier reads `listAccessTokens()` once per pass and drops (in the same locked update, without a message) every watch whose owner key matches no record with `kind === 'token'`, no `revokedAt`, and the same `agentId` and `agentKind`. This covers a crash between token revocation and watch removal, which would otherwise leave a recurring `gh` read.
- **D-14 `link_pull_request` source.** Agent tokens send `source: 'agent'`; other tokens send no `source` (the route then records `manual`).

- **H-3 Lock waits.** `withFileLock` retries for up to about 60 s. Stop paths call `revokeAgentMcpTokens` fire-and-forget (`termination.ts:213`) or await it (`termination.ts:305`, `conversation-runtime.ts:203`); a held lock delays only watch removal, after the token is already revoked.

- **H-5 `refreshPullRequestLinkNow` stays unhooked** (C-6); do not add a notifier call there.

## Out of scope (NonGoals)

- Watching GitLab merge requests.

- Grouping uncovered keys into extra `gh pr list` calls.
- Instruction-block text for agents (W-INJ4, PAN-4935) and the epic-wide docs pass (W-DOC, PAN-4958).
