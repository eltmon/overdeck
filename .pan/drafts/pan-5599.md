# PAN-5599: Order books — the queue skips finished books

**Issue:** https://github.com/eltmon/overdeck/issues/5599
**Depends on:** PAN-5597 (Order books page rework) merged to `main`. This PRD edits `src/lib/orders/phase.ts`, which PAN-5597 creates. Do not start work before `src/lib/orders/phase.ts` exists on `main`.

## Problem

The Flywheel releases work from one order book: the first book with status `ready`. When every issue in that book has landed, the book still holds the slot. The next queued book does not start until a person archives the finished one. On 2026-11-22 a stale July book held the slot and the two open issues of a later book were not released.

PAN-5597 makes this visible and gives a one-click "Archive and move on". The operator delegated the remaining decision, and the decision is: a finished book must not hold the queue. The Flywheel is meant to run without a person in the loop.

## Glossary

- **Book**: an order book, type `OrderBook` in `packages/contracts/src/orders.ts`.
- **Active book**: the book whose issues count as operator-released for automatic pickup, returned by `currentOrderBook` in `src/lib/orders/phase.ts`.
- **Terminal issue**: closed, or carrying the `parked` label.
- **Finished book**: a book with at least one issue where every issue is terminal. `computeBookProgress(book, lookup)` in `src/lib/orders/resolver.ts` returns `{ total, drained }`; finished means `total > 0 && drained`.
- **Positive evidence**: the issue lookup returned a state for the issue. An issue the lookup does not know is not terminal.
- **Issue lookup**: `liveOrderIssueLookup` in `src/lib/orders/resolver.ts`. It reads the shared issue service and returns an empty map when that service is unavailable.

## Decisions

- **D1. Skip, do not archive.** A finished book keeps status `ready`. Nothing writes a status. The active book is derived on every read: the first `ready` book that is not finished. This keeps the rule "Overdeck stores no status it can derive".
- **D2. Fail safe.** A book is finished only on positive evidence. When the issue lookup is unavailable or does not know an issue, the book is not finished and the queue behaves as it does today.
- **D3. A `running` book stays first.** If a book has stored status `running`, it is active regardless of progress (legacy data; nothing writes this status).
- **D4. One function decides.** Dispatch, the API phase and the Flywheel status summary all call `currentOrderBook` with the same finished rule, so the page cannot disagree with dispatch.

## Requirements

- **FR-1** `currentOrderBook` skips `ready` books that are finished.
- **FR-2** Dispatch (`activeOrderBookIssues`), the orders API phase (`deriveBookPhases`) and the Flywheel status summary use the same rule.
- **FR-3** The page shows a finished queued book as Finished with an Archive action, and never shows a finished book as Active.
- **FR-4** The docs describe the new rule.
- **NFR-1** When the issue lookup returns nothing, behavior is identical to before this change.

## Work items

### WI-1. `currentOrderBook` takes a finished rule (FR-1)

**Files:** `src/lib/orders/phase.ts`; `tests/unit/lib/orders/orders-phase.test.ts`; `tests/unit/lib/cloister/flywheel-active-order-book.test.ts`.

Before (as PAN-5597 leaves it):

```ts
export function currentOrderBook(books: readonly OrderBook[]): OrderBook | null {
  return books.find(book => book.status === 'running')
    ?? books.find(book => book.status === 'ready')
    ?? null;
}
```

After:

```ts
export function currentOrderBook(
  books: readonly OrderBook[],
  isFinished: (book: OrderBook) => boolean = () => false,
): OrderBook | null {
  return books.find(book => book.status === 'running')
    ?? books.find(book => book.status === 'ready' && !isFinished(book))
    ?? null;
}
```

In `deriveBookPhases` (same file), call `currentOrderBook(books, (b) => { const p = progressOf(b); return p.total > 0 && p.drained; })`. A finished `ready` book gets phase `queued` and `finished: true`. Its `queuePosition` is `null`: number only the unfinished `ready` books, with the active book at 1.

**Tests:** `skips a finished ready book and returns the next ready book`; `returns null when every ready book is finished`; `a running book is active even when finished`; `with no finished rule the first ready book is active` (the NFR-1 case); `a finished ready book has phase queued, finished true and no queue position`.
