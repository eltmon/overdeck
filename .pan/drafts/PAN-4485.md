## Glossary

- **`/clear`** — Claude Code's built-in command. The harness process keeps running in the same pane, stops writing the current session JSONL, and starts a new JSONL with a fresh session id. It is not compaction and not an Overdeck command.
- **Conversation row** — a row of the `conversations` table, read through `LegacyConversation` (`src/lib/overdeck/conversations.ts`, interface at line ~237). Relevant fields: `id` (legacy numeric id = SQLite `rowid`), `name`, `tmuxSession`, `status` (`'active' | 'ended'`), `endedAt`, `archivedAt`, `claudeSessionId`, `forkStatus`, `clearedToConvId`.
- **Terminal session** — the backend pane a row names in `tmuxSession` (e.g. `conv-20260928-7563`). Herdr or tmux hosts it; "session" below always means this, never the Claude session id.
- **Post-`/clear` sibling** — the row `detectOrphanedClaudeCodeSessions` creates (`src/dashboard/server/services/conversation-lifecycle.ts`, grep `name: \`${parent.name}-post-clear-`). It **copies the parent's `tmuxSession`**, gets the new JSONL's id as `claudeSessionId`, and the detector sets `parent.cleared_to_conv_id = sibling.id` and marks the parent ended.
- **Superseded row** — any row with `clearedToConvId != null`. It no longer owns its terminal session.
- **`/clear` chain** — the rows linked by `clearedToConvId`: parent → sibling → (a second `/clear`) → sibling-2 … All share one `tmuxSession`.
- **Chain head** — the newest row of a chain: the row reached by following `clearedToConvId` until it is null. The chain head is the **session owner**.
- **Broken chain** — following `clearedToConvId` reaches a row that is missing, archived, on a different `tmuxSession`, or already visited (cycle). A broken chain has no resolvable owner.
- **Running repair** — the list-path step that flips an `ended` row back to `active` when its session and harness are alive (`enrichConversationList`, `src/lib/overdeck/conversation-list.ts:206-215`).
- **Input door** — an HTTP handler that sends keystrokes into a conversation's pane on the operator's behalf (plan action, permission answer, pane-choice answer).

## Problem

After `/clear` in a dashboard conversation, the conversation list shows two live rows — the pre-clear parent and its post-`/clear` sibling. Stopping either stops both; resuming either resumes both. Reproduced 2026-10-02 with parent `20260928-7563` and sibling `20260928-7563-post-clear-1415587e`: both `status=active`, both `tmux_session=conv-20260928-7563`, parent `cleared_to_conv_id` = sibling.

### Root cause (verified at HEAD)

One process belongs to two rows. Only two code paths know the parent gave up the session: `shouldResurrect` (`conversation-lifecycle.ts:237-240`, `if (conv.clearedToConvId != null) return false;`) and `session-started` in `agent-projection.ts:320`, which resolves its row via `getSupervisedConversationByTmuxSession` (`conversations.ts:650`). Everything else treats any row naming a live session as its owner:

1. **List revives the parent.** `src/lib/overdeck/conversation-list.ts:208-214`:
   ```ts
   if (liveSessionNames && !sessionAlive && row.status === 'ended' && !row.forkStatus && tmuxSessionAlive) {
     const harnessAlive = await conversationHarnessAlive(row.tmuxSession);
     if (conversationNeedsRunningRepair(row, tmuxSessionAlive, harnessAlive)) {
       markConversationRunning(row.name);
   ```
   `conversationNeedsRunningRepair` (`src/lib/overdeck/conversation-runtime.ts:271-277`) has no `clearedToConvId` check, so the parent flips back to `active` on every list fetch.
2. **Stop kills the shared pane.** `handleConversationStop` (`conversation-runtime.ts:1073`) calls `stopConversationRuntime(conv, name)` (`:183`). Its guard `hasOtherActiveConversationOnTmuxSession` (`conversations.ts:1146`) is a stub that always returns `false`, so the pane closes and `killConversationRuntimeProcesses` kills every process launched by `~/.overdeck/conversations/<tmuxSession>/launcher.sh` — the sibling's process included.
3. **Resume acts on the shared pane.** `handleConversationResume` (`conversation-runtime.ts:1105`): if the harness is alive it reattaches and reports the parent active; if not, `spawnConversationSession(conv.tmuxSession, …, oldSessionId …)` respawns the parent's **pre-clear** Claude session into the shared session name.
4. **Restart-all runs twice.** `handleConversationRestartAll` (`conversation-runtime.ts:1192`), line 1199: `const convs = allConvs.filter((c) => liveSessionNames.has(c.tmuxSession));` selects parent and sibling. Rows come `created_at DESC`, so the sibling restarts first, then the parent's iteration closes the pane and respawns the pre-clear session — the old conversation wins.
5. **Delete and archive kill the sibling.** `handleConversationDelete` (`conversation-runtime.ts:1172-1181`) and `archiveConversationByName` (`src/lib/overdeck/conversation-archive.ts:144-155`) both call `stopConversationRuntime` on the row being removed. Deleting the stale parent kills the live sibling.
6. **Pending-input feed lists the parent.** `getConversationsPendingInputFeed` (`src/lib/overdeck/conversation-reads.ts:380-387`) keeps every row with `liveSessionNames.has(conv.tmuxSession)`, so the parent appears as a second live row and its (pre-clear) transcript is scanned for prompts.
7. **Input doors type into the sibling's pane through the parent.** `handleConversationPlanAction` (`src/lib/overdeck/conversation-delivery.ts:231`), the permission answer (`src/lib/overdeck/conversation-permission.ts:225-240`) and `handleConversationPaneChoiceAnswer` (`src/lib/overdeck/conversation-pane-choice.ts:55-75`) all use `conv.tmuxSession` with no ownership check.

## Decisions

- **D1 — Ownership rule.** A row with `clearedToConvId != null` is superseded and never owns its terminal session. The chain head owns it. Every lifecycle write (repair, stop, resume, restart, delete, archive) and every input door honors this rule.
- **D2 — One resolver module, two existing lookups agree.** New module `src/lib/overdeck/conversation-clear-chain.ts` holds the rule. It walks explicit `clearedToConvId` links from a known row (stop, resume, input doors need "the head of *this* chain"). The existing `getSupervisedConversationByTmuxSession` answers a different question — "which row does an inbound supervisor event for session X belong to" — and stays as is. The two agree because both prefer a row whose `clearedToConvId` is null. Note: when a chain is broken (head archived), `getSupervisedConversationByTmuxSession` can return the superseded parent itself; the new module treats that as "no owner", never as "parent owns it".
- **D3 — Stop on a superseded row stops the chain head** (the issue's stated fix), not a no-op. The superseded row itself is only marked ended **if it is not already ended** — its `ended_at` must not move, because `agent-projection.ts` compares a launch's start time against `ended_at`.
- **D4 — Resume on a superseded row resumes the chain head**: the head's `claudeSessionId`, the head's model/effort/harness, and only the head is marked active. The response is the head's row plus `redirectedFrom: <requested name>`. A broken chain returns **409** `{ error: 'Conversation was cleared and its continuation is unavailable', code: 'conversation-cleared' }`. A superseded row is **never** respawned into the shared session name. The frontend callers (`ConversationPanel.tsx:427-442`, `ConversationTerminal.tsx:29-33`) only invalidate the `['conversations']` query on success and never read the returned `name`, so no frontend change is needed.
- **D5 — Delete and archive of a superseded row skip `stopConversationRuntime`.** The row owns no runtime. They still mark the row ended (only if not ended), archive it, remove its favorite, and clean its attachments. Deleting or archiving the chain head keeps today's behavior (stops the shared runtime).
- **D6 — Restart-all handles each live terminal session once, through its owner.** Superseded rows are dropped; among the remaining rows on one session, the first in `listConversations()` order (`created_at DESC`, i.e. newest) wins. A live session whose only non-archived row is a superseded parent (its head was archived) is skipped on purpose — no row owns it; `sessionOwners` stays pure and restart-all logs one `console.warn` naming each live session it skipped for that reason.
- **D7 — Input doors on a superseded row return 409** `{ error: …, code: 'conversation-cleared', clearedToConvId }`. The sibling's own row answers its prompts.
- **D8 — Do not implement the `hasOtherActiveConversationOnTmuxSession` stub.** With it live, stop on a parent would become a silent no-op (the sibling is active), contradicting D3. Its unused import in `src/dashboard/server/routes/conversations.ts:117` stays untouched.
- **D9 — The `active`-superseded repair lives in the list path** (the issue's stated location) and runs **before** `conversationSessionAliveFromState` is computed, so one response never carries `status: 'ended'` with `sessionAlive: true`.
- **D10 — File-size budget.** `conversation-runtime.ts` is 1242 lines against an allowed 1252 (`scripts/file-size-allowlist.txt`, last `conversation-runtime.ts` row wins). WI-3 moves `handleConversationRestartAll` into a new module `src/lib/overdeck/conversation-restart-all.ts`, freeing ~45 lines before WI-4/5/6 add code. `src/dashboard/server/routes/conversations.ts` is **exactly at its cap (1072/1072)**: WI-3's import change there must be net-zero lines (remove `  handleConversationRestartAll,` from the `conversation-runtime.js` import block, add one `import { handleConversationRestartAll } from '../../../lib/overdeck/conversation-restart-all.js';` line). Never raise an allowlist row. Re-exporting from `conversation-runtime.ts` is forbidden: it creates an import cycle that fails `lint:circular`.

## Requirements

- **FR-1** — When the conversation list is fetched, the list never flips a superseded row from `ended` to `active`, whatever the liveness of its terminal session and harness.
- **FR-2** — When the list is fetched, a superseded row stored as `active` is re-marked `ended` and returned with `status: 'ended'` and `sessionAlive: false`.
- **FR-3** — `POST /api/conversations/:name/stop` on a superseded row stops the chain head's runtime and marks the head ended; the superseded row's existing `ended_at` is unchanged. On the chain head itself, stop behaves as today. A broken chain only marks the requested row ended (if not already) and stops nothing.
- **FR-4** — `POST /api/conversations/:name/resume` on a superseded row resumes the chain head (head's `claudeSessionId`, head's row marked active); a broken chain returns 409 `code: 'conversation-cleared'`. The superseded row is never marked active and never respawned.
- **FR-5** — `POST /api/conversations/restart-all` respawns each live terminal session exactly once, using the session owner's `claudeSessionId`; superseded rows are never restarted.
- **FR-6** — Delete and archive of a superseded row do not stop any runtime; the shared session and the chain head stay live.
- **FR-7** — The pending-input feed never returns a superseded row.
- **FR-8** — Plan action, permission answer and pane-choice answer on a superseded row return 409 `code: 'conversation-cleared'` and send no keystrokes.
- **FR-9** — `docs/DASHBOARD-ARCHITECTURE.md` states the ownership rule, names the chain head as owner, and states that no boot-time conversation auto-resume exists.
- **NFR-1** — No file grows past its allowed line count (`scripts/lint-file-size.sh`); no allowlist row is raised.
- **NFR-2** — No new import cycle (`npm run lint` includes `lint:circular`). New lib modules import only from `conversations.ts` and modules that do not import them back.
- **NFR-3** — No `execSync` or other sync child-process call is added to server-reachable code (dashboard rule).
- **NFR-4** — New tests go in new, focused test files; do not grow `src/dashboard/server/routes/__tests__/conversations.test.ts` (1700 lines). Tests that use a real database follow `src/lib/overdeck/__tests__/conversation-critic-link.test.ts` (temp `OVERDECK_HOME`, dynamic imports, `closeOverdeckDatabase` in `afterAll`). No test uses real `setTimeout` delays; if a handler under test sleeps (stop's 500 ms attachment-cleanup timer), use `vi.useFakeTimers()` or mock the cleanup dependency.

### WI-1 — Chain-ownership module `conversation-clear-chain.ts`

**What/why:** one place that answers "is this row superseded", "who owns this row's session", and "one owner per live session". Every later item uses it.

**Files:** new `src/lib/overdeck/conversation-clear-chain.ts`; new test `src/lib/overdeck/__tests__/conversation-clear-chain.test.ts`.

**Code (target shape):**
```ts
/**
 * PAN-4485: a post-/clear chain (parent → sibling → …) shares one terminal
 * session. Only the chain head — the row whose clearedToConvId is null —
 * owns it. A superseded row (clearedToConvId set) owns nothing.
 */
import { getConversationById, type LegacyConversation } from './conversations.js';

type ChainRow = Pick<LegacyConversation, 'id' | 'tmuxSession' | 'clearedToConvId' | 'archivedAt'>;

export function isSupersededConversation(conv: Pick<LegacyConversation, 'clearedToConvId'>): boolean {
  return conv.clearedToConvId != null;
}

const MAX_CLEAR_CHAIN_LENGTH = 64;

/** The row that owns `conv`'s terminal session, or null when the chain is broken. */
export function resolveClearChainHead<T extends ChainRow>(
  conv: T,
  lookup: (id: number) => T | null = getConversationById as unknown as (id: number) => T | null,
): T | null {
  const seen = new Set<number>([conv.id]);
  let current = conv;
  while (current.clearedToConvId != null) {
    const next = lookup(current.clearedToConvId);
    if (!next || next.archivedAt || next.tmuxSession !== conv.tmuxSession) return null;
    if (seen.has(next.id) || seen.size >= MAX_CLEAR_CHAIN_LENGTH) return null;
    seen.add(next.id);
    current = next;
  }
  return current;
}

/** One row per terminal session: superseded rows dropped, first row per session kept (input order). */
export function sessionOwners<T extends Pick<LegacyConversation, 'tmuxSession' | 'clearedToConvId'>>(rows: readonly T[]): T[] {
  const owners = new Map<string, T>();
  for (const row of rows) {
    if (isSupersededConversation(row) || owners.has(row.tmuxSession)) continue;
    owners.set(row.tmuxSession, row);
  }
  return [...owners.values()];
}
```
Keep `lookup` injectable for unit tests; the default reads the database. If the generic cast is awkward, type it as `LegacyConversation` only — the call sites all pass `LegacyConversation`.

**Tests (`conversation-clear-chain.test.ts`, pure, injected `lookup`):** head of a non-superseded row is the row itself; two-link chain resolves to the newest row; missing target → null; archived target → null; different `tmuxSession` → null; cycle (A→B→A) → null; `sessionOwners` drops superseded rows and keeps the first row per session.
