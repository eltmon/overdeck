# PAN-4370: Prompt-time memory injection almost never injects a memory

**Issue:** [PAN-4370](https://github.com/eltmon/overdeck/issues/4370) · **Blocks:** #4373 (Jev memory relevance filter) · **Sibling split out:** #4374 (`claude-cli` extraction provider) · **Source PRD:** `.pan/drafts/jev-integration.md` "Issue 3"

Date: 2026-09-29. Planned in `pan plan --auto` mode; no operator questions were asked. Every choice is recorded under "Decisions".

---

## Glossary

- **Observation** — one structured memory record (`MemoryObservation`) extracted from an agent turn by an LLM. Stored as JSONL under `~/.overdeck/memory/<project>/<workspaceId>/observations/` and indexed into the per-project FTS5 table `memory_fts` in `~/.overdeck/memory/<project>/memory-search.db`.
- **Extraction** — the background LLM call that turns a compressed transcript delta into an observation (`extractObservationFromTurn`, `src/lib/memory/extract.ts`). Runs through the provider policy.
- **Provider policy** — `extractWithProviderPolicy` in `src/lib/memory/providers/policy.ts`. Resolves the configured provider (`memory.extraction.provider` / `.model` in `~/.overdeck/config.yaml`, or env `OVERDECK_MEMORY_PROVIDER` / `OVERDECK_MEMORY_MODEL`), enforces the daily cost cap, tries the primary plus one fallback, and writes memory health.
- **Query expansion** — `expandMemoryQuery` in `src/lib/memory/query-expansion.ts`. Asks the extraction provider for 3-5 BM25 search terms for the user's prompt. On the `user-prompt` surface it has a 750 ms budget (`PROMPT_TIME_EXPANSION_TIMEOUT_MS`, `src/lib/memory/injection.ts`).
- **Fallback** — the expansion result when expansion does not produce terms: `status: 'fallback'`, `query` = the raw prompt, `reason` = why.
- **Prompt-time injection** — `injectPromptTimeMemory` in `src/lib/memory/injection.ts`. On every user prompt it searches memory and injects the selected context. Called from `src/lib/agents/runtime-command.ts` (hook process, surface `user-prompt`) and `src/lib/agents/spawn-prep.ts` (surface `spawn`).
- **RAG decision log / rag-runs** — append-only JSONL at `~/.overdeck/memory/<project>/<workspaceId>/rag-runs/<date>.jsonl`. Two line types: `type: "query-expansion"` (one per expansion attempt) and `type: "rag-decision"` (one per injection, with `outcome`, `reason`, `query`, `hitCounts`, `expansion.status/reason`).
- **Memory health** — `~/.overdeck/memory/<project>/<workspaceId>/health.json`, written by `updateMemoryHealth` (`src/lib/memory/health.ts`): `status`, `last_success`, `last_failure`, `last_failure_detail`, `failed_by_reason` counts.
- **Match mode** — how `searchMemory` joins query terms into an FTS5 `MATCH` expression. `all` = space-joined quoted terms (FTS5 implicit AND, today's only behavior). `any` = terms joined with ` OR ` (BM25 still ranks rows that match more terms higher).
- **Keyword query** — the prompt reduced to distinct content words: tokenized, lowercased, stopwords and tokens shorter than 3 characters removed, capped at 12 terms.

## Root cause (diagnosed during planning, 2026-09-29, operator host)

There are **two independent causes**. Fixing either one alone does not restore injection.

**Cause A — the configured provider cannot authenticate, so extraction and expansion fail on every call.**
- `~/.overdeck/config.yaml` has `memory.extraction.provider: anthropic`, `model: claude-haiku-4-5`. The `anthropic` provider (`src/lib/memory/providers/anthropic.ts`, line 20: `constructor(private readonly client = new Anthropic()) {}`) uses the Anthropic SDK, which reads only `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` from the environment.
- No dashboard `server.js` process has either variable, the hook environment has neither, and `api_keys` in `config.yaml` has no Anthropic entry. The host uses a Claude subscription only.
- Every recent `health.json` reads, verbatim: `"last_failure_detail": "anthropic/claude-haiku-4-5: Could not resolve authentication method. Expected one of apiKey, authToken, credentials, config, or profile to be set. ..."` with `extractions_succeeded: 0` (for example `panopticon-cli/<ws>/health.json`: 1664 attempts, 0 successes).
- The SDK throws this error before any network call, so it is fast; the 750 ms timeout is **not** the cause. Query expansion maps the policy's `dropped` result to `reason: 'extraction-failed'` (`query-expansion.ts` line 104), which hides the auth cause.
- The newest observation file in `~/.overdeck/memory/overdeck/*/observations/` was written 2026-08-13. `memory_fts` for `overdeck` holds 694 observations, the newest dated 2026-08-13. Nothing has been extracted since.
- No `memory-extraction` cost events exist because `recordExtractionCost` runs only after a successful API response (`anthropic.ts` line 63). This is a symptom, not a separate bug.

**Cause B — the FTS query ANDs every term, so even existing observations never match.**
- `buildMatchQuery` (`src/lib/memory/search.ts` line 166: ``return extractQueryTerms(query).map((term) => `"${term.replaceAll('"', '""')}"`).join(' ');``) joins quoted terms with spaces. FTS5 treats that as AND.
- On fallback the query is the whole raw prompt, so a row must contain every word of the prompt. Measured against the real `overdeck` index: a 17-word prompt → **0** hits under AND, 694 under unfiltered OR.
- Even a successful expansion fails: the two term sets `claude -p` returned for the same prompt during planning → **0** hits each under AND, 628 under OR.
- Keyword-filtered OR (`review agent posts findings verification gate`) ranks "Prioritized stale verification-gate failure and began addressing 3 blocking review findings…" first. BM25 ranking works once OR is used.

**Why 8 of 5,950 decisions had hits:** only prompts short enough that every word appeared in one observation could match under AND.

## Scope

In scope: make prompt-time retrieval find existing observations (Cause B), name provider auth failures instead of hiding them (Cause A reporting), name expansion timeouts, and surface the failure cause in `pan memory doctor` and `pan doctor`.

Out of scope (see Non-goals): adding a subscription-backed provider (filed as #4374), changing the configured provider or the defaults, changing the 750 ms budget, relevance filtering of OR results (#4373).

## Decisions

- **D-1 (Cause B fix):** prompt-time injection uses OR (`matchMode: 'any'`) over the keyword query for all three of its searches. CLI `pan memory search` keeps AND. *Why:* BM25 already ranks multi-term matches first; AND makes BM25 pointless for 3+ terms. The CLI is an explicit operator query where AND is the expected semantic.
- **D-2 (stopwords):** the keyword filter is load-bearing: unfiltered OR matched all 694 rows. The stopword list is fixed in code (WI-1), not configurable.
- **D-3 (no provider switch):** the operator's config names `anthropic` explicitly. The code does not auto-switch to another provider when credentials are missing, and defaults do not change. The failure is reported with a fix hint instead.
- **D-4 (subscription provider split out):** a `claude-cli` provider (measured 6.3 s per `claude -p` call on this host) is independently shippable and has its own review questions (process spawn per turn, the one-shot-exec rule, notional cost against the $5/day cap). Filed as #4374. No acceptance criterion here depends on it: FR-4 is met from the 694 existing observations.
- **D-5 (750 ms unchanged):** this issue makes timeouts measurable (`reason: 'timeout'`) instead of changing the budget. No provider on this host can meet 750 ms today (cliproxy `gpt-5.5`: 2.3 s; `claude -p`: 6.3 s), so fallback retrieval (D-1) is what makes injection work.
- **D-6 (no return-type ripple):** the policy's `dropped.reason` union is unchanged so `extract.ts`, `rollup.ts`, and `feature-registry-population.ts` need no edits. Classification uses the `error` field the dropped result already carries.
- **D-7 (preflight only for the default client):** the anthropic preflight runs only when the provider builds its own SDK client. A caller-injected client (tests) is trusted as-is.
- **D-8 (doctor reads evidence, not env):** `pan doctor` runs in the operator's shell, whose environment is not the dashboard's or the hook's. An env check there can say OK while every extraction fails, so the row reads `health.json` files.
- **D-9 (docs home):** the issue suggests `configuration/memory-governor.mdx`, but that page documents the RAM governor. The agent-memory docs live in the "Memory scopes" section of `configuration/workspaces.mdx`; the new material goes there, plus `docs/MODEL-CALLS.md`.

   ```ts
     'other', 'over', 'same', 'such', 'than', 'too', 'very', 'here', 'yes', 'okay', 'thanks',
   ]);

   /** Distinct content words of `text` for an OR-mode FTS query (PAN-4370): lowercased, stopwords and <3-char tokens dropped, first 12 kept in order. */
   export function buildPromptKeywordQuery(text: string): string {
     const seen = new Set<string>();
     const keywords: string[] = [];
     for (const term of extractQueryTerms(text)) {
       const lower = term.toLowerCase();
       if (lower.length < KEYWORD_MIN_LENGTH || KEYWORD_STOPWORDS.has(lower) || seen.has(lower)) continue;
       seen.add(lower);
       keywords.push(lower);
       if (keywords.length === KEYWORD_QUERY_MAX_TERMS) break;
     }
     return keywords.join(' ');
   }
   ```
