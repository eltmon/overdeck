**What this issue does.** It adds one GitHub Actions job, `integrations`, to `.github/workflows/ci.yml`. The job checks that the four copies of the shared Overdeck skill match their source, runs the Hermes plugin's pytest suite, and builds and tests the OpenClaw plugin from its own lockfile. The job feeds the `test` aggregator, so a red package blocks merge and reaches the work agent as CI verification feedback. It also documents the job in `integrations/README.md` and in the codebase map.

## Glossary

- **Integration packages:** the outside-bot plugins under `integrations/` (PAN-4927 Part B): `hermes/` (a Python package), `openclaw/` (an npm package with its own `package-lock.json`, not a root Bun workspace), `grok-build/` and `grok-bot/` (manifest-only packages with no build step), and `shared/` (the one skill text and its sync script).
- **Shared skill check:** `node integrations/shared/sync-skill.mjs --check`. It writes nothing; it exits 1 when any of the four copies `integrations/<platform>/skills/overdeck/SKILL.md` differs from `integrations/shared/SKILL.md` or is missing, and prints `✓ 4 skill copies match integrations/shared/SKILL.md` on success (`integrations/shared/sync-skill.mjs`, the `if (parsed.check)` branch).
- **Root suite / test shards:** the root Vitest run split over four `test-shard (N/4)` jobs (`ci.yml` job `test-shard`). Its include globs (`vitest.config.ts` `defaultInclude`) are `tests/**/*.test.ts` and similar; they do **not** include `integrations/**`, so the OpenClaw package's own `integrations/openclaw/tests/*.test.ts` never run in the root suite. The root suite does run `tests/unit/integrations/*.test.ts` (manifest, README and sync-skill tests for all four packages, including both Grok packages).
- **`test` aggregator:** the `test` job in `ci.yml` (line 337). It runs nothing itself; it `needs` the other test jobs and is green only when each one concluded `success`. Its check name `test` is what Overdeck reads: `TEST_GATE_NAME = 'test'` (`src/lib/cloister/verification-tests-mode.ts:57`), `isCiTestCheckName` (same file, line 96, regex `^tests?(?:\s*\(.*\)|[-_:].*|\s+\/\s+.*)?$`), and the close-out list `DEFAULT_MAIN_VERIFY_REQUIRED_CHECKS = ['test', 'lint', 'build (22)', 'reject-planning-paths']` (`src/lib/lifecycle/dod-gate.ts:165`).
- **CI verification feedback:** for a project whose tests run on CI (`verification.tests: ci`, PAN-3965), a red CI test job on the PR head is delivered to the work agent as `VERIFICATION FAILED … Failed check: test` by `src/lib/cloister/ci-failure-feedback.ts`; the feedback file lists every failing check run with an excerpt of its job log (`docs/PIPELINE-GATES.md`, "What the CI failure feedback contains (PAN-4534)").
- **SSH push:** `git push git@github.com:eltmon/overdeck.git HEAD:feature/pan-4957`. Needed because the `gh` OAuth token used for HTTPS pushes lacks the `workflow` scope, so GitHub refuses any HTTPS push that changes a file under `.github/workflows/`.

## Requirements

### Functional

- **FR-1 (from PAN-4927 FR-15).** A job with the id `integrations` in `.github/workflows/ci.yml` runs on every pull request to `main` and every push to `main` that the workflow already runs on, with no `paths` filter and no job-level `if:`.
- **FR-2.** The job runs the shared skill check `node integrations/shared/sync-skill.mjs --check` and fails when it exits non-zero.
- **FR-3.** The job installs the Hermes plugin with its `test` extra on Python 3.11 and runs `python -m pytest integrations/hermes`, failing when any test fails.
- **FR-4.** The job runs `npm ci`, `npm run build` and `npm test` in `integrations/openclaw`, failing when any of them exits non-zero.
- **FR-5.** The `test` aggregator `needs` the `integrations` job and fails unless `integrations` concluded `success`.
- **FR-6.** `integrations/README.md` and the codebase map's `integrations/` row name the `integrations` CI job and what it runs.

### Non-functional

- **NFR-1 Self-contained job.** The job does not run `bun install`, `npm run build` at the root, Playwright installs or ripgrep installs. It needs only checkout, Node 22, Python 3.11 and the package-local installs.
- **NFR-2 Bounded wall clock.** The job sets `timeout-minutes: 10` (repo rule PAN-1651; the measured work is under one minute plus installs).
- **NFR-3 Style match.** Steps use `actions/checkout@v4`, `actions/setup-node@v4` with `node-version: 22` (matching every other job), and `actions/setup-python@v5` with `python-version: '3.11'`. A comment block above the job names the issue and what it covers, like the `mobile-android` comment at `ci.yml:283-285`.
- **NFR-4 No new test files.** The job itself is the test (parent PRD W-CI1 "Tests: the job passes on the PR that adds it"). Do not add a Vitest file that reads `ci.yml`: new source-reading tests trip `lint:source-introspection`.
- **NFR-5 No repo-root pollution.** Local verification writes only gitignored paths (`.tmp/`, `integrations/openclaw/node_modules`, `integrations/openclaw/dist`, `__pycache__/`); `git status --porcelain` stays clean apart from the intended edits.

## Decisions

- **D-1 Job id is exactly `integrations`.** AC-29 names it. It does not match `isCiTestCheckName` (the regex wants a `test`/`tests` prefix), so Overdeck does not treat it as a test check by itself. Renaming it to `test-integrations` would contradict AC-29; D-2 makes it count instead.
- **D-2 Wire `integrations` into the `test` aggregator** (the PRD says only "next to `mobile-android`"). Without it the job is advisory: a red `integrations` check would neither block Overdeck's merge gate nor reach the work agent as verification feedback, because both read the `test` check. Precedent: `mobile-android` (PAN-4837 D-10). Consequence: the job must never be skipped (FR-1), because a skipped `needs` job makes `test "<result>" = success` fail.
- **D-3 Run on every PR, no `paths` filter.** The parent PRD says "on every PR", D-2 forbids skipping, and the job is small (two package installs plus ~175 fast tests).
- **D-4 Placement.** Insert the job immediately after `mobile-android` (after `ci.yml:332`, `retention-days: 7`) and before the aggregator's comment block (`ci.yml:333`).
- **D-5 `working-directory:` instead of `cd`.** The OpenClaw steps use `working-directory: integrations/openclaw`, as the `mobile-android` Gradle step does (`working-directory: apps/mobile/android`). One step per command so the failing command is the failing step name.
- **D-6 No dependency caching.** Neither `cache: pip` nor `cache: npm`. The installs take seconds (47 npm packages; pytest and hatchling), and caching adds keys to maintain.
- **D-7 Grok packages stay in the root suite.** `tests/unit/integrations/grok-build*.test.ts` and `grok-bot*.test.ts` already run in the test shards (parent PRD: "The Grok tests run in the existing vitest shards"). Grok packages have no build or package-local tests, so the job has no Grok step.
- **D-8 Docs scope is the CI fact only.** `integrations/README.md` and the codebase map row. The Mintlify pages (`configuration/bots.mdx`, `configuration/mcp.mdx`, …) belong to W-DOC ([PAN-4958](https://github.com/eltmon/overdeck/issues/4958)) and do not describe CI jobs.

## Implementation checkpoints

- **CP-1 Green on the PR (AC-29).** The job can only be proven green on GitHub. After `pan done` opens the PR (or after an SSH push updates it), read `gh pr checks <pr>` for the whole job set. **Fallback:** if `integrations` is red, read its job log (`gh run view --log-failed --job <id>` or `gh api repos/eltmon/overdeck/actions/jobs/<id>/logs`), fix the cause in this branch, and push again over SSH. If the failure is in package code rather than the job (a real test failure that also fails locally on `main`), stop and `pan tell flywheel-orchestrator` — fixing package code is outside this issue.

## Hazards

- **H-1 HTTPS push of a workflow file is refused.** Push with `git push git@github.com:eltmon/overdeck.git HEAD:feature/pan-4957`. If `pan done`'s own push fails for the same reason, push over SSH first, then re-run `pan done`.
- **H-2 Reflex copying from neighbouring jobs.** Every other job runs `bun install --frozen-lockfile` and often `npm run build`; this job must not (NFR-1). It would add minutes and couple the job to the root lockfile.
- **H-3 A skipped `integrations` job turns `test` red** (D-2). Never add a `paths` filter or job-level `if:`.
- **H-4 Feedback shape.** When `integrations` fails, the feedback file lists the `integrations` check run with its job-log excerpt and also the `test` aggregate (the aggregate is dropped only when its log names a failing job with the same `test` prefix, `docs/PIPELINE-GATES.md` PAN-4534 paragraph). Read the `integrations` section; the `test` section only echoes results.
- **H-6 AC-4 needs a PR before `pan done`.** `pan done` refuses while an acceptance criterion is pending, and "green on the PR" can only be checked once a PR exists. Order: SSH-push the branch; `gh pr create --base main --head feature/pan-4957`; wait once with `gh pr checks <pr> --watch`; `pan task done` the AC; then `pan done`, which adopts the open PR (`src/dashboard/server/routes/workspaces/ensure-pr.ts:69-72`: `gh pr list --head <branch>` → an `OPEN` PR returns `created: false`).
- **H-5 Local probes leave ignored files.** `node_modules/`, `dist/`, `__pycache__/` and `.tmp/hermes-venv` are gitignored; never `git add -f` them.
