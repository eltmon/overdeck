# PAN-4481 — Shared Sessions v0 (slice 10): hosted web join page

**Issue:** [PAN-4481](https://github.com/eltmon/overdeck/issues/4481) · **Parent:** [PAN-658](https://github.com/eltmon/overdeck/issues/658) (PRD `.pan/drafts/pan-658.md` rev 3, *Operator decisions → OD-1*) · **Depends on:** [PAN-4475](https://github.com/eltmon/overdeck/issues/4475) (merged, `5d941630c45`), [PAN-4831](https://github.com/eltmon/overdeck/issues/4831) (merged, `ea4f2547d12`).

**Operator decision (2026-11-02, issue comment):** build it. Anyone can join a shared conversation from a browser at `share.overdeck.ai/s/<code>` after a GitHub sign-in, with no install. Scope: (1) a web sign-in flow on the account service, (2) a static viewer bundle served by the share Worker at `/s/:code`, (3) a browser viewer signaling WebSocket path authenticated by that web session. Conversation content stays peer-to-peer and encrypted; overdeck.ai serves only the page and the signaling. PAN-4831 also changed `services/account/src/pkce.ts`; keep the redirect rules as separate functions.

This PRD is written for an implementation model that cannot re-research the code. Every file and line below was read on 2026-11-03 at `a84ad3e4081`. Where a line number may drift, search for the quoted code.

## Glossary

| Term | Meaning |
| --- | --- |
| **share Worker** | The Cloudflare Worker in `services/share/` (`overdeck-share`, `https://share.overdeck.ai`). Rendezvous and admission only; one `ShareRoom` Durable Object (DO) per room. |
| **account Worker** | The Cloudflare Worker in `services/account/` (`overdeck-account`, `https://account.overdeck.ai`). GitHub sign-in, device tokens, invite-only allowlist. |
| **device token** | `odd_` + 64 lowercase hex. Minted by the account Worker; only its SHA-256 is stored. Verified with `AccountRpc.verifyDevice(token)` over a service binding. |
| **service binding / `AccountRpc`** | The share Worker's `ACCOUNT` binding to the account Worker's `AccountRpc` `WorkerEntrypoint` (`services/account/src/index.ts`). Calls never cross the public internet. |
| **PKCE flow** | The account Worker's `GET /auth/start` → GitHub → `redirect_uri?code=odc_…&state=…` → `POST /oauth/token` flow (`services/account/src/pkce.ts`). |
| **redirect rule** | One function that decides whether a `redirect_uri` is acceptable. Today: `validateLoopbackRedirect` (local dashboard) and the exact `NATIVE_APP_REDIRECT` (phone app, PAN-4831). This issue adds a third: `validateShareRedirect`. |
| **web device** | A device row minted for a browser that signed in on `share.overdeck.ai`. `platform = 'web'`, default label `Web browser`. |
| **web session** | The share Worker's `__Host-ods_session` cookie. It holds the browser's device token **sealed** (AES-GCM encrypted) with the Worker secret `WEB_SESSION_KEY`. Page JavaScript never sees the token. |
| **sealed cookie** | A cookie value that is `base64url(iv ‖ AES-GCM ciphertext)` of a small JSON payload, so only the share Worker can read or forge it. |
| **hosted viewer** | The browser bundle `public/viewer/viewer.js` built from `services/share/web/*.ts`. It talks to the share Worker directly (WebSocket) and to the host over WebRTC, reusing slice 4's `WebRtcViewer`. |
| **web-join socket** | `GET /v1/rooms/:code/web-join?v=1`: the browser's viewer signaling WebSocket, authenticated by the web session cookie and an `Origin` check. It speaks the existing viewer protocol (`ViewerFrame` / `ServiceToViewerFrame`). |
| **join intent is a click** | PAN-4475 D-1: opening a join socket reveals the joiner's GitHub identity to the host, so it must only happen after the user clicks **Join**, never as a side effect of loading a URL. |
| **restart dance** | PAN-4474 rule: to get a fresh host offer, a viewer closes its join socket (code 1000, no `leave`), waits for that socket's `close` event, then opens a new one. Opening the new socket first gets the old one replaced with 4008 and the host never re-offers. |
| **OD-2** | PAN-658 operator decision: viewers must be allowlisted overdeck.ai accounts. Unchanged by this issue. |

## Problem

PAN-658 v0 lets a person join a shared conversation only from their own installed Overdeck dashboard. The `/s/:code` page (`services/share/src/pages.ts`) probes `localhost:3011` and otherwise tells the visitor to install Overdeck. The operator's goal is "give someone a link to a conversation and that person can join it and talk with the AI directly". A person without Overdeck installed cannot join at all.

Two pieces are missing:

1. **Browser sign-in.** The account Worker accepts only loopback redirects (local dashboard), the phone app's private-use redirect, and the device flow. A page on `share.overdeck.ai` has no way to obtain an identity. The account Worker also sends no CORS headers (`services/account/src/http.ts` line 5: "No response ever carries an Access-Control-* header"), so a page cannot call `/oauth/token` itself.
2. **Browser viewer transport.** The share Worker's `/v1/rooms/:code/join` needs `Authorization: Bearer odd_…`. A browser `WebSocket` cannot set headers. The slice 4 viewer (`src/dashboard/frontend/src/components/chat/sharing/`) reaches the share Worker only through the viewer's own dashboard server (`/api/joins/*`).

## Goal

A person with a browser and an allowlisted GitHub account opens `https://share.overdeck.ai/s/<code>`, clicks **Sign in with GitHub**, comes back to the same page, clicks **Join**, waits in the lobby, and after the host admits them reads the live conversation in the browser. Content flows only over the WebRTC data channels between the host's dashboard and the browser.

## Requirements

### Functional

- **FR-1** The account Worker accepts exactly `<SHARE_BASE_URL>/auth/callback` as a PKCE `redirect_uri`, through a new `validateShareRedirect` function kept separate from the loopback and native-app rules. Any other `https:` URL is still refused with the 400 page.
- **FR-2** The account Worker accepts `platform=web` only together with the share redirect, and the share redirect only together with `platform=web`. A web device gets the default label `Web browser`.
- **FR-3** `AccountRpc.redeemWebCode({ code, codeVerifier, redirectUri })` exchanges a share-redirect authorization code for a device token with exactly the rules of `POST /oauth/token` (single use, 5-minute expiry, identical redirect, S256 verifier, allowlist re-check). It refuses any `redirectUri` that is not the share redirect.
- **FR-4** `AccountRpc.signOutDevice(token)` revokes the device of a valid token (`revoked_by = 'user'`).
- **FR-5** The share Worker runs the browser sign-in: `GET /auth/signin?code=<CODE>` → account `/auth/start` → GitHub → `GET /auth/callback` → `redeemWebCode` → sets the sealed `__Host-ods_session` cookie → 303 to `/s/<CODE>`.
- **FR-6** Sign-in failures render a plain HTML page with a link back to `/s/<CODE>`: not allowlisted (`invite_only`), cancelled on GitHub (`github_denied`), account being deleted (`account_deleting`), an expired or mismatched sign-in (state cookie missing, wrong, or older than 10 minutes), and an unavailable account service.
- **FR-7** `GET /v1/web/session` reports the browser's identity from the web session (`signedIn`, `githubId`, `login`, `avatarUrl`), or `signedIn: false` with an optional `reason`.
- **FR-8** `POST /auth/signout` (same-origin only) revokes the web device through `signOutDevice`, clears the session cookie and redirects 303 back to `/s/<CODE>`.
- **FR-9** `GET /v1/rooms/:code/web-join?v=1` upgrades to the existing viewer socket for a request that carries a valid web session and `Origin` equal to `PUBLIC_BASE_URL`. The Durable Object receives the same `X-Share-Identity` header as for `/join`, so room rules are unchanged.
- **FR-10** The `ShareRoom` DO answers the text frame `ping` with `pong` through the runtime auto-response, without waking and without reaching the frame decoder.
- **FR-11** The `/s/:code` page for an active room shows a **Join in this browser** section when web join is configured, keeps the localhost probe, and stops the probe's automatic navigation once the visitor has started a browser join.
- **FR-12** The hosted viewer shows: signed-out, signed-in confirmation with **Join**, connecting, lobby, waiting for the host's offer, the conversation (roster plus messages), the host-disconnected banner, a lost-peer screen with **Reconnect**, and one terminal screen per final state (`left`, `kicked`, `revoked`, `ended`, `is-host`, `full`, `replaced`, `rejected`, `disconnected`).
- **FR-13** The hosted viewer requests ICE servers after `status admitted`, caches them for 50 minutes, sends a `ping` every 30 s and declares the connection lost after 75 s without a `pong`, performs the restart dance for **Reconnect**, and restarts once on its own when no offer arrives within 10 s of `status admitted`.
- **FR-14** A browser reload of an admitted viewer rejoins without a second click, using a per-tab `sessionStorage` marker that only a **Join** click sets.
- **FR-15** `GET /viewer/viewer.js` serves the built bundle from the Worker's static assets.

### Non-functional

- **NFR-1** The device token never reaches page JavaScript or browser storage in usable form: it exists only inside the sealed `HttpOnly; Secure; SameSite=Strict` `__Host-ods_session` cookie.
- **NFR-2** Every cross-Worker call goes through the `ACCOUNT` service binding. No new public-internet hop between Workers.
- **NFR-3** Conversation content never transits the share Worker (unchanged PAN-658 NFR-1). The viewer renders message text only through `textContent`; it never assigns `innerHTML` from host data.
- **NFR-4** The hosted page's CSP allows scripts only from `'self'` and the nonce'd probe, connections only to the share origin (`https`, `wss`) and the two localhost probe origins, and images only from `https://avatars.githubusercontent.com`.
- **NFR-5** The minified viewer bundle is at most 64 KiB (65,536 bytes) and contains no React and no `effect` code.
- **NFR-6** Web join is optional configuration: without `ACCOUNT_BASE_URL` or a valid `WEB_SESSION_KEY`, the web routes answer 503 `not_configured`, `/healthz` reports `"web": false`, and the `/s/:code` page renders exactly as today.
- **NFR-7** No agent deploys. Deploy ordering is an operator checkpoint (account Worker first, then the share Worker with its new secret).

## Decisions (made here, not left to the implementer)

- **D-1 — The share Worker is the OAuth client.** The account Worker sends no CORS headers, so the browser cannot exchange a code. The share Worker generates state and the PKCE verifier, keeps them in a sealed cookie, and redeems the code over the service binding (`redeemWebCode`). This is the backend-for-frontend pattern; it keeps PAN-658 D-R3-2 ("credentials live only in servers").
- **D-2 — Reuse the PKCE purpose; no new auth purpose and no migration.** `auth_requests.purpose` has a CHECK of `('pkce','device','admin')` and `pending_attempts.last_flow` a CHECK of `('pkce','device')` (`services/account/migrations/0001_init.sql`). The web flow is the PKCE flow with a third redirect rule, so neither column changes. `devices.platform` and `auth_codes.platform` have no CHECK, so `web` needs only the `PLATFORM_RE` change.
- **D-3 — A web sign-in is a device.** It is minted by `mintDevice` with `platform = 'web'` and a per-browser `environment_id` (lowercase UUID v4 kept in the `__Host-ods_env` cookie). Signing in again from the same browser rotates the token in place (existing `mintDevice` behaviour). The device appears in `GET /v1/devices` and is revoked by operator revoke and account deletion with no new code.
- **D-4 — Sealed cookies.** Both the session cookie and the transient sign-in cookie are AES-GCM sealed with `WEB_SESSION_KEY` (a Worker secret, 64 hex characters = 32 bytes). A stolen cookie is useless outside the share Worker, and the Worker can trust the cookie's contents (state, verifier, code, issue time) without a database.
- **D-5 — A separate browser socket path.** `/v1/rooms/:code/join` stays bearer-only, so "`/v1/*` sockets are never authenticated by ambient credentials" stays true for the server path. The browser uses `/v1/rooms/:code/web-join`, which requires the session cookie **and** `Origin === PUBLIC_BASE_URL` (cross-site WebSocket hijacking defence; the same check the account Worker uses on `/activate`).
- **D-6 — Cookie attributes.** `__Host-ods_session`: `HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=2592000` (30 days; the sealed payload also carries its issue time and is refused after 30 days). `__Host-ods_signin`: `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=600` (Lax because it must survive the GitHub → account → share redirect chain). `__Host-ods_env`: `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=34560000` (400 days, the browser maximum; not secret).
- **D-7 — OD-2 stands.** The account Worker stays invite-only. A non-allowlisted GitHub user who signs in gets the `invite_only` page and leaves a pending attempt the operator can allow. No identity-only participant grant.
- **D-8 — Plain-DOM viewer, built with esbuild.** The hosted viewer is plain TypeScript and DOM APIs, no React, no `MessagesTimeline`, no markdown rendering (message text is shown with `white-space: pre-wrap`). It is bundled by `esbuild` `0.28.1` (the exact version wrangler `4.146.0` already resolves) added as a devDependency of `services/share`. It reuses `WebRtcViewer` from `src/dashboard/frontend/src/components/chat/sharing/webrtc-viewer.ts` by relative import; that file imports `@overdeck/contracts`, which the bundle and the viewer tsconfig both alias to a local shim re-exporting only `packages/contracts/src/sharing.ts` and `sharing-wire.ts` (both free of runtime dependencies), so `effect` never enters the bundle.
- **D-9 — Static assets binding, Worker first.** `wrangler.jsonc` gains `"assets": { "directory": "./public", "binding": "ASSETS", "run_worker_first": true }` and `"build": { "command": "node scripts/build-web.mjs" }`. The Worker serves `/viewer/viewer.js` through `env.ASSETS.fetch`, so every response still carries the Worker's security headers. `public/viewer/` is gitignored; `public/.gitkeep` is committed so the directory always exists.
- **D-10 — Keep the localhost probe.** An installed dashboard is still preferred. The probe's `location.assign` runs only when `document.documentElement.dataset.hostedJoin` is not `"started"`; the viewer sets that flag on a **Join** click and on a reload rejoin.
- **D-11 — Join intent stays a click.** Sign-in returns to `/s/<CODE>` and shows **Join**; it never opens the socket by itself. The reload rejoin uses `sessionStorage` (per tab, not settable by a link), so a crafted URL cannot open a socket.
- **D-12 — Offer watchdog.** A reload can open the new socket before the DO processed the old socket's close, which replaces the old one with 4008 and the host never re-offers. The viewer therefore runs the restart dance once on its own when no offer arrives within 10 s of `status admitted`. A second miss shows **Reconnect** instead of looping.
- **D-13 — Pre-open failures.** A browser cannot read the HTTP status of a refused WebSocket upgrade. When the web-join socket fails before `open`, the viewer re-reads `/v1/web/session`: signed out → the sign-in screen; signed in → state `disconnected` with the text "Could not reach the share. It may have ended; reload the page to check."
- **D-14 — Read-only in this slice.** The hosted viewer has no composer. Prompt drafts and contributor direct-submit are slice 5 ([PAN-4476](https://github.com/eltmon/overdeck/issues/4476)); that slice adds the composer to both viewers.
- **D-15 — Avatars from the GitHub id.** The viewer builds every avatar URL as `https://avatars.githubusercontent.com/u/<githubId>` from the numeric id and ignores the `avatarUrl` string the host sends.
- **D-16 — Licensing.** `services/` is FSL-1.1-MIT (`services/LICENSE.md`); the bundle includes MIT code from `packages/contracts` and the dashboard frontend, which is compatible. No license file changes.

## Architecture

```
browser (share.overdeck.ai/s/CODE)                share Worker                     account Worker
 ├─ GET /s/CODE ───────────────────────────────▶ page (probe + #web-join + viewer.js)
 ├─ GET /v1/web/session ───────────────────────▶ unseal cookie ─ verifyDevice ───▶ AccountRpc
 ├─ click "Sign in" → GET /auth/signin?code ───▶ seal {state,verifier,code} cookie
 │      302 ─────────────────────────────────────────────────────────────────────▶ /auth/start (share redirect, platform=web)
 │      GitHub leg …  302 → share /auth/callback?code=odc_…&state ◀───────────────┘
 ├─ GET /auth/callback ────────────────────────▶ check state ─ redeemWebCode ────▶ AccountRpc (mintDevice)
 │      303 /s/CODE + Set-Cookie __Host-ods_session (sealed odd_ token)
 ├─ click "Join" → WSS /v1/rooms/CODE/web-join ▶ Origin + cookie ─ verifyDevice ─▶ AccountRpc
 │                                               └─ forward upgrade, X-Share-Identity ─▶ ShareRoom DO (unchanged rules)
 └─ RTCPeerConnection ◀═══════ DTLS data channels ═══════▶ host dashboard (PeerHub, unchanged)
```

/** GET /v1/rooms/:code/web-join: the hosted viewer's signaling socket, authorized by the web session (PAN-4481). */
const webJoinSocket: Handler = async (req, rc) => {
  const refused = upgradeRefusal(req);
  if (refused) return refused;
  if (!rc.config.web) return json({ error: 'not_configured', missing: missingWebConfig(rc.env) }, 503);
  if (req.headers.get('Origin') !== rc.config.publicBaseUrl) return json({ error: 'forbidden_origin' }, 403);

  const shortCode = normalizeShortCode(rc.params['code'] ?? '');

  return forwardUpgrade(rc.env, shortCode, INTERNAL.join, { [HDR_IDENTITY]: JSON.stringify(verified.identity) });
};

### WI-7 `web-join-socket` — the browser join state machine (FR-13, D-12, D-13)

**Files:** `services/share/web/join-socket.ts` (new), `tests/unit/services/share/web/join-socket.test.ts` (new). Depends on WI-6.

`BrowserJoin` owns one web-join socket at a time. No DOM access. Everything it takes from `@overdeck/contracts` is an `import type` (root Vitest aliases `@overdeck/contracts` to the full `packages/contracts/src/index.ts`; type-only imports keep the test and the bundle lean). `view.ts` (WI-8) likewise uses `import type` for contracts and for `webrtc-viewer.ts`. Dependencies are injected:

```ts
export interface BrowserJoinDeps {
  WebSocket: { new (url: string): WebSocket };   // the browser global in production
  url: string;                                   // wss://<host>/v1/rooms/<CODE>/web-join?v=1
  now(): number;
  setTimeout: typeof setTimeout; clearTimeout: typeof clearTimeout;
  setInterval: typeof setInterval; clearInterval: typeof clearInterval;
}
export type BrowserJoinState = Exclude<JoinState, 'away'>;   // JoinState from @overdeck/contracts
export interface BrowserJoinView { state: BrowserJoinState; contributor: boolean; closeCode: number | null; error: string | null }
export interface BrowserJoinCallbacks {
  onView(view: BrowserJoinView): void;
  onSignal(data: SignalData): void;     // only while admitted or host-disconnected
  onPreOpenFailure(): void;             // D-13: socket failed before 'open'
}
export const PING_INTERVAL_MS = 30_000, PONG_TIMEOUT_MS = 75_000, ICE_TIMEOUT_MS = 5_000,
  ICE_CACHE_MS = 50 * 60_000, CLOSE_FALLBACK_MS = 5_000, OFFER_WATCHDOG_MS = 10_000;
export class BrowserJoin {
  constructor(deps: BrowserJoinDeps, callbacks: BrowserJoinCallbacks);
  join(): void;                         // opens a socket; state 'connecting'
  leave(): void;                        // sends {"type":"leave"}; 'left' on close or after CLOSE_FALLBACK_MS
  reconnect(): void;                    // restart dance
  sendSignal(data: SignalData): void;   // {"type":"signal","data":…}; only answers and candidates are ever passed
  fetchIceServers(): Promise<readonly IceServer[]>;
  close(): void;                        // page unload / teardown: plain close, no callbacks after
}
```

Rules (mirror `src/dashboard/server/services/share-join.ts`, lines 89–98 and 301–329):

- Text `pong` refreshes the pong clock and is not parsed. Every other frame is `JSON.parse`d; non-objects are ignored.
- `status lobby` → `lobby`; `status admitted` → `admitted` (+ `contributor`), then request ICE unless a list younger than `ICE_CACHE_MS` is cached, and arm the offer watchdog; `status host-disconnected` → `host-disconnected`; `status host-reconnected` → `admitted`.
- `signal` with an object `data` is forwarded to `onSignal` only in `admitted`/`host-disconnected`; an `sdp.type === 'offer'` disarms the watchdog.
- `ice-servers` resolves pending `fetchIceServers()` calls and caches the list; `error turn_unavailable` resolves them with `[]`; `ICE_TIMEOUT_MS` without an answer resolves `[]`.
- Close codes: `1000` → `left`, `4003`/`4011` → `revoked`, `4004` → `ended`, `4008` → `replaced`, `4009` → `is-host`, `4010` → `kicked`, `4013` → `full`; a close during `leave()` → `left`; a close the restart asked for → open the next socket (no state change beyond `connecting`); any other close → `disconnected` with `error 'connection_lost'`.
- Keepalive: every `PING_INTERVAL_MS` send the text `ping`; if `PONG_TIMEOUT_MS` passes since the last `pong` (or since `open`), close the socket and become `disconnected` (`connection_lost`).
- Restart dance (`reconnect()` and the watchdog): `socket.close(1000, 'reconnect')` with no `leave`; open the new socket only from the old socket's `close` event, or after `CLOSE_FALLBACK_MS`. Clear the ICE cache's pending waiters with `[]`.
- Offer watchdog: when `OFFER_WATCHDOG_MS` passes in `admitted` with no offer since `status admitted`, restart once. If the restarted socket also gets no offer, do nothing more (the UI shows **Reconnect** through the peer phase).
- An `error`/`close` before `open` calls `onPreOpenFailure()` and sets `disconnected` with `error 'unreachable'`.

Tests (fake WebSocket class recording `send`/`close`, `vi.useFakeTimers()`): each status frame and each close code produces the documented state; `pong` is not parsed; `ping` is sent at 30 s and the socket is closed at 75 s without `pong`; ICE requested once on `admitted`, cached, `turn_unavailable` → `[]`, timeout → `[]`; `reconnect()` sends no `leave` and opens the second socket only after the first's `close` (and after 5 s when no close event arrives); watchdog restarts once at 10 s and not again; signals in `lobby` are dropped; pre-open failure calls `onPreOpenFailure`.
