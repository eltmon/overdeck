## Glossary

- **Diff panel** — the React component `DiffPanel` in `src/dashboard/frontend/src/components/DiffPanel.tsx` (829 lines). It renders a strip of chips ("All turns", "vs main", "Turn N") and, below the strip, either a file picker or the patch for one file.
- **Chip** — one button in the diff panel strip. "All turns" means `selectedTurnId === null`. "vs main" means `selectedTurnId === 'vs-main'`. This issue adds a "Compare…" chip, which means `selectedTurnId === 'compare'`.
- **File picker** — `DiffFilePickerList` in `DiffPanel.tsx`. It renders a `files: TurnDiffFileChange[]` array. An empty array prints "No changed files in this selection."
- **Popout** — the standalone page `/popout/diff`, rendered by `StandaloneDiffPopoutRoute` in `src/dashboard/frontend/src/App/StandaloneRoutes.tsx`. The diff panel's pop-out button opens it with query params (grep `window.open(\`/popout/diff?${params.toString()}\``).
- **Diff URL prefix** — the base URL the panel fetches from: `/api/agents/:agentId/diffs` or `/api/conversations/:name/diffs` (grep `const baseUrl = diffUrlPrefix ??`).
- **Ref** — any string git resolves to a commit: a branch, tag, SHA, or revision expression such as `HEAD~2`.
- **Two-dot compare** — `git diff <baseSha> <headSha>`: every difference between the two commits' trees. Same result as `base..head` for `git diff`.
- **Three-dot compare** — `git diff <mergeBase> <headSha>` where `mergeBase = git merge-base <baseSha> <headSha>`: only the changes on `head` since it diverged from `base`. Same result as `git diff base...head`.
- **Compare repository** — the absolute path, sent by the client as the `repo` query param, of the git checkout to compare in.
- **Allowed roots** — the directories the compare routes accept as a compare repository (rule in Decision D4).
- **Ignore whitespace** — git's `-w` (`--ignore-all-space`) flag. With `-w`, `git diff --patch` omits hunks whose only change is whitespace, and `git diff --numstat` omits files whose only change is whitespace. `git diff --name-status -w` still lists those files (verified empirically on git 2.43.0).
- **Diff options** — the new `DiffOptions` type (`{ ignoreWhitespace?: boolean }`) that every server diff helper accepts after this issue.
- **No-loss matrix** — `tests/unit/lib/overdeck/no-loss-matrix.ts` (`NO_LOSS_MATRIX`). `tests/unit/lib/overdeck/no-loss-matrix.test.ts` fails when an HTTP route exists without a row.
- **Conversation no-loss test** — `tests/unit/dashboard/server/routes/conversations-no-loss.test.ts`. It reads the files in `CONVERSATION_ROUTE_SURFACE_FILES` and locks the exact conversation route list and count.
- **Fixture repository** — a git repository a test creates in a temp directory with `git init`, no remote, and test-set author/committer dates.

## Problem

1. **No two-ref compare.** The panel can show per-turn, all-turns and vs-main diffs only. To see the changes between two commits in a local-only repository (no remote, no PR, straight-line history), an operator must move a scratch branch and hand-build a `/popout/diff` URL.
2. **No way to ignore whitespace.** Every diff path runs `git diff --patch --minimal` without `-w`, so a re-indented block drowns out the real change:
   - `src/lib/checkpoint/checkpoint-manager.ts` line 211 `const args = ['diff', '--patch', '--minimal', '--no-color', fromCommit, toCommit]` (per-turn and all-turns, agents).
   - line 234/239 numstat and name-status in `diffCheckpointFilesBody` (all-turns file list, agents).
   - line 350 `const args = ['diff', '--patch', '--minimal', '--no-color', 'main...HEAD']` and lines 359/364 (vs-main, agents).
   - line 426 `const args = ['diff', '--patch', '--minimal', '--no-color', baseCommit]` (`diffPatchSinceCommit`, conversations).
   - line 436 `'diff', '--patch', '--minimal', '--no-color', 'HEAD', '--', ...filePaths,` (`diffPatchFilesAgainstHead`, conversations).
   - `src/lib/overdeck/conversation-diffs.ts` line 166 `` `git diff --patch --minimal --no-color ${baseCommit} -- ${quotedPaths}` `` (`diffPatchForFiles`, conversations).

## Decisions

- **D1 — One generic compare endpoint, not per-agent/per-conversation routes.** `GET /api/diffs/compare` takes the repository as a `repo` path, so the planned PAN-3178 Changes surface can reuse it for any registered project, workspace, or conversation.
- **D2 — A second endpoint lists refs for the picker.** `GET /api/diffs/refs?repo=` returns branches, tags and recent commits. It is a separate route (with its own no-loss matrix row) because the compare response must stay a pure diff and the picker needs refs before any compare runs.
- **D3 — Response shape mirrors vs-main.** The compare response always carries `files`; it carries `diff` (the patch) only when `file=` is given. This is the exact contract the panel already renders for vs-main and all-turns (`selectedFilePath` gates the patch fetch). It avoids computing a whole-repository patch just to show the file list. PAN-3178 renders per file and fits the same contract.
- **D4 — Allowed roots.** A compare repository is accepted only when `realpath(repo)` is: (a) inside (or equal to) the realpath of a registered project's `config.path` from `listProjectsSync()`; or (b) inside the realpath of that project's workspaces directory, `resolve(config.path, config.workspace?.workspaces_dir ?? 'workspaces')`, which matters only when `workspaces_dir` is absolute and outside the project; or (c) **exactly equal** to the realpath of the `cwd` of an unarchived conversation from `listConversations()`. Conversation cwds are exact-match only, because a conversation whose cwd is the home directory must not open every repository under home. Anything else returns 400 `REPO_NOT_ALLOWED`. Git then runs at `git rev-parse --show-toplevel` of the accepted path.
- **D5 — Ref validation happens in two stages, and the diff only ever sees SHAs.** Stage 1 (shape, no git spawned): the ref is a non-empty string of at most 256 characters, does not start with `-`, does not contain `..`, and matches `/^[A-Za-z0-9._\/@{}~^+-]+$/` (no whitespace, control characters or `:`). Failure returns 400 `INVALID_REF`. Stage 2: `execFile('git', ['rev-parse', '--verify', '--quiet', '--end-of-options', `${ref}^{commit}`])` (verified on git 2.43.0: `--end-of-options` is accepted, and `--help` as a ref exits 1). Failure returns 400 `UNKNOWN_REF`. Every later git command receives the resolved 40-character SHAs, never the user's string.
- **D6 — `mode` defaults to `two-dot`.** Accepted values are `two-dot` and `three-dot`; anything else returns 400 `INVALID_MODE`. Two-dot is "exactly the changes between A and B", which is the operator's local-only, straight-line case. In three-dot mode, `git merge-base` failing (unrelated histories) returns 400 `NO_MERGE_BASE`.
- **D7 — Compare file lists use `--no-renames` and `-c core.quotePath=false`.** This matches `diffFilesAgainstHead` (grep `'-c', 'core.quotePath=false', 'diff', '--no-renames', '--numstat'`), so numstat paths and name-status paths key identically and non-ASCII paths stay unquoted.
- **D8 — Whitespace is a request query param, `ignoreWhitespace=1`.** The server treats `ignoreWhitespace` values `1` and `true` as on; anything else (including absent) is off. The flag maps to git's `-w` on every patch and numstat command of the view. The browser persists the toggle in the existing diff preferences (`localStorage` key `overdeck.ui.diff.preferences`, new field `ignoreWhitespace`, default `false`). It is a per-browser preference, so it is **not** written to the URL.
- **D9 — Turn-summary file lists ignore the flag.** `GET /api/agents/:id/diffs` and `GET /api/conversations/:name/diffs` return summaries computed without `-w` (agent summaries are event-sourced at turn time; conversation summaries are cached 30 s keyed by transcript stat). With whitespace ignored, a turn chip's picker can still list a whitespace-only file, and selecting it shows "No net changes in this selection." That is the accepted behavior; recomputing summaries is out of scope.
- **D10 — Compare URL params.** The selection lives in `diffTurnId=compare`, `diffBase=<ref>`, `diffHead=<ref>`, `diffMode=two-dot|three-dot`, plus the existing `diffFilePath`. The popout also carries `repo=<absolute path>`. `parseDiffRouteSearch` keeps `diffBase`/`diffHead`/`diffMode` only when `diffTurnId === 'compare'`.
- **D11 — The panel learns the repository from a new `repoPath` prop.** `ConversationPanel` passes `conversation.cwd`; the popout passes its `repo` param. Without `repoPath`, the "Compare…" chip is not rendered.
- **D12 — The ref picker uses a native `<input list>` + `<datalist>`.** No new dependency. The operator can pick a branch, tag or recent commit, or type any ref.
- **D13 — PAN-4501's route move is cherry-picked, not re-implemented.** See "Coordination with PAN-4501". Fallback: if `git cherry-pick` of `123a49ab986` does not apply cleanly, re-create the same move by hand: the new file content is exactly `git show 123a49ab986:src/dashboard/server/routes/conversation-diffs.ts`, and `conversations.ts` loses the three route definitions, the `conversation-diffs.js` lib import, `conversationDiffDependencies`, and the then-unused `getCachedMessages` import, and gains `import { conversationDiffRoutes } from './conversation-diffs.js';` plus `conversationDiffRoutes,` in `conversationsRouteLayer`.
- **D14 — All new server git calls use `execFile` with argument arrays** imported from `node:child_process`. No `exec` string building, no `execSync`.
- **D15 — The compare popout still needs a diff source.** A popout URL needs `prefix` (an agent or conversation diff prefix) as today. A compare-only popout for a project with no conversation is PAN-3178's Changes surface, not this issue.

## Requirements

- **FR-1** `GET /api/diffs/compare?repo=&base=&head=&mode=&file=&ignoreWhitespace=` returns `{ repoRoot, mode, base: { ref, sha }, head: { ref, sha }, mergeBase, files, diff? }` for a repository in the allowed roots, in two-dot or three-dot mode, with no remote and no PR required.
- **FR-2** The compare route returns 400 with a `code` and runs no git command with the input when the ref has an invalid shape (including a leading `-`), and returns 400 when the repo path is outside the allowed roots, not absolute, missing, or not a git repository, or when a ref does not resolve to a commit.
- **FR-3** `GET /api/diffs/refs?repo=` returns `{ repoRoot, head, branches, tags, commits }` under the same repo validation.
- **FR-4** Both new routes have rows in the no-loss matrix and are registered in `server.ts`.
- **FR-5** `ignoreWhitespace=1` applies `-w` to the patch and file list of the agent per-turn, all-turns and vs-main routes.
- **FR-6** `ignoreWhitespace=1` applies `-w` to the patch of the conversation turn and all-turns routes (the conversation "vs main" chip is served by the turn route on `main` today).
- **FR-7** `ignoreWhitespace=1` applies `-w` to the compare route's patch and file list.
- **FR-8** The diff panel has an ignore-whitespace toggle that re-requests the current view with `ignoreWhitespace=1`, and the setting persists per browser.
- **FR-9** The diff panel (inline and popout) has a "Compare…" view with base/head pickers fed by the refs route, a two-dot/three-dot switch, and URL-reflected state, so a popout compare URL opened in a new tab shows the same compare.
- **NFR-1** No `execSync` anywhere; all new git calls are `execFile` arrays (repo rule: no `execSync` in dashboard server code or code reachable from it).
- **NFR-2** `src/dashboard/server/routes/conversations.ts` ends at or under 1072 lines; `DiffPanel.tsx` stays under the 1000-line ceiling (`CEILING=1000` in `scripts/lint-file-size.sh`); `ConversationPanel.tsx` stays at or under 1531 (its cap). Never raise an allowlist cap.

No new tests that read source files to assert on them (the lint rejects source-grep tests; the existing conversation no-loss test is the one allowed exception and is only edited).
