## 0. Glossary

- **Deft / Directive / Deft Directive.** The `deftai/directive` project: an npm engine (`@deftai/directive`, CLIs `deft`, `directive`, `deft-hook`) plus content (skills, AGENTS.md template, hooks). The operator's fork is `eltmon/directive`; at planning time its `master` is `48e8cbf0e7818a2b2ca60a070791e236ca088ac0` (`v0.119.10-16`), 22 commits behind upstream `91f01172b063`.
- **Deposit.** What `directive init` writes into a repo: `.deft/core/` (gitignored payload), a `package.json` pin of `@deftai/directive`, an `AGENTS.md` managed section (`<!-- deft:managed-section v3 -->`), pointer skills `deft-directive-*` in `.claude/skills`, `.agents/skills`, `.codex/skills`, `.cursor/skills`, `.github/skills`, agent hooks whose command contains `deft-hook` in `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`, `.grok/hooks/deft.json`, `.githooks/` + `git config core.hooksPath .githooks`, and an `xbrief/` tree with `xbrief/PROJECT-DEFINITION.xbrief.json`.
- **Directive project.** A repo root where detection (§WI-4) finds at least one of: `.deft/core/VERSION`, the `deft:managed-section` marker in `AGENTS.md`, or a `@deftai/directive` entry in `package.json` `devDependencies`/`dependencies`.
- **Kill switch / flag file.** Root file `.deft-directive-disable`. When present and **untracked**, Deft enforcement (hooks, session ritual, automation) is off for new agent sessions (`packages/core/src/policy/deft-directive-disable.ts`, upstream #3039, first released in **v0.92.0**, commit `5f760c40`). Deft checks presence only. A tracked flag is ignored by Deft.
- **`.no-deft-directive`.** Committed permanent project opt-out (upstream #2926). Overdeck only reports it.
- **`deft` pack.** The PAN-4334 skill pack registered with id `deft`, known-pack default url `https://github.com/eltmon/directive`, adapter `deft-readonly`.
- **`deft-readonly` adapter.** New adapter: reads `content/skills/deft-directive-<name>/SKILL.md` at the trusted commit, keeps only the read-only allowlist, and names each skill `<name>` (prefix stripped). Harness-visible name `deft:<name>`, Overdeck id `deft/<name>`.
- **Skill map.** The versioned classification of every Deft skill (§WI-1) into one of five classes: `compatible`, `translated`, `conflicting`, `runtime-dependent`, `excluded`. Replaces the stale PAN-791 mapping (v0.20.0-rc.3).
- **Host notice.** A fixed Markdown block the mount inserts into every `deft-readonly` SKILL.md copy right after the frontmatter. It states what the agent must not do and translates Deft commands to Overdeck equivalents.
- **Explicit off.** `resolvePackToggle('deft', layers)` returns `{ enabled: false, source }` with `source` `issue` or `project`. `source: 'default'` is **not** explicit off. Global is two-state (off = key cleared), so global can never be explicit off.
- **Managed mode.** A project-level operator decision, stored in `projects.yaml` as `projects.<key>.deft_integration`, meaning "Deft methodology on, Overdeck owns worktrees, review, merge, and the pipeline xBRIEF". It can be enabled only for a detected Directive project, only after the ownership/collision report is printed, and only with confirmation.
- **Deft env file.** A per-launch file the launch step writes: Claude `<OVERDECK_HOME>/launch/<launchKey>/deft.env` (sibling of the PAN-4334 `skill-packs` link), Codex `$CODEX_HOME/overdeck-deft.env`. It holds zero or more of exactly two lines, `DEFT_DIRECTIVE_DISABLE=1` and `DEFT_ORCHESTRATOR=overdeck`. The launcher reads it with a `case` allowlist and exports only those literal values. It is never sourced.
- **Launch step.** The PAN-3942 bash step `pan skills launch-settings …` that every local Claude Code / Codex launch runs before the harness starts (`src/lib/skill-overrides/launcher-lines.ts`). Conversations run it too: `src/lib/overdeck/conversation-runtime.ts:786` passes `managedStateKey: tmuxSession`.

## 1. Verdict and scope

Deft is a process engine that installs by writing tracked repo files, so Overdeck cannot "install" it per launch. This issue delivers what Overdeck can do without touching any repo's tracked state:

1. **`deft` read-only pack** on the PAN-4334 mechanism: 7 engine-free Deft skills mounted per launch with a host notice, plus a Claude `permissions.deny` boundary against Deft's repo-mutating CLIs in non-Directive projects.
2. **Versioned skill map** of all 25 current Deft skills (replaces PAN-791).
3. **Directive-project detection** (derived, read-only) and an **operator-readable collision/ownership report**.
4. **Per-launch off switch** in Directive projects: an explicit `deft` pack off at project or issue level exports `DEFT_DIRECTIVE_DISABLE=1`, writes the flag file only inside an issue worktree, and hides the deposit's `deft-directive-*` pointer skills.
5. **Managed mode**: `pan skills deft enable|disable --project <key>`, gated on detection plus a printed ownership plan; launches in a managed project export `DEFT_ORCHESTRATOR=overdeck`.
6. **Provenance**: the pinned pack ref/commit and the project's engine pin appear in `pan skills deft status` and in a `[launcher] deft:` stderr line at each launch.

Env vars are no-ops on engines that do not read them. The flag file works on every engine ≥ v0.92.0. So this issue ships and is testable before PAN-4425 lands.

## 3. Decisions (auto mode; each also in `plan.autoDecisions`)

- **D1 Fork work is sibling PAN-4425.** The Overdeck pipeline reviews only the eltmon/overdeck PR, so fork changes cannot be reviewed, tested, or `Item:`-trailered here. This PRD defines the env contract; PAN-4425 implements it in `eltmon/directive` under the operator's hard rules.
- **D2 Dashboard controls are sibling PAN-4426.** Route + no-loss-matrix row + component + mount point would push this plan past the 25-file finalize limit. This issue satisfies "explicit project-level action with a displayed plan" through the CLI.
- **D3 No conversation level.** PAN-3942 was rescoped to global/project/issue. A conversation inherits global and project toggles through the same launch step (it has a `managedStateKey`).
- **D4 Toggle requires registration.** `pan skills set --pack deft …` needs the `deft` pack registered (the store rejects unknown packs). `pan skills deft status` prints the add command when it is not.
- **D5 Default never disables a deposit.** In a Directive project, the kill switch applies only on **explicit off** (issue or project). `source: 'default'` leaves Deft exactly as the user configured it.
- **D6 Flag file only in issue worktrees.** Written only when `issueIdFromWorkspacePath(cwd) !== null` (cwd is a `feature-<issue>` worktree root). Review/test roles and conversations launched at the project root get the env var only; on upstream engines that do not read it, Deft stays on for those launches. Documented limit until PAN-4425.
- **D7 Flag ownership by content marker.** The file Overdeck writes starts with `# overdeck:deft-directive-disable`. On re-enable, Overdeck deletes the flag only when its first line is that marker. A user-written flag is never touched.
- **D8 Pointer skills hide with the kill switch.** When explicit off applies, the deposit's pointer skill names found by detection (`deft-directive-*` under `<root>/.claude/skills`, `.agents/skills`, `.codex/skills`) are added to the launch's disabled list (Claude `skillOverrides`, Codex `[[skills.config]] enabled = false`).
- **D9 Capability boundary has two layers.** (a) Host notice in every mounted SKILL.md (both harnesses). (b) Claude only: when any `deft/*` skill is mounted and the project is **not** a Directive project, the settings JSON adds `permissions.deny` for Deft's mutating CLIs (§WI-8). In a Directive project no deny is added, because Deft is the project's own tool. Codex has no equivalent; documented.
- **D10 Frontmatter rename in the mount.** The mount copy rewrites the frontmatter `name:` to the stripped name so the harness registers `deft:<name>`, never `deft:deft-directive-<name>`.
- **D11 Mount hash covers the transform.** `MOUNT_FORMAT_VERSION` goes from 1 to 2, and each hash entry appends the pack's `transform` id and `DEFT_HOST_NOTICE_VERSION`, so a pre-change mount is never reused.
- **D12 Unknown skills are excluded.** A skill name at a newer pinned commit that is not in the skill map is classified `excluded` with reason `unreviewed` and is never mounted.
- **D13 Managed mode stores a decision only.** `projects.<key>.deft_integration: { mode: managed, plan_digest: <sha256 hex of the report text>, enabled_at: <ISO> }`. Detection results are never stored. Disable deletes the key and nothing else.
- **D14 No launch-time network.** Detection and the launch step use fs reads only, plus local `git` (async `execFile`, 5 s timeout) only when writing or removing the flag file.
- **D15 Known-pack URL is the fork.** `KNOWN_PACKS.deft.url = 'https://github.com/eltmon/directive'` (operator plan 2026-09-29: pack sources point at the forks). The operator still chooses `--ref` and approves the commit at `pan skills pack add`.
- **D16 Git hooks are reported, not governed.** The deposited hook scripts do not check the kill switch (verified at `48e8cbf`: `.githooks/pre-commit` runs `run_deft verify:branch` unconditionally and `_deft-run.sh` has no check). Whether the `deft verify:branch` subcommand consults the policy module is **unverified** (`policy/runtime-authority.ts` imports it); PAN-4425 owns that checkpoint. Detection reports `core.hooksPath`; the collision report states that feature-branch commits pass `verify:branch` and that main-branch plan-artifact commits in a Directive plan home may be refused. Governing it is PAN-4425's question.

- **FR-7** Launch resolution (`resolveDeftLaunch`) implements the decision table in §WI-7.
- **FR-8** Launch apply writes/removes the Deft env file, writes/removes the marked flag file per D6/D7, ensures the flag is ignored (`git check-ignore`, else append `/.deft-directive-disable` to `git rev-parse --git-path info/exclude`), and returns pointer names to hide and a provenance line.
- **FR-9** Launcher reads the env file with an allowlist and exports only the two literal assignments (both harnesses).
- **FR-10** Claude settings JSON gains `permissions.deny` (D9) and pointer names (D8) when applicable; Codex gains the pointer names in its skill-override block.
- **FR-11** CLI: `pan skills deft status [--project <key>] [--json]`, `pan skills deft enable --project <key> [--yes]`, `pan skills deft disable --project <key>`.
- **FR-12** Managed-mode store per D13; enable refuses non-Directive projects and unconfirmed runs.
- **FR-13** Docs: `features/skills.mdx` `## Deft Directive` section and `docs/USAGE.md` verb block; PAN-791 gets a superseding comment and is closed.

### Non-functional

- **NFR-1** Nothing in this issue writes a tracked file in any project, runs `directive`/`deft`/`npx @deftai/*`, installs a package, sets `core.hooksPath`, or edits `AGENTS.md`/`CLAUDE.md`/hooks files. - **NFR-2** Fail open: any Deft error in the launch step prints `[launcher] WARNING: deft integration not applied: <message>` to stderr, removes the Deft env file, and still emits the settings JSON / override block and pack mount.
- **NFR-3** Async only (no `execSync`; server-reachable rule). Git via async `execFile` with `GIT_TERMINAL_PROMPT=0` and a 5000 ms timeout.
- **NFR-4** Stored vs derived: only `deft_integration` and PAN-3942/4334 toggles are stored.
- **NFR-5** Tests never hit the network: fixture dirs and temp git repos, temp `OVERDECK_HOME`. Any timeout test uses `vi.useFakeTimers()`.
- **NFR-6** `src/lib/launcher-generator.ts` is unchanged; no non-test file crosses 1000 lines; `src/cli/commands/skills.ts` stays under 1000 (new verbs live in `skills-deft.ts`).
- **NFR-7** Import discipline: `launcher-lines.ts` stays a leaf; `src/lib/skill-overrides/launch.ts` imports `src/lib/deft/*` lazily (dynamic `import()`), like its existing store imports. `src/lib/skill-packs/deft.ts` imports nothing from `skill-overrides/` or `deft/`. `npm run lint:circular` stays green.
