# PAN-4786: Adopted PRs always fail verification on incomplete-plan-items (no xBRIEF)

**Issue:** https://github.com/eltmon/overdeck/issues/4786
**Status:** planned (auto mode, 2026-11-02)

## Glossary

- **Adopted workspace.** A pipeline workspace (`workspaces/feature-<issue>/`) that
  `adoptPrWorkspace` (`src/lib/cloister/pr-workspace-adoption.ts`) created for a PR
  opened outside the pipeline (PAN-4605). On success it appends one
  `workspace.adopted` entry to the workspace pipeline journal. A workspace counts as
  adopted when its journal holds **any** `workspace.adopted` entry, not only as its
  last entry.
- **Pipeline journal.** The append-only file `<workspace>/.overdeck/pipeline.jsonl`,
  read with `readPipelineJournal(workspacePath)` from
  `src/lib/cloister/pipeline-journal.ts`. It is never rewritten, and it is deleted
  with the workspace.
- **xBRIEF / plan.** The issue's plan document. "Has an xBRIEF" means exactly what
  the plan checklist gate sees: `findPlan(workspacePath)` from
  `src/lib/xbrief/io.ts` resolves to a path. That function looks for
  `.pan/specs/<date>-<ISSUE>-<slug>.xbrief.json` in the workspace, then in the main
  checkout (`<workspace>/../..`), then for a workspace draft
  (`.overdeck/spec.vbrief.json` or the legacy `.pan/spec.vbrief.json`) whose `plan.id`
  matches the issue.
- **Plan checklist gate.** Step 12 of the verification runner
  (`checkIncompletePlanItems`, `src/lib/work/done-preflight.ts`). It fails with
  `failedCheck: 'incomplete-plan-items'`. With no xBRIEF it always fails, because
  `evaluateIncompletePlanItems(null)` returns the line "The required xBRIEF checklist
  is missing or unreadable".
- **`skipPlanChecklist`.** The existing option on `VerificationRunnerOptions`
  (`src/lib/cloister/verification-types.ts`, line 25). When it is true, the runner
  uses `[]` instead of calling `checkIncompletePlanItems`. Today only strike merges
  set it (`mergeVerificationOptions`, `src/dashboard/server/routes/workspaces/merge-strike.ts`, line 50).
- **Verification door.** `runVerificationForIssue` (`src/lib/cloister/verification-runner.ts`,
  line 984). Every production verification goes through it: the review request door
  `startRequestReviewPipeline` (`review-pipeline.ts`, line 275), the `/trigger`
  route (`review-pipeline.ts`, line 510) and merge verification (`merge-ops.ts`,
  line 1021).

## Problem

A PR adopted into the pipeline can never pass verification. It has no xBRIEF, so
the plan checklist gate always fails:

```ts
// src/lib/cloister/verification-runner.ts, lines 816-818
    const taskBlockers = options.skipPlanChecklist
      ? []
      : await checkIncompletePlanItems(workspacePath, issueId);
```

The adoption starter (`runAdoptAndReview` in `src/lib/cloister/pr-adoption-review.ts`,
lines 132-136) calls `startReview(issueId, { note, source })` and passes no option.
On 2026-11-02, PR #4780 (PAN-4750) and PR #4783 (PAN-4772) were adopted at 04:21 and
both journaled `verification.failed {failedCheck: 'incomplete-plan-items'}`. The
supervised-handoff route that TENET-10 requires for merge and review machinery is
blocked: no handoff PR can be reviewed.

## Approach (decision)

Resolve the condition **from workspace state at the verification door**, and set the
existing `skipPlanChecklist` option there. Do not add a second skip mechanism.

Why not set the option only in the adoption starter, as the issue body sketches:
adoption runs once. After a verification failure on any other check (lint, a test),
the next `pan review request` finds the workspace and takes the normal route
(`answerMissingWorkspace` returns null when `workspaceExists` is true), so it would
run the plan checklist again and fail. Merge verification (`merge-ops.ts`, line 1021)
and the `/trigger` route would fail the same way. The issue's own condition
("its journal has `workspace.adopted` and has no xBRIEF") is workspace state, so the
door reads workspace state and every run gets the same answer.

Why the wrapper `runVerificationForIssue` and not line 816 inside the runner: the
wrapper sets the option before `runSupervisedVerification` persists it into the
worker state file and before the supervisor compares options (`sameOptions`,
`verification-worker-supervisor.ts`, line 255, for finished results; W2b adds the same
check to the live-worker join). So the resolved option is visible in the worker state,
and a worker run with other options is never reused. This also follows the issue's
instruction to thread the decision through `skipPlanChecklist` into the worker options.

### Decision rules

- An explicit `skipPlanChecklist: true` (strike) is kept as is. The helper reads no
  files in that case.
- Adopted (any `workspace.adopted` entry) **and** `findPlan` resolves `null` ⇒
  `skipPlanChecklist: true`, and one log line.
- Adopted **and** an xBRIEF exists ⇒ options unchanged; the checklist runs.
- Not adopted ⇒ options unchanged; the checklist runs (normal pipeline PRs, and
  workspaces made by hand with `pan workspace create`).
- `findPlan` fails with an `FsError` ⇒ options unchanged (fail closed: the checklist
  runs and reports the read error the way it does today).
- A journal that is missing or unreadable ⇒ not adopted (`readPipelineJournal`
  returns `[]`).

## Requirements

- **FR-1.** Verification of an adopted workspace with no xBRIEF skips the plan
  checklist gate and continues to the empty-changeset guard and the pass steps.
  Typecheck, lint and test gates still run before it (steps 7-8, unchanged).
- **FR-2.** Verification of an adopted workspace whose issue has an xBRIEF still runs
  the plan checklist gate.
- **FR-3.** Verification of a workspace with no `workspace.adopted` journal entry is
  unchanged.
- **FR-4.** An explicit `skipPlanChecklist: true` from the caller (strike merge) is
  preserved unchanged.
- **FR-5.** The decision applies at every verification door (review request,
  `/trigger`, merge verification), not only the first run after adoption.
- **FR-6.** When the skip applies, the dashboard log records one line naming the issue
  workspace and the reason.
- **NFR-1.** `src/lib/cloister/verification-runner.ts` stays at or under 1000 lines.
  `scripts/lint-file-size.sh` only checks files over `CEILING=1000`; the file is 994
  lines on `origin/main`, and above 1000 its allowlist cap (961) applies and lint
  fails. The net change to that file is at most +4 lines. All new logic lives in a new
  module.
- **NFR-2.** No new child-process calls and no `execSync` in server-reachable code;
  the helper is async. Accepted design choice: the helper reads the journal through the
  existing synchronous `readPipelineJournal` (one small local file, read once per
  verification run), exactly as more than a dozen other journal readers in `src/` do today
  (`deacon-lite.ts`, `conflict-repair.ts`, `pr-outside-pipeline.ts`,
  `undispatched-review-recovery.ts`, …). No async twin is added to
  `pipeline-journal.ts` (one variant per operation, `lint:effect-facades`).
- **NFR-4.** A live verification worker is joined only when it runs with the same
  options as the new request (`sameOptions`); otherwise it is killed and a fresh worker
  starts, the same way a worker for a different head is handled today.
- **NFR-3.** No change to `RequestReviewStarter`, `pr-adoption-review.ts`,
  `merge-strike.ts`, the worker request shape, or `checkIncompletePlanItems`.

## Work items

### W1. Add the adopted-workspace plan checklist helper (FR-1..FR-4, FR-6, NFR-2)

Create `src/lib/cloister/adopted-plan-checklist.ts`:

```ts
/**
 * PAN-4786: a PR adopted into a pipeline workspace (PAN-4605) was opened outside the
 * pipeline and has no xBRIEF, so the plan checklist gate could never pass. When the
 * workspace journal shows `workspace.adopted` and no xBRIEF resolves for the issue,
 * verification skips the checklist through the existing `skipPlanChecklist` option —
 * the same skip strike merges use. An xBRIEF, when one exists, is still enforced.
 */
import { Effect } from 'effect';

import { findPlan } from '../xbrief/io.js';
import { readPipelineJournal } from './pipeline-journal.js';
import type { VerificationRunnerOptions } from './verification-types.js';

/** True when the workspace was adopted from an outside PR and no xBRIEF resolves for its issue. */
export async function isAdoptedWorkspaceWithoutPlan(workspacePath: string): Promise<boolean> {
  if (!readPipelineJournal(workspacePath).some((entry) => entry.type === 'workspace.adopted')) return false;
  const planPath = await Effect.runPromise(
    findPlan(workspacePath).pipe(Effect.orElseSucceed(() => 'unreadable' as const)),
  );
  return planPath === null;
}

/** The caller's options, with `skipPlanChecklist: true` added for an adopted workspace that has no xBRIEF. */
export async function withAdoptedPlanChecklistSkip<T extends Pick<VerificationRunnerOptions, 'skipPlanChecklist'>>(
  workspacePath: string,
  options: T,
): Promise<T> {
  if (options.skipPlanChecklist) return options;
  if (!(await isAdoptedWorkspaceWithoutPlan(workspacePath))) return options;
  console.log(`[verification] ${workspacePath}: adopted PR workspace with no xBRIEF — skipping the plan checklist (PAN-4786)`);
  return { ...options, skipPlanChecklist: true };
}
```

## Critique response

### Live workers ignore the changed checklist option

Accepted for the cross-process live join. New work item W2b adds `sameOptions` to the
live-worker join in `runSupervisedVerificationOnce`: a live worker running with other
options is killed and a fresh worker starts, the same as a worker on another head.
A new case in `verification-worker-supervisor-join.test.ts` registers a live worker
with `{}` and requests `{ skipPlanChecklist: true }`, and asserts the kill and the fresh
launch. NFR-4 records the rule and W3 documents it. The in-process
`activeSupervisorRuns` map is left unchanged and listed in Non-goals: review requests
are coalesced earlier by the `requestReviewPipeline` in-flight guard, the remaining race
(merge verification during review verification in one process) already behaves this
way for strike options, and a run is a snapshot whose successor re-resolves the option.

### The line-budget fallback cannot run

Accepted. The line-816 fallback is removed; it produced a boolean where an array is
needed. The wrapper edit is the only variant. The budget fits today (994 + 4 = 998).
If `origin/main` grows, the checkpoint now shortens the seven-line JSDoc above
`runVerificationForIssue` to one line, which frees five lines without a behavior change.

### The helper adds synchronous server I/O

Resolved by revising NFR-2 explicitly. The rule this repo enforces for server code is
no `execSync` and no new sync tmux calls; small synchronous file reads are the
established pattern for the pipeline journal, which more than a dozen modules in `src/` already read
through `readPipelineJournal` (including `deacon-lite.ts` and `pr-outside-pipeline.ts`,
which run far more often than verification). The helper reads one small local file once
per verification run. Adding an async twin would create a sync/async pair that the
one-variant-per-operation rule (`lint:effect-facades`) forbids without a documented
sync caller list, which is more risk than the read it replaces.

### Unresolved after two critic rounds

- Plan lookup errors can authorize the skip
- In-process coalescing still reuses different options
