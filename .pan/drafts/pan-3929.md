# PAN-3929 — Skill text still names deleted status fields; widen the guard's Markdown pattern set

**Issue:** [PAN-3929](https://github.com/eltmon/overdeck/issues/3929)
**Parent:** [PAN-3917](https://github.com/eltmon/overdeck/issues/3917) (The Overdeck Cut)
**Planned:** 2026-09-19 (auto mode)

## Glossary

- **The Cut (PAN-3917):** the change that deleted Overdeck's stored status layer. Since it landed, an issue's pipeline position is computed at read time from the tracker, the plan home, the PR, CI checks, git, and the terminal backend. "Overdeck stores no status it can derive."
- **Deleted status fields:** the six mirror fields `reviewStatus`, `testStatus`, `verificationStatus`, `inspectStatus`, `mergeStatus`, `releaseStatus`, plus `readyForMerge` and `recoveryTrips`. They were columns on a SQLite `review_status` row and fields on the deleted `IssueRecord`. Nothing writes or reads them any more.
- **Derived issue state:** the contract in `packages/contracts/src/derived-issue-state.ts`. One object per issue with `state`, optional `attention`, optional `pr`, optional `branch`.
  - `state` (line 19): one of `backlog`, `parked`, `planned`, `working`, `in-review`, `changes-requested`, `ready`, `merged`, `closed`.
  - `attention` (line 33): `needs-you`, `stuck`, or `api-error`. Orthogonal to `state`. Absent when nothing needs the operator.
  - `pr.reviewState` (line 41): `approved`, `changes-requested`, `review-requested`, `commented`, `none`.
  - `pr.checks` (line 51): `green`, `red`, `pending`.
  - `pr.mergeable` (line 61): `true`, `false`, or `null` when the forge has not computed it.
- **Derived-state read surfaces (verified live 2026-09-19):**
  - `GET /api/issues/resource-allocated` — batch. Each row carries `state: IssueState | null` (`src/dashboard/server/services/resource-discovery.ts:112`) plus `stateLabel`, `status`, `pipelineBucket`. No `attention`, no `pr`.
  - `pan show <ID> --json` — one issue. Prints `state`, `attention` (null when absent), `pr` (absent when there is no PR), `branch` (`src/cli/commands/show.ts:80-90`). Same derivation the dashboard uses.
  - `GET /api/issues` — tracker issues plus `pipelineMembership`. Carries NO derived state.
  - The `/ws/rpc` read model carries the full `derivedIssueStates` array; it is not reachable from a bash skill. No REST route returns it.
- **Guard:** `scripts/guard-no-state-layer.sh`, wired as `npm run lint:no-state-layer` inside `npm run lint` (`package.json:106,116`). Two passes: a code pass over `src/` (full pattern set, `patterns=` line 66) and a Markdown pass over `src/lib/cloister/prompts/` and `sync-sources/` (narrow set, `md_patterns=` line 87). The Markdown pass runs only when the script is called with no arguments (line 130: `if [[ $# -eq 0 ]]`).
- **Guard test:** `tests/unit/scripts/guard-no-state-layer.test.ts`. Every existing case passes a scan root argument (`runGuard`, line 23), so the Markdown pass is never exercised by tests today.
- **Phase lane table:** `PHASE_BY_DERIVED_STATE` in `src/dashboard/frontend/src/lib/pipeline-state.ts:10-20` maps the nine states onto lanes: backlog/parked → todo, planned → plan, working → work, in-review/changes-requested → review, ready/merged/closed → ship. `getPipelineIssuePhase` (line 96) puts `pipelineMembership.bucket === 'post_merge_limbo'` in ship ahead of everything.
- **Skill:** a `SKILL.md` under `sync-sources/skills/<name>/`, distributed to every harness by `pan sync`. Skills are agent-facing prose: a sentence telling an agent to read `readyForMerge` makes the agent look for a field that does not exist.

## Problem

The Cut deleted the status fields but five skills still tell agents to read them. The guard did not catch this because its Markdown pass deliberately left the field names out (`scripts/guard-no-state-layer.sh:22-29`), on the theory that prose uses `reviewStatus` as vocabulary more often than as an instruction. In practice every hit is an instruction: a SQL query against a table that no longer exists, a JSON key an agent is told to check, a CLI example that maps a voice to a deleted event key.

Running the code pass's full pattern set over agent-shipped Markdown finds hits in exactly these five files and nowhere else under `sync-sources/` or `src/lib/cloister/prompts/`:

| File | Hits (occurrences) | Lines |
|---|---|---|
| `sync-sources/skills/pipeline-status/SKILL.md` | 6 camelCase + 6 snake_case column names | 60, 71-75, 126-127, 201, 214-215, 255 |
| `sync-sources/skills/pipeline-list/SKILL.md` | 6 | 33, 88, 108, 143, 147 |
| `sync-sources/skills/pan-recap/SKILL.md` | 3 | 63, 159 |
| `sync-sources/skills/pan-rollout/SKILL.md` | 1 | 26 |
| `sync-sources/skills/pan-tts/SKILL.md` | 1 | 147 |

The issue body says 33 prose hits; the count on this branch is 17 camelCase occurrences plus the snake_case `review_status` table references in pipeline-status. The number does not matter. The deliverable is zero hits under the widened guard.

Verified consequence: `~/.overdeck/panopticon.db` has no `review_status` table (checked with `sqlite3 .tables` on 2026-09-19), so the pipeline-status script fails at its first SQL query today. That skill is broken, not just stale.

## Proposal

Rewrite the five skills to the derived model and widen the guard's Markdown pass to the same pattern set the code pass uses, with tests that exercise the Markdown pass for the first time. Six work items, one per file plus the guard; the five skill items are independent of each other.

## Decisions

- **D1 — pipeline-status data source.** Batch `state` from `GET /api/issues/resource-allocated` (one call), then call `pan show <ID> --json` only for members whose state is `in-review`, `changes-requested`, or `ready`. Those are the only rows where the PR columns carry information. Calling `pan show` for every member would spawn one Node process and one forge read per issue; at 40 members that is over a minute for a "glance" board. Members absent from the resource-allocated response render `state` as `·`.
- **D2 — pipeline-status columns.** Replace `REVIEW · TEST · VERIFY · MERGE · READY` with `STATE · NEEDS · PR REVIEW · CHECKS · MERGEABLE`. TEST and VERIFY were `review_status` columns; the derived model has no test verdict, and `pr.checks` (CI on the PR head) is the nearest observable. The `*` drift-flag glyph is removed: there is no stored value left to drift from the truth.
- **D3 — pipeline-list lane mapping.** Both views use the same lane table as `PHASE_BY_DERIVED_STATE`. The resource view reads `state` from `/api/issues/resource-allocated` and falls back to today's `stateLabel` heuristics only when `state` is `null`. The lifecycle view reads `/api/issues`, which has no derived state, so its ship lane mirrors `getPipelineIssuePhase` line 96: `pipelineMembership.bucket == 'post_merge_limbo'`. The `mergeStatus` clause is deleted. The `--all` verifying bucket (`verifying_on_main`) is untouched: it is not a banned name and changing it is out of scope.
- **D4 — pan-recap ready marker.** Step 2 fetches `/api/issues/resource-allocated` once, builds an `issueId → state` map, and prints `(ready)` when the state is `ready`. The jargon rule on line 63 is rewritten to name the derived vocabulary, not deleted.
- **D5 — pan-rollout vocabulary.** `releaseStatus` becomes "the release set's overall `status`" with the literal values from `src/lib/release-set-types.ts:3`: `pending`, `releasing`, `passed`, `failed`, `partial`, `rolled_back`, `skipped`. These are the values `pan rollout status` prints (`src/cli/commands/rollout.ts:43`).
- **D6 — pan-tts example key.** `reviewStatus.passed` becomes `workAgent.finished`, one of the four lifecycle keys in `LIFECYCLE_EVENT_TYPES` (`src/dashboard/server/services/tts-playback.ts:102-107`) and the natural "work is done" announcement. `voiceMap` keys are matched against `payload.eventType` of `activity.tts` events (`src/lib/tts-speak.ts:72`); the other emitted keys are `planning.started`, `planning.complete`, `workAgent.started`, `merge.approved`, `forgeMerge.merged`.
- **D7 — guard Markdown set = code set.** The Markdown pass adopts every code-pass pattern (`readyForMerge`, `recoveryTrips`, the six field names, `auto-commit`) on top of its existing six. The header comment that argued for the narrow set is rewritten: explanatory vocabulary about deleted fields belongs in `docs/`, which the guard does not scan; agent-shipped Markdown must not name them at all. The full set was run over `sync-sources/` and `src/lib/cloister/prompts/` on 2026-09-19 and hit only the five files above, so widening introduces no false positives on this branch once they are fixed. The two by-name exemptions stay.
- **D8 — no new REST endpoint.** A batch REST route for derived state would let the skills drop `pan show`. It is the right long-term fix and is out of scope here; pipeline-list keeps its existing "Long-term" note updated to say so.
- **D9 — roles/ and docs/ hits are a follow-up.** `roles/plan.md:85`, `roles/test.md:75`, `roles/flywheel.md:71`, `docs/KANBAN-MODEL.md:247`, `docs/AGENT_TYPES_INDEX.md:33` also name deleted fields. `roles/` ships to agents but is not one of the guard's Markdown roots, and the issue names five skills. Filed as [PAN-3934](https://github.com/eltmon/overdeck/issues/3934); this issue does not touch those files.

## Intersecting repo rules

- **Skills ↔ CLI lockstep.** `scripts/lint-skills.sh` (in `npm run lint`) cross-checks every `pan <verb> ...` invocation in a wrapper skill against `pan <verb> --help`. `pan-rollout` and `pan-tts` are wrappers. The rewrites below change no invocations except the `pan tts voices map` argument, which is a free-form positional and is not validated.
- **Guard is a lint gate.** `npm run lint` fails on this branch until all five skills are clean AND the guard is widened. Land order does not matter for the tree; only the final state is gated.
- **No `git stash`, no `git checkout` inside the workspace.** Verify `git branch --show-current` prints `feature/pan-3929` before the first edit.
- **Conventional commits**, lower-case subject, ≤100 chars, `Item:` trailer per xBRIEF item.
- **Karpathy rules.** Touch only the lines that name deleted fields or that the new data flow requires. Do not restyle the rest of the skill.
