# PAN-4199 — Flywheel page: closed issues derive `working`, rows have no titles, and the pre-Cut surfaces that still have data sources come back

**Issue:** [PAN-4199](https://github.com/eltmon/overdeck/issues/4199)
**Planned:** 2026-09-25 (auto mode) against `main` @ `6d1cb29d216`
**Predecessor:** PAN-3964 (restored `/flywheel` as a derived view), PAN-3917 (the Cut, commit `3fb710042dd`)

## Glossary

- **Deriver** — `deriveFlywheelStatus()` in `src/lib/flywheel/derive-status.ts`. The one function that `pan flywheel status`, `GET /api/flywheel/status`, and the Flywheel page all read. Every source is an injectable dependency on `DeriveFlywheelStatusDeps`.
- **Lib batch loader** — `loadIssueStatesForProject(projectPath, issueIds, deps)` in `src/lib/overdeck/derived-issue-state.ts` (line ~757). Derives FR-6 issue state for many issues. Reads tracker rows only from `deps.issues`; a missing entry means `issueOpen: null`.
- **Server adapter** — `loadIssueStatesForProject` in `src/dashboard/server/services/derived-issue-state.ts:100-114`. Wraps the lib batch loader and fills `issues` from the `IssueDataService` cache and `panes` from `getBackendPanes()`.
- **Tracker facts** — `TrackerIssueFacts` (`src/lib/overdeck/derived-issue-state.ts:223-226`): `{ open, labels }`. This PRD adds an optional `title`.
- **Backend panes** — `BackendPane` (`packages/contracts/src/backend-pane.ts`): one live agent pane from Herdr or tmux, carrying `issue`, `role`, `harness`, `model`, `state`, `agentId`, `terminalId`. A pane is **live** when `state` is not `exited` and not `done` (the same `isLive` rule as `derived-issue-state.ts:137`).
- **Tick marker** — the `flywheel-tick: tick=… pick=… phase=… in-flight=… needs-you=…` line the loop prints; parsed into `FlywheelLastTick` (`packages/contracts/src/flywheel-derived.ts:58-67`). `lastTick.inFlight` is the loop's own in-flight list.
- **Workspace census** — the current in-flight set: every `workspaces/feature-*` directory in the flywheel's project (`listFeatureWorkspaces`, `src/lib/cloister/deacon-workspaces.ts`).
- **In-flight source** — new derived field `inFlightSource: 'tick' | 'census'` naming which set the header count shows.
- **Headline strip** — the v1 row of numbers at the top of the Status tab (PRs merged, substrate bugs fixed, order-book progress, features awaiting UAT), rebuilt here from data the page already fetches.
- **Reveal** — v1 `lib/flywheelReveal.ts`: a tiny module-level flag + listener set that lets a header button ask the Flywheel page to switch to the Status tab and scroll to the needs-you block.
- **Orphan session** — a `conv-flywheel` terminal session that is up while no un-archived conversation row exists. `startFlywheel` refuses it with `FlywheelOrphanSession` (409) unless `fresh: true` (`src/lib/flywheel/actions.ts:192-197`).

## Problem (verified 2026-09-25)

1. **Closed issues read `working`.** `defaultLoadStates` (`src/lib/flywheel/derive-status.ts:118-121`):

   ```ts
   async function defaultLoadStates(projectPath: string, issueIds: readonly string[]): Promise<Map<string, DerivedIssueState>> {
     const { loadIssueStatesForProject } = await import('../overdeck/derived-issue-state.js');
     return loadIssueStatesForProject(projectPath, issueIds);
   }
   ```

   It passes no `issues`, so the lib batch loader computes `const issue = deps.issues?.[issueId] ?? null` → `issueOpen: null`, and `deriveState` returns `closed` only when `issueOpen === false` (`derived-issue-state.ts:141`). The route `getFlywheelStatusPayload()` (`src/dashboard/server/routes/flywheel.ts:85-87`) calls `deriveFlywheelStatus()` with no deps, so the server adapter that knows the tracker state is bypassed. A leftover `feature/pan-<n>` branch that is `--no-merged=origin/main` then derives `working` (`derived-issue-state.ts:160`). The in-flight filter at `derive-status.ts:235` never removes a `closed` row in production.
2. **No titles.** `FlywheelInFlightRow` (`packages/contracts/src/flywheel-derived.ts:83-89`) has no `title`; `FlywheelStatusPane.tsx:133-140` renders only `row.issueId`.
3. **`trackerUnknown` is dropped.** The lib sets `derived.trackerUnknown = true` (`derived-issue-state.ts:197`) but the deriver's row literal (`derive-status.ts:226-232`) does not copy it.
4. **`working` does not say whether an agent runs.** A stale branch ahead of main and a live work agent both read `working`.
5. **The loop's own in-flight list is parsed but never rendered** (`FlywheelLastTick.inFlight`).
6. **Wrong copy.** `FlywheelStatusPane.tsx:83` says "Start below"; Start is in the right column's toolbar (`FlywheelConversationPane.tsx:143-147`).
7. **Orphan dead end.** With `run === 'idle'` the toolbar offers only Start; an orphan session makes Start fail with 409 and the page shows only an error toast. `postFlywheelAction` (`src/dashboard/frontend/src/lib/flywheelApi.ts:289-300`) throws a plain `Error` and drops `payload.code`.
8. **Lost v1 surfaces with live data sources:** UAT batches card (v1 `MergeQueueCard`, `git show 3fb710042dd^:src/dashboard/frontend/src/components/flywheel/MergeQueueCard.tsx`), headline tiles, live agent list, run report viewer (`GET /api/flywheel/report` exists, no frontend reader), header open-questions indicator + reveal (`git show 3fb710042dd^:src/dashboard/frontend/src/components/OpenQuestionsIndicator.tsx`, `…/lib/flywheelReveal.ts`), elapsed run time, live conversation harness/model in the conversation-pane header.

## Requirements

- **FR-1** — On the dashboard, `GET /api/flywheel/status` reads tracker rows from the `IssueDataService` cache through the server adapter; a feature workspace whose tracker issue is closed is absent from `inFlight`. `src/lib` imports no server code.
- **FR-2** — From the CLI (`pan flywheel status [--json]`), the deriver's default reads each issue's tracker row with `readIssueFromTracker`, at most 4 reads in parallel. A closed issue is absent; an issue no tracker answers stays, with `trackerUnknown: true`.
- **FR-3** — Every `FlywheelInFlightRow` carries `title: string | null` (tracker title; `null` when unknown) and, when the tracker did not answer, `trackerUnknown: true`. The page renders the title (truncated, full text in the `title` attribute) and a muted "tracker unknown" marker.
- **FR-4** — Every row carries `liveAgents: number` (live backend panes whose `issue` matches). A row with `state === 'working'` and `liveAgents === 0` renders "no agent" next to the state, in the page and the CLI.
- **FR-5** — Every row carries `inTick: boolean` (the id is in `lastTick.inFlight`). Tick ids with no workspace become rows (state from the same loader, `lastJournal: null`). The status carries `inFlightSource`: `'tick'` when a conversation row exists and `lastTick !== null`, else `'census'`. The header count shows rows with `inTick` when the source is `tick` (label "in flight (loop)") and all rows otherwise (label "feature workspaces").
- **FR-6** — The idle empty-state copy names the conversation pane toolbar's Start button instead of "Start below".
- **FR-7** — When `POST /api/flywheel/start` answers 409 with `code: 'FlywheelOrphanSession'`, the idle toolbar shows **Start fresh**, which uses the existing confirm dialog and posts `{ fresh: true }`.
- **FR-8** — The left rail shows a **UAT batches** card wrapping `MergeTrainView` with the feature/batch count, independent of run state.
- **FR-9** — The Status tab shows a headline strip: PRs merged in the 30-day window, substrate bugs fixed (filed in the window and closed), order book landed/total when a book is running, features awaiting UAT. Every value is read from an existing source; nothing is written.
- **FR-10** — The status carries `agents: FlywheelAgentSummary[]` — the live backend panes of the in-flight issues. The Status tab lists issue, role, model, pane state, and a button that opens the issue.
- **FR-11** — The rail gains a **Report** tab rendering `GET /api/flywheel/report` as markdown with path and mtime, or "No report yet".
- **FR-12** — The app header shows a needs-you indicator when `lastTick.needsYou !== null` or any in-flight row has `attention === 'needs-you'`. Clicking it opens `/flywheel`, selects the Status tab, and scrolls to the needs-you block.
- **FR-13** — `FlywheelConversationSummary` carries `createdAt`. The page header shows elapsed run time (now − `conversation.createdAt`) while `run === 'running'`; the conversation-pane header shows the live conversation's harness and model from `status.conversation`.
- **NFR-1** — Nothing new is stored. Every added field is derived on read.
- **NFR-2** — The server status read adds no network call: tracker rows come from the in-memory cache and panes from `getBackendPanes()`.
- **NFR-3** — The CLI tracker reads are bounded by `withConcurrencyLimit(tasks, 4)` (`src/lib/concurrency.ts`).
- **NFR-4** — `src/lib/**` never imports `src/dashboard/**` (existing layering rule).
- **NFR-5** — UI follows the dashboard style guide: badges use `StatusBadge` tones from `components/flywheel/primitives.tsx`; no decorative color (the v1 `text-emerald-400` icon is not restored).

- **D13 — Needs-you indicator shares the sidebar's status query** (`useFlywheelStatus({ refetchInterval: 30_000 })`, same query key `['flywheel','status']`), so it adds no polling.
