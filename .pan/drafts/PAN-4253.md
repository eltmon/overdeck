# PAN-4253 — Effort survives relaunch

**Issue:** [PAN-4253](https://github.com/eltmon/overdeck/issues/4253) (S1 of [PAN-4249](https://github.com/eltmon/overdeck/issues/4249)).
**Program PRD:** `.pan/drafts/PAN-4249.md`, section "Sibling issues". **Audit:** first comment on #4249, §2 "Relaunch drops explicit effort".
**Planned:** 2026-10-02, `pan plan --auto`.

## Summary

`AgentState` has no effort field. `pan start --effort max` launches the first session at `max`, but every relaunch (resume, restart, recovery, messaging fallback, session rotation, crash respawn, cloister model handoff) rebuilds the launcher without an effort, so the agent comes back at the role-file frontmatter value (`high`). This slice persists the launched effort and its source on `AgentState` at spawn, and makes every relaunch path re-apply it through one helper that calls `resolveEffort`.

## Glossary

- **Effort** — the reasoning-effort level a harness launches at. Canonical levels, lowest to highest: `low`, `medium`, `high`, `xhigh`, `max` (`EFFORT_LEVELS`, `packages/contracts/src/effort.ts`).
- **Effort source** — which precedence layer produced the effort (`EffortSource`, same file): `explicit`, `item`, `plan`, `tier`, `sub-role`, `role`, `project`, `default`.
- **`resolveEffort`** — the single resolver in `src/lib/agents/resolve-effort.ts`. It walks the precedence chain and clamps the result to what the model and harness support. It returns `{ effort, source, requested, clamped, warning? }`.
- **Clamp** — replacing an unsupported level with the nearest supported canonical level (for example `max` on `ohmypi` becomes `xhigh`). Done by `resolveEffort` via `clampEffort` (`src/lib/agents/effort-support.ts`).
- **AgentState** — the per-agent record at `~/.overdeck/agents/<id>/state.json`. Interface in `src/lib/agents/agent-state-read.ts` (grep `export interface AgentState`).
- **`cleanAgentState`** — the field whitelist every `state.json` read and write passes through (`agent-state-read.ts`, grep `export function cleanAgentState`). A field that is declared on `AgentState` but missing here is silently dropped on save and on read.
- **Relaunch** — any path that starts a new harness process for an agent that already has a `state.json`: resume (`resumeAgent`), restart (`restartAgent`), recovery (`recoverAgent`), the messaging fresh-launch fallback, session rotation, crash respawn, cloister model handoff.
- **Legacy state** — a `state.json` written before this slice, with no `effort` field.
- **Pin rule** — this slice's decision (D1): a relaunch reuses the persisted effort whatever its source; it does not re-read config.

## Decisions

- **D1 — Pin rule.** At every relaunch, a valid persisted `state.effort` wins, whatever `state.effortSource` says. Config is not re-read for an agent that already has a persisted effort. This mirrors `restartAgent`, which keeps `agentState.model` unless a new model is passed. Consequence: changing `roles.<role>.effort` reaches new spawns only.
- **D2 — Re-clamp on relaunch.** The persisted level is passed to `resolveEffort` as `explicit` with the relaunch's model and harness, so a model or harness change clamps it (for example `max` → `xhigh` when the relaunch harness is `ohmypi`). The persisted `effortSource` travels forward unchanged; it is not rewritten to `explicit`.
- **D3 — Legacy fallback.** Legacy state (no valid `effort`) resolves through `resolveEffort({ role: state.role, subRole: state.reviewSubRole, issueId: state.issueId, model, harness })`. That yields `role` → `project` → `default` (`high`), so behavior matches today for every unconfigured role.
- **D4 — Write-back.** `state.effort`/`state.effortSource` always describe the most recent launch. Every relaunch path assigns both fields from the helper result before its existing `saveAgentStateSync`. After the first relaunch, legacy state becomes pinned (D1).
- **D5 — Persist what the caller supplied at spawn.** `spawnAgent` and `spawnRun` persist `options.effort` with `options.effortSource ?? 'explicit'` when `options.effort` is set, and persist nothing when it is not. They do NOT start resolving effort themselves; making `spawnRun` callers resolve and pass effort is S4 ([PAN-4256](https://github.com/eltmon/overdeck/issues/4256)) and S5 ([PAN-4257](https://github.com/eltmon/overdeck/issues/4257)). When they do, persistence is automatic.
- **D6 — Persist the clamped level.** State stores the level the harness launched with (`ResolvedEffort.effort`), not the pre-clamp request. A model switch away from a `max`-capable model and back does not restore `max`.
- **D7 — `SpawnConfig.effort` narrows to `EffortLevel`.** Only `session-rotation.ts:247` and `service-crash.ts:422` construct a `SpawnConfig` with runtime fields; consumers in `acp.ts`, `kimi-code.ts`, `prime-agent.ts` pass it to `string` parameters, so the narrower type compiles. Add `effortSource?: EffortSource`. No `isEffortLevel` guard is needed in the claude-code adapter.
- **D8 — Invalid persisted values are ignored.** `cleanAgentState` keeps `effort` only when `isEffortLevel(raw.effort)`, and keeps `effortSource` only when `effort` is kept. `effortSource` is not validated against a list: that would be a second copy of the `EffortSource` union outside `packages/contracts`, which the PAN-4249 program forbids, and the field is display metadata. A hand-edited `"effort": "ultra"` reads back as legacy state.
- **D9 — Clamp warnings go to the lifecycle log.** When the helper returns a `warning`, relaunch sites call `logAgentLifecycle(agentId, \`relaunch effort: ${warning}\`)` (`src/lib/persistent-logger.ts:51`). No stderr output from server-reachable paths.
- **D10 — Include cloister model handoff.** It is a relaunch of the same agent id and drops effort the same way. It costs one call site.
- **D11 — Only the claude-code line in the spawn-prep resume branch changes.** Non-claude resumes already receive `opts.effort` through `getOhmypiLauncherFields`/`getCodexLauncherFields`/`getAcpLauncherFields`/`getKimiCodeLauncherFields`/`museEffort` (`spawn-prep.ts:720-750`), which run for both fresh and resume launches.

### W2 — `resolveRelaunchEffort` helper (FR-4, D1–D3, D6)

Files: new `src/lib/agents/relaunch-effort.ts`, new `src/lib/agents/__tests__/relaunch-effort.test.ts`.

Write the module exactly in this shape:

```ts
/**
 * Effort for a relaunch of an existing agent (PAN-4253). A persisted
 * state.effort wins whatever its source (the pin rule) and is re-clamped to
 * the relaunch model/harness; legacy state without one resolves through the
 * role → project → default chain. Callers write the result back onto the
 * state so it always describes the most recent launch.
 */
import { isEffortLevel, type EffortLevel, type EffortSource } from '@overdeck/contracts';
import type { AgentState } from './agent-state-read.js';
import type { RuntimeName } from '../runtimes/types.js';
import { resolveEffort, type EffortConfigSlice } from './resolve-effort.js';

export interface RelaunchEffort {
  effort: EffortLevel;
  source: EffortSource;
  warning?: string;
}

export type RelaunchEffortState = Pick<AgentState, 'effort' | 'effortSource' | 'role' | 'reviewSubRole' | 'issueId' | 'model' | 'harness'>;

export function resolveRelaunchEffort(
  state: RelaunchEffortState,
  launch: { model?: string; harness?: RuntimeName; config?: EffortConfigSlice } = {},
): RelaunchEffort {
  const model = launch.model ?? state.model;
  const harness = launch.harness ?? state.harness;
  if (isEffortLevel(state.effort)) {
    const pinned = resolveEffort({ explicit: state.effort, model, harness });
    return { effort: pinned.effort, source: state.effortSource ?? 'explicit', warning: pinned.warning };
  }
  const legacy = resolveEffort({
    role: state.role,
    subRole: state.reviewSubRole,
    issueId: state.issueId,
    model,
    harness,
    config: launch.config,
  });
  return { effort: legacy.effort, source: legacy.source, warning: legacy.warning };
}

/** AgentState fields for a spawn that was given an effort; empty when it was not (D5). */
export function spawnEffortFields(
  effort: EffortLevel | undefined,
  source: EffortSource | undefined,
): Pick<AgentState, 'effort' | 'effortSource'> {
  return effort === undefined ? {} : { effort, effortSource: source ?? 'explicit' };
}
```

Tests (`relaunch-effort.test.ts`; pass `config` explicitly so no real `~/.overdeck` config is read; build a minimal `EffortConfigSlice` the way `src/lib/agents/__tests__/resolve-effort.test.ts` does):
- persisted `max`, source `role`, model `claude-opus-5-5`, harness `claude-code` → `{ effort: 'max', source: 'role' }`.

- `spawnEffortFields(undefined, 'role')` → `{}`; `spawnEffortFields('max', undefined)` → `{ effort: 'max', effortSource: 'explicit' }`.
