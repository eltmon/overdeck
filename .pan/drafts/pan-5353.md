# PAN-5353 — Send now: flush a queued message into a running Claude Code turn

**Issue:** [PAN-5353](https://github.com/eltmon/overdeck/issues/5353) · **Builds on:** [PAN-4292](https://github.com/eltmon/overdeck/issues/4292) (Steer, `.pan/drafts/pan-4292.md`) · **Planned:** 2026-11-15 · **Revised:** 2026-11-15 (planning agent verified every reference against `main` at `7c5db93e1ac`)

## Summary

When the operator sends a message while a Claude Code turn runs, Overdeck pastes it and presses Enter. Claude Code puts it in its own queue, and the dashboard bubble shows **Sent · waiting for transcript** until the turn reaches a tool boundary or ends. In the Claude Code terminal the operator can press **Ctrl+Enter** on an empty input box to interrupt the turn and send the queued messages at once. The dashboard has no way to do this for a message it already sent. Today the only option is to type a new message with Steer.

This issue adds **Send now**. It is a link on a queued bubble, and **Ctrl+Enter / Cmd+Enter on an empty composer** does the same. Both press Claude Code's send-now chord (Ctrl+X Ctrl+S) in the pane and type no text.

## Glossary

- **Queued message**: a message Overdeck already pasted and submitted with Enter while Claude Code was busy. Claude Code holds it (the pane shows `ctrl+enter to send now` and `❯ Press up to edit queued messages`) and writes a `queue-operation` `enqueue` record to the transcript at once. In the dashboard this is an optimistic user bubble (id starts with `optimistic-`) with `acknowledged === true`. Its footer reads `Sent · waiting for transcript` (`src/dashboard/frontend/src/components/chat/messagesTimeline/messageRows.tsx`, `UserMessageRow`, search `'Sent · waiting for transcript'`).
- **Send-now chord**: Ctrl+X Ctrl+S, Claude Code's `chat:sendNow` action. PAN-4292 spelled it once per backend in `src/lib/terminal-backends/steer-keys.ts`: tmux `STEER_TMUX_KEYS = ['C-x', 'C-s']`, Herdr `STEER_HERDR_KEYS = ['ctrl+x', 'ctrl+s']`, PTY bytes `STEER_PTY_BYTES = '\x18\x13'`.
- **Send now**: this issue's action. It presses the chord with **no text**, so it carries no message of its own.
- **Steer**: PAN-4292's delivery, which types a new message and then presses the chord. It stays unchanged.
- **Steer kind**: `getHarnessBehavior(harness).steerKind` (`packages/contracts/src/harness-behavior.ts`, line ~117 for claude-code). Send now exists only where it equals `'send-now-keys'`, which today means Claude Code only. Server code imports `getHarnessBehavior` from `src/lib/runtimes/behavior.ts`; the frontend imports it from `@overdeck/contracts`.
- **Agent pane IO**: `resolveAgentPaneIo()` in `src/lib/terminal-backends/agent-pane-io.ts`. It is the backend-neutral read/press seam for one agent pane (Herdr `pane.send_keys`, or tmux `send-keys`). A Herdr host whose agent Herdr does not hold falls back to tmux (legacy agents on `tmux -L overdeck`).
- **Ensure-main**: `ensureMainInputTarget(agentId)` in `src/lib/agents/input-target.ts`. It moves Claude Code's input selector back to the main agent, or refuses with `{ ok: false, reason, inputTarget }`.
- **Send queue**: `enqueueConversationSend(conversationName, task)` in `src/dashboard/frontend/src/lib/composerSendQueue.ts`. It runs one conversation's composer POSTs one at a time, in order (PAN-5184). The composer keys it by `conversation.name` on both the conversation and the agent route.
- **Door**: a server function that owns one write and is the only code path for it. Here: `sendNowToConversation` and `sendNowToAgent`.

## Verified mechanics (live probe, 2026-11-15)

The probe used Claude Code **2.1.325** with haiku on a throwaway tmux socket (`tmux -L sendnowprobe`). In every case the input box was empty when the chord was pressed.

1. **Busy turn, one queued message, chord alone.** The turn was writing a 900-word story when it received `Stop the story and reply with only the word QUEUED-B.` with Enter. The pane showed `ctrl+enter to send now` and `❯ Press up to edit queued messages`. `send-keys C-x C-s` interrupted the turn: no story text was written and the model answered `QUEUED-B` at once.
2. **Busy turn, nothing queued, chord alone.** This is a **no-op**. The turn kept running (`Philosophizing… (9s · thinking)`) and was not interrupted.
3. **Idle, chord alone.** This is a **no-op**. The pane did not change.
4. **Busy turn, two queued messages, chord alone.** Both messages (`Reply with the word ONE.`, `Also reply with the word TWO.`) were submitted together, and a new turn started.
5. **PTY supervisor.** `src/lib/channels/pty-supervisor.ts` (~line 802) forwards pane stdin to the child (`process.stdin.on('data', (chunk) => child.write(chunk.toString()))`), so pane keys reach supervised sessions too. Send now needs **no per-tier delivery work**: pressing keys in the pane works on every delivery tier.

Consequences: the route does **not** need to check whether anything is queued, because the chord is harmless with an empty queue and an empty input box (2, 3). Send now flushes **every** queued message, not one bubble (4), and the UI copy says so.

**Agent-route acknowledgement (verified in code).** On the agent route, `messageAgent` (`src/lib/agents/messaging.ts`, search `deliver and wait for the transcript to show the turn`) waits for the transcript before the POST answers. That wait does not block a queued message: `queuedPromptText` in `src/lib/transcript-landing.ts` counts the `queue-operation` `enqueue` record Claude Code writes the instant it queues a message. So the agent POST answers promptly, the bubble becomes acknowledged, and Send now (queued behind it on the send queue) runs right after.

## Decisions

- **D1 — Keys only, one tmux call.** Send now presses the chord and never pastes text. On tmux it is **one** call, `send-keys -t <exact pane target> C-x C-s`, the same shape the steer path uses (`src/lib/tmux.ts` line ~1128: `tmuxExecAsync(['send-keys', '-t', sessionName, ...submitKeys])`), so the two keys can never be split by another writer. On Herdr it is one `pane.send_keys` call with `keys: ['ctrl+x', 'ctrl+s']`. It never sends `C-Enter`/`ctrl+enter` (PAN-4292 probe: tmux sends nothing for it and Herdr sends `\r`). Nothing is added to `src/lib/tmux.ts`: it is at its 1167-line allowlist cap.
- **D2 — Claude Code only.** The gate is `steerKind === 'send-now-keys'`. Any other harness gets 422 `steer-unsupported`. Pi queues follow-ups differently and is out of scope.
- **D3 — Conversations and workspace agents both.** The composer already steers both (`ComposerFooter.tsx`, `showDeliverySelector`), so Send now covers both routes. Remote (Fly) agents are refused with 422 `steer-unsupported`, the same rule as `steerRefusalReason` in `src/lib/agents/messaging.ts` (search `steer is not supported for remote agents`).
- **D4 — Never into a permission menu or a subagent view.** Before it presses, each door checks for a permission prompt on the pane, then runs ensure-main, in that order (ensure-main's Down/Enter would answer a menu). The conversation door uses `conversationPendingPermission(conv)` exactly as `src/lib/overdeck/conversation-message.ts` does (search `PAN-4278: never paste into a permission prompt`). The agent door has no conversation row, so it reads the pane once through `resolveAgentPaneIo(agentId).read(PANE_CAPTURE_LINES)` and refuses when `parsePermissionPrompt(text)` (`src/lib/agents/permission-prompt.ts`) returns non-null. A pane that cannot be read here is not a refusal; ensure-main reads it again and refuses on its own if it cannot.
- **D5 — Serialized behind sends.** The frontend runs every Send now request through `enqueueConversationSend(conversation.name, …)`, so the chord can never land between this tab's pending paste and its Enter. This covers one browser tab only; see Hazards.
- **D6 — Where the link shows.** It shows on a user bubble when all of these hold: the id starts with `optimistic-`, `acknowledged === true` (the non-pending branch of `UserMessageRow`), `deliveryState` is not `unknown`, and the row was given a Send now target. `ConversationView` gives the target only when `agentBusy` is true and the conversation's harness steer kind is `send-now-keys`. The link never shows on a `Sending…`, held, scheduled, subagent, failed, or transcript-backed bubble, because those never reached Claude Code's queue (or already left it).
- **D7 — Ctrl+Enter on an empty composer.** "Empty" for Send now means: the editor's own text, read at key time with `$getRoot().getTextContent()` (not the lagging `text` state behind `isEmpty`), is blank, there are **no** pending attachments at all (uploading, ready or failed), and there are no citations. A composer holding only an uploading attachment is therefore *not* empty, and Ctrl+Enter keeps today's path (`handleSubmit`, which toasts "Please wait for uploads to finish"), because the operator meant to send that attachment. On a `send-now-keys` harness with `conversation.sessionAlive`, an empty Ctrl/Cmd+Enter calls Send now. It ignores `agentBusy`, because the chord is a no-op when idle with an empty input (probe 3) and `agentBusy` may be stale. A non-empty composer keeps PAN-4292's behaviour (steer with text). On a harness with no steer, an empty Ctrl+Enter keeps today's behaviour (nothing is sent).
- **D8 — Feedback.** On success the UI shows nothing extra: the bubble resolves when the transcript catches up. On failure it shows `toast.error(<server error text>)` and the bubble is unchanged. The link shows `Sending now…` while its request runs and is disabled meanwhile.
- **D9 — Copy.** The link label is `Send now`. Its `title` is `Interrupt the current turn and send every queued message now (Claude Code Ctrl+Enter)`. Its `aria-label` is `Send queued messages now`.
- **D10 — Two doors, split by package.** `src/lib/agents/send-now.ts` holds the agent door and the shared `SendNowResult` type. `src/lib/overdeck/conversation-send-now.ts` holds the conversation door and imports the type from `../agents/send-now.js`. This matches the existing import direction: `overdeck/conversation-message.ts` imports `agents/input-target.js` statically, while `agents/messaging.ts` only lazy-imports `overdeck/conversations.js`. The agent door never imports `overdeck/*`. It imports `getAgentState` from `./agent-state-read.js` (the leaf module), never from `../agents.js`, or `lint:circular` fails.
- **D11 — The agent door does its own refusal checks; `messaging.ts` is not changed.** `steerRefusalReason` (`src/lib/agents/messaging.ts` line ~186) is private and returns only a string, which loses the HTTP code. The agent door calls the same primitives itself, in the same order: `getHarnessBehavior(harness).steerKind`, then `agentState.paused === true`, `getAgentRuntimeStateSync(id)?.state === 'suspended'`, `agentState.status === 'stopped'`, then `loadRemoteAgentState(id)?.vmName` (lazy import of `../remote/remote-agents.js`, as `messaging.ts` does).
- **D12 — Status and code for every outcome.** See FR-3 and FR-8. A press that throws (the pane disappeared, Herdr refused, tmux failed) answers 502 `press-failed`; nothing else is retried.
- **D13 — Routes in one top-level route file.** Both routes live in `src/dashboard/server/routes/send-now.ts`. The no-loss matrix test (`tests/unit/lib/overdeck/no-loss-matrix.test.ts`, `enumerateHttpRoutes`) scans only the top-level files in `src/dashboard/server/routes/`, not `routes/agents/`.
- **D14 — Frontend client in its own module.** `requestSendNow` and `sendNowQueued` live in a new `src/dashboard/frontend/src/lib/composerSendNow.ts`, so `composerSend.ts` keeps no toast import and the client item touches no shared file.

## Requirements

- **FR-1**: `POST /api/conversations/:name/send-now` presses the send-now chord in the conversation's pane and answers `200 {"ok":true}`.
- **FR-2**: `POST /api/agents/:id/send-now` does the same for a workspace agent's pane.
- **FR-3**: Both routes answer `422 {code:'steer-unsupported'}` when the harness steer kind is not `send-now-keys`, or when the agent is remote. They answer `409 {code:'permission-pending'}` when a permission prompt is on the pane, and `409 {code:'input-target-not-main'}` when ensure-main fails. They answer `404 {code:'not-found'}` for an unknown name or id. They answer `409 {code:'not-running'}` when the conversation has `status === 'ended'`, or the agent is paused, suspended or stopped. In every refusal no key is pressed.
- **FR-4**: The chord goes through one helper, `pressSendNowChord(agentId)`, which reuses `STEER_TMUX_KEYS` and `STEER_HERDR_KEYS`. No new spelling of the chord exists anywhere else.
- **FR-5**: A queued bubble that meets D6 shows a `Send now` link. Clicking it calls the right route through the conversation send queue.
- **FR-6**: Ctrl/Cmd+Enter on an empty composer calls Send now on a `send-now-keys` harness (D7).
- **FR-7**: A failed Send now shows a toast with the server's error text, and the bubble stays as it was.
- **FR-8**: The conversation route answers `409` with the body of `conversationWriteRefusalBody(conv)` (codes `vault-browse-copy` or `conversation-released`) for a read-only conversation copy. Both routes answer `502 {code:'press-failed'}` when pressing the chord throws, and `403` on a failed origin check.
- **FR-9**: Both new paths are scoped `tell` in `route-scopes.ts`, appear in `TELEMETRY_PROPERTY_DOMAINS.client_route` and `docs/TELEMETRY.md`, and have `no-loss-matrix.ts` rows.
- **NFR-1**: Send now never types text into the pane.
- **NFR-2**: No `execSync` and no `*Sync` tmux helper is added. Server code uses async primitives only (rules: no-execsync-server, prefer-async). `getAgentRuntimeStateSync` is reused as `messaging.ts` already does; it reads a state file and is not a tmux helper.
- **NFR-3**: No file grows past its allowed line count: `ComposerFooter.tsx` stays at or below 1000 lines (975 at planning time, no allowlist row); `ConversationPanel.tsx` stays at or below its 1531 allowlist cap; `src/lib/tmux.ts` is not touched.

### WI-2a — Agent door `sendNowToAgent` and the `SendNowResult` type (FR-2, FR-3, FR-8, D2–D4, D10–D12)

**New file:** `src/lib/agents/send-now.ts`. **Test:** `src/lib/agents/__tests__/send-now.test.ts`.

```ts
export type SendNowCode =
  | 'not-found' | 'not-running' | 'steer-unsupported' | 'permission-pending'
  | 'input-target-not-main' | 'press-failed' | 'vault-browse-copy' | 'conversation-released';

export type SendNowResult =
  | { ok: true }
  | { ok: false; status: 404 | 409 | 422 | 502; code: SendNowCode; error: string };

export interface AgentSendNowDeps {
  getAgentState: (id: string) => AgentState | null;           // default: from './agent-state-read.js'
  getRuntimeState: (id: string) => { state?: string } | null;  // default: getAgentRuntimeStateSync from './runtime-state.js'
  isRemote: (id: string) => Promise<boolean>;                  // default: lazy import of '../remote/remote-agents.js', loadRemoteAgentState(id)?.vmName truthy
  readPane: (id: string) => Promise<string>;                    // default: (await resolveAgentPaneIo(id)).read(PANE_CAPTURE_LINES)
  ensureMain: (id: string) => Promise<EnsureMainResult>;        // default: ensureMainInputTarget
  press: (id: string) => Promise<void>;                         // default: pressSendNowChord
}

export async function sendNowToAgent(rawId: string, deps: Partial<AgentSendNowDeps> = {}): Promise<SendNowResult>;
```

`PANE_CAPTURE_LINES` comes from `../session-pane-choice.js` (the same constant `conversation-permission.ts` uses). Steps, in this order; each refusal returns before any later step and never calls `press`:

1. `const id = normalizeAgentId(rawId)` (`./identity.js`). `getAgentState(id)` null → `404 not-found`, error `` `Agent not found: ${id}` ``.
2. `const behavior = getHarnessBehavior(state.harness ?? 'claude-code')` (`../runtimes/behavior.js`). `behavior.steerKind !== 'send-now-keys'` → `422 steer-unsupported`, error `` `Send now is supported for Claude Code only; ${id} runs ${behavior.displayName}` ``.
3. `state.paused === true` → `409 not-running` with `paused`; `getRuntimeState(id)?.state === 'suspended'` → `suspended`; `state.status === 'stopped'` → `stopped`. Error: `` `${id} is ${why}, so it has no running turn to interrupt` ``.
4. `await isRemote(id)` → `422 steer-unsupported`, error `` `Send now is not supported for remote agents (${id})` ``.
5. Permission check (D4): `try { const text = await readPane(id); if (parsePermissionPrompt(text)) return 409 permission-pending, error 'Waiting: the agent needs a permission answer first' } catch { /* unreadable: fall through to ensure-main */ }`.
6. `const target = await ensureMain(id)`; `!target.ok` → `409 input-target-not-main`, error `target.reason`.
7. `try { await press(id) } catch (err) { return 502 press-failed, error `Could not press send-now in ${id}'s pane: ${message}` }` → `{ ok: true }`.

**Tests** (all deps injected; no real panes, no timers): one case per refusal in steps 1–7 (unknown id, codex harness, paused, suspended, stopped, remote, permission prompt on pane, ensure-main refusal, press throws), each asserting the status, the code, and that `press` was **not** called (except the press-throws case, where it was called once). Happy path: `press` called once with the normalized id and the result is `{ ok: true }`. Ordering case: a permission prompt on the pane means `ensureMain` is **not** called. Unreadable pane case: `readPane` throws, `ensureMain` is still called, and the press happens.

```ts
// Same ceiling as the message POST (composerSend.ts, 120 s). The client must not
// abort while the server may still be pressing ensure-main keys or the chord:
// an early abort frees the send queue, and the next paste could land mid-press
// (the same reason Cancel never aborts, docs/DASHBOARD-ARCHITECTURE.md).
const SEND_NOW_TIMEOUT_MS = 120_000;

/** POST the send-now route. Throws Error(body.error) on a non-2xx answer. */
export async function requestSendNow(conversationName: string, agentId?: string): Promise<void> {
  const endpoint = agentId
    ? `/api/agents/${encodeURIComponent(agentId)}/send-now`
    : `/api/conversations/${encodeURIComponent(conversationName)}/send-now`;
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), SEND_NOW_TIMEOUT_MS);
  try {
    const res = await fetch(endpoint, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: '{}', signal: controller.signal });
    if (!res.ok) {
      const body = await res.json().catch(() => null) as { error?: unknown } | null;
      throw new Error(typeof body?.error === 'string' ? body.error : `Send now failed (${res.status})`);
    }
  } finally {
    clearTimeout(timer);
  }
}

/** Run Send now on the conversation's send queue; a failure becomes a toast. Never rejects. */
export function sendNowQueued(conversationName: string, agentId?: string): Promise<void> {
  return enqueueConversationSend(conversationName, () => requestSendNow(conversationName, agentId))
    .catch((err: unknown) => { toast.error(err instanceof Error ? err.message : 'Send now failed'); });
}
```

(`toast` from `sonner`; `enqueueConversationSend` from `./composerSendQueue`.) Callers use `sendNowQueued`, never `requestSendNow`.

Tests (mock `fetch` and `sonner`; call `resetConversationSendQueues()` in `beforeEach`; no real timers needed):
- With `agentId` the URL is `/api/agents/agent-pan-1/send-now`; without it `/api/conversations/conv%20a/send-now` for name `conv a`.
- A 409 answer with `{ error: 'Waiting: the agent needs a permission answer first' }` makes `sendNowQueued` resolve and call `toast.error` with that text.
- A pending task enqueued first on the same conversation name delays the send-now `fetch` until that task resolves.

## Repo rules that apply

- No `execSync` and no new `*Sync` tmux helper in server-reachable code. Use `tmuxExecAsync` / Herdr's async API.
- Never send `C-Enter`/`ctrl+enter` to a pane (PAN-4292).
- A new HTTP route needs a `route-scopes.ts` row, a `no-loss-matrix.ts` row, and (once scoped) a `client_route` telemetry value plus its `docs/TELEMETRY.md` entry, or CI fails.
- New `src/lib` modules import `getAgentState` from `agent-state-read.js`, never `agents.js` (`lint:circular`).
- Tests that wait on timers use `vi.useFakeTimers()`. A source-reading (grep-the-source) test fails lint, so assert on behaviour. No `skipIf`/`.only`.
- New must-run frontend tests go in `scripts/frontend-test-subset.txt` in sorted position.
- Quality gates: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Do not run the full `npm test` on the host. After a `packages/contracts` change, run `npm run build:contracts` first.
- Commit per item with an `Item: <item-id>` trailer.

## Hazards

- **Text in the pane's input box.** The probe always had an empty input box. If the operator typed text into the agent's input in the Terminal tab, the chord submits that text along with the queue (idle: as a plain submit). This is accepted and documented (WI-7.1); Send now does not read or clear the input box.
- **One-tab serialization.** D5 orders this tab's sends only. The server has no per-conversation lock, so a send from another tab, a phone or `pan tell` that is mid-paste could in principle receive the chord between its paste and its Enter. Accepted; out of scope.
- **The bubble may already be the running turn.** An acknowledged bubble on a busy agent may be the message the current turn is answering. Clicking Send now then flushes nothing and is a no-op (probe 2).
- **`agentBusy` can be stale.** The link may show briefly after the turn ended. The chord is then a no-op (probe 3).
- **Unprobed dialogs.** The probe covered busy and idle screens only. The chord on an AskUserQuestion or plan-approval dialog is unprobed; the permission guard and ensure-main do not cover those. The live check (AC-9) tries it once and records the result; a harmful result becomes a follow-up issue, not a blocker for this one.
- **Linked conversations.** A conversation on another linked machine is reached through the generic `/api/conversations/@<machine>/…` proxy, the same way its message sends are (`requiredScopeFor` maps it to the local row, `route-scopes.ts` search `LINKED_CONVERSATION_PREFIX`). Nothing special is built for it. A linked machine running an older Overdeck answers 404, and the toast shows that error.
