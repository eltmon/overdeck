# PAN-5353 — Send now: flush a queued message into a running Claude Code turn

**Issue:** [PAN-5353](https://github.com/eltmon/overdeck/issues/5353) · **Builds on:** [PAN-4292](https://github.com/eltmon/overdeck/issues/4292) (Steer, `.pan/drafts/pan-4292.md`) · **Planned:** 2026-11-15

## Summary

When the operator sends a message while a Claude Code turn runs, Overdeck pastes it and presses Enter. Claude Code puts it in its own queue, and the dashboard bubble shows **Sent · waiting for transcript** until the turn reaches a tool boundary or ends. In the Claude Code terminal the operator can press **Ctrl+Enter** on an empty input box to interrupt the turn and send the queued messages at once. The dashboard has no way to do this for a message it already sent. Today the only option is to type a new message with Steer.

This issue adds **Send now**. It is a link on a queued bubble, and **Ctrl+Enter / Cmd+Enter on an empty composer** does the same. Both press Claude Code's send-now chord (Ctrl+X Ctrl+S) in the pane and type no text.

## Glossary

- **Queued message**: a message Overdeck already pasted and submitted with Enter while Claude Code was busy. Claude Code holds it (the pane shows `ctrl+enter to send now` and `❯ Press up to edit queued messages`). In the dashboard this is an optimistic user bubble with `acknowledged === true`. Its footer reads `Sent · waiting for transcript` (`messageRows.tsx`, `UserMessageRow`).
- **Send-now chord**: Ctrl+X Ctrl+S, Claude Code's `chat:sendNow` action. PAN-4292 put its spellings in `src/lib/terminal-backends/steer-keys.ts`: tmux `STEER_TMUX_KEYS = ['C-x','C-s']`, Herdr `STEER_HERDR_KEYS = ['ctrl+x','ctrl+s']`, PTY bytes `STEER_PTY_BYTES = '\x18\x13'`.
- **Send now**: this issue's action. It presses the chord with **no text**, so it carries no message of its own.
- **Steer**: PAN-4292's delivery, which types a new message and then presses the chord. It stays unchanged.
- **Steer kind**: `getHarnessBehavior(harness).steerKind` (`packages/contracts/src/harness-behavior.ts`). Send now exists only where it equals `'send-now-keys'`, which today means Claude Code only.
- **Agent pane IO**: `resolveAgentPaneIo()` in `src/lib/terminal-backends/agent-pane-io.ts`. It is the backend-neutral read/press seam for one agent pane (Herdr `pane.send_keys`, or tmux `send-keys`).

## Verified mechanics (live probe, 2026-11-15)

The probe used Claude Code **2.1.325** with haiku on a throwaway tmux socket (`tmux -L sendnowprobe`). In every case the input box was empty when the chord was pressed.

1. **Busy turn, one queued message, chord alone.** The turn was writing a 900-word story when it received `Stop the story and reply with only the word QUEUED-B.` with Enter. The pane showed `ctrl+enter to send now` and `❯ Press up to edit queued messages`. `send-keys C-x C-s` interrupted the turn: no story text was written and the model answered `QUEUED-B` at once.
2. **Busy turn, nothing queued, chord alone.** This is a **no-op**. The turn kept running (`Philosophizing… (9s · thinking)`) and was not interrupted.
3. **Idle, chord alone.** This is a **no-op**. The pane did not change.
4. **Busy turn, two queued messages, chord alone.** Both messages (`Reply with the word ONE.`, `Also reply with the word TWO.`) were submitted together, and a new turn started.
5. **PTY supervisor.** `src/lib/channels/pty-supervisor.ts` (~line 802) forwards pane stdin to the child (`process.stdin.on('data', (chunk) => child.write(chunk.toString()))`), so pane keys reach supervised sessions too. Send now needs **no per-tier delivery work**: pressing keys in the pane works on every delivery tier.

Consequences: the route does **not** need to check whether anything is queued, because the chord is harmless with an empty queue (2, 3). Send now flushes **every** queued message, not one bubble (4), and the UI copy says so.

## Decisions

- **D1 — Keys only.** Send now presses `C-x C-s` (tmux) or `ctrl+x ctrl+s` (Herdr) in the pane and never pastes text. It never sends `C-Enter`/`ctrl+enter` (PAN-4292 probe: tmux sends nothing for it and Herdr sends `\r`).
- **D2 — Claude Code only.** The gate is `steerKind === 'send-now-keys'`. Any other harness gets 422 `steer-unsupported`. Pi queues follow-ups differently and is out of scope.
- **D3 — Conversations and workspace agents both.** The composer already steers both (`ComposerFooter.tsx`, `showDeliverySelector`), so Send now covers both routes. Remote (Fly) agents are refused with 422, the same rule as `steerRefusalReason` in `src/lib/agents/messaging.ts`.
- **D4 — Same guards as a message.** Before it presses, the server runs the permission-prompt guard and `ensureMainInputTarget`, in the same order as `src/lib/overdeck/conversation-message.ts` (search `PAN-4278: never paste into a permission prompt`). The chord must never land in a permission menu or a subagent view.
- **D5 — Serialized behind sends.** The frontend runs the Send now request through `enqueueConversationSend(conversationName, …)` (`src/dashboard/frontend/src/lib/composerSendQueue.ts`). The chord therefore can never land between a pending paste and its Enter.
- **D6 — Where the link shows.** It shows on a user bubble when all of these hold: the id starts with `optimistic-`, `acknowledged === true`, no `deliveryState` of `held`/`unknown`, the harness steer kind is `send-now-keys`, and `agentBusy` is true. It does not show on a `Sending…`, held, failed, or transcript-backed bubble, because those never reached Claude Code's queue.
- **D7 — Ctrl+Enter on an empty composer.** This counts only when the composer has no text, no ready attachments and no citations, the same emptiness test as the send button's `disabled` (`ComposerFooter.tsx`, ~line 778). On a `send-now-keys` harness, Ctrl/Cmd+Enter then calls Send now. It ignores `agentBusy`, because the chord is a no-op when idle (probe 3) and `agentBusy` may be stale. A non-empty composer keeps PAN-4292's behaviour (steer with text). On a harness with no steer, an empty Ctrl+Enter does nothing, as today.
- **D8 — Feedback.** On success the UI shows nothing extra: the bubble resolves when the transcript catches up. On failure it shows `toast.error(<server error text>)`. The link shows `Sending now…` while its request runs and is disabled meanwhile.
- **D9 — Copy.** The link label is `Send now`. Its tooltip is `Interrupt the current turn and send every queued message now (Claude Code Ctrl+Enter)`.

## Requirements

- **FR-1**: `POST /api/conversations/:name/send-now` presses the send-now chord in the conversation's pane and answers `200 {"ok":true}`.
- **FR-2**: `POST /api/agents/:id/send-now` does the same for a workspace agent's pane.
- **FR-3**: Both routes answer `422 {code:'steer-unsupported'}` when the harness steer kind is not `send-now-keys`, or when the agent is remote. They answer `409 {code:'permission-pending'}` when a permission prompt is answerable, and `409 {code:'input-target-not-main'}` when ensure-main fails. They answer `404` for an unknown name or id. They answer `409 {code:'not-running'}` when there is no live session. In every refusal no key is pressed.
- **FR-4**: The chord goes through one helper, `pressSendNowChord()`, which reuses `STEER_TMUX_KEYS` and `STEER_HERDR_KEYS`. No new spelling of the chord exists anywhere else.
- **FR-5**: A queued bubble that meets D6 shows a `Send now` link. Clicking it calls the right route through the conversation send queue.
- **FR-6**: Ctrl/Cmd+Enter on an empty composer calls Send now on a `send-now-keys` harness (D7).
- **FR-7**: A failed Send now shows a toast with the server's error text, and the bubble stays as it was.
- **NFR-1**: Send now never types text into the pane.
- **NFR-2**: No `execSync` or `*Sync` tmux helper is added. Server code uses async primitives only (rules: no-execsync-server, prefer-async).

### WI-2 — Server door `sendNow` (FR-1..FR-3, D2–D4)

**New file:** `src/lib/agents/send-now.ts`.

```ts
export type SendNowResult =
  | { ok: true }
  | { ok: false; status: 404 | 409 | 422; code: 'not-found' | 'not-running' | 'steer-unsupported' | 'permission-pending' | 'input-target-not-main'; error: string };

export async function sendNowToConversation(name: string, deps?: Partial<SendNowDeps>): Promise<SendNowResult>;
export async function sendNowToAgent(agentId: string, deps?: Partial<SendNowDeps>): Promise<SendNowResult>;
```

Steps for the conversation path. Mirror `conversation-message.ts`, and read it before writing: `getConversationByName`, `conv.harness ?? 'claude-code'`, `conv.tmuxSession`, `behavior.capabilities.paneInputGuard`.
1. `getConversationByName(name)`. If null, return 404 `not-found`.
2. `getHarnessBehavior(harness).steerKind !== 'send-now-keys'` → 422 `steer-unsupported`, with error `` `${behavior.displayName} has no send-now` ``.
3. Session not alive → 409 `not-running`, with error `The conversation is not running`. Use the same liveness check the message route uses before delivery. Search `conversation-message.ts` for how it decides the session is alive, and reuse that call. Never add a new liveness check (CLAUDE.md: `src/lib/agents/liveness.ts` is the one module).
4. If `behavior.capabilities.paneInputGuard`: call `conversationPendingPermission(conv)`. If `?.answerable`, return 409 `permission-pending` with error `Waiting: the agent needs a permission answer first`. Then call `ensureMainInputTarget(conv.tmuxSession)`. If `!ok`, return 409 `input-target-not-main` with `target.reason`.
5. `await pressSendNowChord(conv.tmuxSession)` → `{ ok: true }`.

The agent path follows the same steps with the agent's state: harness from agent state, then refuse remote through `loadRemoteAgentState(id)?.vmName`, then refuse when paused/suspended/stopped (reuse the checks in `steerRefusalReason`, `src/lib/agents/messaging.ts` ~line 186, by extracting a shared helper if needed), then ensure-main, then press. The agent route has no conversation permission helper, so it skips step 4's permission check. It still runs ensure-main.

Inject every external call through `deps` (as `conversation-message.ts` does), so the tests need no real panes.

**Tests:** `src/lib/agents/__tests__/send-now.test.ts`. Write one case per refusal code. Each refusal asserts that `pressSendNowChord` was **not** called, and the happy path asserts it was called once with the session name.

## Repo rules that apply

- No `execSync` and no new `*Sync` tmux helper in server-reachable code. Use `sendKeysAsync`.
- Never send `C-Enter`/`ctrl+enter` to a pane (PAN-4292).
- A new HTTP route needs both a `route-scopes.ts` row and a `no-loss-matrix.ts` row, or CI fails.
- Tests that wait on timers use `vi.useFakeTimers()`. A source-reading (grep-the-source) test fails lint, so assert on behaviour.
- Quality gates: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Do not run the full `npm test` on the host.
