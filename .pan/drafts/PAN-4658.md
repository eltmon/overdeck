## Glossary

- **Citation** — one saved annotation: a span of selected text plus an optional comment. Type `PendingCitation` in `lib/citationFormat.ts`. Each conversation has its own ordered list of pending citations, stored by `lib/composerCitations.ts` under `localStorage` key `conv-citations:<conversationName>`.
- **Citation source** — `PendingCitation.source`, a discriminated union. Today its only member is `{ kind: 'message'; messageId; role }`. This issue adds `{ kind: 'file'; path }`.
- **Message citation** — a citation whose source kind is `'message'` (PAN-4642).
- **File citation** — a citation whose source kind is `'file'` (this issue): text selected in an editor pane's Preview, with `path` = the absolute file path the pane edits.
- **Editor pane** — a Stage tab with `paneType: 'editor'` rendered by `components/Stage/panes/EditorPane.tsx`. Its Preview sub-tab renders the unsaved `draft` through `MarkdownTab` → `ChatMarkdown`.
- **File chip** — `components/chat/MarkdownFileLink.tsx`, the clickable markdown-file link that `ChatMarkdown` renders. It is the only caller of `openOrFocusEditorPane`.
- **Cite target** — the conversation whose composer receives an editor pane's file citations. Stored on the pane as `WorkspacePane.citeConversationName`.
- **Origin conversation** — the conversation whose timeline rendered the file chip that opened (or last re-focused) an editor pane.
- **Citation-target context** — a new React context (`CitationTargetContext`, value `string | null`) that tells any `MarkdownFileLink` beneath it which conversation it should record as the cite target.
- **Cite layer** — `CiteSelectionLayer` in `components/chat/citations/CiteSelectionToolbar.tsx`: watches the document selection inside a root element, shows the floating **Cite** button, then the comment box.
- **Selection resolver** — a function that maps a DOM `Selection` to `{ source, quotedText }` or `null`. The message resolver needs both selection ends inside one `[data-cite-message-id]` element; the file resolver accepts any non-empty selection.
- **Citation block** — the text prepended to a prompt on send (`composePromptWithCitations`).
- **Frontend CI subset** — `scripts/frontend-test-subset.txt` (PAN-4697). CI runs only the frontend test files listed there. It is no longer a `package.json` script line.

All frontend paths below are relative to `src/dashboard/frontend/src/` unless they start with `src/`, `scripts/`, `docs/` or `features/`.

## Problem

PAN-4642 lets the operator select text in a conversation reply, add a comment, and have it travel with the next prompt. Operators also read plans, PRDs and briefs in the Stage editor pane's Preview, and want to push back on a passage there the same way. The editor pane has no idea which conversation it belongs to, so there is no composer to send the citation to.

## Decisions (made here; auto mode)

- **D1 — Cite target = origin conversation, recorded on the pane.** When a file chip inside a conversation's main timeline opens or re-focuses an editor pane, the pane records that conversation as `citeConversationName`. The issue's other two candidates are rejected: "most recently active conversation pane" can silently route a note to the wrong agent, and an explicit picker is a new UI surface the issue does not require. The issue says editor tabs open "from many places"; in the current code `MarkdownFileLink` is the only caller of `openOrFocusEditorPane`, but it is rendered on non-conversation surfaces too (D3).
- **D2 — The origin comes from `MessagesTimeline`, not `ConversationPanel`.** `MessagesTimeline` already receives `citationsEnabled` and `conversationName`. It wraps its tree in `<CitationTargetContext.Provider value={citationsEnabled && conversationName ? conversationName : null}>`. So a chip records a target only when that conversation shows a composer (the PAN-4642/PAN-4681 gate). Subagent transcripts and other mounts pass `null`. `ConversationPanel.tsx` stays untouched (it is 11 lines under its cap).
- **D3 — No origin ⇒ no Cite.** An editor pane with no `citeConversationName` (opened from an issue-overview tab, a PRD viewer, a read-only conversation, or persisted before this change) shows no Cite button. Nothing guesses a target.
- **D4 — Re-focus rule.** `openOrFocusEditorPane(filePath, label, citeConversationName)`: if a pane for `filePath` exists and `citeConversationName` is a non-empty string different from the pane's current value, the pane's value is replaced (the most recent conversation that opened the file wins). A `null` argument never clears a recorded value.
- **D5 — Chain through the editor preview.** `EditorPane` wraps its Preview in `<CitationTargetContext.Provider value={pane.citeConversationName ?? null}>`, so a file chip inside the preview opens its file with the same cite target.
- **D6 — Source shape.** `{ kind: 'file'; path: string }` where `path` is the pane's absolute `editorFilePath`. The agent can read an absolute path without knowing the dashboard's cwd.
- **D7 — Exact block format.** Message citations keep their block byte-for-byte (header `Notes on your previous reply:`). File citations are grouped by path, one block per path, header ``Notes on `<path>`:``. The message block comes first, then one block per path in the order each path first appears in the pending list. Entries inside a block keep their relative add order and are numbered from `1.` per block with the PAN-4642 entry rules (quote lines `> `, continuation indent = width of the number prefix, comment lines indented the same, no comment ⇒ no comment line). Blocks are joined by one blank line. A messages-only list produces exactly the PAN-4642 output.
- **D8 — Cite is hidden while the draft is dirty.** Preview renders the unsaved `draft`; a quote from unsaved text is not on disk when the agent reads the file. So the cite layer renders only when `activeTab === 'preview'`, the pane has a cite target, and `dirty` is false. Saving brings Cite back.
- **D9 — The selection must be fully inside the preview.** `useCiteSelection` now requires both `anchorNode` and `focusNode` inside the root (today it checks only the anchor). For message citations this changes nothing, because the message resolver already requires both ends in one row inside the root.
- **D10 — Confirmation toast.** Saving a file citation calls `toast.success('Citation added', { description: 'It goes out with your next prompt in the conversation that opened this file.', action: { label: 'Open conversation', onClick: () => deck.openOrFocusAgentPane(target, 'Agent') } })`. The target conversation is usually another tab, so without this the operator cannot see the chip appear. `StageDeckContextValue` gains `openOrFocusAgentPane` for this (sonner `^1.7.4` supports `action`).
- **D11 — Highlight parity.** A pending file citation's quote is painted in the preview with the same `overdeck-citation` Custom Highlight, best-effort, first occurrence, whitespace-insensitive (PAN-4642 D12). Registry key `${conversationName}:file:${path}`.
- **D12 — Chips name the file.** A file citation's chip shows the file basename before the quote excerpt, and the full path above the quote when expanded.
- **D13 — Archive clears the target.** `closeConversationPanes(conversationId)` also deletes `citeConversationName` from every editor pane whose value equals `conversationId`, in hydrated workspaces and in cold `pan-panes:*` storage, so an archived conversation never receives new citations.
- **D14 — Always pass the third argument.** `MarkdownFileLink` always calls `deck.openOrFocusEditorPane(filePath, basename, citeTarget)` with `citeTarget` = the context value (`null` when absent). The existing four assertions in `MarkdownFileLink.test.tsx` are updated to include `null`; Vitest's `toHaveBeenCalledWith` treats a missing argument and a trailing `null` as different.
- **D15 — Tests extend the existing files, and those files join the CI subset.** `EditorPane.test.tsx`, `MarkdownFileLink.test.tsx` and `lib/panesStore.test.ts` pass today; they are added to `scripts/frontend-test-subset.txt` so the new assertions run in CI.

## Requirements

### Functional

- **FR-1** A file chip clicked (or opened via "Open in internal editor") inside a conversation's main timeline, while that conversation shows a composer, records that conversation as the editor pane's cite target (D1, D2).
- **FR-2** Re-opening the same file from a different conversation re-targets the existing pane; opening it from a surface with no conversation keeps the existing target (D4).
- **FR-3** Selecting text inside the Preview of an editor pane that has a cite target and no unsaved changes shows the floating **Cite** button; `C` opens the comment box under the PAN-4642 D13 rule. No Cite button appears in Edit, without a target, or while dirty (D3, D8).
- **FR-4** Save adds exactly one pending citation `{ source: { kind: 'file', path }, quotedText, comment }` to the target conversation, clears the selection, and shows the D10 toast whose **Open conversation** action focuses the target's agent tab.
- **FR-5** On send, file citations are serialized per D7, after any message block; a messages-only list is byte-identical to PAN-4642.
- **FR-6** File citations survive a reload and switching conversations (the store accepts the new kind).
- **FR-7** The target conversation's chips show the file basename for a file citation; expanded, they show the full path (D12).
- **FR-8** While a file citation is pending, its quote is highlighted in that file's Preview (D11).
- **FR-9** Archiving a conversation removes it as the cite target of every editor pane (D13).
- **FR-10** A file chip inside an editor pane's Preview opens its file with the same cite target (D5).

## Non-goals

- Citing in the Stage `BrowserPane` (sandboxed iframe; #2685).
- Citing from the Edit textarea, or while the draft has unsaved changes.
- A target-conversation picker, or guessing a target (most-recent conversation) for tabs with no origin.
- Giving editor tabs opened from issue-overview, PRD-viewer or other non-conversation markdown a cite target.
- Mapping a rendered-text quote back to raw markdown or to line numbers.
- Any server, contracts, delivery-path or `ConversationPanel.tsx` change.
- Cross-window live sync of pending citations (popout windows pick them up on reload, as in PAN-4642).
- Changing the message-citation format, gate, chips or highlight.

## Hazards

- **Rendered text, not source.** `selection.toString()` on the Preview drops markdown syntax and link URLs. The agent's search of the raw file may need to be fuzzy. Documented (WI-10); not solved.
- **Async markdown render.** If `ChatMarkdown` replaces text nodes after the layout effect (lazy code highlighting), a highlight range can go stale until the next `text` change. Best-effort, same as PAN-4642 D12.
- **Two cite layers at once.** In a split deck the timeline layer and the Preview layer both listen to `document` events. Only the layer whose root contains both selection ends gets a snapshot, so only one Cite button shows. Do not add cross-layer coordination.
- **Ended target.** A target conversation that ends (not archived) keeps its pending citations until it is resumed, exactly like PAN-4642 message citations.
- **Path with a backtick** would break the ``Notes on `…`:`` header's code span. Accepted; such paths are not expected.
