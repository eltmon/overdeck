# PAN-5239 — Flywheel page: make every Needs-you item clickable, with real targets, link styling, and a visible jump

**Issue:** https://github.com/eltmon/overdeck/issues/5239
**Related:** PAN-5198 (one row per item, first-raised jump), PAN-5217 (one native jump button per row), PAN-4751 (jump reopens a pending AskUserQuestion), PAN-4558 (conversation jumps page older history in).

## Glossary

- **Tick marker** — the one line the `/pan-flywheel` loop prints at the end of every tick: `flywheel-tick: tick=<n> pick=<ID|none> phase=<phase> in-flight=<IDs|none> needs-you=<text|none>`. Parsed by `parseTickMarker()` in `src/lib/flywheel/tick-marker.ts`. `needs-you` is always the last key and takes the rest of the line.
- **Needs-you item** — one `;`-separated piece of the `needs-you` value. `splitNeedsYouItems()` (packages/contracts/src/flywheel-derived.ts) splits, trims and de-duplicates them.
- **Item key** — `needsYouItemKey(text)`: the identity two ticks use to decide that an item is "the same item". Today it is `text.trim().toLowerCase()`.
- **Item target** — NEW. An optional trailing `<https://…>` on an item. It is the place the operator should go to act on the item. Only `http:` and `https:` URLs count.
- **Item label** — NEW. The item text with its target removed. It is what the row shows.
- **First-raised message** — `FlywheelNeedsYouItem.firstRaisedMessageId`: the transcript id of the oldest tick message in the item's current unbroken run (`resolveNeedsYouItems()` in `tick-marker.ts`). Absent when the harness records no message ids or the server is older than PAN-5198.
- **Jump button** — the per-row `<button data-testid="flywheel-needs-you-jump" aria-label="Show where this was raised">` in `FlywheelStatusPane.tsx` (PAN-5217).
- **Main conversation view** — the conversation's own agent pane in the Command Deck, reached through the `/conv/<name>` deep link. This is the full-width view, as opposed to the Flywheel page's embedded conversation column (`FlywheelConversationPane`), which the issue calls "the narrow side column".
- **Pending conversation target** — `PendingConversationTarget` (`src/dashboard/frontend/src/App/AppRoutes.tsx` line 38): App state that the Command Deck consumes when it applies a `/conv/<name>` deep link, writing `targetMessageId`/`targetMessageNonce` onto the conversation's agent pane.
- **Row flash** — `MessagesTimeline`'s temporary 2px `var(--color-primary)` outline on one timeline row (`flashRowId` state). Today only the bookmark jump sets it.

## Problem

The operator, looking at the Needs you block on the Flywheel page (2026-11-14): "I cant click on any of these to be taken to them." Verified on build 06b993d8ec3 with 9 rows:

1. The jump scrolls the Flywheel page's embedded conversation column to a days-old message and nothing marks the message. Root cause: `FlywheelPage.handleTickTargetHandled` (`src/dashboard/frontend/src/pages/FlywheelPage.tsx` line 84, grep `const handleTickTargetHandled`) clears `messageId` the moment the timeline reports the scroll, so `MessagesTimeline`'s `targetMessageRow` outline disappears at once. The flash (`setFlashRowId`) runs only on the bookmark path. A row with no first-raised id falls back to the newest tick message (`needsYouRows()` line 65, `?? tick.messageId`; `handleNeedsYouClick` line 81, `messageId ?? status?.lastTick?.messageId`), which looks like nothing happened.
2. Issue IDs render as `font-mono text-foreground hover:underline` buttons: nothing says they are clickable.
3. `PR #7` is a PR in `eltmon/overdeck-landing`; a bare `#7` cannot be linked safely, and the loop wrote it bare.
4. Items with an obvious destination (Play Console, App Store Connect, GitHub App settings) have no way to carry it in the tick format.

## Requirements

- **FR-1** An item may end with a target written `<https://…>` or `<http://…>` (angle brackets, no spaces inside). The row shows the item label (text without the target) as one link to the target. The link opens in a new tab with `rel="noreferrer noopener"`.
- **FR-2** A trailing `<…>` whose content is not an `http(s)://` URL is not a target: the row shows the whole item text, unchanged, with no item link.
- **FR-3** An item's key ignores its target, so adding or changing a target on a later tick does not reset the item's first-raised tick.
- **FR-4** `owner/repo#<n>`, with or without a leading `PR `, links to `https://github.com/owner/repo/pull/<n>`. With a leading `PR `, the link text includes `PR `.
- **FR-5** Issue links, PR links and item links share one link style: underline, pointer cursor, visible focus ring. Text stays monochrome (pan-style-guide: "Action links monochromatic").
- **FR-6** An item with a target renders exactly one interactive element for its text (the item link); issue and PR references inside it are not separately linked, so no link or button is nested in another.
- **FR-7** A row whose item has no first-raised message id renders no jump button. There is no fallback to the newest tick message.
- **FR-8** Clicking a jump button with no pending AskUserQuestion opens `conv-flywheel` in the main conversation view (Command Deck, `/conv/conv-flywheel`) targeted at the item's first-raised message. With a pending AskUserQuestion on `conv-flywheel`, the click reopens the question instead (PAN-4751 behavior is kept).
- **FR-9** When any conversation timeline handles a target-message jump, the target row flashes (2px primary outline, plus `data-flash="true"` on the row wrapper) for 3000 ms, then the flash clears.
- **FR-10** The pan-flywheel skill tells the loop: write a PR outside its own project as `owner/repo#<n>`; append ` <https://…>` to an item whenever it has a destination; a target must not contain `;` or spaces.
- **FR-11** `docs/FLYWHEEL.md` documents the target syntax, the key rule, the link styling, the hidden jump button and the Command Deck jump; `changelog.d/pan-5239.md` records the change under `#### Improved`.
- **NFR-1** Nothing new is stored. The page still derives everything from the tick line in the transcript; the server's `FlywheelNeedsYouItem` schema is unchanged.
- **NFR-2** Every new delay test uses `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()` (repo rule: fake timers for delay-based tests).
- **NFR-3** No file grows past its file-size ceiling (`scripts/lint-file-size.sh`, CEILING=1000, or its `scripts/file-size-allowlist.txt` row). `ConversationPanel.tsx` is not touched, and `CommandDeck/index.tsx` changes only the two `messageIndex` type lines in WI-6.

## Decisions (made here, not left to the executor)

- **D1 — "Main conversation view" = the Command Deck pane.** The issue calls the Flywheel page's conversation column "the narrow side column", so the jump navigates to `/conv/conv-flywheel` in the Command Deck with a pending target. The Flywheel page's embedded column no longer receives jump targets, so the `tickTarget`/`onTickTargetHandled` plumbing that this change orphans is removed from `FlywheelPage` and `FlywheelConversationPane`.
- **D2 — Parse targets in contracts, render in the frontend.** `parseNeedsYouTarget()` lives next to `needsYouItemKey()` in `packages/contracts/src/flywheel-derived.ts`, because the key (server and frontend) must strip the target. The server keeps sending item text verbatim; no schema field is added (NFR-1).
- **D3 — Target regex:** `/^(.*?)\s*<(https?:\/\/[^\s<>]+)>\s*$/i`. The label is group 1 trimmed. If the regex does not match, or the label is empty, there is no target and the label is the whole trimmed text.
- **D4 — `;` inside a URL is not supported.** `splitNeedsYouItems` splits on `;` before target parsing. The skill tells the loop not to write one; a test documents that `<https://x.test/a;b>` splits into two items and neither is a link.
- **D5 — Whole-item link wins.** When an item has a target, its label is one `<a>` and is not segmented into issue/PR refs (FR-6, avoids the PAN-5217 nesting class).
- **D6 — Link style constant.** `export const NEEDS_YOU_LINK_CLASS = 'cursor-pointer rounded-sm text-foreground underline decoration-muted-foreground/60 underline-offset-2 hover:decoration-foreground focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring';` in `FlywheelStatusPane.tsx`. Issue buttons add `font-mono`; PR links add `font-mono`; item links do not.
- **D7 — Hide, don't fall back.** Rows without `firstRaisedMessageId` get no jump button (FR-7). A pending question stays reachable from the app-wide pending-input dialogs, the Decisions panel and the session feed (`requestReopen` callers in `DecisionsPanel.tsx`, `SessionFeedSidebar.tsx`, `App/hooks/usePendingInputDialogs.ts`).
- **D8 — Flash duration 3000 ms for target jumps; bookmark flash stays 1600 ms.** The flash state becomes `{ rowId, durationMs }` so the two paths keep their own durations and the existing bookmark tests stay valid.
- **D9 — `messageIndex` becomes optional** on `PendingConversationTarget`, on `CommandDeck`'s `pendingConversationTarget` prop type and on `openConversationTab`'s `target` type. The timeline finds a target by id first and pages older history in by id (PAN-4558), so an id-only target works. `panesStore`'s `targetMessageIndex` is already optional.
- **D10 — Screenshots** go in `docs/screenshots/pan-5239/` (the `.gitignore` rule at line 210 names `docs/screenshots/<topic>/`) and are linked from the PR body with `?raw=true` blob URLs, the PAN-5191 precedent.

```ts
const NEEDS_YOU_TARGET_RE = /^(.*?)\s*<(https?:\/\/[^\s<>]+)>\s*$/i

/**
 * An item's trailing `<https://…>` is its target (PAN-5239). Anything else in
 * angle brackets is plain text. The label is the item without its target.
 */
export function parseNeedsYouTarget(text: string): { label: string; target?: string } {
  const trimmed = text.trim()
  const match = NEEDS_YOU_TARGET_RE.exec(trimmed)
  const label = match?.[1]?.trim() ?? ""
  if (!match || !label) return { label: trimmed }
  return { label, target: match[2]! }
}

/** Two items are the same item when their keys match; the target is not part of it. */
export function needsYouItemKey(text: string): string {
  return parseNeedsYouTarget(text).label.toLowerCase()
}
```
