# PAN-5233 — Workspace rows record their origin; the rail lists only operator workspaces

**Issue:** [PAN-5233](https://github.com/eltmon/overdeck/issues/5233)
**Status:** draft, 2026-11-13

## Glossary

- **Workspace row** — one row in the `workspaces` table of `~/.overdeck/overdeck.db`. Written only through `src/lib/workspaces/writer.ts` (the write door).
- **Kind** — `workspaces.kind`: `main` (a project's primary checkout, one per project), `issue` (one worktree per pipeline issue), `scratch` (anything else). Kind says what the workspace *is*.
- **Origin** — NEW column `workspaces.origin`: who caused the row to exist. Values: `operator`, `pipeline`, `vault`, `agent`. Origin cannot be derived after the fact, so storing it does not break the "store nothing derivable" rule.
- **Rail** — the WORKSPACES section of the dashboard sidebar (`src/dashboard/frontend/src/components/Sidebar.tsx`).
- **Cmd-K workspaces scope** — the workspaces list in the command palette (`src/dashboard/frontend/src/components/CommandPalette.tsx`).
- **Managed session** — a process Overdeck launched: an agent (`OVERDECK_AGENT_ID` set) or a conversation (`OVERDECK_CONVERSATION` set).
- **Dead issue row** — a non-archived `kind='issue'` row whose `path` directory does not exist.

## Background

On 2026-11-13 the rail listed `vault-0c6b0704`, `vault-e76fe074`, `vault-0978a29e`, `vault-65dc8313`, `vault-7449489f`, `qwen-smoke`, and a "Pipeline worktrees 658" group. 645 of the 658 issue rows were dead.

Root causes, verified in code:

1. The rail's filter is `isUserFacingWorkspace` (`Sidebar.tsx`, search `export function isUserFacingWorkspace`): `workspace.kind !== 'issue' || workspace.isFavorite`. It treats every `scratch` row as operator-made. Two non-operator paths write `scratch` rows:
   - Session Vault "Continue here": `createScratchWorkspace` in `src/dashboard/server/services/vault-continue.ts` (search `D-4: Create`) calls `resolveWorkspaceCreateIntent({ kind: 'scratch', isolated: true, ... })` + `performWorkspaceCreate`.
   - Agents running `pan workspace new` (`workspaceNewCommand`, `src/cli/commands/workspace-scratch.ts`).
2. Issue rows were never archived by the automatic teardown. `closed-issue-reaper` → `reapIssueResidue` (`src/lib/cloister/reap-issue-residue.ts`) removed the directory but not the row. **Fixed on main in e5cc8544749** (the reaper now archives the row once the directory is gone). Not part of this PRD's work.
3. The fallback archival pass in `pan admin db rebuild-workspaces` (`rebuildWorkspacesCommand`, `src/cli/commands/db.ts`) asks `resolveTerminalIssueIds()` (`src/lib/overdeck/terminal-issues.ts`), which filters the `issues` table by stage. That table is a pre-cut cache: on this machine all 910 rows have `stage='working'`, so the pass archives nothing.
4. The rail's collapsed "Pipeline worktrees" group duplicates the Projects section, which already lists each live issue with its phase.

One-time cleanup already done on this machine (2026-11-13): the six debris rows and the 645 dead issue rows were archived, and the five `tally/workspaces/scratch-vault-*` worktrees and branches removed. Work item 5 makes the dead-row cleanup repeatable for every install.

## Requirements

- **FR-1** Every workspace row has a non-null `origin` in `operator | pipeline | vault | agent`.
- **FR-2** `kind='issue'` rows always get `origin='pipeline'`.
- **FR-3** Session Vault "Continue here" writes `origin='vault'`.
- **FR-4** `pan workspace new` writes `origin='agent'` when run inside a managed session and `origin='operator'` otherwise; `--origin operator|agent` overrides the default.
- **FR-5** `POST /api/workspace-registry` writes `origin='operator'` for a browser (cookie/session) request and `origin='agent'` for `internal-token` or `connector` credentials.
- **FR-6** Project creation's main row and `pan workspace main` write `origin='operator'`.
- **FR-7** Existing rows are backfilled once at schema top-up: `issue`→`pipeline`; `main`→`operator`; `scratch` whose name matches `^vault-[0-9a-f]{8}(-\d)?$` → `vault`; other `scratch` → `operator`.
- **FR-8** The rail and the Cmd-K workspaces scope list a row only when it is not archived and (`origin === 'operator'` or `isFavorite`), and a non-favorited `main` row stays off the rail (unchanged `isRailWorkspace` rule).
- **FR-9** The rail's "Pipeline worktrees" count row and the Cmd-K equivalent are removed. Issues stay reachable through Projects, the Issues scope and the pipeline views.
- **FR-10** `pan admin db rebuild-workspaces` archives dead issue rows (directory missing) instead of asking `resolveTerminalIssueIds()`; `--dry-run` reports the count and writes nothing.
- **FR-11** `origin` is mirrored into the workspace identity record so `rebuildMainAndScratchWorkspaces()` restores it.
- **NFR-1** All writes go through `src/lib/workspaces/writer.ts`; no other module writes the column.
- **NFR-2** No `execSync` in server-reachable code; no new sync tmux/git helpers.

## Work items

### 1. Schema: add and backfill `workspaces.origin` (FR-1, FR-7)

File: `src/lib/overdeck/infra.ts`, in the projects/workspaces top-up function (search ``runSchemaTopUp(db, 'ALTER TABLE `workspaces` ADD COLUMN `run_command` text');``).

After that line add:

```ts
// PAN-5233: who caused the row to exist. Not derivable later, so it is stored.
runSchemaTopUp(db, "ALTER TABLE `workspaces` ADD COLUMN `origin` text");
db.exec(`
  UPDATE workspaces SET origin = CASE
    WHEN kind = 'issue' THEN 'pipeline'
    WHEN kind = 'main' THEN 'operator'
    WHEN kind = 'scratch' AND name GLOB 'vault-[0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f]*' THEN 'vault'
    ELSE 'operator'
  END
  WHERE origin IS NULL
`);
```

The `UPDATE ... WHERE origin IS NULL` is idempotent and runs every boot at near-zero cost after the first.

Test: no existing test covers the `run_command` top-up, so add `src/lib/overdeck/__tests__/workspace-origin-topup.test.ts`. Point `OVERDECK_HOME` at a temp dir (follow `src/lib/overdeck/__tests__/conversation-vault-browse.test.ts` for the setup), create a pre-column table with one row of each kind plus a `vault-0978a29e` scratch row, run the top-up, assert the four origins.
