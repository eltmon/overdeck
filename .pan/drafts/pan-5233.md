# PAN-5233 — Workspace rows record their origin; the rail lists only operator workspaces

**Issue:** [PAN-5233](https://github.com/eltmon/overdeck/issues/5233)
**Status:** draft, 2026-11-13. Revised by the planning session the same day: references re-verified against `b9f62aac76b`, test paths corrected, the identity-mirror and credential-mapping gaps closed, and the dead-row race guarded.

## Glossary

- **Workspace row** — one row in the `workspaces` table of `~/.overdeck/overdeck.db`. Read only through `src/lib/workspaces/resolver.ts` (the read door) and written only through `src/lib/workspaces/writer.ts` (the write door). `src/lib/overdeck/infra.ts` owns the DDL. `scripts/guard-workspace-doors.sh` fails CI on SQL against the table anywhere else.
- **Kind** — `workspaces.kind`: `main` (a project's primary checkout, one per project), `issue` (one worktree per pipeline issue), `scratch` (anything else). Kind says what the workspace *is*.
- **Origin** — NEW column `workspaces.origin`: who caused the row to exist. Values: `operator`, `pipeline`, `vault`, `agent`. Origin cannot be derived after the fact, so storing it does not break the "store nothing derivable" rule.
- **Identity mirror** — `metadata.json` under a workspace's memory home (`src/lib/memory/identity-record.ts`, `writeWorkspaceIdentity`). A best-effort recovery hint. `rebuildMainAndScratchWorkspaces()` recreates missing `main`/`scratch` rows from it.
- **Rail** — the WORKSPACES section of the dashboard sidebar (`src/dashboard/frontend/src/components/Sidebar.tsx`).
- **Cmd-K workspaces scope** — the workspaces list in the command palette (`src/dashboard/frontend/src/components/CommandPalette.tsx`).
- **Managed session** — a process Overdeck launched: an agent (`OVERDECK_AGENT_ID` set) or a conversation (`OVERDECK_CONVERSATION` set).
- **Dashboard credential** — the `DashboardCredential` union in `src/dashboard/server/routes/dashboard-auth.ts` (search `export type DashboardCredential =`), returned by `resolveRequestCredential(request)`.
- **Dead issue row** — a non-archived `kind='issue'` row whose `path` directory does not exist.

## Background

On 2026-11-13 the rail listed `vault-0c6b0704`, `vault-e76fe074`, `vault-0978a29e`, `vault-65dc8313`, `vault-7449489f`, `qwen-smoke`, and a "Pipeline worktrees 658" group. 645 of the 658 issue rows were dead.

Root causes, verified in code:

1. The rail's filter is `isUserFacingWorkspace` (`Sidebar.tsx`, search `export function isUserFacingWorkspace`): `workspace.kind !== 'issue' || workspace.isFavorite`. It treats every `scratch` row as operator-made. Two non-operator paths write `scratch` rows:
   - Session Vault "Continue here": `createScratchWorkspace` in `src/dashboard/server/services/vault-continue.ts` (search `D-4: Create`). It calls `deps.resolveWorkspaceCreateIntent({ kind: 'scratch', isolated: true, projectKey, name, refreshParentBranch: true })`, then `deps.performWorkspaceCreate(intent)`. The name is `vault-<first 8 chars of a randomUUID>` or `vault-<id8>-2` … `-9`.
   - Agents running `pan workspace new` (`workspaceNewCommand`, `src/cli/commands/workspace-scratch.ts`).
2. Issue rows were never archived by the automatic teardown. `closed-issue-reaper` → `reapIssueResidue` (`src/lib/cloister/reap-issue-residue.ts`) removed the directory but not the row. **Fixed on main in `e5cc8544749`** (the reaper now archives the row once the directory is gone). That fix is not part of this PRD's work.
3. The fallback archival pass in `pan admin db rebuild-workspaces` (`rebuildWorkspacesCommand`, `src/cli/commands/db.ts`) asks `resolveTerminalIssueIds()` (`src/lib/overdeck/terminal-issues.ts`), which filters the `issues` table by stage. That table is a pre-cut cache: on this machine all 910 rows have `stage='working'`, so the pass archives nothing.
4. The rail's collapsed "Pipeline worktrees" group duplicates the Projects section, which already lists each live issue with its phase.

One-time cleanup already done on this machine (2026-11-13): the six debris rows and the 645 dead issue rows were archived, and the five `tally/workspaces/scratch-vault-*` worktrees and branches removed. Work item 8 makes the dead-row cleanup repeatable for every install.

## Requirements

- **FR-1** Every workspace row has a non-null `origin` in `operator | pipeline | vault | agent` once the schema top-up has run.
- **FR-2** `kind='issue'` rows always get `origin='pipeline'`; `kind='main'` rows always get `origin='operator'`. The writer enforces both whatever the caller passes.
- **FR-3** Session Vault "Continue here" writes `origin='vault'`.
- **FR-4** `pan workspace new` writes `origin='agent'` when run inside a managed session and `origin='operator'` otherwise; `--origin operator|agent` overrides the default.
- **FR-5** `POST /api/workspace-registry` derives origin from the request credential, never from the body. The full mapping is in decision D-3.
- **FR-6** Project creation's main row and `pan workspace main` write `origin='operator'` (follows from FR-2; no caller change).
- **FR-7** Existing rows are backfilled at schema top-up: `issue`→`pipeline`; `main`→`operator`; `scratch` whose name matches `^vault-[0-9a-f]{8}(-[2-9])?$` → `vault`; other `scratch` → `operator`.
- **FR-8** The rail and the Cmd-K workspaces scope list a row only when it is not archived and (`origin === 'operator'` or `isFavorite`). A non-favorited `main` row stays off the rail (unchanged `isRailWorkspace` rule).
- **FR-9** The rail's "Pipeline worktrees" count row and the Cmd-K equivalent are removed. Issues stay reachable through Projects, the Issues scope and the pipeline views.
- **FR-10** `pan admin db rebuild-workspaces` archives dead issue rows (directory missing) instead of asking `resolveTerminalIssueIds()`. `--dry-run` reports the count and writes nothing.
- **FR-11** `origin` is mirrored into the identity record, survives `archiveWorkspace`/`relocateWorkspace`/memory-home migration rewrites of that record, and `rebuildMainAndScratchWorkspaces()` restores it.
- **NFR-1** All row writes go through `src/lib/workspaces/writer.ts`; the backfill `UPDATE` lives in `src/lib/overdeck/infra.ts`, which the doors guard already allows. No other module writes the column.
- **NFR-2** No `execSync` in server-reachable code; filesystem checks use `node:fs/promises`.
- **NFR-3** The schema top-up never throws on database open (a failed backfill logs and continues, like `runSchemaTopUp`).

## Decisions

- **D-1 (writer rule).** `createWorkspace` resolves origin as: `kind === 'issue'` ⇒ `'pipeline'`; `kind === 'main'` ⇒ `'operator'`; otherwise `opts.origin ?? 'operator'`. Callers only pass origin for scratch rows. This makes FR-2 and FR-6 hold for every existing creator (`workspace-manager/create.ts`, `backfillIssueWorkspaces`, `create-perform.ts`, `workspaceMainCommand`, the route's `bootstrapMain`) with no change to them.
- **D-2 (how origin reaches the writer).** `performWorkspaceCreate` gains a second, optional argument: `performWorkspaceCreate(intent, options?: { origin?: WorkspaceOrigin })`. Origin is *not* added to `WorkspaceCreateInput`, `ResolvedWorkspaceIntent` or `toDryRunPayload`. Reason: origin is caller identity, not a resolution of the input; keeping it out of the intent leaves the nine-field dry-run contract (`create-intent.test.ts` asserts exact key order) and the `/resolve` response untouched.
- **D-3 (credential → origin, FR-5).** A pure exported helper `workspaceOriginForCredential(credential: DashboardCredential | null): 'operator' | 'agent'` in `workspace-registry.ts`:

  | Credential `kind` | Origin | Why |
  | --- | --- | --- |
  | `root-session` | `operator` | the operator's browser session cookie |
  | `device` | `operator` | the operator's other paired browser |
  | `phone` | `operator` | the operator's paired phone |
  | `token` without `agentId` | `operator` | an access token the operator minted |
  | `token` with `agentId` | `agent` | a managed agent's per-agent MCP token (PAN-4927) |
  | `machine` with `actor === 'operator'` | `operator` | a linked machine acting for the operator |
  | `machine` with `actor` an `{ agentId }` object | `agent` | a linked machine relaying an agent |
  | `internal-token` | `agent` | Overdeck's own process-to-dashboard calls |
  | `connector` | `agent` | an external connector client |
  | `null` | `operator` | unreachable past the mutation guard; defensive default |

- **D-4 (resolver fallback).** `rowToWorkspace` maps a NULL `origin` (a row an older build wrote after the column existed) to `kind === 'issue' ? 'pipeline' : 'operator'`. The backfill `UPDATE` runs on each process's first database open, so such rows also self-heal at the next dashboard or CLI start.
- **D-11 (creator census).** Verified 2026-11-13 with an untruncated grep: the only `writer.createWorkspace` callers are `workspace-manager/create.ts` (issue rows), `rebuild.ts` (`backfillIssueWorkspaces`, issue; `rebuildMainAndScratchWorkspaces`, from the mirror) and `workspaces/create.ts` (`performWorkspaceCreate`). `performWorkspaceCreate` is called by `workspace-scratch.ts` (new, main), `workspace-registry.ts`, `vault-continue.ts` and `create-perform.ts` (main). Swarm, lane, worker and planning paths call `workspace-manager`'s issue creator. No other path writes a scratch row.
- **D-12 (internal-token is `agent`).** Its senders are `pan` CLI commands (`dashboard-call.ts`, `plan.ts`, `start.ts`, `merge.ts`, …). The dashboard frontend sends it only once, to exchange a bootstrap token for the session cookie (`ensureDashboardSession` in `wsTransport.ts`); later browser requests are `root-session`. The desktop shell injects no headers. No operator surface reaches `POST /api/workspace-registry` with it.
- **D-5 (DDL sites).** `origin text` (nullable, no CHECK) is added in three places: the `ALTER` top-up, the `CREATE TABLE IF NOT EXISTS` in `ensureWorkspaceTablesSync`, and the `workspaces` table in `drizzle/overdeck/0000_overdeck_init.sql`. SQLite cannot add a CHECK through `ALTER`, so the writer's type is the guard.
- **D-6 (identity mirror merge).** `writeWorkspaceIdentity` writes `origin` only when the source carries one: `...(row.origin ? { origin: row.origin } : {})`. All four existing rewrite sites (`createWorkspace`, `archiveWorkspace`, `relocateWorkspace` in `writer.ts`; `migrateMemoryHomesToWorkspaces` in `rebuild.ts`) pass the row's origin.
- **D-7 (dead-row race guard).** `workspace-manager/create.ts` (search `PAN-1990 FR-6/AC-4: create the kind='issue' workspace row before any git`) writes the issue row *before* `git worktree add`. `archiveDeadIssueWorkspaces` therefore skips a row whose `createdAt` is less than 10 minutes before `now` and counts it as skipped. `now` is an injectable option (default `Date.now()`) so tests need no timers.
- **D-8 (conversations that act for the operator).** A conversation that creates a workspace because the operator asked passes `--origin operator`. The CLI help text, `configuration/workspaces.mdx` and the `pan-workspace` skill say so. An agent-made workspace the operator wants on the rail can also be favorited.
- **D-9 (Archived group).** The rail's Archived count row is left alone. `GET /api/workspace-registry` omits archived rows unless `includeArchived=true`, and the rail does not pass it, so archived pipeline and vault rows never reach the rail.
- **D-10 (scope).** Dead-row archival runs only from `pan admin db rebuild-workspaces`, as the issue states. Wiring it into dashboard boot is out of scope.

```ts
  // Not derivable later, so it is stored. The backfill is idempotent and cheap
  // after the first open (WHERE origin IS NULL matches nothing).
  runSchemaTopUp(db, 'ALTER TABLE `workspaces` ADD COLUMN `origin` text');

      UPDATE workspaces SET origin = CASE
        WHEN kind = 'issue' THEN 'pipeline'
        WHEN kind = 'main' THEN 'operator'
        WHEN kind = 'scratch'
          AND (name GLOB 'vault-[0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f][0-9a-f]'

        ELSE 'operator'
      END
      WHERE origin IS NULL
    `);
  } catch (error) {
    console.error(`[schema] workspaces.origin backfill failed\n${error instanceof Error ? error.message : String(error)}`);
  }
```

  ```ts
   * memory homes; `unarchiveWorkspace` reverses it, and backfillIssueWorkspaces
   * enrolls a fresh row if the directory comes back. --dry-run writes nothing.
   */
  export async function archiveDeadIssueWorkspaces(
    options: ArchiveDeadIssueWorkspacesOptions = {},
  ): Promise<ArchiveDeadIssueWorkspacesResult> {
    const now = options.now ?? Date.now();
    const result: ArchiveDeadIssueWorkspacesResult = { scanned: 0, archived: 0, skipped: 0, archivedIds: [] };
    for (const workspace of listWorkspaces({ kind: 'issue' })) {
      result.scanned += 1;
      if (now - workspace.createdAt < DEAD_ROW_MIN_AGE_MS || await pathExists(workspace.path)) {
        result.skipped += 1;
        continue;
      }
      if (options.verbose) {
        console.log(`[rebuild-workspaces] ${options.dryRun ? 'would archive' : 'archiving'} dead issue workspace ${workspace.id} (${workspace.name}, ${workspace.path})`);
      }
      if (!options.dryRun) await archiveWorkspace(workspace.id);
      result.archived += 1;
      result.archivedIds.push(workspace.id);
    }
    return result;
  }
  ```
