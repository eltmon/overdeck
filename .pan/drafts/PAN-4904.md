# PAN-4904: Pull here on a Codex conversation replaces its title with injected `<recommended_plugins>` text

**Issue:** [PAN-4904](https://github.com/eltmon/overdeck/issues/4904)
**Status:** draft (auto-planned, 2026-11-03)
**Verified against:** `feature/pan-4904` @ `678dcaf71b1`

## Glossary

| Term | Meaning |
| --- | --- |
| **Pull here** | The PAN-4650 job that moves a conversation from a linked machine (the *owner*) to this machine (the *viewer*): release → transfer → adopt → finish. Viewer half: `src/dashboard/server/services/conversation-pull.ts`. Owner half: `src/dashboard/server/services/conversation-release-service.ts`. |
| **Transfer store** | A fresh `dir:` Session Vault store the owner settles the transcript into during release, packs, and sends to the viewer. It starts empty: `buildTransfer` passes `index: memoryIndex()`, so `settle()` always mints a **new** record there. |
| **Record title** | `SessionRecord.title` (`src/lib/vault/format.ts`). `continueHere` copies it into the adopted conversation row (`vault-continue.ts`, `createVaultContinuedConversation({ … title: record.title … })`), which stores it with `titleSource: 'manual'`, so nothing re-titles it later. |
| **`recordTitle`** | `SettleOptions.recordTitle` (`src/lib/vault/settle.ts` line 70). Names a record that this settle **mints**; ignored for an existing or forked record. Today only the pipeline-agent poller passes it. |
| **`facts.title`** | The fallback record title: `firstHumanText()` in `settle.ts` — the first transcript line that `isHumanTurn()` accepts, whitespace-collapsed and cut to 80 characters. |
| **Injected prefix** | A user-role transcript line that the harness wrote, not the person. `src/lib/vault/turns.ts` lists them per harness (`CLAUDE_INJECTED_PREFIXES`, `CODEX_INJECTED_PREFIXES`) and matches them by exact prefix after `trimStart()`. |
| **Codex `response_item` user message** | A rollout line `{"type":"response_item","payload":{"type":"message","role":"user","content":[…]}}`. `codexUserText()` in `turns.ts` reads only this form. |

## Problem

After **Pull here** brings a Codex conversation from a linked Mac, the adopted conversation is titled `<recommended_plugins> Here is a list of plugins that are available but not insta…` instead of the owner's title ("Add a --json flag that prints the counts as JSON, and a test for it.").

### Root cause (verified)

1. **Owner side does not send its title.** `buildTransfer` in `src/dashboard/server/services/conversation-release-service.ts` (grep anchor: `const result = await deps.settle({`, around line 193) calls `settle()` without `recordTitle`. The transfer store is empty, so `settle()` takes the mint branch (`settle.ts` line 307):

   ```ts
   title: options.recordTitle ?? facts.title ?? basename(nativePath),
   ```

   and the record title becomes `facts.title`.

2. **`facts.title` picks an injected Codex line.** `firstHumanText()` takes the first line `isHumanTurn(line, 'codex')` accepts. `CODEX_INJECTED_PREFIXES` (`turns.ts` line 31) holds only `<environment_context>`, `<codex_internal_context>` and `# Files mentioned by the user:`. Current Codex writes a `<recommended_plugins>` user message before the typed prompt, so it passes the filter.

   Evidence from the pulled conversation's own rollout
   (`~/.overdeck/agents/conv-20261103-eb80/codex-home/sessions/2026/11/03/rollout-2026-11-03T15-32-39-….jsonl`): line 5 is a `response_item` user message starting `<recommended_plugins>\nHere is a list of plugins…`; line 8 is the typed prompt `Add a --json flag…`.

3. **The adopted row copies the record title.** `vault-continue.ts` passes `title: record.title` to `createVaultContinuedConversation`, which writes `titleSource: 'manual'`. So the bad title is permanent.

### Survey of Codex injected user messages on this machine

A scan of all 2,474 Codex rollouts under `~/.overdeck/agents` and `~/.codex/sessions` counted every `response_item` user message that starts with a tag or `# AGENTS.md`:

| Prefix | Count | Who writes it |
| --- | --- | --- |
| `<environment_context>` | 1188 | Codex (already listed) |
| `<recommended_plugins>` | 1102 | Codex (**missing**) |
| `# AGENTS.md instructions` (followed by ` for <path>` or a newline) | 933 | Codex (**missing**) |
| `<turn_aborted>` | 93 | Codex (**missing**) |
| `<subagent_notification>` | 15 | Codex (**missing**) |
| `<task>` | 7 | Overdeck worker briefs, sent as the prompt — a real instruction, so it stays a human turn |

### Why both layers are needed

- Layer A (owner sends its title) fixes the **online** pull directly.
- Layer B (filter the injected prefixes) fixes the **offline** pull too: when the owner is unreachable, `runOffline` in `conversation-pull.ts` adopts this machine's saved copy, whose record was minted by the owner's regular vault poller with `facts.title` (no `recordTitle`). It also fixes vault browse-copy titles and the seed digest (`seed.ts` line 77, `collectTurns`), which today shows `<recommended_plugins>` as a fake human turn.

Do not drop either layer as redundant.

## Requirements

- **FR-1:** A Pull here (online) of a conversation whose owner row has a non-empty title creates an adopted conversation with exactly that title.
- **FR-2:** When the owner row has no title (`null` or empty), the release settles without `recordTitle`, so the record title falls back to the transcript's first human text.
- **FR-3:** `isHumanTurn(line, 'codex')` returns `false` for Codex `response_item` user messages whose text starts with `<recommended_plugins>`, `# AGENTS.md instructions`, `<turn_aborted>` or `<subagent_notification>`.
- **FR-4:** `transcriptFacts(lines, 'codex').title` is the first typed prompt when a `<recommended_plugins>` user message precedes it.
- **FR-5:** A typed Codex prompt that begins with `<task>` or `<div>` still counts as a human turn.
- **FR-6:** The docs state that a pulled conversation keeps the owner's title and name the Codex injected prefixes the vault ignores.
- **NFR-1:** No change to `conversation-pull.ts`, `vault-continue.ts`, `adopt.ts` or `settle.ts`; the fix lives in the prefix list and in one call site.
- **NFR-2:** No migration or rename of existing vault records or conversation rows.

## Decisions

- **D-1 (title source):** The owner's `conv.title` is the authority for a Pull here transfer. Rationale: the issue's expected behavior is "the adopted conversation keeps the owner's title", and the owner row is what the linked-conversation list already shows.
- **D-2 (call shape):** Pass the title with the conditional spread already used at `src/dashboard/server/services/vault-service.ts` line 274: `...(conv.title ? { recordTitle: conv.title } : {})`. A null or empty title leaves `recordTitle` absent, so `facts.title` still applies (FR-2).
- **D-3 (`recordTitle` is honored):** `buildTransfer` passes `index: memoryIndex()`, which starts empty, so `owned` is `null` in `settle()` and the record takes the mint branch at `settle.ts` line 296–323, where `recordTitle` is read. No `settle.ts` change is needed.
- **D-4 (prefix spelling):** Add `'# AGENTS.md instructions'` in its bare form (no trailing ` for`). The survey found both `# AGENTS.md instructions for <path>` and a form that ends at a newline; the bare prefix matches both.
- **D-5 (`<task>` stays human):** `<task>` is how Overdeck worker briefs arrive; they are the conversation's real first instruction. Do not add it.
- **D-6 (turn counts):** Removing injected lines lowers `countHumanTurns` for future Codex settlements. `Settlement.turn` (`format.ts` line 134) is display-only: its only reader is `pan vault show` (`src/cli/commands/vault/show.ts` lines 52 and 70). Continuity uses line hashes, not turn counts. So a lower count on new settlements of an existing record is acceptable and correct per FR-18 of PAN-2609.
- **D-7 (no repair of existing rows):** Conversation 3550 (`20261103-eb80`) keeps its wrong title; the operator can rename it. Existing vault records are never renamed (`settle.test.ts`: "recordTitle never renames an existing record").
