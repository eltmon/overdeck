# PAN-4398 — Work agents that finished normally show "Ended unexpectedly": add a "Handed to review" outcome

**Issue:** https://github.com/eltmon/overdeck/issues/4398
**Follows:** PAN-4290 (#4318), which introduced the derived session outcome.

## Glossary

- **Session outcome** — the label an *ended* session shows in place of a bare "Session ended". It is computed at render time in the browser by the pure function `deriveSessionOutcome` in `src/dashboard/frontend/src/lib/sessionOutcome.ts`. Nothing is stored.
- **Outcome facts** (`SessionOutcomeFacts`) — the flat input `deriveSessionOutcome` reads. Two adapters build it: `outcomeFactsFromSessionNode` (cockpit, rail, session panel; input is a `SessionNode` plus the derived issue state plus an optional `AgentSnapshot`) and `outcomeFactsFromAgent` (the drawer; input is a drawer agent plus the derived issue state).
- **Derived issue state** (`DerivedIssueState`, `packages/contracts/src/derived-issue-state.ts`) — the server-derived pipeline position of an issue: `state` is one of `backlog | parked | planned | working | in-review | changes-requested | ready | merged | closed`, resolved in the precedence `closed > merged > ready > changes-requested > in-review > working > parked > planned > backlog`.
- **Precedence table** — the ordered rows inside `deriveSessionOutcome`; the first matching row wins. Today it has 12 rows (commented `// 1 —` … `// 12 —`).
- **Primary role** — `plan`, `work`, or `strike` (`PRIMARY_ROLES`, `sessionOutcome.ts` line 104).
- **Synthesized row** — a `SessionNode` that exists because of PR facts, not an agent (`type` `review`, `test`, or `legacy`). `synthesized: true` in the facts.
- **Handoff** — a work agent running `pan done`: it pushes, opens (or updates) the PR, and requests review; the pipeline journal records `review.requested` with `source: "pan-done"`.
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl`, written by `src/lib/cloister/pipeline-journal.ts`. Server-only: no contract type carries it and the dashboard store has no slice for it.

## Problem

After PAN-4290, a work agent that finished its job normally renders **"Ended unexpectedly"** in attention color. Observed 2026-09-29: `agent-pan-4358` ran `pan done` (journal entry `review.requested`, `source: "pan-done"`, 04:32:59Z), its PR #4375 is OPEN, and its recorded status is `stopped`. The row reads "Ended unexpectedly".

### Root cause (verified)

`deriveSessionOutcome` has no row for "work agent handed off and its PR is awaiting review/merge". For `agent-pan-4358`:

- Rows 1–6 do not match (PR not merged; role is `work`, not review/test/plan).
- Row 7 (`stoppedByUser === true`) and the `paused !== true` guard of row 11 read the `AgentSnapshot`. The live `/api/agents` listing on 2026-09-29 does **not** include `agent-pan-4358` (only `planning-pan-4358` appears), although its `~/.overdeck/agents/agent-pan-4358/state.json` has `paused: true`. So `agent` is `undefined`, `paused` is `undefined`, and `recordedStatus` falls back to `node.status` (`stopped`).
- Rows 9/10 need `error|failed|dead` or `running|starting`; `stopped` passes both.
- Row 11 (`sessionOutcome.ts` line 227, `// 11 — primary agent ended cleanly with no outcome on a known open, unmerged issue`) matches: role `work`, not synthesized, `paused` not `true`, `issueState` `in-review`. Result: "Ended unexpectedly".

Planning agents reach the same row 11 when `planningComplete` is not `true`. The session-node adapter copies `node.planningComplete` verbatim (`sessionOutcome.ts` line 293, `planningComplete: node.planningComplete,`) and never consults the derived state, while the drawer adapter already derives it from the state (the D6 block at line 334).

## Decisions (made here, not deferred)

- **D1 — The handoff signal is the derived issue state.** The issue text suggests "an open PR at or after the agent's last commit, or a `review.requested` / `pan done` journal entry". Neither fact reaches the browser: the journal is server-only; `DerivedPrState` has no head SHA or timestamp; and the batch door (`src/lib/overdeck/derived-issue-state.ts`, `const branch = pr ? null : …`) drops `branch` whenever a PR exists. The issue also says "Derive only; store nothing new", which rules out a new server field. So the new row keys off `issueState ∈ {in-review, changes-requested, ready}`. `deriveState` returns those three states only when an open PR exists, or when a review/test/uat pane is live for the issue (the `review.requested` case). That is the faithful in-browser proxy for "handed off".
- **D2 — Placement: new row 11, directly after row 10 and before the old row 11** (old 11 becomes 12, old 12 becomes 13). Rows 9 and 10 must still win: a work agent resumed on review feedback that crashed (recorded `error`/`failed`/`dead`), or whose pane vanished while its record still says `running`/`starting`, stays "Ended unexpectedly" even with an open PR. Only a clean end (`stopped` or no recorded status) on a PR-open issue reaches the new row. Rows 7 (operator stop) and 8 (close-out) also still win.
- **D3 — The new row does not check `paused`.** A pause recorded after `pan done` does not undo the handoff. Also, as the root cause shows, `paused`/`stoppedByUser` silently read as unknown for any ended agent the store no longer lists, so the new row must depend on the issue state alone. Consequence: a paused work agent whose issue is in review now shows "Handed to review" instead of the plain fallback.
- **D4 — Roles: `work` and `strike` only, not synthesized.** Workers, reviewers, test, and plan roles are unchanged.
- **D5 — Tone `quiet`.** `ended-unexpectedly` stays the only `attention` kind (PAN-4290 FR-4).
- **D6 — Planner fallback.** Extract the drawer adapter's post-planning state set (`planned, working, in-review, changes-requested, ready, merged`) into one exported helper, `planFinalizedFromState(state: IssueState | undefined): boolean`. The session-node adapter uses `node.planningComplete === true || planFinalizedFromState(derived?.state)`, **only for `node.type === 'planning'`** nodes; `legacy` (synthesized) nodes keep `node.planningComplete` unchanged, so the existing test "legacy node maps to role plan but is synthesized (reaches the fallback, not row 11)" keeps passing. The `planned` state means the canonical spec exists under `.pan/specs/`, which only `pan plan finalize` writes, so it is evidence of a finalized plan without reading git for a `chore(plan): complete planning` commit.
- **D7 — `parked` is not evidence of finalization.** `parked` outranks `planned` and occurs with or without a spec, so it stays out of the helper's set (unchanged behavior; see Non-goals).

## Requirements

- **FR-1** — `SessionOutcomeKind` gains `'handed-to-review'`. The outcome is `{ kind: 'handed-to-review', label: 'Handed to review', detail: "The work agent handed off; its PR is open for review.", tone: 'quiet' }`.
- **FR-2** — `deriveSessionOutcome` returns FR-1's outcome when `role ∈ {work, strike}`, `synthesized === false`, and `issueState ∈ {in-review, changes-requested, ready}`, and no earlier row (1–10) matched. It does not read `paused`.
- **FR-3** — A work agent whose recorded status is `error`/`failed`/`dead`, or `running`/`starting`, still returns "Ended unexpectedly" (attention) when its issue is `in-review`.
- **FR-4** — A work agent that ended cleanly on an issue in state `working` (no PR, no live review pane) still returns "Ended unexpectedly" (attention).
- **FR-5** — `outcomeFactsFromSessionNode` sets `planningComplete: true` for a `planning` node when `node.planningComplete === true` or the derived state is one of `planned, working, in-review, changes-requested, ready, merged`; for other node types it copies `node.planningComplete` as today.
- **FR-6** — `outcomeFactsFromAgent` uses the same `planFinalizedFromState` helper; its output is unchanged for every state (true for the six states, undefined otherwise, including `closed`).
- **FR-7** — `docs/ISSUE-VIEW.md` "Ended session outcomes (PAN-4290)" describes the new kind, the 13-row table, the paused-with-open-PR behavior, and the planner fallback.
- **NFR-1** — No new store slice, endpoint, polling loop, server field, or contract change. `packages/contracts` is untouched.
- **NFR-2** — `sessionOutcome.ts` stays under the file-size ceiling (354 lines on `origin/main`, ceiling 1000; expected growth under 30 lines).

### WI-2 — Planner "Plan finalized" fallback from the derived state (FR-5, FR-6)

**File:** `src/dashboard/frontend/src/lib/sessionOutcome.ts` (same file as WI-1 → runs after WI-1).

1. Add an exported helper near the adapters:

   ```ts
   /** Issue states that exist only after planning finalized (spec on disk or work past planning). `closed` and `parked` are excluded. */
   const PLAN_FINALIZED_STATES = new Set<IssueState>(['planned', 'working', 'in-review', 'changes-requested', 'ready', 'merged']);

   export function planFinalizedFromState(state: IssueState | undefined): boolean {
     return state !== undefined && PLAN_FINALIZED_STATES.has(state);
   }
   ```
