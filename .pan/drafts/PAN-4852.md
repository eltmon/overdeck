## 2. Problem and goal

Today an operator who wants SageOx in an Overdeck project must commit `.sageox/` to the repository, build `ox` by hand into `~/.local/bin`, and give up on Codex launches. The goal (the operator-owned "SageOx on Overdeck" PR-FAQ, part A):

- try SageOx on **one issue, one project or one conversation without committing anything**, and switch it off cleanly;
- Overdeck **builds `ox`** from the pinned fork commit;
- **Codex** launches get SageOx like Claude Code launches;
- the `eltmon/ox` fork is **current with upstream**.

### 3.3 Build probe (run during planning, scratchpad)

`git archive de597179 | tar -x` into a scratch dir, then `go build` with a fresh empty `HOME` (host Go 1.24.1; `go.mod` says `go 1.26`, so `GOTOOLCHAIN=auto` downloaded `go1.26.0` into `GOMODCACHE`):

1. Env `GOCACHE`, `GOMODCACHE`, `GOPATH` under the pack dir and `GOFLAGS=-modcacherw`: exit 0 in 45 s, **but `HOME/.config/go/telemetry/` was created** (Go's local telemetry counters, `os.UserConfigDir()`).
2. Adding `XDG_CONFIG_HOME=<packdir>/go/config`: `ox`, `ox-adapter-claude-code`, `ox-adapter-codex` all built (exit 0) and **`HOME` stayed empty**.
3. `ox host-contract --json` from that build printed `{"contract":"overdeck-host/1","hostManaged":true,"version":"0.19.0","commit":""}`. **`commit` is empty** because an archive build carries no VCS stamp. Running it also created `HOME/.config/sageox/auth.json.lock`: that is `ox` at run time, not the build.
4. `-modcacherw` matters: without it the module cache is read-only and `rm -rf` of the pack dir fails with `EACCES`.

### 3.4 Codex hook trust (Codex CLI 0.159.0, source `openai/codex`)

- Codex loads `<CODEX_HOME>/hooks.json` as the **User** layer's hooks (`hooks_config_folder`), and a project's `.codex/hooks.json` as the Project layer. Both are **non-managed**. A non-managed hook runs only when its trust status is `Trusted` (`discovery.rs`, `hook_trust_status`), unless Codex runs with `--dangerously-bypass-hook-trust` (applies to every hook; not used here).
- Trust key: `hook_key(source_path_display, event_name, group_index, handler_index)` = `"<absolute hooks.json path>:<event_snake>:<group>:<handler>"`, for example `/home/u/.codex/hooks.json:session_start:0:0`. The operator's `~/.codex/config.toml` shows this exact shape.
- Trust hash (`fingerprint.rs`, `version_for_toml`): `"sha256:" + hex(sha256(JSON of the identity with every object's keys sorted, compact, no extra escaping))`, where identity = `{ "event_name": "<event_snake>", "hooks": [<normalized handler>] }` plus `"matcher"` only when the group has one. Normalized command handler = `{ "type": "command", "command": <string>, "timeout": <normalized seconds>, "async": false }`. Timeout normalization: `SessionEnd` defaults to 1 and is clamped to 1..3; other events default to 600.
- **Verified:** for the operator's real `~/.codex/hooks.json` SessionStart entry (`timeout: 10`, no matcher, no statusMessage), `sha256(sortedCompactJson({event_name:'session_start', hooks:[{type:'command', command:<cmd>, timeout:10, async:false}]}))` equals the `trusted_hash` Codex stored (`9a9311f0…90af`). Adding `"matcher": null` or dropping `async` breaks the match.
- Event snake names: `session_start`, `pre_tool_use`, `post_tool_use`, `user_prompt_submit`, `stop`, `session_end`.

## 8. Hazards

- **H1 PAN-4820 not merged.** Work starts after PAN-4820 merges. Before touching `merge-gate.ts`, `merge-ops.ts` or `src/lib/deft/`, run `pan sync-main` and re-read them. Where PAN-4820's merged names differ from its PRD, use the merged names.

- **H3 Codex trust key path.** The key uses the `hooks.json` path as Codex prints it. If `CODEX_HOME` contains a symlink, Codex may print the resolved path. The WI-17 live checkpoint compares against `hooks/list`.
- **H4 `initCodexHome` rewrites `config.toml`.** The trust block must be written by `launch-settings`, after it, on every launch (AD-24).
- **H5 Login is operator-only.** No `auth.json` exists on this machine. The live `link` run (real `ox init`, real ledger clone) is an operator step; tests inject the `ox` runner. Do not run `ox login` as an agent.
- **H6 Go toolchain download.** `go.mod` needs Go 1.26; `GOTOOLCHAIN=auto` downloads it (about 70 MB) into `<packdir>/go/mod`. The preview says so (AD-8).
- **H7 Fork rebase size.** 297 upstream commits. Conflicts are likely in `cmd/ox/init.go`, `cmd/ox/agent_prime.go`, `internal/daemon/daemon.go`. AD-2 is the fallback.
- **H8 Never contact upstream.** `gh` commands in the fork clone must pass `--repo eltmon/ox` explicitly; this plan runs none.
- **H9 Ledger clone timing.** AD-13 may time out on a slow network; recording then starts once `ox` finishes the clone in the background.
