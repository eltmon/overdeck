# PAN-5282: Upgrade CLIProxy to v8.0.71 with a v8-layout generated config

Issue: [PAN-5282](https://github.com/eltmon/overdeck/issues/5282). It blocks [PAN-5278](https://github.com/eltmon/overdeck/issues/5278), which is paused until this merges. This issue takes over PAN-5278's work item 1.

## Glossary

- **CLIProxy**: the CLIProxyAPI sidecar Overdeck installs and supervises (`src/lib/cliproxy.ts`). It listens on `127.0.0.1:8317`. Claude Code agents that run GPT models point `ANTHROPIC_BASE_URL` at it.
- **Pin**: `CLIPROXY_RELEASE_VERSION` in `src/lib/cliproxy.ts` (line 69, today `'v7.3.16'`). `installCliproxy` downloads that release, and `isCliproxyUpToDateTask` compares the installed binary's version to it.
- **Legacy layout**: the v7 flat config keys (`host`, `port`, `auth-dir`, `api-keys`, `gemini-api-key`, `debug`, `remote-management`, `oauth-model-alias`, `oauth-excluded-models`).
- **v8 layout**: the nested config that starts with `config-version: 8` and has `server:`, `access:`, `management:`, `routing:`, `api-keys:` and `oauth:` sections (upstream `config.example.yaml` at `v8.0.71`).
- **`config.extra.yaml`**: the operator-owned file `~/.overdeck/cliproxy/config.extra.yaml`. Today `buildCliproxyConfig` appends it to the generated config as text (`readConfigExtra`, line 329). On the operator's machine it holds legacy-layout `oauth-model-alias`, `remote-management` and `routing` blocks.
- **Codex alias**: an entry under `oauth-model-alias.codex` (legacy) or `oauth.model-alias.codex` (v8). It has `name` (the upstream Codex model) and `alias` (the name clients may request, for example `claude-opus-5` → `gpt-6-sol`).
- **Model pool collision**: v8 serves one client model name from every upstream that offers it, round-robin ("You may repeat the same alias to build an internal model pool", `config.example.yaml` v8.0.71 line 1019; "overlapping client-visible names can become ambiguous across providers", `oauth:` section). A real Claude account natively offers `claude-opus-5`, so it would share that name with the Codex alias.
- **Management API**: CLIProxy's admin API. `/v0/management/*` keeps its v7 paths and payloads in v8 (upstream `docs/management-api-v8.md`, "v0 compatibility"). The key is `management.secret-key`. An empty key turns the API off.

## Verified facts (2026-11-14)

- `v8.0.71` assets keep the v7 names: `CLIProxyAPI_8.0.71_{linux,darwin}_{amd64,aarch64}.tar.gz` and `CLIProxyAPI_8.0.71_windows_{amd64,aarch64}.zip`. `detectPlatformAsset` (line 398) needs no change.
- The linux amd64 tarball contains `cli-proxy-api`, which matches `extractedBinaryName()` (line 79). The binary prints `CLIProxyAPI Version: %s, Commit: %s, BuiltAt: %s`, which matches `parseCliproxyVersion` (line 442).
- v8 reads legacy-only configs without rewriting them. When a file has both spellings of a field, the v8 value wins ("GET requests and config-version: 8 alone do not migrate a legacy file", `config.example.yaml` lines 4–8).
- Key moves, from `config.example.yaml` v8.0.71 lines 1390–1413: `host` → `server.host`, `port` → `server.port`, `remote-management` → `management`, `api-keys` → `access.api-keys`, `request-retry` → `routing.retry.request-retry`, `debug` → `observability.logs.debug`, `auth-dir` → `oauth.auth-dir`, `codex:` → `oauth.providers.codex`. Gemini API keys are now `api-keys.gemini` groups (`- name: <group>` with `keys: [{ api-key: … }]`, lines 645–667).
- `oauth.model-alias.<channel>` and `oauth.excluded-models.<channel>` exist in v8 (`oauth:` section, lines 1034–1180). Excluded entries support exact names and `*` wildcards. An account's own non-empty `excluded_models` in its auth JSON takes priority over the global list.
- `management.secret-key`: "If a plaintext value is provided here, it will be hashed on startup" (line 116).

## Requirements

- **FR-1** The pin is `v8.0.71`. On the next dashboard start, an existing v7 install upgrades through the existing `isCliproxyUpToDateTask` → `installCliproxy` path.
- **FR-2** Overdeck writes `config.yaml` in the v8 layout, starting with `config-version: 8`.
- **FR-3** `config.extra.yaml` is parsed as YAML, its legacy keys are converted to v8 keys, and it is deep-merged over the generated config. Extra wins on conflicts. An unparseable extra file is reported in the log and ignored, so the proxy still starts.
- **FR-4** The generated config turns on `routing.session-affinity: true` with `session-affinity-ttl: "1h"` (extra may override).
- **FR-5** The generated config turns on the management API on localhost only: `management.allow-remote: false` and `management.secret-key` = the plaintext key from `~/.overdeck/cliproxy/management-key`. Overdeck creates that file with mode 0600 and a random key if it is missing. If extra sets `management.secret-key` (or legacy `remote-management.secret-key`), the extra value wins and Overdeck writes that value into the key file, so the file always holds the active plaintext key.
- **FR-6** After the merge, the config contains `oauth.excluded-models.claude` with every `alias` value from `oauth.model-alias.codex`, combined with any entries already present. Duplicates are removed. A Claude account then never serves a name that a Codex alias claims.
- **FR-7** `readManagementKey(): Promise<string | null>` is exported from `src/lib/cliproxy.ts` for PAN-5278.
- **NFR-1** All new code is async. The sync `ensureConfigFile` is deleted and its one caller (`startCliproxy`, line 631) awaits `ensureConfigFileAsync` (one variant per operation, `docs/EFFECT-BRIDGING.md`).
- **NFR-2** No test talks to the live CLIProxy on port 8317, the live `~/.overdeck/cliproxy/` directory, or any upstream provider.

## Decisions

1. **Pin `v8.0.71`.** Do not chase a later patch in this issue.
2. **Build the config as an object and serialize it with the `yaml` package** (`import YAML from 'yaml'`, already used in 28 `src/lib` files). Do not concatenate text. This removes the duplicate-top-level-key risk the text append has.
3. **Legacy-to-v8 conversion of extra** covers exactly these keys. Any other key is merged as-is, and v8 still reads legacy keys:

   | Legacy key in extra | v8 key |
   | --- | --- |
   | `host` | `server.host` |
   | `port` | `server.port` |
   | `remote-management` | `management` |
   | `api-keys` | `access.api-keys` |
   | `request-retry` | `routing.retry.request-retry` |
   | `max-retry-interval` | `routing.retry.max-retry-interval` |
   | `debug` | `observability.logs.debug` |
   | `auth-dir` | `oauth.auth-dir` |
   | `oauth-model-alias` | `oauth.model-alias` |
   | `oauth-excluded-models` | `oauth.excluded-models` |

   Before you write the conversion, open `config.example.yaml` at tag `v8.0.71` and confirm the two retry keys and `oauth.excluded-models` sit at those paths. If one differs, use the path the example shows and note it in the PR.
4. **Deep merge rule.** Objects merge key by key. Arrays and scalars from extra replace the generated value. The exception is FR-6's exclusion list, which is computed after the merge.
5. **Do not edit the operator's `config.extra.yaml`.** Conversion happens in memory on every build.
6. **Gemini key** goes to `api-keys.gemini: [{ name: 'overdeck-gemini', keys: [{ 'api-key': <key> }] }]`.
7. **Leave out `quota-exceeded`.** The current generator doesn't write it.
