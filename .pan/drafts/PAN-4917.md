# PAN-4917 — CI trailer gate times out on full-history checkout; cancelled check blocks merges and conflict repair

**Issue:** [eltmon/overdeck#4917](https://github.com/eltmon/overdeck/issues/4917)
**Planned:** 2026-11-03 (auto planning, high effort)

## Glossary

- **Trailer gate** — the CI job `prompt-gate`, display name `Prompt change trailer gate` (`.github/workflows/ci.yml`, lines 147-158). It runs `scripts/check-prompt-change-trailer.sh`, which fails a PR that changes `roles/*.md` or `sync-sources/skills/pan-flywheel/SKILL.md` unless one commit in `merge-base..HEAD` carries a `Prompt-Change:` trailer. The job's display name is the check name in a PR's status rollup; it must not change.
- **Full-history checkout** — `actions/checkout@v4` with `fetch-depth: 0`. It fetches every branch (`+refs/heads/*`) and every tag, not only the history the script reads.
- **Shallow clone** — a clone that holds only the newest commit(s) of a ref (`fetch-depth: 1`, the `actions/checkout` default). `git rev-parse --is-shallow-repository` prints `true`.
- **Unshallow** — `git fetch --unshallow`: fetch the missing history so the clone is complete. Valid only on a shallow clone; git refuses it on a complete one.
- **Blobless partial clone** — `--filter=blob:none`: fetch commits and trees but no file contents. `git log`, `git rev-list`, `git merge-base` and `git diff --name-only` read only commits and trees. Git fetches a missing blob on demand from the promisor remote if a command needs one (for example inexact rename detection).
- **`overdeck-state`** — an archived branch on `origin` (tagged `state-final`). It must never be deleted (universal rule). It holds about 195,000 commits that are not on `main`.
- **Status rollup** — GitHub's `statusCheckRollup` on a PR head: one row per check run (`status`, `conclusion`) or commit status (`state`, `context`).
- **Check conclusion** — the result of a completed check run: `SUCCESS`, `FAILURE`, `NEUTRAL`, `CANCELLED`, `SKIPPED`, `TIMED_OUT`, `ACTION_REQUIRED`, `STARTUP_FAILURE`, `STALE`.
- **Unfinished check** — in this PRD, a check whose conclusion is `CANCELLED`, `TIMED_OUT` or `STALE`. It stopped before it judged the code.
- **Red head** — `PrFacts.checks === 'red'`, computed by `summarizeStatusCheckRollup` in `src/lib/cloister/pr-facts.ts`. Any completed check whose conclusion is not `SUCCESS`/`NEUTRAL`/`SKIPPED`, or any commit status in `FAILURE`/`ERROR`, makes the head red.
- **Conflict-repair gate** — `evaluateConflictRepairGate` in `src/lib/cloister/merge-gate.ts`. It decides whether an approved PR that conflicts with `main` gets a sync-main repair prompt from the conflict-repair patrol (`src/lib/cloister/conflict-repair.ts`, `tickConflictRepair`).
- **Merge gate** — `evaluateIssueMergeGate` / `evaluateMergeReadiness` (`pr-facts.ts`). It decides whether a PR may merge. This PRD does not change it.

## Problem

### 1. The trailer gate's checkout is slow because it fetches every branch

`.github/workflows/ci.yml` lines 147-158 (grep anchor: `name: Prompt change trailer gate`):

```yaml
  prompt-gate:
    runs-on: ubuntu-latest
    name: Prompt change trailer gate
    timeout-minutes: 5

    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Check Prompt-Change trailer for roles/ and docs/flywheel-brief.md
        run: bash scripts/check-prompt-change-trailer.sh
```

On 2026-11-03 the checkout step took more than 5 minutes three times, and the job was cancelled before the script ran. Verified for main run 41686923189, attempt 1: `Run actions/checkout@v4` started 17:43:08 and concluded `cancelled` at 17:48:08; the check run's conclusion is `cancelled`. Attempt 2 of the same job passed in 53 seconds, so the checkout time varies widely.

Measured on a local clone at planning time:

| What is fetched | Commits | Trees | Blobs |
| --- | --- | --- | --- |
| `origin/main`, full | 19,698 (7.4 MiB) | 97,868 (8.6 MiB) | 66,828 (367.2 MiB) |
| `origin/main`, blobless | 19,698 (7.4 MiB) | 97,868 (8.6 MiB) | 0 |
| `overdeck-state` not on main, blobless | 195,341 (24.1 MiB) | 390,730 (39.7 MiB) | 0 |

`origin` also has 716 branches and 588 tags. `fetch-depth: 0` fetches all of them. So the issue's first suggestion, `fetch-depth: 0` plus `filter: blob:none`, still makes the server enumerate and send about 700,000 commits and trees, most of them from `overdeck-state`. A targeted fetch of only `main` and the checked-out commit, blobless, is about 118,000 objects and 16 MiB, and it does not grow with the number of branches.

The script needs only `origin/main`, the merge base, `git diff --name-only` and the commit messages (`scripts/check-prompt-change-trailer.sh`, functions `resolve_merge_base`, `changed_prompt_files`, `has_prompt_change_trailer`). `resolve_merge_base` is meant to log `base ref origin/main not found; skipping` and exit 0 when `origin/main` is missing, but it runs inside a command substitution (`merge_base="$(resolve_merge_base)"` in `check`), so its `exit 0` ends only the subshell and the log line becomes the merge-base value. The script then fails: `PROMPT_CHANGE_BASE_REF=nonexistent bash scripts/check-prompt-change-trailer.sh` exits 128 with `fatal: invalid object name 'prompt-trailer'.` (verified by the plan critic). So a plain shallow checkout would make the gate fail with a confusing git error, not pass. The new fetch must fail with a clear `prompt-trailer:` message when it cannot produce a complete history.

### 2. A cancelled check blocks conflict repair, and the decline reason does not name it

`src/lib/cloister/merge-gate.ts` lines 231-236 (grep anchor: `if (facts.checks === 'red') {` inside `evaluateConflictRepairGate`):

```ts
  // PAN-4451: GitHub builds no merge ref for a conflicting PR, so pull_request CI
  // never runs on it and its head cannot get a test result. Only a red head
  // disqualifies; the merge gate re-judges CI on the repaired head.
  if (facts.checks === 'red') {
    return { conflicting: false, reason: `CI checks failing on PR HEAD ${facts.headSha ?? 'unknown'}`, facts };
  }
```

A job killed by its own `timeout-minutes` reports conclusion `CANCELLED`. This is the same conclusion as a run that a newer push superseded (`concurrency: cancel-in-progress: true` in `ci.yml`). So a timed-out trailer gate made the heads of PR #4911 (PAN-4479) and PR #4915 (PAN-4480) red. The gate declined repair for both, and both PRs stayed approved and CONFLICTING. The patrol's log line (`conflict-repair.ts`, `logDeclinedConflict`) printed only `CI checks failing on PR HEAD <sha>`, so nobody could see which check was red.

An unfinished check did not judge the code. The repair pushes a new head, CI runs again on it, and the merge gate judges CI there. So an unfinished check gives no reason to withhold the repair.

## Decisions

- **D1 — Targeted blobless fetch, not `fetch-depth: 0` + `filter: blob:none`.** The checkout stays at the default depth 1. The script gains a `--fetch` mode that fetches `refs/heads/main` and the `HEAD` commit with `--no-tags --filter=blob:none`, adds `--unshallow` when the clone is shallow, and then asserts the clone is complete and `origin/main` resolves. Reason: the measured table above. `overdeck-state` is most of the cost and the issue's option 1 still fetches it.
- **D2 — The fetch lives in the script, not inline in YAML.** One source of truth, and the script's `--self-test` exercises it against a local `file://` remote. `tests/unit/scripts/check-prompt-change-trailer.test.ts` already runs `--self-test`, so the CI test shards cover the fetch.
- **D3 — The `HEAD` commit is fetched by SHA.** On `pull_request` events `HEAD` is the merge commit `refs/pull/<n>/merge`. If only `main` is fetched, the merge commit's PR-side parent history stays missing. GitHub serves a reachable SHA as a fetch want (`actions/checkout` itself fetches by SHA). The fetch passes `"$(git rev-parse HEAD)"`, not `$GITHUB_SHA`, so it always names the commit that is checked out.
- **D4 — `timeout-minutes: 20`**, the same as `build` and `lint-group`, with the PAN-1651 comment. A slow fetch then fails at 20 minutes, not 5.
- **D5 — The script's checking behavior is unchanged.** Without `--fetch` the script runs exactly as today, including its existing missing-base-ref behavior (exit 128, see Problem 1), which this PRD does not fix. `npm run lint:prompt-trailer` runs in clones that have `origin/main`. With `--fetch` it fetches, asserts, then runs the same `check`.
- **D6 — The CI step name is corrected.** The step name says `docs/flywheel-brief.md`, but the script watches `sync-sources/skills/pan-flywheel/SKILL.md`. The step is renamed to `Check Prompt-Change trailer for roles/ and the flywheel skill`. The job's `name: Prompt change trailer gate` does not change, because it is the check name in the rollup.
- **D7 — Unfinished checks do not disqualify conflict repair.** The conflict-repair gate treats a red head whose failing checks all concluded `CANCELLED`, `TIMED_OUT` or `STALE` the same as `pending` (PAN-4451 already waives pending and absent CI there). Any other failing conclusion (`FAILURE`, `ACTION_REQUIRED`, `STARTUP_FAILURE`, …) or a commit status in `FAILURE`/`ERROR` still declines. The rule is by conclusion, because GitHub reports a timeout and a superseded run identically.
- **D8 — The decline reason names the failing checks.** It keeps the prefix `CI checks failing on PR HEAD <sha>` (an existing test asserts it) and appends `: <name> (<CONCLUSION>), …`.
- **D9 — Per-check failures come from a new leaf module.** `src/lib/cloister/pr-facts.ts` is 988 lines against the 1000-line file-size ceiling. `FailedCheck` and `listFailedTestChecks` move to a new `src/lib/cloister/check-failures.ts` with a new unfiltered `listFailedChecks`. `pr-facts.ts` re-exports all three, so existing imports (`ci-failure-feedback.ts`, the `pr-facts-*` tests) do not change, and `pr-facts.ts` shrinks.
- **D10 — `PrFacts.checkFailures` is GitHub-only.** GitLab reports one pipeline status, not per-check rows, so the field stays absent there, and a red GitLab head still declines repair as today.
- **D11 — The merge gate is unchanged.** A cancelled check still blocks merging. Only the repair decision changes.

## Requirements

- **FR-1** — `bash scripts/check-prompt-change-trailer.sh --fetch` fetches `refs/heads/main` into `refs/remotes/origin/main` and the `HEAD` commit's full history, with `--no-tags --filter=blob:none`, adding `--unshallow` only when the clone is shallow.
- **FR-2** — After the fetch, `--fetch` exits 1 with a `prompt-trailer:` error message when the clone is still shallow or `origin/main` does not resolve. It also exits 1 with `prompt-trailer: history fetch failed from <remote>` when the `git fetch` itself fails.
- **FR-3** — After a successful fetch, `--fetch` runs the same check as the no-argument mode and produces the same exit code and messages.
- **FR-4** — The script's `--self-test` exercises `--fetch` against a shallow `file://` clone: a branch with a prompt change and no trailer fails, a branch with the trailer passes, and `main` passes. Each fetched clone ends non-shallow. A shallow clone whose `origin` is missing exits 1 with `prompt-trailer: history fetch failed`.
- **FR-5** — The `prompt-gate` job checks out at the default depth, runs the script with `--fetch`, has `timeout-minutes: 20`, and keeps `name: Prompt change trailer gate`.
- **FR-6** — `listFailedChecks(rollup)` in `src/lib/cloister/check-failures.ts` returns every failing rollup row (any check, not only the test job) as `{ name, conclusion, targetUrl? }`, using the same failure predicate as `summarizeStatusCheckRollup`.
- **FR-7** — GitHub `PrFacts` carry `checkFailures: listFailedChecks(pr.statusCheckRollup)`. GitLab facts and `emptyPrFacts` leave it absent.
- **FR-8** — `evaluateConflictRepairGate` does not decline a red head when `checkFailures` is non-empty and every entry's conclusion is `CANCELLED`, `TIMED_OUT` or `STALE`.
- **FR-9** — When `evaluateConflictRepairGate` declines a red head, its reason is `CI checks failing on PR HEAD <sha>: <name> (<CONCLUSION>), …` listing every failing check, or exactly `CI checks failing on PR HEAD <sha>` when `checkFailures` is absent or empty.
- **NFR-1** — On this PR's own CI run, the `Prompt change trailer gate` job completes with conclusion `success` in under 3 minutes.
- **NFR-2** — `scripts/lint-file-size.sh` passes: `src/lib/cloister/pr-facts.ts` ends at or below its `origin/main` line count (988).
- **NFR-3** — `npm run lint:circular` passes: `check-failures.ts` imports nothing from `pr-facts.ts`.
- **NFR-4** — The merge gate's behavior and `summarizeStatusCheckRollup` are unchanged; existing `pr-facts-*` and `merge-gate*` tests pass without edits other than added cases.

```bash
# PAN-4917: CI checks out one commit. Fetch the history the check reads, which
# is the base branch and HEAD, without blobs or tags. fetch-depth: 0 also pulls
# every other branch; the archived overdeck-state branch alone is ~195k commits,
# and that checkout timed the job out.
fetch_history() {
  local remote="${BASE_REF%%/*}" branch="${BASE_REF#*/}"
  local deepen=()
  if [[ "$(git rev-parse --is-shallow-repository)" == true ]]; then
    deepen=(--unshallow)
  fi
  # The script runs under set -e; test the fetch so a failure prints our message.
  if ! git fetch --no-tags --filter=blob:none ${deepen[@]+"${deepen[@]}"} "$remote" \
    "+refs/heads/$branch:refs/remotes/$remote/$branch" "$(git rev-parse HEAD)"; then
    fail "history fetch failed from $remote"
    exit 1
  fi
  if [[ "$(git rev-parse --is-shallow-repository)" != false ]] \
    || ! git rev-parse --verify --quiet "$BASE_REF" >/dev/null; then
    fail "history fetch left the clone shallow or without $BASE_REF"
    exit 1
  fi
}
```

```ts
/**
 * PAN-4917: conclusions of a check that stopped before it judged the code.
 * GitHub reports a job killed by its own timeout-minutes as CANCELLED, the same
 * as a run a newer push superseded, so the rule is by conclusion, not cause.
 */
const UNFINISHED_CHECK_CONCLUSIONS = new Set(['CANCELLED', 'TIMED_OUT', 'STALE']);

/**
 * PAN-4917: why a red head is not repaired, naming each failing check, or null
 * when every failing check is unfinished. The repair pushes a new head that CI
 * runs again, and the merge gate judges CI there. With no per-check detail
 * (GitLab) a red head still declines.
 */
function redHeadDeclineReason(facts: PrFacts): string | null {
  const failures = facts.checkFailures ?? [];
  if (failures.length > 0 && failures.every((check) => UNFINISHED_CHECK_CONCLUSIONS.has(check.conclusion))) return null;
  const named = failures.map((check) => `${check.name} (${check.conclusion})`).join(', ');
  return `CI checks failing on PR HEAD ${facts.headSha ?? 'unknown'}${named ? `: ${named}` : ''}`;
}
```

## Critique response

### Failed fetch misses the required error

Accepted. Under `set -euo pipefail` a bare failing `git fetch` exits with git's code (128) before the `fail` call. WI-1's `fetch_history` now runs the fetch inside `if ! git fetch …; then fail "history fetch failed from $remote"; exit 1; fi`. The self-test's `clone-broken` case now asserts exit status 1 and the `prompt-trailer: history fetch failed` text, and AC-3 says the same. A scratch copy with this change passed `--self-test`.

### Fallback restores the costly checkout

Accepted. The WI-2 fallback no longer uses `fetch-depth: 0`. If GitHub refuses the SHA want, the script fetches an advertised ref from `PROMPT_CHANGE_FETCH_REF`, which the CI step sets to `${{ github.ref }}` (`refs/pull/<n>/merge` on PRs, `refs/heads/main` on push), and NFR-1's timing bound still applies. The SHA stays the primary want, because `github.ref` can move past the checked-out merge commit when a PR is updated during a run.

### Missing-base skip does not work

Accepted as a framing correction. Problem 1 and D5 now say that the no-argument script exits 128 when `origin/main` is missing, and hazard H2 in the continue file no longer claims a silent pass. Fixing that path is a Non-goal: CI with `--fetch` asserts `origin/main` before `check` runs.
