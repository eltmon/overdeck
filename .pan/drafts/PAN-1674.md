# PAN-1674 — Share one TLDR venv across workspaces instead of copying it into each one

**Issue:** [PAN-1674](https://github.com/eltmon/overdeck/issues/1674)
**Status:** planned (auto mode, 2026-09-29)

## Glossary

- **TLDR** — the `llm-tldr` Python package. Its `tldr` CLI summarizes code files. The `tldr-read-enforcer` hook calls it on large-file Reads; the TLDR daemon keeps an index in `<checkout>/.tldr/`.
- **TLDR venv** — a Python virtualenv that holds `llm-tldr`, CPU-only torch and their dependencies. Every consumer finds it at `<checkout>/.venv` and runs `<checkout>/.venv/bin/tldr`.
- **Project-root venv** — `<projectRoot>/.venv`, the venv in the primary checkout (for Overdeck: `/home/eltmon/Projects/overdeck/.venv`, 1.5G).
- **Workspace venv** — `<projectRoot>/workspaces/feature-<issue>/.venv`.
- **Legacy copy** — a workspace venv that is a real directory made by `cp -a` from the project-root venv (the current behavior).
- **Shared link** — a workspace venv that is a symbolic link to the project-root venv (the new behavior).
- **Python-project marker** — a file at the workspace root that means the project owns `.venv` for its own Python dependencies: `pyproject.toml`, `requirements.txt`, `Pipfile`, or `setup.py`.
- **Disk safety floor** — 10 GiB of available bytes, the same number as `DISK_PRUNE_TRIGGER_BYTES` in `src/lib/cloister/disk-pressure-patrol.ts` (line 18).
- **Common-dir exclude file** — the repository's `info/exclude`, resolved from inside a worktree with `git rev-parse --git-path info/exclude`. All worktrees of a repository read the same file.

### Empirical checks done during planning

1. `tldr structure . --lang typescript` runs correctly from a scratch directory whose `.venv` is a symlink to the project-root venv. `sys.prefix` resolves to the link path, and output lands in the scratch directory.
2. A `.gitignore` line `.venv/` does **not** ignore a symlink named `.venv` (`git status` shows `?? .venv`; `git check-ignore` exits 1). A line `.venv` (no slash) ignores it. Overdeck's `.gitignore` line 33 is `.venv/`.
3. In a linked worktree, `git rev-parse --git-path info/exclude` returns `<repo>/.git/info/exclude` (the common dir). Adding `/.venv` there makes the symlink disappear from `git status` in the worktree.
4. Each of these removes only the link and leaves the target intact: Node `fs.promises.rm(link, { recursive: true, force: true })` (what `src/dashboard/server/routes/resources/reclaim.ts` line 48 does), `git worktree remove --force` on a worktree holding the link, and `rm -rf "<workspace>"` (what `src/dashboard/server/routes/workspaces/stash-clean.ts` line 417 does).
5. `rsync -a` (no `-L`) copies the link as a link.

## Requirements

### Functional

- **FR-1** Workspace creation makes the workspace venv a symbolic link to the project-root venv when `<projectRoot>/.venv/bin/tldr` exists. It never copies the venv.
- **FR-2** Workspace creation never builds a venv (`python3 -m venv`, `pip install`). When the project root has no TLDR venv, it records a step that names `pan admin tldr install` and skips TLDR setup.
- **FR-3** Workspace creation skips the shared link, and records a step, when the workspace root holds a Python-project marker.
- **FR-4** Workspace creation adds `/.venv` to the common-dir exclude file (idempotent), so the link never shows as untracked in any project.
- **FR-5** Overdeck's own `.gitignore` ignores `.venv` as a file or a directory.
- **FR-6** `pan admin tldr install` builds the project-root venv once (CPU-only torch first, then `llm-tldr`, then the `.tsx/.jsx` patch from the installed Overdeck package).
- **FR-7** `pan admin tldr dedupe [--dry-run]` converts every legacy copy under `<projectRoot>/workspaces/feature-*/.venv` into a shared link and reports the bytes reclaimed.
- **FR-8** Workspace creation refuses to start when the project path's filesystem has less than the disk safety floor available.
- **FR-9** The corrupted-workspace backup (`stash-clean.ts`) excludes `.venv`.
- **FR-10** `relocateVenvScripts` and its test are deleted, because nothing copies venvs any more.
- **FR-11** User docs and skills describe the shared link, `pan admin tldr install`, and `pan admin tldr dedupe`.

### Non-functional

- **NFR-1** A workspace venv adds no more than a few bytes of disk (one symlink).
- **NFR-2** Tests never run python, pip, or the network. All external effects in the new module go through an injected deps object.
- **NFR-3** New `src/lib` code is plain async/sync TypeScript with no exported Effect wrapper (`npm run lint:effect-facades`). No `execSync` in code reachable from the dashboard server.
- **NFR-4** No file grows past its `origin/main` line count or allowlist cap (`scripts/lint-file-size.sh`). `create.ts` shrinks.

## Decisions (auto mode)

1. **Target of the link = project-root venv.** It already exists on this machine and every other consumer (`pan up`, the main daemon, merge-agent) already uses it. A machine-level venv under `~/.overdeck/` was rejected: it adds a second location, and shells that carry `OVERDECK_HOME=/tmp` would build 1.5G in `/tmp`.
2. **No auto-build during workspace creation.** Building on demand would need a cross-process lock, a ready marker, and crash recovery for half-built venvs, because two workspaces can be created at the same time. An explicit `pan admin tldr install` removes that concurrency surface. Behavior change: a project with no project-root venv no longer gets a private venv per workspace; its workspaces run without TLDR (Reads fall back to full reads, as the hook already does) until the operator runs `pan admin tldr install` once in the primary checkout.
3. **Python-project workspaces skip the link.** With a link, a `uv sync` or `pip install` inside one workspace would write into the venv every workspace shares. Skipping is the safe default; those workspaces run without TLDR.
4. **Exclude via common-dir `info/exclude`, never the project's tracked `.gitignore`.** This follows the precedent in `src/lib/projects/create-perform.ts` lines 110–149 (`excludeWorkspacesDir`: "Never the tracked `.gitignore`"). That helper skips linked worktrees, so the new code resolves the path with `git rev-parse --git-path info/exclude` run in the workspace instead. Overdeck's own `.gitignore` also gets `.venv` (FR-5) because Overdeck's workspaces are the main population.
5. **One disk floor.** Reuse 10 GiB (the value of `DISK_PRUNE_TRIGGER_BYTES`). Refuse, do not warn: ENOSPC mid-write zero-fills files (the incident truncated `~/.claude.json`), so a warning is not enough. The check `statfs`es the project path, not `OVERDECK_HOME`, because the two can be on different filesystems.
6. **Dedupe is CLI only.** A new HTTP route would need a `no-loss-matrix.ts` row and a UI. The operator runs it once to reclaim the legacy copies; new workspaces never create copies.
7. **The reclaim route's venv janitor is not wired up.** `cachedVenvCandidates` in `reclaim.ts` is populated only by tests. After this change a new workspace venv is a symlink, so a per-workspace venv janitor has nothing to reclaim; dedupe handles the legacy copies.
8. **The `.tsx/.jsx` patch script path** comes from the installed Overdeck package (`packageRoot` exported by `src/lib/paths.ts` line 97, `scripts/` is in `package.json` `files`), not from the project being set up. Today it is `join(projectConfig.path, 'scripts', 'patches', ...)`, which exists only when the project is Overdeck itself.

### W6 — `pan admin tldr dedupe [--dry-run]` (FR-7)

**Files:** new `src/lib/workspace-manager/tldr-venv-dedupe.ts`, new `src/lib/workspace-manager/__tests__/tldr-venv-dedupe.test.ts`, `src/cli/commands/admin/tldr-handler.ts`, `src/cli/commands/admin/index.ts` (add `.option('--dry-run', 'Report legacy workspace venv copies without changing them')`; description becomes `'TLDR daemon: status, start, stop, warm, install, dedupe'`).

```ts
export interface DedupeEntry { workspacePath: string; bytes: number; action: 'converted' | 'would-convert' | 'skipped'; reason?: string }
export async function dedupeWorkspaceVenvs(projectRoot: string, opts: { dryRun: boolean }, deps?): Promise<DedupeEntry[]>;
```

Algorithm:
1. Refuse (throw with a message) when `<projectRoot>/.venv/bin/tldr` is missing.
2. For each directory `<projectRoot>/workspaces/feature-*`: `lstat` `<ws>/.venv`. Skip silently when missing or already a symlink. Skip with reason when it is a real directory without `bin/tldr`, or when the workspace has a Python-project marker.
3. Measure bytes with `du -sb <ws>/.venv` via async exec.
4. In dry-run, record `would-convert`. Otherwise: stop the workspace daemon (`getTldrDaemonService(ws, venv).stop()`, errors ignored) → `rename(<ws>/.venv, <ws>/.venv.pan-1674-old)` → `linkWorkspaceTldrVenv` → `ensureVenvExcluded` → `rm(<ws>/.venv.pan-1674-old, { recursive: true, force: true })` → restart the daemon (`start(true)`, errors ignored) → record `converted`. If the link step fails, rename the old directory back before recording `skipped`.
The CLI prints one line per entry and a total like `Reclaimed 28.5 GiB from 19 workspaces` (dry run: `Would reclaim ...`). `--json` prints the entries.

Tests use a temp project tree with fake venv directories (a `bin/tldr` file) and injected `du`/daemon deps: a real copy becomes a symlink to the root venv and the old directory is gone; dry run changes nothing; symlinks and Python-marker workspaces are skipped; the root venv content survives.

## Non-goals

- A machine-level venv under `~/.overdeck/` shared across projects.
- Building the venv automatically during workspace creation.
- TLDR for Python-project workspaces (a differently named venv would need hook changes).
- Wiring the reclaim route's venv janitor (`cachedVenvCandidates`) or adding an HTTP/UI surface for dedupe.
- Sharing or deduplicating the `.tldr/` index (about 4 MB per workspace).
- Changing the Deacon disk-pressure patrol or its BuildKit prune.
- Running dedupe automatically; the operator runs it once.

## Repo rules that apply

- No `execSync` in code reachable from the dashboard server; `create.ts` runs inside the server. Use the async `exec` already used there.
- No shell variables in `rm` targets; the Node `rm` in W6 uses a computed path in code, which is allowed, but never shells out to `rm -rf $VAR`.
- Tests that read source text or add `skipIf`/`.only` fail lint; assert behavior through injected deps.
- One variant per operation in `src/lib`: no Effect wrapper around the new async functions.
- New lib modules must not import `agent-state` heavy modules; `tldr-venv*.ts` imports only `fs`, `path`, `child_process`, `util`, `../paths.js`, and (dynamically) `../tldr-daemon.js`.
- Quality gates: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never the full `npm test`.
