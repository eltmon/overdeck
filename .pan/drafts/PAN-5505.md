- Run and direct many coding agents at once, across harnesses, models and machines.
- Carry work from a conversation or an issue to a merged pull request.

## Get started

Try Overdeck without installing anything. This starts Overdeck and opens the dashboard in your browser:

```bash
npx @overdeck/core
```

To install the `overdeck` and `pan` commands, run the install script. It needs Node.js 22 or later, installs with npm into `~/.local`, and does not use sudo:

```bash
curl -fsSL https://overdeck.ai/install | sh
```

`pan` is the short name for `overdeck`. Both run the same CLI. Next, follow the [Quickstart](/quickstart) to add a project and start your first agent.

## What Overdeck does

### Conversations with your code

Start a conversation with an agent in any project and steer it while it works. Each turn shows the files it changed, and the diffs, files and commits sit beside the chat. See [Conversations](/features/conversations) and [the file explorer](/features/file-explorer).

### The issue pipeline

`pan start <issue>` plans the issue, makes an isolated workspace for it, and starts a work agent. Review agents and a test agent check the work, and the pull request waits for you to click Merge unless you turn on auto-merge. Issues come from GitHub, Linear, GitLab, Rally or Jira. See [Planning](/features/planning), [the review convoy](/features/convoys), [merge batches](/features/merge-batches), [auto-merge](/configuration/auto-merge) and [issue trackers](/configuration/issue-trackers).

### Order books and the Flywheel (early)

The Flywheel is a loop that runs in one conversation. It picks the next issue from your order books and backlog, starts work on it, watches the pull request until it lands, and parks what it cannot decide for you. The Flywheel is early. See [order books](/configuration/order-books) and [the Flywheel vision](/vision).

### Harnesses and models

Agents run on the coding-agent CLI you choose: Claude Code, Codex, Pi, OpenCode, Kimi Code, Grok Build and others. You pick the model for each role in the pipeline. See [harnesses](/configuration/harnesses) and [model presets](/configuration/model-presets).

### Overdeck Anywhere

Every machine runs its own Overdeck. Link your machines to see all of their conversations in one list, move a conversation to another machine, and answer agents from your phone. overdeck.ai accounts are invite-only for now. See [Overdeck Anywhere](/anywhere).

### Seeing the work

Needs you collects every question, plan and permission prompt that waits on you. The Board shows every issue by its state. Each conversation and issue shows its cost at API rates, so the cost on a subscription plan can differ. See [Command Deck](/features/mission-control).

### Skills, memory and rules

`pan sync` gives every supported harness the bundled skills, and you can turn each skill on or off per project, issue or conversation. Project memory keeps curated facts in your repo, and context layers deliver your rules to each agent when it starts. See [skills](/features/skills), [memory](/configuration/memory) and [context layers](/configuration/context-layers).

For the full list, see the [features page on overdeck.ai](https://overdeck.ai/features/) and the [CLI reference](/cli/overview).

## A short history

Overdeck started in January 2026 as **Panopticon**. The name came from the Panopticon in Doctor Who, the great hall of the Capitol on Gallifrey where the Time Lords gather. The command was `pan` and the npm package was `panopticon-cli`.

In April 2026 the zero-install launcher shipped as `@panctl/cli`. In June 2026 the project was renamed **Overdeck**, and on June 20, 2026 the package became `@overdeck/core`. The new name has no Doctor Who meaning. `pan` stayed as the short command and `overdeck` is the long one. That is also why planning files in your repo live under `.pan/`.
