## blocks-the-design: Relay check POST skips the mutation guard

WI-8 specifies `rejectUnauthorizedDashboardRequest` for `POST /api/anywhere/relay-check` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 562–571). That guard accepts an admin root session before checking Origin or CSRF ([dashboard-auth.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/dashboard/server/routes/dashboard-auth.ts), lines 491–512). The remote gate explicitly leaves Origin and CSRF to routes ([remote-request-gate.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/dashboard/server/remote-request-gate.ts), lines 47–48). This POST obtains credentials and makes a TURN allocation, so a request carrying a valid root cookie and an untrusted Origin would start network work; single-flight only coalesces simultaneous requests. The existing `rejectUnsafeDashboardMutationRequest` enforces Content-Type, Origin and CSRF for cookie credentials while allowing the CLI internal token ([dashboard-auth.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/dashboard/server/routes/dashboard-auth.ts), lines 282–309). Use that guard for the new route and test that a root-cookie POST with no CSRF or a foreign Origin never invokes the probe.

## blocks-the-design: Diagnostics can expose TURN URL secrets

WI-3 copies `firstTurnUrl` verbatim into a `ChannelOpenError` ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 339–356). WI-7 returns the same raw URL in the API response and copies arbitrary peer error text into `detail` (lines 490–526); WI-9 prints both in the doctor row (lines 640–653). The existing `turnUrlRank` accepts a `turns:host:443?token=secret` URL because it identifies only the scheme and port, and `relayIceServers` preserves the URL unchanged ([relay-ice-servers.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/lib/anywhere/channel/relay-ice-servers.ts), lines 14–25 and 29–44). Thus a token in a directory-supplied TURN URL reaches the connector status line, route response or doctor output, contrary to NFR-1. Emit only a validated scheme, host and port in diagnostics, and use controlled error categories instead of forwarding arbitrary peer error text. Add tests with a secret-bearing URL and an error containing candidate text; the current `never logs SDP or candidate text` test covers only a normal direct dial ([rtc-transport.test.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/src/lib/anywhere/channel/__tests__/rtc-transport.test.ts), lines 239–250).

## sharpens-framing: Failed probe does not always mean blocked egress

WI-7 maps a 12-second gather timeout and any thrown peer error to `state: 'failed'` with a TURN URL ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5242/.pan/drafts/PAN-5242.md), lines 521–527). WI-9 maps every such result to “This machine gathered no TURN relay candidate” and instructs the operator to allow outbound TLS or UDP (lines 640–644). A hung gather or `createOffer()` failure has not established that conclusion. Give `failed` a cause such as `zero-candidates`, `timeout` or `peer-error`, and reserve the network fix for `zero-candidates`; test the timeout and thrown-error doctor rows.
