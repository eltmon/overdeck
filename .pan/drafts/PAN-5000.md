# PAN-5000 — Anywhere display bugs found by the 2026-11-04 screenshot run

**Issue:** [PAN-5000](https://github.com/eltmon/overdeck/issues/5000)
**Base:** `main` at `46234b961f4` (build 0.73.1)
**Screenshots (before):** orchestrator's `/home/eltmon/Projects/overdeck/.tmp/anywhere-status/anywhere/` — 01, 14, 15, 16, 29, 33, 35.

## Glossary

- **Paired device record** — an entry in the access-token registry (`~/.overdeck/access-tokens.json`, door `src/lib/access-tokens.ts`) with `kind: 'device'` (a browser paired with `pan pair`), `kind: 'phone'` (the Overdeck phone app, PAN-4835), or no `kind` at all (legacy; "a record with no `kind` is a device", `src/lib/access-tokens.ts` header, PAN-2351 FR-10). Other kinds (`token`, `machine`, `connector`) are not paired devices.
- **Active** — a record with no `revokedAt`.
- **Anywhere status card** — `AnywhereStatusCard.tsx`, fed by `GET /api/anywhere/status` (`src/dashboard/server/routes/anywhere.ts`).
- **Paired devices panel** — `DevicesPanel.tsx`, fed by `GET /api/devices` (`src/dashboard/server/routes/pairing.ts`). It lists revoked rows too, labelled "Revoked … ago".
- **Linked conversation** — a conversation that runs on another machine linked to this one (PAN-4650). The viewer caches the owner's shared rows and merges them into `GET /api/conversations` through `mergeConversationRows` → `linkedListRow` (`src/lib/overdeck/linked-conversations-merge.ts`). Its list `name` is `@<environmentId>/<owner name>` (`linkedConversationName`, `packages/contracts/src/linked-conversations.ts`).
- **No-project deck** — the Command Deck bucket for conversations outside every registered project. Its deck key is the sentinel `NO_PROJECT_KEY = '__no-project__'`; its display label is `NO_PROJECT_LABEL = 'No project'` (`src/dashboard/frontend/src/components/CommandDeck/projectsData.ts`, lines 14–15).
- **App bar** — the top strip in `src/dashboard/frontend/src/App/AppChrome.tsx`: the project crumb on the left and the search button in the centre.
- **Attachment reference line** — a line `@<absolute path>` that the composer puts before the message text, one per uploaded file (`ComposerFooter.tsx`, line 493–496). The path is under `<OVERDECK_HOME>/conversation-attachments/<conversation>/`.
- **Derived title** — the quick title `derivePromptTitle` (`src/lib/conversations/transcript-summary.ts`, line 252) builds from the first prompt while the AI title is generated.
- **Preview popover** — `OpenPreviewPopover.tsx`, the **Preview** button and popover in a linked conversation's title bar (PAN-4650 WI-19).
- **Isolated dashboard** — the Playwright fixture `src/dashboard/frontend/tests/fixtures/isolated-dashboard.ts`: a built dashboard on a temp `OVERDECK_HOME` and a free port, never the operator's `:3011`.

## Problem

The 2026-11-04 screenshot run of the Anywhere screens (dashboard `:3011`, linked to a MacBook) found five display bugs:

1. **Paired devices count is wrong.** The status card says "Paired devices 0" while the Paired devices panel lists an active Android phone (screens 01, 33).
2. **Raw project key shown.** With the no-project deck selected, the app bar crumb reads `__no-project__` and the search placeholder reads `Search __no-project__…` (screen 15).
3. **Bad titles for linked conversations.** An untitled linked conversation shows `@<env-id>/<name>` as its title (screen 14), and a linked conversation shows `/Users/eltmon/.overdeck/conversation-…` as its title in the phone list (screen 29).
4. **The Preview popover ignores Escape** (screen 16).
5. **Copy.** The Anywhere section description is cut off at 1600 px (screen 01, "— Reach this machine f…"); Phone notifications says "No device receives notifications yet" next to "Overdeck app: 1 phone" (screen 35).

## Root causes (verified against `46234b961f4`)

### Bug 1 — count skips phones

`src/dashboard/server/routes/anywhere.ts`, line 116:

```ts
// A record with no kind is a device (PAN-2351 FR-10).
const active = records.filter((record) => (record.kind ?? 'device') === 'device' && !record.revokedAt).length;
```

The list route counts phones, the status route does not. `src/dashboard/server/routes/pairing.ts`, line 180 (list) and line 199 (revoke lookup):

```ts
return noStore(jsonResponse({ devices: records.filter((record) => record.kind === 'device' || record.kind === 'phone').map(deviceView) }));
...
const target = records.find((record) => record.id === id && (record.kind === 'device' || record.kind === 'phone'));
```

So a phone is listed but not counted. The two predicates also disagree on a record with no `kind`: the count includes it, the list leaves it out.

### Bug 2 — sentinel key rendered as text

`src/dashboard/frontend/src/App/AppChrome.tsx`, lines 175–181 (crumb) and line 192 (placeholder) print `selectedProjectKey` verbatim:

```tsx
{selectedProjectKey ? (
  <>
    <span className="h-3.5 w-3.5 rounded-[4px] bg-primary/40" aria-hidden="true" />
    {selectedProjectKey}
  </>
) : (
...
<span className="truncate">{selectedProjectKey ? `Search ${selectedProjectKey}…` : 'Search issues, conversations, commands…'}</span>
```

When the no-project deck is selected, `selectedProjectKey === '__no-project__'`.

### Bug 3a — linked rows fall back to their `@env/name` list name

`linkedListRow` copies the owner's title as-is (`src/lib/overdeck/linked-conversations-merge.ts`, line 83: `title: row.title,`). Every renderer then does `conv.title ?? conv.name` (for example `ConversationRow.tsx` lines 617 and 643; `MobileConversations.tsx` line 54 uses `c.title?.trim() || c.name`). A `null` title therefore shows `@<environmentId>/<name>`, and an empty-string title shows an empty line on the desktop list. A local conversation created without a message gets the title `New conversation` at creation (`src/lib/overdeck/conversation-runtime.ts`, line 1040), so local rows rarely hit this fallback.

### Bug 3b — the derived title keeps the attachment path

The composer sends `@<path>\n<text>` (`src/dashboard/frontend/src/components/chat/ComposerFooter.tsx`, lines 493–496):

```ts
const attachmentPrefix = uploadedAttachments
  .map((attachment) => `@${attachment.serverPath}`)
  .join('\n');
const composedMessage = [attachmentPrefix, composePromptWithCitations(messageText, citations)].filter(Boolean).join('\n');
```

`derivePromptTitle` (`src/lib/conversations/transcript-summary.ts`, lines 252–280) replaces every character outside `[\p{L}\p{N}#/_+.-]` with a space, so it drops the `@` and keeps the path, which becomes the first "word" of the title. Callers: `src/lib/overdeck/conversation-message.ts` line 665, `src/dashboard/server/routes/hooks.ts` line 635, `src/dashboard/server/routes/admin.ts` line 72, and `fallbackTranscriptTitle` in the same file (lines 228, 245). The title in screen 29 was derived this way on the MacBook (the owner) and reached the phone through the linked row.

### Bug 4 — no key handler

`src/dashboard/frontend/src/components/chat/OpenPreviewPopover.tsx` (151 lines) holds `open` in state and toggles it only from the Preview button (line 97). Nothing listens for Escape. The repo's pattern is `ContextWindowMeter.tsx` lines 61–78 (document `keydown` for Escape and `pointerdown` outside a wrapper ref, registered only while open).

### Bug 5a — description truncated by the header actions

`src/dashboard/frontend/src/components/Settings/primitives/SettingsSection.tsx`, lines 28–59: the header row is `flex items-center justify-between` with no wrap; the description span is `hidden @lg:inline truncate`, and the actions div is `shrink-0`. The Anywhere section has four action buttons, so the description loses the space and is cut with an ellipsis. The description text itself ("Reach this machine from your other devices", `AnywhereSection.tsx` line 53) is fine.

### Bug 5b — the empty state names the wrong kind of device

`src/dashboard/frontend/src/components/Settings/anywhere/PushPanel.tsx`, line 95: the empty state covers only web-push subscriptions (browsers), but says "No device receives notifications yet." The phone app has its own line (`nativeLine`, line 23–27: "Overdeck app: 1 phone").

## Requirements

## Decisions

- **D-1 (count predicate).** One exported predicate in `src/lib/access-tokens.ts`:
  `isPairedDeviceRecord(record) = (record.kind ?? 'device') === 'device' || record.kind === 'phone'`. All three sites use it. This honours the documented rule that a no-kind record is a device, so the list now also shows legacy no-kind records. The count keeps `!record.revokedAt`; paired devices and phones never carry `expiresAt`.
- **D-2 (count AC).** The panel lists revoked rows too, so the acceptance check is "count = active records of the list", never "count = list length".
- **D-3 (no-project placeholder).** "Search No project…" reads badly and search is not scoped to the deck, so the no-project deck uses the global placeholder `Search issues, conversations, commands…`. The crumb keeps its small colored square and reads `No project`.
- **D-4 (where to fix linked titles).** Fix once, on the server, in `linkedListRow`. The desktop list renders the merged rows; the Stage pane finds its conversation in that same list (`src/dashboard/frontend/src/components/Stage/index.tsx` line 317, `conversations.find((c) => c.name === pane.conversationId)`), so the panel header and machine banner get the fixed title too; the phone list reads `GET /api/conversations` and looks linked rows up with `findLinkedConversationRow` (`MobileConversations.tsx` line 73). No frontend renderer changes. `resource-discovery-shared.ts` line 88 also copies `record.row.title`, for issue-linked conversations in the project tree; it is left unchanged because the issue tree is not one of the reported screens (NonGoal).
- **D-5 (path test for linked titles).** A title "starts with an absolute file path" when it matches `^@?(?:~|[A-Za-z]:)?[\\/][^\s\\/]+[\\/]` — an optional `@`, an optional `~` or drive letter, then a separator, a path segment and a second separator. So `/Users/eltmon/.overdeck/conversation-…` and `C:\Users\x\…` match, while `/pan-flywheel start` (one separator) does not. Linked rows get this guard because the owner may still run a version without FR-5, and its stored titles do not change.
- **D-6 (derived title).** Remove every line whose trimmed text matches `^@(?:[A-Za-z]:)?[\\/]\S*$` before the existing compaction. If nothing is left, return `''`. Callers already skip the update on `''` (`if (derivedTitle)`), and the AI title generator still runs with the full prompt.
- **D-7 (Escape only).** The issue asks only for Escape. Add a document `keydown` listener, registered only while open, that sets `open` to false on `Escape`. Outside-click closing is not added (NonGoal). Closing never calls `stopForward`.
- **D-8 (header wrap).** Fix the shared primitive: the header row gets `flex-wrap gap-x-4 gap-y-2`, and the description span loses `truncate`. Where everything fits on one line, nothing changes; where it does not, the actions wrap below. The `hidden @lg:inline` container-width rule stays.
- **D-9 (copy).** `No browser receives notifications yet.` — the subscription list is web push, which is browsers only.
- **D-10 (screenshots).** One Playwright spec, `src/dashboard/frontend/tests/pan-5000-anywhere-display.spec.ts`, on the isolated dashboard, with `page.route` mocks. The linked rows in the `/api/conversations` mock are built by calling the real `mergeConversationRows` (import from `../../../lib/overdeck/linked-conversations-merge.js`, as `pan-2355-mobile.spec.ts` imports `src/lib`), so the screenshot shows the server function's real output. The spec is not added to the `test:playwright` CI script (it is evidence capture, and CI runs only listed specs). **Implementation checkpoint:** if the linked conversation panel (screens 15 and 16) does not render its title bar from REST mocks in the isolated dashboard, the agent captures the remaining screens, lists screens 15/16 in the PR body as "recapture after deploy", and relies on the component test for FR-6. Never add `test.skip`, `skipIf` or `.only` (the test-skip gate rejects them).

## Repo rules that apply

- **Quality gates** before `pan done`: `npm run typecheck`, `npm run lint`, and `npx vitest run <each touched test file>`. Never run the full `npm test` on the host. `npm run typecheck` skips `*.test.ts`, so a test file's types are only proven by running it.
- **New frontend test files** must be added to `scripts/frontend-test-subset.txt` (sorted, paths relative to `src/dashboard/frontend`), or CI never runs them.
- **No test may read source files** and no change may add `test.skip`, `skipIf` or `.only`; the lint and test-skip gates reject both.
- **Fake timers** are not needed: no item adds delay or retry logic.
- **Playwright specs never touch the operator's `:3011` dashboard** or its `OVERDECK_HOME`; use `startIsolatedDashboard`. Run `npm run build` before the spec.
- **Style guide** (`pan-style-guide`): no new colors, badges or font weights; WI-6 changes layout classes only.
- **Commits** use conventional-commit subjects and an `Item: <item-id>` trailer per xBRIEF item.
