# PAN-4905: "Add a Fly machine" names the wrong config file for `remote.enabled`

**Issue:** [PAN-4905](https://github.com/eltmon/overdeck/issues/4905)
**Status:** draft (planning, `pan plan --auto`)
**Base commit verified:** `678dcaf71b1` (feature/pan-4905, 2026-11-03)

## Glossary

- **config.toml** — `~/.overdeck/config.toml`, path constant `CONFIG_FILE` in
  `src/lib/paths.ts` (line 53: `export const CONFIG_FILE = join(CONFIG_DIR, 'config.toml');`).
  Loaded by `loadConfig()` / `loadConfigSync()` in `src/lib/config.ts`. It is the
  **only** home of `remote.enabled` (`[remote] enabled = true`).
- **config.yaml** — `~/.overdeck/config.yaml`, path from `getGlobalConfigPath()` in
  `src/lib/config-yaml/load.ts` (line 404). Its `remote:` section holds only
  `resiliency_tier` and `max_concurrent_agents` (schema `RemoteConfig` in
  `src/lib/config-yaml/schema.ts` ~line 114). Any other key there, including
  `enabled`, is silently ignored.
- **Remote** — the Fly.io remote subsystem gated by `remote.enabled`. When false,
  Fly machines, `pan start --remote`, and remote workspace creation all refuse.
- **`remote-disabled` refusal** — the first early refusal in `refuseEarly()` in
  `src/dashboard/server/services/fly-machine-service.ts` (line 177). It throws
  `FlyMachineError('remote-disabled', …)`, which `POST /api/machines/fly` returns as
  HTTP 409 `{ error: 'remote-disabled', message }` (status map in
  `src/lib/anywhere/fly/provision-shared.ts` line 31). Both the dashboard dialog and
  `pan machines add-fly` (`src/cli/commands/machines-fly.ts` line 97-100) print `message`.
- **Hint** — the one sentence fragment this issue introduces that names the exact
  file and key: ``add `enabled = true` under `[remote]` in ~/.overdeck/config.toml``.
- **Display path** — a filesystem path with the home directory prefix replaced by `~`
  (e.g. `/home/x/.overdeck/config.toml` → `~/.overdeck/config.toml`).
- **Turn on remote** — the new dashboard action that writes `enabled = true` into the
  `[remote]` table of config.toml, and nothing else.
- **MachinesResponse** — the `GET /api/machines` body, schema in
  `packages/contracts/src/machines.ts` line 205, built by `buildMachinesResponse()` in
  `src/dashboard/server/routes/machines.ts` line 99.

## Problem

Found while filming the Overdeck Anywhere video. Settings → Anywhere → Machines →
**Add a Fly machine** (and `pan machines add-fly`) refuses with:

```
Fly machines need remote.enabled: true in the Overdeck config.
```

"The Overdeck config" is ambiguous. `~/.overdeck/config.yaml` already has a `remote:`
section, so the operator sets `remote.enabled: true` there. It has no effect, because
`remote.enabled` is read only from config.toml (`loadConfig()` in `src/lib/config.ts`
lines 379-414 parses `CONFIG_FILE` and then overlays only `resiliency_tier` and
`max_concurrent_agents` from config.yaml). The same trap catches
`pan admin config set remote.enabled true`: `src/cli/commands/config-set.ts` writes the
key into config.yaml, validation passes (unknown keys are ignored), and it prints
"Set remote.enabled = true in …/config.yaml" while nothing changes.

The dialog also gives no warning before the click: it fails only after the operator
presses **Add**.

Eight sibling messages for the same condition name no file, and several name a CLI verb
that no longer exists (`pan remote setup`; the live verb is `pan admin remote setup`,
registered by `registerRemoteCommands(admin)` in `src/cli/commands/admin/index.ts` line 86). Those are split to follow-up [PAN-4908](https://github.com/eltmon/overdeck/issues/4908).

## Decisions (made here; recorded as autoDecisions)

- **D-1: config.toml stays the only home of `remote.enabled`.** We do not teach
  config.yaml to accept `enabled`. Reasons: every doc (`configuration/linked-machines.mdx`
  line 161, `docs/fly-provider.md` line 149), `pan admin remote setup`, and `doctor-fly`
  already treat config.toml as the home; a second home for a spend gate recreates the
  exact two-homes confusion this issue reports; and `src/lib/settings-api.ts` has only 5
  lines of headroom (1503 vs cap 1508) and `src/dashboard/server/routes/settings.ts` has 0
  (1104 vs cap 1104). Rejected alternative: "YAML `remote.enabled` overrides TOML" (option B).
- **D-2: Turn on remote ships, as a narrow targeted TOML edit.** It sets only
  `[remote] enabled = true`. It never calls `saveConfig()` (sync, and it rewrites the whole
  file from merged defaults, dropping comments) and never reuses `pan admin remote setup`'s
  block, which also writes `default_location: 'remote'` and would flip `pan start` routing
  (`src/cli/commands/start.ts` line 87).
- **D-3: Pre-click state comes from `GET /api/machines`.** `MachinesResponse.self` gains
  two optional fields, `remoteEnabled: boolean` and `remoteConfigFile: string` (display
  path). The Machines panel already polls this query every 5 s, and the dialog shares the
  React Query cache key, so there is no new read route.
- **D-4: The dialog stays openable when remote is off.** It opens, shows a "Remote is off"
  notice with the hint and a **Turn on remote** button, and disables **Add** until the
  machines query reports `remoteEnabled: true`. The panel button reads
  "Add a Fly machine (remote off)" while off.
- **D-5: When config.yaml contains `remote.enabled`, the refusal says so.** The
  `remote-disabled` message adds: "~/.overdeck/config.yaml sets remote.enabled, but that
  file does not hold this setting." This names the exact trap the operator fell into.
- **D-6: `pan admin config set remote.enabled <v>` refuses** with exit 1, writes nothing,
  and prints the hint. A silent no-op write is the bug.
- **D-7 (revised): Sibling messages move to follow-up [PAN-4908](https://github.com/eltmon/overdeck/issues/4908).**
  They are a separate bug (dead verb `pan remote setup`, no file named) and would push this
  plan to 31 files, over the 25-file finalize surface limit. See `## Follow-ups`.
- **D-8: No new CLI verb** (`pan admin remote enable`) — the CLI message names the exact
  file and line, which is what the issue asks; a new verb would also need a wrapper skill.
- **D-9: The write is atomic** (temp file + rename) via the existing
  `writeFileAtomic(path, text, mode)` exported from `src/lib/model-presets/state.ts`
  line 63, because a crash mid-write zeroes files on this machine class (PAN-2623).

### WI-1 — `remote-enabled` helper module (hint + yaml probe)

New file `src/lib/remote-enabled.ts`:

```ts
/**
 * `remote.enabled` lives only in config.toml `[remote]` (PAN-4905). config.yaml's
 * `remote:` section holds resiliency_tier and max_concurrent_agents only.
 */
import { readFile } from 'node:fs/promises';
import { homedir } from 'node:os';
import { parse } from 'yaml';
import { CONFIG_FILE } from './paths.js';
import { getGlobalConfigPath } from './config-yaml/load.js';

export function displayPath(path: string): string {
  const home = homedir();
  return path === home || path.startsWith(`${home}/`) ? `~${path.slice(home.length)}` : path;
}

/** "add `enabled = true` under `[remote]` in ~/.overdeck/config.toml" */
export function remoteEnabledHint(path: string = CONFIG_FILE): string {
  return `add \`enabled = true\` under \`[remote]\` in ${displayPath(path)}`;
}

/** True when the global config.yaml has a `remote.enabled` key (which nothing reads). */
export async function configYamlSetsRemoteEnabled(path: string = getGlobalConfigPath()): Promise<boolean> {
  let text: string;
  try { text = await readFile(path, 'utf8'); } catch { return false; }
  try {
    const doc = parse(text) as { remote?: unknown } | null;
    return typeof doc?.remote === 'object' && doc.remote !== null && Object.hasOwn(doc.remote, 'enabled');
  } catch { return false; }
}
```

Check `import { getGlobalConfigPath } from './config-yaml/load.js'` does not create an
import cycle (`npm run lint:circular` if present, else `npx madge --circular` is not
required — typecheck plus the module's own test importing it is the check). If it cycles,
inline `join(OVERDECK_HOME… )` is NOT allowed; instead accept the path as a required
parameter and let callers pass `getGlobalConfigPath()`.

Tests: `src/lib/__tests__/remote-enabled.test.ts` — `displayPath` with a home-prefixed

### WI-2 — `enableRemoteInConfigToml()` targeted writer

Add to `src/lib/remote-enabled.ts`:

```ts
export class RemoteEnableError extends Error {}

export async function enableRemoteInConfigToml(path: string = CONFIG_FILE): Promise<{ changed: boolean; path: string }>
```

Algorithm (decision rules, no judgment needed):

1. Read `path` (ENOENT → `''`).
2. Parse with `parse` from `@iarna/toml`. Parse failure → throw
   `RemoteEnableError(`${displayPath(path)} does not parse, so nothing was changed: ${message}`)`.
3. If `parsed.remote?.enabled === true` → return `{ changed: false, path }` (no write).
4. Split into lines. Find the first line matching `/^\s*\[\s*remote\s*\]\s*(#.*)?$/`.
   - Found: scan following lines until the next line matching `/^\s*\[/`. If a line in that
     range matches `/^\s*enabled\s*=/`, replace that whole line with `enabled = true`.
     Otherwise insert `enabled = true` immediately after the header line.
   - Not found: append (ensuring the text ends with `\n` first) `\n[remote]\nenabled = true\n`.
5. Parse the new text. If it fails, or `remote.enabled !== true`, throw
   `RemoteEnableError(`Could not turn on remote automatically: ${hint} by hand.`)` and write
   nothing. (This covers inline `remote = { … }` tables and dotted `remote.enabled = false`
   keys, which make the appended `[remote]` a duplicate definition.)
6. `await writeFileAtomic(path, newText, 0o644)` (import from `./model-presets/state.js`).
7. Return `{ changed: true, path }`.

Tests (same test file): missing file → creates `[remote]\nenabled = true\n`; `[remote]`
with `enabled = false # old` → line replaced, comment lines elsewhere preserved byte-for-byte;
`[remote]` without `enabled` but with `resiliency_tier = "durable"` → inserted after header,
tier kept; only `[remote.fly]` present → appended `[remote]` and `remote.fly.app` still parses;
already true → `changed: false` and file mtime/text unchanged; inline `remote = { enabled = false }`
→ throws `RemoteEnableError`, file unchanged; unparseable file → throws, unchanged.
