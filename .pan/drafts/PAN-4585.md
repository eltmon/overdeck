## Glossary

- **Semgrep CE** — the open-source Semgrep engine, LGPL-2.1. Overdeck may install it.
- **Registry rules** — rule packs such as `p/default` that the CLI downloads from
  semgrep.dev at scan time. They are under the Semgrep Rules License v1.0 (internal use,
  no redistribution, no "as a service"). Overdeck never bundles, caches for others, or
  serves them. Only the user's own CLI fetches them on the user's machine.
- **Managed install** — the Semgrep CLI that Overdeck installs into an Overdeck-owned
  directory: tool environment under `~/.overdeck/tools/semgrep/`, launcher symlink at
  `~/.overdeck/bin/semgrep`. It is separate from any Semgrep the user installed.
- **Pin** — `SEMGREP_VERSION`, the exact engine version the managed install provides
  (precedent: `RTK_VERSION = '0.41.0'` in `src/cli/commands/setup/hooks.ts`, line 23).
- **uv / pipx** — Python tool installers. `uv tool install` and `pipx install` each create
  an isolated virtualenv per tool. Overdeck points both at its own directories through
  `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR` and `PIPX_HOME`/`PIPX_BIN_DIR`.
- **Project layer** — the repo-committed `.pan.yaml` (or legacy `.overdeck.yaml`) that
  `src/lib/config-yaml/load.ts` merges over `~/.overdeck/config.yaml`. It is found from
  `process.cwd()` (`findProjectRoot()`), so it is whatever repo the current process runs in.
- **Global layer** — `~/.overdeck/config.yaml`, operator-owned.
- **Prereq registry** — `src/lib/prereqs/registry.ts`: the lazy "install this tool"
  backend behind `GET /api/prereqs/:feature` and `POST /api/prereqs/install`
  (`src/dashboard/server/routes/prereqs.ts`).
- **CheckResult** — a `pan doctor` row: `{ name, status: 'ok' | 'warn' | 'error', message, fix? }`.

## Requirements

  `security` key. The loader drops it from the project layer, the same way it drops
  `tts.daemonHost`/`tts.daemonPort` today. Reason: a work agent can commit a `.pan.yaml`
  to the branch it is working on; security settings must come only from operator-owned
  files.
- **NFR-1 Licensing** No registry rule file is committed to this repo or written to any
  shared or hosted location. Phase 1 runs no scan, so it downloads no rules.
- **NFR-2 Privacy** Every Semgrep invocation Overdeck makes sets
  `SEMGREP_ENABLE_VERSION_CHECK=0` (the version check is a network call to semgrep.dev,
  observed on 1.180.0 as "A new version of Semgrep is available") and
  `SEMGREP_SEND_METRICS=off`. Phase 1 invokes only `semgrep --version`.
- **NFR-3** Async only: the install module uses `execFile` (promisified) with a timeout.
  It is reachable from the dashboard server through the prereq registry, so no `execSync`.
- **NFR-4** One shared install per machine under `~/.overdeck/tools/semgrep/`, never per
  workspace.
- **NFR-5** The engine version is pinned to `1.180.0`.
- **NFR-6** Linux and macOS only. On Windows the installer returns `unsupported` and doctor
  warns.
- **NFR-7** (new) The managed install never touches the user's own Semgrep: it never runs
  `uv tool install` / `pipx install` against the user's default tool directories, never
  writes `~/.local/bin/semgrep`, and never `pip install`s into a system Python or uses sudo.

## Decisions (made in this document)

- **D1 Phase 1 = issue item 1 only.** Items 1–3 together are about 37 files (counted
  per file below and in #4590). The finalize lint cap is 25 files. Config/install/doctor
  separate cleanly from the gate along one dependency edge, so they ship first.
- **D2 Phase 1 config is `enabled` only.** `gate`, `severity`, `configs`,
  `timeout_seconds` have no consumer until #4590, and documenting a `gate:` key that does
  nothing would mislead users. #4590 adds them to the same module. Unknown keys inside
  `security.semgrep` are ignored, not rejected, so a config written for a later phase does
  not break phase 1.
- **D3 Bad values throw at config load**, like `jev:` and `ollama:` do
  (`normalizeJevConfig` in `src/lib/config-yaml/jev.ts`). `security` and
  `security.semgrep` must be mappings; `enabled` must be a boolean.
- **D4 The project layer cannot set `security`** (FR-11). Per-project overrides arrive in
  #4590 through `projects.yaml` `verification.sast`, which lives in `~/.overdeck/` and is
  operator-owned.
- **D5 Pin `1.180.0`**, published 2026-10-07 (17 days before planning). PyPI latest is
  1.182.1 (2026-10-22). Pinning a release at least two weeks old is supply-chain hygiene,
  and 1.180.0 is the version every probe in this PRD ran against.
- **D6 Installer order: uv, then pipx, then fail with a fix message.** No Homebrew (its
  formula floats and cannot be pinned), no system pip, no sudo.
- **D7 Isolated tool directories.** uv: `UV_TOOL_DIR=~/.overdeck/tools/semgrep/uv`,
  `UV_TOOL_BIN_DIR=~/.overdeck/tools/semgrep/bin`. pipx:
  `PIPX_HOME=~/.overdeck/tools/semgrep/pipx`, `PIPX_BIN_DIR=~/.overdeck/tools/semgrep/bin`.
  Then `~/.overdeck/bin/semgrep` is a symlink to `~/.overdeck/tools/semgrep/bin/semgrep`.
  Verified 2026-10-24: `UV_TOOL_DIR=… UV_TOOL_BIN_DIR=… uv tool install --force semgrep==1.180.0`
  exits 0, creates `bin/semgrep` and `bin/pysemgrep` symlinks, and `bin/semgrep --version`
  prints exactly `1.180.0`. The tool env is about 334 MB.
- **D8 Version check = trimmed stdout of `semgrep --version` equals `SEMGREP_VERSION`.**
  1.180.0 prints the bare version (`1.180.0`) on stdout when
  `SEMGREP_ENABLE_VERSION_CHECK=0` is set.
- **D9 The dashboard prereq install refuses while disabled.** `installTool('semgrep')`
  returns `success: false` with the message
  `Semgrep support is off (security.semgrep.enabled: false in ~/.overdeck/config.yaml)`
  when the flag is off. This enforces FR-1 for the only path that installs without a CLI.
- **D10 `semgrep` is NOT added to `PREREQUISITES` in `src/lib/system-prerequisites.ts`.**
  That list renders the setup checklist banner for every user regardless of config, which
  would violate FR-1.
- **D11 Doctor rows:** disabled → no rows. Enabled →
  `Semgrep` row (ok on pin match, warn on version mismatch, error when missing, warn on
  Windows) and `Semgrep registry` row (ok when `HEAD https://semgrep.dev/c/p/default`
  answers 2xx/3xx within 5 s, warn otherwise). Registry is warn-only: no scan runs in
  phase 1, and scans in #4590 skip rather than fail when the registry is unreachable.
- **D12 Settings autosave keeps `security:`.** `writeYamlConfigPreservingComments`
  (`src/lib/settings-api.ts`, line 771) parses the existing file with `parseDocument` and
  writes only the sections it names (`topLevelSections` list starting near line 816), so a
  hand-written top-level `security:` block survives a Settings save. No `settings-api.ts`
  change is needed in phase 1; #4594 must write `security.semgrep` through a path-scoped
  edit (the `src/lib/jev/settings.ts` pattern).
- **D13 Concurrent installs are not locked.** `pan sync` and a dashboard install racing
  both run `uv tool install --force` into the same directory. uv's own lock serializes
  them; the second run reinstalls the same pin. Accepted for phase 1.

## Repo rules that apply to this work (restated)

- **No `execSync` in dashboard-reachable code.** `src/lib/semgrep/install.ts` and
  `src/lib/prereqs/registry.ts` are reachable from the server. Use
  `promisify(execFile)` with an explicit `timeout`. `src/cli/commands/doctor.ts`'s
  `checkCommand` is `execSync`-based and CLI-only — do not import it into `src/lib/`.

  test the timeout branch with `vi.useFakeTimers()` + `await vi.advanceTimersByTimeAsync(5_000)`,
  never a real wait. Use `AbortController` + `setTimeout`, not `AbortSignal.timeout`
  (it ignores fake timers in happy-dom).
- **File-size ratchet** (`scripts/lint-file-size.sh`, last allowlist row wins):
  `src/lib/config-yaml/schema.ts` 1082/1114, `src/lib/config-yaml/merge.ts` 995/1045,
  `src/cli/commands/doctor.ts` 1015/1042. Every change below adds at most 3 lines to each.
  Never raise an allowlist row.

  `execFile`, `fetch`, platform and paths through a deps object. Do not add
  `skipIf`/`.only` tests — the test-skip gate fails them.
- **Never put a shell variable in an `rm` target** (and never `rm` in code — use

- **Conventional commits**, lower-case subject, ≤100 chars, `Item: <item-id>` trailer per

  `npx vitest run <touched test files>`. Never the full `npm test` on the host.

   ```ts
   /** Raw `security:` block as it appears in config.yaml (PAN-4585). */
   export interface YamlSecurityConfig {
     semgrep?: YamlSemgrepConfig;
   }

   /** Raw `security.semgrep:` block. Phase 1 reads only `enabled`; later keys are ignored. */
   export interface YamlSemgrepConfig {
     enabled?: boolean;
   }

   export interface NormalizedSemgrepConfig {
     enabled: boolean;
   }

   export interface NormalizedSecurityConfig {
     semgrep: NormalizedSemgrepConfig;
   }

   export const DEFAULT_NORMALIZED_SECURITY: NormalizedSecurityConfig = {
     semgrep: { enabled: false },
   };

   /**
    * Fold one config layer's `security:` block onto the value merged so far. Off by
    * default; a bad value throws at config load, like `jev:` does. Unknown keys under
    * `security.semgrep` are ignored so a config written for a later phase still loads.
    */
   export function normalizeSecurityConfig(
     raw: YamlSecurityConfig | null | undefined,
     current: NormalizedSecurityConfig,
   ): NormalizedSecurityConfig {
     if (raw === null || raw === undefined) return current;
     if (typeof raw !== 'object' || Array.isArray(raw)) {
       throw new Error('config.yaml: security must be a mapping');
     }
     const semgrep = raw.semgrep;
     if (semgrep === null || semgrep === undefined) return current;
     if (typeof semgrep !== 'object' || Array.isArray(semgrep)) {
       throw new Error('config.yaml: security.semgrep must be a mapping');
     }
     const merged: NormalizedSemgrepConfig = { ...current.semgrep };
     if (semgrep.enabled !== undefined) {
       if (typeof semgrep.enabled !== 'boolean') {
         throw new Error(`config.yaml: security.semgrep.enabled must be true or false (got: ${String(semgrep.enabled)})`);
       }
       merged.enabled = semgrep.enabled;
     }
     return { ...current, semgrep: merged };
   }
   ```

**Files:** `src/lib/semgrep/install.ts` (new), `src/lib/semgrep/__tests__/install.test.ts` (new).

```ts

/** Env every Overdeck-run Semgrep process gets (NFR-2). */
export const SEMGREP_QUIET_ENV = { SEMGREP_ENABLE_VERSION_CHECK: '0', SEMGREP_SEND_METRICS: 'off' } as const;

/** `~/.overdeck/bin/semgrep` — the only path Overdeck ever runs Semgrep from. */

export function semgrepToolsDir(home = getOverdeckHome()): string; // join(home, 'tools', 'semgrep')

/** Trimmed stdout of `<binary> --version`, or null when it cannot run (missing, not executable, timeout). */
export async function readSemgrepVersion(binary: string, deps?: Pick<SemgrepInstallDeps, 'execFile'>): Promise<string | null>;

export type SemgrepInstallStatus = 'present' | 'installed' | 'failed' | 'unsupported';
export interface SemgrepInstallOutcome {
  status: SemgrepInstallStatus;
  /** Version the managed binary reports after the call; null when none runs. */
  version: string | null;
  installer?: 'uv' | 'pipx';
  message: string;
  fix?: string;

export interface SemgrepInstallDeps {

  platform?: NodeJS.Platform;          // default process.platform
  execFile?: (file: string, args: string[], opts: { env: NodeJS.ProcessEnv; timeout: number }) => Promise<{ stdout: string; stderr: string }>;
  /** What occupies the launcher path; default lstat + readlink (see step 3). */
  inspectLauncher?: (linkPath: string) => Promise<LauncherOccupant>;
  /** Point the launcher at the managed target; default unlink-if-present + fs.promises.symlink. */

export type LauncherOccupant = 'absent' | 'managed' | 'foreign';

export async function ensureSemgrepInstalled(deps?: SemgrepInstallDeps): Promise<SemgrepInstallOutcome>;

/** One spinner line for the two CLI callers (sync, install). */
export function formatSemgrepInstallOutcome(outcome: SemgrepInstallOutcome): { level: 'succeed' | 'info' | 'warn'; text: string };
```

`ensureSemgrepInstalled` steps, in order:

1. `platform === 'win32'` → `{ status: 'unsupported', version: null, message: 'Semgrep support is Linux and macOS only (Windows is unsupported)' }`.
2. `current = await readSemgrepVersion(managedSemgrepPath(home), deps)`. If
   `current === SEMGREP_VERSION` → `{ status: 'present', version: current, message: \`Semgrep ${SEMGREP_VERSION} already installed\` }`. No installer runs.
3. Launcher ownership: `occupant = await inspectLauncher(managedSemgrepPath(home))`. The
   default implementation calls `fs.promises.lstat`; `ENOENT` → `absent`; a symlink whose
   `fs.promises.readlink` equals `join(tools, 'bin', 'semgrep')` → `managed`; a regular
   file, a directory, or a symlink pointing anywhere else → `foreign`. `foreign` →
   `{ status: 'failed', version: current, message: '~/.overdeck/bin/semgrep exists and is not the Overdeck-managed launcher', fix: 'Move ~/.overdeck/bin/semgrep out of the way, then run pan sync' }`
   and stop before any installer runs. The installer never deletes or replaces a file it
   did not create (NFR-7).
4. Pick the installer: run `uv --version` (timeout 10 s); on success use uv. Otherwise run
   `pipx --version`; on success use pipx. If both fail →
   `{ status: 'failed', version: current, message: 'Neither uv nor pipx is installed', fix: 'Install uv (https://docs.astral.sh/uv/getting-started/installation/) or pipx, then run pan sync' }`.
5. Run the install with `timeout: 600_000` and env `{ ...process.env, ...SEMGREP_QUIET_ENV, <dirs> }`:
   - uv: `execFile('uv', ['tool', 'install', '--force', \`semgrep==${SEMGREP_VERSION}\`], { env: { …, UV_TOOL_DIR: join(tools, 'uv'), UV_TOOL_BIN_DIR: join(tools, 'bin') } })`
   - pipx: `execFile('pipx', ['install', '--force', \`semgrep==${SEMGREP_VERSION}\`], { env: { …, PIPX_HOME: join(tools, 'pipx'), PIPX_BIN_DIR: join(tools, 'bin') } })`
   A thrown error → `{ status: 'failed', installer, message: \`${installer} install of semgrep==${SEMGREP_VERSION} failed: <first line of error message>\`, fix: 'Run pan sync again; see the installer output above' }`.
6. `mkdir -p ~/.overdeck/bin`, then `linkLauncher(join(tools, 'bin', 'semgrep'), managedSemgrepPath(home))`.
   The default `linkLauncher` calls `fs.promises.unlink(linkPath)` ignoring `ENOENT`, then
   `fs.promises.symlink(target, linkPath)`. Step 3 guarantees the path is `absent` or
   `managed` here.
7. `after = await readSemgrepVersion(managedSemgrepPath(home), deps)`. `after === SEMGREP_VERSION`
   → `{ status: 'installed', version: after, installer, message: \`Installed Semgrep ${SEMGREP_VERSION} to ~/.overdeck/bin/semgrep (via ${installer})\` }`;
   otherwise `{ status: 'failed', version: after, installer, message: \`semgrep --version returned ${after ?? 'no output'} after install\` }`.

`readSemgrepVersion` runs `(deps?.execFile ?? defaultExecFile)(binary, ['--version'], { env: { ...process.env, ...SEMGREP_QUIET_ENV }, timeout: 30_000 })`
and returns `stdout.trim()` (last non-empty line), or `null` on any error. Every call
inside `ensureSemgrepInstalled` passes its `deps`, so tests control both version checks.

`formatSemgrepInstallOutcome`: `present` → `info`; `installed` → `succeed`; `failed` →
`warn` with `message` plus ` — ${fix}` when set; `unsupported` → `warn`.

## Phase 2 design: the sast verification gate (handed to #4590 — NOT a work item of this plan)

Research preserved for #4590's planner. Probes ran on 2026-10-24 against Semgrep 1.180.0
(`uvx --from semgrep==1.180.0 semgrep`) in a throwaway git repo.

**Exit codes.** `semgrep scan --config p/default --json --metrics off --error <targets>`
exits `1` when there are findings and `0` when clean. With the registry unreachable
(HTTPS proxy to a closed port) it exits `2` with a `requests.exceptions.ProxyError`
traceback. Treat 0/1 as "scan completed", anything else as a scanner error → gate
skipped with a visible warning.

**JSON shape.** Top-level keys: `version, results, errors, paths, time,
engine_requested, skipped_rules, profiling_results`. Each result has `check_id`, `path`,
`start{line,col,offset}`, `end{…}`, `extra{message, fix?, metadata, severity,
fingerprint, lines, validation_state, engine_kind}`. `extra.lines` is the literal
string `requires login` without a Semgrep login, so never rely on it for the snippet.
Registry rules reported severities `ERROR` and `WARNING`. Map any newer
`CRITICAL`/`HIGH` → `ERROR`, `MEDIUM` → `WARNING`, `LOW` → `INFO`, unknown → `WARNING`,
and filter by threshold in Overdeck code rather than with `--severity`.

**Do not use `--baseline-commit`.** The issue text says baseline mode aborts on a dirty
tree; on 1.180.0 it does not (untracked file and unstaged edit both scanned, exit 1).
But `strace -f -e trace=execve` shows baseline mode runs
`git worktree add --no-checkout /tmp/tmpXXXX <sha>`, `git checkout <sha>` and
`git update-ref HEAD` inside that worktree, and `git worktree remove` at the end. In
Overdeck every workspace is a worktree of the shared primary `.git`, and eleven modules
list worktrees (`src/lib/hygiene.ts`, `src/lib/worktree.ts`,
`src/lib/cloister/deacon-swarm-gc.ts`, `deacon-swarm-orphan-gc.ts`,
`strike-workspace-reaper.ts`, `strike-completion.ts`,
`src/lib/workspaces/worker-worktrees.ts`, `src/lib/overdeck/workspace-hygiene.ts`,
`src/lib/vault/wip-apply.ts`, `src/cli/commands/swarm.ts`, `strike.ts`). A scan killed
by a timeout leaves the `/tmp` worktree registered. Explicit file targets touch no git
state: the same strace for `semgrep scan … app.py` shows only `git remote get-url origin`
and `git ls-remote --get-url`.

**Diff scope.** After the runner's sync step, `mb = git merge-base origin/<target> HEAD`.
Targets = `git diff --name-only --diff-filter=AMR <mb>` (working tree vs merge-base,
existing files only). Keep a finding only when its `[start.line, end.line]` overlaps an
added range from `git diff -U0 --diff-filter=AMR <mb>` for that path. Use the working
tree diff, not `<mb>...HEAD`, so line numbers match the contents Semgrep scanned on a
dirty tree. Accepted trade: a finding whose match lies on unchanged lines but was caused
by the change (a deleted sanitizer) is missed; the security review lane covers that.
Untracked new files are not scanned (review judges committed HEAD anyway).

**Capped files.** `src/lib/cloister/verification-runner.ts` is at 961/961. Extract
`SyncResult`, `syncSingleRepo`, `buildSyncFailureFeedback`, and `getSyncTargetBranch`
(lines 71–80 and 112–211; none is imported by a test) into
`src/lib/cloister/verification-sync.ts` first. `src/lib/projects.ts` is at 1217/1217, so
the per-project override goes on `ProjectVerificationConfig` in
`src/lib/workspace-config.ts` (`verification.sast`), which has no cap.

**Shape.** `sast-gate.ts` (pure: argv builder, exit mapping, JSON parse, severity and
hunk filters, `nosemgrep` / `.semgrepignore` / local-rule-path change detection from the
`-U0` diff, output formatting) and `sast-run.ts` (per repo root from
`resolveWorkspaceRepoRoots`, `acquireQualityGateAdmission({ gateName: 'sast' })` with
`release()` in `finally`, `OVERDECK_GATE_ADMITTED=1` and `SEMGREP_QUIET_ENV` in the
child env, strip `SEMGREP_APP_TOKEN` and `SEMGREP_RULES`, write
`<workspace>/.overdeck/sast-latest.json` keyed by per-repo head). The runner appends one
`QualityGateResult` named `sast`: `required: true` in `blocking`, `required: false` in
`advisory`; skipped → `passed: true, required: false` plus a new `skipped?: boolean`
field on `QualityGateResult` (`src/lib/cloister/validation.ts`) and
`VerificationGateRecord` (`verification-artifact.ts`). The review context reuses
`sast-latest.json` when the head matches and otherwise records a `stale`/`absent` status
rather than scanning again in the review path.

### Disabled Semgrep remains registered

Accepted in part. The design now starts no process while disabled:
`isToolInstalled('semgrep')` returns `false` before any probe when
`security.semgrep.enabled` is false (WI-5 step 3), so `GET /api/prereqs/useSemgrep`
cannot run the binary, and `installTool('semgrep')` already refuses. FR-1 is reworded to
say what "registers" means: nothing is registered into an agent, session, or harness,
and the static catalog entries (`useSemgrep`, `semgrep` in `INSTALLABLE_TOOLS`) remain
as data that `GET /api/prereqs` lists. Filtering the two GET responses by config would
add `src/dashboard/server/routes/prereqs.ts` and a dashboard route test to the plan,
which takes it to 7 subsystems and past the finalize size limit, for a listing that
executes nothing. #4594 (dashboard) decides whether the UI hides the entry while off.
The disabled-state behavior is tested at the registry level (WI-5 tests).

### Installer overwrites an unowned launcher

Accepted. `ensureSemgrepInstalled` gains a launcher ownership step (WI-3 step 3) before
any installer runs: `lstat` + `readlink`; only an absent path or a symlink to the
managed target `~/.overdeck/tools/semgrep/bin/semgrep` may be replaced. A regular file,
a directory, or a symlink elsewhere returns `failed` with a "move it out of the way"
fix and is left untouched. Tests cover a regular file, a foreign symlink, and the managed
symlink. The hook manifest in `src/lib/sync-hooks.ts` is not reused: it tracks hook
scripts that sync copies, and the readlink check is a complete ownership test for a
single symlink.

### Injected command runner is bypassed for version checks

Accepted. `readSemgrepVersion(binary, deps?)` takes the `execFile` dep, both calls
inside `ensureSemgrepInstalled` (steps 2 and 7) pass `deps`, and the test fake throws on
any unscripted call, so no test can start a real process.
