## 2. Problem and goal

PAN-4820 shipped the per-issue Deft pipeline as library and CLI code. The dashboard shows nothing of Deft's own state, and the operator must use the CLI to switch an issue. This issue makes Deft's state visible on the dashboard surfaces the operator already uses, answers Deft's questions from Needs-you and the question dialog, adds a view of Deft's review cycle, and adds **Run on Deft** / **Back to Overdeck** to the issue menu.

Operator decision AD-22 (issue comment, 2026-11-02) binds the wording: the dashboard shows Deft's own steps using Deft's own names, the way it shows Overdeck's own review and checks. It adds no Overdeck reviewer, check, or instruction to a Deft issue.

### 3.3 Deft review cycle (read from Directive source)

- **No per-round state on disk.** The skill is instructions. The only per-PR files are overwrite-in-place (`pr:watch` heartbeat, CLEAN record). No round counter exists (`packages/core/src/pr-watch/main.ts:548-554`, `review-monitor/verify.ts:78-84`).
- **`.deft/review-monitor.json` is obsolete.** `writeReviewMonitorFile` is "intentionally no-op" (`packages/core/src/review-monitor/record.ts:690-692`); SKILL.md:693 says the file "is obsolete and ignored". The lease is the sticky PR comment `<!-- deft:review-owner -->` (`review-monitor/lease-comment.ts:28-36`, field regex `^(kind|owner|monitor_agent_id|agent_id|pass_kind|ceiling|head_sha|started_at|expires_at|platform_primitive|ended_at):\s*(.*)$`). A lease expires at `started_at + 30 min` (`DEFAULT_STALE_MINUTES = 30`) and is inactive when `head_sha` differs from the PR head or `ended_at` is set.
- **Greptile edits one rolling summary comment in place** (SKILL.md:851-858). Inline findings arrive as PR review comments (`pulls/<n>/comments`).
- **Exit predicate** (SKILL.md:880-897), all on one fetch, else `unknown`:
  1. The Greptile check run is `completed` with conclusion `success` or `neutral`.
  2. The PR head SHA is read at check time.
  3. `Last reviewed commit:` in the rolling summary equals the head. Regex: `Last reviewed commit:\s*\[.*?\]\(https?://github\.com/[^/]+/[^/]+/commit/([0-9a-f]{7,40})`.
  4. Confidence ≥ the floor: `policy.review.minGreptileConfidence` (integer 1-5) when set, else 4 (`packages/core/src/policy/min-greptile-confidence.ts:16,25`).
  5. Zero P0 and P1.
- **Verdict names** (`pr-watch/constants.ts:20-67`) include `CLEAN`, `NEW_P0_P1`, `PENDING`, `NO_REVIEWER_INSTALLED`, `ERRORED`, `STALL`, `TIMEOUT`, `MERGED`, `CLOSED_UNMERGED`.
- **Severity parsing** (`packages/core/src/content-contracts/skills/greptile-detector.ts`): badges `<img alt="P0"` / `<img alt="P1"` (line 271-272); `TIER2_RE = /^[\s\-*]*\*\*P([01])\b[^*]*\*\*/gm`; `TIER25_RE = /^#{1,6}\s+P([01])\s*[·‧•-]\s/gm`; confidence `/Confidence Score:\s*(\d+)\s*\/\s*5/`. Code fences are stripped first. Severity labels are `P0`, `P1`, `P2`; only P0/P1 block (`content/coding/review.md:34-38`). This plan also counts `<img alt="P2"`.
- **Reviewer presence** (`pr-merge-readiness/reviewer-presence.ts:94-143`), in order: policy `review.reviewers` (an empty list means no reviewer); a Greptile review comment; a bot review check run (name matches greptile, slizard, or coderabbit); a config file `greptile.json` or `.greptile/config.json` at the repo root. Only Greptile can end the cycle; SLizard is advisory, CodeRabbit is a future adapter.
- **Heartbeats** that matter here: `pr-watch-<pr>-<pid>.json` (`phase` `polling|starting|terminal`), and agent-written heartbeats with `phase` `polling|fixing` and on exit `terminal_state` one of `CLEAN`, `NEW P0/P1`, `ERRORED`, `TIMEOUT`, `STALL`, `NO_REVIEWER_INSTALLED`.
- **CLEAN record** `.deft-scratch/merge-path-arm/pr-<N>.clean.json` = `{ pr_number, head_sha, cleaned_at, source: "pr:watch" }`. A missing file does not mean not-CLEAN.
- **Finish loop** lines carry `phase` `pr-watch|address`, `message` `"pr:watch verdict=<V>"`; written only by `pr:finish-loop`.

## 5. Requirements

Requirement ids FR-13 to FR-17 continue the PAN-4820 numbering (retired there, moved here). New ids start at FR-18.

### Functional

- **FR-13** `GET /api/issues/:id/deft` returns the issue's Directive state parsed from its worktree: scopes, escalations, heartbeats, decisions, approved scopes, policy, spec drift, install drift, lift conflicts, finish loop, gate runs, and review-cycle file inputs. `GET /api/deft/issues` returns one summary row per Deft issue. The reader uses `fs/promises` only and runs no child process.

## 12. Implementation notes (deviations found in operator review of #4879)

- **External escalations are not pending input.** FR-14, WI-4 and WI-19 put an open `external` escalation into `pendingInputKinds` as `deftExternal`. That made `pendingInputCount > 0`, so the enrichment service fired the awaiting-input rising edge (a warn activity entry and a priority-1 TTS line), re-emitted it on every idle poll, and the frontend's `isAwaitingInput` showed the agent as waiting. Deft's contract for `external` is "dashboard indicator, no interrupt". The shipped design carries the count in its own enrichment field, `deftExternalEscalations` (on `AgentEnrichment`, the `agent.enrichment_changed` payload and `AgentSnapshot`), and Needs-you renders it as a quiet line per agent ("PAN-1 · Deft: waiting on external (n)") that is not a decision and not in the count. There is no `deftExternal` pending-input kind.
