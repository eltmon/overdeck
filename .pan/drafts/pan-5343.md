## 1. Glossary

- **Deck** — the Stage's tabs, panes and split layout for one key (`deckKey`). Before this change the key is always a project key or `NO_PROJECT_KEY` (`'__no-project__'`, `FE/components/CommandDeck/projectsData.ts` line 14). Panes are stored in `usePanesStore` under `panesByWorkspace[deckKey]` (localStorage `pan-panes:<key>`, `pan-active-pane:<key>`). The split layout is stored in localStorage `pan-layout:<key>`.
- **All projects deck** — a new deck with the key `ALL_PROJECTS_KEY = '__all-projects__'`. Its panes may be conversations from any project. It has no Home pane.
- **Real project key** — a deck key that names a registered project: not null, not `NO_PROJECT_KEY`, not `ALL_PROJECTS_KEY`. Tested by the new `isRealProjectKey` (H-D17).
- **Agent pane** — a pane with `paneType: 'agent'` and `conversationId: <conversation name>` (`FE/lib/panesStore.ts` lines 19–80). It renders `AgentPane` → `ConversationPanel`, and each one has its own composer.
- **Layout** — a binary tree of leaves and splits (`FE/lib/paneLayout.ts` lines 11–13). A `null` layout or a single leaf means "no split": the Stage shows only the active pane. Split ratios clamp to 0.15–0.85 in `updateRatio` (line 97).
- **Leaf / visible pane** — a pane whose id is a leaf of the deck's layout. With a null layout, the only visible pane is the active pane.
- **Focused pane** — the deck's active pane (`activePaneByWorkspace[deckKey]`). With more than one leaf, `PaneLayoutView` highlights its split header (`splitHeaderFocused`, `FE/components/Stage/PaneLayoutView.tsx` line 107).
- **Focus history** — a session-only, most-recent-first list of pane ids per deck, kept in the new deck layout store (H-D14). It is not persisted.
- **Open beside** — show a conversation in a new leaf next to the panes already on screen, without hiding them.
- **Preset** — one of the four equal layouts: One, Two side by side, Three columns, Grid of four (H-D7).
- **Deck layout store** — the new zustand store `FE/lib/deckLayoutStore.ts` that owns each deck's layout and focus history (H-D14).

## 3. Decisions

- **H-D1 One new deck key.** Add a leaf module `FE/lib/deckKeys.ts` with no imports:
  ```ts
  export const ALL_PROJECTS_KEY = '__all-projects__';
  export const ALL_PROJECTS_LABEL = 'All projects';
  ```
  `projectsData.ts` re-exports both next to `NO_PROJECT_KEY`. (A leaf module lets `panesStore.ts` import the key without importing `projectsData.ts`, which pulls in `wsTransport`; that keeps `lint:circular` clean.) `isKnownProject` and `isKnownProjectKey` accept `ALL_PROJECTS_KEY`. The URL is `/command-deck/__all-projects__`, built by the existing route code with no special case.
- **H-D2 Two doors, one state.** The project switcher gets an **All projects** item as its first menu item, with a `✱` mark (`ProjectMark` gains a `glyph?: string` prop; muted background, the glyph instead of initials) and the subtitle `<N> projects · <M> active`, where N is the number of projects the switcher lists and M is the number of conversations in the `['conversations']` query with `sessionAlive === true`. When the All deck is selected, the closed button shows the same mark, `All projects`, and that subtitle in place of the path. The Conversations section gets a **This project / All projects** segmented switch on its own row under its header, as in the mockup. Both doors call `selectProject` (`useDeckNavigation`). "This project" selects `readLastProjectKey()`, else the first project the switcher lists, else `NO_PROJECT_KEY`.
- **H-D3 The All projects list.** With `ALL_PROJECTS_KEY` selected, `ConversationsSection` passes no `includeIds` and passes `groupByProject`. The `Active / All N` switch still applies; its count N is the full conversation count. Render order:
  1. the **Needs you** section, unchanged, each row prefixed by its project's `<ProjectMark size="sm">`;
  2. the Inbox rows, grouped by project: one non-collapsible header per project with the mark, the project name and, right-aligned, `N working` (count of rows with `isWorking === true`) or `idle`. Projects sort by name, case-insensitive; conversations under no registered project come last under `No project`;
  3. Snoozed and Settled (shown with the All filter), with today's collapsible headers, each row prefixed by its project mark.
  Rows keep today's row menu, meta line and handoff tree; a handoff tree groups under its root conversation's project. The Shift+click range order follows this grouped render order.
- **H-D4 What hides in All projects mode:** the **Project home** nav item, the Issues and Workspaces sections, the deck's Home tab, and the "Changes in <project>" new-pane action. The top-bar crumb reads `All projects / <active pane label>` with 0 or 1 leaf, and `All projects / N conversations side by side` with N ≥ 2 leaves.
- **H-D5 Click semantics.**
  - **Plain click:** in the All deck, show the conversation in the focused leaf (H-D6 `showConversation`). In a project deck, keep today's behavior (`openConversationTab`).
  - **Ctrl+Click** (Cmd+Click on macOS), the row's hover **Beside** button, and the row menu's new **Open beside** item: open beside (H-D6 `openConversationBeside`), in the selected deck. In project mode the list shows only that project's conversations, so the conversation always belongs to the deck.
  - **Open in its project** (new row-menu item, from the mockup): today's `useOpenConversation(null)` path — switch to the conversation's own project deck.
  - **Multi-select** moves off Ctrl/Meta: Shift+click keeps the range and toggle behavior, and the bulk bar keeps working. `handleRowClick` calls the new `onOpenBeside(name)` prop on `e.metaKey || e.ctrlKey` when the prop is given, and keeps today's toggle when it is not. The Settle box is unchanged.
- **H-D6 The two openers.** New file `FE/components/Stage/openConversationInDeck.ts`. Both functions work on the stores through `getState()`, so the left column can call them from any route. Neither is on `StageDeckContext`.
  - `showConversation(deckKey, name, label): string` — `ensureHome(deckKey)`; read `layout = getLayout(deckKey)` and the active pane id **before** adding a pane. If the conversation's agent pane is a visible leaf, focus it. Otherwise find or add its agent pane; when the layout has ≥2 leaves, `setLayout(replaceLeaf(layout, focus, paneId))` where `focus` is the active id if it is a leaf, else the first leaf. The replaced pane stays open as a tab. Then `setActivePane` and `noteFocus`. Returns the pane id.
  - `openConversationBeside(deckKey, name, label): string` — `visible` = the layout's leaves, or `[activeId]` with a null layout and an active pane, or `[]`. If the conversation is already visible, focus it. Otherwise find or add its agent pane, then:
    - `visible.length === 0` → nothing more (the pane is active and alone);
    - `1 ≤ visible.length ≤ 3` → `setLayout(presetLayout([...visible, paneId], visible.length + 1))`, an equal grid;
    - `visible.length === 4` → replace the least recently focused visible leaf other than the active one (oldest index in focus history; a leaf never in the history counts as oldest; ties go to the later leaf in leaf order) with `replaceLeaf`, keeping the 2×2 shape. The replaced pane stays a tab.
    Then `setActivePane(paneId)` and `noteFocus`. The same rule applies in project decks.
- **H-D7 Layout presets.** Add to `paneLayout.ts`:
  - `presetLayout(paneIds: readonly string[], preset: 1 | 2 | 3 | 4): PaneLayout` — uses the first `preset` ids and throws `Error('presetLayout needs N panes')` when fewer are given:
    - 1 → `leaf(a)`;
    - 2 → `{ kind: 'split', dir: 'row', a: leaf(a), b: leaf(b), ratio: 0.5 }`;
    - 3 → `{ kind: 'split', dir: 'row', a: leaf(a), b: { split row, leaf(b), leaf(c), 0.5 }, ratio: 1/3 }`;
    - 4 → `{ kind: 'split', dir: 'col', a: { split row a, b, 0.5 }, b: { split row c, d, 0.5 }, ratio: 0.5 }`.
  - `presetOf(layout: PaneLayout | null): 1 | 2 | 3 | 4 | null` — `null` layout or a leaf → 1; otherwise the preset n whose tree has the same `kind`/`dir` nesting as `layout` (ratios ignored) with n = `leafCount(layout)`, else `null`.
  The **Layout** bar (`FE/components/Stage/LayoutPresetBar.tsx`) shows four buttons at the right end of the tab strip, in the All deck only, with the mockup's SVG icons and titles: `One`, `Two side by side`, `Three columns`, `Grid of four`, each `aria-pressed`. **Candidates** are agent panes only: the visible agent leaves in leaf order, then the other agent panes by focus history (most recent first), then the rest in tab order (this is the order after a reload, when the history is empty). Button n is disabled when there are fewer than n candidates. Pressing n calls `setLayout(n === 1 ? null : presetLayout(candidates, n))` and activates `candidates[0]` when the active pane is not among the first n. The pressed button is `presetOf(layout)`.
- **H-D8 Drag a row onto a pane.** Rows get `draggable` and set `application/x-conversation-name` to the conversation name. A tiny store, `FE/components/Stage/conversationDragStore.ts` (zustand, `{ dragging: { name: string; deckKey: string } | null }`), is set on dragstart and cleared on dragend. `deckKey` is the conversation's own project deck (`resolveConversationProjectName(conv) ?? NO_PROJECT_KEY`). While it holds a value whose `deckKey` equals the Stage's deck, or the Stage's deck is the All deck, `PaneLayoutView` shows the same drop overlay it shows for tab drags. On drop with that data type, the Stage calls `onDropConversation(targetPaneId, name, zone)`:
  - `center` → `setActivePane(targetPaneId)`, then `showConversation(deckKey, name, label)` (replace that leaf);
  - an edge → `setActivePane(targetPaneId)`, then `openConversationBeside(deckKey, name, label)`.
  The mockup's "left half replaces / right half beside" is not used; the existing centre/edge zones stay, so tab drags and row drags read the same.
- **H-D9 Pane identity.** In the All deck, each split header and each agent tab label is prefixed with `<ProjectMark size="sm">` for the pane's conversation's project (`No project` uses `muted`). `PaneBar` gains an optional `renderTabPrefix?: (pane) => ReactNode`; `PaneLayoutView` gains an optional `renderHeaderPrefix?: (pane) => ReactNode`. The conversation header itself is unchanged.
- **H-D10 No Home in this deck.** `panesStore` treats `ALL_PROJECTS_KEY` as a Home-less deck (H-D15). With no panes, the Stage shows a centered empty state: `Pick conversations on the left. Ctrl+Click opens one beside another.` (`Cmd+Click` when `currentPlatform()` from `FE/lib/shortcuts/keys.ts` is `'mac'`).
- **H-D11 Deck-bound features in this deck.** `terminalCwd` is `undefined`, so the terminal drawer opens in the home folder as it does for No project. The dock already follows the focused pane. Ctrl+Alt+1..9 keep today's behavior.
- **H-D12 Deep links.** When the All deck is selected and a `/conv/<id>` navigation names a conversation, it opens in the All deck with `showConversation` and does not switch projects. The effect at `CommandDeck/index.tsx` lines 148–182 skips `onSelectProject` and calls `showConversation(ALL_PROJECTS_KEY, …)` instead of `openConversationTabIn` when `selectedProject === ALL_PROJECTS_KEY`. A message target (`pendingConversationTarget`) and `?view=terminal` still apply, through `updatePane` on the shown pane.
- **H-D13 New conversation in this deck.** The left column's **New conversation** button and the Stage's "+ New conversation" action create the conversation in the remembered last real project (`readLastProjectKey()` when it is a real project key, else unscoped) and open it beside the focused pane in the All deck. The button's second line gains the project name first, for example `overdeck · Opus 5.5 · High` (`No project · …` when unscoped).
- **H-D14 The deck layout store (new, replaces "layout in Stage state").** `FE/lib/deckLayoutStore.ts` (zustand):
  ```ts
  export const layoutStorageKey = (deckKey: string) => `pan-layout:${deckKey}`
  interface DeckLayoutStore {
    layoutByDeck: Record<string, PaneLayout | null>
    focusHistoryByDeck: Record<string, string[]>   // most recent first, max 32, session only
    hydrateLayout(deckKey: string): PaneLayout | null // ALWAYS re-reads localStorage; keeps a valid layout with >1 leaf, else null
    getLayout(deckKey: string): PaneLayout | null     // hydrates when the deck is not in memory yet
    setLayout(deckKey: string, next: PaneLayout | null): void // ≤1 leaf → null; writes through (removeItem for null)
    noteFocus(deckKey: string, paneId: string): void
  }
  export const selectDeckLayout = (deckKey: string) => (s: DeckLayoutStore) => s.layoutByDeck[deckKey] ?? null
  export function resetDeckLayoutStore(): void // tests only
  ```
  The localStorage key and the "≤1 leaf is stored as null" rule are unchanged, so existing tests that seed or read `pan-layout:<deck>` keep working. The Stage calls `hydrateLayout(deckKey)` in its mount effect (replacing the hydrate effect inside lines 352–374), reads the layout with `useDeckLayoutStore(selectDeckLayout(deckKey))`, routes its `setLayout` callback to the store, and calls `noteFocus(deckKey, activeId)` in an effect whenever the active pane changes.
- **H-D15 Home-less decks in `panesStore`.** `const isHomeless = (id: WorkspaceId) => id === ALL_PROJECTS_KEY` (imported from `FE/lib/deckKeys.ts`). For a Home-less deck:
  - `readPanes` drops any `home` pane and returns the rest, `[]` when storage is empty;
  - `ensureHome` hydrates without synthesizing Home (the name stays, so every caller keeps working);
  - `addPane` on a deck not in memory hydrates from storage first instead of seeding `[makeHomePane()]` (line 358);
  - `resolveActiveId` returns `PaneId | null`; with `null` the deck's `activePaneByWorkspace` entry is deleted and `pan-active-pane:<key>` is removed;
  - `closePane` may close the last pane.
  Project decks behave exactly as today.
- **H-D16 The All deck survives a reload.** `FE/lib/lastProject.ts` gains `ALL_PROJECTS_DECK_STORAGE_KEY = 'overdeck.ui.allProjectsDeck'` with `readAllProjectsDeck(): boolean` and `writeAllProjectsDeck(on: boolean)`. App's write effect (`App.tsx` line 202–204) becomes: `ALL_PROJECTS_KEY` → `writeAllProjectsDeck(true)` and leave the last project alone; another non-null key → `writeAllProjectsDeck(false)` and `writeLastProjectKey(key)`. `initialProjectKey` takes a new input `allProjectsDeck: boolean`: an explicit route project still wins; for a `/conv/` path or a storage fallback, `allProjectsDeck === true` returns `{ key: ALL_PROJECTS_KEY, fromStorage: false }`; a bare `/command-deck` still returns `{ key: null }`.
- **H-D17 One "real project" helper.** `projectsData.ts` exports `isRealProjectKey(key: string | null | undefined): key is string` — true when `key` is non-empty and is neither `NO_PROJECT_KEY` nor `ALL_PROJECTS_KEY`. Use it at `NewConversationButton.tsx` line 37, `useCreateConversation.ts` line 78 and `ActivityFeedTab.tsx` line 17. `projectCrumbLabel` (`appChromeLabels.ts`) returns `ALL_PROJECTS_LABEL` for the All key.
- **H-D18 Pane-number badges.** When the selected deck's layout has ≥2 leaves, a row whose conversation's agent pane is a leaf shows a small badge with its 1-based leaf position from `collectLeafIds` (title `Shown in pane N`). It applies to project decks too. The list reads the in-memory deck state only (`useDeckLayoutStore` + `usePanesStore`); it never hydrates storage itself.
- **H-D19 Make this the only pane.** Each split header gets a `⤢` button (`aria-label="Make this the only pane"`), in every deck: `setLayout(null)` and activate that pane. The other panes stay as tabs.

## 4. Requirements

- **FR-1** Both doors select the All projects deck (H-D1, H-D2).
- **FR-2** The list shows conversations from every project: Needs you first, then one group per project, with pane-number badges (H-D3, H-D18).
- **FR-3** Project-only items are hidden in All projects mode, and the crumb reads as in H-D4.
- **FR-4** Plain click, Ctrl/Cmd+Click, Beside, Open beside and Open in its project behave as in H-D5 and H-D6, and Shift+click still multi-selects.
- **FR-5** Layout presets 1/2/3/4 produce the H-D7 trees and survive a reload.
- **FR-6** Dragging a row onto a pane replaces it or opens beside it (H-D8).
- **FR-7** Split headers and tabs show the project mark in the All deck (H-D9).
- **FR-8** The deck has no Home pane and shows the empty state (H-D10, H-D15).
