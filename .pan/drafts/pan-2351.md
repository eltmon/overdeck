## Glossary

- **Internal token** — root secret at `~/.overdeck/internal-token` (`src/lib/internal-token.ts:34-36`,
  `tokenFilePath()`), created by `ensureInternalTokenSync()` (`:77-98`, `randomBytes(32).toString('hex')`,
  file mode 0600). Read via `getInternalTokenSync()` (`:43-67`; env `OVERDECK_INTERNAL_TOKEN` wins).
  Header: `x-overdeck-internal-token` (`INTERNAL_TOKEN_HEADER`, `:29`) or `Authorization: Bearer`.
- **Session cookie** — `overdeck_session` (`src/dashboard/server/routes/dashboard-auth.ts:12`),
  HMAC-derived: `createHmac('sha256', internal).update('overdeck-dashboard-session-v1')` (`dashboard-auth.ts:43-46`),
  so it is stable across restarts. Minted by `POST /api/dashboard/session`
  (`src/dashboard/server/server.ts:172-203`), which requires internal token OR loopback/Docker-bridge peer
  (`rejectUnauthorizedDashboardSessionMintRequest`, `dashboard-auth.ts:290-301`; `isLoopbackPeer`, `:275-288`).
- **Events token** — a SECOND, disjoint scheme: `OVERDECK_EVENTS_TOKEN` bearer on `GET /events/stream`
  (`src/dashboard/server/routes/events.ts:107-114`, `authorized()`); **open to all callers when unset** (`:108-109`).
- **Scoped access token (NEW)** — named, revocable credential `odk_<32 hex>` with an explicit scope set,
  hash-at-rest, for remote devices (phone, second laptop) and external services (Hermes). Never equal to
  the internal token.
- **Scope** — one of `read:events`, `read:state`, `read:conversations`, `tell`, `operate`, `admin`.
  `admin` ⊇ `operate` ⊇ `tell`; the `read:*` scopes are independent grants. Internal token and session
  cookie imply `admin` (the session cookie is the operator's own browser).

## Problem

Auth today is binary: internal token = full trust; session cookie = full trust; WS upgrades = origin-only;
events SSE = optional single bearer. There is no per-token scope, expiry, name, or revocation anywhere
(verified: `grep -ri scope` over `src/dashboard/server/routes/` finds only unrelated uses — cost windows,
context rules, `Effect.scoped`). Every remote consumer in epic PAN-2350 would have to hold root. A leaked
phone credential must not equal a leaked machine.

Additionally, `/ws/terminal` has no application heartbeat at all (verified: no `ws.ping`/`pong` in
`ws-terminal.ts`; only `ATTACH_TIMEOUT_MS`/`READY_TIMEOUT_MS` one-shot timers at `:40-41`), and Cloudflare's
edge cuts WebSockets idle ≥~100s — a prerequisite for PAN-2352.

What already exists and is NOT rebuilt here: `/ws/rpc` emits `system.heartbeat` every 15s
(`ws-rpc.ts:753-758`, `Stream.tick('15 seconds')`); the SSE stream sends `: keepalive` comments every 15s
(`events.ts:45`, `:214-216`). Those satisfy FR-4 of the epic already.

## Decisions

> **2026-09-29 (PAN-3762):** The registry may already exist from PAN-3762. `src/lib/access-tokens.ts` has exactly W1's form (file, record, `odk_` token, SHA-256 at rest, `timingSafeEqual`, 5 s refresh, `lastUsedAt` throttle) plus one optional record field, `kind?: 'device' | 'token'`; PAN-3762's pairing writes `kind: 'device'` with `scopes: ['admin']`. `dashboard.require_token_mint` is already read from raw `config.yaml` by `src/lib/remote-access/config.ts` (D-4 semantics, plus the remote request gate treating a forwarded loopback peer as remote). PAN-2351 still adds scope enforcement and `scopeSatisfies`, `pan token`, the `access-tokens` routes and Settings UI, and the `config-yaml` schema entry and Settings toggle for `require_token_mint`.

- **D-1 Token store is a file, not a DB table.** Registry at `~/.overdeck/access-tokens.json`, mode 0600,
  sibling of `internal-token`. Rationale: the SQLite DB is a disposable cache by tenet ("rebuildable from
  git + GitHub") — credentials must survive `pan admin db rebuild-*`. Auth material already lives in
  `OVERDECK_HOME` files (internal-token precedent). N is small (tens); no query needs SQL.
- **D-2 Opaque server-verified secrets, not JWTs.** One machine is the only verifier; revocation must be
  instant (≤5s); no stateless-verification need. Token = `odk_${randomBytes(32).toString('hex')}` (64 hex
  chars, matching internal-token entropy). Store only `sha256(token)` hex.
- **D-3 Additive over existing schemes (no-loss).** Internal token and session cookie keep working
  everywhere with implicit `admin`. `OVERDECK_EVENTS_TOKEN` keeps working on `/events/stream`; scoped
  tokens with `read:events` become an additional accepted credential there. Nothing existing breaks.
- **D-4 `require_token_mint` config flag** (`dashboard.require_token_mint`, default `false`): when true,
  `isLoopbackPeer` no longer satisfies session-mint auth. Needed because ANY local reverse proxy
  (cloudflared in PAN-2352, Traefik) makes every visitor a loopback peer, which would let strangers mint
  operator sessions. Off by default — zero behavior change for plain local use.
- **D-5 Heartbeat as a control frame, not WS protocol ping.** `/ws/terminal` already has a `\x00`-prefixed
  JSON control channel (`sendControl`, `ws-terminal.ts:59-63`; `parseControlMessage`, `:45-57`). Add
  `{type:'ping'}`/`{type:'pong'}` there — browser WebSocket API cannot send protocol-level pings, so a
  server-only `ws.ping()` would keep Cloudflare alive but not detect dead clients; the control frame does both.

## Requirements

- **FR-1** Create/list/revoke named scoped tokens via CLI and dashboard Settings; plaintext shown exactly
  once at creation.
- **FR-2** Every dashboard auth path can demand a scope: `rejectUnauthorizedDashboardRequest` (and the
  mutation variant) accept an optional `requiredScope`; scoped tokens are checked hash-vs-registry with
  `timingSafeEqual` (reuse `constantTimeTokenEqual`, `dashboard-auth.ts:77-82`).
- **FR-3** Scope floor: a token lacking a scope gets 403 (not 401) with a JSON body naming the missing scope.
- **FR-4** Revocation effective ≤5s (in-process cache TTL ≤5s or invalidate-on-write; file mtime check is fine).
- **FR-5** `/ws/terminal` ping/pong control frames at 20s; client (XTerminal.tsx) replies; server closes
  after 2 missed pongs (code 1001). SSE and `/ws/rpc` keepalives already exist (see Problem) — verify, don't rebuild.
- **FR-6** `require_token_mint` flag per D-4.
- **NFR-1** No `execSync`; Node 22 dist; heartbeat/revocation-TTL tests use `vi.useFakeTimers()`.
- **NFR-2** Registry file writes are atomic (write temp + rename) and 0600, like `ensureInternalTokenSync`
  (`internal-token.ts:88-93`).
- **NFR-3** No hardcoded fallbacks: absent registry file = no scoped tokens (empty set), never a default token.
- **NFR-4** Fail closed: an unreadable or corrupt registry file means zero valid scoped tokens plus a loud boot-time error — never a silently permissive parse fallback.

## Work items

### W1 — Token registry module: `src/lib/access-tokens.ts` (new)

Single read/write door for the registry (two-doors tenet). API:
`createAccessToken({name, scopes}): {token, record}` · `listAccessTokens(): AccessTokenRecord[]` (no hashes
in return type consumed by UI — include `tokenHash` only internally) · `revokeAccessToken(id)` ·
`verifyAccessToken(presented): {ok: true, record} | {ok: false}` (sha256 + timingSafeEqual; updates
`lastUsedAt` lazily, throttled to 1/min to avoid write storms). Record:
`{id, name, scopes: Scope[], tokenHash, createdAt, lastUsedAt, revokedAt?}`. File
`~/.overdeck/access-tokens.json`; in-process cache invalidated by mtime, max age 5s (FR-4).
Scope type + `scopeSatisfies(granted, required)` helper (`admin`→all, `operate`→`tell`).
**Tests:** `tests/unit/lib/access-tokens.test.ts` — create/verify/revoke, scope satisfaction matrix,
cache TTL with fake timers, atomic write (temp file rename), 0600 mode.

### W2 — Auth integration: `src/dashboard/server/routes/dashboard-auth.ts`

- Extend `hasDashboardInternalTokenHeaders` (`:103-117`) — no change; ADD `resolveRequestScopes(request):
  Scope[] | null`: internal token → `['admin']`; session cookie → `['admin']`; else `verifyAccessToken`
  on the same two headers → record scopes; else null.
- `rejectUnauthorizedDashboardRequest(request, requiredScope?)` (`:303-314`): unchanged behavior when
  `requiredScope` omitted; when present, 401 if no credential, 403 `{error, missingScope}` if credential
  lacks scope.
- `rejectUnsafeDashboardMutationRequest` (`:149-170`): pass-through `requiredScope`; scoped-token requests
  skip CSRF like internal-token requests do today (`:160`) — CSRF defends cookies, not header tokens.
- Session mint (`server.ts:172-203` + `dashboard-auth.ts:290-301`): accept a scoped token as mint
  credential — the minted session then carries THAT token's scopes, not admin. Requires the session→scope
  association: keep it simple — mint returns the cookie only for `admin`-scoped credentials; non-admin
  tokens use header auth directly, no cookie (browsers for non-operator users arrive in Phase 3 pairing;
  decision recorded to avoid speculative session-scope machinery now).
- `require_token_mint` (D-4): in `rejectUnauthorizedDashboardSessionMintRequest`, skip the
  `isLoopbackPeer(request)` branch when the flag is on.
- **Peer-trust audit (security gate):** enumerate every auth-relevant peer-address trust site —
  `grep -rn "isLoopbackPeer\|remoteAddress" src/dashboard/server/` — and record a table in the PR:
  each site is (a) gated by `require_token_mint`, (b) requires a credential regardless of peer, or
  (c) documented harmless when world-reachable. Verified 2026-07-28 baseline: `isLoopbackPeer` has
  exactly one auth call site (session mint, `dashboard-auth.ts:297`); `rejectUnauthorizedDashboardRequest`
  (`:303-314`) requires a credential from every peer; the only other peer-IP consumer is the conversation
  upload rate limiter (`conversations.ts:500-504`), which reads the spoofable `x-forwarded-for` header —
  re-verify at implementation and pin it to the real TCP peer when `require_token_mint` is on. The audit
  exists so "no other loopback-trust hole" is proven by the table, not assumed.
- Events route (`events.ts:107-114`): `authorized()` additionally accepts a scoped token with `read:events`.
  The unset-`OVERDECK_EVENTS_TOKEN`-means-open behavior is preserved for local compat (documented hazard;
  PAN-2352's runbook requires setting `require_token_mint` + an events token before tunneling).
**Tests:** extend existing dashboard-auth tests; scope-floor matrix (read:events token → SSE 200,
tell 403, terminal 403 — terminal case lands via PAN-1166's gate test).

### W4 — `/ws/terminal` heartbeat

## Intersecting repo rules (restated)

Fake timers for every heartbeat/TTL test (never real `setTimeout`); no `execSync` in server-reachable code;
never hardcode fallbacks (empty registry = no tokens, loud absence); two doors (registry module is the only
reader/writer of the token file); dashboard is Node 22 dist — `npm run build` before restart, and this
touches no boot path (route layers only), so a normal `pan reload` suffices; commit early and often on main.

## Out of scope

Token expiry/rotation policies (add when a consumer needs them); per-token rate limits; pairing UX
(PAN-2356); browser sessions for non-admin identities (PAN-2356 pairing); replacing `OVERDECK_EVENTS_TOKEN`
(kept, additive).
