## Glossary

- **Registry** — `src/lib/access-tokens.ts`, the single read/write door for `~/.overdeck/access-tokens.json` (mode 0600, atomic temp-file rename). Built by PAN-3762 exactly per this PRD's original W1. Records: `{ id, name, scopes, tokenHash, createdAt, lastUsedAt, revokedAt?, kind? }`. Verification (`verifyAccessToken`, `:260`) is synchronous against an in-memory snapshot that `main.ts:138-139` loads at boot and refreshes every 5 s.
- **`odk_` token** — `odk_<64 hex>` plaintext (`createAccessToken`, `:206`); only its SHA-256 hex is stored.
- **Record kind** — `kind: 'device'` is a paired device (PAN-3762, always `scopes: ['admin']`). `kind: 'token'` is a scoped API token (new here). A record with no `kind` is treated as `'device'` (legacy rule, FR-10).
- **Scope** — one of `read:events`, `read:state`, `read:conversations`, `tell`, `operate`, `admin`. `admin` satisfies every scope. `operate` satisfies `tell`. The three `read:*` scopes are independent grants; nothing but `admin` implies them.
- **Credential** — the value `resolveDashboardCredential(headers)` (`src/dashboard/server/routes/dashboard-auth.ts:151-159`) returns: `internal-token`, `root-session`, `device`, or (new) `token`, or `null`. `internal-token` and `root-session` are **root credentials** and imply `admin`. `device` and `token` are **registry credentials**; they carry the record's scopes and are revocable.
- **Remote request gate** — `src/dashboard/server/remote-request-gate.ts`, one global `HttpRouter` middleware that every `/api/*` and `/events/*` request passes through (`remoteGateRejection`, `:99-109`).
- **WebSocket upgrade gate** — `authorizeDashboardUpgrade` (`src/dashboard/server/ws-auth.ts:30-38`), called by `/ws/terminal` (`ws-terminal.ts:244`), `/ws/rpc` (`ws-rpc.ts:1186`, `:1203`), `/ws/voice` (`ws-voice.ts:47`) and `/ws/autopreso` (`ws-autopreso.ts:37`).
- **Route-scope table** — (new) `src/dashboard/server/route-scopes.ts`: the one list mapping `METHOD path-pattern` to the scope a registry credential needs. Anything not listed needs `admin`.
- **Live connection registry** — `src/dashboard/server/device-connections.ts`: close callbacks keyed by registry record id; `closeDeviceConnections(id)` ends every open socket/stream of that record.

## Problem

Every consumer in epic PAN-2350 (a phone, Hermes, an SSE sidecar) needs a credential. Today the only registry credential is a paired device, and every device is `admin`. The registry type allows only `'admin'` (`access-tokens.ts:35`, `export type AccessTokenScope = 'admin';`), and no gate reads scopes: `remoteGateRejection` passes any non-null credential (`remote-request-gate.ts:105`, `if (resolveDashboardCredential(headers) !== null) return null;`) and `authorizeDashboardUpgrade` does the same (`ws-auth.ts:35-37`). A leaked phone or sidecar credential therefore equals a leaked machine.

Adding a narrow token is not just a new record kind. Four existing call sites assume "registry credential ⇒ device" or "any credential ⇒ root", and each becomes a privilege-escalation path the moment a `kind: 'token'` record can exist:

1. **Root-session mint.** `routes/dashboard-session.ts:86-103` special-cases only `kind === 'device'`; any other credential falls through to `rejectUnauthorizedDashboardRequest`, passes, and receives the unrevocable root `overdeck_session` cookie.
2. **Pairing-credential issuance.** `routes/pairing.ts:71` denies only `kind === 'device'`, so a token could mint pairing credentials and create new admin devices.
3. **Device revocation.** `routes/pairing.ts:174` restricts only devices, so a token could revoke the operator's devices.
4. **The two gates** pass any credential, as quoted above.

Two transport rules also block useful tokens: a `POST` with no `Origin` and no `Referer` is refused as `Missing origin` (`routes/origin-validation.ts:121-127`), so a programmatic `tell` client cannot post a message; and CSRF is skipped only for the internal token (`dashboard-auth.ts:198`, `if (hasDashboardInternalToken(request)) return null;`).

Heartbeats: `/ws/rpc` already emits `system.heartbeat` every 15 s (`ws-rpc.ts:774`, `Stream.tick('15 seconds')`) and `/events/stream` already sends `: keepalive` every 15 s (`routes/events.ts:49`, `KEEPALIVE_INTERVAL_MS = 15_000`). Both meet the epic's ≤25 s requirement and are not rebuilt. `/ws/terminal` has none; that work moved to PAN-4434.

## Decisions

> **2026-09-29 (PAN-3762):** The registry may already exist from PAN-3762. `src/lib/access-tokens.ts` has exactly W1's form (file, record, `odk_` token, SHA-256 at rest, `timingSafeEqual`, 5 s refresh, `lastUsedAt` throttle) plus one optional record field, `kind?: 'device' | 'token'`; PAN-3762's pairing writes `kind: 'device'` with `scopes: ['admin']`. `dashboard.require_token_mint` is already read from raw `config.yaml` by `src/lib/remote-access/config.ts` (D-4 semantics, plus the remote request gate treating a forwarded loopback peer as remote). PAN-2351 still adds scope enforcement and `scopeSatisfies`, `pan token`, the `access-tokens` routes and Settings UI, and the `config-yaml` schema entry and Settings toggle for `require_token_mint`.

Original decisions, still in force:

- **D-1 Token store is a file, not a DB table.** Built as `~/.overdeck/access-tokens.json` by PAN-3762. The SQLite DB is a rebuildable cache; credentials must survive a rebuild.
- **D-2 Opaque server-verified secrets, not JWTs.** Instant revocation, one verifier.
- **D-3 Additive over existing schemes (no-loss).** Internal token, root session cookie, device credentials and `OVERDECK_EVENTS_TOKEN` keep working exactly as today.
- **D-4 `require_token_mint`.** Already enforced by PAN-3762 (`dashboard-auth.ts:344-346`, `remote-request-gate.ts:93-96`). Its schema entry and Settings toggle moved to PAN-4435.
- **D-5 Terminal heartbeat as an app-level control frame.** Moved to PAN-4434 with the rest of the heartbeat work. Rationale restated there: a data frame counts as traffic at every proxy; intermediaries treat protocol ping frames inconsistently.

New decisions (2026-09-30):

- **D-6 One table, default `admin`, read by every auth check.** One table, `route-scopes.ts`, says which scope each `METHOD path` needs; anything unlisted needs `admin`. It is read by the remote request gate (all HTTP under `/api/` and `/events/`), by `authorizeDashboardUpgrade` (all `/ws/*`), and by the per-route helpers `rejectUnauthorizedDashboardRequest` and `rejectUnsafeDashboardMutationRequest` (defense in depth: `GET /knowledge-viewer/*`, `routes/knowledge-viewer.ts:272-277`, sits outside the gate's prefixes and relies on the helper). The helpers derive the scope from the request's own method and path, so they take no scope parameter; the original FR-2 "optional `requiredScope` parameter" is replaced by this table so scope declarations cannot drift between call sites. `GET /a/:slug` (`routes/artifacts.ts:229-241`) is host-gated public artifact serving with no credential check; it is unchanged.
- **D-7 A registry credential is judged by its scopes, regardless of peer.** When a request presents a valid `odk_` credential, the gate checks that credential's scopes and never falls back to loopback peer trust. A narrow token sent from `127.0.0.1` still gets 403 on an `admin` route. (A loopback caller that sends no credential keeps today's peer trust.)
- **D-8 Scopes on every registry credential.** `device` credentials carry their record's scopes too (always `['admin']` from pairing), and the gates check devices and tokens with the same code. A hand-edited device record with narrower scopes is honored as narrower, never silently widened.
- **D-9 Tokens travel only in `Authorization: Bearer`.** A `kind: 'token'` record is recognized only from the Bearer header. If its plaintext arrives in the `overdeck_device` cookie, `resolveDashboardCredential` returns `null`. So every token credential is header-borne, which makes FR-9's CSRF/Origin relaxations safe.
- **D-10 No `?token=` query parameter on WebSocket upgrades.** `ws-auth.ts:34` and `docs/DASHBOARD-AUTH.md` promised one. Tokens in URLs land in proxy and access logs. Programmatic WebSocket clients (Node `ws`, Python `websockets`) can set `Authorization`. Browsers use the session or device cookie. Remove the promise.
- **D-11 Root-only credential minting.** Only root credentials (`internal-token`, `root-session`) may create or revoke access tokens, issue pairing credentials, or revoke devices other than the caller's own device. A device or token credential gets 403 on those operations, even with `admin` scope. This extends PAN-3762's rule "a paired device cannot mint more devices".
- **D-12 A token never mints a session.** `POST /api/dashboard/session` answers a `token` credential with 403 and sets no cookie. Token clients authenticate each request with the Bearer header.
- **D-13 The route-scope table starts minimal.** Only obviously non-secret reads and the message routes get narrow scopes. The table grows per consumer, in the issue that adds the consumer.
- **D-14 CLI revocation goes through the dashboard.** `pan token revoke` calls `DELETE /api/access-tokens/:id` with the internal token (closes live connections immediately), and writes the registry directly only when the dashboard is unreachable (no connections can be open). This copies `pan devices revoke` (`src/cli/commands/pair.ts:141-160`). `pan token create` and `pan token list` use the registry directly; a created token is accepted by a running dashboard within 5 s (snapshot refresh).
- **D-15 Split.** The `/ws/terminal` heartbeat (FR-5) moved to PAN-4434. The Settings token section and the `require_token_mint` schema entry and toggle (FR-6 and the Settings half of FR-1) moved to PAN-4435. What remains here is one security boundary that must land together: a `kind: 'token'` record without the gate, mint and pairing hardening is an escalation path.

## Requirements

- **FR-1** Create, list and revoke named scoped tokens through `pan token` and the `/api/access-tokens` routes; the plaintext appears exactly once, in the create response. *(Settings UI half moved to PAN-4435.)*
- **FR-2** Scope is enforced from one route-scope table at the remote request gate, the WebSocket upgrade gate, and the per-route auth helpers; unlisted routes require `admin` (D-6).
- **FR-3** A registry credential that lacks the required scope gets **403** with body `{ "error": "insufficient_scope", "missingScope": "<scope>" }` (HTTP) or an upgrade rejection with status 403 (WebSocket). A missing or invalid credential stays **401**.
- **FR-4** Revocation is effective within 5 s: new requests fail at once in-process and within 5 s cross-process (snapshot refresh); `DELETE /api/access-tokens/:id` closes the token's live WebSockets and SSE streams at once; `pan token revoke` goes through that route when the dashboard runs.
- **FR-5** *Retired here — moved to [PAN-4434](https://github.com/eltmon/overdeck/issues/4434).* (`/ws/terminal` ping/pong heartbeat.)
- **FR-6** *Retired here — moved to [PAN-4435](https://github.com/eltmon/overdeck/issues/4435).* (`require_token_mint` schema entry and Settings toggle; the flag itself is enforced since PAN-3762.)
- **FR-7** A `token` credential never obtains a root session cookie, a pairing credential, a new access token, or the revocation of a device (D-11, D-12).
- **FR-8** A `kind: 'token'` record authenticates only from `Authorization: Bearer`; the same plaintext in the `overdeck_device` cookie authenticates as nothing (D-9).
- **FR-9** A Bearer-borne `token` credential skips the CSRF check in `rejectUnsafeDashboardMutationRequest`, and a non-GET request carrying `Authorization: Bearer odk_…` with no `Origin` and no `Referer` passes origin validation. Cookie-borne credentials keep both checks.
- **FR-10** Device credentials carry their record's scopes and are checked by the same code as tokens; a record with no `kind` is a device (D-8).
- **NFR-1** No `execSync` in server-reachable code; the dashboard runs as the Node 22 dist; any test of the 5 s refresh uses `vi.useFakeTimers()` (the existing `tests/unit/lib/access-tokens.test.ts:28` pattern), never a real wait.
- **NFR-2** Registry writes stay atomic and 0600 (unchanged `writeRegistry`, `access-tokens.ts:136-150`).
- **NFR-3** No hardcoded fallbacks: an absent registry is zero tokens; an unknown scope string in the file satisfies nothing.
- **NFR-4** Fail closed: a corrupt or unreadable registry is zero valid tokens plus a loud error (unchanged `failSnapshot`, `access-tokens.ts:165-171`).
- **NFR-5** File-size ratchet: `src/dashboard/server/ws-rpc.ts` is 1219 lines with an allowlist cap of 1221, so its edit must add at most 2 lines. No allowlist cap is raised.

## Route-scope table (the whole initial table)

| Scope | `METHOD path` |
| --- | --- |
| `read:events` | `GET /events/stream`, `GET /events/version` |
| `read:state` | `GET /api/issues`, `GET /api/agents`, `GET /api/agent-directory`, `GET /api/flywheel/status`, `GET /api/pipeline/membership` |
| `read:conversations` | `GET /api/conversations`, `GET /api/conversations/:id`, `GET /api/conversations/:name/messages`, `GET /api/conversations/:name/about` |
| `tell` | `POST /api/agents/:id/message`, `POST /api/agents/:id/tell`, `POST /api/conversations/:name/message` |
| `operate` | WebSocket `/ws/terminal` |
| `admin` | everything else, including `/ws/rpc` (it carries `terminalWrite` and `writeFileAtPath`), `/ws/voice`, `/ws/autopreso` |

A `:param` segment matches exactly one non-empty path segment. Matching is exact and case-sensitive on the path that `gatePathname` (`remote-request-gate.ts:54-76`) returns; a path that matches nothing needs `admin`, so every mismatch fails closed. `GET /api/conversations/:id` also matches `/api/conversations/archived` and `/api/conversations/pending-input`; both are conversation-list reads, so that is intended.
