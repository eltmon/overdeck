# PAN-5461 — Computer use: Settings page with one-click setup, and the platform provider seam

**Issue:** [PAN-5461](https://github.com/eltmon/overdeck/issues/5461)
**Follows:** PAN-5452 (the `pan computer` CLI, merged in #5457)
**Siblings that build on this:** PAN-5462 (Windows via WSL2), PAN-5463 (macOS)
**Mockup (operator-approved 2026-11-17):** `.tmp/computer-use-settings/index.html` in the primary checkout (gitignored). Screens are described in WI-6a so the executor does not need the file.

## Summary

PAN-5452 shipped `pan computer` (Linux only), the global `computer_use.enabled` flag, a `pan doctor` check and the `pan-computer-use` skill. Turning it on still means hand-editing `~/.overdeck/config.yaml`, and the readiness checks only exist inside `pan doctor`, which reports nothing while the feature is off.

This issue adds **Settings → Computer Use**: one button installs any missing system packages, turns on GNOME accessibility, sets `computer_use.enabled: true`, and tests the helper. It also introduces the **platform provider seam** (`src/lib/computer-use/platform.ts`) so PAN-5462 and PAN-5463 add Windows and macOS as providers instead of editing `if (platform !== 'linux')` branches.

## Glossary

- **Host**: the machine running the Overdeck dashboard server. Every status on the page describes the host's desktop, never the device the browser runs on (the dashboard can be opened from a phone).
- **Provider**: an object implementing `ComputerUseProvider` (WI-1a) for one platform: it resolves the desktop session, reports readiness, runs setup steps, and runs the helper. This issue ships one provider, `linux`.
- **Platform id**: `'linux' | 'wsl' | 'darwin'`, from `detectPlatform()` (WI-1a). `'wsl'` is Linux running under WSL2 (`WSL_DISTRO_NAME` set, or `/proc/sys/kernel/osrelease` contains `microsoft`, case-insensitive). Anything else is `'unsupported'`.
- **Readiness check**: one row of the "What Overdeck checked" list: `{ id, label, status, detail, fixCommand? }`, `status` ∈ `ok | action | missing | unavailable`.
- **Setup step**: one action the Setup button runs: `install-packages`, `enable-accessibility`, `grant-permissions` (macOS only, PAN-5463), `enable-flag`, `test-helper`. Steps already satisfied are not listed.
- **Probe**: one read-only host check (a `which`, the gi import, `gsettings get`). Probes run through an injected `execFile` so tests never spawn processes.
- **Desktop lock**: PAN-5452's cross-process O_EXCL lock file (`~/.overdeck/computer-use/lock`) that serializes helper calls (`withDesktopLock` in `src/lib/computer-use/lease.ts`).
- **Desktop lease**: PAN-5452's single-holder claim on input (`~/.overdeck/computer-use/lease.json`, 120 s TTL). Read with the new exported `readLease()` (WI-2a).
- **Settings door**: a path-scoped writer that edits only named YAML paths in `~/.overdeck/config.yaml` with `doc.setIn`, preserving comments. Pattern: `src/lib/semgrep/settings.ts`.
- **Mutation guard**: `rejectUnsafeDashboardMutationRequest(request)` from `src/dashboard/server/routes/dashboard-auth.ts`, called first in every mutating route.
- **Admin-only route**: a route with no row in `src/dashboard/server/route-scopes.ts`; `requiredScopeFor(method, path)` returns `'admin'` for unlisted routes.
- **Frontend test subset**: `scripts/frontend-test-subset.txt`, the list of frontend test files CI runs (`npm run test:frontend-subset`). A frontend test file not listed there never runs on CI.

## Decisions

- **D-1 One button, not a checklist of fixes.** The page has a single primary action ("Set up and turn on", or "Turn on Computer Use" when nothing is missing). The readiness checks sit in a collapsed "What Overdeck checked" list. Individual fix buttons are not shipped (operator feedback 2026-11-17: "it should just be one click").
- **D-2 Package installs use the OS's own password prompt.** On Linux the server runs `pkexec <pkgmgr> install -y <fixed list>` so the desktop's polkit dialog asks for the password once. Overdeck never sees the password.
- **D-3 The package list is fixed server-side.** The setup route never takes package names, commands or paths from the request body. The body is never read.
- **D-4 Supported package managers for one-click install:** `apt-get`, `dnf`, `pacman` (package table in WI-2b). With `zypper`, `apk` or no detected manager, the `install-packages` step is still listed (so the Off card never claims everything is installed), but without `needsPassword`, and running it returns `failed` with the per-manager command to copy (`zypper`/`apk`) or the package names to install by hand (no manager). Setup therefore stops before turning the flag on. The missing rows also carry a `fixCommand` for `zypper`/`apk`.
- **D-5 GNOME accessibility is turned on without a password:** `gsettings set org.gnome.desktop.interface toolkit-accessibility true`, run with the session env from `resolveDesktopEnv()` (it needs `DBUS_SESSION_BUS_ADDRESS`). When `gsettings` is not on PATH (non-GNOME desktops) the check row reads `ok` with detail "Not GNOME" and no step is added.
- **D-6 Readiness runs whether or not the feature is on.** The probes move out of `src/cli/commands/doctor-computer-use.ts` into `src/lib/computer-use/readiness-linux.ts`. `pan doctor` keeps its current output (no rows while off) by wrapping it with a fixed legacy message table (D-14).
- **D-7 Status refresh never waits behind an agent.** The status route runs the helper handshake only if the desktop lock is free within 2 s (`tryWithDesktopLock`, WI-2a); otherwise the `helper` check reports `ok` with detail "Skipped: an agent is using the desktop". The Setup button's `test-helper` step waits on the lock normally (`withDesktopLock`, which gives up after its existing ~60 s attempt budget), and the helper's own 30 s timeout (`HELPER_TIMEOUT_MS` in `helper.ts`) caps the handshake. No new timeout code is needed for setup.
- **D-8 Routes are admin-only.** No `route-scopes.ts` rows, so no `TELEMETRY_PROPERTY_DOMAINS` or `docs/TELEMETRY.md` changes. Mutations call the mutation guard. An agent's scoped token can't turn computer use on.
- **D-9 WSL is detected and refused until PAN-5462.** `detectPlatform()` returns `'wsl'` under WSL2 and `providerFor('wsl')` returns `null` in this issue, so the page shows "Not available on this machine", `pan computer` refuses with `unsupported_platform`, and `pan doctor` shows its non-Linux warn row. Reason: WSLg gives Linux GUI apps a display, so without this the Linux provider would drive WSLg windows instead of the Windows desktop.
- **D-10 The seam is owned here.** The seam types live in `src/lib/computer-use/platform-types.ts` (specified verbatim in WI-1a); `platform.ts` holds `detectPlatform` and `providerFor` and re-exports the types. Providers and their helper modules import types from `platform-types.ts`, never from `platform.ts`, because `platform.ts` imports every provider and `lint:circular` counts `import type` edges. PAN-5462 and PAN-5463 add providers by adding a `case` in `providerFor`; they must not change the interface without updating this PRD's text in their own PR.
- **D-11 "Turn off" is a plain switch** once the feature is on. Turning off does not uninstall packages or turn GNOME accessibility back off.
- **D-12 The `disabled` error names the page.** New text: `Computer use is off. Turn it on in the dashboard under Settings → Computer Use, or set computer_use: { enabled: true } in ~/.overdeck/config.yaml.`
- **D-13 One issue, not more siblings.** The plan touches about 40 files across more than 6 path prefixes, past the finalize projected-surface limits (25 files, 6 subsystems). It ships as one issue with `plan.metadata.sizeJustification`: the operator approved this scope as one issue; Windows and macOS are already split out (PAN-5462/5463); most files are new small modules and their tests; the seam, routes and page are one feature whose slices are not useful to the operator alone.
- **D-14 Doctor keeps its exact rows.** `checkComputerUse` maps readiness rows back to today's `CheckResult` rows with a fixed table (WI-2b), in today's order, with today's apt `fix` strings. Doctor runs the helper handshake **without** the desktop lock (lock mode `'none'`), as it does today, and skips setup-step planning. It decides "Linux or not" with `detectPlatform()`, so WSL gets the non-Linux warn row (D-9).
- **D-15 Package-manager detection is local.** `readiness-linux.ts` detects the manager itself with `which` through the injected `execFile`, in the same order as `src/lib/prereqs/registry.ts` (`pacman`, `dnf`, `zypper`, `apk`, `apt-get`). It must not import `prereqs/registry.ts`: that module pulls in chalk, Semgrep install and terminal-backend code, and its `checkCommand` spawns real processes that tests cannot inject.
- **D-16 Key checks fail closed on platforms without rules.** `assertKeyComboAllowed(key, allow, platform)` has rules only for `'linux'`. For `'windows'` or `'mac'` it throws `unsupported_platform` ("No blocked-shortcut rules for <platform> yet.") even when `allowSystemShortcut` is true. PAN-5462/5463 replace the throw with their rule tables. These platforms are unreachable in this issue.
- **D-17 Both install paths ship.** The Linux install step tries `pkexec` first and falls back to opening a terminal window when there is no polkit agent (exit 127, "No authentication agent found" in stderr, or `pkexec` not found). Both paths are code and tests in this issue. The live checkpoint (WI-8) only records which path the operator's desktop actually takes.
- **D-18 Icon:** `MousePointerClick` from `lucide-react`. `MonitorCog` does not exist in the installed `lucide-react@0.400.0`.
- **D-19 Entry points.** Settings nav item, command-palette row, and the D-12 `disabled` message (which agents relay to the operator). No conversation-tab or project-Home entry: this is a one-time host setting, and the place an operator meets it is an agent's `disabled` error, which now names the page.
- **D-20 Lease helper rename.** `lease.ts` already has a private `readLease(path, readFileFn)`. Rename it to `readLeaseRecord` so the new exported `readLease(now, deps)` can take the name.

## Requirements

### Functional
- **FR-1** `detectPlatform()` returns `'linux'`, `'wsl'`, `'darwin'` or `'unsupported'` as defined in the Glossary; `providerFor(id)` returns the registered provider or `null`.
- **FR-2** Every `pan computer` command resolves its provider through `providerFor(detectPlatform())`; a `null` provider throws `unsupported_platform` with the message `Computer use isn't supported on this host (<platform>) yet.`
- **FR-3** The Linux provider's `readiness()` returns these checks in order: `session` (Desktop session), `atspi` (Accessibility bindings), `gnome-a11y` (GNOME accessibility), `input` (Mouse and keyboard input), `screenshots` (Screenshots), `clipboard` (Clipboard), `helper` (Helper). Same probes as today's doctor check.
- **FR-4** `GET /api/computer-use/status` returns `ComputerUseStatusView` (WI-3b). Readiness follows D-7.
- **FR-5** `POST /api/computer-use/setup` runs the listed setup steps in order and returns `{ ok, steps: [{ id, label, status: 'done'|'skipped'|'failed'|'waiting', message?, command? }], status }`. It stops at the first `failed` or `waiting` step. It only turns the flag on if every earlier step succeeded.
- **FR-6** `PUT /api/computer-use/settings` with `{ enabled: boolean }` writes `computer_use.enabled` through a settings door and returns the new status.
- **FR-7** `POST /api/computer-use/release` force-releases the desktop lease and returns the new status.
- **FR-8** Settings shows a "Computer Use" nav item directly after "Security", rendering the section described in WI-6a.
- **FR-9** The command palette offers "Open Computer Use settings" (keywords: computer, desktop, automation, screen).
- **FR-10** `pan computer` commands that fail with `disabled` print the D-12 message.
- **FR-11** `pan doctor` output is unchanged in content (still no rows while off) after the refactor.
- **FR-12** `assertKeyComboAllowed` takes the provider's key platform and fails closed for platforms without rules (D-16).
- **FR-13** A second `POST /api/computer-use/setup` while one is running returns 409 `{ error: 'Setup is already running' }`.

### Non-functional
- **NFR-1** No `execSync`/`spawnSync` in any code reachable from the dashboard server (repo rule `no-execsync-server`). Use `execFile` promisified, as `doctor-computer-use.ts` does today, or `spawn(...).unref()` for the detached terminal. A `readFileSync` of `/proc/sys/kernel/osrelease` is allowed (no child process).
- **NFR-2** The status route answers in under 3 s when the lock is held (D-7), and independent probes run in parallel (`Promise.all`).
- **NFR-3** Tests that exercise timeouts or polling use `vi.useFakeTimers()` (repo rule `fake-timers-for-retry-tests`) **only when no real I/O is bounded by the faked clock**. Fake timers over real `fs` calls race on busy CI runners (PAN-3305, PAN-3320), so the one test that drives `withFileLock` against a real lock file uses real timers with tiny bounds (`retryMs: 1`, `timeoutMs: 20`, total under 100 ms); everything above it injects a fake `withFileLock`. Tests inject `execFile`, `spawnDetached`, the lock functions and paths through `deps` parameters; they never `vi.mock('node:child_process')` and never write the real `~/.overdeck`.
- **NFR-4** UI follows `pan-style-guide`: Broadsheet vocabulary, badge tint 8%/32%, `rounded-md` badges (no pills), amber = operator must act, emerald = outcome, blue = machine working, no `font-bold`/`font-semibold`, switch tracks use `.switch-track-on`, no new `useMemo`/`useCallback`/`memo` (React Compiler; `lint:manual-memo`).
- **NFR-5** No file in `src/` passes its allowed line count (`lint:file-size`). `CommandPalette.tsx` (1051 lines, cap 1124) grows by at most 2 lines; `doctor.ts` and `schema.ts` are not edited.

`detectPlatform` logic: `platform = deps.platform ?? process.platform`. `'darwin'` → `'darwin'`. `'linux'` → `'wsl'` when `env.WSL_DISTRO_NAME` is a non-empty string or `readOsRelease()` matches `/microsoft/i`, else `'linux'`. Anything else → `'unsupported'`. The default `readOsRelease` reads `/proc/sys/kernel/osrelease` with `readFileSync(..., 'utf8')` inside try/catch and returns `null` on any error.

**Tests (`platform.test.ts`):** linux → `'linux'`; linux + `WSL_DISTRO_NAME=Ubuntu` → `'wsl'`; linux + osrelease `5.15.167.4-microsoft-standard-WSL2` → `'wsl'`; linux + osrelease `null` → `'linux'`; darwin → `'darwin'`; win32 → `'unsupported'`. All via `deps`, no real `/proc` read.

### WI-2a Lock additions: typed timeout, `readLease`, `tryWithDesktopLock`
**Files:** edit `src/lib/vault/file-lock.ts`; edit `src/lib/computer-use/lease.ts`; new test `src/lib/vault/__tests__/file-lock.test.ts`; edit `src/lib/computer-use/__tests__/lease.test.ts`.

`file-lock.ts`:
- Add `export class FileLockTimeoutError extends Error { constructor(message: string) { super(message); this.name = 'FileLockTimeoutError'; } }`.
- Add `timeoutMs?: number` to `FileLockOptions` ("Give up after this long, measured with Date.now()").
- In `acquire`, compute `const deadline = options.timeoutMs === undefined ? Infinity : Date.now() + options.timeoutMs;`. Before each retry sleep, if `Date.now() >= deadline` stop retrying. Both exhaustion paths (attempts or deadline) throw `new FileLockTimeoutError(<today's message>)`. Callers that catch a plain `Error` keep working because it is a subclass with the same message.

Before (`acquire`, end):
```ts
      await new Promise((resolve) => setTimeout(resolve, retryMs));
    }
  }
  throw new Error(`Could not acquire lock ${lockPath}; another ${options.label ?? 'pan vault'} process may be stuck`);
```
After:
```ts
      if (Date.now() >= deadline) break;
      await new Promise((resolve) => setTimeout(resolve, retryMs));
    }
  }
  throw new FileLockTimeoutError(`Could not acquire lock ${lockPath}; another ${options.label ?? 'pan vault'} process may be stuck`);
```

`lease.ts`:
- Rename the private `readLease(path, readFileFn)` to `readLeaseRecord` and update its two callers (`claimLease`, `releaseLease`) (D-20).
- Add:
```ts
export interface LeaseView { holder: string; expiresAt: string }
/** The current unexpired lease, or null. Never throws on a missing or corrupt file. */
export async function readLease(now: number, deps: LeaseFsDeps = {}): Promise<LeaseView | null>;
/** Like withDesktopLock, but gives up after `waitMs` and returns { acquired: false } instead of throwing. */
export async function tryWithDesktopLock<T>(fn: () => Promise<T>, options: { waitMs: number }, deps: WithDesktopLockDeps = {}): Promise<{ acquired: true; value: T } | { acquired: false }>;
```
`readLease` returns `{ holder, expiresAt }` only when `new Date(expiresAt).getTime() > now`; any read error other than ENOENT also returns `null` (status must never fail on the lease). `WithDesktopLockDeps` gains `withFileLock?: typeof withFileLock`. `tryWithDesktopLock` calls `(deps.withFileLock ?? withFileLock)(lockPath, fn, { staleMs: 60_000, label: 'pan computer', timeoutMs: options.waitMs })` (after the same `mkdir` as `withDesktopLock`) and maps only `FileLockTimeoutError` to `{ acquired: false }`; errors thrown by `fn` propagate.

**Tests (NFR-3: no fake timers over real fs):** `file-lock.test.ts` uses a temp dir from `mkdtemp(join(os.tmpdir(), 'pan-5461-lock-'))` and **real timers**: create the lock file by hand, then `withFileLock(path, fn, { retryMs: 1, timeoutMs: 20 })` rejects with `FileLockTimeoutError` and never calls `fn`; `{ retryMs: 1, maxAttempts: 3 }` without `timeoutMs` also rejects with `FileLockTimeoutError`; a free lock runs `fn` and removes the file. `lease.test.ts`: `readLease` returns null for missing, corrupt and expired files and the view for a live lease (inject `readFile`); `tryWithDesktopLock` with an injected `withFileLock` that throws `FileLockTimeoutError` returns `{ acquired: false }`, with one that runs `fn` returns `{ acquired: true, value }`, and an error thrown inside `fn` propagates (inject `mkdir` and paths too).
