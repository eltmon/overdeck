# PAN-4597: Keep approved green PRs on Awaiting Merge

**Issue:** [PAN-4597](https://github.com/eltmon/overdeck/issues/4597) · **PR:** #4607

This PRD was written after the implementation, from the issue body and its comment, so the plan checklist matches the shipped work.

## Glossary

- **Derived `ready`:** the issue state `deriveState` returns in `src/lib/overdeck/derived-issue-state.ts`. Awaiting Merge (`selectAwaitingMerge`) and the issue view's **Merge to main** (`canMerge` in `src/dashboard/frontend/src/lib/issueActions.ts`) both read it.
- **Gate answer:** the merge gate's per-head approval answer, which `evaluateIssueMergeGate` records in `src/lib/cloister/approval-at-head.ts`. It lives `GATE_ANSWER_TTL_MS` (5 minutes).
- **UAT-train tick:** the 60-second interval started by `startUatTrainReconciler` in `src/dashboard/server/main.ts`.

## Root cause

`ready` requires `prApprovedAtHead === true`, which comes from the cached gate answer. Only auto-merge, the merge doors and the post-merge sibling walk ran the gate. So a PR held for UAT was `ready` for five minutes after another merge, then decayed to `in-review`. That emptied Awaiting Merge and hid **Merge to main**.

## Requirements

- **FR-1:** `approval-at-head.ts` exposes `GATE_ANSWER_TTL_MS`, `GATE_ANSWER_REFRESH_AFTER_MS` (3 minutes) and `approvalAtHeadNeedsRefresh(issueId, head)`. The module stays import-free.
- **FR-2:** `listOpenPullRequestsForProject` returns a project's open, non-draft PRs or MRs by issue, from the cached forge listings.
- **FR-3:** On each UAT-train tick, a refresher re-runs `evaluateIssueMergeGate` for every PR that the forge reports approved, green and mergeable, when its answer is missing, belongs to another head, or is past the refresh age. It tries each issue head at most once per refresh window. The forge's `reviewDecision` selects candidates only; it never derives `ready` (#3983, #4066).
- **FR-4:** The issue view's **Merge to main** appears for the same PR, because `canMerge` reads the same derived state.
- **FR-5:** `docs/MERGE-WORKFLOW.md` states what makes a PR appear on Awaiting Merge.

## Acceptance criteria

- **Decay without refresh:** with fake timers, an answer older than `GATE_ANSWER_TTL_MS` derives `in-review` when no tick runs.
- **No decay with refresh:** with ticks every minute, the PR stays `ready` for 12 minutes.
- **One gate call per head per window:** a new head is asked at once.
- **Candidates:** only approved, green, mergeable PRs are candidates.
- **Docs:** `docs/MERGE-WORKFLOW.md` contains the section "What makes a PR 'ready'".
