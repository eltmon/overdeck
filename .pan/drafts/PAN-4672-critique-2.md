## blocks-the-design: Temp compose write can expose or overwrite another file

The PRD's exact replacement at `/home/eltmon/Projects/overdeck/workspaces/feature-pan-4672/.pan/drafts/PAN-4672.md`, lines 101–109, uses a predictable `${process.pid}.tmp` path and `writeFileSync(tmpPath, after, 'utf-8')`. That opens an existing path with truncation and follows symlinks. On this host, `stat -c '%a %n' /home/eltmon /home/eltmon/.overdeck /home/eltmon/.overdeck/traefik` returns `750`, `775`, `775`: a group member can place a symlink at the predictable path before migration and make the write truncate another file the CLI can access. Also, a compose file with mode `0600` is first written to a temp file with the default `0666 & umask` mode (typically `0644`); the later `chmodSync` cannot undo that exposure. The planned test checks only the final mode under umask `077`, so it misses both cases. The repository already uses exclusive temp-file creation in `/home/eltmon/Projects/overdeck/workspaces/feature-pan-4672/src/lib/projects-config-write.ts`, lines 63–85.

Change work item 1 to create the temp file exclusively with initial mode `0600` (or stricter), write through its file descriptor, then set the preserved mode before rename. Clean up only a temp file this call created. Add a test for an existing temp path and a test that observes the temp mode before `chmodSync`.
