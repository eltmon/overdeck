# PAN-4638 — Run gauntlet lanes on any linked machine: desktop, laptop and Fly VMs

**Issue:** [PAN-4638](https://github.com/eltmon/overdeck/issues/4638) · **Epic PRD:** `.pan/drafts/pan-2350.md` (Overdeck Anywhere, revision 5), work item **W-WORK3**, requirements **FR-10** (lanes part), **FR-22**, **FR-23**, decision **D-19**. **Builds on:** PAN-4645 (links), PAN-4651 (`--machine`, Auto placement, work doors, worker stand-ins and follower), PAN-4652 (Fly machines). All three are merged on `main` (`1c20fe2c38b`, `4758883f0dd`, `895b013cc77`).

**Status:** draft for `pan plan --auto`, written 2026-11-01 against `main` at `4a774743263`.

## Summary

Today `pan lane start --machine <label|auto>` resolves a target, launches only when the target is this machine, and refuses any other machine with `Lanes on other machines arrive with PAN-4638 (chosen: <label>)` (`src/cli/commands/lane.ts:179-186`). This issue makes the other machine run the lane.

The design splits the lane door in two:

- **Home** (the orchestrator's machine) keeps every rule that needs the run's rows: parent and launcher standing (D8), run (D4), critic link and the default `--at` (WI-19 of PAN-4223), iteration (D7), idempotency (FR-6), model, harness and effort. Then it calls the owner and writes a **remote lane stand-in** on disk.
- **The owner** (the machine that runs the lane) does only the local work: worktree, brief, conversation row, runtime start with the lane contract. It is a new work door, `POST /api/machines/work/lanes`.

A home follower mirrors the owner's reports and liveness into the stand-in, so `pan lane list|show|wait|stop|reap` work from the orchestrator as they do today. The merged conversation list stamps lane facts onto the owner's linked row, so the dashboard nests a remote lane under its orchestrator without frontend changes.

## Glossary

| Term | Meaning |
| --- | --- |
| Home | The machine where the orchestrator conversation runs and where `pan lane start` is called. |
| Owner | The linked machine that runs a remote lane (PAN-4650 vocabulary). |
| Remote lane | A lane whose conversation runs on an owner, not on home. |
| Local lane | A lane whose conversation runs on home (today's only kind). |
| Stand-in | Home's on-disk record of a remote lane: `~/.overdeck/remote-lanes/<name>/lane.json` (launch facts, write-once), `mirror.json` (the follower's copy of owner state), `archived.json` (written once by reap). Reports are mirrored to `~/.overdeck/agents/conv-<name>/reports/`. It is never a row in `conversations` (epic D-5). |
| Lane row | The shape `listAllLaneRows()` returns: one entry per local lane (from `conversations`) or remote lane (from the stand-in store). |
| Cwd key | The string iteration counting (D7) groups on: the local `cwd`, or `<environmentId>:<cwd>` for a remote lane. |
| Owner door | `POST /api/machines/work/lanes` and its two siblings, `GET …/lanes/:name/status` and `POST …/lanes/:name/reap`, on the owner. |
| Linked row | A row of another machine's conversation in home's merged list (`linkedListRow`, `src/lib/overdeck/linked-conversations-merge.ts:43`), id `-<linked_conversations.id>`, name `@<environmentId>/<name>`. |
| Fly machine | A Fly.io VM running `pan serve`, linked one way from home (PAN-4652); label `fly-<machineId>`. |
| Actor | Who a link request acts as: `operator` or `agent:<id>` (`linkActorHeaders`, `src/lib/anywhere/link-client.ts`). |

## Background (verified 2026-11-01)

- `launchLane` (`src/lib/lanes/launch.ts:306`) resolves parent, launcher (D21), run, critic link, project config, model and harness, then under `withProjectLock` (`:374`) checks idempotency with `occupies()` (`:376`, `isAlive(row.tmuxSession)`), counts iterations over `listLaneConversations` rows (`:383`), creates the worktree, writes the brief, calls `createConversation` with `parentName` and `lane` (`:483` onward) and starts the runtime with `laneContract(...)` (`:508`). The CPU check (`:323-331`) refuses with 429 `cpu-saturated` unless `force`.
- `createConversation` (`src/lib/overdeck/conversations.ts:721`) throws `a lane needs a parent` without `parentName`; `parent_conversation_id` and `critic_of_conversation_id` are foreign keys to local rows (`src/lib/overdeck/infra.ts:143,150`). It calls `vacateConversationName(db, opts.name, now)` (`:735`), which replaces a same-name row.
- `pan lane report` (`src/lib/lanes/report.ts`, `reportLane`) runs inside the lane, reads its row by `$OVERDECK_CONVERSATION` and refuses unless the row has `laneKey`, `laneRole` and `gauntletRun`. Reports go to the worker report store keyed `conv-<name>` (`src/lib/agents/worker/report.ts`).

- `waitForLane` (`src/lib/lanes/wait.ts:71`) judges liveness with `conversationHarnessAlive(conv-<name>)` on this machine; `waitForLaneSet` lists lanes through `GET /api/lanes` and reads reports from the local store.
- The CLI resolves `<lane>` only from local `conversations` (`resolveLaneLocally`, `src/cli/commands/lane.ts:65`).
- PAN-4651 precedent for workers: `POST /api/fleet/workers` writes a stand-in (`src/lib/agents/worker/remote-standin.ts`, `remote.json`, `mirrorRemoteReport` keeps `git` and `verdict`), and `RemoteWorkerFollower` (`src/dashboard/server/services/remote-worker-follower.ts`, started in `anywhere-boot.ts:168`) polls the owner every 5 s while the link is online and backs off 1 s doubling to 300 s ±20 % while not.
- Owner work doors (`src/dashboard/server/routes/machines-work.ts`): `workDoorPreflight` (`:82`) requires a `machine` credential (403 `machine-only`) and matches the project by git origin (404 `project-missing`). `markConversationStartedBy` (`src/lib/overdeck/conversation-provenance.ts`) stamps `started_by_environment_id`. The agent fence (`src/dashboard/server/link-fence.ts:34-39`) refuses agent actors on `POST /api/lanes` and on conversation writes unless the conversation was started by the caller's environment.
- `resolveTargetMachine(machine, gitOrigin, needs)` (`src/dashboard/server/services/fleet-target.ts:89`) returns `{ ok, self, link, environmentId, label, reason }` or `{ ok: false, status, body }`; `fly` answers 400 `fly-unavailable`. `ownerRefusal` (`src/dashboard/server/routes/fleet-work.ts:164`) rewrites `project-missing` with the `pan machines add-project` hint.
- `fetchBase` (`src/lib/lanes/worktree.ts`) runs `git fetch origin` (all branches), so a commit a builder pushed is present on the owner after it.
- Fly machines (PAN-4652): `pan serve` runs with `HOME=/` and the project clone at `/workspace/<key>` (`docs/ANYWHERE-ARCHITECTURE.md` "Fly machines"). Docker runs with `--storage-driver=vfs`; the `docker` capability tag comes from `docker info` (`src/lib/anywhere/machine-capabilities.ts`). Fly machines run Claude Code only (#4296).
- The Command Deck tree nests rows by `parentConversationId` and, for critics, `criticOfConversationId` (`displayParentId`, `src/dashboard/frontend/src/components/CommandDeck/conversation-tree.ts:67`); the Awareness rail folds rows with `gauntletRun` + `laneKey` into run cards (`components/sessionFeed/gauntletRunEntries.ts`).

## Requirements

### Functional

- **FR-1 Remote launch.** `pan lane start … --machine <label|environment-id|auto> [--needs <tags>]` runs the lane on the chosen machine when that machine is not home. Home sends `machine` and `needs` in the `POST /api/lanes` body; the route resolves the target with `resolveTargetMachine`. When the target is home, the launch is today's local launch.
- **FR-2 Home owns the run rules.** Parent, launcher standing, run, critic link and default `--at`, iteration, idempotency (one live lane per run, key and role) and `--replace` apply across local and remote lanes of the run.
- **FR-3 Owner door.** `POST /api/machines/work/lanes` (machine credential only) creates the lane's directory under the owner's lanes root, writes the brief, creates a lane row with lane facts and no parent, stamps `started_by_environment_id` with home's environment, and starts the runtime with the lane contract. `pan lane report` inside the lane works on the owner as on home.
- **FR-4 Stand-in and mirroring.** Home writes a stand-in before calling the owner and removes it when the owner refuses. A follower mirrors the owner's reports (with `git` and `verdict`), activity, last activity time, git facts and cost into the stand-in.
- **FR-5 Listing.** `GET /api/lanes`, `GET /api/lanes/:name`, `pan lane list` and `pan lane show` include remote lanes, with `machine: { environmentId, label, reachable, lastSeenAt }` (null for local lanes). Remote lanes have `id: null`; the CLI table prints the lane name in `ID` and the machine label in a new `MACHINE` column.
- **FR-6 Waiting.** `pan lane wait <lane>` and `pan lane wait --run|--parent` return a remote lane's reports with the same exit codes. An unreachable owner counts as alive and never trips the idle timeout.
- **FR-7 Stop and reap.** `pan lane stop <lane>` and `pan lane reap <lane> [--park] [--keep]` on a remote lane run on the owner through the link; reap then archives the stand-in. Neither discards work.
- **FR-8 Nesting in the dashboard.** In `GET /api/conversations` (page 1), the linked row of a remote lane carries `parentConversationId`, `parentConversationName`, `gauntletRun`, `laneKey`, `laneRole` and `criticOfConversationId` from the stand-in, so the Command Deck nests it under the orchestrator and the Awareness rail counts it in the run card.
- **FR-9 Critic across machines.** A critic or verifier on any machine may judge a builder on any machine. The judged commit must be on `origin`; the owner fetches it and refuses with 400 when it is missing.
- **FR-10 Fly machines are ordinary targets.** A linked Fly machine is chosen by label or by Auto like any linked machine. A lane whose resolved harness is not `claude-code` is refused on a Fly machine with 400 naming #4296.
- **FR-11 Agent fence.** An agent actor on a link may use the owner door. It may not use `POST /api/lanes/:name/reap` on another machine (new fence rule); the owner reap door checks provenance.

### Non-functional

- **NFR-1 No placeholder rows.** Home never inserts a `conversations` row for a remote lane (epic D-5).
- **NFR-2 Async only.** Every git, file and network call on the server is async; no `execSync`.
- **NFR-3 One writer per stand-in file.** `lane.json` is written once by the launch, `mirror.json` only by the follower, `archived.json` once by reap. Writes are temp file plus `rename`, mode 0600.
- **NFR-4 Tests use fakes and fake timers.** The follower's poll and back-off tests use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`; no real delays (repo rule "Fake timers for retry/backoff tests").
- **NFR-5 Bounded follower load.** One poll per running stand-in every 5 s while its link is online; at most 20 reports per poll.

## Decisions

- **D-4638-1 Validate at home, execute on the owner.** Home has every row of the run; the owner has none. So home computes `iteration`, `branch`, base, `at`, `answering`, title and brief header, and the owner receives them precomputed. The owner never reads run rows.
- **D-4638-2 Home allocates the conversation name.** Home picks a name with `generateConversationName()` that is free locally and in the stand-in store and sends it. The owner refuses an existing name with 409 `name-taken` and never vacates it (`createConversation` gains `refuseExistingName`). Home retries with a new name up to 3 times on `name-taken`. So a remote lane has the same name on both machines, and `conv-<name>` keys the report store on both.
- **D-4638-3 The owner's lane row has no parent.** `createConversation` accepts `lane` without `parentName` only when `remoteLaunch: true`. The owner door then calls `markConversationStartedBy(name, credential.environmentId)`. The parent link lives in home's stand-in.
- **D-4638-4 Stand-in store, not `conversations`.** See Glossary. The store directory is `~/.overdeck/remote-lanes/` so listing is one `readdir` of a small directory. Reports are mirrored to `agents/conv-<name>/reports/` so every existing report reader works unchanged. The stand-in is never deleted after a successful launch, because D7 counts archived lanes.
- **D-4638-5 Iteration groups on the cwd key.** Two machines with the same home layout produce the same path string, so a remote lane's cwd key is `<environmentId>:<cwd>`.
- **D-4638-6 Pairing keys on names.** `PairingRow.id` becomes `number | null`, `PairingRow.criticOfId` becomes `criticOfName: string | null`, and `pairing.ts` maps by name. `LaneView.id` becomes `number | null`. `CriticSummary.id` becomes `number | null`.
- **D-4638-7 A local critic of a remote builder.** The FK cannot point at a stand-in, so home writes `~/.overdeck/agents/conv-<critic>/lane-link.json` `{ "criticOfName": "<builder>" }` (write-once) and creates the row without `criticOfName`. `listAllLaneRows` reads the sidecar for local critic and verifier rows whose FK is null. A remote critic's link is in its stand-in.
- **D-4638-8 Reuse follows the newest lane.** `--reuse` continues in the newest lane's directory on that lane's machine. `--machine` together with `--reuse` is 400 `--reuse continues on the newest lane's machine; drop --machine`.
- **D-4638-9 Orchestrator lanes stay home.** `--role orchestrator` with a remote target is 400 `orchestrator lanes run on the orchestrator's machine`. An orchestrator lane on the owner would launch lanes listed only there.
- **D-4638-10 CPU check where the lane runs.** A remote launch skips home's CPU check; the owner door runs `assessCpuPressure()` and answers 429 `cpu-saturated` unless `force`.
- **D-4638-11 Harness resolved at home, checked on the owner.** Home resolves model and harness from home's gauntlet config (as today). The owner door re-runs `resolveAllowedHarness(harness, model)` and answers 400 on a refusal. Home refuses a non-`claude-code` harness for a Fly machine target before calling it (FR-10).
- **D-4638-12 Actor.** `pan lane start` sends `x-overdeck-sender` (`senderFromEnv().id`), and the route forwards with `actorForSender` (`src/dashboard/server/linked-conversation-proxy.ts:95`), so an orchestrator agent reaches the owner as that agent. The follower polls as `operator`. A `POST /api/lanes` that arrived through a secure channel may not place a lane on another machine (403 `no-chained-hops`), the same rule as the fleet routes.
- **D-4638-13 Stop and reap through the owner.** Home's new `POST /api/lanes/:name/stop` forwards a remote lane to the owner's `POST /api/conversations/<name>/stop` (allowed by the fence because of provenance). Home's `POST /api/lanes/:name/reap` forwards to the owner reap door, then writes `archived.json` unless `keep`. An owner 404 still archives the stand-in, with a warning. An unreachable owner answers 503 and archives nothing.
- **D-4638-14 No stop cascade.** Local lanes do not stop when the orchestrator ends, so the follower does not stop remote lanes when the parent ends.
- **D-4638-15 Messaging a remote lane.** `pan tell @<label>/<name>` (PAN-4650) reaches it. `LaneView.machine` tells the orchestrator which form to use; `pan tell conv-<name>` on home is not forwarded.
- **D-4638-16 `fly` stays with #4743.** `--machine fly` (a new VM per lane), `remote.auto_fly` and `gauntlet.fly.max_vms` are #4743's. A lane runs on a Fly machine made with `pan machines add-fly --project <key>`, named by label or chosen by Auto. A linked Fly machine is an ordinary Auto candidate, because it is linked and already paid for; the D-19 Fly exclusion is about creating a new VM.
