# PAN-4634: Put GPT-6.1 Terra on the claude-code route (no CLIProxy pin bump)

**Issue:** [PAN-4634](https://github.com/eltmon/overdeck/issues/4634) — follow-up from [PAN-4633](https://github.com/eltmon/overdeck/issues/4633) decision D8.

## Summary

The issue assumed the pinned CLIProxyAPI (v7.3.16) cannot serve `gpt-6.1-terra` and that a pin bump would fix it. A re-probe on 2026-11-11 shows that the pinned v7.3.16 binary now serves `gpt-6.1-terra` under ChatGPT sign-in, with no binary or config change. CLIProxy refreshes its model catalog every 3 hours from a remote file (`https://raw.githubusercontent.com/router-for-me/models/refs/heads/main/models.json`), and Terra entered that catalog on 2026-10-26 at 23:15 UTC, after the PAN-4633 probe. So this issue does **not** bump the pin. It adds `gpt-6.1-terra` to the claude-code 272K route set, replaces the negative-probe notes with the dated positive probe, and updates the docs and the changelog.

## Glossary

- **CLIProxy / CLIProxyAPI** — the local sidecar (`router-for-me/CLIProxyAPI`) on `127.0.0.1:8317`. It exposes an Anthropic-compatible `/v1/messages` endpoint backed by ChatGPT-subscription OAuth, so the claude-code harness can drive GPT models. Lifecycle code: `src/lib/cliproxy.ts`.
- **Pin** — `CLIPROXY_RELEASE_VERSION` in `src/lib/cliproxy.ts`, the release `pan install` downloads. Today `'v7.3.16'`.
- **claude-code route** — a `claude-code` harness session on an OpenAI model. Launch env points `ANTHROPIC_BASE_URL` at CLIProxy.
- **`GPT_56_MODELS`** — the `Set` in `src/lib/agents/provider-env.ts` of OpenAI ids that the claude-code route pins to the 272K billing tier (`CLIPROXY_GPT56_CONTEXT_WINDOW` = 272000) for both `CLAUDE_CODE_MAX_CONTEXT_TOKENS` and `CLAUDE_CODE_AUTO_COMPACT_WINDOW`. The name is kept for continuity; it holds GPT-6 ids too.
- **Capability fallthrough** — the last branch of `getClaudeCodeContextPolicyForModel`: an id not in `GPT_56_MODELS` but present in `MODEL_CAPABILITIES` gets both env values from its `contextWindow`.
- **Probe** — a direct HTTP request to the running CLIProxy (`GET /v1/models`, `POST /v1/messages`) plus a `claude --print` round trip through it.

## Decisions

- **D1 — No pin bump.** v7.3.16 serves Terra today because its remote catalog refresh picked Terra up, so `CLIPROXY_RELEASE_VERSION` stays `'v7.3.16'`. A 7.x → 8.x jump is a major version with unverified changes to the version banner, `oauth-model-alias` and the management API. Nothing in this issue needs it. The issue scope allows "the CLIProxy version (or config) that serves" Terra; the answer is the current version.
- **D2 — Add `gpt-6.1-terra` to `GPT_56_MODELS`.** This is behavior-neutral for the launch env: Terra's capability `contextWindow` is already `CLIPROXY_GPT56_CONTEXT_WINDOW`, so the fallthrough already returns 272000/272000. The change makes the route explicit and keeps the set aligned with "ids CLIProxy serves at the 272K pin". The existing test `src/lib/__tests__/model-capabilities.test.ts` (the `it.each([... 'gpt-6.1-terra' ...])('feeds the same window to the harness env exports and the capability table for %s'` block near line 71) already proves the 272K result and must keep passing. No new test: a test that reads the Set literal from source is rejected by the source-grep lint, and the policy result cannot distinguish set membership from the fallthrough.
- **D3 — `gpt-6-rosalind` and `gpt-6-astra-law` stay out of `GPT_56_MODELS`.** Neither is in today's `/v1/models` list.
- **D4 — Word the docs as a dated probe under ChatGPT sign-in, not as a version guarantee.** The served list comes from a remote catalog that changes with no pin change, so docs say "verified on <date>", never "CLIProxy 7.3.16 serves X" without a date.
- **D5 — Keep the 2026-09-29 claim dated in the docs.** `gpt-6-sol` was served on 2026-09-29 and is not served today. This issue does not fix or re-document `gpt-6-sol`; the existing dated sentence stays as is, and the new Terra sentence carries its own date.
- **D6 — Add "GPT-6.1 Sol and Terra" to the 272K sentence in `configuration/harnesses.mdx`.** `gpt-6.1-sol` is already in `GPT_56_MODELS` but missing from that sentence; listing only Terra would leave the sentence wrong in a new way.
- **D7 — Changelog: add one bullet to the v0.78.0 Upcoming block.** The shipped v0.77.0-or-earlier entry at `changelog.mdx:205` stays unchanged (shipped history).
