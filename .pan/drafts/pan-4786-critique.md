## blocks-the-design: Live workers ignore the changed checklist option

The PRD says resolving `skipPlanChecklist` before `runSupervisedVerification` makes joins correct (Approach, W2). The supervisor compares options only when adopting a *finished* result: [verification-worker-supervisor.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/lib/cloister/verification-worker-supervisor.ts), lines 255-273. Its live-worker join at lines 327-333 checks the head and deadline, but never `sameOptions`; its in-process `activeSupervisorRuns` map at lines 395-409 returns the existing promise by issue ID without checking options. A request made after an xBRIEF appears can therefore reuse a running `skipPlanChecklist: true` verification and skip the checklist despite FR-2. A request after this fix is deployed can also reuse a running worker with the old `false` option and fail the adopted PR again. W2's test mocks the supervisor, so it cannot catch either case. Make both live reuse paths option-sensitive and add a test that changes `skipPlanChecklist` while a worker is active.

## blocks-the-design: The helper adds synchronous server I/O

NFR-2 at [pan-4786.md](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/.pan/drafts/pan-4786.md), lines 108-109, requires no new synchronous I/O in server-reachable code. W1's proposed async helper calls `readPipelineJournal` at lines 140-142 and explicitly forbids an async twin at lines 160-163. [pipeline-journal.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4786/src/lib/cloister/pipeline-journal.ts), lines 125-147, uses `existsSync` and `readFileSync` and parses the entire journal. Thus every new verification-door call can block the dashboard event loop while it reads the journal; an `async` function signature does not change that. Use an async journal reader with the same malformed-line behavior, or revise NFR-2 explicitly if synchronous reads are an accepted design choice.
