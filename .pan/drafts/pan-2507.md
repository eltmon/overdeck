# PAN-2507 — Preemptive pipeline scheduler: yield idle work agents to unblock advancing dispatch

**Status:** draft · **Author:** operator-directed design, 2026-07-08 · **Executor note:** this PRD is written to be implemented without re-research. Every file/line reference was verified against main at commit `8c38076b6a`. Where a line number may have drifted, a search string is given.

## Problem

When a review/test/merge ("advancing") dispatch cannot reserve capacity, the deacon logs and defers to the next patrol — forever, if work agents keep the box full. Meanwhile the work agents it defers *behind* are often idle (waiting on their own reviews). Nothing ever pauses a work agent to let an advancing agent run, so the pipeline's *drain* starves behind its *fill*. The operator's goal: fine-grained micromanagement — stop and restart agents as needed so issues are never blocked and throughput is maximal.

Today's only mitigations, both static:
- 3 reserved advancing slots above the work cap (`reserved_advancing_slots`, `src/lib/cloister/config.ts`, search `reserved_advancing_slots: 3`).
- The memory governor sheds only under HARD memory pressure (`shed()` in `src/lib/cloister/memory-governor.ts`), which is an OOM defense, not a throughput scheduler.

## Glossary

- **Work agent** — implementation agent, role `work`, id `agent-<issue>` (or swarm slot `agent-<issue>-slot-N`).
- **Advancing agent** — role `review`, `test`, or `ship`; unblocks merges. Advancing agents run inside the issue's existing workspace — they create **no new docker stack**; their marginal footprint is one `claude`/`codex` process (~1 GB).
- **Slot** — a unit of the count ceiling in `src/lib/cloister/concurrency.ts` (`getConcurrencyLimits()`).
- **Yield (preemption)** — the scheduler pausing a running work agent (session killed, state preserved, resumable via `--resume`) to free capacity for an advancing dispatch. Distinct from an operator pause.
- **Idle** — `isAgentIdleForNudge(sessionName)` returns true (Stop-hook state; defined in `src/lib/cloister/deacon.ts`, search `function isAgentIdleForNudge`).
- **Patrol** — the deacon's periodic cycle (`runDeaconCycle` in `src/lib/cloister/deacon.ts`).

## Priority model (the decision, made here)

Capacity contention resolves in this fixed priority order — higher preempts lower, never the reverse:

1. **merge/ship** (frees an entire workspace + docker stack — the most memory-positive action)
2. **test**
3. **review**
4. **work-rework** (work agent addressing blocked-review feedback)
5. **work-new** (fresh implementation)

Preemption only flows *down* this list: an advancing dispatch may yield a work agent. New work NEVER preempts anything. Advancing roles never preempt each other.

## Requirements

- **FR-1** When `tryReserveAdvancingSlot()` fails (count) or `canDispatchAdvancing()` is memory-gated, the dispatcher must attempt a **yield**: select a victim work agent, pause it with scheduler attribution, re-attempt the reservation, and proceed with the dispatch if it now succeeds.
- **FR-2** Victim selection predicate (ALL must hold): role `work`; status `running`; `isAgentIdleForNudge(sessionId)` true; not operator-attached (`tmux -L overdeck list-clients -t <session>` empty — use existing async tmux helpers); `paused !== true`; not within its post-resume yield cooldown (FR-6). Among eligible victims pick, in order: (a) an agent whose own issue has `reviewStatus ∈ {pending, in_progress}` — it is blocked on the pipeline anyway; (b) longest-idle by `lastActivity` ascending.
- **FR-3** A yielded agent is recorded with `paused: true`, `pausedReason: "yield: making room for <role> of <ISSUE>"`, plus two NEW `AgentState` fields: `yieldedByScheduler: true`, `yieldedAt: <ISO>`. Reusing `paused` means every existing no-resume gate (deacon skip paths, boot reconciliation candidate exclusion, spawn refusal) protects yielded agents with zero extra wiring.
- **FR-4** Resume-yielded-first: at the top of `autoResumeStoppedWorkAgents` (`src/lib/cloister/deacon-auto-resume.ts`, search `autoResumeStoppedWorkAgents started`), before normal candidates, resume agents with `yieldedByScheduler === true` — oldest `yieldedAt` first — but only when a slot AND the memory gate allow (same per-iteration `assessMemoryPressure()` brake). Resuming clears `paused`, `pausedReason`, `yieldedByScheduler`, `yieldedAt`.
- **FR-5** An operator `pan unpause` on a yielded agent also clears the two yield fields (one code path: extend `clearAgentPausedSync` in `src/lib/agents/agent-state.ts`, search `export function clearAgentPausedSync`).
- **FR-6** Anti-thrash: (a) an agent resumed from yield may not be re-yielded for `yield_cooldown_secs` (default 600) — track via `lastYieldResumeAt` on `AgentState`; (b) at most `max_yielded` (default 3) agents may be in yielded state at once; (c) a yield happens only when the reservation retry will actually succeed (re-check after pausing; if it still fails, resume the victim immediately and log).
- **FR-7** Config, in `~/.overdeck/cloister.toml` under `[concurrency]` (extend `ConcurrencyConfig` in `src/lib/cloister/config.ts`, search `export interface ConcurrencyConfig`): `preemption` (bool, default **false** — opt-in), `max_yielded` (default 3), `yield_cooldown_secs` (default 600). Defaults added to `DEFAULT_CLOISTER_CONFIG` (search `max_work_agents: 6`).
- **FR-8** Observability: every yield and yield-resume emits a `logDeaconEventSync` line AND an activity-feed entry (`emitActivityEntrySync`) reading as a plain sentence, e.g. `Yielded agent-pan-1234 (idle 22m) to run review for PAN-5678`. The dashboard agent card shows the `pausedReason` already — no frontend work required beyond that string.
- **NFR-1** All new tmux interaction uses async primitives (`sendKeysAsync`, `killSession` Effect) — never sync. No `execSync` anywhere server-reachable.
- **NFR-2** Delay/cooldown tests use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` — never real timers (repo rule).
- **NFR-3** The yield pause must go through the existing pause write path (`saveAgentStateSync` after setting fields — mirror how `pan pause` sets them; see `applyAgentUnpaused` neighborhood in `src/lib/agents/agent-state.ts`), never a direct DB write (two-doors tenet).

## Design

### New module: `src/lib/cloister/preemption.ts`

Single owner of yield mechanics. Public surface (pinned):

```ts
export interface YieldOutcome { yielded: boolean; victimId?: string; reason?: string }

/** FR-2 predicate + ordering, pure & unit-testable: pass in candidates. */
export function selectYieldVictim(
  candidates: readonly YieldCandidate[], nowMs: number, cooldownSecs: number,
): YieldCandidate | null

/** FR-1 flow: pick victim → pause+stop (async) → return outcome. */
export async function yieldWorkAgentFor(role: 'review'|'test'|'ship', issueId: string): Promise<YieldOutcome>

/** FR-4: resume yielded agents oldest-first while capacity allows. Returns resumed ids. */
export async function resumeYieldedAgents(maxToResume: number): Promise<string[]>
```

`yieldWorkAgentFor` implementation steps: read config (`preemption !== true` → `{yielded:false}`); count current yielded (`listAgentStates` filter `yieldedByScheduler`) vs `max_yielded`; build candidates from `listRunningAgentsSync()` + runtime idle state; `selectYieldVictim`; set pause+yield fields via agent-state save; `stopAgentSync(victimId)` (search `export function stopAgentSync` in `src/lib/agents/termination.ts`); log + activity entry.

### Wire points (exact, six sites)

Replace the bare defer at each with a yield attempt. Pattern:

```ts
// BEFORE
if (!tryReserveAdvancingSlot()) { …defer log…; continue; }
// AFTER
if (!tryReserveAdvancingSlot()) {
  const y = await yieldWorkAgentFor(role, issueId);
  if (!y.yielded || !tryReserveAdvancingSlot()) { …existing defer log…; continue; }
}
```

1–5. `src/lib/cloister/deacon-review-status.ts` lines 372, 533, 586, 740, 835 (search `if (!tryReserveAdvancingSlot())` — five occurrences; each site knows its role/issueId locally).
6. `src/lib/cloister/deacon.ts` line 1307 (same search).

Memory-gated case: `canDispatchAdvancing`/`tryReserveAdvancingSlot` already return false when the cached memory band ≠ ok (`src/lib/cloister/concurrency.ts`, search `getCachedMemoryVerdict`). Pausing an idle work agent frees its process RSS (~1–2 GB), which is exactly the marginal footprint the advancing agent needs — so the same yield path covers both count- and memory-blocked dispatches. After a yield, `await assessMemoryPressure()` once (RSS settle ~2s, mirroring `RSS_SETTLE_MS` in `deacon-auto-resume.ts`) before the retry.

### Resume path (FR-4)

In `autoResumeStoppedWorkAgents` (`deacon-auto-resume.ts`), immediately after the concurrency-limits/hold-set setup and BEFORE the normal candidate loop, insert: `const resumedYielded = await resumeYieldedAgents(workSlots);` and decrement the remaining budget by its length. `resumeYieldedAgents` uses the existing `resumeAgent(agentId)` (`src/lib/agents/resume.ts`, search `export async function resumeAgent`) and stamps `lastYieldResumeAt`.

### AgentState fields

Add to the `AgentState` interface (`src/lib/agents/agent-state.ts`) and the agents-table serialization (`src/lib/database/schema.ts` agents DDL + `AGENT_COLUMNS_FOR_DB` in `src/lib/overdeck/agent-state-sync.ts`): `yieldedByScheduler?: boolean`, `yieldedAt?: string`, `lastYieldResumeAt?: string`. Follow the exact pattern of the existing `paused`/`pausedAt` columns (nullable INTEGER/TEXT; requires a schema migration bump — mirror the most recent migration in `src/lib/database/schema.ts`).

## Acceptance criteria (map 1:1 to work items)

- AC-1 Unset config yields defaults `preemption=false, max_yielded=3, yield_cooldown_secs=600`; `preemption=false` produces zero behavior change at all six sites (test-locked).
- AC-2 Yield fields persist through the agents table and are cleared by both scheduler resume and operator unpause.
- AC-3 `selectYieldVictim` never returns a non-idle, attached, operator-paused, or cooling-down agent (property covered by the test matrix).
- AC-4 With the ceiling full and one idle work agent, a blocked review dispatch yields it and dispatches within the same patrol; with zero eligible victims it defers exactly as today.
- AC-5 A yielded agent resumes before any other stopped candidate once capacity exists, and never while the memory band ≠ ok.
- AC-6 A resumed-from-yield agent is not re-yielded within the cooldown (fake-timer test).
- AC-7 Every yield/resume appears in the activity feed as a full sentence naming both agents' issues.

## Out of scope

- Preempting non-idle (actively working) agents — a future escalation tier; requires checkpoint semantics.
- Cross-project fairness weighting; docker-stack stop/start as a yield mechanism (stack teardown is too slow/disruptive for slot-granularity scheduling — the memory governor's shed ladder already owns stack reclaim under pressure).
- Dashboard UI beyond the `pausedReason` string.
