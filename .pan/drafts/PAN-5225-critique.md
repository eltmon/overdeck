## blocks-the-design: MIN-1139 cannot pass the requested close-out

The PRD says the issue requires both issues to close without `--accept-*`, then scopes that requirement away for MIN-1139 (PRD lines 76 and 321). WI-7 explicitly expects `verification: miss` and `passed false` for MIN-1139 (line 297). The code confirms the result: `checkVerificationRow()` returns a miss for a failed artifact unless a terminal settlement applies (`src/lib/lifecycle/dod-gate.ts` lines 517–532), and `evaluateDodGate()` requires every miss to be accepted before `passed` is true (lines 944–956). `--force` only skips the CLI confirmation prompt (`src/cli/commands/close.ts` line 112). Thus the proposed acceptance check cannot establish the requested close-out. Keep the failed verdict strict, but make a fresh successful verification run or an explicit operator revision of the acceptance requirement a prerequisite; do not mark the narrowed result as satisfying the original requirement.

## blocks-the-design: Last-fetched target can give a false merged pass

D3a claims a remote-tracking target “only moves forward” and that its stale copy can “never” produce a false pass (PRD line 74). The actual fetch uses a leading `+` in `+refs/heads/<target>:refs/remotes/origin/<target>` (`src/lib/lifecycle/verify-merged.ts` line 30), which permits the tracked ref to move backward on a later successful fetch. If upstream `main` is rewound after the last fetch and the next fetch fails, WI-2's required test deliberately returns success from the old `origin/main` even though current upstream may no longer contain the feature (PRD line 169; ancestry check at `verify-merged.ts` lines 229–238). That can let the destructive close-out proceed on obsolete evidence. State the target-immutability assumption and enforce it, or make a failed fetch unable to produce a positive merged verdict without an independent current forge check. Retain the last-fetched ref for diagnostic comparison if useful.
