# PAN-4647: Auto-save pipeline agent transcripts to the Session Vault

**Issue:** [PAN-4647](https://github.com/eltmon/overdeck/issues/4647)
**Parent PRD:** `.pan/drafts/pan-2350.md` (Overdeck Anywhere, revision 5), work item **W-CONV6**, line 448.
**Supports:** PAN-2350 FR-6 and FR-9 (they read from a saved copy when the owner machine is offline).
**Builds on:** Session Vault Phase A (`src/lib/vault/`, PAN-2609) and its dashboard consumer (PAN-4307).

**W-CONV6 done when:** a finished work agent's transcript is a saved copy on the other machine after one sync.

---

## Glossary

- **Session Vault ("the vault"):** encrypted, off-machine transcript storage in a git or directory backend the operator owns. Code: `src/lib/vault/**`, CLI `pan vault`, dashboard consumer `src/dashboard/server/services/vault-*.ts`.
- **Native transcript:** the harness's own transcript file. Claude Code: `~/.claude/projects/<encoded cwd>/<session-id>.jsonl`. Codex managed agents: `~/.overdeck/agents/<agentId>/codex-home*/sessions/**/rollout-*.jsonl`.
- **Settle:** one call to `settle()` (`src/lib/vault/settle.ts`). It moves the lines a native transcript gained since the last settle into the vault, as encrypted chunks plus a new settlement on a **record**. The first settle of a file *mints* the record.
- **Record:** a `SessionRecord` (`src/lib/vault/format.ts`, `export interface SessionRecord`). It carries `title`, `harness`, `owner`, `cwd`, the chunk log and the settlements.
- **Saved copy:** the vault record of a transcript, as seen from another machine (PAN-2350 glossary).
- **Owned transcript:** a native path this machine has settled at least once. It is listed in `~/.overdeck/vault/index.json` (`local-index.ts`, `owned`). The sync cycle re-settles owned transcripts that grew; it never settles a file for the first time.
- **Sync cycle:** `syncOnce()` (`src/lib/vault/sync.ts`). Step 2 settles owned transcripts that grew; step 4 pulls every record into the machine-local list cache (`ListCacheRow`).
- **Browse copy / browse row:** after each sync, `refreshBrowseCache()` (`src/lib/vault/browse.ts`) writes a decrypted copy of every Claude Code or Codex record another machine owns, and `vault-browse-service.ts` mirrors it as a read-only `vault-<vaultId>` conversation row ("from `<machine>`").
- **Settle poller:** `createVaultSettlePoller()` (`src/dashboard/server/services/vault-settle-poller.ts`). Every 15 s it stats each tracked transcript; growth re-arms a `debounceSec` timer that settles with WIP mode `'auto'`; a subject that drops out of the tracked list is settled once with WIP mode `'force'` and forgotten. It runs only in the primary dashboard (`main.ts`, `startVaultService()`).
- **Poll subject:** one entry the poller tracks. Today every subject is an active managed conversation (`LegacyConversation`). This issue adds pipeline-agent subjects.
- **Pipeline agent:** any Overdeck-managed agent with a parseable `~/.overdeck/agents/<agentId>/state.json` (roles `plan`, `work`, `review`, `test`, `ship`, `worker`, `strike`, `flywheel`, `sequencer`, `knowledge`; `Role` in `src/lib/agents/role.ts`). Conversations (`conv-*` dirs) and external registrations (`ext-*` dirs, which have `registration.json` and no `state.json`) are not pipeline agents.
- **Tracking window:** the period in which a pipeline agent is a poll subject: while its `status` is `running` or `starting`, and for 30 minutes after it stopped (`AGENT_TRACK_AFTER_STOP_MS`).
- **Record title:** the `title` field written when a record is minted. Today it is the first human text of the transcript, cut to 80 characters (`transcriptFacts()` → `firstHumanText()`).

## Problem

Session Vault saves conversations automatically, but not pipeline agents. Verified on `356ce40ec91`:

1. The settle poller lists only active managed conversations:
   ```ts
   // src/dashboard/server/services/vault-settle-poller.ts:57
   function defaultListActive(): LegacyConversation[] {
     return listConversations().filter((conv) => conv.status === 'active' && (conv.harness === 'claude-code' || conv.harness === 'codex'));
   }
   ```
2. The sync cycle settles only transcripts that are already owned (`sync.ts`, step 2: `const owned = await listOwned();`). A transcript nobody settled once is never picked up.
3. The Claude Code `Stop` hook (`pan vault setup --hooks`, `src/cli/commands/vault/hooks.ts`) is opt-in and Claude-only. Codex pipeline agents keep their rollouts in a private `codex-home` under `~/.overdeck/agents/<id>/`, which `discover.ts` never walks.

So when the owner machine goes offline, the other machine has no saved copy of the work, review or test agent transcripts. PAN-2350 FR-6/FR-9 cannot show them.

A second problem appears as soon as pipeline transcripts are saved: their first human text is the orchestration kickoff, so the minted record title would read like `<pasted_content id="b626"> <overdeck-memory-context format="json"> {` (checked against `agent-pan-4630` and `agent-pan-4630-review` transcripts on this machine). The other machine could not tell which issue or role a saved copy belongs to.

## Approach

Reuse the existing settle and sync path. Feed pipeline agents into the existing settle poller as a second kind of poll subject, and give their records a readable title.

- A new dashboard module, `src/dashboard/server/services/vault-agent-subjects.ts`, lists pipeline agents inside the tracking window and resolves each one's current transcript through the one authoritative resolver, `resolveAgentTranscriptCandidate()` (`src/lib/agents/transcript-resolver.ts`, which reads the absolute path recorded in `sessions.json`).
- The settle poller accepts these subjects next to conversations. A subject arrives with its transcript path already resolved and a record title.
- `settle()` gains an optional `recordTitle`, used only when it mints a new record.
- Once the owner machine settles, nothing new is needed on the other machine: its next sync pulls the record into the list cache, and the browse service shows it as a read-only "from `<machine>`" row.

### Decisions

- **D-1 Use the poller, not a sync-cycle sweep.** Pipeline agents get exactly the conversation behavior: a debounced `'auto'` settle while the transcript grows, a `'force'` settle when the subject leaves, and the shutdown flush. One settle path (`settleOnQueue`, PAN-4455 D-6) serializes them with the sync cycle and hand-offs.
- **D-2 Every role, Claude Code and Codex only.** Every agent with a `state.json` is a candidate, so a new role is covered without a list to maintain. Only transcripts whose resolved candidate kind is `claude` (harness `'claude-code'`) or `codex` (harness `'codex'`) are tracked, because the vault can only browse and resume those two (`BROWSE_HARNESSES` in `browse.ts`; the conversation filter in `defaultListActive`). Other kinds are skipped silently.
- **D-3 Tracking window = running/starting, or stopped less than 30 minutes ago.** The end time is `stoppedAt`, else `lastActivity`. An agent with neither, and not running or starting, is not tracked. The 30-minute tail covers a dashboard restart (`pan reload` after every merge): an agent that finished while the dashboard was down is still inside the window at the next boot, gets a baseline on the first poll, and is force-settled when it ages out. There is no backfill of older agents.
- **D-4 Subject name embeds the transcript path:** `agent:<agentId>:<transcriptPath>`. When an agent starts a new session, its resolved path changes, the old subject drops out of the list, and the poller's existing leave branch force-settles the old file once. No new poller logic is needed for session changes.
- **D-5 Record title format.** `<issueId> <role> agent (<agentId>)`, for example `PAN-4630 work agent (agent-pan-4630)` and `PAN-4630 review agent (agent-pan-4630-review)`. When `issueId` is empty after trimming: `<role> agent (<agentId>)`. The title is applied only when `settle()` mints a record. Appends to an existing record never change its title, and P-6 forks keep their rule `<parent title> (continued on <label>)`. Conversations pass no `recordTitle`, so their titles are unchanged.
- **D-6 Agent copies appear as browse rows.** The browse path already turns every Claude Code or Codex record that another machine owns into a read-only "from `<machine>`" conversation row. This issue does not filter, group or relabel those rows. A merged or grouped list is W-CONV2 ([PAN-4650](https://github.com/eltmon/overdeck/issues/4650)); per-issue agent views across machines are [PAN-4651](https://github.com/eltmon/overdeck/issues/4651). The issue-first title lets the conversation search find an agent copy by issue ID.
- **D-7 No change to `src/lib/vault/**` beyond `settle.ts`.** The record format is unchanged (the title is an existing field), so the vault standalone import guard (`tests/unit/lib/vault/import-graph.test.ts`) is unaffected. All agent knowledge stays in the dashboard layer, which may import `src/lib/agents/*`.
- **D-8 Agent-state scan cadence.** `listAgentStatesAsync()` reads every `state.json` (about 900 on the operator's machine). The lister caches the scan for 60 s (`AGENT_LIST_TTL_MS`) and skips `conv-` and `ext-` directory names before any read. Transcript paths are re-resolved on every poll, but only for the agents inside the tracking window.
- **D-9 Remote (Fly) agents are skipped.** Their transcripts are on the VM. The resolver finds no local file, so they produce no subject.

## Requirements

### Functional

- **FR-1** With the vault on, the primary dashboard's settle poller tracks every pipeline agent inside the tracking window whose resolved transcript is a Claude Code or Codex file. It settles that transcript through `settleOnQueue` with WIP `'auto'` after `debounceSec` of quiet following growth, and with WIP `'force'` when the subject leaves the tracked list or the dashboard shuts down.
- **FR-2** The tracking window is: `status` is `running` or `starting`; or `Date.now() - Date.parse(stoppedAt ?? lastActivity) < 30 * 60_000`. Agents outside the window are not subjects.
- **FR-3** A record minted for a pipeline agent has the title from D-5. Conversation records keep `firstHumanText` titles.
- **FR-4** (W-CONV6 done-when) After the owner machine settles a finished work agent's transcript, one `syncOnce()` on another machine joined to the same vault produces a list-cache row with that record's `vaultId`, `title: '<ISSUE> work agent (<agentId>)'`, `harness: 'claude-code'` and `ownerIsHere: false`. `refreshBrowseCache()` on that machine then writes a browse copy with every settled line.
- **FR-5** When an agent's resolved transcript path changes, the old path is force-settled once (D-4) and the new path is tracked from its first observed size.
- **FR-6** With the vault off (no `backend` in `vault/config.json`), the poller scans no agent state. The existing early return in `pollOnce()` runs before `listActive()`.

### Non-functional

- **NFR-1** The agent-state directory scan runs at most once per 60 s per lister. `conv-*` and `ext-*` directory names are skipped before any file read.
- **NFR-2** `src/lib/vault/**` gains no import outside Node built-ins and sibling vault modules; `tests/unit/lib/vault/import-graph.test.ts` stays green.
- **NFR-3** A failing state scan or transcript resolve never throws out of the poll interval. It logs one warning per distinct message, and the poll continues with the conversation subjects.
- **NFR-4** Delay-based tests use `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()` (repo rule `fake-timers-for-retry-tests`). The two-machine test drives no timers at all, because fake timers gating real file I/O time out in CI.
- **NFR-5** No `execSync` and no sync `*Sync` filesystem calls in the new dashboard module (repo rules `no-execsync-server`, `prefer-async`). Use `node:fs/promises` and the async agent-state reader.

## Intersecting repo rules (restated)

- **Fake timers** for delay-based tests (`vi.useFakeTimers()`, `vi.advanceTimersByTimeAsync()`); never real `setTimeout` waits. The e2e test uses no timers at all.
- **No `execSync`** and no blocking `*Sync` calls in code reachable from the dashboard server.
- **Vault standalone guard:** nothing under `src/lib/vault/` or `src/cli/commands/vault/` may import `src/dashboard/`, `src/lib/overdeck/`, `src/lib/terminal-backends/`, Effect or node-pty.
- **Agent-state import leaf:** new modules import from `src/lib/agents/agent-state-read.js`, never `agents.ts`/`agent-state.ts` (`lint:circular`).
- **New source-reading tests fail lint, and an added `skipIf`/`.only` fails the test-skip gate:** assert behavior through calls, never by reading source text.
- **Quality gates before `pan done`:** `npm run typecheck`, `npm run lint`, and `npx vitest run <the test files you touched>`. Never run the full `npm test` on the host.

## Non-goals

- Backfilling agents that stopped more than 30 minutes before the dashboard saw them.
- Discovering Codex managed-agent homes in `pan vault save --all` (`discover.ts`).
- Saving transcripts of harnesses other than Claude Code and Codex (ohmypi, pi, kimi, acp, muse, opencode, prime-agent).
- Saving remote (Fly) agents' transcripts.
- Filtering, grouping or relabeling agent copies in the other machine's conversation list (W-CONV2, [PAN-4650](https://github.com/eltmon/overdeck/issues/4650)), or per-issue agent views across machines ([PAN-4651](https://github.com/eltmon/overdeck/issues/4651)).
- A structured agent-provenance field on `SessionRecord`.
- Changing the secret scan, which blocks a transcript with a credential-like line exactly as it does for conversations.
- Changing the existing hook-plus-poller first-settle race (two processes can each mint a record for the same unowned file). It exists for conversations today and is unchanged here.

## Hazards

- **List noise on other machines.** Every saved pipeline agent becomes a read-only row there (D-6), on a busy day around a hundred. This is accepted for this issue and tracked by PAN-4650.
- **Continue here on an agent copy** adopts the record like any conversation copy. If the agent is still running on its owner machine, its next settle forks (P-6). That is the existing behavior, and nothing is lost.
- **Stop hook double settle.** With `pan vault setup --hooks`, Claude agents are settled by both the hook and the poller. The CAS-conflict re-read in `settle()` already handles concurrent appends; only the very first mint can race (see Non-goals).
- **Shutdown flush budget.** More tracked subjects mean the 10 s shutdown flush can skip some. A skipped agent inside the window is picked up again at the next boot (D-3).
- **Large first settles.** A long flywheel or work transcript settles in full the first time (chunked by `maxChunkBytes`). It is incremental after that.
