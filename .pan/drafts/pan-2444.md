# PAN-2444 — SageOx as an off-by-default skill pack, fork-first (host-managed `ox`)

**Issue:** https://github.com/eltmon/overdeck/issues/2444
**Revision:** 2 (2026-09-29, planning agent, `pan plan --auto`). Revision 1 (2026-07-06, oversight conversation, `ox` v0.11.1) is superseded. Its "ride upstream, file upstream PRs" plan conflicts with the operator's 2026-09-29 fork-first plan, which is authoritative.
**Verified against:** overdeck `main` @ `a54b4cba736`; upstream `sageox/ox` `main` @ `e7bf097` (release `v0.19.0`, 2026-09-28); fork `eltmon/ox` `main` (3 commits ahead of and 1019 commits behind upstream).

## 0. Glossary

- **SageOx / `ox`**: the Go CLI (`github.com/sageox/ox`, MIT) plus the sageox.ai cloud ledger. It records coding-agent sessions through lifecycle hooks, redacts them, and syncs them to a team ledger. `ox agent prime` injects team context at session start.
- **Upstream**: `sageox/ox`. **No agent contacts upstream** (no issues, PRs or comments). Only the operator decides on upstream contact.
- **Fork**: `eltmon/ox`, the operator's fork. All `ox` changes in this issue land here, on branches, through PRs created with `gh pr create --repo eltmon/ox --base <branch>`.
- **Fork base branch**: `overdeck-base`, a branch in the fork pointing at the upstream `v0.19.0` commit. Fork PRs target it. The fork's stale `main` is left untouched (no force push).
- **Fork branch**: `overdeck/host-managed`, cut from `overdeck-base`. Every fork work item adds commits to it.
- **Fork clone**: the work agent's isolated checkout of the fork at `$HOME/Projects/ox-pan-2444`. It is never the operator's `~/Projects/sageox-ox` (old fork, dirty tree) and never under `/tmp`.
- **Host-managed mode**: fork behavior switched on by the env var `OX_HOST_MANAGED=1`. The host (Overdeck) supplies hooks and env at launch, so `ox` writes nothing into the repo and adds no attribution.
- **Host network gate**: fork env var `OX_HOST_NETWORK=on|off`. Under host-managed mode an unset or unknown value means `off`. `off` means `ox` makes no network calls.
- **Host contract probe**: the fork command `ox host-contract --json`. It prints `{"contract":"overdeck-host/1","hostManaged":true,"version":"<ox version>","commit":"<vcs.revision or empty>"}` and exits 0. Upstream `ox` has no such command, so the probe fails there.
- **Pack**: a PAN-4334 external skill source registered in `~/.overdeck/config.yaml` `skills.packs`, pinned to a trusted commit, toggled at global, project and issue level, and mounted per launch.
- **`KNOWN_PACKS`**: the table of well-known pack defaults in `src/lib/skill-packs/adapters.ts:54`.
- **SageOx wiring**: the env vars and Claude Code hooks Overdeck adds to a launch when the `sageox` pack is active for that launch.
- **Upload flag**: the per-project key `sageox_upload: enabled | disabled` in `~/.overdeck/projects.yaml`. Unset means `disabled`.
- **`files_scope` fork prefix**: an xBRIEF `files_scope` entry that starts with `eltmon/ox:` names a file in the fork repo, not in overdeck.

## 1. Verdict

Offer SageOx as a normal PAN-4334 pack that is **off by default**, sourced from the fork. The fork gets one small, additive, env-gated **host-managed mode** that removes the intrusive parts: repo writes, attribution, init nagging, and network traffic. Overdeck turns host-managed mode on for every launch where the pack is on. Uploads need a second, explicit per-project opt-in. Overdeck fails closed: if the `ox` on PATH does not answer the host contract probe, Overdeck mounts no SageOx skills and adds no hooks.

## 2. History and why this revision exists

- PAN-277 integrated SageOx in PR #280 (`dd4b387d497`, 2026-02-28). It was removed in `d3e4f434913` (2026-03-01) because `ox agent prime` injected undocumented attribution instructions, "which crosses a trust boundary". Leftovers were removed in `e5b2b7f7d7d` (2026-05-05).
- PAN-4334 (merged `7e9223421ad`, #4353) built packs and declared SageOx "an integration, not a pack" (`KNOWN_PACKS.sageox.kind = 'integration'`, refused by `pan skills pack add`).
- 2026-09-29 operator plan (issue comment): SageOx is included as a pack, off by default, per-project and per-issue enable, with a clear disclosure of what leaves the machine. All `ox` changes happen in the fork first. Upstream later, and only on the operator's call. Revision 1's D2 (retire the fork) and work item 1 (file an upstream PR) are withdrawn.

## 4. Decisions

- **D1 — The pack toggle is the opt-in.** No `integrations.sageox` key. SageOx is active for a launch when the PAN-4334 toggle for pack `sageox` resolves on (global, project or issue), or any `sageox/<skill>` per-skill override resolves on. Default: off.
- **D2 — Fork first; retire nothing.** All `ox` changes land on the fork branch `overdeck/host-managed`, PR'd into the fork base branch `overdeck-base` with `gh pr create --repo eltmon/ox --base overdeck-base`. The fork's `main` stays as it is. The three old fork commits (`70e0f37a37`, `acdf05c9d0`, `cf00e21238`) are audited and recorded, not deleted.
- **D3 — Agent identity is not stored.** Revision 1's "parse `agent_id` into the runtime record" is withdrawn. `ox` mints its own agent ids and Overdeck stores no status it can derive.
- **D4 — No ephemeral split.** Revision 1's `OX_EPHEMERAL=1` for slot agents is withdrawn. `OX_EPHEMERAL` means "no local ledger", which with uploads off would lose the session. All Overdeck launches get the same wiring.
- **D5 — Not adopted:** murmur, `ox plan`, carts, Ox Dot/meetings. The matching skills are opt-in (see D9).
- **D6 — Two gates, both structural.** Pack on ⇒ local recording only: Overdeck exports `OX_HOST_NETWORK=off` and `OX_SESSION_PUBLISHING=manual`. Upload flag `enabled` for the launch's project ⇒ `OX_HOST_NETWORK=on` and `OX_SESSION_PUBLISHING=auto`. The fork enforces the same default: under host-managed mode, a missing `OX_HOST_NETWORK` means off.
- **D7 — Fail closed on the binary.** Overdeck runs the host contract probe (2 s timeout) at launch when the pack is active. If the probe fails, the launch gets no SageOx wiring, the `sageox` pack is removed from the mount selection, and the launch step prints one warning line on stderr. The launch itself continues.
- **D8 — Claude Code only in v1.** Codex launches never mount `sageox` skills and never get SageOx wiring; the launch step prints a warning when the pack would have been active. Codex hook injection without a committed `.codex/hooks.json` is unverified.
- **D9 — Pack shape.** `KNOWN_PACKS.sageox = { kind: 'pack', url: 'https://github.com/eltmon/ox', adapter: 'plain', skillsRoot: 'extensions/skills', optIn: [...] }`. A new optional `skillsRoot` field on `KnownPack` points the `plain` adapter at `extensions/skills` instead of `skills`. Opt-in (off unless individually enabled): `ox-cli-init`, `ox-cli-attest`, `ox-cli-skill-manager`, `ox-cli-pr-header`, `ox-cli-plan`, `ox-cli-cart`, `ox-cli-cart-start`, `ox-cli-cart-done`, `ox-cli-cart-drop`. These either write to the repo, publish, or duplicate xBRIEF planning.
- **D10 — The `integration` kind is removed.** With `sageox` flipped to a pack, nothing uses `kind: 'integration'`, `note`, or `PackSourceError('integration')`. Remove them (orphan cleanup). Deft (#3943) can add its own shape later.
- **D11 — `.sageox/` must exist at the launch's git root.** Overdeck checks for the directory before wiring (belt and braces with the probe). Overdeck never runs `ox init` and never runs `ox login`. The operator does that by hand, once, in a project they chose.
- **D12 — `pan install` never installs `ox`.** The operator builds `ox` from the pinned fork commit (`go build -o <dir>/ox ./cmd/ox`). `pan doctor` reports the probe result and, when both are known, whether the binary's commit matches the `sageox` pack's trusted commit.
- **D13 — Env and hooks travel in the Claude `--settings` JSON.** `pan skills launch-settings` merges `{"env":{...},"hooks":{...}}` into the JSON it already prints. Each hook command also carries its env assignments inline, so hooks are correct even if Claude Code does not pass the `env` settings to hook processes. The `env` key covers the agent's own `ox` calls through skills.
- **D14 — Upload flag storage.** `sageox_upload` lives in `projects.yaml` but is typed and written by a new module `src/lib/sageox/config.ts` (the `store.ts:84-87` pattern), because `projects.ts` is above the file-size ceiling.
- **D15 — CLI surface.** `pan skills pack sageox` with subcommands `status [--project <key>] [--json]` and `upload <on|off> --project <key>`. It lives in `src/cli/commands/skills.ts` next to the other pack verbs. No new top-level verb.

### Implementation checkpoints

- **CP-1 (fork item F3): offline recording.** Verify that under `OX_HOST_MANAGED=1 OX_HOST_NETWORK=off`, `ox agent hook SessionStart` followed by `ox agent hook Stop` in a repo with a `.sageox/config.json` writes a session directory under the local ledger cache and makes no network call. **Fallback:** if local recording needs the network, host-managed mode with the network off also forces `OX_SESSION_RECORDING=disabled`. The docs then say "with uploads off, SageOx records nothing; turn uploads on to record". Record which branch was taken in `docs/SAGEOX-FORK.md`.
- **CP-2 (Overdeck item O4): hooks and settings env.** Verify with a fixture that the settings JSON parses and that each hook command string starts with the inline env assignments. No live Claude run is required; the inline env makes hook behavior independent of how Claude passes `env`.

## 7. Disclosure text (FR-16)

## 10. Repo rules that intersect (restated)

- **No `execSync` in new code** (server-reachable or not; NFR-1). Use promisified `execFile` with a timeout.
- **Fake timers** for the probe timeout test: `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync`.
- **File-size ratchet:** `projects.ts` and `doctor.ts` must not grow; hence D14 and the `checkKimi` extraction. Never raise an allowlist row.
- **Import cycles:** new lib modules that need agent state import from `agent-state-read.js`; `src/lib/sageox/disclosure.ts` is a leaf so `adapters.ts` can import it (adapters.ts must not import `skill-overrides/`).
- **Quality gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never the full `npm test`.
- **Test gate:** no new `skipIf`/`.only`; no tests that read source text.
- **Fork hard rule:** see §8 fork rules. No upstream contact of any kind.
- **Worktree discipline:** never `git checkout` another branch inside the overdeck workspace; the fork clone is a separate repo.

## 11. Non-goals

- Any issue, PR, or comment on `sageox/*` (upstream); upstreaming is the operator's later call.
- Force-pushing or rewriting the fork's `main`.
- Overdeck running `ox init`, `ox login`, or any upload; `pan install` installing `ox`.
- SageOx wiring for Codex, ohmypi, Kimi, ACP, or remote (Fly) launches.
- A local-only ledger that works without `ox login` + `ox init`, or a self-hosted ledger.
- murmur, `ox plan`, carts, Ox Dot; storing `ox` agent ids in Overdeck.
- Turning the pack on by default anywhere; initializing SageOx in any commercial project (MYN).
- A dashboard control for the upload flag (CLI only in v1).
