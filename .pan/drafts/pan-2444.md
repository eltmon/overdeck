# PAN-2444 — Optional SageOx re-integration (session-reasoning capture, OSS-only)

**Issue:** https://github.com/eltmon/overdeck/issues/2444 · **Author:** oversight conversation, 2026-07-06, from commissioned deep research (verified July 2026) + PAN-277 history.
**Verified-Against:** main @ cb519ebf45 · ox upstream @ v0.11.1 (2026-07-02).

## Glossary

- **SageOx / `ox`**: session-reasoning capture for coding agents (github.com/sageox/ox, Go, MIT) + cloud console (sageox.ai). Captures agent transcripts via lifecycle hooks + per-agent adapter binaries, classifies, **redacts** (rules + secret scan, append-only trail), and syncs a per-repo git "Ledger" to the cloud.
- **`ox init`**: creates `.sageox/` in a repo — capture happens ONLY in initialized repos; uninitialized repos refuse priming. This is the isolation primitive.
- **`ox agent prime`**: injects team context at session start; auto-record is now DEFAULT for initialized repos (upstream PR #281). Flags today: `--agent`, `--model`, `--agent-ver`, `--idempotent`, `--format`, `--review` (our fork's `--auto-record`/`--project` never upstreamed; `OX_PROJECT_ROOT` env is first-class upstream).
- **`OX_TOKEN` / `OX_EPHEMERAL=1`**: PAT + ephemeral-runtime mode for throwaway/CI agents (upstream #626/#632) — fits slot agents.
- **Event hooks**: `ox hooks add <event> <cmd>` — ox-side events (session upload, sync) can trigger Overdeck-side reactions.
- **Attribution trailer**: `prepare-commit-msg` hook adds `Co-Authored-By: SageOx` only when the agent's self-scored contribution ≥ 0.5 (#461). Real git author always preserved — the PAN-277-era "commits attributed to Sage Ox" failure mode no longer exists.

## Decisions

- **D1 — Per-project opt-in, structurally enforced.** `ox init` runs ONLY in the overdeck repo. MYN and any commercial project are never initialized; the integration code additionally refuses to wire ox env/hooks unless the project record carries `integrations.sageox: true` AND `.sageox/` exists. Both conditions required (belt and suspenders on the PAN-277 D-series constraint).
- **D2 — Ride upstream, delete the fork delta.** Upstream's `OX_PROJECT_ROOT` + default auto-record replace our fork's flags. The eltmon/ox fork branches are archived after confirming nothing else unique remains (audit in W1).
- **D3 — Agent identity mapping**: `ox agent prime --agent <harness> --model <model> --agent-ver <v>` at kickoff; the returned `agent_id` stored on the agent runtime record (one new nullable column-equivalent in the runtime plane; mirrored to the per-issue record only if it proves useful — start runtime-only).
- **D4 — Slots/strikes use ephemeral mode** (`OX_EPHEMERAL=1` + `OX_TOKEN`), long-lived agents use the standard flow.
- **D5 — NOT adopted**: murmur (Overdeck's commit feed owns agent-to-agent coordination), `ox plan` (vBRIEF owns planning), Ox Dot/meetings (out of scope). Re-evaluate murmur only if the commit feed proves insufficient.
- **D6 — Operator gate before default-on**: pricing is unpublished and the OSS-free-upload policy is UNVERIFIED. Ship dark (config default false); the operator confirms terms with the SageOx team before flipping. **Implementation checkpoint** with stated fallback: if terms don't fit, the integration remains available for self-pointed endpoints (`ox login` supports custom endpoints) or stays dark.

## Requirements

- FR-1: `integrations.sageox: { enabled: boolean (default false) }` per project in projects.yaml; config read door exposes it; Settings UI toggle (per-project).
- FR-2: Launcher wiring (claude-code + codex harnesses first, matching ox adapter maturity): when D1's two conditions hold, export `OX_PROJECT_ROOT=<workspace>` and register ox lifecycle hooks per ox's session-capture architecture; slot/strike spawns add `OX_EPHEMERAL=1` + `OX_TOKEN` from config secret.
- FR-3: Kickoff runs `ox agent prime --agent <harness> --model <model> --idempotent --format json`; parse `agent_id` into the runtime record; failures are non-blocking (log + continue — capture is never allowed to break spawns).
- FR-4: `pan doctor` section: ox binary present/version, repo initialized, daemon healthy, last sync age.
- FR-5: Uninstall/disable path: flipping the flag removes env/hooks on next spawn; `pan` never runs `ox init` or uploads for a project whose flag is false (test this negatively for a MYN-shaped fixture).
- NFR-1: All ox invocations async (no execSync in server-reachable code); every ox call carries a timeout; capture failure degrades silently to no-capture.
- NFR-2: No transcript data flows through Overdeck to ox — ox's own adapters read the harness transcripts directly; Overdeck only wires env/hooks/identity (keeps our surface minimal and their redaction chokepoint authoritative).
