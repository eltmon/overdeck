# PAN-5005: Command Deck tree shows no report or verdict for remote gauntlet lanes

**Issue:** https://github.com/eltmon/overdeck/issues/5005
**Found in:** the live three-machine gauntlet check for PAN-4638 (2026-11-04, build `65e3b1adf86`).
**Planned at:** `d9dcd5cd8ff` on `feature/pan-5005`.

## Glossary

- **Home:** the machine that runs the orchestrator conversation and `pan lane start`. It owns the run's rules.
- **Owner:** the linked machine a remote lane actually runs on (`--machine <label>`).
- **Lane:** a gauntlet conversation with `laneKey`, `gauntletRun` and `laneRole` (`builder`, `critic`, `verifier`, `play`, `orchestrator`).
- **Judge:** a lane whose role is `critic` or `verifier`. It files one verdict with its `done` report.
- **Stand-in:** home's record of a remote lane under `~/.overdeck/remote-lanes/<name>/` (`lane.json` facts, `mirror.json` follower copy, `archived.json`). Home has no `conversations` row for a remote lane. Module: `src/lib/lanes/remote-lanes.ts`.
- **Mirrored report:** the follower (`src/dashboard/server/services/remote-lane-follower.ts`) copies every owner report, verdict included, into home's `~/.overdeck/agents/conv-<name>/reports/`. So `latestWorkerReport('conv-<name>')` at home already returns a remote lane's report.
- **Lane row (`LaneRow`):** the unified local-or-remote lane shape from `listAllLaneRows` in `src/lib/lanes/lane-rows.ts`. A remote `LaneRow` has `id: null`, `cwdKey: '<environmentId>:<cwd>'` and `remote: { facts, mirror }`.
- **Linked row:** a row of another machine's conversation in home's merged list, named `@<environmentId>/<ownerName>` (`linkedConversationName` in `packages/contracts/src/linked-conversations.ts`), with a negative `id`. `mergeConversationRows` (`src/lib/overdeck/linked-conversations-merge.ts`) stamps a remote lane's linked row with lane facts (PAN-4638 FR-8).
- **Lane list fields:** the per-row fields the Command Deck reads for a lane: `laneReport`, `laneIteration`, `laneVerdict` (judges only), `laneLatestVerdict` (builders only).
- **Route key:** the `/conv/<key>` path segment that opens a conversation: `String(id)` for a local row, the linked name `@<environmentId>/<name>` for a linked row (`conversationRouteKey` in `src/dashboard/frontend/src/lib/linkedConversation.ts`; router support at `src/dashboard/frontend/src/App/routes.ts` line 201).

## Problem

The Command Deck tree nests remote lanes under their orchestrator but shows no report or verdict for them:

1. The group summary read `8 lanes · 4 reported` when all 8 lanes had reported `done`; it counted only home's lanes.
2. Remote critic and play rows showed a machine chip but no `DONE` or `PASS` badge.
3. A home builder whose critic ran remotely showed `DONE` but no verdict link.

`pan lane list --run pan4638` showed every report and verdict, so the data is at home.

### Cause (verified)

- `laneEnrichment` in `src/lib/overdeck/conversation-list.ts` (lines 87–136, grep `async function laneEnrichment`) builds its context from `listLaneConversations({ run })` (line 96), which reads only home's `conversations` table. A remote critic is never in the pairing context, so `pairBuilder` finds no critic for a home builder (symptom 3). It also ignores the `lane-link.json` sidecar that links a local critic to a remote builder (`localLaneRow` in `lane-rows.ts` reads it; this code does not).
- `laneEnrichment` runs inside `getEnrichedConversationList`, before linked rows exist. Remote lane rows are added later by `mergeConversationRows`, called from `getMergedConversationList` in `src/dashboard/server/services/conversation-list-merged.ts` (lines 36–59). The merge stamps lane facts (`linked-conversations-merge.ts` lines 154–166) but no lane list fields, so remote rows have no `laneReport` or `laneVerdict` (symptom 2).
- `groupSummary` in `src/dashboard/frontend/src/components/CommandDeck/conversation-tree.ts` (line 136, `if (conv.laneReport) summary.reported += 1;`) counts reported lanes from `laneReport`, so it undercounts (symptom 1). `groupSummary` itself is correct.

A second defect appears once a builder pairs with a remote critic: `laneLatestVerdict.criticId` comes from `CriticSummary.id`, which is `null` for a remote critic (`src/lib/lanes/pairing.ts`, `CriticSummary.id: number | null`). `ConversationRow.tsx` lines 245–254 build the link as `/conv/${latestVerdict.criticId}`, which would become `/conv/null`.

`pan lane list` is correct because `buildLaneViews` in `src/lib/lanes/views.ts` (lines 150–183) already uses `listAllLaneRows` and pairs by name. This fix reuses that approach for the conversation list.

## Requirements

- **FR-1:** A home builder's `laneLatestVerdict` names the newest critic or verifier that judged its iteration, whether that judge runs at home or on another machine.
- **FR-2:** A home critic or verifier of a remote builder pairs through its `lane-link.json` sidecar, so the remote builder's iteration is used.
- **FR-3:** A remote lane's linked row in `GET /api/conversations` (page 1, linked rows included) carries `laneReport`, `laneIteration`, and `laneVerdict` (judges) or `laneLatestVerdict` (builders), with the same values `pan lane list` shows for that lane.
- **FR-4:** The Command Deck group summary counts a remote lane as reported when it has a report, so a run where all lanes reported reads `N lanes · N reported`. This follows from FR-3 with no change to `groupSummary`.
- **FR-5:** `laneLatestVerdict` carries `criticRoute`, the route key of the judging critic (`String(id)` at home, `@<environmentId>/<name>` on another machine). The builder row's verdict link opens `/conv/<criticRoute>`. `criticId` becomes `number | null`.
- **NFR-1:** `GET /api/conversations` does no extra lane work when there are no unarchived stand-ins: `getMergedConversationList` calls the lane-fields function only with the runs of unarchived stand-ins, and skips it when there are none.
- **NFR-2:** No new import cycle. The new module must not import `src/lib/lanes/views.ts` or `src/lib/overdeck/conversation-list.ts` (views.ts imports conversation-list.ts). `npm run lint:circular` passes.
- **NFR-3:** `mergeConversationRows` stays pure: the caller supplies the lane list fields through `RemoteLaneEntry`.
- **NFR-4:** The merged path computes pairing again for runs that also have home lanes. This duplicate work is accepted: it is bounded by the lanes of the runs that have remote lanes, and each report read is one small file read. No new cache is added.

## Decisions

- **D-1 — One lane-fields function for both paths.** Extract `laneEnrichment` into a new module `src/lib/lanes/lane-list-fields.ts` exporting `laneFieldsByRun(runs)`. It builds the context from `listAllLaneRows({ run })` (local and remote) and returns fields for every lane in those runs, keyed by lane name. `conversation-list.ts` uses it for local rows; `conversation-list-merged.ts` uses it for remote stand-ins. Rationale: one computation, so the tree and `pan lane list` cannot disagree; and `conversation-list.ts` gets smaller instead of exporting more.
- **D-2 — Remote fields travel on `RemoteLaneEntry`.** Add an optional `fields?: LaneListFields` to `RemoteLaneEntry`. `mergeConversationRows` spreads it onto the stamped row. Rationale: keeps the merge pure (NFR-3) and reuses the existing stamping seam.
- **D-3 — Route key shape.** `criticRoute` is computed on the server: a remote critic's route is `linkedConversationName(row.remote.facts.environmentId, row.name)` from `@overdeck/contracts`; a local critic's route is `String(row.id)`. The frontend never builds it. Rationale: the server already has the environment id in `LaneRow.remote.facts`; the frontend row for a builder does not know its critic's machine.
- **D-4 — Pairing activity for a remote row.** `PairingRow.activity` for a remote lane is `row.remote.mirror?.activity ?? 'stopped'`, and `'stopped'` when `row.archivedAt !== null`. A local lane keeps `row.local.status` (today's behavior). Activity only feeds `CriticSummary.activity`, which no emitted field uses. Do not import `remoteActivity` from `views.ts` (NFR-2).
- **D-5 — Apply only to lane rows.** In `enrichConversationList`, spread the fields only when the row has `laneKey`: `...(row.laneKey ? lanes.get(row.name) ?? {} : {})`. This keeps today's guard that a non-lane conversation gets no lane fields.
- **D-6 — Archived stand-ins stay unstamped.** `getMergedConversationList` already skips stand-ins with `archivedAt !== null`; their rows get neither lane facts nor lane list fields. No change.
- **D-7 — Remove the orphaned helper.** `localIterationRow` in `src/lib/lanes/iteration.ts` has one caller (`conversation-list.ts` line 97). After WI-1 it has none; remove the function and its import.

   ```ts
   import { linkedConversationName } from '@overdeck/contracts';

   import { latestWorkerReport, type WorkerReport, type WorkerReportStatus } from '../agents/worker/report.js';
   import { withConcurrencyLimit } from '../concurrency.js';
   import { laneIterations } from './iteration.js';
   import { listAllLaneRows, type LaneRow } from './lane-rows.js';
   import { pairBuilder, type PairingRow, type VerdictState } from './pairing.js';

   const LANE_FIELDS_CONCURRENCY = 8;

   /** The lane fields a conversation-list row carries (PAN-4223 WI-5, WI-20; PAN-5005). */
   export interface LaneListFields {
     laneReport: { seq: number; at: string; status: WorkerReportStatus; verdict: string | null } | null;
     laneIteration: number;
     /** Critic and verifier lanes only. */
     laneVerdict?: { value: VerdictState; defects: number | null };
     /** Builder lanes only. */
     laneLatestVerdict?: { value: VerdictState; defects: number | null; criticId: number | null; criticRoute: string } | null;
   }

   /** The `/conv/<key>` of a lane: its id here, its linked name on another machine. */
   function routeOf(row: LaneRow): string {
     return row.remote ? linkedConversationName(row.remote.facts.environmentId, row.name) : String(row.id);
   }

   function pairingActivity(row: LaneRow): string {
     if (row.archivedAt !== null) return 'stopped';
     return row.local ? row.local.status : (row.remote?.mirror?.activity ?? 'stopped');
   }

   export async function laneFieldsByRun(runs: readonly string[]): Promise<Map<string, LaneListFields>> {
     const fields = new Map<string, LaneListFields>();
     const unique = [...new Set(runs)];
     if (unique.length === 0) return fields;
     const context = (await Promise.all(unique.map((run) => listAllLaneRows({ run })))).flat();
     const iterations = laneIterations(context);
     const reports = new Map<string, WorkerReport | null>();
     await withConcurrencyLimit(context.map((row) => async () => {
       reports.set(row.name, await latestWorkerReport(`conv-${row.name}`));
     }), LANE_FIELDS_CONCURRENCY);
     const rowsByName = new Map(context.map((row) => [row.name, row]));
     const pairingRows = context.map((row): PairingRow => {
       const report = reports.get(row.name) ?? null;
       return {
         id: row.id, name: row.name, run: row.run, key: row.key, role: row.role,
         iteration: iterations.get(row.name) ?? 1, createdAt: row.createdAt, criticOfName: row.criticOfName,
         activity: pairingActivity(row),
         report: report ? { status: report.status, ...(report.verdict ? { verdict: report.verdict } : {}) } : null,
       };
     });
     for (const pairing of pairingRows) {
       const report = reports.get(pairing.name) ?? null;
       const entry: LaneListFields = {
         laneReport: report ? { seq: report.seq, at: report.at, status: report.status, verdict: report.verdict?.value ?? null } : null,
         laneIteration: pairing.iteration,
       };
       if (pairing.role === 'critic' || pairing.role === 'verifier') {
         const verdict = report?.status === 'done' ? report.verdict : undefined;
         entry.laneVerdict = { value: (verdict?.value ?? 'pending') as VerdictState, defects: verdict?.defects ?? null };
       } else if (pairing.role === 'builder') {
         const latest = pairBuilder(pairing, pairingRows).latestVerdict;
         const critic = latest ? rowsByName.get(latest.name) : undefined;
         entry.laneLatestVerdict = latest && critic
           ? { value: latest.verdict, defects: latest.defects, criticId: latest.id, criticRoute: routeOf(critic) }
           : null;
       }
       fields.set(pairing.name, entry);
     }
     return fields;
   }
   ```
