## Glossary

- **Access-token registry:** `~/.overdeck/access-tokens.json`, owned by `src/lib/access-tokens.ts`. Each record is one revocable `odk_<64 hex>` credential; only its SHA-256 is stored.
- **Record kind:** `AccessTokenRecord.kind`, one of `device` (default when absent), `token`, `machine`, `phone` (`src/lib/access-tokens.ts:75`).
- **Snapshot:** the in-memory copy of the registry inside one process (`let snapshot`, `access-tokens.ts:132`). `verifyAccessToken` and `listActiveRecordsOfKind` read only the snapshot. The dashboard fills it at boot and every 5 s (`startAccessTokenRefresh`). **A CLI process (`pan start`, `pan kill`, `pan close`) has an empty snapshot unless it calls `refreshAccessTokens()` first.**
- **Agent token:** a `kind: 'token'` record that also carries `agentId`, `agentKind` and `role` (epic D-6). It belongs to one managed agent or one conversation.
- **Owner:** the agent or conversation an agent token belongs to: `{ agentId, agentKind, role, dir }`.
- **Agent id:** for `agentKind: 'agent'`, the `AgentState.id` (for example `agent-pan-4930`, `planning-pan-4930`, a review run id). For `agentKind: 'conversation'`, the conversation's `name` (the `conversations.name` column), **not** its tmux session.
- **Owner directory (`dir`):** where the plaintext token file lives. Agents: `getAgentDir(agentId)` = `<OVERDECK_HOME>/agents/<agentId>/` (`src/lib/agents/agent-state-read.ts:245`). Conversations: `conversationStateDir(conv.tmuxSession)` = `<OVERDECK_HOME>/conversations/conv-<name>/` (`src/lib/overdeck/conversation-pane-role.ts:7`).
- **Token file:** `<dir>/mcp-token`, mode 0600, holding only the plaintext `odk_` token and a trailing newline.
- **Stop path:** any code path after which an agent or conversation is no longer running: `stopAgent`, `stopAgentSync`, the supervisor `exited` lifecycle event, close-out teardown, `stopConversationRuntime`.
- **Sweep:** a periodic job in the primary dashboard that revokes the tokens of dead owners and prunes old revoked records.
- **Liveness oracle:** `isAlive(agentId)` and `isConfirmedDead(verdict)` in `src/lib/agents/liveness.ts:104, :176`. The repo rule (`scripts/lint-liveness.sh`) says every "is this agent alive" decision uses this module.

- **C-3 Reuse check.** Epic step 5 says "reuse when `<dir>/mcp-token` still verifies". `verifyAccessToken` reads the snapshot (empty in a CLI process) and writes `lastUsedAt`. This PRD adds `readActiveAccessTokenRecord`, which reads the file fresh and writes nothing.
- **C-4 Revoke signature.** Epic step 5 has `revokeAgentMcpTokens(agentId, dir?)`. An agent id and a conversation name could collide, so this PRD adds the kind: `revokeAgentMcpTokens(agentId, { agentKind?, dir? })`, default `agentKind: 'agent'`.

This item builds and tests `ensureAgentMcpToken` but adds **no** spawn-site call. A running agent holds a token only after W-INJ1 lands.

## Requirements

### Functional

- **FR-1 Record fields.** A `kind: 'token'` record may carry `agentId`, `agentKind` and `role`. They are valid only on `kind: 'token'`, and all three are present together or not at all. (Epic D-6.)
- **FR-2 Least privilege.** An agent token's scopes come only from `AGENT_TOKEN_SCOPES` (epic D-8) and never include `admin`, `forward`, `read:settings` or `read:costs`. `createAccessToken` refuses `admin` or `forward` when `agentId` is set.
- **FR-3 Delivery.** `ensureAgentMcpToken(owner)` leaves exactly one active agent token for the owner and writes its plaintext to `<dir>/mcp-token` with mode 0600, by temp file plus rename. It reuses the existing token when the file holds a token that is active and belongs to the same owner with the same role. (Epic D-7.)
- **FR-4 Revoke on stop.** After `stopAgent`, `stopAgentSync`, the agent `exited` event, the conversation `exited` event, close-out of an issue and `stopConversationRuntime`, the owner has zero active agent tokens and no token file.
- **FR-5 Sweep.** The primary dashboard sweeps 60 s after boot and then every 10 minutes. One run revokes every active agent token whose owner is dead (rules in W-6) and prunes agent-token records revoked more than 7 days ago.
- **FR-6 Credential identity.** A request that presents an agent token resolves to a `token` credential that carries `agentId`, `agentKind` and `role`.

### Non-functional

- **NFR-1 Downgrade safety.** A registry with agent tokens parses in an Overdeck that predates this change (extra fields are ignored). A registry without the new fields parses unchanged in this version.
- **NFR-2 Secrets.** The plaintext token exists only in the token file and in the return value of `createAccessToken`. It never goes into a log line, a launcher script, argv or an env export.
- **NFR-3 Async only.** No `execSync`, `spawnSync`, `execFileSync` and no new `*Sync` function. `stopAgentSync` stays synchronous; its revoke is fire-and-forget.
- **NFR-4 Fake timers.** Sweep timing tests use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`; no real sleeps (repo rule `fake-timers-for-retry-tests`).
- **NFR-5 No cycles, small modules.** `src/lib/access-token-records.ts` imports nothing from `access-tokens.ts`; `npm run lint:circular` stays clean. New modules stay under 600 lines; `access-tokens.ts` stays under 600 lines.
- **NFR-6 Never block a stop.** Every revoke helper catches its own errors, logs one warning, and resolves. A corrupt registry must never make `pan kill`, close-out or a conversation stop fail.
- **NFR-7 Effect boundary.** No new exported Effect wrapper; `npm run lint:effect-facades` does not rise.

## Decisions

- **D-1 Mint ownership.** This item adds no spawn-site call (C-5). Its acceptance is proved through `ensureAgentMcpToken` for the three owner shapes AC-1 names: a work agent (`agentKind: 'agent'`, `role: 'work'`), a review run (`agentKind: 'agent'`, `role: 'review'`) and a conversation (`agentKind: 'conversation'`, `role: 'conversation'`).
- **D-2 Conversation identity.** `agentId` = `conv.name`; `dir` = `conversationStateDir(conv.tmuxSession)`, always passed by the caller.
  For `agentKind: 'agent'`, `ensureAgentMcpToken`, `revokeAgentMcpTokens` and the sweep pass `agentId` through `normalizeAgentId` (`src/lib/agents/identity.ts:52`; it maps a bare issue id such as `PAN-1` to `agent-pan-1` and leaves qualified ids unchanged), so a mint and a `stopAgent(normalizedId)` revoke always name the same owner.
- **D-3 Fresh reads.** `agent-token.ts` never uses the snapshot. It reads the registry through two new exports of `access-tokens.ts`: `readActiveAccessTokenRecord(token)` and `revokeAccessTokensMatching(match)`. This makes the module correct in CLI processes.
- **D-4 Reuse rule.** Reuse the file's token only when all hold: the file content matches `^odk_[0-9a-f]{64}$` after trim; `readActiveAccessTokenRecord` returns a record; that record has `kind === 'token'`, the same `agentId`, `agentKind` and `role` as the owner, and exactly the scopes in `AGENT_TOKEN_SCOPES[owner.role]` (same set). Otherwise revoke every active token of the owner and mint a new one.
- **D-5 Verify after write.** After minting and writing the file, `ensureAgentMcpToken` calls `readActiveAccessTokenRecord(token)` once. If it returns null (another process overwrote the registry, Fact 3), it mints once more. If the second check also fails it throws `Error('agent token for <agentId> did not persist in the access-token registry')`. `ensureAgentMcpToken` is the only helper that throws; W-INJ1 decides what a launch does when it throws.
- **D-6 Token name.** `agent:<role>:<agentId>`, cut to 200 characters (`MAX_NAME_LENGTH`, access-tokens.ts:59). Agent tokens are shown in `pan token list` and Settings → Access Tokens like any token; filtering them out is a non-goal.
- **D-7 Validator strictness.** `agentId` must match `^[A-Za-z0-9._:/-]{1,200}$`. `agentKind` must be `'agent'` or `'conversation'`. `role` must be a string of 1-64 characters matching `^[a-z][a-z0-9-]*$`; it is **not** checked against the `Role` union, so a future role cannot make this version's file corrupt.
- **D-8 Scopes table** (verbatim from the epic, one constant `AGENT_TOKEN_SCOPES` in `src/lib/mcp/agent-token.ts`):

  | Role | Scopes |
  |---|---|
  | `work`, `worker`, `plan`, `strike`, `sequencer`, `knowledge`, `flywheel` | `read:events, read:state, read:conversations, tell, operate` |
  | `review`, `test`, `ship` | `read:events, read:state, read:conversations, tell` |
  | `conversation` | `read:events, read:state, read:conversations, tell, operate, approve` |

- **D-9 Sweep rules.** For each active agent token (`agentId` set, no `revokedAt`), with `now` and `SWEEP_GRACE_MS = 10 * 60_000`:
  - `agentKind: 'agent'`: revoke when `getAgentState(agentId)` is null. Else, when `max(createdAt, state.startedAt, state.lastResumeAt)` is older than `now - SWEEP_GRACE_MS` and `isConfirmedDead(await isAlive(agentId))` is true, revoke. Otherwise keep. The grace stops the sweep from revoking a token minted for an agent whose pane does not exist yet.
  - `agentKind: 'conversation'`: revoke when `getConversationByName(agentId)` is null, or its `archivedAt` is set, or its `status === 'ended'` and `createdAt` of the token is older than `now - SWEEP_GRACE_MS`. Otherwise keep.
  - The token file of a revoked owner is unlinked best-effort: agents `join(getAgentDir(agentId), 'mcp-token')`; conversations `join(conversationStateDir(conv?.tmuxSession ?? \`conv-${agentId}\`), 'mcp-token')`.
  - After the revocations: `pruneEndedAccessTokens(7 * 24 * 60 * 60_000)`.
  - A failure for one token is logged and the run continues with the next one.
- **D-10 Sweep timing.** First run 60 s after `startAgentTokenSweep()`, then 10 minutes after each run ends (a `setTimeout` chain, so runs never overlap). Timers are `unref()`'d. `stopAgentTokenSweep()` clears the pending timer. Calling start twice is a no-op.
- **D-11 Exited-event placement.** Agents: revoke after `saveAgentStateAndEmitEventWithDeps(…agent.stopped…)` in `case 'exited'` (line 266). Conversations: revoke right after `markConversationEnded(…)`, **before** the `if (conversation.status === 'ended') return` early exit, so a row an operator stop already ended still gets its tokens revoked. The earlier `respawn-pending` and `superseded-launch` returns stay before the revoke, so a stale exit of a replaced harness never revokes the new generation's token.
- **D-12 Close-out matches by issue.** `revokeAgentMcpTokensForIssue(issueId)` lists active `agentKind: 'agent'` tokens, reads `getAgentState(agentId)` for each (from `src/lib/agents/agent-state-read.js`, the leaf module, so no import cycle) and revokes those whose `state.issueId` equals `issueId` ignoring case. It runs before `removeAgentStateImpl` deletes state, so the states still exist. Tokens whose state is already gone are left for the sweep.

## Hazards

- **H-1 Observable only after W-INJ1.** No running agent holds a token until W-INJ1 calls `ensureAgentMcpToken` at launch. Test and UAT roles must verify AC-4 to AC-6 through the unit tests, not by looking for a token on a live agent.
- **H-2 Cross-process lost update.** `mutate` serializes only within a process (Fact 3). A CLI `pan kill` revoke can be overwritten by the dashboard's `lastUsedAt` write, and a mint can be lost the same way. The sweep re-revokes dead owners within one run; D-5 re-mints a lost token once.
- **H-3 Snapshot trap.** Never call `verifyAccessToken` or `listActiveRecordsOfKind` from `agent-token.ts`; a CLI process has an empty snapshot, and `verifyAccessToken` writes `lastUsedAt`.
- **H-4 Fire-and-forget revoke.** `stopAgentSync`'s revoke and the agent `exited` revoke can be cut off by process exit. The sweep is the backstop.
- **H-5 Sweep vs. launch.** Without the grace, a sweep run between mint and pane creation would revoke a new agent's token. Keep D-9's grace; do not shorten it below one sweep interval.
- **H-6 Agent-dir removal guard.** Delete the token file with `unlink`, never `rm`, or `lint:agent-dir-removal` fails (Fact 9).
- **H-7 Import cycles.** `agent-token.ts` must import `getAgentState` from `agent-state-read.js`, not `agents.js` or `agent-state.js`, and must not import `conversations.ts` (the sweep does that).
- **H-9 Mint after the state is saved (W-INJ1 handoff).** D-9 revokes an `agent` token at once when `getAgentState(agentId)` is null. W-INJ1 must call `ensureAgentMcpToken` only after the agent's state is saved (`saveAgentStateSync`, spawn.ts:734; `saveAgentState`, spawn.ts:256), and must check the same for planning sessions (`spawn-planning-session.ts`). The W-10 revision note in the epic PRD repeats this.
- **H-10 Stale agent `exited`.** The agent `exited` handler has no stale-launch guard (conversations have one). A late exit POST from a replaced harness can revoke the new generation's token. This matches the existing state marking, and the next launch re-mints; awareness only.
- **H-8 Lane and worker conversations.** A lane conversation is a conversation, but it is not the operator's chat. W-INJ1 should pass `role: 'worker'` with `agentKind: 'conversation'` for lane rows so they do not get `approve`. This item's types allow it.
