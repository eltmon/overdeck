# PAN-4762 — File links: add Open in browser and Open in <Browser> to the right-click menu

**Issue:** [PAN-4762](https://github.com/eltmon/overdeck/issues/4762)
**Status:** draft (planning, `pan plan --auto`, 2026-11-01)

## Glossary

- **File chip / file link** — the inline chip `MarkdownFileLink` renders for a file path in a conversation transcript (`src/dashboard/frontend/src/components/chat/MarkdownFileLink.tsx`).
- **`filePath` vs `targetPath`** — `MarkdownFileLinkMeta` fields. `filePath` is the real file path. `targetPath` is the same path plus an optional `:line[:column]` goto suffix for external editors. Browser actions always use `filePath`.
- **Generic menu** — the right-click menu built inline in the chip's `onContextMenu` for non-markdown files (`MarkdownFileLink.tsx` lines 415–424, search `{ label: 'Open in editor', onClick: handleOpen }`).
- **Markdown menu** — `openMarkdownContextMenu` (`MarkdownFileLink.tsx` lines 331–357), used for `.md`/`.mdx`/`.markdown` chips (`isMarkdownPath`).
- **Browser-renderable extension** — one of `html`, `htm`, `xhtml`, `svg`, `pdf`, `png`, `jpg`, `jpeg`, `gif`, `webp`, `avif`, `md`, `txt` (exactly this set, from the issue). Only these chips get browser menu items.
- **`BROWSERS`** — a new contracts list in `packages/contracts/src/editor.ts`, separate from `EDITORS`, that names the browsers the dashboard can launch.
- **`default-browser`** — the `BROWSERS` entry that hands the `file://` URL to the platform opener (`xdg-open` / `open` / `explorer`). Its menu label is **Open in browser**.
- **Browser launcher** — the server-side result of detection for one browser: the binary to spawn and the arguments that go before the URL (for example `{ command: 'open', args: ['-a', 'Firefox'] }` on macOS, `{ command: 'firefox', args: [] }` on Linux).
- **PanOpen** — the Effect service in `src/dashboard/server/services/open.ts` that launches editors and the file manager. Its live layer `PanOpenLive` detects tools once at layer build and caches the result.
- **No-loss matrix** — `tests/unit/lib/overdeck/no-loss-matrix.ts`. `tests/unit/lib/overdeck/no-loss-matrix.test.ts` fails when an RPC method in `packages/contracts/src/rpc.ts` has no row in it.

## Problem

Right-clicking a file chip offers **Open in editor**, **Open containing folder**, **Copy relative path** and **Copy full path** (markdown chips: **Open in internal editor**, one **Open in `<Editor>`** per editor, then the same last three). There is no way to view an HTML mockup, SVG, PDF or image in a browser with one click. The operator has to copy the path and paste it into a browser.

## Proposal (summary)

1. Add a `BROWSERS` list, `BrowserId`, `BrowserIdSchema` and `OpenInBrowserInput` to `packages/contracts/src/editor.ts`. Keep it separate from `EDITORS`.
2. Detect browsers in `PanOpenLive` at layer build (async, cached, same pattern as `resolveAvailableEditors`). Add `getAvailableBrowsers()` and `openInBrowser({ path, browser })` to the `PanOpen` service.
3. Add RPC methods `pan.getAvailableBrowsers` and `pan.shellOpenInBrowser` next to the editor methods, wire them in `ws-rpc.ts`, and add no-loss-matrix rows.
4. In `MarkdownFileLink.tsx`, add browser items to both menus for browser-renderable files, right after the editor items and before **Open containing folder**.
5. Update `docs/MARKDOWN-EDITOR-PANE.md`, which already documents these menus.

## Requirements

### Functional

- **FR-1** — `packages/contracts` exports `BROWSERS` with exactly these ids, in this order: `default-browser`, `chrome`, `chromium`, `firefox`, `brave`, `edge`, `vivaldi`. No `BROWSERS` id appears in `EDITORS`, and `EditorIdSchema` rejects every browser id.
- **FR-2** — The server detects browsers once, at `PanOpenLive` layer build, and `getAvailableBrowsers()` returns the detected ids in `BROWSERS` order.
  - Linux: a named browser is available when one of its Linux commands is on `PATH` (`isCommandAvailable`). Chromium checks `chromium`, then `chromium-browser`, and records whichever was found.
  - macOS: a named browser is available when `/Applications/<macApp>.app` exists, checked with async `fs.access` from `node:fs/promises`.
  - Windows and other platforms: no named browser is detected.
  - `default-browser` is available when the platform opener (`xdg-open` / `open` / `explorer`, from the existing `getFileManagerCommand()`) is on `PATH`.
- **FR-3** — `openInBrowser({ path, browser })` spawns the detected launcher with `pathToFileURL(path).href` as the last argument, through the existing `launchDetached`. Linux named browser: `spawn('<found command>', [url])`. macOS named browser: `spawn('open', ['-a', '<macApp>', url])`. `default-browser`: `spawn('<platform opener>', [url])`.
- **FR-4** — `openInBrowser` fails with `PanRpcError` (`code: 'BROWSER_LAUNCH_FAILED'`) and spawns nothing when `path` is not absolute, or when `browser` was not detected.
- **FR-5** — RPC `pan.getAvailableBrowsers` returns `{ browsers: BrowserId[] }`. RPC `pan.shellOpenInBrowser` takes `OpenInBrowserInput` and returns nothing. Both are wired in `src/dashboard/server/ws-rpc.ts` and have no-loss-matrix rows.
- **FR-6** — For a chip whose `filePath` has a browser-renderable extension, the generic menu shows one item per available browser, in `BROWSERS` order, labelled `Open in ${label}` (`default-browser` → **Open in browser**), placed after **Open in editor** and before **Open containing folder**.
- **FR-7** — For a `.md` chip, the markdown menu shows the same browser items after the last **Open in `<Editor>`** item and before **Open containing folder**. `.mdx` and `.markdown` chips get no browser items (they are not in the issue's extension list).
- **FR-8** — A chip with any other extension (for example `.ts`, `.tsx`, `.json`) shows no browser items, and its generic menu still opens synchronously with no RPC call.
- **FR-9** — Choosing a browser item sends `shellOpenInBrowser({ path: filePath, browser: id })` (never `targetPath`). Success toasts `Opened in ${label}` (e.g. `Opened in Firefox`, `Opened in browser`). Failure toasts `Failed to open in ${label}: <message>`.
- **FR-10** — The frontend caches the browser list at module level, like `fetchAvailableEditors()`. On fetch failure it clears the cache and shows the menu with no browser items.

### Non-functional

- **NFR-1** — No `execSync`, `execFileSync`, `accessSync`, `existsSync` or any other sync child-process or filesystem call in `open.ts` (dashboard server code).
- **NFR-2** — The server spawns only launchers that detection found. Spawning a missing binary emits an uncaught `error` event.
- **NFR-3** — `PanOpenInPicker`, `keybindings.ts`, `EditorPane.tsx` and `resolvePreferredEditor()` stay on `EDITORS` and can never offer a browser.
- **NFR-4** — No file grows past its file-size cap. `src/dashboard/server/ws-rpc.ts` is 1136 lines against an effective cap of 1221 (last `scripts/file-size-allowlist.txt` row wins); the two handlers fit, but add nothing else there.

## Decisions (made here; do not re-decide)

- **D-1 `default-browser` uses the platform opener exactly as the issue says** — `xdg-open` on Linux, `open` on macOS, `explorer` on Windows, given the `file://` URL. These openers pick the app by the file's type. For `.html`/`.htm`/`.xhtml` that is normally the browser. For `.png`, `.pdf`, `.md` or `.txt` it may be an image viewer, PDF viewer or text editor. Resolving the real default browser (`xdg-settings get default-web-browser`, macOS LaunchServices) is a non-goal and a possible follow-up. The named **Open in `<Browser>`** items always open a browser.
- **D-2 `BROWSERS` entry shape differs from `EDITORS`** because Chromium has two Linux binaries and macOS launches by app name:

  ```ts
  { id: "chromium", label: "Chromium", linuxCommands: ["chromium", "chromium-browser"], macApp: "Chromium" }
  ```

  `default-browser` has `label: "browser"`, `linuxCommands: []`, `macApp: null`. The lowercase label is deliberate: the menu text is uniformly `Open in ${label}` and the toast is `Opened in ${label}`, so `default-browser` needs no special case.
- **D-3 Windows offers only `default-browser`.** `where google-chrome` does not find Chrome on Windows, and the issue names no Windows detection.
- **D-4 Labels:** `Google Chrome`, `Chromium`, `Firefox`, `Brave`, `Microsoft Edge`, `Vivaldi`. macOS app names: `Google Chrome`, `Chromium`, `Firefox`, `Brave Browser`, `Microsoft Edge`, `Vivaldi`.
- **D-5 The server cache is a `Map<BrowserId, BrowserLauncher>`**, not a `BrowserId[]`, because it must remember which Chromium binary was found. `getAvailableBrowsers()` returns `[...map.keys()]` in `BROWSERS` order.
- **D-6 Fetch the browser list only for browser-renderable chips.** The generic menu for other chips stays synchronous, so `MarkdownFileLink.test.tsx` "shows context menu actions in the expected order and prevents the native menu" (line 146, `.tsx` chip, immediate `getAllByRole`) keeps passing unchanged. For `.md` the markdown menu awaits `Promise.all([fetchAvailableEditors(), fetchAvailableBrowsers()])`.
- **D-7 Reject a non-absolute `path` on the server** before `pathToFileURL`, which would otherwise resolve it silently against the server's cwd. Use `isAbsolute` from `node:path`.
- **D-8 New RPC methods get the default `admin` scope.** `RPC_METHOD_SCOPES` in `src/dashboard/server/route-scopes.ts` (line 148) maps only two read methods; every other method defaults to `admin`, the same as `shellOpenInEditor`. `route-scopes.ts` needs no change.
- **D-9 No-loss-matrix disposition** is `OUT_OF_SCOPE`, matching `pan.shellOpenInEditor` and `pan.getAvailableEditors` (lines 880–881).
- **D-10 `packages/contracts/dist/` is not tracked** (`.gitignore` line 5 `dist/`; `git ls-files packages/contracts/dist` is empty). `npm run typecheck` rebuilds contracts through its `pretypecheck` hook, and Vitest aliases `@overdeck/contracts` to `packages/contracts/src/index.ts`. Do not commit a built `dist/`.
- **D-11 Do not change `launchDetached`.** Detection already guarantees that the spawned binary exists (NFR-2), the same contract the existing `file-manager` reveal guard relies on (`open.ts` line 150).

```ts
// ─── Available browsers detection (async, cached, PAN-4762) ─────────────────

// The binary to spawn for a detected browser and the args before the URL.
interface BrowserLauncher {
  readonly command: string;
  readonly args: ReadonlyArray<string>;
}

async function detectBrowserLauncher(browser: BrowserEntry): Promise<BrowserLauncher | null> {
  if (browser.id === 'default-browser') {
    const cmd = getFileManagerCommand();
    return cmd && (await isCommandAvailable(cmd)) ? { command: cmd, args: [] } : null;
  }
  switch (process.platform) {
    case 'linux':
      for (const command of browser.linuxCommands) {
        if (await isCommandAvailable(command)) return { command, args: [] };
      }
      return null;
    case 'darwin':
      if (!browser.macApp) return null;
      try {
        await access(`/Applications/${browser.macApp}.app`);
        return { command: 'open', args: ['-a', browser.macApp] };
      } catch {
        return null;
      }
    default:
      return null;
  }
}

async function resolveAvailableBrowsers(): Promise<Map<BrowserId, BrowserLauncher>> {
  const launchers = await Promise.all(BROWSERS.map((browser) => detectBrowserLauncher(browser)));
  const available = new Map<BrowserId, BrowserLauncher>();
  BROWSERS.forEach((browser, index) => {
    const launcher = launchers[index];
    if (launcher) available.set(browser.id, launcher);
  });
  return available;
}
```

```ts
  const openInBrowser = useCallback((browser: BrowserEntry) => {
    void getTransport()
      .request((client) => (client as PanRpcProtocolClient)[WS_METHODS.shellOpenInBrowser]({
        path: filePath,
        browser: browser.id,
      }))
      .then(() => {
        toast.success(`Opened in ${browser.label}`);
      })
      .catch((error) => {
        toast.error(`Failed to open in ${browser.label}: ${error instanceof Error ? error.message : String(error)}`);
      });
  }, [filePath]);

  const browserMenuItems = useCallback((availableBrowsers: readonly BrowserId[]): ContextMenuFallbackItem[] =>
    BROWSERS.filter((entry) => availableBrowsers.includes(entry.id)).map((entry) => ({
      label: `Open in ${entry.label}`,
      onClick: () => openInBrowser(entry),
    })), [openInBrowser]);
```
