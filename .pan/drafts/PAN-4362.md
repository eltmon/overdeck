## 2. Problem (verified against the code)

Overdeck places models per role from vendor benchmarks measured at `max`/`xhigh`, but launches at `high` (`DEFAULT_EFFORT`, `packages/contracts/src/effort.ts`). The only live evals are `evals/flywheel-launch.eval.ts` and `evals/review-synthesis.eval.ts`; `evals/memory-status-rollup.eval.ts` is offline and `evals/jev-smoke.eval.ts` is Jev-only. None measures:

- whether a review lane finds a real blocker (gates Sonnet 5.5 on the correctness/performance/requirements lanes and a cross-family Sol lane),
- whether a planner writes a lint-clean xBRIEF (gates moving `plan` off Opus 5.5),
- whether a summarizer invents facts (gates Luna/Haiku/Sonnet for titles, compaction, fork summary, handoff author — Luna's reported 77% hallucination rate),
- whether a work agent acts on `pan tell` review feedback or treats it as prompt injection (Sonnet 5.5's prompting guide names this behavior).

PAN-4361 landed the provider-neutral harness, so all five placement models can now be called. What is missing is the four suites, their fixtures, their scorers, and a way to aggregate per-run results into one five-model table.

Two harness gaps block the suites as the harness stands today:

1. `RunPromptScenarioOptions` (`evals/lib/prompt-harness.ts` lines 22–27) carries one `user: string`. E5 needs a user turn that arrives **after** assistant turns. `callAnthropic` sends `messages: [{ role: 'user', content: opts.user }]` (line 61); `callOpenAIResponses` sends `input: [{ role: 'user', content: prompt.user }]` (`evals/lib/openai-responses.ts` line 32).
2. Evalite stores results per run under `evals/node_modules/.evalite/`; nothing aggregates across runs of different models, so E2's "blockers found by only one model family" and the five-model results table cannot be produced.

## 4. Design

### 4.1 Harness: multi-turn input (FR-1)

Before (`evals/lib/prompt-harness.ts` lines 22–27):

```ts
export interface RunPromptScenarioOptions {
  system: string;
  user: string;
  /** Caps the resolved model's maxOutputTokens (or EVAL_DEFAULT_MAX_OUTPUT_TOKENS when unset). */
  maxTokens?: number;
}
```

After:

```ts
export interface ScenarioMessage {
  role: 'user' | 'assistant';
  content: string;
}

export interface RunPromptScenarioOptions {
  system: string;
  /** Single user turn. Exactly one of `user` / `messages` is required. */
  user?: string;
  /** Multi-turn conversation; must end with a user turn. */
  messages?: ScenarioMessage[];
  maxTokens?: number;
}

export function scenarioMessages(opts: Pick<RunPromptScenarioOptions, 'user' | 'messages'>): ScenarioMessage[] {
  if ((opts.user === undefined) === (opts.messages === undefined)) {
    throw new Error('runPromptScenario needs exactly one of `user` or `messages`.');
  }
  const messages = opts.messages ?? [{ role: 'user', content: opts.user! }];
  if (messages.length === 0 || messages[messages.length - 1]!.role !== 'user') {
    throw new Error('runPromptScenario `messages` must be non-empty and end with a user turn.');
  }
  return messages;
}
```

`runPromptScenario` calls `scenarioMessages(opts)` **before** `resolveEvalModelConfig` so a malformed call rejects with no network call. `callAnthropic` sends `messages: scenarioMessages(opts)`. `callOpenAIResponses` changes its `prompt` parameter type from `{ system: string; user: string }` to `{ system: string; messages: ScenarioMessage[] }` and sends `input: prompt.messages.map(m => ({ role: m.role, content: m.content }))`. The existing single-`user` call sites (`flywheel-launch.eval.ts`, `review-synthesis.eval.ts`) keep working unchanged.

### 4.4 E2 review recall (FR-4, FR-5, FR-6)

**Case shape** (`evals/fixtures/review-recall/<pr>-<slug>.json`), validated by `parseReviewRecallCase(data: unknown): ReviewRecallCase` exported from the scorer module:

```ts
interface ReviewRecallCase {
  id: string;                                   // "<pr>-<slug>"
  lane: 'correctness' | 'performance' | 'requirements';
  provenance: { pr: number; reviewedSha: string; mergeBase: string; commentUrl: string };
  issue: { id: string; title: string; acceptanceCriteria: string[] }; // ACs required non-empty for lane 'requirements'
  diff: string;                                 // unified diff, <= 60,000 chars
  blocker: {
    title: string;                              // from the "### [lane] <title> — `file:line`" heading
    file: string;                               // repo-relative
    lines: number[];                            // cited line(s)
    keywords: string[];                         // 3-6 distinctive lowercase terms from the finding
  };
}
```

**Mining recipe** (the work agent follows it verbatim):

1. `gh search prs --repo eltmon/overdeck "Review CHANGES REQUESTED" --merged --limit 100 --json number`.
2. For each PR: `gh pr view <n> --json comments --jq '.comments[] | select(.body | startswith("# Review CHANGES REQUESTED for")) | {url, body}'`. Take the first such comment.
3. Parse `HEAD reviewed: <sha>` and `merge-base <sha>` from its `## Context` section. Parse the first heading under `## Blocking Findings` of the form `### [<lane>] <title> — \`<file>:<line>\``.
4. Skip the PR when the lane is `security`, or the heading does not match that shape.
5. `git fetch origin pull/<n>/head` then `git cat-file -e <reviewedSha>` and `git cat-file -e <mergeBase>`. Skip the PR when either is unreachable.
6. `git diff <mergeBase> <reviewedSha> -- <blocker file> <decoy1> <decoy2>`, where decoys are the two largest other changed files (by changed-line count) from `git diff --numstat`. If the result exceeds 60,000 chars, drop decoys; if still too large, skip the PR.
7. `keywords`: 3–6 distinctive lowercase terms from the finding's title and Problem text (identifiers, not common words).
8. Stop at 20 cases; the minimum is 12, with at least 2 cases per lane that has any candidates. Record lane counts in the README.

**Scorer** (`evals/lib/review-recall-scorer.ts`):

```ts
export interface ParsedFinding { glyph: '!' | '⊗' | '~' | '≉' | '?'; blocking: boolean; title: string; file: string | null; line: number | null; body: string }
export function parseFindings(report: string): ParsedFinding[];
export function findingMatchesBlocker(f: ParsedFinding, blocker: ReviewRecallCase['blocker'], opts?: { lineWindow?: number; minKeywordHits?: number }): boolean;
export function scoreReviewRecall(report: string, c: ReviewRecallCase): { recall: 0 | 1; precision: number | null; blockingCount: number; score: number };
```

- Heading regex: `^###\s+(!|⊗|~|≉|\?)\s+(.+?)\s+—\s+\`([^`:]+)(?::(\d+))?[^`]*\`\s*$` (multiline). The finding `body` is text up to the next `###`/`##` heading.
- Match rule: finding is blocking **and** its `file` equals `blocker.file` (after stripping a leading `./`) **and** (some cited line is within `lineWindow` = 15 of a `blocker.lines` entry **or** at least `minKeywordHits` = 2 `keywords` occur case-insensitively in title+body).
- `recall` = 1 if any finding matches. `precision` = matching blocking findings / blocking findings; `null` when there are no blocking findings. `score` = `recall`.
- Metrics recorded: `recall`, `precision`, `blockingCount`.

**Eval** (`evals/review-recall.eval.ts`): system = `loadPromptFile(\`roles/review-${lane}.md\`)`. User prompt:

### 4.5 E3 plan quality (FR-7, FR-8, FR-9, FR-10)

**Parser extraction** — before (`src/lib/xbrief/io.ts` lines 269–287): `readPlanSync(planPath)` reads the file, rejects merge-conflict markers, parses, normalizes the envelope, checks `xBRIEFInfo && plan`, else throws. After:

```ts
export function parseXBriefDocument(raw: string, source: string): XBriefDocument {
  if (raw.includes('<<<<<<<') && raw.includes('=======') && raw.includes('>>>>>>>')) {
    throw new XBriefMergeConflictError(source);
  }
  const parsed = normalizeXBriefEnvelope(JSON.parse(raw));
  if (parsed.xBRIEFInfo && parsed.plan) {
    return parsed as XBriefDocument;
  }
  throw new Error(`Invalid xBRIEF format in ${source}: …same message as today…`);
}

export function readPlanSync(planPath: string): XBriefDocument {
  return parseXBriefDocument(readFileSync(planPath, 'utf-8'), planPath);
}
```

**Case shape** (`evals/fixtures/plan-quality/<issue-lower>.json`), validated by `parsePlanQualityCase`:

```ts
interface PlanQualityCase { id: string; issueId: string; issueState: 'CLOSED'; title: string; url: string; body: string; prdPath: string; referenceSpecPath: string }
```

The eval reads `prdPath` and `referenceSpecPath` only through `readRepoText` (Evalite runs with cwd `evals/`, so a bare relative `readFileSync` would resolve wrongly). `body` is the issue body captured at fixture time (`gh issue view <n> --json body`). `prdPath` and `referenceSpecPath` are repo-relative (`.pan/drafts/…md`, `.pan/specs/…json`); the eval reads them at run time. **Selection:** 8 CLOSED `PAN-*` issues having both a `.pan/specs/*-<ID>-*.{xbrief,vbrief}.json` and `.pan/drafts/<id>.md` (case-insensitive id), preferring a spread of reference difficulties and item counts between 3 and 20. Reference specs must parse with `parseXBriefDocument`.

**Scorer** (`evals/lib/plan-quality-scorer.ts`):

```ts
export function extractJsonObject(text: string): unknown;   // whole text, then ```json fence, then first balanced {...}; throws "No JSON object found in response"
export const DIFFICULTY_RANK = { trivial: 0, simple: 1, medium: 2, complex: 3, expert: 4 } as const;
export function scorePlanQuality(output: string, reference: XBriefDocument, prdText: string): {
  schemaPass: 0 | 1; lintErrors: number; lintPass: 0 | 1;
  difficultyAgreement: number; fileScopeOverlap: number; itemCountAgreement: number; score: number;
};
```

- `schemaPass` = 1 when `parseXBriefDocument(JSON.stringify(extractJsonObject(output)), 'model output')` succeeds and `plan.items` is a non-empty array; otherwise every metric is 0 and `score` = 0.
- `lintErrors` = count of `severity === 'error'` from `lintPlanQuality(doc, { prdText })`. `lintPass` = `lintErrors === 0 ? 1 : 0`.
- `difficultyAgreement` = `1 − |meanRank(model) − meanRank(reference)| / 4` over items with a known `metadata.difficulty`; 0 if either side has none.
- `fileScopeOverlap` = Jaccard of the two union sets of `metadata.files_scope` entries, each normalized by stripping a leading `./` and a trailing `/**` or `/*`; 0 when both are empty.
- `itemCountAgreement` = `min(a, b) / max(a, b)` of top-level item counts.
- `score` = `0.4·lintPass + 0.2·difficultyAgreement + 0.2·fileScopeOverlap + 0.2·itemCountAgreement` (when `schemaPass` = 1).

**Eval** (`evals/plan-quality.eval.ts`): system = `loadPromptFile('roles/plan.md')`. Classification order:
