## blocks-the-design: A mixed push runs CI on a bookkeeping commit

[GitHub documents](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow) that `push` path filtering compares the branch before and after the **whole push**; [the push workflow runs at the pushed tip](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows). If one push contains code commit C followed by bookkeeping commit B, the `src/` change triggers CI **on B**. The PRD's [CI-head algorithm](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4618/.pan/drafts/PAN-4618.md), lines 408–416, skips B and selects C, which has no CI run. The planned REST fill then finds no suites for C ([project-ci-fill.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4618/src/lib/overdeck/project-ci-fill.ts), lines 63–83), while the proposed DoD filter also discards B. Main's real verdict and later-green evidence are both lost. Define the CI head from a relevant CI run's `head_sha`, or explicitly handle run-bearing bookkeeping tips in both readers. Add a two-commit, one-push case to the acceptance tests.
