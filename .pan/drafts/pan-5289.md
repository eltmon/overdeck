## 1. Summary

The file explorer today is a Stage tab (`paneType: 'files'`). Opening it hides the conversation, and nothing shows what a conversation changed. This child moves the explorer into a **dock**: a right-hand column inside the Command Deck Stage with four tabs — **Files**, **Changes**, **Search** and **Live** — whose content follows the active Stage tab. It ships its own entry points (Stage + menu, project Home and issue overview **Files** buttons, four global shortcuts), a better **Go to file** ranking with match highlighting and a "changed here" boost, a **Files** scope in the `Ctrl K` palette, and it folds the floating conversation dock into the **Live** tab.

## 2. Glossary

- **Stage** — the tabbed pane area of one project deck, `src/dashboard/frontend/src/components/Stage/index.tsx`. Its panes live in `lib/panesStore.ts`; its split layout is a binary tree (`lib/paneLayout.ts`).
- **Deck / deckKey** — one Stage instance per project. `deckKey` is the Command Deck's `selectedProject` (`components/CommandDeck/index.tsx`, search `deckKey={selectedProject}`): a registered project key, or `NO_PROJECT_KEY` for the no-project deck.
- **Leaf** — one visible region of a split layout. `layoutLeafIds` is the list of pane ids that are leaves.
- **Dock** — the new right column (`components/dock/WorkDock.tsx`), rendered by the Stage beside its pane area.
- **Dock tab** — `'files' | 'changes' | 'search' | 'live'` (`DockTab` in `components/dock/workDockStore.ts`; this child adds `'live'`).
- **Dock scope** — what the dock shows: an explorer root plus a changes source, derived from the active Stage tab by `deriveDockScope` (§6.2).
- **Explorer root / rootId** — `project:<key>` (the primary checkout), `issue:<ID>` (a feature workspace), `workspace:<id>` (a scratch edit workspace). Resolved on the server by `src/dashboard/server/services/explorer/roots.ts`.
- **Root path** — a path relative to an explorer root (what the explorer RPCs take). **Repo path** — a path relative to the git top level (what `/api/conversations/:name/changes` returns). They differ only when a root's folder is a subfolder of its repository (§6.5 `toRootPath`).
- **rootOverride / rootOverrideAnchor** — a root the operator picked in the Files header menu (or that a migration or an edit-workspace switch set), and the id of the Stage pane that was active when it was set. The override applies only while that anchor pane is the active pane (B-D17); nothing clears it on a tab change.
- **Conversation changes** — the `ConversationChanges` body served by `GET /api/conversations/:name/changes` (child A, `src/lib/overdeck/conversation-changes.ts`).
- **Changed-here paths** — the root paths a conversation scope changed: its uncommitted files plus the files of its commits (§6.5). They drive the tree dot, the "Only what this conversation changed" filter, the Search dot and the "changed here" ranking.
- **Live items** — the floating conversation dock's panels (`components/dock/ConversationDock.tsx`): issues popped into the dock with `useConvoDock.add`, and conversations with a pending question.
- **Global shortcut** — a registry shortcut with `scope: 'global'` (`lib/shortcuts/registry.ts`): it runs in the capture phase, so it wins inside Monaco and text fields. **not-editing shortcut** — runs only when focus is not in a text field, terminal or code editor.
- **Match tier** — the rank class of a file-name match for Go to file (§6.6): 0 exact basename, 1 basename prefix, 2 basename contains, 3 path contains, 4 fuzzy subsequence.
- **Isolated dashboard** — `startIsolatedDashboard()` in `src/dashboard/frontend/tests/fixtures/isolated-dashboard.ts`: a built dashboard on a free port with a throwaway `OVERDECK_HOME`, never the operator's `:3011`.
- **Workflow fixture** — `scripts/dev/seed-workflow-fixture.ts` (child S): project `workflow-fixture` named "Workflow fixture", conversations `fixture-1` ("Fixture conversation") and `fixture-2`, commits, uncommitted lines in `docs/shared.md`, and a git-ignored `build/output.txt`.

## 3. Decisions

- **B-D1 One issue with a size justification.** The operator's order book already split the epic into children; D-13 requires that the PR removing the `files` tab ship the dock and every entry point. The plan sets `plan.metadata.sizeJustification`.
- **B-D2 Dock placement.** `.stage` becomes a row: a new `.stageMain` column (PaneBar, pane area, terminal drawer) and the `<WorkDock>` beside it, full Stage height. This matches the mockup (the dock sits beside the tab bar, not under it) and still satisfies parent D-2 (the dock is inside the Stage, not in the app grid).
- **B-D3 Opening a file from the dock uses `openBeside`.** `revealPane(id, besidePaneId)` (Stage/index.tsx, search `const revealPane = useCallback`) replaces a region other than `besidePaneId`; the dock is not a leaf, so in a split deck it replaces the active region, which is the chat. Every open from the dock (tree, Go to file, Changes rows, Search hits, diff view) calls `deck.openBeside({ rootId, path, line?, preview? })`. Child C keeps the code-pane header (breadcrumb, File/Changes toggle, Reveal), gutter marks, the editor bar and the chat-side open paths (C's WI-C1 shrinks to the header; that is C's planning input).
- **B-D4 Global shortcuts exist only while a Stage is mounted.** The dock registers `Ctrl+Shift+E` / `Ctrl+Shift+G` / `Ctrl+Shift+F` / `Ctrl+P` (macOS `⌘⇧E` / `⌘⇧G` / `⌘⇧F` / `⌘P`) while it is mounted. On pages without a Stage the keys keep the browser default (`Ctrl+P` prints, as it does today outside the explorer). Behavior: `Ctrl+Shift+E` opens the dock on Files, and closes the dock when it is already open on Files; `Ctrl+Shift+G` does the same for Changes; `Ctrl+Shift+F` opens Search and focuses its input (never closes); `Ctrl+P` opens Go to file. They replace the focus-scoped `explorer.quick-open` and `explorer.content-search` registrations.
- **B-D5 The palette learns the dock through a mount registration.** `CommandPalette` is mounted in `App.tsx`, outside every `StageDeckProvider`. The mounted dock publishes `{ deckKey, rootId, changedPaths, openFile, revealFile }` into a small zustand store `components/dock/activeDock.ts`, and clears it on unmount. `palette/fileProvider.ts` reads it. No `App.tsx` edit beyond removing the floating dock mount. This is not stored status: it is a live registration of the mounted component, like the keyboard registry.
- **B-D6 Ranking tiers live on the server; "changed here" lives on the client.** The server cannot know the scope, and `packages/contracts` is not this child's file (parent §8). `searchFiles` returns paths sorted by tier (§6.6). The client computes the same tier with `fileMatchTier` (same rules, one shared case table), re-sorts changed-here paths first within a tier, tags them "changed here" and highlights the match. The client asks for 200 paths and shows 50.
- **B-D7 Uncommitted diffs are HEAD versus the working tree, built in the browser.** `GET /api/conversations/:name/diffs/full?file=` diffs from the commit at conversation start, so it also contains committed changes and is not a "Not committed yet" diff. Instead the diff view reads `readFile(rootId, path, 'HEAD')` and `readFile(rootId, path)` (explorer RPC) and builds the diff with `parseDiffFromFile` from `@pierre/diffs` (installed, 1.1.22), rendered by the same `FileDiff` component as `DiffPanel`. This is a data source, not a third renderer (parent §6.1 step 9 intent kept). A file whose read returns `kind: 'binary'` or `'large-text'` shows "This file is too large or binary to diff here" with **Open beside**.
- **B-D8 Data sources per scope** are fixed by the table in §6.4. No new server route is added. A cell with no existing source is a non-goal, stated there.
- **B-D9 The Live tab and pages without a Stage.** The floating handle and its `App.tsx` mount go (parent D-17). `useConvoDock.add` keeps setting `expanded: true`; the dock reads `expanded` as "the operator asked to see Live": while a dock is mounted it opens on Live and calls `setExpanded(false)`. An item added on a page with no Stage (Kanban board, issue rows) therefore opens the Live tab the next time a Command Deck deck mounts. Pending-question conversations show in Live whenever a dock is mounted; elsewhere the existing Needs-you strip and top bar keep showing them. A persisted dock tab of `'live'` with zero Live items renders the Files tab.
- **B-D10 The scope of a code pane.** The pane a file "was opened beside" is not stored. Rule: when the active pane is a `code` pane, its root is the dock root and its path is revealed; the changes source is the conversation of the first leaf (in `layoutLeafIds` order) that is an `agent` pane with a resolvable conversation, else the root's own source.
- **B-D11 Project root of a deck.** `deckKey` is the Command Deck's `selectedProject`, which may be a project key or a project name (`findRegisteredProject` in `components/CommandDeck/UnknownProjectState.tsx` matches either, and `CommandDeck` passes `selectedRegisteredProject?.key` separately). So the deck project is `findRegisteredProject(rootContext.projects, deckKey)`, and the deck root is `project:<that project's key>`. The no-project deck (`NO_PROJECT_KEY`) and an unknown value have no root; the Files and Search tabs say "No project is selected, so there are no files to show." Every place that needs the deck's project (deck root, root-menu workspace filter, "Changes in <name>") uses that found project, never `deckKey` directly.
- **B-D12 Today's explorer header buttons keep a home (parent D-14).** Files header: root name and branch (the root name opens the root menu), **New file** (+), **Collapse all**, and **⋯ View options**. The View options menu holds the five view items of FR-9, then a separator, then **New folder**, **Expand all folders** and **Refresh**. The dotfiles eye and the Changed toggle become View options items.
- **B-D13 File icons stay neutral.** The mockup's coloured extension badges use hardcoded brand hex colours, which the style guide forbids (no hex, colour restraint). `fileIcons.ts` maps an extension to a lucide glyph plus a short monospace extension label rendered in `text-muted-foreground`; no brand colours.
- **B-D14 The isolated Playwright spec is not added to CI's `test:playwright` list.** It seeds git repositories and boots a built dashboard; CI e2e is already flaky (#5298). The work agent and the test role run it locally (`npm run build` first). Unit tests carry the CI coverage.
- **B-D15 `changelog.d/pan-5289.md`**, not `5289.md`: `changelog.d/README.md` requires the lowercase issue id.
- **B-D17 An override belongs to the tab that was active when it was set.** Parent §6.3 says the override "wins until the active tab changes". A clearing effect on active-pane changes would also fire during the files-pane migration (closing the active `files` pane changes the active pane) and wipe the override it just set. So the store keeps `rootOverrideAnchor` (the active pane id at the time of the set) and `deriveDockScope` applies the override only while `activePane?.paneId === rootOverrideAnchor` (an `undefined` anchor applies to any pane, for backward compatibility). Returning to the anchor tab shows the override again. No effect writes or clears it on tab changes.
- **B-D16 Edit workspaces follow into the dock.** `switchRoot` and `leaveEditWorkspace` (`explorer/edit/edit-workspace-switch.ts`) also move a dock `rootOverride` equal to the old root. `ensureEditRoot` additionally sets the mounted dock's `rootOverride` to the new edit root, anchored to `activeDock.activePaneId`, when the dock's effective root is the project root it switched from (read from `activeDock`), so a file created in the Files tab stays visible. Moving an override keeps its anchor.

## 4. Requirements

### Functional
- **FR-1** The Stage renders a dock beside its pane area with tabs Files, Changes, Search and (only when it has items) Live; a close button; a left-edge resize handle clamped to 260–720 px and persisted per deck; and a scope line under the tabs (parent FR-7, FR-8, D-2).

- **FR-4** `paneType: 'files'` panes are no longer rendered. On deck load each persisted one is closed and the dock opens on the Files tab with `rootOverride` set to its root (a legacy one with only `issueId` uses `issue:<ID>`; one with neither is closed without opening the dock) (parent D-3, WI-B2).

- **FR-10** The `Ctrl K` palette gains a **Files** scope and a "Files" result group from the mounted dock's root, using the same RPC and ranking (parent FR-12, WI-B6).

### 6.2 Dock scope

`components/dock/dockScope.ts` (pure, no React):

```ts
import type { WorkspacePane } from '../../lib/panesStore'
import type { Conversation } from '../CommandDeck/ConversationList'
import { rootIdForConversation, type RootContext } from '../explorer/rootForConversation'

export type DockRootNullReason = 'linked' | 'outside' | 'no-project'

export type DockChanges =
  | { kind: 'conversation'; conversation: Conversation }
  | { kind: 'root'; rootId: string }            // issue or edit-workspace root: explorer gitStatus
  | { kind: 'project-main'; projectKey: string } // project root: today's commits on the default branch
  | { kind: 'none' }

export type DockHeader =
  | { kind: 'conversation'; title: string; branch: string | null }
  | { kind: 'issue'; issueId: string }
  | { kind: 'workspace' }
  | { kind: 'project' }
  | { kind: 'none' }

export interface DockScope {
  rootId: string | null
  nullReason?: DockRootNullReason
  /** Root path to reveal and select in the Files tab (active code pane). */
  revealPath?: string
  changes: DockChanges
  header: DockHeader
  /** The deck's own project root, or null (B-D11). Used by "Open project files". */
  deckRootId: string | null
}

export interface DockScopeInput {
  activePane: WorkspacePane | null
  layoutLeafIds: readonly string[]
  panesById: ReadonlyMap<string, WorkspacePane>
  deckKey: string
  conversations: readonly Conversation[]
  rootContext: RootContext
  rootOverride?: string
  /** Pane id the override belongs to (B-D17); undefined applies to every pane. */
  rootOverrideAnchor?: string
}

export function deriveDockScope(input: DockScopeInput): DockScope
```

Rules, first match wins (`deckRootId` = `project:<p.key>` where `p = findRegisteredProject(rootContext.projects, deckKey)`, else `null`; B-D11):

1. `rootOverride` set and (`rootOverrideAnchor === undefined` or `rootOverrideAnchor === activePane?.paneId`) → `rootId = rootOverride`; `changes` by its kind: `project:<k>` → `project-main` with `projectKey: k`; `issue:`/`workspace:` → `root`; `header` by kind (`project`, `issue` with the id, `workspace`).
2. Active pane `agent` with a `conversationId` found in `conversations` (match `c.name`) → `rootId = rootIdForConversation(conv, rootContext)`; when `null`, `nullReason = conv.origin === 'linked' ? 'linked' : 'outside'`; `changes = { kind: 'conversation', conversation }`; `header = { kind: 'conversation', title: conv.title?.trim() || 'New conversation', branch: conv.branch ?? null }`.
3. Active pane `agent` with `agentId` and `issueId` (a pipeline session) → `rootId = issue:<ISSUEID upper>`, `changes = root`, `header = issue`.
4. Active pane `issue` with `issueId` → same as rule 3.
5. Active pane `code` with `explorerRootId` → `rootId = explorerRootId`, `revealPath = explorerPath`; `changes` = the conversation of the first leaf in `layoutLeafIds` (other than the code pane) that is an `agent` pane whose `conversationId` resolves (B-D10), else by root kind as in rule 1; `header` by root kind.
6. Anything else (home, editor, browser, commits, plan, docs, legacy `files`, no active pane) → `rootId = deckRootId`; `nullReason = 'no-project'` when null; `changes = deckRootId ? project-main(<deck project key>) : none`; `header = project` (or `none`).

`DockScope` also carries `overridden: boolean` (true when rule 1 applied), so the scope line can offer the reset of §6.3.

`useRootContext()` is extracted from `useRootLabel` in `explorer/rootForConversation.ts` (same react-query keys `['registered-projects']` and `['workspace-registry']`), and `useRootLabel` calls it. Header line text (FR-1, mockup `renderDock`):

| header.kind | Text |
|---|---|
| conversation | `For <b>{title}</b> · {rootLabel} · {branch}` (omit missing parts) |
| issue | `Issue <b>{rootLabel}</b>` (rootLabel is "ID · title") |
| workspace | `Edit workspace <b>{rootLabel}</b>` |
| project | `Project <b>{rootLabel}</b> · main checkout` |
| none | `No project` |

`WorkDock.tsx` props: `{ deckKey, activePane, layoutLeafIds, panesById, conversations }`. It:

### 6.6 Go to file ranking

Rules (server `searchFiles` and client `fileMatchTier`, identical): `q = query.trim().toLowerCase()`; `p = path.toLowerCase()`; `base` = text after the last `/` of `p`.

| Tier | Condition (first true wins) |
|---|---|
| 0 | `q` contains no `/` and `base === q` |
| 1 | `q` contains no `/` and `base.startsWith(q)` |
| 2 | `q` contains no `/` and `base.includes(q)` |
| 3 | `p.includes(q)` |
| 4 | `fuzzyScore(path, query) !== null` (today's function, unchanged) |
| — | no match: excluded |

Server sort: tier ascending; tiers 0–3 then path length ascending, then `localeCompare`; tier 4 by fuzzy score descending, then path length, then `localeCompare` (today's order). Empty `q` returns no paths (today's behavior via `fuzzyScore`). Client: `rankFileMatches(paths, query, changed: ReadonlySet<string>)` stable-sorts by `(tier, changedHere ? 0 : 1)` keeping the server order otherwise, and `matchRanges(path, query)` returns highlight ranges: tiers 0–2 → one range in the basename at `base.indexOf(q)`; tier 3 → one range in the full path at `p.indexOf(q)`; tier 4 → one range per greedy-matched character (same scan as `fuzzyScore`). One JSON case table, `src/dashboard/frontend/src/components/explorer/search/__tests__/file-match-cases.json` (`[{ "path", "query", "tier" }]`, ≥ 12 cases covering every tier, a `/` query, a case-insensitive match and a non-match), is imported (JSON `import`) by both the server test and the client test.

`QuickOpen` (before → after): props gain `changedPaths?: ReadonlySet<string>` and `onReveal?(path: string): void`; it requests `searchFiles(rootId, q, 200)`, applies `rankFileMatches`, shows the first 50, renders the basename and folder with `<mark>` (class `bg-warning/30 text-inherit rounded-sm`) over `matchRanges`, shows a `.chip`-style tag "changed here" for changed paths, Enter calls `onPick`, Shift+Enter calls `onReveal` when given, and a footer reads "Enter open beside the chat · Shift Enter reveal in files · Files changed here rank first".
