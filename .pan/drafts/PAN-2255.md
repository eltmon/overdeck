# PAN-2255: Agent Mailboxes

## Glossary

- Agent mailbox: the issue-addressed feedback contract layered over workspace `.pan/feedback/*.md` files.
- Mailbox item: one numbered feedback markdown file plus machine-readable delivery metadata embedded in that file.
- Issue+role address: durable destination key `{ issueId, role }`, normally `{ "PAN-2255", "work" }`; never an agent id.
- Push delivery: best-effort live `messageAgent` notification to a running agent.
- Drain-on-spawn: deterministic pull step during work-agent spawn/resume that injects pending mailbox items into the first prompt.
- Pending: a mailbox item has been written and still needs an eligible agent to receive it.
- Delivered: the system placed the item pointer in a live push or spawn/resume prompt.
- Acknowledged: the system has recorded that the item was consumed by the issue+role startup/drain contract or is obsolete because the pipeline moved past it.
- Operator escalation: last-resort surfacing to the operator when action-required mail cannot be delivered and no eligible agent appears within the policy window.

## Requirements

- FR-1: Feedback delivery state MUST be addressed by issue id and role, not by `agentId`, so slot churn, resume ids, dashboard restarts, and Deacon auto-resume do not orphan messages.
- FR-2: The existing numbered `.pan/feedback/*.md` files MUST remain the mailbox store; delivery metadata/state is stored with those files, not in a separate archive.
- FR-3: Every work-agent spawn and resume for an issue MUST drain pending and already-delivered-but-action-required mailbox items into the first prompt before normal work continues.
- FR-4: Push delivery to a live agent MAY continue as an optimization, but successful or failed push delivery MUST NOT be the durability guarantee.
- FR-5: Missing live agents MUST NOT immediately mark `feedback_delivery_needs_you`; escalation is allowed only after the default one-Deacon-patrol policy window finds no eligible spawn/resume.
- FR-6: Close-out MUST summarize any still-pending mailbox items in a tracker comment with stale-warning framing before workspace teardown removes `.pan/feedback/`.
- NFR-1: Do not introduce mailbox archiving or a new durable feedback store outside `.pan/feedback/` and the close-out tracker comment.
- NFR-2: Delay/policy-window tests MUST use `vi.useFakeTimers()` and timer advancement, not real sleeps.
- NFR-3: New tmux delivery work MUST use existing async delivery primitives; do not add sync tmux callers.

## Verified References

- `src/dashboard/server/pending-feedback.ts`: currently persists `agentId` in `PendingFeedbackDelivery`, so restart replay still targets an ephemeral agent id.
- `src/lib/cloister/feedback-target.ts`: `resolveIssueFeedbackTarget()` returns `needsYou` and `surfaceIssueFeedbackNeedsYou()` immediately marks `feedback_delivery_needs_you`.
- `src/dashboard/server/routes/workspaces.ts`: `deliverQueuedFeedback()` enqueues by issue but stores `agentId` and deletes the queue only after `messageAgent()` succeeds.
- `src/lib/cloister/feedback-writer.ts`: `writeFeedbackFile()` writes the numbered `.pan/feedback/NNN-*.md` workspace mirror and continue-file feedback entry.
- `src/lib/agents/spawn.ts`: `spawnAgent()` builds and delivers the initial work prompt; this is the spawn drain point.
- `src/lib/agents/resume.ts`: `resumeAgent()` builds and delivers resume/continue prompts; this is the resume drain point.
- `src/lib/cloister/deacon-auto-resume.ts`: `handleAgentStoppedEvent()` is the Deacon auto-resume path that must naturally pick up mailbox drains.
- `src/lib/close-out.ts`: `executeCloseOutPromise()` closes the tracker and removes the workspace; pending mailbox comments must happen before workspace teardown destroys `.pan/feedback/`.
