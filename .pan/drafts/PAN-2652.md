# PAN-2652 — Conversation view follows Claude Code session forks

**Issue:** https://github.com/eltmon/overdeck/issues/2652
**Related:** #2672 (post-/clear siblings render the original transcript — same pin-first root cause; this PRD fixes its transcript-resolution half only).
**Status:** planned (auto mode, 2026-11-05). Verified against `main` at `df325e4cb3f` (v0.74.0).

## Glossary

- **Session id** — the UUID Claude Code uses as a transcript file name: `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`.
- **Locator** — one row of the `conversation_files` table (`conversation_id`, `harness`, `locator` = session id, `created_at`, autoincrement `id`). A conversation can have several. DDL: `drizzle/overdeck/0000_overdeck_init.sql:58`. There is **no unique index** on `(conversation_id, locator)`, so `INSERT OR IGNORE` never ignores.
- **Read door** — `LEGACY_CONVERSATION_SELECT` in `src/lib/overdeck/conversations.ts`; it derives `LegacyConversation.claudeSessionId` from the locators.
- **Write door** — `setConversationClaudeSessionId(name, id)` in `src/lib/overdeck/conversations.ts`.
- **Origin locator** — the oldest locator of a conversation. Listing surfaces (sessions feed, archive, title search) keep using it; this PRD does not change them.
- **Current locator** — the newest claude-code locator (`created_at DESC, id DESC`). After this PRD, `claudeSessionId` means the current locator.
- **Launcher pin** — the `--session-id <uuid>` or `--resume <uuid>` in `~/.overdeck/conversations/<tmuxSession>/launcher.sh` (fallback `~/.overdeck/agents/<tmuxSession>/launcher.sh`), read by `readLauncherPinnedSessionId` (`src/lib/agents/transcript-resolver.ts:92`). It is written once per spawn and never changes while the process lives.
- **Fork** — Claude Code continuing a running process in a **new** session file that copies some or all of the old file's entries with the **same entry `uuid` values**. Backgrounding a turn ("Backgrounding after the current tool finishes…") does this in-process; the process, its cmdline and the launcher keep the old id.
- **Lineage** — candidate file F is a fork of current file CF when at least one of the first 20 `uuid` values found in F's entries also appears in CF. Copied entries predate the fork, so a lineage verdict for a (CF, F) pair never changes once computed.
- **Session index** — `~/.overdeck/agents/<tmuxSession>/sessions.json`, append-only JSON lines `{sessionId, at, source, harness, model, path?}`. Since PAN-3950 the `session-start-hook` and `heartbeat-hook` (`sync-sources/hooks/heartbeat-hook`, `pan_append_session_index` in `sync-sources/hooks/pan-hook-lib.sh:121`) append it for `conv-*` sessions too. `parseSessionIndex` (`src/lib/session-history.ts:142`) dedups by id and moves a re-observed id to the end, so the last entry is the most recently observed session.
- **Human conversation** — a row whose name does not start with `agent-`, `planning-` or `specialist-` (`isAgentConversationName`, `src/lib/overdeck/conversations.ts:419`).
- **Chain head / superseded row** — PAN-4485 /clear chain (`src/lib/overdeck/conversation-clear-chain.ts`). A row with `clearedToConvId != null` is superseded (`isSupersededConversation`) and owns nothing; the chain head owns the shared terminal session.
- **Eligible conversation** (for adoption) — `status === 'active'`, human, not superseded, harness transcript kind `claude-jsonl`, `cwd` set, `claudeSessionId` set.

## Problem (verified 2026-11-05)

The Conversation tab freezes while the Terminal advances, because nothing notices that Claude Code moved the live session to a new file. Five points, all present on `main`:

1. **Launcher pin wins.** Four sites compute `pinned ?? conv.claudeSessionId`:
   - `src/lib/overdeck/conversation-reads.ts:158-159` (`resolveSessionFile`) — quote: `const pinned = await readLauncherPinnedSessionId(conv.tmuxSession);`
   - `src/dashboard/server/ws-rpc.ts:826-833` (`subscribeConversationMessages`) — quote: `const resolvedSessionId = pinnedSessionId ?? conv.claudeSessionId;`
   - `src/dashboard/server/sharing/conversation-bridge.ts:233-234` (`resolveClaudeSessionFile`)
   - `src/lib/overdeck/fork-source-session.ts:83-84` (`resolveForkSourceSessionFile`)
2. **Oldest locator wins.** `src/lib/overdeck/conversations.ts:409` — quote: `ORDER BY (cf.harness = 'claude-code') DESC, cf.created_at ASC, cf.id ASC`.
3. **The /clear scanner adopts only /clear files.** `detectOrphanedClaudeCodeSessions` (`src/dashboard/server/services/conversation-lifecycle.ts:514`) requires the `/clear` sentinel in the first 5 lines (`readFirstClearTimestamp`, line 646). Correct by its design; a fork has no sentinel.
4. **Agents only.** `resolveLiveSessionId` (`conversations.ts:435-442`) consults the session index only for agent names; for human rows it returns the oldest locator.
5. **The write door does nothing.** `setConversationClaudeSessionId` (`conversations.ts:894-903`) inserts a newer row that the oldest-wins read door never returns. The native-compact path (`src/lib/overdeck/conversation-message.ts:472`) and the Kimi spawn path (`src/lib/agents/spawn.ts:483`) write through it.

Consequences beyond the frozen tab, all from the stale `claudeSessionId`:
- Resume and restart-all respawn `--resume <oldest id>` (`conversation-runtime.ts:1116,1137`; `conversation-restart-all.ts:33,39`), so a resumed conversation silently returns to the pre-fork session.
- Delivery receipts watch the stale file (`conversation-message.ts:586-587,643-648`).
- Cost ledger joins `cost_events.session_id = conversation_files.locator` (`src/lib/overdeck/conversation-ledger-costs.ts:27`); fork-session costs are missing from the ledger until a locator exists.
- An open Conversation tab streams one file for the life of the subscription: `streamClaudeTranscript(sessionFile, …)` (`src/dashboard/server/services/claude-transcript-stream.ts:27`), and the frontend resubscribes only on a name change (`useConversationMessagesStream.ts`, `streamIdentity = …:${conversation.name}`).

## Decisions

- **D1 — Current = newest locator.** Flip the read-door subquery to `created_at DESC, id DESC` (keep the claude-code harness preference). The oldest locator stays the origin for the listing queries that carry their own `ASC` copy (`sessions-feed.ts:226`, `conversation-archive.ts:148,174`, `conversation-title-search.ts:48`); they are not touched.
- **D2 — Write door re-points without duplicating.** No unique index exists, and the ledger sums over every matching locator row, so a duplicate row double-counts cost. The write door: no-op when the id is already current; `UPDATE created_at` when the row exists but is not current; `INSERT` otherwise. It emits a session-changed notification only when the current locator changed.
- **D3 — Precedence for the four pin-first sites** (new helper `resolveConversationClaudeSessionId`):
  - agent conversation → `pin ?? claudeSessionId` (unchanged behavior, out of scope);
  - superseded row → `claudeSessionId` only, never the pin (the pin belongs to the chain head);
  - human chain head → `claudeSessionId ?? pin`.
  Safe because every id a human conversation is launched with is either a recorded locator or used only when no locator exists: `createConversation` records the id (`conversation-runtime.ts:1037-1041`, `src/lib/flywheel/actions.ts:133` after `createConversation`); resume and restart-all launch `conv.claudeSessionId ?? randomUUID()` (`conversation-runtime.ts:1137`, `conversation-restart-all.ts:39`), so a random id appears only when the row has no locator, and then the pin fallback answers. Verified with `git grep -n "randomUUID()" src/lib/overdeck/ src/lib/flywheel/actions.ts`: the only session-id `randomUUID()` hits are `conversation-runtime.ts:1037` (recorded by `createConversation`), `flywheel/actions.ts:217` (recorded by `createConversation`), and the two `?? randomUUID()` fallbacks above. `ensureForkSessionReady` (`conversation-forks.ts:221`) is called with `conv.claudeSessionId` (`conversation-kickoff.ts:23`, `conversation-vault-continue.ts:75`); `reactivateConversationForSpawn` (`conversations.ts:814-838`) records its id as a new locator, which the flipped read door now returns (this also fixes singleton re-runs, the PAN-1866 reason for pin-first). `handleConversationSwitchModel` does not respawn a started conversation (model and harness are locked once `claudeSessionId` is set, `conversation-runtime.ts:404-415`).
- **D4 — Adoption runs in the 10-second lifecycle poll**, immediately before `detectOrphanedClaudeCodeSessions` (`conversation-lifecycle.ts:429`). The hooks write `sessions.json` client-side; `src/dashboard/server/routes/hooks.ts` receives `session_id`/`transcript_path` only for the memory pipeline, so there is no server event to hang adoption on.
- **D5 — Two candidate sources, one lineage guard.** Source A: the conversation's session index (cheap, generic for any harness-side rotation the hooks report). Source B: the backgrounding marker in the current file's tail plus a project-dir scan (covers the case where hooks do not report the fork id, or hooks are absent). Every candidate must pass lineage, must not start with the /clear sentinel, must not already be a locator of any conversation, and must live directly in `claudeProjectDir(conv.cwd)`. Lineage is what keeps a post-/clear session (recorded in the same `sessions.json`) and nested `claude` runs in the same terminal session from being adopted.
- **D6 — The open stream follows the conversation's session.** A small in-process notifier (leaf module, no wire contract change) is fired by the write door; `subscribeConversationMessages` switches to the new file with `Stream.switchMap` and the first event from the new file is a snapshot with `reset: true` (a fork can be shorter than the old file — 2,037 vs 12,384 entries — and `applyConversationMessagesEvent` suppresses a shrinking snapshot without `reset`).
- **D7 — Native `/compact` restarts the runtime on the compacted fork.** Once the write door is real, the native-compact locator write makes the view show the compacted fork while the live process keeps writing the old file — the same divergence this issue fixes. Restarting the runtime with `--resume <fork>` is the only coherent meaning of native compaction. (Opt-in path: `manualCompactMode === 'overdeck-native'`, `conversation-compaction.ts:43-47`.)
- **D8 — Process matching keeps the launched id.** `conversationRuntimeRootPids` (`conversation-runtime.ts:167-180`) matches `--resume <claudeSessionId>` / `--session-id <claudeSessionId>`. After adoption the process cmdline still carries the pinned id, so the needle set must include the launcher pin; the `launcher.sh` path match alone is not relied on.
- **D9 — Launcher is not rewritten in place.** The next resume or restart regenerates it from the current locator (`--resume <current>`).

## Planning Q&A

Auto mode (`pan plan --auto`): no questions were asked. Defaults chosen:

/**
 * In-process notification that a conversation's current Claude session changed
 * (PAN-2652). Fired by the write door (setConversationClaudeSessionId) only when
 * the current locator actually changed; the live transcript stream listens so an
 * open Conversation tab follows forks without a reload.
 */
type Listener = (sessionId: string) => void;
const listeners = new Map<string, Set<Listener>>();

export function onConversationSessionChanged(name: string, listener: Listener): () => void {
  const set = listeners.get(name) ?? new Set<Listener>();
  set.add(listener);
  listeners.set(name, set);
  return () => {
    set.delete(listener);
    if (set.size === 0) listeners.delete(name);
  };
}

export function notifyConversationSessionChanged(name: string, sessionId: string): void {
  for (const listener of [...(listeners.get(name) ?? [])]) {
    try { listener(sessionId); } catch { /* a listener failure never breaks the write door */ }
  }
}
```

export function setConversationClaudeSessionId(name: string, claudeSessionId: string): void {
  const db = overdeckDb();
  const id = getConversationUuidByName(name);
  if (!id) return;
  const harness = getConversationByName(name)?.harness ?? 'claude-code';
  const changed = db.transaction(() => {
    const current = db.prepare(`
      SELECT locator, created_at FROM conversation_files WHERE conversation_id = ?
      ORDER BY (harness = 'claude-code') DESC, created_at DESC, id DESC LIMIT 1
    `).get(id) as { locator: string; created_at: number } | undefined;

    // Strictly newer than the current row so same-millisecond writes still win.
    const now = Math.max(toMillis(), (current?.created_at ?? 0) + 1);

    }
    return true;
  })();

}

 * The Claude session id a conversation's transcript reads use (PAN-2652).
 * Human chain heads: the current locator, then the launcher pin. Superseded
 * /clear rows: their own locator only — the shared launcher belongs to the head.

import { isAgentConversationName, type LegacyConversation } from './conversations.js';

type SessionConv = Pick<LegacyConversation, 'name' | 'tmuxSession' | 'claudeSessionId' | 'clearedToConvId'>;

export async function resolveConversationClaudeSessionId(
  conv: SessionConv,

/**
 * Follow a conversation's current Claude session for a live transcript stream
 * (PAN-2652). Opens the stream on the resolved file, then, on every
 * session-changed notification, re-resolves and switches; the first snapshot
 * from a switched file carries reset: true so a shorter fork replaces the view.
 */
export function followConversationSession<E, R>(
  conversationName: string,
  open: (switched: boolean) => Stream.Stream<E, PanRpcError, R>,
): Stream.Stream<E, PanRpcError, R> {
  const changes = Stream.callback<boolean, PanRpcError>((queue) =>
    Effect.acquireRelease(
      Effect.sync(() => onConversationSessionChanged(conversationName, () => {
        try { Queue.offerUnsafe(queue, true); } catch { /* disconnected */ }
      })),
      (off) => Effect.sync(off),
    ),
  );
  return Stream.concat(Stream.make(false), changes).pipe(Stream.switchMap(open));
}
```
