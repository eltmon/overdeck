# PAN-2311 — Reconcile per-issue record on strike-PR / UAT-batch merges + merge-fulfillment verifier

**Issue:** [PAN-2311](https://github.com/eltmon/overdeck/issues/2311) — bug(pipeline): strike-PR / UAT-batch merges don't reconcile per-issue record (mergeStatus/labels/branches) — done issues stuck 'pending' + add merge-fulfillment verifier

Planning model: `agent:claude-opus-4-8` · auto mode (no interactive Q&A)

---

## Glossary

- **Per-issue record** — the permanent-plane JSON at `.pan/records/<issue-lowercase>.json`, holding the `pipeline` block (`reviewStatus`, `testStatus`, `mergeStatus`, `readyForMerge`, `closedOut`…), `closeOut`, and `owner`. Written only through the single write door in `src/lib/pan-dir/record.ts`/`records.ts`. Git-backed, travels across machines.
- **`review_status` table** — the runtime-plane SQLite cache (`~/.overdeck/overdeck.db`) of the same verdicts. Rebuildable; not authoritative.
- **Write door** — `setReviewStatusSync(issueId, update)` (`src/lib/review-status.ts:221`). It writes the journal record FIRST (`updateIssueRecordForReviewStatusSync` → `updateIssueRecordForIssue` → `projectPipeline`) then best-effort upserts the SQLite row.
- **Read door (per-issue)** — `getReviewStatusSync(issueId)` (`src/lib/review-status.ts:714`). DB-first with a self-healing fallback: when the DB row is missing/stale it overlays the record's `pipeline` block (`readJournalStatusSync`) and lazily re-upserts.
- **`postMergeLifecycle`** — the *merge* reconciliation ceremony (`src/lib/cloister/merge-agent.ts:319`). Sets `mergeStatus='merged'`, applies `merged` + `verifying-on-main` labels, kills sessions/Docker, transitions the issue to `verifying_on_main`. It does NOT set `reviewStatus='passed'`, does NOT apply `closed-out`, and does NOT delete branches — those belong to close-out (`src/lib/close-out.ts`).
- **Merge oracle** — `verifyMergedBeforeLifecycle(issueId, projectPath, sourceBranch?, options?)` (`merge-agent.ts:277`). The gate at the top of `postMergeLifecycle`. Authoritative check: `gh pr list --head <branch>` must show a merged PR. `options.allowVerifiedNoPrMerge` accepts the *no-PR* case only.
- **Strike** — `pan strike <id>` creates a `strike/<id>` worktree off `origin/main`; the spawner merges it and (should) run `pan done <id> --strike`.
- **UAT batch train** — `promoteUatGeneration` (`src/lib/cloister/uat-promote.ts:95`) merges an aggregate `uat/<codename>` branch into main in one no-ff commit carrying multiple member issues.
- **Merge-fulfillment verifier** — new capability: for a done/closed issue whose record says `mergeStatus != merged`, verify at git/code level that the work is actually on `origin/main`, then reconcile the record → merged or flag a genuinely-stranded issue.

---

## Problem

18 `done`/closed issues carry `pipeline.mergeStatus=pending` in `.pan/records/pan-XXXX.json` and lack `merged`/`closed-out` labels, **despite their work being genuinely merged into main**. Leftover `feature/pan-2258` + `strike/pan-*` branches were never cleaned. Drift set: PAN-1762, 1832, 1847, 1919, 1935, 1989, 2044, 2076, 2148, 2150, 2155, 2173, 2174, 2181, 2214, 2222, 2248, 2258.

The project tree renders canonical `state` (Done); the issue slide-out renders `mergeStatus` (pending) — hence "Done in tree / pending in display."

### Root cause (verified against the code, three distinct gaps that share one theme)

The theme: **on-merge reconciliation is keyed on the member issue's *own* `feature/<id>` PR.** Merges that land through any other branch shape never reconcile the per-issue record.

1. **Strike PRs** — a strike works on `strike/<id>`. The automatic on-merge hook is the GitHub webhook `handlePullRequestPromise` (`src/lib/webhook-handlers.ts:373`), which fires `postMergeLifecycle` on `pr.merged === true` (dispatch at `webhook-handlers.ts:388-402`). But it first calls `issueIdFromBranch(pr.head.ref)` (`webhook-handlers.ts:48-51`), whose regex `feature\/([a-z]+-\d+)$` matches only `feature/…`. A merged `strike/pan-XXXX` PR returns `null` and is dropped at `webhook-handlers.ts:378` — no reconciliation. `pan done <id> --strike` (`src/cli/commands/done.ts:480-511`) reconciles correctly, but nothing runs it automatically on a PR merge, and the role model now has the spawner (not the agent) merge the strike branch (`roles/strike.md`). No deacon sweep compensates (all key on `feature/<id>` + an in-pipeline review record which strikes lack).

2. **UAT batch members** — `promoteUatGeneration` DOES fan out `firePostMergeLifecycle(member.issueId)` once per member (`uat-promote.ts:184-189`). But `postMergeLifecycle` bails at its oracle guard (`merge-agent.ts:361-365`): a member's commits reached main only via the aggregate `uat/…` merge commit, so `gh pr list --head feature/<id>` shows the member's *own* PR still open → `verifyMergedBeforeLifecycle` returns `merged:false` at `merge-agent.ts:313` and everything after (mergeStatus at `:370`, labels at `:428-438`) is skipped. `allowVerifiedNoPrMerge` only rescues the *no-PR* case (`:311`), not the *open-PR* case. So per-issue reconciliation is *invoked but ineffective*.

3. **Renumbered / alternate PRs** — e.g. PAN-2248 landed as `#2264`. As long as the head ref is `feature/<id>` or `strike/<id>` the branch-based fixes above catch it; the PR *number* changing is not the problem, the branch shape is.

The empty `review_status` table is **not** an independent bug: it is by design (JSON/git-backed cache, no boot seed — PAN-1983). The per-issue read door self-heals from the record's `pipeline` block, but the record itself says `pending`, so the display shows `pending`. The defect is entirely upstream in the records.

The read-door done→merged reconciliation in `issue-data-service.ts` is the scope of a **separate** issue (PAN-2310) and is explicitly out of scope here.

---

## Proposal

Close the three merge-completion gaps at their source, add a durable code-level verifier/backfill safety net, and reconcile the existing 18-issue drift set:

- **Strike:** widen `issueIdFromBranch` so the existing merge webhook recognizes `strike/<id>` refs and dispatches `postMergeLifecycle`; ensure the strike reconciliation also marks `reviewStatus='passed'` (strikes skip the review role that normally sets it).
- **UAT batch:** thread a caller-verified, code-level "already on main" signal from the per-member fan-out through `firePostMergeLifecycle` → `postMergeLifecycle` → the oracle, so a member whose own PR is still open but whose `headSha`/`branch` is an ancestor of `origin/main` is accepted and reconciled.
- **Verifier core:** a new module that, for one issue, returns `merged | stranded | unknown` using code-level evidence only (tracked-PR merged state and/or `git merge-base --is-ancestor <branch> origin/main`) — never a commit-subject grep.
- **Reconcile action:** a shared helper that finishes the record/label/branch bookkeeping for an already-merged, already-closed issue without resurrecting it into `verifying_on_main`.
- **CLI backfill:** `pan admin db reconcile-merges` runs the verifier over done/closed issues with `mergeStatus != merged`, reconciles the confirmed-merged, and flags the stranded.

## Requirements

### Functional
- **FR-1** A merged `strike/<id>` PR reconciles the per-issue record identically to the standard path: `pipeline.mergeStatus='merged'`, `reviewStatus='passed'`, `merged` label applied, `verifying-on-main` handoff started.
- **FR-2** After a UAT batch promote, every member's per-issue record has `pipeline.mergeStatus='merged'` and the `merged` label applied — even though each member's own PR is still open.
- **FR-3** The merge-fulfillment verifier decides `merged` vs `stranded` for one issue using code-level evidence only (tracked-PR merged state and/or feature/strike branch tip contained in `origin/main`); an issue mentioned only incidentally in a commit subject (e.g. `chore(records): update PAN-123`) is not, by itself, judged merged.
- **FR-4** A reconcile action sets `mergeStatus='merged'` + `reviewStatus='passed'` on the record, applies `merged` (and `closed-out` when the issue is closed) labels, and deletes the feature/strike branch only when it is contained in `origin/main`; it never deletes an uncontained branch and never resurrects a closed issue into `verifying_on_main`.
- **FR-5** `pan admin db reconcile-merges [--issue-id <id>] [--dry-run] [--verbose]` enumerates done/closed issues whose record `mergeStatus != merged`, reconciles those the verifier confirms merged, and prints (without reconciling) those it judges stranded.
- **FR-6** Running the backfill over the current 18-issue drift set reconciles the genuinely-merged issues and surfaces any stranded issue (work not on main) rather than silently marking it merged.

### Non-functional
- **NFR-1** No new direct store access — record writes go through `setReviewStatusSync` / the record write door; label and branch operations reuse existing helpers (`cleanupMergedLabels`, the close-out label constants, the strike/feature reapers or the same `git` primitives).
- **NFR-2** Idempotent and safe to re-run: reconciling an already-reconciled issue is a no-op; the `postMergeLifecycle` in-flight guard (PAN-328) stays intact.
- **NFR-3** Merge verification uses async `exec`/`gh` (no `execSync` in server-reachable code); any delay/retry test uses fake timers.

---

## Decisions (made in this document)

- **DEC-1** The empty `review_status` table is working-as-designed; do NOT add boot-time table repopulation. The per-issue read door already self-heals from the record. Resolves issue "Fix scope" item 2 as an investigation with a no-code outcome.
- **DEC-2** The read-door done→merged reconciliation (`issue-data-service.ts`) is PAN-2310's scope — NonGoal here.
- **DEC-3** "Real merge" is defined as: the issue's tracked PR reports merged, OR the issue's `feature/<id>` or `strike/<id>` branch tip is an ancestor of `origin/main` (`git merge-base --is-ancestor`). A `git log --grep PAN-<id>` match is explicitly rejected as evidence because it matches incidental mentions in `chore(records)`/`chore(beads)`/`chore(state)`/`docs:` commits and other PRs' bodies.
- **DEC-4** Strike/backfill reconciliation sets `reviewStatus='passed'` in addition to `mergeStatus='merged'` (strikes and the backfilled drift issues skip the review role that normally sets `reviewStatus='passed'`). UAT members already carry `reviewStatus='passed'` from their review, so the UAT fix only needs `mergeStatus`.
- **DEC-5** The backfill uses the lean reconcile action (FR-4), NOT full `postMergeLifecycle`, for already-done/closed issues — `postMergeLifecycle`'s terminal-guard would short-circuit anyway, and we must not transition a closed issue back into `verifying_on_main` or trigger a deploy/verification.
- **DEC-6** The UAT batch signal is code-level (member `headSha`/`branch` ancestor of `origin/main`), not a blind "trust the caller" flag — so a member whose commits did NOT actually land is still refused.

### 1. strike-webhook-reconcile — recognize merged `strike/<id>` PRs (FR-1, DEC-4)
- **Files:** `src/lib/webhook-handlers.ts`; `src/cli/commands/done.ts` (strike path); `src/lib/cloister/merge-agent.ts` (add `markReviewPassed?` option); tests under `tests/unit/lib/webhook-handlers*.test.ts`.
- **Change:** widen `issueIdFromBranch` (`webhook-handlers.ts:48-51`) to match `(?:feature|strike)\/([a-z]+-\d+)$` so all 7 callers recognize strike refs; the existing merged-PR dispatch (`:388-402`) then fires `postMergeLifecycle(issueId, projectPath, pr.head.ref, { markReviewPassed: <ref starts with strike/> })`. Add a `markReviewPassed?: boolean` option to `postMergeLifecycle` that folds `reviewStatus:'passed'` into the `setReviewStatusSync` at `merge-agent.ts:370`. Pass `markReviewPassed:true` from `pan done --strike` (`done.ts:493`).
- **Why:** strike PRs are the largest slice of the drift set; this is the automatic on-merge reconciliation for future strikes.

### 2. uat-batch-member-reconcile — accept batch-merged members (FR-2, DEC-6)
- **Files:** `src/lib/cloister/merge-agent.ts` (oracle + option), `src/dashboard/server/routes/specialists/shared.ts` (`firePostMergeLifecycle` options passthrough), `src/lib/cloister/uat-promote.ts` (fan-out passes member context); tests under `src/lib/cloister/__tests__/`.
- **Change:** add `verifiedMergedBranch?: string` / `verifiedMergedSha?: string` option to `postMergeLifecycle` → `verifyMergedBeforeLifecycle`; when set, the oracle accepts the member as merged if `git merge-base --is-ancestor <sha-or-branch> origin/main` succeeds, even when its own PR is open. `firePostMergeLifecycle` gains an optional opts arg and forwards it. At the fan-out (`uat-promote.ts:186-189`) pass each `member.branch`/`member.headSha`.
- **Why:** the reconciliation is already invoked per member — this makes the oracle stop silently rejecting them.

### 3. merge-fulfillment-verifier — code-level merged/stranded verdict (FR-3, DEC-3)
- **Files:** new `src/lib/pan-dir/merge-fulfillment.ts` exporting `verifyIssueMergeFulfillment(issueId, project): Promise<{ verdict: 'merged'|'stranded'|'unknown'; evidence: string }>`; unit test `src/lib/pan-dir/__tests__/merge-fulfillment.test.ts`.
- **Change:** read the record (prUrl/prNumber); check tracked-PR merged state (reuse `gh pr view`/`getPullRequestState`) and `git merge-base --is-ancestor` for `feature/<id>` and `strike/<id>` against `origin/main` (mirror `verifyStrikeBranchMergedIntoMain`, `done.ts:336`). `merged` = PR merged OR a branch contained; `stranded` = neither, and no branch exists; `unknown` = cannot resolve (non-GitHub / branch absent / API error). Never use `git log --grep`.
- **Why:** foundation for beads 4-5; encodes the "real merge vs incidental mention" contract.
- **requiresInspection: true** (foundation for 4 and 5; defines the verdict contract).

### 4. reconcile-merged-issue-action — finish record/label/branch bookkeeping (FR-4, DEC-4, DEC-5)
- **Files:** `src/lib/pan-dir/merge-fulfillment.ts` (or a sibling `merge-reconcile.ts`) exporting `reconcileMergedIssue(issueId, project, opts)`; unit test.
- **Change:** `setReviewStatusSync(issueId, { mergeStatus:'merged', reviewStatus:'passed', readyForMerge:false })`; apply `merged` label and, when the tracker issue is closed, `closed-out` label + strip workflow labels (reuse `cleanupMergedLabels` and the close-out label constants in `close-out.ts`); delete `feature/<id>`/`strike/<id>` (local+remote) only when contained in `origin/main`.
- **Why:** the lean, close-out-shaped reconciliation the backfill needs for already-done issues.

### 5. cli-reconcile-merges — `pan admin db reconcile-merges` backfill (FR-5, FR-6)
