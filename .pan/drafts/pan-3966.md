# PAN-3966 — Warm-idle reap and agent stop are tmux-only: a lingering Herdr pane blocks every role-run re-dispatch with `already running`

**Issue:** https://github.com/eltmon/overdeck/issues/3966
**Planned:** 2026-09-21 (auto mode, no operator questions) against `a06277393fe` on `feature/pan-3966`.
**Precedent fix:** `3760a5d5bc4` (the sequencer-only reap). This PRD generalizes it.

## Glossary

- **Terminal backend** — the pane substrate an agent runs in. `src/lib/terminal-backends/select.ts` picks **Herdr** when the `herdr` binary and this Overdeck home's session socket exist, else **tmux**. `OVERDECK_TERMINAL_BACKEND` and `terminal.backend` in config.yaml override the probe.
- **Herdr pane** — a pane in the `herdr --session overdeck` server. Its shell is a bare `/bin/bash`; Overdeck's launcher runs as a child of that shell. The pane **outlives** the harness: when `claude` exits the pane sits at `$`, and when `claude` is idle at its prompt the pane reports `agent_status: idle`.
- **Detected agent** — a Herdr pane whose foreground process Herdr recognised (claude-code). It has an agent record: `agent.get <name>` answers it. **Pane-bound agent** — a pane Herdr holds no record for (codex, ACP, kimi, ohmypi); it is found only by the `agentId` token on the pane (`session.snapshot` / `pane list`).
- **`agentPaneExists(agentId)`** (`src/lib/terminal-backends/launch.ts:130`) — the spawn guard: true when a tmux session or a live Herdr agent/pane of that name exists.
- **`closeAgentPane(agentId)`** (`launch.ts:148`) — closes the Herdr pane `agentPaneExists` sees via `findHerdrAgent` → `backend.close`. Returns `false` on tmux or when nothing is found. Added by the sequencer fix.
- **Liveness oracle** — `isAlive(agentId)` in `src/lib/agents/liveness.ts:149`. Returns `{alive: true}` or `{alive: false, reason: 'no-session' | 'pane-dead' | 'runtime-missing' | 'runtime-indeterminate'}`. On Herdr it maps `probeHerdrAgentLiveness`: `alive → alive`, `exited → pane-dead`, `absent → no-session`, `indeterminate → runtime-indeterminate` (`liveness.ts:161-184`).
- **Warm-idle leftover** — a role-run session (review/test/ship/sequencer) that finished its cycle and is still alive at its prompt by design (PAN-2579, `docs/ROLES.md` "Session lifecycle: warm by default").
- **Role run** — a non-work agent spawned by `spawnRun` (`src/lib/agents/spawn.ts:120`): review, test, ship, plan helpers, `sequencer-runner`.
- **Settle** — waiting, bounded, for Herdr to drop the agent record after `pane.close`; Herdr drops it asynchronously, so an immediate relaunch under the same name can still collide.
- **`stopAgent` / `stopAgentSync`** (`src/lib/agents/termination.ts:200` / `:150`) — the two stop doors. Every stop path in the codebase ends in one of them (dashboard Stop button → `stopAgent`; `pan kill`, `pan pause`, the memory governor, the emergency brake, handoff rework, swarm stop/reset → `stopAgentSync`).

## Problem

Since the Herdr cut (PAN-3917) both stop doors and the `spawnRun` warm-idle reap only reach tmux:

1. **`stopAgent` / `stopAgentSync` never close a Herdr pane.** `termination.ts:153-167` and `:207-225` run `sessionExists` → `killSession` (tmux only), then `killLauncherProcessSync/Async` (`:61-143`) which does `pgrep -f <agents>/<id>/launcher.sh`. A Herdr pane's shell is `/bin/bash` and the harness was `exec`'d, so the sweep matches nothing. State is rewritten to `stopped`, the pane and the idle harness survive, and `findHerdrAgent` keeps reporting the agent. Verified live 2026-09-20: `claude` pid's parent cmdline `/bin/bash`, grandparent `herdr --session overdeck server`.
2. **`spawnRun`'s reap is tmux-only.** `spawn.ts:176-196`: when `agentPaneExists` is true it probes `isPaneDead` (tmux `#{pane_dead}`), which on Herdr catches and answers `false`, so the "reap the warm-idle leftover" path never fires and the spawn throws `Role run <id> already running`.
3. Every pre-spawn stop in the pipeline — `review-convoy.ts:230`, `verification-runner.ts:134`, `handoff.ts:124`, `start-fresh-session.ts:99`, `swarm.ts:401/698` — therefore stops nothing on Herdr, and the next `spawnRun` (or `spawnAgent`'s guard at `spawn.ts:630`) refuses. 749 sequencer refusals Aug 28–Sep 20; the sequencer was patched in isolation (`3760a5d5bc4`), every other role run still hits the wall.

Live census 2026-09-21 (`herdr --session overdeck agent list`): ~20 finished agents at `idle`/`done` with `claude` still alive — the residue this issue leaves behind.

**Load-bearing change:** making the stop doors close the Herdr pane. The `spawnRun` reap widening (item 4) only covers the `exited` case; a warm-idle leftover whose harness is still alive is, by PAN-2579 design, refused by the guard — what unblocks re-dispatch there is that the caller's `stopAgent` now empties the pane first, so `agentPaneExists` answers false.

## Decisions (made here, not by the executor)

- **D1. `stopAgentSync` gets a synchronous Herdr close through the `herdr` CLI; no caller migrates.** Nine callers use the sync door; `kill.ts` alone has five test files asserting `stopAgentSync` was called, and `emergencyBrake` (`concurrency.ts:355`) is sync and `Effect.try`-wrapped. A sync CLI shell-out fixes all nine at once with zero caller churn, and `killLauncherProcessSync` already shells out synchronously in that same function, so the posture is unchanged. The async door uses the existing socket client via `closeAgentPane`.
- **D2. The sync helper lives in a new leaf module `src/lib/terminal-backends/herdr-cli-sync.ts`** importing only `./select.js` and `node:child_process`/`node:fs`. `termination.ts` needs a *static* import; `launch.ts` pulls both adapters (tmux adapter → liveness → runtime-state → conversations) and would risk a new cycle against `scripts/circular-deps-baseline.txt`. The async door lazy-imports `launch.js` inside the function (the `spawn.ts:185` pattern).
- **D3. Sync backend gate (no duplication of `selectTerminalBackend`):** skip when `process.env.OVERDECK_TERMINAL_BACKEND === 'tmux'` or the configured `terminal.backend === 'tmux'`; otherwise attempt only when `existsSync(herdrSocketPath())`. The leaf module never imports `config-yaml`: `termination.ts` reads `loadConfigSync().terminal?.backend` itself (it already sits inside the agents-barrel closure that imports config-yaml, so no new edge) and passes it in as `configBackend`. A missing binary surfaces as `spawnSync` `error` (ENOENT) and is a no-op.
- **D4. Settle lives inside the close helpers** (async `closeAgentPane` and sync `closeHerdrPaneSync`): poll "is it still there" every 200 ms for at most 3000 ms after `close`. Both stop doors and the `spawnRun` reap inherit it. Sync sleep = `Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, ms)` (no subprocess).
- **D5. Every `spawnSync` carries `timeout: 3000`** so a hung socket cannot wedge `pan kill` or the deacon. Worst case for one wedged stop ≈ 12 s (get + list + close + settle).
- **D6. `spawnRun` reap criterion = `isAlive` says `pane-dead`, OR `no-session`** (the record dropped between `agentPaneExists` and the probe — a spurious refusal otherwise). `runtime-indeterminate` and `alive` keep throwing. `runtime-missing` is NOT reapable (see NonGoals). Reap through `stopAgent`, never `killSession`.
- **D7. `pan pause` decides `shouldStop` from `agentPaneExists`**, because the residue this issue leaves has `state.status === 'stopped'` with a live pane, so the current `sessionExistsSync || status running/starting` rule leaves the pane alive. `pan kill` is NOT changed (its `sessionExistsSync` only gates a `!state && !isRunning` skip, and every Overdeck-spawned agent has `state.json`; touching it drags five test files).
- **D8. `stopSequencerRun` (`sequencer-agent.ts:89-97`) collapses to one `stopAgent` call.** Its own `closeAgentPane` + settle loop becomes redundant duplication created by this change; leaving it would teach the next reader to copy the pattern.
- **D9. Cost stated honestly:** `emergencyBrake` runs on the dashboard event loop; it now adds up to three `spawnSync` calls per stopped agent on top of its existing `pgrep` + `sleep 0.5`. Same posture, not a new violation. It is also Herdr-blind at the `tmuxActive` census (NonGoal).

## Repo rules that intersect (restated)

- **Fake timers for every delay test** (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync`); never a real 3 s wait, never `maxForks: 1`.
- **No `execSync` in dashboard-server-reachable code.** The async door must stay socket-based (`closeAgentPane`); only the sync door may shell out, and only because it already does.
- **Async tmux primitives only** for any new tmux interaction. This change adds none.
- **Circular-deps ratchet** (`scripts/lint-circular-deps.sh`): no new cycle in `src/`. See D2.
- **Skills ↔ CLI lockstep:** no `pan` flag or help string changes here, so no `skills/` edits.
- **Conventional commits**, `npm run typecheck && npm run lint && npm test` before `pan done`.
- **Never `git stash`; never `git checkout` in the workspace.**

## Requirements

- **FR-1.** After `stopAgent(id)` resolves on a Herdr host, `agentPaneExists(id)` returns `false` (the pane is closed and Herdr's record has dropped or the 3 s settle bound elapsed).
- **FR-2.** After `stopAgentSync(id)` returns on a Herdr host, the same holds — through the `herdr` CLI.
- **FR-3.** A Herdr close failure (socket down, binary missing, pane already gone) never prevents the stop door from marking `state.json` / `runtime.json` `stopped`.
- **FR-4.** `spawnRun` reaps an existing pane whose `isAlive` verdict is `pane-dead` or `no-session` through `stopAgent` and proceeds to launch; `alive` and `runtime-indeterminate` still throw `Role run <id> already running`.
- **FR-5.** `pan pause <id>` stops an agent whose pane exists on the host backend even when `state.status` is already `stopped`.
- **FR-6.** `closeAgentPane` returns only after Herdr stops reporting the agent, or after 3000 ms, whichever is first; it polls every 200 ms.
- **FR-7.** `stopSequencerRun` performs exactly one `stopAgent` call and no direct `closeAgentPane`.
- **NFR-1.** Every subprocess the sync close spawns has `timeout: 3000`.
- **NFR-2.** No new import cycle in `src/` (`scripts/lint-circular-deps.sh` passes without baseline changes).
- **NFR-3.** All delay behaviour is unit-tested under fake timers; no test sleeps for real.
- **NFR-4.** `docs/TERMINAL-BACKENDS.md` and `docs/ROLES.md` describe stop/reap as backend-aware in the sentences named in item 8.

### 3. `stopAgentSync` closes the Herdr pane through the CLI (FR-2, FR-3, NFR-1, NFR-2)

**New file:** `src/lib/terminal-backends/herdr-cli-sync.ts` (leaf: imports only `spawnSync` from `node:child_process`, `existsSync` from `node:fs`, and `HERDR_BINARY`, `herdrSessionName`, `herdrSocketPath` from `./select.js`).

```ts
export const HERDR_CLI_TIMEOUT_MS = 3_000;
const SETTLE_MS = 3_000;
const SETTLE_POLL_MS = 200;

/** Sync sleep without a subprocess. */
function sleepSync(ms: number): void {
  Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, ms);
}

/** D3: the sync twin of the host selection — never a subprocess to decide. */
export interface HerdrSyncDeps {
  env?: NodeJS.ProcessEnv;
  /** `terminal.backend` from config.yaml; the caller reads config (D3). */
  configBackend?: string;
  socketExists?: (p: string) => boolean;
  run?: typeof spawnSync;
}
export function herdrHostSelectedSync(deps: HerdrSyncDeps = {}): boolean {
  const env = deps.env ?? process.env;
  if (env.OVERDECK_TERMINAL_BACKEND === 'tmux') return false;
  if (deps.configBackend === 'tmux') return false;
  return (deps.socketExists ?? existsSync)(herdrSocketPath());
}

type CliResult = { ok: true; json: unknown } | { ok: false; code: string | null };

function herdrCallSync(args: readonly string[], run = spawnSync): CliResult {
  const result = run(HERDR_BINARY, ['--session', herdrSessionName(), ...args], {
    encoding: 'utf-8', timeout: HERDR_CLI_TIMEOUT_MS, stdio: ['ignore', 'pipe', 'ignore'],
  });
  if (result.error) return { ok: false, code: null };
  try {
    const parsed = JSON.parse(result.stdout || '{}');
    if (parsed.error) return { ok: false, code: String(parsed.error.code ?? '') };
    return { ok: true, json: parsed.result };
  } catch { return { ok: false, code: null }; }
}

/** `agent get <id>` → pane_id, else scan `pane list` for tokens.agentId (pane-bound). */
export function findHerdrPaneIdSync(agentId: string, run = spawnSync): string | null { … }

/** Close the pane and wait (bounded) until `findHerdrPaneIdSync` answers null. Returns true when a pane was closed. */
export function closeHerdrPaneSync(agentId: string, deps: HerdrSyncDeps = {}): boolean {
  const run = deps.run ?? spawnSync;
  if (!herdrHostSelectedSync(deps)) return false;
  const paneId = findHerdrPaneIdSync(agentId, run);
  if (!paneId) return false;
  herdrCallSync(['pane', 'close', paneId], run);
  const deadline = Date.now() + SETTLE_MS;
  while (Date.now() < deadline && findHerdrPaneIdSync(agentId, run) !== null) sleepSync(SETTLE_POLL_MS);
  return true;
}
```

Parser rule (so the settle loop always terminates): a non-zero `status`, a `result.error`, an empty or unparsable stdout, or a missing `result.agent.pane_id` is a NON-HIT for `agent get` and falls through to the `pane list` token scan; a non-hit there returns `null`. `herdrCallSync` therefore returns `{ok:false}` whenever `result.status !== 0 || result.error || !stdout` before attempting `JSON.parse`. `herdr --session overdeck pane list` → `{"result":{"panes":[{"pane_id":…,"tokens":{"agentId":"agent-pan-3921",…}}]}}` (the `tokens` key is absent on unstamped panes); `herdr pane close <pane_id>` closes it. Match `tokens.agentId` case-insensitively, as `findAgentIdPane` does (`herdr.ts:216-228`).

## NonGoals

- Migrating `stopAgentSync` callers to the async door (D1); `stopAgentSync` stays and is documented as the CLI/deacon door.
- Changing `pan kill`'s `isRunning` gate (D7).
- Treating `runtime-missing` as reapable in `spawnRun`: the subtree walk can miss a host-process harness (codex app-server, ACP) and would reap a live run.
