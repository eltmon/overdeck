## 1. Glossary

Define every term before use. The executing agent may be a smaller model with no prior context.

| Term | Definition |
| --- | --- |
| **UAT** | Browser-based User Acceptance Testing run by the `test` role's UAT sub-run. Its verdict is recorded separately from the automated test gate as `review_status.uat_status` / `uat_notes`. |
| **UAT verdict** | A write of `uatStatus: 'passed' \| 'failed'` (terminal) or `'pending' \| 'testing'` (non-terminal) through the review-status write door. |
| **Write door** | `setReviewStatusSync(issueId, update)` in [`src/lib/review-status.ts`](../../src/lib/review-status.ts). The single sanctioned path for mutating a `ReviewStatus`. Every REST route, CLI command, deacon patrol, and record restore funnels through it. |
| **Read door** | `getReviewStatusSync(issueId)` in the same file. It reconciles the journal record over the SQLite cache and enriches notes back from the record (see "Note plane" below). |
| **Relay** | `relayUatFailureFeedbackPromise()` in [`src/lib/cloister/uat-failure-feedback.ts`](../../src/lib/cloister/uat-failure-feedback.ts). Writes a rework feedback file into the workspace and messages the work agent to read it. |
| **Rework feedback file** | A markdown file at `<workspace>/.pan/feedback/NNN-<specialist>-<outcome>.md`, written by `writeFeedbackFile()` in [`src/lib/cloister/feedback-writer.ts`](../../src/lib/cloister/feedback-writer.ts). `NNN` is a monotonically increasing sequence; the writer performs **no** deduplication of its own. |
| **Convergence gate** | The PAN-3151 mechanism that marks an issue `stuck` when repeated review cycles stop reducing the blocking-finding count, so rework is suppressed and a human decision is surfaced instead. Implemented in [`src/lib/cloister/review-convergence.ts`](../../src/lib/cloister/review-convergence.ts) and [`src/lib/review-status-reconcile.ts`](../../src/lib/review-status-reconcile.ts). |
| **Cycle** | One recorded failed verdict for a gate. Review records `ReviewCycleEntry { cycle, runId, atCommit, blockingCount, recordedAt }`; this PRD adds the UAT analogue. |
| **Delivery identity / anchor** | A stable string identifying "which verdict am I delivering feedback for". If the identity has not changed, the relay must not write a second feedback file or send a second message. |
| **needs-you** | A durable operator escalation created by `surfaceIssueFeedbackNeedsYou(issueId, reason, details)` in [`src/lib/cloister/feedback-target.ts`](../../src/lib/cloister/feedback-target.ts). It marks the workspace stuck and surfaces the issue on the Decisions surface. |
| **Parked orbit** | A row produced by the parked-population resolver ([`src/lib/parked/resolver.ts`](../../src/lib/parked/resolver.ts)) describing why an issue is not moving, with a `park`/`unpark` sentence pair from the `PARK_REASONS` map. |
| **Note plane** | PAN-1988 split: verdict *notes* (`reviewNotes`, `testNotes`, `uatNotes`, …) are written as `NULL` into the SQLite cache and live only in the per-issue journal record's `pipeline` block. The read door re-hydrates them via `enrichReviewNotesFromRecordSync()`. **Reading `uat_notes` straight from SQLite always yields NULL — that is by design, not the bug.** |
| **Record** | The permanent per-issue JSON at `${OVERDECK_HOME}/state/<project>/records/<issue>.json` on the `overdeck-state` branch. Its `pipeline` block is the source of truth for durable verdicts; the SQLite `review_status` row is a rebuildable cache. |
| **Stall sweeper** | The observability patrol in [`src/lib/cloister/stall-sweeper.ts`](../../src/lib/cloister/stall-sweeper.ts). It **recommends** remedies and emits `sweep.*` events; since PAN-3551 it takes no actions. |

## 3. Requirements

### Functional

- **FR-1** — A pure, unit-testable UAT convergence module exists, exporting a cycle-entry type, a
  verdict-anchor function, a cycle cap constant, and `evaluateUatConvergence()`.
- **FR-2** — `review_status` persists a UAT cycle series and the last-delivered UAT feedback
  anchor, in columns created by a schema migration that also normalizes pre-existing rows.
- **FR-3** — The relay deduplicates on the persisted anchor, not a process-local `Map`, so a
  dashboard restart or a record-driven verdict restore cannot produce a second feedback file for a
  verdict already delivered.
- **FR-4** — The relay's live agent message carries a `dedupKey` so the delivery door's
  crash-independent keyed dedup also suppresses a duplicate injection.
- **FR-5** — Each newly-anchored failed UAT verdict appends one cycle entry to the series.
- **FR-6** — When the series reaches the cap, the issue is marked `stuck` with
  `stuckReason: 'uat-not-converging'` and `stuckDetails` carrying the cycle series.
- **FR-7** — While `stuckReason === 'uat-not-converging'`, the relay surfaces a needs-you
  escalation instead of messaging the work agent.
- **FR-8** — The write door rejects a `uatStatus: 'failed'` write when neither the update nor the
  enriched existing status carries non-blank `uatNotes`.
- **FR-9** — Each caller-facing entry point converts that rejection into its own idiom: HTTP 400
  for the REST routes, a non-zero-exit error for the CLI, and a skip-plus-nudge for the deacon
  recovery patrol (a patrol must never crash on one bad issue).
- **FR-10** — `uatCycleHistory` and `uatFeedbackAnchor` are mirrored into the per-issue record and
  restored from it, so a SQLite cache rebuild cannot resurrect an already-delivered verdict.
- **FR-11** — A non-failed UAT verdict write, and unsticking a `uat-not-converging` gate, both
  clear the anchor and the cycle series.
- **FR-12** — The parked resolver names `uat-not-converging` with park/unpark guidance, and
  `pan show` prints the UAT cycle series.

### Non-functional

- **NFR-1** — No `execSync` anywhere on a dashboard-reachable path; async exec/spawn only.
- **NFR-2** — All new state reads and writes go through the existing read door
  (`getReviewStatusSync`) and write door (`setReviewStatusSync` / the review-status DB module). No
  new direct SQLite, record-file, or `state.json` access.
- **NFR-3** — `npm run typecheck`, `npm run lint`, and `npm test` all pass with no new failures.
  Note that `npm run typecheck` **excludes every `*.test.ts` file** — only `npm test` gives real
  signal on test code.
- **NFR-4** — The migration is idempotent and safe to run against a database already carrying the
  columns, matching the `tryIdempotentDdl` pattern already in `schema.ts`.

## 4. Decisions made in this document

`--auto` planning mode. Every question that would normally be asked is decided here and mirrored
into `plan.autoDecisions[]`.

### D1 — Anchor formula

`uatVerdictAnchor({ issueId, headAnchor, notes })` returns
`sha256(issueId.toUpperCase() + ' ' + headAnchor + ' ' + notes.trim()).slice(0, 32)`,
where `headAnchor = reviewedAtCommit ?? prHeadSha ?? 'no-head'`.

*Rationale:* including the notes means a re-verdict at the **same** commit but with **new**
evidence relays exactly once more — which is correct, because the agent is being told something it
has not been told before. Unbounded re-relay is prevented by the cycle cap (D2), not by the anchor.
Excluding notes would be equally defensible but would silently swallow a genuinely new failure
report at an unchanged commit.

### D2 — Convergence rule

`UAT_CONVERGENCE_MAX_CYCLES = 3`. `evaluateUatConvergence(entries)` returns `'not-converging'`
when `entries.length >= UAT_CONVERGENCE_MAX_CYCLES`, otherwise `'converging'`.

*Rationale:* UAT produces no countable finding series — there is no analogue of review's blocking-
finding count, so review's reversal/stall arithmetic does not transfer. Because the anchor dedup
(D1/FR-3) means a repeated write of an unchanged verdict never appends a cycle, every entry in the
series is by construction a **distinct** verdict. Three distinct failed UAT verdicts without a pass
is a loop a human should look at. This is deliberately simpler than
`evaluateReviewConvergence()` — do not port that function's reversal/stall logic.

### D3 — Cycle recording and gate evaluation live at the write door, not in journal reconcile

Review records cycles inside `reconcileJournalIntoCacheSync()`
([`src/lib/review-status-reconcile.ts:126`](../../src/lib/review-status-reconcile.ts)) because a
sandboxed reviewer's verdict arrives through the journal. UAT verdicts do not: the reconcile hooks
(`ReviewStatusReconcileHooks`, same file lines 27-33) carry no UAT delivery at all — the only UAT
delivery site is `setReviewStatusSync` at
[`src/lib/review-status.ts:519`](../../src/lib/review-status.ts).

Therefore: `deliverUatFailureToWorkAgentHostSide()`
([`src/lib/review-status.ts:706`](../../src/lib/review-status.ts)) records the cycle, evaluates
convergence, and marks stuck; the relay then reads `stuckReason` and chooses needs-you over an
agent message. **Do not add UAT logic to `review-status-reconcile.ts`.**

### D4 — Reset points

The anchor and the cycle series are cleared at exactly three places:

1. Any write of a non-`failed` `uatStatus` — extend the existing `else if (update.uatStatus)` clear
   at [`src/lib/review-status.ts:521-523`](../../src/lib/review-status.ts).
2. `clearReviewStatus()` at [`src/lib/review-status.ts:896-905`](../../src/lib/review-status.ts) —
   already calls the clear helper; it now clears durable fields too.
3. Unstick of a `uat-not-converging` gate (D5).

`resetPipelineVerdictsForWorkStartSync()`
([`src/lib/review-status.ts:659`](../../src/lib/review-status.ts)) is **left unchanged**: it
touches neither `uatStatus` nor `uatNotes` today, so adding UAT-only field clears there would be a
behavior change outside this issue's scope. Recorded as a NonGoal.

### D5 — Unstick semantics for `uat-not-converging`

Follow the PAN-3151 precedent exactly. `handleUnstick` in
[`src/dashboard/server/routes/workspaces/review-control.ts:282-299`](../../src/dashboard/server/routes/workspaces/review-control.ts)
already resets `reviewStatus`/`testStatus`/`mergeStatus` to `pending` for every gate and
additionally clears `reviewCycleHistory` when `stuckReason === 'review-not-converging'`. Add the
symmetric clause: when `stuckReason === 'uat-not-converging'`, also clear `uatStatus`, `uatNotes`,
`uatCycleHistory`, and `uatFeedbackAnchor`.

*Rationale:* a scoped reset that preserved a green review would be cheaper, but it would make two
convergence gates behave differently on the same button, and the whole-lifecycle reset is the
documented contract operators already have. Consistency wins. `pan unstick` needs no change — the
CLI at [`src/cli/commands/unstick.ts:21`](../../src/cli/commands/unstick.ts) is a thin HTTP client
over this same route.

### D6 — Empty-notes rejection shape

The write door throws a typed `UatVerdictMissingNotesError`. Callers translate:

| Entry point | Behavior |
| --- | --- |
| `POST /api/workspaces/:issueId/review-status` | HTTP 400 with a message naming `uatNotes` as required |
| legacy specialist route | HTTP 400, same message |
| `pan admin specialists done test … --uat-status failed` | printed error, `process.exitCode = 1`, no write attempted |
| deacon unsignaled-verdict recovery | skip the UAT fields, log a warning, and nudge the test agent for evidence — never let one issue throw out of a patrol loop |

The `'No UAT notes were provided.'` fallback at
[`src/lib/cloister/uat-failure-feedback.ts:73`](../../src/lib/cloister/uat-failure-feedback.ts) is
**deleted**: with FR-8 in force it is unreachable for any verdict that passed the write door, and
leaving it would keep the contradiction alive.

### D7 — Legacy-row backfill

The migration must not leave rows that the new write door would throw on. Migration v65 backfills
every row where `uat_status = 'failed'` and the cached notes are NULL/blank with the explicit
marker text
`Legacy UAT failure recorded before PAN-3580; no evidence was captured. Re-run UAT to obtain actionable notes.`

*Rationale:* `restoreReviewStatusFromRecords()` re-writes historical verdicts through the write
door; without the backfill, a rebuild would throw on any pre-PAN-3580 notesless failure. The marker
is explicitly labelled legacy so nobody mistakes it for real evidence — unlike the deleted
`'No UAT notes were provided.'` string, which masqueraded as the failing-criteria section.

### D8 — Restore asymmetry with `reviewCycleHistory`

`reviewCycleHistory` is mirrored **into** the record (`projectPipeline()` at
[`src/lib/pan-dir/records.ts:144`](../../src/lib/pan-dir/records.ts)) but is **not** restored by
`pipelineToDurableUpdate()` at
[`src/lib/pan-dir/verdict-restore.ts:50-82`](../../src/lib/pan-dir/verdict-restore.ts). This PRD
mirrors **and** restores the two new UAT fields, because surviving a cache rebuild is the whole
point of FR-10. Bringing `reviewCycleHistory` to parity is deliberately out of scope (NonGoal).

### WI-1 — Pure UAT convergence module (FR-1)

**Files:** `src/lib/cloister/uat-convergence.ts` (new),
`tests/unit/lib/cloister/uat-convergence.test.ts` (new).

Create the module in the style of its review sibling

```ts
/**
 * UAT convergence detection and cycle tracking (PAN-3580).
 *
 * UAT produces no countable finding series, so convergence is a plain cap on
 * distinct failed verdicts rather than review's reversal/stall arithmetic.
 */
import { createHash } from 'node:crypto';

export interface UatCycleEntry {
  cycle: number;
  anchor: string;
  atCommit?: string;
  recordedAt: string;
}

/** Distinct failed UAT verdicts tolerated before the gate engages. */
export const UAT_CONVERGENCE_MAX_CYCLES = 3;

/** Stable identity for one UAT verdict — see PRD decision D1. */
export function uatVerdictAnchor(input: {
  issueId: string;
  headAnchor?: string;
  notes?: string;
}): string {
  const head = input.headAnchor?.trim() || 'no-head';
  const notes = input.notes?.trim() ?? '';
  return createHash('sha256')
    .update(`${input.issueId.toUpperCase()} ${head} ${notes}`)
    .digest('hex')
    .slice(0, 32);
}

export function evaluateUatConvergence(
  entries: readonly UatCycleEntry[],
): 'converging' | 'not-converging' {
  return entries.length >= UAT_CONVERGENCE_MAX_CYCLES ? 'not-converging' : 'converging';
}
```

**Tests:** anchor stability for identical inputs; anchor divergence when the head anchor changes;
anchor divergence when the notes change; `'converging'` at 0/1/2 entries; `'not-converging'` at 3
and above.

## 8. Repo rules that intersect this work

Restated so the executing agent does not have to recall them:

- **Async only on server-reachable paths.** Never `execSync`; use `execAsync` or `spawn`. Never
  `sendKeys`; use `sendKeysAsync`.
- **Fake timers for any delay-based test.** If a test exercises retry, backoff, or a timed patrol,
  use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`. Never real `setTimeout` delays.
- **`npm run typecheck` excludes every `*.test.ts`.** A green typecheck says nothing about test
  code; run `npm test`.
- **Two doors.** Extend `getReviewStatusSync` / `setReviewStatusSync` and the review-status DB
  module. Do not add a new direct SQLite, record-file, or `state.json` access path.
- **Per-item durability.** Commit exactly one xBRIEF item at a time and push the feature branch
  before running `pan task done`.
- **Worktree discipline.** Verify `git branch --show-current` is `feature/pan-3580` before the
  first edit; never `git checkout` inside the workspace; never `git stash`.
- **Effect bridging.** When a callee returns an `Effect`, yield it directly; reserve
  `Effect.tryPromise` for Promise-returning thunks.
- **Root cause, no bandaids.** If something outside this plan is broken, investigate the cause and
  say so — do not add defensive code downstream to tolerate bad data.
