# PAN-2364 — Per-slot failure isolation: `failedMergeBlock` keyed by slot, not per-issue

**Issue:** [PAN-2364](https://github.com/eltmon/overdeck/issues/2364)

## Glossary

- **`failedMergeBlock`** — a record that a specific slot failed to merge cleanly (merge conflict or verification failure). Currently stored as a single value per issue: `PanIssueSwarmRecord.failedMergeBlock?: PanIssueSwarmFailedMergeBlock` (record.ts:80) and in-memory as `failedMergeBlocks: Map<string, FailedMergeBlock>` keyed by `issueId.toUpperCase()` (deacon-swarm.ts:75).
- **`PanIssueSwarmFailedMergeBlock`** — the block struct (record.ts:62–67): `{ issueId, itemId, slotIndex, branch?, note }`. Already carries `slotIndex` — but only one block per issue is stored.
- **Per-issue coordinator guard** — the early `if (failedMergeBlock) { ... continue; }` in `coordinateSwarmSlots` (deacon-swarm.ts:275–277): when ANY slot block exists, ALL further swarm coordination for the issue is skipped on every patrol. This is the root cause of the isolation failure.
- **`pan swarm recover <issue> <slot>`** — calls `swarmRecoverCommand` in `swarm.ts:155`; currently fails if `block.slotIndex !== slotIndex` (line 184–185), meaning only the one recorded slot can be recovered.
- **`pan swarm status`** — `swarmStatusCommand` in `swarm.ts:544`; currently does not display the failed-merge block at all.
- **In-memory map** — `failedMergeBlocks` at deacon-swarm.ts:75: `Map<string, FailedMergeBlock>` keyed by `issueId.toUpperCase()`. One entry per issue.
- **Durable record** — `workspacePath/.pan/records/<issueId>.json` → `swarm.failedMergeBlock`; written by `writeSwarmFailedMergeBlock` (deacon-swarm.ts:666).

## Problem (verified 2026-07-04 against main @ `6681632b`)

In `coordinateSwarmSlots` (deacon-swarm.ts:275–277):

```ts
const failedMergeBlock = getFailedMergeBlock(issueId, workspace.workspacePath);
if (failedMergeBlock) {
  actions.push(`[swarm] blocked ${issueId}: failed-merge slot ${failedMergeBlock.slotIndex} (item ${failedMergeBlock.itemId})`);
  continue;
}
```

When slot 1 fails to merge for issue PAN-2253, the coordinator skips ALL coordination for PAN-2253: slots 2, 3, 4, and 5 cannot be merged, dispatched, GC'd, or finalized, regardless of their own state. The entire swarm parallelism collapses to a manual recovery queue.

`pan swarm recover PAN-2253 2` would currently fail with `Recorded failed-merge slot for PAN-2253 is slot 1, not slot 2` (swarm.ts:185), so other healthy slots cannot be individually recovered either.

The `PanIssueSwarmFailedMergeBlock` struct already has a `slotIndex` field. The data is there; the storage and guard are not per-slot.

---

## Requirements

- **FR-1** — The in-memory store and durable record MUST support multiple failed-merge blocks per issue, one per `slotIndex`. A block for slot 1 MUST NOT prevent merging, dispatching, or GC of slots 2–N.
- **FR-2** — `coordinateSwarmSlots` MUST skip only the failed slot's item during merge dispatch; all other slots continue normally. The per-issue `continue;` guard MUST be removed.
- **FR-3** — `pan swarm recover <issue> <slotIndex>` MUST succeed as long as a block for the given `slotIndex` exists, regardless of other slots' blocks. Multiple slots may be recovered independently.
- **FR-4** — `pan swarm status` MUST list ALL failed-merge blocks (all blocked slots), not just one.
- **FR-5** — Migration: existing durable records with the old `swarm.failedMergeBlock` (singular) field MUST be read as a single-element `failedMergeBlocks` array. No data loss on upgrade.
- **NFR-1** — No new explicit `any`; async only; no `execSync`; no new files ≥ 1,000 lines.

```ts
export function getFailedMergeBlock(
  issueId: string,
  workspacePath?: string,
  slotIndex?: number,
): FailedMergeBlock | undefined {
  const normalized = issueId.toUpperCase();
  if (workspacePath) {
    const record = readIssueRecordForWorkspaceSync(workspacePath, normalized)?.swarm;
    // PAN-2364: prefer failedMergeBlocks array; fall back to legacy failedMergeBlock.
    const durable: FailedMergeBlock[] = record?.failedMergeBlocks ?? (record?.failedMergeBlock ? [record.failedMergeBlock] : []);
    if (slotIndex !== undefined) {
      const found = durable.find(b => b.slotIndex === slotIndex);
      if (found) return { ...found, issueId: found.issueId.toUpperCase() };
    } else if (durable.length > 0) {
      return { ...durable[0], issueId: durable[0].issueId.toUpperCase() };
    }
  }
  const slotMap = failedMergeBlocksBySlot.get(normalized);
  if (!slotMap) return undefined;
  if (slotIndex !== undefined) return slotMap.get(slotIndex);
  return slotMap.values().next().value; // first block (arbitrary order)
}

/** Return all failed-merge blocks for an issue (in-memory + durable merged). */
export function getAllFailedMergeBlocks(issueId: string, workspacePath?: string): FailedMergeBlock[] {
  const normalized = issueId.toUpperCase();
  const inMemory = [...(failedMergeBlocksBySlot.get(normalized)?.values() ?? [])];
  if (!workspacePath) return inMemory;
  const record = readIssueRecordForWorkspaceSync(workspacePath, normalized)?.swarm;
  const durable: FailedMergeBlock[] = record?.failedMergeBlocks ?? (record?.failedMergeBlock ? [record.failedMergeBlock] : []);
  // Merge: in-memory takes precedence for same slotIndex (it's the live state).
  const bySlot = new Map<number, FailedMergeBlock>(durable.map(b => [b.slotIndex, b]));
  for (const b of inMemory) bySlot.set(b.slotIndex, b);
  return [...bySlot.values()];
}
```

export function clearFailedMergeBlock(issueId: string, workspacePath?: string, slotIndex?: number): void {

## Migration note

Existing records in `<workspace>/.pan/records/<issueId>.json` with `swarm.failedMergeBlock` (singular) will be read as `[failedMergeBlock]` by `getAllFailedMergeBlocks` and `getFailedMergeBlock`. On the first `recordFailedMergeBlock` or `clearFailedMergeBlock` call for the issue, `writeSwarmFailedMergeBlocks` clears the legacy `failedMergeBlock` field and writes the array-form `failedMergeBlocks`. Migration is automatic on first write; no batch migration script needed.
