## Problem (verified at `9fd6cdd62db`)

**P1. Fresh installs show Advanced from the second load on.** `initialMode()` (`uiMode.ts:18-29`) returns `simple` only when neither `overdeck:ui-mode` nor `overdeck:last-tab` is set, and never saves what it resolved. `App.tsx:435-442` writes `last-tab` on every load, so load 2 finds `last-tab`, finds no `ui-mode`, and returns `advanced`. The `catch` branch and SSR also return `advanced`. Simple Home's own composer triggers load 2: `TalkItThrough.tsx:88` does `window.location.assign('/conv/…')`.

**P2. Neither Home can start anything without a project.** The server can: `handleConversationCreate` (`src/lib/overdeck/conversation-runtime.ts`) starts from `getDefaultCwd()` and resolves a project only when `projectKey` is given; `POST /api/terminals` resolves a missing cwd to `getDefaultCwd()` (`terminals.ts:43-52`). But:
- Simple Home's `TalkItThrough` wraps the text in a discuss-then-file prompt (`seedDiscussPrompt`, `TalkItThrough.tsx:39-51`), cannot open a terminal, and hides its project picker when there are no projects (`TalkItThrough.tsx:109`).
- Advanced Home has no composer (`HomePage.tsx:141-152`).
- The Command Deck with no selection shows "Select a project to open its deck" (`CommandDeck/index.tsx:1549-1556`).
- The sidebar's No-project row renders only when an unscoped conversation already exists (`{hasUnscopedConversations && (`, `Sidebar.tsx:714`; computed at `:241-244`).

**P3. The Launcher's "Run in terminal:" row opens a dead pane.** `ProjectHome.tsx:120`: `openTerminal: () => api.openTypedPane('terminal')`. A `terminal` pane with no `terminalId` renders "No terminal session attached." (`Stage/panes/TerminalPane.tsx`), and Stage closes every `terminal` pane on load ("Terminals are drawer-only now.", `Stage/index.tsx:198-201`). The typed query is discarded.

**P5 (Slice A part). No way to attach an unscoped conversation to a project from the conversation itself.** The move exists (`PATCH /api/conversations/:name/move`, called only by `moveConversation` in `components/CommandDeck/useConversationMutations.ts:35-44`), but it is buried in the tab/row ⋮ menu (`ConversationActionMenu.tsx:177-215`, `ConversationRow.tsx:683`).

## Decisions

- **D1 — Save the resolved mode on first load.** `initialMode()` writes what it resolves to `overdeck:ui-mode`. Fresh storage → `simple`, saved. `last-tab` present without `ui-mode` → `advanced`, saved (FR-2 unchanged for existing users). Blocked storage and SSR → `simple` (unsaved). This works because `uiMode.ts` is imported by `App.tsx` (and `HomeSwitch.tsx`), so the store initializes at module import, before App's first `last-tab` effect runs.
- **D2 — The Home composer is the existing Launcher, not a new input.** Home intents, in order:
  1. `agent` for the composer's current harness. `id` = the harness id (e.g. `claude-code`), `agentName` = its display label, `keys: '↵'`. When the harness is still unresolved (ModelPicker not loaded), `id: 'agent'` and no `agentName`, so the row reads "Ask agent:" and the request omits `harness` (server routes by provider, the same as `TalkItThrough` today).
  2. `terminal`, `keys: '⌃↵'`.
  3. `codex` agent row, `keys: '⌘⇧↵'`, shown only when `codexAvailable` is true **and** the first row's harness is not already `codex`.
  4. Simple mode only: `talk`, row "Talk it through first:", no keys.
  The `web` intent is not offered on Home (Home has no browser pane).
- **D2a — `codexAvailable` source.** The prerequisites query: `report.checks.find((c) => c.id === 'codex')?.found === true`. Use `queryKey: ['prerequisites']` with `staleTime: 5 * 60_000` so it shares the cache with `SetupChecklistBanner`. A failed query means `false`.
- **D2b — Harness display labels.** `homeComposerIntents.ts` exports `HOME_AGENT_LABELS: Record<Harness, string>` with the same values as `HARNESS_LABELS` in `components/Settings/sections/ProviderManagementSection.tsx:50-58` (`'claude-code': 'Claude Code'`, `ohmypi: 'oh-my-pi'`, `codex: 'Codex'`, `acp: 'ACP'`, `opencode: 'OpenCode'`, `'kimi-code': 'Kimi Code'`, `muse: 'Muse Code'`). Do not refactor the Settings file.
- **D3 — Plain Enter asks the agent with your exact text.** No seed prompt. The seeded discuss-then-file flow stays as the `talk` row (Simple only). The codex row sends `harness: 'codex'` with the composer's current model, exactly as the deck's `createDeckConversation` does today (`CommandDeck/index.tsx:1181-1187`).
- **D4 — Project chip.** Initial selection, first match wins: (1) `localStorage['overdeck:talk-project']` if it names a registered project key (the key `TalkItThrough.tsx:20` already uses); (2) the first registered project; (3) no project. The chip is a button that opens a small menu: each registered project (label `name ?? key`), the no-project choice, and "Add a project…". Copy: Advanced "In: <name>" / "In: No project (home folder)"; Simple "In: <name>" / "Not in a project". Simple strings live in `SIMPLE_STRINGS.home` (WI-8). A successful send saves the chosen key to `overdeck:talk-project`, or removes the key when no project was chosen.
- **D4a — "Add a project…" in this slice.** It navigates with `window.history.pushState({ tab: 'project-new' }, '', '/projects/new')` followed by `window.dispatchEvent(new PopStateEvent('popstate'))` — the same pair `ProjectHome.tsx:93-96` uses for `/costs`. The tab id `'project-new'` maps to `/projects/new` (`App/routes.ts:30`; `App.tsx:225-228` uses the same state object). No `returnTo`: `getNewProjectReturnToFromSearch` honors only `/workspaces/new` (`App/routes.ts:133-148`), and after a create the app already lands on the new project's deck. **Implementation checkpoint:** confirm in the browser that the popstate switches to the New project page. Fallback: `window.location.assign('/projects/new')`. #4281 replaces this with the modal.
- **D5 — Terminal hand-off uses sessionStorage.** Record `sessionStorage['overdeck:pending-terminal'] = JSON.stringify({ deckKey, command, at: Date.now() })`. Only one record exists at a time (a new write replaces the old). Readers ignore a record older than 30 s or for another `deckKey`. `writePendingTerminal` also dispatches `window.dispatchEvent(new CustomEvent('overdeck:pending-terminal', { detail: { deckKey } }))` so an already-mounted drawer reacts in the same tab. sessionStorage survives the Home composer's hard navigation.
- **D5a — Who opens the drawer.** The Home composer only writes the hand-off and navigates; it does not touch the terminal store. `Stage` peeks (non-consuming) the hand-off for its `deckKey` on mount and on the event, and calls `setTerminalOpen(deckKey, true)`. Inside a deck, `ProjectHome`'s row writes the hand-off and calls the new `api.openTerminalDrawer()`.
- **D5b — How the drawer consumes the hand-off without making two terminals.** `TerminalDrawer` has two consumers, and only one can run for a given hand-off because both use the consuming `takePendingTerminal`:
  - (a) The existing bootstrap effect (`TerminalDrawer.tsx:167-183`) runs only when no real terminal exists. It calls `takePendingTerminal(threadId)` and passes the result as `command` into its single `createTerminalSession(cwd, command)` call. So a fresh drawer creates exactly one shell and runs the command in it.
  - (b) A new effect runs when `hasReal` is true (at least one real terminal). It calls `takePendingTerminal(threadId)`; when that returns a command, it calls `createTerminalSession(cwd, command)` and then `newTerminal(threadId, name)` + `pokeResize()`, or `toast.error('Could not start terminal (dashboard session expired?)')` on failure. Its dependencies are `[hasReal, pendingNonce, threadId, cwd]`, where `pendingNonce` is state bumped by a `window` listener for `overdeck:pending-terminal` events whose `detail.deckKey === threadId`.
  - If the event arrives while bootstrap (a) is in flight, (b) sees `hasReal === false` and does nothing; when (a) finishes, `hasReal` flips to true, (b) re-runs, and takes any hand-off (a) did not already take. A hand-off is never lost and never runs twice.
- **D6 — `POST /api/terminals` runs an optional command.** Body `{ cwd?, command? }`. When `command` is a string: trim it; if it contains `\n` or `\r` → 400 `{ error: 'command must be a single line' }`; if longer than 2000 chars → 400 `{ error: 'command must be at most 2000 characters' }`; if empty after trim → ignore it. Validate before `createSession` so a rejected request creates no session. After `createSession`, send it with a module-local helper:
  ```ts
  /** Type one literal line into a fresh shell and press Enter (the shell reads
   * it from pty typeahead once it starts). Local on purpose: tmux.ts is at its
   * allowlisted ceiling. */
  function sendLiteralLine(sessionName: string, text: string) {
    return Effect.tryPromise({
      try: async () => {
        await tmuxExecAsync(['send-keys', '-t', exactPaneTarget(sessionName), '-l', text]);
        await tmuxExecAsync(['send-keys', '-t', exactPaneTarget(sessionName), 'Enter']);
      },
      catch: (cause) => cause,
    });
  }
  ```
  `tmuxExecAsync` is exported at `src/lib/tmux.ts:523`, `exactPaneTarget` at `:660`. If sending fails, the route still returns 200 with the session (the shell exists; the user can retype) and adds `commandSent: false`; on success `commandSent: true`. `src/lib/tmux.ts` is not edited.
- **D7 — The No-project deck is always reachable.** (a) The sidebar renders the No-project row whenever the Projects section renders. (b) When the Command Deck has no selected project, registered projects have loaded, and there are zero, it selects `NO_PROJECT_KEY` once (new hook `useDefaultDeckSelection`). (c) With projects registered and none selected, the empty state keeps "Select a project to open its deck" and adds a "Start without a project" button that selects `NO_PROJECT_KEY`.
- **D7a — `/command-deck/__no-project__` already works; no App change.** `getCommandDeckProjectRouteFromPath` (`App/routes.ts:94-100`) seeds `selectedProjectKey` (`App.tsx:172-174`); `isKnownProject` accepts `NO_PROJECT_KEY` (`UnknownProjectState.tsx:28-34`); `terminalCwd` is `selectedRegisteredProject?.path` (`CommandDeck/index.tsx:1516`), which is `undefined` for the No-project deck, so the server uses `getDefaultCwd()`. For a registered project the composer navigates with the project **key**; `findRegisteredProject` matches key or name (`UnknownProjectState.tsx:19-26`), so `deckKey` equals the key the hand-off was written with.
- **D8 — `TalkItThrough` is retired as a component.** `seedDiscussPrompt` moves to `components/home/homeComposerIntents.ts`. `components/simple/TalkItThrough.tsx` is reduced to `export { seedDiscussPrompt } from '../home/homeComposerIntents';` plus a one-line header comment, so any import keeps working. ### WI-4 — Terminal hand-off module (D5)

**Files:** new `components/home/pendingTerminal.ts`; new `components/home/__tests__/pendingTerminal.test.ts`.

API:
```ts
export const PENDING_TERMINAL_KEY = 'overdeck:pending-terminal';
export const PENDING_TERMINAL_EVENT = 'overdeck:pending-terminal';
export const PENDING_TERMINAL_MAX_AGE_MS = 30_000;
export function writePendingTerminal(entry: { deckKey: string; command: string }): void
export function peekPendingTerminal(deckKey: string): string | null   // read, never delete
export function takePendingTerminal(deckKey: string): string | null   // read, delete when it matches
```

### WI-10 — Type-to-focus hook (FR-4)

**Files:** new `components/home/useTypeToFocus.ts`; new `components/home/__tests__/useTypeToFocus.test.tsx`.

`useTypeToFocus(ref: RefObject<HTMLInputElement | null>)` adds a `document` `keydown` listener. It acts only when: `e.key.length === 1`; no `ctrlKey`/`metaKey`/`altKey`; `e.defaultPrevented` is false; `document.activeElement` is `document.body` or null; and `document.querySelector('[role="dialog"]')` is null.
