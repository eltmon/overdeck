# PAN-5359 — Per-turn memory injection for project-root conversations and Codex

**Issue:** [PAN-5359](https://github.com/eltmon/overdeck/issues/5359)
**Sibling split out:** [PAN-5366](https://github.com/eltmon/overdeck/issues/5366) — conversation-page indicator (proposal 3)
**Planning mode:** `pan plan --auto`, high effort. No operator questions were asked; every default is recorded under "Decisions".

## Glossary

- **Per-turn injection / prompt-time injection** — before a user prompt reaches the model, Overdeck calls `POST /api/memory/inject` with the prompt. The route runs `injectPromptTimeMemory` (`src/lib/memory/injection.ts`) and returns a context string. The caller puts that string in front of the prompt.
- **Global Claude hook** — `~/.overdeck/bin/user-prompt-submit-hook` (source `sync-sources/hooks/user-prompt-submit-hook`). `pan admin hooks install` and the desktop provisioner register it in the user-global `~/.claude/settings.json` (`OVERDECK_HOOK_REGISTRATIONS`, `src/lib/claude-hooks-registration.ts`, line 108). It fires for every Claude Code session on the machine, in any cwd.
- **Workspace memory hook** — `~/.overdeck/hooks/memory/overdeck-memory-hook.js`, which `injectMemoryHookSettings` (`src/lib/caveman/workspace.ts`, line 55) writes into an issue workspace's `.claude/settings.json`. The issue body refers to this hook as `prompt-inject`.
- **Memory identity** — a `MemoryIdentity` (`packages/contracts/src/memory.ts`, line 10): `{ projectId, workspaceId, issueId | null, runId, sessionId, agentRole, agentHarness }`. It selects the FTS database (`~/.overdeck/memory/<projectId>/memory-search.db`) and the workspace memory home (`~/.overdeck/memory/<projectId>/<workspaceId>/`). No identity means no injection.
- **rag-runs** — the decision log `~/.overdeck/memory/<projectId>/<workspaceId>/rag-runs/<YYYY-MM-DD>.jsonl`. `injectPromptTimeMemory` appends one `type: 'rag-decision'` line per call (`writeDecision`, `injection.ts`, line 449), whatever the outcome.
- **Main workspace row** — the singleton `workspaces` row with `kind = 'main'` for a project (`getMainWorkspace`, `src/lib/workspaces/resolver.ts`, line 207). A project-root conversation's identity comes from this row.
- **Codex app-server host** — `dist/codex-app-server-host.js`, built from `src/lib/codex/app-server-host.ts`. One host process per Codex agent or conversation (transport `app-server`, the default). It owns the `codex app-server` child, and every dashboard message, `pan tell` delivery and pane-typed line becomes a turn through `CodexAppServerHost.handleMessageOp` (line 270) → `manager.startTurn` (line 293).
- **Rollout** — Codex's JSONL transcript. `readCodexRolloutMessage` (`src/lib/codex-rollout-message.ts`, line 92) is the only reader of user and assistant text in it. The chat panel (`codex-conversation-parser.ts`), the transcript adapter, harness metadata (titles), enrichment, search indexing and the cost parser all call it.
- **Turn-context block** — new in this PRD. The exact wrapper the Codex host puts around injected memory: `<overdeck-turn-context>\n{context}\n</overdeck-turn-context>\n\n{prompt}`. The rollout reader removes it again.

## Verified current state (2026-11-15)

These findings change the issue's premise, so they come first.

1. **Claude project-root conversations already reach `/api/memory/inject`.** The issue says only the workspace memory hook calls the route. The global Claude hook also does, for every session (`sync-sources/hooks/user-prompt-submit-hook`, lines 50–60: `curl … "$PAN_DASHBOARD_URL/api/memory/inject"`). Evidence from this machine's logs:
   - overdeck root conversations: 740 `rag-decision` records in `~/.overdeck/memory/panopticon-cli/2a8c522b-…/rag-runs/`, every one `outcome: injected` (knowledge index plus sibling hits).
   - dfai root conversations: 24,981 records in `~/.overdeck/memory/dfai/3c603f9d-…/rag-runs/`, every one `expansion-failed`, with zero candidates in every source. The reason is `provider-auth-failed` in 24,813 of them. dfai has no workspace observations to find, and query expansion has no credential (the PAN-4370 concern in `.overdeck/context/codebase/concerns.md`). Writing hooks into dfai's `.claude/settings.json` would change neither number. That file is also tracked in dfai's git, so writing to it would dirty the primary checkout.
2. **Projects without a main workspace row get no injection at all.** `resolveMemoryIdentityFromConversation` (`src/dashboard/server/routes/hooks.ts`, line 763) returns null when the conversation row has no `workspace_id`. `createConversation` sets that id from `resolveWorkspaceForCwd(cwd)` (`src/lib/overdeck/conversations.ts`, lines 741–743), and that returns null when the project has no main row. On this machine 12 of 24 registered projects have no main row: auricle, eltmon-stream, eltmon-video, krux, lexerra, mind-your-now, myn-cli, orca, pan-tts, papers-please, puzzdom, tindra. Most were imported on 2026-07-29. In the last 30 days, 21 project-root Claude conversations and one Codex conversation had `workspace_id = NULL`, so they had no identity. `seedProjectsFromYaml` and `backfillIssueWorkspaces` (`src/lib/workspaces/rebuild.ts`, lines 41–76) never create main rows. Only two paths do: `finishProjectSetup` (`src/lib/projects/create-perform.ts`, lines 361–370, via `pan project finish-setup`), and `rebuildMainAndScratchWorkspaces` (`rebuild.ts`, line 97, via `pan db`). The rebuild path recreates rows only from a `metadata.json` mirror that these projects never had.
3. **Codex has no per-turn path.** `handleMessageOp` passes the operator's text to `manager.startTurn` unchanged, and nothing in `src/lib/codex/` calls `/api/memory/inject`. The Pi path (`injectPiConversationMemory`, `src/lib/agents/runtime-command.ts`, line 600) is not a usable model for root conversations. It returns early without an `issueId` and keys identity on folder names, not workspace rows.
4. **The route cannot find a Codex conversation by session id before the first turn.** `getConversationByClaudeSessionId` (`conversations.ts`, line 617) matches `conversation_files.locator`. For Codex rows that is the thread id, recorded once the thread exists. The route has no lookup by conversation name.

## Requirements

### Functional

- **FR-1** The inject route resolves a memory identity for a conversation from its main (or owning) workspace row, found either by Claude session id or by conversation name (`body.conversation`, the tmux session such as `conv-20261115-9025`).
- **FR-2** When a conversation row has no `workspace_id`, or its id names no row, identity falls back to `resolveWorkspaceForCwd(conversation.cwd)`.
- **FR-3** Dashboard boot creates a missing `kind = 'main'` workspace row for every registered, non-system project whose `primary_path` is an existing directory. The backfill never modifies or removes rows.
- **FR-4** Before each host-mediated Codex turn, the app-server host calls `POST /api/memory/inject` and prepends the returned context wrapped in the turn-context block. The route logs the call to rag-runs as for Claude.
- **FR-5** Codex injection fails open: no token, bare context, an HTTP error, a non-OK body, empty context, a timeout over 1500 ms, or context containing `</overdeck-turn-context>` all start the turn with the original text.
- **FR-6** `readCodexRolloutMessage` removes a leading turn-context block from user messages. Timeline, titles, search and enrichment then show only the operator's text.
- **FR-7** The pane line `[user] …` and the `op/message` journal event keep the original text. The event records `memoryContextChars`.
- **FR-8** Regression tests lock the Claude path for project-root conversations: the registration table holds the global UserPromptSubmit hook, and the route resolves a root-conversation identity with no agent state.

### Non-functional

- **NFR-1** `src/lib/codex/app-server-host.ts` stays at or under 1000 lines, and `src/dashboard/server/main.ts` stays at or under 1000 lines. The file-size lint checks files above 1000 lines against their `origin/main` count. Host logic goes into a new module.
- **NFR-2** No `execSync` and no sync child-process calls in any touched file. All file and HTTP I/O is async.
- **NFR-3** Timeout tests use `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()`, and the client builds its timeout from `AbortController` + `setTimeout`. Never use `AbortSignal.timeout` (happy-dom ignores fake timers for it) or real waits.
- **NFR-4** The Codex call adds at most 1500 ms before `turn/start`. Dashboard delivery posts to the host with an 8000 ms socket timeout (`src/lib/agents/delivery.ts`, around line 526), and the turn must still start inside that budget.

## Decisions (auto mode)

- **D-1 — Proposal 1 becomes an identity fix, not a hook install.** The global Claude hook already covers every Claude session (finding 1). A second hook in project `.claude/settings.json` would double the calls and dirty tracked files. The real gap is identity (findings 2 and 4). FR-1, FR-2, FR-3 and FR-8 replace proposal 1.
- **D-2 — Codex calls the route over HTTP from the host.** It does not import `injectPromptTimeMemory` into the host. The route already does identity resolution, the compliance warning, the briefing update, docs context, the 750 ms fast path and rag-runs logging. One server path keeps Claude and Codex identical.
- **D-3 — Injection sits in `handleMessageOp`.** Dashboard messages, `pan tell` and pane lines all pass through it. Turns typed in the native Codex terminal (PAN-3835 companion), `codex.transport: tui`, and sub-agent messages (`subagent-message` op) bypass it; they are NonGoals. A Codex `UserPromptSubmit` hook (the SageOx route, `src/lib/sageox/codex-hooks.ts`) was rejected: it needs per-launch trust hashes in every agent's `CODEX_HOME`, and it would share `hooks.json` with SageOx's hook writer.
- **D-4 — The context rides in the user input.** It is wrapped in one unambiguous block that one reader strips. The `turn/start` call (`app-server-manager.ts`, line 268) sends only `threadId`, `input`, `model` and `effort`. Overdeck sends no per-turn instruction field, and the replay fixtures under `src/lib/codex/__fixtures__/replay/` show none. The block starts with `<`, so without stripping the Claude-style filter `isSystemInjection` would hide the whole message. The Codex parser does not use that filter; it would show the raw block instead. Either result is wrong, so the strip in `readCodexRolloutMessage` is required.
- **D-5 — The host request carries `conversation: process.env.OVERDECK_CONVERSATION`.** The conversation launcher exports it (`src/lib/overdeck/conversation-runtime.ts`, around line 849), with `agentId: process.env.OVERDECK_AGENT_ID` and `sessionId: <owner thread id>`. Codex work agents have agent state and resolve through it. Conversations have no `state.json`, so they resolve by name.
- **D-6 — Backfill main rows at boot.** The alternatives were synthesizing a workspace id (it orphans memory homes) or asking the operator to run `pan project finish-setup` per project (they cannot see the gap). The backfill uses `createWorkspace` (`src/lib/workspaces/writer.ts`, line 85), which already refuses a second main row.
- **D-7 — The conversation-page indicator (proposal 3) moved to PAN-5366.** It needs a new route, frontend component and scope rows. With it, this plan exceeds finalize's six-subsystem limit, and the issue's acceptance list does not require it. PAN-5366 depends on the resolver from WI-1.
- **D-8 — `issueId` stays `null` for conversation identities, as today.** An issue-linked conversation keeps the cross-workspace sibling search it gets now. Changing that is out of scope.

```ts
 * Memory identity for a conversation (PAN-5359). A conversation has no agent
 * state; its identity comes from the workspace row that owns its cwd: the
 * row on `conversations.workspace_id`, else the longest-prefix match for the

 * workspaces of the same project for sibling hits.
 */

import type { LegacyConversation } from '../overdeck/conversations.js';
import { getWorkspaceById, resolveWorkspaceForCwd } from '../workspaces/resolver.js';
import type { WorkspaceRow } from '../workspaces/types.js';

export interface ConversationIdentityDeps {
  getWorkspaceById?: (id: string) => WorkspaceRow | null;
  resolveWorkspaceForCwd?: (cwd: string) => WorkspaceRow | null;
}

export function memoryIdentityForConversation(
  conversation: Pick<LegacyConversation, 'workspaceId' | 'cwd' | 'tmuxSession' | 'harness'> | null,
  sessionId: string,
  deps: ConversationIdentityDeps = {},
): MemoryIdentity | null {
  if (!conversation) return null;

  return {
    projectId: workspace.projectId,
    workspaceId: workspace.id,
    issueId: null,
    runId: conversation.tmuxSession,
    sessionId,
    agentRole: 'conversation',
    agentHarness: conversation.harness ?? 'claude-code',
  };
}
```

```ts
/** PAN-5359: the Codex host's per-turn memory wrapper; this reader strips it. */
export const CODEX_TURN_CONTEXT_OPEN = '<overdeck-turn-context>';
export const CODEX_TURN_CONTEXT_CLOSE = '</overdeck-turn-context>';

/** Wrap `context` in front of `prompt`; null when the context cannot be wrapped safely. */
export function wrapCodexTurnContext(context: string, prompt: string): string | null {
  if (!context.trim() || context.includes(CODEX_TURN_CONTEXT_CLOSE)) return null;
  return `${CODEX_TURN_CONTEXT_OPEN}\n${context}\n${CODEX_TURN_CONTEXT_CLOSE}\n\n${prompt}`;
}

/** Remove one leading turn-context block; any other text is returned unchanged. */
export function stripCodexTurnContext(text: string): string {
  if (!text.startsWith(CODEX_TURN_CONTEXT_OPEN)) return text;
  const end = text.indexOf(CODEX_TURN_CONTEXT_CLOSE);
  if (end === -1) return text;
  return text.slice(end + CODEX_TURN_CONTEXT_CLOSE.length).replace(/^\n+/, '');
}
```

1. Create `src/lib/codex/prompt-memory.ts`:

```ts
/**
 * Per-turn memory for Codex app-server turns (PAN-5359). The host asks the
 * dashboard's `/api/memory/inject` (the same route the Claude hooks call, so
 * identity, briefing, docs and rag-runs logging are shared) and wraps the
 * answer in front of the prompt. Fails open: any miss returns the prompt.
 */
import { getDashboardLoopbackApiUrl } from '../config.js';
import { getInternalToken, INTERNAL_TOKEN_HEADER } from '../internal-token.js';
import { wrapCodexTurnContext } from '../codex-rollout-message.js';

export const CODEX_PROMPT_MEMORY_TIMEOUT_MS = 1500;

export interface CodexPromptMemoryInput {
  prompt: string;
  agentId: string;
  sessionId: string;
  conversation?: string;
}

export interface CodexPromptMemoryDeps {
  fetchImpl?: typeof fetch;
  token?: () => string | null;
  baseUrl?: () => string;
  env?: NodeJS.ProcessEnv;
  timeoutMs?: number;
}

export interface CodexPromptMemoryResult {
  text: string;
  contextChars: number;
}

export async function applyCodexPromptMemory(
  input: CodexPromptMemoryInput,
  deps: CodexPromptMemoryDeps = {},
): Promise<CodexPromptMemoryResult> {
  const unchanged = { text: input.prompt, contextChars: 0 };
  const env = deps.env ?? process.env;
  if (!input.prompt.trim() || env.OVERDECK_BARE_CONTEXT === '1') return unchanged;
  const token = (deps.token ?? getInternalToken)();
  if (!token) return unchanged;
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), deps.timeoutMs ?? CODEX_PROMPT_MEMORY_TIMEOUT_MS);
  try {
    const baseUrl = deps.baseUrl ? deps.baseUrl() : (env.OVERDECK_DASHBOARD_URL || getDashboardLoopbackApiUrl());
    const response = await (deps.fetchImpl ?? fetch)(`${baseUrl}/api/memory/inject`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', [INTERNAL_TOKEN_HEADER]: token },
      body: JSON.stringify({
        prompt: input.prompt,
        sessionId: input.sessionId,
        agentId: input.agentId,
        ...(input.conversation ? { conversation: input.conversation } : {}),
      }),
      signal: controller.signal,
    });
    if (!response.ok) return unchanged;
    const body = await response.json().catch(() => null) as { ok?: unknown; context?: unknown } | null;
    if (body?.ok !== true || typeof body.context !== 'string') return unchanged;
    const text = wrapCodexTurnContext(body.context, input.prompt);
    return text ? { text, contextChars: body.context.length } : unchanged;
  } catch {
    return unchanged;
  } finally {
    clearTimeout(timer);
  }
}
```

Without it, fall back to `getDashboardLoopbackApiUrl()` (`src/lib/config.ts`, line 455), which ignores env and builds `http://localhost:<api_port>`. Never use `getDashboardApiUrl()`: it falls back to `DASHBOARD_URL`, which can be a stale public Traefik URL that 404s (`config.ts` comment at line 428). `config.ts` is already in the host's import graph through `cost.js`. If `npm run lint` (`lint:circular`) reports a new cycle anyway, inline the same three-line loopback computation in `prompt-memory.ts` instead. The route answers 202 on success, which `response.ok` accepts.

## Hazards

- **`getInternalToken()` caches its first result.** A host started before the dashboard ever wrote `internal-token` keeps `null` and never injects until it restarts. The dashboard launches hosts, so the file normally exists. The `[launcher]` log is the place to look if a Codex conversation never logs rag-runs.
- **The native Codex terminal shows the wrapped block** in its own scrollback for host-mediated turns, because it reads the app-server thread directly. This is accepted (NonGoal).
- **`resolveWorkspaceForCwd` does not filter archived rows.** overdeck's root conversations attach to an archived scratch row (`2a8c522b-…`, project key `panopticon-cli`). Leave it unchanged; it is recorded in `concerns.md`.
- **Two identity keyings exist.** Agent identities use folder names (`overdeck/feature-pan-5359`). Conversation identities use workspace rows (`panopticon-cli/<uuid>`). The new resolver keeps the conversation keying; do not merge them.
