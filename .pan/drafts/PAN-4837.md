## Glossary

- **App / phone app:** the native iOS and Android app this issue creates at `apps/mobile`. Bundle id `ai.overdeck.app`, display name "Overdeck".
- **Shell:** the app's own React screens in `apps/mobile/src/shell/` (sign-in, machine list, pair, settings, removed-machine, machine view). Everything that is not a dashboard screen.
- **Phone screens:** the existing PWA screens under `src/dashboard/frontend/src/components/mobile/` (`MobileApp.tsx` and its children). The shell renders `MobileApp` for the current machine.
- **Native shell mode:** the frontend code path taken when `isNativeShell()` (`src/dashboard/frontend/src/lib/nativeShell.ts:2`) is true. The app's `main.tsx` sets `globalThis.__OVERDECK_NATIVE__ = true` before any frontend module runs.
- **Capacitor:** framework that runs a web build in the platform WebView and adds native plugins. Version `^8.5.0` (resolves to 8.6.0 today; MYN pins `^8.5.0`).
- **Origin:** the WebView page origin. iOS: `capacitor://localhost`. Android: `https://localhost` (Capacitor's default `androidScheme`).
- **Directory:** `wss://connect.overdeck.ai/v1/directory`, the account's machine list and WebRTC signalling (`services/connect`). The app connects as a **client** (`hello-client`), never as a machine.
- **Account token:** the `odd_…` device token from `account.overdeck.ai`, minted by the PKCE sign-in. It authorizes the directory socket (subprotocol `overdeck.bearer.<token>`).
- **Phone token:** the `phone`-kind access token a machine mints in `POST /api/phones/exchange` (`src/dashboard/server/routes/phones.ts:63-102`). Sent as `Authorization: Bearer` inside the secure channel only.
- **Secure channel:** Noise handshake plus secret-stream over a WebRTC data channel (`@overdeck/anywhere-channel`). **Pairing mode** (`XXpsk0`, keyed by an `odp_` code) once per machine; **link mode** (`IK`, phone pins the machine key) afterwards.
- **Link key:** an X25519 key pair the app generates **per paired machine** (PAN-4835 D-2). Its public half is the phone's identity on that machine.
- **Push key:** one X25519 key pair per app install, generated natively. Its public half goes to every machine (`pushKeyHex`) and to the directory (`hello-client.publicKeyHex`). Its secret half never enters JavaScript.
- **Client id:** a lowercase UUID v4 per app install, generated natively. Used as the directory `clientId`, the account `environment_id`, and the machine `clientId`.
- **Shims:** `installChannelShims` from `@overdeck/anywhere-channel/web` (`packages/anywhere-channel/src/shims.ts:73`). They route relative `/api/…` and `/ws/…` requests to the current machine's channel.
- **Route:** `rtc://` = direct WebRTC; `rtc+turn://` = WebRTC through TURN (relay plan only). In code: `dialMachine(env, { relay: false | true })`.
- **Rig:** the Mac build machine reached by `ssh -o BatchMode=yes -i ~/.ssh/gauntlet_air eltmon@<ip>` (skill `myn-rig-release`; machine memory `mac-rig-safari-testing`: the IP is assigned by DHCP, 192.168.1.83 on 2026-10-28, not the skill's 192.168.1.116).

## Corrections to the epic (decided here)

- **C-1 Link keys are per machine and generated in JavaScript.** The epic's `ensureKeys() → { clientId, linkPublicKeyHex, linkSecretKeyHex, pushPublicKeyHex }` conflicts with PAN-4835 D-2 (fact 5). The native plugin returns only `{ clientId, pushPublicKeyHex }`. The shell generates a fresh link key pair for each pairing with a new `generateStaticKeyPair()` export of `@overdeck/anywhere-channel` and stores it with that machine's record in secure storage. The link secret key enters JavaScript in both designs, because the Noise handshake runs there.
- **C-2 `hello-client.publicKeyHex` carries the push public key.** It is the only install-level X25519 key the app has (fact 12). The contract comment and `docs/CONNECT-SERVICE.md` say so.
- **C-3 iOS key generation uses CryptoKit, Android uses lazysodium.** iOS `Curve25519.KeyAgreement.PrivateKey()` gives a raw 32-byte X25519 key that libsodium's `crypto_box_seal_open` accepts (libsodium clamps at use). Adding `swift-sodium` would need a Swift package reference in `project.pbxproj` edited on Linux; PAN-4838 adds libsodium when its Notification Service Extension needs `crypto_box_seal_open`. Android keeps the epic's `com.goterl:lazysodium-android` (minSdk 24 has no platform X25519), which PAN-4840 reuses.
- **C-4 The Android plugin is Java.** The Capacitor 8 template has no Kotlin toolchain, and MYN's app-local plugins are Java. PAN-4840 may add Kotlin for its own service.
- **C-5 iOS secrets stay in the app's default Keychain access group here.** Keychain Sharing is a PAN-4838 capability (epic W-IOS1 files list). PAN-4838 moves the push key into `$(AppIdentifierPrefix)ai.overdeck.shared` when it adds the extension. A Simulator build without signing cannot use a shared access group (`errSecMissingEntitlement`).
- **C-6 Scaffold dependencies are trimmed** to `@capacitor/core`, `cli`, `ios`, `android`, `app`, `browser`. `push-notifications` arrives with PAN-4838/PAN-4840, which use it. `status-bar`, `splash-screen` and `haptics` have no caller in this issue.
- **C-7 Machine switching reloads the page.** Selecting another machine stores its id and navigates to `/m`. A reload gives the RPC transport, the React Query cache and the Zustand stores a clean start for the new machine with no reset code in the frontend.
- **C-8 Settings has no notification or Live Activity switch yet.** Those switches have no behavior until PAN-4838/4839/4840 ship them. Settings here: signed-in account, paired machines (forget one), app version, sign out.
- **C-9 Base URLs are build-time configurable** (`VITE_OVERDECK_ACCOUNT_URL`, `VITE_OVERDECK_DIRECTORY_URL`, defaults `https://account.overdeck.ai` and `https://connect.overdeck.ai`), matching the CLI's `OVERDECK_ACCOUNT_URL` and `directory_url`, so the app can run against a staging or local stack.

## Requirements

### Functional

- **FR-1 Workspace.** `apps/mobile` is a bun workspace (`@overdeck/mobile`, private, MIT) whose `vite build` produces `apps/mobile/dist`, wrapped by a Capacitor 8 project with `appId: 'ai.overdeck.app'`, `appName: 'Overdeck'`, `webDir: 'dist'`, iOS 15.0, Android `minSdkVersion 24`/`compileSdkVersion 36`/`targetSdkVersion 36`.
- **FR-2 URL scheme.** Both platforms open the app for `ai.overdeck.app:` URLs (`/oauth/callback` and `/pair`), delivered to JavaScript as `App` `appUrlOpen` events or `App.getLaunchUrl()`.
- **FR-3 Device identity and secure storage.** A native plugin `OverdeckKeys` returns a stable client id and push public key, and stores named secrets in the iOS Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, not synchronizable) or in Android SharedPreferences encrypted with an AndroidKeyStore AES-GCM key. The push secret key never crosses the bridge.
- **FR-4 Sign in.** PKCE sign-in to overdeck.ai in the system browser (`@capacitor/browser`), callback through the scheme, code exchange through native HTTP, account token stored as a secret.
- **FR-5 Machine list.** After sign-in the app shows the directory's machines with online state, label, fingerprint and "Paired" for machines it holds a token for; paired machines first. It shows the directory state (connecting, refused with the refusal text).
- **FR-6 Pairing.** Scan the machine's QR (camera), paste the link, or open an `ai.overdeck.app:/pair#…` link; the app checks the link against the directory's entry for that machine, dials, runs a pairing-mode channel with a fresh link key, checks the descriptor, calls `/api/phones/exchange`, checks the descriptor's machine key again, and stores the machine.
- **FR-7 Routes.** Dial direct first. If that fails and the directory says `relayAllowed` and the last `relay-status` is not `stopped`, dial through TURN. Otherwise show "No direct path to <machine>. Install Tailscale on it or use the relay plan." Relay bytes are reported to the directory as `relay-usage` every 60 s and when a relayed raw channel closes.
- **FR-8 Machine view.** For the current paired machine, the app renders the phone screens (`MobileApp`) with all `/api/…` and `/ws/…` traffic going through the channel shims with the phone token, and a header control that returns to the machine list.
- **FR-9 Native shell mode in the frontend.** In native shell mode the RPC transport skips the dashboard session and CSRF; `MobileApp` skips the service worker, install prompt, notifications button and `MobilePairScreen`; controls whose routes the phone token cannot call are hidden.
- **FR-10 Removed and outdated machines.** A dial refused with `unknown-peer` shows "This phone was removed from <machine>. Pair again." with Pair again and Forget. A machine whose directory `serverVersion` is below `MIN_PAN_VERSION`, or whose descriptor lacks `capabilities.phoneApp`, or that refuses with `unsupported`, shows "Update Overdeck on <machine> to use the app (pan <MIN_PAN_VERSION> or later)."
- **FR-11 Several machines.** The app keeps every paired machine and switches between them (C-7).
- **FR-12 Sign out.** In order: `DELETE /api/phones/self` on each paired machine, best effort, 5 s each, a dropped connection counts as success; `push-unregister` and `forget-client` to the directory if online; `DELETE /v1/devices/<deviceId>` with the account token; `OverdeckKeys.reset()`; clear `localStorage`; reload.
- **FR-13 Foreground reconnect (CP-3).** When the app returns to the foreground, it restarts the directory socket (resetting its back-off), drops peer connections that are not `connected`, and resets the RPC transport, so fresh Needs-you data appears within 5 s on the same network. While the RPC connection is not live after a resume, the machine view shows an "Updating…" banner over the cached data.
- **FR-14 Request log for the scope inventory.** A build with `VITE_OVERDECK_REQUEST_LOG=1` records every routed request and every RPC request tag in `globalThis.__overdeckRequestLog`, shaped `{ http: Array<{ method: string; path: string; status: number }>, rpc: string[] }` (paths without the query string, de-duplicated; RPC tags de-duplicated). The AC-21 run saves it verbatim as `apps/mobile/request-log.json` and the WI-23 test reads it.
- **FR-15 Android debug build in CI.** A CI job builds the web bundle, runs the app's unit tests, syncs Capacitor and runs `./gradlew assembleDebug`, and uploads the debug APK.

### Non-functional

- **NFR-1 One protocol implementation.** The app uses `@overdeck/anywhere-channel/web` for every channel, dial, HTTP and WebSocket operation. It copies no protocol code.
- **NFR-2 Least privilege.** The app never sends the phone token outside a channel, never sends the account token anywhere but the account service and the directory subprotocol, and never logs either token, the link secret key or a pairing code.
- **NFR-3 Bounded native surface.** The native code in this issue is the `OverdeckKeys` plugin and its registration on each platform. No other native feature.
- **NFR-4 Fake timers.** Tests of back-off, the 60 s relay report, the 5 s sign-out timeouts and the resume path use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()` (repo rule `fake-timers-for-retry-tests`).
- **NFR-5 No god files.** Every new file stays under 400 lines; `MobileApp.tsx` and `wsTransport.ts` must not grow past their `origin/main` line counts plus the lines this PRD adds (the ratchet is derived from `origin/main` by `scripts/lint-file-size.sh`; never raise an allowlist row).
- **NFR-6 The desktop bundle is unchanged in behavior.** Every frontend change is behind `isNativeShell()`; the dashboard's own tests keep passing unchanged.
- **NFR-7 Isolated browser verification.** Any Playwright or CDP session used for verification uses its own browser instance or the emulator's own WebView, never another agent's session.

## Decisions

- **D-1 Separate Vite project in `apps/mobile` that imports frontend source by relative path** (epic W-APP1 step 2). `resolve.dedupe: ['react', 'react-dom', '@tanstack/react-query']` and identical version ranges to `src/dashboard/frontend/package.json` keep one copy of each (bun's isolated store links equal versions to the same real path). `@overdeck/contracts` is aliased to `packages/contracts/src/index.ts`. `events` and `sodium-native` are aliased as in `packages/anywhere-channel/cp1/vite.config.ts`, with `createRequire` rooted at `packages/anywhere-channel/package.json` (absolute path from the config file).
- **D-2 Tailwind** uses `apps/mobile/tailwind.config.js`, which spreads the frontend config and replaces `content` with absolute globs for `apps/mobile/index.html`, `apps/mobile/src/**/*.{ts,tsx}` and `src/dashboard/frontend/src/**/*.{ts,tsx}`. `apps/mobile/postcss.config.js` points `tailwindcss` at it. `main.tsx` imports `../../../src/dashboard/frontend/src/index.css`.
- **D-3 Boot order** in `apps/mobile/src/main.tsx`: set `__OVERDECK_NATIVE__`; import the CSS; install the shims with `currentMachine` from the session module; optionally wrap them with the request log (FR-14); then `await import('./shell/ShellApp')` and render. No frontend module evaluates before the shims are in place.
- **D-4 Tests.** `apps/mobile/vitest.config.ts` (environment `happy-dom` 20.10.6, include `src/**/__tests__/**/*.test.{ts,tsx}`, same aliases as D-1). Run with `npx vitest run --config apps/mobile/vitest.config.ts <files>` or `npm --prefix apps/mobile test`. Root `npm test` does not run them; the CI job does (FR-15).
- **D-5 Typecheck lane.** Root script `typecheck:mobile = tsc --noEmit -p apps/mobile/tsconfig.json`, appended to the root `typecheck` chain. `apps/mobile/tsconfig.json` copies the frontend's `compilerOptions` (strict, `noUnusedLocals`, `noUnusedParameters`, `jsx: react-jsx`, `moduleResolution: bundler`), adds `"types": ["vite/client"]`, paths `@overdeck/contracts → ../../packages/contracts/src/index.ts`, includes `src` plus the frontend's ambient declarations `../../src/dashboard/frontend/src/vite-env.d.ts` and `../../src/dashboard/frontend/src/types/ambient.d.ts` (frontend files that the app imports rely on them), and excludes tests like the frontend.
- **D-6 Secret names and shapes.** Plugin secrets: `account` = JSON `{ token, deviceId, label }`; `machines` = JSON array of `PairedMachine { environmentId, label, machineKeyHex, linkPublicKeyHex, linkSecretKeyHex, token, tokenId, pairedAt }`. Non-secret state in `localStorage`: `overdeck.currentMachine` (environment id) and `overdeck.pkce` (`{ state, verifier, createdAt }`, deleted after the callback or after 10 minutes).
- **D-7 Dial policy.** Direct with `timeoutMs: 8000` when relay is available, else the default 15 s. The route that worked is remembered per machine for the session; a resume (FR-13) forgets it so direct is tried again. Each dial then opens a link channel: `openSecureChannel(raw, { mode: 'link', localKey: { publicKey, secretKey } from the machine record, remoteKeyHex: machineKeyHex })`.
- **D-8 Error texts** (exact): directory not online → "Not connected to overdeck.ai."; FR-7 no path → "No direct path to <label>. ## Hazards

- **H-1 Services not deployed** (fact 2). Mitigation: WI-21 precondition and signal.
- **H-2 Duplicate React.** A second React copy breaks hooks at runtime only. Mitigation: D-1 dedupe plus equal ranges; WI-18's build plus the WI-21 run render `MobileApp`.
- **H-3 Shims installed late.** A module that captured `fetch` before the shims would bypass the channel. Mitigation: D-3 dynamic import; WI-18's `boot.test.ts` proves the order by behavior.
- **H-4 Keychain survives reinstall on iOS.** Mitigation: WI-8 step 2.
- **H-5 Uppercase UUIDs.** iOS `uuidString` is uppercase; every server validator is lowercase. Mitigation: `.lowercased()` and the WI-6 validator.
- **H-6 Workflow push.** `gh` cannot push `.github/workflows/`. Mitigation: SSH push (WI-25).
- **H-7 `bun.lock`.** CI runs `--frozen-lockfile`. Mitigation: WI-1 commits the lockfile; any later dependency (WI-22 fallback) commits it too.
- **H-8 Self-revoke drops the channel** (PAN-4835 H-3). Mitigation: WI-19 treats it as success.
- **H-10 Symlinked Swift packages.** `Package.swift` points at `apps/mobile/node_modules/@capacitor/*`, which bun links into its store. Mitigation: WI-8 copies them with `rsync -aL`.
- **H-11 iOS sign-in prompt.** `@capacitor/browser` uses `SFSafariViewController`, which asks "Open in Overdeck?" before following the `ai.overdeck.app:` redirect. Accepted here; `ASWebAuthenticationSession` is a release-polish follow-up for PAN-4841.
- **H-12 Tailscale stop.** `tailscale down` cuts the operator's tailnet access to this host. Mitigation: WI-21 announces it, keeps the window short and restores it.
- **H-9 The `/m` path on reload.** Capacitor serves `index.html` for extension-less paths on both platforms; WI-21 confirms a reload at `/m?tab=conversations` lands in the machine view.
