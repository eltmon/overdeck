# PAN-5011 — Idle Herdr work agents show as ended and their composer is locked

**Issue:** [PAN-5011](https://github.com/eltmon/overdeck/issues/5011)
**Status:** planned (auto mode, 2026-11-04)

## Glossary

- **Herdr** — the default terminal backend (`src/lib/terminal-backends/herdr.ts`). It owns agent panes and reports a per-pane agent state.
- **Pane state** — `BackendPane['state']` in `packages/contracts/src/backend-pane.ts`: `idle | working | blocked | done | exited | unknown`.
  - `done` is Herdr's "turn finished; pane and harness still alive, sitting at the prompt". It is **not** an exit.
  - `exited` is a dead pane.
  - `unknown` is a live pane whose agent Herdr does not detect (every harness launched through a host process — pi, codex, … — reports `unknown` for its whole life, see the header of `herdr.ts`).
- **Presence** — `SessionNodePresence` in `packages/contracts/src/types.ts:619`: `active | idle | suspended | ended`. It is the field on a `SessionNode` (a row in the Command Deck rail tree or the issue cockpit tree) that the frontend uses to decide whether the session is alive.
- **Session tree** — the server-built list of `SessionNode`s per issue: `GET /api/session-trees` (`src/dashboard/server/routes/projects.ts`, `collectSessionTreeNodes`) feeds the Command Deck rail tree and its agent tabs; `GET /api/issues/:id/activity` (`src/dashboard/server/routes/command-deck.ts`, `fetchActivityDataWithContext`) feeds the cockpit's transcript-derived sections.
- **Cockpit tree** — `src/dashboard/frontend/src/components/Stage/cockpit/IssueTreeLane.tsx`, which builds rows directly from the browser's backend pane inventory (`useBackendPanes`).
- **Composer lock** — `ComposerFooter.tsx:182` `const isDisabled = !conversation.sessionAlive || sending;`. `SessionPanel.tsx:294` sets `sessionAlive: session.presence !== 'ended'`. So any row whose presence is `ended` gets a disabled composer.

## Problem

The operator cannot type to an idle Herdr work agent. Example from the issue: the Work · PAN-4841 tab, where Herdr reports the agent `done` (idle at its prompt, waiting for the operator).

### Verified root cause (differs from the issue body)

Live evidence, 2026-11-04 11:2x UTC on this host:

- `herdr --session overdeck agent list` reported `agent-pan-4841` with `agent_status: "working"`.
- `curl -s 'http://localhost:3011/api/session-trees?projects=overdeck'` reported the PAN-4841 work node as `status: running, presence: ended`. Every other Herdr work node (PAN-4638, 4840, 4885, 4950, 4956, 4960, 4998, 4999) was also `presence: ended`, whatever its Herdr state.

So the work row is `ended` for **every** Herdr work agent, not only `done` ones. The cause:

1. **Work/planning/strike/knowledge rows use a tmux-only liveness check.** `src/dashboard/server/routes/projects.ts:256` (`const presence = await deriveSessionPresence(checkId, rtState, context.tmuxSessionNames);`) and `src/dashboard/server/routes/command-deck.ts:331` (same call). `tmuxSessionNames` comes from `listSessionNames()` (`src/lib/tmux.ts:852`, runs `tmux list-sessions`). On a Herdr host that set never contains Herdr panes, and `deriveSessionPresence` (`src/dashboard/server/services/session-presence.ts:16`, `if (!hasTmux) return 'ended';`) returns `ended` on its first line. This is the Command Deck rail tree → agent tab → `SessionPanel` → locked composer path the operator hit.

2. **Pane state `done` is mapped to `ended` in three pane-based mappings**, as the issue says, plus one mapping that maps it to the wrong live value:
   - `src/dashboard/server/routes/command-deck.ts:440` — `nodeStatusFor`: `case 'done': return { status: verdict ?? 'completed', presence: 'ended' };` (review/test/ship rows of the activity route; lines 462, 514).
   - `src/dashboard/frontend/src/components/Stage/cockpit/IssueTreeLane.tsx:37` — `paneStatus`: `case 'done': return { status: 'stopped', presence: 'ended' }` (cockpit tree; this one also maps `unknown` to `ended`, so a live pi/codex work pane is locked too).
   - `src/dashboard/server/routes/session-tree-specialists.ts:97-99` and `:158` — `reviewPane?.state === 'idle' ? 'idle' : 'active'`: a `done` (or `unknown`) review/test pane reads `active` though it is idle. Not a lock, but it is the same mapping written a fourth way.

The issue body named only item 2's first and second bullets. Item 1 is the larger cause and is fixed here too, because fixing only item 2 leaves the operator's composer locked.

## Requirements

- **FR-1** One shared function maps a pane state to a presence: `working | blocked → active`, `idle | done → idle`, `exited → ended`, `unknown → idle`.
- **FR-2** Server session-tree work, planning, strike and knowledge rows take their presence from the issue's backend pane for that agent when one exists; only when no pane exists does the existing tmux/runtime logic run.
- **FR-3** The activity route's review/test/ship rows (`nodeStatusFor`) map `done` like `idle`: `{ status: 'running', presence: 'idle' }`. `exited` and a missing pane stay `ended` with the verdict status.
- **FR-4** The cockpit tree (`IssueTreeLane`) maps a `done` pane to `{ status: 'running', presence: 'idle' }` and an `unknown` pane to presence `idle`.
- **FR-5** The session-tree specialist rows (review, test) take presence from the shared function when a pane exists.
- **FR-6** A row whose agent has a live pane (any state but `exited`) is never ended: no `endedAt`, whatever the runtime state (`suspended` included) or a stale `state.stoppedAt` says.
- **FR-7** The cockpit tree's pane rows carry the canonical agent id (`pane.agentId`, falling back to `pane.id`) as `sessionId`, and `hasJsonl` from the matching activity section, so selecting a live work row renders `ConversationPanel` with a composer that sends to `/api/agents/<agentId>/message`.
- **FR-8** The activity route picks each specialist role's pane preferring a non-`exited` pane over an `exited` one of the same role.
- **NFR-1** No new tmux or Herdr calls per request: the pane list each route already fetches (`getBackendPanesForIssue`) is reused, fetched once per issue.
- **NFR-2** `src/dashboard/server/routes/command-deck.ts` must not grow (1329 lines on `origin/main`, allowlist cap 1331). `projects.ts` stays at or under 1000 lines (the file-size ceiling).
- **NFR-3** tmux hosts (`terminal.backend: tmux`) keep working: the backend inventory's tmux probe also yields panes keyed by session name, so the same pane-first rule applies; with no pane the old tmux branch runs unchanged.

## Decisions

- **D1 — Pane state is authoritative when a pane exists.** The terminal backend owns liveness (PAN-3917 D10, `docs/TERMINAL-BACKENDS.md`). `deriveSessionPresence` returns the shared mapping for a present pane and never reaches the heartbeat/output.log freshness checks for it.
- **D2 — `unknown → idle`.** A pane Herdr lists is alive; `unknown` only means Herdr did not detect the harness. `idle` keeps the composer open without claiming activity. This matches `nodeStatusFor`'s existing default. It changes the specialist rows (were `active`) and the cockpit tree (was `ended`) for undetected panes.
- **D3 — The helper lives in contracts** (`packages/contracts/src/backend-pane.ts`, next to `paneAgentKey`/`indexPanesByAgentKey`), named `presenceForPaneState`, with an inline `"active" | "idle" | "ended"` return type (no import from `./types`, which would close a cycle `lint:circular` refuses). The server and the frontend both import it from `@overdeck/contracts`. Vitest and the frontend tsconfig alias contracts to `src`; the root server typecheck reads `packages/contracts/dist`, so the work agent must rebuild contracts (`bun run --cwd packages/contracts build`) before `npm run typecheck`.
- **D4 — Status stays per call site.** Only presence is shared. `nodeStatusFor` keeps its `verdict` handling; `IssueTreeLane.paneStatus` keeps its `SessionNode['status']` values.
- **D5 — Out of scope (NonGoals), follow-up filed as [PAN-5013](https://github.com/eltmon/overdeck/issues/5013) (the Flywheel copy is [PAN-4666](https://github.com/eltmon/overdeck/issues/4666)):** `activityForPaneState` (`src/dashboard/server/services/agent-state-service.ts:203-210`, `done → 'stopped'` in the read model) and the pipeline liveness helpers that treat `done` as not-live (`src/lib/overdeck/derived-issue-state.ts:159-161`, `src/lib/flywheel/derive-status.ts:171-173`, `src/dashboard/server/routes/parked.ts:97`). They drive dispatch and read-model activity, not the composer, and `docs/TERMINAL-BACKENDS.md:241` already documents the "idle/done = waiting for input" semantic they would need to adopt. No pane transition emits `agent.status_changed { status: 'stopped' }` (the only emitter is `buildConfirmedDeadAgentEvents`, `src/lib/cloister/agent-status-events.ts:49`, for confirmed-dead agents), so the corrected presence is not overwritten by a ws-rpc delta.
- **D6 — The ws-rpc presence poller stays as is.** `startSharedPresencePoller` (`src/dashboard/server/ws-rpc.ts:615`) reads the tmux census; on Herdr it never knows a session, so it never emits a false `ended`. Periodic snapshot refetch carries the corrected presence.
- **D7 — `SessionPanel` and `ComposerFooter` do not change.** `sessionAlive: presence !== 'ended'` is correct once presence is correct.

### W1 — Shared `presenceForPaneState` in contracts (FR-1)

File: `packages/contracts/src/backend-pane.ts` (append after `indexPanesByAgentKey`). `packages/contracts/src/index.ts:30` already has `export * from "./backend-pane"`, so the helper is reachable from `@overdeck/contracts` with no index change.

```ts
/**
 * Pane state → session-node presence (PAN-5011). Herdr's `done` is a finished
 * turn with the pane and harness alive, never an exit; `unknown` is a live pane
 * whose harness Herdr does not detect. Only `exited` ends a session.
 */
export function presenceForPaneState(state: BackendPane["state"]): "active" | "idle" | "ended" {
  switch (state) {
    case "working":
    case "blocked":
      return "active"
    case "exited":
      return "ended"
    default:
      return "idle"
  }
}
```

The inline union is assignable to `SessionNodePresence`.

Steps:
1. `queries.ts` `ActivitySection`: add `hasJsonl?: boolean;` (the activity route already sends it; verified live on `/api/command-deck/activity/PAN-4841?summary=1`).
2. `paneToSession`: `sessionId: pane.agentId ?? pane.id`.
3. Extract the pane/section merge out of the `sessions` `useMemo` into an exported pure function:

```ts
/** Pane rows first (FR-5), enriched with their activity section; then finished sessions the backend no longer owns. */
export function cockpitSessions(panes: readonly BackendPane[], sections: readonly ActivitySection[]): SessionNode[] {
  const base: SessionNode[] = []
  for (const pane of panes) {
    const session = paneToSession(pane)
    if (!session) continue
    const section = sections.find((candidate) => candidate.sessionId === session.sessionId)
    base.push(section?.hasJsonl ? { ...session, hasJsonl: true } : session)
  }
  const paneTypes = new Set(base.map((session) => session.type))
  for (const section of sections) {
    const session = toCockpitSession(section)
    if (session && !paneTypes.has(session.type)) base.push(session)
  }
  return base
}
```

The `useMemo` then calls `cockpitSessions(panes, activity.data?.sections ?? [])` and keeps its legacy-planning push unchanged.
