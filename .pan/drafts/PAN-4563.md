# PAN-4563 — Replay-backed protocol tests for codex app-server and ACP transports

**Issue:** [PAN-4563](https://github.com/eltmon/overdeck/issues/4563)
**Status:** draft (planning, `pan plan --auto`)
**Planned against:** `main` at `6f80870ebfc` (2026-10-19). Installed CLIs on the planning host: `codex-cli 0.159.0`, `kimi 2.0.1`, `opencode 1.18.31`.

## Glossary

- **Client** — Overdeck's side of a JSON-RPC connection: `CodexAppServerManager` for Codex, `AcpSessionRuntime` (built on `effect-acp`) for ACP.
- **Provider** — the agent process on the other side: `codex app-server`, or `kimi acp`.
- **Frame** — one JSON-RPC message on the wire. Both transports in scope use newline-delimited JSON (NDJSON): one frame per line.
- **Direction** — `out` is a frame Overdeck sends to the provider. `in` is a frame the provider sends to Overdeck.
- **Frame kind** — derived from the frame's keys: **request** has `id` and `method`; **notification** has `method` and no `id`; **response** has `id` and no `method` (and `result` or `error`).
- **Client request / server request** — a request whose direction is `out` / `in`. A codex approval is a server request (`item/commandExecution/requestApproval`); the client answers it with an `out` response carrying the same `id`.
- **Capture** — recording every frame of a live session, in observed order, to a fixture file. Enabled by the env var `OVERDECK_PROTOCOL_CAPTURE_DIR` or by the recorder script.
- **Scrub** — deterministic rewriting applied to each frame at capture time, before anything touches disk: home/cwd paths become placeholders, secrets become `<REDACTED>`, emails become `<EMAIL>`, oversized strings are truncated.
- **Fixture** — one JSONL file: a header line, then one line per frame. Format id `overdeck-protocol-capture/1` (defined in Work Item 1).
- **Replay** — a test-only stand-in for the provider process. It plays a fixture's `in` frames to the real client code in recorded order, waits for the client's `out` frames at the points the recording had them, and checks them.
- **Cursor** — the replay engine's position in the fixture's frame list.
- **Id rewriting** — replay substitutes the live client request id for the recorded one in every recorded response to a client request. Server-request ids are replayed verbatim because the client echoes them.
- **Optional tail** — `out` frames recorded after the last `in` frame (for example the ACP `session/cancel` sent by `AcpHost.stop()`). Replay matches them if they arrive but does not wait for them.
- **Owner thread / descendant thread** — Codex terms from `app-server-manager.ts` `threadScope()` (line 531): the conversation's own thread, and a sub-agent thread spawned from inside the owner's tree.
- **Recorder** — the dev script `src/lib/protocol-capture/record.ts` that drives the real host classes through a named scenario with capture on.
- **Scenario** — one named recording recipe in the recorder (prompt + scripted operator actions), for example `codex interrupt`.
- **Synthetic fixture** — a fixture whose header has `"synthetic": true`, allowed only for the Codex user-input case and only under the checkpoint in Work Item 15.

## Problem

The structured harness transports have no recorded-protocol tests. The codex app-server integration has a schema fixture (`src/lib/codex/__fixtures__/app-server-schema.json`) and a hand-scripted fake server (`src/lib/codex/__tests__/fake-app-server.ts`). ACP has hand-written mock peers (`src/lib/acp/__tests__/fixtures/acp-mock-peer.ts` and `packages/effect-acp/test/fixtures/acp-mock-peer.ts`, which differ in content). A hand-written mock behaves the way its author expects. The real provider does not always behave that way, especially for event ordering. When a CLI update changes ordering or adds fields, the tests stay green and the dashboard breaks.

Ordering cases that need real coverage:

1. An idle status notification arriving before or around the turn-completed event; turn-completed is the real end of the turn.
2. An interrupt request returning first, with the interrupted terminal state arriving later in a separate event.
3. A sub-agent's child turn completing before the parent turn completes. The child's completion must not end the parent's turn in Overdeck's state.
4. Approval and user-input requests that the provider initiates mid-turn.

Two defects are already visible from reading the code, and the new tests would expose both:

- **D-1 (no interrupted state on Codex).** `CodexAppServerState` (`src/lib/codex/app-server-manager.ts:137`) has no turn outcome. `applyNotification` treats every owner `turn/completed` the same (line 601: `if (message.method === 'turn/completed') {`). The schema's `TurnStatus` enum is `completed | interrupted | failed | inProgress` (`app-server-schema.json:13038`). Overdeck cannot report that a turn ended interrupted.
- **D-2 (wrong user-input answer shape).** `answerUserInput` (`app-server-manager.ts:316`) writes `{ id, result: { answers } }` with `answers: Record<string, string[]>`. The schema's `ToolRequestUserInputResponse` (`app-server-schema.json:20957`) requires `answers` values to be `ToolRequestUserInputAnswer` objects `{ "answers": string[] }`. Codex gets the wrong shape.

## Requirements

### Functional

- **FR-1** A capture mode exists, off by default, enabled only by `OVERDECK_PROTOCOL_CAPTURE_DIR=<absolute dir>`. When set, every Codex app-server connection (stdio or native socket) and every ACP host session writes one fixture file into that dir.
- **FR-2** Capture records every frame in both directions in observed order, and scrubs each frame before it is written (rules in Work Item 1).
- **FR-3** A recorder script drives the real `CodexAppServerHost`/`CodexAppServerManager` and the real `AcpHost`/Kimi ACP runtime through named scenarios and writes a fixture whose header names the scenario, CLI version, and host options.
- **FR-4** A replay engine plays a fixture to the real client code with no child process and no network: server frames in recorded order, client frames matched by kind and method (responses by id and `result`), client request ids rewritten.
- **FR-5** Codex replay replaces only the child process (through the existing `spawnProcess` + `readVersion` manager options); the real stdio transport, manager, and host run. ACP replay replaces only the `ChildProcessSpawner` service; the real `effect-acp` client, `AcpSessionRuntime`, Kimi runtime factory, and `AcpHost` run.
- **FR-6** Codex fixtures and replay tests exist for all four ordering cases (case 4 as two fixtures: approval and user-input).
- **FR-7** Kimi ACP fixtures and replay tests exist for turn completion and interrupt.
- **FR-8** Codex manager state and host `status()` expose the owner's last turn outcome (`lastTurnStatus`) from `turn/completed` `turn.status` (fixes D-1).
- **FR-9** `answerUserInput` sends the schema shape `{ answers: { <questionId>: { answers: string[] } } }` (fixes D-2).
- **FR-10** A developer doc explains how to record a fixture, review its scrubbing, and add a replay test, and lists every defect the replay tests found with its disposition.

### Non-functional

- **NFR-1** With `OVERDECK_PROTOCOL_CAPTURE_DIR` unset, no production code path changes behavior and no file is written.
- **NFR-2** Committed fixtures contain no absolute home path (`/home/`, `/Users/`, `/root/`), no secret-pattern match, and are each ≤ 256 KiB. A test enforces this.
- **NFR-3** Replay tests run no child process, open no TCP socket, and need no credentials. (The ACP host's local Unix control socket under a temp `OVERDECK_HOME` is allowed; the existing `src/lib/acp/__tests__/host.test.ts` already does this.)
- **NFR-4** No file grows past the file-size ratchet. `src/lib/codex/app-server-host.ts` is 985 lines and `src/lib/acp/host.ts` is 908 lines against a 1000-line ceiling (`scripts/lint-file-size.sh` `CEILING=1000`): each gets at most a few lines; all new logic goes in new modules. Do not add tests to `app-server-host.test.ts` (979 lines) or `acp/__tests__/host.test.ts` (1307 lines).
- **NFR-5** Capture writes are async (`fs/promises`), never `*Sync`.

## Decisions

1. **One new leaf module dir** `src/lib/protocol-capture/` holds the fixture format, scrubber, capture sink, ACP logging adapter, replay engine, and recorder. Test adapters live next to the tests they serve (`src/lib/codex/__tests__/`, `src/lib/acp/__tests__/fixtures/`).
2. **Codex capture** wraps the `AppServerTransport` in `useTransport`, so stdio and native connections are captured the same way. The host's `appserver-events.jsonl` is post-parse and one-directional; it is not the capture.
3. **Codex replay** goes through the existing `spawnProcess` + `readVersion` options with a fake child, so the real `createStdioTransport` framing runs. No new manager option. The native-socket path is not replayed (its frames are the same JSON).
4. **ACP capture** uses `protocolLogging` with `stage: "raw"` events, passed from `host.ts main()` through `support.makeRuntime`. Both directions go through one per-direction line splitter.
5. **ACP replay** provides a replay `ChildProcessSpawner` to `makeKimiAcpRuntime`. Kimi is the ACP agent under test because `acp` is the Kimi harness (`src/lib/runtimes/acp.ts:77` defaults provider to `kimi`).
6. **Scrub at capture time**, never as a later step, so raw secrets never reach disk. Rules in Work Item 1.
7. **Replay matching:** kinds must match; requests and notifications match by `method`; client responses match by `id` and deep-equal `result` (or both have `error`). Params of client requests are not compared (they carry environment-specific values). A mismatch rejects `replay.done` with an error naming the fixture seq, the expected frame, and the actual frame.
8. **Client frames that arrive early** (before the cursor reaches their recorded position) are queued and matched in order when the cursor gets there. Server frames are always delivered in recorded order, one per `setImmediate` tick.
9. **Optional tail:** `done` resolves once every `in` frame has been delivered and every `out` frame before the last `in` frame has matched. Later `out` frames are matched if they arrive, else ignored.
10. **Order-dependent assertions are guarded by fixture preconditions.** Where a test relies on an ordering (for example "the interrupt response precedes `turn/completed`"), the test first asserts that ordering on the fixture's frame list with a message saying "re-check case N against the new CLI". A re-recording that flips the order fails loudly instead of deadlocking.
11. **Expected values come from the fixture** (turn ids, request ids, thread ids, stop reasons), never hard-coded, so a re-recording does not require editing ids in tests.
12. **Timers in Codex replay tests:** `vi.useFakeTimers({ toFake: ['setTimeout', 'clearTimeout', 'setInterval', 'clearInterval'] })` in `beforeEach`, `vi.useRealTimers()` in `afterEach`. This parks the host's 120 s `waitForPath` poll and the manager's request timeouts. `setImmediate` and `queueMicrotask` stay real, and replay schedules on `setImmediate`, so it still advances. ACP replay tests use real timers (no `session/load`); if a future ACP fixture exercises `session/load`, it must fake timers per the repo rule (below).
13. **Recorder, not hand edits.** Fixtures come from the recorder only. Hand-written fixtures are forbidden except the single synthetic fallback in Work Item 15.
14. **Recorder model defaults:** Codex `gpt-5.6-luna`, effort `low` (the model the PAN-3835 protocol experiment used). Kimi `k3`. Both are overridable with `--model`/`--effort`. *Implementation checkpoint:* if a default model is rejected by the provider, pick the cheapest model `pan models` lists for that harness, and record the choice in the fixture header and the doc.
15. **Defect triage rule (AC 4 of the issue).** When a replay assertion fails because Overdeck is wrong (not because the test is wrong): if the fix touches only files already in this plan's scope and is ≤ 40 changed lines, fix it in this PR and keep the assertion. Otherwise file a GitHub issue (`gh issue create`, body: fixture name, failing assertion, observed frames) and change the assertion to pin the current behavior with a `// PAN-<n>: <defect>; flip when fixed` comment. Every finding goes into the doc's "Findings" table (Work Item 19).

### Intersecting repo rules (restated)

- **Fake timers for delay tests:** any test that exercises a timeout, retry, backoff, or delay uses `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()`, never a real wait.
- **Async-only in reachable server code:** capture uses `fs/promises`; no `execSync`, no `*Sync` fs in the capture sink.
- **No one-shot agents:** the recorder runs a persistent `codex app-server` / `kimi acp` session through the same host classes production uses. It never shells out to `codex exec` or `claude -p`.
- **No variables in `rm` targets:** the recorder deletes its own temp dirs with `fs/promises` `rm` on paths returned by `mkdtemp`, never by shell.
- **Quality gates:** `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.

## Fixture format (`overdeck-protocol-capture/1`)

Line 1 is the header; every later line is a frame.

```jsonc
// header
{"type":"header","format":"overdeck-protocol-capture/1","harness":"codex-app-server","provider":null,
 "cliVersion":"0.159.0","scenario":"interrupt","recordedAt":"2026-10-20T03:00:00.000Z",
 "hostOptions":{"model":"gpt-5.6-luna","effort":"low","prompt":"Count from 1 to 400, …"},
 "scrubbed":true}
// optional header keys: "synthetic": true, "syntheticNote": "<why>", "followUpIssue": "PAN-<n>"
// frame
{"type":"frame","seq":0,"dir":"out","t":0,"message":{"id":1,"method":"initialize","params":{…}}}
{"type":"frame","seq":1,"dir":"in","t":41,"message":{"id":1,"result":{…}}}
// a line that was not valid JSON is kept verbatim:
{"type":"frame","seq":7,"dir":"in","t":90,"text":"<raw line>"}
```

`harness` is `"codex-app-server"` or `"acp"`. `provider` is `"kimi"` for ACP and `null` for Codex. `t` is milliseconds since capture start (diagnostic only; replay ignores it). `scenario` and `hostOptions` are `null` for env-var captures.

### WI-1 — Fixture format and scrubber (foundation)

Files: `src/lib/protocol-capture/fixture.ts` (new), `src/lib/protocol-capture/scrub.ts` (new), `src/lib/protocol-capture/__tests__/capture.test.ts` (new).

`fixture.ts` exports (Node built-ins only, no Effect):

```ts
export const PROTOCOL_CAPTURE_FORMAT = 'overdeck-protocol-capture/1';
export type FrameDirection = 'out' | 'in';
export type FrameKind = 'request' | 'notification' | 'response' | 'raw';
export interface ProtocolFixtureHeader { type: 'header'; format: typeof PROTOCOL_CAPTURE_FORMAT; harness: 'codex-app-server' | 'acp'; provider: string | null; cliVersion: string | null; scenario: string | null; recordedAt: string; hostOptions: Record<string, unknown> | null; scrubbed: true; synthetic?: true; syntheticNote?: string; followUpIssue?: string }
export interface ProtocolFrame { type: 'frame'; seq: number; dir: FrameDirection; t: number; message?: Record<string, unknown>; text?: string }
export interface ProtocolFixture { header: ProtocolFixtureHeader; frames: ProtocolFrame[] }
export function frameKind(frame: ProtocolFrame): FrameKind;          // per Glossary; 'raw' when only `text`
export function parseProtocolFixture(text: string): ProtocolFixture; // throws on a missing/foreign header, a non-frame line, or non-consecutive seq
export async function loadProtocolFixture(path: string): Promise<ProtocolFixture>; // fs/promises readFile + parse
```

`scrub.ts` exports `interface ScrubContext { paths: ReadonlyArray<{ value: string; placeholder: string }> }`, `function defaultScrubContext(input: { cwd?: string; codexHome?: string; overdeckHome?: string; home?: string }): ScrubContext`, and `function scrubValue(value: unknown, context: ScrubContext): unknown` (pure, returns a new value). Rules, applied recursively to every string and object key-value:

1. **Paths:** replace each `paths[i].value` occurrence with its placeholder, longest value first. `defaultScrubContext` maps `cwd → <CWD>`, `codexHome → <CODEX_HOME>`, `overdeckHome → <OVERDECK_HOME>`, `home (os.homedir()) → <HOME>`; empty values are skipped.
2. **Secret keys:** a value whose key matches `/^(access_?token|refresh_?token|id_?token|api_?key|authorization|cookie|password|secret|client_?secret|bearer|auth_?token)$/i` becomes `"<REDACTED>"`. (Anchored on purpose: `tokenUsage`, `inputTokens` must survive.)
3. **Secret values:** inside any string, replace matches of `/sk-[A-Za-z0-9_-]{16,}/g`, `/gh[pousr]_[A-Za-z0-9]{20,}/g`, `/xox[abpr]-[A-Za-z0-9-]{10,}/g`, `/eyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]+/g`, `/Bearer\s+[A-Za-z0-9._~+\/-]+=*/g` with `<REDACTED>`.
4. **Emails:** replace `/[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}/g` with `<EMAIL>`.
5. **Size:** a string longer than 8192 characters becomes `"<TRUNCATED:<length>>"`.

Tests in `capture.test.ts` (describe `scrubValue` and `parseProtocolFixture`): each rule rewrites a sample; `tokenUsage.total.inputTokens` survives; a nested `params.thread.path` under the codex home becomes `<CODEX_HOME>/…`; `parseProtocolFixture` rejects a file whose first line is not a header with the format id, and rejects a gap in `seq`. Secret-shaped inputs are built at runtime.

### WI-2 — Capture sink and Codex transport wrapper

Files: `src/lib/protocol-capture/capture.ts` (new), `src/lib/protocol-capture/__tests__/capture.test.ts`.

```ts
export const PROTOCOL_CAPTURE_DIR_ENV = 'OVERDECK_PROTOCOL_CAPTURE_DIR';
export interface ProtocolCaptureSink {
  readonly path: string;
  setHeader(fields: Partial<Pick<ProtocolFixtureHeader, 'cliVersion' | 'scenario' | 'hostOptions' | 'provider'>>): void; // before the first frame only; later calls are ignored
  recordMessage(dir: FrameDirection, message: unknown): void;   // scrub, then queue
  recordText(dir: FrameDirection, line: string): void;          // JSON.parse → message, else text frame; scrub; queue
  recordChunk(dir: FrameDirection, chunk: string): void;        // per-direction line buffer; each complete non-empty line → recordText
  close(): Promise<void>;                                       // flush partial lines as frames, await all writes
}
export function createProtocolCaptureSink(input: { path: string; harness: ProtocolFixtureHeader['harness']; scrub: ScrubContext; now?: () => number }): ProtocolCaptureSink;
export function protocolCaptureFromEnv(env: NodeJS.ProcessEnv, input: { harness: ProtocolFixtureHeader['harness']; scrub: ScrubContext }): ProtocolCaptureSink | undefined;
export function captureAppServerTransport(transport: AppServerTransport, sink: ProtocolCaptureSink): AppServerTransport;
```

- Ordering: `recordMessage`/`recordText` assign `seq` synchronously at call time; writes go through one promise chain of `fs/promises` `appendFile`, so file order equals call order. The header is written by the first append (`mkdir(dirname(path), { recursive: true })` first, file mode `0o600`).
- `protocolCaptureFromEnv` returns `undefined` when the env var is unset or empty, or not absolute. Otherwise the path is `<dir>/<harness>-<recordedAt with ':' and '.' replaced by '-'>-<process.pid>.jsonl`.
- `captureAppServerTransport`: `send(message)` → `sink.recordMessage('out', message)` then `inner.send(message)`; `onMessage(handler)` → `inner.onMessage(text => { sink.recordText('in', text); handler(text); })`; `onClose`/`close` delegate.

Tests (describe `capture sink`): header is line 1 and frames follow in call order; a JSON object split across two `recordChunk` calls becomes one frame; two lines in one chunk become two frames; an unparsable line is stored as `text`; a cwd path in a frame is written as `<CWD>`; `protocolCaptureFromEnv({}, …)` returns `undefined`; the transport wrapper records an `out` and an `in` frame around a fake transport.

### WI-7 — Replay engine (foundation)

Files: `src/lib/protocol-capture/replay.ts` (new), `src/lib/protocol-capture/__tests__/replay.test.ts` (new).

```ts
export interface ReplayMatcher { dir?: FrameDirection; method?: string; threadId?: string; where?: (frame: ProtocolFrame) => boolean }
export class ReplayMismatchError extends Error {}
export interface ProtocolReplay {
  readonly fixture: ProtocolFixture;
  /** Adapter: register the function that delivers one server line (no trailing newline) to the client. */
  onServerLine(deliver: (line: string) => void): void;
  /** Adapter: hand over each complete line the client wrote. */
  acceptClientLine(line: string): void;
  /** Begin delivering frames. Adapters call this once the client is attached. */
  start(): void;
  /** Resolves when the cursor reaches the next `in` frame matching `matcher`, without delivering it; delivery pauses there. */
  pauseBefore(matcher: ReplayMatcher): Promise<ProtocolFrame>;
  /** Resolves when the cursor reaches an `out` frame matching `matcher` and is waiting for the client. */
  awaitingClient(matcher: ReplayMatcher): Promise<ProtocolFrame>;
  resume(): void;
  /** Resolves per Decision 9; rejects with ReplayMismatchError on the first mismatch. */
  readonly done: Promise<void>;
  /** Client lines that were never matched (extra frames, or frames left after `done`). */
  unmatchedClientLines(): string[];
}
export function createProtocolReplay(fixture: ProtocolFixture, options?: { schedule?: (fn: () => void) => void }): ProtocolReplay;
```

Behavior (each is a named test in `replay.test.ts`, using small fixtures built in the test):

1. Delivers `in` frames in seq order, one per `schedule` tick (default `setImmediate`).
2. Stops at an `out` frame until a matching client line arrives; then continues.
3. Rewrites the id of a recorded response to a client request to the live id the client used (live id `"a7"` for recorded `3`), and keeps server-request ids verbatim.
4. Queues a client line that arrives before its recorded position and matches it when the cursor gets there.
5. Rejects `done` with `ReplayMismatchError` when the client sends a different method; the message contains the seq, the expected method, and the actual line.
6. Rejects `done` when a client response's `result` differs from the recorded one.
7. Resolves `done` while a trailing `out` notification never arrives (optional tail).
8. `pauseBefore` holds delivery before the matching frame until `resume()`.
9. A `text` frame is delivered verbatim.
10. `unmatchedClientLines()` returns a client line sent after the last frame.
11. `pauseBefore` and `awaitingClient` reject at once when no frame from the cursor onward matches the matcher; the error names the matcher and the cursor seq. (A mis-armed breakpoint is a diagnosed failure, not a test timeout.)

`threadId` in a matcher compares against `params.threadId ?? params.thread?.id` (the same rule as `messageThreadId` in `app-server-manager.ts:643`; reimplement it locally to keep the module a leaf).

## Non-goals

- Deduplicating or changing the two `acp-mock-peer.ts` files.
- Replaying the Codex native Unix-socket (WebSocket) transport; stdio frames carry the same JSON.
- An ACP sub-agent or ACP approval case (the issue requires only turn completion and interrupt on ACP).
- An OpenCode ACP fixture.
- Regenerating or committing a new `app-server-schema.json`.
- Any dashboard UI change, including surfacing `lastTurnStatus` in the frontend.
- Turning capture on for any production launch, or exposing it in settings or the CLI.
- Changing `effect-acp` (`packages/effect-acp`).

## Risks and hazards

- **H-1 Live recording needs credentials.** `~/.codex/auth.json` exists on the planning host; Kimi needs a logged-in `kimi` CLI. A failed login is an escalation, not a reason to hand-write fixtures.
- **H-2 CLI drift.** Installed codex is 0.159.0; the protocol doc was verified on 0.153.4. Sub-agent announcements, status notifications, or interrupt ordering may differ. Decision 10 preconditions make that visible.
- **H-3 Secrets in fixtures.** `account/read`, `initialize` responses (user agent, paths), `thread.path`, and model instructions can carry personal data. Scrub at capture, review by hand, and rely on the hygiene test.
- **H-4 Timer leaks.** `recordOwnerThread` starts a 120 s poll. Codex replay tests must fake `setTimeout`/`setInterval` (Decision 12) or they leak a real poll per test.
- **H-5 Effect queue offer API.** The exact sync/unsafe `Queue` offer name depends on the installed `effect` version; check `node_modules/effect` types before writing WI-9.
- **H-6 ACP late prompt response.** After a local cancel, the provider's real `session/prompt` response arrives for an id the client already dropped. Watch for client-side error logs; triage per Decision 15.
- **H-7 Fixture determinism.** Replay delivers one frame per `setImmediate`. Assertions must use `pauseBefore`/`awaitingClient`, never "check state right after an await". Arm a breakpoint before dispatching the op that leads to its frame; arming after an `await` is safe only for frames that come after the awaited response.

## Probe pass (pre-finalize)

- **Sub-agent label depends on adoption order.** The `[turn sub:…]` pane label needs the `spawnAgent` item before the child's `turn/completed`; WI-13 now asserts that as a precondition.
- **Recorder and test must drive identical client sequences.** Both build the manager and host the same way and call `manager.start()` then `host.handleOp({ op: 'message' })`; the codex recorder never calls `host.start()`, and the ACP recorder and test both call `host.start()`/`host.stop()`. A difference shows up as a `ReplayMismatchError`, not a silent pass.
- **Deadlock instead of failure.** If the client never sends an expected frame, `done` never settles; the vitest per-test timeout (real timers, unaffected by `vi.useFakeTimers`) turns that into a failure. `awaitingClient`/`pauseBefore` assertions keep tests from relying on tick timing (H-7).
- **Projected surface.** 19 items, 23 distinct `files_scope` entries (fixture dirs as two globs), 5 subsystems: within the 25-file and 6-subsystem limits.
