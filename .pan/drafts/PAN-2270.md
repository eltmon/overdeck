## Glossary

- **Strike workspace** — `workspaces/feature-<id>-strike`, a git worktree on branch `strike/<id>`. Created by `pan strike`; lives alongside, not inside, the normal `feature-<id>` directory.
- **Feature workspace** — `workspaces/feature-<id>`. The path the review subsystem expects as the canonical workspace for an issue.
- **`findWorkspacePath(projectPath, issueLower)`** — defined in `src/lib/lifecycle/archive-planning.ts:67`; calls `findAllWorkspacePaths` which tries candidates in order: `feature-<id>`, `feature-<id>-strike`, `feature-<numeric>`, `<id>`, `.worktrees/<id>`, and `../feature-<id>`. Returns the first one that `existsSync`.
- **`spawnReviewRoleForIssue(opts)`** — the single review entry point in `src/lib/cloister/review-agent.ts`. Takes `{ issueId, workspace, branch }`. The `workspace` path must exist on disk; the `branch` is used for `git diff` and review output paths.
- **`deacon-review-status.ts`** — `src/lib/cloister/deacon-review-status.ts`; three of its recovery/dispatch paths call `findWorkspacePath` then `spawnReviewRoleForIssue`. All three bail out with `workspace unavailable` when `findWorkspacePath` returns null.
- **Manual unblock** — today's workaround for PAN-2258/RUN-53: `pan workspace create PAN-<id>` (creates `workspaces/feature-<id>`) + `pan review restart`. Both require human intervention.
- **PR head branch** — the `strike/<id>` branch, which always exists on `origin` while the PR is open. Review needs to run `git diff` against the PR's head SHA; as long as the strike workspace exists, this is available.

## Problem (verified 2026-07-04 against main @ `6681632b`)

A strike completes its branch and creates a PR (after PAN-2360 fixes the kickoff). Overdeck's review subsystem is then expected to auto-trigger review. But every path that triggers or restarts a review resolves the workspace via `findWorkspacePath`, which looks for `workspaces/feature-<id>` first. Because no such directory exists for a strike-originated issue (only `workspaces/feature-<id>-strike` exists), `findWorkspacePath` returns null.

Three concrete sites in `src/lib/cloister/deacon-review-status.ts` exhibit this:

1. **`handleReviewCoordinatorDied` (line 364):**
   ```ts
   const workspace = findWorkspacePath(resolved?.projectPath ?? '', issueLower);
   if (!resolved || !workspace) {
     actions.push(`Skipped review re-dispatch for ${issueId}: workspace unavailable`);
     return actions;
   }
   ```

2. **`reconcileConvoys` (line 528):**
   ```ts
   const workspace = agentState?.workspace || (resolved ? findWorkspacePath(resolved.projectPath, issueLower) : null);
   ```
   If the agent state has no `workspace` field (fresh dispatch) and `findWorkspacePath` returns null, the convoy re-dispatch bails.

3. **`checkMissingReviewStatus` (line 820):**
   ```ts
   const workspace = findWorkspacePath(resolved?.projectPath ?? '', issueLower);
   if (!workspace) {
     actions.push(`Skipped missing-status review for ${issueId}: ...`);
   ```

All three emit `workspace unavailable` and stop without spawning a review agent.

**Root cause:** `findWorkspacePath` already knows about the strike workspace path (`feature-<id>-strike` is the second candidate in `findAllWorkspacePaths`). But the callers in `deacon-review-status.ts` pass a hardcoded `feature/${issueLower}` as the `branch` argument to `spawnReviewRoleForIssue`, even when the resolved workspace is the strike workspace. Review then runs `git diff feature/<id>` against the wrong branch.

The fix: after `findWorkspacePath` returns a workspace, infer the correct branch name from the workspace path — if the path ends in `-strike`, use `strike/<id>` as the branch; otherwise use `feature/<id>`.

## Work items

### W1 — Extract `inferBranchFromWorkspace` helper (FR-1, FR-2)

**New helper — place in `src/lib/lifecycle/archive-planning.ts`** (immediately after `findWorkspacePath`, line ~70):

```ts
/**
 * Infer the git branch for an issue given its resolved workspace path.
 * Strike workspaces (path ends in '-strike') use `strike/<id>`; all other
 * workspaces use `feature/<id>`.
 *
 * PAN-2270: callers that resolve workspace via findWorkspacePath must use this
 * to derive the branch — never hardcode `feature/${issueLower}`.
 */
export function inferBranchFromWorkspace(workspacePath: string, issueLower: string): string {
  if (workspacePath.endsWith('-strike')) return `strike/${issueLower}`;
  return `feature/${issueLower}`;
}
```

Grep anchor for the insertion point: `export function findWorkspacePath` (the function this new helper follows).

This helper is trivial and requires no imports beyond the existing `string` types already in scope.
