# PAN-4605 — A PR opened outside a pipeline workspace is never reviewed and nobody is told

**Issue:** https://github.com/eltmon/overdeck/issues/4605
**Status:** draft (planning, `pan plan --auto`)
**Planned at:** main `050e5b3c406`, 2026-10-24

## Glossary

- **Pipeline workspace** — the git worktree `workspaces/feature-<issue-lower>/` of the
  project's primary checkout, on branch `feature/<issue-lower>`. The review pipeline
  (verify → push → review) only runs in one. Created by `createWorkspace()` in
  `src/lib/workspace-manager/create.ts`.
- **Outside PR** — an open, non-draft pull request whose head branch is exactly
  `feature/<issue-lower>` for an issue that has no pipeline workspace. Supervised
  handoff conversations (`pan handoff --cwd <worktree>`) produce these: the handoff
  worktree is a worktree of the primary checkout, but it is not under `workspaces/`.
- **Adoption** — creating the pipeline workspace on the outside PR's existing branch at
  the PR's head commit (never a new branch from `main`), then starting the review
  pipeline in it. Adoption never pushes, never forces a checkout, and never deletes a
  branch or worktree.
- **Review starter** — `startRequestReviewPipeline` in
  `src/dashboard/server/routes/workspaces/review-pipeline.ts`, registered on
  `src/lib/cloister/request-review-pipeline.ts` (`registerRequestReviewStarter`) so the
  webhook in `src/lib/` can reach it without importing a route. It returns
  `{ started: false, reason: 'no-workspace' }` when the issue has no workspace.
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl`, append-only, written by
  `appendPipelineEntry` in `src/lib/cloister/pipeline-journal.ts`. It is never written
  into a workspace directory that does not exist (the function skips the write).
- **Derived attention** — the `attention` field of `DerivedIssueState`
  (`packages/contracts/src/derived-issue-state.ts`), computed at read time by
  `deriveAttention` in `src/lib/overdeck/derived-issue-state.ts`. Command Deck's
  **Needs you** group (`isNeedsYouFeature` in
  `src/dashboard/frontend/src/components/CommandDeck/pipeline-helpers.ts`) renders from it.
- **Needs-you announcement** — `surfaceIssueFeedbackNeedsYou(issueId, reason, details)` in
  `src/lib/cloister/feedback-target.ts` (line ~306): the established door (31 callers) that
  emits a `warn` activity entry `"<ISSUE> needs you: <reason>"`.

## Problem (verified)

`handlePullRequest` in `src/lib/webhook-handlers.ts` (grep anchor:
`console.log(\`[webhook] Review not started for ${issueId}: ${outcome.reason}\`);`,
line ~340) starts the review pipeline for an opened or readied non-draft `feature/` PR.
When the starter returns `started: false` it only logs. On 2026-10-24, PRs #4599, #4602
and #4603 were opened from handoff worktrees (`~/Projects/hoff-pan-4527`, …). No
workspace existed, so nothing ran and nobody was told; `pan review request PAN-4527`
failed with `Workspace does not exist`.

Verified facts that shape the fix:

1. `git -C /home/eltmon/Projects/overdeck worktree list` shows the `hoff-*` directories
   are worktrees of the primary checkout, and `git branch -a` marks `+ feature/pan-4527`
   (checked out in another worktree). So "branch checked out elsewhere" is the **common**
   case, not an edge case. `git worktree add` refuses a branch that is checked out in
   another worktree unless forced; this plan never forces.
2. `appendPipelineEntry` (`pipeline-journal.ts` ~L70-90) refuses to write when the
   workspace directory does not exist ("a missing workspace is a skip, not a write"). So
   when adoption is impossible there is no journal to append to.
3. Command Deck's Needs-you group reads `derived.attention`, not activity entries. The
   PAN-4399 `work-not-started` attention is the precedent for a derived, never-stored
   Needs-you signal (`src/lib/overdeck/work-start-state.ts`, `featureStateBadge.ts`,
   `pipeline-helpers.ts` `sublineFor`).
4. `createWorktree` in `src/lib/workspace-manager/worktree-ops.ts` (~L97-159) fetches only
   the default branch, then decides "branch exists" from `git branch -r --list`. If
   `origin/feature/<x>` was never fetched into the primary checkout, it runs
   `git worktree add -b feature/<x> <path> origin/main` — a new branch from `main` with the
   PR branch's name. `pan workspace create <id>` has the same defect.
5. `/api/review/:issueId/request` (`review-pipeline.ts` `case 'no-workspace':` in the
   `postWorkspaceRequestReviewRoute` switch, ~L921) returns
   `400 { error: 'Workspace does not exist' }`.
6. `review-pipeline.ts` is 983 lines. `scripts/lint-file-size.sh` passes every file at or
   under `CEILING=1000` (`if (( n <= CEILING )); then continue`), so the file has 17 lines
   of headroom. The allowlist row `901 … # PAN-3847` only applies above the ceiling.
   `src/lib/overdeck/derived-issue-state.ts` is 919 lines (81 lines of headroom).
7. The webhook route dispatches handlers detached (`void dispatchWebhook(...)` in
   `src/dashboard/server/routes/webhooks.ts` ~L178), so a minutes-long adoption
   (`createWorkspace` runs `bun install` and builds workspace packages) never delays the
   200 response.
8. `createWorkspace` handles a missing `projectConfig.workspace` via
   `getDefaultWorkspaceConfig()`. Overdeck's `projects.yaml` entry has
   `workspace: { type: monorepo, workspaces_dir: workspaces }`.

## Decisions (made here; do not re-decide)

- **D1 — Adopt only the exact pipeline branch.** Adoption runs only when
  `pr.head.ref === \`feature/${issueId.toLowerCase()}\`` (exact, case-sensitive). Strike,
  bypass and mixed-case branches are never adopted.
- **D2 — Preflight in git before `createWorkspace`; never clean up after.** Order:
  fetch the PR branch → compare the fetched ref to the PR head → prune and list worktrees
  → reconcile the local branch → `createWorkspace` → assert workspace HEAD. A mismatch at
  any step refuses; nothing is removed (`removeWorktree`/`removeWorkspace` run
  `git branch -D`, which would destroy unpushed commits).
- **D3 — Missing PR head SHA ⇒ refuse** (`head-unknown`). `WebhookPayload.pull_request.head.sha`
  is optional; an unverifiable head is never adopted.
- **D4 — Local branch rule.** If local `feature/<x>` is absent, create it at the verified
  remote ref with tracking. If it equals the PR head, use it. If it is a strict ancestor of
  the PR head, fast-forward it with `git update-ref refs/heads/feature/<x> <head> <old>`
  (compare-and-swap). Otherwise refuse `local-branch-diverged` (it may hold unpushed work).
- **D5 — The journal records only what happened in a workspace.** Success appends
  `workspace.adopted` to the new workspace's journal before the review starts (so the
  journal reads `workspace.adopted → review.requested → verification.started`). A failure
  after the worktree exists appends `workspace.adoption-failed` with `data.fix`. So does a
  review that does not start after a successful adoption (no starter registered, or the
  starter answers `started: false`, e.g. `dirty-workspace`): the orchestrator appends
  `workspace.adoption-failed` with `data.reason` `review-not-started` or `no-starter`. The
  next `review.requested` supersedes it. A failure with no workspace cannot be journaled
  (fact 2); it is made visible by D6 instead.
- **D6 — Visibility is derived, plus one announcement.** A new derived attention
  `pr-outside-pipeline` holds while an open, non-draft PR on the exact pipeline branch
  exists for an open issue and EITHER no pipeline workspace exists OR the workspace
  journal's last entry is `workspace.adoption-failed`. It carries
  `prOutsidePipeline: { prNumber, fix, worktreePath? }`. Command Deck groups it into
  Needs you, and `pan show` prints the fix. At the moment adoption fails, the orchestrator
  also calls `surfaceIssueFeedbackNeedsYou` once. The derived signal also catches PRs
  opened while the dashboard was down, and it clears by itself when a workspace appears.
  So a just-opened PR is not hidden by the cached repo listing (idle listings are cached
  for 5 minutes, `pr-cache-policy.ts`), the webhook calls `refreshIssuePullRequestStateNow`
  (`src/dashboard/server/services/issue-pr-refresh.ts`, which runs
  `invalidateRepoPullRequests` and schedules a derived refresh) on `opened`, `reopened`,
  `ready_for_review` and `closed`.
- **D7 — `pan review request` adopts too, before any other shortcut.** The issue's fix
  text for the checked-out case is "`git worktree remove …`, then `pan review request`".
  After the worktree is removed there is still no workspace, so the `/request` route asks
  `answerMissingWorkspace` right after it reads the derived state and BEFORE the
  approved-PR force/nudge block and `requestReviewGuarded` (whose `tests-requeued`,
  `already-passed` and circuit-breaker answers would otherwise report success without a
  workspace). A merged issue skips it, so the existing merged guard still answers. With no
  workspace and an open pipeline-branch PR, adoption starts in the background (202). The
  PR lookup is a fresh, branch-targeted `gh pr list --head`, never the cached repo listing,
  and a forge failure answers 503, never "no PR". The route grows by at most 10 lines
  (17 lines of headroom, fact 6); the logic lives in the new lib module.
- **D8 — `createWorktree` fetches the feature branch** (best effort) before deciding
  whether it exists, so `pan workspace create <id>` and adoption both check out an
  existing remote branch instead of cutting a same-named branch from `main` (fact 4).
- **D9 — Coalesce per issue.** One adoption per issue at a time. A second caller (an
  `opened` + `ready_for_review` pair, a webhook redelivery, or `pan review request` racing
  the webhook) awaits the first caller's promise.
- **D10 — Polyrepo projects are refused** (`polyrepo`) with a fix telling the operator to
  run `pan workspace create <ID>` by hand. Adopting sub-repo branches is out of scope.
- **D11 — Scope of the UI.** Command Deck (Needs-you group + state badge) and `pan show`
  carry the signal. The Kanban `NeedsYouStrip` / simple-mode projection is out of scope.

## Requirements

### Functional

- **FR-1** — When the review starter returns `no-workspace` for an opened or readied
  non-draft PR whose head ref is exactly `feature/<issue-lower>`, the webhook adopts the
  branch and then starts the review pipeline with no manual step.
- **FR-2** — Adoption fetches `feature/<issue-lower>` from `origin`, verifies the fetched
  ref equals the PR head SHA, and refuses (`head-moved`) when it does not.
- **FR-3** — Adoption refuses (`checked-out-elsewhere`, with `worktreePath`) when the
  branch is checked out in a worktree other than the canonical workspace path, and never
  forces a checkout.
- **FR-4** — Adoption reconciles the local branch per D4 and refuses
  (`local-branch-diverged`) when the local branch holds commits not in the PR head.
- **FR-5** — After `createWorkspace`, adoption verifies the workspace's `HEAD` equals the
  PR head and its current branch is `feature/<issue-lower>`; on mismatch it refuses
  (`workspace-head-mismatch`) and removes nothing.
- **FR-6** — Adoption appends `workspace.adopted` (success) or `workspace.adoption-failed`
  (failure with an existing workspace) to the workspace pipeline journal.
- **FR-7** — Every adoption refusal produces one Needs-you announcement naming the PR
  number, the reason, and the exact fix commands.
- **FR-8** — `DerivedIssueState.attention` is `pr-outside-pipeline`, with
  `prOutsidePipeline: { prNumber, fix, worktreePath? }`, under the D6 rule.
- **FR-9** — Command Deck groups a `pr-outside-pipeline` issue under Needs you, shows the
  fix as the row subline, and shows a "Review never started" state badge whose tooltip is
  the fix.
- **FR-10** — `pan show <id>` prints the fix line under the `needs` line when the attention
  is `pr-outside-pipeline`.
- **FR-11** — `POST /api/review/:issueId/request` for an unmerged issue with no workspace
  answers before any approved-head, nudge or circuit-breaker shortcut: with an open
  pipeline-branch PR (read fresh from GitHub) it starts adoption in the background and
  answers `202` with `adopting: true`; with no such PR it answers
  `400 { error: 'Workspace does not exist', hint }`; when GitHub cannot be read it answers 503.
- **FR-12** — `createWorktree` fetches the feature branch from `origin` before checking
  whether it exists, so an unfetched remote branch is checked out, not re-cut from `main`.
- **FR-13** — `docs/PIPELINE-GATES.md` and `docs/MERGE-WORKFLOW.md` describe how a PR from
  outside a workspace enters the pipeline.

### Non-functional

- **NFR-1** — Adoption never runs `git push`, `git worktree add --force`, `git branch -D`,
  `git worktree remove`, or `removeWorkspace`.
- **NFR-2** — The webhook handler still never throws; every adoption error is caught and
  announced.
- **NFR-3** — No new `execSync` anywhere reachable from the dashboard server; all git
  calls use promisified `execFile` with argv arrays (CWE-78: no shell interpolation).
- **NFR-4** — `review-pipeline.ts` stays at or under 1000 lines;
  `derived-issue-state.ts` stays at or under 1000 lines.
- **NFR-5** — The derived loaders run `git worktree list --porcelain` at most once per
  loader call and only when some issue qualifies for the attention.
- **NFR-6** — Tests use real git in temp directories or injected deps; no real network,
  no real `bun install`, no real timers for delays.

Fix text (exact wording; `<ID>` upper-case, `<branch>` from `pipelineBranchFor`):

- With `worktreePath`:
  ``PR #<n> (<branch>) is checked out in <worktreePath>, so Overdeck cannot create the pipeline workspace and nothing has verified or reviewed it. When the session working there is finished, run `git -C <projectPath> worktree remove <worktreePath>`, then `pan review request <ID>`.``
- Without:
  ``PR #<n> (<branch>) was opened outside a pipeline workspace and nothing has verified or reviewed it. Run `pan review request <ID>` to adopt the branch into a workspace and start verification.``

3. If `ws` is null: `worktreePath = findBranchWorktree(await listWorktrees(), pipelineBranchFor(issueId), join(projectPath, 'workspaces', \`feature-${lower}\`))`;

### WI-4 — Adoption core (FR-2, FR-3, FR-4, FR-5, FR-6, NFR-1, NFR-3)

**New file:** `src/lib/cloister/pr-workspace-adoption.ts`.

```ts
export interface AdoptablePr {
  readonly issueId: string;       // upper-case
  readonly number: number;
  readonly headRef: string;
  readonly headSha: string | undefined;
  readonly repo: string;          // owner/name, for messages
}

export type AdoptionRefusal =
  | 'not-feature-branch' | 'head-unknown' | 'no-project' | 'polyrepo'
  | 'fetch-failed' | 'head-moved' | 'checked-out-elsewhere'
  | 'local-branch-diverged' | 'create-failed' | 'workspace-head-mismatch';

export type AdoptionOutcome =
  | { readonly adopted: true; readonly workspacePath: string }
  | { readonly adopted: false; readonly reason: AdoptionRefusal; readonly detail: string;
      readonly fix: string; readonly worktreePath?: string; readonly workspacePath?: string };

export interface AdoptionDeps {
  /** Runs git with argv; resolves trimmed stdout; rejects on non-zero exit. */
  git(args: readonly string[], cwd: string): Promise<string>;
  createWorkspace(issueId: string, project: { name: string; path: string }):
    Promise<{ success: boolean; workspacePath: string; errors: string[] }>;
  resolveProject(issueId: string):
    { projectPath: string; projectName: string; polyrepo: boolean } | null;
}

export async function adoptPrWorkspace(pr: AdoptablePr, deps?: Partial<AdoptionDeps>): Promise<AdoptionOutcome>;
```

Defaults: `git` = promisified `execFile('git', args, { cwd })` (stdout `.trim()`);
`createWorkspace` = dynamic `import('../workspace-manager.js')` →
`createWorkspace({ projectConfig: findProjectByPath(project.path) ?? project, featureName: issueId.toLowerCase() })`;
`resolveProject` = `resolveProjectFromIssueSync(issueId)` plus
`polyrepo: findProjectByPath(projectPath)?.workspace?.type === 'polyrepo'`
(`findProjectByPath`, `resolveProjectFromIssueSync` from `../projects.js`).

Steps, in this order (`lower = issueId.toLowerCase()`, `branch = pipelineBranchFor(issueId)`,
`canonical = join(projectPath, 'workspaces', \`feature-${lower}\`)`):

1. `pr.headRef !== branch` → `not-feature-branch`.
2. `!pr.headSha` → `head-unknown`.
3. `resolveProject` null → `no-project`; `polyrepo` → `polyrepo`.
4. `git fetch origin +refs/heads/<branch>:refs/remotes/origin/<branch>` in `projectPath`;
   rejection → `fetch-failed` (detail = error message).
5. `remote = git rev-parse refs/remotes/origin/<branch>`; `remote !== pr.headSha` → `head-moved`.
6. `git worktree prune`, then `findBranchWorktree(git worktree list --porcelain, branch, canonical)`;
   non-null → `checked-out-elsewhere` with `worktreePath`.
7. Local branch (D4): `local = git rev-parse --verify --quiet refs/heads/<branch>` (rejection ⇒ absent).
   - absent → `git branch --track <branch> refs/remotes/origin/<branch>`
   - `local === pr.headSha` → nothing
   - `git merge-base --is-ancestor <local> <pr.headSha>` resolves → `git update-ref refs/heads/<branch> <pr.headSha> <local>`
   - otherwise → `local-branch-diverged`
8. `createWorkspace(issueId, { name: projectName, path: projectPath })`. `success === false` →
   `create-failed` (detail = `errors.join('; ')`); if `existsSync(join(result.workspacePath || canonical, '.git'))`
   set `workspacePath` and append `workspace.adoption-failed`.
9. `head = git rev-parse HEAD` and `current = git branch --show-current` in the workspace;
   `head !== pr.headSha || current !== branch` → append `workspace.adoption-failed`, return
   `workspace-head-mismatch` with `workspacePath`. Remove nothing.
10. Append `workspace.adopted` (`source: 'pr-adoption'`, `data: { prNumber, headSha, repo }`),
    return `{ adopted: true, workspacePath }`.

`workspace.adoption-failed` entries carry `source: 'pr-adoption'` and
`data: { prNumber, reason, detail, fix }`.

Fix text per refusal (export `adoptionRefusalFix(reason, ctx)`; `<ID>` upper-case):

| Reason | Fix |
| --- | --- |
| `checked-out-elsewhere` | `prOutsidePipelineFix({ issueId, prNumber, projectPath, worktreePath })` |
| `head-moved` | ``The PR head moved while Overdeck was adopting it. Run `pan review request <ID>` to adopt the current head.`` |
| `local-branch-diverged` | ``Local branch <branch> (<local short sha>) has commits that are not in PR #<n>, and they may be unpushed work. Inspect them with `git -C <projectPath> log <headSha>..<branch>`, then either push them to the PR or move them to another branch, so <branch> matches the PR head. Then run `pan review request <ID>`.`` |
| `fetch-failed` | ``Overdeck could not fetch <branch> from origin (<detail>). Check the remote, then run `pan review request <ID>`.`` |
| `create-failed` | ``Creating the pipeline workspace failed: <detail>. Fix the cause, run `pan workspace create <ID>` (it resumes an unfinished setup), then run `pan review request <ID>`.`` |
| `workspace-head-mismatch` | ``The new workspace <workspacePath> is not at PR #<n>'s head. Inspect it, then run `pan review request <ID>`.`` |
| `polyrepo` | ``Overdeck does not adopt polyrepo branches automatically. Run `pan workspace create <ID>`, then `pan review request <ID>`.`` |

## Critique response

### Retry route can bypass adoption

Accepted. D7 and WI-7 now call `answerMissingWorkspace` immediately after the derived
state is read and before the approved-head force/nudge block and `requestReviewGuarded`,
so `tests-requeued`, `already-passed` and the circuit breaker can no longer answer for an

merged guard still answers. WI-5 tests the approved-PR case on the helper; WI-7's AC
checks the call order in the handler.

### PR lookup can falsely report no PR

Accepted. `findOpenPipelinePr` is now a fresh, branch-targeted
`gh pr list --head <branch> --state open` through `runGh` (never the cached repo listing)
and returns `found` / `none` / `error`; `answerMissingWorkspace` maps `error` to 503, never
to "no PR". For the derived attention, the webhook now calls
`refreshIssuePullRequestStateNow` (invalidate the repo listing + schedule a derived
refresh) on `opened`, `reopened`, `ready_for_review` and `closed`. Tests cover an empty
answer and a rejected forge read.

### Review start failure clears the alert

Accepted. After a successful adoption, a null starter or a `started: false` answer now
appends `workspace.adoption-failed` (`reason: 'no-starter'` / `'review-not-started'`, with
the starter's error text and a fix) to the adopted workspace's journal. The derived rule
already keys on that entry being last, so Needs you and `pan show` keep showing it until a
later `review.requested` supersedes it. WI-5 tests `dirty-workspace` and no-starter.

### A registry row can hide a missing workspace

Accepted. `pipelineWorkspacePath` now requires `.git` inside every candidate, the registry
row path included; a stale row whose directory is missing or not a worktree is ignored.
WI-3 adds a stale-row test.

### Diverged-branch fix can destroy commits
