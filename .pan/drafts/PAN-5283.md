# PAN-5283 — Flywheel page redesign: lane board, plain-language blockers, Needs-you action cards, health strip, shipped-today timeline

**Issue:** https://github.com/eltmon/overdeck/issues/5283
**Mode:** `pan plan --auto` (YOLO: the operator approved the redesign up front; the mockup guides the build and is never a gate).
**Related open work:** PAN-4666 (Flywheel `paneIsLive` drops Herdr `done` panes — this PRD absorbs its fix, see WI-3), PAN-5275 (whole Needs-you row clickable — in flight on `feature/pan-5275`, touches the same block, see H2).

## Glossary

- **Flywheel status** — the JSON `deriveFlywheelStatus()` returns (`src/lib/flywheel/derive-status.ts`, grep `export async function deriveFlywheelStatus`). Served by `GET /api/flywheel/status` (`src/dashboard/server/routes/flywheel.ts`, grep `'/api/flywheel/status'`) and printed by `pan flywheel status` (`src/cli/commands/flywheel.ts`). Schema: `FlywheelDerivedStatus` in `packages/contracts/src/flywheel-derived.ts`.
- **Status tab** — the `status` tab of the Flywheel rail on `/flywheel` (`src/dashboard/frontend/src/pages/FlywheelPage.tsx`, grep `tab === 'status'`). Its body today is `FlywheelHeadlineStrip` + `FlywheelStatusPane`. This issue replaces `FlywheelStatusPane`'s body.
- **Rail** — the left column of `FlywheelPage` (default 560 px, min 360 px; `SPLIT_DEFAULT_LEFT`, `SPLIT_MIN_LEFT`). The right column is the `conv-flywheel` conversation.
- **In-flight row** — one `FlywheelInFlightRow` in `status.inFlight`: the union of the project's `workspaces/feature-*` census and the ids in the newest tick's `in-flight=` list, minus merged/closed.
- **Card** — the new visual unit for one issue on the lane board.
- **Lane / stage** — the column a card sits in. In-flight stages: `plan`, `build`, `checks`, `review`, `merge`. Shipped lanes: `deploy` (merged today, not yet in the running dashboard build) and `done` (merged today and deployed, or deploy does not apply).
- **Blocker** — one plain-language sentence on a card explaining why it is not moving (or what it is waiting for), derived from existing facts. Structured as `{ kind, severity, text, action? }`.
- **Gate queue** — the machine-wide quality-gate admission directory `~/.overdeck/verification-workers/admission/` (`src/lib/cloister/quality-gate-admission.ts`, `admissionRoot()`): `owner.json` / `slot-<n>.json` are running gates, `waiter-<ticket>.json` are queued gates. A waiter ticket carries `workspacePath`, `gateName`, `createdAt`, `pid`, optional `issueId` and `footprintBytes`. **No wait reason is stored**; it is recomputed at read time (D9).
- **Soft reserve** — `resources.governor_soft_reserve_gb` (`resolveSoftReserveBytes()` in `src/lib/cloister/quality-gate-memory.ts`): memory gates must leave free.
- **Handoff conversation** — a `pan handoff` conversation tied to an issue: an unarchived `conversations` row with `issue_id` set, returned by `listIssueConversations(issueId)` (`src/lib/overdeck/conversations.ts`, grep `export function listIssueConversations`). Live example 2026-11-14: `20261114-d9c5` for PAN-5276, cwd `/home/eltmon/Projects/hoff-pan-5276`.
- **Owner** — who drives an issue: `flywheel`, `conversation` (a handoff conversation, named), or `operator`.
- **Health strip** — a single row of facts at the top of the Status tab that the global header (`src/dashboard/frontend/src/App/AppChrome.tsx` lines 203–222) does **not** show.
- **Global header items** (must not be repeated): `DeaconPauseToggle`, `RunningAgentsPill` (agent count), `StoppedAgentsBanner`, `LowCostModePill`, `StaleBuildChip`, `GitHubQuotaPill` (GitHub quota), `SystemHealthPill` (memory health), `DecisionsIndicator`, `NeedsYouIndicator` (Needs-you count).
- **Main CI verdict** — the newest **completed** push run of the `CI` workflow (`ci.yml`) on the project's default branch, from GitHub Actions.
- **Deployed build** — `getBuildInfo().buildCommit` (`src/lib/deploy/build-info.ts`) of the running dashboard server process.
- **Shipped today** — merges, deploys and releases since local midnight on the server host.
- **Herdr `done`** — Herdr's `agent_status: "done"`: the harness finished its turn and is alive at its prompt. It is NOT an exit (PAN-5011; `presenceForPaneState` in `packages/contracts/src/backend-pane.ts`).

## Problem (verified live on 2026-11-14, build d0c9b93efe2 and `pan flywheel status --json`)

Live: the tick named 7 ids, the census added PAN-5278 and PAN-5281.
2. **A live agent shows as "no agent".** Root cause confirmed: `paneIsLive` (`src/lib/flywheel/derive-status.ts` line 171) is
   ```ts
   function paneIsLive(pane: BackendPane): boolean {
     return pane.state !== 'exited' && pane.state !== 'done';
   }
   ```
   Live Herdr `pane list` showed `agent-pan-5275` (role `work`, issue `PAN-5275`) and `conv-20261114-cc68` (PAN-5277) with `agent_status: "done"`, and `pan show PAN-5275 --health` reported `alive=true`. Both rows reported `liveAgents: 0`. This is PAN-4666. Meanwhile PAN-5275's typecheck sat in the gate queue: the live admission dir held **9 waiter tickets and zero owners** (all slots empty, memory-blocked), e.g. `workspaces/feature-pan-5275 tsc:services/account/tsconfig.json`. No ticket carried `issueId`.
3. **Handoff work is invisible.** PAN-5276/5277/5279 run as handoff conversations in `~/Projects/hoff-pan-<n>` worktrees. Their gate tickets use those cwds, not `workspaces/feature-*`, so nothing ties them to the issue today. PR and journal show "—".
4. **Cryptic text.** `#5127 · none · green` (PR column), raw journal type `verification.failed`, titles truncated at `max-w-[18rem]`, a 4-column table that scrolls sideways in a 360 px rail.
5. **Needs-you items are text, not actions.**

## Goals

One screen that answers in two seconds: what is moving, what is stuck and why, what needs me.

## Requirements

### Functional

- **FR-1** — Every in-flight row carries `stage` (`plan|build|checks|review|merge`), `stageSince` (ISO or null), `owner`, `agent` (or null), `blocker` (or null), `cost` (USD number or null) and `lastActivity` (`{ at, label }` plain text, or null). Derived on read; nothing stored.
- **FR-2** — A pane counts as a live agent unless its state is `exited`; a `done` or `unknown` pane is confirmed through `isAlive()` from `src/lib/agents/liveness.ts` (PAN-4666).
- **FR-3** — A handoff conversation counts as the issue's agent: when the issue has no live work pane, the newest active `listIssueConversations` row becomes `agent` with `role: 'handoff'`.
- **FR-4** — A gate-queue waiter whose `issueId` or `workspacePath` maps to an in-flight issue gives that issue a `gate-queue` blocker such as `typecheck queued: 11.5 GB free, needs 2.2 GB, gates keep 12.0 GB (20 min)`. An issue with a queued gate never renders "no agent".
- **FR-5** — Blocker text is plain language and never a raw journal event name. `lastActivity.label` comes from an exhaustive `Record<PipelineJournalEntryType, string>` label map.
- **FR-6** — The board header count equals the number of in-flight cards (`status.inFlight.length`); a second number counts shipped-today cards (Deploy + Done lanes).
- **FR-7** — The Status tab renders a lane board: seven lanes in order Plan, Build, Checks, Review, Merge, Deploy, Done today. Each card shows the full title wrapped to at most 2 lines, issue id, time in stage, cost when known, an owner chip, the agent (role, model, state), the blocker line when present and the last activity label. Clicking a card opens the issue (existing `onNavigateIssue`).
- **FR-8** — Needs-you renders as action cards: question text, why (the first-raised tick message's prose excerpt), since (tick number + time + age), a jump-to-message action, and a real control where a structured source supplies one (test-removal waiver, start issue, answer agent → open issue). Free-text items get jump + link only.
- **FR-9** — The health strip shows only: main CI verdict + commit; deployed build vs that verdict ("deployed = main CI verdict" or "N commits behind"); gate queue (running, queued, oldest wait); next merge-train batch (members, status, or "batching paused until HH:MM"); last release tag. It shows none of the Global header items.
- **FR-10** — A Shipped-today timeline lists merges (first-parent commits on `origin/main` since local midnight whose subject ends `(#<n>)`), deploys (successful `pan reload` entries in `restart-events.jsonl` since midnight) and releases (tags `v*` created since midnight), newest first, each linked to its issue or PR.
- **FR-11** — `pan flywheel status` prints the blocker text instead of the bare `no agent` suffix, so the CLI and page agree.
- **FR-12** — The page has no horizontal page scroll at 360 px rail width and at 390 px phone width, in light and dark themes.

### Non-functional

- **NFR-1** — No new stored status, table, file or column. In-memory memo caches of derived reads are allowed (D6).
- **NFR-2** — No new frontend polling: no new `refetchInterval` under `src/dashboard/frontend/src/components/flywheel/`; all new data rides `GET /api/flywheel/status`, which the page already polls at 5 s (`useFlywheelStatus`, `src/dashboard/frontend/src/lib/flywheelApi.ts` line 31).
- **NFR-3** — No `execSync`/`spawnSync` in any code reachable from the server; git reads use promisified `execFile`.
- **NFR-4** — All contract changes are additive optional fields; existing consumers (`NeedsYouIndicator`, `FlywheelPage` reveal selectors `[data-testid="flywheel-needs-you"]` and `[data-attention="needs-you"]`, CLI printer) keep working.
- **NFR-5** — Health and shipped-today reads hit the forge at most once per 60 s (memo), and the per-poll row additions are local reads only (sqlite, small files).
- **NFR-6** — Style follows `pan-style-guide`: no pill badges, no decorative color, "running is not green" (a working agent is `info`, never `success`).

## Decisions (made here; the executor does not re-decide)

- **D1 Stage rule** (first match wins), in `deriveStage()`:
  1. row is a member of a pending auto-merge (`status ∈ {pending, merging, blocked, failed}`) or of a window-lane generation (`status ∈ {assembling, ready}`) → `merge`;
  2. `state === 'ready'` → `merge`;
  3. verification in flight (the newest `verification.*` journal entry is `verification.started` and nothing newer of `verification.passed|verification.failed`) **or** the issue has a gate-queue waiter or owner → `checks`;
  4. `state ∈ {in-review}` → `review`;
  5. `state ∈ {working, changes-requested}` → `build`;
  6. otherwise (`backlog|planned|parked`, or a live `plan` pane) → `plan`.
- **D2 stageSince** = `at` of the newest journal entry that enters the chosen stage: `checks` ← `verification.started` (or the oldest gate ticket `createdAt` if newer); `build` ← newest of `verification.failed|feedback.delivered|handoff.started|workspace.adopted|review.verdict`; `review` ← newest of `verification.passed|review.requested|review.dispatched|review.redispatched`; `merge` ← the pending auto-merge `scheduledAt`, else the generation `createdAt`, else newest `merge.attempted`; `plan` ← the live plan pane's `stateSince` (epoch ms → ISO), else null. Null renders no time.
- **D3 Owner rule**: `flywheel` when `inTick` is true or the issue's work agent `startedBy` starts with `flywheel:` (`isFlywheelStartedBy`, `src/lib/agents/provenance.ts`); else `conversation` `{ name, title }` from the newest unarchived `listIssueConversations` row; else `operator`. `planning-auto-handoff` and `operator:*` are operator origins (docs/FLYWHEEL.md). A `pan start` from a non-flywheel conversation stamps no conversation name, so it reads `operator` — attributing it is a NonGoal.
- **D4 Agent rule**: prefer the live `work` pane for the issue, then any other live issue pane (`worker`, `review`, `test`, `uat`, `strike`, `plan`, `conversation`), then the newest active handoff conversation (FR-3). Agent `state` is the pane state mapped `working|blocked → working/blocked`, `idle|done → idle`, `unknown → unknown`; when the issue has a gate-queue waiter, state is `waiting`. `role: 'handoff'` for a conversation pane or conversation row.
- **D5 Liveness (PAN-4666)**: `exited` → dead; `working|blocked|idle` → live; `done|unknown` → `isAlive(paneAgentKey(pane))` from `src/lib/agents/liveness.ts`; live when `verdict.alive` or `verdict.reason === 'runtime-indeterminate'`. Probed at concurrency 4 via the injectable dep `isAgentAlive`. A probe that throws counts as live (never drop a possibly-live agent).
- **D6 Caching**: the route memoizes `deriveFlywheelHealth()` per project root for 30 s and the CI-verdict forge read for 60 s, both in module-level `Map`s in `src/lib/flywheel/health.ts` with an injectable clock. The memo is a derived cache, not status (NFR-1).
- **D7 Health and shipped-today are server-only**: they live in `src/lib/flywheel/health.ts` (`deriveFlywheelHealth`), called by the route and merged into the payload as optional `health` and `shipped` fields. `pan flywheel status` does not compute them (CLI JSON simply lacks the fields).
- **D8 Main CI verdict source**: GitHub REST `repos/<github_repo>/actions/workflows/ci.yml/runs?branch=<default branch>&event=push&status=completed&per_page=1` through `projectCiGhApi` (`src/lib/ci/project-ci-github.ts`). The read-model `ciByProjectKey` only keeps the current head and loses the previous verdict when a new head starts (`packages/contracts/src/event-reducers.ts` lines 679–722), so it cannot answer "newest concluded". When the project has no `github_repo`, the field is null and the strip omits it.
- **D9 Gate wait reason (recomputed at read)** per waiter, in order: `owners.length >= slots` → `slots`; the ticket has `footprintBytes` and `memAvailable − Σ owners.footprintBytes − footprint < softReserve` → `memory`; an older waiter exists → `queue`; else `cpu`. Texts:
  - memory: `<gate> queued: <free> GB free, needs <need> GB, gates keep <reserve> GB (<age>)`
  - slots: `<gate> queued: <n>/<slots> gate slots busy (<age>)`
  - queue: `<gate> queued behind <k> other gate(s) (<age>)`
  - cpu: `<gate> queued: waiting for CPU to settle (<age>)`
  GB = bytes / 1024³ with one decimal, the same math as `bytesToGb` in `src/dashboard/server/services/system-health-service.ts`. `<age>` = `<m> min` (`<1 min` under 60 s, `<h> h <m> min` ≥ 60 min). Gate label: `vitest` → `tests`; `tsc:tsconfig.json` → `typecheck`; `tsc:<path>` → `typecheck (<path>)`; `gate:<name>:…` → `<name>`; anything else verbatim. Multiple waiters for one issue: the oldest one's text plus ` +<n> more`.
- **D10 Waiter → issue mapping**: `ticket.issueId` (upper-cased) when present; else the longest candidate path that equals or is a parent of `ticket.workspacePath`, where candidates are each in-flight row's workspace path and the `cwd` of every active handoff conversation for that issue; else the regex `/(?:feature|hoff)-([a-z]+-\d+)(?:-strike)?(?:\/|$)/i` on the path. Unmapped waiters still count in the health strip.
- **D11 Blocker precedence** (first match wins) in `deriveBlocker()`; severities in brackets:
  1. gate-queue waiter (D9) [waiting]
  2. `attention: 'needs-you'` → `agent is waiting for your answer` [needs-you, action `answer-agent`]
  3. `attention: 'api-error'` → `agent hit a provider error (rate limit or outage)` [stuck]
  4. `attention: 'work-not-started'` → `auto-start failed: <workStart.error ?? 'no work agent came up'>` (+ `, retrying at HH:MM` when `workStart.nextRetryAt`) [needs-you, action `start-issue`]
  5. `attention: 'pr-outside-pipeline'` → first sentence of `prOutsidePipeline.fix` [needs-you]
  6. `attention: 'stuck'` → `agent idle with unpushed commits` [stuck]
  7. newest `verification.failed` newer than any `verification.passed|verification.started`: `data.failedCheck === 'test-skip'` → `test-skip gate failed: needs your test-removal waiver` [needs-you, action `waive-test-removal`]; `data.via === 'ci'` → `CI tests failed on PR #<data.prNumber>` + suffix; else `<failedCheck> check failed (round <cycleCount>)` + suffix. Suffix = `, agent fixing` when an agent is live, else `, no agent running`. [stuck]
  8. newest entry is `feedback.undelivered` → `review feedback not delivered` (`CodeRabbit feedback not delivered` when `data.kind` or `data.reason` contains `coderabbit`, case-insensitive) [stuck]
  9. newest entry is `merge.failed` → `merge failed: <data.reason>` (or `merge failed`) [stuck]
  10. pending auto-merge row: `pending` → `auto-merge at HH:MM`; `merging` → `merging now`; `blocked|failed` → `auto-merge blocked: <failureReason first 120 chars>` [waiting / waiting / stuck]
  11. window-generation member → `in train batch <name without uat/ prefix> (<n> PRs), waiting for batch CI` [waiting]; when `projectBatchCiPausedUntil` is non-null and the row is `ready` → `train batching paused until HH:MM; merges one at a time` [waiting]
  12. `pr.checks === 'red'` → `CI red on PR #<n>` + suffix [stuck]
  13. `pr.mergeable === false` → `merge conflict with main` [stuck]
  14. newest entry is `blocked.declared` → `blocked: waits on <data.blockers joined ', '>` [stuck]
  15. newest entry is `review.stalled|review.stall-escalated` → `review stalled` [stuck]
  16. `stage ∈ {build, checks, review}` and no agent → `no agent running` [stuck]
  Else null. HH:MM is server-local 24 h time. A blocker with severity `waiting` is not "stuck".
- **D12 Shipped lanes**: Deploy and Done-today cards come from `health.shipped.merges` (D7), not from `inFlight` (merged rows are already filtered out of `inFlight`). A merge is `deployed: true` when it is not in `git rev-list <buildCommit>..origin/main`; `deployed: null` when deploy does not apply (D13). Deploy lane = `deployed === false`; Done lane = the rest.
- **D13 Deploy applicability**: the deployed-build comparison, the Deploy lane and deploy timeline events apply only when `buildCommit` is non-null and `git -C <projectRoot> cat-file -e <buildCommit>^{commit}` succeeds (the flywheel's project is the dashboard's own repo). Otherwise those fields are null and the UI omits them.
- **D14 Needs-you buttons come only from structured sources**: row blockers with `action` (`waive-test-removal` → embed the existing `TestRemovalWaiverControl` from `src/dashboard/frontend/src/components/CommandDeck/SessionView/TestRemovalWaiverControl.tsx`; `start-issue` → a two-step `Start` / `Confirm start` button that POSTs `/api/agents` with `{ issueId }` and `dashboardMutationJsonHeaders()`, the body `useIssueActions` sends for `startAgent`; `answer-agent` → `Open <ID>` calling `onNavigateIssue`). Free-text tick items get the jump action and, when present, their target link. A tick item that names an in-flight issue id with a structured action renders as **one merged card** (tick text as the question, the row's action attached). Restart approval is not duplicated: the global `RestartApprovalBanner` owns it.
- **D15 Lane layout in the rail**: lanes stack vertically (a lane = heading `Build · 3` + its cards). Empty lanes render only their heading with a muted `—`. No horizontal scrolling anywhere.
- **D16 Phone layout**: below Tailwind `md` (768 px) `FlywheelPage` stacks the rail above the conversation column (`flex-col md:flex-row`), the resize separator is hidden, the rail is full width; the left width applies only at `md` and above via a CSS variable (`style={{ '--fw-left': \`${leftWidth}px\` }}` + `md:w-[var(--fw-left)]`).
- **D17 Header**: page header text becomes `<N> in flight · <M> shipped today` where N = `status.inFlight.length` and M = Deploy + Done cards; `inFlightCountLabel` returns the same string and is reused by the board heading. The `(loop)` / `feature workspaces` wording is retired; the owner chip shows which cards the loop drives.
- **D18 Needs-you "why"**: `resolveNeedsYouItems` attaches `context` = the first-raised tick message's text with every line containing `flywheel-tick:` removed, whitespace-collapsed, last 280 characters (prefixed `…` when cut). Absent when empty.
- **D19 Mockup**: an interactive static HTML mockup at `.tmp/pan-5283-flywheel-mockup/index.html` (gitignored), filled with the live 2026-11-14 snapshot shapes, screenshotted with Playwright at 560 px rail (1440 px viewport) and 390 px phone, light and dark, into `docs/screenshots/pan-5283/mockup-{rail,phone}-{light,dark}.png`. It is never a gate.
- **D20 Final screenshots**: a Playwright spec `src/dashboard/frontend/tests/pan-5283-flywheel-board.spec.ts` against the isolated dashboard fixture (`tests/fixtures/isolated-dashboard.js`, pattern from `pan-4523-river-bands.spec.ts`), with `page.route('**/api/flywheel/status', …)` serving a fixture payload, writes `docs/screenshots/pan-5283/board-{rail,phone}-{light,dark}.png` and asserts no horizontal scroll and header count = card count. Theme is seeded via `localStorage['overdeck.ui.theme']` (docs/SCREENSHOTS.md). The PR body links the committed PNGs.
- **D21 Cost**: `getCostForIssueAggregate(id)?.totalCost` (`src/lib/overdeck/cost-sync.ts` line 408) when > 0; else the sum of the issue's handoff conversations' `totalCost` when > 0; else null. Rendered `$4.12` (two decimals).
- **D22 Journal reads**: a new dep `journalTail(workspacePath)` returns `readPipelineJournal(ws, { limit: 50 })`; `lastJournal` stays as a dep (existing tests inject it) and, when `journalTail` is not injected but `lastJournal` is, the tail is `[lastJournal()]`. Same cost as today's `lastPipelineEntry`, which already reads the whole file.
