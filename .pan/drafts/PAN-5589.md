# PAN-5589: Gate admission counts CPU-pinned workloads as host pressure

**Issue:** [PAN-5589](https://github.com/eltmon/overdeck/issues/5589)
**Related:** [PAN-5588](https://github.com/eltmon/overdeck/issues/5588) (CPU bypass bound restarts for every head; in work, same files), PAN-5520 (bounded CPU wait), PAN-4311 (PSI-based admission).

## Glossary

- **Quality-gate admission:** the machine-wide FIFO queue in `src/lib/cloister/quality-gate-admission.ts` that every local gate, direct Vitest run and `tsc` lane enters before it starts. Files live under `~/.overdeck/verification-workers/admission/`.
- **Pressure sample:** the value `sampleQualityGatePressure()` returns: `{ cpuUtilization, loadPerCore, psiSomeAvg10, pressured }`. A gate is admitted only when `pressured` is `false` both before and 1.5 s after it takes a slot.
- **cpuUtilization:** whole-machine busy fraction (0-1) over a 250 ms window, computed from `os.cpus()` times summed across every core.
- **PSI `some avg10`:** Linux CPU Pressure Stall Information (`/proc/pressure/cpu`), the percentage of the last 10 s in which at least one runnable task waited for a CPU. It is system-wide.
- **Load per core:** 1-minute load average divided by core count. The fallback contention signal when PSI is unavailable (macOS, old kernels).
- **Contention signal:** PSI `some avg10 >= psiStartAvg10` (or, without PSI, load per core `>= 1`).
- **Pinned workload:** a process whose CPU affinity mask (`taskset -c 20-23`) or cgroup CPU quota limits it to a few cores. Its runnable tasks queue on those cores and raise PSI and load, while other cores sit idle.
- **Contended-utilization floor:** the new constant `QUALITY_GATE_CONTENDED_UTILIZATION_FLOOR = 0.5`. Below it, the contention signal is ignored.
- **File-size cap:** `scripts/lint-file-size.sh` fails any non-test `src` file over 1000 lines (no allowlist row exists for the admission module). `quality-gate-admission.ts` is 997 lines on `origin/main` at writing time.

## Problem

On a 24-core host, a non-Overdeck service ran 7 `ffmpeg -preset slow` encodes pinned with `taskset -c 20-23` and `nice 15`. cpu20-cpu23 were at 100 %, most other cores at 3-30 %, the machine 37 % busy. Seven runnable tasks sharing four cores pushed PSI `some avg10` to 33-37 and the load average to about 33. Gate tickets reported `{"kind":"cpu","sample":{"cpuUtilization":0.44,"loadPerCore":1.21,"psiSomeAvg10":35.03,"pressured":true}}`. Gates waited on "CPU pressure" for over an hour while 20 cores were free. With PAN-5588 this held four work agents to about one gate every 10 minutes.

## Root cause (verified)

`src/lib/cloister/quality-gate-admission.ts`, lines 247-270 (search for `export async function sampleQualityGatePressure`):

```ts
  const psiSomeAvg10 = (await readPsi()).someAvg10
  const contended = psiSomeAvg10 != null
    ? psiSomeAvg10 >= psiStartAvg10
    : loadPerCore >= QUALITY_GATE_LOAD_PER_CORE_START_THRESHOLD
  return {
    cpuUtilization,
    loadPerCore,
    psiSomeAvg10,
    pressured: cpuUtilization >= QUALITY_GATE_CPU_START_THRESHOLD || contended,
  }
```

The thresholds are at lines 47-50 (search for `const QUALITY_GATE_CPU_START_THRESHOLD = 0.75`):

```ts
const QUALITY_GATE_CPU_START_THRESHOLD = 0.75
const QUALITY_GATE_LOAD_PER_CORE_START_THRESHOLD = 1
// PAN-4311 D10: with CPU PSI available, start heavy runs only once `some avg10` is below the
// configured start threshold. Load per core counts IO wait, so it is the fallback only without PSI.
```

PSI and load are system-wide. They count every task that waits for a CPU, including tasks that wait only because their affinity mask or cgroup quota restricts them. A new gate is not restricted by that mask, so that stall does not apply to it. `contended` alone makes `pressured` true even when most cores are idle.

`grep -rn "pressured" src --include=*.ts` confirms this is the only implementation of the gate rule; `tests/vitest-cpu-admission.ts` and `scripts/tsc-admitted.mjs` call into it and carry no copy of the rule.

## Decisions

- **D1 — The rule.** `pressured = cpuUtilization >= 0.75 || (cpuUtilization >= 0.5 && contended)`. When utilization is below 0.5, at least half the machine is idle, so one more gate has CPUs to run on whatever PSI says. The 0.75 trigger stays unchanged and independent.
- **D2 — Same floor for the load fallback.** Load per core has the same system-wide flaw, so the floor also gates the load-average branch.
- **D3 — The floor is a constant, not a config key.** The issue names a constant of `0.5`. No `resources.*` key is added.
- **D4 — Extract the decision to `quality-gate-cpu.ts`.** The admission module is 997 lines and capped at 1000. The issue also asks for a header paragraph there. So the three thresholds and a pure function `isQualityGateCpuPressured()` move into `src/lib/cloister/quality-gate-cpu.ts` (36 lines, already imported by the admission module, imports nothing from it). `sampleQualityGatePressure` and `cpuTotals` stay where they are, because the test file imports `sampleQualityGatePressure` from the admission module, and PAN-5588 is editing the admission module's imports and file helpers. Moving less keeps the conflict surface small.
- **D5 — The pure function takes a structural type.** `isQualityGateCpuPressured(reading: { cpuUtilization: number; loadPerCore: number; psiSomeAvg10: number | null }, psiStartAvg10: number): boolean`. It does not import `QualityGatePressureSample` from the admission module, so no import cycle can form (`npm run lint:circular`).
- **D6 — Extraction first, behavior change second.** Work item 1 is a behavior-preserving move (all existing tests pass byte-for-byte unchanged). Work item 2 adds the floor. This keeps each diff reviewable on its own.
- **D7 — Three existing sample tests change.** The `sampleQualityGatePressure (PAN-4311)` describe block in `tests/unit/lib/cloister/quality-gate-admission.test.ts` runs every case at 0 % utilization. Three cases assert `pressured: true` from PSI or load alone, which is exactly the behavior this issue removes. They are rewritten in place to run at 60 % utilization, so they still prove the PSI threshold, the configured threshold and the load fallback. They are never deleted or skipped. Every other admission test (the queue, slot, memory, fairness, bypass and queue-snapshot describes) injects `samplePressure` and stays byte-for-byte unchanged. This is how the issue's "existing admission tests pass unchanged" is read.
- **D8 — New header paragraph, not an edit of PAN-5520's.** The module-header rule is added as its own paragraph after the PAN-5520 paragraph. The PAN-5520 lines are not edited, because PAN-5588 edits that paragraph.
- **D9 — Scope is gate admission only.** `src/lib/cloister/cpu-pressure.ts` (`assessCpuPressure`, PSI `some avg60` for lane launches, agent-start warnings and the opt-in Flywheel hold) has the same system-wide signal but is out of scope.

## Requirements

- **FR-1:** `sampleQualityGatePressure` returns `pressured: false` when PSI `some avg10` is at or above the start threshold and `cpuUtilization` is below 0.5.
- **FR-2:** `sampleQualityGatePressure` returns `pressured: true` when PSI `some avg10` is at or above the start threshold and `cpuUtilization` is at or above 0.5.
- **FR-3:** `sampleQualityGatePressure` returns `pressured: true` whenever `cpuUtilization` is at or above 0.75, whatever PSI or load say.
- **FR-4:** Without PSI (`psiSomeAvg10: null`), load per core at or above 1 counts as contention only when `cpuUtilization` is at or above 0.5.
- **FR-5:** The configured `resources.quality_gate_psi_start_avg10` threshold still applies inside the floor.
- **FR-6:** The module header of `quality-gate-admission.ts` states that PSI alone is not pressure, and why.
- **FR-7:** `docs/PIPELINE-GATES.md`, `configuration/memory-governor.mdx` and the `quality_gate_psi_start_avg10` doc comments state the floor rule; `changelog.d/pan-5589.md` records the fix.
- **NFR-1:** `src/lib/cloister/quality-gate-admission.ts` stays at or under 1000 lines (`bash scripts/lint-file-size.sh` passes).
- **NFR-2:** No import cycle: `quality-gate-cpu.ts` imports nothing from `quality-gate-admission.ts` (`npm run lint:circular` passes).
- **NFR-3:** The pressure sample's shape (`QualityGatePressureSample`) and the `cpu` wait-reason ticket format are unchanged, so status readers and older checkouts sharing the admission root keep working.
