# PAN-5516: `pan conversations resume` fails locally with "Missing origin"

Issue: https://github.com/eltmon/overdeck/issues/5516
PR: https://github.com/eltmon/overdeck/pull/5525 (implementation already pushed; this PRD records it)

## Glossary

- **Internal token:** the per-machine secret the CLI sends in `INTERNAL_TOKEN_HEADER` through `callDashboard` (`src/cli/commands/dashboard-call.ts`). It resolves to the credential kind `internal-token` in `resolveDashboardCredential` (`src/dashboard/server/routes/dashboard-auth.ts`).
- **Origin check:** `validateOriginHeaders` (`src/dashboard/server/routes/origin-validation.ts`). It refuses a write with no `Origin` and no `Referer` (`Missing origin`) unless it carries an `odk_` bearer.
- **`crossSiteWriteRefusal`:** the check in `src/dashboard/server/linked-conversation-proxy.ts`. A write with a valid internal token or access token (kinds `internal-token`, `token`) skips the Origin check; any other write runs `validateOriginHeaders`. GET and HEAD always pass.
- **Conversation key:** the `:name` segment of `/api/conversations/:name/...`. Three forms name the same row: the numeric rowid (`3989`), the stored name (`20261117-32dc`) and the session name (`conv-20261117-32dc`).
- **`resolveConversationKey`:** `src/lib/overdeck/conversation-reads.ts`. Digits resolve by id; otherwise by stored name, then by session name (`getConversationByTmuxSession` strips `conv-`).

## Problem

`pan conversations resume` posts through `callDashboard` with the internal token and no Origin. `postConversationResumeRoute` (`src/dashboard/server/routes/conversations.ts`) ran `validateOrigin(request)`, so every CLI resume got 403 `Missing origin`. The route also passed `:name` straight to `handleConversationResume`, which looks up only the stored name, so `3989` and `conv-20261117-32dc` answered 404.

## Requirements

- **FR-1:** A POST to the resume route carrying a valid internal token and no Origin is admitted.
- **FR-2:** A POST to the resume route with no credential and no Origin is refused with 403 `Missing origin`; a wrong internal token is refused the same way.
- **FR-3:** The resume route accepts the numeric id, the stored name and the `conv-` session name, and calls `handleConversationResume` with the stored name.
- **FR-4:** An unknown key reaches the handler unchanged, which answers 404.
- **NFR-1:** No new credential rule: reuse `crossSiteWriteRefusal`. No change to `validateOriginHeaders` (a cycle: `dashboard-auth.ts` imports `origin-validation.ts`) or to other routes.

## Work items

1. **resume-origin (FR-1, FR-2, NFR-1).** In `postConversationResumeRoute`, replace the `validateOrigin(request)` block with `const refused = crossSiteWriteRefusal(request.headers as HeaderMap, request.method); if (refused) return refused;`, importing `crossSiteWriteRefusal` from `../linked-conversation-proxy.js`. Tests: `conversations-resume-route.test.ts` cases "admits a POST that carries only the internal token", "refuses a POST with no credential and no Origin", "refuses a POST with a wrong internal token and no Origin".
2. **resume-identifiers (FR-3, FR-4).** Export `resolveConversationKey` and in the route compute `const name = resolveConversationKey(key)?.name ?? key;` before calling `handleConversationResume(name, ...)`. Tests: "resolves the stored name", "resolves the numeric conversation id", "resolves the conv- session name", "passes an unknown identifier through unchanged".
3. **changelog (docs).** Add `changelog.d/pan-5516.md` with one `#### Fixed` bullet, no em dashes. No other documented surface changes: the route path, its scope (`operate`) and the CLI verb are unchanged.
