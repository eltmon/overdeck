# PAN-4255 — Change effort live on claude-code sessions, and show the effective effort with its source

**Issue:** [PAN-4255](https://github.com/eltmon/overdeck/issues/4255) (slice S3 of [PAN-4249](https://github.com/eltmon/overdeck/issues/4249))
**Foundation:** PAN-4249 (`packages/contracts/src/effort.ts`, `src/lib/agents/resolve-effort.ts`), S1 PAN-4253 (`AgentState.effort`/`effortSource`, `src/lib/agents/relaunch-effort.ts`), S2 PAN-4254 (conversation effort doors, `src/lib/overdeck/conversation-effort.ts`, `GET /api/effort/default`). All three are merged on `main`.
**Mode:** planned with `pan plan --auto`. Every choice that would have been a question is in [Decisions](#decisions) and in `plan.autoDecisions` of the xBRIEF.

## Summary

Today a claude-code conversation cannot change effort from the dashboard. `POST /api/conversations/:name/thinking-level` answers 400 for claude-code, the composer effort picker is disabled with the tooltip "Change effort in the native terminal for this session.", and the chip reads **"Effort unverified"** for almost every claude-code session. Work agents have no live-change API at all.

This issue:

1. Delivers `/effort <level>` to a running claude-code session through the terminal backend, waits until the session transcript confirms the change, and only then persists the new level (conversation row or agent state).
2. Adds `POST /api/agents/:id/effort` so work agents (and any other claude-code agent) get the same live change, persisted to `AgentState` so S1's relaunch pin keeps it.
3. Removes "Effort unverified". The chip shows the effective level and its source (`High · default`, `Low · set`, `Max · terminal`). "Observed" is a separate, factual flag: the level was read from the session transcript.

## Glossary

- **Effort** — a canonical reasoning-effort level: `low`, `medium`, `high`, `xhigh`, `max` (`EFFORT_LEVELS` in `packages/contracts/src/effort.ts`).
- **Live change** — changing the effort of a session that is already running, without a relaunch.
- **`/effort <level>`** — Claude Code's built-in slash command. Verified on Claude Code 2.1.284 in this planning session (see [Empirical facts](#empirical-facts-verified-2026-10-03)).
- **Confirmation record** — the transcript line Claude Code writes after `/effort`: a `type: "user"` JSONL record whose `message.content` is a string starting with `<local-command-stdout>Set effort level to <level> (`.
- **Observed effort** — an effort level read from the session transcript: the `effort` field on an assistant record, or the level in the latest confirmation record. Only claude-code transcripts carry it (Claude Code ≥ 2.1.280).
- **Resolution** — the level Overdeck launched or stored, plus its `EffortSource` layer (`explicit`, `item`, `plan`, `tier`, `sub-role`, `role`, `project`, `default`), as returned by `resolveEffort`/`resolveRelaunchEffort`.
- **Chip** — the effort button in the composer toolbar (`EffortPicker`).
- **Chip source** — the word after the `·` in the chip: the resolution's source, or `terminal` when the observed level differs from the resolution (someone ran `/effort` in the native terminal).
- **Door** — an HTTP endpoint that performs a state-changing action.
- **Pane** — the terminal-backend (Herdr or tmux) pane that runs the harness. Conversations address it by `conv.tmuxSession`; agents by their agent id.

## Empirical facts (verified 2026-10-03)

Probed with an isolated `CLAUDE_CONFIG_DIR` and a throwaway tmux socket, Claude Code 2.1.284, launched exactly as Overdeck launches (`claude --model claude-opus-5-5 --effort high`):

1. `/effort low` **applies even though the session was launched with `--effort high`**. The pane prints `Set effort level to low (saved as your default for new sessions): Quick, straightforward implementation…`.
2. The transcript gets three records: a `<local-command-caveat>` meta record, a user record `"<command-name>/effort</command-name>\n            <command-message>effort</command-message>\n            <command-args>low</command-args>"`, and the confirmation record `"<local-command-stdout>Set effort level to low (saved as your default for new sessions): …</local-command-stdout>"`. No assistant turn is needed.
3. `/effort max` prints `Set effort level to max (this session only): …`.
4. `/effort bogus` prints `<local-command-stdout>Invalid argument: bogus. Valid options are: low, medium, high, xhigh, max, auto, ultracode [on|off]</local-command-stdout>`. Other failure strings in the binary: `Failed to set effort level: …`, `Not applied: CLAUDE_CODE_EFFORT_LEVEL=…`.
5. **Side effect:** for `low`/`medium`/`high`/`xhigh`, Claude Code writes `modelSettings.<model>.effortLevel` into the user's `~/.claude/settings.json` ("saved as your default for new sessions"). `max` is session-only. Overdeck always passes `--effort` on launch, so Overdeck sessions are not affected; the operator's own interactive `claude` sessions of that model are.
6. Every assistant record carries top-level `"effort":"<level>"` and `"perTurnEffort":"<level>"` (Claude Code ≥ 2.1.280; 2.1.266 and older have neither). After `/effort low`, the next assistant record had `effort: "low"`. This is the observed signal.
7. While the session is still starting (notices on screen) a paste can be lost. The first paste in the probe did not land; a second one after the prompt was ready did.
8. Records whose text starts with `<` are filtered out of the dashboard timeline (`src/dashboard/server/services/conversation/message-filters.ts:11`, `if (text.startsWith('<')) return true;`), so the `/effort` records do not render as operator messages.

## Decisions

- **D1 — Confirmation is the confirmation record, not a turn.** After delivery, read the session transcript from the pre-delivery byte offset. The first user record whose string content contains `<local-command-stdout>` and either `Set effort level to <level>` (success) or `Invalid argument:` / `Failed to set effort level` / `Not applied:` (rejection) decides the result. Success persists the level Claude Code printed, which may differ from the request if Claude Code capped it. Nothing within 10 s → `not-confirmed`, nothing persisted.
- **D2 — Refuse when affirmatively busy.** Before delivering, call `waitForAgentIdle(paneId, 5000)`. If it returns false **and** the runtime mirror affirmatively says the session is working (`getAgentRuntimeStateSync(paneId)?.state === 'active'`), answer 409 `busy` and deliver nothing. Unknown or missing mirror state (a conversation that has never had a turn may have none; `waitForAgentIdle` on tmux only returns true for a mirror `idle`) is treated as not busy, matching `messageAgent`, which warns and sends (`messaging.ts:745-749`). Reason for refusing a busy session: Claude Code queues typed input during a turn, so a delivered `/effort` could run after the 10 s window and change effort without Overdeck persisting it.
- **D2a — Never paste into a permission prompt (PAN-4278).** The core reads the pane once with `resolveAgentPaneIo(paneId).read(PANE_CAPTURE_LINES)` and refuses with 409 `permission-pending` when `parsePermissionPrompt(text)` is non-null, before `ensureMainInputTarget` (whose Down/Enter would answer the prompt). An unreadable pane counts as no prompt. This applies to both doors, because the agent message path has no such guard today.
- **D3 — Reuse the claude-code delivery prelude, in one core.** Both doors call `applyClaudeLiveEffort`, which runs: busy check (D2) → pane permission check (D2a) → `ensureMainInputTarget(paneId)` (409 `input-target-not-main`) → transcript snapshot → `deliverAgentMessage(paneId, '/effort <level>', caller, deliveryMethod)`. Conversations pass `paneId = conv.tmuxSession` and `resolveConversationDeliveryMethod(conv)`; agents pass the agent id and the supervisor rule from `messaging.ts:784-786`. No change to `delivery.ts`.
- **D4 — Clamp before delivery.** The requested level goes through `resolveEffort({ explicit: level, model, harness: 'claude-code' })` first, so `/effort` is sent with a level the model supports. A clamp warning is returned in the response as `warning`.
- **D5 — Do not touch `~/.claude/settings.json`.** Claude Code saves non-`max` levels as the per-model default (fact 5). Restoring the file would race Claude Code's own write and could make a running Claude Code reload settings and undo the live change. Overdeck sessions always launch with `--effort`, so they are unaffected. The side effect is documented in `configuration/effort.mdx` and stated in the chip tooltip when the picker is enabled for claude-code.
- **D6 — Observed effort travels in `ContextUsage.lastEffort`.** It sits beside `lastModel` and flows through the HTTP messages read, the WebSocket transcript deltas, and the conversation detail read with no new transport. Its value is the latest, in file order, of: an assistant record's `effort` (fallback `perTurnEffort`), or the level in a confirmation record. Records with `isSidechain: true` are ignored. The parser keeps it across incremental calls and does **not** reset it at a compact boundary (effort survives compaction).
- **D7 — Agents get observed effort and resolution on the agent conversation response.** `GET /api/agents/:id/conversation` adds `observedEffort: EffortLevel | null` (from the parse result) and `effortResolution: { effort, source } | null` (from `resolveRelaunchEffort(state)` when the agent state exists). The Command Deck `SessionNode` is not changed (file-size limit, and agent-row display belongs to S7 [PAN-4259](https://github.com/eltmon/overdeck/issues/4259)).
- **D8 — Chip source vocabulary.** The chip shows `<Level> · <source>`, where source is one of `set` (`explicit`), `item`, `plan`, `tier`, `sub-role`, `role`, `project`, `default`, or `terminal`. `terminal` means the observed level differs from the resolution. A separate `observed` flag (tooltip and `data-observed` attribute) says whether the level was read from the transcript. The word "verified"/"unverified" is not shown.
- **D9 — Conversation resolution without a schema change.** A conversation whose `effort` column is set resolves to `{ effort: conversation.effort, source: 'explicit' }`. A conversation with `effort: null` that has a session (`sessionAlive || claudeSessionId`) resolves through the existing `fetchEffortDefault({ model, harness, issueId })`, which returns the same `resolveEffort` chain the launcher used. No `effort_source` column is added. Accepted limit: S2's composers send an effort on create, so most new conversations read `set`.
- **D10 — Live change persists as `explicit`.** Conversations: `setConversationEffort(name, confirmedLevel)`. Agents: `saveAgentStateSync({ ...fresh getAgentState(id), effort: confirmedLevel, effortSource: 'explicit' })`, so `resolveRelaunchEffort` pins it on resume, recovery, rotation, and respawn.
- **D11 — Agent door scope.** `POST /api/agents/:id/effort` supports claude-code agents only. Any other harness answers 400 `Live effort change is supported for claude-code agents only`. Conversations keep their existing codex/ACP/OpenCode/Pi branches unchanged.
- **D12 — Clean the lint-effort row assigned to this issue.** `ThinkingLevel` becomes `'off' | 'minimal' | Exclude<EffortLevel, 'max'>` (same members, no literal union copy), and the `conversation-control.ts` baseline row is deleted.
- **D13 — Status codes for both doors.** 400 invalid level / unsupported harness; 404 not found; 409 `busy`, `permission-pending`, `input-target-not-main`; 422 session ended / not running, or `effort-rejected` (Claude Code's message is in `error`); 502 `not-delivered`; 504 `not-confirmed` with `error: "Claude Code did not confirm the effort change within 10 s; the stored effort is unchanged."`. Success: 200 `{ ok: true, effort, source: 'explicit', warning? }`.
- **D14 — Timing constants.** Idle wait 5000 ms; confirmation poll every 250 ms for at most 10000 ms. Tests use fake timers (repo rule `fake-timers-for-retry-tests`).

```ts
import { isEffortLevel, type EffortLevel } from '@overdeck/contracts';

export type EffortCommandResult =
  | { kind: 'set'; level: EffortLevel }
  | { kind: 'rejected'; message: string };

const SET_PATTERN = /Set effort level to ([a-z]+)\b/;
const REJECT_PATTERNS = [/Invalid argument:[^<]*/, /Failed to set effort level[^<]*/, /Not applied:[^<]*/];

/** Reads one `<local-command-stdout>` string. Null when it is not an /effort result. */
export function parseEffortCommandStdout(content: string): EffortCommandResult | null {
  if (!content.includes('<local-command-stdout>')) return null;
  const set = SET_PATTERN.exec(content);
  if (set && isEffortLevel(set[1])) return { kind: 'set', level: set[1] };
  for (const pattern of REJECT_PATTERNS) {
    const hit = pattern.exec(content);
    if (hit) return { kind: 'rejected', message: hit[0].trim() };
  }
  return null;
}

/** The effort a single JSONL record shows, or null (D6). */
export function observedEffortFromRecord(record: unknown): EffortLevel | null { … }
```

`observedEffortFromRecord` rules: not an object or `isSidechain === true` → null. `type === 'assistant'`: return `record.effort` if `isEffortLevel`, else `record.perTurnEffort` if `isEffortLevel`, else null. `type === 'user'` with `message.content` a string: return the level of `parseEffortCommandStdout(content)` when its kind is `set`, else null. Anything else → null.

Tests (table-driven, using the literal strings from [Empirical facts](#empirical-facts-verified-2026-10-03)):
- the `low` and `max` stdout strings → `{ kind: 'set', level }`;
- the `Invalid argument: bogus…` string → `{ kind: 'rejected', message: 'Invalid argument: bogus. Valid options are: low, medium, high, xhigh, max, auto, ultracode [on|off]' }`;
- the `<command-name>/effort</command-name>…` record content → null;
- an assistant record `{ type: 'assistant', effort: 'low', perTurnEffort: 'low' }` → `'low'`; with only `perTurnEffort: 'xhigh'` → `'xhigh'`; with `isSidechain: true` → null; with `effort: 'auto'` → null.

### W2 — Live-change core for claude-code panes (FR-1, FR-2)

**File (new):** `src/lib/agents/effort-live.ts`. **Test (new):** `src/lib/agents/__tests__/effort-live.test.ts`.

```ts
export interface ClaudeLiveEffortTarget {
  /** Pane address: conv.tmuxSession for conversations, the agent id for agents. */
  paneId: string;
  workspace: string;                 // conv.cwd / agentState.workspace
  sessionId: string;                 // conv.claudeSessionId / getLatestSessionId(...)
  deliveryMethod?: 'auto' | 'supervisor' | 'channels' | 'tmux';
  caller: 'conversation-effort' | 'agent-effort';
}

export type ClaudeLiveEffortResult =
  | { ok: true; effort: EffortLevel }
  | { ok: false; code: 'busy' | 'permission-pending' | 'input-target-not-main' | 'not-delivered' | 'not-confirmed' | 'effort-rejected'; error: string };

export interface ClaudeLiveEffortDeps {
  waitForIdle?: typeof waitForAgentIdle;
  runtimeState?: typeof getAgentRuntimeStateSync;
  readPane?: (paneId: string) => Promise<string | null>; // default: resolveAgentPaneIo(paneId).read(PANE_CAPTURE_LINES), errors -> null
  ensureMain?: typeof ensureMainInputTarget;
  snapshot?: typeof captureTranscriptUserRecordSnapshot;
  deliver?: typeof deliverAgentMessage;
  readSince?: (sessionFile: string, offset: number) => Promise<{ records: unknown[]; nextOffset: number }>;
}

export const LIVE_EFFORT_IDLE_TIMEOUT_MS = 5000;
export const LIVE_EFFORT_CONFIRM_TIMEOUT_MS = 10000;
export const LIVE_EFFORT_POLL_MS = 250;

export async function applyClaudeLiveEffort(
  target: ClaudeLiveEffortTarget,
  level: EffortLevel,
  deps: ClaudeLiveEffortDeps = {},
): Promise<ClaudeLiveEffortResult>
```

Steps, in order:
1. `const idle = await waitForIdle(target.paneId, LIVE_EFFORT_IDLE_TIMEOUT_MS)`; if `!idle && runtimeState(target.paneId)?.state === 'active'` → `{ ok: false, code: 'busy', error: 'The session is mid-turn. Change effort when it is idle.' }`. Nothing delivered. Not idle with unknown/missing mirror state continues (D2).
1a. `const paneText = await readPane(target.paneId)`; `paneText && parsePermissionPrompt(paneText)` → `{ ok: false, code: 'permission-pending', error: 'Waiting: the agent needs a permission answer first' }`. Nothing delivered.
2. `const main = await ensureMain(target.paneId)`; `!main.ok` → `{ ok: false, code: 'input-target-not-main', error: main.reason }`.
3. `const before = await snapshot(target.workspace, target.sessionId)`; `offset = before.readOffset ?? before.fileSize ?? 0`.
4. `const delivery = await deliver(target.paneId, \`/effort ${level}\`, target.caller, target.deliveryMethod)`; `!delivery.ok` → `{ ok: false, code: 'not-delivered', error: delivery.failure ?? 'the terminal refused the message' }`. A thrown error is caught and mapped the same way.
5. Poll: every `LIVE_EFFORT_POLL_MS` until `LIVE_EFFORT_CONFIRM_TIMEOUT_MS` elapses, `readSince(before.sessionFile, offset)`; advance `offset` to `nextOffset`; for each record that is a `type: 'user'` record with string `message.content`, call `parseEffortCommandStdout`. First `set` → `{ ok: true, effort: result.level }`. First `rejected` → `{ ok: false, code: 'effort-rejected', error: result.message }`.
6. Timeout → `{ ok: false, code: 'not-confirmed', error: 'Claude Code did not confirm the effort change within 10 s; the stored effort is unchanged.' }`.

The default `readSince` uses `fs/promises` `open`/`read` from `offset` to EOF, splits on `\n`, parses only complete lines (keep a trailing partial line for the next poll by returning `nextOffset` at the last newline), and treats a missing file (`ENOENT`) as `{ records: [], nextOffset: offset }` (a brand-new session has no file until its first record).
