# PAN-4643 — `pan diagnose`: collect diagnostics and hand them to Claude Code or Codex

**Issue:** [PAN-4643](https://github.com/eltmon/overdeck/issues/4643)
**Status:** planned (auto mode, 2026-11-01)

## Glossary

- **Bundle** — a directory `~/.overdeck/diagnostics/<stamp>/` (honours `OVERDECK_HOME`) that holds redacted diagnostic files plus `MANIFEST.md`. `<stamp>` is UTC `YYYYMMDDTHHMMSSZ`, for example `20261101T044453Z`.
- **Bundle entry** — one file the bundle will hold, described in memory as `{ path, content, kind, description }` before it is redacted and written.
- **Collector** — a function that gathers raw text for one or more bundle entries. A collector never throws; it returns entries plus failures.
- **Collector failure** — `{ source, reason }`. The bundle still completes; `MANIFEST.md` lists each failure.
- **Redaction marker** — any string starting with `[REDACTED` that a redaction step writes in place of a secret (`[REDACTED_API_KEY]`, `[REDACTED_TOKEN]`, `KEY=[REDACTED]`, `[REDACTED]`, …).
- **Key-name redaction** — a line-based pass over YAML config that replaces the value of any key whose name looks secret (see FR-7).
- **Text redaction** — `redactSensitiveText` in `src/lib/secret-redaction.ts` line 148, which replaces values that look like secrets by shape.
- **Eligible harness** — a harness CLI that is installed (found on `PATH`) **and** authenticated. Only `claude-code` and `codex` are supported by this command.
- **Foreground launch** — starting the harness CLI as a child process with `stdio: 'inherit'` in the operator's own terminal, interactively, with the prompt as its first positional argument. It is not an Overdeck agent, not a Herdr/tmux pane, and not a one-shot (`claude -p` / `codex exec` are forbidden).
- **Doctor JSON report** — the object `pan doctor --json` prints (FR-1).

## Problem

When Overdeck breaks on a machine, the operator has `pan doctor` (text only), `pan health`, and the static `pan-diagnose` skill. Nothing collects logs, config, versions and service state in one place, and nothing hands that context to a model that can fix the machine. t3code's `npx t3 triage` shows the value: one command, pick Claude Code or Codex, the model gets all the context, fixes local problems, and drafts an upstream issue for real bugs. It must work when the dashboard, the supervisor or Herdr is down, because that is when people need it.

## Decisions (made here; the executor must not re-decide)

- **D1 — Verb name.** `pan diagnose`. `pan triage` keeps its tracker meaning. No rename of `pan issues --triage`.
- **D2 — Doctor JSON runs out of process.** The bundle runs `pan doctor --json` as a child process: `spawn(process.execPath, [...process.execArgv, process.argv[1], 'doctor', '--json'], { stdio: ['ignore', 'pipe', 'pipe'], env: process.env })`. This does not depend on `pan` being on `PATH` (#2630), isolates a crashing or hanging check, and exercises the real CLI flag. `execArgv` is filtered to drop any `--inspect`, `--inspect-brk` or `--inspect-port` entry (with or without `=value`), so a debugged parent does not make the child fight over the debugger port. Timeout 120 s, then `SIGTERM`.
- **D3 — Harness cwd.** The harness starts with `cwd = getOverdeckHome()`. The bundle lives under it, so both the bundle and `config.yaml` / `projects.yaml` are inside the harness's workspace. No `--add-dir` flag is passed (this also avoids Claude's variadic `--add-dir` swallowing the prompt).
- **D4 — Launch argv.** Claude Code: `['claude', prompt]`. Codex: `['codex', prompt]`. No permission-bypass flags (`--dangerously-skip-permissions`, `--dangerously-bypass-approvals-and-sandbox`, `--full-auto`, `-s danger-full-access`), no `--model`, no `-p`, no `exec`. The operator approves the model's actions with the harness's own default approval mode.
- **D5 — Skill delivery.** The bundle includes a copy of `SYNC_SOURCES.skills/pan-diagnose/SKILL.md` as `TROUBLESHOOTING.md`. The prompt tells the model to follow it. This works even when `pan sync` never ran (an empty `~/.claude/skills` is a common failure this command must handle).
- **D6 — Consent.** Before launching a harness, the command always prints the bundle path and the `MANIFEST.md` file list, then asks `Start <Harness label> with this bundle? [y/N] `. Only `y`/`yes` (case-insensitive) proceeds. `--yes` skips the question. No consent marker file is stored.
- **D7 — TTY required to launch.** When stdin or stdout is not a TTY and the command would launch a harness, it writes the bundle, prints its path, prints `pan diagnose needs an interactive terminal to start a harness. Use --bundle-only, or run it in a terminal.` to stderr, and exits 1.
- **D8 — Explicit `--harness` is validated before collecting.** An ineligible explicit harness fails fast with exit 1 and a fix message; no bundle is written.
- **D9 — No `--harness`.** On a TTY: 0 eligible → print each harness's reason and fix, suggest `--bundle-only`, exit 1; 1 eligible → print `Using <label> (the only installed and signed-in harness).` and use it; 2 eligible → numbered menu (`1) Claude Code  2) Codex`), read one line, invalid input → exit 1 with `No harness selected.`. Off a TTY → D7 applies (bundle is still written).
- **D10 — Codex auth location.** Read `$CODEX_HOME/auth.json` when `CODEX_HOME` is set and non-empty, else `getNativeCodexAuthPath()`. Only `classifyNativeCodexAuth(raw).status === 'valid'` counts as authenticated.
- **D11 — Issue step is prompt-enforced.** "No issue without explicit confirmation" is enforced by the prompt text, because the model runs the `gh` command, not Overdeck. Tests assert the prompt text, not model behaviour. `--no-issue` removes the issue section and replaces it with a prohibition.
- **D12 — Failed `pan` commands.** Not recorded anywhere locally, so not collected. `MANIFEST.md` says so in its "Not included" section.
- **D13 — Home path.** After redaction, every occurrence of `os.homedir()` in every entry is replaced with `~`.
- **D14 — Description.** `--describe "<text>"` is optional. Without it, on a TTY, the command asks `Describe what went wrong (one line, Enter to skip): `. The text goes through the same redaction as every other entry.
- **D15 — Telemetry.** `diagnose` is not added to `TELEMETRY_CLI_VERBS`; it reports as `other`.

- **FR-14** Harness eligibility: installed = the command resolves on `PATH` (async `execFile('which', [cmd])`, exit 0); authenticated = Claude `checkClaudeLogin()` `ok`, Codex D10. Reasons and fixes:

  | --- | --- | --- |
  | `claude-code` (label `Claude Code`, command `claude`) | `Install: npm install -g @anthropic-ai/claude-code` | `Run: claude, then /login (or set ANTHROPIC_API_KEY)` |

- **FR-15** While the harness child runs, the parent installs no-op `SIGINT` and `SIGQUIT` handlers. The terminal sends these signals to the whole foreground process group, so without the handlers Node's default action would kill `pan` on the first Ctrl+C and orphan the harness. The child receives the signal directly and handles it itself. The parent removes both handlers when the child exits. After exit it prints `Bundle kept at <path>` and exits with the child's exit code (`1` when the code is null).
- **FR-16** `--bundle-only` writes the bundle, prints its absolute path as the last stdout line, and exits 0. It never prompts for a harness. It completes when the dashboard and supervisor are down.
