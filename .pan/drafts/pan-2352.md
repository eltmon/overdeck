# PAN-2352 — Remote dashboard access via Cloudflare Tunnel + Access (Overdeck Anywhere Phase 1a)

**Status:** draft · **Author:** claude-fable-5 orchestrating conversation · **Date:** 2026-07-04
**Epic:** [PAN-2350](https://github.com/eltmon/overdeck/issues/2350) · **Parent PRD:** `.pan/drafts/pan-2350.md`
**Depends on:** PAN-2351 (scoped tokens, heartbeat, `require_token_mint`) and PAN-1166 (WS gates). Do not
expose the dashboard before both are merged and deployed.

Anchors verified 2026-07-04.

## Glossary

- **Tunnel** — `cloudflared`, a daemon on the home machine holding outbound-only connections to
  Cloudflare's edge; maps `https://deck.<domain>` → `http://localhost:3011`. No inbound ports.
- **Access** — Cloudflare Zero Trust identity proxy in front of the tunnel hostname; every request needs an
  Access SSO login (free ≤50 users). Browser flow = cookie after Google/GitHub/email-OTP login.
- **Device token** — a PAN-2351 scoped token with `admin` scope (the operator's own device), delivered once
  to a new browser via the existing URL-hash bootstrap (`#overdeck_token=`, consumed at
  `src/dashboard/frontend/src/lib/wsTransport.ts:50-62`) and exchanged for the `overdeck_session` cookie.
- **Trusted origin** — entry in the allowlist built by `getTrustedOrigins()`
  (`src/dashboard/server/routes/origin-validation.ts:13-42`); extended via `OVERDECK_TRUSTED_ORIGINS` CSV
  (`:26`). The CLI injects these env vars at server spawn (`src/cli/index.ts:1002-1004`,
  `src/cli/commands/restart.ts:131-133`).

## Problem

The dashboard is reachable only on the LAN. The frontend is already host-agnostic
(`window.location.host`-derived URLs — `wsTransport.ts:25-35`, `XTerminal.tsx:473-476`), so remote access
is an auth + origin + ops problem, not a code rewrite. Two code-level gaps remain after PAN-2351/1166:
the security posture flags that must flip when a local reverse proxy fronts the server, and a doctor
command so a broken tunnel is diagnosable in one step.

## Decisions

- **D-1 Cloudflare Tunnel + Access, not ngrok/Funnel/VPN** (epic D-2). Requires a domain on Cloudflare DNS —
  **operator input needed: which domain** (the only external prerequisite).
- **D-2 Behind the tunnel, peer-based session mint MUST be off.** cloudflared connects to :3011 from
  loopback, so every tunnel visitor is a loopback peer to `isLoopbackPeer`
  (`dashboard-auth.ts:275-288`) — `require_token_mint: true` (PAN-2351 D-4) is mandatory, enforced by the
  doctor and stated in the runbook. Access alone is the perimeter; the device token is the second factor.
- **D-3 Operator devices get `admin`-scoped device tokens** (they are the operator; PAN-2351 mints session
  cookies only for admin-scoped credentials). Narrower grants arrive with pairing in PAN-2356.
- **D-4 SSE hardening:** `OVERDECK_EVENTS_TOKEN` must be set when tunneled (the `/events/stream` route is
  open when it's unset — `routes/events.ts:107-114`). Doctor-enforced.
- **D-5 One hostname, same-origin.** No split API/frontend hosts; avoids the `XTerminal.tsx` VITE_API_URL
  gap (it uses `window.location.host` only) and keeps cookies first-party.

## Requirements

- **FR-1** `docs/REMOTE-ACCESS.md`: full runbook — Cloudflare DNS + tunnel creation (token connector),
  systemd unit, Access application + policy (operator emails), the three server-side settings
  (`OVERDECK_TRUSTED_ORIGINS` += `https://deck.<domain>`, `require_token_mint: true`,
  `OVERDECK_EVENTS_TOKEN`), device onboarding, revocation, and teardown.
- **FR-2** `pan remote-access doctor`: checks (a) cloudflared service running + tunnel healthy, (b) tunnel
  origin present in resolved trusted origins, (c) `require_token_mint` on, (d) events token set,
  (e) heartbeats active (PAN-2351 W4 present in running dist), (f) end-to-end: fetch
  `https://deck.<domain>/api/health` (route exists: `server.ts:115-119`) and expect the Access login or
  200-with-credential. Prints PASS/FAIL per check with the fix for each.
- **FR-3** `pan remote-access invite`: mints an admin device token (PAN-2351 registry) and prints
  `https://deck.<domain>/#overdeck_token=<token>` plus a QR code (terminal QR, e.g. `qrcode-terminal`) for
  phone onboarding. Token is single-name ("pixel-8", "macbook") for later revocation.
- **FR-4** Config: `dashboard.remote_access: { hostname?: string }` in the YAML layer
  (`src/lib/config-yaml/schema.ts`, next to `tts?` at `:487-490`, defaults + normalizer per that pattern)
  so doctor/invite know the hostname without re-prompting.
- **NFR-1** Zero new server routes; zero changes to auth semantics beyond flags PAN-2351 already added.
- **NFR-2** The runbook is executable top-to-bottom by a non-author (test: the operator follows it on the
  coffee-shop laptop without help).

## Acceptance criteria

- [ ] AC-1 `pan remote-access doctor` all-green on the configured machine; each failure mode prints its fix
      (unit-test the check functions with injected env/config).
- [ ] AC-2 Phone on cellular: full dashboard, live terminal ≥10 min (heartbeat survival), AUQ answered.
- [ ] AC-3 Coffee-shop laptop: same URL + `pan remote-access invite` token → picks up the flywheel
      conversation; no home-machine changes needed.
- [ ] AC-4 Negative: with `require_token_mint` off, doctor FAILS with the D-2 explanation; anonymous
      `/events/stream` through the tunnel is 401 (events token set).
- [ ] AC-5 Root internal token never appears in any URL, doc, or invite output (grep the deliverables).

## Intersecting repo rules (restated)

`pan <verb>` ↔ skill convention (lint-skills in same commit); no `execSync` in anything server-reachable
(doctor is CLI-side, `execAsync` for systemctl/cloudflared probes); operator-facing doctor output must
stand alone (define "trusted origin", "session mint" inline); never hot-patch env onto the live server —
origin/env changes go through `pan restart` (which injects Traefik/trusted-origin env,
`restart.ts:131-133`) with `--health-timeout 120`.

## Out of scope

Collaborator access policies (Phase 3 pairing); Cloudflare Access service tokens for Hermes (PAN-2353
fallback path documents them); native-app auth flows; multi-hostname setups.
