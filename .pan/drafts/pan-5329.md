# PAN-5329 — Workflow redesign B follow-up

**Issue:** https://github.com/eltmon/overdeck/issues/5329

**Parent:** PAN-5284 (workflow redesign), live check of child B (PAN-5289, #5328) on :3011 at build `0b6542ff99a`.
**PRD:** `.pan/drafts/pan-5329.md` on main (same text as this body).

The dock works: Files, Changes and Search follow the active tab, project Home's Files button opens it, Go to file opens beside the chat, and Ctrl+Shift+E and Ctrl+Shift+G toggle it. A live check at 1920×1000 found five defects. Fix all five in one PR.

## 1. Ctrl+Shift+F opens the chat's find bar, not the dock's Search box (high)

Steps: open a conversation tab, press Ctrl+Shift+F, type `workDockStore`. The dock opens on Search, but the text goes into the conversation's find bar ("workDockStore 1/2") and the dock input stays empty.

Cause: `src/dashboard/frontend/src/components/chat/messagesTimeline/MessagesTimeline.tsx`, around line 530, has a window capture-phase keydown listener that matches `(event.ctrlKey || event.metaKey) && event.key.toLowerCase() === 'f'` without checking `shiftKey`. It calls `stopPropagation()` and opens the chat find bar, which takes focus.

Fix: add `&& !event.shiftKey && !event.altKey` to that condition, so it matches plain Ctrl/⌘+F only. Test: in `MessagesTimeline` tests (or a new `MessagesTimeline.find-shortcut.test.tsx`), Ctrl+F opens the find bar and Ctrl+Shift+F does not. If you add a test file, add it to `scripts/frontend-test-subset.txt`.

## 2. Go to file match highlight is unreadable (high)

The matched characters render as pure yellow (`rgb(255,255,0)`) with near-white text (`rgb(241,240,238)`) in the dark theme.

Cause: `src/dashboard/frontend/src/components/explorer/search/QuickOpen.tsx` line 28, `const MARK_CLASS = 'rounded-sm bg-warning/30 text-inherit'`. A Tailwind opacity modifier on a `var()`-based color token compiles to no CSS (style guide, "Lists and switches"), so `<mark>` falls back to the browser's yellow.

Fix: use the mockup's rule (`docs/design/workflow-redesign-mockup.html` line 303): background `color-mix(in srgb, var(--state-needs-you) 30%, transparent)`, `color: inherit`, radius 2px, padding `0 1px`. Use an arbitrary-value class or a named class in `index.css`. Check `ContentSearch` and any other `<mark>` added by PAN-5289 for the same `bg-*/NN` pattern and fix them too. Test: assert the class no longer contains `bg-warning/`.

## 3. The chat becomes about 90 px wide when a file opens beside it (high: breaks parent D-13, "each child leaves the dashboard usable")

Steps: at 1920×1000, open a conversation and press Ctrl+P, then Enter on a file. The Stage splits 50/50. The conversation half is about 350 px, and its Agents rail (`SubagentRail`, about 255 px open) leaves about 90 px for messages, one word per line.

Fix: `src/dashboard/frontend/src/components/chat/SubagentRail.tsx` collapses to its 30 px strip automatically when its conversation pane is narrower than 760 px. Measure the pane with a `ResizeObserver`. This auto-collapse never writes `overdeck.ui.agentsRailCollapsed`. Clicking the strip while narrow opens the rail for that pane until it is wide again. The stored preference applies again once the pane is 760 px or wider. Test with a mocked `ResizeObserver`: narrow pane → collapsed without a localStorage write; wide pane → stored preference.

## 4. The Files tree lists the `.git` folder (low)

Fix: `src/dashboard/frontend/src/components/explorer/tree/explorer-tree-model.ts` skips an entry named exactly `.git` at every depth, whatever the dotfile setting. Do the same in `projectChangedRows`. Test in `explorer-tree-model.test.ts`.

## 5. A long attribution tag pushes the commit subject out of the project Changes row (low)

On project Home, Changes, the row for `05e7e23` shows an empty subject, and the tag "PAN-5325 gh shim refuses vetoed" (a conversation title) runs past the dock edge.

Cause: `src/dashboard/frontend/src/components/dock/changes/ProjectMainChangesList.tsx` around line 129 renders `<ChangeTag>{commit.by.title ?? …}</ChangeTag>` with no width limit.

Fix: give `ChangeTag` (wherever it is defined) `max-w-[40%] truncate` and a `title` attribute with the full text, so the subject keeps most of the row. Test in `ProjectMainChangesList.test.tsx`: a 60-character tag has the truncate class and a `title`.
