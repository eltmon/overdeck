# PAN-5329 — Workflow redesign B follow-up

**Issue:** https://github.com/eltmon/overdeck/issues/5329

**Parent:** PAN-5284 (workflow redesign), live check of child B (PAN-5289, #5328) on :3011 at build `0b6542ff99a`.
**PRD:** `.pan/drafts/pan-5329.md` (this file). Planned against `54270cb7f4f` on `feature/pan-5329`; every reference below was re-read at that commit.

The dock works: Files, Changes and Search follow the active tab, project Home's Files button opens it, Go to file opens beside the chat, and Ctrl+Shift+E and Ctrl+Shift+G toggle it. A live check at 1920×1000 found five defects. Fix all five in one PR.

## Glossary

- **Work dock (dock):** the right-hand panel of the Command Deck's tab area with the tabs Files, Changes, Search and Live (`src/dashboard/frontend/src/components/dock/WorkDock.tsx`).
- **Shortcut registry:** `src/dashboard/frontend/src/lib/shortcuts/registry.ts`. It installs one capture-phase and one bubble-phase `keydown` listener on `window`. A `global` shortcut runs in the capture listener, which calls `preventDefault()` and `stopPropagation()`.
- **Capture-phase window listener:** `window.addEventListener('keydown', fn, true)`. `stopPropagation()` in one such listener does **not** stop another listener on the same target (`window`). Only `stopImmediatePropagation()` does. This is why the chat's own listener still runs after the registry handles Ctrl+Shift+F.
- **Chat find bar:** the "Search conversation…" input that `MessagesTimeline` shows when `searchOpen` is true.
- **Go to file (Quick Open):** the Ctrl+P file picker, `components/explorer/search/QuickOpen.tsx`, mounted by `components/dock/DockQuickOpen.tsx`.
- **Agents rail:** `components/chat/SubagentRail.tsx`, the right column of a conversation pane that lists the main agent and its subagents. Open it is `w-64` (256 px). Collapsed it is a 30 px strip (`w-[30px]`) with the label "Agents".
- **Conversation pane row:** the flex row in `ConversationPanel.tsx` (line 1023, `<div className="flex min-h-0 min-w-0 flex-1 overflow-hidden">`) that holds the messages column, the inline diff panel and the Agents rail. The rail is its last child, so the rail's `parentElement` is this row.
- **Stored rail preference:** `localStorage['overdeck.ui.agentsRailCollapsed']` (`'true'`/`'false'`), constant `AGENTS_RAIL_COLLAPSED_KEY` in `SubagentRail.tsx` line 7.
- **`defaultCollapsed`:** optional `SubagentRail` prop (PAN-4222) for embedded previews: the rail starts at that state and never writes the stored preference.
- **Narrow pane:** a conversation pane row whose measured width is greater than 0 and less than 760 px.
- **Pane-local override:** a rail open/closed choice the operator made while the pane was narrow. It lives in component state only and is cleared when the pane becomes wide.
- **`ChangeTag`:** the small bordered tag in a Changes group header, defined in `components/dock/changes/ChangeGroup.tsx` line 41.
- **Frontend test subset:** `scripts/frontend-test-subset.txt`, one path per line relative to `src/dashboard/frontend`, C-locale sorted, `merge=union`. CI runs only the frontend test files listed there.

All paths below are relative to `src/dashboard/frontend/src/` unless they start with `src/`, `docs/`, `features/`, `scripts/`, `changelog.d/` or `sync-sources/`.

### WI-3 — Agents rail auto-collapses in a narrow pane (defect 3, high: parent D-13, "each child leaves the dashboard usable") — FR-3

**Steps to reproduce:** at 1920×1000, open a conversation and press Ctrl+P, then Enter on a file. The Stage splits 50/50. The conversation half is about 350 px, and the open rail (256 px) leaves about 90 px for messages, one word per line.

**Where:** only `components/chat/SubagentRail.tsx`. Do not touch `ConversationPanel.tsx` (NFR-2).

**Measurement decisions:**

- Measure the rail's `parentElement` (the conversation pane row, Glossary). Its width does not depend on the rail's own state, so collapsing cannot cause an open/close loop.
- Get the element with a **stable** callback ref stored in state: `const [host, setHost] = useState<HTMLElement | null>(null)`; `const hostRef = useCallback((el: HTMLElement | null) => { if (el) setHost(el.parentElement) }, [])`. Pass `ref={hostRef}` to **both** the collapsed `<button>` and the open `<aside>`, so the ref survives the swap between them. Never use an inline lambda: React detaches and reattaches an inline ref on every render. Ignoring `null` keeps `host` across the button/aside swap (the parent row is the same element).
- In a `useEffect` on `[host]`: if `host` is null return. Otherwise create `new ResizeObserver((entries) => { const w = entries[entries.length - 1]?.contentRect.width ?? 0; if (w > 0) setNarrow(w < NARROW_PANE_PX) })`, call `observe(host)`, return `() => observer.disconnect()`.
- `const NARROW_PANE_PX = 760` (module constant, exported for the test).
- **Unmeasured means wide.** `narrow` starts `false`, and a width of 0 (a hidden pane, or jsdom) is ignored. This keeps the 10 existing `SubagentRail` tests unchanged: the `test-setup.ts` ResizeObserver mock (line 60) never fires.
- All new hooks (`useState` for `host`, `narrow`, `override`; the `useEffect`s) go **above** the existing `if (subagents.length === 0) return null;` line (line 64), to keep hook order stable.

**State:** keep the existing `collapsed` state, renamed `storedCollapsed` (it still starts from `defaultCollapsed ?? localStorage`). Add `narrow: boolean` (default `false`) and `override: boolean | null` (default `null`, meaning "no pane-local choice"). When `narrow` turns `false`, reset `override` to `null` (a `useEffect` on `[narrow]`: `if (!narrow) setOverride(null)`).

Effective collapsed state: `const collapsed = narrow ? (override ?? true) : storedCollapsed`.

`toggleCollapsed(next)`:

```tsx
  const toggleCollapsed = useCallback((next: boolean) => {
    if (narrow) { setOverride(next); return; }        // pane-local; never persisted
    setStoredCollapsed(next);
    if (defaultCollapsed !== undefined) return;
    try { localStorage.setItem(AGENTS_RAIL_COLLAPSED_KEY, String(next)); } catch { /* ignore */ }
  }, [narrow, defaultCollapsed]);
```

| Situation | Rail shows | Writes stored preference? |
|---|---|---|
| Pane unmeasured or ≥ 760 px | `storedCollapsed` (stored preference, or `defaultCollapsed`) | Toggle writes it, as today (never with `defaultCollapsed`) |
| Pane < 760 px, no override | collapsed strip | No |
| Pane < 760 px, operator clicks the strip | open rail (override = false) | No |
| Pane < 760 px, operator clicks X on the open rail | collapsed strip (override = true) | No |
| Pane goes from < 760 px to ≥ 760 px | override cleared; `storedCollapsed` applies again | No |
| `defaultCollapsed` caller (Agents page preview) in a narrow pane | same narrow rules | No (never) |

**Before** (line 55–62):

```tsx
  const [collapsed, setCollapsed] = useState(
    () => defaultCollapsed ?? (typeof window !== 'undefined' && localStorage.getItem(AGENTS_RAIL_COLLAPSED_KEY) === 'true'),
  );
  const toggleCollapsed = useCallback((next: boolean) => {
    setCollapsed(next);
    if (defaultCollapsed !== undefined) return;
    try { localStorage.setItem(AGENTS_RAIL_COLLAPSED_KEY, String(next)); } catch { /* ignore */ }
  }, [defaultCollapsed]);
```

**After:** as specified above (`storedCollapsed`/`setStoredCollapsed`, `narrow`, `override`, `host`, the observer effect, the reset effect, the new `toggleCollapsed`, and `const collapsed = …`). The JSX keeps its classes; it only gains `ref={hostRef}` on the `<button>` and the `<aside>`, where `hostRef` is the callback ref.

**Tests:** add `describe('SubagentRail narrow pane (PAN-5329)', …)` to `components/chat/SubagentRail.test.tsx`. Stub the observer per test with `vi.stubGlobal('ResizeObserver', FakeResizeObserver)` and `vi.unstubAllGlobals()` in `afterEach`, where `FakeResizeObserver` records its callback in a module-level array on construction, has a no-op `observe`, and removes its callback from the array in `disconnect()`. ### WI-5 — `ChangeTag` truncates at 25% with a full-text tooltip (defect 5, low) — FR-5

**Symptom:** on project Home → Changes, the row for `05e7e23` shows an empty subject, and the tag "PAN-5325 gh shim refuses vetoed" runs past the dock edge.

**Cause (verified):** `components/dock/changes/ChangeGroup.tsx` line 41–43: `ChangeTag` is `shrink-0` with no width limit, so in the header row (`ProjectMainChangesList.tsx` line 129, `<ChangeTag>{commit.by.title ?? commit.by.id ?? 'unattributed'}</ChangeTag>`) the subject (`min-w-0 flex-1 truncate`) shrinks to zero.

Before:

```tsx
export function ChangeTag({ children }: { children: ReactNode }) {
  return <span className="shrink-0 rounded border border-border px-1.5 font-mono text-[11px] leading-[18px] text-muted-foreground">{children}</span>
}
```

After (the `title` is derived from string children, so no caller changes):

```tsx
export function ChangeTag({ children }: { children: ReactNode }) {
  const title = typeof children === 'string' ? children : undefined
  return (
    <span
      title={title}
      className="max-w-[25%] shrink-0 truncate rounded border border-border px-1.5 font-mono text-[11px] leading-[18px] text-muted-foreground"
    >
      {children}
    </span>
  )
}
```

`shrink-0` stays so short tags ("pushed", "this chat") keep their size; `max-w-[25%]` caps long ones against the header button's content width.

**Decision: 25%, not the issue's 40%.** The subject span is `flex-1` with a 0 basis, so it gets only what is left after every other item. At the default dock width (`DOCK_DEFAULT_WIDTH = 340` in `components/dock/workDockStore.ts` line 22) the header button's content box is 316 px (`px-3`). Fixed items take about 166 px: chevron 14, commit icon 14, short sha ≈ 48 (7 mono chars at 11.5px), time ≈ 50 ("01:32 AM" at 11px) and five `gap-2` gaps of 8. That leaves about 150 px for subject plus tag. A 40% cap (126 px) leaves the subject about 24 px (3 characters); 25% (79 px) leaves it about 71 px, so the subject and the tag share the row about equally, and the tag still shows the issue ID ("PAN-5325 gh…"). At the 720 px maximum dock width the tag cap is 174 px. This keeps the issue's stated goal, "the subject keeps most of the row", which 40% cannot meet at the default width.

This also changes the tags in `ConversationChangesList.tsx` line 181 (`commitWho(commit)` returns a string, and the pushed/not-pushed literals): they gain the same cap and tooltip, which is intended.
