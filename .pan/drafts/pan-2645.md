# PAN-2645 — Opt-in Observation-first conversation view

**Status:** Draft  
**Tracking issue:** [PAN-2645](https://github.com/eltmon/overdeck/issues/2645)  
**Audience:** Implementation, review, test, and documentation agents

## Glossary

- **Observation:** An existing `MemoryObservation` record produced from a transcript slice. It contains a session identity, `sourceTranscriptOffset`, `summary`, `narrative`, `actionStatus`, files, tags, and timestamp. It is not a chat message and must be labeled as an Observation.
- **Observation-first mode:** An opt-in dashboard presentation that promotes observations to the primary work narrative and nests the corresponding low-level work events as evidence.
- **Raw transcript mode:** The current Conversation timeline. It renders normalized user/assistant messages, work-log entries, tool inputs/results/errors, and other affordances without observation grouping.
- **Evidence:** The existing normalized transcript rows covered by an observation. Evidence remains expandable and retains its original content and ordering.
- **Covered range:** For one session, the transcript interval after the preceding observation’s `sourceTranscriptOffset` through the current observation’s `sourceTranscriptOffset`, inclusive.
- **Unmatched span:** Normalized transcript content that cannot be assigned to an observation deterministically. It renders with the existing raw components.
- **Global default:** The saved Conversation setting `conversations.observation_first_view`; absent or `false` means raw transcript mode.
- **Session override:** A local dashboard preference for one open conversation/session that temporarily selects Observations or Raw without changing the global default.
- **No-loss audit:** A focused test inventory proving each existing Conversation row and affordance remains directly visible or reachable as evidence.

## Problem

Some harnesses expose orchestration as source-like tool entries such as `await tools.exec_command(...)`, followed by transport calls such as `write_stdin` and `wait`. These are legitimate audit records, but they dominate the Conversation view and make the operator reconstruct the meaning of the work. Multiple transport events often represent one meaningful operation or finding.

The goal is to improve how Overdeck expresses an agent’s work without changing the agent’s reasoning, prompts, tool strategy, execution, or transcript. Overdeck already extracts structured Memory observations; the dashboard should optionally use them as the readable narrative while preserving raw transcript events as evidence.

## Goals

1. Offer an opt-in, reversible Observation-first Conversation view.
2. Reuse `MemoryObservation`; do not create another observation schema or another durable store.
3. Deterministically associate observations with normalized transcript ranges.
4. Preserve complete auditability and every current Conversation affordance.
5. Work uniformly across Claude Code, Codex, pi, and ohmypi after parser normalization.
6. Handle delayed or failed observation extraction without hiding work.

## Non-goals

- Change model behavior, commentary requirements, prompts, reasoning, or tool calls.
- Require models to emit a new progress protocol.
- Rewrite or delete transcript JSONL.
- Replace the Memory extraction pipeline.
- Generate observations synchronously in the request/render path.
- Guess relationships from matching prose or tool names.
- Make Observation-first mode the default in this issue.

## Product decision

The feature is a presentation mode, not a replacement transcript. The global setting defaults **off**. When enabled, an Observation card replaces only the primary rendering of its deterministically covered work-log rows. Its **View evidence** control expands those same normalized rows using the existing renderers. User messages and assistant prose remain first-class chronological messages and are never swallowed into evidence.

If observation data is missing, late, unhealthy, for another session, or cannot be joined, the existing raw timeline is rendered. Fidelity wins over compactness.

## Deterministic projection

The implementation must use this rule:

```ts
type ConversationDisplayMode = 'observations' | 'raw'

interface ObservationTimelineGroup {
  observation: MemoryObservation
  evidence: WorkLogEntry[]
}

// For observations matching the exact sessionId, sorted by sourceTranscriptOffset:
// group[i].evidence = work entries whose sourceTranscriptOffset is
//   > group[i - 1].observation.sourceTranscriptOffset (or >= 0 for the first)
//   && <= group[i].observation.sourceTranscriptOffset
// Entries without a compatible offset are unmatched raw rows.
```

An observation with zero evidence can still render as an Observation if it matches the session; it may describe a decision or result with no tool call. Two observations with the same offset retain timestamp then ID order, and only the first may claim the interval; later same-offset observations have empty evidence. This prevents duplicate evidence.

### Implementation checkpoint: offset compatibility

Before changing parser output, verify Memory’s `sourceTranscriptOffset` is the same byte coordinate available while parsing each harness file. Record the result in an inline module comment and parser tests.

- Preferred: stamp the exact end byte offset on normalized entries.
- Fallback for any incompatible parser: omit the field for that parser and leave its work raw while still rendering zero-evidence Observation cards.
- Do not convert line indexes, character counts, or event sequences into pretend byte offsets.

## UX specification

### Settings copy

**Observation-first conversation view**  
“Show Memory observations as the readable work narrative and keep raw tool calls under View evidence. Does not change how agents work.”

The switch is off by default.

### Header

Place **Observations / Raw** alongside the current Conversation/Terminal and Tools controls. In Observation mode, the existing Tools control continues to determine whether expanded evidence is initially compact; it must not remove **View evidence**.

### Card

```text
OBSERVATION                                      7:45 PM
Release blocked by existing tests               Warning
Two conversation model-switching tests failed. Publishing is
paused while their root cause is checked.
Next: compare the failures against current main.
[View evidence · 6 events]
```

Expanded evidence uses current work-log rows rather than a second renderer. Errors stay visibly red/destructive and running entries retain their live indicator.

## Rollout and reversibility

There is no migration. The optional config field is false when absent. Existing localStorage payloads parse because the new field is optional. Disabling the setting or choosing Raw restores current rendering immediately. Rollback removes the new projection and controls without modifying transcripts or Memory records.
