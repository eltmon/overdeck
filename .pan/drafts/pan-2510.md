# PAN-2510 — Merged/closed workspaces leak Docker containers + networks → pool exhaustion

**Issue:** [PAN-2510](https://github.com/eltmon/overdeck/issues/2510)
**Mode:** `pan plan --auto` (no interactive Q&A; defaults recorded below)

## Glossary

- **`_devnet` network** — the per-workspace Docker bridge network declared as
  `networks: devnet:` in the workspace's `.devcontainer/docker-compose.devcontainer.yml`.
  Docker compose names it `<project>_devnet`, i.e. `overdeck-feature-<issue>_devnet`.
  It is **compose-managed** (not `external:`), so `docker compose ... down` removes it.
- **Compose project name** — `overdeck-feature-<issue-lowercase>` (see
  `composeProjectNameForWorkspace` / `stopWorkspaceDockerPromise`).
- **Address pool exhaustion** — Docker's default `default-address-pools` only carves
  ~31 `/24` bridge subnets. Once ~31 networks exist, `docker network create` fails with
  *"all predefined address pools have been fully subnetted"* and every new workspace
  spawn is blocked.
- **Terminal-state issue** — closed / merged (an issue with no in-flight work that
  should keep infra). We use `isIssueClosed(issueId)` (`src/lib/cloister/issue-closed.ts:60`)
  as the terminal predicate.

## Problem

Merged/closed workspaces leave their Docker stacks **running**, so their `_devnet`
networks are never freed (`docker network prune` only frees container-less networks).
Networks accumulate until the ~31-network pool is exhausted, at which point **every**
new work-agent spawn fails to create its network — halting the drain.

## Root-cause findings (verified against the tree at `3fccf30470`)

1. **Close-out never resolves the workspace, so it never tears Docker down (primary).**
   `executeCloseOutPromise` Step 3 *does* call `stopWorkspaceDocker(workspacePath, issueLower)`
   (`src/lib/close-out.ts:293-298`) — but only `if (workspacePath && existsSync(workspacePath))`.
   The workspace path comes from a **buggy local** `findWorkspacePath`
   (`src/lib/close-out.ts:557-570`) whose only feature-naming fallback is
   `join(dirname(projectPath), \`feature-${issueLower}\`)` → e.g.
   `/home/eltmon/Projects/feature-pan-2510`, which never exists. Real workspaces are at
   `<projectPath>/workspaces/feature-<issue>/`. So `workspacePath` resolves to `null`,
   Step 3's Docker stop **and** worktree removal are silently skipped. (Confirmed:
   `workspaces/feature-pan-1491` and `workspaces/feature-pan-2468` — both CLOSED — still
   exist on disk.) The **correct** resolver already exists:
   `findAllWorkspacePaths` / `findWorkspacePath` in
   `src/lib/lifecycle/archive-planning.ts:47-69`, which checks `workspaces/feature-<issue>`.
   `postMergeLifecycle` uses that correct one (`src/lib/cloister/merge-agent.ts:530`).

2. **Post-merge Docker stop is bypassed by operator-bypass merges.** Many drain merges
   skip `postMergeLifecycle` (operator-bypass strands it — see memory
   `project_operator_bypass_completion_mechanics`), so its Docker stop never runs either.
   → The durable fix must live in **close-out** (per operator direction) plus a reaper backstop.

3. **The deacon's closed-issue reaper reaps everything except Docker.**
   `reconcileClosedIssueAgents()` (deacon-wired, runs every ~60s patrol at
   `src/lib/cloister/deacon.ts:2783`) → `reapIssueResidue`
   (`src/lib/cloister/reap-issue-residue.ts`) kills sessions, removes the worktree, deletes
   branches, removes agent dirs — but **never stops the Docker stack or removes `_devnet`.**
   Clean insertion point for the FR-3 backstop.

4. **Autonomous stack rebuild has no terminal-state guard (FR-2).**
   `rebuildWorkspaceStack(issueId, opts)` (`src/lib/workspace/rebuild-stack.ts:135`,
   returns `Effect<RebuildWorkspaceStackResult>`) is invoked from four callers:
   `src/lib/agents/spawn-prep.ts:778`, `src/lib/cloister/deacon-review-status.ts:169`,
   `src/lib/cloister/verification-runner.ts:496`, and the manual CLI
   `src/cli/commands/workspace-rebuild.ts:18`. None checks whether the issue is terminal,
   so a patrol/auto-resume touching a closed issue would rebuild (recreate the network for)
   a stack that should stay gone. Guarding the single chokepoint `rebuildWorkspaceStack`
   covers all four. (The draft previously mis-cited the first caller as `cloister/spawn-prep.ts`;
   the real path is `src/lib/agents/spawn-prep.ts:778`.)

5. **No pool-width safety net (NFR-1).** `/etc/docker/daemon.json` is
   `{"ipv6": false, "live-restore": true}` — no `default-address-pools`, so the pool stays
   at the ~31-network default.

## Proposal

Single shared teardown primitive; close-out and the reaper both call it; a terminal guard
stops rebuilds; a doctor advisory + docs cover the pool width.

- **FR-1 — close-out owns verified Docker teardown.** Replace close-out's buggy local
  `findWorkspacePath` with the canonical `findAllWorkspacePaths` (single source of truth),
  and make Step 3 a first-class **verified** teardown: containers + `_devnet` network
  removed, then assert the network is gone. Order preserved: Docker teardown BEFORE worktree
  removal (compose files must still exist).
- **FR-3 — reaper backstop.** Add Docker teardown to `reapIssueResidue` so the deacon's
  periodic (and boot) `reconcileClosedIssueAgents` patrol frees leaked stacks. Because the
  worktree may already be gone, the primitive must tear down **by project/network name**
  (`docker compose -p overdeck-feature-<issue> down` + `docker network rm
  overdeck-feature-<issue>_devnet`), not only via on-disk compose files.
- **FR-2 — no rebuild of terminal stacks.** Guard `rebuildWorkspaceStack` itself
  (single chokepoint covering all three autonomous callers): no-op when
  `isIssueClosed(issueId)` is true.
- **NFR-1 — widen pool (advisory).** `pan doctor` counts `overdeck-feature-*_devnet`
  networks, warns when near the pool limit, detects a missing `default-address-pools` in
  `daemon.json`, and prints the recommended snippet. We do **not** auto-edit
  `/etc/docker/daemon.json` (needs root + a docker daemon restart). Insertion point:
  `doctorCommand()` at `src/cli/commands/doctor.ts:648`, near the existing Docker Compose
  label-drift check (`src/cli/commands/doctor.ts:829-841`); add a `checkDevnetNetworkPool()`
  helper alongside `checkComposeLabelDrift` (`src/cli/commands/doctor.ts:194`) and push its
  `CheckResult` into the `checks` array.

### Insertion points (verified at HEAD)

- **Shared primitive (AD-1):** new export in `src/lib/workspace-manager/docker.ts` (which
  already holds `stopWorkspaceDockerPromise` / `getContainersReferencingWorkspacePathPromise`).
  Name-based: `docker compose -p overdeck-feature-<issue> down -v --remove-orphans`, then
  explicit `docker network rm overdeck-feature-<issue>_devnet` (ignore "not found"), then
  verify absence via `docker network ls`. Returns `{ networkRemoved: boolean; steps: string[] }`.
- **FR-1a resolver fix:** `src/lib/close-out.ts:557-570` local `findWorkspacePath` →
  replace with `findWorkspacePath` from `src/lib/lifecycle/archive-planning.ts:67` (which
  checks `workspaces/feature-<issue>`). This alone re-enables Step 3's gated worktree removal.
- **FR-1b close-out teardown:** `src/lib/close-out.ts:293-298` — call the shared name-based
  primitive (ungated by workspace-dir existence) and record a `Docker stack removed` step
  (or a warning step if the network survives).
- **FR-3 reaper:** `src/lib/cloister/reap-issue-residue.ts:17` `reapIssueResidue` — invoke the
  shared primitive (name-based, before/independent of the worktree-removal block at lines 50-62).
  Wired via `reconcileClosedIssueAgents` (`src/lib/cloister/closed-issue-reaper.ts:53`),
  which the deacon patrol runs (`src/lib/cloister/deacon.ts:2783`).
- **FR-2 guard:** `src/lib/workspace/rebuild-stack.ts:135` — inside the returned `Effect.gen`,
  first `yield* Effect.promise(() => isIssueClosed(issueId))`; if closed, `return { success:
  false, error: 'issue is terminal (closed/merged) — skipping stack rebuild' }`.

## Planning Q&A

`--auto` mode — no interactive questions. Auto-decisions:

- **AD-1: Shared teardown primitive rather than duplicating compose-down logic.** Both
  close-out (FR-1) and the reaper (FR-3) need name-based, workspace-dir-independent teardown
  with verification. One primitive in `workspace-manager/docker.ts` satisfies the
  single-source-of-truth tenet.
- **AD-2: FR-2 guard lives in `rebuildWorkspaceStack`, not in each caller.** It takes
  `issueId` and is the single chokepoint for all three autonomous callers; guarding it once
  is minimal and complete. The manual `pan workspace rebuild` CLI inherits the guard, which
  is acceptable — rebuilding a closed issue's stack is never desirable.
- **AD-3: FR-2 terminal predicate = `isIssueClosed` (closed/merged) only.** We do NOT block
  rebuild for `verifying-on-main` issues, because such an issue can be legitimately
  re-activated and needs its stack. The narrow closed/merged guard is the clearly-safe
  subset; the verifying-on-main nuance is recorded as a hazard, not enforced.
- **AD-4: NFR-1 is advisory (doctor check + docs), not an automated daemon.json edit.**
  Editing `/etc/docker/daemon.json` and restarting the Docker daemon requires root and would
  bounce every running container — unsafe for an agent to perform. Belt-and-suspenders per
  the issue ("a transient leak can't hard-block spawns").
- **AD-5: close-out Docker verification is best-effort — it records a warning step but does
  NOT fail the whole close-out.** Close-out is a terminal ceremony that also closes the tracker
  issue and archives artifacts; a Docker daemon that is down or a stubborn network must not
  block issue closure. The FR-3 reaper backstop is the safety net that retries teardown for any
  stack that survived close-out. Verified-removal means "attempt removal, then assert and log
  whether the network is gone", not "abort close-out if it isn't."
- **AD-6: tests ship in the same bead as the behavior they cover, not as separate beads.** A
  bug fix without its regression test is incomplete work (CLAUDE.md "Deliver Complete
  Features"); each behavior bead carries its own unit-test acceptance criterion.

## NonGoals

- Do NOT auto-edit `/etc/docker/daemon.json` or restart the Docker daemon.
- Do NOT block or alter rebuild for `verifying-on-main` issues that may re-activate.
- Do NOT change `postMergeLifecycle`'s existing merge-time Docker stop (it already uses the
  correct resolver); the durable owner is close-out + the reaper.
- Do NOT run `docker network prune -f` globally (it would touch non-Overdeck networks).
- Do NOT delete JSONL session files or workspace `.pan/` planning artifacts.

## Requirements

- **FR-1** Close-out runs a verified Docker teardown (containers + `_devnet` network removed, removal asserted) using the canonical workspace resolver.
- **FR-2** Autonomous stack rebuild no-ops for terminal (closed/merged) issues.
- **FR-3** The periodic/boot closed-issue reaper stops + removes leaked Docker stacks and `_devnet` networks, by project/network name, even when the workspace dir is gone.
- **NFR-1** `pan doctor` warns when the `_devnet` network count approaches the pool limit and when `daemon.json` lacks `default-address-pools`, printing the recommended snippet.
