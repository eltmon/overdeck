## Glossary

- **Admission queue** — the machine-wide FIFO queue in `src/lib/cloister/quality-gate-admission.ts`. A caller calls `acquireQualityGateAdmission(request, deps)`, waits for a slot, runs its heavy command, then calls `handle.release()`. State lives in files under `~/.overdeck/verification-workers/admission/` (`admissionRoot()`).
- **Slot** — one of `resources.quality_gate_slots` concurrent leases (default 2, global config only). Slot 0 is `owner.json`, slot i ≥ 1 is `slot-<i>.json`.
- **Ticket / waiter** — `waiter-<ticketId>.json`, one per queued caller. The oldest live ticket is the **head**; only the head may take a slot.
- **Owner record** — the JSON in a slot file: the ticket plus `acquiredAt`. Its `pid` is the process that holds the slot.
- **Gate** — any command that holds admission: a verification-worker quality gate (`runQualityGates` in `src/lib/cloister/validation.ts`), a local Vitest run (`tests/vitest-cpu-admission.ts`), and, after this change, each `tsc` lane.
- **tsc lane** — one `tsc --noEmit -p <tsconfig>` process. `npm run typecheck` runs 13 lanes in sequence; `npm run lint` runs 4 more inside `scripts/lint-effect-diagnostics.sh`.
- **Footprint key** — a string that names a gate kind for memory estimation: `tsc:<tsconfig>`, `vitest:<dir>` or `gate:<name>:<command>`.
- **Footprint estimate** — the bytes the queue assumes a gate will use at its peak: the largest of the last 5 recorded peaks for its key, or `DEFAULT_GATE_FOOTPRINT_BYTES` (2.5 GiB) when no peak exists.
- **Peak RSS** — the largest sum of `VmRSS` over a gate's process tree (the root process and all descendants) seen while the gate ran.
- **Reservation** — for an owner that is still running: `max(0, owner.footprintBytes − growth)`, where `growth = max(0, currentTreeRss(owner.pid) − owner.rssBaselineBytes)`. It is the memory the owner has been promised but has not allocated yet. An owner with `fullReservation: true`, or with no readable baseline or tree RSS, reserves its whole footprint until it releases.
- **RSS baseline** — `rssBaselineBytes`, the owner process tree's RSS measured just before the owner record is published. It removes the acquiring process's own memory (the verification worker, the wrapper, the Vitest main process) from the growth that counts against the reservation.
- **Soft reserve** — `resources.governor_soft_reserve_gb`, the memory governor's "hold new agents" level. This host sets 12 GiB.
- **MemAvailable** — `memAvailable` from `readProcMemory()` in `src/dashboard/server/services/proc-memory.ts` (Linux `/proc/meminfo`; macOS uses its own formula, PAN-4267).
- **Reentrancy env** — `OVERDECK_GATE_ADMITTED=1` (a parent already holds a slot), `OVERDECK_GATE_ADMISSION=0` (operator opt-out), `CI` (any non-empty value). Any of them makes a caller skip admission.

## Problem (verified against the code on 2026-11-14)

1. **Agent-shell typechecks never enter the queue.** `acquireQualityGateAdmission` has three callers: `src/lib/cloister/validation.ts` (`admission = await acquireQualityGateAdmission({`, around line 465), `tests/vitest-cpu-admission.ts` (Vitest `globalSetup`), and nothing else. Every `tsc` an agent starts runs unadmitted: the 13 lanes of `npm run typecheck` (`package.json` lines 113-122), the 4 lanes of `scripts/lint-effect-diagnostics.sh` (`LANES=(` at line 33, run at line 77 `if output=$("$TSC_BIN" --noEmit -p "$tsconfig" 2>&1); then`), `scripts/lint-dashboard-types.sh` line 50 and `scripts/lint-frontend-types.sh` line 52.
2. **The queue checks only CPU.** `sampleQualityGatePressure` (`quality-gate-admission.ts` line 127) reads CPU utilization, CPU PSI and load per core. Nothing reads MemAvailable. With 2 slots, two 2 GB+ gates can start on a host that is already short of memory.
3. **MemAvailable alone would not have stopped the incident.** Three typechecks started seconds apart. Each one samples memory before any of them has allocated, so each sees enough. The check must also subtract what already-admitted gates are about to allocate (their reservations).

Incident numbers (issue body): MemAvailable fell to 2.4 GiB with swap full; the overlapping lanes were `tsconfig.effect-diag.json` (2.4 GB), `src/dashboard/server/tsconfig.json` (2.2 GB) and a typecheck in `feature-pan-5233` (1.2 GB).

## Requirements

### Functional

- **FR-1** — Every `tsc` lane in the root `package.json` `typecheck` and `typecheck:*` scripts, and every `tsc` call in `scripts/lint-effect-diagnostics.sh`, `scripts/lint-dashboard-types.sh` and `scripts/lint-frontend-types.sh`, runs through `scripts/tsc-admitted.mjs`, which takes its own admission per `tsc` process. A chained `npm run typecheck` takes one slot per lane, one after another.
- **FR-2** — The admission queue checks memory. The head waiter waits while `MemAvailable − Σ reservations of live owners − ownFootprint < softReserve`. It is admitted on the first poll where that inequality no longer holds and the existing slot and CPU rules also pass.
- **FR-3** — Each gate's footprint estimate comes from measured peaks. After a gate exits on its own (an exit code, not a signal), its peak RSS is recorded under its footprint key. The estimate is the largest of the last 5 recorded peaks for that key. A key with no recorded peak uses `DEFAULT_GATE_FOOTPRINT_BYTES` = 2.5 GiB.
- **FR-4** — Owner and ticket records carry `footprintBytes` (the estimate the gate was admitted with). The memory check reads every live owner's `footprintBytes` and its current process-tree RSS to compute reservations.
- **FR-5** — The three callers pass footprint keys and record peaks: the tsc wrapper (`tsc:<tsconfig>`), the Vitest `globalSetup` (`vitest:<cwd relative to the repo root, or ".">`), and host verification gates in `validation.ts` (`gate:<name>:<raw gate.command>`). Container gates (`gate.container && gate.container_name`) also pass `gate:<name>:<raw gate.command>` plus `fullReservation: true`, so they wait on memory before they start and reserve their whole estimate until release; they record no peak, because their memory never appears in the host process tree. Remote (Fly) gates stay unadmitted, as today.
- **FR-6** — The reentrancy env keeps working: under `CI`, `OVERDECK_GATE_ADMISSION=0` or `OVERDECK_GATE_ADMITTED=1`, the wrapper runs `tsc` directly without loading `tsx` or the admission module, and Vitest keeps its current skip.
- **FR-7** — The wrapper is transparent to the ratchet scripts: it runs `node_modules/.bin/tsc` (relative to the current directory) with inherited stdio, exits with tsc's exit code, writes its own messages only to stderr, prefixes them `[gate-admission]`, and never writes text matching `error TS` or `    effect\(`.
- **FR-8** — A gate that waits on memory says so. The queue calls `deps.onWaiting(reason)` when the head waiter's blocking reason changes; the wrapper prints it to stderr, and `validation.ts` logs it through `opts.onLog` and `console.log` with the prefix `[quality-gate] Waiting for memory:`.
- **FR-9** — A memory-wait timeout never starts the gate. `QualityGateAdmissionTimeoutError` carries `lastWaitReason` (the kind of the last `onWaiting` reason). When the wrapper's 30-minute wait (`maxWaitMs: 30 * 60_000`, the same as Vitest's) ends with `lastWaitReason === 'memory'`, it prints `[gate-admission] refusing to start <key>: waited 30 minutes for memory (<details>)` to stderr and exits 75 without spawning tsc; the Vitest globalSetup throws an `Error` with the same text, which stops the run. Every other admission failure (a CPU or queue timeout, a file-system error, a failed import) fails open: warn `[gate-admission] proceeding without admission: <reason>` and run unadmitted, as Vitest does today.
- **FR-10** — Memory is checked again after the settle. After publishing its owner and waiting `settleMs`, the queue re-samples memory and re-evaluates the rule with the reservations of the other live owners (its own owner excluded; its own footprint still counted). When the rule fails, it removes its owner file, notifies `memory`, and keeps waiting at the head, exactly like the existing post-settle CPU check.
- **FR-11** — Owners record `rssBaselineBytes` (their tree RSS just before publishing), and reservations subtract only growth above that baseline (glossary "Reservation").
- **FR-12** — `QualityGateAdmissionRequest.fullReservation` (default false) makes an owner reserve its whole `footprintBytes` until release, whatever its tree RSS reads.

### Non-functional

- **NFR-1** — New wait, poll and sampling logic is tested with fake timers (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` / the existing `drive()` helper). No test waits on real wall-clock delay.
- **NFR-2** — The memory check fails open: when MemAvailable cannot be read (`memAvailable` ≤ 0 or the read throws), the memory rule is skipped and only the slot and CPU rules apply.
- **NFR-3** — An estimate never exceeds what the host could ever offer: `ownFootprint = min(estimate, max(0, memTotal − softReserve))`. A gate larger than the host can hold is still admitted once memory recovers, instead of waiting forever.
- **NFR-4** — Mixed versions share the admission directory: workspaces on older checkouts keep running their own admission code. New record fields are optional on read; an owner without `footprintBytes` reserves 0.
- **NFR-5** — No file passes its size cap (`scripts/lint-file-size.sh` applies only to non-test src files above 1000 lines). `quality-gate-admission.ts` is 481 lines; the memory arithmetic lives in the new `quality-gate-memory.ts`, and admission must stay at or below 650 lines.
- **NFR-6** — The new modules import nothing heavy. `quality-gate-memory.ts` and `process-tree-rss.ts` must not import `memory-governor.ts` or `runaway-process-patrol.ts` (both pull in dashboard routes, Docker stats and agent state, and risk `lint:circular`). `proc-memory.ts` and `config-yaml/load.js` are loaded with dynamic `import()` inside default deps, the way `resolveQualityGateSlots` already loads config.

## Decisions (made in this document)

- **D1 — Split.** PAN-5248 keeps the admission half; the container half is [PAN-5250](https://github.com/eltmon/overdeck/issues/5250). Both halves together touch about 40 files (finalize's projected-surface lint caps a plan at 25), and they share no code.
- **D2 — Wrapper, not a PATH shim.** `npm run` and `npx` put `node_modules/.bin` first on `PATH`, so a `tsc` shim in the agent guard directory (`src/lib/launcher-git-guard.ts` installs `git`/`gh` shims there) would never see the lanes that caused the incident. An explicit wrapper in each lane catches every `npm run typecheck`/`npm run lint` lane. An agent typing `npx tsc …` or `node_modules/.bin/tsc …` by hand stays unadmitted; that is a NonGoal, and the docs plus the ratchet scripts' `Reproduce:` hints point agents at the wrapper instead.
- **D3 — Wrapper runtime.** `scripts/tsc-admitted.mjs` is plain ESM. Its fast path (reentrancy env) uses only Node built-ins. Its admitted path calls `register()` from `tsx/esm/api` (tsx ^4.23.15 is a root devDependency) and then dynamically imports `../src/lib/cloister/gate-admission-run.ts` by `new URL(..., import.meta.url)`. Measured on this host: register + importing the admission module, `proc-memory.ts` and the global config loader takes about 0.7 s. With the existing 1.5 s settle and 0.25 s CPU sample, an idle host adds about 2.5 s per lane, about 30 s per full `npm run typecheck`. That cost is accepted; it buys the guarantee.
- **D4 — Reservation rule.** `reservation(owner) = owner.fullReservation || owner.rssBaselineBytes == null || treeRss == null ? (owner.footprintBytes ?? 0) : max(0, (owner.footprintBytes ?? 0) − max(0, treeRss − owner.rssBaselineBytes))`, with `treeRss = readTreeRssBytes(owner.pid)`. The baseline makes the reservation track the gate's own growth even though the owner pid is the acquiring process (the verification worker, the wrapper, the Vitest main process), not the gate command. Old-version owners have no `footprintBytes` and reserve 0. Owners whose process is dead are reclaimed by the existing stale-owner logic before the check runs. Vitest's recorded peak covers its whole tree, main process included, so its estimate runs high by the main process's RSS; that is conservative and accepted.
- **D5 — Estimate rule.** Estimate = max of the last 5 recorded peaks for the key; default 2.5 GiB. The max (not the last value) keeps Vitest keys conservative, because one key covers runs of very different sizes.
- **D6 — Peak sampling.** One sampler serves all three callers: `startPeakRssSampler(rootPid)` samples the tree once at start and every 2000 ms, and `stop()` returns the peak or `null` when no sample succeeded. Tree discovery reads `/proc/<n>/stat` for every numeric `/proc` entry and takes field 4 (ppid) after the last `)`, then reads `VmRSS:` from `/proc/<pid>/status` for tree members only (page-size independent). On non-Linux platforms the sampler returns `null` and no peak is recorded, so macOS keeps the default estimate. Roots: the wrapper samples its `tsc` child; Vitest samples `process.pid` (its forks are descendants); `validation.ts` samples `execPromise.child.pid` (the detached `nice -n 19 sh -c` group leader).
- **D7 — Recording rule.** A peak is recorded only when the gate exited on its own: wrapper child `code !== null`; Vitest teardown always; `validation.ts` on pass, or on failure when `typeof error.code === 'number'` and `!error.killed` and `!error.signal`. Timeouts and signals record nothing. Container gates never start a sampler, so they record nothing and keep the default (or any earlier recorded) estimate.
- **D8 — Footprint store.** One file per key under `<admissionRoot>/footprints/<sha256(key) first 24 hex>.json` holding `{ "key": string, "peaks": [{ "bytes": number, "at": number }] }` (newest last, at most 5). Writes go to a temp file in the same directory and `rename()` over the target. Two writers racing on one key can lose one peak; that is accepted. A missing or unparseable file reads as "no peaks". The `footprints` directory sits inside the admission root, which the existing scans ignore (`listSlotOwnerFiles` matches `owner.json`/`slot-<n>.json`, `listLiveTickets` matches `waiter-*.json` and `.tmp-*`).
- **D9 — Soft reserve source.** `resolveSoftReserveBytes()` reads `loadGlobalConfigNoMigration().config.resources.governorSoftReserveGb` (global config only, already normalized; verified to return 12 on this host), the same loader `resolveQualityGateSlots` uses. On any error it falls back to `computeGovernorReserveDefaultsGb(os.totalmem() / GiB).soft` from `src/lib/config-yaml/governor-reserves.ts`. No new config key is added (`config-yaml/schema.ts` and `merge.ts` sit at their allowlist caps).
- **D10 — Check order inside the loop.** Head check → slot scan (collecting the live owner records it reads) → memory check → CPU sample → measure `rssBaselineBytes` → publish owner → settle → CPU re-sample (unchanged) → memory re-check (FR-10: re-scan the slot files for other live owners, exclude its own owner, keep its own footprint). A failed re-check unlinks its own owner file only when `sameOwner(...)` still matches, exactly as the CPU branch does.
- **D11 — FIFO stays strict.** A head waiter blocked on memory blocks the waiters behind it, even smaller ones. That prevents starvation of large gates; the `onWaiting` message names the cause.
- **D15 — Fail closed on memory, open on everything else.** Only a timeout whose last wait reason was memory refuses to start (FR-9). Exit code 75 (`EX_TEMPFAIL`) tells the caller to retry later; the ratchet scripts report it as `failed (exit 75) without TypeScript diagnostics` and print the refusal line.
- **D12 — The handle records.** `QualityGateAdmissionHandle` gains `footprintBytes: number` and `recordPeak(peakBytes: number): Promise<void>`. `recordPeak` is a no-op when the request had no `footprintKey`, never throws (errors are swallowed), and writes to the store under the same admission root. Callers never import the store directly.
- **D13 — Keys.** Wrapper: `tsc:<value of -p/--project, leading "./" stripped>`, or `tsc:tsconfig.json` without `-p`. Vitest: `vitest:<path from the nearest ancestor directory that contains a .git entry to process.cwd()>`, `vitest:.` at that root or when none is found. Verification gate: `gate:<gate name>:<gate.command before placeholder substitution>` (placeholders such as `{{CHANGED_BASE}}` change per run and would fragment the key).
- **D14 — Log text.** `validation.ts` keeps its existing `Queued for CPU admission:` line (docs and operators grep it) and adds `[quality-gate] Waiting for memory: <details>` lines from `onWaiting`.

## Work items

### WI-1 — Process-tree RSS sampler (`process-tree-rss`)

**What/why:** the queue needs current tree RSS for reservations (FR-4) and every caller needs peak RSS (FR-3). A leaf module keeps the wrapper and Vitest from importing the runaway patrol's dashboard dependencies (NFR-6).

**File:** new `src/lib/system-health/process-tree-rss.ts`.

```ts
export interface ProcReader {
  listPids(): Promise<number[]>            // numeric entries of /proc
  readStat(pid: number): Promise<string | null>
  readStatus(pid: number): Promise<string | null>
}
export async function readProcessTreeRssBytes(rootPid: number, reader?: ProcReader, platform?: NodeJS.Platform): Promise<number | null>
export interface PeakRssSampler { stop(): Promise<number | null> }
export function startPeakRssSampler(rootPid: number, opts?: { intervalMs?: number; read?: (pid: number) => Promise<number | null> }): PeakRssSampler
```

Steps:
1. `readProcessTreeRssBytes` returns `null` when `platform !== 'linux'` or the root's status cannot be read. It builds a ppid map from every pid's `stat` (ppid = the 2nd whitespace field after the last `)`), walks descendants of `rootPid` breadth-first, sums `VmRSS:` kB × 1024 from each member's `status`, and skips members whose status vanished mid-walk.
2. `startPeakRssSampler` calls `read(rootPid)` immediately, then every `intervalMs` (default 2000) with an `unref()`'d `setInterval`; it tracks the max non-null value; `stop()` clears the interval, awaits any in-flight read, and returns the max or `null`.
3. Default `ProcReader` uses `fs/promises` `readdir('/proc')`, `readFile('/proc/<pid>/stat')`, `readFile('/proc/<pid>/status')`, returning `null` on ENOENT/ESRCH.

**Tests:** new `src/lib/system-health/__tests__/process-tree-rss.test.ts` with an in-memory `ProcReader`: a 3-process tree with an unrelated sibling sums only the tree; a `comm` containing `) (` still parses ppid; a vanished member is skipped; non-Linux returns `null`. Sampler with fake timers: max across ticks, `stop()` returns `null` when every read is `null`, no read after `stop()`.

### WI-2 — Footprint store and memory headroom (`quality-gate-memory`)

**What/why:** FR-2, FR-3, D5, D8, D9 and NFR-3 as pure, injectable functions the queue calls.

**File:** new `src/lib/cloister/quality-gate-memory.ts`.

```ts
export const DEFAULT_GATE_FOOTPRINT_BYTES = 2.5 * 1024 ** 3
export const GATE_FOOTPRINT_HISTORY = 5
export function footprintStoreDir(admissionRoot: string): string            // join(root, 'footprints')
export async function readGateFootprintEstimate(key: string, admissionRoot: string): Promise<number>
export async function recordGateFootprintPeak(key: string, peakBytes: number, admissionRoot: string, now?: () => number): Promise<void>
export async function resolveSoftReserveBytes(): Promise<number>
export interface MemoryHeadroomInput {
  memAvailableBytes: number; memTotalBytes: number; softReserveBytes: number
  estimateBytes: number; reservationsBytes: number
}
export interface MemoryHeadroomVerdict {
  ok: boolean; footprintBytes: number /* clamped */; headroomBytes: number
}
export function evaluateMemoryHeadroom(input: MemoryHeadroomInput): MemoryHeadroomVerdict
export function ownerReservationBytes(owner: { footprintBytes?: number; rssBaselineBytes?: number; fullReservation?: boolean }, treeRssBytes: number | null): number
```

Rules: `evaluateMemoryHeadroom` clamps `footprintBytes = min(estimateBytes, max(0, memTotalBytes − softReserveBytes))`, computes `headroomBytes = memAvailableBytes − reservationsBytes − footprintBytes`, `ok = headroomBytes >= softReserveBytes`. `ownerReservationBytes` implements D4: the whole `footprintBytes ?? 0` when `fullReservation` is true, `rssBaselineBytes` is undefined, or `treeRssBytes` is null; otherwise `max(0, footprint − max(0, treeRss − baseline))`. `recordGateFootprintPeak` ignores non-finite or ≤ 0 peaks, keeps the newest 5, writes `.tmp-<pid>-<n>-<name>` then `rename()`, and creates the directory with `mkdir({ recursive: true })`. Note the temp name starts with `.tmp-<pid>-`, inside the `footprints/` subdirectory, so the admission root's temp sweep never sees it.

**Tests:** new `tests/unit/lib/cloister/quality-gate-memory.test.ts`: default estimate with no file; estimate is the max of recorded peaks; the 6th record drops the oldest; a torn file reads as default; clamp on a host smaller than the estimate; `ok` flips exactly at `headroom == softReserve`; reservation floors at 0; a 1 GiB baseline with a 1.1 GiB tree and a 2.5 GiB footprint reserves 2.4 GiB; a missing baseline, a `null` tree RSS or `fullReservation: true` reserves the whole footprint; `resolveSoftReserveBytes` falls back when the config loader throws (mock `../config-yaml/load.js`).

- New exported type:

  | { kind: 'queue' }
  | { kind: 'slots' }

- Before publishing the ticket: `estimate = footprintKey ? await readFootprintEstimate(key) : 0`; store it as `ticket.footprintBytes` (omit the field when no key).

- Update the module header comment (lines 8-15) to say admission checks CPU and memory.

## Hazards

- **H1 — Mixed versions.** Workspaces not rebased onto this change keep running unadmitted lanes and memory-blind admission against the same directory. Their owners carry no `footprintBytes` and reserve 0 (NFR-4). Nothing to do but rebase.
- **H2 — Wrapper cost.** About 2.5 s per lane on an idle host (D3). Do not "optimize" by dropping the settle step; it belongs to the CPU rule.
- **H3 — Agent Bash timeouts.** An agent's Bash tool can kill a lane while it is queued. The wrapper's ticket is reclaimed by pid liveness, as Vitest's is today.
- **H4 — Over-conservative estimates.** A Vitest key's max-of-5 can stay high after one large run; it decays only after 5 smaller runs. Accepted (D5).
- **H6 — Verification can stall on memory.** Verification gates call acquire with no `maxWaitMs`, so a host that sits near the soft reserve holds every keyed verification gate with only `Waiting for memory:` log lines. This is the intended protection (the issue asks gates to wait); the operator relieves it by freeing memory or lowering `resources.governor_soft_reserve_gb`.
- **H5 — Test env leakage.** Under Vitest, `OVERDECK_GATE_ADMITTED=1` is set in `process.env` by the globalSetup. Ratchet-script tests must set `OVERDECK_GATE_ADMISSION: '0'` explicitly so they never depend on that.

## Critique response

Round 1 (`.pan/drafts/PAN-5248-critique.md`, codex/gpt-6-sol). Every blocking finding changed the design.

### memory timeout starts unsafe typechecks

Accepted. FR-9 now fails closed on memory only: `QualityGateAdmissionTimeoutError` carries `lastWaitReason` (WI-3b), and when it is `'memory'` the wrapper prints `refusing to start` and exits 75 without spawning (WI-4, D15), and the Vitest globalSetup throws (WI-10). CPU and queue timeouts, file-system errors and import failures still fail open, as today. WI-4 tests that a memory timeout never calls `spawn`.

### memory is stale after settling

Accepted. FR-10 and WI-3b add a post-settle memory re-check: re-scan the other live owners (own owner excluded, own footprint counted), re-sample MemAvailable, and on failure remove the owner file (guarded by `sameOwner`) and keep waiting. WI-3b test 1 lowers MemAvailable during the settle and asserts the owner file is gone and the waiter is still queued.

### owner RSS does not match the measured gate

Accepted. FR-11 and D4: each owner records `rssBaselineBytes`, its tree RSS just before it publishes, and the reservation subtracts only growth above that baseline. The verification worker, the wrapper and the Vitest main process therefore no longer shrink a reservation for a gate that has allocated nothing. A missing baseline or an unreadable tree reserves the whole footprint. WI-2 and WI-3 test a 1 GiB baseline with a 1.1 GiB tree (2.4 GiB reserved).

### container gates bypass low-memory protection

Accepted. FR-5 and FR-12: container gates pass `gate:<name>:<command>` and `fullReservation: true`, so they wait on MemAvailable before starting and reserve their whole estimate until release. Their memory is then counted twice while they run (once in MemAvailable, once as a reservation); that is conservative and accepted until container measurement lands with PAN-5250. WI-11 asserts the flag.

### test the host gate recording path

Accepted (sharpens-framing). WI-11 now asserts that a passing host gate calls `recordPeak` with the sampler's peak before `release`, and that a killed gate records nothing.

### Unresolved after two critic rounds

- queued waiters can bypass low memory on timeout
- dashboard ratchet discards refusal exit code
