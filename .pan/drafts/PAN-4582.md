# PAN-4582 — Herdr: one tab per agent, PTYs sized at launch and at view, restored shells reaped

**Issue:** [PAN-4582](https://github.com/eltmon/overdeck/issues/4582)
**Related:** [PAN-3952](https://github.com/eltmon/overdeck/issues/3952) (1-row viewports on unviewed panes; work item W4 resolves its sizing ask), [PAN-4586](https://github.com/eltmon/overdeck/issues/4586) (`pane.read` response shape; filed during this planning, out of scope here).

## Glossary

- **Herdr** — the default terminal backend: a headless `herdr --session <s> server` driven over a unix-socket NDJSON API (`src/lib/terminal-backends/herdr-api.ts`). Version on this host: herdr 0.9.1, protocol 22.
- **Workspace / tab / pane** — Herdr's hierarchy. A workspace holds tabs; a tab holds one or more panes laid out by splits; each pane owns one terminal (`terminal_id`) and one PTY.
- **Overdeck-owned workspace** — a Herdr workspace carrying the `issue` token (`workspace.report_metadata`). Issue workspaces carry `issue=<ISSUE-ID>`; operator conversations share one workspace with `issue=conversations` (`CONVERSATIONS_WORKSPACE` in `src/lib/terminal-backends/launch.ts`).
- **Layout rect** — the rectangle Herdr's layout gives a pane (`pane.layout` → `layout.panes[].rect {width,height}`). With no TUI client attached the tab area is 120x40.
- **PTY size** — the kernel window size of the pane's terminal (`stty -F <tty> size`). This is what the harness draws into.
- **Observe stream** — `herdr --session <s> terminal session observe <terminalId> [--cols N --rows N]`: read-only NDJSON frames. Many may attach.
- **Control stream** — `herdr ... terminal session control <terminalId> [--cols N --rows N]`: frames out on stdout, `terminal.input` / `terminal.resize` in on stdin. Only one may attach at a time.
- **Residue shell** — a pane in an Overdeck-owned workspace that carries no `agentId` token, has no Herdr-detected agent, and runs only its shell (foreground process is the shell itself).
- **Two-sighting rule** — the reaper closes a residue shell only when two consecutive sweeps both saw it as residue.

## Verified facts (probed 2026-10-24 on a throwaway `herdr --session pan4582probe server`)

These are the facts the design rests on. Each was observed, not inferred.

1. **Splitting halves the tab.** `HerdrBackend.startAgent` calls `pane.split {workspace_id, direction:'down'}` (`src/lib/terminal-backends/herdr.ts` line 587, `'pane.split'`). Live on the `overdeck` session right now, tab `w2:t3` holds 8 conversation panes and `herdr pane layout --pane w2:p15` gives the newest a rect `height: 1` and `w2:p16` a rect `height: 0`. Issue workspaces hold the root shell plus the agent, so a work agent gets 20 of 40 rows before any reviewer arrives.
2. **`tab.create` returns the new tab's root pane.** `tab.create {workspace_id, cwd, env, label, focus:false}` answers `{"type":"tab_created","tab":{tab_id,…},"root_pane":{pane_id, terminal_id, workspace_id, tab_id, …}}`. The root pane's rect is the full tab area (120x40). `env` and `cwd` reach the shell (probe printed `ENV=tab-env-ok PWD=/home/eltmon`). `focus:false` leaves focus where it was.
3. **A new PTY copies the size of the session's focused pane, not its own rect.** With the focused pane at 10 rows, `tab.create` (and even `workspace.create` in another workspace) produced a PTY of `10 120` under a 40x120 rect. With the focused pane at 40 rows, new PTYs were `40 120`. On the live session the focused pane is `w2:p15` at 1 row, so `tab.create` alone would still launch harnesses into 1-row PTYs.
4. **The headless server never pushes the layout rect to the PTY.** A pane whose rect grew from 20 to 40 kept its old PTY size indefinitely.
5. **Only a control attach resizes the PTY.** `observe --cols 90 --rows 25` left the PTY unchanged. `control --cols 100 --rows 30` set the PTY to `30 100` on attach. `{"type":"terminal.resize","cols":110,"rows":35}` on control's stdin set it to `35 110`. The size persists after the control stream closes. `pane.resize` changes split ratios only; no other API method sets a PTY size (checked against `herdr api schema --json`).
6. **Observe frames render at the observer's own size and never follow the PTY.** `observe --cols 80 --rows 20` reported every frame as `width 80, height 20` even after the PTY was resized to 100x30; `observe` without dims reported 120x40 while the PTY was 31x101.
7. **Control frames follow their own resizes.** A control stream opened at 80x20 and resized to 100x30 emitted a new `full:true` frame at `100x30`, then incremental frames at `100x30`.
8. **A second controller is refused, not stolen.** While one control stream was attached, a second exited 0 after writing `{"reason":"terminal attach failed: terminal … already has an attached client; retry with --takeover","type":"terminal.closed"}` to stderr and nothing to stdout. The first kept control.
9. **Closing a tab's only pane closes the tab; closing a workspace's last pane closes the workspace.**
10. **`tab.create` announces its root pane as `pane_created`.** On the subscription list `HerdrBackend.events()` uses, `tab.create` produced `pane_created` for the root pane, then `pane_updated` with the stamped tokens, so the backend inventory sees a tab-launched agent at once, as it did a split pane. `toBackendEvents` needs no change.
11. **The dashboard never resizes a Herdr PTY.** `serveHerdrTerminal` (`src/dashboard/server/ws-terminal.ts` line 190) sends the snapshot control frame with `cols: attach.cols, rows: attach.rows`. `XTerminal.tsx` sets `requestedSize` to the snapshot dims, so `sendResizeIfNeeded` finds the measured size equal and sends no `resize`. `HerdrTerminalProcess` (`src/dashboard/server/services/terminal-service.ts` line 252) opens the controller lazily on the first write or resize, so the PTY is never resized and long lines clip at the right edge.

## Problem

Every Herdr agent launch splits a pane out of the workspace's current tab, so all operator conversations share one tab and each new one gets half of the remaining rows. The newest conversation's PTY ends up 0–1 rows tall; Claude Code cannot draw there, the observe snapshot is blank, and the dashboard Terminal tab shows nothing. Even in a tab of its own, a new PTY inherits the focused pane's size (fact 3), so a launch while a cramped pane holds focus still starts the harness in a 1-row terminal. After a Herdr restore with `resume_agents_on_restore = false`, the old conversation panes come back as bare shells that nothing closes, and they keep their share of the tab forever. Finally, the dashboard Terminal tab never sizes the PTY to its viewport, so long lines clip.

## Proposal

1. Launch every Herdr agent into its **own new tab** (`tab.create`) in its workspace — conversations and issue workspaces alike — and run the launcher in that tab's root pane.
2. Before the launcher runs, **size the new PTY to its layout rect** with a short-lived control attach (`--cols <width> --rows <height>`), then release the controller. This also resolves [PAN-3952](https://github.com/eltmon/overdeck/issues/3952)'s sizing ask.
3. Make the dashboard's Herdr terminal bridge **take control at attach** with the viewer's dims and **read output from its control stream**, so the PTY matches the viewer from the first frame and follows later viewport resizes. When control is refused, fall back to a read-only observe stream.
4. Add a **host-hygiene reaper** that closes residue shells in Overdeck-owned workspaces, guarded by the two-sighting rule and never closing a workspace's last pane.

## Decisions (made here; the executor does not re-decide them)

- **D1 — One tab per agent in every Herdr workspace.** Conversations and issue workspaces both use `tab.create`. Rationale: an issue workspace with the work agent, four reviewers, synthesis and test reaches 7 panes and hits the same 40/2^N collapse; one rule is simpler than two.
- **D2 — The tab label is the agent name** (`spec.name`, else `spec.tokens.role`). Tab labels are display-only in Herdr; nothing reads them back.
- **D3 — The PTY is sized to the root pane's layout rect** (`rect.width` cols, `rect.height` rows), read with `pane.layout {pane_id}` right after `tab.create`. Sizing is skipped when the rect is missing or either side is below 2. A sizing failure is logged and never fails the launch.
- **D4 — Sizing releases the controller before the launch continues.** The helper waits for the control child to exit before it resolves, so a dashboard viewer that attaches right after launch is not refused (fact 8).
- **D5 — The dashboard bridge controls eagerly.** `HerdrTerminalProcess` opens the control stream in its constructor with the viewer's dims (this resizes the PTY, fact 5) and pumps output from the control stream's frames (fact 7). A control stream that ends before delivering its first `snapshot` or `output` frame counts as refused: the bridge opens an observe stream at the current dims and becomes read-only (writes and resizes are dropped). Trade-off accepted: a second viewer of the same terminal is read-only while the first holds control. That is already true today as soon as the first viewer types or resizes.
- **D6 — The reaper runs in the host-hygiene scheduler** (`src/lib/cloister/hygiene-scheduler.ts`), once at startup and every 10 minutes, and returns `[]` when the Deacon is frozen (`isDeaconGloballyPaused()`), when the host backend is tmux, or when Herdr is unavailable — the same freeze rule `reapOrphanedDashboardServers` and `reapLeftoverPlaywrightBrowsers` follow.
- **D7 — Reaper selection rule.** A pane is closed only when ALL hold: its workspace carries a non-empty `issue` token; the pane has no `agentId` token; the pane has no detected agent (`agent` null/absent); `paneProcessLiveness` answers `'exited'` (foreground process is the shell); the same `pane_id|terminal_id` key was a candidate in the previous sweep; and it is not the workspace's only remaining candidate when every pane in that workspace is a candidate (keep one pane so the workspace survives). `'indeterminate'` always keeps the pane.
- **D8 — Two sightings, not process age.** The two-sighting rule needs no `ps` call and works on every platform. It covers the millisecond windows where a fresh tab's root pane or a fresh workspace's root shell is a bare, untokened shell. Sighting state is in memory only; a restart just delays the first close by one interval.
- **D9 — No re-layout of panes that already share a tab.** Panes stacked before this change keep their tab until they exit. Their dashboard Terminal tab renders correctly after W5, because the bridge resizes the PTY to the viewer at attach.
- **D10 — `pane.read` shape bug is out of scope.** Filed as [PAN-4586](https://github.com/eltmon/overdeck/issues/4586).

## Requirements

### Functional

- **FR-1** Every Herdr agent launch (`HerdrBackend.startAgent`, both detection paths) creates a new tab with `tab.create` and runs the launcher in that tab's root pane; `startAgent` no longer calls `pane.split`.
- **FR-2** The new tab's label is the agent name (`spec.name ?? spec.tokens.role`).
- **FR-3** Before `pane.send_input` sends the launcher, the new terminal's PTY is set to the root pane's layout rect through a control attach with `--cols`/`--rows`.
- **FR-4** A failed, refused or timed-out sizing attempt is logged and the launch continues.
- **FR-5** `TerminalControl` (`src/lib/terminal-backends/types.ts`) exposes the control stream's frames as `frames: AsyncIterable<TerminalFrame>`, and `controlTerminal` returns them.
- **FR-6** `sizeHerdrTerminal(terminalId, cols, rows, deps)` in `herdr-stream.ts` resolves `'sized'` on the first snapshot or output frame, `'refused'` when the stream ends first, `'timeout'` after `timeoutMs` (default 3000), and resolves only after the control child has exited (bounded wait 1000 ms). It never throws.
- **FR-7** `HerdrTerminalProcess` opens its control stream at construction with the requested dims, emits output from the control stream's frames, and forwards `write`/`resize` to it.
- **FR-8** When the control stream ends before its first snapshot/output frame and the bridge was not closed, `HerdrTerminalProcess` opens an observe stream at the current dims and emits its output; `write` and `resize` become no-ops.
- **FR-9** `reapHerdrResiduePanes()` closes residue shells per D7 and returns one action string per closed pane.
- **FR-10** The reaper never closes a pane that carries an `agentId` token, a pane with a detected agent, a pane whose liveness probe is `'running'` or `'indeterminate'`, a pane in a workspace without an `issue` token, a pane seen as residue in only one sweep, or the last kept pane of a workspace whose panes are all residue.
- **FR-11** The reaper returns `[]` without calling Herdr when the Deacon is frozen, the host backend is tmux, or `probeHerdrAvailability()` reports unavailable.
- **FR-12** `startHygieneScheduler()` runs the reaper once at startup and then every 10 minutes.
- **FR-13** `docs/TERMINAL-BACKENDS.md`, `docs/DASHBOARD-ARCHITECTURE.md` and `configuration/terminal-backend.mdx` describe tab-per-agent launches, launch-time PTY sizing, the eager controller and its read-only fallback, and the residue reaper.

### Non-functional

- **NFR-1** `src/lib/terminal-backends/herdr.ts` ends at or below 1008 lines (its `origin/main` count and allowlist row). Never raise the allowlist row.
- **NFR-2** No `execSync` or other blocking call in any code reachable from the dashboard server; everything here is async.
- **NFR-3** Unit tests never spawn the real `herdr` binary and never touch a real socket. Every delay (the sizing deadline, the child-exit wait) is tested with `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`, never real `setTimeout` waits.
- **NFR-4** `src/dashboard/frontend/src/components/XTerminal.tsx` is not modified (it sits at 1069 lines against a 1075 row, and the fix is server-side).
- **NFR-5** No new HTTP route (so no `no-loss-matrix.ts` row is needed).

## Repo rules that intersect this work (restated)

- **Fake timers for delay tests.** Any test exercising a deadline or wait uses `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`; never real sleeps, never `maxForks: 1`.
- **No `execSync` in dashboard-reachable code** (PAN-70). The reaper and the bridge run inside the dashboard server.
- **File-size ratchet.** `scripts/lint-file-size.sh` compares each file to its `origin/main` line count or its `scripts/file-size-allowlist.txt` row. `herdr.ts` is at 1008 = its row. If a change would grow it, extract code to a new module; never raise a row.
- **Tests must not read source files** and must not add `skipIf`/`.only` (the lint and test-skip gates reject both).
- **Herdr request text must be well-formed UTF-16** — `herdr-api.ts` already sanitizes; do not bypass `HerdrApiClient.call`.
- **New lib modules that need agent state import `getAgentState` from `agent-state-read.js`**, never `agent-state.js` (circular-import lint). The reaper needs no agent state.
- **Quality gates before `pan done`:** `npm run typecheck`, `npm run lint`, and `npx vitest run <the test files touched>`. Never run the full `npm test` on the host.
- **Never experiment on the live `overdeck` Herdr session.** Use the throwaway recipe in "Implementation checkpoint" below.

   ```ts
   /** The two Herdr stream openers; the real ones in production, fakes in tests. */

     readonly observe: (terminalId: string, deps: { cols: number; rows: number }) => TerminalObservation;
   }
   ```

An `exit` frame (or iterator end) on the control stream BEFORE any snapshot/output frame, while `this.ended` is false, means control was refused: set `this.controller = null`, open `this.observation = streams.observe(terminalId, { cols: this.cols, rows: this.rows })`, log once (`[terminal-service] Herdr terminal <id> is controlled by another client; serving it read-only`), and pump the observation. **Why:** FR-9–FR-12 — after a Herdr restore, old panes come back as idle shells that nothing closes.

1. Module shape (copy the conventions of `src/lib/cloister/playwright-mcp-reaper.ts`: a pure selection function plus a thin runner that returns `string[]`):
   ```ts

   export interface ResiduePaneView {
     readonly paneId: string;
     readonly terminalId: string;
     readonly workspaceId: string;
     readonly hasAgentId: boolean;
     readonly detected: boolean;
     readonly process: 'running' | 'exited' | 'indeterminate';

   export interface ResidueSelection {
     /** Panes to close now. */
     readonly close: readonly ResiduePaneView[];
     /** Candidate keys (`paneId|terminalId`) to remember for the next sweep. */

   }

   export function selectHerdrResiduePanes(input: {
     readonly ownedWorkspaceIds: ReadonlySet<string>;
     readonly panes: readonly ResiduePaneView[];
     readonly previous: ReadonlySet<string>;

   export interface HerdrResidueReapDeps {
     readonly isPaused?: () => boolean;                         // default isDeaconGloballyPaused
     readonly herdrApi?: () => Promise<HerdrApiClient | null>;  // null on a tmux host or when Herdr is unavailable
     readonly processLiveness?: (paneId: string, api: HerdrApiClient) => Promise<'running' | 'exited' | 'indeterminate'>; // default paneProcessLiveness
   }

   export async function reapHerdrResiduePanes(deps?: HerdrResidueReapDeps): Promise<string[]>;

   /** Test seam: no production caller (PAN-3958 CH-8). */
   export function _resetHerdrResidueSightingsForTests(): void;
   ```
2. Selection (`selectHerdrResiduePanes`), per D7: consider only panes whose `workspaceId` is in `ownedWorkspaceIds`. A candidate has `!hasAgentId && !detected && process === 'exited'`. 3. Runner: return `[]` when `isPaused()`; `herdrApi()` returns null (default: `hostTerminalBackendName()` is not `'herdr'`, or `probeHerdrAvailability()` reports unavailable — both from `src/lib/terminal-backends/select.ts`; then `getHerdrApiClient()`).
