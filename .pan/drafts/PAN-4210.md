# PAN-4210: Deferred work-agent handoffs never retried (Deacon freeze + stale planning label)

**Issue:** [PAN-4210](https://github.com/eltmon/overdeck/issues/4210)
**Related:** PAN-4155 (introduced the journal-driven retry, commit `cfc84da28a1`, PR #4177)
**Planning mode:** `pan plan --auto`, 2026-09-25

## Summary

The issue says the retry for a guardrail-deferred planning hand-off lives in
memory and dies on a dashboard restart. That is not what the code does. PAN-4155
already stores the retry schedule in the pipeline journal and re-reads it on every
60-second deacon-lite tick, and a test already proves it resumes after a restart.

The retry never ran on 2026-09-25 for two other reasons, verified on this machine:

1. **The Deacon is frozen.** `app_settings` in `~/.overdeck/overdeck.db` holds
   `deacon.globally_paused = 'true'`, set 2026-09-18T11:11:23Z. `runDeaconLite()`
   returns before any routine runs, so `retryDeferredHandoffs` never reads a
   journal. The five journals (PAN-4197/4198/4199/4200/4201) each still hold exactly
   one line, `handoff.deferred`. Nothing retried, stood down, or gave up. `pan start`
   still worked because POST `/api/agents` does not read the freeze flag.
2. **The stand-down check trusts a stale status label.** Even without the freeze,
   the first due tick would have abandoned every one of these hand-offs as
   "planning was restarted after the deferral". `operatorStandDownReason` stands
   down when `planning-<issue>/state.json` says `status: 'running'`. Since the
   PAN-3917 Cut, `saveAgentStateAndEmitEvent` appends an event and writes no
   `state.json`, so the planning agent's label stays `running` forever after spawn.
   All five `planning-pan-*/state.json` files read `running`, with an mtime equal to
   their spawn time, while `dashboard.log` shows `[complete-planning] Marked
   planning-pan-4197 as stopped` for each of them.

This plan fixes defect 2 and makes defect 1 visible. The retry keeps honoring
the Deacon freeze, because the freeze is the operator's emergency stop. A deferral
made while frozen now says the retry is held, and `pan show` shows the hold. The
operator's immediate remedy is to unfreeze the Deacon (sidebar Snowflake toggle,
or `POST /api/deacon/pause {"paused":false}`). This plan does not flip that flag.

## Glossary

- **Hand-off / auto-handoff:** after `pan plan finalize` with auto-start consent,
  complete-planning POSTs `/api/agents` once to start the work agent
  (`completePlanningAutoSpawn`, `src/lib/overdeck/planning-promotion.ts`).
- **Deferral:** a spawn guardrail (agent ceiling, leaked specialists, critical RAM,
  stale health snapshot) refused that POST. complete-planning journals
  `handoff.deferred` instead of `planning.failed` (PAN-4155).
- **Pipeline journal:** `<workspace>/.overdeck/pipeline.jsonl`, append-only,
  written by `appendPipelineEntry` (`src/lib/cloister/pipeline-journal.ts`). It is a
  log of actions, never authority.
- **Deacon-lite:** the 60-second patrol loop (`src/lib/cloister/deacon-lite.ts`)
  that runs in the forked deacon child (`src/dashboard/server/deacon-main.ts`). It
  holds six routines; the sixth is `retryDeferredHandoffs`.
- **Deacon freeze / global pause:** the persisted flag `deacon.globally_paused` in
  `app_settings` (overdeck.db). Read by `isDeaconGloballyPaused()`
  (`src/lib/overdeck/control-settings.ts:151`). Toggled by the sidebar
  `DeaconPauseToggle` (Snowflake icon) and `POST /api/deacon/pause`. When `true`,
  every deacon-lite tick returns at `deacon-lite.ts:497` before running any routine.
- **Stand-down:** `retryDeferredHandoffs` ends a deferral without calling it a
  failure because the operator already acted; it journals `handoff.abandoned` with
  `outcome: 'stood-down'`.
- **Status label:** the `status` field in `~/.overdeck/agents/<id>/state.json`. It is
  written at spawn and by explicit stop paths (`pan kill`), never by the
  complete-planning stop projection. It is a snapshot, not liveness.
- **Live inventory:** `liveAgentInventory()` (`src/lib/terminal-backends/inventory.js`),
  the selected terminal backend's list of live panes. `null` means unreadable.

## Current behavior (verified references)

### Deacon-lite short-circuits on the freeze

`src/lib/cloister/deacon-lite.ts:493-505` (search `export async function runDeaconLite`):

```ts
export async function runDeaconLite(): Promise<void> {
  if (isDeaconGloballyPaused()) return;
  await checkStuckWorkAgents();
  ...
  // PAN-4155: re-send a planning hand-off a spawn guardrail refused.
  await retryDeferredHandoffs();
}
```

`startDeaconLite()` (`deacon-lite.ts:550`) runs one patrol at once, then one every
`DEACON_LITE_INTERVAL_MS = 60_000`. A restart therefore re-derives pending hand-offs
from the journal on boot already. The existing test `resumes the schedule from the
journal after a restart`
(`src/lib/cloister/__tests__/deacon-lite-retry-deferred-handoff.test.ts`, the
second `it` in `describe('retryDeferredHandoffs')`) proves it at the module level.
The issue's own acceptance test ("seeds a journal with a recent `handoff.deferred`,
boots the retry scheduler, and asserts the start is re-attempted") is covered by that
test. WI-2 adds the same assertion at the `startDeaconLite()` level, on the
incident's exact shape.

### The stand-down check reads status labels

`src/lib/cloister/deferred-handoff.ts:91-117` (search `function operatorStandDownReason`):

```ts
  const work = readAgentState(workAgentId);
  if (work) {

```

## Requirements

- **FR-1:** `operatorStandDownReason` never stands down on a `status` label alone. A
  planning agent counts as "restarted" only when its `startedAt` is later than the
  deferral's `deferredAt`.
- **FR-2:** A work agent blocks the retry only when its pane is in the live inventory,
  it is paused, or its `startedAt`/`stoppedAt` is later than `deferredAt`. A
  `running`/`starting` label with an older `startedAt` and no live pane does not
  block the retry.
- **FR-2a:** When the retried spawn is refused because a work-agent start is already
  in flight (`409` with `code: 'AGENT_START_IN_FLIGHT'`), the retry stands down
  instead of classifying it as a guardrail refusal and retrying for two hours.
- **FR-3:** A test that boots deacon-lite with `startDeaconLite()`, with a seeded
  `handoff.deferred` whose `nextRetryAt` has passed and a seeded
  `planning-<issue>/state.json` with `status: 'running'`, asserts that the work-agent
  spawn is re-attempted.
- **FR-4:** While `isDeaconGloballyPaused()` is `true`, deacon-lite does not
  re-attempt the spawn and appends nothing to the journal. On the first tick after
  the flag clears, it re-attempts from the journal.
- **FR-5:** When complete-planning journals a deferral while the Deacon is frozen,
  the `handoff.deferred` entry carries `data.deaconPaused: true`, and the warn-level
  activity line says the retry is held until the Deacon is unfrozen and names
  `pan start <ISSUE>`.
- **FR-6:** The complete-planning JSON response for a journaled deferral made while
  frozen carries `workAgentRetryHeld: 'deacon-paused'`, and its `message` says the
  retry is held while the Deacon is frozen instead of promising a retry.
- **FR-7:** `pan plan finalize` and `pan plan done` print the held message when the
  response carries `workAgentRetryHeld: 'deacon-paused'`, and the existing
  "retried automatically for up to 2 hours" line otherwise.
- **FR-8:** `pan show <id>` prints a hold line under the pipeline block when the
  journal's last `handoff.*` entry is `handoff.deferred` or `handoff.retried` and the
  Deacon is frozen at the time of the command.
- **FR-9:** `docs/PIPELINE-GATES.md` states that the Deacon freeze holds the retry,
  what happens on unfreeze (including give-up past the two-hour window), and the
  timestamp-based stand-down rule.
- **NFR-1:** Retry timing tests use `vi.useFakeTimers()` and
  `vi.advanceTimersByTimeAsync()`. No real `setTimeout` waits.
- **NFR-2:** No new stored status. The hold is derived from the freeze flag (live)
  and recorded only as a fact in the journal entry written at deferral time.
- **NFR-3:** The retry still sends no guardrail acknowledgement.

## Decisions

- **D1: The retry honors the Deacon freeze.** The freeze is the operator's
  emergency stop (Snowflake toggle, top-of-app banner). An automated spawn must not
  bypass it. Alternative (not chosen): exempt `retryDeferredHandoffs` from the
  freeze, because auto-start consent was already granted and guardrails still apply
  on the retry. The operator can flip this later by moving the call out from under the
  `isDeaconGloballyPaused()` return in `runDeaconLite`.
- **D2: The two-hour window keeps counting while frozen.** On unfreeze, a deferral
  older than `DEFERRED_HANDOFF_WINDOW_MS` gives up on the first tick. That path is
  already loud: `planning.failed stage=auto-handoff` and a warn activity line that
  names `pan start`. No freeze-aware clock math.
- **D3: Drop status-label checks; keep facts.** The live inventory, `paused`,
  `startedAt` and `stoppedAt` are facts. `status` is a spawn-time snapshot. Agent
  state is written only after the terminal-backend pane exists, so a genuinely
  running or starting agent is either in the live inventory or has a `startedAt`
  later than the deferral.
- **D4: The hold is shown, not stored.** `pan show` reads the freeze flag live. The
  journal records `deaconPaused: true` only as the fact at deferral time.
- **D5: Fix the stale comment, not the projection.** Making the planning stop
  projection write `state.json` again is a wider change to the agent-state model
  (PAN-3917 removed that write on purpose). WI-3 only corrects the comment so it
  no longer claims a row write.

  `vi.advanceTimersByTimeAsync()`, never real delays.

  dashboard server. `isDeaconGloballyPaused()` is a synchronous SQLite read, which
  the file's other callers already use. Do not add child-process calls.

  `npx vitest run <touched test files>`. Never run the full `npm test` on the host.

  A file that grows past its `origin/main` line count needs an allowlist row in the
  same commit (`<lines> <path> # PAN-4210`).
- **Journal discipline:** append only, written at the moment of the action, never
  rewritten. No new stored status.
