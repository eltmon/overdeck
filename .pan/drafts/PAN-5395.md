# PAN-5395: Work agents in single-repo projects never start — untracked Overdeck sync output reads as a dirty workspace

**Issue:** https://github.com/eltmon/overdeck/issues/5395

## Glossary

- **Single-repo project.** A project whose `workspace.type` is not `polyrepo`. Each issue workspace is one linked git worktree at `<project>/workspaces/feature-<issue>/`, made from the project's own repository. Code calls this "monorepo".
- **Polyrepo wrapper.** For a `workspace.type: polyrepo` project, the workspace root is a separate git repo that Overdeck creates. PAN-5199 heals that repo's `.gitignore`. This issue does not change wrappers.
- **Sync output.** Files Overdeck writes into a workspace's `.claude/` directory when it creates the workspace or launches an agent: skills, agent definitions, the merged Claude settings, the MCP server config, the sync manifest and the caveman variant marker. These files are never the user's work product.
- **Dirty-workspace start gate.** The check in `spawnIssueAgentForRoute` (`src/dashboard/server/routes/agents/spawn-issue.ts`) that runs `git status --porcelain --untracked-files=all` and returns HTTP 409 `WORKSPACE_DIRTY` when a path is not Overdeck-owned.
- **Worktree exclude file.** `<gitdir>/info/overdeck-exclude` in a linked worktree's private git dir. The worktree's `core.excludesFile` (set with `git config --worktree`, which needs `extensions.worktreeConfig=true`) points at it. It hides untracked paths from `git status` and `git add` in that worktree only. The primary checkout and other worktrees do not see it. `src/lib/git/worktree-exclude.ts` (PAN-4852) owns this file. It stores one block per owner (`# overdeck:<owner> begin` … `# overdeck:<owner> end`). Deft and SageOx already write blocks there.
- **Common `info/exclude`.** `<common gitdir>/info/exclude`. Every worktree of the repository and the primary checkout share it. This plan never writes it.

## Problem

The OKF-11 work agent (project `okf`, single-repo) never started. Every start from 16:29 to 17:10 UTC on 2026-11-15 was refused. `~/.overdeck/agents/agent-okf-11/lifecycle.log` records `agent.start_refused_dirty_workspace`, and the porcelain listed only files Overdeck wrote (`.claude/…`, `.overdeck/`) plus the project's own `scripts/__pycache__/`.

Cause, verified against the code at `6a6e5f38220`:

- `src/dashboard/server/routes/agents/spawn-issue.ts`, line 110, `isOnlyOverdeckRuntimeWorkspaceChanges`. It tolerates untracked sync paths only when `options.polyrepoWrapper === true` (line 117: `|| (options.polyrepoWrapper === true && status === '??' && isOverdeckWorkspaceSyncPath(path))`).
- The gate at line 709 (`if (statusOut.trim() && !isOnlyOverdeckRuntimeWorkspaceChanges(statusOut, { polyrepoWrapper: Boolean(polyrepoWorkspace) }))`) returns 409 for a single-repo workspace that has untracked `.claude/settings.json`, `.claude/mcp.json`, `.claude/agents/*.md` and similar files.
- `.overdeck/` is already tolerated everywhere by `isOverdeckWorkspaceRuntimePath` (`src/lib/state-plane.ts`, line 95). The `.claude/` files are the actual blocker.
- The okf `.gitignore` lists only `.claude/skills/` (written by `ensurePanGitignore`, `src/lib/workspace-manager/migration.ts`, line 205, from `OVERDECK_PROJECT_GITIGNORE_ENTRIES`). Sync also writes `.claude/agents/`, `.claude/settings.json`, `.claude/settings.local.json`, `.claude/mcp.json`, `.claude/.overdeck-manifest.json` and `.claude/.caveman-variant`. Any project that does not gitignore all of them hits the same refusal.

The okf workspace (`git status --porcelain --untracked-files=all --ignored`, run during planning) showed these sync files outside `.claude/skills/`. The exact set is: `.claude/.caveman-variant`, `.claude/.overdeck-manifest.json`, `.claude/agents/pan-*.md`, `.claude/mcp.json`, `.claude/settings.json` and `.claude/settings.local.json`. `settings.local.json` was written about five hours after workspace creation, by an agent launch (`src/lib/providers.ts`, line 711; `src/lib/claude-settings-overlay.ts`, line 113).

**A second failure sits right after the start gate.** The `pan done` preflight (`src/lib/work/done-preflight.ts`, `filterUncommittedPorcelainLines`, line 57) and the approve gate (`src/dashboard/server/routes/workspaces/merge-ops.ts`, line 76, `shouldBlockApproveForDirtyStatus`) use `isOverdeckOwnedOnlyStatus` (`src/lib/state-plane.ts`). It does not know about sync paths either. So even if the start gate tolerated `?? .claude/settings.json`, the agent would stall again at `pan done`. Or it would "fix" the stall by committing the files. That is a credential leak: in the okf workspace, `.claude/mcp.json` holds a Linear API bearer token copied from `~/.claude/mcp.json` by `copyOverdeckSettingsToWorkspace` (`migration.ts`, line 98).

## Decision: issue Fix option 1, through the existing worktree exclude file

The issue asks the PR to choose one of two fixes and state the choice. **This plan chooses option 1**: at workspace creation (and on every start, to repair existing workspaces), hide Overdeck's sync output with an exclude block that is local to the clone and never committed. The PR description must say "Fix option 1 (local exclude), worktree-scoped".

Why option 1 and not option 2 (drop the `polyrepoWrapper` condition):

1. Option 2 fixes only the start gate. `pan done` preflight and the approve gate still see `?? .claude/…` as uncommitted work, so the stall moves downstream.
2. Option 2 leaves the files visible to `git add -A`. A work agent can then commit and push `.claude/mcp.json` (credentials) and `.claude/settings.json` (merged operator settings) into the user's repository. Option 1 makes `git add -A` skip them.
3. Option 1 fixes every git-status gate at once, with no change to any predicate.

How option 1 is done:

- **Worktree scope, never common `info/exclude`.** Writing the common file (what the operator did by hand for okf) would also hide these paths in the user's primary checkout. A user who wants to commit `.claude/settings.json` there would no longer see it. The worktree exclude file affects only the issue workspace. The cost: `setExcludeBlock` sets `extensions.worktreeConfig=true` in the repository's shared `.git/config`. This is now true for every single-repo project, not only Deft/SageOx opt-ins. Git ≥ 2.20 supports it. For a normal non-bare repository it changes nothing else. This plan accepts that cost.
- **Reuse `src/lib/git/worktree-exclude.ts`.** A worktree has one `core.excludesFile`. A second exclude file would fight Deft and SageOx for it. Add a new owner `sync` to the `ExcludeOwner` union. The owner must be lowercase letters only, because `BLOCK_LINE` is `/^# overdeck:([a-z]+) (begin|end)$/`. `workspace-sync` would not parse.
- **Exact, root-anchored patterns, not `.claude/`.** The blanket `.claude/` entry in `OVERDECK_WORKSPACE_ROOT_SYNC_ENTRIES` suits an Overdeck-owned wrapper. In a user's repository it would hide the project's own new files, such as `.claude/commands/x.md`. The pattern list is the set of files Overdeck writes, each anchored with a leading `/` so that a nested `src/.claude/settings.json` stays visible (verified in a scratch repo during planning):

  ```
  /.claude/skills/
  /.claude/agents/pan-*.md
  /.claude/settings.json
  /.claude/settings.local.json
  /.claude/mcp.json
  /.claude/.overdeck-manifest.json
  /.claude/.caveman-variant
  ```

  This matches the overdeck repo's own `.gitignore` (lines 112–129 and 206 list exactly these files). The agents pattern is narrowed to `pan-*.md` because every shipped agent definition in `sync-sources/agents/` is `pan-*.md` (`pan-merge-agent.md`, `pan-review-agent.md`, `pan-test-agent.md`, `pan-uat-agent.md`, `pan-work-agent.md`), so a project's own `.claude/agents/my-agent.md` stays visible.
- **Accepted trade-off: new project files under these exact paths go silent.** Today an untracked `.claude/settings.json` refuses the start loudly. After this change, a project's first `.claude/settings.json`, `.claude/settings.local.json` or `.claude/mcp.json` created inside an issue workspace is hidden from `git status` and `git add -A`, and must be added with `git add -f`. Overdeck overwrites or merges into these files in every workspace anyway, and two of them can hold credentials, so hiding them is the safer default. Both doc paragraphs (WI-4) say `git add -f`.
- **No `.overdeck/` or `.pan/` patterns.** The gates already tolerate both through `isOverdeckWorkspaceRuntimePath`. Also, `.overdeck/memory/` and `.pan/drafts|specs/` are committed work product. Hiding them would break `git add` for `pan memory add` and plan finalize.
- **Primary checkout is skipped.** When `excludeTarget(workspacePath).scope === 'common'` (the path is not a linked worktree), the helper writes nothing and returns `skipped`.
- **Non-fatal.** Any git or filesystem error is caught and returned as a warning. Workspace creation and agent start continue. If the exclude could not be written, the start gate then refuses as it does today.
- **Polyrepo unchanged.** Wrappers keep the PAN-5199 `.gitignore` heal and the `polyrepoWrapper` predicate branch. The new call runs only when the project is not polyrepo.
- **Predicate unchanged.** `isOnlyOverdeckRuntimeWorkspaceChanges` keeps its exact behavior. Its existing test "rejects … without the polyrepoWrapper option" stays as it is.

## Requirements

- **FR-1.** Workspace creation for a single-repo project writes a `sync` owner block with the seven patterns above into the worktree exclude file of the new workspace.
- **FR-2.** Every agent start for a single-repo project with a local workspace writes (or confirms) the same block before the dirty-workspace gate runs `git status`, so workspaces created before this fix are repaired.
- **FR-3.** In a single-repo workspace whose only untracked files are sync output and `.overdeck/` runtime files, the start gate proceeds. `git status --porcelain --untracked-files=all` lists none of the seven sync paths, and `isOnlyOverdeckRuntimeWorkspaceChanges` returns `true` on its output.
- **FR-4.** Untracked paths outside the seven patterns stay visible and keep refusing the start. Examples are `.claude/notes.md`, `.claude/commands/x.md`, `src/.claude/settings.json` and `scripts/__pycache__/x.pyc`.
- **FR-5.** The primary checkout's `git status` and the common `info/exclude` file do not change.
- **FR-7.** When the worktree's own `core.excludesFile` already points at a file other than `<gitdir>/info/overdeck-exclude` (and other than the legacy `<gitdir>/info/overdeck-deft-exclude`, which `setExcludeBlock` migrates), the helper changes nothing and returns `skipped` with a warning naming that file. The existing worktree ignore rules keep applying.
- **FR-6.** A lifecycle log entry `agent.workspace_sync_exclude` records the result whenever the start-time call writes the block or returns a warning.
- **NFR-1.** All new git calls are async (`execFile` through `worktree-exclude.ts`). No `execSync` reaches the dashboard server (repo rule: no `execSync` in server-reachable code).
- **NFR-2.** The helper never throws. Errors become a `warning` string in its result.
- **NFR-3.** The helper is idempotent. A second call with the block already present returns `unchanged` and rewrites nothing.
- **NFR-4.** `src/dashboard/server/routes/agents/spawn-issue.ts` stays at or under 1000 lines (file-size guard `scripts/lint-file-size.sh`, CEILING=1000; it is 940 lines today). The helper logic lives in a lib module, and the route adds only the call.

   ```ts
   /**
    * PAN-5395: hide Overdeck's .claude/ sync output from git in a single-repo
    * issue workspace, through the worktree-scoped exclude file
    * (src/lib/git/worktree-exclude.ts, owner `sync`). Never writes the common
    * info/exclude: a path that is not a linked worktree is skipped. Never throws.
    */
   import { execFile } from 'node:child_process';
   import { homedir } from 'node:os';
   import { dirname, join, resolve } from 'node:path';
   import { promisify } from 'node:util';
   import { excludeTarget, readExcludeBlock, setExcludeBlock } from '../git/worktree-exclude.js';
   import { OVERDECK_WORKSPACE_SYNC_EXCLUDE_PATTERNS } from '../workspace-sync-paths.js';

   const execFileAsync = promisify(execFile);
   /** Same name as worktree-exclude.ts's private constant; export that one instead if the reviewer prefers. */
   const LEGACY_DEFT_EXCLUDE_NAME = 'overdeck-deft-exclude';

   function expandHome(path: string): string {
     return path === '~' || path.startsWith('~/') ? join(homedir(), path.slice(1)) : path;
   }

   export interface WorkspaceSyncExcludeResult {
     status: 'written' | 'unchanged' | 'skipped';
     /** Exclude file path when status is written or unchanged. */
     file?: string;
     /** Set when a git or filesystem error stopped the write; status is then 'skipped'. */
     warning?: string;
   }

   /** The worktree's core.excludesFile, or null when unset or unreadable. */
   async function worktreeExcludesFile(workspacePath: string): Promise<string | null> {
     try {
       return (await execFileAsync('git', ['config', '--worktree', '--get', 'core.excludesFile'], { cwd: workspacePath })).stdout.trim() || null;
     } catch {
       return null;
     }
   }

   export async function ensureWorkspaceSyncExclude(workspacePath: string): Promise<WorkspaceSyncExcludeResult> {
     try {
       const target = await excludeTarget(workspacePath);
       if (target.scope !== 'worktree') return { status: 'skipped' };
       const configured = await worktreeExcludesFile(workspacePath);
       const configuredPath = configured === null ? null : resolve(workspacePath, expandHome(configured));
       // A worktree excludes file that Overdeck did not write: setExcludeBlock would repoint
       // core.excludesFile away from it and its rules would stop applying. Leave it alone.
       // The pre-PAN-4852 Deft file is not foreign: setExcludeBlock migrates its patterns.
       if (configuredPath !== null && configuredPath !== target.file
         && configuredPath !== join(dirname(target.file), LEGACY_DEFT_EXCLUDE_NAME)) {
         return { status: 'skipped', warning: `worktree core.excludesFile points at ${configuredPath}, not ${target.file}; left unchanged` };
       }
       const wanted: readonly string[] = OVERDECK_WORKSPACE_SYNC_EXCLUDE_PATTERNS;
       const current = await readExcludeBlock(workspacePath, 'sync');
       const blockMatches = current !== null && current.length === wanted.length && current.every((p, i) => p === wanted[i]);
       // The block alone is not proof: core.excludesFile must point at the file too.
       if (blockMatches && configuredPath === target.file) {
         return { status: 'unchanged', file: target.file };
       }
       await setExcludeBlock(workspacePath, 'sync', wanted);
       return { status: 'written', file: target.file };
     } catch (error) {
       return { status: 'skipped', warning: error instanceof Error ? error.message : String(error) };
     }
   }
   ```

   `setExcludeBlock` points the worktree's `core.excludesFile` at the file, which is why the `unchanged` path checks that pointer as well.

## Hazards

- **`extensions.worktreeConfig=true`** is now set in every single-repo project's `.git/config` on its first workspace. This is harmless for non-bare repos without `core.worktree`. If a repo sets `core.worktree` in its common config, git's worktree-config rules apply. That case is rare and accepted.
- **Concurrent starts** can race on `git config`'s lock. The helper returns a warning, the gate may refuse once, and the next start retries and succeeds.
- **The global excludes copy is a snapshot.** In worktree scope, the exclude file starts with a copy of the global excludes file taken at write time. This is accepted PAN-4852 behavior.
- **New project files at the seven paths are hidden.** A project's first `.claude/settings.json`, `.claude/settings.local.json` or `.claude/mcp.json` created in an issue workspace needs `git add -f`. The docs say so. A project's own `.claude/agents/<name>.md` stays visible unless its name starts with `pan-`.
- **Deft/SageOx teardown.** With a `sync` block present, `removeExcludeBlock(…, 'deft'|'sageox')` keeps the exclude file and the `core.excludesFile` pointer instead of deleting them. `src/lib/deft/uninstall.ts` (`clearWorktreeWiring`, lines 141–150) only unsets the pointer when it names the legacy Deft file, and the SageOx removal (`removeSageoxPlacement`) does not touch exclude config. So neither depends on the file being deleted, and no change is needed.
- **The test import path.** Importing `isOnlyOverdeckRuntimeWorkspaceChanges` from `spawn.js` already works in `agents-spawn-dirty-workspace.test.ts` (with `activity-logger.js` mocked). Copy that mock if the import side effects need it.

## Critique response

### Reported workspace still refuses to start

No design change. The issue's Fix section says it plainly: "`scripts/__pycache__/` was produced by the okf project's own Python. It is not Overdeck output, so leave it to the project's `.gitignore`." This plan fixes the class of failure, which is Overdeck's own sync output blocking every single-repo start. It does not fix OKF-11's project-specific tool output. OKF-11 is already unblocked on this machine. The operator's local unblock added `__pycache__/` (with `.claude/` and `.overdeck/`) to `~/Projects/okf/.git/info/exclude`, which was verified during planning: that file holds those three lines. Editing okf's tracked `.gitignore` belongs to the okf project, not to an Overdeck PR, and the issue rules it out. The NonGoals keep `__pycache__` refusing the start on purpose. That way the gate still protects a project's real untracked files.

### Existing worktree ignores can disappear

Accepted, and the design is changed. `setExcludeBlock` rebuilds `overdeck-exclude` from the global, local or system excludes plus the owner blocks. It then repoints the worktree's `core.excludesFile`, so a foreign worktree-level excludes file would silently stop applying. `ensureWorkspaceSyncExclude` now reads `git config --worktree --get core.excludesFile` first. When that value names a file other than the target `overdeck-exclude` or the legacy Deft file, the helper returns `skipped` with a warning and writes nothing (FR-7). The new test `leaves a foreign worktree excludes file alone` proves that the pointer and its rules survive. The warning reaches the lifecycle log through WI-3, and the start gate then behaves as it does today.

### Route test bypasses the route

This finding sharpens the framing but does not block the design. The route-level test proves the contract the route depends on: real porcelain after the helper satisfies the unchanged predicate. Driving `spawnIssueAgentForRoute` itself would mean booting its whole Effect route stack (issue data service, terminal backend, guardrails), and no existing test does that. The ordering, helper before `git status`, is a three-line change that the WI-3 acceptance criterion pins and review checks against the diff.
