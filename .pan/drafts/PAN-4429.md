# PAN-4429 — Remove TLDR entirely

**Issue:** https://github.com/eltmon/overdeck/issues/4429 · supersedes PAN-1674 (closed).
**Mode:** auto-planned 2026-09-29 against `c00ec0c7afa` (main was one commit ahead with no TLDR changes).

## Glossary

- **TLDR** — the `llm-tldr` Python tool plus Overdeck's integration around it: a Claude Code `Read` hook that returns an outline instead of the file, a per-workspace Python venv, an index daemon, cost metrics, a Settings toggle, two skills and docs.
- **Read hook / `tldr-read-enforcer`** — `sync-sources/hooks/tldr-read-enforcer`, a PreToolUse hook on `Read`. It denies a Read of a code file over 3 KB and injects a ~1K-token outline. `tldr-post-edit` is its PostToolUse partner on `Edit|Write`; it marks files dirty and re-warms the index.
- **Bin dir** — `~/.overdeck/bin/` (`BIN_DIR`). `pan sync` copies hook scripts there; `~/.claude/settings.json` points at them.
- **Hook registration** — an entry under `hooks.<HookType>[].hooks[].command` in `~/.claude/settings.json`. Written by `applyOverdeckHookRegistrations()` in `src/lib/claude-hooks-registration.ts`.
- **Manifest prune** — `syncHooks()` in `src/lib/sync-hooks.ts` (lines 123-135, PAN-3881) deletes a bin-dir file whose `sync-sources/hooks/` source was deleted, if sync wrote it.
- **Daemon pidfile** — `<checkout>/.tldr/daemon.pid`, written by the `tldr` binary itself (`tldr-daemon.ts` `getPidFilePath()` lines 204-207).
- **No-loss map** — `tests/unit/lib/overdeck/no-loss-matrix.ts` (enforced by `no-loss-matrix.test.ts`: every live HTTP route needs a row) plus the prose ledger `docs/THE-CUT.md`.
- **Deleted-subject exemption** — PAN-3906: the test-skip gate allows deleting tests whose subject was deleted. Never re-add tests to satisfy it.
- **Prompt-Change trailer** — `scripts/check-prompt-change-trailer.sh` (`npm run lint:prompt-trailer`, part of `npm run lint`): when `roles/*.md` changes, some commit on the branch must carry a body line `Prompt-Change: <why>`.

## Problem

The Read hook's header claims "saving 90-95% of context tokens". A 14-day audit of 2,071 transcripts found 282 denials. Within 8 tool calls after a denial, 74.5% re-read the file with offset/limit, 13.8% read it through Bash, 3.9% re-read it in full, and only 7.8% worked from the outline. 161 of 282 denials ended with ≥80% of the file read back. Each denial also costs an extra model turn and ~250 ms. Every new workspace pip-installs CPU torch + `llm-tldr` (~1.5 GB, up to 5 min) and starts a daemon, even when `agents.tldr.enabled` is false; 18 copies filled the disk on 2026-09-29.

## Decision

Delete every TLDR code path (not deprecate). Migrate existing installs: unregister the hooks from `~/.claude/settings.json` *before* deleting their scripts, stop running daemons, never delete `.venv`/`.tldr/` directories. Keep exactly one thing from `feature/pan-1674`: the disk-space guard commit `70fe945e5d6`.

```ts
/** Hook scripts Overdeck used to ship and now removes from existing installs (PAN-4429). */
export const RETIRED_HOOK_SCRIPT_NAMES = ['tldr-read-enforcer', 'tldr-post-edit'] as const;

/** Pure: drop every settings.json hook entry whose command references a retired
 *  script, in either `<binDir>/<name>` or literal `overdeck/bin/<name>` form.

 *  matcher group only when all of its hooks were retired (same rule as
 *  pruneLegacyPanopticonHook). */
export function pruneRetiredOverdeckHooks(settings: ClaudeSettings, binDir: string): string[]

/** Migration for pan sync / pan install. Order: read settings.json → prune →
 *  backup + atomic write (only if changed) → delete `<binDir>/<name>` for each
 *  retired name → remove mcp.json `mcpServers.tldr` when its command ends with
 *  `tldr-mcp`. Returns { unregistered, deletedBins, mcpRemoved, warning? }. */
export async function retireTldrHooks(opts: { settingsPath?: string; binDir?: string; mcpPath?: string } = {}): Promise<RetireResult>
```

Decision rules:
- Model the pure prune on `pruneLegacyPanopticonHook` (`claude-hooks-registration.ts` ~line 152, anchor `export function pruneLegacyPanopticonHook`). Iterate every hook type present in `settings.hooks`, not only PreToolUse/PostToolUse.
- Reuse `backupSettings`, `atomicWriteJson`, `pruneBackups` exactly as `provisionClaudeHooks` does (`claude-hooks-provision.ts` ~lines 132-134).
- Unparseable `settings.json`: do not write it; return a `warning`; **still delete the bin files**. Rationale: Claude Code loads no hooks from an invalid settings file, and `syncHooks()`' manifest prune would delete them anyway.
- Missing `settings.json`, bin files or mcp.json: no-op, no error.
- Under `process.env.VITEST` with no explicit `settingsPath`, return without touching real files (same guard as `provisionClaudeHooks` lines ~73-79).
- This function must not depend on `jq` or `python3`.

Workspace-local copies: `copyOverdeckSettingsToWorkspace` (`src/lib/workspace-manager/migration.ts` ~83-130) merges the global `~/.claude/settings.json` hooks into each workspace's untracked `<workspace>/.claude/settings.json` and copies `~/.claude/mcp.json` to `<workspace>/.claude/mcp.json`. ```ts
