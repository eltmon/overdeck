# PAN-5006: `pan lane start --machine auto` prints no reason when Auto picks this machine

**Issue:** [eltmon/overdeck#5006](https://github.com/eltmon/overdeck/issues/5006)
**Found in:** the live three-machine gauntlet check for #4638 (2026-11-04, `pan` 0.73.1).

## Glossary

- **Auto placement** — `--machine auto`. The pure rule `choosePlacement` in
  `src/lib/anywhere/placement.ts` picks one machine from this machine plus the visible linked
  machines, and answers a `PlacementAnswer` (`packages/contracts/src/machines.ts`, line 129).
- **Reason line** — the string `placementReason()` builds, for example
  `Auto → desk (CPU pressure 3%, 41 GB free, 2 agents)` (`placement.ts`, `export function placementReason`).
- **Rejection** — a `PlacementRejection` `{ environmentId, label, reason }` for each machine Auto
  passed over, with a reason such as `offline`, `no project`, `no docker`, `CPU saturated` or `reserved`.
  `choosePlacement` already returns them on success: `{ ok: true, …, reason, rejections }`.
- **Home** — the machine that runs `pan lane start` and its dashboard. **This machine** = home.
- **`FleetTarget`** — the union `resolveTargetMachine` answers
  (`src/dashboard/server/services/fleet-target.ts`, `export type FleetTarget`): `self: true`,
  `self: false` with a `link`, or `ok: false` with a refusal.
- **`RemoteLaneTarget`** — the lane core's description of a linked machine to launch on
  (`src/lib/lanes/launch.ts`, `export interface RemoteLaneTarget`).
- **`resolveMachine`** — the `LaneLaunchDeps` dependency that turns a `--machine` value into a
  target (`launch.ts`, `resolveMachine?: (machine: string, needs…`). `POST /api/lanes` supplies
  it as `laneMachineResolver` (`src/dashboard/server/routes/lanes.ts`).
- **`machine` field** — `LaneLaunchResult.machine` (`src/lib/lanes/types.ts`): the linked machine
  that runs the lane, `null` for a lane on this machine. It is load-bearing: see D-2.

## Problem

`configuration/linked-machines.mdx` ("Auto placement") says Auto "picks a machine for you and
prints why". `pan lane start --machine auto` prints the reason only when Auto picks a linked
machine. When Auto picks this machine, it prints nothing, and the JSON result has
`"machine": null`, exactly like a launch with no `--machine`. The operator cannot tell that Auto
ran, which machines it passed over, or why.

From the #4638 run (home tagged `docker, gpu, linux`; the Mac `ios-sim, macos`; the Fly VM `linux`):

```
$ pan lane start --role play --key auto --machine auto ... --json
Auto → fly-8d4101ae001028 (CPU pressure 0%, 1 GB free, 0 agents)        # stderr
{ ..., "machine": { "label": "fly-8d4101ae001028", "reason": "Auto → fly-8d4101ae001028 (...)" } }

$ pan lane start --role critic --for twice --machine auto --needs docker ... --json
{ ..., "machine": null }                                                 # no Auto line at all
```

Placement was right (the critic ran on home); only the explanation is missing.

## Root cause (verified 2026-11-04 against `de146272ac8`)

1. `resolveTargetMachine`'s auto branch (`fleet-target.ts`, lines 137 and 139) copies
   `answer.reason` into the `FleetTarget` but drops `answer.rejections`:

   ```ts
   if (answer.self) return { ok: true, self: true, environmentId: answer.environmentId, label: answer.label, reason: answer.reason };
   const link = links.find((candidate) => candidate.environmentId === answer.environmentId)!;
   return { ok: true, self: false, link, environmentId: link.environmentId, label: link.label, reason: answer.reason };
   ```

2. `laneMachineResolver` (`routes/lanes.ts`, line 174) drops the reason for a self pick:

   ```ts
   if (target.self) return null;
   ```

3. `launchLane` (`launch.ts`, line 414) reads `null` as "this machine" and returns
   `machine: null` (line 656), so the result has no reason.

4. `src/cli/commands/lane.ts` line 258 prints only `result.machine?.reason`:

   ```ts
   if (result.machine?.reason) deps.stderr(result.machine.reason);
   ```

## Decisions

- **D-1 (auto mode default): a new sibling field `placement` on `LaneLaunchResult`.**
  `placement: { label: string; reason: string; rejections: PlacementRejection[] } | null`.
  It is set whenever the `--machine` value resolved with a non-null reason (Auto, including the
  Fly fallback string), for a pick of this machine *and* for a pick of a linked machine. It is
  `null` when `--machine` is absent, names a machine explicitly, or comes from `--reuse`.
- **D-2: `machine` keeps its meaning "null = runs here".** Rejected alternative: put the self
  pick into `machine` with `self: true` (the `fleet-work.ts` `machineOf` precedent). That would
  change three load-bearing readers: `handleLaneLaunch` (`lanes.ts` line 209,
  `if (result.machine) deps.follow(result.conversation.name);`) would start the remote-lane
  follower on a local conversation; the CLI (`lane.ts` line 281) would print the
  `… on <label> in <cwd>` form for a local lane; and three tests assert `machine` is null for a
  local lane (`lanes-route-machine.test.ts` line 132, `views-remote.test.ts` line 102,
  `launch-remote.test.ts` line 311). The sibling field changes none of them.
- **D-3: `machine.reason` stays.** A remote Auto lane still has `machine.reason` set (the same
  string as `placement.reason`) so older readers keep working. The CLI reads
  `result.placement?.reason ?? result.machine?.reason`, so a new CLI against an older dashboard
  still prints the reason, and no case prints it twice.
- **D-4: the passed-over line.** When `placement.rejections` is non-empty the CLI prints a
  second stderr line, right after the reason line:
  `Passed over: <label>: <reason>; <label>: <reason>`
  (labels and reasons in the order `choosePlacement` returns them, joined by `; `). It prints for
  an Auto pick of this machine and of a linked machine alike. With no rejections it prints
  nothing. `noMachineFits()` is not reused, because its `No machine fits:` prefix is wrong on a
  success.
- **D-5: an explicit `--machine <this machine's label>` prints nothing.** `resolveTargetMachine`
  answers `reason: null` there; nothing was chosen, so there is nothing to explain.
- **D-6: `resolveMachine` returns a discriminated value.** Its return type becomes
  `Promise<RemoteLaneTarget | LocalLanePlacement | null>`, where
  `LocalLanePlacement = { self: true; label: string; reason: string; rejections: PlacementRejection[] }`.
  `null` still means "this machine, nothing to explain". `RemoteLaneTarget` gains
  `rejections: PlacementRejection[]`. Only the `--machine` call site (line 414) keeps a
  placement; the `--reuse` site (line 418) and the stop site (line 481) treat a
  `LocalLanePlacement` exactly as they treat `null` today.
- **D-7: `FleetTarget` gains optional `rejections?: readonly PlacementRejection[]`** on both
  `ok: true` variants, set only in the auto branch (lines 137, 139) and in the auto Fly fallback
  (line 133, from `answer.rejections`). It is optional so `startFlyTarget`, the explicit-machine
  branches and the fleet routes (`fleet-work.ts`) need no change.
- **D-8: The JSON output of `--json` is the raw result**, so it gains `placement` with no CLI
  change. The MCP `lane_start` tool (`src/lib/mcp/tools-lanes.ts` line 48) passes the
  `/api/self/lanes` body through untyped, so it gains `placement` with no change either.

## Requirements

- **FR-1** — `pan lane start --machine auto` prints the reason line on stderr when Auto picks
  this machine (for example `Auto → home (CPU pressure 0%, 31 GB free, 2 agents)`).
- **FR-2** — The `POST /api/lanes` 201 body carries `placement: { label, reason, rejections }`
  whenever Auto chose the machine, for this machine and for a linked machine.
- **FR-3** — When Auto passed over one or more machines, the CLI prints
  `Passed over: <label>: <reason>; …` on stderr after the reason line.
- **FR-4** — `placement` is `null` when `--machine` is absent, names a machine explicitly, or
  the machine came from `--reuse`; the CLI prints no reason and no passed-over line then.
- **FR-5** — `machine` stays `null` for a lane Auto placed on this machine, and home does not
  start the remote-lane follower for it.
- **NFR-1** — No change to the output of `pan worker run`, `pan start --machine` or fleet
  conversation spawns; `FleetTarget`'s new field is optional and those callers ignore it.
- **NFR-2** — The reason line for a remote Auto pick is printed exactly once.
