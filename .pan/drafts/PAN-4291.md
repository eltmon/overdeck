# PAN-4291 — Stop draining the GitHub GraphQL budget; sample the right counter

**Issue:** [PAN-4291](https://github.com/eltmon/overdeck/issues/4291) · **Builds on:** PAN-4264 (the quota ledger, `runGh`, pause gate, sampler)

## Summary

Overdeck spends most of the operator's 5,000-point hourly GitHub GraphQL budget on its own polling, and its quota display under-reports that spend. Four causes are fixed here:

1. The sampler reads REST `GET /rate_limit` → `resources.graphql`, which does not match what `/graphql` charges. GraphQL `rateLimit(dryRun: true)` returns the real numbers for free.
2. The deacon's 60-second closed-issue reaper asks GitHub "is there a merged PR for this branch?" for every closed-but-unmerged branch on every tick, through an unmetered `gh` exec.
3. The PR cache (`readRepoPullRequests`) lists 200 PRs of every registered project every ~30 s, including projects with no git remote and projects on the skipped list, and the ledger prices each call at 1 point when GitHub charges 3 per 100-PR page.
4. The pause gate waits a flat 10 minutes when its (wrong) sample shows budget left, so pauses outlive the real reset.

## Glossary

- **GraphQL budget / bucket** — GitHub's 5,000 points per hour per identity for `/graphql`. Ledger bucket `graphql`. REST (`core`) is a separate 5,000-request bucket, ledger bucket `rest`.
- **`rateLimit(dryRun: true)`** — a GraphQL field that returns `limit`, `used`, `remaining`, `resetAt` for the calling identity without charging the query. Verified 2026-09-28: 30 dry-run queries in 26 s raised `used` by 15 while background polling alone raised it by 24 in 21 s, so dry-run costs nothing.
- **Sample** — a `kind: 'sample'` line in the quota ledger (`~/.overdeck/github-quota/ledger-<YYYYMMDDHH>.jsonl`) carrying `remaining`, `limit`, `resetAt` for one `(pool, bucket)`. Written by `src/lib/github-quota/sampler.ts` every 5 minutes (first at boot + 2 min).
- **Pool** — the identity spent: `user` (the `gh` CLI token), `pat`, `app`.
- **Pause** — a record in `~/.overdeck/github-quota/pause.json` that makes non-essential callers skip GitHub for one `(pool, bucket)` until `until`. Written by `recordGitHubRefusal` in `src/lib/github-quota/pause-gate.ts`.
- **Window reset (`resetAt`)** — the time GitHub refills the bucket. A sample whose `resetAt` is later than now describes the current window.
- **`runGh`** — the metered `gh` exec door in `src/lib/github-quota/run-gh.ts`: pause check, exec, one ledger line.
- **pr-cache** — `readRepoPullRequests()` in `src/lib/overdeck/derived-issue-state.ts`: one `gh pr list` per project, cached by `createSettledTtlPromiseCache` (`src/lib/concurrency.ts`), consumed by the board, PR sync (60 s sweep), merge-train, auto-merge scheduler and substrate stats.
- **Negative answer (close-out)** — `gh pr list --head <branch> --state merged` found no merged PR that proves the branch landed.
- **Idle repo** — a repo whose latest successful PR listing contains zero rows with `state === 'OPEN'`.
- **Local failure** — a `gh` exec that failed without GitHub answering (no remote, not a git repo, `gh` missing, timeout, network). GitHub charges nothing for it.
- **Skipped project** — a project `tryResolveProjectTrackerType(project)` returns `null` for (no `tracker`, `rally_project`, `github_repo`, `issue_prefix`, `gitlab_repo`); pipeline membership already skips it and lists it in `~/.overdeck/github-quota/skipped-projects.json` (today: papers-please, puzzdom, orca).

## Evidence (verified 2026-09-28)

- `gh api rate_limit --jq .resources.graphql` → `used: 45`, while `gh api graphql -f query='{rateLimit(dryRun:true){used resetAt}}'` → `used: 2424`, `resetAt: 12:48:05Z`. The REST `reset` (12:26:59Z) is also wrong.
- Ledger hour 11 (UTC) by caller: `pr-cache graphql ok` 444 calls, `pr-cache graphql error` 413 calls (all no-remote projects), `close-out rest ok` 945 (App-pool issue reads — out of scope), `pipeline-membership graphql ok` 174.
- `gh pr list` query shape (`GH_DEBUG=api`): `pullRequests(first: $limit)` with `reviewRequests(first: 100)` and `statusCheckRollup: commits(last: 1) { … contexts(first:100) }`; `--limit 150` pages as 100 then 50.
- Dry-run cost of that shape on `eltmon/overdeck`: first 100 → 3, first 50 → 2, first 30 → 1. GitHub's formula: sum of requests over every connection, divided by 100, rounded, minimum 1. For a PR page of size N with `reviewRequests` + `statusCheckRollup`: `1 + 3N` requests.
- Registered repos with a remote: overdeck (1,311 PRs, 0 open), orca (stablyai/orca, skipped list), krux, lexerra (4 PRs, 2 open), tindra, eltmon-video, myn-cli, papers-please (skipped list). No remote or not a git repo: auricle, myn (polyrepo wrapper), eltmon-stream, pan-tts, puzzdum. Only overdeck has more than 100 PRs, and none of its PRs is open, so `--limit 100` loses no open PR today.

## Requirements

### Functional

- **FR-1** The sampler writes the user-pool `graphql` sample from GraphQL `rateLimit(dryRun: true)` (`remaining`, `limit`, `resetAt`), and the user-pool `rest` sample from REST `/rate_limit` → `resources.core`. The user-pool `graphql` sample is never taken from REST `resources.graphql`.
- **FR-2** On a primary refusal, when the latest sample for the refused `(pool, bucket)` has `resetAt` later than now, the pause ends at that `resetAt` if the sample shows `remaining === 0`, else at `min(now + 10 min, resetAt)`. Sample age does not matter: a future `resetAt` identifies the current window.
- **FR-3** Each new sample reconciles the active primary pause on its `(pool, bucket)`: `remaining > 0` removes the pause; `remaining === 0` sets `until` to the sample's `resetAt`. Secondary pauses are never changed by a sample.
- **FR-4** `isSquashMergedViaPr` in `src/lib/close-out.ts` resolves the branch tip SHA first, and skips the GitHub call when the same `(projectPath, branch, tipSha)` got a negative answer less than `CLOSE_OUT_NEGATIVE_TTL_MS` (1 hour) ago.
- **FR-5** The close-out merged-PR lookup execs through `runGh`, so it writes a ledger line under the caller in context (`close-out` from the reaper) and honors the pause gate.
- **FR-6** `readRepoPullRequests` makes no `gh` call for a project with no git remote (or not a git repo) or a skipped project; it returns `[]` for them.
- **FR-7** `readRepoPullRequests` lists `--limit 100` instead of 200.
- **FR-8** A settled PR listing of an idle repo stays cached for `PR_CACHE_IDLE_TTL_MS` (5 min); a listing with any OPEN row keeps `PR_CACHE_TTL_MS` (30 s).
- **FR-9** `runGh` prices `gh pr list` / `gh issue list` per page from `--limit` and `--json` fields using GitHub's formula, capped by the rows actually returned.
- **FR-10** `runGh` records a non-refusal failure at cost 0 when GitHub did not answer (stderr has neither `HTTP <3 digits>` nor `GraphQL:`), and at cost 1 otherwise.
- **FR-11** The rate-limit banner states the account's GitHub-reported use for the paused bucket, `used of limit`, from the latest sample of the paused `(pool, bucket)`.

### Non-functional

- **NFR-1** Tests use fake timers for every TTL, interval and pause-end assertion (`vi.useFakeTimers()`, `vi.setSystemTime`, `vi.advanceTimersByTimeAsync`).
- **NFR-2** Metering and bookkeeping never fail the metered call (existing PAN-4264 NFR-2): parse errors in pricing fall back to cost 1.
- **NFR-3** No new `execSync`/sync child-process calls in server-reachable code; `runGh` stays Promise-only (no Effect wrapper, no sync twin).
- **NFR-4** No import from `src/lib/pipeline-membership-gather.ts` into `src/lib/overdeck/derived-issue-state.ts` (circular-ESM risk under Node 22 strict ESM).
- **NFR-5** After deployment, a normal hour's GitHub-reported GraphQL use stays under 2,000 points (post-deploy checkpoint below).

## Decisions

- **D1 — Sampler keeps REST for `rest`.** REST `resources.core` is correct for the REST bucket and free; only `graphql` moves to the GraphQL dry-run query. Run the REST call first so a GraphQL failure never loses the REST sample.
- **D2 — App pool unchanged.** `getAppRateLimit()` (`src/lib/github-app.ts`, line ~438) keeps REST `/rate_limit` for both app buckets. The pill and banner show the user pool; moving the app pool is a NonGoal.
- **D3 — No network probe on refusal.** The pause gate never calls GitHub. Whether a dry-run query is accepted while the bucket is exhausted is unverified, so FR-2/FR-3 use samples only.
- **D4 — close-out negative cache has a 1-hour TTL.** A PR merged after its issue closed keeps the same branch tip, so a TTL-less cache would never reap it until the deacon restarts. 31 closed branches × 1 point per hour is negligible. Only a successful "no qualifying PR" answer is cached; a thrown error (pause, rate limit, local failure) and "merged PR whose merge commit is not on local main yet" are never cached, because their answer can change without the tip moving.
- **D5 — `--limit 100`, single call.** Halves overdeck's cost (6 → 3). The alternative (open + merged split listing) costs the same on small repos and adds a second call. Hazard: an open PR older than the repo's newest 100 PRs drops out of the board and auto-merge view (pr-sync keeps its `gh pr view` fallback). Verified zero such PRs today.
- **D6 — Skipped projects read `[]`.** A policy skip is not a refusal; for a project with no remote `[]` is true, and a skipped project has no tracker so no Overdeck issue depends on its listing. PR sync then leaves existing links to its per-link `gh pr view` fallback.
- **D7 — The tracker predicate moves to a leaf module** `src/lib/project-tracker-type.ts`; `pipeline-membership-gather.ts` re-exports it so existing imports and tests keep working (NFR-4).
- **D8 — Skip/idle policy lives in a new module** `src/lib/overdeck/pr-cache-policy.ts`, so `derived-issue-state.ts` (864 lines, under the 1,000-line ceiling in `scripts/lint-file-size.sh`) grows by only a few lines.
- **D9 — Direct `gh` callers outside close-out and pr-cache are not migrated here.** About 19 files still exec `gh` directly (list below). Migrating them exceeds this plan's 25-file ceiling; sibling issue [PAN-4302](https://github.com/eltmon/overdeck/issues/4302) tracks it.
- **D10 — Pricing is estimated.** Priced list calls keep `estimated: true`; the real cost is not in `gh`'s output.

## Intersecting repo rules (restated)

- Fake timers for any delay/TTL/interval test; never real `setTimeout` waits (`sync-sources/rules/fake-timers-for-retry-tests.md`).
- No `execSync` in dashboard-server-reachable code; prefer async `execFile`.
- New GitHub callers go through `runGh` with a named caller (`.overdeck/context/codebase/concerns.md`, PAN-4264 entry).
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never the full `npm test` on the host.
- File-size ratchet: a file over 1,000 lines that grows needs a `scripts/file-size-allowlist.txt` row. None of the touched files should cross it.
