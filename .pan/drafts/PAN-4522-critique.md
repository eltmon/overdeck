## blocks-the-design: Latest per type loses runtime fields

The PRD's D2 says the latest event of each type reproduces the full runtime fold ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/.pan/drafts/PAN-4522.md), lines 119–123). It does not. `agent.model_set` preserves earlier `sessionModel` and `sessionHarness` when a later event omits them ([event-reducers.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/packages/contracts/src/event-reducers.ts), lines 1305–1319); the event schema makes both fields optional ([events.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/packages/contracts/src/events.ts), lines 470–480). I ran the shared reducer on two `agent.model_set` events: sequence 1 set `sessionModel=s1` and `sessionHarness=claude-code`; sequence 2 set only `model=m2`. Full replay retained both earlier fields, while the planned latest-per-type fold omitted them. Conditional `agent.message_received` and `agent.channel_reply` updates also make D2's blanket last-writer claim unsafe. The smallest fix is to revise FR-1/W1/W2 so the boot fold retains enough history to reproduce partial and conditional updates, and add this two-event counterexample as a test. The existing `queryByTypesSince` in [event-store.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/src/dashboard/server/event-store.ts), lines 508–519, is a replay mechanism to evaluate before adding a query.

## blocks-the-design: Equal activity stamps can discard newer state

FR-4 and W4 keep a client runtime entry only when its `lastActivity` is strictly greater than the snapshot's ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/.pan/drafts/PAN-4522.md), lines 92–96 and 350–360). `agent.context_saturation_changed` advances `updatedAtSequence` and `contextSaturatedAt` without advancing `lastActivity` ([event-reducers.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/packages/contracts/src/event-reducers.ts), lines 1358–1371). I applied `agent.activity_changed` at sequence 10 and then `agent.context_saturation_changed` at sequence 11: the client and older snapshot both had `lastActivity=2026-10-04T03:00:00.000Z`; the client had `updatedAtSequence=11` and the new saturation field, while the snapshot had sequence 10. The proposed comparison returned `false`, so it would erase the newer field. Amend FR-4/W4 to use `updatedAtSequence` to break equal-stamp ties when both entries have a valid sequence, and test that case.

## sharpens-framing: The boot test bypasses boot

W3 calls `foldRuntimeSeed(store.queryLatestPerAgentByType(...), agentsById)` directly and calls this an end-to-end boot test ([PRD](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/.pan/drafts/PAN-4522.md), lines 312–321). Existing [read-model-served-agent-status.test.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-4522/src/dashboard/server/__tests__/read-model-served-agent-status.test.ts), lines 190–234, shows how to instantiate `ReadModelServiceLive` with a fake resolver and read `getSnapshot`. Make W3 exercise that service with an injected event store and assert both the first snapshot's runtime stamp and the failure fallback; keep the direct query/fold test under W1/W2.
