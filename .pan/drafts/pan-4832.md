# PAN-4832 — Fly remote smoke test (PAN-4696)

**Issue:** [PAN-4832](https://github.com/eltmon/overdeck/issues/4832) · **Parent check:** [PAN-4696](https://github.com/eltmon/overdeck/issues/4696) (post-merge verification of [PAN-4295](https://github.com/eltmon/overdeck/issues/4295))

This is a throwaway issue. Its only purpose is to give a remote (Fly.io) work agent a tiny, deterministic job that keeps it busy for about 150 seconds, so the operator can check the PAN-4696 post-deploy items. Its PR is never merged; the operator closes it unmerged.

## Glossary

- **Remote work agent** — a work agent started with `pan start <id> --remote`. It runs on a Fly machine with the repo cloned at `/workspace`, on the feature branch.
- **`REMOTE_DONE` sentinel** — the file `/workspace/.pan/REMOTE_DONE`. A remote agent creates it after its final push. The work prompt's REMOTE block (`src/lib/cloister/prompts/work.md`, line 342: `touch /workspace/.pan/REMOTE_DONE && echo "PAN_REMOTE_DONE {{ISSUE_ID}}"`) defines this contract. Remote agents cannot run `pan done`.
- **Remote reap** — `reapCompletedRemoteAgents()` in `src/lib/remote/remote-completion.ts`. Every 60 s deacon-lite tick it finds remote agents with the sentinel, materializes a local worktree, destroys the machine, and requests review with `source: "remote-reap"`.
- **Host heartbeat** — the file `/workspace/.pan/host-heartbeat` on the VM. PAN-4696 check 3 requires its mtime to be under 2 minutes old while the agent works. The agent must therefore stay busy long enough for that check.

## Problem

PAN-4696 needs one live remote run against the deployed build. The run must (1) be handed off by the 60 s reap tick with no operator command, (2) produce `review.requested` with `source: "remote-reap"` in the materialized workspace's `.overdeck/pipeline.jsonl`, and (3) show a fresh host heartbeat while the agent is still working. The agent's task must be trivial so any failure points at the remote pipeline, not at the change.

## Requirements

- **FR-1** — The branch adds exactly one line, `Fly remote smoke test for PAN-4696`, to `docs/fly-smoke.txt`. The file does not exist on `main` today (verified 2026-11-02), so the agent creates it with that single line.
- **FR-2** — After the append and before the commit, the agent runs two separate foreground `sleep 75` commands. That keeps it working for about 150 s so the heartbeat can be sampled mid-work.
- **FR-3** — The agent commits the file and pushes `feature/pan-4832` to `origin`. On a remote run it then creates the `REMOTE_DONE` sentinel. It never runs `pan done` on a remote run.
- **NFR-1** — The branch diff against `origin/main` touches only `docs/fly-smoke.txt` (plus the planning artifacts that `pan plan finalize` already committed). No tests, no source changes.

## Work items

### WI-1 — Append the smoke line, hold for 150 s, commit and push (FR-1, FR-2, FR-3, NFR-1)

Files: `docs/fly-smoke.txt` (new).

Steps, in this exact order. The order matters: committing or creating the sentinel before the sleeps lets the reap hand the branch off before the heartbeat window exists, and the test then proves nothing.

1. `pan task claim PAN-4832 smoke-line`.
2. Append the line: `printf 'Fly remote smoke test for PAN-4696\n' >> docs/fly-smoke.txt`. Run `mkdir -p docs` first only if `docs/` is missing (it exists on `main`).
3. Run `sleep 75` as one foreground shell command.
4. Run `sleep 75` again as a second, separate foreground shell command. Do not merge them into one `sleep 150`: that exceeds the default 120 s Bash tool timeout.
5. Commit: `git add docs/fly-smoke.txt && git commit -m "chore(smoke): add fly remote smoke line (PAN-4832)" -m "Item: smoke-line"`.
6. Push: `git push origin feature/pan-4832`.
7. `pan task done PAN-4832 smoke-line` (and any `.acN` sub-items the task tool asks for).
8. Remote run only: `touch /workspace/.pan/REMOTE_DONE && echo "PAN_REMOTE_DONE PAN-4832"`. Local run: follow the normal work prompt completion instead.

Before/after for `docs/fly-smoke.txt`:

```text
# before: file absent
# after:
Fly remote smoke test for PAN-4696
```

**Implementation checkpoint (sleep).** `sleep 2` ran fine in a Claude Code Bash call on the host on 2026-11-02. If the harness refuses a foreground `sleep 75`, fall back to `timeout 75 tail -f /dev/null || true`, run twice, still as two separate calls.

## Documentation

The only file this change touches, `docs/fly-smoke.txt`, is itself under `docs/`. The change alters no documented behavior, so no other doc file changes. WI-1 is the documentation item for the plan's docs gate.

## Decisions

- **One item, not many.** The issue says "One xBRIEF item, no tests, no other files". The issue is authoritative over the generic decomposition guidance.
- **Item kind is `docs`.** The single touched file lives under `docs/`, so `kind: "docs"` and `files_scope: ["docs/fly-smoke.txt"]` both satisfy the finalize docs gate.
- **No tests.** The issue forbids them. `verify_commands` are plain shell checks instead.

## Non-goals

- No tests and no edits to any file other than `docs/fly-smoke.txt`.
- The PR is never merged; the operator closes it unmerged.
- The Flywheel must not start this issue.
- No `pan done` on a remote run.
