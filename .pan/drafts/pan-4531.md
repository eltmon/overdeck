# PAN-4531 — A verification run whose outcome is decided stops before its next gate

**Issue:** [PAN-4531](https://github.com/eltmon/overdeck/issues/4531)
**PR:** [#4608](https://github.com/eltmon/overdeck/pull/4608), which builds on PAN-4527 ([#4599](https://github.com/eltmon/overdeck/pull/4599)) and PAN-4532 ([#4602](https://github.com/eltmon/overdeck/pull/4602))
**Status:** delivered. This PRD records the work in PR #4608.

## Glossary

- **Local gate**: one entry in the runner's `gates` map (install, typecheck, lint, build, ...). The runner runs
  them through `runQualityGates` (`src/lib/cloister/validation.ts`).
- **CPU admission**: the machine-wide FIFO queue that each heavy gate enters before it runs
  (`src/lib/cloister/quality-gate-admission.ts`, PAN-4311). Direct local Vitest runs enter the same queue.
- **CI tests mode**: `verification.tests: ci`. The `test` gate's verdict is the CI test job for the head
  (`readLatestCiTestResult(workspacePath, head8)`).
- **Verified head**: the head the run's verdict is for, under the PAN-4527 same-head rule
  (`src/lib/cloister/verification-head.ts`). It is the launch head while HEAD is same or synced; otherwise HEAD
  has moved.
- **Decided run**: a run whose verdict is already known before its gates finish. There are three cases:
  - **ci-red**: in CI tests mode, CI recorded `failed` for the verified head.
  - **merged**: the PR merged.
  - **superseded**: an agent commit moved HEAD (review verification only).
- **Not run**: the local gates a ci-red run skipped. They are listed in the artifact's `notRun` field.

## Root cause

`src/lib/cloister/verification-runner.ts`, ~lines 578-590 on main, read the CI verdict only after every local
gate had run:
`const ciTestRed = testsMode === 'ci' && !localGateResults.some(...) && readLatestCiTestResult(workspacePath, headShort) === 'failed';`
A head with red CI therefore held the single admission slot for about 25 minutes before it failed `test`.
This was seen on PAN-4259 on 2026-10-04: seven waiters were queued, including the agent's own isolation test run.

## Requirements

- **FR-1**: `runQualityGates` accepts `shouldStop`. It asks before each gate and stops before the gate requests
  CPU admission when `shouldStop` returns true.
- **FR-2**: In CI tests mode, a head whose CI is red before the run runs no local gate and fails `test` with the
  existing message and attempt accounting (PAN-3965). It lists the skipped gates in `notRun`.
- **FR-3**: CI turning red during a gate stops the run before the next gate, and the run fails at `test`.
- **FR-4**: With CI passed or unknown, behavior is unchanged.
- **FR-5**: The same check also stops a run whose PR merged, with the existing merged skip. It also stops a
  review-verification run superseded by an agent commit: that run returns a deferred outcome, and the supervisor
  restarts on the new head, at most `MAX_SUPERSEDED_RESTARTS` (3) times. The issue does not ask for FR-5. It is
  included because once the runner checks between gates, a run on a merged or moved head is just as certain to be
  wasted.
- **FR-6**: `docs/PIPELINE-GATES.md` states that a known-red CI head short-circuits local gates.

## Non-goals

- No preemption of a gate that is already running. The check runs between gates.
- No change to the attempt budget or to the `test` failure message.
- No new HTTP route, CLI verb or setting.

## Acceptance criteria

1. Given a `runQualityGates` call whose `shouldStop` turns true after the first gate, then no later gate requests
   CPU admission.
2. Given CI recorded `failed` for the verified head before verification starts, then no local gate runs, admission
   is never requested, the run fails at `test` with the existing message, and `notRun` lists the gates.
3. Given CI flips to `failed` during a gate, then the next gate does not run and the run fails at `test`.
4. Given CI passed or unknown, then every gate runs as before.
5. Given the PR merges during a gate, then the run stops with the merged skip. Given an agent commit during a
   gate, then the run is superseded and the supervisor returns the restarted run's verdict.
6. `docs/PIPELINE-GATES.md` contains "A decided run stops before its next gate".
