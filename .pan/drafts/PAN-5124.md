# PAN-5124 — Built-in defaults: mid workhorse to Opus 5.5; cheap workhorse and background calls to Haiku 5.5

**Issue:** [PAN-5124](https://github.com/eltmon/overdeck/issues/5124)
**Verified against:** `feature/pan-5124` at `85b97f82a30` (main + backlog-sequence commits), 2026-11-11.

## Glossary

- **Workhorse slot:** one of three named model slots (`expensive`, `mid`, `cheap`) in `workhorses:` in `~/.overdeck/config.yaml`. Roles reference a slot as `workhorse:<slot>`. The built-in slot values live in `DEFAULT_WORKHORSES` in `src/lib/config-yaml/roles.ts`.
- **Mid workhorse:** the `mid` slot. The `work`, `test`, `ship` and `worker` roles and the `review.correctness/performance/requirements` sub-lanes default to `workhorse:mid`.
- **Cheap workhorse:** the `cheap` slot. Trivial tiered-execution bands and any role an operator points at `workhorse:cheap` use it.
- **Background call:** a short model call that Overdeck makes outside an agent session: conversation titles, title refinement, the About summary, smart compaction (chunked transcript summaries), and memory extraction and memory query expansion.
- **Built-in default:** the value Overdeck uses when the operator's config does not set the key. An install that sets its own value keeps it; this issue changes only built-in defaults.
- **Effort:** the reasoning-depth control. Claude Code takes `--effort <low|medium|high|xhigh|max>`; the Messages API takes `output_config: { effort }`. Haiku 5.5 thinks by default at `medium`; Haiku 4.5 has no effort control (its capability row has no `effortLevels`).
- **Claude Code minimum:** `minClaudeCodeVersion` on a model's capability row. `claude-haiku-5-5` requires `2.1.293` (`src/lib/model-capability-additions.ts`, search `minClaudeCodeVersion: '2.1.293'`). `assertClaudeCodeSupportsModel` in `src/lib/claude-code/requirements.ts` throws `ClaudeCodeTooOldError` with the standard upgrade message when the binary is older.
- **Anthropic preset:** the `anthropic` model preset in `src/lib/model-presets/presets.ts` (`Anthropic defaults`). `anthropic-cost-saver` spreads it. Each preset carries a `version`; `applyPreset` records the applied version, and `updateAvailable` is true when `applied.version < preset.version` (`src/lib/model-presets/apply.ts`, search `updateAvailable`).
- **Implementation checkpoint:** the real-model run the issue requires before the PR is ready (20 title calls + 20 compactions, Haiku 5.5 vs Haiku 4.5), with a stated fallback.

## Problem

The operator decided on 2026-11-11 (issue body) to move two sets of built-in defaults:

1. `mid` → `claude-opus-5-5`. The 2026-09-29 eval (`docs/model-evals/2026-09-29-opus-5-5-vs-sonnet-5-5.md`) found Opus 5.5 caught 30/60 review blockers vs Sonnet 5.5's 10/60. The Anthropic preset already sets `workhorses.mid` to `claude-opus-5-5`; the built-in default should match. Work agents on defaults cost about twice as much; the cost-saver preset keeps Sonnet for 30% of work.
2. `cheap` and every background-call default → `claude-haiku-5-5`. Haiku 5.5 costs &#36;0.10/&#36;0.50 per MTok on prompts up to 100K tokens (vs &#36;1/&#36;5 for Haiku 4.5) and has a 1M window (vs 200K).

Moving background calls to Haiku 5.5 brings three behavior changes that the code does not handle today:

- Haiku 5.5 thinks by default at `medium`, and thinking tokens count toward `max_tokens`. Title calls pay for reasoning they do not need, and memory extraction (`max_tokens: 2048`) can be cut off before its JSON.
- Haiku 5.5 needs Claude Code 2.1.293. Background calls spawn bare `claude` and never run the minimum-version check, so an old Claude Code is not refused with the upgrade message.
- Smart compaction sizes chunks by model id, but when the caller passes no model, `getChunkBudgetChars(undefined)` returns the 300,000-char default while `runModelSummary` runs `DEFAULT_SUMMARY_MODEL`. On Haiku 5.5 (about 30% more tokens per char than Haiku 4.5) a 300,000-char chunk can cross the 100K-token tier, which costs 5x.

## Decisions

- **D1 — FR-4 keeps the existing 240,000-char Haiku 5.5 row.** The row was added on 2026-10-08 (commit `780357f9882`) to keep each chunk under the 100K-token price tier. The 1M window is the hard ceiling, not the chunk target: a 1M-token chunk would bill every token at 5x. The 1M window still helps through the overflow-retry path and long carried-forward summaries. The fix FR-4 needs is the missing-model gap: `getChunkBudgetChars` must resolve an empty model to `DEFAULT_SUMMARY_MODEL`, the same model `runModelSummary` runs.
- **D2 — Effort pin rule.** A background call passes effort `low` only when the model's own capability row lists `low`: `getModelEffortLevels(model)?.includes('low') === true` (`src/lib/model-capabilities.ts`, `export function getModelEffortLevels`). Do not use `supportedEffortLevels` — it treats a model with no row as "all five levels". Haiku 4.5 has no `effortLevels`, so an operator who keeps Haiku 4.5 gets byte-identical args and request bodies.
- **D3 — "Classifier calls" in FR-3.** Nothing reads `docs.classifier.*` at runtime (only `defaults.ts`, `domain-mergers.ts`, `schema.ts` and `presets.ts`; `grep -rn "classifier\.model\|\.classifier\b" src` finds no caller). The default `docs.classifier.model` value still moves to `claude-haiku-5-5` (FR-2), but there is no classifier call to pin. The effort pin applies to every call that exists in the title family — first-message title, title refinement and About, which all go through `buildStructuredClaudeArgs` — and to memory extraction and query expansion, which share `AnthropicExtractionProvider.extract`. Memory extraction is included because thinking counts toward its 2048 `max_tokens`, and query expansion has a 750 ms budget.
- **D4 — Smart compaction keeps default effort (`medium`).** Compaction quality benefits from reasoning, and the issue's FR-3 names only titles and classifiers.
- **D5 — Background calls run the existing Claude Code preflight.** `invokeClaudeStructured` and the non-rpc path of `runModelSummary` call `prepareHarnessLaunch('claude-code', { model })` from `src/lib/harness-binary.ts` and spawn the returned `binaryPath` instead of bare `'claude'`. That runs `requireHarnessBinary` (honors a configured executable) and `assertClaudeCodeSupportsModel` (the PAN-4359 refusal text plus the PAN-5108 update-on-refusal). The check validates the binary that is then spawned.
- **D6 — The refusal may reach existing failure handling, with its message intact.** `ClaudeCodeTooOldError` propagates unchanged out of the background function. The title caller already logs `err.message` (`src/lib/overdeck/conversation-runtime.ts`, search `TITLE-GEN-FAILED`), and compaction callers already fall back to a heuristic summary — that is not "another model", so it is allowed. No code path may catch the error and retry on a different model.
- **D7 — A background call may trigger the PAN-5108 auto-update.** It goes through the same `assertClaudeCodeSupportsModel`, so the machine-wide `harnesses.auto_update` switch governs it exactly as it governs a launch. The version read is cached per binary path and mtime (`readClaudeCodeVersion` in `src/lib/claude-code/version.ts`), so frequent title calls do not spawn `claude --version` each time.
- **D8 — The requirement list includes the Claude-Code background models.** `listConfiguredModels` adds `conversations.titleModel` (source `conversations.title_model`) and `conversations.compactionModel` (source `conversations.compaction_model`), so the dashboard banner and `pan doctor` show a too-old Claude Code before the first background call fails. Memory extraction uses the Anthropic SDK, not Claude Code, so it is not listed.
- **D9 — Bump the Anthropic preset to `version: 2`, `date: '2026-11-11'`.** Its cheap and background values change, and `version` exists so installs that applied v1 see `updateAvailable`. `anthropic-cost-saver` spreads `ANTHROPIC` and inherits the bump. The OpenAI preset does not change.
- **D10 — The Anthropic trivial tier band keeps no effort.** `presets.test.ts` asserts `tierBands.trivial.effort` is undefined for both Anthropic presets, and any preset effort must be `high`. Haiku 5.5 runs the trivial band at its own default (`medium`). Only the comment changes: Haiku 5.5 has effort control, and the band leaves it at the model default.
- **D11 — Frontend mirrors.** Update `RolesPanel.tsx` `DEFAULT_WORKHORSES` (both slots), the four `|| 'claude-haiku-4-5'` select fallbacks, both memory-model placeholders and `FALLBACK_COMPACTION_MODEL`. Leave the tiered-execution crew defaults (`CrewRow.tsx` `DEFAULT_CREW_MODEL`, `TieredExecutionSection.tsx` `DEFAULT_MODEL` and its "new crews start on Haiku 4.5" text): they are a separate setting the issue does not list.
- **D12 — The implementation checkpoint gates the Haiku default flips, not FR-1.** The checkpoint item runs after the title effort pin lands (so titles are measured as they will ship) and before any Haiku 5.5 default is written. Decision rule: **GO** if Haiku 5.5's titles are at least as good as Haiku 4.5's on ≥18/20 and its compaction summaries keep the same facts (goal, decisions, open work, file paths) on ≥18/20, and the mean cost per call is not higher; otherwise **FALLBACK**. On FALLBACK, cancel the Haiku default items (xBRIEF ids `haiku-config-defaults`, `haiku-module-constants`, `haiku-preset-v2`, `haiku-settings-fallbacks` = WI-9 to WI-12) and every one of their acceptance-criterion ids: `pan task cancel pan-5124 <item>` changes one id only, so also run it for each `<item>.acN` (pending `.acN` rows block `pan done`). Cancelled items release their dependents (`src/lib/xbrief/dag.ts`, search `blocker?.status === 'cancelled'`). Then write the docs and changelog for FR-1 only, and state in the PR that cheap and background defaults stay on Haiku 4.5. FR-3, FR-4 and FR-5 still ship: they are no-ops for Haiku 4.5 by D2 and the Haiku 4.5 row having no `minClaudeCodeVersion`.
- **D14 — Items never wait for the PR.** The changelog entry links the PR if it is already open when the item runs, otherwise [#5124](https://github.com/eltmon/overdeck/issues/5124); the release-day author rewrites links anyway. The checkpoint summary is copied into the PR body at `pan done` time (continue.json note), not by WI-8.
- **D13 — The changelog entry goes in a new `Unreleased` block.** v0.77.0 is the top block today. If a `description="Unreleased"` block exists when this item runs, add the entry there instead of creating a second one.
