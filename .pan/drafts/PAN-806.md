# PAN-806 — Epic B: Agents use `pan` primitives for git history ops, never raw git

**Issue:** https://github.com/eltmon/overdeck/issues/806
**Mode:** `pan plan --auto` (no interactive Q&A — design decisions recorded below)
**Planned against:** `feature/pan-806` @ `7b3fb349c`

---

## Glossary

- **History op** — any git operation that rewrites commit history or hides working-tree
  state: `git rebase` (all forms), `git reset --hard`, `git stash`. `git add`/`commit`/
  `status`/`fetch`/`push`/`log`/`diff`/`merge` are **not** history ops and stay permitted.
- **Agent session** — a tmux session spawned by Overdeck for a pipeline role (work, review,
  test) bound to an issue. Distinguished at runtime by `OVERDECK_AGENT_ID` being exported in
  its shell (launcher, `launcher-generator.ts:270`).
- **PATH wrapper / guard dir** — a per-agent directory prepended to `PATH` by the launcher,
  containing a `git` shim that intercepts blocked subcommands and otherwise `exec`s real git.
- **pre-rebase hook** — git's built-in hook fired at the start of `git rebase`. Runs
  regardless of how git was invoked (even `/usr/bin/git rebase`), so it cannot be bypassed by
  an absolute path — unlike the PATH wrapper.
- **Sentinel** — the env var `OVERDECK_PAN_GIT_OP=1`. Set by `pan` around its **own** internal
  history ops so the guards let them through. This is the contract that keeps `pan done` /
  `pan sync-main` working while raw agent rebases are blocked.

## Problem

During PAN-698 a work agent attempted a destructive `mv .pan/ .planning/ .claude/skills/ /tmp/`
because the work prompt told it to run a raw `git rebase origin/main` with no safe exit path on
a dirty worktree. The invariant we want: **agents never touch git history. Commits are fine;
rebasing, hard-resetting, and stashing are not.** All sync/submit flows go through `pan`
primitives (`pan sync-main`, `pan done`), which use merge (not rebase) for mid-work syncs and
own the final rebase internally.

This contradictory block is the **primary control** to remove.

### 2. `.git/hooks/pre-rebase` is DEAD in this repo — Husky owns the hooks path
The PRD's Mechanism 1 ("write `<workspace>/.git/hooks/pre-rebase`") **would never fire.** This
repo sets `core.hooksPath = .husky/_` (local scope, shared across worktrees, relative → resolves
per-worktree). When `core.hooksPath` is set, **git ignores `.git/hooks/` entirely.** Verified:
```
$ git rev-parse --git-path hooks   → .husky/_
$ git config --local core.hooksPath → .husky/_
$ ls .husky/_/pre-rebase            → exists (husky v9 dispatcher stub)
$ cat .husky/_/.gitignore           → *      (whole dir is generated/gitignored)
```
Husky v9 generates `.husky/_/<hook>` stubs that source `.husky/_/h`, which runs the tracked
user hook `.husky/<hook>` if present (this is how the committed `.husky/pre-push` and
`.husky/commit-msg` release guards run). **Correction:** install the hook into the git-resolved
hooks path (`git rev-parse --git-path hooks`), not `.git/hooks/`. This is correct for both
Husky projects (→ `.husky/_/pre-rebase`) and plain-git projects (→ `.git/hooks/pre-rebase`).

copy is `~/.claude/skills/rebase-and-submit/SKILL.md` (modified 2026-04-24); `git grep` /

## The critical gap the PRD missed: the guards would break `pan done`

`pan done` Step 0 (`src/cli/commands/done.ts:357-379`) calls `rebaseAndPushRepos`
(`src/lib/rebase-helper.ts:222`), which **runs in the agent's own process** and invokes:
- `git rebase origin/<target>`  (`rebase-helper.ts:97`)
- `git rebase --abort`          (`:107`)
- `git rebase --continue`       (`:192`)
all via `execAsync('git …', { cwd, env })` — `git` resolved through the agent's (wrapped) PATH,
and the rebase fires the pre-rebase hook.

So **both** PRD mechanisms, as written, would block `pan done`'s legitimate internal rebase and
brick the entire submit flow. The PRD only reasoned about `pan sync-main` (which is safe anyway —
it uses **merge**, verified at `merge-agent.ts:1183` `syncMainIntoWorkspace` → auto-commit +
`git merge`, never rebase/reset/stash).

**Resolution — the sentinel contract.** `pan` sets `OVERDECK_PAN_GIT_OP=1` in the env of its
own history-op git calls (only `rebase-helper.ts` needs it — see scan below). Both guards
**bypass when the sentinel is present**:
- agent runs raw `git rebase` → no sentinel → **blocked**
- `pan done` runs `git rebase` internally → sentinel set → **allowed**

This single env-var contract is the foundation both guards depend on; it must land before/with
them.

### Scan: which pan-internal blocked-git calls run in the agent's wrapped PATH?
| Call site | Op | Runs where | Needs sentinel? |
|---|---|---|---|
| `rebase-helper.ts:97/107/192` | rebase/--abort/--continue | **agent process** (`pan done`) | **YES** |
| `merge-agent.ts` `syncMainIntoWorkspace` | merge (+ add/commit) | server (dashboard) | no (merge not blocked) |
| `stashes.ts` | stash push/pop/drop/apply | server / human CLI | no (unwrapped PATH) |
| `safety/dangerous-git-ops.ts:127` | reset --hard | server / human CLI | no (unwrapped PATH) |
| `cloister/validation.ts:276` | reset --hard ORIG_HEAD | server (deacon) | no (unwrapped PATH) |

Only `rebase-helper.ts` runs a **blocked** op in the **agent's wrapped PATH**. Everything else
either isn't a blocked op or doesn't run in an agent session.

## Requirements

- **FR-1** — `work.md`'s raw restart-rebase block (`:241-246`) is replaced with a `pan sync-main
  {{ISSUE_ID}}` instruction (merge-based; requires the dashboard to be running).
- **FR-2** — `work.md` contains an explicit permitted/forbidden git-operations table
  (permitted: add, commit, status, fetch, push, log, diff, merge-via-`pan sync-main`;
  forbidden: rebase, reset --hard, stash).
- **FR-3** — `pan`-internal history ops carry the `OVERDECK_PAN_GIT_OP=1` sentinel so `pan done`
  is never blocked by the guards (`rebase-helper.ts`).
- **FR-4** — A `pre-rebase` hook is installed at worktree creation into the git-resolved hooks
  path; it blocks `git rebase` inside an agent session (`OVERDECK_AGENT_ID` set) and exits 1
  with a message pointing at `pan sync-main` / `pan done`; it allows the rebase when the
  sentinel is set or when no agent session is present (human in the workspace).
- **FR-5** — The launcher prepends a per-agent PATH wrapper that blocks `git rebase`,
  `git reset --hard`, and `git stash`, passes every other git command through to the real git
  binary, and bypasses all blocks when the sentinel is set. Installed for every harness
  (claude-code, codex, pi/oh-my-pi) for issue-bound agent sessions (not conversation panels).
- **FR-6** — The guard dir is removed on agent stop (`stopAgentSync`).
- **NFR-1** — No human-developer behavior change: a human shell on `main` or inside a workspace
  (no `OVERDECK_AGENT_ID`, no wrapped PATH) can still rebase/reset/stash.
- **NFR-2** — `pan sync-main` (merge) and `pan done` (rebase) continue to work end-to-end.
- **NFR-3** — Permitted ops (`git add`, `commit`, `status`, `fetch`, `push`, `merge`) are never
  blocked by either guard.

### B3 — Install the `pre-rebase` hook at worktree creation  (FR-4)
**File:** `src/lib/workspace-manager.ts` (`createWorktree`, after `git worktree add` ~`:342-351`,
near the beads-redirect setup).
After the worktree exists, resolve the hooks dir and write the hook:
```ts
const { stdout: hooksRel } = await execAsync('git rev-parse --git-path hooks', { cwd: targetPath });
const hooksDir = isAbsolute(hooksRel.trim()) ? hooksRel.trim() : join(targetPath, hooksRel.trim());
mkdirSync(hooksDir, { recursive: true });
const hookPath = join(hooksDir, 'pre-rebase');
writeFileSync(hookPath, PRE_REBASE_HOOK, 'utf-8');
chmodSync(hookPath, 0o755);
```
Hook body (checks the same literal sentinel as B1):
```sh
#!/bin/sh
# Overdeck: block raw `git rebase` in agent sessions. pan-internal rebases set the sentinel.
[ "$OVERDECK_PAN_GIT_OP" = "1" ] && exit 0
if [ -n "$OVERDECK_AGENT_ID" ]; then
  echo "ERROR: raw 'git rebase' is forbidden in Overdeck agent workspaces." >&2
  echo "To sync with main:  pan sync-main $OVERDECK_ISSUE_ID" >&2
  echo "To submit for review: pan done $OVERDECK_ISSUE_ID" >&2
  exit 1
fi
exit 0
```
**Test:** create a temp git repo, run `createWorktree` (or call the extracted installer), then
run `git -c core.hooksPath=… rebase` with `OVERDECK_AGENT_ID` set → exits 1 with the message;
with `OVERDECK_PAN_GIT_OP=1` set → allowed; with neither → allowed. (Prefer extracting a small
`installPreRebaseHook(targetPath)` so the test can call it directly.)
**Inspection:** `false` — leaf; the contract (sentinel/agent-id) is fully specified here.
**Depends on B1** (`blocks`): the hook must not be live before `pan done` carries the sentinel.

## Hazards
- **H1** — Land B3/B4 before B1 and every agent's `pan done` rebase gets blocked → submit flow
  bricks. B1 `blocks` B3 and B4.
- **H2** — Husky regenerates `.husky/_/` on a mid-session `bun install`, clobbering the installed
  `_/pre-rebase`. Mitigation: the PATH wrapper (B4) independently blocks rebase; the window is
  narrow (installs rarely re-run mid-session).
- **H3** — PATH wrapper is bypassable via absolute path (`/usr/bin/git reset --hard`). Accepted
  (PRD-acknowledged): the pre-rebase **hook** covers the higher-risk rebase even via absolute
  path; reset/stash wrapper is defense-in-depth behind the prompt (primary control).
- **H4** — Adding the wrapper changes `launcher-generator.test.ts` inline snapshots; they must be
  updated in B4 or the suite goes red.
- **H5** — The sentinel var name must be byte-identical across B1/B3/B4 (`OVERDECK_PAN_GIT_OP`).
