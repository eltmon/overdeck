# PAN-3959 — Record the transcript path in the session index at session start; resolver stops guessing per harness

**Issue:** https://github.com/eltmon/overdeck/issues/3959
**Baseline:** every file/line reference below was verified against `origin/feature/pan-3950` at `fd42eb98876` (PR #3951, open at planning time 2026-09-20), per the operator's planning note on the issue. If a number has drifted, search for the quoted identifier. This issue branches off (or rebases onto a main that contains) PAN-3950 — the `sessions.json` append-only index, the `orderedTranscriptCandidates` resolver, and the deleted `session.id` pointer all come from that branch.
**Mode:** `pan plan --auto`; no operator Q&A. Decisions and their rationales are in `## Decisions`.

## Glossary

- **Session index** — `~/.overdeck/agents/<agentId>/sessions.json`, append-only JSON Lines. Entry shape today: `{sessionId, at, source, harness, model}`; `{reset: true, at}` lines are generation boundaries. Parsed by `parseSessionIndex` (`src/lib/session-history.ts:116`), which dedupes by `sessionId`, newest occurrence wins.
- **`path` field** — the new optional entry field this issue adds: the absolute filesystem path of that session's transcript, recorded by whatever component creates or captures the session.
- **Transcript candidate** — `{kind, path}` where kind is `claude | codex | pi | ohmypi | acp | kimi | muse` (`src/lib/session-history.ts:38-39`). Resolution tries candidates newest-first and returns the first path that exists.
- **The resolver** — ONE shared ordering function, `orderedTranscriptCandidates` (`src/lib/session-history.ts:74`), fed by two adapters: sync `listAgentTranscriptCandidatesSync` (`src/lib/agent-enrichment.ts:254`) and async `listAgentTranscriptCandidates` (`src/dashboard/server/routes/jsonl-resolver.ts:212`). Both adapters build an `indexedPaths` map by running a per-harness path formula for every index entry, then add `launcherPinned` and `stateDerived` extras.
- **Per-harness path formula (the "legacy fallback")** — the per-entry branches that derive a transcript path from a session id: claude `join(projectDir, sessionId + '.jsonl')` (agent-enrichment.ts:265, jsonl-resolver.ts:237), kimi hashed bucket `kimiSessionsRoot(...)/<id>/agents/main/wire.jsonl` (agent-enrichment.ts:266, jsonl-resolver.ts:238), codex `findRolloutPath` walk over `codex-home*` (agent-enrichment.ts:270-281, jsonl-resolver.ts:239-246), pi/ohmypi filename scan `findPiTranscriptForSession[Sync]` (agent-enrichment.ts:244-252/267, jsonl-resolver.ts:202-210/247-248), acp fixed `acp-session.jsonl`, muse fixed `muse-session.jsonl` (agent-enrichment.ts:268-269, jsonl-resolver.ts:249-250). These stay (PAN-3958 deletes them).
- **Guessing extras** — the two candidate sources that exist only because the index lacks paths: `launcherPinned` (greps `launcher.sh` for `--session-id`/`--resume`, claude only; agent-enrichment.ts:286-293, jsonl-resolver.ts:255-262) and `stateDerived` (claude: runtime-mirror `claudeSessionId` + `state.json.sessionId`; non-claude: `resolveCodexRolloutPath`/`resolvePiSessionPath`/`resolveAcpTranscriptPath`/`resolveKimiWirePath`/`resolveMuseSessionPath`; agent-enrichment.ts:295-302, jsonl-resolver.ts:264-286). This issue deletes both (see D2).
- **Capture point** — the code that first learns a harness session's real identity: the Claude SessionStart hook, codex's `writeThreadId` sites, kimi's `writeKimiSessionId` sites, the pi/ohmypi extension's `session_start`/`turn_end` handlers, the ACP host's session persistence, muse's spawn-time `resolveMuseSessionPath`.
- **Live discovery** — `watchForAgentTranscriptCandidate` (`src/dashboard/server/ws-rpc.ts:245`): resolves candidates, and while none exists watches the nearest existing directory of `sessions.json` plus every candidate path. Fewer, exact candidates ⇒ it watches the agent directory and the recorded path's parent only, with no code change to the watcher.

## Problem

Resolving "where is this agent's transcript" requires guessing per harness from the session id. The formulas live in two adapters that must stay parity-perfect (PR #3951 needed five review rounds for parity bugs), and live discovery must watch five different filesystem roots because the candidate list spans every harness layout. Every harness that knows its transcript location at session start currently throws that knowledge away; the system re-derives it later, badly.

## Requirements

- **FR-1** `SessionIndexEntry` gains `path?: string` — an absolute transcript path. `appendSessionIdToHistory` accepts it via `metadata.path` and includes it in the appended line when non-empty. `parseSessionIndex` preserves it, and when dedupe keeps a newer pathless duplicate of a `sessionId`, the kept entry inherits the displaced entry's `path`.
- **FR-2** The Claude Code hooks record `transcript_path` from the hook payload: `session-start-hook` and `heartbeat-hook` pass it to `pan_append_session_index` (which gains a seventh positional arg and emits `path` when non-empty), and `session-start-hook` includes it as `transcriptPath` in the `model_set` event body so the server-side observer `observeSessionIndexEvent` (`src/dashboard/server/services/agent-state-service.ts:73-84`) records it too.
- **FR-3** Both resolver adapters short-circuit per-harness formulas for entries carrying `path`: the entry contributes exactly one candidate, `{kind: transcriptCandidateKind(entry.harness ?? currentHarness), path: entry.path}`. Entries without `path` behave exactly as before.
- **FR-4** Every codex capture point records the rollout path: the TUI spawn in `src/lib/runtimes/codex.ts` (~:836), the background capture in `src/lib/agents/spawn.ts:1014-1019`, the conversation launch in `src/lib/overdeck/conversation-runtime.ts:829-834`, and the app-server host on `thread/started` (`src/lib/codex/app-server-host.ts:245`) once the rollout exists (bounded background wait).
- **FR-5** Every kimi capture point records `join(kimiSessionsRoot(kimiHome, workspace), sessionId, 'agents', 'main', 'wire.jsonl')`: the resume and fresh-launch branches of `launchAndCaptureManagedKimiSession` (`src/lib/runtimes/kimi-code.ts:444,461`), the class writer (`kimi-code.ts:759`), restart/recovery (`src/lib/agents/recovery.ts:304,651`), and conversation launch (`src/lib/overdeck/conversation-runtime.ts:860`).
- **FR-6** The pi and ohmypi extensions record the session file: at `session_start` by a bounded scan of `<agentDir>/sessions` for `*_<sessionId>.jsonl` / `<sessionId>.jsonl`, and on the first `turn_end` carrying `sessionLogPath` by appending an upgraded entry for the same `sessionId` (dedupe makes the path-carrying entry authoritative).
- **FR-7** The ACP host records `{sessionId: started.sessionId, path: <agentDir>/acp-session.jsonl}` where it persists `acp-session-id` (`src/lib/acp/host.ts:159-160`), and the muse runtime records `{sessionId: museSessionId(path), path}` where spawn confirms the session log (`src/lib/runtimes/muse.ts:75-79`).

- **NFR-1** Append-only discipline preserved: one JSON object per line, lines stay ≤4095 bytes (the existing PIPE_BUF guard covers the new field), nothing edits or truncates `sessions.json`.
- **NFR-2** No new store, table, manifest, or module. The index file that already exists carries the new field. The exported `resolve*` helpers in `jsonl-resolver.ts` stay — ws-rpc and the conversation adapters use them for real conversations (`ws-rpc.ts:124-144`, `src/lib/overdeck/conversation-forks.ts:71-73`, `src/lib/conversations/transcript-adapter.ts:560`); only their use *inside* `listAgentTranscriptCandidates` is removed.

## Decisions

- **D1 — The schema change is additive and merge-on-dedupe.** `path` is optional; a newer pathless duplicate inherits the older entry's `path` instead of erasing it. Rationale: the server-side `observeSessionIndexEvent` and the jq-less hook path can append a later entry for the same `sessionId` without knowing the path; plain newest-wins would clobber the recorded path. The path is a stable fact about a session, so inheritance is safe.
- **D2 — "The legacy fallback" = the per-entry formula branches; `launcherPinned`/`stateDerived` are deleted now.** The issue body demands net-negative production lines and asserts the named tests survive "deleting all harness-specific path helpers except the legacy fallback"; the planning note demands the legacy fallback stay untouched and PAN-3958 do the consolidation. The only reading that satisfies all three: the per-entry formulas are the fallback that stays, and the launcher/state guessing layer is what this issue removes. Those extras exist solely to recover from an index without paths; once writers record paths they are dead weight and their deletion is the net-negative lever.
- **D3 — Writers record at the capture point, never by formula at read time.** Each harness has exactly one place that first knows the real path; the change is a 1–5 line append at that site. Claude's launcher-time entries (`createFreshSessionIdentity`, `src/lib/session-history.ts:242-253`; specialists, `src/lib/agents/spawn.ts:350`) stay pathless — the SessionStart hook supersedes them for the same `sessionId` via dedupe, per the issue's writer assignment.
- **D4 — Pi/ohmypi use scan-at-start plus `sessionLogPath` upgrade.** The extension's declared `SessionStartEvent` carries only `{reason, sessionId, model}` (`packages/pi-extension/src/index.ts:102-106`), but `TurnEndEvent.sessionLogPath` (`:133`) is the harness's own absolute path. The session-start scan covers the gap before the first turn; the first `turn_end` upgrades the entry. A module-level `lastRecordedSessionPath` in the extension process (one session per process) prevents appending on every turn.
- **D5 — Muse conversations are not instrumented.** Conversation-launched muse sessions (`src/lib/overdeck/conversation-runtime.ts:582-588`) have no post-launch session wait today, and adding a poller is new machinery for a harness whose conversation transcripts resolve through the conversation route (`src/lib/overdeck/conversation-reads.ts:88`) anyway. `MuseRuntime.spawnAgent` is the only writer site.
- **D6 — ACP host writes through `appendSessionIdToHistory` directly.** The host runs as its own process but is same-repo code; `appendSessionIdToHistory` resolves the agent dir from `getOverdeckHome()`, which matches the host's `options.overdeckHome ?? process.env.OVERDECK_HOME ?? ~/.overdeck` default chain (`src/lib/acp/host.ts:67-69`). Tests set `OVERDECK_HOME` to a fixture dir.
- **D7 — Plan-size escape hatch used.** The plan names ~27 files across ~9 subsystem prefixes, over the finalize lint's projected-surface limits, so `plan.metadata.sizeJustification` is set: the record shape only has value when all six writers land together, and splitting per harness would ship a half-instrumented index that re-creates exactly the parity drift this issue removes.
