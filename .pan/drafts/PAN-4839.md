A lock-screen and Dynamic Island card that shows "N need you · M running" and nothing else. The two numbers travel in plain text through overdeck.ai and Apple (OD-1, settled by the operator on 2026-11-02). It is on by default, and the app's Settings has a switch to turn it off.

## Glossary

- **Live Activity:** an iOS 16.1+ card on the lock screen and in the Dynamic Island, defined with ActivityKit and drawn by a WidgetKit extension. Its content changes by APNs push with no app code running, so the content cannot be decrypted on the phone the way an alert can.
- **Content state:** the `Codable` struct a Live Activity renders. Here it is exactly `{ needsYou: Int, running: Int }`.
- **Activity push token:** a per-activity APNs token from `Activity.pushTokenUpdates`. It differs from the app's alert device token and changes when iOS rotates it or a new activity starts.
- **`liveactivity` push:** an APNs request with header `apns-push-type: liveactivity` and topic `ai.overdeck.app.push-type.liveactivity`. Its body is `aps.timestamp`, `aps.event`, `aps["content-state"]` and `aps["stale-date"]`.
- **Stale date:** a time after which iOS marks the card stale (`context.isStale`). The card then draws its numbers dimmed.
- **Widget extension:** a new Xcode target `OverdeckWidgets` (bundle id `ai.overdeck.app.widgets`, product `OverdeckWidgets.appex`) embedded in the app.
- **Directory:** `services/connect`, the overdeck.ai Cloudflare Worker with one Durable Object per account (`docs/CONNECT-SERVICE.md`).
- **Machine:** a computer running `pan up`. It holds `phone` access-token records, one per paired phone (`src/lib/access-tokens.ts`, kind `phone`, field `clientId`).
- **Report:** one machine's counts for one phone, sent in a `push-activity` frame. The directory keeps the last report per (phone, machine).
- **Sum:** the counts the card shows: the sum of a phone's reports that are fresh (received in the last `ACTIVITY_STALE_MS`, 10 minutes).
- **Primary dashboard:** a dashboard that is not a peer (`isPeerDashboard` false in `src/dashboard/server/main.ts`). Only it sends pushes.
- **Mac rig:** the Mac build machine reached with `ssh -i ~/.ssh/gauntlet_air eltmon@<rig-ip>` (IP by DHCP, usually `.83`). `apps/mobile/README.md` lines 59-84 has its Simulator steps.

## Requirements

### Functional

- **FR-1 The card.** On iOS 16.2 or later, the app shows a Live Activity whose content is exactly two integers: how many items need you and how many agents are running. Lock screen text: "N need you · M running" ("1 needs you" for one). Dynamic Island compact: the needs-you count leading and the running count trailing; minimal: the needs-you count; expanded: "N need you" and "M running". Before the first update the counts draw as "–".
- **FR-2 Counts only through Apple and overdeck.ai.** Every `push-activity` frame and every `liveactivity` APNs body carries the two counts and the APNs timing fields (`timestamp`, `event`, `stale-date`) and nothing else: no titles, names, ids, labels or text.
- **FR-3 What the counts mean.** On each machine, `needsYou` = `conversations.length + agents.length` of `buildNeedsYou()`, and `running` = the read-model agents whose `status` is in `{running, active, starting, thinking, working}`. The card shows the sum over every machine paired with the phone that reported in the last 10 minutes.
- **FR-4 Updates.** A machine reports a change within 20 s (5 s poll, at most one report per 15 s, the latest state always sent). It re-reports unchanged counts every 5 minutes. The directory pushes when the sum changes, or at most every 4 minutes to move the stale date forward. The stale date is 10 minutes after each push.
- **FR-5 On by default, switch in Settings.** The app starts or adopts the card on launch and on every return to the foreground while the setting is on. Settings → "Live Activity" turns it off: the card ends at once and the directory forgets the token. Turning it back on starts it again.
- **FR-6 Registration.** The app registers each activity push token with the directory in `activity-register { token, apsEnvironment }`, and registers again on every foreground start so the directory pushes the current sum at once.
- **FR-7 Sign-out.** Sign-out ends the card. The existing `forget-client` deletes the directory's activity registration and reports.
- **FR-8 Not iPhone-capable devices.** On Android, on iOS before 16.2, and when the user turned Live Activities off in iOS Settings, the app sends no activity frames. Settings hides the switch on Android and iOS before 16.2, and shows "Turn on Live Activities for Overdeck in iOS Settings." when iOS disallows them.
- **FR-9 Dead tokens.** An APNs 410, or 400 `BadDeviceToken` / `DeviceTokenNotForTopic` / `Unregistered`, clears the phone's activity registration if it still holds that token.

### Non-functional

- **NFR-1 Alerts never starve.** Activity pushes have their own per-account window, `ACTIVITY_PUSH_RATE_PER_MINUTE = 60`, separate from the 30-per-minute alert window.
- **NFR-2 Protocol version stays 1.** New frames only; `CONNECT_PROTOCOL_VERSION` stays `1`.
- **NFR-3 Primary dashboard only.** A peer dashboard sends no `push-activity`.
- **NFR-4 Async only.** No `execSync`, no new `*Sync` calls in server-reachable code (repo rule `no-execsync-server`, `prefer-async`).
- **NFR-5 Fake timers.** Every test of the poll, throttle, keepalive, refresh, retry or rate window uses `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync()`, or an injected `now`/`sleep`; never a real wait (repo rule `fake-timers-for-retry-tests`).
- **NFR-6 Logs.** Directory logs carry frame type, ids and a short outcome, never a token. Machine logs never carry a token. Swift logs print a token's length, never the token.
- **NFR-7 iOS floor unchanged.** The app target stays at iOS 15.0; ActivityKit code is behind `@available(iOS 16.2, *)`; the widget target is 16.2.

## Decisions (auto mode; each is recorded in `plan.autoDecisions`)

- **D-1 New frames, not an extended `push-register`.** Client → directory: `activity-register { token, apsEnvironment? }` and `activity-unregister {}`. Machine → directory: `push-activity { to, needsYou, running }`. A separate registration keeps alert push working when the card is off. This replaces the epic's `push-register { liveActivityToken }` sketch (`pan-4823.md` line 385).
- **D-2 `push-activity` is fire-and-forget.** It has no `requestId` and no answer frame; the machine has nothing to do with a result. The directory logs the outcome.
- **D-3 The directory sums.** Each machine reports to every phone it is paired with. The directory keeps the last report per (clientId, environmentId) and pushes the sum of fresh reports. A card fed by several machines would otherwise flip between their numbers. Reports are stored even when the phone has no activity registration, so a new registration can be pushed at once.
- **D-4 Push on register.** `activity-register` pushes the current sum at once when a fresh report exists. The app therefore starts the card with `-1, -1` ("–") and needs no counts route on the machine.
- **D-5 Priority.** APNs priority 10 when the sum differs from the last pushed sum (or on the first push after a register), else 5 (refresh only). `NSSupportsLiveActivitiesFrequentUpdates` is on. AC-12 asks for an update within 30 s; priority 5 may be delayed by iOS.
- **D-6 Timing constants.** Contracts: `ACTIVITY_STALE_MS = 600_000`, `ACTIVITY_REFRESH_MS = 240_000`, `ACTIVITY_PUSH_RATE_PER_MINUTE = 60`, `ACTIVITY_COUNT_MAX = 9_999`. Machine (sender module): `LIVE_ACTIVITY_POLL_MS = 5_000`, `LIVE_ACTIVITY_MIN_INTERVAL_MS = 15_000`, `LIVE_ACTIVITY_KEEPALIVE_MS = 300_000`. The refresh (4 min) is shorter than the keepalive (5 min) so every keepalive moves the stale date, and two missed keepalives leave the card stale.
- **D-7 "Running" matches the dashboard pill.** The same five statuses as `AgentPillPopoverRow.tsx:3`, no role filter, so the phone and the desktop agree.
- **D-8 Local machine counts.** Fleet rows of linked machines are not counted; the phone does not show them either (fact 8). PAN-4887 can revisit.
- **D-9 Independent of `push.enabled`.** The machine's `push` config governs notifications. The card has only the app's switch (OD-1). The sender runs whenever a phone record exists and the directory is online.
- **D-10 Entitlement overlap with PAN-4838.** ActivityKit push tokens need the Push Notifications capability (`aps-environment`). Rule: if `apps/mobile/ios/App/App/App.entitlements` exists, ensure it has `aps-environment`; otherwise create it with `aps-environment = development` and set `CODE_SIGN_ENTITLEMENTS = App/App.entitlements` on the App target's Debug and Release configurations. Then comment on PAN-4838 that the file exists. This issue does not add `@capacitor/push-notifications`, Keychain Sharing, App Groups or the NSE.
- **D-11 `apsEnvironment` from the build.** The Swift plugin answers `sandbox` in `#if DEBUG` builds and `production` otherwise. It does not depend on PAN-4838's code.
- **D-12 Target generation on the rig.** The widget target is added to `project.pbxproj` by a committed, idempotent Ruby script using the `xcodeproj` gem, run on the Mac rig. Fallback in WI-8.
- **D-13 No push-to-start.** iOS ends a Live Activity after at most 8 hours; the card comes back the next time the app is opened. Push-to-start (iOS 17.2+) is out of scope.
- **D-14 Stale draws dimmed.** When `context.isStale`, the numbers draw at 50 % opacity; no extra text.
- **D-15 Debug demo.** A `#if DEBUG` launch argument `-overdeckLiveActivityDemo N,M` starts a local card with those counts, so the rig can screenshot the widget without sign-in or APNs. Release builds ignore it.
- **D-16 Live device run is a gated checkpoint.** A real `liveactivity` push needs the production APNs secrets (PAN-4841) and a signed build on a device. WI-12 records the device run if the secrets exist, else records "not run" and hands the step to PAN-4841 by issue comment.
- **D-17 Size justification.** The plan spans contracts, the directory, the machine, the app and iOS native code (more than 25 files and 6 path subsystems). W-IOS2 is one epic work item and the OD-1 privacy rule must be proven across all layers in one review, so it ships as one issue with `plan.metadata.sizeJustification`.

## Architecture

```
 Machine (primary dashboard)              connect.overdeck.ai (account DO)                      iPhone
 ───────────────────────────              ────────────────────────────────                      ──────
 live-activity-service: every 5 s
   counts = buildNeedsYou + agents
   changed & ≥15 s since last, or 5 min ──► push-activity {to, needsYou, running}  (per phone)
                                            store report (client, env)
                                            sum fresh reports (10 min)
                                            changed, or ≥4 min since push,
                                            and a registration exists     ──► APNs liveactivity ──► widget draws
                                                                                {timestamp, event,     "3 need you · 2 running"
                                            ◄── activity-register {token, apsEnvironment} ───────── app (foreground)
                                            ◄── activity-unregister ──────────────────────────────── Settings switch off
```
