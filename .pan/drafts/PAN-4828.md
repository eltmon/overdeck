## Glossary

- **Directory:** the overdeck.ai connection service, `services/connect` (Cloudflare Worker plus one Durable Object per account). Machines hold a WebSocket to it at `wss://connect.overdeck.ai/v1/directory`.
- **Machine:** a computer running the Overdeck dashboard server. It talks to the directory with `MachineToDirectoryFrame` and hears `DirectoryToMachineFrame`.
- **Client:** the new directory role from epic decision D-2. A phone app connected to the directory. It is not a machine and does not use a machine slot.
- **Frame:** one JSON text message on the directory WebSocket. Every frame has a string `type` field that discriminates the union it belongs to.
- **Contracts file:** `packages/contracts/src/connect.ts`. It is *runtime-import-free*: the connect Worker imports it by relative path, so it may only use `import type`. Constants (plain values) are allowed; runtime imports are not.
- **Decoder:** `services/connect/src/protocol.ts` `decodeMachineFrame`. It rebuilds each incoming frame from known keys and answers `bad_frame` for any unknown `type`. This issue does not change it.
- **Reducer:** `services/connect/src/directory-state.ts` `reduce`. A pure function from (state, event) to (state, effects). Its private `frame()` function switches over every non-`hello` machine frame type.
- **Sealed payload:** a notification encrypted with libsodium `crypto_box_seal` to the phone's push public key, then base64-encoded. `crypto_box_seal` adds 48 bytes (32-byte ephemeral public key plus 16-byte MAC).
- **Type-level rejection test:** a line in a test file prefixed with `// @ts-expect-error`. `tsc` fails with TS2578 ("Unused '@ts-expect-error' directive") if the line does *not* produce a type error, so each such line proves the type rejects that shape.

## Decisions

- **D-1 `push` joins `MachineToDirectoryFrame` now, with a reducer stub.** The machine's directory port types `send(frame: MachineToDirectoryFrame)` (`directory-client.ts:202`), and W-MAC3 (PAN-4843) must send `push` through it. Keeping `push` in the union is the contract; Fact 3 forces a `case 'push'` in `directory-state.ts` `frame()`. The stub returns exactly what the directory does today for an undecodable frame from a registered machine: `error bad_frame "malformed frame"` to the sender and a log effect, state unchanged. Use an explicit `case`, never a `default:`, so the switch stays exhaustive and the next frame type again forces a decision. W-CON3 (PAN-4830) replaces the stub.
- **D-2 `push-result` is a discriminated pair.** The epic shape is `{ requestId, ok: boolean, error?: … }`. This PRD types it as `{ ok: true }` or `{ ok: false; error: PushResultError }`. JSON on the wire is identical; the type additionally rejects `ok: false` with no error and `ok: true` with an error.
- **D-3 Sealed cap: keep 3,072 characters; the plaintext ceiling is 2,256 bytes.** The cap is the contract the directory enforces, and 3,072 leaves about 860 bytes of headroom under the 4 KB APNs and FCM limits (Fact 10), while 2,900 bytes leaves 5. `PUSH_PLAINTEXT_MAX_BYTES = 2_256` is exported so W-MAC3 trims to it instead of the epic's 2,900. The epic's NFR-5 number is superseded for W-MAC3; this is recorded as a hazard and posted as a comment on PAN-4843.
- **D-4 `clientLimit: 4013` and `"client_limit"` land here, not in W-CON2.** The epic assigns the close code to W-CON2, but both are zero-runtime contract additions next to `CLIENT_LIMIT_MESSAGE`, and putting them here means W-CON2 never edits `CONNECT_CLOSE_CODES` or its exact-match test.
- **D-5 Client `signal.purpose` is the literal `"link"`.** The epic says a client's signal purpose "must be `'link'`". Typing it as the literal makes `"approval"` a compile error for every producer (the phone, W-WEB1). The directory decoder (W-CON2) still checks it at runtime.
- **D-6 `ice-servers` and `relay-usage` reuse the machine members via `Extract`.** The epic says they "follow the machine rules unchanged", so the client union takes them from `MachineToDirectoryFrame` and cannot drift.
- **D-7 Add `typecheck:contracts` to the root `typecheck`.** Fact 6 shows the rejection tests would otherwise be unenforced. It costs about 10 s and passes today (Fact 7).
- **D-8 Docs are one sentence.** W-DOC (PAN-4842) rewrites `docs/CONNECT-SERVICE.md` for the client role and push delivery. This issue adds only the sentence that keeps the doc true now, to avoid conflicting edits.
- **D-9 Size limits stay comments, except the sealed cap.** The repo convention puts per-field limits as comments in `connect.ts` and as constants in `protocol.ts` (`MAX_LABEL_CHARS`). Only `PUSH_SEALED_MAX_CHARS` and `PUSH_PLAINTEXT_MAX_BYTES` are exported, because the machine (producer) and the directory (validator) both need them.
