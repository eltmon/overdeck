**Q1 — Is the `@overdeck/core` library entry a supported public API?**
`package.json` has `"main": "./dist/index.js"`, built from `src/index.ts` (14 lines), which does
`export * from` `lib/paths.js`, `lib/config.js`, `lib/shell.js`, `lib/backup.js`, `lib/sync.js`,
`lib/tracker/index.js`, `lib/providers.js`, `lib/settings.js`, and five `lib/docs/*` modules. Those
modules hold 34 of the Shape B wrappers this epic deletes (`sync.ts` 12, `settings.ts` 8,
`shell.ts` 5, `config.ts` 4, `backup.ts` 3, `providers.ts` 2), 3 Shape A façades (`config.ts`), and
3 Shape C pairs (`backup.ts` 1, `providers.ts` 2). No file in this repository imports
`@overdeck/core` as a library, and no Mintlify page documents library usage (only
`npx`/`npm install -g`).
**Recommended:** No. Declare `src/index.ts` internal (header comment), allow removals, and note the
removed names in the release notes of the release that ships W2. Affects W2, W10.

**Q2 — What does "no module keeps both" mean?**
The issue says a module is Effect-native or Promise-native, never both. The audit (§2.4) finds 173
exported functions with genuine Effect bodies (`Effect.gen` pipelines, not façades) in 64 modules,
many of them in modules that also hold façades. Converting genuine Effect bodies to `async` is a
rewrite, not a deletion.
**Recommended:** Enforce it per **operation**, not per module: after this epic no operation is
exported in two variants (Effect + Promise, or Effect + sync, or Promise + sync) unless §10 keeps
the pair with a documented synchronous caller. Genuine Effect bodies stay Effect. A module may export
Effect functions and `async` functions for different operations. Converting the 173 genuine Effect
exports is out of scope (§8). Affects D1, FR-7, the ratchet design in W1.

**Q3 — After a twin is deleted, does the surviving `fooSync` get renamed to `foo`?**
Shape B deletion frees the bare name `foo`. Renaming `fooSync` → `foo` is readable but touches every
caller: `resolveProjectFromIssueSync` alone has 145 production and 184 test references;
`getProjectSync` 75 + 85; `listProjectsSync` 69 + 98. Every in-flight branch that calls a renamed
function conflicts.
**Recommended:** Keep the `Sync` suffix in this epic. Diffs stay deletion-only and reviewable, and
Node's own convention (`readFileSync`) already reads correctly. A later, purely mechanical rename
issue may follow once the epic is done. Never reuse a freed bare name for a different signature in
the same PR. Affects W2, W8.

**Q4 — Delete the legacy Pi runtime classes?**

`src/lib/runtimes/index.ts:142` says Pi "is legacy and no longer registered". No production file

is still used through `pi-fifo.ts`, `findPiTranscriptPath`, and `piSessionsRoot`, which stay.
**Recommended:** Delete both classes and their tests (the "backward-compat exports" are internal,

## 1. Glossary

| Term | Meaning |
| --- | --- |
| **Effect** | The `effect` library (`effect@4.0.0-beta.73`). An `Effect.Effect<A, E>` is a lazy description of work that runs only when executed. |
| **Promise-native** | A function declared `async` (or returning `Promise<T>`) with no Effect in its signature. |
| **Bridge** | Code that turns one style into the other. `Effect.promise(thunk)` and `Effect.tryPromise(thunk)` turn a Promise into an Effect; `Effect.runPromise(effect)` turns an Effect into a Promise. `docs/EFFECT-BRIDGING.md` says the Promise→Effect bridges are only for callees that genuinely return a Promise. |
| **Façade** | An exported function whose whole body is a bridge around another in-repo function. It adds a name and a style but no behaviour. Two shapes: A and B. |
| **Shape A (Promise façade)** | `export const foo = (…) => Effect.promise(() => fooPromise(…))` or `Effect.tryPromise({ try: () => fooPromise(…), catch: … })`, where `fooPromise` is an `async` function in the same repository (usually private, in the same file). Callers typically run it straight back to a Promise with `Effect.runPromise(foo(…))`. 220 in `src/lib`. |
| **Shape B (sync façade)** | `export const foo = (…) => Effect.sync(() => fooSync(…))` or `Effect.try({ try: () => fooSync(…), catch: … })`, where `fooSync` is an in-repo synchronous function. Most were added under the comment `// ─── Effect variants (PAN-1249) ───`. 301 in `src/lib`. |
| **Shape C (true twin)** | Two exported functions that implement the same operation independently, one synchronous (`fooSync`, usually `execFileSync`/`readFileSync`) and one Effect or `async` (`foo`). Neither is a façade over the other. 82 pairs in `src/lib`. |
| **Ping-pong** | A call chain that crosses the bridge back and forth with no Effect feature used in between, e.g. `Effect.runPromise(getAgentJsonlPath(id))` where `getAgentJsonlPath` is `Effect.promise(() => getAgentJsonlPathPromise(id))`, whose body calls `Effect.runPromise(getAgentWorkspace(id))`, which is another façade. |
| **Live / dead** | A façade or twin is **dead** when no production (non-test) file references its name outside its own declaration. **Live** otherwise. Measured with a name index, so "dead" is exact and "live" is an upper bound (a same-named local helper counts as a reference; e.g. eight files define their own private `normalizeIssueId`). `tsc --noEmit` is the final authority when a row is acted on. |
| **Production reference** | A reference to a name in a non-test file under `src/`, `packages/`, `apps/`, or `scripts/`. Test files match `tests/**`, `**/__tests__/**`, `*.test.ts(x)`, `*.spec.ts(x)`. |
| **`yield*` site** | A reference inside an `Effect.gen(function* () { … })` generator. These callers genuinely consume an Effect. |
| **Typed error channel** | The `E` in `Effect.Effect<A, E>`; `Effect.tryPromise`'s `catch:` maps a rejection into a tagged error (e.g. `FsError`) that callers can match with `Effect.catchTag`. |
| **Failure vs defect** | In Effect, a *failure* is a typed error that `Effect.catch` handles. A *defect* is an unexpected throw/rejection that `Effect.catch` does **not** handle. `Effect.promise` turns a rejection into a defect; `Effect.tryPromise` turns it into a failure. Rewrites must preserve which one a caller saw. |
| **Glued declaration** | A line such as `}async function getAgentWorkspacePromise(…)`: the closing brace of one function and the next declaration on one line, left by the PAN-1379 mechanical rewrite (`a09d03c0246`). 144 lines in 48 files. |
| **Harness storage knowledge** | Code that knows where a harness keeps its transcripts, session ids, or home directory (`~/.claude/projects/<slug>`, `$CODEX_HOME/sessions`, `~/.kimi-code/sessions`, pi/omp agent dirs). |
| **No-loss ledger** | `.pan/notes/pan-3958-no-loss.md`: one row per deleted exported name, naming its replacement or stating "no production consumer (inventory row …)". It is the answer to "was anything lost?" for reviewers. `tsc` and the unchanged test suite are the proof. |
| **Façade ratchet** | The new shrink-only gate from W1 (`npm run lint:effect-facades`). It counts Shape A, Shape B and Shape C per module and fails when any count grows. |
| **CH-n** | A proposed child issue (§6.2). Not filed yet. |

### 2.4 Does any caller use what Effect adds?

- **Typed errors.** Across all non-test `src/`, `Effect.catchTag` on a `src/lib/errors.ts` tag occurs

- **Interruption and Layer DI.** No façade body takes an `AbortSignal` or requires a service from the

- **Genuine Effect code.** Of 754 Effect-returning exports in `src/lib`, 521 (69 %) are façades,

## 3. Decisions (made here; do not re-decide during implementation)

- **D1 — Direction: Promise-native.** Every Shape A module becomes Promise-native for its façaded
  operations: the private `fooPromise` body is exported under the public name `foo` (as `export
  async function foo`) and the façade is deleted. Evidence: §2.4 (no caller uses typed errors,
  interruption, or DI; 334 ping-pong sites vs 70 `yield*` sites). Genuine Effect exports stay (Q2).
- **D2 — Call-site bridges preserve semantics exactly.** When a former façade is called from an
  Effect context, the bridge moves to the call site and keeps the original failure/defect behaviour:

  | Old façade | Old call | New call |
  | --- | --- | --- |
  | `Effect.promise` | `yield* foo(x)` | `yield* Effect.promise(() => foo(x))` |
  | `Effect.tryPromise` | `yield* foo(x)` | `yield* Effect.tryPromise(() => foo(x))` |
  | either | `foo(x)` passed to a combinator (`Effect.all`, `Effect.retry`, `Effect.repeat`, `Effect.timeout`, `Effect.forEach`, `pipe` chains built before running) | the same inline bridge as above, so laziness and re-execution are preserved |
  | either | `await Effect.runPromise(foo(x))` | `await foo(x)` |
  | `Effect.promise` | `Effect.runPromise(foo(x).pipe(Effect.catch(() => Effect.succeed(d))))` | `await foo(x)` (the old catch never saw a rejection: it was a defect) |
  | `Effect.tryPromise` | `Effect.runPromise(foo(x).pipe(Effect.catch(() => Effect.succeed(d))))` | `await foo(x).catch(() => d)` |
  | `Effect.tryPromise` | caller uses `Effect.catchTag('<Tag>', …)` on it | `yield* Effect.tryPromise({ try: () => foo(x), catch: (cause) => new <Tag>({ … }) })` copying the old `catch:` mapping; §2.4 found no such caller, so this row is a safety net |

  `Effect.tryPromise(() => …)` (single-argument form) fails with `Cause.UnknownError`, which
  `Effect.catch` handles, matching the old failure channel.
- **D3 — Shape B callers call the sync function directly.** `yield* foo(x)` inside a generator becomes
  `fooSync(x)` (a plain statement at the same point, same timing). If the wrapper was `Effect.try` and
  the yielded expression is followed by `.pipe(` containing `Effect.catch`, `Effect.orElse`, or
  `Effect.catchTag`, write `yield* Effect.try(() => fooSync(x)).pipe(…)` instead. Combinator
  arguments get `Effect.sync(() => fooSync(x))` inline (laziness). `await Effect.runPromise(foo(x))`
  becomes `fooSync(x)`; in a **non-async** function whose returned Promise is used, it becomes
  `Promise.resolve().then(() => fooSync(x))` so a throw stays a rejection.
- **D4 — Tests are ported, not deleted, when the subject survives.** A test that calls a deleted
  wrapper is rewritten to call the surviving function with the same assertions (codemod in W6 step 5).
  Tests are deleted only when their subject is deleted without a surviving equivalent (dead Shape A
  bodies, Shape C rows C1/C2, runtime twin classes), and each such test is listed in the no-loss
  ledger.
- **D5 — No-loss ledger.** Every PR in this epic appends a section to `.pan/notes/pan-3958-no-loss.md`:
  one row per deleted exported name → surviving name, or "no production consumer (inventory
  `file:line`)". Reviewers read the ledger; `tsc --noEmit` plus the unchanged test suite prove it.
- **D6 — The façade ratchet lands first (W1).** A shrink-only gate like
  `scripts/lint-effect-diagnostics.sh`: counts per module, `NEW:` fails, `--update` only lowers,
  baseline growth requires an issue reference audited by `scripts/lint-ratchet-audit.sh`. Every
  child PR lowers the baseline in the same commit as the deletion.
- **D7 — Glued declarations are split in the same touch.** Any file a PR edits for this epic gets its
  `}async function` / `}function` / `}export` lines split into `}` + blank line + declaration.
- **D8 — Shape C decisions follow the table in §10**, generated by rules C1–C6 (W8). A kept sync
  twin gets a module-header comment naming its synchronous callers and why they cannot await.
- **D9 — The Effect runtime interface and classes are deleted** (`AgentRuntime`, `AgentRuntimeError`,
  `ClaudeCodeRuntime`, `CodexRuntime`, `OhmypiRuntime`, their factories). Zero consumers (§2.5).
- **D10 — Keep the `Sync` suffix** on surviving synchronous functions (Q3).
- **D11 — Harness storage has one owner per harness:** a new leaf module
  `src/lib/runtimes/storage/<harness>.ts` (imports only `node:*` and `src/lib/paths.ts`), so it can be
  imported from anywhere without creating an import cycle (`scripts/lint-circular-deps.sh` must not
  gain a cycle). Existing functions move there; there are no re-export shims (W9).
- **D12 — tmux stays supported.** `docs/TERMINAL-BACKENDS.md` keeps tmux as a supported backend, so
  `src/lib/tmux.ts` twins are handled by §10 like any other module, not deleted wholesale.
- **D13 — No new dependencies.** The ratchet reuses the `typescript` compiler API (already a
  devDependency); no knip/ts-prune.

## 5. Intersecting repo rules (restated)

- **Typecheck excludes tests.** `npm run typecheck` does not type-check `*.test.ts`. After a rename or
  deletion, run `npx tsc --noEmit -p tsconfig.json` **and** the affected test files with
  `npx vitest run <paths>` so an undefined import in a test fails locally, not on main.
- **Never run the full `npm test` on the host** (PAN-3965). Local gates are `npm run typecheck`,
  `npm run lint`, and `npx vitest run <touched test files>`; the full suite runs once on CI and a red
  CI test job returns as verification feedback. To find every test that imports a touched module:
  `git grep -lE "from '.*/<module-basename>(\.js)?'" -- tests 'src/**/__tests__/**'`.
- **No `execSync` in server-reachable code** (`src/dashboard/**`, `src/lib/cloister/**`; PAN-70).
  Shape C work must convert, never add, blocking calls there (FR-8).
- **Prefer async tmux primitives** (`prefer-async.md`): do not add new sync tmux functions or callers.
- **Effect bridging** (`docs/EFFECT-BRIDGING.md`): never write `Effect.promise(() => <something that
  returns an Effect>)`; it throws `TypeError: internalCall(...).then is not a function` at runtime.
  After D1 the former façades return Promises, so the D2 bridges are correct; before D1 lands in a
  module, do not bridge its façades.
- **Test-skip gate** (PAN-3847/PAN-3906): verification fails if the whole diff removes more
  `it()`/`test()` calls than it adds, except whole test files deleted together with their subject
  module. Ported tests (D4) keep the balance. When CH-1 or CH-8 genuinely deletes tests of a deleted
  subject inside a surviving module, the operator records `pan verify waive-test-removal <issue>
  --reason "PAN-3958 deleted subject, see no-loss ledger"` at that HEAD; the implementer asks for it
  in the PR body and never re-adds tests to pass the gate.
- **File-size ratchet** (`scripts/lint-file-size.sh`): files may not grow past their base line count;
  this epic only shrinks files. Run `bash scripts/lint-file-size.sh --lower` after a PR to lower
  allowlist caps of touched files (`src/lib/tmux.ts`, `src/lib/sync.ts`, …).
- **Circular-dependency ratchet** (`scripts/lint-circular-deps.sh`): no new cycle. Moving code
  (W9) must keep storage modules leaf-only (D11).
- **Fake timers** for any test that waits (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`);
  this epic adds no waits, but ported tests that already use fake timers keep them.
- **Worktree / stash discipline:** work only in the issue's workspace; never `git stash`; never edit
  the primary checkout.
- **Dashboard runs Node 22 dist.** After a server-reachable change, `npm run build` before `pan reload`.
- **Additive-by-default rule (operator feedback "no actions lost").** A refactor that deletes surface
  must enumerate what exists first and prove every item has a home. Here the inventory is the
  enumeration and the no-loss ledger (D5) is the proof.
