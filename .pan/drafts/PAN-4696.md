## Glossary

- **Deployed build** — the dashboard server the Flywheel's `pan reload` started. Its commit is `buildCommit` in `curl -s localhost:3011/api/health`. At planning time it was `6563a676e9fa7a6927615402cf5b4425bae197f7` (built 2026-11-02T15:23:59Z, generation `.pan-reload-generation-b`).
- **Deacon child** — the Node process `~/.overdeck/deployments/dashboard/.pan-reload-generation-*/dist/dashboard/deacon.js`, a child of the dashboard server. It runs deacon-lite and the hygiene scheduler. Its stdout is inherited from the dashboard (`src/dashboard/server/services/deacon-supervisor.ts`, `stdio: ['ignore', 'inherit', 'inherit', 'ipc']`), so its console lines land in `~/.overdeck/logs/dashboard.log` — **not** `~/.overdeck/logs/deacon.log`.
- **Deacon-lite tick** — `runDeaconLite()` in `src/lib/cloister/deacon-lite.ts`, run every 60 s (`GET /api/deacon/status` → `deaconLite.intervalMs: 60000`). Its last routine is `await reapFinishedRemoteAgents();` (search `PAN-4295: hand finished Fly remote agents to review`).
- **Remote reap routine** — `reapFinishedRemoteAgents()` in `src/lib/cloister/remote-reap-routine.ts`. It calls `reapCompletedRemoteAgents()` (`src/lib/remote/remote-completion.ts`) and prints `[deacon-lite] Remote reap <ISSUE>: handed-off (<details>)` for each hand-off.
- **Hand-off** — the reap's success path in `remote-completion.ts`: materialize `workspaces/feature-<id>`, open the PR, write the `completed` marker, copy transcripts back, destroy the machine, delete the remote workspace metadata, then call `requestReviewThroughRoute(issueId, { source: 'remote-reap', … })` (search `source: 'remote-reap'`).
- **Deacon freeze** — `app_settings.deacon.globally_paused` in `~/.overdeck/panopticon.db`. When `'true'`, `runDeaconLite()` returns before any routine runs, so no automatic reap happens. The hygiene scheduler ignores it.
- **Host heartbeat** — `refreshHostHeartbeatForEphemeralVms()` in `src/lib/remote/remote-agents.ts`, run every 60 s by the hygiene scheduler (`src/lib/cloister/hygiene-scheduler.ts`, routine name `refreshHostHeartbeatForEphemeralVms`). It writes the current ISO time to `/workspace/.pan/host-heartbeat` on each remote agent whose `remote-state.json` has `status` `running`/`starting` and `tier` ≠ `durable`. Each pass prints `[hygiene-scheduler] refreshHostHeartbeatForEphemeralVms: Host heartbeat refreshed for <ISSUE> on <vmName>` to `dashboard.log`.
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl` (`src/lib/cloister/pipeline-journal.ts`). The review door appends `{ type: 'review.requested', issueId, source }` when it accepts a request (`src/dashboard/server/routes/workspaces/review-pipeline.ts`, search `type: 'review.requested'`). The route maps the request body's `source` to itself only for a fixed list that includes `'remote-reap'` (search `rawSource === 'remote-reap'`); anything else journals `'api'`.
- **Smoke issue** — a throwaway GitHub issue created by the work agent only to drive one remote run. Its PR is closed unmerged.
- **Remote agent state** — `~/.overdeck/agents/agent-<smoke-id-lower>/remote-state.json`, with `vmName` (for example `pan-pan-4677-ws`), `status`, `tier`.
- **`SMOKE`** — placeholder in this document for the smoke issue ID (uppercase, for example `PAN-4900`); **`smoke`** — the same ID lowercased (`pan-4900`).

## Problem

PAN-4295 restored three host loops for Fly remote agents (auto-reap, ephemeral-VM heartbeat, credential refresh). Its pre-merge live smoke test (PAN-4677, recorded under `## Live verification` in `docs/fly-provider.md`) proved the reap only through the feature branch's own `dist/` build via a manual `node dist/cli/index.js admin remote reap`. Three behaviors could not be observed before merge because only the deployed deacon child runs them:

1. The 60 s deacon-lite tick hands a finished agent off with no operator command.
2. The hand-off's review request journals `source: "remote-reap"` (pre-merge it journaled `"api"` because the deployed review route had the old source parser).
3. The hygiene scheduler keeps `/workspace/.pan/host-heartbeat` fresh (under 2 minutes old) while the agent works.

`docs/fly-provider.md` ends the PAN-4295 section with "The automatic 60 s tick, the `remote-reap` journal source and the heartbeat file are checked after deploy in [#4696]". This issue performs that check and records the result there.

## Requirements

### Functional

- **FR-1** — With no operator reap command, the deployed deacon-lite tick hands the smoke agent off after `/workspace/.pan/REMOTE_DONE` appears: `dashboard.log` gains `[deacon-lite] Remote reap SMOKE: handed-off (…)`, the Fly machine is gone from `fly machines list -a pan-workspaces`, and `workspaces/feature-smoke/` exists locally.

- **FR-3** — While the smoke agent works, `/workspace/.pan/host-heartbeat` on its VM is under 120 s old, on two readings taken at least 60 s apart, and the second reading's mtime is strictly later than the first (proves the loop rewrites it, not a single write).
- **FR-4** — The smoke run uses the deployed, un-worked-around path: no `[remote.fly] image` override, no manual `git push` of the smoke branch, no `--plan skip`. This doubles as the live regression check for PAN-4682 and PAN-4683.

### Non-functional

- **NFR-1** — No source code under `src/` changes in this branch. A failed check is root-caused and filed as a new issue, never fixed here (see D-3).
- **NFR-2** — The work agent never runs `pan reload`, `pan restart`, `pan up`, or any dashboard/deacon restart. The deployed build is what is under test; only the Flywheel deploys.
- **NFR-3** — The work agent never runs `pan admin remote reap` (with or without `--dry-run`) for SMOKE before FR-1 is observed or the D-4 timeout expires. Running it would make FR-1 unobservable.
- **NFR-4** — No destructive HTTP requests. Deep-wipe (`POST /api/issues/:id/deep-wipe`) is forbidden, including for the smoke issue.
- **NFR-5** — Waiting uses one long foreground poll loop that prints only on change (no chatty repeated polls, no foreground `sleep` outside a loop). Each loop has an explicit cap.

## Decisions (made in this doc)

- **D-1 — Consent.** The issue itself orders a `pan start <id> --remote` run, so its Fly spend (a few cents) and the temporary `remote.enabled = true` flip are in scope. No operator question is asked. The flip is restored in WI-7 even when a check fails.
- **D-2 — Start path.** Two commands: `pan plan SMOKE --auto`, wait until it finalizes (issue reaches Planned), then `pan start SMOKE --remote`. Not `pan start SMOKE --remote --plan auto`: that path's post-planning auto-start goes through the dashboard spawn route's guardrail gate (`src/dashboard/server/routes/agents/spawn-issue.ts`, search `Guardrail acknowledgement required`), which refused hand-offs on this host at 11/10 work agents. The direct CLI `pan start --remote` calls `spawnRemoteAgent` (`src/cli/commands/start.ts`) and does not pass that gate.
- **D-3 — A failed check is filed, not fixed.** A fix in this branch could not be verified live until another merge and deploy, so it would need its own post-deploy check. On any failed check: investigate the root cause (read `dashboard.log`, the reap's details line, the agent's `remote-state.json`), file a new GitHub issue that links PAN-4295 and PAN-4696 with the evidence and the cause, record the failure in the docs table with the filed issue link, and run `pan tell flywheel-orchestrator "work PAN-4696: <check> failed on the deployed build — filed <#n>"`. The docs item still lands (it records a true result). Exception: a PAN-4682/PAN-4683 regression (D-5) is filed and then worked around so FR-1..FR-3 can still be observed.
- **D-4 — Timeouts.** Wait up to 30 min for the smoke planning to finalize; up to 20 min for `remote-state.json` to reach `status: running`; up to 30 min after `running` for `REMOTE_DONE`; up to **10 min** (10 ticks) after `REMOTE_DONE` for the automatic hand-off. A single failed reap attempt (for example `cannot lock ref 'refs/remotes/origin/feature/…'`, seen in PAN-4677) followed by a hand-off on a later tick still passes FR-1. When the 10-min hand-off wait expires: check the deacon freeze and `dashboard.log` for `Remote reap SMOKE` lines, record FR-1 as failed (D-3), then — only now — run `pan admin remote reap --issue SMOKE` once so the machine does not keep billing, and continue with WI-6/WI-7 if a workspace was materialized.
- **D-5 — PAN-4682/4683 regression fallback.** If `pan start SMOKE --remote` starts a second planning session (`planning-smoke` appears again) or the machine fails to start because the image does not exist, file a regression issue linking PAN-4682 or PAN-4683, then continue with the old workaround: `git -C workspaces/feature-smoke push origin feature/smoke` and `pan start SMOKE --remote --plan skip`, or set `[remote.fly] image = "registry.fly.io/pan-workspaces:latest"` in `~/.overdeck/config.toml` (and remove it in WI-7).
- **D-6 — Smoke task length.** PAN-4677's agent lived about 80 s (`startedAt 08:05:39`, `lastActivity 08:06:58` in its `remote-state.json`), which leaves room for at most one heartbeat write. The smoke task therefore includes an explicit `sleep 150` before its commit, giving at least two heartbeat ticks while the agent is busy. Claude Code's Bash tool default timeout is 120 s, so the task body states the sleep as two steps of `sleep 75`.
- **D-7 — Evidence file.** Raw command output collected across items goes to `.tmp/pan-4696-evidence.md` in the workspace (`.tmp/` is gitignored, `.gitignore` line `.tmp/`). The committed record is the docs section; each item commits its own row or paragraph there, which is the commit that carries its `Item:` trailer.
- **D-8 — Transcript copy-back is observed but not gated.** PAN-4295 also fixed `copyFromVm` (an Effect was awaited without being run, so `remote-sessions/` stayed empty). WI-5 records whether `~/.overdeck/agents/agent-smoke/remote-sessions/` holds at least one `.jsonl` after the hand-off. A miss is filed per D-3 but does not fail FR-1.
- **D-9 — Review convoy.** The hand-off requests a real review of the smoke PR, which spawns reviewers and a verification worker. WI-7 runs `pan review abort SMOKE` right after the journal is read so they stop billing.
