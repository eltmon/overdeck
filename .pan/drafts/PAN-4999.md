# PAN-4999: pan tell rejects a conversation's bare name; only the conv- prefixed name works

**Issue:** [PAN-4999](https://github.com/eltmon/overdeck/issues/4999)
**Status:** draft (planned 2026-11-04, `pan plan --auto`)

## Glossary

- **Target**: the first argument of `pan tell`, `pan kill`, `pan pause`, `pan unpause`, `pan untroubled` and `pan conv pending`. All six resolve it through one shared resolver.
- **Shared resolver**: `resolveCliAgentTarget` and its wrapper `resolveCliSingleAgentId` in `src/cli/agent-target.ts` (PAN-4465).
- **Conversation name**: the `name` column of the `conversations` table in `~/.overdeck/overdeck.db`, for example `20261103-3f3a`. Unique (`conversations_name_unique`), compared case-sensitively by `getConversationByName` (`WHERE c.name = ?`).
- **Conversation rowid**: the number the dashboard shows in `/conv/<n>`, for example `3570`. Looked up by `getConversationById`.
- **Session name (`tmuxSession`)**: the terminal session of a conversation, normally `conv-<name>`. This is the agent ID that `messageAgent` delivers to.
- **Qualified agent ID**: input that starts with a known prefix (`agent-`, `planning-`, `conv-`, `strike-`, `inspect-`) or is a singleton such as `flywheel-orchestrator`. Detected by `isQualifiedAgentId` (`src/lib/agents/identity.ts`).
- **Issue-shaped input**: input that matches `/^[A-Za-z]+-\d+$/`, for example `PAN-1148`. This is the standard issue ID shape (`parseIssueId` in `src/lib/issue-id.ts`, line 42 `issueId.match(/^([A-Za-z]+)-(\d+)$/)`).
- **Name-shaped input**: any input that is not a dashboard URL, not `conv/…` / `conv:…`, not a qualified agent ID, not all digits and not issue-shaped. Examples: `20261103-3f3a`, `pan-1148-review`, `my-notes`.
- **Agent directory**: `<OVERDECK_HOME>/agents/<agentId>/` (`AGENTS_DIR` in `src/lib/paths.ts`). A local agent writes `state.json` there; a remote (Fly) agent writes `remote-state.json` there.

## Problem

Steps from the issue: conversation `20261103-3f3a` (rowid 3570, session `conv-20261103-3f3a`) is running.

- `pan tell 20261103-3f3a "hi"` → `Error: Agent agent-20261103-3f3a not running`
- `pan tell conv-20261103-3f3a "hi"` → delivered.
- `pan tell 3570 "hi"` → delivered (bare digits already try the rowid).

### Root cause (verified)

`src/cli/agent-target.ts`, `resolveCliAgentTarget` (grep anchor `return { kind: 'issue', issueId: resolveIssueId(input) };`):

```ts
export async function resolveCliAgentTarget(input: string): Promise<AgentTargetResolution> {
  const urlMatch = input.match(CONV_URL);
  if (urlMatch) return resolveExplicitConversationForm(decodeURIComponent(urlMatch[1]), input);

  const prefixMatch = input.match(CONV_PREFIX);
  if (prefixMatch) return resolveExplicitConversationForm(prefixMatch[1], input);

  if (isQualifiedAgentId(input)) return { kind: 'agent', agentId: input.toLowerCase(), via: 'agent-id' };

  if (/^\d+$/.test(input)) return resolveBareDigits(input);

  return { kind: 'issue', issueId: resolveIssueId(input) };
}
```

`20261103-3f3a` is not a URL, not `conv/…`, not qualified and not all digits, so it falls through to the last line. `resolveIssueId` (`src/lib/issue-id.ts:123`) upper-cases it to `20261103-3F3A`. `resolveCliSingleAgentId` then calls `resolveAgentTarget` (`src/lib/agents/identity.ts:79`), which never returns null for this input: it returns the canonical `agent-20261103-3f3a` even though no such agent exists (comment: "If no single fallback exists, preserves the historical canonical agent-* target"). `messageAgent` then fails its liveness check and throws `Agent agent-20261103-3f3a not running` (`src/lib/agents/messaging.ts:704`). The conversation table is never consulted, and the error blames a running conversation.

The resolver's `no agent for <issue>` failure branch in `resolveCliSingleAgentId` is therefore dead for name-shaped input, so the operator never sees the list of accepted forms.

## Requirements

- **FR-1**: A name-shaped target that equals the `name` of a local (non-vault) conversation resolves to that conversation's `tmuxSession`, with `via: 'conversation'`.
- **FR-2**: For one live conversation, the bare name, the `conv-<name>` agent ID and the bare rowid all resolve to the same agent ID (`conv-<name>`).
- **FR-3**: Issue-shaped targets (`/^[A-Za-z]+-\d+$/`) keep today's behavior exactly: `{ kind: 'issue', issueId }`, with no conversation lookup.
- **FR-4**: A name-shaped target that matches no conversation but whose resolved agent directory exists (`<AGENTS_DIR>/<resolveAgentTarget(resolveIssueId(input))>`) keeps today's behavior: `{ kind: 'issue', issueId: resolveIssueId(input) }`. This keeps `pan tell PAN-1148-review` (agent `agent-pan-1148-review`) and remote agents (which have only `remote-state.json`) working.
- **FR-5**: A name-shaped target that matches both a local conversation and an existing agent directory is `ambiguous`, listing both explicit forms (`conv/<rowid>` and the agent ID).
- **FR-6**: A name-shaped target that matches neither is `unresolved`. Its reason names every form that was tried, for example: `no conversation named 20261103-zzzz and no agent agent-20261103-zzzz`.
- **FR-7**: A name-shaped target whose conversation lookup throws falls back to FR-4 when the agent directory exists; otherwise it is `unresolved` with reason `conversation lookup failed: <message>; no agent <agentId>`.
- **FR-8**: A name-shaped target that matches only a Session Vault conversation row (`origin: 'vault'`) is treated as no conversation (same rule as `resolveBareDigits`).
- **FR-9**: `ACCEPTED_TARGET_FORMS` lists the bare conversation name as an accepted form, so `printAgentTargetFailure` shows it.
- **NFR-1**: The conversation module (`src/lib/overdeck/conversations.js`) stays lazily imported (existing `lookupConversation`), and issue-shaped targets never load it (no extra latency on the hot `pan tell PAN-123` path).
- **NFR-2**: No new export on the `src/lib/agents.js` barrel (every resolver test mocks the barrel with an explicit export list; `src/lib/__tests__/agents-barrel-exports.test.ts` pins its export set).
- **NFR-3**: The name lookup passes the raw input to `getConversationByName` without lower-casing (names are stored and compared case-sensitively).

## Decisions

- **D1 — issue-shaped first.** Issue-shaped input never consults the conversation table. Consequence: a conversation a user named exactly like an issue ID (for example `pan-1148`) is not reachable by its bare name; `conv/pan-1148` and `conv-pan-1148` still work. This keeps `pan tell PAN-123` byte-for-byte unchanged and avoids importing the conversation DB module on the hot path.
- **D2 — agent-directory existence decides between "keep today's issue path" and "unresolved".** The check is `existsSync(join(AGENTS_DIR, resolveAgentTarget(resolveIssueId(input))))`. A directory check (not `state.json`) is used because remote agents persist only `remote-state.json` (see `src/cli/commands/kill.ts`, comment "Remote (fly.io) agents persist remote-state.json, not state.json"). `resolveAgentTarget` comes from the `agents.js` barrel that agent-target.ts already imports; `AGENTS_DIR` comes from `src/lib/paths.js`; `existsSync`/`join` from `node:fs`/`node:path`. Sync FS is acceptable here: `agent-target.ts` is CLI-only (same rationale as `listBareNumericIssueMatches`).
- **D3 — inline regex for issue shape.** Use a module constant `const ISSUE_ID_SHAPE = /^[A-Za-z]+-\d+$/;` in `agent-target.ts`, not `parseIssueId`. Reason: `src/cli/commands/__tests__/kill.test.ts` mocks `../../../lib/issue-id.js` with an explicit export list that lacks `parseIssueId`; vitest throws on access to a missing mocked export. Rally IDs (`US123`) are therefore name-shaped; they still resolve through FR-4 when their agent directory exists.
- **D4 — ambiguity over silent preference.** When both a conversation and an agent match a name-shaped target, return `ambiguous`, mirroring `resolveBareDigits`. Collisions are rare, and guessing would deliver a message to the wrong recipient.
- **D5 — scope is the shared resolver.** The fix lands in `resolveCliAgentTarget`, so `pan tell`, `pan kill`, `pan pause`, `pan unpause`, `pan untroubled` and `pan conv pending` all gain the bare-name form. No per-command change.
- **D6 — no change to `messaging.ts`.** The downstream `Agent <id> not running` error stays; after this change a name-shaped unknown target never reaches it, and issue-shaped targets keep their existing message.

### WI-1: Resolve name-shaped targets through the conversation table (FR-1, FR-3…FR-8, NFR-1…NFR-3)

File: `src/cli/agent-target.ts` (150 lines on main; stays well under any file-size cap).

Steps:

1. Add imports at the top:
   ```ts
   import { existsSync } from 'node:fs';
   import { join } from 'node:path';
   import { AGENTS_DIR } from '../lib/paths.js';
   ```
2. Add the constant next to `CONV_URL` / `CONV_PREFIX`:
   ```ts
   const ISSUE_ID_SHAPE = /^[A-Za-z]+-\d+$/;
   ```
3. Add a helper below `resolveBareDigits`:
   ```ts
   /**
    * A target that is neither an issue ID, a number nor a qualified agent ID:
    * a conversation name such as 20261103-3f3a, or an agent suffix form such as
    * PAN-1148-review (PAN-4999). The conversation wins only when no agent
    * directory claims the same name; both → ambiguous; neither → unresolved
    * with every form tried.
    */
   async function resolveNameShaped(input: string): Promise<AgentTargetResolution> {
     const issueId = resolveIssueId(input);
     const agentId = resolveAgentTarget(issueId);
     const agentExists = agentId !== null && existsSync(join(AGENTS_DIR, agentId));
     const lookup = await lookupConversation(input);
     const conversationRow = lookup.ok && lookup.row?.origin !== 'vault' ? lookup.row : null;

     if (conversationRow && agentExists) {
       return {
         kind: 'ambiguous',
         input,
         candidates: [
           { explicitForm: agentId, label: `agent ${agentId}` },
           conversationCandidate(conversationRow),
         ],
       };
     }
     if (conversationRow) return { kind: 'agent', agentId: conversationRow.tmuxSession, via: 'conversation' };
     if (agentExists) return { kind: 'issue', issueId };
     const agentLabel = agentId ?? `agent-${input.toLowerCase()}`;
     const reason = lookup.ok
       ? `no conversation named ${input} and no agent ${agentLabel}`
       : `conversation lookup failed: ${lookup.message}; no agent ${agentLabel}`;
     return { kind: 'unresolved', input, reason };
   }
   ```
   The two reason strings are exact; WI-3 tests assert them verbatim. `resolveAgentTarget` returns `null` only when `resolveBareNumericId` does, which cannot happen for non-digit input, so `agentLabel` is normally `agentId`; the fallback keeps the type narrow without a non-null assertion.
4. Replace the last line of `resolveCliAgentTarget`:
   Before:
   ```ts
   if (/^\d+$/.test(input)) return resolveBareDigits(input);

   return { kind: 'issue', issueId: resolveIssueId(input) };
   ```
   After:
   ```ts
   if (/^\d+$/.test(input)) return resolveBareDigits(input);

   if (ISSUE_ID_SHAPE.test(input)) return { kind: 'issue', issueId: resolveIssueId(input) };

   return resolveNameShaped(input);
   ```
5. Update the module header comment (line 3–4) to list conversation names: "Accepts issue IDs, qualified agent IDs, bare numerics, conversation names, and conversation forms (`conv/<n>`, `conv:<n>`, a dashboard `/conv/<n>` URL)."
6. Update the `resolveCliAgentTarget` JSDoc to mention PAN-4999's name-shaped branch.

Do not change `resolveCliSingleAgentId`, `resolveExplicitConversationForm`, `resolveBareDigits` or any command file.

## Non-goals

- Reaching a conversation by its bare name when that name is issue-shaped (D1). `conv/<name>` covers it.
- Case-insensitive conversation-name lookup (NFR-3).
- Changing `messageAgent`'s `Agent <id> not running` error (D6).
- Fixing `queueUntilLimitResets` / `laneVerdictRefusal` in `src/cli/commands/tell.ts`, which derive the conversation name by slicing `conv-` off the agent ID; wrong for conversations whose session is not `conv-<name>`.
- Fixing `rowToLegacyConversation`'s `conv-${name}` default for a null `tmux_session`.
- Making non-prefixed agent directories (`ext-…`, `cctest`) addressable by their raw name.
- Pane-only agents with a name-shaped ID and no agent directory: they become `unresolved` instead of reaching the downstream liveness check. They do not exist in practice (agent state is written after the session exists, and spawns always create the directory).
