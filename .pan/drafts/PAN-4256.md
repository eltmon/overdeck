# PAN-4256 — Effort on role launch surfaces

**Issue:** [PAN-4256](https://github.com/eltmon/overdeck/issues/4256) (S4 of [PAN-4249](https://github.com/eltmon/overdeck/issues/4249)).
**Program PRD:** `.pan/drafts/PAN-4249.md`, section "Sibling issues". **Audit:** first comment on #4249, section 2 role rows and section 6 bugs 4, 5, 7.

## Summary

Seven launch surfaces still ignore `roles.<role>.effort`: the review parent, the test role (two call sites), `pan worker run`, `pan spawn`, the Flywheel, the dashboard agent start and restart routes, and the remote Fly launcher. This slice makes each of them resolve effort through `resolveEffort()` and hand the result to the harness. Where a surface has a user-facing input (a CLI flag or an API body), it also accepts an explicit level.

The mechanism is the same everywhere: **the caller resolves, `spawnRun`/`spawnAgent` pass it through.** PAN-4253 decision D5 made `spawnRun` persist and thread `options.effort` / `options.effortSource` into every launcher field and into `getRoleRuntimeBaseCommand`, but deliberately left resolution to callers. This slice is the "callers" half.

## Glossary

- **Effort** — the reasoning-effort level passed to a harness. Canonical levels, low to high: `low`, `medium`, `high`, `xhigh`, `max`. Enum: `EFFORT_LEVELS` in `packages/contracts/src/effort.ts`.
- **Resolver** — `resolveEffort(input)` in `src/lib/agents/resolve-effort.ts`. Precedence: `explicit` → `item` → `plan` → `tier` → `sub-role` → `role` → `project` → `default` (`high`). It returns `{ effort, source, requested, clamped, warning? }`. An invalid `explicit` throws `InvalidEffortError`; invalid lower layers fall through.
- **Source** — the `EffortSource` layer that won (`explicit`, `role`, `default`, …).
- **Clamp** — replacing a level the model or harness cannot run with the nearest supported one (`clampEffort` in `src/lib/agents/effort-support.ts`). The resolver clamps only when it is given `model` / `harness`.
- **Role-file role** — a role with a `roles/<role>.md` definition (`review`, `test`, `worker`, …). For claude-code, `roleSystemPromptInjection` (`src/lib/agents/runtime-command.ts`, grep `const effort = explicitEffort ?? (typeof frontmatter.effort`) emits `--effort <explicit>` when an effort is passed, else the frontmatter `effort: high`. So today `roles.review.effort` / `roles.test.effort` / `roles.worker.effort` are validated but never reach the harness.
- **Pin rule** — PAN-4253 D1: on any relaunch of an existing agent (resume, restart, recovery, rotation), a persisted `state.effort` wins and is re-clamped (`resolveRelaunchEffort`, `src/lib/agents/relaunch-effort.ts`).
- **Surface** — one code path that starts an agent or conversation.
- **Lint ratchet** — `scripts/lint-effort.sh` (`npm run lint:effort`). Shrink-only per-file counts of `effort ?? 'high'` fallbacks and copies of the effort union. Its `BASELINE` row `src/dashboard/frontend/src/components/Settings/RolesPanel.tsx=1 # PAN-4256` belongs to this issue.
- **File-size cap** — `scripts/lint-file-size.sh`. A non-test `src` file over 1000 lines may not grow past its `scripts/file-size-allowlist.txt` cap (last row for the path wins) or its `origin/main` line count. Agents may not raise a cap.

## Requirements

- **FR-1** The review parent's fresh spawn resolves `resolveEffort({ role: 'review', issueId, model: opts.model, harness: opts.harness })` and passes `effort` + `effortSource` to `spawnRun`. With `roles.review.effort: medium` the parent launches with `--effort medium`.
- **FR-2** Both test-role spawns resolve `resolveEffort({ role: 'test', issueId })` and pass `effort` + `effortSource` to `spawnRun`.
- **FR-3** `startWorker` resolves `resolveEffort({ explicit: options.effort, role: 'worker', issueId, model: options.model, harness: options.harness })` and passes `effort` + `effortSource` to `spawnRun`. Every `startWorker` caller (`pan worker run`, `plan-critic-dispatch.ts`) inherits it.
- **FR-4** `pan worker run --effort <level>` accepts the five canonical levels and passes them to `startWorker`. Any other value exits `1` (`WORKER_EXIT.usage`) before a worker starts.
- **FR-5** `pan spawn --effort <level>` resolves `resolveEffort({ explicit, itemEffort: item.metadata?.effort, planEffort: doc.plan.metadata?.effort, role: 'worker', issueId, model, harness })` and appends the harness-native effort tokens to the pane argv. An invalid `--effort` exits `1` before any worktree or pane is created.
- **FR-6** `pan flywheel start` (and `POST /api/flywheel/start`) resolves `resolveEffort({ role: 'flywheel', model, harness, config })`, stores the level on the `conv-flywheel` conversation row, and launches the session with it. `roles.flywheel.effort: medium` ⇒ the next start launches at `medium`.
- **FR-7** The RolesPanel copy states when Flywheel effort applies (next start; a paused Flywheel resumes at the level it started with). The `type Effort` union is replaced by `EffortLevel` from `@overdeck/contracts`, and the `RolesPanel.tsx` row is removed from `scripts/lint-effort.sh`.
- **FR-8** `spawnRemoteAgent` accepts `effort?: string`, resolves `resolveEffort({ explicit: options.effort, role: 'work', issueId, model, harness: 'claude-code' })`, and passes `--effort <level>` on both the launcher-script path and the no-prompt command path. `pan start --remote --effort <level>` forwards its flag.
- **FR-9** `POST /api/agents` accepts an optional body `effort`. A canonical level is forwarded as `pan start … --effort <level>` (local) or to `spawnRemoteAgent` (remote). Any other value answers `400` before anything spawns. An absent `effort` adds no `--effort` arg.
- **FR-10** `POST /api/agents/:id/restart` accepts an optional body `effort`. A canonical level relaunches at that level (clamped to the relaunch model/harness) and is persisted with source `explicit`. Any other value answers `400`. An absent `effort` keeps today's pin behavior.

## Decisions

- **D1 — Callers resolve; `spawnRun` stays pass-through.** Follows PAN-4253 D5. No change to `src/lib/agents/spawn.ts`. Each caller passes `effort: resolved.effort, effortSource: resolved.source`; `spawnRun` persists both on `state.json` and threads `effort` to the launcher.
- **D2 — Clamping at call sites.** Callers pass `model`/`harness` to `resolveEffort` only when they hold them (review-agent's `opts.model`/`opts.harness`, the worker's flags, `pan spawn`'s `--model`/`--harness`, Flywheel and remote's resolved values). The test role, and a review dispatch without `opts.model`, pass neither. Config-level `roles.<role>.effort` is still safe there because config load rejects a level the role's resolved model cannot run (PAN-4249 D7), and the codex/ohmypi launcher helpers re-clamp. **Accepted gap:** a `projects.yaml` project `effort` (which config load does not check against a role model) of `max`, on a claude-code role-file role whose model lacks `max`, reaches `--effort max` unclamped when the caller held no model. Closing it means resolving inside `spawnRun` after `selectedModel` is known, which D1 rules out; record it in the PR body.
- **D3 — Review resume is out.** The `resumeAgent` branch relaunches under the PAN-4253 pin rule. FR-1 touches only the fresh spawn.
- **D4 — `pan spawn` uses the item and plan layers.** It already holds `doc` and `item`, so `itemEffort` and `planEffort` cost nothing. No `tierName` (tier effort is PAN-4257). Role is `worker`, matching the pane's `role: 'worker'` token.
- **D5 — `pan spawn` effort tokens per harness.** New exported helper `spawnWorkerEffortArgs(harness, effort)` in `src/cli/commands/spawn.ts`: `claude-code` → `['--effort', e]`; `codex` → `['-c', \`model_reasoning_effort=${e}\`]`; any other harness → `[]` plus a yellow stderr line `--effort is not applied for harness <h>; pan spawn passes it only to claude-code and codex.` #4511 will reuse this helper when it adds the binary.
- **D6 — Flywheel resolves before spawning.** `spawnConversationSession` resolves with no `role` (`resolveConversationEffort` in `src/lib/overdeck/conversation-effort.ts`), so passing nothing would ignore `roles.flywheel.effort`. `startFlywheel` therefore pre-resolves and passes the level as `explicit`. The Flywheel CLI and API gain no `--effort`/body field (NonGoal); config is the input.
- **D7 — Flywheel resume keeps its start effort.** Resume goes through `handleConversationResume`, which relaunches from the stored `conversations.effort` (PAN-4254). Changing `roles.flywheel.effort` reaches the next `pan flywheel start` (or Start / Start fresh), not a resume.
- **D8 — Dashboard start forwards only an explicit value.** Same principle as PAN-3857 for `--model`: forwarding a resolved default would stamp it as `explicit`. `pan start` resolves `roles.work.effort` itself.
- **D9 — Restart accepts an explicit override; restart-fresh, resume, recover, restart-all and restart-with-current-config do not.** They relaunch under the pin rule or through `pan start`'s own resolution. Live change of a running agent stays `POST /api/agents/:id/effort` (PAN-4255).
- **D10 — Switch-model: no change.** `POST /api/agents/:id/switch-model` is a permanent `409` and launches nothing.
- **D11 — Restart route parsing moves to `shared.ts`.** `lifecycle-restart.ts` has one line of file-size headroom. W12 extracts the body destructure and model normalization into `parseAgentRestartBody` in `shared.ts`, which frees about ten lines, then adds `effort`.
- **D12 — Validation helper.** `parseAgentEffortOverride(value: unknown): EffortLevel | undefined` in `src/dashboard/server/routes/agents/shared.ts` returns `undefined` for `undefined`/`null`/`''`, the level for a canonical value, and throws `Error('Invalid effort "<v>"; expected one of low, medium, high, xhigh, max')` otherwise (message built from `EFFORT_LEVELS.join(', ')`). Both dashboard routes use it.
- **D13 — Remote state.** `RemoteAgentState` gains no effort field (display/persistence of remote effort is PAN-4259).
- **D14 — Copy for the RolesPanel note.** Replace the first sentence with: `Max agents applies on the next tick — no restart needed. Effort applies the next time the Flywheel starts; a paused Flywheel resumes at the effort it started with.` Keep the `flywheel-scope-timing` span unchanged.
