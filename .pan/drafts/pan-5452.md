# PAN-5452 — Computer use: agents drive local desktop apps with `pan computer`

**Issue:** [PAN-5452](https://github.com/eltmon/overdeck/issues/5452)
**Status:** planned 2026-11-16 (revised during planning; see "Planning revisions" at the end)
**Scope:** Linux desktops (X11 fully, Wayland as far as the helper supports). macOS and Windows refuse with a clear message.

## Summary

Overdeck agents can't see or operate desktop apps. Orca (`stablyai/orca`, MIT) has a feature called Computer Use for this. On Linux it's one Python file, `native/computer-use-linux/runtime.py`. It reads the AT-SPI accessibility tree, takes window screenshots, and sends input through AT-SPI actions, XTest and xdotool. The helper doesn't need Orca running: it reads one JSON operation file and prints one JSON response. On 2026-11-16 it ran from an Overdeck agent shell with `/usr/bin/python3` and listed the operator's open apps (Chromium, Firefox, Chrome, Cursor, Codex, ghostty, …).

This PRD vendors that helper and wraps it in a `pan computer` CLI verb. It adds a desktop lease, so that two agents never drive the one shared pointer and keyboard at the same time. It ships a `pan-computer-use` skill to every harness, adds a `pan doctor` row and docs. The feature is opt-in through `computer_use.enabled` in the global config.

## Glossary

- **Computer use:** an agent reading a desktop app's UI (accessibility tree plus screenshot) and acting on it (click, type, keys, scroll, drag), the way a person would.
- **Helper:** the vendored Orca script, `native/computer-use-linux/runtime.py`. It's run as `/usr/bin/python3 -I <helper> <operation-file>`. It reads one JSON **operation** and prints one JSON **response** line, either `{"ok":true,…}` or `{"ok":false,"error":"<message>"}`.
- **Operation:** a JSON object with a `tool` field (`handshake`, `list_apps`, `list_windows`, `get_app_state`, `click`, `perform_secondary_action`, `scroll`, `drag`, `type_text`, `press_key`, `hotkey`, `paste_text`, `set_value`) plus that tool's fields (see the field table in Work item 3).
- **AT-SPI:** the Linux accessibility bus that GTK, Qt, Chromium and Electron apps publish their UI tree on. The helper reads it through PyGObject (`gi.repository.Atspi`), which only the **system** Python has here. The Linuxbrew `python3` on the operator's PATH lacks `gi`, so the helper must always run under `/usr/bin/python3`.
- **Snapshot:** what `get_app_state` and every action return: `snapshotId`, `app`, `windowTitle`, `windowIndex`, `windowBounds`, `treeLines` (the rendered tree, one string per element), `elements` (one record per element: `index`, `runtimeId`, `controlType`, `name`, `automationId`, `actions`, `frame`, …), `focusedSummary`, `selectedText`, `truncation` and optional screenshot fields (`screenshotPngBase64`, `screenshotWidth`, `screenshotHeight`, `screenshotScale`, `screenshotError`). See `make_snapshot` in the helper. Observed live on 2026-11-16 (`get_app_state` on ghostty):
  - `treeLines` is an array of strings. Each is indented with one **tab** per depth level and reads `<index> <controlType> <name>[, Secondary Actions: a, b, …]`, for example `\t\t\t3 panel ~/Projects/overdeck`. A disabled element's line carries ` (disabled)` (helper line 521).
  - An element record looks like `{"index":3,"runtimeId":[0,0,0],"automationId":"","name":"~/Projects/overdeck","controlType":"panel","localizedControlType":"panel","className":"","value":"","isSelected":false,"isDisabled":false,"nativeWindowHandle":0,"frame":{"x":0,"y":0,"width":800,"height":554},"actions":[]}`.
  - Sending a cached record back unchanged as `root` works, and so does the app selector `pid:<n>`. A `root` (subtree) read **numbers its elements from 0 again**: its indexes don't match the full tree's.
- **Element index:** the number shown on a tree line. Actions name an element by index. The helper itself needs the full **element record** (it matches `runtimeId` plus a signature, `find_element` / `same_element_signature`), so Overdeck must remember the records from the latest snapshot. That is the **snapshot cache**.
- **Desktop lease:** a short, renewable claim, held in a file, that one holder (an agent, a conversation or the operator) is driving the desktop's input. Holders without the lease get `desktop_busy` for input commands.
- **Desktop session env:** `DISPLAY`, `WAYLAND_DISPLAY`, `XAUTHORITY`, `XDG_SESSION_TYPE`, `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS`. Agent shells lack most of them. The systemd user manager has them: `systemctl --user show-environment` printed `DISPLAY=:1`, `XAUTHORITY=/run/user/1000/gdm/Xauthority`, `XDG_SESSION_TYPE=x11` and `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus` on the operator's machine.
- **Port record:** an entry in `scripts/upstream-ports.json` (`{ local, upstream, path, commit }`) plus a two-line header at the top of the ported file. `npm run lint:upstream-ports` (`scripts/upstream-port-diff.sh --check`) enforces both.

## Decisions

- **D-1 Vendor, don't depend on Orca.** We copy the helper into Overdeck. We don't call `orca-ide computer`, because that requires the Orca app to be installed and running. The copy lives at `native/computer-use-linux/runtime.py` (the same path as upstream, so re-vendoring is a plain copy). It's unchanged except for two port-header lines added after the shebang. Orca's MIT license is already at `licenses/orca-LICENSE`.
- **D-2 CLI and skill only.** v1 adds no dashboard route, no MCP tool and no UI. A CLI verb works in every harness through its shell tool. A new HTTP route would also need a no-loss-matrix row, which v1 avoids. MCP tools are a follow-up.
- **D-3 Opt-in, global config only.** `computer_use.enabled` defaults to `false`. Only `~/.overdeck/config.yaml` can set it: the project layer is stripped, like `security`, because a repo must never switch on desktop control for the operator. With it off, every `pan computer` command except `capabilities` and `release` refuses with `disabled` (FR-13).
- **D-4 Linux only.** On `darwin` and `win32`, commands other than `capabilities` and `release` refuse with `unsupported_platform`. Orca's Windows helper (`runtime.ps1`) and macOS helper (a Swift package that needs signing) are follow-ups.
- **D-5 No desktop means refuse.** If no `DISPLAY` or `WAYLAND_DISPLAY` can be resolved (a Fly machine, a headless linked machine, an SSH session with no desktop), commands refuse with `no_desktop_session`. No remote-host detection is needed: the missing display is the signal.
- **D-6 One driver at a time.** Every helper call runs under one cross-process file lock, so calls never overlap. Input commands also need the desktop lease. Read-only commands (`capabilities`, `list-apps`, `list-windows`, `get-app-state` without `--restore-window`, `wait`) don't need the lease, so other agents can still look.
- **D-7 Port the Linux blocked-shortcut list.** Orca blocks key chords that quit, lock, log out or switch VTs. That check lives in Orca's TypeScript (`src/main/computer/action-contracts/computer-blocked-key-combos.ts`), not in the helper, so we port its Linux rules.
- **D-8 Not ported in v1:** tree diffs (`treeDiff`), "suspected noop" verification, and Orca's agent-facing error-code mapping. Helper errors pass through as `helper_error` with the helper's own message.
- **D-9 Skill name `pan-computer-use`.** The name `computer-use` is already taken on this machine by Anthropic's synced claude.ai skill (`~/.claude/skills/synced/*/computer-use`). That skill drives the Claude desktop app, which is macOS/Windows only.

## Requirements

- **FR-1** Overdeck ships the Orca Linux helper at `native/computer-use-linux/runtime.py`, recorded as a port of Orca commit `c6b9ac9549b`, and includes `native` in the npm package.
- **FR-2** `pan computer` provides `capabilities`, `list-apps`, `list-windows`, `get-app-state`, `wait`, `click`, `perform-secondary-action`, `set-value`, `type-text`, `press-key`, `hotkey`, `paste-text`, `scroll`, `drag` and `release`, each with a `--json` flag.
- **FR-3** `computer_use.enabled` (global config only, default `false`) gates every command except `capabilities` and `release` (see FR-13).
- **FR-4** Commands resolve the desktop session env (process env first, then `systemctl --user show-environment`), and refuse with `no_desktop_session` when there is no display.
- **FR-5** A desktop lease plus a file lock serialize helper calls and keep input commands to one holder at a time.
- **FR-6** A per-holder snapshot cache turns `--element-index` (and `--from-element-index` / `--to-element-index`) into element records.
- **FR-7** Output: readable text by default and a stable JSON shape with `--json`. Screenshots are written as PNG files and their paths are reported.
- **FR-8** `hotkey` and `press-key` refuse the ported Linux system shortcuts unless `--allow-system-shortcut` is passed.
- **FR-9** `get-app-state --query <text>` / `--max-elements <n>` narrow the printed tree. `wait` polls until `--text`, `--enabled` or `--window-title` holds.
- **FR-10** A `pan-computer-use` skill reaches every harness through `sync-sources/skills/`.
- **FR-11** `pan doctor` reports computer-use readiness, and only when `computer_use.enabled` is true.
- **FR-12** Docs page, docs nav entry, CLI reference section and changelog entry.
- **FR-13** `pan computer capabilities` never refuses with `disabled`, `unsupported_platform` or `no_desktop_session`. It reports the platform, whether the feature is on, whether a desktop session resolved, and (only on Linux with a desktop session) the helper's `handshake` capabilities. `pan computer release` touches only the lease file.
- **NFR-1** No file under `/tmp`: operation files, the lock, the lease, caches and screenshots live under `~/.overdeck/computer-use/` (resolved with `getOverdeckHome()`).
- **NFR-2** Async only: `execFile`/`spawn` through promises. No `execSync`/`spawnSync` anywhere in the new code.
- **NFR-3** Operation files are created with mode `0600` and deleted in a `finally`. `--text-stdin` / `--value-stdin` keep secrets out of shell history.
- **NFR-4** No new npm or Python dependencies. The helper uses only system packages (`python3-gi`, `gir1.2-atspi-2.0`, `xdotool`, optionally `xclip`/`xsel`, and `grim` on Wayland).
- **NFR-5** Every new TypeScript file stays under the 1,000-line ceiling (`scripts/lint-file-size.sh`, `CEILING=1000`), and no allowlist row is added.

**3b. `desktop-env.ts`, `resolveDesktopEnv(deps)` → `{ ok: true, env } | { ok: false, code: 'no_desktop_session', message }`**:
1. Keys: `DISPLAY`, `WAYLAND_DISPLAY`, `XAUTHORITY`, `XDG_SESSION_TYPE`, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`.
2. Start from `process.env`. For each key that is unset or empty, take the value from `systemctl --user show-environment` (run with async `execFile`, 5 s timeout; parse `KEY=value` lines; ignore a failure).
3. If `XDG_RUNTIME_DIR` is still unset, use `/run/user/<uid>` when that directory exists. If `DBUS_SESSION_BUS_ADDRESS` is still unset and `<XDG_RUNTIME_DIR>/bus` exists, use `unix:path=<XDG_RUNTIME_DIR>/bus`.
4. If both `DISPLAY` and `WAYLAND_DISPLAY` are still empty, return `no_desktop_session` with the message `No desktop session on this host: no DISPLAY or WAYLAND_DISPLAY in this shell or in systemctl --user show-environment. Computer use only works on a machine with a logged-in desktop.`
5. Otherwise return `process.env` merged with the resolved keys.

Tests (`__tests__/desktop-env.test.ts`): process env wins over systemctl; systemctl fills the gaps; a systemctl failure plus no display gives `no_desktop_session`; the bus fallback works.

**3c. `helper.ts`, `runHelper(operation, deps)` → parsed response:**

**3g. `tree-filter.ts`, `filterTree(lines, query, maxElements)`:** keeps the lines that contain `query` (case-insensitive) plus each kept line's ancestors. Original order is preserved and no line is duplicated. `maxElements` caps the matching lines (ancestors don't count). If nothing matches, return `[`No element matches "${query}".`]`. It runs preamble steps 1–4 and 8 below and returns the helper response plus the saved screenshot info. `deps` injects `platform`, `loadConfig`, `resolveDesktopEnv`, `withDesktopLock`, `claimLease`, `runHelper`, `saveSnapshot`, `saveScreenshot` and `holderKey`.
- `commands.ts` exports one async function per CLI command except `wait`. Each one validates its arguments, runs steps 5–7, builds the operation from the field table in 3c, and calls `runComputerOperation`. It returns a result object for 3i to format.
- `wait.ts` exports `waitFor(...)` (the `wait` command, below). It calls `runComputerOperation` once per poll.

`run.ts` also exports `runCapabilities(deps)` and `runRelease({ force }, deps)`.

`capabilities` (FR-13, `runCapabilities`) never refuses at steps 1–3: off Linux it reports the platform with `helper: null`; with the feature off it reports `enabled: false`; with no display it reports `desktopSession.ok: false`. It returns `{ platform, enabled, desktopSession: { ok, sessionType, display } | { ok: false, message }, helper: <handshake capabilities> | null, helperError?: string }`. It runs the `handshake` operation only when the platform is `linux` and the desktop env resolved. That call takes the lock but never the lease. A helper failure fills `helperError` and still returns `ok: true`.

`release` (`runRelease`) skips steps 1–3 and 5–8. It runs `releaseLease` inside `withDesktopLock` and nothing else, so an operator can always clear a stuck lease.

The preamble, in order:
1. Platform check (not for `capabilities` or `release`): anything but `linux` gives `unsupported_platform`: `Computer use supports Linux desktops only for now (this host is <platform>).`
2. Config check (every command except `capabilities` and `release`): `computerUse.enabled` false gives `disabled`: `Computer use is off. The operator turns it on with computer_use: { enabled: true } in ~/.overdeck/config.yaml.`
3. `resolveDesktopEnv`.
4. `withDesktopLock`. Inside it: `claimLease` for input commands (everything except `capabilities`, `list-apps`, `list-windows`, `wait`, and `get-app-state` without `--restore-window`), then `runHelper`.
5. Key checks happen before the lock: `hotkey` and `press-key` run `assertKeyComboAllowed`.
6. Stdin flags read stdin fully before the lock. `--text-stdin` / `--value-stdin` conflict with `--text` / `--value` and give `invalid_argument`.
7. Element flags resolve through `elementRecord` before the lock.
8. After an action or `get-app-state`, `saveSnapshot` and `saveScreenshot` run **inside the same `withDesktopLock` call**, right after `runHelper`, so two calls never interleave cache writes or screenshot pruning.

`wait` (FR-9): it polls `get_app_state` with `noScreenshot: true` every 500 ms. It takes and releases the lock on **each** poll, never across the whole wait. It succeeds when the condition holds:
- `--text t`: some tree line contains t (case-insensitive).
- `--enabled t`: some line contains t, and no line containing t also contains ` (disabled)`.
- `--window-title t`: a `list_windows` window title contains t.

The timeout is `--timeout <ms>` (default 10,000, maximum 120,000; a larger value gives `invalid_argument`). Running out of time gives `wait_timeout`. On success it saves the snapshot and returns the matching lines. While the app or window doesn't exist yet (helper error containing `appNotFound`), it keeps polling.

The cases:

- `drag` sends `fromElement` / `toElement`, or `from_x`… for coordinates.
