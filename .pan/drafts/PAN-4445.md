# PAN-4445: Overdeck Anywhere from the dashboard — pair and revoke devices, trusted addresses, and the Anywhere status card

**Issue:** [PAN-4445](https://github.com/eltmon/overdeck/issues/4445) · **Epic:** [PAN-2350](https://github.com/eltmon/overdeck/issues/2350) · **Sibling (split during planning):** [PAN-4446](https://github.com/eltmon/overdeck/issues/4446) (Session Vault setup / join / unlock / sync from the dashboard) · **Planned:** 2026-09-30 (auto mode)

## Summary

An operator can pair another device with this machine, see and revoke paired devices, add the address other devices use to the dashboard's trusted origins, and read one "Anywhere" status card, all from the dashboard with no terminal step. The server routes for pairing and devices already exist (PAN-3762); this issue adds the screens, a persisted trusted-origin list, and a status route. The Session Vault half of the original issue is split into PAN-4446 because it builds on files that the unmerged PAN-4307 (PR #4444) adds. The design for that half is in the section "Sibling scope: Session Vault from the dashboard" at the end of this document, so PAN-4446's planner lowers from it without re-research.

## Glossary

- **Overdeck Anywhere** — the epic (PAN-2350) for using one machine's Overdeck from other devices and machines.
- **Paired device** — a browser or desktop client holding its own revocable `odk_` device token. Stored as an access-token record with `kind: 'device'` in `~/.overdeck/access-tokens.json` (`src/lib/access-tokens.ts`).
- **Pairing credential** — a one-time `odp_` value, valid 10 minutes, held only in the running dashboard's memory (`src/dashboard/server/pairing-credentials.ts`). A device trades it for a device token at `POST /api/pairing/exchange`.
- **Pairing link** — `<origin>/#pair=<credential>`. The credential rides in the URL fragment only, so it never reaches a server log.
- **Credential kind** — what `resolveDashboardCredential()` (`src/dashboard/server/routes/dashboard-auth.ts`, line 162) returns: `internal-token` (the machine's root token; the CLI and every pipeline agent use it), `root-session` (the operator's browser on this machine, via the `overdeck_session` cookie), `device` (a paired device), or `token` (a scoped API token, Bearer only).
- **Trusted origin** — a browser origin (`scheme://host[:port]`) the dashboard accepts for mutations and WebSocket upgrades. Computed by `getTrustedOrigins()` in `src/dashboard/server/routes/origin-validation.ts` (line 48) and cached for the process lifetime.
- **Saved trusted origin** — a trusted origin added from the dashboard and persisted in the new file `~/.overdeck/trusted-origins.json` (this issue).
- **Loopback origin** — an origin whose host is `localhost`, `*.localhost`, `127.0.0.1`, `::1` or `[::1]`. It works only on this machine.
- **Reachable address** — a trusted origin that is not a loopback origin. Another device can open the dashboard there.
- **Anywhere status** — the aggregate this issue adds at `GET /api/anywhere/status`: machine identity, addresses, active device count, vault state, and a list of problems.
- **Problem** — an entry in the Anywhere status with a stable `code`, a plain-language `message`, and an `action` the UI turns into a button.
- **Vault state** (for the card) — `off` (no backend configured), `locked` (backend configured but this machine has no key, or its key was retired by a rotation), `rotation-pending` (a key rotation started on this machine has not finished), `ready`.
- **Unlock** — joining an existing vault from this machine with the vault passphrase (PAN-4328) or the recovery phrase. There is no `pan vault unlock` verb and no lock action. Unlock belongs to PAN-4446.
- **No-loss matrix** — `tests/unit/lib/overdeck/no-loss-matrix.ts`; every HTTP route needs a row or CI fails.

## Decisions (made in this document)

- **D-1 Split.** This issue ships devices, trusted origins and the status card. The Session Vault setup/join/unlock/sync controls ship in PAN-4446, blocked by PAN-4307. Reason: the combined scope exceeds the plan-size gate (more than 25 files, more than 6 subsystems), and the halves have different blockers — nothing in flight blocks this half.
- **D-2 One vault surface.** Vault setup controls go into PAN-4307's `Settings → Session Vault` section (PAN-4446), not into a second vault panel under Anywhere. The Anywhere section shows the vault row of the status card and a button that opens `session-vault`.
- **D-3 Trusted-origin storage.** Saved origins live in `~/.overdeck/trusted-origins.json`, not `config.yaml`. Reason: `config.yaml` writes go through `src/lib/settings-api.ts` (capped at 1508 lines in `scripts/file-size-allowlist.txt`), and PAN-4435 is adding `dashboard.*` keys concurrently. The file is operator configuration, not derived status.
- **D-4 File origins merge unconditionally.** `getTrustedOrigins()` adds saved origins in every launch mode, outside the `!hasEnvOriginConfig` bare-launch branch, so a Traefik or env launch still trusts them.
- **D-5 Adding an origin needs the root session.** `POST /api/anywhere/trusted-origins` accepts only credential kind `root-session`. It returns 403 for `internal-token` (pipeline agents and the CLI), `device` and `token`. This mirrors D-11 for pairing credentials: a credential that could widen the dashboard's attack surface stays with the operator's browser on this machine.
- **D-6 Loopback origins are refused on add.** They are already trusted by default for this port and never help another device. The server answers 400.
- **D-7 One loopback check.** Move the body of `isLoopbackBase()` into a new import-free module `src/lib/remote-access/loopback.ts` as `isLoopbackOrigin()`. `pair.ts` re-exports it under its old name, so `tests/unit/cli/pair.test.ts` keeps passing and `pair.ts` keeps its startup-cost rule (an import-free module costs nothing). The server status route uses the same function.
- **D-8 Problems are computed on the server.** `GET /api/anywhere/status` returns `problems[]` with `action.kind ∈ { 'pair-dialog', 'settings-section', 'none' }`. The UI maps kinds to buttons and never renders "run pan …".
- **D-9 Vault state source (implementation checkpoint).** If `src/lib/vault/open.ts` exists on `main` when the item starts (PAN-4307 merged), map `openVaultContext()`: `off → off`, `key-missing | key-mismatch → locked`, `rotation-pending → rotation-pending`, `open → ready`. **Fallback** when it does not exist: `readVaultConfig()` (`src/lib/vault/config.ts` line 114) — no `backend` ⇒ `off`; else `stat(join(vaultDir(), 'key.next'))` exists ⇒ `rotation-pending`; else `loadVaultKey()` (`src/lib/vault/identity.ts` line 70) returns null ⇒ `locked`; else `ready`. Record which branch was taken in the commit message.
- **D-10 Vault `off` is a state, not a problem.** Not using the vault is a valid choice. The card shows the state with a "Set up" button (action `settings-section: session-vault`). `locked` and `rotation-pending` are problems.
- **D-11 Rotation-pending has no fix button.** Dashboard-driven key rotation is out of scope. The problem's action is `none` and its message states the fact and links the docs section; this is the one allowed exception to "every problem has a fix button", recorded as a NonGoal.
- **D-12 QR code.** Use `qrcode-generator` 2.0.4 (MIT, zero dependencies, ships `dist/qrcode.d.ts`) in `src/dashboard/frontend/package.json`. Render with `createDataURL()` into an `<img>`; no `innerHTML`.
- **D-13 Docs page.** Extend `configuration/remote-access.mdx` (already in `docs.json` under Configuration). Do not create a new `configuration/anywhere.mdx`; the root `anywhere.mdx` is the plans-and-pricing page.
- **D-14 CLI unchanged except D-7.** `pan pair` and `pan devices` keep their output. The dashboard calls the same routes they call, which satisfies "same server code as the CLI".

## Requirements

### Functional

- **FR-1** `~/.overdeck/trusted-origins.json` holds `{ "version": 1, "origins": string[] }`. `readSavedTrustedOriginsSync()` returns the normalized origins, and returns `[]` for a missing file; for an unreadable or invalid file it returns `[]` and logs one `console.warn` naming the file.
- **FR-2** `addSavedTrustedOrigin(origin)` normalizes the origin, refuses non-http(s) and loopback origins, deduplicates, and writes the file atomically (temp file + rename, mode `0644`).
- **FR-3** `getTrustedOrigins()` includes every saved origin in every launch mode, and a new `invalidateTrustedOriginsCache()` makes the next call re-read the file.
- **FR-4** `GET /api/devices` rows include `scopes: string[]`.
- **FR-5** `POST /api/anywhere/trusted-origins` with body `{ origin }` from a root session returns `200 { origin, added: boolean }`, where `origin` is normalized and `added` is false when it was already trusted; an `Origin` header equal to the new origin is accepted on the very next request with no restart.
- **FR-6** The same route returns 403 for `internal-token`, `device` and `token` credentials, 400 for an invalid, non-http(s) or loopback origin, and never writes the file in those cases.
- **FR-7** `GET /api/anywhere/status` returns `{ machine, addresses, devices, vault, problems }` as specified in WI-4, with `Cache-Control: no-store`.
- **FR-8** Settings has an **Anywhere** nav item and section (`id: 'anywhere'`) containing the status card and the Devices panel.
- **FR-9** The Devices panel lists paired devices (name, scopes, created, last seen, revoked time) and revokes one through `DELETE /api/devices/:id` after an in-app confirmation.
- **FR-10** "Pair a device" opens a dialog: pick or type the address, see whether it is trusted, add it with one button, then get the pairing link, a QR code of it, a copy button and the expiry time. A 403 from `POST /api/pairing/credentials` (a paired device's session) renders an explanation instead of a link.
- **FR-11** The status card renders in the Anywhere section and in the Health page. Each problem renders its message and, unless `action.kind === 'none'`, a button that performs the action.

### Non-functional

- **NFR-1** No `execSync` or other blocking child process in server code. The only synchronous file read is `readSavedTrustedOriginsSync()` at cache fill, matching the existing `readTraefikConfigFromYaml()` precedent in the same function.
- **NFR-2** No new route is callable by pipeline agents in a way that changes trust: FR-6 is enforced by credential kind, and unit tests assert the 403 for `internal-token`.
- **NFR-3** Every new HTTP route has a no-loss-matrix row.
- **NFR-4** New tests do not read source files and add no `skipIf`/`.only` (the lint and the test-skip gate reject both). Any delay in a test uses fake timers.
- **NFR-5** Playwright runs only against `startIsolatedDashboard()` in fresh browser contexts; it never touches the operator's live dashboard or a shared browser profile.
- **NFR-6** No file grows past its `scripts/file-size-allowlist.txt` cap; every file this issue touches is under 1000 lines today.

```ts
const request = yield* HttpServerRequest.HttpServerRequest;
const authError = rejectUnsafeDashboardMutationRequest(request);
if (authError) return noStore(authError);
// PAN-4445 D-5: only the operator's browser on this machine widens origin trust.
if (resolveDashboardCredential(request.headers as HeaderMap)?.kind !== 'root-session') {
  return noStore(jsonResponse({ error: 'Only a browser session on this machine can add a trusted address.' }, { status: 403 }));

const body = parseJsonObject(yield* request.text);
if (!body || typeof body['origin'] !== 'string') return noStore(jsonResponse({ error: 'body must be { origin: string }' }, { status: 400 }));
const result = yield* Effect.promise(() => addSavedTrustedOrigin(body['origin'] as string, getTrustedOrigins()));
if (!result.ok) {

      ? 'That address only works on this machine. Use an address another device can reach, such as a Tailscale name.'
      : 'Enter an http:// or https:// address, for example https://desk.tailnet.ts.net.',

}
if (result.added) {
  invalidateTrustedOriginsCache();
  emitActivityEntry({ source: 'dashboard', level: 'info', message: `Added trusted address ${result.origin}`, details: '{}' });
}
return noStore(jsonResponse({ origin: result.origin, added: result.added }));
```
