# PAN-5370 — Workflow redesign live-check fixes

**Issue:** [PAN-5370](https://github.com/eltmon/overdeck/issues/5370) · **Parent epic:** #5284 · **Found in:** live check of C (#5290) and G (#5294) at buildCommit `52e312dd0df`, 1920 × 1000, Broadsheet dark.

Five small dashboard defects. Each is a leaf fix in one or two frontend files plus its test. No server, contract or schema change.

## Glossary

- **Frame header** — the left column's Issues section header. `IssuesSection.tsx` renders `ProjectNode` with `variant="frame"`; the header is the `div[data-variant="frame"]` in `ProjectNode.tsx`. The `tree` variant (Command Deck project tree) uses the same chips but different markup and is not changed.
- **Eyebrow** — the small uppercase "Issues" label (`<span className="eyebrow">Issues</span>`), inside the collapse toggle button `data-testid="issues-section-toggle"` together with the chevron and the count.
- **Chips** — `ProjectCiChip` ("CI", "CI ✗", "CI 3/12"), `ProjectDeployChip` (an in-flight `pan reload`), `ProjectIdentityChip` ("eltmon · overdeck-agent[bot]"). Their classes `.projectCiChip`, `.projectDeployChip`, `.projectIdentityChip` live in `components/CommandDeck/styles/command-deck.module.css` and all set `flex-shrink: 0`.
- **Filter button** — `IssuesFilterMenu`'s trigger `data-testid="issues-filter"`, text "Filter: All".
- **Code pane breadcrumb** — `data-testid="code-pane-breadcrumb"` in `components/explorer/code/CodePaneHeader.tsx`: the root label, then each path segment, joined by `›`.
- **Leading group / file segment** — new names in this PRD: the leading group is the root label plus every segment except the last (and the separators); the file segment is the last path segment (the file name).
- **Spend fact** — the fifth fact, "Spend this week", in `components/Stage/HomePane/HomeFacts.tsx`, fed by `useProjectSpend` in `useHomeData.ts` (`GET /api/costs/summary?project=<PREFIX>`).
- **Landed fact** — the fourth fact, "Landed this week". On error it already shows value `—` and sub `unavailable`; that is the behavior the Spend fact copies.
- **Action row** — the Home `role="toolbar" aria-label="Project actions"` row in `components/Stage/HomePane/HomeActions.tsx`: New conversation (split), Files, Changes on main, Terminal, Open in <editor>, Start an issue…, More ▾.
- **New conversation defaults store** — `useNewConversationDefaults` in `components/frame/deck/newConversationDefaults.ts`: the `model`, `harness`, `effort` quick create sends and the left column's New conversation button shows.
- **Default conversation model** — `models.default_conversation_model` in `/api/settings`, held by `components/chat/defaultConversationModel.ts`. Its module variable starts as `''` (`FALLBACK_DEFAULT_CONVERSATION_MODEL`) until `ensureDefaultConversationModel()` has fetched settings once (the call is memoised in `settingsRequest`, never reset).
- **`model pending`** — what `compactModelName('')` returns (`lib/model-names.ts:8`). The button's second line shows it when the store's `model` is `''`.

## Live evidence gathered during planning

Playwright against `:3011` (1920 × 1000, dark, project `overdeck`, dock closed, Linux, preferred editor Cursor):

- **Action row:** the toolbar is 1048 px wide (the `.inner` max-width 1120 px minus 2 × 36 px padding — it already spans the facts row's full width). Children widths: New conversation split 226, Files (keycap "Ctrl Shift E") 188, Changes on main 151, Terminal 101, Open in Cursor 137, Start an issue… 140, More 79 = 1022, plus 6 gaps × 8 px = 1070 px > 1048. **More** wraps to `top: 249` while the others sit at `top: 205`.
- **Frame header (263 px wide):** the toggle button (chevron + "Issues" + count, natural width 77 px) is squeezed to **0 px**, the CI chip draws at `left: 14` over it, the identity chip takes 189 px, and the filter wrapper is squeezed to 58 px so "Filter: All" wraps. Cause: the toggle has `min-w-0` (shrinkable), the chips are `flex-shrink: 0`, and the filter wrapper shrinks.
- **Breadcrumb (reproduced through a workspace Vite on :3010):** with `LeftColumn.tsx` open beside the Flywheel conversation, the breadcrumb is 359 px wide with 494 px of content; the `LeftColumn.tsx` span ends at x = 1431 while the breadcrumb ends at x = 1295, so the file name is not visible at all. Cause: the breadcrumb `span` is `flex … truncate`, so its children are flex items whose minimum width is their own text. They cannot shrink, so the overflow is cut at the end, which is the file name.
- **Default model (reproduced on the same run):** on a fresh load of `/command-deck/overdeck` the left column button read `model pending · High`; after a conversation (with its composer's model picker) opened, it read `Fable 5 · High`.

## Requirements

- **FR-1** The frame header shows the chevron, the "Issues" eyebrow and the count on one line at the default 264 px column width, never overlapped. The filter button never wraps or clips. When the chips do not fit, the identity chip truncates with an ellipsis first; anything still too wide is clipped by the chip container, never drawn over the eyebrow or the filter.
- **FR-2** The code pane breadcrumb always shows the file segment in full while it fits in the header. The leading group truncates first (end ellipsis), and the `›` separator before the file name always stays visible. A file name wider than the whole breadcrumb truncates with its own ellipsis. The breadcrumb's `title` stays the full path, and its `textContent` is unchanged.
- **FR-3** The Spend fact shows value `—` and sub `unavailable` when `GET /api/costs/summary` fails (HTTP error, network error after the default retries, or no answer within 20 s). Precedence: no prefix (`—` / `needs an issue prefix`) → error (`—` / `unavailable`) → data → loading (`…` / `…`). Error wins over stale data, the same as Landed.
- **FR-4** At 1920 × 1000 with the dock closed (Linux, Cursor as preferred editor, every action present), every action row child shares one `top`. The row keeps `flex-wrap`, so narrower panes may still wrap.
- **FR-5** On a fresh load of any route (for example `/activity`), the New conversation defaults store's `model` becomes the settings' `default_conversation_model` without any model picker or Home composer mounting, so the button never says `model pending` once settings answer, and quick create never posts `model: ''` after that. A stored manual pick still wins.
- **NFR-1** No change to the tree variant of `ProjectNode`, to the shared chip classes' own rules, or to any server route.
- **NFR-2** Tests that drive a timeout use a mock or fake timers, never a real 20 s wait (repo rule "fake timers for retry/backoff/delay tests"). `fetchWithTimeout` uses `AbortSignal.timeout`, which happy-dom does not drive from `vi.useFakeTimers()`, so the timeout path is tested by mocking, not by advancing timers.
- **NFR-3** Every new frontend test file is listed in `scripts/frontend-test-subset.txt` in sorted position (CI runs only that list).

## Decisions

- **D-1 (FR-1)** Fix inside the frame header markup only. The toggle button gets `shrink-0`; the three chips move into a new wrapper `span` with class `styles.frameHeaderChips` (`data-testid="issues-header-chips"`); the `headerActions` wrapper gets `shrink-0`; the filter trigger gets `whitespace-nowrap`. The identity chip, which is the one that does not fit, is the one that gives way: a new rule `.frameHeaderChips > .projectIdentityChip` (two classes, so it outranks `.projectIdentityChip { flex-shrink: 0 }` without editing it) makes it shrinkable with an ellipsis. CI and deploy chips keep `flex-shrink: 0`. Rejected: hiding the identity chip (loses information the tree variant shows), editing the shared chip classes (changes the tree variant, NFR-1).
- **D-2 (FR-2)** Pure CSS, no measurement: split the breadcrumb into a leading group `span` (`min-w-0 truncate`, shrinkable: the root label and every segment but the last, with the separators *between* them), a final separator `span` (`shrink-0 px-1`, the `›` before the file name) and a file segment `span` (`shrink-0 max-w-full truncate text-foreground`). The final separator is its own non-shrinking sibling so the leading group's ellipsis never eats it: a truncated path reads `overdeck › src › dash… › LeftColumn.tsx`. Rejected: a measured `overdeck › … › frame ›` middle collapse with ResizeObserver — the issue's example says "for example", and end ellipsis meets "leading segments truncate first" with no layout code to test.
- **D-3 (FR-3)** Use the existing `fetchWithTimeout` (`lib/apiFetch.ts`, PAN-1705) with `timeoutMs: SPEND_TIMEOUT_MS` (new exported constant `20_000`) and React Query's `signal`. A timeout rejects with a `DOMException` named `TimeoutError`; the global retry rule (`main.tsx`, `isNetworkError`) retries only `TypeError`s, so a timeout becomes `isError` at once. `HomeFacts` gets a new boolean prop `spendError`; `ProjectHome` passes `spend.isError`. `useProjectChanges` is not changed (issue scope).
- **D-4 (FR-4)** Tighten spacing: toolbar `gap-2` → `gap-1.5` (saves 6 × 2 = 12 px) and `ACT_LAYOUT` `px-3` → `px-2.5` (saves about 7 × 4 = 28 px), about 1030 px against 1048 px. **Implementation checkpoint:** measure with the Playwright probe (WI-8). If More still wraps or the headroom (1048 minus the summed widths and gaps) is under 16 px, also change `ACT_LAYOUT`'s inner `gap-2` → `gap-1.5` and re-measure. Longer editor labels ("VS Code Insiders") may still wrap; FR-4 covers only the stated configuration and wrapping stays allowed elsewhere.
- **D-5 (FR-5)** Follow the issue's prescribed fix: one call at module load in `newConversationDefaults.ts`. It is the only placement that covers every reader of the store, because `useCreateConversation` reads it from `ProjectHome` as well as from the button. One addition: re-derive only when the derived model is non-empty (`if (m && m !== current)`). In production this changes nothing (when settings fail and nothing is stored, the store is already `''`), but it stops a failed import-time fetch in unit tests from resetting a model a test set in `beforeEach` (see Hazards).
