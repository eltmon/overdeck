# PAN-4557 — Herdr terminal attach drops bracketed-paste mode, so multi-line paste is sent as separate lines

**Issue:** https://github.com/eltmon/overdeck/issues/4557
**Status:** planned (auto mode, 2026-10-21)

## Glossary

- **Bracketed paste mode (DEC private mode 2004).** A terminal app turns it on by writing
  `ESC [ ? 2004 h` (`\x1b[?2004h`) and off with `\x1b[?2004l`. While it is on, the terminal
  wraps every paste as `\x1b[200~<text>\x1b[201~`, so the app can tell a paste from typing.
  Claude Code, Codex, OpenCode and bash readline all turn it on.
- **xterm** — the `@xterm/xterm` 6.0.0 terminal emulator in the browser
  (`src/dashboard/frontend/src/components/XTerminal.tsx`). Its `term.modes.bracketedPasteMode`
  mirrors the last `?2004h/l` it parsed. Its `term.paste(text)` converts `\r?\n` to `\r` and
  wraps the text in the bracket markers only when that mode is on, then emits one `onData`.
- **Herdr** — the default terminal backend. `herdr terminal session observe <terminalId>`
  streams NDJSON `terminal.frame` records; `terminal session control` additionally reads
  `terminal.input` / `terminal.resize` commands on stdin (`src/lib/terminal-backends/herdr-stream.ts`).
- **Full frame / snapshot** — the first `terminal.frame` record with `"full": true`. It is a
  repaint of Herdr's grid. `ws-terminal.ts` forwards it to the browser as the `snapshot`
  control frame.
- **Attach input normalization** — Herdr server code (`src/server/pane_input.rs`,
  `apply_terminal_attach_input`, tag v0.9.1) that treats a `terminal.input` payload that is
  exactly one complete bracketed paste as a paste: it strips the markers and re-wraps the
  text only if the pane's app has mode 2004 on *now* (`Pane::paste_payload` in `src/pane.rs`).

## Problem

On a Herdr host the browser xterm reports `bracketedPasteMode: false` for panes whose app
turned bracketed paste on at startup. A paste of `"PASTEME line1\nline2"` into `/conv/3259`
went out over `/ws/terminal` as `"PASTEME line1\rline2"` with no markers, so the agent can
receive the lines as separate Enter-terminated inputs instead of one pasted block.

### Root cause (verified 2026-10-21)

1. **Herdr's full frame carries no mode state.** Live probe against this planning agent's own
   Claude Code pane (`term_65e521e44bf3511`, herdr 0.9.1):
   `herdr --session overdeck terminal session observe term_65e521e44bf3511 --cols 120 --rows 40`
   returned one full frame whose DEC private modes were only
   `?2026h ?25l ?25h ?2026l ?25h` — no `?2004h`. The frame begins
   `\x1b[?2026h\x1b[?25l\x1b]8;;\x1b\\\x1b[2J\x1b[1;1H…`.
2. **Herdr exposes no mode state anywhere else.** `herdr pane get`, `herdr pane process-info`,
   `herdr api snapshot` and the v0.9.5 `socket-api.mdx` / `cli-reference.mdx` have no
   bracketed-paste or mode field. So the issue's "replay Herdr's mode state after the
   snapshot" option is closed: there is nothing to replay.
3. **The browser resets xterm before painting the snapshot.**
   `src/dashboard/frontend/src/components/XTerminal.tsx` (search `resettable.reset?.();`,
   ~line 709) calls `term.reset()` on every `snapshot` control frame, which clears all modes.
   The snapshot never turns 2004 back on, so xterm sends pastes raw.
4. tmux is unaffected: the tmux path attaches a real tmux client through node-pty, and tmux
   replays the pane's modes to a newly attached client.

### Why forcing `?2004h` is safe on Herdr

Herdr's own attach input path already normalizes pastes to the pane's live mode. From herdr
tag v0.9.1:

```rust
// src/server/pane_input.rs
pub(super) fn apply_terminal_attach_input(runtime: &TerminalRuntime, data: Vec<u8>) -> Result<(), String> {
    runtime.scroll_reset();
    if let Some(text) = crate::raw_input::complete_text_bracketed_paste(&data) {
        runtime.try_send_paste(text.to_owned())   // re-wraps only if the app has ?2004 on
    } else {
        runtime.try_send_bytes(Bytes::from(data))
    }
}
```

Herdr's unit tests `terminal_attach_paste_uses_plain_text_when_runtime_did_not_enable_brackets`
and `terminal_attach_paste_preserves_brackets_when_runtime_enabled_them`
(`src/server/headless/tests/mod.rs`) pin both directions. The `terminal session control`
client sends `ClientMessage::ControlTerminal`, which `attach_terminal_client` turns into a
`ClientConnectionMode::TerminalAttach` connection, and `terminal.input` becomes
`ClientMessage::Input` → `ServerEvent::ClientInput` → `apply_terminal_attach_input`
(`src/server/headless.rs` ~2120–2146). Herdr's own TUI client follows the same contract: it
always forwards bracketed pastes and lets the server normalize them.

So if the browser always wraps a paste for a Herdr terminal, Herdr delivers it bracketed to an
app that wants brackets and plain to an app that does not. The dashboard's
`HerdrTerminalProcess.write` (`src/dashboard/server/services/terminal-service.ts` ~line 293)
sends each WebSocket message as one `terminal.input`, and xterm emits a whole paste as one
`onData`, so the payload reaches Herdr as exactly one complete bracketed paste.

### Second defect on the same path

The right-click context-menu **Paste** (`pasteFromClipboard`, `XTerminal.tsx` ~line 291)
sends the clipboard text straight to the WebSocket with `wsRef.current.send(text)`. It skips
xterm's paste handling, so it never adds bracket markers and never converts `\n` to `\r` — on
tmux as well as Herdr. It must go through `term.paste(text)`.

## Requirements

- **FR-1** — When the dashboard serves a browser terminal from a Herdr terminal, the `snapshot`
  control frame's `data` starts with `\x1b[?2004h`, so xterm has bracketed paste on after the
  snapshot is written.
- **FR-2** — Only the first frame of a Herdr attach (the one sent as the `snapshot` control
  frame) gets the prefix. Later frames are forwarded byte-for-byte unchanged, so an app that
  turns 2004 off after attach is not overridden.
- **FR-3** — The tmux attach path (`captureFreshSnapshot` / `captureViewportSnapshot`) is unchanged.
- **FR-4** — The terminal context-menu Paste routes clipboard text through `term.paste(text)`
  and never calls `WebSocket.send` directly.
- **FR-5** — Docs describe the Herdr snapshot mode gap and the forced `?2004h`.
- **NFR-1** — `src/dashboard/frontend/src/components/XTerminal.tsx` must not grow past its
  `origin/main` line count (1072). The allowlist cap (last row, 1075, PAN-1166) leaves 3 lines,
  and the planned change shrinks the file. Never raise an allowlist cap.
- **NFR-2** — No mouse-reporting (`?1000`, `?1002`, `?1003`, `?1006`) or focus (`?1004`)
  modes are injected.

## Decisions

- **D1 — Force `?2004h` in the Herdr snapshot instead of replaying Herdr state.** Herdr exposes
  no mode state (root cause 2). Forcing the mode on is safe because of attach input
  normalization (see above).
- **D2 — Prefix in `serveHerdrTerminal` only, first frame only.** The prefix must sit inside the
  snapshot `data`, because the client's `term.reset()` runs before it writes that data. It does
  not go in `decodeTerminalRecord` or `HerdrTerminalProcess.pump`: a later full frame would then
  turn the mode back on over an app that turned it off.
- **D3 — The RPC `TerminalService.streamSession` path is not changed.** It shares
  `HerdrTerminalProcess` but has no frontend xterm consumer (`git grep subscribeTerminal
  src/dashboard/frontend/src` finds nothing).
- **D4 — Fix the context-menu paste in the same issue.** It is the same symptom (a multi-line
  paste arrives as separate lines). The fix is one line, and it also fixes the tmux path.
- **D5 — Mouse and focus modes stay out.** Forcing mouse modes would re-break the drag-select
  fix in `5d2dafcf16d` (`handleForcedSelectionMouseDown` keys off
  `term.modes.mouseTrackingMode === 'none'`). Herdr already encodes mouse input on its side
  via `terminal.mouse`.

## Non-goals

- Replaying mouse-reporting or focus modes, or any mode other than 2004.
- Changing Herdr itself. An upstream request for mode state in `terminal.frame` is a possible
  follow-up, not part of this issue.
- Changing the RPC `TerminalService.streamSession` path (no frontend consumer).
- Changing the tmux attach path.
- Sanitizing paste payloads for lone surrogates in `controlTerminal.write` (PAN-4506 scope).

## Hazards

- `controlTerminal.write` (`herdr-stream.ts`) serializes with plain `JSON.stringify`, without the
  `wellFormedReplacer` that `herdr-api.ts` uses. A pasted lone surrogate would make Herdr reject
  that `terminal.input` line. This was true before this change and stays out of scope.
- If a pasted text itself contains `\x1b[201~`, Herdr's `complete_text_bracketed_paste` returns
  `None` and forwards the raw bytes, markers included. This is the same as any real terminal
  and is accepted.
- `XTerminal.tsx` is at its file-size cap. Any extra line beyond the planned shrink fails
  `scripts/lint-file-size.sh`.
