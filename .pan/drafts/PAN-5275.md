# PAN-5275 — Flywheel Needs-you: make the whole row clickable, not just the 12px icon

**Issue:** [PAN-5275](https://github.com/eltmon/overdeck/issues/5275)
**Related:** PAN-5198 (one row per item, first-raised jump), PAN-5217 (removed `role="button"` from the row for ACT 307n5z; added the native jump button), PAN-5239 (item targets, link styling, jump only when a first-raised id exists).
**Planned on:** build `d0c9b93efe2`, branch `feature/pan-5275`.

## Glossary

- **Needs-you block** — the `<div role="group" aria-label="Needs you" data-testid="flywheel-needs-you">` on the Flywheel page's Status tab (`src/dashboard/frontend/src/components/flywheel/FlywheelStatusPane.tsx`, grep `data-testid="flywheel-needs-you"`). It lists the items of the loop's last tick `needs-you=` line.
- **Needs-you row** — one `<li data-testid="flywheel-needs-you-item">` in that block. Built from `needsYouRows(tick)` (same file, grep `export function needsYouRows`), which returns `{ key, text, label, target?, messageId? }`.
- **First-raised id** — `row.messageId`, copied from `needsYouItems[].firstRaisedMessageId`. It is the transcript id of the tick message that first raised the item. When it is absent, the row has no jump (PAN-5239 FR-7).
- **Jump** — the action "open the flywheel conversation at the message that raised this item". `FlywheelStatusPane` calls its `onNeedsYouClick(messageId)` prop. `FlywheelPage.handleNeedsYouClick` (`src/dashboard/frontend/src/pages/FlywheelPage.tsx`, grep `const handleNeedsYouClick`) either reopens a pending AskUserQuestion or opens `/conv/conv-flywheel` at that message. This issue does not change the page handler.
- **Jump button** — the native `<button data-testid="flywheel-needs-you-jump" aria-label="Show where this was raised">` with a 12x12 px `MessageSquare` icon at the start of a row that has a first-raised id.
- **Inner controls** — the interactive elements inside a row's text: issue buttons (`data-testid="flywheel-needs-you-issue"`, call `onNavigateIssue`), PR links (`flywheel-needs-you-pr`, open GitHub in a new tab) and the item-target link (`flywheel-needs-you-link`, opens `row.target` in a new tab).
- **Jumpable row** — a row whose `row.messageId` is set.
- **ACT 307n5z** — W3C ACT rule "Element with presentational children has no focusable content". An element with the ARIA `button` role must not contain focusable descendants. PAN-5217 removed `<li role="button" tabIndex={0}>` from these rows for this rule. The test `no button-role element contains another button or link (PAN-5217, ACT 307n5z)` in `FlywheelStatusPane.test.tsx` guards it.

## Problem

The operator reported on 2026-11-14 that the Needs-you items are "still not clickable". Reproduced in a signed-in browser on build `d0c9b93efe2` (1600x1000, `/flywheel`, Status tab): there were 11 rows, each with a jump button. The jump button works. Clicking the row text does nothing: no navigation, the default arrow cursor, no console errors. Only the underlined issue and PR references respond. The row looks like a target, but only a 12 px icon is one.

Current row render, `FlywheelStatusPane.tsx` lines 155–216 (grep anchor: `data-testid="flywheel-needs-you-item"`):

## Requirements

- **FR-1** — On a jumpable row, a click anywhere on the row that is not on an inner control or the jump button calls `onNeedsYouClick(row.messageId)` exactly once.
- **FR-2** — A click on the jump button calls `onNeedsYouClick(row.messageId)` exactly once (not twice through bubbling to the row).
- **FR-3** — A click on an inner control (issue button, PR link, item-target link) does its own action and does not call `onNeedsYouClick`. An issue button still calls `onNavigateIssue(issueId)`.
- **FR-4** — A jumpable row shows that it is a target: `cursor: pointer`, a hover background (`hover:bg-warning/[0.14]`, the class the pre-PAN-5217 row used), and the jump icon brightens to `text-foreground` while the row is hovered.
- **FR-5** — A row without a first-raised id has no click handler, no `cursor-pointer` class and no hover background. Clicking it calls nothing.
- **FR-6** — No row gets a `role`, a `tabIndex` or an `onKeyDown`. The jump button stays the row's single keyboard target: it is a native button, so Enter and Space activate it, and it keeps its `focus-visible:ring-2` focus ring. The ACT 307n5z test keeps passing, now also over a jumpable row.
- **FR-7** — When the operator ends a drag-selection of text inside the row, the resulting click does not jump. A plain click (collapsed selection) jumps.
- **NFR-1** — `FlywheelStatusPane.tsx` stays under the file-size ceiling (`scripts/lint-file-size.sh`, `CEILING=1000`; the file is 341 lines today).
- **NFR-2** — No change to `FlywheelPage.tsx`, `@overdeck/contracts`, the server, or the jump destination behavior.

## Decisions (made here, not left to the executor)

- **D1 — A clickable `<li>`, not a row-level button.** The issue allows "a row-level button or a clickable row". A row-level `<button>` or `role="button"` would contain the inner issue buttons and links, which breaks ACT 307n5z and reverts PAN-5217. So the `<li>` gets a mouse `onClick` only, with no role, tabIndex or key handler. This reverses PAN-5217 FR-1's "no `onClick`, no `cursor-pointer` or hover classes" for jumpable rows on purpose; PAN-5217's accessibility constraint (no role, no tabIndex, no nesting) is kept.
- **D2 — Keyboard support is the existing jump button.** It is native, so Enter and Space work, and it already has a focus ring. Adding a second tab stop on the row for the same action would duplicate it and need a role, which D1 forbids.
- **D3 — The jump button stops propagation.** Its handler is `(e) => { e.stopPropagation(); onNeedsYouClick?.(row.messageId!); }`, so one icon click is one call.
- **D4 — All three inner controls stop propagation on click.** Issue buttons: `(e) => { e.stopPropagation(); onNavigateIssue?.(segment.issueId); }`. PR links and the item-target link: `onClick={(e) => e.stopPropagation()}` (default navigation still happens). Keyboard activation of these elements fires a click event, so this covers Enter as well; no `onKeyDown` is added.
- **D5 — A row with both a target and a first-raised id:** the link text opens the URL (D4 stops the jump); every other part of the row, including the gap and the jump icon, jumps.
- **D6 — Drag-selection guard.** A module-level helper decides whether a click ended a text selection inside the row:

  ```ts
  /** True when the click ended a drag-selection inside the row, not a plain click (PAN-5275 FR-7). */
  function endsSelectionWithin(row: HTMLElement): boolean {
    const selection = window.getSelection();
    return !!selection && !selection.isCollapsed && !!selection.anchorNode && row.contains(selection.anchorNode);
  }
  ```

  The row handler returns early when it is true.
- **D7 — Hover styling.** Jumpable `<li>` className: `group -mx-1 flex cursor-pointer items-baseline gap-1.5 rounded-sm px-1 hover:bg-warning/[0.14]`. The `-mx-1 px-1` pair gives the hover background a little room without moving the text column. The jump button adds `group-hover:text-foreground`. Non-jumpable `<li>` keeps `-mx-1 flex items-baseline gap-1.5 px-1` so both kinds of rows stay aligned.
- **D8 — No `title` on the row.** A row tooltip would also show over the inner links and mislead. The jump button keeps its own `title`.
- **D9 — No new component.** The change is about 15 lines in the existing map; extracting a row component is not needed for this issue.
- **D10 — Screenshots** go in `docs/screenshots/pan-5275/` (the `.gitignore` comment at line 210 names `docs/screenshots/<topic>/` as the place for them) and are linked from the PR body with `?raw=true` blob URLs, as PAN-5239 did.

## After (target code)

```tsx
{needsYouRows(tick).map((row) => {
  const jumpId = row.messageId;
  return (
    <li
      key={row.key}
      data-testid="flywheel-needs-you-item"
      className={jumpId
        ? 'group -mx-1 flex cursor-pointer items-baseline gap-1.5 rounded-sm px-1 hover:bg-warning/[0.14]'
        : '-mx-1 flex items-baseline gap-1.5 px-1'}
      {...(jumpId ? {
        onClick: (e: MouseEvent<HTMLLIElement>) => {
          if (endsSelectionWithin(e.currentTarget)) return;
          onNeedsYouClick?.(jumpId);
        },
      } : {})}
    >
      {jumpId ? (
        <button
          type="button"
          aria-label="Show where this was raised"
          title="Open the conversation at the message that first raised this, or the question the flywheel is waiting on"
          data-testid="flywheel-needs-you-jump"
          className="shrink-0 self-center cursor-pointer rounded-sm text-muted-foreground hover:text-foreground group-hover:text-foreground focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring"
          onClick={(e) => { e.stopPropagation(); onNeedsYouClick?.(jumpId); }}
        >
          <MessageSquare className="h-3 w-3" aria-hidden="true" />
        </button>
      ) : (
        <span className="h-3 w-3 shrink-0" aria-hidden="true" />
      )}
      {/* …segment span unchanged except the three onClick changes in D4… */}
    </li>
  );
})}
```

Type the handler with `import type { MouseEvent } from 'react';` (the style of `FlywheelStatePane.tsx` line 11, `import type { ReactNode } from 'react';`) and write `(e: MouseEvent<HTMLLIElement>)` instead of `React.MouseEvent`. Use the plain form `onClick={jumpId ? handler : undefined}` rather than the spread if it reads better; either leaves no click handler on a non-jumpable row.
