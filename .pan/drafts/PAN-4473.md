## Glossary

- **Share service.** The Cloudflare Worker in `services/share/` (`https://share.overdeck.ai`). One `ShareRoom` Durable Object per room. It runs the lobby, admission, block list and signaling relay, and never sees content. Already built (slice 1).
- **Room.** The share service's record for one share, addressed by its **short code** (8 symbols from `BCDFGHJKLMNPQRSTVWXZ23456789`).
- **Device token.** `odd_` + 64 lowercase hex. The PAN-4330 sign-in token, stored in `${OVERDECK_HOME}/account.json` (mode 0600) as `AccountRecord.accessToken`. It authenticates `POST /v1/rooms`.
- **Host token.** `odh_` + 64 lowercase hex. Returned once by `POST /v1/rooms`. It authenticates the host WebSocket (`GET /v1/rooms/:code/host?v=1`) and `DELETE /v1/rooms/:code`. It is a secret that must never reach the browser.
- **Host socket.** The single WebSocket the host's **dashboard server** (never the browser) holds to `GET /v1/rooms/:code/host?v=1`. The service sends `room` snapshots over it; the host sends admission frames over it.
- **Room snapshot.** `RoomSnapshot` in `packages/contracts/src/sharing.ts`: scope, data owner, controller, `hostConnected`, participants (each `lobby` or `admitted`, with `contributor` and `connected` flags) and the block list. Sent after every room change.
- **Host frame.** `HostFrame` in `packages/contracts/src/sharing.ts`: `admit {githubId, contributor?}`, `kick`, `revoke`, `unrevoke`, `set-contributor`, `set-controller`, `signal`, `ice-servers`, `end`.
- **Share command.** The subset of host frames the browser may ask for in this slice: `admit`, `kick`, `revoke`, `unrevoke`, `set-contributor`. Defined in this issue.
- **Share record file.** `${OVERDECK_HOME}/shared-sessions.json`, mode 0600. The host's durable memory of its rooms, holding each room's host token. Defined in this issue; replaces the rev-2 `shared_sessions` SQLite table.
- **Share view.** `ShareView`: what the dashboard server tells the browser about one share. It has no `hostToken` field by construction.
- **Share manager.** The dashboard-server object that owns all host sockets for this process (`src/dashboard/server/services/share-host.ts`).
- **Stale record.** A share record on disk with no live host socket in this process. It appears after a dashboard restart (re-park is slice 8, PAN-4479) or after the host socket closed.
- **Lobby panel.** The frontend panel inside the share dialog listing waiting joiners, admitted viewers and blocked identities, with the per-person actions.
- **Data owner.** The GitHub identity that created the room (this machine's signed-in account). Controller handoff is slice 7; in this slice the data owner is always the controller.

## Problem

Slice 1 (PAN-658) built the share service, but nothing on a user's machine can create a room or admit anyone. There is no way to share a conversation from the dashboard, no place to hold the host token, and no UI that shows who is waiting in the lobby. Slices 3–11 all assume a host that has created a room, holds its host socket, and can admit viewers.

## Scope

This issue is slice 2 of Shared Sessions v0. It delivers the host side of sharing **without any WebRTC**:

1. A share record file door (`src/lib/sharing/share-record.ts`).
2. A share service HTTP client and URL config (`src/lib/sharing/share-service.ts`).
3. A host socket manager in the dashboard server (`src/dashboard/server/services/share-host.ts`).
4. Four dashboard routes under `/api/shares` (`src/dashboard/server/routes/shares.ts`), each with a `no-loss-matrix.ts` row.
5. A "Share this conversation" menu action, a share dialog, and a lobby panel in the frontend.
6. Tests: unit, route, a Miniflare integration test against the real share Worker, frontend component tests, and a Playwright screenshot spec.
7. Docs in `docs/SHARED-SESSIONS.md` and `docs/DASHBOARD-ARCHITECTURE.md`.

## Requirements

- **FR-1** `POST /api/shares` with `{ "conversationName": "<name>" }` creates a room on the share service for that local conversation and answers 201 with a `ShareView` whose `joinUrl` is `<share base URL>/s/<shortCode>` (default base `https://share.overdeck.ai`).
- **FR-2** The host token is written to `${OVERDECK_HOME}/shared-sessions.json` (mode 0600, atomic temp-file + rename) keyed by short code, with `scopeKind`, `scopeId`, `hostToken`, `joinUrl` and `createdAt`. At most one record exists per `(scopeKind, scopeId)`.
- **FR-3** After creating a room, the dashboard server opens the host socket with `Authorization: Bearer <hostToken>` and keeps the latest `room` snapshot in memory.
- **FR-4** `GET /api/shares` lists every share record (live and stale) as `ShareView`s with the latest snapshot and the host socket's connection state.
- **FR-5** `POST /api/shares/:code/commands` relays one share command (`admit` with optional `contributor`, `kick`, `revoke`, `unrevoke`, `set-contributor`) over the host socket.
- **FR-6** `DELETE /api/shares/:code` ends the share: `DELETE /v1/rooms/:code` with the host token, close the host socket, remove the record.
- **FR-7** The conversation header's ⋮ menu has a "Share this conversation" item for conversations that run on this machine (`runsHere`), opening the share dialog.
- **FR-8** The share dialog shows the join link with a Copy button, the connection state, the lobby panel and **End share**. It shows a distinct signed-out state when the machine has no `account.json`.
- **FR-9** The lobby panel lists waiting joiners (GitHub avatar + `@login`) with **Admit**, **Admit as contributor** (one click: one `admit` frame with `contributor: true`) and **Revoke**; admitted viewers with **Grant contributor** / **Remove contributor**, **Kick** and **Revoke**; blocked identities with **Un-revoke**. Admitted viewers show contributor, offline and controller markers.
- **FR-10** The record is removed when the share ends: `DELETE /api/shares/:code`, a host-socket close with code 4004 (room ended), or a 404 on the host-socket upgrade.
- **NFR-1** The host token never appears in any `/api/shares*` response body, in any log line, or in any error message. `ShareView` has no `hostToken` field.
- **NFR-2** Every `/api/shares*` route is gated by the existing dashboard auth: mutations call `rejectUnsafeDashboardMutationRequest`, `GET` calls `rejectUnauthorizedDashboardRequest`. No `route-scopes.ts` rows are added, so all four routes need the default `admin` scope.
- **NFR-3** Delay-based tests (keepalive ping, HTTP timeouts) use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`; no test sleeps.
- **NFR-4** `ConversationPanel.tsx` grows by at most 2 lines (allowlist cap 1531, current 1520). `src/dashboard/server/main.ts` is not touched (986 of 1000 lines).
- **NFR-5** Lobby UI follows `pan-style-guide`: `shared/Modal.tsx`, no pill badges, `font-medium` not bold, one destructive action per row, live presence is blue never green.

## Decisions

Auto mode asked the operator nothing. Each choice below is final for this issue and is mirrored in the xBRIEF `plan.autoDecisions[]`.

- **D-1 Host socket lifecycle.** The manager opens the host socket right after `POST /v1/rooms` succeeds and the record is written. It does **not** reconnect after a close, and it does **not** re-park on dashboard boot. Both belong to slice 8 (PAN-4479, whose body owns "after a host network drop or dashboard restart, the host re-parks"). A closed socket leaves the share `disconnected` with its record kept, so slice 8 can re-park it. Rationale: no overlap with a sibling slice; the room survives 5 minutes on the service either way.
- **D-2 Stale records.** `GET /api/shares` returns a stale record with `connection: 'disconnected'` and `snapshot: null`. **End share** works on it (HTTP `DELETE` needs only the host token).
- **D-3 One share per conversation.** `POST /api/shares` for a conversation that already has a share: if the share is live in this process (`connecting` or `connected`), answer **200 with the existing view** (re-opening the dialog never mints a second link). If the existing record is stale, **end it first** (best-effort `DELETE /v1/rooms/:code`, ignore any failure), remove the record, then create a new room and answer 201.
- **D-4 Server-side eligibility.** `POST /api/shares` rejects a conversation that is not in the local database (`getConversationByName(name) === null` → 404 `conversation_not_found`; linked `@<env>/…` names are never local, so they get 404 too) and a vault browse copy or released conversation (`conversationWriteRefusal(conv)` → its 409 body). The frontend `runsHere` gate is a convenience, not the check.
- **D-5 Signed-out state.** `readAccount()` returns `null` → 412 `{ "error": "not_signed_in", "message": "Sign in with pan account login to share conversations." }`. `readAccount()` throws → 500 `{ "error": "account_unreadable", "message": <the thrown message> }`. The dialog renders the 412 as a signed-out panel with the command `pan account login`.
- **D-6 Live lobby updates by polling.** The dialog polls `GET /api/shares` with TanStack Query `refetchInterval: 1000` while open, and invalidates `['shares']` after every command. The snapshot lives in server memory, so a poll is a local read. A `/ws/rpc` domain event would touch `events.ts`, `types.ts`, `event-reducers.ts`, `read-model.ts`, `store.ts` and `main.ts` (5+ files) for a panel that is open only while sharing; polling has 159 `refetchInterval` precedents (e.g. `components/Settings/anywhere/MachinesPanel.tsx`).
- **D-7 Share URL config.** `anywhere.share_url` in `${OVERDECK_HOME}/config.yaml`, default `https://share.overdeck.ai`, validated like `anywhere.directory_url` (`src/lib/anywhere/directory-config.ts`): `https:`, or `http:` to a loopback host; no query, fragment or credentials; trailing slash stripped. Read on every share creation. No env var.
- **D-8 Plain async modules, Effect routes.** `share-record.ts`, `share-service.ts` and `share-host.ts` are plain async TypeScript with injected seams (`openSocket`, `fetch`), like `src/dashboard/server/services/directory-client.ts` and `src/lib/account/store.ts`. The route module is an Effect `HttpRouter` module like `routes/triggers.ts`, wrapping a plain async handler per route with `Effect.promise`. This **overrides** the parent PRD sentence "new host-side modules under `src/dashboard/server/` are written Effect-native": the repo's one-variant-per-operation rule (`docs/EFFECT-BRIDGING.md`, `npm run lint:effect-facades`) forbids Effect wrappers over in-repo Promise code, and the closest precedent (`directory-client.ts`) is a plain class.
- **D-9 No new `src/lib/errors.ts` tags.** Nothing in this slice runs in an Effect error channel, so `ShareServiceError` / `RoomNotFound` (parent *New Error Types*) are not added here. Errors are string codes in JSON bodies, like `routes/triggers.ts` and the share service itself.
- **D-10 Ending a share uses HTTP `DELETE`, not the `end` frame.** `DELETE /v1/rooms/:code` works whether or not the host socket is open, so one code path handles live and stale shares. 204 and 404 both mean "gone"; any other answer or a network failure keeps the record and returns 502.
- **D-11 Keepalive.** The host socket sends a WebSocket protocol ping (`socket.ping()`) every 30 s; 75 s without a pong terminates the socket and marks the share `disconnected`. **Implementation checkpoint:** in the Miniflare integration test, confirm workerd answers protocol pings on a hibernating socket (send `ping()`, await `'pong'`). If it does not, remove the keepalive, mark the share `disconnected` only on `close`/`error`, and record the reason in a comment in `share-host.ts`.
- **D-12 Command result.** `POST /api/shares/:code/commands` answers 202 `{ "ok": true }` once the frame is sent. The effect is visible in the next snapshot. The latest `error` frame from the service (e.g. `unknown_participant`) is kept on the view as `lastError` and shown by the panel.
- **D-13 Placement of the menu item.** The ⋮ menu item lives in `components/chat/sharing/ShareDialog.tsx` as `ShareConversationMenuItem` and renders nothing unless `runsHere(conversation)`. `ConversationPanel.tsx` gets one import line and one JSX line after `Continue on another device` (line ~915). The sidebar mirror `CommandDeck/ConversationActionMenu.tsx` is not changed (NonGoal).
- **D-14 Dialog primitive.** `shared/Modal.tsx` with a zustand store and a `ShareDialogHost` mounted in `main.tsx` next to `NewConversationDialogHost` (style guide: dialogs build on `Modal.tsx`; reference `components/newConversation/NewConversationDialog.tsx`).
- **D-15 Record shape adds `joinUrl`.** The parent PRD's record has `scopeKind`, `scopeId`, `hostToken`, `createdAt`. This issue adds `joinUrl` so a stale record can still show its link after a restart. Additive; slice 8 reads the same file.
- **D-16 Playwright spec is not added to CI.** `src/dashboard/frontend/tests/pan-4473-share-lobby.spec.ts` produces the screenshots the acceptance criteria require and is run by the work agent and the test role. It is not added to the `test:playwright` script (that script lists four layout specs; a mocked-API screenshot spec does not need to gate every PR).
- **D-17 Size justification.** The projected surface is 23 files across 8 path-subsystems, because three mandated registries live outside `src/` (`tests/unit/lib/overdeck/no-loss-matrix.ts`, `scripts/frontend-test-subset.txt`, the Miniflare harness under `tests/integration/`) and each `docs/*.md` counts as its own subsystem. The code is one vertical feature; splitting it would ship a backend with no UI or a UI with no backend.

```ts
  readonly shortCode: string;
  readonly joinUrl: string;
  readonly scope: ShareScope;
  readonly createdAt: string;            // ISO
  readonly connection: ShareConnection;
  readonly snapshot: RoomSnapshot | null; // null for a stale record
  readonly lastError: ShareLastError | null;
}

export interface ListSharesResponse { readonly shares: readonly ShareView[] }
```

### Share record file door (`src/lib/sharing/share-record.ts`)

```ts
export const SHARED_SESSIONS_FILENAME = 'shared-sessions.json';
export interface ShareRecord {
  scopeKind: 'conversation';
  scopeId: string;      // conversation name
  hostToken: string;    // odh_ + 64 hex
  joinUrl: string;
  createdAt: string;    // ISO
}
export interface ShareRecordFile { version: 1; rooms: Record<string, ShareRecord> }  // key = shortCode
export function sharedSessionsPath(): string;                         // join(getOverdeckHome(), SHARED_SESSIONS_FILENAME)
export async function readShareRecords(): Promise<Record<string, ShareRecord>>;   // {} on ENOENT; throws Error naming the path on bad JSON/shape
export async function putShareRecord(shortCode: string, record: ShareRecord): Promise<void>;
export async function removeShareRecord(shortCode: string): Promise<boolean>;
export async function findShareRecordByScope(scopeKind: 'conversation', scopeId: string): Promise<{ shortCode: string; record: ShareRecord } | null>;
```

Rules:
- Imports only Node built-ins and `../paths.js` (`getOverdeckHome`), like `src/lib/account/store.ts`.
- Writes go through one in-process queue (`mutate(fn)`), copied from `src/lib/access-tokens.ts` lines 277–286: read from disk, apply, write.
- Write: `mkdir(home, { recursive: true, mode: 0o700 })`, `writeFile(<path>.<pid>.<uuid>.tmp, JSON + '\n', { mode: 0o600 })`, `rename`; unlink the temp file on failure.
- Validation on read: `version === 1`; each key matches `/^[BCDFGHJKLMNPQRSTVWXZ2-9]{8}$/`; `hostToken` matches `/^odh_[0-9a-f]{64}$/`; `scopeKind === 'conversation'`; `scopeId`, `joinUrl`, `createdAt` are non-empty strings. Any failure throws `Error(\`Cannot read ${path}: <reason>. Delete it to forget local shares.\`)`. The message never contains a token.
- `putShareRecord` throws `Error('A share already exists for conversation <scopeId> (<otherCode>)')` when a different short code already holds the same `(scopeKind, scopeId)`. Same code → replace.
- When `removeShareRecord` removes the last entry, the file stays with `"rooms": {}` (no delete).

### Share service client (`src/lib/sharing/share-service.ts`)

```ts
export const DEFAULT_SHARE_URL = 'https://share.overdeck.ai';
export const SHARE_HTTP_TIMEOUT_MS = 10_000;
export type ShareUrlResult = { url: string } | { error: string };
export function parseShareUrl(raw: unknown): ShareUrlResult;            // same rules as parseDirectoryUrl, key name anywhere.share_url
export async function readShareUrl(): Promise<ShareUrlResult>;            // reads ${OVERDECK_HOME}/config.yaml → anywhere.share_url
export function hostSocketUrl(base: string, shortCode: string): string; // https→wss, http→ws; `${base}/v1/rooms/${code}/host?v=1`
export type ShareServiceFailure = { ok: false; status: number | null; error: string };
export async function createRoom(base: string, deviceToken: string, scope: ShareScope, opts?: { fetch?: typeof fetch }):
  Promise<{ ok: true; room: CreateRoomResponse } | ShareServiceFailure>;
export async function deleteRoom(base: string, shortCode: string, hostToken: string, opts?: { fetch?: typeof fetch }):
  Promise<{ ok: true } | ShareServiceFailure>;
```

- `createRoom`: `POST ${base}/v1/rooms`, headers `Authorization: Bearer <deviceToken>`, `Content-Type: application/json`, body `JSON.stringify({ scope })`. 201 → validate the body (`shortCode` is 8 alphabet symbols; `hostToken` is `odh_` + 64 hex; `joinUrl` is an `https:` URL, or a loopback `http:` URL, ending in `/s/<shortCode>` — see the note below; `snapshot` is an object with `participants` and `blocked` arrays) → `{ ok: true, room }`; a malformed 201 → `{ ok: false, status: 201, error: 'bad_response' }`. Non-201 → `{ ok: false, status, error: body.error ?? 'http_<status>' }`. A thrown fetch → `{ ok: false, status: null, error: 'unreachable' }`; a timeout → `'timeout'`.
  - Note: the Worker builds `joinUrl` from its own `PUBLIC_BASE_URL`, which may differ from the configured base in local development (Miniflare). So `joinUrl` is never compared with `base`.
- `deleteRoom`: `DELETE ${base}/v1/rooms/<code>` with `Authorization: Bearer <hostToken>`. 204 or 404 → `{ ok: true }`. Others → failure as above.
- Timeouts: `AbortController` + `setTimeout(SHARE_HTTP_TIMEOUT_MS)`, cleared in `finally`.
- No function logs, and no failure message includes a token.

### Host socket manager (`src/dashboard/server/services/share-host.ts`)

```ts
export const PING_INTERVAL_MS = 30_000;
export const PONG_TIMEOUT_MS = 75_000;

/** The part of a `ws` WebSocket the host uses; tests supply a fake. */
export interface ShareSocket {
  readonly readyState: number;
  on(event: 'open', l: () => void): unknown;
  on(event: 'message', l: (data: RawData, isBinary: boolean) => void): unknown;
  on(event: 'close', l: (code: number, reason: Buffer) => void): unknown;
  on(event: 'unexpected-response', l: (req: unknown, res: { statusCode?: number }) => void): unknown;
  on(event: 'error', l: (error: Error) => void): unknown;
  on(event: 'pong', l: () => void): unknown;
  send(data: string): void;
  ping(): void;
  close(code?: number, reason?: string): void;
  terminate(): void;
}

export interface ShareManagerDeps {
  readAccount(): Promise<AccountRecord | null>;
  readShareUrl(): Promise<ShareUrlResult>;
  createRoom: typeof createRoom;
  deleteRoom: typeof deleteRoom;
  records: { read: typeof readShareRecords; put: typeof putShareRecord; remove: typeof removeShareRecord };
  openSocket(url: string, headers: Record<string, string>): ShareSocket;
  now(): Date;
}

export type CreateShareOutcome =
  | { kind: 'created'; view: ShareView }        // → 201
  | { kind: 'existing'; view: ShareView }       // → 200
  | { kind: 'error'; status: number; body: { error: string; message?: string } };

export class ShareManager {
  constructor(deps: ShareManagerDeps);
  create(scope: ShareScope): Promise<CreateShareOutcome>;
  list(): Promise<ShareView[]>;                                     // records on disk ⋈ live hosts
  command(shortCode: string, command: ShareCommand): Promise<{ status: 202 | 404 | 409; body: object }>;
  end(shortCode: string): Promise<{ status: 204 | 404 | 502; body?: object }>;
  stop(): void;                                                     // closes every host socket (tests)
}
export function defaultOpenSocket(url: string, headers: Record<string, string>): ShareSocket; // new WebSocket(url, { headers, handshakeTimeout: 10_000 })
export function getShareManager(): ShareManager;                  // lazy singleton with production deps
export function setShareManagerForTests(manager: ShareManager | null): void;
```

`create(scope)` steps, in order:
1. If a live host (`connecting`/`connected`) exists for the scope → `{ kind: 'existing', view }`.
2. Concurrent `create` calls for the same scope share one in-flight promise (a `Map<scopeKey, Promise>`), so two clicks never mint two rooms.
3. `readShareUrl()` error → `{ status: 500, body: { error: 'share_url_invalid', message } }`.
4. `readAccount()`: `null` → 412 `not_signed_in` (D-5); throws → 500 `account_unreadable`.
5. Stale record for the scope (`records.read()` finds the scope with no live host) → `deleteRoom` best-effort, `records.remove`.
6. `createRoom(base, account.accessToken, scope)`. Failure mapping: 401 → 409 `{ error: 'account_rejected', message: 'overdeck.ai rejected this sign-in; run pan account login' }`; 403 → 409 `{ error: 'account_expired', message: 'overdeck.ai access for this account has expired' }`; 429 → 429 `rate_limited`; `status: null` → 502 `share_service_unreachable`; anything else → 502 `{ error: 'share_service_error', message: <service error code> }`.
7. `records.put(shortCode, { scopeKind, scopeId, hostToken, joinUrl, createdAt: now().toISOString() })` **before** opening the socket.
8. Open the host socket (`openSocket(hostSocketUrl(base, code), { Authorization: 'Bearer ' + hostToken })`), state `connecting`, `snapshot` = `room.snapshot` from the create response → `{ kind: 'created', view }`.

Host socket handling (one `ShareHost` object per live room, internal to the module):
- `open` → start the ping timer (D-11). State stays `connecting` until the first `room` frame.
- `message` (text) → `JSON.parse`; ignore non-object / unknown types. `room` → `snapshot = frame.snapshot`, state `connected`. `error` → `lastError = { code, githubId?, at }`. `signal` and `ice-servers` are ignored in this slice (slice 3 consumes them). Binary frames are ignored.
- `pong` → clear the pong deadline.
- `unexpected-response` with 404 or 401 → the room is gone or the token is bad: remove the record, drop the host.
- `close` 4004 → room ended: remove the record, drop the host.
- `close` 4008 → `lastError = { code: 'replaced', at }`, state `disconnected`, record kept.
- Any other `close` / `error` / pong timeout → state `disconnected`, record kept, timers cleared. No reconnect (D-1).

`command(code, command)`: no record → 404 `share_not_found`; no live host or state ≠ `connected` → 409 `share_not_connected`; else `socket.send(JSON.stringify(command))` → 202 `{ ok: true }`. The command object is rebuilt from known keys only before sending.

`end(code)`: no record → 404 `share_not_found`; `readShareUrl()` error → 500; `deleteRoom(base, code, record.hostToken)` failure → 502 `{ error: 'share_service_error', message }` with the record kept; success → close the socket with 1000, drop the host, `records.remove(code)` → 204.

`list()`: for each record on disk, build a `ShareView` from the record plus the live host (or `connection: 'disconnected', snapshot: null, lastError: null` for a stale record). Order by `createdAt` ascending. The view builder copies fields one by one; it never spreads a record (NFR-1).
