# PAN-4266 — Command Deck model picker is clipped and shifts the conversation column left

**Issue:** https://github.com/eltmon/overdeck/issues/4266
**Status:** planned (auto mode, 2026-09-27)
**Base commit verified against:** `c7f3ac5177c`

## Glossary

- **Command Deck** — the three-column dashboard surface at `/command-deck`, rendered by `src/dashboard/frontend/src/components/CommandDeck/index.tsx`. Its left column (`styles.sidebar`) holds the conversation list; the header of that column holds the model picker.
- **Conversation column** — the Command Deck element with CSS-module class `.sidebar` (`command-deck.module.css`, `overflow: hidden`). The issue calls it `_sidebar` because Vite dev class names look like `_sidebar_<hash>`.
- **Chat model picker** — `src/dashboard/frontend/src/components/chat/ModelPicker.tsx` (exported `ModelPicker`). It is the picker in the Command Deck header, in the composer footer, on the simple home page (`simple/TalkItThrough.tsx`), and in Settings → Roles. It has a two-panel dropdown with a search input.
- **Effort picker** — `src/dashboard/frontend/src/components/chat/EffortPicker.tsx`. It uses the same `.pickerDropdown` class.
- **Shared model select** — `src/dashboard/frontend/src/components/shared/ModelPicker/ModelPicker.tsx` (`ModelSelect`, `HarnessSelect`, `ModelHarnessPicker`). A different component with its own CSS module. **It is not the component in this bug** (see "Correction to the issue").
- **Dropdown** — the `<div className={styles.pickerDropdown}>` the pickers render while open.
- **Portal** — React `createPortal(node, document.body)`: the dropdown DOM node becomes a child of `<body>`, so no ancestor `overflow: hidden` can clip it. React events still bubble through the React tree; native DOM `contains()` checks do not.
- **Clipped ancestor** — an ancestor element whose computed `overflow-x` is `hidden`. The browser can still scroll such an element programmatically (for example to reveal a focused input); the user cannot scroll it back.
- **Gutter** — the 8 px minimum gap between the dropdown and each viewport edge.

## Correction to the issue

The issue names `shared/ModelPicker/ModelPicker.tsx` as the broken file. It is not. The measured values (`z-index: 9999`, 460 px max width, a focused search input) belong to `.pickerDropdown` in `CommandDeck/styles/command-deck.module.css` (line ~4662), which is used only by the chat model picker and the effort picker. The Command Deck header renders the **chat** picker:

```tsx
// src/dashboard/frontend/src/components/CommandDeck/index.tsx, ~line 1356
<div className={styles.sidebarHeaderGroup}>
  <ModelPicker
    value={sidebarModel}
```

(`ModelPicker` there is imported from `../chat/ModelPicker`.) The "home-page picker that renders correctly" is the same chat component in `simple/TalkItThrough.tsx` line ~124, inside an unclipped container. The shared model select has no search input and its dropdown is `left: 0; right: 0` (as wide as its trigger), so neither failure mechanism applies to it. It stays out of scope.

## Root cause (verified in code)

1. **Clipping.** `.pickerDropdown` is `position: absolute` inside `.pickerContainer` (`position: relative`), inside `.sidebar` (`overflow: hidden`), inside `.layout` (`overflow: hidden`). A 300–460 px dropdown anchored in a 320 px column overflows the column and is cut off.
   ```css
   /* command-deck.module.css ~4662 */
   .pickerDropdown {
     position: absolute;
     left: 0;
     top: calc(100% + 4px);
     z-index: 9999;
     ...
     min-width: 300px;
     max-width: min(calc(100vw - 16px), 460px);
   ```
   `usePickerPosition` (`chat/usePickerPosition.ts`) only chooses `align: 'left' | 'right'` against the **viewport**, never against the clipping column.
2. **Column shift.** The search input uses the React `autoFocus` attribute:
   ```tsx
   // chat/ModelPicker.tsx ~line 563-571
   <input
     type="text"
     className={styles.pickerSearchInput}
     placeholder="Search models…"
     ...
     autoFocus
   />
   ```
   React calls `element.focus()` with no options, so the browser scrolls the nearest clipped ancestor (`.sidebar`) sideways to reveal the input. The column content stays shifted until reload.

## Requirements

- **FR-1** — The chat model picker dropdown renders in a portal on `document.body` with `position: fixed`, placed from the trigger container's `getBoundingClientRect()`.
- **FR-2** — The dropdown stays inside the viewport with an 8 px gutter on all four sides: it opens downward unless there is too little space below (then upward), aligns its left edge with the trigger unless that overflows the right gutter (then aligns its right edge with the trigger's right edge), and is finally clamped horizontally into `[8, innerWidth - 8 - width]`.
- **FR-3** — While open, the dropdown repositions on window `resize`, on any `scroll` outside the dropdown (capture phase), and when its own size changes (`ResizeObserver`).
- **FR-4** — Opening the chat model picker focuses the search input with `focus({ preventScroll: true })`. The `autoFocus` attribute is removed.
- **FR-5** — When a picker closes, every clipped ancestor (computed `overflow-x: hidden`) of the trigger with a non-zero `scrollLeft` is reset to `scrollLeft = 0`. `scrollTop` is never touched, and ancestors with `overflow-x` `auto`/`scroll`/`visible`/`clip` are never touched.

## Work items

### WI-1 — `resetClippedAncestorScroll` helper (FR-5)

Files: new `src/dashboard/frontend/src/components/chat/resetClippedScroll.ts`, new `src/dashboard/frontend/src/components/chat/__tests__/resetClippedScroll.test.ts`.

```ts
/**
 * PAN-4266: a focused input inside an `overflow: hidden` column makes the
 * browser scroll that column sideways, and the user cannot scroll it back.
 * Reset horizontal scroll on every clipped ancestor. Never touches scrollTop
 * or real scroll containers (auto/scroll), so scrollable pages keep position.
 */
export function resetClippedAncestorScroll(start: HTMLElement | null): void {
  for (let el = start?.parentElement ?? null; el && el !== document.body; el = el.parentElement) {
    if (el.scrollLeft !== 0 && getComputedStyle(el).overflowX === 'hidden') el.scrollLeft = 0;
  }
}
```

Tests (happy-dom, the frontend Vitest environment; set `el.style.overflowX` explicitly — do not rely on the `overflow` shorthand expanding in happy-dom — and assign `scrollLeft` directly):
- an `overflow-x: hidden` ancestor with `scrollLeft = 64` is reset to 0;
- an `overflow-x: auto` ancestor with `scrollLeft = 64` keeps 64;
- `scrollTop = 50` on a hidden ancestor keeps 50;
- `null` input does not throw.

### WI-2 — `useFloatingPickerPosition` hook (FR-1, FR-2, FR-3, FR-5, NFR-1, NFR-3)

Files: new `src/dashboard/frontend/src/components/chat/useFloatingPickerPosition.ts`, new `src/dashboard/frontend/src/components/chat/__tests__/useFloatingPickerPosition.test.tsx`.

Signature:

```ts
export interface FloatingPickerOptions { preferredHeight?: number } // default 400
export function useFloatingPickerPosition(
  open: boolean,
  anchorRef: RefObject<HTMLElement | null>,
  dropdownRef: RefObject<HTMLElement | null>,
  options?: FloatingPickerOptions,
): { style: CSSProperties };
```

Algorithm (constants `GUTTER = 8`, `GAP = 4`, `MIN_DOWN_HEIGHT = 240`, same values as `usePickerPosition.ts`):
1. `a = anchorRef.current.getBoundingClientRect()`; `w = dropdownRef.current?.offsetWidth ?? 0`.
2. `spaceBelow = innerHeight - a.bottom - GUTTER`; `spaceAbove = a.top - GUTTER`; `openUp = spaceBelow < Math.min(preferredHeight, MIN_DOWN_HEIGHT) && spaceAbove > spaceBelow`.
3. `maxHeight = Math.max(120, Math.min(preferredHeight, (openUp ? spaceAbove : spaceBelow) - GAP))`.
4. `left = a.left; if (left + w > innerWidth - GUTTER) left = a.right - w; left = Math.min(Math.max(left, GUTTER), Math.max(GUTTER, innerWidth - GUTTER - w))`.
5. Style: `{ position: 'fixed', left, right: 'auto', maxHeight, top: openUp ? 'auto' : a.bottom + GAP, bottom: openUp ? innerHeight - a.top + GAP : 'auto' }`.
6. Store the numbers `{ openUp, left, top/bottom, maxHeight }` in state; call `setState` only when one differs (NFR-3). Measure only the anchor rect and the dropdown's `offsetWidth` — never the dropdown's own rect (the existing hook's header comment documents the toggle loop that causes).
7. Run the measurement in `useLayoutEffect` while `open` (the portal node is mounted in the same commit, so `dropdownRef.current` is set). Subscribe: `window` `resize`; `window` `scroll` with `{ capture: true, passive: true }` ignoring events whose `target` is a `Node` inside `dropdownRef.current`; `ResizeObserver` on the dropdown when `typeof ResizeObserver !== 'undefined'`. Clean all up on close/unmount.
8. When `open` changes from `true` to `false` (track with a ref), call `resetClippedAncestorScroll(anchorRef.current)` from WI-1.
9. Before the first measurement, return `{ position: 'fixed', visibility: 'hidden', top: 0, left: 0 }` so no frame paints at the wrong place.

Tests (mock `getBoundingClientRect` on the anchor, `offsetWidth` on the dropdown via `Object.defineProperty`, set `window.innerWidth/innerHeight`; render a tiny harness component):
- anchor at left 600 in a 1512 px viewport, dropdown width 460 → `style.left === 600`, `style.top === a.bottom + 4`;
- anchor right edge at 1500, width 460 → `style.left === 1500 - 460`;
- anchor at left 2 with width 460 → `style.left === 8`;
- anchor near the bottom (a.top 900 in 982 px) → `style.bottom === 982 - 900 + 4` and `style.top === 'auto'`;
- dispatching `resize` after changing the anchor rect updates `style.left`;
- toggling `open` true → false calls the WI-1 reset (an `overflow-x: hidden` parent with `scrollLeft` 50 ends at 0).
