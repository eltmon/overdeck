## Glossary

- **`/m` shell (web):** the phone view the dashboard serves at `/m`, `/m?tab=conversations`, `/m?conversation=<id>`, `/m/pipeline`, `/m/pipeline?issue=<id>`. Root component `MobileApp` in `src/dashboard/frontend/src/components/mobile/MobileApp.tsx`, lazy-loaded by `src/dashboard/frontend/src/App.tsx` line 148 (grep: `terminalPath === '/m'`). It runs in a phone browser or as a Home Screen web app (PWA).
- **Native app:** `apps/mobile`, the Capacitor 8 iOS/Android app. Root `ShellApp` (`apps/mobile/src/shell/ShellApp.tsx`). It renders its own **shell screens** (sign-in, machine list, pair, settings) and, for the current machine, `MachineView` (`apps/mobile/src/shell/MachineView.tsx`), which renders the same `MobileApp` with a `headerSlot`.
- **Native shell flag:** `isNativeShell()` from `src/dashboard/frontend/src/lib/nativeShell.ts` (a leaf module). True only inside the native app.
- **Landing pages:** the three tab lists of `MobileApp` (Needs you, Conversations list, Pipeline list) and the native app's machine list (`MachinesScreen`). Not landing pages: an open conversation, an open issue sheet, the pair screen, settings.
- **Appearance:** `system | light | dark`, stored in `localStorage['overdeck.appearance']` (PAN-5041 D-1). **Resolved theme:** `light | dark`; `system` resolves through `matchMedia('(prefers-color-scheme: dark)')`.

That route is admin-only (it is not listed in `src/dashboard/server/route-scopes.ts`), so a paired phone token cannot call it, and when it succeeds it changes the background of every new tmux session on the machine.
- **Design language:** `data-theme="broadsheet" | "ledger"` on `<html>`, set by the frontend `index.html` (the `/m` web shell has it, default `broadsheet`). The native app sets none (PAN-5041 D-6), so it renders the `:root` / `.dark` tokens.

The monochrome component `OverdeckMark` (`src/dashboard/frontend/src/components/OverdeckMark.tsx`, viewBox `0 0 32 32`, `currentColor`) already exists.

- **WAAPI:** the Web Animations API, `Element.animate(keyframes, options)`.
- **Hints banner:** the new dismissible banner that holds the install hint and the notifications control, which today sit in the `/m` header.

## Problem

Operator, 2026-11-13: "We should do a pass on the look and styling of the mobile app its kind of ugly, and maybe an Overdeck logo behind the main mobile landing pages, but you know where its a bit faint. And when first loading the overdeck logo should do the animation that we do for videos."

Today (`MobileApp.tsx` lines 175-235, verified at `e0f28691ead`):

- The header is `<h1 className="text-base font-medium">Overdeck</h1>` plus, on the web, `<InstallAffordance />` and `<TurnOnNotificationsButton compact />`. On an iPhone those render two wrapped strings: "To install, tap Share, then Add to Home Screen" and "Notifications unavailable" (`TurnOnNotificationsButton.tsx` line 53, grep `Notifications unavailable`).
- The tab bar is three text buttons (`TABS`, grep `{ tab: 'needs-you', label: 'Needs you' }`), no icons.
- Empty states are a single grey line: `MobileNeedsYou.tsx` grep `Nothing needs you.`, `MobileConversations.tsx` grep `No conversations.`, `MobilePipeline.tsx` grep `No active issues.`.
- There is no brand mark anywhere on the phone screens.
- `/m` has no appearance control. The System/Light/Dark setting (PAN-5041) exists only in `apps/mobile/src/shell/SettingsScreen.tsx` (`AppearanceSection`, grep `data-component="appearance-setting"`). In the `/m` web shell the theme is whatever `overdeck.ui.theme` says (default dark), shared with the desktop dashboard in the same browser.
- The native machine list (`MachinesScreen.tsx`) is a plain header with two text buttons and a bare list; with no machines it shows nothing at all.

## Proposal

1. Move the appearance store (key, read, write, subscribe, resolve) into one frontend leaf module, `src/dashboard/frontend/src/lib/appearance.ts`. The native `apps/mobile/src/shell/appearance.ts` re-exports it and keeps only its Capacitor side effects. The `/m` web shell gets its own small controller that applies the resolved theme **without** writing `overdeck.ui.theme` and **without** any server request.
2. One shared `AppearanceChoice` radiogroup component, used by the native Settings screen and by a new `/m` settings sheet behind a gear icon in the web header.
3. Shared brand pieces in `src/dashboard/frontend/src/components/mobile/brand.tsx`: the mark colors, `LogoWatermark`, `MobileEmptyState`, and the row class constants. Both surfaces import them, so both get one visual language.
4. `LogoSting`, an overlay drawn over the already-mounted app. It plays at most once per `sessionStorage` lifetime (one browser tab session, or one native app process: the native machine-switch reload keeps `sessionStorage`, like `LAUNCH_URL_KEY` in `ShellApp.tsx`). It is timer-driven, skippable with a tap, and under reduced motion shows the settled logo briefly with no motion.
5. Restyle the `/m` header, tab bar, rows, empty states, and the native machine list, sign-in and settings screens with the dashboard tokens.
6. Screenshot evidence before and after, at iPhone 14 and Pixel 7 sizes, light and dark.

## Requirements

### Functional

- **FR-1** `/m` and the native app share one appearance store: key `overdeck.appearance`, values `system|light|dark`, anything else (missing, invalid, storage error) reads as `system`. Writing it from either surface notifies the same in-page listeners.
- **FR-2** The `/m` web header has a Settings button (gear icon, accessible name `Settings`) that opens a settings sheet with the System/Light/Dark choice. Choosing one applies the resolved theme at once, persists across reloads, and with `system` follows the OS live.
- **FR-3** In the `/m` web shell, applying the appearance never writes `localStorage['overdeck.ui.theme']` and never sends `PUT /api/settings/ui-theme` (or any request).
- **FR-4** The first paint of any `/m` path already has the resolved appearance's `.dark` state (no flash of the desktop theme).
- **FR-5** The `/m` header shows the Overdeck mark and wordmark. The install hint and the notifications control move from the header into one dismissible hints banner below the header. After dismissal, both controls remain available in the settings sheet.
- **FR-6** The tab bar shows an icon above each label, keeps the existing accessible names (`Needs you`, `Conversations`, `Pipeline`) and `aria-current="page"`, and keeps safe-area padding.
- **FR-7** Rows show a clear hierarchy: title, secondary line (project or kind/status), age on the right. Needs-you rows mark blocking items with one amber dot. Pipeline rows show the project name and age. Conversation group headers use a chevron icon and a plus icon (PAN-5045 grouping, collapse state and `+` behavior unchanged).
- **FR-8** Each empty state is a centered block with the existing title text unchanged plus a one-line detail.
- **FR-9** A faint control-ring watermark is centered behind each landing page (three `/m` tab lists, native machine list): opacity 0.05 in light, 0.04 in dark, `aria-hidden="true"`, `pointer-events: none`, in a non-scrolling layer behind the scroller. It does not render on an open conversation, an open issue sheet, the pair screen or settings.
- **FR-10** The logo sting plays over the app on the first `/m` load of a browser tab session and on a cold start of the native app. It plays at most once per `sessionStorage` lifetime. It starts its 0.25 s fade at the later of `MIN_STING_MS` (1.3 s) and the moment the surface's content is ready, and never later than `STING_MS` (2.3 s). A tap starts the fade at once. A web `/m` load that opens a deep link (`?subject=`, `?conversation=`, `?issue=`) skips the sting and still marks it played.
- **FR-11** Under `prefers-reduced-motion: reduce`, the sting calls no animation: it shows the settled lockup for 600 ms and is removed with no fade.
- **FR-12** The sting never delays usable content: the app beneath is mounted and fetching from the first render (the sting is an overlay, not a gate), and once content is ready the sting holds at most until `MIN_STING_MS`.
- **FR-13** The native machine list, sign-in and settings screens use the same header, row, empty-state and mark components.

### Non-functional

- **NFR-1** No new npm dependency (no GSAP). Icons come from `lucide-react` (already a frontend dependency): `Inbox`, `MessageSquare`, `ListOrdered`, `Settings`, `X`, `ChevronRight`, `Plus` (each verified present in `src/dashboard/frontend/node_modules/lucide-react/dist/esm/icons/`).
- **NFR-2** The desktop dashboard's theme behavior is unchanged on every non-`/m` path: same key, same default (dark), same server sync, same toggle.
- **NFR-3** Style follows `pan-style-guide`: token classes only (`bg-background`, `bg-card`, `border-border`, `text-foreground`, `text-muted-foreground`, `rounded-md`), weight at most `font-medium` except the wordmark (the brand asset's 600), no pill badges, one colored signal per row, and no Broadsheet-only patterns (eyebrow, chip, soft card, dot-metadata), because the native app renders Ledger tokens (no `data-theme`).
- **NFR-4** Tests follow repo rules: fake timers for every sting timing test (`vi.useFakeTimers()` + `vi.advanceTimersByTime()`), no `it.skip` / `skipIf` / `.only`, no source-grep tests. Frontend tests live in the frontend Vitest project; native tests in `apps/mobile/vitest.config.ts`.
- **NFR-5** No new import cycle: `lib/appearance.ts` imports nothing from `hooks/useTheme.ts`; `npm run lint` (which includes `lint:circular`) passes.
- **NFR-6** Text contrast over the watermark stays WCAG AA: the watermark is at most 5% opacity of `--primary` over `--background`, which moves the background luminance by under 2%.

## Decisions

- **D-1 Shared store location.** `src/dashboard/frontend/src/lib/appearance.ts` holds `Appearance`, `ResolvedTheme`, `APPEARANCE_KEY`, `APPEARANCES`, `readAppearance`, `writeAppearance`, `onAppearanceChange`, `useAppearance`, `resolveAppearance`, and `isMobileShellPath(pathname)`. The body of each function moves verbatim from `apps/mobile/src/shell/appearance.ts` lines 19-78. `apps/mobile/src/shell/appearance.ts` re-exports these names (`export { ... } from '../../../../src/dashboard/frontend/src/lib/appearance';`) and keeps `AppearanceDeps`, `installAppearance`, `defaultAppearanceDeps`. Existing native imports and tests keep working unchanged.
- **D-2 `/m` default is System.** With no stored value, `/m` resolves `system` like the native app. A browser that showed `/m` dark because the desktop dashboard default is dark now follows the OS. Headless Chromium reports light, so every Playwright spec sets `colorScheme` explicitly.
- **D-3 `/m` never writes the desktop key.** `useTheme` gains `setLocalTheme(theme)`: applies the class with transitions suppressed and sets `{ theme, resolvedTheme }`; no storage write, no server sync. The `/m` controller uses it. `setTheme` and `toggleTheme` are unchanged.
- **D-4 `useTheme` module-load guard.** At module load, `useTheme.ts` skips `applyTheme(getStoredTheme())` and the module-load `syncThemeToServer` when `!isNativeShell() && isMobileShellPath(window.location.pathname)`. Its initial state on those paths is `resolveAppearance(readAppearance(), systemDark)`; this also matters because `useColorTheme.ts` line 90 applies UI tokens for `useTheme.getState().resolvedTheme` at load and re-applies on every `useTheme` change (line 188). This keeps the pre-paint (D-5) instead of flipping to the desktop theme while the lazy `MobileApp` chunk loads (`Sidebar.tsx` imports `useTheme`, so the module evaluates on every route).
- **D-5 Pre-paint.** The frontend `index.html` flash script (grep `Flash prevention: Apply theme class before React mounts`) resolves `overdeck.appearance` when `location.pathname === '/m' || location.pathname.indexOf('/m/') === 0`, else keeps today's `overdeck.ui.theme` logic.
- **D-6 Controller lifetime.** `useMobileAppearance()` (new hook, `components/mobile/useMobileAppearance.ts`) runs in a `useLayoutEffect` in `MobileApp` only when `!isNativeShell()`. It applies now, on every `onAppearanceChange`, and on every `matchMedia('(prefers-color-scheme: dark)')` `change`. The native app keeps PAN-5041's `installAppearance` in `ShellApp`.
- **D-7 Settings button is web-only.** In the native app the `MobileApp` header shows `headerSlot` (the machine button) as today; appearance stays in the native Settings screen. Reason: native Settings already owns appearance plus the native chrome sync, and one entry point per surface avoids two screens for one setting.
- **D-8 Hints banner rules.** `MobileHintsBanner` renders only in the web shell. It is hidden when `localStorage['overdeck.m.hintsDismissed'] === '1'`, or when the page is standalone (`prompt.standalone`) **and** push status reports a `thisDevice` web-push subscription. Otherwise it shows `<InstallAffordance prompt={prompt} />` and `<TurnOnNotificationsButton />` (non-compact, so the full reason text replaces "Notifications unavailable"), plus a `Dismiss` button (lucide `X`, accessible name `Dismiss`). Dismiss writes the key. Storage errors read as not dismissed and writes fail silently. The settings sheet always contains the same two controls under the headings `Install` and `Notifications`.
- **D-9 Sting mounting.** `ShellApp` renders `<LogoSting />` as the last child of its root `div` (cold start). `MobileApp` renders `<LogoSting />` only when `!isNativeShell()`. One `sessionStorage` key, `overdeck.logoSting.played`, value `'1'`. The `useState` initializer only reads the key (pure, safe under `React.StrictMode` double invocation); a mount `useEffect` writes it. A storage read error means "play"; a write error is ignored.
- **D-10 Ready signal and early finish.** `LogoSting` takes `ready: boolean` and `skip?: boolean`. Constants `MIN_STING_MS = 1300` (ring drawn, hub popped), `STING_MS = 2300`. The fade starts at `max(MIN_STING_MS, t_ready)`, capped at `STING_MS`, where `t_ready` is the time since mount when `ready` first became true (measured with `Date.now()`, which Vitest fake timers control). The minimum keeps the brand moment visible on a warm snapshot cache. Ready signals:
  - `/m` web (`MobileApp`): `ready = sessionAuthFailed || hasSnapshot`, both from `useConnectionState`.
  - Native (`ShellApp`): `ready = boot.kind === 'failed' || (boot.kind === 'ready' && (account === null || (services !== null && (!inMachineView || hasSnapshot))))`, with `hasSnapshot` from `useConnectionState` (already imported in `ShellApp.tsx`). Use the component's existing variables of those names; if a name differs, use the variable that drives the same branch of the render.
  - Deep links (`/m` web only): `skip = route.subjectId !== null || route.conversationId !== null || route.issueId !== null`, read once from the first route. A skipped sting renders nothing and still writes the played key, so a later plain load in that tab session does not play it.
- **D-11 Sting technique.** WAAPI on inline SVG parts plus an HTML wordmark span. The ring uses `pathLength="1"` (so no `getTotalLength()`), inside `<g transform="rotate(-90 20 20)">` so the draw starts at the top. The satellite arc is a five-stop `transform: translate(...)` keyframe list sampled from the recipe's path `M -16.8 -11.2 Q -7.76 -8.91 0 0` (no CSS `offset-path`, whose support on iOS 15 WKWebView is uncertain). The wordmark unmask is CSS `clip-path: inset(...)` on an HTML `<span>` (well supported), not on SVG text. When `typeof Element.prototype.animate !== 'function'` (for example happy-dom) the parts render settled. Removal is driven by `setTimeout`, never by `finished` promises or `animationend`.
- **D-12 Sting timings** (ms from mount; easing constants `EASE_OUT_QUAD = 'cubic-bezier(0.25, 0.46, 0.45, 0.94)'` for power2.out, `EASE_OUT_CUBIC = 'cubic-bezier(0.215, 0.61, 0.355, 1)'` for power3.out, `EASE_OUT_SINE = 'cubic-bezier(0.39, 0.575, 0.565, 1)'` for power1.out):

  | Part | Property | From → to | Delay | Duration | Easing |
  | --- | --- | --- | --- | --- | --- |
  | ring | `strokeDashoffset` | `1` → `0` | 200 | 750 | EASE_OUT_QUAD |
  | hub | `transform` | `scale(0)` → `scale(1)` | 750 | 450 | EASE_OUT_CUBIC |
  | satellite | `opacity` | `0` → `1` | 1300 | 250 | EASE_OUT_SINE |
  | satellite group | `transform` | `translate(-16.8px,-11.2px)`, `(-12.36px,-9.64px)`, `(-8.08px,-7.26px)`, `(-3.96px,-4.04px)`, `(0px,0px)` | 1300 | 950 | EASE_OUT_CUBIC |
  | wordmark | `clipPath` | `inset(0 100% 0 0)` → `inset(0 0 0 0)` | 1250 | 850 | EASE_OUT_CUBIC |

  Every animation uses `fill: 'both'`. Constants: `STING_MS = 2300`, `FADE_MS = 250`, `REDUCED_HOLD_MS = 600`. The guide rings, halo, tagline and mono label of the video recipe are dropped (NonGoals).
- **D-13 Sting colors** follow the theme with Tailwind `dark:` classes: ring/hub `stroke-[#4f46e5] dark:stroke-[#6366f1]` / `fill-[#4f46e5] dark:fill-[#6366f1]`, satellite `fill-[#818cf8] dark:fill-[#a5b4fc]`, wordmark `text-[#2d2d2d] dark:text-[#f5f0ea]`. These literals are the brand asset's own colors and live only in `brand.tsx` as `MARK_CLASSES`.
- **D-14 Watermark placement.** In `MobileApp`, `<main>` stays the scroller (`MobileNeedsYou` scrolls via `row.closest('main')`). It is wrapped in `<div className="relative min-h-0 flex-1">` whose first child is `<LogoWatermark />` (`absolute inset-0`) and whose second child is `<main className="relative h-full overflow-y-auto">`. The watermark renders only when `!fullScreen`. `MachinesScreen` uses the same wrapper around its `<ul>`.
- **D-15 Design language.** No change to `data-theme` in either surface (keeps PAN-5041 D-6 native background colors valid). Components use only tokens that exist in all four scopes.
- **D-16 Row data per tab** (only fields that exist today):
  - Needs you (`Decision` in `lib/useDecisions.ts`): title = today's label expression; secondary = `describePendingInput(...)` plus ` · on ${machineLabel}` when `machineLabel` is set; age = `formatRelativeTime(since, now)`; a 6 px `bg-state-needs-you` dot before the title when `decision.blocking` (accessible text `Blocking` via `sr-only`), nothing otherwise.
  - Conversations (`Conversation` in `CommandDeck/ConversationList.tsx`): project = the group header (PAN-5045); title; secondary = `issueId` when set; age = `recencyAt(c)` as today.
  - Pipeline (`Issue` in `types.ts`): line 1 `font-mono` identifier plus ` · ${issue.project.name}` (non-mono) when `issue.project` is set; title `line-clamp-2`; right column: `formatRelativeTime(issue.updatedAt, now)` above `NeedsYouMark` when it applies. Phase stays the `PhaseHeader` grouping.
- **D-17 Native screenshots harness (implementation checkpoint).** Try in order: (a) the iOS Simulator on the Mac rig (`apps/mobile/README.md` "Run in the iOS Simulator") with the Simulator appearance set light and dark; (b) an Android emulator per `apps/mobile/README.md`. If neither is reachable within the session, record the deviation in `apps/mobile/acceptance/PAN-5208.md` and attach the `MachinesScreen.test.tsx` DOM evidence instead. The `/m` screenshots are never skipped.
