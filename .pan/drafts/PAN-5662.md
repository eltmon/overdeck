# PAN-5662 — Composer: `@` files and `$` skills pickers, plus the "Ask anything" placeholder

**Issue:** [PAN-5662](https://github.com/eltmon/overdeck/issues/5662)
**Status:** draft (planning, `pan plan --auto`, 2026-11-24)
**Base commit:** `c40a85d4089` (feature/pan-5662)

## Glossary

- **Composer** — the Lexical text editor at the bottom of a conversation tab. Component `ComposerPromptEditor` in `src/dashboard/frontend/src/components/chat/ComposerPromptEditor.tsx`, mounted by `ComposerFooter.tsx` (and, with menus off, by `SubagentComposer.tsx`).
- **Trigger** — one of the three characters `/`, `@`, `$` that opens a picker menu in the composer.
- **Trigger token** — the trigger character plus the characters typed after it, up to the caret. For `@` and `$` the token never contains whitespace. For `/` the filter may contain spaces (existing behavior: `/pan work` filters to `pan work`).
- **Word start** — position 0 of the text, or a position whose previous character matches `/\s/` (space, tab, newline).
- **Trigger context** — `{ char, index, filter }`: which trigger is active, where its character sits, and the filter text after it. `null` means no menu for that trigger.
- **Slash menu** — the existing `/` menu (`SlashMenu` component, `aria-label="Slash commands"`): harness-native commands, Overdeck `/pan …` commands, and on Claude Code a **Skills** group (PAN-5347).
- **File menu** — the new `@` picker (`aria-label="Files"`). Lists files of the conversation's explorer root.
- **Skill menu** — the new `$` picker (`aria-label="Skills"`). Lists the conversation's enabled skills.
- **Explorer root** — the folder the file explorer reads, named by a root id: `project:<key>`, `issue:<ID>`, or `workspace:<id>`. `rootIdForConversation` (`src/dashboard/frontend/src/components/explorer/rootForConversation.ts`) maps a conversation to one, or to `null`.
- **Root-relative path** — a path relative to the explorer root folder, with `/` separators, as returned by `explorerSearchFiles`. For a project or issue root this equals the repo-relative path.
- **Skill mention form** — how a harness invokes a skill from typed text: `slash` (`/<name>`, Claude Code), `dollar` (`$<name>`, Codex), or none.
- **Harness capability** — a declared per-harness field in `packages/contracts/src/harness-capabilities.ts`. Consumers read capability fields, never harness names (`lint:harness-branches`).

## Problem

The composer has one inline trigger, `/`. Typing `@` or `$` does nothing, and the placeholder reads `Message the agent…`, so nothing tells the operator that triggers exist. The Codex desktop composer has three triggers (`@` files, `$` skills, `/` commands) and advertises them in its placeholder. The operator's standing complaint is that Overdeck features exist but are hard to reach (memory `ui-discoverability-is-the-priority`); this issue puts file references and skills one keystroke away inside the conversation tab, where the operator already is.

## Requirements

### Functional

- **FR-1** Typing `@` at a word start opens the File menu, listing files of the conversation's explorer root that match the characters typed after `@`, ranked by `explorerSearchFiles`.
- **FR-2** Each File menu row shows the file name (mono label) and its directory path (dimmed description); the filter substring is highlighted in the name when present.
- **FR-3** Selecting a File menu row (Enter, Tab, or click) replaces the `@<filter>` token before the caret with `@<root-relative path> ` and leaves the rest of the prompt untouched.
- **FR-4** A conversation with no explorer root (linked row, cwd outside every project, or a mount outside a Stage) gets no File menu.
- **FR-5** Typing `$` at a word start opens the Skill menu, listing the same enabled skills the `/` menu's Skills group lists (`GET /api/skills/overrides` scoped by `skillContextForConversation`), filtered by skill name.
- **FR-6** Selecting a Skill menu row inserts the harness's native skill invocation: `/<name> ` when the harness declares `skillMention: "slash"` (Claude Code), `$<name> ` when it declares `skillMention: "dollar"` (Codex).
- **FR-7** A harness declaring `skillMention: null`, or a composer with no skill context, gets no Skill menu and makes no skills request for `$`.
- **FR-8** The `/` menu keeps every current behavior (contents, grouping, filtering with spaces, Enter/Escape/arrows, Tab closes, Codex shows no Skills group and fetches nothing), with one change: a `/` opens it only at a word start.
- **FR-9** A trigger character inside a word opens no menu: `foo@bar.com`, `foo$bar`, `src/`. A `$` token whose filter starts with an uppercase letter or a digit (`$HOME`, `$5`) is not a skill trigger, so after typing `echo $HOME` or `costs $5` no menu is visible.
- **FR-10** With no explicit `placeholder` prop, the composer placeholder is `Ask anything. ` followed by the supported triggers in the order `@ files`, `$ skills`, `/ commands`, joined by `, `. With none supported it is `Ask anything`.
- **FR-11** One shared trigger-menu implementation serves `/`, `@`, `$`: one presentational menu component, one keyboard handler, one set of pure trigger helpers.

### Non-functional

- **NFR-1** No new server route, RPC method, or file lister; the File menu reuses `pan.explorerSearchFiles`.
- **NFR-2** Capability, not harness name: the skill mention form comes from a new `HarnessCapabilities.skillMention` field. No new `harness === '<name>'` comparison (`lint:harness-branches`).
- **NFR-3** File search is debounced 120 ms after the last filter change, never runs for an empty filter, and drops answers to stale queries.
- **NFR-4** The skills request still runs only while a menu that shows skills is open, once per open; the placeholder never depends on a fetched list.
- **NFR-5** `ComposerFooter.tsx` stays at or under 1000 lines and gains no new fetch; `ComposerPromptEditor.tsx` stays under 1000 lines.
- **NFR-6** Existing `ComposerPromptEditor.test.tsx`, `ComposerPromptEditor.skills.test.tsx`, `skillSlashCommands.test.ts`, `slashCommands.skills.test.ts` assertions stay unedited and green. The only permitted edit to existing test files is adding exports to their `vi.mock('lexical', …)` factories (WI-5).

## Decisions (auto mode — each is also in `plan.autoDecisions[]`)

- **D1 — New capability `skillMention: "slash" | "dollar" | null`; keep `skillSlashCommands`.** `skillSlashCommands` still gates the `/` menu's Skills group and its fetch, so the four Codex no-fetch tests stay valid unedited. `skillMention` gates the `$` menu and picks the insert form. Claude Code `"slash"`, Codex `"dollar"`, every other harness `null`. A contract test asserts `skillSlashCommands === (skillMention === "slash")` for every runtime so the two never disagree.
- **D2 — `/` adopts the word-start rule.** Requirement 3 ("`/` keeps working unchanged") is read as: every existing `/` flow is unchanged. A `/` inside a word (`src/`, `and/or`) no longer pops the command menu. This is needed so typing a path inside an `@` token (`@src/comp`) never opens the slash menu, and every existing test types `/` at position 0.
- **D3 — `@` and `$` detection is caret-aware; `/` stays whole-text.** `@`/`$` tokens contain no whitespace, so the token always lies inside the caret's Lexical text node: detection reads `anchorNode.getTextContent().slice(0, anchor.offset)`, and insertion calls `anchorNode.spliceText(start, tokenLength, insert, true)`. This keeps text after the caret and line breaks intact. `/` keeps its current whole-text context and root-rebuild insertion (unchanged behavior).
- **D4 — `@`/`$` menus open from text changes, not keydown.** The menu is open while a trigger context exists and the operator has not dismissed that context (Escape or click outside records `"<char>:<index>"`; a new token at another index opens again). This works on AltGr keyboard layouts, where `@` arrives with Ctrl+Alt set and the existing `/` keydown filter would reject it. `/` keeps its keydown path.
- **D5 — A live `@`/`$` context wins over the `/` menu.** When the caret sits right after an `@`/`$` token, the slash menu is not rendered and its key handler is inactive (`/review @fi` shows the File menu).
- **D6 — `$` filter rule resolves the `echo $HOME` acceptance criterion.** Requirement 5 says a `$` after whitespace is a trigger, and the AC says `echo $HOME` shows no menu. Rule: a `$` context is valid only while its filter is empty or matches `/^[a-z][a-z0-9._:-]*$/`. Skill names are lowercase; environment variables and prices are not. So `echo $` briefly shows the Skill menu (requirement 5), and typing `H` closes it; after `echo $HOME` no menu is visible. `$home` stays a valid context but matches no skill name, so nothing renders. Skill rows match by case-insensitive substring of the **name only**, never the description.
- **D7 — Tab selects in `@` and `$` menus; Tab still closes the `/` menu.** Requirement 1 asks for Tab select; requirement 3 keeps `/` unchanged. The shared key handler takes a `tabSelects` flag.
- **D8 — Root from `useConversationChangesContext()`.** `ComposerFooter` passes `fileRootId={useConversationChangesContext()?.rootId ?? null}`. No new query, no QueryClientProvider needed in tests, and no extra requests outside a Stage. A popout or drawer mount (`PlainChangesScope`, root `null`) gets no File menu and no `@ files` in its placeholder.
- **D9 — Insert the root-relative path.** `explorerSearchFiles` returns root-relative paths, and for project and issue roots that equals the repo-relative path the issue asks for. A conversation whose cwd is a subfolder of the root still gets root-relative paths (see NonGoals).
- **D10 — Empty `@` filter shows a hint row, never a search.** The server returns nothing for an empty query, so the File menu shows one non-selectable row `Type to search files` until a character is typed. While a search is in flight or returns nothing, no rows render; Enter then submits the prompt as typed (same rule as the `/` menu, which intercepts Enter only when rows exist).
- **D11 — File menu size.** Request `limit: 20`, show all returned rows in server order.
- **D12 — Placeholder inputs.** `files = fileRootId != null`; `skills = skillContext !== undefined && skillMention !== null`; `commands = slashCommandsEnabled`. An explicit `placeholder` prop always wins (SubagentComposer keeps `Message <agentType>…`).
- **D13 — Skill rows show the inserted form as the label.** Claude Code rows read `/<name>`, Codex rows read `$<name>`, so the operator sees exactly what will be inserted.

### Implementation checkpoint — Codex `$<name>` delivery

Codex documents `$<skill-name>` as its explicit skill mention, and its own TUI inserts that text. Overdeck delivers Codex prompts over `codex app-server`. **Checkpoint (WI-7):** in a live Codex conversation, select a skill from the `$` menu, send, and check the Codex transcript shows the skill being used. **Fallback if it is not recognized:** keep inserting `$<name> ` (the issue mandates it and it is Codex's own syntax), and file a follow-up issue for structured skill input over app-server. Do not change the insertion form.
