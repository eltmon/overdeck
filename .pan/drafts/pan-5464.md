## Summary

The operator wants one "video production" skill bundle. Overdeck already has skill packs (operators call them skill bundles, see `features/skill-packs.mdx`), but a pack is exactly one git repository. The video skills come from four repositories with four licenses, so this issue ships **four known packs** and a new, small **pack group** concept so that one name (`video`) turns all four on.

Today the operator gets most of these skills by accident: `~/.claude/skills` holds symlinks into an old `~/Projects/OpenMontage` clone and HyperFrames copies installed by `npx skills`. Those load into every session on the machine. The packs replace that with pinned, per-scope skills.

## Glossary

- **Skill pack**: a third-party git repo of skills, pinned to one trusted commit, registered with `pan skills pack add`, mounted per launch. Code: `src/lib/skill-packs/`. Docs: `features/skill-packs.mdx`, `docs/SKILL-PACKS.md`.
- **Known pack**: an entry in `KNOWN_PACKS` (`src/lib/skill-packs/adapters.ts`, search `export const KNOWN_PACKS`). It supplies the default url, ref, adapter, skills root, opt-in list, excludes and disclosure, so `pan skills pack add <id>` needs no url. Interface: `export interface KnownPack` in the same file.
- **Adapter**: how a pack repo is read. `plain` scans `skills/` (or `skillsRoot`) for `<dir>/SKILL.md` (`scanSkillDirs`); `claude-plugin` reads `.claude-plugin/plugin.json` and scans its `skills` field, default `skills/` (`claudePluginSkillDirs`).
- **Manifest**: `PackManifest`, returned by `readPackManifest(root, adapter, opts)` in adapters.ts. It has **two callers that each build their own `opts`**: `manifestAt` in `src/lib/skill-packs/sources.ts` (search `async function manifestAt`; used by add/update previews) and `listPackCatalog` in `src/lib/skill-overrides/catalog.ts` (search `const readOpts = {`; used by launches, `pan skills list` and `pan skills pack list`). Any new read option must be passed by both, or the preview and the launch disagree.
- **Mount**: the content-addressed directory `~/.overdeck/packs/mounts/<sha256>/plugins/<pack>/skills/<skill>/…` built by `buildMount` (`src/lib/skill-packs/mount.ts`). The hash comes from `mountHash`. Immutable once built.
- **Launch selection**: `resolveLaunchPackSelection` in `src/lib/skill-overrides/launch.ts` turns the catalog into `MountPack[]`. Today it sets `transform` only from the adapter (`deft-readonly`, `gstack-runtime`) and passes each skill as `{ name, dir }` only (search `.map(skill => ({ name: skill.name, dir: skill.dir }))`).
- **Extraction**: `extractCommit` (`src/lib/skill-packs/sources.ts`, search `export async function extractCommit`) runs `git archive` of the trusted commit into `~/.overdeck/packs/<id>/<commit>/`. Seven call sites pass `pluginRootOf(id)`.
- **Root skill**: a repo whose main skill is `SKILL.md` at the repo root, with helper files beside it (video-use). `scanSkillDirs` starts at `skills/` and never sees it.
- **Host notice**: a short block Overdeck inserts into a mounted `SKILL.md` to adapt it to Overdeck (precedent: `applyDeftHostNotice` in `src/lib/skill-packs/deft.ts`, which splits frontmatter with `FRONTMATTER_OPEN`/`FRONTMATTER_CLOSE`).
- **Pack group**: NEW. A named list of pack ids. `video` = `remotion`, `hyperframes`, `openmontage`, `video-use`. A group is only an alias that expands to its member packs when a command runs. It has no state of its own.
- **Fork-first policy**: known packs come from operator-controlled forks under `github.com/eltmon/` (`features/skill-packs.mdx`, "Fork-first policy"). No agent opens issues or PRs on, or pushes to, an upstream repo.
- **Isolated home**: `OVERDECK_HOME=$HOME/.overdeck/tmp/pan-5464-live` (`getOverdeckHome()` in `src/lib/paths.ts` reads the variable on every call). Every live check in this PRD uses it so nothing touches the operator's real `config.yaml`, `projects.yaml` or `~/.overdeck/packs`.

## Requirements

- **FR-1**: `pan skills pack add remotion|hyperframes|openmontage|video-use` works with no url, using the eltmon forks and the pinned commits above.
- **FR-2**: Extracting any pack never runs the Git LFS smudge filter and never downloads LFS objects. LFS pointer files inside a pack's skill dirs are listed in the preview under **Not applied** as `LFS objects (<n>)`.
- **FR-3**: A known pack can declare `archivePaths`; extraction then archives only those repo-relative paths that exist at the commit, plus the capability-probe paths that exist. HyperFrames' extraction is under 20 MB.
- **FR-4**: The `openmontage` pack mounts exactly the 38 skills listed above.
- **FR-5**: A known pack can declare a root skill: a skill name plus repo-relative paths that the mount copies into `skills/<name>/`. `video-use` uses it, and its preview shows `Skills 2`.
- **FR-6**: The `video-use` mounted `SKILL.md` carries a host notice (API key from the environment only, helpers run through `uv run --no-project --with-requirements`, never write into the skill dir), and the mount holds a generated `requirements.txt`.
- **FR-7**: License detection recognizes AGPL, LGPL and GPL by their full names (`GNU AFFERO GENERAL PUBLIC LICENSE` → `AGPL-3.0`, etc.).
- **FR-8**: A built-in pack group `video` exists. `pan skills pack add --group video` runs the add flow for each member; `pan skills set --group video on|off|inherit [--project|--issue]` sets each member's pack toggle; `pan handoff --group video` expands to one `--pack` per cached member.
- **FR-9**: Operators can define groups in `~/.overdeck/config.yaml` under `skills.pack_groups.<name>: [<pack id>, …]`. A config group with a built-in name replaces the built-in.
- **NFR-1**: A launch still never touches the network or runs git (unchanged invariant: `listPackCatalog` reads the cache only).
- **NFR-2**: Mount hashes of existing packs stay identical. New hash input is added only for skills that set `paths` or packs with the new transform.
- **NFR-3**: No file grows past its file-size ceiling (`scripts/lint-file-size.sh`, ceiling 1000 lines unless `scripts/file-size-allowlist.txt` says otherwise). New logic goes in new files where a section says so.

## Decisions

- **D-1. One pack per upstream, never one aggregate repo.** Pinning, trust and license are per commit. Vendoring all four into one repo would mix AGPL with an unlicensed repo and lose provenance.
- **D-2. Group is an alias, not a pack.** It expands to member pack ids when a command runs. No registry entry, no mount, no toggle of its own. `pan skills list` does not show groups; `pan skills pack list` prints a `Groups` section after the packs.
- **D-3. Forks exist; pin the 2026-11-17 heads.** The forks were created by the operator before planning. The work agent never creates a fork. Each `KNOWN_PACKS` entry gets the 40-hex commit from the Research table with a comment `// eltmon/<fork> main head 2026-11-17 (PAN-5464)`. If `gh api repos/eltmon/<fork>/commits/<sha>` fails for any of them, the agent stops and reports with `pan tell flywheel-orchestrator`.
- **D-4. Opt-in.** Opt-in stays reserved for skills that change files Overdeck owns or push. None of the 62 mounted video skills does, so no `optIn` lists. Provider skills that call paid APIs are default-on, because each does nothing without an API key the operator sets. Each pack's `disclosure` says this.
- **D-5. LFS.** Add `GIT_LFS_SKIP_SMUDGE: '1'` to the env of the local `git()` helper in sources.ts. Git still spawns the configured LFS filter; git-lfs reads the variable and passes pointer files through. Do not add `-c filter.lfs.*` overrides.
- **D-6. Archive paths.** `KnownPack.archivePaths?: readonly string[]` (repo-relative). The effective list is `archivePaths ∪ CAPABILITY_PROBE_PATHS`, filtered to paths that exist at the commit (`git cat-file -e <commit>:<path>` per path). `CAPABILITY_PROBE_PATHS = ['.claude-plugin', 'hooks', '.mcp.json', 'commands', 'agents', 'LICENSE', 'LICENSE.md']`, so the preview still detects hooks, MCP servers, commands, agents and the license. An empty effective list throws `pack <id>: none of its archive paths exist at <commit>`. A known pack never sets both `pluginRoot` and `archivePaths` (asserted by a test).
- **D-7. Extraction reuse.** An existing extraction is reused only when every effective archive path exists inside it; otherwise it is removed and rebuilt. This mirrors today's `pluginRoot` check. A full-tree extraction is a superset, so it is reused.
- **D-8. Root skill consumers.** A root skill has `dir: '.'` and `paths`. Every consumer of `skill.dir` follows the paths instead: the manifest lists executables and LFS pointers only under `paths`; `updatePack` computes the changed-skill hash as the `treeHash` of each path joined with `,`; the mount copies only `paths`. Nothing passes `.` to `listExecutables` or `treeHash`.
- **D-9. video-use runtime.** No new runtime adapter. The mount writes `requirements.txt` from `pyproject.toml` `[project].dependencies` (parsed with `@iarna/toml`) into the mounted skill dir. The host notice tells the agent to run helpers with `uv run --no-project --with-requirements <skill dir>/requirements.txt python <skill dir>/helpers/<script>.py …`. uv caches environments under `~/.cache/uv`, so nothing writes into the mount. `ELEVENLABS_API_KEY` comes from the environment; if missing, a managed agent asks with the `request_secret` tool, and the notice forbids writing a `.env` file.
- **D-10. Transform selection.** `KnownPack.mountTransform?: 'video-use'`. `resolveLaunchPackSelection` uses the adapter transform for `deft-readonly`/`gstack-runtime` as today, else `known?.mountTransform`. The `video-use` transform changes only the skill named `video-use`; `manim-video` is copied unchanged.
- **D-11. Groups in the CLI.** `pan skills pack add --group <name>` runs members in order, prints `already added` for registered members and continues, and exits 1 at the end if any member was declined or failed. `pan skills set --group <name>` first checks that every member is registered; if any is not, it writes nothing and exits 1 with `pack <id> is not added; run pan skills pack add --group <name>`. `--group` and `--pack` together exit 1 with `use either --pack or --group, not both`.
- **D-12. Global duplicates are not removed by code.** The `~/.claude/skills` symlinks and `npx skills` copies are operator-owned. Docs explain the double listing; the operator decides whether to unlink them.
- **D-13. Dashboard UI for groups is PAN-5465's.** This issue is CLI and launch only.
