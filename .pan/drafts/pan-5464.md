# PAN-5464: Video production skill set: Remotion, HyperFrames, OpenMontage and video-use packs, plus a `video` pack group

**Issue:** [PAN-5464](https://github.com/eltmon/overdeck/issues/5464)
**Companion:** [PAN-5465](https://github.com/eltmon/overdeck/issues/5465) (add packs to a running conversation). The two issues are independent; PAN-5465 accepts `--group` only after this issue lands.

## Summary

The operator wants one "video production" skill bundle. Overdeck already has skill packs (operators call them skill bundles, see `features/skill-packs.mdx`), but a pack is exactly one git repository. The video skills come from four repositories with four licenses, so this issue ships **four known packs** and a new, small **pack group** concept so that one name (`video`) turns all four on.

Today the operator gets most of these skills by accident: `~/.claude/skills` holds symlinks into an old `~/Projects/OpenMontage` clone and HyperFrames copies installed by `npx skills`. Those load into every session on the machine. The packs replace that with pinned, per-scope skills.

## Glossary

- **Skill pack**: a third-party git repo of skills, pinned to one trusted commit, registered with `pan skills pack add`, mounted per launch. Code: `src/lib/skill-packs/`. Docs: `features/skill-packs.mdx`.
- **Known pack**: an entry in `KNOWN_PACKS` (`src/lib/skill-packs/adapters.ts`, search `export const KNOWN_PACKS`). It supplies the default url, ref, adapter, skills root, opt-in list, excludes and disclosure, so `pan skills pack add <id>` needs no url.
- **Adapter**: how a pack repo is read. `plain` scans `skills/` (or `skillsRoot`) for `<dir>/SKILL.md`; `claude-plugin` reads `.claude-plugin/plugin.json`.
- **Mount**: the content-addressed directory `~/.overdeck/packs/mounts/<sha256>/plugins/<pack>/skills/<skill>/…` built by `buildMount` (`src/lib/skill-packs/mount.ts`). Immutable once built.
- **Extraction**: `extractCommit` (`src/lib/skill-packs/sources.ts`, search `export async function extractCommit`) runs `git archive` of the trusted commit into `~/.overdeck/packs/<id>/<commit>/`.
- **Root skill**: a repo whose one skill is `SKILL.md` at the repo root, with helper files beside it (video-use). The current scan (`scanSkillDirs`, adapters.ts) starts at `skills/` and never sees it.
- **Host notice**: a short block Overdeck inserts into a mounted `SKILL.md` to adapt it to Overdeck (precedent: `applyDeftHostNotice` in `src/lib/skill-packs/deft.ts`).
- **Pack group**: NEW. A named list of pack ids. `video` = `remotion`, `hyperframes`, `openmontage`, `video-use`. A group is only an alias that expands to its member packs. It has no state of its own.
- **Fork-first policy**: known packs come from operator-controlled forks under `github.com/eltmon/` (`features/skill-packs.mdx`, "Fork-first policy"). No agent opens issues or PRs on, or pushes to, an upstream repo.

## Requirements

- **FR-1**: `pan skills pack add remotion|hyperframes|openmontage|video-use` works with no url, using the eltmon forks and a pinned default ref.
- **FR-2**: Extracting any pack never runs the Git LFS smudge filter and never downloads LFS objects. LFS pointer files inside a mounted skill dir are listed in the preview under **Not applied** as `LFS objects (<n>)`.
- **FR-3**: The `openmontage` pack mounts the standalone skills under `.agents/skills/`, minus the WI-3 exclude list.
- **FR-4**: A known pack can declare a root skill: a skill name plus repo-relative paths that the mount copies into `skills/<name>/`. `video-use` uses it.
- **FR-5**: The `video-use` mounted `SKILL.md` carries a host notice: API key from the environment only, helpers run through `uv run --no-project --with-requirements`, never write into the skill dir.
- **FR-6**: License detection recognizes AGPL, LGPL and GPL by their full names (`GNU AFFERO GENERAL PUBLIC LICENSE` → `AGPL-3.0`, etc.).
- **FR-7**: A pack group `video` exists. `pan skills pack add --group video` runs the add flow for each member; `pan skills set --group video on|off|inherit [--project|--issue]` sets each member's pack toggle; `pan handoff --group video` expands to one `--pack` per cached member.
- **FR-8**: Operators can define their own groups in `~/.overdeck/config.yaml` under `skills.pack_groups.<name>: [<pack id>, …]`. A config group with a built-in name replaces the built-in.
- **NFR-1**: A launch still never touches the network (unchanged invariant).
- **NFR-2**: No change to how existing packs mount. Mount hashes of existing packs stay identical (the new fields are not part of their hash input).

## Decisions

- **D-1. One pack per upstream, never one aggregate repo.** Pinning, trust and license are per commit. Vendoring all four into one repo would mix AGPL with an unlicensed repo and lose provenance.
- **D-2. Group is an alias, not a pack.** A group expands to member pack ids at the moment a command runs. No registry entry, no mount, no toggle of its own. `pan skills list` does not show groups; `pan skills pack list` prints a `Groups` section after the packs.
- **D-3. Forks.** Create, without cloning: `gh repo fork remotion-dev/skills --clone=false --fork-name remotion-skills` (the name `eltmon/skills` is already the mattpocock fork), `gh repo fork heygen-com/hyperframes --clone=false`, `gh repo fork OpenMontageInc/OpenMontage --clone=false`, `gh repo fork browser-use/video-use --clone=false`. Pin each known pack to the fork's default-branch head **as a 40-hex commit** (like `pstack`), recorded in `KNOWN_PACKS[id].ref` with a comment naming the date.
- **D-4. Opt-in.** Opt-in stays reserved for skills that change files Overdeck owns or push. Provider skills that call paid APIs (ElevenLabs, HeyGen, Kling, Seedance…) are default-on, because each does nothing without an API key the operator sets. Each pack's `disclosure` says this.
- **D-5. LFS.** Set `GIT_LFS_SKIP_SMUDGE=1` in the env of the `git archive` call in `extractCommit`. git-lfs then passes pointer files through unchanged. Do not add `-c filter.lfs.*` overrides.
- **D-6. video-use runtime.** No new runtime adapter. The mount writes a `requirements.txt` generated from `pyproject.toml` `[project] dependencies` into the mounted skill dir, and the host notice tells the agent to run helpers as `uv run --no-project --with-requirements <skill dir>/requirements.txt python <skill dir>/helpers/<script>.py …`. uv caches environments under `~/.cache/uv`, so nothing writes into the mount. `ELEVENLABS_API_KEY` comes from the environment; if it is missing, a managed agent asks with the `request_secret` tool, and the notice forbids writing a `.env` file.
- **D-7. Global duplicates are not removed by code.** The `~/.claude/skills` symlinks and `npx skills` copies are operator-owned. Docs explain the double listing; the operator decides whether to unlink them.
