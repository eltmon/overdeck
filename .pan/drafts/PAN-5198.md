# PAN-5198: Flywheel page Needs-you items, one actionable row each

**Issue:** [PAN-5198](https://github.com/eltmon/overdeck/issues/5198)
**Planned:** 2026-11-13, `pan plan --auto` (no operator questions; defaults are in "Decisions").

## Glossary

- **Flywheel** — the `/pan-flywheel` loop skill running in conversation `conv-flywheel`. It has no run record; the page is a derived view (`docs/FLYWHEEL.md`).
- **Tick marker** — the line the loop prints at the end of every tick: `flywheel-tick: tick=<n> pick=<ID|none> phase=<phase> in-flight=<ID,…|none> needs-you=<text|none>`. Parsed by `parseTickMarker()` in `src/lib/flywheel/tick-marker.ts`.
- **Tick message** — an assistant message in the flywheel transcript whose text contains a parseable tick marker. Only assistant messages count (same rule as `findLastTick()`).
- **Newest tick** — the last tick message in the transcript (`findLastTick()`); the server returns it as `status.lastTick`.
- **Needs-you line** — the `needs-you` value of a tick marker (`TickMarker.needsYou`, `null` for `none`).
- **Needs-you item** — one `;`-separated piece of a needs-you line, trimmed, empty pieces dropped. Example: `waive PAN-5095 test removal; PAN-5071 Worker deploy; PR #7 merge` has three items.
- **Item key** — `item.trim().toLowerCase()`. Two items are the same item when their keys are equal.
- **Unbroken run** — for an item in the newest tick: the newest tick plus every consecutive older tick message whose needs-you line also contains that item's key. The run ends at the first older tick message that lacks the item (a tick with `needs-you=none` lacks every item). Non-tick messages between ticks do not break a run.
- **First-raised tick** — the oldest tick message in an item's unbroken run. Its message is where the loop explained the item.
- **Needs-you block** — the warning-tinted block on the Flywheel page's Status tab (`data-testid="flywheel-needs-you"`).
- **Tick jump** — `FlywheelPage`'s `tickJump` state `{ messageId?, nonce }`, passed to `FlywheelConversationPane` → `ConversationPanel` `targetMessageId`. `MessagesTimeline` scrolls to that message and, when it is not loaded, pages older history with `loadOlderUntil(messageId)` (up to 100 pages of 75 rows, `useOlderHistory.ts` `LOAD_OLDER_UNTIL_MAX_PAGES`).
- **Pending question** — an unanswered AskUserQuestion in `conv-flywheel`, from `GET /api/conversations/pending-input`; decided by `resolveNeedsYouAction()` in `src/dashboard/frontend/src/lib/flywheelNeedsYou.ts`.

## Requirements

- **FR-1** The Needs-you block renders one row per needs-you item of the newest tick, in line order, duplicates (same key) shown once. An item absent from the newest tick has no row.
- **FR-2** In each row, issue IDs render as controls that call `onNavigateIssue(<id>)`, which opens the issue drawer.
- **FR-3** In each row, a PR reference renders as a link to that PR only when its repository is known: `owner/repo#<n>` links to `https://github.com/owner/repo/pull/<n>`; `PR #<n>` or `#<n>` links to the `pr.url` of an in-flight row with `pr.number === n`. Any other PR reference renders as plain text.
- **FR-4** Clicking a row outside a link (or pressing Enter/Space on the focused row) jumps the conversation pane to the item's first-raised tick message. When the first-raised message id is unknown, it jumps to the newest tick message.
- **FR-5** The server computes each item's first-raised tick from the transcript it already reads in `deriveFlywheelStatus()` and returns it as `status.lastTick.needsYouItems`. Nothing new is stored.
- **FR-6** A pending question keeps priority: clicking any row first runs `resolveNeedsYouAction()`; `reopen-question` reopens the dialog and does not jump.
- **FR-7** The header `NeedsYouIndicator` keeps its count and its reveal; the block keeps `data-testid="flywheel-needs-you"` on its outer element so the reveal's `querySelector` still finds it.
- **FR-8** The `/pan-flywheel` skill tells the loop to separate needs-you items with `; `, to keep an item's wording identical from tick to tick until it is resolved, and to write a PR outside the flywheel's project as `owner/repo#<n>`.
- **FR-9** `docs/FLYWHEEL.md` and `changelog.d/pan-5198.md` describe the new behavior.
- **NFR-1** The backward walk stops as soon as every item's run has ended, so the 5-second status poll does not re-parse the whole transcript when items are fresh.
- **NFR-2** One split and normalize implementation, in `@overdeck/contracts`, used by both the server and the frontend fallback.
- **NFR-3** `FlywheelStatusPane.tsx` and `FlywheelPage.tsx` stay well under 1000 lines (today 251 and 260); no allowlist change.

## Decisions

- **D-1 Server-side resolution, optional field.** `FlywheelLastTick` gains `needsYouItems?: FlywheelNeedsYouItem[]`. The server always sets it when there is a last tick. The field is optional so the frontend still renders when it is absent (an older server, or a test fixture): it then splits `needsYou` with the same contracts helper and uses the newest message id for every row. No new route.
- **D-2 PR links only when the repo is known (FR-3).** The report's own `PR #7` is an `overdeck-landing` PR; linking a bare `#7` to the flywheel project's repo would open an unrelated old overdeck PR. So bare references link only through an in-flight row's PR. The row click still reaches the message that names the repo, and FR-8 makes the loop qualify cross-repo PRs from now on. Qualified references always link to GitHub (the issue says "opens the PR on GitHub").
- **D-3 Issue-ID pattern.** `\b[A-Z]{2,}-\d+\b`, case-sensitive. Project issue prefixes are letters only (conventions.md, PAN-4860). This covers `PAN-`, `MIN-`, `KRUX-` and other projects the flywheel may drive, not only `PAN-`. A false match such as `UTF-8` opens a drawer for a missing issue; accepted.
- **D-4 Row markup.** The block becomes a `<div role="group" aria-label="Needs you" data-testid="flywheel-needs-you">` holding a `<ul>`. Each row is `<li role="button" tabIndex={0} data-testid="flywheel-needs-you-item">` with `onClick` and an `onKeyDown` for Enter and Space (same pattern as `components/CommandDeck/PipelineRow.tsx`). Issue IDs are `<button type="button" data-testid="flywheel-needs-you-issue">`; PR links are `<a target="_blank" rel="noreferrer" data-testid="flywheel-needs-you-pr">`. Both call `event.stopPropagation()` in `onClick` and `onKeyDown`, so using a link never also jumps.
- **D-5 Callback shape.** `FlywheelStatusPane`'s `onNeedsYouClick` changes from `() => void` to `(messageId: string | undefined) => void`. The pane resolves the per-row id (`firstRaisedMessageId ?? tick.messageId`); the page applies question priority, then jumps to the id it was given.
- **D-6 Run boundaries.** A run crosses tick-number resets (a restarted loop in the same conversation) because only presence in consecutive tick messages counts. When a run reaches the oldest readable tick message (the transcript file `resolveSessionFile()` returns, so a session rollover cuts history), that oldest tick is the first-raised tick.
- **D-7 Duplicates.** Within one line, a repeated item (same key) keeps its first spelling and renders once.
- **D-8 The CLI stays as is.** `pan flywheel status` keeps printing the joined needs-you line; `--json` output gains the new field through the shared deriver with no CLI code change.

```ts
/**
 * One `;`-separated item of the newest tick's needs-you line (PAN-5198), with
 * the oldest tick of the item's current unbroken run: the message that raised
 * it, which is where the loop explained it.
 */
export const FlywheelNeedsYouItem = Schema.Struct({
  text: Schema.String,
  firstRaisedTick: Schema.Number,
  /** The first-raised tick message's `createdAt`. */
  firstRaisedAt: Schema.String,
  /** The first-raised tick message's id, when the harness records one. */
  firstRaisedMessageId: Schema.optional(Schema.String),
})
export type FlywheelNeedsYouItem = typeof FlywheelNeedsYouItem.Type

/** Two items are the same item when their keys match. */
export function needsYouItemKey(text: string): string {
  return text.trim().toLowerCase()
}

/** Split a needs-you line on `;`: trimmed, empty pieces dropped, one per key. */
export function splitNeedsYouItems(needsYou: string | null | undefined): string[] {
  if (!needsYou) return []
  const seen = new Set<string>()
  const items: string[] = []
  for (const piece of needsYou.split(";")) {
    const text = piece.trim()
    const key = needsYouItemKey(text)
    if (!text || seen.has(key)) continue
    seen.add(key)
    items.push(text)
  }
  return items
}
```

```ts
/**
 * The newest tick's needs-you items, each with the oldest tick message of its
 * current unbroken run (PAN-5198). Walks tick messages newest first, using the
 * same assistant-only rule as `findLastTick`, and stops once every item's run
 * has ended. A run that reaches the oldest tick in `messages` ends there.
 */
export function resolveNeedsYouItems(messages: readonly TickMarkerMessage[]): FlywheelNeedsYouItem[] {
  type Seen = { tick: number; at: string; messageId?: string };
  let items: Array<{ text: string; key: string; first: Seen }> | null = null;
  const open = new Set<string>();
  for (let i = messages.length - 1; i >= 0; i -= 1) {
    const message = messages[i];
    if (!message || message.role !== 'assistant' || !message.text.includes(TICK_MARKER_PREFIX)) continue;
    const parsed = parseTickMarker(message.text);
    if (!parsed) continue;
    const here: Seen = { tick: parsed.tick, at: message.createdAt, ...(message.id ? { messageId: message.id } : {}) };
    if (items === null) {
      items = splitNeedsYouItems(parsed.needsYou).map((text) => ({ text, key: needsYouItemKey(text), first: here }));
      for (const item of items) open.add(item.key);
    } else {
      const keys = new Set(splitNeedsYouItems(parsed.needsYou).map(needsYouItemKey));
      for (const item of items) {
        if (!open.has(item.key)) continue;
        if (keys.has(item.key)) item.first = here;
        else open.delete(item.key);
      }
    }
    if (open.size === 0) break;
  }
  return (items ?? []).map(({ text, first }) => ({
    text,
    firstRaisedTick: first.tick,
    firstRaisedAt: first.at,
    ...(first.messageId ? { firstRaisedMessageId: first.messageId } : {}),
  }));
}
```

```ts
/**
 * Splits one flywheel needs-you item into text, issue-ID and PR segments
 * (PAN-5198). A PR links only when its repository is known: `owner/repo#n`
 * names it, or an in-flight row carries that PR number. A bare `#n` from
 * another repository stays text, because a guessed repo opens the wrong PR.
 */
import type { FlywheelInFlightRow } from '@overdeck/contracts';

export type NeedsYouSegment =
  | { kind: 'text'; text: string }
  | { kind: 'issue'; text: string; issueId: string }
  | { kind: 'pr'; text: string; url: string };

// Order matters: a qualified ref must win over its bare `#n` tail.
const REF_RE = /\b([A-Za-z0-9][\w.-]*\/[\w.-]+)#(\d+)\b|\bPR #(\d+)\b|(?<![\w/#])#(\d+)\b|\b([A-Z]{2,}-\d+)\b/g;

export function needsYouSegments(text: string, inFlight: readonly FlywheelInFlightRow[]): NeedsYouSegment[] { … }
```

Behavior of `needsYouSegments` (the executor writes the loop; the rules are fixed):
- Walk `REF_RE` matches with `matchAll`; text between matches becomes `text` segments; adjacent text merges; an input with no match returns one `text` segment.
- Group 1+2 (qualified) → `pr` with `url: https://github.com/${repo}/pull/${n}`.
- Group 3 (`PR #n`) or 4 (`#n`) → `pr` with the `url` of the first `inFlight` row whose `pr?.number === n`; when none, a `text` segment holding the matched text.
- Group 5 → `issue` with `issueId` = the match.
- `text` of every non-text segment is the exact matched substring.
