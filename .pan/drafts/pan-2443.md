# PAN-2443 — OTel GenAI semconv: OTLP ingestion layer for cross-harness telemetry

**Issue:** https://github.com/eltmon/overdeck/issues/2443 · **Author:** oversight conversation, 2026-07-06, from commissioned deep research (verified July 2026).
**Verified-Against:** main @ 40322cda2b.

## Glossary

- **gen_ai.\* semconv**: OpenTelemetry's Generative-AI semantic conventions — standardized span/metric/event/attribute names for LLM calls, tools, and agents. Spec repo: https://github.com/open-telemetry/semantic-conventions-genai. Status: EVERY item is `Development` (experimental); zero tagged releases.
- **OTLP**: the OpenTelemetry wire protocol; an *OTLP receiver* accepts telemetry over HTTP/gRPC.
- **Shim**: a mapping from a harness's custom telemetry namespace (`claude_code.*`, `codex.*`) to gen_ai attributes + our internal event shape.
- **Key attributes** (current spec): `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.usage.input_tokens` / `output_tokens` / `cache_read.input_tokens` / `cache_creation.input_tokens` / `reasoning.output_tokens`, `gen_ai.conversation.id` (correlation only — no session entity), `gen_ai.agent.id/name`, tool attrs, `invoke_agent`/`invoke_workflow` spans.
- **Stability gate**: `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` selects the post-v1.37 format; v1.36 is the migration baseline.

## Hard facts that shape the design (from research)

1. **No cost in the spec.** Token counts standardize; USD never does. All pricing (rate tables, subscription $0-marginal display, cache multipliers) stays in Overdeck (PAN-2387/2388 remain the pricing owners).
2. **Per-harness native emission today**: Gemini CLI ≈ conformant gen_ai (metrics + span attrs); **Claude Code emits `claude_code.*` incl. `claude_code.cost.usage` (USD) and `claude_code.api_request` events with cache splits** via `CLAUDE_CODE_ENABLE_TELEMETRY=1`; Codex CLI emits `codex.*` via `[otel]` config. Nobody but Gemini is conformant — shims required regardless.
3. **Churn risk is real**: two breaking reshapes already; agent/workflow conventions are the active frontier. Mitigation: pin one snapshot, confine names to the shim layer.

## Decisions

- **D1 — Ingest-first, emit-later.** Phase 1 is an OTLP receiver + shims feeding OUR store; emitting Overdeck's own gen_ai spans (pipeline stages as `invoke_workflow`/`invoke_agent`) is a separate later phase (W5) — valuable for external dashboards, not required for cost truth.
- **D2 — The receiver feeds the existing cost_events write door.** No parallel telemetry store (two-door tenet). OTLP-derived rows carry `source: otel` and a dedupe key (conversation.id + response.id / event timestamp) so parser-derived and ACP-derived (PAN-2442 usage_update) rows never double-count. One dedupe design shared across all three sources — define it once in `src/lib/costs/dedupe.ts`.
- **D3 — Claude Code native telemetry is adopted immediately** (independent of gen_ai conformance): launcher sets `CLAUDE_CODE_ENABLE_TELEMETRY=1` + OTLP endpoint at the local receiver; its `cost_usd` events become a primary cost source with the JSONL parser as reconciliation. This directly serves PAN-2388/2439 before any gen_ai standardization matters.
- **D4 — Pin the spec snapshot** (vendored constants file with the snapshot date + repo SHA); set `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` where we control emitters. All gen_ai attribute names live in one module.
- **D5 — Correlation contract**: we stamp `gen_ai.conversation.id` = Overdeck session id and `gen_ai.agent.name` = agent id on everything we can influence (env-configurable resource attrs), giving cross-harness joins in any OTel backend.

## Requirements

- FR-1: OTLP/HTTP receiver endpoint in the dashboard server (`/otel/v1/metrics`, `/otel/v1/logs`, `/otel/v1/traces` — accept protobuf+JSON), token-gated to localhost agents.
- FR-2: Shim modules: `claude-code-otel-shim` (claude_code.* → internal cost/telemetry events, incl. cost_usd passthrough), `gemini-otel-shim` (gen_ai native), `codex-otel-shim` (codex.* — model + conversation id + token counts). Each ≤ 200 lines, table-driven.
- FR-3: Launchers export telemetry env per harness when `telemetry.otel_ingest: true` (config, default off until verified): Claude Code vars, Codex `[otel]` config block, Gemini CLI flags.
- FR-4: Deduped ingestion into cost_events via the shared dedupe key (D2); reconciliation report (`pan admin costs reconcile`) comparing parser vs OTLP totals per session.
- FR-5 (phase W5, optional): Overdeck emits `invoke_workflow`/`invoke_agent` spans per pipeline stage through the standard OTel SDK to a configurable exporter.
- NFR-1: Receiver must be non-blocking (no execSync; bounded queue; drop-with-counter on overload — never stall the event loop).
- NFR-2: All gen_ai names confined to the shim/constants modules (grep-lintable).

## Work items

1. **Receiver (FR-1, NFR-1)** + fixture tests (protobuf + JSON payloads).
2. **Claude Code shim + launcher env (FR-2, FR-3, D3)** — the immediate cost win; acceptance ties to PAN-2439's $0-strip bug: the 24h strip shows real dollars from OTLP source.
3. **Dedupe + reconciliation (FR-4, D2)** — shared with PAN-2442's usage_update path; property test: same session ingested via parser AND OTLP yields identical totals, not doubled.
4. **Gemini + Codex shims (FR-2)** — Gemini trivial (native), Codex table-driven.
5. **Optional emission (FR-5)** — after the order-book run; gives Grafana/Langfuse dashboards.

## Acceptance criteria

- [ ] AC-1: A Claude Code agent session with telemetry on produces cost_events rows (source=otel) whose USD total matches the JSONL parser total within $0.01.
- [ ] AC-2: Dual-source session shows no double-count (reconcile report zero-delta).
- [ ] AC-3: A Gemini-CLI session's tokens appear with correct model + conversation correlation without any transcript parsing.
- [ ] AC-4: Receiver survives a 10k-event burst without event-loop p99 breach (fake timers/load fixture).
- [ ] AC-5: gen_ai names appear only in shim/constants modules.

## Intersecting repo rules

No execSync server-side; fake timers for retry/delay tests; two-door state rule (D2); file-size ratchet; comment-preserving config writes.

## Sequencing

W1–W3 can slot right after the current cost trio (PAN-2387/2388) lands — they share the dedupe design. W5 is discretionary.
