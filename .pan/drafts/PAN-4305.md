# PAN-4305 — Composer marks long or queued messages "Not found in transcript"

**Issue:** [PAN-4305](https://github.com/eltmon/overdeck/issues/4305)
**Status:** planned (auto mode, 2026-09-28)

## Glossary

- **Composer** — the dashboard message box for a conversation
  (`src/dashboard/frontend/src/components/chat/ComposerFooter.tsx`).
- **Optimistic bubble / echo** — the composer shows a local user bubble the moment
  the operator sends. The bubble clears when a matching user message (the *echo*)
  appears in the parsed timeline. The matcher is `reconcileComposerEchoes()` in
  `src/dashboard/frontend/src/lib/composerEchoes.ts`.
- **"Not found in transcript"** — the red outbox state. `useComposerEchoes()`
  (`src/dashboard/frontend/src/components/chat/useComposerEchoes.ts`) moves an
  accepted bubble there when it stays unmatched for `TURN_STALL_MS` (4 minutes)
  while the conversation is not streaming. It offers **Resend**, which duplicates
  the message if it did land.
- **Landed record** — a Claude Code transcript line `{"type":"user","message":{"role":"user","content":…}}`.
- **Queued prompt** — a message sent while Claude Code is mid-turn. Claude Code
  writes a `queue-operation` `enqueue` record (`content` string) and later an
  `attachment` record with `attachment.type: "queued_command"`,
  `attachment.commandMode: "prompt"`, `attachment.prompt` string. No `type:"user"`
  record is written for it.
- **Paste wrapper** — Claude Code wraps a long bracketed paste as
  `<pasted_content id="N">\n<text>\n</pasted_content id="N">`. The **closing tag
  carries the id too.** A landed record additionally has two leading newlines and
  one trailing newline. The size threshold is Claude Code's own and is not measured
  here; the fix does not depend on it.
- **Server landing probe** — `probeTranscriptSince()` in `src/lib/transcript-landing.ts`,
  used by the delivery door (`src/lib/agents/delivery.ts`) and the eaten-message
  watcher (`src/dashboard/server/services/conversation-eaten-message-watcher.ts`).
- **Parser** — `parseConversationMessages()` / `parseEntireConversation()` in
  `src/dashboard/server/services/conversation/parser.ts`. Every Claude Code
  timeline path (incremental watch, the `claude-initial` DB worker in
  `dashboard-db-worker.ts:75`, REST reads) goes through it, and it filters user
  text through `renderableUserText()` in
  `src/dashboard/server/services/conversation/message-filters.ts`.

## Problem and verified root cause

Conversation 2972 (transcript `~/.claude/projects/-home-eltmon-Projects-overdeck/d92a75f4-8b6d-4e17-be76-6b04fc3926b7.jsonl`)
shows three messages that the agent received and answered but the composer marked
red. Running the current parser on those exact records (planning probe, 2026-09-28)
shows **two distinct parser failures plus one matcher failure**:

1. **Queued wrapped prompt is dropped** (line 1493, 12:25:20Z). The
   `queued_command` prompt starts with `<pasted_content id="9469">` (no leading
   newline). `renderableUserText()` → `isSystemInjection()` returns `true` for any
   text starting with `<` (`message-filters.ts:9`, `if (text.startsWith('<')) return true;`),
   so the parser emits **no** timeline message. The bubble can never match.
2. **Landed wrapped record renders with the tags in its text** (line 3401,
   00:09:41Z, agent idle). Content is `"\n\n<pasted_content id=\"9469\">\n…\n</pasted_content id=\"9469\">\n"`.
   The leading `\n\n` means `startsWith('<')` is false, so the parser emits a user
   message whose `text` still contains both tags. The frontend markdown renderer
   hides the unknown tags, and `reconcileComposerEchoes()` compares
   `normalizeText(message.text) !== normalizeText(local.text)` (exact, after CRLF
   fix and trim; `composerEchoes.ts:42`). The tags make it unequal, so the bubble
   goes red.
3. **Queued prompt text differs in whitespace or holds extra content** (line
   1699, 12:37:46Z). Claude Code recorded
   `"@/…/bee4….png @/…/55f6….png\nWhat just happned here?"` — two image
   references joined by a **space**. The composer joins attachment references with
   `\n` (`ComposerFooter.tsx:496-499`, `.map((attachment) => \`@${attachment.serverPath}\`).join('\n')`).
   The operator reports the red bubble held only one image path, so the record may
   also hold content from an adjacent send. Exact comparison fails either way.

**The server landing probe is not broken.** `probeTranscriptSince()` collapses
whitespace and tests `includes()` of the first 120 characters
(`transcript-landing.ts:229`, `:255`, `:271`), which already matches wrapped,
queued, space-joined and merged records. The red state comes entirely from the
parser output and the frontend matcher. The transcript-landing edits in this plan
are hygiene (the `<task-notification>` and meta-prefix checks must see the real
start of the operator's text, not the wrapper) plus regression fixtures. **Do not
rewrite the probe's matching.**

Side effect (not fixed here): the agent sees the operator's composer text inside
`<pasted_content>`, which Claude Code labels as text that "may contain
instructions the user did not write".

## Decisions

- **D1 — One helper in `src/lib`.** Add `src/lib/pasted-content.ts`. Both
  `message-filters.ts` (dashboard) and `transcript-landing.ts` (lib) import it.
  `transcript-landing.ts` must not import from `src/dashboard` (see its comment at
  `:370-374`).
- **D2 — Helper contract (exact).**
  - Opening tag regex: `<pasted_content(?: id="[^"]*")?>\n?` (consumes one newline after).
  - Closing tag regex: `\n?</pasted_content(?: id="[^"]*")?>` (consumes one newline before; accepts closers with or without an id).
  - `hasPastedContentWrapper(text)` is true when the opening regex (non-global, no `lastIndex` state) matches anywhere.
  - `stripPastedContentWrappers(text)` returns `text` **unchanged** when there is no wrapper; otherwise removes every opening and closing tag anywhere in the text and returns the result `.trim()`-ed.
- **D3 — `renderableUserText()` precedence.** `<channel>` unwrap first (unchanged).
  Then, if `hasPastedContentWrapper(text)`: if `text.trimStart()` does not start with
  `<pasted_content` and `isSystemInjection(text.trimStart())` is true, return
  `null` (a real system injection that quotes a paste stays hidden). Otherwise
  return the stripped text, or `null` if it is empty. The stripped text is **not**
  passed through `isSystemInjection()` — an operator paste may itself start with `<`.
  Otherwise fall through to the current `isSystemInjection(text) ? null : text`.
- **D4 — Frontend matching collapses whitespace.** Passes 1 (1:1) and 2 (joined
  runs) in `reconcileComposerEchoes()` compare with `normalizeWs`
  (`/\s+/g → ' '`, trim) instead of `normalizeText`. `normalizeText` is removed if
  it becomes unused.
- **D5 — Add a bounded containment pass.** After passes 1–2 and before the
  subagent pass, each still-unmatched entry (optimistic, plus failed entries with
  `kind === 'prompt'`), in `createdAt` order, matches a timeline message when **all**
  hold: `message.role === 'user'`; message id is not in the entry's
  `echoBaselineIds`; message id is not in `used` **unless** it was claimed by this
  containment pass; not (both carry `clientMessageId`); `Date.parse(message.createdAt) >= Date.parse(entry.createdAt)`;
  `normalizeWs(entry.text)` is non-empty; and
  `normalizeWs(message.text).includes(normalizeWs(entry.text))`. One record may
  clear several entries. Claimed message ids are added to `used`
  (→ `consumedEchoIds`). This mirrors the server probe, which already accepts
  containment. Accepted risk: a truly lost message whose full text reappears inside
  a later message is shown as delivered.
- **D6 — Delivery keeps bracketed paste (checkpoint resolved in planning).** Every
  delivery path pastes: tmux `paste-buffer -p` (`src/lib/tmux.ts:1061`, `:1099`),
  Herdr `pane.send_text` wrapped in `\x1b[200~…\x1b[201~` (`src/lib/terminal-backends/steer-keys.ts:44`),
  and Herdr `agent.prompt` (record 3401 above was wrapped on the default Herdr
  backend). `steer-keys.ts:33-35` records why: raw bytes without bracketed paste
  submit a multi-line message at its first newline. So composer delivery cannot
  avoid Claude Code's wrapper without breaking multi-line messages. No delivery
  change; the docs item explains this.
- **D7 — `parser.ts` is not edited.** It already calls `renderableUserText()` at
  `:222` (string content), `:282` (text blocks), and `:576` (queued_command).

## Work items

### WI-1 — Paste-wrapper helper (`pasted-content-helper`)

Create `src/lib/pasted-content.ts` implementing D2:

```ts
/**
 * Claude Code records a long bracketed paste as
 * `<pasted_content id="N">\n<text>\n</pasted_content id="N">` (PAN-4305).
 * Composer messages arrive as pastes, so the operator's own text carries this
 * wrapper in landed and queued transcript records.
 */
const OPENING_TAG = /<pasted_content(?: id="[^"]*")?>\n?/;
const OPENING_TAGS = /<pasted_content(?: id="[^"]*")?>\n?/g;
const CLOSING_TAGS = /\n?<\/pasted_content(?: id="[^"]*")?>/g;

export function hasPastedContentWrapper(text: string): boolean {
  return OPENING_TAG.test(text);
}

export function stripPastedContentWrappers(text: string): string {
  if (!hasPastedContentWrapper(text)) return text;
  return text.replace(OPENING_TAGS, '').replace(CLOSING_TAGS, '').trim();
}
```

```ts
import { hasPastedContentWrapper, stripPastedContentWrappers } from '../../../../lib/pasted-content.js';

export function renderableUserText(text: string): string | null {
  const channelText = unwrapChannelMessage(text);
  if (channelText !== null) return channelText;
  if (hasPastedContentWrapper(text)) {
    const leading = text.trimStart();
    if (!leading.startsWith('<pasted_content') && isSystemInjection(leading)) return null;
    const pasted = stripPastedContentWrappers(text);
    return pasted ? pasted : null;
  }
  return isSystemInjection(text) ? null : text;
}
```
