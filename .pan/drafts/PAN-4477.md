# PAN-4477 — Shared Sessions v0 (slice 6): read-only terminal channel

**Issue:** [PAN-4477](https://github.com/eltmon/overdeck/issues/4477) · **Parent PRD:** `.pan/drafts/pan-658.md` (rev 3), *Default surface & terminal toggle (FR-9)*, *Transport & Wire Format*, *Reuse: the terminal-sharing primitive* · **Depends on:** [PAN-4475](https://github.com/eltmon/overdeck/issues/4475) (viewer surface, merged on `main` as `5d941630c45`).

Planned in `pan plan --auto` mode on 2026-11-03 against `main` at `0016ed23e4a`. Every reference below was read from that tree.

## Glossary

- **Host / data owner** — the Overdeck dashboard server that owns the shared conversation. It runs the `PeerHub`.
- **Viewer** — an admitted participant's browser, rendering `/#/shared/<code>` (`SharedConversationView`).
- **PeerHub** — `src/dashboard/server/sharing/peer-hub.ts`: one werift `RTCPeerConnection` per eligible viewer, five labelled data channels (`control`, `conversation`, `drafts`, `terminal`, `presence`).
- **Negotiated peer** — a peer whose viewer hello passed `negotiateHello` (`PeerEntry.helloState === 'negotiated'`). Only negotiated peers receive content.
- **Envelope** — `SharedEnvelope { v, ch, streamId, seq, t, payload }` (`packages/contracts/src/sharing.ts` line 123), encoded and fragmented by `encodeSharedMessage`, reassembled by `SharedChannelReader` (`packages/contracts/src/sharing-wire.ts`).
- **Terminal watch** — the viewer's request, sent on `control`, to start (`watch: true`) or stop (`watch: false`) receiving the host terminal. New in this slice.
- **Terminal bridge** — new `src/dashboard/server/sharing/terminal-bridge.ts`. Turns one watch into a stream of `TerminalPayload`s from whichever terminal backend holds the conversation's terminal.
- **Terminal backend** — Herdr (the default) or tmux (`terminal.backend: tmux`). See `docs/TERMINAL-BACKENDS.md`.
- **Herdr observe stream** — `observeTerminal(terminalId)` in `src/lib/terminal-backends/herdr-stream.ts` line 240: a read-only `herdr terminal session observe` child. Many may run on one terminal. Its first frame is a full snapshot. It has no write method (`TerminalObservation`, `src/lib/terminal-backends/types.ts` line 199).
- **PTY hub** — `PtyHub` in `src/dashboard/server/pty-hub.ts`: one `tmux attach-session` PTY per tmux session, shared by every `/ws/terminal` WebSocket client of that session. Registry `activePtyHubs`.
- **Hub listener** — new: a non-WebSocket consumer of a PTY hub's output (`PtyHubListener`). The terminal bridge's tmux path is one.
- **Client size** — the size a tmux *client* must have so the window keeps its size: window width × (window height + status lines).
- **`TerminalFrame`** — the existing backend-neutral frame union in `src/lib/terminal-backends/types.ts` line 192: `snapshot {cols, rows, data}`, `output {data}`, `size {cols, rows}`, `exit {code}`.

## Problem

PAN-4474 created the `terminal` data channel on every peer connection but sends nothing on it, and PAN-4475's viewer gives it no listener. The parent PRD's FR-9 requires a viewer to toggle to a **read-only** view of the host's live terminal, with viewer keystrokes structurally unable to reach the host shell. This slice delivers that toggle end to end: host source, wire payloads, viewer peer, and viewer UI.

## Correction to the parent PRD (decided here)

The parent PRD (*Reuse: the terminal-sharing primitive*) and the issue body say the bridge "subscribes to the `pty-hub.ts` byte stream as an additional consumer". That was written when tmux was the only backend. Two facts on `main` make it incomplete:

1. **Herdr is the default backend and has no PTY hub.** `serveHerdrTerminal` in `src/dashboard/server/ws-terminal.ts` (search `function serveHerdrTerminal`) gives every WebSocket client its own `HerdrTerminalProcess`; `activePtyHubs` is never populated on a Herdr host.
2. **A tmux PTY hub exists only while a `/ws/terminal` tab has the session open.** `ws-terminal.ts` creates it inline (search `activePtyHubs.set(sessionName, hub)`) and `removeClientFromHub` (`pty-hub.ts` line 111) tears it down and kills the PTY when the last WebSocket client leaves (line 120, `if (hub.clients.size === 0)`).

**Decision D-1:** the terminal bridge resolves the conversation's terminal on each watch and uses:
- **Herdr:** one `observeTerminal(terminalId)` per watching viewer. Read-only by construction (no write method exists), and each stream starts with its own full snapshot.
- **tmux:** the PTY hub, as the issue specifies, through a new hub-listener seam. If no hub exists, the bridge creates one at the window's client size so watching does not resize the host window.

**Rejected alternative (recorded):** a separate `tmux attach-session -r -f ignore-size` client per share. Probed live on tmux 3.4 (2026-11-03, throwaway `-L probe4477*` sockets): an `ignore-size` client does not resize the window while a normal client is attached, **but when it is the only client the window takes its size**, and when a normal client later leaves, the window snaps back to the read-only client's size. That is a host-visible resize the hub-listener approach avoids, and it would ignore the issue's explicit instruction.

## Requirements

### Functional

- **FR-1** An admitted, connected viewer can switch between a **Conversation** view and a **Terminal** view. The Terminal view renders the host terminal of the shared conversation live.
- **FR-2** The host sends terminal content to a viewer only while that viewer's terminal watch is on. The viewer turns it on when the Terminal view mounts and off when it unmounts.
- **FR-3** The terminal is read-only by construction: the host subscribes to no inbound message on the `terminal` channel; the terminal bridge and every terminal source expose no write method; the viewer's xterm is created with `disableStdin: true` and registers no `onData` handler; the viewer never calls `send` on the `terminal` channel.
- **FR-4** Only negotiated peers receive `terminal` envelopes. A `terminal-watch` that arrives before the viewer hello negotiated, or after a failed hello, is ignored.
- **FR-5** Each watch start delivers a `snapshot` first, then `output` and `size` payloads. A conversation with no live terminal gets `unavailable terminal_not_found`. A terminal that exits after its snapshot gets `unavailable terminal_ended`.
- **FR-6** On a Herdr host the source is one observe stream per watching viewer, closed when the watch stops or the peer closes. On a tmux host the source is a hub listener on the session's PTY hub; a hub the bridge created is torn down when its last listener and last WebSocket client are both gone.
- **FR-7** A viewer whose peer renegotiates (a new host offer) while its Terminal view is open sends `terminal-watch true` again after the new hello and receives a fresh snapshot.

### Non-functional

- **NFR-1** Existing `/ws/terminal` clients behave as before while no viewer watches: the existing tests in `src/dashboard/server/__tests__/pty-hub.test.ts`, `ws-terminal-auth.test.ts`, `ws-terminal-heartbeat*.test.ts` and `ws-terminal-herdr-snapshot.test.ts` pass with their existing cases unmodified. Input routing (`inputClient`), coalescing, the ready gate and teardown-on-last-client (when no listener remains) are unchanged. One deliberate difference while a viewer watches a tmux terminal that no tab had open: the bridge's hub already exists, so the host's first tab takes the existing-hub path (viewport snapshot or empty snapshot plus resize), exactly like a second tab does today, instead of the 500-line fresh snapshot. This is accepted; do not "fix" it.
- **NFR-2** The wire format stays version 1 and changes additively: an older host ignores `terminal-watch` (`onControlMessage` returns on any non-`hello` kind today), and an older viewer ignores the `terminal` channel (no listener today). `packages/contracts/src/sharing.ts` stays type-only with no `import`.
- **NFR-3** Nothing logs terminal bytes, snapshot data or watch requests.
- **NFR-4** Watching never resizes the host's tmux window by itself: a bridge-created hub spawns its PTY at the client size (window height + status lines).
- **NFR-5** Repo rules hold: async only (no `execSync`); fake timers for any delay-based test; no `skipIf`, no `.only`, no test that reads source files; a herdr child per watching viewer is bounded by the room cap (50 participants).
- **NFR-6** The documentation names the toggle, the read-only guarantee and the two backend sources (WI-11).

## Decisions

- **D-1** Backend-specific sources (see *Correction*).
- **D-2 Toggle goes on `control`.** `control` is the only channel the host reads. New `ControlPayload` variant `{ kind: 'terminal-watch'; watch: boolean }`. The `terminal` channel stays host → viewer only.
- **D-3 Terminal content is enveloped.** `terminal` messages are ordinary `SharedEnvelope`s with a `TerminalPayload`, so `seq` gap detection, fragmentation (a large snapshot) and the `ChannelWriter` backpressure apply unchanged. The parent PRD's "raw tmux bytes" means the payload `data` is the raw terminal output string.
- **D-4 `TerminalPayload` mirrors `TerminalFrame`** except `exit`, which becomes `unavailable { reason: 'terminal_ended' }`:
  `snapshot {cols, rows, data}` · `output {data}` · `size {cols, rows}` · `unavailable {reason: 'terminal_not_found' | 'terminal_ended'}`.
- **D-5 Resolution per watch.** The bridge resolves `conversationId` (the conversation name) → `conv.tmuxSession` through `runDashboardDbJob('getConversationByName', name)` (the same call `resolveClaudeSessionFile` makes in `conversation-bridge.ts`), then `resolveHerdrTerminalId(tmuxSession)` (`services/terminal-service.ts` line 193) → Herdr, else `sessionExists(tmuxSession)` → tmux, else missing. No respawn wait in v0: a viewer re-toggles to retry.
- **D-6 Herdr observe opens without `--cols/--rows`,** so frames come at the PTY's own size. Verified live on 2026-11-03: a bare `herdr --session overdeck terminal session observe term_65f5f45d57e1134` first frame reported `width 120, height 40`, matching that pane's `viewport_rows: 40` from `herdr pane get`, while the same observe with `--cols 50 --rows 10` reported `50×10`. (Herdr's agent name for a conversation is its `conv-<name>` tmux session name, confirmed in the same `agent list`.) No `\x1b[?2004h` prefix (`HERDR_SNAPSHOT_MODES`): that exists for paste input, and a viewer never inputs.
- **D-7 A Herdr viewer does not follow a host resize** until it re-toggles (an observe stream keeps its opening size, `docs/TERMINAL-BACKENDS.md` line 874). A tmux viewer does follow: the hub notifies listeners of every hub resize.
- **D-8 Watch is idempotent per peer.** A second `watch: true` while attached is ignored; `watch: false` while not attached is ignored; a non-boolean `watch` is ignored.
- **D-9 Terminal channel overflow** uses the existing `ChannelWriter` rule: a peer whose queued content passes 64 Mi characters is closed (`WRITER_MAX_QUEUED_CHARS`), and the viewer sees "Connection to the host was lost." with **Reconnect**. No terminal-specific drop-and-resnapshot in v0.
- **D-10 The viewer xterm sizes to the host,** never to its container: no `FitAddon`. The container scrolls when the host grid is larger than the panel. The palette comes from `useColorTheme` and `useTheme` exactly like `XTerminal.tsx` (lines 101–114); `XTerminal.tsx` itself is not modified (it is on the file-size allowlist).
- **D-11 The toggle lives in `SharedConversationView`'s admitted screen,** as two buttons (**Conversation**, **Terminal**) with `aria-pressed`, shown once the peer is connected. Default: Conversation (parent PRD: the conversation panel is the default surface).
- **D-12 Terminal data bypasses React state.** `useSharedJoin` exposes `watchTerminal(listener): () => void`; payloads go straight from `WebRtcViewer.onTerminal` to the registered listener, which writes to xterm.

### WI-4 — `subscribeToTmuxHub`: a read-only tmux source over the hub (item `tmux-hub-subscribe`) · Traces FR-3, FR-5, FR-6, NFR-4

Add to `src/dashboard/server/pty-hub-attach.ts`:
```ts
export interface TmuxHubDeps {
  readonly hubs: Map<string, PtyHub>;
  sessionExists(sessionName: string): Promise<boolean>;
  /** Window width and height + status lines, from `display-message -p '#{window_width},#{window_height},#{status}'`. */
  clientSize(sessionName: string): Promise<{ cols: number; rows: number } | null>;
  /** Visible-pane capture with escape sequences: capturePane(sessionName, 0, { escapeSequences: true }). */
  captureViewport(sessionName: string): Promise<string>;
  spawn(sessionName: string, cols: number, rows: number): pty.IPty;
}
export const productionTmuxHubDeps: TmuxHubDeps;
/** Streams a tmux session's hub as TerminalFrames; null when the session does not exist. The subscription has no write method. */
export async function subscribeToTmuxHub(
  sessionName: string,
  onFrame: (frame: TerminalFrame) => void,
  deps?: TmuxHubDeps,
): Promise<{ close(): void } | null>;
```
Steps:
1. Hub lookup `deps.hubs.get(sessionName)`. If none: `await deps.sessionExists` → false ⇒ return `null`. `await deps.clientSize` → null ⇒ return `null`. Re-check `deps.hubs.get(sessionName)` **synchronously** after the awaits (ws-terminal may have created one); if still none, build `{ pty: null, clients: new Set(), cols, rows, pendingInput: [], inputClient: null, clientStates: new Map() }`, `deps.hubs.set(...)`, then `attachHubPty(deps.hubs, sessionName, hub, deps.spawn(sessionName, cols, rows))`.
2. Register a listener **before** capturing: until the snapshot is sent, `onData` appends to a local `pending` array and the last `onSize` is remembered; after, they forward as `output` / `size` frames. `onExit` forwards `{ kind: 'exit', code: null }`.
3. `const data = await deps.captureViewport(sessionName)` (a failed capture yields `''`). Emit `{ kind: 'snapshot', cols: hub.cols, rows: hub.rows, data }`, then one `output` frame with `pending.join('')` if non-empty. A size change seen while pending is applied by reading `hub.cols/rows` at snapshot time, so no separate `size` frame is needed then.
4. `close()` calls `removeHubListener(deps.hubs, sessionName, hub, listener)` once, with the hub object captured in step 1; later calls do nothing; no frame is emitted after `close()`.
`clientSize` production: `tmuxExecAsync(['display-message', '-p', '-t', sessionName, '#{window_width},#{window_height},#{status}'])`; status `off` ⇒ +0, `on` ⇒ +1, a digit `n` ⇒ +n; invalid ⇒ null.
Never call `pty.write` or `pty.resize`.

Tests in `pty-hub-attach.test.ts` (fake deps, fake `IPty`, fake timers): no hub + missing session ⇒ `null` and `spawn` not called; no hub ⇒ `spawn` called once with the client size (e.g. window 100×30 + status on ⇒ 100×31) and the hub is registered with `inputClient === null`; an existing hub ⇒ `spawn` not called, snapshot uses the hub's dims; output that arrives during the capture is delivered after the snapshot, in order; `notifyHubSize` after the snapshot ⇒ a `size` frame; `close()` on a bridge-created hub with no clients kills the PTY and unregisters the hub; the fake PTY's `write` and `resize` spies have zero calls across the whole suite.

### WI-5 — `TerminalBridge` (item `terminal-bridge`) · Traces FR-3, FR-5, FR-6, NFR-3

New file `src/dashboard/server/sharing/terminal-bridge.ts`, modelled on `ConversationBridge`'s shape.
```ts
export interface TerminalSink { send(payload: TerminalPayload): void }
export type TerminalTarget =
  | { readonly kind: 'herdr'; readonly terminalId: string }
  | { readonly kind: 'tmux'; readonly sessionName: string }
  | { readonly kind: 'missing' };
export interface TerminalBridgeDeps {
  resolveTarget(conversationName: string): Promise<TerminalTarget>;
  observeHerdr(terminalId: string): TerminalObservation;
  subscribeTmux(sessionName: string, onFrame: (frame: TerminalFrame) => void): Promise<{ close(): void } | null>;
}
export class TerminalBridge {
  constructor(conversationName: string, deps: TerminalBridgeDeps);
  /** Starts one read-only stream for this sink; resolves to its detach function. */
  attach(sink: TerminalSink): Promise<() => void>;
  /** Detaches every sink; later attaches return a no-op detach and send nothing. */
  close(): void;
}
export function productionTerminalBridgeDeps(): TerminalBridgeDeps;
export function terminalPayloadOf(frame: TerminalFrame, sawSnapshot: boolean): TerminalPayload;
```
Behaviour per attach:
- `resolveTarget` throws or answers `missing` ⇒ `sink.send({ kind: 'unavailable', reason: 'terminal_not_found' })`, return a no-op detach.
- `herdr` ⇒ `observeHerdr(terminalId)`; pump `frames` with `for await`; map `snapshot` → `snapshot`, `output` → `output`, `size` → `size`; `exit` (or the iterator ending) ⇒ `unavailable` with `terminal_not_found` if no snapshot was seen yet, else `terminal_ended`, then stop. Detach ⇒ `observation.close()` and stop delivering.

## Non-goals

- Viewer input to the host terminal in any form, including for contributors or the controller.
- A Herdr viewer following a host resize without re-toggling (D-7).
- Terminal scrollback history beyond the snapshot (tmux: visible viewport; Herdr: the full frame).
- Sharing any terminal other than the shared conversation's own (`conv.tmuxSession`): no companion terminals, no agent panes.
- Waiting out a conversation respawn (switch-model, resume) during a watch; the viewer re-toggles.
- Terminal-specific overflow recovery (D-9).
- Linked-machine (`@<machine>`) conversations as a share scope.
- Any change to the share Worker (`services/share/`).
