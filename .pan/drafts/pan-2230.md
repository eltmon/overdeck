# PAN-2230 — Circular-dependency ratchet (madge --circular baseline) wired into lint

**Epic:** A (Stop the bleeding — ratchets) · see [`docs/CODEBASE-HEALTH-ROADMAP.md`](../../docs/CODEBASE-HEALTH-ROADMAP.md)
**Issue:** https://github.com/eltmon/overdeck/issues/2230
**Executor:** normal pipeline (work agent), NOT handoff orchestration.
**Planning mode:** `pan plan --auto` — no interactive Q&A; inferred defaults recorded in `## Auto Decisions` below and in `plan.autoDecisions[]`.

This is the fourth Epic-A ratchet, a direct sibling of **A3** (`docs/codebase-health/A3-file-size-guard.md`). It installs a mechanical guard so import cycles can only **shrink**, never grow. It does NOT break any existing cycle — cycle-breaking is follow-up work the ratchet then protects.

---

## Glossary

- **Import cycle / circular dependency** — a set of modules that (transitively) import each other, e.g. `a.ts → b.ts → a.ts`. Circular ESM imports are why the dashboard server can only run from prebuilt `dist/` (Node strict ESM rejects `require()` of an ES module in a cycle; `tsx`/source-mode fails). This is a standing dev-loop tax and the root of the stale-dist incident class (the dashboard running day-old code while an operator debugs "the pipeline").
- **[madge](https://github.com/pahen/madge)** — a dependency-graph tool with a `--circular` mode that reports every cycle. `--json` emits an array of cycles, each an array of module paths in cycle order. Resolves TypeScript via the local `typescript` dep.
- **Baseline** — `scripts/circular-deps-baseline.txt`: the canonical list of cycles present today, **one cycle per line**. A cycle may be **removed** from the baseline but no NEW cycle may appear; this is the ratchet. (Set-of-lines semantics, exactly like the `eslint-any-allowlist.json` half of the ratchet audit — not the `<count> <path>` semantics of the file-size baseline.)
- **Canonical cycle** — a cycle rendered rotation-invariantly: rotate the member list so its lexicographically-smallest path is first (preserving cyclic order), then join with `" > "`. Two madge runs that report the same cycle starting at different members produce the same canonical line, so the baseline is stable across runs.
- **Guard-script convention** — this repo enforces invariants with bash scripts wired into `npm run lint` (`scripts/lint-file-size.sh`, `scripts/lint-source-introspection.sh`, `scripts/lint-overdeck-boundaries.sh`, …). A4 adds one more in exactly that style, and — like the file-size baseline — is audited by `scripts/lint-ratchet-audit.sh`.
- **Ratchet audit** — `scripts/lint-ratchet-audit.sh` (wired into `npm run lint` and `.husky/pre-push`) requires an issue reference (`[A-Z]+-[0-9]+` or `#[0-9]+`) in the commit message whenever a ratchet baseline/allowlist is *increased*. Lowering is always free. A4 extends it to cover the circular baseline.

---

## Problem

No madge / dependency-cruiser exists anywhere in the repo, and nothing stops new import cycles from appearing. The dashboard's circular ESM imports already force the dist-only run posture. This issue installs the ratchet: **`npm run lint` fails if a new import cycle appears**, and the committed baseline lists today's cycles so that removing one lowers the baseline. It does NOT break any cycle (Epic B / follow-up).

---

## Requirements

**FR-1** — A new guard `scripts/lint-circular-deps.sh` exits 1 when a cycle exists under `src/` that is **not** in the committed baseline, and names the new cycle.
**FR-2** — The guard exits 1 ("stale baseline") when a baselined cycle no longer exists, and directs the user to `--update`. `--update` drops resolved cycles from the baseline (shrink-only; never adds/raises).
**FR-3** — The guard exits 0 on this branch with a committed `scripts/circular-deps-baseline.txt` capturing the cycles madge currently detects under `src/`, one canonical cycle per line, sorted.
**FR-4** — `--regen` writes the full current cycle set to the baseline (the audited "accept new cycles" escape hatch).
**FR-5** — The guard is wired into `npm run lint` as `lint:circular`, in the chained `lint` script (before `lint:ratchet-audit`, so the audit runs last).
**FR-6** — `scripts/lint-ratchet-audit.sh` audits `scripts/circular-deps-baseline.txt`: a commit that adds a cycle line without an issue reference fails; the same addition with an issue reference passes.

**NFR-1** — Pure addition: the only changes are the new script, the new baseline file, `package.json`, `scripts/lint-ratchet-audit.sh`, `bun.lock`, and docs. No production `src/**` code is modified (no cycle is broken here).
**NFR-2** — Deterministic: madge output is canonicalized and `sort`ed so the baseline is stable run-to-run. No `execSync` concern (standalone bash + a `node -e` JSON transform).
**NFR-3** — Excludes tests (`*.test.ts`, `*.test.tsx`, `**/__tests__/**`) and `.d.ts` files; `node_modules` is excluded by madge by default.

## Auto Decisions (recorded, `--auto` mode)

- **madge over dependency-cruiser.** The issue offers either; madge is purpose-built for `--circular`, has a clean `--json` cycle array, needs no config file, and resolves TS via the existing `typescript ^5.3.2`. dependency-cruiser is a heavier configured tool. A simple bash guard matches the A3 ethos.
- **Scope = all of `src/` (`.ts,.tsx`), not just the dashboard.** The motivating cycles are in `src/dashboard/server`, but a repo-wide ratchet is strictly more valuable and mirrors the file-size guard's `src/` scope. Frontend path-alias imports madge can't resolve are simply skipped (never false-positive), so alias under-detection is acceptable for a *regression* ratchet — see hazard H2.
- **Baseline unit = one canonical cycle per line (set semantics).** A cycle is a list of files, not a single file, so the file-size `<count> <path>` shape doesn't fit; the `eslint-any-allowlist.json` set-of-lines shape (also audited by ratchet-audit via `comm`) does.
- **Ratchet-audit integration is in-scope.** "Same pattern as the file-size guard" — and the file-size baseline IS audited by ratchet-audit. Including it keeps the baseline honest (no silent `--regen` inflation).

## Proposal

### WI-1 — Add `madge` dev dependency (bead `add-madge-dep`)

Add `madge` to `devDependencies` in `package.json` and run `bun install` from the workspace root (updates `bun.lock`; hardlinked, ~2s). Do not pin an exotic version — take the current stable `^8` line.

Verify: `node_modules/.bin/madge --version` exits 0.

### WI-2 — Guard script + baseline (bead `guard-script-and-baseline`) — **requiresInspection**

Create `scripts/lint-circular-deps.sh` following the `lint-source-introspection.sh` shape (it already has the `check` / `--update` / `--regen` set-of-lines pattern this needs):

```bash
#!/usr/bin/env bash
#
# lint-circular-deps.sh — ratchet against NEW circular imports (A4, codebase health).
# madge --circular finds import cycles under src/. A baselined cycle may be REMOVED
# but no NEW cycle may appear; this is the ratchet. Baseline is
# scripts/circular-deps-baseline.txt (one canonical cycle per line, sorted).
# Check mode fails on new cycles and on stale baseline entries (cycles that no
# longer exist). Run with --update to drop resolved cycles (shrink-only, never adds).
# Run with --regen to accept the full current set (audited by lint-ratchet-audit.sh —
# adding a cycle line needs an issue reference in the commit message).
set -euo pipefail

MODE=check
case "${1:-}" in
  --update) MODE=update ;;
  --regen)  MODE=regen ;;
  "")       MODE=check ;;
  *) echo "usage: bash scripts/lint-circular-deps.sh [--update|--regen]" >&2; exit 2 ;;
esac

cd "$(dirname "$0")/.."

BASELINE="scripts/circular-deps-baseline.txt"
MADGE="node_modules/.bin/madge"

# Emit one canonical cycle per line, sorted. Each cycle from madge is an array of
# paths in cycle order; rotate to start at the lexicographically-smallest member
# (cyclic order preserved) and join with " > " so the line is rotation-invariant.
scan_current() {
  "$MADGE" --circular --json --extensions ts,tsx \
    --exclude '(\.test\.tsx?$|\.d\.ts$|/__tests__/)' src 2>/dev/null \
  | node -e '
      let d=""; process.stdin.on("data",c=>d+=c).on("end",()=>{
        const cycles = JSON.parse(d || "[]");
        const canon = cycles.map(cy => {
          let mi = 0;
          for (let i = 1; i < cy.length; i++) if (cy[i] < cy[mi]) mi = i;
          return cy.slice(mi).concat(cy.slice(0, mi)).join(" > ");
        });
        canon.sort();
        for (const c of canon) console.log(c);
      });
    '
}

if [[ "$MODE" == "regen" ]]; then
  scan_current > "$BASELINE"
  echo "✓ circular-deps baseline regenerated: $(wc -l < "$BASELINE") cycle(s)"
  exit 0
fi

if [[ ! -f "$BASELINE" ]]; then
  echo "✖ missing $BASELINE — run: bash scripts/lint-circular-deps.sh --regen" >&2
  exit 1
fi

tmp_current=$(mktemp)
scan_current > "$tmp_current"

if [[ "$MODE" == "update" ]]; then
  # keep only baseline cycles that still exist (shrink-only)
  kept=$(comm -12 <(sort "$BASELINE") <(sort "$tmp_current"))
  printf '%s\n' "$kept" | sed '/^$/d' | sort > "$BASELINE"
  before=$(sort -u <(cat) < /dev/null; :)  # no-op guard for set -u
  rm -f "$tmp_current"
  echo "✓ circular-deps baseline updated: $(wc -l < "$BASELINE") cycle(s) remain"
  exit 0
fi

# check mode
fail=0; stale=0
# new cycles present now but not baselined
while IFS= read -r c; do
  [[ -z "$c" ]] && continue
  echo "✖ new import cycle (not baselined): $c"
  fail=1
done < <(comm -13 <(sort "$BASELINE") <(sort "$tmp_current"))
# stale baseline cycles gone from current
while IFS= read -r c; do
  [[ -z "$c" ]] && continue
  echo "✖ stale baseline cycle (no longer exists): $c"
  stale=1
done < <(comm -23 <(sort "$BASELINE") <(sort "$tmp_current"))
rm -f "$tmp_current"

if (( fail || stale )); then
  echo ""
  (( fail ))  && echo "circular-deps guard failed: break the new cycle, or (to intentionally accept it) run: bash scripts/lint-circular-deps.sh --regen  (and reference an issue in the commit)."
  (( stale )) && echo "circular-deps guard found resolved cycles. Lower the baseline: bash scripts/lint-circular-deps.sh --update"
  exit 1
fi
echo "✓ circular-deps guard passed (no new cycles; baseline current)"
```

> The `--update` block above is written for clarity; the executor should keep the `comm -12` "intersection of baseline and current" logic (drop resolved cycles, never add) and drop the stray no-op line. The authoritative behavior: `--update` = keep baseline ∩ current; `--regen` = write current; `check` = fail on (current − baseline) new cycles and (baseline − current) stale cycles.

Make executable: `chmod +x scripts/lint-circular-deps.sh`. Generate the baseline with `bash scripts/lint-circular-deps.sh --regen` and commit `scripts/circular-deps-baseline.txt` verbatim (do not hand-edit).

**Implementation checkpoint (madge output shape):** the exact path prefix madge emits for a `src` scan (e.g. `dashboard/server/foo.ts` relative to `src`, vs `src/dashboard/...`) is whatever madge produces; the baseline captures it verbatim and canonicalization runs on madge's own output, so it is internally consistent regardless. **Fallback:** if `--json` returns an unexpected shape, run `node_modules/.bin/madge --circular src` once, inspect, and adjust the `node -e` parse — the canonical-line contract (rotation-invariant, sorted, one per line) is fixed; only the parse of madge's JSON may need a tweak.

Any added cycle line without an issue reference in the commit message fails; with one, it passes.

## Acceptance criteria

Map 1:1 to work items — see the vBRIEF `plan.items[].items`. In short:

- Guard exits 0 on branch with a committed canonical, sorted baseline (FR-3).
- A new cycle → guard exits 1 and names it (FR-1).
- Removing a baselined cycle → guard exits 1 (stale) → `--update` lowers the baseline (FR-2/FR-4).
- `npm run lint` chain includes and runs `lint:circular` and exits 0 (FR-5).
- Ratchet audit fails on an unreferenced added cycle line, passes with an issue reference (FR-6).
- No production `src/**` is modified (NFR-1).
