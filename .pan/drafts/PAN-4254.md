## Glossary

- **Effort** — the reasoning-effort level a harness runs at. Canonical set: `low`, `medium`, `high`, `xhigh`, `max` (`EFFORT_LEVELS`). Default `high`, never `xhigh`/`max` (`sync-sources/rules/effort-high-default.md`).
- **Conversation** — a dashboard/CLI chat session stored in the `conversations` table (`src/lib/overdeck/conversations.ts`). Column `effort` is nullable text (`effort: Schema.NullOr(Schema.String)`, line 66).
- **Spawn** — `spawnConversationSession(...)` in `src/lib/overdeck/conversation-runtime.ts` (line 548). Every conversation launch goes through it: create, resume, restart-all, fork/handoff (`ensureForkSessionReady`), lanes, Flywheel.
- **Create** — `POST /api/conversations` → `handleConversationCreate` (`conversation-runtime.ts` line 1024).
- **Resume** — `handleConversationResume` (line 1105). Relaunches a dead conversation, optionally with a body-supplied `model`/`effort`.
- **Restart-all** — `handleConversationRestartAll` (line 1194). Relaunches every live conversation from its stored row.
- **Switch-model** — `handleConversationSwitchModel` (line 350). Changes a conversation's stored model/harness before its session starts (or live for pi).
- **Thinking-level API** — `POST /api/conversations/:name/thinking-level` → `handleConversationThinkingLevel` (`src/lib/overdeck/conversation-delivery.ts` line 361). Changes effort live for codex/ACP/opencode/Prime/pi and persists it with `setConversationEffort`.
- **Fork / handoff** — `POST /api/conversations/:name/summary-fork` → `handleConversationSummaryFork` (`src/lib/overdeck/conversation-forks.ts` line 720). `pan fork` and `pan handoff` call it through `forkConversationViaServer` (`src/cli/commands/fork-client.ts`). The new conversation is the **successor**; the source is the **parent**.
- **pi ThinkingLevel** — pi's own level set `off | minimal | low | medium | high | xhigh` (`src/lib/runtimes/conversation-control.ts` line 6). `off` and `minimal` are not canonical effort levels.
- **opencode variant** — opencode accepts free-form effort names matching `/^[a-z][a-z0-9_-]*$/` (today inlined at `conversation-runtime.ts` lines 722 and 1038).
- **Clamping** — `clampEffort(requested, model, harness)`: keep the level when the model+harness pair supports it, else the highest supported level below it (`effort-support.ts`).
- **lint:effort** — `scripts/lint-effort.sh`, a shrink-only ratchet that counts `effort ?? 'high'` fallbacks and enum copies per file against a `BASELINE` map.

## Problem

1. **Crash bug (audit §6 bug 1).** `export const SAFE_EFFORT_PATTERN = /^(low|medium|high)$/;` (`conversation-runtime.ts` line 205) rejects `xhigh`/`max` at create (line 1038, 400 `Invalid effort`) and at spawn (lines 722-724, `throw new Error('Invalid effort level')`). The thinking-level API persists `xhigh`/`max` (`conversation-delivery.ts` lines 376-394) and pi's `off`/`minimal`. A conversation changed live to `xhigh` therefore throws "Invalid effort level" on its next resume (`conversation-runtime.ts` line 1138) and on restart-all (line 1211).
2. **No effort at creation.** The dashboard never sends `effort` when it creates a conversation: `const payload: Record<string, unknown> = { model: sidebarModel, harness, ...` (`CommandDeck/index.tsx` line 1133) and the `JSON.stringify({ model, harness: ..., message: ..., })` body in `home/HomeComposer.tsx` lines 104-109. (`simple/TalkItThrough.tsx`, named in the issue, is now a 9-line re-export shim; PAN-4280 moved its composer to `HomeComposer.tsx`.) The row stores NULL and the session silently launches at `high`.
3. **Resume drops a body-supplied effort.** `const effort = typeof body['effort'] === 'string' && body['effort'].trim() ? ... : (conv.effort ?? undefined);` (line 1115) launches with it but only the model is persisted (`if (model && modelChanged) setConversationModel(name, model);`).
4. **Switch-model ignores effort.** `handleConversationSwitchModel` never reads or clamps `conv.effort`, so a stored `xhigh` survives a switch to a model without `xhigh`.
5. **No `--effort` on `pan handoff` / `pan fork`.** The successor always copies `conv.effort ?? undefined` (`conversation-forks.ts` line 884).
6. **Ad hoc fallbacks.** `effort: string = 'high'` (line 553), `piEffort: effort ?? 'high'` (653), `codexEffort: effort ?? 'high'` (686), `kimiCodeEffort: effort ?? 'high'` (712). None of them clamp to the model or harness.
7. **Frontend enum copies.** `EffortPicker.tsx` lines 15-21 define a private `EFFORT_LEVELS` object list; `ModelPicker.tsx` repeats `['low', 'medium', 'high', 'xhigh', 'max']` per model row (lines 61-70, 99-108, 116, 118-125) and `['low', 'medium', 'high']` at line 331. `resolveComposerEffort` (`ComposerFooter.tsx` lines 89-109) falls to the browser default for pi's `off`/`minimal`.

## Decisions

- **D1 — One conversation-effort module.** All validation, canonicalization and resolution for conversations lives in a new leaf `src/lib/overdeck/conversation-effort.ts`. `conversation-runtime.ts` (1242 lines, allowlist cap 1252) and `conversation-forks.ts` import from it; neither re-implements it. This keeps `conversation-runtime.ts` net-shrinking.
- **D2 — Launch effort always comes from `resolveEffort`.** For canonical values the module calls `resolveEffort({ explicit, issueId, model, harness })` and uses `.effort` (the clamped level). An absent value resolves through the project layer (when the conversation has an `issueId`) to the default `high`. Conversations pass no `role`, `tierName`, item or plan layer — they are not role launches.
- **D3 — opencode keeps its free-form carve-out.** `resolveEffort` throws on non-canonical input, so for `harness === 'opencode'` a value that is not canonical but matches `/^[a-z][a-z0-9_-]*$/` passes through unchanged. Canonical values on opencode still go through `resolveEffort`.
- **D4 — pi `off`/`minimal` are stored as `low`.** Nothing verifies that `omp --thinking off` is accepted at launch (`launcher-generator.ts` line 772 passes `piEffort` raw), and the ohmypi harness declares `effortLevels: ["low", "medium", "high", "xhigh"]` (`packages/contracts/src/harness-behavior.ts` line 126). So the thinking-level API still sends `off`/`minimal` to the live pi runtime unchanged, but persists `low`. Legacy rows that already hold `off`/`minimal` are read as `low` on every launch. Trade-off: a relaunched pi conversation runs at `low`, not `off`.
- **D5 — Stored value = launched value.** Create, resume-with-body-effort, switch-model and fork persist the **clamped** level, never the raw request, so the row never claims a level the model cannot run.
- **D6 — Absent stays NULL.** Create without `effort` stores NULL (the launch still resolves `high` or the project layer). Fork with neither `--effort` nor a parent effort stores NULL.
- **D7 — Invalid input is a 400 at the API boundary; spawn still throws on junk.** Create, resume and fork return `400 { error: 'Invalid effort' }` for a value that is not canonical, not a pi `off`/`minimal`, and not an opencode variant on opencode. `spawnConversationSession` lets `InvalidEffortError` propagate (message `Invalid effort level: "<value>"`).
- **D8 — Switch-model clamps; it does not accept a new effort.** After the model/harness update, a non-null stored effort is re-resolved for the new model+harness and persisted when it changed. A stored value that is invalid for the new harness (an opencode variant moved to claude-code) is reset to NULL. No live `set_thinking_level` is sent on a live pi switch; pi clamps internally.
- **D9 — Fork/handoff effort precedence:** request `effort` → parent's stored effort → NULL. A parent effort that is invalid for the successor's harness is dropped (NULL), not an error. The chosen value is clamped to the successor's launch model and harness.
- **D10 — The CLI does not pre-validate `--effort`.** `pan handoff`/`pan fork` forward the string; the server's 400 surfaces as the existing `ForkServerError` path (exit 1). This keeps opencode variants working and avoids a second validator.
- **D11 — Lanes stay out of scope.** `src/lib/lanes/launch.ts` imports `SAFE_EFFORT_PATTERN` (line 32) and `launch.test.ts` line 276 asserts `xhigh` is refused with `effort must be low, medium or high`. The constant stays exported for the lane door only; its comment changes to say conversations no longer use it. lint:effort keeps `conversation-runtime.ts` at baseline 1 for that line.
- **D12 — Frontend new-conversation effort default.** The new pickers start from `loadStoredEffort()` (browser-stored last choice, default `high`), share the `conv-composer-effort` storage key with the composer picker, and send `effort` only when the model's level list is non-empty.
- **D13 — `ModelPicker.tsx` enum copies are cleaned here** even though lint:effort tags that row `PAN-4259`, because the issue body assigns it to this slice.

### WI-1 — `conversation-effort.ts` module (foundation)

New file `src/lib/overdeck/conversation-effort.ts`:

```ts
/**
 * Conversation effort (PAN-4254): validation, pi canonicalization and launch
 * resolution for every conversation door. Launch levels come from
 * resolveEffort (src/lib/agents/resolve-effort.ts); this module only adds the
 * two conversation-specific carve-outs — pi's off/minimal and opencode's
 * free-form variants.
 */
import { isEffortLevel } from '@overdeck/contracts';
import { resolveEffort } from '../agents/resolve-effort.js';
import type { RuntimeName } from '../runtimes/types.js';

const OPENCODE_EFFORT_PATTERN = /^[a-z][a-z0-9_-]*$/;
const PI_BELOW_LOW = new Set(['off', 'minimal']);

/** pi's off/minimal are stored and launched as `low` (D4); every other value is unchanged. */
export function canonicalConversationEffort(value: string): string {
  return PI_BELOW_LOW.has(value) ? 'low' : value;
}

/** True when a conversation door may accept `value` for `harness` (D3, D4, D7). */
export function isValidConversationEffort(value: string, harness: RuntimeName): boolean {
  const canonical = canonicalConversationEffort(value);
  if (isEffortLevel(canonical)) return true;
  return harness === 'opencode' && OPENCODE_EFFORT_PATTERN.test(value);
}

export interface ConversationEffortInput {
  effort?: string | null;
  model?: string;
  harness: RuntimeName;
  issueId?: string;
}

/**
 * The level a conversation launches at. Canonical (or pi off/minimal) values
 * and absent values go through resolveEffort and are clamped to the model and
 * harness; an opencode variant passes through. Throws InvalidEffortError for
 * anything else.
 */
export function resolveConversationEffort(input: ConversationEffortInput): string {
  const raw = input.effort?.trim() || undefined;
  if (raw && input.harness === 'opencode' && !isEffortLevel(raw) && OPENCODE_EFFORT_PATTERN.test(raw)) return raw;
  return resolveEffort({
    explicit: raw === undefined ? undefined : canonicalConversationEffort(raw),
    issueId: input.issueId,
    model: input.model,
    harness: input.harness,
  }).effort;
}
```

The patterns above contain no `low|medium|high` literal, so lint:effort does not count this file. Tests go in WI-2's test file (one file for the whole slice's server tests).
