## blocks-the-design: Pin and wake can use the wrong workspace

WI-2 specifies `workspacePathForIssue` as `defaultWorkspacePath` (PRD line 242), WI-9 derives the CLI path the same way (line 441), and WI-11 checks the pin at that derived path (line 458). The idle-stop service instead uses each registered `WorkspaceRow.path` (WI-7, lines 360 and 390). The repository already exposes the actual issue workspace through `getWorkspaceForIssue` (`src/lib/workspaces/resolver.ts:123-132`); `defaultWorkspacePath` only constructs `<project>/<workspaces_dir>/feature-<issue>` (`src/lib/workspace/stack-health.ts:261-267`). For a registered workspace at another path, `pan workspace pin` writes a pin that neither stop service checks, and `pan workspace up` cannot find the journal or compose project that the idle stop used. Resolve the registered issue workspace first in the shared path helper, pass that path to `wakeWorkspaceStack`, and test a registered nondefault path end to end.

## blocks-the-design: Wake excludes services the old reaper stops

D12 says the new wake starts what the old reaper stopped (PRD line 140), and `pan workspace up` is described as starting a workspace's stopped Docker containers (line 427). The old reaper's full-stack tier stops every service except `dev` (`src/lib/cloister/idle-stack-reaper.ts:275-279,317-324`), including databases and caches. WI-4 wakes only services in `RECLAIMABLE_STACK_SERVICES`, the default idle set, or configured idle services (PRD lines 24, 313); `RECLAIMABLE_STACK_SERVICES` contains only `api`, `fe`, `frontend`, and `server` (`src/lib/workspace/stack-reclaim-docker.ts:21-22`). A reaped `postgres` therefore remains down after `pan workspace up` reports success, and the app can stay unavailable. Specify and test a safe full-stack wake path for containers stopped by the old reaper, or narrow the command's promise and supply a working restart command for that case.

## blocks-the-design: Old reaper still stops gate work

FR-3 protects verification and gate-queue use (PRD lines 48-55), but WI-11's old-reaper protection checks only a pin, inbound connections, exec sessions, and unreadable probes (lines 457-465). The old reaper gates on live agent IDs (`src/lib/cloister/idle-stack-reaper.ts:232-250,303-324`), so a queued verification without an agent pane can reach its full-stack stop. The verification runner restores a reclaimed stack once at `src/lib/cloister/verification-runner.ts:218`, then reaches `runQualityGates` at line 441; the old reaper writes no reclaim journal, so that restore cannot recover a stop during the wait. Include verification-active and gate-queue checks in the old reaper's protection decision, with an unreadable queue treated as protected, and test an agent-less queued verification past the grace window.
