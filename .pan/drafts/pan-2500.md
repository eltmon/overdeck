# PAN-2500 — Memory-aware resource governor

**Issue:** https://github.com/eltmon/overdeck/issues/2500
**Epic:** #1666 (Pipeline Throughput Hardening)
**Folds in:** #2390 (oomd killed the tmux server), #629 (workspace quotas & resource governance)
**Depends on:** #2464 (Machine Room — per-stack RSS attribution + reclaim advisor, closed/merged)
**Verified-Against:** main @ 1964747461.

---

## Glossary

- **Admission gate** — the decision point that says "may this agent start/resume *now*?" Today there are **two** of them and they disagree (see Root Cause).
- **HTTP spawn path** — an agent start triggered by an operator (dashboard "Start", CLI `pan start`) that flows through the dashboard route handlers and calls `evaluateSpawnGuardrails()`.
- **Autonomous resume/dispatch path** — the deacon starting agents on its own: boot orphan-recovery, patrol auto-resume, and the on-`agent.stopped` reactive resume. Lives in `src/lib/cloister/deacon-auto-resume.ts`.
- **`MemAvailable`** — the kernel's estimate (in `/proc/meminfo`) of RAM available for new work without swapping. The correct number to gate on (not `MemFree`).
- **Footprint** — the total resident memory one admitted agent will hold: its `claude`/`codex` process + the PTY supervisor + **its workspace docker stack** + transient tool spikes (Playwright/Chrome, vitest).
- **Stack** — all containers of one issue's workspace compose project (e.g. `myn-feature-min-857`). The dominant, count-invisible RAM consumer.
- **Hysteresis band** — separate thresholds for *start shedding* vs *start re-admitting*, with a gap between them, so the governor cannot oscillate (thrash resume↔pause).
- **Governor** — the new control loop this PRD adds: one memory-aware admission predicate + a shed/recover state machine, consulted by **both** paths.
- **`docker pause` vs `docker stop`** — `pause` sends SIGSTOP: CPU frozen, **RAM retained**. `stop` frees RAM. Reclaiming memory requires `stop` (or stopping the agent process), never `pause`.

## Requirements

### Functional
- **FR-1** The autonomous resume/dispatch path MUST consult a memory-pressure predicate before admitting any agent, using the same `MemAvailable`-based thresholds the HTTP spawn path already enforces.
- **FR-2** When `MemAvailable` is below the **SOFT** threshold, the deacon MUST admit no *new* resumes/dispatches this patrol (defer, never kill), and log the deferral with the observed `MemAvailable`.
- **FR-3** When `MemAvailable` is below the **HARD** threshold, the governor MUST actively shed resident memory in value-ascending order (FR-6) until `MemAvailable` clears the **RECOVERY** threshold or nothing shed-eligible remains.
- **FR-4** The governor MUST NOT re-admit or unpause anything until `MemAvailable` exceeds the **RECOVERY** threshold, which MUST be strictly greater than the SOFT threshold (hysteresis).
- **FR-5** Admission MUST be gated on estimated **footprint in bytes** (`claude` RSS + supervisor + workspace-stack RSS + tool-spike reserve), admitting an agent only if `footprint ≤ MemAvailable − reserve`. Footprint estimates are learned from live per-stack RSS (reuse #2464 attribution), with a configured default for cold start.
- **FR-6** Eviction order MUST be: (a) `docker stop` stacks of merged/closed issues (reclaim-advisor-safe per #2464); (b) pause idle work agents (stop the `claude` process, preserve tmux + workspace, resumable via `--resume`); never shed an operator-attached agent or a core service (dashboard, deacon, cliproxy, traefik).
- **FR-7** Under memory pressure the reserved advancing-slot budget MUST shrink: a review/test specialist is spawned only when there is actual advancing work AND footprint budget exists.
- **FR-8** Boot-reconciliation MUST resume the candidate set as a memory-paced trickle (resume one, let RSS settle, re-check `MemAvailable`, resume next) instead of the current grace→`resume_all` burst.

### Non-functional
- **NFR-1** No new blocking/sync calls in server-reachable code — `docker stats`/`/proc` reads MUST be async (`execAsync`/`fs.promises`), per the no-execSync-server rule.
- **NFR-2** The governor MUST NOT introduce steady-state thrash: with a stable workload straddling a threshold, resume/pause actions MUST converge (verified by the hysteresis test in W2).
- **NFR-3** All thresholds MUST be config-driven with justified defaults — no hardcoded fallback that silently overrides an unset value (no-hardcoded-model-fallback principle applied to thresholds).

## Root cause (verified)

Two admission gates exist; only one checks memory.

**Gate A — HTTP spawn path (memory-aware).** `evaluateSpawnGuardrails()` at `src/dashboard/server/routes/agents/shared.ts:548` blocks a spawn when RAM is critically low:

```ts
// shared.ts:557
if (health.summary.availableMemoryBytes < health.thresholds.memoryAvailableCriticalBytes) {
  warnings.push({ severity: 'critical', code: 'memory_pressure', message: `Available RAM is critically low (${availableGb} GB).` });
}
// … a critical warning → blocked:true, status 429 (shared.ts:593-612)
```

Called only from the HTTP surfaces: `routes/agents.ts`, `routes/agents/spawn.ts`, `routes/resources/spawn-gate.ts`.

**Gate B — autonomous resume/dispatch path (memory-blind).** `autoResumeStoppedWorkAgents()` at `src/lib/cloister/deacon-auto-resume.ts:818` gates on count + CPU load only:

```ts
// deacon-auto-resume.ts:827-857 (paraphrased)
const workSlots = workResumeSlotsAvailable(runningBefore, concurrencyLimits); // count: max_work_agents(6) − running
const loadCeiling = cores * RESUME_LOAD_FACTOR;                                // RESUME_LOAD_FACTOR = 1.5 (:601)
for (const agentId of candidates) {
  if (resumeAttempts >= workSlots) break;          // count gate
  if (loadavg()[0] > loadCeiling) break;           // CPU-load gate — NOT memory
  await new Promise(r => setTimeout(r, RESUME_STAGGER_MS)); // 150ms (:603)
  await handleAgentStoppedEvent(agentId, { skipGlobalGates: true, … });
}
```

The identical count+load-only pattern repeats in `applyBootReconciliationDecision()` (`:912-934`) and `handleAgentStoppedEvent()`'s global gates (`:741-757`). `git grep evaluateSpawnGuardrails src/lib/cloister src/lib/agents` → **no matches.** The resume/spawn primitives (`src/lib/agents/resume.ts`, `src/lib/agents/spawn.ts`) contain **zero** memory checks.

**Why count+load is insufficient:** the cap counts *agents* (`6 work + 3 advancing + 3 swarm = up to 12`), but each admitted agent drags a workspace **docker stack** whose RSS the count never sees. At rest on the incident box, two workspace `java` backends held 1.28 GB and 0.99 GB. CPU `loadavg` and RAM pressure are orthogonal — agents idle-blocked on I/O keep load low while their stacks stay resident. Result: boot resumes the deferred queue 6-at-a-time every 60 s, RAM exhausts, and (#2390) systemd-oomd kills the whole tmux server. `--no-resume` is the only existing escape because it is the sole memory-blind-but-total off switch.

## Work items

### W1 — Single memory admission door (the core fix; prevents the OOM alone)

**What/why:** make Gate B honor the memory rule Gate A already enforces.

**Files/functions:**
- New `src/lib/cloister/memory-governor.ts` exporting `assessMemoryPressure(): Promise<MemoryVerdict>` where `MemoryVerdict = { band: 'ok'|'soft'|'hard', availableBytes, thresholds }`. It reads `MemAvailable` via the existing async parser `readProcMemory()` (`src/dashboard/server/services/system-health-service.ts:332`, which delegates to `readProcMemoryLinux()` at `:268`, `MemAvailable` at `:279`). Extract the threshold/predicate logic so `evaluateSpawnGuardrails` (`shared.ts:557-569`) and the governor share one source of truth — do not duplicate the comparison.
- In `deacon-auto-resume.ts`: before the resume loops in `autoResumeStoppedWorkAgents` (`:827`) and `applyBootReconciliationDecision` (`:912`), and in `handleAgentStoppedEvent`'s global-gate block (`:742`), call `assessMemoryPressure()`; if `band !== 'ok'`, defer exactly as the load gate does (`logDeaconEventSync(... deferred — memory gate …)`, `break`/`return null`).

**Before/after (autoResumeStoppedWorkAgents loop):**
```ts
// BEFORE (deacon-auto-resume.ts:853)
const load1 = loadavg()[0];
if (load1 > loadCeiling) { logDeaconEventSync(`… load gate tripped …`); break; }

// AFTER — add the memory gate beside the load gate
const load1 = loadavg()[0];
if (load1 > loadCeiling) { logDeaconEventSync(`… load gate tripped …`); break; }
const mem = await assessMemoryPressure();
if (mem.band !== 'ok') {
  logDeaconEventSync(`autoResumeStoppedWorkAgents: memory gate (${mem.band}) — availMB=${Math.round(mem.availableBytes/1048576)}; deferring remaining candidates`);
  break;
}
```

**Tests:** `tests/unit/lib/cloister/memory-governor.test.ts` — `assessMemoryPressure` returns `soft`/`hard`/`ok` at the configured boundaries (fake `MemAvailable`); a deacon-resume test that stubs `assessMemoryPressure` to `soft` and asserts zero resumes.

### W2 — Hysteresis bands (anti-thrash)

**What/why:** three thresholds with `recovery > soft` so shedding and re-admitting never fight. Satisfies FR-4, NFR-2 — the operator's "we don't want to always --resume."

**Files:** `memory-governor.ts` holds a tiny state machine `{ mode: 'admitting'|'holding'|'shedding' }`; transitions on band crossings only. Config keys in `src/lib/cloister/config.ts` (schema near the concurrency block `:69-82`, defaults near `:335-337`): `memory.soft_reserve_gb`, `memory.hard_reserve_gb`, `memory.recovery_reserve_gb` (defaults, e.g., 12 / 6 / 20 GB — final numbers set at the implementation checkpoint below).

**Implementation checkpoint:** default thresholds are tuned to *this* 62 GB host; express defaults as a fraction of `totalmem()` with an absolute floor, and record the chosen fractions. **Fallback if unclear:** SOFT = max(15% total, 8 GB), HARD = max(8% total, 4 GB), RECOVERY = max(25% total, 12 GB).

**Tests:** feed a `MemAvailable` sequence that crosses SOFT downward then rises just past SOFT (but below RECOVERY) — assert the governor stays in `holding` and does NOT re-admit until RECOVERY is crossed.

### W3 — Gigabyte budget with docker-stack accounting

**What/why:** admit on footprint bytes, not agent count (FR-5). Reuse #2464's per-stack attribution.

**Files:** extend `memory-governor.ts` with `estimateFootprint(role, projectKey)` sourced from live per-stack RSS (`sumProcessMemory` at `system-health-service.ts:421` and the Machine Room stack attribution from #2464) plus a configured cold-start default per role. Admission predicate: `estimate ≤ availableBytes − softReserve`.

**Tests:** admission allows N agents whose summed estimated footprint fits the free budget and defers the N+1th; footprint learned from a stubbed `docker stats` map overrides the cold-start default.

### W4 — Tiered eviction under HARD pressure

**What/why:** FR-3, FR-6. Reclaim ladder, cheapest-value first.

**Files:** `memory-governor.ts` `shed(target): Promise<ShedResult>`:
1. `docker stop` stacks whose issue is merged/closed — reuse the reclaim-safety computation from #2464 (do not re-derive "safe to stop").
2. Pause idle work agents via the existing pause gate (`setAgentPaused(agentId, reason)` in `src/lib/agents/agent-state.ts`; `pausedReason` marks it governor-shed so `pan unpause`/recovery clears it). Idle = runtime `state === 'idle'`. This frees the `claude` RSS; the agent resumes via the normal `--resume` path when RECOVERY is crossed.
- Never shed an operator-attached agent or a core service. `docker pause` is explicitly NOT used for reclaim (retains RAM).

**Tests:** with two merged-issue stacks and one idle work agent, `shed` stops the stacks first and only pauses the agent if still under HARD; asserts an operator-attached agent is never chosen.

### W5 — On-demand specialist budget

**What/why:** FR-7. Don't hold 3 advancing slots' worth of GB idle under pressure.

**Files:** where advancing dispatch is gated (`canDispatchAdvancing` at `concurrency.ts:160`, and its callers), add a footprint check so a specialist spawns only when advancing work exists AND budget exists. Do not change the reserved-slot *count* semantics when RAM is plentiful.

**Tests:** advancing dispatch proceeds with headroom; is withheld when `band==='soft'` even though a count slot is free.

### W6 — Memory-paced boot

**What/why:** FR-8 — replace the grace→`resume_all` burst.

**Files:** `applyBootReconciliationDecision` (`deacon-auto-resume.ts:885`) already loops candidates with a `RESUME_STAGGER_MS` sleep; change the loop to, after each resume, await a short RSS-settle window then re-`assessMemoryPressure()` and `estimateFootprint` before the next admit. Keep the existing per-agent skip/deferred bookkeeping. `DEFAULT_BOOT_RECONCILIATION_GRACE_SECS` (`boot-reconciliation.ts:19`) is unchanged; only the apply-loop becomes memory-governed.

**Tests:** boot with 20 candidates and a `MemAvailable` that drops below SOFT after 3 resumes — assert exactly 3 resume and 17 are deferred with the memory reason.

### W7 — Kernel safety net (#2390)

**What/why:** a governor miss should degrade gracefully, not wipe every agent.

**Files:** the tmux-server transient unit setup — set `ManagedOOMPreference=avoid` so systemd-oomd deprioritizes the tmux server. Document in `docs/AGENT-STATE-PLANES.md` (liveness-oracle section) and cross-link from the new governor doc (W8).

**Tests:** N/A (systemd unit property); verify via `systemctl show overdeck-tmux-server.service -p ManagedOOMPreference` in the acceptance run.

### W8 — Documentation (required deliverable)

Add `docs/RESOURCE-GOVERNOR.md`: the two-gates-now-one-door model, the three bands + hysteresis diagram, the footprint formula, the eviction ladder, and the config keys with defaults. ## Restated intersecting repo rules (executor: obey these)

- **no-execSync-server** — every `docker stats`/`/proc`/`docker stop` call in governor code (server-reachable) uses `execAsync`/`spawn`/`fs.promises`. Never `execSync`.
- **Single source of truth** — the memory predicate has ONE implementation shared by `evaluateSpawnGuardrails` and the governor. Do not fork the thresholds.
- **No hardcoded fallback** — thresholds resolve from config or fail loudly; the cold-start footprint default is an explicit configured value, not a code literal chosen silently.
- **Stash discipline / worktree discipline** — standard; work in the assigned workspace on `feature/pan-2500`.
