## Problem

When machine B continues a conversation that machine A started (`pan vault resume` on B, or "Continue here" in
B's dashboard, PAN-4437), A's dashboard shows nothing. A's conversation row and composer look the same as before.
The operator on A can keep typing; the engine then saves those new turns as a settlement fork (P-6) and says
nothing in the dashboard. The operator cannot see that the conversation moved or that their local turns were
split off.

Verified facts that shape the design:

1. **A keeps its owned entry after B adopts.** `adoptRecord` writes only B's local index; A's
   `index.owned[nativePath]` still points at the original `vaultId`. A's next `syncOnce` pulls the record and
   writes its list-cache row with `ownerIsHere: false` and B's label. So "continued elsewhere" is derivable from
   A's local index alone: owned entry → its row → `ownerIsHere === false`.
2. **A browse row for the record appears on A.** `browse.ts` creates `vault-<vaultId>` for every non-tombstone
   row with `!ownerIsHere`, so the link target the issue asks for exists on A after that same sync.
3. **After a settlement fork, the owned entry points at the fork.** The fork row is `ownerIsHere: true`; the
   parent row is `ownerIsHere: false`. The list cache has no parent link today, so the cache must carry it.
4. **Version forks also set `parent`.** `format.ts` documents `parent` as "Set on version forks (P-7)", and
   `forkRecordAtVersion` writes it. Without a discriminator, a `pan vault resume <id>@3` fork taken on A of a
   B-owned record would wrongly read as "Local turns since then were saved as a fork". The discriminator is
   `segments[0]?.prefix === null`: only `settle.ts` writes a first segment with a null prefix; `claimAndMaterialize`
   always writes a non-null prefix, and an unmaterialized version fork has no segments.
5. **The conversation list polls.** `CommandDeck/index.tsx` refetches `['conversations']` every 10 s
   (`refetchInterval: 10000`), so no new push event is needed.
6. **`getConversationListWithVaultCopies`** (`src/lib/overdeck/conversation-list.ts`) is the only producer of
   `GET /api/conversations` rows (`routes/conversations.ts`). The Agents Directory and lanes use
   `getEnrichedConversationList` and are out of scope.

## Goal

- A's conversation row shows `continued on <label>` once B owns the record.
- A's composer shows a notice: `Continued on <label>.` with a "View its copy" link that opens `vault-<vaultId>`.
- After A settles new local lines, the notice also reads `Local turns since then were saved as a fork (<id8>).`
- The composer stays enabled in both states: typing on A is what produces the fork, and the engine already saves
  it. There is no "Save local turns as a fork" button.

## Requirements

### Functional

- **FR-1** `ListCacheRow` gains two optional fields, `parentVaultId?: string` and
  `forkKind?: 'settlement' | 'version'`. `syncOnce` sets both only when the pulled record's `parent` is non-null:
  `parentVaultId = value.parent.vaultId`; `forkKind = value.segments[0]?.prefix === null ? 'settlement' : 'version'`.
  Records without a parent and tombstone rows carry neither field (the keys are absent, not `null`).
- **FR-2** New pure function `roundTripStates(index)` in new `src/lib/vault/round-trip.ts` returns a
  `Map<nativePath, RoundTripState>` with an entry only for owned paths that have a state, by these rules in order:
  1. Look up the row whose `vaultId` equals the owned entry's `vaultId`. No row → no state.
  2. Row `tombstone` → no state.
  3. Row `ownerIsHere === false` → `{ kind: 'continued-elsewhere', vaultId: entry.vaultId, ownerLabel: row.ownerLabel }`.
  4. Row `ownerIsHere === true`, `forkKind === 'settlement'`, `parentVaultId` set, and the parent's row exists, is
     not a tombstone and has `ownerIsHere === false` → `{ kind: 'forked-locally', forkVaultId: entry.vaultId,
     parentVaultId, parentOwnerLabel: parentRow.ownerLabel }`.
  5. Otherwise no state.
- **FR-3** New `src/lib/overdeck/conversation-vault-continuity.ts` maps conversation rows to states:
  - Claude Code row (`harness` is `'claude-code'`, `null` or `undefined`) with a non-null `claudeSessionId`:
    candidate owned paths are those whose entry `harness === 'claude-code'` and whose `basename` is
    `<claudeSessionId>.jsonl`.
  - Codex row (`harness === 'codex'`): candidate owned paths are those whose entry `harness === 'codex'` and that
    start with `join(overdeckHome, 'agents', tmuxSession) + sep`.
  - Several candidates → the lexicographically greatest path wins (Codex rollout names embed their start time, so
    this is the newest). The row's state is that path's state, or `null`.
  - `origin === 'vault'` rows and every other harness → `null`.
  - Lookups are built once per call in O(owned entries): a `Map<basename, path[]>` for Claude and a
    `Map<tmuxSession, path[]>` for Codex (the first path segment after `<overdeckHome>/agents/`).
- **FR-4** `getConversationListWithVaultCopies(limit, offset)` reads the local index exactly once per call,
  outside the coalesced enrichment cache, and sets `vaultContinuity` on every local row of every page (the
  existing `if (offset !== 0) return enriched;` early return must not skip it). Browse copies get
  `vaultContinuity: null`. A local index that cannot be read or parsed yields `null` for every row and one
  `console.warn('[vault] continuity: …')` per distinct message; the list never fails because of it.
- **FR-5** `ConversationRow` shows a chip with text `continued on <label>` (`data-testid="vault-continuity-badge"`,
  `MonitorSmartphone` icon, the same `conversationBranchChip` classes as the PAN-4436 owner badge) in both row
  variants. `<label>` is `ownerLabel` for `continued-elsewhere` and `parentOwnerLabel` for `forked-locally`. The
  chip's `title`: `Continued on <label>` or `Continued on <label>. Local turns since then were saved as a fork (<id8>).`
- **FR-6** New `VaultContinuityNotice` renders above the composer input for a local conversation with a non-null
  `vaultContinuity` (`role="status"`, `data-testid="vault-continuity-notice"`):
  - Line 1: `Continued on <label>.` followed by a button "View its copy" that calls
    `onOpenCopy('vault-<id>')`, where `<id>` is `vaultId` (continued-elsewhere) or `parentVaultId` (forked-locally).
  - Line 2, only for `forked-locally`: `Local turns since then were saved as a fork (<id8>).` where `<id8>` is
    `forkVaultId.slice(0, 8)`.
  - `ComposerFooter` passes its existing local `openConversationRoute` as `onOpenCopy`, which pushes
    `/conv/vault-<id>`. The composer input stays rendered and enabled.
- **FR-7** Docs: `docs/SESSION-VAULT.md` and `configuration/session-vault.mdx` describe both states (WI-7).

- **NFR-3** Nothing writes a native transcript: the round-trip computation is read-only, and the two-machine test

- **NFR-5** Tests never touch the operator's real `~/.claude` or `~/.overdeck`: engine tests set `OVERDECK_HOME`

## Decisions (made in this document)

- **D-1 Fork discriminator.** `forkKind` in the list cache (FR-1), derived from `segments[0]?.prefix === null`.
  Only `'settlement'` forks produce `forked-locally`. A version fork reports no state (its parent may be owned
  elsewhere, but no local turns were split off). Rejected: filling `parentVaultId` only for settlement forks,
  because the issue defines `parentVaultId` as `record.parent?.vaultId`.
- **D-2 Names.** Engine function `roundTripStates`, type `RoundTripState`, file `round-trip.ts` (the issue's file
  name). Not `continuityStates`: `continuity.ts` owns the word in the engine. The wire field stays
  `vaultContinuity` (issue).
- **D-3 Match rules** are the issue's (FR-3). Tie-break: greatest path. Rows without `claudeSessionId` → `null`.
- **D-4 Every page gets the field** (FR-4). Continuity is a per-row fact, and one index read per call is cheap.
- **D-5 Unreadable index → no states, never an error** (FR-4). A corrupt `index.json` already breaks
  `pan vault`; the conversation list must not inherit that.
- **D-6 The composer stays enabled** (Goal). No read-only guard and no "Save local turns as a fork" button.
- **D-7 Link target.** "View its copy" opens the browse row of the record B owns: `vault-<vaultId>` for
  continued-elsewhere, `vault-<parentVaultId>` for forked-locally. If PAN-4436 has not created the row yet (the
  browse refresh failed), the route shows the normal not-found state; no extra handling.
- **D-8 Frontend type lives in `ConversationList.tsx`** next to `origin` and `vaultOwnerLabel` (PAN-4436 pattern).
  The frontend does not import from `src/lib`.
- **D-9 No new push event.** The 10 s list poll picks up the state (fact 5).
- **D-10 The new component file holds the notice;** `ComposerFooter` only renders it (NFR-4).

### WI-2 `round-trip-states` — the pure engine function (FR-2, D-2)

Files: `src/lib/vault/round-trip.ts` (new), `tests/unit/lib/vault/round-trip.test.ts` (new).

```ts
/**
 * Session Vault round-trip states (PAN-4447, PAN-2609 P-6).
 *
 * For each native path this machine owns, says whether another machine has
 * continued its record (`continued-elsewhere`) or whether this machine's later
 * turns were saved as a settlement fork of a record owned elsewhere
 * (`forked-locally`). Pure over the local index; "continuity" in continuity.ts
 * means line-hash tails, so this module uses "round trip". Imports only types.
 */
import type { ListCacheRow, LocalIndex } from './local-index.js';

export type RoundTripState =
  | { kind: 'continued-elsewhere'; vaultId: string; ownerLabel: string }
  | { kind: 'forked-locally'; forkVaultId: string; parentVaultId: string; parentOwnerLabel: string };

export function roundTripStates(index: Pick<LocalIndex, 'owned' | 'listCache'>): Map<string, RoundTripState> {
  const rows = new Map<string, ListCacheRow>(index.listCache.map((row) => [row.vaultId, row]));
  const states = new Map<string, RoundTripState>();
  for (const [nativePath, entry] of Object.entries(index.owned)) {
    const row = rows.get(entry.vaultId);
    if (!row || row.tombstone) continue;
    if (!row.ownerIsHere) {
      states.set(nativePath, { kind: 'continued-elsewhere', vaultId: entry.vaultId, ownerLabel: row.ownerLabel });
      continue;
    }
    if (row.forkKind !== 'settlement' || !row.parentVaultId) continue;
    const parent = rows.get(row.parentVaultId);
    if (!parent || parent.tombstone || parent.ownerIsHere) continue;
    states.set(nativePath, { kind: 'forked-locally', forkVaultId: entry.vaultId, parentVaultId: row.parentVaultId, parentOwnerLabel: parent.ownerLabel });
  }
  return states;
}
```

Tests (`round-trip.test.ts`, literal `LocalIndex` fixtures, no I/O), one `it` per rule: owned-here row → no entry;
owned-elsewhere row → `continued-elsewhere` with the row's label; tombstone row → no entry; owned entry with no
row → no entry; settlement fork with parent owned elsewhere → `forked-locally`; version fork with parent owned
elsewhere → no entry; settlement fork whose parent is owned here, tombstoned or missing → no entry.
