# PAN-5463 — Computer use on macOS: port Orca's Swift helper, with permission setup that works from `npx`

**Issue:** [PAN-5463](https://github.com/eltmon/overdeck/issues/5463)
**Depends on:** PAN-5461 (Settings page + platform provider seam, `src/lib/computer-use/platform.ts`, including the `'waiting'` setup status and the `grant-permissions` step id). PAN-5452 shipped `pan computer` for Linux.
**Sibling:** PAN-5462 (Windows via WSL2).

## Summary

Overdeck runs natively on macOS (CLI via `npx @overdeck/core` or a global install, and the Electron desktop app). This issue makes `pan computer` and Settings → Computer Use work on macOS by vendoring Orca's Swift helper (`native/computer-use-macos/`, MIT, ~6,900 lines, macOS 14+), adapting it to Overdeck, building it as a small `.app` bundle in CI, and shipping it **inside the npm package** so it works from `npx` without the desktop app.

macOS will not let any app grant itself Accessibility or Screen Recording. So setup is: one click installs the helper and opens the two System Settings pages; the operator switches on "Overdeck Computer Use" in each; Overdeck notices and finishes.

## Facts about Orca's helper (verified 2026-11-17; paths under `~/Projects/orca/`)

- `native/computer-use-macos/Package.swift`: swift-tools 6.0, `.macOS(.v14)`, products `OrcaComputerUseMacOSCore` (library) and `orca-computer-use-macos` (executable), test target `OrcaComputerUseMacOSTests`; no external dependencies. `Sources/OrcaComputerUseMacOS/main.swift` is 4,974 lines; 21 small Core files; 7 test files (576 lines) run with `swift test`.
- **Process model:** a daemon, not one-shot. `main.swift` 4933–4974 dispatches argv: `--agent <socket> --token-file <path>` (NSApplication + Unix socket server), `--permissions` / `--permission <accessibility|screenshots>` (setup window), `--permission-status` (prints JSON), `--permission-status-file <path>`. Anything else exits 13.
- **Wire protocol:** newline-delimited JSON over a Unix stream socket (bind + chmod 0600, `main.swift` 4573–4617). Request `{id, method, params?, token?}` (14–19); response `{id, ok:true, result}` or `{id, ok:false, error:{code,message}}` (4842–4903); `method:"terminate"` quits.
- **Methods (camelCase):** handshake, listApps, listWindows, getAppState, click, performSecondaryAction, setValue, typeText, pressKey, hotkey, pasteText, scroll, drag (238–262). Params are nested and camelCase (`clickCount`, `mouseButton`, `fromX/fromY/toX/toY`), and elements are referenced by **index** (`elementIndex`, `fromElementIndex`, `toElementIndex`, `rootElementIndex`) resolved against a snapshot cache inside the helper (357, 1175–1176). Indexes stay stable across reads on macOS. Actions report `delivery: "background"|"foreground"`.
- **Caller trust (must change):** besides the token, `isAuthorizedAgentPeer` (4742–4754) requires the peer's command line to contain Orca's `computer-sidecar.js` path and the peer or its parent to be an app whose bundle ID passes `TrustedOrcaApplication.isTrusted` (`com.stablyai.orca*`, `com.github.Electron`). Overdeck would be rejected with `permission_denied`.
- **Lifetime (must change):** exits if no authenticated session claims it within 30 s (3509–3546) and when the last authenticated connection closes (`AgentSessionOwnership.swift` 34–39).
- **Permissions:** Accessibility via `AXIsProcessTrusted()` (1293–1300, with a settle retry), Screen Recording via `CGPreflightScreenCaptureAccess()` / `CGRequestScreenCaptureAccess()` (1302–1319). Settings URLs (1321–1331): `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` and `…?Privacy_ScreenCapture`. Orca checks status by launching the app with `/usr/bin/open -n <app> --args --permission-status-file <tmp>/status.json` and polling the file (Orca `src/main/computer/macos-permissions/macos-computer-use-permission-status.ts` 92–131) "so TCC checks its identity instead of inheriting the parent's grants".
- **Build:** Orca `config/scripts/native-build/macos/build-computer-macos.mjs`: `swift build -c release --triple arm64-apple-macosx` and `x86_64-apple-macosx`, `lipo -create`, wrap as `.app` (`Contents/MacOS/<exe>`, generated Info.plist with `LSUIElement true`, `LSMinimumSystemVersion 14.0`, `NSAccessibilityUsageDescription`, `NSScreenCaptureUsageDescription`), `codesign --force --deep --sign <identity>`; release adds `--options runtime --timestamp --entitlements` (an empty entitlements dict). It must be an `.app` because TCC grants attach to the app's code identity.
- **Blocked shortcuts** (Orca `src/main/computer/action-contracts/computer-blocked-key-combos.ts` 21–45, `MACOS_RULES`): cmd+ctrl+q (lock screen), cmd+shift+q (log out), cmd+alt+escape (Force Quit), cmd+shift+backspace (empty Trash), cmd+q (quit app); aliases cmd/command/meta/super/win/cmdorctrl → `cmd`, alt/option → `alt`, `esc` → `escape`, `delete` → `backspace`.

## Glossary

- **Helper app**: `Overdeck Computer Use.app`, bundle id `com.overdeck.computer-use`, the adapted Orca helper.
- **Installed helper**: the copy extracted to `~/.overdeck/computer-use/macos/Overdeck Computer Use.app`. TCC grants attach to this copy's identity, so it must not move.
- **Helper zip**: `native/computer-use-macos/dist/overdeck-computer-use-macos.zip` (+ `.sha256`), built in CI and shipped in the npm tarball.
- **Daemon**: the helper running in `--agent` mode, shared by all `pan computer` calls on the machine.
- **Ad-hoc signed**: `codesign --sign -`. Runs on Apple Silicon and can receive TCC grants, but the grant is tied to the exact binary (cdhash), so every helper change requires granting permission again.
- **Developer ID signed**: signed with an Apple "Developer ID Application" certificate and notarized. Grants survive helper updates.

## Decisions

- **D-1 Ship the helper in the npm package, not only in the desktop app.** It must work from `npx @overdeck/core` (operator requirement 2026-11-17). Setup extracts the zip with `/usr/bin/ditto -x -k <zip> <dir>` into the installed-helper location. A newer zip (sha256 differs from `~/.overdeck/computer-use/macos/installed.sha256`) is re-extracted by setup, and Settings says permissions may need granting again.
- **D-2 Signing.** CI signs ad-hoc by default. When the secrets `MACOS_CERTIFICATE`, `MACOS_CERTIFICATE_PWD`, `APPLE_API_KEY`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER_ID` exist, it signs with the Developer ID identity (hardened runtime, timestamp, empty entitlements) and notarizes the zip with `xcrun notarytool submit --wait` then `xcrun stapler staple` on the `.app` before zipping. Ad-hoc works with no cost; Developer ID only spares the operator re-granting permissions after updates. Setting up the certificate is out of scope (operator's Apple account); document how in WI-8.
- **D-3 One daemon per machine, idle exit.** `pan computer` is one process per command but the helper's element-index cache must survive between commands, so the daemon outlives the CLI. Change the lifetime rule: exit after **10 minutes without a request**, on `terminate`, or if never claimed within 30 s of launch. Remove "exit when the last authenticated connection closes".
- **D-4 Launch through LaunchServices** so TCC treats the helper as its own app, not as part of Terminal/node: `/usr/bin/open -n -g -a "<installed helper>" --args --agent <socket> --token-file <token>`. **Implementation checkpoint** (WI-7): confirm System Settings lists "Overdeck Computer Use" (not Terminal) when it asks for Accessibility. Fallback: spawn `Contents/MacOS/<exe>` directly, detached, and record in the PR that grants attach to the parent terminal app (document it).
- **D-5 Trust model:** replace Orca's bundle-ID and sidecar-path peer check with: (a) the token must match, and (b) the peer's uid (`getpeereid` / `LOCAL_PEERCRED`) must equal the helper's own uid. The socket stays 0600 inside a 0700 directory. The token is 32 random bytes (hex), written once to `~/.overdeck/computer-use/macos/agent.token` with mode 0600 and kept (multiple CLI processes connect over time); the helper reads it at startup.
- **D-6 Socket path:** `/tmp/overdeck-cu-<uid>/agent.sock` (directory mode 0700, created if missing; refuse to use it if it exists and isn't owned by the current uid). Do **not** use `os.tmpdir()`: it follows `TMPDIR`, which managed sessions may redirect, so the dashboard and each agent could compute different paths, and long paths can pass the 104-byte Unix socket limit. `/tmp` on macOS is short and environment-independent. It is ephemeral runtime state, so the no-`/tmp` rule (about files you need later) doesn't apply.
- **D-7 Protocol adapter in TypeScript, helper protocol unchanged.** `commands.ts` keeps building Linux-shape operations; a darwin adapter maps them to the helper's methods and params (WI-3). This keeps one CLI and one set of command builders.
- **D-8 Rename user-visible Orca strings** in the helper (permission window copy, usage descriptions, the exit-13 message) to Overdeck. Keep code identifiers unchanged where they aren't user-visible, to keep upstream diffs small.
- **D-9 Setup steps (darwin provider):** `install-packages` labeled "Install the Overdeck Computer Use helper" (no password, extracts the zip; skipped when installed and current); `grant-permissions` labeled "Allow Accessibility and Screen Recording" — runs `open -n -a <helper> --args --permissions` (Orca's own setup window, which opens the two Settings pages) and returns `{ status: 'waiting', message: 'Switch on "Overdeck Computer Use" in the two System Settings pages that opened, then press Continue.' }` until both permissions read granted, then `done`.
- **D-10 Blocked shortcuts:** port `MACOS_RULES`; darwin provider sets `blockedKeyPlatform: 'mac'`.
- **D-11 Source checkouts:** when the zip is absent (a dev checkout running from source), `install-packages` builds the helper locally with `npm run build:computer-macos` if `swift` is on PATH (Xcode Command Line Tools); otherwise it fails with `command: xcode-select --install`.
- **D-12 Port records:** every vendored file gets the port header (`//` for Swift) and a record in `scripts/upstream-ports.json`. Modified files say so on a third header line: `// modified for Overdeck: <one-line summary>`. Verified: `scripts/upstream-port-diff.sh` `check()` (lines 72–122) only requires the header line and the `// upstream: <path> @ <commit>` line somewhere in the first 10 lines, so the extra line passes. `Package.swift` must keep `// swift-tools-version: 6.0` as line 1; its two header lines go on lines 2–3.
- **D-13 npm tarball hygiene:** add `"!native/computer-use-macos/.build"` to `package.json` `files` so a local Swift build never ships.

- **D-14 Session latch removed (completes D-3).** `AgentSessionOwnership.swift` sets `sessionClosed = true` when the last authenticated connection closes, and `registerConnection` then returns `.rejected` for every later connection. With one daemon shared by many short CLI processes, the second `pan computer` call would be refused. Remove `sessionClosed` entirely: an authenticated connection is always `.claimed` (first) or `.retained` (later); `disconnect` never ends the daemon. Core test: connect A (claimed) → disconnect A → connect B returns `.retained`, not `.rejected`.
- **D-15 Per-holder index cache.** The helper namespaces its snapshot cache by `params.session` (`snapshotNamespace`, `main.swift` ~1852). The adapter always sends `session: <holderKey>` (the same `holderKey()` from `lease.ts` that `run.ts` uses), so two agents sharing the daemon never resolve each other's element indexes.
- **D-16 Error mapping.** Widen `ComputerUseErrorCode` (`src/lib/computer-use/errors.ts`) with exactly one new code, `permission_denied`. The daemon client maps helper `{ok:false, error:{code,message}}` as: `permission_denied` → `permission_denied` with message `<helper message> Finish setup in Settings → Computer Use.`; `invalid_argument` → `invalid_argument`; `element_not_found` → `element_not_found`; every other code (`app_not_found`, `app_blocked`, `background_unavailable`, `window_not_found`, `window_stale`, `window_not_focused`, `value_not_settable`, `element_not_clickable`, `element_not_enabled`, `action_not_supported`, `action_timeout`, `accessibility_error`) → `helper_error` with message `<code>: <message>` so the helper's code stays visible to agents and the skill.
- **D-17 Stale socket and launch race.** The helper's `bindSocket` fails with EADDRINUSE when a socket file from a crashed daemon remains (`main.swift` 4573–4617; it never unlinks). On ECONNREFUSED the client `lstat`s the path and, only if it is a socket, unlinks it before launching. `connectOrLaunch` runs only inside `withDesktopLock` (runComputerOperation already holds it; readiness probes use PAN-5461's `tryWithDesktopLock`), so two CLI processes never run `open -n` at once.
- **D-18 Permission status file location and shape.** The file (and `--permission-status` stdout) is `{"accessibility":"granted|not-granted","screenshots":"granted|not-granted"}` (`main.swift` 4817–4830); `screenshots` means Screen Recording. `--permission-status-file` writes to `~/.overdeck/computer-use/macos/permission-status-<uuid>.json` (not `/tmp`; it is read back), removed after reading or on timeout.
- **D-19 macOS CI before a PR exists.** The work agent's host is Linux and cannot run `swift`. `computer-use-macos.yml` triggers on `push` to `feature/**` with the path filters, on `pull_request`, and on `workflow_dispatch`, so every pushed Swift change gets a macOS run; the agent watches it with `gh run watch`. Workflow files are pushed over SSH (`git push git@github.com:eltmon/overdeck.git HEAD`) because the gh OAuth token lacks the `workflow` scope.
- **D-20 Tolerant CI permission assertions (checkpoint).** GitHub's macOS runners may pre-grant TCC permissions. The CI step asserts `--permission-status` prints valid JSON naming both permissions, and logs (does not assert) their values; `getAppState` against Finder must return either `ok:true` or `permission_denied`, and anything else fails. `handshake` must succeed in all cases.

## Requirements

### Functional
- **FR-1** `providerFor('darwin')` returns the darwin provider; `pan computer capabilities --json` on macOS 14+ reports the helper handshake.
- **FR-2** All `pan computer` subcommands work on macOS against native apps with the same flags and output shape as Linux; actions include `delivery`.
- **FR-3** Darwin readiness checks, in order: `macos-version` (≥ 14), `helper` (installed and current), `accessibility` (granted/not), `screen-recording` (granted/not), `handshake`. Permission status comes from launching the installed helper with `--permission-status-file` via `open -n -g` (Orca's method) and polling the file 50 × 100 ms.
- **FR-4** Settings → Computer Use on macOS: Off state says "Setup installs the Overdeck Computer Use helper and opens two macOS permission pages. Switch on Overdeck Computer Use in each, then press Continue." and runs D-9; the waiting state shows "Continue"; the On state lists Accessibility and Screen Recording rows with their status; re-checks on window focus.
- **FR-5** Blocked macOS shortcuts are refused unless `--allow-system-shortcut`.
- **FR-6** After an Overdeck update that changes an ad-hoc-signed helper, readiness reports the permissions as not granted and the On card shows amber "Needs attention" with "macOS asks you to allow the updated helper again." and a "Fix setup" button.
- **FR-7** `npx @overdeck/core` (a published tarball) contains the helper zip and its sha256 file.

### Non-functional
- **NFR-1** No sync child processes in server-reachable code; promisified `execFile`/`spawn` only.
- **NFR-2** Fake timers for socket-wait and polling tests.
- **NFR-3** Unix-socket client code is unit-tested against a fake NDJSON server (a `net.Server` on a temp socket in the test).
- **NFR-4** No new route-scope rows; reuse PAN-5461 routes.

### WI-3 mapping table (verified against `main.swift` @ c6b9ac9549b, 2026-11-17)

Requests (`toMacRequest(operation, holderKey)` → `{ method, params }`). `params` = every operation field except `tool`, renamed, plus `session: holderKey` (D-15):

| Linux `tool` | macOS method | field renames |
| --- | --- | --- |
| `handshake` | `handshake` | none |
| `list_apps` | `listApps` | none |
| `list_windows` | `listWindows` | none (`app`) |
| `get_app_state` | `getAppState` | `root` (element record) → `rootElementIndex: root.index` |
| `click` | `click` | `element` → `elementIndex`; `mouse_button` → `mouseButton`; `click_count` → `clickCount`; `x`,`y`,`modifiers` unchanged |
| `perform_secondary_action` | `performSecondaryAction` | `element` → `elementIndex`; `action` unchanged |
| `set_value` | `setValue` | `element` → `elementIndex`; `value` unchanged |
| `type_text` | `typeText` | `element` → `elementIndex`; `text` unchanged |
| `press_key` / `hotkey` | `pressKey` / `hotkey` | `key` unchanged |
| `paste_text` | `pasteText` | `text` unchanged |
| `scroll` | `scroll` | `element` → `elementIndex`; `direction`,`pages`,`x`,`y` unchanged |
| `drag` | `drag` | `fromElement` → `fromElementIndex`; `toElement` → `toElementIndex`; `from_x`/`from_y`/`to_x`/`to_y` → `fromX`/`fromY`/`toX`/`toY` |

`app`, `windowIndex`, `restoreWindow`, `noScreenshot` pass through unchanged (the helper reads those exact names). An unknown `tool` throws `invalid_argument`.

Responses (`fromMacResponse(method, result, request)` → Linux-shape `HelperResponse`):

- `handshake` → `{ ok: true, capabilities: result }` (Linux `run.ts` reads `response.capabilities`).
- `listApps` (`{ apps: [{ name, bundleId, pid, … }] }`) → `{ ok: true, apps: [{ name, bundleIdentifier: bundleId ?? undefined, pid }] }`.
- `listWindows` (`{ app, windows: [{ index, title, isMinimized, … }] }`) → `{ ok: true, app: result.app, windows: result.windows }` (fields already match `format.ts`'s `windows`).
- `getAppState` (`{ snapshot, screenshot, screenshotStatus }`) → `{ ok: true, snapshot: toRawSnapshot(result, request) }`.
- Every action method (`{ snapshot, screenshot, screenshotStatus, action }`) → `{ ok: true, action: toHelperAction(result.action), snapshot: toRawSnapshot(result, request) }`.

`toRawSnapshot` builds `RawSnapshot` (`src/lib/computer-use/format.ts` lines ~23–35) plus the screenshot fields `saveScreenshot` reads:

| `RawSnapshot` field | from macOS |
| --- | --- |
| `snapshotId` | `snapshot.id` |
| `app` | `{ name: snapshot.app.name, bundleIdentifier: snapshot.app.bundleId ?? undefined, pid: snapshot.app.pid }` |
| `windowTitle` | `snapshot.window.title` (empty string → `null`) |
| `windowIndex` | `request.params.windowIndex ?? null` (the helper returns a window id, not an index) |
| `windowBounds` | `{ x, y, width, height }` from `snapshot.window` |
| `treeLines` | `snapshot.treeText` split on `\n`: drop the header (every line up to and including the first empty line) and the footer (the last empty line and everything after it). What remains is the element lines, with their leading tabs kept. |
| `focusedSummary` | the footer line: `The focused UI element is X.` → `X`; `No UI element …` → `null` |
| `selectedText` | `null` |
| `truncation` | `snapshot.truncation` |
| `elements` | `[{ index: n }]` for every tree line matching `/^\t*(\d+)(?:\s|$)/` (the leading index `SnapshotRenderHeuristics.line` writes). Required: `elementRecord()` resolves indexes from this list before the helper is called, and `renderResultJson` reads `elements.length`. Do not derive it from `elementCount`; indexes are not contiguous on subtree reads. |
| `screenshotPngBase64`, `screenshotWidth/Height/Scale` | `screenshot.data`, `.width`, `.height`, `.scale`; all `null` when `screenshot` is `null` |
| `screenshotError` | `{ message: screenshotStatus.message }` when `screenshotStatus.state === 'failed'`, else `null` |

`toHelperAction(action)` → `{ path, actionName, fallbackReason, delivery, verification }` where `verification` is `null` when absent, else `{ state, reason: v.reason ?? (v.property ? \`${v.property} read back\` : 'none') }` (macOS sends `{state, property}` for verified actions; `renderActionLine` prints `.reason`). `HelperAction` in `format.ts` gains `delivery?: 'background' | 'foreground'`; `renderActionLine` appends `, delivery: <value>` when present. The JSON output already passes `action` through, so `delivery` appears there (FR-2).
