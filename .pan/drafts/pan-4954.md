**What this delivers.** A real, installable, MIT npm package at `integrations/openclaw/` (`@overdeck/openclaw`, version `0.1.0`) that connects an OpenClaw gateway to Overdeck. The Overdeck MCP tools reach OpenClaw through OpenClaw's own MCP client (`mcp.servers.overdeck`, `transport: "streamable-http"`), pointed at the Overdeck connector (default) or at the dashboard over Tailscale. The plugin adds what MCP cannot: a per-turn "needs you" summary (`before_prompt_build`), the bundled `overdeck` skill, and two native chat tools, `overdeck_pending` and `overdeck_answer`. It also records checkpoint CP-7 (the current OpenClaw release) in `integrations/openclaw/docs/verification.md`.

## Glossary

- **OpenClaw:** a self-hosted agent gateway. Its plugins are npm packages with an `openclaw.plugin.json` manifest and a JavaScript entry. The current release is **2026.10.10** (npm `latest`, checked 2026-11-04; `extended-stable` is 2026.9.36, `beta` 2026.11.5-beta.1). The local checkout `~/Projects/OpenClaw` is **2026.5.6** (HEAD `6110e47be0`, 2026-05-07).
- **Gateway:** the long-running OpenClaw process that hosts agents, channels (Slack, Telegram and others) and plugins. One gateway can serve many chat sessions.
- **Manifest:** `openclaw.plugin.json` in the plugin root. OpenClaw reads it before loading plugin code. Only documented fields are read.
- **Plugin entry:** the JavaScript module named by `package.json#openclaw.extensions`. Its default export is a plugin definition `{ id, name, description, configSchema, register }`.
- **`definePluginEntry`:** the OpenClaw SDK helper (`openclaw/plugin-sdk/plugin-entry`) that builds a plugin definition. In 2026.10.10 it is a pure function that returns `{ id, name, description, configSchema, register }` (plus optional `kind`, `reload`, `nodeHostCommands`, `securityAuditCollectors`); see Facts F-4.
- **`contracts.tools`:** the manifest list of native tool names the plugin owns. Runtime `api.registerTool(...)` calls must match it.
- **`before_prompt_build`:** an OpenClaw plugin hook that runs before each agent turn's prompt is built. A handler may return `{ prependContext: string }` to add text in front of the turn's context.
- **`mcp.servers`:** the OpenClaw config block of outbound MCP servers. The embedded OpenClaw runtime exposes their tools to agents under provider-safe names `<server>__<tool>`, for example `overdeck__list_conversations`.
- **Overdeck MCP server:** the tool module in `src/lib/mcp/`. Over HTTP it is sessionless and answers JSON (`enableJsonResponse: true`).
- **Overdeck connector:** `pan mcp connector serve` (W-CONN2). It runs next to a bot, pairs with one Overdeck machine, and serves the Overdeck MCP tools on `http://127.0.0.1:7466/mcp`, guarded by a local bearer token (`odl_<64 hex>`, stored in `<connectorHome>/local-token`).
- **Local token:** the connector's `odl_` bearer token. In this package's config it is `localToken`. On the Tailscale route the same field carries an `odk_` access token instead.
- **Pending item:** one thing that waits for the operator, as returned by the Overdeck tool `list_pending_input`: a permission prompt, a question, a plan approval, a menu, or an agent request.
- **Item ref:** an 8-hex-character fingerprint of one pending item (D-6). `overdeck_answer` refuses to answer unless the item at the given number still has the same ref.
- **CP-7:** implementation checkpoint 7 of the parent PRD: confirm the plugin's assumptions against the current OpenClaw release.
- **Scratch directory:** `$HOME/.overdeck/tmp/pan-4954-cp7/`. The live CP-7 check keeps every OpenClaw file there, never in the repo and never in `/tmp` (repo rule `no-tmp-scratch`).

## Requirements

### Functional

- **FR-1 Package.** `integrations/openclaw/` is an npm package `@overdeck/openclaw` version `0.1.0`, MIT, ESM (`type: module`), with its own `package-lock.json`, `tsconfig.json`, `vitest.config.ts`, `README.md`, `PUBLISHING.md`, `CHANGELOG.md`, `LICENSE` and `docs/verification.md`. It is not a root workspace. `npm ci && npm run build && npm test` succeeds in that directory on Node 22.
- **FR-2 Manifest and entry.** `openclaw.plugin.json` uses only documented 2026.10.10 manifest fields, declares `contracts.tools: ["overdeck_pending", "overdeck_answer"]`, and its `configSchema` deep-equals the entry's `configSchema`. `package.json#openclaw.extensions` is `["./dist/index.js"]`. The entry's default export is a plain plugin definition with `id: "overdeck"`.
- **FR-3 Config and URL rule.** Config keys are `connectorUrl` (default `http://127.0.0.1:7466/mcp`), `localToken`, `summary` (default `true`), `allowAnswers` (default `false`). The plugin accepts `connectorUrl` only when its protocol is `https:`, or `http:` with hostname exactly `127.0.0.1`, `localhost` or `[::1]`, and it has no user name or password.
- **FR-4 Always register the contracted tools.** `register` registers both native tools on every load. When the URL is refused or `localToken` is missing, each tool answers a setup error text and the summary hook is not registered.
- **FR-5 Summary hook.** When `summary` is true and the client is set up, a `before_prompt_build` handler fetches `list_pending_input` at most once per 5 minutes, and on the turn it fetched and found pending items it returns `{ prependContext }` with at most 5 items of at most 300 characters each, labeled as data, not instructions. On any error it returns nothing.
- **FR-6 `overdeck_pending`.** Takes no parameters, calls `list_pending_input`, and returns a numbered list; each line carries the item number, its ref, label, machine, kind, prompt and the valid choices, or the reason it cannot be answered from OpenClaw.
- **FR-7 `overdeck_answer`.** Takes `{ item: integer, ref: string, choice: string }`. It re-reads `allowAnswers` on every call and refuses without any network call when it is false. Otherwise it lists again, refuses unless item `item` exists and has ref `ref`, maps the item kind and choice to exactly one Overdeck answer tool with only named arguments, calls it, and returns a sentence naming what it answered.
- **FR-8 MCP tools through OpenClaw.** The README tells the operator to add `mcp.servers.overdeck` with `transport: "streamable-http"`; the config blocks in the README are byte-equal to `openclawConfig({ reach: 'connector', url: CONNECTOR_LOCAL_URL })` and `openclawConfig({ reach: 'tailscale', url: TAILSCALE_PLACEHOLDER_ORIGIN + '/mcp' })`.
- **FR-9 CP-7 recorded.** `integrations/openclaw/docs/verification.md` records CP-7 (a), (b) and (c) with the OpenClaw version, the date, the command and the result.
- **FR-10 Documentation.** `configuration/mcp.mdx` "Connect a bot" gains an OpenClaw paragraph with the connector config block and a link to the package.

### Non-functional

- **NFR-1 No secret leaks.** The local token is never a tool parameter, never logged, never in a returned text, and never in a thrown error message. Error texts name at most `url.origin`. No `odk_`, `odl_` or `odr_` literal followed by hex appears in any committed package file (parent NFR-2).
- **NFR-2 Named fields only.** Every outgoing tool-call argument object is built from named fields; no spread of model input (security review W2).
- **NFR-3 Portable schemas.** Every JSON Schema the plugin registers uses only the keys `type`, `properties`, `required`, `items`, `enum`, `description` (no `anyOf`, `oneOf`, `const`, `format`, `minimum`, `maximum`, `additionalProperties`).
- **NFR-4 Fake timers.** The 5-minute throttle and the request timeout are tested with `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`; no real sleeps (repo rule `fake-timers-for-retry-tests`). Request timeouts use `AbortController` plus `setTimeout`, never `AbortSignal.timeout` (which ignores fake timers).
- **NFR-5 Light and Node 22.** The package has zero runtime dependencies and does not install `openclaw` in development. Dev dependencies are `typescript`, `vitest`, `@types/node` only.
- **NFR-6 Module size.** Every source file stays under 300 lines; every test file under 400.
- **NFR-7 Data, not instructions.** Every text the plugin builds from Overdeck data (summary, pending list) says it is data and collapses whitespace to single spaces, so an item cannot forge extra lines.

## Decisions

- **D-1 Plain-object entry, no `openclaw` import (changes parent D-22's "`definePluginEntry`").** `src/index.ts` default-exports a plain `OpenClawPluginDefinition` typed by local structural interfaces in `src/openclaw-api.ts`. Why: `definePluginEntry` only builds that object (F-4); importing it needs the `openclaw` package at build, test and run time, which is 274 MB with 68 dependencies and requires Node ≥ 24.16 (F-16) while this repo and its CI run Node 22 (F-12); and a local-path install would not resolve the SDK (F-15). The MYN model works this way (F-4). The live CP-7 check runs the real host, which proves the shape.
- **D-2 `package.json` carries the compatibility contract.** `openclaw.extensions: ["./dist/index.js"]`, `openclaw.compat.pluginApi: ">=2026.5.6"`, `openclaw.install.minHostVersion: ">=2026.5.6"`, `peerDependencies: { "openclaw": ">=2026.5.6" }` with `peerDependenciesMeta: { "openclaw": { "optional": true } }` (so `npm ci` never installs the host). Why 2026.5.6: the parent PRD's facts were read from that checkout and 2026.10.10 is checked here; nothing older was checked. The parent's `>=2026.5.0` is raised to what was verified.
- **D-3 Manifest has documented keys only.** Drop the parent draft's `entry` and `license` keys (not manifest fields, F-13); the entry is `package.json#openclaw.extensions` (F-14) and the license is `package.json#license`. Final manifest in WI-9.
- **D-4 `localToken` is not `required` in `configSchema`.** Why: `openclaw plugins install` enables a plugin by default, and a required field missing from config is a validation error for the whole OpenClaw config. The plugin instead answers "localToken is not set" from its tools (FR-4). The parent draft had `"required": ["localToken"]`.
- **D-5 The tools always register (FR-4).** `contracts.tools` must match runtime registrations (F-13), so `register` never returns early. A refused URL or a missing token becomes the tools' answer text and a `logger.warn` line without the token.
- **D-6 `overdeck_answer` takes `{ item, ref, choice }` (adds `ref` to the parent's `{ item, choice }`).** Why: the pending list can change between `overdeck_pending` and `overdeck_answer` (a prompt is answered in the dashboard, a new one arrives). Without a check, item 3 could answer a different prompt than the one the user saw. The ref is the first 8 hex characters of SHA-256 over `JSON.stringify([kind, targetKey, key])` (see WI-5), so it is stable for one prompt and different for any other. The tool refuses unless the current item `item` has exactly that ref.
- **D-7 `overdeck_answer` answers only single-question prompts.** A question item with more than one question is listed with the reason "this prompt has N questions; use the answer_question tool or the Overdeck dashboard". Why: `choice` is one string; splitting it into several answers would need a separator a free-text answer could contain. The MCP tool `overdeck__answer_question` stays available for multi-question prompts.
- **D-8 Choice grammar** (exact rules in WI-6): permission `allow-once | allow-always | deny`; agent permission `allow | deny`; question and Pi ask: an option number, an exact option label (case-insensitive), or free text; Codex approval and menus: an option number; plan: `approve-auto | approve-manual | reject-ultraplan | reject-feedback: <text>`.
- **D-9 Summary throttle semantics.** The hook fetches when at least 5 minutes have passed since its last fetch attempt (successful or not), and returns `prependContext` only on the turn that fetched and found at least one item. Turns in between get nothing, so the summary does not repeat every turn. The timer is per gateway process, not per chat session.
- **D-10 Timeouts.** Tool calls time out after 10 s; the summary hook's call times out after 5 s, so a slow connector never holds a turn longer than that.
- **D-11 Not used in 0.1.0:** manifest `mcpServers` (F-22: only a stdio example is documented and a static definition cannot read `connectorUrl` from plugin config), OpenClaw's MCP OAuth (`auth: "oauth"`; bots reach Overdeck through the connector or Tailscale, parent D-3), and the CP-7(a) native proxy fallback (built only if CP-7(a) fails, as a follow-up issue; see WI-12).
- **D-12 Tests in two places.** Behavior tests live in the package (`integrations/openclaw/tests/*.test.ts`, run by `npm test`). Package-shape tests that must run in CI today live at `tests/unit/integrations/openclaw.test.ts` (root vitest, F-8), following `grok-bot.test.ts`.

## Hazards

- **H-1 Summary in shared channels.** The summary goes into every agent turn of the gateway, which may serve group chats. Mitigation: the README privacy note and `summary: false`; the summary carries labels and prompt text only, never tokens.
- **H-2 Prompt injection.** Conversation titles, questions and plans are written by agents. Every text is single-lined and labeled as data (NFR-7); the shared skill says the same; answers need the user's explicit choice, `allowAnswers: true` and `approve`.
- **H-3 Answering the wrong prompt.** Handled by the ref check (D-6).
- **H-4 Plugin API drift.** OpenClaw marks its plugin APIs experimental. The local structural types (D-1) do not track the SDK, so the live `plugins validate` and `plugins inspect` checks (WI-12) are the guard; `openclaw.install.minHostVersion` keeps older hosts away.
- **H-5 CP-7 side effects.** The probe token is a real token on the operator's dashboard: read-only scopes, never written to a file, revoked in step 9.
- **H-7 Token-shaped test fixtures.** Any fake `odl_`/`odk_` token in a test is built at runtime (`['odl', 'a'.repeat(64)].join('_')`), never written as one literal: the WI-10 secret scan, the WI-12 grep and GitHub push protection (GH013) all match literals.
- **H-6 The connector route is not run live in this issue.** It needs the operator's overdeck.ai sign-in. The dashboard `/mcp` probe covers the same transport (F-1); `verification.md` lists the connector check as not run with its steps.
