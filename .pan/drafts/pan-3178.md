# PAN-3178 — First-class worktrees & diffs: +/− changes badge, dedicated Changes surface, conversation worktrees

**Issue:** [PAN-3178](https://github.com/eltmon/overdeck/issues/3178)
**Status:** approved direction (operator picked **Option A**, 2026-07-26); details refining in-issue
**Mockup:** `drafts/pan-3178-mockup.html` (interactive, 3 options — Option A selected)

---

## 1. Glossary

- **Changes badge** — the compact `+N −M` indicator (additions/deletions) rendered in issue and conversation chrome. Follows the `pan-style-guide` badge formula — **not a pill**.
- **Changes surface** — the dedicated full-width diff view (left file rail / center diff / optional right rail) shared by issue detail and conversations. The deliverable at the heart of this PRD.
- **Workspace diff-stat** — per-file and total `+N −M` computed from a workspace worktree: three-dot `main...HEAD` **plus** uncommitted working-tree changes. Works with or without a PR.
- **Three-dot diff** — `git diff main...HEAD`: changes on the feature branch since the merge-base, i.e. "what this branch did", unaffected by main moving forward.
- **Conversation worktree** — a git worktree created at conversation-creation time for project-scoped conversations: `workspaces/conv-<slug>/` on branch `conv/<slug>`.
- **Polyrepo project** — a project whose `workspace.type === 'polyrepo'`; the workspace is a wrapper directory containing one worktree (or symlink) per repo. The wrapper itself is not a git repo.
- **Cohort / layer** — CodeRabbit Change Stack terms. A cohort groups related changes; layers inside it are the suggested reading order, each anchored to specific diff line ranges with its own summary. Phase 2 vocabulary.
- **pierre** — `@pierre/diffs`, our vendored diff renderer (Apache-2.0, Shiki-based).

## 2. Problem statement

Worktrees and diffs are how the operator answers the most frequent question in the system — *"what did the agent actually change?"* — and today that answer is buried, stale, or broken:

1. **Issue pages show no change signal at a glance.** No `+/−` indicator exists anywhere near the issue title, on any density (drawer, cockpit, rail). The operator must open the Files tab (PR-backed, so it shows nothing before a PR exists and misses uncommitted work) or the cockpit Code tab.
2. **Conversation diff UX is broken in three distinct ways** (operator screenshots 2026-07-26): (a) reaching a diff requires opening the "Changed files" folder row inside a specific message; (b) the secondary pane it opens sometimes renders "No completed turns yet"; (c) the pane **leaks across conversation switches** — switch conversations and the previous conversation's diff pane stays open showing stale or empty content.
3. **Conversations have no worktrees.** `handleConversationCreate` resolves `cwd` to the project root or `~/Projects` (`src/lib/overdeck/conversation-runtime.ts:776-780`, `src/lib/default-cwd.ts:16`). Conversation edits land in the shared primary checkout — the exact worktree-discipline hazard the global rules warn about — or in no isolation at all, with no clean diff story.
4. **`@pierre/diffs` is under-used.** We render only `FileDiff` + `Virtualizer` + `parsePatchFiles` (`src/dashboard/frontend/src/components/DiffPanel.tsx:6-7`). The installed package already ships split layout, hunk expansion, a line-annotation framework, accept/reject hunks, merge-conflict UI, and virtualized multi-file components. We are pinned at 1.1.22; npm latest is 1.2.12 (2026-07-24) with 1.3.0-rc.1 available. The operator has approved going to RC/beta.

## 3. Research summary (what we are copying, and from whom)

**Reference parallel-agent workspace UX** (operator screenshots): every workspace row in the sidebar carries a live `+N −M` badge; one click opens a three-panel changes view — left "Changes N / All files" rail with per-file `+N −M`, center syntax-highlighted diff with collapsible unchanged-region gaps ("18 unchanged lines"), terminal at bottom. The badge is always visible; the diff is always one click away.

**CodeRabbit Change Stack** (changelog + launch blog, May–July 2026): replaces the flat alphabetical file list with *cohorts* (related changes grouped) and *layers* (reading order a senior reviewer would pick), each layer anchored to diff line ranges with an AI summary; three-panel layout (cohort/layer nav left, diff center, synced summary right); Semantic/Unified/Split diff views; Code Peek (click identifier → definitions/usages); J/K/Z keyboard navigation. Closed source — no embeddable library exists (confirmed 2026-07-26: SaaS or 500+-seat Enterprise container only). **We copy the interaction model, not the product.**

**The same reference UX, part 2 — in-message file chips and sub-tabs** (operator screenshots 2026-07-26): changed files also appear **inline in the message flow as visible file chips** (`index.html +170 −7`) attached to the message that made them — never behind a folder row. **Hover** shows a floating mini-diff card (hunk gaps, syntax highlighting, one file). **Click** opens that file's diff as a **sub-tab inside the conversation pane's own tab strip** (next to the conversation tab), with unified/split toggle. The workspace-level Changes panel lives separately in the rail. Per-message turn attribution is preserved — the chip says "this turn touched these files."

**What `@pierre/diffs` 1.1.22 (installed) already provides** — verified against `node_modules/@pierre/diffs/dist/react/index.d.ts` exports: `FileDiff`, `MultiFileDiff`, `PatchDiff`, `VirtualizedFileDiff`, `AdvancedVirtualizedFileDiff`, `Virtualizer`, `parsePatchFiles`, `WorkerPoolContextProvider` (already wired in `DiffWorkerPoolProvider.tsx`), `DiffLineAnnotation`/`LineAnnotation` (inline comments on any line/side), `HunkExpansionRegion`/`ExpansionDirections` (collapsible gaps), `DiffAcceptRejectHunkConfig`, merge-conflict regions (`MergeConflictRegion`, `RenderMergeConflictActions`), line selection, custom file-header renderers, SSR entrypoint. **The rendering layer for everything in this PRD already exists in the repo.** What no library provides is the organization layer (AI cohorts/summaries) — that is Phase 2 application code.

## 4. Requirements

### Functional

- **FR-1 — Workspace diff-stat endpoint.** `GET /api/workspaces/:issueId/diff-stats` returns per-repo, per-file and total additions/deletions for the workspace worktree: `git diff --numstat main...HEAD` + uncommitted (`git diff --numstat` unstaged + `--staged`) + untracked file count. Polyrepo-aware via `resolveWorkspaceRepoRootsSync` (`src/lib/project-repos.ts:169`). Includes `ahead`, `behind`, `branch`, `dirty`, `base`, `computedAt`.
- **FR-2 — Conversation diff-stat endpoint.** `GET /api/conversations/:name/diff-stats`, same shape, backed by the existing `groupFilesByRepo` machinery (`src/lib/overdeck/conversation-diffs.ts:69`).
- **FR-3 — Changes badge.** A shared `ChangesBadge` component rendering `+N −M` (git-convention green/red text, style-guide badge formula, not a pill). Placements: (a) issue detail header next to the title on **all densities** (drawer `IssueDrawer.tsx:99-132`, cockpit `IssueMissionControl.tsx:508-551`, shared `IssueDetail.tsx`), (b) kanban card footer (`KanbanCards.tsx:801-829`), (c) **conversation header meta row, immediately after the branch/worktree chip** — the `● active · Local main · Cursor · <date-id>` row at the top of the conversation view (operator screenshot 2026-07-26). When the conversation has a conv worktree, the badge sits next to the `conv/<slug>` chip; when it doesn't, it sits next to the `Local main` chip. Clicking navigates to the Changes surface. Data source priority: workspace diff-stat → PR details (`issues.ts:757`) → hidden. Hidden when zero changes and clean; untracked shown as a separate muted `N untracked` suffix, never folded into `+N`.
- **FR-4 — Changes surface.** A shared `ChangesSurface` component: left rail = file list with per-file `+N −M`, search/filter, grouped by repo for polyrepo; center = `@pierre/diffs` virtualized multi-file diff with **unified/split toggle**, hunk expansion enabled, custom file headers showing per-file stats; keyboard navigation (`j`/`k` next/prev file or hunk, `[`/`]` unified/split). Full patch fetched from a `?full=true` variant of the diff-stat endpoints (or existing full-diff routes where they already fit).
- **FR-5 — Issue detail integration + no-loss audit.** Add a **Changes** tab to `ISSUE_DETAIL_TABS` (`IssueDetail.tsx:49-58`) rendering `ChangesSurface`; **absorb** the Files tab (`IssueDetail.tsx:369-374`) and the cockpit Code tab's `ChangedFilesView` (`IssueMissionControl.tsx:637-642`). Per the no-loss-audit rule: enumerate every command/action/view the Files tab, Code tab, and `GitHubCiPanel` expose, prove each has a home in the new surface or is explicitly retired, and lock it with a focused test. `GitHubCiPanel` (CI checks) is **not** a diff affordance — it keeps its own home; only `ChangedFilesView` is absorbed.
- **FR-6 — Conversation diff UX teardown + rebuild (chip/sub-tab model from the reference UX).** Delete the folder-row → secondary-pane flow entirely. In its place, three cooperating surfaces:
  1. **In-message changed-file chips (visible, not collapsed).** After each agent message that touched files, render one chip per file: `path +A −D`, with file-kind icon. Powered by the existing per-turn diff route (`conversations.ts:903`) — turn-scoped checkpoint data survives **as the attribution source for chips** ("this turn touched these files"); what dies is the turn-*navigation* UI ("Turn 2" pickers, checkpoint dropdowns).
  2. **Hover → floating mini-diff card.** Hovering a chip shows a floating card with that file's diff (hunk gaps, pierre rendering, one file only, capped height, scrollable). Pure peek — no actions, dismiss on mouse-out.
  3. **Click → file-diff sub-tab ("sub-sub-tab").** Clicking a chip opens the file's diff as a **sub-tab inside the conversation pane's own tab strip** (alongside the Conversation/Terminal/About tabs): `<file icon> path +A −D ✕`. The sub-tab body is the same pierre `FileDiff` component the ChangesSurface uses (per-file mode, unified/split toggle). Phase 1 renders diffs read-only — no Edit mode, no Viewed checkboxes (Cursor has them; we defer).
  Sub-tab state is keyed strictly to the active conversation id: switching conversations swaps or clears sub-tabs — **no state may survive a conversation switch** (regression test required; this is the leak from the operator screenshots). The aggregate "all changes" view for the conversation remains the Changes surface (FR-4), reached from the header badge; sub-tabs are the per-file, per-message path. The old in-message folder row and the leaking pane component are deleted.
- **FR-7 — Conversation worktrees (auto-create, best-effort).** On `handleConversationCreate` with a resolved `projectKey`, automatically create a git worktree at `workspaces/conv-<slug>/` on a new branch `conv/<slug>` (from the repo's default branch) and use it as the conversation `cwd`. **Creation is best-effort and never blocks the conversation:** if any prerequisite is missing — project root not a git repo, workspaces dir missing/unwritable, branch-name collision that can't be deduped, git error, or `conversations.worktrees: false` — the conversation is created normally without a worktree and the skip is recorded on the conversation record (`worktreeStatus: "skipped" | "failed"`, `worktreeSkipReason`). The badge then shows the no-worktree state per FR-3. A **"Create worktree" affordance** in the conversation header (visible whenever no worktree exists — skipped, failed, or pre-existing conversation) re-runs the same creation path on demand; because the harness cwd is fixed at spawn, the action is **"Create worktree & restart"** — it creates the worktree, updates the conversation record, and resumes the session in the new cwd.
- Monorepo: one worktree. Polyrepo: worktree the **primary repo only** at creation; additional repos are added lazily through the existing progressive-polyrepo machinery (`workspace-manager.ts:107-123` `addNewRepoToWorkspace`), mirroring `/workspace-add-repo`. No worktree for project-less conversations (`~/Projects` cwd stays). Config opt-out: `conversations.worktrees: false` (default **true**). Conv workspaces never get Docker devcontainer stacks. Cleanup: conversation archive/delete removes the worktree **only if clean** (`git status --porcelain` empty and no ahead commits); otherwise it surfaces the dirty state to the operator and keeps it. The issue reaper and workspace janitors must exclude `conv-*` workspace dirs from issue-keyed cleanup. Existing conversations are not migrated automatically — they get the "Create worktree & restart" affordance instead.
- **FR-8 — `@pierre/diffs` upgrade + adoption.** Bump to `^1.2.12` (evaluate `1.3.0-rc.1` changelog; RC acceptable per operator). Re-verify the `:host` override contract (overrides must be `:host` PURE accent colors — see `DiffPanel.tsx:38-71` and project memory). Adopt: `MultiFileDiff`/virtualized components as the single rendering path (retire bespoke file lists), hunk expansion by default, split/unified toggle, worker-pool highlighting everywhere. Line annotations and accept/reject are enabled behind component props for Phase 2 but no UI is built for them in Phase 1.

### Non-functional

- **NFR-1 — Performance.** Diff-stat p95 < 300 ms server-side per repo after warm cache. Server memoizes per workspace path for 5 s; client uses react-query with 15 s `staleTime` and invalidation on domain events (agent commit/activity events already flowing through the event router). Full-patch fetch is lazy — only when the Changes surface opens.
- **NFR-2 — No event-loop blocking.** All git calls async (`execAsync`/`spawn`); no `execSync` anywhere reachable from the dashboard server (repo rule). Diff-stat computation is off the read-model critical path.
- **NFR-3 — Style-guide compliance.** `pan-style-guide`: no pill badges, no decorative color, no green "running" agents, no cyan misuse. Green/red is reserved for the `+/−` signal pair only.
- **NFR-4 — No-loss audit gate.** FR-5's audit test must be green before merge; any affordance dropped from Files/Code tabs is named in the PR description.
- **NFR-5 — Worktree safety.** Conversation worktrees follow the same discipline rules as issue workspaces: never `git checkout` another branch inside them, never the primary checkout as cwd. Creation must be idempotent (existing dir + branch → reuse).

## 5. Decisions (made here, not left to the implementer)

1. **Option A is the chosen UX** (dedicated Changes surface). Option B (full CodeRabbit guided stack) is Phase 2 on the same surface; Option C (docked panel) is rejected — it repeats the "diff as an afterthought pane" mistake we are tearing out.
2. **Badge shows workspace state, not PR state**, whenever a workspace exists — it must reflect uncommitted work, because "what has the agent done *so far*" is the common case during active work. PR stats are the fallback for merged/closed issues without a live workspace.
3. **Three-dot `main...HEAD` + uncommitted** is the canonical comparison. Two-dot would drown the badge in upstream drift.
4. **Untracked files never inflate `+N`.** They render as `· N untracked` in muted text.
5. **Zero state hides the badge.** No `+0 −0` noise on untouched issues.
6. **Polyrepo conversation worktrees are lazy.** Primary repo at creation; the wrapper directory layout matches `workspace-manager/create.ts:223-264` so existing repo-resolution code (`resolveWorkspaceRepoRootsSync`) works unmodified. Rationale: conversations are exploratory; most touch one repo; eager multi-worktree creation multiplies cost and janitor surface for no benefit.
7. **Handoff/fork conversations get their own fresh worktree** from the default branch, unless `--cwd` is passed (unchanged override). They do **not** share the parent's worktree — sharing would couple two live sessions' uncommitted state.
8. **The Changes tab absorbs Files and Code's ChangedFilesView.** One diff home, not three. CI status stays with `GitHubCiPanel`.
9. **Server caching is a 5 s in-process memo, nothing durable.** No DB table, no read-model column for diff stats in Phase 1 — derived data, cheap to recompute, not worth a state plane.
10. **Phase 2 is explicitly out of scope here** and must be filed as a follow-up issue at Phase-1 merge time: AI cohort/layer manifest (generated by a cheap-tier agent pass over the full patch), per-range anchors rendered through pierre's `DiffLineAnnotation`, right-rail synced summaries, `Z` focus mode. Phase 1 design constraints that enable it: the left rail component accepts section groups (not just a flat file list), and the center diff exposes line-range anchors.
11. **The conversation badge lives in the header meta row, next to the branch/worktree chip** (operator direction 2026-07-26, screenshot of the `● active · Local main · Cursor` row) — not in the message flow. The in-message "Changed files" folder row becomes a link to the same surface and stops being the only path.
12. **Worktree auto-creation is best-effort and never blocks conversation creation** (operator direction 2026-07-26: "automatically create the worktree if possible"). Missing prerequisites record `worktreeStatus` + `worktreeSkipReason` on the conversation and creation proceeds; a "Create worktree & restart" header action covers skipped, failed, and pre-existing conversations.
13. **The file-diff sub-sub-tab ships in PAN-3178, not PAN-1990** (placement question, decided 2026-07-26). The sub-tab is diff UX — same renderer, same endpoints, same component family as the Changes surface — and must not be stranded behind [PAN-1990](https://github.com/eltmon/overdeck/issues/1990)'s schema/migration epic. The one piece that legitimately belongs to 1990 is **layout persistence**: when 1990's per-workspace layout state lands, the set of open file-diff sub-tabs becomes part of the persisted conversation/workspace layout. Cross-link both issues at implementation time.
14. **FR-7 absorbs [PAN-2085](https://github.com/eltmon/overdeck/issues/2085)** (auto-isolate conversations in a worktree — filed 2026-06-27, unstarted). 2085's competitor research adds two refinements adopted here: (a) **branch from `origin/main`, not local main** — the conv worktree's base is the fetched remote default branch when reachable, so conversations start from latest even when local main lags; (b) an **apply-or-discard lifecycle** — at conversation archive, a clean worktree's branch is offered as "apply to main via PR" or "discard"; dirty state is surfaced, never silently deleted. (The PR/apply path may be as thin as "open a PR from `conv/<slug>`" — no bespoke merge machinery in Phase 1.) 2085 is closed as superseded with a link here once this PRD lands.
