# PAN-4264 — GitHub API quota: measure per caller, surface it, back off on limits, stop wasted polling

**Issue:** https://github.com/eltmon/overdeck/issues/4264 (body plus the operator's 2026-09-27 15:07 UTC comment, which adds four telemetry work streams to this issue).
**Planned:** 2026-09-27, auto mode. Every judgment call is in "Decisions" and mirrored in the xBRIEF `autoDecisions[]`.

## Glossary

- **Quota pool.** The GitHub identity whose limit a call spends. The ledger records three pools:
  - **user pool:** the `gh` CLI token. Every `gh` exec and the agent shim spend it.
  - **pat pool:** the `GITHUB_TOKEN` personal access token read by `getGitHubConfig()`, used by `github-client.ts` and the Octokit issue poller. It is recorded separately because Overdeck cannot tell whether it belongs to the same account as `gh`. Mixing the two would write contradictory samples into one series.
  - **app pool:** GitHub App installation tokens minted by `src/lib/github-app.ts`.
- **Bucket.** A GitHub limit counter inside a pool: `graphql` (points) or `rest` (GitHub calls it `core`, counted in requests).
- **Primary rate limit.** The hourly budget, 5,000 per pool and bucket. GitHub reports it through `x-ratelimit-*` headers, GraphQL `rateLimit { cost remaining resetAt }`, and the free `GET /rate_limit` endpoint.
- **Secondary rate limit.** GitHub's burst and abuse limit. The error says "secondary rate limit" or "abuse detection", sometimes with a `retry-after` header.
- **Hidden per-user limit.** The case from the issue evidence: this token's `/rate_limit` shows 4,956 GraphQL points remaining, yet GraphQL refuses with `graphql_rate_limit` because another client acting as the same user spent a per-user limit this token cannot see.
- **Caller.** A named logical Overdeck subsystem that spends quota. The closed list is `GITHUB_QUOTA_CALLERS` (FR-2).
- **Ledger.** The append-only per-hour JSONL files under `~/.overdeck/github-quota/`. Every process appends one line per GitHub call or `/rate_limit` sample.
- **Pause gate.** `~/.overdeck/github-quota/pause.json`. While a pause is active for a bucket, non-essential callers skip GitHub calls in that bucket.
- **Non-essential caller.** A read-model poller whose data can be stale for minutes without harm: `pipeline-membership`, `pr-cache`, `pr-sync`, `ci-repair`, `issue-poller`, `close-out`. Every other caller is **essential** and is never paused (merge, verdict recording, tracker writes, agents).
- **runGh.** The new metered `gh` exec helper in `src/lib/github-quota/run-gh.ts`.
- **operatorHash.** HMAC-SHA256 of the GitHub numeric user id under a fixed product salt, truncated to 16 hex characters. It is sent only when `telemetry.operator_grouping` is on.
- **HogQL.** PostHog's SQL query API (`POST /api/projects/:id/query/`), used by the doctor remote view.

## Problem

GitHub refuses Overdeck's calls several times a day with "API rate limit already exceeded for user ID 678719". The refusals stall review verdicts (PAN-4263), close-outs, merges and pipeline membership. Overdeck can neither see nor explain it:

1. **No chokepoint.** GitHub calls go through six transports and about 45 `src/` files that exec `gh` directly. Only two places read quota headers, and a third place only reacts to refusals:
   - `src/dashboard/server/services/github-client.ts` `ghFetch`: `const remaining = res.headers.get('x-ratelimit-remaining');`
   - `src/dashboard/server/services/issue-data-service.ts` `pollGitHub`: `cache.updateRateLimit('github', …)`
   - `src/lib/github-graphql-run.ts`, which only refuses to retry.
   No GraphQL query reads `rateLimit { … }`.
2. **No shared back-off.** Only IssueDataService suspends on a limit, through `cache.db` `rate_limits`. The pipeline membership gather, PR sync, PR cache, CI refill and the deacon child keep calling.
3. **Wasted polling.**
   - `resolveProjectTrackerType` (`src/lib/pipeline-membership-gather.ts:172`, `` `Cannot resolve tracker for ${project.name}` ``) throws on every refresh for papers-please, puzzdom and orca.
   - krux makes four GitHub App REST calls per refresh, and all return 404 because the App is not installed there.
   - Each App REST call also mints a new installation token: `getInstallationAccessToken` (`src/lib/github-app.ts:379`) calls `generateInstallationToken(config)` with no cache.
4. **Bursts.**
   - Boot enqueues every project at once: `enqueueProjectsResourceRefresh(listProjectsSync().map(...), 'boot-warm')` at `src/dashboard/server/main.ts:615`.
   - `startProjectResourceConvergence` (`src/dashboard/server/services/project-resource-refresh-queue.ts:178`) enqueues every project every 5 minutes.
   - The CI refill runs immediately at boot (`main.ts:782`, `startProjectCiRefillAfterProjectionReady(15 * 60 * 1000)`).
5. **Telemetry is blind** (operator comment). `src/lib/telemetry/service.ts` sends `distinctId = install id` with no operator grouping and no GitHub usage. The operator cannot tell whether another Overdeck instance they run (their Mac) is spending the shared per-user quota.

## Requirements

### Functional

- **FR-1 Ledger.** Every metered GitHub call appends one JSON line to `~/.overdeck/github-quota/ledger-<YYYYMMDDHH>.jsonl` (UTC hour) with `{ ts, pid, kind: 'call' | 'sample', caller, pool: 'user' | 'pat' | 'app', bucket: 'graphql' | 'rest', cost, estimated, outcome: 'ok' | 'error' | 'rate_limited' | 'secondary_limited' | 'unknown', remaining?, limit?, resetAt?, agent? }`. `unknown` is used only by the agent shim, which cannot see the exit status before `exec`. Readers aggregate the last 60 minutes from the current and previous hour files. Files older than 3 hours are deleted on hour rollover.
- **FR-2 Callers.** `GITHUB_QUOTA_CALLERS` in `packages/contracts/src/github-quota.ts` is exactly: `pipeline-membership`, `pr-cache`, `pr-sync`, `ci-repair`, `issue-poller`, `close-out`, `tracker-client`, `app-rest`, `quota-sampler`, `agent`, `other`.
  - The current caller comes from an `AsyncLocalStorage` context set with `withGitHubCaller(caller, fn)`.
  - When no context is set, the caller is `other`. When no context is set but the call goes through the App REST door, the caller is `app-rest`.
- **FR-3 Cost.**
  - GraphQL queries built by Overdeck include `rateLimit { cost remaining resetAt limit }`, and the real cost is recorded.
  - `fetch`/Octokit paths record `x-ratelimit-remaining/limit/reset/used` headers, cost 1 per request.
  - `gh` subcommands with no visible cost (`gh pr …`, `gh issue …`) record cost 1 with `estimated: true`. They are classified as bucket `graphql` because gh implements them with GraphQL.
  - `gh api <path>` and `gh run …` are bucket `rest`.
- **FR-4 Samples.** The dashboard samples `GET /rate_limit` every 5 minutes for the user pool (`gh api rate_limit`) and, when the App is configured, for the app pool. Each sample writes one ledger line with `kind: "sample"`. `/rate_limit` does not spend quota.
- **FR-5 Pause gate.** A rate-limit or secondary-limit refusal observed by any process writes `pause.json` for that pool and bucket (atomic tmp + rename). Duration rules:
  - Primary limit with a visible reset (the refused bucket's latest sample shows `remaining == 0`): pause until that sample's `resetAt`.
  - Primary limit hidden (the sample shows `remaining > 0`, or no sample within 10 minutes): pause 10 minutes, capped at the sample's `resetAt` when that is sooner. The floor is 60 seconds.
  - Secondary limit: pause for `retry-after` seconds when present. Otherwise pause 60 seconds, doubling on each consecutive secondary refusal within 30 minutes, capped at 15 minutes.
  - For a **primary** refusal only, an `x-ratelimit-reset` header on the refused response wins over the sample-based rules. A **secondary** refusal ignores `x-ratelimit-reset`, because that header describes the hourly window, not the burst limit.
- **FR-6 Gate enforcement.** `assertGitHubCallAllowed(caller, pool, bucket, nowMs = Date.now())` throws `GitHubQuotaPausedError` for a non-essential caller during an active pause on that exact `(pool, bucket)`. A pause on another pool never blocks the call. It returns for essential callers. `runGh` and the App REST door call it before every call.
- **FR-7 Never read as no data.** A refused or paused call throws a typed error: `GitHubRateLimitedError` (with `kind: 'primary' | 'secondary'`) or `GitHubQuotaPausedError`. The migrated callers keep their existing "failed" signal and never turn these errors into an empty result:
  - Pipeline membership classifies both errors as `forge_transient`.
  - `readRepoPullRequests` returns `null`.
  - PR sync skips the sweep without counting failures.
- **FR-8 Migrated callers.** These call sites go through `runGh` or `withGitHubCaller`:
  - pipeline membership (open-PR snapshot, both GraphQL batches, App issue listings)
  - PR cache (`readRepoPullRequests`)
  - PR sync (`readGithubPullRequest`)
  - CI repair (`projectCiGhApi`, `project-pipelines` `defaultGhApi`)
  - close-out tracker reads (`readLiveTrackerIssueState`, `isIssueClosed`), through `runGh`
  - the PAT client (`ghFetch`, caller `tracker-client`, pool `pat`)
  - the issue poller (`pollGitHub`, caller `issue-poller`, pool `pat`)
  - the close-out reaper sets caller `close-out` in `reconcileClosedIssueAgents` (`src/lib/cloister/closed-issue-reaper.ts`). The shared `issue-closed.ts` readers take the caller from context, so the `closeOut()` ceremony and `pan close` stay essential (caller `other`).
- **FR-9 Agent shim.** Agents launched with the git guard also get a count-only `gh` shim in the same guard directory. It appends a ledger line (`caller: "agent"`, `estimated: true`) and `exec`s the real `gh`.
- **FR-10 Snapshot.** The dashboard publishes a `GitHubQuotaSnapshot` through the read model:
  - per caller and bucket: points and calls in the last hour
  - the latest sample per pool and bucket
  - the active pause, if any
  - `ownUsageLow: boolean`
  - the account login
  It uses a `github_quota.changed` event emitted with `emitOnly`, and `GET /api/github-quota` returns the same snapshot.
- **FR-11 Pill.** The app bar shows a GitHub quota pill (GraphQL remaining / limit for the user pool). Its popover lists the top 5 callers by points in the last hour.
- **FR-12 Banner.** While a pause is active, a banner in `system-notices-row` states the pause end time (local `HH:MM`) and the cause, using the decision table in Work Item 16.
- **FR-13 Doctor local view.** `pan doctor github-quota` prints:
  - the caller table for the last hour
  - the latest samples
  - the active pause
  - projects skipped for bad config
  - repos where the App is missing
  `--json` prints the same data as JSON.
- **FR-14 Skip misconfigured projects.** A project whose tracker cannot be resolved is skipped by every membership refresh until `projects.yaml` changes (mtime). It is logged once per mtime, never counted as a refresh failure, and listed by plain `pan doctor` as a `warn` row.
- **FR-15 App-not-installed fallback.** A 404 from an App REST issue listing for a repo records `appInstalled: false` for that repo in `~/.overdeck/github-quota/repo-notes.json` (6-hour TTL). Later membership refreshes use the `gh` (user token) path for that repo's issue listings. The first 404 per repo per TTL logs one warning, and `pan doctor github-quota` lists the repo.
- **FR-16 Token cache.** `getInstallationAccessToken` reuses a minted token until 5 minutes before its `expiresAt`.
- **FR-17 Stagger.** Boot-warm and periodic-convergence refreshes enqueue projects one at a time, spaced at `max(PROJECT_RESOURCE_REFRESH_DEBOUNCE_MS + 1_000, floor(window / projectCount))`. The window is 60 seconds for boot and 4 minutes for convergence. The CI refill's first run moves from boot to boot + 2 minutes.
- **FR-18 Telemetry contract.** `TELEMETRY_EVENT_NAMES` gains `github_quota_sample`, `github_rate_limited` and `instance_heartbeat`. The new domains and properties are in Work Item 20. `docs/TELEMETRY.md` tables match (`tests/unit/telemetry-docs.test.ts`).
- **FR-19 Quota telemetry.**
  - The dashboard sends `github_quota_sample` hourly.
  - Any process that records a refusal sends `github_rate_limited`, at most one per 10 minutes per install. The throttle is cross-process, keyed on the mtime of `~/.overdeck/github-quota/last-rate-limited-event`.
- **FR-20 Heartbeat.**
  - The dashboard sends `instance_heartbeat` with `dashboard_running: true` at most once per 24 hours. It checks at boot and hourly.
  - The CLI sends it with `dashboard_running: false` after a command when no heartbeat was sent in the last 24 hours.
  - The last-sent time lives in `~/.overdeck/telemetry-heartbeat.json`.
- **FR-21 Operator grouping.** Setting `telemetry.operator_grouping` is off by default and shown in Settings → Telemetry. When it is on and a hash is available, every Node and browser event carries `operatorHash`. The hash comes from `gh api user --jq .id` once (a direct async `execFile`, not `runGh`), and only the hash is cached, at `~/.overdeck/telemetry-operator-hash` (mode 0600).
- **FR-22 Doctor remote view.** When grouping is on and a PostHog read key and project id are configured, `pan doctor github-quota` also lists every other install (distinct id) with the same `operatorHash` seen in the last 48 hours: platform, arch, version, last seen, and its last `github_quota_sample` points summary.

### Non-functional

- **NFR-1 Never block the event loop.** Ledger appends in server-reachable code use `fs.promises.appendFile` (the line is under 4 KB, so the append is atomic under `O_APPEND`). No `execSync` or other sync child process anywhere reachable from the server. Bounded sync reads of the small quota files are allowed everywhere, including the server: at most the current and previous ledger hour files, plus `pause.json`, `repo-notes.json` and `skipped-projects.json`. Do not add an async twin of `readLedgerWindow`.
- **NFR-2 Metering never fails a caller.** Every ledger write, sample or telemetry capture is wrapped in try/catch and swallowed. A metering failure must not change the call's result.
- **NFR-3 Privacy.** No GitHub login, email, hostname, user name, filesystem path, repository name or raw user id is ever sent to PostHog. The login stays in the local snapshot, banner and doctor output only. A unit test enforces this (Work Item 25).
- **NFR-4 Fake timers.** Every test of pause durations, the 5-minute sampler, hourly and daily timers, throttles and the stagger uses `vi.useFakeTimers()` with `vi.advanceTimersByTimeAsync`. No real delays (repo rule `fake-timers-for-retry-tests`).
- **NFR-5 One variant per operation.** `runGh` is Promise-only, with no Effect wrapper and no sync twin (`npm run lint:effect-facades`, `docs/EFFECT-BRIDGING.md`).
- **NFR-6 File-size ratchet.** New logic goes in new files. `src/cli/commands/doctor.ts`, `src/lib/github-app.ts`, `src/dashboard/server/main.ts` and `src/dashboard/server/services/issue-data-service.ts` get only small call-site edits. If a touched file grows past its `origin/main` line count, the same commit adds a `scripts/file-size-allowlist.txt` row `<lines> <path> # PAN-4264` (`scripts/lint-file-size.sh`).
- **NFR-8 No import cycles.** `src/lib/github-quota/*` never imports `src/lib/telemetry/*`. The pause gate exposes `onGitHubRefusal(listener)`, and telemetry registers its listener at server boot and CLI start. `src/lib/telemetry/operator-hash.ts` never imports `src/lib/github-quota/run-gh.ts`. Node ESM rejects cycles in the built dashboard (`dashboard-node22-only` rule).
- **NFR-7 The quota is derived runtime state.** The snapshot is `emitOnly`: never appended to the durable event log, never persisted in overdeck.db.

## Decisions (auto mode)

1. **One plan with `sizeJustification`, not sibling issues.** The operator appended the telemetry scope to this issue and asked for it to be folded into this plan. Every slice reads the same ledger and pause gate. Items are vertical slices with only real edges, so the foreman can fan out. If the surface proves unmanageable, the foreman may split the telemetry items (19–25) into a sibling issue.
2. **Cross-process substrate: JSONL ledger plus a pause file under `~/.overdeck/github-quota/`, not `cache.db`.**
   - The callers run in four places: the dashboard, the deacon child, the CLI, and agent shells. The agent `gh` shim is `/bin/sh` and cannot write SQLite.
   - `cache.db` (`src/dashboard/server/services/cache-service.ts`) lives in server code that `src/lib` must not import.
   - IssueDataService keeps its existing `cache.db` suspension and also checks the new gate (Work Item 7).
3. **Meter only the named callers (FR-8).** The remaining ~35 `gh` exec files stay unmigrated. Their user-pool usage shows up as the gap between the `/rate_limit` sample's `used` and the metered sum, which the snapshot reports as `unattributed`. Migrating them is a named follow-up (NonGoals).
4. **Pause by pool and bucket.** A GraphQL refusal does not stop REST calls. The hidden per-user limit only affects GraphQL, and REST keeps working.
5. **Essential callers are never paused.** Merge, verdict recording and agent calls get typed errors and their own retries. PAN-4263 owns the verdict-path retry.
6. **PAN-4263 coordination.** PAN-4263 is in flight on `feature/pan-4263` and edits `src/lib/forge.ts`, `src/lib/github-pr-lookup.ts`, `src/lib/github-pr-selection.ts`, a new `src/lib/forge-transient.ts`, and three lines of `src/lib/github-app.ts` (an `updatedAt` field on `listPullRequestsForHead`). This plan does not touch `forge.ts`, `github-pr-lookup.ts`, `github-pr-selection.ts` or `forge-transient.ts`. Its `github-app.ts` edits are in `getInstallationAccessToken` and `githubApiWithToken` only. The App-not-installed fallback (Work Item 22) wraps the dependencies in `pipeline-membership-gather.ts` and does not edit `github-app.ts`.
7. **Telemetry keeps its closed-union contract.** Points are bucketed (`quota_points_bucket`) and remaining is bucketed (`quota_remaining_bucket`), so "raw counts are never sent" stays true. `github_quota_sample` uses flat per-caller keys.
8. **operatorHash salt** is the source constant `OPERATOR_HASH_SALT = 'overdeck-operator-grouping-v1'`. It is a pepper, not a secret: pseudonymity holds only against parties without the Overdeck source. The docs say so. The hash is computed from `gh api user --jq .id`. When `gh` is unavailable or unauthenticated, no hash is sent (the property is omitted). The App path is not used, because an installation token has no user.
9. **PostHog read config.** `telemetry.posthog_read_key` and `telemetry.posthog_project_id` in `~/.overdeck/config.yaml`, overridden by `OVERDECK_POSTHOG_READ_KEY` and `OVERDECK_POSTHOG_PROJECT_ID`. The query host is `POSTHOG_HOST` with `.i.` removed (default `https://us.posthog.com`). The key is never shown in the Settings UI in this issue.
10. **`pan doctor github-quota` is a Commander subcommand** of `doctor`: `program.command('doctor')…` gains `.command('github-quota')` with its own action and `--json`. Plain `pan doctor` keeps its action.
11. **CLI heartbeat reports `dashboard_running: false`.** A running dashboard sends its own heartbeat at most every 24 hours, so a CLI process that finds no heartbeat in 24 hours knows no dashboard sent one.
12. **PAT is its own pool (`pat`).** It is not known whether `GITHUB_TOKEN` is the `gh` account. Separate series cannot contradict each other, and the banner's `ownUsageLow` predicate reads only the user pool.
13. **Login display.** The banner and doctor need the account login. `src/lib/github-quota/identity.ts` reads `gh api user --jq .login` once per dashboard start (1 REST point) and caches it in memory only. It is never sent to PostHog.

### Work Item 3 — `runGh` and the GraphQL runner


## Repo rules restated for the executor

- **Frontend tests** run from the frontend package: `npm --prefix ./src/dashboard/frontend run test -- <path relative to src/dashboard/frontend>`. The root Vitest config excludes `src/dashboard/frontend/**`.

- **Fake timers** for every delay, interval, throttle or pause test (`vi.useFakeTimers()`, `vi.advanceTimersByTimeAsync`). Never real `setTimeout` waits.
- **No `execSync`** in server-reachable code; use async `execFile`. `src/cli/commands/doctor.ts` `checkCommand` is execSync-based, so never import it into server code.
- **One variant per operation:** no Effect wrapper around `runGh`, no sync twin.
- **File-size ratchet:** keep new logic in new files. Add an allowlist row in the same commit if a touched file grows past its `origin/main` count.
- **Dashboard runs from `dist/` under Node 22:** after server changes, `npm run build` before any live check.
- **Quality gates** before `pan done`: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` on the host.
- **Telemetry:** Node events go only through `src/lib/telemetry/service.ts`, and browser events only through `src/dashboard/frontend/src/lib/telemetry.ts`. Event names and properties come from `@overdeck/contracts`.
- **PAN-4263 files are off limits:** `src/lib/forge.ts`, `src/lib/github-pr-lookup.ts`, `src/lib/github-pr-selection.ts`, `src/lib/forge-transient.ts`.
