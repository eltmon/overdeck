# PAN-1872: bug(cli) pan start crashes when sync-main hits a conflict

**Filed by:** flywheel (RUN-32)
**Fixed by:** commit `7297d2469c0cd9f31ae55c10e45cd408e5f4f523` (2026-06-14) — emergency patch applied directly to main before planning

## Problem

`pan start <id>` on an in_review issue whose feature branch had merge conflicts with
main ran auto sync-main, which correctly aborted on conflict but then crashed:

```
✖ Cannot read properties of undefined (reading 'toUpperCase')
```

The work agent was never spawned, leaving conflicted issues permanently stranded
unless a human resolved the conflict by hand.

## Root Causes Fixed

1. **`src/cli/commands/start.ts`** — sync-main conflict path fell through to code that
   assumed a non-null issueId and didn't continue to spawn the agent.
2. **`src/lib/cloister/work-agent-prompt.ts`** — `buildWorkAgentPrompt` and
   `buildActiveSliceContext` called `.toUpperCase()` on `ctx.issueId` without
   guarding for undefined.
3. **`src/lib/agents.ts`** — `assertWorkspaceStackHealthyForSpawn` called
   `.toUpperCase()` on issueId without guard.
4. **`src/lib/projects.ts`** — `findProjectByTeamSync` could return undefined teamPrefix.
5. **`src/lib/workspace/stack-health.ts`** — `normalizeIssue` called `.toUpperCase()`
   on issueId without guard.

## Fix Summary

- `start.ts`: surfaces conflict files in the warning, explicitly continues spawning the
  work agent so the issue is not stranded.
- Other four files: guard all `.toUpperCase()` calls with `?? ''` fallback.
