# PAN-5586 — Add Gemini 4 Carbon, Neon and Hydrogen; update Google tier mapping and deprecation remaps

**Issue:** https://github.com/eltmon/overdeck/issues/5586
**Status:** planned (auto mode, 2026-11-21, HEAD `f08a9910ae8`)
**Related:** PAN-4555 (open, date-gated 2026-12-01: raise Gemini 4 Argon to list rates), PAN-4827 (the previous
Gemini catalog refresh; its PRD `.pan/drafts/PAN-4827.md` is the pattern this one follows), PAN-4003 (open: remove
the ohmypi harness).

Google released three Gemini 4 models in November 2026 that Overdeck does not know. A user cannot pick them, cost
tracking cannot price them, and the Google provider's tier ids still point at the Gemini 3.1 generation. This PRD
registers the three ids everywhere `gemini-4-argon` is registered, moves the Google tier ids to Gemini 4, points the
two Gemini 2.5 deprecation remaps at Google's own 2026-12-01 routing targets, and documents the change.

## Glossary

- **Tier ids:** `PROVIDERS.google.tierModels.{opus,sonnet,haiku}` in `src/lib/providers.ts`. `getProviderEnv()`
  exports them to Claude Code launches as `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`,
  `ANTHROPIC_DEFAULT_HAIKU_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL` (the last two
  take the haiku id for Google, which has no `haikuModel`).
- **`MODEL_DEPRECATIONS`:** the single-hop map from a retired id to its live replacement
  (`src/lib/model-deprecations.ts`). `resolveModelId()` applies it. Pickers and `getAvailableModels()` hide every
  key in it.
- **`MODEL_API_IDS`:** a second, independent id map in `src/dashboard/server/routes/settings.ts` (line 106) that
  the Settings "test API key / test model" route uses to pick the wire model for a configured id.
- **Lookup list:** the hard-coded Google id array inside `getProviderForModel()` (`src/lib/providers.ts` line
  494, search `if (['gemini-4-argon',`). It must contain every live and retired Google id.
- **Capability row:** an entry in `AUDITED_MODEL_ADDITIONS` (`src/lib/model-capability-additions.ts`), spread
  first into `MODEL_CAPABILITIES` (`src/lib/model-capabilities.ts` line 69). Key order in this object is the order
  the dashboard picker API (`getAvailableModelsApi`, `src/lib/settings-model-catalog.ts`) lists models.
  `model-capabilities.ts` is at its file-size cap (1422); new rows never go there.
- **Capability class:** `frontier | workhorse | small` in `MODEL_CAPABILITY_CLASSES`
  (`src/lib/model-capability-class.ts`). Only the tier-fitness checker (`src/lib/agents/tier-fitness.ts`) reads
  it; a wrong class produces a warning in Settings, never a launch failure.
- **`costPer1MTokens`:** Overdeck's blended display cost = (input $/M + output $/M) / 2. Argon: (2+10)/2 = 6.
- **pi provisioning:** `provisionPlan()` in `src/lib/pi-models.ts` lists ids that older pi builds (0.85.0, 1.5.2)
  do not ship; at launch they are merge-written into `~/.pi/agent/models.json`, filtered against the installed pi
  catalog. pi is the Google provider's default harness (`providers.ts` line 160, `defaultHarness: 'pi'`).
- **omp registry:** `ompProviderDef()` in `src/lib/ohmypi-models.ts`, the ohmypi counterpart. ohmypi is being
  removed (PAN-4003, open); this issue adds rows only, no other omp changes.

## Verified facts (official sources, read 2026-11-21)

Sources: https://aistudio.google.com/docs/models, `/docs/models/gemini-4-{carbon,neon,hydrogen,argon}`,
https://aistudio.google.com/docs/pricing, https://aistudio.google.com/docs/deprecations,
`/docs/whats-new-gemini-4-{carbon,neon,hydrogen,argon}`, `/docs/thinking`, `/docs/caching`. (`ai.google.dev`
301-redirects there.) Cross-checked against the pi 1.6.0 bundled catalog (`pi-ai/dist/providers/data/google.json`),
which already ships all three ids at the same prices.

| Model id | Released | Context | Max output | Thinking levels (default) | Standard $/M input / output / cached | Free tier |
| --- | --- | --- | --- | --- | --- | --- |
| `gemini-4-carbon` | 2026-11-10 | 1,048,576 | 65,536 streaming, 32,768 non-streaming; up to 1,048,576 with long decode | low, medium, high (medium) | 2.00 / 10.00 / 0.10 through 2026-11-30; 4.00 / 20.00 / 0.20 from 2026-12-01 | no |
| `gemini-4-neon` | 2026-11-18 | 1,048,576 | 65,536 streaming and non-streaming; long decode to 1,048,576 | low, medium, high, xhigh (high) | 3.00 / 15.00 / 0.15 | no |
| `gemini-4-hydrogen` | 2026-11-12 | 1,048,576 | 65,536 streaming and non-streaming; long decode to 1,048,576 | low, medium, high, xhigh (high) | 1.50 / 7.50 / 0.075 | yes |

All three: status Stable, inputs text/image/video/audio/PDF, output text, sampling parameters (`temperature`,
`top_p`, `top_k`) ignored (Neon and Hydrogen return 400 for out-of-range values), explicit context caching
(`cachedContents`) not supported, implicit caching from 4,096 prompt tokens, no prompt-length price tiers, no
shutdown date.

Deprecations page: "Effective December 1, 2026, all API requests to `gemini-2.5-pro` will automatically route to
`gemini-3.8-flash`" and "... `gemini-2.5-flash` will automatically route to `gemini-3.5-flash-lite`". Both 2.5 ids
shut down on 2026-12-01 at the earliest. `gemini-3-pro-preview` is shut down (2026-03-09).

**Difference from the issue body:** the issue says only Neon thinks up to xhigh. Google's thinking guide lists
xhigh for Hydrogen too. The official page wins; the PR body must note this difference. Every id and price in the
issue matches the official pages.

Google's models index describes Carbon as "Our strongest reasoning model" and Neon as "Frontier-level
intelligence with fast end-to-end task completion"; it assigns no tier labels. The issue's tier mapping
(opus Neon, sonnet Carbon, haiku Hydrogen) is explicit, so this PRD follows it (see Decisions D2).

## Decisions

- **D1 — Order.** In every ordered list (`PROVIDERS.google.models`, the `getAvailableModels` Google list in
  `settings.ts`, the key-validation list in `routes/settings.ts`, `AUDITED_MODEL_ADDITIONS`, the frontend
  `MODELS_BY_PROVIDER.google`), insert the three ids directly after `gemini-4-argon` in the order
  `gemini-4-neon`, `gemini-4-carbon`, `gemini-4-hydrogen`. Argon stays first, so the existing
  `existing.google[0]` assertion in `settings-model-catalog.test.ts` stays valid.
- **D2 — Tier mapping follows the issue:** `opus: 'gemini-4-neon', sonnet: 'gemini-4-carbon', haiku:
  'gemini-4-hydrogen'`. Rationale: the issue is explicit and Google publishes no tier labels; Neon is the most
  expensive steady-state Gemini 4 model through 2026-11-30.
- **D3 — Capability classes:** Neon `frontier`, Carbon `frontier`, Hydrogen `workhorse`. The header rule of thumb
  in `model-capability-class.ts` (opus slot ⇒ frontier, sonnet ⇒ workhorse, haiku ⇒ small, ties broken by price)
  is overridden by price and Google's description: Carbon costs exactly what Argon (`frontier`) costs and Google
  calls it its strongest reasoning model; Hydrogen ($1.50/$7.50) costs more than `gemini-3.6-flash` (`workhorse`,
  $0.75/$3.75), so `small` would make tier-fitness warn on every medium/complex tier that uses Google's haiku id.
- **D4 — Skill scores** inherit until benchmarked: Neon and Carbon copy Argon's `skills` object exactly; Hydrogen
  copies `gemini-3.8-flash`'s `skills` object exactly. Each `notes` string says so.
- **D5 — Carbon pricing equals Argon's rows on the branch.** No dated-pricing mechanism exists on main (`cost.ts`
  has no effective-date field; PAN-4555 is a manual date-gated edit). Carbon's `cost.ts` row, `costPer1MTokens`,
  omp cost and picker description use the introductory rates ($2/$10/$0.10, blended 6), exactly like Argon. If
  PAN-4555 has merged into the branch before this work lands (Argon's `cost.ts` row reads `inputPer1k: 0.004`),
  use the list rates ($4/$20/$0.20, blended 12) for Carbon instead and say so in the PR. Work item 3 adds a comment
  to PAN-4555 so the 2026-12-01 change covers Carbon.
- **D6 — Deprecation remaps follow Google's routing:** `gemini-2.5-pro → gemini-3.8-flash`, `gemini-2.5-flash →
  gemini-3.5-flash-lite`. `MODEL_API_IDS` in `routes/settings.ts` gets the same two targets so the Settings test
  route probes the model Google will actually serve. Side effect: `gemini-2.5-flash` has no class row, so
  `capabilityClassOf('gemini-2.5-flash')` moves from `workhorse` (via `gemini-3-flash-preview`) to `small` (via
  `gemini-3.5-flash-lite`); `gemini-2.5-pro` stays `frontier` (via `gemini-3.8-flash`). No test asserts either.
  `gemini-3-pro-preview → gemini-3.1-pro-preview` and `gemini-3-flash → gemini-3-flash-preview` are unchanged.
- **D7 — Fallback targets** (`FALLBACK_MAP`, `src/lib/model-fallback.ts` line ~203): Neon and Carbon →
  `claude-sonnet-5-5` (the Argon convention; the file avoids Opus as a default fallback), Hydrogen →
  `claude-haiku-4-5` (the Google fast/budget convention in the same block).
- **D8 — Images:** the three new capability rows set `supportsImages: true` (Google lists image input), so pi
  provisioning writes `input: ['text', 'image']`. Argon's row is not changed (out of scope).
- **D9 — pi and omp:** all three ids go into the Google `provisionPlan` (pi 0.85.0 and 1.5.2 lack them; the
  installed-catalog filter skips them on pi 1.6.0+). The omp registry gets three rows, nothing else.
- **D10 — Grep parity scope.** The acceptance check compares `git grep -l` over `src/` and `docs/` only. Hits in
  `.pan/`, `.release/` and `changelog.mdx` are history and must not be edited. The one expected Argon-only file
  is `src/dashboard/frontend/src/lib/__tests__/dashboard-utils.test.ts`: it is Argon-specific and not in CI's
  frontend subset, so the new friendly-name assertions go in `gemini-qwen-glm-catalog.test.ts` instead.
