## Glossary

- **Phone app:** the Capacitor 8 app at `apps/mobile` (bundle id `ai.overdeck.app`). Its web layer runs in WKWebView on iOS.
- **Shell:** the app's own screens and logic in `apps/mobile/src/shell/` (sign-in, machines, pairing, settings).
- **Directory:** `services/connect` at `connect.overdeck.ai`. The phone is a directory **client** (`hello-client`), not a machine.
- **Push key pair:** one X25519 key pair per app install, created by the native `OverdeckKeys` plugin. The machine seals each notification to its public half. The secret half never enters JavaScript.
- **Sealed payload / `s`:** libsodium `crypto_box_seal` of the UTF-8 JSON `PhonePushPayload` (`packages/contracts/src/connect.ts:105-121`), base64 encoded. The APNs body carries it in the top-level key `s`.
- **Placeholder:** the fixed alert text the directory sends to Apple: title `Overdeck`, body `Something needs you` (`services/connect/src/push/apns.ts:20-21`).
- **APNs:** Apple Push Notification service. **APNs token:** the device token iOS returns from `registerForRemoteNotifications`, a hex string.
- **`apsEnvironment`:** which APNs host the directory uses for this token: `sandbox` (`api.sandbox.push.apple.com`) or `production`. A token only works on the host that matches the app's signing.
- **NSE (Notification Service Extension):** an iOS app extension that runs for every remote notification with `mutable-content: 1`, may rewrite its title and body, and has about 30 s and a small memory limit to do it.
- **Keychain access group:** a label on a Keychain item that decides which signed binaries may read it. The app and the NSE are separate binaries; they share items only through a common group listed in both entitlements.
- **`$(AppIdentifierPrefix)`:** an Xcode build variable that expands to the signing team id plus a dot (for example `KUU2VM9GB9.`). It is empty in a build with no team.
- **Local Swift package:** a folder with a `Package.swift` that the Xcode project references by relative path (`XCLocalSwiftPackageReference`), exactly as it already references `CapApp-SPM`.
- **Mac rig:** the operator's Mac build machine, reached with `ssh -i ~/.ssh/gauntlet_air eltmon@<rig-ip>` (address by DHCP, usually `.83`). It has Xcode and the operator's Apple ID session. `apps/mobile/README.md` "Run in the iOS Simulator" is the build recipe.
- **`simctl push`:** `xcrun simctl push <udid> <bundle-id> <file.apns>` delivers a remote-notification payload to a Simulator without Apple's servers.

## Requirements

### Functional

- **FR-1 Register for notifications.** On iOS, after sign-in, the app asks for notification permission once (when iOS reports `prompt`), calls `PushNotifications.register()` on every launch when permission is granted, and keeps the latest APNs token.
- **FR-2 Tell the directory.** The app sends `push-register { platform: 'ios', token, apsEnvironment }` when it gets a new token while the directory is online, and on every transition of the directory socket into `online`.
- **FR-3 Correct APNs environment.** `apsEnvironment` is `sandbox` for a Debug build and `production` for a Release build, decided in native code (`#if DEBUG`).
- **FR-4 Notifications switch.** Settings shows a Notifications switch on iOS. Off sends `push-unregister` (now, or at the next `online`) and stops `push-register`. On asks for permission if needed and registers again. When iOS permission is denied, Settings says how to turn it on in iOS Settings.
- **FR-5 Decrypt in the NSE.** A Notification Service Extension reads `s`, opens it with the push key pair from the shared Keychain group, and replaces the title and body with the payload's `title` and `body`. It sets `threadIdentifier` to the payload's `tag` and puts `url`, `machine`, `kind` and `tag` in `userInfo`, and removes `s`.
- **FR-6 Placeholder on failure.** If `s` is missing, is not base64, does not open, or is not a v1 payload, or the key cannot be read, the notification shows unchanged (title `Overdeck`, body `Something needs you`). The same applies when the NSE runs out of time.
- **FR-7 Shared push key.** The push key pair is stored in the Keychain access group `$(AppIdentifierPrefix)ai.overdeck.shared`, which the app and the NSE both list. The account token and the paired-machine records stay in the app's private group, which the NSE cannot read.
- **FR-8 Tap opens the right screen.** Tapping a decrypted notification opens the machine named by the payload's `machine` at the payload's `url` (a `/m` path), also from a cold launch. A machine that is not paired opens the machine list. A notification without `machine` (not decrypted) opens the app where it was.

### Non-functional

- **NFR-1 Same crypto as the machine.** The NSE opens boxes made by `sodium-native` `crypto_box_seal`. A committed fixture sealed by `sodium-native` proves it in a Swift test, and a Vitest proves the fixture itself on Linux.
- **NFR-2 Keys stay on the device.** Push key items keep `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` and `kSecAttrSynchronizable = false`. The push secret key never crosses the Capacitor bridge. Logs never contain the secret key, the APNs token, `s` or notification text. A Debug build may log the push **public** key.
- **NFR-3 URL trust.** The tap handler accepts only a same-origin path whose pathname is `/m` or starts with `/m/`; anything else becomes `/m`. The payload came from a paired machine, but the app does not navigate to a scheme or host from it.
- **NFR-4 Android untouched at runtime.** No push call runs on Android in this issue (`pushSupported()` is iOS-only). `./gradlew assembleDebug` still exits 0 after the new dependency.
- **NFR-5 Fake timers.** Any JS test of timing uses `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()` (repo rule). This issue adds no timers.
- **NFR-6 No new god files.** Keep each changed file under 600 lines; `ShellApp.tsx` is 284 lines today.

## Decisions

- **D-1 libsodium through a local Swift package.** New package `apps/mobile/ios/OverdeckPush/` depends on `swift-sodium` `exact: "0.9.1"` (product `Sodium`). It holds the decrypt, the content rewrite, the Keychain store and the push-key store. The App target and the NSE target both link its product `OverdeckPush`. Why: the pbxproj gains one `XCLocalSwiftPackageReference` (the same pattern as `CapApp-SPM`) instead of a remote package reference and an XCTest target, and the logic is tested with `swift test` on the rig. `CapApp-SPM/Package.swift` is not touched by hand (fact 10).
- **D-2 One Keychain implementation.** `KeychainStore.swift` moves from the App target into the package (`Sources/OverdeckPush/KeychainStore.swift`), gains an optional `group` parameter, and is used by both binaries. The App target's copy and its two pbxproj entries are removed.
- **D-3 The shared group is `$(AppIdentifierPrefix)ai.overdeck.shared` (epic W-IOS1).** Both `Info.plist` files carry `OverdeckSharedKeychainGroup = $(AppIdentifierPrefix)ai.overdeck.shared` so Swift reads the expanded name at run time. The App entitlement lists `$(AppIdentifierPrefix)ai.overdeck.app` first, so items written without a group keep landing in the app's private group, then the shared group. The NSE entitlement lists only the shared group. No App Group (`group.ai.overdeck.app`) in this issue; PAN-4839 adds it if its widget needs it.
- **D-4 Push-key items always name the shared group.** Every add, get and delete of `pushSecretKey` and `pushPublicKey` passes `group`. `removeAll()` deletes by service with no group (all groups the app can read), then by service and the shared group.
- **D-5 Fallback for builds without the entitlement.** If writing the push key to the shared group fails with `errSecMissingEntitlement` (OSStatus -34018), `ensureKeys` writes it to the private group and logs `[OverdeckKeys] shared keychain group unavailable; notifications will show the placeholder` once. This keeps an unsigned Simulator build working (fact 2). In such a build the NSE shows the placeholder.
- **D-6 No key migration.** No iOS install exists (fact 3). `ensureKeys` reads the push key from the shared group, then from any group; it never moves items.
- **D-7 `apsEnvironment` by build configuration.** New `OverdeckKeys.pushEnvironment()` returns `{ apsEnvironment: 'sandbox' }` under `#if DEBUG`, else `{ apsEnvironment: 'production' }`. TestFlight and App Store builds are Release (production); an Xcode Debug run is sandbox. A Release build run from Xcode with a development profile would register the wrong host; that case is documented, not handled.
- **D-8 `PUT /api/phones/self/push-key` is not called.** The push key is created once per install and changes only in `reset()`, which sign-out runs and which also deletes every paired machine. So there is no event that would need it.
- **D-9 Registration lives in `apps/mobile/src/native/push.ts`, iOS-gated.** `pushSupported()` returns `Capacitor.getPlatform() === 'ios'`. PAN-4840 widens it to Android after it adds Firebase. The module is otherwise platform-neutral (it sends `platform` from `shellPlatform()`), so PAN-4840 reuses it.
- **D-10 The token and the switch live in `localStorage`.** Keys `overdeck.pushToken` and `overdeck.notifications` (`'off'` means off; anything else, including absent, means on). Neither is secret. Sign-out's `localStorage.clear()` removes both.
- **D-11 `PushNotifications.unregister()` is never called.** Turning the switch off only clears the directory registration. Turning it on again re-sends the kept token.
- **D-12 Foreground notifications show.** `capacitor.config.ts` sets `plugins.PushNotifications.presentationOptions: ['alert', 'sound']`, so a notification for another machine still shows while the app is open.
- **D-13 NSE layout.** Sources in `apps/mobile/ios/App/NotificationService/` (`NotificationService.swift`, `Info.plist`, `NotificationService.entitlements`), bundle id `ai.overdeck.app.NotificationService`, deployment target 15.0, the same `MARKETING_VERSION` (1.0) and `CURRENT_PROJECT_VERSION` (1) as the App target (App Store validation requires matching versions).
- **D-14 No team in the project.** The pbxproj gets no `DEVELOPMENT_TEAM`. Store signing is PAN-4841. Rig builds that need the shared group pass `DEVELOPMENT_TEAM=<team> -allowProvisioningUpdates` on the `xcodebuild` command line.
- **D-15 Pbxproj edits are written by hand with fixed object ids** (table in WI-4 and WI-5). There is no Ruby or `xcodeproj` gem on this Linux host. The rig build is the check.
- **D-16 Acceptance split.** Epic AC-11 needs APNs secrets in production (fact 6) and a signed-in iPhone. This issue proves decryption with a Swift test against a `sodium-native` fixture, proves the built app embeds the NSE, and tries a `simctl push` on the rig. The real-APNs run happens in this issue only if `/healthz` reports `"apns":true` when the work agent reaches WI-10; otherwise the agent records that in `ACCEPTANCE.md`, comments on PAN-4841 so its TestFlight run carries epic AC-11, and tells the flywheel.

     /// The plaintext a machine seals into a `push` frame (packages/contracts/src/connect.ts `PhonePushPayload`).
     public struct PhonePushPayload: Decodable, Equatable {
         public let v: Int
         public let machine: String
         public let kind: String
         public let title: String
         public let body: String
         public let url: String
         public let tag: String
         public let issueId: String?
         public let ts: String
     }

     public struct PushKeyPair: Equatable {
         public let publicKey: [UInt8]
         public let secretKey: [UInt8]
         public init(publicKey: [UInt8], secretKey: [UInt8]) { … }
     }

     public enum SealedPush {
         /// The payload, or nil when `sealed` is not base64, does not open with `keys`, or is not a v1 payload.
         public static func open(_ sealed: String, keys: PushKeyPair) -> PhonePushPayload? {
             guard keys.publicKey.count == 32, keys.secretKey.count == 32,
                   let data = Data(base64Encoded: sealed),
                   let plain = Sodium().box.open(anonymousCipherText: Array(data), recipientPublicKey: keys.publicKey, recipientSecretKey: keys.secretKey),

             return payload
         }
     }

## Hazards

- **H-1 APNs is off in production** (fact 6). Mitigation: D-16.
- **H-2 Hand-written pbxproj.** A wrong object id or a missing section entry stops Xcode from opening the project. Mitigation: CP-2 and the rig build in WI-3/WI-5 verify commands; the Linux tests catch missing strings early.
- **H-3 Wrong `apsEnvironment` kills the registration.** APNs answers `BadDeviceToken` and the directory clears the registration (`apns.ts:107-110`). Mitigation: D-7, and WI-10 checks the stored environment in the real run.
- **H-4 Before first unlock after a reboot** the push key is unreadable (`AfterFirstUnlock`), so the NSE shows the placeholder. Accepted, documented in WI-11.
- **H-5 Android crash risk.** Calling `PushNotifications.register()` on Android without Firebase crashes the app. Mitigation: `pushSupported()` (D-9, NFR-4) and the `assembleDebug` check in WI-6.
- **H-6 swift-sodium age.** 0.9.1 is from 2021. Mitigation: CP-1.
- **H-7 Notification permission in the Simulator** may need a UI tap. Mitigation: WI-10 step 3 records the method used.
- **H-8 The rig is shared state.** Every rig build rsyncs into one `~/overdeck-mobile/` and builds into one `DerivedData`. Mitigation: WI-3, WI-5, WI-6 and WI-10 never run in parallel (xBRIEF readiness `sequential`).
