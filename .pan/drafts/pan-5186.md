## 1. Summary

This issue builds the browser half of the explorer's read side:

1. The Stage `'files'` pane becomes the **explorer pane**. It opens from the project home (root `project:<key>`) and from an issue tab (root `issue:<ID>`). The old changed-files list (`FilesPane.tsx`) is deleted; its job moves to the explorer's **Changed** filter.
2. A lazy, virtualized **tree** of the root, sorted naturally, with dotfile and ignored-entry handling, git colors and letter badges, and keyboard and multi-select support.
3. Live updates from the PAN-5185 watch stream, and git status refreshed on a debounce.
4. A right-click menu with the **read actions** (Open, Copy path, Copy relative path, Find in folder, Download) and the **git actions** (Stage, Unstage, Discard changes).
5. **Quick open** (`Ctrl/Cmd+P`) and **content search** (`Ctrl/Cmd+Shift+F`, or Find in folder).

Opening a file creates a `'code'` pane spec. The code pane that renders it is PAN-5187's (parent WI-8). Until PAN-5187 merges, an opened file shows the Stage's existing "not implemented yet" placeholder.

## 2. Glossary

Parent §2 terms apply (explorer pane, code pane, explorer root, root id, port record). Terms added here:

- **Root-relative path** — a POSIX path inside the root, with no leading `/`. The root itself is `''`.
- **Loaded directory** — a directory whose `explorerListDir` result is in the explorer store. Only loaded directories are re-listed on watch events.
- **Expanded set** — the root-relative paths of folders shown open in the tree. It is persisted per root.
- **Visible rows** — the flat, ordered list of rows the tree renders after projection (expansion, dotfile filter, Changed filter).
- **Decoration** — the git status shown on a row: a color class, and for files a one-letter badge.
- **Committed-only change** — a file the branch changed in commits since it left the default branch, with no working-tree change. It comes from the `committed` array of `explorerGitStatus`, which is empty for `project` roots.
- **Watch hub** — the module in this issue that holds one `explorerWatch` server subscription per root and fans its batches out to every local listener (tree, git status, and later PAN-5187's code panes).
- **Code pane open spec** — the `PaneSpec` this issue creates for a file: `{ paneType: 'code', label: <basename>, explorerRootId, explorerPath }`, plus optional reveal fields.
- **Pane-scoped shortcut** — a key handler attached with React `onKeyDown` to the explorer pane's root element. It fires only while keyboard focus is inside that pane.

## 3. Contracts this issue consumes (from parent WI-1, owned by PAN-5185)

The client calls these through `getTransport()` (`FE/lib/wsTransport.ts`, search `export function getTransport`). The calling pattern is the one `EditorPane.tsx` uses (search `[WS_METHODS.readFileAtPath]({ path: filePath })`).

| Method (`WS_METHODS.…`) | Input | Result |
|---|---|---|
| `explorerListDir` | `{ rootId, path }` | `{ entries: ExplorerEntry[], truncated: boolean, absPath: string }` |
| `explorerGitStatus` | `{ rootId }` | `{ entries: { path, status, staged }[], committed: { path, status }[], branch: string \| null, truncated: boolean }` |
| `explorerGitStage` | `{ rootId, paths, action: 'stage'\|'unstage'\|'discard' }` | `{}` |
| `explorerSearchFiles` | `{ rootId, query, limit }` | `{ paths: string[] }` |
| `explorerSearchContent` | `{ rootId, query, scopePath?, regex, caseSensitive, limit }` | `{ matches: { path, line, column, preview }[], truncated: boolean }` |
| `explorerWatch` (stream) | `{ rootId }` | stream of `{ events: { kind: 'create'\|'update'\|'delete'\|'rename'\|'overflow', path, oldPath?, isDirectory? }[] }` |

`ExplorerEntry = { name, path, kind: 'file'|'dir'|'symlink', size?, mtimeMs, ignored }`. Working-tree `status` is one of `untracked | added | modified | deleted | renamed | conflicted`. Error codes arrive as `PanRpcError.code` (`PanRpcError` from `@overdeck/contracts`): this issue handles `ROOT_NOT_FOUND`, `NOT_FOUND`, `NOT_A_GIT_REPO` and `PATH_OUTSIDE_ROOT`.

The download route `GET /api/explorer/download?root=<rootId>&path=<rel>&inline=0|1` is parent WI-12, owned by **PAN-5188**. This issue only builds a link to it.

## 4. Decisions

- **D-B1 Contract reconciliation.** The first step of the work agent is `pan sync-main`, so the branch has PAN-5185's code. Then it reads `packages/contracts/src/explorer.ts` and `packages/contracts/src/rpc.ts` (search `explorerListDir`). If a method, field or error-code name differs from §3, the code on `main` wins. Every RPC call in this issue goes through one module, `FE/components/explorer/explorer-rpc.ts` (WI-B2), so a rename is a one-file change there. If PAN-5185 is still unmerged when work starts, the work agent stops and reports through `pan tell flywheel-orchestrator`; it does not invent server code.
- **D-B2 What "open a file" does here.** Double click, Enter and the menu's **Open** call `openCodePane()` (WI-B1). A single click only selects the row (and toggles a folder). Preview tabs (single click opens a reusable italic tab) are parent FR-7 and belong to PAN-5187. PAN-5187 changes `openFileFromTree` in `ExplorerPane.tsx`, which is the one seam for it.
- **D-B3 This issue owns the `'code'` pane type, not its renderer.** WI-B1 adds `'code'` to `PaneType`, the fields `explorerRootId`, `explorerPath`, `explorerRevealLine`, `explorerRevealColumn` and `explorerRevealNonce`, the `addPane` dedupe on `(explorerRootId, explorerPath)`, the label `File` and the tab icon. `renderPane` gets no `case 'code'` here. The existing `default:` branch renders `PanePlaceholder` ("This code pane is not implemented yet.") until PAN-5187 adds `case 'code'`. No interim viewer is built.
- **D-B4 Reveal fields follow the message-target precedent.** A content-search click opens the file with `explorerRevealLine`, `explorerRevealColumn` and a fresh `explorerRevealNonce`, as `targetMessageId` / `targetMessageNonce` do for agent panes (`FE/lib/panesStore.ts`, search `targetMessageNonce`). When the code pane already exists, `openCodePane` patches these fields with `updatePane` and focuses the pane. PAN-5187's code pane reads them; this issue only writes them.
- **D-B5 One watch subscription per root, shared.** The watch hub (WI-B8) is a ref-counted module, so PAN-5187's code panes can listen to the same stream without a second server subscription. This issue does not consume watch events in code panes (parent WI-9 is PAN-5187's).
- **D-B6 The Download item is included.** The menu builds the WI-12 URL with `inline=0` and opens it through a temporary `<a download>`. Until PAN-5188 merges, the route answers 404. That interim is accepted, because the order book runs PAN-5188 later and nobody else adds this item.
- **D-B7 No git actions on `project` roots.** Parent D-6 says the primary checkout is never written. Staging and discarding write the index and the working tree, so on a `project` root the Stage, Unstage and Discard items are not rendered. They appear on `issue` and `workspace` roots.
- **D-B8 Changed filter renders a tree synthesized from git status.** When **Changed** is on, the rows come from the `explorerGitStatus` paths (working tree plus `committed`), with every ancestor folder synthesized and expanded. They do not come from the loaded directories. So a deleted file still shows, which matches what `FilesPane` showed. When a path has both a working-tree and a committed change, the working-tree status wins.
- **D-B9 Folder priority is FR-4's, not Orca's.** Orca's `STATUS_PRIORITY` (`~/Projects/orca/src/renderer/src/lib/source-control/paths/git-path-decoration.ts:17-24`) ranks `deleted > modified > added = untracked > renamed > copied` and has no `conflicted`. This issue uses FR-4: `conflicted (6) > deleted (5) > modified (4) > renamed (3) > added (2) > untracked (1)`. The port header names the change.
- **D-B10 Folders show color, files show color and a letter.** A folder's name takes its dominant descendant color; it has no letter. Badges are plain monospace letters, not pills (`pan-style-guide`).
- **D-B11 Shortcuts are pane-scoped React handlers.** There is no keybinding registry. `App.tsx` binds only `Cmd/Ctrl+K` and `Cmd/Ctrl+J` (search `e.key === 'k' && isCmdOrCtrl`), and `useStageShortcuts.ts` ignores combinations with Shift or Ctrl (search `if (e.altKey || e.ctrlKey || e.shiftKey) return`). So `Ctrl/Cmd+P` and `Ctrl/Cmd+Shift+F` are handled in an `onKeyDown` on the explorer pane's root element, with `preventDefault()` (which stops the browser's print dialog). Code panes get no shortcuts in this issue. `QuickOpen` takes props only, so PAN-5187 can mount it in a code pane.
- **D-B12 Expand all is capped.** **Expand all** (header button) expands breadth-first from the root, skipping ignored folders and, when dotfiles are hidden, dot folders. It stops after 2,000 folders and shows the toast "Expanded the first 2,000 folders." **Collapse all** clears the expanded set.
- **D-B13 Dotfiles show by default.** The toggle hides names that start with `.`. Both the toggle and the expanded set persist in `localStorage` under `overdeck.explorer.<rootId>`, with every read and write in try/catch.
- **D-B14 Content search debounce.** Content search runs 300 ms after the last change to the query or a toggle, when the query has at least 2 characters, and at once on Enter. Quick open queries 120 ms after the last keystroke (parent WI-7) and sends nothing for an empty query.
- **D-B15 The swap lands in one item.** The Stage render switch, the `'files'` dedupe change, `IssueOverview` passing `explorerRootId`, the legacy-pane migration and the `FilesPane` deletion are one work item (WI-B14). Split, they would break the issue tab's Files button partway through the branch.
- **D-B16 Visible means mounted and the document is visible.** The 60 s safety refresh of git status runs only while the explorer pane is mounted and `document.visibilityState === 'visible'`.
