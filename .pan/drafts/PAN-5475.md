## Glossary

- **Cost event**: one priced provider request. Fields include time, agent id, issue id, stage (`session_type`),
  provider, model, input/output/cache-read/cache-write tokens and cost in USD.
- **Cost ledger**: where cost events live. Two stores: the append-only archive
  `~/.overdeck/costs/events.jsonl` and the `cost_events` table in `~/.overdeck/overdeck.db`
  (`src/lib/overdeck/paths.ts`, `OVERDECK_DB_FILENAME = 'overdeck.db'`).
- **Price table**: Overdeck's built-in per-model prices (`src/lib/cost.ts`, `getPricing`, `calculateCost`).
- **Bucket**: the pseudo issue ids for spend with no issue: `CONVERSATIONS`, `FLYWHEEL`, `UNATTRIBUTED`
  (`src/lib/costs/attribution.ts`, `NO_ISSUE_BUCKETS`), plus legacy `UNKNOWN`.
- **Stage**: the `session_type` of a cost event, normally the role the agent ran as.
- **Costs page**: the dashboard view at `/costs`, headed **Cost Tracking**.
- **Experimental features**: the switch in **Settings → Experimental** that reveals `/costs` and seven other views
  (documented in `features/dashboard-views.mdx` `## Experimental features`).
- **Mint check**: `npx -y mint@4.3.49 validate` and `npx -y mint@4.3.49 broken-links`, run from the workspace root.
  Always pin `mint@4.3.49`. Never run `mint validate --fix`: it rewrites about 80 files that sibling issues edit.
- **Dash rule**: no em dash (U+2014) or en dash (U+2013) in any line this issue adds or edits, and none in the
  frontmatter `title` or `description` of any touched page.

`FE/` below means `src/dashboard/frontend/src/`.

## Background: verified facts

### How cost is recorded

- F-1. **Claude Code** sessions record cost from a hook. `heartbeat-hook` runs on `PostToolUse`
  (`src/lib/claude-hooks-registration.ts`, search `{ hookType: 'PostToolUse', scriptName: 'heartbeat-hook' }`) and calls
  `record-cost-event.js` (`sync-sources/hooks/heartbeat-hook`, search `record-cost-event.js`). The script
  (`sync-sources/hooks/record-cost-event.ts`) reads new assistant messages from the session transcript, one event per
  request id, and prices the tokens with the price table. So Claude Code spend is recorded after each tool call.
- F-2. **Pi and Codex** sessions are swept from their transcripts when the dashboard starts and every 5 minutes
  (`src/dashboard/server/services/cost-reconcile-service.ts`, `RECONCILE_INTERVAL_MS = 5 * 60_000`,
  `startCostReconcileService`, called from `src/dashboard/server/main.ts`). So their spend can lag up to about five
  minutes, and nothing is swept while the dashboard is down.
- F-3. `pan cost backfill` reconstructs events from stored Claude Code, Pi and Codex transcripts. Without `--write`
  it is a dry run that prints what it would import; `--write` stores the non-duplicate events
  (`src/cli/commands/cost.ts`, `runCostBackfill`, `Run with --write to persist`).
- F-4. Every event is written to `~/.overdeck/costs/events.jsonl` and the `cost_events` table (`appendCostEvent` in
  `src/lib/costs/events.ts`; `CostWriter.record` in `src/lib/overdeck/cost.ts`). Duplicate request ids are dropped
  (`checkDuplicate`).

### Prices: API list prices, not your plan bill

- F-5. Every dollar figure is tokens times the published API price for the model, from the price table
  (`record-cost-event.ts`, `getPricing(provider, model)` then `calculateCost`). The same table prices Codex, Kimi,
  Grok and Muse sessions (`src/lib/cost-parsers/kimi-parser.ts`, `src/lib/costs/grok-collector.ts`,
  `src/lib/cost-parsers/muse-parser.ts`, search `getPricing`).
- F-6. Pi sessions use the cost Pi itself reports for each message when Pi reports one; otherwise Overdeck prices the
  tokens with its table (`src/lib/cost-parsers/ohmypi-parser.ts`, `hasInlineCost`, `computeCostFromPricing`).
- F-7. Overdeck does not know what your subscription covers. No code writes a "covered by plan" marker: the only
  references to `subscription-covered` are readers (`src/lib/overdeck/cost-agent-stats.ts`,
  `src/dashboard/server/routes/resources/agents-stats.ts`), and `grep -rn "subscription-covered" src sync-sources`
  finds no writer. So on a Claude Max or ChatGPT plan, the figures are what the same tokens would cost at API prices,
  not what you pay. No dashboard view or command shows a separate plan cost.
- F-8. A model with no row in the price table: the Claude Code hook records no event for it (`if (!pricing) continue;`);
  Pi records the event with cost 0 and an `unpriced-model` warning (`ohmypi-parser.ts`, `reason: 'unpriced-model'`);
  Muse records 0 (`muse-parser.ts`, `pricing ? ... : 0`). Mis-priced models are tracked in #4844.

### Attribution

- F-9. The hook takes the issue from `OVERDECK_ISSUE_ID` and the agent from `OVERDECK_AGENT_ID`, which Overdeck sets when
  it launches an agent for an issue. When no issue is set, a Claude Code session whose git branch contains
  `pan-`, `min-`, `aud-`, `krux-` or `cli-` followed by a number records against that issue
  (`record-cost-event.ts`, `branchMatch = branch.match(/(pan|min|aud|krux|cli)[-](\d+)/i)`). Otherwise the issue is
  `UNKNOWN`. Do not generalize this to other prefixes or harnesses.
- F-10. Spend with no issue is sorted into buckets (`src/lib/costs/attribution.ts`, `classifySessionBucket`): a
  session that belongs to the Flywheel conversation goes to `FLYWHEEL`, any other known conversation to
  `CONVERSATIONS`, and the rest to `UNATTRIBUTED`. The dashboard's 5-minute sweep reclassifies `UNKNOWN` rows this way
  (`cost-reconcile-service.ts`, `reclassifyUnknownCostEvents`). The Costs page labels them **Conversations**,
  **Flywheel orchestration**, and "No issue, unattributed" (`FE/lib/cost-bucket-labels.ts`; the real label contains an
  em dash, so paraphrase it, never quote it).
- F-11. Stage is the role the session ran as. Observed values on this machine (`sqlite3 ~/.overdeck/overdeck.db
  "select session_type, count(*) from cost_events group by 1"`): `work`, `implementation`, `review`,
  `review.correctness`, `review.requirements`, `review.performance`, `review.security`, `test`, `plan`, `flywheel`,
  `strike`, `inspect`, `background`. Some imported sessions show their harness name (`codex`, `ohmypi`) as the stage.
  List only a few examples on the page; do not claim the list is complete.
- F-12. **Project spend** (changelog v0.87.0, #5288): `GET /api/costs/summary?project=<PREFIX>`
  (`src/dashboard/server/routes/costs.ts`, `PAN-5288 A-D17`) counts an event when its issue id starts with
  `<PREFIX>-` or its agent id is the session of one of the project's conversations (live or archived)
  (`src/dashboard/server/services/project-spend.ts`, `inProjectSpend`, `conversationSessionsForProject`). A
  conversation belongs to a project by its project, or else by the registered project path that contains its folder.
- F-13. Windows (`src/lib/costs/request-digest.ts`, `usageWindowStarts`): **today** starts at local midnight on the
  dashboard machine; **week** starts at the start (UTC) of the day seven days ago; **month** covers the last 30 days
  (`MONTH_MS = 30 * 24 * 60 * 60 * 1000`). Project Home reads this route from the archive
  (`readEventsSince`), while the Costs page's Issues tab reads the `cost_events` rollup
  (`src/lib/overdeck/cost-sync.ts`, `getCostsByIssue`). Do not claim the two totals reconcile.

### Where spend shows in the dashboard

- F-14. **Project Home, Spend this week** (`FE/components/Stage/HomePane/HomeFacts.tsx`, `label="Spend this week"`):
  the project's week spend, with today's spend below it (`$43 today` style). Without an issue prefix it shows a dash and
  `needs an issue prefix`; when the read fails or takes over 20 seconds it shows `unavailable`
  (`FE/components/Stage/HomePane/useHomeData.ts`, `SPEND_TIMEOUT_MS = 20_000`). It refreshes every 60 seconds.
  Clicking it opens `/costs` (`FE/components/Stage/ProjectHome.tsx`, `onSpend={() => navigate('/costs', 'costs')}`),
  which lands on Home unless Experimental features is on (`FE/lib/experimentalFeatures.ts`, `EXPERIMENTAL_TAB_IDS`
  contains `'costs'`; `FE/App.tsx`, `denyExperimental`). #5562 item 4.
- F-15. **Issue drawer, Details tab** (`FE/components/issue-detail/IssueDrawerDetails.tsx`): the **Pipeline** section
  lists each phase's agent with its cost, and a **Total** row whose tooltip reads
  `Whole issue, including agents not listed above`. **Cost breakdown** expands two tables, **By stage** and
  **By model** (`FE/components/CommandDeck/ZoneCOverviewTabs/CostsTab.tsx`, `title="By stage"`, `title="By model"`),
  with costs under one cent shown as `<$0.01` (write it as `&lt;&#36;0.01` or inside backticks).
- F-16. **Board cards**: hovering an issue card with recorded cost shows a cost badge; clicking it opens the cost
  breakdown (`FE/components/KanbanBoard/cards/KanbanCards.tsx`, `data-testid={\`card-cost-${issue.identifier}\`}`,
  `CostBreakdownModal`).

### Cost limits (opt-in, warn only)

- F-30. `~/.overdeck/cloister.toml` (`src/lib/cloister/config.ts`, `CLOISTER_CONFIG_FILE = join(OVERDECK_HOME,
  'cloister.toml')`) accepts a `[cost_limits]` table: `per_agent_usd`, `per_issue_usd`, `daily_total_usd` (each is
  today's spend; unset or 0 means not checked) and `alert_threshold` (fraction, default 0.8) (`CostLimitsConfig`).
  There are no defaults.
- F-31. A crossing writes one warning line to the dashboard log (`src/lib/cloister/service-health.ts`,
  `checkCostAlerts`, `COST LIMIT REACHED`, `Cost warning:`). Nothing in the dashboard shows it, and limits never stop
  or pause an agent (`src/lib/cloister/cost-monitor.ts` header, `Does NOT automatically stop agents`).
