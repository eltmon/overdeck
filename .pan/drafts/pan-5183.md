## 1. Summary

Overdeck shows a project's files only through what an agent did: the changed-files list (`FilesPane`), file links in chat, and the markdown-only `EditorPane`. No surface lists a project's directories. This PRD adds a full file explorer to the Stage with parity to Orca's explorer and t3code's file viewers:

1. A live tree of any project checkout or workspace, colored by git status, updated by a file watcher.
2. A Monaco editor for every text file, with autosave and Orca's disk-conflict handling.
3. t3code's viewers for images, PDF, audio, fonts, large text and CSV, archives and SQLite (tier 1), and Office, notebooks and Mermaid (tier 2).
4. File actions: create, rename, move by drag, duplicate, delete to a recoverable trash, undo and redo, upload from the OS, and download.
5. **Edit workspaces.** The primary checkout is never written. The first write from a project's tree creates an isolated worktree, and the write lands there.
6. **Create PR** with two paths: a direct PR with a one-click merge when GitHub reports no conflicts, or a pipeline PR that creates an issue and goes through Overdeck's review pipeline.

## 2. Glossary

- **Explorer pane** — the Stage pane with `paneType: 'files'`. This PRD repurposes the existing `'files'` type (today the changed-files list, `FilesPane.tsx`) as the explorer. The changed-files list becomes the explorer's **Changed** filter.
- **Code pane** — a new Stage pane type, `'code'`, that shows one file from an explorer root in Monaco or a viewer. One code pane per `(explorerRootId, explorerPath)`.
- **Explorer root** — the directory a tree shows. Three kinds:
  - `project` — a registered project's primary checkout (`config.path` from the projects registry). **Read-only on disk.** Writes go to an edit workspace (FR-12).
  - `issue` — an issue workspace, `<project>/workspaces/feature-<issue-lower>/` (path from `getWorkspacePathForIssue`, `src/dashboard/server/workspace-paths.ts`).
  - `workspace` — a workspace-registry row of kind `scratch` that is `isolated` (a git worktree). Edit workspaces are this kind.
- **Root id** — the string the client sends to name a root: `project:<projectKey>`, `issue:<ISSUE-ID>` or `workspace:<registryId>`. The client never sends an absolute root path; the server resolves the root id. All file paths in explorer requests are **relative to the root**, POSIX separators.
- **Edit workspace** — an isolated scratch workspace that the explorer creates on the first write in a `project` root. Branch `scratch/edit-<slug>`, directory `<project>/workspaces/scratch-edit-<slug>/`, based on `origin/<default branch>`. `<slug>` is `MMDD-HHMM` local time, with `-2`, `-3`… on collision.
- **Disk signature** — Orca's content fingerprint: two-lane FNV-1a hash plus byte length, formatted `"<hashA>-<hashB>-<length>"` (Orca `src/shared/file-write/disk-baseline-signature.ts`). It is computed on the server from the bytes on disk.
- **Disk precondition** — the `expectedSignature` a write carries. The server refuses the write when the file's current signature differs (FR-8).
- **Self-write suppression** — the client ignores watcher events for a path it wrote itself within the last 750 ms (Orca `editor-self-write-registry.ts`).
- **Watcher child** — a Node child process, forked by the dashboard server, that runs `@parcel/watcher` and sends batched change events to its parent over IPC.
- **Overdeck trash** — `~/.overdeck/trash/<root-slug>/<timestamp>-<n>/<relative path>`. Deleted entries are moved here and can be restored. Entries older than 7 days are pruned.
- **Direct PR** — a PR opened from an edit workspace's branch to the default branch with no issue and no pipeline. The operator merges it with one click.
- **Pipeline PR** — a PR for a new tracker issue, created by converting the edit workspace into an issue workspace (`feature/<issue>`) and requesting review through Overdeck's pipeline.
- **Port record** — one entry in `scripts/upstream-ports.json` that maps an Overdeck file to the upstream file and commit it was ported from (FR-17).

## 3. Decisions

- **D-1 Port once; do not vendor.** Vendoring means copying upstream folders unchanged so that later upstream commits can be re-copied. Measured against the code, that is not possible:
  - Orca's explorer folder is 87 files and about 11.8k lines. Its runtime import closure is about 2,825 files and 320k lines. 21 explorer files import Orca's global store (`src/renderer/src/store/index.ts`, built from about 50 slices). Even with the store cut out, the closure stays at about 190k lines, because explorer code reaches terminal tabs, agent sessions and worktree activation directly (for example `tree/use-file-explorer-tree-pane-state.ts` → `lib/browser/documents/file-preview.ts` → `lib/workspace/activation/worktree-activation.ts`).
  - Both upstreams use React 19 (Orca `~19.2.8`, t3code `19.3.0`), zustand 5 and Tailwind 4. Overdeck's dashboard uses React `^18.3.1`, zustand `^4.5.7` and Tailwind `^3.4.19` (`src/dashboard/frontend/package.json`). The upstream code uses React-19-only patterns: a context rendered directly as a provider (Orca `components/ui/tooltip.tsx:66`), `ref` received as a plain prop (Orca `lib/text-input/ime/ime-text-field.tsx:39-42`, t3code `FileBrowserPanel.tsx:85-99`), and `useEffectEvent` (Orca `hooks/useMetadataListRequest.ts:30`, t3code `PdfViewer.tsx:234`). Their UI primitives use Tailwind-4-only class syntax such as `bg-(--x)` and `origin-(--radix-…)`.
  - **So:** we port the logic and behavior file by file into Overdeck's stack and style. To keep pulling upstream improvements, every ported file gets a port record, and `scripts/upstream-port-diff.sh` lists the upstream commits that touched each ported file since its recorded commit (FR-17). A person or the Flywheel reviews that list and ports what matters. This replaces `git cherry-pick`, which cannot work across unrelated histories anyway.
- **D-2 Editor is Monaco.** Overdeck already ships `monaco-editor ^0.55.1` and `@monaco-editor/react ^4.7.0`, the same versions Orca uses. t3code's editor needs `@pierre/diffs/edit` from `@pierre/diffs 1.7.0-beta.3`; Overdeck pins `1.1.22`, which has no `./edit` export.
- **D-3 Tree is Overdeck's own component.** It uses `@tanstack/react-virtual` (already installed) for virtualization and ports Orca's tree projection logic (`tree/`). `@pierre/trees` is not added.
- **D-4 Look follows Overdeck's style guide.** Ported components use Overdeck's Tailwind 3 tokens (`src/dashboard/frontend/tailwind.config.js`) and `components/shared/ContextMenu.tsx`. Before writing UI, the executor loads the `pan-style-guide` skill. Git decoration colors map to existing semantic tokens:
  - untracked and added → `success`
  - modified and renamed → `warning`
  - deleted and conflicted → `destructive`
  - ignored → `faint-foreground`, italic
- **D-5 The watcher never runs in the dashboard process.** `@parcel/watcher` froze the dashboard before (PAN-4193). The dashboard's own child processes send SIGCHLD; parcel's inotify `poll()` fails with EINTR, and the backend deadlocks in its destructor (header of `src/dashboard/server/services/conversation-directory-watcher.ts`). Node's `fs.watch` was rejected for large trees (more than a GB of native watcher state, same header). Orca runs `@parcel/watcher` in a forked child with a supervisor (`src/main/ipc/filesystem/watcher-process/child-lifecycle/parcel-watcher-child-launch.ts:31`). We do the same. If the child deadlocks, only the child stops; the supervisor kills and restarts it (FR-3). `@parcel/watcher ^2.6.0` is already in root `package.json` (search `"@parcel/watcher"`) and in the `neverBundle` list of `src/dashboard/server/tsdown.config.ts`.
- **D-6 The primary checkout is never written.** Every write request with a `project:` root id is refused by the server with code `EDIT_WORKSPACE_REQUIRED`. The client then creates or reuses an edit workspace and repeats the write there (FR-12). This keeps the worktree rule: edits in the primary checkout would land on `main` outside review.
- **D-7 Delete moves to the Overdeck trash.** Browsers have no OS trash, and the server may be on another machine (Overdeck Anywhere). So the server moves deleted entries to the Overdeck trash, which also makes directory deletes undoable. Orca cannot undo those. A rename across filesystems (`EXDEV`) falls back to a recursive copy, then removal.
- **D-8 All new RPC methods and HTTP routes are admin-scoped.** Methods missing from `RPC_METHOD_SCOPES` (`src/dashboard/server/route-scopes.ts`, search `export const RPC_METHOD_SCOPES`) default to `admin` (search `RPC_METHOD_SCOPES[tag] ?? 'admin'`). No entries are added. New HTTP routes get `admin` rows in `ROUTE_SCOPES` in the same file, following the existing rows.
- **D-9 "No conflicts" means GitHub will merge it now, without bypass.** One-click merge is enabled only when `gh pr view` reports `mergeable == "MERGEABLE"` and `mergeStateStatus` is one of `CLEAN`, `UNSTABLE` or `HAS_HOOKS`. Every other state disables the button and shows the reason in words: `DIRTY` = conflicts, `BLOCKED` = required checks or reviews not met, `BEHIND` = branch out of date, `DRAFT`, `UNKNOWN` = GitHub still computing. The merge is a squash pinned to the head commit through the existing forge adapter (`getForgeAdapter(...).mergeReviewArtifact`, `src/lib/forge.ts`, search `async mergeReviewArtifact(input)`). Required checks and branch protection still apply. No `--admin` anywhere.
- **D-10 Edits are authored by the operator.** Edit workspaces are created by the dashboard with no agent, so they keep the operator's git identity and remote. The bot identity is set only at agent spawn (`src/lib/agents/spawn.ts`, search `configureWorkspaceGitHubIdentity`). Direct and pipeline PRs are both opened as the operator.
- **D-11 One active edit workspace per project by default.** A request to begin editing reuses the newest edit workspace of that project whose PR is not merged or closed. The **New edit workspace** menu item forces a fresh one. "Newest open edit workspace" is derived from the workspace registry (branch prefix `scratch/edit-`) and GitHub, so no new stored state is added.
- **D-12 Size limits.**
  - Text files up to 5 MiB open in Monaco, editable.
  - Text files over 5 MiB open in the large-text viewer, read-only.
  - A file is binary when its first 8 KiB contains a NUL byte (t3code `WorkspaceFileSystem.ts:427-433`).
  - Uploads are capped at 100 MiB per file.
  - Directory listings are capped at 10,000 entries per directory, with a `truncated` flag.
- **D-13 Undo and redo** are an in-memory stack per root, 50 steps, cleared on page reload (Orca `mutations/fileExplorerUndoRedo.ts`). Undo of a delete restores from the Overdeck trash.
- **D-14 Downloads and uploads are HTTP routes; everything else is WebSocket RPC.** Large binary bodies do not belong on `/ws/rpc` frames.

## 4. Requirements

### Functional

- **FR-1** The explorer opens from a project's home (ActionDock **Files** button, at project scope) on root `project:<key>`, and from an issue tab (ActionDock **Files**) on root `issue:<ID>`. Each `(deck, root)` pair has at most one explorer pane.
- **FR-2** The tree lists directories lazily, one directory per request. It sorts directories first, then files, in natural, case-insensitive order (`9` < `99` < `100`). It virtualizes rows, toggles dotfiles, keeps the expanded set per root across reloads, and shows ignored entries italic and dimmed. **Expand all** skips ignored directories.
- **FR-3** The tree, open code panes and git colors update within 500 ms of a change on disk made by any process. A burst of more than 5,000 events becomes one `overflow` event, and the client re-lists every expanded directory.
- **FR-4** Rows are colored by git status, with a one-letter badge (`U` untracked, `A` added, `M` modified, `D` deleted, `R` renamed, `C` conflicted). A folder takes the highest-priority status of its descendants, in the order conflicted > deleted > modified > renamed > added > untracked.
- **FR-5** The right-click menu offers:
  - **Read actions:** Open, Copy path, Copy relative path, Find in folder, Download.
  - **Git actions:** Stage, Unstage, Discard changes (with a confirmation dialog).
  - **Write actions:** New file, New folder, Rename, Duplicate, Delete.
- **FR-6** **Quick open** (`Ctrl/Cmd+P` while the explorer or a code pane has focus) fuzzy-matches file paths in the root. **Search** (`Ctrl/Cmd+Shift+F`, or **Find in folder**) searches file contents. It can be scoped to a folder and has case and regex toggles.
- **FR-7** Text files open in a code pane with Monaco and syntax highlighting for every Monaco language. Autosave runs 1,000 ms after the last keystroke, and `Ctrl/Cmd+S` saves immediately. Markdown files have an Edit / Preview toggle that reuses `MarkdownTab`.
- **FR-8** Conflict handling, with Orca parity:
  - Every write carries the disk signature of the content the editor last loaded or saved, and the server refuses a write whose precondition fails.
  - When a file changes on disk and its pane has no unsaved edits, the pane reloads after 250 ms.
  - When a file changes on disk and its pane has unsaved edits, the pane shows a banner with **Compare** (a Monaco diff of disk against the edits), **Reload from disk**, **Keep my edits** and **Overwrite**.
  - A file deleted on disk is marked *deleted*. A delete followed by a create of the same basename is marked *renamed*. If the file reappears, the mark clears.
  - The pane's own writes do not trigger the banner (self-write suppression).
- **FR-9** Viewers. Tier 1: images (png, jpg, gif, webp, svg, avif; heic and tiff via decoders), PDF, audio, fonts, large text and CSV/TSV tables, zip archives and SQLite databases. Tier 2: Office documents (docx, xlsx, pptx, odt, ods, odp), Jupyter notebooks and Mermaid diagrams. Any other binary file shows its size and a **Download** button.
- **FR-10** File actions:
  - **Create:** an inline name row, for a file or a folder.
  - **Rename:** inline. Open code panes follow the new path.
  - **Move:** drag rows onto a folder. Folders expand after 600 ms of hover, and the tree scrolls when a drag reaches its edge.
  - **Duplicate:** creates `name copy.ext`, then `name copy 2.ext`, and so on.
  - **Delete:** moves to the Overdeck trash. A multi-select asks for confirmation.
  - **Undo / redo:** `Ctrl/Cmd+Z` and `Ctrl/Cmd+Shift+Z` while the tree has focus.
  - **Upload:** drop files from the OS onto a folder.
  - **Download:** a file as is, a folder as `.tar.gz`.
- **FR-11** Dragging tree rows onto a conversation composer inserts their root-relative paths, one per line, at the cursor.
- **FR-12** Edit workspaces:
  - The first write action in a `project` root creates an edit workspace, or reuses one (D-11), then repeats the action there.
  - While the workspace is created, the editor keeps the pending edit in memory and shows "Creating edit workspace…".
  - Afterwards, the explorer pane and that project's code panes switch to the edit workspace root, and a banner reads: "Editing in edit workspace `<name>` (branch `scratch/edit-<slug>`). The main checkout is not changed." with **Create PR** and **Discard** buttons.
  - If the file's content in the new worktree differs from the content the edit started from, the FR-8 banner appears instead of a silent write.
- **FR-13** **Create PR** opens a dialog with title, body, a draft toggle and two buttons: **Open PR** (direct) and **Send through pipeline** (pipeline).
  - Both commit every change in the edit workspace (`git add -A`, commit message = title) and push the branch.
  - **Direct** opens a PR from `scratch/edit-<slug>` to the default branch.
  - **Pipeline** follows FR-16.
- **FR-14** After a direct PR is open, the banner shows the PR link, its state and a **Merge** button. The button is enabled only under D-9; otherwise it is disabled with the reason shown. **Refresh** re-reads the state; there is no polling. A successful merge removes the edit workspace (worktree, local branch and registry row) unless it has uncommitted changes, in which case it is kept and the banner says why.
- **FR-15** **Discard** removes an edit workspace: its worktree, its local branch and its registry row. A checkbox, on by default, also closes the PR if one is open. A confirmation dialog lists the uncommitted files that will be lost.
- **FR-16** **Send through pipeline:**
  1. Creates a tracker issue with the dialog's title and body, plus the line "Created from the Overdeck file explorer."
  2. Renames the branch to `feature/<issue-lower>` and moves the worktree to `<project>/workspaces/feature-<issue-lower>/`.
  3. Updates the registry row.
  4. Opens the PR with `ensurePRExists`.
  5. Requests review with `requestReviewGuarded`.

  The explorer then shows the root `issue:<ID>`.
- **FR-17** Every ported file starts with a header naming the upstream, its license, its path and its commit, and has a port record. `scripts/upstream-port-diff.sh` prints, for each record, the upstream commits since the recorded commit that touched the upstream path.
- **FR-18** Orca's and t3code's MIT license texts ship in `licenses/`. `docs/ACKNOWLEDGEMENTS.md` lists both. Any upstream sub-licenses that come along (for example t3code `apps/web/src/components/files/office/LICENSE.opencode`) ship too.

### Non-functional

- **NFR-1** Server code uses only async I/O: `fs/promises`, async `execFile`/`spawn`. No `execSync`, `readFileSync` or other `*Sync` call is reachable from the dashboard server (repo rules: no `execSync` in server code; prefer async).
- **NFR-2** The dashboard process never loads `@parcel/watcher` (D-5).
- **NFR-3** Path safety, on every request:
  - Relative paths only: no absolute paths, no `..` segments, no NUL bytes.
  - Containment is checked on the realpath of the nearest existing ancestor.
  - Writes inside any `.git` directory are refused. That includes renamed or bare git dirs and NTFS aliases (port t3code `WorkspaceFileSystem.ts:32-36, 201-219`).
  - Symlinks that resolve outside the root are refused.
- **NFR-4** A 5,000-entry directory lists in under 300 ms on the server, and the tree scrolls 10,000 rows at 60 fps (virtualized).
- **NFR-5** The watcher never watches ignored directories. The ignore list is Orca's (`src/main/ipc/filesystem/watchers/filesystem-watcher-ignore.ts:2-15`: `.git node_modules dist build .next .cache target .venv __pycache__ .dart_tool .gradle .turbo`) plus `workspaces` when the root is a primary checkout, because Overdeck worktrees live under it.
- **NFR-6** Overdeck stores no status it can derive. Edit workspaces are registry rows (already stored). PR state is read from GitHub on demand. Undo stacks are in-memory. The only new on-disk data is the trash.
- **NFR-7** Every new `src/` file stays under the 1,000-line ceiling (`scripts/lint-file-size.sh`). Watch the existing caps on files this work touches (`scripts/file-size-allowlist.txt`):
  - `src/dashboard/server/ws-rpc.ts`: 1128 lines, cap 1221
  - `src/dashboard/frontend/src/components/CommandDeck/index.tsx`: 1590, cap 1612
  - `src/dashboard/server/routes/workspaces/merge-ops.ts`: 1768, cap 1835

  New handlers therefore live in new files.

## 5. Repo rules that apply (restated)

- **Async only** in server-reachable code (NFR-1). Delays use `await new Promise(r => setTimeout(r, ms))`.
- **Fake timers** for every debounce, batching, autosave or retry test: `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`, never real waits. A test that must use real time goes in `<name>.slow.test.ts`.
- **One variant per operation in `src/lib`.** Add no Effect wrapper around in-repo Promise code and no sync/async twins (`npm run lint:effect-facades`, `docs/EFFECT-BRIDGING.md`). Server RPC handlers wrap Promise code with `Effect.tryPromise` at the handler, as `services/file-at-path.ts` does.
- **No new import cycles** (`npm run lint:circular`). New lib modules that need agent state import `getAgentState` from `agent-state-read.js`.
- **No-loss matrix.** Every new RPC method and every new top-level HTTP route needs a row in `tests/unit/lib/overdeck/no-loss-matrix.ts` (search `surface: 'pan.readFileAtPath'`), or `no-loss-matrix.test.ts` fails.
- **Route scopes** (D-8).
- **Changelog.** Each child PR adds `changelog.d/<issue>.md` (format in `changelog.d/README.md`). Never edit the top of `changelog.mdx`.
- **New tests must not read source files with grep-style assertions or add `skipIf`/`.only`.** The lint and test-skip gates reject both.
- **Workspace doors.** Workspace-registry rows are written only through `src/lib/workspaces/writer.ts` and resolved only through `src/lib/workspaces/create.ts` (`scripts/guard-workspace-doors.sh`).
- **Never `git stash`.** No code path in this PRD stashes.
- **Quality gates** before `pan done`: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` locally; CI runs it.
- **Style:** the `pan-style-guide` skill. Running is not green, no pill badges, no Inter.

### WI-11 — Write services: write, create, rename, copy, delete, restore and trash  (traces FR-8 server side, FR-10, D-6, D-7)

**Files:** new `src/dashboard/server/services/explorer/write.ts`, `trash.ts`; edit `ws-rpc-explorer.ts`.

**Steps:**
1. `writeFile(root, rel, text, expectedSignature, allowMissing)`:
   - `resolveInsideRoot(..., { forWrite: true })`.
   - If the file exists and `expectedSignature !== null` and `diskSignature(current) !== expectedSignature`, throw `DISK_CONFLICT`.
   - If the file is missing, `expectedSignature` is not null and `allowMissing` is false, throw `DISK_CONFLICT`.
   - Write atomically: write to `<dir>/.<name>.overdeck-tmp-<random>`, `fsync`, then `rename` over the target. Keep the file mode of an existing file.
   - Return `{ signature, mtimeMs }`.
2. `create(root, rel, kind)`: `mkdir(parent, { recursive: true })`, then `writeFile(path, '', { flag: 'wx' })` or `mkdir(path)`. `ALREADY_EXISTS` on `EEXIST`.
3. `rename(root, from, to)`: both paths resolved for write. Refuse when the target exists (`ALREADY_EXISTS`). `fs.rename`; on `EXDEV`, `cp(from, to, { recursive: true })`, then `rm(from, { recursive: true })`.
4. `copy(root, from, to)`: `fs.cp(..., { recursive: true, errorOnExist: true, force: false })`.
5. `trash.ts`:
   - `trashPaths(root, rels): Promise<string[]>` moves each path to `~/.overdeck/trash/<root-slug>/<ISO-timestamp>-<n>/<rel>`. The root slug is the root id with `:` replaced by `-`. Use `OVERDECK_HOME` from `src/lib/paths.ts`, not a hardcoded `~/.overdeck`. The EXDEV fallback is as in step 3. It returns the trash ids `<root-slug>/<ISO-timestamp>-<n>`.
   - `restore(root, trashId)` moves the entry back to its original relative path, which is recorded in `<trash entry>/.overdeck-trash.json` `{ rootId, path }`. `ALREADY_EXISTS` if something now occupies that path.
   - `pruneTrash()` removes entries older than 7 days. It runs at the start of every `trashPaths` call and is cheap, because it only lists the top-level directories under each root slug.
6. Register the handlers `explorerWriteFile`, `explorerCreate`, `explorerRename`, `explorerCopy`, `explorerDelete` and `explorerRestore` in `ws-rpc-explorer.ts`, and add their no-loss-matrix rows.

**Tests:** `__tests__/write.test.ts` (precondition match, mismatch, missing and null-overwrite; atomic write keeps the mode; create `ALREADY_EXISTS`; rename refuses an existing target; a project root gives `EDIT_WORKSPACE_REQUIRED`); `__tests__/trash.test.ts` (trash then restore round trip; restore refuses an occupied path; prune removes only entries older than 7 days, using an injected clock).
