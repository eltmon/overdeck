# PAN-4486: New conversation split button with a per-launch options dialog

**Issue:** [PAN-4486](https://github.com/eltmon/overdeck/issues/4486)
**Blocked by:** PAN-4254 (all five effort levels at creation). PAN-4254 merged on main as `83ec5bbcba9` (PR #4489), so this issue is unblocked. `isValidConversationEffort` and `resolveConversationEffort` in `src/lib/overdeck/conversation-effort.ts` are the PAN-4254 doors this plan uses.
**Related:** PAN-3942 (skill layers), PAN-4334 (skill packs), PAN-4185 (bare context and skip CLAUDE.md), PAN-1357 (template conversations, later), PAN-743 (consistent new-conversation actions).

## Glossary

- **Quick create**: the main click on the Command Deck sidebar `+` button. It POSTs `/api/conversations` with the sidebar's stored model, harness and effort, and no dialog opens.
- **Options dialog**: the new modal, "New conversation with options…". Every choice in it applies to that one launch only.
- **Split button**: the sidebar `+` button plus a caret button next to it. The caret opens a one-item menu.
- **Context opt-outs**: the two PAN-4185 flags. `bareContext` drops every Overdeck-injected layer. `skipClaudeMd` (claude-code only) sets `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Both are stored on the row as `conversations.bare_context` and `conversations.skip_claude_md`.
- **Skill layers**: the PAN-3942 per-skill on/off maps at the global, project and issue levels, resolved narrowest-first in `src/lib/skill-overrides/resolve.ts`. Pack skills (PAN-4334) have ids of the form `pack/skill`.
- **Conversation skill layer**: the new layer this issue adds. It is a `Record<string, boolean>` stored on the conversation row and resolved before the issue layer, so it is the narrowest of all.
- **Launch-settings step**: the launcher bash line `pan skills launch-settings --harness … --cwd … [--issue …]`, built in `src/lib/skill-overrides/launcher-lines.ts`. It runs before the harness starts on every launch: create, resume, restart-all and fork. It turns the resolved layers into Claude `--settings {"skillOverrides":…}` or Codex `[[skills.config]] enabled = false`.
- **Launch context**: the `ConversationLaunchContext` type in `src/lib/overdeck/conversation-launch-context.ts`. It is read from the row by `conversationLaunchContext(conv)`, which is how resume, restart and fork keep per-conversation launch facts.
- **Effort source**: the `EffortSource` from `resolveEffort()` (`src/lib/agents/resolve-effort.ts`). Its values are `explicit | item | plan | tier | sub-role | role | project | default`.
- **Frontend subset**: root `package.json` script `test:frontend-subset`. CI runs only the frontend test files listed there.

## Problem

The Command Deck sidebar sets new-conversation options in place. It has the model and effort pickers (`NewConversationPickers`) and two sticky checkboxes, "No context" and "Skip CLAUDE.md". The checkboxes live in `src/dashboard/frontend/src/components/CommandDeck/NewConversationContextOptions.tsx` and are mounted at `CommandDeck/index.tsx` line 1378. They persist in localStorage key `overdeck.commandDeck.newConversationContext`, so a one-off choice silently carries into the next conversation. Three launch options have no UI at all: a resolved effort default with its source, a linked issue, and per-conversation skills.

## Proposal (summary)

1. Make the sidebar `+` a split button. The main click stays quick create. The caret opens a menu with one item, "New conversation with options…".
2. That item, and a matching command-palette action, open a store-driven modal mounted in `main.tsx`. Its fields are: project and working directory, model and harness, effort (with the resolved default and its source), the two context opt-outs, per-conversation skill on/off, a linked issue, and an optional first message.
3. The backend gets a conversation skill layer, stored on the row and applied by the launch-settings step on every launch. It also accepts a `cwd` inside the chosen project, and gets a read route for the default effort and its source.
4. The two checkboxes leave the sidebar. Quick create sends no context opt-outs.

## Requirements

### Functional

- **FR-1**: The main click on the sidebar `+` creates a conversation with no dialog. The POST body has the same fields as today, except that `bareContext` and `skipClaudeMd` are never sent.
- **FR-2**: A caret button beside the `+` opens a menu with one item, "New conversation with options…", which opens the options dialog. The dialog's project is preset to the deck's selected project, unless that is the no-project bucket.
- **FR-3**: The command palette has an action "New conversation with options…" that opens the same dialog with no project preset.
- **FR-4**: The dialog has the following fields, and submitting it POSTs `/api/conversations` with these values:
  - Project (registered projects, plus "No project").
  - Working directory (defaults to the project path; disabled with no project).
  - Model and harness.
  - Effort (the levels the model supports; defaults to the resolved default, with its source shown).
  - No context, and Skip CLAUDE.md (shown only for claude-code), each with the PAN-4185 explanation text.
  - Skills (per-skill Inherit / On / Off over the effective state).
  - Linked issue (a searchable picker).
  - First message (optional).
- **FR-5**: Opening, editing or submitting the dialog never writes localStorage keys `conv-composer-model`, `conv-composer-harness`, `conv-composer-effort` or `overdeck.commandDeck.newConversationContext`. The next quick create therefore uses exactly what it used before.
- **FR-6**: `POST /api/conversations` accepts `skillOverrides`, an object of skill id to boolean. It persists the object on the row (`conversations.skill_overrides`, JSON text) and rejects a malformed object, or one that names a core skill, with 400.
- **FR-7**: Every launch of a conversation (create, resume, restart-all, fork, and a post-`/clear` relaunch) applies the row's skill overrides as the narrowest layer, above issue, project and global. A skill the conversation turns off is hidden from the harness, and a pack skill it turns on is mounted.
- **FR-8**: `POST /api/conversations` accepts `cwd` only together with `projectKey`. The `cwd` must pass `validateCwdContainment` and its realpath must equal, or be under, the realpath of the project path. Otherwise the request fails with 400 and no row is created. The row stores the realpath.
- **FR-9**: `GET /api/effort/default?model=<id>&harness=<runtime>&issue=<ID>` returns `{ effort, source, requested, clamped, warning? }` from `resolveEffort({ model, harness, issueId })`. An unknown harness or a malformed issue id is ignored, not rejected.
- **FR-10**: The sidebar no longer renders the "No context" and "Skip CLAUDE.md" checkboxes. `NewConversationContextOptions.tsx` and its test are deleted.
- **FR-11**: After a successful dialog create, the dialog closes, `['conversations']` is invalidated, and the new conversation opens through `/conv/<id>`.

## Decisions

- **D1. The conversation layer lives on the row, and the launcher rereads the row.** The launch-settings step gets `--conversation <tmuxSession>`. It is emitted by `launcherSkillOverrideLines` whenever `spawnMode === 'conversation'` and `managedStateKey` is set. `pan skills launch-settings` then loads the row with `getSupervisedConversationByTmuxSession`. No line is added to `conversation-runtime.ts` or `launcher-generator.ts`. Resume, restart and fork already regenerate the launcher, so the layer survives every relaunch with no extra plumbing.
  - Rejected: an exported env var, because it could leak into child launches.
  - Rejected: threading the map through `generateLauncherScript`, because `conversation-runtime.ts` is at its line cap.
- **D2. Do not widen `SkillOverrideLevel`.** Add `conversation?: SkillOverrideMap` to `SkillOverrideLayers`, and add `'conversation'` to `SkillStateSource` and `PackSkillSource` only. The PUT `/api/skills/overrides` door stays unable to write a conversation level. Conversation overrides are set only at creation, in the dialog.
- **D3. Conversation values are per-skill only.** There are no conversation-level pack toggles. For a pack skill id, a conversation value beats every level and every pack toggle. Core skills ignore the conversation layer, exactly as they ignore every other layer.
- **D4. Working directory is limited to the chosen project.** The rule is `validateCwdContainment(cwd)`, and the realpath must equal or be under the realpath of the project path. Create keeps accepting a primary checkout, because a project's root is today's default cwd. The fork door's primary-checkout ban does not apply to the operator's create dialog.
- **D5. The dialog always sends `effort` when the model supports effort.** It sends the resolved default when the operator leaves effort untouched, so the row records it. When the model supports no effort (`pickerEffortLevels(model) ?? MODEL_EFFORT_SUPPORT[model]` is `[]`), the field shows "Not supported by this model" and `effort` is omitted.
- **D6. The dialog host is mounted in `main.tsx` and is opened through a zustand store.** This follows the `LinkPullRequestDialogHost` pattern. It opens the new conversation by URL (`/conv/<id>`), not through CommandDeck callbacks.
  - **Implementation checkpoint:** in the browser, confirm that after a dialog create the new conversation becomes the selected conversation in the Command Deck.
  - **Fallback:** if it does not, dispatch `window.dispatchEvent(new CustomEvent('overdeck:conversation-created', { detail: { name, id, projectKey } }))`. Then add a listener in `CommandDeck/index.tsx`, modelled on the `overdeck:open-fork-modal` listener at ~line 1120, that runs the same selection and tab-opening steps as `createConversationForProject`. The file must stay at or under its 1612-line cap.
- **D7. The project preset resolves to a yaml key.** The dialog matches the preset against `/api/registered-projects` by `key`, then by `name`. It uses the key for both `GET /api/skills/overrides?project=` and the POST.
- **D8. The skills field falls back when the issue is unowned.** If `GET /api/skills/overrides` with `issue=` answers non-OK, refetch without `issue`. If that also fails, show "Skills unavailable" and send no `skillOverrides`.
- **D9. Quick create sends no context opt-outs.** The orphaned localStorage key `overdeck.commandDeck.newConversationContext` is left in place. Nothing reads it.
- **D10. The issue picker filters the dashboard store's issues client-side.** It matches a case-insensitive substring of the identifier or title and shows the first 20 results. No new endpoint is added.
- **D11. Keep one issue, with `plan.metadata.sizeJustification`.** The issue's acceptance criteria bind the dialog to the backend behavior: "row records each one" and "override survives resume". The backend slice has no operator-visible surface without the dialog.

## Repo rules that intersect this work (restated)

- **File-size ratchet:** `scripts/lint-file-size.sh` compares against the `origin/main` count or the last allowlist row. Caps: `conversation-runtime.ts` 1252 (zero headroom; WI-3 must land first), `conversations.ts` 1222, `CommandDeck/index.tsx` 1612, `CommandPalette.tsx` 1124. Never raise an allowlist row; extract instead.
- **No `execSync`** in dashboard-server-reachable code. `realpath` and `stat` come from `node:fs/promises`.
- **Fake timers** for any delay-based test (`vi.useFakeTimers()`). happy-dom's `AbortSignal.timeout` ignores fake timers, so use `AbortController` + `setTimeout` if a timeout is needed.
- **New HTTP route ⇒ a no-loss-matrix row**, or CI goes red (WI-7).
- **`lint:circular`:** new lib modules import `getAgentState` from `agent-state-read.js` if they need it. `launch.ts` reaches `conversations.js` only by dynamic import.
- **Test-skip gate:** never add `skipIf`/`.only`. Delete a component and its test in the same commit.
- **New source-reading tests fail lint** (`lint:source-introspection`): assert behavior, never grep source text in tests.
- **Style guide:** no pill badges, no decorative color, and the "running is not green" law.
- **Quality gates** before `pan done`: `npm run typecheck`, `npm run lint`, `npx vitest run <touched tests>`. Never run the full `npm test` on the host.
- **Browser verification** (test role / UAT) must use an isolated Playwright browser profile, never another agent's session.
