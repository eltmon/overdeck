## Glossary

- **Muse Ember** — Meta model `muse-ember-1.0`, released 2026-11-09. Context window 1,048,576 tokens; max output 524,288 tokens. Standard data terms only (no Contributor variant). Prices per million tokens for a request with up to 200,000 input tokens: $0.10 input, $0.004 cached input, $0.50 output. A request with more than 200,000 input tokens (cached tokens included) is billed entirely at $0.30 / $0.012 / $1.50, which is exactly 3x every component. Meta reasoning effort: `minimal`, `low`, `medium`, `high`, `xhigh`, `max`; API default `max`; `none` returns HTTP 400. Meta's docs do not support a bare `muse-ember` alias. Sources: https://dev.meta.ai/docs/models, https://dev.meta.ai/docs/pricing-rate-limits, https://dev.meta.ai/docs/reasoning, https://dev.meta.ai/models/muse-ember/, https://research.meta.ai/blog/muse-ember (read by the issue author 2026-11-10).
- **Existing Muse models** — `muse-wonder-1.0` ($4.00 / $0.20 / $20.00, effort `minimal`-`max`, default `max`), `muse-spark-1.3` ($1.25 / $0.15 / $4.25, effort up to `max`, default `high`), `muse-spark-1.3-contributor` ($0.10 / $0.002 / $0.20, default `high`, **no `max`**). None has a long-context premium. `muse-spark-1.2` exists but is older and is **not** added.
- **Muse harness** — runtime `muse` (Muse Code, binary `muse`), provider `meta`. `MUSE_BEHAVIOR` is in `packages/contracts/src/harness-behavior.ts` (line ~230); its `effortLevels` is `["low", "medium", "high", "xhigh"]`, so Overdeck never sends `max` to Muse Code.
- **Capability table** — `MODEL_CAPABILITIES` in `src/lib/model-capabilities.ts`. It spreads `AUDITED_MODEL_ADDITIONS` from `src/lib/model-capability-additions.ts` first (line 69), so the order of Muse rows in the additions file is the order of `getAvailableModelsApi().meta`.
- **`MuseModel` / `ModelId`** — TypeScript unions in `src/lib/settings.ts` line 56. Adding an ID forces a key in every `Record<ModelId, …>` map: `MODEL_CAPABILITIES` (via the additions row) and `MODEL_PROVIDERS` in `src/lib/model-fallback.ts` (line ~21). Typecheck fails until both have it.
- **Blended cost** — `costPer1MTokens`, the equal input/output average the pickers show: (0.10 + 0.50) / 2 = **0.3** for Ember.
- **Settings catalog API** — `getAvailableModelsApi()` in `src/lib/settings-model-catalog.ts`. Line 63 builds each row's name as `<displayName> (<context> context)`; line 67 pushes Meta rows with `harness: 'muse'` and the capability `effortLevels`. So `displayName: 'Muse Ember 1.0'` with `contextWindow: 1048576` yields `Muse Ember 1.0 (1M context)`.
- **No-loss catalog fixture** — `src/lib/__tests__/fixtures/pre-opencode-model-catalog.json`, compared by `src/lib/__tests__/settings-model-catalog.test.ts` after post-fixture additions are filtered out in `withoutOpus55()` (line 106). New models are added to that filter, never to the fixture.
- **Long-context tier** — a price multiplier that applies when one request's total input (`inputTokens + cacheReadTokens + cacheWriteTokens`) exceeds a threshold. `calculateCost()` in `src/lib/cost.ts` (line ~245) already implements per-model tiers for `claude-sonnet-4` (>200K) and `claude-haiku-5-5` (>100K, every component 5x).
- **Muse cost parser** — `summarizeMuseRecords()` in `src/lib/cost-parsers/muse-parser.ts` (line 47). It is the only path that prices Muse sessions: `runtimes/muse.ts`, `conversations/harness-metadata.ts` and `dashboard/server/services/muse-conversation-parser.ts` all call it. Today it sums every `model_completed` event's usage and prices the session total with a hand-written formula (line 77), never through `calculateCost()`.

## Decisions

1. **Ember is appended last in every Muse list** (`AUDITED_MODEL_ADDITIONS`, `PROVIDERS.meta.models`, `MODEL_PROVIDERS`, `MuseModel`, `modelCatalog.ts`, the `models` tuple in `muse-support.test.ts`). This keeps Wonder at `meta[0]` (asserted at `muse-support.test.ts:71`) and leaves every existing row's position unchanged. The order then also reads newest-last.
2. **The long-context tier is applied, through the existing mechanism.** `calculateCost()` already supports per-model input thresholds (Glossary, Long-context tier), so per the issue's rule the tier is added there: a `muse-ember-1.0` branch at `totalInputTokens > 200000` setting all three multipliers to 3, the same shape as the Haiku 5.5 branch. Because the Muse parser bypasses `calculateCost()` and prices the session aggregate (Verified fact 9), `summarizeMuseRecords()` is changed to price each `model_completed` event through `calculateCost()`. This is no new pricing engine: it reuses the existing function, and for the other three models the per-event sum equals today's aggregate formula.
3. **Threshold is strictly greater than 200,000**, measured on the request's `input_tokens` including cached tokens (the parser passes `inputTokens: input_tokens - cached` and `cacheReadTokens: cached`, whose sum `calculateCost()` uses). Meta: "up to 200K" is base, "above 200K" is long.
4. **Meta's pages win over Muse Code's catalog** (Verified fact 4). Ember gets `contextWindow: 1048576` and `maxOutputTokens: 524288`; Contributor keeps `max` excluded. The Muse Code figures (1,007,997 context, 128,000 output, `max` on Contributor) are recorded in `notes` and `docs/MODEL-CONTEXT-AUDIT.md`, not applied. Changing existing `contextWindow` values would also change their `(1M context)` labels and break the no-loss comparison.
5. **No `minimal`, no default-effort field, no harness cap change** (Verified fact 7). Ember's `notes` say: Meta lists `minimal` (not an Overdeck level), Meta's API default is `max`, the Muse harness row caps launches at `xhigh`, and Overdeck always passes an explicit level (default `high`). This follows the repo rule that reasoning effort defaults to `high` and is never defaulted to `xhigh` or `max`.
6. **Capability class `small`**, as the issue says. Ember is the cheapest Standard-terms Muse model.
7. **No minimum Muse Code version is recorded** because none gates Ember (Verified facts 2-3). Docs say the integration was verified with Muse Code 1.4.15 and that Muse Code fetches its model list from Meta at startup.
8. **No no-loss exception row** (Verified fact 6). Ember's ID is added to the `withoutOpus55()` meta filter, like `museWonderId`.
9. **Two stale user-facing strings are corrected in passing** because Ember makes them wrong: `harness-policy.ts:173` ("Select a Muse Spark model") and the `muse` harness description in `shared/ModelPicker/ModelPicker.tsx:24` ("Standard or Contributor models"). `providers.ts:91`'s description also names Ember.
10. **Changelog:** add an `Unreleased` v0.76.0 block in the `docs/RELEASING.md` "Update the public changelog" format (step 2 lists the parts the Flywheel later removes). Keep the existing `RELEASE STEP` comment above it.
11. **Release to npm is not the work agent's job.** After merge, green main CI and deploy, the Flywheel completes and dates the v0.76.0 block and runs `pan release stable --version 0.76.0 --skip-tests`.
12. **Size justification:** a mechanical model addition across the catalog, cost, launcher and dashboard layers plus docs (about 20 files with tests). Splitting into sibling issues would force several releases for one model launch the operator wants today.
