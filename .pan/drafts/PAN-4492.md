# PAN-4492: Composer messages to Claude Code on Herdr sometimes arrive without Enter

**Issue:** https://github.com/eltmon/overdeck/issues/4492
**Status:** planned (auto mode, 2026-10-03)
**Base commit at planning time:** `f7f982f4a6a` (main)

## Glossary

- **Herdr** — the default terminal backend (`docs/TERMINAL-BACKENDS.md`). Overdeck talks to it over a JSON socket through `HerdrApiClient.call(method, params)` (`src/lib/terminal-backends/herdr-api.ts`).
- **Detected agent** — a Herdr pane whose foreground process Herdr recognised as a coding agent. `agent.get` returns it with an `agent` field (`"claude"` for Claude Code) and an `agent_status` (`idle | working | blocked | done`).
- **`agent.prompt`** — Herdr's own "type this text and press Enter" call. Herdr writes the text and the Enter itself; Overdeck cannot interpose between them.
- **`pane.send_text` / `pane.send_keys` / `pane.read`** — Herdr's raw pane calls: write text, press named keys (`enter`, `ctrl+x`, …), and read the screen. `pane.read` with `source: 'visible'` returns the visible screen, including a full-screen TUI's alternate screen; `source: 'recent'` is empty on the alternate screen.
- **Bracketed paste** — wrapping text in `ESC[200~ … ESC[201~` so the TUI treats it as one paste instead of typed keys (a raw newline would submit). Claude Code collapses a large paste to a placeholder line `[Pasted text #N +M lines]` in its input box.
- **Composer** — Claude Code's input box. On screen it sits between two horizontal rule rows (`────…`), above a footer of status lines. Live capture from Herdr (`herdr --session overdeck pane read w21:p6E --source visible`, 2026-10-03):

  ```text
  ✻ Cogitated for 5m 31s · done 12:01 PM

  ──────────────────────────────────────────────────────────
  ❯ yes file it and fix it
  ──────────────────────────────────────────────────────────
    Opus 5.5 (claude-opus-5-5)  /home/eltmon/Projects/overdeck  main
    ctx 11%  2/1.0M  out 1.0k  cost $1.3849
    5h 6% (3h48m)  7d 2% (74h58m)
    ⏵⏵ bypass permissions on (shift+tab to cycle) · ← 1 agent
  ```

  (The `❯` is followed by U+00A0, a no-break space. This pane was idle with text sitting unsubmitted in its composer — the symptom this issue describes. The text's origin was not confirmed; `~/.overdeck/logs/dashboard.log` does not exist on this host, so the issue's 250-of-287 figure could not be re-derived.)
- **Payload presence** — `'present' | 'absent' | 'unproven'` (`ComposerPayloadPresence`, `src/lib/pane-composer.ts`). `present` = the delivered text (or a paste placeholder) is still in the composer; `absent` = the composer is found and does not hold it; `unproven` = the composer cannot be located, so nothing may be concluded.
- **Verify line** — `deliveryVerifyLine(content)` (`src/lib/pane-composer.ts`): the last line of the message with at least 3 non-blank characters. Matching uses its first 40 characters.
- **Blocking menu** — any numbered choice menu or permission prompt on screen. `paneHasBlockingChoiceMenu(paneText)` (`src/lib/pane-choice-menu.ts:270`) reports both (test: `tests/lib/pane-choice-menu.test.ts`, "reports permission menus the card path excludes"). An Enter while one is showing answers it (PAN-3212, PAN-4278).
- **Resubmit** — one extra submit keystroke sent after the first submit did not clear the composer.

## Problem

A composer message to a Claude Code conversation on a Herdr host sometimes stays in Claude Code's input box with no Enter. The dashboard reports it delivered.

The Herdr path is `deliverAgentMessage` (`src/lib/agents/delivery.ts`, search `herdrBackend.prompt({ paneId: herdrAgent.paneId }`) → `HerdrBackend.prompt` (`src/lib/terminal-backends/herdr.ts`, search `'agent.prompt',`). For a normal (non-steer) prompt that is one `agent.prompt` call: Herdr types the text and presses Enter in the same breath, and Overdeck reports `delivered` on any non-error return.

The tmux path (`sendKeys`, `src/lib/tmux.ts` — the issue says `sendKeysAsync:1005`; the protection actually lives in `export const sendKeys = (` at line 1028) protects the submit three ways:

1. It waits until the pasted text is visible in the pane before pressing Enter.
2. It waits a size-proportional settle (600 ms–3 s: `Math.max(600, Math.min(3000, lines * 15 + Math.floor(length / 1000) * 50))`) so Claude Code finishes ingesting a large paste.
3. After Enter, it checks the submitted text left the input area and presses Enter once more if not.

None of these run on Herdr. A large paste can still be processing when Herdr's Enter arrives, and the Enter is lost. The only post-send check, `watchForEatenConversationMessage` (`src/dashboard/server/services/conversation-eaten-message-watcher.ts`), redelivers only after a compaction boundary — never for a missing submit.

## Decisions (made here; auto mode)

- **D1 — Replace `agent.prompt` with our own paste → verify → submit → verify for Claude Code panes.** The issue allows "after `agent.prompt` (or in place of its built-in Enter)". In-place wins: it restores protection #1 and #2 (the pre-Enter wait, which is the actual cause), where an after-the-fact check can only add #3. The steer path already proves `pane.send_text` (bracketed) → settle → `pane.send_keys` in production (PAN-4292). No production caller passes `PromptOptions.wait` (only `delivery.ts` calls `herdrBackend.prompt`, without `wait`), and `delivery.ts` ignores the returned `state`.
- **D2 — Scope: Herdr detected agents with `agent === 'claude'`, plus every steer.** The composer parser targets Claude Code's layout. Other Herdr-detected harnesses keep `agent.prompt` unchanged. A prompt that carries `options.wait` also keeps `agent.prompt` (its waited semantics and tests stay as they are).
- **D3 — The steer path joins the same routine.** Steer is Claude-only and had the same missing guarantees; its resubmit uses the steer chord (`STEER_HERDR_KEYS`), never Enter, matching the tmux steer chaser. `steerHerdrPane` becomes unused and is deleted with its import.
- **D4 — Pane presence is the only decider.** No transcript check in the submit routine: a queued message on a busy agent never lands in the transcript until the turn ends, and `pan tell` to work agents has no transcript offset. A busy Claude Code clears its composer on Enter (the message queues), so `absent` correctly means submitted.
- **D5 — Never resubmit on `unproven`.** An extra Enter is sent only when the last read positively shows the payload still in the composer, the Herdr agent is not `blocked`, and no blocking menu is on screen. At most one resubmit per delivery.
- **D6 — Composer anchoring without a cursor.** Herdr's `pane.read` returns no cursor row, so `activeComposerRegion` (cursor-anchored) cannot be used. New rule: find rule rows (`/^\s*[─━═]{6,}/`, the existing `COMPOSER_TOP_BOUNDARY`). Two or more → the composer is the rows strictly between the last two. Exactly one → the rows above it (a paste taller than the screen pushes the top rule off). None → `null` (`unproven`). A false `present` from the one-rule fallback costs at most one Enter on an empty composer, which Claude Code ignores.
- **D7 — Matching normalisation.** Strip ANSI, U+00A0, all whitespace and box-drawing characters (`[─-╿]`) from both the composer region and the verify-line slice before `includes` — the same normalisation `conversation-forks.ts` uses (search `normalizePaneVerification`). This survives wrapped rows and the `❯` + no-break-space prefix. A `[Pasted text #<n>` placeholder in the region also counts as `present`.
- **D8 — Payload never visible before submit.** If the paste is never seen in the composer: when the agent is `blocked` or a blocking menu is on screen, do not press Enter and return `blocked` (mapped to `{ refused: true, reason: 'agent_blocked' }`, which the composer already reports as "Not delivered", retryable). Otherwise press Enter anyway after the settle (tmux does the same, "Sending Enter anyway to avoid orphaned input"). No re-paste (a re-paste can stack duplicates).
- **D9 — Logging, not new result fields.** The resubmit and the held-for-menu cases log one `console.warn` line each with prefix `[herdr-submit]` and the token `PAN-4492`; the dashboard captures `console` output in its log. `PromptResult` / `DeliveryResult` gain no fields (delivery.ts has 1 line of file-size headroom).
- **D10 — No import of `agents/permission-prompt.ts` or `agent-pane-io.ts`** from the new module: `agent-pane-io.ts` sits in baselined import cycle 32 (`scripts/circular-deps-baseline.txt`) and dynamically imports `launch.ts`, which reaches `herdr.ts`. The new module imports only `pane-composer.ts`, `pane-choice-menu.ts` (both import nothing) and `steer-keys.ts`, and takes the Herdr API structurally, like `steer-keys.ts` does.
- **D11 — Live reproduction is a script, committed.** `scripts/herdr-submit-soak.ts` drives the real delivery door against a scratch Claude Code conversation, so "reproduce first" (baseline, before the wiring lands) and AC-1 (20 consecutive 5 KB sends after) are the same repeatable command.

## Requirements

- **FR-1** — For a Herdr-detected Claude Code agent (`agent === 'claude'`) and a prompt without `wait`, `HerdrBackend.prompt` delivers by `pane.send_text` with bracketed paste, waits until the payload is visible in the composer and at least the size-proportional settle has passed, then presses Enter with `pane.send_keys`.
- **FR-2** — After the submit keystroke, the routine polls the composer for up to the submit-confirm window. `absent` ends the delivery with no extra keystroke.
- **FR-3** — If the composer still holds the payload at the end of the window, and the agent is not `blocked`, and no blocking menu is on screen, the routine sends the submit keystroke exactly once more and logs a `[herdr-submit] … resubmitting (PAN-4492)` line.
- **FR-4** — If a blocking menu or `blocked` status is present at the decision point, no extra keystroke is sent and a `[herdr-submit] … holding (PAN-4492)` line is logged.
- **FR-5** — A steer (`submit: 'steer'`) uses the same routine and resubmits with the steer chord (`ctrl+x ctrl+s`), never Enter.
- **FR-6** — `unproven` presence (composer not locatable) never triggers a resubmit.
- **FR-7** — Non-Claude Herdr agents and prompts with `wait` keep the existing `agent.prompt` behaviour byte-for-byte.
- **FR-8** — `scripts/herdr-submit-soak.ts` sends N multi-line messages of a given size to a named conversation through `deliverAgentMessage` and reports how many landed as transcript user records and how many needed a resubmit.
- **NFR-1** — `src/lib/terminal-backends/herdr.ts` stays at or under 1008 lines (its `scripts/file-size-allowlist.txt` cap); `src/lib/agents/delivery.ts` is not modified.
- **NFR-2** — No new import cycle (`npm run lint:circular` stays green).
- **NFR-3** — All new delay-based tests use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` or an injected `sleep`; no real-time waits.
- **NFR-4** — The submit routine never throws for a failed `pane.read` after the paste was sent; a read failure counts as `unproven`. A failed `pane.send_text` before anything was typed still throws (it is a delivery failure).
- **NFR-5** — Success-path latency is the settle (`pasteSettleMs`, 600 ms–3 s) plus a few 50 ms polls — under 2 s for an 80-line 5 KB message (settle 1450 ms), the same budget tmux spends.

### W1 — Cursor-free composer presence in `pane-composer.ts` (FR-6, D6, D7)

**File:** `src/lib/pane-composer.ts`. **Test:** `tests/lib/pane-composer.test.ts`.

Add two exports below `activeComposerPayloadPresence`:

```ts
const PASTE_PLACEHOLDER = /\[Pasted text #\d+/;

/**
 * PAN-4492: the composer of a screen read with no cursor row (Herdr `pane.read`).
 * Two or more rule rows: the rows strictly between the last two. One rule row:
 * the rows above it (a paste taller than the screen pushes the top rule off).
 * None: null.
 */
export function ruleBoundedComposerRegion(screen: string): string | null {
  const lines = screen.replace(PANE_ANSI_PATTERN, '').split('\n');
  const rules: number[] = [];
  lines.forEach((line, index) => { if (COMPOSER_TOP_BOUNDARY.test(line)) rules.push(index); });
  if (rules.length === 0) return null;
  const bottom = rules[rules.length - 1]!;
  const top = rules.length >= 2 ? rules[rules.length - 2]! : -1;
  return lines.slice(top + 1, bottom).join('\n');
}

const normalizeComposerText = (value: string): string => value.replace(/[─-╿\s ]/g, '');

/** PAN-4492: payload presence in a cursor-less screen's composer. */
export function screenComposerPayloadPresence(screen: string, content: string): ComposerPayloadPresence {
  const region = ruleBoundedComposerRegion(screen);
  if (region === null) return 'unproven';
  if (PASTE_PLACEHOLDER.test(region)) return 'present';
  const verify = normalizeComposerText(deliveryVerifyLine(content).slice(0, 40));
  if (verify.length < 3) return 'unproven';
  return normalizeComposerText(region).includes(verify) ? 'present' : 'absent';
}
```

Shape:

```ts
/** Structural, like steer-keys.ts: importing herdr-api here would close an import cycle through types.ts. */
export interface HerdrSubmitApi { call(method: string, params: Record<string, unknown>): Promise<unknown> }
export interface HerdrSubmitDeps { readonly sleep?: (ms: number) => Promise<void>; readonly now?: () => number }
export type HerdrSubmitOutcome = 'submitted' | 'resubmitted' | 'held' | 'unconfirmed' | 'blocked';

export const PASTE_VISIBLE_TIMEOUT_MS = 3_000;
export const SUBMIT_CONFIRM_MS = 2_000;
export const POLL_INTERVAL_MS = 50;
const SCREEN_LINES = 200;

/** The tmux formula (src/lib/tmux.ts sendKeys): 600 ms to 3 s, by line count and size. */
export function pasteSettleMs(text: string): number {
  return Math.max(600, Math.min(3000, text.split('\n').length * 15 + Math.floor(text.length / 1000) * 50));
}

export async function pasteAndSubmitHerdrPane(
  api: HerdrSubmitApi, paneId: string, text: string, mode: SubmitMode = 'enter', deps: HerdrSubmitDeps = {},
): Promise<HerdrSubmitOutcome>
```

Algorithm (each step is a small private helper; `read()` = `api.call('pane.read', { pane_id, source: 'visible', lines: SCREEN_LINES, strip_ansi: true })` → `text ?? ''`, and any throw → `null`; `blocked()` = `agent.get { target: paneId }` → `agent_status === 'blocked'`, a throw → `false`):

1. `await api.call('pane.send_text', { pane_id: paneId, text: `\x1b[200~${text}\x1b[201~` })` — a throw here propagates (nothing was typed).
2. `start = now()`. Poll `read()` every `POLL_INTERVAL_MS` until presence is `present` or `now() - start >= PASTE_VISIBLE_TIMEOUT_MS`. Then sleep the remainder of `pasteSettleMs(text)` measured from `start` (zero if already past).
3. If the paste was never `present`: if `blocked()` or `paneHasBlockingChoiceMenu(lastScreen)` → log `[herdr-submit] ${paneId}: paste not visible and the pane is blocked on a menu; not pressing ${label} (PAN-4492)` and return `'blocked'`. Otherwise continue (press anyway).
4. Press submit: `pane.send_keys { pane_id, keys: mode === 'steer' ? [...STEER_HERDR_KEYS] : ['enter'] }`.
5. Poll `read()` every `POLL_INTERVAL_MS` for up to `SUBMIT_CONFIRM_MS`. First `absent` → return `'submitted'`. Track the last presence.
6. At the deadline: last presence `unproven` → return `'unconfirmed'` (no keys). Last presence `present` → if `blocked()` or `paneHasBlockingChoiceMenu(lastScreen)` → log the holding line (`… still holds the message but a menu or permission prompt is showing; not resending ${label} (PAN-4492)`) and return `'held'`. Otherwise log `[herdr-submit] ${paneId}: message still in Claude Code's input box ${SUBMIT_CONFIRM_MS} ms after ${label}; resubmitting once (PAN-4492)`, press the submit keys once more, and return `'resubmitted'`.

`label` is `Enter` or `the steer chord`. `sleep` defaults to `(ms) => new Promise((r) => setTimeout(r, ms))`; `now` defaults to `Date.now`.
