## blocks-the-design: Cockpit pane rows still cannot open the composer

PRD W5 and the xBRIEF change only `paneStatus`. In `src/dashboard/frontend/src/components/Stage/cockpit/IssueTreeLane.tsx:43-59`, `paneToSession` sets `sessionId: pane.id` and never sets `hasJsonl`. `packages/contracts/src/backend-pane.ts:31-37` says a Herdr pane ID such as `w1:p1` is a backend handle, while `pane.agentId` is the agent key. Selecting the cockpit row passes it to `SessionPanel` (`IssueMissionControl.tsx:199-207`), which renders `ConversationPanel` only when `hasJsonl` is true (`SessionPanel.tsx:417-433`) and passes `session.sessionId` as the agent ID (`:425`). That ID would route a send to `/api/agents/w1%3Ap1/message` (`src/dashboard/frontend/src/lib/composerSend.ts:120-122`) instead of the work agent. A W5 test of only status and presence misses both failures. Make cockpit rows carry the canonical agent ID and conversation availability, then test selection of a Herdr pane whose `id` differs from `agentId` through the rendered composer and its send target.

## blocks-the-design: A live pane can still receive an endedAt

FR-6 says any non-exited pane has no `endedAt`, but W3/W4 only expand `tmuxAlive`. Both routes still set `sessionEnded` when `rtState?.state === 'suspended'` before checking pane liveness (`src/dashboard/server/routes/projects.ts:268-276`; `src/dashboard/server/routes/command-deck.ts:348-356`). A live `done` or `working` pane with stale suspended runtime state will therefore have `presence: idle/active` and a populated `endedAt`, contradicting the pane-first authority in D1. `SessionPanel.tsx:281-294` carries that timestamp into a conversation it marks alive. Gate the suspended branch on the absence of a live pane, or derive `sessionEnded` from the final presence when a pane exists. Add a test with a live pane and suspended runtime state in both routes.

## blocks-the-design: Activity specialists can select an exited pane over a live one

W4 builds `panesByAgent` for work rows, but leaves `firstPaneWithRole` as `issuePanes.find((pane) => pane.role === role)` in `src/dashboard/server/routes/command-deck.ts:424-428`. `getBackendPanesForIssue` includes exited panes (`src/dashboard/server/services/backend-inventory.ts:404-410`), and the cache keeps pane entries by ID (`:264-277`, `:307-310`). When an exited review or test pane precedes a restarted live pane of the same role, `nodeStatusFor` receives the exited pane and reports `ended`; the W4 single-pane tests still pass. The repository already has an exited-versus-live preference in `indexPanesByAgentKey` (`packages/contracts/src/backend-pane.ts:40-50`). Apply that preference when choosing each role's pane and test an exited pane followed by a live `done` pane.
