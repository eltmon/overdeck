# PAN-4244 — Make the reload-health-timeout zombie fixture deterministic

**Issue:** [PAN-4244](https://github.com/eltmon/overdeck/issues/4244)
**Type:** test-only fix (no production code changes)
**Verified against:** `feature/pan-4244` at `93468d610c1` on 2026-09-27

## Glossary

- **Zombie process** — a process that has exited but whose parent has not yet
  called `wait()` on it. `kill(pid, 0)` still succeeds for it, and `ps -o stat=`
  reports a state starting with `Z`.
- **Zombie fixture** — the `'zombie'` branch of `spawnedServerPid()` in
  `src/cli/commands/__tests__/reload-health-timeout.integration.test.ts`. It
  must return the pid of a real zombie so the reload's liveness probe can be
  tested against "kill(0) says alive, ps says dead".
- **Outer shell / inner child** — the fixture spawns an outer `sh`, which
  starts a background inner child and then `exec`s into `sleep`. `sleep` never
  reaps children, so once the outer shell has exec'd, an exited inner child
  stays a zombie.
- **Reap race** — if the inner child exits *before* the outer shell has
  exec'd, `dash` (Ubuntu's `/bin/sh`) can reap it. The pid then vanishes
  entirely instead of becoming a zombie.
- **Deadline** — a wall-clock limit (`Date.now()`-based) on a polling loop,
  after which the loop throws a descriptive error instead of spinning.
- **CPU admission** — `tests/vitest-cpu-admission.ts` (Vitest `globalSetup`)
  makes every local `npx vitest run` wait for a machine-wide CPU lease. It is
  skipped when `CI` is set, `OVERDECK_GATE_ADMITTED=1`, or
  `OVERDECK_GATE_ADMISSION=0` (line 28).

## Problem

`src/cli/commands/__tests__/reload-health-timeout.integration.test.ts` fails
intermittently in CI with `Error: Test timed out in 5000ms.` The failing case is
always `rolls back to the previous deployment when the new server is zombie (ps
broken: false)` (the `it.each` at lines 352–356). It reddened main at
`b132ed1e6` and PRs #4237, #4231, #4227.

## Root cause (verified)

The issue guessed two causes. Only the first is real.

1. **The zombie fixture can spin forever (confirmed).** Lines 252–267:

   ```ts
   const child = spawn('sh', ['-c', 'sh -c "exit 1" & echo $!; exec sleep 60'], {
     stdio: ['ignore', 'pipe', 'ignore'],
   });
   children.push(child);
   const [chunk] = await once(child.stdout!, 'data') as [Buffer];
   const pid = Number(chunk.toString().trim());
   for (;;) {
     const state = await new Promise<string>((resolve) => {
       execFile('ps', ['-p', String(pid), '-o', 'stat='], (_error, stdout) => resolve(String(stdout).trim()));
     });
     if (state.startsWith('Z')) return pid;
     await new Promise<void>((resolve) => setTimeout(resolve, 20));
   }
   ```

   The inner `sh -c "exit 1"` exits immediately. When it exits before the outer
   `dash` reaches `exec sleep 60`, `dash` reaps it and the pid disappears. `ps`
   then prints nothing forever, the loop never sees `Z`, and the test burns its
   whole 5000 ms budget. The loop has no deadline.

   Measured on this host (24 cores) with a standalone probe of the exact
   fixture, 300 attempts each: idle → 299 zombie / 1 vanished; with 24 busy
   `sh` loops → 282 zombie / 18 vanished (6%). CI runners are loaded, so the
   flake rate matches the observed failures.

2. **The reload health-wait path is NOT the cause.** `run()` (lines 330–348)
   already installs `vi.useFakeTimers({ toFake: ['Date', 'setTimeout',
   'clearTimeout'] })` (line 334) and steps the clock in 100 ms increments until
   the reload settles. The liveness decision lives in
   `src/lib/platform-lifecycle.ts` lines 647–656 (`spawnedPidProvenDead`, line
   306) and treats a vanished pid as dead too, so even the vanished case would
   pass *if the fixture returned*. No production code needs to change.

## Decisions

- **DEC-1: Fix the fixture only.** No edits to `src/cli/commands/reload.ts` or
  `src/lib/platform-lifecycle.ts`. The health-wait path already runs on fake
  timers (line 334).
- **DEC-2: Build the zombie by killing after exec.** The inner child is a
  long-lived `sleep 60`, so the outer shell cannot reap it early. The test waits
  until the outer pid has exec'd into `sleep`, then sends `SIGKILL` to the inner
  pid. Its parent is now `sleep`, which never reaps, so the inner pid becomes a
  zombie every time. Verified: 600/600 zombies (300 idle, 300 under 24 busy
  loops), worst-case fixture time 441 ms under load.
- **DEC-3: Match the exec by basename.** Check `ps -p <outerPid> -o comm=` with
  `.endsWith('sleep')`, not `=== 'sleep'`, because macOS `comm` can print a
  full path.
- **DEC-4: One 2000 ms wall-clock deadline covers both polls** (exec wait and
  `Z` wait). That is about 4.5× the measured worst case. The fixture runs before
  `run()` installs fake timers, so `Date.now()` is real there. Do not move the
  fixture call after `run()`.
- **DEC-5: No real `setTimeout` in the fixture.** Pace the polls with
  `setImmediate` (each `ps` call already takes a few ms). This removes the
  existing 20 ms `setTimeout` at line 265.
- **DEC-6: On deadline, throw a descriptive error** naming the pid, the phase
  that stalled (`exec` or `zombie`), and the last `ps` output. A future flake
  then reads as a clear fixture failure, not "timed out in 5000ms".
- **DEC-7: Keep the default 5000 ms `it` timeout.** See implementation
  checkpoint CP-1 for the fallback.
- **DEC-8: Soak with 8 busy `sh` loops, not `stress-ng`.** `stress-ng` is not
  installed on the host. Eight loops match the issue's `stress-ng --cpu 8`
  example without starving the other agents on this 24-core host. The soak loop sets `OVERDECK_GATE_ADMISSION=0`,
  because otherwise every `npx vitest run` waits for a CPU lease that the
  synthetic load prevents (it can wait up to 30 minutes and looks like a hang).

## Requirements

- **FR-1** The zombie fixture returns a pid whose `ps -o stat=` starts with `Z`
  on every run, independent of scheduling order.
- **FR-2** The zombie fixture fails within 2000 ms with an error naming the pid,
  the stalled phase, and the last observed `ps` output, instead of looping
  forever.
- **FR-3** `docs/TESTING.md` tells authors how to write fixtures that wait on
  real process state.
- **NFR-1** The fixture adds no real `setTimeout` delay (fake-timers rule).
- **NFR-2** The six existing tests in the file keep their names and
  assertions and still pass.
- **NFR-3** The file passes 50 consecutive runs under an 8-core busy-loop load.

## Intersecting repo rules (restated)

- **Fake timers for delay-based tests:** retry/backoff/delay code in tests uses
  `vi.useFakeTimers()`; never add real `setTimeout` waits. Real-process waits
  are bounded by deadlines, paced by `setImmediate`.
- **Never run the full `npm test` on the host.** Run only the touched file.
- **`npm run typecheck` excludes `*.test.ts`.** It proves nothing about the test
  file; `npx vitest run <file>` and `npm run lint` are the checks.
- **Never raise `maxForks`/timeouts to mask a bug.** The fix is the fixture, not
  a bigger timeout (see CP-1 for the one allowed fallback).

## Work items

### WI-1 — Deterministic zombie fixture with a deadline (FR-1, FR-2, NFR-1, NFR-2, NFR-3)

**File:** `src/cli/commands/__tests__/reload-health-timeout.integration.test.ts`
**Function:** `spawnedServerPid` — replace only the zombie branch (lines
252–266). The `'exited'` and `'alive'` branches (lines 240–251) stay as they
are.

**Steps:**

1. Add a small helper above `spawnedServerPid` that runs `ps` for one field:

   ```ts
   /** One `ps` field for a pid; empty when the pid does not exist. */
   function psField(pid: number, field: 'comm' | 'stat'): Promise<string> {
     return new Promise((resolve) => {
       execFile('ps', ['-p', String(pid), '-o', `${field}=`], (_error, stdout) => resolve(String(stdout).trim()));
     });
   }
   ```

2. Replace the zombie branch.

   Before (lines 252–266): see "Root cause" item 1.

   After:

   ```ts
   // A zombie: the outer shell starts a long-lived child, then execs into
   // `sleep`, which never reaps. Killing the child only after that exec makes
   // it a zombie every time — a child that exits before the exec can be reaped
   // by the shell and vanish instead (PAN-4244). kill(0) still succeeds on the
   // zombie, so only ps's `Z` state shows the server is dead.
   const child = spawn('sh', ['-c', 'sleep 60 & echo $!; exec sleep 60'], {
     stdio: ['ignore', 'pipe', 'ignore'],
   });
   children.push(child);
   const [chunk] = await once(child.stdout!, 'data') as [Buffer];
   const pid = Number(chunk.toString().trim());
   const deadline = Date.now() + 2000;
   let phase: 'exec' | 'zombie' = 'exec';
   let last = '';
   while (Date.now() < deadline) {
     if (phase === 'exec') {
       last = await psField(child.pid!, 'comm');
       if (last.endsWith('sleep')) {
         process.kill(pid, 'SIGKILL');
         phase = 'zombie';
       }
     } else {
       last = await psField(pid, 'stat');
       if (last.startsWith('Z')) return pid;
     }
     await new Promise<void>((resolve) => setImmediate(resolve));
   }
   throw new Error(
     `zombie fixture: pid ${pid} (outer ${child.pid}) stalled in phase '${phase}' after 2000ms; last ps output: '${last}'`,
   );
   ```

   Notes for the implementer:
   - `pid` is the inner child; `child.pid` is the outer shell, which becomes
     `sleep` after exec. The `afterEach` SIGKILL of `child` (lines 138–143)
     kills the outer `sleep`; the zombie is then reparented to init and reaped.
     No extra cleanup is needed.
   - Keep `setTimeout` out of this function entirely.
   - Do not change `setUpTimedOutReload`, `run()`, or any `it`/`it.each` body.

3. **Implementation checkpoint CP-1 (timeout).** Run the soak in WI-1 step 4.
   If every run passes, keep the default 5000 ms `it` timeout. If the zombie
   case fails with Vitest's `Test timed out in 5000ms` (not the fixture's own
   error), add a third argument `10_000` to the `it.each(...)(name, fn)` call at
   lines 352–356 only, with a one-line comment citing PAN-4244, and re-run the
   soak. If the fixture's own deadline error fires, stop and report it via
   `pan tell` — the DEC-2 construction has failed and needs re-planning; do not
   raise the deadline.

4. **Soak procedure** (from the workspace root):

   ```bash
   # Synthetic load on 8 cores (the issue's `stress-ng --cpu 8` example) for up
   # to 15 minutes. Kill the loops by pid: `pkill -f` on the loop text would
   # also match and kill the shell running this script.
   pids=''
   for i in $(seq 8); do timeout 900 sh -c 'while :; do :; done' & pids="$pids $!"; done
   pass=0
   for i in $(seq 50); do
     OVERDECK_GATE_ADMISSION=0 npx vitest run src/cli/commands/__tests__/reload-health-timeout.integration.test.ts \
       >/tmp/pan-4244-soak.log 2>&1 && pass=$((pass+1)) || { echo "run $i FAILED"; tail -40 /tmp/pan-4244-soak.log; break; }
   done
   echo "passed $pass/50"
   kill $pids 2>/dev/null
   ```

   Expected: `passed 50/50`. Put the result line in the commit message body.

**Tests that prove it:** the six existing tests in the file, especially

### WI-2 — Document real-process fixtures in docs/TESTING.md (FR-3)

**File:** `docs/TESTING.md`. Add a new `### Real-process fixtures` subsection
under `## Writing Tests`, directly after the `### Mocking` subsection (which
ends with the paragraph "…reduce the repository's two-worker CI concurrency to
hide a leak.", line 104) and before `## Dashboard UI Testing`.

Content (adapt wording, keep every point):

```markdown
### Real-process fixtures

Some tests need a real pid in a specific state (exited, alive, zombie). Build
those states so they cannot race the scheduler, and bound every wait:

- Construct the state deterministically. For a zombie, start a long-lived
  child, wait until its parent has `exec`'d into a process that never reaps
  (such as `sleep`), and only then kill the child. A child that exits before
  the exec can be reaped by the shell and vanish (PAN-4244).
- Poll real process state against a wall-clock deadline and throw an error
  that names the pid, the phase, and the last observed state. Never write an
  unbounded `for (;;)` poll: it turns into an opaque `Test timed out in 5000ms`.
- Pace the poll with `setImmediate`, not `setTimeout`, and run the fixture
  before `vi.useFakeTimers()` so `Date.now()` is real.
```
