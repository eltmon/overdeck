## blocks-the-design: Composer state survives a fresh run

The proposed claim clears message queries and calls `clearOptimistic` only for a known prior owner. In [composerStore.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5665/src/dashboard/frontend/src/lib/composerStore.ts), lines 589–594, that method clears only `optimistic`; command results and failed sends remain keyed by `conv-flywheel`. [ConversationPanel.tsx](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5665/src/dashboard/frontend/src/components/chat/ConversationPanel.tsx), lines 626–628, appends old command results to the new run's visible message list. On a first cache claim, an old optimistic echo can remain visible too. More seriously, [useComposerDeliveryState.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5665/src/dashboard/frontend/src/components/chat/useComposerDeliveryState.ts), lines 121–135, automatically retries `heldOffline` entries by name when the connection is live; [composerStore.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5665/src/dashboard/frontend/src/lib/composerStore.ts), lines 880–892, sends them to that name. Thus a prompt held for run A can be delivered to run B. The planned test mock reads only the messages query, so it would miss both leaks.

Smallest resolution: make the composer state that renders or auto-sends run-aware, or remove the old run's command results and auto-held sends before mounting B. Define how an unknown first owner handles echoes, and add a run-switch test with these store entries. Manual failed-send retries can remain as an explicit operator action if that is the intended boundary.

## blocks-the-design: Run identity can repeat

The PRD says `id:createdAt` changes on every new row. [conversations.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5665/src/lib/overdeck/conversations.ts), lines 358–360 and 482–491, exposes SQLite `rowid` as `id` and converts `created_at` to an ISO timestamp. Its insert uses `now = toMillis()` at lines 738–740 and 762–780; `toMillis()` has millisecond precision at lines 450–459. [conversation-replace.ts](/home/eltmon/Projects/overdeck/workspaces/feature-pan-5665/src/lib/overdeck/conversation-replace.ts), lines 26–27, deletes the old unlinked row. Repeating the repository's table shape in an in-memory SQLite check, then inserting, deleting and inserting with the same millisecond produced `(rowid, created_at) = (1, 42)` both times. A rapid replacement can therefore reuse the complete identity, skip the cache claim, and show A's transcript as B's. The acceptance tests cover only differing `createdAt` values.

Smallest resolution: use a value guaranteed unique per row, such as the existing `conversations.id` UUID, in the pane response; alternatively guarantee a monotonic creation stamp at insert. Update the identity test to cover rowid reuse with a same-millisecond replacement. This requires revisiting the PRD's no-server-change boundary.
