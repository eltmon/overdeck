## 1. Summary

Today a `project:<key>` explorer root is read-only: the code pane shows "Read-only: the main checkout is never edited directly", and the tree hides every write action. This issue makes that root editable without ever writing the primary checkout:

1. The first save or file action in a `project` root creates (or reuses) an **edit workspace**, a scratch git worktree on branch `scratch/edit-<slug>`. The pending edit lands there, and every pane on that project root switches to the new root.
2. A banner on the edit workspace offers **Create PR** and **Discard**.
3. **Create PR** commits everything and either opens a **direct PR** (with a one-click **Merge** when GitHub reports no conflicts) or **sends it through the pipeline**: it creates a GitHub issue, pushes the branch as `feature/<issue>`, opens the PR, and hands it to Overdeck's existing PR-adoption door (PAN-4605), which builds the pipeline workspace and starts review.
4. **Discard** removes the edit workspace (worktree, local branch, registry row) and optionally closes its PR.
5. A user page, `features/file-explorer.mdx`, documents the whole explorer.

## 2. Glossary

Terms from the parent glossary keep their meaning: **explorer root**, **root id**, **explorer pane**, **code pane**, **edit workspace**, **direct PR**, **pipeline PR**, **disk signature**. New or sharpened here:

- **Edit branch** — a branch matching `^scratch/edit-[A-Za-z0-9-]+$`. Only a workspace-registry row whose `branchName` matches this is an edit workspace. Other `scratch/*` rows (made by `pan workspace new`) are never touched by any route in this issue.
- **Edit slug** — `MMDD-HHMM` in server local time, plus `-2`, `-3` … up to `-20` on a collision. Name `edit-<slug>`, branch `scratch/edit-<slug>`, directory `<project>/<workspaces_dir>/scratch-edit-<slug>/`.
- **Root switch** — the client step that moves everything bound to one root id to another: drafts are re-keyed first, then explorer and code panes are retargeted (`updatePane`), then the expanded-folder set is copied.
- **Pending save** — a draft key marked by a root switch. When the code pane for that key mounts on the new root, it saves the draft once.
- **PR support** — the project can open GitHub PRs from the explorer: `inferProjectForge(config) === 'github'` (`src/lib/project-repos.ts`, search `export function inferProjectForge`), which requires `github_repo` and no `gitlab_repo`.
- **Pipeline support** — PR support, plus `tryResolveProjectTrackerType(config) === 'github'` (`src/lib/project-tracker-type.ts`) and a non-empty `getIssuePrefix(config)` (`src/lib/projects.ts`).
- **Merge verdict** — `{ canMerge, reason }` computed from `gh pr view` fields by the D-9 table (§3 D-F7).
- **Adoption** — `adoptPrAndStartReview(pr, { source })` (`src/lib/cloister/pr-adoption-review.ts`, search `export function adoptPrAndStartReview`): it fetches a `feature/<issue>` PR branch, creates the pipeline workspace through the paved workspace-creation path, checks the head, and starts review. Coalesced per issue; never throws.
- **Operator identity** — the `user.name` and `user.email` from `git config --global`. Commits made by the explorer use it (parent D-10).

## 3. Decisions (deviations and refinements of the parent)

Each is also in `plan.autoDecisions[]`.

- **D-F1 PR, merge, discard and status are HTTP routes; begin-edit stays RPC.** Parent D-14 says "everything else is WebSocket RPC", but parent WI-15 specifies HTTP routes under `/api/explorer/edit-workspaces/:workspaceId`. We follow WI-15: these calls are long (git hooks, push, GitHub) and are one-shot request/response. The only RPC is `pan.explorerBeginEdit`, whose contract and no-loss row already exist (PAN-5185 D-A1/D-A2). No new RPC contract is added.
- **D-F2 The pipeline path uses PR adoption, not a hand-moved worktree.** Parent WI-16 renames the branch, runs `git worktree move`, rewrites the registry row and calls `requestReviewGuarded`. A moved scratch worktree never had pipeline setup (no dependency install, no `.overdeck/`), and its registry row would be hand-built. PAN-4605's adoption door already turns a pushed `feature/<issue>` PR into a properly created pipeline workspace and starts review. So the pipeline path: commit → create the GitHub issue → push `HEAD:refs/heads/feature/<issue-lower>` → `ensurePRExists` → remove the edit workspace (everything is committed and pushed, so nothing is lost) → `adoptPrAndStartReview` in the background. This drops parent WI-16 steps 2–5 and their checkpoints. **The webhook adopts too.** When GitHub delivers `pull_request.opened` for a `feature/*` head, `src/lib/webhook-handlers.ts` (search `PAN-4605: a PR opened outside a pipeline workspace`) starts review, gets `no-workspace`, and calls `adoptPrAndStartReview` itself. Both callers are safe together: `adoptPrAndStartReview` coalesces concurrent calls per issue (its `inFlight` map). The one unsafe case is a second adoption after the first finished, because the workspace then already exists. So the explorer calls adoption only when `getWorkspacePathForIssue(config.path, issueId).workspacePath` does not exist yet; when it exists, the webhook already adopted it and the explorer logs `[explorer-edit] <ID> already adopted` and skips the call.
- **D-F3 Pipeline needs a GitHub-tracked project.** `src/` has no dashboard route that creates tracker issues, and per-project tracker construction (`src/lib/pipeline-membership-gather.ts`) uses `loadConfigSync`, which NFR-1 forbids in server code. The explorer's PR flow is GitHub-only anyway (D-9 reads `gh pr view`). So the issue is created with `gh issue create --repo <github_repo>`, and the id is `<ISSUE_PREFIX>-<number>` (the same mapping as `issueIdFromTrackerIssue`, `src/lib/tracker/issue-id.ts`). When the project lacks pipeline support, **Send through pipeline** is disabled with its reason in words. Linear, Jira, Rally and GitLab trackers are out of scope.
- **D-F4 Direct PR creation uses argv `gh`, not the forge adapter.** `githubForgeAdapter.createReviewArtifact` builds a shell string with `--title "${input.title}"` (`src/lib/forge.ts`, search `gh pr create --head ${input.sourceBranch}`). An operator-typed title with `"` or `$(` breaks or injects. The explorer runs `gh pr create --repo <r> --head <b> --base <base> --title <t> --body <body> [--draft]` as an argument vector through `runGh` (`src/lib/github-quota/run-gh.ts`, caller `'other'`). Merging still uses `getForgeAdapter('github').mergeReviewArtifact` (its target and SHA are validated, and it covers the GitHub App path).
- **D-F5 Pushes do not use `gitPush`.** `gitPush` (`src/lib/git/operations.ts`, search `export async function gitPush`) first runs `git fetch <remote> <branch>`, which fails for a branch the remote does not have yet, and it never sets upstream. The explorer pushes with the explorer git runner: `git push --set-upstream origin HEAD:refs/heads/<branch>` (direct) or `git push origin HEAD:refs/heads/feature/<issue-lower>` (pipeline), with a 180 s timeout.
- **D-F6 Repository hooks run; failures are shown.** Worktrees share the primary checkout's `core.hooksPath` (`git config --show-origin core.hooksPath` → `.git/config`, checked 2026-11-13). In this repo commit-msg runs commitlint: `Fix typo in README` fails (`subject-empty`, `type-empty`), `chore: edit README.md` passes (checked 2026-11-13 with `npx --no -- commitlint`, which resolves the binary from the parent `node_modules`). The explorer never passes `--no-verify`. A refused commit or push returns its stderr (last 4,000 characters) and the dialog shows it, so the operator can fix the title. The default title is a conventional-commit subject: `chore: edit <file>` or `chore: edit <file> and <n> more files` (D-F12).
- **D-F7 Merge verdict table** (parent D-9, made exact). `canMerge` is true only when `state === 'OPEN'`, `isDraft === false`, `mergeable === 'MERGEABLE'` and `mergeStateStatus` is `CLEAN`, `UNSTABLE` or `HAS_HOOKS`. Otherwise `reason` is the first matching line:

  | Condition | `reason` |
  |---|---|
  | `state === 'MERGED'` | `Already merged` |
  | `state === 'CLOSED'` | `The PR is closed` |
  | `isDraft` or `mergeStateStatus === 'DRAFT'` | `The PR is a draft` |
  | `mergeable === 'CONFLICTING'` or `mergeStateStatus === 'DIRTY'` | `Conflicts with the base branch` |
  | `mergeStateStatus === 'BLOCKED'` | `Required checks or reviews are not met` |
  | `mergeStateStatus === 'BEHIND'` | `The branch is out of date with the base branch` |
  | `mergeable === 'UNKNOWN'` or `mergeStateStatus === 'UNKNOWN'` | `GitHub is still checking whether this PR can merge` |
  | any other `mergeStateStatus` value `X` | `GitHub reports X` |

  When the first read is `UNKNOWN`, the server waits 2,000 ms and reads once more (fake timers in tests).
- **D-F8 Merge refuses unpushed work instead of keeping the workspace.** Parent FR-14 keeps a dirty workspace after a merge. We refuse the merge instead (409 `UNPUSHED_CHANGES`, "Commit and push your changes first.") when `git status --porcelain` is non-empty or local `HEAD` differs from the PR's `headRefOid`. So a merge never lands without the operator's latest edits, and a successful merge always removes the workspace. **Push changes** in the PR row (POST `/pr` again while the PR is open) commits and pushes follow-up edits.
- **D-F9 Removal order and the watcher.** Removal runs `git worktree remove [--force] -- <path>`, then `git branch -D <edit branch>`, then (best effort) `git push origin --delete <edit branch>`, then `deleteWorkspace(id)` (`src/lib/workspaces/writer.ts`, search `export async function deleteWorkspace`). A probe on 2026-11-13 (parcel 2.6.0, inotify) showed that deleting a watched root yields `delete` events and no subscribe error, so removing a root that a client still watches does not crash the watcher child. The client still switches its panes away right after a merge or discard.
- **D-F10 Remote edit branches are cleaned up.** After a direct merge, and after a discard whose PR is no longer open (closed by the checkbox, merged, or never opened), the server runs `git push origin --delete <edit branch>`. A failure (branch never pushed, no network) is logged and ignored. Discard with "Also close PR" unchecked keeps the remote branch, because deleting it would close the PR.
- **D-F11 Every project-root gate, named.** Before this issue, project roots are read-only through these gates. Each changes as stated:
  1. Server `readFile` returns `writable: false` for project roots — **unchanged** (it is true of the disk).
  2. Server `resolveInsideRoot(..., { forWrite: true })` throws `EDIT_WORKSPACE_REQUIRED` — **unchanged**; the client never sends a project-root write.
  3. `CodePane.tsx` `const writable = load.status === 'ready' && load.result.kind === 'text' && load.result.writable` — becomes **editable** for project roots too (WI-F9).
  4. `useCodePaneSave.ts` autosave `save` — for project roots it calls `ensureEditRoot` instead of the save queue (WI-F9).
  5. `useExplorerActions.ts` `if (isProject) throw new Error(READ_ONLY_MESSAGE)` in `runWrite` — becomes a switch-then-replay (WI-F10).
  6. `useExplorerActions.ts` `runHistory` `if (isProject) return` — **unchanged** (a project root has no undo history; after a switch the edit root has it).
  7. `ExplorerPane.tsx` `const writable = rootKind !== 'project' && !changedOnly` — becomes `const writable = !changedOnly` (WI-F10).
  8. `ExplorerPane.tsx` drop toast "The main checkout is read-only, so files can't be added here." — removed; a drop on a project root uploads through `runWrite` (WI-F10).
  9. `ExplorerContextMenu.tsx` git actions `rootKind !== 'project'` — **unchanged**: Stage, Unstage and Discard changes stay hidden on project roots (the primary checkout's index is never written).
  10. `useTreeActionKeys.ts` `isProjectRoot` — **unchanged** (it only gates undo/redo keys).
  11. Upload route 409 `EDIT_WORKSPACE_REQUIRED` — **unchanged**; uploads reach it only with an edit root.
- **D-F12 Default PR title** (client, `edit/default-pr-title.ts`): from the explorer's git status, take the changed paths (`entries`, then `committed`, deduplicated, in that order). Zero paths → `chore: edit files`. One → `chore: edit <basename>`. More → `chore: edit <basename of first> and <n-1> more files`. Truncate to 100 characters.
- **D-F13 Reuse rule (parent D-11), exact.** `beginEdit(projectKey, forceNew=false)` takes the project's `scratch` rows (`listWorkspaces({ projectId, kind: 'scratch' })`) with an edit branch, newest `createdAt` first. A row is a candidate only if `resolveExplorerRoot('workspace:' + id)` succeeds (D-A4: directory exists, inside the workspaces dir, not the primary checkout). With PR support it reads the branch's PR (`gh pr list --head <branch> --state all -L 1`); the first candidate with no PR or an `OPEN` PR is reused. A failed `gh` lookup counts as "no PR" (the edits are safe either way: the branch is local). Without PR support the newest candidate is reused. No candidate, or `forceNew`, creates one.
- **D-F14 Single flight.** The server serializes `beginEdit` per project key (a promise chain in a module `Map`), so two concurrent calls never race the minute-granular slug. The client keeps one in-flight `beginEdit` promise per project key, so two panes autosaving together share one call.
- **D-F15 Untracked files are not carried over.** An edit workspace is cut from `origin/<default branch>`. A file that exists only in the primary checkout (untracked, ignored, or a local-only commit) does not exist there. After the switch the code pane shows the PAN-5187 "This file no longer exists." message and keeps the draft in memory; the pending save answers `NOT_FOUND` and shows a toast. Carrying such files over is a non-goal.
- **D-F16 Code panes show a one-line note; only the explorer pane shows the full banner.** Parent WI-14 puts the banner (with Create PR and Discard) on every explorer and code pane. Buttons in every code tab are clutter, so code panes on an edit root show the note line only: "Editing in edit workspace `<name>` (branch `<branch>`). The main checkout is not changed." The explorer pane shows the note plus **Create PR**, **Discard** and **New edit workspace**.
- **D-F17 Live GitHub actions are not exercised by automated roles.** Opening, merging and closing real PRs, and creating real issues, are outward-facing and (for merge) land commits on `main`. The review and test roles verify them through service tests with injected fakes and a real-git test against a local bare remote. Browser UAT covers creating an edit workspace and the banner, disabled-button reasons, and Discard. A real PR round trip is an operator check, listed in the PR description.
- **D-F18 Shared types live in contracts as plain interfaces.** `EditWorkspaceStatus` and friends are added to `packages/contracts/src/explorer.ts` as TypeScript interfaces (no Schema), next to the existing explorer contracts, so server and client agree on one shape.
- **D-F19 Route errors are typed.** `services/explorer/edit-workspace-errors.ts` exports `class EditWorkspaceError extends Error { code: string; status: number }`. The route module maps it to `{ error, code }` with its status. Anything else goes through the existing `explorerErrorResponse` (`services/explorer/http-errors.ts`).

## 4. Requirements

### Functional

- **FR-1** [parent FR-12] On a `project:<key>` root, the code pane is editable. Typing creates nothing. The first save (autosave 1,000 ms after the last keystroke, blur, or `Ctrl/Cmd+S`) or the first file action (create, rename, duplicate, delete, move, upload) calls `pan.explorerBeginEdit({ projectKey, forceNew: false })`.
- **FR-2** [parent FR-12, D-11] `explorerBeginEdit` reuses or creates an edit workspace by D-F13 and returns `{ rootId: 'workspace:<id>', workspaceId, name, branch, path, created }`. A project whose primary checkout is not the top level of a git repository fails with `NOT_A_GIT_REPO`. An unknown project fails with `ROOT_NOT_FOUND`.
- **FR-3** [parent FR-12] While `beginEdit` runs, the explorer pane and the code pane show "Creating edit workspace…". Afterwards, every loaded explorer and code pane on that project root switches to the edit root (root switch), the triggering edit is saved there, and the main checkout stays unchanged.
- **FR-4** [parent FR-12, FR-8] If the file in the new worktree differs from the content the edit started from, the PAN-5187 external-change banner appears (Compare, Reload from disk, Keep my edits, Overwrite) instead of a silent write.
- **FR-5** [parent FR-12, D-F16] The explorer pane on an edit root shows: "Editing in edit workspace `<name>` (branch `<branch>`). The main checkout is not changed." with **Create PR**, **Discard** and **New edit workspace**. Code panes on an edit root show the same sentence without buttons.
- **FR-6** [parent FR-13] **Create PR** opens a dialog with Title (required, default D-F12), Body, a Draft checkbox (direct only), and two buttons: **Open PR** and **Send through pipeline**. Each button is disabled with its reason in words when the project lacks PR support or pipeline support. Each has a footnote: Open PR — "Commits every change in this edit workspace, pushes `<branch>` and opens a PR to `<default branch>`." Send through pipeline — "Creates a GitHub issue, opens its PR and hands it to Overdeck's review pipeline."
- **FR-7** [parent FR-13] Both modes commit every change (`git add -A`, then `git commit -m <title>` as the operator identity). If nothing is staged and the branch has no commits ahead of `origin/<default branch>`, the request fails with 409 `NOTHING_TO_COMMIT`.
- **FR-8** [parent FR-13, FR-14] **Open PR** pushes the edit branch and opens a PR to the default branch. While a PR is open, the dialog becomes "Commit and push" (Title labeled "Commit message", one button), which commits and pushes to the same PR.
- **FR-9** [parent FR-14] With a PR, the banner shows a PR row: link `#<n>`, state (Open, Draft, Merged, Closed), **Merge**, **Refresh**, and **Push changes** when the explorer's git status shows uncommitted changes. **Merge** is enabled only when the merge verdict says `canMerge` and there are no uncommitted changes; otherwise it is disabled and its reason is shown inline. The PR row refreshes after a push, after a merge attempt and on Refresh. There is no polling.
- **FR-10** [parent FR-14, D-F8] **Merge** re-reads the PR, refuses unless `canMerge`, refuses unpushed work, squash-merges pinned to the head SHA, then removes the edit workspace (D-F9, D-F10). The client then switches every pane on the edit root back to `project:<key>`.
- **FR-11** [parent FR-15] **Discard** opens a dialog listing the uncommitted files (from git status) and the open code panes with unsaved edits, with "Also close PR #n" (checked by default, shown only when a PR is open). Confirming removes the edit workspace with force and, if checked, closes the PR. The client switches panes back to `project:<key>` and drops the edit root's drafts.
- **FR-12** [parent FR-16, D-F2, D-F3] **Send through pipeline** commits, creates a GitHub issue titled with the dialog title and a body of the dialog body plus the line "Created from the Overdeck file explorer.", pushes `feature/<issue-lower>`, opens the PR with `ensurePRExists`, removes the edit workspace, and starts adoption in the background. It answers `{ issueId, issueUrl, prUrl, prNumber }`. The client switches panes back to `project:<key>` and shows "Created `<ID>` and opened PR #`<n>`. Overdeck is setting up its pipeline workspace and will start review."
- **FR-13** [parent D-11] **New edit workspace** calls `beginEdit({ forceNew: true })` and points this explorer pane at the new root. Code panes stay on their current root.
- **FR-14** All four routes, and every destructive step, accept only edit workspaces (edit branch, D-A4 root). Any other workspace id answers 409 `NOT_AN_EDIT_WORKSPACE` and nothing runs.
- **FR-15** [parent WI-18] `features/file-explorer.mdx` documents the explorer end to end and is in `docs.json` navigation after `features/workspaces`.

### Non-functional

- **NFR-1** Server code is async only: `runGit` (explorer git runner), `runGh`, `fs/promises`, `listProjectsAsync`. No `execSync`, `loadConfigSync`, `resolveProjectFromIssueSync` or other blocking call is added to code reachable from the dashboard server.
- **NFR-2** No route or service ever writes the primary checkout's working tree or index. Git commands run with `cwd` = the primary checkout only for `worktree remove`, `branch -D` and `push --delete`.
- **NFR-3** Every new HTTP route has a `ROUTE_SCOPES` row with `scope: 'admin'`, a no-loss-matrix row, a `TELEMETRY_CLIENT_ROUTES` entry and its value in the `client_route` row of `docs/TELEMETRY.md`. GET routes check `rejectUnauthorizedDashboardRequest`; POST routes check `rejectUnsafeDashboardMutationRequest` (JSON body, CSRF).
- **NFR-4** Every new `src/` file stays under 1,000 lines. Tests that involve delays (`UNKNOWN` re-read, debounces) use `vi.useFakeTimers()` and `vi.advanceTimersByTimeAsync()`.
- **NFR-5** No `--no-verify`, no `git stash`, no deep-wipe, no `--admin` merge anywhere.

## 5. Repo rules that apply (restated)

- **Fake timers** for every delay, debounce and retry test. Never real waits.
- **One variant per operation in `src/lib`.** This issue adds no `src/lib` module. Do not wrap Promise code in exported Effect façades (`npm run lint:effect-facades`).
- **No new import cycles** (`npm run lint:circular`). Services under `services/explorer/` must not import route modules; the route module injects `ensurePRExists` into the pipeline service.

No SQL (`scripts/guard-workspace-doors.sh`).
- **No-loss matrix and route scopes** (NFR-3). `no-loss-matrix.test.ts` scans `HttpRouter.add(` calls, and `route-scopes.test.ts` requires every `ROUTE_SCOPES` path in `TELEMETRY_PROPERTY_DOMAINS.client_route` (search `lists every scoped path as a telemetry client route`).
- **New tests must not read source files** with grep-style assertions or add `skipIf`/`.only`.
- **Style:** load the `pan-style-guide` skill before writing UI. Running is not green, no pill badges, no Inter. Use `components/shared/Modal.tsx` for dialogs and `useConfirm` from `components/DialogProvider.tsx` only for yes/no confirms.
- **Quality gates** before `pan done`: `npm run typecheck`, `npm run lint`, `npx vitest run <touched test files>`. Never the full `npm test` locally.
- **Changelog:** `changelog.d/pan-5191.md` (`#### New`, format in `changelog.d/README.md`). Never edit the top of `changelog.mdx`.
- **Never `git stash`; never a destructive HTTP request speculatively.**

### 6.1 Shared types (added to `packages/contracts/src/explorer.ts`, after `ExplorerBeginEditResult`)

  rootId: string            // 'workspace:<id>'

  defaultBranch: string
  path: string

  url: string
  number: number

## 9. Out of scope (NonGoals)

- Trackers other than GitHub Issues for Send through pipeline (D-F3), and forges other than GitHub for Create PR.
- Carrying files that exist only in the main checkout (untracked, ignored, local-only commits) into an edit workspace (D-F15).
- Moving or renaming the scratch worktree into a pipeline workspace (D-F2 replaces it with adoption).
- Polling PR state; AI-generated PR titles or bodies; stacked PRs.
- Git actions (stage, unstage, discard changes) on `project` roots.
- Undo history on `project` roots.
- Reaping abandoned edit workspaces automatically.
- Automated roles creating real GitHub PRs, issues or merges (D-F17).
- Any change to `pan workspace` CLI behavior or to scratch workspaces not on an edit branch.
