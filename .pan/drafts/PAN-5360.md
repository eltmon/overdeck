# PAN-5360: Memory facts — source attribution, supersession and a duplicate/contradiction lint

**Issue:** [PAN-5360](https://github.com/eltmon/overdeck/issues/5360)
**Status:** planned (auto planning, 2026-11-15)

## Glossary

- **Fact** — one curated memory file `<id>.md` with YAML frontmatter, read by
  `parseMemoryFact` in `src/lib/memory/facts/store.ts`. Not an observation (the automatic
  session memory under `~/.overdeck/memory/`).
- **Store** — one flat directory of facts. Three exist: project
  (`<planHome>/.overdeck/memory/`), operator (`~/.overdeck/context/memory/`, `--user`) and machine
  (`~/.overdeck/context/machine-memory/`, `--machine`). The CLI picks one with `resolveFactTarget`
  (`src/cli/commands/memory-facts.ts`).
- **Launch index** — the one-line-per-fact list `renderManagedMemorySections`
  (`src/lib/memory/facts/render.ts`) renders into every managed session at launch. It never
  touches the network.
- **Injection** — every path that hands facts to an agent: the launch index, the dashboard
  Context preview (same renderer) and `pan memory search` fact matches (`findMatchingFacts`).
  All of them filter with `isActiveFact` (`store.ts`).
- **Active fact** — a fact the launch index and search include. After this change: `status`
  is `active` (or absent), `superseded_by` is absent, and `review` is empty.
- **Source** — free-text attribution in frontmatter `source:` (who or what made the rule and
  when), for example `twitch:alice 2026-11-10 14:20` or `operator`. Shown by `show` as
  `Attribution:`.
- **Supersession** — fact X replaces fact Y. X carries `supersedes: [Y]`; Y carries
  `status: superseded` and `superseded_by: X`. Y stays on disk and is no longer active.
- **Retire** — `pan memory retire <id>`: the existing hard delete. Unchanged.
- **Link finding** — a deterministic lint finding about supersession links (dangling id,
  one-way link, cycle, status/link mismatch).
- **Duplicate pair** — two active facts whose similarity is at or above the duplicate threshold.
- **Contradiction candidate** — a pair of active facts whose similarity is at or above the
  (lower) candidate threshold; the LLM judge decides whether it contradicts.
- **Judge** — the function that asks an LLM whether two facts contradict. Default: memory
  extraction provider via `extractWithProviderPolicy` (`src/lib/memory/providers/policy.ts`).
- **Embedder** — the function that turns fact texts into vectors. Default:
  `createConversationEmbeddingProvider` (`src/lib/conversation-search/embedding-provider.ts`).
- **Lexical similarity** — local TF-IDF cosine over word tokens; no network. Used when no
  embedder is available.

## Problem

Verified against `c4d4c268676`:

- `pan memory add` always writes `source: null` — `src/cli/commands/memory-facts.ts` line 224
  (`source: null,`). There is no `--source` flag on `add` or `edit` (registration lines 413-442).
  `edit` keeps the old value (line 292, `source: existing.source,`).
- `MemoryFact` (`src/lib/memory/facts/store.ts` lines 26-38) has `updated` but no `created`, no
  `supersedes`/`superseded_by`, and no `status`. The only "inactive" signal is a non-empty
  `review` list (`isActiveFact`, lines 216-218: `return fact.review.length === 0;`).
- `serializeMemoryFact` (lines 169-180) builds a fresh frontmatter object from known keys only,
  so `pan memory edit` silently **drops every unknown frontmatter key** today. The issue requires
  unknown keys to stay preserved.
- `retire` deletes the file (`removeMemoryFact`, lines 209-214). A superseded rule either stays
  active or disappears with nothing linking old to new.
- Nothing detects duplicate or contradicting facts. In the dfai project store (172 facts),
  `disable-timestream-for-sieges-and-caravans.md` is still an active fact whose description
  begins "Superseded arrival rule: …", so every agent reads it from the index.

## Proposal (chosen approach)

1. Extend the fact schema with optional `created`, `supersedes`, `superseded_by`, `status`
   (`active | superseded | retired`); keep `source`. Preserve unknown keys through parse and
   serialize. Redefine `isActiveFact` so superseded/retired facts leave the index and search.
2. `pan memory add|edit --source <text> --supersedes <ids>`. A superseding write marks each old
   fact `superseded` and links both ways, without deleting it. Both files are validated before
   either is written.
3. `pan memory show` prints the attribution, created date, status and links. `pan memory list
   --all` shows every fact including superseded ones; `--review` keeps meaning "carries a review
   marker".
4. `pan memory lint`: an advisory report of link findings, duplicate pairs (embedding similarity,
   lexical fallback) and contradictions (LLM judge over the most similar pairs). It never edits.
5. `retire` stays the hard delete.

## Requirements

- **FR-1** Frontmatter accepts optional `created` (YYYY-MM-DD), `supersedes` (list of fact ids),
  `superseded_by` (one fact id) and `status` (`active`, `superseded` or `retired`). An invalid
  value makes the file a parse problem, like an invalid `updated` today.
- **FR-2** Unknown frontmatter keys survive `parseMemoryFact` → `serializeMemoryFact` unchanged
  (same values, original relative order, after the known keys).
- **FR-3** `isActiveFact` returns true only when `status` is `active`, `supersededBy` is null and
  `review` is empty. The launch index, Context preview and `pan memory search` fact matches
  therefore exclude superseded and retired facts.
- **FR-4** `pan memory add <id> --source <text>` writes `source:`; `add` always writes
  `created: <today>`.
- **FR-5** `pan memory add|edit <id> --supersedes <a,b>` writes `supersedes` on the new/edited
  fact and rewrites each named fact with `status: superseded`, `superseded_by: <id>` and today's
  `updated`, keeping all its other fields. The old file is never deleted.
- **FR-6** `pan memory edit <id> --source <text>` replaces `source`. `edit` keeps `created`,
  `supersedes`, `superseded_by`, `status` and unknown keys unless a flag changes them.
- **FR-7** `pan memory show <id>` prints `Attribution:`, `Created:`, `Status:` and `Supersedes:`
  lines (each only when it has a value) between the existing `Source: <file>` line and the raw file.
- **FR-8** `pan memory list --all` lists every parsed fact with a status suffix for non-active
  facts; `--review` lists only facts whose `review` is non-empty; the default lists active facts.
- **FR-9** `pan memory lint` reports link findings, duplicate pairs and contradictions for one
  store, as text or `--json`, and never writes a fact file.
- **FR-10** Similarity uses the configured embedder when it is available and falls back to
  lexical similarity when it is not (disabled, no key, or an embed error); the report names the
  method used and the fallback reason.
- **FR-11** The contradiction pass judges at most `MAX_CONTRADICTION_PAIRS` (20) candidate pairs,
  most similar first; `--no-llm` skips it; an unavailable judge is reported, not fatal.
- **NFR-1** The launch path stays offline: `render.ts` imports nothing from the lint modules, and
  no lint module is imported by `render.ts`, `store.ts` or `operator-sync*.ts`.
- **NFR-2** Lint tests never touch the network: embedder and judge are injectable, and tests
  inject deterministic fakes.
- **NFR-3** No hardcoded model: the judge uses the memory extraction provider selection
  (`resolveExtractionProviderSelection`), the embedder uses `conversationSearch` config.
- **NFR-4** `pan memory lint` exits 0 after printing a report, whatever it finds; it exits 1 only
  for invalid flags or an unresolvable store.

## Decisions (made here, auto mode)

- **D1 Status default.** Absent `status` means `active`. `serializeMemoryFact` writes `status`
  only when it is not `active`, so existing files do not change shape on edit.
- **D2 `superseded_by` wins.** A fact with `superseded_by` set is inactive even if `status` says
  `active`; lint reports the mismatch. This keeps hand-edited stores safe.
- **D3 Frontmatter key order** on write: `type, title, description, tags, created, updated,
  source, status, supersedes, superseded_by, review`, then unknown keys in their parsed order.
- **D4 Same store only.** `--supersedes` ids are looked up in the write target directory. An id
  missing there is refused with `no fact "<y>" in <dir>`; nothing is written.
- **D5 Supersede rules.** Refuse (exit 1, nothing written) when: an id equals the fact's own id
  (`a fact cannot supersede itself`); the named fact is already superseded by a different id
  (`"<y>" is already superseded by "<z>"`); or, on `edit`, the edited fact itself has
  `superseded_by` (`"<x>" is superseded by "<z>"; edit that fact instead`). Naming a fact already
  superseded by this same id is a no-op for that fact (idempotent repeat). These rules make
  supersession cycles impossible through the CLI.
- **D6 `edit --supersedes` appends.** The edited fact's `supersedes` becomes the union of its
  current list and the new ids, in order, without duplicates.
- **D7 Undo is a hand edit.** There is no un-supersede flag. To undo, edit both files (remove
  `status`/`superseded_by` from the old fact and the id from the new fact's `supersedes`); lint
  flags any half-undone link. Documented in `configuration/memory.mdx`.
- **D8 `status: retired`** is accepted and excluded from the index, but no CLI flag writes it;
  `retire` remains the hard delete. A human may set it by hand to keep a dead rule on disk.
- **D9 `created`.** `add` writes today's date. `edit` never adds `created` to a fact that lacks
  it (no backfill) and never changes an existing one.
- **D10 `source` validation.** One line, at most 200 characters (reuse
  `MEMORY_FACT_DESCRIPTION_MAX`); enforced in `parseMemoryFact` (so hand edits are checked too).
  `source` is not added to the machine-path haystack, so existing files cannot become problems.
  Probe: `redactSensitiveText('source: twitch:alice 2026-11-10 14:20')` returns the text unchanged.
  Probe (2026-11-15): no fact in the overdeck project store, the operator store, the machine store or
  any `~/Projects/*/.overdeck/memory/` store has a `status`, `created`, `supersedes`, `superseded_by` or
  `source` key, so the new validation turns no existing file into a parse problem; no migration is needed.
- **D11 Two-file write.** `writeSupersedingFact` serializes, parses and secret-scans every file
  (new fact plus each old fact) before writing any; then writes the new fact, then each old fact,
  each via the existing temp-file + `rename`. An I/O failure after the first write throws an
  error naming the files already written.
- **D12 `show` label.** The existing first line `Source: <file>` stays (asserted at
  `tests/unit/cli/memory-facts.test.ts` line 155). The fact's `source` prints as
  `Attribution: <text>`.
- **D13 `list` filters.** Default: active facts. `--review`: `review.length > 0` (unchanged
  meaning, now independent of status). `--all`: every parsed fact. `--review` with `--all` is
  refused. Plain-text lines for non-active facts end with ` [superseded by <id>]`,
  ` [superseded]`, ` [retired]` or ` [review: <markers>]`.
- **D14 Sync-conflict copies** (`conflictCopyText`, `src/lib/memory/facts/operator-sync-conflicts.ts`
  lines 36-45) clear `supersedes` and `supersededBy` on the copy (so a copy never claims a link)
  and keep every other field, including unknown keys.
- **D15 Lint scope.** One store per run, chosen like `list` (`resolveFactTarget(flags, 'read')`,
  `--project|--user|--machine|--here`). Link checks run over all parsed facts; similarity and
  contradictions run over active facts only (a superseded fact and its successor are similar by
  construction).
- **D16 Similarity.** Text per fact = `title + "\n" + description + "\n" + body`. Lexical: tokens
  are lowercase `[a-z0-9]+` runs of length ≥ 2 minus a fixed English stopword list; TF-IDF with
  `idf = ln(1 + N / df)`; cosine. Embedding: `createConversationEmbeddingProvider()`; used when its
  `enabled` is true; if `embed` throws, fall back to lexical with the error message (first 200
  chars) as the fallback reason. Thresholds (exported constants in `lint-similarity.ts`):
  lexical duplicate 0.60, lexical candidate 0.30, embedding duplicate 0.90, embedding candidate
  0.75. `--threshold <n>` overrides the duplicate threshold only (0 < n ≤ 1).
- **D17 Contradiction candidates** are all pairs at or above the candidate threshold (duplicates
  included — "enable X" vs "disable X" is both), sorted by similarity descending, capped at
  `MAX_CONTRADICTION_PAIRS = 20`.
- **D18 Default judge.** `extractWithProviderPolicy(prompt, CONTRADICTION_JSON_SCHEMA, { identity,
  temperature: 0, maxTokens: 300 }, { recordHealth: async () => {} })`. The no-op `recordHealth`
  stops lint from writing a health file for a synthetic workspace. Identity:
  `{ projectId: <project key, or 'operator' / 'machine'>, workspaceId: 'memory-lint', issueId:
  null, runId: 'memory-lint', sessionId: 'memory-lint-<uuid>', agentRole: 'conversation',
  agentHarness: 'overdeck' }`. Schema: `{ contradicts: boolean, reason: string }`. Each fact body
  is truncated to 2,000 characters in the prompt. If the first call returns `skipped` or
  `dropped`, the pass stops with status `unavailable` and that reason; a malformed answer for one
  pair counts in `pairsFailed` and the pass continues.
- **D19 Exit code.** Advisory, like `/okf lint`: exit 0 after any report (NFR-4).
- **D20 Description hint.** Lint adds a link finding `description-says-superseded` for an active
  fact whose description matches `/\bsupersed/i` (the dfai case), suggesting `pan memory edit
  <new> --supersedes <id>`.
- **D21 MCP `memory_add` is out of scope.** Agents prefer the MCP tool, so `source` should reach
  it, but `supersedes` through an agent token lets any agent drop a fact from every index — a
  trust decision. It also adds the `src/dashboard` subsystem and `configuration/mcp.mdx`,
  breaching the 6-subsystem plan limit. Filed as sibling issue PAN-5365 (https://github.com/eltmon/overdeck/issues/5365).
- **D22 `pan done` guard needs no change.** `filterUncommittedPorcelainLines`
  (`src/lib/work/done-preflight.ts`) keeps every `.overdeck/memory/` porcelain line, modified
  (` M`) as well as new (`??`), so a rewritten superseded fact also blocks `pan done` until
  committed.
- **D23 Lint registration** lives in `src/cli/commands/memory.ts` next to
  `registerMemoryFactCommands(memory);` (line 474), with the command in a new file
  `src/cli/commands/memory-lint.ts`, so the lint item does not edit `memory-facts.ts`.

### W7 — Lint link checks (FR-9 links, D20)

Files: `src/lib/memory/facts/lint-links.ts` (new), `tests/unit/lib/memory/facts/lint-links.test.ts` (new).

```ts
export type LinkFindingKind = 'dangling-supersedes' | 'dangling-superseded-by' | 'one-way-link'
  | 'status-without-link' | 'link-without-status' | 'cycle' | 'description-says-superseded';

```
Rules: `supersedes` id not in the store → dangling-supersedes; `supersededBy` not in store →
dangling-superseded-by; X supersedes Y but Y.supersededBy ≠ X (or Y.supersededBy = X but X does
