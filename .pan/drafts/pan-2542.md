# PAN-2542: Add GPT-5.6 (Sol / Terra / Luna) support, make gpt-5.6-sol the new OpenAI default

**Issue:** [PAN-2542](https://github.com/eltmon/overdeck/issues/2542)

## Glossary

- **GPT-5.6** — OpenAI's model family released 2026-07-09 (general availability; a
  narrower partner preview shipped 2026-06-25). Ships as three sizes, largest to
  smallest: **Sol**, **Terra**, **Luna**. There is no bare `gpt-5.6` API model —
  every call must name a tier.
- **`gpt-5.6-sol`** — flagship tier. API model ID confirmed by OpenAI's Codex CLI
  model docs (`learn.chatgpt.com/docs/models`) and OpenRouter
  (`openai/gpt-5.6-sol`, OpenRouter strips the `openai/` prefix goes to the raw
  OpenAI API). Codex CLI docs state Sol at "medium reasoning" is Codex's "default
  Power setting" — i.e. **Sol is OpenAI's own recommended default**, matching what
  this issue asks Overdeck to do for its own default.
- **`gpt-5.6-terra`** — mid tier. Docs describe it as "GPT-5.5-competitive
  performance at 2x lower cost" — i.e. roughly gpt-5.5's capability class at
  roughly half gpt-5.5's price.
- **`gpt-5.6-luna`** — fastest/cheapest tier, the rough successor to the
  `gpt-5.4-mini` market position in the previous generation.
- **CLIProxy** — the local sidecar (`CLIProxyAPI`) that lets `claude-code`-harness
  agents run non-Anthropic models. `src/lib/model-capabilities.ts` models a
  **conservative effective context ceiling** (`CLIPROXY_CODEX_CONTEXT_WINDOW =
  150_000`) for Codex/ChatGPT-subscription models specifically because Claude
  Code's own auto-compact logic doesn't know the proxied model's real marketing
  window and hard-wedges near it (PAN-1672, PAN-1615). This ceiling is **not**
  model-specific — it is an integration constraint of the CLIProxy↔Claude-Code
  path itself, so every Codex-routed OpenAI model in this codebase (`gpt-5.5`
  included) carries the same `contextWindow` value regardless of its real
  marketing window.
- **"opus tier"** — `ProviderConfig.tierModels.opus` in `src/lib/providers.ts`,
  the model returned when role/tier resolution wants "the best model this
  provider offers." This is the field that currently reads `gpt-5.5` and is
  the literal "default" this issue asks to change.
- **Subscription-only model** — a model ID present in
  `SUBSCRIPTION_ONLY_OPENAI_MODELS` (`src/lib/harness-policy.ts`) that is
  blocked when `authMode === 'api-key'` — it may only be used with ChatGPT/Codex
  subscription sign-in (`codex login`), never a plain `OPENAI_API_KEY`.

Sourced 2026-07-09 from OpenAI's Codex CLI model docs
(`learn.chatgpt.com/docs/models`), OpenRouter's per-model pages
(`openrouter.ai/openai/gpt-5.6-sol`, `.../gpt-5.6-terra`), and
`aipricing.guru/openai-pricing` (cross-checked against two independent
sources each):

|---|---|---|---|---|---|
| `gpt-5.6-sol` | flagship, **new default** | $5.00 | $0.50 | $30.00 | 1M (marketing) |
| `gpt-5.6-terra` | balanced | $2.50 | $0.25 | $15.00 | 1M (marketing) |
| `gpt-5.6-luna` | fast/cheap | $1.00 | $0.10 | $6.00 | 1M (marketing) |

existing pricing in `src/lib/cost.ts` — this is coincidental, not a copy-paste
error; keep both entries.

No official SWE-bench Verified score has been published for GPT-5.6 Sol at
launch. Published benchmarks: Terminal-Bench 2.1 88.8% (Sol), "Agents' Last
Exam" 53.6 (Sol — a new high, ahead of Claude Fable 5 on that specific
benchmark). **Do not write a SWE-bench number for GPT-5.6 into any file** —
where a doc has a SWE-bench column, write "not published at launch" instead of
inventing a figure.

Auth: GPT-5.6 shipped through the OpenAI API and Codex CLI, gated behind
ChatGPT/Codex sign-in at launch (same posture as `gpt-5.5` in this codebase
today). Treat all three tiers as subscription-only per FR-4 below.

  `gpt-5.5` to `gpt-5.6-sol` in `src/lib/providers.ts`, and propagate that same

  shared `ModelPicker.tsx`, the `dashboard-utils.ts` display-name mapper).

  `gpt-5.5` and the rest of the legacy catalog (`settings.ts`,
  `providers.ts`, `router-config.ts`, `MODEL_API_IDS`, `settings-api.ts`
  `openaiOrder`).
- **FR-8**: This is an **additive** change. `gpt-5.5` stays fully supported,
  unchanged, and undeprecated — do not touch its existing entries' values
  (see the no-loss note in Work Item 2 about the stale `$3/$18` comment: leave
