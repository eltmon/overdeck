# PAN-5418: Diff window All turns shows only the conversation's own change per file

**Issue:** [PAN-5418](https://github.com/eltmon/overdeck/issues/5418) — parent epic [PAN-5284](https://github.com/eltmon/overdeck/issues/5284), follow-up to [PAN-5408](https://github.com/eltmon/overdeck/issues/5408) (#5417).

## Glossary

- **All turns** — the default view of the conversation diff window (`DiffPanel.tsx`, `defaultView = 'full'`). It reads `GET /api/conversations/:name/diffs/full`, served by `getConversationDiffFull` in `src/lib/overdeck/conversation-diffs.ts`.
- **cwd repo** — the git top-level of the conversation's `cwd` (`repoRootForDir(conv.cwd)`). This issue changes only the cwd repo block. Other repositories are still scoped from transcript edit records and are out of scope.
- **Changes API** — `GET /api/conversations/:name/changes?scope=conversation` (`getConversationChanges` in `src/lib/overdeck/conversation-changes.ts`). It returns `ConversationChanges` (`packages/contracts/src/conversation-changes.ts`): `commits[]` (newest first, each with `sha`, `subject`, `authoredAt`, `files[]` of `{ path, status: 'A'|'M'|'D'|'R', additions, deletions, oldPath? }`) and `uncommitted[]` (same file fields; counts are the file's whole `git diff HEAD` numstat).
- **Attributed commit** — a commit in `changes.commits`. It was tied to this conversation by an `Overdeck-Conversation:` trailer or by a sha in tool output.
- **Attributed file** — a path that appears in an attributed commit's `files` or in `changes.uncommitted`. PAN-5408 already restricts the All turns list to these.
- **Uncommitted attributed edit** — the `changes.uncommitted` entry for a path.
- **Foreign change** — any change to a file that is not in an attributed commit: another agent's commit, a merge, or anything between the conversation's commits.
- **Combined patch** — one ordinary `git diff` for a file that spans all the conversation's changes to it. It is only used when it is provably equal to the conversation's own changes (see FR-3).
- **Commit section** — the part of the response `diff` that holds one attributed commit's patch for the files that need sections. It starts with a **section preamble**.
- **Section preamble** — two mbox-style header lines plus a blank line: `From <40-hex sha> Mon Sep 17 00:00:00 2001\nSubject: <subject>\n\n`. `@pierre/diffs`' `parsePatchFiles` splits a patch on `/(?=^From [a-f0-9]+ .+$)/m` (`COMMIT_METADATA_SPLIT`) and keeps the preamble as the parsed patch's `patchMetadata`. The **uncommitted section** uses the all-zero sha (`'0'.repeat(40)`) and the subject `Uncommitted changes`.

## Problem

Each file's **patch and counts** are still computed from one base commit to the working tree. `src/lib/overdeck/conversation-diffs.ts`, lines 394–417 (grep anchor: `const baseCommit = await findCommitAtTime(cwdRepoRoot, attributionBaseTime(conv, changes));`):

## Requirements

- **FR-1** For each attributed file in the cwd repo, the All turns patch contains only changes from the conversation's attributed commits and its uncommitted attributed edit. No line from a foreign change appears.
- **FR-2** Each attributed file's `additions`/`deletions` in the `files` list equal the per-file sums over the conversation's attributed commits plus its uncommitted attributed edit, the same numbers the Changes API gives.
- **FR-3** A file gets a **combined patch** only when all of these hold. Otherwise it gets **commit sections**.
  1. No attributed commit lists the file with status `R`.
  2. The oldest attributed commit for the file has a parent (`git rev-parse --verify --quiet <sha>^` exits 0).
  3. For each pair of consecutive attributed commits `a_i`, `a_{i+1}` (chronological order), `git diff --quiet a_i a_{i+1}^ -- <path>` exits 0.
  4. If the file has an uncommitted attributed edit, the file is tracked and `git diff --quiet a_last HEAD -- <path>` exits 0.

  The combined patch is `git diff <a_first>^ <a_last> -- <path>`. When there is an uncommitted attributed edit, it is `git diff <a_first>^ -- <path>` (to the working tree).
- **FR-4** A file with commit sections appears once per attributed commit that touched it, in chronological order, inside that commit's section. When it also has an uncommitted attributed edit, it appears once more, inside the uncommitted section.
- **FR-5** A file with only an uncommitted attributed edit gets `git diff HEAD -- <path>`. If that edit is an untracked new file, it gets the existing new-file patch (PAN-5408 FR-5, `untrackedFilePatch`). This keeps PAN-5408 FR-5 behavior.
- **FR-6** The diff window shows each commit-section file block with a label row directly above the file's diff: `<7-char short sha> <subject>`, or `Uncommitted` for the uncommitted section. Files from a plain patch show no label.
- **FR-7** `?file=<path>` and `?ignoreWhitespace=1` keep working: the filter limits the patch to that path, and `-w` reaches every new git call. `files` still lists every attributed file when a filter is given.
- **FR-8** **vs main**, **Compare…**, per-turn diffs (`/diffs/:turnId`) and non-cwd repositories keep their current ranges and behavior.
- **FR-9** Docs describe the per-file scoping: the PAN-5408 paragraph in `docs/DASHBOARD-ARCHITECTURE.md`, the All turns paragraph in `features/conversations.mdx`, and a `changelog.d/pan-5418.md` `#### Fixed` entry.
- **NFR-1** Every new git call uses `execFile` with an argument array (no shell string), `maxBuffer: 50 * 1024 * 1024` for patch output, and runs only in dashboard-server-reachable async code. No `execSync`.
- **NFR-2** Run one `git show` per attributed commit that has sectioned files, not one per (commit, file) pair. A combined patch is one `git diff` per file. Contiguity checks are one `git diff --quiet` per consecutive pair.
- **NFR-3** New logic lives in a new module, `src/lib/overdeck/conversation-diff-own.ts`, which does not import `conversation-diffs.ts` (no import cycle; `npm run lint:circular` stays green). `conversation-diffs.ts` must not grow; it should shrink.

## Decisions (made here; the executor does not re-decide)

- **D1 — Option 2 with option 1 as fallback** (the issue's suggested approach). Use a combined patch when FR-3 holds, and commit sections otherwise.
- **D2 — Contiguity is a content check, not a history walk.** FR-3.3 compares the file's content at `a_i` with its content at `a_{i+1}^`. When they are equal, nothing foreign changed the file between the two commits, so the combined diff equals the composition of the conversation's own changes. This check holds whatever the history shape is (merges, a foreign change that was later reverted, out-of-order author dates). If the order is wrong, the check fails, and sections (which are always exact) are used.
- **D3 — Chronological order** = `[...changes.commits].reverse()`, then a stable sort by `Date.parse(authoredAt)` ascending. The Changes API lists commits newest first by `authoredAt`.
- **D4 — Unresolvable shas are skipped.** An attributed commit for which `git cat-file -e <sha>^{commit}` fails (for example, a rewritten history) contributes no patch. Its file stays in `files` with its Changes API counts.
- **D5 — Counts are sums (FR-2), even for a combined patch.** In rare cases a combined patch's own +/− differs from the sum, for example when a later commit rewrites a line that an earlier commit added. The issue specifies sums, and the list must match the Changes API.
- **D6 — `kind` for each listed file:** take the file's entries in chronological order (commits, then the uncommitted entry). If the last entry's status is `D`, kind is `D`. Otherwise, if the first entry's status is `A`, kind is `A`. Otherwise kind is the last entry's status. (Today `attributedFiles` keeps the newest commit's status, so a file the conversation created and then edited shows as `M`.)
- **D7 — Section labels travel in the patch text** as mbox preambles (glossary). The response shape stays `{ diff, files }`. `parsePatchFiles` already splits on them (verified with `@pierre/diffs` 1.1.22: two `From` sections parse into two patches with distinct `cacheKey`s and the preamble as `patchMetadata`; two plain `diff --git a/X b/X` blocks parse into two files `k-0-0`, `k-0-1`).
- **D8 — Output order.** In `diff`, all plain patches come first: combined patches, the uncommitted-only patch, untracked new-file patches, and non-cwd repo patches. All commit sections come after them, oldest first, and the uncommitted section comes last. **Never put a plain patch after a preamble**: `parsePatchFiles` would absorb it into the previous section, and it would get that section's label.
- **D9 — Renamed files always use sections**, with pathspec `<oldPath> <path>` and `-M`, so `git show` renders a rename rather than a whole-file add.
- **D11 — The label is a plain row in PatchFiles' own wrapper, not `@pierre/diffs`' `renderHeaderMetadata` slot.** The wrapper row is visible no matter how the library's shadow-DOM header behaves, and the existing mock-based test can assert it. No live checkpoint is needed.
- **D10 — Line-level filtering of other agents' uncommitted lines is out of scope.** The uncommitted part is the file's whole `git diff HEAD`, which matches the Changes API's uncommitted counts.

Steps:
1. Move `untrackedFilePatch` (`conversation-diffs.ts` lines 208–221, grep anchor `PAN-5408 FR-5: a new-file patch for an untracked path`) here unchanged.
2. `ownFileChanges`: build per-path `{ path, kind, additions, deletions }`. Sum the additions and deletions over every commit file and uncommitted file with that path. Derive `kind` per D6, iterating in D3 chronological order and then the uncommitted entry. Return an empty map for `null`.
3. `buildOwnPatches` algorithm:
   1. `chrono` = D3 order of `changes?.commits ?? []`, filtered to shas where `git cat-file -e <sha>^{commit}` exits 0 (D4).
   2. `uncommittedByPath` = map of `changes.uncommitted` by path.
   3. For each path: `own` = commits in `chrono` whose `files` contain `path`, and `unc` = `uncommittedByPath.get(path)`. `untracked` = `unc?.status === 'A'` and `git ls-files -- <path>` prints nothing and `existsSync(join(repoRoot, path))`.
      - `own.length === 0`: if `untracked`, push `untrackedFilePatch` output into `plain`. Else if `unc`, add the path to `uncommittedOnly`.
      - Else, if FR-3 holds (checks run in the order listed; stop at the first failure): push `git diff --patch --minimal --no-color [-w] <first>^ [<last>] -- <path>` output into `plain`. Omit `<last>` when `unc` exists.
      - Else: for each commit in `own`, add `path` to `sectionPaths[sha]`, plus that commit file's `oldPath` when its status is `R`. If `unc` exists, add `path` to `uncommittedSection` (or to `uncommittedUntracked` when `untracked`).
   4. If `uncommittedOnly` is non-empty, push `diffPatchFilesAgainstHead(repoRoot, uncommittedOnly, options)` into `plain`.
   5. For each commit in `chrono` with `sectionPaths`, run `git show --format= --patch --minimal --no-color -M [-w] <sha> -- <paths…>`. When the output trims to something non-empty, push `sectionPreamble(sha, subject) + out` into `sections`.
   6. If `uncommittedSection` or `uncommittedUntracked` is non-empty, take `diffPatchFilesAgainstHead` for the tracked ones and append each untracked file's `untrackedFilePatch`. If the joined body is non-empty, push `sectionPreamble(UNCOMMITTED_SECTION_SHA, 'Uncommitted changes') + body` into `sections`.
4. Git helper: `execFileAsync('git', args, { cwd: repoRoot, encoding: 'utf-8', maxBuffer: 50 * 1024 * 1024 })`. For the `--quiet` checks, exit code 0 means "same", and a rejected promise with `code === 1` means "differs". Treat any other error as "differs", so the code falls back to sections, which are always exact.
