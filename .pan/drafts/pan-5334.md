# PAN-5334 — D1 follow-up: pushed commits in detached worktrees, the `HEAD` branch label, Copy session id

**Parent PRD:** `.pan/drafts/pan-5291.md` (child D1 of epic `.pan/drafts/pan-5284.md`). Found in the epic owner's D-15 live check on :3011 at buildCommit `9707e582e09`.

## 1. Glossary

- **Status line** — the second header row under a conversation's title: state · folder · branch (+PR) · commit counts · cost (`components/chat/header/ConversationStatusLine.tsx`).
- **Detached worktree** — a git worktree whose HEAD points at a commit, not a branch. Handoff worktrees (`~/Projects/hoff-<slug>`) are detached on purpose before `pan review request`. A detached HEAD has no upstream, so `@{u}` does not resolve.
- **Upstream** — the remote-tracking branch that `@{u}` names for the current branch.

FE below means `src/dashboard/frontend/src`.

## 2. What is wrong (verified 2026-11-15)

1. **Wrong push count.** Conversation `20261115-4cbc` (cwd `/home/eltmon/Projects/hoff-pan-5325`, detached) shows `1 commit not pushed`. `GET /api/conversations/20261115-4cbc/changes?scope=conversation` returns commit `a46a441` with `"pushed": false`. That commit is on `origin/feature/pan-5325`: `git -C ~/Projects/hoff-pan-5325 rev-list HEAD --not --remotes` prints nothing. The cause is `listLocalShas` in `src/lib/overdeck/conversation-change-commits.ts` (lines 89–97):
   ```ts
   export async function listLocalShas(repoRoot: string): Promise<{ shas: Set<string>; hasUpstream: boolean }> {
     try {
       const out = await git(repoRoot, ['rev-list', '@{u}..HEAD']);
       return { shas: new Set(...), hasUpstream: true };
     } catch {
       return { shas: new Set(), hasUpstream: false };
     }
   }
   ```
   Both callers compute `pushed: local.hasUpstream && !local.shas.has(commit.sha)` (`conversation-change-commits.ts` line 173 and `conversation-changes.ts` line 276). Without an upstream, every commit counts as not pushed.
2. **`HEAD` as a branch name.** `FE/components/chat/ConversationBranchMeta.tsx` line 25 renders `conversation.branch` as is. For a detached checkout the conversation list sends `branch: "HEAD"` (`src/lib/overdeck/conversation-list.ts` line 276, `gitInfo.branch`), so the status line reads `HEAD`.
3. **Copy session id never renders.** `FE/components/chat/header/ConversationHeaderMenu.tsx` line 141:
   ```ts
   const sessionId = conversation.sessionFile?.split('/').pop()?.replace('.jsonl', '') ?? null;
   ```
   `/api/conversations` rows carry `claudeSessionId` but never `sessionFile`, so `sessionId` is always null and the item is never shown. The `Conversation` type has both fields (`FE/components/CommandDeck/ConversationList.tsx` lines 53 and 55).

## 3. Decisions

- **D-1 Fallback only.** With an upstream, `listLocalShas` keeps `@{u}..HEAD` unchanged. Without one, it counts a commit as pushed when any remote-tracking ref contains it: `git rev-list HEAD --not --remotes`. It uses the fallback only when `git remote` prints at least one name. With no remote it returns `{ shas: new Set(), hasUpstream: false }` as today. The return field keeps its name `hasUpstream`, and in the fallback it is `true`, because it means "the `shas` set is meaningful". Update the JSDoc on the function and the module header line 12 to say so.
- **D-2 Detached label.** When `conversation.branch === 'HEAD'`, render the text `detached` and use the title `Detached HEAD · ${cwd}`. Every other branch value renders unchanged.
- **D-3 Session id source.** `sessionId = conversation.claudeSessionId ?? <sessionFile basename> ?? null`. The display rule is unchanged: show the item only when `sessionId` is truthy and differs from `conversation.name`.

## 4. Requirements

- **FR-1** A commit that a remote-tracking ref contains counts as pushed when HEAD has no upstream (D-1).
- **FR-2** A repo with no remote still reports every commit as not pushed.
- **FR-3** A detached checkout's status line shows `detached` (D-2).
- **FR-4** ⋯ → Copy session id appears for a conversation with a `claudeSessionId` that differs from its name, and copies that value (D-3).
- **NFR-1** Async `execFile` only. The dashboard server calls this code, so `execSync` is not allowed.

  } catch {
