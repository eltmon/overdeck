# PAN-4506 — Review kickoff rejected by Herdr ("unexpected end of hex escape"): reviewer never starts

**Issue:** https://github.com/eltmon/overdeck/issues/4506
**Planned against:** `main` @ `dcb3d6d82e2` (2026-10-03)

## Glossary

- **Kickoff** — the first prompt Overdeck types into a freshly launched (or resumed) agent pane. For a reviewer it is the review role prompt built in `spawnReviewRoleForIssue` (`src/lib/cloister/review-agent.ts`).
- **Herdr** — the default terminal backend. Overdeck talks to it over NDJSON on a unix socket (`src/lib/terminal-backends/herdr-api.ts`), one `{id, method, params}` line per connection.
- **Lone surrogate** — a single UTF-16 code unit in `U+D800–U+DFFF` without its partner. Characters outside the Basic Multilingual Plane (most emoji, e.g. `🛠` = `U+1F6E0` = `🛠`) are stored in a JS string as a *pair* of code units. `String.prototype.slice(0, n)` counts code units, so it can cut a pair in half and leave a lone high surrogate at the end.
- **Well-formed text** — a JS string with no lone surrogates. `JSON.stringify` of a lone surrogate emits `"\ud83e"` (legal JSON syntax, and Node's `JSON.parse` accepts it), but Herdr's Rust `serde_json` parser rejects it when deserializing into a `String` with `unexpected end of hex escape`.
- **`invalid_request`** — the error code Herdr answers when it cannot parse a request at all. It arrives with an empty id: `{"id":"","error":{"code":"invalid_request",…}}`. Nothing was executed.
- **Tier-1 summary** — `formatTier1Summary(manifest)` in `src/lib/cloister/review-context.ts`: the compact review-context block embedded into every reviewer kickoff (parent at `review-agent.ts:503`, convoy lanes at `review-convoy.ts:175`).
- **Pipeline journal** — `<workspace>/.overdeck/pipeline.jsonl`, append-only (`src/lib/cloister/pipeline-journal.ts`). Deacon-lite recovery routines key off its last entry (the *tail*).
- **Silent-reviewer recovery** — `recoverSilentReviewers` (`src/lib/cloister/silent-reviewer-recovery.ts`, PAN-4433): a reviewer with a `reviewDispatchedAt` stamp and no transcript/report after `roles.review.stallMinutes` is re-dispatched once, then escalated.
- **Undispatched-review recovery** — `recoverUndispatchedReviews` (`src/lib/cloister/undispatched-review-recovery.ts`, PAN-4221): re-requests a review whose journal tail is a `request-review` `verification.passed` with no live reviewer.
- **Needs-you (activity channel)** — `surfaceIssueFeedbackNeedsYou(issueId, reason, details)` in `src/lib/cloister/feedback-target.ts:306`: emits a `warn` activity entry `"<ISSUE> needs you: <reason>"`. This is the channel PAN-4433's silent-reviewer escalation already uses.

## Root cause (verified during planning)

1. **The offending character.** The live PAN-4383 review manifest `workspaces/feature-pan-4383/.pan/review/agent-pan-4383-review-4e585623/context.json` holds 8 CodeRabbit findings. Finding 0 has a 7,593-char body; `body.slice(0, 200)` ends in `"…885-885\`: _\ud83e"` — a lone high surrogate (the first half of a `🛠`/`🧹`-style emoji in CodeRabbit's `_🛠️ Refactor suggestion_` header). Verified with a Node probe against the real file.
2. **Where it enters the kickoff.** `src/lib/cloister/review-context.ts:460`:
   ```ts
   const bodyPreview = finding.body.slice(0, 200);
   ```
   `formatTier1Summary` embeds `bodyPreview` into the tier-1 summary, which is embedded into every reviewer kickoff (parent and convoy lanes).
3. **Why Herdr rejects it.** Reproduced live against herdr 0.9.1 with a *read-only* `agent.get` whose `target` contains `\ud83e`:
   ```
   {"id":"","error":{"code":"invalid_request","message":"invalid request: unexpected end of hex escape at line 1 column 78"}}
   ```
   The same string with the lone surrogate replaced by `U+FFFD` parses (answer: `agent_not_found`). So Herdr is behaving like any strict `serde_json` server; nothing to file upstream. The client must not send ill-formed text.
4. **Why the reviewer looks "silent" instead of failed.** For a claude-code specialist role, `spawnRun` (`src/lib/agents/spawn.ts`) sets `tracksKickoffDelivery = role === 'flywheel'` (line 275), so the review kickoff takes the `else` branch at ~line 554:
   ```ts
   const delivery = await deliverAgentMessage(agentId, prompt, 'spawnRun:initial-prompt', undefined, kickoffOpts);
   if (resolvedHarness === 'kimi-code' && !delivery.ok) {
     throw new Error(delivery.failure ?? `delivery returned ok=false via ${delivery.path}`);
   }
   ```
   `deliverAgentMessage` returns `{ ok: false, path: 'herdr', failure: 'invalid_request: invalid request: unexpected end of hex escape …' }` (`src/lib/agents/delivery.ts:449-451` catches the Herdr throw). For every harness except kimi-code, `ok: false` is discarded. `spawnRun` returns a healthy state, `spawnReviewRoleForIssue` stamps `reviewDispatchedAt` and reports success, and the pane sits at an empty prompt until silent-reviewer recovery fires, re-dispatches the same doomed text, and escalates after the second silence. Each new review request repeats the whole cycle.
5. **Resume path.** `resumeAgent` → `deliverInitialPromptWithRetry` logs `Kickoff delivery attempt 1/2 failed …` twice, then `review-agent.ts:590` falls back to a fresh spawn, which hits item 4.

## Requirements

- **FR-1** — Truncated previews in the review tier-1 summary never end in a lone surrogate (truncation is code-point safe).
- **FR-2** — Every request `HerdrApiClient` writes to the Herdr socket (`call` and `stream`) carries well-formed text: lone surrogates in any string value are replaced with `U+FFFD` before serialization.
- **FR-3** — `pasteAndSubmitHerdrPane` sends and compares a well-formed copy of the text, so the composer-presence check compares the same string Herdr typed.
- **FR-4** — When the kickoff delivery in `spawnRun`'s ready-wait branch returns `ok: false` with an `invalid_request:` failure, `spawnRun` closes the pane, writes the `stopped` row, and throws a `KickoffRejectedError` carrying the failure — for every harness, not only kimi-code.
- **FR-5** — The pipeline journal has a new entry type `review.dispatch-failed` with `data: { reviewer, error }`; `pan show` renders it.
- **FR-6** — When `spawnReviewRoleForIssue` fails because of a `KickoffRejectedError`, it appends `review.dispatch-failed` to the issue journal and surfaces a Needs-you activity entry containing the error, then returns `success: false` with the error (as today).
- **FR-7** — A `review.dispatch-failed` journal tail is left alone by `recoverUndispatchedReviews` and `recoverStalledReviews`; only a new review request (operator or new head) starts another dispatch.
- **NFR-1** — `src/lib/agents/delivery.ts` (1159 lines, allowlist cap 1160) and `src/lib/terminal-backends/herdr.ts` (1008 lines, cap 1008) are not modified.
- **NFR-2** — No file over 1000 lines grows past its allowed count (`scripts/lint-file-size.sh`); `spawn.ts` (1074, cap 1089) grows by at most 4 lines; `review-agent.ts` (955) stays at or under 1000.
- **NFR-3** — No new import cycle (`npm run lint` includes the circular-import check). New helper modules have no Overdeck imports, or only `pipeline-journal.js` plus dynamic `feedback-target.js`.

## Decisions

- **D1 — Fix at the source and at the wire.** The truncation is fixed where it happens (FR-1), and the Herdr client sanitizes every request (FR-2) because many other strings (pane text, `pan tell` bodies, issue titles) reach Herdr and any `.slice` anywhere can produce the same failure. Replacing with `U+FFFD` loses one broken character; it never drops a request.
- **D2 — Hand-rolled helpers, no `toWellFormed()`.** `tsconfig.json` sets `"lib": ["ES2022", "ES2023.Array"]`, so `String.prototype.toWellFormed` is untyped even though Node 22 has it. Do not change `lib` in this issue. Use the regex below.
- **D3 — Only `invalid_request:` fails the spawn.** Herdr answers `invalid_request` before executing anything, so the text certainly did not land and a retry of the same text fails identically. Other `ok: false` failures (an ambiguous disconnect after `pane.send_text` was written, guard refusals, tmux failures) are left as they are today, because some of them may have typed the text. kimi-code keeps its existing throw-on-any-failure.
- **D4 — Needs-you uses the existing activity channel.** `surfaceIssueFeedbackNeedsYou` is what PAN-4433's escalation uses. The Command Deck "Needs you" bucket (`isNeedsYouFeature` in `src/dashboard/frontend/src/components/CommandDeck/pipeline-helpers.ts`) is derived from a blocked pane in `derived-issue-state.ts`; wiring journal tails into derived attention is out of scope.
- **D5 — The journal entry ends recovery loops by being the tail.** `recoverUndispatchedReviews` only acts on a `verification.passed` tail (`undispatched-review-recovery.ts:85`), and `stalledReviewReason` (`deacon-lite.ts:259`) only on `review.requested`/`review.dispatched`/`review.redispatched`. A `review.dispatch-failed` tail is skipped by both with no code change to either routine; this issue adds tests that pin that.
- **D6 — Silent-reviewer re-dispatch needs no change.** `redispatchParent` already escalates immediately when `spawnReviewRoleForIssue` returns `success: false` (`silent-reviewer-recovery.ts`, the `if (!outcome.success) return escalate(…, 're-dispatch failed: …')` branch). After FR-4 a rejected kickoff makes it return `success: false`.
- **D7 — No change to the resume retry loop.** `deliverInitialPromptWithRetry` (`delivery.ts:1035-1100`) still tries twice on `invalid_request`; `delivery.ts` has one line of size headroom, and with FR-1/FR-2 the rejection no longer occurs for this cause.
- **D8 — PAN-4383 itself is recovered operationally after deploy.** Once this merges and `pan reload` ships it, the operator (or Flywheel) runs `pan review request PAN-4383`; the work agent does not touch PAN-4383's workspace.

### W1 — Leaf helper: well-formed text (`src/lib/well-formed-text.ts`, new)

**Why:** FR-1/FR-2/FR-3 need one shared, dependency-free implementation.
**Files:** `src/lib/well-formed-text.ts` (new), `src/lib/__tests__/well-formed-text.test.ts` (new).
**Code:**
```ts
/**
 * Well-formed UTF-16 helpers (PAN-4506). A JS string can hold a lone
 * surrogate — most often the first half of an emoji that `.slice` cut in two.
 * `JSON.stringify` writes it as `"\ud83e"`, which strict JSON parsers such as
 * Herdr's `serde_json` reject with "unexpected end of hex escape".
 * `String.prototype.toWellFormed` is untyped under this repo's ES2022 lib.
 */
const LONE_SURROGATE = /[\uD800-\uDBFF](?![\uDC00-\uDFFF])|(?<![\uD800-\uDBFF])[\uDC00-\uDFFF]/g;

/** Replace every lone surrogate with U+FFFD. */
export function toWellFormedText(text: string): string {
  return text.replace(LONE_SURROGATE, '�');
}

/** `text.slice(0, maxUnits)` that never splits a surrogate pair. */
export function truncateWellFormed(text: string, maxUnits: number): string {
  const cut = text.slice(0, maxUnits);
  return /[\uD800-\uDBFF]$/.test(cut) ? cut.slice(0, -1) : cut;
}
```
(Regex has no `u` flag on purpose: it must match individual code units.)
**Tests (`well-formed-text.test.ts`):**
- `toWellFormedText('a\uD83Eb')` returns `'a�b'`; `toWellFormedText('a\uDC00')` returns `'a�'`; `toWellFormedText('ok 🛠️')` returns the input unchanged.
- `truncateWellFormed('x'.repeat(199) + '🛠rest', 200)` returns `'x'.repeat(199)` (length 199); `truncateWellFormed('abc', 200)` returns `'abc'`; `truncateWellFormed('x'.repeat(198) + '🛠rest', 200)` keeps the full emoji (length 200).

/**

    super(`Agent ${agentId} kickoff rejected by the terminal backend: ${failure}`);

  return typeof failure === 'string' && failure.startsWith('invalid_request:');
}

export function isKickoffRejection(error: unknown): error is KickoffRejectedError {
  return error instanceof Error && error.name === 'KickoffRejectedError';
}
