# PAN-2257: Issue tree troubled badge

## Glossary

- Troubled gate: an agent state flag (`troubled: true`) that blocks start/resume paths and causes stopped or suspended message delivery to queue mail instead of reaching the agent live.
- Troubled reason: the agent failure reason currently stored as `lastFailureReason`; the frontend issue calls this `troubledReason`, but no separate field exists today.
- Failure count: `consecutiveFailures` from agent state.
- Troubled timestamp: `troubledAt` from agent state.
- Queued deliveries: pending message files in an agent state's `mail/` directory.
- Issue tree: the Command Deck project tree feature row rendered by `src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureItem.tsx`.

## Requirements

- FR-1: Command Deck issue-tree rows render a warning-semantic troubled badge for troubled agent sessions.
- FR-2: Hover/click surfaces troubled reason, failure count, and troubled timestamp; a troubled session with zero failures is called out as likely spurious.
- FR-3: The troubled badge clears the existing troubled gate in one click using the existing untroubled route/action semantics.
- FR-4: While troubled, the badge shows queued-deliveries count alongside the troubled signal.
- NFR-1: Browser verification for the tree row must use an isolated Playwright browser/profile.
- NFR-2: The implementation must not add new troubled-clear backend semantics; it reuses `POST /api/agents/:id/untroubled`.

## Verified References

- `packages/contracts/src/types.ts` defines `AgentSnapshot` with `troubled`, `troubledAt`, `consecutiveFailures`, and `lastFailureReason`, while `SessionNode` currently has pause fields but no troubled fields.
- `src/dashboard/server/routes/projects.ts` builds Command Deck session-tree nodes in `collectSessionTreeNodes()` and currently forwards pause fields only.
- `src/lib/agents/messaging.ts` queues undelivered messages into `getAgentDir(agentId)/mail/*.md`.
- `src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureItem.tsx` renders issue-tree aggregate badges and the paused one-click action.
- `src/dashboard/frontend/src/components/IssueActionMenu/useIssueActions.ts` reuses `POST /api/agents/:agentId/untroubled`, but its current agent selection is issue-level and can target the wrong agent when a troubled slot session exists.
- `src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureItem.test.tsx` is the focused test file for Command Deck issue-tree row behavior.

## Decisions

- Extend `SessionNode` rather than deriving the badge only from the global agents store, because the issue tree is already session-tree driven and must represent slot sessions such as `agent-pan-2222-slot-1`.
- Treat `lastFailureReason` as the displayed troubled reason unless a future state field named `troubledReason` exists.
- Count queued deliveries as `.md` files in the agent `mail/` directory, using `0` when the directory is absent or unreadable.
- Render troubled as a warning/amber gate, not destructive red, because the operator action is investigative/clear-gate rather than a data loss or failed-review state.
- Make the badge target the specific troubled `sessionId`; do not rely on issue-level active-agent selection for slot agents.

## Non-Goals

- Do not change `pan tell` queueing behavior; that is related PAN-2255.
- Do not drain queued mail on spawn; that is related PAN-2255.
- Do not introduce bulk clear-all-troubled semantics for multiple sessions.
- Do not change the existing untroubled API route or backend state-clearing behavior beyond session-tree metadata exposure.
- Do not redesign Command Deck tree layout or replace existing action-menu behavior.
