# PAN-4224: Primary main keeps diverging after plan-artifact pushes

**Issue:** https://github.com/eltmon/overdeck/issues/4224
**Sibling (split out during planning):** https://github.com/eltmon/overdeck/issues/4225 covers the continue/spec writers that still write into the primary checkout.

## Glossary

- **Primary checkout.** The operator's main clone at `<project>` (for Overdeck, `/home/eltmon/Projects/overdeck`), checked out on `main`. It is the **plan home** for project-level artifacts.
- **Plan home.** The checkout that holds `.pan/`. `resolvePlanHome(p)` (`src/lib/pan-dir/paths.ts:46`) returns the issue workspace when `p` is inside `<project>/workspaces/<name>/`. Otherwise it returns the primary checkout. For a polyrepo project it returns the `pan_records.repo` sub-repo of that checkout.
- **Workspace plan home.** `resolvePlanHome(<project>/workspaces/feature-<issue>)`: the issue's feature-branch worktree (or its plan-home sub-repo).
- **Plan-artifact push.** `pushPlanArtifacts(cwd)` in `src/lib/overdeck/plan-artifact-commit.ts:122`. `pan backlog write-sequence` (`src/cli/index.ts:304`) and the `pan orders` write verbs (`src/cli/commands/orders.ts:76`) call it after they commit `.pan/backlog/` or `.pan/orders/` on `main` in the primary checkout.
- **Replay.** When origin has moved, the push rebuilds each local plan-artifact commit on top of the fetched upstream with `git merge-tree --write-tree` + `git commit-tree`. It never touches the working tree. Then it pushes the rebuilt tip.
- **Follow.** After the replayed tip lands on origin, the push moves local `main` onto it with `git reset --keep <tip>`.
- **Landed commit.** A local commit whose change is already on the upstream, usually because an earlier push replayed it. `git rev-list --cherry-pick --right-only <onto>...<head>` omits landed commits (patch-id equivalence).
- **Colliding untracked file.** An untracked file under `.pan/` in the plan home whose path the follow would create, because the path is added between `HEAD` and the pushed tip.
- **Backup root.** `<planHome>/.overdeck/plan-artifact-backups/`. It holds a `.gitignore` containing `*`, so git ignores the root and everything under it in any repo. Each follow that displaces files makes a `<backupRoot>/<stamp>/` directory. `<stamp>` is `new Date().toISOString().replace(/[:.]/g, '-')`.
- **Activity entry.** An `activity.entry` domain event. It shows in the dashboard activity feed. A short-lived CLI emits it with `emitActivityEntryOncePortable` (`src/lib/activity-logger.ts:227`), which posts to the dashboard's settled internal event endpoint. It returns `'failed'` when the dashboard is down.

## Problem

On 2026-09-26 the primary checkout had 7 local `chore(workspace): backlog sequence` commits that diverged from `origin/main`. The backup is branch `backup/primary-main-2026-09-26`. The failure chain, verified against origin's history:

1. `PAN-4200 (#4214)` merged at 20:33 and added `.pan/continues/PAN-4200.xbrief.json`. The primary checkout already held an **untracked** copy of that path.
2. At 20:35:50 a sequence write committed `c8353dd7faa` locally. The push replayed it as `34411afe5f9` and pushed it. Then `reset --keep` refused: `Untracked working tree file '.pan/continues/PAN-4200.xbrief.json' would be overwritten`. Local `main` kept `c8353dd7faa`.
3. The next write (20:36:48) replayed **both** local commits. `c8353dd7faa` was already on origin, so its replay produced **empty** commit `a4ae61d3bf7` (author time 20:35:50, commit time 20:36:51, 0 files). The later local commits `f3080c6ef94`, `395375877f9`, and `bc1f4664fd5` never reached origin. Replaying stale commits over newer upstream sequence content conflicted, so those pushes were refused.
4. Each later write added one more local commit. Local `main` drifted further, and the warning only went to the CLI's stderr.

There are two root causes and one design gap:

- **R1 (follow).** `pushPlanArtifacts` does not handle untracked `.pan/` files that the incoming tip adds (`plan-artifact-commit.ts:208`).
- **R2 (replay).** `pushPlanArtifacts` replays every commit in `onto..head`, including landed ones (`plan-artifact-commit.ts:151`, `:177`). After one failed follow, each later push either adds an empty duplicate or conflicts.
- **R3 (hygiene).** Complete-planning promotes the workspace PRD draft into the **primary** checkout and deletes the workspace copy (`planning-promotion.ts:673` passes `projectRoot: projectPath`; `drafts.ts:286-290`). The draft is left untracked in the primary and **missing from the feature branch**. PAN-4200's PR carried its continue file but no draft. The planning prompt (`spawn-planning-session.ts:269`) and the finalize gate message (`plan-finalize.ts:173`, `:216`) also point agents at the primary path.

At the time of writing the primary checkout held untracked drafts for #4197, #4198, #4199, #4200, #4210, #4211, #4212, #4221, and #4222. It also held untracked continues for PAN-3956, PAN-4198, and PAN-4199. The continue writers are PAN-4225's scope (see Non-goals).

## Requirements

### Functional

- **FR-1.** `pushPlanArtifacts` replays only local commits that are not already on the upstream (`--cherry-pick --right-only --no-merges`). It never creates a commit whose tree equals its parent's tree.
- **FR-2.** When every local commit is already on the upstream, `pushPlanArtifacts` pushes nothing. It moves the branch onto the upstream (self-heal) and reports that it did so.
- **FR-3.** Before the follow, `pushPlanArtifacts` sets aside every colliding untracked `.pan/` file. After a successful follow it deletes the set-aside copies that are byte-identical to the incoming blob and keeps the others under the backup root. If the follow still fails, it moves every set-aside file back to its original path.
- **FR-4.** The result of `pushPlanArtifacts` lists every kept backup as `{ path, backup }`: the plan-home-relative path and the absolute backup path.
- **FR-5.** `pushPlanArtifacts` refuses (without pushing) when `<onto>..<head>` contains a merge commit, and it names the reason.
- **FR-6.** `pan backlog write-sequence` and every `pan orders` write verb emit a `warn` activity entry to the dashboard when the push reports a problem (a non-skipped failure, a `warning`, or kept backups). They still print the same line to stderr.
- **FR-7.** Complete-planning promotes the PRD draft into the **workspace plan home**, so the planning commit (`git add .pan/`) carries it on the feature branch. A draft that exists only in the primary checkout is **copied** into the workspace plan home, and the primary copy stays in place.
- **FR-8.** The planning prompt's PRD reference and the PRD-first gate failure message name the workspace plan-home path. The prompt falls back to the primary path only when the draft exists only there.

### Non-functional

- **NFR-1.** Async `execFile` only. This module is reachable from the dashboard server, so it must never use `execSync` or a shell string.
- **NFR-2.** Never `git stash` (universal rule). Never force-push. Never skip hooks. Never throw from `pushPlanArtifacts`: every failure becomes a result.
- **NFR-3.** No untracked file content is lost. Every displaced non-identical file survives under the backup root, and every displaced file is restored when the follow fails.
- **NFR-4.** Tests for git behavior use real temporary repositories (the existing harness). No new test sleeps on real timers.

## Decisions

- **D1. Split the continue/spec writers into PAN-4225.** The census found about 10 writers across cloister, lifecycle, CLI start/scope, and swarm that pass the primary root. Readers such as `handoff-context.ts:124` and `test-skip-waiver.ts:47` also read the primary copy, so moving only the writes would break feedback delivery. That redesign exceeds this issue's size limit (more than 6 subsystems). This issue fixes the push, which makes any such collision survivable, and fixes the draft writer that the issue body names.
- **D2. Only untracked collisions are cleared.** A tracked `.pan/` file with a local modification that the incoming tip also changes still makes `reset --keep` refuse. That refusal now reaches the dashboard (FR-6) with the path named. Discarding an operator's working-tree edit is not authorized by the issue.
- **D3. Backup location.** `<planHome>/.overdeck/plan-artifact-backups/<stamp>/<original relative path>`. The root gets a `.gitignore` with `*` on first use. `.overdeck/` is not wholly ignored in every plan home (Overdeck tracks `.overdeck/context/codebase/`), so the self-ignoring root keeps backups out of `git status` in any repo.
- **D4. Identical means same blob id.** "Identical" is `git hash-object <file>` equal to `git rev-parse <tip>:<path>`.
- **D5. The activity helper lives in a new module** `src/lib/overdeck/plan-artifact-push-report.ts`. This keeps `plan-artifact-commit.ts` free of the dashboard client. The new `ActivitySource` member is `'plan-artifacts'`.
- **D6. Activity ids are deterministic** so a repeated identical failure does not spam the feed: `plan-artifact-push:<first 12 hex of sha1(planHome + "\n" + message)>`.
- **D7. Draft promotion target.** Pass the **workspace path** as the promotion root. For a normal project, the workspace-authored draft already sits in the target directory, so promotion reports `canonical-exists` and leaves it in place for the planning commit. This is correct: the draft is now in the plan home that ships.

### WI-2: Clear colliding untracked `.pan/` files before the follow (FR-3, FR-4)

File: `src/lib/overdeck/plan-artifact-commit.ts`.

1. Extend the success variant of `PushPlanArtifactsResult` with `readonly backedUp?: readonly { readonly path: string; readonly backup: string }[]`. Add the same optional field to the `skipped: true` variant, for FR-2.
2. Add a non-exported `async function followTip(cwd, branch, head, tip): Promise<{ ok: true; backedUp: {path; backup}[] } | { ok: false; reason: string }>`. It replaces lines 200-216 and runs these steps:
   1. If `rev-parse HEAD !== head`, return `ok: false` with `<branch> moved meanwhile` (the same text as today).
   2. `added = git diff --name-only --no-renames --diff-filter=A -z HEAD <tip> -- .pan/`
   3. `untracked = git ls-files --others --exclude-standard -z -- .pan/`
   4. `collisions = added ∩ untracked`.

   6. Run `git reset --quiet --keep <tip>`.
   7. On success, `rm` the backups whose content was identical, then remove the `<stamp>` directory if it is empty (`rm` with `recursive: true` only after checking that `readdir` returns `[]`). Return `ok: true` with the non-identical ones as `backedUp`.
   8. On failure, `rename` every backup back to its original path, then return `ok: false` with the first line of the error.

On `ok: false` it returns `{ pushed: true, sha: tip, rebased: true, warning: 'pushed, but could not move <branch> onto the pushed commits (<reason>); run git pull --rebase in <cwd>' }`, which keeps today's text. ## Intersecting repo rules (restated)

- Async git only: use `execFile` via `promisify`. Never use `execSync` in server-reachable code.
- Agents never run `git stash`. Set files aside with `fs.rename`.
- Never force-push. Never pass `--no-verify` to the push.
- Tests exercise real temporary git repos. Use no real-timer sleeps. If a test needs time, use fake timers.
- Quality gates: `npm run typecheck`, `npm run lint`, and `npx vitest run <touched test files>`. Never run the full `npm test` locally.
- `scripts/lint-file-size.sh` ratchet: `plan-artifact-commit.ts` is 218 lines. If it grows past the god-file threshold, add an allowlist row as the lint instructs.

## Non-goals

- Moving the continue/spec/feedback/slot writers and readers off the primary checkout (PAN-4225).
- Clearing **tracked** `.pan/` files with local modifications that block the follow. They produce a surfaced warning instead (D2).
- A one-time cleanup of the untracked files that already sit in the primary checkout. The robust follow handles each one when it collides.
- Any change to how `commitPlanArtifacts` stages or commits.
- A persistent "diverged" badge in the workspace UI.
