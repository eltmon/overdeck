## Data wiring (read doors only)

- Crew roster + states: agents under the issue from the read model /
  `resource-discovery` (slot agents by `agent-<issue>-slot-N`, supervisor by
  `supervisor` id from `supervisorAgentId(issueId)`); state mapping: session
  alive + recent output → working; alive + idle → listening; supervisor alive →
  reviewing when inspect in flight; dead/done → faded. Tier names/models via
  `resolveStaffing`-consistent data already in slot assignments + spec items.
- Costs per member: `/api/costs/by-issue` per-model stats (NOTE: correctness
  depends on PAN-2387/2388 — render what the aggregator returns; do NOT
  hand-compute a parallel rollup; the invariant test lives in PAN-2393).
- Feed events: existing domain events (`agent.*`, supervisor verdicts via
  review events, bead done via `plan.item_status_changed`) → humanize into
  sentences (mapping table in HappenedFeed.tsx; NO raw event names in copy).
- Perspective drawer: last-N transcript lines from the member's conversation
  (existing conversation parse service endpoints); commit-feed deliveries show
  as "◀ commit <short> received" lines once PAN-2385 ignition emits them.
- DAG: merged plan view (`GET /api/workspaces/:issueId/plan`) — statuses from
  statusOverrides overlay.

## Non-technical copy rules (binding)

Narrative formula: "<who> is <plain verb> — <n> of <m> tasks done" + "Up next:
<plain next step>." + "Nothing needs you yet." / needs-you banner otherwise.
Stage glosses: Planned/what to build · Building/n-m tasks · Reviewing/quality
check · Testing/does it work · Shipping/merge to main. Never render: pickup,
released, verification gate, merge-ready, readyForMerge, vBRIEF.
