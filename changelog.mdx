Overdeck ships to npm as [`@overdeck/core`](https://www.npmjs.com/package/@overdeck/core). Install or upgrade with `npm install -g @overdeck/core@latest`, then run `pan install` so the terminal backend and synced skills match the new version.

This page starts at v0.60.0, the release that removed Overdeck's state layer. Older releases are listed on [GitHub Releases](https://github.com/eltmon/overdeck/releases).

<Update label="v0.74.0" description="2026-11-04">
  #### New

  - **Overdeck MCP for agents and bots:** every managed agent now gets Overdeck's own tools over MCP, so it can check off its plan, signal done, hand off, delegate to a worker or lane, start an issue, schedule a message, read and add memory, link and watch pull requests, ask you for a secret, and ask you to link a machine, without shelling out to `pan`. Claude Code, Codex and the ACP harnesses get the server injected automatically; harnesses without MCP get a short CLI instructions block instead. Agent tokens are minted per agent and revoked when it ends, and approvals for every harness collect in one fleet-wide pending list. See [Overdeck MCP](/configuration/mcp) and [`pan mcp`](/cli/mcp). ([#4968](https://github.com/eltmon/overdeck/pull/4968), [#4967](https://github.com/eltmon/overdeck/pull/4967), [#4978](https://github.com/eltmon/overdeck/pull/4978), [#4983](https://github.com/eltmon/overdeck/pull/4983), [#4982](https://github.com/eltmon/overdeck/pull/4982), [#4997](https://github.com/eltmon/overdeck/pull/4997), [#4975](https://github.com/eltmon/overdeck/pull/4975), [#4984](https://github.com/eltmon/overdeck/pull/4984), [#4985](https://github.com/eltmon/overdeck/pull/4985), [#4974](https://github.com/eltmon/overdeck/pull/4974), [#4989](https://github.com/eltmon/overdeck/pull/4989), [#4981](https://github.com/eltmon/overdeck/pull/4981), [#4991](https://github.com/eltmon/overdeck/pull/4991), [#4992](https://github.com/eltmon/overdeck/pull/4992), [#4977](https://github.com/eltmon/overdeck/pull/4977))
  - **Connect your own bots:** Settings → Anywhere → **Connect a bot** links Hermes, OpenClaw, Grok Build or a Grok bot (through the xAI API) to your fleet. A bot signs in with OAuth 2.1 and you approve it on an approval card, or it reaches your machines through `pan mcp connector` and the overdeck.ai directory. An opt-in public `/mcp` endpoint over Tailscale Funnel is available for bots that run elsewhere. Plugin source for each bot is in `integrations/`. See [Bots](/configuration/bots). ([#4979](https://github.com/eltmon/overdeck/pull/4979), [#4986](https://github.com/eltmon/overdeck/pull/4986), [#4990](https://github.com/eltmon/overdeck/pull/4990), [#4988](https://github.com/eltmon/overdeck/pull/4988), [#4980](https://github.com/eltmon/overdeck/pull/4980), [#5014](https://github.com/eltmon/overdeck/pull/5014), [#4966](https://github.com/eltmon/overdeck/pull/4966), [#5030](https://github.com/eltmon/overdeck/pull/5030), [#5035](https://github.com/eltmon/overdeck/pull/5035), [#5032](https://github.com/eltmon/overdeck/pull/5032), [#4996](https://github.com/eltmon/overdeck/pull/4996), [#4965](https://github.com/eltmon/overdeck/pull/4965), [#5040](https://github.com/eltmon/overdeck/pull/5040), [#5052](https://github.com/eltmon/overdeck/pull/5052))
  - **Native phone apps for iOS and Android:** an Overdeck app for iPhone and Android pairs with your machine by QR code (Settings → Anywhere → **Set up the phone app**) and talks to it over the same end-to-end encrypted channel as linked machines. It shows Needs you and your conversations grouped by project, answers questions, starts new conversations, and follows System, Light or Dark appearance. Push notifications are sealed to each phone, so Apple, Google and overdeck.ai cannot read them, and you can pause them or choose which kinds you get. On iPhone a Live Activity shows your counts. The apps are in TestFlight and Play internal testing now. See [Phone app](/configuration/phone). ([#4923](https://github.com/eltmon/overdeck/pull/4923), [#4883](https://github.com/eltmon/overdeck/pull/4883), [#4891](https://github.com/eltmon/overdeck/pull/4891), [#4894](https://github.com/eltmon/overdeck/pull/4894), [#4902](https://github.com/eltmon/overdeck/pull/4902), [#4898](https://github.com/eltmon/overdeck/pull/4898), [#4899](https://github.com/eltmon/overdeck/pull/4899), [#4900](https://github.com/eltmon/overdeck/pull/4900), [#4877](https://github.com/eltmon/overdeck/pull/4877), [#4962](https://github.com/eltmon/overdeck/pull/4962), [#5051](https://github.com/eltmon/overdeck/pull/5051), [#4964](https://github.com/eltmon/overdeck/pull/4964), [#5044](https://github.com/eltmon/overdeck/pull/5044), [#5031](https://github.com/eltmon/overdeck/pull/5031), [#5047](https://github.com/eltmon/overdeck/pull/5047), [#5050](https://github.com/eltmon/overdeck/pull/5050))

Peers connect over WebRTC with a TURN fallback, and the host reconnects and viewers restore on their own. See [Shared Sessions](/configuration/shared-sessions) and [`pan share`](/cli/share). ([#4880](https://github.com/eltmon/overdeck/pull/4880), [#4889](https://github.com/eltmon/overdeck/pull/4889), [#4895](https://github.com/eltmon/overdeck/pull/4895), [#4912](https://github.com/eltmon/overdeck/pull/4912), [#4913](https://github.com/eltmon/overdeck/pull/4913), [#4919](https://github.com/eltmon/overdeck/pull/4919), [#4911](https://github.com/eltmon/overdeck/pull/4911), [#4915](https://github.com/eltmon/overdeck/pull/4915), [#4916](https://github.com/eltmon/overdeck/pull/4916), [#4972](https://github.com/eltmon/overdeck/pull/4972))

  - **Restart hold:** `pan restart hold --reason "…"` stops every `pan reload` and dashboard restart, from any conversation, until `pan restart release` or its `--until` time. Use it during a live test that a restart would interrupt. ([#5056](https://github.com/eltmon/overdeck/pull/5056))
  - **SageOx and Deft:** try SageOx in a project without committing it, with an Overdeck-built `ox` and Codex support; and a per-issue Deft Directive with its state in the dashboard and a **Run on Deft** switch. ([#4893](https://github.com/eltmon/overdeck/pull/4893), [#4879](https://github.com/eltmon/overdeck/pull/4879))

  #### Improved

  - **The merge train explains itself:** when it skips a PR it now says why (checks pending at a given commit, a failed PR listing, a conflict) in the pending list and the logs, instead of skipping silently. The PR listing it reads is lighter and logs its failures, and per-PR auto-merge no longer races UAT batch generations. ([#5039](https://github.com/eltmon/overdeck/pull/5039), [#5053](https://github.com/eltmon/overdeck/pull/5053), [#4976](https://github.com/eltmon/overdeck/pull/4976))
  - **Fewer stuck reviews and merges:** a review approval that hits a temporary GitHub error is saved and retried instead of lost; the review-convergence check judges only the rounds since the last approval; the merge step no longer rebases away a conflict the branch already resolved; and a reviewer's verdicts are ranked by review order, not by timestamp. ([#5037](https://github.com/eltmon/overdeck/pull/5037), [#4994](https://github.com/eltmon/overdeck/pull/4994), [#5038](https://github.com/eltmon/overdeck/pull/5038), [#4707](https://github.com/eltmon/overdeck/pull/4707), [#4701](https://github.com/eltmon/overdeck/pull/4701))
  - **Fewer merge conflicts between parallel PRs:** the codebase notes' `last-verified` line holds only a date, and the phone app's acceptance log merges both sides automatically. ([#5025](https://github.com/eltmon/overdeck/pull/5025), [#5055](https://github.com/eltmon/overdeck/pull/5055))
  - **Disk-aware starts:** concurrent workspace starts reserve disk space up front, so several starts at once can no longer run the disk out. Agent scratch files live under `~/.overdeck/tmp` with a 14-day cleanup, so a reboot no longer deletes them. ([#4973](https://github.com/eltmon/overdeck/pull/4973), [#5009](https://github.com/eltmon/overdeck/pull/5009))
  - **`pan tell` accepts a conversation's bare name**, and `pan lane start --machine auto` says why it picked this machine. ([#5004](https://github.com/eltmon/overdeck/pull/5004), [#5024](https://github.com/eltmon/overdeck/pull/5024))
  - **Telemetry:** PostHog now covers the phone apps and Anywhere desktop events. ([#5027](https://github.com/eltmon/overdeck/pull/5027))

([#5008](https://github.com/eltmon/overdeck/pull/5008), [#5017](https://github.com/eltmon/overdeck/pull/5017), [#5023](https://github.com/eltmon/overdeck/pull/5023), [#4921](https://github.com/eltmon/overdeck/pull/4921), [#4901](https://github.com/eltmon/overdeck/pull/4901), [#4987](https://github.com/eltmon/overdeck/pull/4987))

<Update label="v0.73.0" description="2026-11-03">
  #### New

  - **Overdeck Anywhere:** each of your machines runs its own Overdeck, and the machines now link to each other, so you can see, control and move conversations and work between them from any one dashboard. Everything that runs on your own machines is free and open source. The hosted overdeck.ai services are optional, invite-only for now, and their source is in `services/` under the Functional Source License. See [Overdeck Anywhere](/anywhere) and [Linked machines](/configuration/linked-machines).
    - **Linked machines:** run `pan pair` on one machine and `pan machines link <url>` on the other, and the two dashboards talk server to server over an end-to-end encrypted channel. Your browser still talks only to the machine it opened. A link learns every route to the other machine (LAN, Tailscale, direct, relay or SSH), uses one that answers, and reports the other machine's health. **Link both ways** is the default. ([#4715](https://github.com/eltmon/overdeck/pull/4715))
    - **overdeck.ai sign-in and directory:** `pan account login` signs a machine in to account.overdeck.ai with GitHub's device flow, and `pan account status` and `pan account logout` complete the group. A signed-in machine registers in the connect.overdeck.ai directory, which lists your machines in Settings → Anywhere → Directory (or `pan machines directory`). Link two of them without a pairing code by two-screen approval: both screens show the same six-digit code, and you approve only if the codes match. The free account includes 3 machines. ([#4691](https://github.com/eltmon/overdeck/pull/4691), [#4726](https://github.com/eltmon/overdeck/pull/4726))
    - **Direct and relay routes:** when no LAN or Tailscale route answers, linked machines open a peer-to-peer WebRTC path through the directory and show it as `direct`. When no direct path exists, the relay add-on carries the same encrypted channel through a TURN relay, with a 50 GB monthly allowance per account, and the status card shows **Using relay**. The relay tries TURN over TLS and TCP first, so it can connect when UDP is blocked. ([#4726](https://github.com/eltmon/overdeck/pull/4726), [#4868](https://github.com/eltmon/overdeck/pull/4868))
    - **SSH machines:** Settings → Anywhere → **Add an SSH machine** (or `pan machines add-ssh`) starts `pan up` on an SSH host, or adopts one already running, and links it. Removing a machine that Overdeck started stops its server; a server you started yourself keeps running. ([#4720](https://github.com/eltmon/overdeck/pull/4720), [#4866](https://github.com/eltmon/overdeck/pull/4866))
    - **`pan connect`:** `npx @overdeck/core connect` on a fresh server installs a lasting runtime, runs Overdeck as a systemd user service (or a launch agent on macOS) that survives logout and reboot, and prints the link to use on your main machine. **Update all** and `pan update` update that runtime. ([#4718](https://github.com/eltmon/overdeck/pull/4718), [#4824](https://github.com/eltmon/overdeck/pull/4824))
    - **Fly VMs as machines:** `pan machines add-fly` starts a Fly.io VM that runs Overdeck, links it, and can start a conversation there; unlinking destroys the VM. Choose **Fly (new VM)** in the Machine field or pass `--machine fly`, and set `remote.auto_fly` to let **Auto** create one. `pan start <id> --remote` now runs the work agent as a linked conversation on the VM's server. `pan machines add-fly --harness codex` runs Codex on the VM and keeps its ChatGPT sign-in in sync. You pay Fly directly. Fixes found while testing Fly machines are included. ([#4742](https://github.com/eltmon/overdeck/pull/4742), [#4818](https://github.com/eltmon/overdeck/pull/4818), [#4850](https://github.com/eltmon/overdeck/pull/4850), [#4749](https://github.com/eltmon/overdeck/pull/4749), [#4797](https://github.com/eltmon/overdeck/pull/4797), [#4807](https://github.com/eltmon/overdeck/pull/4807), [#4812](https://github.com/eltmon/overdeck/pull/4812), [#4815](https://github.com/eltmon/overdeck/pull/4815))
    - **Conversations across machines:** one conversation list shows the conversations on every linked machine. Open and control a conversation on another machine, message it with `pan tell @<label>/<conv>`, or choose **Pull here** (`pan conv pull`) to move it to this machine with its uncommitted changes; the old copy then refuses new turns. **Open preview** and `pan machines forward` reach a dev server on the other machine. **Open in editor** opens the owner's checkout in VS Code over Remote-SSH, through a Tailscale route or an SSH machine. ([#4731](https://github.com/eltmon/overdeck/pull/4731), [#4867](https://github.com/eltmon/overdeck/pull/4867))
    - **Work across machines:** the Machine field, `--machine <label>` and `--machine auto` choose where a conversation, worker or issue runs. **Auto** avoids a machine whose CPU is saturated, and `--needs docker` picks a machine that has Docker. `pan worker run --machine` delegates to another machine, and Needs you, usage and **Compare settings** cover the whole fleet. `pan lane start --machine` runs gauntlet lanes on any linked machine, nested under the orchestrating conversation at home. ([#4744](https://github.com/eltmon/overdeck/pull/4744), [#4758](https://github.com/eltmon/overdeck/pull/4758))
    - **Fleet versions and Update all:** Settings → Anywhere → Fleet versions (or `pan machines versions`) lists the Overdeck and harness CLI versions on every machine. **Update all** (`pan machines update`) updates them and waits for running turns to finish first. ([#4719](https://github.com/eltmon/overdeck/pull/4719))
    - **Phone app and push notifications:** the dashboard installs on a phone as a web app at `/m`, reached over Tailscale Serve. It shows Needs you, your conversations and a read-only pipeline board, and answers an agent's question in three taps. Settings → Anywhere → **Set up a phone** pairs it. Your machine sends Needs-you notifications itself with Web Push, encrypted so the push service cannot read them, with an optional ntfy topic. ([#4693](https://github.com/eltmon/overdeck/pull/4693), [#4784](https://github.com/eltmon/overdeck/pull/4784), [#4688](https://github.com/eltmon/overdeck/pull/4688))
    - **Set up Tailscale:** Settings → Anywhere → **Set up Tailscale** (or `pan tailscale setup`) installs Tailscale, signs in, serves the dashboard over HTTPS with token sign-in required, and finds other Overdeck machines on your tailnet. `pan tailscale status` shows the current state. ([#4706](https://github.com/eltmon/overdeck/pull/4706))
    - **Webhook triggers:** `pan triggers` (or Settings → Anywhere → Triggers) creates a secret URL that messages a conversation or starts a new one when GitHub, Stripe, CI or a chat bot posts to it. GitHub and Stripe signatures are checked. Events reach the machine through Tailscale Funnel, or the directory's webhook inbox holds them for 24 hours while the machine is offline. ([#4700](https://github.com/eltmon/overdeck/pull/4700), [#4726](https://github.com/eltmon/overdeck/pull/4726))
    - **MCP server:** `pan mcp serve` (stdio) and the `/mcp` endpoint let an MCP client list and read conversations, send messages, start conversations and workers, and answer waiting questions, limited to what its token's scopes allow. **Copy MCP URL** in Settings → Anywhere mints a scoped token and copies the URL. ([#4699](https://github.com/eltmon/overdeck/pull/4699))
    - **Desktop app without a local server:** the desktop app can open a chosen machine's dashboard instead of starting its own server, and its menu and tray switch between machines. ([#4665](https://github.com/eltmon/overdeck/pull/4665))
    - **Pipeline transcripts in the Session Vault:** finished pipeline agents' transcripts are saved to the Session Vault automatically, so your other machines can open them. ([#4664](https://github.com/eltmon/overdeck/pull/4664))
    - **Known limitations:** three parts of Anywhere were not verified end to end before release. The **Set up Tailscale** step has not been run on a real machine. Running `npx @overdeck/core connect` as a systemd service on a fresh VPS has not been tested on a real VPS ([#4863](https://github.com/eltmon/overdeck/issues/4863)). The relay's TURN-over-TCP fallback for networks that block UDP is covered by tests but has not yet connected on a live Fly VM. The release acceptance run is in [`docs/ANYWHERE-RELEASE-CHECKLIST.md`](https://github.com/eltmon/overdeck/blob/main/docs/ANYWHERE-RELEASE-CHECKLIST.md). ([#4864](https://github.com/eltmon/overdeck/pull/4864))
  - **Deft pipeline per issue:** `pan skills deft use <ISSUE>` runs one issue on Deft Directive's own pipeline. Overdeck installs Directive into that issue's worktree and hides every installed file from git, so the PR never carries it. The work agent gets Deft's build, pre-PR and review-cycle skills, and Overdeck runs no review, test or verification agents for that issue. The merge gate waives approval at head for a Deft issue, refuses a PR that carries install files or a stale Deft state archive, and auto-merge holds an issue whose Deft policy requires a human merge. `pan skills deft save|show|back <ISSUE>` commits the state archive, shows the install and merge-guard verdict, and switches the issue back to Overdeck's pipeline. ([#4857](https://github.com/eltmon/overdeck/pull/4857))
  - **gstack skill pack:** `pan skills pack add gstack` adds gstack from the `eltmon/gstack` fork. Overdeck renders its skills and runtime under `~/.overdeck/packs/gstack/` and never writes `~/.claude` or `~/.gstack`. The consent preview lists the render command, every script the mounted skills can run and the skills left unmounted. Turn the pack on at global, project or issue level. `pan skills pack browser gstack` builds gstack's browser, design and PDF runtime after a second consent, so skills such as qa, browse and make-pdf can mount. `pan skills pack remove gstack` removes every mount it made. ([#4735](https://github.com/eltmon/overdeck/pull/4735), [#4745](https://github.com/eltmon/overdeck/pull/4745))
  - **pstack skill pack:** `pan skills pack add pstack` registers poteto's pstack from the `eltmon/plugins` fork (Cursor's Claude Code build, 58 skills, 7 opt-in). Turn it on with `pan skills set --pack pstack on [--project <key>|--issue <id>]` and invoke skills as `/pstack:<name>`. Known packs no longer need a url in `pan skills pack add`. ([#4728](https://github.com/eltmon/overdeck/issues/4728))
  - **Color themes, including VS Code themes:** Settings → Appearance has separate light and dark color themes, with built-in themes. **Import VS Code theme** reads a theme `.json` file or a `.vsix` extension package and previews it before you save. The theme also colors terminals and code blocks. **Duplicate and edit** copies a theme into an editor with color pickers and a live preview. ([#4689](https://github.com/eltmon/overdeck/pull/4689), [#4806](https://github.com/eltmon/overdeck/pull/4806), [#4809](https://github.com/eltmon/overdeck/pull/4809))
  - **Scheduled conversations:** a schedule sends a stored prompt to a conversation on a recurring timetable, for example every evening at 21:00. Manage schedules with `pan conv schedule add|list|pause|resume|rm`, or choose **Schedule…** from a conversation's row or tab menu. A row with an active schedule shows a next-run badge, and a delivered run moves the conversation back to Inbox. ([#4668](https://github.com/eltmon/overdeck/pull/4668), [#4800](https://github.com/eltmon/overdeck/pull/4800))
  - **Send a message when rate limits reset:** when a conversation has hit its usage limit, choose **Send when limits reset** in the composer, or run `pan tell --when-limit-resets`, and Overdeck delivers the message once the limit resets. Queued messages show in the timeline with Edit and Cancel, and `pan conv pending <conv>` lists them. ([#4686](https://github.com/eltmon/overdeck/pull/4686))
  - **Settle and snooze conversations:** the conversation list is now split into Needs you, Inbox, Snoozed and Settled. Settle a conversation to mark it done for now without stopping it, or snooze it until a chosen time. Every action has Undo, and a bulk bar acts on several rows at once. Conversations settle themselves after 3 days with no activity; change or turn this off in Settings → Conversations or with `pan conv auto-settle-idle-days <days>` (`0` turns it off). ([#4709](https://github.com/eltmon/overdeck/pull/4709), [#4793](https://github.com/eltmon/overdeck/pull/4793))
  - **Cite selected text:** select text in an agent's reply, or in a markdown preview in the editor pane, click **Cite**, add a comment, and the quote goes out with your next prompt. ([#4667](https://github.com/eltmon/overdeck/pull/4667), [#4795](https://github.com/eltmon/overdeck/pull/4795))
  - **`pan diagnose`:** collects a redacted diagnostic bundle and, after you confirm, starts Claude Code or Codex in it to find and fix the problem. It works when the dashboard, the supervisor or Herdr is down. `pan doctor --json` is new as well. ([#4676](https://github.com/eltmon/overdeck/pull/4676))
  - **Open file links in a browser:** right-clicking a file link offers **Open in browser** and an item for each browser installed on this machine. ([#4765](https://github.com/eltmon/overdeck/pull/4765))
  - **New models:** Kimi K3.1 Pro and K3.1 Pro Highspeed on the Claude Code, Kimi Code CLI and ACP routes; Highspeed needs a Kimi Code Allegretto (Pro) plan or higher. <Update label="v0.60.0" description="2026-09-23">
  ## The Cut

  Overdeck no longer keeps its own copy of pipeline state. Where an issue stands is read live from git, the issue tracker, the pull request and the terminal backend, so the dashboard can no longer drift from reality. Every feature stays; only the state layer is gone. [docs/THE-CUT.md](https://github.com/eltmon/overdeck/blob/main/docs/THE-CUT.md) maps each removed piece to its new home. ([#3917](https://github.com/eltmon/overdeck/issues/3917))

  What this changes for you:

  - **Herdr is the default terminal backend.** `pan install`, `pan sync`, `pan up` and `pan doctor` install and check Herdr for you. tmux is still supported through `terminal.backend: tmux`. See [Terminal backend](/configuration/terminal-backend). ([#3995](https://github.com/eltmon/overdeck/pull/3995))
  - **Planning artifacts live in your repo.** Drafts, specs, continues, orders and the backlog sequence are committed under `.pan/` in the project (or its plan home), not in a separate state worktree. `pan admin migrate-plan-home <project>` copies open issues' artifacts across.
  - **Merge readiness comes from the PR.** It is PR approvals, green checks and forge mergeability. Review verdicts are PR reviews, posted by the GitHub App.
  - **Retired commands.** `pan approve` becomes `gh pr review --approve` or the dashboard Merge button, `pan review pending` becomes `gh pr list`, and `pan inspect`, `pan reset-to-planned`, `pan unstick`, `pan review resync/reset` and `pan copy-config` are gone because there is no stored state left for them to act on.
  - **Simpler background supervisor.** The patrol loop is now four routines: nudge stuck work, nudge on API errors, reconcile liveness, and reap closed issues.
