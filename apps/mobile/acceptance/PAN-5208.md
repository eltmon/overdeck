# PAN-5208 acceptance evidence

Phone app visual pass: a new `/m` header with the Overdeck lockup and a Settings gear, tab-bar icons, clearer rows and empty states, a faint logo watermark behind the landing lists, the logo sting on first load, and the System/Light/Dark appearance setting in `/m`.

## Deviation: native machine-list screenshots

Plan decision D-17 asks for native machine-list screenshots in light and dark from the iOS Simulator or an Android emulator. None were captured. Two routes were tried in this session:

- **Android emulator (this host):** the branch's debug build was installed on the `galaxyA16` AVD, booted read-only and headless (`emulator -avd galaxyA16 -read-only -no-window`, `./gradlew installDebug`). The AVD's lock screen has a credential. `wm dismiss-keyguard`, a swipe and `locksettings set-disabled true` did not clear it, so the app never reached the foreground.
- **iOS Simulator (Mac rig):** not attempted. A new Simulator per `apps/mobile/README.md` holds no account, so the app would stop at the sign-in screen. Reaching the machine list needs a GitHub sign-in through overdeck.ai, which only the operator can complete.

The DOM evidence for the native screens comes from `apps/mobile/src/shell/__tests__/MachinesScreen.test.tsx` instead:

- `PAN-5208: shows the empty state for an online directory with no machines`
- `PAN-5208: renders the watermark outside the list and keeps the header button names`

The sign-in and settings headers are covered by `SignInScreen.test.tsx` → `shows the Overdeck lockup` and `SettingsScreen.test.tsx` → `puts the ‹ Machines back button and the Settings title in a header`. The native screens use the same `brand.tsx` pieces (`MobileScreenHeader`, `OverdeckLockup`, `LogoWatermark`, `MobileEmptyState`) that the `/m` screenshots below show.

## Deviation: opaque header, tab bar and scrim

The plan's `bg-card/80` / `bg-card/90` (header, tab bar, with `backdrop-blur`) and `bg-background/60` (settings scrim) render nothing. The theme colors are plain `var(--x)` strings, so Tailwind emits no opacity variant for them, as a check of the built CSS showed. The header and tab bar use opaque `bg-card` instead, and the scrim uses `bg-black/50`, like the phone app's delete-account dialog.
