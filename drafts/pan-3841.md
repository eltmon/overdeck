# PAN-3841 — Retrospective button: open a No-project conversation that reviews recent cross-issue activity and summarizes pipeline problems

**Issue:** https://github.com/eltmon/overdeck/issues/3841
**Planned:** 2026-09-16 (auto mode, `pan plan --auto`)
**Reference output:** the summary produced by conversation `20260916-7665` (Claude transcript `~/.claude/projects/-home-eltmon-Projects-overdeck/efc01bcc-8870-4513-9cab-d7b1925b0ca5.jsonl`), reproduced in Appendix A.

## Glossary

- **Command Deck** — the primary dashboard control surface at `/command-deck/<project>`. Its left column is rendered by `src/dashboard/frontend/src/components/CommandDeck/index.tsx`; the column's top row (`styles.sidebarHeaderRow`, line 1348) holds the title "Command Deck", the sidebar `ModelPicker`, and the "New conversation" plus button. This row is what the issue calls the **Command Deck header**.
- **No-project bucket** — the sentinel deck `NO_PROJECT_KEY = '__no-project__'` (`projectsData.ts:13`) that holds conversations not scoped to any registered project ("unscoped conversations"). An unscoped conversation is one created through `POST /api/conversations` **without** a `projectKey`.
- **Unscoped conversation** — see above. The server gives it `cwd = getDefaultCwd()` (`~/Projects` if it exists, else `$HOME`; `src/lib/default-cwd.ts:16-19`) and no `project_key`.
- **Kickoff prompt** — the first user message delivered to a freshly spawned conversation. `POST /api/conversations` accepts it as `message` (`conversation-runtime.ts:923`).
- **Conversation kickoff template** — a Markdown file under `roles/` that the server reads **at request time** and renders into a kickoff prompt. The existing precedent is `roles/handoff.md`, read by `readFile(join(packageRoot, 'roles', 'handoff.md'))` in `src/lib/conversations/summary-fork.ts:342` and rendered by `renderHandoffPrompt` (`summary-fork.ts:156-161`, `split('{{focus}}').join(...)`). Because it is read from disk on every request, editing it takes effect on the next click with **no build and no dashboard restart**.
- **`packageRoot`** — `src/lib/paths.ts:106`; resolves to the checkout root both in dev (`src/`) and in the built dashboard (`dist/`). `roles/` ships in the npm package (`package.json` `files` includes `roles`).
- **Window** — the lookback period for the retrospective: `24h` (default) or `7d`.
- **State worktree** — the per-project `overdeck-state` checkout at `${OVERDECK_HOME}/state/<projectKey>/`, resolved by `resolveStateReadHomeAsync(project, key)` (`src/lib/state-read-home.ts:42-53`). It returns `{ root, migrated }`; when `migrated` is false the project still uses the legacy `<root>/.pan/<domain>/` layout.
- **Records** — per-issue pipeline records `records/<issue>.json` in the state worktree (legacy: `.pan/records/`). Fields verified on `pan-3836.json`: top-level `pipeline`, `feedback`, `recoveryTrips`, `scopeDrift`, `sessionHistory`, `statusOverrides`, `tasks`; `pipeline` carries `reviewStatus`, `reviewedAtCommit`, `reviewSpawnedAt`, `testStatus`, `uatStatus`, `uatNotes`, `verificationStatus`, `verificationNotes`, `mergeStatus`, `prUrl`, `scopeDrift`.
- **Deacon log** — `${OVERDECK_HOME}/logs/deacon.log` (about 20 MB); every line starts with an ISO timestamp in brackets, e.g. `[2026-09-16T19:23:54.547Z] nudgeIdleWorkAgentsWithOpenBeads: Nudged idle agent-pan-3836 …`.
- **Lifecycle log** — `${OVERDECK_HOME}/agents/<agentId>/lifecycle.log`.
- **Review synthesis / feedback files** — `<workspace>/.pan/review/<runId>/synthesis.md` (`src/lib/cloister/review-agent.ts:85`) and `<workspace>/.overdeck/feedback/`.
- **Prompt-Change trailer** — a `Prompt-Change: <reason>` line in a commit message. `scripts/check-prompt-change-trailer.sh:30-33` requires one on some commit in `merge-base..HEAD` whenever any `roles/*.md` file changes. Adding `roles/retrospective.md` triggers this.
- **File-size ratchet** — `scripts/lint-file-size.sh`: a `.ts`/`.tsx` file over 1000 lines may not exceed its `origin/main` line count unless `scripts/file-size-allowlist.txt` has a row. Current caps: `CommandDeck/index.tsx` 1612 (file is 1603 → 9 lines of headroom), `routes/conversations.ts` 1070 (file is 1070 → zero headroom), `conversation-runtime.ts` 1163 (file is 1163 → zero headroom). `server.ts` is 495 lines and is not ratcheted.

## Problem

PAN-3836 needed eight rework cycles. About half the delay came from pipeline/substrate faults and half from a haiku-tier work agent, but nothing showed that as a whole; each symptom appeared one at a time in feedback files, deacon logs, and review syntheses. A human shepherding conversation spent hours assembling the picture in Appendix A. An operator should be able to click one button and get that same shape of report for the last 24 hours or 7 days.

## Proposal (decisions made)

1. **Template home: `roles/retrospective.md`.** Of the three prompt homes in the repo only `roles/` satisfies "tunable without a dashboard rebuild": `src/lib/cloister/prompts/*.md` is copied to `dist/dashboard/prompts/` at build (`package.json:95`) and cached in memory by `renderPrompt` (`reference/prompts.mdx:128-131`), and the TalkItThrough seed prompt is inlined in the frontend bundle (`TalkItThrough.tsx:38-51`). `roles/handoff.md` is the existing conversation kickoff template read at request time, so the retrospective template sits next to it.
2. **Button placement: the Command Deck header row**, not the No-project overview. The sidebar's No-project bucket renders only when an unscoped conversation already exists (`Sidebar.tsx:247-250`, `:748`), so a button that lives only inside that deck is unreachable on a fresh install. The header row is always rendered.
3. **Window selector: a two-item menu** on the button ("Last 24 hours" default-first, "Last 7 days"), modeled on the ActionDock overflow menu (`Stage/stage.module.css:410-442`). No free-form date input.
4. **Server endpoint `POST /api/conversations/retrospective`** in a **new** route file. It renders the template and delegates to the existing conversation write door `handleConversationCreate` with no `projectKey`, so the conversation is unscoped and lands in the No-project bucket. The two god files (`routes/conversations.ts`, `conversation-runtime.ts`) are at their ratchet caps and are not edited except for one zero-line-growth `export` keyword.
5. **Frontmatter is stripped before delivery.** `handleConversationCreate` derives the conversation title from the first 60 characters of the message (`conversation-runtime.ts:944-945`); an unstripped `---\nname: …` block would become the title. The body's first line is therefore title-shaped: `Pipeline retrospective: last 24 hours`.
6. **Read-only is enforced by the prompt, pinned by a test.** Conversations spawn with the same permission flags as every other conversation (`conversation-runtime.ts:562`); there is no per-conversation tool sandbox. The template lists the forbidden verbs explicitly, and a prompt-invariant test fails if a later "tune" drops that clause.
7. **Model and harness come from the Command Deck sidebar picker** (`sidebarModel`, `sidebarHarness`, `index.tsx:245-246`), exactly like the existing plus button. No hardcoded model.
8. **Navigation after launch is a hard `window.location.assign('/conv/<name>')`**, the same as TalkItThrough (`TalkItThrough.tsx:81-83`). The `/conv/<id>` deep-link effect selects the No-project deck for an unscoped conversation (`index.tsx:592`: `resolveConversationProjectName(conv) ?? NO_PROJECT_KEY`).

## Requirements

### Functional

- **FR-1** A `roles/retrospective.md` template exists with YAML frontmatter (`name: retrospective`, `description: …`) and a body that uses exactly these placeholders: `{{WINDOW_LABEL}}`, `{{WINDOW_START}}`, `{{WINDOW_END}}`, `{{OVERDECK_HOME}}`, `{{PROJECT_LINES}}`.
- **FR-2** The template body instructs the model to (a) treat the conversation as read-only and never run pipeline mutations, (b) read the listed inputs, filtering time-stamped sources by `{{WINDOW_START}}`, and (c) produce the four-section output shape from the issue (headline; substrate faults; work-agent quality faults grouped by tier/model; recommended follow-ups), each fault with an evidence path and an existing-issue link or "needs filing".
- **FR-3** `renderRetrospectiveKickoff({ template, window, now, overdeckHome, projects })` in `src/lib/overdeck/conversation-retrospective.ts` strips frontmatter, substitutes every placeholder, and returns a string whose first line is `Pipeline retrospective: <label>` and which contains no `{{`.
- **FR-4** `handleRetrospectiveConversationCreate(body, deps)` accepts `{ window?: '24h' | '7d', model?, harness?, effort? }`, defaults `window` to `24h`, rejects any other window with HTTP 400 `{ error: 'Invalid window' }`, reads the template from `join(packageRoot, 'roles', 'retrospective.md')` on every call, renders it, and calls `deps.createConversation({ message, model, harness, effort })` with **no** `projectKey` and no `issueId`.
- **FR-5** `POST /api/conversations/retrospective` (new file `src/dashboard/server/routes/conversations-retrospective.ts`, layer merged in `server.ts`) validates the origin like the sibling routes and returns the same 201 body as `POST /api/conversations`.
- **FR-6** A `RetrospectiveButton` in the Command Deck header row opens a two-item menu ("Last 24 hours", "Last 7 days"); choosing an item POSTs `{ window, model, harness }` to the endpoint, then navigates to `/conv/<name>`. A failed POST shows the server error via `toast.error` and leaves the button usable.
- **FR-7** The per-project lines rendered into `{{PROJECT_LINES}}` name, for every registered project: key, repo path, state root, whether it uses the migrated layout, and `github_repo` when set.

### Non-functional

- **NFR-1** Editing `roles/retrospective.md` changes the next kickoff prompt with no `npm run build` and no dashboard restart (template read per request; no module-level cache).
- **NFR-2** No new `execSync` or sync tmux primitives in server-reachable code; template read uses `node:fs/promises`.
- **NFR-3** `routes/conversations.ts` and `conversation-runtime.ts` line counts do not increase; `CommandDeck/index.tsx` stays at or below 1612 lines (or an allowlist row `<lines> src/dashboard/frontend/src/components/CommandDeck/index.tsx # PAN-3841` is added in the same commit).
- **NFR-4** The commit that adds `roles/retrospective.md` carries a `Prompt-Change:` trailer.
- **NFR-5** Frontend follows `pan-style-guide` (no pill badges, no decorative color; reuse `styles.conversationAddBtn` sizing for the icon button).

```markdown
---
name: retrospective
description: Overdeck kickoff template for the No-project pipeline retrospective conversation (read-only review of recent cross-issue pipeline problems).
---

Pipeline retrospective: {{WINDOW_LABEL}}

You are reviewing everything the Overdeck pipeline did between {{WINDOW_START}} and {{WINDOW_END}} (UTC) across all projects, and writing a retrospective of what went wrong. Model the report on the shape below.

## Ground rules (read-only)

This conversation is read-only. Do not run pipeline mutations of any kind:
- no `pan start`, `pan kill`, `pan resume`, `pan done`, `pan tell`, `pan close`, `pan merge`, `pan reset-session`, `pan unstick`, `pan restart`, `pan reload`, or any other `pan` verb that changes state;
- no `gh issue create`, `gh issue edit`, `gh issue close`, `gh pr merge`, or any other GitHub write;
- no `git commit`, `git push`, `git stash`, `git checkout`, or any write to a workspace or to the `overdeck-state` branch;
- no HTTP POST/DELETE/PATCH to the dashboard.
Reading files, `grep`, `gh issue list`, `gh issue view`, `gh pr view`, `gh run list`, and `pan show`/`pan memory search` are fine. If you believe an issue should be filed, put it under "Recommended follow-ups" and let the operator file it.

## Inputs

Overdeck home: `{{OVERDECK_HOME}}`

Registered projects:
{{PROJECT_LINES}}

For each project:
1. Per-issue records: `<state root>/records/*.json` when the layout is migrated, otherwise `<state root>/.pan/records/*.json`. Use `updated` to keep records touched after {{WINDOW_START}}. Read `pipeline` (reviewStatus, reviewedAtCommit, reviewSpawnedAt, testStatus, uatStatus, uatNotes, verificationStatus, verificationNotes, mergeStatus, prUrl), `feedback`, `recoveryTrips`, `scopeDrift`, and `sessionHistory` (count review cycles and manual interventions from it).
2. Review syntheses: `<repo path>/workspaces/*/.pan/review/*/synthesis.md`, and feedback files under `<repo path>/workspaces/*/.overdeck/feedback/`.
3. Deacon log: `{{OVERDECK_HOME}}/logs/deacon.log`. It is large; filter lines whose bracketed timestamp is at or after {{WINDOW_START}} (for example `awk -F'[][]' '$2 >= "{{WINDOW_START}}"'`) and look for recoveries, re-dispatches, nudges, stuck flags, orphan cleanups, and auto-resumes.
4. Agent lifecycle logs: `{{OVERDECK_HOME}}/agents/*/lifecycle.log`, plus any spawn failures.
5. CI: `gh run list --repo <github_repo> --created ">={{WINDOW_START}}"` and the `overdeck/test` status stamps on PRs from `gh pr view <n> --json statusCheckRollup`.
6. Issues filed in the window: `gh issue list --repo <github_repo> --search "created:>={{WINDOW_START}}" --label pipeline`, and the same for `blocks-main` and `bug`. Use these to link faults to issues that already exist.

## Output shape

1. **Headline** — issues touched in the window, how many needed more than two review cycles, how many needed manual intervention.
2. **Pipeline and substrate faults** — one bullet each: what happened, the evidence path (file path or command output), and either a link to the existing issue or "needs filing".
3. **Work-agent quality faults** — grouped by tier/model, listing the recurring failure classes with evidence.
4. **Recommended follow-ups** — each with a one-line rationale.

Describe every issue in plain language, never as a bare ID. Keep the report to what the evidence supports; say "no evidence found" for a source that turned up nothing.
```
