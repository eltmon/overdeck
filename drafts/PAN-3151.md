# PRD: PAN-3151 — Review→rework non-convergence detection and planning-time size bound

**Issue:** https://github.com/eltmon/overdeck/issues/3151
**Author:** planning agent (k3[1m]), 2026-07-26, `--auto` mode

## Glossary

- **Review cycle** — one full review run for an issue, identified by a runId of the form
  `agent-<issue>-review-<head8>` (built in `src/lib/cloister/review-agent.ts:565`). Each cycle
  writes a directory `.pan/review/<runId>/` in the workspace containing per-reviewer reports
  (`security.md`, `correctness.md`, `performance.md`, `requirements.md`) and a `synthesis.md`.
- **Blocking finding** — a finding a reviewer marks with severity `!` or `⊗` in the
  `## Findings` section of its report (parsed by `findBlockingFindings` in
  `src/lib/cloister/deacon-review-signals.ts:31`). In `synthesis.md` they appear as
  `### [<subRole>] <title>` headings under `## Blocking Findings`.
- **Blocking-finding count** — the number of blocking findings in one cycle's synthesis.
  The issue quotes PAN-3093's per-cycle counts (12 → 7 → 5 → 4 → 12); those numbers are the
  `### ` heading count under `## Blocking Findings` in each cycle's `synthesis.md` (verified:
  cycle f75a76c4 has exactly 12).
- **Reconcile** — `reconcileJournalIntoCacheSync` in `src/lib/review-status-reconcile.ts`, the
  single chokepoint where a journal/DB status write becomes effective and where the
  blocked→rework feedback hook fires (`wasBlocked → nowBlocked`, lines ~144–148).
- **Rework re-drive** — the host-side delivery of a blocked verdict to the work agent via
  `deliverReviewVerdictFeedbackHostSide` (`src/lib/review-status.ts:495`) →
  `deliverReviewVerdictFeedbackPromise` (`src/lib/cloister/review-verdict-feedback.ts:97`),
  which writes a feedback file and calls `messageAgent(..., { owesRework: true })`.
- **Stuck** — the `review_status.stuck` flag written by `markWorkspaceStuck`
  (`src/lib/overdeck/review-status-sync.ts:416`). Every deacon dispatch loop skips stuck
  issues (e.g. `src/lib/cloister/deacon-review-status.ts:359,749`, `deacon.ts:1404`,
  `deacon-merge.ts:776`, `stuck-remediation.ts:38,86`). Cleared by the existing unstick
  route (`src/dashboard/server/routes/workspaces/review-control.ts:289`, `[unstick]`).
- **Quality lint** — `lintPlanQuality` (`src/lib/xbrief/quality-lint.ts:405`), run by
  `pan plan finalize` (`src/cli/commands/plan-finalize.ts:38`); errors block finalize,
  `--no-quality-lint` is the emergency bypass (`src/cli/index.ts:378`).
- **Projected surface** — the union of all `metadata.files_scope` entries across a plan's
  active items, and the set of distinct top-level subsystems (first two path segments) they
  span. Knowable at planning time; diff size is not.

## Problem

PAN-3093 (29 files, +5,594/−402, 15 commits) ran five review cycles whose blocking-finding
count did not converge: 12 → 7 → 5 → 4 → **12**. The review→rework loop assumes each cycle
strictly shrinks the defect surface; at this change size that assumption fails, each fix
exposes an adjacent unhandled path, and nothing in the pipeline notices. Cost: ~$98, five
review convoys, ~7 hours of pipeline residency, defect count back where it started. Three
substrate gaps:

1. Planning does not bound the diff an xBRIEF may authorize.
2. The review dispatcher does not treat "cycle N with a non-decreasing finding count" as a
   signal — the rework re-drive fires unconditionally on every blocked verdict.
3. The per-cycle count is only visible to whoever manually diffs `synthesis.md` files.

**Explicitly not in scope:** disrupting PAN-3093 itself (15 commits in flight, current cycle
finishes); changing reviewer prompts or the prompt-level "convergence gate" in
`roles/review.md:62` (that gate governs which findings reviewers may *report*; it did not
and cannot stop the loop, because each cycle's findings are genuinely new).

## Proposal

Three mechanisms, matching the issue's three fix directions.

### 1. Review convergence gate (detection + loop stop)

Record the blocking-finding count of every blocked review cycle, persist the per-cycle
history on the issue's review status, and evaluate a deterministic convergence rule at the
reconcile chokepoint. When the rule fires:

- mark the workspace stuck with reason `review-not-converging` and the count series in
  `stuckDetails` (this stops every deacon re-dispatch path, which already skips stuck);
- suppress the automatic rework re-drive — the work agent is NOT messaged to "fix the
  findings" again;
- emit an error-level activity entry and surface needs-you with the counts, so the operator
  sees "not converging — consider decomposition" where they already look.

Escape hatch (existing, no new machinery): the operator reviews the trend, then either
splits the work, or clicks unstick / runs the unstick route and re-requests review — the
next cycle simply appends to the history.

**Convergence rule** (auto-decision D3): after appending cycle *n*'s count, the issue is
**not converging** when either

- (a) *reversal*: `count[n] > count[n-1]` and `n ≥ 3` — the defect count went backwards after
  enough history to establish a trend (fires on PAN-3093 at cycle 5: 4 → 12); or
- (b) *stall*: `count[n] ≥ count[n-1]` and `count[n-1] ≥ count[n-2]` — two consecutive
  comparisons with no decrease (fires on e.g. 12 → 7 → 5 → 5 → 5 at cycle 5, and on
  5 → 5 → 5 at cycle 3).

A passed verdict or a count of 0 ends the loop normally and never triggers the gate. The
minimum of 3 cycles means a single bump on cycle 2 (e.g. 12 → 13) does not fire.

**Counting** (auto-decision D2): count from `synthesis.md` first — the number of `^### `
headings under `## Blocking Findings` (`None` → 0) — because the synthesizer deduplicates
cross-sub-role findings and this reproduces the exact numbers the issue quotes. If the
newest run dir has no synthesis (deacon fallback still running, self-review mode), fall back
to summing `findBlockingFindings` across the run's report files. Reports and synthesis live
in `.pan/review/<runId>/` (`PAN_DIRNAME = '.pan'`, `src/lib/pan-dir/types.ts:10`; dir built
at `review-agent.ts:568`). The `roles/review.md` self-review banner mentions
`.overdeck/review/` — that path is stale prompt text; the helper checks `.pan/review` first
and `.overdeck/review` as a defensive fallback.

### 2. Persisted per-cycle history (reporting substrate)

New `reviewCycleHistory` field on `ReviewStatus`
(`src/lib/review-status-reconcile.ts:22-70`), persisted as a JSON TEXT column
`review_cycle_history` on the `review_status` table (schema v61 → v62 idempotent DDL,
pattern at `src/lib/database/schema.ts:789`), mirrored into the per-issue permanent record's
pipeline block exactly like `reviewerVerdicts` (`src/lib/pan-dir/records.ts:135`,
`src/lib/overdeck/review-status-record-sync.ts:126`). Entry shape:

```json
{ "cycle": 5, "runId": "agent-pan-3093-review-f75a76c4", "atCommit": "f75a76c4…",
  "blockingCount": 12, "recordedAt": "<ISO>" }
```

Appends are deduped by `runId` so a sandboxed reconcile re-run is idempotent.

### 3. Planning-time projected-surface bound

New quality-lint rule `lintProjectedSurface` in `lintPlanQuality`: **error** when a plan's
projected surface exceeds **25 distinct files** or **6 distinct subsystems** (first two
path segments of each `files_scope` entry), unless `plan.metadata.sizeJustification` is a
non-empty string. Threshold rationale: PAN-3093 touched 29 files across ~6 subsystems
(schema, ready-set resolution, assembly, two-phase promote, post-merge verification,
cleanup) — both dials would have flagged it. The error message tells the planner to split
the work into independently shippable sibling issues, per the existing swarm-contract
guidance at `src/lib/cloister/prompts/planning.md:217`, which this PRD also strengthens with
the numeric thresholds. Escape hatches: `sizeJustification` (recorded, reviewable) and the
existing `--no-quality-lint` emergency bypass. The lint sees `files_scope`, which the
planner already must declare on every item — no new authoring burden.

### 4. Trend reporting

Project `reviewCycleHistory` through the dashboard read model (alongside `stuckReason` at
`src/dashboard/server/read-model.ts:333`) and render the count series in the issue view's
review section (e.g. `Review cycles: 12 → 7 → 5 → 4 → 12`, with the
`review-not-converging` stuck reason the dashboard already surfaces). `pan show` prints the
same series next to its existing stuck display (`src/cli/commands/show.ts:110-116`).

## Requirements

### Functional

- **FR-1** — When a review cycle's verdict transitions to `blocked` or `failed`, the
  pipeline records a cycle entry `{cycle, runId, atCommit?, blockingCount, recordedAt}` on
  the issue's review status, deduped by `runId`.
- **FR-2** — The blocking count is derived from the newest `.pan/review/<runId>/synthesis.md`
  `## Blocking Findings` heading count, falling back to the sum of blocking findings across
  the run's report files, falling back to skipping recording (with a warn log) when no
  review artifacts exist.
- **FR-3** — When the recorded series satisfies the convergence rule (reversal at n≥3, or
  two consecutive non-decreases), the issue is marked stuck with reason
  `review-not-converging` and the full count series in `stuckDetails`.
- **FR-4** — While the gate is engaged, the automatic rework re-drive is suppressed: no
  `messageAgent(..., owesRework)` is sent for that verdict, from ANY caller of
  `deliverReviewVerdictFeedback` (reconcile hook, deacon-review-signals, legacy routes,
  `pan done`). The feedback file and PR comment are still written (record-keeping).
- **FR-5** — When the gate engages, an error-level activity entry and a needs-you surface
  state the count series and the "consider decomposition" guidance.
- **FR-6** — `pan plan finalize` fails quality lint with rule `projected-surface` when the
  plan's projected surface exceeds 25 files or 6 subsystems and
  `plan.metadata.sizeJustification` is absent or empty; the error message names the split
  into sibling issues as the remedy. With a non-empty `sizeJustification`, or with
  `--no-quality-lint`, finalize proceeds.
- **FR-7** — The dashboard issue view and `pan show` display the per-cycle blocking-count
  series for any issue with ≥1 recorded cycle.

### Non-functional

- **NFR-1** — All new status persistence flows through the existing doors: schema v62
  idempotent DDL, `upsertReviewStatusSync`, the record mirror; no new direct DB access.
- **NFR-2** — Cycle-entry append is idempotent across sandboxed/host reconcile re-runs
  (dedupe by runId).
- **NFR-3** — No new timers, retries, or delays; tests use the existing sync fs and in-memory
  DB patterns. (Fake-timer rule restated: not applicable — nothing here waits.)
- **NFR-4** — The gate changes no behavior for issues whose series is converging, short
  (<3 cycles), or passing; the PAN-794 infra breaker and all other stuck reasons behave
  exactly as before.

## Decisions (auto mode)

- **D1 — Hook at the reconcile chokepoint, not the verdict CLI.** Cycle recording and gate
  evaluation run inside `reconcileJournalIntoCacheSync` at the existing
  `wasBlocked → nowBlocked` transition (`review-status-reconcile.ts:144-148`). Every verdict
  path — `pan done`, deacon fallback, journal recovery, HTTP route — funnels through this
  transition (verified: the hook at `review-status.ts:696` is the only wiring of
  `deliverReviewVerdictFeedbackHostSide`). Hooking the CLI would miss the journal and
  recovery paths.
- **D2 — Count from synthesis.md first.** The synthesis deduplicates cross-sub-role
  findings, and the heading count under `## Blocking Findings` reproduces the issue's quoted
  numbers exactly (verified 12 on PAN-3093 cycle f75a76c4). Raw-report summing is only a
  fallback.
- **D3 — Convergence rule = reversal-at-n≥3 OR two consecutive non-decreases.** The issue
  says "fails to decrease across two consecutive cycles"; the reversal clause is needed so
  PAN-3093's actual signature (strict decrease then jump 4 → 12) fires at cycle 5 rather
  than waiting for two more wasted cycles.
- **D4 — Gate action reuses `stuck`, no new lifecycle state.** Stuck already halts every
  deacon dispatch loop and already has an operator escape hatch (unstick route,
  `review-control.ts:289`). A new state would fork every one of those call sites.
- **D5 — Feedback suppression lives in `deliverReviewVerdictFeedbackPromise` as well as the
  reconcile hook.** The function has direct callers outside reconcile
  (`deacon-review-signals.ts:252`, `legacy-routes.ts:496`, `specialists/done.ts:244`); the
  in-function check on `stuckReason === 'review-not-converging'` covers all of them. The
  reconcile-side skip exists so the gate is evaluated once, at recording time.
- **D6 — Thresholds 25 files / 6 subsystems, overridable per plan.** Sized so PAN-3093
  (29 files, ~6 subsystems) would have been flagged. A hard error (not warn) because a warn
  is exactly the "nobody notices" failure mode this issue is about; the
  `sizeJustification` metadata and `--no-quality-lint` are the two deliberate bypasses.
- **D7 — Dashboard display is a minimal trend line.** No new chart component; the decision
  surface is the count series plus the existing stuck-reason badge.

## Hazards

- **H1 — Polyrepo wrapper workspaces.** The review dir lives in the wrapper workspace, not a
  sub-repo; the WI-4 path resolution must use the same wrapper resolution as
  `review-verdict-feedback.ts:100-103` and never probe sub-repos for review artifacts.
- **H2 — Format drift in synthesis.md.** If a future synthesis format renames
  `## Blocking Findings`, the count silently falls back to report summing (which may
  double-count). The WI-2 tests pin both formats; the count-skip warn log (FR-2) makes total
  absence visible.
- **H3 — Gate false positive on legitimately hard issues.** A genuine 4-cycle grind with one
  reversal now stops the loop. That is the intended behavior (the issue asks for exactly
  this stop), and the unstick route is the documented override; the needs-you message must
  say so.
- **H4 — Sandboxed reconcile re-entry.** A sandboxed reader reconciles with a read-only DB;
  the append must dedupe by runId so the host's later reconcile doesn't double-record, and
  gate evaluation must be pure given the series so both contexts decide identically.
- **H5 — Lint false positive on mechanical bulk plans.** A 30-file rename xBRIEF trips the
  25-file rule. `sizeJustification` is the recorded escape; the error message must name it.
- **H6 — `stuck` semantics leak.** WI-4 sets stuck fields on the reconciled object AND calls
  `markWorkspaceStuck`; both write paths must agree, or the read model and DB diverge (the
  drift this repo's two-door tenet exists to prevent). Tests must assert both.
