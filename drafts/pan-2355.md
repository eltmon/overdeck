## Glossary

- **Tab routing** — the SPA has NO router: `TAB_PATHS` map (`FE/src/App/routes.ts:4`),
  `getTabFromPath()` (`:33`), a conditional render chain (`FE/src/App/AppRoutes.tsx:92-245`), manual
  `history.pushState` (`FE/src/App.tsx:367`). Standalone full-window routes branch before the main chrome
  (`FE/src/App/StandaloneRoutes.tsx` — terminal `:13`, flywheel popout `:23`, conversation popout `:48`).
- **Needs-You data** — already modeled: store selector `selectPendingInputSubjects` (`FE/src/lib/store.ts`)
  feeding `NeedsYouSection` (`FE/src/components/sessionFeed/SessionFeedSidebar.tsx:173`) — every subject
  blocked on the operator (AUQ, plan-mode, session-resume, PermissionRequest).
- **AUQ answer transports** — `FE/src/App/hooks/usePendingInputDialogs.ts:222-261`: structured →
  `POST /api/agents/<id>/answer-question`; Codex numbered → `POST /api/conversations/<id>/codex-approval`;
  prose fallback → `POST /api/conversations/<id>/message`. Poll source: `GET /api/conversations/pending-input`
  (`:84`, 4s interval).
- **Conversation stream** — WS RPC `subscribeConversationMessages`
  (`FE/src/components/chat/useConversationMessagesStream.ts:150`); HTTP transcript fallback
  (`ConversationPanel.tsx:1163`); composer send via `sendConversationMessage`
  (`FE/src/lib/composerStore.ts:90-106` → `POST /api/conversations/<name>/message` or
  `/api/agents/<id>/message`, supports `deliverAs: 'steer' | 'follow_up'`).
- **Service-worker constraints** — static serving: `staticRouteLayer`
  (`src/dashboard/server/server.ts:205`), root `dist/dashboard/public` (vite `outDir`,
  `FE/vite.config.ts:91`); **extensionless paths fall through to the SPA `index.html` fallback**
  (`server.ts:264-265`) and `index.html` is deliberately no-cache (`server.ts:272-292`). Therefore the SW
  must be a fixed-name real file (`/sw.js`) emitted into the outDir, scope `/`.
- **Style law** — `design/style-guide/STYLE-GUIDE.md` + `/pan-style-guide` skill: DM Sans prose,
  `font-medium` everywhere (no bold), one signal color per row, `rounded-sm` badges (no pills), green ≠
  running. Tokens are the CSS variables in `FE/src/index.css:15-70` (+ `.dark`).

## Problem

The dashboard on a phone is a desktop layout that reflows badly: the only width breakpoints are one
767px rule in command-deck CSS and a 560px rule in Stage; the sole mobile affordance is the Sidebar
hamburger (`FE/src/components/Sidebar.tsx:155`, `:329-341`). There is no `useIsMobile` hook, no manifest,
no service worker, no push (all verified absent). Core mobile jobs — answer an AUQ, read/steer a
conversation, scan the pipeline — require desktop-sized xterm and hover interactions today.

## Decisions

- **D-1 Route strategy: a standalone mobile branch** (`/m` and children), rendered via the
  StandaloneRoutes pattern rather than a new Tab — the mobile shell must not mount the desktop chrome
  (Sidebar, panes, terminals) at all. Desktop URLs opened on a phone offer a "switch to mobile" banner
  (one `useIsMobile` check at the App branch point); no forced redirect.
- **D-2 New shared hook `useIsMobile()`** (`matchMedia('(max-width: 767px)')`, matching the existing
  767px precedent, `command-deck.module.css:50`) — introduced once, in `FE/src/lib/`.
- **D-3 Mutations from mobile use `dashboardMutationJsonHeaders`** (`FE/src/lib/wsTransport.ts:83`).
  The known inconsistency (conversation send and AUQ answers post cookie-only JSON without CSRF —
  `composerStore.ts:96-106`, `usePendingInputDialogs.ts:232-255`) is NOT fixed here; mobile reuses those
  exact existing call paths untouched (surgical-change rule). File the CSRF unification as its own issue
  during implementation.
- **D-4 PWA tooling: `vite-plugin-pwa`** (injectManifest mode, fixed `sw.js` name, `index.html` stays
  no-cache; precache hashed bundles only, never `/api` or `/ws`). Runtime caching: NONE for API (live
  dashboard must never serve stale state); offline = a static "reconnecting" shell.
- **D-5 Web Push v1 = same-machine origin.** VAPID keypair generated once into `~/.overdeck/`
  (file, not DB — survives rebuilds, PAN-2351 D-1 precedent), subscription store likewise
  (`~/.overdeck/push-subscriptions.json`, single writer module). PAN-2356 later relocates the origin to
  the relay; the provider interface (PAN-2354 D-2) isolates that move.
- **D-6 Terminal on mobile is read-mostly**: snapshot + live tail via the existing `/ws/terminal`,
  no soft-keyboard input affordance in v1 (input via conversation composer instead). xterm fit on small
  screens is a mockup-phase question.

## Requirements

- **FR-1** Mobile shell at `/m`: bottom tab bar — Needs-You (default), Conversations, Pipeline; installable
  (manifest: name, icons from `favicon.svg` + generated PNGs, `display: standalone`, theme color from the
  dark token `#080b10`).
- **FR-2** Needs-You feed: consumes `selectPendingInputSubjects`; answering an AUQ reuses the
  `usePendingInputDialogs` mutation paths verbatim (D-3); target ≤3 taps from push notification to answered.
- **FR-3** Conversation list + view: list from `GET /api/conversations` (`routes/conversations.ts:204`);
  view reuses `useConversationMessagesStream` + a mobile-layout timeline (the existing
  `MessagesTimeline` components restyled, not forked, unless the mockup proves a fork necessary); composer
  reuses `sendConversationMessage` incl. `deliverAs`.
- **FR-4** Pipeline board: phase-grouped read view from the same store the desktop `PipelineView` uses;
  card tap → issue detail sheet (read-only v1).
- **FR-5** Web Push: SW handles `push` + `notificationclick` (deep link into `/m` routes); server gets
  `POST /api/push/subscriptions` (+ DELETE), scope `admin`; PAN-2354 gains the `webpush` provider sending
  via VAPID to all registered subscriptions. iOS requires home-screen install — documented.
- **FR-6** Everything obeys the style law (Glossary) — reviewed against `/pan-style-guide` before merge.
- **NFR-1** Zero regression to the desktop bundle: mobile routes lazy-loaded (`React.lazy`); CI bundle-size
  note in PR.
- **NFR-2** SW never caches `/api`, `/ws`, or `index.html`; update flow = `skipWaiting` + reload prompt.
- **NFR-3** All new timers/reconnect logic fake-timer tested.
