# PAN-3296 — `pan start` flips plan status in the state worktree but never commits it

**Issue:** https://github.com/eltmon/overdeck/issues/3296
**Related:** PAN-3291 (reconciler content-conflict wedge), PAN-2541 (state plane), PAN-2677 (prior bare-write stranding), PAN-2516 (drift patrol), PAN-3286 (pipeline that exposed this bug).

## Glossary

- **State worktree** — the checkout of the orphan branch `overdeck-state` at `${OVERDECK_HOME}/state/<project>/`, holding `specs/`, `records/`, `continues/`, `drafts/`. All writes to it must go through the state write door (commit + push immediately).
- **Canonical spec** — the xBRIEF file `specs/<date>-<ISSUE>-<slug>.xbrief.json` in the state worktree. It has a top-level `status` field (`PanSpecStatus`: proposed/active/completed/cancelled) AND an inner `plan.status` field (proposed/approved/running/completed/…).
- **Bare write** — a filesystem write to the state worktree that is not followed by a commit+push. Bare writes leave the worktree dirty, which blocks every later `git rebase` there (git refuses to rebase over unstaged changes to tracked files).
- **State write door** — `queueAutoCommit()` + `flushAutoCommits()` in [`src/lib/pan-dir/auto-commit.ts`](../../src/lib/pan-dir/auto-commit.ts): stages the concrete paths, commits, and pushes; callers fail loudly when the push does not land.
- **Push-race reconciler** — `reconcileStatePush()` at [`src/lib/pan-dir/record-update.ts:274`](../../src/lib/pan-dir/record-update.ts): on a rejected push it fetches, rebases onto `origin/overdeck-state`, replays the record mutation on conflict, and re-pushes. `pan task claim/done/...` reach it via `applyTaskStatusChange` → `updateIssueRecord()`.
- **Drift patrol** — `reconcileStatePlaneDrift()` at [`src/lib/pan-dir/auto-commit.ts:272`](../../src/lib/pan-dir/auto-commit.ts) (PAN-2516), run by the deacon (`deacon.ts:3110`): adopts uncommitted `specs/`+`records/` changes on a patrol cadence. It exists but did not save the PAN-3286 incident because the wedge (blocked claim + blocked reconciler) bites immediately, in-process, before any patrol cycle.

## Root cause (verified 2026-07-30)

`updatePlanStatus()` at [`src/lib/xbrief/lifecycle-io.ts:228`](../../src/lib/xbrief/lifecycle-io.ts) is a bare file write (tmp + rename, no commit):

```ts
export function updatePlanStatus(filePath: string, newStatus: string): void {
  const doc = readPlanSync(filePath);
  ...
  writeFileSync(tmp, serializeXBriefDocument(doc), 'utf-8');
  renameSync(tmp, filePath);
}
```

It has exactly three callers:

1. `transitionXBriefOnMainPromise` internally at `lifecycle-io.ts:352` — **safe** (the caller queues + flushes a commit right after, lines 358-367).
2. [`src/cli/commands/start.ts:1233`](../../src/cli/commands/start.ts) — **the bug**. After spawning the work agent, `pan start` first runs `transitionXBriefOnMain(projectRoot, id, 'active', 'approved', …)` (line 1216, commits+pushes), then calls `updatePlanStatus(spawnedPlanPath, 'running')` where `spawnedPlanPath = findPlanSync(workspace)`. After promotion, `findPlanSync` (in `src/lib/xbrief/io.ts:179`) resolves to the **canonical spec in the state worktree**, so the `running` flip (plus a `plan.sequence` bump and `updated` timestamps) lands as an uncommitted modification.
3. [`src/dashboard/server/routes/agents/spawn.ts:620`](../../src/dashboard/server/routes/agents/spawn.ts) — **same bug**, dashboard/deacon start path (`markWorkStartAccepted`: transition to `approved` at line 596, then bare `updatePlanStatus(planPath, 'running')`).

Downstream, the dirty spec blocks `git rebase origin/overdeck-state` in `reconcileStatePush()` — git refuses to rebase over unstaged changes — so `pan task claim` fails for the work agent and every subsequent records write that hits a push race queues locally (the observed 5-ahead/21-behind).

## Requirements

- **FR-1:** After `pan start <id>` (CLI path) completes against a migrated project, the canonical spec's `plan.status` is `running`, the state worktree is clean (`git status --porcelain` empty), and the commit is pushed to `origin/overdeck-state` (fails loudly otherwise).
- **FR-2:** The dashboard/deacon start path (`markWorkStartAccepted` in `spawn.ts`) satisfies the same invariant as FR-1.
- **FR-3:** No exported bare-write spec mutation surface remains in `lifecycle-io.ts`: `moveXBriefFilesOnly` and `deleteXBrief` are removed (no-loss audit: their only callers are their own unit tests).
- **FR-4:** `reconcileStatePush()` no longer wedges on uncommitted changes confined to write-door-owned paths (`specs/`, `records/`): it adopts them with a `chore(state): adopt orphaned write` commit and a loud `console.warn` before rebasing. Dirty paths OUTSIDE the owned dirs still fail with an error naming the offending paths (never silently commit operator files).
- **FR-5:** A durability test gate exercises every exported spec-mutation door against a temp migrated state worktree with an origin and asserts `git status --porcelain` is empty after each call (the "no bare writes left behind" guard from the issue's fix sketch).
- **NFR-1:** The workspace-local fallback still works: when `findPlanSync` resolves to a workspace draft (pre-promotion), the `running` flip is still written to that workspace file (gitignored; no state-door involvement).
- **NFR-2:** No new sync tmux/exec primitives; record-update continues to use its existing async `git()` helper; specs.ts continues on Effect.

## Design decisions (made here, not left to the executor)

- **D1 — Collapse the two-step flip into one committed transition.** At both call sites, replace the pair (`transitionXBriefOnMain(..., 'active', 'approved', ...)` followed by bare `updatePlanStatus(path, 'running')`) with a single `transitionXBriefOnMain(projectRoot, issueId, 'active', 'running', 'chore(state): start <ID> xBRIEF (status=running)')`. `transitionXBriefOnMainPromise` already handles the lifecycle-dir move AND the `plan.status` write, then commits+pushes and throws when the push fails. End state on disk is identical to today's (top-level `status: 'active'`, `plan.status: 'running'`), minus the dirty file. Verified: no production code gates on the intermediate `plan.status === 'approved'` (grep at planning time found zero consumers).
- **D2 — Keep the workspace-draft fallback flip.** After the transition call, keep calling `updatePlanStatus(spawnedPlanPath, 'running')` ONLY when `spawnedPlanPath` is inside the workspace (`spawnedPlanPath.startsWith(workspace + sep)`); a path outside the workspace is the canonical state-worktree spec already handled by D1. Do not modify `updatePlanStatus` itself to auto-commit — queueing inside the primitive would double-queue with `transitionXBriefOnMainPromise`'s own batch and degrade its explicit commit subjects to "batch update" messages.
- **D3 — Adoption scope = `specs/` + `records/`**, matching the PAN-2516 drift patrol's `ownedPaths`. `continues/` and `drafts/` writes go through their own doors and were not implicated; widening adoption is deliberately out of scope (NonGoal).
- **D4 — Remove, don't fix, the test-only bare doors.** `moveXBriefFilesOnly` and `deleteXBrief` have zero production callers; keeping exported bare-write doors invites the next PAN-3296. Their describe-blocks in `src/lib/xbrief/__tests__/lifecycle-io.test.ts` are deleted with them.
- **D5 — Adoption uses `--untracked-files=all`**, like the drift patrol, so a never-committed new spec file also gets adopted rather than colliding mid-rebase.

const transition = await Effect.runPromise(transitionXBriefOnMain(
  projectRoot, id, 'active', 'running',

...
const spawnedPlanPath = findPlanSync(workspace);
if (spawnedPlanPath && spawnedPlanPath.startsWith(workspace + sep)) {

### WI-4: `reconcileStatePush` adopts orphaned write-door-owned changes (traces FR-4)

**Files:** `src/lib/pan-dir/record-update.ts` (inside `reconcileStatePush`, before the `git rebase` at line 287; use the module's existing `git()` helper at line 140).

Per D3/D5, at the top of each reconciliation attempt (before `rebase`):

1. `git status --porcelain=v1 --untracked-files=all` in `gitRoot`.
2. If empty → proceed as today.
3. If every dirty path (after stripping the 3-char status prefix and resolving `->` renames, same parsing as `reconcileStatePlaneDrift`) is under `specs/` or `records/` → `git add -- specs records` then `git commit -m 'chore(state): adopt orphaned write before state rebase (PAN-3296)' -- specs records`, and `console.warn('[record-update] adopted orphaned state write(s): <paths>')`. Then proceed to rebase.
4. If any dirty path falls outside those dirs → throw `Error` naming the offending paths (message must tell the operator the state worktree has non-state-door changes that block reconciliation), preserving today's fail-closed behavior for unowned files.

Test (same file as existing record-update/durability tests): seed a temp migrated state repo + bare origin; commit a record; advance origin independently (so the local push races); dirty a tracked spec file; run `updateIssueRecord` with a mutator → assert the adoption commit exists with the `adopt orphaned write` subject, the record mutation lands on `origin/overdeck-state`, and porcelain is empty. Second case: dirty an unowned path (e.g. `stray.txt` at the worktree root) → assert the reconcile throws and names `stray.txt`.

## Hazards for the work agent

- **H1:** The state worktree in tests must be a *migrated* layout (`resolveStateReadHomeSync` returns `migrated: true`) or the doors fall back to legacy `.pan/` paths — copy the harness setup from the existing `state-door-durability.test.ts` rather than hand-rolling.
- **H2:** Do not modify `updatePlanStatus` to queue auto-commits (double-queue hazard, D2). Do not add rebase/replay behavior to `pushStateBranch` in auto-commit.ts — its no-replay stance is PAN-2541 D10 by design; adoption belongs in `reconcileStatePush` only.
- **H3:** `git rebase` refuses on ANY unstaged tracked change, not only files the rebase touches — the adoption check must run before every rebase attempt in the loop, not just the first.
- **H4:** Commit messages in the state worktree are not commitlint-gated (no husky there), but code-repo commits are — use `pan commit` conventions for the code repo.
