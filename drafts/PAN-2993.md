# PAN-2993 — Strike landing wedges permanently when the strike agent is dead

**Issue:** https://github.com/eltmon/overdeck/issues/2993
**Observed on:** PAN-2895 / PR #2903 — four failed landing attempts over 3 days.

## Glossary

- **Strike landing** — the Deacon-owned flow that merges a pushed `strike/<issue>` branch through the verified merge door. Driven by `patrolStrikeLandings()` in `src/lib/cloister/deacon-strike-landing.ts`, invoked once per Deacon patrol cycle (`src/lib/cloister/deacon.ts:3088`).
- **Landing state** — `strikeLandingState` on the issue's `ReviewStatus`: `'ready' | 'landing' | 'recovering' | 'landed' | 'needs_you'` (`src/lib/strike-landing.ts:1`).
- **Merge door endpoint** — `POST /api/internal/strikes/:id/merge` on the dashboard server; `requestStrikeMerge()` (`src/lib/cloister/deacon-strike-landing.ts:26-51`) POSTs to it from the Deacon process.
- **Transport failure** — the POST itself failed (`fetch` threw: ECONNREFUSED during a dashboard restart, socket hang up, response body unreadable). The endpoint never returned a structured verdict, so nothing is known about the merge — only that the request didn't get through.
- **Agent recovery** — `handleFailure()` (`deacon-strike-landing.ts:112-130`) messaging the warm `strike-<issue>` session with rebase-and-repush instructions and setting state `'recovering'`.
- **Mail queue** — per-agent `~/.overdeck/agents/<id>/mail/*.md` files written by `queueAgentMail()` (`src/lib/agents/messaging.ts:56-64`). A stopped agent with no resumable session never reads them.
- **PAN-1980 no-rotation path** — `messaging.ts:213-221`: when resume of a stopped agent fails, the agent is left stopped and feedback is queued in mail; `messageAgent()` returns normally (no throw).
- **Re-arm** — `pan strike-ready <id>` (`src/cli/commands/strike-ready.ts`) persisting readiness for the pushed strike HEAD so the patrol can (re)claim it.

## Problem

Three defects compound into a permanent wedge:

1. **Transport failures are misclassified as agent-actionable.** `requestStrikeMerge`'s catch (`deacon-strike-landing.ts:48-50`) returns `Strike merge request failed: fetch failed` when the POST races a dashboard restart. The `NON_ACTIONABLE` regex (`:107`) doesn't match it, so `handleFailure` routes it to agent recovery, whose message (`:117`) demands "A fresh pushed HEAD is required before another landing attempt." An infra-level ECONNREFUSED needs a plain retry at the same head, not a new commit.
2. **Recovery delivery to a dead agent reports success.** `deliverRecovery` (`:97`) calls `messageAgent()`, which returns `Promise<void>`. When the strike session is unresumable, the PAN-1980 path queues the message as mail and returns normally, so `handleFailure` sets `strikeLandingState: 'recovering'` (`:121`). Nothing reads that mail; the patrol skips `'recovering'` markers (`:138`), so the state is terminal in practice.
3. **`pan strike-ready` cannot re-arm from `'recovering'`.** The same-head early-return (`strike-ready.ts:72-81`) only resets to `'ready'` when the state is `'needs_you'`. With state `'recovering'` and an unchanged pushed head, the operator's re-arm silently no-ops — there is no sanctioned retry without inventing a new commit.

## Requirements

### Functional

- **FR-1** `requestStrikeMerge` classifies transport failures at the source: its catch branch returns `{ success: false, transport: true, error: … }`. A structured HTTP response (even an error one) never sets `transport`.
- **FR-2** A transport-flagged failure does not enter agent recovery. `executeStrikeLanding` routes it to a new `handleTransportFailure()` that records the attempt (outcome `'transport-failed'`), increments a `strikeTransportRetryCount`, computes `strikeNextAttemptAt` with exponential backoff (60s base, ×2 per consecutive failure, 30min cap), and sets the state back to `'ready'` at the **same** head. The patrol skips a candidate whose `strikeNextAttemptAt` is later than `deps.now()` (ISO-8601 string comparison).
- **FR-3** After 10 consecutive transport failures the landing escalates to `'needs_you'` with full attempt history (feedback file + needs-you surfacing), instead of retrying forever against a dead endpoint.
- **FR-4** The new status fields (`strikeTransportRetryCount`, `strikeNextAttemptAt`) round-trip through the permanent-record mirrors (`src/lib/pan-dir/records.ts:136-140`, `src/lib/overdeck/review-status-record-sync.ts:114-118`) so a DB rebuild does not forget backoff state. A successful landing (`'landed'`) and any re-arm clear both fields.
- **FR-5** `messageAgent()` returns a `MessageDeliveryOutcome` — `{ delivered: boolean; queuedToMail: boolean; reason?: string }` — from every return path. Mail-only paths (paused, gated, the PAN-1980 no-rotation path) report `delivered: false`. Paths that reach a live or successfully resumed session report `delivered: true`. Codex mid-turn `.pending` mail counts as `delivered: true` (the notify hook replays it at turn end to a live session). The signature change is additive: existing callers `await` and ignore the result; no caller outside strike landing changes.
- **FR-6** `handleFailure` consumes the outcome: when `deliverRecovery` resolves with `delivered: false`, the landing goes straight to `'needs_you'` (feedback file + needs-you, with the non-delivery reason appended to the attempt detail) instead of `'recovering'`. A thrown delivery error keeps its existing needs_you escalation (`deacon-strike-landing.ts:123`).
- **FR-7** `pan strike-ready <id>` with an unchanged pushed head re-arms from `'recovering'` exactly as it does from `'needs_you'`: state `'ready'`, `strikeRecoveryCount: 0`, transport retry fields cleared, attempt history preserved. Same-head calls in `'ready'`/`'landing'`/`'landed'` keep returning the previous status unchanged (no double-landing).
- **FR-8** `docs/SPECIALIST_WORKFLOW.md` (strike section, lines 311-313) documents the new behavior: transport failures retry at the same head with backoff, undelivered recovery goes to `'needs_you'`, and `pan strike-ready` re-arms from `'recovering'`.

### Non-functional

- **NFR-1** No `execSync`, no new sync primitives; all code stays on the async paths already used (this module is Deacon/server-reachable).
- **NFR-2** No wall-clock waits anywhere: backoff is data (`strikeNextAttemptAt` vs injected `deps.now()`), never `setTimeout`. Tests inject `now`/deps; the fake-timers rule is not triggered because no timers exist.
- **NFR-3** Additive change: the `StrikeLandingState` union, existing state transitions, the 3-cycle agent-recovery budget, and the PAN-1980 no-session-rotation policy are all unchanged.

## Design decisions (made here, not by the executor)

- **D1 — classify at the source, not by regex.** Any throw inside `requestStrikeMerge`'s try (fetch rejection or unreadable body) means the endpoint never returned a verdict → `transport: true`. Downstream never regexes for `fetch failed`. The `NON_ACTIONABLE` regex is still extended with `fetch failed|ECONNREFUSED|ECONNRESET|socket hang up|ETIMEDOUT|EAI_AGAIN` as a safety net for transport-flavored details that arrive via the unexpected-supervised-failure catch (`deacon-strike-landing.ts:151-159`) — those route to `needs_you`, never to agent recovery demanding a fresh HEAD.
- **D2 — a third failure class.** The issue text says "add transport failures to the non-actionable class", but non-actionable routes to `needs_you`. Transport failures get their own class that retries silently; only exhaustion (FR-3) surfaces to the operator.
- **D3 — retry via patrol re-claim, not an in-process loop.** `handleTransportFailure` resets state to `'ready'` with a due-time; the next patrol cycle re-claims when due. The existing `leaseKey`/supervisor machinery already serializes claims. Backoff comparison is lexicographic on ISO-8601 UTC strings (both sides come from `deps.now()`/`toISOString()`); compute the due time as `new Date(Date.parse(deps.now()) + delayMs).toISOString()`.
- **D4 — widen `messageAgent`'s return type instead of throwing.** Throwing on mail-only queuing would change behavior for ~20 existing callers (stuck-remediation, ci-failure-feedback, …). Returning an outcome object is source-compatible for all of them (they ignore the value) and gives future callers the same visibility.
- **D5 — transport counter is independent of `strikeRecoveryCount`.** A transport blip between two agent-recovery cycles must not consume the 3-cycle recovery budget, and vice versa.
- **D6 — `'recovering'` + operator re-arm = recovery.** The operator running `pan strike-ready` IS the recovery signal; no fresh commit required. `'landing'` stays excluded from re-arm to avoid double-landing a merge already in flight.

## Acceptance criteria (map 1:1 to work items)

- **AC-W1** Given `fetchImpl` rejects, `requestStrikeMerge` returns `success: false` with `transport: true`; given a structured HTTP error response, `transport` is absent. New fields survive a record round-trip through `records.ts` / `review-status-record-sync.ts`.
- **AC-W2** A transport-flagged failure resets state to `'ready'` at the same head with an increased `strikeTransportRetryCount`, a future `strikeNextAttemptAt`, and no `deliverRecovery` call; the patrol skips not-yet-due markers and claims them once due; the 10th consecutive transport failure produces `'needs_you'` with history; `'landed'` clears both transport fields.
- **AC-W3** `messageAgent` resolves `delivered: false, queuedToMail: true` on the PAN-1980 path and gated/paused paths, `delivered: true` on live-delivery paths; `npm run typecheck` passes with no edits to callers outside strike landing.
- **AC-W4** `deliverRecovery` resolving `{ delivered: false }` yields `'needs_you'` (feedback written, needsYou surfaced) with the non-delivery reason in the attempt detail; `{ delivered: true }` still yields `'recovering'`; a rejected delivery still yields `'needs_you'`.
- **AC-W5** Same-head `pan strike-ready` from `'recovering'` returns a status with `strikeLandingState: 'ready'`, `strikeRecoveryCount: 0`, cleared transport fields, preserved attempts; from `'landing'` it returns the previous status unchanged.
- **AC-W6** `docs/SPECIALIST_WORKFLOW.md` describes same-head transport retries with backoff, needs-you on undelivered recovery, and `strike-ready` re-arm from `recovering`.
