# PAN-2765 — Decisions inbox + interactive-idle detection

> **Status:** draft · **Issue:** https://github.com/eltmon/overdeck/issues/2765
> **Working mode:** operator-directed pipeline bypass. Implemented directly on `main`
> by the orchestrating conversation, reviewed in-session. Not routed through
> plan → work → review.

## Glossary

Define these before use; the document relies on them throughout.

- **Blocking surface** — anything that stops an agent until a human answers. Overdeck
  folds every one into `pendingInputKinds: string[]`. The kinds are fixed in
  `src/dashboard/frontend/src/lib/pendingInput.ts`: `askUserQuestion`,
  `permissionRequest`, `exitPlanMode`, `enterPlanMode`, `sessionResume`, `rateLimit`.
- **AUQ** — an `AskUserQuestion` tool call. A *structured* question with options.
- **Prose question** — a question the agent writes as ordinary assistant text, then
  ends its turn. Carries no tool call. This is the common case and is currently
  undetectable.
- **Interactive role** — a session a human converses with: `plan` (agent id prefix
  `planning-`) and conversations (`conv-`). Contrast with **autonomous roles**
  (`work`, `review`, `test`), which run to completion without a human in the loop.
- **Turn-end** — Claude Code fires its `Stop` hook when the assistant finishes
  responding. Overdeck's `stop-hook` translates this to `activity: idle`.
- **Enrichment** — the per-agent projection computed by
  `computeAgentEnrichment` (`src/lib/agent-enrichment.ts`) and polled by
  `agent-enrichment-service.ts`, carrying `hasPendingQuestion`, `pendingInputKinds`,
  `pendingAskUserQuestion`.
- **Needs you** — the existing pinned list in `SessionFeedSidebar.tsx`, fed by
  `selectPendingInputSubjects`.
- **Decisions** — the new surface this PRD introduces. Supersedes *Needs you* as the
  canonical list; *Needs you* becomes a view onto the same selector.

## Motivation — the observed failure

On 2026-07-15 the operator screenshotted `PAN-2760`. The `Planning` node showed
`fable-5 · 36m` and nothing else. The agent had, 36 minutes earlier, written three
options and a recommendation and ended its turn. The operator had no way to know.

Verified live at the time:

```
planning-pan-2760  status: healthy  hasPendingQuestion: False
                   pendingInputKinds: []   resolution: working
```

The dashboard was not lying — it genuinely had no signal. Two independent defects
produce this.

### Defect A — turn-end erases the operator signal

`~/.overdeck/bin/stop-hook` line 42:

```bash
BODY="{\"kind\":\"activity\",\"activity\":\"idle\",\"timestamp\":\"$TS\"}"
```

Its own header comment states the reducer "clears currentTool / thinking / waiting on
that transition". So finishing a turn actively clears any waiting state.

The three detectors in `computeAgentEnrichmentPromise`
(`src/lib/agent-enrichment.ts:505`) then all miss:

```ts
const detection = questionDetection ?? runtimeDetection ?? paneDetection ?? fallbackDetection
```

- `questionDetection` — needs an AUQ tool_use in the JSONL. A prose question has none.
- `runtimeDetection` — needs `runtimeState.state === 'waiting-on-human'`, which only
  Claude Code's `Notification` hook produces. It did not fire;
  `pending-events.jsonl` was empty after 36 minutes.
- `paneDetection` — `detectAwaitingInputForAgent` matches only *modals*. Read
  `src/lib/agent-input-detection.ts:109-162`: permission menus (`1. Yes` / `2. Yes,
  and allow` / `3. No`), `[y/N]` confirms, "planning finalized — click Done",
  session-resume, rate-limit ("keep current model" + "switch to X"). A prose question
  above an empty composer matches none.
- `fallbackDetection` — needs `resolution === 'needs_input'`. It was `working`.

**The conceptual gap:** an interactive session does not *finish*, it *yields the
turn*. Overdeck models turn-end as `idle`, and `idle` carries no operator signal.

**Decision (made here, not left to the executor):** for an **interactive role** with a
**live tmux session**, `activity: idle` means the operator's move. Emit
`pendingInputKinds: ['agentTurnEnded']`. Do **not** apply this to autonomous roles —
a work agent's idle can mean between-items or complete, and flagging those would
flood the surface and destroy its signal.

### Defect B — the Needs-you list cannot see conversations

`selectPendingInputSubjects` (`src/dashboard/frontend/src/lib/store.ts:400`) derives
from `agentsById` and `channelPermissionRequestsById` only. Conversations arrive on a
separate REST endpoint, `/api/conversations/pending-input`, consumed only by
`usePendingInputDialogs.ts:119` to feed the modal.

So a question from a regular conversation or the flywheel reaches the modal but is
**invisible** in the one list that claims to show what needs you. If the modal is
dismissed or missed, the question is unreachable.

## Requirements

### Functional

- **FR-1** An interactive-role agent (`plan`, conversation) whose runtime activity is
  `idle` while its tmux session is live MUST report a pending input of kind
  `agentTurnEnded`.
- **FR-2** FR-1 MUST NOT apply to autonomous roles (`work`, `review`, `test`, `ship`).
- **FR-3** The `agentTurnEnded` kind MUST carry the label `Answer the agent` in
  `PENDING_INPUT_KIND_LABEL`.
- **FR-4** The `Planning` node in the Command Deck tree MUST render the pulsing
  `AwaitingInputIndicator` when it has any pending input, and clicking it MUST
  re-open the dialog for that subject via `requestReopen`.
- **FR-5** An issue row in the Command Deck tree MUST be visually shaded when any
  descendant session has pending input, so the issue reads as needing attention
  without expanding it.
- **FR-6** A single selector MUST enumerate every outstanding decision across agents,
  conversations, and permission requests.
- **FR-7** The Decisions surface MUST appear in three placements: a persistent count
  in the sidebar rail, a topbar peek popover, and a full inbox view.
- **FR-8** Decisions MUST be grouped by consequence — *Blocking work* (an agent has
  stopped) vs *Waiting* (work continues) — not by kind.
- **FR-9** Dismissing a dialog MUST NOT remove its Decisions entry. An entry clears
  only when the underlying input is genuinely resolved.

### Non-functional

- **NFR-1** The interactive-idle check MUST NOT add JSONL or pane I/O per poll beyond
  what the enrichment poller already performs.
- **NFR-2** All new UI MUST conform to `design/style-guide/STYLE-GUIDE.md`: DM Sans,
  no weight above 500, SF Mono for identifiers only, badges at `rounded-sm` with the
  8%/32% tint formula, and at most one colored signal per row.

## Design decisions

Stated plainly so no executor has to guess.

**Amber identifies the surface, not the row.** Every Decisions item is "a human must
act", which is amber by the style guide's table. Painting every row amber triggers the
guide's own failure mode — when everything is colored, nothing is. Amber marks the
surface (rail count, triangle, section heads). Each row carries a status left-border
plus exactly one colored badge (its kind). Red is reserved for genuinely stopped
agents. **Rows must not also carry a triangle** — border + badge + triangle is three
signals for one concept, which the guide forbids.

**Grouping by consequence, not kind.** Kind tells you what the dialog *is*; consequence
tells you whether it matters. Kind lives in the badge.

**Issue shading is a tint, not a border.** Issue rows already use their left border for
status. Shading uses a low-alpha amber background so it composes with the existing
border rather than fighting it.

### 2 — Detect interactive idle

*What/why:* FR-1, FR-2, NFR-1.

File: `src/lib/agent-enrichment.ts`, inside `computeAgentEnrichmentPromise`.

`role` and `runtimeState` are already resolved above; this adds no I/O.

```ts
// An interactive session does not finish — it yields the turn. Turn-end
// (stop-hook → activity idle) is the operator's move, and a prose question
// leaves no other trace: no AUQ tool_use, no modal in the pane. Autonomous
// roles are excluded — their idle can mean between-items or complete.
const isInteractiveRole = role === 'plan' || agentId.startsWith('conv-')
const turnEndedWaiting = isInteractiveRole && runtimeState?.state === 'idle'
```

Fold into the detection chain *below* the existing detectors so a real AUQ or modal
still wins the `reason`/`prompt`, and push the kind inside the
`!shouldSuppressPendingInput` block:

```ts
if (turnEndedWaiting && !pendingInputKinds.includes('agentTurnEnded')) {
  pendingInputKinds.push('agentTurnEnded')
}
```

`hasPendingQuestion` must become true for this case.

*Proves it:* new cases in `src/lib/__tests__/compute-agent-enrichment.test.ts` —
a `plan`-role idle agent yields `agentTurnEnded`; a `work`-role idle agent does not;
an active `plan` agent does not.

## Known adjacent defects (explicitly out of scope)

Recorded so they are not rediscovered as surprises:

1. **`pendingProposedPlan` is a dead wire.** `agent-enrichment-service.ts` reads
   `enrichment.pendingProposedPlan` at lines 54 and 238, but that property does not
   exist on `AgentEnrichment`. It is always `undefined`, so plan payloads never reach
   the store from the agent path. Fixing it makes plan dialogs start appearing where
   they never have — a behavior change needing its own decision.
2. **The dashboard server is not typechecked.** Root `tsconfig.json` has
   `"exclude": [..., "src/dashboard/**/*"]` and `src/dashboard/server/package.json`
   has no `typecheck` script. That is why defect 1 compiles. Closing this hole will
   surface a backlog of latent errors and deserves its own issue.
