## Glossary

- **CodeRabbit** — an AI code-review SaaS that posts PR review comments when quota is available. It is NOT installed today: no `.coderabbit.yaml` exists, no `coderabbit` references appear in `src/` or config files (grep-verified at `Verified-Against` SHA), and no `coderabbitai` comments appear on recent PRs.
- **Opportunistic** — CodeRabbit reviews some PRs when quota allows and silently skips others. Absence of a review MUST be indistinguishable from CodeRabbit-passed. This is the core safety invariant.
- **Review convoy** — the four-subagent review pipeline spawned by `spawnReviewRoleForIssuePromise` in `src/lib/cloister/review-agent.ts` (grep anchor: `spawnReviewRoleForIssuePromise`). It spawns `security`, `correctness`, `performance`, `requirements` sub-reviewers and a synthesis agent.
- **`buildReviewSubRolePrompt`** — builds the per-sub-role convoy spawn message; grep anchor: `function buildReviewSubRolePrompt`. Located at `src/lib/cloister/review-agent.ts`.
- **`spawnReviewRoleForIssuePromise`** — the async function that orchestrates the full convoy spawn; grep anchor: `async function spawnReviewRoleForIssuePromise`. Located at `src/lib/cloister/review-agent.ts`.
- **`setReviewStatus` / `reviewGatesPassedSync`** — the merge-readiness computation. Located at `src/lib/review-status.ts`. `readyForMerge` is derived at every write from `hasBlockers`, explicit overrides, and `reviewGatesPassedSync(merged)` — grep anchor: `readyForMerge is EVENT-DRIVEN`. No CodeRabbit state may participate in this computation.
- **PR comment plumbing** — two existing utilities: `postPrComment` in `src/lib/cloister/review-verdict-feedback.ts` (grep anchor: `async function postPrComment`) posts via `gh api repos/.../issues/:n/comments`; `fetchDiscussions` in `src/lib/overdeck/discussions.ts` (grep anchor: `pulls/${prNumber}/reviews?per_page=100`) fetches PR review submissions authored by any user.
- **Lint guard script** — a shell script in `scripts/` that exits non-zero if `coderabbit` appears in structural merge-path files, wired into `npm run lint`.

## Problem

CodeRabbit reviews can surface actionable findings cheaply and complement our convoy reviewers. However, three failure modes must be prevented:

1. **Gating on absence.** CodeRabbit reviews appear only sometimes (quota). Any code path that reads CodeRabbit state and blocks on its absence will create intermittent failures — the exact class this epic eliminates (Principle 1: nothing intermittent may gate).
2. **Drift into structural paths.** Once a CodeRabbit ingestion helper exists, future contributors may accidentally wire it into `review-status.ts`, `deacon-merge.ts`, or `verification-runner.ts`. The invariant must be enforced mechanically, not by convention.
3. **Unanswered review threads.** CodeRabbit comments that the agent addresses but never replies to leave the PR history with unresolved threads, degrading code-review hygiene.

## Requirements

- **FR-1** — A `.coderabbit.yaml` config file MUST exist at the repo root tuned for this repo's conventions (path filters, review profile, review dimensions matching the convoy's).
- **FR-2** — Before spawning the review convoy, `spawnReviewRoleForIssuePromise` MUST attempt to fetch CodeRabbit review comments for the PR and, if any are present, inject a summarized findings block into the sub-role spawn prompts. If none are present (quota miss or quota exhausted), the convoy spawns identically to today — no indication of absence, no failure.
- **FR-3** — When a work agent addresses or rejects a CodeRabbit finding (after a review cycle completes), it MUST reply to the CodeRabbit PR thread via the existing `postPrComment` helper. The reply text MUST follow a canonical template defined in this PRD so cheap-model executors produce consistent output.
- **FR-4** — The merge-readiness computation in `src/lib/review-status.ts` MUST have zero CodeRabbit state as input. Mechanically enforced by: (a) a unit test asserting `setReviewStatus` / `reviewGatesPassedSync` have no CodeRabbit input even when a CodeRabbit review object is passed in the environment; and (b) a lint-guard script `scripts/lint-no-coderabbit-merge-gate.sh` that fails if `coderabbit` (case-insensitive) appears in `src/lib/review-status.ts`, `src/lib/cloister/deacon-merge.ts`, or `src/lib/cloister/verification-runner.ts`. The script is wired into `npm run lint`.
- **NFR-1** — No new explicit `any`; async only (no `execSync` in server-reachable code).
- **NFR-2** — No new non-test source file ≥1,000 lines.
- **NFR-3** — Quota reality is documented inline in code: a zero-finding result from the CodeRabbit fetch MUST be treated identically to a network error or absence — zero difference in convoy behavior.

### W2 — CodeRabbit findings ingestion into convoy spawn (FR-2)

**File:** `src/lib/cloister/coderabbit-ingestion.ts` (new file, <200 lines).

This module encapsulates the CodeRabbit fetch and summary so the convoy spawn code stays under its ceiling and the ingestion logic is independently testable.

```ts
// src/lib/cloister/coderabbit-ingestion.ts

/**
 * Fetches CodeRabbit review comments for a PR and returns a formatted findings
 * block for injection into convoy spawn prompts.
 *
 * IMPORTANT — quota invariant: this function MUST return null for EVERY failure
 * mode (no reviews, network error, CodeRabbit absent, quota miss). Callers must
 * treat null identically to "CodeRabbit was not configured" — zero effect on
 * convoy behavior. Never throw; swallow all errors.
 */
export async function fetchCodeRabbitFindings(opts: {
  prOwner: string;
  prRepo: string;
  prNumber: number;
}): Promise<string | null>;
```

**Implementation details:**

1. Call `gh api "repos/${opts.prOwner}/${opts.prRepo}/pulls/${opts.prNumber}/reviews?per_page=100"` using `execAsync` (the same pattern as `src/lib/overdeck/discussions.ts:239`, grep anchor: `pulls/${prNumber}/reviews?per_page=100`).
2. Filter for items where `user.login === 'coderabbitai[bot]'` and `state !== 'DISMISSED'`.
3. Also call `gh api "repos/${opts.prOwner}/${opts.prRepo}/pulls/${opts.prNumber}/comments?per_page=100"` (inline review comments, same pattern as `src/lib/overdeck/discussions.ts:272`, grep anchor: `pulls/${prNumber}/comments?per_page=100`) and filter for `user.login === 'coderabbitai[bot]'`.
4. If the union of findings is empty, return `null`.
5. If non-empty, return a Markdown block:

```
---
## CodeRabbit findings (advisory — non-gating)

The following findings were left by CodeRabbit on this PR. They are context for
your review, not additional acceptance criteria. The convoy verdict is entirely
determined by the PR diff and the existing AC checklist.

${findings.map(f => `- **${f.path ?? 'general'}${f.line ? `:${f.line}` : ''}**: ${f.body.slice(0, 300)}`).join('\n')}
---
```

6. Wrap the entire function body in a `try/catch`; on any error log a `[coderabbit-ingestion] fetch failed — skipping: ${err.message}` warning and return `null`. No rethrow.

**Injection point in convoy spawn:**

In `spawnReviewRoleForIssuePromise` (grep anchor: `async function spawnReviewRoleForIssuePromise`), after the context manifest build block (grep anchor: `Context manifest built`) and before the call to `buildReviewSubRolePrompt`, add:

```ts
// Fetch CodeRabbit findings opportunistically — null means not present or quota miss.
// Treat null identically to absent: no effect on convoy behavior (FR-2, NFR-3).
let coderabbitBlock: string | null = null;
if (opts.prUrl) {
  const parsed = parseGitHubPrUrl(opts.prUrl);
  if (parsed) {
    coderabbitBlock = await fetchCodeRabbitFindings({
      prOwner: parsed.owner,
      prRepo: parsed.repo,
      prNumber: parsed.number,
    }).catch(() => null);
  }
}
```

Pass `coderabbitBlock` into `buildReviewSubRolePrompt`. In that function (grep anchor: `function buildReviewSubRolePrompt`), append the block after the `template.trim()` line and before the closing sentinel, only when non-null:

```ts
coderabbitBlock ? coderabbitBlock : null,
```

**Tests:** `tests/unit/lib/cloister/coderabbit-ingestion.test.ts` (new file):

- returns `null` when `gh api` throws;

### W4 — Structural non-gating invariant: lint guard + unit test (FR-4)

**Part A — lint-guard script:** `scripts/lint-no-coderabbit-merge-gate.sh` (new file):

```bash
#!/usr/bin/env bash
# lint-no-coderabbit-merge-gate.sh — CodeRabbit MUST NOT appear in merge-gate files.
# CodeRabbit is opportunistic and structurally non-gating (PAN-2374).
# Absence of a review must be indistinguishable from passing.
set -euo pipefail
cd "$(dirname "$0")/.."

GATE_FILES=(
  "src/lib/review-status.ts"
  "src/lib/cloister/deacon-merge.ts"
  "src/lib/cloister/verification-runner.ts"
)

fail=0
for f in "${GATE_FILES[@]}"; do
  if [[ ! -f "$f" ]]; then continue; fi
  if grep -qi "coderabbit" "$f"; then
    echo "✖ $f references 'coderabbit' — CodeRabbit state must never reach the merge gate (PAN-2374)."
    fail=1
  fi
done

if (( fail )); then
  echo ""
  echo "CodeRabbit ingestion belongs only in src/lib/cloister/coderabbit-ingestion.ts"
  echo "and its callers inside the convoy spawn (review-agent.ts)."
  exit 1
fi

echo "✓ no-coderabbit-merge-gate guard passed"
```
