# PAN-3743 — Dashboard REST/RPC requests queue >20s during 5-minute cost-reconcile windows

**Issue:** https://github.com/eltmon/overdeck/issues/3743
**Status:** draft PRD
**Author:** conversation conv-20260816-9367, 2026-08-16

## Glossary

- **DB job worker** — the worker-thread pool behind `runDashboardDbJob()` in
  `src/dashboard/server/services/dashboard-db-task.ts`. Route handlers and RPC methods enqueue
  named operations (`listSessionsFeed`, `scanConversations`, …); workers execute them off the
  main thread. `MAX_PENDING_JOBS` bounds the queue; `workerLane(operation)` picks the lane.
- **Cost-reconcile sweep** — the periodic job in
  `src/dashboard/server/services/cost-reconcile-service.ts` (interval `RECONCILE_INTERVAL_MS =
  5 * 60_000`, line 6; started in `startCostReconcileService()`, line 48). Each sweep runs
  `reconcilePiTranscripts()`, `reclassifyUnknownCostEventsSync()`, and a codex `CostWriter.reconcile`.
- **Burst window** — the seconds around each sweep firing, when the server also runs the GitHub
  tracker sync. Observed live 2026-08-16: `[cost-reconcile] skipped …: unknown-model` /
  `no-usage` floods (hundreds of lines), event-loop p99 warnings of 100–150 ms, REST responses
  exceeding client timeouts.
- **Awareness panel** — the activity sidebar (CommandDeck). Its fetches go through
  `fetchWithTimeout` (`src/dashboard/frontend/src/lib/apiFetch.ts:17`, default `timeoutMs = 20_000`).
  When a request exceeds 20 s the panel renders the abort error text `signal timed out`.

## Problem (verified 2026-08-16)

1. The sweep runs **synchronous I/O on the server main thread**:
   - `src/lib/costs/reconciler.ts:23` imports `readFileSync, readdirSync, openSync, readSync, fstatSync`
     and uses them in the transcript walk (lines 159–186 read `sessions.json` + `state.json` per
     agent dir; lines 275–291 read JSONL tails). The agents dir has ~400 entries.
   - `src/lib/costs/attribution.ts:32` — `reclassifyUnknownCostEventsSync()` does synchronous DB
     work in-process.
2. The sweep **re-visits the same historical files every 5 minutes**. The `[cost-reconcile] skipped
   …` flood lists the same 2026-07/2026-08 rollout files on every sweep; the skip verdict is
   recomputed by re-reading each file.
3. During burst windows, user-facing reads stall past 20 s: Awareness shows `signal timed out`;
   opening a conversation leaves the panel empty for many seconds. WS RPC `getSnapshot` stays fast
   (~20 ms observed), so the stall is in queued/blocked work, not uniform event-loop death — but
   the sync I/O in (1) contributes repeated 100–150 ms main-thread pauses.

Repo rules that intersect (restated so the executor does not need to recall them):

- **No `execSync` (and by extension no bulk sync fs I/O) in dashboard-server-reachable code** —
  blocks the event loop (PAN-70). Use async fs or a worker.
- **Fake timers for delay/interval tests** — any test around `RECONCILE_INTERVAL_MS` must use
  `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`; never real waits.
- **One read door / one write door** — new instrumentation goes through the telemetry write door
  (`docs/TELEMETRY.md`), not ad-hoc files.

## Requirements

- **FR-1** The cost-reconcile sweep must not execute synchronous fs or DB work on the dashboard
  server main thread.
- **FR-2** The sweep must persist per-file skip verdicts keyed by `(path, mtimeMs, size)` so a file
  whose verdict is known and whose stat is unchanged is skipped without opening it, and without
  logging a per-file line.
- **FR-3** `runDashboardDbJob` must record queue wait (enqueue→start) and execution time
  (start→finish) per job, log any job whose wait or run exceeds 1 s with operation name and lane,
  and keep a per-lane depth gauge readable in the log.
- **FR-4** Interactive read operations (`listSessionsFeed`, `getSessionsFeedFacets`,
  `getConversationByName`, `getDiscoveredSessionById`) must not share a worker lane with bulk
  operations (`scanConversations`, `enrichSessions`, `embedSessions`). Verify the current
  `workerLane()` mapping in `src/dashboard/server/services/dashboard-db-task.ts` and correct it if
  any interactive op shares the bulk lane.
- **NFR-1** During a sweep, REST and RPC read endpoints respond in <2 s.
- **NFR-2** One hour of normal operation produces zero `signal timed out` renders in Awareness and
  zero `fetchWithTimeout` aborts in the browser console.

## Work items

### 1. Skip-verdict cache for the reconciler (FR-2)

Files: `src/lib/costs/reconciler.ts`.

Add a small persistent cache (SQLite table `cost_reconcile_file_state` in the overdeck DB the cost
door already opens, or a JSON sidecar under `${OVERDECK_HOME}/costs/` if the DB migration is
disproportionate — decide for the DB table; the cost door already owns migrations). Schema:
`path TEXT PRIMARY KEY, mtime_ms INTEGER, size INTEGER, verdict TEXT` where verdict ∈
`imported | no-usage | unknown-model | error`.

In the walk, before parsing a file: `stat` it; on `(mtime_ms, size)` match with a terminal verdict,
skip silently. After parsing, upsert the verdict. Files that produced `error` are retried (do not
cache errors as terminal). Log one summary line per sweep:
`[cost-reconcile] sweep: N files, M cache-skipped, K parsed, I imported`.

### 2. Move sweep work off the main thread (FR-1)

Files: `src/dashboard/server/services/cost-reconcile-service.ts`,
`src/dashboard/server/services/dashboard-db-task.ts`, `src/lib/costs/attribution.ts`.

Add a `costReconcileSweep` operation to the DB job worker (`DashboardDbOperation` union +
`runInline` switch in `dashboard-db-task.ts:205`), executing the body of `runCostReconcileOnce`
inside the worker. `cost-reconcile-service.ts` keeps the interval/dedup shell and calls
`runDashboardDbJob('costReconcileSweep')`. Route it to the **bulk** lane (FR-4).

Before (cost-reconcile-service.ts:13-14):
```ts
  inFlight = (async () => {
    const result = await reconcilePiTranscripts();
```
After:
```ts
  inFlight = (async () => {
    const result = await runDashboardDbJob<ReconcileResult>('costReconcileSweep', { reason });
```
`reclassifyUnknownCostEventsSync()` moves inside the worker job unchanged (it is only "sync" with
respect to its own thread, which is now a worker). The `cost.recorded` bus announcement must still
happen in the server process — return imported event summaries from the job and emit from the
service shell (the event bus does not exist in the worker). Check what `CostWriter.reconcile`
emits and preserve equivalent behavior; if the emit-from-worker problem makes this item balloon,
fall back to worker-izing only `reconcilePiTranscripts`'s **file walk + parse** (return parsed
`CostEvent[]`, run `record()` in-process) — that removes ~all of the sync fs I/O, which is the
point of FR-1.

### 3. Queue instrumentation (FR-3)

File: `src/dashboard/server/services/dashboard-db-task.ts` (`runDashboardDbJob`, line 267; the
worker message handlers around lines 100–200).

Stamp `enqueuedAt` when the job is created and `startedAt` when the worker picks it up; on
completion compute `waitMs` / `runMs`. Log
`[db-jobs] slow: op=<operation> lane=<lane> waitMs=<n> runMs=<n> depth=<pending.size>` when either
exceeds 1_000. This is a log-only surface; no new HTTP endpoint (one read door — do not add an
ad-hoc stats route).

### 4. Lane audit (FR-4)

File: `src/dashboard/server/services/dashboard-db-task.ts` (`workerLane`).

Read the current mapping; assert in a unit test that every interactive op listed in FR-4 maps to a
different lane than every bulk op. Fix the mapping if the assertion fails today.

### 5. Documentation

- `docs/DASHBOARD-ARCHITECTURE.md` — add a "DB job worker lanes" subsection: lanes, which ops are
  interactive vs bulk, the 1 s slow-job log line format, and the costReconcileSweep job.
- `docs/TELEMETRY.md` — note the slow-job log line as a diagnostic surface.
- Module header of `cost-reconcile-service.ts` — describe the worker-delegation shape and the
  skip-verdict cache.

### 6. Tests

- `tests/unit/lib/costs/reconciler-skip-cache.test.ts` — verdict cached → file not re-opened
  (spy on fs open); mtime bump → re-parsed; `error` verdict → retried.
- `tests/unit/dashboard/db-task-lanes.test.ts` — FR-4 lane assertion.
- Interval behavior tests use fake timers (`vi.useFakeTimers()` — repo rule; never real 5-minute
  waits).

## Acceptance criteria

- **AC-1 (↔FR-1/WI-2)** `grep readFileSync\|readdirSync src/lib/costs/reconciler.ts` call sites are
  only reachable from worker context (or the fallback shape is in place and the server main thread
  performs no per-file fs calls during a sweep).
- **AC-2 (↔FR-2/WI-1)** Two consecutive sweeps over an unchanged corpus: the second logs
  `cache-skipped == N-0` and produces zero per-file `skipped` lines.
- **AC-3 (↔FR-3/WI-3)** Artificially delaying a worker job produces the `[db-jobs] slow:` line with
  correct waitMs/runMs/depth.
- **AC-4 (↔FR-4/WI-4)** Lane unit test green.
- **AC-5 (↔NFR-1/NFR-2)** Live observation: during one sweep window, `curl -w %{time_total}` on
  `/api/activity` and a conversation transcript fetch both return <2 s; one hour with no
  `signal timed out` in Awareness.
- **AC-6 (↔WI-5)** Named docs updated in the same PR.

## Implementation checkpoint

The exact endpoint that produced the operator's `signal timed out` was not pinned (the Awareness
panel makes several fetches). After WI-3 lands, reproduce a burst window and read the slow-job log
to identify it; if it is not a DB-job op at all (e.g. a route doing its own I/O), file a follow-up
scoped to that route rather than stretching this PRD.
