Telemetry

Anonymous usage data helps prioritize what to build. It never includes your code, prompts, or project names.

Share anonymous usage data
Counts and outcomes only — which features get used and where the pipeline stalls. Changes apply the next time the dashboard loads.
Telemetry on · reporting as install 3f9c…b21e (a random ID — not you, not your machine)

What's sent

  • Feature usage — tab views, agent spawns, merges, plan approvals
  • pan command names and success/failure
  • Pipeline stage outcomes, per harness and model
  • Crash reports (stack traces, paths stripped)
  • App version, OS, and a random install ID

Never sent

  • Code, diffs, prompts, or agent transcripts
  • File paths and repository names
  • Issue titles and branch names
  • Anything from other tools' config or credentials

The full event list lives in docs/TELEMETRY.md and is enforced by CI.

Also configurable outside the dashboard

# ~/.overdeck/config.yaml
telemetry:
  enabled: false
# or per-shell — the environment variable always wins
OVERDECK_TELEMETRY=0

When off, Overdeck makes zero requests to *.posthog.com — from the dashboard, the server, and the CLI.

Interaction notes: the switch writes telemetry.enabled via PUT /api/settings; the status line flips immediately, capture stops on next dashboard load (server and CLI read the flag per run). Off-state dims “What's sent” to reinforce that nothing leaves the machine.
