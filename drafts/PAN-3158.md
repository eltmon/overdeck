# PAN-3158 — Awaiting Merge: hide projects with nothing ready

**Issue:** [PAN-3158](https://github.com/eltmon/overdeck/issues/3158)
**PRD status:** draft for xBRIEF lowering, authored in `--auto` planning mode (no interactive Q&A; decisions recorded in the xBRIEF `autoDecisions[]`).

## Glossary

- **Merge train** — the per-project batching engine that assembles features which passed review and tests into one UAT batch per project. Design doc: `docs/UAT-BATCH-TRAINS.md`.
- **Section** — one project's block on the Awaiting Merge page, rendered by `MergeTrainView.tsx` as `<section data-testid="merge-train-project-<key>">`.
- **Queue** — `section.queue`: ready-to-merge features for that project, from `GET /api/merge-train/queues`.
- **Generation** — a UAT batch. `visibleGenerationsOf(section)` (`MergeTrainView.tsx:152`) keeps only `assembling` / `ready` / `superseded` generations.
- **Idle section** — a section with `queue.length === 0 && visibleGenerationsOf(section).length === 0`. New term introduced by this change.
- **Enabled / disabled** — `section.enabled`: whether the merge train is on for that project. Disabled sections render "merge train off" copy (`MergeTrainView.tsx:519-522`).
- **Project filter chips** — the per-project toggle buttons at `MergeTrainView.tsx:448-477`, persisted to localStorage. Distinct from the idle filter this PRD adds.

## Problem

The Awaiting Merge page renders a section for **every** registered project. With
eight projects registered and one with ready work, the operator reads seven
identical copies of:

> No features are ready to merge. When work passes review and tests, it lines up
> here and a test batch assembles automatically.

The repeated boilerplate is noise that pushes the one section carrying real
information down the page.

## Requirements

### Functional

- **FR-1** — A section whose train is **on** and which is idle (no queue, no visible generations) is not rendered.
- **FR-2** — A section whose train is **off** (`enabled: false`) renders exactly as it does today, idle or not. The existing comment at `MergeTrainView.tsx:427-432` is correct: "the train is OFF here" is a different answer from "nothing is ready", and hiding it would send the operator hunting for work that was never coming.
- **FR-3** — When the filter leaves nothing to render, the page falls through to the existing page-level empty state (`MergeTrainView.tsx:487`, "No features are ready to merge in any project. …") so the page is never blank. This includes the edge where the operator's project-filter chips select only idle enabled projects.
- **FR-4** — When at least one section renders and at least one idle enabled section was hidden, a quiet footer line states the omission: *"N projects with nothing ready are hidden"* (singular: *"1 project with nothing ready is hidden"*).
- **FR-5** — A section with a queue or a visible generation renders exactly as it does today.

### Non-functional

- **NFR-1** — The behavior change is anchored by the existing `MergeTrainView` test suite: the page-level-message-absent assertions at `__tests__/MergeTrainView.test.tsx:222` and `:239` keep passing unchanged.
- **NFR-2** — No server, API, or data-shape changes; the filter is a pure render-time derivation from data the view already holds.

## Proposal (before/after)

### 1. Add an idle predicate and a render filter

After `visibleGenerationsOf` (line 156), add:

```ts
/** A section with nothing to show: no ready features, no visible batches. */
function isIdleSection(section: MergeTrainProjectSection): boolean {
  return section.queue.length === 0 && visibleGenerationsOf(section).length === 0;
}
```

After `visibleSections` (line 267), add:

```ts
// Idle enabled sections are hidden outright — repeating "No features are ready
// to merge" under every project name is noise. Disabled sections are NEVER
// idle-hidden: "merge train off" is information, not emptiness, so a disabled
// row always renders even when it has nothing queued. This filter replaces the
// old anyDisabled/nothingAnywhere collapse guard with the same invariant
// encoded structurally: any disabled row keeps renderedSections non-empty.
const renderedSections = visibleSections.filter((s) => !s.enabled || !isIdleSection(s));
const idleHiddenCount = visibleSections.length - renderedSections.length;
```

Delete the `anyDisabled` / `nothingAnywhere` block (lines 427–438); its
invariant moves into the filter above. This is a deliberate replacement, and
the no-loss check is: every state that previously collapsed to the page-level
message (all projects enabled + idle) still collapses, because every section is
then idle-hidden and `renderedSections` is empty; every state that previously
refused to collapse (any disabled project) still refuses, because disabled
sections are never filtered out.

### 2. Restructure the JSX conditional (lines 479–493)

Before: `sections.length === 0 → nothingAnywhere → visibleSections.length === 0 → map`.

After:

```tsx
{sections.length === 0 ? (
  <p /* unchanged: loading / no-projects copy */>
) : visibleSections.length === 0 ? (
  <p /* unchanged: "Every project is filtered out…" chip copy */>
) : renderedSections.length === 0 ? (
  <p className="px-1 py-1.5 text-xs text-muted-foreground">
    {loading
      ? 'Loading the merge train…'
      : 'No features are ready to merge in any project. When work passes review and tests, it lines up here and a test batch assembles automatically.'}
  </p>
) : (
  <>
    <div className="space-y-3">
      {renderedSections.map((section) => { /* unchanged section body */ })}
    </div>
    {idleHiddenCount > 0 && (
      <p className="px-1 pt-1 text-[10.5px] text-muted-foreground" data-testid="merge-train-idle-hidden-note">
        {idleHiddenCount} project{idleHiddenCount === 1 ? '' : 's'} with nothing ready {idleHiddenCount === 1 ? 'is' : 'are'} hidden
      </p>
    )}
  </>
)}
```

The `loading` ternary inside the third branch preserves the old `!loading`
guard from `nothingAnywhere`: while one of the two queries is still fetching,
`renderedSections` can be transiently empty and the page must say "Loading…"
rather than flash the empty state.

### 3. Remove the now-dead per-section idle branch (lines 523–526)

After the filter, every enabled section in `renderedSections` has a queue or a
visible generation, so the `featureCount === 0 && visibleGenerations.length === 0`
ternary branch ("No features are ready to merge. When work passes review and
tests, …") is unreachable. Simplify the section body to
`!section.enabled ? off-copy : content`, removing the dead middle branch. The
off-copy (lines 519–522) stays verbatim.

## Decisions made in this doc (auto mode)

1. **Include the optional footer line** (FR-4). The issue marks it optional but
   recommends it ("keeps the page honest about what it is not showing"); it is
   two lines of JSX and one assertion.
2. **Replace `anyDisabled`/`nothingAnywhere` with the `renderedSections`
   filter** rather than keeping both. Two branches with identical copy is
   redundant; the filter encodes the same invariant structurally. The
   replacement equivalence is argued in Proposal §1 and covered by the existing
   all-disabled and mixed tests.
3. **Chip-filter edge falls to the page-level empty copy** (FR-3): if the
   operator's chips select only idle enabled projects, the page shows the
   "No features are ready to merge in any project" message rather than a blank
   area — the issue's point 3 made this call explicitly.
4. **Project filter chips still list every project**, idle or not. The chips
   are the operator's selection tool; hiding idle projects from them would make
   an idle project unselectable and contradict FR-3's edge case.

## Acceptance criteria

1. Given a project with train on, empty queue, and no visible generations, when the Awaiting Merge page renders alongside any project that has ready work, then the idle project's section testid is absent from the DOM.
2. Given a project with train off, when the page renders, then its section renders with "merge train off" and the "turned off for <name>" copy whether or not it is idle.
3. Given every registered project is enabled and idle, when the page finishes loading, then the page-level "No features are ready to merge in any project" message renders and no project section testid is present.
4. Given at least one section renders and at least one idle enabled section is hidden, then the footer renders "N project(s) with nothing ready is/are hidden" with correct singular/plural forms.
5. Given a project with a non-empty queue or a visible generation, then its section renders byte-identical copy to before the change (queue count, batch list, escape hatch).
6. `npx vitest run src/dashboard/frontend/src/components/merge-train/__tests__/MergeTrainView.test.tsx` exits 0, including the unchanged page-message-absent assertions at lines 222 and 239.
7. `docs/UAT-BATCH-TRAINS.md` §"Multi-project shape" states that idle enabled projects are hidden; `grep -n "hidden" docs/UAT-BATCH-TRAINS.md` finds the sentence.
