# PAN-1610 — One issue-action registry rendered on every surface

**Issue:** https://github.com/eltmon/overdeck/issues/1610
**Mockup (BINDING):** [`docs/design/mockups/issue-actions-one-registry-pan-1610.html`](https://github.com/eltmon/overdeck/blob/main/docs/design/mockups/issue-actions-one-registry-pan-1610.html) — v2: registry hub, per-surface presentation modes, today-vs-proposed drift matrix, five-surface parity contract.
**Depends on:** PAN-2499 (one IssueView family = one actions mount per density) and PAN-2661 (grouping + descriptions moved into the registry; grouped context menu shipped). Do not start before both merge.

## Glossary

- **Registry / hook / groups** — as defined in the PAN-2661 PRD (same files). After PAN-2661, `issueActions.ts` owns `GROUP_ORDER`/`GROUP_LABELS`/`description` and the grouped context-menu renderer exists.
- **The five surfaces** — (1) cockpit header `IssueActionMegaMenu` (`Stage/cockpit/IssueMissionControl.tsx:174,770`); (2) rail right-click `FeatureContextMenu` (grouped after PAN-2661); (3) board cards + (4) drawer action bar, both via the hybrid toolbar `IssueActionMenu` (`components/IssueActionMenu/IssueActionMenu.tsx:264`; consumers `KanbanBoard/cards/KanbanCards.tsx`, `drawer/DrawerActionBar.tsx:12-25` which also bolts a `MergeButton` beside it); (5) **Zone B action strip** — already registry-driven via session-scoped entries tagged `ownerSurface: 'ZoneBActionStrip'` (`issueActions.ts:130-135`: View terminal, View State.md, View vBRIEF, Copy Session ID, Copy tmux command). Surface 5 is the existing proof of the mechanism this issue generalizes.
- **Presentation mode** — a declared rendering of the registry: `grouped-panel` (cockpit popover), `grouped-context` (right-click), `primary-strip` (phase-primary buttons + a grouped overflow), optionally with `pinned` actions (drawer pins merge).

## Decisions

- **D-1 — Surfaces declare a mode; the registry owns everything else.** Item set, gating, groups, order, descriptions, confirm flows, dialogs — all from `issueActions.ts`/`useIssueActions`. A surface contributes only `{ mode, pinned?, surfaceExtras? }`.
- **D-2 — Surface extras become registry entries with `ownerSurface` tags** (the existing `issueActions.ts:130-135` pattern). Open State Dir and View JSONL register as `scope: 'session', ownerSurface: 'rail-session'`; PAN-2661's temporary `sessionExtras` props are removed. Confirm flows and the parity test cover them like every other entry.
- **D-3 — The hybrid toolbar becomes `primary-strip` mode.** `IssueActionMenu`'s primary buttons stay; its flat overflow is replaced by the PAN-2661 grouped menu opened from the `⋯` button. The drawer's ad-hoc `MergeButton` composition (`DrawerActionBar.tsx:20-25`) becomes `pinned: ['merge']` in its mode declaration — same button component, declared rather than bolted on.
- **D-4 — Cockpit panel converges on the shared renderer.** `IssueActionMegaMenu` renders the same grouped body as the context menu (popover chrome differs; content component is shared). Its Danger section adopts the collapsed-disclosure behavior for consistency.
- **D-5 — No new action semantics.** Zero changes to predicates, endpoints, dialogs, or confirm text anywhere in this issue.

## Requirements

- **FR-1** A `renderIssueActions(mode, state)` layer (or equivalent component set) such that all five surfaces contain no action definitions, no group lists, and no ordering logic of their own.
- **FR-2** Board + drawer render `primary-strip` with grouped overflow (D-3); drawer declares `pinned: merge`.
- **FR-3** Cockpit panel renders the shared grouped body (D-4).
- **FR-4** Rail session extras registered per D-2; `sessionExtras` prop deleted.
- **FR-5** Five-surface parity test: for fixture states in ≥3 phases, every surface's reachable action set ≡ registry (filtered by scope/ownerSurface), identical gating, danger last, zero out-of-registry items — asserted by introspecting rendered output, not by trusting props.
- **NFR-1** No layout regressions on kanban cards (strip width budget unchanged — overflow absorbs everything beyond the phase primaries).
