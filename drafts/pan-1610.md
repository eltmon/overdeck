## Glossary

- **Registry / hook / groups** — as defined in the PAN-2661 PRD (same files). After PAN-2661, `issueActions.ts` owns `GROUP_ORDER`/`GROUP_LABELS`/`description` and the grouped context-menu renderer exists.
- **The five surfaces** — (1) cockpit header `IssueActionMegaMenu` (`Stage/cockpit/IssueMissionControl.tsx:174,770`); (2) rail right-click `FeatureContextMenu` (grouped after PAN-2661); (3) board cards + (4) drawer action bar, both via the hybrid toolbar `IssueActionMenu` (`components/IssueActionMenu/IssueActionMenu.tsx:264`; consumers `KanbanBoard/cards/KanbanCards.tsx`, `drawer/DrawerActionBar.tsx:12-25` which also bolts a `MergeButton` beside it); (5) **Zone B action strip** — CORRECTION from review: `ZONE_B_SESSION_ACTIONS` (`issueActions.ts:107-126`) is a **metadata inventory** (`{key,label,scope,ownerSurface}` — no predicate, handler, confirm, or description); Zone B hardcodes its own mutations (`ZoneBActionStrip.tsx:130,355`), and `issueActions.no-actions-lost.test.ts:166` proves those keys are absent from `ISSUE_ACTIONS`. So Zone B is a naming PRECEDENT, and this issue's work is to **promote** that metadata into an executable surface-action contract. Current `ownerSurface` union: `ProjectNode | ContainerNode | FeatureItem | ZoneBActionStrip`; current scope value is `session-artifact` — extend those unions, do not invent parallel ones.
- **Presentation mode** — a declared rendering of the registry: `grouped-panel` (cockpit popover), `grouped-context` (right-click), `primary-strip` (phase-primary buttons + a grouped overflow), optionally with `pinned` actions (drawer pins merge).

## Decisions

- **D-1 — Surfaces declare a mode; the registry owns everything else.** Item set, gating, groups, order, descriptions, confirm flows, dialogs — all from `issueActions.ts`/`useIssueActions`. A surface contributes only `{ mode, pinned?, surfaceExtras? }`.
- **D-2 — Surface extras are PROMOTED into an executable contract.** Open State Dir / View JSONL / Deep Wipe already exist in the metadata array (`issueActions.ts:123`); this issue gives session-scoped entries the full executable shape (predicate, invocation, description, kind, confirm) via a discriminated union with `ISSUE_ACTIONS` — one schema, two scopes. They register with the EXISTING union values (`ownerSurface: 'FeatureItem'`; `scope: 'session-artifact'`). PAN-2661's temporary `sessionExtras` props are removed. Zone B's hardcoded mutations migrate to the same contract.
- **D-3 — The hybrid toolbar becomes `primary-strip` mode.** `IssueActionMenu`'s primary buttons stay; its flat overflow is replaced by the PAN-2661 grouped menu opened from the `⋯` button, which gains a text label (`⋯ N more`) per the mockup. CORRECTION from review: `merge` is NOT a registry key — `MergeButton` (`MergeButton.tsx:23,50`) owns readiness/stuck-retry/mutation/confirm machinery. The drawer therefore declares a **typed pinned-component slot** `pinned: [{ key: 'merge', render: MergeButton }]`, and D-1 is amended: the registry owns all MENU actions; pinned slots are declared components excluded from set-parity but included in the mode declaration. The drawer's existing `pinRight={['viewPr']}` (`DrawerActionBar.tsx:15`) is PRESERVED as a registry-key pin.
- **D-4 — Cockpit panel converges on the shared renderer.** `IssueActionMegaMenu` renders the same grouped body as the context menu (popover chrome differs; content component is shared). Its Danger section adopts the collapsed-disclosure behavior for consistency.
- **D-5 — No new action semantics** for existing `ISSUE_ACTIONS` entries. The Zone B/extras promotion (D-2) ADDS contracts where none existed (hardcoded behavior is preserved verbatim as it migrates — e.g. Zone B's stop confirmation copy). Board note: `KanbanCards.tsx:607,733` carries a hardcoded Unpause + endpoint — migrate it to the registry `unpause` entry in WI-2 (same endpoint, so behavior-neutral).

## Requirements

- **FR-1** A `renderIssueActions(mode, state)` layer (or equivalent component set) such that all five surfaces contain no action definitions, no group lists, and no ordering logic of their own.
- **FR-2** Board + drawer render `primary-strip` with grouped overflow (D-3); drawer declares `pinned: merge`.
- **FR-3** Cockpit panel renders the shared grouped body (D-4).
- **FR-4** Rail session extras registered per D-2; `sessionExtras` prop deleted.
- **FR-5** Five-surface parity test built on an explicit oracle `expectedActions(registry, state, surface, context)` — surfaces legitimately differ (session extras on rail/Zone B, pinned merge on drawer), so parity means each surface ≡ its oracle output, not surface ≡ surface. Assert by introspecting rendered output; include gating identity, danger last, and zero out-of-registry MENU items (pinned component slots exempt per D-3).
- **NFR-1** No layout regressions on kanban cards (strip width budget unchanged — overflow absorbs everything beyond the phase primaries).
