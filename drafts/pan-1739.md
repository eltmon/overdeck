# PAN-1739 — Command Deck tree hides strike agents / renders dead sessions as "working"

**Issue:** [PAN-1739](https://github.com/eltmon/overdeck/issues/1739)
**Mode:** `pan plan --auto` (no interactive Q&A)

## Glossary

- **ProjectTree** — the Command Deck left-hand issue tree
  (`src/dashboard/frontend/src/components/CommandDeck/ProjectTree/`). One
  `FeatureItem` per issue; each renders `SessionNode` rows for its agent
  sessions.
- **Session node** — one row describing a spawned agent session. Backend
  contract fields used here: `type` (`work`/`strike`/`planning`/`review`/…),
  `status`, `presence`, and a separate live `runtime` snapshot
  (`agentRuntimeById[sessionId]`) carrying `activity` (`working`/`thinking`/…).
- **presence** — the liveness oracle. Derived backend-side from live tmux
  (`services/session-presence.ts`): `'ended'` when no tmux session exists,
  else `active`/`idle`/`suspended`.
- **Allowlist** — `isWorkOrSpecialistSession()` in `FeatureItem.tsx`: an
  enumeration of session `type`s that count toward a feature's aggregate
  badges, activity summary, and colored edge bar.
- **Tombstone** — a session whose process/tmux is dead but whose stale state
  still renders as if alive.

## What the issue reported (RUN-18 screenshot, 2026-06-10)

1. **RC1 — allowlist omits `strike`.** `isWorkOrSpecialistSession` enumerated
   `work|planning|review|reviewer|test|ship|merge` and dropped `strike`, so the
   live strike session was absent from the tree aggregate. `SessionNode`'s
   `describeSession`/`describeSessionPurpose` also lacked a `strike` case.
   Described as the **4th** allowlist a strike has fallen out of.
2. **RC2 — a dead planning session rendered as `working · 22m`.** A completed +
   killed planning session still showed live "working" activity and a
   growing timer.

## Findings against the current code (verified this session)

### RC1 is ALREADY FIXED on `origin/main`

Commit `2e5f3a9214` ("fix(dashboard): add 'strike' session node mirroring Work
agents", 2026-06-12 — two days after this issue was filed) landed all of RC1:

- `FeatureItem.tsx:327-336` — `isWorkOrSpecialistSession` now includes
  `session.type === 'strike'`.
- `SessionNode.tsx:258` — `case 'strike': return 'Strike'` in
  `deriveSessionLabel`.
- `SessionNode.tsx:274-275` — `case 'strike':` purpose blurb in
  `describeSessionPurpose`.
- `SessionNode.test.tsx:469` — a strike-node render test exists.

**Gap that remains:** the exact surface that regressed four times — the
`isWorkOrSpecialistSession` **allowlist enumeration** — has **no unit test**.
It is an unexported pure helper. A missing type would still silently fall out
without any test failing. This plan adds that lock (a 5th miss must fail CI),
but does **not** re-implement RC1.

### RC2 is still reproducible — the frontend ignores an `ended` presence

`presence` is correctly reconciled against tmux
(`services/session-presence.ts:16-17`: `if (!hasTmux) return 'ended'`, added
PAN-865 2026-04-27 — predates this issue). The defect is entirely in the
frontend `SessionNode.tsx`, which prefers the stale live `runtime.activity`
over `presence`:

- `effectiveActivity(runtime, presence)` (`SessionNode.tsx:97-103`) only
  special-cases `activity === 'stopped'`. When a tmux session is killed
  externally (specialists `pan done` / `pan kill` / OOM) **no `agent.stopped`
  event is emitted** (confirmed: events only fire through deliberate stop
  routes), so the runtime snapshot stays frozen at `activity: 'working'`.
  With `presence === 'ended'` this still returns `'working'`.
- `displayStatus = (activity ?? session.status)` (`SessionNode.tsx:611`) →
  `'working'`.
- `isLiveActivity` (`SessionNode.tsx:664-666`) is `true` for
  `statusCssKey === 'running'|'working'|…` **without gating on presence**, so
  the icon tile paints with `styles.sessionIconRunning` (the green "live" look).
- `deriveDotStatus(runtime, 'ended')` (`SessionNode.tsx:105-109`) →
  `activityToStatus('working')` → `'active'` → green status dot.
- `durationLabel = formatDuration(session.duration)` (`SessionNode.tsx:674`,
  rendered at `:746-747`). Backend sets `endedAt: undefined` and computes
  `duration = Date.now() - startedAt` (`routes/projects.ts:255-262`), so the
  timer keeps climbing forever on a dead session.

Net: a dead session with a stale `runtime.activity: 'working'` renders with a
green running icon, an active dot, and an ever-growing timer — "working · 22m".

The backend `status` field can also be a stale `'running'`
(`routes/projects.ts:263-269`, never reconciled against tmux), but the feature
aggregate already presence-gates it (`isRunningSession` at `FeatureItem.tsx:348`
requires `presence === 'active'`), so it does not mislead the aggregate. The
sole user-visible defect is the per-row rendering above.

## Fix approach (decisions — recorded in `--auto` mode)

**D1.** Do not re-fix RC1. Lock it: export `isWorkOrSpecialistSession` and add a
unit test asserting every current session `type` (including `strike`) is
recognized. This is the precise guard that would have caught all four misses.

**D2.** Fix RC2 in the frontend by making `presence === 'ended'` the
authoritative liveness signal in `SessionNode.tsx` — not a backend `status`
rewrite and not a new "reaper". Rationale: `presence` is already correctly
derived from tmux; the visible defect is purely the frontend preferring stale
`runtime.activity`. This is the smallest change that fixes every session type
uniformly regardless of how the tmux died.

**D3.** For non-live (`!isLive`) sessions, suppress the growing duration label
rather than freezing it. The backend supplies no `endedAt`
(`duration = now - startedAt`), so a correct lifetime cannot be shown; the
existing "last heard N ago" already conveys recency.

## Concrete changes

### FeatureItem.tsx (RC1 lock)
- `export function isWorkOrSpecialistSession(...)` (currently unexported,
  `:327`). No behavior change.

### SessionNode.tsx (RC2 fix) — presence is authoritative
- `effectiveActivity` (`:97`): at the top, `if (presence === 'ended') return
  undefined;` — a dead session has no live activity.
- `isLiveActivity` (`:664`): gate on `isLive` —
  `const isLiveActivity = isLive && !isPaused && (statusCssKey === 'running' || …)`.
  `isLive` (`:610`) is already `presence in {active,idle,suspended}`.
- `durationLabel` (`:674`): `const durationLabel = isLive ? formatDuration(session.duration) : null;`

## Non-goals

- The canonical session-prefix/role registry ([PAN-1683](https://github.com/eltmon/overdeck/issues/1683))
  that would derive every allowlist from one source. This plan fixes the
  symptom + adds a lock; PAN-1683 is the structural fix.
- A backend liveness "reaper" that emits `agent.stopped`/`agent.status_changed`
  when a tmux session dies externally ([PAN-1689](https://github.com/eltmon/overdeck/issues/1689) family).
- Backend `status`/`duration` reconciliation in `collectSessionTreeNodes`
  (`routes/projects.ts`) — left unchanged; the aggregate already presence-gates.
- The Activity-cockpit twin builder (`routes/command-deck.ts`) and its
  rendering — a separate code path, not the reported ProjectTree surface.
- Re-implementing RC1 (already landed as `2e5f3a9214`).

## Requirements

- **FR-1** — `isWorkOrSpecialistSession` is exported and covered by a unit test
  that recognizes every current session type (including `strike`); a dropped
  type fails the test. (bead `rc1-allowlist-lock`)
- **FR-2** — A session with `presence === 'ended'` renders no live icon
  (`sessionIconRunning`) even when its runtime snapshot's `activity` is stale
  `'working'`. (bead `rc2-presence-authoritative`)
- **FR-3** — A dead (`presence === 'ended'`) session's status dot resolves to
  `'ended'`, not an active/working dot. (bead `rc2-presence-authoritative`)
- **FR-4** — A non-live (`!isLive`) session renders no growing duration label.
  (bead `rc2-presence-authoritative`)
- **NFR-1** — No regression to live-session rendering: a running session
  (`presence` active/idle + `activity` `working`) still shows the green live
  icon and dot.

## Acceptance (maps 1:1 to beads)

- **RC1-lock:** `isWorkOrSpecialistSession` is exported and a unit test asserts
  it returns `true` for `strike` and every other current type; adding a new
  type without listing it (or dropping `strike`) fails the test.
- **RC2-fix:** a `SessionNode` with `presence: 'ended'` and a runtime snapshot
  `activity: 'working'` renders no `sessionIconRunning` class, an `ended` status
  dot, and no duration label; a live `presence: 'active'` + `activity: 'working'`
  session still renders `sessionIconRunning` (no regression).
