# PAN-3021 — Generate composer slash-command autocomplete from the CLI command registry

**Issue:** https://github.com/eltmon/overdeck/issues/3021
**Author:** planning agent (claude-fable-5), 2026-07-24
**Mode:** `pan plan --auto` (non-interactive; defaults recorded in autoDecisions)

## Glossary

- **Composer** — the Lexical-based text input in the dashboard conversation panel (`src/dashboard/frontend/src/components/chat/ComposerPromptEditor.tsx`). Typing `/` opens a filterable autocomplete menu of commands.
- **`SLASH_COMMANDS`** — the hand-maintained array at `ComposerPromptEditor.tsx:65–211` that feeds that menu. Each entry: `{ id, label, description, insert, category? }` (interface at `:57–63`).
- **CLI command registry** — the Commander (`commander@^12.1.0`) program assembled in `src/cli/index.ts` (top-level `program.command(...)` calls plus `registerX(program)` functions from `src/cli/commands/*`). This is the single source of truth for which `pan` verbs exist and their descriptions.
- **Hidden command** — a Commander command registered with `{ hidden: true }` (e.g. `review spawn-reviewer`, `src/cli/index.ts:380`). Excluded from help; must be excluded from the menu. The public API to filter them is `program.createHelp().visibleCommands(cmd)` (commander typings line 233).
- **Generated file** — a committed TypeScript module produced by a codegen script from the CLI registry. The frontend imports it; a lint gate keeps it in sync.
- **Curation overlay** — a small checked-in JSON file of explicit deny rules, category mappings, and hand-authored "extras" applied over the generated set. This is the issue's required "explicit allowlist/denylist over the generated set — not an independently maintained copy."
- **Static entries** — menu entries that are NOT `pan` CLI commands and therefore cannot be generated: the AI-CLI entries (`/model`, `/context`, `/effort`, `/cancel`) and the dashboard-intercepted `/handoff` (currently `ComposerPromptEditor.tsx:66–94` and `:195`).
- **Drift gate** — a lint step that regenerates the file and fails CI on any diff, following the `scripts/lint-skills.sh` precedent (which runs `node dist/cli/index.js <verb> --help` against the locally built CLI).

## Problem

`SLASH_COMMANDS` is a hardcoded array that has drifted 38 top-level commands behind the CLI (`strike`, `strike-ready`, `swarm`, `task`, `approve`, `merge`, `flywheel`, `pause`, `unpause`, `release`, …). It also contains entries for commands whose CLI shape has since changed or disappeared (e.g. `pan admin tasks compact` — there is no `admin tasks` group in `pan admin --help` today). An operator typing `strike` gets no match and reasonably doubts the verb exists. Hand-patching the list recreates the drift; the fix must make composer/CLI disagreement mechanically impossible (single-source-of-truth tenet).

## Decision: build-time generation with a committed file and a drift lint (not a runtime endpoint)

The issue offers two directions: generate at build time, or serve from an endpoint backed by the registry. **Chosen: build-time generation into a committed file, enforced by a drift lint.** Rationale:

- The dashboard server cannot cheaply import the Commander program (the CLI's `src/cli/index.ts` has load-time side effects: env loading, node preflight, `program.parse()`); an endpoint would need the same extraction work plus runtime coupling and a loading state in the composer.
- The repo already has this exact pattern for skills: `scripts/lint-skills.sh` runs the locally built CLI (`node dist/cli/index.js …`) and fails CI on drift. We mirror it.
- A committed file keeps the frontend build independent of CLI build ordering; Vite just imports a module.

Introspection happens **inside the CLI itself** via a new plumbing subcommand `pan admin commands --json`, so the emitted tree is by construction the tree the shipped binary parses — no separate program-construction path that could itself drift.

## Requirements

### Functional

- **FR-1** The CLI exposes `pan admin commands` listing every *visible* command path (recursively, all depths) with its description; `--json` emits a machine-readable array. Hidden commands and Commander's implicit `help` command are excluded.
- **FR-2** A codegen script produces `slashCommands.generated.ts` from `pan admin commands --json` output plus the curation overlay. Output is deterministic (stable ordering = registry walk order) so the drift diff is meaningful.
- **FR-3** The composer menu is fed by the generated entries merged with the static entries; the hand-maintained `SLASH_COMMANDS` array body is deleted. Every currently-missing top-level command enumerated in the issue (`strike`, `swarm`, `task`, `flywheel`, `merge`, `pause`, …) appears in the menu.
- **FR-4** Curation is an explicit overlay: `deny` (path prefixes to exclude), `categories` (top-level verb → menu section header), `extras` (hand-authored additive entries, e.g. flag variants like `pan show --cv`). No independent copy of the command list exists anywhere in the frontend.
- **FR-5** A lint step (`npm run lint`, CI) regenerates the file and fails on any diff, with a message naming the fix command (`npm run generate:slash-commands`).
- **FR-6** No-loss audit: every entry of the pre-change `SLASH_COMMANDS` list either resolves to an entry in the new merged list or is recorded in an explicit deliberate-removals table (reason: the CLI path no longer exists), enforced by a test per `.claude/rules/additive-refactor-no-loss.md`.

### Non-functional

- **NFR-1** No `execSync` in any code reachable from the dashboard server (`.claude/rules/no-execsync-server.md`). The generator is a standalone script (never imported by the server), so `spawnSync` there is acceptable — same posture as `scripts/lint-skills.sh`.
- **NFR-2** Menu descriptions stay scannable: generator truncates each description to its first sentence, capped at 100 chars with `…`.
- **NFR-3** The generated module carries a `// GENERATED FILE — do not edit` header naming the regeneration command.
- **NFR-4** The existing composer behaviors (filtering, category grouping in `SlashMenu`, highlight, insert-with-trailing-space) are unchanged; only the data source moves.

## Work items

### W1 — CLI introspection: `collectCommandTree()` + `pan admin commands [--json]`  (traces: FR-1)

**Files:** `src/cli/command-introspection.ts` (new), `src/cli/commands/admin/index.ts` (edit, `registerAdminCommands(program)` at `:25` already receives the root program), test `src/cli/commands/__tests__/command-introspection.test.ts` (new).

New module exports:

```ts
export interface CommandInfo {
  /** Command path below the program root, e.g. ["admin","cloister","status"] */
  path: string[];
  description: string;
  /** Declared positional args, e.g. [{ name: "id", required: true, variadic: false }] */
  args: { name: string; required: boolean; variadic: boolean }[];
  /** True when the command has visible subcommands */
  hasSubcommands: boolean;
}

export function collectCommandTree(root: Command): CommandInfo[]
```

Walk rules (deterministic, no judgment):
- Recurse depth-first in registration order using `root.createHelp().visibleCommands(cmd)` so hidden commands are skipped by Commander's own definition of visible.
- Skip the implicit `help` command (name === 'help').
- Emit an entry for every visible command at every depth. `args` from `cmd.registeredArguments` (`.name()`, `.required`, `.variadic`).
- Do not read options/flags; flag variants are curation extras, not generated.

Register in `registerAdminCommands`:

```ts
adminCmd
  .command('commands')
  .description('List every visible pan command (plumbing; feeds composer autocomplete codegen)')
  .option('--json', 'Emit machine-readable JSON')
  .action((opts) => {
    const tree = collectCommandTree(program);
    if (opts.json) { console.log(JSON.stringify(tree, null, 2)); return; }
    for (const c of tree) console.log(`pan ${c.path.join(' ')}  —  ${c.description}`);
  });
```

Test: build a synthetic Commander program (a few nested commands, one `{ hidden: true }`, one with `<id>` arg) and assert the walker emits exactly the visible paths, arg metadata, and skips hidden + help. Pure unit test, no CLI spawn.

### W2 — Generator script + curation overlay + committed generated file  (traces: FR-2, FR-4, NFR-2, NFR-3)

**Files:** `scripts/generate-slash-commands.mjs` (new), `scripts/slash-commands-curation.json` (new), `src/dashboard/frontend/src/components/chat/slashCommands.generated.ts` (new, committed), `package.json` (add script `"generate:slash-commands": "node scripts/generate-slash-commands.mjs"`).

Generator behavior:
1. If `dist/cli/index.js` is missing, exit 1 with: `dist/cli/index.js not found — run 'npm run build:cli' first`.
2. `spawnSync('node', ['dist/cli/index.js', 'admin', 'commands', '--json'])`, parse `CommandInfo[]`.
3. Entry selection: include every command where `hasSubcommands === false` (leaf), **plus** non-leaf commands that declare positional args (e.g. `pan plan [id]` is runnable directly). Pure group containers (`review`, `workspace`, `admin`, `backup`, …) are not entries themselves — their children are.
4. Apply overlay `deny`: drop any entry whose `path.join(' ')` starts with a listed prefix. Ship `deny: []` initially (the issue's default: show everything visible; hiding plumbing is an explicit later curation act).
5. Map each entry:
   - `id`: `'pan-' + path.join('-')`
   - `label`: `'pan ' + path.join(' ')`
   - `insert`: `'pan ' + path.join(' ')` + (`' '` if `args.length > 0`)
   - `description`: first sentence (split on `. `), then hard-cap 100 chars with trailing `…`
   - `category`: `overlay.categories[path[0]] ?? 'CLI'`
6. Append `overlay.extras` verbatim (each already a full `SlashCommand`).
7. Write `slashCommands.generated.ts`:

```ts
// GENERATED FILE — do not edit by hand.
// Source: the pan CLI command registry via `pan admin commands --json`.
// Regenerate: npm run generate:slash-commands   (drift-gated by scripts/lint-slash-commands.sh)
import type { SlashCommand } from './slashCommandTypes';

export const GENERATED_SLASH_COMMANDS: SlashCommand[] = [ /* … */ ];
```

Curation overlay initial content:
- `deny`: `[]`
- `categories`: map current menu section names onto top-level verbs so grouping survives, e.g. `{ "up": "Core", "down": "Core", "restart": "Core", "reload": "Core", "status": "Core", "init": "Core", "sync": "Core", "doctor": "Core", "install": "Core", "skills": "Core", "test": "Core", "start": "Lifecycle", "plan": "Lifecycle", "tell": "Lifecycle", "kill": "Lifecycle", "pause": "Lifecycle", "unpause": "Lifecycle", "untroubled": "Lifecycle", "resume": "Lifecycle", "recover": "Lifecycle", "sync-main": "Lifecycle", "done": "Lifecycle", "reopen": "Lifecycle", "reset-to-planned": "Lifecycle", "wipe": "Lifecycle", "close": "Lifecycle", "issues": "Lifecycle", "strike": "Lifecycle", "strike-ready": "Lifecycle", "swarm": "Lifecycle", "task": "Lifecycle", "approve": "Lifecycle", "inspect": "Lifecycle", "scope": "Lifecycle", "backlog": "Lifecycle", "staffing": "Lifecycle", "show": "Observation", "open": "Observation", "monitor": "Observation", "inbox": "Observation", "health": "Observation", "briefing": "Observation", "resources": "Observation", "memory": "Observation", "compliance": "Observation", "review": "Review", "merge": "Review", "flywheel": "Flywheel", "orders": "Flywheel", "rollout": "Flywheel", "release": "Flywheel", "workspace": "Workspace", "destroy": "Workspace", "project": "Project", "projects": "Project", "admin": "Admin", "fork": "Conversation", "handoff": "Conversation", "conversations": "Conversation", "unarchive-conversation": "Conversation", "backup": "Data", "restore": "Data", "cost": "Data", "knowledge": "Data", "registry": "Data", "docs": "Data", "artifacts": "Data", "context": "Data", "dev": "Core", "tts": "Core", "ohmypi-auth": "Core", "caveman-compress": "Data", "open?": "Observation" }` — the work agent regenerates and fills any verb missing from this map with a sensible section or leaves it defaulting to `CLI`; the exact assignment of a verb to a section is cosmetic and not drift-gated.
- `extras`: the pre-change flag-variant conveniences plus their categories, copied verbatim from the old list: `pan show --cv`, `pan show --context`, `pan show --health` (Observation); `pan plan --auto --auto-start`, `pan review reset --session` (Lifecycle/Review); `pan fork --plain`, `pan handoff --model`, `pan handoff --harness`, `pan handoff --cwd` (Conversation).

### W4 — Drift gate wired into lint  (traces: FR-5)

Script:

## Non-goals

- No runtime endpoint serving commands (`/api/slash-commands`) — build-time generation chosen instead.
- No generation of per-command flag/option entries — flag variants remain curated extras.
- No change to menu UX: filtering, grouping, highlighting, keyboard navigation, insert semantics stay as-is.
- No population of the `deny` list in this issue — it ships empty; hiding plumbing is a later, explicit curation decision.
- No changes to skills, `scripts/lint-skills.sh`, or the t3code composer redesign (`docs/research/t3code-drift-plan.md`) — the generated module is plain data and compatible with that future work.

## Hazards / intersecting repo rules restated for the executor

- **No `execSync` in server-reachable code** — the generator and lint scripts are standalone Node scripts, never imported by `src/dashboard/**`. Keep it that way.
- **File-size ratchet** — `ComposerPromptEditor.tsx` shrinks (fine). The new generated file may be large; if `scripts/lint-file-size.sh` flags it, add it to the lint script's exclusions for generated files if such a mechanism exists, otherwise baseline it in `scripts/file-size-baseline.txt` within the same work item that creates it.
- **Determinism** — no `Date.now()`/timestamps inside the generated file, or the drift gate flakes.
- **The CLI must stay side-effect-safe** — `pan admin commands` runs the full CLI startup (env load, preflight); that is the accepted cost and matches `lint-skills.sh`. Do not import `src/cli/index.ts` from any script.
- **Commander walk must use `visibleCommands`** — checking a private `_hidden` field would break across commander upgrades.
