# PAN-2568 — Fix the summary-fork delivery race: large pastes must actually submit, and stranded forks must fail loudly

**Issue:** https://github.com/eltmon/overdeck/issues/2568
**Status:** draft
**Author:** conversation orchestrator (Fable), 2026-07-10
**Incident reference:** conv 744 (`conv-20260710-d908`, codex / gpt-5.6-sol), forked from conv 736 on 2026-07-10.

---

## Glossary

Define these before anything else; every section below uses them.

- **Composer** — the text-input box at the bottom of a harness TUI (Claude Code or codex). Text can sit in the composer without being sent; pressing Enter *submits* it as a user message.
- **Submit** — the harness accepting composer content as a user turn. Only submitted text reaches the model and the transcript. Codex writes its first session file (under `<agent>/codex-home/sessions/`) only after the first submit.
- **Paste burst** — a run of bytes arriving at the TUI faster than human typing. Both Claude Code and codex classify an Enter (`\r`) arriving *inside* a burst as a newline **in** the pasted text, not as a submit keystroke.
- **PTY supervisor** — `dist/pty-supervisor.js` (source `src/lib/channels/pty-supervisor.ts`), the Node 22 process that owns the harness's PTY and accepts message-injection POSTs on `${OVERDECK_HOME}/sockets/pty-<id>.sock`.
- **Delivery tiers** — `deliverAgentMessage()` (`src/lib/agents/delivery.ts:177`) tries, in order: supervisor socket → legacy Channels socket → tmux paste-buffer fallback.
- **Echo confirmation** — the supervisor's check that text it wrote to the PTY has been rendered back by the TUI (`isEchoConfirmed`, `src/lib/channels/pty-supervisor.ts:240`).
- **Purge** — the supervisor erasing an unconfirmed write with one Backspace (`\x7f`) per written character (`purgePtyInput`, `src/lib/channels/pty-supervisor.ts:265`), so retries and the tmux fallback can never stack duplicate copies (the PAN-1769 invariant).
- **Verify line** — the last non-trivial line of a delivered message; both the tmux tier and the supervisor use its first 40 chars to detect the text on screen (`src/lib/tmux.ts:1145-1146`, `pty-supervisor.ts:230-233`).
- **Runtime mirror** — the harness-side transcript/state that `confirmForkPromptAccepted` (`src/lib/overdeck/conversation-forks.ts:271`) polls to decide whether a fork's summary was accepted (`accepted` / `still-idle` / `unknown`).
- **Fork pipeline** — `runForkPipeline` (`src/lib/overdeck/conversation-forks.ts:357`): spawn successor session → generate summary → `injectForkSummary` → clear `forkStatus` to `null` (= complete).
- **Stranded delivery** — the failure mode this PRD eliminates: message text present in the composer, never submitted, no error surfaced anywhere.

## Incident summary (what actually happened)

Fork of conv 736 → conv 744 (codex harness, ~15–30 KB summary):

1. `injectForkSummary` delivered via `deliverAgentMessage` → supervisor tier. The supervisor wrote the summary into codex's PTY during its boot render storm; echo was not confirmed within 2.5 s, so it purged and rewrote (pane showed `Input echo not confirmed … (attempt 1/2); purging and rewriting content before Enter`).
2. The **caller's socket POST timed out at 8 s** (`bridge-conv-20260710-d908.log`: `"pty-supervisor":"socket-post-failed: socket POST timeout"`) while the supervisor was still mid-injection, and fell through to the tmux tier.
3. The tmux tier pasted a **second full copy** onto the same PTY, concurrent with the supervisor's purge/rewrite. Its paste verification failed twice (`Paste verification failed … Sending Enter anyway`), so it sent `C-m` blind; the Enter (and the 2 s submit-verify resend) arrived inside the combined paste burst and became newlines.
4. The supervisor's final purge could erase at most 8,192 chars of a much larger paste, so a remnant stayed in the composer regardless.
5. `confirmForkPromptAccepted` returned `unknown` (codex's runtime mirror is silent until the first submit), `injectForkSummary` logged a warning and **returned normally**, and `runForkPipeline` cleared `forkStatus` to `null`. Result: a "healthy, active" conversation with an empty transcript and the entire summary sitting unsent in the composer. A manual Enter in the terminal submits it.
6. An operator message sent 10 minutes later (`caller: conversation-message`) failed through the identical chain.

## Root causes (numbered, each mapped to a fix)

- **RC-1 — client/supervisor timeout race.** The 8 s client timeout at `src/lib/agents/delivery.ts:215-221` budgets the supervisor at "≈5.3 s" but ignores payload size: echo-confirming a multi-KB paste on a booting TUI exceeds 2.5 s per attempt. When the client abandons the POST, the tmux fallback writes concurrently with the still-running supervisor — two writers, one PTY. → fixed by WI-1, WI-2.
- **RC-2 — purge cap breaks the PAN-1769 invariant above 8 KB.** `INPUT_PURGE_MAX_CHARS = 8_192` (`pty-supervisor.ts:40`) means large pastes cannot be fully erased; remnants stack with the fallback copy. → fixed by WI-3.
- **RC-3 — Enter swallowed with no idle-state recovery.** Every Enter was fired into an active paste burst. Nothing ever retries a *standalone* Enter once the PTY is quiet — the one action that provably works. → fixed by WI-4.
- **RC-4 — silent completion.** `injectForkSummary` treats `unknown` as success-shaped; `runForkPipeline` marks the fork complete. → fixed by WI-5.

## Requirements

### Functional

- **FR-1** A single exported function computes the supervisor's worst-case injection time from payload length; the supervisor's internal waits and the delivery client's socket timeout are both derived from it, with the client strictly greater. Mid-injection abandonment becomes structurally impossible, not tuned-around.
- **FR-2** Echo-confirmation timeout and the pre-Enter settle delay scale with payload size (bounded floors and caps; exact formulas in WI-2).
- **FR-3** `purgePtyInput` erases the full written character count for any payload the supervisor accepts (new cap 262,144 chars), with a size-scaled settle.
- **FR-4** When a fork's summary cannot be confirmed as accepted and the verify line is still visible in the pane, `injectForkSummary` sends a single standalone Enter via the async tmux primitive, waits, and re-checks — up to 2 nudges — before declaring failure.
- **FR-5** A fork whose summary is delivered but never submitted ends with `forkStatus = 'failed'` and a `forkError` that tells the operator exactly what to do ("open the Terminal tab and press Enter"). `runForkPipeline` must not clear `forkStatus` to `null` in that case, and must NOT call `markConversationEnded` (the session is alive and recoverable).
- **FR-6** Behavior for small messages (≤ 1 KB) is unchanged within tolerance: budgets resolve to today's effective values (2.5 s echo window, 300 ms settle, ~8 s client ceiling +margin), so ordinary `pan tell` latency does not regress.

### Non-functional

- **NFR-1** All new tests that exercise timeouts/delays use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` — never real `setTimeout` waits (repo fake-timers rule).
- **NFR-2** Only async tmux primitives (`sendKeysAsync`, `capturePaneText`); no new sync `sendKeys` callers, no `execSync` anywhere server-reachable.
- **NFR-3** The new shared budget module is a leaf (imports nothing from `src/lib` beyond types) to avoid adding a circular-ESM edge — Node strict ESM rejects cycles in the dashboard build.
- **NFR-4** No new dependencies; supervisor remains Node-22-only.

### WI-1 — Shared injection-budget module (fixes RC-1) — traces FR-1, FR-6, NFR-3

**Files:** new `src/lib/channels/injection-budget.ts`; edit `src/lib/channels/pty-supervisor.ts`, `src/lib/agents/delivery.ts`.

Create `src/lib/channels/injection-budget.ts` (leaf module, constants moved out of `pty-supervisor.ts:35-41`):

```ts
export const INPUT_ECHO_CONFIRM_INTERVAL_MS = 50;
export const INPUT_ECHO_CONFIRM_ATTEMPTS = 2;
export const INPUT_ECHO_CONFIRM_PREFIX_CHARS = 40;
export const INPUT_PURGE_MAX_CHARS = 262_144;
export const SUPERVISOR_CLIENT_MARGIN_MS = 2_000;
const INJECTION_OVERHEAD_MS = 3_000; // PTY writes, log appends, scheduler slack

/** Echo window for one attempt: 2.5s floor + 100ms per KB, capped at 15s. */
export function echoConfirmTimeoutMs(contentLength: number): number {
  return Math.min(2_500 + Math.ceil(contentLength / 1_024) * 100, 15_000);
}

/** Pause between confirmed echo and the standalone Enter: 300ms floor + 50ms/KB, capped at 2s. */
export function inputSettleMs(contentLength: number): number {
  return Math.min(300 + Math.ceil(contentLength / 1_024) * 50, 2_000);
}

/** Settle after a purge: 150ms floor + 25ms/KB of erased content, capped at 1s. */
export function purgeSettleMs(erasedChars: number): number {
  return Math.min(150 + Math.ceil(erasedChars / 1_024) * 25, 1_000);
}

/** Worst-case wall time injectPtyMessage can spend before responding. */
export function supervisorInjectionBudgetMs(contentLength: number): number {
  const clamped = Math.min(contentLength, INPUT_PURGE_MAX_CHARS);
  return (
    INPUT_ECHO_CONFIRM_ATTEMPTS * echoConfirmTimeoutMs(contentLength) +
    INPUT_ECHO_CONFIRM_ATTEMPTS * purgeSettleMs(clamped) +
    inputSettleMs(contentLength) +
    INJECTION_OVERHEAD_MS
  );
}
```

### WI-3 — Full-length purge (fixes RC-2) — traces FR-3

**File:** `src/lib/channels/pty-supervisor.ts` (`purgePtyInput` :265-269).

Before:

```ts
async function purgePtyInput(child: pty.IPty, charCount: number): Promise<void> {
  const count = Math.min(charCount, INPUT_PURGE_MAX_CHARS) + 8;
```

After (cap now 262,144 via injection-budget; settle scales):

```ts
async function purgePtyInput(child: pty.IPty, charCount: number): Promise<void> {
  const count = Math.min(charCount, INPUT_PURGE_MAX_CHARS) + 8;
  child.write('\x7f'.repeat(count));

}
```

### WI-4 — Pane-verified standalone-Enter recovery in the fork pipeline (fixes RC-3) — traces FR-4, NFR-2

**Files:** `src/lib/tmux.ts`, `src/lib/overdeck/conversation-forks.ts` (`injectForkSummary` :320-348).

1. In `tmux.ts`, extract the verify-line computation currently inlined at :1145-1146 into an exported pure helper, used by `sendKeys` and the fork recovery (single source of truth):

```ts
export function deliveryVerifyLine(content: string): string {
  const lines = content.split('\n');
  return ([...lines].reverse().find(l => l.trim().length >= 3) ?? lines[lines.length - 1])?.trim() ?? '';
}
```

2. In `injectForkSummary`, replace the give-up branches. The function's signature changes to return `Promise<'submitted' | 'stranded'>` (today `Promise<void>`). After each `deliverAgentMessage` + `confirmForkPromptAccepted` cycle that does NOT return `'accepted'`:

```ts
const verify = deliveryVerifyLine(summary).slice(0, 40);
for (let nudge = 1; nudge <= 2; nudge++) {
  const pane = await capturePaneText(conv.tmuxSession, 40);
  if (verify.length >= 3 && !pane.includes(verify)) break; // composer empty — text lost, fall through to re-delivery/failure
  console.warn(`[${caller}] ${conv.name}: delivered text still in composer — sending standalone Enter (nudge ${nudge}/2)`);
  await sendKeysAsync(conv.tmuxSession, 'C-m', `${caller}:enter-nudge`);
  const outcome = await confirmForkPromptAccepted(conv.tmuxSession, 8000);
  if (outcome === 'accepted') return 'submitted';
  const after = await capturePaneText(conv.tmuxSession, 40);
  if (verify.length >= 3 && !after.includes(verify)) return 'submitted'; // composer cleared; codex mirror may lag
}
```

The nudge runs when `confirmForkPromptAccepted` returns `'still-idle'` **or** `'unknown'` — the incident case was `'unknown'` (codex mirror silent before first submit), so the current "unknown → return, don't retry" branch at :338-341 is replaced by this recovery, and only after the nudges fail does it fall through. Full re-delivery (the existing attempt-2 loop) remains the fallback after a nudge cycle finds the composer *empty*; a nudge cycle that finds the composer still full and fails both Enters proceeds to WI-5's stranded handling instead of re-pasting (re-pasting onto a full composer is exactly how duplicates happen).

**Why this works:** by the time the nudge runs, both delivery tiers have finished (WI-1 removed the overlap), the PTY is quiet, and a lone `C-m` in its own read is unambiguously a submit keystroke — this is the manual fix verified live on conv 744.

**Tests (named):** new `src/lib/overdeck/__tests__/conversation-forks-enter-nudge.test.ts` (fake timers; mock `capturePaneText`, `sendKeysAsync`, and `forkPipelineRuntimeOverrides.getAgentRuntimeStateSync`) — (a) composer-still-full + idle mirror → exactly one `C-m`, then `accepted` → returns `'submitted'`; (b) composer cleared but mirror silent → `'submitted'` without a second nudge; (c) both nudges fail with composer full → `'stranded'`, and **no** re-delivery of the summary occurs.
