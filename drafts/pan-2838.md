# PAN-2838 — Project settings disclosure: static 'collapsed' badge + panel missing for projects with no in-flight issues

**Issue:** https://github.com/eltmon/overdeck/issues/2838
**Mode:** auto planning (no interactive Q&A)

## Glossary

- **Cockpit branch** — the rich body of `ProjectHome` (`src/dashboard/frontend/src/components/Stage/ProjectHome.tsx:132-198`) that renders `ProjectOverview` when `features.length > 0`.
- **Sparse fallback** — the `ProjectHome` branch at lines 200-238 rendered when a project has no in-flight pipeline features; today it shows launcher/docks/timeline only.
- **Settings disclosure** — the native `<details>` element (`ProjectDisclosure`, `ProjectOverview.tsx:544-609`) wrapping `ProjectSettingsSection` (`ProjectOverview.tsx:222-291`), which edits the project auto-merge default and swarm policy.
- **projectKey** — the exact `projects.yaml` key. The settings routes (`src/dashboard/server/routes/projects.ts:737-784`) resolve it via `getProjectSync(key)` (`src/lib/projects.ts:580-583`), which is an exact `config.projects[key]` lookup — display names do NOT resolve.

## Requirements

- **FR-1** The disclosure has no static "collapsed" pill; open/closed state is shown by a chevron that rotates with `details[open]` (pure CSS, no React state).
- **FR-2** The collapsed summary row shows the current auto-merge default (`⚡ Auto` / `🔒 Hold for UAT` / `Global default`) and swarm mode (`off`/`auto`/`always`/`inherit`) without expanding, sourced from the same react-query keys `['project-auto-merge-default', key]` and `['project-swarm-policy', key]`.
- **FR-3** A registered project with zero in-flight pipeline features (e.g. Mind Your Now) shows the Project settings disclosure on its HOME tab; both settings are readable and writable there.
- **FR-4** No-loss: the cockpit branch keeps the auto-merge segmented control (3 options), the swarm `<select>`, and both helper-copy lines unchanged.
- **FR-5** Frontend tests cover the open/closed affordance, the summary values, and the sparse-fallback rendering path.
- **FR-6** Docs describe the panel's new availability: `docs/SWARM-POLICY.md` (project-values sentence) and `configuration/auto-merge.mdx` (per-project default section).

## Decisions (auto mode)

1. **Extract a shared component.** The issue offered "render the disclosure in the sparse branch too, or hoist it out of ProjectOverview". Chosen: extract `ProjectSettingsSection` + `ProjectDisclosure` into a new `src/dashboard/frontend/src/components/CommandDeck/ProjectSettingsDisclosure.tsx` exporting `ProjectSettingsDisclosure({ projectKey })`, consumed by both `ProjectOverview` and the sparse branch of `ProjectHome`. Duplication would drift; hoisting to a shared file is the smallest no-drift shape.
2. **Gate the sparse render on `projectKey` truthiness, not `projectKey ?? projectName`.** The issue sketched the release-panel pattern (`ProjectHome.tsx:176`), but the release route explicitly accepts name-or-key while the settings routes use the exact-key `getProjectSync` lookup — a name fallback would 404 and break saves. `projectKey` is threaded from `selectedRegisteredProject?.key` (`CommandDeck/index.tsx:1449`) and is present for every registered project even with zero features, so FR-3 holds.
3. **Lightweight summary from the same query keys** (react-query dedupes identical keys against one cache entry) instead of lifting queries and threading props — smaller diff, identical data.
4. **Style guide compliance:** summary values are plain `--muted-foreground` text — no pills (border-radius 999 badges are a forbidden pattern), no decorative color, `font-medium` weight for new text. Chevron via Tailwind `group` on `<details>` + `group-open:rotate-90` on a lucide `ChevronRight` (Tailwind 3.4 supports `group-open:`).
