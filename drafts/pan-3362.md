# PAN-3362 — Seed tracker-backed issue fixtures into workspace containers for UI UAT

**Issue:** [PAN-3362](https://github.com/eltmon/overdeck/issues/3362) — *No way to seed tracker-backed issue fixtures in workspace containers — every UI-redesign UAT is environment-blocked and needs an operator override*

## Glossary

- **Workspace container** — the per-issue Docker Compose stack (template:
  `infra/.devcontainer-template/docker-compose.devcontainer.yml.template`) with
  `init` / `frontend` / `server` services. The `server` service runs the
  pre-built dashboard (`node dist/dashboard/server.js`, Node 22) as a
  **read/UI peer** with `OVERDECK_DISABLE_DEACON=1`.
- **Container-local `OVERDECK_HOME`** — `/home/node/.overdeck` inside the
  container. The host's `~/.overdeck` is deliberately *not* mounted
  (single-deacon invariant). It holds the container's own `overdeck.db`,
  `cache.db`, and `projects.yaml`. It survives `docker compose restart` but is
  lost on container *recreate* (`up --force-recreate`, rebuild).
- **Skip-polling mode** — `src/dashboard/server/main.ts:170-173` starts
  `IssueDataService` with `skipPolling: true` when `OVERDECK_DISABLE_DEACON=1`.
  The service loads its L2 cache **once at boot** and never polls a tracker.
- **Tracker issue cache** — `${OVERDECK_HOME}/cache.db`, table
  `api_cache(tracker, cache_key, data, …)` (`src/dashboard/server/services/cache-service.ts:78-100`).
  `IssueDataService.loadCachedData()` (`src/dashboard/server/services/issue-data-service.ts:711-756`)
  reads `getStale(tracker, 'issues')` for `github`/`linear`/`rally` at boot.
- **Write door** — the single canonical writer for a domain (two-door tenet).
  Relevant doors: `saveOverdeckAgentStateSync` (`src/lib/overdeck/agent-state-sync.ts:274`),
  `upsertReviewStatusSync` (`src/lib/database/review-status-db.ts:37`),
  `emitActivityEntryDurable` (`src/lib/activity-logger.ts:129`),
  `registerProjectSync` (`src/lib/projects.ts:557`),
  `CacheService.set` (`src/dashboard/server/services/cache-service.ts:192`).
- **Fixture issue** — the obviously-fake seeded issue: project key
  `uat-fixtures`, issue prefix `FIX`, issue id `FIX-1`.
- **Crew spine** — the issue-detail UI element showing the agent tree for an
  issue: the work agent row plus review convoy sub-role rows
  (`agent-<issue>-review-<role>`), derived by
  `src/dashboard/frontend/src/lib/deriveSpecialists.ts`.

## Problem

A workspace-isolated dashboard container has **no tracker-backed issue data by
design**: `IssueDataService` is cache-only under `skipPolling`, the
container-local `cache.db`/`overdeck.db` are empty, and no project is registered
in the container-local `projects.yaml`. UI-redesign acceptance criteria are
almost entirely "open an issue and look at it", so the test role's only honest
outcome is `TESTS FAILED` for an environment reason, and the only exit is an
operator `pan close --accept-tests` override on work whose diff was never in
question. Live occurrence: PAN-3356 (cockpit redesign v2) — typecheck/lint/12,888
tests green, dashboard boots, UAT 100% blocked. Same class: PAN-2809, PAN-2619.

Three doors are shut in the container:

1. Issue data is cache-only and nothing populates it (no tracker, no deacon).
2. UI project registration fails — `GET /api/fs/list-dirs`
   (`src/dashboard/server/routes/fs.ts:22`) returns 401 (auth gate
   `rejectUnauthorizedDashboardRequest`, `src/dashboard/server/routes/dashboard-auth.ts:303-314`).
3. CLI project registration fails — `tracker_unconfigured`
   (`src/lib/pipeline-membership-gather.ts:197`) because the fresh container
   project has no tracker fields.

## Proposal

Add **`pan admin seed-uat-fixtures <issue-id>`**: one command that seeds a
minimal, obviously-fake issue fixture set into a workspace container's
container-local data stores, sufficient for the issue detail page to render
end-to-end, then restarts the container's `server` service so the skip-polling
server picks the data up.

The command has two modes:

- **Host mode (default):** `pan admin seed-uat-fixtures pan-1234` run on the
  host. Resolves the workspace's compose stack (project name
  `overdeck-feature-pan-1234`), runs the seeder **inside** the `server`
  container via `docker compose … exec -T server node dist/cli/index.js admin
  seed-uat-fixtures --local`, then `docker compose … restart server` and waits
  for the server's health endpoint.
- **Local mode:** `pan admin seed-uat-fixtures --local` run *inside* the
  container (by the host wrapper, or manually by an operator shelled in).
  Performs the actual writes against the container-local `OVERDECK_HOME`.

Local mode writes, **all through canonical write doors** (no raw SQL):

| Data | Door | Effect |
| --- | --- | --- |
| Fake project registration | `registerProjectSync('uat-fixtures', cfg)` (`src/lib/projects.ts:557`) | Container-local `projects.yaml` gains a project with **no tracker fields**, path `/home/node/.overdeck/uat-fixtures/repo` (container-writable), `issue_prefix: 'FIX'` |
| Tracker issue cache row | `CacheService.set('github', 'issues', [fixtureIssue])` (`cache-service.ts:192`) | `IssueDataService.loadCachedData()` serves `FIX-1` at boot |
| Agent rows (work + review convoy) | `saveOverdeckAgentStateSync` (`agent-state-sync.ts:274`) | `agents` table rows: `agent-fix-1-work` (branch `feature/fix-1`), `agent-fix-1-review-security|correctness|performance|requirements` with `reviewSubRole` set — the crew spine |
| Review/PR/CI state | `upsertReviewStatusSync` (`review-status-db.ts:37`) | `review_status` row: `review_status: 'approved'`, `test_status: 'passed'`, `pr_url`/`pr_number`/`pr_head_sha` (obviously fake), phase fields |
| Activity history | `emitActivityEntryDurable` (`activity-logger.ts:129`) | 3–4 `activity.entry` events for `FIX-1` (spawned → review approved → tests passed) |
| xBRIEF plan | direct file write (workspace-runtime path, not canonical state) | `/home/node/.overdeck/uat-fixtures/repo/workspaces/feature-fix-1/.overdeck/spec.vbrief.json` with 3 items + ACs, plus `continue.json` — resolved by `resolvePlanLocation`'s `findPlan(workspacePath)` fallback (`src/dashboard/server/routes/workspaces/workspace-data.ts:181-206`) so the Plan tab badge has a count |

The normalized fixture issue mirrors the GitHub normalization shape built at
`src/dashboard/server/services/issue-data-service.ts:~960-994`: `id:
'github-uat-fixtures-repo-1'`, `identifier: 'FIX-1'`, `canonicalStatus:
'in_progress'`, `labels: ['uat-fixture']`, `project: { id:
'github-uat-fixtures-repo', name: 'uat-fixtures/repo', … }`, `sourceRepo:
'uat-fixtures/repo'`.

**Obviously fake, mechanically:** reserved project key `uat-fixtures`, reserved
prefix `FIX`, issue title prefixed `[FIXTURE]`, label `uat-fixture`, description
banner stating it is seeded and not real pipeline state, PR URL host
`github.com/uat-fixtures/repo` (a repo that does not exist).

**Host-seeding guard:** `--local` refuses to run unless
`OVERDECK_DISABLE_DEACON=1` or `CONTAINER_MODE=1` is present in the environment
(both are set by the workspace compose template — verified at lines
`CONTAINER_MODE=true` (frontend env, ~line 114) and
`OVERDECK_DISABLE_DEACON=1` (server env, ~line 172) of the template), unless
`--force` is passed. This makes polluting a host `OVERDECK_HOME` a deliberate
act, never an accident.

**Idempotent:** every write is an upsert (`INSERT OR REPLACE`, `ON CONFLICT`,
file overwrite). Re-running re-seeds cleanly; required after a container
recreate wipes `/home/node/.overdeck`.

**Why a CLI command and not an HTTP seed endpoint:** the issue asks for one
command next to the existing container recovery commands (`pan workspace
rebuild`, `pan workspace reap`); a mutation endpoint on the container server
would be a new unauthenticated-write surface for no operational gain. The
restart requirement (skip-polling reads cache/DB only at boot) is handled by the
host wrapper, so the operator never has to know about it.

**Why no tracker fields on the fixture project:** with
`OVERDECK_DISABLE_DEACON=1` + `skipPolling`, no tracker sync path ever runs in
the container, so `tracker_unconfigured` can never fire from normal container
operation. The fixture project must stay tracker-less so it can never be
mistaken for — or synced to — a real tracker.

## Requirements

### Functional

- **FR-1** — One command, `pan admin seed-uat-fixtures <issue-id>`, seeds the
  complete fixture set into the named issue's workspace container and leaves
  the container dashboard serving it (including the required server restart).
- **FR-2** — After seeding, the container dashboard's issue detail for `FIX-1`
  renders: a phase, a branch (`feature/fix-1`), PR/CI state (`pr_url`,
  `pr_number`, `pr_head_sha` present), at least one work-agent row, a review
  convoy (four sub-role rows), an xBRIEF plan with a non-zero item count on the
  Plan tab badge, and at least one Activity entry.
- **FR-3** — Fixtures are obviously fake: reserved project key `uat-fixtures`,
  reserved prefix `FIX`, `[FIXTURE]` title prefix, `uat-fixture` label, and a
  description banner; no fixture field references a real repo, tracker, or issue.
- **FR-4** — Seeding requires no tracker connection and starts no deacon,
  patrol, or polling loop; the single-deacon invariant is unchanged.
- **FR-5** — Re-running the command is idempotent: it overwrites the fixture set
  and leaves no duplicate rows.

### Non-functional

- **NFR-1** — All DB writes go through the canonical write doors listed in the
  Proposal table; no raw SQL against `overdeck.db`/`cache.db` outside those
  doors.
- **NFR-2** — `--local` refuses to seed a non-container `OVERDECK_HOME` (no
  `OVERDECK_DISABLE_DEACON=1` / `CONTAINER_MODE=1`) unless `--force` is passed.
- **NFR-3** — The command is documented in `docs/WORKSPACE-CONTAINERS.md` next
  to the stack-health/recovery commands, and the test role's container guidance
  (`roles/test.md`) tells test agents to seed before declaring an
  environment-blocked UAT.

## Decisions (made in this document)

- **D1 — CLI over HTTP endpoint.** Matches the issue's requested shape
  (`pan admin seed-uat-fixtures`), avoids a new unauthenticated mutation surface,
  and the host wrapper hides the restart requirement.
- **D2 — Container-local writes only.** The fixture project/issue live only in
  the container's own `OVERDECK_HOME`; the host can never serve them through a
  read door. The `--local` guard (NFR-2) is the mechanical backstop.
- **D3 — Restart the server after seeding.** Skip-polling mode loads cache and
  read model once at boot (`main.ts:170-173`,
  `issue-data-service.ts:711-756`), so a seed without a restart is invisible.
  The host wrapper performs `docker compose restart server` and waits for health.
- **D4 — Fixture project has no tracker fields, ever.** Tracker-less config can
  never be synced, polled, or mistaken for real pipeline state; in skip-polling
  mode nothing resolves its tracker.
- **D5 — Fake project path is container-local**
  (`/home/node/.overdeck/uat-fixtures/repo`). The host project dir is mounted
  read-only in the container; the xBRIEF fallback resolution
  (`findPlan(workspacePath)`) needs a writable location for the seeded
  workspace's `.overdeck/spec.vbrief.json`.
- **D6 — No wrapper skill.** `pan admin seed-uat-fixtures` gets a row on the
  `docs/SKILLS-CONVENTION.md` exclusion list (rationale: guidance lives in
  `roles/test.md` + `docs/WORKSPACE-CONTAINERS.md`; `--help` covers mechanics).
- **D7 — The `list-dirs` 401 is out of scope.** The issue itself calls it a
  separate paper cut; seeding addresses the root. File a follow-up if desired.

## Non-goals

- Fixing `GET /api/fs/list-dirs` 401 in containers (separate paper cut).
- PAN-2809 (node-pty musl/glibc live-terminal Playwright in containers).
- Seeding real tracker data, or any tracker connection at seed time.
- Seeding the host dashboard or any non-container `OVERDECK_HOME`.
- Registering the fixture project on the host or syncing it anywhere.
- Changing deacon/patrol behavior, the single-deacon invariant, or
  `IssueDataService` polling.
- Per-project application seeds (`pan admin db seed` exists for that; this is
  Overdeck dashboard fixture data only).

## Work items

### WI-1 — Fixture data module (`fixture-data`)

New file `src/lib/uat-fixtures/fixture-data.ts`: pure, dependency-light builder
functions returning the fixture set described in the Proposal table:

- `fixtureProjectConfig()` — `ProjectConfig` for key `uat-fixtures` (no tracker
  fields, path `/home/node/.overdeck/uat-fixtures/repo`, `issue_prefix: 'FIX'`).
- `fixtureNormalizedIssue()` — the cached GitHub-shape issue (see Proposal).
- `fixtureAgentStates()` — `AgentState[]`: `agent-fix-1-work` (role `work`,
  `branch: 'feature/fix-1'`, `issueId: 'FIX-1'`) plus four convoy rows
  `agent-fix-1-review-{security,correctness,performance,requirements}` with
  `reviewSubRole` set, matching what `deriveSpecialists.ts` maps.
- `fixtureReviewStatus()` — `ReviewStatus` for `upsertReviewStatusSync`:
  `reviewStatus: 'approved'`, `testStatus: 'passed'`, `prUrl:
  'https://github.com/uat-fixtures/repo/pull/1'`, `prNumber: 1`, `prHeadSha:
  'fix7ure0000000000000000000000000000000000'`.
- `fixtureActivityEntries()` — 3–4 `EmitActivityOptions` entries for `FIX-1`.
- `fixtureXBriefDoc()` / `fixtureContinueJson()` — a valid xBRIEF v0.8 document
  (`plan.id: 'fix-1'`, 3 items each with 2 ACs, statuses `pending`) and a
  minimal continue.json.

Every literal that identifies the fixture (key, prefix, ids, URLs) is exported
as a named constant so the seeder, CLI, and tests share one source. Unit tests
in `tests/unit/lib/uat-fixtures/fixture-data.test.ts` assert: the normalized
issue matches the GitHub cache shape (fields enumerated above), every identifier
carries the fake markers (FR-3), the xBRIEF doc parses against the repo's xBRIEF
reader, and no fixture string contains `eltmon/` or a real tracker host.

**Why first:** WI-2 and WI-3 only wire these builders to doors; if the shapes
are wrong, both are wrong. This is the plan's single inspection gate.

### WI-2 — Seed writer (`seed-writer`)

New file `src/lib/uat-fixtures/seed.ts` exporting
`seedUatFixturesLocal(opts?: { force?: boolean }): Promise<SeedReport>`:

1. Enforce the NFR-2 guard: throw unless `OVERDECK_DISABLE_DEACON === '1'` or
   `CONTAINER_MODE === '1'` in `process.env`, or `opts.force`.
2. `registerProjectSync('uat-fixtures', fixtureProjectConfig())`.
3. Instantiate `CacheService` (opens container-local `cache.db` per
   `OVERDECK_HOME`) and `set('github', 'issues', [fixtureNormalizedIssue()],
   { ttlSeconds: 86_400 })`.
4. `saveOverdeckAgentStateSync` for each `fixtureAgentStates()` row.
5. `upsertReviewStatusSync(fixtureReviewStatus())`.
6. `emitActivityEntryDurable` for each `fixtureActivityEntries()` entry.
7. `mkdir -p` + write `spec.vbrief.json` and `continue.json` under
   `/home/node/.overdeck/uat-fixtures/repo/workspaces/feature-fix-1/.overdeck/`
   (path derived from `OVERDECK_HOME`, not hardcoded).
8. Return a report of what was written (counts + fixture issue id) for CLI output.

Unit tests in `tests/unit/lib/uat-fixtures/seed.test.ts` use
`setupOverdeckTestDb()` (`tests/helpers/overdeck-test-db.ts`) with a temp
`OVERDECK_HOME`: seeding populates the agents table (5 rows), review_status (1
row with PR fields), events (activity entries readable back), writes both plan
files, refuses without container env vars, honors `force`, and is idempotent on
re-run (row counts unchanged).

### WI-3 — CLI command (`cli-command`)

New file `src/cli/commands/admin/seed-uat-fixtures.ts`, registered in
`src/cli/commands/admin/index.ts` alongside the existing one-file-per-subcommand
pattern (see `admin/state-migrate.ts` for the shape):

```
pan admin seed-uat-fixtures <issue-id>   # host mode
pan admin seed-uat-fixtures --local [--force]
```

- `--local`: calls `seedUatFixturesLocal({ force })`, prints the report.
- Host mode: resolves the compose project for the issue's workspace (project
  name `overdeck-feature-<issue-lower>`; compose-file resolution follows the
  same helper `pan workspace rebuild` uses — find it via
  `grep -n "rebuildWorkspaceStack" src/lib`), refuses with a clear error if no
  such stack exists, runs
  `docker compose -p overdeck-feature-<issue-lower> exec -T server node dist/cli/index.js admin seed-uat-fixtures --local`,
  then `docker compose -p … restart server`, then polls
  `http://localhost:3013/api/health` (container-internal) or the Traefik URL
  `https://api-feature-<issue-lower>.overdeck.localhost/api/health` until 200 or
  a 60s timeout, printing the seeded fixture summary and the dashboard URL.
- Uses `execAsync`/`spawn` — never `execSync` (server-reachable code rule does
  not apply to the CLI, but match repo convention anyway).

Verify: `pan admin seed-uat-fixtures --help` renders; `npm run typecheck`;
`npm run lint` (lint-skills must stay green — the command is on the exclusion
list per D6, WI-4).

   behavior, the ephemeral-across-recreate caveat (re-seed after

   real `FIX` project).
2. `roles/test.md` — extend the container rule at line 64 ("If that isolated

   the UAT environment-blocked.
3. `docs/SKILLS-CONVENTION.md` — exclusion-list row for
   `pan admin seed-uat-fixtures` (rationale per D6).

## Acceptance criteria

- **AC-1 (FR-1, FR-2, end-to-end):** Given this issue's own workspace container
  stack is running, when `pan admin seed-uat-fixtures pan-3362` completes, then
  the command exits 0 after the server restart, and the container dashboard
  (`https://feature-pan-3362.overdeck.localhost`) shows `FIX-1` in its issue
  surfaces; opening `FIX-1`'s detail renders a phase, branch `feature/fix-1`, a
  PR link, four review-convoy rows, a Plan tab with a non-zero item badge, and a
  non-empty Activity feed. (This is the issue's browser UAT — it exercises the
  feature itself.)
- **AC-2 (FR-3):** `grep -ri "eltmon" /home/node/.overdeck/uat-fixtures/` in the
  seeded container finds nothing, and the fixture issue title begins with
  `[FIXTURE]`.
- **AC-3 (FR-4):** Seeding completes with `GITHUB_TOKEN` and `LINEAR_API_KEY`
  unset and makes no network calls to a tracker.
- **AC-4 (FR-5):** Running the seed twice in the same container leaves exactly
  one `FIX-1` cache row, five agent rows, and one review_status row.
- **AC-5 (NFR-2):** `pan admin seed-uat-fixtures --local` outside a container
  (no env markers) exits non-zero with a message naming `--force`.
- **AC-6 (NFR-1):** `grep -n "prepare(" src/lib/uat-fixtures/seed.ts` finds no
  SQL — all persistence calls the doors named in the Proposal table.
- **AC-7 (NFR-3):** `docs/WORKSPACE-CONTAINERS.md` contains a "Seeding UAT issue
  fixtures" section and `roles/test.md` names `pan admin seed-uat-fixtures` in
  its container-UAT guidance.
