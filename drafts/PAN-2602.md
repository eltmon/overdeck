## Glossary

- **Command Deck / issue tree** — the dashboard's left-rail tree of projects → issues → agent sessions, fed by `GET /api/issues/resource-allocated`.
- **Resource discovery** — `computeResourceAllocatedIssues()` in `src/dashboard/server/services/resource-discovery.ts`; scans tracker, tmux, docker, branches, PRs, workspaces per project and decides which issues appear in the tree. Cached with a 30s TTL + stale-while-revalidate (`resource-discovery.ts:22, :722-757`).
- **ResourceSource** — the tag set on a discovered issue naming why it was found: `'tracker' | 'tmux' | 'workspace' | 'branch' | 'pr' | 'vbrief' | 'beads' | 'docker' | 'remote-agent'` (`resource-discovery.ts:24`).
- **Membership filter** — the three chained `.filter()` calls at `resource-discovery.ts:661-712` that decide tree admission. Today: terminal-tracker exclusion (PAN-2054), then `readyForMerge || isLiveResource || (active tracker label && branch)`.
- **Bead** — a beads (bd 1.1.0, Dolt-native) task row; associated to an issue by a label equal to the lowercase issue id (`pan-2602`), optionally prefixed `workspace:`. Statuses: `open | in_progress | closed` (no `cancelled` status; cancellation is a close *reason*).
- **Beads read door** — `createBeadsResolver()` in `src/lib/beads/resolver.ts`; `getAllBeads()` (`:104`) is the single bulk list. Raw `bd list` in app code is forbidden by `scripts/lint-beads-access.sh`.
- **Beads write door** — `runMutationBatch()` in `src/lib/beads/writer.ts:87`; the only sanctioned mutation path (`bd close` is blocked for agents by `src/lib/beads/bd-shim.ts`).
- **beads.freshness_changed** — the only beads domain event (`packages/contracts/src/events.ts:37-47`), emitted by `beads-sync-service.ts` when a `dolt pull` advances the head.
- **Handoff/bypass conversation** — an interactive conversation spawned by `pan handoff`, often working on a `bypass/<issue>` branch outside the registered-agent pipeline.
- **Verification gate** — `runVerificationForIssuePromise()` in `src/lib/cloister/verification-runner.ts:309`; runs quality gates after a work agent signals done, with 3-strikes escalation to needs-you.
- **Close-out** — `closeOut()` in `src/lib/lifecycle/workflows.ts:159`, the true terminal of an issue; `postMergeLifecycle()` (`src/lib/cloister/merge-agent.ts:276`) is the merge-time handoff that precedes it.
- **PAN-1812 caveat** — a beads read timeout is *unknown*, not proof of zero open beads; consumers must fail closed (`src/lib/work/done-preflight.ts:62-64`).

## Problem

1. **Visibility gap.** The membership filter treats a feature branch or workspace alone as merged-issue debris (`resource-discovery.ts:701-712` comment). Work done by a handoff conversation on `bypass/pan-2564` (9+ commits, no registered agent, no issueId on the conversation) was invisible under Issues. Branch-ahead, partial beads, and conversations are collected as sources but never admit an issue.
2. **Orphaned-bead leak.** 36 GitHub-closed issues carry open beads (evidence in the issue body; 2026-07-12 audit: ~31 are done-but-never-bead-closed). Nothing reconciles beads when an issue goes terminal, so raw partial-bead progress is ~95% noise and only meaningful when gated on GitHub-issue-OPEN + recency.

## Requirements

- **FR-1** — Union in-pipeline signal: admit an issue to the tree when GitHub-OPEN and any of: (a) partial bead completion (`0 < closed < total`) with newest bead `updated_at` within 14 days; (b) any `in_progress` bead; (c) feature/bypass branch ahead of `main`; (d) open PR (already a signal); (e) issueId-linked conversation; (f) spec/PRD artifact active with mtime within 14 days. The PAN-2054 terminal exclusion stays first and wins (AC-6).
- **FR-2** — Conversations declare an issue association: `pan handoff --issue <id>`, branch auto-detect (`feature/ | strike/ | bypass/`), precedence explicit > parent inheritance > branch auto-detect > null. The `issue_id` column already exists end-to-end (Drizzle schema `src/lib/overdeck/conversations.ts:38`; legacy store `conversations-db.ts:43`; read door `conversation-reads.ts:367`); this FR populates and renders it.
- **FR-3** — Sweep orphaned beads at terminal transitions: close remaining `open`/`in_progress` beads with a reason category at close-out and at merge, plus a one-shot `pan beads sweep` backfill for the 36 existing carriers. Reason categories carried as `bd close --reason` text: merged / closed-completed / closed-not-planned.
- **FR-4** — Verification gate enforces "no open beads for this issue" as an explicit check (today only guidance text at `verification-runner.ts:623`), failing closed on read timeout (PAN-1812).
- **NFR-1** — No per-issue bead queries at render. One bulk `getAllBeads()` per refresh feeds an in-memory per-issue rollup `{total, closed, inProgress, lastUpdated}` refreshed on `beads.freshness_changed`; git branch-ahead rides the existing 30s discovery TTL.

## Key decisions (made here, not left to the executor)

- **D2/D-rollup:** the rollup is a dashboard-server in-memory service cache (new `beads-rollup-service.ts`), *not* a persisted read-model event — appending ~400-issue derived payloads to the event store on every bead write would bloat the append log with derivable data.
- **D3/D-event:** `beads.freshness_changed` today compares head before/after within one poll (`beads-sync-service.ts:100-107`), so local writes (which advance the head before the poll) never fire it. Fix: compare against the *previous poll's* head; emit on any movement. First observation records without emitting.
- **D4:** recency window = 14 days, exported named constant, no config.
- **D5:** no new bead status; "cancelled" is a close reason string.
- **D7:** issue-nested conversation rows are additive; the Conversations section keeps its full inventory (no-loss).
- **D8:** FR-4 reuses `checkOpenBeadsPromise` (`done-preflight.ts:55`) as a new `'open-beads'` check inserted after the vbrief-ac block (after `verification-runner.ts:648`), before the success path (`:701`).
- **D9:** FR-3 hooks at BOTH terminals: `closeOut` between `completeVBriefStep` (`workflows.ts:186`) and `teardownWorkspace` (`:195`), and `postMergeLifecycle` adjacent to `compactBeads` (`merge-agent.ts:437-448`). Both non-fatal. Merge hook is the backstop for bypass/admin merges that skip verification.
- **D10:** backfill verb is `pan beads sweep` under the existing beads group (`src/cli/commands/beads.ts`), report shape from `pan admin db backfill-records` (`db.ts:516-532`). GitHub-OPEN issues with orphans are skipped and listed separately — they are stalled work for FR-1, not sweep targets.

## Hazards (restated repo rules included)

- **H1 (PAN-1812):** failed/timed-out beads reads are unknown, never zero — rollup keeps last-known + stale flag; gate fails; sweep aborts.
- **H2 (AC-6):** terminal-tracker exclusion stays first; new clauses only ever *add* open-issue admissions. Regression test required.
- **H3:** merge hook must not re-trigger `postMergeLifecycle`; the locked in-flight-guard test must stay green.
- **H4:** one bulk list per refresh; resolver lock timeouts in seconds (the 500ms starvation bug was fixed in `4f6db409ef`); never raw `bd`.
- **H7 (repo rule):** delay/debounce tests use `vi.useFakeTimers()` — never real timers.
- **H8 (repo rule):** no `execSync` anywhere server-reachable; `execFileAsync` with timeouts for the new git checks.

## Acceptance criteria (issue-level)

- AC-1: an open issue with a feature/bypass branch ahead of `main` and no live agent appears in the in-pipeline surface (item 5).
- AC-2: a handoff conversation can declare an `issueId` and nests under its issue in the tree (items 6, 7, 8).
- AC-3: closing/merging an issue reconciles its remaining open beads; a GitHub-closed issue never carries open beads (items 9-12).
- AC-4: the verification gate blocks an issue with open beads; timeout ≠ proof (item 13).
- AC-5: the rollup is maintained on bead-write/git events with no per-issue query at render (items 1, 2, 5).
- AC-6: the 36 closed-orphaned issues do NOT appear as in-pipeline (item 5 regression test; items 9-12 drain them at the source).
