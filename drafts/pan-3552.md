## 1. Glossary

Every term of art this document uses, defined before use.

| Term | Meaning |
| --- | --- |
| **Convoy** | The four parallel review sub-reviewers — `security`, `correctness`, `performance`, `requirements` — each spawned as its own tmux agent and each writing one report to `.pan/review/<runId>/<subRole>.md`. |
| **Synthesis parent** | The `review`-role agent (`agent-<issue>-review`) that waits for the four convoy reports, decides APPROVED / CHANGES REQUESTED, writes `.pan/review/<runId>/synthesis.md`, and signals the verdict. |
| **Verdict of record** | The on-disk synthesis artifact (`synthesis.md` for convoy reviews, `review.md` for quick/self reviews). Per `docs/REVIEW-AGENT-ARCHITECTURE.md` it is the source of truth for a review outcome; the SQLite `review_status` row is a cache of it. |
| **The row** | The `review_status` row in the runtime SQLite cache (`reviewStatus`, `testStatus`, `reviewedAtCommit`, `lastVerifiedCommit`, …), read/written through `src/lib/review-status.ts`. |
| **Write door** | `recordReviewVerdict()` in `src/lib/cloister/review-verdict-writer.ts:130` — the single function permitted to write a *terminal* review verdict to the row, with head-anchor staleness rejection. |
| **Head anchor** | A `HeadAnchor` string (single sha, or a composite snapshot for polyrepo workspaces) identifying the commit(s) a verdict or verification was recorded against. |
| **Discovery-fork mode** | PAN-1862 machinery: the synthesis parent reads the diff first, signals `pan admin specialists discovery-ready review <id>`, and the server forks its Claude JSONL session into each reviewer so the reviewers replay the parent's context as warm prompt-cache reads. |
| **Selective re-review** | PAN-1862 machinery: on a re-review cycle, only reviewers whose domain changed are re-run; the rest carry their prior `passed` verdict forward as a stub report. Governed by `reReviewScope` (`all` \| `changed` \| `blockers`). |
| **Branch-invalidation sweep** | PAN-3154 machinery: `reconcileBranchInvalidation()` watches `origin/main`, probes in-pipeline branches with `git merge-tree`, and stamps a `conflictsSince` blocker on branches a merge invalidated. |
| **Stall sweeper** | PAN-3485/3487/3489 patrol over the parked population. It became observability-only on 2026-08-05 (PAN-3551); `sweep.action` / `sweep.unparked` are its remaining actor-shaped event surface, now emitted by nothing. |
| **Parked population** | `resolveParkedPopulation()` in `src/lib/parked/resolver.ts` — the read that classifies every stalled issue into one of ten orbits. The God View consumes it. This read is KEPT. |
| **Fallback synthesis** | `synthesizeReviewFromReports()` in `src/lib/cloister/deacon-review-signals.ts:30` — when all four reports exist and the parent is dead, read the reports, write `synthesis.md`, record the verdict. No LLM involved. KEPT. |

## 2. Problem

The review pipeline accreted eight layers over six months. The operator commissioned an evidence
review (`/home/eltmon/review-pipeline-evolution-2026-08-05.md`) that classified each layer by whether
it answers a real observed incident or a speculative threat. Two findings drive this issue:

1. **No forged verdict has ever occurred.** `git log --grep` / `git log -S` searches for forge /
   fabricated / tamper / self-approve found nothing, and the PAN-3367 audit of 30 issues with the
   "verdict laundering" signature found zero unearned merges
   (`docs/audits/pan-3367/README.md`). The threat model is trusted agents on a single-operator
   machine.
2. **Every real incident is verdict loss or row drift** — a stale record rebuild clobbering a
   `passed`, a dead parent leaving reports unsynthesized, a recovery path replaying the wrong
   verdict, five approved verdicts wiped on 2026-08-02.

The cost of the speculative layers is not theoretical. Live evidence from 2026-08-05, recorded in the
issue's comment thread while driving PAN-3511 to merge:

- **Verdict/row drift with no reconciler.** The parent finalized run `agent-pan-3511-review-80d42c27`
  as `passed` on all four lanes and the test agent recorded a durable TESTS PASSED verdict at head
  `80d42c27a5`. The POST returned HTTP 200 but landed while a duplicate review cycle was restarting.
  The row sat at `reviewStatus: reviewing` / `testStatus: pending` indefinitely. Nothing reconciled it.
- **Duplicate dispatch wedges the row.** A second review dispatch at 11:12 UTC repeated an
  already-finalized run at the same head. The parent correctly refused to duplicate its signal — but
  the dispatch path had already flipped the row to `reviewing`
  (`src/lib/cloister/review-agent.ts:546`), and the refusal path emitted nothing to reset it.
- **Manual recovery was the only exit.** `pan review request` after a `sync-main` was the only way to
  get the row moving.

## 3. Proposal

Cut the pipeline down to the operator's stated flow — *convoy reviewers do their job, they tell the
parent, the parent tells the work agent "ship it" or the feedback* — plus exactly the two protections
that answer observed incidents (the artifact as verdict of record, and the single write door), plus
the reconciliation that today's drift evidence proves is missing.

**Kept, untouched:** the convoy + synthesis parent; the verdict-of-record contract; `recordReviewVerdict()`
with its head-anchor guards; the minimal dead-parent fallback (`synthesizeReviewFromReports`); feedback
delivery to the work agent (PR comment + feedback file + `pan tell`); the parked-population read.

**Dropped:** discovery-fork + cache-miss detection; selective re-review / per-reviewer verdicts; the
branch-invalidation sweep; the stall sweeper's residual actor event surface. HMAC attestation and the
sandbox boundary are already absent from `main` — PAN-3511 merged without them — so this issue only
asserts that absence, it does not remove code.

**Added:** dispatch consults the verdict of record before mutating the row; the deacon's unapplied-verdict
reconciler covers `reviewing` rows, not only `pending` ones, and writes through the write door; a
same-head converge no longer re-gates an already-recorded test verdict.

## 4. Requirements

### Functional

- **FR-1** — The review convoy launches inline at dispatch for every harness. No session fork, no
  discovery-ready signal, no discovery-pending agent state, no fork cache-miss detector.
- **FR-2** — Every review cycle runs all four convoy reviewers. No per-reviewer verdict map, no
  carried-forward stub reports, no `reReviewScope` configuration on any surface.
- **FR-3** — No patrol probes branches for post-merge conflicts. `conflictsSince` is removed from the
  status shape, the durable record, and the parked-population orbits. The conflict gate at review
  dispatch (`resolveConflictGate`) and `pan sync-main` remain the conflict story.
- **FR-4** — The stall sweeper keeps only its detection surface. `sweep.action` and `sweep.unparked`
  event types and the per-row action-count fields are removed; `sweep.scan`,
  `sweep.recommendation`, and `sweep.escalated` remain and continue to feed the God View.
- **FR-5** — Review dispatch reads the verdict of record before writing `reviewStatus: 'reviewing'`.
  When a fresh terminal artifact exists for the active run at the current head, dispatch converges the
  row from that artifact through the write door and does not re-enter `reviewing`.
- **FR-6** — The deacon's unapplied-verdict reconciler treats a `reviewing` row with an on-disk
  verdict at current head the same as a `pending` one, and lands the verdict through
  `recordReviewVerdict()` rather than a direct `setReviewStatusSync` write.
- **FR-7** — `recordReviewVerdict()` does not reset a terminal `testStatus` when the incoming verdict's
  evidence head equals the head the test verdict was recorded against.
- **FR-8** — The documentation describing the review pipeline, the parked population, the merge
  workflow, and the flywheel state model describes the simplified flow; no doc instructs an agent or
  operator to use a removed command, setting, or event.

### Non-functional

- **NFR-1** — `npm run typecheck`, `npm run lint`, and `npm test` stay green at every item boundary.
  Each item must leave the tree shippable on its own.
- **NFR-2** — No removal may widen a write surface. `recordReviewVerdict()` remains the only terminal
  verdict write door, and `tests/unit/lib/head-anchor-write-sites.test.ts` must stay an exact-match
  audit (entries are removed when their site is removed, never loosened).
- **NFR-3** — Removals must not strand a caller. `npm run lint:circular`,
  `npm run lint:source-introspection`, `npm run lint:park-exits`, and `npm run lint:file-size` are
  part of `npm run lint` and must pass unmodified except for baseline entries that genuinely no
  longer exist.

## 6. Decisions made in this document

These are decided here so no work item requires judgment.

- **D1 — HMAC attestation and the sandbox boundary are already gone.** `src/lib/review-attestation-key.ts`,
  `src/lib/agent-host-secret-boundary.ts`, and `src/lib/cloister/review-artifact-attestation.ts` do not
  exist on `main` at `299d98db34`; the only surviving mention is
  `roles/review-security.md:42-43`, which instructs reviewers not to *ask* for them. There is no
  removal item — item 15 asserts the absence in the architecture doc.
- **D2 — Keep `src/lib/conversations/session-fork.ts`.** The review fork is one of its two consumers;
  conversation summary forks are the other and are unrelated to this issue. Remove only the review
  caller.
- **D3 — Keep the per-lane convoy recovery, rename it.** `handleReviewDiscoveryReady` does two jobs:
  the fork launch (dropped) and per-lane recovery of reviewers that died without writing a report
  (PAN-3368 — kept, and the same-run parent resume at `review-agent.ts:716` depends on it). Rename it
  `launchMissingConvoyReviewers(issueId, opts)` with fork parameters removed, and keep every caller
  pointed at the renamed function.
- **D4 — Keep `checkStalledReviewParents`.** It is already observability-only (PAN-3551) and is one of
  the "real protections" the report keeps. It is out of scope for this issue except where it reads
  removed fields.
- **D5 — Do not migrate the SQLite `agents` columns.** `review_discovery_pending`,
  `review_discovery_ready_at`, `review_convoy_forked_at`, `review_fork_cache_checked`, and
  `review_forked_from_parent` stay in the schema as inert columns; the code stops reading and writing
  them. The `agents` table is a rebuildable cache (`docs/AGENT-STATE-PLANES.md`), so a destructive
  column drop buys nothing and risks a boot failure. `review_context_manifest_path` is still used and
  stays wired.
- **D6 — Removing `reReviewScope` from the config schema is not a breaking change requiring a
  migration.** `loadYamlConfig` validation in `src/lib/config-yaml/roles.ts:297` currently *rejects*
  invalid values; after removal an unknown `roles.review.reReviewScope` key in a user's
  `config.yaml` must be ignored, not fatal. Verify by loading a config that still carries the key.
- **D7 — `conflictsSince` is removed from the status shape and the durable record, not merely stopped.**
  Durable per-issue records on `overdeck-state` that already carry the field simply lose it on their
  next rebuild; record readers must tolerate the extra key rather than throw.
- **D8 — Convergence writes with `writer: 'reconciler'`.** The write door's `VerdictInput.writer`
  already carries the writer tag used in `review.verdict_dispatched` / `review.verdict_rejected`
  events; dispatch-time convergence uses `'dispatch-converge'` and the deacon reconciler uses
  `'reconciler'`, so the God View and the activity feed can tell them apart.
- **D9 — Freshness for a dispatch-time converge is the existing artifact window.**
  `SYNTHESIS_ARTIFACT_FRESH_MS` (30 minutes, `src/lib/cloister/synthesis-verdict.ts`) already defines
  "belongs to the current review cycle". Reuse it; do not introduce a second window.
- **D10 — This ships as one xBRIEF, not sibling issues**, with `plan.metadata.sizeJustification` set.
  `review-agent.ts`, `review-convoy.ts`, `review-status.ts`, `pan-dir/record.ts`,
  `parked/resolver.ts` and `deacon.ts` are each touched by two or more of the five drops, so parallel
  sibling workspaces would rebase-conflict on nearly every item. The DAG's `blocks` edges serialize
  exactly the items that share files.
- **D11 — PAN-3512 is upstream of this plan, not part of it.** A strike agent (`strike-pan-3512`) is
  implementing PAN-3512 — the `recordReviewVerdict` write door, its dispatch-not-drop semantics, and
  the fallback kill-conditional — in these same files while this plan is being authored. Items 7.7,
  7.12, 7.13 and 7.14 carry `metadata.upstreamDependency: "PAN-3512"`. Each of them **must run
  `pan sync-main PAN-3552` before its first edit** and must build on whatever write-door shape
  PAN-3512 merged. Do not reimplement dispatch-not-drop, do not re-derive the fallback
  kill-conditional, and do not "correct" the write door's signature back to what this document shows
  if PAN-3512 changed it — adapt to it.

## 10. Hazards for the implementing agent

1. **`tests/unit/lib/head-anchor-write-sites.test.ts` is an exact-array audit.** Removing an anchor
   write site fails the suite until the matching `allow(...)` entry is deleted. Delete entries; never
   relax the comparison.
2. **`scripts/source-introspection-baseline.txt` and `scripts/file-size-allowlist.txt` are ratchets.**
   Deleting a test file or shrinking a god file may require a baseline edit in the same commit; the
   file-size ratchet compares against `origin/main` at lint time, so shrinking never needs an entry
   but a moved file might.
3. **`npm run typecheck` excludes every `*.test.ts`.** A removal that breaks a test's types is only
   caught by `npm test` — run both.
4. **Stale vitest cache.** If a test still exercises deleted code after the edit, remove
   `.experimental-vitest-cache` before concluding the change did not apply.
5. **Circular imports.** `review-status.ts` reaches back into cloister, which is why several call
   sites use dynamic `await import()`. Preserve that shape when editing; `npm run lint:circular` is in
   `npm run lint`.
6. **The parked resolver's orbit count is asserted.** `src/lib/parked/__tests__/resolver.test.ts`
   covers "all ten orbits"; removing the conflicts orbit makes it nine.
7. **Per-item push discipline.** Commit exactly one item at a time and push the feature branch before
   `pan task done`.
8. **PAN-3512 is landing in these files right now.** `strike-pan-3512` owns the `recordReviewVerdict`
   write door, dispatch-not-drop, and the fallback kill-conditional. Run `pan sync-main PAN-3552`
   immediately before starting items 7.7, 7.12, 7.13 and 7.14, re-read
   `src/lib/cloister/review-verdict-writer.ts` after the sync, and adapt to the merged signature. If a
   step in this document contradicts what PAN-3512 landed, PAN-3512 wins and the deviation goes in the
