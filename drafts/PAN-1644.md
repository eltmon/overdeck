# PAN-1644: Hook-driven progressive conversation titling

**Issue:** https://github.com/eltmon/overdeck/issues/1644
**Status:** proposed (planning completed 2026-07-07)
**Follow-up split-out:** PAN-1646 (semantic topic-drift titling — separate product feature)

## Glossary

- **Conversation** — a dashboard-managed Claude Code (or Pi/Codex) chat session. DB row in the `conversations` table (`src/lib/database/schema.ts:463`), keyed by unique `name`; its tmux session is `conv-<name>`.
- **title_source** — TEXT column recording how the current title was produced. Type `LegacyTitleSource` at `src/lib/overdeck/conversations.ts:621`: `'auto' | 'ai' | 'ai-refined' | 'manual' | 'default'`. This PRD adds `'ai-explicit'`.
- **Deterministic title** — a title derived from the user's prompt text by string processing only (no model call).
- **Replaceable title** — a title automatic machinery may overwrite. Protection invariant: `'manual'` and (new) `'ai-explicit'` are never overwritten by automatic paths.
- **cheapMode** — `backgroundAi.cheapMode` config flag; `isBackgroundFeatureEnabled()` (`src/lib/background-ai/features.ts:37-44`) returns false for ALL background AI features when set.
- **UserPromptSubmit hook** — Claude Code hook firing when the user submits a prompt; script at `sync-sources/hooks/user-prompt-submit-hook`, installed to `~/.overdeck/bin/` and registered in `~/.claude/settings.json` by `src/cli/commands/setup/hooks.ts` (~365-519).
- **Stop hook** — Claude Code hook firing when the assistant finishes a turn; script at `sync-sources/hooks/stop-hook`.
- **Internal token** — `x-overdeck-internal-token` header checked by `hasDashboardInternalToken()`; hooks read it from `$OVERDECK_INTERNAL_TOKEN` or `~/.overdeck/internal-token` (see `user-prompt-submit-hook` lines 34-40).
- **Write door** — `updateConversationTitle(name, title, titleSource)` at `src/lib/overdeck/conversations.ts:1300` is the single write path for titles (two-door rule).
- **Event store** — `getEventStore()` at `src/dashboard/server/event-store.ts:402` (THROWS if called before `initEventStore()` — relevant for non-server callers). `emitOnly()` = in-memory, non-persisted domain event.
- **conversationsListRevision** — read-model counter (`packages/contracts/src/event-reducers.ts:99-101`); the sidebar `ConversationList.tsx:207-212` invalidates the `['conversations']` React Query on every bump.

## Problem

Conversations get stuck on `New conversation` because titling is coupled to HTTP message-delivery handlers instead of canonical hook signals. Verified live on 2026-07-07: 30 non-archived stuck rows, ALL `title_source='default'`, ALL `ended`, none with a resolvable transcript file. Root causes (all verified at the cited lines):

1. Blank-start creation writes `title='New conversation'`, `titleSource='default'` — `src/lib/overdeck/conversation-runtime.ts:734-735`.
2. First-later-message path is AI-only: `src/lib/overdeck/conversation-message.ts:366-371` calls `deps.generateAiTitle()` only when `conv.titleSource === 'default'`, no deterministic title first.
3. cheapMode kills the AI path: `generateAiTitle()` (`src/lib/overdeck/conversation-reads.ts:638-665`) returns immediately when `isBackgroundFeatureEnabled('conversationTitles')` is false; `features.ts:42` returns false whenever `backgroundAi.cheapMode` is true.
4. The UserPromptSubmit hook has the prompt text + `session_id` (stdin JSON) but only emits `waiting_clear` / `message_received` / `thinking_start` heartbeat events that drop the prompt.
5. No title-changed event exists; title propagation relies on React Query polling (2s pending / 10s normal, `ConversationList.tsx:193-202`).
6. First-answer refinement (`scheduleTitleRefinement()`, `conversation-reads.ts:667-764`) polls the JSONL every 1.5s for up to 10 minutes.
7. Explicit user retitle writes `title_source='ai'` (`conversation-reads.ts:836`) — indistinguishable from automatic AI titles, so refinement (which replaces `'ai'`) can overwrite a user-requested retitle.

## Decisions (Planning Q&A)

### Q1 — Title-source model (answered 2026-07-07)

**Question:** Lock flag vs more precise title_source values?
**Options offered:** (1, Recommended) Precise source values — add `'ai-explicit'`, no migration; (2) `title_locked` boolean column via migration; (3) full vocabulary overhaul + data migration.
**Answer: Option 1 — precise source values.** Add `'ai-explicit'` for user-requested retitles. Protected set = `{'manual', 'ai-explicit'}`. No schema migration; `NULL` title_source (346 legacy rows) stays protected-by-default (current `canReplaceTitle` already returns false for it).

### Q2 — Backfill mechanics (answered 2026-07-07)

**Question:** How does the backfill run and what do no-transcript rows get? (All 30 current stuck rows have no transcript.)
**Options offered:** (1, Recommended) Admin CLI command + dated fallback; (2) CLI report-only for no-transcript rows; (3) boot-time migration.
**Answer: Option 1.** `pan admin conversations backfill-titles` → server endpoint; transcript-backed rows titled from first user message; no-transcript rows get `Untitled — <YYYY-MM-DD of created_at>` (source `'auto'`) and are listed in the report with reason `no transcript`. Satisfies the "0 stuck" acceptance.

### Q3 — Refinement scope (answered 2026-07-07)

**Question:** Once-only first-answer refinement, or add later-turn cadence now?
**Options offered:** (1, Recommended) once-only, defer ongoing to PAN-1646; (2) add later-turn cadence now.
**Answer: Option 2 — add later-turn cadence now.** Subsequent Stop events may re-refine with debounce, still respecting protected sources. (PAN-1646 remains the separate semantic topic-drift feature.)

### Auto-decisions (technical, made by planner)

- **AD-1 Endpoint shape:** dedicated `POST /api/hooks/user-prompt-submit` and `POST /api/hooks/turn-complete` in `src/dashboard/server/routes/hooks.ts`, modeled on the existing `postPermissionEventRoute` (`hooks.ts:349-393`): parse JSON, resolve `getConversationByClaudeSessionId(session_id)` (`src/lib/overdeck/conversations.ts:996`), no-op `{ok:true}` when unresolvable. Both REQUIRE the internal token (`hasDashboardInternalToken`, as `postMemoryTurnRoute` does at `hooks.ts:328`) — stricter than permission-event, which the work agent must NOT weaken.
- **AD-2 Resolution key:** `session_id` from hook stdin JSON via `conversation_files.locator`, per the issue ("not by tmux/agent id"). No `conv-<name>` fallback — a miss is a silent no-op.
- **AD-3 Deterministic derivation:** new `derivePromptTitle(prompt: string): string` in `src/lib/conversations/transcript-summary.ts`, reusing the compaction rules of `fallbackTranscriptTitle()` (lines 111-144: strip code fences/URLs/filler, first 8 words, `sanitizeTitle`) applied to the raw prompt; when compaction yields empty, fall back to the creation-path truncation (60 chars + `…`, `conversation-runtime.ts:733-734`).
- **AD-4 Deterministic titling condition:** only when `titleSource === 'default'`. An `'auto'` title is already prompt-derived; later prompts must not re-derive it (that job belongs to AI refinement / PAN-1646).
- **AD-5 Refinement eligibility:** new `canRefineTitle(conv)` beside `canReplaceTitle` (`conversations.ts:1416-1419`): refinable sources = `{'default','auto','ai','ai-refined'}`; `'manual'`, `'ai-explicit'`, and `NULL` are never refinable.
- **AD-6 Later-turn cadence:** in-memory per-conversation state `{turnsSinceRefine, lastRefinedAtMs}` in the refinement service. First refinement (titleSource ∈ {'default','auto','ai'}): refine on the next turn-complete, no debounce. Later refinements (titleSource `'ai-refined'`): only when `turnsSinceRefine >= 5` AND `now - lastRefinedAtMs >= 10 * 60_000`. Constants `LATER_REFINE_MIN_TURNS = 5`, `LATER_REFINE_MIN_INTERVAL_MS = 600_000` (module constants; config surface deferred). State resets on server restart — acceptable, next turn-complete re-primes it.
- **AD-7 Event emission point:** `conversation.title_changed` is emitted from inside `updateConversationTitle()` (the write door) so every writer (deterministic, ai, ai-refined, manual PATCH, explicit retitle, backfill) emits. Guard with try/catch around `getEventStore()` because it throws before `initEventStore()` (`event-store.ts:402-410`) — non-server contexts (unit tests, any CLI import) must not crash.
- **AD-8 Backfill runs server-side:** CLI calls `POST /api/admin/conversations/backfill-titles` (in `src/dashboard/server/routes/admin.ts`, which already mirrors the `pan admin` namespace). Keeps the single write door and event emission; direct-DB CLI writes are rejected. CLI errors clearly if the dashboard is not running. `--dry-run` supported.
- **AD-9 Hook non-blocking:** new hook curl calls use `-m 1` max-time and must not change hook exit codes (hooks `set +e`, `exit 0`). jq-guarded body construction like the existing memory-inject block (`user-prompt-submit-hook:42-50`).
- **AD-10 HTTP path compat:** `handleConversationMessage` sets the deterministic title synchronously when `titleSource === 'default'` before its existing optional `generateAiTitle` call — HTTP-only installs (hooks absent) still get titles. Hook and HTTP paths are idempotent against each other (second writer sees `titleSource !== 'default'`).
- **AD-11 Polling removal:** `scheduleTitleRefinement()` (`conversation-reads.ts:667-764`) and its only call site (`conversation-reads.ts:664`) are deleted; turn-complete refinement supersedes it (no-loss audit: first-answer refinement behavior is preserved by the new service, and gains later-turn cadence).

## Requirements

- **FR-1** On the first `UserPromptSubmit` for a conversation with `titleSource='default'`, the server sets a deterministic prompt-derived title (source `'auto'`) — even when `backgroundAi.cheapMode=true`, without waiting for delivery or the assistant answer, and without any model call.
- **FR-2** Automatic titling/refinement never overwrites `'manual'` or `'ai-explicit'` titles; explicit user retitle now records `'ai-explicit'`.
- **FR-3** Every title write emits `conversation.title_changed`; the conversation list updates from the event (revision bump → query invalidation), not from waiting on the poll interval.
- **FR-4** First-answer refinement is triggered by the Stop hook (`/api/hooks/turn-complete`), not JSONL polling; `scheduleTitleRefinement()` is removed.
- **FR-5** Later-turn refinement runs on subsequent turn-completes with debounce (≥5 turns AND ≥10 min since last refinement), only for refinable sources, only when `titleRefinement` is enabled.
- **FR-6** The HTTP message path still produces a deterministic title without hooks installed; existing send behavior unchanged.
- **FR-7** `pan admin conversations backfill-titles` renames all titleable stuck rows: transcript-backed from first user message, no-transcript to `Untitled — <date>`, with a per-row report (`--dry-run` supported). After a real run, 0 non-archived rows remain at `New conversation`.
- **NFR-1** Deterministic paths make zero AI invocations.
- **NFR-2** Hook script additions are fire-and-forget (`curl -m 1`), never block or fail the hook.
- **NFR-3** All debounce/cadence tests use vitest fake timers (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`) — repo rule, no real waits.
- **NFR-4** All title writes go through `updateConversationTitle()`; no new direct `UPDATE conversations` statements.
