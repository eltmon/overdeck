# PAN-2372 — bug(swarm): slot finishes (`pan done`) without writing durable completion state

**Issue:** https://github.com/eltmon/overdeck/issues/2372
**Author:** planning agent (claude-fable-5), 2026-07-10
**Mode:** `pan plan --auto` (no interactive Q&A; defaults recorded in autoDecisions)

## Glossary

- **Swarm / slot** — a swarm parallelizes one issue's vBRIEF items across N slot worktrees (`workspaces/feature-<issue>-slot-<n>`), each with its own agent (`agent-<issue>-slot-<n>`) and branch (`feature/<issue>-slot-<n>`). The deacon's swarm coordinator (`coordinateSwarmSlots` in `src/lib/cloister/deacon-swarm.ts`) classifies slots, merges ready ones into the feature branch, and finalizes the issue.
- **Per-issue record** — the single durable JSON record for an issue (`PanIssueRecord`, `src/lib/pan-dir/record.ts:151`). Post-migration it lives at `${OVERDECK_HOME}/state/<project>/records/<issue>.json` on the `overdeck-state` branch; pre-migration at `<workspace>/.pan/records/<issue>.json`.
- **statusOverrides** — the record field mapping vBRIEF item/subItem ids to statuses. The canonical spec on `overdeck-state` is immutable; item done-ness lives only in this overlay.
- **Runtime plane** — rebuildable local state: agent `state.json`, the agents table, agent events/`getAgentRuntimeState`. Per `docs/AGENT-STATE-PLANES.md`, it can be rebuilt (and therefore lost) at any time.
- **Durable / permanent plane** — the per-issue record on git (`overdeck-state`). Survives DB rebuilds, dashboard restarts, and host moves.
- **classifyInFlightSlots** — `src/lib/cloister/deacon-swarm.ts:359`. Buckets each in-flight slot into `running | ready-to-merge | failed | stalled | awaiting-completion-signal`.
- **classifyDurableReadySlot** — `src/lib/cloister/deacon-swarm-completion.ts:80`. Mode-independent predicate: slot branch ahead ≥ 1 of the feature branch AND slot worktree clean ⇒ `ready-to-merge`.
- **infer_completion** — `swarm.infer_completion` config (`off | nudge | auto`), read by `swarmInferCompletionMode()` (`deacon-swarm-completion.ts:110-113`). `nudge` only messages the slot to run `pan done`; `auto` additionally converges a stably-done slot to `ready-to-merge`.
- **State-plane predicate** — `isStatePlanePath` / `isStatePlaneOnlyStatus` / `isStatePlaneOnlyDiff` in `src/lib/state-plane.ts` — the ONE shared classifier for "this diff/status touches only pipeline state, not code" mandated by `docs/STATE-PLANE-COMMIT-POLICY.md` (operator comment on this issue, 2026-07-06).

## Problem

Three verified facets of one durable-completion gap (cluster with PAN-2363/PAN-2364; third facet reproduced live on PAN-2378 during RUN-56):

1. **Slot `pan done` persists nothing durable.** `completeSlotWork` (`src/cli/commands/done.ts:438-472`) writes agent `state.json` (`stopped`) and `saveAgentRuntimeState(... resolution: 'completed')` — both runtime-plane. No statusOverride, no record marker. If the runtime resolution is lost (DB rebuild, dashboard restart, event not delivered from the CLI process), the deacon can never again distinguish "done, awaiting merge" from "idle" — `[swarm] PAN-XXXX slot N running` forever, no finalize, no PR. (The original 2026-07-05 incident manifested as an empty workspace `continue.json`; the write surface has since moved to the per-issue record, but the gap — completion without a durable, verified write — is unchanged.)
2. **Record writes are neither atomic nor corruption-safe.** `writeIssueRecordSync` (`record.ts:261-281`) and `writeIssueRecordForWorkspaceSync` (`record.ts:288-308`) use plain `writeFileSync` — a mid-write crash truncates the record (the "empty/malformed at char 0" symptom). All record readers (`readIssueRecord*`, `record.ts:310-341`) catch-all to `null`, and `ensureIssueRecordSync` (`record.ts:504-530`) then fabricates a fresh empty record, so the next write **silently replaces** a corrupt record, destroying every accumulated statusOverride.
3. **The deacon's completion detection reads the wrong record and can't converge alive-idle slots.**
   - **Split-brain read doors:** `defaultReadStatusOverrides` (`deacon-swarm.ts:216-222`) and all swarm durable state (`finalizedAt`, `failedMergeBlock`, slot assignments, superseded attempts) go through `readIssueRecordForWorkspaceSync`/`writeIssueRecordForWorkspaceSync`, which are hard-wired to `<workspace>/.pan/records/` (`getIssueRecordPathForWorkspace`, `record.ts:196-198`) with **no migration resolution**. The merge path's mirror (`mirrorTaskOperationToRecord` → `writeStatusOverridesSync`, `src/lib/vbrief/dag-cli.ts:108-137`) resolves through the supposedly migration-aware `getIssueRecordPath` (`record.ts:206-212`) — which is ALSO broken today, see the next bullet. Once resolution is fixed, without WI-2 the writer and the deacon's reader would use **different files** on a migrated project: merged items never appear completed to the coordinator, and every swarm write to `<workspace>/.pan/records/` is a stray legacy writer per `docs/STATE-PLANE-COMMIT-POLICY.md`.
   - **State-home key mismatch (discovered live during this planning session, 2026-07-10):** `resolveStateReadHomeSync` in `src/lib/state-read-home.ts:21` defaults `projectKey = basename(project.path)` (`"overdeck"`), but the state worktree is keyed by the **projects.yaml key** (`"panopticon-cli"`) — the convention `state-home.ts`'s `projectKey()` (`state-home.ts:69-74`, `listProjectsSync().find(...).key`) implements. `~/.overdeck/state/overdeck/migration-complete.json` does not exist, so every consumer of the sync read door — `getIssueRecordPath` (`record.ts:207`), `projectPanPaths`/specs/drafts (`specs.ts:32`), the auto-commit queue (`auto-commit.ts:31`), and the `pan plan finalize` PRD gate — silently treats this **migrated** project as unmigrated and resolves legacy `.pan/` paths. This is exactly the "detection depends on a marker that can be silently empty/absent" failure mode the issue names, one level up: the migration marker read misses due to a wrong key, and the code falls back silently instead of surfacing the mismatch.
   - **Alive-idle never converges:** in `classifyInFlightSlots`, `classifyDurableReadySlot` is consulted only in the missing-agent (line 380) and vanished-session (line 395) branches. An alive-but-idle slot falls to `classifyDoneWithoutSignal`, whose auto-convergence (`deacon-swarm-completion.ts:66`) requires `mode === 'auto'` — but the default is `'nudge'` (`config.ts:391`, fallback at `deacon-swarm-completion.ts:112`) and nothing sets it. Verified live on PAN-2378: two clean+ahead gpt-5.5 slots that never ran `pan done` stalled permanently; reaping their sessions let `classifyDurableReadySlot` converge them with zero work lost — operator confirmed the predicate is correct and `auto` is the substrate-correct default (`docs/FLYWHEEL-STATE.md:1880-1905`).
   - **Clean-check defeated by state-plane dirt:** `defaultIsSlotWorktreeClean` (`deacon-swarm-completion.ts:129-132`) requires porcelain-empty. Untracked/modified state-plane files (e.g. `.pan/continue.json`, `.pan/records/`) in a slot worktree make a genuinely-done slot read dirty, blocking the durable-ready predicate. Policy rule (operator comment): use the ONE shared state-plane predicate, not per-gate path lists.

## Proposal

Make slot completion a durable, verified, single-door write, and make the deacon's detection consume durable state through the same door:

0. Unify state-home key resolution: `resolveStateReadHomeSync` resolves the projects.yaml key exactly like `state-home.ts`'s `projectKey()` (basename only as fallback), so migrated projects actually resolve migrated.
1. Atomic (tmp + rename) record writes with read-back verification and corrupt-file sidecar preservation at the record write door.
2. Re-home the workspace record door (`getIssueRecordPathForWorkspace` and its read/write wrappers) onto the same migration-aware resolution as `getIssueRecordPath`, converging every swarm read/write on the canonical record.
3. Slot `pan done` writes a durable `swarm.slotCompletions` marker into the per-issue record and verifies it by reading it back; failure exits non-zero so the agent knows completion did NOT persist.
4. `classifyInFlightSlots` treats a matching durable marker as `ready-to-merge` regardless of session/runtime state; the coordinator clears the marker on merge and on requeue/supersede; unreadable (vs absent) records are surfaced, never silently treated as "no progress".
5. Default `swarm.infer_completion` flips `nudge` → `auto` (explicit `nudge`/`off` still honored), so clean+ahead alive-idle slots converge after the existing nudge + 2-consecutive-stable-passes grace.
6. `defaultIsSlotWorktreeClean` uses `isStatePlaneOnlyStatus` so state-plane-only dirt counts as clean.

## Requirements

- **FR-1** `writeIssueRecordSync` and `writeIssueRecordForWorkspaceSync` write via temp-file-then-`renameSync` (same-directory), never truncate-in-place, and verify the renamed file parses as JSON; a failed verification throws.
- **FR-2** When a record write path encounters an existing record file that exists, is non-empty, and fails `JSON.parse`, it preserves the corrupt bytes as `<recordPath>.corrupt-<epochMs>` and logs a warning before writing a fresh record. Corrupt records are never silently overwritten.
- **FR-3** `getIssueRecordPathForWorkspace` resolves the owning project from the workspace/issue and, when resolvable, delegates to `getIssueRecordPath` (canonical, migration-aware); when the project cannot be resolved it falls back to `<workspace>/.pan/records/`. `writeIssueRecordForWorkspaceSync` queues `queueIssueRecordCommit` when the project is resolvable.
- **FR-4** Slot-shaped `pan done` (`completeSlotWork`) persists `swarm.slotCompletions[String(slotIndex)] = { slotIndex, itemId, agentId, completedAt }` in the per-issue record before touching runtime state.
- **FR-5** After writing the marker, `completeSlotWork` reads the record back through the read door and confirms the marker is present and parseable; on failure it prints an explicit error and exits with a non-zero code.
- **FR-6** `classifyInFlightSlots` classifies a slot `ready-to-merge` (signal `durable-completion`, exitStatus 0) when the durable marker exists and its `itemId` equals the slot's current `itemId` — in every liveness branch (alive, dead, vanished, missing-agent), checked before the runtime-state consultation.
- **FR-7** The coordinator clears the slot's marker after a successful slot merge and when a slot is requeued or superseded; `defaultReadStatusOverrides` distinguishes an absent record from an unreadable one and surfaces unreadable records as a warning action instead of silent `undefined`.
- **FR-8** The default `swarm.infer_completion` is `auto` (both the config default at `config.ts:391` and the fallback in `swarmInferCompletionMode`); explicitly configured `nudge`/`off` are honored unchanged.
- **FR-9** `defaultIsSlotWorktreeClean` returns true when `git status --porcelain` output is empty OR every reported path satisfies `isStatePlanePath` (via `isStatePlaneOnlyStatus`).
- **FR-10** `docs/SWARM.md` documents the durable completion marker, the `auto` default, and the state-plane-aware clean check; `docs/AGENT-STATE-PLANES.md` documents that swarm durable state (including `slotCompletions`) lives in the per-issue record on the permanent plane through the canonical door.
- **FR-11** `resolveStateReadHomeSync` (`src/lib/state-read-home.ts:21`) resolves the state-worktree key from projects.yaml (same semantics as `projectKey()` in `state-home.ts:69-74`: registered project key first, `basename(project.path)` only as fallback), so a migrated project whose directory basename differs from its project key resolves `migrated: true`.
- **NFR-1** All new/changed behavior is covered by unit tests that inject `now`/deps (existing pattern in `tests/unit/lib/cloister/deacon-swarm-*.test.ts`); any delay/backoff-adjacent test uses fake timers or injected clocks, never wall-clock sleeps.
- **NFR-2** No `execSync` anywhere server-reachable; async exec only (existing rule, restated because this touches deacon code).

function writeRecordFileAtomicSync(path: string, record: PanIssueRecord): void {
