## Glossary

Define these before reading further; the document uses them exactly as defined.

- **Workspace registry** — the PAN-1990 runtime-plane tables (`projects`, `workspaces`, `project_targets`, `pinned_docs`) reached only through the two doors: `src/lib/workspaces/resolver.ts` (reads) and `src/lib/workspaces/writer.ts` (writes), enforced by `scripts/guard-workspace-doors.sh` in `npm run lint`.
- **Workspace kind** — `WorkspaceKind = 'main' | 'issue' | 'scratch'` (`src/lib/workspaces/types.ts`). `main` = singleton project root; `issue` = pipeline-owned worktree 1:1 with a tracker issue; `scratch` = user-created, shared-directory by default or `--isolated` worktree.
- **Target directory / target path** — the directory a workspace's `path` column points at. A *shared* workspace targets an existing checkout it does not own; an *isolated* workspace owns a dedicated git worktree.
- **Project target** — a row in `project_targets(project_id, path, is_primary)`: one of possibly several directories a project claims. Exactly one `is_primary=1` per project (partial unique index). CLI: `pan project add-target` (`src/cli/commands/project.ts:410`).
- **Memory home** — `~/.overdeck/memory/{projectId}/{workspaceId}/` containing `observations/`, `pending/`, `status.json`, `archive/`, `summaries/`, `rag-runs/`, `metadata.json`. Path builders in `src/lib/memory/paths.ts`.
- **Status rollup** — the LLM-synthesized `MemoryStatus` snapshot (`packages/contracts/src/memory.ts`): headline, summary, goal, `phase`, accomplished, decided, open, nextSteps, confidence, workingSet, tags. `MemoryStatusPhase` literals (`packages/contracts/src/memory.ts:50`): `"exploring" | "planning" | "building" | "verifying" | "cleaning" | "shipping"`.
- **Status archive** — prior status snapshots written by the rollup commit path into `archive/` (`resolveArchiveDir`, `src/lib/memory/paths.ts:57`; archived by `commitStatusRollup`, read back by `readArchivedStatuses`, `src/lib/memory/rollup.ts:210`).
- **Prompt-time injection** — `injectPromptTimeMemory()` (`src/lib/memory/injection.ts:74`): at UserPromptSubmit and agent spawn, expands the query (`src/lib/memory/query-expansion.ts`), searches FTS, and injects status + hits + pinned docs under byte budgets, logging a `RagDecision` to `rag-runs/`.
- **Subspace** — the closed-source desktop app whose workspace model PAN-1990 was modeled on. Its observed behavior (grove.db schema, `subspace workspaces` and `subspace-memory` CLIs, Claude Code hook wiring) is the parity reference; see "Subspace reference model" below.
- **Workspace ref** — a workspace id or name resolved by `resolveWorkspaceRef()` (`src/lib/workspaces/resolver.ts:100`): id match first, then cross-project unique-name match; ambiguity is reported, never guessed.

## Motivation

PAN-1990 ported Subspace's storage model near-1:1 (UUID identity, kind enum, `project_targets`, per-workspace memory homes, per-project FTS with a workspace column, archive-not-delete, resolver/writer two doors). What did not carry over is the *premise*: in Subspace a workspace is a long-lived, user-owned lens that **targets** a repo directory, independent of any issue — created by operator intent, relocatable, recallable by target directory, with a browsable status history and a standing session briefing. In Overdeck the pipeline is the workspace factory, and the user-facing mode (`scratch`) can only target the project's primary path. This PRD closes the remaining behavioral gaps while keeping Overdeck's deliberate divergences (see Decisions).

## Subspace reference model (observed evidence, 2026-07-29, app v0.10.26)

- `grove.db` (`~/Library/Application Support/com.subspace.app/grove.db`): `workspaces(id UUID, project_id FK, name, path, branch_name, parent_branch, parent_branch_guessed, is_main_repository, is_git_repository, is_archived, title, layout_config, is_favorite, …)`; `project_targets(project_id, path, is_primary)` with one primary per project. Multiple workspaces may target one directory; a project carries multiple target paths.
- CLI: `subspace workspaces create --name --target-path <dir> [--shared (default) | --isolated] [--parent-branch] [--git-start-point]`; `workspaces plan` (resolve intent without creating — dry run); `workspaces update --relocate` (repoint a workspace at a moved clone); `list/get/activate/delete`.
- Recall: `subspace-memory workspace-search | target-search | project-search | global-search | timeline | read <path> [--from --lines] | status [--workspace] [--history N]`. `target-search` = "workspaces targeting this directory."
- Session priming: SessionStart hook runs `subspace-memory inject` — emits a rendered briefing (status + recent observations + cross-workspace + docs) into the session, deduped per session via `.injected.json`; UserPromptSubmit runs scoped first-prompt RAG.
- Status lifecycle: each synthesis archives the prior status to `memory/archive/YYYY-MM-DD_<slug>.json`; `status --history N` reads it. `status.json.phase` is memory-synthesized (`exploring`, `verifying`, …), not pipeline-derived.

## Decisions

- **D-1 (kept from PAN-1990): `issue` kind and the pipeline-as-factory stay.** Issue workspaces continue to be created by `createWorkspacePromise()` and archived by lifecycle flows. Parity work must not alter issue-workspace creation, teardown, or the pipeline-phase badge for issue rows.
- **D-2: UUID-keyed memory homes stay.** No renames of `~/.overdeck/memory/{projectId}/{workspaceId}/`. Human browsability comes from CLI/dashboard, not disk layout. `pan workspace get <ws>` (exists, `workspace.ts:92`) MUST print the memory-home path (WI-2 adds it if absent).
- **D-3: `--target-path` accepts any existing absolute directory**, not only registered project targets (matches Subspace). If the path is not under any `project_targets` row of the chosen project, the command prints an informational note suggesting `pan project add-target`, but does not fail.
- **D-4: dry-run is a flag, not a verb.** Subspace has `workspaces plan`; Overdeck gets `pan workspace new … --dry-run` (prints the resolved intent JSON, writes nothing). One less verb; same capability.
- **D-5: relocate is forbidden for `kind='issue'`.** Issue worktree paths are pipeline-owned. `pan workspace relocate` on an issue workspace errors with guidance. `main` relocate is allowed only with `--force` (the project's `projects.yaml` path remains the config source of truth and the command warns about divergence).
- **D-6 (supersedes PAN-1990 D-6): non-issue turns get same-project cross-workspace injection.** When `issueId === null`, the (previously skipped) second search arm becomes a same-project cross-workspace search excluding the current workspace, under the existing sibling byte budget. Issue turns keep the current sibling behavior unchanged.
- **D-7: SessionStart briefing reuses the prompt-time machinery.** Composition = current status + last N observations digest + pinned docs, built from `readCurrentStatus`/`readRecentObservations`/existing pin readers — no new retrieval pipeline. Dedup marker per session lives in the memory home (`rag-runs/injected-<sessionId>.json`). Budget: a new `SESSION_START_MEMORY_BUDGETS` constant beside `PROMPT_TIME_MEMORY_BUDGETS`; do not silently reuse prompt-time budgets.
- **D-8: history depth is caller-chosen.** `readArchivedStatuses` keeps its default of 3 for synthesis; the CLI passes `--history N` through (cap 50).
- **D-9: `pan memory read` is containment-checked.** Only paths inside the resolved workspace memory home may be read (realpath containment, symlink-safe — same posture as `src/lib/memory/pin-path.ts`). JSONL session files under `~/.claude` are NEVER readable through this command.
- **D-10: no per-workspace boards/threads/notes/transcripts.** Subspace hangs tasks/boards/threads/notes off workspaces; Overdeck already owns those domains elsewhere (xBRIEF, conversations, issue pipeline) and links via `workspace_id`. Explicit non-goal.
- **D-11: no model hardcoding.** Any new LLM call (none is planned; briefing is composed from existing artifacts) must resolve via provider policy. An unset provider fails loudly — never a code-literal fallback.
- **D-12: sidebar memory phase is served from the list DTO.** `GET /api/workspace-registry` gains `memoryPhase: string | null` per row, read server-side from `status.json` (null when absent or for issue-kind rows, which keep the pipeline badge). No per-row client fetches.
- **D-13: issue-kind rows are registry state, not user workspaces.** The boot seeding (`backfillIssueWorkspaces()` in `src/lib/workspaces/rebuild.ts`) enrolls every `workspaces/feature-*` worktree as a `kind='issue'` row. Those rows stay — they are the memory-home owners and the pipeline's linkage point — but they are an implementation detail of the pipeline, not something the operator "created." **User-facing workspace surfaces default to non-issue kinds.** The sidebar WORKSPACES rail and the Cmd-K `workspaces` scope list `main` + `scratch` (+ any explicitly favorited issue workspace); the remaining issue rows collapse into a "N pipeline worktrees" count row (same pattern as the existing archived-count row), expandable on demand. This is the direct fix for the observed defect: a fresh install showing dozens of `feature-pan-XXXX` "workspaces" the operator never made.

## Requirements

Functional:

- **FR-1** `pan workspace new <name> --target-path <dir>` creates a shared scratch workspace whose `path` is the given directory (validated: absolute, exists; `is_git_repository` detected via `.git` presence). Mutually exclusive with `--isolated`.
- **FR-2** `pan workspace new … --dry-run` prints the resolved intent as JSON (`{projectId, kind, name, path, branchName, parentBranch, parentBranchGuessed, isGitRepository, wouldCreateWorktree}`) and writes nothing (no DB row, no worktree, no memory home).
- **FR-3** `pan workspace relocate <ws> --path <dir>` repoints a `scratch` workspace's `path` (and `main` with `--force`), refreshes `is_git_repository`, re-writes the memory-home `metadata.json`, and touches `last_accessed_at`. Errors for `kind='issue'` and for archived workspaces.
- **FR-4** `pan memory search <query> --target [path]` searches across ALL workspaces (any project, any kind, non-archived by default) whose `path` resolves (realpath) to the given directory (default: cwd), merging results by rank like `--global` does.
- **FR-5** `pan memory status` accepts `--workspace <ref>` (id or name) as an alternative to the issue positional; both resolve to a workspace and read the same `status.json`.
- **FR-6** `pan memory status … --history N` prints the current status followed by up to N archived statuses, newest first (`--json` emits `{current, history: […]}`).
- **FR-7** `pan memory summary` accepts `--workspace <ref>` as an alternative to the issue positional.
- **FR-8** `pan memory timeline [--workspace <ref>] [--days N] [--limit M] [--json]` prints chronological observations (timestamp, actionStatus/summary, files) for the resolved workspace (default: cwd's workspace via `resolveWorkspaceForCwd`).
- **FR-9** `pan memory read <path> [--from N] [--lines M]` prints a file from the resolved workspace's memory home, containment-checked per D-9.
- **FR-10** On SessionStart, the memory hook response carries a rendered briefing (status headline/goal/phase/nextSteps + recent-observations digest + pinned-doc titles) injected into the session as additional context, at most once per session id (dedup marker per D-7). Disabled when observations are disabled; degrades to current behavior on any composition failure.
- **FR-11** For a turn whose `MemoryIdentity.issueId` is null, prompt-time injection includes a same-project cross-workspace search arm (excluding the current workspace) under the existing sibling budget (D-6). Issue-scoped behavior is byte-for-byte unchanged.
- **FR-12** The sidebar workspace rail shows a memory-phase badge for non-issue workspaces (from `memoryPhase` in the list DTO, D-12); issue rows keep the pipeline-phase badge. `WorkspaceView` shows phase + confidence with the existing memory surface.
- **FR-13** The sidebar WORKSPACES rail and the Cmd-K `workspaces` palette scope list only `main`, `scratch`, and favorited workspaces by default; non-favorited issue-kind rows collapse into an expandable "N pipeline worktrees" count row (D-13). The expanded state persists in localStorage alongside the existing grouping toggle. `GET /api/workspace-registry` keeps returning all kinds (the filter is presentation-side); the `?kind` query param already supports server-side filtering where callers want it.
- **FR-14** `pan admin db rebuild-workspaces` additionally archives (never deletes) issue-kind rows whose tracker issue is terminal (closed/merged, resolved through the canonical issue resolver — never a direct tracker/DB read), so stale pre-PAN-1990 worktrees stop appearing even in the expanded pipeline group. `--dry-run` reports what would be archived.

Non-functional:

- **NFR-1** All registry reads/writes go through the two doors; `scripts/guard-workspace-doors.sh` stays green.
- **NFR-2** No `execSync` anywhere server-reachable; async `execFile`/`spawn` only (relocate/target validation included).
- **NFR-3** Tests exercising retries/delays/debounce use `vi.useFakeTimers()` + `advanceTimersByTimeAsync` — never real timers.
- **NFR-4** Claude Code JSONL session files are read-only to every new code path (D-9 explicitly denies them).
- **NFR-5** No-loss: every existing CLI flag, verb, API field, and dashboard affordance keeps working; new behavior is additive. The PAN-1990 no-loss audit (`tests/unit/dashboard/no-loss-audit.test.ts`) stays green.
- **NFR-6** SessionStart briefing composition adds no synchronous LLM call and completes from local files only (D-7), so hook latency stays bounded.
