# PAN-2284 — Boot-reconciliation "Resume all" reports 0 resumed because the candidate list is full of phantom rows

**Issue:** [PAN-2284](https://github.com/eltmon/overdeck/issues/2284)
**Author:** agent:claude-opus-4-8 (planning, --auto)
**Date:** 2026-07-03

## Glossary

- **Boot reconciliation** — on dashboard boot, the Deacon (Overdeck's background patrol
  process) enumerates work agents that were left `stopped` and asks the operator, via the
  **BootReconciliationModal**, whether to resume them. Governed by
  `src/lib/cloister/boot-reconciliation.ts`.
- **Candidate** — an agent the modal presents as needing a resume/hold decision.
  Produced by `listBootReconciliationCandidates()` → `isBootReconciliationCandidate(agent)`.
- **Resume path** — `handleAgentStoppedEvent()` in
  `src/lib/cloister/deacon-auto-resume.ts`, the single function that actually decides
  whether a stopped agent gets resumed. It returns the resumed agent id, or `null` (with a
  logged reason) when the agent is not resumable.
- **`applyBootReconciliationDecision()`** — iterates the candidates and calls the resume
  path on each; the array it returns is the set of agents actually resumed.
- **Phantom candidate** — a candidate whose row still exists in the agents registry but is
  not actually resumable: its workspace directory was deleted, or its work is already
  merged / completed.
- **Skip breakdown** — a per-category count of why candidates were not resumed
  (e.g. `{ workspace_missing: 28, completed: 5, merged: 3 }`).

## Problem

On boot `boot-2026-07-03T10:36:30.127Z` the modal held **39 candidates**; the operator
clicked **Resume all** and the response reported **0 resumed**. From
`~/.overdeck/logs/deacon.log`, all 39 were skipped by the resume path: ~28 for
`workspace missing`, the rest for `already merged` / `completed marker exists and
review/test passed`. Same on the 08:10 and 08:11 boots (36 candidates each → 0 resumed).

**Root cause.** `isBootReconciliationCandidate()`
(`src/lib/cloister/boot-reconciliation.ts:47-52`) only gates on
`role === 'work' && status === 'stopped'` (plus paused/troubled/stoppedByUser). It does
**not** apply the resumability predicates the resume path later enforces:

- workspace directory exists on disk,
- the issue is not already merged,
- there is no processed completion marker with passing review/test.

So the candidate set is dominated by dead registry rows whose workspaces were deleted long
ago, plus finished-and-merged agents. Two harms:

1. **Operator-facing:** the modal presents dozens of agents as needing a decision, then
   "Resume all" reports 0 resumed with no explanation — it reads as a broken button.
2. **Signal:** the 1–2 genuinely resumable agents per boot are buried in phantom rows.

The deeper structural fault: the *candidate predicate* and the *resume predicate* are two
copies of the same intent that have drifted. Per the repo's single-source-of-truth tenet,
the fix is one shared predicate consumed by both — not a second copy of the checks.

## Proposal

1. **Extract a shared, synchronous skip classifier** — `bootReconciliationSkipReason(agent)`
   returning `'workspace_missing' | 'completed' | 'merged' | null` — covering the
   *terminal* sync skips that the resume path always honors (never flips back to resume).
2. **Feed it into `isBootReconciliationCandidate`** so the modal's candidate set contains
   only genuinely resumable agents. This alone fixes the operator-facing bug: with the
   phantom rows gone, boots that hold only phantoms short-circuit to "no candidates →
   resume_all" and no confusing modal appears.
3. **Delegate the resume path's corresponding checks to the same classifier** so there is
   one source of truth and the two paths cannot drift again — with **no behavioral change**
   to `handleAgentStoppedEvent`.
4. **Return a skip breakdown** from `POST /api/boot-reconciliation/decision` and surface it
   in `BootReconciliationModal`, so any remaining "0 resumed" (transient concurrency
   deferral, an agent that became non-resumable between boot and click) is self-explanatory.

### Why the classifier only covers three categories

The resume path (`handleAgentStoppedEvent`, `src/lib/cloister/deacon-auto-resume.ts:615-763`)
has many skip reasons, but only three are **terminal and synchronous** — always skip, no
async lookup, never overridden by pending review feedback:

- `workspace_missing` — `!state.workspace || !existsSync(state.workspace)` (line 641)
- `merged` — `review.mergeStatus === 'merged'` (710), `state.merged === true` (715), or
  merge-ready+passed (706)
- `completed` — `handedOffViaDone && reviewStatus==='passed' && testStatus==='passed'` (693)

The others are deliberately **left in the resume path**: `issue closed` and `tmux session
alive` are async; `backoff active`, `idle runtime`, and the `completed + blocked → resume`
override are transient or resume-flipping. Adding those to the boot-time candidate filter
would require making the sync boot enumeration async (NFR-1) for negligible benefit —
`workspace_missing` alone is ~28 of ~33 phantoms.

## Requirements

- **FR-1** The candidate list excludes any work agent whose workspace directory does not
  exist on disk.
- **FR-2** The candidate list excludes any work agent already merged (review
  `mergeStatus === 'merged'`, agent-state `merged === true`, or `readyForMerge` with review
  and test both `passed`).
- **FR-3** The candidate list excludes any work agent that handed off via `pan done` and
  whose review and test both `passed`.
- **FR-4** The workspace-missing / merged / completed skip predicates are defined exactly
  once (a shared classifier) and consumed by BOTH the candidate filter AND the resume path,
  with no behavioral change to the resume path's skip/resume decisions.
- **FR-5** `POST /api/boot-reconciliation/decision` returns a skip breakdown of the form
  `{ resumed: string[], skipped: { workspace_missing?: n, completed?: n, merged?: n,
  other?: n }, deferred: number }`.
- **FR-6** `BootReconciliationModal` surfaces the skip breakdown so a 0-resumed outcome
  explains itself (e.g. "No agents resumed — 3 already merged, 1 completed").
- **NFR-1** Boot-time candidate classification stays synchronous — no async gates added to
  candidate enumeration.
- **NFR-2** No new typecheck, lint, or test failures.

## Planning Q&A

Ran in `--auto` mode — no interactive questions. Inferred decisions recorded in
`plan.autoDecisions[]` and mirrored here:

- **Shared predicate over duplicated checks.** The single-source-of-truth tenet requires one
  classifier consumed by both paths (B1+B3), not a second copy of the checks in the
  candidate filter.
- **Classifier scope = three terminal sync categories** (workspace_missing, merged,
  completed). Async/transient/resume-flipping skips stay in the resume path (NFR-1).
- **Stale-row janitor is OUT of scope.** Deleting agents-registry rows whose workspace is
  gone (issue "part 3", related #1846 / reconciliation inventory epic #2075/#2077) is a
  distinct, higher-risk behavior owned by the agents write-door. The candidate filter already
  removes phantoms from the modal, which is the operator-facing bug. Deferred.
- **New dedicated module for the classifier** (`boot-reconciliation-predicates.ts`) to keep
  it cycle-safe and give both consumers one clean import home. If the work agent confirms no
  cycle, co-locating in `boot-reconciliation.ts` is acceptable.
- **`applyBootReconciliationDecision` return shape becomes an object** `{ resumed, skipped,
  deferred }`; the four return-consumers and the pan-871 test are updated to read `.resumed`.
