# PAN-2338 — Boot Reconciliation lists every historical stopped agent; "Resume all" is a silent no-op

**PRD:** [`.pan/drafts/pan-2338.md`](https://github.com/eltmon/overdeck/blob/main/.pan/drafts/pan-2338.md)
**Issue:** [PAN-2338](https://github.com/eltmon/overdeck/issues/2338)
**Mode:** `pan plan --auto` (no interactive Q&A; defaults recorded in `plan.autoDecisions[]`).

## Glossary

- **Boot reconciliation** — on dashboard boot, the Deacon offers work agents that were plausibly interrupted by the crash/restart as "resume candidates", holding them for a grace window before defaulting to `resume_all`.
- **Candidate** — an agent that `isBootReconciliationCandidate()` returns true for; only candidates are held and only candidates are resumed by "Resume all".
- **Terminal issue stage** — an issue that has finished the pipeline: `verifying_on_main` (awaiting close-out), `closed`, or `cancelled`. A work agent whose issue is terminal has no live work to resume.
- **Boot state** — the persisted `boot_reconciliation.*` settings (`bootId`, `graceDeadline`, `decision`, `perAgent`) in the overdeck settings store, read via `getBootReconciliationState()`.
- **Read door / write door** — the single canonical resolver (`listAllAgentsSync`) and mutator (`removeAgentSync` / AgentWriter) for the agents domain. No direct DB access outside these.

## Problem (verified against HEAD b0a12af7fc)

`isBootReconciliationCandidate` (`src/lib/cloister/boot-reconciliation.ts:47-52`) gates on role/status/paused/troubled/stoppedByUser only — no recency, no workspace-existence, no terminal-issue gate. `listBootReconciliationCandidates()` (`:58`) filters *all* rows from `listAllAgentsSync()`, so every historical `stopped` work agent (weeks old, workspace gone, issue merged) becomes a resume candidate. "Resume all" → `applyBootReconciliationDecision` (`src/lib/cloister/deacon-auto-resume.ts:892`) attempts each, the resume path declines terminal agents (`src/lib/agents/resume.ts` — "no resumable session id"), and the route returns `count: 0` with the modal (`src/dashboard/frontend/src/components/BootReconciliationModal.tsx:170`) printing a bare "No agents were resumed."

The `agents` table grows unbounded (497 rows / 468 stopped in the incident, 44 dead PAN-1791 swarm-slot rows), because terminal rows are never reaped.

## Verified facts

- `listAllAgentsSync()` rows carry `lastActivity: string | null`, `workspace: string | null`, `issueId`, `role`, `status`, `paused`, `troubled`, `stoppedByUser` (`src/lib/overdeck/agents.ts:962-1006`). Field is `lastActivity`, **not** `lastActivityAt`.
- Boot state (`getBootReconciliationState`, `src/lib/overdeck/control-settings.ts:437-459`) stores `bootId`, `graceDeadline`, `decision`, `perAgent` — **no `bootStartedAt`**. `stampBootReconciliation(bootId, graceDeadline)` is called once at `boot-reconciliation.ts:138`.
- `StartupConfig` (`src/lib/cloister/config.ts:99-107`) has `reconciliation_grace_secs` (default 120); no max-age field.
- The overdeck DB has an `issues` table with a `stage` column (written at `agents.ts:867`, `agent-state-sync.ts:224`). Terminal stages per `Stage` literals (`src/lib/overdeck/issues.ts:31-43`): `verifying_on_main`, `closed`, `cancelled`.
- `applyBootReconciliationDecision(deps)` returns `Promise<string[]>` (resumed ids). Callers: `deacon.ts:1666` wrapper, `dashboard/server/main.ts:623-625`, route `routes/boot-reconciliation.ts:122` (`count: resumed.length`), route `routes/misc/deacon.ts:32`, tests `__tests__/pan-871-auto-resume.test.ts:526,558`.
- GET `/api/boot-reconciliation` (`routes/boot-reconciliation.ts:59-91`) puts *every* stopped/paused/troubled/remote work agent into `set` — the blanket `agent.status === 'stopped'` clause (`:70`) is what surfaces old rows in the modal.
- `removeAgentSync(agentId)` (`agents.ts:834-841`) deletes the DB row **and** `~/.overdeck/agents/<id>/`. `pan admin db` is mounted at `src/cli/commands/admin/index.ts:38` via `registerDbCommands` (`src/cli/commands/db.ts:70`) — new subcommand is `pan admin db gc-agents`.
- Existing tests: `src/lib/cloister/__tests__/boot-reconciliation.test.ts` mocks `listAllAgentsSync`, `control-settings`, and `config`. Its "lists only … resumable candidates" test (`:128`) uses workspaces that are never created on disk, so the new workspace-exists gate will require updating that test.

## Design decisions

- **D1 — Single predicate, reads context from state/config (no signature change).** `isBootReconciliationCandidate(agent)` is called from three sites (boot-reconciliation, route, apply path). Rather than thread `bootStartedAt`/config through every call, the predicate reads `bootStartedAt` from boot state and `reconciliation_max_candidate_age_secs` from config internally. All non-boot call sites run *after* boot stamping, so state is valid there.
- **D2 — Stamp `bootStartedAt` before listing candidates.** `startBootReconciliation` computes `candidateIds` (`:116`) before `stampBootReconciliation` (`:138`); the recency gate needs `bootStartedAt` at listing time. Fix: stamp `bootStartedAt` up front (idempotent-preserved across re-entry) so the first listing sees the correct value. Recency window = `lastActivity >= bootStartedAt − maxAgeSecs`.
- **D3 — Recency source = `lastActivity`, fallback `stoppedAt` then `startedAt`; if none, exclude.** An agent with no timestamp cannot be proven recent, so it is not a candidate (fail-closed — the whole point of the fix).
- **D4 — Terminal detection via local `issues.stage` (sync).** Add `getIssueStageSync(issueId)` reading the overdeck `issues` table; terminal = `verifying_on_main | closed | cancelled`. Stays sync (predicate is sync) and within the read door (DB cache).
- **D5 — `applyBootReconciliationDecision` returns `{ resumed: string[]; outcomes: BootReconciliationOutcome[] }`.** `outcome ∈ resumed | skipped`; `reason ∈ no-resumable-session | deferred-concurrency | deferred-load`. FR-1 already filters terminal/stale/workspace-gone agents out of candidacy, so those reasons don't recur here; the dominant real skip is `no-resumable-session`.
- **D6 — Tighten GET `set` display, keep paused/troubled context.** Drop the blanket `status === 'stopped'` clause so old non-candidate stopped rows disappear from the modal; keep candidate / paused / troubled / remote rows (paused/troubled remain read-only context, a separate operator concern).
- **D7 — `gc-agents` reaps via `removeAgentSync`, `--dry-run` default-off.** Reap work-role rows whose issue stage is terminal (covers the 44 PAN-1791 slot rows). Tests must assert live/non-terminal agents are NOT reaped.
- **D8 — Skip codebase-context bootstrap.** `.pan/context/codebase/*.md` bootstrap is deferred; this is a bounded bug fix, not an architectural change. Recorded as an autoDecision.

## Requirements

- **FR-1** — Gate candidates to genuinely-interrupted, resumable work (recency window + live workspace + non-terminal issue).
- **FR-2** — "Resume all" reports per-agent resumed/skipped outcomes with reasons; never a bare "No agents resumed" when candidates were unresumable.
- **FR-3** — `pan admin db gc-agents` reaps terminal/orphaned work-agent rows + state dirs via the write door.
- **NFR-1** — All reads via `listAllAgentsSync` / resolver; all mutations via `removeAgentSync` (write door). No direct DB deletes.
- **NFR-2** — `npm run typecheck && npm run lint && npm test` green.

## NonGoals

- Not changing the grace-window timer or the `resume_all`-on-expiry default behavior.
- Not reaping paused/troubled rows (they are intentionally held).
- Not adding recency/terminal gates to `autoResumeStoppedWorkAgents` (the steady-state patrol) — scope is boot reconciliation only.
- Not touching `resume.ts` session-resolution logic.
- Not bootstrapping `.pan/context/codebase/*.md`.
