## Gaps and dispositions

Disposition legend: **pursue** (file child issue now), **defer** (revisit after named precondition),
**reject** (deliberate non-goal — record why).

### G1. Multi-agent task surface + A2A messaging — PURSUED
Filed as [PAN-2565](https://github.com/eltmon/overdeck/issues/2565) with its own PRD. The largest gap; everything else here is smaller.

### G2. Conversation-level checkpoints / restore / revert — pursue
Traycer: per-turn checkpoint manifests + restore/revert dialogs. Overdeck: git commits exist in
pipeline flows, but interactive conversations have no "rewind the files this turn touched".
Sketch: snapshot changed files per assistant turn (git stash-free — use a shadow ref or
`git worktree`-local commit on a checkpoint ref; NEVER `git stash` per repo rule), restore action
in the conversation timeline. Child issue should decide granularity (turn vs tool-call).

### G3. Live collaborative artifacts with comment threads — defer (precondition: PAN-658 ships)
Traycer: specs/tickets/stories/reviews as Yjs docs with comments/resolve/@mentions/assignment.
Overdeck: PRDs/vBRIEFs are git-committed files — durable, reviewable, agent-legible, but no
in-dashboard editing, comments, or co-editing. Deferring because: (a) the co-editing transport
should be the PAN-659-lineage followup riding PAN-658's `collab` channel, not a parallel stack;
(b) [PAN-277](https://github.com/eltmon/overdeck/issues/277) already holds the product thinking for collaborative refinement. When picked up,
scope comments-on-artifacts (dashboard-rendered, git-persisted) separately from live co-editing —
comments do not need CRDT.

### G4. Persistent roles (owner/editor/viewer), orgs/teams — gated (filed as [PAN-2608](https://github.com/eltmon/overdeck/issues/2608))
Traycer is cloud-accounts-first; Overdeck is local-first with session-scoped sharing (PAN-658
lobby model). Durable multi-user projects would change the product's trust model and require
always-on infrastructure. Gated behind the operator explicitly starting the shared-instance phase of the product vision — tracked as [PAN-2608](https://github.com/eltmon/overdeck/issues/2608) so the precondition is visible. Note the boundary precisely: PAN-658's signaling/TURN service is always-on but stateless, content-blind, and membership-only; G4 crosses into durable accounts + authorization state served while the data owner is offline — a different trust model.

### G5. Cross-device sync of conversations/tasks — PURSUED (filed as [PAN-2609](https://github.com/eltmon/overdeck/issues/2609))
Traycer: cloud CRDT rooms sync transcripts/artifacts across devices (PTY buffers stay host-local).
Overdeck: conversations are machine-local; `overdeck-state` syncs pipeline state via git.
Resolved 2026-07-12: pursued as [PAN-2609](https://github.com/eltmon/overdeck/issues/2609) with a full PRD (`drafts/pan-2609.md`). Chosen shape: user-owned private git remote (state-plane pattern, user-scoped), single-owner conversations with explicit CAS adoption — preserves the PAN-658 no-content-on-our-servers stance. E2E-relay and self-hosted room server were rejected for v1 (recorded in the PRD).

### G6. Message queueing UI — pursue (small)
Queue prompts typed mid-turn with reorder/edit-before-send. Overdeck currently pastes into the
PTY. Note: PAN-658 WI-8 builds a host-side FIFO submit queue for contributors — the child issue
should reuse that queue primitive for the local single-user case rather than building twice.

### G7. Workspace safety classification + bulk cleanup UI — pursue
Traycer classifies worktrees by evidence tier (Merged / At base / Unreferenced / Review / Orphaned
/ In use) with bulk delete. Overdeck has close-out teardown + the closed-issue reaper, but no
operator surface answering "which of these 30 workspaces are safe to delete?" — a recurring real
pain (disk pressure; see also the `.venv` disk-hog history). Child issue: classification service
over existing workspace/branch/merge state + a settings panel with bulk actions routed through
existing teardown primitives (never raw `rm -rf`).

### G8. Per-provider rate-limit usage views — defer (precondition: provider APIs expose it usefully)
Traycer surfaces rate-limit windows per provider. Overdeck tracks spend, not headroom. Value is
real (agents die on 429s today) but the data sources are uneven across providers. Fold into cost
surfaces when picked up.

### G9. Polish batch — pursue as one child issue, checklist-scoped
Small items, none deserving a standalone PRD: customizable keybindings; MCP server management UI
(user scope, auth status); unified in-dashboard notification bell (activity feed + needs-you
already exist — this is presentation); resource-monitor chip (memory governor exists server-side,
no frontend surface); terminal appearance settings (font/cursor); find-in-terminal; guided
first-run onboarding; prevent-sleep-while-agents-run (desktop).

## Decision rules used (and to reuse at triage)

1. **Local-first wins ties.** A feature requiring our cloud to hold user content is deferred or
   rejected unless it can be redesigned to keep content local/E2E (G4, G5).
2. **Reuse pipeline primitives.** If a gap overlaps something the pipeline already does
   (queueing → PAN-658 WI-8; cleanup → close-out/reaper), the child issue must extend, not fork (G6, G7).
3. **Comments ≠ CRDT.** Asynchronous annotation is cheap and git-persistable; live co-editing is
   expensive infrastructure. Never bundle them (G3).
4. **Parity is not the goal.** Each pursued item must serve Overdeck's pipeline-first,
   git-durable model on its own merits; "Traycer has it" is evidence of demand, not a requirement.
