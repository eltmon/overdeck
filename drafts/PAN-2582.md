# PAN-2582 — Lead/Crew terminology + slot assignments on the vBRIEF DAG

## Glossary

- **Item** — one node of a vBRIEF plan (`doc.plan.items[]`), carrying `dependsOn` edges and metadata (`files_scope`, `readiness`, `verify_commands`, `expected_outputs`).
- **Lead** *(new term)* — the durable whole-issue work agent `agent-<issue>` that owns beads bookkeeping, integrates parallel branches, and runs `pan done`. Replaces the operator-facing terms “whole-issue agent” (swarm) **and** “foreman” (tiered execution, `roles/work.md:74-96`) — one concept, one word.
- **Crew / crew member** *(new term)* — a parallel agent working exactly one item in its own worktree/branch. Replaces the operator-facing term “slot agent”. Internal identifiers (`agent-<issue>-slot-N`, `slotIndex`, `slotItemId`) are NOT renamed.
- **Slot index** — the internal parking-space number (`slotIndex`) a crew member occupies. Stays an internal term.
- **Slot assignment** — the durable `slotIndex → itemId (+agentId)` record read by `listDurableSlotAssignments` and stored on the per-issue record (`record.swarm.slotAssignments`, `src/lib/cloister/feedback-target.ts` self-heal path shows the shape).
- **Slot-eligible** — an item that may run on a crew member: `isSlotEligible()` at `src/lib/vbrief/swarm-readiness.ts:136` — `readiness === 'ready'`, non-empty high-confidence `files_scope`, ≥1 `verify_commands`, ≥1 `expected_outputs`.
- **Dispatch frontier** — dispatchable items (dependencies satisfied, not merged) ∩ slot-eligible ∩ no `files_scope` overlap with in-flight/selected items — computed in `dispatchNextWave()` (`src/lib/cloister/deacon-swarm.ts:884`, anchor `getDispatchableItems(doc, mergedItemIds)`).
- **DAG tab** — the vBRIEF viewer’s graph view (`src/dashboard/frontend/src/components/vbrief/`), currently rendering items + dependsOn edges with **zero** slot/runtime references (verified by grep 2026-07-11).

## Requirements

### Functional
- **FR-1 (Runtime overlay: in-flight)** — DAG nodes whose item has a live slot assignment render a badge `crew N · <model> · running` (liveness from the agents table row `slotIndex/slotItemId` + tmux).
- **FR-2 (Runtime overlay: delivered-by)** — completed items render which crew member delivered them (from reconciled/merged slot history in `slot-reconcile.ts`), or `lead` when no slot assignment ever existed for the item.
- **FR-3 (Trunk marking)** — items that are NOT slot-eligible render visually distinct, with the failing predicate named in a tooltip (e.g. “not crew-eligible: files_scope overlaps item X / readiness=needs-info / no verify_commands”). Source: `analyzeSwarmReadiness()` verdicts (`swarm-readiness.ts:73`, fields `slotEligible`, `overlapMatrix`).
- **FR-4 (Frontier tint)** — items in the current dispatch frontier get a distinct tint so “what the next wave would pick up” is visible. Reuse the same selection predicate as `dispatchNextWave` — extract it into a pure exported helper rather than duplicating (see WI-3).
- **FR-5 (Data endpoint)** — the plan API the viewer already calls (`GET /api/workspaces/:issueId/plan`) is extended with a `runtime` block: `{ assignments: [{itemId, slotIndex, agentId, model, live}], frontierItemIds: [], slotEligibility: {itemId: {eligible, reasons[]}} }`. No new endpoint.
- **FR-6 (Lead/Crew in UI copy)** — operator-facing strings change: CrewStage keeps “The crew” (`src/dashboard/frontend/src/components/Stage/cockpit/CrewStage.tsx:136`); agent labels rendered as `crew 1`, `crew 2` instead of `slot 1` where shown; the Lead’s row labels as `lead` (today it renders as bare “Work”).
- **FR-7 (Lead/Crew in CLI copy)** — `pan swarm` output strings say “crew member N” / “lead” instead of “slot N” / “whole-issue agent” (message text only, e.g. `[swarm] orphan slot 1 …` in `deacon-swarm.ts`; flags/ids unchanged).
- **FR-8 (Foreman unification)** — `roles/work.md:74-96` and `docs/TIERED-EXECUTION.md` replace “foreman” with “lead” (the tiered path becomes “the lead path”). `sync-sources/rules/` mentions of foreman get the same rename with a “formerly foreman” note for greppability.

### Non-functional
- **NFR-1 (No identifier churn)** — tmux session names, agent ids, state fields (`slotIndex`, `slotItemId`), branch names (`feature/<id>-slot-N`) are unchanged. Rename is copy/docs only.
- **NFR-2 (Zero new stores)** — the overlay reads existing sources (agents table, slot assignments, swarm-readiness verdicts). No new persistence.
- **NFR-3 (Style guide)** — badges follow the pan-style-guide (no decorative color; running ≠ green; tint = muted accent).

## Decisions made in this document (do not re-litigate)

1. **Lead/Crew wins** (operator, 2026-07-12). Not Trunk/Lanes. “The crew” copy already shipped in the cockpit — this PRD aligns everything else to it.
2. **Rename is copy-only** (NFR-1). Identifier renames are explicitly out of scope; if ever wanted, that is a separate migration issue.
3. **No new endpoint** — the runtime block rides the existing plan API (FR-5).
4. **Frontier logic is extracted, not duplicated** (WI-3); the dispatcher and the UI must never disagree about the frontier.
