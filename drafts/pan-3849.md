## 1. Glossary

- **Record.** The per-issue JSON file on the `overdeck-state` branch, `records/<issue-lowercase>.json`, on disk at `~/.overdeck/state/<projectKey>/records/`. Its `pipeline` block holds verdicts. Written only through `updateIssueRecord` (`src/lib/pan-dir/record-update.ts:498`).
- **Review-status row.** The SQLite row in `overdeck.db` table `review_status`, read by `getReviewStatusSync` (`src/lib/review-status.ts:842`) and written by `setReviewStatusSync`. It mirrors the record's `pipeline` block.
- **Anchor.** A git head snapshot string produced only by `snapshotWorkspaceHeadsPromise` (`src/lib/git-utils.ts:394`). Two fields hold anchors: `reviewedAtCommit` (what the review approved) and `lastVerifiedCommit` (what the verification gate passed).
- **Verdict write door.** `recordReviewVerdict` in `src/lib/cloister/review-verdict-writer.ts:129`, the only function allowed to write a terminal review verdict.
- **Verification gate.** The `quality_gates` commands from `projects.yaml`, run by `runVerificationForIssue` in `src/lib/cloister/verification-runner.ts`.
- **Convoy.** One review cycle: four reviewer sessions (security, correctness, performance, requirements) plus one synthesis parent, all Claude Code sessions in tmux. Spawned by `spawnReviewRoleForIssue` (`src/lib/cloister/review-agent.ts`).
- **Deacon.** The patrol process. `runPatrol` in `src/lib/cloister/deacon.ts:2626` runs every patrol step in sequence on a 60-second timer (`deacon.ts:221`).
- **Patrol.** One step inside `runPatrol`. Numbered #1 to #78 in the review's Appendix C.
- **Monitor mail.** The PAN-3015 delivery tier in `messageAgent` (`src/lib/agents/messaging.ts:525-546`): write a file into `~/.overdeck/agents/<id>/mail/`, return success. A `pan monitor` background task the model starts inside its own session prints the file to stdout.
- **Transcript.** The Claude Code JSONL session file under `~/.claude/projects/<encoded-workspace>/<sessionId>.jsonl`. It grows when a turn starts. `probeTranscriptSince` (`src/lib/transcript-landing.ts`) checks whether a delivered message appears in it after a byte offset.
- **Confirmed turn.** A delivery is confirmed when `probeTranscriptSince` reports `matchedUserRecord` or a new assistant turn after the delivery's byte offset. `deliverResumeMessageWithTranscriptConfirmation` (`src/lib/agents/delivery.ts:666`) already implements this for resume.
- **Placeholder.** A `state.json` and `agents` row written before the real spawn, with `model: "pending-work-spawn"` and `status: "starting"` (`src/dashboard/server/routes/agents/spawn-helpers.ts:60-70`).
- **Work activity.** `getAgentWorkActivityMs` (`src/lib/cloister/agent-idle.ts:45`): the newest of the hook-driven runtime mirror timestamp and the transcript heartbeat, deliberately excluding tmux window activity.
- **Stuck flag.** `review_status.stuck = 1` with a `stuckReason`. Patrols skip stuck issues (`deacon-review-status.ts:393, :512`; `deacon-merge.ts:790`; `deacon.ts:1416`). Cleared by `clearWorkspaceStuck` (`src/lib/overdeck/review-status-sync.ts`).
- **No-loss audit.** A test that enumerates what an old surface provided and proves the new surface provides it, run before the old surface is deleted (rule `additive-refactor-no-loss`).
- **Owes rework.** `issueOwesReworkSync` (`src/lib/work-agent-lifecycle.ts:30`): the pipeline has a failed verdict that the work agent must fix.

## 2. Requirements

Functional requirements (FR) and non-functional requirements (NFR). Work items cite the ones they satisfy in a `Traces:` line. Never renumber these; retire an id explicitly if it is dropped.

- **FR-1.** `messageAgent` returns `delivered: true` for a Claude Code agent only after the message is confirmed in the agent's transcript as a new turn. Otherwise it returns `delivered: false` with a `reason`.
- **FR-2.** The monitor-mail tier is not used by the automatic delivery cascade. `pan inbox` and the mail directory remain as a manual channel.
- **FR-3.** A failed UAT verdict counts as owing rework everywhere `issueOwesReworkSync` is consulted, and `pan tell` passes `owesRework` when the issue owes rework.
- **FR-4.** `pan tell` exits non-zero and prints the reason when delivery is not confirmed. It exits promptly after delivery.
- **FR-5.** "Idle" for every patrol means work activity older than a threshold. The runtime mirror's `idle` state alone never makes an agent idle.
- **FR-6.** Every nudge or feedback message from a patrol goes through `messageAgent`; no patrol calls `sendKeys` directly.
- **FR-7.** The verdict write door refuses a terminal review verdict that carries no evidence anchor. Verdict and anchor are written in one call.
- **FR-8.** A `passed` review is never reset by a patrol. Post-review drift marks the row stale; only `pan done` or `pan review request` clears staleness. A stale row is not `readyForMerge`.
- **FR-9.** The test role is never skipped because two anchors are equal.
- **FR-10.** The review verdict command never writes `verificationStatus`. A verification pass clears a `verification_stuck` flag.
- **FR-11.** Each verification run writes an immutable file named by run time and head; feedback references that file.
- **FR-12.** The verification gate fails a diff that adds `.skip`, `.only`, `xit`, `xdescribe`, or `xtest` in test files, or removes test cases. Vitest refuses `.only` in every gate run.
- **FR-13.** CI runs vitest on every push. No CI step skips tests because of an Overdeck commit status.
- **FR-14.** The lint ratchet names files whose per-file finding count increased.
- **FR-15.** Feature branches are cut from `origin/<target>` after a fetch. Scope drift diffs against a freshly fetched `origin/<target>`.
- **FR-16.** A re-review request is refused when the working tree is dirty or when HEAD equals the last approved anchor. No patrol dispatches a convoy with `force: true`.
- **FR-17.** The verification cycle counter is per issue and is reset only by `pan review reset`.
- **FR-18.** The record lock is per issue and is released before any git push.
- **FR-19.** Spawning an agent never takes the record lock.
- **FR-20.** `pan done` writes the completion marker, PR URL and `reviewRequestedAt` in one record write. No patrol re-creates a review request.
- **FR-21.** A reviewer's launcher writes `status: stopped` when the reviewer exits. No patrol infers reviewer exit from a missing tmux session.
- **FR-22.** Each patrol deleted in Phases 1 to 5 is deleted only after a test proves the state it repaired is unreachable and, for Phases 3 to 5, after a soak with a would-have-fired counter at zero.
- **FR-23.** One module answers "is this agent alive" and "is this agent idle"; every caller uses it.
- **FR-24.** Agent state is written only after the tmux session exists. There are no placeholders.
- **FR-25.** Session identity is never inferred from listing a transcript directory.
- **FR-26.** Each remaining patrol has a per-day firing budget; exceeding it opens a needs-you naming the patrol and suspends that patrol until the next day.
- **FR-27.** A report-only invariant checker reports, per issue and per agent, whether record, row and liveness agree, without writing any of them.
- **NFR-1.** No `execSync` in code reachable from the dashboard server (rule `no-execsync-server`).
- **NFR-2.** Tests that exercise delays, retries or timeouts use fake timers (rule `fake-timers-for-retry-tests`).
- **NFR-3.** Every phase ships alone: after it merges, the pipeline still carries an issue from `pan start` to merge with review, tests and UAT.
- **NFR-4.** Every deletion is preceded by a no-loss audit test that blocks until every old affordance is accounted for.
- **NFR-5.** Every phase updates the docs it touches in the same PR (`docs/AGENT-MESSAGE-DELIVERY.md`, `docs/MONITOR-TRANSPORT.md`, `docs/PIPELINE-GATES.md`, `docs/REVIEW-AGENT-ARCHITECTURE.md`, `docs/AGENT-STATE-PLANES.md`, `docs/MERGE-WORKFLOW.md`, `docs/DEFINITION-OF-DONE.md`, `CLAUDE.md` invariants, `roles/*.md`).

## 3. Decisions already made (do not re-open)

1. **Consolidate, do not rewrite.** The stages stay. Only the machinery between them changes. (Review, Section 7.)
2. **Delivery never throws for a gated agent; it returns `delivered: false` with a reason.** Callers that need escalation already branch on `delivered` (`uat-failure-feedback.ts:141-153`). Throwing would change their behaviour.
3. **The transcript is the delivery oracle for Claude Code agents.** Other harnesses keep their current confirmation and are out of scope for FR-1; they must set `confirmed: false` in the outcome so callers can tell.
4. **The confirmation primitive is `deliverResumeMessageWithTranscriptConfirmation`**, generalized. Do not write a second one.
5. **Monitor mail stays as a manual tool** (`pan inbox`, `pan monitor`), removed only from the automatic cascade and from role prompts.
6. **A stale review is a new field `reviewStaleSince`**, not a reset. Blocked reviews keep today's behaviour (new commits re-dispatch), minus `force: true`.
7. **The `overdeck/test` commit status keeps its name** because GitHub branch protection requires that context (`src/lib/github-app.ts:823-824`). CI simply stops reading it. Changing branch protection is an operator action, not part of this PRD.
8. **The record lock stays a directory lock (`mkdir`)**; only its key and its extent change.
9. **`stoppedByUser` semantics are unchanged.** An operator stop still gates automatic delivery. (Phase 4 does not replace it.)
10. **Patrol budgets are configuration**, with a default per patrol in code, not a hardcoded constant in each patrol.
11. **Reasoning effort for any agent this work spawns is `high`** (rule `effort-high-default`).

## 4. Rules that apply to every work item

- **No `execSync`, `execFileSync`, `spawnSync` in `src/dashboard/server/**` or anything it imports.** Use `execAsync`, `execFileAsync` or `spawn`. The repo eslint rule enforces this for the server tree.
- **Use `sendKeysAsync`, never `sendKeys`, in new code** (rule `prefer-async`). The one existing `sendKeys` call touched by this PRD is deleted.
- **Fake timers for any test with a delay or retry:** `vi.useFakeTimers()` in `beforeEach`, `vi.useRealTimers()` in `afterEach`, `vi.advanceTimersByTimeAsync(ms)` to move time.
- **Tests live in `tests/unit/<mirror of src path>/` or `src/<module>/__tests__/`.** Name new test files after the module under test. Existing files named below are the ones to extend.
- **Commit one work item at a time and push before `pan task done`** (rule `per-bead-durability`). Never `git stash`.
- **Do not touch `roles/*.md` prompts beyond the lines this PRD names.**
- **Quality gates before `pan done`:** `npm run typecheck`, `npm run lint`, `npm test`. `npm run typecheck` excludes test files; run `npx vitest run <file>` for each new test.
- **State branch:** never `git add`/`commit`/`push` on `~/.overdeck/state/*` by hand; the record writer owns it.

### W32. One liveness module

**Files.** New `src/lib/agents/liveness.ts`, callers: `src/lib/cloister/deacon-auto-resume.ts` (`queryConfirmedSession`, `handleAgentStoppedEvent:719`), `src/lib/parked/resolver.ts:461`, `src/lib/cloister/feedback-target.ts` (`isLiveSession`), `src/lib/work-agent-lifecycle.ts:102` (`sessionExistsSync`), `src/lib/agents/messaging.ts:596-612` (zombie detection), `src/lib/cloister/agent-idle.ts` (W5's idle helper moves here), new `tests/unit/lib/agents/liveness.test.ts`.

**Steps.**

1. `liveness.ts` exports:
   ```ts
   export type LivenessVerdict = { alive: true; paneAlive: true; runtimePid?: number } | { alive: false; reason: 'no-session' | 'pane-dead' | 'runtime-missing' };
   export async function isAlive(agentId: string): Promise<LivenessVerdict>;       // tmux session exists AND pane not dead AND (for supervisor-launched agents) the harness process is in the pane's subtree
   export function isAliveSync(agentId: string): LivenessVerdict;                   // same, sync tmux primitives, for the lifecycle classifier only
   export function isIdle(agentId: string, thresholdMs = 5 * 60_000, now = Date.now()): boolean; // W5's rule
   export function idleAgeMs(agentId: string, now = Date.now()): number | null;
   ```
   Implement `isAlive` from the existing pieces: `sessionExists` (`tmux.ts:1097`), `isPaneDead`, and `hasAgentRuntimeInSubtree` (`messaging.ts:597`).
2. Replace each caller's private definition with the module's function. The sweeper's `a.tmuxActive && (status === 'running' || 'starting')` becomes `isAliveSync(a.id).alive`. `feedback-target.ts` `isLiveSession` becomes `(await isAlive(id)).alive`, which fixes the remain-on-exit zombie case (F12 root cause (c)).
3. Add a lint guard `scripts/lint-liveness.sh` (pattern of `scripts/lint-pipeline-membership.sh`): fail if `sessionExists(` or `sessionExistsSync(` or `pane_dead` appears outside `src/lib/agents/liveness.ts`, `src/lib/tmux.ts`, and their tests. Wire it into `npm run lint`.

**Tests.** Session absent → `no-session`; session present, pane dead → `pane-dead`; session present, pane alive, no harness process → `runtime-missing`; all present → alive. `lint-liveness.sh --self-test` detects a seeded violation.

**Acceptance.** AC-W32: `bash scripts/lint-liveness.sh` passes on the tree.

**Traces:** FR-23.
