# PAN-3123 — Memory governor: swap and PSI as first-class pressure inputs

## Glossary

- **Governor** — the deacon memory governor in `src/lib/cloister/memory-governor.ts`. Its `assessMemoryPressure()` gates every autonomous agent admission (resume, dispatch, boot reconciliation) through a three-mode hysteresis state machine.
- **Governor mode** — one of `admitting` (normal), `holding` (admit nothing new, kill nothing), `shedding` (actively reclaim: stop merged/closed stacks, pause idle work agents). Module-level state in `memory-governor.ts:66`.
- **Reserves** — SOFT / HARD / RECOVERY GiB thresholds from `resources.governorSoftReserveGb` / `governorHardReserveGb` / `governorRecoveryReserveGb` in `~/.overdeck/config.yaml`. RECOVERY > SOFT always (normalized at `src/lib/config-yaml/merge.ts:665-668`).
- **`MemAvailable`** — kernel estimate of RAM allocatable without swapping, from `/proc/meminfo`. Currently the governor's *only* input.
- **`SwapFree` / `SwapTotal`** — swap headroom, already parsed into `ProcMemorySnapshot` (`src/dashboard/server/services/system-health-service.ts:70-71`) on both Linux (`:340-341`) and Darwin (`:370-378`). The governor ignores them today.
- **PSI** — Pressure Stall Information, `/proc/pressure/memory`. `some avg10` = % of the last 10s at least one task stalled on memory; `full avg10` = % of the last 10s *all* non-idle tasks stalled. Direct evidence the machine is *suffering*, as opposed to merely *full*. Already parsed elsewhere for host health by `parseMemoryPressure` (`src/lib/system-health/linux.ts:97-108`); not yet read by the governor path.
- **Runway** — this PRD's umbrella term for the two new governor inputs: swap elasticity (burst absorber) and PSI (active-suffering signal).

## Problem

Observed 2026-07-26 (RUN-71): 62.62 GB RAM, **MemAvailable 28.98 GB**, SwapTotal 8 GB, **SwapFree 0.00 GB**. The governor saw only MemAvailable, reported `admitting`, and kept admitting agents into a machine with zero swap runway — the state RUN-70 OOM-killed from. `assessMemoryPressure()` (`memory-governor.ts:116-127`) passes only `snapshot.memAvailable` into `nextGovernorMode()` (`:90-101`); there is no swap or PSI term anywhere in the module.

MemAvailable alone overstates headroom exactly when the machine is least able to absorb a burst: with SwapFree at 0, any anonymous-allocation spike must be satisfied from RAM immediately or the OOM killer fires.

The operator's follow-up measurement (issue comment, 10:38Z) sharpens the fix: PSI `full avg10` was 0.00 while swap sat at ~99% used — the machine was *latent-risk*, not *suffering*. So: **SwapFree should gate admission** (cheap, reversible), and **PSI should gate shedding** (expensive, disruptive) — a swap-only shedding rule would have shed healthy agents on a machine that was working fine.

## Decision record (auto mode — no interactive Q&A)

- **D1 — Swap gates admission, PSI gates shedding.** From the operator's issue comment, which explicitly refines the issue body's "near zero ⇒ shedding" suggestion. Low swap ⇒ at least `holding`; `shedding` from runway requires low swap *and* PSI `full avg10` at/above threshold.
- **D2 — Swapless machines are exempt.** When `SwapTotal === 0`, both runway gates are inert; RAM-only behavior is preserved bit-for-bit. A machine that never had swap elasticity must not suddenly hold forever — that would be a behavior change beyond this issue.
- **D3 — PSI unavailable ⇒ no PSI shedding.** Non-Linux platforms and kernels without PSI return `null`; the swap gate still applies (Darwin reports swap via sysctl).
- **D4 — Composition, not a second latch.** Runway feeds the existing single-mode hysteresis: the RAM verdict is computed by the unchanged `nextGovernorMode`, then composed with a swap verdict and the PSI shed upgrade. Re-admission requires *both* gates clear (RAM ≥ RECOVERY and SwapFree ≥ swap-recovery threshold). No independent swap latch.
- **D5 — `canAdmit` and `nextGovernorMode` keep their signatures and RAM-only semantics.** `canAdmit` is a pinned public shape (`memory-governor.ts:181-187` comment); `nextGovernorMode` is exported and covered by existing tests that must stay green unchanged. New behavior lands in a new exported composer.
- **D6 — Config, not literals.** Three new keys with defaults: `governor_swap_soft_free_percent: 25`, `governor_swap_recovery_free_percent: 50`, `governor_psi_full_shed_avg10: 1` (1.0 matches the existing PSI-full critical band, `LINUX_MEMORY_PRESSURE_DEFAULTS.fullCriticalAvg10` at `src/lib/system-health/linux.ts:21`). Recovery normalized to exceed soft, mirroring the existing reserve normalization.
- **D7 — Verdict carries runway observability.** `MemoryVerdict` gains optional `swapTotalBytes?`, `swapFreeBytes?`, `psiFullAvg10?` so operators can see *why* the governor is holding — the original defect was invisibility.

## Requirements

- **FR-1** — `ProcMemorySnapshot` carries `psiSomeAvg10: number | null` and `psiFullAvg10: number | null`; populated from `/proc/pressure/memory` on Linux, `null` on Darwin or when the file is unreadable.
- **FR-2** — With MemAvailable ≥ RECOVERY and SwapFree below the swap-soft percent of SwapTotal, `assessMemoryPressure()` returns a non-`admitting` verdict (`holding`). This is the issue's acceptance criterion.
- **FR-3** — Swap hysteresis: once held for low swap, the governor re-admits only when SwapFree reaches the swap-recovery percent of SwapTotal (and RAM ≥ RECOVERY).
- **FR-4** — PSI shed upgrade: SwapFree below swap-soft **and** PSI `full avg10` ≥ configured threshold ⇒ `shedding`, even with healthy MemAvailable.
- **FR-5** — SwapTotal = 0 ⇒ runway gates inert; verdict identical to today's RAM-only behavior.
- **FR-6** — PSI `null` ⇒ no PSI shedding; swap gate still applies.
- **FR-7** — All three thresholds are config-yaml keys with the D6 defaults; swap-recovery is normalized to exceed swap-soft.
- **FR-8** — `MemoryVerdict` exposes the runway fields (D7).
- **NFR-1** — `canAdmit(footprintBytes, availableBytes)` signature and semantics unchanged.
- **NFR-2** — Exported `nextGovernorMode(availableBytes, reserves, previousMode)` behaves exactly as before; its existing tests pass unmodified.
- **NFR-3** — `docs/RESOURCE-GOVERNOR.md` documents the new inputs, thresholds, and decision rules.

```ts
export function parseMemoryPsi(content: string): { someAvg10: number | null; fullAvg10: number | null } {
  const result: { someAvg10: number | null; fullAvg10: number | null } = { someAvg10: null, fullAvg10: null };
  for (const line of content.split('\n')) {
    const match = line.match(/^(some|full)\s+.*\bavg10=([^\s]+)/);
    if (!match) continue;
    const value = Number(match[2]);
    if (!Number.isFinite(value) || value < 0) continue;
    if (match[1] === 'some') result.someAvg10 = value;
    if (match[1] === 'full') result.fullAvg10 = value;
  }
  return result;
}
```

3. Add the composer (leave `nextGovernorMode` at :90-101 byte-identical):

```ts
/**
 * PAN-3123: compose the RAM-only hysteresis verdict with swap/PSI runway.
 * Low swap gates admission (holding — cheap, reversible); PSI full stalls on
 * top of low swap gate shedding (expensive). Swapless machines and
 * PSI-unavailable snapshots leave the RAM-only verdict untouched (FR-5/FR-6).
 * Re-admission requires BOTH gates clear: RAM >= RECOVERY (inside
 * nextGovernorMode) and SwapFree >= the swap-recovery percent.
 */
export function nextGovernorModeWithRunway(
  availableBytes: number,
  reserves: GovernorReserves,
  runway: GovernorRunway,
  runwayThresholds: GovernorRunwayThresholds,
  previousMode: GovernorMode,
): GovernorMode {
  const memMode = nextGovernorMode(availableBytes, reserves, previousMode);
  if (runway.swapTotalBytes <= 0) return memMode; // FR-5: no swap => no runway gate
  const swapSoftBytes = runway.swapTotalBytes * (runwayThresholds.swapSoftFreePercent / 100);
  const swapRecoveryBytes = runway.swapTotalBytes * (runwayThresholds.swapRecoveryFreePercent / 100);
  const swapLow = previousMode === 'admitting'
    ? runway.swapFreeBytes < swapSoftBytes
    : runway.swapFreeBytes < swapRecoveryBytes;
  const psiShed = swapLow
    && runway.psiFullAvg10 != null
    && runway.psiFullAvg10 >= runwayThresholds.psiFullShedAvg10;
  if (memMode === 'shedding' || psiShed) return 'shedding';
  if (swapLow) return 'holding';
  return memMode;
}
```
