# PAN-3753 — Merge-train flap: dead issue rendered ready-to-merge; merged UAT batch repeatedly invalidated

**Issue:** https://github.com/eltmon/overdeck/issues/3753
**Status:** draft PRD
**Author:** conversation conv-20260816-9367, 2026-08-16

## Glossary

- **Review-status store** — the per-issue `ReviewStatus` records (`loadReviewStatuses`,
  `src/lib/review-status.ts:79`; sync variant `src/lib/review-status-json.ts:21`) carrying
  `readyForMerge`, `mergeStatus`, `blockerReasons`.
- **Stale-blocker patrol** — `reconcileStaleMergeBlockers` in `src/lib/cloister/deacon-merge.ts`
  (~lines 435–470, cooldown `STALE_MERGE_BLOCKER_COOLDOWN_MS = 2 min`, line 412): for every
  non-merged status with a `merge_conflict`/`not_mergeable` blocker, re-runs the conflict gate
  and clears the blocker if the branch is mergeable, logging
  `Cleared stale merge blocker for <id> — branch is mergeable again; readyForMerge will recompute`.
- **UAT generation** — a batch record reconciled by `reconcileUatGenerations`
  (`src/lib/cloister/uat-reconciler.ts`); `isStale` (lines ~150–165) invalidates a LIVE
  generation when a member "left the ready queue" or its branch gained commits.
- **Pipeline membership** — the canonical per-issue classification resolver
  (docs/PIPELINE-MEMBERSHIP.md); it already classifies PAN-1641 as
  "open issue with an unmerged convention branch but no PR — needs a PR or disposition".
- **Flywheel merge-train surface** — the dashboard flywheel view that rendered PAN-1641 as a
  train with a clickable Merge.

## Problem (verified 2026-08-16)

PAN-1641: issue open, label `planned`, only PR #1679 **closed unmerged in June**, branch
`origin/feature/pan-1641` still exists, its agent paused. The dashboard log repeats, for hours:

```
[deacon] Cleared stale merge blocker for PAN-1641 — branch is mergeable again; readyForMerge will recompute
[review-status] Reported overdeck/review for PAN-1641 (488412ea)
[review-status-reconcile] re-emitting status for PAN-1641 (canonical differs from last event — healing lost status_changed)
[uat-reconciler] invalidating uat/pan-sable-0816: PAN-1641 left the ready queue
```

Chain: (1) the review-status store still holds a live-looking record for PAN-1641 — nothing
retired it when its PR closed; (2) the stale-blocker patrol sees a mergeable branch and clears
the blocker, flipping `readyForMerge` computation positive — without consulting pipeline
membership or PR-open state; (3) the flywheel painted it as a ready merge train, the operator
clicked Merge, and the action no-opped (no open PR to merge — verified: no merge commit, no new
PR); (4) each ready-queue flap re-invalidates UAT generation `uat/pan-sable-0816`, **a batch
that already merged to main as f33a226f0a** — a merged generation is being treated as live;
(5) review-status-reconcile "heals" a canonical/event divergence every cycle without converging,
and review-status stamps `overdeck/review` onto commit 488412ea of a branch with no open PR.

This is a single-source-of-truth violation (multiple writers deriving mergeability
independently) plus a latch-family bug (per operator memory: verify the fix by positive
evidence the loop stops).

## Requirements

- **FR-1** `readyForMerge` must be derivable only for an issue whose pipeline-membership
  classification permits merging (an open PR / in_flight state). The stale-blocker patrol must
  skip issues whose membership says "no PR / needs disposition" — one read door: consult the
  membership resolver, do not re-derive from branch mergeability alone.
- **FR-2** When a PR closes unmerged (or an issue leaves the pipeline), its review-status record
  must be retired (terminal state or removal) so no patrol resurrects it. Define the retirement
  trigger mechanically (event or reconciler), not doctrinally.
- **FR-3** A UAT generation that has been promoted/merged is terminal: `isStale`/invalidation
  must never run against it. Merged generations must be marked as such at promote time and
  filtered from reconciliation.
- **FR-4** The review-status-reconcile heal loop must converge: healing writes the canonical
  value once; if canonical and event state still differ on the next cycle, that is an error to
  surface (log at warn with both values), not an infinite re-emit.
- **FR-5** The flywheel merge-train surface renders a Merge action only when the merge execution
  path can actually act (open PR present). For "needs disposition" issues it must render the
  disposition problem instead.
- **NFR-1** Positive evidence: after the fix, one hour of dashboard.log contains zero
  occurrences of the four-line loop above for any issue in PAN-1641's state.

### 2. Review-status retirement (FR-2)

Files: `src/lib/review-status.ts` (+ writer), the merge/close-out lifecycle
(docs/MERGE-WORKFLOW.md names the post-merge and close paths), and wherever PR-closed
observations land (the external-event stream / webhook observations,

Add a retirement transition: on PR closed-unmerged or issue reopened-to-planning, set the record

gate (WI-1) reports "no PR", write the retirement instead of merely skipping, so the record
stops surfacing everywhere at once. State in the PR which trigger was wired.

### 3. Terminal UAT generations (FR-3)

File: `src/lib/cloister/uat-reconciler.ts`.

At promotion/merge success, stamp the generation record `promoted` (or equivalent terminal
marker); `reconcileUatGenerations` filters terminal generations before `isStale`. Backfill: on
boot, any generation whose merge commit is an ancestor of origin/main gets stamped terminal
(one-time reconciliation — this heals `uat/pan-sable-0816`).

### 4. Converging heal (FR-4)

`[review-status-reconcile] NOT CONVERGING for <id>: canonical=<…> event=<…>` at warn and stop
re-emitting until canonical changes. (Root-causing PAN-1641's specific divergence is expected to
fall out of WI-2 — a retired record stops being re-reported.)
