# PRD: PAN-2252 — Dashboard port has no identity check (residual gaps)

**Issue:** https://github.com/eltmon/overdeck/issues/2252
**Author:** planning agent (claude-fable-5), 2026-07-16, auto mode
**Status:** draft

## Glossary

- **Primary checkout** — the canonical Overdeck installation whose `dist/dashboard/server.js` is supposed to own the host dashboard port (default 3011). On dev machines this is the main clone (e.g. `/home/eltmon/Projects/overdeck`); on product machines it is the npm package root.
- **Linked git worktree** — a checkout created by `git worktree add`. Mechanically distinguishable from a primary clone: its `.git` is a plain **file** containing a `gitdir: <primary>/.git/worktrees/<name>` pointer, whereas a primary clone's `.git` is a **directory**. Workspace worktrees (`workspaces/feature-*`), handoff worktrees (`hoff-*`), and slot worktrees are all linked worktrees.
- **Peer mode** — a dashboard server started with `OVERDECK_DISABLE_DEACON=1` (e.g. inside workspace containers). Reported as `mode: "peer"` by `/api/health`.
- **Dashboard identity** — the `{ repoRoot, mode, buildCommit, builtAt }` object returned by `getDashboardIdentity()` (`src/dashboard/server/identity.ts:17`) and served on `GET /api/health`.
- **Host dashboard port** — `dashboard.api_port` from `~/.overdeck/config.toml` (default 3011), read by `readHostDashboardApiPort()` (`src/dashboard/server/identity.ts:34`).

## Background — what already landed

The issue's two proposed layers were implemented on main in commit `55ae3c878c` ("fix: guard dashboard identity on health checks", 2026-07-03), refined by `f6cbd6d143` and the PAN-2322 override hardening. Verified against the code at planning time:

1. **Identity in `/api/health`** — `getDashboardIdentity()` returns `repoRoot` (resolved server cwd), `mode` (`primary`/`peer`), and build info; served by the health route (`src/dashboard/server/server.ts:115-119`).
2. **CLI health gates verify identity** — `waitForDashboardHealthPromise` (`src/lib/platform-lifecycle.ts:203-240`) accepts `expectedIdentity` and fails with exactly `port held by non-primary server (cwd=…, mode=…)`. `pan restart` (both paths), `pan reload`, and detached `pan up` pass `expectedIdentity: { repoRoot: process.cwd(), mode: 'primary' }`.
3. **Server-side bind refusal** — `shouldRefuseHostDashboardPort` (`src/dashboard/server/identity.ts:47-69`), enforced in server config resolution (`src/dashboard/server/config.ts:~86-118`): refuses the host port when `mode === 'peer'`, when `repoRoot` matches `workspaces/feature-*`, or when the parent dir ends with `/workspaces`; container boots (`/.dockerenv` or `/workspaces/overdeck`) are exempt. The `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY` override is restricted to conversations / no-agent-identity processes (PAN-2322).
4. **`pan restart` cwd guard (partial)** — `refuseWorkspaceDashboardRestart` (`src/cli/commands/restart.ts:81-92`), called at `restart.ts:212` for dashboard/full scopes; matches only `workspaces/feature-*`.
5. **Supervisor watchdog** — `src/supervisor/watchdog.ts` already calls `assertDashboardIdentity(response)` on every poll; a squatter cannot pacify the watchdog.

Both acceptance bullets in the original issue body are therefore already satisfied on main. **This plan covers only the residual gaps**, which are the issue comment's additional requirement (2026-07-03: "`pan up`/`pan restart` must refuse to run when cwd is not the primary checkout — workspace worktree, handoff worktree, or any non-primary path") plus coverage holes found during discovery.

## Gaps this plan closes

- **G1 — `pan up` has no cwd guard.** The confirmed spawner of the 2026-07-03 recurrence was a work agent running `pan up` from `workspaces/feature-pan-1917`. Today `pan up` (`src/cli/index.ts:648+`) proceeds through host side effects (tmux global-env flush, Traefik config regeneration, host-tools install) and spawns the local dist regardless of cwd; only the server-side bind refusal saves the port.
- **G2 — guards and bind refusal miss non-`workspaces/` worktrees.** Incident spawners included `hoff-gh-quota` (a handoff worktree that is a sibling of the primary root, not under `workspaces/`). `isWorkspaceRepoRoot`'s regex and `shouldRefuseHostDashboardPort`'s parent-dir check both miss it: a hoff-worktree server in primary mode (deacon on) would bind 3011 today.
- **G3 — `pan reload` has no cwd guard.** `reloadCommand` (`src/cli/commands/reload.ts:182`) will happily build-and-restart from a workspace cwd; it even builds from `origin/main` inside whatever repoRoot it resolves.
- **G4 — foreground `pan up` health gate skips identity.** The non-detached path's `resolveDashboardReadyUrl` call (`src/cli/index.ts`, foreground else-branch, search for the second `resolveDashboardReadyUrl({`) omits `expectedIdentity`, unlike the detached path.
- **G5 — identity is anchored to invoker cwd, not the installation.** `expectedIdentity` uses `process.cwd()` and `spawnDashboardDetached` (`src/cli/commands/restart.ts:143`) inherits the CLI's cwd, so the server's `repoRoot` is wherever the operator happened to stand. One incident spawner ran from `/home/eltmon/Projects` (not a repo at all): the resulting server would report `repoRoot=/home/eltmon/Projects` and fail every later identity check even though it ran the correct dist. Deriving identity from the resolved bundle root makes it deterministic.

## Requirements

- **FR-1:** The dashboard server refuses to bind the host dashboard port when its `repoRoot` is a linked git worktree (`.git` is a file), regardless of directory naming or mode — in addition to the existing peer/workspace refusals. Container boots remain exempt.
- **FR-2:** `pan up` exits with code 2 and a refusal message naming the primary checkout when its cwd resolves to a non-primary checkout (workspace worktree or any linked worktree), before performing any host side effects (tmux env flush, Traefik regen, host-tools install, server spawn).
- **FR-3:** `pan restart`'s existing cwd refusal is broadened from `workspaces/feature-*` to any linked worktree, via a shared guard.
- **FR-4:** `pan reload` applies the same shared guard before acquiring the restart lock or building.
- **FR-5:** All dashboard boot health gates (restart ×2, reload, `pan up` detached **and foreground**) verify `expectedIdentity`, with `repoRoot` derived from the resolved server-bundle root (the same value the spawned server will report), not from `process.cwd()`.
- **FR-6:** `sync-sources/skills/pan-up/SKILL.md` and `sync-sources/skills/pan-restart/SKILL.md` describe the non-primary-cwd refusal (exit code 2) and the identity-verified health gate, including the "port held by non-primary server (cwd=…, mode=…)" failure shape.
- **NFR-1:** Workspace-container servers and in-container CLI invocations keep working: the container exemption (`/.dockerenv`, `/workspaces/overdeck`) is evaluated before any linked-worktree refusal (container worktree mounts have a `.git` file).
- **NFR-2:** Product installs are unaffected: a cwd that is not inside any git repo, or inside a normal clone (`.git` directory), is never refused.

## Design decisions (made here — do not re-derive)

- **"Non-primary checkout" = linked git worktree or `workspaces/feature-*` pattern.** Detection: `<repoRoot>/.git` exists and is a plain file. This covers every worktree-shaped spawner from the incidents (feature-*, hoff-*, slot worktrees) with zero configuration, and cannot false-positive on a product user's normal clone. A cwd outside any git repo is allowed (product installs run `pan up` from arbitrary directories); the deterministic-identity change (FR-5) covers that class instead.
- **Primary-root derivation for error messages:** parse the `.git` file's `gitdir: <abs>/.git/worktrees/<name>` pointer and report `<abs>`; for `workspaces/feature-*` fall back to `dirname(dirname(repoRoot))` (existing behavior).
- **Identity anchor = bundle root:** `resolve(resolveBundledServerPath(), '..', '..', '..')` (i.e. `dist/dashboard/server.js` → checkout/package root). `spawnDashboardDetached` sets `cwd` to this root so the server's `getDashboardIdentity().repoRoot` equals it; every `expectedIdentity` call site uses the same shared helper so the comparison cannot drift.
- **`pan dev` stays unguarded** (NonGoal): interactive dev mode, already protected by the dev-supervisor marker refusal in `pan up`, and not named by the issue.

## Work items

### W1 — Linked-worktree detection + server-side bind refusal (FR-1)

**Files:** `src/dashboard/server/identity.ts`, `tests/unit/dashboard/identity.test.ts`

1. Add `export function isLinkedWorktreeRoot(repoRoot: string): boolean` — true iff `<repoRoot>/.git` exists and `statSync(...).isFile()`.
2. Add `export function primaryRootFromLinkedWorktree(repoRoot: string): string | null` — read the `.git` file, match `/^gitdir:\s*(.+)$/m`, and when the target path contains `/.git/worktrees/`, return the portion before `/.git/`; else null.
3. In `shouldRefuseHostDashboardPort`, after the existing `runningInContainer` early-return and the `mode === 'peer'` / `isWorkspaceRepoRoot` checks, add: `if (isLinkedWorktreeRoot(repoRoot)) return true;` (ordering matters — see NFR-1).
4. Tests use `fs.mkdtempSync` fixtures (a dir with a `.git` file vs a `.git` directory). Follow the existing test style in `tests/unit/dashboard/identity.test.ts`.

### W2 — Shared non-primary cwd guard for the CLI (FR-3 groundwork)

**Files:** `src/cli/commands/restart.ts`, `src/cli/commands/__tests__/dashboard-cwd-guard.test.ts` (new)

1. Generalize `refuseWorkspaceDashboardRestart` into `export function refuseNonPrimaryDashboardCwd(cwd: string, verb: string): boolean`:
   - `existsSync('/.dockerenv')` → return false (container exemption, NFR-1).
   - `resolveGitRepoRoot(cwd)` null → return false (NFR-2).
   - Refuse when `isWorkspaceRepoRoot(repoRoot) || isLinkedWorktreeRoot(repoRoot)` (both imported from `../../dashboard/server/identity.js`, matching the existing import).
   - Message: `Refusing to <verb> the host dashboard from non-primary checkout <repoRoot>. Run this command from the primary checkout at <primary>.` where `<primary>` = `primaryRootFromLinkedWorktree(repoRoot) ?? dirname(dirname(repoRoot))`; omit the second sentence when underivable. Set `process.exitCode = 2`, return true.
2. Update the `restart.ts:212` call site to the new name/signature (verb `'restart'`).
