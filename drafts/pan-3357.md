# PAN-3357 — Transcript retention: retain forever by default, one deletion door for agent state dirs

**Issue:** https://github.com/eltmon/overdeck/issues/3357
**Status:** draft
**Author:** conversation (Claude Fable 5), 2026-07-31

## Glossary

Define these before reading further; every term is used exactly as defined.

- **Agent dir** — a directory under `~/.overdeck/agents/` (code constant `AGENTS_DIR` from `src/lib/paths.ts:27`). One per spawned agent or conversation, named by its tmux session (`agent-pan-1234`, `agent-pan-1234-review-security`, `planning-pan-1234`, `strike-pan-1234`, `conv-20260714-3489`).
- **conv-\* dir** — an agent dir whose name starts with `conv-` (predicate: `isConversationDirectory()` in `src/lib/agent-directory-cleanup.ts:98`). Belongs to a dashboard conversation.
- **Transcript artifact** — any file matching `**/*.jsonl` inside an agent dir. This includes codex rollouts (`codex-home/sessions/YYYY/MM/DD/rollout-*.jsonl`), ohmypi session logs (`sessions/*.jsonl` for conversations, per-run `*.jsonl` in the dir root for work/review agents — PAN-1908), ACP transcripts (`acp-session.jsonl`), and small runtime logs (`activity.jsonl`, `appserver-events.jsonl`). Decision (see Decisions): ALL `**/*.jsonl` files are treated as transcript artifacts; do not attempt to distinguish "real" transcripts from runtime jsonl.
- **Transcript-bearing harness** — a harness whose transcript lives inside the agent dir: `codex`, `ohmypi`/`pi`, `acp`. NOT `claude-code` (transcripts in `~/.claude/projects/`) and NOT `kimi-code` (transcripts in `~/.kimi-code/sessions/`).
- **Runtime residue** — everything in an agent dir that is not a transcript artifact: `state.json`, `pty-token`, `sessions.json`, `session.id`, `codex-thread-id`, `git-guard/`, launcher scripts, sockets, markers.
- **Deletion door** — the single function all code must call to remove or clean an agent dir. Introduced by this PRD (`removeAgentStateDir()` in a new module `src/lib/agents/state-dir-removal.ts`).
- **Retention purge** — `cleanupStaleAgentState()` in `src/lib/cloister/deacon.ts:828`, the deacon patrol that deletes agent dirs with no live tmux session after a retention window (`retention.agent_state_days`, default 7; `retention.reviewer_state_days`, default 1 for `review-*` names — see `src/lib/cloister/config.ts:305-312,493-494`).
- **Orphan sweep** — `findOrphanedAgentDirs()` / its deletion callers in `src/lib/agent-directory-cleanup.ts` (rm sites at lines 228 and 429). Already skips conv-\* dirs (line 163).

## Background — the incident this hardens against

The deacon retention purge deleted every agent dir older than 7 days with no live tmux session, including conv-\* dirs, which are the only home of codex/ohmypi conversation transcripts. 258 conv-\* dirs were purged between 2026-07-12 and 2026-07-31 (evidence: `Purged stale agent state: conv-*` lines in `~/.overdeck/logs/deacon.log`), surfacing as "Transcript missing" in the dashboard. The 2026-07-05 incident fix (commit `fe0fc57715`) had guarded only the orphan sweep, not the retention purge — two deletion paths, one guard.

**Already landed (do not re-implement):**
- Commit `7952eb6a67` adds `if (isConversationDirectory(dir.name)) continue;` at `src/lib/cloister/deacon.ts:858`, before any retention math, with a red/green regression test (`cleanupStaleAgentState conv-* preservation` describe block in `src/lib/cloister/__tests__/deacon-stash-janitor.test.ts`).
- All 216 purged dirs were restored from restic B2 snapshots; 173 pre-rebrand dirs were copied from `~/.panopticon/agents/` (this machine only).

**The remaining gap this PRD closes:** work/review/planning agents on transcript-bearing harnesses keep their transcripts inside their agent dir too, and those dirs are still deleted by four other paths (retention purge at 7 days / 1 day, pre-fresh-spawn wipes, close-out/deep-wipe teardown, orphan sweep). The operator's stated policy is: **transcripts are retained forever unless retention is explicitly configured.** There is no such configuration today, and deletions are scattered across five call sites with no shared invariant.

## Requirements

Functional:

- **FR-1** — conv-\* agent dirs are never deleted by any automatic cleanup path (retention purge, orphan sweep, reaper patrols). Landed in `7952eb6a67` + `fe0fc57715`; this PRD adds the guard-by-construction (FR-3) so future paths cannot regress it.
- **FR-2** — Transcript artifacts (`**/*.jsonl` inside any agent dir) are never deleted by default, by any code path, including explicit lifecycle wipes (pre-fresh-spawn wipe, close-out teardown, deep-wipe). Deleting an agent dir means deleting its runtime residue; transcript artifacts and their parent directories stay on disk.
- **FR-3** — Exactly one deletion door performs agent-dir removal/cleanup. Every existing deletion site is routed through it. A CI guard script fails the build on any new direct `rm`/`rmSync` of a path under `AGENTS_DIR` outside the door (same pattern as `scripts/guard-workspace-doors.sh`).
- **FR-4** — New optional config `retention.transcript_days` (cloister config). Unset (the default) = retain forever. When set to N, a dedicated deacon sweep may delete transcript artifacts older than N days from agent dirs whose agent/conversation has ended. No hardcoded fallback: unset means the sweep does not run at all.
- **FR-5** — One-time idempotent backfill command `pan admin migrate-legacy-agent-dirs` that copies (never moves, never overwrites) `conv-*` dirs from `~/.panopticon/agents/` into `~/.overdeck/agents/`. No-ops when the legacy dir is absent. (Already done by hand on the primary machine; the command exists for other machines.)
- **FR-6** — Stale documentation is corrected: `runParallelReview` / "Phase 6" references in `src/lib/cloister/config.ts:305-312` and `src/lib/cloister/deacon.ts:836-840` describe machinery deleted in R6 (`src/lib/cloister/review-agent.ts:6`); rewrite them to describe the actual current owners.

Non-functional:

- **NFR-1** — The deletion door and sweep are async-only (`fs/promises`); no `execSync`, no sync fs walks on the server/deacon path (PAN-70).
- **NFR-2** — All new tests use temp dirs (`mkdtempSync`) and, for anything time-based, `vi.useFakeTimers()` — never real waits (repo fake-timers rule).
- **NFR-3** — No new files exceed the file-size ratchet; the door lives in its own new module, NOT added to `src/lib/cloister/deacon.ts` (already allowlisted god file at 3546 lines) or `src/lib/agents/agent-state.ts`.

## Decisions (made here — do not re-litigate downstream)

1. **Preserve in place, do not archive-move.** The door deletes everything except `**/*.jsonl` (and the directories needed to hold them), leaving a pruned skeleton. Rationale: every transcript resolver (`resolveCodexRolloutPath` at `src/dashboard/server/routes/jsonl-resolver.ts:330`, `resolveAcpTranscriptPath` at `:350`, `resolvePiSessionPath` at `:395`) reads from the agent dir by agent id; in-place preservation means zero resolver changes. An archive-move design would require touching every resolver and the conversation-reads fallbacks — rejected.
2. **`**/*.jsonl` is the preservation predicate.** Simple, harness-agnostic, future-proof. Runtime jsonl (`activity.jsonl`, `appserver-events.jsonl`) rides along; it is small and historically useful. Do not build a per-harness allowlist.
3. **Wipe-before-fresh-spawn stays correct.** `wipeAgentStateDirs()` callers (`src/lib/cloister/review-agent.ts:708`, `src/cli/commands/start-fresh-session.ts:92`, `src/dashboard/server/routes/agents/lifecycle-restart.ts:532`) wipe so a new session does not inherit a stale saved session id. Session identity lives in runtime residue (`sessions.json`, `session.id`, `codex-thread-id`), which the door still deletes — preserving rollout jsonl does not reintroduce the stale-session hazard. Known acceptable side effect: `resolveCodexRolloutPath`'s newest-rollout fallback may briefly resolve the previous session's rollout between fresh spawn and the new session's first write (`codex-thread-id` is gone, so the fallback fires). This window already exists today for other reasons (PAN-1690); do not attempt to fix it here.
4. **Deep-wipe also preserves transcripts.** Deep-wipe remains the destructive teardown for workspaces/branches/state, but transcript artifacts under `AGENTS_DIR` survive it. A future `--purge-transcripts` escape hatch is explicitly out of scope.
5. **conv-\* dirs are skipped entirely by the retention purge** (not routed through the door with preservation) — landed behavior, keep it: a conversation dir's runtime residue is tiny and its `pty-token`/`sessions.json` are needed for resume.
6. **`retention.transcript_days` applies only to ended agents/conversations** (no live tmux session, conversation status `ended`/archived). It deletes transcript files older than N days, then removes empty parent dirs. Unset = the sweep is not registered in the patrol at all.

## Intersecting repo rules (restated for the executor)

- **No `execSync`** anywhere reachable from server/deacon code; all new fs work uses `fs/promises` (PAN-70).
- **Fake timers** for any time-dependent test; never real waits; never `maxForks: 1` to hide OOM.
- **No hardcoded fallback**: `transcript_days` unset must mean "sweep not registered", never a silent default number.
- **File-size ratchet**: working-tree files may not exceed their `origin/main` line count without an issue-referenced entry in `scripts/file-size-allowlist.txt`. `deacon.ts` is allowlisted at 3546 (`# PAN-3357`); if WI-2 grows it, bump that entry with this issue ref. New logic goes in new modules.
- **Two-door state rule**: conversation status in WI-4 is read via the conversations resolver, not raw DB access.
- **Commit style**: commitlint scopes are `[cloister, dashboard, workspace, cli, review, beads, db, specialists, terminal, infra, deps]`.
- **Stash discipline / worktree discipline**: never `git stash`; verify `git branch --show-current` is `feature/pan-3357` before the first edit.
