# PAN-2611 — pan close: `teardown:sync-beads` always fails post-Dolt-cutover

**Issue:** https://github.com/eltmon/overdeck/issues/2611
**Planning session:** 2026-07-13 (auto mode, agent:claude-fable-5)
**Status:** draft

## Glossary

- **Canonical beads home** — the single physical local Dolt store for a project's beads. For a migrated project this is `${OVERDECK_HOME}/state/<project>/.beads/` (the state worktree); for an unmigrated project it is `<projectRoot>/.beads/`. Resolved by `resolveCanonicalBeadsHome()` in `src/lib/beads/home.ts:8`.
- **Redirect file** — `.beads/redirect`, a one-line file whose contents are a path (relative to the worktree root, or absolute) telling `bd` where the real beads store lives. `bd` follows **exactly one hop**: if the redirect target directory itself contains a `redirect` file, bd prints `Warning: redirect chains not allowed, ignoring redirect in <dir>` and uses that directory directly.
- **Recovery export / snapshot** — the derived `issues.jsonl` + `export-state.json` pair written next to the canonical store by `exportBeadsJsonl()` (`src/lib/beads/export.ts:48`). It is the only production writer of that snapshot; `runMutationBatch()` (`src/lib/beads/writer.ts:110`) refreshes it after every mutation batch.
- **Close-out ceremony** — `closeOut()` in `src/lib/lifecycle/workflows.ts:159`: verify merge → archive artifacts → complete vBRIEF → `teardownWorkspace()` → close tracker issue → clear review status. A blocking failure in teardown appends `close-out:abort` and stops before the tracker close (`workflows.ts:200-203`).
- **`teardown:sync-beads`** — teardown step 6 (`teardown-workspace.ts:789-794`): before deleting the worktree it calls `exportBeadsJsonl(workspacePath)` to validate/refresh the recovery snapshot (`syncWorkspaceBeadsImpl`, `teardown-workspace.ts:261-279`).

## Root cause (verified live 2026-07-13; corrects the issue body's analysis)

The issue body attributes the failure to `archive-planning:archive-artifacts` "archiving the `.beads/` redirect away" before sync-beads runs. **That is not the mechanism.** The archive step only *copies* `.beads/` (`cp(beadsDir, join(archiveDir, '.beads'), { recursive: true })`, `src/lib/lifecycle/archive-planning.ts:275-279`); the workspace `.beads/` is intact when sync-beads runs.

The actual mechanism is a **redirect chain** created by the Dolt cutover ([PAN-2564](https://github.com/eltmon/overdeck/issues/2564)):

1. Workspace creation (`createWorktree` in `src/lib/workspace-manager/worktree-ops.ts:111-130`) writes the worktree redirect pointing at the **project root**: `.beads/redirect` = `../../.beads`.
2. Post-cutover, the project root `.beads/` is itself a redirect to the state worktree (`/home/eltmon/Projects/overdeck/.beads/redirect` → `/home/eltmon/.overdeck/state/panopticon-cli/.beads`) and its local Dolt store is retired (`embeddeddolt.retired-cutover-20260712`).
3. `exportBeadsJsonl(workspacePath)` runs `bd vc status` with `cwd = workspacePath` (`export.ts:58`). bd follows hop 1 to the project root, refuses hop 2 (`Warning: redirect chains not allowed`), and operates on the project root's **retired** store. `vc status` there prints `Branch: main` but **no `Commit:` line**, so `doltHead()` returns null and the export throws `Beads export refused because bd vc status did not report a Dolt commit.` (`export.ts:60`).
4. `teardown:sync-beads` fails; teardown continues (steps do not abort mid-sequence), so `removeWorktree` still deletes the workspace; then `hasBlockingFailure` aborts the ceremony (`close-out:abort`) before the tracker close. **A second run succeeds** because the worktree is gone and the whole workspace branch of teardown skips.

Live verification (2026-07-13):

- `bd vc status` in the workspace → `Warning: redirect chains not allowed, ignoring redirect in /home/eltmon/Projects/overdeck/.beads` + no `Commit:` line.
- `bd vc status` in `/home/eltmon/.overdeck/state/panopticon-cli/` → `Commit: c7e4uovo`.
- `bd list` in the workspace silently returns **stale beads from the retired project-root store** — the chain break corrupts reads, not just close-out.

## No-loss audit of the old step

What did the workspace-side export ever preserve? `exportBeadsJsonl` reads from the **shared** store (all worktrees redirect to one store — the workspace holds no local bead data, only the redirect file) and writes the recovery snapshot next to that store. Post-cutover the snapshot is already refreshed at the canonical home by `runMutationBatch` after every mutation (`writer.ts:110`). Deleting a worktree therefore destroys no bead state. Keeping the step as a close-time validation of the canonical snapshot (export/list record-count cross-check, `export.ts:71-76`) preserves everything the old step did, provided it runs where bd can see the Dolt commit.

## Decision

**Re-route `teardown:sync-beads` to the canonical beads home, and stop minting redirect chains at worktree creation.** Do not reorder the ceremony (the archive step is not the cause) and do not retire the step (its record-count validation is the no-loss guarantee).

Decision rule for the sync step: *if `resolveCanonicalBeadsHome(workspacePath)` returns a path, run `exportBeadsJsonl(dirname(canonicalHome), { beadsDir: canonicalHome })`; if it returns null, keep the existing `exportBeadsJsonl(workspacePath)` call unchanged.*

Decision rule for the redirect writer: *if `resolveCanonicalBeadsHome(targetPath)` returns a path and that directory exists, write the absolute canonical path as the redirect content (one hop, mirroring `src/lib/vbrief/beads.ts:437-443`); otherwise keep the existing relative `../../.beads` behavior.*

## Requirements

- **FR-1:** On a migrated project, the first `pan close <id> --force` completes the full ceremony: `teardown:sync-beads` exports from the canonical beads home and succeeds without a manual re-run.
- **FR-2 (no-loss):** The close-time export still performs the record-count cross-check against `bd list --all` and still refreshes `issues.jsonl` + `export-state.json` at the canonical home.
- **FR-3:** `createWorktree` writes a **one-hop** redirect: new worktrees' `.beads/redirect` contains the absolute canonical beads home path when it is resolvable.
- **FR-4:** When no canonical home resolves (project not registered / resolution fails), both surfaces preserve today's behavior exactly (workspace-cwd export; relative `../../.beads` redirect).
- **NFR-1:** No `execSync` or other event-loop-blocking primitives introduced in server-reachable code (both touched paths are reachable from the dashboard server).
- **NFR-2:** No new circular ESM imports (`worktree-ops.ts` → `beads/home.ts` must not cycle; `beads/home.ts` imports only `projects.js`, `state-read-home.js`, `dolt-layout.js`).

**File:** `src/lib/lifecycle/teardown-workspace.ts:261-279` (function `syncWorkspaceBeadsImpl`). `dirname` is already imported from `path` (line 3); add `import { resolveCanonicalBeadsHome } from '../beads/home.js';`.

Before:

```ts
  try {
    const result = await exportBeadsJsonl(workspacePath);
    return stepOk(step, [`Validated ${result.state.recordCount} canonical beads records for ${issueLower}`]);
  } catch (err) {
    return stepFailed(step, `Failed to sync workspace beads: ${(err as Error).message}`);
  }
```

After:

```ts
  // Post-Dolt-cutover the canonical beads store lives outside the workspace
  // (the state worktree for migrated projects). bd refuses the workspace's
  // chained redirect (workspace .beads -> project root .beads -> state
  // worktree), so export from the canonical home directly (PAN-2611).
  const canonicalHome = resolveCanonicalBeadsHome(workspacePath);
  try {
    const result = canonicalHome
      ? await exportBeadsJsonl(dirname(canonicalHome), { beadsDir: canonicalHome })
      : await exportBeadsJsonl(workspacePath);
    return stepOk(step, [`Validated ${result.state.recordCount} canonical beads records for ${issueLower}`]);
  } catch (err) {
    return stepFailed(step, `Failed to sync workspace beads: ${(err as Error).message}`);
  }
```

Keep the existing `existsSync(workspaceBeadsDir)` skip guard unchanged. Note `exportBeadsJsonl`'s first argument is the **cwd for the `bd` child process**; `options.beadsDir` pins the snapshot target directory explicitly so no path inference runs against the state worktree.

### WI-2 — Write one-hop redirects at worktree creation (traces FR-3, FR-4)

**File:** `src/lib/workspace-manager/worktree-ops.ts:111-130` (inside `createWorktree`). Add `import { resolveCanonicalBeadsHome } from '../beads/home.js';`.

Before (abridged):

```ts
    const sourceBeadsDir = join(repoPath, '.beads');
    if (existsSync(sourceBeadsDir)) {
      ...
          const relPath = relative(targetPath, sourceBeadsDir);
          writeFileSync(redirectPath, relPath, 'utf-8');
      ...

```

After:

```ts
    // Point the worktree's .beads/ directly at the canonical beads home
    // (state worktree for migrated projects, project root otherwise). The
    // project root may itself be a redirect post-cutover; bd refuses redirect
    // chains and silently falls back to the stale store (PAN-2611).
    const canonicalHome = resolveCanonicalBeadsHome(targetPath);
    const sourceBeadsDir = canonicalHome ?? join(repoPath, '.beads');
    if (existsSync(sourceBeadsDir)) {
      const worktreeBeadsDir = join(targetPath, '.beads');
      const redirectPath = join(worktreeBeadsDir, 'redirect');
      if (!existsSync(redirectPath)) {
        try {
          mkdirSync(worktreeBeadsDir, { recursive: true });
          // Absolute canonical path when resolvable (one hop, mirrors
          // src/lib/vbrief/beads.ts); relative project-root fallback otherwise.
          writeFileSync(redirectPath, canonicalHome ?? relative(targetPath, sourceBeadsDir), 'utf-8');
        } catch {
          // Non-fatal — if redirect creation fails, bd falls back to its usual bootstrap path.
        }
      }
    }
```

**Proven by:** WI-4 tests.
