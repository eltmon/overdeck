## Glossary

- **Policy strip** — the per-issue row of policy controls rendered in issue headers. Component: `src/dashboard/frontend/src/components/IssuePolicyStrip.tsx`.
- **Override** — a per-issue value explicitly set by the operator, stored server-side; `null` means "use the resolved default". The API returns both `override` and `resolved` objects per domain.
- **Resolved default** — the value that actually applies when no override is set (from global/project config).
- **Effective value** — `override ?? resolved` for a given knob.
- **Chip** — a small badge in the collapsed strip showing one active override (e.g. `work · GPT-5.5`).
- **Panel** — the popover opened by the Policies button containing all five controls.
- **Segmented control** — a row of mutually exclusive buttons (like tabs) replacing a `<select>` for small enums.
- **needsRestart** — the existing derived flag: a work-model override differs from the model the running agent was recorded with, so the override only applies on next spawn.

## Requirements

### Functional

- **FR-1** Collapsed strip renders exactly one **Policies** button (sliders icon + "Policies" label + override-count badge shown only when count > 0) plus one chip per active override. With zero overrides, nothing but the quiet button renders — no "default (…)" captions anywhere.
- **FR-2** Clicking the button (or any chip) toggles a popover panel; the panel closes on outside click and Escape. Only one instance's panel may be open at a time (component-local state is sufficient — each mount has its own).
- **FR-3** The panel groups controls under two headings: **Review** (Mode, Re-review, Model) and **Work** (Model, Swarm). The words "re-review" and "reviewers" never appear as top-level control labels; grouping carries the review context.
- **FR-4** Enum knobs are segmented controls whose first segment is `Default · <resolved value>`; selecting it clears the override (saves `null`). Review Mode: Quick / Full / None. Re-review: Changed / All / Blockers. Swarm: Off / Auto / Always.
- **FR-5** Model knobs remain native `<select>`s whose first option is `Default · <resolved>` — for the review model the resolved text is **"per-role default"** when `resolved.reviewModel` is null (the string "unconfigured" must not appear anywhere); for the work model it is `tiered` or the resolved model id (existing `workDefault` logic). Remaining options are plain model names with NO "reviewers:"/"work:" prefixes.
- **FR-6** The Re-review row renders only when the **effective** review mode is `full` (same condition as today's `review.resolved.reviewMode === 'full'`, but computed from `override.reviewMode ?? resolved.reviewMode`).
- **FR-7** An overridden row shows an override dot on its label and a per-row "reset" link that saves `null`. A "Reset all to defaults" footer action appears when ≥1 override is active and clears every override (sequential saves are fine).
- **FR-8** When `needsRestart` is true: an amber `restart pending` chip renders in the collapsed strip, and the panel shows the amber note with the existing sentence and the "Restart agent with new staffing" button wired to the existing `restart()`; the result message (`restartMessage`) renders next to it. Amber = "a human must act" per the style guide.
- **FR-9** All five POST endpoints, payload shapes, and the `refresh()`-after-save behavior are byte-identical to today. `saving` disables every control in the panel while a save is in flight.

### Non-functional

- **NFR-1 (no-loss)** Every affordance of the current strip survives: 5 settable knobs, override indication, conditional re-review control, per-knob clear-to-default, restart warning + button + result message, saving-disabled state, aria-labels on every control, `data-testid="issue-policy-strip"` on the root. A focused test (WI-5) enumerates these and gates the change.
- **NFR-2 (style guide)** DM Sans inherited (no font-family declarations), `font-medium` only (no bold/semibold), chip/badge tint formula `bg-{signal}/8 border-{signal}/32`, `rounded` small radii (no pills), primary tint for override signals, amber only for the restart surface. No hardcoded hex, no `slate-*`.
- **NFR-3** No new dependencies. No API/server changes. Component stays one file (plus its test).

## Design decisions (made here — do not re-litigate)

1. **Popover via `createPortal` with `position: fixed`**, copying `ConversationActionMenu.tsx`, NOT the mockup's `position: absolute` — two of the three mounts (drawer, cockpit) have scrollable/overflow ancestors that would clip an absolute panel. Compute `top/left` from the button's `getBoundingClientRect()` when opening; close on `mousedown` outside and on `Escape`; clamp left so the 400px panel stays in viewport (`Math.min(rect.left, window.innerWidth - 416)`).
2. **Chip labels**: `review · <value>`, `re-review · <value>`, `review model · <name>`, `work · <name>`, `swarm · <value>`. Key part muted, value part foreground. Chips are buttons that open the panel (no inline × — removal happens in the panel).
3. **Keep the exported name `IssuePolicyStrip`** and the `ReviewPolicyControl` re-export; keep the `{ issueId: string }` prop. Zero changes at the three mount sites.
4. **Model display names**: use `model.name` from `/api/settings/available-models` in options and chips (existing behavior uses `model.name` in options; chips resolve the override id → name via the same `models` list, falling back to the raw id if not found).
5. **Segmented "Default" sublabel** shows the resolved value at all times, so the effective value is always discoverable without hunting — this replaces today's permanent captions.
