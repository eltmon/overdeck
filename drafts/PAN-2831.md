# PAN-2831 — Issues pane sorts issue IDs lexicographically (PAN-532 renders after PAN-2822)

**Issue:** https://github.com/eltmon/overdeck/issues/2831
**Status:** draft → finalized by planning session 2026-07-17
**Author:** planning agent (claude-fable-5), auto mode

## Glossary

- **Issues pane** — the "Issues" section of the CommandDeck sidebar (`src/dashboard/frontend/src/components/CommandDeck/index.tsx`, ~line 1345), which renders the selected project's features via `ProjectNode`. Its row order comes from `groupProjects()` in `src/dashboard/frontend/src/components/CommandDeck/projectsData.ts`.
- **Issue id** — tracker identifier, standard form `PREFIX-NUMBER` (`PAN-532`), Rally form `TYPENUMBER` (`F29698`). See `src/lib/issue-id.ts` for the backend parser (not reused here — see D2).
- **Lexicographic sort** — plain string comparison (`localeCompare` or default `Array.prototype.sort()`), which orders `PAN-2822` before `PAN-532` because `'2' < '5'` character-wise.
- **Numeric collation** — `Intl.Collator` with `numeric: true`, which compares embedded digit runs by numeric value, yielding `PAN-532 < PAN-2822`.
- **contracts** — the `packages/contracts` Bun-workspace package (`@overdeck/contracts`), imported by both the dashboard frontend and the dashboard server; the only shared home for a comparator both sides can use.

## Problem

Every surface that orders issues by id uses lexicographic comparison, so mixed-width ids interleave in an order the operator reads as random. The comparator is duplicated inline at each call site, so a per-surface fix would leave the bug latent elsewhere.

## Proposal

One shared comparator in contracts; swap all seven call sites.

**New file** `packages/contracts/src/issue-sort.ts`:

```ts
/**
 * Numeric-aware issue-id comparator (PAN-2831).
 *
 * Plain string sorts order PAN-2822 before PAN-532 ('2' < '5'). This
 * comparator collates embedded digit runs by numeric value, so ids sort
 * numerically within a prefix. Every surface that sorts issue ids must
 * use it instead of localeCompare or default Array.sort().
 */
const collator = new Intl.Collator('en', { numeric: true, sensitivity: 'base' });

export function compareIssueIds(a: string, b: string): number {
  return collator.compare(a, b);
}
```

Re-exported from `packages/contracts/src/index.ts`. Each call site becomes `.sort((a, b) => compareIssueIds(a.issueId, b.issueId))` (or `.sort(compareIssueIds)` for plain string arrays; in `useSearch.ts` only the tiebreak line changes — score stays primary).

## Requirements

- **FR-1** — `@overdeck/contracts` exports `compareIssueIds(a: string, b: string): number` that orders standard ids numerically within a prefix (`PAN-532 < PAN-538 < PAN-806 < PAN-2822`), groups distinct prefixes lexicographically (`AUR-2 < PAN-1`), orders non-numeric suffixes after the base id (`PAN-532 < PAN-532-hotfix < PAN-538`), handles Rally ids (`F532 < F2822`), and treats case-insensitive equal ids as equal. Unit-tested in `packages/contracts/src/issue-sort.test.ts`.
- **FR-2** — The Issues pane (via `groupProjects()` in `projectsData.ts`) orders features with `compareIssueIds`; project-level name ordering is unchanged. Unit-tested in a new colocated `projectsData.test.ts`.
- **FR-3** — Remaining frontend call sites (`MergePolicySection.tsx`, `useSearch.ts` tiebreak, `HomePage.tsx`) use `compareIssueIds`; `useSearch` keeps score-descending primary.
- **FR-4** — Server call sites (`routes/projects.ts:659`, `resource-discovery.ts:809`, `:930`) use `compareIssueIds`; no `.issueId.localeCompare` remains in those files.
- **NFR-1** — Ordering is deterministic across environments (collator locale pinned to `'en'`).
- **NFR-2** — No behavioral change to any surface whose primary sort key is not the issue id.

## Decisions

- **D1 — Home = contracts, not frontend lib.** Server call sites exist (#5–#7); contracts is the only package both sides import. A frontend-lib comparator would leave the API payload order broken.
- **D2 — Pinned `Intl.Collator('en', { numeric: true, sensitivity: 'base' })`, not hand-rolled parsing.** Numeric collation covers standard, Rally, mixed-width, and suffixed ids with zero parsing code; `src/lib/issue-id.ts` is backend-only (Effect dependency) and would need porting for no gain. Simplicity-first.
- **D3 — Only issue-id comparisons change.** Priority/recency/name/score primaries are preserved verbatim (acceptance requires preserved grouping semantics).
- **D4 — No docs item.** No documented surface describes issue-list ordering; `plan.metadata.docsJustification` is set on the vBRIEF.
