# PAN-3090 — Simple issue page: narrative feed, visible question, honest blocked state

**Issue:** [PAN-3090](https://github.com/eltmon/overdeck/issues/3090)
**Approved design:** `docs/design/simple-issue-page-mockup.html` (interactive mockup, reviewed and approved by the operator in conversation on 2026-07-25; screenshots in `docs/design/screenshots/simple-issue-mockup-*.png`)
**Scope:** dashboard frontend, simple mode only. No backend changes. No changes to advanced mode, the drawer, or `ConversationPanel`.

---

## Glossary

- **Simple mode** — the jargon-free dashboard persona (PAN-2908 C-SIMPLE). UI copy is linted against a banned-word list (`BANNED_WORDS` in `src/dashboard/frontend/src/lib/simple/strings.ts:11-30`); the lint test scans every non-test `.ts`/`.tsx` file in `src/dashboard/frontend/src/components/simple/` (`src/dashboard/frontend/src/lib/__tests__/simple-foundations.test.ts:132-147`).
- **Kickoff prompt** — the first `user`-role message in a work agent's transcript. Overdeck generates it at spawn; it contains the issue title, workspace path, per-issue record JSON, and role instructions (~55 KB typical).
- **Conversation-messages stream** — the WS-RPC subscription `useConversationMessagesStream(conversation)` (`src/dashboard/frontend/src/components/chat/useConversationMessagesStream.ts:141`) that fills a React Query cache key `conversationMessagesQueryKey(name)` with `{ messages: ChatMessage[], workLog: WorkLogEntry[], streaming }`. `name` is the agent id for agent transcripts.
- **Work log** — `WorkLogEntry[]` (`src/dashboard/frontend/src/components/chat/chat-types.ts:32-46`): server-parsed tool-call summaries with `label`, `detail`, `command`, `changedFiles`, `tone` (`'thinking' | 'tool' | 'info' | 'error'`). The same data `ConversationPanel` renders in its tool-call sections.
- **Pending question payload** — `agent.pendingAskUserQuestion` on the agent snapshot (`packages/contracts/src/types.ts:330`): `{ toolUseId, askedAt, questions: [{ question, header?, multiSelect?, options: [{ label, description? }] }] }`. Already rendered by `AskUserQuestionDialog` (`src/dashboard/frontend/src/components/AskUserQuestionDialog.tsx:37-41`).
- **Narrative feed** — the new simple-mode rendering of the transcript: assistant prose, one-line tool actions, system lines, and a live-status row, in chronological order.
- **Rich question card** — the needs-you status card variant that quotes the pending question text and renders its options as selectable rows with an inline answer composer.

## Problem

`SimpleIssuePage` mounts the full operator transcript (`DrawerAgentSession` → `ConversationPanel`, `src/dashboard/frontend/src/components/simple/SimpleIssuePage.tsx:156-169`) as its "What it's saying and doing" feed. Because the first message in an agent transcript is the machine kickoff prompt, the page opens with ~55 KB of raw prompt rendered by `ChatMarkdown`'s large-message fallback (`LARGE_MESSAGE_CHARS = 50_000`, `src/dashboard/frontend/src/components/chat/ChatMarkdown.tsx:459-505`) as a monospace wall with a "Large message (55 KB)" banner — on a surface whose own copy is linted to ban the word "workspace".

Three amplifiers:

1. The needs-you status card shows only "The agent needs one decision from you before it can continue" (`src/dashboard/frontend/src/lib/simple/userFacingState.ts:67-71`). The actual question and options sit unused on the agent snapshot; the answer composer is ~700px below the transcript wall.
2. `STEP_INDEX_BY_STATE` (`src/dashboard/frontend/src/components/simple/parts.tsx:42-48`) maps `needs-you` → step 1 ("Writing code") with a blue machine-working pulse. A blocked agent is not working; per the style-guide signal law (amber = human must act, blue = machine working), this is the wrong color and the wrong claim.
3. The embedded panel header leaks advanced chrome into simple mode: "Drifted master" warning badge, "Tools" button, and a one-agent picker.

## Requirements

### Functional

- **FR-1 — Narrative feed.** The simple issue page renders the agent transcript as a narrative feed, never as raw message bubbles: kickoff prompt collapses to a one-line system entry with the raw payload behind a disclosure; assistant messages render as prose clamped to ~3 lines with a "Read more" toggle; work-log entries render as quiet one-line actions (edited files, commands run, searches) with muted timestamps; entries interleave chronologically.
- **FR-2 — Rich question card.** When the pending-input agent's `pendingAskUserQuestion` payload contains exactly one question with `multiSelect` not true, the status card quotes the question text, renders each option (label + description) as a single-select row, and hosts the answer composer inline. Send delivers via the existing `answer` action (`text = typed text, else selected label`). After send, the card shows an "Answer sent" confirmation and the feed's live row returns to a working state.
- **FR-3 — Generic card fallback.** Any other pending-input shape (multiple questions, `multiSelect: true`, or no structured payload) keeps today's generic card + below-feed composer behavior. The Advanced AUQ dialog remains the path for those.
- **FR-4 — Honest blocked state.** When the page state is `needs-you`: the current progress-track node renders amber with a "waiting on you" caption (not a blue working pulse), and the feed header's live chip reads "waiting on you" in warning tone. When the agent is running, the chip reads "live" in info tone.
- **FR-5 — Chrome removal.** "Drifted master", "Tools", and the agent picker no longer render in simple mode. The feed header shows a quiet caption `<Role> agent · <agent-id>` (e.g. "Work agent · min-896", agent id in `font-mono`). When the issue has more than one agent, a minimal text segmented control switches the feed between agents.
- **FR-6 — Steering composer.** When the rich question card is shown, the below-feed composer is hidden (the card hosts answering). In all other states the steering composer below the feed behaves as today.
- **FR-7 — Live updates.** The feed subscribes to the same conversation-messages stream as today; new entries append and the view auto-scrolls to the newest entry when the user is already at the bottom. The final row reflects current state: working-phase label while running (reuse `src/dashboard/frontend/src/lib/workingPhase.ts`), "Paused — waiting for your answer" while needs-you, done sentence when ready/done.

### Non-functional

- **NFR-1 — Style-guide conformance.** DM Sans for all prose; `font-mono` only on identifiers (agent id, file paths, commands); no weight above `font-medium` (500); signal colors per the token table (amber = human, blue = machine, emerald = outcome, red = broken); at most one colored signal per feed row; cards borderless with ambient shadow in light mode, hairline border in dark mode.
- **NFR-2 — Copy-lint compliance.** All new user-facing strings live in `SIMPLE_STRINGS` (`strings.ts`) and contain no `BANNED_WORDS` matches; new component source passes the existing copy-lint test.
- **NFR-3 — No new backend.** All data derives from existing sources: `deriveSimpleIssue`, the conversation-messages stream, the agent snapshot's `pendingAskUserQuestion`, and `useSimpleActions`.
- **NFR-4 — Performance.** Feed shaping is a pure, memoized function; no per-entry markdown rendering for clamped rows (plain-text preview; full `ChatMarkdown` only behind "Read more" expansion).

## Decisions (made here, not left to the implementer)

1. **Kickoff detection = the first `user` message in the transcript.** Work agents are always spawned with a prompt, so `messages.find(m => m.role === 'user')` as the earliest entry is the kickoff. It renders as a system line ("Task started · told to <issue title lowercased>") with the full raw text behind a `<details>` disclosure capped at ~180px with internal scroll. If there are no messages yet, the existing empty state renders ("Nothing to show yet — updates appear here as it works.").
2. **Non-kickoff user messages render neutrally, never as "You".** Operator-typed steering and machine-injected feedback (e.g. verification failures delivered through the same door) are indistinguishable from `ChatMessage` alone; attributing machine text to the human would be a lie. They render as plain quoted rows with timestamp. Only the optimistic local append after the operator presses Send on this page is labeled "You answered".
3. **Rich card only for the single-question, single-select payload.** That is the overwhelming common case; anything more complex stays on the existing generic card + Advanced dialog path. No partial answering of multi-question payloads (the `answer-question` endpoint takes an ordered `answers[]`; partial arrays risk misalignment).
4. **Feed shaping is presentation-only.** `buildSimpleFeedEntries()` maps; it does not filter content out of existence. Every transcript item has a home: system line, say, action, or reply. The raw kickoff remains one click away (no-loss audit satisfied by construction).
5. **Work-log action text shaping, in priority order:** `changedFiles?.length` → "Edited `<a>`, `<b>` (+n more)"; else `command` → "Ran `<command>`" (truncated at 80 chars); else `label` verbatim. `tone === 'error'` styles the row in `--destructive-foreground`; no other row carries color.
6. **The feed keeps an internal scroll region** (max-height ~470px, up from today's 420px panel) and auto-follows only when already at the bottom.
7. **Multi-agent issues** get a minimal text segmented control (`Work · Review · …` by role label) above the feed — not the advanced picker. Single-agent issues show no switcher.
8. **Effort stays unset** (inherits the `high` default) for any spawned role working on this issue.

## Work items

### WI-1 — Feed-shaping pure module (traces: FR-1, NFR-4)

**Files:** new `src/dashboard/frontend/src/lib/simple/feedEntries.ts`; new test `src/dashboard/frontend/src/lib/__tests__/simple-feed.test.ts`.

**What/why:** a pure, memoizable function that turns the stream payload into narrative-feed entries, unit-testable offline with no React.

**Shape:**

```ts
import type { ChatMessage, WorkLogEntry } from '../../components/chat/chat-types';

export type SimpleFeedEntry =
  | { kind: 'system'; id: string; createdAt: string; text: string; raw: string }
  | { kind: 'say'; id: string; createdAt: string; preview: string; full: string; clamp: boolean }
  | { kind: 'action'; id: string; createdAt: string; text: string; files?: readonly string[]; failed: boolean }
  | { kind: 'reply'; id: string; createdAt: string; text: string };

export function buildSimpleFeedEntries(input: {
  messages: readonly ChatMessage[];
  workLog: readonly WorkLogEntry[];
  issueTitle: string;
}): SimpleFeedEntry[]
```

Rules (implement exactly):

1. The earliest `role === 'user'` message → `{ kind: 'system', text: 'Task started · told to ' + issueTitle-in-lowercase, raw: message.text }`.
2. Other `user` messages → `{ kind: 'reply', text }`.
3. `assistant` messages → `{ kind: 'say' }`; `preview` = first 280 chars of `text` with markdown fences/headers stripped to plain text (simple regex pass — strip ``` fences, leading `#`/`*` markers); `clamp = text.length > 280`.
4. `WorkLogEntry` → `{ kind: 'action' }` per Decision 5; `failed = tone === 'error'`.
5. Merge all entries sorted by `(createdAt, sequence ?? 0)`; stable.

**Tests (`simple-feed.test.ts`) — name them:**

- `collapses the first user message into a system entry with the raw prompt preserved`
- `renders later user messages as neutral replies, never attributed`
- `clamps assistant messages over 280 chars with a plain-text preview`
- `shapes work-log entries: edited files, ran command, fallback label, error tone`
- `interleaves messages and work log chronologically`
- `empty transcript yields no entries`
