# PAN-3294 — Concurrency guard, TTL, and storm breaker for work-agent-stop-hook LLM calls

**Issue:** https://github.com/eltmon/overdeck/issues/3294
**Author:** planning agent (claude-fable-5), auto mode, 2026-07-30

## Glossary

- **Stop hook chain** — Claude Code fires `~/.overdeck/bin/stop-hook` on every agent Stop event; it chains `work-agent-stop-hook` in the background (`sync-sources/hooks/stop-hook:135-138`, `"$WORK_AGENT_HOOK" &`).
- **work-agent-stop-hook** — bash script (source of truth: `sync-sources/hooks/work-agent-stop-hook`, installed to `~/.overdeck/bin/` by `pan admin hooks install` / `src/lib/claude-hooks-provision.ts`). Detects work agents that forgot `pan work done`. Its Phase 3 fallback pipes the pane tail to `claude -p --model <haiku>` (line 369).
- **pan-hook-lib.sh** — shared library sourced by all Overdeck hooks (`sync-sources/hooks/pan-hook-lib.sh`). Provides `pan_resolve_agent_id` and `pan_emit_event`. New guard primitives land here.
- **Single-flight lock** — at most one running instance of the hook body per agent. Implemented as an atomically-created lock *directory* (`mkdir`), not `flock` — `flock(1)` is absent on stock macOS, and the incident machine was a Mac.
- **TTL / watchdog** — hard wall-clock cap on the `claude -p` child; on expiry the child is killed and the hook exits without emitting a resolution.
- **Storm breaker / token bucket** — machine-wide sliding-window rate limit on hook-initiated LLM spawns; over the cap the hook logs a drop and exits without calling the LLM.
- **Resolution** — the lifecycle signal (`done` / `needs_input` / `unclear` / `stuck` / `api_error`) the hook emits via `emit_resolution()` (line 146). Two consecutive `unclear` ratchet to `stuck` (lines 394-420).

## Incident summary (why)

A dashboard EADDRINUSE crash-loop (~20s cadence, ~25 min) fired the Stop hook chain each cycle. Nothing bounded fan-out: 35 concurrent `claude -p --model claude-haiku-4-5` processes plus 70 hook shells accumulated, load hit 91.81 on an 8-core/8 GB Mac, and the operator had to kill 105 PIDs manually. Three independent gaps: no per-agent concurrency cap, no per-call TTL, no machine-wide rate limit.

## Audit result (verified 2026-07-30)

`grep` over `sync-sources/hooks/*` shows exactly one hook spawns an LLM: `work-agent-stop-hook:369` (`RESULT=$(echo "$ANALYSIS_PROMPT" | claude -p --model "$COMPLETION_MODEL" 2>>"$CLAUDE_STDERR")`). The match in `stop-hook:152` is a comment. `specialist-stop-hook`, `session-start-hook`, and the compact hooks make no LLM calls. The installed `~/.overdeck/bin/work-agent-stop-hook` is byte-identical to the sync-source. Therefore: primitives go in `pan-hook-lib.sh` (reusable by future LLM-calling hooks), wiring goes only into `work-agent-stop-hook`.

## Requirements

- **FR-1** At most one `work-agent-stop-hook` body runs per agent at any time. A second invocation that finds a live holder exits 0 immediately without curl/tmux/LLM work.
- **FR-2** A lock whose holder PID is dead is treated as stale: the new invocation removes it and proceeds. The lock is always released on exit (trap on EXIT).
- **FR-3** The `claude -p` call is killed after a configurable timeout (default 60 s, env `OVERDECK_HOOK_LLM_TIMEOUT`). On timeout the hook logs and exits 0 **without emitting any resolution** (a timeout under load must not ratchet `unclear` → `stuck`).
- **FR-4** A machine-wide sliding-window rate limit caps hook-initiated LLM spawns (default 6 per 60 s, env `OVERDECK_HOOK_LLM_RATE_LIMIT`). Over the cap the hook logs a drop line and exits 0 without spawning `claude` and without emitting a resolution.
- **FR-5** Guard primitives are shared functions in `pan-hook-lib.sh`, callable by any hook.
- **FR-6** `docs/HOOKS.md` documents the three guardrails and their env vars.
- **NFR-1** All new locking is portable to stock macOS + Linux: `mkdir`-based atomic locks only; no new `flock`, no GNU-only `timeout` dependency (fall back to a pure-bash watchdog when `timeout`/`gtimeout` are absent).
- **NFR-2** Fail-safe direction: when a guard cannot decide (bucket lock contended, lock dir unremovable), it must *skip the LLM call*, never spawn extra ones.
- **NFR-3** Tests use tiny configured timeouts (≤1 s TTL). Note on the repo fake-timers rule: these are subprocess integration tests executing the real bash script — vitest fake timers cannot advance a child process's clock, so small real delays are unavoidable; keep every test's real wait ≤ ~2 s so the suite stays parallel-safe (no `maxForks` masking).

## Design decisions (made here, not by the executor)

1. **Whole-body lock, not LLM-only** (FR-1). The incident piled up 70 hook *shells*, not just 35 LLM calls; every phase does curl and tmux work. Acquire the lock immediately after the `COMPLETED_FILE` early-exit (line 47), before the pipeline-status curl.
2. **Lock shape**: `$AGENT_STATE_DIR/stop-hook.lock.d/` created with `mkdir` (atomic on POSIX). Holder writes `$$` to `stop-hook.lock.d/pid`. On acquisition failure: read pid; if empty or `kill -0` fails → stale → `rm -rf` and retry `mkdir` exactly once; otherwise exit 0. `trap 'rm -rf "$LOCK_DIR"' EXIT` right after acquisition.
3. **Timeout helper** `pan_run_with_timeout <secs> <cmd...>`: use `timeout -k 5` if present, else `gtimeout -k 5`, else pure-bash fallback (background the command, watchdog subshell `sleep $secs; kill -TERM; sleep 2; kill -KILL`, `wait` and normalize the return code). Timeout must be observable as rc 124 (or 137/143 from the fallback kills).
4. **Timeout ≠ failure**: current behavior maps `claude` rc≠0 to `UNCLEAR` (lines 371-375) — that stays for genuine failures. Timeout (rc 124/137/143) is a *new, distinct* branch: log, exit 0, emit nothing.
5. **Token bucket**: file `${OVERDECK_HOME:-$HOME/.overdeck}/hook-llm-calls.log`, one epoch-seconds line per allowed spawn. `pan_llm_rate_check` (in lib): under a `mkdir` lock (`hook-llm-calls.lock.d`, ~1 s bounded spin), prune lines older than 60 s, count survivors; `>= limit` → return 1; else append `date +%s` and return 0. If the bucket lock can't be acquired within the bound, return 1 (NFR-2: fail closed for spawning).
6. **Rate-limit hit emits no resolution** — same reasoning as decision 4: during a storm, 35 agents flipping to `unclear`/`stuck` would be a second incident.
7. **Config via env with hardcoded defaults in the lib** — matches the existing `OVERDECK_HOOK_TIMEOUT` (`pan-hook-lib.sh:15`) and `OVERDECK_COMPLETION_CHECK_MODEL` (hook line 339) pattern. No config.yaml plumbing in this issue.

## Work items

### WI-1 — Single-flight lock primitive in pan-hook-lib.sh  (traces: FR-1, FR-2, FR-5, NFR-1)

**Files:** `sync-sources/hooks/pan-hook-lib.sh`, new `tests/scripts/pan-hook-lib-guards.test.ts`

Add two functions after `pan_resolve_agent_id` (line 47):

```bash
# Acquire a single-flight lock directory. Returns 0 with the lock held
# (caller must trap-release), 1 if a live holder exists.
# Usage: pan_acquire_singleflight_lock "$AGENT_STATE_DIR/stop-hook.lock.d"
pan_acquire_singleflight_lock() {
  local lock_dir="$1"
  if mkdir "$lock_dir" 2>/dev/null; then
    printf '%s' "$$" > "$lock_dir/pid" 2>/dev/null || true
    return 0
  fi
  local holder
  holder=$(cat "$lock_dir/pid" 2>/dev/null || echo "")
  if [ -n "$holder" ] && kill -0 "$holder" 2>/dev/null; then
    return 1
  fi
  # Stale (dead or unreadable holder) — reclaim once.
  rm -rf "$lock_dir" 2>/dev/null
  if mkdir "$lock_dir" 2>/dev/null; then
    printf '%s' "$$" > "$lock_dir/pid" 2>/dev/null || true
    return 0
  fi
  return 1
}

pan_release_singleflight_lock() {
  [ -n "$1" ] && rm -rf "$1" 2>/dev/null
  return 0
}
```

Tests (execute `bash -c '. pan-hook-lib.sh; …'` from the vitest file, mirroring the harness style of `tests/scripts/work-agent-stop-hook.test.ts`): acquire succeeds on empty dir and creates `pid`; second acquire against a live holder (use the test process's own live PID written into `pid`) returns 1; acquire against a dead-PID lock reclaims and returns 0; release removes the dir.

### WI-2 — Portable timeout primitive in pan-hook-lib.sh  (traces: FR-3, FR-5, NFR-1)

It must pass stdin through to the command and propagate stdout (callers use `RESULT=$(echo "$x" | pan_run_with_timeout 60 claude -p …)`). ### WI-3 — Machine-wide LLM token bucket in pan-hook-lib.sh  (traces: FR-4, FR-5, NFR-2)

**Files:** `sync-sources/hooks/pan-hook-lib.sh`, `tests/scripts/pan-hook-lib-guards.test.ts`

Add `pan_llm_rate_check` per design decision 5. Window 60 s; limit `${OVERDECK_HOOK_LLM_RATE_LIMIT:-6}`; bucket file `${OVERDECK_HOME:-$HOME/.overdeck}/hook-llm-calls.log`; lock dir sibling `hook-llm-calls.lock.d` with bounded acquisition (10 × 0.1 s attempts), fail closed (return 1) on lock exhaustion. On success (under limit) the function appends the current epoch and returns 0.

Tests (set `OVERDECK_HOME` to a temp dir): first call returns 0 and appends one line; pre-filling the file with `limit` fresh timestamps makes the next call return 1 and append nothing; pre-filling with old (>60 s) timestamps prunes them and returns 0; a held lock dir with a live-PID marker makes the call return 1 (fail closed).

- No changes to other hooks — the audit confirms none spawn LLMs today; they inherit the primitives when/if they ever do.

- No fix for the dashboard EADDRINUSE crash-loop that triggered the incident (separate issue).
- No behavior change for genuine `claude` failures (non-timeout rc≠0 still yields `UNCLEAR`).
- No migration of the existing `flock` uses in the hook/lib (resolution cache, pending-events buffer).
- No config.yaml plumbing for the new knobs (env-only, matching existing hook knobs).
