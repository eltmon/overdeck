## Glossary

- **Cockpit** — the issue view rendered by `IssueMissionControl.tsx` inside a Stage pane; one of three densities of the issue-view kit (`rail`, `cockpit`, `console`). This PRD changes ONLY the cockpit.
- **Stage pane** — the resizable center pane system (`src/dashboard/frontend/src/components/Stage/`). The cockpit's width is the pane's width, which is why all cockpit breakpoints are CSS **container queries** (`@container`), not viewport media queries.
- **Agent spine / AgentsLane** — the left "AGENTS & STEPS" column inside the cockpit (`AgentsLane.tsx`, rendered via `IssueTreeLane`), listing Plan/Work/Review(+sub-reviewers)/Verification/Test/Ship sessions.
- **Tab band** — this PRD's new name for the row of detail tabs (Overview, Code, PRD/Plan, …) after it is lifted out of the center column.
- **Tasks rail** — the fixed 256px right column (`TasksRail.tsx`) showing plan progress. This PRD folds it into a **Tasks chip** (in the tab band) that opens a **slide-over drawer**.
- **Agent conversation** — the transcript shown when an agent is selected (`SessionPanel` rendered by `IssueTreeContextPanel`). Never call this a "session pane" in user-facing copy; frame it as the concrete agent ("the Correctness reviewer").
- **No-loss gate** — the surface lock in `src/dashboard/frontend/src/components/issue-view/inventory.ts` + `densitySections.ts`, enforced by `tests/unit/dashboard/frontend/issue-view-no-loss.test.ts` and `src/dashboard/frontend/src/components/issue-view/IssueView.test.tsx`. Every section name must keep a real, visible `data-section` element.

## Problem

Clicking an agent squeezes its conversation into the center cell of a three-column grid, and the 11 detail tabs wrap into two rows inside that same cell. Verified current state:

1. **Grid** — `src/dashboard/frontend/src/components/Stage/cockpit/cockpitBody.module.css:96-100` (search `grid-template-columns: minmax(210px, 264px)`):
   ```css
   @container (min-width: 840px) {
     .missionBody {
       grid-template-columns: minmax(210px, 264px) minmax(0, 1fr) 256px;
     }
   }
   ```
   Agents lane ≤264px, Tasks rail fixed 256px, conversation gets the remainder.
2. **Tabs live inside the center column** — `IssueMissionControl.tsx:893` (search `data-section="Detail Tabs"`): the `<nav>` uses `flex flex-wrap gap-1` **inside** `<main>` (line 892), so 11 tabs wrap to two rows in a narrow pane.
3. **11 tabs including Conversation** — the `TABS` array at `IssueMissionControl.tsx:79-91` (search `const TABS: Array<{ id: MissionTab`): overview, code, plan, timeline, discussion, costs, artifacts, ship, **conversation**, files, terminal.
4. **Agent click flow** — `selectSessionFromTree` (`IssueMissionControl.tsx:797-801`, search `const selectSessionFromTree`) sets the selected session and clears `activeTab`; `IssueTreeContextPanel` (rendered at lines 915-929 under `data-section="SessionPanel"`) then shows `SessionPanel` — still inside the same squeezed center cell.
5. Out of scope: the outer shell already solved its width — the Awareness column (`CommandDeck/styles/command-deck.module.css:1401`, 300px) has a 30px collapsed rail (PAN-1591), and the project tree is JS-resizable. **Do not touch the outer shell.**
6. Already done, do not rebuild: Review → sub-reviewer convoy nesting with expand/collapse already exists in `AgentsLane.tsx` (search `reviewExpanded`, lines 247, 304-318).

## Requirements

### Functional

- **FR-1** The detail-tab menu renders as ONE full-width row (the tab band) between the header card and the body grid. It never wraps; at narrow container widths it scrolls horizontally (`overflow-x: auto`). Tab badges (`tabBadge`) are preserved.
- **FR-2** The Conversation tab is removed from `TABS`. Clicking an agent in the spine shows that agent's conversation in the main panel, which now spans all cockpit width right of the spine. Everything the Conversation tab rendered keeps a visible home (see D-2).
- **FR-3** The Tasks rail column is removed from the grid. A Tasks chip in the tab band shows `done/total` plan progress (same query key as `TasksRail` — zero new fetches) and opens a right-anchored slide-over drawer rendering the existing `TasksRail` content. "Open full" inside the drawer still opens the full Tasks view (the `beads` tab).
- **FR-4** The agent spine is collapsible to an icon-only rail (~56px) via a toggle in its header; the choice persists in `localStorage` and defaults to expanded.
- **FR-5** The conversation transcript is capped at a readable measure: the cockpit's `SessionPanel` wrapper gets `max-width: 980px`, horizontally centered. Applied ONLY at the cockpit call site (SessionPanel has other consumers).
- **FR-6** Pipeline phase click-through is unchanged: `handleStageClick`/`handlePhaseClick`/`openAgentByType` (`IssueMissionControl.tsx:804-826`) still open the matching agent conversation or tab.
- **FR-7** The no-loss gate stays green: every cockpit section in `DENSITY_SECTIONS.cockpit` keeps a real visible `data-section` element; no section name is deleted or renamed.
- **FR-8** Documentation updated (see WI-7).

### Non-functional

- **NFR-1** Style guide conformance (see "Intersecting repo rules"): `font-medium` only (the moved tab nav drops its pre-existing `font-semibold` — explicitly authorized here), badge tint formula 8%/32%, no `rounded-full` status pills, no hardcoded hex, one colored signal per row.
- **NFR-2** No new endpoints, polling loops, stores, or direct canonical-state access (the `docs/ISSUE-VIEW.md` data-model rule). The Tasks chip reuses TasksRail's existing query key (`/api/issues/:id/tasks`, shared with `TasksPanel` — see the header comment in `TasksRail.tsx:7-17`).
- **NFR-3** All new responsive behavior uses `@container` queries on `.missionWrap` (which already sets `container-type: inline-size`, `cockpitBody.module.css:22-26`) — never viewport media queries.
- **NFR-4** Quality gates pass: `npm run typecheck`, `npm run lint`, `npm test` with no new failures.

## Decisions (made here — do not re-derive)

- **D-1 Tab band placement.** The `<nav data-section="Detail Tabs">` moves out of `<main>` to become a direct child of the cockpit wrap, between the `<header>` (ends line 880, search `data-section="StatusNarrative"`) and `<div className={styles.missionBody}>` (line 882). It keeps its `data-section` marker and `tabBadge` rendering. Styling: keep current per-tab classes except (a) replace `font-semibold` with `font-medium`, (b) parent goes from `flex flex-wrap` to `flex flex-nowrap overflow-x-auto`, (c) the bottom-border "attached tab" look may be simplified to the mockup's rounded active-pill (`bg-primary/9 text-primary`) — either is acceptable; do not invent a third style.
- **D-2 Conversation-tab dissolution, with homes.** Remove `{ id: 'conversation', label: 'Conversation' }` from `TABS`, remove `'conversation'` from the `MissionTab` union (`IssueMissionControl.tsx:60-72`), and delete the `activeTab === 'conversation'` branch (line 954). `MissionConversationTab` (35 lines, renders Launch card / ActiveAgentPanel / Agents card / Quick tools card / Conversation timeline card) is NOT deleted: `IssueTreeContextPanel`'s `context === 'issue'` branch (line 528, search `if (context === 'issue') return <OverviewTab`) changes from returning `OverviewTab` alone to returning `OverviewTab` followed by `MissionConversationTab` (both wrapped in the existing spacing container). Net effect: the issue-context body (what you see after "Back to issue") is a strict superset; nothing the Conversation tab showed is lost. The already-dead fallback `return <MissionConversationTab …>` at line 529 goes away with this restructure.
- **D-3 Tasks chip + drawer.** Grid at ≥840px becomes `minmax(210px, 264px) minmax(0, 1fr)`. The chip renders in the tab band's right side (`margin-left: auto`), shows `done/total` + a small progress bar, and carries `data-section="TasksRail / TasksTab"` (a real, always-visible element — the render test rejects hidden markers). Clicking it opens a slide-over drawer (absolutely-positioned panel + scrim inside the cockpit wrap, as in the mockup): the drawer body renders `<TasksRail issueId={issueId} onOpenFull={() => { closeDrawer(); selectTab('beads') }} />` unchanged. Escape and scrim-click close it. Done/total comes from the same `useQuery` data TasksRail already fetches; extract a small shared rollup helper (using the existing `taskStatusBucket` from `src/dashboard/frontend/src/lib/taskStatus`) rather than a second fetch or a second bucketing implementation.
- **D-4 Spine collapse.** Add a collapse toggle to the spine header area (the `<aside>` wrapper around `IssueTreeLane`, `IssueMissionControl.tsx:883-891`). Collapsed state: grid first column becomes `56px` (add a conditional class on `.missionBody`, e.g. `.spineCollapsed`, in `cockpitBody.module.css`); rows render icon tile only with `title` tooltips (hide `.body` and status text in `agentsLane.module.css` under the collapsed class). Persist as `localStorage['overdeck.cockpit.spineCollapsed']`, default expanded. Keyboard: the toggle is a real `<button>` with `aria-expanded`.
- **D-5 Transcript measure.** In `IssueTreeContextPanel`, wrap the `<SessionPanel …>` return (line 521-527, search `<SessionPanel`) in `<div className="mx-auto w-full max-w-[980px]">`. Do not modify `SessionPanel` itself.
- **D-6 No inventory renames.** All section names in `DENSITY_SECTIONS.cockpit` and `ISSUE_VIEW_INVENTORY` survive as-is (`Detail Tabs`, `SessionPanel`, `Conversation / Files / Terminal tabs`, `TasksRail / TasksTab`, …). Only the physical location of their `data-section` elements moves. If the no-loss render test needs a home-path update (e.g. a component moved), update `home` in `inventory.ts` — never delete an entry.

## Intersecting repo rules (restated for the executor)

1. **Style guide is law** (`design/style-guide/STYLE-GUIDE.md`, skill `pan-style-guide`): DM Sans, `font-medium` everywhere (no semibold/bold in anything you touch), SF Mono only for identifiers, badge tint = 8% background / 32% border, no `rounded-full` status pills, no hardcoded hex, no `slate-*`, blue = machine working / emerald = outcome / amber = human must act / cyan = money only.

3. **No new data paths** — reuse existing query hooks and query keys; no new endpoints, polling loops, or store slices (`docs/ISSUE-VIEW.md`).
4. **No-loss gate** — deletions/moves are proven by `issue-view-no-loss.test.ts` + `IssueView.test.tsx`, never by memory. Markers must be real visible elements.
5. **Explicit literal Tailwind classes** — interpolated utility strings get purged (see the comment at `IssueMissionControl.tsx:93`).
6. **Worktree discipline** — work in `workspaces/feature-pan-2842/`, never checkout another branch; verify `git branch --show-current` = `feature/pan-2842` before the first edit.
7. **Fake timers** for any delay-based test (`vi.useFakeTimers()` — unlikely needed here, but binding if a drawer animation test waits).
8. **Quality gates before `pan done`:** `npm run typecheck`, `npm run lint`, `npm test` (run `bun install` from the workspace root first; never symlink node_modules).
