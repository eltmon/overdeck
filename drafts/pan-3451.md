# PAN-3451 — pi/ohmypi extensions still gate work-complete evidence on .beads/issues.jsonl (dead since PAN-2648)

**Issue:** https://github.com/eltmon/overdeck/issues/3451

## Glossary

- **evidence-clean path** — the first check in each extension's `handleWorkAgentTurnEnd`: when objective on-disk evidence says the work is finished, the extension POSTs `/api/agents/:id/work-complete` immediately, skipping the output-marker scan and the dashboard classifier.
- **canonical checklist door** — `checkIncompletePlanItemsPromise(workspacePath, issueId)` in `src/lib/work/done-preflight.ts:31`, the same gate `runVerificationForIssue()` uses. It reads the merged xBRIEF view (`readWorkspacePlanSync` in `src/lib/xbrief/io.ts:358`): canonical spec from `specs/` on `overdeck-state` (fallback: workspace `.overdeck/spec.vbrief.json`) overlaid with the per-issue record's `statusOverrides`.
- **extension** — the vendored hook packages `packages/pi-extension` and `packages/ohmypi-extension`, near-identical forks loaded by `pi --extension <dist>` / `omp --extension <dist>`. Zero runtime dependencies; they talk to the dashboard over HTTP with the internal token (`x-overdeck-internal-token` header, `packages/pi-extension/src/index.ts:183`).

## Problem

`evidenceClean()` (`packages/pi-extension/src/index.ts:499`, `packages/ohmypi-extension/src/index.ts:506`) computes:

```ts
return await allIssueBeadsClosed(workspace, issueId) && await xbriefSatisfied(workspace)
```

`allIssueBeadsClosed()` reads `<workspace>/.beads/issues.jsonl`. Since PAN-2648 removed the beads engine, no workspace has that file, the read always throws, and the function always returns `false`. The `evidence-clean` completion path can never fire. It fails soft (the marker scan and classifier still run), but it is dead code that silently weakens pi/ohmypi work-complete detection.

A second, adjacent staleness: `xbriefSatisfied()` (`pi-extension:488`) reads `.pan/spec.vbrief.json` and `.pan/continue.json` — pre-PAN-2541 legacy paths. The current workspace continue file is `.overdeck/continue.json` and the canonical spec lives on `overdeck-state`, so this conjunct is also reading dead locations (it defaults to `true` when nothing is found, so today it passes vacuously).

## Proposal

Replace the local file-guessing with the canonical server-side door:

1. **New dashboard endpoint** `POST /api/agents/:id/plan-checklist` in `src/dashboard/server/routes/agents/runtime-events.ts`, registered in `src/dashboard/server/routes/agents.ts` next to `postAgentClassifyCompletionRoute`. It authenticates with `validateAgentRuntimeEventAuth` (same as the sibling runtime-event routes), resolves the agent's `workspace` and `issueId` from `getAgentState(id)` (the pattern used in `src/dashboard/server/routes/cloister.ts:104`), runs `checkIncompletePlanItemsPromise(state.workspace, state.issueId)`, and returns `{ success: true, complete: boolean, incomplete: string[] }`. No client-supplied paths — the agent runtime record is the source of truth.
2. **Both extensions**: `evidenceClean()` becomes a `postJsonWithTimeout` POST to `/api/agents/${env.agentId}/plan-checklist` returning `result?.['complete'] === true`. Any network/HTTP failure yields `null` → `false` → the turn falls through to the structured-marker scan and classifier exactly as today (fail-soft preserved).
3. **Delete the dead helpers** from both extensions: `isClosedBead`, `beadMatchesIssue`, `allIssueBeadsClosed`, and the now-subsumed `statusComplete`, `planItemsComplete`, `xbriefSatisfied` (the endpoint covers "plan is satisfied" strictly better, via the live door).
4. **Beads-residue cleanup in the same files**: the work-complete summary string changes from `'All issue beads are closed and the plan is satisfied'` to `'All xBRIEF plan items are complete'`; the `COMPLETION_PHRASES` entry `'all beads closed'` becomes `'all tasks closed'` (the phrasing the `classify-completion` route at `runtime-events.ts:169` already recognizes).
5. **Docs**: update the "Pi Completion Detection" section of `docs/HOOKS.md:133-142`, which currently documents the beads check.

### Why a server endpoint instead of mirroring `readWorkspacePlanSync` in the extension

The canonical resolution walks projects.yaml lookup, state-read-home resolution, spec filename parsing, and the per-issue record door (`src/lib/xbrief/io.ts:284-291`, `src/lib/pan-dir/paths.ts:22`). Duplicating that inside two zero-dependency extension packages would create a parallel read path for canonical state — exactly what the single-source-of-truth tenet forbids — and would drift the moment the state plane moves again. The extension already maintains an authenticated HTTP channel to the dashboard; asking the server (which owns the doors) keeps one read path. Shelling out to `pan task` from the hook was rejected: it spawns a Node process per `turn_end`, depends on `pan` being on the hook's PATH, and parses CLI output.

## Requirements

- **FR-1** — A new `POST /api/agents/:id/plan-checklist` route, internal-token authenticated, resolves the agent's workspace/issueId from the agent runtime record and reports checklist completeness via `checkIncompletePlanItemsPromise`.
- **FR-2** — The pi extension's `evidenceClean()` consults that endpoint instead of `.beads/issues.jsonl`.
- **FR-3** — The ohmypi extension's `evidenceClean()` makes the identical change (the two files are deliberate forks; they must stay in lockstep).
- **FR-4** — `isClosedBead`, `beadMatchesIssue`, `allIssueBeadsClosed`, `statusComplete`, `planItemsComplete`, and `xbriefSatisfied` are removed from both extensions, and the beads-flavored strings (`'all beads closed'`, the work-complete summary) are updated.
- **NFR-1** — Fail-soft is preserved: endpoint unreachable, non-2xx, or agent record missing ⇒ evidence-clean does not fire; marker scan and classifier still run. No new hard failure mode for pi/ohmypi agents.
- **NFR-2** — No new direct reads of spec/record/state stores outside the existing canonical doors (one-read-door tenet).

## NonGoals

- Changing `runVerificationForIssue()` or the `pan done` preflight — they already use the canonical door.
- Changing the `classify-completion` heuristics or the structured-marker protocol (`OVERDECK_WORK_COMPLETE`, `OVERDECK_SPECIALIST_RESULT`).
- Removing historical "bead" mentions that refer to the old beads migration itself (e.g. `docs/ohmypi-contract.md`'s migration-bead references are historical records).
- Claude Code hook completion flow (uses `Stop` hook + server-side flow; unaffected).
- Bootstrapping the repo-wide `.pan/context/codebase/` map — absent on main; authoring it from a three-file discovery would fabricate authority. Deferred.

### 1. `add-plan-checklist-endpoint` — server route (traces FR-1, NFR-2)

Files: `src/dashboard/server/routes/agents/runtime-events.ts`, `src/dashboard/server/routes/agents.ts`, `tests/unit/dashboard/server/routes/plan-checklist.test.ts` (new).

In `runtime-events.ts`, next to `postAgentClassifyCompletionRoute` (line 161), add:

```ts
export const postAgentPlanChecklistRoute = HttpRouter.add(
  'POST',
  '/api/agents/:id/plan-checklist',
  httpHandler(Effect.gen(function* () {
    const request = yield* HttpServerRequest.HttpServerRequest;
    const auth = yield* Effect.promise(() => validateAgentRuntimeEventAuth(request));
    if (!auth.ok) return auth.response;

    const params = yield* HttpRouter.params;
    const id = params['id'] ?? '';
    if (!id.trim()) return jsonResponse({ success: false, error: 'missing agent id' }, { status: 400 });

    const { getAgentState } = yield* Effect.promise(() => import('../../../../lib/agents.js'));
    const state = yield* getAgentState(id);
    if (!state?.workspace || !state.issueId) {
      return jsonResponse({ success: false, error: 'agent workspace or issue unknown' }, { status: 422 });
    }

    const { checkIncompletePlanItemsPromise } = yield* Effect.promise(
      () => import('../../../../lib/work/done-preflight.js'),
    );
    const incomplete = yield* Effect.promise(() => checkIncompletePlanItemsPromise(state.workspace, state.issueId));
    return jsonResponse({ success: true, complete: incomplete.length === 0, incomplete });
  })),
);
```

## Acceptance criteria

1. `POST /api/agents/:id/plan-checklist` returns `{ success: true, complete: true }` for an agent whose workspace plan has all items in a terminal status, and `complete: false` with named items otherwise; it rejects requests without the internal token.
2. With the endpoint reporting complete, a pi `turn_end` produces a `work-complete` POST with reason `evidence-clean`; with the endpoint reporting incomplete or unreachable, it does not.
3. `git grep -n "issues.jsonl\|allIssueBeadsClosed\|beadMatchesIssue\|isClosedBead\|xbriefSatisfied\|all beads closed" packages/` returns no hits.
4. The ohmypi extension diff mirrors the pi extension diff modulo naming.
5. `docs/HOOKS.md` "Pi Completion Detection" names the plan-checklist endpoint and no longer mentions beads.
6. `npm run typecheck`, `npm run lint`, and the pi/ohmypi package test suites are green.

## Hazards / deploy notes

- The endpoint is only reachable once the dashboard runs a build containing item 1; the extension change is safe to land first because a 404/network failure degrades to today's behavior (marker scan + classifier).
- Extension changes reach agents only after the package `dist/` is rebuilt and new pi/ohmypi sessions start; already-running sessions keep the old extension until resumed.
- `postJsonWithTimeout` returns `null` on non-2xx and on abort — the `result?.['complete'] === true` shape intentionally treats every failure as "not clean", never as "clean".
