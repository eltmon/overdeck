# PAN-3194 — Resume probes must verify the transcript exists before claiming resumable

**Issue:** https://github.com/eltmon/overdeck/issues/3194
**Status:** PRD draft (planning `--auto` mode; decisions recorded in `autoDecisions`, no interactive Q&A)

## Glossary

- **Resume probe** — any code path that decides an agent "has a resumable Claude session". Three exist today: `getWorkAgentLifecycleStateSync` / `getWorkAgentLifecycleStateSnapshot` in `src/lib/work-agent-lifecycle.ts` (drives `pan start`'s refusal and the `/api/agents/:id/has-session` route), `buildStoppedAgentLifecycle` in `src/dashboard/server/routes/agents/shared.ts` (drives the stopped-agent listing's `hasSession`), and the spawn-mode decision inside `resumeAgent` in `src/lib/agents/resume.ts` (the deacon auto-resume equivalent).
- **sessionId / stored session id** — the Claude Code session UUID persisted in `~/.overdeck/agents/<id>/session.id` (plus `sessions.json`, `runtime.json claudeSessionId`), resolved by `getLatestSessionIdSync` in `src/lib/agents/activity.ts`.
- **JSONL transcript** — the Claude Code conversation file at `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`, computed by `sessionFilePath(cwd, sessionId)` in `src/lib/paths.ts:286`. `claude --resume <id>` dies when this file is absent.
- **jsonl-missing** — the diagnostic reason emitted by `resolveJsonlPath` in `src/dashboard/server/routes/jsonl-resolver.ts:443` when the stored session id has no transcript on disk.
- **Troubled gate** — after `maxConsecutiveFailures` recorded launch failures the agent is marked `troubled` and auto-resume stops retrying. "Launch crash: tmux session lost before kickoff delivery" (`src/lib/cloister/deacon-auto-resume.ts:217`) is the failure wording seen in the incident.
- **PAN-2895 recovery** — the existing `claudeJsonlMissingRecovery` block in `src/lib/agents/resume.ts:354-365` that fresh-launches and clears stale pointers when the transcript is gone. Merged 2026-07-21 in bb3b6d4599; **no test coverage**, and the live `dist/dashboard/server.js` at incident time predated it (0 matches for `claudeJsonlMissingRecovery`/`PAN-2895` in the running build).

## Problem

agent-pan-2876 crash-looped 3× into troubled because every resume path targeted a Claude session whose JSONL transcript does not exist. The agent row carried `sessionId 7c080a61-…`; transcript resolution logged `reason=jsonl-missing` at every patrol since 2026-07-26 04:53; the resume probes still treated the session as resumable:

1. `getLatestSessionIdSync` (`src/lib/agents/activity.ts:171-172`) returns the `session.id` file contents **without checking the transcript exists**:

   ```ts
   const fromSessionFile = getSessionId(agentId);
   if (fromSessionFile) return fromSessionFile;
   ```

2. The lifecycle probe (`src/lib/work-agent-lifecycle.ts:53`) trusts that id:

   ```ts
   const hasSavedSession = !!getLatestSessionIdSync(agentId);
   ```

   so `requiresSessionResetBeforeFreshStart` (line 72) and `canResumeSession` (line 122) come out true, `pan start` refuses a `--fresh`-less start with "has a resumable Claude session", and the dashboard offers Resume against a dead transcript.

3. The deacon auto-resume path (`handleAgentStoppedEvent` → `resumeAgent`, `src/lib/cloister/deacon-auto-resume.ts:784`) attempted `--resume` against the missing transcript on the incident build; the session died before kickoff delivery, the pre-kickoff death accumulated (`deacon-auto-resume.ts:210-219`), and the troubled gate tripped.

The PAN-2895 in-`resumeAgent` recovery already fixes (3) in source, but it is untested, and the probe-level lie in (1)/(2) is unfixed: even on a current build, `pan start` still refuses to start fresh without an explicit `--fresh`, and the UI still advertises a resumable session that cannot resume.

## Requirements

### Functional

- **FR-1** — Every resume probe MUST verify the Claude JSONL transcript exists at `sessionFilePath(workspace, sessionId)` for the resolved session id before claiming a session is resumable. This covers the `pan start` fresh-refusal path, the `/api/agents/:id/has-session` route and stopped-agent listing (`canResumeSession`/`hasSession`), and the deacon auto-resume spawn decision.
- **FR-2** — A stopped/crashed claude-code agent whose stored session id has no transcript on disk MUST route to the fresh-spawn path: `recommendedAction: 'start'`, `canStartFresh: true`, `canResumeSession: false`, `requiresSessionResetBeforeFreshStart: false`. `pan start` without `--fresh` MUST proceed instead of refusing.
- **FR-3** — The auto-resume path (deacon → `resumeAgent`) MUST fresh-launch with pointer clearing when the transcript is missing, so no `--resume` launch is attempted and no launch-crash failure accrues to the troubled counter for this case. (Behavior landed in PAN-2895; this issue locks it with regression tests.)
- **FR-4** — Non-claude-code harnesses (codex, ohmypi, acp) MUST retain current resumability behavior. The transcript probe applies only when `agentState.harness` is `'claude-code'` or unset.

### Non-functional

- **NFR-1** — Probes are read-only. A missing transcript MUST NOT cause the lifecycle resolver to mutate agent state (no clearing `session.id` on read); pointer clearing stays in `resumeAgent`'s recovery path (`clearAgentSessionPointers`, `src/lib/agents/session-pointers.ts:17`).
- **NFR-2** — `WorkAgentLifecycleState` changes are additive only (new optional field); existing fields keep their meaning so dashboard consumers (`src/dashboard/frontend/src/types.ts:160`, routes in `listing.ts`/`lifecycle-stop.ts`/`spawn.ts`, `src/lib/orders/dispatch-gate.ts`, `src/cli/commands/unpause.ts`) are unaffected.

## Proposal

Introduce one shared predicate and use it at every probe point.

### Work item 1 — `transcript-probe-predicate`: shared transcript-existence predicate

**Files:** `src/lib/paths.ts`, `src/lib/agents/resume.ts`, `src/lib/__tests__/paths.test.ts`

Add to `src/lib/paths.ts`, next to `sessionFilePath` (line 286):

```ts
/**
 * Does the Claude Code JSONL transcript for this session id exist on disk?
 * The single existence check every resume probe must use (PAN-3194) —
 * mirrors the jsonl-missing detection in jsonl-resolver.ts.
 */
export function claudeSessionTranscriptExists(cwd: string, sessionId: string): boolean {
  return existsSync(sessionFilePath(cwd, sessionId));
}
```

(`existsSync` is already imported in `paths.ts` — verify at edit time; add to the existing `node:fs` import if not.)

In `src/lib/agents/resume.ts`, replace the inline check at lines 354-358:

```ts
// BEFORE
const expectedClaudeJsonl = sessionFilePath(agentState.workspace, sessionId);
const claudeJsonlMissingRecovery = effectiveHarness === 'claude-code'
  && !compactSeed
  && resumeDriftReasons.length === 0
  && !existsSync(expectedClaudeJsonl);

// AFTER
const expectedClaudeJsonl = sessionFilePath(agentState.workspace, sessionId);
const claudeJsonlMissingRecovery = effectiveHarness === 'claude-code'
  && !compactSeed
  && resumeDriftReasons.length === 0
  && !claudeSessionTranscriptExists(agentState.workspace, sessionId);
```

(Keep `expectedClaudeJsonl` for the log line at 362. `existsSync` import in resume.ts stays — it is used elsewhere in the file, e.g. lines 144, 280, 288.)

Tests: extend `src/lib/__tests__/paths.test.ts` with present/absent cases (mock `node:fs` `existsSync` per-path, or use a real temp file under a mocked `os.homedir`).

### Work item 4 — `resume-spawn-plan-decider`: pure spawn-plan extraction + regression lock

**Files:** new `src/lib/agents/resume-spawn-plan.ts`, `src/lib/agents/resume.ts`, new test `src/lib/agents/__tests__/resume-spawn-plan.test.ts`

`resumeAgent` has no direct unit tests (its ~25-import dependency surface is always mocked wholesale, e.g. `message-agent-interventions.test.ts:74`). Lock the FR-3 behavior by extracting the decision at `src/lib/agents/resume.ts:337-395` into a pure function:

```ts
export interface ResumeSpawnPlanInput {
  harness: RuntimeName;
  compactSeed: boolean;
  driftReasons: string[];
  piProcessWasAlive: boolean;
  transcriptExists: boolean;   // caller computes via claudeSessionTranscriptExists for claude-code
  allowExplicitRecovery: boolean;
}
export interface ResumeSpawnPlan {
  mode: 'resume-saved' | 'fresh';
  freshReason?: 'compact' | 'drift' | 'pi-dead-recovery' | 'claude-jsonl-missing';
  clearSessionPointers: boolean;  // true only for claude-jsonl-missing
  rotationRefused: boolean;       // PAN-1980 refusal preserved
}
export function decideResumeSpawnPlan(input: ResumeSpawnPlanInput): ResumeSpawnPlan { … }
```

The extraction is behavior-preserving: same conditions, same precedence (compact → drift-refusal → pi-dead → jsonl-missing → resume-saved), same PAN-1980 `sessionRotationRefused` semantics (drift + missing transcript still refuses — see NonGoals). `resume.ts` calls the decider and keeps all side effects (logging, `clearAgentSessionPointers`, `saveSessionId`, launcher build) where they are.

Tests in `resume-spawn-plan.test.ts` (no mocks needed — pure): missing transcript → `{mode:'fresh', freshReason:'claude-jsonl-missing', clearSessionPointers:true, rotationRefused:false}` (this is the issue's regression: no `--resume` launch is attempted, so no launch-crash failure can accrue to the troubled counter); present transcript, no drift → `resume-saved`; drift + present → `rotationRefused:true`; compact → fresh with seed; ohmypi dead process → `pi-dead-recovery`.

## Decisions (recorded in `--auto` mode)

- **D1 — Fresh-spawn routing, not read-path clearing.** The issue offered "routes to the fresh-spawn path (or marks the agent's sessionId stale and clears it)". Chosen: probes report non-resumable and route to fresh spawn without mutating state; `resumeAgent`'s existing `clearAgentSessionPointers` remains the only mutation point, and a fresh spawn overwrites `session.id` anyway. Read doors must not write (NFR-1).
- **D2 — Claude-code harness only.** The probe checks the transcript only when `harness` is `'claude-code'` or unset. Codex resumes by thread id resolved from on-disk rollouts (`resolveCodexThreadIdSync`), ohmypi from its session JSONL — both already disk-verified. ACP transcript verification is a possible follow-up, not this issue.
- **D3 — Drift + missing transcript still refuses (PAN-1980 preserved).** The `claudeJsonlMissingRecovery` gate keeps its `resumeDriftReasons.length === 0` condition: when model/harness drift exists, the PAN-1980 rotation refusal wins and the agent stays stopped for an operator decision. The incident shape (plain resume, no drift) is fully covered; widening the recovery to override the refusal is a deliberate non-goal.
- **D4 — Pure-decider extraction instead of a full `resumeAgent` mock harness.** The regression lock for FR-3 lives in `resume-spawn-plan.test.ts` against a pure function. Mocking `resumeAgent`'s ~25 imports to test it directly buys the same coverage at much higher fragility.
- **D5 — `hasSavedSession` semantics unchanged; new additive `hasResumableTranscript` field.** Keeps every existing consumer (dashboard `hasSession`, dispatch-gate, unpause) working; the no-loss rule applies.

## Hazards

- **H1 — Deploy gap caused the incident.** The live `dist/dashboard/server.js` at incident time contained no PAN-2895 code (verified: 0 matches for `claudeJsonlMissingRecovery`), so even the existing recovery wasn't running. This issue's fix only reaches the field via the DoD deploy row (fresh build + dashboard restart). Close-out must verify the deployed build contains the merge.
- **H2 — Check the resolved id, don't re-resolve.** `getLatestSessionIdSync` step 4 (`sessions.json` → `pickFreshestExistingSessionIdSync`, `activity.ts:135-151`) already prefers ids whose JSONL exists, but step 2 (`session.id`) returns unchecked. Probes must existence-check whatever id the resolver returned, in the same call, not re-run resolution.
- **H3 — The async Effect `getLatestSessionId` (`activity.ts:220`) is a thinner resolver** (no codex/acp/ohmypi branches). The async snapshot's probe must gate on claude-code/undefined harness so a codex thread id is never checked against a Claude JSONL path (would false-negative every stopped codex agent).
- **H4 — One extra `existsSync` per stopped claude-code agent per evaluation.** Same cost profile as the existing `sessionExistsSync` tmux call and `jsonl-resolver`'s stats; no batching needed.
- **H5 — Do not edit the PAN-806 test's mocks.** `work-agent-lifecycle-resume-truth.test.ts` mocks `existsSync: () => true` globally — it keeps passing (transcript always "present"). New probe tests go in a new file with path-aware mocks.
