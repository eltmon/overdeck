# PAN-3012 — Transcript backups: preserve harness conversation JSONL before harnesses delete it

Issue: https://github.com/eltmon/overdeck/issues/3012
Status: DRAFT (authored 2026-07-23, references verified against main the same day)

## Glossary

- **Harness transcript** — the JSONL session file a coding harness writes as the canonical record of a conversation. Claude Code: `~/.claude/projects/<encoded-cwd-hash>/<sessionId>.jsonl`. Codex: `~/.codex/sessions/**`. Pi family: `~/.pi/agent/sessions/`, `~/.omp/agent/sessions/`. Agent-embedded: `~/.overdeck/agents/*/codex-home/sessions/`. The full authoritative list is `discoverySources` in `src/lib/conversations/harness-discovery.ts:28-54`.
- **Harness retention** — the harness's own deletion policy for those files. Claude Code deletes sessions after `cleanupPeriodDays` (default 30) from `~/.claude/settings.json`; Overdeck has no hook into or notification of that deletion. Other harnesses have their own (undocumented) policies. Overdeck must treat every harness transcript as **deletable at any time by a process it does not control**.
- **Soft archive** — Overdeck's existing conversation archive: a DB flag surfaced via `GET /api/conversations/archived` (`src/dashboard/server/routes/conversations.ts:251`) and `conversation-lifecycle.ts`. It preserves the conversation row and metadata, NOT the transcript. Unarchive and transcript viewing still resolve the original harness path.
- **Scanner** — the discovery orchestrator (`src/lib/conversations/scanner.ts`, PAN-457) that walks harness roots via `discoverJsonlFiles()` (`harness-discovery.ts:56`) and upserts `discovered_sessions` rows. It already visits every file this feature must protect.
- **Transcript resolution** — the read path that maps a conversation/session to its JSONL on disk: `resolveConversationTranscript()` (`src/lib/conversations/transcript-path.ts:14`) and `resolveJsonl()` / `extractHashFromJsonlPath()` (`src/lib/conversations/hash-resolver.ts:191,128`).
- **Backup store** — this feature's Overdeck-owned copy of transcripts, default root `~/.overdeck/backups/transcripts/`. NOT on `overdeck-state` (transcripts are large, private, and per-machine; the state branch is for pipeline state).
- **Deacon patrol** — the periodic maintenance tick (`src/lib/cloister/deacon.ts:221`, `patrolIntervalMs: 60_000`) that hosts background sweeps.

## Background

Overdeck's archive gives a false sense of durability. Archiving a conversation flags the DB row; the transcript stays in harness-owned storage. When Claude Code's cleanup (default 30 days) or any other harness deletes the JSONL, the archived conversation becomes a tombstone: unarchive succeeds but the transcript viewer, search/enrichment, summary-fork, and `conv-lookup` all dead-end on a missing file. The DB is by design a disposable cache "rebuilt from … JSONL transcripts" — so transcript loss is also *state* loss with no recovery path.

Nothing in the codebase copies transcripts anywhere today (verified: no hits for any backup/copy of `.claude/projects` outside scan/read paths). The scanner already discovers every file and records size/mtime, so the marginal cost of protecting them is small.

### Harness retention landscape (researched online 2026-07-23)

| Harness | Auto-deletes? | Window / mechanism |
|---|---|---|
| Claude Code | **Yes — on every startup** | `cleanupPeriodDays`, default **30 days** since last activity (`~/.claude/settings.json`). Known footgun: `cleanupPeriodDays: 0` silently disables persistence entirely (anthropics/claude-code#23710). Widely reported silent-loss complaints (#59248, #62959). |
| Codex CLI | No | Manual `codex delete` only; automatic retention is an open feature request (openai/codex#6015). |
| Pi / OhMyPi | No | Manual delete via `/resume` Ctrl+D or community `pi-session-cleanup` extension; no built-in policy. |
| Gemini CLI (ACP) | **Yes — enabled by default** | `sessionRetention`: `maxAge` default **30d**; optional `maxCount` (unlimited by default). Deletes the whole per-session dir. |
| Goose (ACP) | No | SQLite `sessions.db`; manual `goose session remove`; cleanup is an open feature request (block/goose#3892). |
| OpenCode (ACP-adjacent) | No | Unbounded growth today; `session prune` is an open feature request (anomalyco/opencode#22110, #4980). |

Implications: the binding deadline is **30 days since last activity** (Claude Code and Gemini CLI, both defaults, both silent). Everything else keeps transcripts until a human deletes them — but several of those trackers show upstream pressure to add auto-cleanup, so "no policy today" is not a stable guarantee. A **daily** sweep therefore gives ~30 missed-sweep margins on the tightest known policy; sub-daily intervals add no protection (a file at deletion risk is by definition ≥30 days old). The residual risks a sweep interval cannot fix are (a) manual deletion moments after a session ends and (b) a user-tightened `cleanupPeriodDays` of ≤1 day — mitigated by also sweeping after every full scan and immediately after conversation archive.

## Requirements

### Functional

- **FR-1** — A background **transcript backup sweep** MUST copy harness transcripts into the backup store. It runs (a) piggybacked on the existing scanner passes, (b) on a deacon patrol tick at a configurable interval (default **daily** — see retention landscape: the tightest known harness policy is 30 days, so daily gives ~30 missed-sweep margins and sub-daily adds no protection), and (c) immediately when a conversation is archived (archive intent = preserve intent). A file is (re-)backed up when its `(size, mtime)` differs from the last backed-up generation.
- **FR-2** — Backups MUST be per-session, content-addressed-deduped, and compressed: `<backupRoot>/<harness>/<original-relative-path>.zst` plus a small JSON sidecar (`.meta.json`) recording original absolute path, size, mtime, sha256, and backup time. Re-backup of an unchanged file (same sha256) is a no-op.
- **FR-3** — **Scope setting** (`conversations.backup.scope`): `all` (every discovered session), `tracked` (sessions correlated to an Overdeck conversation or agent), `archived` (only archived conversations' sessions). Default `tracked`.
- **FR-4** — **Retention setting** (`conversations.backup.retention_days`): `0` = keep forever (default). Non-zero prunes backup generations older than N days **only for sessions whose original still exists**; a backup whose original is gone is never pruned automatically.
- **FR-5** — **Read-path fallback**: `resolveConversationTranscript()` and `resolveJsonl()` MUST, when the original path does not exist, transparently resolve to a decompressed copy of the newest backup generation (materialized to a cache dir under the backup root). Callers see a readable JSONL path either way. This makes archived conversations readable forever with zero caller changes.
- **FR-6** — **Loss detection**: when the sweep finds a previously-discovered session whose original file is gone and which has NO backup, it MUST record a `transcript.lost` event carrying every piece of metadata Overdeck still holds for it (from `discovered_sessions` + conversation correlation: session id, harness, project/cwd, first/last activity, size, message count, and enrichment title/summary if they exist). Fail loud, no silent fallback.
- **FR-6a** — **Lost-sessions view**: `GET /api/conversations/backup/lost` lists unacknowledged lost sessions; the settings warning's "View lost sessions" opens a panel rendering that retained metadata. The transcript content is unrecoverable and the panel MUST say so plainly — its purpose is (1) an inventory of *what* was lost (title, project, harness, dates) so the operator knows the blast radius, (2) a diagnosis surface showing which harness's retention did the deleting, with a pointer to the fix (e.g. raise `cleanupPeriodDays`, raise Gemini `sessionRetention.maxAge`), and (3) an **Acknowledge** action (`POST /api/conversations/backup/lost/ack`) per row or all-at-once that clears the amber warning. Acknowledged losses stay queryable (`?all=1`) but stop counting toward the warning. If the lost session was correlated to an Overdeck conversation, the row links to the conversation page, which retains its own DB-side metadata (title, summary, cost, activity) even without the transcript.
- **FR-7** — **Settings UI**: a "Transcript backups" group inside the existing Conversations settings section (`src/dashboard/frontend/src/components/Settings/sections/ConversationSettingsSection.tsx`) with: enable toggle, scope select, retention select, backup-root path display, status block (last sweep, sessions protected, disk usage, lost-session warning), and a "Back up now" button hitting a new `POST /api/conversations/backup/run`. Mockup: see PAN-3012 artifact mockup (2026-07-23) — visual reference only; implementation follows the existing section's row primitives.
- **FR-8** — **Config**: settings persist under `conversations.backup.*` in `~/.overdeck/config.yaml` via the existing settings write door (`src/dashboard/server/routes/settings.ts`). Defaults: `enabled: true`, `scope: tracked`, `retention_days: 0`, `sweep_interval_hours: 24`, `root: ~/.overdeck/backups/transcripts`.
- **FR-9** — **CLI**: `pan admin transcripts backup` (run sweep now) and `pan admin transcripts status` (same numbers as the status block). Read/write only through the same service module the routes use — one door.

### Non-functional

- **NFR-1** — Zero sync FS calls; `fs/promises` throughout (scanner precedent). No `execSync` anywhere server-reachable.
- **NFR-2** — The sweep must be incremental and bounded: skip unchanged files by `(size, mtime)` before hashing; use the scanner's `runWithPool` parallelism; never block the event loop.
- **NFR-3** — Compression via a pure-JS or already-vendored dependency (`zstd` wasm or `zlib` gzip fallback). No new native addon (node-pty lesson).
- **NFR-4** — Backup store writes are crash-safe: write to temp file + rename; sidecar written after payload.
- **NFR-5** — Delay/retry tests use fake timers (`vi.useFakeTimers()` + `advanceTimersByTimeAsync`), per the repo rule.

## Design sketch

New module `src/lib/conversations/transcript-backup.ts` owning the whole domain (one read door, one write door):

```ts
export interface TranscriptBackupStatus {
  enabled: boolean;
  lastSweepAt: string | null;
  protectedCount: number;   // sessions with >=1 backup generation
  lostCount: number;        // originals gone, no backup
  diskUsageBytes: number;
}
export async function runBackupSweep(opts?: { force?: boolean }): Promise<SweepResult>;
export async function getBackupStatus(): Promise<TranscriptBackupStatus>;
export async function resolveBackupFallback(originalPath: string): Promise<string | null>;
```

Fallback wiring (after — `transcript-path.ts`, inside `resolveConversationTranscript` where the candidate existence check fails today):

```ts
if (!(await exists(candidate))) {
  const fallback = await resolveBackupFallback(candidate);
  if (fallback) return { path: fallback, fromBackup: true };
}
```

Generation index lives in the sidecar files themselves (filesystem is the source of truth); the DB may cache status counters but must be rebuildable by walking the backup root.

## Acceptance criteria

- AC-1 (↔WI-1): deleting a backed-up original and re-running the sweep changes nothing; deleting an *un*-backed-up discovered session records `transcript.lost` and increments `lostCount`.
- AC-2 (↔WI-2): with the original deleted, the conversation transcript view and `conv-lookup` read the backup copy end-to-end (verify through the real code path, not a unit stub).
- AC-3 (↔WI-3): patrol sweep fires on interval under fake timers; concurrent-sweep guard proven by test.
- AC-4 (↔WI-4/5): toggling enable/scope/retention in the dashboard round-trips to `config.yaml`; "Back up now" returns sweep counts; status block matches `pan admin transcripts status`.
- AC-5 (↔WI-6): CLI commands work in a sandbox without the dashboard running.
- AC-6 (↔WI-7): docs pages updated in the same PR.
