# PAN-2829 — Complete the vBRIEF → xBRIEF rename across code, docs, skills, and UI

**Issue:** https://github.com/eltmon/overdeck/issues/2829
**Author:** planning agent (claude-fable-5), auto mode, 2026-07-17
**Upstream cause:** deftai/xBRIEF renamed the spec vBRIEF → xBRIEF at v0.7.0 (UK trademark held by vBrief Ltd, deftai/xBRIEF#11).

## Glossary

- **xBRIEF / vBRIEF** — the machine-readable plan format. One spec, two names: vBRIEF before upstream v0.7.0, xBRIEF after. Overdeck emits v0.8.
- **Envelope** — the top-level metadata key of a spec document: `xBRIEFInfo` (v0.7+) or `vBRIEFInfo` (legacy). Exactly one of these plus `plan` forms a valid document.
- **State branch / state worktree** — the orphan branch `overdeck-state`, checked out at `${OVERDECK_HOME}/state/<project>/`, holding `specs/`, `continues/`, `drafts/`, `records/`.
- **Spec file** — `specs/YYYY-MM-DD-<ISSUE>-<slug>.vbrief.json` on the state branch (canonical plan).
- **Continue file** — `continues/<issue-lowercase>.vbrief.json` on the state branch (session resume state; plain JSON, **no envelope**).
- **State write door** — the canonical writer that commits/pushes state-worktree changes (`src/lib/pan-dir/`).
- **Legacy-compat read path** — code that exists solely to keep reading old-named artifacts (envelope key, file extension, workspace `spec.vbrief.json`, root `vbrief/` lifecycle dirs).

## Decisions (auto mode)

- **D1 — full identifier rename.** All `VBrief*` TS identifiers become `XBrief*`. Issue AC-1's grep gate cannot be satisfied by renaming only the envelope field.
- **D2 — serializer always emits `xBRIEFInfo`.** The version-based envelope selection is deleted; readers accept `vBRIEFInfo` indefinitely and normalize it to the canonical `xBRIEFInfo` field (inverse of today). Round-trip preservation of the legacy envelope existed to prevent *silent* up-conversion; this issue's explicit committed migration supersedes it and makes the serializer idempotent with migrated files.
- **D3 — full state migration (envelopes + file renames), deferred live run.** Shipped as an idempotent admin CLI subcommand (state-migrate family) with `--dry-run`, fixture-tested. **The live run happens only after this PR merges and the dashboard is redeployed** — old deployed code filters on `endsWith('.vbrief.json')` and would stop seeing every renamed spec (~49 active issues). Continues are rename-only (no envelope).
- **D4 — UI copy says "xBRIEF"** (not neutral "Spec"): one term across docs/CLI/UI.
- **D5 — `write-vbrief` becomes a redirect stub** to the renamed `write-xbrief` skill (all-up precedent).
- **D6 — historical artifacts untouched:** `docs/prds/**`, `docs/design/**`, `docs/research/**`, `.release/**`, `design/style-guide/mockups/**`.
- **D7 — permanent legacy-compat survivors:** `vBRIEFInfo` read normalization + optional type property, `.vbrief.json` acceptance in every reader, `PAN_SPEC_FILENAME = 'spec.vbrief.json'`, root `vbrief/{proposed,active,…}` dirs + `findLegacyVBriefByIssue`, legacy test fixtures, docs/skill redirect stubs.
