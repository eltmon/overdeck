# PAN-3863 — SSH Hosts and Remote Overdeck Servers

Issue: https://github.com/eltmon/overdeck/issues/3863
Research date: 2026-09-17 UTC. Companion to PAN-3762, not a replacement federation system.

## Glossary

- SSH target: a connection profile for an existing machine, retaining its SSH alias and credential-owner reference.
- Execution host: the machine that owns files, Git, processes and terminal state.
- Environment: a complete authoritative Overdeck server, with PAN-3762 environmentId and per-device access sessions.
- Direct SSH mode: a trusted local service operates a remote machine over SSH without claiming that it is a complete Overdeck environment.
- Paired server mode: a client talks to the remote machine's own Overdeck API; that host owns its orchestrator.
- Relay/helper: Orca's host-side SSH RPC/PTY daemon, distinct from Anywhere's public network relay.
- Connection generation: identifier for an attempt/registration incarnation, used to reject delayed work from a superseded connection.
- Unverifiable: the host cannot currently confirm an operation/process outcome; neither success nor exit can be inferred.
- Pairing: verifying a server and exchanging a limited bootstrap grant for revocable device access.

## Outcome and relationship to Anywhere

Provide the SSH Hosts controls in the supplied screenshot: Import, Add target, label/user/host/port/key reference, connection status, Test, Connect/Disconnect, edit, explicit reset and removal with ownership consequences. Add Remote Overdeck Servers with Connect to a host, Share this host, and Cloud machines. Cloud machines lists existing supported providers/provisioned environments; it is not a new cloud-provider project.

Herdr v0.9.1 reduces terminal work: it already owns persistent processes, observation/control streams, SSH-machine profiles and forwarded API operations. tmux remains supported. Neither product supplies Overdeck's scoped device authorization, issue lifecycle, browser/mobile application or machine federation. Those remain PAN-3762/PAN-2351 responsibilities.

## What Orca actually implements

Local clone inspected at commit 291b4ddd6f1c1af480169885e0fda7f9c78ff053. The appendix records exact source anchors. This section distinguishes observed code from proposed Overdeck decisions.

### Direct SSH implementation trace

1. `settings-remote-security-section-renderers.tsx` mounts SshPane for desktop-only SSH settings. SshPane loads targets and triggers best-effort import on opening; it calls window.api.ssh CRUD/test/connect operations and consumes globally hydrated connection states.
2. `ipc/ssh-target-crud-handlers.ts` owns target mutations. Renderer-supplied generation is removed; the owner allocates it. Import returns repository readoptions when a previously removed target is restored. SshTarget stores configHost, source, IdentityAgent, IdentitiesOnly, jump/proxy settings, retention and saved forwards.
3. `ssh-config-parser.ts` enumerates concrete aliases. `ssh-g-config-resolution.ts:resolveWithSshG` asks system OpenSSH for effective configuration, preserving Include/Match/wildcard inheritance; it uses bounded execution and separates arguments. `ssh-transport-selection.ts` routes proxy/fdpass/jump scenarios to system SSH and accounts for security keys. Orca also has ssh2; Overdeck v1 deliberately uses system OpenSSH alone to reduce compatibility branches.
4. `ssh-connection-manager.ts` caches a connection per target and fences concurrent attempts with Symbols. A late cancellation closes only its own connection, never the replacement. `ipc/ssh-connect-flow.ts` establishes the connection and then the relay session, checking attempt ownership at async boundaries.
5. `ssh-relay-deploy.ts` deploys a versioned helper with installation locks, staging/promote steps, runtime/native-dependency checks and bounded cleanup. It can reattach an existing helper rather than restart processes just because the client changed. This is substantial host-side infrastructure, not a bare SSH command.
6. `ssh-channel-multiplexer.ts` carries framed RPC and notifications with sequence/ack state, bounded writes, keepalives, request timeouts and cancellation. Timeout/connection-loss errors represent an unverifiable outcome: replay may duplicate an already executed mutation.
7. `providers/ssh-pty-session-reattach.ts` uses pty.attach, validates process incarnation and source-activation identity, and commits/rolls back the receiving lease. Old frames/exits cannot silently affect a reused PTY ID.
8. `ssh-reconnect-ladder.ts` distinguishes failed handshakes from flapping links, resets delay only after a stable minute, and budgets retry time against terminal retention. SshTarget defaults terminal retention to 0 (“until reset”), with optional bounded grace. Disconnect, reset, terminate and forget have different consequences.

### Remote-server implementation trace

1. RuntimeEnvironmentsPane renders separate Connect/Share/Cloud workflows and delegates catalog, connection and mutation actions. It does not make a raw SSH target a full runtime implicitly.
2. `use-runtime-environment-mutation-actions.ts` calls verifyAndAddFromPairingCode. `ipc/runtime-environment-pairing-verification.ts` parses the link, rejects unintended loopback, makes a 15-second status.get request with capabilities, validates the returned runtime status, and only then persists. Error categories distinguish invalid access link, host identity mismatch, interruption, unreachable host and local save failure. Loopback is explicitly allowed for an SSH tunnel and marked connectionDependency=ssh-tunnel.
3. `shared/runtime-environments.ts` separates private endpoint credentials from public descriptions. Records include runtime identity, endpoints/preference, paired device and pairingRevision. Public serialization removes deviceToken and publicKeyB64. Credential rotation advances revision so stale asynchronous responses can be fenced.
4. `shared/runtime-environment-store.ts` stores a bounded (1 MiB) catalog in orca-environments.json. The inspected implementation uses permission-hardened secure JSON files (POSIX 0600/file, 0700/directory; Windows ACLs), not evidence of OS-keychain encryption. Do not describe it as an encrypted-at-rest catalog. Overdeck must use PAN-3762's protected credential boundary rather than downgrade it.
5. `shared/remote-runtime-request-socket.ts` generates an ephemeral keypair, derives a shared key using the pairing offer's host public key and authenticates with deviceToken plus client capabilities inside the encrypted protocol. Requests have IDs, bounded serialization, deadlines, cancellation and typed handshake failures. This is application encryption over WebSocket, distinct from SSH encryption.
6. `docs/reference/remote-wire-compatibility.md` mandates capability negotiation for new stream opcodes and tests old/new clients in both directions. Changing payload meaning can break old clients even if the frame shape stays the same.
7. `docs/reference/ssh-execution-boundary.md` makes host ownership explicit: local process absence cannot prove remote death, and remote files/Git cannot fall back to the local checkout. For offline control-plane continuity it favors the peer/headless runtime model.

### Borrow, adapt, defer

| Practice | Overdeck decision |
| --- | --- |
| Effective OpenSSH config, aliases and manual/import provenance | Adopt; preserve alias, resolve on the credential-owning machine, never overwrite manual values during import. |
| Attempt and registration generations, late-completion fencing | Adopt for targets, streams, connection attempts and pairing revisions. |
| Separate reachability, process liveness and task completion | Adopt; connection loss ⇒ unverifiable, not stopped. |
| Verify remote descriptor/identity before saving | Adopt using PAN-3762 pairing/device sessions. |
| Capability negotiation and bidirectional skew tests | Adopt; new terminal framing cannot silently disappear. |
| Per-host credentials and redacted public models | Adopt; retain protected storage chosen in PAN-3762. |
| Versioned custom PTY relay/native addon deployment | Avoid for v1. Use Herdr/tmux plus the remote Overdeck server where full orchestration is required. |
| Automatic SSH import when settings opens | Adapt to explicit import with a preview/diff. Merely opening Overdeck settings should not mutate targets. |
| Custom WebSocket crypto implementation | Do not copy. Use authenticated TLS/SSH under PAN-2351/PAN-3762 now; optional relay E2EE belongs to PAN-2356's threat model. |
| Automatic helper install/repair and destructive removal semantics | Use explicit scoped setup/reset actions; background reconnect cannot install, replace or terminate a server. |

- FR-2: Explicit import preview supports concrete aliases, Include, effective User/Port/IdentityFile/IdentityAgent/IdentitiesOnly/ProxyJump/ProxyCommand; preserve manual entries and removed-target suppression. Do not auto-connect imported GitHub/GitLab aliases from the screenshot: successful SSH authentication is not proof of an interactive execution host.
- FR-3: Add/edit/test/connect/disconnect/reset/forget controls with clear operation-specific consequences and progress/error states. Test probes reachability/auth/platform/capabilities without installing or starting runtimes.
- FR-4: Direct SSH supports terminal inventory/control through installed Herdr/tmux, remote files via SFTP and bounded argv-based Git operations, plus workspace browsing in remote paths. Managed agents/workspaces require a paired remote Overdeck environment with its own writer/Deacon.
- FR-5: Connect/Share/Cloud workflows reuse PAN-3762's catalog, identity, verified descriptor, pairing and revocable sessions. Share never exports the internal root token. Browser-only clients delegate SSH to an explicitly named authorized owner service.
- FR-6: Import/reference Herdr machine profiles by their opaque ID and remote-session identity. Resolve remote operations explicitly; do not maintain an independently editable duplicate profile with silent drift.
- FR-7: Disconnect detaches transport and preserves processes. Reset terminates only explicitly enumerated owned sessions after confirmation; forget removes metadata without deleting remote files. Retention is supported only when owner backend can enforce it; otherwise expose “until explicitly stopped” and omit a fake timed guarantee.
- FR-8: Every file/Git/session/action/response carries host/environment ownership and generation. Wrong-host, stale-generation and ambiguous mutations fail; unavailable remote never falls back to local.
- FR-9: Negotiate protocol/features, fence late attempts, bound frames and retries, show unverifiable outcomes, and isolate one host's failure.
- FR-10: Preserve all Anywhere backlog capabilities through a machine-readable ownership/parity fixture and linked documentation.
- NFR-1: Async-only owner-side OpenSSH processes, no shell interpolation of user payloads. Respect known_hosts; host-key changes require an explicit foreground decision and never StrictHostKeyChecking=no.
- NFR-2: Credentials stay with their OS owner; redact status/logs/public DTOs. Desktop uses protected storage; browser receives scoped connection access only.
- NFR-3: One orchestrator per state directory, no shared SQLite/state-dir mounts, no implicit daemon replacement or background install.
- NFR-4: Fake timers for retries; two-host failure/late-frame tests; old/new protocol matrix.

## Chosen implementation contracts and before/after

Existing `src/dashboard/server/routes/remote.ts` is Fly-workspace-specific; it is not a general host catalog. Preserve its routes while delegating new host operations to an explicit domain service.

```ts
// Before: provider-owned VM identity dominates existing remote routes
const fly = createFlyProviderFromConfig(config.remote);
// After: host-aware operation; provider remains optional provisioning metadata
const target = yield* hosts.resolve(hostId);
yield* hosts.assertGeneration(target, request.generation);
return yield* hostExecutor.forTarget(target).listSessions();
```

Create `src/lib/overdeck/hosts.ts` as the only host read/write door and `src/lib/remote-access/ssh/` with config.ts, connection.ts, executor.ts and tunnels.ts. Prefer one system OpenSSH implementation. SSH aliases refer to the selected owner machine's config, which the UI labels explicitly. Persist non-secret target metadata through the existing settings/config writer; extend PAN-3762's catalog by reference, not a second credential store. Paired environment identity is authoritative when a target is upgraded; keep stable host aliases pointing to that environment.

New owner-service API proposal: GET /api/hosts; POST /api/hosts/import-preview; POST /api/hosts/import; POST /api/hosts; PATCH /api/hosts/:id; POST /api/hosts/:id/test|connect|disconnect|reset; DELETE /api/hosts/:id for metadata-only forget. Every mutation checks operate/admin as appropriate, origin, generation and owner. Browser payloads contain a host ID, never arbitrary commands or socket paths. Return typed stage failures and progress events. No write operations occur on GET.

For remote files/Git, expose typed operations (list/read/save file; status/diff/log; registered workspace actions) with root/path validation and the existing authorization model. Do not expose a generic unauthenticated exec API. Stage file writes with temporary file+rename on the same host, preserve file mode and surface conflict/version checks. Managed Git mutations continue through the remote Overdeck workspace writer; raw SSH is initially browse/read Git only. Remote file save requires explicit user action and write capability. A Git-only SSH service is labeled unsupported for execution, not connected as a usable machine.

Herdr API forwarding uses `--machine <id>` only for supported API commands; it neither forwards session-management nor interactive terminal attach. For remote observe/control, execute the documented NDJSON CLI on the owner host through a bounded SSH channel. Inventory all remote namespaces through the owner executor; a saved Herdr profile represents only one namespace. Do not copy SSH secrets into Herdr or rewrite its machine catalog on discovery. Explicit import stores external profile ref and a fingerprint; external edits trigger refresh/conflict handling.

For full remote Overdeck, PAN-3762 owns install/launch/reuse/pair and SSH loopback tunnel. The desktop main process in `apps/desktop/src/` owns local ssh; the dashboard running on another machine must never imply it is using the viewer laptop's keys. Headless/browser clients use direct authenticated server endpoints, or an explicitly configured owner-side SSH service. No mobile SSH execution is emulated in JavaScript.
