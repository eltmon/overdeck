## Glossary

- **bd / beads** — the git-backed issue tracker; since PAN-2564 backed by an embedded Dolt store whose canonical home is the project's state worktree (`${OVERDECK_HOME}/state/<project>/`).
- **refs/dolt/data** — a git ref in the project's infra remote carrying the published Dolt data; the cross-machine authority.
- **Reconcile** — `pan admin beads reconcile <project>` (`src/cli/commands/admin/beads-reconcile.ts` → `src/lib/beads/reconcile.ts`): a read-only, no-loss audit comparing bead sources; writes a markdown report plus an `approval.json` (`approved: false`) to the state worktree's `notes/` directory. It never chooses a winner, imports, pushes, or deletes.
- **Cutover marker** — `beads-cutover.json` (`src/lib/beads/cutover-marker.ts`), the record that a reviewed reconcile authorized a project's Dolt cutover; validated against the live `refs/dolt/data` head.
- **Quality gates** — per-project commands in machine-local `~/.overdeck/projects.yaml` (`src/lib/projects.ts:18`) run by the verification gate after a work agent signals done.
- **Bulk presence read** — one `getAllBeads()` resolver call deriving the set of issue IDs that have beads from bead labels, instead of one `bd` subprocess per issue/workspace (pattern: `issuesWithBeadsBounded`, `src/dashboard/server/routes/backlog.ts:53-66`).

## Problem

Seven landing gaps from PAN-2564 (each small and independent; none block the shipped system):

1. **myn 4-store split.** mind-your-now has four bead stores — `frontend/.beads` (131 records, incl. live min-865), `api/.beads` (33), the canonical state worktree (23), and a retired empty root DB. The reconcile tool is hardwired to exactly three fixed sources (`local-dolt`, `remote-dolt`, `state-jsonl` — `src/lib/beads/reconcile.ts:11`) and would abort for myn because `git fetch origin refs/dolt/data` (line 118) fails on the never-published remote. The 13 per-workspace `.beads/redirect` files were rewritten to the canonical path before the polyrepo topology was understood; the original mapping for 11 inactive workspaces is gone (redirects are gitignored). myn must NOT be published until a reviewed reconcile exists.
2. **No server gate.** Root `tsconfig.json:19` excludes `src/dashboard/**`, and root `npm run build` (package.json:81) does not build the server bundle. A `yield*`-outside-generator PARSE error shipped through green gates. Verified during planning: `npx tsc --noEmit -p src/dashboard/server/tsconfig.json` fails with **152 pre-existing errors**; `npm run build:dashboard:server:bundle` is green in ~2s.
3. **Sync bd stragglers.** `src/lib/cloister/flywheel.ts:170` (isReadyOrHasPrd) and `:328` (buildClassifyLookups without `issuesWithBeads`) still run `execFileSync('bd')` per issue/workspace; so does the `pan start` spawn gate (`src/cli/commands/start.ts:621`).
4. **Comparator noise.** The v53 migration bumped `updated_at` on every row, so the panopticon-cli reconcile flagged all 3253 records "conflicting" — the report is unreadable.
5. **Recency pollution.** The same mass reset poisons any recency analysis built on bead `updated_at` (e.g. PAN-2602's in-pipeline signal).
6. **Marker schema.** `cutover-marker.ts:25` validates both head fields as 40-hex git SHAs, but local Dolt heads from `bd vc status` are 32-char base32.
7. **Backlog degraded mode** under bd contention — deferred (see Non-goals).

## Requirements

- **FR-1** The reconcile comparator classifies records whose only differing field is `updated_at` as `metadata-drift`, distinct from `conflicting`, and the report summarizes counts per classification.
- **FR-2** `pan admin beads reconcile <project>` accepts repeatable `--store <name>=<path>` options adding extra local bead stores to the comparison, and tolerates an unpublished `refs/dolt/data` (remote reported absent, not fatal).
- **FR-3** A 4-store reconcile report + merge-plan recommendation exists for mind-your-now, produced read-only, with the operator approval gate left closed (`approved: false`). No publish, no marker, no store mutation.
- **FR-4** CI and the machine quality gates fail on a dashboard-server source parse error (gate = `npm run build:dashboard:server:bundle`). The 152-error typecheck debt is recorded in a follow-up issue, not fixed here.
- **FR-5** The flywheel derives beads presence from one bulk resolver read (shared helper), and the `pan start` spawn gate uses the async retry resolver; no `execFileSync('bd')` per issue/workspace remains at flywheel.ts:170/:328 or start.ts:621.
- **FR-6** `beads-cutover.json` accepts a Dolt-native 32-char base32 `localReconciledHead`; `remoteDoltHead` stays a 40-hex git SHA (it is compared against `git ls-remote` output at cutover-marker.ts:66-74); the convention is documented in the interface JSDoc.
- **FR-7** The 2026-07-12 `updated_at` mass reset is documented in `docs/BEADS.md` and cross-posted as a comment on PAN-2602.
- **FR-8** *(discovered during planning)* New-workspace beads redirects point at the resolved canonical home (`resolveCanonicalBeadsHome`, `src/lib/beads/home.ts:8`), never at a directory that itself holds a redirect. Today `worktree-ops.ts:111-130` writes `<worktree>/.beads/redirect → <repo>/.beads`, which post-cutover is itself a redirect — bd refuses redirect chains, bootstrap fails (`Error 1007: database exists`), and every mutation batch in a post-cutover workspace fails before push (reproduced live by this issue's own `pan plan finalize`). The polyrepo path (`create.ts:258-273`) silently skips redirect creation in the same case and must one-hop-resolve instead.
- **NFR-1** All reconcile operations for myn are strictly read-only; the only writes are report/approval/recommendation files under the state worktree's `notes/`.
- **NFR-2** Bulk presence reads keep the existing 8s bound; retry/delay tests use fake timers (repo rule).
