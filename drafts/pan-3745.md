# PAN-3745 — `cost.recorded` events are rejected at the ws-rpc boundary: emitter/contract name and payload mismatch

**Issue:** https://github.com/eltmon/overdeck/issues/3745
**Status:** draft PRD
**Author:** conversation conv-20260816-9367, 2026-08-16

## Glossary

- **Domain event bus** — `EventBus` (`src/lib/overdeck/infra.ts:531`); events emitted here reach the
  event store and fan out to dashboard clients through `subscribeDomainEvents`
  (`src/dashboard/server/ws-rpc.ts:777`).
- **Boundary guard** — `passesDomainEventSchema` (`src/dashboard/server/ws-rpc.ts:67`): drops any
  event not in the contracts `DomainEvent` union before RPC encoding, logging
  `[ws-rpc] dropping domain event that fails DomainEvent schema validation …`. Exists because one
  un-encodable event used to kill the subscription stream for every client (PAN-2225 class).
- **Contracts union** — `DomainEvent` (`packages/contracts/src/events.ts:1450`), the schema union of
  every event clients may receive.

## Problem (verified 2026-08-16)

The cost write door announces each recorded cost event
(`src/lib/overdeck/cost.ts:591`):

```ts
yield* bus.emit({ type: 'cost.recorded', payload: { issueId: event.issueId, cost: event.cost } });
```

But the contracts union member is **`cost.event_recorded`**
(`packages/contracts/src/events.ts:1230-1243`) with payload
`{ agentId, issueId, workspaceId?, cost, inputTokens, outputTokens }`. Every consumer uses the
contract name: the God View confluence reducer
(`src/dashboard/frontend/src/components/GodView/confluence/useConfluenceData.ts:417,452`), the
motion catalog (`src/dashboard/frontend/src/lib/motionCatalog.ts:56,81` — "Number pulse" on the
overview counter), the read model (`src/dashboard/server/services/domain-services.ts:175`), and a
second emitter (`src/dashboard/server/services/agent-event-utils.ts:125`).

Nothing anywhere subscribes to the literal `cost.recorded` (repo-wide grep: the emitter at
cost.ts:591 is the only occurrence outside tests; the adjacent comment "cost.subscribe +
/api/costs/stream feed from this" is stale — `src/dashboard/server/routes/costs.ts` contains
neither). Consequences:

1. Every cost event recorded through the cost door is dropped at the boundary — the God View live
   cost counter and confluence view never see door-recorded costs.
2. The guard logs the drop each time; cost-reconcile sweeps (every 5 minutes, see PAN-3743) turn
   that into recurring log spam.

**Decision (made here): rename the emitter to the canonical `cost.event_recorded` and emit the full
contract payload.** Adding `cost.recorded` to the union instead would enshrine two names for one
concept (violates one-term-per-concept) and still leave consumers listening on the other name.

## Requirements

- **FR-1** `record()` in `src/lib/overdeck/cost.ts` announces `cost.event_recorded` with the full
  contract payload: `agentId`, `issueId`, `cost`, `inputTokens` (= `event.input`), `outputTokens`
  (= `event.output`), `workspaceId` when known.
- **FR-2** A recorded event whose `agentId` or `issueId` is absent/unattributed must not produce a
  schema-failing broadcast: skip the announcement for those (they are reclassified later by the
  attribution backfill) — do not invent placeholder values.
- **FR-3** After the change, a full cost-reconcile sweep produces zero
  `[ws-rpc] dropping domain event … type=cost.recorded` lines.
- **NFR-1** No behavior change for the existing `agent-event-utils.ts` emitter or any consumer;
  this is an emitter-side alignment only.

## Work items

### 1. Align the emitter (FR-1, FR-2)

File: `src/lib/overdeck/cost.ts` (line 591, inside `record()` — the `CostEvent` in scope carries
`agentId`, `issueId`, `input`, `output`, `cost`; see the insert at lines 568–587).

Before:
```ts
// 3. Announce — cost.subscribe + /api/costs/stream feed from this.
yield* bus.emit({ type: 'cost.recorded', payload: { issueId: event.issueId, cost: event.cost } });
```
After:
```ts
// 3. Announce on the canonical contract type — God View live counters feed from this.
if (event.agentId && event.issueId) {
  yield* bus.emit({
    type: 'cost.event_recorded',
    payload: {
      agentId: event.agentId,
      issueId: event.issueId,
      cost: event.cost,
      inputTokens: event.input,
      outputTokens: event.output,
    },
  });
}
```
Match the emit-call typing convention used by `agent-event-utils.ts:125` (check whether it casts to
the contracts event type and mirror it). Fix the stale comment while touching the line.
