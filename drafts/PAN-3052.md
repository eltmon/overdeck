# PAN-3052 — Extract `applyBootReconciliationDecision` out of the deacon-auto-resume god file

**Issue:** https://github.com/eltmon/overdeck/issues/3052
**Verified against:** `feature/pan-3052` @ `44eaa91f1a` (contains `cb39b20958`, the boot-dialog honesty fix)

The boot-dialog honesty fixes (defects 1–4 of the original report) already landed in
`cb39b20958` and are test-locked. **This issue is only the remaining refactor:** a pure,
behavior-preserving move of `applyBootReconciliationDecision` into its own module so
`src/lib/cloister/deacon-auto-resume.ts` drops back under the 1000-line god-file ceiling
and its baseline row can be deleted.

## Glossary

- **God-file ceiling / ratchet** — `scripts/lint-file-size.sh` (wired into `npm run lint`)
  enforces `CEILING=1000` lines on non-test `src/**/*.ts(x)`. Files over the ceiling live in
  `scripts/file-size-baseline.txt` (`"<lines> <path>"`); a baselined file may shrink but never
  grow. Check mode **fails on stale entries**: a baselined file that shrinks to ≤1000 lines makes
  `npm run lint` fail until `bash scripts/lint-file-size.sh --update` drops its row
  (verified: `scripts/lint-file-size.sh:103-106`).
- **`applyBootReconciliationDecision(deps)`** — the with-deps implementation at
  `src/lib/cloister/deacon-auto-resume.ts:926-1017`. Applies the operator's boot-reconciliation
  decision (`resume_all` / `per_agent` / `hold_all`): iterates candidates through concurrency /
  load / memory gates and calls `handleAgentStoppedEvent` per candidate.
- **`AutoResumeNotifierDeps`** — `{ notifyAgentStopped, notifyAgentStatusChanged }`, defined at
  `deacon-auto-resume.ts:52-55`. Every `*WithDeps` function takes it; `deacon.ts` injects it.
- **Zero-arg wrapper** — `deacon.ts:1767-1769` exports
  `applyBootReconciliationDecision(): Promise<BootReconciliationApplyResult>` which calls the
  with-deps implementation with `autoResumeNotifierDeps()` (a `deacon.ts`-private function,
  line 1740, closing over the notifier callbacks that live in `deacon.ts`). All external callers
  (`src/dashboard/server/main.ts:52`, `src/dashboard/server/routes/boot-reconciliation.ts:10`,
  `src/dashboard/server/routes/misc/deacon.ts:4`) import this wrapper from `deacon.js`.
- **Idempotency set** — `appliedBootReconciliationDecisions` (`deacon-auto-resume.ts:59`), a
  module-level `Set<string>` keyed by `bootReconciliationDecisionKey()`
  (`deacon-auto-resume.ts:920-924`) so one decision is applied at most once per boot/decision/perAgent
  combination.
- **Pacing constants** — `RESUME_LOAD_FACTOR = 1.5` (line 604), `RESUME_STAGGER_MS = 150`
  (line 606), `RSS_SETTLE_MS = 2000` (line 611) in `deacon-auto-resume.ts`. All are also used by
  `autoResumeStoppedWorkAgents` / `recoverOrphanedAgents` (lines 773, 858, 891, 901), so they
  **stay defined in `deacon-auto-resume.ts`** and gain `export`.
- **Throwaway boot test** — booting the built `dist/dashboard/server.js` under Node 22 with an
  alternate port and a temp `OVERDECK_HOME`, per the no-live-boot-hotpatch rule. The server reads
  `API_PORT`/`PORT` (default 3011, `src/dashboard/server/config.ts:71`) and `GET /api/health`
  returns `{ status: "ok", ... }` (`src/dashboard/server/server.ts:132`).

## Why the move is safe and where the cycle danger is

`deacon.ts` (lines 40, 150) is the **only** file importing from `deacon-auto-resume.js`
(verified by grep across `src/`). No test file imports `applyBootReconciliationDecision`
(`src/lib/cloister/__tests__/boot-reconciliation.test.ts` — 18 tests — exercises
`boot-reconciliation.ts` and the outcomes module, not this function; verified by grep).

The moved function calls `handleAgentStoppedEvent`, which **stays** in `deacon-auto-resume.ts`
(already exported, line 629). So the import graph after the move is:

```
deacon.ts ──► boot-reconciliation-apply.ts ──► deacon-auto-resume.ts
deacon.ts ──► deacon-auto-resume.ts                      (unchanged)
```

Acyclic. The one forbidden edge is `deacon-auto-resume.ts` → `boot-reconciliation-apply.ts` —
never add it. Node 22 strict ESM rejects cycles Bun tolerates, and this is boot-path code
(`main.ts` imports `deacon.js` at startup), which is why item 2 is a real boot test.

- **FR-5** Behavior identical: gates, `RESUME_STAGGER_MS`/`RSS_SETTLE_MS` pacing, idempotency-set
  semantics, and the `already-running` branch (`deacon-auto-resume.ts:1000-1006`) all move verbatim.

- **FR-6** `docs/codebase-health/B-deacon-decomp.md` records the extraction so the decomposition

- **NFR-1** No import cycle: `boot-reconciliation-apply.ts` must not import from `deacon.js`, and
  `deacon-auto-resume.ts` must not import from `boot-reconciliation-apply.js`.

## Decisions (made here, not left to the executor)

- **D1 — Module name:** `src/lib/cloister/boot-reconciliation-apply.ts`, matching the existing
  sibling family (`boot-reconciliation.ts`, `boot-reconciliation-outcomes.ts`,
  `boot-reconciliation-predicates.ts`).
- **D2 — Route imports stay on the `deacon.js` wrapper.** The issue AC says "`deacon.ts` and
  `routes/boot-reconciliation.ts` import it from there", but the route calls the **zero-arg**
  wrapper, which needs `autoResumeNotifierDeps()` — private to `deacon.ts` (the notifier callbacks
  live there; importing them from the new module would create the forbidden cycle). The AC's intent
  — the function no longer lives in `deacon-auto-resume.ts` and is imported from the new module by
  its consumer — is satisfied by `deacon.ts` importing from the new module and the routes
  continuing to import the wrapper from `deacon.js`, unchanged. This is the only reading compatible
  with the issue's own "no behavior change" constraint.
- **D3 — Type re-exports move with the function.** `deacon-auto-resume.ts:57` re-exports
  `BootReconciliationApplyResult` / `BootReconciliationOutcome` / `BootReconciliationOutcomeReason`
  from `boot-reconciliation-outcomes.js` solely for the moved function's consumers. The new module
  takes over that re-export; the line-57 re-export and the now-orphaned line-6 value imports are
  removed from `deacon-auto-resume.ts` (only `deacon.ts` imported them, verified by grep).
- **D4 — Constants are exported, not moved or duplicated** (see FR-2): three `const` declarations
  gain the `export` keyword; their comment blocks stay put.
- **D5 — The throwaway boot test runs with `OVERDECK_DISABLE_DEACON=1` and a temp
  `OVERDECK_HOME`.** ESM cycle failures surface at module-load time, before any runtime flag is
  consulted, so a deacon-disabled boot still proves the import graph loads under Node 22 strict
  ESM — while honoring the single-deacon invariant (never run a second deacon against
  `~/.overdeck`). The live `pan restart --health-timeout 120000` happens at deploy after merge
  (Definition of Done), not from this workspace.
