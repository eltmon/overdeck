# PAN-2882 PRD — GitLab merged/open-MR oracle for pipeline membership

**Issue:** [PAN-2882](https://github.com/eltmon/overdeck/issues/2882)
**Sibling (filed during planning):** [PAN-3215](https://github.com/eltmon/overdeck/issues/3215) — DoD gate verify-merged GitLab gap (explicit NonGoal here)
**Follow-up to:** [PAN-2877](https://github.com/eltmon/overdeck/issues/2877) (tracker/branch/spec lenses for GitLab projects), [PAN-2948](https://github.com/eltmon/overdeck/issues/2948) (polyrepo-aware producers)

## Glossary

- **Membership gather** — `gatherProjectLensSignals()` in `src/lib/pipeline-membership-gather.ts:499`. Builds the six durable lens signals (`IssueLensSignals`) per issue for one project. The only read door for pipeline membership.
- **Lens** — one durable signal: `hasOpenPr` (L1), `hasMergedPr` (L1-merged, the squash-merge oracle), `hasConventionBranch`/`branchUnmerged` (L2), `hasMergedBranchWork` (L2-work), `issueOpen` (L3), `phaseLabel` (L4), `hasXbriefSpec` (L6-spec).
- **Bucket** — the membership verdict from `resolvePipelineMembership()` in `src/lib/pipeline-membership.ts:99`: `in_flight`, `zombie_pr`, `post_merge_limbo`, `planned_backlog`, `clean_terminal`.
- **Convention branch** — `feature/<id-lowercase>` or `strike/<id-lowercase>`.
- **Forge** — GitHub or GitLab. Per-repo resolution: `RepoConfig.forge` → legacy `RepoConfig.remote` → project-level inference (`github_repo`/`gitlab_repo`) → `'github'`. Implemented by `getRepoForge` (`src/lib/project-repos.ts:52`, currently private).
- **Polyrepo** — a project whose `workspace.repos[]` lists several repos (mind-your-now: `fe`, `api`, `infra`, `docs`, `myn-skills`, `openclaw-plugin`). Each repo is a **separate GitLab project** (verified live 2026-07-28: `fe` → `eltmon/mind-your-now`, `api` → `eltmon/mind-your-now-backend`, `infra` → `eltmon/myn-infra`, `docs` → `eltmon/mind-your-now-docs`).
- **`glab`** — the GitLab CLI. Authenticated per host (`glab auth status` ✓ on this machine as `eltmon` on gitlab.com). When run with a cwd inside a repo, it resolves the GitLab project from the repo's git remote — this is how every existing GitLab call in the codebase works (`src/lib/forge.ts:176,291`).

## Problem

For GitLab projects the membership gather is forge-blind. Every forge-dependent lens in `gatherProjectLensSignals()` is gated on `project.github_repo` (`src/lib/pipeline-membership-gather.ts:511-516` computes `owner`/`repo` from `github_repo` only; lines 526-541, 577-585, and 609-655 all short-circuit without them). The merged-PR oracle `listMergedPullRequestHeadsBatched` (line 113) is GitHub-GraphQL-only, and the open-PR snapshot `listOpenPullRequestsSnapshot` (line 59) shells out to `gh`. So for a GitLab project `hasOpenPr` and `hasMergedPr` are **always false**.

Consequences observed live (operator-verified, flywheel RUN-73 tick 2, 2026-07-28):

| issue | membership said | GitLab truth |
| --- | --- | --- |
| MIN-896 | `planned_backlog` — "unmerged convention branch but no PR" | !89 (and !73) **merged** 2026-07-26 |
| MIN-908 | `post_merge_limbo` — "landed via a non-PR path" | !75 **merged** 2026-07-27 |
| MIN-864 | `planned_backlog` — "no PR" | !67 **open** |

Root mechanism for the false `planned_backlog` rows: GitLab squash-merge creates a new commit on `main`, so the stale branch tip is never an ancestor and the L2 git lens (`git for-each-ref --no-merged=main`, `snapshotBranchRefs` line 394) keeps reporting the branch unmerged. Only the L1-merged oracle can override that (`branchLive = hasConventionBranch && branchUnmerged && !hasMergedPr`, `src/lib/pipeline-membership.ts:102`) — and the oracle is dead for GitLab. The widened finding from the operator's RUN-73 comment: **open** MRs are equally invisible, so `in_flight` and `zombie_pr` are also unreachable for GitLab projects.

## Proposal

Add a glab-backed GitLab MR lens to the membership gather, wired through the same forge-capability split PAN-2877 established:

1. **New module `src/lib/gitlab-merge-requests.ts`** — two async functions shelling out to `glab` with `cwd` = repo path (project identity comes from the git remote; no new auth or host config, self-hosted GitLab works for free):
   - `listOpenGitLabMergeRequests(repoPath)` → all open MRs (`glab mr list --output json --per-page 100`, page loop until a short page), TTL-cached 30 s per repoPath, mirroring `listOpenPullRequestsSnapshot`.
   - `listGitLabMergedMergeRequestHeads(repoPath, heads)` → per-head exact queries (`glab mr list --merged --source-branch <head> --output json --per-page 100`, page loop), concurrency-limited, TTL-cached per (repoPath, head). Per-head exact queries — not a merged-MR snapshot — because an arbitrarily old squash-merge must never fall off a paginated snapshot and silently reintroduce the false-`planned_backlog` bug.
2. **Per-repo forge on `projectRepositories()`** — extend `ProjectRepository` with `forge`, resolved by exporting and reusing `getRepoForge` from `src/lib/project-repos.ts`. Repos resolving to `github` (e.g. MYN's `myn-skills`, `openclaw-plugin` with `remote: github`) are excluded from GitLab queries.
3. **Wire the open-MR lens** — when the project has no `github_repo` but ≥1 gitlab-forge repo, gather open MRs from every gitlab-forge repo and feed `hasOpenPr`/`headRefsByIssue` exactly as the GitHub rows do. This unlocks `in_flight` and `zombie_pr` for GitLab projects.
4. **Wire the merged-MR oracle** — same gate: for open candidates, query each gitlab-forge repo for the candidate heads (observed refs + both convention names, same formula as the GitHub path at lines 637-654) and union the results into `mergedPrIssues`. A branch merged in ANY gitlab-forge repo of the project counts (polyrepo merge-set semantics from the issue body).
5. **Docs** — update `docs/PIPELINE-MEMBERSHIP.md` so the capability-gating paragraph and read-doors section describe the glab-backed GitLab lenses.

When `github_repo` is set, behavior is byte-for-byte today's (GitHub path wins; recorded as autoDecision AD3).

### Error semantics

A glab failure in any queried repo throws, wrapped by the existing `withUnavailableReason('forge_unavailable', …)` — the membership surface then shows *unavailable* instead of silently wrong rows. This matches the GitHub path, which poisons the gather on any forge failure. No silent per-repo degradation.

### Deliberately NOT done (see NonGoals)

- No GitLab equivalent of `listIssueStatesBatched` — for GitLab projects, tracker state already comes complete from `listProjectTrackerIssues` (`includeClosed: true`), and branch-only candidates without tracker state resolve `issueOpen: false` → `clean_terminal`, which is the safe direction.
- No head-sha matching in the gather. The GitHub oracle also matches on branch name alone; the resolver pairs L1-merged with L2 so a branch that gained new commits after its MR still shows live work. Finer per-head-sha verdicts remain `merge-completeness.ts`'s job.
- DoD gate verify-merged path — filed as PAN-3215.

## Requirements

### Functional

- **FR-1** — A GitLab-backed project with a stale convention branch whose head has a merged MR yields `hasMergedPr: true` for that issue, so the resolver produces `post_merge_limbo` (open issue) or `clean_terminal` (closed issue), never `planned_backlog`.
- **FR-2** — A GitLab-backed project with an open MR on a convention branch yields `hasOpenPr: true`, so the resolver produces `in_flight` (open issue) or `zombie_pr` (closed issue).
- **FR-3** — Polyrepo union: an MR merged in ANY gitlab-forge repo of the project satisfies FR-1 for the issue, regardless of which repo the branch ref was observed in.
- **FR-4** — Repos whose resolved forge is `github` are never queried via glab; projects with `github_repo` set take the existing GitHub path unchanged.
- **FR-5** — Both GitLab lens functions are reachable through `PipelineMembershipGatherDeps` so unit tests inject fakes without shelling out (same pattern as the existing GitHub deps).
- **FR-6** — A glab failure in any queried repo surfaces as `PipelineMembershipUnavailableError` with reason `forge_unavailable`.

### Non-functional

- **NFR-1** — No `execSync` anywhere; all glab calls via `execFileAsync` with a 30 s timeout and bounded buffer (the gather runs inside the dashboard server process).
- **NFR-2** — Per-head glab fan-out is concurrency-limited (≤5) and TTL-cached (30 s) so a dashboard patrol cadence does not fork-bomb glab; the open-MR snapshot is cached per repo with the same 30 s TTL as the GitHub snapshot.
- **NFR-3** — `src/lib/pipeline-membership-gather.ts` must stay under the 1000-line ratchet ceiling (`scripts/lint-file-size.sh`); the glab I/O lives in the new module to keep the gather's growth to wiring only.
- **NFR-4** — Delay/cache tests use `vi.useFakeTimers()` where timers are involved (repo rule); no real `setTimeout` waits in tests.

export interface GitLabMergeRequestRow {
  iid?: number;
  title?: string;
  web_url?: string;
  state?: string;          // 'opened' | 'merged' | 'closed'
  source_branch: string;
  target_branch?: string;
  sha?: string;
  draft?: boolean;
}

export function listOpenGitLabMergeRequests(
  repoPath: string,
  run?: (args: string[], cwd: string) => Promise<string>,   // injectable, defaults to glab

export function listGitLabMergedMergeRequestHeads(
  repoPath: string,
  heads: string[],
  run?: ...,
): Promise<string[]>   // subset of `heads` having ≥1 merged MR

Caching via `createSettledTtlPromiseCache` (`src/lib/concurrency.ts:53`): open snapshot keyed by repoPath; merged heads keyed per (repoPath, head), both 30 s. ## Decisions (auto mode — recorded in `plan.autoDecisions[]`)

- **AD1 — glab CLI, not raw REST+token.** Every existing GitLab call in the codebase (`src/lib/forge.ts:176,291`, merge-completeness) shells `glab` with cwd in the repo; auth and host (incl. self-hosted) resolve from glab's per-host config and the git remote. A parallel REST client would add token plumbing and a second auth surface for zero gain. Verified live on this machine: `glab auth status` ✓ and both query shapes return correct data for MYN.
- **AD2 — per-head exact queries for merged MRs, not a full snapshot.** GitLab REST filters `source_branch` one at a time; a whole-list merged snapshot paginates unboundedly and any cap silently drops old merges — the exact failure this issue fixes. Per-head queries are exact forever; cost is bounded by open-candidate heads × gitlab repos, TTL-cached, concurrency-limited.
- **AD3 — GitHub wins when `github_repo` is set.** Mixed/exotic configs keep today's behavior; the GitLab path activates only when there is no `github_repo` and ≥1 gitlab-forge repo. Zero risk of regression for the GitHub projects (overdeck, krux).
- **AD4 — polyrepo union without merge-set resolution.** The gather is project-wide and cannot cheaply resolve per-issue merge sets; querying every gitlab-forge repo for every candidate head is a sound superset (a merged MR named `feature/<id>` in any project repo is evidence the issue's work landed).
- **AD5 — DoD gate out of scope.** The verify-merged path's GitHub-only oracle (`verifySquashMergedPrByBranch`, `src/lib/lifecycle/workflows.ts:715`) and monorepo-scoped git checks are a separate surface with per-issue (not batched) semantics — filed as PAN-3215.
- **AD6 — scope includes the open-MR lens.** The operator's RUN-73 tick-2 comment on the issue authoritatively widened scope: `L1_openPr` is as dead as the merged lens for GitLab (MIN-864), so this plan wires both.

## Hazards

- **H1 — glab absent or unauthenticated on a host.** The gather throws `forge_unavailable` and the membership surface shows unavailable rather than false rows. Mitigation: documented error semantics (FR-6); the dashboard already renders typed unavailability with a Retry affordance.
- **H2 — Existing test at `tests/unit/lib/pipeline-membership-gather.test.ts:541` shells no GitLab deps.** After WI-3/WI-4 the gather calls the new deps for that fixture; the test must inject them or it will attempt real glab calls. Mitigation: WI-3 carries the test update explicitly.
- **H3 — Fork-filter regression.** The line-578 filter currently drops everything when `owner`/`repo` are unset; restructuring it wrongly could re-admit GitHub fork PRs. Mitigation: WI-3 names the exact before/after condition and the existing fork test (`ignores foreign refs, specs, and fork pull requests`, line 624) must stay green unchanged.
- **H4 — Fan-out cost on large projects.** open-candidates × 2 convention heads × gitlab repos glab spawns per gather. Mitigation: NFR-2 (concurrency ≤5, 30 s TTL); MYN-scale verified at ~1 s per repo query.
- **H5 — `web_url` parsing for `headRepoFullName` on unusual self-hosted layouts.** Parsing between host and `/-/` is the documented GitLab URL contract; if it ever fails, the row still carries `headRefName` and the GitLab path does not fork-filter, so membership is unaffected.
