# PAN-2261 PRD: reduce bd lock contention under fleet load

## Glossary

- **bd**: the Beads CLI used for in-repo task tracking.
- **Ready bead**: an open Beads task eligible for the current issue's work agent.
- **Deacon patrol**: the Cloister watchdog loop that nudges, resumes, and remediates agents.
- **Start gate**: the `pan start` beads-required validation before a work agent launches.
- **JSONL fallback**: read-only parsing of `.beads/issues.jsonl` when a live `bd` command is locked or unavailable.
- **Transient bd failure**: lock-contention, timeout, or temporary resource failure recognized by `isTransientBdError()`.

## Requirements

- **FR-1**: Provide a shared async read helper that can answer ready/open bead questions from one `bd list --json` snapshot and fall back to `.beads/issues.jsonl`.
- **FR-2**: Deacon idle nudges must not run one `bd ready -l <issue>` process per running work agent.
- **FR-3**: Stuck remediation must not run one `bd ready -l <issue>` process per running work agent.
- **FR-4**: JSONL fallback must remain read-only and must not become a canonical Beads writer.
- **FR-5**: `pan start` must retry beads checks for materially longer than the shared three-attempt default before returning a retryable lock failure.
- **FR-6**: Retryable lock failure messages must expose attempt count and useful holder/caller diagnostics when available.
- **NFR-1**: Dashboard/server-reachable code must stay async and must not use `execSync`.
- **NFR-2**: Retry/backoff tests must use fake timers.
- **NFR-3**: Dashboard-spawn checks must keep a short acquisition timeout so HTTP paths fall back quickly instead of blocking behind the bd lock queue.

## Decisions

1. Keep `bd` as the canonical writer. Direct `.beads/issues.jsonl` parsing is a read-only fallback for readiness checks.
2. Add one shared ready-beads query in `src/lib/beads-query.ts` rather than duplicating label/status parsing in Deacon modules.
3. Batch Deacon reads by workspace/patrol and filter issue labels in memory.
4. Tune both `src/cli/commands/start.ts` and `src/lib/agents/spawn.ts` because both can block launch on beads.
5. Preserve short dashboard fallback behavior; only operator-invoked start paths should become materially patient.

## Non-Goals

- Do not replace Beads/Dolt internals.
- Do not remove the work-agent beads-required gate.
- Do not make dashboard HTTP handlers wait behind long bd lock queues.
- Do not unskip the existing parity-based concurrent retry test without deterministic failure injection.
- Do not add browser or Playwright verification for this backend/CLI issue.
