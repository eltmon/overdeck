# PAN-3230 — orphan-proposed-reconciler reads legacy `<project>/.pan/specs`; blind to migrated projects since PAN-2541

**Issue:** https://github.com/eltmon/overdeck/issues/3230
**Author:** planning agent (claude-fable-5), auto mode, 2026-07-28

## Glossary

- **State worktree / `overdeck-state`** — the same-repo orphan branch holding a migrated project's permanent pipeline state, checked out on disk at `${OVERDECK_HOME}/state/<projectKey>/` with top-level `specs/`, `drafts/`, `continues/`, `records/` directories (PAN-2541).
- **Migrated project** — a project whose state worktree contains a valid `migration-complete.json` marker (validated by `validMarker()` in `src/lib/state-read-home.ts:13-20`). Unmigrated projects keep using the legacy in-repo `<projectRoot>/.pan/` layout.
- **Read door / path authority** — `getProjectPanPaths(projectRoot)` in `src/lib/pan-dir/paths.ts:22-35`. It resolves `{panDir, specsDir, draftsDir, continuesDir}` via `resolveStateReadHomeSync()`: the state worktree root for a migrated project, `<legacyRoot>/.pan/` otherwise. It is a leaf module importable from anywhere without cycles.
- **Orphan-proposed reconciler** — `src/lib/cloister/orphan-proposed-reconciler.ts`, the post-promotion safety net that finds promoted specs with `plan.status: 'proposed'` and no live agent, and spawns a work agent for them (subject to the fail-closed pickup gate). Runs every deacon patrol cycle and reactively.
- **Pickup gate** — `decideAutonomousWorkDispatch` (`src/lib/cloister/autonomous-work-dispatch.ts`), the fail-closed predicate requiring a `released` label, `flywheel.auto_pickup_backlog`, order-book membership, or persisted planning consent before the reconciler may spawn work (see `docs/FLYWHEEL.md:145`).
- **Proposed spec** — an xBRIEF JSON file whose `plan.status` is `"proposed"`, meaning planning finalized but work never started.

## Problem

`orphan-proposed-reconciler.ts` derives the specs directory as `join(projectPath, '.pan', 'specs')` at two sites — `findSpecPathForIssue` (line 123) and `findOrphanProposedSpecsForReconciler` (line 216) — instead of `getProjectPanPaths(projectPath).specsDir`. For a migrated project the legacy directory is frozen at its pre-cutover contents, so the reconciler has enumerated zero candidates since the 2026-07-10 migration. Verified on this machine: `~/.overdeck/state/panopticon-cli/specs` holds 418 specs (79 `proposed`), all invisible to the reconciler.

This is the same bug class as PAN-3165 (fixed `xbrief/xbrief-index.ts` the same way). A sweep of the tree (`grep -rn "'.pan', 'specs'\|'.pan', 'drafts'"`) at planning time found the identical hardcoded join in these additional live callers:

| --- | --- |
| `src/lib/cloister/orphan-proposed-reconciler.ts:123`, `:216` | The reconciler itself — zero orphan candidates (this issue's headline). |
| `src/cli/commands/doctor.ts:611` | `pan doctor` reports zero orphan proposed specs. |
| `src/lib/cloister/flywheel.ts:186` (specs), `:211` (drafts) | Flywheel planned-issue detection and declared file footprints see nothing; PRD detection fails. |
| `src/lib/backlog/lookups.ts:39` | Backlog `isPlanned` returns false for every planned issue. |

**Deliberately dual-path / legacy-aware sites that must NOT change** (they exist to serve unmigrated projects or historical data and are the guard's allowlist): `src/lib/pan-dir/**` (the authority itself), `src/lib/state-read-home.ts`, `src/lib/state-plane.ts` (branch-content policy constants), `src/lib/pan-dir/auto-commit.ts` (migration-aware `ownedPaths` branches), `src/lib/orders/validate.ts` (probes both roots by design), `src/lib/cloister/merge-agent.ts` (`SYNC_MAIN_MAIN_PREFERRED_PATHS` conflict preferences), `src/lib/overdeck/planning-promotion.ts` (migration-aware staging), `src/cli/commands/admin/state-migrate.ts` (migration tooling), prose in comments/message strings (e.g. `verification-runner.ts:722`).

No existing lint guard covers this: `scripts/lint-state-writes.sh` polices *writers* of the spec surface, not path derivation. That is why PAN-3165's fix didn't prevent this recurrence.

## Decisions (made in this doc)

- **D1 — fix all live callers in this issue, not siblings.** Each fix is a one-to-three-line substitution of an established pattern; splitting eight one-liners into sibling issues costs more pipeline overhead than it buys. The projected surface is ~13 files across exactly 6 subsystems, inside the finalize caps.
- **D2 — include the drafts joins in the files already being touched.** Drafts detection fails identically for migrated projects, the read door exposes `draftsDir` alongside `specsDir`, and a guard that ignores drafts would be half a guard.
- **D3 — include the write-side `auto-synthesize.ts` fix.** It produces the same invisible-spec symptom and breaks `--plan skip` auto-start outright. The fix is directory substitution only; persistence to git stays owned by the state-plane drift reconciler (`reconcileStatePlaneDrift` in `src/lib/pan-dir/auto-commit.ts`) — do NOT add manual git operations.
- **D4 — guard matches the code shape, not prose.** `scripts/lint-state-paths.sh` greps `src/` for the two-token join shape (`'.pan', 'specs'` / `'.pan', 'drafts'`, single or double quotes, plus the template/string forms `'.pan/specs` and `'.pan/drafts`) with a file allowlist for the deliberate sites listed above. Prose mentions in comments don't use the join shape and template-literal/string forms in allowlisted files are permitted.
- **D5 — hoist `getProjectPanPaths` calls out of per-issue loops.** The resolver does sync FS reads (marker parse). Call it once per project/scan, never per issue id inside a closure (relevant at `flywheel.ts:211`, where `isPlanned`-style closures run per id).
- **D6 — no behavior change for unmigrated projects.** For a project with no valid marker, `getProjectPanPaths` resolves `<legacyRoot>/.pan/specs` — the same directory as today. All existing tests that build temp projects without a marker must stay green unmodified.
