# PAN-2581 — Phase-aware idleness: never treat a warm agent on a pipeline-owned issue as stalled

**Issue:** https://github.com/eltmon/overdeck/issues/2581 (closed after part 1; this PRD documents the full scope including the residual poke path)
**Verified against codebase:** 2026-07-12 on `main` (post `cb2199bf1c`)

---

## Glossary

- **Warm-idle** — an agent whose session is alive at its prompt with its role’s current obligation complete; the INTENDED state under the warm-by-default lifecycle (PAN-2579, `docs/ROLES.md` §Session lifecycle).
- **Pipeline-owned issue** — an issue whose next step belongs to the pipeline, not the work agent: review in flight (`reviewStatus: reviewing`), review passed awaiting test, or an un-serviced durable review request (`reviewRequestedAt` set, review pending). Predicate: `shouldSkipReviewStatus()` at `src/lib/cloister/stuck-remediation.ts:35` (exported).
- **Stuck-remediation** — the deacon’s staged escalation for idle agents (`stuck-remediation.ts`, log line anchor `` `[deacon] stuck-remediation stage=${stage}` `` at `:160`).
- **Health-check poke loop** — the SECOND, independent idleness consumer: Cloister’s health monitor (`src/lib/cloister/service.ts:1118` `getAgentsNeedingAttention` → `:1139/:1147 pokeAgent` → `pokeAgentWithEscalation` `:1345`). Sends “Hey, I noticed you haven’t made progress…”; after 5 no-progress pokes it PAUSES the agent: `` setAgentPausedSync(agentId, `needs-you: idle-alive — …`) `` at `:1360`.
- **Owed rework** — the opposite of pipeline-owned: review blocked/failed, verification failed, or tests failed with nothing merged — the work agent owes a fix. Predicate: `hasPendingRework()` (`stuck-remediation.ts:56`). Remediation MUST keep firing for these (PAN-2519 wedge path).

## Problem

Both idleness consumers treated “status=running + no recent activity” as a stall with no knowledge of the issue phase. On PAN-399 (2026-07-11) stage-1 pokes every ~21 min told a COMPLETED work agent to re-run `pan done`; each re-run re-journaled `reviewRequestedAt`, re-armed review, clobbered landed verdicts, and burned ~$63 ($28.89 on a $10 per-agent cap). Separately, the health-check loop’s idle-alive escalation pauses warm agents (MIN-865 shape: `needs-you: idle-alive — no observable progress across 10 pokes`), manufacturing the paused-delivery-target deadlock PAN-2461’s resurrection ladder then has to undo.

## Requirements

- **FR-1 (Remediation phase gate)** — stuck-remediation stages 1–3 skip work agents whose issue is pipeline-owned. **LANDED** in `cb2199bf1c`: `shouldSkipReviewStatus` extended (`stuck-remediation.ts:35-48`); locked by `tests/unit/lib/cloister/stuck-remediation-phase-gate.test.ts` (6 cases).
- **FR-2 (Health-check poke gate — residual)** — the health-check poke loop applies the same phase gate before poking or idle-alive-pausing a `work`, `review`, or `test` agent. Review/test agents are included because a warm-idle reviewer post-verdict is `status=running` too and would otherwise be poked into spurious re-runs; a genuinely stalled mid-review parent is now covered by the PAN-2584 45-minute liveness deadline, not pokes.
- **FR-3 (Rework keeps remediation)** — agents with owed rework (`hasPendingRework`) keep the full escalation ladder (unchanged; PAN-2519).
- **NFR-1 (One predicate)** — both consumers share `shouldSkipReviewStatus`; no second phase predicate may be written (drift risk).
- **NFR-2 (Health recording unaffected)** — the gate suppresses ACTIONS (poke/pause), never health measurement or event recording.

```ts
// stuck-remediation.ts (new, next to shouldSkipReviewStatus)
export function shouldSkipIdlePokeForAgent(role: string | undefined, status: ReviewStatus | null): boolean {
  if (role !== 'work' && role !== 'review' && role !== 'test') return false;
  return shouldSkipReviewStatus(status);
}
```

## Decisions

1. Review/test roles are inside the FR-2 gate (rationale in FR-2); plan/strike/flywheel are outside — their idleness semantics are unrelated.
2. The gate lives in `stuck-remediation.ts` beside the predicate it wraps, not in `service.ts` (NFR-1).
3. No config knob. Phase-gating is correctness, not preference.
