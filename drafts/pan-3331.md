## Glossary

- **Quick-action band** — a full-width, fixed-height strip inserted between WorkspaceView's header bar and its panel group, visible for every workspace kind, holding three elements: the git sync card, the run card, and the open-in menu.
- **Git sync card** — shows branch, dirty-file count, ahead/behind vs the branch's upstream, expands to list recent remote commits, and offers a one-click **Pull** (fast-forward only).
- **Upstream** — the checked-out branch's own tracking ref (`@{u}`), falling back to `origin/HEAD` when no upstream is set. NOT unconditionally `origin/HEAD` (see verified state #1 for why this distinction matters).
- **Run card** — launches the workspace's run command in a new tmux session in the workspace path and attaches its terminal in the view. The command defaults from project service config and is overridable per workspace.
- **Memory feed** — WorkspaceView's memory panel (status headline + observations). The band sits above it, not inside it.
- **Registry / two doors** — the PAN-1990 workspace tables behind `src/lib/workspaces/resolver.ts` (reads) and `writer.ts` (writes); `scripts/guard-workspace-doors.sh` enforces in lint.
- **Mutation guard** — `rejectUnsafeDashboardMutationRequest` (`src/dashboard/server/routes/dashboard-auth.ts:149`), applied by every registry mutation route.

## Motivation

A workspace view should answer three operational questions instantly: is my checkout current with its remote, how do I run this thing, and how do I open it in my other tools. Today WorkspaceView answers none of them — it renders header → panels with no action surface, git ahead/behind exists only in the issue-workspace data route, nothing in the codebase performs a plain fast-forward pull, and the terminals API discards run commands. The band turns "remote moved while you weren't looking" from a class of incident (stale checkouts caused three separate failures on 2026-07-29) into a glanceable card with a safe one-click fix.

## Decisions

- **D-1: One git-state module, upstream-correct.** New `src/lib/workspaces/git-state.ts` exporting `getWorkspaceGitState(path, {fetch?: boolean}): Promise<WorkspaceGitState>` — `{branch, detached, dirtyFiles, ahead, behind, hasUpstream, upstreamRef, recentRemoteCommits: [{sha, subject, author, date}], fetchedAt}`. Ahead/behind via `git rev-list --left-right --count HEAD...@{u}` with fallback to `origin/HEAD` when no upstream (and `hasUpstream:false` so the UI can say "no upstream"). Recent remote commits: `git log HEAD..@{u} --format=... -n 10`. All `execFileAsync` argument vectors.
- **D-2: The card is honest — fetch before judge, but rate-limited.** `fetch: true` runs `git fetch <remote> <branch>` first. The route holds an in-memory per-path last-fetch map; fetches within 30s of the previous are skipped (state still recomputed). Frontend requests `fetch=1` on mount and on the manual refresh affordance; the 30s poll re-reads without forcing fetch. Rate-limit tests use fake timers.
- **D-3: Pull is fast-forward only, and only where it's safe.** New `pullWorkspaceFastForward(path)` in the same module: refuse when dirty (`git status --porcelain` non-empty), when a git operation is in flight (reuse `ensureSyncGitQuiescent` from `src/lib/cloister/sync-main-git.ts:139`), or when not fast-forwardable — each refusal returns a typed reason the UI renders verbatim. Executes `git pull --ff-only <remote> <branch>`. **Issue-kind workspaces do not use this**: their Pull affordance delegates to the existing `POST /api/issues/:issueId/sync-main` (existing semantics, no-loss); the band's card still *displays* state for them from D-1.
- **D-4: Run command storage is a real column.** `run_command text` (nullable) added to `workspaces` in `ensureWorkspaceTablesSync` (verified state #6 rules out `layout_config`). Writer: `setWorkspaceRunCommand(id, command: string | null)` beside `updateWorkspaceLayout` (`writer.ts:122`); resolver surfaces `runCommand` on `WorkspaceRow`. Default when null: the project's first `services[].start_command` (verified state #7), shown as a placeholder the operator can accept or override; multiple services render as a picker in the card's expander.
- **D-5: Run spawns a real tmux session via the registry route, not a widened terminals API.** `POST /api/workspace-registry/:id/run` resolves the workspace, picks `runCommand ?? default`, spawns `createSession('ws-run-<8charid>', workspace.path, command, {env})` (tmux lib already supports initialCommand — verified state #4), records nothing durable, returns `{sessionName, command}`. The frontend mounts `<XTerminal sessionName>` in the terminal panel area (for main/scratch, which today show "No active agent terminal", the run session becomes the panel's content; for issue kind it renders alongside via the panel's existing structure). A Stop affordance calls the existing `DELETE /api/terminals/:name`. Only one live run session per workspace: a second Run while one is alive re-focuses it; the card offers Restart (kill + spawn).
- **D-6: Open-in is minimal and config-gated.** Menu entries: **Reveal in file manager** (darwin `open <path>`, linux `xdg-open`, win32 `explorer` — platform branch copied from `browser.ts:26-35`, via a new `openPath(path)` beside `openBrowser`) always present; **Open in editor** present only when the new optional config `ui.open_in_editor_command` (in `~/.overdeck/config.yaml`, e.g. `cursor {path}` or `code {path}`) is set — the command template's `{path}` is substituted and spawned `execFileAsync`-style after splitting template tokens (no shell string interpolation). Served by `POST /api/workspace-registry/:id/open` body `{target: 'file-manager' | 'editor'}`, mutation-guarded (it spawns processes).
- **D-7: Band placement and visibility.** Inserted after the header (verified state #5), `shrink-0`, rendered for every kind. Cards degrade honestly: non-git workspace (`isGitRepository=false`) hides the git card; detached HEAD shows a warning chip instead of Pull; no-upstream shows "no upstream" with the fallback comparison labeled.
- **D-8: Cadence.** One `useQuery` per open WorkspaceView: `['workspace-registry', id, 'git']`, `refetchInterval: 30000`, `staleTime: 25000`, initial request with `fetch=1`. No polling when the view is closed (query unmounts). This bounds server git work to the workspace actually on screen.
- **D-9: No model calls; no new dialog frameworks; style guide binds** (mono for branch/path/shas, one colored signal per card — the behind-count dot may use the amber human-attention signal; Pull is the card's single primary action; forbidden utilities per the guide).
- **D-10: Keyboard affordance.** The palette gains a "Run workspace command" action (workspaces + actions scopes) that triggers D-5 for the active workspace. No global keybinding in this issue (the dashboard has no keybinding registry; out of scope).

## Intersecting repo rules (restated for the executor)

- **Two doors** for all registry access; new column only via `ensureWorkspaceTablesSync`; guard script must stay green.
- **No `execSync`** server-reachable; argument-vector spawns only; never interpolate names/paths into shell strings.
- **Async tmux only** (`createSession`/`killSession` from `src/lib/tmux.ts`, never `*Sync` variants).
- **Fake timers** for rate-limit/poll tests.
- **Mutation guard** on every new POST/PUT; GET unguarded like siblings.
- **Style guide** (`sync-sources/dev-skills/pan-style-guide/SKILL.md`): mono for branch/sha/path values, `font-medium` max, badge tint formula, one colored signal per card, semantic tokens only.
- **Playwright verification** by the implementer; never ask the operator to eyeball.
- **Worktree discipline / push-per-item** as standard.

All ten "Verified current state" claims still hold. Re-verification surfaced two implementation nuances the executor must know:

1. **Async `createSession` performs no initialCommand validation.** The Effect-based `createSession` (`src/lib/tmux.ts:1053`) passes `initialCommand` straight into `buildNewSessionArgs`, unlike the deprecated `createSessionSync` (`:643`) which special-cases backticks/newlines/>500-char commands via a temp script. Decision: the run route (`POST /api/workspace-registry/:id/run`) validates the resolved command — reject with 400 when it contains a newline or backtick or exceeds 500 characters — instead of adding temp-script complexity to the async tmux path.
2. **`ui.*` is a net-new config section.** No `ui` key exists in the config-yaml schema (`src/lib/config-yaml/schema.ts`); the existing "UI theme" is a separate file (`src/lib/ui-theme.ts`, `~/.overdeck/ui-theme.json`), not yaml config. Decision: WI-4 adds an optional `ui?: { open_in_editor_command?: string }` section to the schema plus a `getOpenInEditorCommand()` accessor in `src/lib/config.ts` following the `getConversationsConfigSync`/Effect-variant pattern (`src/lib/config.ts:496+`), rather than piggybacking on `ui-theme.json`.

`openBrowser` (`src/lib/browser.ts:26`) is Effect-based (`Effect.Effect<void, ProcessSpawnError, ChildProcessSpawner>`); the new `openPath` follows the same Effect shape and platform branching.
