# PAN-3655 — Unify issue Conversation/Terminal switching with the shared segmented selector

## Glossary

- **Segmented selector / view toggle** — the enclosed `Conversation | Terminal`
  control rendered with the `viewToggle` / `viewToggleBtn` / `viewToggleBtnActive`
  CSS-module classes defined in
  `src/dashboard/frontend/src/components/CommandDeck/styles/command-deck.module.css:3425-3457`.
- **Issue detail** — `IssueDetail`
  (`src/dashboard/frontend/src/components/issue-detail/IssueDetail.tsx`), the ONE
  issue-detail component rendered by the drawer (density `drawer`), the cockpit
  route (density `page`), and the compact inline expansion (density `rail`).
- **Cockpit** — `IssueMissionControl`
  (`src/dashboard/frontend/src/components/Stage/cockpit/IssueMissionControl.tsx`),
  the six-tab issue cockpit (Overview, Session, Plan, Changes, Activity,
  Discussion). Its **Session** tab embeds `IssueDetail` at density `page`.
- **Session pane** — `DrawerAgentSession`
  (`src/dashboard/frontend/src/components/drawer/DrawerAgentSession.tsx`), the
  component that renders either the selected agent's transcript
  (`ConversationPanel`) or its live tmux terminal (`XTerminal`) behind a
  `view: 'conversation' | 'terminal'` prop.
- **Drawer tab state** — `drawer.tab` in the Zustand store
  (`src/dashboard/frontend/src/lib/store.ts:100`), a free string synced to the
  URL as `?issue=<id>&tab=<tab>` by `replaceDrawerUrl` (store.ts:149-161).
- **Ended agent** — an agent whose `status` is `stopped`, `dead`, or `failed`;
  `isEndedAgent()` in `src/dashboard/frontend/src/lib/agentConversation.ts:28`.
  An ended agent has no attachable tmux session.
- **No-loss inventory** — the PAN-2499 surface lock:
  `ISSUE_VIEW_INVENTORY` in
  `src/dashboard/frontend/src/components/issue-view/inventory.ts`, gated by
  `tests/unit/dashboard/frontend/issue-view-no-loss.test.ts`.

## Problem

Issue detail presents **Conversation** and **Terminal** as two peer top-level
tabs (`ISSUE_DETAIL_TABS` at `IssueDetail.tsx:49-58`), and the cockpit Session
tab renders a bespoke sub-tab strip (`IssueMissionControl.tsx:805-827`) styled
with raw Tailwind classes. Both contradict the established dashboard pattern:
Conversation and Terminal are two view modes of *one* selected agent session,
and the dashboard already has an enclosed segmented selector for exactly this —
used by `ConversationPanel.tsx:720-735` and `FlywheelConversationPane.tsx:294-313`.
The issue surfaces copy neither the control nor its semantics, and today the
selector markup itself is copy-pasted between ConversationPanel and Flywheel
with no shared component.

## Proposal

Treat Conversation and Terminal as view modes of one session surface everywhere:

1. **Extract one reusable `ViewToggle` component** at
   `src/dashboard/frontend/src/components/shared/ViewToggle.tsx` (the `shared/`
   directory already hosts cross-surface primitives: `ContextMenu.tsx`,
   `Tooltip.tsx`). It renders the canonical `viewToggle` classes from
   `command-deck.module.css` with `role="tablist"`, one `role="tab"` button per
   option, `aria-selected`, and per-option `disabled` + explanatory
   `title`/`aria-label`.
2. **Adopt it in the two source-of-truth surfaces** (`ConversationPanel`,
   `FlywheelConversationPane`) so four surfaces share one implementation instead
   of three copies plus a fourth (requirement 7). Visual output is unchanged.
3. **Put the selector in the session pane toolbar.** `DrawerAgentSession` gains
   an optional `onChangeView` prop; when present it renders the `ViewToggle`
   (Conversation | Terminal) in its existing toolbar row next to the agent
   picker. The Terminal segment is disabled when there is no selected agent or
   the agent is ended, with an accessible explanation.
4. **Consolidate the drawer/page tab strip.** `ISSUE_DETAIL_TABS` drops the
   `conversation` and `terminal` entries and gains one
   `{ id: 'session', label: 'Session' }` entry (label matches the cockpit's
   existing Session tab). The store's tab *values* `'conversation'` and
   `'terminal'` remain valid addressable ids — the displayed Session tab is
   active when `tab ∈ {conversation, terminal, session}` — so legacy
   `?tab=terminal` deep links, `openIssue()`'s `'conversation'` default, and
   stored tab state all keep working with zero migration (requirement 5).
5. **Delete the cockpit's bespoke sub-tab strip.** The cockpit Session tab keeps
   driving `IssueDetail` via `issueDetailTabFor` (`'conversation' | 'terminal'`);
   the selector inside the embedded session pane now performs the switch through
   the existing `onSelectTab` → `resolveTabSelection` → `selectTab('session',
   subView)` path. No cockpit state changes.

Agent selection already survives the switch: `IssueDetail` owns
`selectedAgentId` (`IssueDetail.tsx:284-290`) and passes it to both bodies, and
the cockpit's `activeSubView` never touches session identity.

## Decisions (auto mode — recorded, not asked)

- **D1 — Shared component in `components/shared/`, CSS stays in
  `command-deck.module.css`.** The `viewToggle` classes are the visual source of
  truth and are imported by four components from that module today; moving the
  CSS would churn every importer for no behavioral gain. The reusable unit is
  the component, not the stylesheet.
- **D2 — Tab values `'conversation'`/`'terminal'` are preserved; only the
  displayed strip consolidates.** This satisfies the legacy-navigation
  requirement for free (store tab is a free string; `?tab=terminal` and the
  `openIssue('PAN-x')` default already use these values) and keeps
  `IssueDetailTabId` flowing through the cockpit's existing `LEGACY_TAB_MAP`.
- **D3 — Selector placement is the `DrawerAgentSession` toolbar**, the one
  integration point both issue shells already share, rather than inside
  `ConversationPanel`'s header (hidden when embedded) or a new header row in
  `IssueDetail` (a third layout to maintain).
- **D4 — Consolidated tab label is "Session"** (id `session`), matching the
  cockpit's existing Session tab and docs/ISSUE-VIEW.md vocabulary.
- **D5 — Availability signal for Terminal is `!isEndedAgent(agent)`** — the same
  rule the terminal body already uses (`DrawerAgentSession.tsx:214`). No new
  liveness probe.
- **D6 — `AgentOutputPanel`, `AgentSection`, and `SessionPanel` keep their
  current toggles.** They switch different option sets (activity/terminal,
  transcript/conversation/terminal, conversation/terminal/findings) with
  different styles; folding them in is out of scope (see NonGoals).

## Before / after sketches

**Shared component (new file `components/shared/ViewToggle.tsx`):**

```tsx
import styles from '../CommandDeck/styles/command-deck.module.css';

export interface ViewToggleOption {
  id: string;
  label: string;
  disabled?: boolean;
  /** Why the option is disabled — surfaced as title + aria-label. */
  disabledReason?: string;
}

export function ViewToggle({ options, value, onChange, ariaLabel }: {
  options: readonly ViewToggleOption[];
  value: string;
  onChange: (id: string) => void;
  ariaLabel: string;
}) {
  return (
    <div className={styles.viewToggle} role="tablist" aria-label={ariaLabel}>
      {options.map((option) => (
        <button
          key={option.id}
          type="button"
          role="tab"
          aria-selected={value === option.id}
          disabled={option.disabled}
          title={option.disabled ? option.disabledReason : undefined}
          aria-label={option.disabled ? `${option.label} — ${option.disabledReason}` : option.label}
          className={`${styles.viewToggleBtn} ${value === option.id ? styles.viewToggleBtnActive : ''}`}
          onClick={() => onChange(option.id)}
        >
          {option.label}
        </button>
      ))}
    </div>
  );
}
```

## Requirements

### Functional

- **FR-1** — One reusable `ViewToggle` component
  (`components/shared/ViewToggle.tsx`) renders the canonical enclosed segmented
  selector with `role="tablist"` / `role="tab"` / `aria-selected` semantics and
  per-option disabled state carrying an accessible explanation.
- **FR-2** — `IssueDetail`'s tab strip replaces the peer Conversation and
  Terminal tabs with one **Session** tab; the session body hosts the shared
  selector and switches between transcript and live terminal in one click.
- **FR-3** — The cockpit Session tab uses the same selector (via the embedded
  `IssueDetail` session pane); the bespoke Tailwind sub-tab strip at
  `IssueMissionControl.tsx:805-827` is deleted.
- **FR-4** — Switching Conversation ⇄ Terminal never changes the selected
  agent, including swarm/specialist selections.
- **FR-5** — The Terminal segment is enabled exactly when the selected agent is
  not ended (`!isEndedAgent`); otherwise it is disabled with an explanatory
  `title` and `aria-label`, and Conversation remains usable.
- **FR-6** — Legacy navigation resolves: `?tab=terminal` / `?tab=conversation`
  URLs and stored tab state open the consolidated session surface in the
  matching mode, in both the drawer and the cockpit.
- **FR-7** — `ConversationPanel` and `FlywheelConversationPane` render the
  shared `ViewToggle` instead of inline markup, with unchanged visuals and
  behavior (ConversationPanel still hides the toggle when there is no live
  session).
- **FR-8** — Every other issue section and affordance keeps a home: Overview,
  Plan map, Tasks, Activity, Files, Artifacts, the agent picker, transcript
  composer, branch chip, tools toggle, status rail, and cockpit-only surfaces.

### Non-functional

- **NFR-1** — A no-loss audit test enumerates the eight old
  `ISSUE_DETAIL_TABS` ids and proves each resolves to a destination after
  consolidation (`conversation` → Session/conversation mode, `terminal` →
  Session/terminal mode, the rest unchanged tab ids).
- **NFR-2** — Focused tests cover drawer/page issue detail, cockpit, agent
  persistence across both switch directions, terminal availability, and legacy
  navigation.
- **NFR-3** — The PAN-2499 no-loss inventory and its locked test stay green;
  the cockpit `Session tab` entry's relocation surface
  (`'Conversation / Files / Terminal tabs'`) remains accurate.
- **NFR-4** — Visual parity: the selector in issue surfaces is pixel-identical
  to the conversation/Flywheel control because all four import the same
  component and CSS module.

## NonGoals

- Folding `AgentOutputPanel` (activity/terminal), `AgentSection`
  (transcript/conversation/terminal), or `SessionPanel`
  (conversation/terminal/findings, different `sessionPanelToggleBtn` styles)
  into the shared component. Different option sets and, for SessionPanel,
  different styling.
- Moving or restyling the `viewToggle` CSS; any visual redesign of the selector.
- Changing terminal attach mechanics, `XTerminal`, or the `/ws/terminal`
  protocol.
- Changing the cockpit's Plan / Changes / Activity sub-tab strips.
- Renaming the store's `drawer.tab` values or migrating stored URLs.

## Acceptance criteria

1. Given an issue with a live agent in the drawer, when the operator clicks
   **Terminal** in the session pane selector, the body renders the live
   terminal; clicking **Conversation** renders the transcript again — and the
   agent picker shows the same agent throughout (FR-2, FR-4).
2. The issue-surface selector renders the same `viewToggle` markup and classes
   as the conversation/Flywheel control, with `role="tablist"`, `role="tab"`,
   and `aria-selected` on the active segment (FR-1, NFR-4).
3. Given the selected agent is ended, the Terminal segment renders `disabled`
   with an explanatory `title`/`aria-label` and Conversation still switches
   normally (FR-5).
4. Given `/?issue=PAN-1&tab=terminal`, the drawer opens the session surface in
   terminal mode; given a cockpit URL with `?tab=terminal`, the cockpit opens
   Session/terminal (FR-6).
5. `tests/unit/dashboard/frontend/issue-view-no-loss.test.ts` passes unchanged,
   and the new audit test enumerating the eight old `ISSUE_DETAIL_TABS` ids
   passes (NFR-1, NFR-3).
6. `npm --prefix ./src/dashboard/frontend run test` passes for
   `ViewToggle.test.tsx`, `IssueDetail.test.tsx`, `IssueDrawer.test.tsx`,
   `DrawerAgentSession.test.tsx`, `IssueMissionControl.test.tsx`, and
   `chat/__tests__/ConversationPanel.test.tsx` (NFR-2).
