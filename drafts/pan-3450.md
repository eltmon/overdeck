# PAN-3450: `pan sync` never prunes removed skills/rules from cache and harness dirs

## Glossary

- **Bundle / `sync-sources/`** — the skills, dev-skills, agents, and rules shipped inside the
  Overdeck repo/package. `SYNC_SOURCES` in `src/lib/paths.ts:234` points at it.
- **Cache** — `~/.overdeck/skills/`, `~/.overdeck/agent-definitions/`, `~/.overdeck/rules/`
  (`SKILLS_DIR`, `CACHE_AGENTS_DIR`, `CACHE_RULES_DIR` in `src/lib/paths.ts:249-251`). A local
  mirror of the bundle produced by `refreshCacheSync()`.
- **Cache manifest** — `~/.overdeck/.manifest.json` (`CACHE_MANIFEST`, `src/lib/paths.ts:252`).
  Rebuilt wholesale from cache contents at the end of every `refreshCacheSync()`.
- **Target** — a directory the cache is distributed to: `~/.claude/` (via `executeSyncSync`),
  `~/.agents/skills/` (via `executeAgentSkillsSync`), and each workspace's `.claude/` (via
  `mergeSkillsIntoWorkspaceSync`).
- **Target manifest** — `.overdeck-manifest.json` in the target root. Maps relative path →
  `{ hash, source, installed_at }`. `source: 'overdeck'` means Overdeck placed the file and may
  manage it; any other value (or absence) means user-owned — never touch.
- **Stale entry** — a file present in cache or target (and manifest) whose source no longer
  exists in the bundle (skill/rule/agent removed from `sync-sources/`).
- **Prune** — delete a stale entry and drop its manifest entry.

## Problem

`pan sync` copies sources into its caches and harness dirs but never deletes entries whose
source was removed. Three stages, all copy-only:

1. **Cache refresh** — `refreshCacheSync()` (`src/lib/sync.ts:228`) copies every bundled
   skill/agent/rule into the cache. Nothing removes cache files whose source was deleted.
   `copyDirectoryRecursive()` (`src/lib/sync.ts:199`) also does `mkdirSync(dest)` up front
   (line 202), so an *empty* source dir (git does not track dirs — a `git rm` of a skill's
   files leaves the empty tree on disk) is faithfully recreated as an empty dir in the cache.
2. **Claude target** — `executeSyncSync()` (`src/lib/sync.ts:421`) walks the cache and copies
   per manifest comparison (`src/lib/sync.ts:436-507`). Removed-from-bundle files stay in the
   cache (problem 1), so they are re-copied to `~/.claude/` forever. Same shape in
   `executeAgentSkillsSync()` (`src/lib/harness-skill-sync.ts:46`) for `~/.agents/skills/`.
3. **Workspace target** — `mergeSkillsIntoWorkspaceSync()` (`src/lib/skills-merge.ts:67`)
   copies cache → `workspace/.claude/{skills,agents,rules}` (sources array at
   `src/lib/skills-merge.ts:87-91`). Same copy-only pattern.

Observed consequence (issue body): the beads removal (PAN-2648) deleted skills/rules from the
repo, yet weeks later agents were still being instructed to use `bd`, because
`beads-dolt-authority.md` and the `beads*` skills survived in every cache and target and were
re-provisioned on every sync. Manual cleanup was required on 2026-08-01.

## Proposal

Make pruning **manifest-driven and provenance-checked** — the exact mechanism the issue
proposes. One shared helper in `src/lib/manifest.ts`, wired into all four copy stages:

**For every manifest entry with `source === 'overdeck'` whose relative path is no longer in
the current source set:**

- target file missing → drop the manifest entry (housekeeping).
- target file present and its hash **matches** the manifest hash → the file is unmodified
  Overdeck-placed content: delete it, drop the entry, and remove now-empty ancestor
  directories up to (but not including) the target base.
- target file present but hash **differs** → the user modified it: keep the file, drop the
  manifest entry (it becomes user-owned, matching its real state), and report it once in a
  `keptModified` list.

Files with no manifest entry, or a non-`'overdeck'` source, are **never** touched. Deletion
only ever applies to content provably placed by Overdeck and never modified — the same trust
rule `compareFileToManifest` already uses for updates.

The **source set** each stage prunes against:

| Stage | Function | Target base | Source set |
|---|---|---|---|
| Cache | `refreshCacheSync()` | `~/.overdeck/` | files under `SYNC_SOURCES.{skills,dev-skills,agents,rules}` mapped to `skills/`, `agent-definitions/`, `rules/` |
| Claude | `executeSyncSync()` | `~/.claude/` | cache files (`skills/`, `agents/`) **plus** `rules/` from `CACHE_RULES_DIR` (see D3) |
| Agent Skills | `executeAgentSkillsSync()` | `~/.agents/` | cache skills as `skills/<rel>` |
| Workspace | `mergeSkillsIntoWorkspaceSync()` | `workspace/.claude/` | cache `skills/`, `agents/`, `rules/` |

The cache prune reads the **old** cache manifest (before the wholesale rebuild) to
distinguish previously-managed entries from user-placed files. After pruning, the rebuilt
manifest carries forward the old entry (fresh hash, original source label) for any on-disk
cache file not in the source set, and labels never-manifested files `source: 'user'` — so
user content in the cache is neither deleted nor re-labeled `overdeck` (which would make it a
prune candidate next sync).

**Empty-dir wrinkle:** `copyDirectoryRecursive()` stops creating `dest` up front; it creates
the destination lazily, only when copying the first file into it. An empty source tree then
produces nothing in the cache, and the prune removes any stale empty dirs already there.

### Decisions (auto mode — recorded in `plan.autoDecisions`)

- **D1 — Modified stale targets are kept, not deleted.** The issue mandates leaving
  user-authored content untouched; deleting user-modified content is a one-way door. Dropping
  the manifest entry makes the keep permanent and idempotent (no re-report every sync).
- **D2 — User-placed cache files keep their provenance.** The rebuilt cache manifest
  preserves old labels / uses `source: 'user'` for files outside the source set, so the cache
  prune never deletes them on a later sync. Distribution behavior for such files is unchanged
  (they still flow to targets, as today).
- **D3 — Target prune includes the `rules/` prefix, sourced from `CACHE_RULES_DIR`.** Stale
  bundled rules are exactly what kept `beads-dolt-authority.md` live in sessions; the
  manifest-provenance + hash-match guard makes pruning them safe. Current (non-stale) rules
  entries are kept as-is — whether `~/.claude/rules/` duplicates the CLAUDE.md folding is a
  pre-existing question this issue does not touch.
- **D4 — `removeLegacySkills070Sync()` stays.** Its hardcoded list (`src/lib/sync.ts:150`) is
  now subsumed by target pruning, but it is harmless, cheap defense in depth; removing it is
  out of scope.
- **D5 — No dry-run/plan surface for prunes.** `planSyncSync()` and `SyncItem.status` are
  unchanged; prune reporting lands in the execute results and CLI output only. Keeps the diff
  off the display-type surface.

## Requirements

- **FR-1** — `refreshCacheSync()` removes cache entries (skills dirs, agent files, rule
  files) that were recorded in the old cache manifest with `source: 'overdeck'` and no longer
  exist under `SYNC_SOURCES`.
- **FR-2** — Cache files not recorded in the old manifest, recorded with a non-`'overdeck'`
  source, or modified since recording are preserved and are not re-labeled `overdeck` in the
  rebuilt manifest.
- **FR-3** — `executeSyncSync()`, `executeAgentSkillsSync()`, and
  `mergeSkillsIntoWorkspaceSync()` delete target files whose manifest entry is
  `source: 'overdeck'`, whose path is absent from the stage's source set, and whose on-disk
  hash matches the manifest hash; they drop the manifest entry and remove now-empty ancestor
  dirs below the target base.
- **FR-4** — A stale target file whose hash differs from its manifest entry is kept, its
  entry is dropped, and the path is reported in `keptModified`.
- **FR-5** — Copying an empty source directory tree creates no directories in the cache or
  any target.
- **FR-6** — `pan sync` CLI output reports how many entries were pruned (and how many
  user-modified stale files were kept) per stage, only when nonzero.
- **NFR-1** — Pruning is idempotent: a second `pan sync` with an unchanged bundle prunes
  nothing.
- **NFR-2** — Pruning never touches files without a manifest entry or with a
  non-`'overdeck'` source (user-owned invariant), verified by test.

## Work Items

### WI-1 — Shared prune helper in `src/lib/manifest.ts` (+ result types)

Add to `src/lib/manifest.ts`:

```ts
export interface PruneResult {
  /** Relative paths deleted (or manifest-only entries dropped). */
  pruned: string[];
  /** Stale paths kept because the user modified them; entry dropped. */
  keptModified: string[];
}

export function pruneStaleManifestEntriesSync(
  targetBase: string,
  manifest: Manifest,
  currentSourceRelPaths: ReadonlySet<string>,
  opts?: { prefixes?: string[] },
): PruneResult
```

Semantics: iterate `Object.entries(manifest.installed)`; skip entries where
`entry.source !== 'overdeck'`, where `rel` is in `currentSourceRelPaths`, or where
`opts.prefixes` is given and no prefix matches `rel`. For the rest apply the
missing/hash-match/hash-differs rules from the Proposal. Empty-ancestor cleanup: from
`dirname(deletedFile)` walk up while the dir exists, is empty, and is not `targetBase`;
`rmdirSync` each. Uses `removeManifestEntry` (`src/lib/manifest.ts:102`), `hashFileSync`
(`src/lib/manifest.ts:39`), `existsSync`, `rmSync`/`rmdirSync`, `readdirSync`.

Also extend the shared result types so later items compile independently:

- `SyncResult` in `src/lib/sync.ts:395` gains `pruned: string[]; keptModified: string[];`
  (both constructors — `executeSyncSync` at `src/lib/sync.ts:421` and
  `executeAgentSkillsSync` at `src/lib/harness-skill-sync.ts:46` — initialize them to `[]`
  in this item).
- `MergeResult` in `src/lib/skills-merge.ts:25` gains the same two fields, initialized in
  `mergeSkillsIntoWorkspaceSync`.

Tests: `tests/unit/lib/manifest-prune.test.ts` — construct a temp targetBase + manifest by
hand (no `paths.js` mock needed; the helper takes explicit args) covering: prune on
hash-match, entry-drop on missing file, keep+drop on hash-mismatch, skip non-overdeck source,
skip unmanifested files, prefix filtering, empty-ancestor removal stopping at targetBase,
idempotency (second run prunes nothing).

## Acceptance Criteria

1. Given a cache skill dir and rule file recorded in the old cache manifest with
   `source: 'overdeck'` and absent from `sync-sources/`, when `refreshCacheSync()` runs, then
   it deletes them from the cache and the rebuilt manifest contains no entry for them.
2. Given a cache file with no old-manifest entry (or one whose on-disk content was modified),
   when `refreshCacheSync()` runs, then the file survives and the rebuilt manifest does not
   label it `overdeck`.
3. Given a target file whose manifest entry is `source: 'overdeck'`, absent from the cache
   source set, with matching hash, when any of the three distribute functions runs, then it
   deletes the file, drops the manifest entry, and removes now-empty ancestor dirs below the
   target base.
4. Given the same stale entry but a user-modified file, when the distribute function runs,
   then it preserves the file, drops the manifest entry, and includes the path in
   `keptModified`.
5. Given an empty source skill directory, when `refreshCacheSync()` runs, then it creates no
   directory for it in the cache.
6. Given a bundle unchanged between two runs, when `pan sync` runs twice, then the second run
   reports zero pruned entries.
7. When `pan sync` prunes or keeps entries, then the CLI prints the pruned/kept counts and
   the kept paths.
8. `npm run typecheck`, `npm run lint`, and `npm test` pass with the new tests green.
9. The three docs surfaces in WI-7 state the prune behavior and the never-delete-user-content
   guarantee.
