# PAN-2857 — Pipeline membership is blind to `strike/` branches

Active strike work (live `strike/pan-XXXX` branch, running agent, no PR yet) classifies as
`clean_terminal` ("backlog, never started") and is hidden from every membership surface —
the issues rail, the CommandDeck pipeline board, `pan pending`, and the flywheel — until its
PR opens. This PRD specifies the gatherer-side fix that keeps the durable-lens doctrine intact.

Issue: https://github.com/eltmon/overdeck/issues/2857

## Glossary

- **Membership resolver** — `resolvePipelineMembership()` in `src/lib/pipeline-membership.ts:91`,
  the single function that classifies an issue into a pipeline bucket from boolean lens signals.
  It never sees branch names.
- **Gatherer** — `gatherProjectLensSignals()` in `src/lib/pipeline-membership-gather.ts:196`,
  which builds `IssueLensSignals` (the booleans) from GitHub + git for one project.
- **Durable lenses** — the signals membership is computed from: L1 open PR, L1-merged merged PR
  (the merge oracle), L2 unmerged convention branch, L3 issue open, L4 phase label, L6 vBRIEF
  spec. L5 (agents/DB/tmux) never decides membership.
- **Convention branch** — a branch named for an issue. Today the code recognizes only
  `feature/<id-lowercase>`; strikes use `strike/<id-lowercase>` (created by `pan strike`).
- **Strike** — an urgent fix agent (`pan strike <id>`) that skips planning, works on a
  `strike/<id>` branch, and opens its PR only at `pan done`.
- **Bucket** — the resolver's classification: `in_flight`, `zombie_pr`, `post_merge_limbo`,
  `planned_backlog`, `clean_terminal` (only the last is out of the pipeline).

## Root cause (verified against the tree at 6f8bbe66d5)

A strike issue in its working phase fails every lens:

1. `issueIdFromRef()` (`src/lib/pipeline-membership-gather.ts:189-193`) guards on
   `/(?:^|\/)feature\//` — `strike/pan-2853` returns `null`. This function parses BOTH the
   `git for-each-ref` branch listing (line 249) AND open-PR head refs (line 241), so it also
   blinds the L1 lens to an open strike PR.
2. The two branch listings (`:210` plain, `:211` with `--no-merged=main`) pass only
   `refs/heads/feature/*` and `refs/remotes/origin/feature/*` patterns — strike refs never
   reach the parser at all.
3. The `candidateHeads` fallback (`:260-261`) and merged-PR fallback (`:266-268`) hardcode
   `feature/<id>` head names, so a merged-and-deleted strike branch is not seen by the merge
   oracle.
4. Strikes have no PR (until `pan done`), no vBRIEF spec (skip planning by design), and no
   phase label — so no other lens rescues them.

Result at `src/lib/pipeline-membership.ts:156`: `clean_terminal`, "open issue with no branch
and no PR — backlog, never started". Confirmed second surface (issue comment, 2026-07-18):
the CommandDeck pipeline board is fed by `enumerate-in-flight`
(`src/lib/reconstruct/enumerate-in-flight.ts:27`), which delegates to the same chain — the
six-consumer delegation audit (`tests/unit/lib/pipeline-membership-audit.test.ts:15-22`)
proves one fix restores visibility everywhere.

## Decisions

- **D1 — gatherer-only fix.** The resolver sees only booleans; recognizing `strike/` refs in
  the gatherer restores visibility in all six consumers at once. No resolver bucket-logic change.
- **D2 — bucket is `planned_backlog`, reason wording generalized.** No new
  `IssueLensSignals` field, no strike-specific reason/bucket. The branch-live reason at
  `pipeline-membership.ts:139` changes from "unmerged feature branch" to
  "unmerged convention branch (feature/ or strike/)". `PLANNED_BACKLOG_SPEC_ONLY_REASON`
  (`:34`) is untouched — PAN-2822's `specOnlyPlanned` DTO derivation matches it byte-for-byte.
- **D3 — L1 fix rides along.** Widening `issueIdFromRef()` also makes an OPEN strike PR
  register `hasOpenPr` → `in_flight` (same one-line regex; strictly-worse variant of the bug).
- **D4 — verification is unit-test level.** Gather + resolver tests plus the existing
  delegation audit prove all surfaces; no live strike branch UAT.

## Requirements

- **FR-1** — A local or remote `strike/<id>` ref sets `hasConventionBranch` (and
  `branchUnmerged` when unmerged) for that issue; an open issue with an unmerged strike
  branch and no PR resolves `planned_backlog` / `inPipeline: true`; closed issue + leftover
  strike branch stays `clean_terminal`.
- **FR-2** — An open PR with a `strike/<id>` head sets `hasOpenPr` and resolves `in_flight`.
- **FR-3** — A merged strike PR whose branch is deleted sets `hasMergedPr` via the fallback
  heads and resolves `post_merge_limbo`.
- **FR-4** — The branch-live `planned_backlog` reason names both conventions;
  `PLANNED_BACKLOG_SPEC_ONLY_REASON` is byte-identical.
- **FR-5** — `docs/PIPELINE-MEMBERSHIP.md` names `strike/<id>` alongside `feature/<id>` as a
  recognized convention branch and states that a live strike branch surfaces before its PR.
- **NFR-1** — Existing feature-branch membership behavior unchanged: full gather/audit/
  resource-discovery suites green with pre-existing expectations unmodified.

## Hazards

- Reason string asserted verbatim at `resource-discovery.test.ts:403` — update with the wording.
- `PLANNED_BACKLOG_SPEC_ONLY_REASON` asserted byte-for-byte
  (`pipeline-membership-audit.test.ts:81-83`) and drives PAN-2822 — do not touch.
- Four new ref patterns total (heads + remotes, both invocations); a partial add silently
  breaks `branchUnmerged`.
- An issue may have BOTH `feature/` and `strike/` branches; `headRefsByIssue` is a Set union,
  so tests must not assume one head per issue.

2. Existing feature-branch behavior unchanged — full suite green, pre-existing expectations
   unmodified (NFR-1).
3. `docs/PIPELINE-MEMBERSHIP.md` lists `strike/` as a recognized convention branch.
