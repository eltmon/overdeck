## Glossary

- **Order book** — an operator-curated Flywheel campaign: a durable queue of issues in two lanes with enforced pickup rules (`docs/ORDER-BOOKS.md`).
- **Pickup posture** — `open` (dispatch live: eligible book items start when a slot frees) or `drain` (in-flight items finish; nothing new starts until reopened). Stored in `OrderBookSettings.posture`.
- **Posture attribution** — the three persisted-but-currently-unrendered fields `postureSetAt` (ISO timestamp), `postureSetBy` (actor string), `postureReason` (free text), written by the settings write door on posture change (`packages/contracts/src/orders.ts:44-46`).
- **Lane A / Lane B** — Lane A is parallel, capped by `settings.laneAConcurrency`; Lane B is always strictly serial (one item at a time, in order). The panel only edits Lane A concurrency.
- **Brief overlay** — optional repo-relative markdown path (`settings.briefOverlay`) appended to every item's kickoff brief for the run. Server resolves the path; the client validates shape only.
- **Off-book pickup** — starting an issue outside the running book. Always blocked in the UI; the only path is the logged CLI override `pan start <id> --off-book`, recorded in the run record with actor and timestamp. It is a fixed policy, not a setting.
- **Save chip** — the per-field save indicator introduced by this rebuild: `idle | saving | saved | error` rendered beside the field's label.
- **Stale reason** — a `postureReason` that describes a previous posture, carried into a new posture save (see FR-3 for the detection rule).
- **8%/32% badge tint formula** — pan-style-guide tinting: background `color/[0.08]`, border `color/[0.32]`, text `color-foreground`. In this codebase: `bg-warning/[0.08] border-warning/[0.32] text-warning-foreground` (verified in use at `src/dashboard/frontend/src/pages/OrderBookPage.tsx:215-223`).

## Requirements

### Functional

- **FR-1 — Atomic posture + reason.** Posture is a two-button segmented control (`Open` / `Drain`). Clicking the *other* state expands an inline confirmation containing a consequence sentence, a prefilled editable reason input, a confirm button, and Cancel. Confirm sends **one** patch `{ posture, postureReason }`. The stranded standalone "Posture reason" field is removed. There is no gesture that types a reason and discards it.
- **FR-2 — Both postures visibly active.** The active segment gets the 8%/32% tint: blue (`info`) when `open`, amber (`warning`) when `drain`. The inactive segment is neutral (`text-muted-foreground`, transparent border) and enabled. `aria-pressed` reflects the active state. A consequence hint renders under the control for the current posture.
- **FR-3 — Attribution line + stale flag.** Under the control, always render: posture label · `set by` + `postureSetBy` (monospace, fallback `operator`) · formatted `postureSetAt` · quoted `postureReason` (fallback `No reason recorded.`). When the stale rule fires, append a small amber `STALE REASON` tag (8%/32% warning tint, rounded-sm, uppercase 10px) with `title` tooltip: `This reason was recorded before the current posture was set — it describes a previous state.` **Stale rule (decision made here):** the contract has no `reasonSetAt`, so staleness is detected as the known-default-mismatch: `posture === 'open' && postureReason === 'Operator paused new pickup.'` or `posture === 'drain' && postureReason === 'Operator reopened pickup.'`. This exactly catches the verified live contradiction (book stores `open` + "Operator paused new pickup.") and the class of bugs the old UI created; broader detection would need a contract change (NonGoal).
- **FR-4 — Per-field save state.** Replace the single `saving` boolean with a keyed map over field ids `'posture' | 'lane' | 'brief'`: `idle | saving | saved | error`. Chip renders beside the owning field's label: saving = spinner + `Saving…` (muted); saved = `Saved ✓` (success color) that reverts to idle after **1600 ms**; error = `Couldn't save` + underlined `Retry` button (destructive color) that re-runs the **same patch**. Footer becomes left `Changes save automatically`, right (mono) `last saved HH:MM:SSZ` (UTC, updated on every successful save) or `last saved —` before the first save. No state can hang: every save terminates in saved or error-with-retry on its field.
- **FR-5 — Lane A concurrency stepper.** Replace the number input with a − / value / + stepper, min 1, max 8, buttons disabled at the bounds, value in monospace. Hint copy under the label: `How many parallel-safe Lane A items may run at once. Lane B ignores this — it is always one item at a time, in order.` Changes debounce **500 ms**, then save `{ laneAConcurrency }` through the save-state machinery.
- **FR-6 — Brief overlay validation.** Monospace path input, placeholder `docs/briefs/refactor-p3.md`, hint `Markdown appended to every item's kickoff brief for this run.` Input debounces **550 ms**, then: empty → status line `None — items run with their PRDs alone.` (muted) and, if the persisted value was non-empty, saves `{ briefOverlay: '' }`; non-`.md` (case-insensitive `/\.md$/i` on the trimmed value) → inline error `Not a markdown file — expected a repo-relative .md path.` (destructive color) and **no save**; valid `.md` differing from the persisted value → saves `{ briefOverlay }` with chip feedback and status `Appended to every item's kickoff brief.` (success color). Client-side shape validation only — path resolution stays server-side, so the status must not claim the file resolves or state a size.
- **FR-7 — Off-book policy row.** Row label `Off-book pickup` with an expander toggle button `how the override works` (`aria-expanded`). Policy line: lock glyph 🔒 + `Blocked while this book runs — fixed policy, not a preference.` Expander body (complete sentences, defines the term inline): `While a run is active the flywheel only starts issues that are in this book. Starting anything else requires `pan start <id> --off-book`, which succeeds but is written to the run record with who ran it and when — an audited exception, not a setting.` (`pan start <id> --off-book` in monospace.)
- **FR-8 — Tests.** `__tests__/RunSettingsPanel.test.tsx` covers: reason persists atomically via the posture confirm (regression for defect 1); `open` renders active styling (defect 2); per-field save transitions including error + retry re-sending the same patch and the 1600 ms saved-fade (defect 3); attribution renders and the stale tag appears/absents per the FR-3 rule (defect 4); stepper debounce + bounds; brief overlay error-without-save and valid-path save.
- **FR-9 — Docs.** `configuration/order-books.mdx` "Pickup posture" (lines 63-67) and "Setup and Progress" (line 95) sections updated: OPEN is now shown blue-tinted (machine dispatching), not neutral; attribution (who/when/why) is always visible in run settings with a stale-reason flag; run settings save automatically per field with visible saved/error state.

### Non-functional

- **NFR-1 — Style guide.** DM Sans, `font-medium` maximum weight, 8%/32% tint formula, `rounded-sm`/`rounded-md` (no pills), amber = human-paused, blue = machine dispatching, works in both themes using existing Tailwind tokens only (`info`, `warning`, `success`, `destructive`, `muted-foreground`, `border`, `card`).
- **NFR-2 — Fake timers.** Every test exercising debounce (500/550 ms), the saved-fade (1600 ms), or async save resolution MUST use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` per the repo rule — no real waits.
- **NFR-3 — No backend/contract change.** No edits to `packages/contracts`, routes, or the orders writer. Props signature of `RunSettingsPanel` unchanged.

## Design — component structure (before/after)

Single file rebuild of `RunSettingsPanel.tsx`. Internal shape:

```tsx
type FieldId = 'posture' | 'lane' | 'brief';
type SaveState =
  | { state: 'idle' }
  | { state: 'saving' }
  | { state: 'saved' }
  | { state: 'error'; retry: () => void };
```

Core save helper (replaces `save` at `:20-30`):

```tsx
const [saves, setSaves] = useState<Record<FieldId, SaveState>>({ posture: {state:'idle'}, lane: {state:'idle'}, brief: {state:'idle'} });
const [lastSaved, setLastSaved] = useState<Date | null>(null);
const savedTimers = useRef<Record<FieldId, ReturnType<typeof setTimeout> | undefined>>({} as never);

const runSave = (field: FieldId, patch: Partial<OrderBookSettings>) => {
  clearTimeout(savedTimers.current[field]);
  setSaves((s) => ({ ...s, [field]: { state: 'saving' } }));
  void onChange(patch).then(
    () => {
      setLastSaved(new Date());
      setSaves((s) => ({ ...s, [field]: { state: 'saved' } }));
      savedTimers.current[field] = setTimeout(() => setSaves((s) => ({ ...s, [field]: { state: 'idle' } })), 1600);
    },
    () => setSaves((s) => ({ ...s, [field]: { state: 'error', retry: () => runSave(field, patch) } })),
  );
};
```

Posture confirm flow (replaces buttons at `:74-93` and removes the reason input at `:64-73`):

- Local state `pendingTo: 'open' | 'drain' | null` and `confirmReason: string`.
- Clicking the inactive segment sets `pendingTo` and prefills `confirmReason` with the default for the target (`drain` → `Operator paused new pickup.`, `open` → `Operator reopened pickup.`); focus + select the input.
- Consequence copy: to `drain` → `In-flight items will finish. Nothing new dispatches from this book until it is reopened.`; to `open` → `Eligible items will start dispatching again — Lane A up to its concurrency, Lane B one at a time in order.`
- Reason input label: `Why? Recorded on the run and shown to anyone reading this book.`
- Confirm button label: `Switch to drain` / `Reopen pickup`, tinted per target (8%/32% warning/info). Cancel collapses without saving.
- Confirm: `runSave('posture', { posture: pendingTo, postureReason: confirmReason.trim() || default })`, then collapse.
- Hint under the control (current posture): open → `Dispatch is live: eligible items start when a slot frees, Lane B strictly in order.`; drain → `Draining: in-flight items finish, nothing new starts until reopened.`

Attribution `postureSetAt` formatting: render the ISO string as short UTC — `MMM D, HH:MMZ` (e.g. `Jul 19, 07:21Z`) via a small local formatter (`toLocaleString('en-US', { month: 'short', day: 'numeric', timeZone: 'UTC' })` + manual `HH:MM` + `Z`); if `postureSetAt` is absent, omit that segment.

Lane/brief local state keeps the existing sync-from-props `useEffect` pattern (`:16-17`); the confirm-flow reason is deliberately **not** synced from props while the confirm is open (it is transient local state, so a background settings refresh cannot clobber a half-typed reason).

## Acceptance criteria (map 1:1 to work items)

1. Chip shows spinner during an in-flight save, `Saved ✓` on success fading to idle after 1600 ms (fake timers), `Couldn't save · Retry` on failure; Retry re-sends the identical patch; footer shows mono `last saved` time after success.
2. A reason typed during a posture switch is saved atomically in one patch with the posture; there is no rendered input that accepts a reason without a save path; both postures render active-state tinting and correct `aria-pressed` in both directions.
3. Attribution (who · when · "why") renders whenever the panel does, with mono actor; the stale tag appears exactly per the FR-3 rule with the specified tooltip.
4. Stepper clamps to [1, 8] with disabled buttons at bounds and emits a single debounced `{ laneAConcurrency }` patch.
5. A non-`.md` path shows the inline error and never calls `onChange`; a valid path and an explicit clear both persist with owner-adjacent feedback.
6. The off-book row renders the fixed-policy line and an expander whose body defines the `--off-book` override in complete sentences.
7. `configuration/order-books.mdx` describes the blue OPEN treatment, always-visible attribution with stale flag, and per-field autosave feedback.
