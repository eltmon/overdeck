## Glossary

- **Conversation** — a dashboard-managed chat session (`/conv/:id`), backed by a Claude Code JSONL transcript on disk. Rendered by `ConversationPanel` → `ConversationView` → `MessagesTimeline`.
- **Session file** — the parent transcript at `~/.claude/projects/<encoded-cwd>/<sessionId>.jsonl`. Computed by `sessionFilePath(cwd, sessionId)` in `src/lib/paths.ts:286`.
- **Subagent** — a child agent spawned from a conversation via Claude Code's `Agent` tool (agent types: `Explore`, `general-purpose`, etc.). NOT an Overdeck pipeline agent — it has no `pan` state, no tmux session, no issueId. This feature is read-only observation of harness-native subagents; the work-agents-via-pan rule is not implicated.
- **Subagents directory** — sibling directory to the session file: `~/.claude/projects/<encoded-cwd>/<sessionId>/subagents/`. Contains, per subagent:
  - `agent-<agentId>.jsonl` — the subagent's full transcript, **same JSONL schema as the parent** (entries carry `isSidechain: true` and `agentId`, which the parser ignores harmlessly).
  - `agent-<agentId>.meta.json` — verified live shape: `{"agentType":"Explore","description":"Find conversation transcript rendering","toolUseId":"toolu_0169…","spawnDepth":1}`.
- **toolUseId join** — `meta.toolUseId` equals the `tool_use` block id in the parent transcript. The parser sets `WorkLogEntry.id = block.id` (`src/dashboard/server/services/conversation/parser.ts:395`), so the inline `Agent` row and the subagent metadata share a key with no extra bookkeeping.
- **WorkLogEntry** — the parsed tool-call row type (`packages/contracts/src/rpc.ts:157–172`), rendered as the bullet + label + one-line detail + chevron row.
- **`ConversationEvent`** — the WS wire event union (`packages/contracts/src/rpc.ts:191–205`): currently `{kind:'messages', …}` | `{kind:'discovering'}`. Streamed by `pan.subscribeConversationMessages`.
- **Rail** — the proposed right-side panel in the conversation body listing subagents, following the existing inline `DiffPanel` pattern.

## Background — current behavior (verified 2026-07-18)

- The parent JSONL no longer contains subagent messages inline: the last 30 sessions in `~/.claude/projects/-home-eltmon-Projects-overdeck/` contain zero `"isSidechain":true` entries in parent files. Subagent transcripts live only in the subagents directory. The parser has no `isSidechain` handling and needs none for parent files.
- Current harness JSONL writes the spawn tool as `"name":"Agent"` (verified in a live session file). Both renderers special-case only `'Task'`:
  - `src/dashboard/frontend/src/components/chat/messagesTimeline/workLogRows.tsx:205` (`ToolUseExpanded`) — an `Agent` row's expanded body falls through to the pretty-printed JSON dump at lines 267–271.
  - `src/dashboard/server/services/format-tool-input.ts:89` (`summarizeToolInputForWorkLog`) — an `Agent` row gets no `subagentType: description` one-liner.
- Transcript transport: live conversations stream over WS method `pan.subscribeConversationMessages` (`packages/contracts/src/rpc.ts:43`, Rpc schema at `:389`, payload `{ conversationName: string }`). Server handler at `src/dashboard/server/ws-rpc.ts:877` resolves the session file (`:915–922`), full-parses it (`parseEntireConversation`, `:952`), emits a snapshot (`:985–994`), then tails appends with `watchConversation` (`:998`) guarded by `gateSnapshotEmission` (append-only, PAN-1642). Ended conversations use one-shot REST `GET /api/conversations/:name/messages` (`src/dashboard/server/routes/conversations.ts:452`).
- Client: `useConversationMessagesStream` (`src/dashboard/frontend/src/components/chat/useConversationMessagesStream.ts:141`) subscribes and merges events into the react-query cache via `applyConversationMessagesEvent` (`:62`); streaming is gated by `shouldStreamConversationMessages` (`:111`).
- Layout: `ConversationPanel` body is a flex row (`src/dashboard/frontend/src/components/chat/ConversationPanel.tsx:994`) holding the main column plus an optional inline `DiffPanel` (`:1047–1057`). The rail slots in as a third sibling.
- `MessagesTimeline` is re-exported from the refactored directory (`src/dashboard/frontend/src/components/chat/MessagesTimeline.tsx:7–8` → `./messagesTimeline/MessagesTimeline`); all new rendering work targets `src/dashboard/frontend/src/components/chat/messagesTimeline/`.

## Requirements

### Functional

- **FR-1 Discovery.** For a claude-jsonl conversation, the server enumerates subagents from `<sessionFile minus .jsonl>/subagents/*.meta.json`, producing `{agentId, agentType, description, toolUseId, spawnDepth, status}` per subagent. A missing or empty directory yields an empty list, not an error.
- **FR-2 Live list.** While a conversation is live-streamed, the subagent list is pushed as a new `{kind:'subagents'}` `ConversationEvent` on the existing subscription: once after the initial snapshot, and again whenever the list content changes (new spawn, status flip). New spawns appear in the UI without reload.
- **FR-3 Status.** `status` is `'running'` when the subagent's `toolUseId` is an unresolved `tool_use` in the parent parse state (present in `pendingToolUse`), else `'done'`. For ended conversations every subagent is `'done'`.
- **FR-4 Subagent transcript.** The subagent's transcript is retrievable through the same two doors as the parent transcript: `pan.subscribeConversationMessages` with a new optional `agentId` payload field (snapshot + live tail of the subagent JSONL), and REST `GET /api/conversations/:name/messages?agentId=<id>` for ended conversations. Parsing reuses `parseEntireConversation` / `watchConversation` unchanged.
- **FR-5 Rail UI.** The conversation body shows a right-side rail listing subagents (agent type, description, status indicator, depth marker when `spawnDepth > 1`). The rail is hidden entirely when the list is empty (covers Pi/Codex conversations, which have no subagents directory). Selecting a subagent opens its transcript rendered with `MessagesTimeline` (read-only: no composer). Selection is reflected in the URL as `?subagent=<agentId>` so views are linkable, mirroring the `?diff=1` pattern.
- **FR-6 Inline row linking.** The expanded body of an `Agent`/`Task` work-log row whose `WorkLogEntry.id` matches a known subagent's `toolUseId` shows an "Open subagent transcript" action that selects that subagent in the rail.
- **FR-7 `Agent` tool-name parity.** `'Agent'` is handled identically to `'Task'` in both `ToolUseExpanded` and `summarizeToolInputForWorkLog` (subagent type + description header, prompt as markdown; one-line `type: description` summary).
- **FR-8 Documentation.** Developer doc describing the data layout, transport, and status derivation; user-facing note in the Mintlify docs. See work item 8.

### Non-functional

- **NFR-1 Async only.** No `execSync`, no sync `fs` calls in server code (`readdir`/`readFile` via `fs/promises`). This is the standing no-execsync-server rule; it applies to the discovery module and route changes.
- **NFR-2 Path safety.** `agentId` from the wire is validated against `/^[A-Za-z0-9_-]+$/` and the resolved transcript path must be inside the subagents directory (`path.resolve` prefix check) before any file read. Invalid ids → REST 400 / WS `discovering` event, never a path read.
- **NFR-3 Bounded watching.** The subagents directory is re-scanned on a 2000 ms interval only while a subscription is active, and the interval is cleared in the stream's release/cleanup. A directory scan is one `readdir` + at most N small `readFile`s of meta files; cache meta contents by filename (meta files are write-once) so steady-state polling is `readdir` + set comparison only.
- **NFR-4 Append-only view.** Subagent transcript streams go through the same `gateSnapshotEmission` guard as parent streams — a transient shrink must not blank the panel (PAN-1642 semantics).
- **NFR-5 Fake timers in tests.** Any test exercising the 2 s poll uses `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()` — never real waits (standing fake-timers rule).
- **NFR-6 No new state plane.** The feature reads only the JSONL plane. No DB columns, no `overdeck-state` writes, no new resolver domains.

## Design decisions (made here, not left to the implementer)

- **D-1: extend the existing subscription, don't add a second RPC.** The subagent list rides `pan.subscribeConversationMessages` as a new event kind, and subagent transcripts reuse the same RPC with an optional `agentId`. Rationale: the handler already owns session-file resolution (the non-trivial part, `ws-rpc.ts:905–929`), and one subscription per view keeps the client simple. A separate `subscribeConversationSubagents` RPC is rejected.
- **D-2: full-list events, not deltas.** Each `{kind:'subagents'}` event carries the complete list (small — realistically < 50 entries). The client replaces, never merges. Avoids a second merge protocol.
- **D-3: poll the directory, don't `fs.watch` it.** The directory may not exist at subscribe time (first spawn creates it), and `fs.watch` cannot watch a nonexistent path; watching the parent for dir-creation then rebinding is complexity for no user-visible gain over a 2 s poll. Decision: poll, per NFR-3. (`watchConversation` itself already has a 500 ms poll fallback for the same class of reason, `watch.ts` header comment.)
- **D-4: status from parent parse state, not from the subagent file.** The parent stream already tracks `pendingToolUse`; a subagent is running iff its `toolUseId` is pending there (FR-3). Rejected alternative — inferring liveness from subagent-file mtime — is racy and requires stat-ing every file every poll.
- **D-5: the rail renders a second `MessagesTimeline`, not a new transcript component.** The subagent parse output is the same `{messages, workLog}` shape; reuse the renderer with the composer omitted and a header (agent type, description, back/close affordance).
- **D-6: claude-jsonl harness only.** Gate list emission on the same `transcriptKind === 'claude-jsonl'` check the handler already performs (`ws-rpc.ts:901`). Pi/Codex conversations never emit a subagents event; the rail never shows.
- **D-7: nested subagents render flat.** All meta files in the directory are listed regardless of `spawnDepth`; depth > 1 gets a visual marker only. No tree UI in this issue.
- **D-8: UI style.** Follow the pan-style-guide skill: no pill badges, color restraint, no green "running" dots — running status uses the existing `tone` color language of the work log (`var(--primary)` accent, muted otherwise).

### 3. Server — wire into the WS handler and REST route

**Files:** `src/dashboard/server/ws-rpc.ts` (handler at `:877`); `src/dashboard/server/routes/conversations.ts` (route at `:452`).

(a) **`agentId` branch.** In the handler, after `sessionFile` is resolved (`:920–922`): if `input.agentId` is present, replace `sessionFile` with `subagentTranscriptPath(sessionFile, input.agentId)` (null → `conversationDiscoveringStream()`), then fall through to the existing snapshot + `watchConversation` flow unchanged — including the `gateSnapshotEmission` guard (NFR-4). (b) **List emission.** In the parent-stream branch, inside the existing `Effect.acquireRelease` acquire (after the initial snapshot `offer` at `:985–994`): compute the initial list via `listSubagentMetas`, stamp `status` per FR-3 from `initial.pendingToolUse`, and `offer({kind:'subagents', subagents})` (emit even when empty so the client can clear stale state on resubscribe). Also add `subagents` (with all-`done` status) to the parent-shaped response so ended conversations can populate the rail without a live stream. `ConversationResponse` (`packages/contracts/src/rpc.ts:178–189`) gains `subagents?: SubagentSummary[]`.
