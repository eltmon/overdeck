# PAN-2231 — Forbid source-introspection tests (lint guard)

**Issue:** [PAN-2231](https://github.com/eltmon/overdeck/issues/2231) — chore(lint): forbid source-introspection tests (tests that readFileSync src/ and regex it)

## Glossary

- **Source-introspection test** — a test that reads a source file's *text*
  (`readFileSync`/`readFile` of a `.ts`/`.tsx` path) and asserts on that text with
  string/regex matchers, instead of exercising the module's runtime behavior.
- **Offender** — a test file containing one or more source-introspection reads.
- **Baseline (shrink-only ratchet)** — a committed file enumerating current
  offenders with a per-file count. A baselined file may *reduce* its count but
  never *increase* it; a non-baselined file with any offending read fails. This
  mirrors `scripts/file-size-baseline.txt` semantics.
- **Detection signal** — a `.ts`/`.tsx` *string literal* passed as the path
  argument to `readFileSync`/`readFile` inside a test file.

## Problem

The campaign's red-main incident: `tests/lib/cloister/review-agent.test.ts`
`readFileSync`'d `src/dashboard/server/routes/workspaces.ts` and regex-matched its
source. The workspaces decomposition (#2124) moved the routes, and every such test
went red on main and on every branch simultaneously. Source-introspection tests are
brittle to any extraction/rename and turn ordinary refactors into outages — a failing
test on main empties the merge gate for every in-flight PR.

Verified current offenders (scanner preview at planning time, HEAD `d89cd9f76d`):
`tests/lib/cloister/review-agent.test.ts` (20 reads),
`src/dashboard/frontend/src/components/Settings/__tests__/SettingsPage.test.ts` (11),
`src/dashboard/server/routes/__tests__/effect-patterns.test.ts` (1, reads
`routes/workspaces.ts`), and ~18 other test files with 1–4 reads each.

## Proposal

Add a custom lint script `scripts/lint-source-introspection.sh` — modeled on
`scripts/lint-file-size.sh` — wired into the `npm run lint` chain (and therefore CI,
`.github/workflows/ci.yml:100`). It fails when a test file reads a `.ts`/`.tsx` source
path via `readFileSync`/`readFile`. Existing offenders are captured in a committed,
enumerable, shrink-only baseline `scripts/source-introspection-baseline.txt`. A self-test
proves the guard bites on a new introspection read and passes on a clean tree.

Repointing the existing offenders to behavioral assertions / exported constants is
explicitly **out of scope** — the issue calls for that "over time", and the acceptance
criteria only require new offenders to fail and existing ones to be baselined/enumerable.

### Detection signal (decided in-doc)

Flag: a **quoted string literal ending in `.ts` or `.tsx`** (single or double quote)
that appears as the path argument to a `readFileSync`/`readFile(` call in a test file.

Rationale:
- The largest offender cluster (`SettingsPage.test.ts`, 11 reads) uses **test-relative**
  paths like `'../../SettingsPage.tsx'` that contain **no literal `src/` substring**.
  Restricting to a `src/` substring would miss them. The `.ts`/`.tsx` extension is the
  correct generalization: a test never legitimately reads a sibling `.ts`/`.tsx` file's
  text except to introspect it (behavior is exercised by `import`, not `readFileSync`).
- The call token and the path literal may be on **adjacent lines**
  (`readFileSync(\n  '../x.tsx'),`), so detection must be multi-line aware — mirror the
  awk/perl windowed approach in `lint-state-writes.sh`.

Test-file scope = `tests/**/*.ts(x)`, `src/**/__tests__/**/*.ts(x)`,
`src/**/*.test.ts(x)`.

### Baseline metric

Per-file **count of offending reads** (`<count> <path>`, sorted by path). Baselined
file: `count > allowed` → FAIL (added introspection); `count < allowed` → stale, run
`--update` to ratchet down; missing/zeroed → stale. Non-baselined file with `count > 0`
→ FAIL (new offender). This is the same ratchet shape as `lint-file-size.sh`.

### Script modes

- **(default) check** — enforce: no new offenders, no count increases, no stale entries.
- **`--update`** — recompute counts for *existing* baseline entries; lower stale counts,
  drop resolved/removed files; **never** raise or add. (Identical to `lint-file-size.sh`.)
- **`--regen`** — write the complete current offender set to the baseline. This is the
  one-time seed path and the audited "accept new offender" escape hatch (equivalent to
  `lint-file-size.sh`'s "manually edit the baseline in an issue-referenced commit").
  Because the baseline is seeded by the script's *own* scanner, `baseline == scanner
  output` by construction, so `check` passes on the seed commit deterministically.

## Requirements

- **FR-1** — `scripts/lint-source-introspection.sh` detects test files that pass a
  `.ts`/`.tsx` string-literal path to `readFileSync`/`readFile` and fails (non-zero exit)
  when an unbaselined offender or a count increase is present.
- **FR-2** — Detection is multi-line aware and matches both root-relative
  (`'src/....ts'`) and test-relative (`'../../x.tsx'`) literal paths. It does **not**
  require a literal `src/` substring.
- **FR-3** — Existing offenders are captured in a committed, enumerable, shrink-only
  baseline `scripts/source-introspection-baseline.txt` (`<count> <path>`); baselined files
  may reduce their count but not increase it; new offender files fail.
- **FR-4** — The guard is wired into `npm run lint` as `lint:source-introspection`,
  so CI (`npm run lint`) enforces it.
- **FR-5** — `--update` lowers stale counts and drops resolved/removed entries and never
  raises/adds; `--regen` reseeds the complete current baseline.
- **FR-6** — A self-test (`tests/unit/scripts/lint-source-introspection.test.ts`) proves
  the guard fails on a new introspection read, passes on a clean tree, and that `--update`
  ratchets a shrunk file's count down.
- **NFR-1** — The script follows `scripts/lint-file-size.sh` conventions: bash,
  `set -euo pipefail`, `<count> <path>` baseline, check/`--update` modes, `✓`/`✖` messages
  with an actionable remediation line.
- **NFR-2** — The guard passes on the current tree at the seed commit (baseline equals the
  scanner's own output).

## NonGoals

- Repointing existing offenders to behavioral assertions or exported constants (deferred;
  "over time" per the issue).
- Detecting dynamically-computed (non-literal) source paths — literal-path detection
  matches the sibling lints and keeps false positives near zero.
- Flagging reads of non-source fixtures (`.json`/`.md`/`.yaml`/`.jsonl`) or a test reading
  its own generated output.
- Deleting or refactoring `routes/workspaces.ts` or its introspection tests.

## Planning Q&A

`pan plan --auto` — no interactive Q&A. Inferred decisions recorded in `plan.autoDecisions[]`:

1. **Detection = `.ts`/`.tsx` literal read, not `src/`-substring match.** The biggest
   offender cluster uses test-relative `../../*.tsx` paths with no `src/` substring;
   the extension signal is the correct generalization and yields near-zero false positives.
2. **Baseline metric = per-file offender count, shrink-only ratchet.** Mirrors
   `lint-file-size.sh` exactly (well-understood, already tested pattern).
3. **`--regen` is the seed + audited-accept path.** Guarantees `baseline == scanner
   output` on the seed commit so CI is green by construction; keeps logic DRY (one scanner).
4. **Guard, seed baseline, and lint-chain wiring ship as one bead.** An unwired or
   unbaselined guard has zero value and can't pass its own check — they are atomically
   coupled into one working, CI-enforced tracer-bullet slice.
5. **Repointing offenders is out of scope** — the issue defers it; ACs require only
   baseline + new-offender-fails.
