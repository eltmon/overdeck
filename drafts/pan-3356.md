# PAN-3356 — Issue cockpit redesign v2: live-run IA — 6 tabs, crew spine, needs-you slot

**Visual contract:** `docs/design/issue-detail-redesign-mockup-v2.html` (committed `96a9a9ad42`). Open it in a browser before implementing; every layout decision below is rendered there. The v1 mockup (`docs/design/issue-detail-redesign-mockup.html`) is kept only as the anti-reference — it dropped surfaces and must not be implemented.

**Scope:** the **cockpit density only** — the issue page at `/command-deck/:project/:issue`, rendered by `src/dashboard/frontend/src/components/Stage/cockpit/IssueMissionControl.tsx`. The console/drawer and rail densities are unchanged except for inventory bookkeeping. Shared issue-view kit components are extended, never forked.

## Glossary

- **Cockpit** — the full-page issue surface (`IssueMissionControl.tsx`), one of three densities of the issue view kit (`docs/ISSUE-VIEW.md`).
- **Density section / marker** — a named surface registered in `src/dashboard/frontend/src/components/issue-view/inventory.ts` and `densitySections.ts`, rendered as a visible `data-section="<name>"` attribute. The **no-loss gate** (`tests/unit/dashboard/frontend/issue-view-no-loss.test.ts`) hardcodes the expected section lists and counts and fails when a surface disappears.
- **Action registry** — `src/dashboard/frontend/src/lib/issueActions.ts`. All 46 issue actions (`ISSUE_ACTION_DEFINITIONS`, line 601) render from this single registry; `issue-actions-surface-parity.test.tsx` fails any surface-local action list.
- **Crew spine** — the left column listing one row per pipeline session (planner, work, review convoy, ship). The restyled `AgentsLane`.
- **Needs-you slot** — a single banner slot between header and pipeline band that shows the highest-priority item requiring the operator, with a queue count when several apply.
- **Segmented view** — a small two/three-button toggle inside a tab that switches sub-views (e.g. Conversation ⇄ Terminal) without changing the selected tab.
- **Binding set** — the tab ids the cockpit delegates to the shared `IssueDetail` component (`ISSUE_DETAIL_TAB_IDS`, `IssueMissionControl.tsx:66`).

## Background

The cockpit accreted 13 tabs plus a floating Tasks chip (`TABS`, `IssueMissionControl.tsx:71–85`), three of which duplicate each other (Files vs Code both render `ChangedFilesView`; Activity vs Timeline both render `ActivityTab`), and a "45 more" actions button. The v2 mockup restructures the page around the live run — a running agent with a question waiting — while a feature-parity audit (embedded in the mockup's legend) maps every current surface to a new home. Nothing is dropped; things are folded.

## Decisions (made here — do not re-litigate downstream)

- **D1 — Tab fold, 13 → 6.** New `MissionTab` ids: `overview | session | plan | changes | activity | discussion`. Old ids map for deep-link compatibility (FR-2).
- **D2 — Default tab rule:** `session` when any agent session exists (running or historical), else `overview`. (Today's default is `conversation`, line 415.)
- **D3 — Session tab** keeps the existing `IssueDetail` delegation: the segmented control renders `IssueDetail density="page" showTabs={false}` with `activeTab='conversation'` or `'terminal'`. No new session plumbing.
- **D4 — Tell composer:** extract the tell form from `ActiveAgentPanel` (section `active-agent-panel-tell`) into a shared `TellComposer` kit component; `ActiveAgentPanel` keeps using it; the Session tab pins it under the transcript. Same mutation, no new endpoint.
- **D5 — Plan tab** = segmented Tasks ⇄ Map ⇄ PRD: `TasksPanel`, `PlanMapCard`/`XBriefViewer` (DAG, keeps its fullscreen promotion), `PrdViewer`. Task `done/total` count renders inside the Plan tab label from the shared `taskTotals` rollup. The floating sticky Tasks chip and its `TasksDrawer` slide-over are removed; their inventory entry relocates (WI-12).
- **D6 — Changes tab** = segmented Files ⇄ Checks ⇄ Artifacts: `ChangedFilesView`, `GitHubCiPanel`, `DrawerArtifactsPanel`. The old Code-tab badge logic (`tabBadge()`, line 407–410: `!` failed / `…` running / `✓` passed) moves onto the Changes tab unchanged.
- **D7 — Activity tab** = segmented Feed ⇄ Status history: `ActivityTab` + `StatusHistoryTab`. The Timeline tab is removed as a tab; both its renderers survive here.
- **D8 — Discussion tab** unchanged (`DiscussionsTab`).
- **D9 — Overview tab** = StatusNarrative summary, review outcomes (`SpecialistStrip` results), `HappenedFeed`, `PickupGateCard`. `CrewStage`'s who-is-doing-what merges into the crew spine; its `data-section="CrewStage"` marker moves to the spine's presence header.
- **D10 — Needs-you slot:** new kit component `NeedsYouSlot`. Priority ladder, highest first: awaiting-input → stuck → troubled/paused → stale-review → blocker (`IssueBlockerSpotlight` content) → pickup gate. Exactly one item visible; a trailing "+N more" chip when several are active. Item actions come from the registry (e.g. `recoverAgent`, `purgeReview`, `unpause`) — no surface-local actions. The absorbed banners keep their section markers, rendered by `NeedsYouSlot` conditionally (the gate checks markers exist in source, so conditional render is fine).
- **D11 — Right rail** (the current `Awareness rail` marker, kept): cards Now (`NowPanel`), Run details (new, read from `IssueViewModel.header`/`agents` — agent role, model, harness, started, workspace + `PanOpenInPicker`), Gates (`VerificationGates`), Cost (from `useIssueCostsQuery`, with "All costs →" opening the full per-model rollup previously on the Costs tab), Environment (`UatEnvironmentPanel`), Recent activity (`DrawerActivityRail` excerpt with "All activity →" switching to the Activity tab).
- **D12 — Header:** issue title is the `<h1>`; phase line = one phase badge (style-guide signal color) + one-sentence `StatusNarrative`; meta chips = branch (copy button), PR (`Create PR` link when none, per mockup), single cost badge (cyan, tabular), tracker split button (`trackerIssueUrl`), then `IssueActionMenu mode="primary-strip"` unchanged. Cost renders in the header once — the old `HeaderStat` cost, giant narrative cost, and Costs tab total collapse into this chip + the rail Cost card.
- **D13 — Pipeline band:** extend the existing Pipeline Band (`IssueDetailShell.tsx:76`) with truthful per-step sublabels: date + duration when done, live counter when running, and explicit skip reasons ("Skipped · no suite configured", linking to test configuration) instead of "—". Ship step expands to show live merge progress (`ShipProgress` compact) during an active merge; the Ship tab is removed.
- **D14 — Ship/Costs/Artifacts/Tasks-chip removals are relocations, not deletions.** Every removed tab's renderer survives at the home named above, and `inventory.ts` records the relocation (PAN-2499 pattern) while `EXPECTED_COCKPIT_SECTIONS` is updated in the same commit.

## Requirements

### Functional

- **FR-1** The cockpit renders exactly six tabs — Overview, Session, Plan, Changes, Activity, Discussion — with no horizontal scrollbar at ≥1100px viewport width.
- **FR-2** Navigating to a legacy tab id (`conversation`, `terminal`, `tasks`, `files`, `artifacts`, `code`, `timeline`, `costs`, `ship`, `plan` as plan-map) selects the new tab and sub-view that hosts that surface. No legacy deep link 404s or lands on a wrong tab.
- **FR-3** Session tab: segmented Conversation ⇄ Terminal over the same selected session; `TellComposer` pinned below; agent selection driven by the crew spine.
- **FR-4** Plan tab: segmented Tasks ⇄ Map ⇄ PRD; task `done/total` count in the tab label; xBRIEF fullscreen promotion still works from the Map view.
- **FR-5** Changes tab: segmented Files ⇄ Checks ⇄ Artifacts; check-state badge on the tab per D6.
- **FR-6** Activity tab: segmented Feed ⇄ Status history.
- **FR-7** Needs-you slot shows exactly one highest-priority operator item with registry-backed actions and a "+N more" count; renders nothing when nothing needs the operator.
- **FR-8** Crew spine lists every session (plan, work, each review specialist, ship) with status dot, model, duration, cost; selection drives the Session tab; all ten `agent-row-*` sub-sections survive.
- **FR-9** Right rail renders Now, Run details, Gates, Cost (with working "All costs →"), Environment, Recent activity (with working "All activity →").
- **FR-10** Header per D12; cost appears exactly once in the header.
- **FR-11** Pipeline band shows truthful sublabels including explicit skip reasons, and live merge progress in the Ship step during a merge.
- **FR-12** Done-state and pre-work states match the mockup's variants: done shows the postmortem header (emerald Done badge, merged commit, review summary); pre-work shows the teaching empty state with `StartAgentCta` (model/harness overrides preserved).
- **FR-13** All issue actions continue to render from the registry; the overflow menu exposes all groups with disabled-with-reason entries.

### Non-functional

- **NFR-1** `issue-view-no-loss.test.ts` passes with its expectation lists and counts updated in the same change; every old cockpit section has a recorded home or relocation. No surface is silently dropped.
- **NFR-2** `issue-actions-surface-parity.test.tsx` passes unmodified (no surface-local actions introduced).
- **NFR-3** Style-guide conformance (`design/style-guide/STYLE-GUIDE.md`): DM Sans ≤ 500 weight, SF Mono only for identifiers, badge tint 8%/32%, blue=machine, amber=human-must-act, emerald=outcome, cyan=money, purple=live specialist activity, red only broken/destructive.
- **NFR-4** No new endpoints, polling loops, or stores — `IssueViewModel` contract (`docs/ISSUE-VIEW.md` §Data model) holds; reuse existing query hooks and keys.
- **NFR-5** `npm run typecheck`, `npm run lint`, `npm test` (root + frontend) green.
