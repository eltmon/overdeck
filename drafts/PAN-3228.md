# PAN-3228 — needs_input gates all destructive recovery; operator answer path for pane menus

**Issue:** https://github.com/eltmon/overdeck/issues/3228
**Author:** planning agent (claude-fable-5), 2026-07-28, auto mode.

## Glossary

- **Pending operator decision** — a live blocking prompt only a human may answer: a Claude Code tool-permission menu, an AskUserQuestion (AUQ), a session-resume gate, a disambiguation/confirmation menu. Detected two ways: (a) pane detection — `detectAwaitingInputFromPaneSync` / `detectAwaitingInputForAgent` in `src/lib/agent-input-detection.ts:209/:337` returning an `AwaitingInputDetection` with a `reason`; (b) JSONL scan — `scanPendingInputsPromise` in `src/lib/agent-enrichment.ts` finding unanswered AUQ tool_uses (survives session death).
- **Destructive recovery** — any autonomous or CLI action that kills or replaces an agent's live session or wipes its saved session state: `pan start --fresh` (`prepareFreshWorkAgentSession`, `src/cli/commands/start-fresh-session.ts:38`), `restartAgent()` (`src/lib/agents/recovery.ts:67`), the deacon dead-end respawn branch (`src/lib/cloister/deacon.ts:1806-1867`), and the REST restart family in `src/dashboard/server/routes/agents/lifecycle-restart.ts`.
- **Pane choice menu** — a numbered TUI menu parsed from a tmux pane by `parsePaneChoiceMenu` (`src/lib/pane-choice-menu.ts:139`); `paneChoiceMenuSignature` (`:275`) fingerprints it; `buildChoiceKeystrokes` (`:285`) produces the arrow/enter keystrokes to answer it. PAN-3113 shipped a full answer stack for **conversations** (`handleConversationPaneChoiceAnswer`, `src/lib/overdeck/conversation-pane-choice.ts:100`; route `POST /api/conversations/:id/pane-choice`, `src/dashboard/server/routes/conversations.ts:629`). Agents have no equivalent.
- **needs-you trip** — a durable one-per-open-obligation operator escalation; the dead-end pattern is `recordDeadEndNeedsYou` (`src/lib/cloister/dead-end-trip.ts`, used at `deacon.ts:1772,1816`).
- **Redrive gate** — `decideAgentAutonomousRedrive` / `decideAutonomousRedrive` in `src/lib/cloister/redrive-gate.ts:25-53`, the shared admission check for autonomous re-drive (entry points `dead-session-rework`, `swarm-slot-requeue`). Delegates to `getAgentResumeGateBlockReason` / `decideResumeGate` (`src/lib/agents/agent-state.ts:753/:783`), which classify only persisted state.json fields (paused / troubled / stoppedByUser / failure-backoff) — never live pending input.
- **Blocking reasons** — `BLOCKING_AWAITING_INPUT_REASONS` (`src/lib/agent-enrichment.ts:129-137`, module-private): `tool_permission`, `user_question`, `disambiguation`, `confirmation`, `planning_done`, `session_resume`, `rate_limit`. The predicate `isBlockedOnPendingInput` (`:144`) is the PAN-3070 single source for "this agent is parked".

## Incident summary (verified from the issue, 2026-07-28)

agent-pan-2882 froze on a Claude Code `&`-background-operator permission menu (auto-approve hook cannot clear it). Enrichment correctly reported `needs_input` / `tool_permission`. The deacon nudge was correctly aborted by the pane-choice-menu guard. Then the flywheel ran `pan start pan-2882 --fresh` — which (per PAN-3150, `start-fresh-session.ts:17-24`) kills the live session itself and wipes the agent dir — destroying the pending decision, discarding session context, and blanking the conversation view. Root cause: **no destructive-recovery path consults pending input, and no non-destructive verb exists to answer the prompt** (the PAN-3150 closed-loop shape; PAN-987's Channels relay is dead).

## Decisions (made in this document)

- **D1 — Gate at the destructive chokepoints with a new live-detection helper; keep `getAgentResumeGateBlockReason` pure.** The resume-gate classifier takes persisted state fields only; pending input is live pane/JSONL state. A new async helper (`detectPendingOperatorDecision`, Work Item 1) is called by each destructive path. `decideAgentAutonomousRedrive` becomes async and consults it internally so every redrive entry point inherits the gate.
- **D2 — Blocking set for destructive recovery = `tool_permission`, `user_question`, `disambiguation`, `confirmation`, `planning_done`, `session_resume`, **plus** a non-empty JSONL AUQ scan. `rate_limit` is excluded**: a rate-limit wait is not an operator decision, and gating on it would park agents that recovery can legitimately cycle. The JSONL AUQ check makes the gate meaningful even for dead sessions (a fresh respawn abandons an unanswered AUQ).
- **D3 — Operator override is `--force` / `{force: true}`, never implicit.** `pan start --force` already means "clear a paused gate and start anyway" (`src/cli/index.ts:515`); it now also overrides the pending-decision gate. The REST restart routes accept `force` in the body. The flywheel is doctrine-forbidden from using `--force` (Work Item 8). No actor-identity sniffing — the gate refuses everyone equally without force.
- **D4 — The answer path reuses the shipped PAN-3113 keystroke mechanism (tmux `sendRawKeystroke` + signature verification), not a new PTY-supervisor endpoint.** The supervisor only injects text (`src/lib/channels/pty-supervisor.ts:405-491` — single POST endpoint, `content` payload); menus need arrow/enter keystrokes. `sendRawKeystroke` (`src/lib/tmux.ts:1125`) is already the mechanism for codex approvals and conversation pane choices, works for every harness, and needs no supervisor protocol change. The conversation handler's session-scoped core is extracted and shared (Work Item 5). This supersedes PAN-987.
- **D5 — Scope split: the dashboard decision-card answer UI ships as a sibling issue.** `pan answer` (Work Item 7) plus the agent REST route (Work Item 6) fully close the PAN-3150 loop — a non-destructive answer verb exists for both terminal and API callers. Rendering the parsed menu on the agent decision card requires plumbing `pendingPaneChoice` through contracts schema → enrichment service → read model → store → `useDecisions` → `DecisionsPanel` (~10 more files), which would push this plan past the 25-file finalize lint. That UI slice is independently shippable and is filed as **PAN-3235** (https://github.com/eltmon/overdeck/issues/3235), blocked on this issue's route + shared core.
- **D6 — Gate refusals from autonomous contexts emit a needs-you trip** (deacon path via `recordDeadEndNeedsYou`-style durable trip). CLI refusals print an actionable message naming the pending prompt and the `pan answer` verb — the operator is already present.

## Requirements

- **FR-1** — A shared helper detects a pending operator decision for an agent id from live pane detection and the JSONL AUQ scan, honoring D2's blocking set.
- **FR-2** — `pan start --fresh` refuses to replace a live session (and to wipe state for a dead one with pending AUQ) when FR-1 detects a pending decision, unless `--force`. The refusal names the prompt and the answer verb.
- **FR-3** — `restartAgent()` and the REST restart family refuse (HTTP 409) under the same condition, unless `force`.
- **FR-4** — `decideAgentAutonomousRedrive` defers (with needs-you) when FR-1 detects a pending decision; the deacon dead-end respawn branch defers and emits a durable needs-you trip. Regression: an agent with a detected pending permission prompt is never auto-respawned or accepted for autonomous re-drive.
- **FR-5** — A session-scoped pane-choice answer core (extracted from the conversation handler, behavior-preserving) is shared by conversations and agents.
- **FR-6** — `POST /api/agents/:id/pane-choice` answers an agent's live pane menu with signature verification, mirroring the conversation route's contract (400/404/409 semantics, `answeredLabel` on success).
- **FR-7** — `pan answer <id> [option#]` lists the live menu (no arg) and answers it (with arg), through the FR-5 core.
- **FR-8** — Flywheel doctrine: a needs_input agent is parked-on-operator; emit/refresh the needs-you escalation and move on; `--fresh` and `--force` on such an agent are forbidden.
- **NFR-1** — No `execSync` in server-reachable code; async tmux primitives only; fake timers for any delay-based tests.
- **NFR-2** — The gate must not close the PAN-3150 recovery door for genuinely inert agents: no detection ⇒ no deferral; detection failures (tmux errors) fail open with a logged warning so a broken capture can never park all recovery.

## Work items

### 1. `detectPendingOperatorDecision` helper (FR-1) — foundation

**Files:** `src/lib/agents/pending-decision-gate.ts` (new), `src/lib/agents/__tests__/pending-decision-gate.test.ts` (new).

Export:

```ts
export interface PendingOperatorDecision {
  source: 'pane' | 'jsonl-auq';
  reason: AwaitingInputReason | 'ask_user_question';
  prompt?: string;
}
export const DESTRUCTIVE_RECOVERY_BLOCKING_REASONS: ReadonlySet<AwaitingInputReason>; // D2 set, no rate_limit
export async function detectPendingOperatorDecision(agentId: string): Promise<PendingOperatorDecision | null>;
```

Implementation: if the tmux session exists, run `detectAwaitingInputForAgent(agentId)` (`agent-input-detection.ts:337`, Effect — run with `Effect.runPromise`, catch `TmuxError` → fail open per NFR-2); a detection whose reason is in the D2 set returns a `pane` decision. Then (regardless of liveness) run `countPendingAskUserQuestionsForAgent(agentId)` (`agent-enrichment.ts:305`); a count > 0 returns a `jsonl-auq` decision. Otherwise null. Tests use injected fakes for both detectors (no real tmux), covering: tool_permission blocks, rate_limit passes, no-detection passes, dead-session-with-pending-AUQ blocks, detector-throw fails open.

4. The deacon dead-end pass with a detected pending permission prompt never calls `spawnWorkAgentThroughAgentsEndpoint` and records a needs-you action; `decideAgentAutonomousRedrive` returns defer+needsYou under a fake detection.

6. The agent route returns 200+`answeredLabel` on a signature-matched answer, 409 `menu-changed` on drift, 404 for unknown agents; GET returns the parsed menu payload.
7. `pan answer <id>` prints the live menu; `pan answer <id> 2` answers option 2 and exits 0 only on confirmed dismissal; both exit non-zero with a clear message when no menu is pending.
8. `roles/flywheel.md` inert-agent section instructs parking + needs-you for pending-decision agents and forbids `--fresh`/`--force` on them.
9. The three doc files contain the updates named in Work Item 9.

## Hazards / intersecting rules restated

- **No `execSync` in server-reachable code** (PAN-70). The gate helper and route use async primitives only.
- **Fake timers** for any test touching the keystroke-gap/confirm waits (`vi.useFakeTimers` or injected `sleep` fakes — the existing deps-injection pattern makes real timers unnecessary).
- **`sendKeys` (sync) is legacy** — the answer core inherits `sendRawKeystroke` (async) from PAN-3113; do not add sync tmux calls.
- **Deacon runs as a child process** — the gate must work lib-side without the dashboard read model (it does: tmux capture + JSONL scan only).
- **Fail-open on detector errors (NFR-2)** — a tmux capture failure must not park recovery; log and proceed.
- **`pan start` no-op short-circuit** (`start.ts:814`) runs BEFORE the fresh path; the gate belongs inside `prepareFreshWorkAgentSession` so both live-replace and dead-wipe cases are covered.
- **Do not answer menus Overdeck did not open** (PAN-3212): the answer path only ever sends keystrokes after signature verification against the menu on screen now.
