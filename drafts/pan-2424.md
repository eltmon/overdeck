# PAN-2424 — The Order Book: first-class operator priority queue

## Glossary

- **Order book**: a per-project, operator-authored markdown file listing *confirmed* issues to execute before anything in the backlog, with explicit ordering/dependency edges.
- **Confirmed issue**: an issue the operator has already decided to do — no triage, no pickup gate; only dependencies and load limit its start.
- **Load governor**: the existing concurrency ceiling (`cloister.concurrency`) plus live health signals (event-loop p99, memory chip state) that bound total in-flight agents.
- **Auto-pickup**: the flywheel's backlog-saturation behavior (`auto_pickup_backlog`). Order-book items are a separate class it never touches.
- **Remote overflow**: dispatching an issue's work phase to a Fly.io remote workspace when local capacity saturates.
- **Lane** (legacy term): in the proven runs, an edge-free group (Lane A) vs a serialized chain (Lane B). In the official feature, lanes are expressed as plain dependency edges — a serial chain is `blocks` edges; a parallel group has none.

## Requirements

- FR-1: A canonical per-project file `<projectRoot>/.pan/order-book.md` is parsed into `{ items: [{ issueId, position, blockedBy: issueId[], notes, uatHold?: boolean, remoteEligible?: derived }], updatedAt, sourceSha }`.
- FR-2: A read door `resolveOrderBook(projectKey)` (lib + `GET /api/projects/:key/order-book`) is the only consumer-facing access; nothing else parses the markdown.
- FR-3: A lint (wired into `npm run lint` like `scripts/lint-skills.sh`) fails when the file exists but does not parse, names an unknown issue, or contains a dependency cycle.
- FR-4: Auto-pickup exemption: `auto_pickup_backlog` logic skips any issue present in any project's order book.
- FR-5: Flywheel dispatch rule: each tick, every order-book item whose `blockedBy` are all closed/merged and whose project passes the load governor gets dispatched (plan if unplanned → start), in book order. No artificial width limit beyond the governor.
- FR-6: Item state is derived at read time from review_status + agents + tracker state. The book file itself stores no status.
- FR-7: `uatHold: true` on an item (markdown annotation) means: work fully, assemble merge trains, never merge without operator action.
- FR-8: Flywheel page panel: headline (done / in-flight / next-up) + per-item rows (position, phase chip, deps, N-of-M beads, cost so far, blocked-on). Copy follows the cockpit non-technical rules.
- FR-9: Remote overflow config `order_book: { use_remote: boolean (default false), remote_capacity: number (default 5) }` in config.yaml (comment-preserving write door; Settings UI toggle). When local governor saturates and dispatchable items remain, dispatch up to `remote_capacity` items' work phases remotely — only items whose resolved staffing is remote-eligible (today: Anthropic model + claude-code harness).
- NFR-1: No new state plane — parser output is cache-only, rebuilt from the markdown (single-source rule).
- NFR-2: Book edits reach the flywheel on its next tick without restarts (mtime-based cache like config-yaml `load.ts`).
- NFR-3: All copy in the panel passes the operator-facing plain-language rules.
