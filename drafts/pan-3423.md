# PAN-3423 — Redesign the SystemHealthPill popover: attention-grouped reasons, metered vitals, actionable agent alerts

## Glossary

- **SystemHealthPill** — the sidebar pill component at `src/dashboard/frontend/src/components/SystemHealthPill.tsx` showing overall system-health state; clicking it opens the **popover**, the panel this PRD redesigns.
- **HealthReason** — the contract object (`packages/contracts/src/system-health.ts:26-35`) carrying one finding: `code` (e.g. `agent.runtime.inactive.stalled`), `domain` (`host` | `admission` | `agent` | `service`), `severity` (`info` | `warning` | `critical`), `message`, optional `metric`/`observed`/`threshold`.
- **Attention item** — NEW presentational concept: one row in the redesigned "Needs attention" section, derived from one or more `HealthReason`s plus the `agents`/`topConsumers` snapshots.
- **Context note** — NEW presentational concept: a `severity: "info"` reason rendered inside a collapsed disclosure instead of the main list.
- **No-loss audit test** — `src/dashboard/frontend/src/components/system-health-ui-no-loss.test.tsx`, the gate that proves every old popover affordance has a home in a refactor. Must be updated in the same change, never deleted.
- **xBRIEF / spec** — Overdeck's machine-readable plan format; not modified by this work.

## Problem

The popover's most important information — *what needs the operator's attention right now* — is a flat bullet list (`SystemHealthPill.tsx:401-407` renders `• {reason.message}` for every reason from `healthReasons()`, lines 68-75, which flattens host + admission + all agents + all services reasons into one array). Observed live on 2026-08-01:

- Informational disclaimers ("Swap occupancy is historical context…") render in the same list, at the same weight, as stall alerts — nothing distinguishes "FYI" from "act now".
- Identical warnings repeat verbatim once per agent ("The active agent has produced no activity for 53 minutes." appeared twice in a row).
- Durations render as raw minutes ("2946 minutes" instead of "49 h").
- The message says "The active agent" without naming which agent (`src/lib/agents/health.ts:225-235` emits this copy server-side).
- No row offers an action; the operator must cross-reference the Top consumers list below by hand.

Secondary issues: the metric tiles are text-only (44.3/62.6 GB doesn't read as ~71% full), three low-value tiles (admitted agents, containers, relay) consume a full grid row each, and Top consumers rows have no proportional size cue.

## Approved design

The operator approved an interactive mockup on 2026-08-01, at
`/home/eltmon/Projects/overdeck/.tmp/system-health-panel-redesign-mockup.html`
(gitignored scratch dir; open in Chrome). It shows a side-by-side of the current
popover and the redesign, with Warning / Critical / Healthy state toggles. **The
mockup is the visual spec** — layout, spacing, and copy below are normative even
if the mockup file is later cleaned up.

Redesigned popover, top to bottom:

1. **Header** — title "System health", a state badge (`Healthy` green / `Warning` amber / `Critical` red, pill with dot), relative updated time ("Updated 12s ago"), close button.
2. **Summary line** — one synthesized sentence answering "do I need to do anything?", e.g. "2 agents stalled for ~49 h and 2 idle for ~53 min. Memory at 71% — spawn headroom is fine." Derived from the same attention model as the rows; when healthy: "All clear. 18.4 GB spawn headroom, relay running, no stalled agents."
3. **Vitals tiles (2×2)** — CPU, Memory, Overdeck share, Swap — each with a thin meter bar under the value. Bar color: green < 60%, amber 60–85%, red > 85% (CPU/memory/swap); the Overdeck-share bar is neutral blue (it is an attribution, not a pressure signal). Swap tile gets an inline ⓘ and sub-label "historical · not live pressure".
4. **Chip row** — "1 admitted agent", "51 containers", "Relay running" (green dot) — replaces the three single-value tiles and the full-width relay tile.
5. **Needs attention** — the replacement for the bullet list. One severity-dotted row per attention item: red dot for critical/stalled, amber for warning. Rows name the subject (`agent-min-864-test · MIN-864`), humanize durations, and group identical-code agent reasons into one row with a `×N` count badge and the agent names in the sub-line. Rows for agents with a kill target carry the existing Kill/Remove action; agent rows also get an **Open** action navigating to that agent's issue view. Sorted critical-first, then by duration descending.
6. **Context notes disclosure** — all `severity: "info"` reasons collapse into a `<details>`: "2 context notes — background, not pressure signals". Closed by default.
7. **Top consumers** — each row gains a kind badge (`container` / `agent` / `specialist`), a thin proportional memory bar (relative to the largest consumer), and a `LEAKED` tag + amber highlight when `consumer.leaked`. Kill/Remove buttons unchanged (existing `KillButton`, lines 157-233). Footer: "Show all N containers ↓" expander. The "Leaked specialists: N" header text becomes "⚠ N leaked specialists" when N > 0, "No leaks" otherwise.

## Requirements

### Functional

- **FR-1** — Reasons with `severity: "info"` never render in the main attention list; they render inside the collapsed context-notes disclosure, with the count in the summary line.
- **FR-2** — Agent-domain reasons sharing a `code` are grouped into one attention row with a `×N` badge; the sub-line lists the affected agent ids (truncated to 2 names + "+N more").
- **FR-3** — Agent inactivity rows name the agent and humanize the duration (minutes < 60, then hours rounded to 1 significant figure: "53 min", "49 h"). Implemented server-side in the reason message (`src/lib/agents/health.ts:225-235`) so every consumer benefits: message becomes `<agentId> has produced no activity for <humanized duration>.`
- **FR-4** — Each vitals tile (CPU, Memory, Overdeck share, Swap) renders a meter bar; thresholds per the design above; null metrics render "Unavailable" with no bar (never a zero bar — null is not zero, per the contract comment at `system-health.ts:47-50`).
- **FR-5** — Admitted work agents, container count, and webhook-relay status render as a chip row, not tiles. Relay chip shows a green dot when running, red when stopped/unavailable, gray when not configured.
- **FR-6** — Attention rows for agents with `killTarget` render the existing Kill flow (reuse `KillButton`, lines 157-233, do not reimplement); agent rows render an **Open** action linking to the agent's issue view (same navigation target as clicking the agent elsewhere in the dashboard).
- **FR-7** — Top consumer rows render kind badge, proportional memory bar, and leaked tag/highlight when `consumer.leaked === true`.
- **FR-8** — The summary line synthesizes from the attention model: counts of stalled/idle agents, memory percent, admission headroom. Healthy state renders the "All clear" variant and the Needs-attention section is replaced by a single all-clear row.
- **FR-9** — The critical-state toast (`SystemHealthPill.tsx:249-288`) and its "Open" action keep working; the leaked-highlight flow (`highlightLeakedOnly`) is preserved.

### Non-functional

- **NFR-1** — No contract changes: `packages/contracts/src/system-health.ts` is untouched. The redesign is presentational plus the FR-3 server copy change (message text only, not schema).
- **NFR-2** — The grouping/humanization logic lives in a pure, unit-testable module (new file `src/dashboard/frontend/src/lib/system-health-attention.ts`), not inline in the component.
- **NFR-3** — Popover width, position, and keyboard/Escape/outside-click behavior (lines 243-266, 342-348) are unchanged.

### 2. Frontend: pure attention-model module

New file `src/dashboard/frontend/src/lib/system-health-attention.ts`. Export:

```ts
export interface AttentionItem {
  severity: 'critical' | 'warning';
  code: string;
  title: string;            // e.g. 'agent-min-864-test · MIN-864' or 'Spawn admission blocked'
  sub: string;              // e.g. 'no activity for 49 h — stalled'
  agents: string[];         // agent ids grouped into this row (1 for singletons)
  agentId?: string;         // set when exactly one agent — drives Open/Kill actions
}
export function buildAttentionItems(snapshot: SystemHealthSnapshot): AttentionItem[];
export function contextNotes(snapshot: SystemHealthSnapshot): HealthReason[]; // severity === 'info'
export function summaryLine(snapshot: SystemHealthSnapshot, items: AttentionItem[]): string;
```

Grouping rule: key = `reason.code`; agent-domain reasons resolve their agent via `snapshot.agents` (match by position — `agents[i].reasons` belongs to `agents[i]`); host/admission/service reasons are always singletons titled by the existing `reasonLabel()` mapping (lines 77-123 — extract it into this module and reuse). Sort: critical severity first, then warning; within a severity, stalled before idle. `summaryLine` produces the FR-8 sentence from item counts + `host.metrics.memoryUsedPercent` + `admission.availableMemoryBytes`.

Unit tests: `tests/unit/frontend/system-health-attention.test.ts` (follow the existing frontend test setup — see `SystemHealthPill.test.tsx` for the snapshot-fixture pattern; `createSnapshot()` helper there is the model). Cover: info reasons excluded from items and returned by `contextNotes`; two agents with the same code group into one `×2` item; stalled sorts before warning; healthy snapshot yields empty items and the all-clear summary.
