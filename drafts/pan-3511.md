## 1. Glossary

- **Verdict** — the terminal outcome of one review cycle: `passed` | `blocked` | `failed`.
- **Verdict artifact** — the durable file a finished reviewer writes: `.pan/review/<runId>/synthesis.md` (convoy) or `.pan/review/<runId>/review.md` (quick/self review). **The verdict of record.**
- **Review row** — the `review_status` row (SQLite `overdeck.db`, mirrored journal). Derived, lagging, **never authoritative**.
- **Convoy review** — 4 lens sub-reviewers + a synthesis parent (PAN-1862).
- **Quick / self review** — one agent reviews all dimensions in one pass and signals via `pan specialists done review <id> --status …` (PAN-1981; the fleet default per `roles/review.md:40`).
- **Head anchor** — the commit a verdict/verification ran at: `lastVerifiedCommit` (verification), `reviewedAtCommit` / `reviewerVerdicts[].atCommit` (review).
- **Orphan patrol** — `reconcileReviewStatusOrphan()` in `src/lib/cloister/deacon-review-status.ts:543` — resets `reviewing` rows with no live convoy.
- **Fallback synthesis** — `monitorReviewConvoySignals()` in `src/lib/cloister/deacon-review-signals.ts:180` — synthesizes from on-disk lens reports when the convoy parent is wedged/dead.
- **Write door / read door** — the Overdeck two-doors tenet: one canonical writer, one canonical resolver per domain; nothing else touches the store.

## 2. Problem statement (why this exists)

On 2026-08-02 PAN-1577 lost **five** APPROVED verdicts in one evening. The full chain, verified end to end:

1. A rework agent pushed commits; the row's `lastVerifiedCommit` stayed stale at the old head.
2. The deacon fallback synthesized APPROVED at the fresh head and wrote it through `setReviewStatusSync` — and `rejectVerdictEvidenceHeadMismatch` (`src/lib/review-verdict-guards.ts:69`, invoked at `src/lib/review-status.ts:196`) **silently rejected the write** (fresh evidence head ≠ stale anchor). Row's `updatedAt` never moved — proof the verdict never landed.
3. The fallback ran `killSession(state.id)` **unconditionally** (`deacon-review-signals.ts:247`), destroying the convoy regardless of the rejected write.
4. The orphan patrol (`deacon-review-status.ts:606`) read a dead-looking row and reset it to `pending`, retry 5/3.

Root cause is not any one of those; it is the **accreted architecture**: ≥4 verdict writers (coordinator, fallback, quick-agent signal, journal reconcile), ≥4 verdict clearers (orphan reset, regression guards, head-mismatch guard, stuck markers), **zero shared contract** for "what is the verdict, where does it live, who may write/clear it, and what is the honest next step from any state." Quick mode has no fallback writer at all, so its verdict is even more exposed when the agent dies between artifact and signal.

## 3. Solution — the verdict-of-record contract

Four clauses. Everything in this PRD is one of these clauses being made true.

1. **The artifact is the verdict.** Both shapes are read through `readLatestSynthesisVerdict()` (freshness-bounded to 30 min, carries head evidence when present). *(Landed.)*
2. **One verdict write door.** Every verdict — coordinator synthesis, fallback, quick-agent signal, orphan restore, sweeper restore — flows through `recordReviewVerdict()`. The verification-head contract becomes **dispatch, not drop**: a fresh-head verdict LANDS and triggers a verification re-run instead of being silently rejected.
3. **Every recovery path reads the artifact before acting.** A fresh artifact's verdict wins over the row's history everywhere: orphan reset *(done)*, feedback-target stuck-setting, infra-failure stuck-setting, sweeper stuck re-drive, journal-vs-artifact disagreement.
4. **Guards become dispatchers, not destroyers.** No guard may delete a verdict silently; every rejection must emit an event and route the honest next step (re-verify / re-dispatch / restore).

## 4. Requirements

**Functional**

- FR-1 `recordReviewVerdict(issueId, input)` in a new `src/lib/cloister/review-verdict-writer.ts`: one function that (a) writes/refreshes the artifact evidence, (b) updates the row via `setReviewStatusSync` (`src/lib/review-status.ts:156`), (c) emits the domain event, (d) returns an explicit `{ landed: true } | { landed: false; reason }` outcome. (traces WI-2)
- FR-2 All four verdict writers migrate to FR-1's door: fallback (`deacon-review-signals.ts:230`), quick-agent signal (`src/cli/commands/specialists/done.ts`), coordinator/synthesis path, and the two restore sites (orphan restore at `deacon-review-status.ts:594`, sweeper restore). (traces WI-2)
- FR-3 The head-mismatch behavior changes from silent drop to **accept + dispatch**: when the verdict's evidence head is fresher than `lastVerifiedCommit`, the write door lands the verdict and dispatches a verification re-run at the evidence head. When the evidence is OLDER than the anchor (a genuinely stale verdict), the write is rejected WITH a domain event + activity entry, never silent. `rejectVerdictEvidenceHeadMismatch` (`review-verdict-guards.ts:69`) is removed from the write path of verdicts of record (it may persist for non-verdict writes). (traces WI-3)
- FR-4 The fallback never kills on an assumed write. `killSession(state.id)` at `deacon-review-signals.ts:247` runs ONLY when the write door returned `landed: true`. (traces WI-4)
- FR-5 `feedback-target.ts:267` and `deacon-review-status.ts:378,621` consult `readLatestSynthesisVerdict()` before marking stuck; a fresh `passed` artifact restores the row instead of marking. (traces WI-5)
- FR-6 The sweeper's stuck-flag path (`src/lib/cloister/stall-sweeper.ts:350`) consults the artifact first: fresh `passed` → restore (no re-drive); fresh `blocked`/`failed` → re-drive with the artifact's blocker as feedback. (traces WI-6)
- FR-7 Journal-vs-artifact disagreement in `reconcileInFlightJournals` (`src/lib/cloister/advancing-selfheal.ts:65`): artifact wins; the journal is transport, never a second source of truth. (traces WI-7)
- FR-8 Docs: `docs/REVIEW-AGENT-ARCHITECTURE.md` gains the contract + the two-mode artifact/signal/recovery table (already drafted in the issue's design comment). (traces WI-8)

**Non-functional**

- NFR-1 No silent verdict loss anywhere: every rejected or superseded verdict produces a domain event + activity entry with the reason. (all WIs)
- NFR-2 Both review modes (convoy, quick) are covered by every clause — fixture tests use BOTH artifact filenames. (all WIs)
- NFR-3 Additive-only migration of existing rows; no history rewrite.
- NFR-4 Every changed path keeps its current behavior when NO artifact exists (empty-result paths must not regress: an absent artifact means "no evidence," not "approve").

## 5. Decisions (made — do not re-litigate)

- **Dispatch, not drop.** A fresh-head verdict is truth about what the reviewer saw; verification is the merge gate's problem and re-runs cheaply. Silently dropping verdicts is how PAN-1577 happened.
- **The artifact, not the journal, is the verdict of record.** The journal is a transport with lag; the artifact is authored by the reviewer.
- **Both modes stay.** Convoy and quick review coexist; the contract is mode-agnostic. The mode-selection drift (`roles/review.md` says convoy disabled, code runs convoys) is out of scope — note it on the issue for a later mode-policy pass.
- **Freshness bound 30 min** for honoring artifacts in recovery (prevents old-cycle resurrection). Already shipped in `SYNTHESIS_ARTIFACT_FRESH_MS`.

### WI-3 The verdict write door + dispatch-not-drop

**What/why:** create `src/lib/cloister/review-verdict-writer.ts` exporting:

```ts
export interface VerdictInput {
  verdict: 'passed' | 'blocked' | 'failed';
  notes?: string;
  runId?: string;
  evidenceHead?: string;          // commit the review ran at (fresh evidence)
  reviewerVerdicts?: ReviewStatus['reviewerVerdicts'];
  writer: 'coordinator' | 'fallback' | 'quick-signal' | 'orphan-restore' | 'sweeper-restore';
}
export type VerdictOutcome = { landed: true } | { landed: false; reason: string };
export async function recordReviewVerdict(issueId: string, input: VerdictInput): Promise<VerdictOutcome>
```

Behavior:
1. Read the row via `getReviewStatusSync`.
2. If `input.evidenceHead && status.lastVerifiedCommit && input.evidenceHead !== status.lastVerifiedCommit`:
   - If the evidence head is an **ancestor-or-equal of the row's head evidence** (genuinely stale) → return `{ landed: false, reason: 'stale-evidence-head' }` AND emit domain event `review.verdict_rejected` + activity entry. Staleness check: `git merge-base --is-ancestor <evidenceHead> <lastVerifiedCommit>` in the workspace (async — `execFileAsync`, never execSync).
   - Otherwise (evidence is FRESHER) → land the verdict AND dispatch verification re-run at `evidenceHead` (call the existing verification dispatch used by `runVerificationForIssue` in `src/lib/cloister/verification-runner.ts`), then continue to step 3.
3. `setReviewStatusSync(issueId, { reviewStatus: input.verdict, reviewNotes: input.notes, reviewerVerdicts: input.reviewerVerdicts, ...(input.evidenceHead ? { reviewedAtCommit: input.evidenceHead } : {}) })`.
4. Emit `review.status_changed` (already the write door's behavior) + an `activity.entry` sentence naming the writer.
5. Return `{ landed: true }`.

**Files:** new `src/lib/cloister/review-verdict-writer.ts`; `src/lib/review-status.ts` (the `rejectVerdictEvidenceHeadMismatch` call at :196 becomes conditional — skipped when the update carries `x-verdict-of-record: true` OR removed once all writers migrate; decide at implementation: keep the guard for non-door writers only).

**Migrate the writers:**
- Fallback (`deacon-review-signals.ts:230-244`): replace the direct `setReviewStatusSync` call with `recordReviewVerdict(..., writer: 'fallback')`; gate `killSession` (WI-4).
- Quick signal (`src/cli/commands/specialists/done.ts`): route the verdict write through the door with `writer: 'quick-signal'`.
- Coordinator/synthesis completion path (where the live synthesis parent POSTs its verdict — locate via `grep "reviewStatus: 'passed'" src/lib/cloister/`): route through the door.
- Orphan restore (`deacon-review-status.ts:594`) and sweeper restore: route through the door with `evidenceHead: artifact.headSha`.

**Tests:** `src/lib/cloister/__tests__/review-verdict-writer.test.ts` —
- fresh-head verdict lands + verification dispatch fires (mock dispatch) + event emitted;
- stale-head verdict → `{landed:false}` + event + NO row change;
- no evidence head → lands (current quick-mode behavior preserved);
- row update carries notes/reviewerVerdicts/reviewedAtCommit.
