## Glossary

Define-before-use; every term of art in this document appears here first.

- **Annotation** — one operator comment anchored to a location in the rendered app: `{ comment, anchor }` where the anchor carries a CSS selector, an `outerHTML` snippet, a bounding box, the page URL, and (best-effort) the React component's source `file:line`.
- **Batch** — the set of annotations the operator accumulated in one Preview session and sends to the agent as a single message. Batches are ephemeral: they are never persisted as canonical state.
- **Pin** — the numbered visual marker the overlay draws at an annotated element.
- **Overlay** — a self-contained JavaScript file Overdeck injects into the previewed app's HTML. It implements annotate mode (hover highlight, click-to-pin, comment box) and reports annotations to the dashboard via `postMessage`.
- **Preview host** — the existing per-workspace Traefik hostname serving the workspace's frontend, e.g. `feature-pan-2685.overdeck.localhost`. Computed in `src/dashboard/server/routes/workspaces/workspace-data.ts:525-528` (`` let frontendUrl = `https://${featureFolder}.${dnsDomain}` ``).
- **Annotated preview host** — the NEW hostname this PRD introduces, `preview-feature-<issue>.{domain}`, routed by Traefik to the dashboard server, which reverse-proxies the preview host and injects the overlay. "We own the proxy" is the whole trick: no per-project setup, no app changes.
- **Preview proxy** — the dashboard-server module implementing that reverse proxy (HTML injection, header stripping, WebSocket passthrough).
- **Anchor / source mapping** — resolving a clicked DOM element to its React component and source file:line via React's dev-build fiber debug info (the technique used by MIT-licensed `react-dev-inspector` and LocatorJS). Best-effort: when unavailable, the anchor is selector + `outerHTML` only.
- **Work agent** — the running implementation agent for the issue, resolved from the SQLite agents table (the runtime read door, PAN-1908).
- **Delivery door** — `deliverAgentMessage(agentId, message, caller)` in `src/lib/agents/delivery.ts:177`, the single primitive for sending a message to a running agent (PTY supervisor → Channels → tmux tiers). This PRD adds no new delivery path.
- **Issue cockpit** — the per-issue dashboard view, `src/dashboard/frontend/src/components/Stage/cockpit/IssueMissionControl.tsx`, whose tabs are declared in the `MissionTab` union (line 53) and `TABS` array (line 72).
- **HMR** — hot module replacement; dev servers (Vite etc.) keep a WebSocket open to the page. The preview proxy must pass these upgrades through or the previewed app breaks.

## Background and prior art

OpenAI Codex ships an in-app browser with an annotation mode: click an element or drag a region, write a comment, and the batch is consumed by the agent as instructions anchored to visual selectors (https://developers.openai.com/codex/app/browser). Open-source prior art for element→source mapping: `react-dev-inspector` (MIT, https://github.com/zthxxx/react-dev-inspector) and LocatorJS (MIT). stagewise (https://github.com/stagewise-io/stagewise) is the closest full product but is **AGPLv3 — design reference only; never vendor or import its code into Overdeck.**

Out of scope for this issue (file follow-ups; do NOT implement here): rrweb DOM-mirroring transport for remote/Fly workspaces, CDP-screencast hosted browser, Electron `WebContentsView` desktop preview, stagewise CLI integration.

## Requirements

Functional:

- **FR-1** The issue cockpit has a new **Preview** tab that embeds the annotated preview host for the issue's workspace in an iframe, alongside a panel listing pending annotations and a send action.
- **FR-2** The dashboard server reverse-proxies `preview-feature-<issue>.{domain}` to the workspace's preview host: HTML responses get the overlay `<script>` injected and framing-hostile headers (`content-security-policy`, `x-frame-options`) stripped; all other responses pass through byte-for-byte; WebSocket upgrades (HMR) pass through.
- **FR-3** The overlay implements: annotate-mode toggle (driven by the parent via `postMessage`), hover element highlight, click-to-pin with comment input, Shift+drag region selection (bbox-only anchor), numbered pins, Esc to exit mode.
- **FR-4** Each annotation captures: comment, CSS selector, `outerHTML` snippet (truncated to 500 chars), bounding box, `location.href`, viewport `{width, height, dpr}`, React component display-name chain, and best-effort source `file:line`.
- **FR-5** The Preview tab receives annotations via `postMessage`, lists them (edit comment / delete), and submits the batch.
- **FR-6** `POST /api/issues/:issueId/annotations` validates the batch and returns 422 on malformed payloads.
- **FR-7** The route resolves the issue's running work agent from the agents table; if none is running it returns **409** `{ error: 'no-running-work-agent' }` and the UI explains that annotations are delivered to a running agent and how to start one. Decision rule: **no running work agent ⇒ 409; never auto-spawn.**
- **FR-8** On submit, the server captures screenshots via Playwright (already a root dependency, `package.json:186`): one viewport screenshot with numbered boxes drawn at each annotation's bbox, plus one clip per annotation; saved under `<workspace>/.overdeck/annotations/<batchId>/`.
- **FR-9** The server formats the batch into one operator-message (exact template below) and delivers it via `deliverAgentMessage(agentId, message, 'annotations-api')`.
- **FR-10** Documentation ships with the feature (work item 8).

Non-functional:

- **NFR-1** No `execSync` anywhere in server-reachable code (PAN-70 rule) — Playwright and all proxy I/O are async.
- **NFR-2** Boot-path safety: the proxy is wired like the existing WebSocket setups and must not break server boot; the change is runtime-boot-tested before touching the live server (rule restated below).
- **NFR-3** No new runtime dependencies. Use node `http`/`https`, existing `ws` (`package.json:164`), existing `playwright` (`package.json:186`).
- **NFR-4** The overlay reaches user apps ONLY via proxy injection on the annotated preview host — never via project build changes; the plain preview host stays untouched.
- **NFR-5** Annotations and batches are ephemeral (screenshots on disk are workspace runtime files, gitignored). No new canonical-state plane, no new read/write doors (single-source-of-truth tenet).
- **NFR-6** `postMessage` is origin-checked in both directions.

## Architecture decisions (made here; do not re-litigate downstream)

- **D-1 Subdomain proxy, not path-prefix.** A path proxy (`/preview/<issue>/…`) breaks absolute asset URLs (`/assets/x.js` would hit the dashboard root). The annotated preview host is a sibling subdomain, so absolute paths resolve against the proxy naturally.
- **D-2 Proxy upstream = the existing preview host through Traefik** (`https://feature-<issue>.{domain}`), not container internals. Traefik already terminates TLS with locally-generated certs; the proxy's HTTPS client must trust that local CA (see checkpoint C-1).
- **D-3 Transform only `text/html`.** Request upstream with `accept-encoding: identity` so injection needs no gunzip. Decision rule: content-type is not `text/html` ⇒ byte-for-byte passthrough, headers untouched except hop-by-hop.
- **D-4 Injection point:** insert `<script src="/__overdeck/annotation-overlay.js" data-overdeck-dashboard-origin="<dashboard origin>"></script>` immediately before `</head>` (case-insensitive first match); if no `</head>`, before `</body>`; if neither, append. The proxy serves `/__overdeck/annotation-overlay.js` itself (never forwarded upstream).
- **D-5 Source mapping is best-effort.** Resolve the DOM node's React fiber via the `__reactFiber$…` expando key, ascend to the nearest fiber with `_debugSource` (React ≤ 18); React 19 removed `_debugSource`, so fall back to the `_debugOwner` display-name chain. Decision rule: fiber unavailable ⇒ anchor is selector + outerHTML only; never block annotation on mapping failure.
- **D-6 Screenshots are best-effort context, not the anchor.** Server-side capture re-renders the annotated URL fresh (auth/SPA state may differ from the operator's session); the authoritative anchor is selector + source file:line. Playwright launches chromium with `ignoreHTTPSErrors: true` (local Traefik certs only).
- **D-7 Delivery target is the issue's running work agent** — most-recent `role === 'work'` agent for the issue, the exact pattern of `projectAgentHarnessModel` in `src/lib/pan-dir/records.ts:183` (filter `listOverdeckAgentStatesSync()` by `issueId`, `role === 'work'`, sort by `startedAt` desc).

### 3. Annotation overlay script (traces: FR-3, FR-4, NFR-4, NFR-6)

**Files:** new `src/dashboard/overlay/annotation-overlay.ts`; build entry in root `tsdown.config.ts` (root config builds CLI/server — see CLAUDE.md "Build configs").

Self-contained, no imports from the rest of the codebase, no external deps. Behavior:

- Reads `data-overdeck-dashboard-origin` from its own `<script>` tag; ignores every `message` event whose `event.origin` differs from it; posts all messages to `window.parent` with that origin as `targetOrigin` (NFR-6).
- Protocol (all messages `{ type: 'overdeck:…', … }`): overlay→parent `overlay-ready`, `annotation-added` (full annotation payload), `annotation-updated`, `annotation-removed`; parent→overlay `set-mode {annotate: boolean}`, `clear-pins`, `remove-pin {id}`.
- Annotate mode: `mousemove` → `elementFromPoint` → outline via a fixed-position highlight box (never mutate the app's DOM nodes; the overlay renders inside a single `<div id="__overdeck-overlay">` with maximal `z-index`). Click → pin + floating comment `<textarea>`; Enter saves, Esc cancels. Shift+drag → region bbox annotation (no element anchor). Esc exits annotate mode.
- Metadata capture per FR-4. CSS selector builder: id if present, else shortest unique path of `tag.class:nth-of-type` segments (port the approach from react-dev-inspector, MIT — port/reimplement, do not import stagewise/AGPL code). Fiber walk per D-5: find object key starting `__reactFiber$` on the node or ancestors; ascend `.return` to nearest `_debugSource` (`{fileName, lineNumber}`); collect `_debugOwner` display names for the component chain.

Build: add a second tsdown entry producing a single-file IIFE for the browser, output `dist/dashboard/annotation-overlay.js`. **Checkpoint C-2:** verify tsdown supports a per-entry `platform: 'browser'` / `format: 'iife'` in this repo's version; **fallback:** a dedicated small `tsdown.config.ts` in `src/dashboard/overlay/` (mirroring how `scripts/` and `packages/contracts/` have their own configs — see CLAUDE.md "Build configs") wired into `npm run build`.

**Tests:** frontend/jsdom vitest: selector builder uniqueness, fiber-walk returns null gracefully on non-React DOM, `injectOverlayTag`-consumed attributes read correctly, origin filtering drops foreign messages.
