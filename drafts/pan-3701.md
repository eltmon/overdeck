## 0. Glossary (define-before-use)

- **First-party LLM call** — a request where Overdeck's own code authors the prompt, selects the model, and programmatically consumes the output. Distinct from **harness traffic** (claude-code/codex/etc. agent processes making their own API calls), which is out of scope by definition.
- **HTTP-transport site** — a first-party call made over HTTP (raw `fetch` or an SDK). **CLI-transport site** — a first-party call whose transport is a subprocess (`claude -p`, `omp --mode rpc`) with structured-output flags. This PRD migrates HTTP-transport sites only (D-8).
- **`effect/unstable/ai`** — the AI module of the unified `effect` package, already present at the pinned `effect@4.0.0-beta.73` (root `package.json`). Relevant pieces: `LanguageModel` (`node_modules/effect/src/unstable/ai/LanguageModel.ts:110`, service with `generateText`/`generateObject`/`streamText`), `LanguageModel.make` (`:786` — a provider implements just two hooks: `generateText` and `streamText` over `ProviderOptions`), `EmbeddingModel.make` (`node_modules/effect/src/unstable/ai/EmbeddingModel.ts:239` — one hook, `embedMany`, with built-in request batching via `RequestResolver`), `Tool`/`Toolkit` (typed tool calling), `AiError`.
- **`ExecutionPlan`** — `node_modules/effect/src/ExecutionPlan.ts`: Effect's built-in try-A-then-B-with-schedule plan primitive, purpose-built for provider/model fallback.
- **Adapter** — an in-repo `LanguageModel.make` / `EmbeddingModel.make` implementation targeting a wire shape (Anthropic-messages or OpenAI-chat), parameterized by base URL + headers. **No upstream provider packages exist for Effect v4 yet — writing thin adapters is the design, not a stopgap.**
- **Cost write doors** — the two existing sinks first-party calls already use: `recordBackgroundAiCost` (`src/lib/background-ai/cost.ts:56-90` → `appendCostEventSync`) and `recordExtractionCost` (`src/lib/memory/providers/types.ts:97-128` → `insertCostEventSync`). They remain the only cost paths (D-6).
- **Background-AI registry** — `BACKGROUND_AI_FEATURES` (`src/lib/background-ai/registry.ts:10-19`), the canonical list of 8 first-party AI features, gated by `isBackgroundFeatureEnabled` (`src/lib/background-ai/features.ts`).

### Cross-cutting census findings this PRD fixes

1. **No LLM call uses `Effect.retry`/`Schedule`** — the only "retry" is the memory policy's two-provider loop (`src/lib/memory/providers/policy.ts:34-69`), a shortened-prompt retry in compaction, and 2-attempt schema loops in `extract.ts`/`rollup.ts`.
2. **Three fallback mechanisms** coexist: `model-fallback.ts` tier logic, memory `fallbackChain` policy, and "none" (A1, B3, A5).
3. **Two Vercel-SDK consumers are the only ones** (B2, B3) — migrating both removes the `ai` and `@ai-sdk/openai` dependencies.
4. **No first-party site streams** — every call awaits a full response (D-4 exploits this).

## 2. Locked design decisions

- **D-1 — One door: `src/lib/ai/`.** All first-party model calls go through a new module family `src/lib/ai/` (the single-source-of-truth tenet applied to first-party AI). After this issue, a raw `fetch` to a model endpoint or a model-SDK import outside `src/lib/ai/` (and the out-of-scope list above) is a defect.
- **D-2 — Anchor `effect@4.0.0-beta.73`. This work does NOT upgrade Effect.** The `Schema.Defect` drift between beta.73 and beta.78 (`packages/effect-acp/VENDORING.md`, "Effect 4.0.0-beta.73 compatibility edits") is the documented precedent: unstable-module APIs move between betas. Every API cited here was verified in the beta.73 tree. If an upgrade lands first, re-verify `LanguageModel.make` / `EmbeddingModel.make` signatures before executing.
- **D-3 — Two text adapters via `LanguageModel.make`, in-repo.** `anthropicMessagesAdapter({baseUrl, headers})` serves api.anthropic.com, CLIProxy (`CLIPROXY_BASE_URL` from `src/lib/cliproxy.ts`), and any Anthropic-compatible provider already described by `src/lib/providers.ts` (`getProviderForModelSync`/`getProviderEnvSync`). `openaiChatAdapter({baseUrl, headers})` serves api.openai.com, Ollama's `/v1`, and compatible endpoints. Reuse the existing header conventions verbatim from A2 (`enrich-session.ts:420-430`) and A3 (`cliproxy.ts:46-53`). The Anthropic adapter MUST support `cache_control: {type: 'ephemeral'}` system blocks (B1 uses prompt caching today, `anthropic.ts:39`) and surface cache read/write token counts in usage.
- **D-4 — `streamText` is a single-part stream over `generateText` in v1.** `LanguageModel.make` requires both hooks; since no first-party site streams (census finding 4), the `streamText` hook wraps the non-streaming call and emits its parts as one stream. Real SSE streaming is a follow-up if a site ever needs it. State this in the adapter's module header.
- **D-5 — Embeddings consolidate onto `EmbeddingModel.make`.** Port A4's three providers (already Effect-shaped) as `embedMany` hooks; B2's batch indexing rides the built-in `RequestResolver` batching; A5 reuses the openai embedding adapter. C5 (local transformers) is wrapped behind the same provider dispatch as a non-network `embedMany` hook — same interface, unchanged behavior, no network. L2 normalization and `Float32Array` output semantics are preserved exactly (`providers.ts:61-107` is the reference).
- **D-6 — Cost events keep their existing write doors and shapes.** A usage-tap wrapper (WI-3) reads response usage and calls `recordBackgroundAiCost` (features: `ttsSummarizer`, `conversationEnrichment`, `sessionEmbeddings` per current call sites) or `recordExtractionCost` (memory) with the same fields as today — synthetic `agentId='background'`, `source='background:<feature>'` / `source='memory-extraction'` unchanged, so dashboards and ledgers see no schema drift. Sites that are uncosted today (A5 docs, B3 autopreso, B2's estimate-only path) **stay uncosted in this issue** — adding cost coverage is a separate decision, and silently changing ledger contents is not this PRD's job.
- **D-7 — `ExecutionPlan` replaces fallback *execution*; `model-fallback.ts` *data* stays canonical.** `MODEL_PROVIDERS` (`model-fallback.ts:22`), `FALLBACK_MAP` (`:119`), tier ranks (`:205,:227`) remain the one source of model→provider/fallback facts — they also serve agent/harness routing, which this issue must not touch. What moves: the *first-party execution* of "try tier model, fall back" (enrichment) and "try primary, then chain" (memory) becomes `ExecutionPlan.make` steps consuming that data. The memory policy's cost-cap check (`queryMemoryExtractionCostUsdSync`, `policy.ts` daily cap default $5) and health recording (`updateMemoryHealth`) wrap the plan — they are policy, not fallback, and stay where they are.
- **D-8 — CLI-transport sites are a named follow-up, not this issue.** C1–C4 route prompts through `claude -p`/`omp` with sandbox hardening (`--safe-mode --tools '' --disallowedTools mcp__*`, `transcript-summary.ts:207-219`), harness dispatch, and CLI cost envelopes (`total_cost_usd`). A `LanguageModel.make` hook *can* wrap a subprocess, but migrating them buys no stack consolidation (they share no HTTP client to delete) and risks behavior drift in sandboxing and cost parsing. File the follow-up issue at close-out (WI-10) and link it here.
- **D-9 — autopreso migrates including tools; then the Vercel SDK deps drop.** B3 is the only tool-calling site; `LanguageModel.generateText` accepts a `Toolkit` (`LanguageModel.ts:267` `GenerateTextOptions<Tools>`). After B2 and B3 land, remove `ai` and `@ai-sdk/openai` from `package.json` in the same PR that migrates the last consumer (verified: those two files are the only non-test importers).
- **D-10 — No behavior changes ride along.** Same prompts, same models, same defaults, same feature gates (`isBackgroundFeatureEnabled` call sites untouched), same error-swallowing postures at the drivers (e.g. the TTS interval swallows errors, `tts-summarizer.ts:226-228` — keep it). This is a transport/abstraction consolidation; any behavioral improvement (adding retry where there was none, costing the uncosted) must be explicitly listed, and the only ones listed are FR-7's schedule-based retry *where a fallback already existed*.

## 3. Requirements

### Functional

- **FR-1** `src/lib/ai/` exposes `LanguageModel` layers for the two wire shapes (D-3), constructed per-provider from `providers.ts` data — never from hardcoded model IDs (never-hardcode-a-model rule: an unresolvable model/provider fails loudly).
- **FR-2** `src/lib/ai/` exposes `EmbeddingModel` layers for openai/voyage/ollama/local (D-5) with output parity: same vectors (modulo float tolerance), same L2 normalization, same `Float32Array` type as `embeddings/providers.ts` today.
- **FR-3** Sites A1, A2, A3, B1, B3 produce their responses through `LanguageModel`; sites A4, B2, A5, C5 through `EmbeddingModel`. No `fetch` to a model endpoint, no `@anthropic-ai/sdk`, no `ai`/`@ai-sdk/*` import remains at any in-scope site.
- **FR-4** Cost parity (D-6): for each costed site, the cost event written after migration has the same `feature`/`source`/provider/model fields and equivalent USD math as before (existing pricing via `getPricingSync`/`calculateCostSync` unchanged). Proven by golden tests comparing pre/post event shapes (WI-3).
- **FR-5** B1's prompt caching survives: the Anthropic adapter sends `cache_control` and reports cache read/write tokens into the cost calc exactly as `anthropic.ts:27-61` does today.
- **FR-6** Enrichment tier selection and memory provider chains produce the same model choices as today for the same config inputs — `ExecutionPlan` re-expresses execution, not selection (D-7). Table-driven test over the existing fixtures in `tests/lib/memory/provider-policy.test.ts` and the enrichment tests.
- **FR-7** Transient HTTP failures (429/5xx/network) on sites that already have a fallback (A2 via tier fallback, A3/B1 via memory chain) retry/fall over through `ExecutionPlan` schedules; sites with no fallback today (A1, A5, B3) keep single-shot semantics (D-10).
- **FR-8** autopreso's three base-URL paths (OpenAI key / Codex bearer / Ollama) all work through the openai-chat adapter, and its two tools keep their behavior (Toolkit port, WI-8).
- **FR-9** `ai` and `@ai-sdk/openai` are removed from `package.json` (D-9).
- **FR-10** The memory daily cost cap and health recording behave identically (D-7), including the `extracted | skipped | dropped` result contract of `extractWithProviderPolicy` (`policy.ts:34-69`) — its callers (`extract.ts:72`, `query-expansion.ts:105`, `rollup.ts:108`, `worker-pool.ts:185`, `feature-registry-population.ts:87`) must not need changes beyond imports.

### Non-functional

- **NFR-1** No Effect version change (D-2). Mechanical check: `package.json` diff contains no `effect`/`@effect/*` version edits.
- **NFR-2** All new retry/backoff/schedule tests use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync` — never real timers (fake-timers rule, restated from global CLAUDE.md; ExecutionPlan schedule tests WILL hit this).
- **NFR-3** Dashboard-server-reachable code stays event-loop-safe: no `execSync`, no sync fetch patterns; the new module is `async`/Effect throughout.
- **NFR-4** Effect-boundary discipline: call sites that are plain-async today keep a thin `Effect.runPromise` boundary at the existing seam (the pattern A4's callers already use, e.g. `routes/discovered-sessions.ts:861`); do not virally rewrite drivers (`worker-pool`, interval loops) to Effect in this issue.
- **NFR-5** Deploy discipline for dashboard-server sites (A1, A2-via-routes, B2-service): `npm run build` before restart; boot-path is untouched by design (no new Layers wired into server bootstrap — `src/lib/ai/` layers are constructed at call time), so no live-server boot-path risk; if that changes, the no-hot-patch rule applies (`pan restart --health-timeout 120000`, milliseconds).
- **NFR-6** Test seams: existing DI-style mocks (B2's injectable `createOpenAI`/`embedMany`, A4's injectable `fetchFn`, memory's provider registry) are replaced by mock `LanguageModel`/`EmbeddingModel` layers — the standard Effect testing story. The affected test census is §G of the sweep report; every listed file compiles and passes post-migration.

## 4. Target architecture

```
src/lib/ai/
├── adapters/
│   ├── anthropic-messages.ts   LanguageModel.make — api.anthropic.com | CLIProxy | compatible (D-3)
│   ├── openai-chat.ts          LanguageModel.make — api.openai.com | ollama /v1 | compatible (D-3)
│   └── embeddings.ts           EmbeddingModel.make — openai | voyage | ollama | local-transformers (D-5)
├── models.ts                   provider/base-url/key resolution over providers.ts + model-fallback.ts DATA (D-7)
├── plans.ts                    ExecutionPlan builders: enrichmentTierPlan(tier, config), memoryChainPlan(selection) (D-7)
├── cost-tap.ts                 usage → recordBackgroundAiCost | recordExtractionCost (D-6)
└── index.ts                    the door: acquireLanguageModel(feature, opts), acquireEmbeddingModel(opts)
```

Call sites depend on `src/lib/ai/index.ts` only. The door hands back a ready `LanguageModel`/`EmbeddingModel` service (layer built from config at call time), with the cost tap pre-applied for costed features.

## 7. Intersecting repo rules restated (executor must follow)

- **Never hardcode a model fallback** — `src/lib/ai/` resolves models only from config/registry data; unresolvable ⇒ loud error. (The existing `'gpt-4.1-nano'`/`'claude-haiku-4-5…'` defaults in the memory registry are *config-owned defaults* already; do not add new literals.)
- **Fake timers for every retry/backoff test** (NFR-2). **No `execSync`** anywhere server-reachable. **No `git stash`; commit per item and push before `pan task done`.**
- **Typecheck excludes tests** — run the full `npm test` before claiming green.
- **Do not upgrade Effect** (NFR-1). **Do not touch harness routing** — `model-fallback.ts` data tables serve agent routing too (D-7); changes there are out of scope.
- **Dashboard deploys**: `npm run build` before restart; `pan restart --health-timeout 120000` (value is milliseconds).
