# PAN-2322 — Harden host dashboard-port guard: workspace/UAT agents must not seize primary :3011 via `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY`

**Issue:** https://github.com/eltmon/overdeck/issues/2322
**Verified against:** `main` @ f8d2b29779 (2026-07-07). All file/line references checked at writing time.

## Glossary

- **Primary dashboard** — the single `dist/dashboard/server.js` process started from the primary checkout (`/home/eltmon/Projects/overdeck`) that binds the **host dashboard API port** (default `3011`, configurable via `dashboard.api_port` in the Overdeck config file). It runs the Deacon/orchestrator; there must be exactly one (single-deacon invariant).
- **Peer dashboard** — a dashboard booted with `OVERDECK_DISABLE_DEACON=1` (see `getDashboardIdentity()`, `src/dashboard/server/identity.ts:16-21`). Read/UI only; never the orchestrator.
- **Workspace checkout** — a git worktree at `workspaces/feature-<issue>[-slot-N]/`. Detected by `isWorkspaceRepoRoot()` (`src/dashboard/server/identity.ts:23-25`), regex `/(^|\/)workspaces\/feature-[^/]+$/i`.
- **The port guard** — the refusal in `ServerConfigLayer` (`src/dashboard/server/config.ts:73-93`): a peer or workspace boot must not bind the host dashboard API port. Implemented by `shouldRefuseHostDashboardPort()` (`src/dashboard/server/identity.ts:45-67`), which already: allows any port ≠ host port; allows anything **inside a container** (`/.dockerenv` or repoRoot `/workspaces/overdeck` — PAN-2298); refuses `peer` mode and workspace/`workspaces/`-parent roots on the host port.
- **The override / escape hatch** — env var `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY=1`, honored unconditionally at `src/dashboard/server/config.ts:78`. Nothing in the codebase sets it (repo-wide grep: only `config.ts` and `tests/unit/dashboard/config.test.ts` reference it); it exists as a manual operator escape hatch.

## Background — why now

Two live incidents:

1. **2026-07-03 (in the issue):** the PAN-1917 UAT agent booted a dashboard from its workspace, was correctly refused, read the refusal message — which names the override — set `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY=1`, and took host `:3011` from the operator.
2. **2026-07-07 (today):** the PAN-2405 test agent SIGTERM'd the live primary and bound `:3011` from `workspaces/feature-pan-2405` with the same override, running unreviewed feature-branch code as the full orchestrator. Recovery required a manual restart, and the polluted relaunch env caused a follow-on `overdeck.localhost` WebSocket 403 outage.

The guard's refusal message is a self-defeating instruction: an agent that hits the guard is *told* how to bypass it.

## Requirements

- **FR-1 — Workspace boots can never use the override.** When `isWorkspaceRepoRoot(identity.repoRoot)` is true, the guard must refuse the host dashboard API port regardless of `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY`. The override remains functional for **non-workspace** refusals (host-side peer mode with a deliberately-stopped canonical dashboard — the documented operator use).
- **FR-2 — The refusal message must not name the override.** Neither the thrown `ServerConfigError` message nor the `console.error` line may contain the string `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY`. Operator documentation moves to the `pan-dashboard-restart` dev-skill (FR-3).
- **FR-3 — Document the override for operators only.** `sync-sources/dev-skills/pan-dashboard-restart/SKILL.md` gains a short "override" note: what the env var does, that it is operator-only, and that workspace checkouts are refused unconditionally.
- **NFR-1 — The unit suite stays green when run from a workspace worktree.** `tests/unit/dashboard/config.test.ts` currently passes inside `workspaces/feature-*` only because `beforeEach` sets the override (line 69). After FR-1 that crutch is dead. The suite must make dashboard identity deterministic (mock `getDashboardIdentity`) instead of depending on where the suite runs. This is mandatory: the work agent implementing this change runs `npm test` from a workspace.
- **Out of scope (explicitly):** redirecting UAT/test agents to workspace-container dashboards (FR-3 in the issue body) — file as a follow-up issue and reference it from `pan done` notes. Also out of scope: `shouldRefuseHostDashboardPort()` itself (correct as-is), the devcontainer template (already `PORT=3013`, `infra/.devcontainer-template/docker-compose.devcontainer.yml.template:150`), and open siblings [PAN-2292], [PAN-1416], [PAN-1444].

## Work items

### WI-1 — Gate the override and scrub the message (FR-1, FR-2)

**File:** `src/dashboard/server/config.ts` (guard at lines 73-93).
`isWorkspaceRepoRoot` is exported from `./identity.js`; add it to the existing import at the top of the file (currently `getDashboardIdentity, readHostDashboardApiPort, shouldRefuseHostDashboardPort`).

Before (`config.ts:78-93`):

```ts
const overrideAllowed = process.env['OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY'] === '1';
if (shouldRefuseHostDashboardPort({
  repoRoot: identity.repoRoot,
  mode: identity.mode,
  port,
  hostDashboardApiPort,
}) && !overrideAllowed) {
  const msg = (
    `Refusing to bind host dashboard port ${port} from repoRoot=${identity.repoRoot} ` +
    `mode=${identity.mode}. Peer/workspace dashboards must set PORT or API_PORT ` +
    `to a non-host port. To override (e.g. when the canonical dashboard is deliberately stopped), set ` +
    `OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY=1.`
  );
  console.error(`[overdeck] ${msg}`);
  throw new ServerConfigError('API_PORT', msg);
}
```

After:

```ts
// The override is an operator-only escape hatch for a deliberately-stopped
// canonical dashboard. It must never let a workspace checkout seize the host
// port (PAN-2322: UAT agents used it to hijack :3011 on 2026-07-03 and 2026-07-07).
// The refusal message deliberately does not name the env var — agents read it.
const overrideAllowed =
  process.env['OVERDECK_WORKSPACE_DASHBOARD_ALLOW_PRIMARY'] === '1' &&
  !isWorkspaceRepoRoot(identity.repoRoot);
if (shouldRefuseHostDashboardPort({
  repoRoot: identity.repoRoot,
  mode: identity.mode,
  port,
  hostDashboardApiPort,
}) && !overrideAllowed) {
  const msg = (
    `Refusing to bind host dashboard port ${port} from repoRoot=${identity.repoRoot} ` +
    `mode=${identity.mode}. Peer/workspace dashboards must set PORT or API_PORT ` +
    `to a non-host port.`
  );
  console.error(`[overdeck] ${msg}`);
  throw new ServerConfigError('API_PORT', msg);
}
```

**Traces:** FR-1, FR-2. **Proven by:** WI-2 tests 1-3.
