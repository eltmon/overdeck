# PAN-3864 — Separate live fleet from retained strike history

Issue: https://github.com/eltmon/overdeck/issues/3864
Research date: 2026-09-17 UTC. Scope: correct lifecycle presentation and reconcile canonical observations; no destructive cleanup.

## Glossary

- Live process: a backend confirms that a process/session exists; it may be idle or finished with its task.
- Work state: actual working/idle/blocked/unknown observation, independent of process presence.
- Retained history: agent metadata and transcript/session pointers kept for inspection or recovery.
- Needs attention: unresolved user input, retry/gate, failure or unverifiable active attempt; may have no live process.
- Warm idle: an intentionally retained live specialist after its phase verdict, available for another cycle.
- Projection: a UI/API view derived from canonical records and observations; deleting it must not delete the record.

## Verified incident and root cause

The supplied concern is reproducible. A read-only Playwright visit to https://overdeck.localhost/agents showed **192 / 192 agents**, **183 STRIKE RUNNING labels**, **9 active** and **2 stuck** at that snapshot. The first cards included old strike sessions with runtimes above 1,500 hours. These are different counts with different meanings, not evidence of 192 active processes.

A nearby GET /api/agents observation returned 89 rows: 80 stopped, 8 healthy and 1 error. Its 17 strikes included 16 stopped records, with start dates back to July 19. The machine's overdeck tmux inventory had only one strike-named session, strike-pan-3839. Its captured output said implementation/tests/push were complete and readiness had been signaled; it remained a live terminal. This is evidence of self-reported completion, not an independently verified merge/close-out. Do not kill it merely on that text.

Four connected causes are verified in source:

1. `FleetAgentsView.tsx:isFleetAgent` admits every strike except status=dead. Stopped strikes intentionally remain visible forever to preserve outcome inspection.
2. `verbBadgeForAgent` has no stopped-strike branch. After problem/input checks, it returns STRIKE RUNNING based on role. Historical durations can keep advancing from startedAt.
3. The page consumes `selectAgents`, the WebSocket-backed agentsById snapshot. `read-model.ts` bootstraps this from AgentsResolver.list({}); `pruneAgentsForReadSource` checks known closed issues and canonical membership, not active-process membership. Thus its inventory differs from the REST endpoint.
4. The REST listing implements its own one-hour stopped cutoff only when stoppedAt/lastActivity exists, with intentional exemptions for unresolved review/retry/gates. Fixing this cutoff alone cannot fix the browser. Missing time means unknown age, not infinite activity.

The records are not themselves proof of a resource leak. They preserve inspection/recovery and PAN-3513 documents previous GC deleting resume-critical pointers. The first remedy is correct views/classification, followed by owner-driven session lifecycle when completion is authoritative. This task does not authorize data deletion.

Evidence captured locally at /tmp/overdeck-1087-research/agents-live.png and agents-live.txt; REST and tmux snapshots were collected read-only. These are transient research files; implementation must commit sanitized fixtures and reproducible tests, not depend on /tmp artifacts.

## Requirements

- FR-1: Default /agents to Active; add Needs attention and History scopes, URL-restored with existing filters/view modes.
- FR-2: Stopped/ended strikes do not appear as active merely because of role. All retained outcomes remain accessible in History.
- FR-3: Unresolved pending input/retry/gates remain visible in Needs attention even when stopped. Do not suppress actionable failures using an age threshold.
- FR-4: One shared lifecycle classification feeds REST, WebSocket snapshots and frontend labels/counts. Scope differences may be intentional; identical row evidence cannot imply different liveness.
- FR-5: Process liveness, work state and pipeline outcome remain separate. A completed/warm-idle live process is not labeled actively working. Never infer completed from stopped or unknown from a missing timestamp alone.
- FR-6: Historical badges and elapsed durations reflect stopped/completed evidence; missing stoppedAt yields unknown duration, not Date.now-startedAt. Preserve stable sorting/search/deep links and issue actions.
- FR-7: Reconciliation updates canonical observed state through the agent writer; absent backend observation/unreachable remote is unverifiable, not evidence for destructive cleanup.
- FR-8: No transcript, pointer, agent-dir, branch or workspace removal. History queries must include retained/tombstoned records excluded from default live projections.
- FR-9: Audit retained versus unfinished cleanup through canonical read doors and report exact preservation reasons. A retained-transcripts marker is already completed cleanup, not a running agent. A non-closed-out record requires lifecycle evidence before calling it stale or eligible for cleanup.
- NFR-1: Pure deterministic classifier with fake-clock fixtures; no per-row shell calls in React or read-model mapping.
- NFR-2: Existing pipeline concurrency/warm-specialist semantics remain unchanged unless a separate verified defect is found.
- NFR-3: Rendered counts name their units: live processes, working agents, needs attention and retained history. Preserve canonical cost accounting.

## Design and before/after

```ts
// Before, existing isFleetAgent special case:
if (agent.role === 'strike') return agent.status !== 'dead';
// After, proposed shared projection:
const lifecycle = classifyAgentPresence(agent, observation, pipelineEvidence);
return scope === 'active' ? lifecycle.liveProcess
  : scope === 'attention' ? lifecycle.needsAttention
  : lifecycle.hasRetainedHistory;
```

Active means confirmed live process (including clearly labeled idle/waiting/completed-waiting-for-landing sessions). Working is a separate counter. Startup attempts have their own visible Starting status with bounded launch grace, not a false live badge. Pending remote work whose host is unreachable appears in Needs attention with Unverifiable, never quietly in completed history. A row may be live and need attention simultaneously; scope counters need not sum to a unique fleet total and the UI must not imply otherwise.

Place schema-safe classification in `packages/contracts/src/agent-presence.ts` and export it. Inputs are optional persisted lifecycle, observed backend state, phase completion, pending-input/gate/retry evidence and timestamps. Output includes liveProcess, workState, needsAttention, hasRetainedHistory, badge, observedAt and endedAt. Any backend verification happens once in the owning domain service, not inside this pure helper. Herdr/tmux adapters can later feed the same observation contract under PAN-3861.

Modify AgentsResolver/its projection service to expose the needed lifecycle evidence, then consume that in REST listing and read-model snapshots. Add an explicit paginated history read through the existing domain door, since closed/tombstoned records pruned from the live snapshot cannot be recovered by a client-side tab alone. Do not expose entire raw agent records or unbounded transcript content. Preserve current default GET /api/agents compatibility; add documented scope/cursor/pageSize parameters or a dedicated history route with equivalent schemas.

For strikes, use canonical strike landing status (ready/landing/recovering/landed/needs_you) and issue lifecycle when present. A role name never determines current work state. A stopped strike may have failed or self-aborted; show its actual recorded outcome or “Stopped — outcome unknown.” A live ready strike may show “Waiting for landing”; do not mark merged until the issue resolver verifies it. Review/test/ship warm-idle classification must continue to use the established phase-verdict logic.

## Follow-up: exact card provenance and cleanup lifecycle

Follow-up read-only audit used listAllAgentsSync() and readIssueRecordForWorkspaceSync(), not direct store reads. At the audit time there were 837 retained agent records, including 196 strikes: 195 stopped and one running. Of 196 strikes, 79 carried phase=retained-transcripts. Matching the prior captured browser text to the canonical records found exactly 183 displayed strikes: 182 stopped, one running; 73 displayed strikes were already tombstoned as retained-transcripts. The 192 card count therefore comprised those 183 strikes plus nine other agent cards after the page/read-model filters. It was never a tmux session count.

The remaining 116 stopped strikes without the retained-transcripts marker split at the first periodic-GC predicate into 94 not closed out and 22 closed out (still requiring tracker/PR/session/review/durability checks). These counts do not prove the 94 are abandoned or the 22 are eligible. Retention is intentionally conservative. Current source runs the periodic agent GC every 60 patrol cycles; it excludes already retained-transcripts records. The closed-issue reaper stops matching strike sessions, while the strike workspace reaper handles merged worktrees only when no strike process is live. Those are separate lifecycle operations.

Source anchors verified during follow-up:
- src/lib/overdeck/agents.ts:123, Agent Schema: missing phase/stoppedAt projection; listAllAgentsSync at :1023 exposes them through the canonical read door.
- src/dashboard/server/read-model.ts:426, agentSnapshotFromOverdeck: omits historical marker and ended time.
- src/lib/cloister/agent-gc.ts:253, pruneAgentRowsAfterTranscriptCleanup: keeps tombstone record when transcript-bearing directory remains.
- src/lib/cloister/agent-gc.ts:315, pruneTerminalStoppedAgents: excludes retained-transcripts and requires live terminality proof.
- src/lib/cloister/deacon.ts:3136, periodic GC schedule.

This issue fixes the root cause of history being presented as active work at the domain projection and UI layers. It also requires an explicit cleanup-ownership audit; it does not claim that hiding cards repairs a missing lifecycle transition.
