## Glossary

- **Flake / flaky test** — a test that fails non-deterministically (passes some runs, fails others) for environmental reasons unrelated to the code under test. Distinguished from a deterministic failure by the presence of a reproducible retry pass.
- **Retry** — vitest's built-in `retry` config option: re-runs a failed test up to N times before recording it as failed. `retry: 1` means one re-run (two total attempts).
- **Retried-pass** — a test that failed on attempt 1 but passed on attempt 2+. Must be logged loudly; cannot be silently dropped from failure counts.
- **Quarantine** — the state of a test file that is excluded from the blocking verification gate and CI `test` job, while still running in the non-blocking `flake-lane` CI job. Quarantine requires an inline issue reference; it is shrink-preferred (adding requires justification, removing is always free).
- **`scripts/flaky-quarantine.txt`** — the single source of truth for quarantined tests. Line format: `<relative-path-from-repo-root>  # PAN-<n>` (inline issue ref). Comment lines start with `#`.
- **Flake lane** — the non-blocking CI job (`.github/workflows/ci.yml` job name `flake-lane`) that runs ONLY quarantined tests. Its failure does not block merges; it provides observability.
- **Verification gate** — Overdeck's pre-merge quality gate, driven by `src/lib/cloister/verification-runner.ts`, which calls `runQualityGates(DEFAULT_GATES, ...)` from `src/lib/cloister/validation.ts`. It runs inside the dashboard server process.
- **`OVERDECK_VERIFICATION`** — a new env var (`'1'`) set by the verification gate's test-gate invocation to signal to vitest that it is in CI/verification mode, enabling retry and quarantine exclusions.
- **`DEFAULT_GATES`** — the `Record<string, QualityGateConfig>` exported at `src/lib/cloister/validation.ts:331`, which specifies the commands run by the verification gate when no project-specific `quality_gates` block exists.

## Requirements

- **FR-1** — vitest must retry failed tests once (`retry: 1`) when `process.env.CI` or `process.env.OVERDECK_VERIFICATION` is set; local dev runs stay at `retry: 0`.
- **FR-2** — A retried-pass (failed attempt 1, passed attempt 2) must emit a clearly visible reporter warning that names the test and the failure reason. It must not be silently omitted from output.
- **FR-3** — `scripts/flaky-quarantine.txt` must be the single source of truth for quarantined tests. Each non-empty, non-comment line must carry an inline issue reference matching `([A-Z]+-[0-9]+|#[0-9]+)`; missing references fail lint.
- **FR-4** — In CI and verification-gate runs (`process.env.CI || process.env.OVERDECK_VERIFICATION`), quarantined test files must be excluded from the blocking test invocation.
- **FR-5** — A non-blocking `flake-lane` CI job must run ONLY the quarantined files; its failure must not block merges (job-level `continue-on-error: true` or marked non-required).
- **FR-6** — The verification runner's test gate (`DEFAULT_GATES.test`) must: (a) set `OVERDECK_VERIFICATION=1` in the gate env, and (b) expand quarantine exclusions into the vitest command before launching.
- **FR-7** — A `lint:quarantine-audit` script must validate every entry in `scripts/flaky-quarantine.txt` has an inline issue reference; it runs as part of `npm run lint` in CI.
- **NFR-1** — No new explicit `any`; async only (no `execSync` in server-reachable code); no new files ≥1,000 lines.
- **NFR-2** — The fake-timers repo rule stands: retry/quarantine is not a license to keep real-timer tests. Any delay-based test must use `vi.useFakeTimers()` per the repo rule.

```bash
#!/usr/bin/env bash
# lint-quarantine-audit.sh — verify every entry in scripts/flaky-quarantine.txt
# has an inline issue reference.  Adding requires justification; removing is free.
set -euo pipefail
cd "$(dirname "$0")/.."

QUARANTINE="scripts/flaky-quarantine.txt"
ISSUE_REF_RE='([A-Z]+-[0-9]+|#[0-9]+)'

if [[ ! -f "$QUARANTINE" ]]; then
  echo "lint-quarantine-audit: $QUARANTINE not found — skipping"
  exit 0
fi

failures=0
while IFS= read -r line; do
  # Skip empty lines and comment-only lines
  trimmed="${line%%#*}"    # strip comment
  trimmed="${trimmed//[[:space:]]/}"   # strip whitespace
  [[ -z "$trimmed" ]] && continue
  # Non-comment line — must have an inline issue ref
  if ! echo "$line" | grep -Eq "$ISSUE_REF_RE"; then
    echo "lint-quarantine-audit: missing issue ref on line: $line" >&2
    (( failures++ )) || true
  fi
done < "$QUARANTINE"

if [[ "$failures" -gt 0 ]]; then
  echo "lint-quarantine-audit: $failures line(s) missing issue references." >&2
  echo "  Every quarantine entry must have '# PAN-<n>' or '# #<n>' inline." >&2
  exit 1
fi
echo "lint-quarantine-audit: OK ($(grep -cEv '^\s*(#|$)' "$QUARANTINE" || echo 0) entries validated)"
```

**Step 1: Add quarantine-file reader helper.** Before the `DEFAULT_GATES` definition (grep anchor: `export const DEFAULT_GATES: Record<string, QualityGateConfig> = {`), add:

```ts
/**
 * Reads scripts/flaky-quarantine.txt relative to projectRoot and returns
 * `--exclude <path>` vitest args for each quarantined file.
 * Returns an empty string when the file does not exist or is empty.
 * Only active when process.env.CI or process.env.OVERDECK_VERIFICATION is set.
 */
function buildQuarantineExcludes(projectRoot: string): string {
  if (!process.env.CI && !process.env.OVERDECK_VERIFICATION) return '';
  const quarantinePath = join(projectRoot, 'scripts', 'flaky-quarantine.txt');
  if (!existsSync(quarantinePath)) return '';
  const lines = readFileSync(quarantinePath, 'utf-8').split('\n');
  const excludes = lines
    .map((l) => l.split('#')[0].trim())
    .filter(Boolean)
    .map((p) => `--exclude ${p}`)
    .join(' ');
  return excludes;
}
```

### W4 — Add non-blocking `flake-lane` CI job (FR-5)

**File:** `.github/workflows/ci.yml`

Add after the existing `clean-install` job. Insert a new job:

```yaml
  flake-lane:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    # Non-blocking: flake-lane failures are observable but do not block merges.
    continue-on-error: true
    # Only run when there are quarantined tests to run.
    steps:
      - uses: actions/checkout@v4

      - name: Use Node.js 22
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Setup Bun
        uses: oven-sh/setup-bun@v2
        with:
          bun-version: latest

      - name: Install dependencies
        run: bun install --frozen-lockfile

      - name: Build
        run: npm run build

      - name: Install Playwright browsers (for playwright quarantine tests)
        run: npx playwright install --with-deps chromium

      - name: Run quarantined tests (non-blocking flake lane)
        run: |
          QUARANTINE="scripts/flaky-quarantine.txt"
          if [[ ! -f "$QUARANTINE" ]]; then
            echo "No quarantine file — nothing to run"
            exit 0
          fi
          # Parse file paths (strip inline comments, skip empty/comment lines)
          mapfile -t FILES < <(grep -Ev '^\s*(#|$)' "$QUARANTINE" | awk '{print $1}')
          if [[ ${#FILES[@]} -eq 0 ]]; then
            echo "Quarantine file is empty — nothing to run"
            exit 0
          fi
          echo "Running ${#FILES[@]} quarantined file(s): ${FILES[*]}"
          # CI=1 activates retry:1 for this run too
          CI=1 npx vitest run "${FILES[@]}" || {
            echo "::warning::Flake-lane failures detected in quarantined tests: ${FILES[*]}"
            exit 1
          }
```

Note: the job uses `continue-on-error: true` so it remains non-blocking at the workflow level. The `exit 1` still produces a visible failure annotation in the CI UI.

3. **Flake-lane runs under `OVERDECK_FLAKE_LANE=1`** (not `CI=1`) so config-level exclusion
   does not drop the very files it must run; it passes the parsed file list as positional
   args. `retry:1` also activates under this env.

4. **Inline per-entry issue-ref audit** (`scripts/lint-quarantine-audit.sh`, wired into
   `npm run lint`) rather than a git-commit-message ratchet — matches "a tracker-issue
