# PAN-3192 — Typecheck the dashboard frontend in the mandated quality gates

**Issue:** https://github.com/eltmon/overdeck/issues/3192

## Glossary

- **Mandated gates** — the three commands every work agent must pass before `pan done`,
  per `CLAUDE.md` ("Quality gates"): `npm run typecheck`, `npm run lint`, `npm test`.
- **Ratchet** — a guard whose baseline may shrink but never grow. Precedent:
  `scripts/lint-dashboard-types.sh` (server type errors, PAN-2765) and
  `scripts/lint-file-size.sh` (file line counts).
- **Baseline file** — a checked-in file under `scripts/` recording the accepted
  backlog. The server guard stores a bare integer
  (`scripts/dashboard-types-baseline.txt`, currently `62`); the frontend guard
  introduced here stores one `error TS` line per baselined error so failures can
  name the *new* errors.
- **Verification runner** — `src/lib/cloister/verification-runner.ts`, which runs
  the `quality_gates` from `~/.overdeck/projects.yaml` before review. Its
  `typecheck` gate is `npm run typecheck`, so wiring the frontend guard into root
  `npm run typecheck` automatically covers local agents, the verification runner,
  and CI (`.github/workflows/ci.yml` build job, step `Type check`).

## Problem

No mandated gate typechecks `src/dashboard/frontend`:

- Root `tsconfig.json:20` excludes `src/dashboard/**/*`.
- Root `package.json:102` `typecheck` = `tsc --noEmit && typecheck:hooks &&
  typecheck:evals && typecheck:dashboard`; `typecheck:dashboard`
  (`package.json:136`) runs `scripts/lint-dashboard-types.sh`, which is scoped to
  the **server** alone (`lint-dashboard-types.sh:32`,
  `TSCONFIG="src/dashboard/server/tsconfig.json"`).
- `src/dashboard/frontend/package.json` has no `typecheck` script; the frontend is
  typechecked only as a side effect of its `build` (`tsc && vite build`).

Cost proof: PAN-3156 (strike/pan-3156) sat red on one line
(`WorkspaceHeader.tsx(47,17)`, TS2322) across two flywheel runs because the
agent's gates truthfully could not see it. Second defect: when the backlog is
non-zero, an agent who does run a frontend build sees a mixed error list and
cannot tell its own error from pre-existing ones — the PAN-3156 agent dismissed
CI's error as pre-existing noise.

**Verified state on main as of 2026-07-27 (this workspace, HEAD c6f5c820ef):**
`npx tsc --noEmit -p src/dashboard/frontend/tsconfig.json` reports **0 errors**.
The two backlog errors quoted in the issue (`src/test-setup.ts`,
`src/test-utils/strictFetchMock.ts`) no longer reproduce on current main. The
baseline will therefore likely seed at 0 — the seed procedure below measures at
implementation time rather than trusting this number.

## Requirements

- **FR-1** — `npm run typecheck` from the repo root typechecks
  `src/dashboard/frontend` and fails when the frontend error count exceeds the
  baseline.
- **FR-2** — The guard is a ratchet: the baseline may shrink but never grow.
  `--update` refuses to raise it; a shrunken count without `--update` fails as a
  stale baseline with the remedy printed.
- **FR-3** — On failure, the output separates errors with no baseline match
  ("NEW") from baselined backlog ("known"), so an agent can identify its own
  breakage without triaging the whole list.
- **FR-4** — `src/dashboard/frontend/package.json` gains a `typecheck` script
  (`tsc --noEmit`) so developers inside the frontend tree can run the raw check.
- **NFR-1** — No `.github/workflows/*.yml` changes. The gate rides the existing
  `npm run typecheck` step in CI's build job.
- **NFR-2** — The regression test is hermetic: it stubs `npx` via `PATH` in a
  temp directory and never invokes a real `tsc` (keeps `npm test` fast and
  independent of the live frontend backlog).

## Decisions (made in this document — no judgment calls at implementation time)

- **D1 — Count-based gate, error-list baseline, advisory annotation.** The gate
  decision is a pure count comparison, semantically identical to
  `lint-dashboard-types.sh` (grow → fail, shrink → stale-baseline failure, equal
  → pass). The baseline file stores the sorted `error TS` lines (count =
  non-comment lines) instead of a bare integer, and the failure branch diffs
  current errors against baselined errors to label NEW vs known. A
  fingerprint-based gate (fail on any unmatched error) was considered and
  rejected: a dependency bump that rewords a pre-existing error's message would
  relabel it as new and block the pipeline on phantom errors. Under the
  count-based gate, line/message drift can only ever mislabel the *annotation*,
  never fail the gate — and the annotation is only needed when the gate is red,
  which is exactly when the agent must find its own error. Comparison keys strip
  the `(line,col)` position so ordinary edits don't shift labels.
- **D2 — Seed by measurement, not by this document.** The work item re-runs the
  frontend typecheck and seeds the baseline from the live result (0 errors as of
  2026-07-27, but main moves).
- **D3 — One wiring point.** Root `package.json` gains
  `"typecheck:frontend": "bash scripts/lint-frontend-types.sh"` and the
  `typecheck` chain appends `&& npm run typecheck:frontend`. That single edit
  covers local agents, the verification runner, and CI. No workflow edits.
- **D4 — `lint-ratchet-audit.sh` is not extended.** It audits the file-size
  allowlist, ESLint allowlist, and circular baseline. The dashboard-types
  integer baseline is deliberately not audited because the script self-enforces
  shrink-only via `--update` refusal; the frontend baseline has the same
  self-enforcement and follows the same trust model.
- **D5 — Operator-local `~/.overdeck/projects.yaml` is not edited.** It already
  carries a `frontend-typecheck` quality gate (`npx tsc --noEmit` in
  `src/dashboard/frontend`, `required: true`) — a raw check with no ratchet.
  After this lands it is redundant; the operator may choose to drop it. That
  file is operator-owned config, out of scope for this issue (see H2).

## Work items

### 1. `frontend-types-guard-script` — create the ratchet script and seed the baseline

**Files:** `scripts/lint-frontend-types.sh` (new), `scripts/frontend-types-baseline.txt` (new)

Create `scripts/lint-frontend-types.sh` with exactly this content (mode 0755):

```bash
#!/usr/bin/env bash
#
# lint-frontend-types.sh — typecheck guard for the dashboard frontend (PAN-3192).
#
# The root tsconfig excludes src/dashboard/**, and lint-dashboard-types.sh covers
# only the server, so no mandated gate (typecheck/lint/test) ever typechecked
# the frontend. Frontend-only type errors were invisible locally and surfaced
# only in CI — PAN-3156 burned two flywheel runs on a one-line error its own
# gates could not see.
#
# Like the server guard this is a RATCHET, not a hard gate: the error count may
# shrink but never grow. The baseline also records the baselined error lines so
# a failure can name the NEW errors instead of dumping a mixed list the agent
# cannot triage — the second PAN-3156 defect.
#
# Baseline is scripts/frontend-types-baseline.txt: '#'-prefixed header lines
# plus one baselined `error TS` line per row, sorted. Count = non-comment lines.
# Run with --update to lower a stale baseline after fixing errors.
# --update never raises: accepting growth would defeat the ratchet.
#
set -euo pipefail

MODE=check
if [[ "${1:-}" == "--update" ]]; then
  MODE=update
elif [[ $# -gt 0 ]]; then
  echo "usage: bash scripts/lint-frontend-types.sh [--update]" >&2
  exit 2
fi

BASELINE_FILE="scripts/frontend-types-baseline.txt"
TSCONFIG="src/dashboard/frontend/tsconfig.json"

if [[ ! -f "$BASELINE_FILE" ]]; then
  echo "✖ missing $BASELINE_FILE" >&2
  exit 1
fi

baseline_count=$(grep -cvE '^[[:space:]]*(#|$)' "$BASELINE_FILE" || true)

# tsc exits non-zero when it reports errors; count them rather than trust status.
output=$(npx tsc --noEmit -p "$TSCONFIG" 2>&1 || true)
current=$(printf '%s\n' "$output" | grep -E 'error TS' | sort || true)
count=$(printf '%s\n' "$current" | grep -cE 'error TS' || true)

# Normalized comparison key: strip the (line,col) position so an edit that
# shifts a pre-existing error's line does not relabel it as NEW when annotating.
norm() { grep -E 'error TS' | sed -E 's/^([^(:]+)\([0-9]+,[0-9]+\)/\1/' | sort -u; }

if [[ "$MODE" == "update" ]]; then
  if (( count > baseline_count )); then
    echo "✖ refusing to raise the baseline: $count errors vs baseline $baseline_count." >&2
    echo "  Fix the new errors — the ratchet only lowers." >&2
    exit 1
  fi
  {
    echo "# frontend type-error baseline for lint-frontend-types.sh (PAN-3192)."
    echo "# One baselined 'error TS' line per row, sorted. Lower with: bash scripts/lint-frontend-types.sh --update"
    printf '%s\n' "$current"
  } > "$BASELINE_FILE"
  echo "✓ frontend-types baseline updated: $baseline_count → $count"
  exit 0
fi

if (( count > baseline_count )); then
  echo "✖ dashboard frontend typecheck regressed: $count errors (baseline $baseline_count)." >&2
  echo "  Errors with no baseline match (yours to fix):" >&2
  comm -23 <(printf '%s\n' "$current" | norm) <(grep -E 'error TS' "$BASELINE_FILE" | norm || true) | sed 's/^/  NEW: /' >&2
  echo "  Baselined backlog (pre-existing — not yours):" >&2
  comm -12 <(printf '%s\n' "$current" | norm) <(grep -E 'error TS' "$BASELINE_FILE" | norm || true) | sed 's/^/  known: /' >&2
  echo "  Note: an edit that rewords a pre-existing error can relabel it as NEW;" >&2
  echo "  the count delta ($((count - baseline_count))) bounds how many are truly new." >&2
  echo "  Reproduce: npx tsc --noEmit -p $TSCONFIG" >&2
  exit 1
fi

if (( count < baseline_count )); then
  echo "✖ stale baseline: $count errors but baselined at $baseline_count — run: bash scripts/lint-frontend-types.sh --update" >&2
  exit 1
fi

echo "✓ frontend-types guard passed ($count known errors; none new)"
```

    npx tsc --noEmit -p src/dashboard/frontend/tsconfig.json 2>&1 | grep -E 'error TS' | sort || true
  } > scripts/frontend-types-baseline.txt

### 3. `frontend-types-ratchet-test` — regression test for shrink-only behavior

**Files:** `tests/unit/scripts/lint-frontend-types.test.ts` (new)

Mirror the harness shape of `tests/unit/scripts/lint-file-size.test.ts`:
`mkdtempSync` a temp dir, copy the real script and a written baseline into
`<tmp>/scripts/`, and run it with `execFileSync('bash', ...)`. No git repo is
needed (the script does not use git).

Make it hermetic (NFR-2): write a fake `npx` at `<tmp>/bin/npx`:

```bash
#!/usr/bin/env bash
cat "$FAKE_TSC_OUTPUT"
```

and invoke the script with
`env: { ...process.env, PATH: "<tmp>/bin:" + process.env.PATH, FAKE_TSC_OUTPUT: <file> }`.
The test writes canned `error TS` lines (and non-error noise lines) to the
`FAKE_TSC_OUTPUT` file per case.

Cases (all must pass):

1. **green at parity** — baseline and current both have the same one error line →
   exit 0, output contains `✓ frontend-types guard passed (1 known errors; none new)`.
2. **red on growth, NEW labeled** — baseline has error A, current has A plus a
   new error B in a different file → exit 1, output contains `NEW: ` followed by
   B's normalized text, and A appears under `known: `.
3. **stale on shrink, then --update lowers** — baseline has A and B, current has
   only A → exit 1 with `stale baseline`; run `--update` → exit 0 and
   `baseline updated: 2 → 1`; re-run check → exit 0.
4. **--update never raises** — baseline has A, current has A+B → `--update`
   exits 1 with `refusing to raise the baseline` and the baseline file is
   byte-identical afterwards.
5. **missing baseline** — delete the baseline file → check exits 1 with
   `✖ missing scripts/frontend-types-baseline.txt`.
6. **line-shift does not relabel** — baseline has A at `(10,5)`; current has A at
   `(47,17)` (same file, code, message) plus genuinely new B → exit 1, the NEW
   section lists B but not A.

**Verify:** `npx vitest run tests/unit/scripts/lint-frontend-types.test.ts` — all
six cases pass. Also `npm test` stays green (the new file is picked up by the
root vitest glob).

## NonGoals

- Driving the frontend type-error backlog to zero. The ratchet prevents growth;
  `--update` lowers the baseline as errors are fixed, but fixing the backlog is
  not this issue.
- Changing what root `npm test` runs for the frontend (the issue mentions the
  three named frontend test files as context only).
- Editing `.github/workflows/*.yml` — the gate rides the existing
  `npm run typecheck` CI step (NFR-1).
- Editing `~/.overdeck/projects.yaml` (operator-owned; see H2).
- Changing `scripts/lint-dashboard-types.sh` or migrating the server guard to
  the error-list baseline format.
- Extending `scripts/lint-ratchet-audit.sh` to the new baseline (D4).

## Hazards

- **H1 — Baseline drift between planning and implementation.** Main had 0
  frontend errors on 2026-07-27; a merge could change that. Mitigation: the
  measure-then-seed decision rule in work item 1.
- **H2 — The operator-local `frontend-typecheck` gate has no ratchet.**
  `~/.overdeck/projects.yaml` runs raw `npx tsc --noEmit` in the frontend as a
  required gate. If the backlog regrows past 0, that gate hard-fails
  verification independently of this ratchet. After this issue lands the
  operator may want to remove the local gate as redundant — operator-owned, not
  edited here.
- **H3 — Annotation is advisory.** An edit that rewords a pre-existing error's
  message relabels it as NEW in the failure output. The gate decision is
  count-based so this can never false-fail; the failure text states the count
  delta as the bound on truly-new errors.
- **H4 — Hand-editing the baseline upward is possible.** Same trust model as the
  integer `dashboard-types-baseline.txt`, which `lint-ratchet-audit.sh` also
  does not audit. Mitigation: `--update` refusal is the enforced path; the
  header documents the contract.
- **H5 — `npx tsc` resolution.** The script relies on `npx` resolving the
  frontend workspace's own `typescript` devDependency. Standard workspace setup
  (`bun install` at the root) provides it; a workspace that skipped install
  fails the `install` quality gate before ever reaching typecheck.
