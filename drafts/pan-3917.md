## Glossary

- **State layer**: every place Overdeck stores a copy of a fact that another system already owns. Concretely: the `overdeck-state` branch as a data plane, per-issue pipeline records (`records/<issue>.json`), the six status fields (`reviewStatus`, `testStatus`, `verificationStatus`, `inspectStatus`, `mergeStatus`, `releaseStatus`), `readyForMerge`, `statusOverrides`, task claims, `recoveryTrips`, `resumePoint`, `sessionHistory`, and the SQLite tables that mirror them.
- **Owner of a fact**: git owns branches and commits; the tracker (GitHub for PAN, Linear plus GitLab for MIN) owns issues, pull requests, checks, reviews, and merges; the terminal backend (Herdr or tmux) owns session liveness and state; the harness transcript (JSONL) owns what an agent did and what it cost.
- **Derived state**: a value computed at read time from an owner, never written back.
- **Terminal backend**: the process that owns agent terminals. Two adapters: Herdr (default after this issue) and tmux (supported).
- **Herdr**: the Rust terminal runtime for coding agents, v0.9.1 (2026-09-16, Apache-2.0). Unix-socket NDJSON API; concepts are server session, workspace, tab, pane, agent, worktree, machine. Agent states: `idle`, `working`, `blocked`, `done`, `unknown`.
- **Issue workspace**: the Herdr workspace (or the set of tmux sessions) that hosts every pane spawned for one issue. It is the issue tree in the dashboard.
- **Deacon-lite**: the surviving watcher. It observes and nudges or notifies; it never reconciles a stored copy.
- **Foreman**: the work agent when a plan has parallel waves. It dispatches same-family workers as in-harness subagents and cross-family workers as backend panes via `pan spawn`.
- **Re-point**: a feature keeps its behavior but reads its inputs from an owner instead of the state layer.
- **`.pan/`**: the in-repo planning directory. `PAN_DIRNAME` in `src/lib/pan-dir/types.ts:10`. Holds `drafts/`, `specs/`, `continues/`, `orders/`, `notes/`, `backlog/sequence.md`. The repo already tracks these and ignores only workspace working copies (`.gitignore` lines 64–80).
- **xBRIEF**: the machine-readable plan (`docs/XBRIEF.md`). Its checklist stays the task source of truth; its completion state moves from the record to `.pan/continues/<issue>.xbrief.json` plus commit trailers.

## Problem

Overdeck's `src/` grew from 64k lines in February to 690,712 today. Of 4,596 `fix:` commits, 2,343 mention patrol, deacon, review, merge, resume, orphan, stuck, or stale: the pipeline repairing itself. The cause is structural. Each stored copy of an owned fact drifts, a patrol is written to reconcile the drift, the patrol acts on a transient state, and a new guard is written. The Deacon's `runPatrol` (`src/lib/cloister/deacon.ts:2528`) invokes about sixty such routines every cycle. Live evidence today: the MIN-1039 agent's `state.json` says `claude-opus-5` while its pane runs Fable 5.1, and the work-agent stop hook nagged that orchestrator at 11:32Z for not calling `pan work done` while it was mid-wave.

## Outcome

Every feature stays. The state layer goes. After this issue:

- No code under `src/` reads or writes `records/`, the six status fields, `statusOverrides`, claims, `recoveryTrips`, or the `overdeck-state` branch.
- Planning artifacts live in each project repo under `.pan/`.
- Session liveness and state come from the terminal backend; Herdr is the default, tmux is supported.
- Review verdicts are PR reviews. Gate results are check runs and workspace artifacts. Merge readiness is approvals plus green checks plus forge mergeability. Item status is a commit trailer plus the checklist file.
- The dashboard renders the same boards from derived state, and the issue tree is the issue workspace.
- The Deacon is deacon-lite. The flywheel is a loop skill. Day-to-day swarming is the foreman model; the swarm plumbing stays dormant.

- **D2 Restart gate**: keep `services/restart-gate.ts`, `routes/restart-gate.ts`, `RestartApprovalBanner.tsx`. Replace the on-disk claim store with an in-memory request map.
- **D3 Auto-merge**: keep `services/auto-merge-executor.ts`, `AutoMergeToggle.tsx`, `MergePolicySection.tsx`, `auto-merge-eligibility.ts`, `auto-merge-policy.ts`. Move `/api/flywheel/config` and `/api/flywheel/auto-merge/*` under `routes/merge-train.ts`. Gate on forge mergeability, approvals, and checks.
- **D4 Closed-issue reaper**: keep `closed-issue-reaper.ts` as a deacon-lite routine. It reads the tracker only.
- **D5 API-error recovery**: keep detection from `deacon-api-recovery.ts` as a deacon-lite routine: on repeated 429 or provider failure text in a pane, resume once through the backend. Delete the escalation ladder.
- **D6 Version ship**: keep `pan release` and `version-ship*.ts`. Ship records become git tags plus GitHub releases; delete `ship-record.ts`, `ship-status.ts`, `pending-promotion-reconciler.ts`.
- **D7 Deacon controls**: keep `deacon-supervisor.ts`, `routes/misc/deacon.ts`, `DeaconActivityView.tsx`, `DeaconPauseToggle.tsx`, and `pan admin cloister status|stop|emergency-stop`, shrunk to deacon-lite's surface. Delete `brake` and `freeze`.
- **D8 Migration scope**: migrate `drafts/`, `specs/`, `continues/`, `orders/`, `notes/`, and `backlog/sequence.md` for OPEN issues from each state worktree into `<repo>/.pan/`. Closed-issue artifacts stay on the archived branch. MYN's plan home is the `api` repo, named as `planHome: api` in `projects.yaml`.
- **D9 Plan home layout**: `.pan/` in the project repo, the layout `getProjectPanPaths` already returns for unmigrated projects. No new directory name.
- **D10 Runtime**: Herdr default, tmux supported, selected by `terminal.backend` in `config.yaml` with default `herdr` when the binary and a session socket are present, else `tmux` with a diagnostic. No per-session persisted backend ref: the inventory of both backends is read live and matched to issues by workspace name and metadata.
- **D11 Swarm**: `pan swarm`, tiers, slot GC, foreman liveness stay in the tree and are not wired into the default work path. Slot records move off the state branch into `.pan/continues/`.
- **D12 Flywheel**: `pan flywheel start` launches a conversation running the `pan-flywheel` skill v2 (loop shape of `pan-gauntlet-loop`). Run records, telemetry, substrate-bug weights, parked reports, and the FlywheelPage are deleted. Order books and parked items stay as inputs.
- **D13 The branch**: `overdeck-state` is never deleted (bundled rule). Each project's branch gets a `state-final` tag; its worktree under `~/.overdeck/state/<project>/` is removed after W1 migrates; `migration-complete.json` markers are removed.
- **D14 The day**: prepare, dispatch a wave of workers in isolated worktrees with hard `files_scope`, integrate in dependency order with green gates at every merge, reload. Anything a worker cannot land is reported by name at integration; nothing is deferred silently.

## Requirements

- **FR-1** No module under `src/` imports `src/lib/pan-dir/record*.ts`, `task-door.ts`, `auto-commit.ts`, or reads `records/`, `statusOverrides`, `tasks.claims`, `recoveryTrips`, or any of the six status fields. A CI guard fails on any such reference.
- **FR-2** `getProjectPanPaths` returns `<projectRoot>/.pan/` unconditionally. `resolveStateReadHomeSync` and the migration-marker branch are deleted. Drafts, specs, continues, orders, notes, and the backlog sequence are read and written under `.pan/` in the project repo (or the configured `planHome` repo for polyrepo projects) and committed on the feature branch by the agent that changes them.
- **FR-3** A terminal backend contract exists with two adapters. Operations: `create(workspaceFor(issue))`, `startAgent(pane, kind, argv, env, tokens)`, `prompt(target, text, wait?)`, `wait(target, until[], timeout)`, `observe(terminalId)`, `control(terminalId)`, `list()`, `events()`, `reportMetadata(pane, tokens)`, `close(ref)`, `resume(ref)`. Each returns a typed result or `unsupported` with a reason. The tmux adapter reports `working|idle|exited` with idle derived from stale activity exactly as `src/lib/agents/liveness.ts` does today; it returns `unsupported` for `wait`, `blocked`, native resume, and metadata tokens.
- **FR-4** The Herdr adapter drives `herdr --session overdeck` headless: `workspace.create`, `pane.split`, `agent.start`, `agent.prompt` with `wait`, `agent.wait`, `pane.wait_for_output`, `events.subscribe`, `agent.list`, `pane.report_metadata`, `terminal session observe` and `control` NDJSON streams bridged to the existing terminal WebSocket contract. It never installs, updates, stops, or replaces a server during a read.
- **FR-5** Every launcher (`pan start`, `pan spawn`, `pan review`, `pan strike`, specialists, `pan handoff --issue`) places its pane in the issue workspace and stamps `pane.report_metadata` tokens `issue`, `role`, `harness`, `model`. The issue tree renders every pane in the issue workspace plus in-harness subagents from the transcript directory. A `pan handoff --issue` reviewer appears as the Review row, not as a conversation.
- **FR-6** Issue state is derived: `backlog`, `parked`, `planned`, `working`, `in review`, `changes requested`, `ready`, `merged`, `closed`, from the tracker, the PR, checks, git, and the backend, per the table in W6. Session state is the backend's. Attention states are `needs you`, `stuck`, `api error`.
- **FR-7** Review verdicts are posted as PR reviews (approve or request changes) by the reviewer role. Verdict feedback to the work agent is keyed off PR review state. The four reviewer nodes, round artifacts, and convergence detection keep working from artifacts.
- **FR-8** Verification results (typecheck, lint, tests, stub-UI lint, test-skip gate) are written as workspace artifacts (`verification-latest.json`) and reported as GitHub check runs where the App is installed. The Lint row reads the artifact. No `verificationStatus` is written.
- **FR-9** Merge train, merge agent, and auto-merge compute the ready set from approvals, green checks, and forge mergeability. Conflict ordering, batch merges, sibling rebases, UAT batch trains, and polyrepo merge verification keep their behavior.
- **FR-10** `pan task done <item>` writes the item's status into `.pan/continues/<issue>.xbrief.json`, verifies a commit on the feature branch carries the trailer `Item: <item-id>`, verifies the branch is pushed, and commits the continue file. `pan task claim` records the claim in the same file. `pan done` opens or updates the PR, requests review, and writes nothing else. `pan close` reads PR merged plus issue state.
- **FR-11** Deacon-lite runs: `checkStuckWorkAgents` (idle N minutes with unpushed work), `checkApiErrorAgents` (D5), `reconcileAgentLiveness` (backend inventory vs. dashboard cache, cache side only), `closed-issue-reaper` (D4). Host hygiene (docker bridge pool, idle stacks, disk pressure, orphan dashboard servers, playwright reaper, transcript retention, strike and swarm worktree GC, memory pressure) runs from a plain interval scheduler outside deacon-lite. Every other patrol in Appendix A is deleted.
- **FR-12** The dashboard read model is rebuilt from derived sources: tracker issue data service, PR and check reads, git info, backend inventory and events, transcript parsing. No SQLite table mirrors pipeline state; the DB keeps costs, conversation search, health history, and caches.
- **FR-13** `pan-flywheel` skill v2 exists and `pan flywheel start` launches it in a conversation. The flywheel routes, services, telemetry, run state, and page are deleted.
- **FR-14** The work role prompt (`src/lib/cloister/work-agent-prompt.ts`, `sync-sources/agents/pan-work-agent.md`) is one protocol: the foreman. `pan spawn --issue <id> --item <item> --model <model> [--harness <h>]` creates a worker pane in the issue workspace. The per-item inspection gate and `pan inspect` are deleted.
- **FR-15** `sync-sources/` hooks, skills, and rules receive a file-by-file pass with the same rule. The work-agent stop hook is deleted. CLAUDE.md is rewritten under a hundred lines without the "No bandaids" and "Never do agent work" lines. Docs in Appendix C are deleted; `docs/TERMINAL-BACKENDS.md`, `docs/FOREMAN.md`, and `docs/THE-CUT.md` are added.
- **FR-16** Migration (D8) runs for `panopticon-cli` and `mind-your-now` before any deletion of the record plane, and the MIN-1039 orchestrator's `pan tell`, `pan task done`, and `pan done` work at every point of the day.
- **NFR-1** Every merge to `main` passes `npm run typecheck`, `npm run lint`, and `npm test` with no new failures.
- **NFR-2** One worker per item, one isolated worktree per worker, `files_scope` is a hard boundary, one commit per item with a conventional subject and the trailer `Item: <item-id>`, no `pan` commands from workers, no pushes from workers, no `git stash`, no history rewriting, no `--no-verify`.
- **NFR-3** Server-reachable code uses async subprocesses only, never `execSync`. Delay and retry tests use Vitest fake timers. New tmux calls use `sendKeysAsync`.
- **NFR-4** The safety export (`overdeck.db`, `panopticon.db`, `costs/events.jsonl`, `state-final` tags) is taken by the operator before W3 runs. No JSONL transcript is deleted. `overdeck-state` is never deleted.
- **NFR-5** The Herdr adapter is verified against a real headless server in a throwaway session before W8 merges; recorded schema fixtures are committed.

### Issue state derivation (FR-6)

| State | Rule |
| --- | --- |
| backlog | issue open, no `.pan/specs/*<ISSUE>*.xbrief.json` on main or the feature branch |
| parked | tracker label `parked`, or listed in `.pan/parked.md` |
| planned | spec file exists |
| working | a live backend pane whose `issue` token is this issue, or feature branch ahead of main with no PR |
| in review | PR open, review requested or a reviewer pane live |
| changes requested | latest PR review state is `CHANGES_REQUESTED` |
| ready | PR approved, checks green, `mergeable` true |
| merged | PR merged |
| closed | issue closed |
