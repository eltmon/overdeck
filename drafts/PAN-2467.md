# PAN-2467 — Multi-repo merge train: per-repo completeness gate

**Issue:** https://github.com/eltmon/overdeck/issues/2467
**Planned:** 2026-07-25 (auto mode)
**Campaign:** polyrepo campaign issue 1 of 4 (#2467 merge train, #3037 `pan sync-main`, #3040 `pan strike`, #1696 UAT merge train). This PRD covers ONLY the merge-completeness gap; the other three surfaces are sibling issues and out of scope here.

## Glossary

- **Polyrepo project** — a project whose `projects.yaml` `workspace.repos` lists multiple git repositories (e.g. Mind Your Now: `mind-your-now` frontend + `mind-your-now-backend` api). A monorepo project has no `workspace.repos`; the repo-resolution door collapses it to a single synthetic entry.
- **Repo-resolution door** — `src/lib/project-repos.ts`. `resolveProjectReposFromResolvedIssueSync(issueId, resolvedProject)` returns `ResolvedProjectRepo[]` with `{ repoKey, repoPath, forge, sourceBranch, targetBranch, mergeOrder, required }`. `required` is `repo.readonly !== true` (`src/lib/project-repos.ts:91`). Call sites iterate the list; NO `if (polyrepo)` branching is ever added at a call site.
- **MergeSet** — per-issue, per-repo merge state (`src/lib/merge-set.ts`), persisted in SQLite via `src/lib/overdeck/merge-sync.ts`. Each `MergeSetRepoState` carries `mergeStatus: 'pending'|'ready'|'merging'|'merged'|'failed'|'blocked'|'skipped'`, `artifactUrl` (the PR/MR URL), and `required`. Built from the repo-resolution door by `ensureMergeSetForIssueSync`.
- **Review artifact** — the forge object under review: a GitHub PR or GitLab MR. Created per repo at `pan done` time by `createReviewArtifactsForIssuePromise` (`src/lib/review-artifacts.ts:95`).
- **Forge adapter** — `ForgeAdapter` in `src/lib/forge.ts:95` (`github` and `gitlab` implementations) with `createReviewArtifact` / `mergeReviewArtifact` / `discoverArtifact` etc.
- **Merge oracle / chokepoint** — `verifyMergedBeforeLifecycle` (`src/lib/cloister/merged-pr-verification.ts:13`): the check `postMergeLifecycle` runs before flipping an issue to merged. Every post-merge entry path (GitHub webhook, deacon reconcilers, `merge-ops` routes, `pan done --strike`, specialists) funnels through `postMergeLifecycle` (`src/lib/cloister/merge-agent.ts:293`), which calls this oracle at `merge-agent.ts:334` and returns early when it reports not-merged.
- **Coordinated polyrepo merge** — the `merge-ops.ts` path (`src/dashboard/server/routes/workspaces/merge-ops.ts:500-775`) that loops a polyrepo issue's repos, merges each artifact, then flips the MergeSet and `review_status` to merged and fires `postMergeLifecycle`.
- **Stranded repo** — a repo whose feature branch has commits not landed on its target branch and no merged review artifact, while the issue is nonetheless marked merged. The MIN-857 incident: api repo `feature/min-857` had 2 unmerged commits and no MR at all.
- **Blocker reasons** — `review_status.blockerReasons` entries surfaced by `getMergeBlockersPayload` (`src/lib/cloister/merge-blockers.ts:21`), filtered by the `MERGE_BLOCKER_TYPES` set (`merge-blockers.ts:14`), shown on the dashboard and by `pan flywheel merge-blockers`.

## Problem

The issue-level "merged" decision is single-PR everywhere. Verified against the tree at `49f770c244`:

1. **`merge-ops.ts:518-521` silently drops artifact-less repos.** The coordinated polyrepo merge computes
   ```ts
   const activeRepos = mergeSet.repos
     .filter(repo => repo.mergeStatus !== 'skipped' && !!repo.artifactUrl)
     .sort((a, b) => a.mergeOrder - b.mergeOrder);
   ```
   A **required** repo with real commits whose MR was never created (or whose creation failed — `review-artifacts.ts:130-141` leaves `mergeStatus: 'pending'` with no `artifactUrl` when `createReviewArtifact` returns no URL) is filtered out, never merged, never counted in `failedRepos` (`merge-ops.ts:740`), and the set is flipped to `status: 'merged'` at `merge-ops.ts:757-762` with `postMergeLifecycle` fired at `:768`. This is the exact MIN-857 mechanism.
2. **`verifyMergedBeforeLifecycle` checks one repo.** `merged-pr-verification.ts:24` resolves a single `{owner, repo}` via `resolveGitHubIssueSync` (the tracker repo) and looks for one merged PR on one branch. For a polyrepo GitHub project, a merged PR in the tracker repo alone satisfies the oracle; sibling repos are never queried. (For non-GitHub projects it returns `merged: false` — pre-existing behavior, unchanged by this PRD.)
3. **`POST /api/issues/:id/forge-merge` counts absent artifacts as merged.** `merge-ops.ts:1373-1456`: a repo with no discoverable artifact is marked `mergeStatus: 'skipped'` and pushed as `{ merged: true }` (`:1409-1416`), so `allMerged` (`:1456`) is true even when a required sibling has unmerged commits.
4. **Nothing reads `MergeSetRepoState.required` or aggregates per-repo merge state.** `required` is written (`merge-set.ts:90`, `merge-sync.ts:755`) and participates in zero decisions. No code anywhere computes "all required repos merged" before the issue-level transition.

Consequence: silent partial delivery — half a feature ships to production with no error and no signal (MIN-857's api half would have bricked voice UAT).

## Proposal

Add a single **merge-completeness assessor** that answers, per required repo, "does this repo still have unmerged work for this issue?", and wire it into the three decision points above. Evidence rule (squash-safe):

- Enumerate repos through the MergeSet door (`ensureMergeSetForIssueSync`, which routes through `resolveProjectReposFromResolvedIssueSync`). Never hand-roll repo discovery.
- Per **required** repo: fetch and count commits on `origin/<sourceBranch>` not reachable from `origin/<targetBranch>` (`git rev-list --count`). Zero ahead or branch absent → repo complete (no changes, or merge-commit landed).
- If commits are ahead, query the forge for a **merged** review artifact on that source branch. Merged artifact found → complete (squash/rebase merges leave branch commits unreachable from target forever, so git evidence alone would false-positive). No merged artifact → **incomplete**; name the repo, the ahead-count, and whether an open MR exists.
- Any repo whose state cannot be determined (fetch fails, forge API errors) → **fail closed**: report incomplete with an `unverifiable` classification and a clear reason. Silent partial delivery is the failure mode this issue exists to kill; a wedged merge with an actionable reason is recoverable, a stranded repo is not.

Wire-up: (a) the coordinated polyrepo merge blocks before flipping to merged when a required, non-skipped repo is stranded — after first attempting artifact self-heal via `discoverArtifact`; (b) `verifyMergedBeforeLifecycle` runs the assessor for multi-repo merge sets so every `postMergeLifecycle` entry path is guarded; (c) `forge-merge` stops counting artifact-less repos with commits as merged; (d) a new `unmerged_sibling_repo` blocker type surfaces the block on the dashboard and `pan flywheel merge-blockers`.

## Requirements

- **FR-1** Repo enumeration for the gate goes exclusively through `ensureMergeSetForIssueSync` / `resolveProjectReposFromResolvedIssueSync`; no new resolver, no `workspaceConfig.type === 'polyrepo'` conditional at call sites.
- **FR-2** The forge layer exposes a merged-artifact lookup for a source branch on both GitHub and GitLab adapters.
- **FR-3** `assessMergeCompleteness(issueId)` classifies every required repo as `merged` | `no-changes` | `unmerged` | `unverifiable`, with human-readable per-repo reasons, and `complete === true` only when no repo is `unmerged`/`unverifiable`.
- **FR-4** `verifyMergedBeforeLifecycle` returns `merged: false` with a repo-naming reason when the issue's merge set has >1 repo and the assessor reports incomplete, so no `postMergeLifecycle` caller can flip a partially-merged issue.
- **FR-5** The coordinated polyrepo merge refuses to mark the set/issue merged while a required, non-skipped repo lacks a merged artifact: it first self-heals via `discoverArtifact`, then classifies (no commits ahead → record `skipped`; commits ahead → fail the merge naming the repo).
- **FR-6** `POST /api/issues/:id/forge-merge` reports `merged: false` for a repo with commits ahead and no artifact, and does not fire `postMergeLifecycle` in that case.
- **FR-7** A blocked train writes a `blockerReasons` entry of type `unmerged_sibling_repo`, and `getMergeBlockersPayload` includes that type.
- **FR-8** A guard test proves a polyrepo issue with one required repo stranded does NOT reach `mergeStatus: 'merged'`.
- **NFR-1** No `execSync` anywhere server-reachable — assessor and forge lookup use `execAsync`/async spawn only.
- **NFR-2** `merge-ops.ts` is baselined at 1923 lines in `scripts/file-size-baseline.txt` and may not grow: gate logic lives in the new module; if the calling diff still grows the file, the same commit carries a manually audited baseline edit referencing PAN-2467.
- **NFR-3** Any test exercising retries/delays uses `vi.useFakeTimers()` (repo rule); assessor tests mock exec rather than sleeping.

### W2 — Merge-completeness assessor (FR-1, FR-3) — foundation, inspect before dependents

**Files:** `src/lib/cloister/merge-completeness.ts` (new), `tests/unit/lib/cloister/merge-completeness.test.ts` (new).

```ts
export type RepoCompleteness = 'merged' | 'no-changes' | 'unmerged' | 'unverifiable';
export interface RepoCompletenessResult {
  repoKey: string; state: RepoCompleteness; aheadCount: number; artifactUrl?: string; reason: string;
}
export interface MergeCompletenessResult { complete: boolean; repos: RepoCompletenessResult[]; summary: string; }
export async function assessMergeCompleteness(issueId: string, labels?: string[]): Promise<MergeCompletenessResult>
```

Algorithm per repo from `ensureMergeSetForIssueSync(issueId)` (fall back to `resolveProjectReposForIssueSync` only if the merge set cannot be built; both are doors):

1. Skip `required === false` repos (record them as `no-changes` with reason "readonly repo").
2. In the repo's **primary checkout** (`ResolvedProjectRepo.repoPath` — workspaces may already be torn down at webhook/deacon time): `git fetch origin <sourceBranch> <targetBranch>` (tolerate a missing source branch — that means no changes), then `git rev-list --count origin/<targetBranch>..origin/<sourceBranch>`.
3. `aheadCount === 0` or branch absent → `no-changes`.
4. `aheadCount > 0` → `getForgeAdapter(repo.forge).findMergedArtifact({ sourceBranch, cwd: repoPath })`; found → `merged`; not found → `unmerged` with reason `"<repoKey>: <n> commit(s) on <sourceBranch> not on <targetBranch>, no merged artifact"`.
5. Any exec/forge error → `unverifiable` with the error message (fail closed).
6. `complete = repos.every(r => r.state === 'merged' || r.state === 'no-changes')`; `summary` joins incomplete repos' reasons.

All git/forge calls via `execAsync`-style async helpers (NFR-1). Tests inject mocked exec/adapters and cover: all-merged, one stranded (unmerged), squash-merged branch with merged MR, fetch failure → unverifiable → `complete: false`, monorepo single-entry set.

## Decisions (made here, not by the implementer)

- **D1 Evidence rule is git-ahead + merged-artifact, not git alone** — squash merges leave branch commits permanently unreachable from target; git-only would block forever after every squash merge.
- **D2 Unverifiable fails closed** — a repo whose state can't be determined blocks the train with a reason; silent partial delivery is strictly worse than a retryable block.
- **D3 Gate placement is merge-ops pre-flight + `verifyMergedBeforeLifecycle`** — not `auto-merge-eligibility.ts`, not `merge-strike.ts`, not the UAT train; those are campaign siblings (#3040, #1696) and this issue must not sprawl into them.
- **D4 Self-heal before blocking** — an artifact that exists but was never recorded (artifact-creation race) is recovered via `discoverArtifact` rather than blocking the operator.
- **D5 Non-GitHub monorepo behavior in the oracle is unchanged** — `verifyMergedBeforeLifecycle`'s `Non-GitHub project` early return predates this issue; the GitLab polyrepo case is protected by the merge-ops gate (the path MIN-857 actually took).
- **D6 New blocker type, not overloading `not_mergeable`** — `unmerged_sibling_repo` names the failure so the flywheel/operator can act without reading logs.
