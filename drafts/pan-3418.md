# PRD: PAN-3418 — Empty-string conversation model is stored, never backfilled, and blanks the harness+model chips

**Issue:** https://github.com/eltmon/overdeck/issues/3418
**Mode:** `pan plan --auto` (no interactive Q&A; all decisions recorded in `autoDecisions`)

## Glossary

- **Conversation** — a row in the `conversations` table of `~/.overdeck/overdeck.db`, backing a `conv-*` tmux session.
- **Write door** — the only module allowed to write a domain's store. For conversations, the live write door is `src/lib/overdeck/conversations.ts` (functions `createConversation`, `backfillConversationModel`, `setConversationModel`, …).
- **Backfill** — `backfillConversationModels()` in `src/lib/overdeck/conversation-runtime.ts:463`, triggered once per dashboard boot by `startConversationModelBackfill()` (`src/dashboard/server/routes/conversations.ts:188`). It reads each model-less conversation's JSONL transcript and records the model the harness actually used.
- **`FALLBACK_GROUPS`** — the hardcoded Anthropic+OpenAI model list in `src/dashboard/frontend/src/components/chat/ModelPicker.tsx` (ends at line 108) used until `/api/settings/available-models` resolves.
- **`knownModelIds`** — module-level `Set` in `ModelPicker.tsx:115`, initialized from `FALLBACK_GROUPS` and re-synced by `syncKnownModels()` when the real model list arrives.
- **`liveConversation`** — `ModelPicker` prop. When true the picker drives a *running* conversation's model switch; when false (Command Deck header) it selects the model for the *next* conversation.
- **Command Deck** — the sidebar surface in `src/dashboard/frontend/src/components/CommandDeck/index.tsx` that hosts the new-conversation `ModelPicker` and the conversation list (`ConversationRow`).

## Problem statement

A conversation can be created with `model = ''` (empty string). The row is then permanently wrong: the harness and model chips vanish from the Command Deck row, and the boot-time backfill can never repair it because its SQL predicate only matches `model IS NULL`. Reproduced live on conversation `20260801-7889` (conv 1794), which silently ran 222/222 assistant turns on `claude-opus-5` with no `--model` flag and no record of that choice. A read-only sweep of the host DB (2026-08-01) found **5 rows with `model = ''`** (`20260801-7889`, `20260726-3088`, `20260720-9741`, `20260709-1871`, `20260624-1015`).

### Verified causal chain (every link checked against the workspace tree)

1. **Frontend fallback is legitimately `''`.** `FALLBACK_DEFAULT_CONVERSATION_MODEL = ''` at `src/dashboard/frontend/src/components/chat/defaultConversationModel.ts:4` (deliberate — no hardcoded model fallbacks).
2. **CommandDeck captures `''` and never re-seeds.** `useState<string>(loadStoredModel)` at `src/dashboard/frontend/src/components/CommandDeck/index.tsx:244` runs once at mount. `loadStoredModel` (`ModelPicker.tsx:127`) validates the localStorage value against `knownModelIds`, which at mount only covers `FALLBACK_GROUPS` — a last-used model from any other provider (`k3`, GLM, MiniMax, OpenRouter favorites) fails validation and falls through to `getDefaultConversationModel()` → `''`. The picker's mount effect (`ModelPicker.tsx:204-291`) fetches the real model list and calls `syncKnownModels(effectiveGroups)` (line 277) but **never calls `onChange`**, so the parent's `sidebarModel` stays `''`.
3. **The server keeps `''` as a supplied value.** `src/lib/overdeck/conversation-runtime.ts:885-886`:
   ```ts
   const model = typeof body['model'] === 'string' ? body['model'].trim() : undefined;
   const effort = typeof body['effort'] === 'string' ? body['effort'].trim() : undefined;
   ```
4. **The write door's `??` doesn't catch `''`.** `src/lib/overdeck/conversations.ts:1233-1234` (`createConversation`) and `:1294` (`reactivateConversationForSpawn`) use `opts.model ?? null` — `??` only guards null/undefined.
5. **The backfill predicate can never heal `''`.** `src/lib/overdeck/conversations.ts:1375-1377`:
   ```ts
   overdeckDb().prepare(`UPDATE conversations SET model = ? WHERE name = ? AND model IS NULL`).run(model, name);
   ```
   The probe above it (`conversation-runtime.ts:469`) already selects `!conv.model` rows (falsy covers `''`), so only the SQL predicate blocks the repair.
6. **Both chips are gated on the model.** `src/dashboard/frontend/src/components/CommandDeck/ConversationRow.tsx:400-407` renders harness + model chips only inside `{conv.model && (…)}`, hiding the correctly-stored harness too.

**Correction to the issue body:** the issue cites `src/lib/database/conversations-db.ts:507` and `:683`. That module has **zero production consumers** (verified: `git grep -rl "from.*conversations-db" src/` returns nothing; the header comment of `tests/unit/lib/database/conversation-workspace-linkage.test.ts` states the same). The live path is `src/lib/overdeck/conversations.ts`. All fixes target the live module; the dead duplicate is left untouched.

**Additional finding:** `resolveAllowedHarness` (`conversation-runtime.ts:196`) returns `'claude-code'` whenever `!model`, so an empty model also pinned harness resolution — coercing `''` to `undefined` preserves that designed default while letting an explicit harness resolve normally when a model *is* present.

## Requirements

- **FR-1** — `handleConversationCreate` coerces an empty/whitespace-only `model` and `effort` to `undefined`, so an empty request field behaves identically to an omitted one.
- **FR-2** — The conversation write door stores `NULL`, never `''`, for `model` and `effort` (both `createConversation` and `reactivateConversationForSpawn`).
- **FR-3** — `backfillConversationModel` matches `WHERE name = ? AND (model IS NULL OR model = '')` so already-broken rows self-heal on the next backfill pass.
- **FR-4** — The Command Deck model picker re-seeds its selection after the real model list and settings resolve, so a last-used model absent from `FALLBACK_GROUPS` is restored instead of blanked.
- **FR-5** — `ConversationRow` renders the harness chip independently of model presence; the model chip renders only when a model is known.
- **FR-6** — The 5 existing `model = ''` rows on the host DB are repaired through the write door (the widened backfill), with `20260801-7889` resolving to `claude-opus-5`; any row whose transcript can't resolve a model is logged, not guessed.
- **NFR-1** — No silent model fallback: a model-less conversation is stored `NULL` and the model the harness actually used is recorded from its transcript by the backfill.
- **NFR-2** — No hardcoded model default is introduced anywhere (repo rule: never hardcode a model fallback).

## Decisions (made here, not left to the implementer)

- **D1 — Fix the live write door.** All DB changes land in `src/lib/overdeck/conversations.ts`. The issue-cited `src/lib/database/conversations-db.ts` is production-dead and stays untouched (surgical-changes rule; removing it is a separate cleanup concern).
- **D2 — Re-seed from inside ModelPicker via `onChange`** (the issue's option A), gated on `!liveConversation`. The picker alone knows when the fetch settled and what `knownModelIds` became; CommandDeck re-running `loadStoredModel` would have to guess the timing. Gating on `!liveConversation` is mandatory — auto-firing `onChange` in a live-conversation panel would switch a running session's model.
- **D3 — Record, don't reject.** "Never spawn with an empty model silently" is satisfied by *recording the model the harness actually used* (widened backfill, FR-3), not by failing loudly. Operators may deliberately create model-less conversations to use their personal CLI default; rejecting them would break a legitimate flow. Combined with FR-4, new conversations will practically always carry an explicit model.
- **D4 — Data repair rides the backfill.** The 5 broken rows heal automatically at the first dashboard boot after deploy (the backfill runs at `routes/conversations.ts:188` module load). No hand-rolled `UPDATE`s — `backfillConversationModel` is the write door and does the repair.
- **D5 — Tests fold into their implementation items** (tracer-bullet slices), one new test file per backend item to avoid parallel-edit conflicts on a shared test file.
- **D6 — Effort gets the same coercion as model** (FR-1/FR-2): `''` effort has the identical store-and-never-heal shape (`SAFE_EFFORT_PATTERN` guard at `conversation-runtime.ts:892` is falsy-skipped by `''`). `harness` needs no coercion — `resolveAllowedHarness` validates it against the allowed set.

## Work items

### WI-1 — Coerce empty model/effort at the route boundary (`server-coerce-empty-fields`)

**File:** `src/lib/overdeck/conversation-runtime.ts:885-886`

Before:
```ts
const model = typeof body['model'] === 'string' ? body['model'].trim() : undefined;
const effort = typeof body['effort'] === 'string' ? body['effort'].trim() : undefined;
```
After:
```ts
const rawModel = typeof body['model'] === 'string' ? body['model'].trim() : undefined;
const model = rawModel ? rawModel : undefined;
const rawEffort = typeof body['effort'] === 'string' ? body['effort'].trim() : undefined;
const effort = rawEffort ? rawEffort : undefined;
```
(Or equivalently `body['model'].trim() || undefined` inline — implementer's choice, same semantics.)

**Test (same commit):** new `tests/unit/lib/overdeck/conversation-runtime-empty-model.test.ts`. `vi.mock('../../../../src/lib/overdeck/conversations.js')` (capture `createConversation` opts; stub `getConversationByName` → null, `listConversations` → []) and `vi.mock('../../../../src/dashboard/server/event-store.js')` (`getEventStore()` → `{ emitOnly: vi.fn() }`). The fire-and-forget spawn IIFE (`conversation-runtime.ts:911`) catches its own errors, so the test must not await it; assert only on the synchronous `createConversation` call.

### WI-2 — Write door stores NULL for empty model/effort (`db-writes-null-for-empty`)

**File:** `src/lib/overdeck/conversations.ts`

Add a module-local helper near the other private helpers:
```ts
function nullIfEmpty(value: string | undefined): string | null {
  const trimmed = value?.trim();
  return trimmed ? trimmed : null;
}
```
Apply it in `createConversation` (params at lines 1233-1234: `opts.model ?? null` → `nullIfEmpty(opts.model)`, same for `opts.effort`) and in `reactivateConversationForSpawn` (line 1294: `opts.model ?? null` → `nullIfEmpty(opts.model)`). Defense-in-depth at the write door: even a caller that bypasses the route cannot store `''`.

**Test (same commit):** new `tests/unit/lib/overdeck/conversations-empty-model.test.ts` using `setupOverdeckTestDb()` from `tests/helpers/overdeck-test-db.ts` (pattern: `tests/unit/lib/database/conversation-workspace-linkage.test.ts`). Cases: `createConversation({…, model: ''})` → `getConversationByName(name).model` is `null`; `model: '  '` → `null`; `model: 'k3'` → `'k3'`; `effort: ''` → `null`; `reactivateConversationForSpawn({…, model: ''})` → `null`.

### WI-5 — Picker re-seeds after the model list resolves (`picker-reseeds-after-model-list-load`)

**File:** `src/dashboard/frontend/src/components/chat/ModelPicker.tsx`, inside `loadModels()` (mount effect, lines 204-291).

After `syncKnownModels(effectiveGroups)` (line 277) and settings resolution, add (per D2):
```ts
if (!liveConversation) {
  const resolved = loadStoredModel(getDefaultConversationModel());
  if (resolved && resolved !== value && isKnownModel(resolved)) {
    const found = effectiveGroups.flatMap((g) => g.models).find((m) => m.id === resolved);
    onChange(resolved, found?.effortLevels ?? []);
  }
}
```
Why this is safe against clobbering a fast user pick: the parent (`CommandDeck/index.tsx:1348-1351`) persists every user pick via `saveStoredModel`, so `loadStoredModel()` at resolution time returns the user's fresh pick if they chose one during the fetch — `onChange` then fires with the value they already have, a harmless no-op. The stale closure over `value` (mount-time `''`) is exactly what we want to compare against.

**Test (same commit):** extend `src/dashboard/frontend/src/components/chat/__tests__/ModelPicker.test.tsx`. Mock fetch for the three endpoints the mount effect calls (`/api/settings/available-models` returning a group containing `k3`, `/api/settings/openrouter/models`, `/api/settings`) plus `/api/settings/harness-policy`; seed `localStorage['conv-composer-model'] = 'k3'`; render with `value=""` and a spy `onChange`; assert `onChange` was eventually called with `('k3', expect.any(Array))`. Second case: `liveConversation={true}` → `onChange` NOT called by the effect.

## Acceptance criteria (map 1:1 to work items)

- **AC-1 (WI-1):** POST `/api/conversations` with `model: ''` (or whitespace-only) reaches `createConversation` with `model: undefined`; same for `effort`. Proven by `conversation-runtime-empty-model.test.ts`.
- **AC-2 (WI-2):** `createConversation` and `reactivateConversationForSpawn` persist `NULL` for empty/whitespace `model` and `effort`, and persist real values unchanged. Proven by `conversations-empty-model.test.ts`.
- **AC-3 (WI-3):** `backfillConversationModel` repairs a row seeded with `model = ''` and never overwrites a non-empty model. Proven by `conversations-model-backfill.test.ts`.
- **AC-4 (WI-4):** `ConversationRow` renders the harness chip when `model` is null, and both chips when a model is present. Proven by `ConversationRow.test.tsx`.
- **AC-5 (WI-5):** Given a localStorage model absent from `FALLBACK_GROUPS` but present in the fetched list, the picker calls `onChange` with it after the mount fetch; with `liveConversation`, it never does. Proven by the extended `ModelPicker.test.tsx`.
- **AC-6 (WI-6):** Post-deploy, `20260801-7889.model = 'claude-opus-5'` and zero `model = ''` rows remain (or every remainder is logged with a reason in an issue comment).
- **AC-7 (all):** `npm run typecheck`, `npm run lint`, and `npm test` pass with the new tests included.

## NonGoals

- No hardcoded conversation-model default anywhere (NFR-2) — a model-less conversation stays `NULL` and is recorded by the backfill.
- No changes to the production-dead `src/lib/database/conversations-db.ts` duplicate.
- No rejection of model-less conversation creation (D3).
- No auto-switching of a running conversation's model — the re-seed is gated on `!liveConversation` (D2).
- The missing cost/token figures on young conversation rows (explicitly excluded by the issue — enrichment fills them in later).
- `extractModelFromSessionFile` semantics (records the *first* assistant model in the transcript) are unchanged; mid-session model switches are out of scope.
