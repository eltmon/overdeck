# PAN-3727 PRD — Sweeper ghost escalations for closed issues

## Glossary

- **Parked orbit** — a state an issue can sit in where no autonomous actor will
  advance it within 24h. Nine orbits exist (stuck-flag, needs-you,
  deacon-ignored, operator-gate, uat-failed, merge-failed, zombie-session,
  idle-running, circuit-breaker). Defined in `src/lib/parked/resolver.ts:46-58`.
- **Parked resolver** — `resolveParkedPopulation()`
  (`src/lib/parked/resolver.ts:425`), the single read door that unions all nine
  orbits into typed rows. Consumed by the stall sweeper, `pan parked`,
  `GET /api/parked`, and the velocity route.
- **Stall sweeper** — `runStallSweeperPatrol()`
  (`src/lib/cloister/stall-sweeper.ts:152`). Operator-owned orbits
  (operator-gate, deacon-ignored, needs-you, circuit-breaker) are never acted
  on; they are re-surfaced to the operator via `sweep.escalated` events on a
  24h TTL.
- **Recovery trip** — a durable record of a recovery path that tripped ≥25
  times, stored on the per-issue record (`record.recoveryTrips[]`,
  `src/lib/pan-dir/record.ts`). An `open: true` trip classifies as a needs-you
  parked row. Door: `acknowledgeRecoveryTrip()`
  (`src/lib/cloister/recovery-trip.ts:67`).
- **Operator stop gate** — `stoppedByUser` on an agent row (agents table in
  `overdeck.db`, mirrored from state.json). Set by `markAgentStopped(state,
  'operator')` (`src/lib/agents/agent-state.ts:912-925`). Classifies as an
  operator-gate parked row when the agent is not running and has no completed
  handoff marker (`src/lib/parked/resolver.ts:292`).
- **Per-issue record** — `records/<issue>.json` on `overdeck-state`, read via
  `readIssueRecord()` (`src/lib/pan-dir/record.ts:463`). Its `pipeline` block
  (`PanIssuePipelineRecord`, `src/lib/pan-dir/record.ts:163-209`) carries
  `closedOut`, `closedOutAt`, `reopenedAt`, and `mergeStatus`.
- **Close-out** — the `closeOut()` lifecycle workflow
  (`src/lib/lifecycle/workflows.ts:171`), invoked by `pan close <id>` and
  automatic close-out. Verifies the merge, tears down the workspace, closes
  the tracker issue, marks the record pipeline terminal
  (`markRecordPipelineClosedOutSync`, `src/lib/pan-dir/record.ts:925-940`),
  prunes stopped agent rows (`pruneStoppedAgentsForIssue`,
  `src/lib/cloister/agent-gc.ts:299`), and clears review status.
- **Tracker closed check** — `isIssueClosed()`
  (`src/lib/cloister/issue-closed.ts:157`). Shadow-state first, then a live
  tracker call (`isTrackerIssueClosed`, TTL-cached 5 min). Deliberately
  returns `false` on any error/timeout — the correct posture for the
  destructive closed-issue reaper, noisy for the sweeper.

## Problem

The stall sweeper escalates parked rows for issues that are already merged and
closed. Observed on MIN-941 (Done in Linear since 2026-08-06, fully merged):
ghost `sweep.escalated` events fired 2026-08-10 and 2026-08-14 while the issue
was invisible in CTRL-K and the pipeline.

Three verified root causes:

1. **Close-out leaves parked-classifier residue in place.** MIN-941's record
   has a `closeOut` block (close-out ran), yet it still carried an open
   recovery trip (`orphan-proposed-pickup-gate`, `open: true`, from planning
   on 2026-08-05) → needs-you row; and `planning-min-941` still has
   `stopped_by_user = 1` in the agents registry → operator-gate row.
   `closeOut()` never acknowledges open trips, and
   `pruneStoppedAgentsForIssue` preserves stopped rows whose state dir has
   retained transcripts (`src/lib/cloister/agent-gc.ts:262-264`), leaving the
   gate flags on the surviving row.
2. **The resolver's only terminality evidence for non-live issues is a live
   tracker call that fails open toward "open".** Pass 2 of
   `resolveParkedPopulation` (`src/lib/parked/resolver.ts:488-498`) calls
   `isIssueClosed` for every row-producing issue; for Linear issues
   `isLinearIssueClosed` returns `false` on any error/timeout and the negative
   result is cached for 5 min. One blipped lookup resurrects a closed issue
   into the parked population for up to ~5 min — long enough for the sweeper
   to see a row whose 24h re-surface TTL has expired and escalate it.
3. **Cheap local terminal evidence exists and is already being read.** The
   resolver reads the per-issue record for trips (`defaultReadOpenTrips`,
   `src/lib/parked/resolver.ts:400`), and that same record carries
   `pipeline.closedOut === true` / `pipeline.mergeStatus === 'merged'` after
   close-out. Treating record-level terminality as decisive for non-zombie
   orbits kills both ghost rows for every closed-out issue without touching
   the reaper's fail-closed semantics.

Interim state: the MIN-941 trip was manually acked on 2026-08-14
(overdeck-state `f1d187e8`), so the needs-you ghost is gone. The
`planning-min-941` stop-gate row was deliberately left, so one more
operator-gate ghost escalation is possible on a tracker blip until this fix
lands.

## Proposal

Four changes, each behind an existing door pattern:

1. **Close-out acknowledges its own residue.** After the agent-row prune in
   `closeOut()`, a new step acknowledges every open recovery trip on the issue
   (via a new `acknowledgeAllOpenRecoveryTrips` door extracted from the
   `pan parked ack` loop) and clears operator-gate flags (`stoppedByUser`,
   `troubled`, operator `paused`) on the issue's remaining stopped agent rows
   (via a new `clearAgentOperatorGatesForIssueSync` door in
   `src/lib/agents/agent-state.ts`).
2. **Resolver hardening.** `resolveParkedPopulation` reads record-level
   terminality (`pipeline.closedOut === true`, or `pipeline.mergeStatus ===
   'merged'` with no `reopenedAt`) from the same record read that already
   fetches trips. A record-terminal issue is treated as closed: no tracker
   call, non-zombie orbits suppressed, trips skipped. Tracker terminality
   remains the fallback when the record carries no terminal evidence (e.g.
   strikes merged without close-out).
3. **Reopen keeps the record truthful.** `clearRecordPipelineClosedOut(Sync)`
   (`src/lib/pan-dir/record-update.ts:127-158`) — the single door both
   `pan reopen` and the state-plane patrol reopen path use — also drops a
   stale `pipeline.mergeStatus === 'merged'`, so a reopened issue is never
   record-terminal.
4. **Residue reconciliation patrol.** A new
   `reconcileTerminalIssueResidue()` in
   `src/lib/cloister/parked-residue.ts`, wired into the deacon on the same
   hourly cadence as the state-plane patrol (`src/lib/cloister/deacon.ts:3113`),
   enumerates each project's records (`listIssueRecords`,
   `src/lib/pan-dir/record-list.ts:29`), finds terminal records still
   carrying open trips or operator-gate rows, and cleans them through the
   doors from items 1–2. Its first run after deploy is the one-time sweep
   covering the existing TIN-1/LEX-1-class residue; recurrence makes the
   cleanup self-healing for any future leak path.

## Requirements

### Functional

- FR-1: `closeOut()` acknowledges every open recovery trip on the issue's
  record before completing, reporting the count as a ceremony step.
- FR-2: `closeOut()` clears `stoppedByUser`, `troubled`, and operator `paused`
  flags on the issue's stopped agent rows (rows preserved by the prune keep
  their transcripts but lose the gate flags). Live agents and scheduler yields
  are never touched.
- FR-3: `resolveParkedPopulation` treats an issue whose record is
  pipeline-terminal (`closedOut === true`, or `mergeStatus === 'merged'` with
  `reopenedAt` unset) as closed: it produces no non-zombie parked rows for
  that issue and does not call the tracker closed-check for it.
- FR-4: When the record carries no terminal evidence, the resolver falls back
  to the existing tracker closed-check unchanged.
- FR-5: `pan reopen` (and the state-plane patrol reopen path) leaves the
  record with no `pipeline.mergeStatus === 'merged'`, so a reopened issue
  classifies as non-terminal.
- FR-6: The deacon runs a terminal-residue reconciliation on the state-plane
  patrol cadence that acknowledges open trips and clears operator-gate flags
  on stopped agent rows for every record-terminal issue, across all projects.

### Non-functional

- NFR-1: The destructive reaper's fail-closed tracker posture
  (`isLinearIssueClosed` returning `false` on error) is unchanged.
- NFR-2: All new writes go through existing door patterns
  (`updateIssueRecordForWorkspace` for trips, `saveAgentStateSync` for agent
  flags); no direct store access.
- NFR-3: New tests use `vi.useFakeTimers()` for any delay/TTL logic and never
  real `setTimeout`.
- NFR-4: The resolver change adds no new I/O per candidate issue — record
  terminality rides the record read that already fetches trips.

## Decisions

- D1: Record terminality is decided locally and never fails open — a missing
  or unreadable record means "no evidence", falling through to the tracker
  check. This inverts the failure mode that caused the ghost: tracker blips
  can no longer resurrect an issue the record proves terminal.
- D2: The `reopenedAt` guard in the terminal predicate is defense-in-depth for
  records written before WI-5 lands (an issue reopened before this fix keeps
  a stale `mergeStatus: 'merged'`); WI-5 stops new staleness at the door.
- D3: The residue sweep is a recurring patrol, not a one-time CLI — the first
  run after deploy covers the existing backlog (TIN-1/LEX-1 class), and
  recurrence self-heals any future leak path that bypasses close-out.
- D4: Residue cleanup failure inside close-out is non-blocking (stepSkipped).
  A completed merge must never be un-closable because a bookkeeping ack
  failed; the patrol (WI-6) is the backstop.
- D5: `isLinearIssueClosed`'s false-on-error posture is deliberately NOT
  changed — it protects the destructive closed-issue reaper. The sweeper's
  noise is fixed by giving the resolver better evidence, not by loosening the
  reaper's safety margin.

## Acceptance Criteria

- AC-1 (FR-3): Given a record-terminal issue with an open recovery trip and a
  stoppedByUser agent row, when `resolveParkedPopulation` runs, then it
  returns no rows for that issue and never calls the tracker closed-check —
  proven by the new resolver tests with an `isClosed` spy that fails the test
  if invoked.
- AC-2 (FR-1, FR-2): Given a close-out fixture with an open trip and a
  preserved stoppedByUser row, when `closeOut()` completes, then the record
  has no open trips and the agent row has no gate flags, and the ceremony
  output contains a `close-out:ack-parked-residue` step.
- AC-3 (FR-5): Given a closed-out record, when `pan reopen` runs, then the
  record's `pipeline.mergeStatus` is no longer `'merged'` and the resolver
  classifies the issue as non-terminal.
- AC-4 (FR-6): Given a project whose records include a terminal issue with an
  open trip, when the deacon's residue reconciliation runs, then the trip is
  acknowledged and an action message names the cleaned issue.
- AC-5 (NFR-1): `git diff` on `src/lib/cloister/issue-closed.ts` is empty —
  the reaper posture is untouched.
- AC-6: `npm run typecheck`, `npm run lint`, and `npm test` pass with the new
  tests included.
