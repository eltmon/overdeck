## Glossary

- **The hotfix** — `authorizeTerminalUpgrade()` in `src/dashboard/server/ws-terminal.ts:88-101` currently
  runs ONLY `validateOriginHeaders(...)`; the PAN-457 token/cookie gate was removed (the comment at
  `:89-95` names this issue as the tracking ticket). `/ws/rpc` had the same gate removed
  (`ws-rpc.ts:1293-1301`, origin-only `validateOrigin`); `/ws/voice` is origin-only too
  (`ws-voice.ts:27-31`, `:50-61`).
- **Session cookie** — `overdeck_session` (`dashboard-auth.ts:12`), HMAC-derived from the internal token
  with context `overdeck-dashboard-session-v1` (`dashboard-auth.ts:43-46`). Because it is derived, not
  random-per-boot, **restarts no longer invalidate cookies** — the issue body's "randomBytes(32) unless
  env set" complaint is stale; the fix already landed. This PRD adds the regression test that locks it.
- **Session mint** — `POST /api/dashboard/session` (`server.ts:172-203`) accepts internal token OR
  loopback/Docker-bridge peer (`rejectUnauthorizedDashboardSessionMintRequest`, `dashboard-auth.ts:290-301`;
  `isLoopbackPeer`, `:275-288`). A browser arriving via Traefik IS a mintable peer (Traefik's connection
  originates from the host-local Docker bridge, accepted at `:286`) — the original 2026-05 breakage was the
  missing `OVERDECK_TRAEFIK_*` origin env, not the peer check. This is why auto-mint now works without the
  URL-hash token.
- **Bootstrap token** — `pan up` opens the browser at `${url}#overdeck_token=<token>`
  (`src/cli/index.ts:1409-1414`); frontend consumes it (`wsTransport.ts:50-62`) and exchanges for the cookie
  (`ensureDashboardSession`, `:64-81`) — **silently swallowing 401 at `:72`** (`if (response.status === 401) return`).
- **Reauth token** — `reauth-*` terminal sessions already require a one-time cookie token
  (`ws-terminal.ts:201-220`, `consumeReauthTerminalToken`); unchanged by this PRD.

## Problem

Anyone who can complete a WebSocket handshake with a trusted/absent Origin header gets full PTY read/write
on `/ws/terminal` and full domain-event/RPC access on `/ws/rpc`. Origin checks stop cross-origin *browser*
attacks only; they stop nothing that can set its own headers (any non-browser client on the machine, any
same-host container, and — fatally for [PAN-2350](https://github.com/eltmon/overdeck/issues/2350) — anything
that reaches the port once a tunnel or proxy fronts it). The gate must come back without recreating the
2026-05 "Reconnecting forever" regression, whose root causes are now understood (origin env + silent 401 +
per-boot session token; the third is already fixed).

## Requirements

- **FR-1** All four realtime surfaces — `/ws/terminal`, `/ws/rpc`, `/ws/voice`, and the reauth path —
  authorize upgrades with ONE shared helper: origin validation AND (session cookie OR internal token OR
  scoped token with the surface's required scope). Scopes: terminal → `operate`; rpc → `read:state`;
  voice → `operate`.
- **FR-2** Browser credential rides the cookie (browsers send cookies on same-origin upgrade requests
  automatically). Programmatic clients may use the existing `?token=` query parameter (precedent:
  `XTerminal.tsx:473-476` appends `&token=` for reauth) carrying a scoped token — never the internal token
  in a URL.
- **FR-3** The frontend guarantees mint-before-connect ordering: `ensureDashboardSession()` resolves before
  any WS connect (RPC transport and XTerminal), and a 401 from the mint is surfaced as a visible error
  state, not swallowed (`wsTransport.ts:72`).
- **FR-4** Auto-mint keeps working for loopback/Traefik-bridge peers with zero configuration (verified by
  test); `require_token_mint: true` (PAN-2351 D-4) disables peer-based mint for tunnel deployments.
- **FR-5** A threat-model section in docs states exactly what the gate defends against (same-host
  other-user/sandboxed processes; anything behind a local proxy) so future reviewers don't re-litigate.
- **NFR-1** No behavior change for the standard flows: `pan up` bootstrap, Traefik `pan.localhost`, plain
  `localhost:3011`. The 2026-05 regression scenario is a named test case.
- **NFR-2** Fake timers for any reconnect/backoff test; no real-clock waits.

## Work items

### W1 — Shared upgrade authorizer: `src/dashboard/server/ws-auth.ts` (new)

`authorizeWebSocketUpgrade(request, { requiredScope }): { ok: true, principal } | { ok: false, status, message }`.
Order: origin (`validateOriginHeaders`) → 403; then credential: session cookie (compare via
`constantTimeTokenEqual`, `dashboard-auth.ts:77-82`) ⇒ admin; `x-overdeck-internal-token` /
`Authorization: Bearer` ⇒ admin; `?token=` query ⇒ `verifyAccessToken` (PAN-2351) + `scopeSatisfies` →
401/403. Export a small `principal` (`{kind: 'session'|'internal'|'scoped', scopes}`) for logging.
Replace the bodies of `authorizeTerminalUpgrade` (`ws-terminal.ts:88-101`), the `/ws/rpc` check
(`ws-rpc.ts:1298-1301`), and `isTrustedWebSocketOrigin` usage in `ws-voice.ts:50-61` with calls to it.
Delete the hotfix comment; reference this PRD instead.
**Tests:** unit matrix in `tests/unit/dashboard/ws-auth.test.ts` — {no credential, cookie, internal token,
scoped ok, scoped missing-scope, bad origin} × {terminal, rpc, voice} expectations.

### W2 — Frontend ordering + loud 401

- `wsTransport.ts:64-81`: remove the silent-return at `:72`; on 401 set a module-level
  `sessionAuthFailed` state and throw a typed error; `WsTransport` and `EventRouter` render/log a clear
  "dashboard session could not be established — see docs/REMOTE-ACCESS.md" failure instead of reconnect-looping.
- `XTerminal.tsx`: await `ensureDashboardSession()` before `new WebSocket(wsUrl)` (`:480`), so the cookie
  exists on first upgrade. Reconnect attempts re-ensure the session (covers cookie expiry mid-session).
- Verify `/ws/rpc` connect path already awaits the session promise; if not, add the await in
  `resolveRpcUrl`'s caller.
**Tests:** frontend unit test: mint 401 ⇒ error state, no WS constructor call; mint 200 ⇒ connect proceeds.

### W3 — Regression locks for the 2026-05 failure modes

Named tests (server-side integration where possible):
1. **Traefik-shape mint:** request with trusted origin + Docker-bridge peer + no token ⇒ 200, cookie set.
2. **Restart stability:** two server "boots" (re-import module, `_resetDashboardSessionTokenForTests`,
   `dashboard-auth.ts:24-27`) with the same internal token derive the SAME session token (locks the
   HMAC derivation at `:43-46`).
3. **Gate present:** upgrade with valid origin and no credential ⇒ 401 on all three WS paths (the exact
   hole the hotfix opened).

### W4 — Threat-model doc

`docs/DASHBOARD-AUTH.md` (new): the two-token model (internal root, scoped tokens), session/CSRF HMAC

origin checks do and do NOT defend, and the 2026-05 post-mortem summary. Link from `CLAUDE.md` is NOT
