# PAN-2464 — Machine Room: complete /resources overhaul

**Issue:** https://github.com/eltmon/overdeck/issues/2464 · **Mockup (BINDING):** `docs/design/mockups/resources-machine-room.html` (operator-approved 2026-07-07).
**Verified-Against:** main @ 50f7b5a25a.

## Glossary

- **Machine Room**: the redesigned `/resources` page — every consumer of this machine (containers, agents, core services, host processes), live, attributed, reclaimable.
- **Stack**: all containers belonging to one issue's workspace (compose project `myn-feature-min-857` etc.). The default grouping unit — never a flat container list.
- **Reclaim advisor**: computed list of resources that are safe to free *because the pipeline says so* (issue merged/closed ⇒ its stack, volumes, and workspace `.venv` are candidates).
- **Spawn gate**: the guardrail verdict from `evaluateSpawnGuardrails(health)` (`src/dashboard/server/routes/agents/spawn.ts:341`) that blocks/soft-blocks agent spawns; today it surfaces only as an HTTP 409.
- **Burn rate**: live $/h per agent session, derived from the cost door (`cost_events` table) over a trailing window.
- **Idle-honesty hint**: a nag row on any stack holding >1 GB RAM while idle >2h, offering Pause.
- **docker pause**: freezes a container's processes (SIGSTOP semantics) — near-zero CPU, RAM retained, resume in seconds (no Java cold-start). Distinct from stop.

## Existing surfaces (verified)

- Server: `src/dashboard/server/routes/resources.ts` (370 lines) — `/api/resources`, per-container details/history/logs, docker **start/restart** (NO stop, NO pause), prune endpoints. Stats via `DockerStatsCollector` (`src/lib/docker-stats.ts`, imported at resources.ts:23).
- Frontend: `ResourcesPanel.tsx` (230 lines), `ResourceCard.tsx`, `ContainerDetailPanel.tsx`, `useResourceStats.ts` (22 lines), route `'/resources'` in `src/dashboard/frontend/src/App/routes.ts:12`, mounted in `AppRoutes.tsx:156`.
- Agents runtime: `agents` table (overdeck.db) + tmux `-L overdeck`; costs in `cost_events`.
- Guardrails: `emitStartAgentPhase(issueId,'guardrails',…)` events (spawn.ts:340-370) — reuse the same evaluate call for the header widget.
- Events feed: `events` table (`activity.entry`) — source for history annotations.

## Decisions

- **D1 — Extend the existing read door.** All new data flows through `/api/resources` (extended payload) and sibling endpoints in `resources.ts`; no new state plane, no direct DB access from the frontend. Where `resources.ts` would exceed the file-size ratchet, split into `routes/resources/` module folder (index + collectors + actions), baseline-neutral.
- **D2 — Stack grouping is server-side.** The server maps container → compose project → issue (via workspace path convention `workspaces/feature-<issue>`), returning stacks with aggregates; the client never re-derives grouping.
- **D3 — Reclaim candidates come from pipeline state**: merge/close status via the canonical issues resolver (never GitHub calls in the request path). A stack is reclaimable iff its issue's record says merged/closed AND no live agent session references it.
- **D4 — Pause uses `docker pause`/`unpause`;** Stop uses `docker stop` (30s grace); Tear-down = stop + `docker compose down -v` equivalent through the existing teardown lib (`src/lib/lifecycle/teardown-workspace.ts`) with a typed-confirm modal showing the reclaim estimate. Tear-down NEVER deletes the git worktree — containers/volumes only.
- **D5 — Burn rate** = cost_events for the agent's session over the last 30 min, extrapolated to $/h; total = session sum. Subscription-covered usage shows $0/h with the hypothetical in a tooltip (per the cost-display convention).
- **D6 — History annotations** are read from the `events` table (gate flips, reclaims, stack starts/stops) plus a lightweight spike-attribution sampler: when host CPU>threshold, snapshot top processes and store one annotation event. No continuous per-process history.
- **D7 — Forecast is heuristic, not ML**: predicted footprint of a stack = its own last-run peak (stored on stop) or the fleet median for first runs. Label it "≈".

## Requirements

- FR-1: Host vitals strip — CPU% + 1/5/15 load + 30-point sparkline, RAM used/avail+swap, disk used/free+reclaimable, docker counts (containers, stacks, networks/pool-31), agent count + aggregate burn, spawn-gate state with reason string. (Mockup section 1.)
- FR-2: Reclaim advisor — server computes candidates (D3): merged-issue stacks (RAM+disk), orphaned workspace `.venv`s (>1 GB, issue closed), dangling volumes + build cache, exited containers. Per-line action + "Reclaim all safe" (sequential, streamed progress). Advisor hidden when total < 500 MB.
- FR-3: Stack cards — aggregate CPU/RAM/disk meters, pipeline-phase chip (reuse phase chip components/colors from the project-overview pipeline work, PAN-2450), expandable per-service rows, UAT URL button when the project defines one.
- FR-4: Limit awareness — per-container memory limit shown as meter denominator; amber ≥85%, red ≥95%; OOM-kill count last 24h (docker events); "Raise limit" opens the compose override editor path, "Create issue" pre-fills a bug.
- FR-5: Verb set — Start, Stop, Pause/Unpause, Restart, Logs, Terminal (existing panel), Tear down (typed confirm + reclaim estimate) at stack AND service level. New endpoints: `POST /api/resources/docker/container/:id/stop`, `/pause`, `/unpause`, `POST /api/resources/stacks/:issueId/{start|stop|pause|teardown}`.
- FR-6: Agents section — per session: process-tree CPU/RAM (pgrep by session PID tree), status chip (working/idle Nm/fan-out), burn $/h + total (D5), Terminal + Pause actions (existing agent endpoints).
- FR-7: Core services — dashboard server (event-loop p99 from the existing metrics route), deacon last-tick age + patrol summary, aggregated support fleet row (traefik, smee, pty-supervisors, tldr).
- FR-8: Host processes — top-N by CPU and RAM outside docker, with owner attribution where derivable (agent session → issue; chrome; transient bursts kept 1h after exit with "caused spike" note).
- FR-9: History — 24h stacked CPU + RAM chart with annotation markers (D6); annotation list clickable → scrolls to the culprit row.
- FR-10: Idle-honesty hints (mockup rule 12) and capacity forecast bar (D7).
- FR-11: Filter box (`/`), group-by segmented control (workspace/kind/flat), keyboard S/P/L on focused row.
- NFR-1: No execSync anywhere server-side; all docker calls async with timeouts; stats collection must not raise event-loop p99 (batch `docker stats --no-stream` on the existing collector cadence).
- NFR-2: 5s auto-refresh via existing WS/event stream where available, polling fallback; page usable (cached snapshot + "stale" badge) if docker daemon is down.
- NFR-3: Destructive actions (stop/teardown/prune) are POST endpoints that are NEVER called speculatively; teardown requires typed confirmation server-validated.

## Intersecting repo rules (restated)

No `execSync` in server-reachable code (use execAsync/spawn). Fake timers for any retry/delay test. File-size ratchet — the D1 folder split keeps files under baseline. Two-door rule: pipeline state via the issues resolver only. Never speculative destructive HTTP. Dashboard runs Node 22 via `pan up`; `npm run build` before restart. Screenshot verification is the implementer's job (Playwright), not the operator's.
