## 1. Glossary

| Term | Meaning in this document |
| --- | --- |
| **Project** | One entry in `~/.overdeck/projects.yaml` (`ProjectConfig`, `src/lib/projects.ts:308`). Owns the primary path, tracker mapping, `github_repo`, `workspace.default_branch`, and the `workspaces/` directory. |
| **Workspace** | One row in the `workspaces` table (`WorkspaceRow`), kind `main`, `issue`, or `scratch`. A lens on one checkout of a project. Never owns tracker or pipeline configuration. |
| **Main workspace** | The singleton `kind='main'` row whose path is the project's primary path. Resolved or lazily created by `getMainWorkspace()` / `pan workspace main`. |
| **Registration** | Writing a project entry to `projects.yaml` through `registerProjectFromPath` (`src/lib/project-registration.ts:45`). |
| **Intent** | The operator's creation request before anything is written. |
| **Resolve** | Turning an intent into a fully computed preview plus `findings`, with zero writes. Safe to call on every keystroke. |
| **Perform** | Executing a resolved intent: the writes (clone or `git init`, registration, main-workspace bootstrap). |
| **Finding** | `{ field, code, message, detail? }`. A validation problem rendered against the field that caused it. Never a throw. |
| **Resolve-before-create** | The pattern from PAN-3330: the preview and the real create run literally the same resolve function, so the preview cannot disagree with the outcome. |
| **Mode** | How the project's directory comes to exist: `clone` (git clone a remote), `existing` (register a directory already on disk), `new` (mkdir + git init). |
| **Repo slug** | `owner/repo` for GitHub, `group/sub/repo` for GitLab. Stored as `github_repo` or `gitlab_repo`. |
| **Issue prefix** | The uppercase token in front of issue numbers (`PAN` in `PAN-3836`). Stored as `issue_prefix`. |
| **Prompt guard env** | Git environment that disables interactive credential prompts so a private repo without cached credentials fails fast instead of hanging the server. |
| **Job** | A server-side record for a long-running perform (clone). Polled by id. |
| **Two doors** | Every state domain has exactly one read path (resolver) and one write path (writer). See `docs/WORKSPACES-AND-PROJECTS.md` "The two doors". |

## 2. Background and problem

### 2.1 What exists today

**Project creation has two front doors that both produce a thin entry.**

- Dashboard: `NewProjectModal` (`src/dashboard/frontend/src/components/CommandDeck/NewProjectModal.tsx`) with tabs "Add existing" and "New project". Submit POSTs to `/api/projects` (`handleStart`, line 62).
- Route: `POST /api/projects` (`src/dashboard/server/routes/projects.ts:915`). Mode `existing` registers an absolute path under `$HOME`. Mode `new` runs `mkdir -p` then `git init` under a parent directory, then registers.
- CLI: `pan project add <path>` (`src/cli/commands/project.ts:27`, registered at line 375) with `--name`, `--linear-team`, `--rally-project`.

All three end in `registerProjectFromPath` (`src/lib/project-registration.ts:45-83`), which writes exactly this:

```ts
// src/lib/project-registration.ts:64
const projectConfig: ProjectConfig = { name, path: fullPath };
registerProjectSync(key, projectConfig);
```

It never runs `git remote get-url origin`, never sets `github_repo`, `issue_prefix`, `tracker`, or `workspace.default_branch`, and never creates the `main` workspace row. The `pan-new-project` skill (`sync-sources/skills/pan-new-project/SKILL.md`) exists because of this; its "WHY THIS SKILL EXISTS" table lists what breaks when only `pan project add` runs.

**There is no clone.** `git clone` appears in the codebase only for Fly remote VMs (`src/lib/remote-workspace.ts:116`, `src/cli/commands/workspace-remote.ts:219,241`), executed over SSH on the VM. Nothing clones onto the local machine.

**There is no resolve-before-create for projects.** The modal has no preview strip. Errors come back as ad hoc `{ error: string }` bodies from the route and are shown as one line.

**Workspace creation already has the right shape.** `src/lib/workspaces/create.ts` exports `resolveWorkspaceCreateIntent` (line 241) and `performWorkspaceCreate` (line 359). The page `/workspaces/new` (`src/dashboard/frontend/src/pages/NewWorkspacePage.tsx`) calls `POST /api/workspace-registry/resolve` on every settled field change through `useWorkspaceCreateIntent` (`src/dashboard/frontend/src/components/workspace/new/useWorkspaceCreateIntent.ts`). This PRD copies that shape onto projects.

### 2.2 What the reference implementation does

Orca's clone handler (`~/Projects/orca/src/main/ipc/repos/repo-clone-lifecycle.ts:116-292`) is the model for WI-1's perform step:

- Derives the target folder from the URL basename minus `.git` (`repo-clone-path.ts:17-57`).
- Claims the target with a non-recursive `mkdir` and records that it created it, so only a directory it created is deleted on failure.
- Spawns `git clone --progress -- <url> <path>` with `stdio: ['ignore','ignore','pipe']` and parses `^([\w\s]+):\s+(\d+)%` from stderr for progress.
- Sets `GIT_TERMINAL_PROMPT=0`, empty `GIT_ASKPASS`/`SSH_ASKPASS`, `GCM_INTERACTIVE=never`, and `GIT_SSH_COMMAND='ssh -o BatchMode=yes'` (`src/shared/git-credential-prompt-env.ts:85-104`, `src/main/git/command-runner/git-process-env.ts:61-78`) so a private repo without cached credentials fails fast.
- Discovers owner/repo from the remote after clone and derives the project id `github:<owner>/<repo>` from it.

Orca has no server-side dry run; validation is client-side gates. Overdeck keeps resolve-before-create.

## 3. Goals and non-goals

### Goals

1. Clone a GitHub (or GitLab) repository into `~/Projects/<repo>` and register it as a project, from the dashboard and the CLI.
2. Every project creation mode resolves through one server-side function that produces a complete preview and `findings` before anything is written.
3. Registration derives `github_repo` / `gitlab_repo`, `tracker`, `workspace.default_branch`, and a proposed `issue_prefix` from the repository, and creates the `main` workspace row.
4. A `/projects/new` page replaces `NewProjectModal`, with a one-line guide on project versus workspace.

### Non-goals (explicit follow-ups, do not implement here)

- A smart name field on `/workspaces/new` that accepts an issue id or URL and routes to `pan start`.
- Checked-in per-repo setup config (shared directories, setup command) like Orca's `orca.yaml`.
- Moving worktrees out of `<project>/workspaces/` to a central directory.
- Cloning onto a Fly remote host.
- Editing the tracked `.gitignore` of a registered repository (see D-8).
- Test/quality-gate config detection (`tests:`, `quality_gates:`). The skill keeps doing that.

## 4. Decisions (made here, not by the executor)

- **D-1. Clone is a project mode, never a workspace mode.** A cloned repo has its own remote and identity, so it needs a project entry. A second checkout of a known project is an isolated workspace, which already exists.
- **D-2. Remote probing is memoized and never runs per keystroke.** Resolve runs `git ls-remote --symref <url> HEAD` only after the URL parses, memoizes the result by normalized URL for 60 seconds, and the pre-write resolve passes `refreshRemote: true` to bypass the memo. This mirrors `refreshParentBranch` in `WorkspaceCreateInput` (`src/lib/workspaces/create.ts:104`). Hard timeout 15 000 ms. Uses the prompt guard env. Timeout, non-zero exit, or unparseable output becomes the finding `remote-unreachable`; it never throws.
- **D-3. Proposed issue prefix = uppercase key with hyphens removed, truncated to 10 characters.** The derivation `parseGitHubReposSync` already applies when `issue_prefix` is unset (`src/lib/tracker-utils.ts:72-74`: `key.toUpperCase().replace(/-/g, '')`) is kept for keys of 10 characters or fewer, so short keys stay identical to today; longer keys are cut to the first 10 characters so the proposal always passes the `/^[A-Z][A-Z0-9]{0,9}$/` validation. The operator may override. If another project already has that prefix in `issue_prefix` or `issue_prefixes`, finding `issue-prefix-taken`.
- **D-4. Default parent directory for `clone` and `new` is `~/Projects`.** Same default the modal uses today (`NewProjectModal.tsx:45`, `${data.path}/Projects`). The parent need not exist; it is created with `mkdir -p` at perform time.
- **D-5. Clone failure cleanup deletes only what the core created.** The core claims the target with a non-recursive `mkdir`. If that `mkdir` succeeded and the clone then fails, the core removes the target directory. It never removes the parent, and never removes a target it did not create.
- **D-6. Clone runs as a job.** `POST /api/projects` with `mode: 'clone'` returns `202 { jobId }`. The page polls `GET /api/projects/create-jobs/:jobId` every 750 ms. Jobs live in an in-memory `Map` in the route module and are dropped 10 minutes after reaching a terminal state. If the poll returns 404 (server restarted mid-clone), the page fetches `GET /api/registered-projects` and treats the project as created when the expected key is present, otherwise shows "Clone was interrupted; check `<path>` and retry".
- **D-7. `existing` and `new` keep the synchronous contract.** They still return `200 { key, name, path }` so `NewProjectWiring.test.tsx` expectations carry over. Only `clone` returns 202.
- **D-8. `workspaces/` is excluded through `.git/info/exclude`, not the tracked `.gitignore`.** Registration must not dirty a repository the operator just cloned. Perform appends `workspaces/` (or the configured `workspaces_dir` plus `/`) to `<primary>/.git/info/exclude` when `.git` is a directory and the line is not already present. Skip when `.git` is a file (a worktree). The `pan-new-project` skill's Step 6 becomes optional and says so.
- **D-9. Main bootstrap reuses the workspace core.** Perform calls `resolveWorkspaceCreateIntent({ kind: 'main', projectKey })` then `performWorkspaceCreate(intent)`, guarded by `getMainWorkspace(projectKey)`, exactly as `workspaceMainCommand` does (`src/cli/commands/workspace-scratch.ts:92-119`). No second implementation.
- **D-10. `registerProjectFromPath` gains an optional `extras` argument.** `RegisterProjectOptions` adds `extras?: Pick<ProjectConfig, 'issue_prefix' | 'github_repo' | 'gitlab_repo' | 'tracker' | 'workspace'>`. The written config is `{ name, path, ...extras }`. Callers that pass nothing get today's behavior.
- **D-11. Home-boundary enforcement is an input flag.** The route passes `homeBoundary: true` (current behavior). The CLI passes `false` because `pan project add /any/path` has always been allowed. The guard logic moves from `buildHomeGuard` (`src/dashboard/server/routes/projects.ts:904`) into the core as `isWithinHome`; the route helper is deleted.
- **D-12. Accepted URL forms** (parsed by a pure function, no network): `https://github.com/o/r`, `https://github.com/o/r.git`, `git@github.com:o/r.git`, `ssh://git@github.com/o/r.git`, and shorthand `o/r` (expands to `https://github.com/o/r.git`). GitLab: `https://gitlab.com/g/sub/r`, `git@gitlab.com:g/r.git`. Any other host clones fine but sets no repo slug and no tracker. Trailing `/` and `.git` are stripped before deriving the folder name.
- **D-13. Progress phases** are git's own words from stderr (`Counting objects`, `Compressing objects`, `Receiving objects`, `Resolving deltas`) plus the synthetic `registering` and `done`.
- **D-14. The page lives at `/projects/new`, tab id `project-new`.** All three "new project" entry points (sidebar `+`, `/workspaces/new` chip buttons, HomePage) navigate there. `?mode=clone|existing|new` preselects a tab. `NewProjectModal.tsx` is deleted in WI-6 after the no-loss audit test in WI-5 passes.
- **D-15. Existing-mode detection commands** (all async `execFile`, cwd = the directory, 5 000 ms timeout): `git remote get-url origin` for the slug; `git symbolic-ref --short refs/remotes/origin/HEAD` for the default branch, falling back to `git rev-parse --abbrev-ref HEAD`; a missing `.git` yields `isGitRepository: false` and no detection.
- **D-16. Do not refactor `resolveWorkspaceRemote`** (`src/lib/github-credentials.ts:32-47`). It has its own callers and throw semantics. The new parser is a separate pure module.
- **D-17. Detected values are proposals the operator can override.** `issuePrefix`, `name`, and `parentDir` are editable on the page and as CLI flags. `github_repo` and `default_branch` are detected only.

## 5. Requirements

### Functional

- **FR-1.** `resolveProjectCreateIntent(input)` returns a `ResolvedProjectIntent` for modes `clone`, `existing`, `new` with zero writes and no mutating git command.
- **FR-2.** `performProjectCreate(intent, hooks)` clones or inits as the mode requires, registers with detected extras, excludes `workspaces/` via `.git/info/exclude`, bootstraps the `main` workspace, and returns `{ key, name, path, mainWorkspaceId }`.
- **FR-3.** Clone progress is reported through `hooks.onProgress({ phase, percent })` and a clone failure removes only a target directory the core created (D-5).
- **FR-4.** `POST /api/projects/resolve` returns the resolved intent. `POST /api/projects` accepts `mode: 'clone'` and returns `202 { jobId }`; `GET /api/projects/create-jobs/:jobId` returns job state. `existing`/`new` keep their `200 { key, name, path }` contract.
- **FR-5.** `pan project clone <url> [--parent <dir>] [--name <name>] [--issue-prefix <P>] [--dry-run]` and `pan project add <path> [--dry-run]` are thin wrappers over the core. `--dry-run` prints the resolved intent as JSON and writes nothing.
- **FR-6.** `/projects/new` shows mode tabs, fields per mode, a resolved status strip, inline findings, a disabled create button while findings exist or the intent is stale, clone progress, and a one-line project-versus-workspace guide.
- **FR-7.** Every affordance of `NewProjectModal` has a home on the page, proven by a no-loss audit test, before the modal is deleted.
- **FR-8.** Registration derives `github_repo` or `gitlab_repo`, `tracker`, `workspace.default_branch`, and proposes `issue_prefix` per D-3; the `main` workspace row exists after every successful create.
- **FR-9.** Docs and the `pan-new-project` skill describe the new flow.

### Non-functional

- **NFR-1.** No `execSync` anywhere reachable from the dashboard server. All git calls use `execFile`/`spawn` with `promisify` or event handlers. (Rule: no-execsync-server.)
- **NFR-2.** Resolve never blocks on the network except the memoized remote probe (D-2), and never for longer than 15 s.
- **NFR-3.** All state access goes through the existing doors: `projects.yaml` via `registerProjectSync`/`registerProjectFromPath`; the `workspaces`/`projects` tables via `src/lib/workspaces/resolver.ts` and `writer.ts`. No direct SQL. (Rule: single-source-of-truth; `scripts/guard-workspace-doors.sh` enforces.)
- **NFR-4.** Tests that exercise polling or timeouts use `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`. (Rule: fake-timers-for-retry-tests.)
- **NFR-5.** The page follows `pan-style-guide` (no pill badges, no decorative color, monospace status strip like `/workspaces/new`).
- **NFR-6.** `npm run typecheck`, `npm run lint`, `npm test` pass. Note that typecheck excludes `*.test.ts`; run `npx vitest run <file>` on every new test file.

**7.2 `repo-url.ts`.**

```ts
export interface ParsedRepoUrl {
  cloneUrl: string;                 // normalized, always ends in .git for github/gitlab https
  provider: 'github' | 'gitlab' | null;
  slug: string | null;              // owner/repo or group/.../repo
  folderName: string;               // last path segment minus .git
}
export function parseRepoUrl(raw: string): ParsedRepoUrl | null;
```

Rules (D-12). Return `null` when no form matches. Implement with three regexes in this order:
1. Shorthand `^([A-Za-z0-9_.-]+)\/([A-Za-z0-9_.-]+)$` → github, `cloneUrl = https://github.com/${o}/${r}.git`.
2. SCP-like `^(?:ssh:\/\/)?git@([^:/]+)[:/](.+?)(?:\.git)?\/?$` → host decides provider (`github.com` → github, `gitlab.com` → gitlab, else null); `cloneUrl` is the raw string with `/` trailing stripped.
3. HTTPS `^https?:\/\/([^/]+)\/(.+?)(?:\.git)?\/?$` → same host rule; for github/gitlab append `.git` to the normalized URL.

`slug` is the captured path with `.git` removed; `folderName` is its last segment. Tests: one `it` per form above plus `it('returns null for a bare word')` and `it('strips trailing slash and .git')`.

**7.3 `resolveProjectCreateIntent`.** Skeleton (fill in, keep this order so fail-fast semantics match `resolveWorkspaceCreateIntent`):

```ts
export async function resolveProjectCreateIntent(input: ProjectCreateInput): Promise<ResolvedProjectIntent> {
  const findings: ProjectIntentFinding[] = [];
  const intent: ResolvedProjectIntent = { mode: input.mode, key: null, name: '', path: null, cloneUrl: null,
    provider: null, repoSlug: null, defaultBranch: null, remoteChecked: false, isGitRepository: false,
    proposedIssuePrefix: null, wouldClone: false, wouldGitInit: false, willCreateMainWorkspace: false, findings };
  const home = input.homeDir ?? homedir();
  const parentDir = resolve(input.parentDir ?? join(home, 'Projects'));

  // 1. Mode-specific source validation (no fs, no git yet).
  if (input.mode === 'clone') {
    const parsed = input.url ? parseRepoUrl(input.url.trim()) : null;
    if (!parsed) { findings.push({ field: 'url', code: 'url-invalid', message: 'Enter a GitHub or GitLab URL, or owner/repo.', detail: input.url }); return intent; }
    intent.cloneUrl = parsed.cloneUrl; intent.provider = parsed.provider; intent.repoSlug = parsed.slug;
    intent.name = input.name?.trim() || parsed.folderName;
    intent.wouldClone = true; intent.isGitRepository = true;
  } else if (input.mode === 'existing') {
    if (!input.path || !isAbsolute(input.path)) { findings.push({ field: 'path', code: 'path-not-a-directory', message: 'Choose an existing directory.', detail: input.path }); return intent; }
    intent.name = input.name?.trim() || basename(input.path);
  } else {
    intent.name = input.name?.trim() ?? '';
    intent.wouldGitInit = true; intent.isGitRepository = true;
  }

  // 2. Key.
  const key = intent.name.toLowerCase().replace(/[^a-z0-9-]/g, '-');
  if (!key.replace(/-/g, '')) { findings.push({ field: 'name', code: 'name-invalid', message: 'Name must contain a letter or number.', detail: intent.name }); return intent; }
  intent.key = key;
  if (getProjectSync(key)) findings.push(   // projects.yaml is mtime-cached; listProjectsAsync() is the async sibling used by workspaces/create.ts — prefer it for the prefix scan in step 5
    { field: 'name', code: 'project-exists', message: `Project '${key}' is already registered.`, detail: key });

  // 3. Path + home boundary + fs checks (async only).
  // clone/new: path = join(parentDir, mode === 'clone' ? folderName-derived key : key); target-exists when non-empty.
  // existing: path = realpath(input.path); path-not-a-directory when stat fails.
  // homeBoundary: path-outside-home when !isWithinHome(path, home) — use nearest existing ancestor realpath, as projects.ts:1010-1030 does today.

  // 4. Detection.
  // existing && .git present: origin slug via `git remote get-url origin`, default branch per D-15. parseRepoUrl(originUrl) fills provider/repoSlug.
  // clone: probeRemote(cloneUrl, { refresh: input.refreshRemote }) → { defaultBranch } | { error }. On error push remote-unreachable. Set remoteChecked = true either way.

  // 5. Issue prefix (D-3). proposed = (input.issuePrefix ?? key.toUpperCase().replace(/-/g, '').slice(0, 10)). Validate /^[A-Z][A-Z0-9]{0,9}$/ → issue-prefix-invalid. Taken check across listProjectsSync(): issue_prefix or issue_prefixes includes it → issue-prefix-taken.

  // 6. willCreateMainWorkspace = findings.length === 0 && getMainWorkspace(key) === null.
  return intent;
}
```

`probeRemote` lives in the same file:

```ts
const REMOTE_PROBE_TTL_MS = 60_000;
const REMOTE_PROBE_TIMEOUT_MS = 15_000;
const remoteProbeMemo = new Map<string, { at: number; result: RemoteProbeResult }>();

export function promptGuardGitEnv(base: NodeJS.ProcessEnv = process.env): NodeJS.ProcessEnv {
  return { ...base, GIT_TERMINAL_PROMPT: '0', GIT_ASKPASS: 'true', SSH_ASKPASS: 'true', GCM_INTERACTIVE: 'never',
    GIT_SSH_COMMAND: base.GIT_SSH_COMMAND ?? 'ssh -o BatchMode=yes' };
}

async function probeRemote(cloneUrl: string, opts: { refresh?: boolean }): Promise<RemoteProbeResult> {
  const hit = remoteProbeMemo.get(cloneUrl);
  if (!opts.refresh && hit && Date.now() - hit.at < REMOTE_PROBE_TTL_MS) return hit.result;
  let result: RemoteProbeResult;
  try {
    const { stdout } = await execFileAsync('git', ['ls-remote', '--symref', '--', cloneUrl, 'HEAD'],
      { env: promptGuardGitEnv(), timeout: REMOTE_PROBE_TIMEOUT_MS, killSignal: 'SIGKILL' });
    const match = stdout.match(/^ref:\s+refs\/heads\/(\S+)\s+HEAD$/m);
    result = { ok: true, defaultBranch: match?.[1] ?? null };
  } catch (err) {
    result = { ok: false, error: err instanceof Error ? err.message : String(err) };
  }
  remoteProbeMemo.set(cloneUrl, { at: Date.now(), result });
  return result;
}
```

**7.4 `performProjectCreate`.**

```ts
export async function performProjectCreate(intent: ResolvedProjectIntent, hooks: ProjectCreateHooks = {}): Promise<ProjectCreateResult> {
  if (intent.findings.length > 0) throw new Error(intent.findings[0].message);
  if (!intent.key || !intent.path) throw new Error('Project intent did not resolve to a key and path.');

  let createdTarget = false;
  if (intent.wouldClone || intent.wouldGitInit) {
    await mkdir(dirname(intent.path), { recursive: true });
    try { await mkdir(intent.path); createdTarget = true; }        // non-recursive claim (D-5)
    catch (err) { if ((err as NodeJS.ErrnoException).code !== 'EEXIST') throw err; }
  }
  try {
    if (intent.wouldClone) await runClone(intent.cloneUrl!, intent.path, hooks);
    else if (intent.wouldGitInit) await execFileAsync('git', ['init', '--quiet'], { cwd: intent.path });
  } catch (err) {
    if (createdTarget) await rm(intent.path, { recursive: true, force: true });
    throw err;
  }

  hooks.onProgress?.({ phase: 'registering', percent: null });
  const extras = buildExtras(intent);   // { issue_prefix?, github_repo? | gitlab_repo?, tracker?, workspace?: { default_branch } } — omit undefined keys
  const registered = await registerProjectFromPath({ path: intent.path, name: intent.name, extras });
  await excludeWorkspacesDir(intent.path, extras.workspace?.workspaces_dir ?? 'workspaces');   // D-8

  const wsIntent = await resolveWorkspaceCreateIntent({ kind: 'main', projectKey: registered.key });
  if (wsIntent.findings.length > 0) throw new Error(wsIntent.findings[0].message);
  const existing = getMainWorkspace(registered.key);
  const mainWorkspaceId = existing ? existing.id : (await performWorkspaceCreate(wsIntent)).id;
  hooks.onProgress?.({ phase: 'done', percent: 100 });
  return { key: registered.key, name: registered.config.name, path: registered.config.path, mainWorkspaceId };
}
```

`runClone` uses `spawn('git', ['clone', '--progress', '--', url, path], { env: promptGuardGitEnv(), stdio: ['ignore', 'ignore', 'pipe'], signal: hooks.signal })`. It parses stderr chunks split on `/[\r\n]+/` with `/^([\w ]+):\s+(\d+)%/` and calls `hooks.onProgress({ phase: match[1].trim(), percent: Number(match[2]) })`. Resolve on exit code 0; reject with the last 20 stderr lines otherwise. Never use `execFile` here: clone stderr exceeds the 1 MB `maxBuffer`.

`excludeWorkspacesDir(root, dir)`: if `stat(join(root, '.git'))` is a directory, read `join(root, '.git', 'info', 'exclude')` (missing file = empty), and append `${dir}/\n` when no existing line equals `${dir}/` or `${dir}`. `mkdir -p` the `info` directory first.

`buildExtras`: `tracker: 'github'` and `github_repo: repoSlug` when `provider === 'github'`; `tracker: 'gitlab'` and `gitlab_repo` when `gitlab`; `issue_prefix: proposedIssuePrefix` when non-null; `workspace: { default_branch }` when `defaultBranch` non-null. Do not write `workspaces_dir` (the default applies).
