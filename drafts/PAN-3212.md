# PAN-3212 — Residual hardening: lock the blocking-menu delivery guard with tests, extend it to the keyed submit path

## Glossary

- **Blocking choice menu** — a numbered modal a harness draws over the pane
  (Claude Code's session-resume gate, permission prompts, plan approval). While
  it is up, the composer accepts no pasted text and a bare Enter confirms the
  highlighted row.
- **Resume gate** — Claude Code's `Resume from summary / Resume full session
  as-is` menu shown when resuming an old session. Its highlighted default is
  "Resume from summary", which compacts the session.
- **`sendKeys`** — the shared tmux paste+Enter delivery fallback in
  `src/lib/tmux.ts` (Effect variant, line 1163). Used by `deliverAgentMessage`'s
  tmux tier and ~15 call sites.
- **Keyed delivery / `completeKeyedSubmit`** — the dedup-keyed tmux delivery
  path in `src/lib/tmux-dedup.ts` that submits via a single server-side
  `if-shell` transaction (`send-keys C-m` + poison/terminal markers).
- **`paneHasBlockingChoiceMenu()`** — guard in `src/lib/pane-choice-menu.ts:270`
  that parses pane text with `mode: 'guard'` and returns true when a blocking
  numbered menu is on screen.
- **`MessageDeliveryFailed`** — error class (`src/lib/tmux.ts:682`) carrying the
  session name and pane snapshot; the delivery cascade already treats it as a
  first-class failure shape.

## Problem

The merged fix changed failure semantics in two places without branch-level
tests, and left one sibling path unguarded:

1. The `sendKeys` guard branch (unverified paste + blocking menu → throw, no
   Enter) has no test. A regression there re-opens the exact incident: a stray
   Enter answering the resume gate's "Resume from summary" and discarding the
   operator's 146.9k-token session.
2. The `handleConversationResume` gate-skip branch has no test. It is embedded
   in a large function whose same-module dependencies
   (`spawnConversationSession`, `waitForConversationRuntimeReady`) make direct
   unit testing brittle, so the branch's behavior is unpinned.
3. `completeKeyedSubmit` (`src/lib/tmux-dedup.ts:401`) sends its Enter inside
   a tmux `if-shell` transaction (`:434-439`) guarded by marker and pane-identity
   conditions but NOT by a menu check. A blocking menu that swallowed the keyed
   paste would receive that Enter — the same auto-approve-the-modal defect the
   issue's root-cause section generalizes to ("any of them landing while a
   pane sits on a permission prompt, plan approval, or resume gate would
   confirm that modal's default").

## Proposal

Three independent items:

1. **Test the `sendKeys` guard branch** using the established
   `child_process.execFile`-mock + fake-timers pattern from
   `tests/lib/tmux-send-escape.test.ts`.
2. **Extract the resume gate-skip into a small exported seam** in a new module
   `src/lib/overdeck/resume-contract-delivery.ts` and unit-test it with mocked
   `capturePaneText` / `deliverAgentMessage`. Extraction also shrinks the
   allowlisted god file `conversation-runtime.ts` instead of growing it.
3. **Extend the guard to `completeKeyedSubmit`**: capture the pane before the
   `if-shell` submit (through a new `KeyedTmuxDeps.readPaneText` test seam) and
   throw `MessageDeliveryFailed` when a blocking menu is present — before any
   Enter is sent, so the pending marker survives for a later retry.

## Requirements

- **FR-1** — A unit test proves: when paste verification fails AND the pane
  shows a blocking numbered menu, `sendKeys` rejects with
  `MessageDeliveryFailed` and no `send-keys -t <session> C-m` tmux call is
  issued.
- **FR-2** — The resume-contract gate skip lives behind an exported, unit-tested
  seam: gated pane → delivery skipped; clear pane → contract delivered;
  capture failure → delivery still attempted; delivery failure → contained, no
  throw to the resume flow.
- **FR-3** — `completeKeyedSubmit` captures the pane before its submit
  transaction and throws `MessageDeliveryFailed` without sending Enter when
  `paneHasBlockingChoiceMenu` is true; the pending marker is preserved.
- **NFR-1** — Fail-open behavior is preserved where no menu is present:
  unverified paste without a menu still sends Enter (`sendKeys`), and a clear
  pane in the keyed path still submits normally.
- **NFR-2** — All new tests that drive retry/settle delays use
  `vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync()`; no real
  `setTimeout` waits.
- **NFR-3** — The keyed path's marker/poison/terminal transaction semantics
  (cycles 10-13 documented above `completeKeyedSubmit`) are unchanged; the
  guard only adds a client-side abort BEFORE the transaction begins.

```ts
// src/lib/overdeck/resume-contract-delivery.ts
import { deliverAgentMessage } from '../agents.js';
import { paneHasBlockingChoiceMenu } from '../pane-choice-menu.js';
import { capturePaneText } from '../tmux.js';

export type ResumeContractOutcome = 'delivered' | 'skipped-gated' | 'failed';

export async function deliverResumeContractUnlessGated(
  tmuxSession: string,
  contract: string,
  caller: string,
  method: 'auto' | 'channels' | 'tmux',
): Promise<ResumeContractOutcome> {
  const pane = await capturePaneText(tmuxSession, 90).catch(() => '');
  if (pane && paneHasBlockingChoiceMenu(pane)) {
    console.log(`[conversations] resume contract skipped for ${tmuxSession} — the harness is showing a blocking choice menu; the operator answers it`);
    return 'skipped-gated';
  }
  try {
    await deliverAgentMessage(tmuxSession, contract, caller, method);
    return 'delivered';
  } catch (err: unknown) {
    console.error(`[conversations] resume contract delivery failed for ${tmuxSession}:`, err instanceof Error ? err.message : String(err));
    return 'failed';
  }
}
```

## Decisions made in this document

- **Residual-only scope.** The issue's three-bullet fix is fully merged
  (`fac085ef4e`); re-implementing it would be wasted work. Recorded as
  autoDecision 1 in the xBRIEF.
- **Extend the guard to the keyed path.** The issue's own blast-radius
  paragraph names every modal-answering delivery path; `completeKeyedSubmit`'s
  `if-shell` Enter was the only one left without a menu check. Recorded as
  autoDecision 2.
- **Extract, don't test in place.** `handleConversationResume` calls
  same-module `spawnConversationSession` / `waitForConversationRuntimeReady`,
  which `vi.mock` cannot intercept without replacing the function under test.
  Extraction into `resume-contract-delivery.ts` gives a clean seam and shrinks
  an allowlisted god file. Recorded as autoDecision 3.
