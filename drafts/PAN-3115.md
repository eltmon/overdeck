# PAN-3115 PRD — Pipeline membership read door: typed per-project unavailability instead of 503

## Glossary

- **Read door** — `GET /api/pipeline/membership?project=<key>`, the single canonical HTTP read path for pipeline membership. `roles/flywheel.md` Mission #3 mandates calling it once per project key from `GET /api/registered-projects`.
- **Gather** — `gatherProjectLensSignals()` in `src/lib/pipeline-membership-gather.ts`; collects the durable lens signals (L1 PRs, L2 branches, L3 issue state, L4 labels, L6 specs) for one project. Throws on any lens failure today.
- **Snapshot** — the server-side per-project cache of the last successful gather (`membershipSnapshots` map in `src/dashboard/server/services/pipeline-membership.ts`). GET requests are snapshot-only readers; they never gather inside a GET (PAN-2972).
- **Typed unavailable** — a determined answer from the door meaning "cannot tell for this project", carrying a machine-readable `reason` so a caller can distinguish *no pipeline work* from *could not tell*.
- **MembershipUnavailableReason** — the closed union of typed reasons introduced by this change.
- **Polyrepo** — a project whose `workspace.repos[]` lists multiple member checkouts (e.g. auricle: `frontend`, `backend`, `infra`).

## Problem

Verified on this machine (2026-07-26), matching the issue table: 6 of 12 registered projects make the door return 503.

| Project | Verified root cause |
| --- | --- |
| auricle | `workspace.repos` lists `infra`, but `/home/eltmon/Projects/auricle/infra` is not a git repository (`git rev-parse --show-toplevel` → fatal). `frontend` and `backend` are repos on `main`. The gather's `git rev-list --first-parent main` in `infra` throws and fails the whole project. |
| pan-tts | The checkout's only branch is `master` (`git symbolic-ref HEAD` → `refs/heads/master`) but config says `default_branch: main`, so `git rev-list --first-parent main` → "unknown revision". |
| papers-please, puzzdom | `projects.yaml` entries have only `name` + `path` — no `issue_prefix` — so `gatherProjectLensSignals` throws at `src/lib/pipeline-membership-gather.ts:400`. |
| lexerra, krux | `github_repo` is set but the GitHub App is not installed on those repos; the REST issue listing 404s. |

Mechanism: a gather failure leaves the snapshot with `lastError` set and no value; `readPipelineMembershipSnapshotsForProjects` (`src/dashboard/server/services/pipeline-membership.ts:103-118`) then returns an `error`, and the route (`src/dashboard/server/routes/pipeline-membership.ts:37-42`) turns that into a bare 503 with a prose message. The failure *type* is discarded at the snapshot boundary (`MembershipSnapshot.lastError` is a plain string, services/pipeline-membership.ts:63-69), so no caller can distinguish "no pipeline work" from "could not tell" — and per the two-door doctrine, an orchestrator that cannot tell must not silently under-report or fall back to ad-hoc derivation.

Batch consumers already degrade per project and need no change: `src/cli/commands/pending.ts:34-46` and `src/lib/reconstruct/enumerate-in-flight.ts:11-24` skip failed projects with a log line. The per-project HTTP door is the blind surface.

## Requirements

- **FR-1** — `GET /api/pipeline/membership` never answers a *determined* gather failure with 503. It returns HTTP 200 with `{ "status": "unavailable", "reason": <MembershipUnavailableReason>, "message": <string>, "projectKey": <key> }`.
- **FR-2** — The reason taxonomy is `missing_issue_prefix | repo_unavailable | default_branch_unresolved | forge_unavailable | tracker_unconfigured | gather_failed`, defined once in `@overdeck/contracts` and used by the gather (throw sites), the service (propagation), the route (response body), and the frontend (parse).
- **FR-3** — The gather resolves each repository's effective default branch from repo reality (configured branch if it verifies → `origin/HEAD` symref → current checkout `HEAD` → probe `main`/`master` → typed `default_branch_unresolved`), so `pan-tts` (master-only) gathers successfully with no config edit.
- **FR-4** — A project path or polyrepo member path that is not a git repository fails the project closed with `repo_unavailable`, and the message names the offending path. No partial lens set is ever gathered (a partial gather can silently misclassify an issue as `clean_terminal`).
- **FR-5** — Forge-lens failures (tracker list, GitHub issue/PR/state/merged-head calls) rethrow as `forge_unavailable` with the original message preserved; the reason is assigned by *lens boundary*, never by parsing error text.
- **FR-6** — `GET /api/registered-projects` entries gain an additive `membershipQueryable: boolean` (`true` iff the project has an `issue_prefix`).
- **FR-7** — The frontend membership probe (`projectsData.ts`) treats a 200 `{status:"unavailable"}` body as failure — throwing so `ProjectMembershipBoundary` keeps rendering the message plus the Retry button exactly as it does for 503 today.
- **NFR-1** — The success response shape is unchanged: HTTP 200 with the bare `PipelineMembership[]` array. No existing consumer of a healthy project sees any difference.
- **NFR-2** — The transient cold-boot state (no snapshot value and no recorded error) keeps the PAN-2972 behavior: fast 503 `Pipeline membership snapshot is loading` + Retry. It is a seconds-long transient, not a determined answer.
- **NFR-3** — Operator machine config (`~/.overdeck/projects.yaml`) is not edited by this change: the phantom auricle `infra` entry, the pan-tts `default_branch: main`, and the missing papers-please/puzzdom prefixes are operator decisions. The door's job is to report them actionably (and, for the branch, to stop depending on the config value).
- **NFR-4** — No new direct store access; all changes stay inside the existing read/write doors.

## Decisions (made in this doc — auto mode, no operator Q&A)

- **D1 — 200 + typed body, not a smarter 5xx.** The issue mandates the door never 503 a determined failure; a 200 with `status:"unavailable"` keeps `response.ok` honest for orchestrators combining per-project results and carries the reason in one parseable place.
- **D2 — Success shape stays the bare array.** A uniform envelope (`{status:"ok", memberships:[...]}`) would break every existing array consumer (flywheel doc parsing, the resource-strip Playwright mock, the frontend probe's `response.ok` shortcut) for zero functional gain. The contract is: array → rows; object with `status:"unavailable"` → typed blind spot.
- **D3 — Cold-boot "loading" stays 503.** It is transient and self-heals on the first background refresh; giving it its own 200 status would force a third frontend state for a seconds-long window and dilute the meaning of "unavailable" (which is a *determined* answer an operator must act on).
- **D4 — Fail closed per project on a bad repo path.** Skipping auricle's phantom `infra` repo and gathering from the other two would let an issue with only-infra branches read as `clean_terminal` — a silently wrong authoritative answer, worse than a loud typed blind spot.
- **D5 — Resolve the default branch from the repo, not the config.** Fixes pan-tts and every future master-based project permanently; config `default_branch` remains the first preference when it verifies.
- **D6 — No invented prefixes for papers-please/puzzdom.** Their tracker identity is an operator registration decision; the door reports `missing_issue_prefix` and `registered-projects` exposes `membershipQueryable: false`.
- **D7 — Reasons assigned by lens boundary.** Which lens failed determines the reason; error-message string matching against `gh`/HTTP output is brittle and banned.

### WI-1 — Typed unavailable contract (`typed-unavailable-contract`)

Add to `packages/contracts/src/types.ts`:

```ts
export const MEMBERSHIP_UNAVAILABLE_REASONS = [
  'missing_issue_prefix', 'repo_unavailable', 'default_branch_unresolved',
  'forge_unavailable', 'tracker_unconfigured', 'gather_failed',
] as const;
export type MembershipUnavailableReason = (typeof MEMBERSHIP_UNAVAILABLE_REASONS)[number];
export interface PipelineMembershipUnavailableBody {
  status: 'unavailable';
  reason: MembershipUnavailableReason;
  message: string;
  projectKey: string;
}
```

```ts
export class PipelineMembershipUnavailableError extends Error {
  constructor(readonly reason: MembershipUnavailableReason, message: string) {
    super(message);
    this.name = 'PipelineMembershipUnavailableError';
  }
}
```
