# PAN-3754 — Memory governor: hysteresis hold wedges admissions on a healthy host; messages misattribute the trigger

**Issue:** https://github.com/eltmon/overdeck/issues/3754
**Status:** draft PRD
**Author:** conversation conv-20260816-9367, 2026-08-16

## Glossary

- **Governor** — `src/lib/cloister/memory-governor.ts`. Modes: `admitting | holding | shedding`,
  mapped to bands `ok | soft | hard` (`bandForGovernorMode`, lines 161–165). Consumed by deacon
  gates (auto-resume, dispatch) via `assessMemoryPressure()` (line 174).
- **Reserves** — config-driven GiB thresholds (`readGovernorReserves`, lines 86–93):
  `resources.governorSoftReserveGb`, `governorHardReserveGb`, `governorRecoveryReserveGb`;
  plus `governorWatchReserveGb` (line 96) for the activity-feed warn (PAN-3550).
- **Hysteresis** — `nextGovernorMode` (lines 116–127): ≥recovery ⇒ admitting; <hard ⇒ shedding;
  an admitting governor holds when it crosses below soft; **a holding governor re-admits ONLY at
  ≥recovery**.
- **Runway** — swap/PSI overlay (`nextGovernorModeWithRunway`, lines 129–159): full-swap alone
  does not hold when PSI is readable and below `governorPsiFullShedAvg10` (PAN-3485 follow-up
  correction, comment at lines 149–156); PSI unavailable + swap low ⇒ conservative hold.
- **Patrol** — `src/lib/cloister/memory-pressure-patrol.ts`: turns verdicts into operator
  messages (soft message at lines 260–262; watch at 243–244) and a details block
  (`buildMemoryDetails`, lines 48–58) that currently hardcodes
  `Swap free: unavailable | PSI full avg10: unavailable` (line 58 — a WI placeholder).

## Problem (verified 2026-08-16, live host)

Host state: 62 GiB total, ~17 GiB MemAvailable, memory PSI full avg10 = 0.00, swap 8/8 GiB
resident (idle residency; PSI-clean). Operator-visible Awareness messages claimed:
"stopped admitting work — 11.7 GiB available is under the 9.4 GiB soft reserve" and
"Memory critical — 12.5 GiB available is under the 5.0 GiB hard reserve … kernel may start
killing processes". Both are arithmetically false as printed. Meanwhile admissions were held:
review/test dispatches and resumes deferred, "agent activity stalled" warning shown.

Two defects:

1. **Hysteresis wedge.** One transient dip below soft (9.4 GiB) moves the governor to `holding`;
   re-admission requires MemAvailable ≥ recovery (15.7 GiB). On this host the desktop workload
   (Chrome, two JVMs, esbuild, Vite) keeps MemAvailable oscillating ~12–17 GiB, so the governor
   can hold for hours/days while PSI stays 0.00 — the same "wedged pipeline on a healthy host"
   failure the PAN-3485 swap correction fixed for the swap axis, now on the memory axis.
2. **Message misattribution.** The patrol templates "X available is under the Y reserve" from
   the CURRENT reading and the band, regardless of which trigger set the mode (historical dip,
   hysteresis, runway). The operator gets self-refuting numbers and cannot act (violates the
   operator-messages-stand-alone rule). The details block prints hardcoded "unavailable" for
   swap/PSI — hiding exactly the data that would exonerate the host.

## Requirements

- **FR-1** The governor records WHY it entered its current non-admitting mode: trigger kind
  (`soft-dip | hard | swap-psi | psi-unavailable`), the reading and threshold at trigger time,
  and the timestamp. The verdict exposes this.
- **FR-2** PSI-informed early re-admit: a `holding` governor whose PSI full avg10 has been 0.00
  (or < an early-readmit threshold) continuously for a configured window re-admits once
  MemAvailable ≥ soft (not recovery). A dip with real pressure (PSI elevated) keeps the
  existing recovery-only behavior. No oscillation: early re-admit re-arms only after the window
  elapses again.
- **FR-3** Patrol messages print the stored trigger AND the current reading, self-consistently:
  e.g. "holding since 14:22 (dipped to 8.9 GiB, soft reserve 9.4 GiB); now 12.5 GiB available —
  re-admits at 15.7 GiB, or at 9.4 GiB once PSI stays 0 for 10 min." Every band's message must
  be arithmetically consistent with the numbers it prints.
- **FR-4** `buildMemoryDetails` prints real swap free/total and PSI values from the verdict
  (delete the hardcoded placeholder).
- **NFR-1** No behavior change for genuine pressure: <hard sheds; PSI ≥ shed threshold with low
  swap sheds; PSI-unavailable conservative hold stands.
