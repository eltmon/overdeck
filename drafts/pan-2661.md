## Glossary

- **Registry** — `ISSUE_ACTIONS` in `src/dashboard/frontend/src/lib/issueActions.ts:218-262`: 44 entries `{ key, label, panVerb, endpoint, enabledWhen, phasePrimary, kind, group }`. Kinds: `safe | dialog | destructive`. Groups: `planning | work | review | agent | workspace | artifacts | navigation | danger | preserved`.
- **Gating predicates** — the `enabledWhen` functions at `issueActions.ts:137-195` (`canPlan`, `canRestartReview`, …). Untouched by this issue.
- **Phase** — `PipelinePhase`, 11 values, derived by `deriveIssueActionPhase()` (same file); `PHASE_PRIMARY_KEYS` maps each phase to its primary action keys.
- **Hook** — `useIssueActions(issueId)` (`src/dashboard/frontend/src/components/IssueActionMenu/useIssueActions.ts` — NOT under lib/): returns `{primary, secondary, overflow}` (ordering `:377-388`; note primary entries are NOT gate-filtered there — the grouped menu filters them, a deliberate presentation choice), disabled-reason strings (`:142-195`), destructive confirm messages (`:215-241`), dialog key declarations (`:197-205`; actual routing `:357-359` + `IssueActionMenu.tsx:206-261`).
- **Flat menu** — `FeatureContextMenu` (`src/dashboard/frontend/src/components/CommandDeck/ProjectTree/FeatureItem.tsx:702-760`): flattens `[...primary, ...secondary, ...overflow]` (`:711-714`) into one list under a single "Issue actions" label, then appends three hardcoded extras — Open State Dir, View JSONL, Deep Wipe (`:734-755`).
- **Cockpit grouping** — `GROUP_ORDER`/`GROUP_LABELS` in `src/dashboard/frontend/src/components/Stage/cockpit/IssueMissionControl.tsx:86-108`, consumed only by the cockpit's `IssueActionMegaMenu` (`:174`, mounted `:770`).
- **Danger disclosure** — the collapsed `▸ Danger (N available)` row that expands to the danger-group items (mockup behavior).

## Decisions

- **D-1 — Grouping moves INTO the registry.** `GROUP_ORDER: IssueActionGroup[]` and `GROUP_LABELS` are exported from `issueActions.ts`; `IssueMissionControl.tsx` deletes its local copies and imports them. Order (BINDING): planning, work, review, agent, workspace, artifacts, navigation, danger. (`preserved` never renders.)
- **D-2 — `description` becomes a required registry field.** One plain sentence per action, no pipeline jargon; the copy for all **43 retained** actions is in the mockup spec appendix and is BINDING (`reviewTest` is migrated per D-6 and needs none). Tooltip precedence: enabled item → description; disabled item → disabled reason (description only inline via Explain); the cockpit panel keeps its current disabled-reason titles and gains description titles ONLY on enabled buttons — a deliberate, tested presentation change. Rendered as: `title` tooltip on every menu item and panel button, and inline under labels when Explain is on (D-5).
- **D-3a — Phase-primary items ARE repeated** in their home group (shortcut on top, complete groups below — newcomers get predictable groups, experts get the shortcut). The parity test asserts multiplicity accordingly: primary keys appear exactly twice, all others exactly once. The menu gets `max-height: 70vh; overflow-y: auto` on its content (the current `ContextMenuContent` has none — `shared/ContextMenu.tsx:8-16`).
- **D-3 — Menu structure (BINDING, from the mockup):** header label + phase chip + counts line ("N available now · M gated") → **For this phase** (from `getPhasePrimaryActions` × `deriveIssueActionPhase`, enabled items only; section hidden when none) → registry groups in `GROUP_ORDER` (skip `danger`) with disabled items visible-dimmed carrying their reason tooltip → **This session** (surface extras) → **Danger** collapsed disclosure, last. Empty groups hidden. `kind: 'destructive'` items outside the danger group (purgeReview, resetToPlanned, resetSession, restartAgent) stay in their group, destructive-styled, confirm-gated.
- **D-4 — Duplicate Deep Wipe is deleted, and the surviving flow is made whole.** The hardcoded item at `FeatureItem.tsx:750-755` (window.confirm; handler sends `{deleteWorkspace:true}` — `CommandDeck/index.tsx:959-965`) is removed. The registry `wipe` becomes the single entry — BUT today its invocation sends `{}` (no `bodyForAction` case, `useIssueActions.ts:118-139,303-310`). This issue adds `bodyForAction('wipe') → {deleteWorkspace:true}` and keeps the registry's typed confirmation. This is a DELIBERATE behavior unification (typed confirm replaces window.confirm), not a silent one — it is called out in D-7 and tested. Open State Dir / View JSONL move under "This session" (surface-local props here; registry promotion is PAN-1610).
- **D-5 — Explain toggle.** A footer row "Explain actions" toggles inline descriptions + `pan <verb>` chips; persisted in `localStorage` key `overdeck.issueActions.explain`. Off by default.
- **D-6 — `reviewTest` is retired via an explicit migration table, not a delete.** Correction from review: it DOES render today (group `preserved` is in the cockpit's `GROUP_ORDER`, `IssueMissionControl.tsx:98-108`) and has live consumers with a WIDER gate than `requestReview` (`hasWorkspace` vs `canRequestReview`): `spotlight.ts:47-53`, `ReviewVerificationCard.tsx:102-119`, plus tests (`issueActions.test.ts:153`, `issueActions.no-actions-lost.test.ts:18-21,61-64`, `action-parity.test.ts:7-9`, `IssueDrawer.test.tsx:764,787`). Migration: (1) `ReviewVerificationCard` keeps its recovery affordance by switching to `restartReview`/`recoverReview` as gated (product call recorded here: its purpose is re-running a failed/stuck review — `restartReview` matches); (2) `spotlight.ts` switches to `requestReview` with its gate; (3) each named test updated in the same commit; (4) only then is the entry deleted and `preserved` dropped from the group union. Every step is one commit-reviewable table row in the implementation.
- **D-7 — Behavior-change ledger (exactly two, both deliberate).** (1) Deep-wipe unification per D-4 (typed confirm + explicit `{deleteWorkspace:true}` body). (2) `reviewTest` consumer migration per D-6. EVERYTHING else — predicates, confirm flows, dialog routing, `IssueActionDialogHost` mounting (`FeatureItem.tsx:757`) — is untouched. An implementing agent finding a third behavior change has left spec.

## Requirements

- **FR-1** Registry exports `GROUP_ORDER`, `GROUP_LABELS`, and every entry carries `description` (D-2); cockpit imports them (local copies deleted).
- **FR-2** A shared `GroupedIssueActionMenu` renders D-3's structure from the registry + hook state; `FeatureContextMenu` uses it in place of the flat dump.
- **FR-3** Danger renders as a collapsed disclosure, last, keyboard-operable (Enter/Space), with an available-count in its header.
- **FR-4** Hardcoded Deep Wipe deleted; Open State Dir / View JSONL under "This session" (D-4).
- **FR-5** Disabled items remain visible, dimmed, with today's reason strings discoverable — NOTE: Radix disabled items suppress pointer events (`shared/ContextMenu.tsx:20-57`), so reasons render via a non-disabled wrapper span carrying the tooltip (and `aria-describedby` for keyboard/screen-reader users), not via `title` on the disabled item. Enabled/disabled semantics byte-identical to `useIssueActions`.
- **FR-6** `reviewTest` retired per D-6.
- **FR-7** Parity test: the rendered menu's item set ≡ registry (minus `preserved`, plus session extras), group order ≡ `GROUP_ORDER`, destructive items confirm-gated, danger disclosure last, exactly one wipe entry.
- **FR-8** Explain toggle per D-5.
- **NFR-1** Style guide: DM Sans, `font-medium`, semantic tokens, destructive = `--destructive` only; group labels uppercase 10px muted (match the cockpit panel's existing label style).
- **NFR-2** Keyboard: arrow navigation across items, Enter runs, disclosure toggles with Enter/Space; visible focus states.
