# PAN-3410 — Dashboard style guide v2: Geist type system, display scale, chips, soft cards, page-not-modal doctrine

**Issue:** https://github.com/eltmon/overdeck/issues/3410
**Relates to:** PAN-3411 (New Workspace page — first consumer of the new patterns)
**Status:** draft

---

## Glossary

- **Style guide law** — `design/style-guide/STYLE-GUIDE.md`, the source of truth; the bundled skill `sync-sources/dev-skills/pan-style-guide/SKILL.md` is its distilled agent-facing form. Both must change together.
- **Geist / Geist Mono** — open-source variable typefaces (SIL OFL 1.1), one `woff2` file each covering weights 300–900. Self-hosted; no CDN fetches.
- **Display scale** — new type tiers for page-level typography (`display-xl`, `display-lg`), distinct from the existing UI text sizes. Only display tiers may use weights above 600.
- **Eyebrow label** — a small uppercase Geist Mono label with wide tracking used as a category/kicker above a title (e.g. card categories) or as a quiet text-button label.
- **Chip** — a bordered, `rounded-lg` pill-adjacent button with a leading icon. **Dashed chip** = the additive/tentative variant ("add …"). **Selected chip** = strengthened border + subtle fill.
- **Soft card** — a `rounded-xl` card with muted fill (`bg-muted/50`-class token), hairline or no border, generous padding.
- **Keycap hint** — a small rounded inline element rendering a keyboard glyph (↵, ⌘L) inside buttons or beside actions.
- **Page-not-modal doctrine** — major creation/composition flows render as routed full pages; modals are reserved for confirmations and small (≤4-field) forms.

## Motivation

The current guide enforces restraint well (semantic tokens, color discipline, badge formula) but caps ALL type at `font-medium` and defines no display tier — so no surface can ever read as a *place*; everything reads as a panel. Creation flows land as cramped dialogs because the system has no vocabulary for anything bigger. This revision adds the missing vocabulary — type with real hierarchy, chips, soft cards, hero placeholders, keycap CTAs — while keeping the color restraint that makes the dashboard calm.

## Decisions

- **D-1: Typefaces.** UI sans becomes **Geist Variable**; mono becomes **Geist Mono Variable**. Self-hosted `woff2` under the frontend's static assets with `@font-face` (weight range 300–900, `font-display: swap`). DM Sans and SF Mono references are removed. License files ship beside the fonts.
- **D-2: Weight hierarchy replaces the flat cap.** Body/UI text: 400–500 (unchanged in practice). Section headings: 500–600. **Display tiers only: 600–800.** The old rule "no bold anywhere" becomes "no bold outside its tier" — enforcement wording in both guide docs must state the tier table explicitly.
- **D-3: Display scale.** `display-xl`: clamp(48px, 7vw, 72px), tracking-tight, weight 700–800, for page heroes and hero-editable titles. `display-lg`: ~40px, weight 650–700, for section heroes. Defined as Tailwind theme extensions (named text styles), not ad-hoc arbitrary values.
- **D-4: Hero-placeholder pattern.** An editable page title renders its placeholder at full display size in `text-muted-foreground/40`-class token; the input is chromeless (no border/fill) at rest.
- **D-5: Eyebrow/mono-label pattern.** Uppercase Geist Mono, `text-[11px]`-class size, `tracking-[0.12em]`-class, `text-muted-foreground`. Sanctioned uses: card categories, kicker labels, quiet text-buttons (e.g. CANCEL). This deliberately widens mono beyond identifiers; the guide's mono rule is rewritten to name both uses.
- **D-6: Chip spec.** `rounded-lg`, `h-9`–`h-10`, border `border-border`, leading icon 16px, label 400–500. Dashed variant: `border-dashed` for additive actions. Selected: `border-foreground/40` + `bg-muted` fill. Hover: fill only, never color.
- **D-7: Soft card spec.** `rounded-xl`, `bg-muted/50`-class fill, border optional hairline, padding ≥ `p-5`, title 400–500, optional eyebrow. Replaces nothing existing by force — it's the sanctioned pattern for suggestion/idea/preview cards going forward.
- **D-8: Large CTA + keycap.** New `cta` button tier: `h-12+`, `rounded-xl`, soft primary fill (`bg-primary/10 text-primary` at rest, solid on hover/focus per token), optional trailing keycap hint (`rounded-md bg-foreground/8 px-1.5` mono glyph). One per view, same as the existing single-primary rule.
- **D-9: Dot-metadata line.** Pattern: 6px status dot (semantic signal color) + Geist Mono quiet text, items separated by `·`. Sanctioned for ambient state summaries (e.g. "Memory enabled · Files shared").
- **D-10: Page-not-modal doctrine.** Creation/composition flows (new project, new workspace, and future editors) are routed pages. Modals remain for confirmations and ≤4-field quick forms. The guide gains this as a named rule; PAN-3411 executes it for workspaces; migrating NewProjectModal is a listed follow-up, not part of this issue.
- **D-11: What does NOT change.** Semantic tokens only; color restraint (one signal per row, amber/blue/emerald/red meanings); badge tint formula (radius may move `rounded-sm`→`rounded-md` for texture consistency — single deliberate change, called out in the diff); no hardcoded hex; no decorative color. State this list verbatim in both docs so agents don't over-rotate.
- **D-12: Migration is bounded, not a repaint.** This issue ships: fonts/tokens, both guide docs, and mechanical migration of font-family + weight utilities where the old cap forced `font-medium` on headings that should now use their tier. It does NOT restyle individual components to the new patterns — consumers adopt them per-feature (PAN-3411 first).
