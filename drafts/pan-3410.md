# PAN-3410 — Dashboard style guide v2: the selectable "Broadsheet" theme (Geist type system, display scale, chips, soft cards, page-not-modal doctrine)

**Issue:** https://github.com/eltmon/overdeck/issues/3410
**Relates to:** PAN-3411 (New Workspace page — first consumer of the new patterns)
**Status:** draft (rev 2, 2026-08-01 — v2 is now a selectable theme, not a cutover)

---

## Glossary

- **Style guide law** — `design/style-guide/STYLE-GUIDE.md`, the source of truth; the bundled skill `sync-sources/dev-skills/pan-style-guide/SKILL.md` is its distilled agent-facing form. Both must change together.
- **Overdeck Theme** — the dashboard's appearance setting: `ui.theme` in `~/.overdeck/config.yaml`, surfaced as a picker in Settings → Appearance. Selects one of two complete, named design languages. Per-instance (single-operator dashboard); applies live without restart.
- **Ledger** — the current design language, kept as a first-class legacy theme: DM Sans, flat `font-medium` cap, panel-first. Frozen: bug fixes only, no new patterns.
- **Broadsheet** — the new design language introduced by this issue: Geist/Geist Mono, tiered weights, display scale, chips, soft cards, hero placeholders, keycap CTAs, dot-metadata lines. The default theme.
- **Theme scope** — a `data-theme="ledger|broadsheet"` attribute on the document root. Every theme-varying token (font families, display utilities, weight-tier rules) hangs off this attribute, so a theme switch is one attribute flip — no rebuild, no restart, no fetch.
- **Geist / Geist Mono** — open-source variable typefaces (SIL OFL 1.1), one `woff2` file each covering weights 300–900. Self-hosted; no CDN fetches.
- **Display scale** — Broadsheet-only type tiers for page-level typography (`display-xl`, `display-lg`), distinct from the existing UI text sizes. Only display tiers may use weights above 600.
- **Eyebrow label** — a small uppercase Geist Mono label with wide tracking used as a category/kicker above a title or as a quiet text-button label. Broadsheet only.
- **Chip** — a bordered, `rounded-lg` pill-adjacent button with a leading icon. **Dashed chip** = the additive/tentative variant ("add …"). **Selected chip** = strengthened border + subtle fill. Broadsheet only.
- **Soft card** — a `rounded-xl` card with muted fill (`bg-muted/50`-class token), hairline or no border, generous padding. Broadsheet only.
- **Keycap hint** — a small rounded inline element rendering a keyboard glyph (↵, ⌘L) inside buttons or beside actions. Broadsheet only.
- **Page-not-modal doctrine** — major creation/composition flows render as routed full pages; modals are reserved for confirmations and small (≤4-field) forms. The doctrine is theme-independent: it applies dashboard-wide under either theme.

## Motivation

The current guide enforces restraint well (semantic tokens, color discipline, badge formula) but caps ALL type at `font-medium` and defines no display tier — so no surface can ever read as a *place*; everything reads as a panel. Creation flows land as cramped dialogs because the system has no vocabulary for anything bigger. This revision adds the missing vocabulary — type with real hierarchy, chips, soft cards, hero placeholders, keycap CTAs — while keeping the color restraint that makes the dashboard calm.

The new vocabulary ships as a **selectable theme, not a flag-day cutover.** The current style is good at what it does — dense, quiet, tabular — and it remains the right choice for a pure monitoring posture. So v2 becomes **Broadsheet**, the current style becomes **Ledger**, and the choice between them is a first-class setting ("Overdeck Theme") rather than a migration everyone absorbs at once. Both themes are fully self-hosted and maintained; new patterns land in Broadsheet only (D-15).

## Decisions

- **D-1: Typefaces & hosting.** Broadsheet UI sans is **Geist Variable**; mono is **Geist Mono Variable**. Ledger keeps **DM Sans** (variable) for UI prose and **Space Grotesk** for the sidebar wordmark, unchanged. **All four families are self-hosted `woff2`** under the frontend's static assets with `@font-face` (variable weight ranges, `font-display: swap`) and license files beside them. The Google Fonts `<link>` is removed: zero external font requests in either theme. The SF Mono stack remains the terminal/code fallback in both themes.
- **D-2: Weight hierarchy replaces the flat cap. (Broadsheet.)** Body/UI text: 400–500. Section headings: 500–600. **Display tiers only: 600–800.** The old rule "no bold anywhere" becomes "no bold outside its tier" — enforcement wording in both guide docs must state the tier table explicitly. Under Ledger the flat `font-medium` cap applies unchanged.
- **D-3: Display scale. (Broadsheet.)** `display-xl`: clamp(48px, 7vw, 72px), tracking-tight, weight 700–800, for page heroes and hero-editable titles. `display-lg`: ~40px, weight 650–700, for section heroes. Defined as Tailwind theme extensions (named text styles), not ad-hoc arbitrary values. Under Ledger these utilities resolve to Ledger-safe fallbacks per D-13.
- **D-4: Hero-placeholder pattern. (Broadsheet.)** An editable page title renders its placeholder at full display size in `text-muted-foreground/40`-class token; the input is chromeless (no border/fill) at rest.
- **D-5: Eyebrow/mono-label pattern. (Broadsheet.)** Uppercase Geist Mono, `text-[11px]`-class size, `tracking-[0.12em]`-class, `text-muted-foreground`. Sanctioned uses: card categories, kicker labels, quiet text-buttons (e.g. CANCEL). This deliberately widens mono beyond identifiers; the guide's mono rule is rewritten to name both uses. Under Ledger, mono remains identifiers-only.
- **D-6: Chip spec. (Broadsheet.)** `rounded-lg`, `h-9`–`h-10`, border `border-border`, leading icon 16px, label 400–500. Dashed variant: `border-dashed` for additive actions. Selected: `border-foreground/40` + `bg-muted` fill. Hover: fill only, never color.
- **D-7: Soft card spec. (Broadsheet.)** `rounded-xl`, `bg-muted/50`-class fill, border optional hairline, padding ≥ `p-5`, title 400–500, optional eyebrow. The sanctioned pattern for suggestion/idea/preview cards going forward.
- **D-8: Large CTA + keycap. (Broadsheet.)** New `cta` button tier: `h-12+`, `rounded-xl`, soft primary fill (`bg-primary/10 text-primary` at rest, solid on hover/focus per token), optional trailing keycap hint (`rounded-md bg-foreground/8 px-1.5` mono glyph). One per view, same as the existing single-primary rule.
- **D-9: Dot-metadata line. (Broadsheet.)** Pattern: 6px status dot (semantic signal color) + Geist Mono quiet text, items separated by `·`. Sanctioned for ambient state summaries (e.g. "Memory enabled · Files shared").
- **D-10: Page-not-modal doctrine. (Theme-independent.)** Creation/composition flows (new project, new workspace, and future editors) are routed pages. Modals remain for confirmations and ≤4-field quick forms. The guide gains this as a named rule; PAN-3411 executes it for workspaces; migrating NewProjectModal is a listed follow-up, not part of this issue.
- **D-11: What does NOT change (both themes).** Semantic tokens only; color restraint (one signal per row, amber/blue/emerald/red meanings); badge tint formula (radius may move `rounded-sm`→`rounded-md` for texture consistency — single deliberate change, called out in the diff); no hardcoded hex; no decorative color. State this list verbatim in both docs so agents don't over-rotate.
- **D-12: Migration is bounded, and scoped to Broadsheet.** The mechanical migration (font-family + weight utilities) lands entirely under the Broadsheet theme scope. **Ledger rendering is byte-for-byte today's styles** — no font swap, no weight changes, no utility changes. It does NOT restyle individual components to the new patterns — consumers adopt them per-feature (PAN-3411 first).
- **D-13: Theming model.** A single `data-theme="ledger|broadsheet"` attribute on the document root carries the theme. Font families and the display-scale utilities are defined per-scope (Ledger values are the `:root` defaults; Broadsheet overrides under `[data-theme="broadsheet"]`). Components never branch on theme: Broadsheet-only utilities resolve to Ledger-safe fallbacks (`display-xl` → `text-xl font-medium`, `display-lg` → `text-lg font-medium`, eyebrow → `text-xs uppercase tracking-wider font-medium`) when Ledger is active, so a surface written against the v2 vocabulary degrades in scale and texture but never breaks.
- **D-14: Configuration surface — "Overdeck Theme".** `ui.theme` in `~/.overdeck/config.yaml`, enum `ledger | broadsheet`, default `broadsheet` when unset. An invalid value fails loudly at config resolution with a clear "invalid ui.theme" error — never a silent fallback (consistent with the no-hardcoded-fallback rule). Settings → Appearance gains an **Overdeck Theme** picker: two selectable cards, each showing the theme name, a one-line description, and a live mini-specimen rendered in that theme's fonts. The picker writes through the existing config write door; on write the SPA flips `data-theme` immediately (no reload), and boot applies the resolved value before first paint.
- **D-15: Theme governance.** New patterns (D-4..D-9) are Broadsheet-only forever; Ledger receives bug fixes only. The law file documents both themes and marks Ledger **legacy**. New surfaces must render correctly under both themes via the D-13 fallbacks rather than conditional markup. PAN-3411's New Workspace page is authored against Broadsheet primitives and relies on this mapping: under Ledger it loses display scale and texture but no functionality.
