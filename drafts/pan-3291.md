# PAN-3291 — push-race reconciler wedges permanently on records/*.json content conflicts

**Issue:** https://github.com/eltmon/overdeck/issues/3291
**Author:** planning agent (claude-fable-5), auto mode, 2026-07-30
**Verified against:** `feature/pan-3291` @ `a584bc6cb2`

## Glossary

- **State branch / `overdeck-state`** — the same-repo orphan branch holding permanent pipeline state (`records/`, `specs/`, `drafts/`, `continues/`), checked out as a worktree at `${OVERDECK_HOME}/state/<project>/`. Constant `STATE_BRANCH` from `src/lib/state-read-home.ts`.
- **State worktree root / `gitRoot`** — the on-disk checkout of the state branch, resolved by `resolveStateReadHomeSync(project).root`.
- **Record / mirror file** — `records/<issue>.json`, a full-file snapshot of an issue's durable pipeline state, regenerated from canonical state on every write through the record write door. Re-derivable: a lost mirror version self-heals on the file's next write-door update.
- **Record write door** — `updateIssueRecord()` in `src/lib/pan-dir/record-update.ts:318`: takes the per-issue fs lock, runs the caller's `mutator` on the record, writes it, commits, and pushes within a bounded durability budget.
- **Mutator** — the caller-supplied `IssueRecordMutator` function that transforms the current record into the desired next record. Replaying the mutator against a newer base record re-derives "current truth wins".
- **Push race** — two machines push to `origin/overdeck-state` concurrently; the loser's push is rejected non-fast-forward.
- **Push-race reconciler** — `reconcileStatePush()` in `src/lib/pan-dir/record-update.ts:274`: today it fetches origin and runs `git rebase origin/overdeck-state`, retrying up to `MAX_STATE_PUSH_RECONCILIATIONS = 3` (`record-update.ts:24`).
- **Restore checkpoint** — the compensating commit `chore(records): restore <issue> after failed state push` created by `restoreRetryableRecord()` (`record-update.ts:220`) so HEAD stays retryable after a failed durability attempt.
- **Poisoned commit** — a local unpushed commit that content-conflicts with origin during rebase replay. Because rebase replays every local commit one at a time, the same commit aborts the rebase identically on every reconcile attempt, forever.
- **Durability deadline** — `withRecordDurabilityDeadline()` (`record-update.ts:53`): bounds the whole commit/push/reconcile under the record lock (default 30s, `OVERDECK_RECORD_DURABILITY_BUDGET_MS`); on timeout the `onTimeout` cleanup must abort any in-flight git operation so nothing mutates the worktree after the lock releases.
- **Ours / theirs** — during `git merge origin/overdeck-state` executed on the local `overdeck-state` branch, **ours = local HEAD**, **theirs = origin**. `git checkout --theirs -- <path>` takes origin's version.
- **Push-health file** — new runtime-plane JSON file (this PRD, work item 3) tracking the consecutive reconcile-failure streak per project. Lives under `${OVERDECK_HOME}/push-health/`, never on the state branch.
- **Needs-you** — an operator-facing escalation. In this PRD it is delivered as an `error`-level activity entry via `emitActivityEntry()` (`src/lib/activity-logger.ts:354`), which flows event store → WebSocket → dashboard activity feed.
- **Activity source** — the `ActivitySource` string union at `src/lib/activity-logger.ts:22`. This PRD adds `'state-door'`.

## Problem

On 2026-07-29 this machine's `overdeck-state` diverged to 74 ahead / 44 behind origin and every state push failed for hours. Log signature, repeating per write:

```
[pan-dir/records] Failed to update record for PAN-3260: Failed to reconcile PAN-3260 state after push race: Rebasing (2/39)error: could not apply 082ef066c2... chore(records): restore PAN-3260 after failed state push
```

Root cause, confirmed in code:

1. `reconcileStatePush()` (`record-update.ts:283-299`) rebases the local state branch onto `origin/overdeck-state`. Rebase replays each of the N local unpushed commits one at a time.
2. On conflict, `replayConflictedRecord()` (`record-update.ts:183`) only handles the case where the **sole** conflicted path is the **current** issue's record (`record-update.ts:196-198`). A conflict on any other record — e.g. an intermediate restore checkpoint for a different issue — throws, `abortRebase()` runs, and the write fails.
3. The poisoned commit never goes away, so every subsequent write for every issue fails at the same replay step. Each failure adds another restore checkpoint (`restoreRetryableRecord`, `record-update.ts:265-271`), so the local stack only grows and reconciliation gets bigger.
4. Nothing surfaces the wedge: the reconciler retry-loops silently while divergence compounds, until an operator notices blocked pipelines (PAN-3286) and performs a manual merge.

The operator recovery precedent (commits `b115fb6b2b`, `d902f8fea3`) was a **same-branch merge**: `git merge origin/overdeck-state`, resolve conflicted records (origin side for stale mirrors, replay for the actively-written one), push. That is exactly what the reconciler should do mechanically.

Note the auto-commit push path is *deliberately* not the fix site: `pushStateBranch()` (`src/lib/pan-dir/auto-commit.ts:716-739`) never rebases or replays by design ("The paths-only queue has no mutation intent", PAN-2541 D10). `reconcileStatePush()` is the only reconcile owner for the migrated state branch, gated at `record-update.ts:353-373`.

## Proposal

Three changes, all scoped to the migrated state branch:

1. **Merge-based reconcile** — replace the rebase in `reconcileStatePush()` with a single 3-way merge of `origin/overdeck-state` into the local branch, with a deterministic conflict policy: conflicts confined to `records/` auto-resolve (origin wins; the record being written is then re-derived by replaying the mutator so current truth wins); a conflict touching any other path aborts the merge cleanly and fails the attempt. A merge is one resolution event regardless of how many local commits accumulated, so a poisoned intermediate commit structurally cannot wedge it.
2. **Never-terminal failure** — track a per-project consecutive reconcile-failure streak in a runtime-plane push-health file; on crossing 3 consecutive failures, emit a self-contained `error` activity entry naming the conflicted paths, so the dashboard shows the wedge instead of the system silently retry-looping.
3. **`pan doctor` divergence reporting** — a new doctor check reports, per migrated project, the state worktree's ahead/behind counts vs `origin/overdeck-state` plus the streak and last failure reason from the push-health file (fulfils the PAN-2375 divergence-surfacing intent).

## Requirements

- **FR-1** — Push-race reconciliation performs a single 3-way merge of `origin/overdeck-state` into the local state branch (per attempt) instead of a per-commit rebase replay. A content conflict introduced by any intermediate local commit (e.g. another issue's restore checkpoint) does not abort reconciliation.
- **FR-2** — When every conflicted path of the reconcile merge is under `records/`, the reconciler resolves them deterministically without human input: each conflicted record takes origin's version (`git checkout --theirs`); the record currently being written is then re-derived by replaying the caller's mutator on the origin version and re-written through `writeIssueRecordSync`; the merge concludes with a merge commit and the push retry proceeds.
- **FR-3** — When any conflicted path is NOT under `records/` (e.g. `specs/`, `drafts/`, `continues/`), or a conflicted `records/` path cannot be resolved by `git checkout --theirs` (delete/modify conflict), the reconciler aborts the merge (`git merge --abort`), leaves the worktree in a retryable non-mid-merge state, and fails the attempt with an error naming the conflicted paths.
- **FR-4** — Every failed reconcile attempt-set (a `reconcileStatePush` call that throws) increments a per-project consecutive-failure streak persisted in the push-health file; a successful reconcile (record pushed) resets the streak to 0 and stamps `lastSuccessAt`.
- **FR-5** — When the streak crosses the threshold (3), exactly one `error`-level activity entry is emitted via `emitActivityEntry` with source `'state-door'`, containing: project name, the conflicted paths from the last failure, the streak count, and a plain-language instruction that state pushes are failing and `pan doctor` shows the divergence. Subsequent failures beyond the threshold do not re-emit until the streak resets and crosses again.
- **FR-6** — `pan doctor` includes a state-divergence check per migrated project: ahead/behind commit counts of the local state branch vs `origin/overdeck-state` (after a bounded fetch), the reconcile-failure streak, and the last failure reason. Status mapping: `error` when streak ≥ 3; `warn` when streak ≥ 1 or ahead ≥ 10; `ok` otherwise.
- **FR-7** — The durability-deadline `onTimeout` cleanup and `restoreRetryableRecord` abort an in-flight **merge** (bounded, 5s) in addition to the existing rebase abort, so a deadline abort never leaves the state worktree mid-merge after the record lock releases.
- **NFR-1** — No `execSync` anywhere server-reachable; all new git invocations go through the existing promisified `git()` helper (`record-update.ts:140`) or `runGitWithTimeout` and honor the `AbortSignal` + `throwIfDurabilityAborted` discipline between synchronous steps.
- **NFR-2** — Any test exercising retries or delays uses `vi.useFakeTimers()`; the reconcile loop itself has no wall-clock sleeps today and this change must not add any.
- **NFR-3** — The doctor divergence check's fetch is bounded (≤10s) and offline-tolerant: on fetch failure it reports counts against the last-fetched origin ref and labels them stale rather than erroring.
- **NFR-4** — Push-health file writes are atomic (write temp file, rename) so a crash mid-write cannot truncate it (crash-zero-byte precedent PAN-2623).

## Decisions (made here, not by the executor)

- **D1: merge, not rebase.** The issue offered "the reconcile rebase (or a merge-based alternative)". Merge chosen: one 3-way resolution regardless of local stack depth, immune to poisoned commits, matches the operator recovery precedent (`b115fb6b2b`, `d902f8fea3`). Same-branch origin merges are allowed; the never-merge guard applies to main↔state cross-merges only.
- **D2: take-origin-then-replay, not regenerate-from-canonical.** The issue named this the cheaper option; the write door already owns mutator replay (`replayConflictedRecord` pattern).
- **D3: conflict policy in code, not a `.gitattributes` merge driver.** A custom driver needs per-clone `merge.<name>.driver` config (fragile across worktree recreation); code in the reconciler is self-contained and testable.
- **D4: streak lives in a runtime-plane local file, keyed by state-worktree basename.** Not on the state branch (it is the failing transport), not in SQLite (the record write door must work from CLI processes without the server). Key = `basename(resolveStateReadHomeSync(project).root)`, derivable from `ProjectConfig` alone.
- **D5: threshold = 3 consecutive failed `reconcileStatePush` calls**, module constant, aligned with `MAX_STATE_PUSH_RECONCILIATIONS`.
- **D6: delete/modify conflicts on records are NOT auto-resolved** — abort per FR-3. Records are essentially never deleted; safety over cleverness.
- **D7: for conflicted records other than the one being written, origin wins even if the local side had unpushed mutations.** Mirror-class files are re-derivable and self-heal on their next write-door update (issue statement + incident evidence). Accepted data-tolerance, documented as hazard H3.

       // Bounded local cleanup — same contract as abortRebase.

### 2. `merge-reconcile` — merge-based reconcile with deterministic records/ conflict policy

**Why:** FR-1, FR-2, FR-3. The core fix.

**Files:** `src/lib/pan-dir/record-update.ts`, new test file `src/lib/pan-dir/__tests__/record-reconcile.test.ts`

**Steps — rewrite the body of the attempt loop in `reconcileStatePush` (`record-update.ts:283-313`):**

Before (current):
```ts
await git(gitRoot, ['fetch', 'origin', STATE_BRANCH], { signal });
try {
  await git(gitRoot, ['rebase', `origin/${STATE_BRANCH}`], { signal });
} catch (error) {
  ...replayConflictedRecord... // single-conflict, current-record-only
}
```

After (target shape):
```ts
await git(gitRoot, ['fetch', 'origin', STATE_BRANCH], { signal });
try {
  await git(gitRoot, ['merge', '--no-edit', `origin/${STATE_BRANCH}`], { signal });
} catch (error) {
  throwIfDurabilityAborted(signal);
  try {
    await resolveMergeConflicts(project, issueId, mutator, gitRoot, recordPath, signal);
  } catch (resolveError) {
    await abortMerge(gitRoot, { signal });
    await abortRebase(gitRoot, { signal });
    throw new Error(
      `Failed to reconcile ${issueId} state after push race: ${gitFailureMessage(resolveError)}`,
      { cause: error },
    );
  }
}
```

`resolveMergeConflicts` (replaces `replayConflictedRecord`; delete the old function):
1. List conflicts: `git diff --name-only --diff-filter=U` → `conflicts: string[]` (relative to `gitRoot`).
2. If `conflicts` is empty, the merge failed for a non-conflict reason → rethrow (message from the merge error).
3. If any path does not start with `records/` → throw `new Error('state merge conflicted outside records/: <paths>')`.
4. For each conflicted path: `git checkout --theirs -- <path>` then `git add -- <path>`. If checkout fails (delete/modify), throw (D6) — the outer catch aborts the merge.
5. `throwIfDurabilityAborted(signal)`.
6. If `relative(gitRoot, recordPath)` was among the conflicts: `const remoteRecord = readIssueRecordSync(project, issueId)`; throw if unreadable; `const result = await mutator(remoteRecord)`; `throwIfDurabilityAborted(signal)`; `writeIssueRecordSync(project, issueId, result ?? remoteRecord)`; `git add -- <relativeRecordPath>` (mirrors the current `replayConflictedRecord` body at `record-update.ts:200-216`).
7. Conclude the merge: `git -c core.editor=true commit --no-edit` (completes the in-progress merge commit with the default message).

The push loop after the merge is unchanged (`record-update.ts:301-312`): push, return record on success, retry on `isRemoteRefRaceError`, rethrow otherwise. At reconcile start (before the first fetch), run `abortMerge` + `abortRebase` once so a worktree stranded mid-operation by a prior crash recovers (mirrors `restoreRetryableRecord`'s posture).

**Tests (`record-reconcile.test.ts`, following the temp-repo pattern of `record-update.test.ts` — real git repos, bare origin, a second clone simulating the other machine; `execFileSync` in tests is fine, none of it is server-reachable):**
- **Two-writer convergence:** both clones mutate the same `records/<issue>.json` from a shared base; clone B pushes first; clone A's `updateIssueRecord` succeeds without human input; origin's final record contains A's mutation applied on top of B's pushed version; no `restore … after failed state push` commit exists on origin.
- **Poisoned-commit (the PAN-3291 wedge):** clone A accumulates ≥3 local commits including one that conflicts with origin (a restore checkpoint for a *different* issue), origin diverges; A's next write reconciles successfully in one call; ahead count returns to 0 after push.
- **Non-records conflict:** conflicting `specs/` file on both sides → `updateIssueRecord` rejects with an error naming the path; `git status` in the state worktree shows no in-progress merge; a subsequent write after the operator resolves origin manually succeeds.
- **Delete/modify conflict on a record:** origin deletes the record, local modifies → reconcile aborts cleanly (per D6) with the conflicted path in the message.

## Intersecting repo rules (restated for the executor)

- **Fake timers** for any retry/backoff/delay test (`vi.useFakeTimers()` + `vi.advanceTimersByTimeAsync`); the reconcile loop has no sleeps — do not add any.
- **No `execSync`** in anything server-reachable (`record-update.ts` and `activity-logger.ts` are server-reachable). Test files may use `execFileSync` per the existing `record-update.test.ts` pattern.
- **Never bypass** the overdeck-state protection guards; the reconcile merge is same-branch (local `overdeck-state` ← `origin/overdeck-state`), never a main↔state merge. No `--no-verify` anywhere (the `git()` helper's `HUSKY: '0'` env is pre-existing state-worktree behavior, not a hook bypass to replicate elsewhere).
- **Abort-signal discipline:** every new git step takes `{ signal }`; every synchronous mutation between subprocesses is preceded by `throwIfDurabilityAborted(signal)`; `onTimeout` cleanups stay bounded (5s aborts) and never wait out a full git timeout under the lock.
- **One xBRIEF item per commit, push before `pan task done`** (per-bead durability rule).

## Acceptance criteria (map 1:1 to work items)

1. After a durability-deadline abort during a conflicted reconcile merge, the state worktree has no in-progress merge or rebase and the record file is retryable.
2. Simulated two-writer conflict on one `records/*.json` reconciles without human input; both clones converge; no restore-checkpoint accumulation on origin; the poisoned-commit scenario (intermediate conflicting local commit) also reconciles in a single `updateIssueRecord` call; non-records conflicts reject with the conflicted path named and a clean worktree.
3. Push-health file increments/resets correctly, `crossedThreshold` fires exactly once at 3, corrupt file reads as zeroed default, writes are tmp+rename atomic.
4. Three consecutive reconcile failures produce exactly one `state-door` error activity entry naming the conflicted paths; success resets the streak.
5. `pan doctor` prints per-project state divergence (ahead/behind, streak, last failure) with the FR-6 status mapping and survives an unreachable origin.
6. `docs/STATE-PLANE-COMMIT-POLICY.md` describes the merge-based conflict policy, the escalation threshold, and the doctor check; `docs/AGENT-STATE-PLANES.md` links to it.

## Non-goals

- No change to the legacy (unmigrated) `main`-branch state push path (`pushOriginMain` / `rebaseLegacyMainAndRetry` in `auto-commit.ts`).
- No reconcile for non-record state writers (specs/drafts/continues push failures still surface only via doctor divergence + the streak escalation when a record write trips over them).
- No auto-resolution of conflicts outside `records/` — those are for a human.
- No `.gitattributes` merge driver (D3).
- No push-health wiring into plain (non-reconcile) push successes in `auto-commit.ts`.
- No new dashboard UI surface beyond the activity entry.
- No retroactive repair of already-diverged machines (the doctor `fix` string documents the manual merge).
