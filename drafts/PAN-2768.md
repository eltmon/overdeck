# PAN-2768 — Ship the pan CLI in the packaged desktop app (Sync Now MODULE_NOT_FOUND)

**Issue:** https://github.com/eltmon/overdeck/issues/2768
**Author:** planning agent (claude-fable-5), auto mode, 2026-07-16
**Status:** draft

## Glossary

- **Packaged desktop app** — the electron-builder outputs of `apps/desktop`: Linux AppImage, macOS dmg, Windows nsis. Distinct from the **npm/npx flavor** (`@overdeck/desktop` installed from npm) and from a **source checkout** (`pan up` from the repo).
- **`resources/`** — electron-builder's per-app resource directory inside the packaged app. In an AppImage it mounts at `/tmp/.mount_*/resources`. `extraResources` entries in `apps/desktop/package.json` are copied here.
- **`packageRoot`** — computed by `resolvePackageRootForDir()` in `src/lib/paths.ts:84-101` from the running bundle's location. For the packaged server (which runs from `resources/server/server.js`) it resolves to `resources/`.
- **`panCliInvocation`** — `src/lib/pan-cli-invocation.ts:17`; builds `{command: process.execPath, args: [join(packageRoot, 'dist', 'cli', 'index.js'), ...args]}`. Every dashboard route that shells out to the `pan` CLI goes through it (directly or via `spawnPanCli`).
- **`ELECTRON_RUN_AS_NODE`** — env var that makes the Electron binary behave as plain Node. The desktop app spawns its server child with it set (`apps/desktop/src/server.ts:99`); children of the server inherit it.
- **Staging script** — `apps/desktop/scripts/prepare-server-resources.mjs`, run by every `dist:*` script before electron-builder. It assembles gitignored staging dirs (`server/`, `drizzle/`, `sync-sources/`) that `extraResources` maps into the package.
- **Chunk closure** — the set of code-split JS files transitively imported by an entry. The root tsdown build (`tsdown.config.ts`) emits `dist/cli/index.js` importing sibling chunks at the `dist/` root (`../chunk-*.js`, `../paths-*.js`, …).
- **Externals** — npm packages the bundle does not inline (tsdown externalizes `package.json` dependencies except `@overdeck/*`). They must be resolvable via a `node_modules` at runtime.

## Problem

Clicking **Sync Now** in the packaged AppImage fails:

```
Error: Cannot find module '/tmp/.mount_Overde72AyLw/resources/dist/cli/index.js'
```

`POST /api/system/sync` (`src/dashboard/server/routes/misc/meta.ts:116`) runs `panCliInvocation(['sync'])`, which points at `<packageRoot>/dist/cli/index.js` = `resources/dist/cli/index.js`. But `build.extraResources` in `apps/desktop/package.json:71-92` ships only `drizzle`, `sync-sources` (hooks only — see below), `server`, and `resources`. **`dist/cli` is never packaged**, so every pan-CLI shell-out fails identically.

### Verified caller audit (2026-07-16, this workspace at `af61199ec9`)

All call sites route through `panCliInvocation`/`spawnPanCli` (`git grep panCliInvocation\|spawnPanCli`):

1. `src/dashboard/server/routes/misc/meta.ts:116` — `pan sync` (Sync Now).
2. `src/dashboard/server/routes/misc/meta.ts:528` — `pan restart --dashboard` (detached).
3. `src/dashboard/server/routes/context.ts:549` — `pan context sync`.
4. `src/dashboard/server/routes/issues.ts:432` — `pan reset-to-planned <id>`.
5. `src/dashboard/server/routes/agents/shared.ts:88` — agent spawn (detached, spawn.log).
6. `src/dashboard/server/routes/workspaces.ts:530` and `:544` — `spawnPanCommand` workspace rebuild / start / rebuild-and-start chain (detached, output streamed to activity log).

**None of these passes an explicit `env` to the spawn** — all inherit the server's environment, which in the packaged app includes `ELECTRON_RUN_AS_NODE=1` from `apps/desktop/src/server.ts:96-99`. Drew's stack (`node:electron/js2c/node_init`) confirms the child ran as Node; the only failure is the missing file.

### Second latent gap: sync-sources is hooks-only

The staging script copies **only** `sync-sources/hooks` (`prepare-server-resources.mjs`, "Stage the Claude Code hook bundle (PAN-2595)" block). But `pan sync` reads the full tree — `SYNC_SOURCES.skills/devSkills/agents/rules/hooks` at `<packageRoot>/sync-sources` (`src/lib/paths.ts:159-169`, consumed by `src/lib/sync.ts`). Shipping the CLI without the full tree would let Sync Now launch and then fail on missing source directories. Fixing the spawn but not the payload does not close the report.

## Decision — option 1 (ship the CLI), and why

The issue offered two fixes and asked for one deliberate choice.

**Chosen: option 1 — ship the CLI bundle.** Option 2 (call the sync routine in-process) only cleanly applies to Sync Now. Of the seven call sites, `pan restart --dashboard` *cannot* run in-process (it restarts the server itself, spawned detached so it outlives SIGTERM), and the workspace rebuild/start chains and agent spawn are child processes by design (detached, output-streamed, survive the request). The CLI must therefore ship regardless; rewriting sync in-process on top would be a redundant partial refactor. Option 1 repairs the entire failure class with **zero runtime code change**.

**Packaged layout decision:** ship at `resources/dist/cli/index.js` with a self-contained `resources/dist/node_modules`, rather than nesting under `server/` to share `server/node_modules`. This preserves the canonical `packageRoot/dist/cli/index.js` path (no changes to `pan-cli-invocation.ts` or `paths.ts`), at an accepted size cost (uncompressed externals overlap `server/node_modules` — ~150MB on disk today — but squashfs/dmg/nsis compression shrinks it substantially). Sharing would require new resolution logic and entangle two staging graphs.

**Out of scope:** the npm/npx flavor. `npm pack` strips nested `node_modules`, so vendored externals cannot ship that way; this is the same limitation as the npx node-pty story already tracked on PAN-2561. Do **not** add `cli` to `apps/desktop` `files[]`.

## Requirements

- **FR-1** — The packaging staging script assembles a self-contained CLI runtime (entry + chunk closure + assets + vendored externals) and fails the build if that runtime cannot execute `--version` in isolation.
- **FR-2** — `build.extraResources` maps the staged runtime to `dist/` so the packaged path is exactly `resources/dist/cli/index.js`.
- **FR-3** — The full `sync-sources` tree ships in the package (not only `hooks/`).
- **FR-4** — `apps/desktop/tests/package-structure.test.ts` locks the new packaging contract (removing the extraResources entry or reverting the staging makes the suite fail).
- **FR-5** — A built Linux AppImage, extracted with `--appimage-extract`, contains the CLI and runs it successfully under the bundled Electron with `ELECTRON_RUN_AS_NODE=1`.
- **FR-6** — `docs/DESKTOP-APP.md` and the staging script header document the shipped CLI runtime, the env-inheritance invariant, and the npx-flavor exclusion.
- **NFR-1** — No changes to `src/lib/pan-cli-invocation.ts`, `src/lib/paths.ts`, or any route handler; the fix is packaging-only.
- **NFR-2** — The staging smoke-run executes from a tmpdir outside the repo with `OVERDECK_HOME` pointed at a temp dir (repo `node_modules` must not mask missing externals; the build host's `~/.overdeck` must not be touched).
