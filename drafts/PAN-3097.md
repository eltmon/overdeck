# PAN-3097 — AskUserQuestion dialog: show issue title alongside identifier, and make agent questions self-contained

Issue: https://github.com/eltmon/overdeck/issues/3097
Verified against commit `ae2a6f7310` on `feature/pan-3097` (2026-07-26).

## Glossary

- **AUQ** — AskUserQuestion, the Claude Code tool an agent uses to ask the operator a multiple-choice question. In Overdeck the tool call is denied by `sync-sources/hooks/ask-user-question-hook` (PAN-1520); the denied payload is detected by `src/lib/agent-enrichment.ts` and surfaced as `pendingAskUserQuestion` on the agent/conversation, which drives the dashboard dialog.
- **AUQ dialog** — `AskUserQuestionDialog` in `src/dashboard/frontend/src/components/AskUserQuestionDialog.tsx`, the modal that renders the pending question's options as clickable buttons.
- **Subject** — the `AskUserQuestionSubject` shape the dialog consumes: either an agent snapshot or a conversation row, both carrying `pendingAskUserQuestion`.
- **Needs-you list** — the Decisions surfaces: `DecisionsPanel` (fed by `useDecisions()` in `src/dashboard/frontend/src/lib/useDecisions.ts`) and the "Needs you" tab of `SessionFeedSidebar` (fed by `usePendingInputSubjects()`).
- **Issues resolver / store issues** — the canonical issues read door. The frontend never queries trackers directly; it consumes `issuesRaw` in the Zustand dashboard store (`selectIssues` in `src/dashboard/frontend/src/lib/store.ts:559`), hydrated from the server read model over the `/ws/rpc` snapshot + event stream. Joining against store issues adds **no** new store/tracker access.
- **Bundled rule** — a markdown file in `sync-sources/rules/` with `scope: universal|dev` frontmatter that `pan sync` renders into every harness context file (managed region of `~/.claude/CLAUDE.md`, `pi-global.md`, `codex-global.md`). A `scope: universal` rule reaches every Claude Code / Pi / Codex session on every machine — work agents, plan agents, and conversations alike.

## Problem

Two related failure modes, same root: the operator answers an AUQ without the context the agent assumed they had.

1. **Bare identifier.** The dialog's Issue cell renders only `agent.issueId ?? 'Unknown'` (`AskUserQuestionDialog.tsx:135`). The header prefers `agent.title` (`AskUserQuestionDialog.tsx:76,107`), which for agents happens to be the issue title (populated by `usePendingInputDialogs.ts:144,181`) but is shown *without* the identifier, and for conversations is the conversation title with no issue title at all. `useDecisions.ts:143` labels agent decisions with the bare `issueId`; `SessionFeedSidebar.tsx:247` labels needs-you rows with the title *instead of* the identifier. No surface shows `MIN-663 — Redesign daily briefing layout` as one unit.
2. **Non-self-contained questions.** Agents write questions that assume the reader has the transcript ("Should I go with option B?"). The operator often answers from the dialog alone. The AUQ hook fires *after* the question is written and the dialog shows the original payload, so hook-time text cannot fix this — the guidance must reach agents before they write the question.

## Requirements

- **FR-1** — The AUQ dialog shows `"<issueId> — <issue title>"` (header and Issue cell) for any subject (agent or conversation) bound to an issue whose title resolves from store issues.
- **FR-2** — When the subject is bound to an issue whose title does not resolve, the dialog shows the identifier alone (never `"<id> — undefined"` or `"— Unknown"`). When the subject is unbound (no `issueId`), the dialog omits the Issue cell entirely instead of rendering the literal `Unknown`.
- **FR-3** — Titles are resolved exclusively by joining against store issues (fed by the issues resolver). No new REST endpoint, tracker call, or direct DB/store access is added.
- **FR-4** — `DecisionsPanel` rows (the Needs-you list) show the same `"<issueId> — <title>"` label for issue-bound decisions; conversations keep their conversation-title label plus the issue reference when bound.
- **FR-5** — The `SessionFeedSidebar` "Needs you" rows show `"<issueId> — <title>"` rather than title-only.
- **FR-6** — Agent-facing guidance instructs agents to write self-contained AUQ prompts (1–2 sentences of situation, the decision in plain language, each option's consequence), delivered through a channel that reaches **every** role that can invoke AUQ: work, plan, and conversation, on every harness.
- **NFR-1** — One shared formatting helper produces the `"<issueId> — <title>"` string so the surfaces cannot drift.
- **NFR-2** — Every behavior above is locked by a unit or component test.

## Decisions (made here, not left to the executor)

- **D1 — Formatting helper.** New pure helper `formatIssueRef(issueId?: string | null, title?: string | null): string | null` in a new file `src/dashboard/frontend/src/lib/issueLabel.ts`. Returns `null` when `issueId` is empty/null; `issueId` when title is empty; `` `${issueId} — ${title}` `` (em dash, spaces) otherwise. All three surfaces call it.
- **D2 — Subject shape.** `AskUserQuestionSubject` gains `issueTitle?: string | null`. The existing `title` field keeps its current meaning (conversation title for conversations; for agents it is currently overloaded with the issue title and that population is left untouched so the toast labels at `usePendingInputDialogs.ts:279,435,443,503,515` keep working).
- **D3 — Dialog rendering.** Header `<h2>`: for issue-bound subjects render `formatIssueRef(issueId, issueTitle)`; otherwise fall back to today's `title?.trim() || id`. Issue cell: render the cell only when `issueId` is present, with text `formatIssueRef(issueId, issueTitle)`. The `'Unknown'` literal is removed.
- **D4 — Title source.** Client-side join against store issues (`issues.find((i) => i.id === subject.issueId)?.title`), matching the existing pattern at `usePendingInputDialogs.ts:144`. `useDecisions` builds a memoized `Map<issueId, title>` from `useDashboardStore(selectIssues)` the same way `SessionFeedSidebar.tsx:201-207` already does. This satisfies FR-3: `issuesRaw` is resolver-fed; nothing new touches a store.
- **D5 — Guidance carrier.** A new `scope: universal` bundled rule `sync-sources/rules/ask-user-question-self-contained.md` is the mechanical carrier that reaches work, plan, and conversation roles on all harnesses (FR-6). The planning prompt (`src/lib/cloister/prompts/planning.md:145` "Question discipline") and `roles/plan.md:73` are additionally amended because the plan role is by far the heaviest AUQ user. No per-role duplication beyond that.
- **D6 — Decision.label semantics.** In `useDecisions`, `Decision` gains `issueTitle?: string`. The agent-branch label at `useDecisions.ts:143` (`label: s.issueId ?? s.agentId`) becomes `formatIssueRef(s.issueId, titleByIssueId.get(s.issueId)) ?? s.agentId`. The conversation-branch label at `useDecisions.ts:166` stays `c.title || c.name` (a conversation is recognized by its own title), with `issueTitle` populated so `DecisionsPanel` can render the issue reference beside it.
- **D7 — Out of scope.** The optional "render a snippet of the agent's most recent message in the dialog" backstop from the issue is explicitly NOT built (NonGoal) — the issue names the agent-side fix as primary, and the snippet needs a transcript read path the dialog does not have.

## Work items

### W1 — `formatIssueRef` helper + unit test

Files: `src/dashboard/frontend/src/lib/issueLabel.ts` (new), `src/dashboard/frontend/src/lib/__tests__/issueLabel.test.ts` (new).

Implement per D1:

```ts
/** "PAN-123 — Fix the thing" | "PAN-123" | null. One join point so AUQ surfaces can't drift. */
export function formatIssueRef(issueId?: string | null, title?: string | null): string | null {
  const id = issueId?.trim();
  if (!id) return null;
  const t = title?.trim();
  return t ? `${id} — ${t}` : id;
}
```

Test the four cases: both present, id only, null/empty id (with and without title) → null, whitespace title → id only.

### W6 — Universal bundled rule: self-contained AUQ prompts (FR-6)

Files: `sync-sources/rules/ask-user-question-self-contained.md` (new).

Author per `.claude/rules/rule-authoring.md` — terse, imperative, `scope: universal`:

```markdown
---
scope: universal
---
### Make every AskUserQuestion self-contained

The operator usually answers from a dashboard dialog without your transcript.
Every AskUserQuestion must stand alone: 1–2 sentences of situation (what you
are working on and what you just found or decided), the decision being asked
in plain language, and options whose descriptions state the consequence of
choosing them — never bare labels like "Option B".

WHY: questions like "Should I go with option B?" are unanswerable from the
dialog, forcing the operator to dig up your transcript before they can unblock you.
```

The rule reaches work, plan, and conversation sessions on all harnesses via the `pan sync` rendering pipeline (D5).
