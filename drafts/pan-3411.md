# PAN-3411 — New Workspace as a full-page creation experience

**Issue:** https://github.com/eltmon/overdeck/issues/3411
**Depends on:** PAN-3410 (style guide v2 — display scale, chips, soft cards, CTA, eyebrow labels)
**Relates to:** PAN-3330 (shipped the modal + all backend routes this page reuses)
**Status:** draft

---

## Glossary

- **Creation page** — a routed, full-viewport page (`/workspaces/new`) replacing the `NewWorkspaceModal` dialog as the way operators create user workspaces.
- **Resolve-before-create** — the PAN-3330 contract: field changes call `POST /api/workspace-registry/resolve` (write-free dry run returning the resolved intent + `findings`), and `POST /api/workspace-registry` creates only from a clean resolution. The page changes none of this.
- **Project chip row** — the horizontal selector at the top of the page: a dashed **add existing** chip (register a directory as a project), a **new project** chip, one chip per known project (most recent first), and a **more projects** overflow menu when they don't fit.
- **Hero title** — the page's dominant element: a chromeless editable title at `display-xl` scale whose placeholder reads "Untitled workspace" in muted ink (style guide v2 D-3/D-4).
- **Status strip** — the row beneath the fold divider: left, a dot-metadata line summarizing the resolved intent; right, a quiet mono CANCEL and the large **Start workspace** CTA with an ↵ keycap (Enter submits).
- **Idea cards** — a grid of soft cards, each an eyebrow category + short title, that prefill the form as a starting point.

## Motivation

Creating a workspace is the beginning of a stream of work; the shipped modal treats it as a settings form. A full-page treatment gives the action room: the name becomes the hero, project choice becomes one visible row of chips instead of a dropdown, the resolved intent reads as a calm status line instead of a preview panel, and the empty state teaches by suggestion. Everything the modal can do, the page must do — this is a re-staging, not a re-scoping.

## Decisions

- **D-1: The page owns creation; the modal is deleted in the same PR — behind a no-loss audit.** Enumerate every modal affordance (name, project select incl. sole-project default, target dropdown + Browse/FolderPicker, shared/isolated toggle, advanced parent-branch, live resolved preview, inline findings, Create disabled while stale/invalid, `onCreated` activate+navigate) in a checklist test; the page test suite must tick every row before the modal file is removed. `git rm` of the modal + its test is part of WI-4, never earlier.
- **D-2: Layout (top→bottom).** (1) Project chip row; (2) Hero title (autofocused, Enter moves to submit when valid); (3) target row: a folder chip showing the resolved target directory with a chevron opening the picker (registered targets + Browse…), plus the shared/isolated toggle and the advanced parent-branch disclosure, all in one quiet line; (4) hairline divider; (5) status strip; (6) hairline divider; (7) "Ideas for your next workspace" idea-card grid. Generous page container per style v2 spacing.
- **D-3: The status strip is the resolved intent, re-voiced.** Left side dot-metadata line composes from the live resolution: always "Memory enabled" (every workspace gets a memory home — dot uses the emerald outcome signal), then mode ("Files shared" for shared mode / "Isolated worktree"), then git posture ("git repository" / "no git detected"), then parent branch when overridden. Findings replace the line's segment with the finding text in the destructive token — the strip IS the validation surface; no separate error panel.
- **D-4: CTA semantics.** "Start workspace" disabled while resolution is stale/finding-present (identical contract to the modal). Enter anywhere in the form submits when enabled. On 201: invalidate `['workspace-registry']`, activate, navigate into the workspace view (same post-create posture as the modal's `onCreated`).
- **D-5: Chip row behavior.** Sole registered project ⇒ its chip preselected. `presetProjectKey` (from the per-project entry point) preselects. **add existing** (dashed) and **new project** open `NewProjectModal`; on its `onCreated`, the new project's chip appears selected. Overflow beyond ~5 chips collapses into the **more projects** menu.
- **D-6: Idea cards are static presets in v1.** A fixed list of 6 (eyebrow → prefill): AUTOMATE, DELEGATE, EXPLORE, BUILD, PLAN, DESIGN — each sets the title to its example text and focuses the hero for editing. No model calls, no memory reads in v1; a memory-driven variant is a named non-goal/future.
- **D-7: Entry points navigate.** Sidebar `+`, palette action, and per-project button route to `/workspaces/new` (with `?project=<key>` for preset) instead of opening the modal. Deep-linkable and refresh-safe.
- **D-8: Debounce discipline unchanged** — ~300ms resolve debounce, fake-timer tested, resolve is already write-free (asserted in PAN-3330's suites; do not duplicate server tests here).
