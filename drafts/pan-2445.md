# PAN-2445 — Gate autonomous planning dispatch behind operator pickup posture; never staff it by silent role default

**Issue:** https://github.com/eltmon/overdeck/issues/2445
**Status:** draft (auto planning, 2026-07-17)

## Glossary

- **Reactive lifecycle scheduler** — `src/lib/cloister/service-reactive.ts`. Subscribes to domain events (`issue.transitioned`, `issue.statusChanged`, `issue.closed`, `agent.completed`, …), maps an issue's lifecycle state to a pipeline role (`stateToRole`), and dispatches that role. This is the deacon-side "lifecycle patrol" the issue refers to; boot reconciliation replays the same events on restart, so this path also fires on every dashboard boot.
- **Autonomous dispatch** — a spawn initiated by the scheduler/deacon with no operator action in the loop (as opposed to `pan plan`, the dashboard Start Planning button, or `pan start` auto-plan, which are operator-initiated).
- **Pickup posture** — the operator's standing answer to "may the system start new work by itself?": the global `flywheel.auto_pickup_backlog` flag (SQLite app_settings, read via `isFlywheelAutoPickupBacklog()` in `src/lib/database/app-settings.ts:184`) plus the per-issue `released` label (PAN-2059, `RELEASED_LABEL` in `src/lib/backlog/pickup.ts:32`). `parked`, `vetoed`, and `objection` labels halt pickup in both modes (`isAutoPickable`, `src/lib/backlog/pickup.ts:107`).
- **Recorded model** — the `model` field persisted in a prior plan-role agent state for the same issue (`agent-<issue>-plan` via `spawnRun`, or legacy `planning-<issue>` via the start-planning route — both naming schemes are live, see `.pan/context/codebase/concerns.md`).
- **Workhorse ref** — a `workhorse:<slot>` model reference dereferenced through `config.workhorses` by `derefWorkhorse()` (`src/lib/config-yaml/roles.ts:95`, exported).
- **Needs-you trip** — durable operator-attention record written by `recordDeadEndNeedsYou()` (`src/lib/cloister/dead-end-trip.ts`), backed by `recordRecoveryFailure()` (`src/lib/cloister/recovery-trip.ts`) with threshold 1: the first refusal emits, an already-open trip does not re-emit.

## Problem

`onIssueStateChangePromise` in `src/lib/cloister/service-reactive.ts:208` maps lifecycle state `in_planning` → role `plan` (`ROLE_RUN_STATES`, line 74–84) and dispatches it at line 304–307:

```ts
const { spawnRun } = await import('../agents.js');
const run = await spawnRun(normalizedIssueId, role, {
  prompt: buildReactiveRolePrompt(normalizedIssueId, newState, role),
});
```

Two gaps (per the operator's 2026-07-07 scope-reduction comment, this is preventive hardening — the original incident attribution was withdrawn):

1. **Posture bypass.** No `options.model` and no posture check: any issue whose tracker state lands on (or replays as) `in_planning` gets an autonomous planning spawn even when `auto_pickup_backlog` is off and the issue was never `released`. Lifecycle momentum bypasses the operator's pickup posture.
2. **Silent expensive staffing.** With no model passed, `determineModel({role:'plan'})` (`src/lib/agents/provider-env.ts:240`) falls through to `resolveModel('plan', …)` → `roles.plan` default `workhorse:expensive` (`src/lib/config-yaml/roles.ts:19,39`) — the most expensive model, chosen by nobody.

Operator-initiated planning paths (`pan plan` CLI → `spawnPlanningSession`, dashboard start-planning route, `agent-spawner.startPlanning` invoked by `pan start`) are NOT in scope — an operator is in the loop there and explicitly accepts `roles.plan` routing.

## Decision rules (made here, not left to the executor)

- **D1 — single wiring point.** The gate wires ONLY into the reactive scheduler's plan dispatch (the only autonomous fresh-planning spawn path; `deacon-auto-resume.ts` never spawns planning fresh — it only recovers existing sessions). Work/review/test dispatch is untouched.
- **D2 — posture predicate.** Autonomous plan dispatch is allowed iff `(autoPickupBacklog || labels include 'released')` AND labels include none of `parked` (or legacy parked labels), `vetoed`, `objection`. This mirrors the operative parts of `isAutoPickable`; `ready`/`planned`/`inPipeline`/`epic` are deliberately NOT copied — they gate *work* pickup of planned backlog items and are meaningless pre-planning (an issue in `planning` state is definitionally in-pipeline and unplanned).
- **D3 — fail closed on missing labels.** When issue labels cannot be determined (issue-service singleton not ready), refuse with code `labels-unavailable` — even when `autoPickupBacklog` is true, because parked/vetoed/objection cannot be verified. The needs-you trip makes the refusal visible; a later event retries naturally.
- **D4 — staffing precedence.** recorded model (either agent-state naming scheme) → `roles.plan.autonomousModel` config (new, optional, NO default) → refuse with code `no-autonomous-model` + needs-you. The role-default chain (`roles.plan.model` → `workhorse:expensive`) is never consulted for autonomous dispatch. A recorded model counts as operator-designated because the original spawn that recorded it was operator-initiated or already gated.
- **D5 — config key shape.** camelCase `roles.plan.autonomousModel` (matches `minAgents`/`reReviewScope` convention in `RoleConfig`, `src/lib/config-yaml/schema.ts:366`). Accepts the same scalar ModelRef grammar as `model` including `workhorse:<slot>`; dereferenced via exported `derefWorkhorse`. A dangling ref fails loudly at config validation, never silently at spawn. Explicitly setting it to `workhorse:expensive` is allowed — that is an operator designation, which is the whole point.
- **D6 — refusal surface.** Refusal emits an `emitActivityEntrySync` warn entry AND a durable needs-you trip via `recordDeadEndNeedsYou(issueId, 'autonomous-plan-dispatch', <generation>, <message>)`, mirroring the usage at `src/lib/cloister/deacon.ts:1927`. Use the lifecycle state string as the generation. The message must be operator-standalone: name the issue, say that autonomous planning dispatch was refused and why, and state what the operator can do (release the issue / enable auto-pickup / set `roles.plan.autonomousModel` / run `pan plan <id>` manually).

## Requirements

- **FR-1** — A pure decision function `decideAutonomousPlanDispatch(input)` in a new module `src/lib/cloister/autonomous-plan-dispatch.ts` returns `{ allow: true, model, modelSource: 'recorded' | 'autonomousModel' }` or `{ allow: false, code, reason }` with codes `not-released | parked | vetoed | objection | labels-unavailable | no-autonomous-model`, per D2–D4. Input: `{ autoPickupBacklog: boolean; labels: readonly string[] | null; recordedModel?: string; autonomousModel?: string; workhorses: NormalizedConfig['workhorses'] }`. Posture is checked before staffing (a not-released refusal reports `not-released` even when no model is available).
- **FR-2** — `RoleConfig` gains optional `autonomousModel` (scalar ModelRef). Validation rejects malformed refs and dangling workhorse slots with an error naming `roles.<role>.autonomousModel`. `DEFAULT_ROLES` gains NO default for it.
- **FR-3** — `onIssueStateChangePromise` gates `role === 'plan'` through the decision: gather inputs (flag via `isFlywheelAutoPickupBacklog()`; labels via the issue-service singleton using the same lazy-require pattern as `buildClassifyLookups`, `src/lib/backlog/lookups.ts:25`, yielding `null` when unavailable; recorded model via `getAgentState('agent-<lower>-plan')` then `getAgentState('planning-<lower>')`; config via `loadConfigSync()`), then either refuse per D6 (no spawn) or call `spawnRun(issueId, 'plan', { prompt, model: decision.model })`.
- **FR-4** — Regression tests: a unit matrix over the decision function (FR-1 cases) and reactive-scheduler wiring tests (refusal → no `spawnRun` + needs-you recorded; allow → `spawnRun` receives the resolved model; `in_progress`/work dispatch unchanged).
- **NFR-1** — No hardcoded model fallback anywhere in the new path (no-hardcoded-fallback rule): unresolvable staffing refuses loudly, it never picks a literal.
- **NFR-2** — Server-reachable code stays async: no `execSync`, no sync tmux primitives (existing repo rules; the new module needs neither).
- **NFR-3** — Fake timers for any delay-based test (repo rule); none of the planned tests should need real timers.

## Non-goals

- No gating of operator-initiated planning paths (`pan plan`, dashboard start-planning, `pan start` auto-plan).
- No gating of autonomous work/review/test dispatch staffing (separate issue if wanted).
- No order-book sequence-membership check beyond the `released`/auto-pickup posture — `released` IS the operator's per-issue go signal (PAN-2059); sequence rank ordering is a pickup-priority concern, not a permission concern.
- No dashboard Settings UI surface for `autonomousModel` (config.yaml only in this issue).
- No changes to `deacon-auto-resume` planning-session recovery (it resumes existing sessions, never spawns fresh).
