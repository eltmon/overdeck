# PAN-2619 — Terminal panel frame overflows its container (right columns + bottom tmux status bar clipped)

**Issue:** https://github.com/eltmon/overdeck/issues/2619
**Author:** planning agent (claude-fable-5), 2026-07-13, auto mode
**Status:** draft → proposed via `pan plan finalize`

## Glossary

- **XTerminal** — the single shared React component that instantiates xterm.js (`src/dashboard/frontend/src/components/XTerminal.tsx`). It is the ONLY place `new Terminal(` appears in the frontend (verified by grep), so every terminal surface (Stage TerminalPane, ConversationPanel terminal view, drawer, PlanDialog, AgentOutputPanel, flywheel pane) renders through it.
- **terminalRef container** — the div XTerminal mounts xterm into: `<div ref={terminalRef} className="absolute inset-0" style={{ padding: '8px', … overflow: 'hidden' }}>` (XTerminal.tsx:819-830).
- **FitAddon** — `@xterm/addon-fit@0.11.0`. `proposeDimensions()` computes cols/rows from `getComputedStyle(terminal.element.parentElement)` width/height, minus the **`.xterm` element's own padding**, minus scrollbar width (0 here, since `scrollback: 0`).
- **`.xterm` element** — the div xterm.js creates inside the container on `term.open(container)`. `terminal.element.parentElement` === the terminalRef container.
- **content box vs border box** — with Tailwind preflight's global `box-sizing: border-box`, the container's 8px padding is inside its measured box.

## Root cause (empirically confirmed on the live dashboard, 2026-07-13)

Playwright measurement against `http://localhost:3011/conv/831` (tmux session `conv-20260712-5514` — the exact session in the issue screenshot), viewport 1728×1000:

| Element | rect |
| --- | --- |
| terminalRef container (border box) | 848 × 828 @ (580, 172); computed style `width: 848px, height: 828px, padding: 8px, box-sizing: border-box` |
| container content box | 832 × 812 |
| attach message sent | `cols=106, rows=51` (console: "Sending attach dimensions: 106 x 51") |
| `.xterm-screen` | **848 × 816** @ (588, 180) → right edge 1436 > container right 1428 |

- Cell size is 8×16 px. 106 × 8 = **848** = the container's **full border-box width including padding**; 51 = floor(828/16) from the full border-box height.
- Correct values for the visible content box are floor(832/8) = **104** cols and floor(812/16) = **50** rows.
- So the grid is 2 columns wider and 1 row taller than the visible area. The container's `overflow: hidden` clips the excess: rightmost column glyphs are cut (issue: `table` renders as `tab`) and the bottom row — tmux's status bar — is half-clipped.

**Why FitAddon over-measures:** FitAddon reads the parent's computed width/height (which, for this absolutely-positioned border-box element, resolve to the border box — empirically 848/828 with the padding included) and subtracts padding **only from the `.xterm` element** (`elementPadding` in `FitAddon.ts`). Our 8px padding sits on the *parent* (terminalRef), where FitAddon never subtracts it. The PTY/tmux side happily honors the oversized cols/rows, so nothing reflows — the overflow is just clipped. This is the exact scenario xterm.js documents: padding must live on the `.xterm` element (where FitAddon accounts for it), never on the measured parent.

`/ws/terminal` resize plumbing (`sendResizeIfNeeded`, ResizeObserver + 200ms debounce, window resize listener) is correct; it faithfully transmits the wrong measurement.

## Fix (decided)

Move the 8px padding from the terminalRef container's inline style to the `.xterm` element via CSS:

1. **`src/dashboard/frontend/src/components/XTerminal.tsx`** — delete `padding: '8px',` from the terminalRef inline style (line ~825) and add a scoping class `xterm-host` to that div's className.
   - Before: `<div ref={terminalRef} className="absolute inset-0" … style={{ padding: '8px', backgroundColor: …, overflow: 'hidden', outline: 'none' }} />`
   - After: `<div ref={terminalRef} className="absolute inset-0 xterm-host" … style={{ backgroundColor: …, overflow: 'hidden', outline: 'none' }} />`
2. **`src/dashboard/frontend/src/index.css`** — add, near the existing `.terminal-output` rule (line ~195):
   ```css
   /* Padding must live on .xterm itself, NOT the measured parent: FitAddon
      subtracts the .xterm element's padding but measures the parent's box.
      Padding on the parent double-counts as usable grid space and clips the
      rightmost columns + bottom (tmux status bar) row. (PAN-2619) */
   .xterm-host .xterm {
     padding: 8px;
   }
   ```

Post-fix arithmetic (same 848×828 container): FitAddon available = 848−16 = 832 wide, 828−16 = 812 tall → 104 cols × 50 rows → `.xterm-screen` 832×800, fully inside the content box with the status bar row fully visible. Keep the container's inline `backgroundColor` — it paints the padding area identically in both themes (xterm's canvas only paints the grid).

Rejected alternatives:
- Subtracting the padding manually in `getMeasuredSize()` — re-implements FitAddon's contract in our code and leaves `fit()` itself (which XTerminal also calls) using the wrong math.
- Wrapping in an extra unpadded inner div — works but adds a DOM layer when FitAddon already supports element padding natively.

## Requirements

- **FR-1** — The xterm grid must fit entirely inside the terminalRef container's content box: rightmost column fully visible, bottom (tmux status bar) row fully visible.
- **FR-2** — `cols`/`rows` sent over `/ws/terminal` attach/resize messages must equal the fitted visible grid (tmux pane size == visible grid).
- **FR-3** — FR-1/FR-2 must hold across window resizes and Awareness-rail open/closed toggles (ResizeObserver path re-fits).
- **NFR-1** — A unit regression test must fail if inline padding is reintroduced on the measured container.
- **NFR-2** — No visual change to padding size (stays 8px) or padding-area color in either theme.
