# PAN-3076 — Polyrepo verdict anchors: composite HeadAnchor for the 5 wrapper-blind stamp/compare sites

**Issue:** https://github.com/eltmon/overdeck/issues/3076
**Planned:** 2026-07-25 (auto mode). All file/line references verified against `feature/pan-3076` @ `82a66ba835`.

## Glossary

- **Polyrepo workspace** — a workspace whose root is a one-commit **wrapper repo** (artifacts only; its HEAD never moves) containing one or more **sub-repo** worktrees (e.g. `fe/`, `api/`). Roots are enumerated by `resolveWorkspaceRepoRootsSync(issueId, workspacePath)` in `src/lib/project-repos.ts:169`, returning `WorkspaceRepoRoot { repoKey, dir, sourceBranch, targetBranch, isPolyrepo }` (`src/lib/project-repos.ts:129`).
- **Anchor** — a stored string identifying "the code state a verdict was issued against". Today three fields hold anchors: `reviewedAtCommit`, `lastVerifiedCommit` (review-status plane; wire type `Schema.optional(Schema.String)` at `packages/contracts/src/types.ts:381`) and `roleRunHead` (`src/lib/agents/agent-state.ts:113`).
- **Composite anchor** — the polyrepo anchor form `fe@<sha> api@<sha>` produced by the **producer**.
- **Producer** — `snapshotWorkspaceHeadsPromise(issueId, workspacePath)` in `src/lib/git-utils.ts:361`: monorepo → single full SHA; polyrepo → composite anchor over sub-repo heads (wrapper excluded).
- **Parser** — `parseCompositeSnapshot(snapshot)` — today a *private* function in `src/lib/cloister/inspect-checkpoints.ts:119` returning `Map<repoKey, sha>` (plain single SHA → empty map). A second, stricter parser `parseWorkspaceHeadAnchor` exists at `src/lib/git-utils.ts:278` (throws on malformed; used only to validate anchors before shelling out to `git show`).
- **Stamp site** — code that writes an anchor field. **Compare site** — code that reads an anchor field and compares it against a freshly probed HEAD.
- **Wrapper-blind** — a stamp or compare site that runs `git rev-parse HEAD` at the workspace *root*, which in a polyrepo is the frozen wrapper SHA.
- **Benign move** — a HEAD change that must NOT invalidate verdicts: tree-identical rebase (`^{tree}` equal), state-plane-only commits (`haveSameEffectiveCodeCommit`, `src/lib/pipeline-state-paths.ts:56`), or a rebase with identical patch-id contribution (`haveSameCodeContribution`, `src/lib/pipeline-state-paths.ts:79`).

## Problem

PAN-2948 fixed the READ side of polyrepo anchors (manifests, dispatch, drift anchors) and converted *some* stamp sites to the producer (`src/lib/cloister/deacon-review-status.ts:514,544`, `src/lib/cloister/verification-runner.ts:882`, `src/cli/commands/specialists/done.ts:146`). Because an anchor is a plain `string`, a composite anchor and a wrapper SHA are silently interchangeable, so the remaining wrapper-blind sites produce two failure modes (MIN-901 evidence, confirmed by independent Opus and Kimi K3 source passes):

1. **Compare sites probing the wrapper against a composite anchor never see equality** → infinite review reset + convoy re-dispatch. MIN-901 logged 56 `Reset review` cycles over 3h44m, all showing `(fe@52d65 → 7492ae82)` — a composite `.substring(0,8)` versus a wrapper SHA.
2. **Stamp sites writing the wrapper SHA make the compare always-equal** → post-review sub-repo commits NEVER invalidate a passed review; unreviewed code ships green.

Fixing one side without the other only changes which failure mode fires — the five sites must convert together.

**Degraded sites (in scope — see D1):**

## Decisions (made here, not left to the executor)

- **D1 — Degraded sites are in scope.** G1/G2 are part of the same coupled cluster, listed in the issue body, and convert to the same producer with small diffs. They ship in this issue.
- **D2 — Brand placement.** `export type HeadAnchor = string & { readonly __headAnchor: unique symbol }` lives in `src/lib/git-utils.ts` next to the producer. The producer's return type becomes `Promise<HeadAnchor | undefined>`. The **contracts Schema stays `Schema.String`** — branding the wire type would ripple into the frontend and every deserializer for zero enforcement value (stored values re-enter as plain strings anyway).
- **D3 — Enforcement at the write door, cast at rehydration.** The review-status write-door update types narrow `reviewedAtCommit`/`lastVerifiedCommit` to `HeadAnchor | undefined` so a raw `stdout.trim()` no longer typechecks. Paths that *copy* an already-stored anchor between planes (record mirror `src/lib/pan-dir/record.ts:166`, reconcile `src/lib/review-status-reconcile.ts:48`, history restore) use a single greppable escape hatch `rehydrateHeadAnchor(value: string): HeadAnchor` defined next to the brand, documented as "only for values previously written by the producer". `roleRunHead` keeps a plain-string storage type (its interface is deserialized in ~6 mappers) and is enforced by the write-site scan test (WI-9) instead.
- **D4 — One canonical lenient parser.** `parseCompositeSnapshot` moves to `src/lib/git-utils.ts` as an export (same lenient `Map<repoKey, sha>` semantics, plain SHA → empty map); `inspect-checkpoints.ts` deletes its private copy and imports it. The strict `parseWorkspaceHeadAnchor` (`git-utils.ts:278`) is NOT merged into it — it validates anchors before shelling out to `git show` and must keep throwing on malformed input.
- **D5 — Mixed legacy anchors reset once, conservatively.** When a stored anchor and the current snapshot are of different shapes (plain wrapper SHA vs composite), the drift evaluator returns `drifted` (full re-review). This self-heals: the reset clears the anchor, the fixed stamp sites write a composite on the next pass, and the comparison is stable thereafter. No permanent loop is possible because both sides then come from the same producer.
- **D6 — roleRunHead switches from short-8 wrapper SHA to the full producer anchor.** Persisted pre-fix values will compare unequal exactly once post-deploy, marking those sessions stale — the safe direction (at most one redundant respawn; the alternative, never firing, is the current polyrepo bug).
- **D7 — runId derivation for polyrepo.** One helper `deriveReviewRunHead8(issueId, workspace): Promise<string>`: monorepo → `git rev-parse --short=8 HEAD` of the single root (unchanged); polyrepo → first 8 hex of `sha1(compositeAnchor)`. Used by BOTH the runId construction (`review-agent.ts:546-555`) and the staleness probe (`:362-372`) so stamp and compare cannot diverge.
- **D8 — No grep CI guard on `git rev-parse HEAD`** (many legitimate per-repo uses). Enforcement is the type brand plus a *targeted* write-site scan test on the three anchor fields (WI-9).
- **D9 — Per-repo base ref.** Per-repo benign-move checks pass `origin/${root.targetBranch}` as `baseRef` to `haveSameCodeContribution` — the `origin/main` default is wrong for sub-repos with a different target branch.

declare const headAnchorBrand: unique symbol;
/** A workspace head anchor written by snapshotWorkspaceHeadsPromise — either a
 * single full SHA (monorepo) or a composite `fe@<sha> api@<sha>` (polyrepo).
 * Git helpers must not accept it as a plain ref; stamp sites must not fabricate it. */

}

### WI-2 — Drift evaluator (FR-2)

**Files:** new `src/lib/workspace-anchor-drift.ts`, new `tests/unit/lib/workspace-anchor-drift.test.ts`.

```ts
export type AnchorDriftVerdict =
  | { kind: 'current'; currentAnchor: HeadAnchor }
  | { kind: 'benign'; currentAnchor: HeadAnchor }
  | { kind: 'drifted'; currentAnchor: HeadAnchor; changedRepos: string[] }
  | { kind: 'unreadable' };

export async function evaluateWorkspaceAnchorDrift(
  issueId: string,
  workspacePath: string,
  storedAnchor: string,
): Promise<AnchorDriftVerdict>
```

Logic (decision rules — no judgment left):
1. `current = await snapshotWorkspaceHeadsPromise(issueId, workspacePath)`; `undefined` → `unreadable`.
2. `storedAnchor === current` → `current`.
3. Parse both with `parseCompositeSnapshot`. Both maps empty (two plain SHAs) → single-repo path: run today's benign checks at `workspacePath` (`^{tree}` equality, then `haveSameEffectiveCodeCommit`, then `haveSameCodeContribution`) — benign → `benign`, else `drifted` with `changedRepos: []`. Any check that throws falls through to the next; all throwing → `drifted` (matches today's "safer than skipping" comment at `deacon.ts:1622`).
4. Shape mismatch (one map empty, one not) → `drifted` with `changedRepos` = keys of the non-empty side (D5).
5. Both composite: key sets differ → `drifted`. For each key with differing SHAs, resolve `root = resolveWorkspaceRepoRootsSync(issueId, workspacePath)` entry by `repoKey` (missing root → `drifted`) and run the same benign checks in `root.dir` with `baseRef = 'origin/' + root.targetBranch` (D9). Every changed repo benign → `benign`; else `drifted` listing the non-benign repos.

Tests use real temp git repos (mkdtemp + `git init`); mock `resolveWorkspaceRepoRootsSync` via `vi.mock` the way `tests/unit/lib/cloister/deacon-stash-janitor.test.ts` stubs workspace geometry. No delay-based logic → no fake timers needed. Cover: equal composite, one-repo drift, tree-identical rebase in one repo → benign, shape mismatch → drifted, unreadable workspace.

**AC:** the five behaviors above each have a named passing test; `npx vitest run tests/unit/lib/workspace-anchor-drift.test.ts` green.
