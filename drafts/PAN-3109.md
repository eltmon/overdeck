# PAN-3109 — DoD close-out gate blind to non-PR-path landings

**Issue:** https://github.com/eltmon/overdeck/issues/3109
**Author:** planning agent (claude-fable-5), 2026-07-26, auto mode

## Glossary

- **DoD gate** — the mechanical Definition-of-Done audit run by `pan close` / close-out. Eight rows (`DOD_ROWS` in `src/lib/lifecycle/dod.ts:21-60`); each row check lives in `src/lib/lifecycle/dod-gate.ts` and returns `pass | miss | skip`. A `miss` blocks close-out unless the operator passes `--accept-<row>`.
- **Row 4 (`merged`)** — "Merged to main". Checked by `checkMergedRow` (`src/lib/lifecycle/dod-gate.ts:236-294`).
- **Row 5 (`post-merge`)** — "Post-merge lifecycle ran". Checked by `checkPostMergeRow` (`src/lib/lifecycle/dod-gate.ts:296-325`). Passes only when canonical state is `verifying_on_main` (or `mergeStatus === 'merged'`) AND no work/plan agents are running.
- **Membership resolver** — `resolvePipelineMembership` in `src/lib/pipeline-membership.ts:99-174`, the single authoritative classifier of "is this issue in the pipeline". Pure function over `IssueLensSignals`.
- **Membership gather** — `gatherProjectLensSignals` in `src/lib/pipeline-membership-gather.ts:299-469`, which computes the lens signals from git/forge/tracker.
- **L2-work / branch-containment lens (PAN-2887)** — the gather's positive non-PR merge evidence: a convention branch whose tip is (a) **contained** in the repo's default branch (`git for-each-ref --no-merged=<default>` does NOT list it) and (b) **off the default branch's first-parent line** (`git rev-list --first-parent <default>` does not contain the tip SHA). (a)+(b) ⇒ the branch's unique commits arrived via a merge — work landed without a PR. A contained tip ON the first-parent line is just a pointer at main (fresh branch, zero unique work).
- **Convention branch** — `feature/<issue-id-lowercase>` or `strike/<issue-id-lowercase>`, local or `origin/` remote.
- **Non-PR landing** — branch work that reached main without a merged PR the forge can report (merge-agent direct merge, GitLab-side merge, manual merge). MYN is GitLab+Linear, so its `LifecycleContext.github` is unset and no GitHub PR oracle exists at all.
- **Polyrepo wrapper** — a project whose `workspace.repos[]` in `projects.yaml` lists sub-repositories under `project.path`. For MYN, `project.path = /home/eltmon/Projects/myn` is **not itself a git repository**; the six sub-repos (frontend, api, infra, docs, myn-skills, openclaw-plugin) are.
- **`projectRepositories`** — private helper in `src/lib/pipeline-membership-gather.ts:284-296` mapping a `ProjectConfig` to its list of `{ path, defaultBranch }` repositories (the sub-repos for polyrepo projects, else the project root; default branch from config, falling back to `main`).

## Problem

Four MYN issues (MIN-305, MIN-794, MIN-872, MIN-873) sit permanently in `post_merge_limbo`: the membership resolver classifies them "branch work is contained in main but with no merged PR — landed via a non-PR path; run close-out" (`src/lib/pipeline-membership.ts:154`), but `pan close MIN-305 --force` fails the DoD gate with 5 misses including `merged` and `post-merge`. The gate's own remedy is refused by the gate.

### Verified failure mechanism (checked live 2026-07-26)

1. `closeOut` calls `evaluateDodGate` with `verifyMerged: verifyBranchMergedImpl` (`src/lib/lifecycle/workflows.ts:175-178`).
2. `verifyBranchMergedImpl` (`src/lib/lifecycle/workflows.ts:491-600`) runs every git command in `ctx.projectPath` = `/home/eltmon/Projects/myn` — **which is not a git repo** (`git rev-parse` there: "fatal: not a git repository"). `git branch --list … || true` and `git ls-remote … || true` both yield empty, so it returns `BRANCH_ABSENT_MERGE_ERROR` (`src/lib/lifecycle/workflows.ts:596`, constant at `src/lib/lifecycle/dod.ts:70`).
3. `checkMergedRow` then consults two fallbacks (`src/lib/lifecycle/dod-gate.ts:281-291`): durable close-out merge records (empty — nothing ever merged through the pipeline) and forge PR state (`ctx.github` is unset for MIN issues ⇒ none). Row 4 misses.
4. Row 5 misses downstream: post-merge lifecycle never ran for a landing the system never observed, so canonical state is not `verifying_on_main` (`src/lib/lifecycle/dod-gate.ts:315`).
5. Meanwhile the membership gather iterates `projectRepositories(project)` — the **sub-repos** — and finds e.g. `feature/min-873` in `frontend` contained in main with tip off the first-parent line (verified live: contained=yes, tip-on-first-parent=no) ⇒ `hasMergedBranchWork` ⇒ `post_merge_limbo`.

The two doors disagree about one fact because row 4 never runs the containment lens and never looks at the project's configured repositories — it only sees the (repo-less) wrapper.

## Proposal

Teach row 4 a branch-containment fallback that **reuses** the membership gather's L2/L2-work computation (extracted, not forked), evaluated over `projectRepositories(project)` — and let row 5 accept the resulting "non-PR landing" evidence with its agent-quiescence half still enforced.

Pass condition for the fallback, mirroring resolver precedence exactly (`branchLive` wins over merged-work, `src/lib/pipeline-membership.ts:102,146-155`): **at least one convention-branch ref classifies as merged-work AND zero refs classify as unmerged**, across all of the project's repositories.

Rows 1–3 (review/tests/verification) legitimately never ran for these landings and stay operator `--accept-*` territory. Rows 6–7 keep today's behavior (no merge commit resolvable ⇒ `main-verify` skips per `src/lib/lifecycle/dod-gate.ts:332-338`; `deploy` skips for MYN because the live dashboard serves a different repoRoot, `src/lib/lifecycle/dod-gate.ts:375-377`).

## Requirements

- **FR-1** A single, shared implementation of the branch-containment classification (contained / merged-work / pointer-only vs unmerged) exists in `src/lib/pipeline-membership-gather.ts`, used by BOTH `gatherProjectLensSignals` and a new issue-scoped helper. No second copy of the git logic in `dod-gate.ts`.
- **FR-2** A new exported `gatherIssueBranchContainment(project, issueId, run?)` returns, for one issue across all `projectRepositories(project)`, the refs classified as `unmergedRefs`, `mergedWorkRefs`, and `pointerRefs`, using the identical git commands the gather uses (`for-each-ref` over the issue's `feature/`+`strike/` local+`origin/` refs, `for-each-ref --no-merged=<defaultBranch>`, `rev-list --first-parent <defaultBranch>`).
- **FR-3** `checkMergedRow` runs the containment fallback whenever the row is still `miss` after the existing verify-step / durable-record / forge-PR evidence, and flips to `pass` iff `mergedWorkRefs.length > 0 && unmergedRefs.length === 0`. The observed string names the evidence (refs and repos). A containment-lens error appends to `observed` and leaves the row `miss`.
- **FR-4** The merged row result carries `evidence: 'branch-containment'` when (and only when) the fallback produced the pass. `mergedAt`/`mergeCommit` stay unset for containment passes (no fabricated merge metadata).
- **FR-5** `checkPostMergeRow` accepts the merged row result; when its `evidence` is `'branch-containment'` and the lifecycle was not observed, the row passes iff no work/plan agents are running for the issue, with an observed string stating the post-merge lifecycle is not applicable to a non-PR landing. All other paths unchanged.
- **FR-6** Row 4's `expected` text in `DOD_ROWS` (`src/lib/lifecycle/dod.ts:31`) mentions the containment alternative so operator output is self-explanatory.
- **FR-7** `docs/DEFINITION-OF-DONE.md` (rows 4–5) and `docs/PIPELINE-MEMBERSHIP.md` (lens reuse note) document the fallback. The dod-doc-drift test (`tests/unit/lib/lifecycle/dod-doc-drift.test.ts`) stays green.
- **NFR-1** Membership resolver/gather classification behavior is unchanged — the refactor is extract-and-reuse only; all existing `pipeline-membership-gather.test.ts` and `pipeline-membership-audit.test.ts` tests pass unmodified.
- **NFR-2** All new git invocations go through the gather's async `run` dep pattern (promisified `execFile`); no `execSync` (server-reachable code).

## Design decisions (made here — do not re-litigate downstream)

- **D1 — Lens home.** The shared helpers live in `src/lib/pipeline-membership-gather.ts` (the canonical gather door), not a new module: export the currently-private `ProjectRepository` type + `projectRepositories`, extract the per-repo snapshot (the three git commands at lines 314-334) into `snapshotBranchRefs(repoPath, defaultBranch, refPatterns, run)`, and the per-ref classification (lines 392-411) into a pure `classifyBranchRefLine(line, unmergedSet, firstParentShas)` returning `'unmerged' | 'merged-work' | 'pointer'`. `gatherProjectLensSignals` calls them with the existing wildcard patterns; `gatherIssueBranchContainment` calls them with issue-scoped patterns (`refs/heads/feature/<id>`, `refs/remotes/origin/feature/<id>`, `refs/heads/strike/<id>`, `refs/remotes/origin/strike/<id>`, id lowercase).
- **D2 — Failure semantics.** `gatherIssueBranchContainment` propagates git failures (same as the batch gather); `checkMergedRow` catches, appends `branch containment evidence unavailable: <msg>` to observed, and keeps `miss`. No per-repo partial tolerance in v1 (recorded as a hazard).
- **D3 — Dep injection.** `MergedRowDeps` gains optional `readBranchContainment?: (ctx) => Promise<IssueBranchContainment>`; the default resolves the project via `resolveProjectForIssue(ctx.issueId) ?? getProjectConfigFromWorkspacePath(ctx.projectPath)` (the same chain `readDurableMerges` uses at `src/lib/lifecycle/dod-gate.ts:74-77`) and returns empty containment (`{unmergedRefs: [], mergedWorkRefs: [], pointerRefs: []}`) when no project resolves — empty evidence never flips the row.
- **D4 — Row-5 threading.** `EvaluateDodGateDeps.postMerge` signature becomes `(ctx, merged?: MergedDodRowResult)`; `evaluateDodGate` (already awaits `merged` first, `src/lib/lifecycle/dod-gate.ts:418-428`) passes it. `checkPostMergeRow` gains the optional second parameter. Sole production caller is `closeOut` in `workflows.ts` via defaults, so the change is contained.
- **D5 — No fabricated merge commit.** Deriving the merge commit that carried a non-PR landing (for rows 6–7) is explicitly out of scope; those rows keep their existing skip/miss semantics.

## Hazards

- **H1** Fast-forward landings remain indistinguishable from fresh pointers (known PAN-2887 blind spot, `src/lib/pipeline-membership.ts:159-161`) — they classify `pointer`, row 4 stays miss, operator `--accept-merged` remains the escape. Do not "fix" this here.
- **H2** A repo path that is not a git repository makes `gatherIssueBranchContainment` throw (D2) — for polyrepo projects all configured sub-repo paths exist, but a misconfigured repo denies containment evidence; row simply stays miss with the error in observed.
- **H3** `rev-list --first-parent <default>` walks full history per repo; acceptable for a one-shot close-out CLI (the gather already runs it per membership resolution) — do not add caching.
- **H4** Related but distinct: [#2828](https://github.com/eltmon/overdeck/issues/2828) (`pan done --strike` ancestry vs squash-merge) is the same blind-spot family at a different site — NOT addressed here.
