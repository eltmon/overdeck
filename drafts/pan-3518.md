## Glossary

- **Re-review cycle** — after a blocked review and rework, the convoy re-runs. Each lane either **resumes** its prior session (full accumulated history rides along) or spawns fresh.
- **Lane** — one convoy sub-role (`correctness`, `security`, `performance`, `requirements`).
- **Warm window** — the provider-side lifetime of a cached prompt prefix: ~5–10 min for OpenAI (via CLIProxy), 5 min default for Anthropic. Inside it, a resume's first request reads most of its history from cache. Outside it, the first request re-bills the entire history at uncached input price.
- **Cold resume** — a resume whose last session activity is older than the warm window. Today this is nearly every re-review: rework takes 40 min – 11 h (measured 2026-08-02).
- **Digest re-review** — a **fresh** session whose prompt carries a curated digest instead of the accumulated history: the lane's prior verdict report, the changed-files list since the prior verdict, and the existing Tier-1 context-manifest summary.
- **Tier-1 summary** — the compact render of the review context manifest already inlined into convoy prompts (`formatTier1Summary`, used at `src/lib/cloister/review-convoy.ts:182-192`).
- **`atCommit` anchor** — the HEAD commit a prior verdict was issued against, stored per lane in review status (`reviewerVerdicts[role].atCommit`); already used by `computeConvoyScope` (`review-convoy.ts:360-377`) to diff for selective re-review.

## The problem, measured

`reviewResumeDecision` (`src/lib/cloister/review-resume-decision.ts:12-25`) is deliberately simple — resume whenever a saved session exists and harness/model are unchanged:

```ts
export function reviewResumeDecision(params: {
  requestedModel?: string; requestedHarness?: string;
  savedModel?: string; savedHarness?: string;
  hasSavedState: boolean; hasSavedSession: boolean;
}): boolean {
  const modelChanged = !!params.requestedModel && !!params.savedModel && params.requestedModel !== params.savedModel;
  const harnessChanged = !!params.requestedHarness && !!params.savedHarness && params.requestedHarness !== params.savedHarness;
  return params.hasSavedState && params.hasSavedSession && !modelChanged && !harnessChanged;
}
```

It has no notion of cache temperature or history size. Production evidence (2026-08-02, PAN-3410 correctness lane, one day): five resume boundaries re-billed 96k, 136k, 171k, 209k, and 142k uncached input tokens respectively (~755k for one lane in one day; ≈3M/day across four lanes of one issue). Because provider TTLs are minutes and rework cycles are hours, the "resume preserves warm cache" assumption that motivated PAN-1862's resume rule never holds in practice. The resume's continuity has genuine review-quality value — the reviewer remembers its own reasoning and checks the fix — but past the warm window that continuity is bought at full price every cycle, while the lane's prior *report* (which persists the verdict and findings, at `.pan/review/<runId>/<subRole>.md` via `reviewerAgentOutputPath`, `review-convoy.ts:73-75`) already carries most of what a re-review needs.

## Requirements

- **FR-1** — The resume-vs-fresh decision for convoy lanes MUST become temperature- and size-aware, with three possible plans: `resume`, `digest` (fresh spawn with digest prompt), or `fresh` (plain fresh spawn — today's fallback when no session exists or model/harness changed).
- **FR-2** — The decision MUST remain a pure, test-locked function. All IO (session usage tail, prior-report discovery, config) happens in the caller and is passed in as values.
- **FR-3** — The digest prompt MUST inline: (a) the lane's most recent prior report file content, (b) the changed-files list since that report's `atCommit` anchor (or since the single common anchor, reusing `computeConvoyScope`'s diff), and (c) the Tier-1 summary when a manifest exists. It MUST instruct the reviewer to verify the rework against the prior findings rather than re-research the whole diff, and MUST name the same output file path as a normal cycle.
- **FR-4** — A `digest` plan spawn MUST NOT fork from the parent and MUST clear any stale fork-cache-scope marker (PAN-3517 machinery already removes the marker on fresh spawns — this FR is a cross-check, not new code). When the synthesis parent has a live session id and the lane's provider is non-Anthropic, the digest spawn SHOULD export the convoy cache-scope header with the parent's session id so all four digest lanes share one CLIProxy cache cohort and their byte-identical digest prefixes cross-hit.
- **FR-5** — All three policy parameters MUST be operator-configurable under `roles.review.*` with validation: `resume_warm_window_ms` (default **300000** — 5 min, the conservative end of the observed TTL range), `resume_max_cold_history_tokens` (default **60000**), `digest_rereview_enabled` (default **true**).
- **FR-6** — Every cycle MUST emit one log line per lane naming the chosen plan and the inputs that decided it: `[review-agent] Re-review payload plan for <issue>/<lane>: <resume|digest|fresh> (history=~<N>k tokens, idle=<M>m, priorReport=<yes|no>)`.
- **FR-7** — The quick-review **parent** path (`review-agent.ts:680`) MUST be behaviorally unchanged by this PRD (parent continuity feeds synthesis; revisiting it is future work). Signature changes to `reviewResumeDecision` MUST be backward-compatible for that caller.
- **NFR-1** — `digest_rereview_enabled: false` restores today's behavior exactly (resume always, when eligible).
- **NFR-2** — No new DB columns, no tracker writes, no changes to `computeConvoyScope`'s lane-selection semantics (it only *exposes* data it already computes).
- **NFR-3** — History-size estimation is approximate (last usage record's `input + cache_read + cache_creation` tokens). No tokenizers, no full-file parses — read the session JSONL tail only.

## Decisions (made in this document)

- **D-1 — Decision matrix** (evaluated in order; first match wins; "eligible" = `hasSavedState && hasSavedSession && !modelChanged && !harnessChanged` as today):
  1. Not eligible → `fresh` (unchanged current behavior).
  2. Eligible, and (idle ≤ warm window) → `resume` — cache plausibly warm; with PAN-3517 the family cohort header is re-exported.
  3. Eligible, and (`historyTokens` unknown or ≤ max cold history) → `resume` — continuity is cheap.
  4. Eligible, and no prior report found → `resume` — nothing to digest from; continuity is irreplaceable.
  5. Eligible, `digest_rereview_enabled`, idle > warm window, history > max, prior report exists → `digest`.
  6. `digest_rereview_enabled: false` → rows 1–4 only (today's behavior).
- **D-2 — One pure planner, thin IO wrapper.** New exported function `planConvoyReReview(params)` in a new file `src/lib/cloister/review-rereview-plan.ts`, returning a discriminated union `{ kind: 'resume' } | { kind: 'digest' } | { kind: 'fresh' }` plus the deciding inputs for logging. `reviewResumeDecision` keeps its signature (the parent caller is untouched, FR-7); the planner *uses* it for row-1 eligibility. `spawnReviewSubRoleForIssuePromise` gathers the IO and calls the planner where it currently inlines the resume decision (`review-convoy.ts:209-248`).
- **D-3 — Config-only knobs, no per-issue record override in v1.** `reReviewScope` has a per-issue override path (`readIssueRecordSync`, `review-convoy.ts:684-689`); the payload policy does not need one yet. Adding it later is additive.
- **D-4 — Idle time and history size come from the session JSONL tail**, not the DB and not agent state: the last `message.usage` record gives both the last-activity timestamp and a token count that *is* the prompt size the next request would re-bill. Missing/unreadable file ⇒ "unknown" ⇒ matrix row 3 (resume) — never a new failure mode.
- **D-5 — The digest spawn reuses the existing convoy prompt skeleton** (`buildConvoyPrompt`, `review-convoy.ts:79-135`) with two inserted sections (prior report, changed files) rather than a parallel prompt format — one format for synthesis and deacon tooling to consume.
- **D-6 — Changed-files list is best-effort.** `computeConvoyScope` already degrades to "unknown drift ⇒ all lanes run" on anchor failure (`review-convoy.ts:376`); in the digest prompt a missing list is rendered as "changed files unknown — review the full diff" rather than failing the spawn.
