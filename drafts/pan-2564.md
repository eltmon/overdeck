## 1. Glossary (defined before use)

- **beads / `bd`** — the issue tracker CLI (github.com/steveyegge/beads), installed at `/home/eltmon/.local/bin/bd`, version **1.0.4**. Overdeck's per-issue tasks ("beads") live here.
- **Dolt** — a version-controlled SQL database ("Git for data"). As of `bd 1.0.4` it is the **only** supported beads storage backend (`bd init`: *"Dolt is the default (and only supported) storage backend. The legacy SQLite backend has been removed."*).
- **embedded mode** — default `bd` mode: an in-process Dolt engine with data under `.beads/embeddeddolt/`. No external server. Each `bd` write creates a Dolt commit when `dolt.auto-commit=on`.
- **server mode** — `bd init --server`: an external `dolt sql-server`; data under `.beads/dolt/`. Auto-commit defaults OFF.
- **`refs/dolt/data`** — the git ref namespace where Dolt stores its data when a git remote is configured as a Dolt remote. It is **separate from `refs/heads/*`** (normal branches). It travels over the *same* git remote as the code but is not a branch and never merges into one.
- **Dolt remote** — a push/pull target for Dolt history, configured via `bd dolt remote add <name> <url>`. For Overdeck the URL is the project's own git remote as `git+ssh://…`, so Dolt history publishes to `refs/dolt/data` on that remote.
- **`bd bootstrap`** — non-destructive setup/recovery. Detection order (verbatim from `bd bootstrap --help`): sync.remote configured → clone from remote; git origin has `refs/dolt/data` → clone from git; `.beads/backup/*.jsonl` → restore; `.beads/issues.jsonl` → import; no DB → create fresh; DB exists → validate. Flags: `--dry-run`, `--yes`/`--non-interactive`, `--json`.
- **auto-export** — `bd` default: *"After every write command, bd exports issues to `.beads/issues.jsonl` (throttled to once per 60s)."* Disable: `bd config set export.auto false`.
- **`issues.jsonl`** — a **derived export** of the issues table only. Verbatim: *"JSONL exports contain issue records from the issues table … they do not capture Dolt branches, full commit history, working-set state, or non-issue tables."* Not authoritative.
- **`no-db: true`** — a *removed* legacy beads mode that made `issues.jsonl` the source of truth with no database. `bd 1.0.4` exposes no such flag; it survives only as a stale string in some `.beads/config.yaml` files. **Not a supported configuration.**
- **`.beads/redirect`** — a file whose contents are the path to another repo's `.beads/`; makes a worktree share the main/state repo's single Dolt DB. Gitignored.
- **read door / write door** — Overdeck's single-source-of-truth tenet: each domain has exactly one canonical resolver (read) and one canonical writer (write). Beads must have exactly one of each.
- **`overdeck-state`** — the orphan git branch (checked out at `${OVERDECK_HOME}/state/<project>/`) holding Overdeck pipeline state (records, specs, drafts, continues). It carries `issues.jsonl` today; after this change it carries only the *derived* export, never the Dolt DB.
- **Machine A/B/C scenario** — A creates beads; B implements and closes some; C opens the issue view and must see B's closures. The driving requirement.

## 2. Problem

Beads `1.0.4` made **Dolt the only backend** and demoted `.beads/issues.jsonl` to an export-only artifact (*"post-merge hook uses JSONL import only as a legacy fallback when no Dolt remote is configured"*). Overdeck's beads integration grew up in the JSONL era and is now **mixed-authority**:

- `bd` reads/writes a local Dolt DB under `.beads/embeddeddolt/` (per machine, gitignored).
- Multiple runtime paths still parse `.beads/issues.jsonl` **directly** as if authoritative.
- The only thing Overdeck transports cross-machine is `issues.jsonl` committed to `overdeck-state`; the Dolt DB never travels. There is **no `bd dolt push/pull` anywhere in Overdeck** (grep confirms zero).
- The issue view's beads panel reads the *dashboard machine's local* Dolt DB; refreshing does not sync from another machine.

**Measured divergence (2026-07-12):** a full live Dolt export held **3,291** records vs **3,214** lines in the `overdeck-state` `issues.jsonl`, with records present on only one side. The JSONL's last commit was the July-9 state seed. **The JSONL transport is already lossy relative to Dolt.** Canonicalizing JSONL would lock in that loss.

Therefore the Machine A→B→C sequence is **not currently guaranteed**: without an explicit Dolt push from B and pull on C, C shows stale local state.

Root-cause history (verified): `bd` switched to Dolt in [PAN-386](https://github.com/eltmon/overdeck/issues/386); a run of Dolt failures followed — [PAN-1158](https://github.com/eltmon/overdeck/issues/1158) (workspace Dolt DB silently empties → `bd export` writes empty → tracked `issues.jsonl` deleted), [PAN-939](https://github.com/eltmon/overdeck/issues/939)/[PAN-2261](https://github.com/eltmon/overdeck/issues/2261) (lock contention), [PAN-506](https://github.com/eltmon/overdeck/issues/506). `no-db: true` drifted in incidentally (commit `6ab6f1309a`, side effect of a bundled `bd init`) and its *effect* masked those failures, but it was never a deliberate design and is now unsupported.

## 3. Decisions (made in this document)

- **D1 — Dolt is canonical; the canonical copy travels on git as `refs/dolt/data`.** Each machine keeps a **gitignored local Dolt working copy** (the disposable cache). This satisfies the single-source-of-truth tenet: the source of truth is on the git remote (Dolt refs), the local DB is rebuildable via `bd bootstrap`.
- **D2 — `refs/dolt/data` lives on the project's own git remote** (the same remote that hosts code / `overdeck-state`), via `bd dolt remote add origin git+ssh://…`. No external DoltHub/S3.
- **D3 — `issues.jsonl` is a derived, validated recovery/interoperability export only.** Never a live write surface, never a canonical read source in production paths. It remains committed to `overdeck-state` for human/diff/disaster-recovery use, produced by the write door with integrity checks (refuse-empty, source-hash, count/ID verify), never by line-union merge.
- **D4 — One beads read door and one beads write door.** All live reads go through the resolver (`bd … --json` against the synced local Dolt); all mutations go through the writer (bootstrap→pull→mutate→commit→push→typed result). No route/agent/hook touches `issues.jsonl` or `bd` directly for canonical state.
- **D5 — The state migration must never copy a live Dolt layout to `overdeck-state`.** `.beads/dolt/`, `.beads/embeddeddolt/`, and Dolt runtime files (pid/lock/port/log/backup) are gitignored on all branches and `overdeck-state`.
- **D6 — Conflict policy: serialize + never blind-force.** The writer pulls before mutating and pushes after; a rejected push (divergent history) returns a **typed conflict result** for retry/operator action. `bd dolt push --force` is never issued automatically. `dolt.auto-push` is never enabled unattended (NFR-1). **IMPLEMENTATION CHECKPOINT (C1):** verify `bd dolt pull` behavior on a divergent issues-table history and whether `bd merge` resolves it; **fallback** if merge is unsafe — keep the single-writer invariant so cross-machine writes to the *same* project are serialized through one host, making divergence rare, and surface any divergence rather than resolving it automatically.
- **D7 — Reconcile before cutover.** For every project, produce a deterministic no-loss report across {local Dolt, `refs/dolt/data`, `overdeck-state` `issues.jsonl`} and have it reviewed before any import/push/winner-selection.
- **D8 — Everything ships in one delivery** (operator directive). No phase is carved out or deferred; FR-1…FR-8 + NFR-1…NFR-3 all land in this issue.

## 4. Requirements (carried from the issue, normative)

Functional:
- **FR-1 Safe migration gate.** `pan admin state migrate` detects any live Dolt data/runtime layout and refuses to copy it to `overdeck-state`, with an explanatory error. Detection must NOT depend on `issues.jsonl` being absent.
- **FR-2 Canonical beads resolver.** All live beads reads use one resolver backed by `bd … --json` against the synchronized local Dolt. Remove direct runtime parsing of `issues.jsonl`; JSONL may be read only by explicit recovery/import/export-verification/diagnostic paths.
- **FR-3 Canonical beads writer.** All mutations pass through one writer that: (1) ensures the local DB is bootstrapped; (2) syncs from the Dolt remote before mutation; (3) applies the mutation; (4) creates a Dolt commit; (5) pushes at a defined safe checkpoint; (6) returns a typed conflict/retry result rather than overwriting either side. Closing a bead must be durably pushed before `pan done` reports durable completion; prefer pushing after each successfully-closed bead.
- **FR-4 Cross-machine bootstrap.** A fresh clone or newly-registered machine detects `refs/dolt/data` and hydrates via `bd bootstrap`/`bd dolt pull`. A plain git checkout is never treated as proof beads are current.
- **FR-5 Dashboard freshness.** The dashboard obtains beads progress from the canonical resolver. A background synchronizer checks/pulls remote Dolt changes and invalidates the issue's beads query on success. No blocking network pull on the 10s UI poll. The beads rail exposes freshness (last successful sync time) and a visible stale/error state.
- **FR-6 JSONL recovery export.** After successful canonical mutations/sync, produce an explicit validated `issues.jsonl` export that: refuses to replace a non-empty known-good snapshot with an unexpectedly empty export; records the source Dolt commit/hash; verifies count and IDs before publishing; never line-union-merges concurrent updates; is documented as derived, not authoritative.
- **FR-7 Reconcile existing divergence.** Before enabling the new flow for a project, take independent safety exports and compare {local Dolt, `refs/dolt/data`, `overdeck-state` `issues.jsonl`}; produce a deterministic no-loss report; do not import/push/delete/pick-a-winner until reviewed. Preserve all issue fields, labels, dependencies, comments, and Overdeck record types.
- **FR-8 Standardize configuration.** Remove unsupported `no-db` settings; validate `sync.remote`; pin/document the supported `bd` version and embedded-Dolt mode; never commit `dolt/`, `embeddeddolt/`, backup blobs, pid/port/lock/log files to code branches or `overdeck-state`.

Non-functional:
- **NFR-1 Concurrency safety.** Serialize local `bd` operations through the existing async lock boundary (`src/lib/bd-process-lock.ts`). Handle divergent Dolt histories explicitly. Do not enable unattended `dolt.auto-push` unless proven safe for concurrent multi-machine writers.
- **NFR-2 Availability.** Network/remote-Dolt failure may leave the UI in a clearly-marked stale/read-only state but must not fabricate zero progress, silently fall back to an unverified JSONL snapshot, or destroy local work.
- **NFR-3 Observability.** Log/expose local Dolt head, last pulled remote head, last successful pull/push, freshness age, and sync/conflict errors, using standalone operator-facing messages.

## 7. Restated intersecting repo rules (executor must honor)

- **No `execSync` in dashboard/server-reachable code** — the background sync service and any server path use `execAsync`/`spawn`; delays use `await new Promise(r=>setTimeout(r,ms))`.
- **Fake timers for any delay/retry test** (`vi.useFakeTimers()` + `advanceTimersByTimeAsync`); no real `setTimeout` in tests; never drop `maxForks` to 1.
- **Async tmux only** (`sendKeysAsync`) if any tmux touch is needed (unlikely here).
