# PAN-3396 — zombie_pr bucket resurrects closed-out issues; no disposition for recordless rows

**Issue:** https://github.com/eltmon/overdeck/issues/3396
**Mode:** `--auto` planning (all decisions made in this document; see §4)

## 1. Glossary

- **Pipeline membership** — the canonical "is this issue in the pipeline" verdict, computed only by `resolvePipelineMembership()` in `src/lib/pipeline-membership.ts` from durable lens signals gathered by `gatherProjectLensSignals()` in `src/lib/pipeline-membership-gather.ts`. Doc: `docs/PIPELINE-MEMBERSHIP.md`.
- **Bucket** — one of `in_flight | zombie_pr | post_merge_limbo | planned_backlog | clean_terminal` (`packages/contracts/src/types.ts:8-13`). `inPipeline` is `bucket !== 'clean_terminal'`.
- **zombie_pr** — bucket for "tracker issue is closed but a PR/MR for the convention branch is still open" (`src/lib/pipeline-membership.ts:127-137`). Currently `inPipeline: true` with no further qualification.
- **Terminal close-out record** — the per-issue durable record on `overdeck-state` (`records/<issue>.json`) whose `pipeline.closedOut === true` (fields at `src/lib/pan-dir/record.ts:202-203`), written by `markRecordPipelineClosedOutSync()` (`src/lib/pan-dir/record.ts:873-887`) at ceremony step 8 of `closeOut()`.
- **Recordless zombie** — a zombie_pr row for an issue closed before the record system existed: no per-issue record, no journal. The DoD gate's verdict rows report `miss: no review status or journal record found` (`src/lib/lifecycle/dod-gate.ts:347`) and block close-out forever.
- **Residue disposition** — the new operator-recorded judgment this PRD adds: "this tracker-closed issue's leftover artifacts are residue; archive a durable record and clear them without demanding pipeline evidence that can never exist."
- **DoD gate** — the 9-row Definition-of-Done check (`src/lib/lifecycle/dod.ts:22-80`) evaluated by `evaluateDodGate()` before any close-out mutation. `--abandon` (PAN-3211) is the existing precedent for a disposition that skips the gate via a synthetic all-skip gate result (`buildAbandonedDodGate`, `src/lib/lifecycle/dod.ts:122-134`).
- **Convention branch / PR** — `feature/<id-lowercase>` or `strike/<id-lowercase>`, and any PR/MR whose head is one of those refs.

## 2. Problem

Flywheel RUN-79 (2026-08-01) found 11 zombie_pr rows on mind-your-now in three populations:

1. **Already closed out** — e.g. MIN-882 (closed out 2026-07-23, so `pipeline.closedOut === true` exists) still classified zombie_pr/`inPipeline: true` because the closed-issue branch of the resolver (`src/lib/pipeline-membership.ts:127-137`) never consults the close-out record. A leftover open PR resurrects terminal work into the operator-visible exception queue — the same never-retired classification family as the PAN-3379 needs-you phantoms.
2. **Genuine close-out lag** — correctly surfaced; fixed by driving close-out. Working as intended.
3. **Recordless ancients** — MIN-172, MIN-572, MIN-576, MIN-596, MIN-620, MIN-622, MIN-632: pre-record-era closed issues with stale open PRs. `pan close` fails the DoD gate at rows 1–3 (`no review status or journal record found`, `src/lib/lifecycle/dod-gate.ts:347`). There is no mechanical disposition path, so zombie_pr is an unbounded dead-letter queue for these rows.

`--abandon` does not cover population 3: it declares "this work never landed" (unknown for ancient rows), is GitHub-only (`src/cli/commands/close.ts:253-262` — the affected project is Linear-tracked with GitLab MRs), and does not close the stale PR that keeps the row in the bucket.

## 3. Requirements

### Functional

- **FR-1** — A tracker-closed issue with an open convention PR/MR **and** a terminal close-out record classifies `clean_terminal` (`inPipeline: false`). The reason string names the leftover open PR as residue to close on the forge (audit trail).
- **FR-2** — A tracker-closed issue with an open convention PR/MR and **no** terminal close-out record continues to classify `zombie_pr` (`inPipeline: true`). Behavior for populations 2 and 3 is unchanged until dispositioned.
- **FR-3** — The gather populates the new terminal-close-out signal only for candidates that are tracker-closed with an open PR (the only branch that consults it), reads it through the record read door (`readIssueRecord`), and fails toward `zombie_pr` visibility on any read error.
- **FR-4** — `pan close --residue <reason>` dispositions a recordless zombie end-to-end: it (a) requires an operator conversation (`conv-*`), (b) requires the tracker issue to already be closed, verified tracker-agnostically via `isTrackerIssueClosed()`, (c) refuses combination with `--abandon` and every `--accept-*` flag, (d) closes every open convention PR/MR with an honest residue comment, (e) writes a residue DoD gate audit and a terminal close-out marker into the per-issue record (creating the record if none exists), and (f) succeeds with no pre-existing journal/review-status record.
- **FR-5** — After a successful `--residue` close-out, the issue classifies `clean_terminal` (no open PR remains and a terminal close-out record exists), and a repeat `pan close` short-circuits through the existing idempotent path (`readCompletedCloseOut`, `src/lib/lifecycle/dod-gate.ts:869-882`).

### Non-functional

- **NFR-1** — The resolver stays pure: classification from `IssueLensSignals` only; no I/O in `src/lib/pipeline-membership.ts`.
- **NFR-2** — The residue terminal marker must not assert merge evidence that does not exist: it must not write `mergeStatus: 'merged'` (the existing `markRecordPipelineClosedOutSync` does, `src/lib/pan-dir/record.ts:883`).
- **NFR-3** — The durable-lenses invariant holds: membership never reads the SQLite DB, `review-status.json`, agent state, or tmux. The new lens reads only the `overdeck-state` record. `scripts/lint-pipeline-membership.sh` stays green.
- **NFR-4** — File-size ratchet: `src/lib/lifecycle/workflows.ts` (1116 lines, allowlist row `1116 src/lib/lifecycle/workflows.ts # PAN-3215`) and `src/lib/pan-dir/record.ts` (1022 lines, allowlist row `1022 src/lib/pan-dir/record.ts # PAN-3358`) are both exactly at their allowlisted caps. Any growth requires updating the row in `scripts/file-size-allowlist.txt` in the same commit with a `# PAN-3396` comment.

## 4. Design decisions (made here, binding)

- **D1 — New lens `hasTerminalCloseOut`, not a new bucket.** The bucket vocabulary stays five-valued; `clean_terminal` + an audit reason carries the state. A new bucket would churn `@overdeck/contracts`, every frontend grouping, and every consumer filter for zero behavioral gain. The lens is added to `IssueLensSignals` (`src/lib/pipeline-membership.ts:36-66`) and consulted only in the closed-issue branch.
- **D2 — The lens is the durable record only.** `hasTerminalCloseOut` = `record.pipeline.closedOut === true`, read via `readIssueRecord`. It deliberately does NOT replicate `readCompletedCloseOut`'s live-review-status check: that check exists to detect mid-ceremony aborts for re-drive, but by step 8 the tracker issue is already closed and the remaining steps are runtime-plane cleanup, which never justifies resurrecting the issue into the pipeline. Reading live status would also violate NFR-3.
- **D3 — The lens gates only zombie_pr.** An open issue is never suppressed by the close-out record (a reopened issue is live again and should classify `post_merge_limbo`/`in_flight` as the other lenses dictate). Scope is exactly the issue's fix direction.
- **D4 — Disposition door is `--residue <reason>` on `pan close`, operator-conversation-only.** Same trust tier as `--abandon` (both bypass the DoD gate's evidence with a recorded judgment). The flywheel is not granted this door in this issue; granting autonomous residue disposition is a separate policy decision. (Auto-decision: the issue names this flag shape as its example and no alternative shape is documented anywhere.)
- **D5 — `--residue` closes stale convention PRs/MRs itself, with an honest comment.** A disposition door that refuses on the exact condition it exists to clear would be useless, and a PR close is reversible (reopen). The comment never claims a merge: `Closed as residue by pan close --residue: <ID> is closed on the tracker with no pipeline record (pre-record-era). This PR never merged through the pipeline; reopen it if the work is still wanted.` This sidesteps the deliberate anti-lie guards in `src/lib/lifecycle/close-issue.ts:200-204` and `:271-279`, which stay untouched. If any PR/MR close fails, the ceremony hard-fails before writing the terminal marker — no terminal record while a zombie PR survives.
- **D6 — Tracker-closed verification uses `isTrackerIssueClosed()`** (`src/lib/cloister/issue-closed.ts:30`), which is tracker-agnostic (Linear + GitHub), not `--abandon`'s GitHub-only canonical read. The affected population is Linear-tracked. (Auto-decision: issue says "verifies tracker+MR state" without naming the mechanism.)
- **D7 — `--residue` does not require recordlessness.** A partial record (exists but no verdicts) fails the gate identically to a missing one; requiring absence could only false-block legitimate uses. The operator's reason documents the judgment.
- **D8 — Residue logic lives in a new module `src/lib/lifecycle/residue.ts`.** Both ceremony-adjacent god files are at their file-size caps (NFR-4); a new module keeps `workflows.ts` threading to a handful of lines.
- **D9 — `DodGateResult.disposition` gains an optional `kind: 'abandon' | 'residue'`.** `buildAbandonedDodGate` sets `kind: 'abandon'` (additive, no behavior change); the residue builder sets `'residue'` so a reader of the durable audit can tell the two judgments apart.
- **D10 — Residue skips the `closeIssue` ceremony step.** Tracker-closed is pre-verified by the flag validation (D6); the step is recorded as `stepSkipped` naming that pre-verification instead of re-closing an already-closed issue.
