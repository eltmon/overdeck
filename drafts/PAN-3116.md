# PAN-3116 — Derive the file-size ratchet from origin/main; delete the committed baseline

**Issue:** https://github.com/eltmon/overdeck/issues/3116
**Mode:** `pan plan --auto` (non-interactive; decisions recorded in `autoDecisions[]`)

---

## Glossary

- **God file** — a non-test `.ts`/`.tsx` file under `src/` exceeding **1,000 lines** (the **ceiling**). The current ratchet tracks 31 of them.
- **Ratchet** — the shrink-but-never-grow rule: a god file may get smaller, never larger. Enforced by `scripts/lint-file-size.sh`, wired into `npm run lint` (`lint:file-size`) and `.husky/pre-push`.
- **Baseline** — `scripts/file-size-baseline.txt`, the committed 31-line snapshot of `"<lines> <path>"` the ratchet compares against today. **This PRD deletes it.**
- **Allowlist** — the new `scripts/file-size-allowlist.txt`: `<lines> <path> # <ISSUE-REF>` entries permitting audited growth of a god file beyond its `origin/main` line count. Replaces the old "manually edit the baseline in an issue-referenced commit" escape hatch (A3's D4).
- **Base ref** — the git ref the ratchet compares against: `origin/main` by default, overridable with the `FILE_SIZE_BASE_REF` env var (tests use this).
- **Ratchet audit** — `scripts/lint-ratchet-audit.sh`, the pre-push/CI guard requiring an issue reference in any commit that raises a ratchet (currently the file-size baseline, `eslint-any-allowlist.json`, and `scripts/circular-deps-baseline.txt`).
- **UAT promote** — `src/lib/cloister/uat-promote.ts`, the server-side flow that merges a UAT batch branch into `main` in a throwaway worktree; today it reconciles the file-size baseline post-merge and amends the merge commit.

## Problem

`scripts/file-size-baseline.txt` is shared mutable state committed to the repo. Because `lint-file-size.sh` fails on *stale* baseline entries (script header line 6; check loop lines 78–81 and 93–107), any branch that changes the line count of a listed file must also edit the baseline — so every pair of concurrent branches touching any god file collides on the same 31 lines. 71 commits touched the file in 7 days; PAN-3037 and PAN-1696 both hit it as a merge conflict in RUN-71 (PAN-1696's *only* conflict). Two branches that each shrink a *different* god file — both strictly good — still conflict, because both rewrite the same snapshot.

The check is semantically per-file and order-independent; only the storage format serializes branches. The fix is to derive the comparison at lint time instead of storing it.

## Proposal

Replace the committed snapshot with a comparison against the merge target at lint time, and keep the audited-growth escape hatch as a small allowlist that changes rarely (and so rarely conflicts):

1. **`scripts/lint-file-size.sh` rewritten.** For each non-test `src/` file, `allowed = max(CEILING, lines on base ref)` when the file exists on the base ref, else `CEILING`; an allowlist entry overrides with its stated count. No baseline file, no stale-entry failures, no `--update` mode. Comparison happens only for files already over the ceiling in the working tree (~31 `git show` calls — same order of cost as today's per-file `wc`).
2. **`scripts/file-size-baseline.txt` deleted** in the same commit as the rewrite (atomic: the tree never has one file without the other).
3. **`scripts/file-size-allowlist.txt` created** — header comment plus zero entries. Format: `<lines> <path> # <ISSUE-REF>`. Malformed lines (missing count, missing issue ref) fail the lint, so every exception is self-documenting.
4. **`scripts/lint-ratchet-audit.sh` retargeted** from the deleted baseline to the new allowlist, reusing the same added/raised numeric-entry detection. Removing or lowering an entry stays free; adding or raising one requires an issue-referencing commit, exactly as baseline raises did.
5. **Reconcile machinery deleted.** `src/lib/cloister/file-size-reconcile.ts` and its call in `src/lib/cloister/uat-promote.ts` (plus the merge-commit `--amend` it triggered) exist only to keep the stored snapshot fresh; with nothing stored, they go. Their two test files go with them.
6. **Plan-quality rule removed.** The `deferred-file-size-ratchet` rule in `src/lib/xbrief/quality-lint.ts` (and the planning-prompt paragraph at `src/lib/cloister/prompts/planning.md:229`) exists to force baseline reconciliation into xBRIEF items. With no baseline to reconcile, the rule is removed and the prompt paragraph rewritten to describe the derive-at-lint-time contract.
7. **Docs updated.** `docs/codebase-health/A3-file-size-guard.md` gets an `> Update (PAN-3116):` note in the established repo convention (see `docs/codebase-health/B-deacon-decomp.md:26`). Historical journals (`docs/FLYWHEEL-STATE.md`, `docs/flywheel-briefs/run-59-order-book.md`, `docs/codebase-health/B-deacon-decomp.md`) stay untouched — they are records of what happened, not living docs.

### New `lint-file-size.sh` core logic (replaces lines 69–121 of the current script)

```bash
CEILING=1000
BASE_REF="${FILE_SIZE_BASE_REF:-origin/main}"
ALLOWLIST="scripts/file-size-allowlist.txt"

if ! git rev-parse --verify --quiet "$BASE_REF" >/dev/null; then
  echo "✖ file-size guard: base ref '$BASE_REF' not found — fetch it (git fetch origin main) or set FILE_SIZE_BASE_REF." >&2
  exit 1
fi

# Parse allowlist: "<lines> <path> # <ISSUE-REF>"; malformed lines fail.
declare -A allowed_override
if [[ -f "$ALLOWLIST" ]]; then
  while IFS= read -r line; do
    [[ -z "${line//[[:space:]]/}" || "$line" =~ ^[[:space:]]*# ]] && continue
    if [[ "$line" =~ ^([0-9]+)[[:space:]]+([^[:space:]]+)[[:space:]]+#[[:space:]]*([A-Z]+-[0-9]+|#[0-9]+) ]]; then
      allowed_override["${BASH_REMATCH[2]}"]="${BASH_REMATCH[1]}"
    else
      echo "✖ malformed allowlist line: $line (want: <lines> <path> # <ISSUE-REF>)"
      fail=1
    fi
  done < "$ALLOWLIST"
fi

fail=0
while IFS= read -r f; do
  n=$(wc -l < "$f")
  (( n <= CEILING )) && continue
  if [[ -n "${allowed_override["$f"]:-}" ]]; then
    allowed="${allowed_override["$f"]}"
  else
    main_n=$(git show "$BASE_REF:$f" 2>/dev/null | wc -l || true)
    allowed=$(( main_n > CEILING ? main_n : CEILING ))
  fi
  if (( n > allowed )); then
    echo "✖ $f is $n lines (> $allowed) — god files may shrink but never grow past $BASE_REF. Audited growth: add '<n> $f # <ISSUE>' to $ALLOWLIST."
    fail=1
  fi
done < <(
  find src -type f \( -name '*.ts' -o -name '*.tsx' \) \
    ! -name '*.test.ts' ! -name '*.test.tsx' ! -name '*.d.ts' \
    ! -path '*/__tests__/*' ! -path '*/node_modules/*' ! -path '*/dist/*' \
    | sort
)
```

Key semantics, stated as decision rules so the work agent doesn't re-derive them:

- A file at or under 1,000 lines in the working tree passes without any git lookup.
- A file over 1,000 lines that does **not** exist on the base ref fails (new god file) unless allowlisted — `git show` yields empty, `main_n=0`, `allowed=CEILING`.
- A file that shrank on a branch passes even if `origin/main` moved — the allowance only ever tightens when main itself shrinks the file, which is the ratchet working as intended.
- **No stale-entry failures.** Nothing is stored, so nothing can be stale. A branch that shrinks a god file edits no lint metadata at all.
- **Moot allowlist entries** (base-ref count ≥ entry, i.e. main absorbed the growth) are harmless and pruned manually; removals need no issue reference.
- Missing base ref is a hard error with an actionable message, not a silent pass (no fallback chains).

## Requirements

- **FR-1** — `bash scripts/lint-file-size.sh` exits 1 when a non-test `src/` file exceeds 1,000 lines and has no base-ref history or allowlist entry permitting it.
- **FR-2** — The guard exits 1 when a file exceeds its `origin/main` line count (when that count is over the ceiling) without an allowlist entry; exits 0 when the working-tree count is at or below the base-ref count.
- **FR-3** — An allowlist entry `<lines> <path> # <ISSUE-REF>` permits the file up to `<lines>`; a malformed entry (missing count or issue ref) exits 1 naming the line.
- **FR-4** — `scripts/file-size-baseline.txt` no longer exists and nothing in the repo reads it: `git grep -l file-size-baseline` returns only historical docs (`docs/FLYWHEEL-STATE.md`, `docs/flywheel-briefs/`, `docs/codebase-health/` history notes).
- **FR-5** — `scripts/lint-ratchet-audit.sh --range <base>..<head>` fails a commit that adds or raises a `scripts/file-size-allowlist.txt` entry without an issue reference, and passes removals/lowerings and issue-referenced raises.
- **FR-6** — UAT promote merges without running any baseline reconcile or merge-commit amend: `src/lib/cloister/uat-promote.ts` contains no reference to `file-size-reconcile`, and `src/lib/cloister/file-size-reconcile.ts` does not exist.
- **FR-7** — `lintPlanQuality` no longer emits `deferred-file-size-ratchet` for any plan, and the planning prompt no longer instructs baseline reconciliation.
- **NFR-1** — Two branches that each shrink a *different* god file produce zero merge conflicts in lint metadata (there is no shared lint-metadata file to conflict on; the allowlist starts empty and changes only on audited growth).
- **NFR-2** — The guard fails loudly (exit 1, actionable message) when the base ref is unresolvable; it never silently passes.
- **NFR-3** — The guard's per-run cost stays in the same order as today: one `wc -l` per `src/` file, plus one `git show` per over-ceiling file only.
- **NFR-4** — `FILE_SIZE_BASE_REF` overrides the comparison ref so tests hermetic from the network can pin a local ref.
