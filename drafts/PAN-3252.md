# PAN-3252 — QuantumLlama Provider Integration (Benchmark)

> **Benchmark issue.** QuantumLlama is a fictional provider used to exercise the
> Overdeck pipeline end-to-end on the kimi-code harness (PAN-1837 wi14). The branch
> is never merged. The authoritative spec is
> `benchmarks/specs/quantumllama.md` in this repo — implement exactly what it says,
> never research QuantumLlama externally (it does not exist).

## Glossary

- **Provider registry** — `PROVIDERS` in `src/lib/providers.ts`: the map of every AI
  provider Overdeck can route to, keyed by `ProviderName`.
- **`ModelId`** — the union type in `src/lib/settings.ts` (~line 37) enumerating every
  known model identifier. Two maps are **exhaustive** over it (see Hazard H1).
- **Cost module** — `src/lib/cost.ts`: `DEFAULT_PRICING` (per-1K-token rates) +
  `calculateCostSync`. Its `AIProvider` type has only 4 values
  (`'anthropic' | 'openai' | 'google' | 'custom'`); every non-big-three provider
  (kimi, minimax, zai…) keys its pricing rows as `'custom'`.
- **Capability table** — `MODEL_CAPABILITIES` in `src/lib/model-capabilities.ts`:
  per-model `displayName`, `contextWindow`, blended `costPer1MTokens`, skill scores.
  This is what the Cloister and the auto-compact-window wiring
  (`getClaudeCodeContextPolicyForModel` in `src/lib/agents/provider-env.ts`) read.
- **Fallback registry** — `src/lib/model-fallback.ts`: `MODEL_PROVIDERS`
  (model → provider), `FALLBACK_MAP` (model → Anthropic substitute), and
  `detectEnabledProvidersSync` (API-key gating).
- **QL models** — `ql-reason-70b`, `ql-swift-8b`, `ql-nano-1b` (the three
  QuantumLlama models from the spec).

## Requirements

- **FR-1** `quantumllama` is a registered provider: `ProviderName` union member,
  `PROVIDERS` entry (displayName "QuantumLlama", `baseUrl`
  `https://api.quantumllama.ai/v1`, `authType: 'static'`, the three models,
  `tested: false`), `getProviderForModelSync('ql-…')` returns it, and
  `getProviderEnvSync` injects `QUANTUMLLAMA_API_KEY`.
- **FR-2** All three QL models have per-1K pricing rows in `DEFAULT_PRICING` keyed
  `provider: 'custom'`, with cache-read and cache-write-5m rates, and
  `calculateCostSync` produces correct USD costs for QL usage.
- **FR-3** `normalizeModelName` in `src/lib/cost-parsers/jsonl-parser.ts` returns
  `{ provider: 'custom', model }` for models starting with `ql-` instead of falling
  through to the `claude-sonnet-4` default (which would silently mis-price them).
- **FR-4** `model-fallback.ts` knows the QL models: `ModelProvider` union gains
  `'quantumllama'`, `MODEL_PROVIDERS` maps all three, `FALLBACK_MAP` maps them to
  Anthropic substitutes, `getModelProviderSync` resolves `ql-` prefixed IDs, and
  `detectEnabledProvidersSync` / `getAvailableModelsSync(enabledProviders)` gate on
  the QuantumLlama key.
- **FR-5** `MODEL_CAPABILITIES` has entries for all three QL models with the display
  names, context windows, and a new optional `maxOutputTokens` field carrying the
  spec's max-output values (no existing field holds max output — this is additive).
- **FR-6** `config.yaml` / settings can carry QuantumLlama: `ModelId` union includes
  the three QL IDs, `ApiKeysConfig` gains `quantumllama?`, settings env fallback
  reads `QUANTUMLLAMA_API_KEY`, `getAvailableModelsSync(settings)` returns QL models
  when the key is set, and the key name is in the provider env-key allowlists
  (`provider-env.ts`, `child-env.ts`, `env-loader.ts`, `config-yaml/load.ts`).
- **FR-7** Dashboard: `MODELS_BY_PROVIDER` in
  `src/dashboard/frontend/src/components/Settings/modelCatalog.ts` gains a
  `quantumllama` group; `friendlyModelName` in both `CostBreakdownModal.tsx` and
  `Stage/HomePane/Timeline.tsx` renders `ql-reason-70b` → "QL Reason 70B" (the
  generic heuristic would produce "Ql Reason 70b" — wrong casing).
- **FR-8** Docs name `QUANTUMLLAMA_API_KEY` as the expected env var:
  `configuration/harnesses.mdx`, `docs/TESTING-PROVIDERS.md` (provider→env-var
  table), `docs/CONFIGURATION.md`, `docs/USAGE.md`.
- **NFR-1** No HTTP client, request/response, or streaming code for QuantumLlama;
  no agent-spawn changes to actually invoke QL models.
- **NFR-2** `npm run typecheck`, `npm run lint`, `npm test` all pass; no regressions.

## Decisions (auto mode — no operator questions asked)

- **D1: pricing keyed `provider: 'custom'`.** Matches kimi/minimax/zai convention in
  `DEFAULT_PRICING`; widening the 4-value `AIProvider` union would ripple through
  `CostSummary.byProvider` and every provider mapper for zero benchmark value.
- **D2: `defaultHarness: 'claude-code'`.** The registry requires one
  (`tests/unit/lib/providers.test.ts` asserts every provider has a built-in default
  harness). QL is never spawned, so the simplest static-auth default is used.
- **D3: add optional `maxOutputTokens?: number` to `ModelCapability`.** The spec and
  the issue AC require max-output metadata to be resolvable; no existing field holds
  it. Optional field, populated only for QL models — additive, no other entries touched.
- **D4: fallback mapping** `ql-reason-70b → 'claude-sonnet-5'` (flagship→Sonnet, per
  existing `FALLBACK_MAP` comments), `ql-swift-8b → 'claude-haiku-4-5'` and
  `ql-nano-1b → 'claude-haiku-4-5'` (fast/small→Haiku).
- **D5: CLI needs no code change.** `src/cli/commands/status.ts` (~line 220) and
  `src/cli/commands/cost.ts` print raw model IDs for every provider; QL parity is
  achieved by ID passthrough once pricing rows exist. Verified — there is no CLI
  friendly-name mapper to extend.
- **D6: no Pi mapping.** `piProviderForModel` has a `default: return undefined`
  branch; Pi has no quantumllama provider, so no case is added and `qualifyPiModel`
  returns the bare ID. Not a typecheck risk (switch is not exhaustive).
- **D7: model-validation.ts untouched.** `MODEL_ID_PATTERN` already accepts
  `ql-reason-70b`; the validator is pattern-only, not catalog-based.
- **D8: launcher/planning env passthrough out of scope.** QL agents are never
  spawned (fictional provider), so threading the key through
  `spawn-planning-session.ts` / `launcher-generator.ts` env lists is a NonGoal;
  the allowlists in FR-6 cover settings/config parity, which is what the ACs test.
- **D9: curated chat/shared ModelPicker lists untouched.** They are hand-curated
  operator quick-pickers; the Settings catalog (`modelCatalog.ts`) is the dropdown
  source the spec's "model selection dropdowns (if any exist)" refers to.

## Hazards

- **H1 — exhaustive Records force atomicity.** `MODEL_PROVIDERS` is
  `Record<ModelId, ModelProvider>` (`src/lib/model-fallback.ts:22`) and
  `MODEL_CAPABILITIES` is `Record<ModelId, ModelCapability>` via
  `type CapabilityModelId = ModelId` (`src/lib/model-capabilities.ts:104,159`).
  Adding QL IDs to `ModelId` in `settings.ts` **breaks typecheck until both maps
  gain entries in the same commit** — that is why work item 2 bundles all three files.
- **H2 — silent mis-pricing default.** `normalizeModelName` defaults unknown models
  to `{ provider: 'anthropic', model: 'claude-sonnet-4' }`
  (`src/lib/cost-parsers/jsonl-parser.ts`, end of the function around line 209).
  Without FR-3, QL usage would be costed as Sonnet 4.
- **H3 — silent mis-routing default.** `getModelProviderSync` returns `'anthropic'`
  for unknown models (`src/lib/model-fallback.ts:249`). Add the map entries and a
  `startsWith('ql-')` prefix branch before that default.
- **H4 — `PROVIDERS` is `Record<ProviderName, ProviderConfig>`** — adding the union
  member forces the `PROVIDERS` entry in the same commit (same file, work item 1).
  `tests/unit/lib/providers.test.ts:24` asserts every provider has a `defaultHarness`.
- **H5 — never merge.** This branch exists only to verify the kimi-code harness
  e2e. Do not open the PR for merge; complete the pipeline normally otherwise.
