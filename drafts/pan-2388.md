# PAN-2388 — Deliberate token/cost capture for non-claude-code harnesses (ohmypi + codex)

**Issue:** https://github.com/eltmon/overdeck/issues/2388
**Related:** PAN-2387 (codex misattribution symptom + UNKNOWN bucket), PAN-1574 (codex parser origin), PAN-1989 (ohmypi parser origin)
**Mode:** `pan plan --auto` — decisions recorded in `plan.autoDecisions[]`, no interactive Q&A.

## Glossary

- **Harness** — the coding-agent CLI an Overdeck agent runs under: `claude-code`, `ohmypi` (omp), or `codex`.
- **Rollout file** — a Codex CLI session transcript: `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<ts>-<uuid>.jsonl`. Per-agent Codex homes live at `~/.overdeck/agents/<id>/codex-home/`.
- **omp session file** — an oh-my-pi session JSONL: for pan-spawned agents at `<agentDir>/sessions/` (launcher passes `--session-dir`); for ad-hoc omp use at `~/.omp/agent/sessions/<encoded-cwd>/`.
- **Cost event** — one row in the `cost_events` SQLite table + one line in the append-only events archive, written ONLY through `CostWriter.record()` in `src/lib/overdeck/cost.ts` (the write door).
- **Reconcile sweep** — `CostWriter.reconcile({source})` in `src/lib/overdeck/cost.ts:537`: walks per-agent session dirs, parses files with the harness parser, feeds events into `record()` (which deduplicates).
- **requestId** — the dedupe key for a cost event. `checkDuplicate` (`src/lib/overdeck/cost.ts:480`) matches on `requestId` when present, else on `sourceFile`.

## Verified findings (checked against code + live DB, 2026-07-05)

1. **The codex reconcile sweep has never run.** Grep across the repo finds exactly two `reconcile` call sites: `src/dashboard/server/routes/costs.ts:329` calls `reconcile()` with **no argument** (source defaults to `'claude'`, and the function returns `{imported: 0}` immediately for any source that isn't `'ohmypi'`/`'codex'` — see `src/lib/overdeck/cost.ts:540`), and `src/lib/cloister/pi-cost-reconciler.ts:7` calls `reconcile({source: 'ohmypi'})`. **Nothing anywhere passes `source: 'codex'`.**
2. **Live DB has ZERO codex and ZERO ohmypi cost events** (`SELECT ... WHERE session_type='codex'` → empty; same for `ohmypi`), while codex session files exist on disk under e.g. `~/.overdeck/agents/agent-pan-2383-slot-1/codex-home/sessions/2026/`.
3. **The PAN-2387 "gpt-5.4-mini $0.00 calls=4" drill rows are NOT parser output.** PAN-2383's cost events are: 4 × `memory-extraction`/`gpt-5.4-mini`/$0, 33 × plan/opus, 181 × work/haiku+opus. The codex tier's spend is simply absent, and the drill surfaces the 4 memory-extraction rows. The codex parser was never in the loop.
4. **Codex events can never refresh.** The codex branch of reconcile (`src/lib/overdeck/cost.ts:589-612`) records ONE session-level event with `requestId: null`, deduped by `sourceFile`. A rollout imported mid-session would be frozen at its first-import totals forever. (Moot today only because the sweep never runs.)
5. **Codex parser hardcodes a model fallback.** `src/lib/cost-parsers/codex-parser.ts:122`: `if (!model) model = 'gpt-5.5';` — violates the no-hardcoded-model-fallback rule and silently misprices unknown sessions.
6. **Real codex rollout format (cli 0.142.5, verified from a live file):** records are wrapped — `{"timestamp", "type":"event_msg"|"turn_context"|"session_meta"|..., "payload":{...}}`. The resolved model lives ONLY in `turn_context.payload.model` (`task_started` carries no model). `token_count` lives under `event_msg` with `payload.info.total_token_usage` and `payload.info.last_token_usage`, both using `input_tokens`/`cached_input_tokens`/`output_tokens`/`reasoning_output_tokens`/`total_tokens` field names. The current parser reads these correctly at session level.
7. **Real omp session format (verified):** assistant `message.usage` carries `{input, output, cacheRead, cacheWrite, totalTokens, reasoningTokens, cost: {input, output, cacheRead, cacheWrite, total}}` plus `message.provider` (e.g. `openai-codex`) and `message.model`. `parseOhmypiSessionCostEventsSync` (`src/lib/cost-parsers/ohmypi-parser.ts:140`) emits per-message events with stable requestIds `ohmypi:<sessionId>:<entryId>` — the correct shape codex should mirror.
8. **ohmypi live reconcile is gated on a running agent:** `pi-cost-reconciler.ts` early-returns unless some RUNNING agent has `harness === 'ohmypi'`. Sessions from agents that exited before a tick are never swept; the manual route can't catch them up either (finding 1).
9. **Silent skips everywhere:** parsers return `null` on unreadable/unknown files and reconcile does `if (!session) continue;` — no log, no health signal. Acceptance requires loud surfacing.
10. **Existing tests are thin:** `src/lib/cost-parsers/__tests__/` has one synthetic fixture per harness (`codex/rollout.jsonl` 902 bytes, `ohmypi/rpc-toolcall.jsonl`). Claude-code parser tests live at `tests/lib/cost-parsers/jsonl-parser.test.ts`. None were derived from real session files.
11. **Pricing exists** for `gpt-5.5` (`src/lib/cost.ts:109`) and the rest of the gpt-5.x family — $0 is not a pricing-table gap.

## Requirements

### Functional

- **FR-1** Codex rollout files parse to **per-turn cost events** (`parseCodexSessionCostEventsSync`) with correct model id (from the most recent `turn_context` before each `token_count`), token counts (input, cached input, output), and USD computed from `getPricingSync('openai', model)`, charging cached tokens at the cacheRead rate and only the non-cached remainder at the input rate.
- **FR-2** Each codex cost event carries a stable `requestId` (`codex:<threadId>:<turnSeq>`), so re-sweeping a still-growing rollout imports only new turns and never duplicates or freezes totals.
- **FR-3** The codex parser has no hardcoded model fallback. A rollout with no `turn_context`/`task_started` model yields model `unknown` and a loud skip/warning — never silently priced as gpt-5.5.
- **FR-4** `reconcile({source:'codex'})` is invoked automatically by a cloister tick when a running agent has `harness === 'codex'` (mirroring `pi-cost-reconciler.ts`), and `POST /api/costs/reconcile` explicitly sweeps BOTH `ohmypi` and `codex` regardless of running agents (the catch-up path for exited agents).
- **FR-5** The ohmypi parser is validated against real multi-provider session fixtures. When an assistant message reports tokens but no inline `usage.cost`, cost is recomputed from the pricing table via `getPricingSync(provider, model)`; when pricing is also unavailable, the event surfaces a loud warning rather than silently recording $0.
- **FR-6** Unparseable or unrecognized session files surface loudly: reconcile returns `skipped: [{file, reason}]` alongside `imported`, and each skip logs a `console.warn` including the absolute session path.
- **FR-7** Each of the three harness parsers has a fixture-backed test suite derived from real session files asserting: model id, token counts (including cache read/write where the provider reports them), and computed USD.
- **FR-8** After a reconcile pass over the existing on-disk codex sessions (e.g. `agent-pan-2383-slot-*`), the per-issue cost drill shows the codex tier with its real model id and non-zero USD.

### Non-functional

- **NFR-1** No `execSync` in any server-reachable code (repo rule; reconcile paths run in the dashboard server).
- **NFR-2** Committed fixtures are sanitized: structural/usage fields preserved verbatim, prompt/response text redacted. No user content in the repo.
- **NFR-3** All cost writes go through `CostWriter.record()` — no new direct DB/archive writes (two-door rule).
- **NFR-4** The events archive is append-only; the design must never require updating an archived event (per-turn events satisfy this; session-level "update in place" designs do not).

## Design decisions (made here, not left to the executor)

- **D1 — Per-turn codex events, not session-level.** Mirror `parseOhmypiSessionCostEventsSync`: emit one event per `token_count` record using `last_token_usage`, requestId `codex:<threadId>:<seq>` (seq = 0-based index of the token_count record in the file). This makes growing files incrementally importable, keeps the archive append-only, and attributes turns to the model active at that point.
  - **Implementation checkpoint:** verify against a real multi-turn rollout that `last_token_usage` is genuinely per-turn (sums to `total_token_usage`). **Fallback if it isn't:** emit cumulative-delta events (current `total_token_usage` minus sum of previously emitted events for the file), same requestId scheme.
- **D2 — Session-level `parseCodexSessionSync` stays** (used by `runtimes/codex.ts` and `codex-conversation-parser.ts`) but drops the hardcoded fallback (FR-3). The new per-turn function lives alongside it in the same file.
- **D3 — Route sweep is the catch-up path.** The cloister tick stays gated on running agents (perf); the manual `POST /api/costs/reconcile` sweeps both sources unconditionally so historical sessions from exited agents can be imported.
- **D4 — Fixtures are harvested from real on-disk sessions** (codex: `~/.codex/sessions/` April–July files cover both flat-legacy and nested schemas; omp: `~/.omp/agent/sessions/` + any `agents/*/sessions/`), sanitized per NFR-2. Where a provider (kimi/GLM/MiniMax/Gemini) has no real session on disk, synthesize from the documented omp format and mark the fixture `// synthetic` in the test.
- **D5 — Live-run acceptance is satisfied against existing on-disk sessions** (PAN-2383 slot codex-homes) rather than launching a new tiered run: run the reconcile route, then assert the by-issue API shows the codex spend. A fresh tiered run is a bonus, not a gate.
- **D6 — Out of scope:** PAN-2387 items 1 (UNKNOWN bucket regrouping) and 2 (issue rollup vs model-row mismatch); memory-extraction $0 pricing; spend-report backfill tooling; classic `pi-parser.ts` changes; any dashboard UI work.

## Repo rules restated for the executor

- No `execSync` anywhere server-reachable; use async variants.
- Never hardcode a model fallback — fail loudly instead.
- Fake timers (`vi.useFakeTimers()`) for any delay/retry test (none expected here, but reconcile tick tests must not sleep real time).
- Two-door state rule: cost events only via `CostWriter.record()`.
- TLDR hook intercepts whole-file `Read`s — use offset/limit for full source.
- Quality gates before `pan done`: `npm run typecheck`, `npm run lint`, `npm test`.
