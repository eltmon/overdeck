# PAN-2890 — Agent pills: drill-down, context, and consistent scoped counts

**Issue:** https://github.com/eltmon/overdeck/issues/2890
**Status:** draft
**Author:** conversation (operator-directed), 2026-07-18

## Glossary

- **App bar** — the fixed top bar of the dashboard, rendered by `src/dashboard/frontend/src/App/AppChrome.tsx`. Its right side holds the status pills.
- **Pill** — a small rounded status chip in the app bar (e.g. "9 agents", "7 stopped").
- **Running-agents pill** — the green `{n} agent(s)` chip at `src/dashboard/frontend/src/App/AppChrome.tsx:206-210`. Today it is a plain `<span>`, not interactive.
- **Stopped-agents pill** — the amber `{n} stopped` chip rendered by `src/dashboard/frontend/src/components/StoppedAgentsBanner.tsx` (`variant="pill"`, mounted at `AppChrome.tsx:222`). Clicking opens a popover listing stopped agents with a "Restart all" button.
- **Popover** — the dropdown panel a pill opens (pattern: `StoppedAgentsBanner.tsx:215-247`, `DecisionsIndicator.tsx`).
- **Store** — the frontend Zustand store (`src/dashboard/frontend/src/lib/store.ts`), event-sourced from `/ws/rpc`. `selectAgents` yields `Agent[]`; `selectIssues` yields issues with `identifier` and `title`. No polling.
- **URL door** — the navigation pattern in `navigateForDecision()` (`src/dashboard/frontend/src/components/DecisionsIndicator.tsx:16-25`): `window.history.pushState({}, '', path)` followed by `window.dispatchEvent(new PopStateEvent('popstate'))`. App's popstate handler owns routing, so any component can navigate without threading callbacks.
- **Boot-reconciliation banner** — the separate boot-time hold surface (`BootReconciliationModal.tsx`, `GET /api/boot-reconciliation`). Out of scope except for its scope label (FR-5).

## Problem (operator report, 2026-07-18)

1. The stopped-agents popover rows show only `issueId` + `role` (`StoppedAgentsBanner.tsx:222-227`). No issue title, no stop reason, no timestamp — "not helpful if it doesn't have summary description".
2. Rows are not clickable. There is no path from a row to the issue or the agent's session.
3. The running-agents pill ("9 agents") is a non-interactive `<span>` — there is no way at all to see *which* agents it counts.
4. Three surfaces show three different counts at the same moment (boot banner "3 held", stopped pill "7 stopped", running pill "9 agents") with no scope labels explaining the relationship.
5. Operator reports some entries showing "Save Session". That string does not exist in `src/dashboard` (verified by grep 2026-07-18); origin unknown, needs a repro screenshot.

## Requirements

- **FR-1 (shared rows):** One shared agent-row component renders every agent list popover row: mono issue ID, issue title, role, and a context line (stop reason or model + relative last-activity time). Both pills use it.
- **FR-2 (clickable rows):** Clicking any agent row navigates to that agent's issue via the URL door (`/issues/<ID>`), and closes the popover.
- **FR-3 (running pill drill-down):** The running-agents pill becomes a button that opens a popover listing exactly the agents counted by `runningAgentCount`, using FR-1 rows.
- **FR-4 (stop reason):** A pure function derives a one-line stop description from `Agent` fields, in priority order: `pausedReason` → `troubled` (+ failure count) → `stoppedByUser` → "stopped cleanly".
- **FR-5 (scope labels):** Each popover header states its scope in words: stopped pill = "stopped pipeline agents, last 7 days"; running pill = "running now". (The boot banner already states "from the boot at <time>"; it is unchanged.)
- **FR-6 (Save Session):** Identify the surface rendering "Save Session". Decision rule: if rendered by Overdeck frontend/server code, fix it under this issue; if it originates inside an agent terminal pane (harness TUI output), document the meaning in `docs/COMMAND-DECK-RESTORATION.md` and note it as external. Blocked on operator screenshot; if none arrives before the rest of the work merges, record the item as not-reproduced in the issue and close it out with the rest.
- **NFR-1 (no new fetching):** All data comes from the existing store (`selectAgents`, `selectIssues`). No new REST endpoints, no polling, no `useQuery`.
- **NFR-2 (style guide):** Follow the pan-style-guide rules already embodied by neighboring pills: mono for issue IDs, `text-muted-foreground` for secondary text, no decorative color, warning tones only on the stopped pill, `aria-expanded` on the trigger, outside-click + Escape to close (copy the `DecisionsIndicator` pattern).

## Design decisions (made here, not by the implementer)

- **D-1:** Row click navigates to `/issues/<ID>` (the issue drawer route `navigateForDecision` already uses for agent decisions) — NOT to `/command-deck/<project>/<issue>`. Reason: `/issues/<ID>` works from every tab and App already routes it.
- **D-2:** The running set is defined by the existing predicate in `App.tsx:536-539` (`['running', 'active', 'starting', 'thinking', 'working'].includes(a.status)`). Extract it as `isRunningAgentStatus(status)` and use it in both the count and the popover so they can never disagree.
- **D-3:** The stopped set definition in `StoppedAgentsBanner.tsx:64-115` (pipeline roles, 7-day recency, phantom-stop exclusion, dedupe by issue) is correct and unchanged — only its presentation changes.
- **D-4:** Issue titles come from `selectIssues` matched on `identifier.toUpperCase()`; when no issue is in the store (e.g. LEX-1 from an excluded project), the row shows the bare ID and the popover still works. Never fetch a title.
- **D-5:** Per-row restart buttons are NOT added — "Restart all" stays as-is. The operator asked for visibility, not new controls; `pan start <id>` and the issue drawer cover individual restarts.

```tsx
export function describeAgentStop(agent: Agent): string {
  if (agent.pausedReason) return `paused: ${agent.pausedReason}`;
  if (agent.paused) return 'paused';
  if (agent.troubled) return `troubled (${agent.consecutiveFailures} failure${agent.consecutiveFailures === 1 ? '' : 's'})`;
  if (agent.stoppedByUser) return 'stopped by operator';
  return 'stopped cleanly';
}

export function navigateToIssue(issueId: string): void {
  const path = `/issues/${encodeURIComponent(issueId)}`;
  if (window.location.pathname !== path) window.history.pushState({}, '', path);
  window.dispatchEvent(new PopStateEvent('popstate'));
}

export function AgentPillPopoverRow({ agent, title, contextLine, onNavigate }: {
  agent: Agent; title?: string; contextLine: string; onNavigate?: () => void;
}): JSX.Element
```
