## Glossary

| Term | Definition |
| --- | --- |
| **Project** | Long-lived identity for a thing being worked on: stable id, primary path, optional secondary target paths. Today: a `projects.yaml` entry keyed by yaml key, no durable id. |
| **Workspace** | One in-flight session unit against a project: a working directory, git posture, layout, memory home. Today: implicit — a `workspaces/feature-<issue-id>/` worktree derived 1:1 from an issue. |
| **Workspace kind** | Discriminator `main \| issue \| scratch`. `issue` = today's pipeline worktree. `main` = the implicit workspace sitting on the project's primary path. `scratch` = user-named, non-pipeline. |
| **Memory home** | Per-scope directory under `~/.overdeck/memory/` holding observations JSONL, pending turns, status.json, summaries, archive. **Already exists**, keyed `(projectId, issueId)` — this PRD re-keys it to `(projectId, workspaceId)`. |
| **Observation** | One structured record per agent turn (`MemoryObservation` in contracts), extracted from the transcript by a cheap model, appended to daily JSONL and indexed into per-project FTS. |
| **Two doors** | The single-source-of-truth tenet: each domain has exactly one read path (resolver) and one write path (writer). No other code touches the store. |
| **State home** | Durable, git-backed per-project state (PAN-2541): `~/.overdeck/state/<project>/` on the `overdeck-state` branch when migrated; legacy fallback is domain dirs under the project root `.pan/`. Resolved by `src/lib/state-home.ts` / `src/lib/state-plane.ts`. |
| **Runtime plane** | Disposable SQLite cache (`~/.overdeck/overdeck.db`) rebuildable from durable sources (PAN-1908). The new `projects`/`workspaces` tables live here. |
| **Backfill** | Reconstructing runtime rows or observations from durable sources (worktrees, metadata.json, Claude JSONL transcripts). |
| **Identity record** | `metadata.json` in a workspace's memory home carrying the workspace row's full identity — the durable rebuild source for `main`/`scratch` rows. |

## Decisions (made here so the executor doesn't have to)

- **D-1 — Workspace ids are UUIDs for all kinds.** Backfilled `issue` workspaces get fresh UUIDs; the issue linkage lives in `workspaces.issue_id`. Memory homes are keyed by workspace UUID; `metadata.json` inside carries the name. (Fixes Subspace's rename-orphans-memory wart.)
- **D-2 — No `session-context.md` artifact.** The issue specifies a SessionStart-built `session-context.md`. The existing prompt-time injection (`injectPromptTimeMemory` at UserPromptSubmit + spawn) already delivers status + observations + summaries at higher fidelity. Building a parallel SessionStart file would duplicate it. The injection path is extended to workspace scope instead. This supersedes the issue's "Memory home / hooks" table where it conflicts.
- **D-3 — Search scopes are flags, not new subcommands.** `pan memory search <q> [--workspace <id|name>] [--project <p>] [--global]` extends the existing `search` verb. Default remains project scope. (The issue's `workspace-search`/`project-search`/`global-search` subcommand names came from the Subspace CLI; Overdeck's existing verb takes flags.)
- **D-4 — `pan workspace destroy` keeps its name.** The issue says `pan workspace delete`; the CLI already ships `destroy`. Extend `destroy` with `--purge-memory`. Do not add a `delete` alias.
- **D-5 — Memory-home migration maps by issue id, not by stored `workspaceId`.** Existing observation rows' `workspaceId` values are untrusted legacy strings. The migration resolves each existing `~/.overdeck/memory/{projectId}/{issueId}/` directory to the backfilled issue-workspace row **via `issueId`**, moves the directory to `{projectId}/{workspaceUuid}/`, writes `metadata.json`, and rewrites `memory_fts.workspace_id` by matching `issue_id`.
- **D-6 — `MemoryIdentity.issueId` and `MemoryObservation.issueId` become nullable** (`Schema.NullOr(IssueId)`). `projectId` + `workspaceId` become the primary identity pair. Null `issueId` means a `main`/`scratch` workspace turn.
- **D-7 — FTS `scope` column keeps the literal `'workspace'`.** With per-workspace keying, the hardcoded value at `observations.ts:167` becomes semantically correct; reset markers already support `project|workspace|issue|session` scopes. No scope-column change.
- **D-8 — Boot seeding happens in the dashboard server boot path** (where the DB is initialized, same phase as `startTranscriptPoller()` in `src/dashboard/server/main.ts:451`), not in every CLI invocation. CLI commands read through the resolver and error with guidance if the tables are empty (`run pan up or pan admin db rebuild-workspaces`).
- **D-9 — Committed memory artifacts use a new `memory` state domain** with `summaries/` and `pins/` subdirectories, added to `STATE_BRANCH_PATHS`. On migrated projects (overdeck included) this resolves to `~/.overdeck/state/<project>/memory/` on `overdeck-state`; on non-migrated projects `resolveStateDomainPathSync` places it under the project root `.pan/memory/` — both handled by the resolver, no special-casing.
- **D-10 — Event payloads gain `workspaceId` additively.** No payload field is removed or renamed; consumers that ignore it keep working.

## Requirements

### Functional

- **FR-1** `projects` and `project_targets` tables exist in `overdeck.db`; `projects.yaml` entries are upserted into `projects` on dashboard boot; `pan project add` creates rows; `pan project add-target` creates `project_targets` rows.
- **FR-2** `workspaces` table exists with `kind CHECK (kind IN ('main','issue','scratch'))`, non-unique `path`, `branch_name`, `parent_branch`, `parent_branch_guessed`, `is_git_repository`, `issue_id`, `layout_config`, `is_favorite`, `is_archived`, `title`, timestamps. Every existing `workspaces/feature-*/` worktree has a `kind='issue'` row after backfill.
- **FR-3** All reads of `projects`/`workspaces` go through `src/lib/workspaces/resolver.ts`; all writes through `src/lib/workspaces/writer.ts`; a lint-wired guard script fails the build on SQL touching those tables outside the two door files (+ schema.ts migrations).
- **FR-4** `conversations.workspace_id` and `agents.workspace_id` columns exist (nullable). Workspace deletion nulls `conversations.workspace_id` via the writer and never deletes conversation rows or JSONL files.
- **FR-5** `pan workspace new <name>` creates a `scratch` workspace (shared by default, `--isolated` creates a worktree); `pan workspace main` resolves-or-creates the project's singleton `main` workspace; `pan workspace get|activate|archive <ws>` work; `pan workspace list` gains `--kind` and `--archived`; `pan workspace destroy` gains `--purge-memory`.
- **FR-6** `pan start`/`pan plan` create the `kind='issue'` workspace row (via the writer) before the worktree is created; close-out sets `is_archived=1` and preserves the memory home; deep-wipe never touches `~/.overdeck/memory/`.
- **FR-7** Memory homes are keyed `~/.overdeck/memory/{projectId}/{workspaceId}/`; each contains `metadata.json` with the full workspace identity; a migration moves existing issue-keyed homes and rewrites `memory_fts.workspace_id`.
- **FR-8** Observation capture and prompt-time injection work for conversations in `main`/`scratch` workspaces (null `issueId`), resolved via `conversations.workspace_id`.
- **FR-9** `pan memory search` supports `--workspace`, `--project` (default), `--global` scopes against the existing FTS.
- **FR-10** `pinned_docs` table exists (scope `workspace|project`); `pan memory pin|unpin` manage pins; workspace-scoped pins are removed with the workspace, project-scoped survive; pins are included in prompt-time injection.
- **FR-11** Daily summaries and pins are mirrored to the `memory` state domain (`memory/summaries/`, `memory/pins/`) through `resolveStateDomainPathSync`; rolling observations are never committed.
- **FR-12** `pan memory backfill` regenerates observations from `~/.claude/projects/*/*.jsonl` transcripts, mapping each session's `cwd` to a workspace row.
- **FR-13** `pan admin db rebuild-workspaces` reconstructs `projects` + `workspaces` from projects.yaml, worktree scan, and memory-home `metadata.json` (with `--dry-run`, `--verbose`).
- **FR-14** Sidebar shows a **Workspaces** section (favorites first, then recency; kind icons; pipeline-phase badge for issue kind; archived collapsed; flat↔grouped toggle) above the existing **Projects** section.
- **FR-15** A workspace view renders terminals, conversations, memory surface (status headline + observation timeline), and — for issue kind — vBRIEF + pipeline status; `layout_config` persists/restores the arrangement.
- **FR-16** A Cmd-K switcher navigates workspaces across projects (fuzzy name, most-recent-first).
- **FR-17** A no-loss audit test enumerates the pre-change sidebar/dashboard affordances and asserts each has a home in the new layout.
- **FR-18** A project whose primary path is not a git repo gets a functional `main` workspace with `is_git_repository=0`.

### Non-functional

- **NFR-1** No hardcoded model fallback anywhere new; extraction continues through the existing provider policy.
- **NFR-2** All retry/delay/poll tests use fake timers (`vi.useFakeTimers()` + `advanceTimersByTimeAsync`); no real `setTimeout` waits.
- **NFR-3** No `execSync` in any code reachable from the dashboard server; async primitives only (incl. `sendKeysAsync` if tmux is touched).
- **NFR-4** `projects`/`workspaces` remain runtime-plane: fully reconstructible by FR-13 from durable sources; losing `overdeck.db` loses nothing.
- **NFR-5** Migration is idempotent and non-destructive: re-running the memory-home migration or backfill is a no-op; no observation file is ever deleted by migration.
- **NFR-6** All existing pipeline flows (`pan plan`, `pan start`, `pan review`, `pan test`, `pan close`) pass their current tests unchanged.

## Intersecting repo rules (restated — they bind every work item)

- **Fake timers** for anything with delays/polling/retries (`vi.useFakeTimers()` + `advanceTimersByTimeAsync`); never real waits, never `maxForks: 1` masking.
- **No `execSync`** in dashboard-server-reachable code; use `execAsync`/`spawn`; sleep via `await new Promise(r => setTimeout(r, ms))`.
- **Async tmux only** (`sendKeysAsync`); load-buffer/paste-buffer pattern for message delivery.
- **JSONL session files are sacred** — backfill and migration never modify `~/.claude/projects/*/*.jsonl`.
- **No hardcoded model fallback** — extraction stays behind the provider policy; an unset default fails loudly.
- **Dashboard runs Node 22 built dist** — after server changes: `npm run build`, then restart via `pan up`; never Bun, never tsx.
- **Boot-path changes must be runtime-boot-tested** before touching the live server (WI-3's boot seeding qualifies) — validate on a throwaway instance; `pan restart --health-timeout 120` minimum.
- **Beads, not TODO lists**, for task tracking during implementation; commit early and often on main-adjacent work; never `git stash`.
- **Deep-wipe / destructive HTTP**: never send speculatively; WI-4's deep-wipe verification is code-inspection + unit tests, not live endpoint calls.
- **Refactor no-loss audit** (WI-12) gates retiring any existing dashboard surface.
