## Glossary

- **ACP** — Agent Client Protocol (https://agentclientprotocol.com): JSON-RPC over stdio (ndjson) between a *client* (us) and an *agent* (a CLI like `kimi acp`). Lifecycle: `initialize` → `authenticate` → `session/new` (or `session/load` to resume) → `session/prompt`; the agent streams `session/update` notifications and makes reverse requests (`session/request_permission`, `fs/*`, `terminal/*`).
- **effect-acp** — t3code's self-contained Effect implementation of ACP (`packages/effect-acp` upstream). Depends only on `effect`. Exports `./client`, `./agent`, `./schema`, `./rpc`, `./protocol`, `./errors`, `./terminal`.
- **AcpSessionRuntime** — t3code's reusable client runtime over effect-acp (`apps/server/src/provider/acp/AcpSessionRuntime.ts`, 1005 lines): spawns the CLI, owns the session lifecycle, exposes `start`/`prompt`/`cancel`/`getEvents` and config/model/mode setters.
- **ACP host** — (new, ours) the persistent per-agent process the tmux session runs (`node dist/acp-host.js`), modeled on `src/lib/codex/app-server-host.ts`: owns the AcpSessionRuntime, exposes a per-agent unix socket + bearer token for orchestrator delivery, renders the conversation to the pane, writes a transcript JSONL.
- **Behavior matrix** — `packages/contracts/src/harness-behavior.ts`: per-harness capability record (`launchCommandKind`, `transcriptKind`, `feedKind`, …) that drives launcher, delivery, discovery, and frontend.
- **Harness** — the union `'claude-code' | 'ohmypi' | 'codex'` in `packages/contracts/src/types.ts:70`; this issue adds `'acp'`.

## Key design decisions (autoDecisions)

1. **Vendor as `packages/effect-acp` workspace package**, not `src/lib/acp/vendor/`. Keeps upstream import specifiers (`effect-acp/client`) and file layout identical for cheap future diffs; escapes the src-only file-size ratchet (schema.gen.ts is 10,375 lines); `effect: "catalog:"` resolves against Overdeck's catalog exactly as upstream's.
2. **Generic `acp` harness value** with per-provider support modules (`src/lib/acp/kimi.ts` first), not a `kimi-code` harness. This is the whole leverage of ACP — one client, many agent CLIs (Cursor/Grok/Gemini later are ~100-line modules).
3. **Persistent transport = ACP host process** mirroring codex app-server-host: tmux runs `node dist/acp-host.js`, which spawns `kimi acp` via AcpSessionRuntime, renders updates to the pane, exposes `sockets/acp-<id>.sock` + token for delivery. Unlike codex (whose sync adapter kept a one-shot `exec resume` path), ACP's `sendMessage` posts to the host socket from day one.
4. **Kimi routing stays opt-in** (`providerHarnesses.kimi: acp`); the operator deliberately routes kimi via claude-code today — the built-in default must not flip.
5. **Permissions v1 = `auto` mode only**; interactive prompt-mode wiring into the AUQ/pending-input flow is a NonGoal (follow-up issue).
6. **Cost/token usage v1 = none** (adapter returns undefined/zero); ACP has no standardized usage reporting. Follow-up issue.
7. **Start Kimi's support module from Cursor's shape** (no extension wrapper), not Grok's (Grok needs an out-of-band prompt-complete wrapper).
8. **Test layout**: keep upstream colocated `src/*.test.ts` in the vendored package; add `packages/effect-acp/src/**/*.test.ts` to vitest's include globs.
