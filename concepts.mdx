Learn the fundamental concepts that power Overdeck.

## Command Deck

The live development surface where you and your agents work together. A full-height **project sidebar** on the left owns project selection; everything to its right is scoped to the project you pick and updates in real time:

- **App bar**: the project crumb, a project-scoped search, and status pills at a glance (Deacon health, running-agent count, stopped agents). No more persistent banners; attention items surface as compact pills.
- **Tab strip**: every issue, agent, and conversation you open becomes a tab. Scroll on overflow, middle-click to close, right-click to pop out to a window or close others, and **split the view** (drag a tab to a pane's edge) to watch two panes side by side.
- **Pane body**: the working area. A project's **Home cockpit** (issue swimlanes, recent spend, a stuck count), an **issue view** (a title row with the issue's state, cost and next actions; a pipeline strip; a needs-you banner when you must act; and tabs led by the agent's conversation (Conversation, Tasks, Plan, Changes, Activity, Discussion, Skills, Details). It is the same view the issue drawer shows), or an agent's live conversation and terminal.
- **Activity feed**: the **Feed** tab on `/activity`, with **Needs-you / Project / Global** scopes, so anything waiting on your input is one page away; the top bar's **Needs you** menu lists the same items. Inside Project and Global, the **All / Chats / Activity** tabs: All lists what changed (created, ended, reported, merged) rather than every busy conversation, Chats lists the conversations active in the last day, and a gauntlet run appears as one card.

Command Deck is where you *manage the conversation*, not just watch a workflow run. The center pane streams the agent's turn-by-turn reasoning and tool calls as they happen, the left column keeps the project's conversations, issues and workspaces one click away on every page, and the top bar's Needs you menu and the Activity feed on `/activity` collect anything that needs your attention.

Everything is alive: no refresh buttons. Domain events trigger small, informative UI motion: cost increments animate, tool names fade in and out, status dots pulse.

Details holds the status, the pipeline with per-agent cost, the ship progress, the workspace, and (in the Command Deck tab) the launcher and agent dock.

### What You Can Do From Command Deck

- **Review diffs as they land**: every file change appears inline as the agent works. Open the diff panel for a turn-by-turn view, or hit "vs main" to see the full picture.
- **Talk to agents**: type in the composer to steer an agent mid-task. Point it at the right file, correct its approach, or tell it to rethink.
- **Fork or hand off**: fork a conversation into a new one that starts from a summary of the work, or hand off to a new conversation on a different model. A conversation's model is fixed once it starts.
- **See the plan**: xBRIEF work plans render as interactive DAGs with dependencies, acceptance criteria, and live status tracking.

## Agents

Agents are AI coding assistants that work on the tasks you assign. You direct them from Command Deck: watch them code in real time, send messages to steer their approach, fork or hand off the conversation, and review their diffs inline as they go.

Agent types:
- **Implementation (work) agents**: work on features, bugs, and refactoring in isolated worktrees
- **Planning agents**: write a PRD and an xBRIEF plan before work starts
- **Review and test agents**: check finished work on the pull request

You can manage agents via Command Deck, the CLI, or the REST API.

## Cloister

Cloister is the agent watchdog. It checks each running agent's health, pokes or nudges stuck agents, restarts crashed ones, and recovers stalled reviews. See [Cloister](/features/cloister).

## Planning

`pan start <issue>` plans the issue before work starts: a planning agent writes a PRD and an xBRIEF plan, and they are committed under `.pan/` in your repo. `pan start --plan skip` skips planning. See [Planning](/features/planning).

## Workspaces

**Workspaces are git worktrees**: isolated working directories for each issue. Each workspace:

- Has its own feature branch (e.g., `feature/pan-123`)
- Shares git history with the main repo (no separate clone)
- Can include Docker containers for full development environments
- Is located at `{project}/workspaces/feature-{issue-id}/`
- Keeps runtime files in `.overdeck/`; planning files live in `.pan/` (see [State model](/reference/state-model))

This allows multiple agents to work on different features simultaneously without conflicts.

Workspaces support both local execution and remote execution via Fly.io for cloud-hosted agent environments.

### Main Project Branch Convention

The main project directory should **always** stay on the `main` branch. All feature work happens in workspaces (git worktrees), never in the main project. This ensures specialists always find the correct code, and merge operations have a clean target.

### Docker Integration

Workspaces can include Docker containers for full development environments. Supports both local execution and remote execution via Fly.io.

## Specialists

When a work agent finishes, a review agent and a test agent check the work on the pull request. When the PR is approved and its checks are green, you click **Merge**, or let [auto-merge](/configuration/auto-merge) ship it. See [Specialists](/features/specialists).

## Model routing

Each role runs on a model you choose, usually through one of three workhorse slots. Planned work can also be staffed by difficulty with tiered execution. See [Model routing](/configuration/model-routing) for how roles, workhorse slots, harnesses and tiered execution fit together.

## Skills

Overdeck ships more than 120 skills in the SKILL.md format. `pan sync` installs them for Claude Code and for the harnesses that read `~/.agents/skills`, such as Codex and Pi.

- Development workflows (feature work, bug fixing, refactoring)
- Code review (correctness, security, performance)
- Incident response and debugging
- Codebase onboarding
- Project-specific knowledge capture

See [Skills](/features/skills).

## Convoys

A convoy is the full review mode: four reviewers (security, correctness, performance and requirements) check one pull request in parallel, and a review parent writes the verdict. Turn it on with `roles.review.mode: full`. See [Convoys](/features/convoys).

## Issue Tracker Integration

Overdeck integrates with 5 issue trackers:

- **GitHub Issues**: Full integration with PRs and status updates
- **Linear**: Full integration with cycles, labels, and status updates
- **GitLab Issues**: Issue tracking and MR management
- **Rally (CA Agile Central)**: Enterprise issue tracking
- **Jira (Cloud and Data Center)**: Atlassian issue tracking

The dashboard displays issues from all configured trackers in a unified kanban board with cost badges, agent status indicators, and workspace controls.

## Cost Tracking

Per-issue, per-stage token costs with dashboard analytics. Every agent session is tracked with:

- Model and provider attribution
- Token counts (input/output)
- Dollar costs per stage (planning, work, review, test, merge)
- Daily cost summaries on the Board view
