# Order Books

An order book is a list of issues the Flywheel works through, in the order you set. It replaces a prose list of “special orders” with a durable queue: the book sets which issues run in parallel, which run one at a time, what each issue waits for, and when pickup pauses, and the Flywheel follows it.

Use an order book when the order of work matters: a migration, a refactor that must not overlap with other work, or a release push whose scope must not expand into the normal backlog.

## Order books and the backlog

The backlog sequencer is Overdeck's ranked pool of possible work. An order book is a deliberate subset with explicit execution order.

Membership in the active book counts as operator release, even when:

```text
flywheel.auto_pickup_backlog=false
```

With that setting, an issue outside the active book still needs the `released` label before the Flywheel picks it up on its own. The Flywheel can work through the book without opening the rest of the backlog. A manual `pan start <id>` works for any issue, in the book or not.

## The four phases

The page shows each book in one phase. Overdeck derives the phase from the book's stored status every time it reads the book, and dispatch uses the same rule, so the page cannot disagree with what the Flywheel does.

| Phase | What it means | How a book gets here |
| --- | --- | --- |
| **Draft** | Nothing starts from a draft. | **+ New book** creates one. **Move back to draft** and **Restore as draft** return a book here. |
| **Queued** | The book waits in line, shown with its place (`#2`, `#3`). | **Queue book** on a draft. |
| **Active** | The Flywheel works from this book. Its issues are cleared to start, and `pan start` still works for anything else. | The first queued book that still has open issues becomes active. |
| **Archived** | Kept for the record. Its issues are free to join another book. | **Archive** on a draft or queued book. |

Only one book is active at a time. Queue order is the order the books were created; to run a later book first, move the books ahead of it back to draft.

A book is **finished** when every issue in it has landed or is parked. The Flywheel skips a finished queued book and works from the next one; nothing is stored, the rule is derived on every read. The page marks the book **Finished** and offers **Archive** to tidy the list. A book counts as finished only when the dashboard's issue cache reports every issue closed or parked; the dashboard fetches issues that closed outside the cache window (14 days by default) from the tracker before it decides. Without that evidence the book keeps its place.

## Build a book

Open **Order books** in the dashboard, or go directly to `/orders`.

1. Click **+ New book**, enter a name, and click **Create book**.
2. Add issues from the **Add issues** panel. With an empty search it lists the top of your backlog; type to search open issues by ID, title or label. **Add to** picks the lane. You can also drag a row from the panel onto a lane. Adding an issue only changes the list; work starts when the book is active.
3. Put work that can overlap in the **Parallel lane**. Put work that would collide in the **One-at-a-time lane**.
4. Drag rows to change their order, or use **Run one at a time** and **Run in parallel** on a row to move it between lanes.
5. Fix everything the problems box lists, then click **Queue book**. The book becomes queued, and active once the books ahead of it finish, are archived, or are moved back to draft.
6. If the Flywheel is stopped when the book is active, click **Start Flywheel**.

To rename a book, click its name. The **⋯** menu also offers **Rename**, **Copy book ID for the CLI** and **Archive**.

### Add from other surfaces

You can promote an issue without leaving its current view:

- **Add to order book** appears in the shared issue action menu used by the board and issue drawer.
- Backlog rows expose **+ Order book** and ask only whether the issue belongs in Lane A or Lane B.

These are narrow add actions. Editing, ordering and phase changes stay on `/orders`. An issue that belongs to a book shows its position, such as `A3`, and links to `/orders?book=<id>`.

## Read the page

### The issue list

Each book has one issue list with two lanes, stacked full width.

- **Parallel lane** (`Lane A`): up to the limit you set with **−** and **+**, issues run at the same time.
- **One-at-a-time lane** (`Lane B`): runs top to bottom, one issue at a time.

Every row shows the position, the issue ID, the full title, and one status. A muted second line lists only what applies: `after <issue>`, `re-check PRD first`, `plan when it starts` or `no PRD`. Landed issues collapse behind **Show n landed**.

The status is either what the issue is doing or the one reason it waits:

| Status | Meaning |
| --- | --- |
| **Working** | An agent is working on the issue. |
| **In review** | The issue is in review or ready to merge. |
| **Landed** | The issue is closed. |
| **Waiting for PAN-…** | A prerequisite has not landed yet. |
| **Waiting for a free slot (2 of 2 running)** | The parallel lane is full. |
| **Waiting its turn** | Another issue in the one-at-a-time lane is running. |
| **PRD needs a re-check first** | The issue is set to re-check its PRD against `main` before it starts. |
| **Pickup paused** | Pickup is paused for this book. |
| **Starts next** | Nothing holds the issue back; the Flywheel picks it up next. |
| **Ready, Flywheel is stopped** | Nothing holds the issue back, but the Flywheel is not running. |
| **Not queued yet**, **Book is not active yet**, **Not started** | The book is a draft, queued, or archived. |

**Options** on a row sets **Start only after these issues land**, **Re-check the PRD against main before starting**, and **Write the plan when it starts**.

### Pause pickup

On the active book, **Pause pickup** asks for a reason. Work already running finishes; nothing new starts from the book until you click **Resume pickup**. While pickup is paused the page says who paused it, when, and why.

### Problems

The problems box lists what must be fixed before a draft can be queued:

- an issue is closed or cannot be resolved as open (**Remove** takes it out of the book);
- an issue belongs to another book that is not archived (**Remove** takes it out);
- a prerequisite is missing;
- prerequisites form a cycle;
- a one-at-a-time issue has no draft PRD or canonical spec;
- the book has no issues (`empty-book`); or
- the shared issue store is unavailable or empty (`issue-store-unavailable`): run `pan up` once, then retry.

A closed issue in a queued or active book is not a problem: it has landed. A one-at-a-time issue marked **Write the plan when it starts** turns the missing-PRD result into a warning. Warnings stay visible but do not block queueing.

### More settings

**More settings** holds the **Extra instructions file**, a markdown file added to every issue's kickoff brief, and **Preview what the Flywheel receives**.

The Flywheel page shows the active book's issue list read-only and links to `/orders?project=<key>&book=<id>`.

### Pick the project

Order books are per-project state, and the page header carries a **Project** picker listing every project Overdeck has registered. It opens on the project the server resolved for you, and choosing another one reloads the page against that project's books: every read and write the page makes is scoped to the selection, so you cannot edit one project's book while looking at another's.

The selection is mirrored into the URL as `/orders?project=mind-your-now`, which makes it a shareable deep link: opening that URL selects the project before the first load. Without the parameter the page shows the project containing the dashboard server's own working directory, exactly as it did before. Add `book=<id>` (`/orders?project=mind-your-now&book=2026-08-01-frontend-sweep`) to open a specific book; without it the page opens the active book.

## Use the CLI

The dashboard is the complete editor, but the CLI covers common create, inspect, lane, and start operations:

```bash
pan orders create "Refactor P3 remainder"
pan orders list
pan orders show 2026-07-18-refactor-p3-remainder

pan orders add 2026-07-18-refactor-p3-remainder PAN-2445
pan orders add 2026-07-18-refactor-p3-remainder PAN-2233 --lane B --reverify
pan orders move 2026-07-18-refactor-p3-remainder PAN-2445 --lane A --order 1
pan orders remove 2026-07-18-refactor-p3-remainder PAN-2445
```

`add` defaults to Lane A. `--after <issue>` inserts after an existing item in the target lane. `--reverify` keeps the issue held until its PRD has been checked against current `main`. See [pan orders](/cli/pipeline-commands#pan-orders) for the full option reference.

Queue the validated draft from `/orders` or from the terminal, then start it with either command:

```bash
pan orders queue 2026-07-18-refactor-p3-remainder
pan orders start 2026-07-18-refactor-p3-remainder
pan flywheel start --orders 2026-07-18-refactor-p3-remainder
```

`queue` is the CLI form of the dashboard's **Queue book** action: it moves a draft to the queue. It refuses a book that is not a draft. The CLI `pan orders queue` and `pan orders start` skip the problems check; fix problems on `/orders` first.

`pan orders list` shows each book's phase: `active`, `queued #<n>`, `draft` or `archived`, with ` (finished)` when every issue has landed or is parked. A finished queued book shows `queued (finished)` with no number. `pan orders list` prints the dashboard's phases when the dashboard is running and derives them locally otherwise. Three more verbs move a book between phases:

```bash
pan orders unqueue 2026-07-18-refactor-p3-remainder    # queued → draft
pan orders archive 2026-07-18-refactor-p3-remainder    # draft or queued → archived
pan orders unarchive 2026-07-18-refactor-p3-remainder  # archived → draft
```

`unarchive` is refused, with `cannot be restored: <ISSUE> already belongs to order book <otherId>`, when one of the book's issues has since joined another book that is not archived. The dashboard's **Restore as draft** follows the same rule.

`pan orders start <id>` and `pan flywheel start --orders <id>` both open the one `conv-flywheel` conversation with the book named in its `/pan-flywheel` prompt. They differ when a flywheel is already running: `pan orders start` leaves it running and returns without naming the new book to it, while `pan flywheel start --orders` refuses with "already running" (`pan flywheel stop` first). A paused flywheel makes both refuse; resume it (`pan flywheel resume`) or replace it (`pan flywheel start --fresh --orders <id>`).

### Work on another project's books

Every `pan orders` verb takes `--project <key>`, naming a project from your registry, so you do not have to `cd` into a project to manage its campaign:

```bash
pan orders list --project mind-your-now
pan orders queue 2026-08-01-frontend-sweep --project mind-your-now
```

Without the flag, the command resolves the project that contains your current directory, as before. An unregistered key fails with `Unknown project: <key>` instead of reporting the book as missing.

## What finished means

A book is finished only when it has at least one issue and every issue is terminal. For order-book progress, terminal means either:

- the issue is closed; or
- the issue carries the `parked` label.

The server derives this result from canonical issue state. The orchestrator cannot declare a book finished through prose or a status message. The page marks a finished book **Finished**, and `pan orders list` marks it `(finished)`.

## Reports and what comes next

The flywheel loop writes its run report to `.pan/flywheel/report.md` when it stops (`pan flywheel stop`) or when asked (`pan flywheel report`), and records substrate fixes and learnings in `.pan/flywheel/state.md`. Both are committed; git history is the archive. See [docs/FLYWHEEL.md](https://github.com/eltmon/overdeck/blob/main/docs/FLYWHEEL.md).

The active book's issues count as released for pickup; queued books wait their turn. A finished book is skipped, so the next queued book becomes active on its own. A book that is stale but still has open issues keeps the slot: archive it (`pan orders archive <id>`) or move it back to draft. If you do not want a book's issues picked up, keep it as a draft.
