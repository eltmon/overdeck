# Beads and Dolt

Overdeck uses Dolt as the authoritative beads store. Durable beads history
travels on the project's git remote as `refs/dolt/data`; it does not live on the
`overdeck-state` branch.

Each project has one local Dolt home at
`${OVERDECK_HOME}/state/<project>/.beads/`. Project checkouts and workspaces use
`.beads/redirect` to share it. `pan sync` configures the project remote and runs
`bd bootstrap` to hydrate or adopt a newer remote schema.

Use `pan beads claim|update|close|create|dep|delete` for mutations. Direct
mutating `bd` commands are rejected in agent environments. Read-only commands
such as `bd list`, `bd show`, and `bd ready` remain available.

The dashboard synchronizes in the background. The Beads rail displays its last
successful sync and marks results stale when pulling or schema inspection fails.
Its periodic UI refresh does not contact the git remote.

Before a project's first cutover, run `pan admin beads reconcile <project>` and
review the generated no-loss report. Schema migration is a designated-operator
procedure: unify the local home, migrate exactly one clone with
`BD_ALLOW_REMOTE_MIGRATE=1 bd migrate`, publish it, and run `bd bootstrap` on all
other machines.

`.beads/issues.jsonl` is a validated `--all` recovery export only. Do not read it
as current task state or edit/merge its lines.
