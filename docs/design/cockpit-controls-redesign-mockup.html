Overdeck · design proposal

Cockpit controls: resume session, policies & work overrides

Three surfaces in the issue cockpit share one problem: they present actions and state without identity or structure. Each section below recreates the current UI, then proposes a replacement built from the dashboard's own tokens (DM Sans · 500, SF Mono for identifiers, the 8%/32% badge formula, amber = human, blue = machine, emerald = outcome).

01 · Resume session

A resume affordance that says what it resumes

Today the resume affordance is a lone filled-blue button floating between the tab bar and the issue card. It names no issue, no agent, no session — and blue is the wrong signal: blue means a machine is working, but a stopped session is waiting on you, which is amber's job. The same problem repeats wherever several stopped sessions appear together: nothing binds a session to its issue.

Design notes

  • Identity travels with the action. Every resume affordance leads with the issue pill (PAN-2829, SF Mono) and the agent id, so ownership survives multi-pane layouts, lists, and recovery modals.
  • Amber, not blue. A stopped-but-resumable session is a human-must-act state — the one colored signal on the card is the amber Stopped badge. The CTA stays primary-indigo; the current --info fill misreads as "machine running".
  • Answer the questions the button raises. Role, model, harness, stopped-for duration, spend, and a one-line "where it left off" — everything you'd otherwise dig out of the crew card or tmux.
  • One row, one signal. List rows keep taxonomy neutral (muted role/model text), reserving color for cost (cyan, tabular numerals) per the style guide.
  • "Start fresh…" sits beside resume as the ghost secondary — today reset-session hides in a context menu while resume floats alone.
02 · Policy override chips

Override chips that parse at a glance

The strip next to the Policies button renders each override as a mid-dot run-on — "work · GPT-5.6 Sol · replaces crews" — where key, value, and side-effect all share one voice, and clearing an override means opening the panel and hunting for the right reset link. "restart pending" is a warning styled like just another chip.

Design notes

  • Two-cell chips. A muted key cell (work model) and a foreground value cell (GPT-5.6 Sol) replace the mid-dot run-on; the override dot marks it as a deviation from defaults, matching the dot inside the panel.
  • Clear without opening the panel. The trailing × resets that one override in place — the chip body still opens the panel scrolled to its row.
  • Warnings aren't chips. "restart pending" becomes a sentence with its action attached — amber, because a human must act — instead of cosplaying as a policy value.
  • Side effects (replaces crews) render muted inside the value cell: visible, but subordinate to the value itself.
03 · Policies panel & work selectors

One aligned grid, honest defaults, obvious overrides

The current panel mixes three control styles (segmented buttons, native selects, underlined reset links), wraps its own labels ("Standing crew"), and spends its widest segment on the confusing "Default · quick" — a button whose label changes meaning depending on config elsewhere. Hints repeat under every row whether you need them or not. The redesign below is interactive — click the segments.

Design notes

  • "Inherit", not "Default". The first segment is renamed Inherit · quick — "Default · quick" next to a "Quick" option reads as a duplicate. Inherit says what it does: follow project/global config, whatever that currently resolves to.
  • The resolved value shows only while inheriting. Inherit · quick collapses to Inherit once you override — the inherited value is a fallback fact, not a competing label.
  • Override state is one consistent grammar. Overridden rows get the primary dot, a foreground label, an inset-ring on the chosen segment, and a visible ↺ reset — identical across segments and selects, replacing three different reset styles.
  • Hints on demand. Per-row hint sentences move into the ? tooltips; only conditional consequences (crew suspension, restart pending) stay inline, so the panel is half the vertical noise at the same information content.
  • One select style. Model pickers match the segment styling (same ground, border, radius) instead of native <select> chrome; model names in DM Sans, ids stay mono in the dropdown.
  • The panel names its scope. Header carries the issue id (PAN-2829) and "this issue only" — today that fact hides in the footer while the panel itself is anonymous.
  • Grouped footer count. "1 override on this issue" + reset-all in a fixed footer; the count matches the chip-strip badge so the two surfaces visibly agree.
  • No-loss audit: every current control survives — review mode, re-review scope (appears when mode resolves to full, same as today), review model, work model, swarm, standing crew, restart-pending action, per-row resets, reset-all.

Where this lands

All three surfaces live in the same code the request touched:

  • src/dashboard/frontend/src/components/CommandDeck/SessionView/SessionResumeButton.tsx — becomes the contextual resume strip (issue pill + agent id + state + spend from useIssueActions / lifecycle).
  • src/dashboard/frontend/src/components/IssuePolicyStrip.tsx — chip row (two-cell chips with inline clear) and the panel (Inherit segments, unified select style, header/footer).
  • List surfaces that show stopped sessions (FleetAgentsView, BootReconciliationModal) adopt the issue-pill-first row.

Mock renders in the dashboard's dark tokens only — matching the operator's environment; the real components inherit both themes from index.css automatically.
