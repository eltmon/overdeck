Design rules (binding for implementation)

  • Attribution over telemetry. Every number names its owner (issue, agent, service). A spike without a culprit is a bug in this page.
  • Reclaim advisor is the hero. The page's #1 job is answering "what can I free right now?" — computed from pipeline state (merged/closed issues → their stacks/volumes/venvs are reclaim candidates).
  • Stack = unit of thought. Containers group under their issue's stack; aggregate line first, services on expand. Never a flat container list by default.
  • Full verb set: Start / Stop / Pause (docker pause — freeze without cold-start) / Restart / Logs / Terminal / Tear down (with reclaim estimate) on stacks and services. Tear-down is typed-confirm.
  • Pipeline-aware chips reuse the phase language (working / review / awaiting UAT / merged) — resources and pipeline never disagree.
  • Limits are first-class: a container near its memory limit shows amber at 85%, red + OOM count at 95%, with "raise limit" and "create issue" affordances.
  • Spawn gate visibility: the same guardrail state that blocks agent spawns (OPEN/SOFT/BLOCKED) is shown with its reason — no more mystery 409s.
  • History explains itself: 24h chart with event annotations (spikes, reclaims, gate flips) sourced from the events table.
  • Forecast before you act: starting a stack/agent shows its predicted footprint against free headroom (learned from past runs of the same stack).
  • Live via existing WS events, 5s stats poll; all numbers from the read door (`/api/resources` extended) — no new state plane.
  • Keyboard-first: / filter, S stop, P pause, L logs on the focused row; rows are focusable.
  • Idle honesty: anything holding >1 GB while idle >2h gets the pause hint. The page nags so the operator doesn't have to notice.
