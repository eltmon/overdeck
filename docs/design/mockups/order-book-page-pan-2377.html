  • The book is a first-class page, not prose. Today the order book is a markdown file the model must honor; here every item is a row with mechanical status. The header states the three numbers that matter — landed, in pipeline, held — and which run the book is bound to.
  • Posture is the single most prominent control, and it is amber on DRAIN because amber = a human is holding the gate (style-guide semantics: amber means a human must act). OPEN is deliberately neutral — an open gate is the rest state, not a signal. The control always shows who set it and why; flipping it is the operator's one-click release of the whole plan (pre-released semantics: membership = release, posture = the master valve).
  • Lane A and Lane B are columns with their rule in the header, not a shared list. Lane semantics are the feature: A overlaps freely, B is one-in-flight. Held/released rows are neutral; only in-pipeline (blue = machine working) and landed (emerald = outcome) ever carry color — one colored signal per row max.
  • Serial position is explained in the row detail, not implied. B12's detail says exactly what blocks it (B11 closed out + green main). B13 shows the no-PRD block with a disabled Release — the validation lives on the item, where the operator acts.
  • Landed items stay in the book as history (emerald ✓, muted rows, collapsible). The book doubles as the campaign's record — 13/17 tells the drain story at a glance, and the completed run's retro links from here.
