Mockup 1 of 7 Overdeck UX Overhaul — diagnosis & convergence plan 2026-07-19 · companion to PRD docs/prds/planned/overdeck-ux-overhaul.md
Design proposal · "Make Overdeck not suck"

Simple enough for a junior dev. Powerful enough for the operator. In that order.

The default experience is four plain-English states, one obvious button — and the conversation front and center. Talking to the agent is how work actually gets steered, so the rich conversation (turns, thinking, tool calls, your messages, a real composer) is the main pane of every issue view in both modes. The rest of the machinery — phases, specialists, gates, 43 actions — still exists, one "Advanced" toggle away, unified into a single detail view instead of four divergent ones.

01The diagnosis (verified with live walkthrough, 2026-07-19)

Zero on-ramp: machinery is the first thing you see

A new user lands on 701-card columns, verb badges like QUEUED FOR PLAN, five-action card footers ("Start agent · Tell agent · Done — mark work complete & start review · ··· 41 more"), and banners about boot reconciliation. Nothing answers the only three questions a junior dev has: what is it doing, does it need me, is it done?

card footer: Start agent · Tell agent · Done — mark work complete & start review · ··· 41 more

Four issue surfaces, four dialects

The same issue renders as a kanban card (/board), a drawer (/issues/:id), a cockpit page (/command-deck/:project/:issue), and an expandable row. The task DAG exists only in the cockpit; verification gates only in the drawer; per-phase agent rows only in the rail. Every answer requires knowing which view holds it.

drawer tabs: Overview·Plan·Tasks·Conversation·Terminal·Activity·Files·Artifacts
cockpit tabs: Overview·Code·PRD/Plan·Timeline·Discussion·Costs·Artifacts·Terminal

37 actions, all at once, everywhere

Drawer and cockpit each dump ~37 verbs in a flat list — Start agent next to Stop agent, Pause next to Unpause — and disagree about the danger set (6 vs 5) for the same issue. Two registry entries point at dead endpoints; two open stub dialogs; a dead component carries a parallel bypass action set.

drawer: Plan·Auto-plan·Watch·Done planning·Start·Stop·Pause·Unpause·…·Danger(6)
cockpit: Tell·Plan·…·Start·Stop·Pause·Unpause·…·Danger(5)

03Design principles applied

The conversation is the interface

Steering happens by talking. Every issue view leads with the rich conversation — turns, thinking, tool calls, your bubbles, a real composer — and every agent role (plan, work, review, test, ship) keeps its own conversation, one click apart.

Junior-dev default

If a first-week dev can't do the core loop — hand off a task, answer its question, merge the result — without training, the design fails. Everything beyond that loop is Advanced.

One button rule

Exactly one primary action per issue per state. Secondary actions are quiet. Destructive actions live in Advanced so they can't be clicked by accident.

Plain words, enforced

"Writing code", "being checked", "needs you" — never "convoy dispatched". A copy lint bans internal jargon from user-facing simple-mode strings.

Attention is the scarce resource

"Needs you" outranks chronology on every surface. Questions, found problems, and stuck work surface above everything else.

Conformance is enforced

Component-usage and copy lints fail CI if a second detail shell, a third menu skin, or jargon in simple-mode copy reappears. Drift broke the last redesign; the gate prevents the next one.
