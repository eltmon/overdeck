Crew create & delete, made discoverable

PAN-2760 · Settings → Tiered Execution (TieredExecutionSection.tsx). Create, update, and delete all exist today, but an operator looking straight at the panel concluded none of them did. This proposal adds an Add crew button to the roster and a remove affordance to every collapsed row — both keeping creation and assignment (or deletion and hand-off) one atomic gesture, so no crew can ever exist in the silently-discarded zero-difficulty state. Everything in the proposed section is clickable.

  • Create hides inside a picker. The only way to make a crew is the + new crew… option at the bottom of each difficulty dropdown. A control that reads as “which crew handles medium?” is also the only door to creation, and nothing near the roster header suggests a crew can be made at all.
  • The empty state teaches the trick in prose. “Choose ‘+ new crew…’ on the board to create the first crew.” When copy has to explain where an interaction hides, the affordance isn’t carrying itself.
  • Remove requires knowing the row expands — and then it always refuses. The Remove button lives inside the expanded row, and every saved crew owns at least one difficulty, so pressing it can only ever print “assign these difficulties to another crew first.” The real delete gesture today is reassigning difficulties on the board until the crew silently evaporates. Nobody would guess that.

Supervisor, kind-override add controls, and the Advanced disclosures are unchanged and omitted here — this mockup covers only the surfaces PAN-2760 touches. The kind-override chips are shown because they gate deletion.

  • “+ Add crew” asks for a difficulty before it creates anything. Creation and assignment stay one gesture — the invariant the whole save path depends on (serializeCrews drops any crew owning zero difficulties). A crew that “handles nothing” never exists, so nothing can silently vanish on save. Picking a difficulty that would strand a kind-routed crew is blocked inline, same guard as the board.
  • Every collapsed row carries × remove — and removing hands the work off, mirroring create. Since every saved crew owns a difficulty, a bare delete would always dead-end. Instead, × on a crew that owns difficulties asks who takes them over, then reassigns and removes in one gesture. The kind-override guard still blocks with its existing message, and the last crew can’t be removed (every difficulty needs one).
  • Rows now read as editable. Hovering a collapsed row highlights it and shows an “edit” cue next to the caret — the disclosure is no longer a secret. The Remove button inside the expanded body stays (no-loss) and routes through the same hand-off flow.
  • The empty state is a button, not a lesson. “Add crew” works directly from the empty roster; the first crew takes every difficulty, exactly like the board’s first-crew behavior today.
