Issue policy strip — redesign proposal

The per-issue policy strip (IssuePolicyStrip.tsx, PAN-2674) currently renders five look-alike native selects in the issue header. This mockup proposes collapsing it to a single Policies control that shows overrides only. Everything below is clickable.

REVIEWING
  • Three controls start with “review” — review mode, re-review scope, reviewer model — so the row reads as “review review review” and you have to parse each one to know which is which.
  • Everything shouts its default. Nearly every issue runs on all defaults, yet five selects permanently announce “default (…)”. Settings noise is displayed as if it were status.
  • “default (unconfigured)” is meaningless — it leaks the internal null instead of saying what actually happens (each reviewer role uses its configured model).
  • Native selects with labels baked into options — ragged widths, 11px cramped text, and the label repeats inside every option (“reviewers: GPT-5.5”).

Proposed — overrides-only strip + grouped panel

Collapsed, the strip is one quiet Policies button. Chips appear only for values you actually overrode; an all-defaults issue shows no policy noise at all. The panel groups the five knobs under Review and Work, with the resolved default folded into each control’s “Default” position.

What changed, and why

Status vs settings. The header shows state you need at a glance; policy knobs are settings you touch rarely. Settings move behind one affordance, and only deviations from default surface as chips — so a glance tells you “this issue is special” instead of re-reading five defaults on every issue.

One “review” instead of three. Grouping under a Review heading turns “review / re-review / reviewers” into Mode / Re-review / Model. The reviewer-model control also stops saying “unconfigured” — its default reads per-role default, which is what actually happens.

Default is a position, not a caption. Each control’s first position is “Default · resolved value”, so the effective value stays visible without every control captioning itself. Overridden rows get a dot, a reset link, and a chip outside; the amber restart notice appears only when the override actually requires a restart (amber = a human must act).
