# The Cut — No-Loss Map (PAN-3917)

Every feature stays; the state layer goes. This table is the accounting: one
row per module, route, view, CLI verb, or doc that PAN-3917 deletes, what it
did, and where its surviving job went (or why nothing needed to replace it).
Generated from the PRD's Appendix A inventory (measured on `main` at
`5c9221a983b`) plus a fresh `grep -rlE -i 'deacon|patrol|merge.train|swarm|overdeck-state' docs/*.md` run in this worktree.

Read this alongside [`CLAUDE.md`](../CLAUDE.md)'s one-liner: **Overdeck
stores no status it can derive.** Nearly every "dropped (state layer)" row
below is the same shape — a module that kept a private copy of a fact git,
the tracker, the PR, or the terminal backend already owns.

Six docs are not in this table because they were rewritten in place instead
of deleted: [`MERGE-WORKFLOW.md`](MERGE-WORKFLOW.md), [`XBRIEF.md`](XBRIEF.md),
[`ROLES.md`](ROLES.md), [`REVIEW-AGENT-ARCHITECTURE.md`](REVIEW-AGENT-ARCHITECTURE.md),
[`PIPELINE-GATES.md`](PIPELINE-GATES.md), [`WORKSPACES-AND-PROJECTS.md`](WORKSPACES-AND-PROJECTS.md).
Two are new: [`FOREMAN.md`](FOREMAN.md) (the parallel-wave work protocol) and
[`TERMINAL-BACKENDS.md`](TERMINAL-BACKENDS.md) (the Herdr/tmux contract).

"Lines" is the non-test line count from the PRD's inventory where known;
blank means the row came from the docs grep, which doesn't carry a line count.

## Notes on surviving features (not deletions, but behavior worth knowing)

- **Per-issue pipeline journal — the one piece of stored pipeline state brought back post-cut.** The Cut was right that state is what git, the tracker, the PR and the terminal backend say, but it left no record of what Overdeck itself *did*: between "PR opened" and "review posted" nothing on disk said anything, so `pan show` could only answer `in-review`, a work agent told to confirm a pipeline state change polled for ten minutes (PAN-3705), and a dashboard restart mid-convoy lost the convoy. `src/lib/cloister/pipeline-journal.ts` restores exactly one thing and it is not a status: an **append-only** log at `<workspace>/.overdeck/pipeline.jsonl`, written at the moment of each action and never rewritten, **event-fired** on the existing pipeline-notifier, disposable with the workspace, and never authority — where it disagrees with the PR, the PR wins and the journal is simply stale. No routine repairs it; no API rewrites or deletes an entry. See [`PIPELINE-GATES.md`](PIPELINE-GATES.md) "The pipeline journal".
- **Deacon-lite is five routines, not four.** The rows below that say "deacon-lite: 4 fixed routines" describe the Cut as shipped. `recoverStalledReviews` was added after it, driven entirely by the journal above: it re-dispatches a review convoy whose reviewers are all gone, and it is the only timer the journal work added.

- **`resume` is unsupported on both terminal backends.** `TerminalBackend.resume()` returns `unsupported` on tmux (`terminal-backends/tmux.ts` — "relaunch it with its own resume flag via startAgent") and on Herdr (`terminal-backends/herdr.ts` — "protocol 22 has no agent resume method"). A harness resumes itself via its own resume flag at `startAgent` time; there is no backend-level resume call.
- **`AutoMergeToggle` (dashboard) is read-only.** The per-issue routing key used to be a record field; PAN-3917 (D3) removed the record. The effective value now comes from `GET /api/merge-train/auto-merge`, computed server-side by `cloister/auto-merge-eligibility.ts`: the issue's own tracker labels (`auto-merge` / `hold-for-uat`, see `AUTO_MERGE_LABEL/HOLD_FOR_UAT_LABEL`) take precedence when present, falling back to the project's auto-merge default and the global `require_uat_before_merge` policy. Change the policy through the tracker label or Settings → project → auto-merge default, not the toggle.
- **`pan handoff --issue` does not place its pane in the issue's workspace yet.** `terminal-backends/launch.ts` (FR-5, W8) is the one place `pan start`/`pan spawn`/specialists/`pan strike` resolve the backend and place a pane in the issue's workspace with the four metadata tokens. The conversation-fork path (`overdeck/conversation-forks.ts` → `spawnConversationSession`) does not route through it — a forked conversation's `cwd` is its parent's `cwd` (or an explicit `--cwd`), not the issue's workspace. Giving `pan handoff --issue` the same pane placement as the other spawners is a post-release follow-up.
